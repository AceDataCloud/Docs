description: "用手动流水线任务调用聊天模型，总结提交标题。"

可以在 GitLab CI 任务中调用 AceDataCloud Chat Completions API。[示例流水线](https://raw.githubusercontent.com/AceDataCloud/Docs/main/examples/gitlab/acedatacloud-chat.gitlab-ci.yml)总结最新提交的标题，并将结果保存为短期 Artifact。任务只在默认分支显示，且需要手动启动。

## 配置任务

1. [创建 AceDataCloud API Token](https://platform.acedata.cloud/console/applications)。
2. 在 GitLab 项目中打开 **Settings → CI/CD → Variables**，添加名为 `ACEDATACLOUD_API_TOKEN` 的变量，设为 masked 和 hidden，并保护该变量及默认分支。
3. 将[示例流水线 YAML](https://raw.githubusercontent.com/AceDataCloud/Docs/main/examples/gitlab/acedatacloud-chat.gitlab-ci.yml)复制到项目的 `.gitlab-ci.yml`。如果已有 `stages`，将 `report` 加入现有列表，然后只复制示例任务。
4. 在默认分支运行流水线，手动启动 **acedatacloud_commit_summary** 任务，从 Artifact 下载 `summary.txt`。

任务会将 `CI_COMMIT_TITLE` 发送给 AceDataCloud。如果提交标题包含敏感内容，请先确认项目的数据使用规则。每次手动运行产生一次计费 API 请求；更改触发方式前请查看模型当前价格。Token 保留在 GitLab 的 CI/CD 变量中，不会写入 Artifact。

要总结其他输入，可修改示例中的 `jq --arg title` 和提示词。请继续将 Token 放在 CI/CD 变量中，并用 `jq --arg` 编码用户可控文本，不要在 JSON 字符串里直接拼接 shell 变量。请求结构见 [Chat Completions](/zh-Hans/guides/openai/openai_chat_completions)。

这是可复制的 CI 示例。要将可复用组件发布到 [GitLab CI/CD Catalog](https://docs.gitlab.com/ci/components/)，还需要 GitLab 托管的组件项目和 Release。
