[示例工作流](https://raw.githubusercontent.com/AceDataCloud/Docs/main/examples/n8n/acedatacloud-chat.json)使用 n8n 自带的 Manual Trigger、Edit Fields 和 HTTP Request 节点。它向 AceDataCloud Chat Completions 发送一次非流式请求，并输出回复、响应 ID、模型和 Token 用量，无需安装社区节点。

## 原生节点与模型入口

优先安装独立服务节点，在触发器后的动作面板按服务名搜索，不必先拼HTTP请求。Cloud认证和自托管npm安装分开核实。

- [Suno](/zh-Hans/integrations/n8n-suno)
- [Seedance](/zh-Hans/integrations/n8n-seedance)
- [HappyHorse](/zh-Hans/integrations/n8n-happyhorse)
- [GPT Image](/zh-Hans/integrations/n8n-gpt-image)
- [Nano Banana](/zh-Hans/integrations/n8n-nano-banana)

聊天可安装 [Ace Data Cloud Chat Model](https://github.com/AceDataCloud/AceChatN8N)，再接到 Agent/Basic LLM Chain 的 **Model** 输入，无需填写Base URL；它不是默认预装Provider，Cloud认证未证。已发布0.1.1仍手填模型ID，候选自动列表尚未发布。

以下HTTP工作流是可选的低层样例，不代替上述原生节点或官方收录。

## 导入并运行

1. 按下方[获取 API Key](#获取-api-key)操作，再检查[当前模型价格](https://platform.acedata.cloud/models?utm_source=opensource&utm_medium=referral&utm_campaign=evergreen&utm_content=n8n_docs_zh_hans_pricing)和可用余额。
2. 在 n8n 中新建工作流，选择 **Import from URL**，填入[工作流 JSON 地址](https://raw.githubusercontent.com/AceDataCloud/Docs/main/examples/n8n/acedatacloud-chat.json)。也可以下载 JSON 后选择 **Import from File**。
3. 打开 **AceDataCloud chat**。**Authentication → Generic Credential Type** 和 **Generic Auth Type → Bearer Auth** 已预设。点击 **Connect to Bearer Auth**，创建或选择 HTTP Bearer Auth 凭据。只填 Token 本身，不要加 `Bearer ` 前缀。选中凭据后先保存工作流，再运行。JSON 不包含凭据。
4. 在 **Set prompt and model** 中修改提示词。如需换模型，选择 [Chat Completions](/zh-Hans/guides/openai/openai_chat_completions) 支持的模型。示例使用 `gpt-4o-mini`，并将输出限制为 80 Token；如需更长回复，可修改 HTTP Request 请求体中的 `max_tokens`。
5. 点击一次 **Execute workflow**。在 **Read answer and usage** 中检查 `answer`、`response_id`、`model` 和 Token 用量。工作流导入后默认未激活，只有手动点击才会运行。

请将 Token 保存在 n8n 凭据中，不要写进 Edit Fields 节点或工作流 JSON。处理敏感提示词前，检查 n8n 的执行记录保存设置。

## 获取 API Key

1. 打开[应用管理](https://platform.acedata.cloud/console/applications?utm_source=opensource&utm_medium=referral&utm_campaign=evergreen&utm_content=n8n_docs_zh_hans_api_key)，登录或注册账号。若尚无**通用应用**，点击 **Initialize General Application（初始化通用应用）**。
2. 复制应用卡片上的 **API Key**，或进入 **Keys / Manage Keys → Create（密钥管理 → 创建）**，为 n8n 创建单独命名的密钥。通用应用密钥可使用账号已开通的服务，专用应用密钥只适用于对应服务。
3. 检查 **Expiration Time（有效期）**、**Set Usage Limitation（用量限制）**和 **Allowed APIs（允许的 API）**，允许 Chat Completions 及要使用的模型。运行前确认余额；试用额度以当前账号页面显示为准。
4. 将原始 Token 填入 n8n 的 HTTP Bearer Auth 凭据，不要加 `Bearer `、引号或空格。`platform-...` 账号管理 Token 不能代替生成 API Key。

## 接入自己的自动化

将 **Start a manual test** 换成需要的触发器，并把输入文本映射到 **Set prompt and model** 的 `prompt`。HTTP Request 节点以 `stream: false` 向 `https://api.acedata.cloud/openai/chat/completions` 发送 POST 请求。后续节点可使用 **Read answer and usage** 的 `answer` 和 `response_id`。

每次执行都可能消耗 Credits。最终节点中的 Token 数量不能证明实际扣费；请以 AceDataCloud 的用量记录为准。启用定时或 Webhook 前，先手动运行一次。建议观察 n8n 执行成功率、失败状态、耗时、响应 ID、Token 数量，以及对应的 AceDataCloud 用量记录。

## 错误与重试

HTTP Request 收到失败的 HTTP 响应时会停止本次执行。打开该节点查看状态码和错误信息：

| 状态或现象 | 处理方式 |
| --- | --- |
| `400` | 检查模型、提示词和请求体。 |
| `401` 或 `403` | 检查选中的 Token 及其权限，修正凭据后再运行。 |
| `429` | 检查速率限制，等待后再重试失败的执行。 |
| 超时或 `5xx` | 先查看 AceDataCloud 用量记录，以及已返回的响应 ID，再决定是否重试。即使 n8n 未收到响应，首次请求也可能已经完成。 |

此 POST 默认不自动重试，避免已完成的请求被重复计费。若业务需要重试，请先为结果不明的请求制定核对方法。

此 JSON 可直接导入；只有 n8n 另外发布模板条目后，它才会出现在 n8n 内置的 **Templates** 搜索中。
