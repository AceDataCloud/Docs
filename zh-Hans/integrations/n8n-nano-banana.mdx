此节点由 **Ace Data Cloud** 维护，调用 Ace Data Cloud 的 Nano Banana 服务，并非模型开发方的官方节点。能力包括图像生成与编辑及异步任务查询。直接向模型开发方购买的订阅不能代替 Ace API Key。

<Note>截至 2026-10-19，公开 npm 包已发布，但尚未从 n8n 官方生产目录读到该包。不能把 npm 发布当作 Cloud 认证。本页使用 2026-10-19 正式 npm 新版，已包含服务名搜索别名和原生凭据帮助；npm 新版不自动更新 Cloud 认证版本。n8n 认证包要求英文文档，因此中文上手说明放在此独立客户页面。</Note>

## 安装并找到节点

1. 自托管实例的 owner/admin 按 [n8n 官方安装说明](https://docs.n8n.io/integrations/community-nodes/installation-and-management/gui-installation/)，进入 **Settings → Community nodes → Install**，填写 `@acedatacloud/n8n-nodes-nano-banana@0.1.2`。只在你信任并有权管理的实例中安装。
2. Cloud 只走[官方认证节点搜索安装](https://docs.n8n.io/integrations/community-nodes/installation-and-management/install-verified-community-nodes/)；若搜不到，不改安全设置、不创建同名条目，也不宣称已安装。
3. 在工作流先添加 **Manual Trigger** 或使用已有触发器，再从它后面的 **+** 搜索 **Nano Banana**，选择 **Nano Banana by Ace Data Cloud**；旧版显示 **by AceDataCloud**，内部节点 ID 保持不变。

## 注册并准备专用 API Key

1. 打开 [Ace Data Cloud 应用管理](https://platform.acedata.cloud/console/applications?utm_source=opensource&utm_medium=referral&utm_campaign=evergreen&utm_content=n8n_nano_banana_zh_api_key)，注册或登录。没有 **General application（通用应用）** 时先选择 **Initialize General Application**。
2. 复制应用卡片上的 **API Key**，或进入 **Keys / Manage Keys → Create** 为 n8n 创建单独命名的密钥。通用应用使用账号已开通服务；专用应用只适用于对应服务。
3. 检查 **Expiration Time**、**Set Usage Limitation**、**Allowed APIs**、Nano Banana 服务/模型权限、可用余额和[当前价格](https://platform.acedata.cloud/models?utm_source=opensource&utm_medium=referral&utm_campaign=evergreen&utm_content=n8n_nano_banana_zh_pricing)。查询任务的权限不代表允许生成；试用额度以账号当前显示为准。

## 在 n8n 保存凭据

打开 Nano Banana 节点，在凭据栏创建 **Nano Banana by Ace Data Cloud API**（旧版显示 **by AceDataCloud API**）。将原始 Key 填入 **API Token**，不要加 `Bearer `、引号或空格。`platform-...` 账号管理 Token 不能用于生成或任务查询。

保存后在每个需要权限的节点上选择该凭据。当前凭据测试只查询空任务列表，不生成媒体；测试通过也不能保证某个模型或特定任务有访问权。Key 留在 n8n 凭据存储中，下载的示例不含凭据。

## 先查询自己的已有任务

1. 下载[仅查询已有任务的工作流](https://raw.githubusercontent.com/AceDataCloud/Docs/main/examples/n8n/read-nano-banana-task.json)，在 n8n 用 **Import from URL/File** 导入。它默认停用，仅含触发器、说明和 Nano Banana 查询节点；没有创建或模型节点。
2. 将 **Resource** 设为 **Task**、**Operation** 设为 **Get**。在 **Task ID** 填入你有权读取、由同一服务返回的真实任务 ID，替换示例占位符。Task ID 不是提示词或媒体链接；不要用占位符执行。
3. 选好凭据，只执行该查询节点一次。`finished=true` 且 `successful=true` 才表示成功终态，最终媒体链接在 `data`。处理中继续查**同一个 ID**；失败/取消/权限错误按原结果处理。

此示例的打包、导入和缺凭据边界验收不代表真实授权查询已完成。普通界面安装、Token 保存及成功/失败输出需在你的实例核验；历史任务查询也不是一次新生成或新账单。

## 首次创建与等待结果

已有查询流程确认后，另用 [源仓的创建/轮询示例](https://github.com/AceDataCloud/NanoBananaN8N/tree/main/examples)。选择 **Resource → Image**、**Operation → Generate** 和适用于该操作的模型；例如 `nano-banana` 是现有示例值，运行前仍须核对当前权限和价格。

一次输入 item 可能创建一笔任务；不要批量输入后才检查预算。创建只运行一次，不开 **Retry On Fail**。保存返回的 `taskId`，每次间隔查询同 ID；设置明确超时和失败分支。收到 ID 只是提交成功，不是媒体完成。流程超时不会取消服务器任务，先查旧 ID 再决定是否重试，避免重复收费。

创建操作需要单独预算，本页没有替你提交收费请求。Credits 不是 USD，实际扣费以对应的单条用量记录为准，不以 Token 数量或示例时长推算。

## 常见问题

| 现象 | 处理 |
| --- | --- |
| 搜不到节点 | 区分 Cloud 认证目录与自托管 npm 安装；核对安装成功的包名/版本，从触发器后的动作面板搜索。 |
| 401 / 403 | 检查原始 Key、服务/模型及任务访问权、有效期和 Allowed APIs；停止，不换身份绕过、不重建替代任务。 |
| 429 | 降低并发，按响应等待；不要重发可能已创建的任务。 |
| 创建超时 / 5xx | 查看原执行、已返回 taskId 及用量后再决定重试，优先只查同 ID。 |
| 任务尚未完成 | 检查 `finished`、`successful` 和 `error`，不要仅凭HTTP 200或外层success显示成功。 |
