ACE Music 任务 API 用于查询歌曲、参考音频上传、翻唱、融合和歌词生成任务，也可以分页查看自己的创作历史。本文介绍获取 API Token、查询任务、判断完成状态，以及读取音频和歌词结果的方法。

任务查询免费，余额为零也可查询自己的结果；仍需有效 Token 和任务 API 权限。

## 申请流程

1. 打开 [Ace Data Cloud 控制台](https://platform.acedata.cloud/console/applications)。如果尚未登录，请先注册或登录。
2. 在**通用应用**的 **API Key** 区域选择并复制密钥；如果尚无密钥，点击**创建 API Key**。文中的 API Token 与 API Key 指同一类调用凭据。
3. 你也可以在 [凭据管理](https://platform.acedata.cloud/console/credentials) 中管理密钥。使用 ACE Music 专属应用或设有 API 限制的密钥时，请确认允许访问任务 API；创建歌曲或歌词还需要对应的创作 API 权限。
4. 将示例中的 `YOUR_API_TOKEN` 替换为复制的 Token，通过 `Authorization: Bearer YOUR_API_TOKEN` 请求头发送。

如果还需要创建付费任务，请先确认应用余额和密钥用量限额；余额不足时可前往 [充值页面](https://platform.acedata.cloud/console/coin)。查询已有任务无需充值。请在服务端保存 Token，不要将其放入公开网页或代码仓库。

> 完整接口参数与在线调试：[ACE Music Tasks API](https://platform.acedata.cloud/documents/acemusic-tasks)。

## 查询单个任务

先通过 [歌曲 API](https://platform.acedata.cloud/documents/acemusic-audios-integration) 或 [歌词 API](https://platform.acedata.cloud/documents/acemusic-lyrics-integration) 提交创作，保存返回的 `task_id`。然后向 `POST https://api.acedata.cloud/acemusic/tasks` 发送查询：

```bash
curl --request POST 'https://api.acedata.cloud/acemusic/tasks' \
  --header 'Accept: application/json' \
  --header 'Authorization: Bearer YOUR_API_TOKEN' \
  --header 'Content-Type: application/json' \
  --data '{
    "action": "retrieve",
    "id": "YOUR_TASK_ID"
  }'
```

这里的 `id` 是创作请求返回的 **任务 ID `task_id`**。翻唱或融合使用的 **音轨 ID `response.data[*].id`** 不能代替任务 ID。


### 返回字段

| 字段 | 说明 |
| --- | --- |
| `id` | 平台任务 ID，与提交时返回的 `task_id` 对应。 |
| `type` | `audios` 为歌曲或参考音频任务；`lyrics` 为歌词任务。 |
| `state` / `status` | 任务当前状态，具体含义见下方状态表。 |
| `request` | 该任务的公开创作参数，例如 `action`、`model`、`prompt`。 |
| `response` | 创作结果；任务尚未完成时可能没有最终结果。 |
| `response.success` | 创作是否成功。处理中可能为 `false`，应结合任务状态判断。 |
| `response.data` | 歌曲任务的音轨列表，或歌词任务的标题、正文列表。 |
| `response.error` | 创作失败时的错误信息，包含可公开的 `code` 和 `message`。 |
| `trace_id` | 请求跟踪 ID，排查问题时与任务 ID 一起提供。 |
| `created_at` / `started_at` / `finished_at` | 创建、开始和完成时间，Unix 时间戳，单位秒；未完成时没有完成时间。 |
| `elapsed` | 任务完成后的耗时，单位秒。 |

HTTP 200 表示查询请求成功。歌曲是否已经交付，需要继续检查任务状态和音轨的 `state`、`audio_url`。

## 批量查询

将 `action` 设为 `retrieve_batch`，使用 `ids` 一次查询 1–100 个任务：

```bash
curl --request POST 'https://api.acedata.cloud/acemusic/tasks' \
  --header 'Accept: application/json' \
  --header 'Authorization: Bearer YOUR_API_TOKEN' \
  --header 'Content-Type: application/json' \
  --data '{
    "action": "retrieve_batch",
    "ids": ["YOUR_FIRST_TASK_ID", "YOUR_SECOND_TASK_ID"]
  }'
```

结果中的 `items` 为任务记录列表，`count` 为匹配数量。每条记录与单任务查询格式一致。不存在或当前账号无权访问的任务不会出现在列表中，请按返回记录的 `id` 对照原始请求。

## 查看创作历史

将 `action` 设为 `list`，即可分页查看当前账号的任务。以下示例查询第一页的 20 条歌曲或参考音频任务：

```bash
curl --request POST 'https://api.acedata.cloud/acemusic/tasks' \
  --header 'Accept: application/json' \
  --header 'Authorization: Bearer YOUR_API_TOKEN' \
  --header 'Content-Type: application/json' \
  --data '{
    "action": "list",
    "type": "audios",
    "page": 1,
    "page_size": 20
  }'
```

历史结果也使用 `items` 和 `count`。将 `type` 改为 `lyrics` 可查询歌词历史；省略 `type` 则不按任务类型筛选。

### 请求参数

| 参数 | 类型 | 使用场景 | 说明 |
| --- | --- | --- | --- |
| `action` | string | 所有查询，必填 | `retrieve`、`retrieve_batch` 或 `list`。 |
| `id` | string | `retrieve`，必填 | 单个平台任务 ID。 |
| `ids` | array | `retrieve_batch`，必填 | 1–100 个平台任务 ID。 |
| `type` | string | `list`，选填 | `audios` 或 `lyrics`。歌曲生成、上传、翻唱和融合均属于 `audios`。 |
| `page` | integer | `list`，选填 | 页码，从 1 开始，默认 1。 |
| `page_size` | integer | `list`，选填 | 每页 1–100 条，默认 20。 |
| `limit` / `offset` | integer | `list`，选填 | 另一种分页方式；`limit` 为 1–100，`offset` 从 0 开始，最大 10,000。 |
| `created_at_min` / `created_at_max` | number | `list`，选填 | 创建时间的包含式下限和上限，使用非负 Unix 秒时间戳。 |

分页时请选择 `page` / `page_size` 或 `limit` / `offset` 中的一组，不要混用。由页码计算出的偏移量也不能超过 10,000。

## 任务状态与结果处理

| 状态 | 含义 | 建议处理 |
| --- | --- | --- |
| `created` | 任务已建立。 | 保存原任务 ID，继续查询。 |
| `submitting` | 正在提交创作。 | 继续查询。 |
| `processing` | 正在处理。 | 继续查询，已有部分结果也不代表整组完成。 |
| `storing` | 正在准备音频交付。 | 等待可用的音频地址。 |
| `submission_unknown` | 创作受理状态待确认。 | 保留原任务 ID，继续查询或联系支持，不要另发相同创作。 |
| `succeeded` | 任务成功完成。 | 读取结果，停止轮询。 |
| `partial_failed` | 部分音轨最终失败。 | 保留已完成的音轨，停止轮询并检查错误。 |
| `failed` | 任务最终失败。 | 停止轮询，读取错误信息。 |

对于 `type=audios`：

- 生成、翻唱或融合完整成功时，`response.data` 包含两首候选；成功上传参考音频时包含一首。
- 每首音轨的 `id` 可用于后续翻唱或融合；播放与下载使用 `audio_url`，实际时长见 `duration`（秒）。
- 部分失败的任务仍保留已完成音轨；没有封面不影响已有音频播放，尚无音频地址的音轨仍未交付。

对于 `type=lyrics`，成功后的 `response.data[*].title` 是标题，`response.data[*].text` 是可编辑歌词。接入歌曲自定义模式时，将 `text` 复制到歌曲请求的 `lyric` 字段，详见 [歌词指南](https://platform.acedata.cloud/documents/acemusic-lyrics-integration)。

### Python 轮询示例

下面的示例只查询已有任务，不会创建新的收费任务。先安装 `requests`，并在服务端环境变量 `ACEDATACLOUD_API_TOKEN` 中配置 Token，再替换任务 ID。

```python
import os
import time

import requests

url = "https://api.acedata.cloud/acemusic/tasks"
headers = {
    "Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_TOKEN']}",
    "Accept": "application/json",
}
task_id = "YOUR_TASK_ID"
terminal_states = {"succeeded", "partial_failed", "failed"}

for attempt in range(30):
    response = requests.post(
        url,
        headers=headers,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    response.raise_for_status()
    task = response.json()
    state = task.get("state") or task.get("status")
    print("任务状态：", state)

    if state in terminal_states:
        result = task.get("response") or {}
        print("创作结果：", result.get("data", []))
        if state != "succeeded":
            print("错误信息：", result.get("error"))
        break

    time.sleep(min(5 + attempt, 15))
else:
    print("暂未完成，请保存此任务 ID，稍后继续查询：", task_id)
```

建议从数秒间隔开始轮询并逐步退避。达到本地等待上限后，保留原任务 ID，稍后继续查询。界面刷新、网络中断或查询失败都不应触发自动重新生成或上传。

## 常见错误与费用

| HTTP 状态码 | 处理建议 |
| --- | --- |
| `400` | 检查任务 ID、`action`、分页参数，以及是否混用两种分页方式。 |
| `401` / `403` | 检查 Token 是否有效，以及应用和密钥是否有任务 API 权限。 |
| `404` | 单任务查询未找到当前账号可访问的记录；检查是否误用了音轨 ID，或切换了账号。 |
| `429` | 降低查询频率并退避重试。 |
| `500` / `503` | 保留任务 ID 与 Trace ID，稍后重试查询或联系支持。 |

查询接口不接受通过其他用户 ID 访问他人的作品。歌曲、上传和歌词创作分别计费，查询已有任务免费。生成、翻唱或融合任务最终失败或部分失败时不收生成费；上传和歌词任务最终失败时不收对应创作费用。具体价格见 [歌曲指南](https://platform.acedata.cloud/documents/acemusic-audios-integration) 与 [歌词指南](https://platform.acedata.cloud/documents/acemusic-lyrics-integration)。
