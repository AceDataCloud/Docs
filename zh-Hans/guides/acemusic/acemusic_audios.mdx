ACE Music 可以根据一句创作灵感或自定义歌词生成歌曲，也支持导入参考音频、翻唱已有作品和融合两首参考。本文从获取 API Token 开始，介绍提交请求、查询任务、试听和下载的完整流程。

生成、翻唱和融合每次交付一组两首候选，参考上传每次导入一首音轨。你可以先使用灵感模式完成第一次调用，再按需要选择其他创作方式。

## 申请流程

1. 打开 [Ace Data Cloud 控制台](https://platform.acedata.cloud/console/applications)。如果尚未登录，请先注册或登录。
2. 在**通用应用**区域找到 **API Key**。如果还没有密钥，点击**创建 API Key**；已有密钥可直接使用复制按钮获取 API Token。
3. 如需创建、查看或调整密钥，到 [管理密钥](https://platform.acedata.cloud/console/credentials) 页面操作。使用受限密钥时，请确认它允许访问 ACE Music 及所需的歌曲、歌词和任务接口。
4. 在请求头中填写 `Authorization: Bearer YOUR_API_TOKEN`，将 `YOUR_API_TOKEN` 替换为复制的完整 Token。歌曲生成、参考上传和歌词生成会消耗额度，余额不足时可到 [通用余额](https://platform.acedata.cloud/console/coin) 充值。

API Key 和 API Token 在本文中指调用 API 的同一份凭据。通用应用凭据可在权限范围内复用，无需为本指南中的每次请求创建新密钥。请在服务端保存 Token，不要将它放入网页前端或公开仓库。

> 完整接口参数与在线调试：[ACE Music 歌曲生成 API](https://platform.acedata.cloud/documents/acemusic-audios)。

## 基本使用

第一次调用只需要提供歌曲描述 `prompt`。下面以“一首关于坐末班车回家的温暖民谣”为例，使用默认模型 `acemusic-v1.1` 生成两首候选。

### 设置请求头和请求体

请求地址为 `POST https://api.acedata.cloud/acemusic/audios`。请求头设置如下：

| 请求头 | 值 | 说明 |
| --- | --- | --- |
| `Authorization` | `Bearer YOUR_API_TOKEN` | 使用上一步获取的 Token，保留 `Bearer` 后的空格 |
| `Content-Type` | `application/json` | 请求体使用 JSON |
| `Accept` | `application/json` | 接收 JSON 结果 |

本次请求使用以下参数：

| 参数 | 本次取值 | 说明 |
| --- | --- | --- |
| `action` | `generate` | 生成新歌曲，省略时也使用此操作 |
| `model` | `acemusic-v1.1` | 默认模型，也可选择 `acemusic-v1` |
| `custom` | `false` | 灵感模式，由模型根据描述创作 |
| `prompt` | 歌曲描述 | 可描述语言、主题、风格、乐器与情绪 |
| `async` | `true` | 提交后获取任务 ID，再查询结果 |

### cURL 示例

```bash
curl --request POST 'https://api.acedata.cloud/acemusic/audios' \
  --header 'Authorization: Bearer YOUR_API_TOKEN' \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/json' \
  --data '{
    "action": "generate",
    "model": "acemusic-v1.1",
    "custom": false,
    "prompt": "一首关于坐末班车回家的中文民谣，木吉他伴奏，温暖而充满希望",
    "async": true
  }'
```

### Python 示例

先安装 `requests`（`pip install requests`），并将 Token 保存为环境变量 `ACEDATACLOUD_API_TOKEN`，再执行以下代码：

```python
import os
import requests

response = requests.post(
    "https://api.acedata.cloud/acemusic/audios",
    headers={"Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_TOKEN']}"},
    json={
        "action": "generate",
        "model": "acemusic-v1.1",
        "custom": False,
        "prompt": "一首关于坐末班车回家的中文民谣，木吉他伴奏，温暖而充满希望",
        "async": True,
    },
    timeout=30,
)
response.raise_for_status()
submitted = response.json()
print("请保存任务 ID：", submitted["task_id"])
```

cURL 和 Python 演示的是同一次操作的两种写法，选择其中一种即可。每次新提交都会创建歌曲任务，请勿为了等待结果反复运行提交代码。

### 提交响应

异步请求受理后返回 HTTP `202`。下面是一次实际请求的响应：

```json
{
  "task_id": "ae17781e-b4cd-4ad9-869a-34b8cf96b057",
  "trace_id": "3102971e-7f6a-473c-8255-ba1e8eace89e",
  "status": "created"
}
```

- `task_id`：本次任务的唯一 ID，后续查询需要使用它。
- `trace_id`：排查问题时提供给支持人员的追踪 ID。
- `status`：当前任务状态；受理时通常为 `created`。

此时歌曲仍在处理中，响应没有可播放的音频。请保存你自己请求返回的 `task_id`，进入下一步。

## 查询结果与下载歌曲

使用同一个 Token 调用 `POST /acemusic/tasks`，将 `id` 替换为刚才保存的 `task_id`：

```bash
curl --request POST 'https://api.acedata.cloud/acemusic/tasks' \
  --header 'Authorization: Bearer YOUR_API_TOKEN' \
  --header 'Content-Type: application/json' \
  --data '{
    "action": "retrieve",
    "id": "YOUR_TASK_ID"
  }'
```

查询接口直接返回任务记录。歌曲结果在 `response.data` 中，每个元素代表一首音轨。下方为已完成任务的真实响应节选，仅保留任务状态和音频交付字段：

```json
{
  "id": "ae17781e-b4cd-4ad9-869a-34b8cf96b057",
  "type": "audios",
  "state": "succeeded",
  "response": {
    "success": true,
    "status": "succeeded",
    "data": [
      {
        "id": "3966103b-b0e3-4799-aa6d-b90dfc3e30ee",
        "model": "acemusic-v1.1",
        "title": "末班车的温热",
        "state": "succeeded",
        "duration": 182,
        "audio_url": "https://cdn.acedata.cloud/assets/examples/fish/5ade0339-5f11-487e-aacc-06a908271706-8e3fcb0e5547.mp3?example=audio-001"
      },
      {
        "id": "51b08e57-a990-4aaf-9418-fe3750a833f1",
        "model": "acemusic-v1.1",
        "title": "末班车的温热",
        "state": "succeeded",
        "duration": 174,
        "audio_url": "https://cdn.acedata.cloud/assets/examples/fish/5ade0339-5f11-487e-aacc-06a908271706-8e3fcb0e5547.mp3?example=audio-002"
      }
    ]
  }
}
```

| 字段 | 说明 |
| --- | --- |
| `id` / `state` | 查询记录的任务 ID 与任务状态 |
| `response.success` / `response.status` | 创作结果是否完整成功，以及最终状态 |
| `response.data` | 音轨列表；生成、翻唱、融合完整成功时有两首，上传成功时有一首 |
| `response.data[].id` | 平台音轨 ID，可用于后续翻唱或融合 |
| `response.data[].audio_url` | 已交付音频的播放和下载地址 |
| `response.data[].image_url` | 可选封面地址，缺失不影响音频播放 |
| `response.data[].title` / `lyric` / `style` | 标题、歌词与音乐风格 |
| `response.data[].model` / `state` | 本首音轨使用的模型与交付状态；上传参考可能不含 `model` |
| `response.data[].duration` | 实际音频时长，单位为秒 |

当任务为 `succeeded` 时，可使用 `audio_url` 试听或下载。任务为 `partial_failed` 时，已完成的音轨仍可保留和播放，该组不收生成费。任务为 `failed` 时读取 `response.error` 排查原因。其他状态继续查询，建议间隔数秒并逐步退避。

浏览器刷新或网络中断后，继续查询原任务。封面尚未返回不代表音频不可用；音轨尚无 `audio_url` 时则仍未完成交付。批量查询、历史记录和轮询代码见 [任务查询指南](https://platform.acedata.cloud/documents/acemusic-tasks-integration)。

## 自定义歌词生成歌曲

如果已经有歌词，将 `custom` 改为 `true`，提供 `title`、`lyric` 和 `style`。请求地址和 Token 与基本示例相同，将请求体替换为以下内容即可：

```json
{
  "action": "generate",
  "model": "acemusic-v1.1",
  "custom": true,
  "title": "回家的路",
  "lyric": "[Verse]\n晚风吹过熟悉的街道\n[Chorus]\n灯火等我回到家",
  "style": "中文民谣，木吉他，温暖人声",
  "async": true
}
```

歌词可包含 `[Verse]`、`[Chorus]` 等段落标签。自定义模式请勿再传灵感模式的 `prompt`。还没有歌词时，可先通过 [歌词生成指南](https://platform.acedata.cloud/documents/acemusic-lyrics-integration) 生成草稿，编辑后把歌词结果的 `text` 填入歌曲请求的 `lyric`。

## 上传参考音频

使用同一个歌曲接口，将 `action` 设为 `upload`，提供可访问的 HTTPS `audio_url`。目前仅支持 MP3 文件，`name` 为可选的显示名称。下面的请求体中，音频地址需要替换为自己有权使用的文件：

```json
{
  "action": "upload",
  "audio_url": "https://cdn.acedata.cloud/assets/examples/fish/5ade0339-5f11-487e-aacc-06a908271706-8e3fcb0e5547.mp3?example=audio-001",
  "name": "我的参考旋律",
  "async": true
}
```

此操作不需要 `model`、`custom` 或歌词字段，也不会自动生成新歌曲。提交后同样保存 `task_id` 并查询任务，成功结果的 `response.data` 包含一首音轨，将其 `id` 保存为后续操作的参考音轨 ID。

若希望将新参考与某首已有作品组合使用，可在上传时传入该作品的平台 `audio_id`。本地文件需要先获得可访问的 HTTPS 地址；将文件存入文件服务和调用本接口导入参考是两个步骤。参考导入成功后会收取独立的上传费用。

## 翻唱已有歌曲

将 `action` 设为 `cover`，使用自己可访问的平台音轨 `audio_id`，并填写新歌词和音乐风格：

```json
{
  "action": "cover",
  "model": "acemusic-v1.1",
  "audio_id": "YOUR_TRACK_ID",
  "title": "回家的路·民谣版",
  "lyric": "[Verse]\n晚风吹过熟悉的街道",
  "style": "温暖民谣，木吉他",
  "audio_influence": 60,
  "async": true
}
```

`audio_id` 来自先前成功任务的 `response.data[].id`，与生成任务的 `task_id` 不同。翻唱使用 `acemusic-v1.1`；标题可选，歌词与风格必填。`audio_influence` 控制音频参考程度，范围为 1–100，默认 60。已有平台音轨可直接复用，无需再次付费上传。

## 融合两首参考歌曲

将 `action` 设为 `mashup`，在 `mashup_audio_ids` 中填写恰好两首不同的平台音轨 ID：

```json
{
  "action": "mashup",
  "model": "acemusic-v1.1",
  "mashup_audio_ids": ["YOUR_FIRST_TRACK_ID", "YOUR_SECOND_TRACK_ID"],
  "lyric": "[Verse]\n把两段旅程写成一首歌",
  "style": "中文流行，融合两首参考的旋律与节奏",
  "audio_influence": 60,
  "async": true
}
```

两首参考可来自已完成的上传或歌曲任务，必须是自己可访问且相互兼容的作品；不兼容的组合会被拒绝。融合也使用 `acemusic-v1.1`，歌词和风格必填，标题可选。

翻唱和融合不使用 `custom` 或灵感 `prompt`。当前歌曲接口不提供风格强度、纯音乐、续写、分轨或音色参数，请勿直接套用其他音乐服务的字段。

## 参数速查

| 参数 | 类型 | 何时填写 | 说明 |
| --- | --- | --- | --- |
| `action` | string | 可选 | `generate`（默认）、`upload`、`cover` 或 `mashup` |
| `model` | string | 生成、翻唱、融合 | 默认 `acemusic-v1.1`；生成也支持 `acemusic-v1`；上传不传 |
| `custom` | boolean | 仅生成 | 默认 `false` 为灵感模式，`true` 为自定义歌词模式 |
| `prompt` | string | 灵感生成必填 | 歌曲的创作描述 |
| `title` / `lyric` / `style` | string | 自定义生成必填 | 标题、歌词和风格；翻唱与融合只要求歌词、风格，标题可选 |
| `audio_url` / `name` | string | 上传 | HTTPS MP3 地址必填，显示名称可选 |
| `audio_id` | string | 翻唱必填；上传可选 | 平台音轨 ID，上传时可用于关联已有参考 |
| `mashup_audio_ids` | string[] | 融合必填 | 恰好两个不同且兼容的平台音轨 ID |
| `audio_influence` | number | 翻唱、融合可选 | 参考程度 1–100，默认 60 |
| `async` | boolean | 可选 | 默认 `true`；设为 `false` 会等待结果，超出等待时间仍返回 `202` 与原任务 ID |
| `callback_url` | string | 可选 | HTTPS 完成回调地址；传入后采用异步执行 |

各操作只接受对应字段，请按上面的独立示例构造请求。

## 完成回调与重复请求

### 使用完成回调

如果不希望持续轮询，可在歌曲请求中加入自己的 HTTPS `callback_url`。完成后，平台会向该地址推送最终结果。接收方应按 `task_id` 去重并返回成功状态，回调可能重投。

回调接收失败不会重新生成、重新导入或额外扣费。仍可使用任务 API 获取原任务结果。

### 使用幂等键

在提交请求时可增加 `Idempotency-Key` 请求头，为同一次创作指定唯一键。相同键和相同内容会返回原任务，相同键配不同内容会冲突。每次有意发起的新创作使用新键，同一次提交的重试则保留原键和原内容。

请在发送前保存键，并在受理后保存 `task_id`。网络超时且受理状态不明确时，不要换键自动补发；优先查询原任务，必要时保留幂等键联系支持。

| --- | --- | --- |
| 生成、翻唱、融合 | 一组完整的两首候选 | 完整成功收一次，最终失败或部分失败不收生成费 |
| 参考上传 | 一首成功导入的参考 | 导入成功收一次，失败不收费 |
| 歌词生成 | 一次成功的歌词任务 | 独立收费，歌曲操作不会隐式另收歌词助手费用 |

具体单价与余额请查看 [ACE Music 服务](https://platform.acedata.cloud/services/acemusic) 和 [控制台](https://platform.acedata.cloud/console/applications)。控制台以 Credits 计量，实际金额按所用套餐、优惠、站点定价和汇率折算。

## 常见问题

### 获取 Token 后仍然提示认证或权限错误怎么办？

检查 Token 是否复制完整、`Bearer` 后是否有空格，以及密钥是否被禁用或限制了 ACE Music 的接口访问。不要把应用 ID、任务 ID 当作 Token。

### 请求返回 202，为什么没有音频地址？

`202` 表示任务已受理。使用返回的 `task_id` 查询，完成后从 `response.data[].audio_url` 获取音频。请勿重复提交生成请求来等待歌曲。

### 查询成功就代表两首歌都完成了吗？

查询 HTTP 成功表示读取任务成功，还需要检查任务的 `state` 和每首音轨的 `state`。完整交付两首候选时任务为 `succeeded`；最终仅部分交付时为 `partial_failed`。

### 调用失败时如何排查？

| HTTP 状态码 | 处理建议 |
| --- | --- |
| `400` | 检查必填字段、操作对应的参数、参考音轨与兼容性 |
| `401` / `403` | 检查 Token、凭据状态和接口访问权限 |
| `402` | 检查余额和凭据额度限制 |
| `404` | 检查参考音轨是否存在，以及当前账号是否可访问 |
| `409` | 同一幂等键对应的请求内容不同，请核对原请求 |
| `429` | 降低调用频率，按退避策略重试 |
| `500` / `503` | 保留已有任务 ID，先查询任务再判断下一步 |

异步执行失败会记录在任务终态与 `response.error` 中。联系支持时，请提供 `task_id` 和 `trace_id`，不要提供完整 API Token。
