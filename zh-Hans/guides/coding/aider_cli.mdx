## 获取 Ace Data Cloud API Key

1. 打开 [控制台 → 应用列表](https://platform.acedata.cloud/console/applications)，完成登录。
2. 按计费方式选择应用：使用 Coding Plan 时进入 **Coding Application**；按量使用时选择有对应服务权限的通用/服务应用。Coding 套餐与通用余额分别管理。
3. 复制该应用的 **API Key / API Token**，不要复制 Application ID 或 `platform-` 管理 Token。下文 API Key 字段只填写密钥本身，不含 `Bearer ` 前缀。
4. 确认应用有效且有额度。活动和免费额度以控制台实时显示为准。

用同一把 Key 查询模型目录：

```bash
export ACEDATACLOUD_API_KEY="YOUR_ACEDATACLOUD_API_KEY"
curl --fail-with-body https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY"
```

PowerShell 环境变量写法为 `$env:ACEDATACLOUD_API_KEY = "YOUR_ACEDATACLOUD_API_KEY"`；使用 Windows 自带 curl 时写 `curl.exe`。`/v1/models` 是模型发现入口，目录中出现某个模型不等于当前 Key 有对应 API 权限。还要核对所选协议、应用范围和客户端能力。

下文 `MODEL_ID` 必须替换为具体模型 ID。不要把真实 Key 提交到 Git、贴进日志或截图。

## 1. 安装 Aider

按官方安装器创建 Aider 运行环境：

```bash
python -m pip install aider-install
aider-install
aider --version
```

## 2. 配置 Chat Completions

在启动 Aider 的同一终端设置：

```bash
export OPENAI_API_BASE="https://api.acedata.cloud/v1"
export OPENAI_API_KEY="$ACEDATACLOUD_API_KEY"
cd /path/to/test-project
aider --model openai/gpt-4.1-mini
```

`openai/` 是 LiteLLM 的路由前缀，`gpt-4.1-mini` 是示例模型 ID；换模型时保留前缀。也可用 Aider 的 `--openai-api-base`、`--openai-api-key` 选项，但 Key 推荐通过环境变量传入，避免出现在命令历史中。

PowerShell 对应设置 `$env:OPENAI_API_BASE = "https://api.acedata.cloud/v1"` 与 `$env:OPENAI_API_KEY = $env:ACEDATACLOUD_API_KEY`。

## 3. 只读验证

```bash
aider --model openai/gpt-4.1-mini --chat-mode ask --message "Reply only ADC_AIDER_OK"
```

Aider 对陌生模型可能提示缺少上下文、价格或编辑格式元数据；这不等于密钥错误。先用 ask 模式确认基本连通，再按官方模型设置配置编辑格式和上下文上限，不要随意填超大数值。

## 本轮实际结果与文件任务

2026-09-07 在 macOS arm64、Python 3.12.13 的隔离环境安装 Aider 0.86.2 后，执行只读文件任务未通过：LiteLLM 导入时出现 `module litellm has no attribute _logging / APIConnectionError`，重新安装依赖后仍复现。该失败发生在模型请求之前，不能据此认定 Ace Data Cloud API 不兼容，也不能把本文标为本机已跑通。先按官方安装器重建独立环境并检查 `aider --version`；若仍出现该错误，保留版本与堆栈排查依赖。

## 实战与验收

先新建一个测试目录，在 `fixture.txt` 写入 `hello from Ace Data Cloud`，用 `--read` 明确把文件作为只读上下文传入：

```bash
aider --model openai/gpt-4.1-mini --chat-mode ask --read fixture.txt \
  --message "Quote the exact contents of fixture.txt. Do not modify files."
```

交互式使用时也可以要求：

> 读取 fixture.txt，逐字引用其内容并解释文件用途。不要修改任何文件。

检查是否真的读取文件、是否引用正确内容；然后到 [平台使用历史](https://platform.acedata.cloud/console/usages) 按时间核对请求。对不支持文件工具的聊天模式，先附加该文件，再提同样的问题。不要用一次简单聊天成功推断编辑、图片、工具、自动补全全部可用。

| 现象 | 排查 |
|---|---|
| 401 | API Key 是否完整、是否重复 Bearer 前缀、进程是否读取到变量 |
| 403 / 额度错误 | Key 所属应用、套餐有效期、API 权限与余额 |
| 404 | Base URL 是否重复 `/v1` 或拼入了不该填写的完整接口路径；模型 ID 是否正确 |
| 聊天成功但 Agent 失败 | 检查当前模型的工具调用能力与客户端模式，先完成上面的只读测试 |
| 修改未生效 | 重启客户端；Remote/WSL/容器的配置和变量通常需要放在实际运行端 |
