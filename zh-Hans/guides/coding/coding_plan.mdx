Coding Plan 配置向导固定为三步：选择开发产品、选择接入方案、选择该方案已验证的 exact model。四档套餐拥有相同的 Coding 模型访问范围；当前价格和活动额度以 [Coding Plan 定价页](https://platform.acedata.cloud/services/coding?tab=pricing) 为准。Coding Application 不回退到通用余额。

## 状态

| 状态 | 含义 |
|---|---|
| 待复验 | 旧路径存在，但尚未绑定当前客户端与最终配置字节 |
| 待 evidence | 官方配置机制明确，仍缺工具调用、ApiUsage 与扣费证据 |
| 待能力确认 | 尚未观察当前产品真实 outbound 合同，不生成配置 |
| 受限 | 官方合同不支持，或尚未证明任意自定义 Endpoint |
| 已验证 | 最终配置、客户端请求、用量与 Coding 余额均已核对 |

只有“已验证”方案进入模型选择并显示复制按钮。指南存在、MCP 可用或旧版本曾成功，都不等于当前 profile 已验证。

## 核心接入路线

### Claude Code

Claude Code 使用 Anthropic Messages 协议：

```bash
export ANTHROPIC_BASE_URL="https://api.acedata.cloud"
export ANTHROPIC_AUTH_TOKEN="YOUR_API_TOKEN"
claude
```

已发布配置入口：

- [CLI](https://platform.acedata.cloud/documents/claude-code-terminal-integration)
- [VS Code](https://platform.acedata.cloud/documents/claude-code-vscode-integrations)
- [JetBrains](https://platform.acedata.cloud/documents/claude-code-jetbrains-integration)
- [CC Switch](https://platform.acedata.cloud/documents/claude-code-cc-switch-integration)
- [GitHub Actions](https://platform.acedata.cloud/documents/claude-code-github-actions-integration)

### Codex

Codex 使用 OpenAI Responses 协议：

```bash
export OPENAI_BASE_URL="https://api.acedata.cloud/v1"
export OPENAI_API_KEY="YOUR_API_TOKEN"
codex
```

已发布配置入口：

- [CLI](https://platform.acedata.cloud/documents/codex-terminal-integration)
- [VS Code](https://platform.acedata.cloud/documents/codex-vscode-integration)
- [CC Switch](https://platform.acedata.cloud/documents/codex-cc-switch-integration)

### WorkBuddy 与其他路线

WorkBuddy 的已验证配置使用 OpenAI Chat Completions。保持“自定义协议”关闭，Base URL 填写 `https://api.acedata.cloud/v1`，客户端会补上标准 `/chat/completions` 路径。

其他路线：

- [Hermes Wizard](https://platform.acedata.cloud/documents/hermes-wizard-integration) · [Hermes Manual](https://platform.acedata.cloud/documents/hermes-manual-integration)
- [Coze Messages 状态](https://platform.acedata.cloud/documents/coze-messages-integration) · [Coze Chat 状态](https://platform.acedata.cloud/documents/coze-chat-integration)
- [Kilo VS Code](https://platform.acedata.cloud/documents/kilo-code-vscode-integration) · [Kilo JetBrains](https://platform.acedata.cloud/documents/kilo-code-jetbrains-integration) · [Kilo CLI](https://platform.acedata.cloud/documents/kilo-code-cli-integration)
- [Continue VS Code](https://platform.acedata.cloud/documents/continue-vscode-integration) · [Continue JetBrains](https://platform.acedata.cloud/documents/continue-jetbrains-integration)

## Cursor 限制

Cursor 当前官方 BYOK 合同未证明任意自定义 Base URL 可以稳定工作，因此配置中心不生成 Cursor 配置。实验性兼容边界见 [Cursor 兼容性说明](https://platform.acedata.cloud/documents/development_cursor_coding)。在能力得到真实验证之前，不应把聊天请求偶尔成功视为完整支持。

## API 权限范围

Coding Plan 当前关联以下公开能力：

1. Claude Messages
2. Claude Messages Count Tokens
3. Claude Chat Completions
4. OpenAI Chat Completions
5. OpenAI Responses
6. Gemini Chat Completions
7. GLM Chat Completions
8. Grok Chat Completions
9. Kimi Chat Completions
10. DeepSeek Chat Completions

具体凭证还可能受 `allowed_api_ids` 和应用权限范围限制。客户端 profile 只应展示它已验证兼容的协议和 exact model。

## 动态模型目录

使用有效的 Coding Application 凭证请求：

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_TOKEN"
```

模型目录会持续变化，不在本文维护固定数量或静态模型清单。`/v1/models` 返回全局模型目录，不会按 Coding 凭证自动裁剪；配置前仍需与凭证 API scope、所选 profile 和客户端兼容范围交叉确认。Codex 是客户端名称，不是模型 ID。

## 常见排查

### 返回余额不足

进入 [Applications 控制台](https://platform.acedata.cloud/console/applications)，找到 Coding Application 并主动续购。Coding 余额不会自动回退到通用余额。

### 客户端仍请求原地址

确认环境变量在启动客户端的同一个终端会话中生效，并完全退出后重新启动客户端。

### 模型名称不可用

使用当前 Coding 凭证重新请求 `/v1/models`，确认 exact model ID 同时存在于实时目录和当前 profile 的兼容范围中。

### Token 无法调用某个接口

确认凭证属于 Coding Application，并检查 `allowed_api_ids`、应用 API 权限和所选 profile 的协议范围。
