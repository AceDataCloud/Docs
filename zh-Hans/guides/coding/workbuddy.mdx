[WorkBuddy](https://www.codebuddy.cn/workbuddy)（腾讯 CodeBuddy 家族的桌面 AI 工作台，别名「腾讯龙虾」）是一款面向办公场景的 Agent 客户端，支持 Windows 10+ 与 macOS 12+。它内置了 Auto、混元、GLM、Kimi、MiniMax、DeepSeek 等模型，并提供**自定义模型**机制——凡是「OpenAI 兼容协议 API」都能一键接入。

Ace Data Cloud 为主流对话大模型都提供了 OpenAI 兼容入口，因此只需要一份 API Token，就能在 WorkBuddy 中同时使用 Claude、GPT、Gemini、Grok、Kimi、GLM、DeepSeek 等模型。

本文所有 UI 字段名与开关行为均来自 [WorkBuddy 官方模型配置文档](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model)，接口地址均来自 Ace Data Cloud 控制台中各服务的 API 文档。

## 申请流程

首先到 [Ace Data Cloud 控制台](https://platform.acedata.cloud/console/applications) 获取您的 API Token，留作备用。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

如果你尚未登录或注册，会自动跳转到登录页面邀请您来注册和登录，登录注册之后会自动返回当前页面。首次申请时会有免费额度赠送，可以先体验一下再决定是否购买。

## Ace Data Cloud 接口地址

WorkBuddy 的自定义模型使用 OpenAI Chat Completions 协议。本文采用官方文档推荐的默认路径补全行为：**保持“自定义协议”关闭**，接口地址只填写 Base URL：

```text
https://api.acedata.cloud/v1
```

WorkBuddy 会校验地址并自动补上标准 `/chat/completions` 路径。不要同时填写完整 endpoint 又保持“自定义协议”关闭；只有需要按原样请求非标准完整 URL 时才开启该开关。

模型目录会持续更新，因此本文不维护静态 model ID 清单。请在 Coding 配置选择器或 [实时模型目录](https://platform.acedata.cloud/models) 中选择当前存在、与 WorkBuddy 兼容且已验证的 exact model ID；目录中不存在或选择器标记为未验证的模型不要填写。

## 添加自定义模型

打开 WorkBuddy，进入 **设置 → 模型**，在「自定义模型」区域点击 **添加模型**：

![](https://cdn.acedata.cloud/48850fc532.png)

会弹出「添加模型」对话框（顶部标签明确写着「仅支持 OpenAI 兼容协议 API」，正合适 Ace Data Cloud）：

![](https://cdn.acedata.cloud/1bff6a7feb.png)

按下面的字段一一填入即可：

| 字段 | 填写内容 |
| --- | --- |
| **提供商** | 下拉选择 **自定义 / Custom** |
| **接口地址** | `https://api.acedata.cloud/v1` |
| **API KEY** | 你在 Ace Data Cloud 控制台拿到的 API Token |
| **模型名称** | 从 Coding 配置选择器或实时模型目录复制的 exact model ID |

「高级配置」里的四个复选框可按需勾选：

| 复选框 | 说明 | 建议 |
| --- | --- | --- |
| **工具调用** | 声明该模型支持 Function Calling / Tools。 | 仅当 Coding 选择器或实时目录明确标记该 exact model 支持 tools 时勾选。 |
| **图片输入** | 声明该模型支持多模态图片输入。 | 仅当 Coding 选择器或实时目录明确标记该 exact model 支持图片时勾选。 |
| **推理模式** | 声明该模型是「推理模型」（有思考过程），WorkBuddy 会以对应方式渲染。 | 仅当 Coding 选择器或实时目录明确标记该 exact model 支持推理时勾选。 |
| **自定义协议** | 关闭时按标准 `/chat/completions` 校验并自动补全接口；开启时按填写的 URL 原样发起请求。 | **保持默认关闭**，与本文填写的 Base URL 配套使用。 |

「输入」「输出」两个下拉是上下文窗口大小，留 **「使用服务默认值」** 即可，WorkBuddy 会使用所选模型当前公布的窗口配置。

点击 **保存**，回到对话界面，在模型选择器的「自定义模型」分组下就能看到你新添加的模型。挑一个开始对话，看到正常回复即接入成功。

## 一个入口，多次添加

同一个接口地址可配多个 exact model ID。如果你要在 WorkBuddy 中同时使用多个当前可用模型，把「添加模型」这一步按 Coding 选择器给出的 model ID 重复几次即可：

- 每次弹窗都选 **自定义 / Custom** 作为提供商；
- **接口地址** 与 **API KEY** 分别按上表填入（同一 API Token 全家族通用）；
- **模型名称** 填入你想用的 model ID；
- 每个 model 独立勾选它对应的能力标记。

保存后，它们会在「自定义模型」分组里一并展示，可随时切换。

## 常见问题

**Q：接口地址要写到 `/chat/completions` 吗？**

A：按本文配置不需要。「自定义协议」保持关闭时，WorkBuddy 会校验并自动补全标准 `/chat/completions`，所以填 `https://api.acedata.cloud/v1` 即可。只有当你确实要让客户端按原样请求某个完整 URL 时，才填写完整 endpoint 并开启「自定义协议」。

**Q：模型名称填错了会怎样？**

A：请求会被 Ace Data Cloud 网关拒绝，WorkBuddy 侧会看到 4xx 错误。请按上文表格里的 model ID 或 [Ace Data Cloud 控制台](https://platform.acedata.cloud/documents) 中各服务的 API 文档来填。

**Q：API Key 会不会被上传？**

A：不会。根据 [WorkBuddy 官方文档](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model)，自定义模型的配置（含 API Key）仅保存在本地的 `~/.codebuddy/models.json` 中，不上传云端；WorkBuddy 只作为通信链路把你的输入转发给填写的接口地址。

**Q：调用产生的费用怎么算？**

A：由 Ace Data Cloud 按你实际调用的 model 计费，从 Ace Data Cloud 账户余额中扣除；WorkBuddy 侧仅消耗其自身的 model 相关积分规则（自定义模型的第三方费用由你直接向第三方支付，这里的「第三方」就是 Ace Data Cloud）。
