## 获取 Ace Data Cloud API Key

1. 打开 [控制台 → 应用列表](https://platform.acedata.cloud/console/applications)，完成登录。
2. 按计费方式选择应用：使用 Coding Plan 时进入 **Coding Application**；按量使用时选择有对应服务权限的通用/服务应用。Coding 套餐与通用余额分别管理。
3. 复制该应用的 **API Key / API Token**，不要复制 Application ID 或 `platform-` 管理 Token。下文 API Key 字段只填写密钥本身，不含 `Bearer ` 前缀。
4. 确认应用有效且有额度。活动和免费额度以控制台实时显示为准。

用同一把 Key 查询模型目录：

```bash
export ACEDATACLOUD_API_KEY="YOUR_ACEDATACLOUD_API_KEY"
curl --fail-with-body https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY"
```

PowerShell 环境变量写法为 `$env:ACEDATACLOUD_API_KEY = "YOUR_ACEDATACLOUD_API_KEY"`；使用 Windows 自带 curl 时写 `curl.exe`。`/v1/models` 是模型发现入口，目录中出现某个模型不等于当前 Key 有对应 API 权限。还要核对所选协议、应用范围和客户端能力。

不要把真实 Key 提交到 Git、贴进日志或截图。

## 安装和配置目录

本页固定本轮实际安装的 PyPI 发布版 **`kimi-cli==1.50.0`**（Python 3.12+）。可用 `uv tool install "kimi-cli==1.50.0"` 安装，再运行 `kimi --version`。该发布包默认读取 `~/.kimi/config.toml`，设置 `KIMI_SHARE_DIR` 时以该目录为准；也可显式使用 `kimi --config-file /path/to/config.toml`。

在线主线文档已出现 `.kimi-code`、`openai` 和 `tool_use` 等新配置，但不适用于本次 PyPI 1.50.0。不要跨版本混用；升级后先检查实际 CLI 帮助和包内配置定义。

## 配置模型

在该文件中合并以下 TOML，Key 占位符需在本机替换：

```toml
default_model = "ace-chat"

[providers.acedatacloud]
type = "openai_legacy"
base_url = "https://api.acedata.cloud/v1"
api_key = "YOUR_ACEDATACLOUD_API_KEY"

[models.ace-chat]
provider = "acedatacloud"
model = "gpt-4.1-mini"
max_context_size = 128000
```

`ace-chat` 是本地别名，`model` 才是发给 API 的精确 ID。此例保守设置 128K 上下文；换模型后按实际能力调整，不能复制 Kimi 官方订阅的 1M 配置到任意模型。本发布版的 `openai_legacy` 对应 Chat Completions，`openai_responses` 是另一协议，不能只改名称就视为验证成功。

## 首次使用

进入测试项目运行 `kimi`，选择 `ace-chat`；先完成简单问答，再做文件读取。接入第三方端点不需要把 Ace Data Cloud Key 当作 Kimi 官方 OAuth 登录凭据。

2026-09-07 在隔离配置目录用上述 Provider 和 `gpt-4.1-mini` 实际返回 `ADC_KIMI_OK`。这是文本请求实测，尚未覆盖本客户端的文件读写工具循环。

> 读取 fixture.txt，逐字引用其内容并解释文件用途。不要修改任何文件。

检查是否真的读取文件、是否引用正确内容；然后到 [平台使用历史](https://platform.acedata.cloud/console/usages) 按时间核对请求。对不支持文件工具的聊天模式，先附加该文件，再提同样的问题。不要用一次简单聊天成功推断编辑、图片、工具、自动补全全部可用。

| 现象 | 排查 |
|---|---|
| 401 | API Key 是否完整、是否重复 Bearer 前缀、进程是否读取到变量 |
| 403 / 额度错误 | Key 所属应用、套餐有效期、API 权限与余额 |
| 404 | Base URL 是否重复 `/v1` 或拼入了不该填写的完整接口路径；模型 ID 是否正确 |
| 聊天成功但 Agent 失败 | 检查当前模型的工具调用能力与客户端模式，先完成上面的只读测试 |
| 修改未生效 | 重启客户端；Remote/WSL/容器的配置和变量通常需要放在实际运行端 |
