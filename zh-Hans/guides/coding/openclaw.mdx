## 获取 Ace Data Cloud API Key

1. 打开 [控制台 → 应用列表](https://platform.acedata.cloud/console/applications)，完成登录。
2. 按计费方式选择应用：使用 Coding Plan 时进入 **Coding Application**；按量使用时选择有对应服务权限的通用/服务应用。Coding 套餐与通用余额分别管理。
3. 复制该应用的 **API Key / API Token**，不要复制 Application ID 或 `platform-` 管理 Token。下文 API Key 字段只填写密钥本身，不含 `Bearer ` 前缀。
4. 确认应用有效且有额度。活动和免费额度以控制台实时显示为准。

用同一把 Key 查询模型目录：

```bash
export ACEDATACLOUD_API_KEY="YOUR_ACEDATACLOUD_API_KEY"
curl --fail-with-body https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY"
```

PowerShell 环境变量写法为 `$env:ACEDATACLOUD_API_KEY = "YOUR_ACEDATACLOUD_API_KEY"`；使用 Windows 自带 curl 时写 `curl.exe`。`/v1/models` 是模型发现入口，目录中出现某个模型不等于当前 Key 有对应 API 权限。还要核对所选协议、应用范围和客户端能力。

下文 `MODEL_ID` 必须替换为具体模型 ID。不要把真实 Key 提交到 Git、贴进日志或截图。

## 版本与运行环境

本轮实测组合为 **OpenClaw 2026.9.2 + @acedatacloud/openclaw-provider 2026.5.34 + Node.js 26**（macOS 隔离环境）。OpenClaw 主程序的 Node 要求高于插件自身；旧教程 Node 20+ 已不适用。

```bash
node --version
npm install -g openclaw@2026.9.2
openclaw --version
```

这是本次验证版本，不是要求永久固定；升级后重做后面的检查。

## 安装插件

```bash
openclaw plugins install npm:@acedatacloud/openclaw-provider@2026.5.34 --pin
```

OpenClaw 2026.9.2 对 npm 来源会提示审查来源，对声明的能力还需同意授权。确认包名、发布者和 [插件源码](https://github.com/AceDataCloud/OpenClawProvider) 后，本轮非交互安装使用：

```bash
openclaw plugins install npm:@acedatacloud/openclaw-provider@2026.5.34 \
  --pin --force --accept-capabilities
```

`--force` 在这里表示确认 npm 来源，不是跳过平台鉴权；`--accept-capabilities` 接受插件能力声明。若已运行 Gateway，安装后按提示重启 Gateway。无需为了测试模型而安装聊天渠道或系统守护服务。

## 配置 Key 并检查

在同一终端设置：

```bash
export ACEDATA_API_KEY="$ACEDATACLOUD_API_KEY"
openclaw plugins info acedatacloud --runtime
openclaw models list --all --provider acedatacloud
```

插件支持 `ACEDATA_API_KEY` 与 `ACEDATACLOUD_API_KEY`。本轮运行时显示 `text-inference`、`web-search` 两项能力；不要把插件描述中的 image/video/music 文字当作已注册能力。

需要持久化配置时可用 `openclaw onboard --auth-choice acedatacloud-api-key` 按提示输入 Key。`--acedata-api-key` 属于 onboarding 参数，不是所有子命令都能使用的全局参数。

## 已跑通：一次模型调用

```bash
openclaw infer model run --model acedatacloud/gpt-4.1-mini \
  --prompt "Reply only ADC_OPENCLAW_OK" --json
```

2026-09-07 实际结果：

```json
{
  "ok": true,
  "capability": "model.run",
  "transport": "local",
  "provider": "acedatacloud",
  "model": "acedatacloud/gpt-4.1-mini",
  "attempts": [],
  "outputs": [
    {
      "text": "ADC_OPENCLAW_OK",
      "mediaUrl": null
    }
  ]
}
```

运行日志确认请求发送到 `https://api.acedata.cloud/v1/chat/completions` 并返回 HTTP 200。`infer model run` 是单次模型请求，不包含 Agent 工具循环；下一步再验证：

```bash
openclaw agent --local --session-id adc-first-task \
  --model acedatacloud/gpt-4.1-mini --json \
  -m "Reply only ADC_AGENT_OK"
```

本轮还用 `agent --local` 执行了真实文件任务：在隔离目录创建文件，内容为 `ADC actual file contents 7093`，要求读取该文件但不把内容写入提示词。运行结果逐字返回该内容，记录显示调用 `read` 1 次、工具失败 0 次、没有使用备用 Provider。该结果验证此版本的本地 Agent 文件读取；不代表聊天渠道、全部工具和后台 Gateway 都已验证。

需要默认使用该模型时运行 `openclaw models set acedatacloud/gpt-4.1-mini`。网页搜索应先查看 `openclaw infer web providers --json`，配置/选择 `acedatacloud` 后再调用；它需要搜索服务权限，不能仅靠模型调用成功推断已获授权。

## 实战与验收

先新建一个测试目录，在 `fixture.txt` 写入 `hello from Ace Data Cloud`，然后让客户端执行：

> 读取 fixture.txt，逐字引用其内容并解释文件用途。不要修改任何文件。

检查是否真的读取文件、是否引用正确内容；然后到 [平台使用历史](https://platform.acedata.cloud/console/usages) 按时间核对请求。对不支持文件工具的聊天模式，先附加该文件，再提同样的问题。不要用一次简单聊天成功推断编辑、图片、工具、自动补全全部可用。

| 现象 | 排查 |
|---|---|
| 401 | API Key 是否完整、是否重复 Bearer 前缀、进程是否读取到变量 |
| 403 / 额度错误 | Key 所属应用、套餐有效期、API 权限与余额 |
| 404 | Base URL 是否重复 `/v1` 或拼入了不该填写的完整接口路径；模型 ID 是否正确 |
| 聊天成功但 Agent 失败 | 检查当前模型的工具调用能力与客户端模式，先完成上面的只读测试 |
| 修改未生效 | 重启客户端；Remote/WSL/容器的配置和变量通常需要放在实际运行端 |
