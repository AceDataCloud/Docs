Codex Desktop 会读取 Codex 的 `config.toml`，因此可以尝试复用自定义 `model_provider`。当前路线为**实验性**：官方仓库已有 Desktop 使用 custom provider 的记录，但也存在凭据来源混用、配置被重写和自动化忽略 provider 的已知问题。

## 候选配置

在 `~/.codex/config.toml` 中配置：

```toml
model = "MODEL_ID"
model_provider = "acedatacloud"

[model_providers.acedatacloud]
base_url = "https://api.acedata.cloud/v1"
env_key = "ACEDATACLOUD_API_KEY"
wire_api = "responses"
```

并在启动 Codex Desktop 前设置 `ACEDATACLOUD_API_KEY`。

## 验证范围

1. 使用本地 workspace/thread，不把 cloud thread 或 automation 视为同一合同。
2. 确认 Desktop 显示所选 Provider 与模型。
3. 发送 `Reply only OK`，再执行一次文件读取或编辑。
4. 重启 Desktop，确认 `config.toml` 未被改写。
5. 若存在其他登录凭据，核对实际使用的 credential source。

## 已知边界

- Desktop 的本地 thread、remote/cloud thread、automation 和 review 命令可能采用不同执行路径。
- 当前文档不承诺所有 Desktop 功能都遵循 custom provider。
- 若 Desktop 忽略或重写配置，请改用已验证的 Codex CLI 或 VS Code Extension。
