本教程配置 Codex 桌面应用的本地任务，通过 Ace Data Cloud 的 **OpenAI Responses** 接口调用模型。先取得平台 Key，再设置用户级 Provider，最后检查真实请求。MCP 另按 [Codex MCP 教程](https://platform.acedata.cloud/documents/codex-mcp-all) 配置。

## 获取 Ace Data Cloud API Key

1. 打开 [控制台 → 应用列表](https://platform.acedata.cloud/console/applications)，完成登录。
2. 按计费方式选择应用：使用 Coding Plan 时进入 **Coding Application**；按量使用时选择有对应服务权限的通用/服务应用。Coding 套餐与通用余额分别管理。
3. 复制该应用的 **API Key / API Token**，不要复制 Application ID 或 `platform-` 管理 Token。下文 API Key 字段只填写密钥本身，不含 `Bearer ` 前缀。
4. 确认应用有效且有额度。活动和免费额度以控制台实时显示为准。

用同一把 Key 查询模型目录：

```bash
export ACEDATACLOUD_API_KEY="YOUR_ACEDATACLOUD_API_KEY"
curl --fail-with-body https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY"
```

PowerShell 环境变量写法为 `$env:ACEDATACLOUD_API_KEY = "YOUR_ACEDATACLOUD_API_KEY"`；使用 Windows 自带 curl 时写 `curl.exe`。`/v1/models` 是模型发现入口，目录中出现某个模型不等于当前 Key 有对应 API 权限。还要核对所选协议、应用范围和客户端能力。

下文 `MODEL_ID` 必须替换为具体模型 ID。不要把真实 Key 提交到 Git、贴进日志或截图。
## 1. 安装并找到用户配置

从 [Codex 官方入口](https://developers.openai.com/codex/app/) 安装适合当前系统的桌面应用。打开 Codex 设置中的配置入口；也可直接编辑用户配置：

- macOS / Linux 配置路径：`~/.codex/config.toml`。
- Windows 配置路径：`%USERPROFILE%\.codex\config.toml`。
- 如果设置了 `CODEX_HOME`，以该目录为准。

桌面应用是否支持当前操作系统，以官方下载页面为准。修改前备份已有文件，将以下字段合并进去，保留自己的其他设置；不要在同一文件重复定义同名 Provider 表。Provider 应放用户级配置，不放项目 `.codex/config.toml`。

## 2. 配置模型与 Provider

```toml
model = "gpt-5.4-mini"
model_provider = "acedatacloud"

[model_providers.acedatacloud]
name = "Ace Data Cloud"
base_url = "https://api.acedata.cloud/v1"
env_key = "ACEDATACLOUD_API_KEY"
wire_api = "responses"
```

`gpt-5.4-mini` 是配置示例，先确认模型与应用权限。如果换模型，填写 Responses 路径实际支持的 ID。`base_url` 到 `/v1` 为止，客户端会拼接 `/responses`。`env_key` 是变量名称，不是密钥值。

## 3. 让桌面应用能读取 Key

桌面应用通常不会自动读取你在另一个终端临时 `export` 的变量。可在用户级 `~/.codex/.env`（Windows 对应用户目录下 `.codex\.env`）中保存：

```dotenv
ACEDATACLOUD_API_KEY=YOUR_ACEDATACLOUD_API_KEY
```

这是用户配置目录，不是项目内的 `.env`。不要将它放到共享仓库。macOS/Linux 可运行 `chmod 600 ~/.codex/.env` 限制读取权限。完全退出 Codex 后重新打开，让配置生效。

使用 `env_key` 时不需要运行 `codex login --with-api-key`，也不需要把平台 Key 写到 `auth.json`。已有 ChatGPT 登录可供其支持的功能使用；当前 Provider 的模型请求应从上述变量取 Key，不要混入另一套 `requires_openai_auth = true` 配置。

## 4. 实战：读一个测试文件

1. 建立一个空的本地测试目录，创建 `fixture.txt`，内容为 `hello from Ace Data Cloud`。
2. 在 Codex 打开该目录，并创建新的**本地任务**。
3. 输入：`读取 fixture.txt，逐字回复它的内容；不要修改文件。`
4. 检查文件读取记录和回复，再到 [使用历史](https://platform.acedata.cloud/console/usages) 对照时间、模型与请求状态。
5. 重启 Codex，再次创建本地任务，检查配置仍生效。

只有看到文件读取和真实模型回复，才能认为这条路径通过。设置中显示 Provider 名称，或模型下拉框中出现模型，单独都不足以证明请求已走 Ace Data Cloud。

## 排错与适用范围

| 问题 | 处理 |
|---|---|
| 缺少环境变量 / 401 | 检查用户级 `.env`、变量拼写和 Key；完全退出再启动 |
| 请求仍走旧 Provider | 检查活动配置、用户级文件与 `CODEX_HOME`，新建本地任务再测 |
| 404 / unsupported model | 检查 `/v1` 是否重复、模型是否支持 Responses、Key 是否有该接口权限 |
| 普通回复成功，文件工具失败 | 分别检查模型工具能力和本地目录权限；不要用扩大权限掩盖协议问题 |
| 云端、远程任务或自动化行为不同 | 这些执行环境可能使用不同配置与凭据，需在各自运行环境单独配置验证 |
