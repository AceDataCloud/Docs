`POST https://api.acedata.cloud/suno/projects` 是管理多轨工程的 Beta 接口。一个端点通过 `action` 区分创建、保存、生成候选、提交候选和导出。调用方只需使用下面的公开字段，不需要填写底层生成服务的内部请求结构。

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: 每次修改操作使用新的 UUID
```

除 `retrieve` 外，**每次操作都需要** `Idempotency-Key`。相同键和相同请求只回读原结果；相同键配不同请求返回 409。收费生成遇到网络超时或提交结果不确定时，先用原任务 ID 或同一幂等键查询，不能直接换键重发。

## 先区分这些 ID 和时间单位

| 名称 | 从哪里取得 | 用在哪里 |
|---|---|---|
| `id` | `create` 响应 `data.id` | 当前工程的所有后续请求 |
| `version_id` | 最近一次 `retrieve`、`save`、`add_track`、`commit_candidate` 或 `remove_track` 的 `data.version_id` | 修改、生成候选和导出；必须使用最新版本 |
| `audio_id` / `source_audio_id` | `upload` 终态 `response.data.candidate.audio_id`，或已有的已完成音频 ID | `add_track`、生成或替换时引用原音频 |
| `render_audio_id` | `render` 终态 `response.data.audio_id` | `generate_track` 的工程混音参考 |
| `operation_id` | `generate_track` 或 `replace_section` 终态 `response.data.operation_id` | `commit_candidate`；通常与生成任务的 `task_id` 相同，但应读取返回值 |
| `candidate_id` | 生成终态 `response.data.candidates[].id` | 选择一个候选提交 |
| `track_id` | 工程 `data.state.tracks[].id` | 提交候选或删除轨道 |
| `task_id` | 异步操作提交响应 | 使用 `/suno/tasks` 查询终态；它不是工程 ID |

`start_seconds` / `end_seconds` 是**源音频内的秒数**；`start_beats` / `end_beats` 是**工程时间线上的拍数**。`state.timing.bps` 是每秒拍数，默认 2。例如 41 秒的片段从第 0 拍开始，默认终点为第 82 拍。`generate_track` 的秒数区间用于指定生成参考，不保证候选只有该区间的长度。

## 操作顺序和结果判断

| 顺序 | `action` | 作用 | 返回方式 |
|---|---|---|---|
| 1 | `create` | 创建空工程 | 同步工程数据 |
| 2 | `retrieve` | 读取最新版本和完整 `state` | 同步工程数据 |
| 3 | `save` | 首次保存或整体保存修改后的 `state` | 同步工程数据 |
| 4 | `upload` | 从 HTTPS 音频地址创建素材 | 异步任务 |
| 5 | `add_track` | 将素材音频放入工程 | 异步任务，更新版本 |
| 6 | `save` | 如需接收新轨候选，先保存一个空目标轨道 | 同步工程数据，更新版本 |
| 7 | `render` | 导出当前可听轨道，取得混音参考 `audio_id` | 异步任务 |
| 8 | `generate_track` 或 `replace_section` | 分别生成新轨候选或局部替换候选 | 异步任务，暂不修改工程 |
| 9 | `commit_candidate` | 选择并提交一个候选 | 异步任务，成功后更新版本 |
| 可选 | `remove_track` | 删除指定轨道 | 同步工程数据，更新版本 |

如果只做局部替换，已有可用源音频即可，不需要先 `render`；如果源音频已在工程中，也可跳过 `upload` 和 `add_track`。`render_audio_id` 仅是 `generate_track` 的必填参考。

异步操作提交时先返回 `{ "task_id": "...", "trace_id": "..." }`，**不表示生成成功**。轮询：

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步返回的 task_id"}
```

任务记录有 `finished_at`，且其中的 `response.success` 为 `true`，才算成功；`response.success=false` 时读取 `response.error`。`save` 虽可能带 `task_id`，但它在本接口内同步完成。`upload`、`render`、`generate_track`、`replace_section` 不修改工程版本；`save`、`add_track`、`commit_candidate`、`remove_track` 成功后应取新 `version_id`。

## 请求参数

### 通用字段与请求头

| 参数 | 类型与适用范围 | 说明 |
|---|---|---|
| `action` | 必填字符串 | 固定为本页列出的一个操作名；一次请求只执行一个操作。 |
| `id` | 除 `create` 外必填字符串 | 工程 ID，来自 `create.data.id`。 |
| `version_id` | 修改、生成候选、导出时必填字符串；首次空工程 `save` 可省略 | 使用最新版本，旧版本会被拒绝。`retrieve` 不需要它。 |
| `Idempotency-Key` | 除 `retrieve` 外必填请求头，1–128 字符 | 每个新操作用新键；同键同请求回读原结果，不重新生成或扣费。 |
| `async` | `upload`、`add_track`、`generate_track`、`replace_section`、`commit_candidate`、`render` 可选布尔值 | 这些操作始终异步；`false` 也不会把生成变成同步。 |
| `callback_url` | 上述可选异步字段所在操作的可选 URL | 接收终态通知；省略时按 `task_id` 查询 `/suno/tasks`。仍须检查 `response.success`。 |

### 工程和素材

| `action` | 专属参数 | 类型与条件 | 说明 |
|---|---|---|---|
| `create` | `title` | 必填字符串，1–200 字符 | 新工程标题。 |
| `retrieve` | 无 | — | 只需 `action` 与工程 `id`；返回完整可编辑 `state`。 |
| `save` | `state` | 必填对象 | **整体替换**工程状态，不是局部补丁。以最近一次 `retrieve.data.state` 为基础修改并完整提交，保留未知字段。 |
| `save` | `title` | 可选字符串 | 工程标题；省略时沿用 `state.title`，若也没有则使用默认标题。 |
| `upload` | `audio_url` | 必填 HTTPS URL | 可公开访问的音频素材地址；成功后读取终态 `candidate.audio_id`。素材应由调用方拥有使用权。 |
| `add_track` | `audio_id` | 必填字符串 | 已完成素材的音频 ID，不是 URL。 |
| `add_track` | `name` / `color` | 可选字符串 | 新轨道名称、颜色；名称默认取音频标题，颜色建议 `#RRGGBB`，默认 `#7251F7`。 |
| `add_track` | `title` | 可选字符串 | 同时修改工程标题；通常省略。 |
| `add_track` | `start_beats` / `end_beats` | 可选非负数字，`end_beats > start_beats` | 片段在工程时间线的位置。起点默认 0；终点默认 `起点 + 音频时长 × timing.bps`。 |
| `add_track` | `gain` | 可选非负数字，默认 1 | 片段及新轨道的音量系数。 |
| `remove_track` | `track_id` | 必填字符串 | 要删除的现有轨道 ID。成功后使用返回的新版本。 |

`state.timing.bps` 必须为正数，默认 2。`state.tracks` 是轨道数组；已有音频片段的 `clipId` 引用音频 ID，`startBeats`、`endBeats`、`readStartBeats` 使用工程拍单位。最安全的编辑方式是读取完整 `state`，只修改目标轨道或片段，再整体 `save`。新增空目标轨道至少应有唯一 `id`、`type:"audio"`、`clips:[]`；真实可用的完整形状见下文第 5 步。不要把音频分析结果中的拍点直接当工程时间线坐标。

### 生成、提交和导出

| `action` | 专属参数 | 类型与条件 | 说明 |
|---|---|---|---|
| `generate_track` / `replace_section` | `source_audio_id` | 必填字符串 | 已完成的源音频 ID。先把源音频加入工程，后续候选才能找到对应位置。 |
| `generate_track` / `replace_section` | `model` | 必填枚举字符串 | 可选 `chirp-v3-5`、`chirp-v4`、`chirp-v4-5`、`chirp-v4-5-plus`、`chirp-v5`、`chirp-v5-5`、`chirp-v6`、`chirp-v6-wild`、`chirp-v6-mini`。模型和操作是否可用以任务终态为准；不会自动改用其他模型。 |
| `generate_track` / `replace_section` | `start_seconds` / `end_seconds` | 必填数字，`0 ≤ start_seconds &lt; end_seconds` | 源音频内的起止秒数；替换时终点还必须不超过源音频实际时长。它们不是工程拍数，也不保证候选输出时长。 |
| `generate_track` | `render_audio_id` | 必填字符串 | 当前工程成功 `render` 后的 `response.data.audio_id`，作为生成时的混音参考。 |
| `generate_track` | `stem_control_tags` | 必填字符串 | 新增声部描述，例如 `add Piano`、`add Drums`、`add Bass`；不是固定枚举。 |
| `generate_track` | `batch_size` | 可选整数 1–4，默认 2 | 请求生成的候选数量。 |
| `generate_track` | `instrumental` / `vocal_gender` | 可选布尔值／枚举字符串 | `instrumental` 默认 `true`；声乐偏好可填 `f`、`m`、`unspecified`，默认 `unspecified`。是否遵循偏好以实际音频为准。 |
| `generate_track` / `replace_section` | `title` / `tags` / `negative_tags` | 可选字符串 | 候选标题、期望风格描述、希望避开的风格标签。`tags` 与 `negative_tags` 省略时传空字符串。 |
| `generate_track` | `prompt` | 可选字符串 | 新声部的文本或歌词提示；纯器乐可省略。 |
| `replace_section` | `prompt` / `replacement_lyrics` | 可选字符串 | 前者是原歌曲歌词或上下文文本，后者是替换区间的新歌词；省略时传空字符串。 |
| `replace_section` | `fixed` | 可选布尔值，默认 `false` | 请求固定长度替换；`true` 时区间须短于 26 秒，且所选模型可能不支持。本次真实样例使用默认模式，`fixed=true` 尚未验证。 |
| `commit_candidate` | `operation_id` / `candidate_id` | 必填字符串 | 分别取生成终态的 `data.operation_id` 和选中的 `data.candidates[].id`；候选必须属于当前工程版本。 |
| `commit_candidate` | `track_id` | 必填字符串 | 新轨候选应提交到**生成前已保存的空轨道**；局部替换候选提交到包含唯一源片段的原轨道。 |
| `commit_candidate` | `start_beats` / `end_beats` | 仅新轨候选可选的非负数字 | 指定新片段在工程时间线的位置；省略时沿用源片段起点，并按候选实际时长计算终点。不得与目标轨道已有片段重叠。**局部替换候选必须省略**。 |
| `commit_candidate` | `name` / `gain` | 仅新轨候选可选的字符串／非负数字 | 生成片段名称和音量系数，`gain` 默认 1。 |
| `render` | `title` | 必填字符串 | 导出音频标题。 |
| `render` | `lyrics` / `tags` | 可选字符串 | 导出时的歌词文本和风格描述；歌词默认 `[Instrumental]`。 |
| `render` | `start_beats` / `end_beats` | 可选非负数字，结束须大于开始 | 导出工程拍数范围；省略时取所有可听片段的最早起点和最晚终点。静音片段不参与，存在 solo 轨道时仅选择 solo 轨道。 |

生成只产生候选，**不会自动放入工程**。`commit_candidate` 会检查候选仍属于当前版本。局部替换候选只有在实际时长与完整源音频或选中区间可可靠匹配时才能自动提交；不匹配时保留原工程并返回错误，不能靠手动猜测拍数强行拼接。

## 2026-10-09 真实请求与响应

以下请求体和响应字段均取自同一工程的真实调用。每组 JSON 依次为请求、受理响应（若异步）、任务终态响应。为便于阅读，响应只摘录完成本流程所需的字段；账户、用量和耗时字段未展示。示例 ID 属于本次测试应用，接入时必须用自己请求返回的 ID 和新的 `Idempotency-Key`。

### 1. 创建并读取空工程：`create`、`retrieve`

  "action": "create",
  "title": "Suno Projects Documentation Verification 2026-10-09"
}

## 错误与恢复

| 结果 | 含义 | 下一步 |
|---|---|---|
| `project_version_conflict` / `project_candidate_stale`（409） | 工程版本已变化，或候选不属于当前版本。 | `retrieve` 最新工程并重新规划修改；不要重放旧候选。 |
| `bad_request` / `studio_state_invalid` / `studio_model_unsupported`（通常 400） | 参数、轨道状态、候选时长或模型与操作不匹配。 | 查看任务终态错误，修正输入；候选无法安全拼接时保留原工程。 |
| `studio_audio_unavailable` / `studio_access_denied` / `content_rejected`（403） | 引用音频不可用于该工程操作、无权访问，或内容检查拒绝。 | 检查音频来源和任务 `trace_id`；不要把已生成候选等同于整曲可导出。 |
| `too_many_requests`（429） | 请求受到频率限制。 | 先查询原任务，再决定是否以新幂等键发起新操作。 |
| `studio_unavailable` / `studio_model_unavailable`（503） | 工程处理或所选模型暂时不可用。 | 保留原任务结果；稍后显式重试，不自动切换模型。 |
| `studio_processing_failed` / 超时（500/504） | 处理失败或终态不确定。 | 按 `task_id` 或原幂等键查询，避免重复收费生成。 |

工程和候选与创建它们的应用及执行环境绑定，不能假定跨应用复用或自动故障切换。请持久化成功导出的最终音频 URL，并保留 `trace_id` 便于排查。
