定时任务（`/aichat2/scheduled-tasks`）让你的 AI Agent 在无人值守的情况下**按计划自动运行**——每天汇总新闻、每周生成报告、每小时监控数据等任务，全部交给平台在后台自动完成，完成后推送通知让你直接看结果。

## 功能简介

- **全能力 agentic 执行**：定时任务复用 [AI Chat v2](/documents/aichat2-conversations) 的完整工具链（网页搜索、读取文件、调用 MCP 服务器等），不仅仅是普通问答。
- **灵活的调度规则**：支持每天（`daily`）、每小时（`hourly`）、每周（`weekly`）以及自定义 Cron 表达式。
- **推送通知**：任务完成后通过 Web Push / FCM / APNs 推送到你的浏览器和手机，点击即可跳转到结果对话。
- **模板变量**：在提示词中使用 `{{date}}`（今日日期）、`{{run_count}}`（第几次运行）、`{{last_output}}`（上次输出摘要）实现动态提示。
- **透明计费**：每次运行按实际使用的模型和 token 数计费，与手动发起的对话价格完全相同。在控制台「用量」页可看到以「Scheduled Task」为来源的独立记录。

## 申请方式

同 AI Chat v2，在 [Ace Data Cloud 控制台](https://platform.acedata.cloud/console/applications) 申请 aichat API 权限，获取 API Token 即可同时使用对话和定时任务功能。

## 通过 Nexior 使用

打开 [Nexior](https://studio.acedata.cloud/chatgpt/scheduled)，在左侧对话列表顶部点击「定时任务」（时钟图标）进入管理页。

1. 点击「新建」，填写任务名称、提示词、模型和执行频率。
2. 保存后任务立即生效，下一次调度时间按你设定的频率自动计算。
3. 点击任一任务卡片可查看历次运行记录（时间、状态、结果链接）。
4. 随时通过开关暂停 / 恢复，或点击删除按钮永久移除。

## 通过 API 使用

所有操作统一走 `POST /aichat2/scheduled-tasks`，用 `action` 字段区分。

### 创建定时任务

```bash
curl https://api.acedata.cloud/aichat2/scheduled-tasks \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "create",
    "name": "每日资讯汇总",
    "schedule": {
      "type": "cron",
      "cron": "0 9 * * *",
      "tz": "Asia/Shanghai"
    },
    "template": {
      "model": "gpt-4o-mini",
      "question": "今天是 {{date}}。请搜索并汇总今日 AI 领域最重要的 3 条新闻，用中文概括每条的核心内容（100 字以内）。",
      "max_turns": 5
    }
  }'
```

**响应示例：**

```json
{
  "id": "c3a4b5d6-...",
  "name": "每日资讯汇总",
  "state": "enabled",
  "schedule": { "type": "cron", "cron": "0 9 * * *", "tz": "Asia/Shanghai" },
  "run_count": 0,
  "created_at": 1750000000
}
```

`created_at` 是这条定时任务规则的创建时间（Unix 时间戳，秒），与某一次执行的耗时无关——
单次执行的计时字段请查询对应的运行记录。

### 调度类型说明

| `schedule.type` | 必填字段 | 说明 |
|---|---|---|
| `cron` | `cron`（标准 5 段 Cron 表达式）, `tz` | 最灵活，如 `0 9 * * 1-5`（工作日每天 9:00） |
| `interval` | `interval_seconds`, `tz` | 固定间隔，如 `3600`（每小时） |
| `once` | `at`（Unix 时间戳）, `tz` | 仅运行一次 |

> 所有调度时间自动加 ±60 秒抖动，防止大量任务同时触发。

### 列出所有任务

```bash
curl -X POST https://api.acedata.cloud/aichat2/scheduled-tasks \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{"action": "retrieve_batch"}'
```

### 更新任务

```bash
curl -X POST https://api.acedata.cloud/aichat2/scheduled-tasks \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "update",
    "id": "{task_id}",
    "state": "disabled"
  }'
```

### 查看运行历史

```bash
curl -X POST https://api.acedata.cloud/aichat2/scheduled-tasks \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{"action": "retrieve_runs", "id": "{task_id}"}'
```

**响应示例（单次运行）：**

```json
{
  "id": "exec-uuid",
  "status": "success",
  "scheduled_at": 1750032000,
  "conversation_id": "conv-uuid"
}
```

通过 `conversation_id` 可到 AI Chat v2 接口拿到完整的对话内容，也可直接在 Nexior 查看。

### 查看全部运行记录（跨任务）

不带 `id`，按时间倒序返回当前用户名下所有定时任务的运行记录，每条附带所属任务名称 `task_name`，可按状态筛选并分页：

```bash
curl -X POST https://api.acedata.cloud/aichat2/scheduled-tasks \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{"action": "retrieve_runs_batch", "status": "failed", "offset": 0, "limit": 30}'
```

| 参数 | 说明 |
|---|---|
| `status` | 可选，取值 `queued` / `running` / `success` / `failed`，不传返回全部 |
| `offset` | 可选，跳过条数，默认 `0` |
| `limit` | 可选，每页条数，默认 `30`，最大 `100` |

**响应示例：**

```json
{
  "items": [
    {
      "id": "exec-uuid",
      "task_id": "task-uuid",
      "task_name": "每日邮件摘要",
      "status": "failed",
      "scheduled_at": 1750032000,
      "error_code": "timeout",
      "conversation_id": "conv-uuid",
      "conversation_title": "每日邮件摘要",
      "run_accounts": [
        {
          "connector_identifier": "zhihu/zhihu",
          "provider_alias": "zhihu",
          "label": "主号",
          "account_name": "Germey"
        }
      ]
    }
  ],
  "count": 12
}
```

`count` 是筛选条件下的总条数，用于分页。

`run_accounts` 表示这次运行使用的连接账号，在运行创建时按当时的
`unattended_policy.connection_bindings` 快照记录——之后修改任务绑定不会改写已有记录。
未指定账号的任务（使用各连接器的默认账号）不返回该字段；该功能上线之前产生的历史记录同样没有该字段。
账号名取自连接的当前信息，若账号已被删除则只返回 `connector_identifier` 与 `provider_alias`；
若账号信息暂时查询不到，则整个字段不返回（以免与「账号已删除」混淆）。

> **指定的账号失效时不会改用其他账号。** 若任务通过 `connection_bindings` 指定了某个账号，而运行时该连接已过期、被撤销或已删除，该连接器的凭据将不会注入，依赖它的技能会失败 —— 而不是回退到该连接器的默认账号。这样运行记录上显示的账号始终就是实际使用的账号。未指定账号的任务不受影响，仍使用默认账号。

### 删除任务

```bash
curl -X POST https://api.acedata.cloud/aichat2/scheduled-tasks \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{"action": "delete", "id": "{task_id}"}'
```

## 模板变量

| 变量 | 替换值 |
|---|---|
| `{{date}}` | 当天日期（本地化格式，如 `2026/6/22`） |
| `{{date_iso}}` | ISO 日期（如 `2026-06-22`） |
| `{{run_count}}` | 当前是第几次运行（从 1 开始） |
| `{{task_name}}` | 任务名称 |
| `{{last_output}}` | 上次运行结果的前 500 字摘要（首次运行时为空） |

## 注意事项

- **无人值守模式**：定时任务运行时没有人能回答提问。如果 AI 中途调用 `ask_user_question`（请求你确认）或 `request_user_consent`（请求第三方授权），该次运行会停在等待输入的状态并被记为失败（`awaiting_user_input`），不会继续往下跑。要避免这种情况，请把任务提示词写得足够明确——把可选项、账号、范围都事先定死，不要留下需要追问的空白；需要第三方授权的场景，先手动发起一次对话完成授权，再创建定时任务。
- **余额**：每次运行前会检查账户余额。余额不足时该次运行会标记为失败，并通过推送通知提醒你充值。连续 5 次失败后任务自动暂停。
- **`ends_at` 默认值**：未设置结束时间时，任务默认在创建后 3 个月自动停止，防止遗忘的僵尸任务持续扣费。可在创建时通过 `ends_at`（Unix 时间戳）延长。
- **最大运行时长**：单次运行最长 15 分钟。

## 计费

定时任务与普通 AI Chat v2 使用完全相同的价格体系，按模型和 token 数计费。在控制台用量页，定时任务产生的记录会以「AceChat Scheduled Run」独立展示，便于区分手动对话和自动运行的消耗。
