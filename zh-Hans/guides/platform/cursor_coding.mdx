Cursor 当前提供 OpenAI API Key 与 **Override OpenAI Base URL** 设置，可连接 OpenAI-compatible 服务。该能力存在，但不同版本对 `/chat/completions`、`/responses`、模型列表以及 Agent/Composer 等模式的处理并不完全一致。

不同 Cursor 版本、操作系统和请求模式的兼容范围可能不同。请按本页配置完成实际模式检查，不要根据单次聊天成功推断所有功能均可用。

## Cursor 官方 BYOK 当前保证什么

根据 [Cursor 官方 Bring your own API key 文档](https://cursor.com/help/models-and-usage/api-keys)：

- 支持 OpenAI、Anthropic、Google、Azure OpenAI 和 AWS Bedrock 的凭据；
- 自定义 API Key 仅用于聊天模型，Tab completion 继续使用 Cursor 内置模型；
- API Key 不持久化在 Cursor 服务器，但每次请求会把 Key 发送到 Cursor 后端，用于最终 prompt building；
- 使用自有 Key 时，Cursor 的 Zero Data Retention 政策不适用，数据处理遵循所选提供商的政策。

## 配置

1. 打开 Cursor Settings → Models。
2. 在 OpenAI API Key 中填写你的 Ace Data Cloud API Token。
3. 启用 **Override OpenAI Base URL**，填写 `https://api.acedata.cloud/v1`。
4. 选择或添加与当前 Cursor 协议兼容的精确模型 ID。
5. 先发送 `Reply only OK`，再分别测试 Ask/Edit/Agent 等你实际使用的模式。

## 当前边界

- 自定义 API Key 仅用于聊天模型，Tab completion 继续使用 Cursor 内置模型。
- Cursor 仍可能在服务端完成最终 prompt building；请结合官方隐私说明评估数据路径。
- Base URL Override 可能只覆盖部分请求，或因版本变化在 Chat Completions/Responses 间切换。
- 不应仅凭一个聊天请求成功，就宣称 Agent、Auto、Composer 或后台任务均已接通。

## 完整兼容性检查

若要在生产工作流中长期使用，请同时完成以下检查：

1. 固定 Cursor 版本和操作系统；
2. 对该版本完成真实客户端 smoke，并记录最终请求协议与路径；
3. exact model 的 Chat Completions 请求成功；
4. 工具调用与 Agent 请求确实经过目标 endpoint；
5. 用量和扣费可核对；
6. 明确记录请求是否经过 Cursor 服务器及对应隐私限制。

客户端升级后应重新执行这些检查，确认请求协议、工具调用和数据路径没有变化。
