[Ace Data Cloud Studio](https://studio.acedata.cloud) 面向创作者、运营、设计和业务团队，统一提供 AI 对话、图像、视频、音乐与自动成片工具。用户从创作目标出发选择工作流，不需要先在多个产品之间反复注册、充值和切换。

![Studio 首页：从创作目标进入对话、图像、视频与音乐](https://cdn.acedata.cloud/uploads/34c26779-82a4-4a9b-b81b-fb98ccd525be)

## 适合哪些场景

- **内容创作**：写作、研究、海报、封面、短视频和配乐；
- **营销运营**：商品图、社交媒体素材、活动视觉和品牌内容；
- **设计探索**：参考图编辑、风格探索、构图和多版本方案；
- **业务团队**：用自然语言完成跨模型、多步骤的创作任务；
- **开发者与高级用户**：在支持的场景中配置 API Key、Connector、Skill 或本地工具。

具体可用能力会随站点配置、地区、账号和产品版本变化，以当前页面实际显示为准。

## 如何开始

1. 访问 [studio.acedata.cloud](https://studio.acedata.cloud)；
2. 选择页面当前提供的登录方式；
3. 从首页的创作目标或左侧能力导航进入工具；
4. 阅读当前服务的价格、参数和内容要求；
5. 先用低成本任务验证流程，再进行高分辨率、长视频或批量生成。

不同服务的计费单位、处理时长和参数不同。提交前应查看当前页面与使用记录，不要依据历史截图推算价格。

## 核心工作流

### AI 对话

用于写作、分析、学习、编程和多模态讨论。具体模型、上下文能力和工具支持以当前模型选择器为准。

### AI 图像

覆盖文字生成图像、参考图编辑、扩图、风格转换和视觉设计。不同图像服务在尺寸、文字渲染、人物一致性和编辑能力上各有侧重。

### AI 视频与自动成片

支持文字、图片、参考素材或脚本驱动的视频创作。自动成片工作流可组合脚本、画面、配音、字幕和音乐；长任务应关注状态查询、失败原因和最终输出完整性。

### AI 音乐

支持从风格或歌词生成歌曲，并按页面提供的能力继续编辑或扩展。商业使用前应自行核对内容权利和目标平台规则。

### Connector、Skill 与高级工具

部分账号或站点可使用 Connector、Skill 和本地工具。这些入口受当前产品、权限和运行环境约束，不是所有用户或白牌站点都默认开放。

## Web、移动端与桌面端

Studio Web 版位于 `studio.acedata.cloud`。移动端和桌面端的能力、站点管理入口可能不同：

- 白牌站点管理只在 Web 版向当前 Site 管理员显示；
- 原生移动端和桌面端不会展示所有站点运营设置；
- 手机宽度使用底部能力导航，复杂创作表单更适合桌面浏览器。

## 创建自己的品牌分站

如果需要用自己的名称、Logo、页面域名、能力目录和渠道价格经营 Studio，可在官方 Studio Web 版打开：

**用户头像 → 设置 → 我的分站**

创建后，从“我的分站”对目标分站点击 **管理**，再配置品牌、登录、能力、价格、横幅、统计和自定义域名。

## 白牌和分销边界

- 白牌是共享平台上的 Site 配置，不是独立部署或独立数据库；
- 用户账号、余额、套餐和多数资产属于共享体系；
- 隐藏充值、能力或服务只是页面展示控制，不是授权隔离；
- Site 加价是正常白牌购买流程的渠道价格，不是账号在所有入口的强制租户价；
- 分销收益取决于有效订单、邀请关系、等级、退款和风控，不承诺固定比例、到账速度或收入数字。

## 使用建议

- 重要事实和生成内容需要人工复核；
- 不要在提示词、截图、聊天或工单中泄露密码、API Key、身份证件或支付信息；
- 人像、声音、商标和版权素材应取得必要授权；
- 高成本任务先做小样，确认参数后再扩大规模；
- 出现异常时记录时间、服务、状态码和可公开请求标识，不要提交完整 token。

## 首页第三方网站的 OAuth 授权

网站组件可采用标准 OAuth 跳转，或使用 Studio 当前账号的组件授权。标准跳转由第三方按钮打开授权页，再回到其登记的回调地址；它不要求 Studio 消息协议，也不会自动复用 Studio 登录态。普通 iframe 首次登录后继续授权目前仍有缺口，需按接入文档验证，或使用独立页面／组件授权。

希望使用 Studio 当前账号时，在「设置 → 首页 → 网站组件」开启 OAuth，填写第三方应用 ID 与回调地址。网站和回调地址必须使用同一个 HTTPS 来源，与 Studio 来源不同。不要在设置中填写应用密钥。第三方页面还需要实现组件消息协议，仅填写 URL 不会自动完成 OAuth 对接。

组件申请 `profile:read credentials:read`，不包含 `offline_access`。已登录访客同意后，第三方收到一次性授权码，使用自己的 PKCE verifier 换取 OAuth token，再通过 `https://platform.acedata.cloud/api/v1/credentials/?user_id=<UserInfo返回的id>&limit=100` 读取 `items[*].token`。未登录或拒绝授权时不会提供 Key。

完整说明、可运行的标准跳转示例、scope 目录与错误处理见 [OAuth 接入指南](https://docs.acedata.cloud/zh-Hans/guides/oauth)；使用 Studio 会话的应用另参阅 [组件消息示例](https://github.com/AceDataCloud/Nexior/blob/main/docs/integrations/studio-home-oauth.md)。

允许读取 Key 后，第三方可以保存并使用它。当前 OAuth 撤销端点的成功响应不表示 JWT 即时失效，也不会使已复制的 API Key 失效；需要用户另外撤销或轮换该 Key。
