调用 `https://api.acedata.cloud` 上的 API 时，在 `Authorization` 请求头中携带应用 API Key。

## 获取 API Key

<Steps>
  <Step title="打开应用管理">
    打开[应用管理](https://platform.acedata.cloud/console/applications?lang=zh-cn&utm_source=docs&utm_medium=referral&utm_campaign=evergreen)，登录或注册账号。
  </Step>
  <Step title="选择通用应用">
    如尚未创建，点击**初始化通用应用**。通用 Key 可访问当前账号已开放的服务，专用应用 Key 的权限限于对应服务。
  </Step>
  <Step title="复制 API Key">
    点击图中标记 **1** 的复制按钮，复制 **API KEY** 旁的 Token，再粘贴到应用或环境变量中。

    ![通用应用卡片，标记 1 为 API Key 复制按钮，标记 2 为管理密钥](https://raw.githubusercontent.com/AceDataCloud/NanoBananaDify/2522b2f57210597af2db866445319334a1677a23/_assets/tutorial/get-api-key-en.png)
  </Step>
</Steps>

根据所选[模型价格](https://platform.acedata.cloud/models?lang=zh-cn)检查应用余额，试用额度以账号显示为准。可选的 Key 限制设置见[完整指引](https://platform.acedata.cloud/documents/api-key-guide?lang=zh-cn)。

## 使用 Key

将原始 Token 存入环境变量，在 HTTP 请求头中添加 `Bearer ` 前缀。

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"

curl --fail-with-body https://api.acedata.cloud/v1/chat/completions \
  --header "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{"model":"gpt-6-luna","messages":[{"role":"user","content":"用一句话打个招呼。"}]}'
```

### 响应 JSON

成功时返回 HTTP `200`。以下示例展示响应结构，实际回复内容由请求决定。

```json
{
  "id": "chatcmpl-example",
  "object": "chat.completion",
  "model": "gpt-6-luna",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "你好，很高兴为你提供帮助！"
      },
      "finish_reason": "stop"
    }
  ]
}
```

从 `choices[0].message.content` 读取回复，`finish_reason` 表示回复结束原因。

客户端中名为 **API Key** 或 **API Token** 的字段填写原始 Token。使用客户端凭据存储或后端环境保存密钥。文件上传等操作应使用对应文档规定的请求类型。

## 选择对应凭据

| 凭据 | 用途 |
| --- | --- |
| 应用 API Key | 模型生成和服务调用，访问权限、限额与余额由应用和 Key 设置决定。 |
| 以 `platform-` 开头的平台 Token | 账号与平台管理 API，创建方法见[平台 Token 指南](https://platform.acedata.cloud/documents/platform-token?lang=zh-cn)。 |
| 部署或账号代理凭据 | 按所选部署指南使用对应端点与鉴权方式。 |

## 处理失败请求

| 响应 | 检查方法 |
| --- | --- |
| `invalid_token`、`token_expired` | 重新复制完整 Key，并检查过期时间。 |
| `token_mismatched`、`disabled` | 检查应用的服务权限，以及应用或 Key 是否启用。 |
| `used_up` | 检查应用余额和 Key 用量限制，按需在控制台充值。 |
| `no_token`、`bad_request` | 检查 Authorization 请求头、JSON 格式和必填字段。 |
| `too_many_requests` | 等待当前请求完成，或按对应端点说明重试。试用账号可能限制整个账号同时执行一个计费请求。 |

生成请求已经返回任务 ID 时，按所选服务文档继续查询原任务，可参考 [ACE Music 任务示例](https://platform.acedata.cloud/documents/acemusic-tasks-integration?lang=zh-cn)。连接超时期间任务可能仍在执行。联系支持时提供 `trace_id` 和任务 ID。
