title: "API Key 与鉴权"
description: "创建应用 API Key，并使用它调用 Ace Data Cloud API。"
---

调用 `https://api.acedata.cloud` 上的 API 时，在 `Authorization` 请求头中携带应用 API Key。

## 获取 API Key

<Steps>
  <Step title="打开应用管理">
    打开[应用管理](https://platform.acedata.cloud/console/applications?lang=zh-cn&utm_source=docs&utm_medium=referral&utm_campaign=evergreen)，登录或注册账号。
  </Step>
  <Step title="选择通用应用">
    如尚未创建，点击**初始化通用应用**。通用 Key 可访问当前账号已开放的服务，专用应用 Key 的权限限于对应服务。
  </Step>
  <Step title="复制 API Key">
    在应用卡片复制 **API Key**。需要独立 Key 时，打开**密钥 / 管理密钥 → 创建**，填写名称，创建后从列表中复制新 Token。
  </Step>
</Steps>

根据所选[模型价格](https://platform.acedata.cloud/models?lang=zh-cn)检查应用余额。试用额度以账号显示为准。创建 Key 时按需设置**过期时间**、**用量限制**和**允许的 API**。异步工作流需要同时允许生成与任务查询操作。

## 使用 Key

将原始 Token 存入环境变量，在 HTTP 请求头中添加 `Bearer ` 前缀。

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"

curl --fail-with-body https://api.acedata.cloud/v1/chat/completions \
  --header "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{"model":"gpt-6-luna","messages":[{"role":"user","content":"用一句话打个招呼。"}]}'
```

客户端中名为 **API Key** 或 **API Token** 的字段填写原始 Token。使用客户端凭据存储或后端环境保存密钥。文件上传等操作应使用对应文档规定的请求类型。

## 选择对应凭据

| 凭据 | 用途 |
| --- | --- |
| 应用 API Key | 模型生成和服务调用，访问权限、限额与余额由应用和 Key 设置决定。 |
| 以 `platform-` 开头的平台 Token | 账号与平台管理 API，创建方法见[平台 Token 指南](/zh-Hans/guides/platform/platform_token)。 |
| 部署或账号代理凭据 | 按所选部署指南使用对应端点与鉴权方式。 |

## 处理失败请求

| 响应 | 检查方法 |
| --- | --- |
| `invalid_token`、`token_expired` | 重新复制完整 Key，并检查过期时间。 |
| `token_mismatched`、`disabled` | 检查应用的服务权限，以及应用或 Key 是否启用。 |
| `used_up` | 检查应用余额和 Key 用量限制，按需在控制台充值。 |
| `no_token`、`bad_request` | 检查 Authorization 请求头、JSON 格式和必填字段。 |
| `too_many_requests` | 等待当前请求完成，或按对应端点说明重试。试用账号可能限制整个账号同时执行一个计费请求。 |

生成请求已经返回任务 ID 时，继续[查询原任务](/zh-Hans/concepts/async-tasks)。连接超时期间任务可能仍在执行。联系支持时提供 `trace_id` 和任务 ID。

继续阅读[快速开始](/zh-Hans/quickstart)，或浏览[全部 API 服务](/zh-Hans/services)。
