Questo documento descrive il modo di integrazione dell'API HappyHorse Videos. Questa interfaccia supporta la generazione di video da testo, video da immagine di prima cornice, video da immagine di riferimento e editing video tramite un'unica entrata `/happyhorse/videos` e il parametro `action`.

## Processo di richiesta

Per utilizzare l'API HappyHorse Videos, prima vai al [Pannello di Controllo di Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da conservare per uso futuro.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Se non hai ancora effettuato il login o la registrazione, verrai automaticamente reindirizzato alla pagina di login che ti invita a registrarti e a effettuare il login; una volta completato, verrai riportato automaticamente alla pagina corrente.

**Un API Token è sufficiente per accedere a tutti i servizi della piattaforma, senza necessità di richiederne uno separato per ogni servizio.** La prima richiesta ti darà un credito gratuito, per un'esperienza senza costi; se il credito è insufficiente, puoi ricaricare il saldo generale nel [pannello di controllo](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [HappyHorse Videos API →](https://platform.acedata.cloud/documents/happyhorse-videos)

## Tipi di operazione

`action` determina la modalità di generazione di questa richiesta:

- `generate`: video da testo, azione predefinita, supporta `happyhorse-1.0-t2v` e `happyhorse-1.1-t2v`, deve essere fornito `prompt`.
- `image_to_video`: video da immagine di prima cornice, supporta `happyhorse-1.0-i2v` e `happyhorse-1.1-i2v`, deve essere fornito `image_url`.
- `reference_to_video`: video da immagine di riferimento, supporta `happyhorse-1.0-r2v` e `happyhorse-1.1-r2v`, deve essere fornito `prompt` e 1–9 `image_urls`.
- `video_edit`: editing video, supporta `happyhorse-1.0-video-edit`, deve essere fornito `prompt` e `video_url`, è possibile fornire ulteriormente 0–5 immagini di riferimento `image_urls`.

Le azioni utilizzano per default il modello 1.1; `video_edit` attualmente supporta solo `happyhorse-1.0-video-edit`.

## Utilizzo di base

Per generare un video da testo è sufficiente fornire `prompt`, è possibile anche specificare parametri come `resolution`, `ratio`, `duration`:

```json
{
  "action": "generate",
  "model": "happyhorse-1.1-t2v",
  "prompt": "Un cavallo bianco cinematografico solleva la testa, la criniera si muove dolcemente nel vento dell'alba, spinta lenta della telecamera, illuminazione calda da film",
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}
```

Esempio di risultato restituito:

```json
{
  "success": true,
  "task_id": "27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1",
  "trace_id": "6071ab5e-2f37-46f0-9e07-f1e378112e69",
  "data": [
    {
      "id": "9650580f-6d9e-4bc1-823a-29011790c5cb",
      "video_url": "https://platform2.cdn.acedata.cloud/happyhorse/27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1.mp4",
      "state": "succeeded",
      "duration": 5,
      "resolution": "720P",
      "ratio": null
    }
  ]
}
```

Descrizione dei campi:

- `success`: se la richiesta è andata a buon fine.
- `task_id`: ID del task sul lato Ace Data Cloud, utilizzabile per controllare lo stato del task.
- `trace_id`: ID di tracciamento della richiesta, utilizzato per la risoluzione dei problemi.
- `data`: elenco dei risultati video.
  - `id`: ID del task HappyHorse upstream.
  - `video_url`: indirizzo CDN del video generato.
  - `state`: stato del task, può essere `pending` / `succeeded` / `error`.
  - `duration`: durata del video a pagamento, in secondi; per `video_edit` è la somma della durata del video di input e output.
  - `resolution`: risoluzione di output.
  - `ratio`: rapporto di aspetto di output.

Il codice CURL corrispondente è il seguente:

```shell
curl -X POST 'https://api.acedata.cloud/happyhorse/videos' \
-H 'authorization: Bearer ${bearer_token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "happyhorse-1.1-t2v",
  "prompt": "Un cavallo bianco cinematografico solleva la testa, la criniera si muove dolcemente nel vento dell'alba, spinta lenta della telecamera, illuminazione calda da film",
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}'
```

Il codice Python corrispondente è il seguente:

```python
import requests

url = "https://api.acedata.cloud/happyhorse/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "action": "generate",
    "model": "happyhorse-1.1-t2v",
    "prompt": "Un cavallo bianco cinematografico solleva la testa, la criniera si muove dolcemente nel vento dell'alba, spinta lenta della telecamera, illuminazione calda da film",
    "resolution": "720P",
    "ratio": "16:9",
    "duration": 5,
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Video da immagine di prima cornice

Utilizzando `image_to_video`, `image_url` sarà utilizzato come prima cornice del video. Il rapporto di aspetto in output seguirà il più possibile l'immagine di prima cornice, quindi questa azione non richiede di fornire `ratio`.

```json
{
  "action": "image_to_video",
  "model": "happyhorse-1.1-i2v",
  "image_url": "https://cdn.acedata.cloud/b1c82e4937.png",
  "prompt": "Un cavallo bianco cinematografico solleva la testa, la criniera si muove dolcemente nel vento dell'alba, spinta lenta della telecamera, illuminazione calda da film",
  "resolution": "1080P",
  "duration": 5
}
```

## Video da immagine di riferimento

Utilizzando `reference_to_video`, `image_urls` può contenere da 1 a 9 immagini di riferimento. Nella frase di prompt, puoi fare riferimento alle immagini nell'ordine corrispondente usando `character1`, `character2`, ecc.

```json
{
  "action": "reference_to_video",
  "model": "happyhorse-1.1-r2v",
  "prompt": "character1 cammina in avanti attraverso un prato all'alba con lo stile caldo in pelle e oro di character2",
  "image_urls": [
    "https://cdn.acedata.cloud/b1c82e4937.png",
    "https://cdn.acedata.cloud/eb75d88a3f.png"
  ],
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}
```

## Editing video

Utilizzando `video_edit`, è necessario fornire l'URL del video da modificare `video_url` e l'intento di modifica `prompt`. Le `image_urls` opzionali saranno utilizzate come immagini di riferimento, ad esempio per cambi di abbigliamento, trasferimento di stile o sostituzioni parziali. `audio_setting` può essere `auto` o `origin`, dove `origin` indica di mantenere l'audio originale del video.

```json
{
  "action": "video_edit",
  "model": "happyhorse-1.0-video-edit",
  "prompt": "Applica lo stile caldo in pelle e oro dell'immagine di riferimento mantenendo il movimento della telecamera originale",
  "video_url": "https://platform2.cdn.acedata.cloud/happyhorse/27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1.mp4",
  "image_urls": [
    "https://cdn.acedata.cloud/eb75d88a3f.png"
  ],
  "resolution": "720P",
  "audio_setting": "auto"
}
```

## Callback asincrona
La generazione del video richiede un certo tempo di elaborazione. Se non si desidera mantenere una connessione lunga in attesa, è possibile fornire `callback_url`, in tal caso l'API restituirà immediatamente `task_id`, e una volta completato il compito, invierà il risultato finale a quell'indirizzo:

```json
{
  "action": "generate",
  "prompt": "Un cavallo che corre attraverso una foresta innevata",
  "duration": 5,
  "callback_url": "https://your-domain.com/callback/happyhorse"
}
```

Il risultato restituito immediatamente è il seguente:

```json
{
  "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea"
}
```

Se si desidera solo il polling, senza callback, è possibile fornire `"async": true`, e successivamente consultare i risultati del compito tramite [HappyHorse Tasks API](https://platform.acedata.cloud/documents/happyhorse-tasks).

## Informazioni di fatturazione

HappyHorse fattura in base ai secondi di video output e alla risoluzione:

- `720P`: a partire da circa $0.105 / secondo.
- `1080P`: a partire da circa $0.18 / secondo.
- `video_edit`: fatturato in base alla durata totale del video di input e output, la durata di fatturazione effettiva è basata sulle statistiche upstream dopo il completamento del compito.

I compiti falliti non vengono fatturati e non occupano il limite gratuito.

## Gestione degli errori

Quando si verifica un problema con la richiesta, l'API restituirà il codice di errore corrispondente e la spiegazione, i più comuni sono i seguenti:

- `400`: parametri della richiesta errati, ad esempio action e model non corrispondono, mancano `prompt` / `image_url` / `video_url`, o `duration` supera il range di 3–15 secondi.
- `401`: autenticazione fallita, token non valido o non corrispondente all'API.
- `403`: saldo insufficiente, o il prompt ha colpito contenuti soggetti a revisione e rifiutati.
- `429`: richiesta troppo frequente, attivato il throttling upstream, riprovare più tardi.
- `500`: errore interno del server o fallimento della generazione upstream.
