SUNO ci permette di ottenere file musicali in formato wav. Questo documento spiega il metodo di integrazione con le API correlate.

Il parametro di input principale di questa API è `audio_id`, che è l'ID della canzone generato ufficialmente; opzionalmente supporta anche `callback_url` per il callback asincrono.

Qui il `audio_id` che inseriamo è `4e43116a-bf09-472c-8e1c-655eabf02682`.

```python
import requests

url = "https://api.acedata.cloud/suno/wav"

headers = {
    "accept": "application/json",
    "authorization": "Bearer aa287fa4cc54401087a9fab3f99630af",
    "content-type": "application/json"
}

payload = {
    "audio_id": "4e43116a-bf09-472c-8e1c-655eabf02682"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Il risultato è il seguente:

```json
{
  "success": true,
  "task_id": "6a5a2099-d6d3-4930-9709-a30ac5dc7de5",
  "trace_id": "3fa70e81-6bb7-4ca8-b718-dd16a4eda7e8",
  "data": [
    {
      "file_url": "https://platform.cdn.acedata.cloud/suno/6a5a2099-d6d3-4930-9709-a30ac5dc7de5.wav"
    }
  ]
}
```

Si può osservare che il campo `file_url` in `data` è il file musicale in formato wav ottenuto, ed è un indirizzo CDN accessibile pubblicamente.

> **Riguardo alla persistenza del link WAV**
>
> I file WAV sul CDN upstream di Suno (`https://cdn1.suno.ai/{audio_id}.wav`) vengono mantenuti solo per pochi giorni, dopodiché vengono rimossi e l’accesso restituisce un errore 403.
> Per evitare che il link scada, questa API copia automaticamente il file WAV upstream nel nostro CDN (`https://platform.cdn.acedata.cloud/suno/{task_id}.wav`) prima di restituirlo; il `file_url` restituito è quindi un indirizzo stabile che non scade con l’upstream CDN.
> In caso di fallimento della copia (molto raro), si ritorna all’URL originale upstream, mantenendo il comportamento storico.
