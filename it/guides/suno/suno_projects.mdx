L'API del progetto Suno Studio gestisce progetti musicali multitraccia tramite un unico endpoint:

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
```

L'`action` nella richiesta determina il tipo di operazione. La chiave primaria del Project utilizza uniformemente `id`; `version_id` indica la versione corrente del progetto, e tutte le operazioni di modifica ed esportazione devono inviare la versione più recente per evitare sovrascritture concorrenti.

## Panoramica delle operazioni

| action             | Modalità  | Utilizzo                      |
| ------------------ | --- | ----------------------- |
| `create`           | Sincrona  | Crea un progetto vuoto                   |
| `retrieve`         | Sincrona  | Legge il progetto e lo `state` completo modificabile      |
| `save`             | Sincrona  | Salva lo stato completo del progetto                |
| `upload`           | Asincrona  | Inizializza da un indirizzo audio HTTPS una risorsa aggiungibile al progetto |
| `add_track`        | Asincrona  | Aggiunge al progetto un audio esistente               |
| `generate_track`   | Asincrona  | Genera candidati di nuove tracce per l'intervallo specificato            |
| `replace_section`  | Asincrona  | Genera candidati di sostituzione locale                |
| `commit_candidate` | Asincrona  | Invia al progetto il candidato selezionato             |
| `remove_track`     | Sincrona  | Elimina la traccia specificata                  |
| `render`           | Asincrona  | Esporta una canzone completa dalla versione salvata           |

Le operazioni asincrone restituiscono immediatamente `task_id`. Usa l'interfaccia gratuita `/suno/tasks` per il polling, oppure passa `callback_url` per ricevere il risultato finale.

## Creazione e lettura

```json
{"action":"create","title":"My Studio Project"}
```

Tutte le operazioni di modifica devono inviare un Header `Idempotency-Key` univoco. Dopo la creazione riuscita, `data.id` nella risposta è il Project ID. Un nuovo progetto vuoto potrebbe non avere `version_id` prima del primo salvataggio.

```json
{"action":"retrieve","id":"PROJECT_ID"}
```

La risposta di lettura contiene lo `state` completo. Si consiglia di leggere prima, poi modificare e salvare in base al valore restituito; non costruire manualmente da zero le strutture interne di battute e tracce.

## Salvataggio dello stato completo

```json
{
  "action":"save",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "title":"Edited Project",
  "state":{"tracks":[],"timing":{}}
}
```

Il primo salvataggio di un nuovo progetto vuoto può omettere `version_id`; dopo che il primo salvataggio genera una versione, i salvataggi successivi devono inviare il valore più recente. Se la versione è già cambiata, l'interfaccia restituisce HTTP 409. A questo punto esegui nuovamente `retrieve`, unisci le modifiche e invia con una nuova chiave di idempotenza; non riprovare ciecamente la vecchia richiesta.

## Caricamento e aggiunta di tracce

```json
{
  "action":"upload",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "audio_url":"https://cdn.example.com/reference.mp3",
  "async":true
}
```

Al termine del caricamento, il risultato dell'attività restituisce il candidato `audio_id`. Quindi aggiungilo al progetto:

```json
{
  "action":"add_track",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "audio_id":"AUDIO_ID",
  "name":"Backing Vocals"
}
```

## Generazione e sostituzione

`generate_track` genera candidati di tracce per un intervallo del progetto; `replace_section` restituisce due candidati di sostituzione locale. Entrambe le operazioni non selezionano automaticamente il risultato artistico.

```json
{
  "action":"replace_section",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "source_audio_id":"AUDIO_ID",
  "start_seconds":35.12,
  "end_seconds":48.76,
  "model":"chirp-v6",
  "replacement_lyrics":"nuovo frammento di testo",
  "async":true
}
```

Dopo aver selezionato un candidato, invialo:

```json
{
  "action":"commit_candidate",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "operation_id":"OPERATION_ID",
  "candidate_id":"CANDIDATE_ID",
  "track_id":"TRACK_ID"
}
```

I candidati sono associati alla versione del progetto al momento della generazione. Se il progetto è già cambiato, i vecchi candidati non possono essere inviati direttamente.

## Esportazione della canzone completa

```json
{
  "action":"render",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "title":"Final Mix",
  "lyrics":"[Instrumental]",
  "async":true,
  "callback_url":"https://example.com/webhooks/suno"
}
```

Il server legge lo stato autorevole del progetto della versione specificata e assembla i parametri di esportazione. Il risultato finale contiene `render_id`, `audio_id`, `audio_url` e la durata. Il progetto è associato all'ambiente di esecuzione al momento della creazione e non può essere migrato tra ambienti né sottoposto automaticamente a failover.

> Puoi caricare o elaborare solo audio per i quali possiedi diritti legittimi di utilizzo. L'API del progetto è attualmente in Beta; persisti gli URL audio finali nei risultati importanti.
