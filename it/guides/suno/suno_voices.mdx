SUNO ci consente di creare personaggi vocali personalizzati tramite qualsiasi file audio, realizzando il clonaggio vocale per la generazione musicale. A differenza dell'attuale API Persona (che utilizza `audio_id` generati da Suno), questa API accetta un `audio_url` accessibile pubblicamente, ovvero la propria registrazione vocale. Questo documento spiega come integrare l'API di clonaggio vocale.

Sulla linea di creazione che supporta la verifica della disponibilità del timbro vocale, è possibile trasmettere il `persona_id` nei risultati di creazione a `POST /suno/availability` utilizzando l'applicazione originale e l'identità del chiamante. Quando l'account associato è online, restituisce `data.available=true`; quando viene confermato offline, restituisce `data.available=false`. [Guida alla verifica della disponibilità del timbro vocale](https://platform.acedata.cloud/documents/suno-availability-integration)

## Primo passaggio: creare un personaggio vocale

Fatturazione: dopo la creazione riuscita del personaggio vocale, il costo standard per ogni richiesta è di **0.15 Credits**. Gli sconti sui consumi applicabili sono soggetti alla fattura effettiva; le richieste non riuscite non vengono addebitate.

Questa API dispone di tre parametri di input: `audio_url` (obbligatorio), un URL di file audio in formato MP3 o WAV accessibile pubblicamente, contenente una voce umana chiara di una sola persona; `name` e `description` (facoltativi), che indicano il nome e la descrizione del personaggio vocale.

> **Requisiti del file audio**
> - Il formato audio deve essere `WAV` o `MP3`
> - La durata dell'audio deve essere compresa tra `10~240 secondi`; si consiglia di usare materiale vocale pulito e isolato di una sola persona di `30~60 secondi`
> - L'audio deve contenere una **voce parlata o cantata chiara e riconoscibile di una sola persona**
> - Assicurarsi di evitare **rumore di fondo, accompagnamento, eco, riverbero**; le canzoni complete con accompagnamento solitamente non superano la verifica dell'impronta vocale
> - Non includere **più parlanti** o **voci multiple**
> - Materiale con volume troppo basso, voce poco chiara o rumore eccessivo potrebbe causare **il fallimento del clonaggio** o **risultati di generazione scadenti**
> **Descrizione delle limitazioni d'uso**
> - I personaggi vocali creati caricando audio sono **risorse private**
> - Questo personaggio vocale **non supporta il riutilizzo tra account diversi**
> - Si consiglia di utilizzarlo quanto prima dopo la creazione riuscita; il mancato utilizzo per un lungo periodo potrebbe causare **scadenza o indisponibilità**
> - Il `name` restituito viene generato automaticamente dal sistema; fare riferimento al `persona_id` restituito

> **Gestire gli errori in base al contrassegno esplicito di ripetizione**
> `retryable` nell'oggetto errore è un campo booleano facoltativo. Quando `error.retryable` è `true`, indica che questo errore consente di inviare nuovamente la richiesta in seguito utilizzando lo stesso materiale e gli stessi parametri. Il servizio occupato esplicitamente non accettato o alcuni errori temporanei di verifica dell'impronta vocale possono avere questo contrassegno; si consiglia di utilizzare intervalli di attesa progressivi e di limitare il numero di tentativi.
> Quando `retryable` è `false` o il campo è assente, non reinviare automaticamente solo in base a HTTP 500, `busy` o al testo dell'errore. I problemi di formato, durata, chiarezza, registrazioni duplicate e moderazione dei contenuti devono essere corretti prima; in caso di timeout di invio, interruzione della connessione o risultato di creazione non chiaro, è necessario dare priorità alla consultazione dell'attività utilizzando il `task_id` originale, per evitare la creazione duplicata di timbri vocali. Le richieste non riuscite non vengono addebitate, mentre le richieste ritentate con successo vengono addebitate secondo le regole normali.

```bash
curl -X POST 'https://api.acedata.cloud/suno/voices' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3",
  "name": "My Voice",
  "description": "单人清晰人声示例"
}'
```

> Il suddetto `https://cdn.acedata.cloud/suno_demo.mp3` è materiale di esempio richiamabile direttamente (MP3, 41 secondi, voce isolata di una sola persona).
> Se è necessario un esempio in formato `WAV`, è possibile utilizzare
> `https://cdn.acedata.cloud/uploads/82d23b97-ec1c-4b41-91b8-989fc51f8765` (WAV, 41 secondi, mono 44.1kHz).

Il risultato è il seguente:

```json
{
  "success": true,
  "task_id": "0fa609a6-c8d9-4bb5-8574-e4c93bb55d02",
  "data": {
    "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16",
    "name": "VOICE_20260803037676",
    "is_public": false
  }
}
```

Come si può vedere, il campo `persona_id` di `data` è l'ID del personaggio vocale creato. Il campo `is_public` è sempre `false`, perché i personaggi vocali creati caricando audio sono privati. Si noti che il `name` restituito viene generato automaticamente dal sistema; in seguito, utilizzare `persona_id` per fare riferimento a questo personaggio vocale.

## Secondo passaggio: usare il personaggio vocale per generare musica

Dopo aver ottenuto l'ID del personaggio vocale, possiamo utilizzare [Suno Audios Generation API](https://platform.acedata.cloud/documents/suno-audios) per generare musica. Impostare `action` su `generate` e `persona_id` sull'ID del personaggio vocale restituito sopra; la canzone generata verrà cantata utilizzando la voce clonata.

> **Nota:** il clonaggio vocale supporta solo i modelli `chirp-v4-5` e successivi (come `chirp-v4-5`, `chirp-v5`, `chirp-v5-5`) e non supporta `chirp-v4`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "chirp-v5-5",
  "prompt": "A warm synth-pop song about city nights",
  "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16"
}'
```

Il risultato è il seguente:

```json
{
  "success": true,
  "task_id": "53d8a334-a972-43c5-895e-60c4454e88d5",
  "data": [
    {
      "id": "16463960-077c-4700-bbb3-3c7897b943d3",
      "title": "Soft Neon on My Skin",
      "audio_url": "https://cdn.acedata.cloud/assets/examples/fish/5ade0339-5f11-487e-aacc-06a908271706-8e3fcb0e5547.mp3",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "model": "chirp-v5-5",
      "state": "succeeded",
      "prompt": "A warm synth-pop song about city nights",
      "duration": 156.28
    }
  ]
}
```

`persona_id` può essere utilizzato per la generazione `generate` e anche per le cover `cover` / `upload_cover`. Quando si specifica una voce, non è necessario compilare contemporaneamente `vocal_gender`; la somiglianza vocale dipende comunque dal materiale di riferimento e dal risultato generato.

Le voci create tramite questa interfaccia sono risorse private. Prima di reinterpretare una canzone esistente, chiamare `/suno/upload`, passando l'`audio_url` della canzone originale e il `persona_id` di questa voce; dopo il caricamento riuscito, chiamare `/suno/audios` utilizzando il `data.audio_id` restituito e lo stesso `persona_id`:
```json
{
  "action": "upload_cover",
  "model": "chirp-v6",
  "audio_id": "<与该声音关联上传后返回的 audio_id>",
  "persona_id": "<声音创建接口返回的 persona_id>",
  "custom": true,
  "instrumental": false,
  "lyric": "[Verse]\n填写要演唱的歌词",
  "async": true
}
```

La creazione della voce, il caricamento del brano originale e la cover devono utilizzare lo stesso canale di servizio. Non riutilizzare direttamente un ID brano precedente non associato a questa voce privata; per i dettagli, consulta [Suno carica audio di riferimento](https://platform.acedata.cloud/documents/suno-upload).
