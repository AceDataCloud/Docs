---
title: "API di verifica della disponibilità audio di Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` cerca, in base a `audio_id`, prove positive che l'audio possa continuare a essere elaborato sul percorso corrente. Può essere chiamato prima di operazioni come continuazione o cover; il risultato riflette solo lo stato al momento della verifica e non garantisce il successo di una specifica operazione. Questa API restituisce una risposta sincrona, richiede un API Token e attualmente non addebita Credits.

`audio_id` è l'ID del brano restituito da un'attività Suno completata, non `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Esempio di risposta riuscita:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

Quando la verifica ha esito positivo, `data.available` è `true`; quando non è possibile confermare, viene restituito `503 availability_unknown` e `false` non viene restituito. Un formato `audio_id` non valido restituisce 400; anche il limite di frequenza o anomalie del servizio restituiscono una risposta di errore. Lo stato può comunque cambiare tra il completamento della verifica e l'operazione effettiva.
