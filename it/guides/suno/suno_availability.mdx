---
title: "API di controllo della disponibilità audio Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` cerca, in base a `audio_id`, prove positive che l'audio possa continuare a essere elaborato sulla linea corrente. Può essere chiamato prima di operazioni come continuazione, cover, ecc.; il risultato riflette solo lo stato al momento del controllo e non garantisce che una specifica operazione abbia sicuramente successo. Questa interfaccia restituisce una risposta sincrona, richiede un API Token e attualmente non addebita Credits.

`audio_id` è l'ID del brano restituito da un'attività Suno completata, non `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Esempio di risposta in caso di successo:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

Quando il controllo ha successo, `data.available` sarà solo `true`. Lo stato “non online” restituito da alcune linee non può dimostrare che operazioni successive come la continuazione non possano avere successo, pertanto questa interfaccia restituisce `503 availability_unknown` quando non è possibile confermare e non restituirà `false`. Un formato `audio_id` errato restituisce 400, anche il rate limiting o i guasti upstream restituiscono una risposta di errore. Lo stato può comunque cambiare tra il completamento del controllo e l'operazione effettiva.
