---
title: "API di verifica della disponibilità di audio e timbro Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` accetta un ID risorsa. Per verificare una canzone passare `audio_id`, per verificare un timbro passare `persona_id`, uno dei due è obbligatorio. La verifica viene completata in modo sincrono, richiede un API Token e al momento non scala Credits.

## Richiesta

`audio_id` proviene da un'attività canzone completata e può essere usato per una verifica prima di continuare o fare una cover.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

`persona_id` proviene dal risultato di creazione del timbro. Utilizzare l'applicazione originale e l'identità del chiamante, e inviare il seguente corpo della richiesta sulla linea di creazione che supporta le query dei timbri.

```json
{"persona_id":"33333333-3333-4333-8333-333333333333"}
```

## Risposta

Entrambi i tipi di richiesta utilizzano la stessa risposta di successo. `data.id` è l'ID risorsa di questa query.

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

`available: true` indica che questa verifica ha ottenuto prove positive. Per i timbri, la verifica controlla l'appartenenza della creazione e conferma che l'account associato sia attualmente segnalato online. Il risultato effettivo della generazione rimane soggetto all'attività di generazione.

I timbri privati clonati creati tramite `/suno/voices` dipendono dall'account di creazione. Quando viene confermato che tale account è attualmente offline, l'interfaccia restituisce HTTP 200 e `data` è come nell'esempio seguente.

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

Il client può contrassegnare questo timbro come attualmente non disponibile e verificarlo nuovamente in seguito.

Quando non è possibile confermare, viene restituito HTTP 503 e `availability_unknown`, ad esempio se la risorsa non viene trovata, se i vecchi record non dispongono della linea di creazione o se la query va in timeout. Gli stili di cantanti pubblici possono essere usati tra account diversi e restituiscono anch'essi 503 quando l'account di creazione è offline. Le query delle canzoni restituiscono comunque `available: true` solo quando viene confermata la disponibilità.

Ogni richiesta invia un solo UUID valido. Tutte le linee restituiscono HTTP 400 quando ricevono richieste con entrambi gli ID o con entrambi gli ID mancanti. Le linee che supportano solo le query delle canzoni restituiscono HTTP 400 quando ricevono richieste contenenti solo `persona_id`. In caso di HTTP 429, ridurre la frequenza delle query.
