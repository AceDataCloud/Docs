La funzione principale della Suno Tasks API è interrogare lo stato di esecuzione di un'attività inserendo l'ID dell'attività generato dalla Suno Audios Generation API o dalla Suno Lyrics Generation API.

Questo documento illustrerà dettagliatamente le istruzioni di integrazione della Suno Tasks API, aiutandovi a integrarla facilmente e a sfruttare appieno le potenti funzionalità di questa API. Tramite la Suno Tasks API, potete facilmente interrogare lo stato di esecuzione delle attività della Suno Lyrics Generation API o della Suno Audios Generation API.

## Procedura di richiesta

Per utilizzare la Suno Audios Generation API, per prima cosa ottenete il vostro API Token dalla [console di Ace Data Cloud](https://platform.acedata.cloud/console/applications) e conservatelo come backup.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non avete ancora effettuato l'accesso o la registrazione, verrete automaticamente reindirizzati alla pagina di accesso per invitarvi a registrarvi e ad accedere; al termine tornerete automaticamente alla pagina corrente.

**Un solo API Token può chiamare tutti i servizi della piattaforma, senza doverne richiedere uno separatamente per ciascun servizio.** Alla prima richiesta verrà fornita una quota gratuita, utilizzabile per un'esperienza gratuita; quando la quota è insufficiente, potete ricaricare il saldo universale nella [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Esempio di richiesta

La Suno Tasks API può essere utilizzata per interrogare i risultati di entrambi gli API Suno Audios Generation API e Suno Lyrics Generation API. Per informazioni su come utilizzare la Suno Audios Generation API, fate riferimento alla documentazione [Suno Audios Generation API ](https://platform.acedata.cloud/documents/suno-audios-integration). Per informazioni su come utilizzare la Suno Lyrics Generation API, fate riferimento a [Suno Lyrics Generation API ](https://platform.acedata.cloud/documents/suno-lyrics-generation-integration).

Prendiamo come esempio un ID attività restituito dal servizio Suno Audios Generation API, per dimostrare come utilizzare questa API. Supponiamo di avere un ID attività: eae26f89-b64b-404d-a80c-761996660b1c, di seguito viene mostrato come tramite l'inserimento di un ID attività.

### Impostare le intestazioni della richiesta e il corpo della richiesta

**Request Headers** includono:

- `accept`: specifica la ricezione del risultato di risposta in formato JSON, qui impostato su `application/json`.
- `authorization`: la chiave per chiamare l'API, dopo la richiesta può essere selezionata direttamente dal menu a discesa.

**Request Body** include:

- `id`: l'ID dell'attività caricata.
- `action`: la modalità di operazione sull'attività.

Alcuni esempi di codice sono i seguenti:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/suno/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "eae26f89-b64b-404d-a80c-761996660b1c",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/suno/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "eae26f89-b64b-404d-a80c-761996660b1c",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Il risultato restituito contiene diversi campi. Il campo `request` è il request body al momento dell'avvio dell'attività, mentre il campo `response` è il response body restituito dopo il completamento dell'attività. I campi sono descritti come segue.

- `id`, l'ID dell'attività di generazione di questa canzone, utilizzato per identificare univocamente questa attività di generazione della canzone.
- `request`, le informazioni sulla richiesta nell'interrogazione dell'attività della canzone.
- `response`, le informazioni di ritorno nell'interrogazione dell'attività della canzone.
- `created_at`, l'ora di creazione dell'attività, timestamp Unix (secondi, virgola mobile).
- `started_at`, l'ora di inizio esecuzione dell'attività, timestamp Unix (secondi, virgola mobile).
- `finished_at`, l'ora di completamento dell'attività, timestamp Unix (secondi, virgola mobile). Questo campo non viene restituito quando l'attività non è completata.
- `elapsed`, il tempo impiegato per l'esecuzione dell'attività, in secondi (virgola mobile, con 3 cifre decimali). Questo campo non viene restituito quando l'attività non è completata.

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice e il messaggio di errore corrispondenti. Ad esempio:

- `400 token_mismatched`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`：Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`：Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`：Errore interno del server, qualcosa è andato storto sul server.
