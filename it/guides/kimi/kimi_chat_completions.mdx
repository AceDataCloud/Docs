Kimi è una serie di modelli AI lanciata da Moonshot AI. Attualmente è consigliato `kimi-k3.1-pro`, adatto alla programmazione a lungo termine, al ragionamento complesso, alla comprensione visiva e al lavoro basato sulla conoscenza; `kimi-k3` può ancora essere utilizzato. Viene chiamato tramite l'API Chat Completions compatibile con OpenAI.

Questo documento presenta principalmente il processo di utilizzo delle operazioni dell'API Kimi Chat Completion, grazie alla quale possiamo usare facilmente la funzione di conversazione ufficiale di Kimi.

## Processo di richiesta

Per utilizzare l'API Kimi Chat Completion, per prima cosa vai alla [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token e conservarlo come riserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato l'accesso o la registrazione, verrai automaticamente reindirizzato alla pagina di accesso per invitarti a registrarti e accedere; al termine, tornerai automaticamente alla pagina corrente.

**Un solo API Token può chiamare tutti i servizi della piattaforma, senza dover fare richiesta separatamente per ogni servizio.** Alla prima richiesta verrà offerta una quota gratuita, utilizzabile per un'esperienza gratuita; quando la quota è insufficiente, puoi ricaricare il saldo generale nella [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Utilizzo di base

Successivamente puoi compilare i contenuti corrispondenti nell'interfaccia, come mostrato nella figura:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

Quando utilizzi questa interfaccia per la prima volta, devi compilare almeno tre contenuti: `authorization` può essere selezionato direttamente dall'elenco a discesa; `model` viene utilizzato per selezionare il modello Kimi, si consiglia di usare `kimi-k3.1-pro`; `messages` è un array di messaggi di conversazione, ogni messaggio contiene `role` e `content`, tra cui `role` supporta `user`, `assistant`, `system` e `tool`.

Allo stesso tempo puoi notare che sulla destra viene generato il codice di chiamata corrispondente; puoi copiare il codice ed eseguirlo direttamente, oppure fare direttamente clic sul pulsante «Try» per il test.

<p><img src="https://cdn.acedata.cloud/six7e3.png" width="400" className="m-auto" /></p>

Di seguito è riportata una risposta K3 reale ottenuta usando `reasoning_effort: max` (i campi di estensione non utilizzati sono omessi):

```json
{

  "object": "chat.completion",
  "created": 1784466588,
  "model": "kimi-k3",

      "index": 0,

    "prompt_tokens": 86,
    "completion_tokens": 206,
    "total_tokens": 292

```

Il risultato restituito contiene diversi campi, descritti come segue:

- `id`, l'ID generato per questa attività di conversazione, utilizzato per identificare in modo univoco questa attività di conversazione.
- `model `, il modello Kimi del sito ufficiale selezionato.
- `choices`, le informazioni di risposta fornite da Kimi alla richiesta.
- `usage `: le informazioni statistiche sui token per questa sessione di domande e risposte.

Tra questi, `choices` contiene le informazioni di risposta di Kimi; il suo `choices` contiene le informazioni specifiche della risposta di Kimi, come si può vedere nella figura.

Come si può vedere, il campo `content` in `choices` contiene il contenuto specifico della risposta di Kimi; K3 può anche restituire `reasoning_content`, utilizzato per rappresentare il processo di ragionamento.

## Intensità di ragionamento K3.1 Pro

`kimi-k3.1-pro` abilita sempre il ragionamento. Puoi impostare `reasoning_effort` nel livello superiore del corpo della richiesta su `low`, `high` o `max`; non passare configurazioni che disabilitano il ragionamento. Il modello supporta fino a 1.048.576 token di contesto, ma il limite effettivo della richiesta è comunque soggetto all'interfaccia corrente. Il prezzo viene calcolato in base all'utilizzo di input, output e cache hit; per i dettagli consulta la scheda Pricing del catalogo dei modelli.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Il seguente esempio K3 viene mantenuto per le integrazioni esistenti e la risposta di esempio è stata effettivamente ottenuta tramite una richiesta K3.

## Intensità di ragionamento K3

`kimi-k3` abilita sempre il ragionamento. Il livello superiore del corpo della richiesta supporta il campo `reasoning_effort`, il cui unico valore attualmente supportato è `max`; quando questo campo viene omesso, viene utilizzato ugualmente `max`. `standard`, `high` o altre stringhe possono essere accettate in modo permissivo da alcuni upstream compatibili, ma non è garantito che modifichino il comportamento di ragionamento, quindi non farvi affidamento.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

Quando utilizzi OpenAI SDK, puoi passare direttamente questo campo:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

Durante conversazioni multi-turno e chiamate di strumenti, restituisci in `messages` il messaggio assistant completo del turno precedente, inclusi `reasoning_content` e `tool_calls`.

### Riferimenti ufficiali

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort): spiega che Kimi K3 abilita sempre il ragionamento e che l'unico valore attualmente supportato da `reasoning_effort` è `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview): confronta le differenze nei parametri di ragionamento, nella finestra di contesto e nelle chiamate di strumenti tra K3 e la serie K2.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat): definizioni ufficiali Moonshot per richieste Chat Completions, risposte e campi OpenAPI.

## Risposta in streaming

Questa interfaccia supporta anche le risposte in streaming, molto utili per l'integrazione web, consentendo alla pagina web di ottenere un effetto di visualizzazione parola per parola.

Se desideri restituire le risposte in streaming, puoi modificare il parametro `stream ` nell'intestazione della richiesta impostandolo su `true`.

La modifica è mostrata nella figura, ma il codice di chiamata deve essere modificato di conseguenza per supportare la risposta in streaming.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>

Dopo aver modificato `stream` in `true`, l'API restituirà riga per riga i dati JSON corrispondenti; a livello di codice dobbiamo apportare le modifiche corrispondenti per ottenere i risultati riga per riga.

Codice di chiamata di esempio Python:
```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Di seguito sono riportati estratti dei blocchi di dati di inizio, ragionamento, corpo, fine e utilizzo della stessa risposta reale in streaming di K3 Max:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Come si può vedere, nella risposta sono presenti molti `data`; i `choices` all'interno dei `data` rappresentano il contenuto della risposta più recente, coerente con il contenuto introdotto sopra. I `choices` sono il contenuto della risposta aggiunto, che è possibile integrare nel proprio sistema in base al risultato. Allo stesso tempo, la fine della risposta in streaming viene determinata in base al contenuto dei `data`: se il contenuto è `[DONE]`, significa che la risposta in streaming è completamente terminata. Il risultato `data` restituito contiene diversi campi, descritti di seguito:

- `id`, l'ID generato per questa attività di conversazione, utilizzato per identificare in modo univoco questa attività di conversazione.
- `model `, il modello Kimi selezionato dal sito ufficiale.
- `choices`, le informazioni della risposta fornite da Kimi per il prompt.

Anche JavaScript è supportato, ad esempio il codice di chiamata in streaming per Node.js è il seguente:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Codice di esempio Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Gli altri linguaggi possono essere adattati autonomamente in modo diverso; il principio è lo stesso.

## Conversazione multi-turno

Se si desidera integrare la funzionalità di conversazione multi-turno, è necessario caricare più prompt nel campo `messages`; un esempio specifico di più prompt è mostrato nella figura seguente:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Codice di esempio di chiamata Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Caricando più prompt, è possibile implementare facilmente una conversazione multi-turno. Di seguito è riportata la risposta reale di K3 Max ottenuta da questa richiesta (i campi di estensione non utilizzati sono omessi):

Come si può vedere, le informazioni contenute in `choices` sono coerenti con il contenuto dell'utilizzo di base; questo include il contenuto specifico della risposta di Kimi a più conversazioni, in modo da poter rispondere alle domande corrispondenti in base a più contenuti di conversazione.

## Gestione degli errori

Durante la chiamata dell'API, se si verifica un errore, l'API restituirà il codice e le informazioni di errore corrispondenti. Ad esempio:

- `400 token_mismatched`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`：Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`：Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`：Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```

    "message": "fetch failed"
  },

}
```
