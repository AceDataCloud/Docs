Kimi è una serie di modelli di intelligenza artificiale sviluppata da Moonshot AI. Attualmente, il modello consigliato è `kimi-k3.1-pro`, adatto alla programmazione a lungo termine, al ragionamento complesso, alla comprensione visiva e alle attività basate sulla conoscenza; `kimi-k3` è ancora disponibile. L'API viene utilizzata tramite l'endpoint Chat Completions compatibile con OpenAI.

Questo documento illustra principalmente il flusso operativo dell'API Kimi Chat Completion, che consente di utilizzare facilmente le funzionalità di conversazione ufficiali di Kimi.

## Modelli supportati

Attualmente sono supportati quattro modelli: `kimi-k3.1-pro`, `kimi-k3`, `kimi-k2.6` e `kimi-k2.7-code`. K2.7 Code è progettato per scenari di programmazione e chiamata degli strumenti e viene tariffato allo stesso livello di K2.6; non trasmettere l'interruttore `thinking` o `reasoning_effort` nelle richieste. Gli altri modelli Kimi non sono più supportati. Seleziona esplicitamente uno di questi quattro modelli nel client.

## Procedura di richiesta

Per utilizzare l'API Kimi Chat Completion, accedi innanzitutto alla [console di Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token e conservarlo per un utilizzo successivo.

![]()

Se non hai ancora effettuato l'accesso o la registrazione, verrai automaticamente reindirizzato alla pagina di accesso, dove potrai registrarti ed effettuare il login. Al termine, tornerai automaticamente alla pagina corrente.

**Un solo API Token consente di utilizzare tutti i servizi della piattaforma, senza dover richiedere un token separato per ogni servizio.** Alla prima richiesta riceverai un credito gratuito per provare il servizio senza costi; quando il credito sarà insufficiente, potrai ricaricare il saldo generale nella [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Utilizzo di base

Successivamente, puoi compilare i campi corrispondenti nell'interfaccia, come mostrato nell'immagine:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

Al primo utilizzo di questa interfaccia, è necessario compilare almeno tre campi: `authorization` può essere selezionato direttamente dall'elenco a discesa; `model` serve per selezionare il modello Kimi, si consiglia di utilizzare `kimi-k3.1-pro`; `messages` è un array di messaggi della conversazione, in cui ogni messaggio contiene `role` e `content`, e `role` supporta `user`, `assistant`, `system` e `tool`.

Allo stesso tempo, puoi notare che sulla destra viene generato il codice corrispondente alla chiamata. Puoi copiare il codice ed eseguirlo direttamente oppure fare clic sul pulsante «Try» per effettuare un test.

Il risultato restituito contiene diversi campi, descritti di seguito:

- `id`: ID generato per questa attività di conversazione, utilizzato per identificarla in modo univoco.
- `model `: il modello Kimi selezionato.
- `choices`: le informazioni relative alla risposta fornita da Kimi alla richiesta.
- `usage `: le informazioni statistiche sui token utilizzati in questa sessione di domande e risposte.

Tra questi, `choices` contiene le informazioni relative alla risposta di Kimi. Al suo interno, `choices` contiene i dettagli specifici della risposta di Kimi, come mostrato nell'immagine.

Come puoi vedere, il campo `content` all'interno di `choices` contiene il contenuto specifico della risposta di Kimi; K3 può anche restituire `reasoning_content`, che rappresenta il processo di ragionamento.

## Intensità del ragionamento di K3.1 Pro

`kimi-k3.1-pro` abilita sempre il ragionamento. È possibile impostare `reasoning_effort` al livello superiore del corpo della richiesta su `low`, `high` o `max`; non trasmettere configurazioni che disattivano il ragionamento. Il modello supporta una finestra di contesto fino a 1.048.576 token, ma il limite effettivo delle richieste dipende comunque dall'interfaccia attualmente disponibile. Il prezzo viene calcolato in base all'utilizzo di token di input, output e cache hit. Per ulteriori dettagli, consulta la scheda Pricing del catalogo dei modelli.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Gli esempi seguenti di K3 vengono mantenuti per le integrazioni esistenti; le risposte di esempio sono state effettivamente ottenute tramite richieste a K3.

## Intensità del ragionamento di K3

`kimi-k3` abilita sempre il ragionamento. Il campo `reasoning_effort` è supportato al livello superiore del corpo della richiesta. Attualmente, l'unico valore supportato è `max`; anche se il campo viene omesso, viene comunque utilizzato `max`. Utilizza esclusivamente i valori supportati.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

Quando utilizzi OpenAI SDK, puoi passare direttamente questo campo:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

Durante le conversazioni su più turni e le chiamate agli strumenti, restituisci a `messages` l'intero messaggio `assistant` del turno precedente, inclusi `reasoning_content` e `tool_calls`.

### Riferimenti ufficiali

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort): spiega che Kimi K3 abilita sempre il ragionamento e che attualmente l'unico valore supportato per `reasoning_effort` è `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview): confronta i parametri di ragionamento, le finestre di contesto e le differenze nelle chiamate agli strumenti tra K3 e la serie K2.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat): definizioni ufficiali di Moonshot per le richieste e le risposte Chat Completions e per i campi OpenAPI.

## Risposta in streaming

Questa interfaccia supporta anche le risposte in streaming, una funzionalità molto utile per l'integrazione nelle pagine web, che consente di visualizzare il testo progressivamente, carattere per carattere.

Se desideri ricevere le risposte in streaming, puoi modificare il parametro `stream ` nell'intestazione della richiesta impostandolo su `true`.

Modificalo come mostrato nell'immagine. Tuttavia, anche il codice della chiamata deve essere modificato di conseguenza per supportare le risposte in streaming.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>
Dopo aver modificato `stream` in `true`, l'API restituirà i corrispondenti dati JSON riga per riga. A livello di codice, dobbiamo apportare le modifiche necessarie per ottenere i risultati riga per riga.

Codice di esempio per una chiamata Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Di seguito sono riportati alcuni blocchi di dati iniziali, di ragionamento, di contenuto, di chiusura e di utilizzo, estratti da una risposta in streaming reale della stessa richiesta K3 Max:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Come si può vedere, la risposta contiene numerosi `data` e il campo `choices` all'interno di `data` rappresenta il contenuto più recente della risposta, coerentemente con quanto descritto sopra. `choices` contiene il nuovo contenuto della risposta, che è possibile integrare nel proprio sistema in base ai risultati. Allo stesso tempo, la fine della risposta in streaming viene determinata in base al contenuto di `data`: se il contenuto è `[DONE]`, significa che la risposta in streaming è terminata completamente. I dati `data` restituiti contengono diversi campi, descritti di seguito:

- `id`: l'ID generato per questa attività di conversazione, utilizzato per identificare univocamente l'attività.
- `model `: il modello del sito ufficiale Kimi selezionato.
- `choices`: le informazioni di risposta fornite da Kimi in relazione al prompt.

Anche JavaScript è supportato. Di seguito è riportato, ad esempio, il codice per effettuare una chiamata in streaming con Node.js:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Codice di esempio Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Per altri linguaggi è possibile adattare autonomamente il codice; il principio è sempre lo stesso.

## Conversazioni su più turni

Se si desidera integrare la funzionalità di conversazione su più turni, è necessario inviare più prompt nel campo `messages`. Di seguito è riportato un esempio specifico di più prompt:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Codice di esempio per una chiamata Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Gestione degli errori

Quando si verifica un errore durante una chiamata API, l'API restituisce il codice e le informazioni di errore corrispondenti. Ad esempio:

- `400 token_mismatched`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`: Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`: Troppe richieste, è stato superato il limite di frequenza.
- `500 api_error`: Errore interno del server, si è verificato un problema sul server.

### Esempio di risposta di errore
