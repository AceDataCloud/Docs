## 1. Ottenere l'API Key

Apri l'[elenco delle applicazioni Ace Data Cloud](https://platform.acedata.cloud/console/applications), accedi a un'applicazione disponibile e copia l'API Key.

![Ottenere l'API Key di Ace Data Cloud](https://cdn.acedata.cloud/dvc3cg.jpg)

## 2. Inviare la prima richiesta

```bash
curl https://api.acedata.cloud/openai/images/generations \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "Minimal editorial product illustration: one plain white ceramic coffee mug centered on a solid cobalt blue tabletop, pale cream background, soft shadow, clean geometric shapes, no text, no logo, portrait composition",
    "size": "1024x1536"
  }'
```

L'immagine della risposta riuscita si trova in `data[].url`. Di seguito è riportato il risultato 1024×1536 ottenuto tramite una richiesta effettiva su Ace Data Cloud l'8 settembre 2026 (attività `d56455e2-e7f7-4bcd-b935-475b0a1e0948`, trace `eb938601-8192-407f-b539-1e0554b697ec`):

![Tazza bianca generata da GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

## 3. Parametri comuni

| Campo                | Descrizione                                                                                                                                     |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2` (consigliato per impostazione predefinita), `gpt-image-2.5-flare` (più veloce) o `gpt-image-2.5-sunburst` (maggiore fedeltà e controllo); tutti e tre possono scegliere la corrispondente variante `:official`, mentre `gpt-image-2` supporta anche `:reverse` |
| `prompt`          | Descrizione dell'immagine, fino a 32.000 caratteri                                                                                                                     |
| `size`            | `auto` o `WIDTHxHEIGHT`; larghezza e altezza devono essere multipli di 16, il lato lungo non deve superare 3840, i pixel totali devono essere 655.360–8.294.400 e il rapporto d'aspetto non deve superare 3:1                                                       |
| `n`               | 1–10; quando `response_format=b64_json`, è supportato solo 1                                                                                                 |
| `quality`         | I modelli GPT Image supportano `auto`, `low`, `medium`, `high`; Flare / Sunburst 2.5 / 2.6 (incluso `:official`) supportano inoltre `xhigh`, `max`. Il canale ufficiale addebita in base all'effettivo utilizzo di Token             |
| `response_format` | `url` o `b64_json`                                                                                                                     |
| `callback_url`    | Opzionale; invia il risultato a questo indirizzo dopo il completamento di attività lunghe                                                                                                                      |

Dimensioni comuni:

| Rapporto   | 1K          | 2K          | 4K          |
| ---- | ----------- | ----------- | ----------- |
| 1:1  | `1024x1024` | `2048x2048` | `2880x2880` |
| 4:3  | `1536x1024` | `2048x1536` | `3264x2448` |
| 3:4  | `1024x1536` | `1536x2048` | `2448x3264` |
| 16:9 | `1792x1024` | `2048x1152` | `3840x2160` |
| 9:16 | `1024x1792` | `1152x2048` | `2160x3840` |

`size: "auto"` selezionerà il formato in base al rapporto, ai pixel e all'intento di layout nel prompt; quando sono necessari pixel precisi, inserisci direttamente le dimensioni.

| `gpt-image-2:official`            | Canale API ufficiale, maggiore stabilità, tariffazione in base all'effettivo utilizzo di Token                   |
| `gpt-image-2.5-flare`             | Privilegia la velocità di generazione, tariffazione fissa in base al numero di immagini riuscite                               |
| `gpt-image-2.6-flare`             | Privilegia la velocità di generazione, tariffazione fissa in base al numero di immagini riuscite                               |
| `gpt-image-2.5-flare:reverse`     | Alias inverso esplicito, equivalente a `gpt-image-2.5-flare`, tariffazione fissa in base al numero di immagini riuscite    |
| `gpt-image-2.6-flare:reverse`     | Alias inverso esplicito, equivalente a `gpt-image-2.6-flare`, tariffazione fissa in base al numero di immagini riuscite    |
| `gpt-image-2.5-flare:official`    | Canale API ufficiale, maggiore stabilità e privilegia la velocità di generazione, tariffazione in base all'effettivo utilizzo di Token            |
| `gpt-image-2.6-flare:official`    | Canale API ufficiale, maggiore stabilità e privilegia la velocità di generazione, tariffazione in base all'effettivo utilizzo di Token            |
| `gpt-image-2.5-sunburst`          | Privilegia l'alta fedeltà e il controllo fine, tariffazione fissa in base al numero di immagini riuscite                           |
| `gpt-image-2.6-sunburst`          | Privilegia l'alta fedeltà e il controllo fine, tariffazione fissa in base al numero di immagini riuscite                           |
| `gpt-image-2.5-sunburst:reverse`  | Alias inverso esplicito, equivalente a `gpt-image-2.5-sunburst`, tariffazione fissa in base al numero di immagini riuscite |
| `gpt-image-2.6-sunburst:reverse`  | Alias inverso esplicito, equivalente a `gpt-image-2.6-sunburst`, tariffazione fissa in base al numero di immagini riuscite |
| `gpt-image-2.5-sunburst:official` | Canale API ufficiale, maggiore stabilità e privilegia l'alta fedeltà e il controllo fine, tariffazione in base all'effettivo utilizzo di Token        |
| `gpt-image-2.6-sunburst:official` | Canale API ufficiale, maggiore stabilità e privilegia l'alta fedeltà e il controllo fine, tariffazione in base all'effettivo utilizzo di Token        |

I modelli inversi 2.0 / 2.5 (inclusi gli alias `:reverse`) possono utilizzare GPT Image 2.5 Flare per completare la richiesta durante il ripristino automatico; il modello richiesto e la modalità di fatturazione in base al numero di immagini riuscite rimangono invariati.

Il prezzo mostrato sulla pagina per il canale API ufficiale è una stima precedente alla richiesta; il risultato finale è soggetto all'effettivo utilizzo di Token nella risposta e al registro di utilizzo.

## 4. Generazione di più immagini

```bash
curl https://api.acedata.cloud/openai/images/generations \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "prompt": "A small fox reading under a glowing mushroom, watercolor illustration",
    "size": "1536x1024",
    "n": 2
  }'
```
`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` e i relativi alias `:reverse` vengono fatturati in base al numero di immagini riuscite; `gpt-image-2:official`, `gpt-image-2.5-flare:official` e `gpt-image-2.5-sunburst:official` vengono fatturati in base ai Token effettivi di input testuale e output immagine nella risposta. Il prezzo nella pagina è una stima precedente alla richiesta; fa fede il record di utilizzo finale.

## 5. Callback asincrono

Dopo aver aggiunto `callback_url` al corpo della richiesta, l'interfaccia restituirà prima `{"task_id": "..."}` e, al completamento, invierà il risultato finale tramite POST a tale URL; le richieste sincrone restituiscono ancora `created` e `data`:

```json
{
  "model": "gpt-image-2",
  "prompt": "A product poster with clear typography",
  "size": "1024x1024",
  "callback_url": "https://example.com/webhooks/images"
}
```

Il destinatario del callback deve usare `task_id` per la deduplicazione e verificare l'origine della richiesta e il formato dei dati.

## 6. Risoluzione dei problemi

| Stato  | Verifica                                                  |
| --- | --------------------------------------------------- |
| 400 | Combinazione di `model`, `prompt`, formato delle dimensioni, `n` e `response_format`    |
| 401 | Se la API Key è completa, se l'Header è `Authorization: Bearer ...` |
| 429 | Richieste troppo frequenti, riprovare più tardi                                         |
| 504 | Timeout della generazione sincrona; usare invece `callback_url`                            |

La risposta di errore includerà `error.code`, `error.message` e `trace_id`. Quando si segnala un problema, fornire `trace_id`, non fornire la API Key.

Per i campi completi e le enumerazioni in tempo reale, fare riferimento alla pagina [OpenAI Images Generations API](https://platform.acedata.cloud/documents/openai-images-generations). Per la modifica delle immagini, consultare [Modifica immagini GPT Image 2 / 2.5 / 2.6](https://platform.acedata.cloud/documents/openai-images-edits).

## GPT Image 2.6

GPT Image 2.6 utilizza le interfacce di generazione, modifica, attività asincrone e fatturazione della versione 2.5:

| Modello                                                          | Fatturazione                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0.22 Credits/immagine                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0.22 Credits/immagine                   |
| `gpt-image-2.6-flare:official`                              | Uguale a 2.5 official, fatturato in base all'utilizzo effettivo di Token |
| `gpt-image-2.6-sunburst:official`                           | Uguale a 2.5 official, fatturato in base all'utilizzo effettivo di Token |

La qualità può essere `auto`, `low`, `medium`, `high`, `xhigh`, `max`; per le dimensioni usare `auto` oppure `WIDTHxHEIGHT` conforme ai vincoli sopra indicati. Questa interfaccia supporta `png`, `jpeg`, `webp`; GPT Image 2.6 supporta inoltre GIF animate native, ma SVG non è ancora supportato. La modifica supporta URL di immagini JSON e caricamento di file multipart. `:reverse` è un alias esplicito della versione normale con lo stesso nome. Usare il modello completo, non passare `gpt-image-2.6`.

### GIF animate GPT Image 2.6

La versione normale, `:reverse`, `:official` di Flare, nonché `gpt-image-2.6-sunburst:official`, possono usare `output_format: "gif"`. La versione normale di Sunburst e `:reverse` non rendono ancora disponibili le GIF, ma supportano comunque la generazione e la modifica di immagini statiche. I fotogrammi dell'animazione, le informazioni sul ciclo e la durata di riproduzione verranno mantenuti; `frame_count` indica il numero di fotogrammi, `frame_duration_ms` indica i millisecondi per fotogramma, entrambi devono essere interi positivi e sono utilizzati solo per le GIF. Se non specificato, il valore predefinito è 9 fotogrammi, 200 millisecondi per fotogramma; quando la dimensione della GIF viene omessa o è auto, viene utilizzato il preset 512x512.

Si consiglia di usare prima `size: "512x512"`, `frame_count: 9`, `frame_duration_ms: 200`. Le GIF hanno limiti indipendenti per dimensioni e numero di fotogrammi e non possono applicare direttamente le specifiche statiche 4K; alcuni modelli adatteranno le dimensioni effettive dell'output. `n` indica il numero di file GIF restituiti, non il numero di fotogrammi dell'animazione. La versione normale e `:reverse` continuano a essere fatturati in base al numero di file riusciti, mentre la versione ufficiale è fatturata in base all'utilizzo effettivo di Token.

```json
{
  "model": "gpt-image-2.6-flare",
  "prompt": "A small red ball moves left and right on a white background, seamless looping animation, no text.",
  "output_format": "gif",
  "size": "512x512",
  "quality": "medium",
  "frame_count": 9,
  "frame_duration_ms": 200,
  "n": 1,
  "async": true
}
```

### Immagini statiche 4K GPT Image 2.6

Flare, Sunburst e le rispettive varianti `:reverse`, `:official` possono tutte utilizzare i preset di pixel 4K sopra indicati, ad esempio `3840x2160` e `2160x3840`. Sia la generazione sia la modifica ricevono pixel specifici tramite `size`; `4K` non è un valore `size` valido e anche `4096x4096` supera l'attuale limite di pixel. Le specifiche 4K sopra indicate si applicano a PNG/JPEG/WebP statici; per le GIF usare i relativi parametri dedicati.
