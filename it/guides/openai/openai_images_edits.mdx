## 2. Modifica usando l'URL dell'immagine

Immagine originale:

![Immagine originale per la modifica GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",

  }'
```

## 3. Caricare immagini locali

Usa `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

È possibile passare ripetutamente `image`; la serie GPT Image supporta fino a 16 immagini di riferimento. `image` nelle richieste JSON può essere un singolo URL o un array di URL; i file locali vengono caricati tramite multipart.

### Modelli e modalità di fatturazione

| Modello                                | Scenari applicabili e modalità di fatturazione                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | Canale inverso predefinito, fatturazione fissa in base al numero di immagini riuscite                               |
| `gpt-image-2:reverse`             | Seleziona esplicitamente il canale inverso, fatturazione fissa in base al numero di immagini riuscite                             |
| `gpt-image-2:official`            | Canale API ufficiale, maggiore stabilità, fatturazione in base all'effettivo utilizzo di Token                   |
| `gpt-image-2.5-flare`             | Incentrato sulla velocità di generazione, fatturazione fissa in base al numero di immagini riuscite                               |
| `gpt-image-2.6-flare`             | Incentrato sulla velocità di generazione, fatturazione fissa in base al numero di immagini riuscite                               |
| `gpt-image-2.5-flare:reverse`     | Alias inverso esplicito, equivalente a `gpt-image-2.5-flare`, fatturazione fissa in base al numero di immagini riuscite    |
| `gpt-image-2.6-flare:reverse`     | Alias inverso esplicito, equivalente a `gpt-image-2.6-flare`, fatturazione fissa in base al numero di immagini riuscite    |
| `gpt-image-2.5-flare:official`    | Canale API ufficiale, maggiore stabilità e incentrato sulla velocità di generazione, fatturazione in base all'effettivo utilizzo di Token            |
| `gpt-image-2.6-flare:official`    | Canale API ufficiale, maggiore stabilità e incentrato sulla velocità di generazione, fatturazione in base all'effettivo utilizzo di Token            |
| `gpt-image-2.5-sunburst`          | Incentrato su alta fedeltà e controllo preciso, fatturazione fissa in base al numero di immagini riuscite                           |
| `gpt-image-2.6-sunburst`          | Incentrato su alta fedeltà e controllo preciso, fatturazione fissa in base al numero di immagini riuscite                           |
| `gpt-image-2.5-sunburst:reverse`  | Alias inverso esplicito, equivalente a `gpt-image-2.5-sunburst`, fatturazione fissa in base al numero di immagini riuscite |
| `gpt-image-2.6-sunburst:reverse`  | Alias inverso esplicito, equivalente a `gpt-image-2.6-sunburst`, fatturazione fissa in base al numero di immagini riuscite |
| `gpt-image-2.5-sunburst:official` | Canale API ufficiale, maggiore stabilità e incentrato su alta fedeltà e controllo preciso, fatturazione in base all'effettivo utilizzo di Token        |
| `gpt-image-2.6-sunburst:official` | Canale API ufficiale, maggiore stabilità e incentrato su alta fedeltà e controllo preciso, fatturazione in base all'effettivo utilizzo di Token        |

I modelli inversi 2.0 / 2.5 (inclusi gli alias `:reverse`) possono utilizzare GPT Image 2.5 Flare per completare la richiesta durante il ripristino automatico; il modello richiesto e la modalità di fatturazione in base al numero di immagini riuscite rimangono invariati.

Il prezzo mostrato sulla pagina del canale API ufficiale è una stima precedente alla richiesta; il risultato finale fa riferimento all'effettivo utilizzo di Token nella risposta e ai record di utilizzo.

`quality` supporta `auto`, `low`, `medium`, `high`; Flare e Sunburst 2.5 / 2.6 (incluse le varianti `:reverse` e `:official`) supportano inoltre `xhigh`, `max`. Sia la modifica di immagini tramite URL JSON sia la modifica di file multipart possono passare questo campo; il canale ufficiale fattura in base all'effettivo utilizzo di Token.

## 4. Utilizzare una maschera per la modifica locale

L'interfaccia ufficiale Images Edit specifica l'area in cui sono consentite le modifiche tramite `mask`. I modelli `:official` di Ace Data Cloud seguono lo stesso contratto multipart:

- `mask` deve essere un PNG con canale Alpha, con dimensione non superiore a 4 MB;
- le dimensioni della maschera devono essere esattamente uguali a quelle della prima `image`;
- i pixel trasparenti con Alpha pari a `0` indicano che la modifica è consentita, mentre i pixel non trasparenti indicano che devono essere mantenuti;
- le immagini RGB che sono solo in bianco e nero, ma non hanno un canale trasparente, non possono essere utilizzate come maschere valide;
- il prompt deve descrivere l'intera immagine desiderata, specificando al contempo le modifiche locali e il contenuto che deve rimanere invariato.

Di seguito viene prima generata una maschera a partire dall'immagine originale. L'esempio imposta come trasparente il rettangolo centrale, consentendo al modello di modificare solo questa area:
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Quindi carica insieme l'immagine originale e la maschera:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Puoi anche continuare a utilizzare il metodo di chiamata `images.edit` dell'SDK Python ufficiale di OpenAI, devi solo puntare `base_url` ad Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Quando si utilizza `mask`, l'immagine originale e la maschera devono essere caricate separatamente nella stessa richiesta multipart tramite `image=@input.png` e `mask=@mask.png`. Non combinare l'immagine originale tramite URL con un file di maschera locale; le richieste di modifica solo URL non supportano l'aggiunta di file `mask` locali. La maschera delimita l'area di modifica, ma il modello generativo potrebbe comunque fondere naturalmente i bordi; quando sono richiesti confini rigorosi, utilizza bordi Alpha nitidi e ripeti nel prompt quali contenuti devono rimanere invariati.

Il metodo di chiamata sopra è coerente con gli esempi di maschera dell'[API OpenAI Image Edit](https://developers.openai.com/api/reference/python/resources/images/methods/edit) e del [Cookbook ufficiale GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Parametri comuni

| Campo                | Descrizione                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (più veloce) o `gpt-image-2.5-sunburst` (maggiore fedeltà e controllo); tutti e tre possono selezionare la variante `:official` corrispondente, mentre `gpt-image-2` supporta anche `:reverse` |
| `image`           | JSON utilizza un singolo URL o un array di massimo 16 URL; multipart utilizza uno o più campi file `image`. Quando si utilizza `mask`, è necessario caricare file di immagini locali                                              |
| `mask`            | Maschera PNG opzionale, limitata al caricamento di file multipart; deve avere un canale Alpha, le stesse dimensioni della prima `image` e non superare 4 MB                                                                 |
| `prompt`          | Istruzione di modifica                                                                                                                             |
| `size`            | `auto` o `WIDTHxHEIGHT` conforme ai limiti                                                                                                     |
| `n`               | 1–10; quando `response_format=b64_json`, è supportato solo 1                                                                                           |
| `response_format` | `url` o `b64_json`                                                                                                               |
| `callback_url`    | Indirizzo di callback asincrono opzionale                                                                                                                         |

Le regole sulle dimensioni sono uguali a quelle dell'interfaccia di generazione: larghezza e altezza devono essere multipli di 16, il lato lungo non deve superare 3840, i pixel totali devono essere 655.360–8.294.400 e il rapporto larghezza-altezza non deve superare 3:1. Quando `size` viene omesso o si utilizza `auto`, il modello seleziona il formato combinando il prompt e la prima immagine di riferimento.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` e i relativi alias `:reverse` vengono fatturati in base al numero di immagini riuscite; `gpt-image-2:official`, `gpt-image-2.5-flare:official` e `gpt-image-2.5-sunburst:official` vengono addebitati in base ai Token effettivi dell'input testuale, dell'input dell'immagine di riferimento e dell'output dell'immagine, e fa fede il registro di utilizzo finale.

## 6. Callback asincrono e risoluzione dei problemi

Per le attività lunghe, puoi aggiungere nella richiesta:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

La risposta asincrona 200 è `{"task_id": "..."}`; al completamento verrà effettuato il callback con il risultato finale. Le richieste sincrone restituiscono invece `created` e `data`.

| Stato  | Verifica                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Formato/numero di immagini, combinazioni di parametri e formato delle dimensioni; quando si utilizza `mask`, verifica il canale Alpha PNG, il limite di 4 MB e che le sue dimensioni corrispondano alla prima immagine originale |
| 401 | API Key e Bearer Header                                           |
| 429 | Frequenza delle richieste                                                              |
| 504 | Passa al callback asincrono                                                            |

Le risposte di errore includono `trace_id`. Quando segnali un problema, fornisci questo ID, non fornire l'API Key.

Per i campi completi e le enumerazioni in tempo reale, fai riferimento alla pagina [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Per la generazione di immagini da puro testo, consulta [Generazione immagini GPT Image 2 / 2.5 / 2.6](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 continua a utilizzare le interfacce di generazione, modifica, attività asincrone e fatturazione della 2.5:

| Modello                                                          | Fatturazione                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0,22 Credits/immagine                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0,22 Credits/immagine                   |
| `gpt-image-2.6-flare:official`                              | Uguale a 2.5 official, fatturato in base all'utilizzo effettivo di Token |
| `gpt-image-2.6-sunburst:official`                           | Uguale a 2.5 official, fatturato in base all'utilizzo effettivo di Token |

La qualità può essere `auto`, `low`, `medium`, `high`, `xhigh`, `max`; per le dimensioni utilizza `auto` o `WIDTHxHEIGHT` conforme ai vincoli sopra indicati. Questa interfaccia supporta `png`, `jpeg`, `webp`, ma al momento non supporta SVG/GIF. La modifica supporta URL di immagini JSON e il caricamento di file multipart. `:reverse` è un alias esplicito della versione normale con lo stesso nome. Utilizza il nome completo del modello, non passare `gpt-image-2.6`.
