## 2. Modificare usando l'URL dell'immagine

Immagine originale:

![Immagine originale per la modifica di GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://platform2.cdn.acedata.cloud/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0.png",
    "prompt": "Keep the mug, tabletop, camera angle, portrait layout, and soft shadow unchanged. Change only the mug color from white to vivid orange and the pale cream background to solid dark navy blue. No text and no logo.",
    "size": "1024x1536"
  }'
```

## 3. Caricare immagini locali

Usa `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

Puoi inviare ripetutamente `image`; la serie GPT Image supporta fino a 16 immagini di riferimento. `image` nelle richieste JSON può essere un singolo URL o un array di URL; i file locali vengono caricati tramite multipart.

## 4. Usare una maschera per la modifica locale

L'interfaccia ufficiale Images Edit specifica le aree che possono essere modificate tramite `mask`. Il modello `:official` di Ace Data Cloud segue lo stesso contratto multipart:

- `mask` deve essere un PNG con canale Alpha, di dimensioni non superiori a 4 MB;
- le dimensioni della maschera devono essere esattamente uguali alla prima `image`;
- i pixel trasparenti con Alpha pari a `0` indicano che la modifica è consentita, mentre i pixel non trasparenti indicano che devono essere mantenuti;
- le immagini RGB che sono solo in bianco e nero, ma non hanno un canale trasparente, non possono essere usate come maschere valide;
- il prompt deve descrivere l'immagine completa desiderata, specificando chiaramente al contempo le modifiche locali e i contenuti che devono rimanere invariati.

Di seguito viene prima generata una maschera dall'immagine originale. L'esempio imposta il rettangolo centrale come trasparente, consentendo al modello di modificare solo tale area:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Quindi carica insieme l'immagine originale e la maschera:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Puoi anche continuare a usare il metodo di chiamata `images.edit` dell'SDK Python ufficiale di OpenAI; devi solo puntare `base_url` ad Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Quando usi `mask`, l'immagine originale e la maschera devono essere caricate nello stesso richiesta multipart rispettivamente tramite `image=@input.png` e `mask=@mask.png`. Non combinare un'immagine originale tramite URL con un file maschera locale; le richieste di modifica basate esclusivamente su URL non supportano l'aggiunta di file `mask` locali. La maschera limiterà l'area di modifica, ma il modello generativo potrebbe comunque fondere naturalmente i bordi; quando sono necessari confini rigorosi, usa bordi Alpha nitidi e ripeti nel prompt quali contenuti devono rimanere invariati.

I metodi di chiamata sopra indicati sono coerenti con gli esempi di maschera della [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) e del [Cookbook ufficiale di GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Parametri comuni

| Campo                | Descrizione                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (più veloce) o `gpt-image-2.5-sunburst` (maggiore fedeltà e controllo); tutti e tre possono selezionare la variante `:official` corrispondente, mentre `gpt-image-2` supporta anche `:reverse` |
| `image`           | JSON usa un singolo URL o un array di fino a 16 URL; multipart usa uno o più campi file `image`. Quando si usa `mask`, è necessario caricare file immagine locali                                              |
| `mask`            | Maschera PNG opzionale, limitata al caricamento di file multipart; deve avere un canale Alpha, le stesse dimensioni della prima `image` e non superare 4 MB                                                                 |
| `prompt`          | Istruzione di modifica                                                                                                                             |
| `size`            | `auto` o un `WIDTHxHEIGHT` conforme alle limitazioni                                                                                                     |
| `n`               | 1–10; quando `response_format=b64_json`, è supportato solo 1                                                                                           |
| `response_format` | `url` o `b64_json`                                                                                                               |
| `callback_url`    | Indirizzo di callback asincrono opzionale                                                                                                                         |
Le regole sulle dimensioni sono coerenti con l'interfaccia di generazione: larghezza e altezza devono essere multipli di 16, il lato lungo non deve superare 3840, il totale dei pixel è 655.360–8.294.400 e il rapporto larghezza-altezza non deve superare 3:1. Quando `size` viene omesso o si utilizza `auto`, il modello sceglierà il formato combinando il prompt e la prima immagine di riferimento.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` e `gpt-image-2:reverse` vengono fatturati in base al numero di immagini riuscite; `gpt-image-2:official`, `gpt-image-2.5-flare:official` e `gpt-image-2.5-sunburst:official` vengono regolati in base ai Token effettivi dell'input testuale, dell'input delle immagini di riferimento e dell'output delle immagini; fa fede il registro di utilizzo finale.

## 6. Callback asincrono e risoluzione dei problemi

Le attività lunghe possono includere nella richiesta:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

La risposta asincrona 200 è `{"task_id": "..."}`; una volta completata, viene eseguito il callback con il risultato finale. Le richieste sincrone restituiscono invece `created` e `data`.

| Stato  | Verifica                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Formato/quantità delle immagini, combinazione dei parametri e formato delle dimensioni; quando si usa `mask`, verificare il canale Alpha PNG, il limite di 4MB e che le sue dimensioni coincidano con la prima immagine originale |
| 401 | API Key e Header Bearer                                           |
| 429 | Frequenza delle richieste                                                              |
| 504 | Passare al callback asincrono                                                            |

Le risposte di errore includono `trace_id`. Quando si segnala un problema, fornire tale ID e non fornire l'API Key.

Per i campi completi e le enumerazioni in tempo reale, fare riferimento alla pagina [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Per la generazione di immagini da testo semplice, consultare [GPT Image 2 / 2.5 Generazione di immagini](https://platform.acedata.cloud/documents/openai-images-generations).
