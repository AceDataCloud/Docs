## 2. Modifica usando l'URL dell'immagine

Immagine originale:

![Immagine originale per la modifica di GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
    "prompt": "Keep the mug, tabletop, camera angle, portrait layout, and soft shadow unchanged. Change only the mug color from white to vivid orange and the pale cream background to solid dark navy blue. No text and no logo.",
    "size": "1024x1536"
  }'
```

## 3. Caricare immagini locali

Usa `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

È possibile passare ripetutamente `image`; la serie GPT Image supporta fino a 16 immagini di riferimento. `image` nelle richieste JSON può essere un singolo URL o un array di URL; i file locali vengono caricati tramite multipart.

### Modelli e modalità di fatturazione

| Modello                                | Scenari applicabili e modalità di fatturazione                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | Canale inverso predefinito, fatturazione fissa in base al numero di immagini riuscite                               |
| `gpt-image-2:reverse`             | Seleziona esplicitamente il canale inverso, fatturazione fissa in base al numero di immagini riuscite                             |
| `gpt-image-2:official`            | Canale API ufficiale, maggiore stabilità, fatturazione in base all'effettivo utilizzo di Token                   |
| `gpt-image-2.5-flare`             | Privilegia la velocità di generazione, fatturazione fissa in base al numero di immagini riuscite                               |
| `gpt-image-2.5-flare:reverse`     | Alias inverso esplicito, equivalente a `gpt-image-2.5-flare`, fatturazione fissa in base al numero di immagini riuscite    |
| `gpt-image-2.5-flare:official`    | Canale API ufficiale, maggiore stabilità e privilegia la velocità di generazione, fatturazione in base all'effettivo utilizzo di Token            |
| `gpt-image-2.5-sunburst`          | Privilegia l'alta fedeltà e il controllo preciso, fatturazione fissa in base al numero di immagini riuscite                           |
| `gpt-image-2.5-sunburst:reverse`  | Alias inverso esplicito, equivalente a `gpt-image-2.5-sunburst`, fatturazione fissa in base al numero di immagini riuscite |
| `gpt-image-2.5-sunburst:official` | Canale API ufficiale, maggiore stabilità e privilegia l'alta fedeltà e il controllo preciso, fatturazione in base all'effettivo utilizzo di Token        |

I modelli inversi (incluso l'alias `:reverse`) possono utilizzare GPT Image 2.5 Flare per completare la richiesta durante il ripristino automatico; il modello richiesto e la modalità di fatturazione in base al numero di immagini riuscite rimangono invariati.

Il prezzo mostrato sulla pagina per il canale API ufficiale è una stima precedente alla richiesta; il risultato finale fa riferimento all'effettivo utilizzo di Token nella risposta e ai record di utilizzo.

`quality` supporta `auto`, `low`, `medium`, `high`; solo `gpt-image-2.5-flare` e `gpt-image-2.5-sunburst` (incluse le varianti `:reverse` e `:official`) supportano inoltre `xhigh`, `max`. Sia la modifica JSON tramite URL dell'immagine sia la modifica di file multipart possono passare questo campo; il canale ufficiale fattura in base all'effettivo utilizzo di Token.

## 4. Utilizzare una maschera per la modifica locale

L'interfaccia ufficiale Images Edit specifica le aree consentite per la modifica tramite `mask`. I modelli `:official` di Ace Data Cloud seguono lo stesso contratto multipart:

- `mask` deve essere un PNG con canale Alpha, di dimensioni non superiori a 4MB;
- le dimensioni della maschera devono corrispondere esattamente alla prima `image`;
- i pixel trasparenti con Alpha pari a `0` indicano che è consentita la modifica, mentre i pixel non trasparenti indicano che devono essere mantenuti;
- le immagini RGB che sono solo in bianco e nero, ma non hanno un canale trasparente, non possono essere usate come maschere valide;
- il prompt dovrebbe descrivere l'intera immagine desiderata, specificando al contempo chiaramente le modifiche locali e il contenuto che deve rimanere invariato.

Di seguito viene prima generata una maschera dall'immagine originale. L'esempio imposta il rettangolo centrale come trasparente, consentendo al modello di modificare solo tale area:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Quindi carica insieme l'immagine originale e la maschera:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

È anche possibile continuare a utilizzare il metodo di chiamata `images.edit` dell'SDK Python ufficiale di OpenAI, basta puntare `base_url` ad Ace Data Cloud:
```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Quando si utilizza `mask`, l'immagine originale e la maschera devono essere caricate separatamente nella stessa richiesta multipart tramite `image=@input.png` e `mask=@mask.png`. Non combinare un'immagine originale tramite URL con un file di maschera locale; le richieste di modifica solo tramite URL non supportano l'aggiunta di file `mask` locali. La maschera limiterà l'area di modifica, ma il modello di generazione potrebbe comunque fondere naturalmente i bordi; quando sono necessari confini rigorosi, è necessario utilizzare bordi Alpha nitidi e ripetere nel prompt quali contenuti devono rimanere invariati.

Il metodo di chiamata sopra è coerente con gli esempi di maschere della [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) e del [Cookbook ufficiale GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Parametri comuni

| Campo                | Descrizione                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (più veloce) o `gpt-image-2.5-sunburst` (maggiore fedeltà e controllo); tutti e tre possono selezionare la variante `:official` corrispondente, mentre `gpt-image-2` supporta anche `:reverse` |
| `image`           | JSON utilizza un singolo URL o un array di massimo 16 URL; multipart utilizza uno o più campi file `image`. Quando si utilizza `mask`, è necessario caricare file immagine locali                                              |
| `mask`            | Maschera PNG facoltativa, limitata al caricamento di file multipart; deve avere un canale Alpha, le stesse dimensioni della prima `image` e non superare 4 MB                                                                 |
| `prompt`          | Istruzione di modifica                                                                                                                             |
| `size`            | `auto` o un `WIDTHxHEIGHT` conforme ai limiti                                                                                                     |
| `n`               | 1–10; quando `response_format=b64_json`, è supportato solo 1                                                                                           |
| `response_format` | `url` o `b64_json`                                                                                                               |
| `callback_url`    | Indirizzo di callback asincrono facoltativo                                                                                                                         |

Le regole sulle dimensioni sono coerenti con l'interfaccia di generazione: larghezza e altezza devono essere multipli di 16, il lato lungo non deve superare 3840, il totale dei pixel deve essere compreso tra 655.360 e 8.294.400 e il rapporto larghezza-altezza non deve superare 3:1. Quando `size` viene omesso o si utilizza `auto`, il modello selezionerà il formato in base al prompt e alla prima immagine di riferimento.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` e i relativi alias `:reverse` vengono fatturati in base al numero di immagini generate con successo; `gpt-image-2:official`, `gpt-image-2.5-flare:official` e `gpt-image-2.5-sunburst:official` vengono regolati in base ai Token effettivi dell'input testuale, dell'input delle immagini di riferimento e dell'output delle immagini; fa fede il record di utilizzo finale.

## 6. Callback asincrono e risoluzione dei problemi

Per le attività lunghe, è possibile aggiungere nella richiesta:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

La risposta asincrona 200 è `{"task_id": "..."}`; al completamento verrà effettuato il callback con il risultato finale. Le richieste sincrone restituiscono invece `created` e `data`.

| Stato  | Verifica                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Formato/numero delle immagini, combinazioni di parametri e formato delle dimensioni; quando si utilizza `mask`, verificare il canale Alpha PNG, il limite di 4 MB e che le sue dimensioni corrispondano alla prima immagine originale |
| 401 | API Key e Bearer Header                                           |
| 429 | Frequenza delle richieste                                                              |
| 504 | Passare al callback asincrono                                                            |

Le risposte di errore includono `trace_id`. Quando si segnala un problema, fornire questo ID, non la API Key.

Per i campi completi e le enumerazioni in tempo reale, fare riferimento alla pagina [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Per la generazione di immagini da solo testo, consultare [Generazione immagini GPT Image 2 / 2.5](https://platform.acedata.cloud/documents/openai-images-generations).
