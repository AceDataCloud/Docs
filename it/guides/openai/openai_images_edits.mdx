## 2. Modifica utilizzando l'URL dell'immagine

Immagine originale:

![Immagine originale per la modifica GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",

```

## 3. Caricare immagini locali

Utilizza `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

Puoi passare ripetutamente `image`; la serie GPT Image supporta fino a 16 immagini di riferimento. `image` nelle richieste JSON può essere un singolo URL o un array di URL; i file locali vengono caricati tramite multipart.

| `gpt-image-2.6-flare`             | Incentrato sulla velocità di generazione, fatturazione fissa in base al numero di immagini riuscite                               |

| `gpt-image-2.5-sunburst`          | Incentrato su alta fedeltà e controllo preciso, fatturazione fissa in base al numero di immagini riuscite                           |

| `gpt-image-2.5-sunburst:reverse`  | Alias inverso esplicito, equivalente a `gpt-image-2.5-sunburst`, fatturazione fissa in base al numero di immagini riuscite |

| `gpt-image-2.5-sunburst:official` | Canale API ufficiale, maggiore stabilità e incentrato su alta fedeltà e controllo preciso, fatturazione in base all'effettivo utilizzo di Token        |
| `gpt-image-2.6-sunburst:official` | Canale API ufficiale, maggiore stabilità e incentrato su alta fedeltà e controllo preciso, fatturazione in base all'effettivo utilizzo di Token        |

I modelli inversi 2.0 / 2.5 (inclusi gli alias `:reverse`) possono utilizzare GPT Image 2.5 Flare per completare la richiesta durante il ripristino automatico; il modello richiesto e la modalità di fatturazione in base al numero di immagini riuscite rimangono invariati.

Il prezzo mostrato sulla pagina per il canale API ufficiale è una stima precedente alla richiesta; il risultato finale fa riferimento all'effettivo utilizzo di Token nella risposta e ai registri di utilizzo.

`quality` supporta `auto`, `low`, `medium`, `high`; Flare e Sunburst 2.5 / 2.6 (incluse le varianti `:reverse` e `:official`) supportano inoltre `xhigh`, `max`. Questo campo può essere passato sia nella modifica JSON tramite URL dell'immagine sia nella modifica di file multipart; il canale ufficiale fattura in base all'effettivo utilizzo di Token.

## 4. Utilizzare maschere per la modifica locale

L'interfaccia ufficiale Images Edit specifica tramite `mask` l'area in cui sono consentite le modifiche. I modelli `:official` di Ace Data Cloud seguono lo stesso contratto multipart:

- `mask` deve essere un PNG con canale Alpha, con dimensione non superiore a 4MB;
- le dimensioni della maschera devono essere esattamente uguali a quelle della prima `image`;
- i pixel trasparenti con Alpha pari a `0` indicano che è consentita la modifica, mentre i pixel non trasparenti indicano che devono essere mantenuti;
- le immagini RGB che sono solo in bianco e nero ma non dispongono di un canale trasparente non possono essere utilizzate come maschere valide;
- il prompt deve descrivere l'intera immagine desiderata, chiarendo al contempo le modifiche locali e i contenuti che devono rimanere invariati.

Di seguito viene prima generata una maschera dall'immagine originale. L'esempio imposta il rettangolo centrale come trasparente, consentendo al modello di modificare solo tale area:
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Quindi carica insieme l'immagine originale e la maschera:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Puoi anche continuare a utilizzare il metodo di chiamata `images.edit` dell'SDK Python ufficiale di OpenAI; basta puntare `base_url` ad Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Quando si utilizza `mask`, l'immagine originale e la maschera devono essere caricate separatamente nello stesso richiesta multipart tramite `image=@input.png` e `mask=@mask.png`. Non combinare un'immagine originale URL con un file maschera locale; le richieste di modifica solo URL non supportano l'aggiunta di file `mask` locali. La maschera limiterà l'area di modifica, ma il modello di generazione potrebbe comunque fondere naturalmente i bordi; quando sono necessari confini rigorosi, si devono usare bordi Alpha nitidi e ripetere nel prompt quali contenuti devono rimanere invariati.

Il metodo di chiamata sopra è coerente con gli esempi di maschera della [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) e del [Cookbook ufficiale GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Parametri comuni

| Campo                | Descrizione                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (più veloce) o `gpt-image-2.5-sunburst` (maggiore fedeltà e controllo); tutti e tre possono selezionare la variante `:official` corrispondente, mentre `gpt-image-2` supporta anche `:reverse` |
| `image`           | JSON utilizza un singolo URL o un array di massimo 16 URL; multipart utilizza uno o più campi file `image`. Quando si utilizza `mask`, è necessario caricare file immagine locali                                              |
| `mask`            | Maschera PNG opzionale, limitata al caricamento di file multipart; deve avere un canale Alpha, le stesse dimensioni della prima `image` e non superare 4MB                                                                 |
| `prompt`          | Istruzione di modifica                                                                                                                             |
| `size`            | `auto` o `WIDTHxHEIGHT` conforme ai limiti                                                                                                     |
| `n`               | 1–10; quando `response_format=b64_json`, è supportato solo 1                                                                                           |
| `response_format` | `url` o `b64_json`                                                                                                               |
| `callback_url`    | Indirizzo di callback asincrono opzionale                                                                                                                         |

Le regole sulle dimensioni sono coerenti con l'interfaccia di generazione: larghezza e altezza devono essere multipli di 16, il lato lungo non deve superare 3840, i pixel totali devono essere 655.360–8.294.400 e il rapporto larghezza-altezza non deve superare 3:1. Quando `size` viene omesso o viene utilizzato `auto`, il modello selezionerà il formato in base al prompt e alla prima immagine di riferimento.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` e i relativi alias `:reverse` vengono fatturati in base al numero di immagini riuscite; `gpt-image-2:official`, `gpt-image-2.5-flare:official` e `gpt-image-2.5-sunburst:official` vengono fatturati in base ai Token effettivi dell'input testuale, dell'input dell'immagine di riferimento e dell'output dell'immagine; fa fede il registro di utilizzo finale.

## 6. Callback asincrono e risoluzione dei problemi

Per le attività lunghe, puoi aggiungere nella richiesta:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

La risposta asincrona 200 è `{"task_id": "..."}`; al completamento verrà effettuato il callback con il risultato finale. Le richieste sincrone restituiscono invece `created` e `data`.

| Stato  | Verifica                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Formato/numero di immagini, combinazioni di parametri e formato delle dimensioni; quando si utilizza `mask`, verificare il canale Alpha PNG, il limite di 4MB e se le sue dimensioni corrispondono alla prima immagine originale |
| 401 | API Key e Bearer Header                                           |
| 429 | Frequenza delle richieste                                                              |
| 504 | Passare al callback asincrono                                                            |

Le risposte di errore includeranno `trace_id`. Quando segnali un problema, fornisci questo ID, non l'API Key.

Per i campi completi e le enumerazioni in tempo reale, fare riferimento alla pagina [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Per la generazione di immagini da solo testo, consultare [Generazione immagini GPT Image 2 / 2.5 / 2.6](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 continua a utilizzare le interfacce di generazione, modifica, attività asincrone e fatturazione della 2.5:

| Modello                                                          | Fatturazione                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0.22 Credits/immagine                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0.22 Credits/immagine                   |
| `gpt-image-2.6-flare:official`                              | Uguale a 2.5 official, fatturato in base all'utilizzo effettivo di Token |
| `gpt-image-2.6-sunburst:official`                           | Uguale a 2.5 official, fatturato in base all'utilizzo effettivo di Token |

Le qualità disponibili sono `auto`, `low`, `medium`, `high`, `xhigh`, `max`; per le dimensioni, utilizzare `auto` o `WIDTHxHEIGHT` conforme ai vincoli sopra indicati. Questa interfaccia supporta `png`, `jpeg`, `webp`; GPT Image 2.6 supporta inoltre immagini animate `gif` native, mentre SVG non è temporaneamente supportato. La modifica supporta URL di immagini JSON e caricamenti di file multipart. `:reverse` è un alias esplicito della versione normale con lo stesso nome. Utilizza il nome completo del modello, non passare `gpt-image-2.6`.

### Conversione di immagini in GIF animate con GPT Image 2.6
GPT Image 2.6 Flare, Sunburst nelle versioni standard, `:reverse`, `:official` possono tutti usare `output_format: "gif"`. I fotogrammi dell'animazione, le informazioni sul ciclo e la durata di riproduzione vengono mantenuti; `frame_count` indica il numero di fotogrammi, `frame_duration_ms` indica i millisecondi per fotogramma, il numero di fotogrammi deve essere un intero compreso tra 2 e 16, la durata di ogni fotogramma deve essere un intero compreso tra 20 e 655350 millisecondi, ed è utilizzato solo per GIF; la codifica viene arrotondata ai 10 ms più vicini. Se non specificato, il valore predefinito è 9 fotogrammi, 200 millisecondi per fotogramma; quando `size` del GIF è omesso o è auto, viene utilizzato il preset 512x512.

Si consiglia di utilizzare prima `size: "512x512"`, `frame_count: 9`, `frame_duration_ms: 200`. I GIF hanno limiti indipendenti di dimensioni e numero di fotogrammi e non possono applicare direttamente le specifiche statiche 4K; alcuni modelli regolano le dimensioni effettive dell'output. `n` indica il numero di file GIF restituiti, non il numero di fotogrammi dell'animazione. La versione standard e `:reverse` continuano a essere fatturate in base al numero di file riusciti, la versione ufficiale è fatturata in base all'effettivo utilizzo di Token.

```json
{
  "model": "gpt-image-2.6-flare",
  "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
  "prompt": "Animate the mug gently moving left and right. Keep its appearance and the background, no text.",
  "output_format": "gif",
  "size": "512x512",
  "quality": "medium",
  "frame_count": 9,
  "frame_duration_ms": 200,
  "n": 1,
  "async": true
}
```

### Immagini statiche GPT Image 2.6 4K

Flare, Sunburst e le loro varianti `:reverse`, `:official` possono tutte utilizzare i suddetti preset di pixel 4K, ad esempio `3840x2160` e `2160x3840`. Sia la generazione sia la modifica passano pixel specifici tramite `size`; `4K` non è un valore `size` valido e anche `4096x4096` supera l'attuale limite di pixel. Le suddette specifiche 4K si applicano a PNG/JPEG/WebP statici, per i GIF utilizzare i relativi parametri dedicati.

### Complessità di composizione GPT Image 2.6

`complexity` può essere `low`, `medium`, `high`; se omesso, viene utilizzato il valore predefinito del modello `high`. Controlla la complessità di pianificazione ed è indipendente dalla qualità di rendering `quality`; non comporta costi aggiuntivi per richiesta, la versione ufficiale continua a essere regolata in base ai Token effettivi. Gli altri modelli non supportano questo parametro.

I GIF non supportano mask, immagini di markup, compressione personalizzata, riscrittura del prompt o output in streaming parziale dell'immagine; le combinazioni incompatibili vengono rifiutate prima della generazione. Dimensioni, numero di fotogrammi e quantità sono soggetti congiuntamente al limite di budget pixel del modello; per Flare standard, `1024x1024`, 2 fotogrammi è stato verificato come utilizzabile, ma questa conclusione non può essere estesa a tutte le combinazioni 1K o ai GIF 4K.

### Modifica guidata da markup

La modifica statica di GPT Image 2.6 supporta `markup`. Caricare un PNG trasparente delle stesse dimensioni della prima immagine di riferimento, cerchiare su un livello separato la posizione da modificare e specificare nel `prompt` i requisiti della modifica. Il livello di markup deve contenere pixel trasparenti; ciascuna delle due immagini non può superare 16777216 pixel e l'immagine di markup non può superare 40MB. JSON può passare un URL HTTPS, un data URL base64 PNG o `{ "image_url": "https://..." }`; multipart carica il file tramite `markup`. La piattaforma trasmetterà il livello di markup sotto forma di file. `markup` non può essere utilizzato insieme a `mask`, GIF o `prompt_rewriter`, e non supporta `file_id`.

`input_fidelity` non è applicabile a GPT Image 2.6, ometterlo.
