OpenAI ha recentemente fornito un'interfaccia per creare risposte del modello. Fornisce input di testo o immagini per generare output di testo o immagini. Consente al modello di chiamare il proprio codice personalizzato o di utilizzare strumenti integrati, come la ricerca web o la ricerca file, per utilizzare i propri dati come input per le risposte del modello.

Questo documento presenta principalmente il processo di utilizzo dell'API OpenAI Responses; tramite essa possiamo utilizzare facilmente la funzionalità ufficiale di OpenAI per creare risposte del modello.

## Procedura di richiesta

Per utilizzare l'API OpenAI Responses, per prima cosa vai alla [console di Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da conservare come riserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato l'accesso o la registrazione, verrai automaticamente reindirizzato alla pagina di accesso per invitarti a registrarti e ad accedere; una volta completato, tornerai automaticamente alla pagina corrente.

**Un solo API Token può chiamare tutti i servizi della piattaforma, senza doverne richiedere uno separatamente per ciascun servizio.** La prima richiesta include credito gratuito in omaggio, utilizzabile per una prova gratuita; quando il credito è insufficiente, puoi ricaricare il saldo universale nella [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Utilizzo di base

Successivamente puoi compilare i contenuti corrispondenti nell'interfaccia, come mostrato nell'immagine:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Quando utilizzi questa interfaccia per la prima volta, dobbiamo compilare almeno tre elementi: uno è `authorization`, che può essere selezionato direttamente nell'elenco a discesa. Un altro parametro è `model`; `model` è la categoria di modello del sito ufficiale OpenAI ChatGPT che scegliamo di utilizzare. Qui disponiamo principalmente di 20 tipi di modelli; per i dettagli puoi consultare i modelli che forniamo. L'ultimo parametro è `input`; `input` è l'array di prompt che inseriamo. È un array, il che indica che è possibile caricare più prompt contemporaneamente; ogni prompt contiene `role` e `content`, dove `role` indica il ruolo del richiedente. Forniamo tre identità, ovvero `user`, `assistant` e `system`. L'altro elemento, `content`, è il contenuto specifico della nostra domanda.

Allo stesso tempo, puoi notare che sulla destra viene generato il codice di chiamata corrispondente; puoi copiare il codice ed eseguirlo direttamente, oppure fare clic direttamente sul pulsante «Try» per effettuare un test.

Parametri opzionali comuni:

- `max_tokens`: limita il numero massimo di token per una singola risposta.
- `temperature`: casualità della generazione, compresa tra 0 e 2; maggiore è il valore, più dispersivo sarà il risultato.
- `n`: quante risposte candidate generare alla volta.
- `response_format`: impostazione del formato di ritorno.
- `tools`: definizione di chiamate a funzioni/strumenti.
- `background`: se eseguire in modo asincrono in background.

## Risposta in streaming

Questa interfaccia supporta anche le risposte in streaming, il che è molto utile per l'integrazione web, poiché può consentire alla pagina web di ottenere un effetto di visualizzazione carattere per carattere.

Se desideri restituire risposte in streaming, puoi modificare il parametro `stream ` nell'intestazione della richiesta impostandolo su `true`.

La modifica è mostrata nell'immagine; tuttavia, il codice di chiamata deve essere modificato di conseguenza per supportare le risposte in streaming.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Dopo aver modificato `stream` in `true`, l'API restituirà riga per riga i dati JSON corrispondenti; a livello di codice dobbiamo apportare le modifiche appropriate per ottenere i risultati riga per riga.

Codice di chiamata di esempio Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

La risposta in streaming termina con `response.completed` o `response.incomplete`; il `usage` nello stato finale è l'utilizzo finale di token per questa richiesta ed è anche la base per la fatturazione.

Se il client si disconnette prima che arrivi lo stato finale, questa richiesta viene registrata come chiusa dal client (499) e non verrà fatturata utilizzando una stima locale dei token; se la connessione termina normalmente ma non viene ricevuto lo stato finale e l'`usage` finale, questa richiesta viene registrata come risposta incompleta (502) e allo stesso modo non verrà fatturata utilizzando una stima dei token. Quando si verificano queste due situazioni, inviate nuovamente la richiesta.

Il risultato `data` restituito contiene più campi, introdotti come segue:

- `item_id`, l'ID generato per questa attività di conversazione, utilizzato per identificare in modo univoco questa attività di conversazione.
- `type`, il tipo generato per questa attività Responses di conversazione.
- `model `, il modello del sito ufficiale OpenAI ChatGPT selezionato.
- `delta`, le informazioni di risposta fornite da ChatGPT alla richiesta.

Anche JavaScript è supportato, ad esempio il codice di chiamata in streaming di Node.js è il seguente:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Modello visivo

gpt-4o è un modello linguistico di grandi dimensioni multimodale sviluppato da OpenAI; sulla base di GPT-4, ha aggiunto capacità di comprensione visiva. Questo modello può elaborare contemporaneamente input di testo e immagini, realizzando comprensione e generazione multimodali.
L'elaborazione del testo utilizzando il modello gpt-4o è coerente con il contenuto di utilizzo di base descritto sopra; di seguito verrà brevemente illustrato come utilizzare la capacità di elaborazione delle immagini del modello.

La capacità di elaborazione delle immagini del modello gpt-4o viene utilizzata principalmente aggiungendo un campo `type` al contenuto originale di `content`; tramite questo campo è possibile sapere se ciò che viene caricato è testo o immagine, utilizzando così la capacità di elaborazione delle immagini del modello gpt-4o. Di seguito viene illustrato principalmente come richiamare questa funzionalità in due modi: Curl e Python.

- Metodo tramite script Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice e il messaggio di errore corrispondenti. Ad esempio:

- `400 token_mismatched`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`: Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`: Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`: Errore interno del server, qualcosa è andato storto sul server.
