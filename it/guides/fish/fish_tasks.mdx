La funzionalità principale di Fish Tasks API è interrogare lo stato di esecuzione dell'attività inserendo l'ID dell'attività generato da Fish Audios Generation API.

Questo documento presenterà in dettaglio le istruzioni di integrazione di Fish Tasks API, aiutandovi a integrare facilmente e a sfruttare appieno le potenti funzionalità di questa API. Tramite Fish Tasks API, potete facilmente interrogare lo stato di esecuzione delle attività di Fish Audios Generation API.

## Processo di richiesta

Per utilizzare Fish Audios Generation API, ottenete innanzitutto il vostro API Token dalla [console di Ace Data Cloud](https://platform.acedata.cloud/console/applications) e conservatelo per l'uso.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non avete ancora effettuato l'accesso o la registrazione, verrete automaticamente reindirizzati alla pagina di accesso che vi inviterà a registrarvi e ad accedere; al termine tornerete automaticamente alla pagina corrente.

**Un solo API Token può chiamare tutti i servizi della piattaforma, senza doverne richiedere uno separatamente per ogni servizio.** Alla prima richiesta verrà assegnato credito gratuito, utilizzabile per una prova gratuita; quando il credito è insufficiente, potete ricaricare il saldo universale nella [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Fish Audios Generation API →](https://platform.acedata.cloud/documents/fish-tts)

## Esempio di richiesta

Fish Tasks API può essere utilizzata per interrogare i risultati di Fish Audios Generation API. Per sapere come utilizzare Fish Audios Generation API, consultate la documentazione [Fish Videos Generation API ](https://platform.acedata.cloud/documents/fish-tts-integration).

Prendiamo come esempio un ID attività restituito dal servizio Fish Audios Generation API per mostrare come utilizzare questa API. Supponiamo di avere un ID attività: 2725a2d3-f87e-4905-9c53-9988d5a7b2f5, di seguito mostreremo come passare un ID attività.

### Impostare le intestazioni e il corpo della richiesta

**Request Headers** includono:

- `accept`: specifica la ricezione del risultato della risposta in formato JSON; qui compilare con `application/json`.
- `authorization`: la chiave per chiamare l'API, che può essere selezionata direttamente dal menu a discesa dopo la richiesta.

**Request Body** include:

- `id`: l'ID dell'attività caricata.
- `action`: il metodo di operazione sull'attività.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/fish/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2725a2d3-f87e-4905-9c53-9988d5a7b2f5",
  "action": "retrieve"
}'
```


Il risultato restituito contiene diversi campi; il campo request è il request body al momento dell'avvio dell'attività, mentre il campo response è il response body restituito dopo il completamento dell'attività. La descrizione dei campi è la seguente.

- `id`, l'ID generato per questa attività, utilizzato per identificare univocamente questa attività di generazione.
- `request`, le informazioni della richiesta nell'interrogazione dell'attività.
- `response`, le informazioni di ritorno nell'interrogazione dell'attività; al successo finale, il relativo `cost.amount` rappresenta i Credits effettivamente detratti per questa sintesi.
- `created_at`, l'ora di creazione dell'attività, timestamp Unix (secondi, in virgola mobile).
- `started_at`, l'ora di inizio dell'esecuzione dell'attività, timestamp Unix (secondi, in virgola mobile).
- `finished_at`, l'ora di completamento dell'attività, timestamp Unix (secondi, in virgola mobile). Questo campo non viene restituito quando l'attività non è completata.
- `elapsed`, il tempo richiesto per l'esecuzione dell'attività, in secondi (in virgola mobile, con 3 cifre decimali). Questo campo non viene restituito quando l'attività non è completata.

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice di errore e le informazioni corrispondenti. Ad esempio:

- `400 token_mismatched`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`: Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`: Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`: Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
