Questo API si basa su [Fish Audio Official Model API](https://docs.fish.audio/resources/api-reference/model) ed è utilizzato per **creare un nuovo clone di timbro audio basato su un campione audio**. L'indirizzo è `POST https://api.acedata.cloud/fish/model`.

> Per la ricerca paginata dei timbri esistenti, si prega di fare riferimento a [Fish Model Query API](https://platform.acedata.cloud/documents/fish-model-query); per cercare i dettagli di un singolo timbro per `_id`, si prega di fare riferimento a [Fish Model Get API](https://platform.acedata.cloud/documents/fish-model-get).

## Processo di richiesta

Per utilizzare il Fish Model API, prima vai al [Ace Data Cloud Console](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da conservare per uso futuro.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato il login o la registrazione, verrai automaticamente reindirizzato alla pagina di login che ti invita a registrarti e accedere; una volta completato, verrai riportato automaticamente alla pagina corrente.

**Un API Token è sufficiente per accedere a tutti i servizi della piattaforma, non è necessario richiederne uno per ogni servizio.** La prima richiesta ti darà un credito gratuito, per provare senza costi; se il credito è insufficiente, puoi ricaricare il saldo generale nella [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Fish Model API →](https://platform.acedata.cloud/services/fish)

## Campi del corpo della richiesta

| Campo                    | Tipo       | Obbligatorio | Descrizione                                                                        |
| ----------------------- | -------- | ------------ | --------------------------------------------------------------------------------- |
| `title`                 | string   | Sì           | Nome del timbro, utilizzato per l'identificazione nell'elenco della console.     |
| `voices`                | string   | Sì           | URL HTTP(S) del campione audio (**singolo stringa**, non un array). Questo API non supporta l'upload multipart/binario, si prega di caricare l'audio in un qualsiasi storage pubblico accessibile. |
| `description`           | string   | No           | Descrizione del timbro.                                                           |
| `cover_image`           | string   | No           | URL HTTP(S) dell'immagine di copertura.                                          |
| `tags`                  | string[] | No           | Tag di ricerca per la libreria pubblica, ad esempio `["male","narration","zh"]`. |
| `texts`                 | string[] | No           | Testo di riferimento corrispondente al campione (per correggere la pronuncia).  |
| `enhance_audio_quality` | boolean  | No           | Se migliorare la qualità audio del campione prima dell'addestramento.           |
| `generate_sample`       | boolean  | No           | Se generare automaticamente un campione audio dopo il completamento dell'addestramento. |

> I campi sono identici a quelli upstream, si prega di fare riferimento anche alla [documentazione ufficiale di Fish](https://docs.fish.audio/resources/api-reference/model).

## Esempio: Creare un timbro clone privato

```shell
curl -X POST 'https://api.acedata.cloud/fish/model' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "title": "Il mio timbro clone",
    "description": "Timbro cinese clonato da una registrazione di podcast",
    "voices": "https://example.com/sample-voice.mp3",
    "cover_image": "https://cdn.acedata.cloud/e724d7f13d.png"
  }'
```

> Nota: `voices` deve essere una **stringa** (singolo URL audio), non un array. Se inviato come `["..."]`, l'upstream rifiuterà.

La risposta di successo restituisce direttamente l'oggetto ModelEntity della piattaforma Fish (l'esempio seguente è il timbro minimo utilizzabile che abbiamo testato, con alcuni campi lunghi rimossi per facilitare la lettura):

`_id` può essere utilizzato come valore del campo `reference_id` nell'API [Fish TTS](https://platform.acedata.cloud/documents/fish-tts) per utilizzare questo timbro clone per la sintesi vocale:

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "Ciao, questa è una voce sintetizzata utilizzando il timbro clone che ho appena creato.",
    "reference_id": "e5c6db52c3ed417f9cb2e5a33fb04667",
    "format": "mp3"
  }'
```

## Requisiti per i campioni

Valori di esperienza (coerenti con l'upstream, si prega di fare riferimento alla [documentazione ufficiale di Fish](https://docs.fish.audio/resources/api-reference/model)):

- La durata consigliata è superiore a 30 secondi e inferiore a 5 minuti; oltre 10 minuti il guadagno marginale è limitato.
- Frequenza di campionamento di 16 kHz o superiore, mono o stereo va bene.
- Contenuto il più pulito possibile: senza musica di sottofondo, eco, rumori ambientali evidenti; stesso parlante.
- Formato consigliato `mp3` / `wav`.

Se non sei sicuro della qualità del campione, puoi inviare anche `enhance_audio_quality: true` per far migliorare prima la qualità audio dall'upstream.

## Informazioni sui costi

La creazione di un modello di timbro clone (`POST /fish/model`) è gratuita, non ci sono costi; anche le interfacce di query del timbro ([Fish Model Query](https://platform.acedata.cloud/documents/fish-model-query), [Fish Model Get](https://platform.acedata.cloud/documents/fish-model-get)) non comportano costi. I costi si generano solo durante le chiamate successive per la sintesi vocale con [Fish TTS](https://platform.acedata.cloud/documents/fish-tts) in base all'uso.

## Gestione degli errori

- `400 token_mismatched`: parametri di richiesta mancanti o non validi (il più comune è che `voices` non sia un URL, o sia stato inviato come array).
- `401 invalid_token`: il token di autenticazione non esiste o è non valido.
- `429 too_many_requests`: attivazione del limite di velocità dell'account.
- `500 api_error`: errore interno del server.

Esempio di risposta di errore:
```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "voices è richiesto e deve essere un URL HTTP(S) che punta a un file audio"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## Conclusione

Per chiamare questa interfaccia è sufficiente preparare un URL audio campione accessibile pubblicamente, metterlo nel campo `voices` per ottenere `_id`, e poi fornire `reference_id` a `/fish/tts` per completare il processo end-to-end di "clonazione → sintesi". Un punto comune di errore è che `voices` deve essere una stringa, non può essere un array.
