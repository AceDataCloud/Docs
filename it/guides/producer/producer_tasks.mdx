La principale funzionalità dell'API Producer Tasks è quella di interrogare lo stato di esecuzione di un'attività utilizzando l'ID del compito generato dall'API Producer Audios Generation.

Questo documento fornirà una guida dettagliata per l'integrazione dell'API Producer Tasks, aiutandoti a integrare facilmente e sfruttare appieno le potenti funzionalità di questa API. Con l'API Producer Tasks, puoi facilmente interrogare lo stato di esecuzione delle attività dell'API Producer Audios Generation.

## Processo di richiesta

Per utilizzare l'API Producer Audios Generation, prima di tutto vai al [Pannello di controllo di Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da conservare per uso futuro.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Se non hai ancora effettuato il login o la registrazione, verrai automaticamente reindirizzato alla pagina di login che ti inviterà a registrarti e accedere; una volta completato, verrai riportato automaticamente alla pagina corrente.

**Un API Token è sufficiente per accedere a tutti i servizi della piattaforma, senza necessità di richiederne uno per ogni servizio.** La prima richiesta ti darà un credito gratuito, per un'esperienza senza costi; quando il credito è insufficiente, puoi ricaricare il saldo generale nel [pannello di controllo](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Esempio di richiesta

L'API Producer Tasks può essere utilizzata per interrogare i risultati dell'API Producer Audios Generation. Per informazioni su come utilizzare l'API Producer Audios Generation, consulta la documentazione [Producer Audios Generation API](https://platform.acedata.cloud/documents/producer-audios-integration).

Prendiamo come esempio un ID di attività restituito dal servizio Producer Audios Generation, per dimostrare come utilizzare questa API. Supponiamo di avere un ID di attività: 1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad, e ora dimostriamo come passare un ID di attività.

### Impostazione dell'intestazione della richiesta e del corpo della richiesta

**Request Headers** includono:

- `accept`: specifica di ricevere la risposta in formato JSON, qui inserito come `application/json`.
- `authorization`: la chiave per chiamare l'API, che può essere selezionata direttamente dopo la richiesta.

**Request Body** include:

- `id`: l'ID dell'attività caricata.
- `action`: il modo di operare sull'attività.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

Il risultato restituito contiene diversi campi, il campo request è il corpo della richiesta inviata per avviare l'attività, mentre il campo response è il corpo della risposta restituita al termine dell'attività. La descrizione dei campi è la seguente.
- `id`，ID del compito generato, utilizzato per identificare univocamente questo compito di generazione.
- `request`，informazioni sulla richiesta nel compito di query.
- `response`，informazioni di ritorno nel compito di query.
- `created_at`，data e ora di creazione del compito, timestamp Unix (secondi, float).
- `started_at`，data e ora di inizio esecuzione del compito, stringa di data e ora UTC ISO-8601.
- `finished_at`，data e ora di completamento del compito, timestamp Unix (secondi, float). Questo campo non viene restituito se il compito non è completato.
- `elapsed`，tempo di esecuzione del compito, unità in secondi (float, con 3 cifre decimali). Questo campo non viene restituito se il compito non è completato.

I risultati restituiti contengono più campi, dove gli elementi includono i dettagli specifici del compito batch, e le informazioni specifiche di ogni compito sono simili al formato del risultato della query di un singolo compito sopra. Le informazioni sui campi sono le seguenti.

- `items`, tutti i dettagli specifici del compito batch. È un array, ogni elemento dell'array ha lo stesso formato del risultato della query di un singolo compito sopra.
- `count`, il numero di compiti in questa query batch.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad","1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad"],
  "action": "retrieve_batch"
}'
```

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice di errore e le informazioni corrispondenti. Ad esempio:

- `400 token_mismatched`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`: Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`: Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`: Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```json

  "success": false,

    "message": "fetch failed"

  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
