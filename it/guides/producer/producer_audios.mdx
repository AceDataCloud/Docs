Questo articolo introdurrà le istruzioni per l'integrazione dell'API Producer Audios Generation, che consente di generare musica ufficiale di Producer inserendo parametri personalizzati.

## Procedura di richiesta

Per utilizzare l'API Producer Audios Generation, per prima cosa vai alla [console di Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token e conservarlo come riserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato l'accesso o la registrazione, verrai automaticamente reindirizzato alla pagina di accesso per invitarti a registrarti e ad accedere; una volta completato, tornerai automaticamente alla pagina corrente.

**Un solo API Token può richiamare tutti i servizi della piattaforma, senza necessità di richiederne uno separatamente per ciascun servizio.** Alla prima richiesta verrà assegnato un credito gratuito, che consente di provare il servizio gratuitamente; quando il credito è insufficiente, puoi ricaricare il saldo generale nella [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Utilizzo di base

Per qualsiasi canzone tu voglia, puoi inserire liberamente un testo, ad esempio se voglio generare una canzone sul Natale, posso inserire `a song for Christmas`, come mostrato nell'immagine:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Qui possiamo vedere che abbiamo impostato i Request Headers, tra cui:

- `accept`: il formato del risultato della risposta che si desidera ricevere; qui è compilato come `application/json`, ovvero il formato JSON.
- `authorization`: la chiave per richiamare l'API, che può essere selezionata direttamente dal menu a discesa dopo la richiesta.

Inoltre, i parametri del Request Body includono:

- `action`: l'azione di questa attività di generazione musicale; per generare una canzone è `generate`.
- `model`: il modello utilizzato per creare la canzone; attualmente comprende principalmente: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: il contenuto del testo della canzone.
- `custom`: se utilizzare un metodo personalizzato per generare la canzone.
- `prompt`: il prompt in modalità ispirazione.
- `title`: le informazioni sul titolo della canzone.
- `audio_id`: l'ID della canzone di riferimento, utilizzato per operazioni quali continuazione/versione cover.
- `continue_at`: continua la canzone a partire dal numero di secondi specificato.
- `replace_section_start`/`replace_section_end`: orario di inizio e fine del segmento da sostituire, in secondi.
- `lyrics_strength`: intensità del testo, indica il grado di influenza del testo nella generazione audio; opzionale tra 0 e 1, il valore predefinito è 0.7.
- `sound_strength`: intensità del prompt audio, opzionale tra 0.2 e 1, il valore predefinito è 0.7.
- `cover_strength`: intensità della cover, tra 0.2 e 1, il valore predefinito è 1.
- `weirdness`: grado di eccentricità dello stile, opzionale tra 0 e 1, il valore predefinito è 0.5
- `callback_url`: l'URL per il risultato della callback.
- `async`: opzionale; quando è impostato su `true`, l'interfaccia restituisce immediatamente `task_id`, senza necessità di fornire `callback_url`, quindi ottiene il risultato eseguendo il polling tramite la relativa interfaccia di query delle attività.
- `instrumental`: se è in modalità senza testo.

Inoltre, se desideri generare il codice di integrazione corrispondente, puoi copiarlo direttamente; ad esempio, il codice CURL è il seguente:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Cover di canzoni

Se si desidera eseguire un'operazione di cover su una canzone già generata, è possibile inserire la canzone generata sopra per eseguire la cover; successivamente, genereremo una canzone personalizzata in base al testo e al titolo.

Se si desidera continuare a eseguire la cover di una canzone caricata personalmente, è possibile impostare il parametro `action` su `upload_cover` e inserire l'ID della canzone caricata personalizzata per cui continuare la cover. L'ID della canzone si ottiene utilizzando la [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), come mostrato nell'immagine seguente:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

È quindi possibile specificare i seguenti contenuti:

- action：l'azione di questa attività musicale; attualmente supporta: generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation; questa cover utilizza il parametro `cover`.
- lyric：testo della canzone
- title：il titolo della canzone.
- custom：se generare utilizzando la modalità personalizzata; il valore predefinito è false.
- audio_id：l'ID della canzone di cui eseguire la cover.

## Continua la canzone

## Callback asincrono

Poiché il tempo di generazione di Producer Audios Generation API a volte può essere relativamente lungo, se l'API non risponde per molto tempo, la richiesta HTTP manterrà continuamente la connessione, causando un consumo aggiuntivo di risorse di sistema; pertanto, questa API fornisce anche supporto per callback asincroni.

Il flusso complessivo è: quando il client avvia una richiesta, specifica inoltre un campo `callback_url`; dopo che il client avvia la richiesta API, l'API restituirà immediatamente un risultato, contenente le informazioni di un campo `task_id`, che rappresenta l'ID dell'attività corrente. Una volta completata l'attività, il risultato dell'attività di generazione verrà inviato tramite POST JSON al `callback_url` specificato dal client, includendo anch'esso il campo `task_id`, in modo che il risultato dell'attività possa essere associato tramite ID.

Di seguito capiremo come operare nello specifico attraverso un esempio.

Innanzitutto, il callback Webhook è un servizio in grado di ricevere richieste HTTP; gli sviluppatori dovrebbero sostituirlo con l'URL del server HTTP che hanno configurato. Qui, per comodità di dimostrazione, viene utilizzato un sito web di esempio Webhook pubblico [https://webhook.site/](https://webhook.site/); aprendo questo sito web è possibile ottenere un Webhook URL, come mostrato nell'immagine:

![](https://cdn.acedata.cloud/tbcnai.png)

## Gestione degli errori

Durante la chiamata all'API, se si verifica un errore, l'API restituirà il codice e il messaggio di errore corrispondenti. Ad esempio:

- `400 token_mismatched`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`：Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`：Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`：Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
