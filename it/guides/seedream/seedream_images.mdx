Questo articolo presenterà un metodo di integrazione dell'API SeeDream Images Generation, che consente di generare immagini ufficiali di SeeDream inserendo parametri personalizzati.

## Procedura di richiesta

Per utilizzare l'API SeeDream Images Generation, innanzitutto ottieni il tuo API Token dalla [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) e conservalo come riserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato l'accesso o la registrazione, verrai automaticamente reindirizzato alla pagina di accesso per registrarti e accedere, e al termine tornerai automaticamente alla pagina corrente.

**Un solo API Token può chiamare tutti i servizi della piattaforma, senza necessità di richiederne uno separatamente per ogni servizio.** La prima richiesta include un credito gratuito, che consente di provarlo gratuitamente; quando il credito è insufficiente, puoi ricaricare il saldo universale dalla [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [SeeDream Images Generation API →](https://platform.acedata.cloud/documents/seedream-images)

## Utilizzo di base

Innanzitutto, diamo un'occhiata al metodo di utilizzo di base: inserendo il prompt `prompt`, l'azione di generazione `action` e la dimensione dell'immagine `size`, è possibile ottenere il risultato elaborato. Per prima cosa è necessario passare semplicemente un campo `action`, il cui valore è `generate`, quindi dobbiamo anche inserire il prompt; il contenuto specifico è il seguente:

<p><img src="https://cdn.acedata.cloud/seedream_request_body.png" width="500" className="m-auto" /></p>

Qui possiamo vedere che abbiamo impostato i Request Headers, tra cui:

- `accept`: il formato del risultato della risposta che si desidera ricevere; qui è impostato su `application/json`, ovvero il formato JSON.
- `authorization`: la chiave per chiamare l'API, che può essere selezionata direttamente dal menu a discesa dopo la richiesta.

Sono inoltre impostati i Request Body, tra cui:

- `prompt`: il prompt.
- `model`: il modello di generazione, predefinito `doubao-seedream-5-0-lite-260128` (SeeDream 5.0 Lite, il più recente). Supporta `doubao-seedream-5-0-pro-260628`, `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828`. Tra questi, `doubao-seedream-5-0-pro-260628` (SeeDream 5.0 Pro) è un modello di punta per immagini singole, genera solo immagini singole e **non supporta gruppi di immagini (`sequential_image_generation`), streaming (`stream`) e ricerca web (`tools`)**. **`model` deve ricevere la stringa completa del modello (ad esempio `doubao-seedream-5-0-lite-260128`); abbreviazioni come `doubao-seedream-5.0-lite` restituiranno 400.**
- `image`: le informazioni dell'immagine in input; supporta URL o codifica Base64. `doubao-seedream-5-0-pro-260628` supporta l'input di una singola immagine o di più immagini (massimo 10), mentre `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` supportano l'input di una singola immagine o di più immagini.
- `size`: specifica le informazioni sulle dimensioni dell'immagine generata; supporta i due metodi seguenti, che non possono essere combinati. Metodo 1 | Specificare la risoluzione dell'immagine generata e descrivere il rapporto larghezza-altezza dell'immagine in linguaggio naturale nel prompt. **Le preimpostazioni supportate variano a seconda del modello**: `doubao-seedream-5-0-pro-260628` supporta `1K`/`1.5K`/`2K`; `doubao-seedream-5-0-lite-260128` supporta `2K`/`3K`/`4K`; `doubao-seedream-4-5-251128` supporta solo `2K`/`4K`; `doubao-seedream-4-0-250828` supporta `1K`/`2K`/`4K`. Metodo 2 | Specificare i valori in pixel di larghezza e altezza dell'immagine generata: il valore predefinito è `2048x2048`; l'intervallo dei pixel totali e del rapporto larghezza-altezza varia in base al modello (ad esempio, per 5.0 Pro l'intervallo dei pixel totali è [921600, 4624220], per 5.0 Lite / 4.5 il limite inferiore dei pixel totali è 3,686,400, mentre per 4.0 il limite inferiore è 921,600).
- `sequential_image_generation`: gruppo di immagini: in base al contenuto inserito, genera un gruppo di immagini con contenuti correlati. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` supportano questo parametro, il cui valore predefinito è `disabled`.
- `stream`: controlla se abilitare la modalità di output in streaming. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` supportano questo parametro, il cui valore predefinito è `false`.
- `response_format`: specifica il formato di restituzione dell'immagine generata. Il valore predefinito è `url`, ed è supportato anche `b64_json`.
- `watermark`: indica se aggiungere una filigrana all'immagine generata. Il valore predefinito è `true`.
- `output_format`: specifica il formato del file dell'immagine generata; supporta `jpeg` (predefinito) e `png`. Supportato solo da `doubao-seedream-5-0-pro-260628` e `doubao-seedream-5-0-lite-260128`.
- `tools`: configura gli strumenti che il modello deve chiamare; attualmente supporta `web_search` (ricerca web). Supportato solo da Seedream 5.0 Lite.
- `optimize_prompt_options`: configurazione dell'ottimizzazione del prompt. 5.0 Pro supporta `standard`/`fast`; 5.0 Lite e 4.5 supportano solo `standard`; 4.0 supporta `standard`/`fast`.
- `background`: supportato solo dalla modifica di immagini singole di 5.0 Pro. `transparent` richiede l'input di una PNG con canale trasparente e `output_format` deve essere `png`; `opaque` indica uno sfondo normalmente opaco.
- `layer_decomposition`: supportato solo da 5.0 Pro. Quando impostato su `true`, è necessario inserire una PNG/JPEG; è possibile non passare `prompt` per la separazione automatica, oppure specificare gli elementi con linguaggio naturale/`<bbox>`; `size` supporta `auto`/`1K`/`1.5K`/`2K`. Questa modalità non può essere utilizzata insieme a gruppi di immagini, streaming, ricerca web o `background`.
- `callback_url`: l'URL che richiede il risultato di callback.
- `async`: indica se elaborare in modalità asincrona. Quando è impostato su `true`, l'interfaccia restituisce immediatamente `task_id`, senza necessità di fornire `callback_url`; successivamente il risultato viene ottenuto tramite polling su `/seedream/tasks`.

Il risultato restituito contiene diversi campi, descritti come segue:

- `success`, lo stato attuale dell'attività di generazione video.
- `task_id`, l'ID dell'attività di generazione video corrente.
- `trace_id`, l'ID di tracciamento della generazione video corrente.
- `data`, l'elenco dei risultati dell'attività di generazione immagini corrente.

  - `size`: i pixel dell'immagine generata

Possiamo vedere che abbiamo ottenuto informazioni soddisfacenti sull'immagine; ci basta recuperare l'immagine SeeDream generata in base all'indirizzo del link dell'immagine in `data` nel risultato.

Inoltre, se si desidera generare il codice di integrazione corrispondente, è possibile copiarlo direttamente; ad esempio, il codice CURL è il seguente:

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "doubao-seedream-5-0-lite-260128",
  "prompt": "A single matte blue cube centered on a clean white studio background, neutral lighting"
}'
```

## Attività di modifica immagini

Se si desidera modificare un'immagine, innanzitutto il parametro `image` deve includere il link dell'immagine da modificare.

- model: il modello utilizzato per questa attività di modifica immagini; `doubao-seedream-5-0-pro-260628`, `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` supportano tutti l'input di immagini.
- image: carica l'immagine o le immagini da modificare, una o più immagini

L'esempio di compilazione è il seguente:

<p><img src="https://cdn.acedata.cloud/seedream_edit.png" width="500" className="m-auto" /></p>

Il codice corrispondente:

```python
import requests

url = "https://api.acedata.cloud/seedream/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedream-4-0-250828",
  "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
  "image": ["https://ark-project.tos-cn-beijing.volces.com/doc_image/seedream4_5_imageToimage.png"],
  "size": "2K",
  "watermark": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Facendo clic su esegui, si può notare che si ottiene immediatamente un risultato, come segue:

## Suddivisione dei livelli (Seedream 5.0 Pro)

La suddivisione dei livelli divide un'immagine di input in 1 immagine di sfondo e fino a 16 livelli PNG trasparenti modificabili indipendentemente. La seguente richiesta consente al modello di identificare automaticamente gli elementi principali; se è necessario specificare gli elementi, è possibile aggiungere `prompt`, oppure utilizzare coordinate `<bbox>` normalizzate nella parola chiave.

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "https://example.com/poster.png",
  "layer_decomposition": true,
  "size": "2K",
  "watermark": false
}'
```

I `data` restituiti sono ordinati dal basso verso l'alto in base a `z_index`. Il `z_index` dell'immagine di sfondo è 0; i livelli includono inoltre `name`, `description` e `bounding_box.absolute`/`normalized`. Quando si ricompone usando coordinate assolute, ridimensionare il livello a `[right-left, bottom-top]`, posizionarlo in `[left, top]`, quindi sovrapporlo in ordine crescente di `z_index`. Se la generazione di un qualsiasi livello non riesce, l'intera suddivisione non riesce.

## Output in streaming

Quando Lite/4.x imposta `stream: true`, l'intestazione della richiesta utilizza `accept: application/x-ndjson`. L'interfaccia restituisce riga per riga `image_generation.partial_succeeded` o `image_generation.partial_failed`, e infine restituisce l'unico evento `image_generation.completed` e l'`usage` finale; solo l'evento di completamento attiva una singola fatturazione. La modalità streaming non può essere utilizzata insieme a `async` o `callback_url`.

## Callback asincrono

Poiché il tempo di generazione della SeeDream Images Generation API è relativamente lungo, richiedendo circa 1-2 minuti, se l'API non risponde per molto tempo, la richiesta HTTP manterrà continuamente la connessione, causando un consumo aggiuntivo di risorse di sistema; pertanto questa API fornisce anche il supporto per callback asincroni.

Il processo generale è: quando il client avvia una richiesta, specifica inoltre un campo `callback_url`; dopo che il client ha avviato la richiesta API, l'API restituisce immediatamente un risultato, che include le informazioni del campo `task_id`, che rappresenta l'ID dell'attività corrente. Dopo il completamento dell'attività, il risultato dell'immagine generata verrà inviato tramite POST JSON al `callback_url` specificato dal client, includendo anch'esso il campo `task_id`, in modo che il risultato dell'attività possa essere associato tramite ID.

Se non disponi di un indirizzo pubblico per il callback, puoi anche non specificare `callback_url`, ma impostare il campo `async` su `true` nella richiesta. In questo caso, l'interfaccia restituirà comunque immediatamente `task_id`, ma non invierà il risultato; dovrai utilizzare tale `task_id` per chiamare l'interfaccia `/seedream/tasks` e interrogare ciclicamente lo stato dell'attività per ottenere il risultato finale.

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice e le informazioni di errore corrispondenti. Ad esempio:

- `400 token_mismatched`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`：Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`：Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`：Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
