La principale funzionalità dell'API SeeDream Tasks è quella di interrogare lo stato di esecuzione di un'attività utilizzando l'ID dell'attività generato dall'API SeeDream Images Generation.

Questo documento fornirà una descrizione dettagliata dell'integrazione dell'API SeeDream Tasks, aiutandoti a integrare facilmente e sfruttare appieno le potenti funzionalità di questa API. Con l'API SeeDream Tasks, puoi facilmente interrogare lo stato di esecuzione delle attività dell'API SeeDream Images Generation.

## Processo di richiesta

Per utilizzare l'API SeeDream Images Generation, prima vai al [Pannello di controllo di Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da conservare per uso futuro.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato il login o la registrazione, verrai automaticamente reindirizzato alla pagina di login che ti invita a registrarti e accedere; una volta completato, verrai riportato automaticamente alla pagina corrente.

**Un API Token è sufficiente per accedere a tutti i servizi della piattaforma, senza necessità di richiederne uno per ogni servizio.** La prima richiesta ti darà un credito gratuito, per un'esperienza senza costi; quando il credito è insufficiente, puoi ricaricare il saldo generale nel [pannello di controllo](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [API SeeDream Images Generation →](https://platform.acedata.cloud/documents/seedream-images)

## Esempio di richiesta

L'API SeeDream Tasks può essere utilizzata per interrogare i risultati dell'API SeeDream Images Generation. Per informazioni su come utilizzare l'API SeeDream Images Generation, consulta la documentazione [API SeeDream Images Generation](https://platform.acedata.cloud/documents/seedream-images-integration).

### Impostazione dell'intestazione della richiesta e del corpo della richiesta

**Request Headers** includono:

- `accept`: specifica di ricevere la risposta in formato JSON, qui si compila con `application/json`.
- `authorization`: la chiave per chiamare l'API, che può essere selezionata direttamente dopo la richiesta.

**Request Body** include:

- `id`: l'ID dell'attività caricata.
- `action`: il modo di operare sull'attività.

Impostato come mostrato nella figura seguente:

### Esempio di codice

Si può notare che sul lato destro della pagina sono già stati generati automaticamente vari codici in diverse lingue, come mostrato nell'immagine:

Alcuni esempi di codice sono i seguenti:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/seedream/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "a6e0d456-189b-4c78-9232-2fe72166ab39",
  "action": "retrieve"
}'
```

### Esempio di risposta

Dopo una richiesta riuscita, l'API restituirà le informazioni dettagliate di questa attività. Ad esempio:

```json
{
  "success": true,
  "task_id": "84d1544a-9043-4dde-a98b-e889dacd75f6",
  "trace_id": "176acf03-7ca7-4fc6-85db-e3724d4f59eb",
  "data": [
    {
      "prompt": "un gatto siamese bianco",
      "size": "2048x2048",
      "image_url": "https://platform.cdn.acedata.cloud/seedream/6e5f9085-cc4a-4801-b77b-31550129ff19.jpg"
    }
  ]
}
```

Il risultato restituito contiene diversi campi, descritti come segue:

- `success`, lo stato attuale dell'attività di generazione video.
- `task_id`, l'ID dell'attività di generazione video attuale.
- `trace_id`, l'ID di tracciamento dell'attività video attuale.
- `data`, l'elenco dei risultati dell'attività di generazione immagini attuale.
  - `image_url`, il link all'attività di generazione immagini attuale.
  - `prompt`, la parola chiave.
  - `size`: i pixel dell'immagine generata.

- `action`: il modo di operare sull'attività.

Restituisce risultati che contengono più campi, dove `items` include i dettagli specifici delle attività in batch, ogni attività ha informazioni specifiche e i campi sono gli stessi di quelli sopra.

- `items`, tutti i dettagli specifici delle attività in batch. È un array, ogni elemento dell'array ha lo stesso formato del risultato della query di un'attività singola.
- `count`, il numero di attività in questa query batch.

Ogni oggetto attività nel risultato batch ha anche i seguenti campi di temporizzazione.

- `created_at`, data di creazione dell'attività, timestamp Unix (secondi, float).
- `started_at`, data di inizio esecuzione dell'attività, timestamp Unix (secondi, float).
- `finished_at`, data di completamento dell'attività, timestamp Unix (secondi, float). Questo campo non viene restituito se l'attività non è completata.
- `elapsed`, tempo di esecuzione dell'attività, unità in secondi (float, con 3 cifre decimali). Questo campo non viene restituito se l'attività non è completata.

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice di errore e le informazioni corrispondenti. Ad esempio:

- `400 token_mismatched`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`: Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`: Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`: Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
