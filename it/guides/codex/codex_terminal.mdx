Codex CLI è un agente di programmazione locale open source lanciato da OpenAI, che funziona nel tuo terminale. Può leggere codice, modificare file, eseguire comandi, interpretare errori e assisterti nelle attività di sviluppo quotidiane.

Codex CLI supporta fornitori di modelli personalizzati; puoi utilizzarlo tramite un proxy compatibile con OpenAI Responses fornito da Ace Data Cloud, senza bisogno di un abbonamento separato all'account ufficiale OpenAI. Dopo la configurazione, Codex CLI invierà le richieste a `https://api.acedata.cloud/v1`.

## Procedura di richiesta

Per usare Codex CLI, puoi prima ottenere il tuo API Token dal [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) e tenerlo a portata di mano.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Se non sei ancora loggato o registrato, verrai reindirizzato automaticamente alla pagina di login per registrarti e accedere; dopo il login, tornerai automaticamente alla pagina corrente.

Al primo utilizzo, viene offerto un credito gratuito per provare il servizio Codex CLI.

## Installazione di Codex CLI

Codex CLI supporta macOS, Linux, Windows e WSL. Puoi installarlo tramite npm oppure Homebrew (solo macOS).

### Installazione con npm (consigliata)

Se hai già installato Node.js, puoi installare direttamente tramite npm. Richiede Node.js versione 18 o superiore.

```bash
npm install -g @openai/codex
```

### Installazione con Homebrew (macOS)

Gli utenti macOS possono anche installare tramite Homebrew:

```bash
brew install --cask codex
```

### Verifica dell'installazione

Dopo l'installazione, riapri il terminale e verifica che il comando sia disponibile:

```bash
codex --version
```

Se ricevi `command not found`, probabilmente il terminale non ha ancora caricato il nuovo PATH. Chiudi e riapri il terminale oppure controlla le istruzioni di configurazione del PATH fornite dallo script di installazione.

## Configurazione di Codex CLI

Dopo l'installazione, Codex CLI tenta di connettersi al servizio ufficiale OpenAI per default. Per usare Ace Data Cloud, devi dichiarare un `model_provider` personalizzato nel file di configurazione di Codex e inserire il token API nella variabile d'ambiente corrispondente.

### Primo passo: impostare la variabile d'ambiente

Si consiglia di scrivere il token API nel file di configurazione della shell, ad esempio `~/.zshrc`, `~/.bashrc` o `~/.bash_profile`:

```bash
export ACEDATACLOUD_API_KEY="{token}"
```

Sostituisci `{token}` con il token API copiato dalla console Ace Data Cloud.

Dopo la configurazione, riapri il terminale o esegui il comando `source` corrispondente per applicare subito la modifica:

```bash
source ~/.zshrc
```

### Secondo passo: modificare il file di configurazione di Codex

Codex CLI usa `~/.codex/config.toml` come file di configurazione globale. Se non esiste, crealo:

```bash
mkdir -p ~/.codex
touch ~/.codex/config.toml
```

Inserisci il seguente contenuto in `~/.codex/config.toml`:

```toml
model_provider = "acedatacloud"
model = "gpt-5"
model_reasoning_effort = "high"

[model_providers.acedatacloud]
name = "Ace Data Cloud"
base_url = "https://api.acedata.cloud/v1"
env_key = "ACEDATACLOUD_API_KEY"
wire_api = "responses"
```

Spiegazione dei campi:

| Campo | Descrizione |
| --- | --- |
| `model_provider` | Nome del fornitore predefinito, corrispondente alla chiave sotto `[model_providers.<name>]` |
| `model` | ID del modello predefinito |
| `model_reasoning_effort` | Intensità del ragionamento, valori comuni: `low`, `medium`, `high` |
| `[model_providers.acedatacloud].base_url` | Indirizzo del proxy OpenAI Responses di Ace Data Cloud |
| `[model_providers.acedatacloud].env_key` | Nome della variabile d'ambiente da cui Codex CLI legge il token API |
| `[model_providers.acedatacloud].wire_api` | Tipo di protocollo, per usare OpenAI Responses API deve essere `responses` |

### Pulizia della cache di login OpenAI

Se hai già effettuato il login con un account ufficiale OpenAI in Codex CLI, potresti avere uno stato di login memorizzato localmente (di solito in `~/.codex/auth.json`). Prima di passare al proxy Ace Data Cloud, è consigliabile pulire il login precedente:

```bash
codex logout
```

Se il comando `codex logout` non è disponibile, puoi eliminare manualmente il file di cache:

```bash
rm -f ~/.codex/auth.json
```

Se non hai mai effettuato il login con un account OpenAI ufficiale, puoi saltare questo passaggio.

### Avvio della sessione

Entra nella directory del tuo progetto e avvia Codex CLI:

```bash
cd /path/to/your/project
codex
```

Quando appare l'interfaccia interattiva di Codex, puoi inserire direttamente le tue richieste, ad esempio:

```text
Spiega la struttura delle cartelle di questo progetto
```

### Verifica della configurazione

All'interno di Codex CLI, puoi verificare il modello e il fornitore correnti con:

```text
/model
```

Dovresti vedere che il modello proviene dal fornitore `acedatacloud`, ad esempio:

```text
Model: gpt-5
Provider: acedatacloud
```

Se il fornitore mostrato non è `acedatacloud`, significa che la configurazione non è stata applicata correttamente. Controlla che `~/.codex/config.toml` sia stato salvato correttamente e che la variabile d'ambiente `ACEDATACLOUD_API_KEY` sia leggibile nel terminale corrente:

```bash
echo $ACEDATACLOUD_API_KEY
```

Puoi anche consultare la cronologia delle richieste e i dettagli di fatturazione su [Ace Data Cloud Console - Utilizzo](https://platform.acedata.cloud/console/usages) e verificare il credito residuo su [Ace Data Cloud Console - Applicazioni](https://platform.acedata.cloud/console/applications).

## Come funziona

Codex CLI utilizza nativamente il protocollo OpenAI Responses API. Ace Data Cloud fornisce un servizio proxy compatibile con OpenAI Responses API all’indirizzo `https://api.acedata.cloud/v1/responses`, quindi Codex CLI non richiede un proxy locale né plugin aggiuntivi.

Il flusso di lavoro è il seguente:

1. Codex CLI legge `model_provider` da `~/.codex/config.toml` e carica il blocco di configurazione corrispondente `[model_providers.acedatacloud]`.
2. Codex CLI legge il token API dalla variabile d’ambiente indicata da `env_key` (`ACEDATACLOUD_API_KEY`).
3. Le richieste, tramite il protocollo `wire_api = "responses"`, vengono inviate a `base_url + /responses`, cioè `https://api.acedata.cloud/v1/responses`.
4. Ace Data Cloud verifica l’identità e il credito tramite il token API e inoltra la richiesta al canale modello upstream disponibile.
5. Al termine, la piattaforma registra il consumo e detrae il credito in base all’utilizzo effettivo.

In questo modo continui a usare il comando originale `codex` e l’esperienza nativa di Codex CLI, cambiando solo il servizio modello sottostante in Ace Data Cloud.

## Configurazione del modello

Il campo `model` in `~/.codex/config.toml` determina il modello predefinito usato da Codex. Il servizio OpenAI Responses di Ace Data Cloud supporta diversi modelli comuni, tra cui:

| Modello | Descrizione |
| --- | --- |
| `gpt-5` | Modello predefinito consigliato, adatto alla maggior parte dei compiti di codifica |
| `gpt-5-mini` | Versione più leggera e reattiva, adatta a compiti semplici |
| `gpt-5.5` | Versione aggiornata con capacità superiori |
| `gpt-5.5-pro` | Versione potenziata, ideale per compiti di ragionamento complessi |
| `gpt-4.1` | Modello principale della generazione precedente |
| `o3` | Modello con potenziamento del ragionamento, adatto a compiti che richiedono ragionamenti profondi |
| `o4-mini-high-all` | Modello leggero per ragionamenti |

Per cambiare modello temporaneamente, puoi specificarlo all’avvio di Codex tramite parametro da linea di comando:

```bash
codex --model gpt-5-mini
```

Oppure modifica direttamente il campo `model` in `~/.codex/config.toml` e riavvia. L’elenco completo dei modelli è disponibile nella [documentazione OpenAI di Ace Data Cloud](https://platform.acedata.cloud/documents/openai).

## Livelli di fiducia del progetto

Codex CLI supporta livelli di fiducia diversi per ogni progetto, per controllare quali operazioni l’agente può eseguire. Puoi aggiungere alla fine di `~/.codex/config.toml`:

```toml
[projects."/path/to/trusted/project"]
trust_level = "trusted"

[projects."/path/to/untrusted/project"]
trust_level = "untrusted"
```

Dove:

- `trusted`: l’agente ha permessi completi, può eseguire comandi e modificare file.
- `untrusted`: l’agente ha permessi limitati, più adatto a progetti meno familiari.
