La principale funzionalità dell'API di query dei compiti di Maestro è quella di interrogare lo stato di esecuzione e il risultato finale di un compito tramite l'ID del compito restituito dall'[API di generazione video di Maestro](development_maestro_videos.md) (`POST /maestro/videos`).

Questo documento fornirà dettagliate istruzioni per l'integrazione dell'API di query dei compiti di Maestro. Poiché la generazione video è un compito asincrono, dopo l'invio è necessario utilizzare questa interfaccia per interrogare il progresso e il prodotto finale, **l'interrogazione è gratuita e non consuma crediti.**

`POST https://api.acedata.cloud/maestro/tasks`

## Processo di richiesta

Per utilizzare l'API di query dei compiti di Maestro, prima di tutto vai al [Pannello di controllo di Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da conservare per uso futuro.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Se non hai ancora effettuato il login o registrato, verrai automaticamente reindirizzato alla pagina di login che ti invita a registrarti e accedere; una volta completato, verrai riportato automaticamente alla pagina corrente.

**Un API Token è sufficiente per accedere a tutti i servizi della piattaforma, non è necessario richiederne uno separato per ogni servizio.** La prima richiesta ti darà un credito gratuito, per un'esperienza senza costi; quando il credito è insufficiente, puoi ricaricare il saldo generale nel [pannello di controllo](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [API di query dei compiti di Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Query di un singolo compito

Per informazioni su come creare un compito video, fare riferimento al documento [API di generazione video di Maestro](development_maestro_videos.md). Utilizziamo come esempio un ID di compito restituito: `f57e99c4f60f4373a15517742ce2357d`, per dimostrare come interrogare il suo stato e risultato.

### Impostare l'intestazione della richiesta e il corpo della richiesta

**Request Headers** includono:

- `accept`: specifica di ricevere il risultato della risposta in formato JSON, qui si compila con `application/json`.
- `authorization`: la chiave per chiamare l'API, dopo la richiesta puoi selezionarla direttamente dal menu a discesa.
- `content-type`: il formato del corpo della richiesta, qui si compila con `application/json`.

**Request Body** include:

| Campo       | Tipo     | Obbligatorio | Descrizione                                                |
| ----------- | -------- | ------------ | --------------------------------------------------------- |
| `id`        | string   | Sì          | `task_id` restituito da `POST /maestro/videos`          |
| `action`    | string   | No          | `retrieve` (predefinito, per interrogare un singolo compito) / `retrieve_batch` (per interrogare la lista dei compiti storici) |

### Esempio di codice

Il codice CURL corrispondente è il seguente:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Il codice Python corrispondente è il seguente:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Esempio di risposta

Se la richiesta ha successo, l'API restituirà lo stato e il risultato di quel compito video. Un esempio di risposta quando il compito è completato è il seguente (ogni lingua corrisponde a un `variant`):

```json
{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "status": "succeeded",
  "elapsed": 312,
  "progress": { "percent": 100, "stage": "producing", "message": "rendering scene 2" },
  "request": {
    "prompt": "Spiega in 20 secondi cosa è un database vettoriale, adatto a un pubblico senza basi, concludendo con un punto da ricordare",
    "langs": ["zh-cn", "en"],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        { "lang": "zh-cn", "aspect": "9:16", "kind": "video", "title": "Cosa è un database vettoriale", "output_url": "https://…/zh.mp4" },
        { "lang": "en", "aspect": "9:16", "kind": "video", "title": "What is a vector database", "output_url": "https://…/en.mp4" }
      ],
      "project": { "tarball_url": "https://…/project.tar.gz", "outputs": ["https://…/zh.mp4", "https://…/en.mp4"] },
      "percent": 100,
      "stage": "producing",
      "progress": [ { "stage": "producing", "message": "rendering scene 2", "pct": 60, "t": 1750000000 } ]
    }
  }
}
```

La descrizione dei campi del risultato restituito è la seguente:

- `id`: l'ID di questo compito video, utilizzato per identificare univocamente questo compito di generazione video.
- `status`: stato del compito, i valori possono essere `pending → planning → producing → succeeded` (o `failed`). Lo stato di completamento del compito è determinato da questo `status` di alto livello.
- `elapsed`: tempo già trascorso per il compito (in secondi).
- `progress`: oggetto di progresso di alto livello, `percent` (0–100) sarà fissato a 100 dopo il completamento del compito; `stage` e `message` riflettono l'ultima voce di progresso dell'AI regista (quindi dopo il successo, `stage` potrebbe ancora essere l'ultimo stadio eseguito come `producing`), utilizzabile direttamente per mostrare una barra di progresso.
- `request`: corpo della richiesta al momento dell'avvio del compito.
- `response`: informazioni restituite dal compito.
  - `success`: indica se il compito è stato completato con successo.
  - `data.variants`: ogni lingua corrisponde a un oggetto di prodotto finale, contenente `lang`, `aspect`, `title`, `output_url` (indirizzo per il download del prodotto finale) e altro.
  - `data.project`: prodotto finale dell'intero progetto, contenente `tarball_url` (pacchetto del progetto) e `outputs` (tutti i link ai prodotti finali).
  - `data.progress`: array di eventi di progresso aggiunti per fase (log append-only), utilizzabile per mostrare il progresso in tempo reale in dettaglio.
- `created_at`: data di creazione del compito, timestamp Unix (in secondi).
- `started_at`: data di inizio esecuzione del compito, timestamp Unix (in secondi). Sarà null se il compito non è ancora iniziato.
- `finished_at`: data di completamento del compito, timestamp Unix (in secondi). Sarà null se il compito non è completato.

## Query della lista storica

Passando `action: retrieve_batch` puoi ottenere i compiti più recenti dell'utente attuale (in ordine decrescente di creazione), utilizzabile per la pagina "I miei video".

**Request Body** include:

| Campo               | Tipo     | Obbligatorio | Descrizione                      |
| ------------------- | -------- | ------------ | -------------------------------- |
| `action`            | string   | Sì          | Fisso come `retrieve_batch`     |
| `limit`             | int      | No          | Numero di risultati restituiti, predefinito 20 |
| `created_at_max`    | int      | No          | Restituisce solo i compiti creati prima di questo timestamp Unix (per la paginazione) |
| `created_at_min`    | int      | No          | Restituisce solo i compiti creati dopo questo timestamp Unix |

### Esempio di codice

Il codice CURL corrispondente è il seguente:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### Esempio di risposta

Se la richiesta ha successo, l'API restituirà la lista storica dei compiti dell'utente attuale:
```json
{
  "count": 2,
  "items": [
    {
      "id": "f57e99c4f60f4373a15517742ce2357d",
      "status": "succeeded",
      "progress": { "percent": 100, "stage": "producing", "message": "rendering scene 2" },
      "request": { "prompt": "…", "langs": ["zh-cn", "en"], "aspect": "9:16", "duration": 20 },
      "response": { "success": true, "data": { "variants": [ { "lang": "zh-cn", "output_url": "https://…/zh.mp4" } ] } }
    }
  ]
}
```

La descrizione dei campi del risultato è la seguente:

- `count`: il numero totale di compiti dell'utente attuale.
- `items`: array di compiti, ogni elemento ha lo stesso formato del risultato di "query di un singolo compito".

## Suggerimenti per il polling

Poiché la produzione video richiede tempo, lo `status` passerà da `pending → planning → producing → succeeded` (o `failed`). Si consiglia di eseguire il polling ogni 5-10 secondi, fino a quando lo `status` non diventa `succeeded` o `failed`. È possibile utilizzare il `progress.percent` di alto livello per mostrare una barra di progresso in tempo reale. **Il polling di questa interfaccia è gratuito e non consuma punti.**

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice di errore e le informazioni corrispondenti. Ad esempio:

- `401 invalid_token`: Non autorizzato, token di autorizzazione non valido o mancante.
- `404 not_found`: Compito non trovato, l'`task_id` fornito non esiste.
- `429 too_many_requests`: Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`: Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
