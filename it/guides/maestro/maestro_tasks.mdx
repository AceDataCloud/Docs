La funzione principale dell'API di query delle attività Maestro consiste nel recuperare, tramite l'ID attività restituito dall'[API di generazione video Maestro](development_maestro_videos.md) (`POST /maestro/videos`), lo stato di esecuzione e il risultato finale di tale attività.

Questo documento introdurrà nel dettaglio le istruzioni per l'integrazione dell'API di query delle attività Maestro. Poiché la generazione video è un'attività asincrona, dopo l'invio è necessario utilizzare questa API per effettuare il polling e ottenere l'avanzamento e il video finale, **il polling è gratuito e non consuma crediti.**

`POST https://api.acedata.cloud/maestro/tasks`

## Procedura di richiesta

Per utilizzare l'API di query delle attività Maestro, innanzitutto ottieni il tuo API Token dalla [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) e conservalo come riferimento.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato l'accesso o la registrazione, verrai automaticamente reindirizzato alla pagina di accesso per registrarti e accedere; una volta completato, tornerai automaticamente alla pagina corrente.

**Un solo API Token può chiamare tutti i servizi della piattaforma, senza doverne richiedere uno separatamente per ciascun servizio.** La prima richiesta include crediti gratuiti, che consentono di provare il servizio gratuitamente; quando i crediti sono insufficienti, puoi ricaricare il saldo universale nella [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [API di query delle attività Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Query di una singola attività

Per sapere come creare un'attività video, consulta la documentazione [API di generazione video Maestro](development_maestro_videos.md). Prendiamo come esempio un ID attività restituito: `f57e99c4f60f4373a15517742ce2357d`, per mostrare come consultarne lo stato e il risultato.

### Impostare le intestazioni e il corpo della richiesta

Le **Request Headers** includono:

- `accept`: specifica la ricezione di risultati di risposta in formato JSON; qui impostalo su `application/json`.
- `authorization`: la chiave per chiamare l'API, che può essere selezionata direttamente dal menu a discesa dopo la richiesta.
- `content-type`: il formato del corpo della richiesta; qui impostalo su `application/json`.

Il **Request Body** include:

| Campo       | Tipo     | Obbligatorio durante la query di una singola attività | Descrizione                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | obbligatorio durante la query di una singola attività | `task_id` restituito da `POST /maestro/videos`              |
| `action` | string | no         | `retrieve` (predefinito, query di una singola attività); quando si consulta l'elenco storico è fisso su `retrieve_batch` |

### Esempio di codice

Il codice CURL corrispondente è il seguente:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Il codice Python corrispondente è il seguente:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Esempio di risposta

Dopo che la richiesta ha esito positivo, l'API restituirà lo stato e il risultato di tale attività video. L'esempio di risposta al completamento dell'attività è il seguente (a ogni lingua corrisponde un `variant`):


I campi del risultato restituito sono descritti come segue:

- `id`: l'ID di questa attività video, utilizzato per identificare univocamente questa attività di generazione video.
- `status`: stato dell'attività, con valori `pending → planning → producing → succeeded` (oppure `failed`). Per stabilire se l'attività è completata, fa fede questo `status` di primo livello.
- `elapsed`: tempo trascorso dall'attività (secondi).
- `progress`: oggetto di avanzamento di primo livello; `percent` (0–100) verrà impostato a 100 dopo il successo dell'attività; `stage` e `message` riflettono l'evento di avanzamento più recente del regista AI (pertanto, dopo il successo, `stage` potrebbe ancora essere l'ultima fase di esecuzione come `producing`) e possono essere utilizzati direttamente per visualizzare la barra di avanzamento.
- `request`: corpo della richiesta al momento dell'avvio dell'attività.
- `response`: informazioni di risposta dell'attività.
  - `success`: se l'attività è riuscita.
  - `data.variants`: a ogni lingua corrisponde un oggetto video finale, che include `lang`, `aspect`, `title`, `output_url` (indirizzo per il download del video finale) e così via.
  - `data.project`: output dell'intero progetto, che include `tarball_url` (pacchetto del progetto) e `outputs` (tutti i collegamenti ai video finali).
  - `data.progress`: array di eventi di avanzamento aggiunti per fase (registro append-only), utilizzabile per mostrare l'avanzamento dettagliato in tempo reale.
- `created_at`: ora di creazione dell'attività, timestamp Unix (secondi).
- `started_at`: ora di avvio dell'esecuzione dell'attività, timestamp Unix (secondi). È null quando l'attività non è ancora iniziata.
- `finished_at`: ora di completamento dell'attività, timestamp Unix (secondi). È null quando l'attività non è completata.

## Query dell'elenco storico

Passando `action: retrieve_batch` è possibile ottenere le attività più recenti dell'esecutore attualmente autenticato (in ordine decrescente di data di creazione), utilizzabili per la pagina dell'elenco «I miei video». L'elenco storico è isolato in base all'identità di accesso.

Il **Request Body** include:
| Campo               | Tipo     | Obbligatorio  | Descrizione                              |
| ---------------- | ------ | --- | ------------------------------- |
| `action`         | string | Sì   | Fisso come `retrieve_batch`            |
| `limit`          | int    | No   | Numero di risultati restituiti, predefinito 20; intervallo valido 1–100          |
| `created_at_max` | int    | No   | Restituisce solo le attività strettamente precedenti a questo timestamp Unix (escluso il valore limite, per la paginazione) |
| `created_at_min` | int    | No   | Restituisce solo le attività strettamente successive a questo timestamp Unix (escluso il valore limite)     |

### Esempio di codice

Il codice CURL corrispondente è il seguente:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### Esempio di risposta

Dopo che la richiesta ha avuto successo, l'API restituirà l'elenco delle attività storiche dell'utente corrente:

L'introduzione ai campi del risultato restituito è la seguente:

- `count`: il numero totale di attività visibili all'esecutore attualmente autenticato, non influenzato dalle condizioni temporali o da `limit`.
- `items`: l'array di attività filtrato in base alle condizioni temporali e a `limit`, ordinato in ordine decrescente di data di creazione; il formato di ciascun elemento è coerente con il risultato restituito da «Query di una singola attività».

## Suggerimenti per il polling

Poiché la produzione di video richiede molto tempo, `status` passerà attraverso `pending → planning → producing → succeeded` (oppure `failed`). Si consiglia di effettuare il polling una volta ogni 5–10 secondi, finché `status` non diventa `succeeded` o `failed`. È possibile utilizzare `progress.percent` di primo livello per mostrare una barra di avanzamento in tempo reale. **Il polling di questa interfaccia è gratuito e non consuma crediti.**

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice e il messaggio di errore corrispondenti. Ad esempio:

- `401 invalid_token`: Non autorizzato, token di autorizzazione non valido o mancante.
- `404 not_found`: Attività non trovata, il task_id specificato non esiste.
- `429 too_many_requests`: Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`: Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
