MiMo 2.6 Pro e MiMo 2.6 Flash sono modelli della serie Xiaomi MiMo. Questa interfaccia utilizza il formato OpenAI Chat Completions e applica tariffe in base ai token di input, output e cache raggiunta.

## Modelli e interfaccia

| Modello                | Posizionamento           |
| ----------------- | ------------ |
| `mimo-v2.6-pro`   | Analisi complessa, ragionamento e chiamata di strumenti |
| `mimo-v2.6-flash` | Conversazioni quotidiane e attività leggere    |

Abilitare MiMo e ottenere le credenziali API corrispondenti, inviare richieste a `https://api.acedata.cloud/mimo/chat/completions`. Il `base_url` dell'SDK OpenAI può essere impostato su `https://api.acedata.cloud/mimo`. Anche l'endpoint unificato `/v1/chat/completions` richiede le relative autorizzazioni del servizio.

Il primo gruppo di interfacce riguarda le Chat Completions testuali; immagini, audio, video, ricerca web, Responses, Messages, Batch e UltraSpeed non rientrano nell'ambito di questa versione.

## Esempio Python

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["ACEDATACLOUD_API_KEY"],
    base_url="https://api.acedata.cloud/mimo",
)
response = client.chat.completions.create(
    model="mimo-v2.6-pro",
    messages=[{"role": "user", "content": "解释彩虹形成的原因。"}],
    max_completion_tokens=256,
    extra_body={"thinking": {"type": "disabled"}},
)
print(response.choices[0].message.content)
print(response.usage)
```

L'esempio mostra la sintassi della richiesta; esempi di risposte reali verranno aggiunti dopo la verifica del servizio.

## Streaming, ragionamento e chiamata di strumenti

Impostare `stream=true` per ricevere SSE; se sono necessari i dati di utilizzo finali, passare `stream_options={"include_usage": true}`. Il client deve gestire gli incrementi di contenuto, contenuto di ragionamento e chiamate di strumenti, nonché l'evento usage finale.

Utilizzare `thinking.type=enabled` per abilitare il ragionamento, `disabled` per disabilitarlo. `reasoning_content` e il `content` finale vengono restituiti separatamente; quando si prosegue una chiamata di strumenti, conservare il contenuto di ragionamento nel messaggio dell'assistente, i `tool_calls` completi e il corrispondente `tool_call_id`.

Inviare solo dichiarazioni di strumenti con `type=function`; `tool_choice` supporta solo `auto`. L'applicazione è responsabile dell'esecuzione degli strumenti e della restituzione dei risultati; il fatto che il modello restituisca una chiamata di strumenti non significa che lo strumento sia già stato eseguito. La ricerca web integrata nel servizio non è ancora disponibile.

## Fatturazione

`prompt_tokens` include gli input che hanno raggiunto la cache; `prompt_tokens_details.cached_tokens` viene calcolato al prezzo della cache, mentre gli altri input vengono calcolati al normale prezzo di input. `completion_tokens` include l'output di ragionamento, non sommare ripetutamente i token di ragionamento. Anche le chiamate in streaming vengono fatturate in base all'utilizzo effettivo finale.

I prezzi fanno fede a quelli della console, il costo in dollari dei Credit dipende dal piano di acquisto. Le richieste non riuscite non devono essere considerate completate con successo; se è necessario verificare l'addebito, fornire l'identificatore di tracciamento nella risposta.

## Gestione degli errori

Per errori di parametri, controllare il formato della richiesta; per errori di autenticazione o autorizzazione, controllare le credenziali e lo stato di attivazione del servizio; in caso di 429, riprovare con backoff. Quando non vi è capacità di modelli sana, potrebbe essere restituito 503. Se si verifica un'interruzione dopo l'avvio della risposta in streaming, controllare prima i risultati e l'utilizzo già ricevuti, evitando di ripetere ciecamente la richiesta.
