Questo documento illustra le istruzioni per l'integrazione con l'API di Generazione Video Sora, che consente di generare video ufficiali Sora tramite parametri personalizzati. Questa API supporta due modalità di versione:

- **Versione 1 (modalità classica)**: supporta i parametri `duration` (10/15/25 secondi), `orientation` (orizzontale/verticale), `size` (small/large risoluzione), immagini di riferimento `image_urls`, link del personaggio `character_url` ecc.
- **Versione 2 (modalità partner)**: supporta i parametri `seconds` (4/8/12 secondi), risoluzione a livello di pixel `size` (es. 1280x720), immagini di riferimento `input_reference` ecc.

## Procedura di richiesta

Per utilizzare l'API, è necessario prima richiedere il servizio corrispondente sulla pagina [Sora Videos Generation API](https://platform.acedata.cloud/documents/99a24421-2e22-4028-8201-e19cb834b67e). Una volta entrati nella pagina, cliccare sul pulsante "Acquire", come mostrato nell'immagine:

![](https://cdn.acedata.cloud/q6ytrc.png)

Se non si è effettuato l'accesso o la registrazione, si verrà reindirizzati automaticamente alla pagina di login per registrarsi e accedere; dopo l'accesso si tornerà automaticamente alla pagina corrente.

Alla prima richiesta viene fornito un credito gratuito per utilizzare l'API senza costi.

## Uso base (Versione 1)

Innanzitutto, vediamo come utilizzare la Versione 1: inserendo la parola chiave `prompt`, un array di link di immagini di riferimento `image_urls` e il modello `model`, si ottiene il risultato elaborato. Dettagli come segue:

<p><img src="https://cdn.acedata.cloud/h8dyz3.png" width="500" className="m-auto" /></p>

Qui abbiamo impostato gli header della richiesta, inclusi:

- `accept`: formato di risposta desiderato, qui impostato su `application/json` (formato JSON).
- `authorization`: chiave API per chiamare l'API, selezionabile dopo la richiesta.

Nel body della richiesta sono inclusi:

- `model`: modello per generare il video, supporta `sora-2` (modalità standard) e `sora-2-pro` (modalità HD). `sora-2-pro` supporta video di 25 secondi, mentre `sora-2` solo 10 o 15 secondi.
- `size`: risoluzione video, `small` per qualità standard, `large` per HD (solo Versione 1).
- `duration`: durata video, supporta 10, 15, 25 secondi; 25 secondi solo con `sora-2-pro` (solo Versione 1).
- `orientation`: orientamento video, supporta `landscape` (orizzontale), `portrait` (verticale) (solo Versione 1).
- `image_urls`: array di link immagini di riferimento per generazione video da immagine (solo Versione 1).
- `character_url`: link del personaggio, il video non deve contenere persone reali (solo Versione 1).
- `character_start`/`character_end`: secondi di inizio/fine apparizione del personaggio, intervallo 1-3 secondi (solo Versione 1).
- `prompt`: parola chiave (obbligatorio).
- `callback_url`: URL per callback asincrono.
- `version`: versione API, `1` (default) o `2`.

```shell
curl -X POST 'https://api.acedata.cloud/sora/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "size": "large",
  "duration": 15,
  "orientation": "landscape",
  "prompt": "cat running on the river",
  "model": "sora-2"
}'
```

## Task di generazione video da immagine (Versione 1)

Per effettuare un task di generazione video da immagine, il parametro `image_urls` deve contenere i link delle immagini di riferimento, con le seguenti specifiche:

- `image_urls`: array di link alle immagini di riferimento per il task. Non inviare immagini con volti reali per evitare fallimenti del task.

Esempio di compilazione:

<p><img src="https://cdn.acedata.cloud/ch7x3t.png" width="500" className="m-auto" /></p>

Il codice generato automaticamente è:

<p><img src="https://cdn.acedata.cloud/z1ud8l.png" width="500" className="m-auto" /></p>

Codice corrispondente:

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "size": "large",
    "duration": 15,
    "orientation": "landscape",
    "prompt": "cat running on the river",
    "model": "sora-2",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Task di generazione video con personaggio (Versione 1)

Per generare un video con personaggio, il parametro `character_url` deve contenere il link al video per la creazione del personaggio. Il video non deve contenere persone reali, altrimenti il task fallirà. Specifiche:

- `character_url`: link al video per la creazione del personaggio, senza persone reali.

## Modalità Versione 2

Oltre alla modalità Versione 1, l'API supporta anche la modalità Versione 2, attivabile impostando il parametro `version` a `2`. La Versione 2 supporta durate video più brevi e controllo della risoluzione a livello di pixel.

### Descrizione parametri Versione 2

| Parametro       | Tipo    | Obbligatorio | Descrizione                                         |
|-----------------|---------|--------------|----------------------------------------------------|
| `version`       | integer | Sì           | Impostare a `2`                                    |
| `prompt`        | string  | Sì           | Parola chiave per generare il video                 |
| `model`         | string  | No           | `sora-2` (default) o `sora-2-pro`                   |
| `duration`      | integer | No           | Durata video: `4` (default), `8`, `12` secondi      |
| `size`          | string  | No           | Risoluzione: `720x1280` (default), `1280x720`, `1024x1792`, `1792x1024` |
| `image_urls`    | array   | No           | Array di URL immagini di riferimento, usa solo la prima immagine, dimensioni devono corrispondere a `size` |
| `callback_url`  | string  | No           | URL per callback asincrono                           |

### Esempio base

```shell
curl -X POST 'https://api.acedata.cloud/sora/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "version": 2,
  "prompt": "cat running on the river",
  "model": "sora-2",
  "duration": 8,
  "size": "1280x720"
}'
```

Codice Python corrispondente:

### Uso di immagini di riferimento (Versione 2)

Nella modalità Versione 2, è possibile passare immagini di riferimento tramite il parametro `image_urls` per guidare la generazione video (viene usata solo la prima immagine):

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "version": 2,
    "prompt": "a person walking through a beautiful garden",
    "model": "sora-2",
    "duration": 4,
    "size": "1280x720",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

> **Nota**: la dimensione dell'immagine di riferimento deve corrispondere al parametro `size`, ad esempio se `size` è `1280x720`, l'immagine deve avere dimensioni 1280×720.

### Confronto parametri Versione 1 e Versione 2

| Parametro       | Versione 1           | Versione 2                                   |
|-----------------|---------------------|----------------------------------------------|
| `version`       | 1 (default)          | 2                                            |
| `prompt`        | ✅                   | ✅                                            |
| `model`         | ✅ sora-2 / sora-2-pro | ✅ sora-2 / sora-2-pro                        |
| `duration`      | ✅ 10/15/25 secondi   | ✅ 4/8/12 secondi                             |
| `orientation`   | ✅ landscape/portrait | ❌                                            |
| `size`          | ✅ small/large        | ✅ 720x1280/1280x720/1024x1792/1792x1024     |
| `image_urls`    | ✅ più immagini       | ✅ solo la prima immagine                      |
| `character_url` | ✅                    | ❌                                            |
| `callback_url`  | ✅                    | ✅                                            |

## Callback asincrona

Poiché la generazione video con Sora Videos Generation API richiede circa 1-2 minuti, se l'API non risponde rapidamente la connessione HTTP rimane aperta causando consumo di risorse. Per questo motivo l'API supporta callback asincrona.

Il flusso è: il client invia la richiesta specificando un campo `callback_url`; l'API risponde immediatamente con un `task_id` che identifica il task. Quando il task è completato, il risultato viene inviato tramite POST in formato JSON all'URL `callback_url` specificato, includendo anche il `task_id` per associare il risultato al task.

Vediamo un esempio pratico.

![](https://cdn.acedata.cloud/cjjfly.png)

Copiamo questo URL, ad esempio `https://webhook.site/eb238c4f-da3b-47a5-a922-a93aa5405daa`, da usare come Webhook.

Impostiamo il campo `callback_url` con questo URL e inseriamo gli altri parametri, come mostrato:

## Gestione errori

Durante la chiamata all'API, in caso di errore l'API restituisce un codice e un messaggio di errore. Ad esempio:

- `400 token_mismatched`: richiesta errata, probabilmente parametri mancanti o non validi.
- `400 api_not_implemented`: richiesta errata, probabilmente parametri mancanti o non validi.
- `401 invalid_token`: non autorizzato, token di autorizzazione mancante o non valido.
- `429 too_many_requests`: troppe richieste, superato il limite di velocità.
- `500 api_error`: errore interno del server.

### Esempio di risposta di errore

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
