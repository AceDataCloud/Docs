La principale funzionalità dell'API Sora Tasks è quella di interrogare lo stato di esecuzione di un'attività utilizzando l'ID dell'attività generato dall'API Sora Videos Generation.

Questo documento fornirà una descrizione dettagliata dell'integrazione dell'API Sora Tasks, aiutandoti a integrare facilmente e sfruttare appieno le potenti funzionalità di questa API. Con l'API Sora Tasks, puoi facilmente interrogare lo stato di esecuzione delle attività dell'API Sora Videos Generation.

## Processo di richiesta

Per utilizzare l'API Sora Tasks, è necessario prima andare alla pagina di richiesta [Sora Videos Generation API](https://platform.acedata.cloud/documents/sora-videos) per richiedere il servizio corrispondente, quindi copiare l'ID dell'attività dell'API Sora Videos Generation, come mostrato nell'immagine:

<p><img src="https://cdn.acedata.cloud/za62pb.png" width="500" className="m-auto" /></p>

Infine, accedi alla pagina dell'API Tasks [Sora Tasks API](https://platform.acedata.cloud/documents/sora-tasks) per richiedere il servizio corrispondente. Una volta entrato nella pagina, fai clic sul pulsante "Acquire", come mostrato nell'immagine:

![Pagina di richiesta](https://cdn.acedata.cloud/rci31i.png)

Se non hai ancora effettuato il login o la registrazione, verrai automaticamente reindirizzato alla [pagina di login](https://platform.acedata.cloud) che ti invita a registrarti e accedere. Dopo aver effettuato il login o la registrazione, verrai automaticamente riportato alla pagina corrente.

Alla prima richiesta, verrà offerto un credito gratuito, che ti consente di utilizzare gratuitamente questa API.

## Esempio di richiesta

L'API Sora Tasks può essere utilizzata per interrogare i risultati dell'API Sora Videos Generation. Per informazioni su come utilizzare l'API Sora Videos Generation, fare riferimento al documento [Sora Videos Generation API](https://platform.acedata.cloud/documents/sora-videos-integration).

Prendiamo come esempio un ID di attività restituito dal servizio Sora Videos Generation API e dimostriamo come utilizzare questa API. Supponiamo di avere un ID di attività: b8976e18-32dc-4718-9ed8-1ea090fcb6ea, e ora dimostriamo come passare un ID di attività.

### Impostazione dell'intestazione della richiesta e del corpo della richiesta

**Request Headers** includono:

- `accept`: specifica di ricevere la risposta in formato JSON, qui impostato su `application/json`.
- `authorization`: la chiave per chiamare l'API, che può essere selezionata direttamente dopo la richiesta.

**Request Body** include:

- `id`: l'ID dell'attività caricata.
- `action`: il modo in cui operare sull'attività.

Impostato come mostrato nell'immagine seguente:

<p><img src="https://cdn.acedata.cloud/fe19dd.png" width="500" className="m-auto" /></p>

### Esempio di codice

Si può notare che sul lato destro della pagina sono già stati generati automaticamente vari codici in diverse lingue, come mostrato nell'immagine:

<p><img src="https://cdn.acedata.cloud/ou5lfa.png" width="500" className="m-auto" /></p>

Alcuni esempi di codice sono i seguenti:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/sora/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/sora/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice di errore e le informazioni corrispondenti. Ad esempio:

- `400 token_mismatched`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`: Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`: Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`: Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore
