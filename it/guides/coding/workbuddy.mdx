## 1. Ottenere la API Key

Apri l'[elenco delle applicazioni Ace Data Cloud](https://platform.acedata.cloud/console/applications), accedi a un'applicazione disponibile e copia la API Key.

![Ottenere la API Key di Ace Data Cloud](https://cdn.acedata.cloud/dvc3cg.jpg)

## 2. Aggiungere un modello

In WorkBuddy, vai su **Impostazioni → Modelli → Modelli personalizzati → Aggiungi modello**, quindi compila:

| Campo       | Valore                                                                                                |
| -------- | ------------------------------------------------------------------------------------------------ |
| Provider | `Custom`                                                                                         |
| Indirizzo dell'interfaccia     | `https://api.acedata.cloud/v1`                                                                   |
| API Key  | La API Key appena copiata                                                                                    |
| Nome del modello     | Vai al [catalogo dei modelli](https://platform.acedata.cloud/models) per visualizzare e inserisci esattamente il nome del modello da chiamare, ad esempio `claude-opus-5`, `gpt-6-sol` |
| Protocollo personalizzato    | Disattivato                                                                                               |

![Interfaccia di configurazione di WorkBuddy Custom Provider](https://cdn.acedata.cloud/189027b68722.png)

> L'`id` qui è il nome del modello utilizzato dal parametro `model` nella richiesta API, non è l'UUID del servizio, dell'API o dell'Application, né un nome di visualizzazione personalizzato. Puoi inserire `ds-4.0` solo quando il catalogo in tempo reale restituisce `{"id":"ds-4.0"}`; se non è presente nel catalogo significa che al momento non è disponibile, non indovinarlo né abbreviarlo.

Puoi prima visualizzare i modelli disponibili nel [catalogo dei modelli](https://platform.acedata.cloud/models); se devi confermare il nome esatto richiamabile dalle attuali credenziali Coding, usa la API Key appena copiata per interrogare il catalogo API:

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Nell'array `data` della risposta trova il modello di destinazione e copia esattamente il valore del suo `id`. Configura gli interruttori delle capacità in base al supporto effettivo di quel modello.

Mantenendo disattivato il “protocollo personalizzato”, WorkBuddy completerà il percorso secondo le regole di OpenAI Chat Completions. Gli interruttori delle capacità avanzate (strumenti, immagini, ragionamento) devono essere attivati solo in base alle capacità effettive del modello selezionato; in caso di dubbio, mantieni prima le impostazioni predefinite.

## 3. Verifica

Dopo il salvataggio, seleziona il modello appena aggiunto nel selettore dei modelli di chat e invia `Rispondi solo OK`. Quindi esegui un'attività di file in sola lettura o di strumenti per confermare che le capacità richieste siano disponibili; i record delle chiamate possono essere visualizzati nella [cronologia di utilizzo](https://platform.acedata.cloud/console/usages).

Se il modello non appare, verifica che la configurazione sia stata salvata e abilitata; per l'errore 401 controlla la Key; per l'errore 404 controlla che il nome del modello inserito corrisponda esattamente all'`id` nel catalogo e che l'indirizzo dell'interfaccia sia corretto. La documentazione ufficiale di WorkBuddy indica che la Key viene salvata nella configurazione locale, ma il contenuto delle richieste verrà comunque inviato al servizio di modello configurato.
