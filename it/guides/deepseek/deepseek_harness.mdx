[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) è un agente di programmazione che viene eseguito localmente. Legge l'area di lavoro, chiama strumenti ed esegue comandi, quindi chiama il modello tramite l'interfaccia OpenAI-compatible Chat Completions.

> Questo documento è applicabile a `deepseek-harness-sdk==0.1.0rc6` e `deepseek-harness-runtime-bin==0.1.0rc6`. Dopo aver aggiornato il client, completare nuovamente il test del file di sola lettura qui sotto.

## Ambito di supporto

| Progetto       | Configurazione                             |
| -------------- | ----------------------------------------- |
| URL base API   | `https://api.acedata.cloud/v1`          |
| Modello        | `deepseek-v4-pro`                        |
| Protocollo     | OpenAI-compatible Chat Completions (streaming) |
| Capacità       | Testo, processo di ragionamento, chiamate a strumenti di funzione, ciclo di strumenti Bash locale, statistiche di utilizzo |

La directory dei modelli cambierà. Prima di eseguire, utilizzare la chiave esclusiva del Piano di Codifica per interrogare la directory in tempo reale:

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY"
```

Confermare che la risposta contenga `deepseek-v4-pro`. Non considerare `deepseek-v4-flash` come un sostituto equivalente per la modalità strumenti di questo documento; nella verifica della versione fissa, la sua storia di ragionamento multi-turno e la riproduzione degli strumenti non hanno superato.

## 1. Preparare la chiave esclusiva

Aprire [l'applicazione Coding Plan](https://platform.acedata.cloud/console/applications), accedere all'applicazione di codifica acquistata, creare o copiare la chiave API esclusiva di tale applicazione. Il Piano di Codifica non utilizza un saldo generale, le chiavi di altre applicazioni non possono rappresentare i diritti del pacchetto.

Inserire la chiave solo nella shell corrente:

```bash
export ACEDATACLOUD_API_KEY="INSERISCI_LA_TUA_CHIAVE_CODIFICA_QUI"
export DEEPSEEK_BASE_URL="https://api.acedata.cloud/v1"
export DEEPSEEK_API_KEY="$ACEDATACLOUD_API_KEY"
```

Non inserire la chiave reale in script, repository di configurazione, screenshot del terminale o registrazioni di sessione.

## 2. Creare un'area di lavoro isolata

Il runtime incluso di Harness contiene strumenti Bash locali. Durante la prima verifica, non puntare a progetti reali o alla directory principale; creare una directory usa e getta senza segreti:

```bash
mkdir -p /tmp/deepseek-harness-demo/workspace
mkdir -p /tmp/deepseek-harness-demo/sessions
printf 'compatibility fixture\n' > /tmp/deepseek-harness-demo/workspace/fixture.txt
python3 -m venv /tmp/deepseek-harness-demo/venv
/tmp/deepseek-harness-demo/venv/bin/pip install \
  "deepseek-harness-sdk==0.1.0rc6"
```

Se la rete aziendale utilizza un'immagine PyPI privata, confermare prima che la stessa versione di `deepseek-harness-runtime-bin` sia presente nell'immagine. Non utilizzare `danger-full-access` per ampliare l'ambito di accesso ai file; l'esempio di questo documento passa solo la directory usa e getta a `cwd`.

## 3. Eseguire l'SDK Python ufficiale

Salvare il contenuto seguente come `/tmp/deepseek-harness-demo/run.py`:

```python
import os

from deepseek_harness import DeepSeekHarness

with DeepSeekHarness(
    provider="deepseek-official",
    model="deepseek-v4-pro",
    max_tokens=160,
    cwd="/tmp/deepseek-harness-demo/workspace",
    session_root="/tmp/deepseek-harness-demo/sessions",
    base_url=os.environ["DEEPSEEK_BASE_URL"],
    api_key=os.environ["DEEPSEEK_API_KEY"],
    request_timeout_seconds=180,
) as harness:
    result = harness.run(
        "Read fixture.txt once, then reply with exactly: sdk-harness-ok",
        session_id="acedatacloud-compat",
    )

print(result.final_response)
print(result.finish_reason)
```

Eseguire:

```bash
/tmp/deepseek-harness-demo/venv/bin/python \
  /tmp/deepseek-harness-demo/run.py
```

Risultato atteso:

```text
sdk-harness-ok
completed
```

Questo passaggio verifica anche l'autenticazione Bearer, `/v1/chat/completions`, SSE, contenuto di ragionamento, chiamate agli strumenti e restituzione dei risultati degli strumenti. Una volta completato, è possibile eliminare `/tmp/deepseek-harness-demo`; se la directory di sessione contiene contesto di progetto, deve essere conservata con lo stesso livello di sensibilità del repository di codice.

## Domande frequenti

- **401**: Controllare se `ACEDATACLOUD_API_KEY` è esportato nella stessa shell in cui viene eseguito Python.
- **403 o avviso di quota**: Confermare che la chiave appartenga all'attuale applicazione di codifica, che il pacchetto sia ancora valido e che ci sia un saldo residuo.
- **Modello non disponibile**: Interrogare nuovamente `/v1/models`, non indovinare il nome del modello in base a vecchie schermate.
- **Errore `reasoning_content` / riproduzione degli strumenti**: Confermare che SDK/runtime siano entrambi della versione fissa di questo documento e utilizzare `deepseek-v4-pro`.
- **Numero di esecuzioni degli strumenti anomalo**: Interrompere l'esecuzione di attività che potrebbero avere effetti collaterali, prima utilizzare il fixture di sola lettura di questo documento per verificare la versione attuale del servizio.
- **Installazione fallita**: Confermare che Python 3.10+, l'architettura del sistema operativo siano supportati dall'attuale wheel e controllare che le versioni di SDK/runtime siano coerenti.

## Limiti delle capacità

Questo documento verifica solo il ciclo di testo e strumenti dell'SDK Python locale fino a Chat Completions. Immagini, Files API, `/v1/responses`, `/v1/messages`, aree di lavoro remote e sandbox ospitate non rientrano nell'ambito di questo tutorial; i diritti dell'area di lavoro e i rischi dei comandi locali sono responsabilità della macchina e della configurazione che esegue Harness.
