Questo documento descrive l'integrazione e l'uso dell'API di generazione video MiniMax H3. Questa interfaccia supporta video generati da testo, controllo del primo e dell'ultimo fotogramma e video generati da riferimenti multimodali, utilizzando una struttura `content` multimodale V2 unificata per creare compiti.

## Processo di richiesta

Per utilizzare l'API di generazione video MiniMax H3, prima vai al [Pannello di controllo di Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da conservare per uso futuro.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato il login o la registrazione, verrai automaticamente reindirizzato alla pagina di login che ti invita a registrarti e accedere; una volta completato, verrai riportato automaticamente alla pagina corrente.

**Un API Token è sufficiente per accedere a tutti i servizi della piattaforma, senza necessità di richiederne uno separato per ogni servizio.** La prima richiesta ti darà un credito gratuito, per un'esperienza senza costi; quando il credito è insufficiente, puoi ricaricare il saldo generale nel [pannello di controllo](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [API di generazione video MiniMax H3 →](https://platform.acedata.cloud/documents/minimax-videos-integration)

Si consiglia di salvare il Token come variabile d'ambiente, senza scriverlo nel codice sorgente o inviarlo al repository:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Panoramica dell'interfaccia

- **Base URL**: `https://api.acedata.cloud`
- **Endpoint**: `POST /minimax/videos`
- **Metodo di autenticazione**: Porta `authorization: Bearer {token}` nell'HTTP Header
- **Intestazioni della richiesta**:
  - `accept: application/json`
  - `content-type: application/json`
- **Modello (model)**: `MiniMax-H3`
- **Struttura di input**: Passa testo, immagini, video e audio tramite `content`
- **Modalità di output**: Per impostazione predefinita, attende la generazione completa e restituisce il `task` completo; passando `async: true` o `callback_url`, restituisce immediatamente `task_id` e `trace_id`
- **Query dei risultati**: Ottieni stato e video completato tramite [API di query dei task MiniMax H3](/documents/minimax-tasks-integration)
- **Callback asincrona**: Facoltativa, ricevi il risultato finale del task tramite `callback_url`

Non è necessario passare `action` per scegliere la modalità di generazione, l'interfaccia determinerà automaticamente l'uso in base al tipo di materiale e al `role` nel `content`.

## Scenari adatti

| Scenari         | Combinazione di input                  | Usos comuni                      |
| -------------- | ------------------------------------- | ------------------------- |
| Video generati da testo       | Testo                                | Idee pubblicitarie, prove di storyboard, video brevi, riprese atmosferiche        |
| Video generati da immagine di primo fotogramma     | Testo + Immagine di primo fotogramma             | Far muovere naturalmente immagini di prodotto, poster, foto di persone o illustrazioni      |
| Video di fotogramma finale / primo e ultimo fotogramma | Testo + fotogramma finale, o testo + primo fotogramma + fotogramma finale | Controllare l'inizio e la fine del video, transizioni, cambiamenti di crescita e confronti tra prima e dopo      |
| Video generati da riferimenti multimodali   | Testo + immagine / video / audio di riferimento   | Mantenere coerenza tra personaggi e prodotti, replicare azioni, movimenti di camera, tonalità audio o ritmo di montaggio |

## Processo di chiamata

Per impostazione predefinita, se non si passa `async`, `/minimax/videos` attenderà il completamento della generazione e restituirà direttamente il `task` completo. Se è necessario liberare immediatamente la connessione, passare `async: true` o `callback_url`:

1. Salva `task_id` e `trace_id` nella risposta immediata.
2. Se non è configurato un callback, chiama `/minimax/tasks` ogni circa 10 secondi per controllare.
3. Quando `task.status` diventa `succeeded`, ottieni il video da `task.content.url`.
4. Quando lo stato è `failed` o `cancelled`, interrompi il polling e leggi `task.error`.

## Parametri di richiesta di alto livello

| Parametro             | Tipo       | Obbligatorio   | Valore predefinito        | Descrizione                                                |
| ------------------- | -------- | ------------ | -------------------- | ------------------------------------------------- |
| `model`             | string   | Sì          | -                    | Fisso su `MiniMax-H3`                                  |
| `content`           | object[] | Sì          | -                    | Array di contenuti multimodali, deve contenere un elemento `text` non vuoto                         |
| `resolution`        | string   | Sì          | -                    | `768P` o `2K`                                     |
| `duration`          | integer  | Sì          | -                    | Durata di generazione, intero da 4 a 15 secondi                                     |
| `ratio`             | string   | Obbligatorio se condizionato | `adaptive` | `adaptive`, `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16` |
| `async`             | boolean  | No          | `false`              | Se `true`, restituisce immediatamente l'identificativo del task, i risultati possono essere ottenuti tramite l'interfaccia del task                       |
| `callback_url`      | string   | No          | -                    | URL di callback pubblico per ricevere il risultato finale del task; se fornito, attiva automaticamente la modalità asincrona                     |

Le regole per `ratio` dipendono dal flusso di lavoro:

- **Video generati da testo**: obbligatorio e non può essere `adaptive`.
- **Video di primo fotogramma, fotogramma finale o primo e ultimo fotogramma**: il formato è determinato dall'immagine di input, si consiglia di omettere o passare `adaptive`.
- **Video generati da riferimenti multimodali**: può essere omesso, predefinito `adaptive`; può anche essere specificato un rapporto fisso.

L'interfaccia non accetta campi obsoleti o compatibili, come `prompt`, `image_urls`, `audio_urls`, `messages` e `first_frame_image`. Quando si ricevono errori con questi parametri, si prega di rimuovere i campi obsoleti e migrare a `content`; ad esempio, cambiare `"prompt": "Un gatto che saluta"` in `"content": [{"type": "text", "text": "Un gatto che saluta"}]`. Non inviare contemporaneamente formati nuovi e obsoleti.

## Parametri degli elementi di contenuto

Ogni elemento di contenuto deve avere `type`, gli altri campi sono determinati dal tipo:

| `type`      | Campo dati            | `role`            | Descrizione                                     |
| ----------- | --------------- | ----------------- | -------------------------------------- |
| `text`      | `text`          | Non inviato                | Ogni richiesta deve contenere un elemento di testo non vuoto, massimo 7000 caratteri             |
| `image_url` | `image_url.url` | `first_frame`     | Immagine di primo fotogramma; se c'è solo un'immagine e `role` è omesso, viene trattata come primo fotogramma         |
| `image_url` | `image_url.url` | `last_frame`      | Immagine di fotogramma finale; può essere utilizzata singolarmente o combinata con `first_frame` per controllare inizio e fine |
| `image_url` | `image_url.url` | `reference_image` | Immagine di riferimento per soggetti, personaggi, prodotti, abbigliamento, scene o stili                    |
| `video_url` | `video_url.url` | `reference_video` | Video di riferimento per azioni, movimenti di camera, performance o struttura di montaggio                        |
| `audio_url` | `audio_url.url` | `reference_audio` | Audio di riferimento per tonalità, dialoghi, musica o ritmo                          |

Gli indirizzi dei media supportano tre forme:

- URL HTTPS accessibili pubblicamente, raccomandati per file di grandi dimensioni.
- `mm_file://{file_id}`, per riferirsi a file già caricati o risultati esistenti.
- URI data Base64 corrispondenti al tipo di media. Il Base64 aumenterà il volume di circa un terzo, assicurati che l'intero corpo della richiesta non superi i 64 MB.

## Specifiche e limiti dei materiali
| Materiale | Formato                                      | Limite di file singolo | Dimensione / Durata                                                  | Limite di quantità                     |
| --- | ------------------------------------------- | --------- | --------------------------------------------------------------- | --------------------------- |
| Immagine | JPG, JPEG, PNG, WEBP, HEIC, HEIF                 | Non oltre 30 MB | Larghezza e altezza da 256 a 5760 px; rapporto d'aspetto 0.4-2.5 | Massimo 1 immagine di primo piano, massimo 1 immagine di coda, massimo 9 immagini di riferimento |
| Video    | MP4, MOV; H.264/AVC o H.265/HEVC; traccia audio AAC o MP3 | Non oltre 50 MB | Ogni segmento da 2 a 15 secondi, totale non oltre 15 secondi; larghezza e altezza da 256 a 5760 px; rapporto d'aspetto 0.4-2.5; 23.976-60 fps | Massimo 3 segmenti di video di riferimento |
| Audio    | WAV, MP3                                     | Non oltre 15 MB | Ogni segmento da 2 a 15 secondi, totale non oltre 15 secondi       | Massimo 3 segmenti di audio di riferimento |

Nel contesto di riferimento multimodale, il numero totale di file di immagini, video e audio è al massimo 12. Le scene di primo e ultimo fotogramma e le scene di materiale di riferimento sono mutualmente esclusive: una volta utilizzato `reference_image`, `reference_video` o `reference_audio`, non è possibile utilizzare `first_frame` o `last_frame`, e viceversa.

## Dimostrazione delle capacità di produzione

Di seguito non ci sono immagini concettuali o materiali di riempimento, ma input di riferimento reali e output video effettivi delle capacità di produzione ufficiali di MiniMax H3. Tre gruppi di casi coprono rispettivamente brevi filmati di marca, narrazioni dal vivo e moda e-commerce, adatti per valutare le capacità più critiche del modello nella produzione commerciale.

| Capacità       | Osservazioni chiave                  |
| -------- | --------------------------- |
| Coerenza di persone e volti | Stabilità di tratti, acconciature, trucco e personalità dopo il cambio di inquadratura |
| Performance facciale     | Espressioni oculari, micro-espressioni, tensione emotiva e movimenti naturali della testa in primo piano |
| Mantenimento della struttura del prodotto   | Contorni, materiali, relazioni di indossamento e riflessi di prodotti come occhiali e borse   |
| Esecuzione visiva del marchio   | Coerenza dell'atmosfera della scena, grana cinematografica, colori, logo e ritmo di montaggio |
| Narrazione cinematografica    | Cambi di inquadratura, disposizione dei personaggi, movimenti di camera, ritmo e suono possono formare un paragrafo completo  |

Qui la "capacità facciale" si riferisce alla coerenza dell'aspetto dei personaggi, ai dettagli facciali e al controllo delle performance nella generazione video, non all'identificazione, al confronto facciale o alle interfacce di cambio faccia.

## Video generato da testo

Quando c'è solo un elemento di testo, si tratta di un video generato da testo. Adatto per generare immagini direttamente da idee, copioni o descrizioni di riprese. Le parole chiave possono essere organizzate nell'ordine "soggetto + azione + scena + inquadratura + luce + suono".

```bash
curl -X POST 'https://api.acedata.cloud/minimax/videos' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MiniMax-H3",
    "content": [
      {
        "type": "text",
        "text": "Pubblicità di profumo di livello cinematografico di 15 secondi: su una scogliera nera al mattino, una bottiglia di profumo trasparente è circondata da nebbia e onde del mare. Macro che mostra le gocce d'acqua sulla bottiglia e la rifrazione del vetro, la telecamera si allontana lentamente dal primo piano del prodotto fino all'ampia superficie del mare; tonalità argento-blu, luce naturale reale, alta classe e controllo, finale che fissa il prodotto."
      }
    ],
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }'
```

La modalità sincrona predefinita restituirà il compito completo al termine della generazione:

```json
{
  "task": {
    "id": "f5977217-ed2c-40da-adbe-93d08235618f",
    "model": "MiniMax-H3",
    "status": "succeeded",
    "content": { "url": "https://cdn.acedata.cloud/minimax/f5977217.mp4" },
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }
}
```

Se nella richiesta viene aggiunto `"async": true`, l'interfaccia restituirà immediatamente:

```json
{
  "task_id": "f5977217-ed2c-40da-adbe-93d08235618f",
  "trace_id": "trace_7f8c2b1a"
}
```

## Video generato da immagine di primo fotogramma

Contrassegnare l'immagine come `first_frame`, il modello inizierà a generare da quell'immagine. Adatto per far muovere naturalmente poster, immagini di prodotto, immagini di personaggi e opere fotografiche.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "Il personaggio respira naturalmente e guarda fuori dalla finestra, l'orlo dei vestiti è mosso da una leggera brezza, la telecamera avanza lentamente"
    },
    {
      "type": "image_url",
      "image_url": {
        "url": "https://cdn.acedata.cloud/b1c82e4937.png"
      },
      "role": "first_frame"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

## Video di fotogramma finale e di primo e ultimo fotogramma
只提供 `last_frame` può far sì che il modello generi naturalmente fino al fotogramma specificato; fornendo sia `first_frame` che `last_frame`, è possibile controllare chiaramente il punto di partenza e di arrivo. Adatto per transizioni, cambiamenti di forma, processi di crescita o confronti prima e dopo del prodotto.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "La ragazza cresce naturalmente dall'infanzia all'età adulta, il tempo scorre in modo fluido, il personaggio rimane sempre al centro dell'immagine"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_FIRST_FRAME_URL" },
      "role": "first_frame"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_LAST_FRAME_URL" },
      "role": "last_frame"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

Le dimensioni e il rapporto di aspetto del primo e dell'ultimo fotogramma dovrebbero essere il più possibile coerenti, la posizione del soggetto, la composizione e le differenze di luce non dovrebbero essere troppo grandi, in modo da ottenere una transizione naturale più facilmente.

## Riferimenti video multimodali

I materiali di riferimento possono essere utilizzati in combinazione: le immagini di riferimento controllano l'aspetto del personaggio o del prodotto, i video di riferimento controllano le azioni e i movimenti della camera, gli audio di riferimento controllano il tono dei dialoghi, la musica o il ritmo del montaggio. Nella descrizione devono essere specificati chiaramente cosa deve controllare ogni tipo di materiale, evitando di caricare solo materiali senza fornire relazioni.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "Mantenere coerenti i tratti del viso, l'acconciatura e l'abbigliamento del personaggio di riferimento, completare il video di moda secondo le azioni di performance nel video di riferimento; il ritmo della camera segue l'audio di riferimento, i primi piani evidenziano le espressioni facciali naturali"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_CHARACTER_IMAGE_URL" },
      "role": "reference_image"
    },
    {
      "type": "video_url",
      "video_url": { "url": "YOUR_PERFORMANCE_VIDEO_URL" },
      "role": "reference_video"
    },
    {
      "type": "audio_url",
      "audio_url": { "url": "YOUR_AUDIO_URL" },
      "role": "reference_audio"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

## Notifiche di callback

Passando `callback_url` si attiva automaticamente la modalità asincrona: l'interfaccia di creazione restituisce immediatamente `task_id` e `trace_id`, e dopo il completamento del compito invia un POST al suddetto indirizzo con il risultato finale, la struttura è la stessa della risposta alla query del compito.

Lo stato finale nel callback è `succeeded`, `failed` o `cancelled`. Anche se si utilizza il callback, è consigliabile salvare `task_id`, per poter effettuare query attive o compensare eventuali notifiche perse.

## Errori comuni

| Codice di stato HTTP | Significato           | Suggerimenti per la gestione                           |
| ------------------- | -------------------- | ----------------------------------------------------- |
| `400`               | Errore nei parametri o combinazione di materiali non valida | Controllare i campi obbligatori, `role`, numero e formato dei materiali |
| `401`               | Token mancante o non valido  | Controllare `Authorization: Bearer ...`              |
| `402`               | Saldo o credito insufficiente      | Aggiungere saldo generale nella console                |
| `422`               | Controllo di sicurezza dei contenuti non superato    | Regolare la descrizione o i materiali e ripresentare                  |
| `429`               | Richiesta troppo frequente       | Ritentare dopo un'esponenziale attesa; si consiglia un intervallo di circa 10 secondi per il polling delle attività         |
| `500`               | Servizio temporaneamente non disponibile      | Conservare le informazioni della richiesta, riprovare più tardi                    |

Lo stato `task.status: succeeded` nella risposta sincrona indica che il video è stato generato; la conferma asincrona rappresenta solo che il compito è entrato in coda. Solo quando il compito ha successo verrà addebitato, la query del compito stesso è gratuita e non comporta addebiti ripetuti.
