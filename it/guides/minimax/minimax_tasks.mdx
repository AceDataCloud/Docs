Questo documento descrive l'integrazione e l'uso dell'API di query delle attività di MiniMax H3. Questa interfaccia è utilizzata per interrogare, elencare in batch o eliminare attività asincrone create dall'[API di generazione video MiniMax H3](/documents/minimax-videos-integration).

## Processo di richiesta

Per utilizzare l'API di query delle attività di MiniMax H3, prima di tutto vai al [Pannello di controllo di Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da conservare per uso futuro.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato il login o registrato, verrai automaticamente reindirizzato alla pagina di login che ti invita a registrarti e accedere; una volta completato, verrai riportato automaticamente alla pagina corrente.

**Un API Token è sufficiente per accedere a tutti i servizi della piattaforma, non è necessario richiederne uno separato per ogni servizio.** La prima richiesta include un credito gratuito, per un'esperienza senza costi; quando il credito è insufficiente, puoi ricaricare il saldo generale nel [pannello di controllo](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [API di query delle attività di MiniMax H3 →](https://platform.acedata.cloud/documents/minimax-tasks-integration)

Quando interroghi un'attività, dovresti utilizzare lo stesso Token che ha creato quell'attività. Si consiglia di salvare il Token come variabile d'ambiente, evitando di scriverlo nel codice sorgente o di inviarlo al repository:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Panoramica dell'interfaccia

- **Base URL**: `https://api.acedata.cloud`
- **Endpoint**: `POST /minimax/tasks`
- **Metodo di autenticazione**: Porta `authorization: Bearer {token}` nell'header HTTP
- **Intestazione della richiesta**:
  - `accept: application/json`
  - `content-type: application/json`
- **Interrogare un'attività singola**: `action=retrieve`, passando `id`
- **Interrogare attività in batch**: `action=retrieve_batch`, filtrando per ID attività, intervallo di tempo e condizioni di paginazione
- **Eliminare un'attività**: `action=delete`, passando `id`
- **Informazioni di fatturazione**: L'interrogazione delle attività è gratuita e non comporta costi ripetuti

Dopo aver creato un video, è necessario salvare `task_id`. Si consiglia di interrogare ogni circa 10 secondi, fino a quando l'attività non entra in uno stato finale.

## Parametri della richiesta

| Parametro            | Tipo      | Obbligatorio | Azione applicabile         | Descrizione                                           |
| ------------------- | --------- | ------------ | -------------------------- | ---------------------------------------------------- |
| `action`            | string    | No           | Tutte                     | `retrieve`, `retrieve_batch` o `delete`; predefinito `retrieve` |
| `id`                | string    | Obbligatorio in condizioni | `retrieve`, `delete` | ID di un'attività singola                             |
| `ids`               | string[]  | No           | `retrieve_batch`          | Restituisce solo gli ID delle attività specificate; se omesso, elenca le attività in base ad altre condizioni |
| `limit`             | integer   | No           | `retrieve_batch`          | Numero massimo di attività da restituire in questa richiesta |
| `offset`            | integer   | No           | `retrieve_batch`          | Numero di attività da saltare nella lista dei risultati, utilizzato per la paginazione |
| `created_at_min`    | number    | No           | `retrieve_batch`          | Limite inferiore di creazione, timestamp Unix, in secondi |
| `created_at_max`    | number    | No           | `retrieve_batch`          | Limite superiore di creazione, timestamp Unix, in secondi |

Le tre azioni hanno i seguenti scopi:

| `action`            | Scopo                          | Parametri necessari                  | Struttura della risposta                          |
| ------------------- | ------------------------------ | ------------------------------------ | ------------------------------------------------ |
| `retrieve`          | Interrogare lo stato e il risultato di un'attività | `id`                                | `{ "task": {...} }`                             |
| `retrieve_batch`    | Interrogare in batch per ID attività, tempo e condizioni di paginazione | Opzionali `ids`, intervallo di tempo, `offset`, `limit` | `{ "items": [...], "total": number }`          |
| `delete`            | Annullare o eliminare un'attività in base allo stato attuale | `id`                                | `{ "id": "...", "deleted": true }`             |

## Interrogare un'attività singola

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f5977217-ed2c-40da-adbe-93d08235618f"
  }'
```

Di seguito è riportata una risposta reale di un'attività riuscita:

```json

  "task": {
    "id": "f5977217-ed2c-40da-adbe-93d08235618f",
    "model": "MiniMax-H3",
    "status": "succeeded",

    "updated_at": 1786184758,
    "content": {
      "url": "https://platform2.cdn.acedata.cloud/minimax/f5977217-ed2c-40da-adbe-93d08235618f.mp4"
```

## Stato dell'attività

| `status`    | Significato                     | Elaborazione del client            |
| ----------- | ------------------------------- | ---------------------------------- |
| `queued`    | In coda, in attesa di esecuzione | Continua a interrogare              |
| `running`   | In fase di generazione          | Continua a interrogare              |
| `succeeded` | Generazione riuscita            | Leggi `task.content.url`, ferma l'interrogazione |
| `failed`    | Generazione fallita             | Leggi `task.error`, ferma l'interrogazione |
| `cancelled` | Attività annullata              | Ferma l'interrogazione              |

`succeeded`, `failed` e `cancelled` sono tutti stati finali. Non continuare a interrogare dopo essere entrati in uno stato finale.

## Campi di risposta del task

| Campo                      | Tipo     | Descrizione                                      |
| ------------------------- | -------- | ------------------------------------------------ |
| `id`                      | string   | ID dell'attività                                 |
| `model`                   | string   | Modello utilizzato per l'attività, attualmente `MiniMax-H3` |
| `status`                  | string   | Stato attuale dell'attività                      |
| `error.code`              | string   | Codice di errore in caso di fallimento, restituito solo in caso di errore |
| `error.message`           | string   | Motivo del fallimento, restituito solo in caso di errore |
| `created_at`              | integer  | Data di creazione, timestamp Unix, in secondi    |
| `updated_at`              | integer  | Ultimo aggiornamento dello stato, timestamp Unix, in secondi |
| `content.url`             | string   | Indirizzo del video dopo il successo             |
| `resolution`              | string   | Risoluzione di output, `768P` o `2K`             |
| `duration`                | integer  | Durata del video di output, in secondi           |
| `usage.total_seconds`     | integer  | Quantità totale di costi, pari alla somma dei secondi del video di input e output |
| `usage.input_seconds`     | integer  | Quantità di costi generati dal video di input     |
| `usage.output_seconds`    | integer  | Quantità di costi generati dal video di output    |
| `usage.input_image_count` | integer  | Numero di immagini di input nel conteggio dei costi |
| `ratio`                   | string   | Rapporto di aspetto effettivo; quando si utilizza `adaptive`, fare riferimento a questo risultato |
| `task_type`               | string   | L'attività di generazione video è `generation`   |
| `modality`                | string   | L'attività video è `video`                        |

## Esempio completo di polling in Python
以下代码从环境变量读取 Token，创建任务后每隔 10 秒查询一次：

```python
import os
import time

import requests

BASE_URL = "https://api.acedata.cloud"
HEADERS = {
    "Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_KEY']}",
    "Content-Type": "application/json",
}

create_response = requests.post(
    f"{BASE_URL}/minimax/videos",
    headers=HEADERS,
    json={
        "model": "MiniMax-H3",
        "content": [
            {
                "type": "text",
                "text": "Al mattino, vicino al mare, una vela bianca attraversa la superficie calma dell'acqua, la telecamera si sposta lentamente.",
            }
        ],
        "resolution": "768P",
        "duration": 4,
        "ratio": "16:9",
    },
    timeout=30,
)
create_response.raise_for_status()
task_id = create_response.json()["task_id"]

while True:
    time.sleep(10)
    query_response = requests.post(
        f"{BASE_URL}/minimax/tasks",
        headers=HEADERS,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    query_response.raise_for_status()
    task = query_response.json()["task"]
    print(f"task={task_id} status={task['status']}")

    if task["status"] == "succeeded":
        print(f"video_url={task['content']['url']}")
        break
    if task["status"] in ("failed", "cancelled"):
        raise RuntimeError(task.get("error") or task["status"])
```

Produzione dovrebbe avere un timeout totale per il polling e utilizzare il backoff esponenziale per `429` e temporanei `5xx`. Un timeout di rete non equivale a un fallimento della generazione, è possibile continuare a interrogare utilizzando lo stesso `task_id`.

## Query in batch

Specificare più ID di attività:

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve_batch",
    "ids": ["TASK_ID_1", "TASK_ID_2"],
    "offset": 0,
    "limit": 20
  }'
```

Elencare le attività per intervallo di tempo con paginazione:

```json
{
  "action": "retrieve_batch",
  "created_at_min": 1786000000,
  "created_at_max": 1786200000,
  "offset": 0,
  "limit": 20
}
```

Nella risposta batch, `items` utilizza gli stessi campi di task della query singola, `total` è il numero totale di attività che corrispondono ai criteri di filtro:

```json
{
  "items": [
    {
      "id": "TASK_ID_1",
      "model": "MiniMax-H3",
      "status": "running",
      "resolution": "2K",
      "duration": 5,
      "ratio": "adaptive",
      "task_type": "generation",
      "modality": "video"
    }
  ],
  "total": 1
}
```

La finestra di query delle attività è di 7 giorni. Gli `task_id` che superano questa finestra potrebbero restituire attività non valide; il sistema aziendale dovrebbe salvare l'ID al momento della creazione dell'attività e persistente tempestivamente l'URL del risultato dopo il successo.

## Annullare o eliminare attività

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "delete",
    "id": "YOUR_TASK_ID"
  }'
```

L'azione dipende dallo stato attuale dell'attività:

| Stato attuale   | Comportamento                     |
| --------------- | --------------------------------- |
| `queued`        | Annulla attività non ancora iniziata |
| `succeeded`     | Elimina la registrazione dell'attività |
| `failed`        | Elimina la registrazione dell'attività |
| `running`       | Non è consentito eliminare o annullare, restituisce errore |
| `cancelled`     | Non è consentita l'operazione ripetuta, restituisce errore |

Esempio di eliminazione riuscita:

```json
{
  "id": "YOUR_TASK_ID",
  "deleted": true
}
```

L'eliminazione della registrazione dell'attività non annulla la fatturazione già completata e non garantisce che le copie video salvate vengano eliminate contemporaneamente.

## Risposte di errore e risoluzione dei problemi

Le attività fallite restituiscono comunque un oggetto task con HTTP 200 e forniscono il motivo in `task.error`:

```json
{
  "task": {
    "id": "YOUR_TASK_ID",
    "model": "MiniMax-H3",
    "status": "failed",
    "error": {
      "code": "1026",
      "message": "la descrizione del video contiene contenuti sensibili"
    },
    "task_type": "generation",
    "modality": "video"
  }
}
```

Se l'interfaccia restituisce `400`, controllare `action` e i parametri di condizione; `401` indica che il Token non è valido, `429` indica che le query sono troppo frequenti, `500` indica che il servizio è temporaneamente non disponibile. Le attività fallite non vengono fatturate; le attività riuscite registrano l'uso in base all'ultimo `usage`.
