La funzione principale dell'API Grok Tasks è quella di interrogare lo stato di esecuzione di un'attività tramite l'ID attività generato dall'API Grok Videos Generation.

Questo documento fornisce una guida dettagliata per l'integrazione dell'API Grok Tasks, aiutandovi a integrare facilmente e a interrogare lo stato di esecuzione delle attività dell'API Grok Videos Generation.

## Procedura di richiesta

Per utilizzare l'API Grok Tasks, è necessario prima richiedere il servizio corrispondente alla pagina [Grok Videos Generation API](https://platform.acedata.cloud/documents/grok-videos) e copiare l'ID attività restituito dall'API Grok Videos Generation.

Successivamente, accedere alla pagina [Grok Tasks API](https://platform.acedata.cloud/documents/grok-tasks) per richiedere il servizio corrispondente; una volta entrati nella pagina, cliccare sul pulsante "Acquire".

Se non si è ancora effettuato l'accesso o la registrazione, si verrà automaticamente reindirizzati alla [pagina di login](https://platform.acedata.cloud) per registrarsi e accedere; dopo il login o la registrazione, si tornerà automaticamente alla pagina corrente.

Alla prima richiesta viene offerto un credito gratuito, che consente di utilizzare l'API senza costi.

## Esempio di richiesta

L'API Grok Tasks può essere utilizzata per interrogare i risultati dell'API Grok Videos Generation.

### Impostazione delle intestazioni e del corpo della richiesta

**Request Headers** includono:

- `accept`: specifica che si accetta una risposta in formato JSON, da impostare su `application/json`.
- `authorization`: la chiave API per chiamare l'API, selezionabile direttamente dal menu a tendina dopo la richiesta.

**Request Body** include:

- `id`: l'ID dell'attività da interrogare.
- `action`: il tipo di operazione sull'attività, per una singola interrogazione impostare `retrieve`.

### Esempio di codice CURL

```bash
curl -X POST 'https://api.acedata.cloud/grok/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### Esempio di risposta

Se la richiesta ha successo, l'API restituirà i dettagli dell'attività. Il campo `request` contiene il corpo della richiesta originaria, mentre il campo `response` contiene il corpo della risposta al completamento dell'attività, ad esempio:

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "request": {
    "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
    "model": "grok-imagine-video-1.5-fast",
    "resolution": "480p",
    "duration": 8
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "grok-imagine-video-1.5-fast:41eb9a5f-3b2d-4d1e-9f5a-6c2f1a0b9e77",
        "video_url": "https://cdn.acedata.cloud/c8cbf53aa0.mp4",
        "state": "succeeded"
      }
    ]
  }
}
```

Descrizione dei campi:

- `id`: ID dell'attività generata, utilizzato per identificare univocamente l'attività.
- `request`: informazioni della richiesta dell'attività interrogata.
- `response`: informazioni della risposta dell'attività interrogata.

## Operazioni di interrogazione batch

Per interrogare i dettagli di più attività contemporaneamente, impostare `action` su `retrieve_batch` e passare un array di ID attività tramite `ids`:

**Request Body** include:

- `ids`: array degli ID delle attività da interrogare.
- `action`: tipo di operazione sulle attività, per interrogazione batch impostare `retrieve_batch`.

```bash
curl -X POST 'https://api.acedata.cloud/grok/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```
