Questo articolo presenterà un metodo di integrazione dell'API Flux Images Generation, che può generare immagini ufficiali Flux inserendo parametri personalizzati.

## Processo di richiesta

Per utilizzare l'API Flux Images Generation, per prima cosa vai alla [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da conservare come backup.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato l'accesso o non ti sei registrato, verrai automaticamente reindirizzato alla pagina di accesso che ti inviterà a registrarti ed effettuare l'accesso; al termine, tornerai automaticamente alla pagina corrente.

**Un solo API Token può chiamare tutti i servizi della piattaforma, senza doverne richiedere uno separatamente per ogni servizio.** Alla prima richiesta verrà assegnato credito gratuito, utilizzabile per una prova gratuita; quando il credito non è sufficiente, puoi ricaricare il saldo generale dalla [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Utilizzo di base

Per prima cosa, vediamo il metodo di utilizzo di base: inserendo il prompt `prompt`, l'azione di generazione `action` e la dimensione dell'immagine `size`, puoi ottenere il risultato elaborato. Per prima cosa devi semplicemente passare un campo `action`, il cui valore è `generate`, quindi dobbiamo anche inserire il prompt; i contenuti specifici sono i seguenti:

<p><img src="https://cdn.acedata.cloud/wz85jt.png" width="500" className="m-auto" /></p>

Qui possiamo vedere che abbiamo impostato i Request Headers, inclusi:

- `accept`: il formato del risultato della risposta che si desidera ricevere; qui viene compilato come `application/json`, ovvero in formato JSON.
- `authorization`: la chiave per chiamare l'API, che può essere selezionata direttamente dal menu a discesa dopo la richiesta.

Sono inoltre impostati i Request Body, inclusi:

- `action`: l'azione di questa attività di generazione immagini.
- `size`: la dimensione del risultato della generazione dell'immagine. **Le serie `flux-2-flex` / `flux-2-pro` / `flux-2-max` devono ricevere le proporzioni dell'immagine (ad esempio `1:1`, `16:9`) e non accettano dimensioni in pixel come `1024x1024`; se omesso, verrà restituito 400.**
- `count`: il numero di immagini da generare; il valore predefinito è 1. Questo parametro è valido solo per le attività di generazione immagini e non è valido per le attività di modifica.
- `prompt`: il prompt.
- `model`: il modello di generazione, con valore predefinito `flux-dev`; gli ultimi modelli di punta sono `flux-2-pro`, `flux-2-max` (qualità dell'immagine più alta, da utilizzare con la proporzione dell'immagine `size`).
- `callback_url`: l'URL che deve ricevere il risultato della callback.
- `async`: opzionale; quando impostato su `true`, l'interfaccia restituisce immediatamente `task_id`, senza dover fornire `callback_url`, e successivamente il risultato viene ottenuto tramite polling attraverso la corrispondente interfaccia di query dell'attività.

Il parametro `size` presenta alcune limitazioni particolari, suddivise principalmente in due tipi: rapporto larghezza x altezza `width x height` e proporzione dell'immagine `x:y`; i dettagli sono i seguenti:

| Modello               | Intervallo                                         |
| ---------------- | ------------------------------------------ |
| flux-dev         | Supporta il rapporto larghezza-altezza 1024x1024, 1024x1792, 1792x1024, oppure la proporzione dell'immagine |
| flux-pro         | Supporta il rapporto larghezza-altezza 1024x1024, 1024x1792, 1792x1024, oppure la proporzione dell'immagine |
| flux-2-flex      | Supporta solo la proporzione dell'immagine                                    |
| flux-2-pro       | Supporta solo la proporzione dell'immagine                                    |
| flux-2-max       | Supporta solo la proporzione dell'immagine                                    |
| flux-kontext-pro | Supporta solo la proporzione dell'immagine                                    |
| flux-kontext-max | Supporta solo la proporzione dell'immagine                                    |

Proporzioni di immagini di riferimento: "21:9", "16:9", "4:3", "3:2", "1:1", "2:3", "3:4", "9:16", "9:21".

Dopo aver selezionato i parametri, il codice corrispondente verrà generato automaticamente sul lato destro. Prima di copiare, assicurati che l'header di autorizzazione utilizzi la tua API Key; la documentazione e gli screenshot non devono contenere credenziali reali.

Fai clic sul pulsante «Try» per effettuare il test; qui abbiamo ottenuto il seguente risultato:

```json
{
  "success": true,
  "task_id": "5456c749-3bbb-4f10-9eb8-cfbcac297500",
  "trace_id": "ae4eecb8-1dd6-45b4-bfb3-a1c48872536e",
  "data": [
    {
      "image_url": "https://cdn.acedata.cloud/assets/examples/flux/5456c749-3bbb-4f10-9eb8-cfbcac297500-d0ef60485f73.jpg"
    }
  ]
}
```

Il risultato restituito contiene più campi, descritti come segue:

- `success`, lo stato dell'attività di generazione video in questo momento.
- `task_id`, l'ID dell'attività di generazione video in questo momento.
- `trace_id`, l'ID di tracciamento della generazione video in questo momento.
- `data`, l'elenco dei risultati dell'attività di generazione immagini in questo momento.
  - `image_url`, il link dell'attività di generazione immagini in questo momento.
  - `prompt`, il prompt.

Possiamo vedere che abbiamo ottenuto informazioni soddisfacenti sull'immagine; dobbiamo solo ottenere l'immagine Flux generata in base all'indirizzo del link dell'immagine in `data` nel risultato.

Inoltre, se vuoi generare il codice di integrazione corrispondente, puoi copiarlo direttamente, ad esempio il codice CURL è il seguente:

```shell
curl -X POST 'https://api.acedata.cloud/flux/images' \
-H 'authorization: Bearer {token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "A photorealistic studio product shot of a frosted-glass perfume bottle on wet black slate, single softbox key light, water droplets, dark moody background, 85mm macro.",
  "model": "flux-2-pro",
  "size": "1:1"
}'
```

## Attività di modifica delle immagini

Se desideri modificare una determinata immagine, prima di tutto il parametro `image_url` deve includere il link dell'immagine da modificare; in questo caso `action` supporta solo `edit`, quindi puoi specificare i seguenti contenuti:

- model: il modello utilizzato per questa attività di modifica immagini; supporta `flux-dev`, `flux-pro`, `flux-kontext-pro`, `flux-kontext-max`, `flux-2-flex`, `flux-2-pro`, `flux-2-max`.
- image_url: carica l'immagine da modificare.

Un esempio di compilazione è il seguente:

<p><img src="https://cdn.acedata.cloud/jn9da5.png" width="500" className="m-auto" /></p>

Dopo il completamento, il seguente codice è stato generato automaticamente:

<p><img src="https://cdn.acedata.cloud/6cwxb8.png" width="500" className="m-auto" /></p>

Il codice corrispondente:

```python
import requests

url = "https://api.acedata.cloud/flux/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "edit",
    "prompt": "a white siamese cat",
    "model": "flux-kontext-pro",
    "image_url": "https://cdn.acedata.cloud/ytj2qy.png"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Fai clic su esegui e potrai notare che otterrai immediatamente un risultato, come segue:

```json
{
  "success": true,
  "task_id": "2a7979ff-1f77-4380-92c6-a2dc37c3b4c8",
  "trace_id": "732b65c0-48d9-49f7-b568-64e5acffe4c0",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "timings": 1752744073
    }
  ]
}
```
Si può vedere che l'effetto generato è un effetto di modifica dell'immagine originale, e il risultato è simile a quanto sopra.

## Callback asincrono

Poiché il tempo di generazione della Flux Images Generation API è relativamente lungo, circa 1-2 minuti, se l'API non risponde per molto tempo, la richiesta HTTP manterrà continuamente la connessione, causando un consumo aggiuntivo di risorse di sistema, quindi questa API fornisce anche il supporto per il callback asincrono.

Il processo complessivo è: quando il client avvia una richiesta, specifica inoltre un campo `callback_url`, dopo che il client ha avviato la richiesta API, l'API restituirà immediatamente un risultato, contenente le informazioni del campo `task_id`, che rappresenta l'ID dell'attività corrente. Quando l'attività è completata, il risultato dell'immagine generata verrà inviato tramite POST JSON all'`callback_url` specificato dal client, includendo anch'esso il campo `task_id`, in modo che il risultato dell'attività possa essere associato tramite ID.

Di seguito capiremo come operare nello specifico attraverso un esempio.

Innanzitutto, il callback Webhook è un servizio in grado di ricevere richieste HTTP, gli sviluppatori dovrebbero sostituirlo con l'URL del server HTTP che hanno configurato autonomamente. Qui, per comodità di dimostrazione, viene utilizzato un sito Web di esempio Webhook pubblico https://webhook.site/; aprendo questo sito Web è possibile ottenere un URL Webhook, come mostrato nella figura:

![](https://cdn.acedata.cloud/cjjfly.png)

Copiare questo URL permette di utilizzarlo come Webhook; l'esempio qui è `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`.

Successivamente, possiamo impostare il campo `callback_url` sull'URL Webhook sopra indicato, compilando contemporaneamente i parametri corrispondenti; il contenuto specifico è mostrato nella figura:

<p><img src="https://cdn.acedata.cloud/wm6caw.png" width="500" className="m-auto" /></p>

Facendo clic su esegui, si può notare che verrà immediatamente ottenuto un risultato, come segue:

```
{
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c"
}
```

Dopo aver atteso un momento, possiamo osservare il risultato dell'immagine generata su `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`, come mostrato nella figura:

![](https://cdn.acedata.cloud/v23lot.png)

Il contenuto è il seguente:

```json

  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c",
  "trace_id": "9b4b1ff3-90f2-470f-b082-1061ec2948cc",
  "data": [
    {
      "prompt": "a white siamese cat",
```

Si può vedere che nel risultato è presente un campo `task_id`, mentre gli altri campi sono simili a quelli sopra; attraverso questo campo è possibile realizzare l'associazione dell'attività.

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice e il messaggio di errore corrispondenti. Ad esempio:

- `400 token_mismatched`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`：Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`：Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`：Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
