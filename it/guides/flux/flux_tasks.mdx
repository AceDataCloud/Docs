La funzione principale della Flux Tasks API è interrogare lo stato di esecuzione dell'attività tramite l'ID attività della piattaforma restituito dalla Flux Images Generation API o dalla Flux Videos API.

Questo documento presenterà in dettaglio le istruzioni di integrazione della Flux Tasks API, aiutandovi a integrare facilmente e a sfruttare pienamente le potenti funzionalità di questa API. Tramite la Flux Tasks API, potete facilmente implementare la consultazione dello stato di esecuzione delle attività della Flux Images Generation API.

Per un esempio completo di invio e polling di video, consultate la [Guida all'integrazione della Flux Videos API](https://platform.acedata.cloud/documents/flux-videos-integration). La consultazione delle attività esistenti non comporta costi di generazione aggiuntivi.

## Procedura di richiesta

Per utilizzare la Flux Images Generation API, prima ottenete il vostro API Token dalla [console di Ace Data Cloud](https://platform.acedata.cloud/console/applications) e conservatelo per uso successivo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non avete ancora effettuato l'accesso o la registrazione, verrete automaticamente reindirizzati alla pagina di accesso per invitarvi a registrarvi e ad accedere; una volta completato, tornerete automaticamente alla pagina corrente.

**Un solo API Token può chiamare tutti i servizi della piattaforma, senza doverne richiedere uno separatamente per ciascun servizio.** Alla prima richiesta verrà assegnato un credito gratuito, per poter provare gratuitamente; quando il credito è insufficiente, potete ricaricare il saldo universale dalla [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Esempio di richiesta

La Flux Tasks API può essere utilizzata per interrogare i risultati della Flux Images Generation API. Per come utilizzare la Flux Images Generation API, consultate la documentazione [Flux Images Generation API ](https://platform.acedata.cloud/documents/flux-images-integration).

Prendiamo come esempio un ID attività restituito dal servizio Flux Images Generation API, per dimostrare come utilizzare questa API. Supponiamo di avere un ID attività: 2db0168c-2373-4367-8d9a-9dc778802e8a, di seguito viene mostrato come tramite il passaggio di un ID attività.

### Impostare le intestazioni e il corpo della richiesta

Le **Request Headers** includono:

- `accept`: specifica di ricevere risultati di risposta in formato JSON, qui compilare con `application/json`.
- `authorization`: la chiave per chiamare l'API, dopo la richiesta può essere selezionata direttamente dal menu a discesa.

Il **Request Body** include:

- `id`: l'ID dell'attività caricata.
- `action`: la modalità di operazione sull'attività.

Le impostazioni sono mostrate nella figura seguente:

### Esempio di codice

Si può notare che vari codici in diverse lingue sono già stati generati automaticamente sul lato destro della pagina, come mostrato nella figura:

Alcuni esempi di codice sono i seguenti:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/flux/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/flux/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Il risultato restituito contiene diversi campi; il campo request è il request body al momento dell'avvio dell'attività, mentre il campo response è il response body restituito dopo il completamento dell'attività. La descrizione dei campi è la seguente.

- `id`, l'ID che genera questa attività immagine, utilizzato per identificare univocamente questa attività di generazione dell'immagine.
- `request`, le informazioni della richiesta nell'interrogazione dell'attività immagine.
- `response`, le informazioni di risposta nell'interrogazione dell'attività immagine.
- `created_at`, l'ora di creazione dell'attività, timestamp Unix (secondi, virgola mobile).
- `started_at`, l'ora di inizio dell'esecuzione dell'attività, timestamp Unix (secondi, virgola mobile).
- `finished_at`, l'ora di completamento dell'attività, timestamp Unix (secondi, virgola mobile). Questo campo non viene restituito quando l'attività non è completata.
- `elapsed`, il tempo impiegato per l'esecuzione dell'attività, in secondi (virgola mobile, con 3 cifre decimali). Questo campo non viene restituito quando l'attività non è completata.

## Gestione degli errori

Durante la chiamata dell'API, se si verifica un errore, l'API restituirà il codice e il messaggio di errore corrispondenti. Ad esempio:

- `400 token_mismatched`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`：Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`：Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`：Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore
