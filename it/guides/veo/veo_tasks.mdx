La principale funzionalità dell'API Veo Tasks è quella di interrogare lo stato di esecuzione di un'attività utilizzando l'ID dell'attività generato dall'API Veo Videos Generation.

Questo documento fornirà una guida dettagliata per l'integrazione dell'API Veo Tasks, aiutandoti a integrare facilmente e sfruttare appieno le potenti funzionalità di questa API. Con l'API Veo Tasks, puoi facilmente interrogare lo stato di esecuzione delle attività dell'API Veo Videos Generation.

## Processo di richiesta

Per utilizzare l'API Veo Tasks, è necessario prima andare alla pagina di richiesta [API Veo Videos Generation](https://platform.acedata.cloud/documents/63e01dc3-eb21-499e-8049-3025c460058f) per richiedere il servizio corrispondente, quindi copiare l'ID dell'attività dell'API Veo Videos Generation, come mostrato nell'immagine:

<p><img src="https://cdn.acedata.cloud/txlg6g.png" width="500" class="m-auto"></p>

Infine, accedi alla pagina dell'API Tasks [API Veo Tasks](https://platform.acedata.cloud/documents/52778f8b-93ce-4db3-a62c-bcf0a92e5f3c) per richiedere il servizio corrispondente. Una volta entrato nella pagina, fai clic sul pulsante "Acquire", come mostrato nell'immagine:

![Pagina di richiesta](https://cdn.acedata.cloud/rci31i.png)

Se non hai ancora effettuato il login o la registrazione, verrai automaticamente reindirizzato alla [pagina di login](https://platform.acedata.cloud) che ti invita a registrarti e accedere. Dopo aver effettuato il login o la registrazione, verrai automaticamente riportato alla pagina corrente.

Alla prima richiesta, verrà offerto un credito gratuito, che ti consente di utilizzare gratuitamente questa API.

## Esempio di richiesta

L'API Veo Tasks può essere utilizzata per interrogare i risultati dell'API Veo Videos Generation. Per informazioni su come utilizzare l'API Veo Videos Generation, fare riferimento al documento [API Veo Videos Generation](https://platform.acedata.cloud/documents/63e01dc3-eb21-499e-8049-3025c460058f).

Prendiamo come esempio un ID di attività restituito dal servizio API Veo Videos Generation e dimostriamo come utilizzare questa API. Supponiamo di avere un ID di attività: 1ebe4f2b-59ba-4385-a4ea-0ce8a3fe12ed, e ora dimostriamo come passare un ID di attività.

### Impostazione dell'intestazione della richiesta e del corpo della richiesta

**Request Headers** includono:

- `accept`: specifica di ricevere la risposta in formato JSON, qui si compila con `application/json`.
- `authorization`: la chiave per chiamare l'API, che può essere selezionata direttamente dopo la richiesta.

**Request Body** include:

- `id`: l'ID dell'attività caricata.
- `action`: il modo in cui operare sull'attività.

Impostato come mostrato nell'immagine seguente:

<p><img src="https://cdn.acedata.cloud/xztiqi.png" width="500" class="m-auto"></p>

### Esempio di codice

Si può notare che, sul lato destro della pagina, sono già stati generati automaticamente vari codici in diverse lingue, come mostrato nell'immagine:

Alcuni esempi di codice sono i seguenti:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/veo/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1ebe4f2b-59ba-4385-a4ea-0ce8a3fe12ed",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/veo/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "1ebe4f2b-59ba-4385-a4ea-0ce8a3fe12ed",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice di errore e le informazioni corrispondenti. Ad esempio:

- `400 token_mismatched`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`: Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`: Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`: Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`: Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
