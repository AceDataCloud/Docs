Questo articolo presenterà un metodo di integrazione dell'API SeeDance Videos Generation, che consente di generare video ufficiali SeeDance inserendo parametri personalizzati.

## Procedura di richiesta

Per utilizzare l'API SeeDance Videos Generation, innanzitutto vai alla [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token e conservarlo come riserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato l'accesso o la registrazione, verrai automaticamente reindirizzato alla pagina di accesso per essere invitato a registrarti e ad accedere; una volta completato, tornerai automaticamente alla pagina corrente.

**Un solo API Token può chiamare tutti i servizi della piattaforma, senza necessità di richiederne uno separato per ogni servizio.** Alla prima richiesta verrà assegnato un credito gratuito, che consente di provare il servizio gratuitamente; quando il credito è insufficiente, puoi ricaricare il saldo universale nella [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [SeeDance Videos Generation API →](https://platform.acedata.cloud/documents/seedance-videos)

## Utilizzo di base

Innanzitutto, comprendiamo il metodo di utilizzo di base: inserendo il prompt `content.text`, il tipo `content.type=text` e il modello `model`, è possibile ottenere il risultato elaborato; i dettagli specifici sono i seguenti:

<p><img src="https://cdn.acedata.cloud/seedance_parameters.png" width="500" className="m-auto" /></p>

Qui possiamo vedere che abbiamo impostato i Request Headers, inclusi:

- `accept`: il formato del risultato di risposta che si desidera ricevere; qui è impostato su `application/json`, ovvero il formato JSON.
- `authorization`: la chiave per chiamare l'API, che può essere selezionata direttamente dal menu a discesa dopo averla richiesta.

Sono inoltre impostati i Request Body, inclusi:

- `model`: il modello per generare video.
  - **Serie Seedance 1.x**: `doubao-seedance-1-0-pro-250528`, `doubao-seedance-1-0-pro-fast-251015`, `doubao-seedance-1-5-pro-251215`, `doubao-seedance-1-0-lite-t2v-250428`, `doubao-seedance-1-0-lite-i2v-250428`.
  - **Serie Seedance 2.0** (supporta riferimenti multimodali di personaggi e audio-video): `doubao-seedance-2-0-260128` (standard), `doubao-seedance-2-0-fast-260128` (veloce), `doubao-seedance-2-0-mini-260615` (leggero).
  - **Seedance 2.5**: `doubao-seedance-2-5-260628`, supporta fino a 30 secondi, riferimenti audio puri, più materiali, modifica ed estensione video.
- `content`: array di contenuti in input; `type` può essere `text` (prompt), `image_url` (immagine di riferimento), `audio_url` (audio di riferimento), `video_url` (video di riferimento). Le immagini possono specificare l'uso tramite `role`: `first_frame` (primo fotogramma) / `last_frame` (ultimo fotogramma) / `reference_image` (riferimento del personaggio / soggetto).
- `resolution`: risoluzione di output; opzionale `480p` / `720p` / `1080p` / `4k`. La 2.5 supporta 480p, 720p, 1080p; la 2.0 Fast/Mini supporta 480p, 720p; la 2.0 Standard supporta fino a 4k.
- `ratio`: rapporto d'aspetto; opzionale `16:9` / `4:3` / `1:1` / `3:4` / `9:16` / `21:9` / `adaptive`.
- `duration`: durata del video (secondi, numero intero). Serie 1.0 2–12; 1.5 Pro 4–12; serie 2.0 4–15; 2.5 4–30. La 1.5/2.x supporta `-1` (durata automatica).
- `seed`: seme casuale, numero intero, da -1 a 4294967295.
- `camerafixed`: se fissare la videocamera, `true` / `false`.
- `watermark`: se aggiungere una filigrana, `true` / `false`.
- `generate_audio`: se generare un video con audio, `true` / `false`, supportato da Seedance 1.5 Pro e dalla serie 2.x.
- `return_last_frame`: se restituire nell'output l'URL dell'immagine dell'ultimo fotogramma del video.
- `omni_reference_task_type`: solo 2.5; `auto` / `reference` / `edit` / `extend`.
- `output_format`: solo 2.5; `mp4` / `mov`, predefinito `mp4`.
- `tools`: solo 2.5; attualmente supporta lo strumento di ricerca online `web_search`, che può limitare il numero di risultati, il numero di parole chiave e le fonti di ricerca.
- `priority`: priorità del task opzionale per la 2.5, numero intero 0–9, predefinito 0.
- `safety_identifier`: identificatore stabile e anonimo dell'utente finale, lungo al massimo 64 caratteri; utilizza un hash o un ID anonimo interno, non inserire nome, e-mail o numero di telefono.
- `execution_expires_after`: tempo di timeout del task (secondi), intervallo 3600–259200.
- `callback_url`: indirizzo di callback asincrono; dopo l'impostazione, l'API restituisce immediatamente `task_id`, e al completamento del task invia il risultato tramite POST a questo indirizzo.
- `async`: opzionale; quando impostato su `true`, l'interfaccia restituisce immediatamente `task_id`, senza necessità di fornire `callback_url`; successivamente, il risultato viene ottenuto tramite polling attraverso la corrispondente interfaccia di query del task.

## Descrizione dei parametri inline

Alla fine del prompt `content[].text`, è possibile passare parametri di generazione aggiungendo nella forma `--parameter value` (modalità precedente, con convalida debole; se compilati in modo errato, vengono utilizzati automaticamente i valori predefiniti). L'elenco completo dei parametri è il seguente:

| Parametro inline       | Campo corrispondente              | Descrizione      | Intervallo di valori                                                          |
| ---------- | ----------------- | ------- | ------------------------------------------------------------- |
| `--rs`     | `resolution`      | Risoluzione di output   | `480p` / `720p` / `1080p`                                     |
| `--rt`     | `ratio`           | Rapporto d'aspetto     | `16:9` / `4:3` / `1:1` / `3:4` / `9:16` / `21:9` / `adaptive` |
| `--dur`    | `duration`        | Durata video (secondi) | 2–12                                                          |
| `--frames` | `frames`          | Numero di frame video    | Interi in [29, 289] che soddisfano 25+4n (**supportato solo dalla serie 1.0**)                       |
| `--fps`    | `framespersecond` | Frequenza dei fotogrammi      | Supporta solo `24`                                                      |
| `--seed`   | `seed`            | Seme casuale    | Da -1 a 4294967295                                               |
| `--cf`     | `camerafixed`     | Se la videocamera è fissa | `true` / `false`                                              |
| `--wm`     | `watermark`       | Se aggiungere una filigrana  | `true` / `false`                                              |

> **Pratica consigliata**: utilizzare direttamente i campi di primo livello corrispondenti nel Request Body (come `resolution`, `ratio`, ecc.). Questa è una modalità di convalida forte: se i parametri vengono compilati in modo errato, verrà restituito un messaggio di errore chiaro, rendendo più semplice l'individuazione dei problemi.

## Generazione di video con audio

Seedance 1.5 Pro e la serie 2.x supportano la generazione di video con audio tramite il parametro `generate_audio`:

```json
{
  "model": "doubao-seedance-1-5-pro-251215",
  "content": [
    {
      "type": "text",
      "text": "A girl holds a fox, the wind blows her hair, you can hear the sound of the wind"
    }
  ],
  "generate_audio": true,
  "ratio": "16:9",
  "duration": 5
}
```

La serie 1.0 non supporta questo parametro.

## Generazione, modifica ed estensione omnmodale di Seedance 2.5

`doubao-seedance-2-5-260628` supporta 480p / 720p / 1080p, 4–30 secondi o durata automatica, e aumenta il limite dei materiali a 30 immagini di riferimento, 10 video di riferimento e 10 audio di riferimento (per un totale massimo di 50). La versione 2.5 supporta inoltre il passaggio di solo audio di riferimento, senza più richiedere la fornitura simultanea di immagini o video.

Per la normale generazione omnmodale si può omettere `omni_reference_task_type`, impostarlo su `auto` oppure impostarlo esplicitamente su `reference`. Per la modifica e l'estensione video è necessario passare `reference_video`:

```json
{
  "model": "doubao-seedance-2-5-260628",
  "content": [
    {"type": "text", "text": "Replace the sky with a warm sunset while preserving the subject and camera motion."},
    {"type": "video_url", "role": "reference_video", "video_url": {"url": "https://cdn.acedata.cloud/input.mp4"}}
  ],
  "resolution": "720p",
  "ratio": "adaptive",
  "duration": -1,
  "omni_reference_task_type": "edit",
  "output_format": "mov"
}
```

- `reference`: passare almeno un `reference_image`, `reference_video` o `reference_audio`; la versione 2.5 supporta il passaggio di solo audio di riferimento.
- `edit`: è necessario utilizzare `ratio: adaptive` e `duration: -1`; la durata di output viene fatturata in base al risultato effettivo.
- `extend`: è necessario utilizzare `ratio: adaptive`; `duration` può essere 4–30 oppure `-1`.
- `auto`: il modello seleziona automaticamente la generazione, la modifica o l'estensione in base al prompt e ai materiali.
- Quando il tipo di attività non corrisponde ai materiali o al prompt, l'attività fallirà e restituirà un errore di parametro individuabile; modificare e inviare nuovamente secondo i vincoli sopra indicati.

## Primo fotogramma per video da immagine

Se si desidera un'attività di video da immagine, innanzitutto il parametro `content` deve includere un elemento con `type` pari a `image_url`, e il campo `image_url` deve essere in formato oggetto: `{"url": "https://..."}` oppure in formato Base64 `{"url": "data:image/png;base64,..."}`.

> **Nota**: `image_url` non supporta il passaggio diretto in formato stringa (come `"image_url": "https://cdn.acedata.cloud/e724d7f13d.png"`), è obbligatorio utilizzare il formato oggetto `"image_url": {"url": "https://..."}`, altrimenti verrà restituito un errore 400.

Il codice corrispondente:

```python
import requests

url = "https://api.acedata.cloud/seedance/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "content": [
        {
            "type": "image_url",
            "image_url": {
                "url": "https://ark-project.tos-cn-beijing.volces.com/doc_image/i2v_foxrgirl.png"
            }
        },
        {
            "type": "text",
            "text": "A girl holds a fox in her arms. She opens her eyes and gazes tenderly at the camera, while the fox affectionately holds her back. As the camera slowly pulls away, her hair is gently blown by the wind. --ratio adaptive  --dur 5"
        }
    ],
    "model": "doubao-seedance-1-0-pro-250528"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Fare clic per eseguire, e si può osservare che viene immediatamente ottenuto un risultato, come segue:

## Primo e ultimo fotogramma per video da immagine

Se si desidera il primo e l'ultimo fotogramma per un video da immagine, innanzitutto il parametro `content` deve passare il tipo `image_url`, e impostare rispettivamente `role` su `first_frame` e `last_frame`, così è possibile specificare i seguenti contenuti:

- role: specifica il primo fotogramma o l'ultimo fotogramma.
- image_url
  - url collegamento dell'immagine
    Allo stesso tempo, `content` deve anche inserire il tipo `text` come prompt

Il codice corrispondente:
```python
import requests

url = "https://api.acedata.cloud/seedance/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
   "model": "doubao-seedance-1-0-pro-250528",
    "content": [
         {
            "type": "text",
            "text": "360-degree shot"
        },
        {
            "type": "image_url",
            "image_url": {
                "url": "https://ark-project.tos-cn-beijing.volces.com/doc_image/seepro_first_frame.jpeg"
            },
            "role": "first_frame"
        },
        {
            "type": "image_url",
            "image_url": {
                "url": "https://ark-project.tos-cn-beijing.volces.com/doc_image/seepro_last_frame.jpeg"
            },
            "role": "last_frame"
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Riferimento multimodale di personaggi, audio e video (Seedance 2.0)

La **serie Seedance 2.0** (`doubao-seedance-2-0-260128`, `doubao-seedance-2-0-fast-260128`, `doubao-seedance-2-0-mini-260615`) supporta `reference_image`, `reference_audio` e `reference_video`. È possibile utilizzare materiali propri o autorizzati per mantenere la coerenza di personaggi, soggetti, movimenti, movimenti di camera, suoni e ritmo.

> Caricare solo materiali di persone reali e personaggi propri o autorizzati. I diversi modelli supportano in modi diversi i materiali di persone reali; il formato della richiesta rimane invariato e, se il materiale non soddisfa i requisiti, verrà restituito un errore esplicito.

Punti chiave di utilizzo:

- Solo i modelli della **serie Seedance 2.0** supportano `reference_image`; per i modelli 1.x utilizzare `first_frame` / `last_frame` (primo e ultimo fotogramma per immagini in video).
- Il primo fotogramma per immagini in video, il primo e ultimo fotogramma per immagini in video e il riferimento multimodale completo sono tre scenari mutuamente esclusivi: `first_frame` / `last_frame` non possono essere utilizzati insieme a `reference_image` / `reference_video` / `reference_audio`.
- Se si desidera specificare il primo e l'ultimo fotogramma nel riferimento multimodale completo, contrassegnare le immagini come `reference_image` e indicare nel prompt “immagine 1 come primo fotogramma” oppure “immagine 2 come ultimo fotogramma”; se è necessario bloccare rigorosamente il primo e l'ultimo fotogramma, utilizzare solo `first_frame` / `last_frame`.
- Limite del numero di riferimenti multimodali: fino a **9** `image_url`; la versione 2.0 supporta anche `audio_url` (`role` è `reference_audio`, fino a 3 elementi) e `video_url` (`role` è `reference_video`, fino a 3 elementi).
- **Requisiti dei materiali audio di riferimento (`audio_url`)**: formato `wav` / `mp3`; **durata di ogni elemento 2~15 secondi**, fino a 3 elementi e **durata totale non superiore a 15 secondi**; ogni elemento non deve superare 15 MB. Il superamento dell'intervallo di durata causerà un errore nella fase di elaborazione del materiale.
- **Requisiti dei materiali video di riferimento (`video_url`)**: formato `mp4` / `mov`; **durata di ogni elemento 2~15 secondi**, fino a 3 elementi e **durata totale non superiore a 15 secondi**.
- Per le immagini di riferimento, si consiglia di utilizzare foto **di una sola persona, frontali, nitide e senza ostruzioni**; più nitido è il volto, maggiore sarà la somiglianza.

### Esempio uno: primo piano che mantiene l'aspetto del personaggio

Passare una foto di un volto e fare in modo che quella persona sorrida e saluti la telecamera. Il codice corrispondente:

```python
import requests

url = "https://api.acedata.cloud/seedance/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedance-2-0-fast-260128",
    "content": [
        {
            "type": "text",
            "text": "The woman looks at the camera, gives a warm natural smile and waves her hand, soft studio lighting, gentle camera push-in."
        },
        {
            "type": "image_url",
            "role": "reference_image",
            "image_url": {
                "url": "https://cdn.acedata.cloud/assets/examples/nanobanana/8e075897-0f50-4443-8500-666751791c6c-4346f66287c0.jpg"
            }
        }
    ],
    "resolution": "480p",
    "ratio": "9:16",
    "duration": 5
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Callback asincrono

Poiché il tempo di generazione di SeeDance Videos Generation API è relativamente lungo (circa 1-2 minuti), è possibile utilizzare la modalità asincrona tramite il campo `callback_url`, evitando che la connessione HTTP rimanga occupata a lungo.

Flusso complessivo: il client specifica `callback_url` quando avvia la richiesta e l'API restituisce immediatamente una risposta contenente `task_id`; una volta completata l'attività, la piattaforma invia il risultato generato a `callback_url` sotto forma di POST JSON, e il risultato contiene anch'esso `task_id` per consentire l'associazione.

```json
{
  "task_id": "f7096c6c-9430-4392-8201-d259632d7afd"
}
```

Il campo `task_id` nel risultato corrisponde a quello restituito al momento della richiesta; tramite questo campo è possibile associare l'attività.

## Gestione degli errori

Durante la chiamata all'API, se si verifica un errore, l'API restituirà il codice e il messaggio di errore corrispondenti. Ad esempio:

- `400 token_mismatched`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`：Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`：Troppe richieste, è stato superato il limite di velocità.
- `500 api_error`：Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
