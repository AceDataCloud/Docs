Questo documento ha un solo obiettivo: permetterti di eseguire il primo comando Claude Code **in 5 minuti** usando il proxy AceData Cloud. Il tutorial completo è disponibile nelle sottosezioni dedicate ai vari IDE ([VS Code](https://platform.acedata.cloud/documents/claude-code-vscode-integrations) / [Cursor](https://platform.acedata.cloud/documents/claude-code-cursor-integration) / [JetBrains](https://platform.acedata.cloud/documents/claude-code-jetbrains-integrations)); qui seguiamo solo il percorso più rapido con **CLI da terminale** + **estensione VS Code**.

> **Perché usare AceData Cloud come proxy per Claude Code**:
> - Connessione diretta dalla Cina senza bisogno di VPN
> - Prezzi più bassi rispetto all’ufficiale (fatturazione a token sulla piattaforma)
> - La stessa chiave supporta sia Claude Messages API sia il protocollo Claude Code Token

## Minuto 1: Richiedere le credenziali

Apri la [pagina del servizio Claude Messages](https://platform.acedata.cloud/documents/claude-messages) e clicca sul pulsante "**Acquire**":

![](https://cdn.acedata.cloud/nyq0xz.png)

La piattaforma creerà automaticamente un’Application e ti regalerà un credito gratuito. Annota **Base URL** e **API Token** dalla pagina dei dettagli — ti serviranno per i prossimi 5 passaggi.

| Campo | Valore | Uso |
|-------|--------|-----|
| `BASE_URL` | `https://api.acedata.cloud/claude` | Endpoint compatibile Claude Messages |
| `API_TOKEN` | `sk-...` (copia dalla pagina dettagli) | Header di autenticazione compatibile Anthropic |

## Minuto 2: Installare Claude Code

macOS / Linux / WSL:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows (PowerShell nativo):

```powershell
irm https://claude.ai/install.ps1 | iex
```

Al termine dell’installazione, apri un nuovo terminale e verifica:

```bash
claude --version
```

> Se vedi il numero di versione, è tutto a posto. Claude Code include Node.js runtime integrato, non dipende dalla versione Node installata sulla tua macchina.

## Minuto 3: Puntare le variabili d’ambiente su AceData Cloud

Non usare il comando ufficiale `claude login`, ma sovrascrivi con variabili d’ambiente. Puoi scegliere una delle due modalità:

**Metodo A: Temporaneo (solo per la sessione shell corrente)**

```bash
export ANTHROPIC_BASE_URL="https://api.acedata.cloud/claude"
export ANTHROPIC_AUTH_TOKEN="sk-il-tuo-token"
```

**Metodo B: Persistente (consigliato)**

Aggiungi le due righe sopra a `~/.zshrc` o `~/.bashrc` e poi esegui `source` del file.

> **Errore comune**: la variabile si chiama `ANTHROPIC_AUTH_TOKEN`, non `ANTHROPIC_API_KEY`; se sbagli nome, Claude Code ricade sull’endpoint ufficiale e riceve errore 401.

## Minuto 4: Eseguire il primo comando

Entra in una qualsiasi cartella Git e digita:

```bash
claude
```

Se al primo avvio chiede di fare il login, premi `Esc` per saltare. Poi inserisci:

```
Elenca le dipendenze del progetto corrente e spiega brevemente a cosa servono.
```

Vedrai Claude usare strumenti come `read_file` / `glob` / `grep` per esplorare il repository e poi restituire la lista. Nella barra di stato in basso comparirà `connected to api.acedata.cloud` — questo è il segnale chiave che il proxy è attivo.

## Minuto 5: Collegare anche l’estensione VS Code

1. Apri VS Code → pannello Estensioni → cerca `Claude Code` e installa quella ufficiale Anthropic;
2. Premi **Cmd+Shift+P** → digita `Claude Code: Set Custom API Endpoint`;
3. Inserisci `https://api.acedata.cloud/claude` e premi Invio;
4. Esegui di nuovo `Claude Code: Set API Token` e inserisci il tuo Token.

Se tutto va bene, nella barra laterale apparirà il pannello Claude Code, potrai trascinare file per fare domande o usare `@-mention` per proporre modifiche. Tutti i costi saranno gestiti da AceData Cloud.

## Verifica che stai davvero usando il proxy

Nella chat di Claude Code scrivi:

```
Accedi a https://api.acedata.cloud/whoami e dimmi cosa restituisce
```

Se ricevi le informazioni del tuo account (`{user_id, plan, ...}`), significa che la richiesta passa davvero da AceData Cloud. Se invece viene mostrato un errore 401 su un dominio ufficiale, torna al minuto 3 e controlla il nome delle variabili d’ambiente.

## Le 5 domande più frequenti

**Q: Ho fatto `claude login` e poi ho cambiato le variabili d’ambiente per AceData, ma non funziona. Perché?**  
A: `claude login` scrive il token ufficiale in `~/.claude/.credentials.json`, che ha priorità sulle variabili d’ambiente. Elimina quel file e poi esegui `source ~/.zshrc`.

**Q: Posso usare modelli come `--model claude-opus-4-7`?**  
A: Sì. AceData Cloud passa il campo model così com’è, supportando tutti i modelli pubblici Anthropic più le nostre estensioni `claude-opus-4-7` / `claude-haiku-4-5` / `claude-sonnet-4-5`.

**Q: Posso configurare più profili (personale + lavoro)?**  
A: Sì. Claude Code supporta profili multipli in `~/.claude/settings.json`; oppure puoi definire due funzioni shell `claude_personal` / `claude_work` che esportano token diversi e poi chiamano `claude $@`.

**Q: Posso usare Claude Code in GitHub Actions?**  
A: Sì. Consulta la [guida all’integrazione GitHub Actions](https://platform.acedata.cloud/documents/claude-code-github-actions-integration).

**Q: Cosa succede quando finisco il credito gratuito?**  
A: Vai su [Gestione Applicazioni](https://platform.acedata.cloud/applications) → seleziona l’Application Claude → ricarica credito (paghi in base ai token consumati) oppure passa a un abbonamento a punti.
