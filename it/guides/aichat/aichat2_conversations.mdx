L'API AI Chat v2 (`/aichat2/conversations`) è una nuova generazione di interfaccia per le conversazioni ed è una versione completamente aggiornata dell'[API AI Chat](https://platform.acedata.cloud/documents/aichat-conversations). Sulla base della semplicità della v1 e della gestione delle conversazioni multi-turno, introduce le seguenti funzionalità:

- **Input utente multimodale**: consente di inviare direttamente testo + immagini + blocchi di file tramite il campo strutturato `message`, senza doverli allegare indirettamente utilizzando prima `references`.
- **Chiamate agli strumenti in modalità Agent**: include una serie di strumenti integrati per la ricerca online, il recupero di pagine web, la lettura di file e altre operazioni. Inoltre, è possibile collegare server MCP autorizzati dall'utente (Google Drive, Notion, Slack, GitHub ecc.). Il modello può richiamare autonomamente gli strumenti più volte all'interno di una singola richiesta per completare attività complesse.
- **Eventi di streaming strutturati**: tramite `accept: text/event-stream` oppure `application/x-ndjson` è possibile ricevere eventi token per token come `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` e altri, facilitando la visualizzazione separata dei diversi tipi di contenuto nel frontend.
- **Interruzione / ripresa**: quando il modello necessita di ulteriori informazioni da parte dell'utente, emette un evento `ask_user_question` e si mette in pausa. Nella richiesta successiva, è sufficiente reinserire la risposta tramite `tool_results` per continuare.
- **Nuove operazioni CRUD**: sullo stesso endpoint è possibile completare le operazioni `retrieve` / `retrieve_batch` / `update` / `delete` tramite il campo `action`, senza bisogno di API aggiuntive per la gestione delle conversazioni.
- **Elenco dei modelli in continuo aggiornamento**: per impostazione predefinita, sono disponibili modelli contemporanei come GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 e altri.

Allo stesso tempo, a livello del corpo della richiesta, è **completamente retrocompatibile con la v1**: è sufficiente trasmettere `model` + `question` (+ eventuali `stateful` / `id` / `references` / `preset`) per ottenere una risposta JSON `{answer, id}` equivalente a quella della v1. Pertanto, per migrare da `/aichat/conversations` non è necessario riscrivere il client: basta modificare il percorso in `/aichat2/conversations`.

> Se attualmente utilizzi `/aichat/conversations`, la vecchia interfaccia continuerà a essere disponibile. Puoi effettuare la migrazione secondo i tuoi tempi.

## Procedura di richiesta

Per utilizzare l'API AI Chat v2, accedi innanzitutto alla [console di Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token e conservarlo per un utilizzo successivo.

![]()

Se non hai ancora effettuato l'accesso o la registrazione, verrai reindirizzato automaticamente alla pagina di accesso, dove potrai registrarti ed effettuare il login. Al termine, tornerai automaticamente alla pagina corrente.

**Un solo API Token consente di utilizzare tutti i servizi della piattaforma, senza dover presentare una richiesta separata per ogni servizio.** Al momento della prima richiesta viene assegnata una quota gratuita che puoi utilizzare per provare il servizio senza costi. Quando la quota non è sufficiente, puoi ricaricare il saldo generale dalla [console](https://platform.acedata.cloud/console/coin).

## Utilizzo di base

L'utilizzo più semplice è esattamente lo stesso della v1: invia `model` + `question` e ricevi `{answer, id}`.

Esempio CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Risultato restituito:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Esempio Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

    "accept": "application/json",
    "authorization": "Bearer {token}",

## Conversazioni multi-turno

Come nella v1, imposta `stateful: true` per attivare il salvataggio delle conversazioni. L'API restituirà un `id`; nelle richieste successive sarà sufficiente includere lo stesso `id` per continuare la conversazione, senza dover gestire autonomamente lo storico dei messaggi.

Prima richiesta:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Risposta:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Seconda richiesta, includendo lo stesso `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` è `true` per impostazione predefinita; ometterlo ed esplicitare `true` sono equivalenti. Impostare `stateful: false` salta il caricamento della cronologia delle conversazioni precedenti; ciò non significa che il risultato di questo turno non verrà salvato e non è applicabile ai flussi di lavoro degli strumenti che richiedono una pausa e una successiva ripresa.

### Conversazioni lunghe e conservazione del testo originale

La compressione del contesto organizza soltanto il contenuto inviato al modello in questo turno, senza sostituire i messaggi di chat salvati. Tramite `action: retrieve` è ancora possibile leggere tutti i messaggi salvati; le modifiche e le eliminazioni esplicite delle conversazioni continuano ad avere effetto secondo la richiesta.

Il modello può cercare e leggere la cronologia originale della conversazione corrente in modo paginato. Quando è necessario continuare a modificare un articolo, citare numeri o preparare una pubblicazione, occorre leggere il testo originale corrispondente e non sostituire il contenuto integrale con un riepilogo. Questa funzionalità non ripristina automaticamente i messaggi già persi nelle versioni precedenti.

Se l'organizzazione del contesto non riesce, conserva l'ID della conversazione e controlla l'evento `error`; il servizio non sovrascriverà il testo originale con un riepilogo vuoto. Le operazioni degli strumenti già completate prima dell'errore potrebbero essere ancora valide: consulta prima i relativi risultati per evitare di generare o pubblicare contenuti duplicati. Quando una singola conversazione raggiunge il limite di archiviazione, verrà restituito un errore esplicito; lo spazio non verrà liberato eliminando parti dei record già salvati. Puoi esportare i contenuti necessari e poi avviare una nuova conversazione.

## Risposte in streaming

v2 supporta due formati di streaming, selezionabili tramite l'intestazione `accept`:

| Scenario | `accept` | Formato dei dati |
| --------------------- | ---------------------- | ------------------------------------------ |
| Frontend Web / EventSource | `text/event-stream` | `data: {json}\n\n`, con l'ultima riga `data: [DONE]\n\n` |
| Server / CLI / analisi dello streaming Node | `application/x-ndjson` | Un oggetto JSON per riga |
| Nessuno streaming richiesto | `application/json` (predefinito) | Rest in un'unica risposta `{answer, id}` |

### Esempio NDJSON

```SON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # Compatibile con v1: i frammenti incrementali vengono forniti contemporaneamente tramite il campo delta_answer
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Ogni riga NDJSON è un evento strutturato; il più comune è `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Esempio SSE

Nel browser, `EventSource` non supporta un corpo della richiesta personalizzato; si consiglia di utilizzare `fetch` + analisi manuale suddividendo il contenuto in base a `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Tipi di eventi dello streaming

| `type` | Significato |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta` | Frammento di testo incrementale della risposta dell'assistente. `content` contiene il nuovo contenuto; per compatibilità con v1, lo stesso evento include anche `delta_answer` (uguale a `content`) e `id`. |
| `thinking` | Processo di ragionamento del modello (presente solo quando il modello selezionato espone il reasoning). |
| `tool_use` | Il modello decide di chiamare uno strumento; l'evento contiene `tool_id`, `tool_name`, `input`. |
| `tool_result` | Risultato dell'esecuzione dello strumento, associato al precedente `tool_use` tramite `tool_id`; `is_error` indica se si è verificato un errore. |
| `card` | Scheda strutturata prodotta dallo strumento (ad esempio immagini o anteprime di link), adatta alla visualizzazione diretta. |
| `citation` | URL della fonte utilizzato per integrare le citazioni del frammento di testo corrispondente. |
| `ask_user_question` | Il modello richiede ulteriori informazioni all'utente; la conversazione passa allo stato `awaiting_user_input`. Per maggiori dettagli, consulta la sezione seguente [Riprendere una conversazione sospesa](#恢复暂停的对话). |
| `artifact` | Risultato autonomo generato dal modello (ad esempio blocchi di codice o documenti), che può essere salvato o scaricato. |
| `system_message` | Messaggio informativo del sistema (non contenuto dell'utente o dell'assistente), utilizzato esclusivamente per le notifiche dell'interfaccia utente. |
| `compact` | Il contesto del modello è stato organizzato; i messaggi originali salvati rimangono invariati e il client non deve eliminare la cronologia della chat. |
| `error` | Si è verificato un errore in questo turno; `message` descrive il contenuto dell'errore. |
| `done` | Il salvataggio del record finale della conversazione di questo turno è riuscito; include `usage` (contenente `prompt_tokens` / `completion_tokens` / `total_tokens`) e `terminal_reason`. È comunque necessario determinare se l'attività è stata completata in base al motivo della terminazione. |
Per i client interessati esclusivamente alla risposta finale, concatenare tutti i campi `content` degli eventi `text_delta` equivale al campo `answer` nella modalità `application/json`.

## Input multimodale

Se l'input dell'utente contiene immagini o file, utilizzare `message` (array) al posto di `question`. Ogni elemento dell'array rappresenta un blocco di contenuto:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "Quanti gatti ci sono in questa immagine?" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Tipi di blocchi supportati:

- `text` — testo normale, richiede il campo `text`.
- `image_url` — immagine, richiede `image_url.url`.
- `file_url` — file (PDF, CSV, TXT, ecc.), richiede `file_url.url`.

### Relazione con `references` della v1

Per garantire la compatibilità con i vecchi client, la v2 continua a riconoscere il campo `references: ["https://...", ...]`:

- Se l'estensione dell'URL è `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, viene convertito automaticamente in un blocco `image_url`;
- Le altre estensioni vengono convertite in blocchi `file_url`;
- Se viene fornito anche `question`, questo viene inserito prima come blocco `text`.

Pertanto, se desideri semplicemente migrare dalla v1 senza modificare il corpo della richiesta, è sufficiente sostituire il percorso con `/aichat2/conversations`: l'utilizzo originale di `references` continuerà a funzionare normalmente.

Se hai bisogno di un controllo più preciso (ad esempio, inserire più immagini tra i blocchi di testo oppure mantenere un ordine specifico), utilizza direttamente l'array `message`.

## Chiamate agli strumenti e MCP

Il principale miglioramento della v2 consiste nella capacità del modello di chiamare autonomamente gli strumenti per completare attività in più passaggi. **Questa funzionalità è attiva per impostazione predefinita** e non richiede alcuna configurazione aggiuntiva da parte del client nella richiesta. Scenari comuni:

- L'utente chiede «Cerca le mostre più recenti a Shanghai» → il modello richiama la funzionalità integrata di ricerca web → organizza i risultati in una risposta.
- L'utente chiede «Leggi questo PDF e scrivi un riepilogo» → il modello richiama file_read → scrive il riepilogo.
- L'utente ha già autorizzato Google Drive / GitHub / Notion e altri servizi in [Connections](https://platform.acedata.cloud/connections) → il modello può richiamare i relativi strumenti MCP per leggere e scrivere i loro dati.

Nei flussi NDJSON / SSE, le chiamate agli strumenti vengono rappresentate tramite due tipi di eventi: `tool_use` e `tool_result`, ad esempio:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Se non desideri mostrare nel frontend i dettagli delle chiamate agli strumenti, puoi ignorare le seguenti categorie di eventi: `tool_use` / `tool_result` / `card` / `citation`. L'output finale del modello continuerà a essere trasmesso tramite il flusso `text_delta`.

`max_turns` consente di limitare il numero massimo di cicli di chiamata autonoma degli strumenti da parte del modello durante questa richiesta. L'intervallo consentito è 1–500 e il valore predefinito è 500 se omesso. Impostando un valore basso (ad esempio `max_turns: 1`), è possibile forzare una singola risposta, impedendo qualsiasi chiamata agli strumenti.

## Esecuzione asincrona e autorizzazione non presidiata

Se la chiamata proviene da un Webhook di avviso, da un sistema CI/CD, da un sistema di monitoraggio o da un'altra attività in background, puoi impostare `async: true` affinché l'interfaccia restituisca immediatamente un ID attività mentre l'esecuzione continua in background:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Il mio servizio ha generato un avviso. Usa il mio account WeChat personale per inviare una notifica al gruppo WeChat «AceDataCloud团队»……"
}
```

Esempio di risposta:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Successivamente, puoi utilizzare `action: retrieve` + `id` per recuperare il risultato della conversazione. In alternativa, puoi fornire `callback_url`: al termine dell'attività, la piattaforma invierà una richiesta POST al tuo indirizzo di callback contenente `{ status, answer, usage, error }`. `callback_url` deve utilizzare `http` / `https` e non può contenere direttamente `localhost` o un indirizzo IP privato.

Le attività in background generalmente non prevedono la possibilità per qualcuno di fare clic su un pulsante di conferma. Se desideri che determinate Skill o MCP Server eseguano operazioni come invio, pubblicazione o scrittura in modalità non presidiata, devi specificare esplicitamente l'elenco delle autorizzazioni preventive nel corpo della richiesta:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Il mio servizio ha generato un avviso. Usa il mio account WeChat personale per inviare una notifica al gruppo WeChat «AceDataCloud团队»……"
}
```

I valori in `allowed_skills` sono gli slug delle Skill già connesse; i valori in `allowed_mcp_servers` sono gli slug dei MCP Server già connessi. Le Skill / i MCP Server non inclusi nell'elenco delle autorizzazioni preventive potranno comunque soltanto visualizzare un'anteprima, eseguire un dry-run o rifiutare le operazioni di scrittura in modalità non presidiata.

Se hai bisogno di un controllo più dettagliato, puoi anche utilizzare l'oggetto equivalente `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

L'autorizzazione preventiva è costituita esclusivamente da queste due liste: se una lista è vuota, non viene autorizzata alcuna funzionalità e non è necessario aggiungere ulteriori campi di attivazione.

Nota: l'autorizzazione preventiva significa soltanto che «questa richiesta consente a queste funzionalità di saltare la conferma manuale in modalità non presidiata». La Skill specifica deve comunque supportare `--unattended-confirm` o un meccanismo di sicurezza equivalente; in caso contrario, continuerà a eseguire un dry-run e non effettuerà direttamente operazioni di scrittura.

## Riprendere le conversazioni sospese

Alcuni strumenti possono indurre il modello a «porre una domanda all'utente». In questo caso, il modello emetterà un evento `ask_user_question` e la conversazione verrà sospesa nello stato `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "In quale lingua desideri generare il rapporto, cinese o inglese?",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Nel frontend, visualizza questo evento come una scheda che consenta all'utente di selezionare una risposta, quindi avvia la richiesta successiva utilizzando lo stesso `id` e inserisci la risposta tramite `tool_results`：
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

Nel corpo della richiesta, `tool_use_id` **deve** corrispondere esattamente al `tool_id` ricevuto durante la pausa; in caso contrario verrà restituito un errore 400. Quando nella richiesta è presente anche `tool_results`, `question` / `message` / `references` verranno ignorati.

Se l'utente decide di abbandonare la domanda, è sufficiente inviare direttamente un nuovo `question` / `message`; la piattaforma contrassegnerà automaticamente la chiamata allo strumento sospesa come «utente ha saltato».

## Gestione delle sessioni (CRUD)

La v2 offre una gestione leggera delle sessioni tramite il campo `action` sullo stesso endpoint, senza bisogno di aprire API separate.

### `action: retrieve` —— Recuperare una sessione

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Restituisce il documento completo della sessione (inclusa la cronologia di `messages`, `model`, `title`, `tools_used` e altri dati).

### `action: retrieve_batch` —— Elencare i riepiloghi delle sessioni

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Restituisce `{ items: [...], total }`. **I riepiloghi non includono `messages`**, quindi sono adatti per creare un elenco nella barra laterale; quando l'utente apre una sessione, utilizzare `action: retrieve` per recuperare separatamente tutti i suoi messaggi.

Parametri di filtro facoltativi: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Modificare il titolo o riscrivere la cronologia

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

È possibile inviare anche `messages`, ma il server eseguirà una rigorosa convalida dello schema (deve essere nel formato `ToolUseContent` ripiegato); in caso contrario verrà restituito un errore 400. In generale, si consiglia di utilizzarlo solo per modificare `title`.

### `action: delete` —— Eliminare una sessione

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Restituisce `{ id, success: true }`. Dopo l'eliminazione non sarà possibile recuperare la sessione, quindi verificare prima di effettuare la chiamata.

## Migrazione fluida dalla v1

Se stai già utilizzando [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), la migrazione alla v2 richiede modifiche al codice quasi inesistenti:

1. Modifica l'URL da `https://api.acedata.cloud/aichat/conversations` a `https://api.acedata.cloud/aichat2/conversations`.
2. Se in precedenza utilizzavi nomi di modelli v1 (come `gpt-3.5`, `gpt-4-browsing` ecc.), durante il passaggio alla v2 è consigliabile aggiornare ai modelli attuali (come `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` ecc.).
3. I campi del flusso NDJSON mantengono la compatibilità con le versioni precedenti: ogni evento `text_delta` continua a includere `delta_answer` e `id`, pertanto i client che in precedenza analizzavano riga per riga `delta_answer` non richiedono modifiche.

Dopo la migrazione, puoi attivare in base alle necessità le nuove funzionalità della v2 (messaggi multimodali `message`, SSE, chiamate agli strumenti, CRUD tramite `action`) e procedere gradualmente.

## Gestione degli errori

Le risposte di errore hanno tutte il seguente formato:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Errori comuni:

- `400 bad_request`: mancano campi obbligatori, `tool_use_id` non corrispondente, schema `messages` non valido ecc.
- `401 invalid_token`: intestazione `authorization` non corretta.
- `404 not_found`: la sessione corrispondente all'`id` non esiste durante l'esecuzione di `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: la sessione ha superato il limite di archiviazione; i record salvati esistenti non sono stati sovrascritti.
- `429 too_many_requests`: è stato attivato il limite di frequenza delle richieste.
- `503 context_compaction_failed`: la compattazione del contesto non è riuscita; i record esistenti vengono conservati.
- `500 conversation_persist_failed`: il salvataggio finale di questo turno non è riuscito; aver ricevuto il testo non significa che il record finale sia stato salvato correttamente. Verificare tramite l'ID della sessione.
- `500 chat_error`: il servizio è temporaneamente non disponibile oppure in questo turno non è stato generato alcun contenuto (non verrà addebitato alcun costo).

Nelle risposte in streaming, gli errori vengono inviati tramite un evento `{"type":"error","message":"..."}`, dopodiché il flusso termina. `[DONE]` indica soltanto che il trasferimento è terminato; in presenza di `error`, la richiesta non può essere considerata riuscita e non verrà inviato alcun evento `done` di successo.

## Conclusione

L'API AI Chat v2, pur mantenendo la compatibilità con le versioni precedenti della v1, trasforma le conversazioni da «domande e risposte a turno singolo / multiplo» in «conversazioni osservabili basate su agenti»: input multimodali, chiamate agli strumenti, possibilità di sospensione / ripresa, eventi strutturati in streaming e CRUD integrato. Si consiglia di utilizzare direttamente la v2 per le nuove integrazioni; le integrazioni v1 esistenti possono essere migrate gradualmente e senza interruzioni. Per qualsiasi domanda, non esitare a contattare il nostro team di assistenza tecnica.
