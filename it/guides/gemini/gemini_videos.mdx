Questo documento presenterà le istruzioni per l'integrazione dell'API Gemini Videos Generation, che può generare video Google Gemini (omni-flash) tramite l'input di parole chiave testuali (e immagini di riferimento opzionali).

## Processo di Richiesta

Per utilizzare l'API Gemini Videos Generation, prima vai al [Pannello di Controllo Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da conservare per uso futuro.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Se non hai ancora effettuato il login o la registrazione, verrai automaticamente reindirizzato alla pagina di login che ti invita a registrarti e accedere; una volta completato, verrai riportato automaticamente alla pagina corrente.

**Un API Token è sufficiente per accedere a tutti i servizi della piattaforma, senza necessità di richiederne uno per ogni servizio.** La prima richiesta riceverà un credito gratuito, per un'esperienza senza costi; quando il credito è insufficiente, puoi ricaricare il saldo generale nel [pannello di controllo](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione Completa: [Gemini Videos Generation API →](https://platform.acedata.cloud/documents/gemini-videos)

## Uso di Base

Iniziamo a comprendere le modalità di utilizzo di base, inserendo le parole chiave `prompt`, il modello `model` e il rapporto d'aspetto `aspect_ratio`, per generare il video corrispondente.

Possiamo vedere che qui abbiamo impostato le intestazioni della richiesta, tra cui:

- `accept`: il formato della risposta desiderata, qui impostato su `application/json`, ovvero formato JSON.
- `authorization`: la chiave per chiamare l'API, che può essere selezionata direttamente dopo la richiesta.

Inoltre, abbiamo impostato il corpo della richiesta, che include:

- `prompt`: le parole chiave testuali che descrivono il contenuto del video da generare, **obbligatorio**.
- `model`: il modello per generare il video, attualmente supporta solo `omni-flash`, che è il valore predefinito.
- `aspect_ratio`: il rapporto d'aspetto del video generato, può essere `16:9` (orizzontale) o `9:16` (verticale), predefinito `16:9`.
- `resolution`: la risoluzione di output opzionale, può essere `720p` o `1080p`, predefinita `720p`.
- `image_urls`: un array di link a immagini di riferimento opzionali, utilizzato per guidare la generazione del video; i campi vuoti verranno ignorati. Quando si utilizza `video_urls` per l'editing video, questo parametro è obbligatorio (almeno un'immagine).
- `video_urls`: un array di link a video di riferimento opzionali (massimo 1), utilizzato per **editing video / video di riferimento**; se fornito, deve essere fornita anche almeno un'immagine in `image_urls`.
- `callback_url`: l'indirizzo per il callback asincrono; una volta impostato, l'API restituirà immediatamente `task_id`, e al termine del compito, il risultato verrà inviato a questo indirizzo.
- `async`: opzionale, se impostato su `true`, l'interfaccia restituirà immediatamente `task_id`, senza necessità di fornire `callback_url`, e successivamente si potrà ottenere il risultato tramite l'interfaccia di query del compito corrispondente.

Cliccando sul pulsante "Try" è possibile effettuare un test, e il risultato ottenuto sarà simile al seguente:

```json
{
  "success": true,
  "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
  "data": [
    {
      "id": "omni-flash:job_01k777hjrbfrgs2060q5zvf2a5",
      "video_url": "https://cdn.acedata.cloud/gemini/example-video.mp4",
      "state": "succeeded"
    }
  ]
}
```

Il risultato restituito contiene diversi campi, descritti come segue:

- `success`: indica se la richiesta di generazione video è stata completata con successo.
- `task_id`: l'ID del compito di generazione video.
- `trace_id`: l'ID di tracciamento della richiesta, utilizzato per la risoluzione dei problemi.
- `data`: l'elenco dei risultati video generati.
  - `id`: identificatore unico del video generato.
  - `video_url`: l'indirizzo del link al video generato.
  - `state`: lo stato del compito di generazione video, può essere `pending` / `succeeded` / `failed`.

Dobbiamo solo ottenere il video generato dal link `video_url` presente in `data`.

Il codice CURL corrispondente è il seguente:

```shell
curl -X POST 'https://api.acedata.cloud/gemini/videos' \
-H 'authorization: Bearer ${bearer_token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
  "model": "omni-flash",
  "aspect_ratio": "16:9"
}'
```

Il codice Python corrispondente è il seguente:

```python
import requests

url = "https://api.acedata.cloud/gemini/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
    "model": "omni-flash",
    "aspect_ratio": "16:9"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Video da Immagini

Se desideri generare un video basato su immagini di riferimento, puoi fornire uno o più link a immagini in `image_urls`, per guidare la generazione del video:

```json
{
  "prompt": "The character slowly turns around and smiles at the camera",
  "model": "omni-flash",
  "aspect_ratio": "9:16",
  "image_urls": [
    "https://cdn.acedata.cloud/example-reference.png"
  ]
}
```

## Editing Video / Video di Riferimento

Supporta direttamente l'editing o il riferimento a video esistenti: in `video_urls` puoi fornire un link a un video di riferimento (massimo 1), e **contemporaneamente** fornire almeno un'immagine di riferimento in `image_urls` (richiesta obbligatoria). Puoi descrivere l'effetto di editing desiderato tramite `prompt` (cambiamento di stile, cambio di scena, aggiunta o rimozione di elementi, ecc.):

```json
{
  "prompt": "Restyle the video into cinematic anime, keep the motion",
  "model": "omni-flash",
  "aspect_ratio": "16:9",
  "resolution": "720p",
  "image_urls": [
    "https://cdn.acedata.cloud/example-reference.png"
  ],
  "video_urls": [
    "https://cdn.acedata.cloud/example-source.mp4"
  ]
}
```

> Nota: massimo 1 video di riferimento; e quando si fornisce `video_urls`, è necessario fornire almeno un'immagine in `image_urls` (altrimenti verrà restituito un errore di parametro).

## Callback Asincrono

La generazione del video richiede un certo tempo di elaborazione. Se non desideri mantenere una connessione lunga in attesa, puoi fornire `callback_url`; in questo caso, l'API restituirà immediatamente `task_id`, e al termine del compito, invierà il risultato finale a questo indirizzo:

```json
{
  "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
  "model": "omni-flash",
  "aspect_ratio": "16:9",
  "callback_url": "https://your-domain.com/callback/gemini"
}
```

Il risultato restituito immediatamente sarà il seguente:

```json
{
  "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea"
}
```

## Query dei Risultati del Compito

Se hai utilizzato il callback asincrono o desideri controllare attivamente lo stato del compito, puoi utilizzare il [Gemini Tasks API](https://platform.acedata.cloud/documents/gemini-tasks) (`POST https://api.acedata.cloud/gemini/tasks`) per controllare lo stato e i risultati più recenti del compito in base a `task_id`.

## Gestione degli Errori

Quando si verifica un problema nella richiesta, l'API restituirà il codice di errore corrispondente e la spiegazione, i più comuni sono i seguenti:
- `400`: I parametri della richiesta sono errati, ad esempio manca `prompt` o il valore di `aspect_ratio` è illegale.
- `401`: Autenticazione fallita, token non valido o non corrisponde all'API.
- `403`: Saldo insufficiente, o le parole chiave hanno colpito contenuti rifiutati dalla revisione.
- `500`: Errore interno del server o fallimento nella generazione upstream.
