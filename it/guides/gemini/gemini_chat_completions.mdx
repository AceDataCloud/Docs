Google Gemini è un sistema di conversazione AI molto potente: basta inserire un prompt per generare risposte fluide e naturali in pochi secondi. Gemini può fornire un'assistenza intelligente sorprendente, migliorando notevolmente l'efficienza lavorativa e la creatività umana.

Questo documento presenta principalmente il flusso di utilizzo delle operazioni di Gemini Chat Completion API; sfruttandola possiamo utilizzare facilmente la funzione di conversazione del Gemini ufficiale.

## Processo di richiesta

Per utilizzare Gemini Chat Completion API, innanzitutto vai alla [console di Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da tenere come riserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato l'accesso o non ti sei registrato, verrai automaticamente reindirizzato alla pagina di accesso per invitarti a registrarti ed effettuare l'accesso; al termine, tornerai automaticamente alla pagina corrente.

**Un solo API Token può chiamare tutti i servizi della piattaforma, senza necessità di richiederne uno separatamente per ciascun servizio.** Alla prima richiesta verrà concessa una quota gratuita, utilizzabile per una prova gratuita; quando la quota è insufficiente, puoi ricaricare il saldo generale nella [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## Utilizzo di base

Successivamente puoi compilare i contenuti corrispondenti nell'interfaccia, come mostrato nell'immagine:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

Quando utilizzi questa interfaccia per la prima volta, dobbiamo compilare almeno tre contenuti: uno è `authorization`, che può essere selezionato direttamente nell'elenco a discesa. Un altro parametro è `model`; `model` indica la categoria di modello del sito ufficiale Gemini che scegliamo di utilizzare e i modelli disponibili fanno riferimento all'enumerazione `model` nella documentazione dell'interfaccia. L'ultimo parametro è `messages`; `messages` è l'array dei prompt che inseriamo, è un array e indica che è possibile caricare contemporaneamente più prompt, ciascuno dei quali contiene `role` e `content`, dove `role` indica il ruolo di chi pone la domanda. Forniamo tre identità: `user`, `assistant`, `system`. L'altro `content` è il contenuto specifico della nostra domanda.

Allo stesso tempo, puoi notare che sul lato destro viene generato il codice di chiamata corrispondente; puoi copiare il codice ed eseguirlo direttamente, oppure puoi fare clic direttamente sul pulsante «Try» per effettuare un test.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

> **Suggerimento**: i flash della serie `gemini-3.x` sono modelli di ragionamento e consumano prima i reasoning tokens; imposta `max_tokens` a più di 512, altrimenti potrebbe essere restituito solo contenuto vuoto. `gemini-3.8-flash` è l'attuale modello Flash consigliato, supporta fino a 1 milione di Token di contesto, input di immagini, chiamate di strumenti e risposte in streaming; attualmente viene chiamato tramite l'interfaccia Chat Completions.

`gemini-4-argon` può essere utilizzato anch'esso per Chat Completions e supporta risposte testuali normali e in streaming. Potrebbe utilizzare parte del budget di output per il ragionamento; per compiti complessi, lascia spazio sufficiente per `max_tokens`; Google suggerisce almeno 32768 per le attività comuni di questo modello. Non equiparare questa interfaccia alla funzionalità di output lungo in background della Google Interactions API.

`gemini-4-neon` — ingegneria del software e analisi dei dati. Imposta `model` su questo ID e riserva token di output per il ragionamento e la risposta.

Anche `gemini-4-carbon` e `gemini-4-hydrogen` supportano le risposte testuali normali e in streaming di questa interfaccia. Carbon è rivolto a compiti complessi di ragionamento e ingegneria, Hydrogen è rivolto alla programmazione quotidiana e ai compiti in più passaggi. Entrambi consumano Token di ragionamento, quindi è necessario riservare un budget sufficiente per `max_tokens`; l'output lungo da un milione di Token dei modelli nativi non significa che questa interfaccia renda disponibile tale funzionalità. I campi per immagini e chiamate di strumenti restano soggetti al contratto pubblico e alle restituzioni effettive di questa interfaccia.

## Comprensione delle immagini (input multimodale)
Gemini è un modello multimodale nativo, in grado di «vedere le immagini» direttamente. Per passare un'immagine, basta cambiare il `content` di un messaggio da stringa a un **array di blocchi di contenuto**, inserendo nell'array sia un blocco `text` sia un blocco `image_url`—questo è completamente coerente con OpenAI e con il formato compatibile con OpenAI di Gemini ufficiale.

`image_url.url` supporta due modalità di scrittura:

- **URI `data:` base64 (consigliato, più stabile)**: il formato è `data:<tipo media>;base64,<dati>`, ad esempio `data:image/jpeg;base64,/9j/4AAQ...`. Il **tipo media (MIME) è già scritto nel prefisso `data:`**, quindi non è necessario e non esiste un campo `media_type` separato.
- **URL di immagine pubblicamente accessibile**: ad esempio `https://cdn.acedata.cloud/4hfydw.jpg`.

Tipi di immagine supportati: `png`, `jpeg`, `webp`, `heic`, `heif`.

Codice di esempio di chiamata Python (URI data base64):

```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# Leggi l'immagine locale come URI data base64
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "Descrivi questa immagine in una frase."},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

È anche possibile passare direttamente un URL di immagine pubblicamente accessibile:

```python
payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "Descrivi questa immagine in una frase."},
                {"type": "image_url", "image_url": {"url": "https://cdn.acedata.cloud/4hfydw.jpg"}}
            ]
        }
    ]
}
```

> 💡 `image_url` accetta solo il campo `url` (il valore può essere un URL di immagine o un URI `data:` base64), nonché il campo facoltativo `detail`. **Non passare `media_type`**—quello è il campo immagine di Anthropic Claude e non appartiene al formato `image_url` di OpenAI / Gemini.

## Risposta in streaming

Questa interfaccia supporta anche le risposte in streaming, il che è molto utile per l'integrazione nelle pagine web e consente di ottenere un effetto di visualizzazione parola per parola.

Se si desidera restituire la risposta in streaming, è possibile modificare il parametro `stream ` nell'intestazione della richiesta impostandolo su `true`.

La modifica è mostrata nell'immagine, ma il codice di chiamata deve essere modificato di conseguenza per supportare le risposte in streaming.

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

Dopo aver modificato `stream` in `true`, l'API restituirà riga per riga i dati JSON corrispondenti; a livello di codice, occorre apportare le modifiche corrispondenti per ottenere i risultati riga per riga.

Codice di esempio di chiamata Python:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Anche JavaScript è supportato, ad esempio il codice di chiamata in streaming di Node.js è il seguente:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

## Conversazione multi-turno

Se desiderate integrare la funzionalità di conversazione multi-turno, dovete caricare più parole di domanda nel campo `messages`; un esempio specifico di più parole di domanda è mostrato nella figura seguente:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

payload = {

response = requests.post(url, json=payload, headers=headers)
```

## Modello multimodale Gemini-3.1

`gemini-3.1-pro-preview` è l'ID modello ufficiale dell'attuale Gemini 3.1 Pro, supporta input multimodali come testo, immagini, video e così via, ed è adatto a compiti di ragionamento complesso, programmazione e comprensione.

Esempio di richiesta:

```json

  "model": "gemini-3.1-pro-preview",
```

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice e il messaggio di errore corrispondenti. Ad esempio:

- `400 token_mismatched`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`：Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`：Troppe richieste, è stato superato il limite di velocità.
- `500 api_error`：Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
