Google Gemini è un sistema di conversazione AI molto potente: basta inserire un prompt per generare risposte fluide e naturali in pochi secondi. Gemini può fornire un'assistenza intelligente sorprendente, migliorando notevolmente l'efficienza lavorativa e la creatività umana.

Questo documento presenta principalmente il processo di utilizzo delle operazioni della Gemini Chat Completion API, grazie alla quale possiamo utilizzare facilmente la funzionalità di conversazione di Gemini ufficiale.

## Processo di richiesta

Per utilizzare la Gemini Chat Completion API, vai prima alla [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da conservare come riserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato l'accesso o la registrazione, verrai automaticamente reindirizzato alla pagina di accesso per registrarti e accedere; al termine tornerai automaticamente alla pagina corrente.

**Un solo API Token può richiamare tutti i servizi della piattaforma, senza dover fare richiesta separatamente per ogni servizio.** Alla prima richiesta verrà fornito un credito gratuito, utilizzabile per un'esperienza gratuita; quando il credito è insufficiente, puoi ricaricare il saldo universale nella [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## Utilizzo di base

Successivamente puoi compilare i contenuti corrispondenti nell'interfaccia, come mostrato nell'immagine:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

Quando utilizzi questa interfaccia per la prima volta, dobbiamo compilare almeno tre contenuti: uno è `authorization`, che può essere selezionato direttamente nell'elenco a discesa. Un altro parametro è `model`; `model` rappresenta la categoria di modello del sito ufficiale Gemini che scegliamo di utilizzare, e i modelli disponibili fanno riferimento all'enumerazione `model` nella documentazione dell'interfaccia. L'ultimo parametro è `messages`; `messages` è l'array di prompt che inseriamo, è un array e indica che è possibile caricare contemporaneamente più prompt, ciascuno dei quali contiene `role` e `content`, dove `role` rappresenta il ruolo di chi pone la domanda; forniamo tre identità, rispettivamente `user`, `assistant`, `system`. L'altro `content` è il contenuto specifico della domanda che poniamo.

Allo stesso tempo, puoi notare che sulla destra viene generato il codice di chiamata corrispondente: puoi copiare il codice ed eseguirlo direttamente, oppure fare direttamente clic sul pulsante «Try» per effettuare il test.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

> **Suggerimento**: i modelli flash della serie `gemini-3.x` sono modelli di ragionamento e consumeranno prima reasoning tokens; imposta `max_tokens` sopra 512, altrimenti potrebbe essere restituito solo contenuto vuoto. `gemini-3.8-flash` è l'attuale modello Flash consigliato, supporta fino a 1 milione di Token di contesto, input di immagini, chiamate di strumenti e risposte in streaming; attualmente viene chiamato tramite l'interfaccia Chat Completions.

## Comprensione delle immagini (input multimodale)

Gemini è un modello multimodale nativo e può direttamente «vedere le immagini». Per passare un'immagine, modifica il `content` di un messaggio da stringa a un **array di blocchi di contenuto**, inserendo contemporaneamente nell'array blocchi `text` e blocchi `image_url`: questo è completamente coerente con OpenAI e con il formato compatibile OpenAI di Gemini ufficiale.

`image_url.url` supporta due modalità di scrittura:

- **URI `data:` base64 (consigliato, più stabile)**: il formato è `data:<tipo multimediale>;base64,<dati>`, ad esempio `data:image/jpeg;base64,/9j/4AAQ...`. **Il tipo multimediale (MIME) è già scritto nel prefisso `data:`**, quindi non è necessario e non esiste un campo `media_type` separato.
- **URL di immagine pubblicamente accessibile**: ad esempio `https://cdn.acedata.cloud/4hfydw.jpg`.

Tipi di immagine supportati: `png`, `jpeg`, `webp`, `heic`, `heif`.

Codice di chiamata di esempio Python (URI data base64):
```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# 把本地图片读成 base64 data URI
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

È anche possibile passare direttamente un URL di immagine pubblicamente accessibile:

```python
payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": "https://cdn.acedata.cloud/4hfydw.jpg"}}
            ]
        }
    ]
}
```

> 💡 `image_url` accetta solo il campo `url` (il cui valore può essere un URL dell'immagine o un URI `data:` base64), nonché il campo opzionale `detail`. **Non passare `media_type`**—questo è il campo immagine di Anthropic Claude e non appartiene al formato `image_url` di OpenAI / Gemini.

## Risposta in streaming

Questa interfaccia supporta anche le risposte in streaming, il che è molto utile per l'integrazione con le pagine web e consente alla pagina di ottenere un effetto di visualizzazione carattere per carattere.

Se si desidera restituire la risposta in streaming, è possibile modificare il parametro `stream ` nell'intestazione della richiesta impostandolo su `true`.

La modifica è mostrata nella figura, ma il codice di chiamata deve essere modificato di conseguenza per supportare le risposte in streaming.

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

Dopo aver modificato `stream` in `true`, l'API restituirà riga per riga i dati JSON corrispondenti; a livello di codice dobbiamo apportare le modifiche corrispondenti per ottenere i risultati riga per riga.

Codice di chiamata di esempio in Python:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Anche JavaScript è supportato, ad esempio il codice di chiamata in streaming di Node.js è il seguente:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Codice di esempio Java:


```python
import requests
```

## Modello multimodale Gemini-3.1

`gemini-3.1-pro-preview` è l'ID ufficiale del modello dell'attuale Gemini 3.1 Pro, supporta input multimodali quali testo, immagini e video, ed è adatto a compiti di ragionamento complesso, codifica e comprensione.

Esempio di richiesta:

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "图片的内容是什么？"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/qzx2z1.png"
          }
        }
      ]
    }
  ],
  "stream": false
}
```

Gemini 3.1 Pro supporta allo stesso modo la comprensione video:

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "视频的内容是什么？"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/58yioe.mp4"
          }
        }
      ]
    }
  ],
  "stream": false
}
```

Il formato di risposta è coerente con Gemini 3.0 Pro; per i dettagli, consulta la descrizione nella sezione precedente relativa al modello multimodale Gemini-3.0.

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice e il messaggio di errore corrispondenti. Ad esempio:

- `400 token_mismatched`：Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`：Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`：Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`：Too many requests, you have exceeded the rate limit.
- `500 api_error`：Internal server error, something went wrong on the server.

### Esempio di risposta di errore
```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
