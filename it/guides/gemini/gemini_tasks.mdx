La principale funzionalità dell'API Gemini Tasks è quella di interrogare lo stato di esecuzione di un'attività utilizzando l'ID dell'attività generato dall'API Gemini Videos Generation.

Questo documento fornirà una descrizione dettagliata dell'integrazione dell'API Gemini Tasks, aiutandoti a integrare facilmente e a interrogare lo stato di esecuzione delle attività dell'API Gemini Videos Generation.

## Processo di richiesta

Per utilizzare l'API Gemini Videos Generation, prima di tutto vai al [Pannello di controllo di Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da conservare per uso futuro.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato il login o la registrazione, verrai automaticamente reindirizzato alla pagina di login che ti invita a registrarti e a effettuare il login; una volta completato, verrai riportato automaticamente alla pagina corrente.

**Un API Token è sufficiente per accedere a tutti i servizi della piattaforma, senza necessità di richiederne uno separato per ogni servizio.** La prima richiesta ti darà un credito gratuito, per un'esperienza senza costi; quando il credito è insufficiente, puoi ricaricare il saldo generale nel [pannello di controllo](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Gemini Videos Generation API →](https://platform.acedata.cloud/documents/gemini-videos)

## Esempio di richiesta

L'API Gemini Tasks può essere utilizzata per interrogare i risultati dell'API Gemini Videos Generation.

### Impostazione dell'intestazione della richiesta e del corpo della richiesta

**Request Headers** includono:

- `accept`: specifica di ricevere la risposta in formato JSON, qui si compila con `application/json`.
- `authorization`: la chiave per chiamare l'API, che può essere selezionata direttamente dopo la richiesta.

**Request Body** include:

- `id`: l'ID dell'attività da interrogare.
- `action`: il modo di operare sull'attività, per una singola interrogazione si compila con `retrieve`.

### Esempio di codice CURL

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### Esempio di risposta

Dopo una richiesta riuscita, l'API restituirà i dettagli dell'attività qui. Il campo `request` è il corpo della richiesta al momento dell'avvio dell'attività, il campo `response` è il corpo della risposta restituito al termine dell'attività, ad esempio:

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "started_at": 1769262721.823,
  "finished_at": 1769262730.723,
  "elapsed": 8.9,
  "request": {
    "prompt": "Una ripresa cinematografica di un gattino che insegue una farfalla in un giardino illuminato dal sole",
    "model": "omni-flash",
    "aspect_ratio": "16:9"
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "omni-flash:job_01k777hjrbfrgs2060q5zvf2a5",
        "video_url": "https://cdn.acedata.cloud/gemini/example-video.mp4",
        "state": "succeeded"
      }
    ]
  }
}
```

La descrizione dei campi è la seguente:

- `id`: l'ID dell'attività generata, utilizzato per identificare univocamente questa attività di generazione.
- `request`: informazioni sulla richiesta nell'attività interrogata.
- `response`: informazioni sulla risposta nell'attività interrogata.
- `created_at`: data e ora di creazione dell'attività, timestamp Unix (secondi, float).
- `started_at`: data e ora di inizio dell'esecuzione dell'attività, timestamp Unix (secondi, float).
- `finished_at`: data e ora di completamento dell'attività, timestamp Unix (secondi, float). Questo campo non viene restituito se l'attività non è completata.
- `elapsed`: tempo di esecuzione dell'attività, in secondi (float, con 3 decimali). Questo campo non viene restituito se l'attività non è completata.

## Operazione di interrogazione in batch

Per interrogare i dettagli di più ID di attività, imposta `action` su `retrieve_batch` e passa l'array degli ID delle attività tramite `ids`:

**Request Body** include:

- `ids`: array degli ID delle attività da interrogare.
- `action`: il modo di operare sull'attività, per interrogazioni in batch si compila con `retrieve_batch`.

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```
