La funzione principale dell'API Gemini Tasks è quella di interrogare lo stato di esecuzione di un'attività tramite l'ID attività generato dall'API Gemini Videos Generation.

Questo documento fornisce una guida dettagliata all'integrazione dell'API Gemini Tasks, aiutandovi a integrare facilmente e a interrogare lo stato di esecuzione delle attività dell'API Gemini Videos Generation.

## Procedura di richiesta

Per utilizzare l'API Gemini Tasks, è necessario prima richiedere il servizio corrispondente alla pagina [Gemini Videos Generation API](https://platform.acedata.cloud/documents/gemini-videos) e copiare l'ID attività restituito dall'API Gemini Videos Generation.

Successivamente, accedere alla pagina [Gemini Tasks API](https://platform.acedata.cloud/documents/gemini-tasks) per richiedere il servizio corrispondente; una volta nella pagina, cliccare sul pulsante "Acquire".

Se non si è ancora effettuato l'accesso o la registrazione, si verrà automaticamente reindirizzati alla [pagina di login](https://platform.acedata.cloud) per registrarsi e accedere; dopo il login o la registrazione, si tornerà automaticamente alla pagina corrente.

Alla prima richiesta viene offerto un credito gratuito per utilizzare l'API senza costi.

## Esempio di richiesta

L'API Gemini Tasks può essere utilizzata per interrogare i risultati dell'API Gemini Videos Generation.

### Impostazione delle intestazioni e del corpo della richiesta

**Request Headers** includono:

- `accept`: specifica di ricevere la risposta in formato JSON, impostato su `application/json`.
- `authorization`: la chiave API per chiamare l'API, selezionabile direttamente dopo la richiesta.

**Request Body** include:

- `id`: l'ID dell'attività da interrogare.
- `action`: il tipo di operazione sull'attività, per una singola interrogazione inserire `retrieve`.

### Esempio di codice CURL

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### Esempio di risposta

Se la richiesta ha successo, l'API restituirà i dettagli dell'attività. Il campo `request` contiene il corpo della richiesta originaria, mentre il campo `response` contiene il corpo della risposta al completamento dell'attività, ad esempio:

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "request": {
    "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
    "model": "omni-flash",
    "aspect_ratio": "16:9"
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "omni-flash:job_01k777hjrbfrgs2060q5zvf2a5",
        "video_url": "https://cdn.acedata.cloud/gemini/example-video.mp4",
        "state": "succeeded"
      }
    ]
  }
}
```

Descrizione dei campi:

- `id`: ID dell'attività generata, usato per identificare univocamente l'attività.
- `request`: informazioni della richiesta dell'attività interrogata.
- `response`: informazioni della risposta dell'attività interrogata.

## Operazioni di interrogazione batch

Per interrogare i dettagli di più attività contemporaneamente, impostare `action` su `retrieve_batch` e passare un array di ID attività tramite `ids`:

**Request Body** include:

- `ids`: array degli ID delle attività da interrogare.
- `action`: tipo di operazione sull'attività, per interrogazione batch inserire `retrieve_batch`.

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```
