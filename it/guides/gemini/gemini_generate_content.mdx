Google Gemini è un sistema di conversazione AI molto potente, in grado di generare risposte fluide e naturali in pochi secondi attraverso l'inserimento di prompt. Questo documento descrive principalmente come utilizzare l'API Gemini Generate Content, che è il formato API nativo ufficiale di Google e supporta i due endpoint `generateContent` e `streamGenerateContent`.

## Differenze rispetto alla Chat Completions API

L'API Gemini Generate Content utilizza il formato di richiesta nativo ufficiale di Google (campo `contents`), anziché il formato compatibile con OpenAI (campo `messages`). Se utilizzi già il Google Gemini SDK o hai familiarità con il formato API ufficiale, puoi utilizzare direttamente questa API senza modificare il formato della richiesta.

## Ambito di supporto attuale

L'interfaccia accetta input di testo, immagini, video e audio (`inlineData` o `fileData`), configurazioni di ragionamento e dichiarazioni di funzioni personalizzate. L'output audio, gli strumenti integrati e i campi nativi come la cache esplicita del contesto non hanno ancora una garanzia di disponibilità uniforme; fai riferimento al ritorno effettivo del modello specifico.

Quando invii file come l'audio utilizzando `fileData.fileUri`, assicurati che il file sia direttamente accessibile tramite HTTPS, non dipenda dallo stato di accesso e che il periodo di validità del link firmato copra l'intero tempo di elaborazione della richiesta. L'analisi audio non in streaming restituisce i risultati solo dopo che il modello ha completato l'elaborazione, e potrebbe richiedere più di 90 secondi; il client deve impostare un timeout totale sufficientemente lungo in base alle dimensioni del file e allo scenario aziendale, per evitare di interrompere la connessione mentre il server sta ancora elaborando.

## Procedura di richiesta

Prima di utilizzare l'API Gemini Generate Content, visita prima la pagina [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) e fai clic sul pulsante "Ottieni" per ottenere le credenziali necessarie per la richiesta.

Se non hai ancora effettuato l'accesso o la registrazione, verrai automaticamente reindirizzato alla pagina di accesso. La prima richiesta include una quota gratuita.

## Utilizzo di base

### Non-Streaming（non in streaming）

Invia una richiesta POST a `/v1beta/models/{model}:generateContent`:

> **Suggerimento**: la serie flash `gemini-3.x` è un modello di ragionamento e consumerà prima i reasoning tokens; imposta `generationConfig.maxOutputTokens` a un valore superiore a 512, altrimenti potrebbe restituire solo contenuto vuoto.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Esempio di risultato restituito:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

I campi token in `usageMetadata` vengono fatturati secondo la semantica nativa di Gemini:

- `promptTokenCount` include `cachedContentTokenCount`; la parte colpita dalla cache viene calcolata al prezzo di lettura della cache e non viene conteggiata nuovamente come input ordinario.
- `promptTokensDetails` e `cacheTokensDetails` vengono normalizzati in `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` e nei corrispondenti dettagli `cached_*` sotto `usage.prompt_tokens_details`. Questi valori sono inclusi rispettivamente in `prompt_tokens` e `cached_tokens`; le diverse modalità vengono ricalcolate solo in base ai rispettivi prezzi e non vengono fatturate due volte.
- `candidatesTokenCount` e `thoughtsTokenCount` vengono entrambi calcolati al prezzo dei token di output.
- `toolUsePromptTokenCount` è un token di input degli strumenti indipendente, calcolato al prezzo dei token di input.

Ace Data Cloud restituisce inoltre un oggetto `usage` normalizzato; per i protocolli tra modelli, il costo di questa chiamata viene letto in modo uniforme da `usage.cost`. `cost` è un'anteprima facoltativa del costo; quando l'anteprima del prezzo non è temporaneamente disponibile, la risposta del modello verrà comunque restituita normalmente, ma potrebbe non contenere questo campo. La fattura finale fa fede ai registri di utilizzo.

### Streaming（in streaming）

Invia una richiesta POST a `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

La risposta in streaming restituirà gradualmente il contenuto nel formato SSE (Server-Sent Events). Gli eventi intermedi di solito contengono solo contenuti incrementali; l'evento finale contenente i dati di utilizzo autorevoli includerà `usageMetadata` e l'oggetto `usage` normalizzato, mentre il costo si trova ancora in `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

La chiusura della connessione indica la fine dello stream; lo stream Gemini nativo non invia `data: [DONE]`. Se l'anteprima del prezzo finale non è temporaneamente disponibile, `usage` restituirà comunque l'utilizzo dei token, ma ometterà `cost`.

| `gemini-3.1-pro-preview` | Modello per ragionamento complesso e codifica                                 |

| `gemini-2.5-flash-lite`  | Modello Gemini 2.5 Flash-Lite                  |
| `gemini-3.1-flash-image` | Modello di generazione di immagini                                    |
| `gemini-3-pro-image`     | Modello di generazione di immagini di alta qualità                                 |
| `gemini-2.5-flash-image` | Modello di generazione di immagini Gemini 2.5                         |

`gemini-4-carbon` e `gemini-4-hydrogen` possono attualmente essere chiamati tramite Chat Completions, mentre Generate Content nativo non è temporaneamente disponibile. Le specifiche ufficiali dei modelli elencano input di testo, immagini, video, audio e PDF, nonché output di testo; ciò non significa che la piattaforma attuale abbia verificato tutti i tipi di input. Dopo il ripristino della chiamata nativa, inviare richieste secondo il contratto dell'interfaccia di questa pagina e verificare separatamente gli input e i parametri necessari. L'output di un milione di Token del long decode ufficiale non è incluso nell'attuale contratto dell'interfaccia. Entrambi supportano solo la cache implicita, i Token di pensiero vengono calcolati al prezzo di output; le regole di prezzo predisposte utilizzano lo stesso prezzo unitario per Token di input per ogni modalità di input, gli hit della cache sono calcolati al prezzo unitario di lettura della cache, per i dettagli consultare l'attuale pagina dei prezzi.

### Pensiero interno e riassunto del pensiero

Il pensiero interno del modello e la restituzione di un riassunto del pensiero al chiamante sono due impostazioni indipendenti:

- `thinkingBudget` o `thinkingLevel` controllano il budget o la profondità del pensiero interno del modello; i campi e i valori supportati dipendono dal modello.
- `includeThoughts` controlla se restituire un riassunto del pensiero, il valore predefinito è `false`. Quando il campo viene omesso o viene passato `false`, né le risposte JSON normali né quelle SSE in streaming restituiscono testo contrassegnato con `thought: true`; questi testi vengono conservati solo quando viene esplicitamente passato il valore booleano `true`.

Quando la richiesta non imposta `includeThoughts`, l'interfaccia passa per impostazione predefinita `false` ai modelli di generazione che supportano la configurazione del pensiero, evitando riassunti non necessari nella richiesta; il valore esplicitamente passato dal cliente, il budget di pensiero e il livello vengono mantenuti. Al noto `gemini-2.5-flash-image`, che non supporta la configurazione del pensiero, questo campo non viene aggiunto automaticamente, e nemmeno alle richieste `countTokens` viene aggiunta una configurazione di generazione.

Disattivare il riassunto non equivale a disattivare il pensiero interno, né garantisce la riduzione dei token di pensiero interno. Se la risposta contiene ancora testo di pensiero non richiesto, le uscite JSON normali e SSE lo filtreranno ulteriormente, mantenendo la risposta normale, le firme e l'utilizzo effettivo.

Quando è necessario visualizzare il riassunto, abilitarlo esplicitamente nel modo seguente. Se il modello non genera un riassunto utilizzabile, potrebbe non esserci testo di pensiero anche se è abilitato:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` è lo stato crittografato necessario per i turni successivi, non è il testo del riassunto del pensiero e non è controllato dall'interruttore `includeThoughts`. La firma può trovarsi su una risposta normale, una chiamata di funzione o una Part di testo vuota; quando si filtra il testo di pensiero, la firma e gli altri campi della stessa Part vengono mantenuti, pertanto nella risposta potrebbero rimanere Part che contengono solo la firma e hanno testo vuoto. Quando si gestisce manualmente la cronologia multi-turno, è necessario mantenere l'ordine di queste Part e la posizione delle firme, senza spostare le firme né unirle.

`usageMetadata` e `usage` continuano a registrare l'utilizzo effettivo. Nascondere il riassunto non azzera `thoughtsTokenCount`, la fatturazione continua a essere calcolata in base all'utilizzo effettivo e alle regole di prezzo correnti.

Vedere le [istruzioni ufficiali Google sul pensiero e sui riassunti del pensiero](https://firebase.google.com/docs/ai-logic/thinking) e le [regole delle firme di pensiero](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

  "contents": [
    {
      "role": "user",
      "parts": [{"text": "北京现在的天气怎么样？"}]
    }
  ],
  "tools": [
    {
      "functionDeclarations": [
        {

## Impostazioni di sicurezza

Il filtraggio dei contenuti può essere controllato tramite `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Gestione degli errori

| Codice di stato HTTP | Significato             |
| -------- | -------------- |
| 400      | Parametri della richiesta non validi         |
| 401      | Autenticazione fallita, controlla il Token |
| 403      | Contenuto intercettato dal filtro di sicurezza     |
| 429      | Richieste troppo frequenti         |
| 500      | Errore interno del server        |
