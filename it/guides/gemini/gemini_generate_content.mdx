Google Gemini è un sistema di conversazione AI molto potente, che può generare risposte fluide e naturali in pochi secondi tramite l'inserimento di prompt. Questo documento descrive principalmente il metodo d'uso della Gemini Generate Content API, che è il formato API nativo ufficiale di Google e supporta i due endpoint `generateContent` e `streamGenerateContent`.

## Differenze rispetto alla Chat Completions API

Gemini Generate Content API utilizza il formato di richiesta nativo ufficiale di Google (campo `contents`), anziché il formato compatibile con OpenAI (campo `messages`). Se utilizzi già Google Gemini SDK o conosci il formato API ufficiale, puoi usare direttamente questa API senza dover modificare il formato della richiesta.

## Ambito di supporto attuale

L'interfaccia accetta input di testo, immagini, video e audio (`inlineData` o `fileData`), configurazioni di ragionamento e dichiarazioni di funzioni personalizzate. Campi nativi quali output audio, strumenti integrati e caching esplicito del contesto non hanno ancora una garanzia di disponibilità unificata; fai riferimento al comportamento effettivo restituito dal modello specifico.

Quando invii file quali audio usando `fileData.fileUri`, assicurati che il file sia direttamente accessibile tramite HTTPS, che non dipenda dallo stato di accesso, e che il periodo di validità del link firmato copra l'intero tempo di elaborazione della richiesta. L'analisi audio non in streaming restituisce il risultato solo dopo che il modello ha completato l'elaborazione e potrebbe superare i 90 secondi; il client deve impostare un timeout totale sufficientemente lungo in base alle dimensioni del file e allo scenario aziendale, evitando di disconnettersi mentre il server sta ancora elaborando.

## Procedura di richiesta

Prima di utilizzare Gemini Generate Content API, visita prima la pagina [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) e fai clic sul pulsante "Ottieni" per ottenere le credenziali necessarie per la richiesta.

Se non hai ancora effettuato l'accesso o non ti sei registrato, verrai reindirizzato automaticamente alla pagina di accesso. La prima richiesta include una quota gratuita.

## Utilizzo di base

### Non-Streaming (non in streaming)

Invia una richiesta POST a `/v1beta/models/{model}:generateContent`:

> **Suggerimento**: la serie flash `gemini-3.x` è costituita da modelli di ragionamento, che consumeranno prima reasoning tokens; imposta `generationConfig.maxOutputTokens` a un valore superiore a 512, altrimenti potrebbe essere restituito solo contenuto vuoto.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Esempio di risultato restituito:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

I campi token in `usageMetadata` vengono fatturati secondo la semantica nativa di Gemini:

- `promptTokenCount` include `cachedContentTokenCount`; la parte che colpisce la cache viene calcolata secondo il prezzo di lettura della cache e non viene conteggiata nuovamente come input ordinario.
- `promptTokensDetails` e `cacheTokensDetails` saranno normalizzati in `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` e nei corrispondenti dettagli `cached_*` sotto `usage.prompt_tokens_details`. Questi valori sono inclusi rispettivamente in `prompt_tokens` e `cached_tokens`; le diverse modalità vengono ricalcolate solo secondo i rispettivi prezzi e non vengono fatturate ripetutamente.
- `candidatesTokenCount` e `thoughtsTokenCount` vengono entrambi calcolati secondo il prezzo dei token di output.
- `toolUsePromptTokenCount` è un token di input per strumenti indipendente, calcolato secondo il prezzo dei token di input.

Ace Data Cloud restituisce inoltre un oggetto `usage` normalizzato; tra i protocolli dei modelli, il costo di questa chiamata viene letto uniformemente da `usage.cost`. `cost` è un'anteprima facoltativa del costo; quando l'anteprima del prezzo non è temporaneamente disponibile, la risposta del modello verrà comunque restituita normalmente, ma potrebbe non includere questo campo. La fattura finale fa fede ai record di utilizzo.

### Streaming (in streaming)

Invia una richiesta POST a `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

La restituzione in streaming restituirà gradualmente il contenuto nel formato SSE (Server-Sent Events). Gli eventi intermedi di solito contengono solo contenuti incrementali; l'evento finale con utilizzo autorevole conterrà `usageMetadata` e `usage` normalizzato, e il costo si trova ancora in `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

La chiusura della connessione indica la fine del flusso; il flusso nativo di Gemini non invia `data: [DONE]`. Se l'anteprima del prezzo finale non è temporaneamente disponibile, `usage` restituirà comunque l'utilizzo dei token, ma ometterà `cost`.

### Pensiero interno e riassunti del pensiero

Il pensiero interno del modello e la restituzione di riassunti del pensiero al chiamante sono due impostazioni indipendenti:

- `thinkingBudget` o `thinkingLevel` controllano il budget o la profondità del pensiero interno del modello; i campi e i valori supportati dipendono dal modello.
- `includeThoughts` controlla se restituire i riassunti del pensiero; il valore predefinito è `false`. Quando questo campo viene omesso o viene passato `false`, né le normali risposte JSON né le risposte in streaming SSE restituiscono testo contrassegnato come `thought: true`; questi testi vengono mantenuti solo quando viene esplicitamente passato il valore booleano `true`.

Quando la richiesta non imposta `includeThoughts`, l'interfaccia passa per impostazione predefinita `false` ai modelli di generazione che supportano la configurazione del pensiero, evitando riassunti non necessari alla richiesta; i valori, il budget e il livello di pensiero esplicitamente passati dal cliente vengono mantenuti. Al noto modello `gemini-2.5-flash-image`, che non supporta la configurazione del pensiero, questo campo non viene aggiunto automaticamente, e nemmeno alle richieste `countTokens` viene aggiunta la configurazione di generazione.

Disattivare i riassunti non equivale a disattivare il pensiero interno, né garantisce una riduzione dei token di pensiero interno. Se la risposta contiene ancora testo di pensiero non richiesto, le uscite JSON normali e SSE lo filtrano ulteriormente, mantenendo la risposta normale, le firme e l'utilizzo effettivo.

Quando è necessario visualizzare i riassunti, attivarli esplicitamente come segue. Se il modello non genera un riassunto utilizzabile, potrebbe non esserci testo di pensiero anche se è attivato:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` è uno stato crittografato necessario per i turni successivi, non è testo di riassunto del pensiero e non è controllato dall'interruttore `includeThoughts`. La firma può trovarsi su una risposta normale, una chiamata di funzione o un Part di testo vuoto; durante il filtraggio del testo di pensiero, la firma e gli altri campi dello stesso Part vengono mantenuti, pertanto nella risposta possono rimanere Part che contengono solo una firma e hanno testo vuoto. Quando si mantiene manualmente la cronologia multi-turno, occorre preservare l'ordine di questi Part e la posizione delle firme, senza spostare o unire le firme.

`usageMetadata` e `usage` continuano a registrare l'utilizzo effettivo. Nascondere i riassunti non azzera `thoughtsTokenCount`; la fatturazione continua a essere calcolata in base all'utilizzo effettivo e alle regole tariffarie correnti.

Vedere le [istruzioni ufficiali di Google su pensiero e riassunti del pensiero](https://firebase.google.com/docs/ai-logic/thinking) e le [regole delle firme del pensiero](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

### Chiamata di funzione

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "北京现在的天气怎么样？"}]
    }
  ],
  "tools": [
    {
      "functionDeclarations": [
        {
          "name": "get_weather",
          "description": "获取指定城市的天气信息",
          "parameters": {
            "type": "object",
            "properties": {
              "city": {
                "type": "string",
                "description": "城市名称"
              }
            },
            "required": ["city"]
          }
        }
      ]
    }
  ]
}
```

## Impostazioni di sicurezza

Il filtro dei contenuti può essere controllato tramite `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Gestione degli errori

| Codice di stato HTTP | Significato             |
| -------- | -------------- |
| 400      | Parametri della richiesta non validi         |
| 401      | Autenticazione fallita, controllare il Token |
| 403      | Contenuto bloccato dal filtro di sicurezza     |
| 429      | Richieste troppo frequenti         |
| 500      | Errore interno del server        |
