---
title: "Consultare i task dei modelli Tripo"
description: "Tripo 3D API guide - Ace Data Cloud"
---

Chiama `POST /tripo/tasks` con un token AceDataCloud. La consultazione è gratuita; usa lo stesso account utilizzato per la generazione. Per un singolo task usa `id` o `trace_id`; `action` è impostato su `retrieve` per impostazione predefinita.

```bash
curl -X POST https://api.acedata.cloud/tripo/tasks \
  -H "Authorization: Bearer ${ACEDATACLOUD_API_TOKEN}" \
  -H "Content-Type: application/json" \
  -d "{\"action\":\"retrieve\",\"id\":\"${TASK_ID}\"}"
```

Il risultato di una singola consultazione è il record del task, che contiene `id`, `type`, `trace_id`, la richiesta originale `request`, `started_at` e `progress`. Durante l'elaborazione puoi continuare a consultare il task a intervalli di alcuni secondi. Al termine controlla `response.success`: in caso di successo, `response.data[0].model_url` è l'indirizzo di download; in caso di errore, `response.error` contiene il codice e il messaggio di errore. I timestamp, `finished_at` e il tempo trascorso `elapsed` si trovano al livello superiore del record del task e sono espressi in secondi. Se si verifica `submission_unknown`, conserva l'ID del task originale per le verifiche.

Per la consultazione in batch usa `{"action":"retrieve_batch","ids":["<ID task 1>","<ID task 2>"]}`; puoi anche usare `trace_ids`. Sono consentiti al massimo 100 task per richiesta. La risposta è `{"items":[...],"count":2}` e mantiene l'ordine di input e i duplicati. Per i task non trovati o per i quali non si dispone dell'autorizzazione di lettura, la consultazione singola restituisce `{}`, mentre nella consultazione in batch la posizione corrispondente è `null`.

Il `type` del record del task è `generations`, `models` o `animations`. Per la verifica dello scheletro leggi `response.data[0].riggable`; per le operazioni sui file leggi `response.data[0].model_url`.
