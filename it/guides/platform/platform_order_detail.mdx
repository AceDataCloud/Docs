---
title: "Recuperare i dettagli dell'ordine della piattaforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Interroga un ordine tramite ID ordine. Questo endpoint supporta due modalità di lettura: l'accesso anonimo restituisce solo i campi minimi richiesti dalla pagina di pagamento; quando il proprietario dell'ordine utilizza un Account Token, restituisce i dettagli completi.

## Panoramica dell'interfaccia

| Voce   | Contenuto                                                        |
| --- | --------------------------------------------------------- |
| Metodo  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| Autenticazione  | Opzionale; proiezione minima per accesso anonimo, proiezione completa per proprietario autenticato                                    |

`/orders/{id}` e `/orders/{id}/` sono attualmente entrambi disponibili. L'ID dell'ordine fa parte del link di pagamento e deve essere considerato un identificatore opaco sensibile, non diffonderlo pubblicamente.

## Query anonima

La pagina di pagamento può leggerlo direttamente quando lo stato di accesso viene perso:

```shell
export ORDER_ID='你的订单 ID'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

La risposta anonima include solo `id`, `description`, `price`, `state`, `pay_way`, `pay_url`, `expired_at`, `created_at`. Non restituisce account, Application, Package, identificatori interni di pagamento o metadata.

## Query autenticata

```shell
export PLATFORM_TOKEN='你的账户令牌'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Il proprietario dell'ordine riceverà i dettagli completi dell'Order, inclusi `application` / `applications`, `package` / `packages`, `bank_details`, `invoice_automation` e i campi del modello. Se autenticato ma non proprietario dell'ordine, restituisce `403`; eccetto per i super amministratori.

## Campi chiave

| Campo            | Descrizione                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`, `Paid`, `Finished`, `Expired`, `Failed` o `Refunded` |
| `pay_way`     | Metodo di pagamento corrente dell'ordine; il nome del campo non è `payment_method`                             |
| `pay_url`     | Indirizzo della pagina di pagamento ospitata o del codice QR, potrebbe essere vuoto                                           |
| `price`       | Importo finale dovuto per l'ordine, il modello dell'ordine corrente non fornisce il campo `final_price`                         |
| `amount`      | Quantità di quota del pacchetto; visibile solo nella risposta completa autenticata                                            |
| `finished_at` | Ora di completamento dell'ordine; il nome del campo non è `paid_at`                                      |

La risposta completa può aggiungere campi in base al metodo di pagamento; il client deve leggerli secondo necessità ed evitare sempre di registrare metadata sensibili nella risposta completa.

## Gestione degli errori

- `404`: l'ID dell'ordine non esiste.
- `403`: l'utente ha effettuato l'accesso ma non è il proprietario dell'ordine.
- Le richieste anonime non restituiscono `401`; ottengono solo la proiezione pubblica minima.

## Storno della fattura e nuova richiesta

Tramite `GET /api/v1/orders/{order_id}/invoice/` è possibile leggere la fattura corrente dell'ordine. Dopo l'invio dello storno automatico, la fattura rimane `Issued` e `red_state` indica l'avanzamento dello storno; l'invio riuscito non equivale al completamento dello storno. Durante l'attesa della conferma, l'emissione della nota di credito o l'archiviazione, l'ordine non può richiedere nuovamente una fattura.

Quando un amministratore richiede uno storno a causa di errori nelle informazioni di fatturazione, come intestazione o codice fiscale, il motivo dello storno è “errore di fatturazione”; lo storno automatico attivato dal rimborso dell'ordine continua a utilizzare “interruzione del servizio”.

Dopo che la nota di credito è stata emessa e archiviata con successo, la fattura originale diventa `Voided` e l'ordine può richiedere nuovamente una fattura. La fattura originale può essere visualizzata nella cronologia delle fatture. Se lo storno fallisce o il risultato è in attesa di verifica, verrà gestito dalla verifica finanziaria e l'ordine non vedrà revocata anticipatamente la limitazione di fatturazione. Le fatture emesse manualmente devono prima essere annullate o stornate nel sistema fiscale o di fatturazione, quindi confermate dalla finanza nella piattaforma.
