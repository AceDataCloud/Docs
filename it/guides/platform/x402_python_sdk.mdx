L'SDK Python è adatto per servizi backend, attività di dati, Agent automatizzati e script batch. `acedatacloud` è responsabile delle chiamate API, mentre `acedatacloud-x402` è responsabile della firma dell'header della richiesta `PAYMENT-SIGNATURE`.

Codice sorgente e indirizzi dei pacchetti:

- Repository SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Repository X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- PyPI SDK: [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)
- PyPI X402 Client: [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)

## Installare le dipendenze

```bash
pip install acedatacloud acedatacloud-x402
```

Se si desidera utilizzare `upto`, è inoltre necessario chiamare una volta la CLI di approve Permit2, che dipende da `web3`:

```bash
pip install 'acedatacloud-x402[cli]'
```

Output dell'installazione e del controllo di importazione in un Python venv pulito:

```text
acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
approve-permit2  One-time ERC-20 approve(Permit2, amount) needed before signing upto payments.
```

Spiegazione dei risultati:

- Sia `acedatacloud` sia `acedatacloud-x402` possono essere installati e importati da PyPI.
- `pip install 'acedatacloud-x402[cli]'` include la CLI `approve-permit2`, usata per l'autorizzazione preliminare di `upto`.

## Esempio Base

L'esempio seguente non richiede un API Token. La chiave privata del wallet firma solo localmente e non verrà inviata ad Ace Data Cloud.

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)

print(res["choices"][0]["message"]["content"])
```

L'SDK Python attualmente restituisce un `dict`, quindi l'esempio usa `res["choices"][0]["message"]["content"]`. Non supporre direttamente che abbia necessariamente un attributo `.choices`.

## Esempio Solana

Solana utilizza una secret key codificata in base58:

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import SolanaKeypairSigner, create_x402_payment_handler

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="solana",
        solana_signer=SolanaKeypairSigner.from_base58(os.environ["SOLANA_SECRET_KEY"]),
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

Il percorso Solana costruisce e invia una transazione SPL USDC `TransferChecked`, quindi inserisce la firma della transazione nell'envelope `PAYMENT-SIGNATURE`.

Il paid retry Solana ha già restituito HTTP 200 e `ADC_SOLANA_E2E_OK` sull'API di produzione. In questa query RPC pubblica si è verificata una limitazione della frequenza, quindi la signature on-chain non è stata confermata in modo stabile; se è necessaria una riconciliazione, utilizzare il proprio RPC Solana per interrogare questa transazione.

## Client Async

Lo stesso payment handler può essere utilizzato con `AsyncAceDataCloud`:

```text
import os

from acedatacloud import AsyncAceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AsyncAceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = await client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

## Utilizzare la misurazione posticipata `upto`

Il costo reale di API come chat completion e chiamate al modello potrebbe essere noto solo dopo il termine della risposta. In questo caso, l'API potrebbe restituire contemporaneamente `exact` e `upto`. Se si desidera dare priorità a `upto`:

```python
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
        prefer_scheme="upto",
    )
)
```

Risultato dell'esecuzione del programma Base `upto`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
settlement tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
settled value 3 atomic USDC
```

Conferma on-chain:

```text
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
transfer value 3 atomic USDC
```

Spiegazione dei risultati:

- `content ADC_BASE_UPTO_OK` indica che la richiesta è effettivamente entrata nell'API del modello.
- `settled value 3 atomic USDC` indica che `upto` viene regolato in base all'utilizzo effettivo, anziché addebitare l'intero limite massimo.
- `settlement tx` può essere aperta su BaseScan; durante la riconciliazione, salvare l'hash tx, il payer, il completion id e il riepilogo della richiesta.

`upto` utilizza un'autorizzazione Permit2 per un limite massimo e l'importo effettivo della regolazione non può superare tale limite. Prima del primo utilizzo, è necessario effettuare una volta `approve(Permit2, amount)` per USDC sulla chain di destinazione.

Metodo CLI:

```bash
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Metodo programmatico:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Questo helper è idempotente. Se l'allowance è già sufficiente, restituirà `{"skipped": true}` e non invierà ripetutamente transazioni on-chain.

## Firma di basso livello

Se non si utilizza l'SDK, è anche possibile chiamare direttamente la funzione di firma di basso livello:

```python
import base64
import json

from acedatacloud_x402 import EVMAccountSigner, sign_evm_payment

envelope = sign_evm_payment(requirement, EVMAccountSigner.from_private_key("0x..."))
x_payment = base64.b64encode(json.dumps(envelope, separators=(",", ":")).encode()).decode()
```

Le funzioni di basso livello sono adatte per test, livelli proxy, integrazioni gateway o SDK non ufficiali. Per il codice di business ordinario, utilizzare preferibilmente `create_x402_payment_handler`.
