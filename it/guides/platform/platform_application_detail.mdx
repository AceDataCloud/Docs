Ottieni lo stato completo di una singola richiesta di servizio tramite Application ID — rispetto all'interfaccia elenco, include campi aggiuntivi come l'oggetto `service` completo (inclusi i pacchetti `packages`), adatto per la pagina dei dettagli.

> ℹ️ Questa interfaccia appartiene alla **API di gestione della piattaforma AceDataCloud**, con prefisso unificato `https://platform.acedata.cloud/api/v1/`. Per l'indice completo delle interfacce, consulta [Ottieni l'elenco della documentazione della piattaforma AceDataCloud](https://platform.acedata.cloud/documents/platform-document-list).

## Panoramica dell'interfaccia

| Voce   | Contenuto                                                                    |
| --- | --------------------------------------------------------------------- |
| Metodo  | `GET`                                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/{application_id}` |
| Autenticazione  | ✅ Token dell'account richiesto                                                              |

`/applications/{id}` e `/applications/{id}/` sono attualmente entrambi disponibili; gli esempi usano uniformemente il formato senza barra finale.

## Istruzioni di autenticazione (come ottenere il token dell'account)

Intestazione della richiesta:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Per il metodo dettagliato di ottenimento, consulta [Gestisci il token dell'account della piattaforma AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

> ℹ️ Diversamente dall'interfaccia elenco, **il controllo delle autorizzazioni dell'interfaccia dettagli viene eseguito direttamente su un singolo oggetto**, senza necessità di passare `?user_id=`. Tuttavia, se accedi alla richiesta di un'altra persona riceverai `403 permission_denied`.

## Parametri del percorso

| Parametro               | Tipo   | Obbligatorio  | Descrizione             |
| ---------------- | ---- | --- | -------------- |
| `application_id` | UUID | ✅   | Application ID |

## Esempi di richiesta

### cURL

```shell
curl 'https://platform.acedata.cloud/api/v1/applications/82f57141-2323-4453-8730-60f7d833a2da' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

app_id = "82f57141-2323-4453-8730-60f7d833a2da"
resp = requests.get(
    f"https://platform.acedata.cloud/api/v1/applications/{app_id}",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}",
    },
    timeout=10,
)
app = resp.json()
print(f"Servizio: {app['service']['title']}")
print(f"Rimanenti {app['remaining_amount']} {app['service']['unit']} / utilizzati {app['used_amount']}")
```

### Node.js

```javascript
const appId = '82f57141-2323-4453-8730-60f7d833a2da'
const r = await fetch(`https://platform.acedata.cloud/api/v1/applications/${appId}`, {
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log(await r.json())
```

## Descrizione dei campi di risposta

Il significato dei campi è lo stesso dell'[interfaccia elenco](https://platform.acedata.cloud/documents/platform-application-list), con l'aggiunta di:

| Campo        | Tipo     | Descrizione                                                        |
| --------- | ------ | --------------------------------------------------------- |
| `service` | object | Oggetto del servizio completo (inclusi i pacchetti `packages`, `unit`, `free_amount`), utilizzabile direttamente per il rendering del pannello dei dettagli del servizio |

## Gestione degli errori

| HTTP | code                | Significato                  |
| ---- | ------------------- | ------------------- |
| 401  | `not_authenticated` | Token dell'account mancante              |
| 403  | `permission_denied` | Questa Application non ti appartiene  |
| 404  | `not_found`         | L'Application non esiste o è stata eliminata |

## Suggerimenti pratici

- **Per il monitoraggio in batch, usa preferibilmente l'elenco**: dopo aver recuperato una volta l'elenco delle Application, valuta in base all'unità e alle soglie di ciascun servizio, evitando di richiedere i dettagli uno per uno.
- **Quando devi visualizzare il numero di credenziali**: usa l'[elenco delle credenziali API](https://platform.acedata.cloud/documents/platform-credential-list) filtrando per `application_id`.
- **Approccio di verifica per `disabled=true`**: controlla ticket / notifiche e-mail, per verificare se il servizio è stato disattivato a causa di controllo del rischio, insolvenza o chiamate non conformi; non può essere riattivato tramite API, devi contattare il servizio clienti.
