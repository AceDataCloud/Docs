---
title: "Ottenere le statistiche aggregate delle chiamate API della piattaforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Aggrega per data e API il numero di richieste e l'importo effettivamente detratto dell'account corrente, adatto per creare report mensili, grafici delle tendenze e analisi dei costi. Per il debug voce per voce, utilizzare l'[elenco dei record delle chiamate](https://platform.acedata.cloud/documents/platform-usage-list); per i dettagli offline completi, utilizzare l'[esportazione del volume delle chiamate](https://platform.acedata.cloud/documents/platform-usage-export).

L'intervallo di query dei record delle chiamate e dei riepiloghi di fatturazione è costituito dagli ultimi 60 giorni; i corpi delle richieste e delle risposte vengono conservati separatamente per gli ultimi 30 giorni. La scadenza dei corpi non modifica l'addebito effettivo, l'utilizzo o le statistiche aggregate di quel record.

## Preparazione

1. Accedere alla [piattaforma AceDataCloud](https://platform.acedata.cloud).
2. Creare un token dell'account nella [console Account Token](https://platform.acedata.cloud/console/platform-tokens) e salvarlo immediatamente.
3. Se è necessario restringere l'ambito, ottenere l'ID corrispondente dall'[elenco delle richieste di servizio](https://platform.acedata.cloud/documents/platform-application-list), dall'[elenco delle credenziali API](https://platform.acedata.cloud/documents/platform-credential-list) o dall'[elenco delle API](https://platform.acedata.cloud/documents/platform-api-list).

Per la descrizione completa del token, vedere [gestire i token dell'account](https://platform.acedata.cloud/documents/platform-token). Questa interfaccia utilizza Account Token e non utilizza Credential aziendali.

```shell
export PLATFORM_TOKEN='你的账户令牌'
```

## Panoramica dell'interfaccia

| Voce           | Contenuto                                                     |
| -------------- | ------------------------------------------------------------- |
| Metodo         | `GET`                                                         |
| URL            | `https://platform.acedata.cloud/api/v1/usage/apis/aggregate/` |
| Autenticazione | `Authorization: Bearer ${PLATFORM_TOKEN}`                     |
| OAuth Scope    | `usage:read`（`platform:read` / `platform` possono includerlo） |
| Ambito permessi | Per gli utenti normali è fisso al proprio utilizzo a pagamento; gli amministratori possono passare `user_id` |

## Parametri di query

| Parametro         | Tipo            | Obbligatorio | Predefinito                                  | Descrizione                                                  |
| ----------------- | --------------- | ----------- | --------------------------------------------- | ------------------------------------------------------------ |
| `created_at_from` | date / datetime | No          | Primo giorno del mese corrente nel fuso orario selezionato | Ora di inizio, nome del parametro consigliato                |
| `created_at_to`   | date / datetime | No          | Ora corrente                                  | Ora di fine, nome del parametro consigliato                  |
| `timezone`        | string          | No          | `UTC`                                         | Fuso orario IANA, ad esempio `Asia/Shanghai`; i valori non validi ricadono su UTC |
| `service_id`      | UUID            | No          | —                                             | Filtra per servizio; supporta parametri ripetuti             |
| `application_id`  | UUID            | No          | —                                             | Filtra per Application; supporta parametri ripetuti          |
| `api_id`          | UUID            | No          | —                                             | Filtra per API; supporta parametri ripetuti                  |
| `credential_id`   | UUID            | No          | —                                             | Filtra per credenziale API; supporta parametri ripetuti      |
| `include_models`  | boolean         | No          | `false`                                       | Se calcolare ulteriormente il riepilogo per dimensione del modello; aumenta il costo della query |
| `user_id`         | UUID            | No          | Per gli utenti normali è fisso a sé stessi; per gli amministratori, se omesso, è per tutti gli account | Solo gli amministratori possono specificare qualsiasi account |

`start_time` / `end_time` possono ancora essere utilizzati come alias di compatibilità per i client precedenti; le nuove integrazioni utilizzano uniformemente `created_at_from` / `created_at_to`. La forma data di `created_at_to` includerà quel giorno naturale, ovvero utilizzerà la mezzanotte del giorno successivo come limite.

## Esempi di richiesta

Interroga il riepilogo giornaliero/API del mese corrente nell'ora di Pechino, includendo la dimensione del modello:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  --data-urlencode 'include_models=true' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Interroga l'utilizzo di una settimana per l'Application specificata:

```shell
export APPLICATION_ID='你的 Application ID'

curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'created_at_from=2026-09-01' \
  --data-urlencode 'created_at_to=2026-09-07' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Esempio Python:

```python
import os
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/usage/apis/aggregate/",
    headers={"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    params={
        "created_at_from": "2026-09-01",
        "created_at_to": "2026-09-07",
        "timezone": "Asia/Shanghai",
        "include_models": "true",
    },
    timeout=30,
)
response.raise_for_status()
data = response.json()
print("requests:", data["requests"], "deducted:", data["total"])
for row in data["items"]:
    print(row["date"], row["api_id"], row["amount"])
```

## Esempio di risposta

```json
{
  "items": [
    {
      "date": "2026-09-01",
      "api_id": "00000000-0000-4000-8000-000000000001",
      "amount": 12.5
    }
  ],
  "total": 12.5,
  "apis": {
    "00000000-0000-4000-8000-000000000001": {
      "title": "Example API"
    }
  },
  "requests": 42,
  "models": [
    {
      "model": "example-model",
      "amount": 12.5,
      "requests": 42
    }
  ]
}
```

## Campi della risposta

| Campo      | Descrizione                                                        |
| ---------- | ------------------------------------------------------------------ |
| `items`    | Raggruppati per data nel fuso orario selezionato e `api_id`; ogni riga contiene `date`, `api_id`, `amount` |
| `total`    | Somma di `deducted_amount` nell'intervallo di query               |
| `apis`     | Mappatura dall'ID API al riepilogo del titolo, per facilitare la visualizzazione di `items` |
| `requests` | Numero totale di richieste nell'intervallo di query               |
| `models`   | Calcolato solo quando `include_models=true`; ogni elemento contiene `model`, `amount`, `requests` |

L'unità dell'importo dipende da `service.unit` dell'Application correlata. Se la query include servizi con unità diverse, eseguire prima statistiche separate per `service_id` o `application_id`, evitando confronti o somme diretti.

Quando l'ora di fine non è maggiore dell'ora di inizio, l'interfaccia restituisce una struttura vuota completa: `items=[]`, `total=0`, `apis={}`, `requests=0`, `models=[]`.

## Errori e suggerimenti sulle prestazioni

| HTTP | `error`                 | Gestione                                      |
| ---- | ----------------------- | --------------------------------------------- |
| 400  | `usage_history_expired` | Regolare l'intervallo di tempo a dopo `available_from` nella risposta |
| 401  | `not_authenticated`     | Controllare Account Token, non utilizzare per errore Credential aziendali |
| 403  | `permission_denied`     | Gli utenti normali non possono interrogare altri account |

- Per impostazione predefinita, non attivare `include_models`; abilitarlo solo quando il report necessita effettivamente della suddivisione per modello.
- Per le query su intervalli ampi, separare prima per `service_id` o `application_id`, evitando sia unità miste sia costi di query più elevati.
- Le date senza chiamate non vengono automaticamente riempite con zero; il client deve completare l'asse delle date prima di disegnare il grafico.
