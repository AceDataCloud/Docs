title: "Ottenere l'elenco delle richieste di servizio della piattaforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Restituisce in modo paginato le Application possedute o autorizzate per l'uso dall'account, inclusi saldo, stato, riepilogo del servizio e credenziali associate. Adatto per il monitoraggio batch del saldo, la ricerca dell'Application ID e l'accesso alla gestione delle credenziali.

## Preparazione

1. Accedi alla [piattaforma AceDataCloud](https://platform.acedata.cloud).
2. Crea un token dell'account nella [console Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. Gli utenti normali usano `user_id=me`; puoi anche ottenere il tuo UUID da `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='il tuo token dell'account'
```

## Panoramica dell'interfaccia

| Voce   | Contenuto                                                    |
| --- | ----------------------------------------------------- |
| Metodo  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Autenticazione  | Account Token, il token OAuth richiede `applications:read`       |
| Paginazione  | `count` + `items`                                     |

Gli utenti normali devono passare `user_id=me`. Se non viene passato, la query non viene prima ristretta per account e la paginazione potrebbe restituire `403` in caso di oggetti non autorizzati; gli amministratori possono visualizzare l'intera tabella se non lo passano.

## Parametri di query

| Parametro            | Tipo          | Obbligatorio     | Descrizione                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Obbligatorio per utenti normali | Soggetto della query; supporta parametri ripetuti                                         |
| `affiliation` | string      | No      | `owner` (predefinito) o `granted`; è possibile passare entrambi ripetutamente per ottenerne l'unione, valido solo quando è presente `user_id` |
| `service_id`  | UUID        | No      | Filtra per servizio; supporta parametri ripetuti                                        |
| `scope`       | string      | No      | `Individual` o `Global`; supporta parametri ripetuti                      |
| `type`        | string      | No      | `Usage` o `Period`; supporta parametri ripetuti                           |
| `limit`       | integer     | No      | Numero di elementi per pagina, massimo 100                                         |
| `offset`      | integer     | No      | Offset della paginazione                                               |
| `ordering`    | string      | No      | Supporta solo `created_at` o `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` e `tag` non sono attualmente parametri di filtro lato server. Per gli avvisi sul saldo, dopo aver ottenuto l'elenco, il client deve effettuare la valutazione in base a `remaining_amount`, `service.unit` e alle soglie aziendali di ciascuna Application.

## Esempio di richiesta

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Visualizza contemporaneamente le Application possedute e quelle autorizzate da altri a te:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Descrizione della risposta

La risposta è `{count, items}`. Ogni elemento contiene i campi del modello Application, più:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: riepilogo delle credenziali che il chiamante corrente è autorizzato a vedere;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`;
- il valore effettivo di `scope` è `Individual` o `Global`;
- il valore effettivo di `type` è `Usage` o `Period`.

`remaining_amount` potrebbe essere vuoto; il client deve prima verificare che non sia vuoto, quindi effettuare il confronto numerico. L'unità della quota è determinata da `service.unit`.
