Restituisce in modo paginato le Application possedute dall'account o autorizzate all'uso, inclusi saldo, stato, riepilogo del servizio e credenziali associate. Adatto al monitoraggio batch del saldo, alla ricerca dell'ID Application e all'accesso alla gestione delle credenziali.

## Preparazione

1. Accedi alla [piattaforma AceDataCloud](https://platform.acedata.cloud).
2. Crea un token dell'account nella [console Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. Gli utenti normali utilizzano `user_id=me`; puoi anche ottenere il tuo UUID da `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='il tuo token dell'account'
```

## Panoramica dell'interfaccia

| Voce   | Contenuto                                             |
| --- | ----------------------------------------------------- |
| Metodo  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Autenticazione  | Account Token, l'OAuth token richiede `applications:read`       |
| Paginazione  | `count` + `items`                                     |

Gli utenti normali devono passare `user_id=me`. Se non viene passato, la query non viene prima ristretta per account e la paginazione potrebbe restituire `403` quando incontra oggetti non autorizzati; se un amministratore non lo passa, può visualizzare l'intera tabella.

## Parametri di query

| Parametro            | Tipo          | Obbligatorio     | Descrizione                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Obbligatorio per utenti normali | Soggetto della query; supporta parametri ripetuti                                         |
| `affiliation` | string      | No      | `owner` (predefinito) o `granted`; entrambi possono essere passati ripetutamente per ottenere l'unione, efficace solo quando è presente `user_id` |
| `service_id`  | UUID        | No      | Filtra per servizio; supporta parametri ripetuti                                        |
| `scope`       | string      | No      | `Individual` o `Global`; supporta parametri ripetuti                      |
| `type`        | string      | No      | `Usage` o `Period`; supporta parametri ripetuti                           |
| `limit`       | integer     | No      | Numero di elementi per pagina, massimo 100                                         |
| `offset`      | integer     | No      | Offset di paginazione                                               |
| `ordering`    | string      | No      | Supporta solo `created_at` o `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` e `tag` al momento non sono parametri di filtro lato server. Per gli avvisi di saldo, dopo aver recuperato l'elenco, devi valutare lato client in base a `remaining_amount`, `service.unit` e alle soglie di business di ogni Application.

## Esempio di richiesta

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Visualizza contemporaneamente le Application che possiedi e quelle che altri hanno autorizzato per te:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Descrizione della risposta

La risposta è `{count, items}`. Ogni elemento contiene i campi del modello Application e include inoltre:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: riepilogo delle credenziali che il chiamante corrente è autorizzato a vedere;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`, `allow_overdraft`;
- il valore effettivo di `scope` è `Individual` o `Global`;
- il valore effettivo di `type` è `Usage` o `Period`.

`allow_overdraft` è un campo booleano di sola lettura controllato dall'amministratore, con valore predefinito `false`. Per le applicazioni a consumo (`Usage`) con scoperto abilitato, un saldo insufficiente non impedisce le chiamate e l'addebito avviene comunque in base all'utilizzo effettivo; un saldo negativo rappresenta un importo in attesa di regolamento. La disabilitazione, la scadenza e i limiti delle credenziali API restano comunque validi.

`remaining_amount` potrebbe essere vuoto; il client deve prima verificarne l'assenza, quindi effettuare il confronto numerico. L'unità dell'importo è determinata da `service.unit`.
