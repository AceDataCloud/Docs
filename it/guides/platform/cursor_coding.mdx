Il Cursor attualmente fornisce la chiave API di OpenAI e l'impostazione **Override OpenAI Base URL**, che consente di connettersi a servizi compatibili con OpenAI. Questa funzionalità esiste, ma le diverse versioni gestiscono `/chat/completions`, `/responses`, l'elenco dei modelli e modalità come Agent/Composer in modo non completamente coerente.

La compatibilità tra diverse versioni di Cursor, sistemi operativi e modalità di richiesta può variare. Si prega di completare il controllo della modalità effettiva secondo la configurazione di questa pagina, senza dedurre che tutte le funzionalità siano disponibili basandosi sul successo di una singola chat.

## Cosa garantisce attualmente il BYOK ufficiale di Cursor

Secondo la [documentazione ufficiale di Cursor Bring your own API key](https://cursor.com/help/models-and-usage/api-keys):

- Supporta le credenziali di OpenAI, Anthropic, Google, Azure OpenAI e AWS Bedrock;
- La chiave API personalizzata è utilizzata solo per i modelli di chat, il completamento delle schede continua a utilizzare i modelli integrati di Cursor;
- La chiave API non è persistente sui server di Cursor, ma viene inviata al backend di Cursor ad ogni richiesta, per la costruzione finale del prompt;
- Quando si utilizza una chiave propria, la politica di Zero Data Retention di Cursor non si applica, il trattamento dei dati segue le politiche del fornitore scelto.

## Configurazione

1. Aprire le Impostazioni di Cursor → Modelli.
2. Inserire il proprio Token API di Ace Data Cloud in OpenAI API Key.
3. Abilitare **Override OpenAI Base URL**, inserendo `https://api.acedata.cloud/v1`.
4. Selezionare o aggiungere un ID modello preciso compatibile con il protocollo attuale di Cursor.
5. Inviare prima `Reply only OK`, poi testare separatamente le modalità Ask/Edit/Agent che si utilizzano effettivamente.

## Limiti attuali

- La chiave API personalizzata è utilizzata solo per i modelli di chat, il completamento delle schede continua a utilizzare i modelli integrati di Cursor.
- Cursor potrebbe comunque completare la costruzione finale del prompt sul server; si prega di valutare il percorso dei dati in base alle informazioni sulla privacy ufficiali.
- L'Override del Base URL potrebbe coprire solo alcune richieste, o a causa di variazioni di versione passare tra Chat Completions/Responses.
- Non si dovrebbe affermare che Agent, Auto, Composer o attività in background siano tutti attivi solo perché una richiesta di chat ha avuto successo.

## Controllo completo della compatibilità

Per un utilizzo a lungo termine nei flussi di lavoro di produzione, completare anche i seguenti controlli:

1. Versione e sistema operativo di Cursor fissi;
2. Completare un test smoke reale del client per quella versione e registrare il protocollo e il percorso della richiesta finale;
3. Richiesta di Chat Completions per il modello esatto ha avuto successo;
4. Le chiamate agli strumenti e le richieste di Agent passano effettivamente attraverso l'endpoint target;
5. Il consumo e la fatturazione possono essere verificati;
6. Registrare chiaramente se la richiesta è passata attraverso il server di Cursor e le relative limitazioni sulla privacy.

Dopo un aggiornamento del client, è necessario rieseguire questi controlli per confermare che non ci siano state variazioni nel protocollo delle richieste, nelle chiamate agli strumenti e nei percorsi dei dati.
