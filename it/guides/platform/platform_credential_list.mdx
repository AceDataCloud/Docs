Elenca in modo paginato le credenziali API aziendali. Questa risposta contiene attualmente campi sensibili delle credenziali Token o Identity, che devono essere elaborati solo lato server ed è vietato scriverli nei log, nelle piattaforme di analisi, nella persistenza frontend o nei repository pubblici.

## Preparazione

Crea un [Account Token](https://platform.acedata.cloud/documents/platform-token) e ottieni l'UUID dell'account corrente tramite `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='il tuo token dell’account'
export USER_ID='il tuo UUID dell’account'
```

## Panoramica dell'interfaccia

| Voce   | Contenuto                                                   |
| --- | ---------------------------------------------------- |
| Metodo  | `GET`                                                |
| URL | `https://platform.acedata.cloud/api/v1/credentials/` |
| Autenticazione  | Account Token, il token OAuth richiede `credentials:read`       |
| Paginazione  | `count` + `items`                                    |

Gli utenti normali devono passare il proprio `user_id` o un `application_id` già autorizzato, altrimenti potrebbe essere restituito `403` quando la paginazione incontra oggetti non autorizzati.

## Parametri di query

| Parametro                 | Tipo      | Obbligatorio  | Descrizione                             |
| ------------------ | ------- | --- | ------------------------------ |
| `user_id`          | string  | A seconda dello scenario | Titolare delle credenziali; supporta parametri ripetuti                   |
| `application_id`   | UUID    | No   | Filtra per Application; supporta parametri ripetuti        |
| `host`             | string  | No   | Filtra esattamente per host; supporta parametri ripetuti             |
| `name`             | string  | No   | Filtra esattamente per nome; supporta parametri ripetuti                 |
| `granted`          | boolean | No   | `true` indica credenziali concesse ad altri, `false` indica credenziali per uso proprio |
| `limit` / `offset` | integer | No   | Paginazione                             |
| `ordering`         | string  | No   | `created_at` o `-created_at`   |

`service_id`, `disabled` ed `expired` non sono attualmente parametri di filtro.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/credentials/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Descrizione della risposta

La risposta verificata online è `{count, items}`. Ogni elemento include `id`, `application_id`, `application`, `user_id`, `creator_id`, `name`, `type`, `limited_amount`, `used_amount`, `expired_at`, `allowed_api_ids`, `host`, `granted`, `granted_to_user_id`, `tags`, `metadata` e i campi temporali, e restituisce `token` oppure `username/password` in base al tipo.

> L'attuale risposta dell'elenco restituisce valori sensibili completi. Non mostrarli nella console del browser o nei sistemi di raccolta, né fare affidamento sul recupero del testo in chiaro tramite l'elenco; il client deve essere compatibile con future strategie di mascheramento.
