title: "Creare credenziali API della piattaforma AceDataCloud"

---

Creare credenziali API aziendali per un'Application. La risposta di creazione può contenere un Token che può chiamare direttamente `https://api.acedata.cloud/**`, oppure il nome utente/password delle credenziali di tipo Proxy; devono essere trattati come segreti.

## Preparazione

1. Creare un [Account Token](https://platform.acedata.cloud/documents/platform-token).
2. Ottenere il proprio `application_id` dall'[elenco Application](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='il tuo token account'
export APPLICATION_ID='il tuo Application ID'
```

## Panoramica dell'interfaccia

| Voce    | Contenuto                                                   |
| ---- | ---------------------------------------------------- |
| Metodo   | `POST`                                               |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/` |
| Autenticazione   | Account Token, l'OAuth token richiede `credentials:write`      |
| Body | JSON                                                 |

## Corpo della richiesta

| Campo                  | Tipo              | Obbligatorio  | Descrizione                            |
| ------------------- | --------------- | --- | ----------------------------- |
| `application_id`    | UUID            | Sì   | Application di destinazione                |
| `name`              | string          | No   | Nome visualizzato delle credenziali                         |
| `limited_amount`    | number / null   | No   | Limite di utilizzo per singola credenziale; `null` indica nessun limite indipendente       |
| `expired_at`        | datetime / null | No   | Ora di scadenza ISO 8601                 |
| `allowed_api_ids`   | UUID[] / null   | No   | Consente di chiamare solo queste API; un array vuoto verrà normalizzato come nessuna restrizione       |
| `host`              | string          | No   | Informazioni host delle credenziali                    |
| `for_user_id`       | string          | No   | Utilizzato quando il proprietario dell'Application emette credenziali autorizzate per un altro utente |
| `tags` / `metadata` | array / object  | No   | Dati di estensione personalizzati                       |

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/credentials/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"name\":\"production\",\"limited_amount\":50}"
```

## Descrizione della risposta

In caso di successo restituisce `201` e l'oggetto Credential:

- I servizi di tipo API/Agent restituiscono solitamente `type=Token` e `token`;
- I servizi di tipo Proxy restituiscono solitamente `type=Identity` e `username` / `password`, e una Proxy Application consente una sola credenziale;
- `id`, `user_id`, `creator_id`, `used_amount` e i campi temporali vengono generati dal server.

Anche le attuali interfacce di elenco e dettaglio restituiscono le credenziali in chiaro, ma il client non deve dipendere da questo comportamento storico. Salvarle immediatamente dopo la creazione, evitare di scrivere la risposta nei log; le interfacce future potrebbero essere modificate per restituire dati mascherati.

## Gestione degli errori

- `400`: formato dei campi errato, `allowed_api_ids` sconosciuti, Proxy Application con credenziali già esistenti o altri vincoli di creazione.
- `401`: Account Token non valido.
- `403/404`: nessun diritto di accesso all'Application di destinazione, oppure Application/utente autorizzato inesistente.
