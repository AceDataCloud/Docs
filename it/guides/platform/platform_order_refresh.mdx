---
title: "Aggiornare lo stato dell'ordine della piattaforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Interroga attivamente lo stato più recente del metodo di pagamento corrispondente all'ordine e sincronizzalo con la piattaforma. Questa richiesta potrebbe accedere al servizio di pagamento e modificare lo stato dell'ordine; utilizzala solo in caso di ritardo del callback o quando è necessaria una conferma immediata.

## Preparazione

- Utilizza [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Ottieni il tuo ID ordine dall'[elenco ordini](https://platform.acedata.cloud/documents/platform-order-list).

```shell
export PLATFORM_TOKEN='il tuo token dell’account'
export ORDER_ID='il tuo ID ordine'
```

## Panoramica dell'interfaccia

| Voce    | Contenuto                                                                 |
| ---- | ------------------------------------------------------------------ |
| Metodo   | `POST`                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/refresh/` |
| Autenticazione   | Proprietario dell'ordine o super amministratore                                                        |
| Body | Generalmente vuoto; nello scenario di callback PayPal potrebbe essere necessario `payer_id` / `PayerID`                         |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/refresh/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

In caso di successo, restituisce l'oggetto Order completo aggiornato. Utilizza `state` per determinare il risultato e `finished_at` come ora di completamento; il modello corrente non dispone del campo `paid_at`. I valori di stato includono `Pending`, `Paid`, `Finished`, `Expired`, `Failed`, `Refunded`.

La scadenza del pagamento modifica in `Expired` solo gli ordini ancora nello stato `Pending`. Gli ordini `Refunded` già rimborsati mantengono lo stato rimborsato anche dopo l'aggiornamento o la ricezione di un callback di pagamento ritardato.

## Suggerimenti per i tentativi

- Per i pagamenti normali, affidati preferibilmente ai callback della piattaforma; esegui attivamente il refresh solo quando lo stato non si aggiorna per molto tempo.
- Non effettuare polling ad alta frequenza fisso. Si consiglia il backoff esponenziale e l'interruzione dopo il raggiungimento di uno stato terminale esplicito.
- `401` indica che il token non è valido; `403` indica che non sei il proprietario dell'ordine; `404` indica che l'ordine non esiste.
- Quando la query del servizio di pagamento fallisce, conserva l'ID ordine e il trace ID, quindi riprova più tardi; non creare ordini duplicati come alternativa alla conferma dello stato.
