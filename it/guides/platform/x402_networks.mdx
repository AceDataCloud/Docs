Ace Data Cloud X402 attualmente effettua il regolamento in USDC e supporta due tipi di chain: EVM e Solana. Le modalità di firma, gli indirizzi degli asset, il comportamento del gas e gli scenari applicabili differiscono tra le reti, quindi è necessario scegliere la rete prima dell'integrazione.

## Gli identificatori di rete utilizzano CAIP-2

`accepts[].network` di x402 v2 è un identificatore CAIP-2, non un'abbreviazione come `base` o `skale`. Quando il client abbina le reti, deve confrontare le stringhe CAIP-2:

| Rete             | Identificatore CAIP-2                      |
| -------------- | ----------------------------------------- |
| Base           | `eip155:8453`                             |
| SKALE Base     | `eip155:1187947933`                       |
| Solana mainnet | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` |

## Matrice di supporto

| Rete     | scheme  | Asset                  | Modalità di firma                        | Scenario applicabile               |
| ------ | ------- | ------------------- | ------------------------------------ | --------------------------- |
| Base   | `exact` | Base USDC           | EIP-3009 `TransferWithAuthorization` | Consigliato per impostazione predefinita, supporto maturo di wallet e liquidità. |
| Base   | `upto`  | Base USDC + Permit2 | Permit2 `PermitWitnessTransferFrom`  | API a misurazione successiva come chat e modelli. |
| SKALE  | `exact` | SKALE bridged USDC  | EIP-3009 `TransferWithAuthorization` | Basso costo del gas, adatto alla verifica dei pagamenti EVM e alle chiamate a basso costo. |
| Solana | `exact` | Solana USDC         | SPL `TransferChecked`                | Scenari di wallet Solana, Agent o applicazioni on-chain. |

`upto` è attualmente disponibile solo su Base. Le opzioni effettivamente disponibili sono soggette a `accepts` restituito dall'API. Puoi anche consultare il Facilitator:

```bash
curl https://facilitator.acedata.cloud/supported
```

La risposta di Facilitator `/supported`:

```json
{
  "kinds": [
    { "x402Version": 2, "scheme": "exact", "network": "eip155:8453" },
    {
      "x402Version": 2,
      "scheme": "upto",
      "network": "eip155:8453",
      "extra": { "facilitatorAddress": "0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708" }
    },
    { "x402Version": 2, "scheme": "exact", "network": "eip155:1187947933" },
    {
      "x402Version": 2,
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "extra": { "feePayer": "3SPm6qbgsDkj24MuR8Ss4sH97fziqyCiqFKDyeVU2igq" }
    }
  ]
}
```

Spiegazione dei risultati:

- Gli `exact` di Base, SKALE e Solana sono percorsi di pagamento a importo fisso.
- Solo Base fornisce il percorso di misurazione successiva `upto`, che dipende dall'approve Permit2.
- `extra.facilitatorAddress` nella voce `upto` è l'indirizzo che il client deve scrivere nel witness durante la firma e deve corrispondere al valore restituito dal server.

## Base

Base utilizza il contratto USDC ufficiale:

```text
0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
```

Nello schema `exact`, il client firma `TransferWithAuthorization` EIP-712. Il contenuto della firma include:

- `from`: indirizzo del wallet pagatore
- `to`: indirizzo di ricezione di Ace Data Cloud
- `value`: importo di questo pagamento
- `validAfter` / `validBefore`: finestra temporale di validità della firma
- `nonce`: nonce casuale di 32 byte

Dopo aver verificato la firma, il Facilitator chiamerà `transferWithAuthorization` di USDC on-chain per completare il trasferimento.

Base è la rete di integrazione ufficiale più consigliata, particolarmente adatta alla misurazione successiva `upto`, poiché gli ecosistemi di Permit2, USDC e wallet sono tutti più maturi.

Esempio di risultato della verifica Base `exact`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
content ADC_BASE_E2E_OK
tx 0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
block 46726299
explorer https://basescan.org/tx/0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
transfer value 95215 atomic USDC
```

Spiegazione dei risultati:

- Il retry API pagato restituisce il contenuto del modello `ADC_BASE_E2E_OK`.
- La transazione on-chain è consultabile su BaseScan e il numero del blocco è `46726299`.
- `95215` USDC atomic corrisponde a `0.095215` USDC, ovvero l'importo effettivo regolato per questa chiamata API.

Risultato dell'esecuzione del programma per il pagamento dell'ordine Base `exact`:

```text
order 78481793-304e-47f7-bc0c-8231aec9cc1e
state Finished
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer value 1200000 atomic USDC
```

Spiegazione dei risultati:

- Lo stato finale dell'ordine sulla piattaforma è `Finished`.
- Il `pay_id` dell'ordine viene scritto nello stesso hash della transazione Base.
- `1200000` USDC atomic corrisponde a `1.2` USDC, ovvero l'importo storico effettivamente pagato per questo ordine da 10 Credits secondo la vecchia politica; i nuovi ordini non usufruiscono più di uno sconto aggiuntivo per il metodo di pagamento X402, e l'importo specifico della firma è soggetto alla risposta 402 di questa volta.

## SKALE

SKALE utilizza USDC bridged e la modalità di firma è simile a Base, anch'essa EIP-3009. È adatta a scenari di pagamento EVM a basso costo del gas; le chiamate effettive sono comunque soggette a `accepts` restituito dall'API.

I tipici `accepts` 402 di SKALE includono:

```json
{
  "network": "eip155:1187947933",
  "scheme": "exact",
  "extra": {
    "name": "Bridged USDC (SKALE Bridge)",
    "version": "2",
    "chainId": 1187947933,
    "verifyingContract": "0x85889c8c714505E0c94b30fcfcF64fE3Ac8FCb20"
  }
}
```

SKALE attualmente fornisce solo `exact`. Se hai bisogno della misurazione successiva, utilizza Base `upto`.

Esempio di risultato della verifica SKALE `exact`:

```text
content ADC_SKALE_E2E_OK
tx 0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
block 1969317
explorer https://skale-base-explorer.skalenodes.com/tx/0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
paid 0.095215 USDC
```

Spiegazione dei risultati:
- Il retry dell'API pagata restituisce il contenuto del modello `ADC_SKALE_E2E_OK`。
- La transazione è già consultabile nello SKALE explorer, il numero di blocco è `1969317`。
- L'importo di regolamento di questo pagamento `exact` è `0.095215` USDC。

## Solana

Solana utilizza SPL USDC `TransferChecked`。Il client costruirà una transazione di trasferimento, la firmerà e la invierà, quindi inserirà la firma della transazione o la transazione serializzata nell'envelope `PAYMENT-SIGNATURE`。

Caratteristiche di Solana:

- utilizza Solana wallet adapter o una base58 secret key；
- l'asset è il mint USDC di Solana；
- attualmente supporta solo `exact`；
- Il Facilitator verificherà il mint, la destination, l'authority e l'amount della transfer instruction。

Se si utilizza la modalità wallet fee payer, il wallet invierà direttamente la transazione, il Facilitator sarà responsabile della conferma della transazione e della restituzione del risultato di settlement。

Esempio di risultato della verifica Solana `exact`:

```text
payer AY2RmGm2zPxB1uKvvF4dKyYdr2VySyL3wcD1MKJZoLRd
HTTP 402 -> HTTP 200
content ADC_SOLANA_E2E_OK
chain signature not confirmed in this run
```

Spiegazione del risultato:

- il retry pagato ha già restituito HTTP 200, e il modello ha prodotto `ADC_SOLANA_E2E_OK`。
- Durante l'interrogazione della signature on-chain tramite RPC pubblico potrebbe verificarsi il rate limiting。
- Poiché le interrogazioni RPC pubbliche possono essere limitate, qui non viene indicato il Solana explorer。Quando è necessario un riconciliazione rigorosa, utilizzare il proprio Solana RPC o i record di settlement lato piattaforma per confermare la firma della transazione。

## Come scegliere

| Cosa vuoi fare | Rete consigliata |
| ------------ | ---------------------------- |
| Completare rapidamente il flusso minimo | SKALE `exact` o Base `exact` |
| Rivolgersi a normali utenti Web3 | Base |
| Eseguire misurazioni post-utilizzo come il completamento della chat | Base `upto` |
| Applicazioni dell'ecosistema Solana | Solana `exact` |
| Verifica dei pagamenti EVM a basso costo | SKALE `exact` |

Indipendentemente dalla chain scelta, non hardcodare i prezzi nel client。Il prezzo è determinato da `accepts[].maxAmountRequired` restituito dal server。

## Nuove reti EVM

I pagamenti a importo fisso in USDC nativo delle seguenti reti dispongono del supporto nel codice e vengono abilitati una rete alla volta。
L'effettiva disponibilità dipende dall'ordine o dagli `accepts` restituiti dall'API；non significa che tutte le reti siano già abilitate in produzione。

| Rete      | Alias      | CAIP-2         | USDC nativo                                  |
| ------------ | ---------- | -------------- | -------------------------------------------- |
| Arbitrum One | `arbitrum` | `eip155:42161` | `0xaf88d065e77c8cC2239327C5EDb3A432268e5831` |

Queste reti supportano solo `exact`, e la precisione della valuta è 6。Non utilizzare USDC bridged con lo stesso nome。
Quando si utilizza l'X402 Client TypeScript/Python ufficiale, è possibile passare l'abbreviazione nella tabella o l'identificatore CAIP-2。
Il client utilizza il chain ID di destinazione per costruire la firma；il wallet deve supportare la rete di destinazione。

La tabella di supporto ufficiale dell'estensione wallet Phantom elenca Arbitrum e Polygon；Optimism e Avalanche
al momento non sono elencati in tale tabella, è possibile utilizzare Rabby o MetaMask che supportano la chain di destinazione。Gli indirizzi EVM possono essere uguali su chain diverse,
ma i saldi sono indipendenti tra loro, gli indirizzi Solana non sono applicabili a EVM USDC。
Vedere la [tabella di supporto del wallet Phantom](https://docs.phantom.com/wallet-sdks-overview#chain-support)。

### Punto di accesso graduale per le nuove reti

L'accesso alle nuove chain è nascosto per impostazione predefinita。Quando si accede alla console o a Studio, è possibile usare `?features=x402-arbitrum`
per abilitare la chain corrispondente, più flag sono separati da virgole。Per disabilitare una singola chain usare `?features=-x402-arbitrum`，
per cancellare gli override locali usare `?features=none`。Le opzioni vengono salvate separatamente per ciascun dominio。
Le quotazioni degli ordini e i retry dei pagamenti utilizzano la stessa opzione, il server verificherà indipendentemente；i record di pagamento esistenti restano consultabili。
L'abilitazione del solo flag della pagina non abiliterà chain non ancora configurate, le reti effettivamente pagabili dipendono comunque dagli `accepts` in tempo reale。
