---
title: "Ottenere i dettagli della documentazione della piattaforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Ottieni il contenuto completo e le relazioni di navigazione di un singolo documento tramite UUID o alias del documento. Quando l'alias è noto, può essere richiesto direttamente, senza prima filtrare dall'elenco.

## Panoramica dell'interfaccia

| Voce   | Contenuto                                                              |
| --- | --------------------------------------------------------------- |
| Metodo  | `GET`                                                           |
| URL | `https://platform.acedata.cloud/api/v1/documents/{id_or_alias}` |
| Autenticazione  | Pubblica; conoscendo UUID o alias è possibile leggere direttamente                                       |

## Parametri

- `id_or_alias`: UUID del documento, alias corrente o vecchio alias conservato in `redirect_from`.
- `lang`: suggerimento facoltativo per la lingua; è possibile usare anche `Accept-Language`. La lingua finale del contenuto è determinata da `content_locale` nella risposta.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/documents/platform-token' \
  --data-urlencode 'lang=zh-CN' \
  -H 'Accept: application/json'
```

## Descrizione della risposta

I dettagli utilizzano un singolo oggetto come risposta, che attualmente include:

- `id`, `alias`, `redirect_from`, `name`, `title`, `type`, `rank`, `tags`;
- `content`, `content_mode`, `content_locale`, `content_hash`;
- `parent`, `sibling` e i riepiloghi pubblici di `children` ordinati per rank;
- associazioni `api` / `proxy` / `dataset` / `integration`, nonché `agent` (quando presente).

La risposta non contiene il campo `breadcrumbs`. Quando si costruisce il breadcrumb, è possibile continuare a leggere i dettagli da `parent` oppure utilizzare le relazioni della directory dei documenti già memorizzate nella cache.

## Gestione degli errori

- L'ID/alias non esiste o non soddisfa la visibilità del sito corrente: `404`. `private` controlla solo la visibilità nell'elenco e non impedisce la lettura diretta a chi conosce il link, quindi non può essere usato come confine di riservatezza.
- Il percorso corrente utilizza la forma senza slash finale; non fare affidamento sul fatto che il livello proxy aggiunga automaticamente lo slash.
