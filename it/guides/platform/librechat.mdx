[LibreChat](https://www.librechat.ai/) è un client AI open source altamente configurabile, che utilizza `librechat.yaml` per descrivere fornitori, modelli e regole di routing. Supporta endpoint personalizzati compatibili con OpenAI, quindi può connettersi ad Ace Data Cloud. Questo articolo descrive il processo di configurazione.

## Processo di registrazione

Per connettere Ace Data Cloud in LibreChat, prima vai al [pannello di controllo di Ace Data Cloud](https://platform.acedata.cloud/console/applications) e ottieni il tuo API Token, da conservare per uso futuro.

![Ottieni Ace Data Cloud API Key](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato il login o registrato, verrai automaticamente reindirizzato alla pagina di login che ti invita a registrarti e accedere; dopo aver effettuato il login o la registrazione, verrai riportato automaticamente alla pagina corrente.

Al primo accesso, verrà offerto un credito gratuito, permettendoti di provare gratuitamente i servizi di modello di Ace Data Cloud.

## Distribuzione di LibreChat

LibreChat viene distribuito tramite Docker Compose; prima prepara la directory e scarica la configurazione ufficiale:

```bash
mkdir -p ~/librechat && cd ~/librechat
curl -O https://raw.githubusercontent.com/danny-avila/LibreChat/main/docker-compose.yml
curl -O https://raw.githubusercontent.com/danny-avila/LibreChat/main/.env.example
mv .env.example .env
```

Nel file `.env`, utilizza `openssl rand -hex 32` per generare `JWT_SECRET`, `JWT_REFRESH_SECRET`, `CREDS_KEY`, `CREDS_IV` e altre chiavi di sicurezza, e imposta `ALLOW_REGISTRATION` secondo necessità.

## Configurazione di Ace Data Cloud

Crea `librechat.yaml`, impostando Ace Data Cloud come endpoint personalizzato compatibile con OpenAI (per una descrizione completa dei campi, vedere la [documentazione ufficiale degli Endpoint Personalizzati](https://www.librechat.ai/docs/quick_start/custom_endpoints), sostituendo `{token}` con il tuo Token):

```yaml
version: 1.0.5
cache: true

endpoints:
  custom:
    - name: "Ace Data Cloud"
      apiKey: "{token}"
      baseURL: "https://api.acedata.cloud/v1"
      models:
        default:
          - "MODEL_ID"
        fetch: true
      titleConvo: true
      titleModel: "MODEL_ID"
      modelDisplayLabel: "Ace Data Cloud"
```

Nel file `docker-compose.yml`, sotto il servizio `api`, monta questo file nel contenitore, quindi avvia con `docker compose up -d`:

```yaml
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Nota le regole del percorso per `baseURL`:

| baseURL                               | Richiesta effettiva                                         | Risultato                  |
| ------------------------------------- | ------------------------------------------------------ | ------------------------ |
| `https://api.acedata.cloud/v1`        | `https://api.acedata.cloud/v1/chat/completions`        | Corretto                  |
| `https://api.acedata.cloud/openai`    | `https://api.acedata.cloud/openai/chat/completions`    | Utilizzabile              |
| `https://api.acedata.cloud/openai/v1` | `https://api.acedata.cloud/openai/v1/chat/completions` | 404 (nessun `/v1` sotto `/openai`) |
| `https://api.acedata.cloud`           | `https://api.acedata.cloud/chat/completions`           | 404 (manca `/v1`)        |

## Selezione del modello

Il catalogo dei modelli verrà aggiornato continuamente. Utilizza prioritariamente l'elenco dei modelli caricato automaticamente dal client; se è necessario compilare manualmente, richiedi prima `GET https://api.acedata.cloud/v1/models` per ottenere l'ID del modello corrente, quindi scegli in base alle capacità di contesto, immagine e chiamata agli strumenti supportate dal client.

## Verifica dell'integrazione

Se non sei sicuro se il problema sia in LibreChat o nella rete, puoi prima verificare direttamente l'endpoint con curl (sostituendo `{token}` con il tuo Token):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

Se ricevi un oggetto `chat.completion` compatibile con OpenAI, significa che il Token e l'endpoint sono pronti; se ricevi `HTTP 403 used_up`, significa che il Token è valido ma il saldo è insufficiente, puoi ricaricare nel [pannello di controllo](https://platform.acedata.cloud/console/applications).

## Avanzato: tecniche di configurazione yaml

`librechat.yaml` supporta più gruppi di endpoint, puoi utilizzare `apiKey: "user_provided"` per consentire a ciascun utente di inserire la propria chiave; `titleModel` specifica il modello per generare il titolo della conversazione; `dropParams` può essere utilizzato per rimuovere uniformemente i parametri non supportati dall'API di destinazione. Vedi [dettagli sulla configurazione di librechat.yaml](https://www.librechat.ai/docs/configuration/librechat_yaml).

## Domande frequenti

### Non vedi l'endpoint di Ace Data Cloud dopo l'avvio

Di solito è perché il yaml non è stato montato nel contenitore o ci sono errori di indentazione. Controlla i volumi in `docker-compose.yml` e verifica l'indentazione del yaml.

### Messaggio 404

`baseURL` è stato scritto come `.../openai/v1` o manca `/v1`. Cambialo in `https://api.acedata.cloud/v1`.

### Il menu a discesa dei modelli è vuoto

`fetch: true` ma `/v1/models` fallisce, cambia a `fetch: false` e elenca manualmente `default`.

### Le modifiche al yaml non hanno effetto

Devi riavviare il contenitore: `docker compose restart api`.
