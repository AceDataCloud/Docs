---
title: "Esportare i record delle chiamate API della piattaforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Scarica direttamente i dettagli delle chiamate API dell'account corrente come CSV, adatto per la riconciliazione finanziaria, l'analisi offline o il salvataggio di grandi quantità di record. Se devi solo visualizzare una piccola quantità di dettagli nella pagina, utilizza prima l'[elenco dei record delle chiamate](https://platform.acedata.cloud/documents/platform-usage-list).

L'intervallo di query per i record delle chiamate e i riepiloghi di fatturazione è degli ultimi 60 giorni; i corpi delle richieste e delle risposte vengono conservati separatamente per gli ultimi 30 giorni. La scadenza dei corpi non modifica l'addebito effettivo, l'utilizzo o le statistiche aggregate di quel record.

## Preparazione

1. Accedi alla [piattaforma AceDataCloud](https://platform.acedata.cloud).
2. Crea un token dell'account nella [console Account Token](https://platform.acedata.cloud/console/platform-tokens) e salvalo immediatamente in un gestore di password o in un Secret Manager.
3. Ottieni gli ID di filtro secondo necessità dall'[elenco delle richieste di servizio](https://platform.acedata.cloud/documents/platform-application-list), dall'[elenco delle credenziali API](https://platform.acedata.cloud/documents/platform-credential-list) o dall'[elenco delle API](https://platform.acedata.cloud/documents/platform-api-list).

Per la descrizione completa dei token, consulta [Gestire i token dell'account](https://platform.acedata.cloud/documents/platform-token). I token dell'account e le Credential per chiamare API aziendali non sono intercambiabili.

```shell
export PLATFORM_TOKEN='il tuo token dell'account'
```

## Panoramica dell'interfaccia

| Voce           | Contenuto                                                  |
| -------------- | ---------------------------------------------------------- |
| Metodo         | `GET`                                                      |
| URL            | `https://platform.acedata.cloud/api/v1/usage/apis/export/` |
| Autenticazione | `Authorization: Bearer ${PLATFORM_TOKEN}`                  |
| OAuth Scope    | `usage:read` (`platform:read` / `platform` include in modo espanso) |
| Risposta       | `200 text/csv; charset=utf-8`                              |
| Nome file      | `usages.csv`                                               |

Questa interfaccia restituisce sincronicamente il CSV in streaming, non crea attività di esportazione e non restituisce JSON o link per il download. Solo quando entrambi gli orari di inizio e fine non vengono forniti, vengono esportati per impostazione predefinita i record dall'inizio del mese solare corrente fino al momento attuale; quando viene fornito un solo limite, l'altro non viene automaticamente completato con il limite del mese corrente.

## Parametri di query

| Parametro         | Tipo     | Obbligatorio | Predefinito | Descrizione                                |
| ----------------- | -------- | ------------ | ----------- | ------------------------------------------ |
| `perspective`     | string   | No           | `both`      | `billing`, `actor` o `both`                |
| `service_id`      | UUID     | No           | —           | Filtra per servizio; supporta parametri ripetuti |
| `application_id`  | UUID     | No           | —           | Filtra per Application; supporta parametri ripetuti |
| `api_id`          | UUID     | No           | —           | Filtra per API; supporta parametri ripetuti |
| `credential_id`   | UUID     | No           | —           | Filtra per credenziale API; supporta parametri ripetuti |
| `status_code`     | integer  | No           | —           | Supporta valori ripetuti o separati da virgola |
| `created_at_from` | datetime | No           | —           | Orario di inizio ISO 8601                  |
| `created_at_to`   | datetime | No           | —           | Orario di fine ISO 8601                    |

L'intervallo di esportazione è sempre limitato ai record visibili per l'account corrente come soggetto pagante e/o chiamante effettivo; l'esportazione tra account non è supportata.

## Esempi di richiesta

Salva direttamente il CSV del mese corrente:

```shell
curl --fail-with-body --location \
  'https://platform.acedata.cloud/api/v1/usage/apis/export/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  --output usages.csv
```

Esporta per Application, orario e codice di stato:

```shell
export APPLICATION_ID='il tuo Application ID'

curl --fail-with-body --get \
  'https://platform.acedata.cloud/api/v1/usage/apis/export/' \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'status_code=200,500' \
  --data-urlencode 'created_at_from=2026-09-01T00:00:00Z' \
  --data-urlencode 'created_at_to=2026-09-08T00:00:00Z' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  --output usages.csv
```

Salvataggio in streaming con Python e verifica dell'integrità:

```python
import os
from pathlib import Path

import requests

url = "https://platform.acedata.cloud/api/v1/usage/apis/export/"
headers = {"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"}
params = {
    "created_at_from": "2026-09-01T00:00:00Z",
    "created_at_to": "2026-09-08T00:00:00Z",
    "perspective": "both",
}
output = Path("usages.csv")

with requests.get(url, headers=headers, params=params, stream=True, timeout=120) as response:
    response.raise_for_status()
    if not response.headers.get("content-type", "").startswith("text/csv"):
        raise RuntimeError("服务器没有返回 CSV")
    with output.open("wb") as file:
        for chunk in response.iter_content(chunk_size=64 * 1024):
            file.write(chunk)

last_line = output.read_text(encoding="utf-8").splitlines()[-1]
if last_line.startswith("# truncated:") or last_line.startswith("# error:"):
    raise RuntimeError(f"导出不完整：{last_line}")
```

## Colonne CSV

L'ordine dell'intestazione CSV è fisso:

```text
Usage ID,API,Status Code,Deducted Amount,Original Amount,Trace ID,Created At
```

| Colonna            | Descrizione                                      |
| ------------------ | ------------------------------------------------ |
| `Usage ID`         | ID del record di chiamata                        |
| `API`              | Titolo dell'API; se non corrisponde, potrebbe essere l'ID API o un valore vuoto |
| `Status Code`      | Codice di stato HTTP                             |
| `Deducted Amount`  | Credito finale effettivamente detratto           |
| `Original Amount`  | Credito originale prima dello sconto Application |
| `Trace ID`         | Identificatore di tracciamento della richiesta   |
| `Created At`       | Orario di creazione del record, ISO 8601         |

L'unità di credito è determinata da `service.unit` della Application corrispondente.

## Determinare se l'esportazione è completa

Una singola esportazione può produrre al massimo 1.000.000 record. Dopo che il server ha iniziato a restituire il CSV, non può più modificare un errore intermedio in un altro stato HTTP, pertanto il client deve controllare l'ultima riga:

- `# truncated:`: è stato raggiunto il limite di righe; esporta in segmenti utilizzando finestre temporali più piccole.
- `# error:`: la lettura in streaming è stata interrotta; riduci l'intervallo ed esporta nuovamente.

Quando il programma di riconciliazione rileva uno qualsiasi dei marker, deve considerare il file incompleto e non può contabilizzarlo silenziosamente.

## Errori e tentativi

| Situazione                 | Metodo di gestione                                      |
| -------------------------- | ------------------------------------------------------- |
| `400 usage_history_expired` | Usa `available_from` nella risposta per adeguare l'intervallo agli ultimi 60 giorni |
| `401 not_authenticated`    | Verifica che l'Account Token esista, sia corretto e non sia stato eliminato |
| Risposta non CSV           | Non salvarla come file riuscito; leggi prima la risposta di errore e correggi la richiesta |
| Download interrotto o marker | Riduci la finestra temporale e riesporta usando una strategia di backoff |
