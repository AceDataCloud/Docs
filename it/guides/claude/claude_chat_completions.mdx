Anthropic Claude è un sistema di conversazione AI molto potente: basta inserire un prompt per generare risposte fluide e naturali in pochi secondi. Claude si distingue nel settore grazie alle sue eccellenti capacità di comprensione e generazione del linguaggio. Oggi, Claude è già ampiamente utilizzato in vari settori e ambiti, e la sua influenza è sempre più significativa. Che si tratti di conversazioni quotidiane, scrittura creativa, consulenza professionale o programmazione di codice, Claude può fornire un'assistenza intelligente straordinaria, migliorando notevolmente l'efficienza lavorativa e la creatività umana.

Questo documento presenta principalmente il processo di utilizzo delle operazioni della Claude Chat Completion API; grazie ad essa possiamo utilizzare facilmente la funzionalità di conversazione di Claude ufficiale.

## Processo di richiesta

Per utilizzare la Claude Chat Completion API, per prima cosa vai alla [console di Ace Data Cloud](https://platform.acedata.cloud/console/applications) per ottenere il tuo API Token, da conservare come riserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non hai ancora effettuato l'accesso o non ti sei registrato, verrai automaticamente reindirizzato alla pagina di accesso per registrarti e accedere; una volta completato, tornerai automaticamente alla pagina corrente.

**Un solo API Token può chiamare tutti i servizi della piattaforma, senza doverne richiedere uno separatamente per ciascun servizio.** La prima richiesta include un credito gratuito, utilizzabile per una prova gratuita; quando il credito è insufficiente, puoi ricaricare il saldo generale nella [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Utilizzo di base

Successivamente puoi compilare il contenuto corrispondente nell'interfaccia, come mostrato nella figura:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Al primo utilizzo di questa interfaccia, dobbiamo compilare almeno tre elementi: uno è `authorization`, che può essere selezionato direttamente nell'elenco a discesa. Un altro parametro è `model`, con modelli pubblici selezionabili come `claude-opus-5-5`, `claude-fable-5-1` e altri; il precedente `claude-fable-5` può ancora essere chiamato. L'ultimo parametro è `messages`, che è un array di prompt: ogni elemento contiene `role` e `content`; `role` supporta `user`, `assistant`, `system`, mentre `content` è il contenuto specifico. Quando sono necessari blocchi completi del ragionamento di Claude, firme e semantica degli strumenti nativi, utilizza comunque la Messages API.

Allo stesso tempo, puoi notare che sulla destra viene generato il codice di chiamata corrispondente: puoi copiare il codice ed eseguirlo direttamente, oppure fare clic direttamente sul pulsante «Try» per effettuare un test.

Parametri opzionali comuni:

- `max_tokens`: limita il numero massimo di token in una singola risposta.
- `temperature`: casualità della generazione, compresa tra 0 e 2; maggiore è il valore, maggiore sarà la dispersione.
- `n`: quante risposte candidate generare alla volta.
- `response_format`: impostazione del formato di risposta.

`claude-opus-5-5` supporta Chat Completions normali e in streaming; questo modello consente solo `n=1`. Non impostare per esso una `temperature` inferiore a 1 o un `top_p` non predefinito; per la chiamata degli strumenti utilizza `tool_choice: "auto"`, senza forzare la specifica di uno strumento. L'interfaccia compatibile con Chat non restituisce blocchi di ragionamento nativi.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Dopo la chiamata, possiamo notare che il risultato restituito è il seguente:

```json

        "role": "assistant",

      },

    "prompt_tokens": 8,

    "total_tokens": 20,

      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }

```

Il risultato restituito contiene diversi campi, descritti di seguito:

- `id`, l'ID generato per questa attività di conversazione, utilizzato per identificare in modo univoco questa attività di conversazione.
- `model `, il modello Claude del sito ufficiale selezionato.
- `choices`, le informazioni di risposta fornite da Claude per il prompt.
- `usage `: informazioni statistiche sui token per questa sessione di domande e risposte.

Nel formato Chat Completions, `usage.prompt_tokens` è il totale dell'input; `prompt_tokens_details.cached_tokens` e `prompt_tokens_details.cache_write_tokens` registrano rispettivamente i dettagli di lettura e scrittura della cache. `completion_tokens_details.reasoning_tokens` è un sottoinsieme di `completion_tokens`; non sommarlo nuovamente nel calcolo del totale o dei costi. Le risposte non in streaming possono inoltre restituire l'oggetto `usage.cost`, in cui `amount` è il consumo effettivo di credito, `currency` è l'unità di misura e `list_amount` è l'importo prima dello sconto (se presente).

Il nome del campo compatibile con Chat è `reasoning_tokens`; la Messages API nativa utilizza `output_tokens_details.thinking_tokens`. Lo schema wire dei due protocolli è diverso e il client non deve mescolare i nomi dei campi.

Tra questi, `choices` contiene le informazioni di risposta di Claude, e il suo `choices` contiene le informazioni specifiche della risposta di Claude, come mostrato nella figura.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Si può notare che il campo `content` all'interno di `choices` contiene il contenuto specifico della risposta di Claude.

## Risposta in streaming

Questa interfaccia supporta anche le risposte in streaming, il che è molto utile per l'integrazione con le pagine web e consente di ottenere un effetto di visualizzazione carattere per carattere.

Se desideri restituire la risposta in streaming, puoi modificare il parametro `stream ` nell'intestazione della richiesta impostandolo su `true`.

La modifica è mostrata nella figura; tuttavia, il codice di chiamata deve essere modificato di conseguenza per supportare la risposta in streaming.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

Dopo aver modificato `stream` in `true`, l'API restituirà riga per riga i dati JSON corrispondenti; a livello di codice dobbiamo apportare le modifiche necessarie per ottenere i risultati riga per riga.

Codice di chiamata di esempio Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Anche JavaScript è supportato, ad esempio il codice di chiamata in streaming di Node.js è il seguente:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "claude-opus-4-20250514",
    messages: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/v1/chat/completions", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Ragionamento approfondito
I modelli Claude di nuova generazione potrebbero eseguire il ragionamento secondo la strategia predefinita del modello, senza dover essere attivati tramite il suffisso del modello `-thinking`. Le risposte compatibili con Chat utilizzano il campo usage compatibile con OpenAI `completion_tokens_details.reasoning_tokens`. I `reasoning_tokens` sono già inclusi in `completion_tokens`, non sommarli nuovamente. Il ragionamento e il corpo visibile condividono il limite massimo di token in output, pertanto quando `max_tokens` è basso il corpo potrebbe risultare vuoto o troncato; in questo caso, aumenta il budget di output oppure, se supportato dal modello utilizzato, seleziona un impegno di ragionamento inferiore.

Se sono necessari `thinking` nativo, `output_config.effort`, blocchi di contenuto thinking e restituzione della firma, utilizza `/v1/messages`. Il campo usage corrispondente a Messages è `output_tokens_details.thinking_tokens`, non confonderlo con `completion_tokens_details.reasoning_tokens` di Chat-compatible.

## Modello visivo

claude-sonnet-4-20250514 è un modello linguistico di grandi dimensioni multimodale sviluppato da Claude, che aggiunge capacità di comprensione visiva sulla base di claude-4. Questo modello può elaborare contemporaneamente input di testo e immagini, realizzando comprensione e generazione multimodale.

L'elaborazione del testo utilizzando il modello claude-sonnet-4-20250514 è coerente con i contenuti di utilizzo di base precedenti; di seguito verrà brevemente illustrato come utilizzare la capacità di elaborazione delle immagini del modello.

La capacità di elaborazione delle immagini del modello claude-sonnet-4-20250514 viene utilizzata principalmente aggiungendo un campo `type` al contenuto `content` originale. Attraverso questo campo è possibile sapere se ciò che viene caricato è testo o un'immagine, e quindi utilizzare la capacità di elaborazione delle immagini del modello claude-sonnet-4-20250514. ## Gestione degli errori

Durante la chiamata dell'API, se si verifica un errore, l'API restituirà il codice e il messaggio di errore corrispondenti. Ad esempio:

- `400 token_mismatched`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`：Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`：Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`：Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```

    "message": "fetch failed"
  },

}
```
