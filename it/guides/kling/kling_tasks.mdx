La funzione principale della Kling Tasks API è interrogare lo stato di esecuzione di un'attività inserendo l'ID dell'attività generata dalla Kling Videos Generation API.

Questo documento illustrerà dettagliatamente le istruzioni di integrazione della Kling Tasks API, aiutandovi a integrare facilmente e a sfruttare pienamente le potenti funzionalità di questa API. Tramite la Kling Tasks API, potete facilmente interrogare lo stato di esecuzione delle attività della Kling Videos Generation API.

## Procedura di richiesta

Per utilizzare la Kling Videos Generation API, ottenete prima il vostro API Token nella [console di Ace Data Cloud](https://platform.acedata.cloud/console/applications) e conservatelo come riserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se non avete ancora effettuato l'accesso o non vi siete registrati, verrete automaticamente reindirizzati alla pagina di accesso per registrarvi e accedere; una volta completato, tornerete automaticamente alla pagina corrente.

**Un solo API Token può chiamare tutti i servizi della piattaforma, senza necessità di richiederne uno separatamente per ciascun servizio.** Alla prima richiesta verrà assegnato credito gratuito, per provare il servizio gratuitamente; quando il credito è insufficiente, potete ricaricare il saldo comune nella [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentazione completa: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Esempio di richiesta

La Kling Tasks API può essere utilizzata per interrogare i risultati della Kling Videos Generation API. Per sapere come utilizzare la Kling Videos Generation API, fate riferimento alla documentazione [Kling Videos Generation API ](https://platform.acedata.cloud/documents/kling-videos).

Prendiamo come esempio un ID attività restituito dal servizio Kling Videos Generation API, per mostrare come utilizzare questa API. Supponiamo di avere un ID attività: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, di seguito mostreremo come farlo passando un ID attività.

### Impostare le intestazioni e il corpo della richiesta

**Request Headers** includono:

- `accept`: specifica la ricezione dei risultati di risposta in formato JSON, qui compilare con `application/json`.
- `authorization`: la chiave per chiamare l'API, dopo averla richiesta è possibile selezionarla direttamente dal menu a discesa.

**Request Body** include:

- `id`: l'ID dell'attività caricata.
- `action`: la modalità di operazione sull'attività.

Le impostazioni sono mostrate nell'immagine seguente:

Alcuni esempi di codice sono i seguenti:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Il risultato restituito contiene più campi; il campo request è il request body al momento dell'avvio dell'attività, mentre il campo response è il response body restituito dopo il completamento dell'attività. La descrizione dei campi è la seguente.

- `id`, l'ID che genera questa attività video, utilizzato per identificare univocamente questa attività di generazione video.
- `request`, le informazioni della richiesta nell'interrogazione dell'attività video.
- `response`, le informazioni di risposta nell'interrogazione dell'attività video.
- `created_at`, l'orario di creazione dell'attività, timestamp Unix (secondi, virgola mobile).
- `started_at`, l'orario di inizio dell'esecuzione dell'attività, timestamp Unix (secondi, virgola mobile).
- `finished_at`, l'orario di completamento dell'attività, timestamp Unix (secondi, virgola mobile). Questo campo non viene restituito quando l'attività non è completata.
- `elapsed`, il tempo impiegato per l'esecuzione dell'attività, in secondi (virgola mobile, mantenendo 3 cifre decimali). Questo campo non viene restituito quando l'attività non è completata.

## Gestione degli errori

Quando si chiama l'API, se si verifica un errore, l'API restituirà il codice di errore e il messaggio corrispondenti. Ad esempio:

- `400 token_mismatched`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `400 api_not_implemented`：Richiesta non valida, probabilmente a causa di parametri mancanti o non validi.
- `401 invalid_token`：Non autorizzato, token di autorizzazione non valido o mancante.
- `429 too_many_requests`：Troppe richieste, hai superato il limite di frequenza.
- `500 api_error`：Errore interno del server, qualcosa è andato storto sul server.

### Esempio di risposta di errore

```json
{

  "error": {

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
