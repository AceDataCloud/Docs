AI Chat v2 API (`/aichat2/conversations`) on uuden sukupolven keskustelurajapinta ja [AI Chat API:n](https://platform.acedata.cloud/documents/aichat-conversations) kattavasti päivitetty versio. Se laajentaa v1:n yksinkertaista, hallittua monikierroksista keskustelua seuraavilla ominaisuuksilla:

- **Monimuotoiset käyttäjäsyötteet**: rakenneistetun `message`-kentän kautta voi lähettää suoraan teksti- + kuva- + tiedostolohkoja ilman, että ne tarvitsee ensin liittää epäsuorasti `references`-kentällä.
- **Agenttipohjaiset työkalukutsut**: sisältää joukon verkkohaku-, verkkosivujen nouto-, tiedostonluku- ja muita työkaluja, ja siihen voidaan liittää käyttäjän valtuuttamia MCP-palvelimia (Google Drive, Notion, Slack, GitHub jne.). Malli voi yhdessä pyynnössä kutsua työkaluja itsenäisesti useilla kierroksilla monimutkaisten tehtävien suorittamiseksi.
- **Rakenteistetut suoratoistotapahtumat**: käyttämällä `accept: text/event-stream`- tai `application/x-ndjson`-asetusta voidaan saada token kerrallaan `text_delta`-, `tool_use`-, `tool_result`-, `thinking`-, `citation`-, `card`-, `artifact`- ja muita tapahtumia, mikä helpottaa niiden erillistä renderöintiä käyttöliittymässä tyypin mukaan.
- **Keskeytettävissä / jatkettavissa**: kun malli tarvitsee käyttäjältä lisätietoja, se lähettää `ask_user_question`-tapahtuman ja keskeyttää toiminnan. Seuraavalla kutsulla vastaukset voidaan täyttää takaisin `tool_results`-kentän kautta, jolloin toiminta jatkuu.
- **Uudet CRUD-toiminnot**: samalla endpointilla voidaan suorittaa `retrieve` / `retrieve_batch` / `update` / `delete` `action`-kentän avulla ilman erillistä keskustelunhallinta-APIa.
- **Jatkuvasti päivittyvä malliluettelo**: oletusarvoisesti käytettävissä ovat nykyaikaiset mallit, kuten GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4 ja Kimi K3.

Samalla se on pyyntörungon tasolla **täysin taaksepäin yhteensopiva v1:n kanssa**: lähettämällä vain `model` + `question` (+ valinnaiset `stateful` / `id` / `references` / `preset`) saat v1:tä vastaavan `{answer, id}` JSON-vastauksen. Siksi siirtyminen `/aichat/conversations`-rajapinnasta ei edellytä asiakasohjelman uudelleenkirjoittamista; riittää, että polku vaihdetaan muotoon `/aichat2/conversations`.

> Jos käytät tällä hetkellä `/aichat/conversations`-rajapintaa, vanha rajapinta säilyy edelleen käytettävissä, ja voit siirtyä omaan tahtiisi.

## Peruskäyttö

Yksinkertaisin käyttö vastaa täysin v1:tä: lähetä `model` + `question` ja vastaanota `{answer, id}`.

CURL-esimerkki:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Palautettu tulos:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python-esimerkki:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Monikierroksinen keskustelu

Kuten v1:ssä, lähetä `stateful: true` ottaaksesi keskustelun tallennuksen käyttöön. API palauttaa `id`-tunnuksen; seuraavissa pyynnöissä voit jatkaa keskustelua lähettämällä `id`-tunnuksen takaisin ilman, että sinun tarvitsee itse ylläpitää messages-historiaa.

Ensimmäinen pyyntö:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Palautus:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Toinen pyyntö, lähetä sama `id` mukana:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` on oletusarvoisesti `true`; sen pois jättäminen vastaa `true`-arvon antamista eksplisiittisesti. Jos et halua palvelinpuolen tallentavan tätä keskustelukierrosta, voit asettaa eksplisiittisesti `stateful: false`.

## Suoratoistovastaus

v2 tukee kahta suoratoistomuotoa, jotka valitaan `accept`-otsakkeen mukaan:

| Tilanne                    | `accept`               | Tietomuoto                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web-käyttöliittymä / EventSource  | `text/event-stream`    | `data: {json}\n\n`, viimeinen rivi `data: [DONE]\n\n` |
| Palvelin / CLI / Node-suoratoistoanalyysi | `application/x-ndjson` | Yksi JSON-objekti per rivi                               |
| Suoratoistoa ei tarvita                 | `application/json`（oletus） | Palauttaa kerralla `{answer, id}`                       |

### NDJSON-esimerkki

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Jokainen NDJSON-rivi on strukturoitu tapahtuma, joista yleisin on `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE-esimerkki

Selainpuolen `EventSource` ei tue mukautettuja pyyntöjä, joten on suositeltavaa käyttää `fetch`-kutsua + manuaalista jäsentämistä `\n\n`-erottimella:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Suoratoistotapahtumatyypit

| `type`              | Merkitys                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `text_delta`        | Avustajan vastauksen inkrementaalinen tekstikatkelma. `content` on uusi sisältö; v1-yhteensopivuuden vuoksi sama tapahtuma sisältää myös `delta_answer`-kentän (sama kuin `content`) ja `id`:n.                  |
| `thinking`          | Mallin ajatteluprosessi (näkyy vain, kun valittu malli paljastaa reasoning-tiedot).                                                                |
| `tool_use`          | Malli päättää kutsua työkalua; tapahtuma sisältää `tool_id`:n, `tool_name`:n ja `input`:n.                                                  |
| `tool_result`       | Työkalun suoritusresultaatio, joka yhdistetään edelliseen `tool_use`-tapahtumaan `tool_id`:n kautta; `is_error` ilmaisee, epäonnistuiko se.                                       |
| `card`              | Työkalun tuottama strukturoitu kortti (kuten kuva tai linkin esikatselu), joka sopii suoraan renderöitäväksi.                                                                    |
| `citation`          | Käytetään vastaavan tekstikatkelman viittausten lähde-URL-osoitteiden täydentämiseen.                                                                            |
| `ask_user_question` | Lähetetään, kun malli tarvitsee käyttäjältä lisätietoja; keskustelu siirtyy `awaiting_user_input`-tilaan, katso alempaa [keskeytetyn keskustelun jatkaminen](#keskeytetyn-keskustelun-jatkaminen).                           |
| `artifact`          | Mallin luoma itsenäinen tuotos (kuten koodilohko tai asiakirja), joka voidaan tallentaa tai ladata.                                                                      |
| `system_message`    | Järjestelmän ilmoitustieto (ei käyttäjän tai avustajan sisältöä), vain käyttöliittymäilmoituksia varten.                                                                     |
| `compact`           | Tapahtuma, jossa sisäinen konteksti on tiivistetty; ei vaadi erityiskäsittelyä.                                                                             |
| `error`             | Tällä kierroksella tapahtui virhe; `message` kuvaa virheen sisällön.                                                                        |
| `done`              | Suoratoistovastaus päättyy; sisältää `usage`-tiedot (mukaan lukien `prompt_tokens` / `completion_tokens` / `total_tokens`) ja `terminal_reason`:n. |

Asiakkaille, jotka välittävät vain lopullisesta vastauksesta, kaikkien `text_delta`-tapahtumien `content`-kenttien yhdistäminen vastaa `application/json`-tilan `answer`-kenttää.

## Multimodaalinen syöte

Jos käyttäjän syöte sisältää kuvia tai tiedostoja, välitä `message` (taulukko) `question`-kentän sijaan. Jokainen taulukkoelementti on sisältölohko:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Tuetut lohkotyypit:

- `text` — Tavallinen teksti, `text`-kenttä on pakollinen.
- `image_url` — Kuva, `image_url.url` on pakollinen.
- `file_url` — Tiedosto (PDF, CSV, TXT jne.), `file_url.url` on pakollinen.

### Suhde v1:n `references`-kenttään

Vanhojen asiakkaiden yhteensopivuuden vuoksi v2 tunnistaa edelleen kentän `references: ["https://...", ...]`:
- URL-pääte on `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, muunnetaan automaattisesti `image_url`-lohkoksi;
- Muut tiedostopäätteet muunnetaan `file_url`-lohkoksi;
- Jos samalla annetaan myös `question`, se sijoitetaan edelle `text`-lohkona.

Jos siis haluat vain siirtyä v1:stä etkä halua muuttaa pyyntörungkoa, vaihda poluksi `/aichat2/conversations`, jolloin alkuperäinen `references`-käyttö toimii edelleen normaalisti.

Jos tarvitset tarkempaa hallintaa (esimerkiksi useiden kuvien sijoittamista tekstin väliin tai jos järjestys on tärkeä), käytä suoraan `message`-taulukkoa.

## Työkalukutsut ja MCP

v2:n keskeinen parannus on, että malli voi itsenäisesti kutsua työkaluja monivaiheisten tehtävien suorittamiseksi, **tämä on oletusarvoisesti käytössä**, eikä asiakasohjelman tarvitse tehdä pyynnössä mitään lisämäärityksiä. Yleisiä tilanteita:

- Käyttäjä kysyy: ”Etsi minulle, mitä uusia näyttelyitä Shanghaissa on lähiaikoina” → malli kutsuu sisäänrakennettua web-hakua → kokoaa tulokset vastaukseksi.
- Käyttäjä kysyy: ”Lue tämä PDF ja kirjoita sitten tiivistelmä” → malli kutsuu file_read-työkalua → kirjoittaa tiivistelmän.
- Käyttäjä on valtuuttanut [Connections](https://platform.acedata.cloud/connections)-kohdassa Google Driven / GitHubin / Notionin jne. → malli voi kutsua vastaavia MCP-työkaluja niiden tietojen lukemiseen ja kirjoittamiseen.

NDJSON- / SSE-virrassa työkalukutsut esitetään kahden tapahtumatyypin, `tool_use` ja `tool_result`, kautta, esimerkiksi:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Jos et halua näyttää työkalukutsujen yksityiskohtia käyttöliittymässä, jätä huomiotta tapahtumatyypit `tool_use` / `tool_result` / `card` / `citation`; mallin lopullinen tuloste virtaa edelleen `text_delta`-tapahtumien kautta.

`max_turns` voi rajoittaa, kuinka monta kierrosta malli voi enintään kutsua työkaluja itse tässä pyynnössä; arvoalue on 1–500, ja jos se jätetään pois, oletusarvo on 500. Sen asettaminen pieneksi (esimerkiksi `max_turns: 1`) voi pakottaa kertaluonteisen vastauksen eikä salli mitään työkalukutsuja.

## Asynkroninen suoritus ja valtuutus ilman valvontaa

Jos kutsusi tulee hälytys-Webhookista, CI/CD:stä, valvontajärjestelmästä tai muusta taustatehtävästä, voit asettaa `async: true`, jolloin rajapinta palauttaa tehtävätunnuksen välittömästi ja jatkaa suorittamista taustalla:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Palveluni hälyttää, ilmoita henkilökohtaisella WeChatilla WeChat-ryhmälle 「AceDataCloud团队」……"
}
```

Palautusesimerkki:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Tämän jälkeen voit hakea keskustelun tuloksen käyttämällä `action: retrieve` + `id`; voit myös antaa `callback_url`-osoitteen, jolloin alusta POSTaa `{ status, answer, usage, error }` takaisinsoitto-osoitteeseesi tehtävän valmistuttua. `callback_url`-osoitteen on käytettävä `http` / `https`-protokollaa, eikä siihen voi suoraan kirjoittaa `localhost`-osoitetta tai yksityisen IP:n literaaliosoitetta.

Taustatehtävissä ei yleensä ole ketään, joka voisi klikata vahvistuksen. Jos haluat tiettyjen Skillien tai MCP Serverien suorittavan lähetys-, julkaisu-, kirjoitus- tai muita toimintoja ilman valvontaa, välitä pyynnön rungossa nimenomaisesti esivaltuutuslista:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Palveluni hälyttää, ilmoita henkilökohtaisella WeChatilla WeChat-ryhmälle 「AceDataCloud团队」……"
}
```

`allowed_skills`-kohdan arvot ovat yhdistettyjen Skillien slug-arvoja; `allowed_mcp_servers`-kohdan arvot ovat yhdistettyjen MCP Serverien slug-arvoja. Skillit / MCP Serverit, joita ei ole lueteltu esivaltuutuksissa, voivat ilman valvontaa toimivassa tilassa edelleen vain esikatsella, suorittaa dry-runin tai kieltäytyä kirjoitustoimintojen suorittamisesta.

Jos tarvitset tarkempaa hallintaa, voit myös käyttää vastaavaa `unattended_policy`-objektia:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Esivaltuutus koostuu näistä kahdesta listasta itsestään: tyhjä lista ei valtuuta mitään toimintoja, eikä erillistä kytkentäkenttää tarvita.

Huomaa: esivaltuutus tarkoittaa vain, että ”tämä pyyntö sallii näiden ominaisuuksien ohittaa ihmisen vahvistuksen ilman valvontaa”. Kyseisen Skillin on silti tuettava `--unattended-confirm`-toimintoa tai vastaavaa turvallisuusmekanismia; muutoin se jatkaa dry-run-tilassa eikä suorita kirjoitustoimintoa suoraan.

## Keskeytetyn keskustelun jatkaminen

Jotkin työkalut voivat saada mallin ”esittämään vastakysymyksen käyttäjälle”; tällöin malli lähettää `ask_user_question`-tapahtuman, ja keskustelu jäädytetään `awaiting_user_input`-tilaan:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Haluatko, että luotu raportti on kiinaksi vai englanniksi?",
  "options": ["kiina", "englanti"],
  "id": "f2f4b3e8-..."
}
```

Renderöi tämä tapahtuma käyttöliittymässä kortiksi, josta käyttäjä voi valita vastauksen, ja käynnistä sitten seuraava pyyntö samalla `id`:llä täyttämällä vastaus takaisin `tool_results`-kentän kautta:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

Pyynnön rungossa olevan `tool_use_id`-arvon **on** vastattava täsmälleen keskeytyshetken `tool_id`-arvoa; jos ne eivät vastaa toisiaan, palautetaan 400. Kun pyynnössä on samanaikaisesti `tool_results`, `question` / `message` / `references` jätetään kaikki huomiotta.

Jos käyttäjä päättää luopua tästä kysymyksestä, välitä suoraan uusi `question` / `message`; alusta merkitsee keskeytetyn työkalukutsun automaattisesti tilaan ”käyttäjä ohitti”.

## Keskustelujen hallinta (CRUD)

v2 tarjoaa kevyen keskustelujen hallinnan samalla endpointilla `action`-kentän kautta ilman erillistä API:a.
### `action: retrieve` —— Hae keskustelu

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Palauttaa koko keskusteluasiakirjan (mukaan lukien `messages`-historia, `model`, `title`, `tools_used` jne.).

### `action: retrieve_batch` —— Luettele keskustelujen yhteenvedot

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Palauttaa `{ items: [...], total }`. **Yhteenveto ei sisällä `messages`-kenttää**, joten se soveltuu sivupalkin luetteloon; jos käyttäjä avaa keskustelun, hae sen täydelliset viestit erikseen käyttämällä `action: retrieve` -toimintoa.

Valinnaiset suodatusparametrit: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Muuta otsikkoa tai kirjoita historia uudelleen

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Hangzhoun matkasuunnitelma"
}
```

Myös `messages` voidaan välittää, mutta palvelin suorittaa tiukan schema-validoinnin (sen on oltava tiivistetty `ToolUseContent`-muoto), ja vaatimustenvastaisesta palautetaan 400. Yleensä sitä suositellaan käytettäväksi vain `title`-kentän muuttamiseen.

### `action: delete` —— Poista keskustelu

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Palauttaa `{ id, success: true }`. Poistamisen jälkeen palautus ei ole mahdollista, joten varmista ennen kutsua.

## Sujuva siirtyminen v1:stä

Jos käytät jo [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations) -rajapintaa, siirtyminen v2:een ei juuri vaadi koodimuutoksia:

1. Vaihda URL-osoite `https://api.acedata.cloud/aichat/conversations` osoitteeksi `https://api.acedata.cloud/aichat2/conversations`.
2. Jos välitit aiemmin v1-mallin nimen (kuten `gpt-3.5`, `gpt-4-browsing` jne.), v2:een siirtyessä suositellaan päivittämistä nykyaikaiseen malliin (kuten `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` jne.).
3. NDJSON-virran kentät säilyvät taaksepäin yhteensopivina: jokainen `text_delta`-tapahtuma sisältää edelleen `delta_answer`- ja `id`-kentät, joten asiakkaat, jotka jäsentävät `delta_answer`-kentän riveittäin, eivät tarvitse muutoksia.

Siirtymisen jälkeen voit ottaa käyttöön v2:n uusia ominaisuuksia tarpeen mukaan (multimodaalinen `message`, SSE, työkalukutsut, `action` CRUD) ja edetä omaan tahtiin.

## Virheenkäsittely

Virhevastaus on yhtenäisesti:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Yleiset virheet:

- `400 bad_request`: pakollinen kenttä puuttuu, `tool_use_id` ei täsmää, `messages`-schema on virheellinen jne.
- `401 invalid_token`: `authorization`-otsake on virheellinen.
- `404 not_found`: `action: retrieve / update / delete` -toimintoa käytettäessä `id`-kenttää vastaavaa keskustelua ei ole olemassa.
- `429 too_many_requests`: nopeusrajoitus on laukaistu.
- `500 chat_error`: ylävirran LLM raportoi virheen tai tämän kierroksen `completion_tokens=0` (käsitellään käyttämättömänä, eikä siitä veloiteta).

Virtaavassa vastauksessa virhe lähetetään `{"type":"error","message":"..."}`-tapahtumana, minkä jälkeen virta päättyy välittömästi.

## Johtopäätös

AI Chat v2 API säilyttää v1:n taaksepäin yhteensopivuuden ja samalla päivittää keskustelut ”yhden / usean kierroksen kysymys-vastaus”-mallista ”Agent-pohjaisiksi tarkkailtaviksi keskusteluiksi”: multimodaaliset syötteet, työkalukutsut, keskeytys / jatkaminen, virtaavat jäsennellyt tapahtumat ja sisäänrakennettu CRUD. Uusille integraatioille suositellaan suoraan v2:n käyttöä; olemassa olevat v1-integraatiot voidaan siirtää sujuvasti vaiheittain. Jos sinulla on kysyttävää, ota milloin tahansa yhteyttä tekniseen tukitiimiimme.
