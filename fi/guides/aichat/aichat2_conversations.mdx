AI Chat v2 API (`/aichat2/conversations`) on uuden sukupolven keskustelurajapinta ja [AI Chat API:n](https://platform.acedata.cloud/documents/aichat-conversations) kattavasti päivitetty versio. Se laajentaa v1:n yksinkertaista, hallinnoitua monikierroksista keskustelua seuraavilla ominaisuuksilla:

- **Monimuotoiset käyttäjäsyötteet**: Teksti + kuva + tiedostolohkot voidaan välittää suoraan strukturoidun `message`-kentän kautta ilman, että ne täytyy ensin liittää epäsuorasti `references`-kentän avulla.
- **Agenttipohjaiset työkalukutsut**: Sisältää joukon työkaluja verkkohakuun, verkkosivujen noutamiseen, tiedostojen lukemiseen ja muihin toimintoihin, ja siihen voidaan liittää käyttäjän valtuuttamia MCP-palvelimia (Google Drive, Notion, Slack, GitHub jne.). Malli voi kutsua työkaluja itsenäisesti useita kierroksia yhden pyynnön aikana suorittaakseen monimutkaisia tehtäviä.
- **Strukturoidut suoratoistotapahtumat**: `accept: text/event-stream`- tai `application/x-ndjson`-asetuksella voidaan saada token kerrallaan `text_delta`-, `tool_use`-, `tool_result`-, `thinking`-, `citation`-, `card`-, `artifact`- ja muita tapahtumia, mikä helpottaa niiden erillistä renderöintiä käyttöliittymässä tyypeittäin.
- **Keskeytettävä / jatkettava**: Kun malli tarvitsee käyttäjältä lisätietoja, se lähettää `ask_user_question`-tapahtuman ja keskeyttää toiminnan. Seuraavassa kutsussa vastaus voidaan täyttää takaisin `tool_results`-kentän kautta, jolloin toiminta jatkuu.
- **Uudet CRUD-toiminnot**: Samassa endpointissa voidaan suorittaa `retrieve` / `retrieve_batch` / `update` / `delete` `action`-kentän avulla ilman erillistä keskustelunhallinta-API:a.
- **Jatkuvasti päivittyvä malliluettelo**: Oletusarvoisesti käytettävissä ovat nykyaikaiset mallit, kuten GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4 ja Kimi K3.

Samalla se on pyyntörungon tasolla **täysin taaksepäin yhteensopiva v1:n kanssa**: välittämällä vain `model` + `question` (+ valinnaiset `stateful` / `id` / `references` / `preset`) saat v1:tä vastaavan `{answer, id}` JSON-vastauksen. Siksi siirtyminen `/aichat/conversations`-rajapinnasta ei edellytä asiakkaan uudelleenkirjoittamista; riittää, että vaihdat polun muotoon `/aichat2/conversations`.

> Jos käytät tällä hetkellä `/aichat/conversations`-rajapintaa, vanha rajapinta pysyy edelleen käytössä, ja voit siirtyä omaan tahtiisi.

## Peruskäyttö

Yksinkertaisin käyttötapa on täysin sama kuin v1: välitä `model` + `question` ja saat `{answer, id}`.

CURL-esimerkki:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Palautettu tulos:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python-esimerkki:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Monikierroksinen keskustelu

Kuten v1:ssä, välitä `stateful: true` ottaaksesi keskustelun tallennuksen käyttöön. API palauttaa `id`-arvon; myöhemmissä pyynnöissä tuo vain `id` takaisin jatkaaksesi keskustelua, eikä sinun tarvitse itse ylläpitää messages-historiaa.

Ensimmäinen pyyntö:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Palautus:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Toinen pyyntö, lisää sama `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` on oletusarvoisesti `true`; sen pois jättäminen ja `true`-arvon välittäminen eksplisiittisesti ovat vastaavia. Jos et halua palvelinpuolen tallentavan tätä keskustelukierrosta, voit asettaa eksplisiittisesti `stateful: false`.

## Suoratoistovastaus

v2 tukee kahta suoratoistomuotoa, jotka valitaan `accept`-otsakkeen mukaan:

| Tilanne                    | `accept`               | Datan muoto                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web-käyttöliittymä / EventSource  | `text/event-stream`    | `data: {json}\n\n`, viimeinen rivi `data: [DONE]\n\n` |
| Palvelin / CLI / Node-suoratoistoanalyysi | `application/x-ndjson` | Yksi JSON-objekti per rivi                               |
| Suoratoistoa ei tarvita                 | `application/json`（oletus） | Palauttaa kerralla `{answer, id}`                       |

### NDJSON-esimerkki

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Jokainen NDJSON-rivi on strukturoitu tapahtuma, joista yleisin on `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE-esimerkki

`EventSource` ei tue selainpuolella mukautettuja pyyntörunkoja, joten suositellaan käyttämään `fetch`-toimintoa ja jäsentämään käsin `\n\n`-viipaleittain:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Suoratoistotapahtumatyypit

| `type`              | Merkitys                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `text_delta`        | Avustajan vastauksen inkrementaalinen tekstikatkelma. `content` on uusi sisältö; v1-yhteensopivuuden vuoksi sama tapahtuma sisältää myös `delta_answer`-kentän (joka on sama kuin `content`) ja `id`:n.                  |
| `thinking`          | Mallin ajatteluprosessi (esiintyy vain, kun valittu malli paljastaa reasoning-tietoja).                                                                |
| `tool_use`          | Malli päättää kutsua työkalua; tapahtuma sisältää `tool_id`-, `tool_name`- ja `input`-tiedot.                                                  |
| `tool_result`       | Työkalun suoritustulos; muodostaa parin edellisen `tool_use`-tapahtuman kanssa `tool_id`:n avulla, ja `is_error` ilmaisee, epäonnistuiko se.                                       |
| `card`              | Työkalun tuottama strukturoitu kortti (kuten kuva tai linkin esikatselu), joka soveltuu suoraan renderöitäväksi.                                                                    |
| `citation`          | Käytetään täydentämään vastaavan tekstikatkelman viittausten lähde-URL-osoitteita.                                                                            |
| `ask_user_question` | Lähetetään, kun malli tarvitsee käyttäjältä lisätietoja; keskustelu siirtyy `awaiting_user_input`-tilaan, katso jäljempänä [keskeytetyn keskustelun jatkaminen](#恢复暂停的对话).                           |
| `artifact`          | Mallin luoma itsenäinen tuotos (kuten koodilohko tai asiakirja), joka voidaan tallentaa tai ladata.                                                                      |
| `system_message`    | Järjestelmän ilmoitustieto (ei käyttäjän tai avustajan sisältöä), vain käyttöliittymäilmoituksia varten.                                                                     |
| `compact`           | Tapahtuma, jossa sisäinen konteksti on pakattu; ei vaadi erityiskäsittelyä.                                                                             |
| `error`             | Tällä kierroksella tapahtui virhe; `message` kuvaa virheen sisällön.                                                                        |
| `done`              | Suoratoistovastaus päättyy; sisältää `usage`-tiedot (mukaan lukien `prompt_tokens` / `completion_tokens` / `total_tokens`) ja `terminal_reason`-tiedon. |

Asiakkaille, jotka välittävät vain lopullisesta vastauksesta, kaikkien `text_delta`-tapahtumien `content`-kenttien yhdistäminen vastaa `application/json`-tilan `answer`-kenttää.

## Multimodaalinen syöte

Jos käyttäjän syöte sisältää kuvia tai tiedostoja, välitä `message` (taulukko) `question`-kentän sijaan. Jokainen taulukon elementti on sisältölohko:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Tuetut lohkotyypit:

- `text` — Tavallinen teksti; `text`-kenttä on pakollinen.
- `image_url` — Kuva; `image_url.url` on pakollinen.
- `file_url` — Tiedosto (PDF, CSV, TXT jne.); `file_url.url` on pakollinen.

### Suhde v1:n `references`-kenttään

Vanhojen asiakkaiden yhteensopivuuden vuoksi v2 tunnistaa edelleen `references: ["https://...", ...]` -kentän:
- URL-pääte on `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, muunnetaan automaattisesti `image_url`-lohkoksi;
- muut tiedostopäätteet muunnetaan `file_url`-lohkoksi;
- jos samalla annetaan myös `question`, se asetetaan edelle `text`-lohkona.

Siksi jos haluat vain siirtyä v1:stä etkä halua muuttaa pyyntörunkoa, vaihda poluksi `/aichat2/conversations`, niin alkuperäinen `references`-käyttötapa toimii edelleen tavalliseen tapaan.

Jos tarvitset tarkempaa hallintaa (esimerkiksi useiden kuvien sijoittamista tekstien väliin tai järjestyksen ollessa tärkeä), käytä suoraan `message`-taulukkoa.

## Työkalukutsut ja MCP

v2:n keskeinen parannus on, että malli voi kutsua työkaluja itsenäisesti monivaiheisten tehtävien suorittamiseksi, **tämä on oletusarvoisesti käytössä**, eikä asiakkaan tarvitse tehdä pyynnössä mitään lisämäärityksiä. Tyypillisiä tilanteita:

- Käyttäjä kysyy: ”Etsi minulle, mitä uusia näyttelyitä Shanghaissa on viime aikoina” → malli kutsuu sisäänrakennettua web-hakua → järjestää tulokset vastaukseksi.
- Käyttäjä kysyy: ”Lue tämä PDF ja kirjoita sitten yhteenveto” → malli kutsuu file_readia → kirjoittaa yhteenvedon.
- Käyttäjä on jo valtuuttanut [Connectionsissa](https://platform.acedata.cloud/connections) Google Driven / GitHubin / Notionin jne. → malli voi kutsua vastaavia MCP-työkaluja niiden tietojen lukemiseen ja kirjoittamiseen.

NDJSON- / SSE-virrassa työkalukutsut esitetään kahdenlaisina tapahtumina, `tool_use` ja `tool_result`, esimerkiksi:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Jos et halua näyttää työkalukutsujen yksityiskohtia käyttöliittymässä, jätä huomiotta tapahtumat `tool_use` / `tool_result` / `card` / `citation`, ja mallin lopullinen tuloste virtaa edelleen `text_delta`-tapahtumien kautta.

`max_turns` voi rajoittaa, kuinka monta kierrosta malli voi enintään kutsua työkaluja itse tässä pyynnössä; vaihteluväli on 1–500, ja jos se jätetään pois, oletusarvo on 500. Asettamalla sen pieneksi (esimerkiksi `max_turns: 1`) voidaan pakottaa yksittäinen vastaus ilman minkäänlaisia työkalukutsuja.

## Asynkroninen suoritus ja valtuutus ilman valvontaa

Jos kutsusi tulee hälytys-WebHookista, CI/CD:stä, valvontajärjestelmästä tai muusta taustatehtävästä, voit asettaa `async: true`, jolloin rajapinta palauttaa välittömästi tehtävän ID:n ja jatkaa suoritusta taustalla:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Palautusesimerkki:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Sen jälkeen voit kysyä keskustelun tuloksen käyttämällä `action: retrieve` + `id`; voit myös antaa `callback_url`-osoitteen, jolloin alusta POSTaa `{ status, answer, usage, error }` takaisinsoitto-osoitteeseesi tehtävän valmistuttua. `callback_url`:n on käytettävä `http` / `https`-protokollaa, eikä siihen voi suoraan kirjoittaa `localhost`-osoitetta tai yksityisen IP-osoitteen literaalia.

Taustatehtävissä ei yleensä ole ketään, joka voi klikata vahvistuksen. Jos haluat tiettyjen Skillien tai MCP Serverien suorittavan lähetys-, julkaisu-, kirjoitus- tai muita toimintoja ilman valvontaa, välitä pyynnön rungossa eksplisiittisesti esivaltuutusluettelo:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

`allowed_skills`-kentän arvot ovat yhdistettyjen Skillien slugeja; `allowed_mcp_servers`-kentän arvot ovat yhdistettyjen MCP Serverien slugeja. Skillit / MCP Serverit, joita ei ole lueteltu esivaltuutuksissa, voivat ilman valvontaa edelleen vain esikatsella, suorittaa dry-runin tai kieltäytyä kirjoitustoimintojen suorittamisesta.

Jos tarvitset tarkempaa hallintaa, voit käyttää myös vastaavaa `unattended_policy`-objektia:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Esivaltuutus koostuu näistä kahdesta luettelosta itsestään: tyhjä luettelo ei valtuuta mitään toimintoja, eikä ylimääräistä kytkinkenttää tarvita.

Huomaa: esivaltuutus tarkoittaa vain, että ”tämä pyyntö sallii näiden toimintojen ohittaa ihmisen vahvistuksen ilman valvontaa”. Kyseisen Skillin on edelleen tuettava `--unattended-confirm`-toimintoa tai vastaavaa turvamekanismia; muutoin se jatkaa dry-runina eikä suorita kirjoitustoimintoja suoraan.

## Keskeytetyn keskustelun jatkaminen

Jotkin työkalut saavat mallin ”esittämään vastakysymyksen käyttäjälle”; tällöin malli lähettää `ask_user_question`-tapahtuman, ja keskustelu jäädytetään `awaiting_user_input`-tilaan:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Renderöi tämä tapahtuma käyttöliittymässä kortiksi, josta käyttäjä voi valita vastauksen, ja käynnistä sitten seuraava pyyntö samalla `id`:llä täyttäen vastaus takaisin `tool_results`-kentän kautta:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

Pyynnön rungossa olevan `tool_use_id`:n **on oltava** täysin sama kuin keskeytyksen aikainen `tool_id`; ristiriita palauttaa virheen 400. Kun pyynnössä on samanaikaisesti `tool_results`, `question` / `message` / `references` jätetään kaikki huomiotta.

Jos käyttäjä päättää luopua tästä kysymyksestä, välitä suoraan uusi `question` / `message`, jolloin alusta merkitsee keskeytetyn työkalukutsun automaattisesti tilaan ”käyttäjä ohitti”.

## Keskustelujen hallinta (CRUD)

v2 tarjoaa kevyen keskustelujen hallinnan samalla endpointilla `action`-kentän kautta, ilman erillistä APIa.
### `action: retrieve` —— yhden keskustelun hakeminen

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Palauttaa koko keskusteluasiakirjan (mukaan lukien `messages`-historia, `model`, `title`, `tools_used` jne.).

### `action: retrieve_batch` —— keskusteluyhteenvetojen luetteleminen

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Palauttaa `{ items: [...], total }`. **Yhteenveto ei sisällä `messages`-kenttää**, joten se sopii sivupalkkiluetteloon; jos käyttäjä avaa tietyn keskustelun, hae sen täydelliset viestit erikseen käyttämällä `action: retrieve` -toimintoa.

Valinnaiset suodatusparametrit: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— otsikon muuttaminen tai historian uudelleenkirjoittaminen

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Hangzhoun matkasuunnitelma"
}
```

Myös `messages` voidaan välittää, mutta palvelin suorittaa tiukan schema-validoinnin (sen on oltava tiivistetty `ToolUseContent`-muoto), ja virheellisestä muodosta palautetaan 400. Yleensä sitä suositellaan käytettäväksi vain `title`-kentän muuttamiseen.

### `action: delete` —— yhden keskustelun poistaminen

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Palauttaa `{ id, success: true }`. Poistamisen jälkeen tietoja ei voi palauttaa, joten varmista ennen kutsua.

## Sujuva siirtyminen v1:stä

Jos käytät jo [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations) -rajapintaa, siirtyminen v2:een ei käytännössä vaadi koodimuutoksia:

1. Vaihda URL-osoite `https://api.acedata.cloud/aichat/conversations` osoitteeksi `https://api.acedata.cloud/aichat2/conversations`.
2. Jos välitit aiemmin v1-mallin nimen (kuten `gpt-3.5`, `gpt-4-browsing` jne.), v2:een siirtyessä suositellaan päivittämistä nykyaikaisiin malleihin (kuten `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` jne.).
3. NDJSON-virran kentät säilyvät taaksepäin yhteensopivina: jokainen `text_delta`-tapahtuma sisältää edelleen `delta_answer`- ja `id`-kentät, joten asiakkaisiin, jotka aiemmin jäsensivät `delta_answer`-kentän rivi kerrallaan, ei tarvitse tehdä muutoksia.

Siirtymisen jälkeen voit tarvittaessa ottaa käyttöön v2:n uudet ominaisuudet (monimuotoinen `message`, SSE, työkalukutsut, `action` CRUD) ja edetä omaan tahtiin.

## Virheenkäsittely

Virhevastausten yhtenäinen muoto on:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Yleiset virheet:

- `400 bad_request`: pakollisia kenttiä puuttuu, `tool_use_id` ei täsmää, `messages`-schema on virheellinen jne.
- `401 invalid_token`: `authorization`-otsake on virheellinen.
- `404 not_found`: `action: retrieve / update / delete` -toimintojen yhteydessä `id`-kenttää vastaavaa keskustelua ei ole olemassa.
- `429 too_many_requests`: nopeusrajoitus on laukaistu.
- `500 chat_error`: ylävirran LLM palautti virheen tai tämän kierroksen `completion_tokens=0` (käsitellään käyttämättömänä, eikä siitä veloiteta).

Virtaavassa vastauksessa virhe lähetetään `{"type":"error","message":"..."}`-tapahtumana, minkä jälkeen virta päättyy välittömästi.

## Yhteenveto

AI Chat v2 API säilyttää v1:n taaksepäin yhteensopivuuden ja nostaa keskustelut tasolta ”yhden kierroksen / monen kierroksen kysymys-vastaus” tasolle ”agenttipohjaiset, havainnoitavat keskustelut”: monimuotoiset syötteet, työkalukutsut, keskeytettävät / jatkettavat keskustelut, virtaavat rakenteiset tapahtumat ja sisäänrakennettu CRUD. Uusien integraatioiden suositellaan käyttävän suoraan v2:ta; olemassa olevat v1-integraatiot voidaan siirtää sujuvasti vaiheittain. Jos sinulla on kysyttävää, ota milloin tahansa yhteyttä tekniseen tukitiimiimme.
