AI Chat v2 API (`/aichat2/conversations`) on uuden sukupolven keskustelurajapinta, joka on [AI Chat API:n](https://platform.acedata.cloud/documents/59fb1199-6694-4afb-a222-3554d7f7d05a) kattava päivitysversio. Se laajentaa v1:n yksinkertaista, monikierroksista keskustelua hallinnoivaa rajapintaa seuraavasti:

- **Monimuotoiset käyttäjätulot**: Voit lähettää rakenteellisesti `message`-kentässä suoraan tekstiä + kuvia + tiedostolohkoja ilman, että tarvitsee liittää niitä ensin `references`-kentän kautta.
- **Agenttipohjainen työkalukutsu**: Sisäänrakennettu joukko työkaluja kuten verkkohaku, verkkosivujen kaappaus, tiedostojen lukeminen, ja voit liittää käyttäjän valtuuttamat MCP-palvelimet (Google Drive, Notion, Slack, GitHub jne.). Malli voi yhdessä pyynnössä itsenäisesti kutsua työkaluja monikierroksisesti suorittaakseen monimutkaisia tehtäviä.
- **Rakenteelliset suoravirtaustapahtumat**: Käyttämällä `accept: text/event-stream` tai `application/x-ndjson` saat token-tokenilta `text_delta`-, `tool_use`-, `tool_result`-, `thinking`-, `citation`-, `card`-, `artifact`-tyyppisiä tapahtumia, joita frontendissä voi renderöidä erikseen tyypin mukaan.
- **Keskeytettävä / palautettavissa oleva**: Malli lähettää `ask_user_question`-tapahtuman ja pysähtyy, kun se tarvitsee käyttäjältä lisätietoa. Seuraavalla kutsulla vastaukset täytetään `tool_results`-kenttään ja keskustelu jatkuu.
- **Uudet CRUD-toiminnot**: Samassa endpointissa `action`-kentän kautta voi suorittaa `retrieve` / `retrieve_batch` / `update` / `delete` -toimintoja ilman erillistä istunnonhallinta-API:a.
- **Jatkuvasti päivittyvä mallilista**: Oletuksena käytössä GPT-5.4, Claude Opus 4.7, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K2.5 ym. nykyaikaiset mallit.

Se on myös **täysin taaksepäin yhteensopiva v1:n kanssa** pyynnön tasolla: pelkkä `model` + `question` (+ valinnainen `stateful` / `id` / `references` / `preset`) palauttaa v1:n kaltaisen `{answer, id}` JSON-vastauksen, joten siirtyminen `/aichat/conversations` -polusta `/aichat2/conversations` -polkuun ei vaadi asiakasohjelman uudelleenkirjoitusta.

> Jos käytät nyt `/aichat/conversations` -rajapintaa, vanha rajapinta säilyy palvelussa ja voit siirtyä omaan tahtiisi.

## Hakemusprosessi

API:n käyttöä varten sinun tulee ensin hakea palvelua [AI Chat v2 API](https://platform.acedata.cloud/documents/e4a7c2b9-3f1d-4e8a-9b6c-a5d2f8e1b4c7) -sivulta. Sivulle tultuasi klikkaa "Acquire"-painiketta saadaksesi pyynnöissä tarvittavan tunnistautumistiedon.

Jos et ole kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle. Rekisteröitymisen ja kirjautumisen jälkeen palaat automaattisesti takaisin tälle sivulle.

Ensimmäisen hakemuksen yhteydessä saat ilmaisen käyttökiintiön, jolla voit käyttää API:a maksutta.

## Peruskäyttö

Yksinkertaisin käyttö on täysin sama kuin v1:ssä: lähetä `model` + `question` ja saat `{answer, id}` vastauksen.

CURL-esimerkki:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Vastaus:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python-esimerkki:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Monikierroksinen keskustelu

Kuten v1:ssä, lähetä `stateful: true` aktivoidaksesi keskustelun tallennuksen. API palauttaa `id`-arvon, jota seuraavissa pyynnöissä käytetään keskustelun jatkamiseen ilman, että sinun tarvitsee itse ylläpitää viestihistoriaa.

Ensimmäinen pyyntö:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Vastaus:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Toinen pyyntö, sama `id` mukana:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` on oletuksena `true`. Jos et halua palvelimen tallentavan keskustelua, aseta `stateful: false` eksplisiittisesti.

## Suoravirtauskäsittely

v2 tukee kahta suoravirtausformaattia, jotka valitaan `accept`-otsikolla:

| Käyttötapaus | `accept` | Datan muoto |
| :--- | :--- | :--- |
| Web frontend / EventSource | `text/event-stream` | `data: {json}\n\n`, viimeinen rivi `data: [DONE]\n\n` |
| Palvelin / CLI / Node suoravirtausanalyysi | `application/x-ndjson` | Jokainen rivi on JSON-objekti |
| Ei suoravirtausta | `application/json` (oletus) | Palauttaa kerralla `{answer, id}` |

### NDJSON-esimerkki

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # Yhteensopiva v1:n kanssa: delta_answer-kenttä sisältää inkrementaalisen vastauksen
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

NDJSON:n jokainen rivi on rakenteellinen tapahtuma, yleisin on `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE-esimerkki

Selainpuolella `EventSource` ei tue mukautettua pyyntöä, joten suositellaan `fetch`-kutsua ja manuaalista `\n\n`-pilkkomista:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Suoravirtaustapahtumien tyypit

| `type` | Merkitys |
| :--- | :--- |
| `text_delta` | Avustajan inkrementaalinen vastausteksti. `content` on lisätty sisältö; yhteensopivuuden vuoksi mukana myös `delta_answer` (sama kuin `content`) ja `id`. |
| `thinking` | Mallin ajatteluprosessi (näkyy vain, jos valittu malli paljastaa päättelyvaiheet). |
| `tool_use` | Malli päättää kutsua työkalua, tapahtumassa `tool_id`, `tool_name`, `input`. |
| `tool_result` | Työkalun suoritus tulos, yhdistyy edelliseen `tool_use`-tapahtumaan `tool_id`:n kautta, `is_error` kertoo epäonnistumisesta. |
| `card` | Työkalun tuottama rakenteellinen kortti (esim. kuva, linkkiesikatselu), suoraan renderöitävä. |
| `citation` | Lähde-URL, joka täydentää vastaavan tekstikohdan viitettä. |
| `ask_user_question` | Malli tarvitsee käyttäjältä lisätietoa, keskustelu siirtyy `awaiting_user_input`-tilaan, ks. alla [Keskeytetyn keskustelun palautus](#keskeytetyn-keskustelun-palautus). |
| `artifact` | Mallin tuottama itsenäinen tuotos (esim. koodilohko, dokumentti), tallennettavissa tai ladattavissa. |
| `system_message` | Järjestelmän ilmoitus (ei käyttäjän tai avustajan sisältöä), UI:n käyttöön. |
| `compact` | Sisäinen konteksti on pakattu, ei vaadi erityiskäsittelyä. |
| `error` | Virhe tässä kierroksessa, `message` kuvaa virheen. |
| `done` | Suoravirtauskäsittely päättyy, mukana `usage` (sisältäen `prompt_tokens` / `completion_tokens` / `total_tokens`) ja `terminal_reason`. |

Jos asiakasohjelma haluaa vain lopullisen vastauksen, yhdistämällä kaikki `text_delta`-tapahtumien `content`-kentät saa saman tuloksen kuin `application/json`-tilassa `answer`.

## Monimuotoiset syötteet

Jos käyttäjän syöte sisältää kuvia tai tiedostoja, lähetä `message`-taulukko `question`-kentän sijaan. Jokainen taulukon elementti on sisältölohko:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Tuetut lohkotyypit:

- `text` — tavallinen teksti, vaatii `text`-kentän.
- `image_url` — kuva, vaatii `image_url.url`-kentän.
- `file_url` — tiedosto (PDF, CSV, TXT jne.), vaatii `file_url.url`-kentän.

### Suhde v1:n `references`-kenttään

Yhteensopivuuden vuoksi v2 tunnistaa edelleen `references: ["https://...", ...]`:

- URL-osoitteen pääte `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif` muunnetaan automaattisesti `image_url`-lohkoksi;
- Muut tiedostopäätteet muunnetaan `file_url`-lohkoksi;
- Jos mukana on myös `question`, se sijoitetaan `text`-lohkon eteen.

Jos haluat siirtyä v1:stä v2:een muuttamatta pyyntöä, vaihda vain polku `/aichat2/conversations` -muotoon, vanha `references` toimii edelleen.

Jos haluat tarkempaa kontrollia (esim. useita kuvia tekstin seassa tai tärkeysjärjestys), käytä suoraan `message`-taulukkoa.

## Työkalukutsut ja MCP

v2:n keskeinen parannus on, että malli voi itsenäisesti kutsua työkaluja monivaiheisten tehtävien suorittamiseen, **tämä on oletuksena päällä** eikä asiakasohjelman tarvitse tehdä mitään lisäasetuksia pyynnössä. Tavallisia käyttötapauksia:

- Käyttäjä kysyy: "Etsi minulle viimeisimmät Shanghain näyttelyt" → malli kutsuu sisäänrakennettua web search -työkalua → koostaa vastauksen.
- Käyttäjä pyytää: "Lue tämä PDF ja tee tiivistelmä" → malli kutsuu file_read-työkalua → kirjoittaa tiivistelmän.
- Käyttäjä on valtuuttanut Google Drive / GitHub / Notion -palvelut [Connections](https://platform.acedata.cloud/connections) -sivulla → malli voi kutsua vastaavia MCP-työkaluja lukeakseen ja kirjoittaakseen dataa.

NDJSON / SSE-suoravirtauksessa työkalukutsut näkyvät `tool_use`- ja `tool_result`-tapahtumina, esimerkiksi:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Jos et halua näyttää työkalukutsujen yksityiskohtia frontendissä, voit jättää huomiotta `tool_use` / `tool_result` / `card` / `citation` -tapahtumat. Mallin lopullinen vastaus tulee silti `text_delta`-tapahtumina.

`max_turns`-parametrilla voi rajoittaa, kuinka monta kertaa malli saa kutsua työkaluja tässä pyynnössä. Oletusraja on alustalla. Pienentämällä (esim. `max_turns: 1`) pakotat yksittäisen vastauksen ilman työkalukutsuja.

## Keskeytetyn keskustelun palautus

Jotkin työkalut saattavat pyytää mallia "kysyä käyttäjältä", jolloin malli lähettää `ask_user_question`-tapahtuman ja keskustelu jää `awaiting_user_input`-tilaan:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Frontend renderöi tämän korttina, jossa käyttäjä valitsee vastauksen. Sitten lähetetään seuraava pyyntö samalla `id`:llä, jossa vastaukset täytetään `tool_results`-kenttään:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

`tool_use_id` **täytyy** vastata täsmälleen keskeytyksen aikaisen `tool_id`:n arvoa; muuten palautetaan 400-virhe. Kun `tool_results` on mukana, `question` / `message` / `references` ohitetaan.

Jos käyttäjä haluaa ohittaa kysymyksen, voi lähettää uuden `question`- tai `message`-kentän, jolloin alusta merkitsee keskeytetyn työkalukutsun "käyttäjän ohittamaksi".

## Istunnonhallinta (CRUD)

v2 tarjoaa kevyen istunnonhallinnan samassa endpointissa `action`-kentän kautta, ei tarvetta erilliselle API:lle.

### `action: retrieve` — hae yksi istunto

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Palauttaa koko istuntodokumentin (sisältäen `messages`-historian, `model`-tiedon, `title`-otsikon, `tools_used` jne.).

### `action: retrieve_batch` — listaa istuntojen tiivistelmät

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Palauttaa `{ items: [...], total }`. **Tiivistelmät eivät sisällä `messages`-kenttää**, sopii sivupalkkilistaukseen; kun käyttäjä avaa istunnon, haetaan yksittäinen istunto `action: retrieve` -kutsulla.

Valinnaiset suodatusparametrit: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` — muuta otsikkoa tai uudelleenkirjoita historiaa

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

`messages`-kentän voi myös lähettää, mutta palvelin suorittaa tiukan skeeman tarkistuksen (täytyy olla tiivistetty `ToolUseContent`-muodossa), muuten palautetaan 400. Yleensä suositellaan vain `title`-muutoksia.

### `action: delete` — poista istunto

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Palauttaa `{ id, success: true }`. Poisto on peruuttamaton, varmista ennen kutsua.

## Sujuva siirtyminen v1:stä

Jos käytät jo [`/aichat/conversations`](https://platform.acedata.cloud/documents/59fb1199-6694-4afb-a222-3554d7f7d05a), siirtyminen v2:een vaatii lähes nolla koodimuutosta:

1. Vaihda URL `https://api.acedata.cloud/aichat/conversations` → `https://api.acedata.cloud/aichat2/conversations`.
2. Jos käytit v1-mallinimiä (esim. `gpt-3.5`, `gpt-4-browsing`), suosittelemme päivittämään nykyaikaisiin malleihin (esim. `gpt-5.4`, `claude-opus-4-7`, `gemini-3.1-pro`).
3. NDJSON-virtauskentät ovat taaksepäin yhteensopivia: jokainen `text_delta` sisältää edelleen `delta_answer` ja `id`, joten rivikohtainen `delta_answer`-käsittely toimii ennallaan.

Siirtymisen jälkeen voit halutessasi ottaa käyttöön v2:n uudet ominaisuudet (monimuotoiset `message`-syötteet, SSE, työkalukutsut, `action` CRUD) omaan tahtiin.

## Virheenkäsittely

Virhevastaukset ovat yhtenäisiä:

```json
{
  "error": {
    "code": "chat_error",
    "message": "upstream LLM returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Yleisiä virheitä:

- `400 bad_request`: puuttuva pakollinen kenttä, `tool_use_id` ei täsmää, `messages`-skeema virheellinen jne.
- `401 invalid_token`: väärä `authorization`-otsikko.
- `404 not_found`: `action: retrieve / update / delete` -kutsu ei löydä istuntoa annetulla `id`:llä.
- `429 too_many_requests`: ylitetty nopeusrajoitus.
- `500 chat_error`: ylävirran LLM-virhe tai kierroksen `completion_tokens=0` (käsitellään kuluttamattomana, ei veloiteta).

Suoravirtauskäsittelyssä virheet lähetetään `{"type":"error","message":"..."}`-tapahtumana ja virran lähetys päättyy heti.

## Yhteenveto

AI Chat v2 API on taaksepäin yhteensopiva v1:n kanssa, mutta laajentaa keskustelun "yksikierroksisesta / monikierroksisesta kysymys-vastaus" -mallista "agenttipohjaiseksi havaittavaksi keskusteluksi": monimuotoiset syötteet, työkalukutsut, keskeytettävä / palautettavissa oleva tila, suoravirtausrakenteiset tapahtumat ja sisäänrakennetut CRUD-toiminnot. Suosittelemme uusien integraatioiden aloittamista suoraan v2:lla; olemassa olevat v1-integraatiot voivat siirtyä vaiheittain. Ota yhteyttä tekniseen tukeemme, jos tarvitset apua.
