AI Chat v2 API (`/aichat2/conversations`) on uuden sukupolven keskustelurajapinta ja kattava päivitys [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations) -rajapintaan. Se laajentaa v1-version yksinkertaista, hallittua monivuorovaikutteista keskustelua seuraavilla ominaisuuksilla:

- **Multimodaalinen käyttäjän syöte**: Voit välittää suoraan tekstiä + kuvia + tiedostolohkoja rakenteisen `message`-kentän kautta ilman, että niitä tarvitsee ensin liittää epäsuorasti `references`-kentän avulla.
- **Agenttipohjaiset työkalukutsut**: Sisäänrakennettuna on joukko työkaluja verkkohakuun, verkkosivujen hakemiseen, tiedostojen lukemiseen ja muihin toimintoihin. Lisäksi voidaan liittää käyttäjän valtuuttamia MCP-palvelimia (Google Drive, Notion, Slack, GitHub jne.). Malli voi kutsua työkaluja itsenäisesti useita kertoja yhden pyynnön aikana monimutkaisten tehtävien suorittamiseksi.
- **Rakenteiset suoratoistotapahtumat**: Otsakkeella `accept: text/event-stream` tai `application/x-ndjson` voidaan vastaanottaa tapahtumia, kuten `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card` ja `artifact`, token kerrallaan. Tämä helpottaa niiden erillistä renderöintiä käyttöliittymässä tapahtumatyypin mukaan.
- **Keskeytettävyys / jatkettavuus**: Kun malli tarvitsee käyttäjältä lisätietoja, se lähettää `ask_user_question`-tapahtuman ja keskeyttää toiminnan. Seuraavalla kutsukerralla keskustelua voidaan jatkaa täyttämällä vastaukset `tool_results`-kenttään.
- **Uudet CRUD-toiminnot**: Samassa endpoint-osoitteessa voidaan suorittaa `retrieve` / `retrieve_batch` / `update` / `delete` `action`-kentän avulla ilman erillistä keskustelunhallinnan API-rajapintaa.
- **Jatkuvasti päivittyvä malliluettelo**: Oletusarvoisesti käytettävissä ovat GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 ja muut nykyiset mallit.

Samalla se on pyynnön rungon tasolla **täysin taaksepäin yhteensopiva v1-version kanssa**: välittämällä vain `model` + `question` (sekä valinnaisesti `stateful` / `id` / `references` / `preset`) saat v1-versiota vastaavan `{answer, id}` JSON-vastauksen. Siksi siirtyminen `/aichat/conversations`-rajapinnasta ei edellytä asiakasohjelman uudelleenkirjoittamista. Riittää, että vaihdat poluksi `/aichat2/conversations`.

> Jos käytät tällä hetkellä `/aichat/conversations`-rajapintaa, vanha rajapinta säilyy edelleen käytettävissä. Voit siirtyä uuteen rajapintaan oman aikataulusi mukaisesti.

## Peruskäyttö

Yksinkertaisin käyttötapa on täysin sama kuin v1-versiossa: välitä `model` + `question` ja vastaanota `{answer, id}`.

CURL-esimerkki:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Palautettu tulos:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python-esimerkki:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Monivuorovaikutteinen keskustelu

Kuten v1-versiossa, ota keskustelun tallennus käyttöön asettamalla `stateful: true`. API palauttaa tällöin `id`-tunnuksen. Seuraavissa pyynnöissä voit jatkaa keskustelua välittämällä saman `id`-tunnuksen takaisin ilman, että sinun tarvitsee itse ylläpitää messages-historiaa.

Ensimmäinen pyyntö:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Palautettu tulos:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Toinen pyyntö, jossa käytetään samaa `id`-tunnusta:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "Mikä oli numero, jonka pyysin sinua juuri muistamaan?"
  }'
```

```json
{
  "answer": "Pyytämäsi numero oli 42.",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` on oletusarvoisesti `true`, joten sen pois jättäminen vastaa arvon `true` eksplisiittistä välittämistä. Asetuksen `stateful: false` käyttäminen ohittaa aiemman keskusteluhistorian lataamisen; tämä ei tarkoita, ettei tämän kierroksen tuloksia tallennettaisi, eikä se sovellu työkaluprosesseihin, joita on tarkoitus jatkaa keskeytyksen jälkeen.

### Pitkät keskustelut ja alkuperäisen tekstin säilyttäminen

Kontekstin tiivistäminen järjestää vain tällä kierroksella mallille lähetettävän sisällön uudelleen, eikä se korvaa tallennettuja keskustelutietoja. Täydelliset tallennetut viestit voidaan edelleen lukea käyttämällä toimintoa `action: retrieve`; keskustelun nimenomainen muokkaaminen tai poistaminen tapahtuu edelleen pyynnön mukaisesti.

Malli voi etsiä ja lukea alkuperäisiä historiallisia viestejä sivutettuina tuloksina nykyisen keskustelun sisällä. Kun artikkelin muokkaamista jatketaan, numeroita lainataan tai sisältöä valmistellaan julkaistavaksi, vastaava alkuperäinen teksti on luettava. Yhteenvetoa ei saa käyttää varsinaisen tekstin korvikkeena. Tämä toiminto ei palauta automaattisesti vanhoista versioista jo kadonneita viestejä.

Jos kontekstin järjestely epäonnistuu, säilytä keskustelun tunniste ja tarkista `error`-tapahtuma. Palvelu ei korvaa alkuperäistä tekstiä tyhjällä yhteenvedolla. Ennen virhettä suoritetut työkalutoiminnot saattavat silti olla voimassa, joten tarkista ensin niiden tulokset välttääksesi sisällön uudelleenluomisen tai julkaisemisen. Kun yksittäinen keskustelu saavuttaa tallennusrajan, siitä ilmoitetaan selkeästi virheilmoituksella. Aiemmin tallennetuille tiedoille ei vapauteta tilaa leikkaamalla sisältöä; tarvittava sisältö voidaan viedä ja sen jälkeen aloittaa uusi keskustelu.

## Suoratoistovastaukset

v2 tukee kahta suoratoistomuotoa, jotka valitaan `accept`-otsakkeen avulla:

| Tilanne                    | `accept`               | Tietomuoto                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Verkkokäyttöliittymä / EventSource  | `text/event-stream`    | `data: {json}\n\n`, viimeinen rivi `data: [DONE]\n\n` |
| Palvelin / CLI / Node-suoratoistokäsittely | `application/x-ndjson` | Yksi JSON-objekti kullakin rivillä                               |
| Ei tarvetta suoratoistolle                 | `application/json`（oletus） | Kertapalautus `{answer, id}`                       |

### NDJSON-esimerkki

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "Esittele Hangzhou kolmella lauseella.",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # Yhteensopivuus v1-version kanssa: lisätyt tekstikatkelmat toimitetaan samalla delta_answer-kentän kautta
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Jokainen NDJSON-rivi on rakenteinen tapahtuma, joista yleisin on `text_delta`:

```json
{"type":"text_delta","content":"Hang","delta_answer":"Hang","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"zhou","delta_answer":"zhou","id":"f2f4b3e8-..."}
{"type":"text_delta","content":" on","delta_answer":" on","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE-esimerkki

Selaimen `EventSource` ei tue mukautettua pyyntörunkoa, joten on suositeltavaa käyttää yhdistelmää `fetch` + manuaalinen jäsentäminen jakamalla sisältö osiin merkkijonon `\n\n` perusteella:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "Esittele Hangzhou kolmella lauseella.",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Suoratoistotapahtumien tyypit

| `type`              | Merkitys                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Avustajan vastauksen uusi tekstikatkelma. `content` sisältää lisätyn sisällön; v1-yhteensopivuuden vuoksi sama tapahtuma sisältää myös `delta_answer`-kentän (sama kuin `content`) ja `id`-kentän.                                        |
| `thinking`          | Mallin ajatteluprosessi (näkyy vain, jos valittu malli tuo reasoning-tiedot saataville).                                                                                      |
| `tool_use`          | Malli päättää kutsua työkalua. Tapahtuma sisältää kentät `tool_id`, `tool_name` ja `input`.                                                                        |
| `tool_result`       | Työkalun suorittamisen tulos, joka yhdistetään edelliseen `tool_use`-tapahtumaan `tool_id`-kentän avulla. `is_error` ilmaisee, epäonnistuiko suoritus.                                                             |
| `card`              | Työkalun tuottama rakenteinen kortti (kuten kuva tai linkin esikatselu), joka soveltuu suoraan renderöitäväksi.                                                                                          |
| `citation`          | Vastaavan tekstikatkelman lähde-URL-osoitteen täydentämiseen käytettävä viite.                                                                                                  |
| `ask_user_question` | Lähetetään, kun malli tarvitsee käyttäjältä lisätietoja. Keskustelu siirtyy tilaan `awaiting_user_input`. Katso lisätiedot jäljempänä kohdasta [Keskeytetyn keskustelun jatkaminen](#恢复暂停的对话)。                                                 |
| `artifact`          | Mallin luoma itsenäinen tuotos (kuten koodilohko tai asiakirja), joka voidaan tallentaa tai ladata.                                                                                            |
| `system_message`    | Järjestelmän ilmoitus (ei käyttäjän tai avustajan sisältöä), jota käytetään vain käyttöliittymän ilmoituksena.                                                                                           |
| `compact`           | Mallin konteksti on järjestetty uudelleen; tallennetut alkuperäiset viestit pysyvät muuttumattomina, eikä asiakkaan tarvitse poistaa keskusteluhistoriaa.                                                                                    |
| `error`             | Tällä kierroksella tapahtui virhe. `message` kuvaa virheen sisältöä.                                                                                              |
| `done`              | Tämän kierroksen lopullinen keskustelutietue on tallennettu onnistuneesti. Tapahtuma sisältää `usage`-kentän (mukaan lukien `prompt_tokens` / `completion_tokens` / `total_tokens`) ja `terminal_reason`-kentän; tehtävän valmistuminen on silti arvioitava lopetussyyn perusteella.        |
For asiakkaille, joita kiinnostaa vain lopullinen vastaus, kaikkien `text_delta`-tapahtumien `content`-kenttien yhdistäminen vastaa `application/json`-tilassa olevaa `answer`-kenttää.

## Multimodaalinen syöte

Jos käyttäjän syöte sisältää kuvia tai tiedostoja, välitä `message` (taulukkona) `question`-kentän sijaan. Jokainen taulukon alkio on sisältölohko:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "Kuinka monta kissaa tässä kuvassa on?" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Tuetut lohkotyypit:

- `text` — tavallinen teksti, pakollinen `text`-kenttä.
- `image_url` — kuva, pakollinen `image_url.url`.
- `file_url` — tiedosto (PDF, CSV, TXT jne.), pakollinen `file_url.url`.

### Suhde v1-version `references`-kenttään

Yhteensopivuuden säilyttämiseksi vanhojen asiakkaiden kanssa v2 tunnistaa edelleen kentän `references: ["https://...", ...]`:

- URL-osoitteet, joiden tiedostopääte on `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, muunnetaan automaattisesti `image_url`-lohkoiksi;
- muut tiedostopäätteet muunnetaan `file_url`-lohkoiksi;
- jos samalla annetaan myös `question`, se lisätään ensimmäiseksi `text`-lohkoksi.

Jos siis haluat vain siirtyä v1-versiosta muuttamatta pyyntörunkoa, vaihda poluksi `/aichat2/conversations`, niin alkuperäinen `references`-käyttötapa toimii edelleen.

Jos tarvitset tarkempaa hallintaa (esimerkiksi useiden kuvien sijoittamista tekstin väliin tai jos järjestyksellä on merkitystä), käytä suoraan `message`-taulukkoa.

## Työkalukutsut ja MCP

v2-version keskeinen parannus on, että malli voi kutsua työkaluja itsenäisesti suorittaakseen monivaiheisia tehtäviä. **Tämä on oletusarvoisesti käytössä**, eikä asiakkaan tarvitse tehdä pyyntöön mitään lisämäärityksiä. Yleisiä käyttötapauksia:

- Käyttäjä kysyy: ”Etsi minulle viimeisimmät uudet näyttelyt Shanghaissa” → malli kutsuu sisäänrakennettua verkkohakua → kokoaa tulokset vastaukseksi.
- Käyttäjä kysyy: ”Lue tämä PDF ja kirjoita siitä yhteenveto” → malli kutsuu file_read-työkalua → kirjoittaa yhteenvedon.
- Käyttäjä on valtuuttanut Google Driven / GitHubin / Notionin jne. [Connections](https://platform.acedata.cloud/connections)-osiossa → malli voi kutsua vastaavia MCP-työkaluja tietojen lukemiseen ja kirjoittamiseen.

NDJSON- / SSE-virrassa työkalukutsut esitetään kahdentyyppisinä tapahtumina: `tool_use` ja `tool_result`. Esimerkiksi:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"Shanghai spring exhibitions 2026"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"Tällä hetkellä","delta_answer":"Tällä hetkellä","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"Shanghai","delta_answer":"Shanghai","id":"f2f4b3e8-..."}
...
```

Jos et halua näyttää työkalukutsujen yksityiskohtia käyttöliittymässä, voit ohittaa seuraavat tapahtumatyypit: `tool_use` / `tool_result` / `card` / `citation`. Mallin lopullinen tuloste välitetään edelleen `text_delta`-tapahtumina.

`max_turns`-parametrilla voidaan rajoittaa, kuinka monta työkalukutsukierrosta malli voi enintään suorittaa itsenäisesti tämän pyynnön aikana. Arvoalue on 1–500, ja oletusarvo on 500, jos parametri jätetään pois. Asettamalla arvoksi pienen luvun (esimerkiksi `max_turns: 1`) voit pakottaa mallin antamaan vastauksen ilman työkalukutsuja.

## Asynkroninen suoritus ja valtuutus ilman valvontaa

Jos kutsu tulee hälytyksen Webhookista, CI/CD-järjestelmästä, valvontajärjestelmästä tai muusta taustatehtävästä, voit asettaa arvoksi `async: true`, jolloin rajapinta palauttaa tehtävän tunnuksen välittömästi ja suoritus jatkuu taustalla:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Palveluni on lähettänyt hälytyksen. Ilmoita siitä henkilökohtaisella WeChat-tililläni WeChat-ryhmälle ”AceDataCloud-tiimi”……"
}
```

Esimerkki palautettavista tiedoista:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Tämän jälkeen voit hakea keskustelun tuloksen käyttämällä `action: retrieve` -toimintoa ja `id`-tunnusta. Voit myös antaa `callback_url`-osoitteen, jolloin alusta lähettää tehtävän valmistuttua POST-pyynnöllä tiedot `{ status, answer, usage, error }` takaisin määrittämääsi osoitteeseen. `callback_url`-osoitteen on käytettävä protokollaa `http` / `https`, eikä siinä voi käyttää suoraan osoitetta `localhost` tai yksityisen IP-osoitteen kirjaimellista arvoa.

Taustatehtävissä ei yleensä ole ketään vahvistamassa toimintoja napsauttamalla. Jos haluat joidenkin Skillien tai MCP Serverien suorittavan lähetys-, julkaisu-, kirjoitus- tai muita vastaavia toimintoja ilman valvontaa, välitä pyyntörungossa erikseen ennakkovaltuutettujen luettelo:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Palveluni on lähettänyt hälytyksen. Ilmoita siitä henkilökohtaisella WeChat-tililläni WeChat-ryhmälle ”AceDataCloud-tiimi”……"
}
```

`allowed_skills`-luettelon arvot ovat yhdistettyjen Skillien slug-tunnuksia; `allowed_mcp_servers`-luettelon arvot ovat yhdistettyjen MCP Serverien slug-tunnuksia. Skillit / MCP Serverit, joita ei ole lisätty ennakkovaltuutukseen, voivat valvomattomassa tilassa edelleen vain esikatsella, suorittaa dry-run-toiminnon tai kieltäytyä kirjoitustoiminnoista.

Jos tarvitset tarkempaa hallintaa, voit käyttää myös vastaavaa `unattended_policy`-objektia:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Ennakkovaltuutus koostuu näistä kahdesta luettelosta: tyhjä luettelo tarkoittaa, ettei mitään toimintoja ole valtuutettu, eikä erillistä kytkinkenttää tarvita.

Huomaa: ennakkovaltuutus tarkoittaa ainoastaan sitä, että ”tämä pyyntö sallii näiden toimintojen suorittamisen ilman manuaalista vahvistusta valvomattomassa tilassa”. Kyseisen Skillin on silti tuettava toimintoa `--unattended-confirm` tai vastaavaa turvamekanismia. Muussa tapauksessa se jatkaa dry-run-tilassa eikä suorita kirjoitustoimintoja suoraan.

## Keskeytettyjen keskustelujen jatkaminen

Jotkin työkalut saavat mallin ”esittämään käyttäjälle lisäkysymyksen”. Tällöin malli lähettää `ask_user_question`-tapahtuman, ja keskustelu jäädytetään tilaan `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Haluatko luoda raportin suomeksi vai englanniksi?",
  "options": ["Suomeksi", "Englanniksi"],
  "id": "f2f4b3e8-..."
}
```

Näytä tämä tapahtuma käyttöliittymässä korttina, jossa käyttäjä voi valita vastauksen. Käynnistä sen jälkeen uusi pyyntö samalla `id`-tunnuksella ja täytä vastaus takaisin `tool_results`-kentän kautta:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

Pyynnön rungossa `tool_use_id` **täytyy** olla täsmälleen sama kuin keskeytyshetken `tool_id`; muuten palautetaan virhe 400. Kun pyyntö sisältää samanaikaisesti `tool_results`-kentän, kentät `question` / `message` / `references` ohitetaan.

Jos käyttäjä päättää luopua tästä kysymyksestä, riittää, että lähetetään suoraan uusi `question` / `message`. Alusta merkitsee keskeytetyn työkalukutsun automaattisesti tilaan ”käyttäjä ohitti”.

## Istunnonhallinta (CRUD)

v2 tarjoaa samalla endpointilla kevyen istunnonhallinnan `action`-kentän avulla, eikä erillistä API:a tarvita.

### `action: retrieve` —— Hae yksi istunto

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Palauttaa koko istuntoasiakirjan (mukaan lukien `messages`-historian, `model`-, `title`- ja `tools_used`-kentät).

### `action: retrieve_batch` —— Listaa istuntojen yhteenvedot

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Palauttaa `{ items: [...], total }`. **Yhteenvedot eivät sisällä `messages`-kenttää**, joten ne sopivat sivupalkin luetteloon. Kun käyttäjä avaa jonkin istunnon, sen täydelliset viestit haetaan erikseen käyttämällä `action: retrieve` -toimintoa.

Valinnaiset suodatusparametrit: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Muuta otsikkoa tai kirjoita historia uudelleen

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Hangzhoun matkasuunnitelma"
}
```

Myös `messages` voidaan lähettää, mutta palvelin suorittaa sille tiukan skeemavalidoinnin (sen on oltava litistettyä `ToolUseContent`-muotoa). Muussa tapauksessa palautetaan virhe 400. Yleensä suositellaan käyttämään tätä vain `title`-kentän muuttamiseen.

### `action: delete` —— Poista yksi istunto

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Palauttaa `{ id, success: true }`. Poistamista ei voi peruuttaa, joten varmista asia ennen kutsun suorittamista.

## Sujuva siirtyminen v1:stä

Jos käytät jo [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations)-rajapintaa, siirtyminen v2:een ei käytännössä vaadi koodimuutoksia:

1. Muuta URL-osoite muodosta `https://api.acedata.cloud/aichat/conversations` muotoon `https://api.acedata.cloud/aichat2/conversations`.
2. Jos olet aiemmin käyttänyt v1-mallinimiä (kuten `gpt-3.5`, `gpt-4-browsing` jne.), v2:een siirtyessä on suositeltavaa päivittää nykyisiin malleihin (kuten `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` jne.).
3. NDJSON-virran kentät säilyvät taaksepäin yhteensopivina: jokainen `text_delta`-tapahtuma sisältää edelleen `delta_answer`- ja `id`-kentät, joten aiempien asiakkaiden, jotka jäsentävät `delta_answer`-kentän riveittäin, ei tarvitse tehdä muutoksia.

Siirtymisen jälkeen voit ottaa v2:n uudet ominaisuudet käyttöön tarpeen mukaan (multimodaalinen `message`, SSE, työkalukutsut, `action` CRUD) ja edetä omaan tahtiisi.

## Virheenkäsittely

Virhevastaukset ovat yhdenmukaisessa muodossa:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Yleiset virheet:

- `400 bad_request`: Pakollinen kenttä puuttuu, `tool_use_id` ei täsmää, `messages`-skeema on virheellinen jne.
- `401 invalid_token`: `authorization`-otsake on virheellinen.
- `404 not_found`: `action: retrieve / update / delete` -toiminnon yhteydessä `id`-tunnusta vastaavaa istuntoa ei ole olemassa.
- `413 conversation_storage_limit`: Istunto ylittää tallennusrajan, eikä olemassa olevia tallennettuja tietueita ole korvattu.
- `429 too_many_requests`: Pyyntöjen nopeusrajoitus on saavutettu.
- `503 context_compaction_failed`: Kontekstin tiivistäminen epäonnistui, mutta olemassa olevat tietueet säilyvät.
- `500 conversation_persist_failed`: Tämän kierroksen lopullinen tallennus epäonnistui. Vastaanotettu teksti ei tarkoita, että lopullinen tietue olisi tallennettu onnistuneesti. Tarkista asia istunnon ID:n avulla.
- `500 chat_error`: Palvelu ei ole tilapäisesti käytettävissä tai tämän kierroksen aikana ei tuotettu sisältöä (maksua ei veloiteta).

Virhe lähetetään suoratoistovastauksessa tapahtumana muodossa `{"type":"error","message":"..."}`, minkä jälkeen virta päättyy. `[DONE]` tarkoittaa vain siirron päättymistä. Jos mukana on `error`, pyyntöä ei voi pitää onnistuneena, eikä onnistumista ilmaisevaa `done`-tapahtumaa lähetetä.

## Yhteenveto

AI Chat v2 API säilyttää taaksepäin yhteensopivuuden v1:n kanssa ja päivittää samalla keskustelut ”yhden tai useamman kierroksen kysymys-vastaus”-mallista ”Agent-pohjaisiksi, havainnoitaviksi keskusteluiksi”: multimodaalinen syöte, työkalukutsut, keskeytys- ja jatkamismahdollisuus, rakenteiset suoratoistotapahtumat sekä sisäänrakennettu CRUD. Uusissa integraatioissa suositellaan käyttämään suoraan v2:ta. Olemassa olevat v1-integraatiot voidaan siirtää vaiheittain sujuvasti. Jos sinulla on kysyttävää, ota rohkeasti yhteyttä tekniseen tukitiimiimme.
