AI Chat v2 API (`/aichat2/conversations`) on uuden sukupolven keskustelurajapinta ja [AI Chat API:n](https://platform.acedata.cloud/documents/aichat-conversations) kattavasti päivitetty versio. Se laajentaa v1:n yksinkertaisen, hallinnoidun monikierroksisen keskustelun pohjalta seuraavilla ominaisuuksilla:

- **Monimuotoiset käyttäjäsyötteet**: Lähetä teksti + kuvat + tiedostolohkot suoraan strukturoidun `message`-kentän kautta ilman, että ne täytyy ensin liittää epäsuorasti `references`-kentällä.
- **Agenttipohjaiset työkalukutsut**: Sisältää joukon työkaluja verkkohakuun, verkkosivujen noutamiseen, tiedostojen lukemiseen ja muuhun, ja siihen voidaan liittää käyttäjän valtuuttamia MCP-palvelimia (Google Drive, Notion, Slack, GitHub jne.). Malli voi yhdessä pyynnössä kutsua työkaluja itsenäisesti useilla kierroksilla monimutkaisten tehtävien suorittamiseksi.
- **Strukturoidut suoratoistotapahtumat**: Käyttämällä `accept: text/event-stream`- tai `application/x-ndjson`-asetusta voit vastaanottaa token-kohtaisia `text_delta`-, `tool_use`-, `tool_result`-, `thinking`-, `citation`-, `card`-, `artifact`- ja muita tapahtumia, mikä helpottaa niiden erillistä renderöintiä käyttöliittymässä tyypin mukaan.
- **Keskeytettävä / jatkettava**: Kun malli tarvitsee käyttäjän lisätietoja, se lähettää `ask_user_question`-tapahtuman ja keskeyttää toimintansa. Seuraavassa kutsussa vastaus voidaan täyttää takaisin `tool_results`-kentän kautta, jolloin toiminta jatkuu.
- **Uudet CRUD-toiminnot**: Samassa endpointissa voidaan suorittaa `retrieve` / `retrieve_batch` / `update` / `delete` `action`-kentän kautta ilman erillistä keskustelunhallinta-APIa.
- **Jatkuvasti päivittyvä malliluettelo**: Oletuksena käytettävissä ovat nykyajan mallit, kuten GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4 ja Kimi K3.

Samalla se on pyyntötekstin tasolla **täysin taaksepäin yhteensopiva v1:n kanssa**: lähettämällä vain `model` + `question` (+ valinnaiset `stateful` / `id` / `references` / `preset`) saat v1:tä vastaavan `{answer, id}` JSON-vastauksen. Siksi siirtyminen `/aichat/conversations`-rajapinnasta ei edellytä asiakkaan uudelleenkirjoittamista, vaan riittää, että polku vaihdetaan muotoon `/aichat2/conversations`.

> Jos käytät tällä hetkellä `/aichat/conversations`-rajapintaa, vanha rajapinta pysyy edelleen käytettävissä, ja voit siirtyä omaan tahtiisi.

## Peruskäyttö

Yksinkertaisin käyttötapa on täysin sama kuin v1:ssä: lähetä `model` + `question` ja saat `{answer, id}`.

CURL-esimerkki:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Palautettu tulos:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python-esimerkki:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Monikierroksinen keskustelu

Kuten v1:ssä, lähetä `stateful: true` ottaaksesi keskustelun tallennuksen käyttöön. API palauttaa `id`-tunnuksen; voit jatkaa keskustelua tuomalla `id`-tunnuksen takaisin myöhempiin pyyntöihin ilman, että sinun tarvitsee itse ylläpitää messages-historiaa.

Ensimmäinen pyyntö:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Palautus:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Toinen pyyntö, lähetä sama `id` mukana:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` on oletusarvoisesti `true`; sen pois jättäminen vastaa `true`-arvon välittämistä eksplisiittisesti. Asettaminen `stateful: false` ohittaa aiemman keskusteluhistorian lataamisen; tämä ei tarkoita, ettei tämän kierroksen tulosta tallennettaisi, eikä se sovellu työkalunkulkuihin, joita on jatkettava keskeytyksen jälkeen.

### Pitkät keskustelut ja alkuperäistekstin säilyttäminen

Kontekstin tiivistäminen järjestää vain tällä kierroksella mallille lähetettävän sisällön eikä korvaa tallennettuja keskustelutietueita. Voit edelleen lukea kaikki tallennetut viestit komennolla `action: retrieve`; eksplisiittinen muokkaaminen ja keskustelun poistaminen toimivat edelleen pyynnön mukaisesti.

Malli voi hakea ja lukea sivutettuna historian alkuperäistekstiä nykyisessä keskustelussa. Kun artikkelia on jatkettava muokkaamaan, numeroita siteerattava tai julkaisu valmisteltava, vastaava alkuperäisteksti on luettava eikä tiivistelmää saa käyttää leipätekstin korvikkeena. Tämä ominaisuus ei palauta automaattisesti vanhoissa versioissa jo menetettyjä viestejä.

Jos kontekstin järjestäminen epäonnistuu, säilytä keskustelun ID ja tarkista `error`-tapahtuma; palvelu ei korvaa alkuperäistekstiä tyhjällä tiivistelmällä. Ennen epäonnistumista suoritetut työkalutoiminnot voivat silti olla voimassa, joten tarkista ensin niiden tulokset välttääksesi päällekkäisen luomisen tai julkaisemisen. Kun yksittäinen keskustelu saavuttaa tallennusrajan, palautetaan selkeä virhe; olemassa oleville tallennetuille tietueille ei vapauteta tilaa karsimalla. Voit viedä tarvittavan sisällön ja aloittaa sitten uuden keskustelun.

## Suoratoistovastaukset

v2 tukee kahta suoratoistomuotoa, jotka valitaan `accept`-otsakkeen mukaan:

| Tilanne                    | `accept`               | Datan muoto                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web-käyttöliittymä / EventSource  | `text/event-stream`    | `data: {json}\n\n`, viimeinen rivi `data: [DONE]\n\n` |
| Palvelin / CLI / Node-suoratoistoanalyysi | `application/x-ndjson` | Yksi JSON-objekti kullakin rivillä                               |
| Suoratoistoa ei tarvita                 | `application/json`（oletus） | Palauttaa kerralla `{answer, id}`                       |

### NDJSON-esimerkki

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Jokainen NDJSON-rivi on jäsennelty tapahtuma, joista yleisin on `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE-esimerkki

Selaimessa `EventSource` ei tue mukautettua pyyntörunkoa, joten on suositeltavaa käyttää `fetch`-toimintoa + manuaalista jäsentämistä paloiksi `\n\n`-kohdan mukaan:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Suoratoistotapahtumien tyypit

| `type`              | Merkitys                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Avustajan vastauksen inkrementaalinen tekstikatkelma. `content` on uusi sisältö; v1-yhteensopivuuden vuoksi sama tapahtuma sisältää myös `delta_answer`-kentän (sama kuin `content`) ja `id`:n.                                        |
| `thinking`          | Mallin ajatteluprosessi (esiintyy vain, kun valittu malli paljastaa reasoning-tiedot).                                                                                      |
| `tool_use`          | Malli päättää kutsua työkalua; tapahtuma sisältää `tool_id`:n, `tool_name`:n ja `input`:in.                                                                        |
| `tool_result`       | Työkalun suoritustulos, joka yhdistetään edelliseen `tool_use`-tapahtumaan `tool_id`:n avulla; `is_error` ilmaisee, epäonnistuiko se.                                                             |
| `card`              | Työkalun tuottama jäsennelty kortti (kuten kuva tai linkin esikatselu), joka soveltuu suoraan renderöitäväksi.                                                                                          |
| `citation`          | Käytetään vastaavaa tekstikatkelmaa siteeraavan lähde-URL:n täydentämiseen.                                                                                                  |
| `ask_user_question` | Lähetetään, kun malli tarvitsee käyttäjältä lisätietoja; keskustelu siirtyy `awaiting_user_input`-tilaan, katso lisätietoja jäljempänä kohdasta [keskeytetyn keskustelun jatkaminen](#恢复暂停的对话)。                                                 |
| `artifact`          | Mallin luoma itsenäinen tuotoksena (kuten koodilohko tai asiakirja), joka voidaan tallentaa tai ladata.                                                                                            |
| `system_message`    | Järjestelmän ilmoitusviesti (ei käyttäjän tai avustajan sisältöä), vain käyttöliittymäilmoituksia varten.                                                                                           |
| `compact`           | Mallin konteksti on järjestetty; tallennetut alkuperäiset viestit säilyvät muuttumattomina, eikä asiakkaan tarvitse poistaa keskustelutietueita.                                                                                    |
| `error`             | Tällä kierroksella tapahtui virhe; `message` kuvaa virheen sisällön.                                                                                              |
| `done`              | Tämän kierroksen lopullinen keskustelutietue tallennettiin onnistuneesti; sisältää `usage`-tiedot (mukaan lukien `prompt_tokens` / `completion_tokens` / `total_tokens`) ja `terminal_reason`:n; tehtävän valmistuminen on silti pääteltävä päättymissyyn perusteella. |
Asiakkaille, jotka välittävät vain lopullisesta vastauksesta, kaikkien `text_delta`-tapahtumien `content`-kenttien yhdistäminen vastaa `answer`-kenttää `application/json`-tilassa.

## Multimodaalinen syöte

Jos käyttäjän syöte sisältää kuvia tai tiedostoja, välitä `message` (taulukko) `question`-kentän sijaan. Jokainen taulukkoelementti on sisältölohko:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Tuetut lohkotyypit:

- `text` — Tavallinen teksti, `text`-kenttä pakollinen.
- `image_url` — Kuva, `image_url.url` pakollinen.
- `file_url` — Tiedosto (PDF, CSV, TXT jne.), `file_url.url` pakollinen.

### Suhde v1:n `references`-kenttään

Yhteensopivuuden vuoksi vanhojen asiakkaiden kanssa v2 tunnistaa edelleen `references: ["https://...", ...]` -kentän:

- Jos URL-osoitteen pääte on `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, se muunnetaan automaattisesti `image_url`-lohkoksi;
- Muut tiedostopäätteet muunnetaan `file_url`-lohkoksi;
- Jos `question` annetaan myös samanaikaisesti, se lisätään alkuun `text`-lohkona.

Jos siis haluat vain siirtyä v1:stä muuttamatta pyyntörunkoa, vaihda poluksi `/aichat2/conversations`, jolloin alkuperäinen `references`-käyttö toimii edelleen normaalisti.

Jos tarvitset tarkempaa hallintaa (esimerkiksi useiden kuvien sijoittamista tekstin väliin tai jos järjestys on tärkeä), käytä suoraan `message`-taulukkoa.

## Työkalukutsut ja MCP

v2:n keskeinen parannus on, että malli voi itsenäisesti kutsua työkaluja monivaiheisten tehtävien suorittamiseksi, **ja tämä on oletusarvoisesti käytössä**, eikä asiakas tarvitse mitään lisämäärityksiä pyynnössä. Tyypillisiä tilanteita:

- Käyttäjä kysyy: ”Etsi minulle, mitä uusia näyttelyitä Shanghaissa on viime aikoina” → malli kutsuu sisäänrakennettua web-hakua → jäsentää tulokset vastaukseksi.
- Käyttäjä kysyy: ”Lue tämä PDF ja kirjoita siitä yhteenveto” → malli kutsuu `file_read`-työkalua → kirjoittaa yhteenvedon.
- Käyttäjä on valtuuttanut Google Driven / GitHubin / Notionin jne. [Connections](https://platform.acedata.cloud/connections)-kohdassa → malli voi kutsua vastaavia MCP-työkaluja niiden tietojen lukemiseen ja kirjoittamiseen.

NDJSON- / SSE-virrassa työkalukutsut esitetään kahdentyyppisinä tapahtumina, `tool_use` ja `tool_result`, esimerkiksi:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Jos et halua näyttää työkalukutsujen yksityiskohtia käyttöliittymässä, jätä huomiotta `tool_use` / `tool_result` / `card` / `citation` -tyyppiset tapahtumat; mallin lopullinen tuloste virtaa edelleen `text_delta`-tapahtumien kautta.

`max_turns` voi rajoittaa, kuinka monta kierrosta malli voi enintään kutsua työkaluja itse tässä pyynnössä; sallittu alue on 1–500, ja jos se jätetään pois, oletusarvo on 500. Sen asettaminen pieneksi (esimerkiksi `max_turns: 1`) voi pakottaa kertavastauksen eikä salli mitään työkalukutsuja.

## Asynkroninen suoritus ja valtuutus ilman valvontaa

Jos kutsusi tulee hälytys-WebHookista, CI/CD:stä, valvontajärjestelmästä tai muusta taustatehtävästä, voit asettaa `async: true`, jolloin rajapinta palauttaa tehtävätunnuksen välittömästi ja jatkaa suoritusta taustalla:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Palautusesimerkki:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Voit myöhemmin kysellä keskustelun tulosta käyttämällä `action: retrieve` + `id`; voit myös antaa `callback_url`-osoitteen, jolloin alusta POSTaa `{ status, answer, usage, error }`-tiedot takaisinsoitto-osoitteeseesi tehtävän valmistuttua. `callback_url`-osoitteen on käytettävä `http`- tai `https`-protokollaa, eikä siihen voi kirjoittaa suoraan `localhost`-osoitetta tai yksityistä IP-osoitetta.

Taustatehtävissä ei yleensä ole ketään klikkaamassa vahvistusta. Jos haluat, että tietyt Skillit tai MCP Serverit suorittavat lähetys-, julkaisu-, kirjoitus- tai muita toimintoja ilman valvontaa, välitä pyynnön rungossa nimenomaisesti esivaltuutuslista:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

`allowed_skills`-kentän arvot ovat yhdistettyjen Skillien slug-tunnuksia; `allowed_mcp_servers`-kentän arvot ovat yhdistettyjen MCP Serverien slug-tunnuksia. Skillit / MCP Serverit, joita ei ole lueteltu esivaltuutuksessa, voivat ilman valvontaa edelleen vain esikatsella, suorittaa dry-run-ajon tai kieltäytyä kirjoitustoimintojen suorittamisesta.

Jos tarvitset tarkempaa hallintaa, voit myös käyttää vastaavaa `unattended_policy`-objektia:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Esivaltuutus koostuu näistä kahdesta listasta itsestään: tyhjä lista tarkoittaa, ettei mitään ominaisuuksia valtuuteta, eikä erillistä kytkinkenttää tarvita.

Huomaa: esivaltuutus tarkoittaa vain, että ”tämä pyyntö sallii näiden ominaisuuksien ohittaa ihmisen vahvistuksen ilman valvontaa”. Kyseisen Skillin on silti tuettava `--unattended-confirm`-asetusta tai vastaavaa turvamekanismia; muuten se jatkaa dry-run-ajona eikä suorita kirjoitustoimintoa suoraan.

## Keskeytetyn keskustelun jatkaminen

Jotkin työkalut saavat mallin ”esittämään vastakysymyksen käyttäjälle”. Tällöin malli lähettää `ask_user_question`-tapahtuman, ja keskustelu jäädytetään `awaiting_user_input`-tilaan:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Renderöi tämä tapahtuma käyttöliittymässä kortiksi, josta käyttäjä voi valita vastauksen, ja lähetä sitten seuraava pyyntö samalla `id`-tunnuksella sekä täytä vastaus takaisin `tool_results`-kentän kautta:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

Pyynnön rungossa olevan `tool_use_id`:n **on pakko** vastata täsmälleen keskeytyksen aikaisen `tool_id`:n kanssa; poikkeamasta palautetaan 400. Kun pyynnössä on samanaikaisesti `tool_results`, `question` / `message` / `references` jätetään kaikki huomiotta.

Jos käyttäjä päättää luopua tästä kysymyksestä, välitä suoraan uusi `question` / `message`, jolloin alusta merkitsee keskeytetyn työkalukutsun automaattisesti tilaan ”käyttäjä ohitti”.

## Keskustelujen hallinta (CRUD)

v2 tarjoaa kevyen keskustelujen hallinnan samalla endpointilla `action`-kentän kautta, ilman erillistä API:a.

### `action: retrieve` —— yhden keskustelun hakeminen

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Palauttaa koko keskusteluasiakirjan (mukaan lukien `messages`-historia, `model`, `title`, `tools_used` jne.).

### `action: retrieve_batch` —— keskusteluyhteenvetojen luetteleminen

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Palauttaa `{ items: [...], total }`. **Yhteenveto ei sisällä `messages`-kenttää**, joten se soveltuu sivupalkkiluetteloihin; jos käyttäjä avaa tietyn keskustelun, hae sen täydelliset viestit erikseen käyttämällä `action: retrieve`.

Valinnaiset suodatusparametrit: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— otsikon muuttaminen tai historian uudelleenkirjoittaminen

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

Myös `messages` voidaan välittää, mutta palvelin suorittaa tiukan schema-validoinnin (sen on oltava tiivistetty `ToolUseContent`-muoto), ja virheellisestä muodosta palautetaan 400. Yleensä sitä suositellaan käytettäväksi vain `title`-kentän muuttamiseen.

### `action: delete` —— yhden keskustelun poistaminen

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Palauttaa `{ id, success: true }`. Poistamisen jälkeen tietoja ei voi palauttaa, joten varmista asia ennen kutsua.

## Sujuva siirtyminen v1:stä

Jos käytät jo [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations)-rajapintaa, siirtyminen v2:een ei käytännössä vaadi koodimuutoksia:

1. Muuta URL-osoite `https://api.acedata.cloud/aichat/conversations`-osoitteesta `https://api.acedata.cloud/aichat2/conversations`-osoitteeseen.
2. Jos välitit aiemmin v1-mallin nimen (kuten `gpt-3.5`, `gpt-4-browsing` jne.), v2:een vaihtaessasi on suositeltavaa päivittää nykyaikaiseen malliin (kuten `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` jne.).
3. NDJSON-virran kentät säilyvät taaksepäin yhteensopivina: jokaisessa `text_delta`-tapahtumassa on edelleen `delta_answer` ja `id`, joten asiakkaan, joka jäsentää `delta_answer`-kentän riveittäin, ei tarvitse muuttua.

Siirtymisen jälkeen voit ottaa käyttöön v2:n uusia ominaisuuksia tarpeen mukaan (monimuotoinen `message`, SSE, työkalukutsut, `action` CRUD) ja edetä omaan tahtiin.

## Virheenkäsittely

Virhevastaus on yhtenäisessä muodossa:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Yleiset virheet:

- `400 bad_request`: pakollinen kenttä puuttuu, `tool_use_id` ei täsmää, `messages`-schema on virheellinen jne.
- `401 invalid_token`: `authorization`-otsake on virheellinen.
- `404 not_found`: `action: retrieve / update / delete` -toiminnon yhteydessä `id`:tä vastaavaa keskustelua ei ole olemassa.
- `413 conversation_storage_limit`: keskustelu ylittää tallennusrajoituksen, eikä olemassa olevia tallennettuja tietueita korvattu.
- `429 too_many_requests`: nopeusrajoitus on lauennut.
- `503 context_compaction_failed`: kontekstin tiivistäminen epäonnistui, olemassa olevat tietueet säilytetään.
- `500 conversation_persist_failed`: tämän kierroksen lopullinen tallennus epäonnistui; vastaanotettu teksti ei tarkoita, että lopullinen tietue tallennettiin onnistuneesti, joten tee haku keskustelun ID:llä.
- `500 chat_error`: palvelu ei ole tilapäisesti käytettävissä tai tällä kierroksella ei muodostettu sisältöä (maksua ei veloiteta).

Virtautuvassa vastauksessa virhe lähetetään `{"type":"error","message":"..."}`-tapahtumana, minkä jälkeen virta päättyy. `[DONE]` tarkoittaa vain, että siirto on päättynyt; jos mukana on `error`, sitä ei voi pitää onnistuneena eikä onnistunutta `done`-tapahtumaa lähetetä.

## Johtopäätös

AI Chat v2 API säilyttää yhteensopivuuden v1:n kanssa ja samalla päivittää keskustelut ”yhden kierroksen / monen kierroksen kysymys-vastaus”-mallista ”agenttipohjaisiksi, havainnoitaviksi keskusteluiksi”: monimuotoinen syöte, työkalukutsut, keskeytettävissä / jatkettavissa, virtautetut rakenteiset tapahtumat ja sisäänrakennettu CRUD. Uusille integraatioille suositellaan v2:n käyttöä suoraan; olemassa olevat v1-integraatiot voidaan siirtää sujuvasti vaiheittain. Jos sinulla on kysyttävää, ota milloin tahansa yhteyttä tekniseen tukitiimiimme.
