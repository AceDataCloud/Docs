Artistic QR Tasks API:n päätoiminto on kysyä tehtävän suoritusstatus syöttämällä Artistic QR Generation API:n tuottama tehtävä-ID.

Tässä asiakirjassa käsitellään yksityiskohtaisesti Artistic QR Tasks API:n liittämistä, jotta voit helposti integroida ja hyödyntää tämän API:n voimakkaita ominaisuuksia. Artistic QR Tasks API:n avulla voit helposti kysyä Artistic QR Generation API:n tehtävän suoritusstatus.

## Hakuprosessi

Käyttääksesi Artistic QR Tasks API:a, sinun on ensin mentävä hakusivulle [Artistic QR Generation API](https://platform.acedata.cloud/documents/ee085d2a-a0b9-4f0e-8b4d-8da407345138) ja haettava vastaavaa palvelua, sitten kopioit Artistic QR Generation API:n tehtävä-ID:n, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/2wicjy.png" width="500" class="m-auto"></p>

Lopuksi siirry Artistic QR Tasks API -sivulle [Artistic QR Tasks API](https://platform.acedata.cloud/documents/21de9d76-6e39-4ac3-b8b9-20e7194c02b4) ja hae vastaavaa palvelua, siirryttyäsi sivulle, napsauta "Acquire" -painiketta, kuten kuvassa näkyy:

![Hakusivu](https://cdn.acedata.cloud/rci31i.png)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti [kirjautumissivulle](https://platform.acedata.cloud), jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Kirjautumisen ja rekisteröitymisen jälkeen palaat automaattisesti nykyiselle sivulle.

Ensimmäisellä hakemiskerralla saat ilmaisia krediittejä, joita voit käyttää API:n ilmaiseksi.

## Pyyntöesimerkki

Artistic QR Tasks API:a voidaan käyttää kysymään Artistic QR Generation API:n yhden API:n tuloksia. Lisätietoja siitä, miten käyttää Artistic QR Generation API:a, katso asiakirjasta [Artistic QR Generation API](https://platform.acedata.cloud/documents/ee085d2a-a0b9-4f0e-8b4d-8da407345138).

Otetaan esimerkkinä yksi Artistic QR Generation API:n palauttama tehtävä-ID ja näytetään, miten tätä API:a käytetään. Oletetaan, että meillä on tehtävä-ID: e2c65b20-a970-431e-99c1-76721e799df8, seuraavaksi näytetään, miten syötetään tämä tehtävä-ID.

### Pyyntöotsikon ja -kehon asettaminen

**Request Headers** sisältää:

- `accept`: määrittää, että vastaanotetaan JSON-muotoista vastausta, tässä täytetään `application/json`.
- `authorization`: API:n avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

**Request Body** sisältää:

- `id`: ladattu tehtävä-ID.
- `action`: tehtävän toimintatapa.

Aseta kuten alla olevassa kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/use825.png" width="500" class="m-auto"></p>

### Koodiesimerkki

Voit huomata, että sivun oikealla puolella on automaattisesti luotu koodia eri kielillä, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/jejwy6.png" width="500" class="m-auto"></p>

Osittainen koodiesimerkki on seuraava:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/qrart/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "e2c65b20-a970-431e-99c1-76721e799df8",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/qrart/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "e2c65b20-a970-431e-99c1-76721e799df8",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Virheiden käsittely

Kun kutsut API:ta, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`：Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`：Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`：Valtuuttamaton, virheellinen tai puuttuva valtuutustoken.
- `429 too_many_requests`：Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`：Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.
