Fish Tasks API:n päätoiminto on kysellä Fish Audios Generation API:n luoman tehtävätunnuksen avulla kyseisen tehtävän suoritustilannetta.

Tässä dokumentissa esitellään yksityiskohtaisesti Fish Tasks API:n integrointiohjeet, jotta voit helposti integroida ja hyödyntää täysin tämän API:n tehokkaita toimintoja. Fish Tasks API:n avulla voit helposti toteuttaa Fish Audios Generation API:n tehtävien suoritustilanteen kyselyn.

## Hakuprosessi

Käyttääksesi Fish Audios Generation API:a hanki ensin [Ace Data Cloud -konsolista](https://platform.acedata.cloud/console/applications) API-tokenisi ja säilytä se varalla.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua pyydetään rekisteröitymään ja kirjautumaan sisään, minkä jälkeen palaat automaattisesti nykyiselle sivulle.

**Yhdellä API-tokenilla voi kutsua kaikkia alustan palveluita, eikä jokaista palvelua tarvitse hakea erikseen.** Ensimmäisestä hakemuksesta myönnetään ilmainen käyttökiintiö, jolla voit kokeilla palvelua maksutta; kun käyttökiintiö ei riitä, voit ladata yleissaldoa [konsolissa](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [Fish Audios Generation API →](https://platform.acedata.cloud/documents/fish-tts)

## Pyyntöesimerkki

Fish Tasks API:a voidaan käyttää Fish Audios Generation API:n tulosten kyselyyn. Katso Fish Audios Generation API:n käyttöä koskevat ohjeet dokumentaatiosta [Fish Videos Generation API ](https://platform.acedata.cloud/documents/fish-tts-integration).

Käytämme esimerkkinä yhtä Fish Audios Generation API -palvelun palauttamaa tehtävätunnusta ja näytämme, kuinka tätä API:a käytetään. Oletetaan, että meillä on tehtävätunnus: 2725a2d3-f87e-4905-9c53-9988d5a7b2f5, seuraavaksi näytämme, kuinka välittämällä yksi tehtävätunnus.

### Pyyntöotsikoiden ja pyyntörungon määrittäminen

**Request Headers** sisältää:

- `accept`: määrittää JSON-muotoisen vastaustuloksen vastaanottamisen, tähän täytetään `application/json`.
- `authorization`: API:n kutsun avain, jota voi hakemisen jälkeen suoraan valita avattavasta valikosta.

**Request Body** sisältää:

- `id`: ladatun tehtävän ID.
- `action`: tehtävän toimintatapa.

Asetukset ovat seuraavan kuvan mukaiset:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/fish/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2725a2d3-f87e-4905-9c53-9988d5a7b2f5",
  "action": "retrieve"
}'
```


Palautetussa tuloksessa on yhteensä useita kenttiä, `request`-kenttä on tehtävää käynnistettäessä käytetty request body, ja samalla `response`-kenttä on tehtävän valmistumisen jälkeen palautettu response body. Kenttien esittely on seuraava.

- `id`, tämän tehtävän luonut ID, jota käytetään tämän luontitehtävän yksilöivään tunnistamiseen.
- `request`, tehtävän kyselyn pyyntötiedot.
- `response`, tehtävän kyselyn palautustiedot; lopullisen onnistumisen yhteydessä siinä oleva `cost.amount` on kyseisestä synteesistä todellisuudessa veloitetut Credits.
- `created_at`, tehtävän luontiaika, Unix-aikaleima (sekunteina, liukuluku).
- `started_at`, tehtävän suorituksen alkamisaika, Unix-aikaleima (sekunteina, liukuluku).
- `finished_at`, tehtävän valmistumisaika, Unix-aikaleima (sekunteina, liukuluku). Tätä kenttää ei palauteta, kun tehtävä ei ole valmis.
- `elapsed`, tehtävän suorituksen kesto, yksikkönä sekunti (liukuluku, säilyttää 3 desimaalia). Tätä kenttää ei palauteta, kun tehtävä ei ole valmis.

## Virheenkäsittely

Kun API:a kutsutaan ja kohdataan virhe, API palauttaa vastaavan virhekoodin ja viestin. Esimerkiksi:

- `400 token_mismatched`: Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Ei valtuutettu, virheellinen tai puuttuva valtuutustunnus.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, palvelimella tapahtui jokin virhe.
