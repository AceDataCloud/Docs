Tässä artikkelissa esitellään kasvokuvien staattinen elävyyden tarkistus (korkean tarkkuuden versio) API -liitäntäsuunnitelma, jota voidaan käyttää käyttäjän lataamien staattisten kuvien suojaamiseksi kopioinnilta elävyyden tarkistuksen avulla, jotta voidaan arvioida, onko kuva kopioitu.

## Hakuprosessi

API:n käyttämiseksi sinun on ensin mentävä [kasvokuvien staattinen elävyyden tarkistus (korkean tarkkuuden versio) API](https://platform.acedata.cloud/documents/df41d411-6ba8-41d3-a56f-3f6ec9acaa36) -sivulle ja haettava vastaavaa palvelua. Sivulle päästyäsi napsauta "Acquire" -painiketta, kuten kuvassa on esitetty:

![](https://cdn.acedata.cloud/q6ytrc.png)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Kirjautumisen ja rekisteröitymisen jälkeen palaat automaattisesti nykyiselle sivulle.

Ensimmäisellä hakukerralla saat ilmaisia käyttöoikeuksia, joiden avulla voit käyttää tätä API:a ilmaiseksi.

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, eli syöttää kuvalinkki, jolloin saat käsitellyn tuloskuvan. Ensimmäiseksi sinun on yksinkertaisesti välitettävä `image_url` -kenttä, kasvokuva on esitetty alla olevassa kuvassa:

<p><img src="https://cdn.acedata.cloud/lrbtcn.jpg" width="500" className="m-auto" /></p>

Seuraavaksi voimme täyttää vastaavat tiedot käyttöliittymässä, kuten kuvassa on esitetty:

<p><img src="https://cdn.acedata.cloud/c975uf.png" width="500" className="m-auto" /></p>

Voit nähdä, että olemme asettaneet Request Headers -asetukset, mukaan lukien:

- `accept`: minkälaista vastausmuotoa haluat vastaanottaa, tässä on täytetty `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumiseen käytettävä avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

Lisäksi olemme asettaneet Request Body -asetukset, mukaan lukien:

- `image_url`: käsiteltävän kasvokuvan linkki.
- `face_model_version`: kasvontunnistuspalvelussa käytettävän algoritmimallin versio. Tällä hetkellä syötteet tukevat "3.0".

Valinnan jälkeen voit huomata, että oikealle puolelle on myös luotu vastaava koodi, kuten kuvassa on esitetty:

<p><img src="https://cdn.acedata.cloud/nkcvet.png" width="500" className="m-auto" /></p>

Napsauta "Try" -painiketta, jotta voit testata, kuten yllä olevassa kuvassa on esitetty, ja saamme seuraavat tulokset:

```json
{
  "score": 0,
  "face_model_version": "3.0"
}
```

Voit nähdä, että olemme saaneet kasvokuvien staattisen elävyyden tarkistuksen tulokset, mukaan lukien elävyyspisteet.

Kenttäkuvaus on seuraava:

- `score`: elävyyspisteet, arvot vaihtelevat [0,100], elävyyspisteiden mukaan arvioidaan, onko kuva kopioitu. Tällä hetkellä kynnysarvot voidaan jakaa [5,10,40,70,90], suositeltu kynnysarvo on 40.
- `face_model_version`: kasvontunnistuksessa käytettävän algoritmimallin versio.

Jos haluat luoda vastaavan liitännäiskoodin, voit kopioida sen suoraan, esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/face/detect-live' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": "https://cdn.acedata.cloud/lrbtcn.jpg"
}'
```

Pythonin liitännäiskoodi on seuraava:

```python
import requests

url = "https://api.acedata.cloud/face/detect-live"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "image_url": "https://cdn.acedata.cloud/lrbtcn.jpg"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Virheiden käsittely

API:a kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Valtuuttamaton, virheellinen tai puuttuva valtuutusavain.
- `429 too_many_requests`: Liikaa pyyntöjä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
