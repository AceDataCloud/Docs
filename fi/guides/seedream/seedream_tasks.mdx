SeeDream Tasks API:n päätoiminto on kysyä tehtävän suoritustilaa syöttämällä SeeDream Images Generation API:n tuottama tehtävä-ID.

Tässä asiakirjassa käsitellään SeeDream Tasks API:n liittämistä, jotta voit helposti integroida ja hyödyntää tämän API:n voimakkaita ominaisuuksia. SeeDream Tasks API:n avulla voit helposti tarkistaa SeeDream Images Generation API:n tehtävän suoritustilan.

## Hakuprosessi

Käyttääksesi SeeDream Images Generation API:a, sinun on ensin hankittava API Token [Ace Data Cloud -hallintapaneelista](https://platform.acedata.cloud/console/applications) ja pidettävä se varalla.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Valmiina palaat automaattisesti nykyiselle sivulle.

**Yksi API Token riittää kutsumaan kaikkia palveluja, eikä jokaiselle palvelulle tarvitse hakea erikseen.** Ensimmäisestä hakemuksesta saat ilmaisen määrän, jonka avulla voit kokeilla; jos määrä loppuu, voit ladata yleistä saldoa [hallintapaneelista](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen asiakirja: [SeeDream Images Generation API →](https://platform.acedata.cloud/documents/seedream-images)

## Pyyntöesimerkki

SeeDream Tasks API:a voidaan käyttää SeeDream Images Generation API:n tulosten kysymiseen. Tietoa siitä, miten käyttää SeeDream Images Generation API:a, katso asiakirjasta [SeeDream Images Generation API](https://platform.acedata.cloud/documents/seedream-images-integration).

Otetaan esimerkki SeeDream Images Generation API:n palauttamasta tehtävä-ID:stä, ja näytetään, miten tätä API:a käytetään. Oletetaan, että meillä on tehtävä-ID: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, seuraavaksi näytetään, miten syötetään tämä tehtävä-ID.

### Pyyntöotsikon ja -kehon asettaminen

**Request Headers** sisältää:

- `accept`: määrittää, että vastaanotetaan JSON-muotoisia vastauksia, tässä täytetään `application/json`.
- `authorization`: API:n kutsumiseen käytettävä avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

**Request Body** sisältää:

- `id`: ladattu tehtävä-ID.
- `action`: tehtävän toimintatapa.

Osittainen koodiesimerkki on seuraava:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/seedream/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "a6e0d456-189b-4c78-9232-2fe72166ab39",
  "action": "retrieve"
}'
```

### Vastausesimerkki

Kun pyyntö onnistuu, API palauttaa tämän tehtävän yksityiskohtaiset tiedot. Esimerkiksi:

```json
{
  "success": true,
  "task_id": "84d1544a-9043-4dde-a98b-e889dacd75f6",
  "trace_id": "176acf03-7ca7-4fc6-85db-e3724d4f59eb",
  "data": [
    {
      "prompt": "valkoinen siamilainen kissa",
      "size": "2048x2048",
      "image_url": "https://platform.cdn.acedata.cloud/seedream/6e5f9085-cc4a-4801-b77b-31550129ff19.jpg"
    }
  ]
}
```

Palautetussa tuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `success`, tämänhetkinen videon luontitehtävän tila.
- `task_id`, tämänhetkinen videon luontitehtävän ID.
- `trace_id`, tämänhetkinen videon luontiseurannan ID.
- `data`, tämänhetkisen kuvan luontitehtävän tuloslista.
  - `image_url`, tämänhetkisen kuvan luontitehtävän linkki.
  - `prompt`, vihje.
  - `size`: luodun kuvan pikselit

**Request Body** sisältää:

- `ids`: ladattujen tehtävä-ID:iden taulukko.

返回结果一共有多个字段，其中items是包含了批量任务的具体详情信息，每个任务的具体信息与上文的字段一样，字段信息如下。

- `items`，批量任务的所有具体详情信息。它是一个数组，每个数组的元素 ja上文查询单个任务的返回结果格式 on sama.
- `count`，此处批量查询任务的个数。

批量结果里每个任务对象还带有以下计时字段。

- `created_at`，任务创建时间，Unix 时间戳（秒，浮点）。
- `started_at`，任务开始执行时间，Unix 时间戳（秒，浮点）。
- `finished_at`，任务完成时间，Unix 时间戳（秒，浮点）。任务未完成时不返回该字段。
- `elapsed`，任务执行耗时，单位为秒（浮点，保留 3 位小数）。任务未完成时不返回该字段。

## Virheiden käsittely

在调用 API 时，如果遇到错误，API 会返回相应的错误代码和信息。例如：

- `400 token_mismatched`：Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`：Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`：Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`：Too many requests, you have exceeded the rate limit.
- `500 api_error`：Internal server error, something went wrong on the server.
