Tässä artikkelissa esitellään Recaptcha2 protokolla tunnistus API -liitäntäohje, joka mahdollistaa käyttäjille, että heidän ei tarvitse tunnistaa ja klikata Recaptcha2 vahvistuskuvia, vaan he voivat yksinkertaisesti lähettää Website Keyn, jolloin taustalla tapahtuu automaattinen purku ja vahvistus.

## Hakuprosessi

Käyttääksesi Recaptcha2 protokolla tunnistus API:ta, sinun on ensin mentävä [Ace Data Cloud -ohjauspaneeliin](https://platform.acedata.cloud/console/applications) saadaksesi API Tokenisi, jota voit säilyttää varalla.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään, ja sen jälkeen sinut ohjataan takaisin nykyiselle sivulle.

**Yksi API Token riittää kaikkien palveluiden kutsumiseen, eikä jokaiselle palvelulle tarvitse hakea erikseen.** Ensimmäisellä hakemuksella saat ilmaisia krediittejä, joita voit kokeilla ilmaiseksi; jos krediitit loppuvat, voit ladata yleistä saldoa [ohjauspaneelista](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [Recaptcha2 protokolla tunnistus API →](https://platform.acedata.cloud/documents/captcha-token-recaptcha2)

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, eli syöttää käsiteltävän vahvistuskoodin verkkosivuston URL-osoite, jolloin saat käsitellyn tuloksen. Ensinnäkin sinun on yksinkertaisesti välitettävä `website_url`-kenttä. Esimerkkisivustomme on: `https://www.google.com/recaptcha/api2/demo`, meidän on saatava `website_key` `website_url`-sivulta. Avaa tämä verkkosivusto, paina F12 siirtyäksesi konsoliin, ja etsi Element-sivulta globaalisti `recaptcha-demo`, jolloin saamme seuraavat tulokset:

<p><img src="https://cdn.acedata.cloud/hvx41c.png" width="500" className="m-auto" /></p>

Missä `data-sitekey` vastaa yhtä merkkijonoa, joka on `website_key`-arvo, alla on tarkat parametritulokset:

<p><img src="https://cdn.acedata.cloud/8oowyw.png" width="500" className="m-auto" /></p>

Voimme nähdä, että olemme asettaneet Request Headers, mukaan lukien:

- `accept`: minkälaista vastausmuotoa halutaan vastaanottaa, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n avain, jonka voit valita suoraan alasvetovalikosta hakemuksen jälkeen.

Lisäksi on asetettu Request Body, mukaan lukien:

- `website_url`: käsiteltävän vahvistuskoodin verkkosivuston URL-osoite.
- `website_key`: verkkosivuston avain tunniste Recaptcha2:ssa.
- `proxy`: valinnainen, tuo oma proxy (Bring Your Own Proxy). Asetuksen jälkeen palvelu purkaa vahvistuskoodin antamasi proxy IP:n kautta, mikä auttaa hallitsemaan lähtö IP:n laatua (esimerkiksi välttämään, että kohdesivusto estää julkisen proxy IP:n ja palauttaa `410 Gone`). Muoto on `scheme://[user:pass@]host:port`, `scheme` tukee `http`/`https`/`socks4`/`socks5`, esimerkiksi `http://user:pass@1.2.3.4:8080`. Jos et täytä, käytetään alustan oletusproxia.

- `started_at`, `finished_at`: tämän pyynnön käsittelyn aloitus- ja lopetusaika, Unix aikaleima (sekunteina, liukuluku).

Voimme nähdä, että olemme saaneet käsitellyn Recaptcha2 vahvistustuloksen, jota voimme käyttää POST- tai simuloidussa lähetyksessä kohdesivustolle, kertakäyttöinen, voimassa 120 sekuntia, suositellaan käytettäväksi 60 sekunnin sisällä. Seuraavaksi tarjoamme Python-version, joka lähettää käsitellyn tokenin kohdesivustolle Recaptcha2 vahvistuksen läpäisemiseksi.

Ensinnäkin meidän on selvitettävä, miten sivusto lähettää POST-pyynnön, jotta voimme siirtää luodun tokenin sisään. Meidän on ensin avattava F12-konsoli, sitten suoritettava se manuaalisesti, ja lopuksi voimme nähdä, että sivusto on lähettänyt POST-pyynnön. Meidän tarvitsee vain tarkastella tämän POST-pyynnön rakennetta, tarkka prosessi on seuraava:

- Suorita ensin vahvistus manuaalisesti, tarkka kuva on alla:

<p><img src="https://cdn.acedata.cloud/gwiflr.png" width="500" className="m-auto" /></p>

- Napsauta sitten lähettää ja tarkkaile konsolin verkon muutoksia, tarkka kuva on alla:
<p><img src="https://cdn.acedata.cloud/6hm5kj.png" width="500" className="m-auto" /></p>

- Analysoi tämän lähetyksen POST-pyynnön rakenne, lopuksi voit oikealla hiiren painikkeella kopioida tämän pyynnön CURL-koodin, tarkemmin sanottuna seuraavassa kuvassa:

<p><img src="https://cdn.acedata.cloud/m7y35w.png" width="500" className="m-auto" /></p>

Yllä olevasta kuvasta voidaan päätellä, että tämän POST-pyynnön URL-osoite on: `https://www.google.com/recaptcha/api2/demo`, meidän tarvitsee vain lähettää parametri `g-recaptcha-response`, ja sitten meidän tarvitsee vain siirtää käsitelty token alla olevaan dataan, CURL-koodi tokenin vahvistamiseksi on seuraava:

```shell
curl 'https://www.google.com/recaptcha/api2/demo' \
  --data-raw 'g-recaptcha-response={token}’
```

Tokenin vahvistamiseen liittyvä Python-koodi on seuraava:

```python
import requests

token = '{token}'

data = {
    'g-recaptcha-response': token,
}

response = requests.post('https://www.google.com/recaptcha/api2/demo',data=data)

if response.status_code:
    print(response.text)

```

Sitten ajamme koodin ja huomaamme, että konsoli näyttää tältä:

<p><img src="https://cdn.acedata.cloud/ku22tk.png" width="500" className="m-auto" /></p>

Lopuksi olemme läpäisseet Recaptcha2-varmenteen vahvistuksen.

Lisäksi, jos haluat luoda vastaavan integrointikoodin, voit suoraan kopioida sen, esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo"
}'
```

Pythonin integrointikoodi on seuraava:

```python
import requests

url = "https://api.acedata.cloud/captcha/token/recaptcha2"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
    "website_url": "https://www.google.com/recaptcha/api2/demo"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynkroninen tila (async)

Oletusarvoisesti API on synkroninen ja estää: yksi pyyntö odottaa aina, kunnes tokenin käsittely on valmis. Jos teet useita ratkaisijoiden kiertoja (multi-solver rotation) ja haluat "saada task_id:n heti tehtävän lähettämisen jälkeen, mennä aikatauluttamaan muita ratkaisijoita ja palata myöhemmin lukemaan tuloksia", voit siirtää `async: true` pyynnön rungossa.

Kun siirrät `async: true`, rajapinta palauttaa heti `task_id:n`, eikä estä odottamista:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

Jos haluat tarkistaa edistymistä aktiivisesti, voit käyttää tätä `task_id:tä` kysyäksesi `POST /captcha/tasks` (suositellaan joka 3-5 sekunti). Tämä rajapinta ei laukaise tai edistä tehtävän käsittelyä; vaikka et kysyisi, katkaise verkkoyhteys tai sulje asiakasohjelma, palvelin jatkaa edelleen käsittelyä:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Käsittelyssä palautuu `status: processing`:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

Käsittelyn valmistuttua palautuu `status: ready` ja token:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "token": "03AFcWeA5kjJyDQ9S1a9UYimR6nuxnpEnAs5x2Pixao0dXZhMB......"
}
```

Laskutustiedot: asynkronisessa tilassa tehtävän luominen ja "käsittelyssä" tilan lukeminen eivät aiheuta kustannuksia; **asiakkaan ensimmäinen onnistuneen tuloksen lukeminen laskutetaan kerran** (saman käytännön ja synkronisen tilan hinnan mukaisesti). Palvelin edistää tehtävää itsenäisesti, mutta ei veloita etukäteen, vaikka taustalla olisi valmis. Tehtävä, jota ei ole onnistuttu 120 sekunnin sisällä, päättyy HTTP 504 `timeout` -tilaan, eikä siitä veloiteta. `/captcha/tasks` ei vastaa tehtävän edistämisestä.

## Virheiden käsittely

API:ta kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Valtuuttamaton, virheellinen tai puuttuva valtuutustoken.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
