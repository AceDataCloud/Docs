Tässä artikkelissa esitellään Recaptcha2 kuvantunnistus API -liitäntäohje, joka voi tunnistaa käyttäjän syöttämän sisällön ja Recaptcha2 vahvistuskuvan, ja lopuksi palauttaa tarvittavien klikkausten koordinaatit, jotta vahvistus voidaan suorittaa.

## Hakuprosessi

Käyttääksesi Recaptcha2 kuvantunnistus API:a, sinun on ensin hankittava API Token [Ace Data Cloud -hallintapaneelista](https://platform.acedata.cloud/console/applications) ja pidettävä se varalla.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään, ja sen jälkeen sinut ohjataan takaisin nykyiselle sivulle.

**Yksi API Token riittää kaikkien palveluiden kutsumiseen, eikä jokaiselle palvelulle tarvitse hakea erikseen.** Ensimmäisellä hakemuksella saat ilmaisen käyttöoikeuden, jota voit kokeilla ilmaiseksi; jos käyttöoikeus loppuu, voit ladata yleistä saldoa [hallintapaneelista](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [Recaptcha2 kuvantunnistus API →](https://platform.acedata.cloud/documents/captcha-recognition-recaptcha2)

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, meidän on otettava kuvakaappaus Recaptcha2 vahvistuskuvasta verkkosivustolta, tässä esimerkkisivuston URL: `https://www.google.com/recaptcha/api2/demo`, tarkka sivu on alla olevassa kuvassa:

<p><img src="https://cdn.acedata.cloud/3mgkjk.png" width="500" className="m-auto" /></p>

Meidän on klikattava vahvistuskuvan valintaruutua, jotta vahvistuskuva ilmestyy. Yllä olevassa kuvassa keltainen nuoli osoittaa tekstiä, joka on alla olevan `question` arvon sisältö. Ensinnäkin on tarpeen siirtää yksinkertainen `image` kenttä, joka on itse Recaptcha2 vahvistuskuva, tämä kuva on yllä olevassa kuvassa punaisella nuolella osoitettu kuva, ja se on pakko skaalata standardikokoon (100x100, 300x300, 450x450), jotta palvelu voi tunnistaa kuvatyypin. Kuvan pakkaus on tehtävä itse, tässä artikkelissa suositellaan [pakkaussivustoa](https://www.photopea.com/), jossa voit muuttaa kuvan kokoa ja painoa, pakatun tuloksen kuva on alla:

![](https://cdn.acedata.cloud/l7aotl.png)

Voimme nähdä, että olemme asettaneet Request Headers, mukaan lukien:

- `accept`: haluttu vastausmuoto, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n avain, jonka voit valita suoraan alasvetovalikosta hakemuksen jälkeen.

Lisäksi asetimme Request Body:n, mukaan lukien:

- `image`: Base64-koodattu vahvistuskuva.
- `question`: kysymys ID, tarkista taulukosta, alkaa /m/ -merkillä.

Valinnan jälkeen voimme huomata, että oikealla puolella on myös luotu vastaava koodi, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/bsp8g9.png" width="500" className="m-auto" /></p>

Napsauta "Try" -painiketta testataksesi, kuten yllä olevassa kuvassa näkyy, saimme seuraavanlaisen tuloksen:

```json
{
  "solution": {
    "size": 300,
    "label": "/m/01pns0",
    "confidences": [
      0,
      0.0007,
      1,
      0.0003,
      0.0046,
      1,
      0,
      1,
      0
    ],
    "objects": [
      2,
      5,
      7
    ],
    "type": "multi"
  }
}
```

Palautetussa tuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `solution`, tämän Recaptcha2 vahvistuskuvan tehtävän käsittelyn jälkeen saatu vahvistustulos.
    - `size`, Recaptcha2 vahvistuskuvan koko.
    - `label`, Recaptcha2 vahvistuskuvassa tunnistettu sisältö.
    - `confidences`, Recaptcha2 vahvistuskuvan tunnistusalueen luottamus, alueet alkavat 0:sta.
    - `objects`, Recaptcha2 vahvistuskuvassa tunnistettujen sisältöjen alueet, alueet alkavat 0:sta.
    - `type`, tämän Recaptcha2 vahvistuskuvan tehtävän tyyppi, useita alueita tarkoittaa `multi`.
- `started_at`, `finished_at`: tämän pyynnön käsittelyn aloitus- ja tulostusaika, Unix aikaleima (sekunnit, liukuluku).
- `elapsed`: tämän käsittelyn kokonaisaika (sekunnit).

Voimme nähdä, että saimme käsitellyn Recaptcha2 vahvistuskuvan vahvistustuloksen, ja jaoimme vahvistuskuvan alueisiin, kuten alla olevassa kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/2d6qhx.png" width="500" className="m-auto" /></p>

Voimme nähdä, että alueet alkavat 0:sta, ja tuloksista `objects` saimme 2,5,7, meidän tarvitsee vain simuloida klikkaus näihin kolmeen alueeseen, jotta vahvistus voidaan hyväksyä.

Lisäksi, jos haluat luoda vastaavan liitäntäkoodin, voit suoraan kopioida sen, esimerkiksi CURL-koodi on seuraava:
```shell
curl -X POST 'https://api.acedata.cloud/captcha/recognition/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "question": "/m/01pns0",
  "image": "iVBORw0KGgoAAAANSUhEUgAAASoAAAEsCAIAAAD7AWllAAAAAX..."
}'
```

Pythonin liitännäiskoodi on seuraava:

```python
import requests

url = "https://api.acedata.cloud/captcha/recognition/recaptcha2"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "question": "/m/01pns0",
    "image": "iVBORw0KGgoAAAANSUhEUgAAASoAAAEsCAIAAAD7AWllAAAAAX..."
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynkroninen tila (async)

Oletusarvoisesti API on synkroninen ja estää: yksi pyyntö odottaa aina, kunnes tunnistustulos on käsitelty ennen kuin se palauttaa. Jos teet moninkertaista ratkaisijakierrosta (multi-solver rotation) ja haluat "saada task_id:n heti tehtävän lähettämisen jälkeen, jotta voit aikatauluttaa muita ratkaisijoita ja palata myöhemmin lukemaan tuloksia", voit lisätä pyyntöön `async: true`.

Kun lisäät `async: true`, rajapinta palauttaa heti `task_id:n`, eikä estä odottamista:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/recognition/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "question": "/m/01pns0",
  "image": "iVBORw0KGgoAAAANSUhEUgAAASoAAAEsCAIAAAD7AWllAAAAAX...",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

Jos haluat tarkistaa edistymistä aktiivisesti, voit käyttää tätä `task_id:tä` kysyäksesi `POST /captcha/tasks` (suositellaan joka 3-5 sekunti). Tämä rajapinta ei käynnistä tai edistä tehtävän käsittelyä; vaikka et kysyisi, katkaise verkkoyhteys tai sulje asiakasohjelma, palvelin jatkaa käsittelyä:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Käsittelyssä palautuu `status: processing`:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

Käsittelyn valmistuttua palautuu `status: ready` ja tunnistustulos `solution` (kenttästruktuuri on täysin sama kuin synkronisessa tilassa):

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "solution": {
    "size": 300,
    "label": "/m/01pns0",
    "objects": [2, 5, 7],
    "type": "multi"
  }
}
```

Laskutustiedot: asynkronisessa tilassa tehtävän luominen ja "käsittelyssä" tilan lukeminen eivät aiheuta kustannuksia; **asiakasohjelma veloitetaan kerran, kun se lukee onnistuneen tuloksen ensimmäisen kerran** (sama käytäntö ja hinta kuin synkronisessa tilassa). Palvelin edistää tehtävää itsenäisesti, mutta ei veloita etukäteen, vaikka taustalla olisi valmis. Tehtävä, jota ei ole onnistuttu 120 sekunnissa, päättyy HTTP 504 `timeout` -tilaan, eikä siitä veloiteta. `/captcha/tasks` ei vastaa tehtävän edistämisestä.

## Virheiden käsittely

API:ta kutsuttaessa, jos kohtaat virheen, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Valtuuttamaton, virheellinen tai puuttuva valtuutustunnus.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
