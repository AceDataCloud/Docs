Tässä artikkelissa esitellään Recaptcha3 protokollan tunnistus API -liitäntäohje, joka mahdollistaa käyttäjille, että heidän ei tarvitse tunnistaa ja klikata Recaptcha3 vahvistuskuvia, vaan he voivat yksinkertaisesti lähettää Website Keyn, jolloin taustalla tapahtuu automaattinen purku ja vahvistus.

## Hakuprosessi

API:n käyttämiseksi on ensin mentävä [Recaptcha3 protokollan tunnistus API](https://platform.acedata.cloud/documents/1083df69-f2f3-4c13-901e-e5336b0dbe3d) -sivulle ja haettava vastaavaa palvelua. Sivulle päästyäsi, napsauta "Acquire" -painiketta, kuten kuvassa on esitetty:

![](https://cdn.acedata.cloud/q6ytrc.png)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Kirjautumisen ja rekisteröitymisen jälkeen palaat automaattisesti nykyiselle sivulle.

Ensimmäisellä hakemiskerralla saat ilmaisia krediittejä, joita voit käyttää API:ta ilmaiseksi.

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa. Verrattuna Recaptcha2:een, meidän on annettava ylimääräinen parametri `page_action`, jonka saamiseksi on mentävä koodin pariin. Tällä kertaa esitettävä verkkosivun URL-osoite on: `https://recaptcha-demo.appspot.com/recaptcha-v3-request-scores.php`, alla on esitetty yksi tapa sen hankkimiseksi:

### Nopea tapa:

Avaa f12 ja etsi Element-sivulta `.execute(`, punaisessa laatikossa voimme nähdä `action`-parametrin, ja execute-kutsun jälkeen on myös pitkä merkkijono, joka on myös myöhemmin tarvittava sisältö, tarkemmin sanottuna kuten alla olevassa kuvassa näkyy.

<p><img src="https://cdn.acedata.cloud/imwlto.png" width="500" class="m-auto"></p>

Lisäksi on syötettävä verkkosivun URL-osoite, jolle halutaan käsitellä vahvistuskuva, ensin on yksinkertaisesti välitettävä `website_url`-kenttä, ja lopuksi on syötettävä `website_key`-parametri, joka voidaan saada edellä mainitusta, myös execute-kutsun jälkeen olevasta merkkijonosta. Voimme nyt täyttää vastaavat tiedot käyttöliittymässä, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/1hw2uo.png" width="500" class="m-auto"></p>

Voimme nähdä, että olemme asettaneet Request Headers, mukaan lukien:

- `accept`: minkälaista vastausmuotoa halutaan vastaanottaa, tässä on täytetty `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumiseen käytettävä avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

Lisäksi on asetettu Request Body, mukaan lukien:

- `page_action`: on saatava vahvistuskuvan verkkosivun koodista.
- `website_url`: on käsiteltävän vahvistuskuvan verkkosivun URL-osoite.
- `website_key`: Recaptcha3:n verkkosivun avaimen tunniste.

Valinnan jälkeen voimme huomata, että oikealle puolelle on myös luotu vastaava koodi, kuten kuvassa näkyy:

- `token`, tämän Recaptcha3 vahvistustehtävän käsittelyn tulos.

Voimme nähdä, että olemme saaneet käsiteltyä Recaptcha3 vahvistuksen tuloksen, jota voimme käyttää POST- tai GET-pyyntöjen simuloimiseen kohdesivustolle, kertakäyttöinen, voimassa 120 sekuntia, suositellaan käytettäväksi 60 sekunnin sisällä. Seuraavassa esitellään lyhyesti yksi tapa lähettää luotu token kohdesivustolle:

Kutsu tokenin vahvistamiseen liittyvää Python-koodia:

```python
import requests

url = "https://recaptcha-demo.appspot.c/recaptcha-v3-verify.php?action=examples/v3scores&token='{token}'"

r = requests.get(url)
if r.status_code == 200:
    return r.text
```

Näin saamme tuloksen:

```json
{
  "success": true,
  "hostname": "recaptcha-demo.appspot.com",
  "challenge_ts": "2024-09-14T08:52:26Z",
  "apk_package_name": null,
  "score": 0.9,
  "action": "examples/v3scores",
  "error-codes": []
}
```

Voimme nähdä, että `success` osoittaa tässä vahvistuksen käsittelyn tuloksen, joten olemme onnistuneesti läpäisseet Recaptcha3 vahvistuksen.

Lisäksi, jos haluat luoda vastaavan integrointikoodin, voit suoraan kopioida sen, esimerkiksi CURL-koodi on seuraava:
```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha3' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_url": "https://recaptcha-demo.appspot.com/recaptcha-v3-request-scores.php",
  "website_key": "6LdKlZEpAAAAAAOQjzC2v_d36tWxCl6dWsozdSy9",
  "page_action": "examples/v3scores"
}'
```

Pythonin liitännäiskoodi on seuraava:

```python
import requests

url = "https://api.acedata.cloud/captcha/token/recaptcha3"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_url": "https://recaptcha-demo.appspot.com/recaptcha-v3-request-scores.php",
    "website_key": "6LdKlZEpAAAAAAOQjzC2v_d36tWxCl6dWsozdSy9",
    "page_action": "examples/v3scores"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Virheiden käsittely

API:ta kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`：Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`：Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`：Valtuuttamaton, virheellinen tai puuttuva valtuutustoken.
- `429 too_many_requests`：Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`：Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
