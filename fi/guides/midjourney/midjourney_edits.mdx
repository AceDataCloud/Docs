Tässä artikkelissa esitellään Midjourney Edits API -integraatio-ohjeet, jonka avulla voidaan muokata syötettyjä kuvia syöttämällä avainsanoja.

## Hakuprosessi

API:n käyttämiseksi sinun on ensin mentävä [Midjourney Edits API](https://platform.acedata.cloud/documents/midjourney-edits) -sivulle ja haettava tarvittavaa palvelua. Sivulle päästyäsi napsauta "Acquire"-painiketta, kuten kuvassa on esitetty:

![](https://cdn.acedata.cloud/q6ytrc.png)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Kirjautumisen ja rekisteröitymisen jälkeen palaat automaattisesti nykyiselle sivulle.

Ensimmäisellä hakemiskerralla saat ilmaisia krediittejä, joiden avulla voit käyttää tätä API:a ilmaiseksi.

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, joka koostuu avainsanojen `prompt`, toiminnan `action` ja viittauskuvan `image_url` syöttämisestä, jotta saat käsitellyn tuloksen. Ensinnäkin sinun on yksinkertaisesti välitettävä `action`-kenttä, jonka arvo on `generate`, tarkat tiedot ovat seuraavat:

<p><img src="https://cdn.acedata.cloud/m44i6n.png" width="500" className="m-auto" /></p>

Voit nähdä, että olemme asettaneet Request Headers -tiedot, mukaan lukien:

- `accept`: haluamasi vastausmuoto, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumiseen tarvittava avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

Lisäksi olemme asettaneet Request Body -tiedot, mukaan lukien:

- `mask`: voit määrittää kuvan alueen maskin sijainnin muokkausta ja uudelleenluontia varten.
- `split_images`: jakaa luodut kuvat useiksi kuviksi, jotka palautetaan sub_image_urls-kentän kautta. Oletusarvoisesti se on false.
- `action`: tämän kuvan muokkaustehtävän toiminta, oletusarvo on `generate`.
- `image_url`: muokattavan kuvan linkki.
- `prompt`: avainsanat.
- `mode`: luontitila, valinnaiset `fast`/`relax`/`turbo`.
- `callback_url`: URL, johon tulokset palautetaan.

Valinnan jälkeen voit huomata, että oikealla puolella on myös luotu vastaava koodi, kuten kuvassa on esitetty:

<p><img src="https://cdn.acedata.cloud/9wed3b.png" width="500" className="m-auto" /></p>

Napsauta "Try"-painiketta, niin voit testata, kuten yllä olevassa kuvassa on esitetty, ja saamme seuraavan tuloksen:

Palautetussa tuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `success`, tämän kuvan muokkaustehtävän tila.
- `task_id`, tämän kuvan muokkaustehtävän ID.
- `image_id`, tämän kuvan muokkaustehtävän kuvan ID.
- `sub_image_urls`, kuvan muokkaustehtävän useat kuvatulokset.
- `image_url`, kuvan muokkaustuloksen linkki.
- `image_width`, kuvan muokkaustuloksen leveys.
- `image_height`, kuvan muokkaustuloksen korkeus.
- `progress`, tämän kuvan muokkaustehtävän edistymiskenttä.

Voimme nähdä, että olemme saaneet tyydyttävää kuvaa koskevat tiedot, ja meidän tarvitsee vain käyttää tuloksessa olevaa `image_url`-linkkiä saadaksemme luodun kuvan.

Jos haluat luoda vastaavan integraatiokoodin, voit kopioida sen suoraan, esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/midjourney/edits' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "A cat sitting on a table",
  "split_images": true,
  "image_url": "https://cdn.acedata.cloud/jgo1cw.jpg",
  "action": "generate"
}'
```

## Asynkroninen palautus

Koska Midjourney Edits API:n luomisaika on suhteellisen pitkä, noin 1-2 minuuttia, jos API ei vastaa pitkään aikaan, HTTP-pyyntö pitää yhteyden auki, mikä johtaa ylimääräisiin järjestelmäresurssien kulutuksiin. Siksi tämä API tarjoaa myös asynkronisen palautustuen.

Kokonaisprosessi on seuraava: asiakas aloittaa pyynnön, kun se määrittää ylimääräisen `callback_url`-kentän. Asiakas tekee API-pyynnön, ja API palauttaa heti tuloksen, joka sisältää `task_id`-kentän tiedot, joka edustaa nykyistä tehtävän ID:tä. Kun tehtävä on valmis, luodun videon tulos lähetetään POST JSON -muodossa asiakkaan määrittämään `callback_url`:iin, johon sisältyy myös `task_id`-kenttä, jolloin tehtävän tulos voidaan yhdistää ID:n avulla.

Katsotaanpa esimerkin avulla, miten tämä toimii.

Ensinnäkin Webhook-palaute on palvelu, joka voi vastaanottaa HTTP-pyyntöjä, ja kehittäjän tulisi korvata se omalla HTTP-palvelimensa URL-osoitteella. Tässä esimerkin vuoksi käytämme julkista Webhook-esimerkkisivustoa https://webhook.site/, avaa tämä sivusto saadaksesi Webhook URL:n, kuten kuvassa on esitetty:

![](https://cdn.acedata.cloud/hfrbzw.png)

Kopioi tämä URL, niin voit käyttää sitä Webhookina, tässä esimerkki on `https://webhook.site/556e6971-b41f-4fa8-9151-6e91acd0399f`.

Seuraavaksi voimme asettaa kentän `callback_url` yllä olevaan Webhook URL:iin ja täyttää vastaavat parametrit, tarkat tiedot ovat seuraavat, kuten kuvassa on esitetty:

<p><img src="https://cdn.acedata.cloud/q3fnhv.png" width="500" className="m-auto" /></p>

Napsauta Suorita, ja voit huomata, että saat heti tuloksen, kuten seuraavassa:

```
{
  "task_id": "b8b7fdc2-628e-40dd-bc0c-671c3ddac9e9"
}
```

Odota hetki, ja voit tarkastella luodun videon tulosta osoitteessa `https://webhook.site/556e6971-b41f-4fa8-9151-6e91acd0399f`, kuten kuvassa on esitetty:

<p><img src="https://cdn.acedata.cloud/t8cupr.png" width="500" className="m-auto" /></p>

Sisältö on seuraava:

## Virheiden käsittely

API:ta kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Valtuuttamaton, virheellinen tai puuttuva valtuutustoken.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
