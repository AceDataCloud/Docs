Tässä artikkelissa esitellään hCaptcha-protokollin tunnistus API -liitäntäohje, joka mahdollistaa käyttäjille hCaptcha-tarkistuskoodikuvien tunnistamisen ja klikkaamisen sijaan pelkästään verkkosivuston avaimen lähettämisen kautta taustalla automaattisen purkamisen ja vahvistamisen.

## Hakuprosessi

Käyttääksesi hCaptcha-protokollin tunnistus API:a, sinun tulee ensin käydä [Ace Data Cloud -hallintapaneelissa](https://platform.acedata.cloud/console/applications) hankkimassa API-token, jota voit säilyttää varalla.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään, ja sen jälkeen sinut ohjataan takaisin nykyiselle sivulle.

**Yksi API-token riittää kaikkien palveluiden kutsumiseen, eikä jokaiselle palvelulle tarvitse hakea erikseen.** Ensimmäisestä hakemuksesta saat ilmaisen määrän, jonka avulla voit kokeilla palvelua ilmaiseksi; jos saldo on riittämätön, voit ladata yleistä saldoa [hallintapaneelista](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [hCaptcha-protokollin tunnistus API →](https://platform.acedata.cloud/documents/captcha-token-hcaptcha)

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, eli syöttää käsiteltävän hCaptcha-tarkistuskoodin verkkosivuston URL-osoite, jolloin saat käsitellyn tuloksen. Ensinnäkin sinun on yksinkertaisesti välitettävä `website_url`-kenttä. Esimerkkisivustomme on: `https://accounts.hcaptcha.com/demo`, ja meidän on saatava `website_key` `website_url`-sivulta. Avaa tämä verkkosivusto, paina F12 siirtyäksesi konsoliin, ja tee sitten globaalihaku Element-sivulla hakusanalla `hcaptcha-demo`, jolloin saat seuraavat tulokset:

<p><img src="https://cdn.acedata.cloud/bmx7ik.png" width="500" className="m-auto" /></p>

Missä `data-sitekey` -kenttä vastaa yhtä merkkijonoa, joka on `website_key`-arvo. Alla on tarkat parametritulokset:

<p><img src="https://cdn.acedata.cloud/st6q7a.png" width="500" className="m-auto" /></p>

Täällä voimme nähdä, että olemme asettaneet pyyntöotsikot, mukaan lukien:

- `accept`: minkälaista vastausmuotoa haluat vastaanottaa, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

Lisäksi on asetettu pyyntökeho, joka sisältää:

- `website_url`: käsiteltävän tarkistuskoodin verkkosivuston URL-osoite.
- `website_key`: hCaptchassa käytettävä verkkosivuston avaimen tunniste.
- `rqdata`: valinnainen. hCaptcha Enterprise -haaste voi tarjota sivulla `data-rqdata`, ja tällaisissa haasteissa täytetään sen alkuperäinen arvo; tavallisessa hCaptchassa ei tarvitse täyttää.
- `proxy`: valinnainen, tuo oma proxy (Bring Your Own Proxy). Asetuksen jälkeen järjestelmä purkaa tarkistuskoodin tarjoamasi proxy IP:n kautta, mikä auttaa hallitsemaan lähtö-IP:n laatua (esimerkiksi välttämään, että julkinen proxy IP estetään kohdesivustolla ja palauttaa `410 Gone`). Muoto on `scheme://[user:pass@]host:port`, `scheme` tukee `http`/`https`/`socks4`/`socks5`, esimerkiksi `http://user:pass@1.2.3.4:8080`. Jos et täytä, käytetään alustan oletusproxia.

由上图分析可知，此次POST请求的URL为：`https://accounts.hcaptcha.com/demo`，我们仅需要提交参数 `g-recaptcha-response`、`h-captcha-response` 和 `email`，然后我们只需要将处理后的token传入下面的data中即可，调用token验证所对应CURL代码如下：

```shell
curl 'https://accounts.hcaptcha.com/demo' \
  --data-raw 'email=&g-recaptcha-response={token}&h-captcha-response={token}'
```

调用token验证所对应的Python代码如下：

```python
import requests

token = '{token}'

data = {
    'email': '',
    'g-recaptcha-response': token,
    'h-captcha-response': token
}

response = requests.post('https://accounts.hcaptcha.com/demo',
                        data=data)

if response.status_code == 200:
    print(response.text)

```

另外如果想生成对应的对接代码，可以直接复制生成，例如 CURL 的代码如下：

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/hcaptcha' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "a5f74b19-9e45-40e0-b45d-47ff91b7a6c2",
  "website_url": "https://accounts.hcaptcha.com/demo"
}'
```

Python 的对接代码如下：

```python
import requests

url = "https://api.acedata.cloud/captcha/token/hcaptcha"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_key": "a5f74b19-9e45-40e0-b45d-47ff91b7a6c2",
    "website_url": "https://accounts.hcaptcha.com/demo"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynkroninen tila (async)

Oletusarvoisesti API on synkroninen ja estää: yksi pyyntö odottaa aina, kunnes tokenin käsittely on valmis. Jos teet useita ratkaisijoita (multi-solver rotation) ja haluat "saada task_id heti tehtävän lähettämisen jälkeen, ja sitten aikatauluttaa muita ratkaisijoita, ja palata myöhemmin tulosten lukemiseen", voit lähettää pyyntöön `async: true`.

Kun lähetät `async: true`, rajapinta palauttaa heti `task_id`:n, eikä estä odottamista:

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

Jos haluat tarkistaa edistymistä aktiivisesti, voit käyttää tätä `task_id`:ta kysyäksesi `POST /captcha/tasks` (suositellaan joka 3-5 sekunti). Tämä rajapinta ei käynnistä tai edistä tehtävän käsittelyä; vaikka et kysyisi, katkaise verkkoyhteys tai sulje asiakas, palvelin jatkaa käsittelyä:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Käsittelyssä palautuu `status: processing`:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

Käsittelyn valmistuttua palautuu `status: ready` ja token:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "token": "P1_eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1Ni......"
}
```

Laskutustiedot: Asynkronisessa tilassa tehtävän luominen ja "käsittelyssä" tilan lukeminen eivät aiheuta laskutusta; **asiakas maksaa ensimmäisestä onnistuneesta tuloksen lukemisesta** (sama käytäntö ja hinta kuin synkronisessa tilassa). Palvelin edistää tehtävää itsenäisesti, mutta ei veloita etukäteen, vaikka taustalla olisi valmis. Tehtävä, jota ei ole onnistuttu 120 sekunnissa, päättyy HTTP 504 `timeout` -tilaan, eikä siitä veloiteta. `/captcha/tasks` ei vastaa tehtävän edistämisestä.

## Virheiden käsittely

API:ta kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvista tai virheellisistä parametreista johtuen.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvista tai virheellisistä parametreista johtuen.
- `401 invalid_token`: Valtuuttamaton, virheellinen tai puuttuva valtuutustoken.
- `429 too_many_requests`: Liikaa pyyntöjä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
