Tässä artikkelissa esitellään hCaptcha-protokollin tunnistus API -liittymisohje, joka mahdollistaa käyttäjille hCaptcha-tarkistuskoodikuvien tunnistamisen ja valitsemisen sijaan vain verkkosivuston avaimen lähettämisen, jolloin taustalla tapahtuu automaattinen purku ja vahvistus.

## Hakuprosessi

API:n käyttämiseksi sinun on ensin mentävä [hCaptcha-protokollin tunnistus API](https://platform.acedata.cloud/documents/34806b3a-f0f6-45c5-b8b1-143ced7b9393) -sivulle ja haettava vastaavaa palvelua. Sivulle päästyäsi napsauta "Acquire"-painiketta, kuten kuvassa on esitetty:

![](https://cdn.acedata.cloud/q6ytrc.png)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Kirjautumisen ja rekisteröitymisen jälkeen palaat automaattisesti nykyiselle sivulle.

Ensimmäisellä hakemiskerralla saat ilmaisia krediittejä, joiden avulla voit käyttää tätä API:a ilmaiseksi.

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, joka on syöttää hCaptcha-tarkistuskoodia käsiteltävän verkkosivuston URL-osoite, jolloin saat käsitellyn tuloksen. Ensinnäkin sinun on yksinkertaisesti välitettävä `website_url`-kenttä. Esimerkkisivustomme on: `https://accounts.hcaptcha.com/demo`, ja meidän on saatava `website_key` `website_url` -sivulta. Avaa tämä verkkosivusto, paina F12 päästäksesi konsoliin, ja tee sitten globaalihaku Element-sivulla hakusanalla `hcaptcha-demo`, jolloin saat seuraavat tulokset:

<p><img src="https://cdn.acedata.cloud/bmx7ik.png" width="500" class="m-auto"></p>

Missä `data-sitekey` -kenttä vastaa yhtä merkkijonoa, joka on `website_key` -arvo. Alla on tarkat parametritulokset:

<p><img src="https://cdn.acedata.cloud/st6q7a.png" width="500" class="m-auto"></p>

Voit nähdä, että olemme asettaneet Request Headers -otsikot, mukaan lukien:

- `accept`: minkälaista vastausmuotoa haluat vastaanottaa, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumiseen käytettävä avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

Lisäksi on asetettu Request Body, joka sisältää:

- `website_url`: verkkosivuston URL-osoite, jolle tarkistuskoodi on käsiteltävä.
- `website_key`: hCaptchassa käytettävä verkkosivuston avaimen tunniste.

Valinnan jälkeen voit huomata, että oikealla puolella on myös luotu vastaava koodi, kuten kuvassa on esitetty:

<p><img src="https://cdn.acedata.cloud/5gse4m.png" width="500" class="m-auto"></p>

由上图分析可知，此次POST请求的URL为：`https://accounts.hcaptcha.com/demo`，我们仅需要提交参数 `g-recaptcha-response`、`h-captcha-response` 和 `email`，然后我们只需要将处理后的token传入下面的data中即可，调用token验证所对应CURL代码如下：

```shell
curl 'https://accounts.hcaptcha.com/demo' \
  --data-raw 'email=&g-recaptcha-response={token}&h-captcha-response={token}'
```

调用token验证所对应的Python代码如下：

```python
import requests

token = '{token}'

data = {
    'email': '',
    'g-recaptcha-response': token,
    'h-captcha-response': token
}

response = requests.post('https://accounts.hcaptcha.com/demo',
                        data=data)

if response.status_code == 200:
    print(response.text)

```

另外如果想生成对应的对接代码，可以直接复制生成，例如 CURL 的代码如下：

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/hcaptcha' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "a5f74b19-9e45-40e0-b45d-47ff91b7a6c2",
  "website_url": "https://accounts.hcaptcha.com/demo"
}'
```

Python 的对接代码如下：

```python
import requests

url = "https://api.acedata.cloud/captcha/token/hcaptcha"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_key": "a5f74b19-9e45-40e0-b45d-47ff91b7a6c2",
    "website_url": "https://accounts.hcaptcha.com/demo"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Virheiden käsittely

API:ta kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`：Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`：Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`：Valtuuttamaton, virheellinen tai puuttuva valtuutustoken.
- `429 too_many_requests`：Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`：Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

