Kun verkkosivustojen ja sovellusten torjuntatoimet ovat yhä tiukempia, eri verkkosivustojen ja sovellusten riskienhallintatarkastukset ovat yhä voimakkaampia, joista yksi on IP-estot.

IP-estojen ongelman ratkaisemiseksi tehokas tapa on asettaa proxy, jonka avulla verkkosivuston robotti voi käyttää proxyä peittääkseen todellisen IP-osoitteensa ja siten ohittaa torjuntatoimet.

Kuitenkin proxyjen laatu vaihtelee, esimerkiksi markkinoilla olevat ilmaiset proxyt ovat lähes poikkeuksetta käyttökelvottomia tai estettyjä, ja jotkut maksulliset tavalliset proxyt on myös lisätty eri verkkosivustojen ja sovellusten riskienhallintamustiin. Siksi tällä hetkellä korkealaatuisten tietojen keräämiseen käytettävien proxyjen määrä on vähentynyt, ja markkinoilla on pääasiassa muutamia korkealaatuisia proxy-tyyppejä, kuten yksityiset proxyt, ADSL-proxyt ja mobiiliverkkoproxyt.

Tämä proxy-palvelu perustuu ADSL:ään ja tarjoaa kiertävän proxy-palvelun, ja tämä asiakirja esittelee palvelun hakemisen ja käytön menetelmät.

## ADSL-proxy esittely

ADSL, englanniksi Asymmetric Digital Subscriber Line, tarkoittaa epäsymmetristä digitaalista tilaajayhteyttä. ADSL-yhteys muodostetaan soittamalla, jolloin on syötettävä ADSL-tilin käyttäjätunnus ja salasana, ja jokaisella soitolla vaihdetaan IP-osoite. IP-osoitteet jakautuvat useisiin A-segmentteihin, ja jos kaikki IP-osoitteet ovat käytettävissä, se tarkoittaa, että IP-määrä voi olla jopa kymmeniä miljoonia.

ADSL-perusteiset proxyt tarjoavat verrattuna datakeskuksissa rakennettuihin tavallisiin proxyihin kaksi etua: ensinnäkin linjat ovat pääasiassa mobiili-, kiinteä- ja teleliikennettä, mikä on lähempänä asukkaiden päivittäisiä verkkoyhteyksiä, joten IP-estojen todennäköisyys on alhaisempi. Toiseksi IP-määrä on suuri, ja mitä suurempi IP-määrä on, sitä pienempi on jokaisen IP-osoitteen eston todennäköisyys.

Tämän proxy-palvelun taustalla on laaja ADSL-proxy-allas, joka kattaa pääasiassa Kiinan linjat, ja linjat tulevat pääasiassa mobiili-, kiinteä- ja teleliikenteen soittavista VPS-palvelimista, kattaen yli 100 kaupunkia Kiinassa, ja ulostulo-IP-osoitteita on noin 300 000 päivittäin. Se tukee lähes kaikkia markkinoilla olevia verkkosivustoja ja sovelluksia, ja proxyjen laatu on erittäin korkea, mikä voi merkittävästi vähentää riskienhallinnan todennäköisyyttä.

## Koodiyhteys

Alla on esimerkki Pythonista, joka näyttää tämän proxy-asetuksen menetelmän:

```python
import requests

proxy = 'https://{proxy_username}:{proxy_password}@adsl.proxy.acedata.cloud:30005'

proxies = {
    'http': proxy,
    'https': proxy
}

for _ in range(3):
    resp = requests.get('https://ipinfo.io', proxies=proxies)
    print(resp.text)

```

Tässä ensin määrittelemme proxy-URL:n ja määrittelemme sen proxy-muuttujaksi, protokolla on http-protokolla, ja sen jälkeen seuraa tunnelin proxy-käyttäjätunnus ja salasana (eli ohjauspaneelissa esitetyt käyttäjätunnus ja salasana, erotettuna kaksoispisteellä), ja sen jälkeen tulee `@`-merkki, ja sitten proxy-osoite ja portti.

Seuraavaksi määrittelemme proxies-muuttujan, joka sisältää kaksi avain-arvo-paria, joiden avaimet ovat http ja https, ja niiden arvot ovat molemmat proxy, mikä tarkoittaa, että HTTP- ja HTTPS-protokollan verkkosivustoille käytetään proxy-muuttujaa määritellyn proxy-yhteyden tekemiseen.

Seuraavaksi määrittelemme kolme silmukkaa proxy-testauksen suorittamiseksi, ja tässä pyydetty URL-osoite on [https://ipinfo.io](https://ipinfo.io), joka voi palauttaa pyynnön tehneen verkkosivuston todellisen IP-osoitteen ja IP-osoitteen sijainnin.

Tietysti yllä oleva proxy-asetus on itse asiassa suhteellisen yksinkertainen asetus.

Itse asiassa yllä oleva koodi on ekvivalentti ylimääräisen otsikon - Proxy Authorization asettamiselle pyynnön aikana, joten yllä olevaa koodia voidaan myös kirjoittaa seuraavasti:

```python
import requests
import base64

proxy_host = 'adsl.proxy.acedata.cloud'
proxy_port = '30005'
proxy_username = '{proxy_username}' # 8-merkkinen käyttäjänimi
proxy_password = '{proxy_password}' # 32-merkkinen salasana

credentials = base64.b64encode(
    f'{proxy_username}:{proxy_password}'.encode()).decode()

proxies = {
    'http': f'http://{proxy_host}:{proxy_port}',
    'https': f'http://{proxy_host}:{proxy_port}'
}

headers = {
    'Proxy-Authorization': f'Basic {credentials}'
}

for _ in range(3):
    resp = requests.get('https://ipinfo.io',
                        proxies=proxies, headers=headers)
    print(resp.text)

```

Voimme nähdä, että täällä asetamme ylimääräisen Proxy-Authorization-pyynnön otsikon, jossa on proxy-käyttäjänimi ja salasana (jotka on koodattava Base64-muotoon), ja tällaisen koodin suoritusvaikutus on myös sama.

Muille kielille, kuten JavaScriptin axiosille, voidaan käyttää samanlaista asetusmenetelmää:

```javascript
const axios = require("axios");
const base64 = require("base64");

const proxy_host = "adsl.proxy.acedata.cloud";
const proxy_port = "30005";
const proxy_username = "{proxy_username}"; // 8-merkkinen käyttäjänimi
const proxy_password = "{proxy_password}"; // 32-merkkinen salasana

const credentials = base64.encode(`${proxy_username}:${proxy_password}`);

const proxies = {
  http: `http://${proxy_host}:${proxy_port}`,
  https: `http://${proxy_host}:${proxy_port}`,
};

const headers = {
  "Proxy-Authorization": `Basic ${credentials}`,
};

for (let i = 0; i < 3; i++) {
  axios
    .get("https://ipinfo.io", { proxies, headers })
    .then((resp) => console.log(resp.data))
    .catch((err) => console.error(err));
}
```

Suoritusvaikutus on sama.

Muiden kielten asetustapoja varten, viitataan edellisiin ja muokataan itse.
