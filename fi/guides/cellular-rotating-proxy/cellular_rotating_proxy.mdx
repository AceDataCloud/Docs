Kun verkkosivustojen ja sovellusten torjuntatoimet ovat yhä tiukempia, eri verkkosivustojen ja sovellusten riskienhallintatarkastukset ovat yhä voimakkaampia, joista yksi on IP-estot.

IP-estojen ongelman ratkaisemiseksi tehokas tapa on asettaa proxy, jonka avulla verkkosivuston kaappaaja voi käyttää proxy-IP:tä naamioidakseen oman todellisen IP-osoitteensa, jolloin se voi ohittaa torjuntatoimet.

Kuitenkin proxyjen laatu vaihtelee, esimerkiksi markkinoilla olevat ilmaiset proxyt ovat lähes poikkeuksetta käyttökelvottomia tai estettyjä, ja jotkut maksulliset tavalliset proxyt on myös lisätty monien verkkosivustojen ja sovellusten riskienhallintamustalle. Siksi tällä hetkellä käytettävissä olevat korkealaatuiset datakaappaamiseen soveltuvat proxyt ovat yhä harvinaisempia, ja markkinoilla olevat korkealaatuiset proxyt ovat pääasiassa omistettuja proxyjä, ADSL-proxyjä ja mobiiliverkko-proxyjä.

Tämä proxy-palvelu perustuu mobiiliverkkoon (4G, 5G) perustuvaan kiertoprosessiin, ja tässä asiakirjassa esitellään tämän palvelun hakeminen ja käyttö.

## Mobiiliverkko-proxy

Mobiiliverkko-proxy on itse asiassa mobiilidatan avulla rakennettu proxy-palvelu, jossa kaikki proxy-IP:t ovat puhelimen todellisia IP-osoitteita. Tällaisia proxyjä käytetään suhteellisen harvoin kaappausalalla, joten niiden estämisen todennäköisyys on myös pienempi, joten tämäntyyppinen proxy on erittäin tehokas kaappaamaan verkkosivustoja ja sovelluksia, joilla on erittäin tiukat riskienhallintatoimet.

Tämä proxy-palvelu perustuu laajaan ryhmäohjattuun puhelinpooliin, ja kaikki liikenne ohjataan puhtaasti mobiilidatan kautta, mikä tukee lähes kaikkia markkinoilla olevia verkkosivustoja ja sovelluksia, ja proxyjen laatu on erittäin korkea, mikä voi merkittävästi vähentää riskienhallintatoimien todennäköisyyttä.

Kun sinulla on proxy-käyttäjänimi ja salasana, helpoin tapa on testata curl-komentorivillä, jos et ole vielä asentanut, voit viitata [https://curl.se/](https://curl.se/) asennukseen.

```shell
curl -x 1f78266a:eff0896726224fa2a99fe82dd1f07562@cellular.proxy.acedata.cloud:30000 https://ipinfo.io
```

Tässä käytämme curlin `-x`-parametria määrittämään proxy-osoitteen, proxy-protokolla on oletuksena HTTP/HTTPS, ja tässä pyydetty URL-osoite on [https://ipinfo.io](https://ipinfo.io), tämä sivusto voi palauttaa pyynnön tehneen sivuston todellisen IP-osoitteen ja IP-osoitteen sijainnin.

## Koodiyhteys

Alla on esimerkki Pythonista, joka näyttää mobiiliverkko-proxy-yhteyden asetustavan:

```python
import requests

proxy = 'http://{proxy_username}:{proxy_password}@cellular.proxy.acedata.cloud:30000'

proxies = {
    'http': proxy,
    'https': proxy
}

for _ in range(3):
    resp = requests.get('https://ipinfo.io', proxies=proxies)
    print(resp.text)

```

Tässä ensin määrittelemme proxy-URL:n ja määrittelemme sen proxy-muuttujaksi, protokolla on http, ja sen jälkeen seuraa kiertoprosessin käyttäjänimi ja salasana (eli ohjauspaneelissa näytettävä käyttäjänimi ja salasana, erotettuna kaksoispisteellä), sitten lisäämme `@`-merkin, ja sen jälkeen proxy-osoite ja portti.

Seuraavaksi määrittelemme proxies-muuttujan, joka sisältää kaksi avain-arvo-paria, avaimet ovat http ja https, ja niiden arvot ovat molemmat proxy, mikä tarkoittaa, että HTTP- ja HTTPS-protokollan verkkosivustoille käytetään proxy-muuttujassa määriteltyä proxyä pyyntöjen tekemiseen.

Seuraavaksi määrittelemme kolme silmukkaa proxy-testaukseen, tässä pyydetty URL-osoite on [https://ipinfo.io](https://ipinfo.io), tämä sivusto voi palauttaa pyynnön tehneen sivuston todellisen IP-osoitteen ja IP-osoitteen sijainnin.

Tietysti yllä oleva proxy-asetustapa on itse asiassa suhteellisen yksinkertainen asetustapa.

Itse asiassa yllä oleva koodi on ekvivalentti sille, että pyyntöä tehdessä asetetaan ylimääräinen otsikko - Proxy Authorization, joten yllä olevaa koodia voidaan myös kirjoittaa seuraavasti:

```python
import requests
import base64

proxy_host = 'cellular.proxy.acedata.cloud'
proxy_port = '30000'
proxy_username = '{proxy_username}' # 8-merkkinen käyttäjänimi
proxy_password = '{proxy_password}' # 32-merkkinen salasana

credentials = base64.b64encode(
    f'{proxy_username}:{proxy_password}'.encode()).decode()

proxies = {
    'http': f'http://{proxy_host}:{proxy_port}',
    'https': f'http://{proxy_host}:{proxy_port}'
}

headers = {
    'Proxy-Authorization': f'Basic {credentials}'
}

for _ in range(3):
    resp = requests.get('https://ipinfo.io',
                        proxies=proxies, headers=headers)
    print(resp.text)

```

Voit nähdä, että täällä asetamme ylimääräisen Proxy-Authorization-pyyntöotsikon avulla proxy-käyttäjänimen ja -salasanan (jotka on koodattava Base64-muotoon), ja tällaisen koodin suoritusvaikutus on myös sama.

Muille kielille, kuten JavaScriptin axiosille, voidaan käyttää samanlaista asetustapaa:

```javascript
const axios = require("axios");
const base64 = require("base64");

const proxy_host = "cellular.proxy.acedata.cloud";
const proxy_port = "30000";
const proxy_username = "{proxy_username}"; // 8-merkkinen käyttäjänimi
const proxy_password = "{proxy_password}"; // 32-merkkinen salasana

const credentials = base64.encode(`${proxy_username}:${proxy_password}`);

const proxies = {
  http: `http://${proxy_host}:${proxy_port}`,
  https: `http://${proxy_host}:${proxy_port}`,
};

const headers = {
  "Proxy-Authorization": `Basic ${credentials}`,
};

for (let i = 0; i < 3; i++) {
  axios
    .get("https://ipinfo.io", { proxies, headers })
    .then((resp) => console.log(resp.data))
    .catch((err) => console.error(err));
}
```

Suoritusvaikutus on sama.

Muiden kielten asetustapoja varten, viittaat edellisiin ja muokkaat itse.
