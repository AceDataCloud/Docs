## 1. API-avaimen hankkiminen

Avaa [Ace Data Cloud -sovellusluettelo](https://platform.acedata.cloud/console/applications), siirry käytettävissä olevaan sovellukseen ja kopioi API-avain.

## 2. Kuvan URL-osoitteen käyttäminen muokkaukseen

Alkuperäinen kuva:

![GPT Image 2 -muokkauksen alkuperäinen kuva](https://cdn.acedata.cloud/18240dc44b9c.png)

  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",

## 3. Paikallisen kuvan lataaminen

Käytä `multipart/form-data`-muotoa:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` voidaan välittää toistuvasti, GPT Image -sarja tukee enintään 16 viitekuvaa. JSON-pyynnön `image` voi olla yksittäinen URL-osoite tai URL-osoitteiden taulukko; paikalliset tiedostot ladataan multipart-muodossa.

| Malli                                | Soveltuvat käyttötapaukset ja laskutustavat                                        |
| --------------------------------- | ------------------------------------------------ |

| `gpt-image-2:reverse`             | Valitse käänteinen kanava nimenomaisesti, kiinteä laskutus onnistuneiden kuvien määrän mukaan                             |
| `gpt-image-2:official`            | Virallinen API-kanava, vakaampi, laskutus todellisen Token-kulutuksen mukaan                   |
| `gpt-image-2.5-flare`             | Painottaa generointinopeutta, kiinteä laskutus onnistuneiden kuvien määrän mukaan                               |
| `gpt-image-2.6-flare`             | Painottaa generointinopeutta, kiinteä laskutus onnistuneiden kuvien määrän mukaan                               |
| `gpt-image-2.5-flare:reverse`     | Nimenomainen käänteinen alias, vastaa mallia `gpt-image-2.5-flare`, kiinteä laskutus onnistuneiden kuvien määrän mukaan    |
| `gpt-image-2.6-flare:reverse`     | Nimenomainen käänteinen alias, vastaa mallia `gpt-image-2.6-flare`, kiinteä laskutus onnistuneiden kuvien määrän mukaan    |

| `gpt-image-2.5-sunburst`          | Painottaa korkeaa tarkkuutta ja yksityiskohtaista hallintaa, kiinteä laskutus onnistuneiden kuvien määrän mukaan                           |
| `gpt-image-2.6-sunburst`          | Painottaa korkeaa tarkkuutta ja yksityiskohtaista hallintaa, kiinteä laskutus onnistuneiden kuvien määrän mukaan                           |
| `gpt-image-2.5-sunburst:reverse`  | Nimenomainen käänteinen alias, vastaa mallia `gpt-image-2.5-sunburst`, kiinteä laskutus onnistuneiden kuvien määrän mukaan |
| `gpt-image-2.6-sunburst:reverse`  | Nimenomainen käänteinen alias, vastaa mallia `gpt-image-2.6-sunburst`, kiinteä laskutus onnistuneiden kuvien määrän mukaan |
| `gpt-image-2.5-sunburst:official` | Virallinen API-kanava, vakaampi ja painottaa korkeaa tarkkuutta sekä yksityiskohtaista hallintaa, laskutus todellisen Token-kulutuksen mukaan        |
| `gpt-image-2.6-sunburst:official` | Virallinen API-kanava, vakaampi ja painottaa korkeaa tarkkuutta sekä yksityiskohtaista hallintaa, laskutus todellisen Token-kulutuksen mukaan        |

Virallisen API-kanavan sivuhinta on arvio ennen pyyntöä, ja lopullinen hinta määräytyy vastauksen todellisen Token-kulutuksen ja käyttötietojen perusteella.

`quality` tukee arvoja `auto`, `low`, `medium`, `high`; 2.5 / 2.6 Flare ja Sunburst (mukaan lukien `:reverse`- ja `:official`-versiot) tukevat lisäksi arvoja `xhigh`, `max`. Tämä kenttä voidaan välittää sekä JSON-kuva-URL-muokkauksessa että multipart-tiedostomuokkauksessa; virallinen kanava laskuttaa todellisen Token-kulutuksen mukaan.

## 4. Maskin käyttäminen paikalliseen muokkaukseen

Virallinen Images Edit -rajapinta määrittää `mask`-kentän avulla alueen, jota saa muokata. Ace Data Cloudin `:official`-mallit noudattavat samaa multipart-sopimusta:

- `mask`-kentän on oltava alfakanavallinen PNG, jonka koko on enintään 4 Mt;
- maskin koon on vastattava täsmälleen ensimmäistä `image`-kuvaa;
- läpinäkyvät pikselit, joiden Alpha-arvo on `0`, tarkoittavat sallittua muokkausta, läpinäkymättömät pikselit tarkoittavat säilytettäviä alueita;
- pelkästään mustavalkoinen RGB-kuva, jossa ei ole läpinäkyvyyskanavaa, ei voi toimia kelvollisena maskina;
- kehotteen tulisi kuvata haluttu kokonaiskuva ja samalla selkeästi ilmoittaa paikallinen muutos sekä muuttumattomana säilytettävä sisältö.

Alla luodaan ensin maski alkuperäisestä kuvasta. Esimerkki asettaa keskellä olevan suorakulmion läpinäkyväksi ja sallii mallin muokata vain tätä aluetta:
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Lataa sitten alkuperäinen kuva ja maski yhdessä:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Voit myös käyttää OpenAI:n virallisen Python SDK:n `images.edit`-kutsutapaa; sinun tarvitsee vain osoittaa `base_url` Ace Data Cloudiin:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Kun käytät `mask`-kenttää, alkuperäinen kuva ja maski on ladattava samassa multipart-pyynnössä erikseen kentillä `image=@input.png` ja `mask=@mask.png`. Älä välitä URL-alkuperäiskuvaa ja paikallista maskitiedostoa yhdessä; pelkät URL-muokkauspyynnöt eivät tue paikallisen `mask`-tiedoston liittämistä. Maski rajoittaa muokkausaluetta, mutta generointimalli voi silti yhdistää reunat luonnollisesti; kun tarvitaan tiukkoja rajoja, käytä selkeitä Alpha-reunoja ja toista kehotteessa, minkä sisällön on pysyttävä muuttumattomana.

Yllä oleva kutsutapa vastaa [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit)- ja [GPT Image -virallisen Cookbookin](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image) maskiesimerkkejä.

## 5. Yleiset parametrit

| Kenttä                | Kuvaus                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (nopeampi) tai `gpt-image-2.5-sunburst` (suurempi tarkkuus ja hallinta); kaikille kolmelle voi valita vastaavan `:official`-variantin, ja `gpt-image-2` tukee myös `:reverse`-varianttia |
| `image`           | JSON käyttää yhtä URL:ää tai enintään 16 URL:n taulukkoa; multipart käyttää yhtä tai useampaa `image`-tiedostokenttää. Kun käytetään `mask`-kenttää, paikallinen kuvatiedosto on ladattava                                              |
| `mask`            | Valinnainen PNG-maski, vain multipart-tiedostolataukseen; siinä on oltava Alpha-kanava, sen on oltava samankokoinen kuin ensimmäinen `image`, eikä se saa ylittää 4 Mt:tä                                                                 |
| `prompt`          | Muokkausohje                                                                                                                             |
| `size`            | `auto` tai rajoitusten mukainen `WIDTHxHEIGHT`                                                                                                     |
| `n`               | 1–10; `response_format=b64_json` tukee vain arvoa 1                                                                                           |
| `response_format` | `url` tai `b64_json`                                                                                                               |
| `callback_url`    | Valinnainen asynkroninen takaisinsoitto-osoite                                                                                                                         |

Kokosäännöt ovat samat kuin generointirajapinnassa: leveyden ja korkeuden on oltava 16:n kerrannaisia, pitkä sivu saa olla enintään 3840, kokonaispikselimäärän on oltava 655 360–8 294 400, ja kuvasuhde saa olla enintään 3:1. Kun `size` jätetään pois tai käytetään `auto`-arvoa, malli valitsee kuvasuhteen kehotteen ja ensimmäisen viitekuvan perusteella.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` ja niiden `:reverse`-aliakset laskutetaan onnistuneiden kuvien määrän mukaan; `gpt-image-2:official`, `gpt-image-2.5-flare:official` ja `gpt-image-2.5-sunburst:official` laskutetaan tekstisyötteen, viitekuvasyötteen ja kuvaulostulon todellisten Tokenien perusteella, ja lopullinen tieto määräytyy käyttötietojen mukaan.

## 6. Asynkroninen takaisinsoitto ja vianmääritys

Pitkiin tehtäviin voidaan lisätä pyyntöön:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Asynkroninen 200-vastaus on `{"task_id": "..."}`; valmistumisen jälkeen takaisinsoitto palauttaa lopullisen tuloksen. Synkroniset pyynnöt palauttavat sen sijaan `created`- ja `data`-kentät.

| Tila  | Tarkista                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Kuvamuoto/-määrä, parametrien yhdistelmä ja kokomuoto; kun käytetään `mask`-kenttää, tarkista PNG Alpha-kanava, 4 Mt:n raja ja se, vastaavatko sen mitat ensimmäistä alkuperäiskuvaa |
| 401 | API Key ja Bearer Header                                           |
| 429 | Pyyntötiheys                                                              |
| 504 | Käytä asynkronista takaisinsoittoa                                                            |

Virhevastaus sisältää `trace_id`-kentän. Anna tämä ID palautetta ongelmasta, älä anna API Keytä.

Täydelliset kentät ja reaaliaikaiset enumeraatiot löytyvät [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits) -sivulta. Pelkän tekstin kuvagenerointia varten katso [GPT Image 2 / 2.5 / 2.6 -kuvagenerointi](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 käyttää 2.5:n generointi-, muokkaus-, asynkronisten tehtävien ja laskutusrajapintoja:

| Malli                                                          | Laskutus                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0.22 Credits/kuva                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0.22 Credits/kuva                   |
| `gpt-image-2.6-flare:official`                              | Sama kuin 2.5 official, laskutetaan todellisen Token-kulutuksen mukaan |
| `gpt-image-2.6-sunburst:official`                           | Sama kuin 2.5 official, laskutetaan todellisen Token-kulutuksen mukaan |

Laaduksi voidaan valita `auto`, `low`, `medium`, `high`, `xhigh`, `max`; koossa käytetään `auto`-arvoa tai edellä mainittujen rajoitusten mukaista `WIDTHxHEIGHT`-arvoa. Tämä rajapinta tukee `png`-, `jpeg`- ja `webp`-muotoja; GPT Image 2.6 tukee lisäksi natiivisti animoituja `gif`-kuvia, mutta ei toistaiseksi SVG:tä. Muokkaus tukee JSON-kuva-URL:iä ja multipart-tiedostolatauksia. `:reverse` on samannimisen tavallisen version eksplisiittinen alias. Käytä täydellistä mallinimeä, älä välitä `gpt-image-2.6`.

### GPT Image 2.6 kuvan muuntaminen animoiduksi GIF-kuvaksi
GPT Image 2.6 Flare, Sunburstin tavallinen versio, `:reverse`, `:official` voivat kaikki käyttää `output_format: "gif"` -asetusta. Animaatioruudut, silmukkatiedot ja toistoaika säilyvät; `frame_count` tarkoittaa ruutujen määrää, `frame_duration_ms` tarkoittaa millisekuntien määrää per ruutu, ruutujen määrän on oltava kokonaisluku väliltä 2–16, kunkin ruudun keston on oltava kokonaisluku väliltä 20–655350 millisekuntia, ja niitä käytetään vain GIF:ille; koodaus pyöristetään lähimpään 10 millisekuntiin. Jos ei määritetä, oletusarvona on 9 ruutua ja 200 millisekuntia per ruutu; kun GIFin `size` jätetään pois tai se on auto, käytetään 512x512-esiasetusta.

On suositeltavaa käyttää ensin asetuksia `size: "512x512"`, `frame_count: 9`, `frame_duration_ms: 200`. GIF:illä on erilliset koko- ja ruutumäärärajoitukset, eikä staattisia 4K-määrityksiä voi soveltaa suoraan; jotkin mallit säätävät todellista tulostuskokoa. `n` tarkoittaa palautettavien GIF-tiedostojen määrää, ei animaatioruutujen määrää. Tavallisesta versiosta ja `:reverse`-versiosta veloitetaan edelleen onnistuneiden tiedostojen määrän mukaan, virallisesta versiosta veloitetaan todellisen token-kulutuksen mukaan.

```json
{
  "model": "gpt-image-2.6-flare",
  "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
  "prompt": "Animate the mug gently moving left and right. Keep its appearance and the background, no text.",
  "output_format": "gif",
  "size": "512x512",
  "quality": "medium",
  "frame_count": 9,
  "frame_duration_ms": 200,
  "n": 1,
  "async": true
}
```

### GPT Image 2.6 4K-staattiset kuvat

Flare, Sunburst sekä niiden `:reverse`- ja `:official`-variantit voivat kaikki käyttää edellä mainittuja 4K-pikseliesiasetuksia, kuten `3840x2160` ja `2160x3840`. Sekä generoinnissa että muokkauksessa tarkat pikselit välitetään `size`-parametrin kautta; `4K` ei ole kelvollinen `size`-arvo, ja `4096x4096` ylittää myös nykyisen pikselirajan. Edellä mainitut 4K-määritykset soveltuvat staattisille PNG/JPEG/WebP-kuville; käytä GIF:ille niiden omia parametreja.

### GPT Image 2.6 sommittelun monimutkaisuus

`complexity` voi olla `low`, `medium` tai `high`; jos se jätetään pois, käytetään mallin oletusarvoa `high`. Se hallitsee suunnittelun monimutkaisuutta ja on riippumaton `quality`-renderöintilaadusta; siitä ei veloiteta erikseen per kerta, ja virallinen versio laskutetaan edelleen todellisten tokenien mukaan. Muut mallit eivät tue tätä parametria.

GIF ei tue maskia, merkintäkuvia, mukautettua pakkausta, kehotteen uudelleenkirjoittamista tai osittaista kuvien suoratoistotulostusta; yhteensopimattomat yhdistelmät hylätään ennen generointia. Koko, ruutujen määrä ja lukumäärä ovat yhdessä mallin pikselibudjetin rajoittamia; tavallisen Flaren `1024x1024`, 2 ruutua on vahvistettu toimivaksi, mutta tätä johtopäätöstä ei voi laajentaa kaikkiin 1K-yhdistelmiin tai 4K-GIF:ihin.

### Merkintäohjattu muokkaus

GPT Image 2.6:n staattinen muokkaus tukee `markup`-asetusta. Lataa ensimmäisen referenssikuvan kanssa samankokoinen läpinäkyvä PNG, ympyröi muokattava kohta erillisellä tasolla ja kuvaile muokkausvaatimukset `prompt`-kentässä. Merkintätason on sisällettävä läpinäkyviä pikseleitä; kummankin kuvan koko saa olla enintään 16777216 pikseliä, ja merkintäkuva saa olla enintään 40 Mt. JSONissa voi välittää HTTPS-URL:n, PNG base64 data URL:n tai `{ "image_url": "https://..." }`; multipartissa tiedosto ladataan `markup`-kentän kautta. Alusta välittää merkintätason tiedostona. `markup`-asetusta ei voi käyttää yhdessä `mask`-, GIF- tai `prompt_rewriter`-asetuksen kanssa, eikä se tue `file_id`:tä.

`input_fidelity` ei sovellu GPT Image 2.6:een, jätä se pois.
