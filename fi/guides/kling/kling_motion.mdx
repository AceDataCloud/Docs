Tässä artikkelissa esitellään Kling Motion Generation API -integraatio-ohjeet, jonka avulla voidaan syöttää mukautettuja parametreja Klingin virallisten videoiden luomiseksi.

## Hakuprosessi

API:n käyttämiseksi on ensin mentävä [Kling Motion Generation API](https://platform.acedata.cloud/documents/d3f2c369-102d-4856-9565-702ac5f2df63) -sivulle ja haettava vastaavaa palvelua. Sivulle päästyäsi napsauta "Acquire" -painiketta, kuten kuvassa näkyy:

![](https://cdn.acedata.cloud/q6ytrc.png)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Kirjautumisen ja rekisteröitymisen jälkeen palaat automaattisesti nykyiselle sivulle.

Ensimmäisellä hakukerralla saat ilmaisia krediittejä, joiden avulla voit käyttää API:a ilmaiseksi.

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, eli syöttää kehotussana `prompt`, viittauskuva `image_url` sekä viittausvideon linkki `video_url`, jolloin saat käsitellyn tuloksen. Lisäksi meidän on syötettävä malli `mode`, joka on tällä hetkellä pääasiassa `std` ja `pro`, tarkat tiedot ovat seuraavat:

<p><img src="https://cdn.acedata.cloud/5qlpjt.png" width="500" className="m-auto" /></p>

Voit nähdä, että olemme asettaneet Request Headers, mukaan lukien:

- `accept`: haluamasi vastausmuoto, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumiseen tarvittava avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

Lisäksi olemme asettaneet Request Body:n, joka sisältää:

- `image_url`: viittauskuva, josta videoon luotujen henkilöiden, taustojen jne. elementtien on perustuttava.
- `video_url`: viittausvideon hankintalinkki. Videoon luotujen henkilöiden liikkeet ovat samat kuin viittausvideossa.
- `mode`: videon luontitila, pääasiassa standarditila `std` ja nopeustila `pro`.
- `keep_original_sound`: voit valita, säilytetäänkö videon alkuperäinen ääni, arvot: yes, no.
- `character_orientation`: videossa olevien henkilöiden suunta, voit valita kuvan tai videon mukaisesti, arvot: image, video.
- `prompt`: kehotussana.
- `callback_url`: URL, johon tulokset palautetaan.

Valinnan jälkeen voit huomata, että oikealle puolelle on myös luotu vastaava koodi, kuten kuvassa näkyy:

Jos haluat luoda vastaavan integraatiokoodin, voit kopioida sen suoraan, esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/kling/motion' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": "https://sourceyoya.wenge.com/2025/06/03/683e9f76e4b0684509ab1aca.jpg",
  "video_url": "https://cdn.acedata.cloud/odwfm5.mp4",
  "prompt": "让画面生动起来",
  "mode": "std",
  "character_orientation": "image"
}'
```

## Asynkroninen palautus

Koska Kling Motion Generation API:n luominen vie suhteellisen pitkään, noin 1-2 minuuttia, jos API ei vastaa pitkään aikaan, HTTP-pyyntö pitää yhteyden auki, mikä johtaa ylimääräisiin järjestelmäresurssien kulutuksiin. Siksi tämä API tarjoaa myös asynkronisen palautuksen tuen.

Kokonaisprosessi on seuraava: asiakas aloittaa pyynnön, kun hän määrittää ylimääräisen `callback_url` -kentän. Kun asiakas tekee API-pyynnön, API palauttaa heti tuloksen, joka sisältää `task_id` -kentän tiedot, joka edustaa nykyistä tehtävä ID:tä. Kun tehtävä on valmis, luodun videon tulos lähetetään POST JSON -muodossa asiakkaan määrittämään `callback_url` -osoitteeseen, johon sisältyy myös `task_id` -kenttä, jolloin tehtävän tulos voidaan yhdistää ID:n avulla.

Katsotaanpa esimerkin avulla, miten toiminta tapahtuu.

Ensinnäkin, Webhook-palaute on palvelu, joka voi vastaanottaa HTTP-pyyntöjä, ja kehittäjän tulisi korvata se omalla HTTP-palvelimensa URL-osoitteella. Tässä esimerkissä käytämme julkista Webhook-esimerkkisivustoa https://webhook.site/, avaa tämä sivusto saadaksesi Webhook URL:n, kuten kuvassa näkyy:

![](https://cdn.acedata.cloud/tbcnai.png)
Kopioi tämä URL, niin voit käyttää sitä Webhookina, tässä esimerkki on `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Seuraavaksi voimme asettaa kentän `callback_url` yllä olevaan Webhook URL:iin ja täyttää vastaavat parametrit, tarkat tiedot näkyvät kuvassa:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Klikkaa suorita, niin huomaat, että saat heti tuloksen, kuten alla:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Odota hetki, niin voimme tarkkailla generoidun videon tulosta osoitteessa `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, kuten kuvassa näkyy:

![](https://cdn.acedata.cloud/zv5u2q.png)

Sisältö on seuraava:

```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7822108635/text2video/CjJzzGfBfqcAAAAAAKdVMQ-0_raw_video_1.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Voit nähdä, että tuloksessa on `task_id`-kenttä, muut kentät ovat samankaltaisia kuin edellä, tämän kentän avulla voit liittää tehtävät.

## Virheiden käsittely

API:ta kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Valtuuttamaton, virheellinen tai puuttuva valtuutustoken.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
