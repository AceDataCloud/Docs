Tässä artikkelissa esitellään eräs Kling Motion Generation API -integrointiohje. Sen avulla voidaan luoda Klingin virallisia videoita syöttämällä mukautettuja parametreja.

## Hakuprosessi

Jos haluat käyttää Kling Motion Generation API:a, hanki ensin [Ace Data Cloud -konsolista](https://platform.acedata.cloud/console/applications) API Token -avaimesi varalle.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle rekisteröitymään ja kirjautumaan sisään. Kun se on tehty, palaat automaattisesti nykyiselle sivulle.

**Yhdellä API Token -avaimella voit kutsua kaikkia alustan palveluita, eikä jokaista palvelua tarvitse hakea erikseen.** Ensimmäisestä hakemuksesta saa ilmaista saldoa, jolla voi kokeilla palvelua ilmaiseksi; jos saldo ei riitä, voit ladata yleissaldoa [konsolissa](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [Kling Motion Generation API →](https://platform.acedata.cloud/documents/kling-motion)

## Peruskäyttö

Tutustutaan ensin peruskäyttötapaan: syötä kehotussana `prompt`, viitekuva `image_url` sekä viitevideolinkki `video_url`, niin saat käsitellyn tuloksen. Lisäksi tulee syöttää malli `mode`; tällä hetkellä pääasiassa käytettävissä ovat mallit `std` ja `pro`, ja tarkemmat tiedot ovat seuraavat:

<p><img src="https://cdn.acedata.cloud/5qlpjt.png" width="500" className="m-auto" /></p>

Voidaan nähdä, että tässä asetetaan Request Headers, mukaan lukien:

- `accept`: millaisessa muodossa vastaustulos halutaan vastaanottaa. Tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsuavain, jonka voi valita suoraan pudotusvalikosta hakemisen jälkeen.

Lisäksi asetetaan Request Body, mukaan lukien:

- `image_url`: henkilön ulkoasun viitekuvan URL. Tukee JPG/JPEG/PNG-tiedostoja, tiedosto ≤50MB, leveys ja korkeus kumpikin ≥300px, kuvasuhde 1:2.5～2.5:1; henkilön ylävartalon tai koko vartalon ja pään tulee näkyä selkeästi.
- `video_url`: toiminnan viitevideon URL. Tukee MP4/MOV-tiedostoja, tiedosto ≤100MB, leveys ja korkeus kumpikin 340–3850px, vähintään 3 sekuntia; kun `character_orientation=image`, enimmäispituus on 10 sekuntia, ja kun `character_orientation=video`, enimmäispituus on 30 sekuntia. On suositeltavaa käyttää jatkuvaa yhden otoksen videota, jossa henkilö pysyy aina kuvassa.
- `mode`: luodun videon tila. Pääasiassa on kaksi tyyppiä: vakiotila `std` ja erittäin nopea tila `pro`.
- `keep_original_sound`: voidaan valita, säilytetäänkö videon alkuperäinen ääni. Enum-arvot: yes, no.
- `character_orientation`: henkilön suunta luodussa videossa. Voidaan valita kuvan mukaiseksi tai videon mukaiseksi. Enum-arvot: image, video.
- `prompt`: kehotussana.
- `callback_url`: URL, johon tulos pitää palauttaa takaisinsoittona.
- `async`: valinnainen; kun asetetaan arvoksi `true`, rajapinta palauttaa välittömästi `task_id`-arvon ilman, että `callback_url`-arvoa tarvitsee antaa. Tämän jälkeen tulos haetaan kyseisen tehtäväkyselyrajapinnan avulla polling-menetelmällä.

Valinnan jälkeen voidaan havaita, että oikealle luodaan myös vastaava koodi, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/buwczd.png" width="500" className="m-auto" /></p>

Testaus voidaan tehdä napsauttamalla 「Try」-painiketta. Kuten yllä olevassa kuvassa näkyy, saamme seuraavan tuloksen:

```json
{
  "success": true,
  "video_id": "842578800134742051",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "5.066",
  "state": "succeed",
  "task_id": "363c7a84-e880-472e-a4d4-098e50cfc292"
}
```

Palautustuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `success`, videonluontitehtävän tilanne tällä hetkellä.
- `task_id`, videonluontitehtävän ID tällä hetkellä.
- `video_id`, videonluontitehtävän video-ID tällä hetkellä.
- `video_url`, videonluontitehtävän videolinkki tällä hetkellä.
- `duration`, videonluontitehtävän videolinkin kesto tällä hetkellä.
- `state`, videonluontitehtävän tila tällä hetkellä.

Voidaan nähdä, että saimme tyydyttävät videotiedot. Meidän tarvitsee vain hakea luotu Kling-video tuloksessa olevan `data`-kentän videolinkkiosoitteen perusteella.

Lisäksi jos haluat luoda vastaavan integrointikoodin, voit kopioida sen suoraan. Esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/kling/motion' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
  "video_url": "https://cdn.acedata.cloud/odwfm5.mp4",
  "prompt": "让画面生动起来",
  "mode": "std",
  "character_orientation": "image"
}'
```

## Asynkroninen takaisinsoitto

Koska Kling Motion Generation API:n luontiaika on suhteellisen pitkä, noin 1–2 minuuttia, HTTP-pyyntö pysyy jatkuvasti yhdistettynä, jos API ei vastaa pitkään aikaan, mikä aiheuttaa ylimääräistä järjestelmäresurssien kulutusta. Siksi tämä API tukee myös asynkronisia takaisinsoittoja.

Kokonaisprosessi on seuraava: kun asiakas lähettää pyynnön, se määrittää lisäksi `callback_url`-kentän. Kun asiakas lähettää API-pyynnön, API palauttaa välittömästi tuloksen, joka sisältää `task_id`-kentän tiedot ja edustaa nykyisen tehtävän ID:tä. Kun tehtävä on valmis, videonluonnin tulos lähetetään POST JSON -muodossa asiakkaan määrittämään `callback_url`-osoitteeseen. Se sisältää myös `task_id`-kentän, jolloin tehtävän tulos voidaan yhdistää ID:n avulla.

Seuraavaksi tarkastellaan esimerkin avulla, miten toimitaan tarkemmin.

Ensinnäkin Webhook-takaisinsoitto on palvelu, joka voi vastaanottaa HTTP-pyyntöjä. Kehittäjän tulee korvata se itse rakentamansa HTTP-palvelimen URL-osoitteella. Esittelyn helpottamiseksi käytetään tässä julkista Webhook-esimerkkisivustoa https://webhook.site/. Avaamalla tämän sivuston saat Webhook-URL-osoitteen, kuten kuvassa näkyy:

![](https://cdn.acedata.cloud/tbcnai.png)

Kopioi tämä URL-osoite, niin sitä voidaan käyttää Webhookina. Tässä esimerkissä se on `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Seuraavaksi voidaan asettaa kentän `callback_url` arvoksi yllä mainittu Webhook-URL-osoite ja täyttää samalla vastaavat parametrit. Tarkempi sisältö näkyy kuvassa:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Napsauttamalla suorita voidaan havaita, että tulos saadaan välittömästi seuraavasti:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Hetken kuluttua voimme tarkastella luodun videon tulosta osoitteessa `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, kuten kuvassa näkyy:

![](https://cdn.acedata.cloud/zv5u2q.png)

Sisältö on seuraava:
```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Tuloksessa näkyy `task_id`-kenttä, muut kentät ovat samankaltaisia kuin edellä, ja tämän kentän avulla voidaan toteuttaa tehtävien yhdistäminen.

## Virheenkäsittely

API:a kutsuttaessa API palauttaa vastaavan virhekoodin ja tiedot, jos kohdataan virhe. Esimerkiksi:

- `400 token_mismatched`：Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`：Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`：Luvaton, virheellinen tai puuttuva valtuutustunnus.
- `429 too_many_requests`：Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`：Sisäinen palvelinvirhe, palvelimella tapahtui jotain virheellistä.

### Esimerkki virhevastaus

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
