Discord Agent Proxy on **itsenäisesti käyttöönotettava** palvelu: se säilyttää omia Discord-tilisi tunnistetietoja, ylläpitää jatkuvaa yhteyttä Discordiin ja avaa tämän tilin ominaisuudet **MCP**- ja **REST API** -rajapintojen kautta, jotta tekoäly tai ohjelma voi käyttää Discordia puolestasi.

Säiliö **ei sisällä mitään tekoälymallia**, vaan se vastaa ainoastaan suorittamisesta — kutsut käynnistää tekoälyasiakkaasi (Claude, Cursor jne.) tai oma ohjelmasi.

```
AI-asiakas  ──MCP /mcp──┐
                        ├─→ Discord Agent Proxy ──→ Discord
Oma ohjelmasi ──REST /api───┘      (säilyttää tilisi tunnistetiedot)
```

## ⚠️ Lue ennen käyttöä

**Henkilökohtaisen tilin** (self-bot) automatisoitu käyttö ohjelmalla rikkoo Discordin käyttöehtoja, ja tili voi joutua suljetuksi. Tämä on palvelun olennainen edellytys: annat omat tilisi tunnistetiedot ja kannat riskin itse.

**Suosittelemme vahvasti käyttämään erillistä sivutiliä äläkä käytä päätiliäsi.**

## Palvelun käyttöönotto

Siirry kohtaan [Hallintapaneeli → Sovellukset](https://platform.acedata.cloud/console/applications), etsi Discord Agent Proxy ja luo sovellus. Ota tilaus käyttöön luomisen jälkeen, siirry sitten asetussivulle, täytä Discord-tilisi tunnistetiedot ja ota palvelu käyttöön. Alusta määrittää instanssiresurssit automaattisesti, eikä määrityksiä tarvitse valita.

Käyttöönoton lähettämisen jälkeen siirryt sovellushallintasivulle, jossa käytetään samaa ”Yleiskatsaus / Lokit / Dokumentaatio” -asettelua kuin Telegram- ja WeChat-käyttöönotossa. ”Yleiskatsaus” näyttää instanssin ja tilauksen tilan sekä vahvistaa Discord-yhteyden tilikyselyn avulla; säiliön normaali toiminta ei tarkoita, että tili olisi välttämättä yhdistetty.

”Yleiskatsauksen” Discord-tilikortti tarjoaa kaksi liittymistietoa:

| Kohde       | Esimerkki                                                       | Käyttötarkoitus         |
| -------- | -------------------------------------------------------- | ---------- |
| MCP-liittymisosoite | `https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/mcp` | Määritetään AI-asiakkaaseen |
| Käyttöoikeustunnus     | `V0p7kAWY...`                                            | Autentikointiin, katso alla     |

### Rajapintojen tarkastelu ja testaus hallintapaneelissa

Avaa tämän sovelluksen ”Dokumentaatio”-välilehti nähdäksesi kaikkien 14 REST-toiminnon pyyntöparametrit, vastausrakenteet sekä esimerkit Shell-, Python-, JavaScript- ja muilla kielillä. Instanssin osoite ja käyttöoikeustunnus täytetään automaattisesti; tunnus on oletusarvoisesti piilotettu.

Valitse `GET /api/whoami` ja napsauta ”Testaa” vahvistaaksesi välityspalvelimen yhdistetyn tilin. Lähetys-, muokkaus- tai viestien poistotoiminnot vaikuttavat oikeaan Discord-tiliin, joten varmista pyynnön sisältö ennen testaamista.

”Lataa OpenAPI (JSON)” mahdollistaa täydellisen rajapintamäärittelyn viennin. Tiedosto sisältää instanssin osoitteen, mutta ei käyttöoikeustunnusta. Jos sinun on vaihdettava Discord-tilin tunnistetiedot, valitse ”Yleiskatsauksessa” ”Ota käyttöön uudelleen”, täytä uudet tunnistetiedot ja lähetä.

### Discord-tilin tunnistetietojen hakeminen

1. Kirjaudu Discordiin tietokoneen selaimella ([discord.com/app](https://discord.com/app))
2. Avaa kehittäjätyökalut painamalla `F12` ja vaihda **Network (Verkko)** -paneeliin
3. Napsauta Discordissa mitä tahansa kanavaa ja tarkkaile pyyntöluetteloa
4. Avaa mikä tahansa pyyntö, joka lähetetään osoitteeseen `discord.com/api`, ja etsi **Request Headers (Pyyntöotsakkeet)** -kohdasta `authorization`-kenttä
5. Kopioi sen arvo

Tämä tunnistetietojono vastaa tilisi kirjautumisistuntoa, **älä jaa sitä kenellekään**. Jos se vuotaa, salasanan vaihtaminen Discordissa mitätöi sen välittömästi.

## Autentikointitapa

Kaikki rajapinnat lukuun ottamatta `/health`- ja `/readyz`-rajapintoja edellyttävät käyttöoikeustunnuksen sisällyttämistä **pyyntöotsakkeeseen**:

```
Authorization: Bearer <käyttöoikeustunnuksesi>
```

> **Huomautus: Tämä palvelu hyväksyy vain pyyntöotsakeautentikoinnin eikä tue tapaa, jossa tunnus liitetään URL-osoitteen loppuun muodossa `?token=xxx`.** Rajapinnan osoitteen avaaminen suoraan selaimessa palauttaa `401 unauthorized` -vastauksen; tämä on normaalia eikä tarkoita, että käyttöönotto olisi epäonnistunut. Jos haluat varmistaa, että prosessi on käynnissä, käytä `/health`-osoitetta; jos haluat varmistaa, että Discord-yhteys pystyy käsittelemään pyyntöjä, käytä `/readyz`-osoitetta. Kumpikaan näistä tarkistuksista ei edellytä autentikointia. Kun välityspalvelimen käyttöoikeustunnusta ei ole määritetty, suojatut rajapinnat palauttavat `503`-vastauksen eivätkä ole avoinna anonyymisti.

## Palvelun tilan tarkistaminen

```bash
curl https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/health
curl https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/readyz
```

`/health` tarkoittaa vain, että HTTP-prosessi on käynnissä:

```json
{ "status": "ok" }
```

`/readyz` ilmaisee, onko Discord Gateway käytettävissä. Kun yhteys toimii normaalisti, se palauttaa HTTP 200:

```json
{ "status": "ready", "gateway_ready": true }
```

Kun yhteyttä muodostetaan, tunnistetiedot ovat virheelliset tai yhteys katkeaa, Kubernetesin suora Pod-tarkistus palauttaa HTTP 503 -vastauksen, ja instanssin taustajärjestelmä yrittää automaattisesti uudelleen. Tällöin Pod poistetaan tilapäisesti julkisesta Servicestä, joten tämän diagnostiikka-JSONin lukemista instanssin verkkotunnuksen kautta ei voida taata; tarkista Deploymentin tila hallintapaneelissa ja kutsu MCP / REST -rajapintoja vasta Ready-tilan palautumisen jälkeen.

## Käyttö AI-asiakkaassa (MCP)

Esimerkkinä Claude Code:

```bash
claude mcp add --transport http discord \
  https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/mcp \
  --header "Authorization: Bearer <käyttöoikeustunnuksesi>"
```

Cursorin ja muiden staattisia pyyntöotsakkeita tukevien asiakkaiden osalta määritä Streamable HTTP -osoite niiden nykyisen dokumentaation mukaisesti. Seuraavan rakenteen hyväksyvät asiakkaat voivat käyttää:

```json
{
  "mcpServers": {
    "discord": {
      "type": "http",
      "url": "https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/mcp",
      "headers": {
        "Authorization": "Bearer <käyttöoikeustunnuksesi>"
      }
    }
  }
}
```

Tämä ei ole yleinen määritysmuoto kaikille MCP-asiakkaille. Claude Desktopin / Claude.ai:n etäliitin muodostetaan pilvestä, eikä se lue mitään HTTP-pyyntöotsakkeita paikallisesta `claude_desktop_config.json`-tiedostosta; jos tarvitset tällä hetkellä staattisen Bearer-pyyntöotsakkeen, käytä Claude Codea tai asiakasta, joka nimenomaisesti tukee tätä ominaisuutta.

Kun määritys on valmis, voit ohjata tekoälyä käyttämään Discordia suoraan luonnollisella kielellä, esimerkiksi:

> Katso, onko minulla uusia viestejä ”Projektikeskustelu”-kanavalla, ja jos joku kysyy julkaisupäivästä, auta minua vastaamaan, että se on tänä perjantaina.

## Käyttö ohjelmassa (REST API)

Kaikki REST-rajapinnat sijaitsevat polun `/api` alla, ja vastausrungon muoto on yhtenäisesti `{"data": ...}`; virhetilanteessa se on `{"error": "..."}`.

### Nykyisen tilin tarkastelu

```bash
curl https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/api/whoami \
  -H "Authorization: Bearer <你的访问令牌>"
```

### Viestin lähettäminen

```bash
curl -X POST https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/api/messages \
  -H "Authorization: Bearer <你的访问令牌>" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: <本次发送的唯一操作 ID>" \
  -d '{"channel_id": "1234567890", "content": "你好"}'
```

Kun yrität uudelleen samaa lähetystä, käytä samaa `Idempotency-Key`-avainta; prosessi palauttaa ensimmäisen tuloksen lähettämättä viestiä uudelleen. Instanssin uudelleenkäynnistys tyhjentää enintään 5 000 muistitietuetta sisältävän duplikoinninestotietueen, joten kutsujan on silti itse seurattava pitkän aikavälin toimitustilaa.

Valinnainen parametri `reply_to` on tarkoitettu vastaamiseen määritettyyn viestiin:

```json
{ "channel_id": "1234567890", "content": "收到", "reply_to": "9876543210" }
```

### Viestien lukeminen

```bash
curl "https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/api/channels/1234567890/messages?limit=20" \
  -H "Authorization: Bearer <你的访问令牌>"
```

### Täydellinen rajapintaluettelo

| Menetelmä ja polku                                                   | Parametrit                         | Toiminto     |
| --------------------------------------------------------------------- | ---------------------------------- | ------------ |
| `GET /api/whoami`                                                    | —                                  | Nykyisen agentin tilitiedot |
| `GET /api/guilds`                                                    | —                                  | Luettelo palvelimista, joihin tili on liittynyt |
| `GET /api/guilds/{guild_id}/channels`                                | —                                  | Palvelimen kanavaluettelo |
| `POST /api/guilds/{guild_id}/channels`                               | `{name}`                           | Luo tekstikanava |

### Kanavatunnuksen ja käyttäjätunnuksen hankkiminen

Avaa Discord-asiakasohjelmassa järjestyksessä **Käyttäjäasetukset → Lisäasetukset** ja ota käyttöön **Kehittäjätila**. Napsauta sen jälkeen hiiren oikealla painikkeella mitä tahansa kanavaa tai käyttäjää; valikossa näkyy kohta ”Kopioi tunnus”.

Voit myös kutsua suoraan `GET /api/guilds` ja `GET /api/guilds/{guild_id}/channels` luettelointia varten.

## Usein kysytyt kysymykset

**Palauttaa `401 unauthorized`**

Käyttöoikeustunnus on virheellinen tai se välitettiin käyttäen tapaa `?token=`. Varmista, että tunnus välitetään pyyntöotsikon `Authorization: Bearer <tunnus>` kautta ja että se vastaa konsolissa näkyvää tunnusta.

**Palauttaa `503`**

Yhteyttä Discordiin ei ole vielä muodostettu. Avaa ensin `/readyz` tarkistaaksesi `gateway_ready`-arvon; jos se on pitkään `false`, tilin tunnistetiedot ovat todennäköisesti vanhentuneet. Hanki ne uudelleen ja ota käyttöön uudelleen.

**Palauttaa `403` tai `404`**

Tilillä ei itsellään ole vastaavaa oikeutta (esimerkiksi se ei ole kyseisellä palvelimella tai sillä ei ole oikeutta puhua kyseisellä kanavalla), tai tunnus on täytetty väärin. Tällaiset virheet tulevat Discordilta eivätkä ole välityspalvelun ongelma.

**Palauttaa `429`**

Discordin nopeusrajoitus on lauennut; vastauksen kenttä `retry_after` antaa suositellun odotusajan sekunteina. Vähennä kutsutiheyttä.

**Tili suljetaan viestien lähettämisen jälkeen**

Kuten edellä mainittiin, henkilökohtaisten tilien automatisoitu käyttö rikkoo Discordin käyttöehtoja. Käytä erityistä sivutiliä ja hallitse toimintatiheyttä sekä vältä arkaluonteista toimintaa, kuten joukkolähetyksiä.

## Vahvistuksen laajuus

Tuotannon smoke-testissä 1. elokuuta 2026 käytettiin erityistä tiliä tilin, palvelinten, kanavien, jäsenten, viestien lukemisen, haun, lähettämisen, muokkaamisen, reaktioiden ja poistamisen varmistamiseen. Automaattiset testit kattavat todennuksen, parametrien validoinnin, virhekartoituksen ja nykyisten riippuvuuskirjastojen allekirjoitukset; smoke-testi on silti suoritettava uudelleen worker- tai chart-muutosten jälkeen, eikä historiallista vahvistusta voi pitää todisteena jatkuvasta käytettävyydestä.
