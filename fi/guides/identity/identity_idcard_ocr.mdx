Tässä artikkelissa esitellään henkilökortin tunnistus ja tietojen tarkistus API -liitännäsohjeet, joka voi tarkistaa nimen ja henkilökortin numeron aitouden ja yhdenmukaisuuden syöttämällä henkilökortin kuvan tai nimen ja henkilökortin numeron. Tämä rajapinta on tarkoitettu nimen ja henkilökortin numeron aitouden ja yhdenmukaisuuden tarkistamiseen, ja voit syöttää nimen ja henkilökortin numeron tai toimittaa tarvittavat tarkistustiedot henkilökortin kasvokuvan avulla.

## Hakuprosessi

Käyttääksesi henkilökortin tunnistus ja tietojen tarkistus API:a, sinun on ensin mentävä [Ace Data Cloud -hallintapaneeliin](https://platform.acedata.cloud/console/applications) saadaksesi API-tunnuksesi, jota voit säilyttää varalla.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään, ja sen jälkeen sinut ohjataan takaisin nykyiselle sivulle.

**Yksi API-tunnus riittää kaikkien palveluiden kutsumiseen, eikä jokaiselle palvelulle tarvitse hakea erikseen.** Ensimmäisestä hakemuksesta saat ilmaisen määrän, jonka avulla voit kokeilla palvelua ilmaiseksi; jos määrä loppuu, voit ladata yleistä saldoa [hallintapaneelista](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [Henkilökortin tunnistus ja tietojen tarkistus API →](https://platform.acedata.cloud/documents/identity-idcard-ocr)

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, eli syöttämällä henkilökortin kuvalinkki, voit saada käsitellyn tarkistustuloksen. Ensinnäkin sinun on yksinkertaisesti välitettävä `image_url`-kenttä, ja voimme seuraavaksi täyttää vastaavat tiedot käyttöliittymässä, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/qxy9rh.png" width="500" className="m-auto" /></p>

Voit nähdä, että olemme asettaneet pyyntöotsikot, mukaan lukien:

- `accept`: haluamasi vastausmuoto, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumiseen käytettävä avain, jonka voit valita suoraan alasvetovalikosta hakemuksen jälkeen.

Lisäksi on asetettu pyyntökeho, joka sisältää:

- `image_url`: käsiteltävän henkilökortin kuvalinkki.
- `encryption`: valinnainen, arkaluontoisten kenttien salausparametri (jos salattua tietoa on lähetettävä).

Valinnan jälkeen voit huomata, että oikealla puolella on myös luotu vastaava koodi, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/uw90il.png" width="500" className="m-auto" /></p>

Napsauttamalla "Kokeile" -painiketta voit testata, kuten yllä olevassa kuvassa näkyy, ja saamme seuraavat tulokset:

```json
{
  "result": "0",
  "description": "Nimi ja henkilökortin numero ovat yhdenmukaisia",
  "name": "Henkilökortin nimi",
  "id_card": "Henkilökortin numero",
  "sex": "Henkilökortin sukupuoli",
  "nation": "Henkilökortin kansallisuus",
  "birth": "Henkilökortin syntymäaika",
  "address": "Henkilökortin kotiosoite"
}
```

Palautetussa tuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `result`, varmennustuloksen koodi, maksutilanne seuraavasti.
    - Maksulliset tuloskoodit:
        - 0: Nimi ja henkilökortin numero ovat yhdenmukaisia
        - -1: Nimi ja henkilökortin numero eivät ole yhdenmukaisia
    - Ilmaismaksulliset tuloskoodit:
        - -2: Laillinen henkilökortin numero (pituus, tarkistussumma jne. ei ole oikein)
        - -3: Laillinen nimi (pituus, muoto jne. ei ole oikein)
        - -4: Asiakirjatietokannan palveluhäiriö
        - -5: Asiakirjatietokannassa ei ole tätä henkilökortin tietoa
        - -6: Auktorisoitu vertailujärjestelmä on päivityksessä, yritä myöhemmin uudelleen
        - -7: Varmennuskerroin ylittää päivittäisen rajan.
- `description`, tässä on nimen ja henkilökortin numeron tarkistustulos.
- `name`, henkilökortissa oleva nimitieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `id_card`, henkilökortissa oleva henkilökortin numerotieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `sex`, henkilökortissa oleva sukupuolitieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `nation`, henkilökortissa oleva kansallisuustieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `birth`, henkilökortissa oleva syntymäaikatieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `address`, henkilökortissa oleva kotiosoitteen tieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.

Voimme nähdä, että henkilökortin nimi ja henkilökortin numeron tiedot ovat yhdenmukaisia ja voimassa, ja samalla on käytetty OCR-tekniikkaa muiden tietojen erottamiseen ja esittämiseen.

Lisäksi, jos haluat luoda vastaavan liitännäskoodin, voit suoraan kopioida sen, esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/identity/idcard/ocr' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": {image_url}
}'
```

Pythonin liitännäskoodi on seuraava:

```python
import requests

url = "https://api.acedata.cloud/identity/idcard/ocr"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "image_url": {image_url}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Mukautettu tietojen tarkistus

Tarjoamme myös tavan tarkistaa ilman henkilökortin kuvatietojen paljastamista, voit vain syöttää nimen `name` ja henkilökortin numeron `id_card` tarkistaaksesi nimen ja henkilökortin numeron aitouden ja yhdenmukaisuuden. Alla on täytetyt tarkat tiedot:

<p><img src="https://cdn.acedata.cloud/mc5bbw.png" width="500" className="m-auto" /></p>

Napsauttamalla suorita saat seuraavat tulokset:

```json
{
    "address": "",
    "birth": "",
    "description": "Nimi ja henkilökortin numero ovat yhdenmukaisia",
    "id_card": "Henkilökortin numero",
    "name": "Henkilökortin nimi",
    "nation": "",
    "result": "0",
    "sex": ""
 }
```

Näin tuloksesta ei paljastu muita yksityistietoja, ja tämä voi myös suorittaa nimen ja henkilökortin numeron aitouden ja yhdenmukaisuuden tarkistuksen.

## Virheiden käsittely

API:a kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Valtuuttamaton, virheellinen tai puuttuva valtuutustunnus.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajan.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
