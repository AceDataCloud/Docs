Tässä artikkelissa esitellään henkilötietojen ja voimassaolon tarkistuksen API-liitännäisen ohjeet, jota voidaan käyttää nimen, henkilökortin numeron ja henkilökortin voimassaolon aitouden ja yhdenmukaisuuden tarkistamiseen.

## Hakuprosessi

API:n käyttämiseksi sinun on ensin mentävä [henkilötietojen ja voimassaolon tarkistuksen API](https://platform.acedata.cloud/documents/667017a4-017f-4af0-870e-807034f70632) -sivulle ja haettava vastaavaa palvelua. Sivulle päästyäsi napsauta "Acquire" -painiketta, kuten kuvassa näkyy:

![](https://cdn.acedata.cloud/q6ytrc.png)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Kirjautumisen ja rekisteröitymisen jälkeen palaat automaattisesti nykyiselle sivulle.

Ensimmäisellä hakemiskerralla saat ilmaisia käyttöoikeuksia, joiden avulla voit käyttää tätä API:a ilmaiseksi.

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, eli syöttää henkilökortin kuvalinkki, jolloin saat käsittelyn jälkeen vahvistustuloksen. Ensinnäkin sinun on yksinkertaisesti välitettävä `name`-kenttä, ja voimme seuraavaksi täyttää vastaavat tiedot käyttöliittymässä, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/llvy1l.png" width="500" class="m-auto"></p>

Voit nähdä, että olemme asettaneet pyyntöotsikot, mukaan lukien:

- `accept`: haluamasi vastausmuoto, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumiseen käytettävä avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

Lisäksi on asetettu pyyntökeho, joka sisältää:

- `name`: Nimi.
- `id_card`: Henkilökortin numero.
- `image_url`: Käsiteltävän kasvokuvan linkki.
- `validity_end`: Henkilökortin voimassaolon päättymispäivämäärä, muoto: YYYYMMDD, pitkäaikaiselle käytölle käytä "00000000";
- `validity_begin`: Henkilökortin voimassaolon alkamispäivämäärä, muoto: YYYYMMDD.
- `encryption`: valinnainen, arkaluontoisten kenttien salausparametri (jos salattua tietoa on lähetettävä).

Valinnan jälkeen voit huomata, että oikealle puolelle on myös luotu vastaava koodi, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/l77q0u.png" width="500" class="m-auto"></p>

Napsauta "Try" -painiketta, niin voit testata, kuten yllä olevassa kuvassa näkyy, ja saamme seuraavanlaisen tuloksen:

```json
{
  "result": "0",
  "description": "yhteensopiva"
}
```

Palautetussa tuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `result`, vahvistustuloksen koodi, maksutilanne seuraavasti.
  - Maksulliset tuloskoodit:
    - 0: Nimi ja henkilökortin numero ovat yhteensopivia
    - -1: Nimi ja henkilökortin numero eivät ole yhteensopivia
  - Ilmaiset tuloskoodit:
    - -2: Laillinen henkilökortin numero (pituus, tarkistussumma jne. ei ole oikein)
    - -3: Laillinen nimi (pituus, muoto jne. ei ole oikein)
    - -4: Asiakirjatietokannan palveluhäiriö
    - -5: Asiakirjatietokannassa ei ole tätä henkilökortin tietoa
    - -6: Auktorisoitu vertailujärjestelmä on päivityksessä, yritä myöhemmin uudelleen
    - -7: Vahvistuskertojen määrä ylittää päivittäisen rajan.
- `description`, tässä on nimen ja henkilökortin numeron vahvistustulos.

Voit nähdä, että henkilökortissa nimi, henkilökortin numero ja voimassaoloaika ovat aitoja ja yhdenmukaisia.

Jos haluat luoda vastaavan liitännäiskoodin, voit kopioida sen suoraan, esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/identity/idcard/check-2e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "id_card": "***",
  "validity_begin": "***",
  "validity_end": "***"
}'
```

Pythonin liitännäiskoodi on seuraava:

```python
import requests

url = "https://api.acedata.cloud/identity/idcard/check-2e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "name": "***",
    "id_card": "***",
    "validity_begin": "***",
    "validity_end": "***"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Virheiden käsittely

API:a kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Ei valtuutettu, virheellinen tai puuttuva valtuutusavain.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
