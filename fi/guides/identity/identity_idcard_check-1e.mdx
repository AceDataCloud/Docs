Tässä artikkelissa esitellään henkilökortin valokuvan todentamis-API:n integrointiohjeet, jota voidaan käyttää henkilökortin valokuvan syöttämiseen, henkilökortin valokuvassa olevien tietojen tunnistamiseen sekä nimen, henkilökorttinumeron ja henkilökortin valokuvan vertailuun auktorisoidun tietokannan henkilöllisyystodistusten kanssa, jotta voidaan todentaa henkilökortin tietojen aitous.

## Hakuprosessi

Käyttääksesi henkilökortin valokuvan todentamis-API:a, sinun on ensin mentävä [Ace Data Cloud -hallintapaneeliin](https://platform.acedata.cloud/console/applications) saadaksesi API-tunnuksesi, jota voit säilyttää varalla.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään, ja sen jälkeen sinut ohjataan takaisin nykyiselle sivulle.

**Yksi API-tunnus riittää kaikkien palveluiden kutsumiseen, eikä jokaiselle palvelulle tarvitse hakea erikseen.** Ensimmäisestä hakemuksesta saat ilmaisen käyttöoikeuden, jonka avulla voit kokeilla palvelua ilmaiseksi; jos käyttöoikeus loppuu, voit ladata yleistä saldoa [hallintapaneelista](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [Henkilökortin valokuvan todentamis-API →](https://platform.acedata.cloud/documents/identity-idcard-check-1e)

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, eli syöttää henkilökortin kuvalinkki, jolloin saat käsittelyn jälkeen vahvistustuloksen. Ensinnäkin sinun on yksinkertaisesti välitettävä `image_url`-kenttä, jonka jälkeen voimme täyttää vastaavat tiedot käyttöliittymässä, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/zjxg3k.png" width="500" className="m-auto" /></p>

Voit nähdä, että olemme asettaneet pyyntöotsikot, mukaan lukien:

- `accept`: haluamasi vastausmuoto, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumiseen käytettävä avain, jonka voit valita suoraan alasvetovalikosta hakemuksen jälkeen.

Lisäksi on asetettu pyyntökeho, joka sisältää:

- `image_url`: käsiteltävän henkilökortin kuvalinkki.
- `config`: valinnainen asetuskohde, totuusarvokenttä, oletusarvoisesti kaikki false, tukee `copy_warn`, `border_check_warn`, `reshoot_warn`, `detect_ps_warn`, `temp_id_warn`, `quality` (kynnysarvo 0-100).

Valinnan jälkeen voit huomata, että oikealla puolella on myös luotu vastaava koodi, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/4yh23p.png" width="500" className="m-auto" /></p>

Napsauta "Kokeile"-painiketta, niin voit testata, kuten yllä olevassa kuvassa näkyy, ja saamme seuraavat tulokset:

```json
{
  "sim": 99.76,
  "result": "Success",
  "description": "Onnistui",
  "name": "Henkilökortin nimi",
  "sex": "Henkilökortin sukupuoli",
  "nation": "Henkilökortin kansallisuus",
  "birth": "Henkilökortin syntymäaika",
  "address": "Henkilökortin kotiosoite",
  "id_num": "Henkilökortin numero",
  "portrait": "/9j/4AAQSkZJRgABAQAAAQABAAD/2wBDAAEBAQEBAQEBAQEBAQEBAQEBAQEBA.....DEhE2lbPMcOtG3f/DLT/yX8if7Kxn/AD7h85wdttPifRf1e6//2Q==",
  "warnings": "",
  "quality": 0,
  "encryption": null
}
```

Palautetussa tuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `sim`, samankaltaisuus, arvoalue [0.00, 100.00]. Suositellaan, että samankaltaisuus on vähintään 70, jotta voidaan arvioida, että kyseessä on sama henkilö; voit säätää kynnysarvoa tarpeen mukaan (kynnysarvon 70 virheellisten hyväksymisprosentti on tuhannesosa, kynnysarvon 80 virheellisten hyväksymisprosentti on kymmenestuhannesosa).
- `result`, liiketoimintavirhekoodi, onnistuneessa tapauksessa palauttaa Success, virhetilanteissa katso alla olevaa virhekoodiluetteloa FailedOperation-osiossa.
- `description`, tässä on nimen ja henkilökorttinumeron vahvistustulos.
- `name`, henkilökortissa oleva nimitieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `sex`, henkilökortissa oleva sukupuolitieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `nation`, henkilökortissa oleva kansallisuustieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `birth`, henkilökortissa oleva syntymäaikatieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `address`, henkilökortissa oleva kotiosoitteen tieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `id_num`, henkilökortissa oleva henkilökorttinumerotieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `portrait`, henkilökortin valokuvan base64-koodaus, jos kuvasta ei saada onnistuneesti leikattua, verrataan koko henkilökorttia ja palautetaan tyhjää.
- `warnings`, varoitustiedot, kun Configissa on määritetty varoitustiedot, henkilön vertailu keskeytetään, ja tulos palauttaa virheen (FailedOperation.OcrWarningOccurred) ja sisältää tämän varoitustiedon.
- `quality`, kuvan laatuarvosana, kun pyyntö Configissa on määritetty kuvan sumeusvaroitus, tämä parametri on merkityksellinen, arvoalue (0–100), tällä hetkellä oletuskynnys on 50 pistettä, alle 50 pistettä laukaisee sumeusvaroituksen.
- `encryption`, arkaluontoisten tietojen salausinformaatio.

On havaittavissa, että henkilökortin tiedot ovat erittäin aitoja.

Jos haluat luoda vastaavan integrointikoodin, voit kopioida sen suoraan, esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/identity/idcard/check-1e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": {image_url}
}'
```

Pythonin integrointikoodi on seuraava:

```python
import requests

url = "https://api.acedata.cloud/identity/idcard/check-1e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "image_url": {image_url}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Virheiden käsittely

API:a kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Valtuuttamaton, virheellinen tai puuttuva valtuutustunnus.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
