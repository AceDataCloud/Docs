Tässä artikkelissa esitellään henkilökortin valokuvan todentamis-API:n integrointiohjeet, jota voidaan käyttää henkilökortin valokuvan syöttämiseen, henkilökortin valokuvassa olevien tietojen tunnistamiseen sekä nimen, henkilökorttinumeron ja henkilökortin valokuvan vertailuun auktorisoidun tietokannan valokuvien kanssa, jotta voidaan todentaa, onko kyseessä sama henkilö ja siten vahvistaa henkilökortin tietojen aitous.

## Hakuprosessi

API:n käyttämiseksi sinun on ensin mentävä [henkilökortin valokuvan todentamis-API:n](https://platform.acedata.cloud/documents/7a3f14f7-f1eb-41c2-816c-9f18caca6883) vastaavalle sivulle ja haettava tarvittavaa palvelua. Sivulle päästyäsi napsauta "Acquire"-painiketta, kuten kuvassa on esitetty:

![](https://cdn.acedata.cloud/q6ytrc.png)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Kirjautumisen ja rekisteröitymisen jälkeen palaat automaattisesti nykyiselle sivulle.

Ensimmäisellä hakemiskerralla saat ilmaisia käyttöoikeuksia, joiden avulla voit käyttää tätä API:a ilmaiseksi.

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, joka on syöttää henkilökortin kuvalinkki, jolloin saat käsittelyn jälkeen vahvistustuloksen. Ensimmäiseksi sinun on yksinkertaisesti välitettävä `image_url`-kenttä, ja voimme seuraavaksi täyttää vastaavat tiedot käyttöliittymässä, kuten kuvassa on esitetty:

<p><img src="https://cdn.acedata.cloud/zjxg3k.png" width="500" className="m-auto" /></p>

Voit nähdä, että olemme asettaneet pyyntöotsikot, mukaan lukien:

- `accept`: haluamasi vastausmuoto, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumiseen käytettävä avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

Lisäksi on asetettu pyyntökeho, joka sisältää:

- `image_url`: käsiteltävän henkilökortin kuvalinkki.
- `config`: valinnainen asetuskohde, totuusarvo, oletuksena kaikki ovat false, tukee `copy_warn`, `border_check_warn`, `reshoot_warn`, `detect_ps_warn`, `temp_id_warn`, `quality` (kynnysarvo 0-100).

Valinnan jälkeen voit huomata, että oikealle puolelle on myös luotu vastaava koodi, kuten kuvassa on esitetty:

<p><img src="https://cdn.acedata.cloud/4yh23p.png" width="500" className="m-auto" /></p>

Napsauta "Try"-painiketta, niin voit testata, kuten yllä olevassa kuvassa on esitetty, ja saamme seuraavat tulokset:

```json
{
  "sim": 99.76,
  "result": "Success",
  "description": "Onnistui",
  "name": "Henkilökortin nimi",
  "sex": "Henkilökortin sukupuoli",
  "nation": "Henkilökortin kansallisuus",
  "birth": "Henkilökortin syntymäaika",
  "address": "Henkilökortin osoite",
  "id_num": "Henkilökortin numero",
  "portrait": "/9j/4AAQSkZJRgABAQAAAQABAAD/2wBDAAEBAQEBAQEBAQEBAQEBAQEBAQEBA.....DEhE2lbPMcOtG3f/DLT/yX8if7Kxn/AD7h85wdttPifRf1e6//2Q==",
  "warnings": "",
  "quality": 0,
  "encryption": null
}
```

Palautetussa tuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `sim`, samankaltaisuus, arvoalue [0.00, 100.00]. Suositellaan, että samankaltaisuus on vähintään 70, jotta voidaan arvioida, että kyseessä on sama henkilö. Voit säätää kynnysarvoa tarpeen mukaan (kynnysarvon 70 virheellisten hyväksymisprosentti on tuhannesosa, kynnysarvon 80 virheellisten hyväksymisprosentti on kymmenesosa).
- `result`, liiketoimintavirhekoodi, onnistuneessa tapauksessa palauttaa Success, virhetilanteissa katso alla olevasta virhekoodiluettelosta FailedOperation-osio.
- `description`, tässä on nimen ja henkilökorttinumeron vahvistustulos.
- `name`, henkilökortissa oleva nimitieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `sex`, henkilökortissa oleva sukupuolitieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `nation`, henkilökortissa oleva kansallisuustieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `birth`, henkilökortissa oleva syntymäaikatieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `address`, henkilökortissa oleva osoitetieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `id_num`, henkilökortissa oleva henkilökorttinumerotieto, jos henkilökortin kuvaa ei ole ladattu, se on tyhjää.
- `portrait`, henkilökortin valokuvan base64-koodaus, jos kuvasta ei saada onnistuneesti leikattua, verrataan koko henkilökorttia ja palautetaan tyhjää.
- `warnings`, varoitustiedot, kun Configissa on määritetty varoitustiedot, henkilön vertailu keskeytetään, ja Result palauttaa virheen (FailedOperation.OcrWarningOccurred) ja sisältää tämän varoitustiedon.
- `quality`, kuvan laatupisteet, kun pyyntö Configissa on määritetty kuvan sumeusvaroitus, tämä parametri on merkityksellinen, arvoalue (0–100), tällä hetkellä oletuskynnys on 50 pistettä, alle 50 pistettä laukaisee sumeusvaroituksen.
- `encryption`, arkaluontoisten tietojen salausinformaatio.

Voit nähdä, että henkilökorttitiedot ovat erittäin aitoja.

Jos haluat luoda vastaavan integrointikoodin, voit kopioida sen suoraan, esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/identity/idcard/check-1e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": {image_url}
}'
```

Pythonin integrointikoodi on seuraava:

```python
import requests

url = "https://api.acedata.cloud/identity/idcard/check-1e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "image_url": {image_url}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Virheiden käsittely

API:a kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Ei valtuutettu, virheellinen tai puuttuva valtuutusavain.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
