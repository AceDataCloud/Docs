Tässä artikkelissa esitellään puhelinnumeron kolmen elementin tarkistus API -liittymän ohjeet, jota voidaan käyttää puhelinnumeron, nimen ja henkilökortin numeron aitouden ja yhdenmukaisuuden tarkistamiseen.

## Hakuprosessi

API:n käyttämiseksi sinun on ensin mentävä [puhelinnumeron kolmen elementin tarkistus API](https://platform.acedata.cloud/documents/b4c50108-dda5-4ddb-ba84-776060fb0151) -sivulle ja haettava vastaavaa palvelua. Sivulle päästyäsi napsauta "Acquire" -painiketta, kuten kuvassa näkyy:

![](https://cdn.acedata.cloud/q6ytrc.png)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Kirjautumisen ja rekisteröitymisen jälkeen palaat automaattisesti nykyiselle sivulle.

Ensimmäisellä hakukerralla saat ilmaisia käyttöoikeuksia, ja voit käyttää tätä API:ta ilmaiseksi.

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, eli syöttämällä puhelinnumero saat käsitellyn tuloksen. Ensimmäiseksi sinun on yksinkertaisesti välitettävä `phone`-kenttä. Voimme seuraavaksi täyttää vastaavat tiedot käyttöliittymässä, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/3xbffj.png" width="500" className="m-auto" /></p>

Voit nähdä, että olemme asettaneet Request Headers, mukaan lukien:

- `accept`: haluamasi vastausmuoto, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumiseen käytettävä avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

Lisäksi on asetettu Request Body, mukaan lukien:

- `name`: käsiteltävän käyttäjän nimi, pakollinen parametri.
- `phone`: käsiteltävä puhelinnumero, pakollinen parametri.
- `id_card`: käsiteltävän käyttäjän henkilökortin numero, pakollinen parametri.
- `verify_mode`: tarkistusmuoto (pitkä/lyhyt).
- `encrypt_list`/`ciphertext_blob`/`iv`: valinnaiset salausparametrit, salaa tarvittaessa arkaluontoiset kentät.

Valinnan jälkeen voit huomata, että oikealla puolella on myös luotu vastaava koodi, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/0cp9z1.png" width="500" className="m-auto" /></p>

Napsauta "Try" -painiketta, jotta voit testata, kuten yllä olevassa kuvassa näkyy, ja saamme seuraavan tuloksen:

```json
{
  "result": "0",
  "description": "Todennus hyväksytty",
  "isp": "Mobiili",
  "result_detail": null
}
```

Palautetussa tuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `result`, todennustuloskoodi, maksutilanne seuraavasti.
  - Maksulliset tuloskoodit:
    - 0: Vahvistustulos on yhdenmukainen
    - 1: Vahvistustulos ei ole yhdenmukainen
  - Ilmaiset tuloskoodit:
    - -1: Ei tietoja
    - -2: Moottorin tuntematon virhe
    - -3: Moottorin palveluvirhe
    - -4: Nimen tarkistus ei läpäissyt
    - -5: Puhelinnumero ei ole laillinen
    - -6: Vahvistuskerrat ylittävät päivittäisen rajan, yritä uudelleen seuraavana päivänä
- `description`, liiketoimintatuloksen kuvaus.

Voit nähdä, että puhelinnumeron, nimen ja henkilökortin numeron aitouden ja yhdenmukaisuuden tiedot on jo tarkistettu.

Lisäksi, jos haluat luoda vastaavan liittymiskoodin, voit suoraan kopioida sen, esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/identity/phone/check-3e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "phone": "***",
  "id_card": "***"
}'
```

Pythonin liittymiskoodi on seuraava:

```python
import requests

url = "https://api.acedata.cloud/identity/phone/check-3e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "name": "***",
    "phone": "***",
    "id_card": "***"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Virheiden käsittely

API:ta kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Ei valtuutettu, virheellinen tai puuttuva valtuutusavain.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajan.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "haku epäonnistui"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
