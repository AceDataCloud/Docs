Tässä artikkelissa esitellään puhelinnumeron kaksivaiheinen vahvistus API -integraatio-ohje, jota voidaan käyttää puhelinnumeron ja nimen aitouden ja yhdenmukaisuuden tarkistamiseen.

## Hakuprosessi

API:n käyttämiseksi sinun on ensin mentävä [puhelinnumeron kaksivaiheinen vahvistus API](https://platform.acedata.cloud/documents/1f39c948-6d9b-48f5-83fb-0719da4f6ab0) -sivulle ja haettava vastaavaa palvelua. Sivulle päästyäsi napsauta "Acquire" -painiketta, kuten kuvassa on esitetty:

![](https://cdn.acedata.cloud/q6ytrc.png)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Kirjautumisen ja rekisteröitymisen jälkeen palaat automaattisesti nykyiselle sivulle.

Ensimmäisellä hakukerralla saat ilmaisia käyttöoikeuksia, joiden avulla voit käyttää tätä API:a ilmaiseksi.

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, eli syöttämällä puhelinnumero saat käsitellyn tuloksen. Ensimmäiseksi sinun on yksinkertaisesti välitettävä `mobile`-kenttä. Voimme seuraavaksi täyttää vastaavat tiedot käyttöliittymässä, kuten kuvassa on esitetty:

<p><img src="https://cdn.acedata.cloud/v6k96j.png" width="500" className="m-auto" /></p>

Täällä olemme asettaneet pyyntöotsikot, mukaan lukien:

- `accept`: haluamasi vastausmuoto, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumiseen käytettävä avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

Lisäksi on asetettu pyyntökeho, joka sisältää:

- `name`: käsiteltävän käyttäjän nimi, pakollinen parametri.
- `mobile`: käsiteltävä puhelinnumero, pakollinen parametri.
- `encryption`: valinnainen, arkaluontoisten kenttien salausparametri (jos salattua tietoa on lähetettävä).

Valinnan jälkeen voit huomata, että oikealla puolella on myös luotu vastaava koodi, kuten kuvassa on esitetty:

<p><img src="https://cdn.acedata.cloud/lq800o.png" width="500" className="m-auto" /></p>

Napsauta "Try" -painiketta testataksesi, kuten yllä olevassa kuvassa on esitetty, ja saamme seuraavan tuloksen:

```json
{
  "result": "0",
  "description": "Vahvistustulos on yhdenmukainen"
}
```

Palautetussa tuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `result`, vahvistustuloksen koodi, maksutilanne seuraavasti.
  - Maksulliset tuloskoodit:
    - 0: Vahvistustulos on yhdenmukainen
    - 1: Vahvistustulos ei ole yhdenmukainen
  - Ilmaiset tuloskoodit:
    - -1: Ei tietoja
    - -2: Moottorin tuntematon virhe
    - -3: Moottorin palveluvirhe
    - -4: Nimen tarkistus ei läpäissyt
    - -5: Puhelinnumero ei ole voimassa
    - -6: Vahvistuskerrat ylittävät päivittäisen rajan, yritä uudelleen seuraavana päivänä
- `description`, liiketoimintatuloksen kuvaus.

Voimme nähdä, että puhelinnumeron ja nimen aitous ja yhdenmukaisuus on tarkistettu.

Jos haluat luoda vastaavan integraatiokoodin, voit kopioida sen suoraan, esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/identity/phone/check-2e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "mobile": "***"
}'
```

Pythonin integraatiokoodi on seuraava:

```python
import requests

url = "https://api.acedata.cloud/identity/phone/check-2e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "name": "***",
    "mobile": "***"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Virheiden käsittely

API:a kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Ei valtuutettu, virheellinen tai puuttuva valtuutusavain.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "haku epäonnistui"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
