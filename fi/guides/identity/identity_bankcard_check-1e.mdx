Tässä artikkelissa esitellään pankkikortin perusinformaatiohaku API -liitäntäohje, jota voidaan käyttää pankkikortin perusinformaatiohakuun.

## Hakuprosessi

Käyttääksesi pankkikortin perusinformaatiohaku API:a, sinun tulee ensin mennä [Ace Data Cloud -hallintapaneeliin](https://platform.acedata.cloud/console/applications) saadaksesi API Tokenisi, jota voit säilyttää varalla.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Valmiina palaat automaattisesti nykyiselle sivulle.

**Yksi API Token riittää kaikkien palveluiden kutsumiseen, eikä jokaiselle palvelulle tarvitse hakea erikseen.** Ensimmäisestä hakemuksesta saat ilmaisen käyttöoikeuden, jonka avulla voit kokeilla palvelua ilmaiseksi; kun käyttöoikeus on loppumassa, voit ladata yleistä saldoa [hallintapaneelista](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [Pankkikortin perusinformaatiohaku API →](https://platform.acedata.cloud/documents/identity-bankcard-check-1e)

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, eli syöttämällä pankkikortin numero, voit saada käsitellyn vahvistustuloksen. Ensinnäkin sinun on yksinkertaisesti välitettävä `bank_card`-kenttä, jonka jälkeen voimme täyttää vastaavat tiedot käyttöliittymässä, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/h41nrh.png" width="500" className="m-auto" /></p>

Voit nähdä, että olemme asettaneet pyyntöotsikot, mukaan lukien:

- `accept`: haluamasi vastausmuoto, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumiseen käytettävä avain, jonka voit valita suoraan alasvetovalikosta hakemuksen jälkeen.

Lisäksi olemme asettaneet pyyntökehon, mukaan lukien:

- `bank_card`: pankkikortin numero.
- `encryption`: valinnainen, arkaluontoisten kenttien salausparametri (jos salattua tietoa on lähetettävä).

Valinnan jälkeen voit huomata, että oikealla puolella on myös luotu vastaava koodi, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/grfra7.png" width="500" className="m-auto" /></p>

Napsauta "Kokeile" -painiketta testataksesi, kuten yllä olevassa kuvassa näkyy, ja saimme seuraavan tuloksen:

```json
{
  "result": "0",
  "description": "Haku onnistui",
  "account_bank": "Teollisuus- ja kaupankäyntipankki",
  "account_type": 1
}
```

Palautetussa tuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `result`, vahvistustuloksen koodi, maksutiedot seuraavasti.
    - Maksutuloksen koodi:
        - 0: Haku onnistui
        - -1: Tietoja ei löytynyt
    - Ilmaisen tuloksen koodi:
        - -2: Vahvistuskeskus on kiireinen
        - -3: Pankkikorttia ei ole olemassa
- `description`, liiketoimintatuloksen kuvaus.
- `account_bank`, pankki, jossa tili on avattu.
- `account_type`, kortin luonne: 1. Pankkikortti; 2. Luottokortti; 3. Ennakkomaksukortti; 4. Hyväksytty luottokortti.

Voit nähdä, että pankkikortin perusinformaatio on jo haettu.

Jos haluat luoda vastaavan liitäntäkoodin, voit kopioida sen suoraan, esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/identity/bankcard/check-1e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "bank_card": "****"
}'
```

Pythonin liitäntäkoodi on seuraava:

```python
import requests

url = "https://api.acedata.cloud/identity/bankcard/check-1e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "bank_card": "****"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Virheiden käsittely

API:a kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Valtuuttamaton, virheellinen tai puuttuva valtuutusavain.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "haku epäonnistui"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
