Tässä artikkelissa esitellään MiniMax H3 -tehtävien kysely-API:n integrointi ja käyttö. Tätä rajapintaa käytetään [MiniMax H3 -videonluonti-API](https://platform.acedata.cloud/documents/minimax-videos-integration):lla luotujen asynkronisten tehtävien kyselyyn, joukkoluettelointiin tai poistamiseen.

## Hakuprosessi

Käyttääksesi MiniMax H3 -tehtävien kysely-API:a, hanki ensin API Tokenisi [Ace Data Cloud -konsolista](https://platform.acedata.cloud/console/applications) ja säilytä se varmuuden vuoksi.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle rekisteröitymään ja kirjautumaan sisään, minkä jälkeen palaat automaattisesti nykyiselle sivulle.

**Yhdellä API Tokenilla voi kutsua kaikkia alustan palveluita, eikä sitä tarvitse hakea erikseen jokaiselle palvelulle.** Ensimmäinen hakemus sisältää maksutonta käyttökiintiötä, joten voit kokeilla palvelua ilmaiseksi; jos kiintiö ei riitä, voit ladata yleissaldoa [konsolissa](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [MiniMax H3 -tehtävien kysely-API →](https://platform.acedata.cloud/documents/minimax-tasks-integration)

Tehtävää kyseltäessä tulee käyttää samaa Tokenia, jolla tehtävä luotiin. On suositeltavaa tallentaa Token ympäristömuuttujaksi eikä kirjoittaa sitä lähdekoodiin tai lähettää sitä versionhallintaan:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Rajapinnan yleiskatsaus

- **Base URL**: `https://api.acedata.cloud`
- **Endpoint**: `POST /minimax/tasks`
- **Todennustapa**: HTTP Headerissa välitetään `authorization: Bearer {token}`
- **Pyyntöotsikot**:
  - `accept: application/json`
  - `content-type: application/json`
- **Yksittäisen tehtävän kysely**: `action=retrieve`, välitä `id`
- **Tehtävien joukkokysely**: `action=retrieve_batch`, voidaan suodattaa tehtävä-ID:n, aikavälin ja sivutusehtojen mukaan
- **Tehtävän poisto**: `action=delete`, välitä `id`
- **Laskutustiedot**: tehtävien kysely on maksutonta eikä aiheuta toistuvaa laskutusta

Videon luomisen jälkeen `task_id` on tallennettava. On suositeltavaa tehdä kysely noin 10 sekunnin välein, kunnes tehtävä saavuttaa lopullisen tilan.

## Pyyntöparametrit

| Parametri               | Tyyppi       | Pakollinen   | Soveltuva toiminto                | Kuvaus                                                   |
| ---------------- | -------- | ---- | ------------------- | ---------------------------------------------------- |
| `action`         | string   | Ei    | Kaikki                  | `retrieve`, `retrieve_batch` tai `delete`; oletus on `retrieve` |
| `id`             | string   | Ehdollisesti pakollinen | `retrieve`, `delete` | Yksittäisen tehtävän ID                                              |
| `ids`            | string[] | Ei    | `retrieve_batch`    | Palauttaa vain määritetyt tehtävä-ID:t; jos jätetään pois, tehtävät luetellaan muiden ehtojen mukaan                              |
| `limit`          | integer  | Ei    | `retrieve_batch`    | Tällä kertaa palautettavien tehtävien enimmäismäärä                                          |
| `offset`         | integer  | Ei    | `retrieve_batch`    | Tulostusluettelosta ohitettavien tehtävien määrä, käytetään sivutukseen                                   |
| `created_at_min` | number   | Ei    | `retrieve_batch`    | Luontiajan alaraja, Unix-aikaleima sekunteina                                 |
| `created_at_max` | number   | Ei    | `retrieve_batch`    | Luontiajan yläraja, Unix-aikaleima sekunteina                                 |

Kolmen toiminnon käyttötarkoitukset ovat seuraavat:

| `action`         | Käyttötarkoitus                 | Vaaditut parametrit                           | Vastausrakenne                                  |
| ---------------- | ------------------ | ------------------------------ | ------------------------------------- |
| `retrieve`       | Yhden tehtävän tilan ja tuloksen kysely       | `id`                           | `{ "task": {...} }`                   |
| `retrieve_batch` | Joukkokysely tehtävä-ID:n, ajan ja sivutusehtojen mukaan | Valinnainen `ids`, aikaväli, `offset`, `limit` | `{ "items": [...], "total": number }` |
| `delete`         | Tehtävätietueen peruuttaminen tai poistaminen tehtävän nykyisen tilan mukaan  | `id`                           | `{ "id": "...", "deleted": true }`    |

## Yksittäisen tehtävän kysely

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f5977217-ed2c-40da-adbe-93d08235618f"
  }'
```

## Tehtävän tilat

| `status`    | Merkitys         | Asiakaspään käsittely                      |
| ----------- | ---------- | -------------------------- |
| `queued`    | On lisätty jonoon ja odottaa suoritusta | Jatka kyselyä                       |
| `running`   | Luonti käynnissä       | Jatka kyselyä                       |
| `succeeded` | Luonti onnistui       | Lue `task.content.url`, lopeta kysely |
| `failed`    | Luonti epäonnistui       | Lue `task.error`, lopeta kysely       |
| `cancelled` | Tehtävä on peruutettu      | Lopeta kysely                       |

`succeeded`, `failed` ja `cancelled` ovat kaikki lopullisia tiloja. Älä jatka kyselyä lopulliseen tilaan siirtymisen jälkeen.

## task-vastauksen kentät

| Kenttä                        | Tyyppi      | Kuvaus                              |
| ------------------------- | ------- | ------------------------------- |
| `id`                      | string  | Tehtävän ID                           |
| `model`                   | string  | Tehtävässä käytetty malli, tällä hetkellä `MiniMax-H3`        |
| `status`                  | string  | Tehtävän nykyinen tila                          |
| `error.code`              | string  | Virhekoodi epäonnistumiselle, palautetaan vain epäonnistumisen yhteydessä                    |
| `error.message`           | string  | Epäonnistumisen syy, palautetaan vain epäonnistumisen yhteydessä                     |
| `created_at`              | integer | Luontiaika, Unix-aikaleima sekunteina              |
| `updated_at`              | integer | Viimeisimmän tilapäivityksen aika, Unix-aikaleima sekunteina        |
| `content.url`             | string  | Videon osoite onnistumisen jälkeen                        |
| `resolution`              | string  | Tulostusresoluutio, `768P` tai `2K`             |
| `duration`                | integer | Tulostevideon kesto sekunteina                     |
| `usage.total_seconds`     | integer | Laskutettava kokonaismäärä, yhtä suuri kuin syötevideon sekuntien ja tulostesekuntien summa           |
| `usage.input_seconds`     | integer | Viitevideon syötteestä syntyvä laskutettava määrä                   |
| `usage.output_seconds`    | integer | Tulostevideosta syntyvä laskutettava määrä                     |
| `usage.input_image_count` | integer | Laskutustilastojen syötekuvien määrä                    |
| `ratio`                   | string  | Todellinen tulostuskuvasuhde; käytettäessä `adaptive`-asetusta tässä oleva tulos on ratkaiseva |
| `task_type`               | string  | Videonluontitehtävissä `generation`            |
| `modality`                | string  | Videotehtävissä `video`                   |
## Python-kyselyn täydellinen esimerkki

Seuraava koodi lukee Tokenin ympäristömuuttujasta, luo tehtävän ja kysyy sitä 10 sekunnin välein:

```python
import os
import time

import requests

BASE_URL = "https://api.acedata.cloud"
HEADERS = {
    "Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_KEY']}",
    "Content-Type": "application/json",
}

create_response = requests.post(
    f"{BASE_URL}/minimax/videos",
    headers=HEADERS,
    json={
        "model": "MiniMax-H3",
        "content": [
            {
                "type": "text",
                "text": "清晨的海边，一艘白色帆船驶过平静海面，镜头缓慢横移",
            }
        ],
        "resolution": "768P",
        "duration": 4,
        "ratio": "16:9",
    },
    timeout=30,
)
create_response.raise_for_status()
task_id = create_response.json()["task_id"]

while True:
    time.sleep(10)
    query_response = requests.post(
        f"{BASE_URL}/minimax/tasks",
        headers=HEADERS,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    query_response.raise_for_status()
    task = query_response.json()["task"]
    print(f"task={task_id} status={task['status']}")

    if task["status"] == "succeeded":
        print(f"video_url={task['content']['url']}")
        break
    if task["status"] in ("failed", "cancelled"):
        raise RuntimeError(task.get("error") or task["status"])
```

Tuotantoympäristössä kyselylle tulisi asettaa kokonaisaikakatkaisu, ja koodeille `429` sekä tilapäisille `5xx`-virheille tulisi käyttää eksponentiaalista viivettä. Verkon aikakatkaisu ei tarkoita, että generointi olisi epäonnistunut; kyselyä voidaan jatkaa samalla `task_id`:llä.

## Eräkysely

Määritä useita tehtävätunnuksia:

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve_batch",
    "ids": ["TASK_ID_1", "TASK_ID_2"],
    "offset": 0,
    "limit": 20
  }'
```

Listaa tehtävät sivutettuna aikavälin mukaan:

```json
{
  "action": "retrieve_batch",
  "created_at_min": 1786000000,
  "created_at_max": 1786200000,
  "offset": 0,
  "limit": 20
}
```

Erävastauksen `items` käyttää samoja task-kenttiä kuin yksittäisen tehtävän kysely, ja `total` on suodatusehtoja vastaavien tehtävien kokonaismäärä:

```json
{
  "items": [
    {
      "id": "TASK_ID_1",
      "model": "MiniMax-H3",
      "status": "running",
      "resolution": "2K",
      "duration": 5,
      "ratio": "adaptive",
      "task_type": "generation",
      "modality": "video"
    }
  ],
  "total": 1
}
```

Tehtävien kyselyikkuna on viimeiset 7 päivää. Tämän ikkunan ylittävä `task_id` voi palauttaa virheellisen tehtävän; liiketoimintajärjestelmän tulisi tallentaa ID tehtävää luotaessa ja tallentaa tulos-URL pysyvästi viipymättä onnistumisen jälkeen.

## Tehtävän peruuttaminen tai poistaminen

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "delete",
    "id": "YOUR_TASK_ID"
  }'
```

Toiminto riippuu tehtävän nykyisestä tilasta:

| Nykyinen tila | Toiminta |
| ----------- | ------------- |
| `queued`    | Peruuta tehtävä, jota ei ole vielä aloitettu |
| `succeeded` | Poista tehtävätietue |
| `failed`    | Poista tehtävätietue |
| `running`   | Poistaminen tai peruuttaminen ei ole sallittua, palauttaa virheen |
| `cancelled` | Toistuva toiminto ei ole sallittu, palauttaa virheen |

Esimerkki onnistuneesta poistosta:

```json
{
  "id": "YOUR_TASK_ID",
  "deleted": true
}
```

Tehtävätietueen poistaminen ei peruuta jo toteutunutta laskutusta eikä voi taata, että tallennetut videokopiot poistetaan samanaikaisesti.

## Epäonnistuneet vastaukset ja vianmääritys

Epäonnistuneet tehtävät palauttavat edelleen task-objektin HTTP 200 -vastauksena, ja syy annetaan kohdassa `task.error`:

```json
{
  "task": {
    "id": "YOUR_TASK_ID",
    "model": "MiniMax-H3",
    "status": "failed",
    "error": {
      "code": "1026",
      "message": "video description contains sensitive content"
    },
    "task_type": "generation",
    "modality": "video"
  }
}
```

Kun rajapinta itse palauttaa `400`, tulee tarkistaa `action` ja ehtoparametrit; `401` tarkoittaa, että Token on virheellinen, `429` tarkoittaa, että kyselyjä tehdään liian usein, ja `500` tarkoittaa, että palvelu ei ole tilapäisesti käytettävissä. Generoinnissa epäonnistuneista tehtävistä ei laskuteta; onnistuneiden tehtävien käyttö kirjataan lopullisen `usage`-tiedon mukaan.
