Tässä artikkelissa esitellään Producer Audios Generation API -integraatio-ohjeet, joiden avulla voidaan luoda Producerin virallista musiikkia syöttämällä mukautettuja parametreja.

## Hakuprosessi

Jos haluat käyttää Producer Audios Generation API:a, hanki ensin [Ace Data Cloud -konsolista](https://platform.acedata.cloud/console/applications) API Tokenisi ja säilytä se myöhempää käyttöä varten.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua pyydetään rekisteröitymään ja kirjautumaan sisään; valmistumisen jälkeen palaat automaattisesti nykyiselle sivulle.

**Yhdellä API Tokenilla voi kutsua kaikkia alustan palveluita, eikä sitä tarvitse hakea erikseen jokaiselle palvelulle.** Ensimmäisellä hakukerralla saat ilmaista käyttökiintiötä maksutonta kokeilua varten; kun kiintiö ei riitä, voit lisätä yleistä saldoa [konsolissa](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Valitse pakolliset parametrit toiminnon mukaan

Kun `action=generate` ja `custom=false` (oletus), anna `prompt`; kun `custom=true`
ja `instrumental=false`, anna `lyric`. Mukautetussa instrumentaalimusiikissa voidaan asettaa
`custom=true, instrumental=true`, jolloin ei tarvitse keksiä sanoituksia tai ylimääräisiä kehotteita.
`action=extend` edellyttää `audio_id`:tä ja arvoa `continue_at`, joka on suurempi kuin 0; muussa kuin instrumentaalitilassa tarvitaan lisäksi
`lyric`. Cover-versiot, muunnelmat, osioiden korvaaminen, stemmojen vaihto ja ääniraitojen erottelu edellyttävät kaikki lähteen `audio_id`:tä;
sanoitusten ja kehotteiden ei tulisi olla ehdoitta pakollisia kaikissa toiminnoissa.

MCP:ssä `producer_extend_music` ja `producer_replace_section` valitsevat mukautettujen sanoitusten tilan, kun niille annetaan `lyric`;
instrumentaalisessa jatkossa voidaan välittää `instrumental=true` ja jättää sanoitukset pois.

## Peruskäyttö

Voit ajatella mitä tahansa kappaletta ja syöttää vapaasti tekstin pätkän, esimerkiksi jos haluan luoda jouluaiheisen kappaleen, voin syöttää `a song for Christmas`, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Tässä näemme, että olemme asettaneet Request Headers -otsakkeet, mukaan lukien:

- `accept`: missä muodossa haluat vastaanottaa vastaustuloksen; tähän täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumisen avain, jonka voi hakemisen jälkeen valita suoraan pudotusvalikosta.

Lisäksi Request Body -pyynnön parametreihin kuuluvat:

- `action`: tämän musiikinluontitehtävän toiminto; kappaleen luomisessa se on `generate`.
- `model`: kappaleen luomisessa käytettävä malli, tällä hetkellä pääasiassa: **FUZZ-2.0 Pro**、**FUZZ-2.0**、**FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**、**FUZZ-1.0 Pro**、**FUZZ-1.0**、**FUZZ-1.1**、**FUZZ-0.8**.
- `lyric`: kappaleen sanoitusten sisältö.
- `custom`: luodaanko kappale mukautetulla tavalla.
- `prompt`: kehotus inspiraatiotilassa.
- `title`: kappaleen otsikkotiedot.
- `audio_id`: viitekappaleen ID, jota käytetään esimerkiksi jatkamiseen/uusintaversioon.
- `continue_at`: kappaleen jatkaminen määritetystä sekunnista alkaen.
- `replace_section_start`/`replace_section_end`: korvattavan osion alku- ja loppuaika sekunneissa.
- `lyrics_strength`: sanoitusten voimakkuus, joka ilmaisee sanoitusten vaikutusasteen äänen luomisessa; valinnainen arvo väliltä 0–1, oletus 0.7.
- `sound_strength`: äänikehotteen voimakkuus, valinnainen arvo väliltä 0.2–1, oletus 0.7.
- `cover_strength`: cover-version voimakkuus väliltä 0.2–1, oletus 1.
- `weirdness`: tyylin erikoisuusaste, valinnainen arvo väliltä 0–1, oletus 0.5
- `callback_url`: URL-osoite, johon tulos tulee palauttaa takaisinsoittona.
- `async`: valinnainen; kun asetetaan arvoksi `true`, rajapinta palauttaa välittömästi `task_id`:n, eikä `callback_url`:ää tarvitse antaa; tämän jälkeen tulos haetaan kyselevällä tavalla vastaavasta tehtävän kyselyrajapinnasta.
- `instrumental`: onko kyse sanoituksettomasta tilasta.

Palautetussa tuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `success`, musiikinluontitehtävän tilanne tällä hetkellä.
  - `data`, tämän musiikkitehtävän tulos

    -  `seed`, musiikinluontitehtävän siemenarvo tällä hetkellä.
    - `audio_url`, musiikinluontitehtävän äänilinkki tällä hetkellä.
    - `image_url`, musiikinluontitehtävän kansilinkki tällä hetkellä.
    - `image_id`, musiikinluontitehtävän kansi-ID tällä hetkellä.
    - `state`, musiikinluontitehtävän tila tällä hetkellä.
    - `duration`, musiikin keston tiedot tällä hetkellä.

    - `model`, musiikinluontitehtävässä käytetyn mallin tiedot tällä hetkellä.
    - `lyric`, musiikinluontitehtävän sanoitustiedot tällä hetkellä.

Voimme nähdä, että saimme halutun luodun musiikin tiedot; meidän tarvitsee vain hakea luotu Producer-musiikki tuloksessa olevan `data`-kohdan musiikkilinkkiosoitteen perusteella.

Lisäksi, jos haluat luoda vastaavan integraatiokoodin, voit kopioida sen suoraan; esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Kappaleen coverointi

Jos haluat coveroida jo luodun kappaleen, voit syöttää yllä luodun kappaleen coverointia varten. Seuraavaksi meidän on luotava kappale mukautetusti sanoitusten ja otsikon perusteella.

Jos haluat jatkaa itse lataamasi kappaleen coverointia, voit asettaa parametrin `action` arvoksi `upload_cover` ja syöttää mukautetusti ladatun kappaleen ID:n, jota halutaan jatkaa coveroimalla. Kappaleen ID saadaan [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload) -rajapinnan avulla, kuten alla olevassa kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Tällöin voidaan määrittää seuraava sisältö:

- action: tämän kappaletehtävän toiminto, tällä hetkellä tuetaan seuraavia: generate, cover, extend, upload_cover, upload_extend, replace_section, swap_vocals, swap_instrumentals, variation. Tässä coveroinnissa käytetään `cover`-parametria.
- lyric: sanoitusteksti
- title: kappaleen otsikko.
- custom: luodaanko mukautetussa tilassa, oletusarvo on false.
- audio_id: coveroitavan kappaleen kappale-ID.

## Asynkroninen takaisinsoitto

Koska Producer Audios Generation API:n luontiaika voi joskus olla suhteellisen pitkä, jos API ei vastaa pitkään aikaan, HTTP-pyyntö pitää yhteyden jatkuvasti auki, mikä johtaa ylimääräiseen järjestelmäresurssien kulutukseen, joten tämä API tarjoaa myös tuen asynkronisille takaisinsoitoille.

Kokonaisprosessi on seuraava: kun asiakas lähettää pyynnön, se määrittää lisäksi `callback_url`-kentän, ja kun asiakas lähettää API-pyynnön, API palauttaa välittömästi tuloksen, joka sisältää `task_id`-kentän tiedot ja edustaa nykyistä tehtävätunnusta. Kun tehtävä on valmis, luontitehtävän tulos lähetetään POST JSON -muodossa asiakkaan määrittämään `callback_url`-osoitteeseen, jossa on myös `task_id`-kenttä, jolloin tehtävän tulokset voidaan yhdistää tunnuksen avulla.

Seuraavaksi opimme esimerkin avulla, kuinka toiminto suoritetaan tarkalleen.

Ensinnäkin Webhook-takaisinsoitto on palvelu, joka voi vastaanottaa HTTP-pyyntöjä. Kehittäjien tulisi korvata se oman HTTP-palvelimensa URL-osoitteella. Esittelyn helpottamiseksi käytetään tässä julkista Webhook-esimerkkisivustoa [https://webhook.site/](https://webhook.site/). Avaamalla tämän sivuston saat Webhook-URL-osoitteen, kuten kuvassa näkyy:

![](https://cdn.acedata.cloud/tbcnai.png)

## Virheenkäsittely

APIa kutsuttaessa API palauttaa vastaavan virhekoodin ja -tiedon, jos tapahtuu virhe. Esimerkiksi:

- `400 token_mismatched`: Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Luvaton, virheellinen tai puuttuva valtuutustunnus.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, palvelimella tapahtui jotain odottamatonta.

### Esimerkki virhevastauksesta

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
