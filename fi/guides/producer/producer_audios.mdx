Tässä artikkelissa esitellään Producer Audios Generation API -integrointiohje, jolla voidaan luoda Producerin virallista musiikkia syöttämällä mukautettuja parametreja.

## Hakuprosessi

Jotta voit käyttää Producer Audios Generation API:a, hanki ensin [Ace Data Cloud -konsolista](https://platform.acedata.cloud/console/applications) API Tokenisi ja säilytä se myöhempää käyttöä varten.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle rekisteröitymään ja kirjautumaan sisään, minkä jälkeen palaat automaattisesti tälle sivulle.

**Yhdellä API Tokenilla voi kutsua kaikkia alustan palveluita, eikä jokaista palvelua varten tarvitse hakea erikseen.** Ensimmäisellä hakukerralla saat ilmaista saldoa maksutonta kokeilua varten; jos saldo ei riitä, voit ladata yleistä saldoa [konsolissa](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Peruskäyttö

Voit syöttää vapaasti tekstinpätkän siitä, millaisen kappaleen haluat. Jos esimerkiksi haluan luoda joulua käsittelevän kappaleen, voin syöttää `a song for Christmas`, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Tässä näemme, että olemme asettaneet Request Headers -otsakkeet, mukaan lukien:

- `accept`: missä muodossa haluat vastaanottaa vastaustuloksen; tähän täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumisen avain, joka voidaan valita suoraan pudotusvalikosta hakemisen jälkeen.

Lisäksi Request Body -parametreihin kuuluvat:

- `action`: tämän musiikinluontitehtävän toiminto; kappaleen luominen on `generate`.
- `model`: kappaleen luomiseen käytetty malli; tällä hetkellä tärkeimmät ovat: **FUZZ-2.0 Pro**、**FUZZ-2.0**、**FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**、**FUZZ-1.0 Pro**、**FUZZ-1.0**、**FUZZ-1.1**、**FUZZ-0.8**.
- `lyric`: kappaleen sanoitussisältö.
- `custom`: luodaanko kappale mukautetulla tavalla.
- `prompt`: kehoteteksti inspiraatiotilassa.
- `title`: kappaleen otsikkotiedot.
- `audio_id`: viitekappaleen ID, käytetään esimerkiksi jatkokirjoitukseen/uudelleenversiointiin.
- `continue_at`: jatka kappaleen kirjoittamista määritetystä sekunnista alkaen.
- `replace_section_start`/`replace_section_end`: korvattavan katkelman alku- ja loppuaika sekunteina.
- `lyrics_strength`: sanoitusten voimakkuus, joka ilmaisee sanoitusten vaikutuksen asteen äänen luomisessa; valittavissa välillä 0–1, oletusarvo 0.7.
- `sound_strength`: äänikehotteen voimakkuus, valittavissa välillä 0.2–1, oletusarvo 0.7.
- `cover_strength`: cover-version voimakkuus välillä 0.2–1, oletusarvo 1.
- `weirdness`: tyylin erikoisuusaste, valittavissa välillä 0–1, oletusarvo 0.5
- `callback_url`: URL, johon tulos tulee palauttaa takaisinsoittona.
- `async`: valinnainen; kun arvoksi asetetaan `true`, rajapinta palauttaa välittömästi `task_id`:n, eikä `callback_url`:ia tarvitse antaa, minkä jälkeen tulos haetaan kyselevällä tehtävänhakurajapinnalla.
- `instrumental`: käytetäänkö sanoituksetonta tilaa.

Palautettavassa tuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `success`, musiikinluontitehtävän tämänhetkinen tila.
  - `data`, tämän musiikkitehtävän tulos
    - `id`, tämän musiikinluontitehtävän ID.
    - `sound`, tämän musiikinluontitehtävän kehoteteksti.
    - `seed`, tämän musiikinluontitehtävän siemenarvo.

    - `image_url`, tämän musiikinluontitehtävän kansikuvan linkki.

    - `state`, tämän musiikinluontitehtävän tila.
    - `duration`, tämän musiikin kestoa koskevat tiedot.
    - `progress`, tämän musiikkitehtävän edistymisarvo.
    - `model`, tämän musiikinluontitehtävän käyttämät mallitiedot.
    - `lyric`, tämän musiikinluontitehtävän sanoitustiedot.

Voimme nähdä, että olemme saaneet haluamamme luodun musiikin tiedot. Meidän tarvitsee vain hankkia luotu Producer-musiikki tuloksessa olevan `data`-kentän musiikkilinkkiosoitteen perusteella.

Jos haluat lisäksi luoda vastaavan integrointikoodin, voit kopioida sen suoraan. Esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Kappaleen coverointi

Jos haluat coveroida jo luodun kappaleen, voit syöttää yllä luodun kappaleen coverointia varten; seuraavaksi luomme kappaleen mukautetusti sanoitusten ja otsikon perusteella.

Jos haluat jatkaa itse lataamasi kappaleen coverointia, voit asettaa parametrin `action` arvoksi `upload_cover` ja syöttää mukautetusti ladatun kappaleen tunnuksen, jonka coverointia haluat jatkaa. Kappaleen tunnus saadaan käyttämällä [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload) -rajapintaa, kuten alla olevassa kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Voit määrittää seuraavan sisällön:

- action：tämän kappaletehtävän toiminto, tällä hetkellä tuetaan: generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation; tässä coveroinnissa käytetään parametria `cover`.
- lyric：sanoitusteksti
- title：kappaleen otsikko.
- custom：luodaanko mukautetussa tilassa, oletusarvo on false.
- audio_id：coveroitavan kappaleen kappaletunnus.

## Asynkroninen takaisinsoitto

Koska Producer Audios Generation API:n luontiaika voi joskus olla suhteellisen pitkä, jos API ei vastaa pitkään aikaan, HTTP-pyyntö pitää yhteyden jatkuvasti avoinna, mikä johtaa ylimääräiseen järjestelmäresurssien kulutukseen, joten tämä API tarjoaa myös asynkronisen takaisinsoiton tuen.

Kokonaisprosessi on: kun asiakas käynnistää pyynnön, määritetään lisäksi `callback_url`-kenttä, kun asiakas käynnistää API-pyynnön, API palauttaa välittömästi tuloksen, joka sisältää `task_id`-kenttätiedon ja edustaa nykyistä tehtävätunnusta. Kun tehtävä on valmis, luontitehtävän tulos lähetetään POST JSON -muodossa asiakkaan määrittämään `callback_url`:iin, ja se sisältää myös `task_id`-kentän, jolloin tehtävän tulos voidaan yhdistää tunnuksen avulla.

Seuraavaksi ymmärrämme esimerkin kautta, miten toimia tarkalleen.

Ensinnäkin Webhook-takaisinsoitto on palvelu, joka voi vastaanottaa HTTP-pyyntöjä, kehittäjien tulisi korvata se oman rakentamansa HTTP-palvelimen URL-osoitteella. Demonstroinnin helpottamiseksi tässä käytetään julkista Webhook-esimerkkisivustoa [https://webhook.site/](https://webhook.site/), avaamalla tämä sivusto saat Webhook-URL-osoitteen, kuten kuvassa näkyy:

![](https://cdn.acedata.cloud/tbcnai.png)

Kopioi tämä URL-osoite, niin sitä voidaan käyttää Webhookina, tämän kohdan esimerkki on [https://webhook.site/#!/view/0d73431d-f833-4be4-9276-b6e1690d55c1](https://webhook.site/#!/view/0d73431d-f833-4be4-9276-b6e1690d55c1)。

## Virheenkäsittely

Kun API:a kutsuttaessa tapahtuu virhe, API palauttaa vastaavan virhekoodin ja tiedon. Esimerkiksi:

- `400 token_mismatched`：Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`：Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`：Luvaton, virheellinen tai puuttuva valtuutustunnus.
- `429 too_many_requests`：Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`：Sisäinen palvelinvirhe, palvelimella meni jotain pieleen.

### Esimerkki virhevastausta

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
