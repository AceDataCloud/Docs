Producer Tasks API:n päätoiminto on kysyä tehtävän suoritustilaa syöttämällä Producer Audios Generation API:n tuottama tehtävä-ID.

Tässä asiakirjassa käsitellään yksityiskohtaisesti Producer Tasks API:n integrointia, jotta voit helposti hyödyntää tämän API:n voimakkaita ominaisuuksia. Producer Tasks API:n avulla voit helposti tarkistaa Producer Audios Generation API:n tehtävän suoritustilan.

## Hakuprosessi

Käyttääksesi Producer Tasks API:a, sinun on ensin mentävä hakusivulle [Producer Audios Generation API](https://platform.acedata.cloud/documents/producer-audios) ja haettava vastaavaa palvelua, sitten kopioi Producer Audios Generation API:n tehtävä-ID, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" class="m-auto"></p>

Lopuksi siirry Tasks API -sivulle [Producer Tasks API](https://platform.acedata.cloud/documents/622626b1-30a7-4799-a772-4946e1df3ac0) ja hae vastaavaa palvelua, siirryttyäsi sivulle, napsauta "Acquire" -painiketta, kuten kuvassa näkyy:

![Hakusivu](https://cdn.acedata.cloud/rci31i.png)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti [kirjautumissivulle](https://platform.acedata.cloud), joka kutsuu sinua rekisteröitymään ja kirjautumaan sisään, ja kirjautumisen jälkeen palaat automaattisesti nykyiselle sivulle.

Ensimmäisellä hakukerralla saat ilmaisia krediittejä, joiden avulla voit käyttää tätä API:a ilmaiseksi.

## Pyyntöesimerkki

Producer Tasks API:a voidaan käyttää Producer Audios Generation API:n tulosten tarkistamiseen. Lisätietoja siitä, miten käyttää Producer Audios Generation API:a, katso asiakirja [Producer Audios Generation API](https://platform.acedata.cloud/documents/producer-audios-integration).

Otetaan esimerkki yhdestä Producer Audios Generation API:n palauttamasta tehtävä-ID:stä ja näytetään, miten tätä API:a käytetään. Oletetaan, että meillä on tehtävä-ID: 1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad, seuraavaksi näytetään, miten syötetään tämä tehtävä-ID.

### Pyyntöotsikon ja -kehon asettaminen

**Request Headers** sisältää:

- `accept`: määrittää, että vastaanotetaan JSON-muotoisia vastauksia, tässä täytetään `application/json`.
- `authorization`: API:n kutsuav avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

**Request Body** sisältää:

- `id`: ladattu tehtävä-ID.
- `action`: tehtävän toimintatapa.

Aseta kuten alla olevassa kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/bfe4ww.png" width="500" class="m-auto"></p>

### Koodiesimerkki

Voit huomata, että sivun oikealla puolella on automaattisesti luotu koodia eri kielillä, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/u4pb2f.png" width="500" class="m-auto"></p>

Osittainen koodiesimerkki on seuraava:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

## Virheiden käsittely

API:ta kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Ei valtuutettu, virheellinen tai puuttuva valtuutustoken.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "haku epäonnistui"
  },

}
```
