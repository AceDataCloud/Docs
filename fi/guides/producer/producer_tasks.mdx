Producer Tasks API:n päätoiminto on kysellä tehtävän suoritustilannetta syöttämällä Producer Audios Generation API:n luoma tehtävätunnus.

Tässä dokumentissa esitellään yksityiskohtaisesti Producer Tasks API:n integrointiohjeet, jotka auttavat sinua integroimaan ja hyödyntämään tämän API:n tehokkaita toimintoja helposti. Producer Tasks API:n avulla voit helposti toteuttaa Producer Audios Generation API:n tehtävien suoritustilanteen kyselyn.

## Hakuprosessi

Käyttääksesi Producer Audios Generation API:a hae ensin [Ace Data Cloud -konsolista](https://platform.acedata.cloud/console/applications) API Tokenisi ja säilytä se myöhempää käyttöä varten.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle rekisteröitymään ja kirjautumaan sisään, minkä jälkeen palaat automaattisesti nykyiselle sivulle.

**Yhdellä API Tokenilla voi kutsua kaikkia alustan palveluita, eikä sitä tarvitse hakea erikseen jokaiselle palvelulle.** Ensimmäisestä hakemuksesta annetaan ilmainen käyttökiintiö maksutonta kokeilua varten; kun kiintiö ei riitä, voit ladata yleissaldoa [konsolissa](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Pyyntöesimerkki

Producer Tasks API:a voidaan käyttää Producer Audios Generation API:n tulosten kyselyyn. Lisätietoja Producer Audios Generation API:n käytöstä saat dokumentaatiosta [Producer Audios Generation API](https://platform.acedata.cloud/documents/producer-audios-integration).

Käytämme esimerkkinä yhtä Producer Audios Generation API -palvelun palauttamaa tehtävätunnusta ja havainnollistamme, kuinka tätä API:a käytetään. Oletetaan, että meillä on tehtävätunnus: 1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad, seuraavaksi havainnollistetaan, kuinka välittämällä yksi tehtävätunnus voidaan.

### Pyyntöotsikoiden ja pyyntörungon määrittäminen

**Request Headers** sisältää:

- `accept`: määrittää JSON-muotoisen vastaustuloksen vastaanottamisen, tähän kirjoitetaan `application/json`.
- `authorization`: API:n kutsuavain, jonka voi valita suoraan avattavasta luettelosta hakemisen jälkeen.

**Request Body** sisältää:

- `id`: ladatun tehtävän tunnus.
- `action`: tehtävään kohdistuvan toiminnon tapa.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

- `id`，luontitehtävän ID, jota käytetään tämän luontitehtävän yksilöivään tunnistamiseen.
- `request`，kyselytehtävän pyyntötiedot.
- `response`，kyselytehtävän palautustiedot.
- `created_at`，tehtävän luontiaika, Unix-aikaleima (sekunteina, liukuluku).
- `started_at`，tehtävän suorituksen aloitusaika, Unix-aikaleima (sekunteina, liukuluku).

- `elapsed`，tehtävän suoritusaika sekunteina (liukuluku, 3 desimaalin tarkkuudella). Tätä kenttää ei palauteta, kun tehtävä ei ole valmis.

## Virheenkäsittely

APIa kutsuttaessa API palauttaa vastaavan virhekoodin ja -tiedon, jos tapahtuu virhe. Esimerkiksi:

- `400 token_mismatched`: Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Ei valtuutettu, virheellinen tai puuttuva valtuutustunnus.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, palvelimella tapahtui jotain virheellistä.
