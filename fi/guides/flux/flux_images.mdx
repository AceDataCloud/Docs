Tässä artikkelissa esitellään Flux Images Generation API -integrointiohje, jonka avulla voidaan luoda Fluxin virallisia kuvia syöttämällä mukautettuja parametreja.

## Hakuprosessi

Käyttääksesi Flux Images Generation API:a, hae ensin [Ace Data Cloud -konsolista](https://platform.acedata.cloud/console/applications) API Tokenisi ja säilytä se myöhempää käyttöä varten.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle rekisteröitymään ja kirjautumaan sisään, minkä jälkeen palaat automaattisesti nykyiselle sivulle.

**Yhdellä API Tokenilla voidaan kutsua kaikkia alustan palveluita, eikä jokaista palvelua tarvitse hakea erikseen.** Ensimmäisellä hakukerralla saat ilmaista käyttökiintiötä maksutonta kokeilua varten; jos kiintiö ei riitä, voit lisätä yleissaldoa [konsolissa](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Peruskäyttö

Tutustutaan ensin peruskäyttötapaan: syöttämällä kehotetekstin `prompt`, luontitoiminnon `action` ja kuvakoon `size` voit saada käsitellyn tuloksen. Ensin on yksinkertaisesti välitettävä `action`-kenttä, jonka arvo on `generate`, ja sen jälkeen on syötettävä kehoteteksti. Tarkempi sisältö on seuraava:

<p><img src="https://cdn.acedata.cloud/wz85jt.png" width="500" className="m-auto" /></p>

Tässä voidaan nähdä, että olemme asettaneet Request Headers -otsakkeet, mukaan lukien:

- `accept`: millaisessa muodossa haluat vastaanottaa vastaustuloksen; tähän täytetään `application/json`, eli JSON-muoto.
- `authorization`: API-kutsun avain, joka voidaan valita suoraan pudotusvalikosta hakemisen jälkeen.

Lisäksi on asetettu Request Body, mukaan lukien:

- `action`: tämän kuvanluontitehtävän toiminto.
- `size`: kuvanluontituloksen koko. **`flux-2-flex` / `flux-2-pro` / `flux-2-max` -sarjoille on annettava kuvasuhde (kuten `1:1`, `16:9`); ne eivät hyväksy pikselikokoja, kuten `1024x1024`, ja puuttuva arvo palauttaa 400-virheen.**
- `count`: luotavien kuvien määrä, oletusarvo on 1; tämä parametri on voimassa vain kuvien luontitehtävissä ja ei ole voimassa muokkaustehtävissä.
- `prompt`: kehoteteksti.
- `model`: luontimalli, oletusarvo `flux-dev`; uusimmat lippulaivamallit ovat `flux-2-pro` ja `flux-2-max` (parempi kuvanlaatu, edellyttää kuvasuhdetta `size`).
- `callback_url`: URL, johon tulos tulee palauttaa takaisinsoittona.
- `async`: valinnainen; kun arvoksi asetetaan `true`, rajapinta palauttaa heti `task_id`:n ilman, että `callback_url`-osoitetta tarvitsee antaa, ja tulos haetaan sen jälkeen kyseisestä tehtävän kyselyrajapinnasta pollaamalla.

Parametrilla `size` on joitakin erityisiä rajoituksia, jotka jakautuvat pääasiassa kahteen tyyppiin: `width x height` -leveys-korkeussuhde ja `x:y`-kuvasuhde. Tarkemmat tiedot ovat seuraavat:

| Malli               | Alue                                         |
| ---------------- | ------------------------------------------ |
| flux-dev         | Tukee leveys-korkeussuhteita 1024x1024, 1024x1792, 1792x1024 tai kuvasuhdetta |
| flux-pro         | Tukee leveys-korkeussuhteita 1024x1024, 1024x1792, 1792x1024 tai kuvasuhdetta |
| flux-2-flex      | Tukee vain kuvasuhdetta                                    |
| flux-2-pro       | Tukee vain kuvasuhdetta                                    |
| flux-2-max       | Tukee vain kuvasuhdetta                                    |
| flux-kontext-pro | Tukee vain kuvasuhdetta                                    |
| flux-kontext-max | Tukee vain kuvasuhdetta                                    |

Viitekuvasuhteet: "21:9", "16:9", "4:3", "3:2", "1:1", "2:3", "3:4", "9:16", "9:21".

Kun parametrit on valittu, vastaava koodi luodaan automaattisesti oikealle puolelle. Varmista ennen kopiointia, että valtuutusotsikko käyttää omaa API Key -avaintasi eikä dokumentaatiossa tai kuvakaappauksissa näy todellisia tunnistetietoja.

Napsauta 「Try」-painiketta testataksesi, jolloin saamme seuraavan tuloksen:

```json
{
  "success": true,
  "task_id": "5456c749-3bbb-4f10-9eb8-cfbcac297500",
  "trace_id": "ae4eecb8-1dd6-45b4-bfb3-a1c48872536e",
  "data": [
    {
      "image_url": "https://cdn.acedata.cloud/assets/examples/flux/5456c749-3bbb-4f10-9eb8-cfbcac297500-d0ef60485f73.jpg"
    }
  ]
}
```

Palautustuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `success`, tämänhetkisen videonluontitehtävän tilanne.
- `task_id`, tämänhetkisen videonluontitehtävän ID.
- `trace_id`, tämänhetkisen videonluonnin seuranta-ID.
- `data`, tämänhetkisen kuvanluontitehtävän tulosluettelo.
  - `image_url`, tämänhetkisen kuvanluontitehtävän linkki.
  - `prompt`, kehoteteksti.

Voidaan nähdä, että saimme tyydyttävät kuvatiedot. Meidän tarvitsee vain hakea luotu Flux-kuva tuloksen `data`-kohdassa olevasta kuvalinkkiosoitteesta.

Jos haluat lisäksi luoda vastaavan integraatiokoodin, voit kopioida sen suoraan. Esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/flux/images' \
-H 'authorization: Bearer {token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "A photorealistic studio product shot of a frosted-glass perfume bottle on wet black slate, single softbox key light, water droplets, dark moody background, 85mm macro.",
  "model": "flux-2-pro",
  "size": "1:1"
}'
```

## Kuvatehtävän muokkaaminen

Jos haluat muokata tiettyä kuvaa, parametri `image_url` on ensin annettava muokattavan kuvan linkkinä. Tällöin `action` tukee vain arvoa `edit`, ja voit määrittää seuraavan sisällön:

- model: tässä kuvanmuokkaustehtävässä käytettävä malli; tukee malleja `flux-dev`, `flux-pro`, `flux-kontext-pro`, `flux-kontext-max`, `flux-2-flex`, `flux-2-pro`, `flux-2-max`.
- image_url: lataa muokattava kuva.

Täyttöesimerkki on seuraava:

<p><img src="https://cdn.acedata.cloud/jn9da5.png" width="500" className="m-auto" /></p>

Täyttämisen jälkeen koodi luodaan automaattisesti seuraavasti:

<p><img src="https://cdn.acedata.cloud/6cwxb8.png" width="500" className="m-auto" /></p>

Vastaava koodi:

```python
import requests

url = "https://api.acedata.cloud/flux/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "edit",
    "prompt": "a white siamese cat",
    "model": "flux-kontext-pro",
    "image_url": "https://cdn.acedata.cloud/ytj2qy.png"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Napsauta suorita, niin voidaan havaita, että tulos saadaan välittömästi seuraavasti:

```json
{
  "success": true,
  "task_id": "2a7979ff-1f77-4380-92c6-a2dc37c3b4c8",
  "trace_id": "732b65c0-48d9-49f7-b568-64e5acffe4c0",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "timings": 1752744073
    }
  ]
}
```
Kuten voidaan nähdä, luotu tulos on alkuperäisen kuvan muokkauksen tulos, ja tulos on samanlainen kuin edellä.

## Asynkroninen takaisinsoitto

Koska Flux Images Generation API:n luontiaika on suhteellisen pitkä, noin 1–2 minuuttia, jos API ei vastaa pitkään aikaan, HTTP-pyyntö pysyy jatkuvasti yhteydessä, mikä johtaa ylimääräiseen järjestelmäresurssien kulutukseen, joten tämä API tarjoaa myös tuen asynkronisille takaisinsoitoille.

Kokonaisprosessi on seuraava: kun asiakas lähettää pyynnön, se määrittää lisäksi `callback_url`-kentän. Kun asiakas lähettää API-pyynnön, API palauttaa välittömästi tuloksen, joka sisältää `task_id`-kentän tiedot ja edustaa nykyisen tehtävän ID:tä. Kun tehtävä on valmis, kuvan luomisen tulos lähetetään POST JSON -muodossa asiakkaan määrittämään `callback_url`-osoitteeseen, jossa on myös `task_id`-kenttä, jolloin tehtävän tulokset voidaan yhdistää ID:n avulla.

Seuraavaksi opimme esimerkin avulla, miten toimia tarkemmin.

Ensinnäkin Webhook-takaisinsoitto on palvelu, joka voi vastaanottaa HTTP-pyyntöjä, ja kehittäjän tulee korvata se itse rakentamansa HTTP-palvelimen URL-osoitteella. Esittelyn helpottamiseksi käytetään tässä julkista Webhook-esimerkkisivustoa https://webhook.site/; avaamalla sivuston saat Webhook-URL-osoitteen, kuten kuvassa näkyy:

![](https://cdn.acedata.cloud/cjjfly.png)

Kopioimalla tämän URL-osoitteen voit käyttää sitä Webhookina; esimerkki tässä on `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`.

Seuraavaksi voimme asettaa kentän `callback_url` edellä mainituksi Webhook-URL-osoitteeksi ja täyttää samalla vastaavat parametrit. Tarkka sisältö näkyy kuvassa:

<p><img src="https://cdn.acedata.cloud/wm6caw.png" width="500" className="m-auto" /></p>

Napsauta suorita, ja voit huomata, että tulos saadaan välittömästi seuraavasti:

```
{
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c"
}
```

Hetken kuluttua voimme nähdä kuvan luomisen tuloksen osoitteessa `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`, kuten kuvassa näkyy:

![](https://cdn.acedata.cloud/v23lot.png)

Sisältö on seuraava:

```json
{
  "success": true,
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c",
  "trace_id": "9b4b1ff3-90f2-470f-b082-1061ec2948cc",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "seed": 1698551532,
      "timings": {
        "inference": 3.328
      }
    }
  ]
}
```

Voidaan nähdä, että tuloksessa on `task_id`-kenttä, ja muut kentät ovat samanlaisia kuin edellä. Tämän kentän avulla voidaan toteuttaa tehtävien yhdistäminen.

## Virheenkäsittely

API:a kutsuttaessa API palauttaa vastaavan virhekoodin ja tiedot, jos tapahtuu virhe. Esimerkiksi:

- `400 token_mismatched`：Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`：Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`：Ei valtuutettu, virheellinen tai puuttuva valtuutustunnus.
- `429 too_many_requests`：Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`：Sisäinen palvelinvirhe, palvelimella tapahtui jotain virheellistä.

### Esimerkki virhevastaus

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
