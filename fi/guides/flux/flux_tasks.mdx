Flux Tasks API:n päätoiminto on kysellä tehtävän suoritusstatus alustatehtävän ID:n avulla, jonka Flux Images Generation API tai Flux Videos API palauttaa syötteenä.

Tässä dokumentissa esitellään yksityiskohtaisesti Flux Tasks API:n integrointiohjeet, jotta voit helposti integroida ja hyödyntää täysin tämän API:n tehokkaita toimintoja. Flux Tasks API:n avulla voit helposti kysellä Flux Images Generation API:n tehtävien suoritusstatusta.

Katso täydellinen esimerkki videon lähettämisestä ja kyselystä kohdasta [Flux Videos API:n integrointiopas](https://platform.acedata.cloud/documents/flux-videos-integration). Olemassa olevien tehtävien kyselystä ei veloiteta erillisiä generointimaksuja.

## Hakuprosessi

Käyttääksesi Flux Images Generation API:a, hanki ensin API Tokenisi [Ace Data Cloud -konsolista](https://platform.acedata.cloud/console/applications) ja säilytä se myöhempää käyttöä varten.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle rekisteröitymään ja kirjautumaan sisään, minkä jälkeen palaat automaattisesti tälle sivulle.

**Yhdellä API Tokenilla voit kutsua kaikkia alustan palveluita, eikä sinun tarvitse hakea kutakin palvelua erikseen.** Ensimmäisellä hakukerralla saat ilmaista käyttökiintiötä, jolla voit kokeilla palvelua maksutta; jos kiintiö ei riitä, voit ladata yleissaldoa [konsolissa](https://platform.acedata.cloud/console/coin).

> 📘 Täydellinen dokumentaatio: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Pyyntöesimerkki

Flux Tasks API:a voidaan käyttää Flux Images Generation API:n tulosten kyselyyn. Katso Flux Images Generation API:n käyttöohjeet dokumentaatiosta [Flux Images Generation API](https://platform.acedata.cloud/documents/flux-images-integration).

Käytämme esimerkkinä yhtä Flux Images Generation API -palvelun palauttamaa tehtävä-ID:tä havainnollistaaksemme, kuinka tätä API:a käytetään. Oletetaan, että meillä on tehtävä-ID: 2db0168c-2373-4367-8d9a-9dc778802e8a, ja seuraavaksi havainnollistamme, kuinka välitetään yksi tehtävä-ID.

### Pyyntöotsakkeiden ja pyyntörungon määrittäminen

**Request Headers** sisältää:

- `accept`: määrittää vastaanotettavien vastaustulosten JSON-muodon, tähän täytetään `application/json`.
- `authorization`: API:n kutsumisen avain, jonka voi valita suoraan pudotusvalikosta hakemisen jälkeen.

**Request Body** sisältää:

- `id`: ladatun tehtävän ID.
- `action`: tehtävään kohdistuva toimintatapa.

Määritä seuraavan kuvan mukaisesti:

### Koodiesimerkki

Osa koodiesimerkeistä on seuraavat:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/flux/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/flux/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Palautustuloksessa on useita kenttiä. `request`-kenttä on tehtävää käynnistettäessä käytetty request body, kun taas `response`-kenttä on tehtävän valmistuttua palautettu response body. Kenttien kuvaukset ovat seuraavat.

- `id`, tämän kuvatehtävän generoinnin ID, jota käytetään tämän kuvan generointitehtävän yksilölliseen tunnistamiseen.
- `request`, kuvatehtävän pyyntötiedot kyselyssä.
- `response`, kuvatehtävän palautustiedot kyselyssä.
- `created_at`, tehtävän luontiaika, Unix-aikaleima (sekunteina, liukuluku).
- `started_at`, tehtävän suorituksen aloitusaika, Unix-aikaleima (sekunteina, liukuluku).
- `finished_at`, tehtävän valmistumisaika, Unix-aikaleima (sekunteina, liukuluku). Tätä kenttää ei palauteta, jos tehtävä ei ole valmis.
- `elapsed`, tehtävän suoritukseen kulunut aika sekunteina (liukuluku, 3 desimaalin tarkkuudella). Tätä kenttää ei palauteta, jos tehtävä ei ole valmis.

## Virheenkäsittely

APIa kutsuttaessa API palauttaa vastaavan virhekoodin ja -tiedot, jos virhe kohdataan. Esimerkiksi:

- `400 token_mismatched`: Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Virheellinen pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Ei valtuutettu, virheellinen tai puuttuva valtuutustunnus.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, palvelimella tapahtui jokin virhe.
