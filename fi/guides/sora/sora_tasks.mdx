Sora Tasks API:n päätoiminto on kysyä tehtävän suoritusstatus syöttämällä Sora Videos Generation API:n tuottama tehtävä-ID.

Tässä asiakirjassa käsitellään Sora Tasks API:n liittämistä, jotta voit helposti integroida ja hyödyntää tämän API:n voimakkaita ominaisuuksia. Sora Tasks API:n avulla voit helposti kysyä Sora Videos Generation API:n tehtävän suoritusstatus.

## Hakuprosessi

Käyttääksesi Sora Tasks API:a, sinun on ensin mentävä hakusivulle [Sora Videos Generation API](https://platform.acedata.cloud/documents/99a24421-2e22-4028-8201-e19cb834b67e) ja haettava vastaavaa palvelua, sitten kopioit Sora Videos Generation API:n tehtävä-ID:n, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/za62pb.png" width="500" class="m-auto"></p>

Lopuksi siirry Tasks API -sivulle [Sora Tasks API](https://platform.acedata.cloud/documents/c9d81bad-9064-4796-86b6-4fb43cc93a16) ja hae vastaavaa palvelua, siirryttyäsi sivulle, napsauta "Acquire" -painiketta, kuten kuvassa näkyy:

![Hakusivu](https://cdn.acedata.cloud/rci31i.png)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti [kirjautumissivulle](https://platform.acedata.cloud), jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Kirjautumisen ja rekisteröitymisen jälkeen sinut ohjataan automaattisesti takaisin nykyiselle sivulle.

Ensimmäisellä hakukerralla saat ilmaisia krediittejä, joita voit käyttää API:n ilmaiseksi.

## Pyyntöesimerkki

Sora Tasks API:a voidaan käyttää Sora Videos Generation API:n tulosten kysymiseen. Lisätietoja Sora Videos Generation API:n käytöstä löytyy asiakirjasta [Sora Videos Generation API](https://platform.acedata.cloud/documents/sora-videos-integration).

Otetaan esimerkki yhdestä Sora Videos Generation API:n palauttamasta tehtävä-ID:stä ja näytetään, kuinka tätä API:a käytetään. Oletetaan, että meillä on tehtävä-ID: b8976e18-32dc-4718-9ed8-1ea090fcb6ea, seuraavaksi näytetään, kuinka siirretään tämä tehtävä-ID.

### Pyyntöotsikon ja -kehon asettaminen

**Request Headers** sisältää:

- `accept`: määrittää, että vastaanotetaan JSON-muotoisia vastauksia, tässä täytetään `application/json`.
- `authorization`: API:n kutsuavain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

**Request Body** sisältää:

- `id`: ladattu tehtävä-ID.
- `action`: tehtävän toimintatapa.

Aseta kuten alla olevassa kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/fe19dd.png" width="500" class="m-auto"></p>

### Koodiesimerkki

Voit huomata, että sivun oikealla puolella on automaattisesti luotu koodia eri kielillä, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/ou5lfa.png" width="500" class="m-auto"></p>

Osittainen koodiesimerkki on seuraava:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/sora/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/sora/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Virheiden käsittely

API:ta kutsuttaessa, jos kohtaat virheitä, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Ei valtuutettu, virheellinen tai puuttuva valtuutustoken.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki
