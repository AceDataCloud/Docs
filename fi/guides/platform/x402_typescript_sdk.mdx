TypeScript on yksi suositelluimmista tavoista integroida Ace Data Cloud X402. Virallinen SDK vastaa tavallisista API-kutsuista, tehtävien kyselystä, virheenkäsittelystä ja automaattisista uudelleenyrityksistä; `@acedatacloud/x402-client` vastaa `PAYMENT-SIGNATURE`-pyyntöotsakkeen allekirjoittamisesta kohdattaessa `402 Payment Required`.

Lähdekoodin ja pakettien osoitteet:

- SDK-tietovarasto: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- X402 Client -tietovarasto: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm SDK: [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)
- npm X402 Client: [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client)

## Riippuvuuksien asentaminen

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client
```

Jos käytetään Basea, tarvitaan EVM-allekirjoitusominaisuus:

```bash
npm install ethers
```

Jos käytetään Solanaa, tarvitaan Solana wallet adapter tai `@solana/web3.js`:

```bash
npm install @solana/web3.js
```

Puhtaan npm-projektin asennuksen ja tuonnin tarkistuksen tuloste:

```text
imports_ok true true true true true
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4
```

Tulosten selitys:

- `@acedatacloud/sdk` ja `@acedatacloud/x402-client` voidaan molemmat asentaa npm:stä ja tuoda Node.js:ssä.
- `ethers` käytetään EVM typed data -allekirjoituksiin, `@solana/web3.js` Solana-transaktioiden muodostamiseen.

## Base-esimerkki

Selaimessa voidaan käyttää suoraan `window.ethereum`-objektia. Node.js:ssä `ethers.Wallet` voidaan kääriä EIP-1193-tyyliseksi provideriksi.

```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});

console.log(result.choices[0].message.content);
```

## Selainlompakkoesimerkki

Kun frontend-sovelluksessa käytetään MetaMaskia, Coinbase Walletia tai WalletConnectia, EIP-1193-provider välitetään yleensä suoraan:

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const [address] = await window.ethereum.request({ method: 'eth_requestAccounts' });

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider: window.ethereum,
    evmAddress: address
  })
});

const image = await client.images.generate({
  provider: 'nano-banana',
  prompt: 'a yellow banana on a white background'
});
```

Selainlompakko näyttää allekirjoituksen vahvistusikkunan. Käyttäjä ei allekirjoita mielivaltaista viestiä, vaan API:n palauttaman maksuvaatimuksen: vastaanottajan osoite, USDC-sopimus, summa, voimassaoloaika ja nonce sisältyvät kaikki allekirjoitukseen.

## Solana-esimerkki

Solana käyttää SPL USDC `TransferChecked` -toimintoa. Välitetyn wallet adapterin on tarjottava `publicKey` ja `signAndSendTransaction`.

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'solana',
    solanaWallet: phantomWallet
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});
```

Solana-polku tukee tällä hetkellä vain `exact`-vaihtoehtoa, ei `upto`-vaihtoehtoa. Jos API palauttaa useita `accepts`-arvoja, handler valitsee kohdan, jonka `network = 'solana'`.

Solana-polulla on varmennettu, että maksullinen uudelleenyritys samalla julkisella API:lla voi palauttaa HTTP 200:n ja `ADC_SOLANA_E2E_OK`:n. Julkisia RPC-kyselyitä voidaan rajoittaa, joten tässä artikkelissa ei ilmoiteta Solana tx hashia; kun tarvitset ketjukirjanpidon täsmäytystä, käytä omaa Solana RPC:täsi tai vahvista tiedot konsolilokeista.

## `exact`- tai `upto`-vaihtoehdon valitseminen

Nykyinen TypeScript-handler valitsee ensimmäisen palvelimen palauttaman kohdeverkkoa vastaavan payment requirementin. Ace Data Cloudin API sijoittaa yleensä saman verkon `exact`-vaihtoehdon ennen `upto`-vaihtoehtoa, joten jos haluat nimenomaisesti käyttää jälkikäteen tapahtuvaa mittausta, sinun on välitettävä `preferScheme: 'upto'`.

Esimerkki:

```ts
const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address,
    preferScheme: 'upto'
  })
});
```

Jos palvelin ei palauta kyseisen verkon `upto` requirementia, handler palaa automaattisesti kyseisen verkon ensimmäiseen käytettävissä olevaan requirementiin, joka on yleensä `exact`.

`upto` vaatii kertaluonteisen Permit2-valtuutuksen. `upto` on tällä hetkellä saatavilla vain Basessa, joten Base USDC:lle tarvitsee tehdä vain yksi valtuutus:

```bash
npx tsx scripts/approve-permit2.ts --network base
```

Base `upto` on suorittanut julkisen API-varmennuksen: HTTP 402 -> HTTP 200, ja jälkikäteen tapahtuvan settlementin tx on `0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036`. Katso koko tuloste laskutusmallin kuvauksesta.

## Mitä SDK tekee

`@acedatacloud/sdk`-paketin transport suorittaa payment handlerin kerran saatuaan 402-vasteen:

```ts
type PaymentHandler = (ctx: {
  url: string;
  method: string;
  body?: unknown;
  accepts: PaymentRequirement[];
}) => Promise<{ headers: Record<string, string> }>;
```

`@acedatacloud/x402-client`-paketin palauttama handler:

1. Valitsee `ctx.accepts`-arvoista kohdeverkon payment requirementin.
2. Muodostaa verkon mukaan EVM EIP-712 -allekirjoituksen tai Solana-siirtotransaktion.
3. Sarjallistaa envelopen Base64-muotoon.
4. Palauttaa `{ headers: { 'PAYMENT-SIGNATURE': '<base64>' } }`.
5. SDK yrittää automaattisesti uudelleen alkuperäisellä pyyntötekstillä.

Tämä tarkoittaa, että liiketoimintakoodi tarvitsee kirjoittaa vain tavallisen SDK-kutsun tavoin, eikä 402-uudelleenyritystä tarvitse käsitellä manuaalisesti.
