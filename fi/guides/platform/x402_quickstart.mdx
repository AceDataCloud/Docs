Tämä opas havainnollistaa Ace Data Cloud X402:n koko prosessin yhdellä pienimmällä API-pyynnöllä. Tavoitteena ei ole kirjoittaa ensin monimutkaista koodia, vaan ymmärtää ensin: miksi ensimmäinen pyyntö palauttaa 402:n, mitä `accepts` sisältää ja miten `PAYMENT-SIGNATURE` muuttaa saman API-pyynnön maksetuksi pyynnöksi.

## Valmistelut

Tarvitset:

| Kohde   | Kuvaus                                                   |
| ---- | ---------------------------------------------------- |
| Lompakko   | Kohdeverkkoa tukeva lompakko. Base käyttää EVM-lompakkoa, Solana käyttää Solana-lompakkoa.      |
| USDC | Lompakossa on oltava riittävästi USDC:tä. Todellinen määrä määräytyy 402-vastauksen `maxAmountRequired`-arvon mukaan. |
| Kehitysympäristö | TypeScriptille suositellaan Node.js 18+:aa; Pythonille suositellaan Python 3.10+:aa.    |
| SDK  | Virallisen SDK:n käyttöä suositellaan, allekirjoituksen yksityiskohtien kirjoittamista käsin ei suositella.                                |

X402 ei tarvitse API Tokenia kutsuttaessa Ace Data Cloud API:a. SDK:n ensimmäinen pyyntö ei sisällä `Authorization`-otsaketta, Gateway palauttaa `402 Payment Required` -vastauksen ja maksuvaatimukset; SDK yrittää allekirjoituksen jälkeen automaattisesti uudelleen.

## SDK:n asennus

Lähdekoodi- ja pakettiosoitteet:

- SDK-tietovarasto: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- X402 Client -tietovarasto: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm: `@acedatacloud/sdk`, `@acedatacloud/x402-client`
- PyPI: `acedatacloud`, `acedatacloud-x402`

TypeScript:

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client ethers
```

Python:

```bash
pip install acedatacloud acedatacloud-x402
```

Jos haluat käyttää Solanaa, sinun on myös asennettava vastaavat riippuvuudet:

```bash
npm install @solana/web3.js
```

Python-version Solana signer -riippuvuus sisältyy jo pakettiin `acedatacloud-x402`.

Puhtaan väliaikaisen ympäristön asennus- ja tuontitarkistuksen tuloste:

```text
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4

acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
```

Tulosten selitys:

- Sekä npm-paketit että PyPI-paketit ovat oikeasti julkaistuja paketteja, eivät dokumentaation paikkamerkkinimiä.
- `acedatacloud-x402[cli]` asentaa CLI:n, ja `approve-permit2`-alikomentoa voidaan käyttää Permit2-valtuutukseen `upto`-tapauksissa.

## Ensimmäinen pyyntö palauttaa 402:n

Voit ensin katsoa `curl`illa, mitä maksamaton pyyntö palauttaa. Alla oleva esimerkki ei aiheuta veloitusta, koska se ei sisällä `PAYMENT-SIGNATURE`-otsaketta:

```bash
curl -sS -X POST https://x402.acedata.cloud/openai/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "hi"}],
    "max_tokens": 1
  }'
```

Vastausrakenne sisältää `accepts`-taulukon, jonka tyypillinen rakenne on seuraava:

```json
{
  "x402Version": 2,
  "resource": {
    "url": "/openai/chat/completions",
    "description": "AceDataCloud API call",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "maxAmountRequired": "95215",
      "amount": "95215",
      "maxTimeoutSeconds": 3600,
      "resource": "/openai/chat/completions",
      "description": "...",
      "payTo": "0x...",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913"
      }
    }
  ],
  "error": "PAYMENT-SIGNATURE header is required"
}
```

Sama haasteen sisältö sijoitetaan myös base64-muodossa `PAYMENT-REQUIRED`-vastausotsakkeeseen, jotta asiakas voi lukea maksuvaatimukset jäsentämättä bodya.

Tuotanto-API:n maksamattoman pyynnön ohjelmatulosteen yhteenveto on seuraava:

```text
status=402
x402Version 2
accepts [
  ('eip155:8453', 'exact', '95215'),
  ('eip155:8453', 'upto', '95215'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '95215'),
]
```

Tulosten selitys:

- Ensimmäinen pyyntö ei sisältänyt `Authorization`- tai `PAYMENT-SIGNATURE`-otsaketta, joten se palauttaa HTTP 402:n eikä aiheuta veloitusta.
- `accepts` on tämän pyynnön ainoa luotettava allekirjoitusperuste, ja se sisältää valinnaiset verkot, schemet, määrän ylärajan, vastaanottajan osoitteen ja varallisuuden osoitteen.
- `network` on CAIP-2-tunniste, ja asiakkaan on verkkoa valitessaan täsmättävä CAIP-2-merkkijonon mukaan.
- Tämän `gpt-4o-mini`-pienimmän chat-pyynnön enimmäismäärä on `95215` atomic USDC:tä eli `0.095215` USDC:tä.
- Jokaisen pyynnön on luettava kyseisen pyynnön 402-vastaus; esimerkkimäärää ei pidä kovakoodata liiketoimintakoodiin.

Kenttien merkitykset:

| Kenttä                  | Kuvaus                                                             |
| ------------------- | -------------------------------------------------------------- |
| `scheme`            | Maksujärjestelmä. `exact` tarkoittaa kiinteää määrää, `upto` tarkoittaa valtuutusrajaa ja laskutusta todellisen käytön mukaan.                     |
| `network`           | Maksuverkon CAIP-2-tunniste, esimerkiksi `eip155:8453`, `solana:5eykt4...`.           |
| `maxAmountRequired` | Suurin maksumäärä, yksikkönä USDC atomic units; `95215` tarkoittaa `0.095215` USDC:tä.       |
| `amount`            | Tällä kertaa laskutettava määrä; `exact` on sama kuin `maxAmountRequired`, kun taas `upto` kirjoitetaan laskutusvaiheessa uudelleen todellisen käytön mukaan. |
| `payTo`             | Vastaanottajan osoite.                                                          |
| `asset`             | USDC-sopimusosoite tai Solana mint -osoite.                                     |
| `extra`             | Allekirjoituksessa tarvittavat laajennustiedot, kuten ketjutunnus, EIP-712 domain ja Permit2-osoite.                      |

## Maksun uudelleenyritys SDK:lla

Alla on pienin TypeScript-esimerkki. Se määrittää `network: 'base'`, ja handler valitsee tämänkertaisesta 402-vastauksesta Basen payment requirementin; todellinen määrä ja vastaanottajan osoite määräytyvät silti `accepts`-arvon mukaan:
```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const response = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Reply with exactly: hello' }],
  max_tokens: 8
});

console.log(response.choices[0].message.content);
```

Tämän koodin taustalla tapahtuu neljä vaihetta:

1. SDK lähettää tavallisen API-pyynnön ilman `Authorization`-otsaketta.
2. Gateway palauttaa `402 Payment Required`-vastauksen ja `accepts`-tiedot.
3. `createX402PaymentHandler` valitsee payment requirementin, jossa `network = 'base'`, ja allekirjoittaa `PAYMENT-SIGNATURE`-otsakkeen.
4. SDK yrittää uudelleen samalla pyyntörungolla, ja Gateway kutsuu Facilitatoria vahvistamaan ja selvittämään maksun ennen kuin se päästää pyynnön kohde-APIin.

## Facilitatorin tukemien ominaisuuksien tarkastelu

X402 API ei ole riippuvainen resurssihakemistosta. Asiakas kutsuu suoraan tunnettua APIa ja käyttää kyseisen pyynnön reaaliaikaisesti palauttamia
`402 Payment Required`- ja `accepts`-tietoja ainoana hinnan ja allekirjoituksen perusteena.

Facilitatorin ominaisuusilmoitus sijaitsee osoitteessa:

```bash
curl https://facilitator.acedata.cloud/.well-known/x402
```

Se kuvaa vain `/supported`-, `/verify`- ja `/settle`-päätepisteet sekä tällä hetkellä käytössä olevat maksuverkot, eikä luettele API-resursseja.

Ace Data Cloudin tuotanto-Facilitatorin osoite on:

```text
https://facilitator.acedata.cloud
```

Voit tarkastella, mitä verkkoja ja schemeja se tukee:

```bash
curl https://facilitator.acedata.cloud/supported
```

Palautetut `kinds`-tiedot luettelevat Facilitatorin tukemat verkot ja schemet. Todellisissa kutsuissa API:n palauttama `accepts` on edelleen ratkaiseva.

Facilitatorin `/supported`-tuloste:

```text
kinds [
  ('eip155:8453', 'exact'),
  ('eip155:8453', 'upto', {'facilitatorAddress': '0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708'}),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact')
]
```

Tulokset tarkoittavat:

- `/supported` osoittaa, että Facilitatorilla on näiden verkkojen ja schemejen vahvistus- ja selvitysominaisuudet.
- Sekä Base että Solana tukevat `exact`-schemeä; `upto` on tällä hetkellä saatavilla vain Basessa.
- Se, salliiko tietty API tietyn verkon, määräytyy edelleen kyseisen API:n 402-vastauksen `accepts`-tietojen mukaan.
