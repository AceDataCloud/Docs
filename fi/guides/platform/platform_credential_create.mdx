Luo liiketoiminta-API-käyttöoikeustiedot yhdelle Applicationille. Luontivastaus voi sisältää Tokenin, jolla voi kutsua suoraan `https://api.acedata.cloud/**`, tai Proxy-tyyppisten käyttöoikeustietojen käyttäjänimen/salasanan; niitä on käsiteltävä salaisuuksina.

## Valmistelut

1. Luo [Account Token](https://platform.acedata.cloud/documents/platform-token).
2. Hae omistamasi `application_id` [Application-luettelosta](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='tilisi tunniste'
export APPLICATION_ID='Application ID:si'
```

## Rajapinnan yleiskatsaus

| Kohta    | Sisältö                                                   |
| ---- | ---------------------------------------------------- |
| Menetelmä   | `POST`                                               |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/` |
| Todennus   | Account Token, OAuth-token tarvitsee `credentials:write`      |
| Body | JSON                                                 |

## Pyyntörunko

| Kenttä                  | Tyyppi              | Pakollinen  | Kuvaus                            |
| ------------------- | --------------- | --- | ----------------------------- |
| `application_id`    | UUID            | Kyllä   | Kohde-Application                |
| `name`              | string          | Ei   | Käyttöoikeustietojen näyttönimi                         |
| `limited_amount`    | number / null   | Ei   | Yhden käyttöoikeustiedon käyttöraja; `null` tarkoittaa, ettei erillistä rajaa aseteta       |
| `expired_at`        | datetime / null | Ei   | ISO 8601 -vanhenemisaika                 |
| `allowed_api_ids`   | UUID[] / null   | Ei   | Sallitaan vain näiden APIen kutsuminen; tyhjä taulukko normalisoidaan rajoittamattomaksi       |
| `host`              | string          | Ei   | Käyttöoikeustietojen host-tiedot                    |
| `for_user_id`       | string          | Ei   | Käytetään, kun Applicationin omistaja myöntää valtuutetut käyttöoikeustiedot toiselle käyttäjälle |
| `tags` / `metadata` | array / object  | Ei   | Mukautetut laajennustiedot                       |

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/credentials/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"name\":\"production\",\"limited_amount\":50}"
```

## Vastauksen kuvaus

Onnistunut pyyntö palauttaa `201`-vastauksen ja Credential-objektin:

- API/Agent-tyyppiset palvelut palauttavat yleensä `type=Token` ja `token`;
- Proxy-tyyppiset palvelut palauttavat yleensä `type=Identity` sekä `username` / `password`, ja yksi Proxy Application sallii vain yhden käyttöoikeustiedon;
- `id`, `user_id`, `creator_id`, `used_amount` ja aikakentät luodaan palvelinpuolella.

Nykyiset luettelo- ja tietorajapinnat palauttavat myös käyttöoikeustietojen selväkieliset arvot, mutta asiakkaan ei tulisi luottaa tähän historialliseen toimintatapaan. Tallenna ne välittömästi luomisen jälkeen ja vältä vastauksen kirjoittamista lokeihin; tulevat rajapinnat voivat palauttaa peitetyt arvot.

## Virheenkäsittely

- `400`: kenttämuotovirhe, tuntematon `allowed_api_ids`, Proxy Applicationilla on jo käyttöoikeustiedot tai muut luontirajoitukset.
- `401`: Account Token on virheellinen.
- `403/404`: ei oikeutta käyttää kohde-Applicationia, tai Application-/valtuutettua käyttäjää ei ole olemassa.
