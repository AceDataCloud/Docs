Hae aktiivisesti tilauksen maksutapaa vastaava uusin tila ja synkronoi se alustalle. Tämä pyyntö voi käyttää maksupalvelua ja muuttaa tilauksen tilaa, joten käytä sitä vain, kun takaisinsoitto viivästyy tai välitön vahvistus on tarpeen.

## Valmistelut

- Käytä [Account Tokenia](https://platform.acedata.cloud/documents/platform-token).
- Hae oma tilauksesi ID [tilausluettelosta](https://platform.acedata.cloud/documents/platform-order-list).

```shell
export PLATFORM_TOKEN='tilisi tunniste'
export ORDER_ID='tilauksesi ID'
```

## Rajapinnan yleiskatsaus

| Kohta    | Sisältö                                                                 |
| ---- | ------------------------------------------------------------------ |
| Menetelmä   | `POST`                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/refresh/` |
| Todennus   | Tilauksen omistaja tai pääkäyttäjä                                                        |
| Body | Yleensä tyhjä; PayPal-takaisinsoittotilanteessa voidaan tarvita `payer_id` / `PayerID`                         |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/refresh/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Onnistunut pyyntö palauttaa päivitetyn täydellisen Order-objektin. Käytä `state`-kenttää tuloksen määrittämiseen ja `finished_at`-kenttää valmistumisajankohtana; nykyisessä mallissa ei ole `paid_at`-kenttää. Tila-arvoja ovat `Pending`, `Paid`, `Finished`, `Expired`, `Failed` ja `Refunded`.

Maksun määräaika muuttaa vain edelleen `Pending`-tilassa olevat tilaukset `Expired`-tilaan. Hyvitetyt `Refunded`-tilaukset pysyvät hyvitettyinä myös päivityksen tai viivästyneen maksun takaisinsoiton vastaanottamisen jälkeen.

## Uudelleenyrityssuositukset

- Tavallisissa maksuissa luota ensisijaisesti alustan takaisinsoittoon; tee aktiivinen refresh vain, jos tila ei päivity pitkään aikaan.
- Älä käytä kiinteää korkean taajuuden kyselyä. Eksponentiaalista takaisinvetoviivettä suositellaan, ja lopeta, kun selkeä lopputila on saavutettu.
- `401` tarkoittaa, että tunniste on virheellinen; `403` tarkoittaa, ettet ole tilauksen omistaja; `404` tarkoittaa, ettei tilausta ole olemassa.
- Jos maksupalvelun kysely epäonnistuu, säilytä tilauksen ID ja trace ID ja yritä myöhemmin uudelleen; älä luo päällekkäisiä tilauksia tilan vahvistamisen korvaamiseksi.
