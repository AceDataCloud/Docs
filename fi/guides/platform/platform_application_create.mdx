”Hakemus (Application)” tarkoittaa nykyisen tilin tilaussuhdetta tiettyyn palveluun — hakemus on tehtävä ensin, ennen kuin sille voidaan luoda API-tunnistetiedot ja kutsua liiketoimintarajapintoja. Kun palvelua haetaan ensimmäisen kerran, Application saa palvelun nykyisen `free_amount`-asetuksen; arvo voi olla 0.

> ℹ️ Tämä rajapinta kuuluu **AceDataCloud-alustan hallinta-APIin**, jonka yhtenäinen etuliite on `https://platform.acedata.cloud/api/v1/`. Täydellinen rajapintaluettelo löytyy kohdasta [AceDataCloud-alustan dokumenttiluettelon hakeminen](https://platform.acedata.cloud/documents/platform-document-list).

## Täydellinen integraatioprosessi

Uudet käyttäjät käyvät yleensä nämä 5 vaihetta rekisteröitymisestä ensimmäisen liiketoimintarajapinnan käyttöönottoon:

1. **Hanki tilitunnus** → [AceDataCloud-alustan tilitunnusten hallinta](https://platform.acedata.cloud/documents/platform-token)
2. **Valitse palvelu** → [AceDataCloud-alustan palveluluettelon hakeminen](https://platform.acedata.cloud/documents/platform-service-list)
3. **Luo hakemus** (tämä dokumentti) → Saat alkuperäisen käyttömäärän palvelun asetusten mukaisesti
4. **Luo API-tunnistetiedot** → [AceDataCloud-alustan API-tunnistetietojen luominen](https://platform.acedata.cloud/documents/platform-credential-create)
5. **Kutsu liiketoimintarajapintaa** → Käytä saatua 32-merkkistä Tokenia osoitteessa `https://api.acedata.cloud/<path>`

## Rajapinnan yleiskatsaus

| Kohta            | Sisältö                                                    |
| ------------ | ----------------------------------------------------- |
| Menetelmä           | `POST`                                                |
| URL          | `https://platform.acedata.cloud/api/v1/applications/` |
| Todennus           | ✅ Tilitunnus vaaditaan                                              |
| Content-Type | `application/json`                                    |

## Todennuksen ohjeet (miten tilitunnus hankitaan)

Pyyntöotsikko:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Tilitunnus (Account Token) on ”tilitason avain”, jolla kehittäjät hallitsevat omia tiliresurssejaan API:n kautta. Hankintatavat:

1. **Luonti yhdellä napsautuksella konsolissa (suositellaan)**: Kirjaudu [AceDataCloud-alustalle](https://platform.acedata.cloud) → [Account Token -konsoli](https://platform.acedata.cloud/console/platform-tokens) → napsauta ”Luo”, niin saat `platform-v1-`-alkuisen tunnuksen.
2. **Luonti API:n kautta**: Käytä olemassa olevaa tilitunnusta tai selaimen kirjautumisistunnon JWT:tä kutsuaksesi `POST /api/v1/platform-tokens/`; lisätietoja kohdassa [AceDataCloud-alustan tilitunnusten hallinta](https://platform.acedata.cloud/documents/platform-token).

> ⚠️ Tilitunnus on yhtä arkaluonteinen kuin salasana, eikä sitä saa kirjoittaa käyttöliittymäkoodiin tai julkisiin tietovarastoihin. Jos se vuotaa, poista se välittömästi konsolissa ja luo uusi.

## Pyynnön runko

| Parametri           | Tyyppi   | Pakollinen  | Kuvaus                                                                                                  |
| ------------ | ---- | --- | --------------------------------------------------------------------------------------------------- |
| `service_id` | UUID | ✅   | Haettavan palvelun ID. Sen voi saada [palveluluettelon](https://platform.acedata.cloud/documents/platform-service-list) kentästä `items[].id` |

## Pyyntöesimerkit

### cURL

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/applications/' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'content-type: application/json' \
  -d '{"service_id": "38ecf158-36f2-42f2-8e7f-6786cdfc2452"}'
```

### Python

```python
import os
import requests

PLATFORM_TOKEN = os.environ["PLATFORM_TOKEN"]
SERVICE_ID = "38ecf158-36f2-42f2-8e7f-6786cdfc2452"

resp = requests.post(
    "https://platform.acedata.cloud/api/v1/applications/",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {PLATFORM_TOKEN}",
        "content-type": "application/json",
    },
    json={"service_id": SERVICE_ID},
    timeout=10,
)

if resp.status_code == 201:
    app = resp.json()
    print(f"申请成功！application_id={app['id']}")
    print(f"初始额度：{app['remaining_amount']} {app.get('service', {}).get('unit', '')}")
elif resp.status_code == 400 and resp.json().get("code") == "duplication":
    print("⚠️ 已经申请过此服务，请到 /applications/ 列表里找到现成的 application_id")
else:
    print(f"申请失败：HTTP {resp.status_code} - {resp.text}")
```

### Node.js

```javascript
const PLATFORM_TOKEN = process.env.PLATFORM_TOKEN
const SERVICE_ID = '38ecf158-36f2-42f2-8e7f-6786cdfc2452'

const resp = await fetch('https://platform.acedata.cloud/api/v1/applications/', {
  method: 'POST',
  headers: {
    accept: 'application/json',
    authorization: `Bearer ${PLATFORM_TOKEN}`,
    'content-type': 'application/json',
  },
  body: JSON.stringify({ service_id: SERVICE_ID }),
})

if (resp.status === 201) {
  const app = await resp.json()
  console.log('application_id =', app.id)
} else {
  console.error(await resp.text())
}
```

### Haettu jo (HTTP 400)

```json
{
  "detail": "Item already exists.",
  "code": "duplication",
  "trace_id": "1a87524f8cbba0b790b2951e2e43117e"
}
```

Tämä on suunnittelun mukainen tiukka rajoitus: **jokaisella käyttäjällä voi olla vain yksi Application kutakin palvelua kohden**. Jos sellainen on jo olemassa, etsi olemassa oleva [AceDataCloud-alustan palveluhakemusluettelosta](https://platform.acedata.cloud/documents/platform-application-list).

### Palvelua ei ole olemassa (HTTP 404)

```json
{
  "detail": "Service not found.",
  "code": "not_found",
  "trace_id": "..."
}
```

### Palvelu vaatii tarkistuksen (HTTP 403)

```json
{
  "detail": "This service requires manual verification.",
  "code": "need_verify",
  "trace_id": "..."
}
```

Jos palvelulla on `need_verify=true` (kenttä näkyy palveluluettelossa), valkoista listaa on haettava tukipyyntöprosessin kautta.

## Virheiden käsittely
| HTTP | koodi               | Merkitys                   |
| ---- | ------------------- | -------------------------- |
| 400  | `duplication`       | Nykyinen tili on jo hakenut tätä palvelua |
| 400  | `invalid`           | `service_id` puuttuu tai sen muoto on virheellinen |
| 401  | `not_authenticated` | Tilitunnus puuttuu tai tunnus on poistettu |
| 403  | `need_verify`       | Palvelu vaatii tarkastuksen, käytä tukipyyntöprosessia |
| 404  | `not_found`         | Palvelua ei ole olemassa tai se on poistettu käytöstä |

Virhevastausten yhtenäinen muoto:

```json
{
  "detail": "...",
  "code": "...",
  "trace_id": "..."
}
```

## Käytännön vinkit

- **Luominen itsessään ei veloita**: ensimmäisellä luontikerralla alkuperäinen kiintiö asetetaan palvelun nykyisen `free_amount`-arvon mukaan; tämä arvo voi olla 0, eikä samanlaisen Applicationin uudelleenluonti takaa toistuvaa ilmaista myöntöä.
- **Katso `paid`-kentästä, vaaditaanko maksua**: heti hakemisen jälkeen `paid=false`, ja se muuttuu arvoksi `true`, kun maksu on suoritettu käyttämällä [AceDataCloud-alustan lataustilauksen luomista](https://platform.acedata.cloud/documents/platform-order-create).
- **`disabled=true` tarkoittaa, että se on tilapäisesti poistettu käytöstä**—esimerkiksi riskienhallinnan laukeamisen, maksamattomien laskujen jne. vuoksi. Kun se on poistettu käytöstä, liiketoimintarajapinta palauttaa `403`.
- **Älä luo rajattomasti rinnakkain**: hae ensin kohde-`service_id` sivutetusta palveluluettelosta ja hae sitten kohteita yksitellen liiketoimintatarpeiden mukaan; kun kohtaat `duplication`-virheen, käytä olemassa olevaa Applicationia uudelleen.
