Ace Data Cloud X402 keskittyy tällä hetkellä USDC-selvitykseen ja tukee kahta ketjutyyppiä: EVM:ää ja Solanaa. Eri verkkojen allekirjoitustavat, omaisuusosoitteet, gas-käyttäytyminen ja soveltuvat käyttötapaukset eroavat toisistaan, joten verkko on valittava ennen integraatiota.

## Verkkoidentifikaattori käyttää CAIP-2:ta

x402 v2:n `accepts[].network` on CAIP-2-tunniste, ei lyhenne kuten `base` tai `skale`. Asiakkaan on verrattava verkkoja CAIP-2-merkkijonon perusteella:

| Verkko             | CAIP-2-tunniste                              |
| -------------- | ----------------------------------------- |
| Base           | `eip155:8453`                             |
| SKALE Base     | `eip155:1187947933`                       |
| Solana mainnet | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` |

## Tukimatriisi

| Verkko     | scheme  | Omaisuus                  | Allekirjoitustapa                                 | Soveltuva käyttötapa                        |
| ------ | ------- | ------------------- | ------------------------------------ | --------------------------- |
| Base   | `exact` | Base USDC           | EIP-3009 `TransferWithAuthorization` | Oletussuositus, lompakko- ja likviditeettituki ovat kypsiä.            |
| Base   | `upto`  | Base USDC + Permit2 | Permit2 `PermitWitnessTransferFrom`  | Jälkimittaukselliset API:t, kuten chat ja mallit.             |
| SKALE  | `exact` | SKALE bridged USDC  | EIP-3009 `TransferWithAuthorization` | Alhaiset gas-kustannukset, sopii EVM-maksujen varmennukseen ja edullisiin kutsuihin. |
| Solana | `exact` | Solana USDC         | SPL `TransferChecked`                | Solana-lompakot, Agentit tai ketjusovellusten käyttötapaukset.    |

`upto` on tällä hetkellä saatavilla vain Basessa. Todelliset käytettävissä olevat kohteet määräytyvät API:n palauttaman `accepts`-arvon mukaan. Voit myös tarkastella Facilitatoria:

```bash
curl https://facilitator.acedata.cloud/supported
```

Facilitatorin `/supported`-palautus:

```json
{
  "kinds": [
    { "x402Version": 2, "scheme": "exact", "network": "eip155:8453" },
    {
      "x402Version": 2,
      "scheme": "upto",
      "network": "eip155:8453",
      "extra": { "facilitatorAddress": "0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708" }
    },
    { "x402Version": 2, "scheme": "exact", "network": "eip155:1187947933" },
    {
      "x402Version": 2,
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "extra": { "feePayer": "3SPm6qbgsDkj24MuR8Ss4sH97fziqyCiqFKDyeVU2igq" }
    }
  ]
}
```

Tulosten selitys:

- Basen, SKALEn ja Solanan `exact` ovat kiinteän summan maksupolkuja.
- Vain Base tarjoaa `upto`-jälkimittauspolun, joka edellyttää Permit2-approvea.
- `upto`-merkinnän `extra.facilitatorAddress` on osoite, joka asiakkaan on kirjoitettava witnessiin allekirjoittaessaan, ja sen on vastattava palvelimen palauttamaa arvoa.

## Base

Base käyttää virallista USDC-sopimusta:

```text
0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
```

`exact`-mallissa asiakas allekirjoittaa EIP-712 `TransferWithAuthorization` -pyynnön. Allekirjoituksen sisältöön kuuluvat:

- `from`: maksavan lompakon osoite
- `to`: Ace Data Cloudin vastaanotto-osoite
- `value`: tämän maksun summa
- `validAfter` / `validBefore`: allekirjoituksen voimassaoloaikaikkuna
- `nonce`: 32 tavun satunnainen nonce

Kun Facilitator on varmistanut allekirjoituksen, se kutsuu ketjussa USDC:n `transferWithAuthorization`-toimintoa siirron suorittamiseksi.

Base on suositelluin verkko varsinaiseen integraatioon, erityisesti `upto`-jälkimittaukseen, koska Permit2-, USDC- ja lompakkoekosysteemi ovat kaikki kypsempiä.

Esimerkki Base `exact` -varmennustuloksesta:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
content ADC_BASE_E2E_OK
tx 0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
block 46726299
explorer https://basescan.org/tx/0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
transfer value 95215 atomic USDC
```

Tulosten selitys:

- API:n paid retry palauttaa mallisisällön `ADC_BASE_E2E_OK`.
- Ketjutapahtuma on tarkasteltavissa BaseScanissa, ja lohkon numero on `46726299`.
- `95215` atomic USDC vastaa `0.095215` USDC:tä, joka on tämän API-kutsun todellinen selvityssumma.

Tilauksen maksun Base `exact` -ohjelman suoritustulos:

```text
order 78481793-304e-47f7-bc0c-8231aec9cc1e
state Finished
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer value 1200000 atomic USDC
```

Tulosten selitys:

- Alustan tilauksen lopullinen tila on `Finished`.
- Tilauksen `pay_id`-kenttään kirjoitetaan sama Base-tapahtumahajautus.
- `1200000` atomic USDC vastaa `1.2` USDC:tä, joka on tämän 10 Credits -tilauksen historiallinen tosiasiallisesti maksettu summa vanhan käytännön mukaisesti; uudet tilaukset eivät enää saa ylimääräistä X402-maksutapa-alennusta, ja tarkka allekirjoitettava summa määräytyy tämän 402-vastauksen perusteella.

## SKALE

SKALE käyttää bridged USDC:tä, ja allekirjoitustapa on Basen kaltainen, eli myös EIP-3009. Se soveltuu alhaisten gas-kustannusten EVM-maksutilanteisiin; todelliset kutsut määräytyvät edelleen API:n palauttaman `accepts`-arvon mukaan.

SKALEn tyypillinen 402 `accepts` sisältää:

```json
{
  "network": "eip155:1187947933",
  "scheme": "exact",
  "extra": {
    "name": "Bridged USDC (SKALE Bridge)",
    "version": "2",
    "chainId": 1187947933,
    "verifyingContract": "0x85889c8c714505E0c94b30fcfcF64fE3Ac8FCb20"
  }
}
```

SKALE tarjoaa tällä hetkellä vain `exact`-mallin. Jos tarvitset jälkimittausta, käytä Base `upto` -mallia.

Esimerkki SKALE `exact` -varmennustuloksesta:

```text
content ADC_SKALE_E2E_OK
tx 0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
block 1969317
explorer https://skale-base-explorer.skalenodes.com/tx/0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
paid 0.095215 USDC
```

Tulosten selitys：
- API:n maksettu uudelleenyritys palautti mallisisällön `ADC_SKALE_E2E_OK`。
- Tapahtuma on haettavissa SKALE explorerista, ja lohkon numero on `1969317`。
- Tämän `exact`-maksun selvityssumma on `0.095215` USDC。

## Solana

Solana käyttää SPL USDC:n `TransferChecked`-siirtoa。Asiakas muodostaa siirtotapahtuman, allekirjoittaa ja lähettää sen, minkä jälkeen se asettaa tapahtuman allekirjoituksen tai sarjoitetun tapahtuman `PAYMENT-SIGNATURE`-envelopeen。

Solanan ominaisuudet：

- Käytä Solana wallet adapteria tai base58-salaista avainta；
- Omaisuus on Solana USDC mint；
- Tällä hetkellä tuetaan vain `exact`-vaihtoehtoa；
- Facilitator tarkistaa siirto-ohjeen mintin, destinationin, authorityn ja amountin。

Jos käytetään lompakon fee payer -tilaa, lompakko lähettää tapahtuman suoraan, ja Facilitator vastaa tapahtuman vahvistamisesta sekä palauttaa settlement-tuloksen。

Esimerkki Solana `exact` -vahvistustuloksesta：

```text
payer AY2RmGm2zPxB1uKvvF4dKyYdr2VySyL3wcD1MKJZoLRd
HTTP 402 -> HTTP 200
content ADC_SOLANA_E2E_OK
chain signature not confirmed in this run
```

Tuloksen selitys：

- Maksettu uudelleenyritys on jo palauttanut HTTP 200:n, ja mallin tuloste on `ADC_SOLANA_E2E_OK`。
- Julkisella RPC:llä tehtävä ketjun signature-kysely saattaa kohdata nopeusrajoituksen。
- Koska julkiset RPC-kyselyt voivat olla nopeusrajoitettuja, Solana exploreriä ei kirjoiteta tähän。Kun tarvitaan tarkkaa täsmäytystä, vahvista tapahtuman signature omalla Solana RPC:llä tai alustan settlement-tietueilla。

## Kuinka valita

| Mitä haluat tehdä        | Suositeltu verkko                         |
| ------------ | ---------------------------- |
| Nopeasti toimiva pienin mahdollinen ketju     | SKALE `exact` tai Base `exact` |
| Tavallisille Web3-käyttäjille | Base                         |
| Chat completionien kaltaiseen jälkimittaukseen   | Base `upto`                  |
| Solana-ekosysteemin sovellukset  | Solana `exact`               |
| Edulliseen EVM-maksujen vahvistukseen | SKALE `exact`                |

Riippumatta siitä, minkä ketjun valitset, älä koodaa hintaa kiinteästi asiakkaaseen。Hinta määräytyy palvelimen palauttaman `accepts[].maxAmountRequired`-arvon perusteella。

## Uudet EVM-verkot

Seuraavien verkkojen natiivin USDC:n kiinteämääräisille maksuille on tarjottu koodituki, ja ne avataan verkko kerrallaan。
Saatavuus määräytyy tilauksen tai API:n palauttaman `accepts`-arvon perusteella；tämä ei tarkoita, että kaikki verkot olisi otettu käyttöön tuotannossa。

| Network      | Alias      | CAIP-2         | Native USDC                                  |
| ------------ | ---------- | -------------- | -------------------------------------------- |
| Arbitrum One | `arbitrum` | `eip155:42161` | `0xaf88d065e77c8cC2239327C5EDb3A432268e5831` |

Nämä verkot tukevat vain `exact`-vaihtoehtoa, ja valuutan tarkkuus on 6。Älä käytä samannimistä siltautettua USDC:tä。
Kun käytät virallista TypeScript/Python X402 Clientia, voit välittää taulukossa olevan lyhenteen tai CAIP-2-tunnisteen。
Asiakas muodostaa allekirjoituksen kohdeketjun ID:llä；lompakon on tuettava kohdeverkkoa。

Phantom-laajennuslompakon virallinen tukitaulukko luettelee Arbitrumin ja Polygonin；Optimism ja Avalanche
eivät tällä hetkellä ole tässä taulukossa, joten voit käyttää kohdeketjua tukevaa Rabbya tai MetaMaskia。EVM-osoite voi olla sama eri ketjuissa，
mutta saldot ovat toisistaan riippumattomia, eikä Solana-osoite sovellu EVM USDC:lle。
Katso [Phantom-lompakon tukitaulukko](https://docs.phantom.com/wallet-sdks-overview#chain-support)。

### Uuden verkon asteittaisen käyttöönoton sisäänpääsy

Uusien ketjujen sisäänpääsy on oletusarvoisesti piilotettu。Kun avaat konsolin tai Studion, voit käyttää `?features=x402-arbitrum`
ottaaksesi vastaavan ketjun käyttöön, ja useat flagit erotetaan pilkulla。Poista yksittäinen ketju käytöstä käyttämällä `?features=-x402-arbitrum`，
ja tyhjennä paikalliset ohitukset käyttämällä `?features=none`。Kytkimet tallennetaan erikseen jokaiselle verkkotunnukselle。
Tilaushinnoittelu ja maksun uudelleenyritys käyttävät samaa kytkintä, palvelin vahvistaa ne erikseen；olemassa olevia maksutietueita voi edelleen tarkastella。
Pelkkä sivun flagin käyttöönotto ei ota käyttöön ketjua, jota ei ole vielä määritetty, ja todelliset maksettavat verkot määräytyvät edelleen reaaliaikaisen `accepts`-arvon perusteella。
