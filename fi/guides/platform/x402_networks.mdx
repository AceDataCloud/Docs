Ace Data Cloud X402 käyttää tällä hetkellä USDC-selvitystä ja tukee kahta ketjutyyppiä: EVM:ää ja Solanaa. Eri verkkojen allekirjoitustavat, omaisuusosoitteet, gas-käyttäytyminen ja soveltuvat käyttötapaukset eroavat toisistaan, joten verkko on valittava ennen integrointia.

## Verkkoidentifikaattori käyttää CAIP-2:ta

x402 v2:n `accepts[].network` on CAIP-2-tunniste, ei lyhenne kuten `base` tai `solana`. Asiakkaan on verrattava verkkoja CAIP-2-merkkijonon perusteella:

| Verkko             | CAIP-2-tunniste                            |
| ------------------ | ------------------------------------------ |
| Base               | `eip155:8453`                              |
| Solana mainnet     | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp`  |

## Tukimatriisi

| Verkko | scheme  | Omaisuus              | Allekirjoitustapa                       | Soveltuvat käyttötapaukset                     |
| ------ | ------- | --------------------- | --------------------------------------- | ----------------------------------------------- |
| Base   | `exact` | Base USDC             | EIP-3009 `TransferWithAuthorization`    | Oletussuositus, lompakko- ja likviditeettituki on kypsä. |
| Base   | `upto`  | Base USDC + Permit2   | Permit2 `PermitWitnessTransferFrom`     | Jälkimittaukselliset API:t, kuten chat ja mallit. |
| Solana | `exact` | Solana USDC           | SPL `TransferChecked`                   | Solana-lompakot, Agentit tai ketjusovellusten käyttötapaukset. |

`upto` tarjotaan tällä hetkellä vain Basessa. Todelliset käytettävissä olevat vaihtoehdot määräytyvät API:n palauttaman `accepts`-arvon mukaan. Voit myös tarkistaa Facilitatorin:

```bash
curl https://facilitator.acedata.cloud/supported
```

Facilitatorin `/supported`-palautus:

```json
{
  "kinds": [
    { "x402Version": 2, "scheme": "exact", "network": "eip155:8453" },
    {
      "x402Version": 2,
      "scheme": "upto",
      "network": "eip155:8453",
      "extra": { "facilitatorAddress": "0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708" }
    },
    {
      "x402Version": 2,
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "extra": { "feePayer": "3SPm6qbgsDkj24MuR8Ss4sH97fziqyCiqFKDyeVU2igq" }
    }
  ]
}
```

Tulosten selitys:

- Basen ja Solanan `exact` ovat kiinteämääräisiä maksupolkuja.
- Vain Base tarjoaa `upto`-jälkimittauspolun, joka edellyttää Permit2 approvea.
- `upto`-merkinnän `extra.facilitatorAddress` on osoite, joka asiakkaan on kirjoitettava witnessiin allekirjoittaessaan, ja sen on vastattava palvelimen palauttamaa arvoa.

## Base

Base käyttää virallista USDC-sopimusta:

```text
0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
```

`exact`-mallissa asiakas allekirjoittaa EIP-712 `TransferWithAuthorization` -pyynnön. Allekirjoituksen sisältöön kuuluvat:

- `from`: maksavan lompakon osoite
- `to`: Ace Data Cloudin vastaanotto-osoite
- `value`: tämän maksun määrä
- `validAfter` / `validBefore`: allekirjoituksen voimassaoloaikaikkuna
- `nonce`: 32 tavun satunnainen nonce

Kun Facilitator on varmistanut allekirjoituksen, se kutsuu ketjussa USDC:n `transferWithAuthorization`-toimintoa siirron suorittamiseksi.

Base on suositelluin verkko tuotantointegraatioon, erityisesti `upto`-jälkimittaukseen, koska Permit2-, USDC- ja lompakkoekosysteemit ovat kypsempiä.

Esimerkki Base `exact` -varmennustuloksesta:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
content ADC_BASE_E2E_OK
tx 0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
block 46726299
explorer https://basescan.org/tx/0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
transfer value 95215 atomic USDC
```

Tulosten selitys:

- API:n maksettu uudelleenyritys palauttaa mallisisällön `ADC_BASE_E2E_OK`.
- Ketjutapahtuma on haettavissa BaseScanissa, ja lohkon numero on `46726299`.
- `95215` atomic USDC vastaa `0.095215` USDC:tä, joka on tämän API-kutsun todellinen selvitysmäärä.

Tilauksen Base `exact` -maksun ohjelman ajotulos:

```text
order 78481793-304e-47f7-bc0c-8231aec9cc1e
state Finished
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer value 1200000 atomic USDC
```

Tulosten selitys:

- Alustan tilauksen lopullinen tila on `Finished`.
- Tilauksen `pay_id` sisältää saman Base-tapahtumahashin.
- `1200000` atomic USDC vastaa `1.2` USDC:tä, joka on tämän 10 Credits -tilauksen historiallinen todellinen maksumäärä vanhan käytännön mukaisesti; uudet tilaukset eivät enää saa ylimääräistä X402-maksutapa-alennusta, ja tarkka allekirjoitusmäärä määräytyy tämänkertaisen 402-vastauksen mukaan.

## Solana

Solana käyttää SPL USDC:n `TransferChecked`-toimintoa. Asiakas muodostaa siirtotapahtuman, allekirjoittaa ja lähettää sen, minkä jälkeen tapahtuma-allekirjoitus tai sarjoitettu tapahtuma asetetaan `PAYMENT-SIGNATURE` envelopeen.

Solanan ominaisuudet:

- Käyttää Solana wallet adapteria tai base58-salaista avainta;
- Omaisuus on Solana USDC mint;
- Tällä hetkellä tuetaan vain `exact`-mallia;
- Facilitator tarkistaa transfer instructionin mintin, destinationin, authorityn ja amountin.

Jos käytetään lompakon fee payer -tilaa, lompakko lähettää tapahtuman suoraan, ja Facilitator vastaa tapahtuman vahvistamisesta sekä settlement-tuloksen palauttamisesta.

Esimerkki Solana `exact` -varmennustuloksesta:

```text
payer AY2RmGm2zPxB1uKvvF4dKyYdr2VySyL3wcD1MKJZoLRd
HTTP 402 -> HTTP 200
content ADC_SOLANA_E2E_OK
chain signature not confirmed in this run
```

Tulosten selitys:

- Maksettu uudelleenyritys on jo palauttanut HTTP 200:n, ja mallin tuloste on `ADC_SOLANA_E2E_OK`.
- Julkisen RPC:n kautta tehtävä ketjun signature-kysely voi kohdata nopeusrajoituksia.
- Koska julkisen RPC:n kyselyissä voi esiintyä nopeusrajoituksia, Solana exploreria ei kirjoiteta tähän. Jos tarvitaan tarkkaa täsmäytystä, varmista tapahtuma-allekirjoitus käyttämällä omaa Solana RPC:tä tai alustan selvitystietoja.

## Kuinka valita

| Mitä haluat tehdä                 | Suositeltu verkko  |
| --------------------------------- | ------------------ |
| Ajaa nopeasti läpi pienin polku   | Base `exact`       |
| Tavallisille Web3-käyttäjille     | Base               |
| Jälkimittaukseen, kuten chat-täydennyksiin | Base `upto` |
| Solana-ekosysteemin sovellukset   | Solana `exact`     |

Riippumatta siitä, minkä ketjun valitset, älä kovakoodaa hintaa asiakkaaseen. Hinta määräytyy palvelimen palauttaman `accepts[].maxAmountRequired`-arvon perusteella.

## Uuden EVM-verkon lisääminen
Seuraavien verkkojen natiivin USDC:n kiinteämääräisille maksuille on tarjottu koodituki, ja ne avataan verkko kerrallaan.
Käytettävyyden osalta tilauksen tai API:n palauttama `accepts` on ratkaiseva; tämä ei tarkoita, että kaikki verkot olisi otettu käyttöön tuotannossa.

| Verkko       | Alias      | CAIP-2         | Natiivi USDC                                 |
| ------------ | ---------- | -------------- | -------------------------------------------- |
| Arbitrum One | `arbitrum` | `eip155:42161` | `0xaf88d065e77c8cC2239327C5EDb3A432268e5831` |

Nämä verkot tukevat vain `exact`-tilaa, ja valuutan tarkkuus on 6. Älä käytä samannimistä silta-USDC:tä.
Kun käytät virallista TypeScript/Python X402 Client -asiakasta, voit välittää taulukossa olevan lyhenteen tai CAIP-2-tunnisteen.
Asiakas käyttää kohdeketjun ID:tä allekirjoituksen muodostamiseen; lompakon on tuettava kohdeverkkoa.

Phantom-laajennuslompakon virallisessa tukitaulukossa on lueteltu Arbitrum ja Polygon; Optimism ja Avalanche
eivät tällä hetkellä sisälly tähän taulukkoon, ja voit käyttää kohdeketjua tukevaa Rabbyä tai MetaMaskia. EVM-osoite voi olla sama eri ketjuissa,
mutta saldot ovat toisistaan riippumattomia, eikä Solana-osoite sovellu EVM USDC:lle.
Katso [Phantom-lompakon tukitaulukko](https://docs.phantom.com/wallet-sdks-overview#chain-support).

### Uuden verkon asteittaisen käyttöönoton sisäänkäynti

Uuden ketjun sisäänkäynti on oletusarvoisesti piilotettu. Kun käytät konsolia tai Studiota, voit käyttää `?features=x402-arbitrum`
ottaaksesi käyttöön vastaavan ketjun; erota useat flagit pilkulla. Poista yksittäinen ketju käytöstä käyttämällä `?features=-x402-arbitrum`,
ja tyhjennä paikallinen ohitus käyttämällä `?features=none`. Kytkimet tallennetaan erikseen jokaiselle verkkotunnukselle.
Tilaushinnoittelu ja maksun uudelleenyritys käyttävät samaa kytkintä, ja palvelin validoi ne erikseen; olemassa olevat maksutietueet ovat edelleen tarkasteltavissa.
Pelkkä sivun flagin käyttöönotto ei ota käyttöön ketjua, jota ei ole vielä määritetty; tosiasiallisesti maksettavat verkot määräytyvät edelleen reaaliaikaisen `accepts`-arvon perusteella.
