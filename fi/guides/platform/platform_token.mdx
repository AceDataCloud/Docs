**Tilitunnus (Account Token, aiemmin Platform Token)** on "tilitason avain", jolla kehittäjät hallitsevat AceDataCloud-alustan resursseja ohjelmallisesti (palveluhakemukset, API-tunnukset, tilaukset, kutsutiedot, saldo, tiedostot jne.). Sen tehtävä on samankaltainen kuin käyttöliittymään kirjautumisen jälkeisellä käyttäjä-Tokenilla, eikä sillä oletusarvoisesti ole vanhenemisaikaa; tavalliset käyttäjät voivat hallita vain omia tunnuksiaan, kun taas pääkäyttäjät voivat hallita muiden tilien tunnuksia käyttöoikeuksiensa mukaisesti.

Tilitunnus käyttää alustan rajapintoja sille kuuluvan tilin nykyisillä käyttöoikeuksilla: perusoikeudet, suoraan myönnetyt oikeudet ja käyttäjäryhmän oikeudet yhdistyvät; ryhmään liittymisen tai ryhmästä poistamisen jälkeen seuraava pyyntö arvioidaan uusien oikeuksien mukaisesti. Tiettyjen hakemusten, tilausten ja muiden resurssien käyttö edellyttää edelleen omistajuuden tarkistamista. Tilitunnukset eivät oletusarvoisesti vanhene, joten käytä niitä vain luotettavissa ympäristöissä ja säilytä ne turvallisesti.

> ℹ️ Tämä rajapinta kuuluu **AceDataCloud-alustan hallinta-APIin**, jonka yhtenäinen etuliite on `https://platform.acedata.cloud/api/v1/`. Täydellinen rajapintaluettelo löytyy kohdasta [Hae AceDataCloud-alustan dokumenttiluettelo](https://platform.acedata.cloud/documents/platform-document-list).

## Tilitunnus vs API-tunnus

Nämä ovat kaksi avaintyyppiä, jotka aloittelijat sekoittavat helpoimmin. Katso ensin selkeä ero:

| Ulottuvuus   | **Tilitunnus** (tämä dokumentti)                                                               | **API-tunnus (Credential)**                                                                           |
| ---- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Käyttötarkoitus   | `https://platform.acedata.cloud/**`-hallintarajapintojen kutsuminen                                | `https://api.acedata.cloud/**`-liiketoimintarajapintojen kutsuminen (OpenAI, Midjourney, Suno, Veo jne.)                             |
| Muoto   | `platform-v1-` + 64-bittinen heksadesimaaliarvo (yhteensä 76 merkkiä)                                          | 32-bittinen heksadesimaaliarvo                                                                                         |
| Yhtä tiliä kohden | Yleensä 1–2 kappaletta                                                                    | 1–N kappaletta palveluhakemusta kohden                                                                                     |
| Luontipaikka | [Account Token -konsoli](https://platform.acedata.cloud/console/platform-tokens) | [Luo AceDataCloud-alustan API-tunnus](https://platform.acedata.cloud/documents/platform-credential-create) |
| Mitätöintiehdot | Mitätöityy välittömästi poistamisen jälkeen; mitätöityy vanhentuessaan, kun `expiration` ei ole tyhjä                                                | Voidaan asettaa käyttökiintiön yläraja, vanhenemisaika ja sitoa lähde-IP:hen                                                                             |

Jos haluat vain kutsua GPT-4.1:tä, tarvitset **API-tunnuksen**, et tilitunnusta.
Jos haluat kirjoittaa automaatioskriptin latausten hallintaan, kuukausilaskujen tarkasteluun tai tunnusten massajakoon tiimin jäsenille, käytä silloin tilitunnusta.

## Luo yhdellä napsautuksella konsolissa (suositeltu)

1. Kirjaudu sisään osoitteessa [https://platform.acedata.cloud](https://platform.acedata.cloud).
2. Siirry sivupalkissa kohtaan →「Kehittäjä」→「[Account Token](https://platform.acedata.cloud/console/platform-tokens)」.
3. Napsauta oikean yläkulman「Luo」-painiketta saadaksesi välittömästi `platform-v1-...`-tunnuksen. **Napsauta kopiointipainiketta ja tallenna se salasanojen hallintaan**.

![Account Token -konsoli](https://cdn.acedata.cloud/6g86oz.png)

> ⚠️ Nykyiset luonti-, luettelo- ja tietovastaukset palauttavat kaikki tunnuksen selväkielisenä. Käsittele koko vastausta salaisuutena, äläkä kirjoita sitä lokeihin, analytiikka-alustoille tai käyttöliittymän pysyvään tallennukseen; asiakkaan ei myöskään tulisi luottaa siihen, että luettelo palauttaa selväkielisen arvon pysyvästi.

## Luo tilitunnus APIlla

### Rajapinnan yleiskatsaus

| Kohta    | Sisältö                                                       |
| ---- | -------------------------------------------------------- |
| Metodi   | `POST`                                                   |
| URL  | `https://platform.acedata.cloud/api/v1/platform-tokens/` |
| Todennus   | ✅ Mikä tahansa olemassa oleva tilitunnus tai selaimen kirjautumistilan JWT                                 |
| Body | `application/json` (voidaan välittää tyhjä objekti `{}`)                           |

### Todennuksen selitys (kana ja muna -ongelma)

> Mistä ensimmäinen tunnus tulee? Vastaus on **konsolista** — selaimeen kirjautumisen jälkeen konsoli kutsuu JWT-todennuksella `POST /platform-tokens/`-rajapintaa ja antaa sinulle ensimmäisen tunnuksen.
> Sen jälkeen voit käyttää mitä tahansa olemassa olevaa `platform-v1-...`-tunnusta luodaksesi lisää tunnuksia.

Pyyntöotsikon muoto:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
Content-Type: application/json
```

### Pyyntöesimerkki

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/platform-tokens/' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'content-type: application/json' \
  -d '{}'
```

### Vastaus (HTTP 201)

```json
{
  "id": "3264f1aa-cbe1-4e2c-a434-95adba4f8304",
  "token": "platform-v1-<REDACTED>",
  "expiration": null,
  "user_id": "89518d07-5560-4b05-92c1-667f3ddf6a4b",
  "created_at": "2026-04-26T15:50:11.123456Z",
  "updated_at": "2026-04-26T15:50:11.123456Z",
  "used_at": null
}
```

### Kenttien kuvaus

| Kenttä           | Tyyppi                 | Kuvaus                                                   |
| ------------ | ------------------ | ---------------------------------------------------- |
| `id`         | UUID               | Tunnuksen pääavain, käytetään poistettaessa / haettaessa tietoja                                     |
| `token`      | string             | Tilitunnus selväkielisenä. Muoto `platform-v1-` + 64-bittinen heksadesimaaliarvo (yhteensä 76 merkkiä), on käsiteltävä salaisuutena |
| `expiration` | int \| null        | Vanhenemisaika (sekuntitason aikaleima). `null` tarkoittaa, ettei vanhenemisaikaa ole asetettu                         |
| `user_id`    | UUID               | Omistavan käyttäjän ID. Se on myös kaikissa myöhemmissä luettelorajapinnoissa pakollisesti välitettävä `?user_id=`-parametriarvo               |
| `created_at` | datetime (ISO8601) | Luontiaika                                                 |
| `updated_at` | datetime (ISO8601) | Päivitysaika                                                 |
| `used_at`    | datetime \| null   | Viimeisin aika, jolloin sitä käytettiin todennukseen. Jos sitä ei ole koskaan käytetty, arvo on `null`; voidaan käyttää "zombietunnusten" havaitsemiseen                |

## Hae tilitunnusluettelo

### Rajapinnan yleiskatsaus

| Kohta   | Sisältö                                                       |
| --- | -------------------------------------------------------- |
| Metodi  | `GET`                                                    |
| URL | `https://platform.acedata.cloud/api/v1/platform-tokens/` |
| Todennus  | ✅ Tilitunnus vaaditaan                                                 |

### Pakollinen kyselyparametri

> ⚠️ **Mukana on oltava `?user_id=<your_user_id>`**. Syy: luettelorajapinta tarkistaa sivutustulosten käyttöoikeudet **objektikohtaisesti**. Jos `user_id` puuttuu, ensimmäinen sinulle kuulumaton objekti hylätään ja palautetaan `403 permission_denied`.

Näin saat `user_id`:n:

1. Avaa selaimessa [https://auth.acedata.cloud/user/profile](https://auth.acedata.cloud/user/profile), jossa sivun yläosassa näkyy täydellinen UUID.
2. Tai täytä se suoraan `POST /platform-tokens/`-paluuarvon `user_id`-kentästä.

### Kyselyparametrit
| Parametri     | Pakollinen | Tyyppi | Kuvaus                                      |
| ---------- | --- | ------ | ------------------------------------------- |
| `user_id`  | ✅   | UUID   | Nykyisen tilin käyttäjätunnus                |
| `limit`    | ❌   | int    | Rivien määrä sivua kohden, oletus 10, enintään 100 |
| `offset`   | ❌   | int    | Siirtymä                                    |
| `ordering` | ❌   | string | Lajittelukenttä, oletuksena `-created_at`   |

### Pyyntöesimerkki

```shell
curl 'https://platform.acedata.cloud/api/v1/platform-tokens/?user_id=89518d07-5560-4b05-92c1-667f3ddf6a4b&limit=5' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Vastaus (HTTP 200)

```json
{
  "count": 2,
  "items": [
    {
      "id": "51c575a2-801c-4211-bc47-711452a8c8c9",
      "token": "platform-v1-<REDACTED>",
      "expiration": null,
      "user_id": "89518d07-5560-4b05-92c1-667f3ddf6a4b",
      "created_at": "2026-04-26T15:41:32.761705Z",
      "updated_at": "2026-04-26T15:41:32.761726Z",
      "used_at": null
    }
  ]
}
```

> Tämän rajapinnan sivutusvastaus käyttää rakennetta `count` + `items`. Muut alustan rajapinnat voivat käyttää eri rakennetta, joten noudata vastaavaa dokumentaatiota ja todellista vastausta.

## Hae tilitunnuksen tiedot

| Kohta   | Sisältö                                                                      |
| --- | ----------------------------------------------------------------------- |
| Menetelmä  | `GET`                                                                   |
| URL | `https://platform.acedata.cloud/api/v1/platform-tokens/<id>`（**ei kauttaviivaa lopussa**） |
| Todennus  | ✅ Vain tunnuksen luoja tai pääkäyttäjä voi käyttää                                                       |

```shell
curl 'https://platform.acedata.cloud/api/v1/platform-tokens/51c575a2-801c-4211-bc47-711452a8c8c9' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

Palautusrakenne on sama kuin luettelon elementillä, `HTTP 200`.

## Poista tilitunnus

| Kohta   | Sisältö                                                                      |
| --- | ----------------------------------------------------------------------- |
| Menetelmä  | `DELETE`                                                                |
| URL | `https://platform.acedata.cloud/api/v1/platform-tokens/<id>`（**ei kauttaviivaa lopussa**） |
| Todennus  | ✅ Vain tunnuksen luoja tai pääkäyttäjä voi poistaa                                                       |

```shell
curl -X DELETE 'https://platform.acedata.cloud/api/v1/platform-tokens/3264f1aa-cbe1-4e2c-a434-95adba4f8304' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

- Onnistuneena palautetaan `HTTP 204 No Content`, ilman vastausrunkkoa.
- Poiston jälkeen tämä tunnus **lakkaa toimimasta välittömästi**, ja kaikki sitä käyttävät palvelut saavat heti `401`.
- Tämän `id`:n kysely uudelleen palauttaa `404`.

> ⚠️ Poistoa ei voi peruuttaa. Jos epäilet tunnuksen vuotaneen, voit **luoda ensin uuden, vaihtaa sen käyttöön liiketoimintapuolella ja poistaa sitten vanhan**.

## Toiminnot, joita ei tueta

| Toiminto         | HTTP | Kuvaus                                  |
| ---------- | ---- | ----------------------------------- |
| `PATCH` muokkaus | 405  | Tilitunnuksen luomisen jälkeen **mitään kenttiä ei voi muokata**. Jos tarvitset esimerkiksi uudelleennimeämistä, poista ja luo uudelleen |
| `PUT` korvaus   | 405  | Sama kuin yllä                                  |

---

## Virhekoodien pikaopas

| HTTP | `code`               | Yleinen syy                          |
| ---- | -------------------- | ----------------------------- |
| 401  | `not_authenticated`  | `Authorization`-otsake puuttuu tai tunnus on poistettu  |
| 403  | `permission_denied`  | Luettelorajapinnasta puuttuu `?user_id=`, tai yritetään käyttää toisen tunnuksen tietoja |
| 404  | `not_found`          | `id` ei ole olemassa tai se on poistettu                 |
| 405  | `method_not_allowed` | Tietorajapinnalle lähetettiin `PATCH`/`PUT`         |

Virhevastausten yhtenäinen muoto:

```json
{
  "detail": "You do not have permission to perform this action.",
  "code": "permission_denied",
  "trace_id": "0a88956213edf6e62b71695ee2df0eff"
}
```

Anna vianmäärityksessä `trace_id` asiakaspalvelulle tai liitä se tukipyyntöön, jotta lokit voidaan paikantaa nopeasti.

## Täydellinen koodiesimerkki

### Python

```python
import os
import requests

BASE = "https://platform.acedata.cloud/api/v1"
PLATFORM_TOKEN = os.environ["PLATFORM_TOKEN"]
USER_ID = "89518d07-5560-4b05-92c1-667f3ddf6a4b"

headers = {
    "accept": "application/json",
    "authorization": f"Bearer {PLATFORM_TOKEN}",
    "content-type": "application/json",
}

# 1. 创建新令牌
created = requests.post(f"{BASE}/platform-tokens/", headers=headers, json={}).json()
print("新令牌：", created["token"])
print("UserID：", created["user_id"])

# 2. 列表
listing = requests.get(
    f"{BASE}/platform-tokens/",
    headers=headers,
    params={"user_id": USER_ID, "limit": 50},
).json()
print(f"共 {listing['count']} 枚令牌")

# 3. 删除（注意末尾无斜杠）
resp = requests.delete(f"{BASE}/platform-tokens/{created['id']}", headers=headers)
assert resp.status_code == 204, resp.text
```

### Node.js

```javascript
const BASE = 'https://platform.acedata.cloud/api/v1'
const PLATFORM_TOKEN = process.env.PLATFORM_TOKEN
const USER_ID = '89518d07-5560-4b05-92c1-667f3ddf6a4b'

const headers = {
  accept: 'application/json',
  authorization: `Bearer ${PLATFORM_TOKEN}`,
  'content-type': 'application/json',
}

// 创建
const created = await fetch(`${BASE}/platform-tokens/`, {
  method: 'POST',
  headers,
  body: '{}',
}).then((r) => r.json())

// 列表
const url = new URL(`${BASE}/platform-tokens/`)
url.searchParams.set('user_id', USER_ID)
const listing = await fetch(url, { headers }).then((r) => r.json())
console.log(`共 ${listing.count} 枚令牌`)

// 删除（末尾无斜杠）
await fetch(`${BASE}/platform-tokens/${created.id}`, { method: 'DELETE', headers })
```

## Käyttö muissa alustan API-rajapinnoissa

Aseta `platform-v1-...` suoraan `Authorization: Bearer ...` -otsakkeeseen, jolloin voit kutsua mitä tahansa todennusta vaativaa alustan rajapintaa:

```shell
curl 'https://platform.acedata.cloud/api/v1/applications/?user_id=89518d07-5560-4b05-92c1-667f3ddf6a4b' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

> Se on **täysin erilainen** kuin `https://api.acedata.cloud/**`-liiketoimintarajapinnoissa (OpenAI, Midjourney, Suno, Veo jne.) käytettävä 32-merkkinen heksadesimaalinen API-tunniste. Älä sekoita niitä — tilitunnuksen kirjoittaminen liiketoimintarajapintaan tuottaa `401`, ja päinvastoin.
