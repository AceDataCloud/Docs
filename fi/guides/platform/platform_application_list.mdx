Palauttaa sivutettuna tilin omistamat tai käyttöoikeuden saamat Applicationit, mukaan lukien saldo, tila, palveluyhteenveto ja liitetyt tunnistetiedot. Soveltuu eräsaldojen joukkovalvontaan, Application ID:n etsimiseen ja tunnistetietojen hallintaan siirtymiseen.

## Valmistelut

1. Kirjaudu sisään [AceDataCloud-alustalle](https://platform.acedata.cloud).
2. Luo tilitunnus [Account Token -konsolissa](https://platform.acedata.cloud/console/platform-tokens).
3. Tavalliset käyttäjät käyttävät `user_id=me`; voit myös hakea oman UUID:si osoitteesta `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='sinun tilitunnuksesi'
```

## Rajapinnan yleiskatsaus

| Kohta   | Sisältö                                                    |
| --- | ----------------------------------------------------- |
| Menetelmä  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Todennus  | Account Token, OAuth token tarvitsee `applications:read`       |
| Sivutus  | `count` + `items`                                     |

Tavallisten käyttäjien tulee antaa `user_id=me`. Jos sitä ei anneta, kyselyä ei ensin rajata tilin mukaan, ja sivutus voi palauttaa `403`, kun vastaan tulee kohteita, joihin ei ole käyttöoikeutta; ylläpitäjät voivat nähdä koko taulukon, jos sitä ei anneta.

## Kyselyparametrit

| Parametri            | Tyyppi          | Pakollinen     | Kuvaus                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Pakollinen tavallisille käyttäjille | Kyselyn kohde; tukee toistuvia parametreja                                         |
| `affiliation` | string      | Ei      | `owner` (oletus) tai `granted`; molemmat voidaan antaa toistuvasti, jolloin tuloksena on niiden unioni, voimassa vain kun `user_id` on annettu |
| `service_id`  | UUID        | Ei      | Suodata palvelun mukaan; tukee toistuvia parametreja                                        |
| `scope`       | string      | Ei      | `Individual` tai `Global`; tukee toistuvia parametreja                      |
| `type`        | string      | Ei      | `Usage` tai `Period`; tukee toistuvia parametreja                           |
| `limit`       | integer     | Ei      | Kohteiden määrä sivua kohti, enintään 100                                         |
| `offset`      | integer     | Ei      | Sivutussiirtymä                                               |
| `ordering`    | string      | Ei      | Tukee vain `created_at` tai `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` ja `tag` eivät tällä hetkellä ole palvelinpuolen suodatusparametreja. Saldoilmoitukset tulee arvioida luettelon hakemisen jälkeen asiakkaassa kunkin Applicationin `remaining_amount`-, `service.unit`- ja liiketoimintakynnysarvojen perusteella.

## Pyyntöesimerkit

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Tarkastele samanaikaisesti itse omistamiasi ja muiden sinulle myöntämiä Applicationeja:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Vastauksen kuvaus

Vastaus on muodossa `{count, items}`. Jokainen kohde sisältää Application-mallin kentät sekä lisäksi:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: tunnistetietojen yhteenveto, jonka nykyinen kutsuja saa nähdä;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`, `allow_overdraft`;
- `scope`-kentän todellinen arvo on `Individual` tai `Global`;
- `type`-kentän todellinen arvo on `Usage` tai `Period`.

`allow_overdraft` on ylläpitäjän hallitsema vain luku -tyyppinen totuusarvokenttä, jonka oletusarvo on `false`. Käyttöperusteisissa (`Usage`) sovelluksissa, joissa ylitys on otettu käyttöön, riittämätön saldo ei estä kutsuja, vaan maksu veloitetaan edelleen todellisen käytön mukaan; negatiivinen saldo tarkoittaa selvitettävää luottoa. Käytöstä poisto, vanheneminen ja API-tunnistetietojen rajoitukset ovat edelleen voimassa.

`remaining_amount` voi olla tyhjä; asiakkaan on ensin tarkistettava tyhjä arvo ennen numeerista vertailua. Kiintiöyksikkö määräytyy `service.unit`-kentän mukaan.
