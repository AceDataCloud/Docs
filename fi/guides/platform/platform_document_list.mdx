Palauttaa sivutettuna nykyisellä sivustolla näkyvät kehittäjäasiakirjat, joita voidaan käyttää hakuun, indeksointiin tai navigoinnin rakentamiseen asiakkaassa itse. Luettelo sisältää tällä hetkellä kunkin asiakirjan `content`-kentän ja sisäkkäiset ylätason tiedot, joten vastaus voi olla suuri.

## Rajapinnan yleiskatsaus

| Kohta   | Sisältö                                                 |
| --- | -------------------------------------------------- |
| Menetelmä  | `GET`                                              |
| URL | `https://platform.acedata.cloud/api/v1/documents/` |
| Todennus  | Julkinen; muut kuin järjestelmänvalvojat eivät näe private-asiakirjoja                              |
| Sivutus  | `count` + `items`                                  |

## Kyselyparametrit

| Parametri         | Tyyppi      | Pakollinen  | Oletus     | Kuvaus                           |
| ---------- | ------- | --- | ------ | ---------------------------- |
| `id`       | UUID    | Ei   | —      | Suodata asiakirjan ID:n mukaan; tukee toistuvia parametreja             |
| `private`  | boolean | Ei   | —      | Suodata private-tilan mukaan; muut kuin järjestelmänvalvojat eivät edelleenkään näe yksityisiä asiakirjoja |
| `type`     | string  | Ei   | —      | Suodata tarkasti Documentin todellisen `type`-arvon mukaan  |
| `tag`      | string  | Ei   | —      | Suodata tunnisteen mukaan                        |
| `limit`    | integer | Ei   | 10     | Kohteiden määrä sivua kohden, enintään 100                  |
| `offset`   | integer | Ei   | 0      | Sivutuksen siirtymä                        |
| `ordering` | string  | Ei   | `rank` | Tukee vain järjestämistä `rank`-arvon mukaan; etuliite `-` tarkoittaa laskevaa järjestystä   |

Nykyinen luettelorajapinta ei tue suodatusta `alias`- tai `parent_id`-kentällä. Kun alias tunnetaan, kutsu suoraan [asiakirjan tietoja](https://platform.acedata.cloud/documents/platform-document-detail); kun rakennat puunmuotoista navigointia, hae kerralla sivutettuna ja ryhmittele asiakkaassa kunkin kohteen `parent.id`-arvon perusteella.

## Pyyntöesimerkit

```shell
curl --get 'https://platform.acedata.cloud/api/v1/documents/' \
  --data-urlencode 'tag=development' \
  --data-urlencode 'limit=100' \
  --data-urlencode 'ordering=rank' \
  -H 'Accept: application/json'
```

```python
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/documents/",
    params={"tag": "development", "limit": 100, "offset": 0},
    timeout=30,
)
response.raise_for_status()
data = response.json()
for document in data["items"]:
    parent = document.get("parent") or {}
    print(document["alias"], parent.get("alias"))
```

## Vastausrakenne

```json
{
  "count": 1,
  "items": [
    {
      "id": "00000000-0000-4000-8000-000000000001",
      "alias": "platform-token",
      "name": "Document of Platform Token",
      "title": "管理 AceDataCloud 平台账户令牌（Account Token）",
      "content": "# 管理 AceDataCloud 平台账户令牌……",
      "type": "Text",
      "private": false,
      "primary_only": false,
      "rank": 2400,
      "tags": [
        "development"
      ],
      "parent": {
        "id": "00000000-0000-4000-8000-000000000002",
        "alias": "platform",
        "title": "AceDataCloud 平台"
      },
      "sibling": null,
      "api_id": null,
      "proxy_id": null,
      "api_method": null,
      "metadata": null,
      "created_at": "2026-01-01T00:00:00Z",
      "updated_at": "2026-01-01T00:00:00Z"
    }
  ]
}
```

Luettelo käyttää `DocumentIndexSerializer`-serialisoijaa ja palauttaa tällä hetkellä mallikentät sekä sisäkkäiset suhteet; siihen liittyvillä API-asiakirjoilla voi lisäksi olla `api_method`. Kenttiä voidaan lisätä taaksepäin yhteensopivasti, joten asiakkaan tulee lukea niitä tarpeen mukaan. Kun tarvitset `children`-kentän, jäsennetyn sisällön kielen ja sisällön hash-arvon, käytä tietorajapintaa.

Julkisille tietueille, jotka liittyvät lähdeasiakirjaan, `content_source` tarjoaa lähdeasiakirjan tunnisteen, lähdesisällön hash-arvon, pyydetyn kielen, käännöksen päivitysajan sekä tilan `ready`, `stale`, `missing`, `missing_source` tai `ambiguous`; muilla tietueilla tämä kenttä on `null`. Kun tila on `ready`, `content_hash` vastaa kyseisen kielen käännöstä. Varsinainen sisältö näytetään edelleen alkuperäisten sääntöjen mukaisesti, mukaan lukien kielivaraus, kun käännös puuttuu; asiakirjoja synkronoivien asiakkaiden tulee tarkistaa sekä tila että hash-arvo, eivätkä ne voi päätellä päivitystä pelkästään siitä, että varsinainen sisältö ei ole tyhjä.

## Käyttösuositukset

- Vastaus sisältää varsinaisen sisällön; käytä eräsivutusta ja määritä kohtuullinen aikakatkaisu joukkosynkronoinnissa, älä hae samaa sivua samanaikaisesti.
- alias on julkisen sivun URL-osoitteen vakaa tunniste; kun alias tunnetaan, pyydä suoraan `/api/v1/documents/{alias}`.
- Nykyinen rajapinta ei voi suodattaa ylätason mukaan palvelinpuolella; ryhmittele navigointia rakentaessasi asiakkaassa `parent.id`-arvon mukaan.
