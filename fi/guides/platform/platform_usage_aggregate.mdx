Yhteenveto nykyisen tilin pyyntömääristä ja tosiasiallisesti vähennetyistä käyttökiintiöistä päivämäärän ja API:n mukaan, soveltuu kuukausiraporttien, trendikaavioiden ja kustannusanalyysien tekemiseen. Kun tarvitsee virheenkorjausta kutsu kerrallaan, käytä [kutsutietueluetteloa](https://platform.acedata.cloud/documents/platform-usage-list), ja kun tarvitset täydelliset offline-erittelyt, käytä [kutsumäärän vientiä](https://platform.acedata.cloud/documents/platform-usage-export)。

## Valmistelut

1. Kirjaudu sisään [AceDataCloud-alustalle](https://platform.acedata.cloud)。
2. Luo tilitunnus [Account Token -konsolissa](https://platform.acedata.cloud/console/platform-tokens) ja tallenna se välittömästi。
3. Jos haluat rajata aluetta, hae vastaava ID [palveluhakemusluettelosta](https://platform.acedata.cloud/documents/platform-application-list), [API-valtuustietoluettelosta](https://platform.acedata.cloud/documents/platform-credential-list) tai [API-luettelosta](https://platform.acedata.cloud/documents/platform-api-list)。

Täydellinen tunnusohjeistus löytyy kohdasta [tilitunnusten hallinta](https://platform.acedata.cloud/documents/platform-token)。Tämä rajapinta käyttää Account Tokenia, ei liiketoiminnan Credentialia。

```shell
export PLATFORM_TOKEN='你的账户令牌'
```

## Rajapinnan yleiskatsaus

| Kohta           | Sisältö                                                            |
| ----------- | ------------------------------------------------------------- |
| Menetelmä          | `GET`                                                         |
| URL         | `https://platform.acedata.cloud/api/v1/usage/apis/aggregate/` |
| Todennus          | `Authorization: Bearer ${PLATFORM_TOKEN}`                     |
| OAuth Scope | `usage:read`（`platform:read` / `platform` voi laajennetusti sisältää）              |
| Käyttöoikeusalue        | Tavallisilla käyttäjillä kiinteästi oma maksullinen käyttömäärä; ylläpitäjät voivat välittää `user_id`                                |

## Kyselyparametrit

| Parametri                | Tyyppi              | Pakollinen  | Oletus                    | Kuvaus                                   |
| ----------------- | --------------- | --- | --------------------- | ------------------------------------ |
| `created_at_from` | date / datetime | Ei   | Valitun aikavyöhykkeen kuluvan kuukauden ensimmäinen päivä            | Aloitusaika, suositeltu parametrin nimi                           |
| `created_at_to`   | date / datetime | Ei   | Nykyinen aika                  | Lopetusaika, suositeltu parametrin nimi                           |
| `timezone`        | string          | Ei   | `UTC`                 | IANA-aikavyöhyke, esimerkiksi `Asia/Shanghai`; virheellinen arvo palautuu UTC:hen |
| `service_id`      | UUID            | Ei   | —                     | Suodatus palvelun mukaan; tukee toistuvia parametreja                         |
| `application_id`  | UUID            | Ei   | —                     | Suodatus Applicationin mukaan; tukee toistuvia parametreja              |
| `api_id`          | UUID            | Ei   | —                     | Suodatus API:n mukaan; tukee toistuvia parametreja                      |
| `credential_id`   | UUID            | Ei   | —                     | Suodatus API-valtuustietojen mukaan; tukee toistuvia parametreja                    |
| `include_models`  | boolean         | Ei   | `false`               | Lasketaanko lisäksi koonti mallidimension mukaan; kasvattaa kyselykustannusta                 |
| `user_id`         | UUID            | Ei   | Tavallisilla käyttäjillä kiinteästi oma; ylläpitäjillä kaikki tilit, jos ei välitetä | Vain ylläpitäjät voivat määrittää minkä tahansa tilin                          |

`start_time` / `end_time` ovat edelleen käytettävissä vanhojen asiakkaiden yhteensopivuusaliaksina, uusissa integraatioissa käytetään yhtenäisesti `created_at_from` / `created_at_to`。Päivämäärämuotoinen `created_at_to` sisältää kyseisen kalenteripäivän, eli seuraavan päivän keskiyötä käytetään rajana。

## Pyyntöesimerkit

Kysy kuluvan kuukauden päivittäiset/API-koonnit Pekingin ajassa ja liitä mukaan mallidimensio:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  --data-urlencode 'include_models=true' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Kysy määritetyn Applicationin viikon käyttömäärä:

```shell
export APPLICATION_ID='你的 Application ID'

curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'created_at_from=2026-09-01' \
  --data-urlencode 'created_at_to=2026-09-07' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Python-esimerkki:

```python
import os
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/usage/apis/aggregate/",
    headers={"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    params={
        "created_at_from": "2026-09-01",
        "created_at_to": "2026-09-07",
        "timezone": "Asia/Shanghai",
        "include_models": "true",
    },
    timeout=30,
)
response.raise_for_status()
data = response.json()
print("requests:", data["requests"], "deducted:", data["total"])
for row in data["items"]:
    print(row["date"], row["api_id"], row["amount"])
```

## Vastauskentät

| Kenttä         | Kuvaus                                                           |
| ---------- | ------------------------------------------------------------ |
| `items`    | Ryhmitelty valitun aikavyöhykkeen päivämäärän ja `api_id`:n mukaan; jokainen rivi sisältää `date`、`api_id`、`amount`          |
| `total`    | `deducted_amount`:n summa kyselyalueella                                  |
| `apis`     | API ID:n ja otsikkoyhteenvedon vastaavuus, helpottaa `items`:n näyttämistä                                 |
| `requests` | Pyyntöjen kokonaismäärä kyselyalueella                                                   |
| `models`   | Lasketaan vain, kun `include_models=true`; jokainen kohde sisältää `model`、`amount`、`requests` |

Käyttökiintiön yksikkö riippuu asiaankuuluvan Applicationin `service.unit`:stä。Jos kysely sisältää eri yksiköiden palveluita, tilastoi ne ensin erikseen `service_id`:n tai `application_id`:n mukaan, jotta vältät suoran vertailun tai yhteenlaskun。

Kun lopetusaika ei ole aloitusaikaa suurempi, rajapinta palauttaa täydellisen tyhjän rakenteen: `items=[]`、`total=0`、`apis={}`、`requests=0`、`models=[]`。

## Virhe- ja suorituskykysuositukset

| HTTP | `error`                 | Käsittelytapa                               |
| ---- | ----------------------- | ---------------------------------- |
| 400  | `usage_history_expired` | Säädä aikaväli vastausobjektin `available_from`-ajan jälkeiseksi     |
| 401  | `not_authenticated`     | Tarkista Account Token, älä käytä virheellisesti liiketoiminnan Credentialia |
| 403  | `permission_denied`     | Tavalliset käyttäjät eivät voi kysellä muita tilejä                       |

- Älä oletusarvoisesti ota käyttöön `include_models`:ia; ota se käyttöön vain, kun raportti todella tarvitsee mallijaottelun。
- Laajoissa kyselyissä erottele ensisijaisesti `service_id`:n tai `application_id`:n mukaan, jotta vältät sekä sekayksiköt että pienennät kyselykustannusta。
- Päiviä, joilla ei ole kutsuja, ei täydennetä automaattisesti nollilla; asiakas täydentää päivämääräakselin ennen piirtämistä。
