Yhteenveto nykyisen tilin pyyntömääristä ja tosiasiallisesti vähennetyistä saldoista päivämäärän ja API:n mukaan; soveltuu kuukausiraporttien, trendikaavioiden ja kustannusanalyysien laatimiseen. Käytä [kutsutietueluetteloa](https://platform.acedata.cloud/documents/platform-usage-list), kun virheitä täytyy selvittää tietue kerrallaan, ja [kutsumäärän vientiä](https://platform.acedata.cloud/documents/platform-usage-export), kun tarvitset täydelliset offline-yksityiskohdat.

Kutsutietueiden ja laskutusyhteenvetojen kyselyalue on viimeiset 60 päivää; pyyntö- ja vastaustekstejä säilytetään erikseen viimeiset 30 päivää. Tekstin vanheneminen ei muuta kyseisen tietueen todellista veloitusta, käyttömäärää tai yhdistettyjä tilastoja.

## Valmistelut

1. Kirjaudu sisään [AceDataCloud-alustalle](https://platform.acedata.cloud).
2. Luo tilitunnus [Account Token -konsolissa](https://platform.acedata.cloud/console/platform-tokens) ja tallenna se välittömästi.
3. Jos haluat rajata aluetta, hae vastaava ID [palveluhakemusluettelosta](https://platform.acedata.cloud/documents/platform-application-list), [API-tunnistetietoluettelosta](https://platform.acedata.cloud/documents/platform-credential-list) tai [API-luettelosta](https://platform.acedata.cloud/documents/platform-api-list).

Täydelliset tunnusohjeet ovat kohdassa [tilitunnusten hallinta](https://platform.acedata.cloud/documents/platform-token). Tämä rajapinta käyttää Account Tokenia, ei liiketoiminnan Credentialia.

```shell
export PLATFORM_TOKEN='你的账户令牌'
```

## Rajapinnan yleiskatsaus

| Kohta           | Sisältö                                                       |
| --------------- | ------------------------------------------------------------- |
| Menetelmä       | `GET`                                                         |
| URL             | `https://platform.acedata.cloud/api/v1/usage/apis/aggregate/` |
| Todennus        | `Authorization: Bearer ${PLATFORM_TOKEN}`                     |
| OAuth Scope     | `usage:read`（`platform:read` / `platform` 可展开包含）              |
| Käyttöoikeusalue | Tavallisilla käyttäjillä kiinteästi oma maksullinen käyttö; ylläpitäjät voivat välittää `user_id` |

## Kyselyparametrit

| Parametri         | Tyyppi          | Pakollinen | Oletus                                | Kuvaus                                      |
| ----------------- | --------------- | --------- | ------------------------------------- | ------------------------------------------- |
| `created_at_from` | date / datetime | Ei        | Valitun aikavyöhykkeen kuukauden ensimmäinen päivä | Aloitusaika, suositeltu parametrin nimi     |
| `created_at_to`   | date / datetime | Ei        | Nykyinen aika                         | Lopetusaika, suositeltu parametrin nimi     |
| `timezone`        | string          | Ei        | `UTC`                                 | IANA-aikavyöhyke, esimerkiksi `Asia/Shanghai`; virheellinen arvo palautuu UTC:hen |
| `service_id`      | UUID            | Ei        | —                                     | Suodata palvelun mukaan; tukee toistettuja parametreja |
| `application_id`  | UUID            | Ei        | —                                     | Suodata Applicationin mukaan; tukee toistettuja parametreja |
| `api_id`          | UUID            | Ei        | —                                     | Suodata API:n mukaan; tukee toistettuja parametreja |
| `credential_id`   | UUID            | Ei        | —                                     | Suodata API-tunnistetietojen mukaan; tukee toistettuja parametreja |
| `include_models`  | boolean         | Ei        | `false`                               | Lasketaanko lisäksi mallidimension yhteenveto; kasvattaa kyselyn kustannusta |
| `user_id`         | UUID            | Ei        | Tavallisilla käyttäjillä kiinteästi oma; ylläpitäjillä kaikki tilit, jos ei välitetä | Vain ylläpitäjät voivat määrittää minkä tahansa tilin |

`start_time` / `end_time` ovat edelleen käytettävissä yhteensopivuusaliaksina vanhoille asiakkaille, mutta uusissa integraatioissa käytetään yhtenäisesti `created_at_from` / `created_at_to`. Päivämäärämuotoinen `created_at_to` sisältää kyseisen kalenteripäivän eli käyttää rajana seuraavan päivän keskiyötä.

## Pyyntöesimerkit

Kysy kuluvan kuukauden päivittäiset/API-yhteenvedot Pekingin ajassa sekä mallidimensio:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  --data-urlencode 'include_models=true' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Kysy määritetyn Applicationin viikon käyttömäärä:

```shell
export APPLICATION_ID='你的 Application ID'

curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'created_at_from=2026-09-01' \
  --data-urlencode 'created_at_to=2026-09-07' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Python-esimerkki:

```python
import os
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/usage/apis/aggregate/",
    headers={"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    params={
        "created_at_from": "2026-09-01",
        "created_at_to": "2026-09-07",
        "timezone": "Asia/Shanghai",
        "include_models": "true",
    },
    timeout=30,
)
response.raise_for_status()
data = response.json()
print("requests:", data["requests"], "deducted:", data["total"])
for row in data["items"]:
    print(row["date"], row["api_id"], row["amount"])
```

## Vastauskentät

| Kenttä     | Kuvaus                                                      |
| ---------- | ----------------------------------------------------------- |
| `items`    | Ryhmitelty valitun aikavyöhykkeen päivämäärän ja `api_id`:n mukaan; jokainen rivi sisältää `date`-, `api_id`- ja `amount`-kentät |
| `total`    | `deducted_amount`-kentän summa kyselyalueella              |
| `apis`     | API ID:n ja otsikkoyhteenvedon välinen kartoitus `items`-tietojen esittämisen helpottamiseksi |
| `requests` | Pyyntöjen kokonaismäärä kyselyalueella                      |
| `models`   | Lasketaan vain, kun `include_models=true`; jokainen kohde sisältää `model`-, `amount`- ja `requests`-kentät |

Saldoyksikkö määräytyy vastaavan Applicationin `service.unit`-arvon mukaan. Jos kysely sisältää eri yksiköitä käyttäviä palveluita, tilastoi ne ensin erikseen `service_id`:n tai `application_id`:n mukaan, jotta vältät niiden suoran vertailun tai yhteenlaskun.

Jos lopetusaika ei ole aloitusaikaa suurempi, rajapinta palauttaa täydellisen tyhjän rakenteen: `items=[]`, `total=0`, `apis={}`, `requests=0`, `models=[]`.

## Virheet ja suorituskykysuositukset

| HTTP | `error`                 | Käsittelytapa                                      |
| ---- | ----------------------- | -------------------------------------------------- |
| 400  | `usage_history_expired` | Säädä aikaväli vastausobjektin `available_from`-ajan jälkeiseksi |
| 401  | `not_authenticated`     | Tarkista Account Token, älä käytä virheellisesti liiketoiminnan Credentialia |
| 403  | `permission_denied`     | Tavalliset käyttäjät eivät voi kysellä muita tilejä |

- Älä ota `include_models`-asetusta oletuksena käyttöön; ota se käyttöön vain, kun raportti todella tarvitsee mallikohtaisen erittelyn.
- Laajoissa kyselyissä erottele ensisijaisesti `service_id`:n tai `application_id`:n mukaan; näin vältät sekä yksiköiden sekoittamisen että pienennät kyselykustannuksia.
- Päiviä, joilla ei ole kutsuja, ei täytetä automaattisesti nollilla; asiakas täydentää päivämääräakselin ennen kaavion piirtämistä.
