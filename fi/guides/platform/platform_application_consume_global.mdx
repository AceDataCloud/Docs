---
title: "AceDataCloud Applicationin globaalin saldon jakamisen määrittäminen"
description: "Platform API guide - Ace Data Cloud"
---

Määritä `allow_consume_global`. Käyttöönoton jälkeen ehdot täyttävät käytön mukaan laskutettavat Applicationit voivat jatkaa tilin globaalin saldon käyttöä, kun niiden oma saldo ei riitä.

## Valmistelut

- Luo ja tallenna turvallisesti [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Hae omistamasi `application_id` [palveluhakemusluettelosta](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='tilisi tunnus'
export APPLICATION_ID='Application ID:si'
```

## Rajapinnan yleiskatsaus

| Kohta    | Sisältö                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------- |
| Menetelmä   | `POST`                                                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/applications/{application_id}/update-allow-consume-global/` |
| Todennus   | Account Token                                                                                      |
| Body | JSON                                                                                               |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/applications/${APPLICATION_ID}/update-allow-consume-global/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"allow_consume_global": true}'
```

Onnistuneena palautetaan päivitetty Application-objekti. Noudata vastauksessa olevaa `allow_consume_global`-arvoa äläkä oleta, että pyynnön arvo on varmasti tallennettu.

> `Period`-tyyppiset Applicationit eivät saa kuluttaa globaalia saldoa. Vaikka pyydettäisiin `true`, palvelin säilyttää tämän kentän arvona `false`.

## Virheenkäsittely

- `401`: Account Token on virheellinen tai puuttuu.
- `403`: Nykyinen tili ei ole tämän Applicationin omistaja.
- `404`: Application ID:tä ei ole olemassa.

Globaalin saldon latauspiste ja käytettävissä olevat paketit määräytyvät alustakonsolin sekä [tilauksen luomisen](https://platform.acedata.cloud/documents/platform-order-create) palauttamien todellisten pakettien mukaan; älä oleta, että `Wallet`-tyyppisiä paketteja on olemassa.

## Sovellukset, joille ylitys on sallittu

Kun käytön mukaan laskutettavan sovelluksen vain luku -kenttä `allow_overdraft=true`, sovellus voi jatkaa veloituksia omasta saldostaan, vaikka saldo muuttuisi negatiiviseksi, eikä se vaihda globaaliin tiliin saldon puutteen vuoksi. Sovellukset, joissa ylitys ei ole käytössä, noudattavat edelleen asetusta `allow_consume_global`; vaihdon jälkeen se, sallitaanko ylitys, määräytyy tosiasiallisesti veloitettavan globaalin Applicationin asetusten mukaan.

## Kokeilutilien samanaikaisuusrajoitus

Järjestelmä käyttää vain luku -käyttäjämerkintää `has_recharged` tallentaakseen, onko maksullinen lataus onnistuneesti suoritettu tai onko järjestelmänvalvoja lisännyt krediittejä manuaalisesti. Merkintä päivittyy toimenpiteen onnistumisen jälkeen, ja historialliset käyttäjät täydennetään yhtenäisesti tilausten tai selkeiden pisteidenlisäystietojen perusteella. Tileillä, joilla ei ole tehty maksullista latausta eikä järjestelmänvalvoja ole lisännyt pisteitä manuaalisesti, koko tilillä saa olla samanaikaisesti käynnissä vain yksi laskutettava pyyntö; eri API Keyt ja eri palvelut jakavat tämän yhden paikan. Palkintoja, vaihtokortteja ja siirrettyjä käyttöoikeuksia ei katsota maksullisiksi latauksiksi. Tilejä, joilla maksullinen lataus on jo suoritettu tai joille järjestelmänvalvoja on lisännyt krediittejä manuaalisesti, tämä kokeilun samanaikaisuusrajoitus ei koske, ja ne noudattavat edelleen alkuperäisiä saldo- ja tunnistekiintiötarkistuksia.

Kun olemassa oleva pyyntö on käynnissä, uusi pyyntö palauttaa `429 too_many_requests`. Maksuttomia kyselyrajapintoja, kuten tehtäväkyselyjä, voi edelleen kutsua normaalisti. Realtimen yhteyden todennus noudattaa alkuperäistä kierroskohtaista laskutusprosessia eikä käytä tätä tavallisen pyynnön paikkaa.

Kun asynkroninen rajapinta palauttaa “hyväksytty”, tehtävä on edelleen käynnissä, ja ennen seuraavan luontipyynnön lähettämistä on odotettava lopullista tulosta. Verkkoyhteyden katkeaminen tai välityspalvelimen aikakatkaisu ei tarkoita, että tehtävä olisi pysähtynyt; jos tehtävällä ei pitkään aikaan ole lopputilaa, anna `trace_id` ja ota yhteyttä tukeen tarkistusta varten.

Tämä rajoitus ei muuta kokeiltavissa olevia rajapintoja eikä alkuperäisiä laskutussääntöjä. Maksut veloitetaan edelleen pyynnön päätyttyä todellisen käytön mukaan.
