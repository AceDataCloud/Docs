Ota käyttöön oma WeCom-tili-instanssisi, kirjaudu sisään skannaamalla QR-koodi WeCom-mobiilisovelluksella ja lue tiliä, yhteystietoja, keskusteluja ja paikallisesti synkronoituja viestejä REST API:n tai MCP:n kautta. Instanssi vastaa tavallista WeCom-tiliä, eikä yksityistä palvelinta tai yrityssähköpostin verkkotunnuksen määritystä tarvita.

Tällä hetkellä Alpha-vaiheessa. Tilin luku on läpäissyt todellisen keskustelun varmennuksen; omien tekstiviestien lähetys ja tapahtumien takaisinluku ovat läpäisseet todellisen hyväksyntätestin; muut yhteystiedot, ryhmätoiminnot ja uusien instanssien palautus edellyttävät vielä käyttöönottotyöympäristön hyväksyntätestiä. Median lähetys, lainauksena vastaaminen, todellinen @-maininta, ryhmän jäsenten hallinta ja toimituskuittaukset eivät ole vielä käytettävissä. Käytä instanssin `/api/capabilities`-paluuarvoa ensisijaisena lähteenä.

## Käyttöönotto ja kirjautuminen

Ota palvelu käyttöön Deployment-luokassa ja valitse instanssin kestopaketti. Avaa käyttöönoton jälkeen hallintasivu ja skannaa QR-koodi tilin omalla WeCom-sovelluksella; jos tarvitaan puhelinvahvistusta tai muita kirjautumisvaiheita, avaa etätyöpöytä ja syötä kyseisen instanssin työpöytäsalasana. API-tunnistetiedot ja työpöytäsalasana ovat erillisiä. Kirjautumistiedot tallennetaan instanssin levylle; kontin uudelleenluonti säilyttää levyn, kun taas levyn poistaminen poistaa paikallisen istunnon.

Jokaisesta instanssista veloitetaan erikseen, ja se toimii ostetun keston ajan. REST- / MCP-kutsuista ei veloiteta erikseen viestikohtaisesti, ja todellinen hinta määräytyy pakettisivun mukaan. Nykyinen oletusviite käyttää WeChat-robotin kestopaketteja, ja lopullinen hinnoittelu on vahvistettava käytettävien suoritusresurssien perusteella ennen lopullista julkaisua.

## API ja MCP

Käytä hallintasivulla olevaa instanssin API-osoitetta; kaikki tilirajapinnat sisältävät `Authorization: Bearer <instanssin API token>`. Nämä polut kuuluvat omaan instanssiin eivätkä jaettuun API-yhdyskäytävään. MCP-osoite on instanssin osoite lisättynä polulla `/mcp/`, ja se käyttää samaa Bearer-tokenia.

| Rajapinta                                                       | Toiminto                                          |
| -------------------------------------------------------- | ------------------------------------------- |
| `GET /api/status`、`GET /api/auth/status`                 | Onko tili valmis ja ominaisuusluettelo                                 |
| `GET /api/auth/qr`                                       | Nykyinen kirjautumisen QR-koodi PNG Base64-muodossa                          |
| `GET /api/account`                                       | Nykyinen tili                                        |
| `GET /api/contacts?kind=all`                             | Sisäiset kollegat ja ulkoiset yhteystiedot; voidaan määrittää internal / external          |
| `GET /api/conversations`                                 | Paikalliset keskustelut, alkuperäiset keskustelutunnukset säilytetään                              |
| `GET /api/messages`                                      | Paikallisesti synkronoidut viestit; parametrit conversation_id, after_rowid, limit |
| `POST /api/search`                                       | Yhteystietojen, keskustelujen ja paikallisen tekstin haku                               |
| `POST /api/messages`                                     | Asynkroninen tekstinlähetystehtävä; Idempotency-Key on pakollinen               |
| `POST /api/messages/send`                                | Sama lähetysrajapinta, tukee yhtä tai useampaa kohdetta                            |
| `GET /api/groups/{conversation_id}`                      | Paikallisesti synkronoidut ryhmätiedot ja jäsenet                                 |
| `GET /api/tasks`                                         | Viimeisimmät tehtävät ja kunkin kohteen tulokset                                 |
| `GET /api/tasks/{id}`                                    | Lähetystuloksen kysely                                      |
| `POST /api/tasks/{id}/cancel`                            | Peruuta tehtävä, jota ei ole vielä aloitettu                                   |
| `POST /api/runtime/pause`、`POST /api/runtime/resume`     | Keskeytä automaatio; jatka oman varmennuksen jälkeen                               |
| `GET /api/diagnostics`、`GET /api/diagnostics/screenshot` | Instanssin tila ja nykyinen näyttö, molemmat vaativat todennuksen                              |
| `GET /api/events?after=0`                                | Viestitapahtumat palautettavalla kursorilla                                  |
| `WS /ws`                                                 | Viestitapahtumavirta, Bearer-todennus                             |

Lähetysrakenne sisältää `target`-, `type: "text"`- ja `text`-kentät. `target` hyväksyy keskustelutunnuksen, yhteystietotunnuksen, yrityskäyttäjätunnuksen tai yksilöllisen täydellisen nimen; käytä ensisijaisesti tunnuksia; jos näyttönimi ei vieläkään yksilöi kohdetta, instanssi hylkää toiminnon eikä arvaa kohdetta. Yhteystiedolle, jolla ei ole paikallista keskustelua, avataan ensin keskustelu asiakkaassa, minkä jälkeen todellinen keskustelutunnus tarkistetaan ennen lähetystä. Pyyntöotsikon `Idempotency-Key` koostuu 8–128 kirjaimesta, numerosta tai merkistä `_.:-`. Saman toiminnon toistuvissa pyynnöissä on käytettävä samaa avainta ja samaa pyyntörunkoa.

Korvaa `target` taulukolla `targets`, jotta viestejä voidaan lähettää sarjassa 1–50 yksiselitteisesti määritetylle kohteelle. Molempia ei voi antaa samanaikaisesti. Kaikkien kohteiden henkilöllisyys ratkaistaan ensin, ja samaan kohteeseen viittaavat eri aliakset hylätään. Jos jokin kohde epäonnistuu, myöhemmät lähetykset keskeytetään, ja tehtävän tulos kirjaa kohdekohtaisesti `succeeded`, `failed`, `unknown` tai `not_attempted`; älä pidä osittaista onnistumista täydellisenä onnistumisena. Tämä prosessi edellyttää vielä määritettyjen yhteystietojen todellista hyväksyntätestiä käyttöönottotyöympäristössä.

Tehtävät voivat olla tilassa queued, running, submitting, succeeded, failed, unknown tai cancelled. `succeeded` tarkoittaa, että lähetyksen jälkeen vastaavan keskustelun tietueesta löytyi täsmällinen teksti ja palvelimen viestitunnus; `delivered` on edelleen null, eikä se tarkoita, että vastaanottaja olisi saanut viestin. unknown tarkoittaa, että tulos on epäselvä; tarkista historia äläkä lähetä uudelleen uudella avaimella. Instanssi ei lähetä keskeytyneitä tehtäviä automaattisesti uudelleen.

Historia sisältää vain sisällön, jonka asiakas on jo synkronoinut, eikä se voi taata koko historiaa. Muut kuin tekstiviestit voivat palauttaa tyypin unknown, eikä liitteiden lataaminen ole vielä käytettävissä. Tapahtumat säilyttävät viimeisimmät 10 000 tietuetta, ja `gap` tarkoittaa, että kursori on ylittänyt säilytysikkunan. Ensimmäinen yhteys ei toista vanhaa historiaa uusina viesteinä.

Viestihistorian `server_accepted` ja `server_id` voidaan käyttää sen tarkistamiseen, onko palvelin hyväksynyt paikallisen viestin; jos näkyvissä on vain paikallinen tietue ilman palvelintunnusta, lähetystä ei voida katsoa onnistuneeksi. Nämä kentät eivät tarkoita, että vastaanottaja olisi vastaanottanut tai lukenut viestin. Tapahtumatietueet säilyttävät luontihetken tilan; kysy nykyinen vahvistustila viestihistoriarajapinnasta.

## Tili ja tunnistetiedot

Kirjaudu sisään vain tilille, jonka käyttöön sinulla on oikeus. Määritä API-token luotettuun sovellukseen; se voi käyttää kyseisen instanssin tilitietoja. Älä julkaise salasanoja, QR-koodeja tai keskustelujen kuvakaappauksia julkisissa paikoissa. Instanssin keskeyttäminen katkaisee reaaliaikaiset tapahtumat. Tililtä uloskirjautumisen tai laitteen poistamisen jälkeen mobiilisovelluksesta on kirjauduttava uudelleen sisään.

Nykyinen tekstinsyöttö tukee vain yhtä riviä, ja rivinvaihdot hylätään nimenomaisesti ennen lähetystä. Kun asiakas vaatii turvavarmennusta tai uudelleenkirjautumista, tilin omistajan on suoritettava se etätyöpöydällä; instanssi ei ohita varmennusta. Varmennuksen keskeyttämät tehtävät voivat palauttaa arvon unknown; kysy ensin viestitietueita äläkä lähetä uudelleen uudella idempotenssiavaimella.

Kun turvavarmennuskehote, tililtä uloskirjautuminen tai muutos havaitaan, automaatiojono keskeytetään pysyvästi. Kun puhelinvahvistus on valmis, voit jatkaa vielä suorittamattomia tehtäviä instanssin konsolin toiminnolla ”Jatka varmennuksen jälkeen”; jo lähetettyjä tehtäviä, joiden tulos on epävarma, ei lähetetä uudelleen. Myös tavallinen etätyö voi laukaista WeComin turvavarmennuksen. Virallisissa ohjeissa mainittu 24 tunnin ikkuna, jonka aikana lukitusta ei enää tehdä varmennuksen jälkeen, ei tarkoita, että havaitseminen olisi poistunut, eikä se tarkoita, että instanssi voisi taata pitkäaikaisen valvomattoman käytön.
