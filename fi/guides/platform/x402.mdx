X402 on HTTP `402 Payment Required` -vastaukseen perustuva ketjun sisäinen maksuprotokolla. Ace Data Cloudin X402-ominaisuuden avulla kutsuja voi tehdä ketjun sisäisen maksun suoraan USDC:llä jokaisessa API-pyynnössä ilman API-tokenin luomista tai tilisaldon ennakkolatausta.

Tämä dokumentaatiosarja on järjestetty todellisen integrointijärjestyksen mukaan: suorita ensin yksi vähimmäispyyntö, integroi sitten SDK ja opi sen jälkeen verkot, laskutusmallit, tilausten maksaminen ja Facilitator. On suositeltavaa lukea alla oleva taulukko ylhäältä alas.

## Suositeltu integrointipolku

Jos haluat vain kutsua Ace Data Cloud API:a, käytä ensisijaisesti virallista SDK:ta:

- TypeScript: `@acedatacloud/sdk` + `@acedatacloud/x402-client`
- Python: `acedatacloud` + `acedatacloud-x402`

Julkinen lähdekoodi ja pakettiosoitteet:

| Projekti                 | Osoite                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| Ace Data Cloud SDK | [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)                                         |
| X402 Client        | [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)                           |
| X402 Facilitator   | [https://github.com/AceDataCloud/FacilitatorX402](https://github.com/AceDataCloud/FacilitatorX402)                 |
| npm SDK            | [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)                 |
| npm X402 Client    | [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client) |
| PyPI SDK           | [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)                                   |
| PyPI X402 Client   | [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)                         |

SDK suorittaa automaattisesti ensimmäisen todentamattoman pyynnön, jäsentää `402 Payment Required` -vastauksen, kutsuu payment handleria ja yrittää uudelleen `PAYMENT-SIGNATURE`-otsakkeen kanssa. Sinun tarvitsee vain valmistella lompakko, jossa on USDC:tä, ja valita haluamasi verkko.

Jos haluat, että oma API:si tukee myös X402-maksujen vastaanottamista, sinun on luettava Facilitator-dokumentaatio ja ymmärrettävä `paymentRequirements`-, `paymentPayload`-, `/verify`- ja `/settle`-kohteiden välinen suhde.

## Tukitila

Ace Data Cloud X402 on varmennettu julkisissa API:eissa, virallisissa SDK:issa, Facilitatorissa ja ketjun sisäisissä selvityspoluissa. Alla oleva taulukko kokoaa nykyisen tilan kehittäjäintegroinnissa yleisimmin käytettyjen ominaisuusulottuvuuksien mukaan.

| Ominaisuus                       | Tila                  | Kuvaus                                                                 |
| ------------------------ | ------------------- | ------------------------------------------------------------------ |
| Facilitator capabilities | Käytettävissä                  | `https://facilitator.acedata.cloud/.well-known/x402` palauttaa maksuverkot ja protokollapäätepisteet.  |
| API 402 `accepts`        | Käytettävissä                  | Maksamattomat pyynnöt palauttavat Basen ja Solanan käytettävissä olevat payment requirementit.                    |
| TypeScript SDK           | Käytettävissä                  | `@acedatacloud/sdk` ja `@acedatacloud/x402-client` voivat käsitellä automaattisesti 402:n, allekirjoitukset ja uudelleenyritykset. |
| Python SDK               | Käytettävissä                  | `acedatacloud` ja `acedatacloud-x402` voivat käsitellä automaattisesti 402:n, allekirjoitukset ja uudelleenyritykset.              |
| Base `exact`             | Varmennettu ketjussa               | Soveltuu kiinteäsummasiin API:in ja tilausten maksamiseen.                                                  |
| Base `upto`              | Varmennettu ketjussa               | Soveltuu jälkikäteen mitattaviin API:eihin, kuten chat-täydennyksiin, ja on tällä hetkellä ainoa `upto`-toiminnon tarjoava verkko.                                 |
| Solana `exact`           | HTTP-maksettu uudelleenyritys varmennettu | API:n maksettu uudelleenyritys ja mallivastaus on varmennettu; ketjussa tehdyn allekirjoituksen vahvistamiseen suositellaan oman Solana RPC:n käyttöä täsmäytyksessä.               |
| Tilausten maksaminen                     | Varmennettu ketjussa               | Base `exact` -tilausten maksaminen on suorittanut ketjun sisäisen selvityksen ja päivittänyt tilaustilan.                                   |

Selitys:

- Sekä npm- että PyPI-paketit on asennettu puhtaaseen ympäristöön ja tuotu onnistuneesti.
- Maksamaton API-pyyntö palauttaa 402:n, ja `accepts` sisältää Basen ja Solanan käytettävissä olevat maksutavat.

- Solana `exact` on vahvistanut HTTP 402 -> HTTP 200 -ketjun ja mallin tulosteen. Koska julkisia RPC-kyselyjä saatetaan rajoittaa, tiukassa täsmäytyksessä suositellaan käyttämään omaa Solana RPC:tä tai vahvistamaan transaktioallekirjoitus alustan settlement-tiedoista.

## Integrointia koskevat huomautukset

Integroinnin aikana kehittäjien tulee ensisijaisesti kiinnittää huomiota nykyisen pyynnön palauttamiin reaaliaikaisiin maksuvaatimuksiin sen sijaan, että kopioivat dokumentaation esimerkkimääriä tai -osoitteita:

- `accepts[].maxAmountRequired` on suurin määrä, joka voidaan allekirjoittaa nykyiselle pyynnölle.
- `accepts[].asset` on tässä pyynnössä käytettävä USDC-sopimus tai mint.
- `accepts[].extra.chainId`, `accepts[].extra.facilitatorAddress` ja `accepts[].extra.verifyingContract` osallistuvat EVM typed data -allekirjoitukseen.
- `upto` edellyttää, että lompakko valtuuttaa ensin Permit2:n kohdeketjun USDC:lle; ilman valtuutusta palautetaan `PERMIT2_ALLOWANCE_REQUIRED`.
- Jos jälkikäteen tapahtuvaa mittausta halutaan nimenomaisesti käyttää, välitä TypeScript SDK:ssa `preferScheme: 'upto'`; muutoin SDK valitsee ensimmäisen palvelimen kyseiselle verkolle palauttaman käytettävissä olevan requirementin.

## Julkisesti varmennettava laajuus

Ennen integrointia voit ensin varmentaa nämä julkiset päätepisteet ja SDK-käyttäytymisen:

- API-pyyntö ilman `Authorization`- tai `PAYMENT-SIGNATURE`-otsaketta palauttaa `402 Payment Required` -vastauksen, ja vastauksen `accepts` on tämän pyynnön ainoa allekirjoitusperuste.
- Sekä TypeScript SDK että Python SDK tarjoavat payment handlerin; kun SDK:n siirtokerros vastaanottaa 402:n, se kutsuu handleria ja yrittää uudelleen kerran.
- `https://facilitator.acedata.cloud/.well-known/x402`: palauttaa Facilitatorin tukemat verkot, schemet ja protokollan päätepisteet; API-hinta määräytyy silti kohdepyynnön reaaliaikaisesti palauttaman 402-vastauksen mukaan.
- `https://facilitator.acedata.cloud/supported`: palauttaa Facilitatorin tukemat verkot ja schemet.
- X402Client-tietovarasto sisältää edistyneitä ketjussa toimivia varmennustyökaluja, joilla voidaan vahvistaa allekirjoitus-, uudelleenyritys- ja settlement-käyttäytyminen; työkalujen tuloste ei korvaa tuotannossa API:n palauttamaa `accepts`-arvoa.

`upto` kuuluu jälkikäteen tapahtuvaan mittausperusteiseen settlementiin ja soveltuu API:hin, kuten chat-täydennyksiin ja mallikutsuihin, joissa todellinen käyttömäärä tiedetään vasta vastauksen jälkeen. Tällä hetkellä vain Base tarjoaa `upto`-vaihtoehdon; jos allekirjoituksen vahvistus epäonnistuu, tarkista, että chain id, facilitator-osoite, spender, USDC-sopimus ja Permit2 allowance vastaavat 402-vastausta.
