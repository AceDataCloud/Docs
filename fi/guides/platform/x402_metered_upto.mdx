title: "X402 `exact`- ja `upto`-laskutusmallit"

Ace Data Cloud X402 käyttää tällä hetkellä kahta schemeä: `exact` ja `upto`. Ne ratkaisevat erilaisia laskutusongelmia.

## `exact`

`exact` tarkoittaa, että tämän pyynnön hinta voidaan määrittää ennen kohde-API:in siirtymistä. Asiakkaan allekirjoittama summa on lopullinen veloitettava summa.

Sopii:

- kiinteähintaiseen kuvagenerointiin;
- kiinteähintaisen videotehtävän luontiin;
- kiinteähintaisiin haku- tai työkalu-API:eihin;
- tilausten maksamiseen.

EVM `exact` käyttää USDC EIP-3009 `TransferWithAuthorization` -menetelmää:

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "exact",
    "network": "eip155:8453"
  },
  "payload": {
    "authorization": {
      "from": "0x...",
      "to": "0x...",
      "value": "95215",
      "validAfter": "1780237345",
      "validBefore": "1780240945",
      "nonce": "0x..."
    },
    "signature": "0x..."
  }
}
```

Facilitator vahvistaa allekirjoituksen ja summan `/verify`-vaiheessa ja lähettää tämän valtuutuksen ketjuun `/settle`-vaiheessa.

## `upto`

`upto` tarkoittaa, että asiakas valtuuttaa enimmäisrajan, ja Ace Data Cloud selvittää pyynnön valmistuttua todellisen käytön mukaan; todellinen veloitus ei saa ylittää enimmäisrajaa.

Sopii:

- chat-täydennyksiin: lopullinen hinta riippuu prompt-tokenien ja completion-tokenien määrästä;
- suoratoistovastauksiin: todellinen tulosteen pituus tiedetään vasta sen päätyttyä;
- tuleviin jälkikäteen mitattaviin API:eihin.

`upto` käyttää Permit2 `PermitWitnessTransferFrom` -menetelmää. Asiakas ei allekirjoita kiinteää siirtoa, vaan witnessin sisältävän enimmäisrajavaltuutuksen:

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "upto",
    "network": "eip155:8453"
  },
  "payload": {
    "permit2Authorization": {
      "from": "0x...",
      "spender": "0x4020A4f3b7b90ccA423B9fabCc0CE57C6C240002",
      "nonce": "123456789",
      "deadline": "1780240945",
      "permitted": {
        "token": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
        "amount": "95215"
      },
      "witness": {
        "to": "0x...",
        "facilitator": "0x...",
        "validAfter": "1780237345"
      }
    },
    "signature": "0x..."
  }
}
```

`permitted.amount` on enimmäisraja, ei välttämättä lopullinen veloitus. Gateway muuntaa todellisen käytön `amount`-arvoksi ja välittää sen Facilitatorille `/record`-vaiheessa. Facilitator sallii vain selvityksen, jossa `amount &lt;= permitted.amount`.

Base `upto` -ohjelman ajotulos:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
signed ceiling 95215 atomic USDC
transfer value 3 atomic USDC
```

Selitys:

- 402:ssa palautettu valtuutuksen enimmäisraja on `95215` atomic USDC, ja asiakas allekirjoittaa tämän enimmäisrajan mukaan.
- Mallin varsinaisen vastauksen jälkeen selvitetään vain `3` atomic USDC; ketjutapahtuma on nähtävissä BaseScanissa.
- Tämä tulos osoittaa `upto`-mallin keskeisen eron: allekirjoitettu summa on enimmäisraja, ja ketjussa tehtävä settlement voi olla enimmäisrajaa pienempi.
- Jos todellinen käyttö ylittää enimmäisrajan, Facilitatorin tulee hylätä settlement, ja asiakkaan on valtuutettava uudelleen suuremmalla enimmäisrajalla.

`upto` on tällä hetkellä saatavilla vain Basessa. Kun jälkikäteistä mittausta tarvitaan, käytä Basea.

## Miksi Permit2 approve tarvitaan

`upto`-mallissa x402-proxy nostaa lopulta USDC:tä maksulompakosta Permit2:n kautta. Ennen ensimmäistä käyttökertaa maksulompakon on annettava Permit2:lle kertaluonteinen ERC-20 allowance.

Python CLI:

```bash
pip install 'acedatacloud-x402[cli]'
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Ohjelmallisesti:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Valtuutuksen valmistuttua jokainen pyyntö tarvitsee silti uuden `upto` envelope -allekirjoituksen, koska nonce, deadline, witness ja summan enimmäisraja ovat kaikki erilaisia.

## Nollasumman settlement

`upto` tukee tilannetta, jossa todellinen summa on 0. Esimerkiksi jos kohde-API ei tuota onnistuneesti laskutettavaa käyttöä, Gateway voi välittää `amount = "0"`. Facilitator palauttaa onnistumisen, mutta ei lähetä ketjutapahtumaa.

Tämä voi välttää ongelman, jossa ”pyyntö ei onnistunut, mutta ketjussa veloitetaan silti maksu”.

## Valintasuositukset

| Tilanne                   | Suositus                       |
| ------------------------- | ------------------------------ |
| Kiinteähintainen API      | Käytä `exact`-mallia, logiikka on yksinkertainen. |
| Tilauksen maksu           | Käytä `exact`-mallia.          |
| Chat-täydennykset, token-perusteinen laskutus | Käytä Base `upto` -mallia. |
| Permit2 approvea ei ole vielä tehty | Ota ensin `exact` käyttöön ja vaihda sitten `upto`-malliin. |

Jos et ole varma, kumman valitsisit, käytä ensin SDK:n oletustoimintaa; SDK valitsee palvelimen palauttaman vastaavan verkon payment requirementin.

## Base `upto` -tarkistuslista

Integroitaessa tai vianetsinnässä varmista, että seuraavat parametrit tulevat samasta 402-vastauksesta ja pysyvät samoina asiakkaan allekirjoittaessa:

| Parametri                  | Tarkistettava kohta                                          |
| -------------------------- | ------------------------------------------------------------ |
| `network`                  | Täytyy olla `eip155:8453`.                                   |
| `scheme`                   | Täytyy olla `upto`.                                          |
| `extra.chainId`            | Base chain id on `8453`.                                     |
| `asset`                    | Käytä 402-vastauksessa olevaa Base USDC -sopimusosoitetta.   |
| `extra.facilitatorAddress` | Sen täytyy osallistua witnessiin ja vastata Facilitatorin `/supported`-arvoa. |
| Permit2 allowance          | Maksulompakon on ensin valtuutettava Permit2 Base USDC:lle.  |

Yleiset virheet ja käsittelytavat:

| Virhe                                           | Käsittelytapa                                                                          |
| ----------------------------------------------- | -------------------------------------------------------------------------------------- |
| `invalid_upto_evm_payload_invalid_signature`   | Tarkista, että chain id, facilitator-osoite, Permit2 domain, spender, allekirjoitustili ja witness vastaavat 402-vastausta. |
| `PERMIT2_ALLOWANCE_REQUIRED`                    | Suorita Permit2 approve kohdeketjun USDC:lle ja lähetä pyyntö uudelleen.              |
| `amount exceeds permitted amount`               | Todellinen käyttö ylittää allekirjoitetun enimmäisrajan; allekirjoita uudelleen suuremmalla enimmäisrajalla. |
