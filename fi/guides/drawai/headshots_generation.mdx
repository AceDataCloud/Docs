Tässä artikkelissa esitellään AI-passikuvien valmistus API -liittymän ohjeet, jonka avulla voidaan luoda erilaisia passikuvia syöttämällä henkilökuvan URL-osoite sekä haluamasi malli.

## Hakuprosessi

API:n käyttämiseksi sinun on ensin mentävä [AI-passikuvien valmistus API](https://platform.acedata.cloud/documents/bf7214a3-8447-4157-8a75-f5bb39d5ed1b) -sivulle ja haettava vastaavaa palvelua. Sivulle päästyäsi, napsauta "Acquire" -painiketta, kuten kuvassa näkyy:

![](https://cdn.acedata.cloud/q6ytrc.png)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Kirjautumisen ja rekisteröitymisen jälkeen palaat automaattisesti nykyiselle sivulle.

Ensimmäisellä hakukerralla saat ilmaisia krediittejä, joiden avulla voit käyttää tätä API:a ilmaiseksi.

## Peruskäyttö

Ensinnäkin on hyvä ymmärtää peruskäyttötapa, eli syöttää käsiteltävä henkilökuva sekä haluamasi AI-passikuvamalli, jolloin saat käsitellyn tuloksen. Ensinnäkin sinun on yksinkertaisesti välitettävä `image_urls`-kenttä, joka on käsiteltävien henkilökuvien linkkien taulukko, kuten kuvassa näkyy:

<p><img src="https://cdn.zhishuyun.com/2024-11-03-d23744954ca4819503469f04f2268aa0.jpg" width="500" class="m-auto"></p>

Sitten meidän on myös syötettävä haluamamme malli. Tässä artikkelissa on tarjolla kahdeksan suosituinta mallia, tarkemmat mallit löytyvät alla:

```json
{
   "male_portrait":  Mieskuva
   "male_portrait2":  Mieskuva (toinen versio)
   "kindergarten":  Lastentarhakuvia
   "logo_tshirt": Yrityksen logo T-paidassa
   "wedding":  Häätodistuskuva
   "business_photo":  Liiketoimintakuva
   "bob_suit": Musta puku bob-leikkauksella
   "female_portrait":  Naiskuva
}
```

Sen jälkeen voimme myös määrittää luontinopeusparametrin `mode`, joka jakautuu yleensä kahteen: hidas `relax` ja nopea `fast`, tarkat tiedot ovat seuraavat:

<p><img src="https://cdn.acedata.cloud/73xbla.png" width="500" class="m-auto"></p>

Täällä voimme nähdä, että olemme asettaneet Request Headers, mukaan lukien:

- `accept`: haluamasi vastausmuoto, tässä täytetään `application/json`, eli JSON-muoto.
- `authorization`: API:n kutsumiseen tarvittava avain, jonka voit valita suoraan alasvetovalikosta hakemisen jälkeen.

Lisäksi on asetettu Request Body, joka sisältää:

- `mode`: passikuvan luontikanava, pääasiassa on kaksi vaihtoehtoa: fast (nopea) ja relax (hidas). Kun käytät relaxia, suositellaan vahvasti käyttämään alla olevaa parametria `callback_url`.
- `template`: passikuvamallin tyyli.
- `image_urls`: ladattavien passikuvien linkit.
- `callback_url`: URL, johon tulokset palautetaan.

Valinnan jälkeen voit huomata, että oikealla puolella on myös luotu vastaava koodi, kuten kuvassa näkyy:

<p><img src="https://cdn.acedata.cloud/yp49hc.png" width="500" class="m-auto"></p>

Napsauta "Try" -painiketta, niin voit testata, kuten yllä olevassa kuvassa näkyy, ja saamme seuraavanlaisen tuloksen:

```json
{
  "success": true,
  "task_id": "ae1e4948-dba1-4a6f-87af-67961b647428",
  "data": [
    {
      "id": "202411031951124776",
      "image_url": "https://platform.cdn.acedata.cloud/headshots/ae1e4948-dba1-4a6f-87af-67961b647428.png",
      "template": "Mieskuva"
    },
    {
      "id": "202411031951128490",
      "image_url": "https://platform.cdn.acedata.cloud/headshots/ae1e4948-dba1-4a6f-87af-67961b647428.png",
      "template": "Mieskuva"
    }
  ]
}
```

Palautetussa tuloksessa on useita kenttiä, jotka esitellään seuraavasti:

- `success`, passikuvan luontitehtävän tila.
- `task_id`, passikuvan luontitehtävän ID.
- `data`, passikuvan luontitehtävän tuloslista.
  - `id`, passikuvan luontitehtävän valokuvan ID.
  - `image_url`, passikuvan luontitehtävän kuvalinkki.
  - `template`, passikuvan luontitehtävän passikuvamallin nimi.

Voimme nähdä, että olemme saaneet tyytyväisiä passikuvainformaatiota mallin ja henkilökuvan perusteella, ja voimme vain käyttää tuloksessa olevaa `data`-kuvalinkkiä saadaksemme passikuvan.

Lisäksi, jos haluat luoda vastaavan liityntäkoodin, voit suoraan kopioida sen, esimerkiksi CURL-koodi on seuraava:

```shell
curl -X POST 'https://api.acedata.cloud/headshots/generate' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "mode": "fast",
  "template": "male_portrait",
  "image_urls": ["https://cdn.zhishuyun.com/2024-11-03-d23744954ca4819503469f04f2268aa0.jpg"]
}'
```

## Asynkroninen palautus

Koska AI-passikuvien luominen vie suhteellisen pitkään, noin 1-2 minuuttia, jos API ei vastaa pitkään aikaan, HTTP-pyyntö pitää yhteyden auki, mikä johtaa ylimääräisiin järjestelmäresurssien kulutuksiin. Siksi tämä API tarjoaa myös asynkronisen palautuksen tuen.

Kokonaisprosessi on seuraava: kun asiakas lähettää pyynnön, se määrittää ylimääräisen `callback_url`-kentän. Kun asiakas lähettää API-pyynnön, API palauttaa heti tuloksen, joka sisältää `task_id`-kentän tiedot, joka edustaa nykyistä tehtävän ID:tä. Kun tehtävä on valmis, passikuvan tulos lähetetään POST JSON -muodossa asiakkaan määrittämään `callback_url`:iin, johon sisältyy myös `task_id`-kenttä, jolloin tehtävän tulos voidaan yhdistää ID:n avulla.

Katsotaanpa esimerkin avulla, miten tämä toimii.

Ensinnäkin, Webhook-palaute on palvelu, joka voi vastaanottaa HTTP-pyyntöjä, ja kehittäjän tulisi korvata se omalla HTTP-palvelimensa URL-osoitteella. Tässä esimerkin vuoksi käytämme julkista Webhook-esimerkkisivustoa https://webhook.site/, avaa tämä sivusto saadaksesi Webhook URL:n, kuten kuvassa näkyy:

![](https://cdn.acedata.cloud/sb4p3v.png)

Kopioi tämä URL, niin voit käyttää sitä Webhookina, tässä esimerkki on `https://webhook.site/00f38b26-4289-4899-83d6-0cea7308850a`.

Seuraavaksi voimme asettaa kentän `callback_url` yllä olevaan Webhook URL:iin, samalla kun täytämme henkilökuvan linkin ja mallin. Tässä artikkelissa suositellaan käyttämään asynkronista palautusta, kun parametrin `mode` arvo on `relax`, tarkat tiedot ovat kuvassa näkyvissä:

<p><img src="https://cdn.acedata.cloud/opt326.png" width="500" class="m-auto"></p>

Napsauta Suorita, ja huomaat, että saat heti tuloksen, kuten seuraavassa:

```
{
  "task_id": "763b1450-8804-434f-acc7-d713be73a28f"
}
```

Odota hetki, niin voit tarkastella luotua tulosta osoitteessa `https://webhook.site/00f38b26-4289-4899-83d6-0cea7308850a`, kuten kuvassa näkyy:
![](https://cdn.acedata.cloud/ym6fw1.png)

Sisältö on seuraava:

```json
{
    "success": true,
    "task_id": "763b1450-8804-434f-acc7-d713be73a28f",
    "data": [
        {
            "id": "202411032010131366",
            "image_url": "https://platform.cdn.acedata.cloud/headshots/763b1450-8804-434f-acc7-d713be73a28f.png",
            "template": "Mieskuva"
        },
        {
            "id": "202411032010132420",
            "image_url": "https://platform.cdn.acedata.cloud/headshots/763b1450-8804-434f-acc7-d713be73a28f.png",
            "template": "Mieskuva"
        }
    ]
}
```

Voit nähdä, että tuloksessa on `task_id`-kenttä, muut kentät ovat samankaltaisia kuin edellä, tämän kentän avulla voidaan toteuttaa tehtävän yhteys.

## Virheiden käsittely

API:ta kutsuttaessa, jos kohtaat virheen, API palauttaa vastaavat virhekoodit ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `400 api_not_implemented`: Huono pyyntö, mahdollisesti puuttuvien tai virheellisten parametrien vuoksi.
- `401 invalid_token`: Ei valtuutettu, virheellinen tai puuttuva valtuutustoken.
- `429 too_many_requests`: Liian monta pyyntöä, olet ylittänyt nopeusrajoituksen.
- `500 api_error`: Sisäinen palvelinvirhe, jotain meni pieleen palvelimella.

### Virhevastauksen esimerkki

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
