GLM (General Language Model) on Zhipu AI:n (Zhipu AI / Z.ai) esittelemä uusi sukupolvi suurista kielimalleista, jotka omaavat vahvat kiinan ja englannin ymmärtämisen ja tuottamisen kyvyt. Se on erinomaisesti suoriutunut kiinalaisissa ympäristöissä, koodin tuottamisessa, päättelyssä ja monivaiheisissa keskusteluissa. Uuden sukupolven mallit kuten GLM-5.3, GLM-5.2, GLM-4.7 ovat saaneet paljon optimointeja pitkissä konteksteissa, työkalujen kutsumisessa ja kooditehtävissä, ja niitä voidaan laajasti soveltaa älykkäissä kysymys-vastaus, sisällöntuotanto, koodin apu, asiakaspalvelurobotit ja muissa ympäristöissä.

Tässä asiakirjassa esitellään pääasiassa GLM Chat Completion API:n käyttöprosessi, jonka avulla voit helposti kutsua GLM-sarjan malleja yhtenäisen OpenAI-yhteensopivan rajapinnan kautta.

## Hakuprosessi

Käyttääksesi GLM Chat Completion API:a, sinun on ensin mentävä [Ace Data Cloud -hallintapaneeliin](https://platform.acedata.cloud/console/applications) saadaksesi API-tunnuksesi, jota voit säilyttää varalla.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jos et ole vielä kirjautunut sisään tai rekisteröitynyt, sinut ohjataan automaattisesti kirjautumissivulle, jossa sinua kutsutaan rekisteröitymään ja kirjautumaan sisään. Valmiina ollessasi sinut ohjataan takaisin nykyiselle sivulle.

**Yksi API-tunnus riittää kutsumaan kaikkia palveluja, eikä jokaiselle palvelulle tarvitse hakea erikseen.** Ensimmäisellä hakemiskerralla saat ilmaisen käyttöoikeuden, jonka avulla voit kokeilla ilmaiseksi; jos käyttöoikeus loppuu, voit ladata yleistä saldoa [hallintapaneelista](https://platform.acedata.cloud/console/coin).

## Peruskäyttö

GLM Chat Completion API:n pyyntöosoite on `https://api.acedata.cloud/glm/chat/completions`, ja se käyttää Bearer Token -tunnistusta. Pyyntöruumis on yhteensopiva OpenAI Chat Completions -protokollan kanssa.

Ensimmäisellä kerralla, kun käytät tätä rajapintaa, meidän on täytettävä vähintään kolme sisältöä:

- `authorization`: Valitse suoraan pudotusvalikosta Bearer Token.
- `model`: Valitse kutsuttava GLM-malli, tällä hetkellä tuetut mallit ovat:
  - `glm-5.3`: Uusin lippulaivamalli, tukee 1M kontekstia ja pisimmillään 128K ulostuloa, sopii monimutkaisiin päättely-, koodi- ja agenttitehtäviin. Päättely on aina päällä, ja voit valita `reasoning_effort` arvot `low`, `high` tai `max`.
  - `glm-5.2`: Edellisen sukupolven lippulaivamalli, jolla on vahvat kokonaiskyvyt.
  - `glm-5.1`: Kypsä lippulaivamalli, sopii yleisiin monimutkaisiin tehtäviin.
  - `glm-4.7`: Suoriutuu erinomaisesti päättely-, työkalujen kutsumis- ja kooditehtävissä.
  - `glm-4.6`: Yleinen keskustelumalli, tasapainottaa tehokkuuden ja kustannukset.
  - `glm-3-turbo`: Klassinen keskustelumalli, soveltuu yleisiin tekstin tuottamistehtäviin.
- `messages`: Vihjeiden taulukko, jokaisessa viestissä on `role` ja `content`, `role` tukee kolmea roolia: `user`, `assistant`, `system`.

Yleisesti käytetyt valinnaiset parametrit:

- `max_tokens`: Rajoittaa yhden vastauksen enimmäistoken-määrää.
- `temperature`: Tuotannon satunnaisuus, arvot 0-2, suurempi arvo tarkoittaa hajontaa.
- `top_p`: Ydinotanta-parametri, joka hallitsee ehdokkaiden tokenien kumulatiivista todennäköisyysrajaa.
- `n`: Kuinka monta ehdokasvastausta tuotetaan kerralla.
- `stream`: Onko virtaava vastaus käytössä, oletusarvo `false`.
- `stop`: Mukautettu lopetusjakso.

Alla on yksinkertaisin Python-kutsun esimerkki:

```python
import requests

url = "https://api.acedata.cloud/glm/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "glm-5.2",
    "messages": [
        {"role": "user", "content": "hello"}
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Kutsun jälkeen huomaamme, että palautettu tulos on seuraava:

```json
{
  "id": "msg_202604262252030313862701a04e33",
  "model": "glm-5.2",
  "object": "chat.completion",
  "created": 1777215124,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! 👋 How can I assist you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 10,
    "completion_tokens": 23,
    "total_tokens": 33
  }
}
```

Palautetun tuloksen pääkenttien selitykset ovat seuraavat:

- `id`: Tämän keskustelutehtävän ainutlaatuinen ID.
- `created`: Tämän keskustelutehtävän luomisaika (Unix-aikaleima, sekunnit).
- `model`: Todellinen kutsuttu GLM-mallin nimi.
- `choices`: Mallin tuottamien vastausten lista. `choices[i].message.content` on mallin vastausteksti, `finish_reason` merkitsee lopetusperustetta (`stop`, `length`, `tool_calls`, `content_filter` jne.).
- `usage`: Tämän pyynnön token-käytön tilastot, sisältäen `prompt_tokens`, `completion_tokens`, `total_tokens`.

## Virtaava vastaus

Tämä rajapinta tukee virtaavaa vastausta (Server-Sent Events), mikä on erittäin hyödyllistä verkkosivujen integroinnissa, ja se mahdollistaa verkkosivujen toteuttavan sana sanalta -näyttöefektin.

Jos haluat virtaavan palautteen, aseta pyyntöruumassa `stream`-parametri arvoksi `true`.

Python-esimerkkikutsun koodi:

```python
import requests

url = "https://api.acedata.cloud/glm/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "glm-4.7",
    "messages": [{"role": "user", "content": "hi"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers, stream=True)
for line in response.iter_lines():
    if line:
        print(line.decode("utf-8"))
```

Tulostus näyttää tältä (poiminta):
```text

data: {"id": "msg_2026042622521271f765bbc3734ce1", "object": "chat.completion.chunk", "created": 1777215133, "model": "glm-4.7", "choices": [{"delta": {"content": "Hei! Onko jotain, jossa voin"}, "finish_reason": null, "index": 0}], "usage": null}
```

Voit nähdä, että vastauksessa on paljon `data`, jokainen `data` sisältää inkrementaalisen osan. `choices[i].delta.content` on nykyinen chunkin uusi tekstiosuus, voit yhdistää nämä osat muodostaaksesi täydellisen vastauksen. Kun `data` sisältö on `[DONE]`, se tarkoittaa, että striimausvastaus on päättynyt. Viimeinen chunk, jossa on `usage`, tiivistää tämän pyynnön token-käytön.

JavaScript (Node.js) esimerkki:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "glm-4.7",
    messages: [{ role: "user", content: "hi" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/glm/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Java esimerkkikoodi:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "glm-4.7");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "hi")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);

  .url("https://api.acedata.cloud/glm/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Muita kieliä voi muokata erikseen, periaate on sama.

## Monivaiheinen keskustelu

Jos haluat toteuttaa monivaiheisen keskustelutoiminnon, sinun on lisättävä aiemmat keskustelut `messages` taulukkoon ja säilytettävä `user` ja `assistant` vuorotellen.

Python esimerkkikutsu:

```python
import requests

url = "https://api.acedata.cloud/glm/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "glm-4.7",
    "messages": [
        {"role": "user", "content": "Hei"},
        {"role": "assistant", "content": "Hei! Kuinka voin auttaa sinua tänään?"},
        {"role": "user", "content": "Mitä sanoin juuri nyt?"}
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Lähettämällä useita kysymyksiä voit helposti toteuttaa monivaiheisen keskustelun ja saada seuraavanlaisen vastauksen:

```json
{
  "id": "msg_20260426225208b95324e9945a48d3",
  "model": "glm-4.7",
  "object": "chat.completion",
  "created": 1777215128,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Sanoit: **\"Hei\"** 😊\n\nIlmoita, jos tarvitset jotain muuta!"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 48,
    "completion_tokens": 37,
    "total_tokens": 85
  }
}
```

Voit nähdä, että `choices` sisältää tietoa, joka on peruskäytön mukainen, malli antaa vastauksen täydellisen keskusteluhistorian perusteella, mikä tukee monivaiheista konteksti-interaktiota.

## Järjestelmän kehotus (System Prompt)

Voit lisätä `messages` alkuun viestin, jonka `role` on `system`, rajoittaaksesi mallin roolia, tyyliä tai käyttäytymistä:

```python
payload = {
    "model": "glm-4.7",
    "messages": [
        {"role": "system", "content": "Olet kokenut kiinalaisen kirjoitusavustaja, vastaa tiiviisti ja ammattimaisesti."},
        {"role": "user", "content": "Esittele GLM-malli kolmella lauseella."}
    ]
}
```

## Työkalujen kutsuminen (Function Calling)

GLM-malli tukee OpenAI-yhteensopivaa Työkalujen kutsumista, voit ilmoittaa kutsuttavat funktiot `tools` parametrilla, malli palauttaa tarvittaessa rakenteellista funktiokutsutietoa `choices[i].message.tool_calls` kentässä.

```python
payload = {
    "model": "glm-4.7",
    "messages": [
        {"role": "user", "content": "Miten on sään tänään Pekingissä?"}
    ],
    "tools": [
        {
            "type": "function",
            "function": {
                "name": "get_weather",
                "description": "Tarkista tietyn kaupungin sää",
                "parameters": {
                    "type": "object",
                    "properties": {
                        "city": {"type": "string", "description": "Kaupungin nimi"}
                    },
                    "required": ["city"]
                }
            }
        }
    ]
}
```

Jos malli päättää kutsua työkalua, palautetun tuloksen `finish_reason` muuttuu `tool_calls`:ksi, ja `message.tool_calls` antaa funktion nimen ja JSON-merkkijonona muodossa olevat parametrit. Voit suorittaa kyseisen funktion ja palauttaa tuloksen `role` olevan `tool` viestinä mallille, jolloin saat kokonaisen työkalukutsusilmukan päätökseen.

## Mallin valintasuositukset
| Malli          | Soveltamisalue                                   |
| --------------- | -------------------------------------------- |
| `glm-5.3`      | Uusin lippulaiva, 1M konteksti, pisin 128K ulostulo, suositellaan käytettäväksi monimutkaisessa päättelyssä, koodissa ja Agent-tehtävissä |
| `glm-5.2`      | Edellisen sukupolven lippulaiva, sopii monimutkaiseen päättelyyn, koodiin ja Agent-tehtäviin                    |
| `glm-5.1`      | Kypsä lippulaiva, sopii monimutkaiseen päättelyyn, pitkien asiakirjojen analysointiin                            |
| `glm-4.7`      | Työkalujen kutsuminen, koodin generointi, Agentin orkestrointi jne.                        |
| `glm-4.6`      | Yleinen keskustelu, tasapainoinen valinta sisällön luomiseen                               |
| `glm-3-turbo`  | Yleiset tekstin generointitehtävät, kustannustietoiset tilanteet                            |

## Virheiden käsittely

API:ta kutsuttaessa, jos kohtaat virheen, API palauttaa vastaavan virhekoodin ja tiedot. Esimerkiksi:

- `400 token_mismatched`: Pyyntöparametrit puuttuvat tai ovat virheellisiä.
- `400 api_not_implemented`: Käytetään tukemattomia parametreja tai malleja.
- `401 invalid_token`: Ei valtuutettu, Bearer Token puuttuu tai on vanhentunut.
- `429 too_many_requests`: Ylittää taajuusrajoituksen, yritä myöhemmin uudelleen.
- `500 api_error`: Palvelimen sisäinen virhe tai ylävirta ei ole tilapäisesti saatavilla.

### Virhevastauksen esimerkki

```json
{
  "trace_id": "69ea9bcf-c5da-41a3-be97-c80912a08523",
  "error": {
    "code": "api_error",
    "message": "Palvelu on tilapäisesti käytettävissä, yritä myöhemmin uudelleen."
  }
}
```

Kun palautuu `api_error` ja viesti on `Palvelu on tilapäisesti käytettävissä, yritä myöhemmin uudelleen.`, se yleensä tarkoittaa, että ylävirran GLM-palvelu ei ole tilapäisesti saatavilla, suositellaan kokeilemaan eksponentiaalista taustakäynnistystä tai vaihtamaan toiseen saatavilla olevaan GLM-malliin (esimerkiksi siirtymään `glm-5.1`:stä tilapäisesti `glm-4.7`:ään tai `glm-4.6`:een).
