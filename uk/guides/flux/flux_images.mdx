У цій статті буде представлено опис інтеграції Flux Images Generation API, який може генерувати офіційні зображення Flux шляхом введення користувацьких параметрів.

## Процес подання заявки

Щоб використовувати Flux Images Generation API, спочатку отримайте свій API Token у [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб мати його напоготові.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, не потрібно подавати окрему заявку для кожного сервісу.** Під час першого подання заявки надається безкоштовна квота для безкоштовного ознайомлення; коли квоти недостатньо, можна поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Базове використання

Спочатку ознайомтеся з базовим способом використання: введіть ключове слово `prompt`, дію генерації `action`, розмір зображення `size`, і ви зможете отримати оброблений результат. Спочатку потрібно просто передати поле `action` зі значенням `generate`, а потім також потрібно ввести ключове слово, конкретний вміст наведено нижче:

<p><img src="https://cdn.acedata.cloud/wz85jt.png" width="500" className="m-auto" /></p>

Тут можна побачити, що ми налаштували Request Headers, зокрема:

- `accept`: у якому форматі ви хочете отримати результат відповіді, тут вказано `application/json`, тобто формат JSON.
- `authorization`: ключ для виклику API, після подання заявки його можна безпосередньо вибрати зі спадного списку.

Також налаштовано Request Body, зокрема:

- `action`: дія цього завдання генерації зображення.
- `size`: розмір результату генерації зображення. **Для серій `flux-2-flex` / `flux-2-pro` / `flux-2-max` обов’язково потрібно передавати співвідношення сторін зображення (наприклад, `1:1`, `16:9`), піксельні розміри на кшталт `1024x1024` не приймаються, за замовчуванням буде повернуто 400.**
- `count`: кількість згенерованих зображень, значення за замовчуванням — 1; цей параметр дійсний лише для завдань генерації зображень і недійсний для завдань редагування.
- `prompt`: ключове слово.
- `model`: модель генерації, за замовчуванням `flux-dev`; найновіші флагманські моделі — `flux-2-pro`, `flux-2-max` (вища якість зображення, необхідно використовувати разом зі співвідношенням сторін `size`).
- `callback_url`: URL, на який потрібно надіслати результат зворотного виклику.
- `async`: необов’язково, коли встановлено `true`, інтерфейс негайно повертає `task_id`, не потрібно надавати `callback_url`, після чого результат отримується шляхом опитування через відповідний інтерфейс запиту завдань.

Параметр `size`має деякі особливі обмеження, переважно поділяється на два типи: співвідношення ширини й висоти `width x height` та співвідношення сторін зображення `x:y`, конкретно наведено нижче:

| Модель               | Діапазон                                         |
| ---------------- | ------------------------------------------ |
| flux-dev         | Підтримує співвідношення ширини й висоти 1024x1024, 1024x1792, 1792x1024 або співвідношення сторін зображення |
| flux-pro         | Підтримує співвідношення ширини й висоти 1024x1024, 1024x1792, 1792x1024 або співвідношення сторін зображення |
| flux-2-flex      | Підтримує лише співвідношення сторін зображення                                    |
| flux-2-pro       | Підтримує лише співвідношення сторін зображення                                    |
| flux-2-max       | Підтримує лише співвідношення сторін зображення                                    |
| flux-kontext-pro | Підтримує лише співвідношення сторін зображення                                    |
| flux-kontext-max | Підтримує лише співвідношення сторін зображення                                    |

Рекомендовані співвідношення сторін зображення: "21:9", "16:9", "4:3", "3:2", "1:1", "2:3", "3:4", "9:16", "9:21".

Після вибору параметрів праворуч автоматично буде згенеровано відповідний код. Перед копіюванням переконайтеся, що заголовок авторизації використовує ваш власний API Key, у документації та знімках екрана не повинні відображатися справжні облікові дані.

Натисніть кнопку «Try», щоб провести тестування, тут ми отримали наступний результат:

```json
{
  "success": true,
  "task_id": "5456c749-3bbb-4f10-9eb8-cfbcac297500",
  "trace_id": "ae4eecb8-1dd6-45b4-bfb3-a1c48872536e",
  "data": [
    {
      "image_url": "https://cdn.acedata.cloud/assets/examples/flux/5456c749-3bbb-4f10-9eb8-cfbcac297500-d0ef60485f73.jpg"
    }
  ]
}
```

Результат, що повертається, містить кілька полів, описаних нижче:

- `success`, статус завдання генерації відео в цей момент.
- `task_id`, ID завдання генерації відео в цей момент.
- `trace_id`, ID відстеження генерації відео в цей момент.
- `data`, список результатів завдання генерації зображень у цей момент.
  - `image_url`, посилання завдання генерації зображення в цей момент.
  - `prompt`, ключове слово.

Можна побачити, що ми отримали задовільну інформацію про зображення, нам потрібно лише отримати згенероване зображення Flux за адресою посилання на зображення у `data` результату.

Крім того, якщо ви хочете згенерувати відповідний код інтеграції, його можна безпосередньо скопіювати, наприклад, код CURL наведено нижче:

```shell
curl -X POST 'https://api.acedata.cloud/flux/images' \
-H 'authorization: Bearer {token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "A photorealistic studio product shot of a frosted-glass perfume bottle on wet black slate, single softbox key light, water droplets, dark moody background, 85mm macro.",
  "model": "flux-2-pro",
  "size": "1:1"
}'
```

## Завдання редагування зображень

Якщо ви хочете відредагувати певне зображення, спочатку параметр `image_url`обов’язково має містити посилання на зображення, яке потрібно редагувати, у цьому випадку `action` підтримує лише `edit`, тоді можна вказати наступний вміст:

- model: модель, що використовується для цього завдання редагування зображення, підтримуються `flux-dev`, `flux-pro`, `flux-kontext-pro`, `flux-kontext-max`, `flux-2-flex`, `flux-2-pro`, `flux-2-max`.
- image_url: завантажте зображення, яке потрібно редагувати.

Приклад заповнення наведено нижче:

<p><img src="https://cdn.acedata.cloud/jn9da5.png" width="500" className="m-auto" /></p>

Після заповнення автоматично згенеровано такий код:

<p><img src="https://cdn.acedata.cloud/6cwxb8.png" width="500" className="m-auto" /></p>

Відповідний код:

```python
import requests

url = "https://api.acedata.cloud/flux/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "edit",
    "prompt": "a white siamese cat",
    "model": "flux-kontext-pro",
    "image_url": "https://cdn.acedata.cloud/ytj2qy.png"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Натисніть запуск, і можна виявити, що результат буде отримано негайно, як показано нижче:

```json
{
  "success": true,
  "task_id": "2a7979ff-1f77-4380-92c6-a2dc37c3b4c8",
  "trace_id": "732b65c0-48d9-49f7-b568-64e5acffe4c0",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "timings": 1752744073
    }
  ]
}
```
Можна побачити, що згенерований ефект є ефектом редагування вихідного зображення, результат подібний до наведеного вище.

## Асинхронний зворотний виклик

Оскільки час генерації Flux Images Generation API є відносно тривалим, приблизно 1–2 хвилини, якщо API довгий час не відповідає, HTTP-запит постійно підтримуватиме з’єднання, що призводить до додаткового споживання системних ресурсів, тому цей API також підтримує асинхронний зворотний виклик.

Загальний процес такий: коли клієнт ініціює запит, він додатково вказує поле `callback_url`, після того як клієнт ініціює API-запит, API одразу повертає результат, який містить інформацію поля `task_id`, що представляє ID поточного завдання. Після завершення завдання результат генерації зображення буде надіслано у формі POST JSON до `callback_url`, вказаного клієнтом, де також міститься поле `task_id`, таким чином результат завдання можна пов’язати через ID.

Нижче ми на прикладі дізнаємося, як саме це робити.

Спочатку, Webhook-зворотний виклик — це сервіс, який може приймати HTTP-запити, розробник має замінити його на URL власноруч налаштованого HTTP-сервера. Тут для зручності демонстрації використовується публічний сайт-приклад Webhook https://webhook.site/; відкривши цей сайт, можна отримати Webhook URL, як показано на зображенні:

![](https://cdn.acedata.cloud/cjjfly.png)

Скопіювавши цей URL, його можна використовувати як Webhook; приклад тут — `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`.

Далі ми можемо встановити для поля `callback_url` вказаний вище Webhook URL, водночас заповнивши відповідні параметри; конкретний вміст показано на зображенні:

<p><img src="https://cdn.acedata.cloud/wm6caw.png" width="500" className="m-auto" /></p>

Натисніть запуск, і можна побачити, що результат буде отримано негайно, як показано нижче:

```
{
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c"
}
```

Зачекавши деякий час, ми можемо побачити результат генерації зображення на `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`, як показано на зображенні:

![](https://cdn.acedata.cloud/v23lot.png)

Вміст наведено нижче:

```json
{
  "success": true,
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c",
  "trace_id": "9b4b1ff3-90f2-470f-b082-1061ec2948cc",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "seed": 1698551532,
      "timings": {
        "inference": 3.328

```

Можна побачити, що в результаті є поле `task_id`, інші поля подібні до наведених вище, через це поле можна реалізувати пов’язування завдань.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Занадто багато запитів, ви перевищили ліміт частоти.
- `500 api_error`：Внутрішня помилка сервера, на сервері щось пішло не так.

### Приклад відповіді з помилкою

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
