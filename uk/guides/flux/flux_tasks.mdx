Основна функція Flux Tasks API полягає в запиті статусу виконання завдання за ID завдання платформи, поверненим Flux Images Generation API або Flux Videos API.

У цьому документі буде детально представлено інструкції з інтеграції Flux Tasks API, щоб допомогти вам легко інтегрувати та повною мірою використовувати потужні можливості цього API. Через Flux Tasks API ви можете легко реалізувати запит статусу виконання завдань Flux Images Generation API.

Повний приклад надсилання відео та опитування дивіться в [Посібнику з інтеграції Flux Videos API](https://platform.acedata.cloud/documents/flux-videos-integration). За запит наявних завдань додаткова плата за генерацію не стягується.

## Процес подання заявки

Щоб використовувати Flux Images Generation API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати свій API Token і залишити його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, не потрібно подавати окрему заявку для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт, який можна безкоштовно випробувати; якщо ліміту недостатньо, ви можете поповнити універсальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Приклад запиту

Flux Tasks API можна використовувати для запиту результатів Flux Images Generation API. Щодо того, як використовувати Flux Images Generation API, дивіться документацію [Flux Images Generation API ](https://platform.acedata.cloud/documents/flux-images-integration).

Ми візьмемо як приклад один ID завдання, повернений сервісом Flux Images Generation API, щоб продемонструвати, як використовувати цей API. Припустімо, у нас є ID завдання: 2db0168c-2373-4367-8d9a-9dc778802e8a, далі продемонструємо, як через передавання одного ID завдання.

### Налаштування заголовків запиту та тіла запиту

**Request Headers** включають:

- `accept`: вказує на отримання результату відповіді у форматі JSON, тут заповнюється як `application/json`.
- `authorization`: ключ для виклику API, після отримання заявки можна безпосередньо вибрати зі спадного списку.

**Request Body** включає:

- `id`: ID завантаженого завдання.
- `action`: спосіб операції над завданням.

Налаштування показано на зображенні нижче:

### Приклад коду

Можна побачити, що праворуч на сторінці вже автоматично згенеровано код різними мовами, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/j6gn86.png" width="500" className="m-auto" /></p>

Деякі приклади коду наведено нижче:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/flux/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/flux/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```


Результат, що повертається, містить кілька полів, поле request — це request body під час запуску завдання, водночас поле response — це response body, повернене після завершення завдання. Опис полів наведено нижче.

- `id`: ID згенерованого завдання зображення, використовується для унікальної ідентифікації цього завдання генерації зображення.
- `request`: інформація запиту в завданні запиту зображення.
- `response`: інформація відповіді в завданні запиту зображення.
- `created_at`: час створення завдання, Unix timestamp (секунди, число з плаваючою комою).
- `started_at`: час початку виконання завдання, Unix timestamp (секунди, число з плаваючою комою).
- `finished_at`: час завершення завдання, Unix timestamp (секунди, число з плаваючою комою). Якщо завдання не завершено, це поле не повертається.
- `elapsed`: тривалість виконання завдання, у секундах (число з плаваючою комою, до 3 знаків після коми). Якщо завдання не завершено, це поле не повертається.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та повідомлення. Наприклад:

- `400 token_mismatched`：Некоректний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Некоректний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Занадто багато запитів, ви перевищили ліміт швидкості.
- `500 api_error`：Внутрішня помилка сервера, на сервері щось пішло не так.
