## Динамічний каталог моделей

Спочатку можна відкрити [каталог моделей](https://platform.acedata.cloud/models), щоб переглянути поточні назви моделей, наприклад `claude-opus-5`, `gpt-6-sol`. Якщо потрібно підтвердити, чи відповідають облікові дані Coding і протокол API один одному, виконайте запит із дійсними обліковими даними Coding Application:

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_TOKEN"
```

Каталог моделей постійно змінюється; у цій статті не підтримується фіксована кількість або статичний список моделей. `id` кожного запису у відповіді — це **назва моделі**, яку можна безпосередньо передати параметру API `model`; наприклад, `{"id":"deepseek-v4-pro"}` відповідає значенню `deepseek-v4-pro`; це не UUID сервісу, API або Application. `/v1/models` повертає глобальний каталог моделей і не фільтрується автоматично за обліковими даними Coding; перед налаштуванням усе одно потрібно перехресно підтвердити обсяг API облікових даних, вибраний протокол і діапазон сумісності клієнта.

## Поширене усунення несправностей

- **Недостатньо балансу**: перейдіть до [консолі Applications](https://platform.acedata.cloud/console/applications), знайдіть Coding Application і самостійно поновіть підписку.
- **Клієнт і далі надсилає запити на початкову адресу**: підтвердьте, що налаштування належить тому самому користувачу та робочому простору, який запускає клієнт, і повністю закрийте та перезапустіть клієнт.
- **Назва моделі недоступна**: повторно надішліть запит до `/v1/models`, перевірте, чи введена назва моделі повністю збігається з `id` у каталозі, а також API scope облікових даних і протокол, що підтримується клієнтом.
- **Token не може викликати інтерфейс**: переконайтеся, що облікові дані належать Coding Application, і перевірте `allowed_api_ids` та дозволи API застосунку.
