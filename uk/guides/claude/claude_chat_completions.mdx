Anthropic Claude — це дуже потужна система AI-діалогів, яка лише за кілька секунд може згенерувати плавну й природну відповідь після введення підказки. Claude вирізняється в галузі своїми чудовими можливостями розуміння та генерації мови; сьогодні Claude вже широко застосовується в різних галузях і сферах, а його вплив стає дедалі помітнішим. Чи то повсякденні діалоги, творче письмо, професійні консультації або програмування коду — Claude може надавати вражаючу інтелектуальну допомогу, значно підвищуючи ефективність роботи та творчі здібності людей.

У цьому документі переважно представлено процес використання операцій Claude Chat Completion API, за допомогою якого ми можемо легко використовувати функції діалогу офіційного Claude.

## Базове використання

Далі можна заповнити відповідний вміст в інтерфейсі, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Під час першого використання цього інтерфейсу нам потрібно заповнити щонайменше три поля: одне з них — `authorization`, його можна безпосередньо вибрати зі спадного списку. Інший параметр — `model`, можна вибрати публічні моделі, як-от `claude-opus-5-5`, `claude-fable-5-1` тощо; оригінальний `claude-fable-5` також можна й надалі викликати. Останній параметр — `messages`, це масив запитів, кожен елемент містить `role` і `content`; `role` підтримує `user`, `assistant`, `system`, а `content` є конкретним вмістом. Якщо потрібні повні блоки мислення Claude, підпис і семантика нативних інструментів, як і раніше використовуйте Messages API.

Водночас ви можете звернути увагу, що праворуч є генерація відповідного коду виклику: ви можете скопіювати код і запустити його безпосередньо, або натиснути кнопку «Try» для тестування.

Поширені необов’язкові параметри:

- `max_tokens`: обмежує максимальну кількість токенів в одній відповіді.
- `temperature`: випадковість генерації, від 0 до 2; що більше значення, то більш розгалуженим буде результат.
- `n`: скільки варіантів відповіді генерувати за один раз.
- `response_format`: налаштування формату відповіді.

`claude-opus-5-5` підтримує звичайні та потокові Chat Completions; ця модель дозволяє лише `n=1`. Не встановлюйте для неї `temperature` нижче 1 або нестандартний `top_p`; для виклику інструментів використовуйте `tool_choice: "auto"`, не вказуйте інструмент примусово. Chat-сумісний інтерфейс не повертає нативні блоки мислення.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Після виклику бачимо, що результат, який повертається, є таким:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }
}
```

Результат, що повертається, містить кілька полів, описаних нижче:

- `id` — ID згенерованого завдання цього діалогу, використовується для унікальної ідентифікації цього завдання діалогу.
- `model ` — вибрана модель Claude з офіційного сайту.
- `choices` — інформація про відповідь Claude на запит.
- `usage `: статистична інформація про токени для цього запитання та відповіді.

У форматі Chat Completions `usage.prompt_tokens` є загальним обсягом введення; `prompt_tokens_details.cached_tokens` і `prompt_tokens_details.cache_write_tokens` відповідно фіксують деталі читання та запису кешу. `completion_tokens_details.reasoning_tokens` є підмножиною `completion_tokens`, під час обчислення загального обсягу або вартості не додавайте його повторно. Непотокова відповідь також може повертати об’єкт `usage.cost`, де `amount` — фактичне споживання ліміту, `currency` — одиниця вимірювання, а `list_amount` — сума до знижки (за наявності).

Назва поля Chat-compatible — `reasoning_tokens`; нативний Messages API використовує `output_tokens_details.thinking_tokens`. Wire schema двох протоколів відрізняються, тому клієнт не повинен змішувати назви полів.

Серед них `choices` містить інформацію про відповідь Claude, а `choices` всередині нього є конкретною інформацією про відповідь Claude, як можна побачити на зображенні.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Можна побачити, що поле `content` у `choices` містить конкретний вміст відповіді Claude.

## Потокова відповідь

Цей інтерфейс також підтримує потокову відповідь, що дуже корисно для інтеграції з вебсторінками та може дозволити вебсторінці реалізувати ефект посимвольного відображення.

Якщо ви хочете повертати відповідь потоково, можна змінити параметр `stream ` у заголовку запиту на `true`.

Зміна показана на зображенні, але код виклику потребує відповідних змін для підтримки потокової відповіді.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

Після зміни `stream` на `true` API повертатиме відповідні JSON-дані рядок за рядком, і на рівні коду нам потрібно внести відповідні зміни, щоб отримати результати рядок за рядком.

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Глибоке мислення
Нові покоління моделей Claude можуть виконувати міркування відповідно до стандартної стратегії моделі, без необхідності активації через суфікс моделі `-thinking`. Chat-compatible відповіді використовують сумісне з OpenAI поле usage `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` вже включено до `completion_tokens`, не додавайте їх повторно. Міркування та видимий основний текст спільно використовують ліміт вихідних токенів, тому за малого значення `max_tokens` основний текст може бути порожнім або обрізаним; у такому разі збільште бюджет виходу або, якщо використовувана модель це підтримує, виберіть нижчий рівень вкладення в міркування.

Якщо потрібні нативні `thinking`, `output_config.effort`, блоки вмісту thinking і повернення підпису, використовуйте `/v1/messages`. Відповідне поле usage для Messages — `output_tokens_details.thinking_tokens`, не змішуйте його з `completion_tokens_details.reasoning_tokens` для Chat-compatible.

## Візуальна модель

claude-sonnet-4-20250514 — це мультимодальна велика мовна модель, розроблена Claude, яка на основі claude-4 додає можливість візуального розуміння. Ця модель може одночасно обробляти текстові та зображувальні вхідні дані, реалізуючи міжмодальне розуміння та генерацію.

Обробка тексту з використанням моделі claude-sonnet-4-20250514 узгоджується з основним вмістом використання, описаним вище, нижче буде коротко представлено, як використовувати можливості моделі для обробки зображень.

Можливість обробки зображень моделі claude-sonnet-4-20250514 переважно реалізується шляхом додавання поля `type` на основі початкового вмісту `content`; за допомогою цього поля можна визначити, чи завантажується текст або зображення, і таким чином використати можливості обробки зображень моделі claude-sonnet-4-20250514. Можна побачити, що вміст відповіді сформовано на основі зображення, тому за допомогою наведених вище двох способів можна легко використовувати можливості моделі claude-3-7-sonnet-20250219 для обробки тексту та зображень.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API повертає відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Забагато запитів, ви перевищили ліміт швидкості.
- `500 api_error`：Внутрішня помилка сервера, на сервері щось пішло не так.
