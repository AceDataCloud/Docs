Anthropic Claude — це надзвичайно потужна система AI-діалогів: достатньо ввести підказку, і вона за лічені секунди згенерує плавну та природну відповідь. Claude вирізняється в індустрії своїми чудовими можливостями розуміння та генерації мови. Сьогодні Claude вже широко застосовується в різних галузях і сферах, а його вплив стає дедалі помітнішим. Чи то повсякденні діалоги, креативне письмо, професійні консультації або програмування коду — Claude може надати вражаючу інтелектуальну допомогу, значно підвищуючи ефективність роботи та творчі здібності людей.

Цей документ переважно описує процес використання операцій Claude Chat Completion API, за допомогою якого ми можемо легко користуватися функцією діалогів офіційного Claude.

## Базове використання

Далі можна заповнити відповідний вміст в інтерфейсі, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Під час першого використання цього інтерфейсу нам потрібно заповнити щонайменше три поля: одне з них — `authorization`, його можна безпосередньо вибрати зі спадного списку. Інший параметр — `model`, рекомендується використовувати найновішу флагманську модель `claude-fable-5-1`; попередню `claude-fable-5` все ще можна продовжувати викликати. Останній параметр — `messages`, це масив текстів запитань, кожен елемент містить `role` і `content`; `role` підтримує `user`, `assistant`, `system`, а `content` — це конкретний вміст. Claude Fable 5.1 підтримує контекст у 1 мільйон Token і максимальний вивід у 128K Token.

Водночас ви можете звернути увагу, що праворуч генерується відповідний код виклику: ви можете скопіювати код і запустити його безпосередньо або натиснути кнопку «Try» для тестування.

Поширені необов'язкові параметри:

- `max_tokens`：обмежує максимальну кількість token в одній відповіді.
- `temperature`：випадковість генерації, від 0 до 2; що більше значення, то більш розсіяний результат.
- `n`：скільки кандидатів відповідей генерувати за один раз.
- `response_format`：налаштування формату повернення.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Після виклику ми бачимо, що результат повертається таким:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }
}
```

Результат, що повертається, містить кілька полів, описаних нижче:

- `id`，ID створеного завдання цього діалогу, що використовується для унікальної ідентифікації цього завдання діалогу.
- `model `，вибрана модель Claude з офіційного сайту.
- `choices`，інформація про відповідь Claude на текст запитання.
- `usage `：статистична інформація щодо token для цієї пари запитання-відповідь.

У форматі Chat Completions `usage.prompt_tokens` — це загальний обсяг введення; `prompt_tokens_details.cached_tokens` і `prompt_tokens_details.cache_write_tokens` відповідно записують деталі читання та запису кешу. `completion_tokens_details.reasoning_tokens` є підмножиною `completion_tokens`, тому під час обчислення загального обсягу або вартості не додавайте їх повторно. Непотокова відповідь також може повертати об'єкт `usage.cost`, де `amount` — це фактичне споживання ліміту, `currency` — одиниця вимірювання, а `list_amount` — сума до знижки (за наявності).

Назва поля для Chat-compatible — `reasoning_tokens`; нативний Messages API використовує `output_tokens_details.thinking_tokens`. Wire schema двох протоколів відрізняється, тому клієнт не повинен змішувати назви полів.

Серед них `choices` містить інформацію про відповідь Claude, а `choices` всередині нього — це конкретна інформація про відповідь Claude, як можна побачити на зображенні.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Можна побачити, що поле `content` у `choices` містить конкретний вміст відповіді Claude.

## Потокова відповідь

Цей інтерфейс також підтримує потокові відповіді, що дуже корисно для інтеграції з вебсторінками та дозволяє реалізувати ефект посимвольного відображення на вебсторінці.

Якщо ви хочете повертати відповідь потоково, можна змінити параметр `stream ` у заголовку запиту на `true`.

Зміни показано на зображенні, однак код виклику потребує відповідних змін для підтримки потокової відповіді.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

Після зміни `stream` на `true` API повертатиме відповідні JSON-дані рядок за рядком, і на рівні коду нам потрібно внести відповідні зміни, щоб отримувати результати рядок за рядком.

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Глибоке міркування
Нове покоління моделей Claude може виконувати міркування відповідно до стратегії моделі за замовчуванням, без необхідності активації через суфікс моделі `-thinking`. Chat-compatible відповіді використовують сумісне з OpenAI поле usage `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` уже включено до `completion_tokens`, будь ласка, не додавайте їх повторно. Міркування та видимий основний текст спільно використовують обмеження вихідних token, тому за малого значення `max_tokens` основний текст може бути порожнім або обрізаним; у такому разі збільште вихідний бюджет або, якщо використовувана модель це підтримує, виберіть нижчий рівень міркувань.

Якщо потрібні нативні `thinking`, `output_config.effort`, блоки вмісту thinking та повернення підпису, використовуйте `/v1/messages`. Відповідне поле usage для Messages — `output_tokens_details.thinking_tokens`, не змішуйте його з `completion_tokens_details.reasoning_tokens` для Chat-compatible.

## Візуальні моделі

claude-sonnet-4-20250514 — це мультимодальна велика мовна модель, розроблена Claude, яка на основі claude-4 отримала можливість візуального розуміння. Ця модель може одночасно обробляти текстові та графічні входи, реалізуючи міжмодальне розуміння та генерацію.

Обробка тексту з використанням моделі claude-sonnet-4-20250514 узгоджується з основним вмістом використання вище, нижче буде коротко представлено, як використовувати можливості моделі з обробки зображень.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API повертає відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Занадто багато запитів, ви перевищили обмеження швидкості.
- `500 api_error`：Внутрішня помилка сервера, щось пішло не так на сервері.

### Приклад відповіді з помилкою

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
