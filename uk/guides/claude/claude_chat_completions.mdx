Anthropic Claude — це дуже потужна система AI-діалогів, яка може генерувати плавні та природні відповіді всього за кілька секунд після введення підказки. Claude вирізняється в галузі своїми чудовими можливостями розуміння та генерації мови. Сьогодні Claude вже широко застосовується в різних галузях і сферах, а його вплив стає дедалі помітнішим. Чи то повсякденні діалоги, творче письмо, професійні консультації або програмування коду — Claude може надавати вражаючу інтелектуальну допомогу, значно підвищуючи ефективність роботи та творчість людей.

Цей документ переважно описує процес використання операцій Claude Chat Completion API, за допомогою якого ми можемо легко використовувати офіційні функції діалогів Claude.

## Claude Fable 5.2

Використовуйте повну назву моделі `claude-fable-5-2`. Ця модель підходить для складних міркувань і довготривалих завдань; коли потрібні нативні блоки вмісту міркувань і взаємодія з інструментами, пріоритетно використовуйте Messages. Адаптивне мислення постійно увімкнене, не вказуйте `temperature`, `top_p`, `top_k`, для вибору інструментів використовуйте `auto`, не примусово вказуйте інструмент. `max_tokens` одночасно охоплює мислення та фінальний текст. Наразі інтерфейси Responses і Count Tokens для цієї моделі не надаються.

У перерахунку за поточним максимальним пакетом (142,800 Credits／$13,584), звичайний вхід Fable 5.2 становить $3.20, а вихід — $16／мільйон token; читання кешу — $0.08, запис кешу на 5 хвилин／1 годину відповідно — $4／$6.40／мільйон token. Зазначені вище ціни становлять 40% від офіційної стандартної ціни API (на 60% дешевше); щодо інших пакетів і додаткових знижок для облікових записів звертайтеся до сторінки цін на моделі та рахунку.

## Базове використання

Далі ви можете заповнити відповідний вміст в інтерфейсі, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Під час першого використання цього інтерфейсу нам щонайменше потрібно заповнити три значення: одне з них — `authorization`, яке можна безпосередньо вибрати у випадаючому списку. Інший параметр — `model`, можна вибрати публічні моделі, як-от `claude-opus-5-5`, `claude-fable-5-1` тощо; початкову `claude-fable-5` усе ще можна продовжувати викликати. Останній параметр — `messages`, це масив запитів, кожен елемент містить `role` і `content`; `role` підтримує `user`, `assistant`, `system`, а `content` є конкретним вмістом. Якщо потрібні повні блоки вмісту мислення Claude, підпис і нативна семантика інструментів, усе одно використовуйте Messages API.

Водночас ви можете помітити, що праворуч є генерація відповідного коду виклику, ви можете скопіювати код і запустити його безпосередньо або прямо натиснути кнопку «Try» для тестування.

Поширені необов’язкові параметри:

- `max_tokens`: обмежує максимальну кількість token в одній відповіді.
- `temperature`: випадковість генерації, від 0 до 2, чим більше значення, тим більш розсіяний результат.
- `n`: скільки кандидатів-відповідей генерувати за один раз.
- `response_format`: налаштування формату відповіді.

`claude-opus-5-5` підтримує звичайні та потокові Chat Completions; ця модель дозволяє лише `n=1`. Не встановлюйте для неї `temperature` нижче 1 або нестандартний `top_p`, для виклику інструментів використовуйте `tool_choice: "auto"`, не примусово вказуйте інструмент. Сумісний інтерфейс Chat не повертає нативні блоки вмісту мислення.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Після виклику ми бачимо, що результат, який повертається, є таким:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }
}
```

Результат, що повертається, містить кілька полів, описаних нижче:

- `id` — ID згенерованого завдання цього діалогу, що використовується для унікальної ідентифікації цього завдання діалогу.
- `model ` — вибрана модель Claude з офіційного сайту.
- `choices` — інформація про відповідь, надану Claude на запит.
- `usage `: статистична інформація про token для цієї пари запитання-відповідь.

У форматі Chat Completions `usage.prompt_tokens` — це загальний обсяг вхідних даних; `prompt_tokens_details.cached_tokens` і `prompt_tokens_details.cache_write_tokens` відповідно фіксують деталі читання та запису кешу. `completion_tokens_details.reasoning_tokens` є підмножиною `completion_tokens`, не додавайте його повторно під час розрахунку загального обсягу або вартості. Непотокова відповідь також може повертати об’єкт `usage.cost`, де `amount` — це фактичне споживання ліміту, `currency` — одиниця вимірювання, а `list_amount` — сума до знижки (за наявності).

Назва поля у Chat-compatible — `reasoning_tokens`; нативний Messages API використовує `output_tokens_details.thinking_tokens`. Wire schema двох протоколів відрізняються, клієнт не повинен змішувати назви полів.

Серед них `choices` містить інформацію про відповідь Claude, а `choices` всередині нього є конкретною інформацією про відповідь Claude, як можна побачити на зображенні.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Можна побачити, що поле `content` у `choices` містить конкретний вміст відповіді Claude.

## Потокова відповідь

Цей інтерфейс також підтримує потокові відповіді, що дуже корисно для інтеграції з вебсторінками та може дозволити вебсторінці реалізувати ефект посимвольного відображення.

Якщо ви хочете повертати відповідь потоком, можна змінити параметр `stream ` у заголовку запиту на `true`.

Зміна показана на зображенні, але код виклику потребує відповідних змін для підтримки потокової відповіді.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>
Після зміни `stream` на `true` API повертатиме відповідні JSON-дані рядок за рядком, і на рівні коду нам потрібно внести відповідні зміни, щоб отримувати результати рядок за рядком.

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Багатораундовий діалог

Якщо ви хочете інтегрувати функцію багатораундового діалогу, потрібно передати кілька запитів у полі `messages`; конкретний приклад кількох запитів показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/odwx82.png" width="400" className="m-auto" /></p>

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Глибоке мислення

Моделі Claude нового покоління можуть виконувати міркування відповідно до стратегії моделі за замовчуванням, без потреби в активації через суфікс моделі `-thinking`. Chat-compatible відповіді використовують сумісне з OpenAI поле usage `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` уже включено до `completion_tokens`, не додавайте їх повторно. Міркування та видимий основний текст спільно використовують ліміт вихідних токенів, тому за малого значення `max_tokens` основний текст може бути порожнім або обрізаним; у такому разі збільште бюджет виводу або, якщо використовувана модель це підтримує, виберіть нижчу інтенсивність міркувань.

Якщо потрібні нативні `thinking`, `output_config.effort`, блоки вмісту thinking і повернення підпису, використовуйте `/v1/messages`. Відповідне поле usage для Messages — `output_tokens_details.thinking_tokens`; не змішуйте його з `completion_tokens_details.reasoning_tokens` для Chat-compatible.

## Візуальна модель

claude-sonnet-4-20250514 — це мультимодальна велика мовна модель, розроблена Claude, яка на основі claude-4 отримала можливість візуального розуміння. Ця модель може одночасно обробляти текстові та графічні вхідні дані, реалізуючи міжмодальне розуміння та генерацію.

Текстова обробка з використанням моделі claude-sonnet-4-20250514 узгоджується з описом базового використання вище; нижче буде коротко представлено, як використовувати можливість обробки зображень моделі.

Можливість обробки зображень моделі claude-sonnet-4-20250514 головним чином реалізується шляхом додавання поля `type` на основі початкового вмісту `content`; за допомогою цього поля можна визначити, чи завантажується текст або зображення, і таким чином використовувати можливість обробки зображень моделі claude-sonnet-4-20250514. Нижче переважно описано виклик цієї функції двома способами: Curl і Python.

- Спосіб за допомогою скрипту Curl

```
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "claude-sonnet-4-20250514",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "What'\''s in this image?"
          },
          {
            "type": "image_url",
            "image_url": {
              "url": "https://cdn.acedata.cloud/ueugot.png"
            }
          }
        ]
      }
    ]
  }'
```

- Спосіб за допомогою скрипту Python

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-sonnet-4-20250514",
    "messages": [
        {
            "role": "user",
            "content": [
                {
                    "type": "text", "text": "What's in this image?"
                },
                {
                    "type": "image_url",
                    "image_url": {
                        "url": "https://cdn.acedata.cloud/ueugot.png"
                    }
                },
            ],
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Потім можна отримати наведений нижче результат; інформація про поля в результаті узгоджується з наведеною вище, а саме:


## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`: Поганий запит, можливо через відсутні або недійсні параметри.
- `400 api_not_implemented`: Поганий запит, можливо через відсутні або недійсні параметри.
- `401 invalid_token`: Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`: Забагато запитів, ви перевищили ліміт швидкості.
- `500 api_error`: Внутрішня помилка сервера, на сервері щось пішло не так.
