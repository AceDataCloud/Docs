Цей посібник налаштовує **Third-Party Inference Gateway** для Claude Desktop, а не Claude Code і не MCP Connector для Claude Desktop.

## 1. Отримайте API Key

Відкрийте [список застосунків Ace Data Cloud](https://platform.acedata.cloud/console/applications), перейдіть до доступного застосунку та скопіюйте API Key.

![Отримання API Key Ace Data Cloud](https://cdn.acedata.cloud/dvc3cg.jpg)

## 2. Відкрийте конфігурацію стороннього інференсу

На сторінці входу Claude Desktop послідовно відкрийте **Help → Troubleshooting → Enable Developer Mode**, а потім виберіть **Developer → Configure Third-Party Inference…**.

![Відкриття Third-Party Inference у Claude Desktop](https://cdn.acedata.cloud/713ffd7104a3.png)

> Зображення взято з репозиторію Bifrost Apache-2.0 і використовується лише для орієнтування в меню Claude Desktop; інтерфейс різних версій може дещо відрізнятися.

## 3. Налаштуйте Gateway

Виберіть **Gateway**, а потім заповніть:

| Поле                  | Значення                    |
| ------------------- | --------------------------- |
| Gateway base URL    | `https://api.acedata.cloud` |
| Gateway API key     | Щойно скопійований API Key  |
| Gateway auth scheme | `bearer`                    |
| Credential kind     | `Static API key`            |

![Екран налаштування Gateway у Claude Desktop](https://cdn.acedata.cloud/68d41fe682cb.png)

Натисніть **Apply Changes**, а потім натисніть **Save & Restart**.

## 4. Перевірка

Після перезапуску виберіть доступну модель, створіть новий діалог і надішліть `Reply only OK`, а потім виконайте просте завдання з інструментом. Записи викликів можна переглянути в [історії використання](https://platform.acedata.cloud/console/usages).

Ace Data Cloud Gateway підтримує `/v1/models`, потоковий `/v1/messages` з Bearer-автентифікацією, виклики інструментів і продовження `tool_result`, які використовує Claude Desktop. Поля кешування підказок буде збережено; значення запису та читання кешу, що дорівнюють 0, не означають, що сталося потрапляння в кеш.

401 зазвичай означає, що Key неправильний; якщо модель не знайдено, повторно перевірте конфігурацію та повністю перезапустіть Claude Desktop. Повідомляючи про проблему, надайте trace ID із запису виклику, але не надавайте API Key.
