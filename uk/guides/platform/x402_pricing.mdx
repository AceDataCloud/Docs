Цей документ пояснює, як визначається ціна під час виклику Ace Data Cloud API через X402, і який її зв’язок зі звичайною ціною **Credits** (кредитів) на платформі.

## Основний висновок

X402 не є окремою системою ціноутворення. Кожен виклик API спочатку має вартість у **Credits**, і це єдине джерело ціни, спільне для всіх способів оплати (списання кредитів через API Token, балансу акаунта, ончейн-платежу X402). X402 лише конвертує цю вартість у Credits в ончейн USDC за фіксованим курсом:

> **1 Credit = 0.095215 USDC**（тобто `95215` atomic USDC, USDC має 6 знаків після коми）

Тобто:

```text
Ціна X402 (USDC) = вартість цього виклику в Credits × 0.095215
```

Цей курс не встановлений довільно: він дорівнює **найвигіднішій категорії (великий обсяг) ціни Credits** на платформі. Отже, оплата через X402 ≈ купівля Credits за ціною найвигіднішої категорії з подальшим використанням, **без надбавки X402**; навпаки, ви одразу отримуєте найдешевшу ціну Credits, без необхідності поповнювати баланс заздалегідь і без API Token.

## База ціноутворення

| Пункт        | Значення                       | Пояснення                                                    |
| --------- | ------------------------------ | ----------------------------------------------------- |
| Курс конвертації      | `1 Credit = 0.095215 USDC`     | Фіксований курс, єдино встановлений платформою                                           |
| Одиниця atomic | `1 Credit = 95215 atomic USDC` | USDC має 6 знаків після коми, `atomic = floor(credits × 0.095215 × 1e6)` |
| Мінімальне списання      | `1 atomic USDC`（$0.000001）     | Навіть якщо вартість надзвичайно мала, розраховується щонайменше 1 atomic                                 |
| Валюта розрахунку      | USDC                           | Base — ERC-20 USDC, Solana — SPL USDC                  |

Конвертація виконується платформою централізовано, а сума однакова для всіх підтримуваних мереж (Base, Solana); різні мережі відрізняються лише контрактом активу та способом підпису, ціна однакова.

### Зв’язок зі звичайною ціною Credits

Credits на платформі продаються за ступінчастою системою «чим більший обсяг, тим нижча ціна за одиницю». Під час оплати через X402 за виклик завжди використовується ціна найвигіднішої категорії:

| Спосіб купівлі/оплати        | Орієнтовна ціна Credits за одиницю            | Пояснення                   |
| -------------- | ------------------------ | -------------------- |
| Початкове / мале поповнення      | приблизно `$0.13 / Credit`       | Ціна зі списку, ціна за одиницю при купівлі Credits малими обсягами |
| Великий обсяг / найвигідніша категорія       | `$0.095215 / Credit`     | Найдешевша ціна за одиницю               |
| **Оплата X402 за виклик** | **`$0.095215 / Credit`** | **Завжди дорівнює ціні найвигіднішої категорії**        |

Інакше кажучи, X402 розраховує кожен виклик за ціною Credits найвигіднішої категорії. Для користувачів, які купують Credits малими поповненнями, ціна за одиницю буде вищою, ніж у X402; лише для користувачів із великими поповненнями ціна за одиницю збігається з X402.

## Дві форми ціни: `exact` та `upto`

У відповіді X402 зі статусом 402, `maxAmountRequired` — це сума, яку потрібно підписати. Вона має дві форми:

- **`exact`（фіксована ціна）**：ціну можна визначити до обробки запиту (зображення, відео, музика, пошук, оплата замовлення). `maxAmountRequired = вартість виклику в Credits × 0.095215`, тобто сума до сплати за цей виклик (збігається з `cost.amount` у відповіді після успішного виконання).
- **`upto`（облік використання після завершення）**：для таких інтерфейсів, як чат-доповнення, де «лише після завершення відповіді відомо, скільки token було використано». `maxAmountRequired` є **верхньою межею** (конвертується на основі встановленого для цієї моделі ліміту: ліміт Credits × 0.095215), фактичний розрахунок здійснюється за реальним використанням і не перевищує цієї межі.

Деталі протоколу щодо цих двох схем дивіться в [схемах тарифікації `exact` та `upto`](https://platform.acedata.cloud/documents/x402-metered-upto). Нижче розглядаються лише ціни.

## Ціни Chat (чат-доповнення)

Чат-доповнення використовують облік `upto`: оплата стягується за фактичне використання token prompt / completion. Ціна за кожен мільйон (1M) token = `вартість цієї моделі в Credits за 1M token × 0.095215`, і повністю збігається з ціною в USD, показаною у публічному каталозі моделей платформи (`/api/v1/models?with_pricing=true`).

У таблиці нижче наведено реальні ціни (отримані з каталогу моделей, розраховані за курсом X402), в одиницях USD / 1M token:

| Модель                | Вхід / 1M | Вихід / 1M  | Ліміт `upto`             |
| ----------------- | ------- | -------- | --------------------- |
| gpt-4o-mini       | $0.0796 | $0.3183  | 1 Credit（$0.095215）   |
| gemini-2.5-flash  | $0.1591 | $1.3262  | 5 Credits（$0.476074）  |
| gpt-5 / gpt-5.1   | $0.6631 | $5.3050  | 20 Credits（$1.904299） |
| gemini-2.5-pro    | $0.6631 | $5.3050  | 50 Credits（$4.760750） |
| gpt-4.1           | $1.0610 | $4.2440  | 20 Credits（$1.904299） |
| claude-sonnet-4-5 | $0.6006 | $3.0028  | 50 Credits（$4.760750） |
| grok-4            | $1.5915 | $7.9574  | 10 Credits（$0.952149） |
| claude-opus-4-1   | $3.0028 | $15.0140 | 50 Credits（$4.760750） |

Примітки:

- У таблиці наведені ціни за одиницю, що вимірюється в token; вартість одного запиту = вхідні token × ціна входу за одиницю + вихідні token × ціна виходу за одиницю.
- Ліміт `upto` — це максимальна сума, яку дозволено підписати для одного запиту цієї моделі; це не фактичне списання, і більшість запитів значно нижчі за цей ліміт.
- Ліміт визначає лише «скільки може бути списано максимум», фактичний розрахунок виконується на основі використання token.

### Приклад: котирування та списання збігаються（`exact`）

Нижче наведено один **реальний платний виклик**, здійснений до `serp/google` за допомогою офіційного X402Client (Base `exact`). Він демонструє узгодженість трьох значень: котирування 402, суми підпису та `cost`, поверненого в успішній відповіді.

```text
# 1) Неоплачений запит -> 402, отримання котирування (без списання)
POST /serp/google  ->  402
base/exact maxAmountRequired = 952 atomic = $0.000952 = 0.01 Credit
# 0.01 × 0.095215 = 0.00095215, округлення вниз до atomic = 952

# 2) Підписати за допомогою гаманця PAYMENT-SIGNATURE на 952 atomic, повторити спробу
POST /serp/google (PAYMENT-SIGNATURE) -> 200
body.cost = {"amount": 0.000952, "currency": "usdc", "settlement": "authorized"}
```
Повернуте у відповіді `cost.amount` (0.000952 USDC) повністю відповідає котируванню 402 і `Credits × 0.095215`. Поле `settlement` — це статус розрахунку цього платежу (`authorized` = авторизовано); ончейн-розрахунок обробляється платформою, механізм див. у [схемах тарифікації `exact` та `upto`](https://platform.acedata.cloud/documents/x402-metered-upto)。

### Розрахунок котирування `upto` (чат)

Чат вимірюється за токенами. Котирування (не верхня межа) для певного запиту розраховується за такою формулою (на прикладі gpt-4o-mini):

```text
Credits = 1e-6 × (0.835733 × prompt_tokens + 3.342933 × completion_tokens)
USDC    = Credits × 0.095215
```

Запит із 500 prompt + 200 completion токенами:

```text
Credits = 1e-6 × (0.835733 × 500 + 3.342933 × 200) ≈ 0.001086 Credits
Котирування USDC ≈ 0.001086 × 0.095215 ≈ $0.0001034
```

Клієнт підписує верхню межу `upto` (для gpt-4o-mini 1 Credit = `95215` atomic), це лише **максимально можлива сума списання**; фактичне котирування цього запиту (у наведеному прикладі приблизно $0.0001) значно нижче за верхню межу, розрахунок здійснюється за використанням токенів. Ончейн-механізм розрахунку `upto` див. у [схемах тарифікації `exact` та `upto`](https://platform.acedata.cloud/documents/x402-metered-upto)。

## Ціни інших сервісів (фіксована ціна `exact`)

Пояснення:

- Ціна одного й того самого сервісу змінюється залежно від **моделі, роздільної здатності, тривалості та дії** (особливо для відео). Наведена вище таблиця містить фактичні значення для одного набору параметрів і слугує лише орієнтиром масштабу.
- Для API з фіксованою ціною (`exact`) `maxAmountRequired` у 402-відповіді цього запиту є сумою до сплати за цей раз (збігається з `cost.amount` успішної відповіді, як уже виміряно в попередньому розділі).
- Кожна ціна отримується шляхом округлення вниз `Credits × 0.095215` до одиниць atomic (див. базу тарифікації вище), використовується той самий коефіцієнт конвертації, що й для чату. Через представлення чисел із плаваючою комою та округлення окремі значення можуть відрізнятися від простого добутку на 1 atomic ($0.000001); завжди слід орієнтуватися на значення, повернуте 402.

## Ціна оплати замовлення

Під час оплати замовлення в консолі X402 (купівля пакета / поповнення Credits) ціна визначається відображенням на сторінці замовлення, а `amount` у 402 є остаточною підставою для підпису. Оплата замовлення здійснюється через API платформи та потребує токена облікового запису, див. докладніше в [посібнику з оплати замовлення](https://platform.acedata.cloud/documents/x402-order-payment)。

Один реальний приклад із посібника з оплати замовлення (купівля 10 Credits):

```text
description Ace Data Cloud Credits x 10.0
created price 1.26          # Ціна створення замовлення (USD)
settled    1.20 USDC        # Остаточна сума підпису/розрахунку (= 402 amount)
            = 1200000 atomic USDC
```

Зверніть увагу: **оплата за виклик** (наведені вище Chat / інші сервіси) та **оплата замовлення** — це два різні шляхи. Для оплати за виклик завжди використовується найвигідніша ціна `0.095215`/Credit; оплата замовлення здійснюється за ціною пакета, а різницю між його ціною створення та остаточною сумою розрахунку слід див. у [посібнику з оплати замовлення](https://platform.acedata.cloud/documents/x402-order-payment)。

## Як отримувати ціни в реальному часі

Ціни змінюються залежно від моделі та параметрів, отримуйте їх програмно в реальному часі, не кодуйте їх жорстко:

- **Ціна за виклик**: надішліть до цільового API один запит **без** `PAYMENT-SIGNATURE` (також без `Authorization`) і прочитайте повернене 402 `accepts[].maxAmountRequired`. На цьому етапі списання не відбувається. Для API `exact` це остаточна ціна; для API `upto` (чат) це верхня межа, а фактичний розрахунок здійснюється за використанням.
- **Ціна чату за токен**: `GET https://platform.acedata.cloud/api/v1/models?with_pricing=true&type=chat`, прочитайте `pricing.input_usd` / `pricing.output_usd` кожної моделі (вже розраховано за `credit_usd_rate`).
- **Перевірка конвертації**: `atomic = floor(Credits × 0.095215 × 1e6)`，`USDC = atomic / 1e6` (тобто `USDC ≈ Credits × 0.095215`)。

Приклад мінімального запиту для отримання ціни:

```bash
curl -sS -X POST https://x402.acedata.cloud/midjourney/imagine \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "a cat"}'
# Повертає 402, accepts[].maxAmountRequired є ціною цього виклику (exact)
```

## Підсумок
- Ціна X402 = вартість Credits за цей виклик × `0.095215`, це **та сама ціна**, що й за звичайною тарифікацією Credits, лише розрахунок здійснюється ончейн USDC.
- `0.095215`/Credit — це **найвигідніша категорія** (великі обсяги) ціни Credits на платформі; за малого поповнення ціна Credits вища, тому X402 автоматично надає найвигіднішу ціну за одиницю.
- Сума підпису для інтерфейсів `exact` (зображення / відео / музика / пошук / замовлення) є сумою до сплати за цей виклик; для інтерфейсів `upto` (чат) підписується верхня межа, а розрахунок здійснюється за фактичним використанням.
- Авторитетною ціною є `maxAmountRequired`, повернений 402: для `exact` це сума до сплати (збігається з `cost.amount` у відповіді про успіх, перевірено на практиці); для `upto` це верхня межа, а `cost.amount` у відповіді про успіх є фактичною сумою, розрахованою за використанням (≤ верхньої межі).
