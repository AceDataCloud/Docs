Цей документ пояснює, як визначається ціна при виклику Ace Data Cloud API за допомогою X402, а також яку роль відіграє вона у відношенні до звичайних **Credits** (кредитів) платформи.

## Основні висновки

X402 не є окремою ціновою системою. Кожен виклик API вже має вартість, що вимірюється в **Credits**, яка є єдиним джерелом ціни для всіх способів оплати (зняття кредитів за API Token, баланс рахунку, оплата в ланцюгу X402). X402 просто перетворює цю вартість Credits за фіксованим курсом в USDC на ланцюзі:

> **1 Credit = 0.095215 USDC** (тобто `95215` atomic USDC, USDC має 6 знаків після коми)

Іншими словами:

```text
Ціна X402 (USDC) = Вартість Credits цього виклику × 0.095215
```

Цей курс не встановлюється наосліп, він дорівнює **найкращій ціні (оптовій)** для Credits на платформі. Отже, оплата через X402 ≈ купівля Credits за найкращою ціною, **без надбавки X402**, а навпаки, ви отримуєте найнижчу ціну на Credits, без необхідності попереднього поповнення або API Token.

## Базова ціна

| Пункт        | Значення                          | Опис                                                    |
| ----------- | -------------------------------- | ----------------------------------------------------- |
| Курс обміну | `1 Credit = 0.095215 USDC`       | Фіксований курс, встановлений платформою                     |
| atomic одиниця | `1 Credit = 95215 atomic USDC` | USDC 6 знаків після коми, `atomic = floor(credits × 0.095215 × 1e6)` |
| Мінімальна плата | `1 atomic USDC` ($0.000001)   | Навіть якщо вартість дуже низька, мінімальна сума становить 1 atomic |
| Валюта ціни | USDC                             | Base / SKALE - ERC-20 USDC, Solana - SPL USDC        |

Обмін здійснюється централізовано платформою, сума однакова для всіх підтримуваних мереж (Base, SKALE, Solana); різні мережі лише відрізняються контрактами активів та способами підпису, ціна однакова.

### Відношення до звичайної ціни Credits

Credits платформи продаються за принципом «чим більше використання, тим нижча ціна». X402 при розрахунках за викликами завжди використовує найкращу ціну:

| Спосіб покупки/оплати | Орієнтовна ціна Credits        | Опис                   |
| --------------------- | ------------------------------ | ---------------------- |
| Вхідний / Невеликий поповнення | Приблизно `$0.13 / Credit`   | Ціна за списком, ціна при покупці невеликої кількості Credits |
| Оптовий / Найкраща ціна | `$0.095215 / Credit`         | Найдешевша ціна       |
| **X402 за викликом**  | **`$0.095215 / Credit`**     | **Завжди дорівнює найкращій ціні** |

Іншими словами, X402 розраховує кожен виклик за найкращою ціною Credits. Користувачі, які купують Credits за невеликими поповненнями, платитимуть більше, ніж X402; лише користувачі з великими поповненнями матимуть таку ж ціну, як у X402.

## Два види цінових форм: `exact` та `upto`

У відповіді 402 X402, `maxAmountRequired` - це сума, яку ви повинні підписати. Вона має дві форми:

- **`exact` (фіксована ціна)**: Ціна може бути визначена до обробки запиту (зображення, відео, музика, пошук, оплата замовлення). `maxAmountRequired = Вартість Credits цього виклику × 0.095215`, тобто сума, яку потрібно сплатити (збігається з `cost.amount` у успішній відповіді).
- **`upto` (обсяг після вимірювання)**: Інтерфейси, такі як доповнення чату, де «кількість токенів стає відомою лише після завершення відповіді». `maxAmountRequired` є **верхньою межею** (перерахованою за встановленою моделлю: верхня межа Credits × 0.095215), фактичний розрахунок здійснюється за реальним використанням, але не перевищує верхньої межі.

Деталі угоди про ці дві схеми дивіться в [`exact` та `upto` цінових схемах](https://platform.acedata.cloud/documents/x402-metered-upto). Далі лише про ціну.

## Ціна Chat (доповнення чату)

Доповнення чату є `upto` вимірюванням: плата за фактичне використання токенів prompt / completion. Ціна за мільйон (1M) токенів = `Вартість Credits цього моделі за 1M токенів × 0.095215`, повністю збігається з публічним каталогом моделей платформи (`/api/v1/models?with_pricing=true`).

Нижче наведена реальна ціна (взята з каталогу моделей, за курсом X402), одиниця USD / 1M токенів:

| Модель                | Вхід / 1M | Вихід / 1M  | Верхня межа `upto`     |
| --------------------- | -------- | ----------- | --------------------- |
| gpt-4o-mini           | $0.0796  | $0.3183     | 1 Credit ($0.095215)   |
| gemini-2.5-flash      | $0.1591  | $1.3262     | 5 Credits ($0.476074)  |
| gpt-5 / gpt-5.1       | $0.6631  | $5.3050     | 20 Credits ($1.904299) |
| gemini-2.5-pro        | $0.6631  | $5.3050     | 50 Credits ($4.760750) |
| gpt-4.1               | $1.0610  | $4.2440     | 20 Credits ($1.904299) |
| claude-sonnet-4-5     | $0.6006  | $3.0028     | 50 Credits ($4.760750) |
| grok-4                | $1.5915  | $7.9574     | 10 Credits ($0.952149) |
| claude-opus-4-1       | $3.0028  | $15.0140    | 50 Credits ($4.760750) |

Примітка:

- У таблиці наведено ціну за токен; вартість одного запиту = вхідні токени × вхідна ціна + вихідні токени × вихідна ціна.
- Верхня межа `upto` - це максимальна сума, яку дозволяється підписати за один запит для цієї моделі; це не фактичний зняток, більшість запитів значно нижчі за верхню межу.
- Верхня межа лише визначає «максимальну можливу суму», фактичний розрахунок здійснюється за використанням токенів.

### Приклад: Ціна та зняття збігаються (`exact`)

Нижче наведено реальний платіжний виклик до `serp/google` за допомогою офіційного X402Client (Base `exact`). Він демонструє збіг трьох елементів: цінової пропозиції 402, підписаної суми та `cost`, повернутого в успішній відповіді.

```text
# 1) Неплатіжний запит -> 402, отримання пропозиції (без зняття)
POST /serp/google  ->  402
base/exact maxAmountRequired = 952 atomic = $0.000952 = 0.01 Credit
# 0.01 × 0.095215 = 0.00095215, округлено до atomic = 952

# 2) Підписання 952 atomic PAYMENT-SIGNATURE за допомогою гаманця, повторна спроба
POST /serp/google (PAYMENT-SIGNATURE) -> 200
body.cost = {"amount": 0.000952, "currency": "usdc", "settlement": "authorized"}
```
响应 повернення `cost.amount` (0.000952 USDC) з 402 пропозиції, з `Credits × 0.095215` повністю збігається. Поле `settlement` є станом розрахунку цього платежу (`authorized` = авторизовано); розрахунок в мережі обробляється платформою, механізм див. [`exact` та `upto` тарифні плани](https://platform.acedata.cloud/documents/x402-metered-upto).

### Обчислення тарифу `upto` (чат)

Чат вимірюється в токенах. Пропозиція для певного запиту (не верхня межа) обчислюється за формулою (на прикладі gpt-4o-mini):

```text
Credits = 1e-6 × (0.835733 × prompt_tokens + 3.342933 × completion_tokens)
USDC    = Credits × 0.095215
```

Запит на 500 prompt + 200 completion токенів:

```text
Credits = 1e-6 × (0.835733 × 500 + 3.342933 × 200) ≈ 0.001086 Credits
Пропозиція USDC ≈ 0.001086 × 0.095215 ≈ $0.0001034
```

Клієнт підписує за верхньою межею `upto` (gpt-4o-mini = 1 Credit = `95215` atomic), це лише **максимальна можлива сума**; реальна пропозиція для цього запиту (приблизно $0.0001) значно нижча за верхню межу, розрахунок за використанням токенів. Механізм розрахунку в мережі для `upto` див. [`exact` та `upto` тарифні плани](https://platform.acedata.cloud/documents/x402-metered-upto).

Пояснення:

- Для таких фіксованих цін (`exact`) у відповіді 402 `maxAmountRequired` є сумою, яку потрібно сплатити (збігається з `cost.amount` успішної відповіді, що вже перевірено в попередньому розділі).
- Кожна ціна обчислюється як `Credits × 0.095215`, округлене до atomic одиниць (див. вище базу для обчислення), використовується та ж система перерахунку. Через представлення з плаваючою комою та округлення, окремі значення можуть відрізнятися від простого добутку на 1 atomic ($0.000001), завжди керуйтеся значенням, що повертається в 402.

## Ціна оплати замовлення

При оплаті замовлення через консоль X402 (придбання пакету / поповнення Credits) ціна визначається за даними на сторінці замовлення, 402 `amount` є остаточним підписом. Оплата замовлення проходить через API платформи, потрібен токен облікового запису, деталі див. [Посібник з оплати замовлення](https://platform.acedata.cloud/documents/x402-order-payment).

Один реальний приклад з посібника з оплати замовлення (придбання 10 Credits):

```text
description Ace Data Cloud Credits x 10.0
created price 1.26          # Ціна створення замовлення (USD)
settled    1.20 USDC        # Остаточна сума підпису/розрахунку (= 402 amount)
            = 1200000 atomic USDC
```

Зверніть увагу: **оплата за викликами** (вище Chat / інші послуги) та **оплата замовлення** - це два різні шляхи. Оплата за викликами використовує єдину оптимальну ціну `0.095215`/Credit; оплата замовлення базується на цінах пакетів, різниця між ціною створення та остаточною сумою розрахунку визначається за [Посібником з оплати замовлення](https://platform.acedata.cloud/documents/x402-order-payment).

## Як отримати ціну в реальному часі

Ціна змінюється в залежності від моделі та параметрів, будь ласка, отримуйте її в реальному часі за допомогою програми, не хардкодьте:

- **Ціна за викликом**: надішліть один запит до цільового API **без** `PAYMENT-SIGNATURE` (також без `Authorization`), прочитайте повернене 402 `accepts[].maxAmountRequired`. Цей крок не призводить до витрат. Для інтерфейсу `exact` це остаточна ціна; для інтерфейсу `upto` (чат) це верхня межа, фактичний розрахунок за використанням.
- **Ціна за токен чату**: `GET https://platform.acedata.cloud/api/v1/models?with_pricing=true&type=chat`, прочитайте `pricing.input_usd` / `pricing.output_usd` для кожної моделі (вже обчислено за `credit_usd_rate`).
- **Перевірка перерахунку**: `atomic = floor(Credits × 0.095215 × 1e6)`, `USDC = atomic / 1e6` (тобто `USDC ≈ Credits × 0.095215`).

Приклад мінімального запиту для отримання ціни:

```bash
curl -sS -X POST https://x402.acedata.cloud/midjourney/imagine \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "a cat"}'
# Повертає 402, accepts[].maxAmountRequired є ціною цього (exact) виклику
```

## Підсумок
- X402 ціна = вартість Credits за цей виклик × `0.095215`, і це **така ж ціна**, як і звичайна оплата Credits, просто розрахунок проводиться в USDC на блокчейні.
- `0.095215`/Credit є **оптимальною ставкою** (великий обсяг) для Credits; при малих поповненнях ціна за Credits вища, тому X402 автоматично отримує оптимальну ціну.
- Сума підпису для інтерфейсу `exact` (зображення / відео / музика / пошук / замовлення) є сумою, яку потрібно сплатити; для інтерфейсу `upto` (чат) підписується верхня межа, розрахунок проводиться за фактичним використанням.
- Авторитетна ціна визначається за `maxAmountRequired`, повернутим 402: `exact` є сумою до сплати (відповідає `cost.amount` успішної відповіді, перевірено); `upto` є верхньою межею, успішна відповідь `cost.amount` є реальною сумою, розрахованою за використанням (≤ верхня межа).
