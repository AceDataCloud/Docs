Python SDK підходить для бекенд-сервісів, завдань обробки даних, автоматизованих Agent і скриптів пакетної обробки. `acedatacloud` відповідає за API-виклики, а `acedatacloud-x402` — за підписування заголовка запиту `PAYMENT-SIGNATURE`.

Вихідний код і адреси пакетів:

- Репозиторій SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Репозиторій X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- PyPI SDK: [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)
- PyPI X402 Client: [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)

## Встановлення залежностей

```bash
pip install acedatacloud acedatacloud-x402
```

Якщо потрібно використовувати `upto`, також необхідно одноразово викликати Permit2 approve CLI, цей CLI залежить від `web3`:

```bash
pip install 'acedatacloud-x402[cli]'
```

Вивід перевірки встановлення та імпорту в чистому Python venv:

```text
acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
approve-permit2  One-time ERC-20 approve(Permit2, amount) needed before signing upto payments.
```

Пояснення результатів:

- `acedatacloud` і `acedatacloud-x402` можна встановити та імпортувати з PyPI.
- `pip install 'acedatacloud-x402[cli]'` додає CLI `approve-permit2`, який використовується для попередньої авторизації `upto`.

## Приклад Base

Наведений нижче приклад не потребує API Token. Приватний ключ гаманця використовується лише для локального підписування та не надсилається до Ace Data Cloud.

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)

print(res["choices"][0]["message"]["content"])
```

Python SDK наразі повертає `dict`, тому в прикладі використовується `res["choices"][0]["message"]["content"]`。Не слід напряму припускати, що він обов’язково має атрибут `.choices`.

## Приклад Solana

Solana використовує secret key у кодуванні base58:

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import SolanaKeypairSigner, create_x402_payment_handler

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="solana",
        solana_signer=SolanaKeypairSigner.from_base58(os.environ["SOLANA_SECRET_KEY"]),
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

Шлях Solana створює та надсилає SPL USDC транзакцію `TransferChecked`, а потім поміщає підпис транзакції в envelope `PAYMENT-SIGNATURE`.

Paid retry Solana на production API вже повернув HTTP 200 і `ADC_SOLANA_E2E_OK`。Цього разу публічний RPC-запит зіткнувся з обмеженням швидкості, тому не вдалося стабільно підтвердити on-chain signature; якщо потрібна звірка, використовуйте власний Solana RPC для запиту цієї транзакції.

## Async клієнт

Той самий payment handler можна використовувати для `AsyncAceDataCloud`:

```python
import os

from acedatacloud import AsyncAceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AsyncAceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = await client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

## Використання постоплати `upto`

Фактична вартість API, таких як завершення чату та виклики моделей, може стати відомою лише після завершення відповіді. У такому разі API може одночасно повертати `exact` і `upto`。Якщо потрібно надавати пріоритет `upto`:

```python
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
        prefer_scheme="upto",
    )
)
```

Результат виконання програми Base `upto`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
settlement tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
settled value 3 atomic USDC
```

Підтвердження on-chain:

```text
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
transfer value 3 atomic USDC
```

Пояснення результатів:

- `content ADC_BASE_UPTO_OK` означає, що запит справді надійшов до model API.
- `settled value 3 atomic USDC` означає, що `upto` розраховується за фактичним використанням, а не стягує весь ліміт.
- `settlement tx` можна відкрити в BaseScan; для звірки зберігайте tx hash, payer, completion id і підсумок запиту.

`upto` використовує авторизацію Permit2 для верхнього ліміту, фактична сума розрахунку не може перевищувати цей ліміт. Перед першим використанням необхідно один раз виконати `approve(Permit2, amount)` для USDC у цільовому ланцюзі.

Спосіб CLI:

```bash
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Програмний спосіб:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Цей helper є ідемпотентним. Якщо allowance вже достатній, він поверне `{"skipped": true}` і не надсилатиме повторну on-chain транзакцію.

## Низькорівневе підписування

Якщо ви не використовуєте SDK, також можна напряму викликати низькорівневу функцію підписування:

```python
import base64
import json

from acedatacloud_x402 import EVMAccountSigner, sign_evm_payment

envelope = sign_evm_payment(requirement, EVMAccountSigner.from_private_key("0x..."))
x_payment = base64.b64encode(json.dumps(envelope, separators=(",", ":")).encode()).decode()
```

Низькорівневі функції підходять для тестування, proxy-рівнів, інтеграції gateway або неофіційних SDK. Для звичайного бізнес-коду пріоритетно використовуйте `create_x402_payment_handler`.
