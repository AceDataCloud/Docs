title: "Оновлення статусу замовлення на платформі AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Активно запитує останній статус способу оплати, відповідного замовленню, і синхронізує його з платформою. Цей запит може звертатися до платіжного сервісу та змінювати статус замовлення, використовуйте його лише за затримки зворотного виклику або коли потрібне негайне підтвердження.

## Підготовка

- Використовуйте [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Отримайте ID свого замовлення зі [списку замовлень](https://platform.acedata.cloud/documents/platform-order-list).

```shell
export PLATFORM_TOKEN='ваш токен облікового запису'
export ORDER_ID='ID вашого замовлення'
```

## Огляд інтерфейсу

| Пункт    | Вміст                                                                 |
| ---- | ------------------------------------------------------------------ |
| Метод   | `POST`                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/refresh/` |
| Авторизація   | Власник замовлення або суперадміністратор                                                        |
| Body | Зазвичай порожнє; у сценарії зворотного виклику PayPal може знадобитися `payer_id` / `PayerID`                         |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/refresh/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

У разі успіху повертається повний оновлений об’єкт Order. Використовуйте `state` для визначення результату та `finished_at` як час завершення; поточна модель не має поля `paid_at`. Значення статусів включають `Pending`, `Paid`, `Finished`, `Expired`, `Failed`, `Refunded`.

Кінцевий термін оплати змінює на `Expired` лише замовлення, які все ще перебувають у стані `Pending`. Повернуті замовлення `Refunded` після оновлення або отримання відкладеного зворотного виклику оплати все одно залишаються у статусі повернення коштів.

## Рекомендації щодо повторних спроб

- Для звичайної оплати насамперед покладайтеся на зворотний виклик платформи; активно виконуйте refresh лише тоді, коли статус тривалий час не оновлюється.
- Не виконуйте фіксоване високочастотне опитування. Рекомендується експоненційна затримка та зупинка після досягнення явного кінцевого стану.
- `401` означає, що токен недійсний; `403` означає, що ви не є власником замовлення; `404` означає, що замовлення не існує.
- Якщо запит до платіжного сервісу не вдається, збережіть ID замовлення та trace ID, повторіть спробу пізніше; не створюйте дублікати замовлень замість підтвердження статусу.
