Ace Data Cloud X402 наразі здійснює розрахунки в USDC та підтримує два типи мереж: EVM і Solana. Спосіб підпису, адреса активу, поведінка gas і відповідні сценарії відрізняються залежно від мережі, тому перед інтеграцією потрібно спочатку обрати мережу.

## Ідентифікатори мереж використовують CAIP-2

`accepts[].network` у x402 v2 є ідентифікатором CAIP-2, а не скороченою назвою на кшталт `base` чи `skale`. Клієнт повинен порівнювати мережі за рядком CAIP-2:

| Мережа             | Ідентифікатор CAIP-2                       |
| -------------- | ----------------------------------------- |
| Base           | `eip155:8453`                             |
| SKALE Base     | `eip155:1187947933`                       |
| Solana mainnet | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` |

## Матриця підтримки

| Мережа     | scheme  | Актив                  | Спосіб підпису                         | Сценарій застосування                        |
| ------ | ------- | ------------------- | ------------------------------------ | --------------------------- |
| Base   | `exact` | Base USDC           | EIP-3009 `TransferWithAuthorization` | Рекомендовано за замовчуванням, зріла підтримка гаманців і ліквідності.            |
| Base   | `upto`  | Base USDC + Permit2 | Permit2 `PermitWitnessTransferFrom`  | API з післяоплатним вимірюванням для чатів, моделей тощо.             |
| SKALE  | `exact` | SKALE bridged USDC  | EIP-3009 `TransferWithAuthorization` | Низька вартість gas, підходить для EVM-верифікації платежів і недорогих викликів. |
| Solana | `exact` | Solana USDC         | SPL `TransferChecked`                | Сценарії з гаманцями Solana, Agent або ончейн-застосунками.    |

`upto` наразі доступний лише в Base. Фактично доступні варіанти визначаються полем `accepts`, яке повертає API. Ви також можете переглянути Facilitator:

```bash
curl https://facilitator.acedata.cloud/supported
```

Відповідь Facilitator `/supported`:

```json
{
  "kinds": [
    { "x402Version": 2, "scheme": "exact", "network": "eip155:8453" },
    {
      "x402Version": 2,
      "scheme": "upto",
      "network": "eip155:8453",
      "extra": { "facilitatorAddress": "0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708" }
    },
    { "x402Version": 2, "scheme": "exact", "network": "eip155:1187947933" },
    {
      "x402Version": 2,
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "extra": { "feePayer": "3SPm6qbgsDkj24MuR8Ss4sH97fziqyCiqFKDyeVU2igq" }
    }
  ]
}
```

Пояснення результатів:

- `exact` для Base, SKALE і Solana є шляхом оплати з фіксованою сумою.
- Лише Base надає шлях післяоплатного вимірювання `upto`, який залежить від Permit2 approve.
- `extra.facilitatorAddress` у записі `upto` — це адреса, яку клієнт повинен записати у witness під час підписання; вона має збігатися зі значенням, повернутим сервером.

## Base

Base використовує офіційний контракт USDC:

```text
0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
```

У схемі `exact` клієнт підписує EIP-712 `TransferWithAuthorization`. Вміст підпису включає:

- `from`: адресу гаманця платника
- `to`: адресу отримання Ace Data Cloud
- `value`: суму цього платежу
- `validAfter` / `validBefore`: часовий проміжок дії підпису
- `nonce`: випадковий nonce розміром 32 байти

Після перевірки підпису Facilitator викликає в мережі `transferWithAuthorization` USDC для завершення переказу.

Base є найбільш рекомендованою мережею для офіційної інтеграції, особливо для післяоплатного вимірювання `upto`, оскільки екосистема Permit2, USDC і гаманців є більш зрілою.

Приклад результату верифікації Base `exact`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
content ADC_BASE_E2E_OK
tx 0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
block 46726299
explorer https://basescan.org/tx/0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
transfer value 95215 atomic USDC
```

Пояснення результатів:

- API paid retry повертає вміст моделі `ADC_BASE_E2E_OK`.
- Ончейн-транзакцію вже можна перевірити в BaseScan, номер блоку — `46726299`.
- `95215` atomic USDC відповідає `0.095215` USDC та є фактичною сумою розрахунку за цей виклик API.

Результат виконання програми оплати замовлення через Base `exact`:

```text
order 78481793-304e-47f7-bc0c-8231aec9cc1e
state Finished
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer value 1200000 atomic USDC
```

Пояснення результатів:

- Кінцевий статус замовлення на платформі — `Finished`.
- `pay_id` замовлення записується в той самий хеш транзакції Base.
- `1200000` atomic USDC відповідає `1.2` USDC та є історичною фактично сплаченою сумою цього замовлення на 10 Credits за старою політикою; нові замовлення більше не отримують додаткову знижку за спосіб оплати X402, а конкретна сума підпису визначається відповіддю 402 цього разу.

## SKALE

SKALE використовує bridged USDC, а спосіб підпису подібний до Base — також EIP-3009. Вона підходить для EVM-сценаріїв оплати з низькою вартістю gas; фактичні виклики все одно визначаються полем `accepts`, яке повертає API.

Типовий `accepts` для SKALE 402 містить:

```json
{
  "network": "eip155:1187947933",
  "scheme": "exact",
  "extra": {
    "name": "Bridged USDC (SKALE Bridge)",
    "version": "2",
    "chainId": 1187947933,
    "verifyingContract": "0x85889c8c714505E0c94b30fcfcF64fE3Ac8FCb20"
  }
}
```

SKALE наразі надає лише `exact`. Якщо вам потрібне післяоплатне вимірювання, використовуйте Base `upto`.

Приклад результату верифікації SKALE `exact`:

```text
content ADC_SKALE_E2E_OK
tx 0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
block 1969317
explorer https://skale-base-explorer.skalenodes.com/tx/0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
paid 0.095215 USDC
```

Пояснення результатів:
- API paid retry повертає вміст моделі `ADC_SKALE_E2E_OK`。
- Транзакцію вже можна знайти в SKALE explorer, номер блоку — `1969317`。
- Сума розрахунку цього платежу `exact` становить `0.095215` USDC。

## Solana

Solana використовує SPL USDC `TransferChecked`。Клієнт створює транзакцію переказу, підписує та надсилає її, після чого поміщає підпис транзакції або серіалізовану транзакцію в envelope `PAYMENT-SIGNATURE`。

Особливості Solana：

- використовується Solana wallet adapter або base58 secret key；
- активом є Solana USDC mint；
- наразі підтримується лише `exact`；
- Facilitator перевіряє mint, destination, authority та amount інструкції transfer。

Якщо використовується режим wallet fee payer, гаманець безпосередньо надсилає транзакцію, а Facilitator відповідає за підтвердження транзакції та повернення результату settlement。

Приклад результату перевірки Solana `exact`：

```text
payer AY2RmGm2zPxB1uKvvF4dKyYdr2VySyL3wcD1MKJZoLRd
HTTP 402 -> HTTP 200
content ADC_SOLANA_E2E_OK
chain signature not confirmed in this run
```

Пояснення результату：

- paid retry вже повернув HTTP 200, а модель вивела `ADC_SOLANA_E2E_OK`。
- Під час запиту on-chain signature через публічний RPC можна зіткнутися з rate limiting。
- Оскільки публічні RPC-запити можуть бути обмежені, Solana explorer тут не вказано。Якщо потрібна сувора звірка, використовуйте власний Solana RPC або записи settlement на стороні платформи для підтвердження підпису транзакції。

## Як обрати

| Що ви хочете зробити        | Рекомендована мережа                         |
| ------------ | ---------------------------- |
| Швидко пройти мінімальний шлях     | SKALE `exact` або Base `exact` |
| Для звичайних користувачів Web3 | Base                         |
| Для постоплати, наприклад chat completion   | Base `upto`                  |
| Застосунки екосистеми Solana  | Solana `exact`               |
| Низьковартісна EVM-перевірка платежів | SKALE `exact`                |

Незалежно від обраного ланцюга, не хардкодьте ціну в клієнті。Ціна визначається значенням `accepts[].maxAmountRequired`, яке повертає сервер。
