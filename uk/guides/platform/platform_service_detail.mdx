Отримання повної інформації про окремий сервіс за ID сервісу (UUID) або псевдонімом (alias) — повертає більше полів, ніж [отримання списку сервісів платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-service-list), і додатково розгортає пов’язані об’єкти, такі як `apis`, `proxies`, `datasets`, `packages` тощо. Підходить для сторінок деталей сервісу, сторінок порівняння цін, описів інструментів Agent та інших сценаріїв.

> ℹ️ Цей інтерфейс належить до **API керування платформою AceDataCloud**, з єдиним префіксом `https://platform.acedata.cloud/api/v1/`. Повний індекс інтерфейсів див. у [отриманні списку документів платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-document-list).

## Огляд інтерфейсу

| Пункт   | Вміст                                                         |
| --- | ------------------------------------------------------------- |
| Метод  | `GET`                                                         |
| URL | `https://platform.acedata.cloud/api/v1/services/{service_id}` |
| Авторизація  | ❌ Публічний                                                          |

Наразі доступні як `/services/{id}`, так і `/services/{id}/`; у прикладах уніфіковано використовується форма без завершального слеша.

## Пояснення щодо авторизації

Цей інтерфейс повністю публічний. **Однак після додавання токена облікового запису поле `applied` у відповіді відображатиме фактичний статус подання заявки поточного облікового запису**, інакше воно завжди буде `false`.

Спосіб отримання токена облікового запису див. у [керуванні токенами облікового запису платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

## Параметри шляху

| Параметр           | Тип            | Обов’язковий  | Опис                                                    |
| ------------ | ------------- | --- | ----------------------------------------------------- |
| `service_id` | UUID / string | ✅   | ID сервісу (UUID) або псевдонім (`midjourney`, `openai`, `webextrator` тощо) |

## Приклади запитів

### cURL

```shell
# 按 UUID 查询
curl 'https://platform.acedata.cloud/api/v1/services/8efa1d83-9b75-4562-b44a-af95ce563d05' \
  -H 'accept: application/json'

# 按 alias 查询
curl 'https://platform.acedata.cloud/api/v1/services/midjourney' \
  -H 'accept: application/json'

# 带账户令牌看 applied 状态
curl 'https://platform.acedata.cloud/api/v1/services/midjourney' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

resp = requests.get(
    "https://platform.acedata.cloud/api/v1/services/midjourney",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}",
    },
    timeout=10,
)
svc = resp.json()
print(f"服务: {svc['title']} ({svc['alias']})")
print(f"已申请: {svc['applied']}, 免费额度: {svc['free_amount']} {svc['unit']}")
print(f"API 数: {len(svc['apis'])}, 套餐数: {len(svc['packages'])}")
for pkg in svc["packages"]:
    print(f"  ¥{pkg['price']:>7.2f}  ->  {pkg['amount']} {svc['unit']}")
```

### Node.js

```javascript
const r = await fetch('https://platform.acedata.cloud/api/v1/services/midjourney', {
  headers: { accept: 'application/json' },
})
const svc = await r.json()
console.log(`${svc.title} - 套餐 ${svc.packages.length} 个 - API ${svc.apis.length} 个`)
```

## Опис полів відповіді

Інтерфейс деталей додатково до всіх полів [інтерфейсу списку](https://platform.acedata.cloud/documents/platform-service-list) розгортає:

| Поле         | Тип    | Опис                                                            |
| ---------- | ----- | ------------------------------------------------------------- |
| `apis`     | array | Повний список пов’язаних об’єктів API (кожен містить `id`, `name`, `title`, `path`, `stage`, `cost`) |
| `proxies`  | array | Повний список пов’язаних об’єктів Proxy                                              |
| `datasets` | array | Пов’язані набори даних (якщо `type=Dataset`)                                      |
| `packages` | array | Список пакетів, що містить `type` (`Usage`/`Period`), `price`, `amount`, `duration`   |

Визначення інших полів див. у [отриманні списку сервісів платформи AceDataCloud → опис полів відповіді](https://platform.acedata.cloud/documents/platform-service-list).

## Обробка помилок

| HTTP | code        | Значення                            |
| ---- | ----------- | ----------------------------- |
| 404  | `not_found` | `service_id` (UUID або alias) не існує |
| 500  | —           | Зазвичай це помилково доданий завершальний слеш в URL; видаліть його та повторіть спробу          |

## Практичні поради

- **`alias` > `UUID`**: жорстко закріпити `alias` (наприклад, `midjourney`) у коді стабільніше; UUID змінюється під час міграції середовища.
- **Поле `apis` не містить визначення OpenAPI**: повна схема OpenAPI 3.0 доступна в інтерфейсі [отримання деталей API платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-api-detail).
- **Отримання «повних можливостей» сервісу**: за допомогою цього інтерфейсу отримайте `api_ids`, а потім по черзі викликайте `/apis/{api_id}` для отримання деталей.
- **Якщо `applied=true`**, можна безпосередньо [створити облікові дані API](https://platform.acedata.cloud/documents/platform-credential-create), щоб отримати 32-символьний Token, необхідний для виклику бізнес-інтерфейсу, без потреби подавати заявку повторно.
