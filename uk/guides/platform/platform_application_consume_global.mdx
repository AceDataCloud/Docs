---
title: "Налаштування спільного використання глобального балансу AceDataCloud Application"
description: "Platform API guide - Ace Data Cloud"
---

Налаштуйте `allow_consume_global`. Після увімкнення Application з оплатою за фактом, що відповідають умовам, можуть продовжувати використовувати глобальний баланс облікового запису, коли їхнього власного балансу недостатньо.

## Підготовка

- Створіть і безпечно збережіть [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Отримайте `application_id`, яким ви володієте, зі [списку заявок на сервіс](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='ваш токен облікового запису'
export APPLICATION_ID='ваш Application ID'
```

## Огляд API

| Пункт    | Вміст                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------- |
| Метод   | `POST`                                                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/applications/{application_id}/update-allow-consume-global/` |
| Авторизація   | Account Token                                                                                      |
| Body | JSON                                                                                               |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/applications/${APPLICATION_ID}/update-allow-consume-global/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"allow_consume_global": true}'
```

У разі успіху повертається оновлений об’єкт Application. Орієнтуйтеся на `allow_consume_global` у відповіді, а не припускайте, що значення запиту обов’язково було збережене.

> Application типу `Period` не дозволяється споживати глобальний баланс. Навіть якщо надіслати запит зі значенням `true`, сервер збереже для цього поля значення `false`.

## Обробка помилок

- `401`: Account Token недійсний або відсутній.
- `403`: поточний обліковий запис не є власником цього Application.
- `404`: Application ID не існує.

Для поповнення глобального балансу та доступних пакетів орієнтуйтеся на консоль платформи й фактичні пакети, що повертаються при [створенні замовлення](https://platform.acedata.cloud/documents/platform-order-create); не припускайте існування пакетів типу `Wallet`.

## Застосунки з авторизованим овердрафтом

Коли поле лише для читання `allow_overdraft=true` застосунку з оплатою за фактом, цей застосунок може продовжувати списувати кошти зі свого балансу, навіть якщо баланс стає від’ємним, і не переключатиметься на глобальний обліковий запис через недостатність балансу. Застосунки без увімкненого овердрафту й надалі дотримуються `allow_consume_global`; чи дозволений овердрафт після перемикання, визначається налаштуванням фактичного глобального Application, з якого здійснюється списання.
