[Ace Data Cloud Studio](https://studio.acedata.cloud) орієнтована на творців, операторів, дизайнерів і бізнес-команди, централізовано надаючи інструменти для AI-діалогів, зображень, відео, музики та автоматичного створення відео. Користувачі обирають робочий процес, виходячи з творчої мети, без необхідності спочатку неодноразово реєструватися, поповнювати баланс і перемикатися між кількома продуктами.

![Головна сторінка Studio: перехід до діалогів, зображень, відео та музики від творчої мети](https://cdn.acedata.cloud/uploads/34c26779-82a4-4a9b-b81b-fb98ccd525be)

## Для яких сценаріїв підходить

- **Створення контенту**：письмо, дослідження, постери, обкладинки, короткі відео та музичний супровід；
- **Маркетинг і операційна діяльність**：зображення товарів, матеріали для соціальних мереж, візуальні матеріали заходів і брендований контент；
- **Дослідження дизайну**：редагування референсних зображень, дослідження стилів, композиції та багатоваріантні рішення；
- **Бізнес-команди**：виконання творчих завдань між кількома моделями та в кілька кроків природною мовою；
- **Розробники та досвідчені користувачі**：налаштування API Key, Connector, Skill або локальних інструментів у підтримуваних сценаріях。

Конкретно доступні можливості можуть змінюватися залежно від конфігурації сайту, регіону, облікового запису та версії продукту; орієнтуйтеся на фактичне відображення поточної сторінки.

## Як почати

1. Відвідайте [studio.acedata.cloud](https://studio.acedata.cloud)；
2. Оберіть спосіб входу, який наразі надається на сторінці；
3. Перейдіть до інструменту через творчу мету на головній сторінці або навігацію можливостей ліворуч；
4. Ознайомтеся з цінами, параметрами та вимогами до контенту поточного сервісу；
5. Спочатку перевірте процес за допомогою завдань із низькою вартістю, а потім переходьте до високої роздільної здатності, довгих відео або пакетної генерації。

Одиниці тарифікації, час обробки та параметри різних сервісів відрізняються. Перед надсиланням слід перевірити поточну сторінку та історію використання, не розраховуйте ціни за історичними скриншотами.

## Основні робочі процеси

### AI-діалог

Використовується для письма, аналізу, навчання, програмування та мультимодальних обговорень. Конкретні моделі, можливості контексту та підтримка інструментів визначаються поточним селектором моделей.

### AI-зображення

Охоплює генерацію зображень за текстом, редагування референсних зображень, розширення зображень, перетворення стилю та візуальний дизайн. Різні сервіси зображень мають свої акценти щодо розмірів, рендерингу тексту, узгодженості персонажів і можливостей редагування.

### AI-відео та автоматичне створення відео

Підтримує створення відео на основі тексту, зображень, референсних матеріалів або сценаріїв. Робочий процес автоматичного створення відео може поєднувати сценарій, кадри, озвучення, субтитри та музику; для тривалих завдань слід звертати увагу на перевірку статусу, причини помилок і повноту фінального результату.

### AI-музика

Підтримує генерацію пісень зі стилю або тексту пісні, а також подальше редагування чи розширення відповідно до можливостей, наданих на сторінці. Перед комерційним використанням слід самостійно перевірити права на контент і правила цільової платформи.

### Connector、Skill і розширені інструменти

Деякі облікові записи або сайти можуть використовувати Connector, Skill і локальні інструменти. Ці входи обмежені поточним продуктом, дозволами та середовищем виконання; вони не є відкритими за замовчуванням для всіх користувачів або white-label сайтів.

## Web, мобільна та десктопна версії

Web-версія Studio розміщена за адресою `studio.acedata.cloud`. Можливості, а також входи для керування сайтом у мобільній та десктопній версіях можуть відрізнятися:

- керування white-label сайтом відображається у Web-версії лише для поточного адміністратора Site；
- нативні мобільні та десктопні застосунки не відображають усі налаштування операційного керування сайтом；
- на ширині смартфона використовується нижня навігація можливостей, а складні форми створення краще підходять для десктопного браузера。

## Межі white-label і дистрибуції

- white-label — це конфігурація Site на спільній платформі, а не незалежне розгортання чи незалежна база даних；
- облікові записи користувачів, баланси, плани та більшість активів належать до спільної системи；
- приховування поповнення балансу, можливостей або сервісів є лише контролем відображення на сторінці, а не ізоляцією авторизації；
- націнка Site є ціною каналу в межах звичайного процесу white-label покупки, а не примусовою ціною орендаря для облікового запису в усіх входах；
- дохід від дистрибуції залежить від дійсних замовлень, відносин запрошення, рівня, повернень коштів і контролю ризиків; фіксована частка, швидкість зарахування або суми доходу не гарантуються。

## Рекомендації щодо використання

- важливі факти та згенерований контент потребують ручної перевірки；
- не розкривайте паролі, API Key, документи, що посвідчують особу, або платіжну інформацію в промптах, скриншотах, чатах чи тікетах；
- для портретів, голосів, торговельних марок і матеріалів, захищених авторським правом, слід отримати необхідні дозволи；
- для завдань із високою вартістю спочатку створіть зразок, а після підтвердження параметрів збільшуйте масштаб；
- у разі виникнення аномалій зафіксуйте час, сервіс, код статусу та публічний ідентифікатор запиту; не надсилайте повний token。

## OAuth-авторизація сторонніх вебсайтів на головній сторінці

У налаштуваннях компонента вебсайту увімкніть OAuth і заповніть ID застосунку та адресу зворотного виклику, зареєстровані сторонньою стороною в ACE Data Cloud. Вебсайт і адреса зворотного виклику мають використовувати одне й те саме HTTPS-джерело, яке відрізняється від джерела Studio. Не вказуйте секрет застосунку в налаштуваннях.

Сторінка стороннього сервісу має інтегрувати протокол повідомлень OAuth. Авторизовані відвідувачі побачать офіційну сторінку згоди в області компонента; після згоди стороння сторона може через OAuth token читати наявний API Key цього відвідувача. Якщо користувач не ввійшов або відмовився від авторизації, Key не надається.

Після дозволу на читання Key стороння сторона може зберігати й використовувати його. Скасування OAuth-авторизації не робить уже скопійований Key недійсним; окремо відкличте або замініть Key. Докладніше дивіться в описі компонента Studio у «Інтеграція входу через Ace Data Cloud (OAuth 2.0)».
