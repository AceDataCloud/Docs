Цей посібник пояснює повний процес Ace Data Cloud X402 за допомогою мінімального API-запиту. Мета полягає не в тому, щоб спочатку писати складний код, а в тому, щоб спершу зрозуміти: чому перший запит повертає 402, що міститься в `accepts` і як `PAYMENT-SIGNATURE` перетворює той самий API-запит на оплачений запит.

## Підготовка

Вам потрібно підготувати:

| Пункт   | Опис                                                   |
| ---- | ---------------------------------------------------- |
| Гаманець   | Гаманець, що підтримує цільову мережу. Base використовує EVM-гаманець, Solana використовує Solana-гаманець.      |
| USDC | У гаманці має бути достатньо USDC. Фактична сума визначається `maxAmountRequired` у відповіді 402. |
| Середовище розробки | Для TypeScript рекомендовано Node.js 18+; для Python рекомендовано Python 3.10+.    |
| SDK  | Рекомендовано використовувати офіційний SDK, не рекомендується вручну реалізовувати деталі підпису.                                |

Для виклику Ace Data Cloud API через X402 не потрібен API Token. Перший запит SDK не містить `Authorization`, Gateway повертає `402 Payment Required` і вимоги до оплати; після підпису SDK автоматично повторює запит.

## Встановлення SDK

Вихідний код і адреси пакетів:

- Репозиторій SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Репозиторій X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm: `@acedatacloud/sdk`、`@acedatacloud/x402-client`
- PyPI: `acedatacloud`、`acedatacloud-x402`

TypeScript:

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client ethers
```

Python:

```bash
pip install acedatacloud acedatacloud-x402
```

Якщо потрібно використовувати Solana, також потрібно встановити відповідні залежності:

```bash
npm install @solana/web3.js
```

Залежності Solana signer для версії Python уже включено до `acedatacloud-x402`.

Вивід перевірки встановлення та імпорту в чистому тимчасовому середовищі:

```text
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4

acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
```

Пояснення результату:

- Пакети npm і PyPI є справді опублікованими пакетами, а не назвами-заповнювачами в документації.
- `acedatacloud-x402[cli]` встановлює CLI, а підкоманда `approve-permit2` може використовуватися для авторизації Permit2 у сценарії `upto`.

## Перший запит поверне 402

Ви можете спочатку скористатися `curl`, щоб побачити, що повертає неоплачений запит. Наведений нижче приклад не призведе до списання коштів, оскільки він не містить `PAYMENT-SIGNATURE`:

```bash
curl -sS -X POST https://x402.acedata.cloud/openai/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "hi"}],
    "max_tokens": 1
  }'
```

Тіло відповіді міститиме масив `accepts`, типова структура така:

```json
{
  "x402Version": 2,
  "resource": {
    "url": "/openai/chat/completions",
    "description": "AceDataCloud API call",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "maxAmountRequired": "95215",
      "amount": "95215",
      "maxTimeoutSeconds": 3600,
      "resource": "/openai/chat/completions",
      "description": "...",
      "payTo": "0x...",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913"
      }
    }
  ],
  "error": "PAYMENT-SIGNATURE header is required"
}
```

Такий самий вміст запиту також у форматі base64 розміщується у заголовку відповіді `PAYMENT-REQUIRED`, щоб клієнт міг зчитувати вимоги до оплати без аналізу body.

Нижче наведено підсумок програмного виводу неоплаченого запиту до production API:

```text
status=402
x402Version 2
accepts [
  ('eip155:8453', 'exact', '95215'),
  ('eip155:8453', 'upto', '95215'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '95215'),
]
```

Пояснення результату:

- Перший запит не містить `Authorization` або `PAYMENT-SIGNATURE`, тому повертає HTTP 402 і не призведе до списання коштів.
- `accepts` є єдиною надійною основою для підпису цього запиту та містить доступні мережі, scheme, ліміт суми, адресу одержувача та адресу активу.
- `network` є ідентифікатором CAIP-2, і клієнт під час вибору мережі повинен зіставляти його за рядком CAIP-2.
- Максимальна сума для цього мінімального запиту чату `gpt-4o-mini` становить `95215` atomic USDC, тобто `0.095215` USDC.
- Для кожного запиту слід зчитувати відповідь 402 саме цього запиту; не слід жорстко кодувати приклад суми в бізнес-коді.

Значення полів:

| Поле                  | Опис                                                             |
| ------------------- | -------------------------------------------------------------- |
| `scheme`            | Схема оплати. `exact` означає фіксовану суму, `upto` означає ліміт авторизації та розрахунок за фактичним використанням.                     |
| `network`           | Ідентифікатор CAIP-2 платіжної мережі, наприклад `eip155:8453`、`solana:5eykt4...`。           |
| `maxAmountRequired` | Максимальна сума платежу в USDC atomic units; `95215` означає `0.095215` USDC.       |
| `amount`            | Сума для розрахунку в цьому випадку; для `exact` вона збігається з `maxAmountRequired`, для `upto` змінюється на етапі розрахунку відповідно до фактичного використання. |
| `payTo`             | Адреса одержувача.                                                          |
| `asset`             | Адреса контракту USDC або адреса Solana mint.                                     |
| `extra`             | Розширена інформація, необхідна для підпису, зокрема chain ID, EIP-712 domain, адреса Permit2 тощо.                      |

## Виконання повторного запиту з оплатою через SDK

Нижче наведено мінімальний приклад TypeScript. Він задає `network: 'base'`, handler вибере payment requirement Base із відповіді 402 цього запиту; фактична сума та адреса одержувача все одно визначаються `accepts`:
```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const response = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Reply with exactly: hello' }],
  max_tokens: 8
});

console.log(response.choices[0].message.content);
```

За цим кодом відбуваються чотири кроки:

1. SDK надсилає звичайний API-запит без `Authorization`.
2. Gateway повертає `402 Payment Required` і `accepts`.
3. `createX402PaymentHandler` вибирає payment requirement для `network = 'base'` і підписує `PAYMENT-SIGNATURE`.
4. SDK повторює спробу з тим самим тілом запиту, Gateway викликає Facilitator для перевірки й розрахунку, після чого пропускає запит до цільового API.

## Перегляд можливостей Facilitator

X402 API не залежить від каталогу ресурсів. Клієнт безпосередньо викликає відомий API та використовує
`402 Payment Required` і `accepts`, що повертаються цим запитом у реальному часі, як єдину основу для ціни й підпису.

Оголошення можливостей Facilitator знаходиться за адресою:

```bash
curl https://facilitator.acedata.cloud/.well-known/x402
```

Воно описує лише `/supported`, `/verify`, `/settle` і поточно ввімкнені платіжні мережі, не перелічуючи ресурси API.

Адреса виробничого Facilitator Ace Data Cloud:

```text
https://facilitator.acedata.cloud
```

Можна переглянути, які мережі та scheme він підтримує:

```bash
curl https://facilitator.acedata.cloud/supported
```

Повернене `kinds` перелічує мережі та scheme, які підтримує Facilitator. Під час фактичних викликів усе одно слід орієнтуватися на `accepts`, що повертається API.

Вивід Facilitator `/supported`:

```text
kinds [
  ('eip155:8453', 'exact'),
  ('eip155:8453', 'upto', {'facilitatorAddress': '0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708'}),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact')
]
```

Результат означає:

- `/supported` означає, що Facilitator має можливості перевірки й розрахунку для цих мереж і scheme.
- Base і Solana обидві підтримують `exact`; `upto` наразі доступний лише в Base.
- Чи дозволяє конкретний API певну мережу, усе одно визначається його 402 `accepts`.
