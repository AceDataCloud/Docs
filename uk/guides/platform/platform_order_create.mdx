title: "Створення замовлення на поповнення платформи AceDataCloud"

Створіть замовлення, що очікує на оплату, для одного або кількох Application. Створення записує замовлення, але не завершує оплату автоматично; перед оплатою слід перевірити `price`, пакет і Application у відповіді.

## Підготовка

- Створіть [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Отримайте `application_id` зі [списку Application](https://platform.acedata.cloud/documents/platform-application-list).
- Виберіть `package_id`, що відповідає типу Application і доступний для придбання, з `packages` у [деталях сервісу](https://platform.acedata.cloud/documents/platform-service-detail).

```shell
export PLATFORM_TOKEN='你的账户令牌'
export APPLICATION_ID='你的 Application ID'
export PACKAGE_ID='你的 Package ID'
```

## Огляд API

| Пункт    | Вміст                                              |
| ---- | ----------------------------------------------- |
| Метод   | `POST`                                          |
| URL  | `https://platform.acedata.cloud/api/v1/orders/` |
| Авторизація   | Account Token, OAuth token потребує `orders:write`      |
| Body | JSON                                            |

## Тіло запиту

Для замовлення одного Application використовуйте `application_id` + `package_id`; для пакетного замовлення використовуйте `application_ids` + `package_ids` відповідної довжини. У звичайному замовленні спосіб оплати вибирається в наступному запиті `/pay/`. Під час створення замовлення для внутрішніх покупок iOS передайте `pay_way: "AppleIAP"`, при цьому можна вибрати лише один пакет Usage з `metadata.apple_product_id` і `metadata.apple_price`. Внутрішні покупки Apple використовують окрему попередньо встановлену ціну в доларах США, без додавання знижок за членство, знижок за спосіб оплати або націнок сайту; сума списання в місцевій валюті в інших регіонах визначається на сторінці підтвердження оплати Apple.

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/orders/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"package_id\":\"${PACKAGE_ID}\"}"
```

## Опис відповіді

У разі успіху повертаються `201` і новий об’єкт Order. Ключові поля включають `id`, `price`, `discount`, `state`, `application_id/application_ids`, `package_id/package_ids`, `expired_at` і поля часу. Нове замовлення зазвичай має статус `Pending`, після чого викликається [оплата замовлення](https://platform.acedata.cloud/documents/platform-order-pay).

- `price` — це сума до сплати, розрахована сервером на основі пакета, націнки сайту та знижок; не розраховуйте її самостійно на клієнті.
- Якщо Package не відповідає сервісу або типу Application, повертається `400`.
- Безкоштовний і керований системою Package не можна отримати самостійно через публічний API замовлень.
- Створення замовлення для Application, що не належить поточному обліковому запису, буде відхилено.
