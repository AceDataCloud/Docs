[LobeChat](https://lobehub.com/) — це клієнт ШІ з відкритим вихідним кодом, який підтримує плагіни, бази знань і самостійне розгортання; його можна використовувати в онлайн-версії або розгорнути через Docker. Він підтримує налаштування сумісних з OpenAI ендпоїнтів, тому може підключатися до Ace Data Cloud. У цій статті описано процес налаштування.

## Процес подання заявки

Щоб підключити Ace Data Cloud у LobeChat, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), отримайте ваш API Token і збережіть його для подальшого використання.

![Отримання Ace Data Cloud API Key](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не ввійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти; після входу або реєстрації ви автоматично повернетеся на поточну сторінку.

Під час першого подання заявки надається безкоштовний ліміт, що дозволяє безкоштовно випробувати модельні сервіси Ace Data Cloud.

## Налаштування Ace Data Cloud

Перейдіть до **Налаштування застосунку → Мовні моделі** у LobeChat, знайдіть картку **OpenAI** та увімкніть її, введіть:

| Поле       | Значення                              | Опис                         |
| -------- | ------------------------------ | -------------------------- |
| API Key  | ваш Ace Data Cloud Token        | Token, скопійований із консолі               |
| Адреса API-проксі | `https://api.acedata.cloud/v1` | **має закінчуватися на `/v1`**           |
| Режим запитів клієнта  | увімкнено                             | пряме підключення браузера, Key не проходить через сервер LobeChat |

![Інтерфейс налаштування LobeChat OpenAI Provider](https://cdn.acedata.cloud/629ef9d3084a.png)

> Під час використання інтерфейсу Chat Completions тримайте Responses API Specification вимкненим.

LobeChat не додає `/v1` до Base URL автоматично, шлях запиту безпосередньо має вигляд `{Адреса API-проксі}/chat/completions`:

| Адреса API-проксі                              | Фактичний запит                                                   | Результат                       |
| ------------------------------------- | ------------------------------------------------------ | ------------------------ |
| `https://api.acedata.cloud/v1`        | `https://api.acedata.cloud/v1/chat/completions`        | правильно                       |
| `https://api.acedata.cloud/openai`    | `https://api.acedata.cloud/openai/chat/completions`    | також можна використовувати                      |
| `https://api.acedata.cloud/openai/v1` | `https://api.acedata.cloud/openai/v1/chat/completions` | 404 (під `/openai` немає `/v1`) |
| `https://api.acedata.cloud`           | `https://api.acedata.cloud/chat/completions`           | 404 (немає `/v1`)             |

LobeChat за замовчуванням викликає `/v1/models` для автоматичного завантаження моделей. Якщо Ace Data Cloud повертає багато моделей, інтерфейс буде дуже довгим, тому рекомендується вручну заповнити список дозволених моделей у «Список моделей → Власні назви моделей», розділяючи їх англійськими комами. Якщо потрібно налаштувати відображувану назву, можна використати `=`, формат: `MODEL_ID=відображувана назва`.

## Вибір моделі

Каталог моделей постійно оновлюється. Насамперед використовуйте список моделей, автоматично завантажений клієнтом; якщо потрібно заповнювати вручну, спочатку надішліть запит `GET https://api.acedata.cloud/v1/models`, щоб отримати поточний ID моделі, а потім виберіть відповідно до можливостей клієнта щодо контексту, зображень і викликів інструментів.

## Перевірка інтеграції

Якщо ви не впевнені, чи проблема в LobeChat або в мережі, спочатку можна безпосередньо перевірити ендпоїнт за допомогою curl (замініть `{token}` на ваш Token):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

Повернення сумісного з OpenAI об’єкта `chat.completion` означає, що і Token, і ендпоїнт готові; якщо повертається `HTTP 403 used_up`, це означає, що Token дійсний, але балансу недостатньо — поповніть рахунок у [консолі](https://platform.acedata.cloud/console/applications).

## Розширено: самостійне розгортання через Docker

Якщо ви хочете розгорнути приватну версію для командного використання, можна запустити її однією командою Docker (замініть `{token}` на ваш Token):

```bash
docker run -d \
  --name lobe-chat \
  -p 3210:3210 \
  -e OPENAI_API_KEY={token} \
  -e OPENAI_PROXY_URL=https://api.acedata.cloud/v1 \
  -e ACCESS_CODE=your-secret-password \
  -e OPENAI_MODEL_LIST="MODEL_ID" \
  lobehub/lobe-chat:latest
```

Відкрийте `http://IP-адреса_вашого_сервера:3210`, введіть `ACCESS_CODE`, і можна користуватися; членам команди не потрібно буде окремо вводити Key. Повний опис змінних середовища, таких як `OPENAI_API_KEY`, `OPENAI_PROXY_URL`, `OPENAI_MODEL_LIST`, використаних вище, дивіться в [документації змінних середовища постачальників моделей LobeChat](https://lobehub.com/docs/self-hosting/environment-variables/model-provider). Якщо використовуєте зворотний проксі nginx із HTTPS, обов’язково додайте `proxy_buffering off;`, інакше потокові відповіді буферизуватимуться. Докладніше про інші варіанти розгортання дивіться в [посібнику з початку самостійного розгортання LobeChat](https://lobehub.com/docs/self-hosting/start) і [розгортанні через Docker Compose](https://lobehub.com/docs/self-hosting/platform/docker-compose).

## Поширені запитання

### Повідомлення 404 Not Found

Зазвичай це трапляється, якщо адресу API-проксі вказано як `.../openai/v1` або пропущено `/v1`. Змініть на `https://api.acedata.cloud/v1`.

### Список моделей порожній

Увімкніть перемикач «Режим запитів клієнта»; або вручну заповніть список дозволених моделей у «Власні назви моделей».

### Повідомлення 401 Unauthorized

Переконайтеся, що в API Key вставлено Token Ace Data Cloud (без префікса `Bearer` і без зайвих пробілів), а баланс відповідного застосунку достатній.
