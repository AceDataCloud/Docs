«Заявка (Application)» означає відносини підписки поточного облікового запису на певний сервіс — спочатку необхідно подати заявку, і лише потім можна створити для цієї заявки API-облікові дані та викликати бізнес-інтерфейси. Під час першої заявки на певний сервіс Application отримає поточне налаштоване для цього сервісу значення `free_amount`; це значення може бути 0.

> ℹ️ Цей інтерфейс належить до **API керування платформою AceDataCloud**, єдиний префікс `https://platform.acedata.cloud/api/v1/`. Повний індекс інтерфейсів див. у [отриманні списку документів платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-document-list).

## Повний процес інтеграції

Нові користувачі від реєстрації до успішного виклику першого бізнес-інтерфейсу зазвичай проходять ці 5 кроків:

1. **Отримати токен облікового запису** → [Керування токенами облікового запису платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-token)
2. **Обрати сервіс** → [Отримання списку сервісів платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-service-list)
3. **Створити заявку** (цей документ) → отримати початкову квоту відповідно до конфігурації сервісу
4. **Створити API-облікові дані** → [Створення API-облікових даних платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-credential-create)
5. **Викликати бізнес-інтерфейс** → використовувати отриманий 32-символьний Token для виклику `https://api.acedata.cloud/<path>`

## Огляд інтерфейсу

| Параметр            | Вміст                                                    |
| ------------ | ----------------------------------------------------- |
| Метод           | `POST`                                                |
| URL          | `https://platform.acedata.cloud/api/v1/applications/` |
| Автентифікація           | ✅ Потрібен токен облікового запису                                              |
| Content-Type | `application/json`                                    |

## Опис автентифікації (як отримати токен облікового запису)

Заголовок запиту:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Токен облікового запису (Account Token) — це «ключ рівня облікового запису», який розробники використовують через API для керування ресурсами власного облікового запису. Способи отримання:

1. **Створення одним кліком у консолі (рекомендовано)**: увійдіть до [платформи AceDataCloud](https://platform.acedata.cloud) → [консолі Account Token](https://platform.acedata.cloud/console/platform-tokens) → натисніть «Створити», щоб отримати токен, що починається з `platform-v1-`.
2. **Створення через API**: використовуйте наявний токен облікового запису або JWT стану входу в браузері для виклику `POST /api/v1/platform-tokens/`, докладніше див. у [керуванні токенами облікового запису платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

> ⚠️ Токен облікового запису є настільки ж конфіденційним, як пароль; заборонено записувати його у фронтенд-код або публічні репозиторії. У разі витоку негайно видаліть його в консолі та створіть заново.

## Тіло запиту

| Параметр           | Тип   | Обов'язково  | Опис                                                                                                  |
| ------------ | ---- | --- | --------------------------------------------------------------------------------------------------- |
| `service_id` | UUID | ✅   | ID сервісу, на який подається заявка. Можна отримати з `items[].id` у [списку сервісів](https://platform.acedata.cloud/documents/platform-service-list) |

## Приклад запиту

### cURL

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/applications/' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'content-type: application/json' \
  -d '{"service_id": "38ecf158-36f2-42f2-8e7f-6786cdfc2452"}'
```

### Python

```python
import os
import requests

PLATFORM_TOKEN = os.environ["PLATFORM_TOKEN"]
SERVICE_ID = "38ecf158-36f2-42f2-8e7f-6786cdfc2452"

resp = requests.post(
    "https://platform.acedata.cloud/api/v1/applications/",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {PLATFORM_TOKEN}",
        "content-type": "application/json",
    },
    json={"service_id": SERVICE_ID},
    timeout=10,
)

if resp.status_code == 201:
    app = resp.json()
    print(f"申请成功！application_id={app['id']}")
    print(f"初始额度：{app['remaining_amount']} {app.get('service', {}).get('unit', '')}")
elif resp.status_code == 400 and resp.json().get("code") == "duplication":
    print("⚠️ 已经申请过此服务，请到 /applications/ 列表里找到现成的 application_id")
else:
    print(f"申请失败：HTTP {resp.status_code} - {resp.text}")
```

### Node.js

```javascript
const PLATFORM_TOKEN = process.env.PLATFORM_TOKEN
const SERVICE_ID = '38ecf158-36f2-42f2-8e7f-6786cdfc2452'

const resp = await fetch('https://platform.acedata.cloud/api/v1/applications/', {
  method: 'POST',
  headers: {
    accept: 'application/json',
    authorization: `Bearer ${PLATFORM_TOKEN}`,
    'content-type': 'application/json',
  },
  body: JSON.stringify({ service_id: SERVICE_ID }),
})

if (resp.status === 201) {
  const app = await resp.json()
  console.log('application_id =', app.id)
} else {
  console.error(await resp.text())
}
```

### Уже подано заявку (HTTP 400)

```json
{
  "detail": "Item already exists.",
  "code": "duplication",
  "trace_id": "1a87524f8cbba0b790b2951e2e43117e"
}
```

Це жорстке обмеження дизайну: **кожен користувач може мати лише один Application для кожного сервісу**. Якщо він уже існує, знайдіть наявний через [отримання списку заявок на сервіси платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-application-list).

### Сервіс не існує (HTTP 404)

```json
{
  "detail": "Service not found.",
  "code": "not_found",
  "trace_id": "..."
}
```

### Сервіс потребує перевірки (HTTP 403)

```json
{
  "detail": "This service requires manual verification.",
  "code": "need_verify",
  "trace_id": "..."
}
```

Якщо `need_verify=true` для сервісу (це поле можна побачити у списку сервісів), необхідно пройти процес звернення до служби підтримки для подання заявки до білого списку.

## Обробка помилок
| HTTP | код                 | Значення                   |
| ---- | ------------------- | -------------------------- |
| 400  | `duplication`       | Цю послугу вже було запитано поточним обліковим записом |
| 400  | `invalid`           | `service_id` відсутній або має неправильний формат |
| 401  | `not_authenticated` | Відсутній токен облікового запису або токен було видалено |
| 403  | `need_verify`       | Послуга потребує перевірки, будь ласка, скористайтеся процесом тікетів |
| 404  | `not_found`         | Послуга не існує або була вимкнена |

Єдиний формат відповіді про помилку:

```json
{
  "detail": "...",
  "code": "...",
  "trace_id": "..."
}
```

## Практичні поради

- **Саме створення не списує кошти**: під час першого створення початковий ліміт встановлюється відповідно до поточного `free_amount` послуги; це значення може бути 0, а повторне створення Application того самого типу не гарантує повторного надання.
- **Чи потрібна оплата, визначається полем `paid`**: одразу після подання заявки `paid=false`, після виклику [створення замовлення на поповнення платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-order-create) та завершення оплати воно стає `true`.
- **`disabled=true` означає тимчасове вимкнення** — наприклад, через спрацювання контролю ризиків, заборгованість тощо. У вимкненому стані бізнес-інтерфейси повертатимуть `403`.
- **Не створюйте необмежено паралельно**: спочатку отримайте цільовий `service_id` зі списку послуг із пагінацією, а потім подавайте заявки по черзі відповідно до бізнес-потреб; у разі `duplication` повторно використовуйте наявний Application.
