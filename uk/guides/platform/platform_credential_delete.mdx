Назавжди видалити один набір облікових даних API. Після видалення **негайно неможливо відновити**, усі бізнес-інтерфейси, що використовують цей Token, одразу отримають `401`.

> ℹ️ Цей інтерфейс належить до **API керування платформою AceDataCloud**, єдиний префікс: `https://platform.acedata.cloud/api/v1/`.

## Огляд інтерфейсу

| Пункт   | Вміст                                                                  |
| --- | ------------------------------------------------------------------- |
| Метод  | `DELETE`                                                            |
| URL | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}` |
| Авторизація  | ✅ Потрібен токен облікового запису                                                            |

`/credentials/{id}` і `/credentials/{id}/` наразі обидва доступні; у прикладах однаково використовується форма без завершального слеша.

## Опис авторизації (як отримати токен облікового запису)

Заголовок запиту:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Спосіб отримання див. у [Керування токеном облікового запису платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

## Параметри шляху

| Параметр              | Тип   | Обов’язковий  | Опис        |
| --------------- | ---- | --- | --------- |
| `credential_id` | UUID | ✅   | ID облікових даних, які потрібно видалити |

## Приклади запитів

### cURL

```shell
curl -X DELETE 'https://platform.acedata.cloud/api/v1/credentials/df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

cred_id = "df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6"
resp = requests.delete(
    f"https://platform.acedata.cloud/api/v1/credentials/{cred_id}",
    headers={"authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    timeout=10,
)
assert resp.status_code == 204, resp.text
print("✅ 已删除")
```

### Node.js

```javascript
const credId = 'df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6'
const r = await fetch(`https://platform.acedata.cloud/api/v1/credentials/${credId}`, {
  method: 'DELETE',
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log('status:', r.status) // 204
```

## Відповідь

- **Успіх**: `HTTP 204 No Content`, **без тіла відповіді**.
- **Помилка**: повертається JSON помилки, див. таблицю нижче.

## Обробка помилок

| HTTP | code                | Значення         |
| ---- | ------------------- | ---------- |
| 401  | `not_authenticated` | Відсутній токен облікового запису     |
| 403  | `permission_denied` | Ці облікові дані не належать вам    |
| 404  | `not_found`         | Облікові дані не існують або вже видалені |

## Практичні поради

- **Видалення незворотне**——платформа не зберігає копії Token. Якщо ви лише підозрюєте витік, але хочете зберегти дані моніторингу, слід використати [Ротацію облікових даних API платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-credential-rotate), а не видалення.
- **Видалення не повертає вже використану квоту цих облікових даних**. Баланс Application списується в реальному часі відповідно до використання, видалення облікових даних не впливає на баланс.
- Після видалення можна повторно підтвердити решту облікових даних за `application_id` через [Список облікових даних API](https://platform.acedata.cloud/documents/platform-credential-list).
- **Перед масовим очищенням спершу перевірте викликачів**: список наразі не містить поля часу останнього використання; слід підтвердити за конфігурацією розгортання та записами викликів, що облікові дані більше не використовуються, а потім видаляти їх по черзі.
