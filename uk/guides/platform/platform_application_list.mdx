Повертає посторінково Application, якими володіє обліковий запис або на використання яких він має дозвіл, включно з балансом, статусом, зведенням послуги та пов’язаними обліковими даними. Підходить для пакетного моніторингу балансу, пошуку Application ID та переходу до керування обліковими даними.

## Підготовка

1. Увійдіть до [платформи AceDataCloud](https://platform.acedata.cloud).
2. Створіть токен облікового запису в [консолі Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. Звичайні користувачі використовують `user_id=me`; також можна отримати власний UUID через `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='你的账户令牌'
```

## Огляд API

| Пункт   | Вміст                                                    |
| --- | ----------------------------------------------------- |
| Метод  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Авторизація  | Account Token, OAuth token потребує `applications:read`       |
| Пагінація  | `count` + `items`                                     |

Звичайні користувачі повинні передавати `user_id=me`. Якщо не передавати, запит спочатку не буде звужено за обліковим записом, і під час пагінації об’єкти без прав доступу можуть повертати `403`; адміністратори без передавання можуть переглядати всю таблицю.

## Параметри запиту

| Параметр            | Тип          | Обов’язковий     | Опис                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Обов’язковий для звичайних користувачів | Суб’єкт запиту; підтримує повторювані параметри                                         |
| `affiliation` | string      | Ні      | `owner` (за замовчуванням) або `granted`; можна повторно передати обидва для отримання об’єднання, діє лише за наявності `user_id` |
| `service_id`  | UUID        | Ні      | Фільтрація за послугою; підтримує повторювані параметри                                        |
| `scope`       | string      | Ні      | `Individual` або `Global`; підтримує повторювані параметри                      |
| `type`        | string      | Ні      | `Usage` або `Period`; підтримує повторювані параметри                           |
| `limit`       | integer     | Ні      | Кількість записів на сторінці, максимум 100                                         |
| `offset`      | integer     | Ні      | Зсув пагінації                                               |
| `ordering`    | string      | Ні      | Підтримуються лише `created_at` або `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` і `tag` наразі не є параметрами серверної фільтрації. Для сповіщень про баланс слід після отримання списку визначати на клієнті на основі `remaining_amount`, `service.unit` і бізнес-порогів кожного Application.

## Приклад запиту

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Одночасний перегляд Application, якими ви володієте, і тих, які інші надали вам:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Опис відповіді

Відповідь має формат `{count, items}`. Кожен елемент містить поля моделі Application і додатково:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: зведення облікових даних, які поточний викликач має право бачити;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`;
- фактичне значення `scope` — `Individual` або `Global`;
- фактичне значення `type` — `Usage` або `Period`.

`remaining_amount` може бути порожнім; клієнт повинен спочатку перевірити на порожнє значення, а потім виконувати числове порівняння. Одиниця квоти визначається `service.unit`.
