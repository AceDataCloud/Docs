[NextChat](https://github.com/ChatGPTNextWeb/NextChat) (раніше ChatGPT-Next-Web) — це клієнтський застосунок ШІ з відкритим кодом, який можна розгорнути на Vercel, Cloudflare або Docker. Він підтримує налаштування сумісних із OpenAI кінцевих точок, тому може підключатися до Ace Data Cloud. У цій статті представлено процес налаштування.

## Процес подання заявки

Щоб підключити Ace Data Cloud у NextChat, спершу перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), отримайте свій API Token і збережіть його для подальшого використання.

![Отримання API Key Ace Data Cloud](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу з пропозицією зареєструватися та увійти, після входу або реєстрації ви автоматично повернетеся на поточну сторінку.

Під час першого подання заявки надається безкоштовний ліміт, завдяки якому можна безкоштовно випробувати модельні сервіси Ace Data Cloud.

## Завантаження NextChat

Можна використовувати настільну версію (завантажити `.exe` / `.dmg` / AppImage на [сторінці Releases](https://github.com/ChatGPTNextWeb/NextChat/releases)), [онлайн-версію Web](https://app.nextchat.club/) або самостійно розгорнути на Vercel / Cloudflare / Docker (див. розширений розділ нижче).

## Налаштування Ace Data Cloud

Запустіть NextChat і перейдіть до **Налаштування → Сервіси моделей**:

| Поле          | Значення                           | Опис                              |
| ----------- | --------------------------- | ------------------------------- |
| Постачальник сервісу моделей       | `OpenAI`                    | Використання сумісного з OpenAI протоколу                  |
| Адреса інтерфейсу OpenAI | `https://api.acedata.cloud` | Вказуйте лише кореневий домен, **без `/openai`, без `/v1`** |
| API Key     | Ваш Ace Data Cloud Token     | Token, скопійований із консолі                    |

![Інтерфейс налаштування Ace Data Cloud у NextChat](https://cdn.acedata.cloud/47e0aed34570.png)

NextChat автоматично додає `/v1/chat/completions` після адреси інтерфейсу, тому достатньо вказати лише кореневий домен:

| Адреса інтерфейсу                                  | Фактичний запит                                                      | Результат                       |
| ------------------------------------- | --------------------------------------------------------- | ------------------------ |
| `https://api.acedata.cloud`           | `https://api.acedata.cloud/v1/chat/completions`           | Правильно                       |
| `https://api.acedata.cloud/openai`    | `https://api.acedata.cloud/openai/v1/chat/completions`    | 404 (у `/openai` немає `/v1`) |
| `https://api.acedata.cloud/openai/v1` | `https://api.acedata.cloud/openai/v1/v1/chat/completions` | 404                      |

У полі «Користувацька назва моделі» введіть моделі, розділяючи їх англійськими комами. NextChat підтримує спеціальний синтаксис: `+назва_моделі` для додавання, `-назва_моделі` для приховування, `назва_моделі=відображувана_назва` для налаштування відображуваної назви, `-all` для попереднього приховування всіх. Рекомендований найчистіший запис:

```text
-all,+MODEL_ID=显示名称
```

## Вибір моделі

Каталог моделей постійно оновлюється. Насамперед використовуйте список моделей, автоматично завантажений клієнтом; якщо потрібно заповнити вручну, спочатку надішліть запит `GET https://api.acedata.cloud/v1/models`, щоб отримати поточний ID моделі, а потім виберіть відповідно до можливостей контексту, зображень і викликів інструментів, які підтримує клієнт.

## Перевірка підключення

Якщо ви не впевнені, чи проблема в NextChat або в мережі, можна спочатку безпосередньо перевірити кінцеву точку за допомогою curl (замініть `{token}` на свій Token):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

Повернення сумісного з OpenAI об’єкта `chat.completion` означає, що Token і кінцева точка готові; якщо повертається `HTTP 403 used_up`, це означає, що Token дійсний, але баланс недостатній, достатньо поповнити рахунок у [консолі](https://platform.acedata.cloud/console/applications).

## Розширене: розгортання в один клік на власному домені

NextChat підтримує розгортання власного вебсайту ШІ. Візьмемо Docker як приклад (замініть `{token}` на свій Token):

```bash
docker run -d \
  --name nextchat \
  -p 3000:3000 \
  -e OPENAI_API_KEY={token} \
  -e BASE_URL=https://api.acedata.cloud \
  -e CODE=your-password \
  -e CUSTOM_MODELS="-all,+MODEL_ID=显示名称" \
  yidadaa/chatgpt-next-web
```

Під час розгортання на Vercel / Cloudflare достатньо налаштувати ті самі `OPENAI_API_KEY`, `BASE_URL`, `CODE`, `CUSTOM_MODELS` у змінних середовища проєкту. `CODE` підтримує кілька паролів доступу, розділених англійськими комами, що зручно для підрахунку використання за користувачами. Повний опис наведених вище змінних середовища (`BASE_URL` за замовчуванням — `https://api.openai.com`, синтаксис `+/-/=/-all/+all` для `CUSTOM_MODELS`) дивіться в [офіційному README NextChat](https://github.com/ChatGPTNextWeb/NextChat#environment-variables).

## Поширені запитання

### Повідомлення 404 Not Found

Зазвичай адреса інтерфейсу вказана як `.../openai` або `.../openai/v1`. Змініть її на `https://api.acedata.cloud`, щоб NextChat самостійно додав `/v1/chat/completions`.

### Доданої моделі немає у випадаючому списку моделей

Перевірте формат `CUSTOM_MODELS`: перед кожною моделлю обов’язково має бути `+`; якщо використано `-all`, переконайтеся, що потрібні моделі додано назад за допомогою `+`.

### Повідомлення 401 Unauthorized

Будь ласка, підтвердьте, що в API Key вставлено Token Ace Data Cloud (без префікса `Bearer`, без зайвих пробілів), а баланс відповідного застосунку достатній.
