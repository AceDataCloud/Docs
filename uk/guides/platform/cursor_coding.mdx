Cursor наразі надає OpenAI API Key та **Override OpenAI Base URL** налаштування, що дозволяє підключатися до OpenAI-сумісних сервісів. Ця можливість існує, але різні версії по-різному обробляють `/chat/completions`, `/responses`, список моделей, а також режими Agent/Composer.

Сумісність різних версій Cursor, операційних систем та режимів запитів може відрізнятися. Будь ласка, виконайте фактичну перевірку режиму відповідно до налаштувань на цій сторінці, не роблячи висновків про доступність усіх функцій на основі успішного одноразового чату.

## Офіційні гарантії BYOK від Cursor

Згідно з [офіційною документацією Cursor Bring your own API key](https://cursor.com/help/models-and-usage/api-keys):

- Підтримуються облікові дані OpenAI, Anthropic, Google, Azure OpenAI та AWS Bedrock;
- Користувацький API Key використовується лише для чат-моделей, Tab completion продовжує використовувати вбудовані моделі Cursor;
- API Key не зберігається на серверах Cursor, але кожен запит надсилає Key на бекенд Cursor для остаточного формування prompt;
- При використанні власного Key політика нульового зберігання даних Cursor не застосовується, обробка даних підлягає політиці обраного постачальника.

## Налаштування

1. Відкрийте Налаштування Cursor → Моделі.
2. У полі OpenAI API Key введіть свій Ace Data Cloud API Token.
3. Увімкніть **Override OpenAI Base URL**, введіть `https://api.acedata.cloud/v1`.
4. Виберіть або додайте точний ID моделі, сумісний з поточним протоколом Cursor.
5. Спочатку надішліть `Reply only OK`, а потім протестуйте Ask/Edit/Agent та інші режими, які ви фактично використовуєте.

## Поточні обмеження

- Користувацький API Key використовується лише для чат-моделей, Tab completion продовжує використовувати вбудовані моделі Cursor.
- Cursor все ще може завершити остаточне формування prompt на сервері; будь ласка, оцініть шлях даних, враховуючи офіційні пояснення конфіденційності.
- Base URL Override може покривати лише частину запитів або через зміни версії перемикатися між Chat Completions/Responses.
- Не слід стверджувати, що Agent, Auto, Composer або фонові завдання підключені, лише на основі успішного одного запиту чату.

## Поточні варіанти

При використанні Coding Plan, перевагу слід надавати клієнтам з чітко визначеними налаштуваннями та перевіркою доступу:

- [Огляд налаштувань Claude Code](https://platform.acedata.cloud/documents/claude-code-integration)
- [Огляд налаштувань Codex](https://platform.acedata.cloud/documents/codex-integration)
- [Налаштування WorkBuddy](https://platform.acedata.cloud/documents/development_workbuddy)

## Повна перевірка сумісності

Щоб довгостроково використовувати в робочих процесах, будь ласка, виконайте наступні перевірки:

1. Фіксована версія Cursor та операційна система;
2. Завершіть реальний smoke-тест клієнта для цієї версії та зафіксуйте остаточний протокол запиту та шлях;
3. Успішний запит Chat Completions для точної моделі;
4. Виклики інструментів та запити Agent дійсно проходять через цільовий endpoint;
5. Використання та нарахування можна перевірити;
6. Чітко зафіксувати, чи проходили запити через сервер Cursor та відповідні обмеження конфіденційності.

Після оновлення клієнта ці перевірки слід повторити, щоб підтвердити, що протокол запиту, виклики інструментів та шлях даних не змінилися.
