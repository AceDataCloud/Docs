Отримайте повний статус однієї заявки на послугу за Application ID — порівняно з інтерфейсом списку, містить додаткові поля, як-от повний об’єкт `service` (включно з пакетами `packages`), і підходить для сторінки деталей.

> ℹ️ Цей інтерфейс належить до **API керування платформою AceDataCloud**, з єдиним префіксом `https://platform.acedata.cloud/api/v1/`. Повний індекс інтерфейсів див. у [Отримання списку документації платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-document-list).

## Огляд інтерфейсу

| Пункт   | Вміст                                                                    |
| --- | --------------------------------------------------------------------- |
| Метод  | `GET`                                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/{application_id}` |
| Авторизація  | ✅ Потрібен токен облікового запису                                                              |

Наразі доступні як `/applications/{id}`, так і `/applications/{id}/`; у прикладах використовується форма без завершального слеша.

## Опис авторизації (як отримати токен облікового запису)

Заголовок запиту:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Детальний спосіб отримання див. у [Керування токеном облікового запису платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

> ℹ️ На відміну від інтерфейсу списку, **перевірка дозволів інтерфейсу деталей виконується безпосередньо для одного об’єкта**, тому не потрібно передавати `?user_id=`. Але якщо ви звернетеся до чужої заявки, отримаєте `403 permission_denied`.

## Параметри шляху

| Параметр               | Тип   | Обов’язковий  | Опис             |
| ---------------- | ---- | --- | -------------- |
| `application_id` | UUID | ✅   | Application ID |

## Приклади запитів

### cURL

```shell
curl 'https://platform.acedata.cloud/api/v1/applications/82f57141-2323-4453-8730-60f7d833a2da' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

app_id = "82f57141-2323-4453-8730-60f7d833a2da"
resp = requests.get(
    f"https://platform.acedata.cloud/api/v1/applications/{app_id}",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}",
    },
    timeout=10,
)
app = resp.json()
print(f"服务：{app['service']['title']}")
print(f"剩余 {app['remaining_amount']} {app['service']['unit']} / 已用 {app['used_amount']}")
```

### Node.js

```javascript
const appId = '82f57141-2323-4453-8730-60f7d833a2da'
const r = await fetch(`https://platform.acedata.cloud/api/v1/applications/${appId}`, {
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log(await r.json())
```

## Опис полів відповіді

Значення полів такі самі, як у [інтерфейсі списку](https://platform.acedata.cloud/documents/platform-application-list), додатково містить:

| Поле        | Тип     | Опис                                                        |
| --------- | ------ | --------------------------------------------------------- |
| `service` | object | Повний об’єкт послуги (включно з пакетами `packages`, `unit`, `free_amount`), який можна безпосередньо відобразити на панелі деталей послуги |

## Обробка помилок

| HTTP | code                | Значення                  |
| ---- | ------------------- | ------------------- |
| 401  | `not_authenticated` | Відсутній токен облікового запису              |
| 403  | `permission_denied` | Ця Application не належить вам  |
| 404  | `not_found`         | Application не існує або видалена |

## Практичні поради

- **Для пакетного моніторингу пріоритетно використовуйте список**: після одноразового отримання списку Application визначайте за одиницями та порогами кожної послуги, щоб уникнути запитів деталей по одному.
- **Коли потрібно переглянути кількість облікових даних**: використовуйте [Список облікових даних API](https://platform.acedata.cloud/documents/platform-credential-list) з фільтрацією за `application_id`.
- **Підхід до перевірки `disabled=true`**: перевірте тікети / сповіщення електронною поштою, щоб з’ясувати, чи послугу вимкнено через контроль ризиків, заборгованість або порушення викликів; увімкнути її через API неможливо, необхідно звернутися до служби підтримки.
