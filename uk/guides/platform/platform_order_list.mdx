Повертає замовлення на поповнення рахунку з пагінацією, підходить для пошуку ID замовлення, перегляду статусу оплати та звірки.

## Підготовка

Створіть [Account Token](https://platform.acedata.cloud/documents/platform-token) і отримайте UUID поточного облікового запису з `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='ваш токен облікового запису'
export USER_ID='UUID вашого облікового запису'
```

## Огляд API

| Пункт   | Вміст                                              |
| --- | ----------------------------------------------- |
| Метод  | `GET`                                           |
| URL | `https://platform.acedata.cloud/api/v1/orders/` |
| Авторизація  | Account Token, OAuth token потребує `orders:read`       |
| Пагінація  | `count` + `items`                               |

Звичайні користувачі повинні передавати власний `user_id`; інакше під час пагінації при зустрічі з об’єктами без прав доступу може повертатися `403`.

## Параметри запиту

| Параметр                    | Тип       | Обов’язковий     | Опис                                                        |
| --------------------- | -------- | ------ | --------------------------------------------------------- |
| `user_id`             | UUID     | Обов’язковий для звичайних користувачів | Обліковий запис, якому належить замовлення; підтримує повторювані параметри                                             |
| `pay_way`             | string   | Ні      | Фільтрація за способом оплати; підтримує повторювані значення або значення, розділені комами                                        |
| `state`               | string   | Ні      | Фільтрація за статусом; підтримує повторювані значення або значення, розділені комами                                          |
| `created_at_from/to`  | datetime | Ні      | Діапазон часу створення                                                    |
| `finished_at_from/to` | datetime | Ні      | Діапазон часу завершення                                                    |
| `limit` / `offset`    | integer  | Ні      | Пагінація                                                        |
| `ordering`            | string   | Ні      | `created_at`, `-created_at`, `finished_at` або `-finished_at` |

Поточний список не підтримує фільтрацію за `application_id`, `service_id`, `package_id`, `payment_method` або `tag`; назва поля способу оплати — `pay_way`.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/orders/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'state=Paid,Finished' \
  --data-urlencode 'pay_way=Stripe' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Опис відповіді

Відповідь має вигляд `{count, items}`. Елементи списку у робочому середовищі містять `id`, `user_id`, `application_id/application_ids`, `package_id/package_ids`, `price`, `amount`, `discount`, `remaining_amount`, `state`, `pay_way`, `pay_id`, `pay_url`, `finished_at`, `expired_at`, `invoice`, `metadata` і поля часу.

- Фактичні статуси: `Pending`, `Paid`, `Finished`, `Expired`, `Failed`, `Refunded`; `Cancelled` немає.
- Назви полів: `pay_way`, `finished_at`, `discount` і `price`, а не `payment_method`, `paid_at`, `discount_rate` або `final_price`.
- `price` — це кінцева ціна, записана в замовленні; валюта та деталі розрахунку можуть міститися в контрольованих metadata, тому їх не можна самостійно визначати лише за способом оплати.
