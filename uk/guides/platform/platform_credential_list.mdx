Посторінково перелічує бізнесові API-облікові дані. Ця відповідь наразі містить конфіденційні поля облікових даних Token або Identity, тому її необхідно обробляти лише на сервері; заборонено записувати її в журнали, платформи аналітики, клієнтське сховище або публічні репозиторії.

## Підготовка

Створіть [Account Token](https://platform.acedata.cloud/documents/platform-token) і отримайте UUID поточного облікового запису через `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='你的账户令牌'
export USER_ID='你的账户 UUID'
```

## Огляд інтерфейсу

| Пункт   | Вміст                                                   |
| --- | ---------------------------------------------------- |
| Метод  | `GET`                                                |
| URL | `https://platform.acedata.cloud/api/v1/credentials/` |
| Авторизація  | Account Token, OAuth token потребує `credentials:read`       |
| Пагінація  | `count` + `items`                                    |

Звичайні користувачі повинні передавати власний `user_id` або вже авторизований `application_id`, інакше під час пагінації при зустрічі з об’єктами без прав доступу може повертатися `403`.

## Параметри запиту

| Параметр                 | Тип      | Обов’язковий  | Опис                             |
| ------------------ | ------- | --- | ------------------------------ |
| `user_id`          | string  | залежить від сценарію | Власник облікових даних; підтримує повторювані параметри                   |
| `application_id`   | UUID    | Ні   | Фільтрація за Application; підтримує повторювані параметри        |
| `host`             | string  | Ні   | Точна фільтрація за host; підтримує повторювані параметри             |
| `name`             | string  | Ні   | Точна фільтрація за назвою; підтримує повторювані параметри                 |
| `granted`          | boolean | Ні   | `true` — облікові дані, надані іншим, `false` — облікові дані для власного використання |
| `limit` / `offset` | integer | Ні   | Пагінація                             |
| `ordering`         | string  | Ні   | `created_at` або `-created_at`   |

`service_id`, `disabled`, `expired` наразі не є параметрами фільтрації.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/credentials/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Опис відповіді

Відповідь, перевірена в продакшені, має вигляд `{count, items}`. Кожен елемент містить `id`, `application_id`, `application`, `user_id`, `creator_id`, `name`, `type`, `limited_amount`, `used_amount`, `expired_at`, `allowed_api_ids`, `host`, `granted`, `granted_to_user_id`, `tags`, `metadata` і поля часу, а також залежно від типу повертає `token` або `username/password`.

> Поточна відповідь списку повертає повні конфіденційні значення. Не відображайте їх у консолі браузера чи системах збору даних і не покладайтеся на відновлення відкритого тексту через список; клієнти повинні бути сумісними з майбутніми стратегіями маскування даних.
