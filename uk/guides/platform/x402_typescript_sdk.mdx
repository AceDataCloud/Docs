TypeScript є одним із найбільш рекомендованих способів інтеграції Ace Data Cloud X402. Офіційний SDK відповідає за звичайні API-виклики, опитування завдань, обробку помилок і автоматичні повторні спроби; `@acedatacloud/x402-client` відповідає за підписання заголовка запиту `PAYMENT-SIGNATURE` при виникненні `402 Payment Required`.

Вихідний код та адреси пакетів:

- Репозиторій SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Репозиторій X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm SDK: [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)
- npm X402 Client: [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client)

## Встановлення залежностей

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client
```

Якщо використовується Base, потрібна можливість EVM-підпису:

```bash
npm install ethers
```

Якщо використовується Solana, потрібен Solana wallet adapter або `@solana/web3.js`:

```bash
npm install @solana/web3.js
```

Вивід перевірки встановлення та імпорту в чистому npm-проєкті:

```text
imports_ok true true true true true
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4
```

Пояснення результатів:

- `@acedatacloud/sdk` і `@acedatacloud/x402-client` можна встановити з npm та імпортувати через Node.js.
- `ethers` використовується для підпису EVM typed data, а `@solana/web3.js` — для створення Solana transaction.

## Приклад Base

У браузері можна безпосередньо використовувати `window.ethereum`. У Node.js можна обгорнути `ethers.Wallet` provider'ом у стилі EIP-1193.

```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});

console.log(result.choices[0].message.content);
```

## Приклад браузерного гаманця

Під час використання MetaMask, Coinbase Wallet або WalletConnect у фронтенд-застосунку зазвичай безпосередньо передається EIP-1193 provider:

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const [address] = await window.ethereum.request({ method: 'eth_requestAccounts' });

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider: window.ethereum,
    evmAddress: address
  })
});

const image = await client.images.generate({
  provider: 'nano-banana',
  prompt: 'a yellow banana on a white background'
});
```

Браузерний гаманець покаже підтвердження підпису. Користувач підписує не довільне повідомлення, а вимогу до оплати, повернену API: адреса одержувача, контракт USDC, сума, строк дії та nonce — усе це включено до підпису.

## Приклад Solana

Solana використовує SPL USDC `TransferChecked`. Переданий wallet adapter має надавати `publicKey` та `signAndSendTransaction`.

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'solana',
    solanaWallet: phantomWallet
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});
```

Шлях Solana наразі підтримує лише `exact` і не підтримує `upto`. Якщо API повертає кілька `accepts`, handler вибере елемент із `network = 'solana'`.

Шлях Solana уже перевірено на тому самому публічному API: paid retry може повертати HTTP 200 та `ADC_SOLANA_E2E_OK`. Запити до публічного RPC можуть мати обмеження швидкості, тому в цій статті не вказано Solana tx hash; якщо потрібна ончейн-звірка, використовуйте власний Solana RPC або підтвердження із записів консолі.

## Вибір `exact` або `upto`

Поточний TypeScript handler вибирає першу payment requirement для відповідної мережі, повернену сервером. API Ace Data Cloud зазвичай розміщує `exact` тієї самої мережі перед `upto`, тому якщо ви точно хочете використовувати післяплатний облік, потрібно передати `preferScheme: 'upto'`.

Приклад:

```ts
const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address,
    preferScheme: 'upto'
  })
});
```

Якщо сервер не повертає `upto` requirement для цієї мережі, handler автоматично повернеться до першої доступної requirement для цієї мережі, зазвичай це `exact`.

Для `upto` потрібна одноразова авторизація Permit2. `upto` наразі доступний лише в Base, тому потрібно лише один раз надати авторизацію для Base USDC:

```bash
npx tsx scripts/approve-permit2.ts --network base
```

Base `upto` пройшов перевірку на публічному API: HTTP 402 -> HTTP 200, післяплатний settlement tx — `0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036`. Повний вивід дивіться в описі схеми виставлення рахунків.

## Що робить SDK

Transport `@acedatacloud/sdk` виконує payment handler один раз при отриманні 402:

```ts
type PaymentHandler = (ctx: {
  url: string;
  method: string;
  body?: unknown;
  accepts: PaymentRequirement[];
}) => Promise<{ headers: Record<string, string> }>;
```

Handler, повернутий `@acedatacloud/x402-client`, виконає:

1. Вибере payment requirement цільової мережі з `ctx.accepts`.
2. Створить EVM EIP-712 підпис або Solana transfer transaction відповідно до мережі.
3. Серіалізує envelope у Base64.
4. Поверне `{ headers: { 'PAYMENT-SIGNATURE': '<base64>' } }`.
5. SDK автоматично повторить спробу з вихідним тілом запиту.

Це означає, що бізнес-код потрібно писати лише як звичайний SDK-виклик, без необхідності вручну обробляти повторні спроби 402.
