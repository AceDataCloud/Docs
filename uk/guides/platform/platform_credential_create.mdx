Створіть облікові дані бізнесового API для Application. Відповідь на створення може містити Token, який можна безпосередньо використовувати для виклику `https://api.acedata.cloud/**`, або ім’я користувача/пароль облікових даних типу Proxy; їх необхідно обробляти як секрети.

## Підготовка

1. Створіть [Account Token](https://platform.acedata.cloud/documents/platform-token).
2. Отримайте власний `application_id` зі [списку Application](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='ваш токен облікового запису'
export APPLICATION_ID='ваш Application ID'
```

## Огляд інтерфейсу

| Пункт    | Вміст                                                   |
| ---- | ---------------------------------------------------- |
| Метод   | `POST`                                               |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/` |
| Авторизація   | Account Token, OAuth token потребує `credentials:write`      |
| Body | JSON                                                 |

## Тіло запиту

| Поле                  | Тип              | Обов’язково  | Опис                            |
| ------------------- | --------------- | --- | ----------------------------- |
| `application_id`    | UUID            | Так   | Цільовий Application                |
| `name`              | string          | Ні   | Відображувана назва облікових даних                         |
| `limited_amount`    | number / null   | Ні   | Ліміт використання для одних облікових даних; `null` означає відсутність окремого ліміту       |
| `expired_at`        | datetime / null | Ні   | Час закінчення дії ISO 8601                 |
| `allowed_api_ids`   | UUID[] / null   | Ні   | Дозволити виклики лише цих API; порожній масив буде нормалізовано до відсутності обмежень       |
| `host`              | string          | Ні   | Інформація про host облікових даних                    |
| `for_user_id`       | string          | Ні   | Використовується, коли власник Application видає авторизаційні облікові дані для іншого користувача |
| `tags` / `metadata` | array / object  | Ні   | Користувацькі розширені дані                       |

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/credentials/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"name\":\"production\",\"limited_amount\":50}"
```

## Опис відповіді

У разі успіху повертаються `201` та об’єкт Credential:

- Сервіси типу API/Agent зазвичай повертають `type=Token` і `token`;
- Сервіси типу Proxy зазвичай повертають `type=Identity` та `username` / `password`, і один Proxy Application дозволяє лише одні облікові дані;
- `id`, `user_id`, `creator_id`, `used_amount` і поля часу генеруються на стороні сервера.

Поточні інтерфейси списку та деталей також повертають відкритий текст облікових даних, але клієнт не повинен покладатися на цю історичну поведінку. Збережіть їх одразу після створення та уникайте запису відповіді в журнали; майбутні інтерфейси можуть змінитися на повернення замаскованих даних.

## Обробка помилок

- `400`: помилка формату поля, невідомі `allowed_api_ids`, Proxy Application уже має облікові дані або інші обмеження створення.
- `401`: Account Token недійсний.
- `403/404`: немає прав доступу до цільового Application або Application/авторизований користувач не існує.
