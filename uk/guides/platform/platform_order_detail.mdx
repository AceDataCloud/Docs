Запит замовлення за ID замовлення. Ця кінцева точка підтримує два режими читання: анонімний доступ повертає лише мінімальні поля, потрібні для сторінки оплати; власник замовлення з Account Token отримує повні деталі.

## Огляд інтерфейсу

| Пункт   | Вміст                                                        |
| --- | --------------------------------------------------------- |
| Метод  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| Автентифікація  | Необов’язкова; анонімно — мінімальна проєкція, автентифікований власник — повна проєкція                                    |

`/orders/{id}` і `/orders/{id}/` наразі обидва доступні. ID замовлення є частиною платіжного посилання, його слід розглядати як конфіденційний непрозорий ідентифікатор і не поширювати публічно.

## Анонімний запит

Сторінка оплати може безпосередньо виконувати читання, коли стан входу втрачено:

```shell
export ORDER_ID='你的订单 ID'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

Анонімна відповідь містить лише `id`, `description`, `price`, `state`, `pay_way`, `pay_url`, `expired_at`, `created_at`. Вона не повертає обліковий запис, Application, Package, внутрішні ідентифікатори оплати або metadata.

## Автентифікований запит

```shell
export PLATFORM_TOKEN='你的账户令牌'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Власник замовлення отримує повні деталі Order, включно з `application` / `applications`, `package` / `packages`, `bank_details`, `invoice_automation` та полями моделі. Якщо запит автентифікований, але користувач не є власником замовлення, повертається `403`; за винятком супер-адміністраторів.

## Ключові поля

| Поле            | Опис                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`, `Paid`, `Finished`, `Expired`, `Failed` або `Refunded` |
| `pay_way`     | Поточний спосіб оплати замовлення; назва поля не `payment_method`                             |
| `pay_url`     | Адреса розміщеної сторінки оплати або QR-коду, може бути порожньою                                           |
| `price`       | Остаточна сума до сплати за замовлення; поточна модель замовлення не надає поля `final_price`                         |
| `amount`      | Кількість одиниць ліміту пакета; видима лише в повній автентифікованій відповіді                                            |
| `finished_at` | Час завершення замовлення; назва поля не `paid_at`                                      |

Повна відповідь може містити додаткові поля залежно від способу оплати; клієнт повинен читати їх за потреби та завжди уникати журналювання конфіденційних metadata з повної відповіді.

## Обробка помилок

- `404`: ID замовлення не існує.
- `403`: користувач увійшов у систему, але не є власником замовлення.
- Анонімні запити не повертають `401`; вони отримують лише мінімальну публічну проєкцію.
