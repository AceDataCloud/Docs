Згенеруйте новий Token або пароль для наявного Credential. ID облікових даних, прив’язка Application, ліміти та інші поля залишаються без змін, старий секрет негайно стає недійсним.

> Ротація перерве роботу клієнтів, які все ще використовують старий секрет. Спочатку підготуйте безпечне розповсюдження та план відкату, а потім виконуйте операцію запису.

## Огляд інтерфейсу

| Пункт    | Вміст                                                                          |
| ---- | --------------------------------------------------------------------------- |
| Метод   | `POST`                                                                      |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}/rotate/` |
| Автентифікація   | Account Token                                                               |
| Body | Відсутній або `{}`                                                                     |

Отримайте `credential_id` зі [списку облікових даних](https://platform.acedata.cloud/documents/platform-credential-list):

```shell
export PLATFORM_TOKEN='你的账户令牌'
export CREDENTIAL_ID='要轮换的 Credential ID'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/credentials/${CREDENTIAL_ID}/rotate/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

У разі успіху повертається оновлений Credential. За `type=Token` зчитайте новий `token`; за `type=Identity` зчитайте новий `password`. Розглядайте повну відповідь як секрет і негайно оновіть сторони-викликачі.

## Обробка помилок

- `401`: Account Token недійсний.
- `403`: Немає прав на керування цими обліковими даними.
- `404`: Credential ID не існує.
