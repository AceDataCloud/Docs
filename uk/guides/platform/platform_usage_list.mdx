Переглядайте деталі викликів бізнес-API поточного облікового запису за останні 60 днів; це підходить для звірки списань, виявлення невдалих запитів і усунення проблем за сервісом, Application, API або обліковими даними.

> На цій сторінці переглядається власна історія викликів облікового запису. Якщо ви хочете переглянути лише публічну статистику викликів певного API на всій платформі, скористайтеся [Статистикою викликів API](https://platform.acedata.cloud/documents/platform-api-usage).

## Діапазон зберігання даних

Записи викликів і підсумки виставлення рахунків зберігаються за останні 60 днів; тіла запитів і відповідей зберігаються за останні 30 днів. Для записів за 30–60 днів усе ще можна переглядати такі зведення, як trace, статус, час, модель, використання та фактичне списання, але `metadata.request` і `metadata.response` у деталях більше не повертаються. Зведення, необхідні для агрегування моделей і статистики дійсних результатів, зберігаються до завершення строку зберігання тіл. Якщо потрібно довгостроково зберігати тіла, зберігайте їх самостійно під час виклику.

## Підготовка

### 1. Створіть токен облікового запису

Цей інтерфейс належить до API керування платформою та потребує використання **Account Token (токена облікового запису)**:

1. Увійдіть на [платформу AceDataCloud](https://platform.acedata.cloud).
2. Відкрийте [консоль Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. Натисніть «Створити» та негайно збережіть токен у менеджері паролів або Secret Manager.

Повний опис дивіться в [Керуванні токенами облікового запису платформи AceDataCloud](https://platform.acedata.cloud/documents/platform-token). Токени облікового запису використовуються для `platform.acedata.cloud/api/v1/**`; для виклику бізнес-інтерфейсів `api.acedata.cloud/**` використовуються облікові дані API (Credential), їх не можна змішувати.

```shell
export PLATFORM_TOKEN='你的账户令牌'
```

Не записуйте токен у фронтенд-код, журнали або публічні репозиторії; якщо він витік, негайно видаліть його в консолі та створіть новий.

### 2. Підготуйте ID для фільтрації (необов’язково)

Без передавання умов фільтрації можна переглядати записи, які поточний обліковий запис має право переглядати. Якщо потрібно звузити діапазон:

- `application_id`: отримайте зі [списку заявок на сервіс](https://platform.acedata.cloud/documents/platform-application-list);
- `credential_id`: отримайте зі [списку облікових даних API](https://platform.acedata.cloud/documents/platform-credential-list);
- `api_id`: отримайте зі [списку API](https://platform.acedata.cloud/documents/platform-api-list);
- `service_id`: отримайте зі [списку сервісів](https://platform.acedata.cloud/documents/platform-service-list).

Звичайним користувачам не потрібно передавати `user_id`; якщо його передати явно, він має збігатися з поточним обліковим записом, інакше повертається `403`. Адміністратори можуть використовувати цей параметр для фільтрації між обліковими записами.

## Огляд інтерфейсу

| Пункт           | Вміст                                                  |
| -------------- | ----------------------------------------------------- |
| Метод          | `GET`                                                 |
| URL            | `https://platform.acedata.cloud/api/v1/usage/apis/`   |
| Авторизація    | `Authorization: Bearer ${PLATFORM_TOKEN}`             |
| OAuth Scope    | `usage:read` (`platform:read` / `platform` може включати) |
| Пагінація      | `count` + `items`, за замовчуванням 10 записів на сторінку |

## Діапазон запиту

| `perspective` | Значення                                      |
| ------------- | --------------------------------------------- |
| `both`        | Значення за замовчуванням; повертає записи, за які поточний обліковий запис сплачує або які фактично викликав |
| `billing`     | Повертає лише записи, за які сплачує поточний обліковий запис |
| `actor`       | Повертає лише записи, фактично викликані поточним обліковим записом |

## Параметри запиту

| Параметр            | Тип       | Обов’язковий | За замовчуванням | Опис                                      |
| ------------------- | -------- | ------------ | ---------------- | ----------------------------------------- |
| `perspective`       | string   | Ні           | `both`           | `billing`, `actor` або `both`             |
| `user_id`           | UUID     | Ні           | —                | Лише адміністратори можуть фільтрувати за користувачем; підтримуються повторювані параметри |
| `service_id`        | UUID     | Ні           | —                | Фільтрація за сервісом; підтримуються повторювані параметри |
| `application_id`    | UUID     | Ні           | —                | Фільтрація за Application; підтримуються повторювані параметри |
| `api_id`            | UUID     | Ні           | —                | Фільтрація за API; підтримуються повторювані параметри |
| `credential_id`     | UUID     | Ні           | —                | Фільтрація за обліковими даними API; підтримуються повторювані параметри |
| `status_code`       | integer  | Ні           | —                | Фільтрація за кодом стану HTTP; підтримуються повторювані або розділені комами значення |
| `created_at_from`   | datetime | Ні           | —                | Нижня межа часу створення, ISO 8601       |
| `created_at_to`     | datetime | Ні           | —                | Верхня межа часу створення, ISO 8601       |
| `limit`             | integer  | Ні           | 10               | Кількість записів на сторінці, максимум 100 |
| `offset`            | integer  | Ні           | 0                | Зміщення пагінації                         |
| `ordering`          | string   | Ні           | `-created_at`    | За спаданням часу створення                 |

Якщо час запиту раніший за останні 60 днів, інтерфейс повертає помилку перевірки поля `400` із повідомленням, що повні деталі викликів зберігаються лише 60 днів.

## Приклади запитів

Запит останніх 100 записів:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/' \
  --data-urlencode 'perspective=both' \
  --data-urlencode 'limit=100' \
  --data-urlencode 'ordering=-created_at' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Фільтрація за часом, Application і статусом помилки:

```shell
export APPLICATION_ID='你的 Application ID'

curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/' \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'created_at_from=2026-09-01T00:00:00Z' \
  --data-urlencode 'created_at_to=2026-09-02T00:00:00Z' \
  --data-urlencode 'status_code=500' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Приклад пагінації Python:

```python
import os
import requests

url = "https://platform.acedata.cloud/api/v1/usage/apis/"
headers = {"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"}
params = {"perspective": "both", "limit": 100, "offset": 0}

response = requests.get(url, headers=headers, params=params, timeout=30)
response.raise_for_status()
data = response.json()

for usage in data["items"]:
    print(usage["created_at"], usage["status_code"], usage["deducted_amount"], usage["trace_id"])

if params["offset"] + len(data["items"]) < data["count"]:
    params["offset"] += len(data["items"])
```

## Ключові поля

| Поле                               | Опис                                  |
| -------------------------------- | ----------------------------------- |
| `user_id`                        | Обліковий запис, з якого стягується плата за цей виклик                           |
| `actor_user_id`                  | Обліковий запис, який фактично ініціював виклик; може відрізнятися від `user_id` у разі надання іншим особам дозволу використовувати облікові дані |
| `used_amount`                    | Обсяг використання для цього виклику, розрахований за початковими правилами                       |
| `original_amount`                | Початковий обсяг використання до застосування знижки                         |
| `deducted_amount`                | Остаточно фактично списаний ліміт                           |
| `remaining_amount`               | Залишок ліміту Application після завершення цього списання           |
| `elapsed`                        | Тривалість виклику, зафіксована сервером, у секундах                     |
| `trace_id`                       | Ідентифікатор трасування, що використовується під час діагностики одного запиту                      |
| `metadata`                       | Загальнодоступні метадані; список не повертає повний вміст запиту або відповіді               |
| `api` / `service` / `credential` | Зведена інформація про пов’язані об’єкти для зручного відображення; може бути порожньою, якщо пов’язаний об’єкт більше не існує           |

Одиниця ліміту визначається `service.unit` відповідного Application і не повинна за замовчуванням вважатися доларами США.

## Помилки та повторні спроби

| HTTP | `error`                   | Значення             | Спосіб обробки                               |
| ---- | ------------------------- | -------------- | ---------------------------------- |
| 400  | Помилка перевірки поля                    | Діапазон запиту раніше за 60-денний період зберігання | Скоригуйте час початку до меж останніх 60 днів                  |
| 401  | `not_authenticated`       | Токен облікового запису відсутній або недійсний      | Перевірте Account Token, не використовуйте помилково бізнесові Credential |
| 403  | `permission_denied`       | Запит містить записи, на перегляд яких немає прав    | Видаліть неавторизовані умови фільтрації за користувачем                       |
| 429  | `usage_query_in_progress` | Цілком ідентичний запит досі виконується    | Зачекайте `Retry-After`, а потім виконайте повторну спробу з відступом             |
| 503  | `usage_query_timeout`     | Запит перевищив безпечний ліміт часу на сервері    | Зменште діапазон часу або додайте умови фільтрації, а потім повторіть спробу                   |

Для того самого набору параметрів запиту можна підтримувати щонайбільше один запит у процесі виконання. Для запитів великого діапазону пріоритетно використовуйте вікно в один день або менше, не накладайте ідентичні запити з фіксованим інтервалом.

## Наступні кроки

- [Агрегувати обсяг викликів](https://platform.acedata.cloud/documents/platform-usage-aggregate)：перегляньте використання, зведене за датою та API.
- [Експортувати обсяг викликів](https://platform.acedata.cloud/documents/platform-usage-export)：завантажте велику кількість деталей безпосередньо у CSV.
- [Переглянути записи викликів Proxy](https://platform.acedata.cloud/documents/platform-proxy-usage)：запитуйте записи для сервісів типу Proxy.
- [Переглянути деталі заявки на сервіс](https://platform.acedata.cloud/documents/platform-application-detail)：перевірте баланс і одиницю ліміту.
- [Ротувати облікові дані API](https://platform.acedata.cloud/documents/platform-credential-rotate)：негайно замініть облікові дані, якщо є підозра на їх витік.
