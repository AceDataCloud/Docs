X402 є протоколом на основі HTTP `402 Payment Required` для ланцюгових платежів. Завдяки можливостям X402 від Ace Data Cloud, викликач може не створювати API Token, не попередньо поповнювати баланс рахунку, а безпосередньо здійснювати ланцюгові платежі за допомогою USDC у кожному запиті API.

Цей набір документів організовано за реальним порядком інтеграції: спочатку виконайте мінімальний запит, потім інтегруйте SDK, а після цього зрозумійте мережу, схеми оплати, оплату замовлень та Facilitator. Рекомендується читати за таблицею зверху вниз.

## Рекомендований шлях інтеграції

Якщо ви просто хочете викликати Ace Data Cloud API, спочатку використовуйте офіційний SDK:

- TypeScript: `@acedatacloud/sdk` + `@acedatacloud/x402-client`
- Python: `acedatacloud` + `acedatacloud-x402`

Публічні адреси вихідного коду та пакетів:

| Проект                 | Адреса                                                                                                                 |
| --------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Ace Data Cloud SDK    | [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)                                         |
| X402 Client           | [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)                           |
| X402 Facilitator      | [https://github.com/AceDataCloud/FacilitatorX402](https://github.com/AceDataCloud/FacilitatorX402)                 |
| npm SDK               | [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)                 |
| npm X402 Client       | [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client) |
| PyPI SDK              | [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)                                   |
| PyPI X402 Client      | [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)                         |

SDK автоматично виконає перший запит без аутентифікації, розпарсить `402 Payment Required`, викличе обробник платежів, повторить ці кроки з `PAYMENT-SIGNATURE`. Вам лише потрібно підготувати гаманець з USDC та вибрати мережу, яку ви хочете використовувати.

Якщо ви хочете, щоб ваш API також підтримував X402 для збору платежів, вам потрібно прочитати документацію Facilitator, щоб зрозуміти зв'язок між `paymentRequirements`, `paymentPayload`, `/verify` та `/settle`.

## Статус підтримки

Ace Data Cloud X402 вже пройшов верифікацію в публічному API, офіційному SDK, Facilitator та ланцюгових шляхах розрахунків. У таблиці нижче підсумовано поточний статус за найбільш використовуваними можливостями під час інтеграції розробниками.

| Можливість                   | Статус                  | Опис                                                                 |
| --------------------------- | --------------------- | ------------------------------------------------------------------ |
| Можливості Facilitator      | Доступно              | `https://facilitator.acedata.cloud/.well-known/x402` повертає платіжні мережі та кінцеві точки протоколу.  |
| API 402 `accepts`          | Доступно              | Неплатежні запити повертають доступні вимоги до платежів для Base, SKALE та Solana.              |
| TypeScript SDK             | Доступно              | `@acedatacloud/sdk` та `@acedatacloud/x402-client` автоматично обробляють 402, підписи та повтори. |
| Python SDK                 | Доступно              | `acedatacloud` та `acedatacloud-x402` автоматично обробляють 402, підписи та повтори.              |
| Base `exact`               | Верифіковано в ланцюгу | Підходить для API з фіксованою сумою та оплати замовлень.                                                  |
| Base `upto`                | Верифіковано в ланцюгу | Підходить для API з постоплатою, таких як чат, наразі є єдиною мережею, що пропонує `upto`.                                 |
| SKALE `exact`              | Верифіковано в ланцюгу | Підходить для сценаріїв EVM з низькими витратами на газ.                                              |
| Solana `exact`             | HTTP paid retry верифіковано | Верифіковано API paid retry та відповіді моделі; для підтвердження підпису в ланцюгу рекомендується використовувати власний Solana RPC для звірки.               |
| Оплата замовлень               | Верифіковано в ланцюгу | Оплата замовлень Base `exact` завершена в ланцюгових розрахунках та оновила статус замовлення.                                   |

## Уваги при підключенні

Розробники при підключенні повинні спочатку звертати увагу на реальні вимоги до оплати, які повертаються в поточному запиті, а не копіювати приклади сум або адреси з документації:

- `приймає[].maxAmountRequired` є максимальною сумою, яку можна підписати в поточному запиті.
- `приймає[].актив` є контрактом або mint USDC, який буде використано в цьому запиті.
- `приймає[].extra.chainId`, `приймає[].extra.facilitatorAddress` та `приймає[].extra.verifyingContract` братимуть участь у підписанні EVM типізованих даних.
- `upto` вимагає, щоб гаманець спочатку надав дозвіл Permit2 для USDC цільової мережі; без дозволу буде повернуто `PERMIT2_ALLOWANCE_REQUIRED`.
- Якщо ви чітко хочете використовувати розрахунок за фактичним використанням, передайте в TypeScript SDK `preferScheme: 'upto'`, в іншому випадку SDK вибере першу доступну вимогу, повернуту сервером для цієї мережі.

## Доступні для публічної перевірки області

Перед підключенням можна перевірити ці публічні входи та поведінку SDK:

- API запити без `Authorization` або `PAYMENT-SIGNATURE` повернуть `402 Payment Required`, а `приймає` в відповіді є єдиною підставою для підпису цього запиту.
- TypeScript SDK та Python SDK обидва надають обробник платежів, рівень передачі SDK після отримання 402 викликає обробник та повторює запит.
- `https://facilitator.acedata.cloud/.well-known/x402`: повертає мережі, схеми та кінцеві точки протоколу, підтримувані Facilitator; ціна API все ще базується на 402, що повертається в реальному часі для цільового запиту.
- `https://facilitator.acedata.cloud/supported`: повертає мережі та схеми, підтримувані Facilitator.
- Репозиторій X402Client містить інструменти для верифікації на високому рівні, які можуть бути використані для підтвердження підписів, повторних спроб та поведінки врегулювання; вихід інструменту не замінює `приймає`, повернуте онлайн API.

`upto` належить до розрахунку за фактичним використанням, підходить для API, де реальне використання, таке як доповнення чату, виклики моделей тощо, стає відомим лише після відповіді. Наразі лише Base надає `upto`; якщо перевірка підпису не вдалася, перевірте, чи відповідають chain id, адреса посередника, spender, контракт USDC та дозволи Permit2 відповіді 402.
