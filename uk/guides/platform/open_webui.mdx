[Open WebUI](https://openwebui.com/) (раніше Ollama WebUI) — це клієнт AI з відкритим вихідним кодом, який підтримує багатьох користувачів, бази знань, RAG і приватне розгортання. Він підтримує налаштовувані сумісні з OpenAI кінцеві точки, тому може підключатися до Ace Data Cloud. У цій статті описано процес налаштування.

## Процес отримання

Щоб підключити Ace Data Cloud в Open WebUI, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), отримайте свій API Token і збережіть його для подальшого використання.

![Отримання Ace Data Cloud API Key](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу, де буде запропоновано зареєструватися та увійти; після входу або реєстрації ви автоматично повернетеся на поточну сторінку.

Під час першого отримання надається безкоштовний ліміт, який дає змогу безкоштовно протестувати модельні сервіси Ace Data Cloud.

## Розгортання та налаштування Ace Data Cloud

Open WebUI підключається до сумісної з OpenAI кінцевої точки через змінні середовища, а розгорнути його можна однією командою Docker (замініть `{token}` на свій Token):

```bash
docker run -d \
  --name open-webui \
  -p 3000:8080 \
  -e WEBUI_SECRET_KEY=$(openssl rand -base64 32) \
  -e OPENAI_API_BASE_URL=https://api.acedata.cloud/v1 \
  -e OPENAI_API_KEY={token} \
  -v open-webui:/app/backend/data \
  ghcr.io/open-webui/open-webui:main
```

| Змінна середовища                              | Призначення                                 |
| --------------------------------- | ---------------------------------- |
| `OPENAI_API_BASE_URL`             | Точка входу Ace Data Cloud, **має закінчуватися на `/v1`** |
| `OPENAI_API_KEY`                  | Ваш Token                           |
| `WEBUI_SECRET_KEY`                | Ключ шифрування session, генерується автоматично                  |
| `-v open-webui:/app/backend/data` | Постійне зберігання даних розмов / користувачів                       |

Відкрийте `http://IP-адреса_вашого_сервера:3000`, перший зареєстрований обліковий запис автоматично стане адміністратором. Зверніть увагу на правила шляху Base URL:

| OPENAI_API_BASE_URL                   | Фактичний запит                                                   | Результат                       |
| ------------------------------------- | ------------------------------------------------------ | ------------------------ |
| `https://api.acedata.cloud/v1`        | `https://api.acedata.cloud/v1/chat/completions`        | Правильно                       |
| `https://api.acedata.cloud/openai`    | `https://api.acedata.cloud/openai/chat/completions`    | Також працює                      |
| `https://api.acedata.cloud/openai/v1` | `https://api.acedata.cloud/openai/v1/chat/completions` | 404 (під `/openai` немає `/v1`) |

Після входу перейдіть до **Admin Panel → Settings → Connections** і натисніть «Verify Connection» для перевірки; у **Settings → Models** можна фільтрувати та Pin часто використовувані моделі.

> Крім використання змінних середовища, Open WebUI також підтримує безпосереднє додавання підключення в інтерфейсі: перейдіть до **Admin Settings → Connections**, натисніть ➕ і введіть URL (`https://api.acedata.cloud/v1`) та API Key, після чого Open WebUI автоматично викличе `/models`, щоб отримати список моделей. Докладніше дивіться в офіційній документації [Starting With OpenAI-Compatible Servers](https://docs.openwebui.com/getting-started/quick-start/connect-a-provider/starting-with-openai-compatible).

![Інтерфейс налаштування підключення Open WebUI Ace Data Cloud](https://cdn.acedata.cloud/f366abfd935d.png)

> `MODEL_ID` використовується лише для демонстрації необов’язкового allow list; якщо залишити поле порожнім, буде показано всі моделі, повернуті `/models`.

## Вибір моделі

Каталог моделей постійно оновлюється. Насамперед використовуйте список моделей, автоматично завантажений клієнтом; якщо потрібно вводити вручну, спочатку надішліть запит `GET https://api.acedata.cloud/v1/models`, щоб отримати поточний ID моделі, а потім виберіть її відповідно до підтримуваних клієнтом можливостей контексту, зображень і виклику інструментів.

## Перевірка інтеграції

Якщо ви не впевнені, чи проблема в Open WebUI, чи в мережі, можна спочатку безпосередньо перевірити кінцеву точку за допомогою curl (замініть `{token}` на свій Token):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

Повернення сумісного з OpenAI об’єкта `chat.completion` означає, що Token і кінцева точка готові; якщо повертається `HTTP 403 used_up`, це означає, що Token дійсний, але баланс недостатній — поповніть його в [консолі](https://platform.acedata.cloud/console/applications).

## Розширене: база знань і багато користувачів

База знань (RAG) Open WebUI за замовчуванням використовує ChromaDB для зберігання векторів, а як модель ембедингів можна вказати `text-embedding-3-large` (через Ace Data Cloud). Оригінали документів зберігаються лише на вашому сервері, і моделі надсилаються лише знайдені фрагменти. У **Admin Panel → Users** можна керувати ролями користувачів (Pending / User / Admin); рекомендується встановити «Default User Role» як `pending`, щоб нові користувачі могли користуватися сервісом лише після перевірки та щоб сторонні особи не могли довільно реєструватися й витрачати ліміт. Якщо використовується зворотний проксі nginx, додайте `proxy_buffering off;` і `client_max_body_size 100M;`.

## Поширені запитання

### Відображається Connection error / 404

Зазвичай це трапляється, коли `OPENAI_API_BASE_URL` записано як `.../openai/v1` або пропущено `/v1`. Змініть на `https://api.acedata.cloud/v1`.

### Після завантаження документа неможливо вести діалог

У налаштуваннях RAG в Admin Panel виберіть модель ембедингів `text-embedding-3-large` (OpenAI provider).

### Дані зникають після перезапуску контейнера

Під час запуску потрібно підключити том даних `-v open-webui:/app/backend/data`.
