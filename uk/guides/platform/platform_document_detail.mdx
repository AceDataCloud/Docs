Отримайте повний вміст і навігаційні зв’язки окремого документа за UUID або alias документа. Коли alias відомий, можна виконати запит безпосередньо, без попередньої фільтрації зі списку.

## Огляд інтерфейсу

| Пункт   | Вміст                                                              |
| --- | --------------------------------------------------------------- |
| Метод  | `GET`                                                           |
| URL | `https://platform.acedata.cloud/api/v1/documents/{id_or_alias}` |
| Авторизація  | Публічна; для безпосереднього читання достатньо знати UUID або alias                                       |

## Параметри

- `id_or_alias`: UUID документа, поточний alias або старий alias, збережений у `redirect_from`.
- `lang`: необов’язкова мовна підказка; також можна використовувати `Accept-Language`. Остаточна мова вмісту визначається `content_locale` у відповіді.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/documents/platform-token' \
  --data-urlencode 'lang=zh-CN' \
  -H 'Accept: application/json'
```

## Опис відповіді

Деталі повертаються як один об’єкт, який наразі містить:

- `id`, `alias`, `redirect_from`, `name`, `title`, `type`, `rank`, `tags`;
- `content`, `content_mode`, `content_locale`, `content_hash`;
- `parent`, `sibling` і публічні зведення `children`, відсортовані за rank;
- зв’язки `api` / `proxy` / `dataset` / `integration`, а також `agent` (за наявності).

Відповідь не має поля `breadcrumbs`. Під час побудови навігаційних ланцюжків можна продовжувати отримувати деталі з `parent` або використовувати кешовані зв’язки каталогу документів.

## Обробка помилок

- ID/alias не існує або не відповідає видимості поточного сайту: `404`. `private` контролює лише видимість у списку, не заважає безпосередньому читанню тим, хто знає посилання, і не може слугувати межею конфіденційності.
- Поточний маршрут використовує форму без завершального слеша; не покладайтеся на автоматичне додавання слеша на рівні проксі.
