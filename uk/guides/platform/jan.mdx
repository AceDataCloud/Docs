[Jan](https://jan.ai/) — це офлайн-орієнтований відкритий AI десктопний клієнт, який може як запускати моделі локально, так і підключатися до сумісних з OpenAI кінцевих точок через **Remote Engine**. У цій статті описано, як підключити Ace Data Cloud.

## Процес подання заявки

Щоб підключити Ace Data Cloud у Jan, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), отримайте ваш API Token і збережіть його для подальшого використання.

![Отримання Ace Data Cloud API Key](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли в систему або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти, а після входу або реєстрації ви автоматично повернетеся на поточну сторінку.

Під час першого подання заявки надається безкоштовний ліміт, що дозволяє безкоштовно протестувати модельні сервіси Ace Data Cloud.

## Завантаження Jan

Перейдіть на [офіційний сайт Jan](https://jan.ai/) і завантажте версію для вашої платформи (Windows, macOS, Linux). Для пристроїв Apple Silicon завантажте пакет arm64, щоб отримати найкращу продуктивність.

## Налаштування Ace Data Cloud

Jan розділяє моделі на два типи: **Local Engine** (локальний запуск) і **Remote Engine** (сторонній API). Ace Data Cloud використовує сумісний з OpenAI протокол і підключається через Remote Engine.

Відкрийте Jan, перейдіть до **Settings → Model Providers**, знайдіть картку **OpenAI** та відредагуйте її:

| Поле       | Значення                              | Опис                       |
| -------- | ------------------------------ | ------------------------ |
| API Key  | Ваш Ace Data Cloud Token        | Token, скопійований із консолі             |
| Base URL | `https://api.acedata.cloud/v1` | **Має закінчуватися на `/v1`, без слеша в кінці** |

> Base URL має закінчуватися на `/v1` — це чітка вимога офіційної документації Jan. Якщо ви не хочете перезаписувати початкову конфігурацію OpenAI, можете натиснути «+ Add Provider», створити новий Provider типу `openai-compatible` і заповнити ті самі дані.

![Інтерфейс налаштування додавання AceDataCloud Provider у Jan](https://cdn.acedata.cloud/26017d28afa1.png)

Після збереження користувацького Provider Jan спочатку спробує викликати `{Base URL}/models`, щоб отримати список моделей. Якщо поточна версія або кінцева точка не повертає доступний список, натисніть **+ Add Model** унизу тієї ж сторінки редагування та вручну введіть ID моделі. Після додавання модель з’явиться у випадаючому списку у верхньому лівому куті та матиме іконку «Cloud» для відрізнення віддалених / локальних моделей.

![Інтерфейс керування моделями Provider у Jan](https://cdn.acedata.cloud/ae485550946c.png)

> `MODEL_ID` — це заповнювач; перейдіть до [каталогу моделей](https://platform.acedata.cloud/models), щоб переглянути та замінити його назвою цільової моделі; для точної перевірки орієнтуйтеся на значення `id` у відповіді `/v1/models`. Це значення є назвою моделі, що використовується параметром API `model`, а не UUID сервісу чи API.

## Вибір моделі

[Каталог моделей](https://platform.acedata.cloud/models) постійно оновлюється. Надавайте перевагу списку моделей, автоматично завантаженому клієнтом; якщо потрібно вводити вручну, спочатку надішліть запит `GET https://api.acedata.cloud/v1/models`, скопіюйте значення `id` цільової моделі з масиву `data` у відповіді, а потім виберіть відповідно до можливостей контексту, зображень і виклику інструментів, які підтримує клієнт.

## Перевірка підключення

Якщо ви не впевнені, чи проблема в Jan або в мережі, спочатку можете безпосередньо перевірити кінцеву точку за допомогою curl (замініть `{token}` на ваш Token):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

Повернення сумісного з OpenAI об’єкта `chat.completion` означає, що Token і кінцева точка готові; якщо повертається `HTTP 403 used_up`, це означає, що Token дійсний, але баланс недостатній — поповніть його в [консолі](https://platform.acedata.cloud/console/applications).

## Розширено: локальне + хмарне змішане використання

Jan має вбудований локальний сумісний з OpenAI API Server, який можна увімкнути (Settings → Local API Server). Після увімкнення він слухає `http://localhost:1337/v1/chat/completions` і запускає завантажені вами локальні моделі. Таким чином, у таких фреймворках, як LangChain / LlamaIndex, можна вказати локальний Base URL для безкоштовного налагодження, а для складних завдань перейти на віддалені моделі Ace Data Cloud. Під час перемикання моделей контекст діалогу не втрачається.

## Поширені запитання

### Повідомлення Connection error або 404

Зазвичай це означає, що в Base URL пропущено `/v1`. Змініть на `https://api.acedata.cloud/v1` (обов’язково має закінчуватися на `/v1` і не пишіть як `.../openai/v1`).

### Повідомлення 401 Unauthorized

Переконайтеся, що в API Key вставлено Token Ace Data Cloud (без префікса `Bearer` і без зайвих пробілів), а баланс відповідного застосунку достатній.

### Віддалена модель не з’являється у випадаючому списку

Спочатку натисніть кнопку оновлення моделей, щоб викликати `/v1/models`; якщо автоматичне виявлення не вдалося, вручну натисніть **+ Add Model** і без змін додайте значення `id` моделі з каталогу.

### Чи можна завантажити зображення, щоб модель його проаналізувала

Можна, але потрібно вибрати з поточного каталогу моделей модель, що явно підтримує візуальний ввід.
