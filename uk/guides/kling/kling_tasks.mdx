Основна функція Kling Tasks API полягає в запиті статусу виконання завдання шляхом введення ID завдання, згенерованого Kling Videos Generation API.

У цьому документі буде детально представлено інструкції з інтеграції Kling Tasks API, щоб допомогти вам легко інтегрувати та повністю використати потужні можливості цього API. За допомогою Kling Tasks API ви можете легко реалізувати запит статусу виконання завдань Kling Videos Generation API.

## Процес подання заявки

Щоб використовувати Kling Videos Generation API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token і залишити його про запас.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли в систему або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, немає потреби подавати заявку окремо для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт, доступний для безкоштовного тестування; коли ліміту недостатньо, ви можете поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Приклад запиту

Kling Tasks API можна використовувати для запиту результатів Kling Videos Generation API. Щодо того, як використовувати Kling Videos Generation API, зверніться до документації [Kling Videos Generation API ](https://platform.acedata.cloud/documents/kling-videos)。

Ми візьмемо як приклад один ID завдання, повернений сервісом Kling Videos Generation API, щоб продемонструвати, як використовувати цей API. Припустімо, що ми маємо ID завдання: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, далі продемонструємо, як через передавання одного ID завдання.

### Налаштування заголовків запиту та тіла запиту

**Request Headers** включають:

- `accept`: вказує на отримання результату відповіді у форматі JSON, тут заповнюється як `application/json`.
- `authorization`: ключ для виклику API, після подання заявки його можна безпосередньо вибрати зі спадного списку.

**Request Body** включає:

- `id`: ID завантаженого завдання.
- `action`: спосіб операції із завданням.

Налаштування показано на зображенні нижче:

### Приклад коду

Можна побачити, що праворуч на сторінці вже автоматично згенеровано код різними мовами, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/bsqh3i.png" width="500" className="m-auto" /></p>

Деякі приклади коду наведено нижче:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

У результаті, що повертається, загалом є кілька полів, поле request — це request body під час ініціювання завдання, водночас поле response — це response body, повернене після завершення завдання. Опис полів наведено нижче.

- `id`, ID створеного відеозавдання, використовується для унікальної ідентифікації цього завдання зі створення відео.
- `request`, інформація запиту у відеозавданні.
- `response`, інформація відповіді у відеозавданні.
- `created_at`, час створення завдання, Unix timestamp (секунди, з плаваючою комою).
- `started_at`, час початку виконання завдання, Unix timestamp (секунди, з плаваючою комою).
- `finished_at`, час завершення завдання, Unix timestamp (секунди, з плаваючою комою). Це поле не повертається, коли завдання не завершено.
- `elapsed`, тривалість виконання завдання, у секундах (з плаваючою комою, збережено 3 знаки після коми). Це поле не повертається, коли завдання не завершено.

- `ids`: масив ID завантажених завдань.
- `action`: спосіб операції із завданням.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Забагато запитів, ви перевищили обмеження частоти.
- `500 api_error`：Внутрішня помилка сервера, щось пішло не так на сервері.
