У цій статті буде представлено інструкцію з інтеграції Kling Videos Generation API, який дає змогу генерувати офіційні відео Kling шляхом введення користувацьких параметрів.

## Процес подання заявки

Щоб використовувати Kling Videos Generation API, спершу перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token і зберегти його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token дає змогу викликати всі сервіси платформи, немає потреби подавати заявку окремо для кожного сервісу.** Під час першого отримання надається безкоштовний ліміт, який можна використати для безкоштовного ознайомлення; коли ліміту недостатньо, можна поповнити універсальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Базове використання

Спершу розглянемо базовий спосіб використання: введіть промпт `prompt`, дію генерації `action`, референтне зображення першого кадру `start_image_url` і модель `model`, після чого можна отримати оброблений результат. Спочатку потрібно просто передати поле `action` зі значенням `text2video`; воно переважно містить три дії: генерація відео з тексту (`text2video`), генерація відео із зображення (`image2video`), розширення відео (`extend`). Потім також потрібно ввести модель `model`; наразі доступні моделі `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`, конкретний вміст наведено нижче:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Можна побачити, що тут ми налаштували Request Headers, зокрема:

- `accept`: який формат відповіді потрібно отримати; тут указано `application/json`, тобто формат JSON.
- `authorization`: ключ для виклику API, після отримання його можна безпосередньо вибрати у випадаючому списку.

Також налаштовано Request Body, зокрема:

- `model`: модель для генерації відео, переважно включає моделі `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode`: режим генерації відео, доступні значення: стандартний режим `std`, режим максимальної швидкості `pro` і нативний режим 4K `4k`. Серед них `4k` підтримується лише `kling-v3` та `kling-v3-omni` і несумісний з `camera_control` (керуванням рухом камери).
- `action`: дія цього завдання генерації відео, переважно містить три дії: генерація відео з тексту (`text2video`), генерація відео із зображення (`image2video`), розширення відео (`extend`).
- `start_image_url`: посилання на референтне зображення першого кадру, яке потрібно завантажити, коли вибрано дію генерації відео із зображення `image2video`.
- `end_image_url`: необов’язково для генерації відео із зображення, вказує кінцевий кадр.
- `duration`: тривалість відео в секундах. `kling-v3` та `kling-v3-omni` підтримують цілочисельну тривалість від 3 до 15 секунд; `kling-o1` підтримує лише 5 секунд; інші моделі підтримують 5 або 10 секунд.
- `generate_audio`: чи генерувати аудіо синхронно, необов’язково, булеве значення. Підтримується `kling-v3`, `kling-v3-omni` та `kling-v2-6` (лише режим pro). За замовчуванням — `false`.
- `aspect_ratio`: співвідношення сторін відео, необов’язково, підтримуються `16:9`, `9:16`, `1:1`, за замовчуванням — `16:9`.
- `cfg_scale`: сила релевантності, діапазон [0,1]; що більше значення, то точніше відповідність промпту.
- `camera_control`: необов’язково, параметри об’єкта для керування рухом камери, підтримуються пресети type/simple, а також налаштування horizontal, vertical, pan, tilt, roll, zoom тощо.
- `negative_prompt`: необов’язково, негативний промпт із тим, що не повинно з’являтися, до 200 символів.
- `image_list`: список референтних зображень Omni, застосовується до моделей `kling-o1` та `kling-v3-omni`; спосіб використання дивіться нижче в розділі «Універсальні референси Omni».
- `video_list`: список референтних відео Omni (підтримується редагування відео), застосовується до моделей `kling-o1` та `kling-v3-omni`; спосіб використання дивіться нижче в розділі «Універсальні референси Omni».
- `prompt`: промпт.
- `callback_url`: URL, на який потрібно отримати результат через зворотний виклик.
- `async`: необов’язково; коли встановлено значення `true`, інтерфейс негайно повертає `task_id`, без потреби надавати `callback_url`, після чого результат отримується шляхом опитування відповідного інтерфейсу запиту завдання.

Після вибору можна побачити, що праворуч також згенеровано відповідний код, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Натисніть кнопку «Try», щоб провести тестування. Як показано на зображенні вище, тут ми отримали такий результат:

```json
{
  "success": true,
  "video_id": "900798310464749610",
  "video_url": "https://cdn.acedata.cloud/assets/examples/kling/6c68c267-065b-4423-b66b-a0e4c59ee0d5-6a664a591a53.mp4",
  "duration": "5.041",
  "state": "succeed",
  "task_id": "6c68c267-065b-4423-b66b-a0e4c59ee0d5"
}
```

Результат, що повертається, має кілька полів, описаних нижче:

- `success`: поточний статус завдання генерації відео.
- `task_id`: ID поточного завдання генерації відео.
- `video_id`: ID відео поточного завдання генерації відео.
- `video_url`: посилання на відео поточного завдання генерації відео.
- `duration`: тривалість відео поточного завдання генерації відео.
- `state`: стан поточного завдання генерації відео.

Можна побачити, що ми отримали задовільну інформацію про відео; нам лише потрібно отримати згенероване відео Kling за адресою посилання на відео в `data` результату.

Крім того, якщо потрібно згенерувати відповідний код інтеграції, його можна безпосередньо скопіювати; наприклад, код CURL наведено нижче:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Матриця можливостей моделей

Різні моделі суттєво відрізняються за підтримкою параметрів. Наведену нижче матрицю впорядковано на основі [офіційної документації Kling щодо video models](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels). Перед викликом спершу перевірте, чи підтримує поточна комбінація `model` / `mode` / `duration` потрібну вам функцію, інакше буде повернено помилки на кшталт `model/mode/duration(...) is not supported with image_tail`.
| Модель                  | Режим             | `end_image_url`（перший і останній кадри） | `generate_audio`（супровідний звук） | `camera_control`（рух камери） | Примітки                                           |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ лише `duration=5`     | ❌                    | ✅ лише `duration=5`     | `extend` не підтримує `negative_prompt` і `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | Генерація відео з кількох зображень, `extend` доступний у всіх режимах                         |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Єдиний режим, лише `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Єдиний режим, лише `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | Єдина не-v3 модель, що одночасно підтримує супровідний звук                             |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | Діапазон `duration` 3–15 секунд                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | Режим 4K несумісний із рухом камери                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Підтримує лише `duration=5`                             |

Примітки:

- `mode=4k` підтримують лише `kling-v3` і `kling-v3-omni`; він також є взаємовиключним із `camera_control`（рухом камери）.
- `end_image_url` можна використовувати лише разом із `start_image_url`, коли `action=image2video`. Передавання лише `end_image_url`（без `start_image_url`）буде відхилено.
- `kling-v3` / `kling-v3-omni` приймають будь-яке ціле значення `duration` від 3 до 15 секунд; `kling-o1` приймає лише 5; решта моделей приймають лише 5 або 10.
- `generate_audio` за замовчуванням має значення `false`. Підтримується лише `kling-v3`, `kling-v3-omni` і `kling-v2-6`（режим pro）.

## Функція розширення відео

Якщо ви хочете продовжити генерацію вже створеного відео Kling, можна встановити параметр `action` як `extend` і ввести ID відео, яке потрібно продовжити. ID відео отримується відповідно до базового використання, як показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Тоді можна побачити, що ID відео:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Зверніть увагу, що `video_id` тут є ID згенерованого відео. Якщо ви не знаєте, як генерувати відео, можете звернутися до базового використання вище для генерації відео.

Далі потрібно обов’язково заповнити підказку, яку необхідно розширити на наступному кроці, щоб налаштувати генерацію відео, і можна вказати такий вміст:

- `model`：модель для генерації відео, основні моделі — `kling-v1` 、`kling-v1-5` і `kling-v1-6`.
- `mode`：режим генерації відео, доступні значення: стандартний режим `std`, швидкісний режим `pro` і нативний режим 4K `4k`（підтримуються лише `kling-v3` і `kling-v3-omni`, несумісні з керуванням рухом камери）.
- `duration`：тривалість відео для цього завдання генерації, переважно включає 5 с і 10 с.
- `start_image_url`：під час вибору дії генерації відео із зображення `image2video` обов’язково потрібно завантажити посилання на еталонне зображення першого кадру.
- `prompt`：підказка.

Приклад заповнення наведено нижче:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Після заповнення код автоматично генерується так:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Відповідний код Python:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Натиснувши запуск, можна побачити, що буде отримано такий результат:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```

Як можна побачити, вміст результату узгоджується з наведеним вище, таким чином реалізується функція розширення відео.

## Omni універсальні референси（редагування відео / референсне відео / референси з кількох зображень）

`kling-o1` і `kling-v3-omni` — дві незалежні моделі, обидві підтримують можливість «універсальних референсів». На основі генерації відео з тексту（`action=text2video`）можна додатково передавати референсні зображення або референсні відео, щоб реалізувати **референси з кількох зображень, референсне відео, а також безпосереднє редагування наявного відео**.

**Основна угода**：референсні матеріали мають бути згадані в `prompt` у формі `&lt;&lt;<image_1>>>`、`&lt;&lt;<video_1>>>`（нумерація починається з 1）для посилання на матеріали у відповідній позиції в `image_list` / `video_list`, лише тоді модель застосує ці референси. Якщо передати лише матеріали, але не згадати їх у підказці, матеріали буде проігноровано.

> Пояснення щодо безпеки: поточний API не відкриває `element_list`. ID Kling Element Library не ізольовані між орендарями, тому до надання ізольованого між орендарями Element Management API використовуйте `image_list` для передавання референсного зображення суб’єкта.

Omni-запити не підтримують `negative_prompt`、`cfg_scale` або `camera_control`, а також не можуть використовувати `mode=4k`. Якщо міститься референсне відео, `generate_audio` має бути `false`.

### Референсне відео та редагування відео（`video_list`）
`video_list` використовується для передачі референсних відео та є найпоширенішим сценарієм цієї можливості, поля елементів масиву такі:

- `video_url`：посилання на референсне відео, не може бути порожнім. Не більше 1 відео MP4/MOV, розмір файлу ≤200MB, частота кадрів 24–60fps. `kling-o1` вимагає тривалість 3–10 секунд, ширину й висоту кожну 700–2160px; `kling-v3-omni` вимагає тривалість 3–15.5 секунд, ширину й висоту кожну 700–4553px, загальну кількість пікселів ≤8,294,400, співвідношення сторін 0.4–2.
- `refer_type`：тип референсу, можна вибрати `base` (за замовчуванням, **базове відео, яке потрібно редагувати**, тобто «безпосереднє редагування відео», можна додавати/видаляти/змінювати елементи, змінювати композицію, стиль, колір, погоду тощо) або `feature` (**референс характеристик**, для посилання на його стиль / рух камери / продовження зйомки наступного кадру).
- `keep_original_sound`：чи зберігати аудіо оригінального відео, можна вибрати `yes` (зберегти) або `no` (видалити).

> Примітка：за наявності референсного відео `generate_audio` має бути `false`. Для відео з `refer_type=base` не можна додатково вказувати перший кадр / останній кадр.

Приклад CURL для редагування наявного відео (перетворення відео на аніме-стиль) такий:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Референс за кількома зображеннями（`image_list`）

`image_list` використовується для передачі референсних зображень (елементи / сцени / стиль тощо), поля елементів масиву такі:

- `image_url`：посилання на референсне зображення, не може бути порожнім. Вимоги: формат .jpg/.jpeg/.png; розмір файлу ≤10MB; найкоротша сторона ≥300px; співвідношення сторін 1:2.5 ~ 2.5:1.
- `type`：необов’язково. Якщо не передано, використовується як звичайне референсне зображення; якщо передано `first_frame` / `end_frame`, використовується відповідно як перший кадр / останній кадр (еквівалентно `start_image_url` / `end_image_url`).

Під час використання потрібно посилатися в `prompt` через `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Обмеження кількості: за відсутності референсного відео референсних зображень ≤ 7; за наявності референсного відео референсних зображень ≤ 4. Якщо передаються лише перший / останній кадри, також можна безпосередньо використовувати `start_image_url` / `end_image_url`, але останній кадр потрібно використовувати разом із першим кадром.

> Примітка：якщо одночасно передано `start_image_url` / `end_image_url` та `image_list`, перший / останній кадри будуть розміщені перед `image_list`, що може вплинути на відповідність номерів у `&lt;&lt;<image_N>>>`. Рекомендується вибрати один із варіантів: коли потрібні перший / останній кадри, безпосередньо вказуйте `type` у `image_list`, не змішуйте з `start_image_url` / `end_image_url`.

Приклад CURL генерації відео з референсом за кількома зображеннями:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Асинхронний зворотний виклик

Оскільки API Kling Videos Generation потребує відносно тривалого часу для генерації, приблизно 1-2 хвилини, якщо API довго не відповідає, HTTP-запит постійно підтримуватиме з’єднання, що призводить до додаткового споживання системних ресурсів, тому цей API також підтримує асинхронні зворотні виклики.

Загальний процес такий: коли клієнт ініціює запит, він додатково вказує поле `callback_url`; після того як клієнт надсилає API-запит, API одразу повертає результат, що містить поле `task_id`, яке представляє ID поточного завдання. Після завершення завдання результат згенерованого відео буде надіслано у формі POST JSON на вказаний клієнтом `callback_url`, де також міститиметься поле `task_id`, таким чином результати завдання можна пов’язати через ID.

Нижче ми на прикладі розглянемо, як саме це робити.

Спочатку, Webhook-зворотний виклик — це сервіс, який може приймати HTTP-запити, розробник повинен замінити його URL-адресою власного HTTP-сервера. Для зручності демонстрації тут використовується публічний приклад сайту Webhook https://webhook.site/; відкривши цей сайт, можна отримати Webhook URL, як показано на зображенні:

![](https://cdn.acedata.cloud/tbcnai.png)

Скопіювавши цю URL-адресу, її можна використовувати як Webhook; приклад тут — `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Далі ми можемо встановити для поля `callback_url` вказану вище Webhook URL-адресу, одночасно заповнивши відповідні параметри, конкретний вміст показано на зображенні:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Натиснувши запуск, можна побачити, що результат буде отримано негайно, як показано нижче:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Трохи зачекавши, ми можемо побачити результат генерації відео на `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, як показано на зображенні:

![](https://cdn.acedata.cloud/zv5u2q.png)

Вміст такий:

```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Можна побачити, що в результаті є поле `task_id`, інші поля аналогічні наведеним вище; через це поле можна реалізувати зв’язування завдань.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Занадто багато запитів, ви перевищили ліміт швидкості.
- `500 api_error`：Внутрішня помилка сервера, на сервері щось пішло не так.
### Приклад відповіді з помилкою

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
