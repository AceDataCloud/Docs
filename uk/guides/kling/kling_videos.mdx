У цій статті буде представлено інструкцію з інтеграції Kling Videos Generation API, який дозволяє генерувати офіційні відео Kling шляхом введення користувацьких параметрів.

## Процес подання заявки

Щоб використовувати Kling Videos Generation API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token, і збережіть його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token дозволяє викликати всі сервіси платформи, немає потреби подавати заявку окремо для кожного сервісу.** Під час першого подання заявки надається безкоштовний ліміт, який можна використати для безкоштовного ознайомлення; якщо ліміту недостатньо, ви можете поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Базове використання

Спочатку розглянемо базовий спосіб використання: введіть промпт `prompt`, дію генерації `action`, референтне зображення першого кадру `start_image_url` і модель `model`, після чого можна отримати оброблений результат; спершу потрібно просто передати поле `action` зі значенням `text2video`, воно переважно містить три дії: генерація відео з тексту (`text2video`), генерація відео із зображення (`image2video`), розширення відео (`extend`), а потім нам також потрібно ввести модель `model`; наразі основними є моделі `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`, конкретний вміст наведено нижче:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Можна побачити, що тут ми налаштували Request Headers, зокрема:

- `accept`: який формат відповіді потрібно отримати; тут вказано `application/json`, тобто формат JSON.
- `authorization`: ключ для виклику API, після подання заявки його можна безпосередньо вибрати зі спадного списку.

Також налаштовано Request Body, зокрема:

- `model`: модель для генерації відео; основними є моделі `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode`: режим генерації відео, доступні значення: стандартний режим `std`, надшвидкий режим `pro` та нативний режим 4K `4k`. Серед них `4k` підтримується лише `kling-v3` і `kling-v3-omni` та несумісний з `camera_control` (керуванням рухом камери).
- `action`: дія цього завдання з генерації відео, переважно містить три дії: генерація відео з тексту (`text2video`), генерація відео із зображення (`image2video`), розширення відео (`extend`).
- `start_image_url`: посилання на референтне зображення першого кадру, яке необхідно завантажити, якщо вибрано дію генерації відео із зображення `image2video`.
- `end_image_url`: необов’язкове під час генерації відео із зображення, визначає кінцевий кадр.
- `duration`: тривалість відео в секундах. `kling-v3` і `kling-v3-omni` підтримують цілу тривалість від 3 до 15 секунд; `kling-o1` підтримує лише 5 секунд; інші моделі підтримують 5 або 10 секунд.
- `generate_audio`: чи генерувати аудіо синхронно, необов’язково, булеве значення. Підтримується `kling-v3`, `kling-v3-omni` та `kling-v2-6` (лише режим pro). За замовчуванням `false`.
- `aspect_ratio`: співвідношення сторін відео, необов’язково, підтримує `16:9`, `9:16`, `1:1`, за замовчуванням `16:9`.
- `cfg_scale`: інтенсивність релевантності, діапазон [0,1], що більше значення, то точніше відповідність промпту.
- `camera_control`: необов’язково, параметр-об’єкт для керування рухом камери, підтримує попередні налаштування type/simple, а також конфігурації horizontal, vertical, pan, tilt, roll, zoom тощо.
- `negative_prompt`: необов’язково, негативний промпт із тим, що не повинно з’являтися, максимум 200 символів.
- `image_list`: список референтних зображень Omni, застосовується до моделей `kling-o1` і `kling-v3-omni`, використання дивіться нижче в розділі «Універсальні референси Omni».
- `video_list`: список референтних відео Omni (підтримує редагування відео), застосовується до моделей `kling-o1` і `kling-v3-omni`, використання дивіться нижче в розділі «Універсальні референси Omni».
- `prompt`: промпт.
- `callback_url`: URL для отримання результату через callback.
- `async`: необов’язково, коли встановлено `true`, інтерфейс негайно повертає `task_id`, без необхідності надавати `callback_url`, після чого результат отримується шляхом опитування через відповідний інтерфейс запиту завдань.

Після вибору можна помітити, що праворуч також згенеровано відповідний код, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Натисніть кнопку «Try», щоб провести тестування; як показано вище, тут ми отримали такий результат:

```json
{
  "success": true,
  "video_id": "900798310464749610",
  "video_url": "https://cdn.acedata.cloud/assets/examples/kling/6c68c267-065b-4423-b66b-a0e4c59ee0d5-6a664a591a53.mp4",
  "duration": "5.041",
  "state": "succeed",
  "task_id": "6c68c267-065b-4423-b66b-a0e4c59ee0d5"
}
```

Результат, що повертається, має загалом кілька полів, описаних нижче:

- `success`, статус завдання генерації відео в цей момент.
- `task_id`, ID завдання генерації відео в цей момент.
- `video_id`, ID відео завдання генерації відео в цей момент.
- `video_url`, посилання на відео завдання генерації відео в цей момент.
- `duration`, тривалість відео завдання генерації відео в цей момент.
- `state`, стан завдання генерації відео в цей момент.

Можна побачити, що ми отримали задовільну інформацію про відео; нам лише потрібно отримати згенероване відео Kling за адресою посилання на відео в `data` результату.

Крім того, якщо ви хочете згенерувати відповідний код інтеграції, його можна безпосередньо скопіювати та згенерувати, наприклад, код CURL наведено нижче:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Матриця можливостей моделей

### Тарифікація O1 та референтних відео Omni

Для `kling-o1` тарифікація залежить від режиму та наявності `video_list`. Нижче наведено ціни за готове відео тривалістю 5 секунд:

| Режим  | Без референтного відео | З референтним відео |
| --- | ------------: | ------------: |
| std | 4.005 Credits | 6.010 Credits |
| pro | 5.340 Credits | 8.010 Credits |
Успішні запити `kling-o1` і `kling-v3-omni` з референсним відео оплачуються за розрахунковими секундами: std — **1.202 Credits/секунда**, pro — **1.602 Credits/секунда**. Наприклад, генерація 5 секунд у режимі std коштує 6.010 Credits. Пропуск `video_list` не активує тариф референсного відео; `image_list`, зображення першого та останнього кадрів також не належать до референсного відео. Референсне відео не можна використовувати одночасно з `generate_audio=true`.

Відеомонтаж із `refer_type=base` (за замовчуванням) може відповідати тривалості референсного відео, а остаточна оплата розраховується за фактичною тривалістю готового ролика, округленою до цілих секунд: наприклад, 5.708 секунди оплачуються як 6 секунд, 5.041 секунди — як 5 секунд. `refer_type=feature` використовує запитаний `duration`. `usage.reference_video_seconds` у відповіді вказує остаточну кількість розрахункових секунд; орієнтовна ціна під час запиту може відрізнятися від остаточного списання.

Різні моделі суттєво відрізняються за підтримкою параметрів. Наведену нижче матрицю складено на основі [офіційної документації Kling щодо video models](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels); перед викликом перевірте, чи підтримує поточна комбінація `model` / `mode` / `duration` потрібну вам функцію, інакше буде повернуто помилки на кшталт `model/mode/duration(...) is not supported with image_tail`.

| Модель                  | Режим             | `end_image_url` (перший і останній кадри) | `generate_audio` (озвучення) | `camera_control` (рух камери) | Примітки                                           |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ лише `duration=5`     | ❌                    | ✅ лише `duration=5`     | `extend` не підтримує `negative_prompt` і `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | Відео з кількох зображень, `extend` доступний у всіх режимах                         |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Єдиний режим, лише `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Єдиний режим, лише `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | Єдина не-v3 модель, яка одночасно підтримує озвучення                             |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | Діапазон `duration` 3–15 секунд                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | Режим 4K несумісний із рухом камери                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Підтримує лише `duration=5`                             |

Зауваження:

- `mode=4k` підтримують лише `kling-v3` і `kling-v3-omni`; він також є взаємовиключним із `camera_control` (рухом камери).
- `end_image_url` можна використовувати лише разом із `start_image_url` при `action=image2video`. Передавання лише `end_image_url` (без `start_image_url`) буде відхилено.
- `kling-v3` / `kling-v3-omni` приймають будь-який цілий `duration` від 3 до 15 секунд; `kling-o1` приймає лише 5; інші моделі приймають лише 5 або 10.
- `generate_audio` за замовчуванням має значення `false`. Його підтримують лише `kling-v3`, `kling-v3-omni` і `kling-v2-6` (режим pro).

## Функція розширення відео

Якщо ви хочете продовжити генерацію вже створеного відео Kling, можна встановити параметр `action` як `extend` і ввести ID відео, яке потрібно продовжити. ID відео отримується відповідно до базового використання, як показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Тоді можна побачити, що ID відео має такий вигляд:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Зверніть увагу, що `video_id` тут є ID згенерованого відео. Якщо ви не знаєте, як генерувати відео, можете звернутися до базового використання вище для генерації відео.

Далі потрібно обов’язково заповнити підказку для наступного кроку розширення, щоб налаштувати генерацію відео, і можна вказати такий вміст:

- `model`: модель для генерації відео, переважно моделі `kling-v1`, `kling-v1-5` і `kling-v1-6`.
- `mode`: режим генерації відео; доступні значення: стандартний режим `std`, швидкий режим `pro` і нативний режим 4K `4k` (підтримується лише `kling-v3` і `kling-v3-omni`, несумісний із керуванням рухом камери).
- `duration`: тривалість відео для цього завдання генерації, переважно включає 5 с і 10 с.
- `start_image_url`: посилання на завантажене референсне зображення першого кадру, яке обов’язково потрібне при виборі дії генерації відео зі зображення `image2video`.
- `prompt`: підказка.

Приклад заповнення наведено нижче:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Після заповнення код буде автоматично згенеровано так:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Відповідний код Python:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Натиснувши запуск, можна побачити результат, як показано нижче:

```json

  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```
Як можна побачити, результуючий вміст узгоджується з наведеним вище, що також реалізує функцію розширення відео.

## Omni універсальні референси (редагування відео / референс-відео / референси з кількох зображень)

`kling-o1` та `kling-v3-omni` — це дві незалежні моделі, і обидві підтримують можливість «універсальних референсів». На основі генерації відео з тексту (`action=text2video`) можна додатково передавати референс-зображення або референс-відео, реалізуючи **референси з кількох зображень, референс-відео та безпосереднє редагування наявного відео**.

**Ключова домовленість**: референс-матеріали повинні бути згадані в `prompt` у формі `&lt;&lt;<image_1>>>`, `&lt;&lt;<video_1>>>` (нумерація починається з 1), щоб посилатися на матеріали у відповідних позиціях у `image_list` / `video_list`; лише тоді модель застосує ці референси. Якщо передати лише матеріали, але не згадати їх у промпті, матеріали буде проігноровано.

> Пояснення щодо безпеки: поточний API не відкриває `element_list`. ID Kling Element Library не ізольовані між орендарями, тому до надання Element Management API з ізоляцією орендарів використовуйте `image_list` для передавання референс-зображень об’єктів.

Omni-запити не підтримують `negative_prompt`, `cfg_scale` або `camera_control`, також не можна використовувати `mode=4k`. Якщо міститься референс-відео, `generate_audio` має бути `false`.

### Референс-відео та редагування відео (`video_list`)

`video_list` використовується для передавання референс-відео та є найпоширенішим сценарієм цієї можливості; поля елементів масиву такі:

- `video_url`: посилання на референс-відео, не може бути порожнім. Щонайбільше 1 відео MP4/MOV, розмір файлу ≤200MB, частота кадрів 24–60fps. `kling-o1` вимагає тривалість 3–10 секунд, ширину й висоту по 700–2160px; `kling-v3-omni` вимагає тривалість 3–15.5 секунд, ширину й висоту по 700–4553px, загальну кількість пікселів ≤8,294,400, співвідношення сторін 0.4–2.
- `refer_type`: тип референсу, можливі значення `base` (за замовчуванням, **базове відео для редагування**, тобто «безпосереднє редагування відео», можна додавати/видаляти або змінювати елементи, змінювати композицію, стиль, кольори, погоду тощо) або `feature` (**референс характеристик**, посилання на його стиль / рух камери / продовження зйомки наступного кадру).
- `keep_original_sound`: чи зберігати аудіо оригінального відео, можливі значення `yes` (зберегти) або `no` (видалити).

> Увага: за наявності референс-відео `generate_audio` має бути `false`. Для відео з `refer_type=base` не можна додатково вказувати перший / останній кадр.

Приклад CURL для редагування наявного відео (перетворення відео на стиль аніме) наведено нижче:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Референси з кількох зображень (`image_list`)

`image_list` використовується для передавання референс-зображень (елементи / сцени / стилі тощо); поля елементів масиву такі:

- `image_url`: посилання на референс-зображення, не може бути порожнім. Вимоги: формат .jpg/.jpeg/.png; розмір файлу ≤10MB; найкоротша сторона ≥300px; співвідношення сторін 1:2.5 ~ 2.5:1.
- `type`: необов’язково. Якщо не передано, використовується як звичайне референс-зображення; якщо передано `first_frame` / `end_frame`, використовується відповідно як перший / останній кадр (еквівалентно `start_image_url` / `end_image_url`).

Під час використання потрібно посилатися в `prompt` через `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Обмеження кількості: за відсутності референс-відео кількість референс-зображень ≤ 7; за наявності референс-відео кількість референс-зображень ≤ 4. Якщо передаються лише перший / останній кадри, також можна безпосередньо використовувати `start_image_url` / `end_image_url`, але останній кадр потрібно використовувати разом із першим кадром.

> Увага: якщо одночасно передано `start_image_url` / `end_image_url` та `image_list`, перший / останній кадри розташовуватимуться перед `image_list`, що може вплинути на відповідність нумерації `&lt;&lt;<image_N>>>`. Рекомендується обрати один із двох варіантів: коли потрібні перший / останній кадри, безпосередньо вказуйте `type` у `image_list`, не змішуйте з `start_image_url` / `end_image_url`.

Приклад CURL генерації відео з референсами кількох зображень:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Асинхронний зворотний виклик

Оскільки час генерації Kling Videos Generation API є відносно тривалим, приблизно 1–2 хвилини, якщо API довго не відповідає, HTTP-запит постійно підтримуватиме з’єднання, що призводить до додаткового споживання системних ресурсів, тому цей API також надає підтримку асинхронних зворотних викликів.

Загальний процес такий: коли клієнт надсилає запит, він додатково вказує поле `callback_url`; після того як клієнт надсилає API-запит, API негайно повертає результат, який містить інформацію поля `task_id`, що представляє ID поточного завдання. Після завершення завдання результат генерації відео буде надіслано у формі POST JSON на `callback_url`, вказаний клієнтом, де також міститься поле `task_id`, тож результати завдання можна пов’язати через ID.

Нижче ми на прикладі розглянемо, як саме це виконати.

Спочатку Webhook-зворотний виклик — це сервіс, здатний отримувати HTTP-запити; розробник повинен замінити його на URL власного розгорнутого HTTP-сервера. Тут для зручності демонстрації використовується публічний приклад сайту Webhook https://webhook.site/; відкривши цей сайт, можна отримати Webhook URL, як показано на зображенні:

![](https://cdn.acedata.cloud/tbcnai.png)

Скопіюйте цей URL, і його можна буде використовувати як Webhook; приклад тут: `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Далі ми можемо встановити для поля `callback_url` зазначений вище Webhook URL, одночасно заповнивши відповідні параметри; конкретний вміст показано на зображенні:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Натиснувши запуск, можна побачити, що результат буде отримано негайно, як показано нижче:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```
Зачекайте трохи, ми можемо спостерігати результат згенерованого відео на `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, як показано на рисунку:

![](https://cdn.acedata.cloud/zv5u2q.png)

Вміст такий:

```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Можна побачити, що в результаті є поле `task_id`, інші поля подібні до наведених вище, і через це поле можна реалізувати зв’язування завдань.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API повертає відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Занадто багато запитів, ви перевищили ліміт частоти запитів.
- `500 api_error`：Внутрішня помилка сервера, щось пішло не так на сервері.

### Приклад відповіді з помилкою

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## Висновок

За допомогою цього документа ви вже дізналися, як використовувати Kling Videos Generation API для генерації відео шляхом введення тексту підказки та еталонного зображення першого кадру. Сподіваємося, цей документ допоможе вам краще інтегрувати та використовувати цей API. Якщо у вас виникнуть будь-які запитання, будь ласка, будь-коли звертайтеся до нашої команди технічної підтримки.

### Kling 3.0 Turbo

`model="kling-v3-turbo"` підтримує генерацію відео з тексту та генерацію відео з зображення першого кадру, тривалістю цілих 3–15 секунд. `mode="std"` виводить 720p, `mode="pro"` виводить 1080p. Ця модель має вбудоване нативне аудіо й не надає перемикача для його вимкнення; пропустіть `generate_audio` або встановіть його значення на `true`. Ця модель не підтримує останній кадр, об’єкти руху камери, окремі негативні підказки або `cfg_scale`. Будь ласка, безпосередньо опишіть у `prompt` вміст, який потрібно або якого слід уникати.

### Багатокадрове відео

`kling-v3` і `kling-v3-omni` підтримують `multi_shot=true`. `shot_type="intelligence"` автоматично розбиває сцени відповідно до `prompt`; `shot_type="customize"` надає 1–6 сцен через `multi_prompt`, кожен елемент містить `index`, що безперервно зростає з 1, `prompt` до 512 символів і ціле `duration` щонайменше 1 секунду. Сума тривалостей усіх сцен має дорівнювати загальному `duration`. Налаштовані сцени не використовують глобальний `prompt`. Багатокадрові відео тарифікуються відповідно до вибраної моделі, якості зображення, конфігурації аудіо та загальної тривалості.
