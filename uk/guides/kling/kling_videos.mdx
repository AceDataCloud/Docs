У цьому документі представлено інструкцію зі інтеграції Kling Videos Generation API, який дозволяє генерувати офіційні відео Kling шляхом введення користувацьких параметрів.

## Процес подачі заявки

Щоб використовувати API, спочатку потрібно подати заявку на відповідну послугу на сторінці [Kling Videos Generation API](https://platform.acedata.cloud/documents/3b921a16-a411-4557-8335-53f21d3f9e46). Після переходу на сторінку натисніть кнопку «Acquire», як показано на зображенні:

![](https://cdn.acedata.cloud/q6ytrc.png)

Якщо ви ще не увійшли або не зареєстровані, система автоматично перенаправить вас на сторінку входу для реєстрації та авторизації. Після входу ви повернетесь на поточну сторінку.

При першій подачі заявки надається безкоштовний ліміт для використання API.

## Основне використання

Спочатку ознайомтесь із базовим способом використання: введіть підказку `prompt`, дію генерації `action`, URL початкового зображення `start_image_url` та модель `model`, щоб отримати оброблений результат. Спочатку потрібно передати поле `action` зі значенням `text2video`. Воно включає три типи дій: генерація відео з тексту (`text2video`), генерація відео з зображення (`image2video`) та розширення відео (`extend`). Також потрібно вказати модель `model`. Наразі доступні моделі: `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-video-o1`. Деталі наведені нижче:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Тут ми встановили заголовки запиту (Request Headers), зокрема:

- `accept`: формат бажаної відповіді, тут вказано `application/json` (JSON формат).
- `authorization`: ключ для виклику API, який можна вибрати зі списку після подачі заявки.

Також встановлено тіло запиту (Request Body), яке містить:

- `model`: модель для генерації відео, серед яких `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-video-o1`.
- `mode`: режим генерації відео, доступні значення: стандартний `std`, швидкий `pro` та рідний 4K `4k`. Режим `4k` підтримується лише моделями `kling-v3` та `kling-v3-omni` і не сумісний із `camera_control` (керування камерою).
- `action`: дія генерації відео, включає три варіанти: генерація відео з тексту (`text2video`), генерація відео з зображення (`image2video`), розширення відео (`extend`).
- `start_image_url`: URL початкового зображення, обов’язковий для дії `image2video`.
- `end_image_url`: необов’язковий URL кінцевого кадру для дії `image2video`.
- `duration`: тривалість відео в секундах. Моделі `kling-v3` та `kling-v3-omni` підтримують гнучку тривалість від 3 до 15 секунд (цілі числа), інші моделі — 5 або 10 секунд.
- `generate_audio`: чи генерувати аудіо одночасно, необов’язковий булевий параметр. Підтримується моделями `kling-v3`, `kling-v3-omni` та `kling-v2-6` (тільки у режимі `pro`). За замовчуванням `false`.
- `aspect_ratio`: співвідношення сторін відео, необов’язковий параметр, підтримує `16:9`, `9:16`, `1:1`, за замовчуванням `16:9`.
- `cfg_scale`: інтенсивність відповідності, діапазон [0,1], чим більше, тим точніше відповідність підказці.
- `camera_control`: необов’язковий параметр для керування рухом камери, підтримує типи `type/simple` та налаштування `horizontal`, `vertical`, `pan`, `tilt`, `roll`, `zoom` тощо.
- `negative_prompt`: необов’язковий зворотний підказка, що описує небажані елементи, максимум 200 символів.
- `element_list`: список основних елементів, застосовується лише для моделі `kling-video-o1`. Деталі використання див. у [офіційній документації](https://docs.qingque.cn/d/home/eZQAyImcbaS0fz-8ANjXvU5ed?identityId=1oEG9JKKMFv#section=h.5t7wme23nn6z).
- `video_list`: список референсних відео через URL, застосовується лише для моделі `kling-video-o1`. Деталі див. у [офіційній документації](https://docs.qingque.cn/d/home/eZQAyImcbaS0fz-8ANjXvU5ed?identityId=1oEG9JKKMFv#section=h.5t7wme23nn6z).
- `prompt`: текстова підказка.
- `callback_url`: URL для отримання зворотного виклику.

Якщо потрібно згенерувати код для інтеграції, його можна скопіювати безпосередньо. Наприклад, CURL-запит:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v1",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Функція розширення відео

Якщо потрібно продовжити генерацію вже створеного Kling відео, встановіть параметр `action` у значення `extend` та введіть ID відео, яке потрібно продовжити. ID відео можна отримати за базовим використанням, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Тут ID відео:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Зверніть увагу, що `video_id` — це ID згенерованого відео. Якщо ви не знаєте, як згенерувати відео, зверніться до розділу базового використання.

Далі потрібно вказати підказку для продовження генерації відео, а також такі параметри:

- `model`: модель генерації відео, доступні `kling-v1`, `kling-v1-5`, `kling-v1-6`.
- `mode`: режим генерації відео, стандартний `std`, швидкий `pro` або 4K `4k` (4K підтримується лише `kling-v3` та `kling-v3-omni` і не сумісний із керуванням камерою).
- `duration`: тривалість відео, 5 або 10 секунд.
- `start_image_url`: URL початкового зображення для дії `image2video`.
- `prompt`: текстова підказка.

Приклад заповнення:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Після заповнення автоматично згенеровано код:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Відповідний Python-код:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

При запуску отримаємо результат:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7822108635/extendVideo/Cjil4mfBfs0AAAAAAKhr6A-0_raw_video_1.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```

Результат аналогічний попередньому, що реалізує функцію розширення відео.

## Асинхронний зворотний виклик

Оскільки генерація відео у Kling Videos Generation API займає приблизно 1-2 хвилини, а HTTP-запит може довго утримувати з’єднання, що призводить до додаткового навантаження на систему, API підтримує асинхронний зворотний виклик (callback).

Процес: клієнт при відправці запиту вказує поле `callback_url`. Після отримання запиту API одразу повертає відповідь з полем `task_id`, що ідентифікує завдання. Коли завдання завершиться, результат у форматі POST JSON буде надіслано на вказаний `callback_url`, включно з полем `task_id` для зв’язку результату із завданням.

Розглянемо приклад.

Webhook callback — це HTTP-сервіс, здатний приймати запити. Розробник повинен замінити URL на власний сервер. Для демонстрації використаємо публічний сервіс https://webhook.site/, де можна отримати унікальний Webhook URL, як показано на зображенні:

![](https://cdn.acedata.cloud/tbcnai.png)

Скопіюйте цей URL, наприклад `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, і використовуйте його як Webhook.

Далі встановіть у полі `callback_url` цей URL та заповніть інші параметри, як показано:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Після запуску одразу отримаємо відповідь:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Через деякий час на сторінці `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3` з’явиться результат генерації відео:

![](https://cdn.acedata.cloud/zv5u2q.png)

Зміст:

```json

    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7822108635/text2video/CjJzzGfBfqcAAAAAAKdVMQ-0_raw_video_1.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"

```

У відповіді є поле `task_id`, інші поля аналогічні попереднім. За допомогою `task_id` можна зв’язати результат із завданням.

## Обробка помилок

При виклику API у разі помилки повертаються відповідні коди та повідомлення, наприклад:

- `400 token_mismatched`: некоректний запит, можливо, через відсутність або неправильні параметри.
- `400 api_not_implemented`: некоректний запит, можливо, через відсутність або неправильні параметри.
- `401 invalid_token`: неавторизований, недійсний або відсутній токен авторизації.
- `429 too_many_requests`: перевищено ліміт запитів.
- `500 api_error`: внутрішня помилка сервера.
