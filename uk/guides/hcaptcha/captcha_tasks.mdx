У цьому документі описується API для асинхронного запиту завдань з перевіркою `POST /captcha/tasks`. Коли ви викликаєте будь-який API для перевірки (серії токенів або серії розпізнавання) з параметром `async: true`, API негайно повертає `task_id`, після чого ви можете використовувати цей `task_id` для опитування цього API для отримання остаточного результату. Підходить для сценаріїв з ротацією декількох розпізнавачів (multi-solver rotation): після подання завдання ви відразу отримуєте `task_id`, спочатку викликаєте інших розпізнавачів, а потім повертаєтеся за результатом.

> 📘 Повна інтерактивна документація (включаючи онлайн налагодження): [API для запиту завдань з перевіркою →](https://platform.acedata.cloud/documents/captcha-tasks)

## Процес подання заявки

Щоб використовувати цей API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications) для отримання вашого API токена, залиште його на випадок потреби. **Один API токен може використовуватися для виклику всіх сервісів платформи, не потрібно окремо запитувати для кожного сервісу.**

## Основне використання

### Перший крок: створення завдання асинхронно

У тілі запиту до будь-якого API для перевірки передайте `async: true`, API негайно поверне `task_id` (HTTP 201), не блокуючи очікування:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

### Другий крок: опитування результату за допомогою task_id

Використовуйте `task_id`, отриманий на попередньому кроці, для опитування `POST /captcha/tasks` (рекомендується кожні 3~5 секунд):

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Під час обробки буде повернуто `status: processing`:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "processing"
}
```

Після завершення обробки буде повернуто `status: ready` та відповідні поля результату — структура полів повністю відповідає синхронному режиму:

- **серія токенів** (hcaptcha, recaptcha2, recaptcha3) повертає `token`:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "started_at": 1784885653.0,
  "finished_at": 1784885665.4,
  "elapsed": 12.4,
  "token": "03AFcWeA5kjJyDQ9S1a9UYimR6nuxnpEnAs5x2Pixao0dXZhMB......"
}
```

- **категорія розпізнавання** (recognition/recaptcha2, recognition/hcaptcha) повертає `solution`; **recognition/image2text** повертає `text`.

`/captcha/tasks` є універсальним для всіх API перевірки (серії токенів та розпізнавання), можна використовувати один і той же `task_id` для опитування.

Відповідь з `status: ready` також міститиме поля часу.

- `started_at`, час початку обробки завдання, Unix-мітка часу (секунди, з плаваючою комою).
- `finished_at`, час отримання результату завдання, Unix-мітка часу (секунди, з плаваючою комою). Якщо обробка ще триває, це поле не повертається.
- `elapsed`, час обробки завдання, одиниця виміру — секунди (з плаваючою комою, з 3 знаками після коми). Якщо обробка ще триває, це поле не повертається.

## Інформація про тарифи

В асинхронному режимі створення завдання та опитування «в обробці» не підлягають оплаті; **оплата стягується лише один раз при успішному отриманні результату** (ціна така ж, як у синхронному режимі). Тому скасування ще не завершених завдань під час ротації не призведе до витрат.

## Обробка помилок

При виклику цього API, якщо виникає помилка, буде повернуто відповідний код помилки та інформацію. Наприклад:

- `400 invalid_request`: запит не містить параметра `task_id`.
- `401 invalid_token`: несанкціоновано, токен авторизації недійсний або відсутній.
- `404 not_found`: `task_id` не існує або не належить поточному обліковому запису.

### Приклад відповіді з помилкою

```json
{
  "success": false,
  "error": {
    "code": "not_found",
    "message": "task not found"
  }
}
```
