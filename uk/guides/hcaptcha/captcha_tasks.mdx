У цій статті описано інтерфейс асинхронного запиту завдань капчі `POST /captcha/tasks`. Коли ви викликаєте будь-який інтерфейс капчі (серії token або recognition) з параметром `async: true`, інтерфейс одразу повертає `task_id`, після чого можна використовувати цей `task_id` для опитування цього інтерфейсу і отримання кінцевого результату. Підходить для сценаріїв з ротацією декількох розпізнавачів (multi-solver rotation): після відправки завдання ви одразу отримуєте `task_id`, спочатку виконуєте розподіл на інші розпізнавачі, а пізніше повертаєтесь за результатом.

> 📘 Повна інтерактивна документація (з онлайн-тестуванням): [API запиту завдань капчі →](https://platform.acedata.cloud/documents/captcha-tasks)

## Процес отримання доступу

Щоб користуватися цим інтерфейсом, спочатку отримайте ваш API Token у [Ace Data Cloud консолі](https://platform.acedata.cloud/console/applications) для подальшого використання. **Один API Token дозволяє викликати всі сервіси платформи, не потрібно отримувати окремий для кожного сервісу.**

## Основне використання

### Крок 1: створення завдання в асинхронному режимі

У тілі запиту будь-якого інтерфейсу капчі передайте `async: true`, інтерфейс одразу поверне `task_id` (HTTP 201), не блокуючи очікування:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

### Крок 2: опитування результату за task_id

Використовуйте `task_id`, отриманий на попередньому кроці, для опитування `POST /captcha/tasks` (рекомендується кожні 3–5 секунд):

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Під час обробки повертається `status: processing`:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "processing"
}
```

Після завершення обробки повертається `status: ready` та відповідні поля результату — структура полів повністю збігається з синхронним режимом:

- Серія **token** (hcaptcha, recaptcha2, recaptcha3) повертає `token`:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "started_at": 1784885653.0,
  "finished_at": 1784885665.4,
  "elapsed": 12.4,
  "token": "03AFcWeA5kjJyDQ9S1a9UYimR6nuxnpEnAs5x2Pixao0dXZhMB......"
}
```

- Категорія **recognition** (recognition/recaptcha2, recognition/hcaptcha) повертає `solution`; **recognition/image2text** повертає `text`.

`/captcha/tasks` універсальний для всіх інтерфейсів капчі (серії token і recognition), опитування виконується одним і тим самим `task_id`.

Якщо завдання не вдається виконати в межах допустимого часу, повертається HTTP 504. Цей статус є кінцевим, клієнт повинен припинити опитування; повторні запити з тим самим `task_id` стабільно повертають однаковий результат з помилкою:

```json
{
  "detail": "The captcha task timed out.",
  "code": "timeout",
  "success": false,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "failed",
  "started_at": 1784885653.0,
  "finished_at": 1784885765.4,
  "elapsed": 112.4
}
```

Відповіді з кінцевим статусом `status: ready` та HTTP 504 містять поля часу.

- `started_at` — час початку обробки завдання, Unix timestamp (секунди, з плаваючою точкою).
- `finished_at` — час отримання результату, Unix timestamp (секунди, з плаваючою точкою). Якщо завдання ще обробляється, це поле відсутнє.
- `elapsed` — час обробки завдання в секундах (з плаваючою точкою, з точністю до 3 знаків). Якщо завдання ще обробляється, це поле відсутнє.

## Інформація про тарифи

В асинхронному режимі створення завдання та опитування зі статусом «обробка» не тарифікуються; **плата стягується лише один раз при успішному отриманні результату** (за тією ж ціною, що і в синхронному режимі). HTTP 504 як кінцева помилка також не тарифікується. Тому скасування незавершених завдань під час ротації або їх остаточний провал не призводить до нарахування плати.

## Обробка помилок

При виклику цього інтерфейсу у разі помилки повертаються відповідні коди та повідомлення. Наприклад:

- `400 invalid_request`: у запиті відсутній параметр `task_id`.
- `401 invalid_token`: неавторизовано, токен авторизації недійсний або відсутній.
- `404 not_found`: `task_id` не існує або не належить поточному акаунту.
- `504 timeout`: завдання завершено з помилкою тайм-ауту; припиніть опитування цього `task_id`. Ця помилка не тарифікується.

### Приклад відповіді з помилкою

```json
{
  "success": false,
  "error": {
    "code": "not_found",
    "message": "task not found"
  }
}
```
