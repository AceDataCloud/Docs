Kimi — це серія AI-моделей, запущена Moonshot AI. Наразі рекомендовано `kimi-k3.1-pro`, що підходить для тривалого програмування, складних міркувань, візуального розуміння та роботи зі знаннями; `kimi-k3` все ще можна використовувати. Викликається через сумісний з OpenAI Chat Completions API.

Цей документ переважно описує процес використання операцій Kimi Chat Completion API, за допомогою якого ми можемо легко використовувати офіційну функцію діалогу Kimi.

## Процес подання заявки

Щоб використовувати Kimi Chat Completion API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token і зберегти його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, немає потреби подавати заявку окремо для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт для безкоштовного ознайомлення; коли ліміту недостатньо, можна поповнити універсальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Базове використання

Далі можна заповнити відповідний вміст в інтерфейсі, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

Під час першого використання цього інтерфейсу потрібно заповнити щонайменше три поля: `authorization` можна безпосередньо вибрати зі спадного списку; `model` використовується для вибору моделі Kimi, рекомендовано використовувати `kimi-k3.1-pro`; `messages` — це масив повідомлень діалогу, кожне повідомлення містить `role` і `content`, де `role` підтримує `user`, `assistant`, `system` і `tool`.

Водночас ви можете помітити, що праворуч генерується відповідний код виклику, ви можете скопіювати код і безпосередньо запустити його або безпосередньо натиснути кнопку «Try» для тестування.

<p><img src="https://cdn.acedata.cloud/six7e3.png" width="400" className="m-auto" /></p>

Нижче наведено реальну відповідь K3, отриману з використанням `reasoning_effort: max` (невикористані розширені поля пропущено):

```json
{
  "id": "msg_2D4Btbg1WgvkNE3tCYkR4xGA",
  "object": "chat.completion",
  "created": 1784466588,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 86,
    "completion_tokens": 206,
    "total_tokens": 292
  }
}
```

Результат, що повертається, містить кілька полів, описаних нижче:

- `id` — ID згенерованого завдання цього діалогу, що використовується для унікальної ідентифікації цього завдання діалогу.
- `model ` — вибрана офіційна модель Kimi.
- `choices` — інформація про відповідь, надану Kimi на запит.
- `usage `: статистична інформація щодо токенів для цієї пари запитання-відповідь.

Серед них `choices` містить інформацію про відповідь Kimi, а `choices` всередині нього — конкретну інформацію про відповідь Kimi, як можна побачити на зображенні.

<p><img src="https://cdn.acedata.cloud/tv9rul.png" width="400" className="m-auto" /></p>

Можна побачити, що поле `content` у `choices` містить конкретний вміст відповіді Kimi; K3 також може повертати `reasoning_content`, що використовується для відображення процесу міркування.

## Інтенсивність міркування K3.1 Pro

`kimi-k3.1-pro` завжди вмикає міркування. У верхньому рівні тіла запиту можна встановити `reasoning_effort` як `low`, `high` або `max`; не передавайте конфігурацію для вимкнення міркування. Модель підтримує контекст до 1,048,576 токенів, але фактичне обмеження запиту все ще залежить від поточного інтерфейсу. Ціна розраховується за використанням вхідних даних, вихідних даних і влучань у кеш, докладніше дивіться в картці Pricing у каталозі моделей.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Наведені нижче приклади K3 збережено для наявних інтеграцій, а приклади відповідей справді отримано із запитів K3.

## Інтенсивність міркування K3

`kimi-k3` завжди вмикає міркування. Верхній рівень тіла запиту підтримує поле `reasoning_effort`, єдине наразі підтримуване значення — `max`; якщо це поле пропущено, також використовується `max`. `standard`, `high` або інші рядки можуть бути поблажливо прийняті деякими сумісними апстрімами, але не гарантують зміни поведінки міркування, не покладайтеся на це.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

Під час використання OpenAI SDK це поле можна передати безпосередньо:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

Під час багатораундових діалогів і викликів інструментів передавайте повне повідомлення assistant з попереднього раунду назад у `messages`, включно з `reasoning_content` і `tool_calls`.

### Офіційні посилання

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort): пояснює, що Kimi K3 завжди вмикає міркування, а єдине наразі підтримуване значення `reasoning_effort` — `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview): порівнює параметри міркування, контекстні вікна та відмінності викликів інструментів серій K3 і K2.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat): офіційні запити, відповіді та визначення полів OpenAPI для Chat Completions від Moonshot.

## Потокова відповідь

Цей інтерфейс також підтримує потокові відповіді, що дуже корисно для інтеграції з вебсторінками та дозволяє реалізувати на вебсторінці ефект посимвольного відображення.

Якщо потрібно повертати відповідь потоково, можна змінити параметр `stream ` у заголовку запиту на `true`.

Зміни показано на зображенні, але код виклику потребує відповідних змін для підтримки потокової відповіді.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>

Після зміни `stream` на `true` API повертатиме відповідні JSON-дані рядок за рядком, а на рівні коду потрібно внести відповідні зміни, щоб отримувати результати рядок за рядком.

Приклад коду виклику Python:
```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Нижче наведено фрагменти початкового, міркувального, основного, завершального блоків і блоку даних про використання з однієї реальної потокової відповіді K3 Max:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Можна побачити, що у відповіді є багато `data`, а `choices` всередині `data` є найновішим вмістом відповіді, що узгоджується з вмістом, описаним вище. `choices` — це доданий вміст відповіді, який ви можете інтегрувати у свою систему відповідно до результату. Водночас завершення потокової відповіді визначається за вмістом `data`: якщо вмістом є `[DONE]`, це означає, що відповідь потокової відповіді повністю завершена. Повернутий результат `data` має кілька полів, описаних нижче:

- `id` — ID завдання генерації цього діалогу, що використовується для унікальної ідентифікації цього завдання діалогу.
- `model ` — вибрана модель Kimi з офіційного сайту.
- `choices` — інформація відповіді, надана Kimi на запит.

JavaScript також підтримується, наприклад, код потокового виклику Node.js наведено нижче:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Приклад коду Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Інші мови можна додатково адаптувати самостійно, принципи однакові.

## Багатораундовий діалог

Якщо ви хочете інтегрувати функцію багатораундового діалогу, потрібно передати кілька запитів у полі `messages`, конкретний приклад кількох запитів показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Передавши кілька запитів, можна легко реалізувати багатораундовий діалог. Нижче наведено реальну відповідь K3 Max, отриману цим запитом (невикористовувані розширені поля опущено):

```json
{
  "id": "msg_Rqp8nPGBDHWwBlL4VpxuafOp",
  "object": "chat.completion",
  "created": 1784466628,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "I’m Kimi, an AI assistant developed by Moonshot AI (月之暗面). I don’t have a specific public model version identifier to share from here."
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 134,
    "completion_tokens": 346,
    "total_tokens": 480
  }
}
```

Можна побачити, що інформація, яку містить `choices`, узгоджується з вмістом базового використання; вона містить конкретний вміст відповіді Kimi на кілька діалогів, тож можна відповідати на відповідні запитання на основі вмісту кількох діалогів.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Забагато запитів, ви перевищили ліміт частоти.
- `500 api_error`：Внутрішня помилка сервера, на сервері щось пішло не так.
