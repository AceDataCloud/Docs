Kimi — це серія моделей штучного інтелекту, розроблена компанією Moonshot AI. Наразі рекомендованою моделлю є `kimi-k3.1-pro`, яка підходить для довготривалого програмування, складних міркувань, візуального розуміння та роботи зі знаннями; `kimi-k3` також залишається доступною. Виклик здійснюється через API Chat Completions, сумісний з OpenAI.

У цьому документі переважно описано процес використання Kimi Chat Completion API, за допомогою якого ми можемо легко використовувати офіційні можливості діалогової взаємодії Kimi.

## Підтримувані моделі

Наразі підтримуються чотири моделі: `kimi-k3.1-pro`, `kimi-k3`, `kimi-k2.6` та `kimi-k2.7-code`. K2.7 Code призначена для сценаріїв програмування та виклику інструментів, а її вартість обчислюється за тарифами того самого рівня, що й K2.6; не передавайте для неї параметр `thinking` або `reasoning_effort`. Підтримку інших моделей Kimi припинено, тому явно виберіть одну з цих чотирьох моделей у клієнті.

## Процес подання заявки

Щоб використовувати Kimi Chat Completion API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати свій API Token і зберегти його для подальшого використання.

**Одного API Token достатньо для виклику всіх сервісів платформи, немає потреби подавати окрему заявку для кожного сервісу.** Під час першого подання заявки надається безкоштовний ліміт, який можна використати для ознайомлення із сервісом; коли ліміт буде вичерпано, ви можете поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

## Основне використання

Далі ви можете заповнити відповідні поля в інтерфейсі, як показано на рисунку:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

Під час першого використання цього інтерфейсу необхідно заповнити щонайменше три поля: `authorization` можна безпосередньо вибрати зі спадного списку; `model` використовується для вибору моделі Kimi, рекомендовано використовувати `kimi-k3.1-pro`; `messages` — це масив повідомлень діалогу, кожне з яких містить `role` і `content`, причому `role` підтримує значення `user`, `assistant`, `system` і `tool`.

Водночас ви можете помітити, що праворуч автоматично генерується відповідний код виклику. Ви можете скопіювати код і безпосередньо запустити його або натиснути кнопку «Try», щоб виконати тестування.

<p><img src="https://cdn.acedata.cloud/six7e3.png" width="400" className="m-auto" /></p>

Нижче наведено реальну відповідь K3, отриману за допомогою `reasoning_effort: max` (невикористані додаткові поля пропущено):

```json
{
  "id": "msg_2D4Btbg1WgvkNE3tCYkR4xGA",
  "object": "chat.completion",
  "created": 1784466588,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 86,
    "completion_tokens": 206,
    "total_tokens": 292
  }
}
```

Результат містить декілька полів, опис яких наведено нижче:

- `id` — ID, згенерований для цього завдання діалогу, використовується для його унікальної ідентифікації.
- `model ` — модель з офіційного сайту Kimi, яку було вибрано.
- `choices` — інформація про відповідь Kimi на запитання.
- `usage `: статистична інформація про кількість токенів, використаних під час цього запитання та відповіді.

Серед них `choices` містить інформацію про відповідь Kimi, а вкладене в нього поле `choices` містить конкретні відомості про відповідь Kimi, як можна побачити на рисунку.

<p><img src="https://cdn.acedata.cloud/tv9rul.png" width="400" className="m-auto" /></p>

Як бачимо, поле `content` усередині `choices` містить конкретний текст відповіді Kimi; K3 також може повертати `reasoning_content`, який використовується для відображення процесу міркування.

## Рівень інтенсивності міркування K3.1 Pro

`kimi-k3.1-pro` завжди використовує режим міркування. У верхньому рівні тіла запиту можна встановити `reasoning_effort` у значення `low`, `high` або `max`; не передавайте конфігурацію, яка вимикає міркування. Модель підтримує контекстне вікно обсягом до 1,048,576 токенів, але фактичне обмеження запиту все одно залежить від поточного API. Вартість розраховується відповідно до використання вхідних, вихідних токенів і токенів із кешу; докладніше дивіться картку Pricing у каталозі моделей.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Наведений нижче приклад K3 збережено для наявних інтеграцій, а приклад відповіді дійсно отримано за допомогою запиту до K3.

## Рівень інтенсивності міркування K3

`kimi-k3` завжди використовує режим міркування. У верхньому рівні тіла запиту підтримується поле `reasoning_effort`, єдиним наразі підтримуваним значенням якого є `max`; якщо це поле пропущено, також використовується `max`. Будь ласка, використовуйте підтримуване значення.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

Під час використання OpenAI SDK це поле можна передавати безпосередньо:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

Під час багатокрокового діалогу та виклику інструментів передавайте до `messages` повне повідомлення assistant із попереднього раунду, включно з `reasoning_content` і `tool_calls`.

### Офіційні довідкові матеріали

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort)：пояснює, що Kimi K3 завжди використовує режим міркування, а єдиним наразі підтримуваним значенням `reasoning_effort` є `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview)：порівнює параметри міркування, розміри контекстних вікон і відмінності у виклику інструментів між серіями K3 та K2.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat)：офіційне визначення Moonshot для запитів і відповідей Chat Completions, а також полів OpenAPI.

## Потокова відповідь

Цей інтерфейс також підтримує потокові відповіді, що дуже корисно для інтеграції з вебсторінками та дає змогу реалізувати ефект поступового відображення тексту на вебсторінці.

Якщо ви хочете отримувати потокову відповідь, змініть параметр `stream ` у заголовку запиту на `true`.

Зміни показано на рисунку, проте для підтримки потокових відповідей необхідно також відповідним чином змінити код виклику.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>
Після зміни `stream` на `true` API повертатиме відповідні дані JSON рядок за рядком. На рівні коду нам потрібно внести відповідні зміни, щоб отримувати результати по рядках.

Приклад виклику Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Нижче наведено фрагменти початкового, проміжного, основного, завершального блоків і блоків із даними про використання з реальної потокової відповіді K3 Max за один і той самий запит:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Як можна побачити, у відповіді є багато об'єктів `data`, а `choices` усередині `data` містить найновіший фрагмент відповіді, що відповідає опису вище. `choices` містить новий фрагмент відповіді, який ви можете використовувати для інтеграції зі своєю системою. Водночас завершення потокової відповіді визначається за вмістом `data`: якщо його значення дорівнює `[DONE]`, це означає, що потокова відповідь повністю завершена. Повернений об'єкт `data` містить кілька полів, описаних нижче:

- `id` — ID завдання цієї розмови, який використовується для її унікальної ідентифікації.
- `model ` — модель офіційного вебсайту Kimi, яку було вибрано.
- `choices` — інформація про відповідь Kimi на запит.

JavaScript також підтримується. Наприклад, код потокового виклику в Node.js виглядає так:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Приклад коду Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Код для інших мов програмування можна переписати самостійно — принцип залишається незмінним.

## Багатоетапна розмова

Якщо ви хочете інтегрувати функцію багатоетапної розмови, потрібно передати кілька запитів у полі `messages`. Конкретний приклад передавання кількох запитів наведено на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Приклад виклику Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Передавши кілька запитів, ви можете легко реалізувати багатоетапну розмову. Нижче наведено реальну відповідь K3 Max, отриману на цей запит (невикористані додаткові поля пропущено):

```json
{
  "id": "msg_Rqp8nPGBDHWwBlL4VpxuafOp",
  "object": "chat.completion",
  "created": 1784466628,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "I’m Kimi, an AI assistant developed by Moonshot AI (月之暗面). I don’t have a specific public model version identifier to share from here."
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 134,
    "completion_tokens": 346,
    "total_tokens": 480
  }
}
```

Як можна побачити, інформація, що міститься в `choices`, відповідає опису базового використання. Вона містить конкретну відповідь Kimi на кілька повідомлень діалогу, що дає змогу відповідати на запитання з урахуванням вмісту всієї розмови.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API повертає відповідний код і повідомлення про помилку. Наприклад:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.
