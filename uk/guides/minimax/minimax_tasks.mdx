Цей документ описує інтеграцію та використання API запиту завдань MiniMax H3. Цей інтерфейс використовується для запиту, масового переліку або видалення асинхронних завдань, створених [MiniMax H3 API для генерації відео](/documents/minimax-videos-integration).

## Процес подачі заявки

Щоб використовувати API запиту завдань MiniMax H3, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token, зберігши його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли в систему або не зареєстровані, вас автоматично перенаправлять на сторінку входу, запрошуючи вас зареєструватися та увійти, після чого ви будете автоматично повернені на цю сторінку.

**Один API Token дозволяє викликати всі послуги платформи, не потрібно окремо подавати заявку на кожну послугу.** Перший запит на отримання токена надає безкоштовний ліміт, щоб ви могли безкоштовно протестувати; при недостатньому ліміті ви можете поповнити загальний баланс в [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [API запиту завдань MiniMax H3 →](https://platform.acedata.cloud/documents/minimax-tasks-integration)

При запиті завдання слід використовувати той самий токен, що й для створення цього завдання. Рекомендується зберігати токен як змінну середовища, не записуючи його в код або не відправляючи в репозиторій:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Огляд інтерфейсу

- **Базовий URL**: `https://api.acedata.cloud`
- **Кінцева точка**: `POST /minimax/tasks`
- **Метод аутентифікації**: HTTP Header містить `authorization: Bearer {token}`
- **Заголовки запиту**:
  - `accept: application/json`
  - `content-type: application/json`
- **Запит одного завдання**: `action=retrieve`, передати `id`
- **Масовий запит завдань**: `action=retrieve_batch`, можна фільтрувати за ID завдання, часовими рамками та умовами пагінації
- **Видалення завдання**: `action=delete`, передати `id`
- **Опис тарифікації**: Запит завдань безкоштовний, не призводить до повторної тарифікації

Після створення відео необхідно зберегти `task_id`. Рекомендується запитувати кожні приблизно 10 секунд, поки завдання не перейде в кінцевий стан.

## Параметри запиту

| Параметр             | Тип       | Обов'язковий | Доступні дії            | Опис                                                   |
| ------------------- | -------- | ------------ | --------------------- | ---------------------------------------------------- |
| `action`            | string   | Ні           | Всі                   | `retrieve`, `retrieve_batch` або `delete`; за замовчуванням `retrieve` |
| `id`                | string   | Умовно обов'язковий | `retrieve`, `delete` | ID одного завдання                                      |
| `ids`               | string[] | Ні           | `retrieve_batch`      | Повертає лише вказані ID завдань; при пропуску перераховує завдання за іншими умовами                              |
| `limit`             | integer  | Ні           | `retrieve_batch`      | Максимальна кількість завдань, що повертаються цього разу                                          |
| `offset`            | integer  | Ні           | `retrieve_batch`      | Кількість завдань, які потрібно пропустити з списку результатів, для пагінації                                   |
| `created_at_min`    | number   | Ні           | `retrieve_batch`      | Нижня межа часу створення, Unix-мітка часу, в секундах                                 |
| `created_at_max`    | number   | Ні           | `retrieve_batch`      | Верхня межа часу створення, Unix-мітка часу, в секундах                                 |

Три дії мають такі призначення:

| `action`            | Призначення                       | Обов'язкові параметри                  | Структура відповіді                                  |
| ------------------- | -------------------------------- | ------------------------------------- | ------------------------------------------------- |
| `retrieve`          | Запитати стан і результат одного завдання | `id`                                 | `{ "task": {...} }`                               |
| `retrieve_batch`    | Масовий запит за ID завдань, часом і умовами пагінації | Можливі `ids`, часові рамки, `offset`, `limit` | `{ "items": [...], "total": number }`            |
| `delete`            | Скасувати або видалити запис завдання за його поточним станом | `id`                                 | `{ "id": "...", "deleted": true }`               |

  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve",

## Статус завдання

| `status`     | Значення         | Обробка на клієнті                  |
| ------------ | ---------------- | ---------------------------------- |
| `queued`     | Завдання в черзі, чекає виконання | Продовжувати опитування               |
| `running`    | Виконується       | Продовжувати опитування               |
| `succeeded`  | Успішно виконано   | Зчитати `task.content.url`, зупинити опитування |
| `failed`     | Виконання не вдалося | Зчитати `task.error`, зупинити опитування       |
| `cancelled`  | Завдання скасовано  | Зупинити опитування               |

`succeeded`, `failed` і `cancelled` є кінцевими станами. Не продовжуйте опитування після досягнення кінцевого стану.

## Поля відповіді task

| Поле                        | Тип      | Опис                              |
| ------------------------- | ------- | ------------------------------- |
| `id`                      | string  | ID завдання                       |
| `model`                   | string  | Модель, що використовується для завдання, наразі `MiniMax-H3`        |
| `status`                  | string  | Поточний статус завдання              |
| `error.code`              | string  | Код помилки при невдачі, повертається лише при невдачі                    |
| `error.message`           | string  | Причина невдачі, повертається лише при невдачі                     |
| `created_at`              | integer | Час створення, Unix-мітка часу, в секундах              |
| `updated_at`              | integer | Час останнього оновлення статусу, Unix-мітка часу, в секундах        |
| `content.url`             | string  | URL відео після успішного виконання                        |
| `resolution`              | string  | Вихідна роздільна здатність, `768P` або `2K`             |
| `duration`                | integer | Тривалість вихідного відео, в секундах                     |
| `usage.total_seconds`     | integer | Загальна кількість витрат, дорівнює сумі секунд вхідного та вихідного відео           |
| `usage.input_seconds`     | integer | Кількість витрат, що виникають від вхідного відео                   |
| `usage.output_seconds`    | integer | Кількість витрат, що виникають від вихідного відео                     |
| `usage.input_image_count` | integer | Кількість вхідних зображень у тарифікації                    |
| `ratio`                   | string  | Фактичне співвідношення сторін; при використанні `adaptive` слід орієнтуватися на цей результат |
| `task_type`               | string  | Тип завдання для генерації відео - `generation`            |
| `modality`                | string  | Тип завдання - `video`                   |

## Повний приклад опитування на Python
以下代码 зчитує Token з змінних середовища, після створення завдання кожні 10 секунд запитує:

```python
import os
import time

import requests

BASE_URL = "https://api.acedata.cloud"
HEADERS = {
    "Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_KEY']}",
    "Content-Type": "application/json",
}

create_response = requests.post(
    f"{BASE_URL}/minimax/videos",
    headers=HEADERS,
    json={
        "model": "MiniMax-H3",
        "content": [
            {
                "type": "text",
                "text": "Ранок на узбережжі, білий вітрильник пливе по спокійній поверхні моря, камера повільно переміщується",
            }
        ],
        "resolution": "768P",
        "duration": 4,
        "ratio": "16:9",
    },
    timeout=30,
)
create_response.raise_for_status()
task_id = create_response.json()["task_id"]

while True:
    time.sleep(10)
    query_response = requests.post(
        f"{BASE_URL}/minimax/tasks",
        headers=HEADERS,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    query_response.raise_for_status()
    task = query_response.json()["task"]
    print(f"task={task_id} status={task['status']}")

    if task["status"] == "succeeded":
        print(f"video_url={task['content']['url']}")
        break
    if task["status"] in ("failed", "cancelled"):
        raise RuntimeError(task.get("error") or task["status"])
```

Виробниче середовище повинно мати загальний тайм-аут для опитування, а також використовувати експоненціальне затримування для `429` та тимчасових `5xx`. Тайм-аут мережі не означає, що генерація не вдалася, можна використовувати той же `task_id` для продовження запитів.

## Пакетне запитування

Вказати кілька ID завдань:

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve_batch",
    "ids": ["TASK_ID_1", "TASK_ID_2"],
    "offset": 0,
    "limit": 20
  }'
```

Перегляд завдань за часовим діапазоном:

```json
{
  "action": "retrieve_batch",
  "created_at_min": 1786000000,
  "created_at_max": 1786200000,
  "offset": 0,
  "limit": 20
}
```

У пакетній відповіді `items` використовують ті ж поля task, що й у запиті одного завдання, `total` - це загальна кількість завдань, що відповідають критеріям фільтрації:

```json
{
  "items": [
    {
      "id": "TASK_ID_1",
      "model": "MiniMax-H3",
      "status": "running",
      "resolution": "2K",
      "duration": 5,
      "ratio": "adaptive",
      "task_type": "generation",
      "modality": "video"
    }
  ],
  "total": 1
}
```

Вікно запитів завдань становить останні 7 днів. `task_id`, що перевищує це вікно, може повернути недійсне завдання; бізнес-система повинна зберігати ID під час створення завдання та своєчасно зберігати URL результату після успіху.

## Скасування або видалення завдань

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "delete",
    "id": "YOUR_TASK_ID"
  }'
```

Дії залежать від поточного стану завдання:

| Поточний стан        | Дія            |
| ----------- | ------------- |
| `queued`    | Скасувати завдання, що ще не почалося     |
| `succeeded` | Видалити запис завдання        |
| `failed`    | Видалити запис завдання        |
| `running`   | Не дозволяється видаляти або скасовувати, повертає помилку |
| `cancelled` | Не дозволяється повторна операція, повертає помилку  |

Приклад успішного видалення:

```json
{
  "id": "YOUR_TASK_ID",
  "deleted": true
}
```

Видалення запису завдання не скасовує вже завершену оплату, і не гарантує, що збережена відео-копія також буде видалена.

## Відповіді про помилки та їх усунення

Завдання, що не вдалося, все ще повертають об'єкт task з HTTP 200, і в `task.error` вказується причина:

```json
{
  "task": {
    "id": "YOUR_TASK_ID",
    "model": "MiniMax-H3",
    "status": "failed",
    "error": {
      "code": "1026",
      "message": "опис відео містить чутливий контент"
    },
    "task_type": "generation",
    "modality": "video"
  }
}
```

Якщо інтерфейс повертає `400`, слід перевірити `action` та параметри, `401` означає, що Token недійсний, `429` означає, що запити надто часті, `500` означає, що служба тимчасово недоступна. Завдання, що не вдалося, не підлягають оплаті; успішні завдання обліковуються за остаточним `usage`.
