У цьому документі описується інтеграція та використання API генерації відео MiniMax H3. Цей інтерфейс підтримує генерацію відео з тексту, контроль початкових і кінцевих кадрів, а також мультимодальне посилання на відео, використовуючи єдину структуру `content` V2 для створення завдань.

## Процес подачі заявки

Щоб використовувати API генерації відео MiniMax H3, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications) для отримання вашого API Token, зберігайте його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли в систему або не зареєстровані, вас автоматично перенаправлять на сторінку входу, щоб запросити реєстрацію та вхід, після чого ви будете автоматично повернені на цю сторінку.

**Один API Token дозволяє викликати всі послуги платформи, не потрібно окремо подавати заявку на кожну послугу.** Перший запит на отримання токена надає безкоштовний ліміт, щоб ви могли безкоштовно протестувати; коли ліміт закінчиться, ви можете поповнити загальний баланс в [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [API генерації відео MiniMax H3 →](https://platform.acedata.cloud/documents/minimax-videos-integration)

Рекомендується зберігати токен як змінну середовища, не записуйте його в код або не відправляйте в репозиторій:

```bash

```

## Огляд інтерфейсу

- **Базовий URL**: `https://api.acedata.cloud`
- **Кінцева точка**: `POST /minimax/videos`
- **Метод аутентифікації**: HTTP Header містить `authorization: Bearer {token}`
- **Заголовки запиту**:
  - `accept: application/json`
  - `content-type: application/json`
- **Модель (model)**: `MiniMax-H3`
- **Вхідна структура**: передача тексту, зображень, відео та аудіо через `content`
- **Режим виходу**: за замовчуванням синхронно чекає завершення генерації та повертає повний `task`; при передачі `async: true` або `callback_url` відразу повертає `task_id` та `trace_id`
- **Перевірка результатів**: отримання статусу та готового відео через [API запиту завдань MiniMax H3](/documents/minimax-tasks-integration)
- **Асинхронний зворотний виклик**: за бажанням, отримання остаточного результату завдання через `callback_url`

Вам не потрібно передавати `action` для вибору режиму генерації, інтерфейс автоматично визначить призначення на основі типу матеріалів у `content` та `role`.

## Підходящі сценарії

| Сценарій         | Комбінація введення                  | Загальні використання                      |
| ---------- | --------------------- | ------------------------- |
| Генерація відео з тексту       | Текст                    | Рекламні ідеї, репетиція сцен, короткі відео, атмосферні кадри        |
| Генерація відео з початковим кадром     | Текст + початкове зображення             | Дайте товарним зображенням, постерам, фотографіям або ілюстраціям природно рухатися      |
| Генерація відео з кінцевим/початковим кадром | Текст + кінцеве зображення, або текст + початкове + кінцеве зображення | Контроль початку та кінця відео, переходи, зміни зростання та порівняння до і після      |
| Мультимодальна генерація відео   | Текст + зображення/відео/аудіо   | Збереження узгодженості персонажів та продуктів, відтворення дій, руху камери, тембру або ритму монтажу |

## Процес виклику

За замовчуванням, якщо не передавати `async`, `/minimax/videos` буде чекати завершення генерації та безпосередньо повертати повний `task`. Якщо потрібно негайно звільнити з'єднання, передайте `async: true` або `callback_url`:

1. Збережіть `task_id` та `trace_id` з негайної відповіді.
2. Якщо зворотний виклик не налаштовано, кожні приблизно 10 секунд викликайте `/minimax/tasks` для перевірки.
3. Коли `task.status` змінюється на `succeeded`, отримайте відео з `task.content.url`.
4. Коли статус `failed` або `cancelled`, зупиніть опитування та прочитайте `task.error`.

## Параметри запиту верхнього рівня

| Параметр             | Тип       | Обов'язковий   | Значення за замовчуванням        | Опис                                                |
| -------------- | -------- | ---- | ---------- | ------------------------------------------------- |
| `model`        | string   | Так    | -          | Фіксовано на `MiniMax-H3`                                  |
| `content`      | object[] | Так    | -          | Масив мультимодального контенту, повинен містити один непорожній `text` елемент                         |
| `resolution`   | string   | Так    | -          | `768P` або `2K`                                     |
| `duration`     | integer  | Так    | -          | Тривалість генерації, ціле число від 4 до 15 секунд                                     |
| `ratio`        | string   | Умовно обов'язковий | `adaptive` | `adaptive`, `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16` |
| `async`        | boolean  | Ні    | `false`    | `true` повертає ідентифікатор завдання негайно, результати отримуються через інтерфейс завдань                       |
| `callback_url` | string   | Ні    | -          | Публічний URL для зворотного виклику остаточного результату завдання; при наданні автоматично активує асинхронний режим                     |

Правила для `ratio` залежать від робочого процесу:

- **Генерація відео з тексту**: обов'язково, не може бути `adaptive`.
- **Генерація відео з початковим, кінцевим або початковим/кінцевим кадром**: формат визначається вхідним зображенням, рекомендується пропустити або передати `adaptive`.
- **Мультимодальна генерація відео**: може бути пропущена, за замовчуванням `adaptive`; також можна чітко вказати фіксоване співвідношення.

Інтерфейс не приймає застарілі або сумісні поля, такі як `prompt`, `image_urls`, `audio_urls`, `messages` та `first_frame_image`. При отриманні таких параметрів з помилкою, будь ласка, видаліть застарілі поля та перенесіть їх до `content`; наприклад, змініть `"prompt": "кішка махає"` на `"content": [{"type": "text", "text": "кішка махає"}]`. Не надсилайте одночасно нові та старі формати.

## Параметри елементів контенту

Кожен елемент контенту повинен мати `type`, інші поля визначаються типом:

| `type`      | Поля даних            | `role`            | Опис                                     |
| ----------- | --------------- | ----------------- | -------------------------------------- |
| `text`      | `text`          | Не передавати                | Кожен запит повинен містити один непорожній текстовий елемент, максимум 7000 символів             |
| `image_url` | `image_url.url` | `first_frame`     | Початкове зображення; якщо є лише одне зображення і `role` пропущено, також обробляється як початкове         |
| `image_url` | `image_url.url` | `last_frame`      | Кінцеве зображення; може використовуватися окремо або в комбінації з `first_frame` для контролю початку та кінця |
| `image_url` | `image_url.url` | `reference_image` | Посилання на об'єкт, персонажа, продукт, одяг, сцену або стиль                    |
| `video_url` | `video_url.url` | `reference_video` | Посилання на дії, рух камери, виконання або структуру монтажу                        |
| `audio_url` | `audio_url.url` | `reference_audio` | Посилання на тембр, діалоги, музику або ритм                          |

Адреси медіа підтримують три форми:

- Доступний через Інтернет HTTPS URL, рекомендовано для великих файлів.
- `mm_file://{file_id}`, посилання на вже завантажений або наявний файл.
- Відповідний медіа-типу Base64 data URI. Base64 збільшує обсяг приблизно на третину, будь ласка, переконайтеся, що весь запит не перевищує 64 МБ.

## Специфікації матеріалів та обмеження кількості
| Матеріал | Формат                                       | Обмеження на файл | Розмір / Тривалість                                                  | Обмеження на кількість                  |
| --- | ------------------------------------------- | --------- | --------------------------------------------------------------- | --------------------------- |
| Зображення | JPG, JPEG, PNG, WEBP, HEIC, HEIF                | Не більше 30 MB | Ширина та висота від 256 до 5760 px; співвідношення сторін 0.4-2.5 | Не більше 1 зображення для першого кадру, не більше 1 зображення для останнього кадру, не більше 9 зображень для довідки |
| Відео | MP4, MOV; H.264/AVC або H.265/HEVC; звукова доріжка AAC або MP3 | Не більше 50 MB | Кожен фрагмент 2-15 секунд, загалом не більше 15 секунд; ширина та висота від 256 до 5760 px; співвідношення сторін 0.4-2.5; 23.976-60 fps | Не більше 3 фрагментів довідкового відео |
| Аудіо | WAV, MP3                                    | Не більше 15 MB | Кожен фрагмент 2-15 секунд, загалом не більше 15 секунд                                            | Не більше 3 фрагментів довідкового аудіо |

У багатомодальних довідкових сценах загалом не більше 12 файлів зображень, відео та аудіо. Сцени з першим і останнім кадрами та довідковими матеріалами є взаємовиключними: як тільки використано `reference_image`, `reference_video` або `reference_audio`, не можна більше використовувати `first_frame` або `last_frame`, і навпаки.

## Демонстрація виробничих можливостей

Нижче наведено не концептуальні зображення або матеріали, а реальні довідкові вхідні дані та фактичний відео-вихід з офіційного зразка виробничих можливостей MiniMax H3. Три групи випадків охоплюють брендові короткометражки, реальні наративи та модну електронну комерцію, що підходять для оцінки найважливіших можливостей моделі в комерційному виробництві.

| Можливість       | Основні спостереження                  |
| -------- | --------------------------- |
| Узгодженість персонажів та обличчя | Чи стабільні риси обличчя, зачіска, макіяж та характер персонажа після зміни кадрів     |
| Вираз обличчя     | Погляд, мікровирази, емоційна напруга та природний рух голови в крупному плані      |
| Збереження структури товару   | Контури, матеріал, спосіб носіння та дзеркальне відображення таких продуктів, як окуляри, сумки тощо    |
| Виконання візуального бренду   | Чи є атмосфера сцени, кінематографічна зернистість, кольори, логотип та ритм монтажу єдині |
| Кінематографічний наратив    | Чи можуть зміни в планах, розташування персонажів, рух камери, ритм та звук утворити завершений фрагмент  |

Тут "можливості обличчя" означають узгодженість зовнішності персонажів, деталі обличчя та контроль виконання у відеогенерації, а не ідентифікацію особи, порівняння облич або інтерфейс зміни облич.

### Реклама модних окулярів: деталі обличчя та структура товару зберігаються

**Ціль виробництва:** 9:16 реклама висококласних модних окулярів. Повнофігурне зображення персонажа відповідає за фігуру та ходу, референсне зображення обличчя відповідає за риси обличчя та макіяж, зображення продукту відповідає за обводи, відображення лінз, дужки та контур котячих очей. Цей випадок одночасно перевіряє близькі плани обличчя, узгодженість кількох людей, відносини носіння та геометричну структуру товару.

У рекламі товару підказки повинні чітко розділяти обов'язки референсів персонажів та продукту: матеріали персонажів обмежують обличчя, макіяж, фігуру та харизму; матеріали продукту обмежують контури, матеріали, відображення та місце носіння. ## Текст у відео

Коли є лише один текстовий елемент, це текст у відео. Підходить для безпосереднього створення зображень з ідеї, сценарію або опису кадрів. Підказки можна організувати в порядку "суб'єкт + дія + сцена + кадр + світло + звук".

```bash
curl -X POST 'https://api.acedata.cloud/minimax/videos' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MiniMax-H3",
    "content": [
      {
        "type": "text",
        "text": "15 секунд рекламного парфуму: на чорних рифах узбережжя вранці прозорий флакон парфуму оточений туманом та хвилями. Макрозйомка демонструє краплі води на флаконі та заломлення скла, камера повільно піднімається від крупного плану продукту до широкого морського пейзажу; срібно-блакитний відтінок, природне світло, високий стриманий стиль, в кінці фіксація продукту."
      }
    ],
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }'
```

За замовчуванням синхронний режим повертає повне завдання після завершення генерації:

```json
{
  "task": {
    "id": "f5977217-ed2c-40da-adbe-93d08235618f",
    "model": "MiniMax-H3",
    "status": "succeeded",
    "content": { "url": "https://cdn.acedata.cloud/minimax/f5977217.mp4" },
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }
}
```

Якщо в запиті додати `"async": true`, інтерфейс відразу повертає:

```json
{
  "task_id": "f5977217-ed2c-40da-adbe-93d08235618f",
  "trace_id": "trace_7f8c2b1a"
}
```

## Відео з першого кадру

Позначте зображення як `first_frame`, модель почне генерувати з цього кадру. Підходить для природного анімування постерів, зображень товарів, концепт-артів та фотографій.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "Персонаж природно дихає і дивиться у вікно, краї одягу колишуться від легкого вітру, камера повільно наближається"
    },
    {
      "type": "image_url",
      "image_url": {
        "url": "https://cdn.acedata.cloud/b1c82e4937.png"
      },
      "role": "first_frame"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

## Відео з останнього кадру та першого-останніх кадрів
Тільки надання `last_frame` може дозволити моделі природно згенерувати до вказаного кадру; одночасно надаючи `first_frame` та `last_frame`, можна чітко контролювати початкову та кінцеву точки. Підходить для переходів, зміни форм, процесу зростання або порівняння продуктів до і після.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "Дівчина природно зростає з дитинства до юності, час минає плавно, персонаж завжди знаходиться в центрі кадру"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_FIRST_FRAME_URL" },
      "role": "first_frame"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_LAST_FRAME_URL" },
      "role": "last_frame"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

Розміри та співвідношення сторін першого та останнього кадрів повинні бути якомога більш схожими, позиція об'єкта, композиція та різниця в освітленні не повинні бути занадто великими, так легше досягти природного переходу.

## Багатомодальне посилання на живе відео

Посилальні матеріали можна комбінувати: посилальні зображення контролюють зовнішній вигляд персонажа або продукту, посилальні відео контролюють рухи та камеру, посилальні аудіо контролюють тембр діалогів, музику або ритм монтажу. У підказках слід чітко вказати, що має контролювати кожен тип матеріалу, щоб уникнути завантаження матеріалів без вказівки зв'язків.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "Зберігайте риси обличчя, зачіску та одяг посилального персонажа, виконуйте модний короткометражний фільм відповідно до виконання в посилальному відео; ритм кадрів слідує за посилальним аудіо, крупний план підкреслює природні вирази обличчя"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_CHARACTER_IMAGE_URL" },
      "role": "reference_image"
    },
    {
      "type": "video_url",
      "video_url": { "url": "YOUR_PERFORMANCE_VIDEO_URL" },
      "role": "reference_video"
    },
    {
      "type": "audio_url",
      "audio_url": { "url": "YOUR_AUDIO_URL" },
      "role": "reference_audio"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

## Сповіщення про зворотний виклик

Передача `callback_url` автоматично активує асинхронний режим: інтерфейс створення негайно повертає `task_id` та `trace_id`, а після завершення завдання надсилає POST з остаточним результатом на цю адресу, структура відповідає відповіді на запит завдання.

Остаточний статус у зворотному виклику може бути `succeeded`, `failed` або `cancelled`. Навіть при використанні зворотного виклику рекомендується зберігати `task_id`, щоб мати можливість активно запитувати або компенсувати пропущені сповіщення.

## Загальні помилки

| HTTP статус-код | Значення           | Рекомендації по обробці                           |
| -------- | ------------ | ------------------------------ |
| `400`    | Помилка параметрів або недійсна комбінація матеріалів | Перевірте обов'язкові поля, `role`, кількість та формат матеріалів          |
| `401`    | Відсутній або недійсний токен  | Перевірте `Authorization: Bearer ...` |
| `402`    | Недостатньо балансу або ліміту      | Поповніть загальний баланс у консолі                     |
| `422`    | Перевірка безпеки контенту не пройдена    | Відкоригуйте підказки або матеріали та повторно надішліть                  |
| `429`    | Занадто багато запитів       | Спробуйте знову після експоненційного затримки; рекомендується інтервал для опитування завдань близько 10 секунд         |
| `500`    | Сервіс тимчасово недоступний      | Збережіть інформацію про запит, спробуйте пізніше                    |

Синхронна відповідь з `task.status: succeeded` означає, що відео було згенеровано; асинхронне підтвердження лише вказує на те, що завдання потрапило в чергу. Тільки у випадку успішного завершення завдання буде стягнута плата, запит на завдання безкоштовний, повторна плата не стягуватиметься.
