`POST https://api.acedata.cloud/suno/projects` — це Beta-інтерфейс для керування багатодоріжковими проєктами. Створення, збереження, генерація кандидатів, підтвердження кандидатів та експорт розрізняються через `action`.

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: <每次写操作的新 UUID>
```

Окрім `retrieve`, **кожна операція потребує** `Idempotency-Key`. Той самий ключ із тим самим запитом лише повертає початковий результат; той самий ключ із іншим запитом повертає 409. Якщо платна генерація стикається з мережевим тайм-аутом або результат підтвердження є невизначеним, спочатку виконайте запит за початковим ID завдання або тим самим ключем ідемпотентності; не можна безпосередньо змінювати ключ і надсилати запит повторно.

## Ідентифікатори та одиниці часу

| Назва                             | Звідки отримати                                                                                      | Де використовувати                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | `data.id` у відповіді `create`                                                                      | Усі наступні запити для поточного проєкту                                      |
| `version_id`                   | `data.version_id` останнього `retrieve`, `save`, `add_track`, `commit_candidate` або `remove_track` | Зміна, генерація кандидатів та експорт; необхідно використовувати найновішу версію                              |
| `audio_id` / `source_audio_id` | `response.data.candidate.audio_id` у фінальному стані `upload` або наявний ID завершеного аудіо                                | Посилання на вихідне аудіо під час `add_track`, генерації або заміни                          |
| `render_audio_id`              | `response.data.audio_id` у фінальному стані `render`                                                       | Посилання на мікс проєкту для `generate_track`                         |
| `operation_id`                 | `response.data.operation_id` у фінальному стані `generate_track` або `replace_section`                       | `commit_candidate`; зазвичай збігається з `task_id` завдання генерації, але слід зчитувати значення з відповіді |
| `candidate_id`                 | `response.data.candidates[].id` у фінальному стані генерації                                                       | Вибір кандидата для підтвердження                                         |
| `track_id`                     | `data.state.tracks[].id` проєкту                                                                | Підтвердження кандидата або видалення доріжки                                        |
| `task_id`                      | Відповідь на подання асинхронної операції                                                                                   | Використовуйте `/suno/tasks` для запиту фінального стану; це не ID проєкту                   |

`start_seconds` / `end_seconds` — це **секунди у вихідному аудіо**; `start_beats` / `end_beats` — це **кількість ударів на часовій шкалі проєкту**. `state.timing.bps` — це кількість ударів за секунду, за замовчуванням 2. Наприклад, для фрагмента тривалістю 41 секунду, що починається з удару 0, кінцева точка за замовчуванням — удар 82. Діапазон секунд `generate_track` використовується для визначення посилання для генерації та не гарантує, що кандидат матиме довжину лише цього діапазону.

## Робочий процес операцій

| Порядок  | `action`                             | Призначення                         | Спосіб повернення         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | Створення порожнього проєкту                      | Синхронні дані проєкту       |
| 2   | `retrieve`                           | Читання найновішої версії та повного `state`          | Синхронні дані проєкту       |
| 3   | `save`                               | Перше збереження або повне збереження зміненого `state`      | Синхронні дані проєкту       |
| 4   | `upload`                             | Створення матеріалу з HTTPS-адреси аудіо           | Асинхронне завдання         |
| 5   | `add_track`                          | Додавання аудіо матеріалу до проєкту                  | Асинхронне завдання, оновлення версії    |
| 6   | `save`                               | Щоб отримувати кандидатів для нової доріжки, спочатку збережіть порожню цільову доріжку        | Синхронні дані проєкту, оновлення версії  |
| 7   | `render`                             | Експорт поточних доступних для прослуховування доріжок і отримання посилання на мікс `audio_id` | Асинхронне завдання         |
| 8   | `generate_track` або `replace_section` | Відповідно генерація кандидата нової доріжки або кандидата локальної заміни            | Асинхронне завдання, поки що не змінює проєкт  |
| 9   | `commit_candidate`                   | Вибір і підтвердження кандидата                  | Асинхронне завдання, після успіху оновлюється версія |
| Необов’язково  | `remove_track`                       | Видалення вказаної доріжки                     | Синхронні дані проєкту, оновлення версії  |

Якщо виконується лише локальна заміна, достатньо наявного придатного вихідного аудіо, і спочатку не потрібно виконувати `render`; якщо вихідне аудіо вже є в проєкті, також можна пропустити `upload` і `add_track`. `render_audio_id` є лише обов’язковим посиланням для `generate_track`.

Під час подання асинхронної операції спочатку повертається `{ "task_id": "...", "trace_id": "..." }`, що **не означає успішну генерацію**. Опитування:

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步返回的 task_id"}
```

Завдання вважається успішним лише тоді, коли його запис має `finished_at`, а `response.success` у ньому дорівнює `true`; коли `response.success=false`, прочитайте `response.error`. Хоча `save` може містити `task_id`, він завершується синхронно в межах цього інтерфейсу. `upload`, `render`, `generate_track`, `replace_section` не змінюють версію проєкту; після успішного `save`, `add_track`, `commit_candidate`, `remove_track` слід отримати новий `version_id`.

## Умови запитів

| Параметр                | Тип і сфера застосування                                                                                   | Опис                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | Обов’язковий рядок                                                                                     | Фіксовано як одна з назв операцій, перелічених на цій сторінці; один запит виконує лише одну операцію.                                      |
| `id`              | Обов’язковий рядок, окрім `create`                                                                         | ID проєкту, отриманий із `create.data.id`.                                      |
| `version_id`      | Обов’язковий рядок під час зміни, генерації кандидатів та експорту; для першого `save` порожнього проєкту може бути пропущений                                                         | Використовуйте найновішу версію; старі версії буде відхилено. Для `retrieve` він не потрібен.                                 |
| `Idempotency-Key` | Обов’язковий заголовок запиту, окрім `retrieve`, 1–128 символів                                                              | Використовуйте новий ключ для кожної нової операції; той самий ключ і той самий запит повертають початковий результат без повторної генерації чи списання коштів.                                   |
| `async`           | Необов’язкове булеве значення для `upload`, `add_track`, `generate_track`, `replace_section`, `commit_candidate`, `render` | Ці операції завжди асинхронні; `false` також не перетворює генерацію на синхронну.                                    |
| `callback_url`    | Необов’язковий URL для асинхронних операцій                                                                                | Отримує сповіщення про фінальний стан; якщо пропущено, виконайте запит до `/suno/tasks` за `task_id`. Усе одно необхідно перевірити `response.success`. |

Наведені нижче приклади послідовно демонструють передачу ID і версій між операціями. Відповіді містять лише поля, пов’язані з поточним кроком; під час інтеграції замініть приклади ID значеннями відповідей поточного застосунку.

## Збереження стану проєкту

| Параметр | Тип і опис |
|---|---|
| `state` | Обов’язковий об’єкт. Надсилайте **повний стан проєкту**, а не частковий патч; використовуйте як основу `data.state`, повернутий останньою операцією читання або зміни, і зберігайте невідомі поля. |
| `title` | Необов’язковий рядок; якщо пропущено, використовується `state.title`, а якщо його також немає — заголовок за замовчуванням. |
| `version_id` | Можна пропустити під час першого збереження нового порожнього проєкту; після цього обов’язково використовуйте найновішу версію. |

`state.timing.bps` має бути додатним числом, за замовчуванням 2. `state.tracks` — це масив доріжок; `clipId` наявних аудіокліпів посилається на ID аудіо, а `startBeats`, `endBeats`, `readStartBeats` використовують одиниці тактів проєкту. Найбезпечніший спосіб редагування — прочитати повний `state`, змінити лише цільову доріжку або кліп, а потім зберегти все через `save`. Нова порожня цільова доріжка повинна щонайменше мати унікальний `id`, `type:"audio"`, `clips:[]`; повну структуру порожньої доріжки дивіться у прикладі в розділі «Створення нової аудіодоріжки». Не використовуйте безпосередньо біти з результатів аналізу аудіо як координати часової шкали проєкту.

## Завантаження аудіо та додавання доріжки

| Операція | Параметр | Тип і опис |
|---|---|---|
| `upload` | `audio_url` | Обов’язковий HTTPS URL, що вказує на загальнодоступне аудіо, яке ви маєте право використовувати. `candidate.audio_id` у фінальному стані можна використати для додавання доріжки. |
| `add_track` | `audio_id` | Обов’язковий рядок; ID аудіо завершеного матеріалу, а не URL. |
| `add_track` | `name`、`color` | Необов’язкові рядки; назва доріжки за замовчуванням береться із заголовка аудіо, рекомендований колір `#RRGGBB`, за замовчуванням `#7251F7`. |
| `add_track` | `title` | Необов’язковий рядок; одночасно змінює заголовок проєкту, зазвичай пропускається. |
| `add_track` | `start_beats`、`end_beats` | Необов’язкові невід’ємні числа, кінцева точка має бути більшою за початкову; за замовчуванням починається з 0-го такту, а кінцева точка обчислюється за тривалістю аудіо та `timing.bps`. |
| `add_track` | `gain` | Необов’язкове невід’ємне число, за замовчуванням 1; коефіцієнт гучності кліпу й доріжки. |

## Створення нової аудіодоріжки

Кандидати та версії проєкту під час генерації пов’язані. Спочатку збережіть порожню доріжку для отримання кандидата, потім експортуйте поточний мікс як еталон для генерації; після завершення генерації виберіть кандидата й надішліть його на цю порожню доріжку.

### Резервування цільової доріжки: `save`

Кандидати `generate_track` пов’язані з поточною версією проєкту. До **повного** `state`, повернутого у фінальному стані попереднього `add_track`, додайте наведену нижче порожню доріжку до `state.tracks`, а потім збережіть через `save`; усі інші наявні поля залиште без змін:
```
&#123;
"id": "bdec15b5-ce96-43fa-b681-26298e013b06",
"type": "audio",
"name": "Generated piano",
"clips": [],
"takeLanes": [],
"mute": false,
"solo": false,
"amplitude": 1,
"instrument": &#123;
"type": "song"
&#125;,
"color": "#7251F7"
&#125;

```
Збережена відповідь:
```

&#123;
"success": true,
"task_id": "783f8d49-cc59-4a65-9f9d-ca00e7d7b8a9",
"trace_id": "0a9c8f13-7e4f-4915-8a40-010ce4ac61dc",
"data": &#123;
"id": "af0e104a-2a4c-40e0-9c70-7614566824a6",
"version_id": "cb0a82c9-aa5b-48cc-9395-0528675fc18d"
&#125;
&#125;

```

### Експорт референсного міксу: `render`

| Параметр | Тип і опис |
|---|---|
| `title` | Обов’язковий рядок; заголовок експортованого аудіо. |
| `lyrics`、`tags` | Необов’язкові рядки; текст за замовчуванням — `[Instrumental]`, `tags` — опис стилю. |
| `start_beats`、`end_beats` | Необов’язкові невід’ємні числа, кінцева точка має бути більшою за початкову; якщо пропущено, охоплюються всі чутні фрагменти. Приглушені фрагменти не враховуються; за наявності solo-доріжок вибираються лише solo-доріжки. |

Після успіху отримайте `render_audio_id` з кінцевого стану завдання `response.data.audio_id`.

```

&#123;
"action": "render",
"id": "af0e104a-2a4c-40e0-9c70-7614566824a6",
"version_id": "cb0a82c9-aa5b-48cc-9395-0528675fc18d",
"title": "Suno Projects Docs Source Mix",
"lyrics": "[Instrumental]",
"async": true
&#125;

```
Відповідь про прийняття:
```

## Заміна наявного фрагмента

`replace_section` може безпосередньо використовувати наявне вихідне аудіо без необхідності спочатку експортувати мікс. Генерація повертає лише кандидатів; під час прийняття виберіть початкову доріжку, що містить єдиний вихідний фрагмент.

| Параметр | Тип і опис |
|---|---|
| `source_audio_id` | Обов’язковий; ID завершеного вихідного аудіо, яке потрібно замінити. |
| `model` | Обов’язковий; використовуйте публічні моделі, перелічені в «генерації кандидатів», доступність моделі та операції визначається термінальним станом завдання. |

| `fixed` | Необов’язкове булеве значення, за замовчуванням `false`; якщо встановлено `true`, інтервал має бути коротшим за 26 секунд, і модель може не підтримувати це. |

## エラーと復旧

| 結果 | 意味 | 次の手順 |
|---|---|---|
| `project_version_conflict` / `project_candidate_stale`（409） | プロジェクトのバージョンが変更された、または候補が現在のバージョンに属していません。 | 最新のプロジェクトを `retrieve` して変更を再計画してください。古い候補を再実行しないでください。 |
| `bad_request` / `studio_state_invalid` / `studio_model_unsupported`（通常は 400） | パラメータ、トラックの状態、候補の長さ、またはモデルが操作と一致していません。 | タスクの終端状態エラーを確認し、入力を修正してください。候補を安全に結合できない場合は、元のプロジェクトを保持してください。 |
| `studio_audio_unavailable` / `studio_access_denied` / `content_rejected`（403） | 参照音声がそのプロジェクト操作で利用できない、アクセス権がない、またはコンテンツ検査で拒否されました。 | 音声のソースとタスクの `trace_id` を確認してください。すでに生成された候補を、曲全体をエクスポート可能であることと同一視しないでください。 |
| `too_many_requests`（429） | リクエストにレート制限が適用されています。 | まず元のタスクを照会してから、新しい冪等キーで新しい操作を開始するか判断してください。 |
| `studio_unavailable` / `studio_model_unavailable`（503） | プロジェクト処理または選択したモデルが一時的に利用できません。 | 元のタスク結果を保持してください。後で明示的に再試行し、モデルを自動的に切り替えないでください。 |
| `studio_processing_failed` / タイムアウト（500/504） | 処理に失敗した、または終端状態が不確実です。 | `task_id` または元の冪等キーで照会し、重複課金となる生成を避けてください。 |

プロジェクトと候補は、それらを作成したアプリケーションおよび実行環境に紐付いており、アプリケーション間での再利用や自動フェイルオーバーを想定することはできません。正常にエクスポートされた最終音声 URL を永続化し、調査のために `trace_id` を保持してください。
