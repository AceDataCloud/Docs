`POST https://api.acedata.cloud/suno/projects` — це Beta-інтерфейс для керування багатодоріжковими проєктами. Створення, збереження, генерація кандидатів, подання кандидатів та експорт розрізняються за допомогою `action`.

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: <每次写操作的新 UUID>
```

Окрім `retrieve`, **кожна операція потребує** `Idempotency-Key`. Однаковий ключ та однаковий запит лише повертають початковий результат; однаковий ключ із різними запитами повертає 409. Якщо платна генерація стикається з мережевим тайм-аутом або результат подання є невизначеним, спочатку виконайте запит за початковим ID завдання або тим самим ключем ідемпотентності; не можна безпосередньо змінювати ключ і надсилати повторно.

## Ідентифікатори та одиниці часу

| Назва                             | Звідки отримати                                                                                      | Де використовується                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | `data.id` у відповіді `create`                                                                      | Усі наступні запити поточного проєкту                                      |
| `version_id`                   | `data.version_id` з останнього `retrieve`, `save`, `add_track`, `commit_candidate` або `remove_track` | Зміна, генерація кандидатів та експорт; необхідно використовувати найновішу версію                              |
| `audio_id` / `source_audio_id` | `response.data.candidate.audio_id` у фінальному стані `upload` або наявний ID завершеного аудіо                                | Посилання на вихідне аудіо під час `add_track`, генерації або заміни                          |
| `render_audio_id`              | `response.data.audio_id` у фінальному стані `render`                                                       | Посилання на мікс проєкту для `generate_track`                         |
| `operation_id`                 | `response.data.operation_id` у фінальному стані `generate_track` або `replace_section`                       | `commit_candidate`; зазвичай збігається з `task_id` завдання генерації, але слід читати значення з відповіді |
| `candidate_id`                 | `response.data.candidates[].id` у фінальному стані генерації                                                       | Вибір кандидата для подання                                         |
| `track_id`                     | `data.state.tracks[].id` проєкту                                                                | Подання кандидата або видалення доріжки                                        |
| `task_id`                      | Відповідь на подання асинхронної операції                                                                                   | Запит фінального стану через `/suno/tasks`; це не ID проєкту                   |

`start_seconds` / `end_seconds` — це **секунди у вихідному аудіо**; `start_beats` / `end_beats` — це **кількість бітів на часовій шкалі проєкту**. `state.timing.bps` — це кількість бітів за секунду, за замовчуванням 2. Наприклад, для фрагмента тривалістю 41 секунду, що починається з біту 0, кінцевою точкою за замовчуванням є біт 82. Діапазон секунд у `generate_track` використовується для зазначення посилання для генерації та не гарантує, що кандидат матиме лише довжину цього діапазону.

## Потік операцій

| Послідовність  | `action`                             | Призначення                         | Спосіб повернення         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | Створення порожнього проєкту                      | Синхронні дані проєкту       |
| 2   | `retrieve`                           | Читання найновішої версії та повного `state`          | Синхронні дані проєкту       |
| 3   | `save`                               | Перше збереження або повне збереження зміненого `state`      | Синхронні дані проєкту       |
| 4   | `upload`                             | Створення матеріалу з HTTPS-адреси аудіо           | Асинхронне завдання         |
| 5   | `add_track`                          | Додавання аудіоматеріалу до проєкту                  | Асинхронне завдання, оновлює версію    |
| 6   | `save`                               | Якщо потрібно отримувати кандидатів нової доріжки, спочатку збережіть порожню цільову доріжку        | Синхронні дані проєкту, оновлює версію  |
| 7   | `render`                             | Експорт поточних доступних для прослуховування доріжок, отримання посилання на мікс `audio_id` | Асинхронне завдання         |
| 8   | `generate_track` або `replace_section` | Відповідно генерація кандидата нової доріжки або кандидата локальної заміни            | Асинхронне завдання, поки не змінює проєкт  |
| 9   | `commit_candidate`                   | Вибір і подання кандидата                  | Асинхронне завдання, після успіху оновлює версію |
| Необов’язково  | `remove_track`                       | Видалення вказаної доріжки                     | Синхронні дані проєкту, оновлює версію  |

Якщо виконується лише локальна заміна, достатньо наявного доступного вихідного аудіо, попередньо виконувати `render` не потрібно; якщо вихідне аудіо вже є в проєкті, також можна пропустити `upload` і `add_track`. `render_audio_id` є обов’язковим посиланням лише для `generate_track`.

Під час подання асинхронної операції спочатку повертається `{ "task_id": "...", "trace_id": "..." }`, що **не означає успішну генерацію**. Опитування:

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步返回的 task_id"}
```

Завдання вважається успішним лише тоді, коли запис завдання має `finished_at` і його `response.success` дорівнює `true`; коли `response.success=false`, прочитайте `response.error`. Хоча `save` може містити `task_id`, у цьому інтерфейсі воно завершується синхронно. `upload`, `render`, `generate_track`, `replace_section` не змінюють версію проєкту; після успішного `save`, `add_track`, `commit_candidate`, `remove_track` слід отримати новий `version_id`.

## Угоди щодо запитів

| Параметр                | Тип і сфера застосування                                                                                   | Опис                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | Обов’язковий рядок                                                                                     | Фіксоване ім’я однієї з операцій, перелічених на цій сторінці; один запит виконує лише одну операцію.                                      |
| `id`              | Обов’язковий рядок, окрім `create`                                                                         | ID проєкту, отриманий з `create.data.id`.                                      |
| `version_id`      | Обов’язковий рядок під час змін, генерації кандидатів та експорту; для першого `save` порожнього проєкту можна не вказувати                                                         | Використовуйте найновішу версію, старі версії буде відхилено. Для `retrieve` він не потрібен.                                 |
| `Idempotency-Key` | Обов’язковий заголовок запиту, окрім `retrieve`, 1–128 символів                                                              | Для кожної нової операції використовуйте новий ключ; однаковий ключ та однаковий запит повертають початковий результат без повторної генерації чи списання коштів.                                   |
| `async`           | Необов’язкове булеве значення для `upload`, `add_track`, `generate_track`, `replace_section`, `commit_candidate`, `render` | Ці операції завжди асинхронні; `false` також не зробить генерацію синхронною.                                    |
| `callback_url`    | Необов’язковий URL для асинхронних операцій                                                                                | Отримує сповіщення про фінальний стан; якщо його не вказано, виконуйте запит до `/suno/tasks` за `task_id`. Все одно необхідно перевіряти `response.success`. |

Наведені нижче приклади послідовно демонструють передачу ID і версій між операціями. У відповідях наведено лише поля, пов’язані з поточним кроком; під час інтеграції замініть прикладові ID значеннями відповідей поточного застосунку.

## Збереження стану проєкту

| Параметр | Тип і опис |
|---|---|
| `state` | Обов’язковий об’єкт. Надсилайте **повний стан проєкту**, а не частковий патч; використовуйте `data.state`, повернений останньою операцією читання або зміни, як основу, зберігаючи невідомі поля. |
| `title` | Необов’язковий рядок; якщо пропущено, використовується `state.title`, а якщо його також немає — заголовок за замовчуванням. |
| `version_id` | Можна пропустити під час першого збереження нового порожнього проєкту; надалі обов’язково слід використовувати найновішу версію. |

`state.timing.bps` має бути додатним числом, за замовчуванням 2. `state.tracks` — це масив доріжок; `clipId` наявних аудіокліпів посилається на аудіо ID, а `startBeats`, `endBeats`, `readStartBeats` використовують одиниці тактів проєкту. Найбезпечніший спосіб редагування — прочитати повний `state`, змінити лише цільову доріжку або кліп, а потім виконати загальне `save`. Нова порожня цільова доріжка щонайменше повинна мати унікальний `id`, `type:"audio"`, `clips:[]`; повну структуру порожньої доріжки дивіться у прикладі в розділі «Створення нової аудіодоріжки». Не використовуйте точки такту з результатів аналізу аудіо безпосередньо як координати часової шкали проєкту.

## Завантаження аудіо та додавання доріжки

| Операція | Параметр | Тип і опис |
|---|---|---|
| `upload` | `audio_url` | Обов’язковий HTTPS URL, що вказує на загальнодоступне аудіо, на використання якого ви маєте право. `candidate.audio_id` у кінцевому стані можна використати для додавання доріжки. |
| `add_track` | `audio_id` | Обов’язковий рядок; аудіо ID готового матеріалу, а не URL. |
| `add_track` | `name`、`color` | Необов’язкові рядки; назва доріжки за замовчуванням береться із заголовка аудіо, рекомендований колір — `#RRGGBB`, за замовчуванням `#7251F7`. |
| `add_track` | `title` | Необов’язковий рядок; одночасно змінює заголовок проєкту, зазвичай пропускається. |
| `add_track` | `start_beats`、`end_beats` | Необов’язкові невід’ємні числа, кінцева точка має бути більшою за початкову; за замовчуванням починається з такту 0, а кінцева точка обчислюється за тривалістю аудіо та `timing.bps`. |
| `add_track` | `gain` | Необов’язкове невід’ємне число, за замовчуванням 1; коефіцієнт гучності кліпу та доріжки. |

## Створення нової аудіодоріжки

Кандидати та версія проєкту під час генерування пов’язані. Спочатку збережіть порожню доріжку для отримання кандидатів, потім експортуйте поточний мікс як еталон для генерування; після завершення генерування виберіть одного кандидата та додайте його до цієї порожньої доріжки.

### Резервування цільової доріжки: `save`

Кандидати `generate_track` пов’язані з поточною версією проєкту. До **повного** `state`, поверненого в кінцевому стані попереднього `add_track`, додайте наступну порожню доріжку до `state.tracks`, а потім збережіть через `save`; усі інші наявні поля збережіть без змін:
```
&#123;
"id": "bdec15b5-ce96-43fa-b681-26298e013b06",
"type": "audio",
"name": "Згенероване піаніно",
"clips": [],
"takeLanes": [],
"mute": false,
"solo": false,
"amplitude": 1,
"instrument": &#123;
"type": "song"
&#125;,
"color": "#7251F7"
&#125;

```
Зберегти відповідь:
```

&#123;
"success": true,
"task_id": "783f8d49-cc59-4a65-9f9d-ca00e7d7b8a9",
"trace_id": "0a9c8f13-7e4f-4915-8a40-010ce4ac61dc",
"data": &#123;
"id": "af0e104a-2a4c-40e0-9c70-7614566824a6",
"version_id": "cb0a82c9-aa5b-48cc-9395-0528675fc18d"
&#125;
&#125;

```

### Експорт референсного міксу: `render`

| Параметр | Тип і опис |
|---|---|
| `title` | Обов’язковий рядок; заголовок експортованого аудіо. |
| `lyrics`、`tags` | Необов’язкові рядки; текст за замовчуванням `[Instrumental]`, `tags` — опис стилю. |
| `start_beats`、`end_beats` | Необов’язкові невід’ємні числа, кінцева точка має бути більшою за початкову; за пропуску охоплюються всі чутні кліпи. Приглушені кліпи не враховуються; за наявності solo-доріжок вибираються лише solo-доріжки. |

Після успіху отримайте `render_audio_id` із кінцевого стану завдання `response.data.audio_id`.

```

&#123;
"action": "render",
"id": "af0e104a-2a4c-40e0-9c70-7614566824a6",
"version_id": "cb0a82c9-aa5b-48cc-9395-0528675fc18d",
"title": "Suno Projects Docs Source Mix",
"lyrics": "[Instrumental]",
"async": true
&#125;

```
Відповідь про прийняття:
```

&#123;

## Заміна наявного кліпу

`replace_section` може безпосередньо використовувати наявне вихідне аудіо, без потреби спочатку експортувати мікс. Генерація повертає лише кандидатів; під час застосування виберіть початкову доріжку, що містить єдиний вихідний кліп.

| Параметр | Тип і опис |
|---|---|
| `source_audio_id` | Обов’язковий; ID завершеного вихідного аудіо, яке потрібно замінити. |
| `model` | Обов’язковий; використовуйте загальнодоступні моделі, перелічені в «Генерації кандидатів», доступність моделі й операції визначається кінцевим станом завдання. |

| `prompt`、`replacement_lyrics` | Необов’язкові рядки; перший — оригінальний текст або контекст, другий — новий текст для інтервалу заміни. |

| `fixed` | Необов’язкове булеве значення, за замовчуванням `false`; якщо встановити `true`, інтервал має бути коротшим за 26 секунд, і модель може не підтримувати це. |

Успішно експортований `audio_url` можна використовувати для завантаження або відтворення. Доступність аудіопосилання не доводить, що інші кандидати також мають право на експорт проєкту.

## Помилки та відновлення

| Результат | Значення | Наступний крок |
|---|---|---|
| `project_version_conflict` / `project_candidate_stale`（409） | Версія проєкту змінилася, або кандидат не належить поточній версії. | Виконайте `retrieve` останнього проєкту та повторно сплануйте зміни; не відтворюйте старих кандидатів. |
| `bad_request` / `studio_state_invalid` / `studio_model_unsupported`（зазвичай 400） | Параметри, стан доріжки, тривалість кандидата або модель не відповідають операції. | Перегляньте помилку в кінцевому стані завдання, виправте вхідні дані; якщо кандидата неможливо безпечно з'єднати, збережіть початковий проєкт. |
| `studio_audio_unavailable` / `studio_access_denied` / `content_rejected`（403） | Аудіо, на яке є посилання, недоступне для операції з цим проєктом, відсутні права доступу або вміст відхилено перевіркою. | Перевірте джерело аудіо та `trace_id` завдання; не прирівнюйте вже згенерованого кандидата до можливості експорту всієї композиції. |
| `too_many_requests`（429） | Запит обмежено за частотою. | Спочатку перевірте початкове завдання, а потім вирішіть, чи ініціювати нову операцію з новим ключем ідемпотентності. |
| `studio_unavailable` / `studio_model_unavailable`（503） | Обробка проєкту або вибрана модель тимчасово недоступні. | Збережіть результат початкового завдання; пізніше виконайте явну повторну спробу, не перемикаючи модель автоматично. |
| `studio_processing_failed` / тайм-аут（500/504） | Обробка не вдалася або кінцевий стан невизначений. | Виконайте запит за `task_id` або початковим ключем ідемпотентності, щоб уникнути повторної платної генерації. |

Проєкти та кандидати прив'язані до застосунку й середовища виконання, у яких їх створено; не можна припускати повторне використання між застосунками або автоматичне перемикання у разі збою. Зберігайте URL остаточного аудіо, успішно експортованого, та зберігайте `trace_id` для полегшення діагностики.
