`POST https://api.acedata.cloud/suno/projects` — це Beta-інтерфейс для керування багатодоріжковими проєктами. Один ендпойнт розрізняє створення, збереження, генерацію кандидатів, підтвердження кандидатів та експорт через `action`. Викликачеві потрібно лише використовувати наведені нижче публічні поля, без заповнення внутрішньої структури запитів базового сервісу генерації.

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: 每次修改操作使用新的 UUID
```

За винятком `retrieve`, **кожна операція потребує** `Idempotency-Key`. Однаковий ключ та однаковий запит лише повторно повертають початковий результат; однаковий ключ із різними запитами повертає 409. Якщо платна генерація зіткнулася з мережевим тайм-аутом або результат підтвердження невизначений, спочатку виконайте запит за початковим ID завдання або тим самим ключем ідемпотентності; не можна безпосередньо змінювати ключ і надсилати повторно.

## Спочатку розрізняйте ці ID та одиниці часу

| Назва                             | Звідки отримується                                                                                      | Де використовується                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | `data.id` у відповіді `create`                                                                      | Усі наступні запити поточного проєкту                                      |
| `version_id`                   | `data.version_id` з останнього `retrieve`, `save`, `add_track`, `commit_candidate` або `remove_track` | Для змін, генерації кандидатів та експорту; необхідно використовувати останню версію                              |
| `audio_id` / `source_audio_id` | `response.data.candidate.audio_id` у фінальному стані `upload` або ID вже наявного завершеного аудіо                                | Посилання на вихідне аудіо під час `add_track`, генерації або заміни                          |
| `render_audio_id`              | `response.data.audio_id` у фінальному стані `render`                                                       | Посилання на мікс проєкту для `generate_track`                         |
| `operation_id`                 | `response.data.operation_id` у фінальному стані `generate_track` або `replace_section`                       | `commit_candidate`; зазвичай збігається з `task_id` завдання генерації, але слід читати значення з відповіді |
| `candidate_id`                 | `response.data.candidates[].id` у фінальному стані генерації                                                       | Вибір одного кандидата для підтвердження                                         |
| `track_id`                     | `data.state.tracks[].id` проєкту                                                                | Підтвердження кандидата або видалення доріжки                                        |
| `task_id`                      | Відповідь на надсилання асинхронної операції                                                                                   | Використовується для запиту фінального стану через `/suno/tasks`; це не ID проєкту                   |

`start_seconds` / `end_seconds` — це **секунди у вихідному аудіо**; `start_beats` / `end_beats` — це **долі на часовій шкалі проєкту**. `state.timing.bps` — це кількість долей за секунду, за замовчуванням 2. Наприклад, фрагмент тривалістю 41 секунду, що починається з долі 0, за замовчуванням завершується на долі 82. Інтервал у секундах для `generate_track` використовується для зазначення посилання для генерації та не гарантує, що кандидат матиме довжину лише цього інтервалу.

## Порядок операцій і визначення результату

| Порядок  | `action`                             | Призначення                         | Спосіб повернення         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | Створити порожній проєкт                      | Синхронні дані проєкту       |
| 2   | `retrieve`                           | Отримати останню версію та повний `state`          | Синхронні дані проєкту       |
| 3   | `save`                               | Перше збереження або загальне збереження зміненого `state`      | Синхронні дані проєкту       |
| 4   | `upload`                             | Створити матеріал з HTTPS-адреси аудіо           | Асинхронне завдання         |
| 5   | `add_track`                          | Додати аудіо матеріалу до проєкту                  | Асинхронне завдання, оновлює версію    |
| 6   | `save`                               | Якщо потрібно отримати кандидата нової доріжки, спочатку збережіть порожню цільову доріжку        | Синхронні дані проєкту, оновлює версію  |
| 7   | `render`                             | Експортувати поточні доступні для прослуховування доріжки та отримати `audio_id` посилання на мікс | Асинхронне завдання         |
| 8   | `generate_track` або `replace_section` | Відповідно генерувати кандидата нової доріжки або кандидата локальної заміни            | Асинхронне завдання, поки що не змінює проєкт  |
| 9   | `commit_candidate`                   | Вибрати та підтвердити одного кандидата                  | Асинхронне завдання, після успіху оновлює версію |
| Необов’язково  | `remove_track`                       | Видалити вказану доріжку                     | Синхронні дані проєкту, оновлює версію  |

Якщо виконується лише локальна заміна, достатньо наявного придатного вихідного аудіо, спочатку виконувати `render` не потрібно; якщо вихідне аудіо вже є в проєкті, також можна пропустити `upload` і `add_track`. `render_audio_id` є лише обов’язковим посиланням для `generate_track`.

Під час надсилання асинхронної операції спочатку повертається `{ "task_id": "...", "trace_id": "..." }`, **що не означає успішної генерації**. Опитування:

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步返回的 task_id"}
```

Завдання вважається успішним лише тоді, коли його запис має `finished_at` і `response.success` у ньому дорівнює `true`; коли `response.success=false`, прочитайте `response.error`. Хоча `save` може містити `task_id`, у цьому інтерфейсі він завершується синхронно. `upload`, `render`, `generate_track`, `replace_section` не змінюють версію проєкту; після успішних `save`, `add_track`, `commit_candidate`, `remove_track` слід отримати новий `version_id`.

| `id`              | Обов’язковий рядок, крім `create`                                                                         | ID проєкту, з `create.data.id`.                                      |

Для `retrieve` не потрібен.                                 |
| `Idempotency-Key` | Обов’язковий заголовок запиту, крім `retrieve`, 1–128 символів                                                              | Для кожної нової операції використовуйте новий ключ; однаковий ключ та однаковий запит повторно повертають початковий результат без повторної генерації чи списання коштів.                                   |

| `callback_url`    | Необов’язковий URL для операцій із зазначеними вище необов’язковими асинхронними полями                                                                       | Отримує сповіщення про фінальний стан; якщо не вказано, виконуйте запит до `/suno/tasks` за `task_id`. Все одно потрібно перевіряти `response.success`. |

### Проєкти та матеріали
| `action`       | Спеціальні параметри        | Тип і умови                           | Опис                                                               |
| -------------- | --------------------------- | ------------------------------------- | ------------------------------------------------------------------ |
| `create`       | `title`                     | Обов’язковий рядок, 1–200 символів   | Назва нового проєкту.                                              |
| `retrieve`     | Немає                       | —                                     | Потрібні лише `action` та `id` проєкту; повертає повний редагований `state`. |
| `save`         | `state`                     | Обов’язковий об’єкт                   | **Повністю замінює** стан проєкту, а не є частковим патчем. Змінюйте на основі останнього `retrieve.data.state` і надсилайте повністю, зберігаючи невідомі поля. |
| `save`         | `title`                     | Необов’язковий рядок                  | Назва проєкту; якщо пропущено, використовується `state.title`, а якщо його також немає — стандартна назва. |
| `upload`       | `audio_url`                 | Обов’язковий HTTPS URL                | Загальнодоступна адреса аудіоматеріалу; після успіху прочитайте фінальний `candidate.audio_id`. Матеріал має бути дозволений до використання викликачем. |
| `add_track`    | `audio_id`                  | Обов’язковий рядок                    | Аудіо ID завершеного матеріалу, а не URL.                          |
| `add_track`    | `name` / `color`            | Необов’язкові рядки                   | Назва та колір нової доріжки; назва за замовчуванням береться із заголовка аудіо, рекомендований колір `#RRGGBB`, за замовчуванням `#7251F7`. |
| `add_track`    | `title`                     | Необов’язковий рядок                  | Одночасно змінює назву проєкту; зазвичай пропускається.            |
| `add_track`    | `start_beats` / `end_beats` | Необов’язкові невід’ємні числа, `end_beats > start_beats` | Положення фрагмента на часовій шкалі проєкту. Початок за замовчуванням 0; кінець за замовчуванням `початок + тривалість аудіо × timing.bps`. |
| `add_track`    | `gain`                      | Необов’язкове невід’ємне число, за замовчуванням 1 | Коефіцієнт гучності фрагмента та нової доріжки.                    |
| `remove_track` | `track_id`                  | Обов’язковий рядок                    | ID наявної доріжки, яку потрібно видалити. Після успіху використовуйте повернуту нову версію. |

`state.timing.bps` має бути додатним числом, за замовчуванням 2. `state.tracks` — це масив доріжок; `clipId` наявних аудіофрагментів посилається на аудіо ID, а `startBeats`, `endBeats`, `readStartBeats` використовують одиниці тактів проєкту. Найбезпечніший спосіб редагування — прочитати повний `state`, змінити лише цільову доріжку або фрагмент, а потім виконати повне `save`. Нова порожня цільова доріжка повинна щонайменше мати унікальний `id`, `type:"audio"`, `clips:[]`; повну придатну до використання реальну форму дивіться нижче в кроці 5. Не використовуйте безпосередньо точки такту з результатів аналізу аудіо як координати часової шкали проєкту.

Кандидати локальної заміни можуть бути автоматично додані лише тоді, коли фактичну тривалість можна надійно зіставити з повним вихідним аудіо або вибраним інтервалом; у разі невідповідності початковий проєкт зберігається й повертається помилка, не можна примусово з’єднати їх шляхом ручного вгадування тактів.

## Реальні запити та відповіді від 2026-10-09

Наведені нижче тіла запитів і поля відповідей узято з реальних викликів одного проєкту. Кожна група JSON послідовно містить запит, відповідь про прийняття (якщо асинхронно), відповідь фінального стану завдання. Для зручності читання з відповідей наведено лише поля, потрібні для завершення цього процесу; поля облікового запису, використання та тривалості не показано. Приклади ID належать цій тестовій програмі, під час інтеграції обов’язково використовуйте ID, повернуті власними запитами, і новий `Idempotency-Key`.

### 1. Створення та читання порожнього проєкту: `create`, `retrieve`

Запит `create`:


Усі аудіопосилання, успішно повернуті вище, під час цієї перевірки можуть зчитувати медіабайти; перші 1 024 байти посилань для створення та заміни кандидатів повертають HTTP 206, `audio/mpeg`, а посилання для експорту повертає HTTP 206, `audio/mp4`. Це лише доводить, що посилання доступні для читання, і не означає, що проєкт, який містить цього кандидата, обов’язково можна експортувати.

## Помилки та відновлення

| Результат                                                                            | Значення                          | Наступний крок                                    |
| ----------------------------------------------------------------------------- | --------------------------- | -------------------------------------- |
| `project_version_conflict` / `project_candidate_stale`（409）                   | Версія проєкту змінилася, або кандидат не належить поточній версії.         | Виконайте `retrieve` останнього проєкту та повторно сплануйте зміни; не відтворюйте старих кандидатів.        |
| `bad_request` / `studio_state_invalid` / `studio_model_unsupported`（зазвичай 400）   | Параметри, стан доріжки, тривалість кандидата або модель не відповідають операції.      | Перегляньте помилку кінцевого стану завдання, виправте введення; якщо кандидата неможливо безпечно об’єднати, збережіть початковий проєкт.          |
| `studio_audio_unavailable` / `studio_access_denied` / `content_rejected`（403） | Посилальне аудіо не можна використати для операції проєкту, немає прав доступу, або вміст відхилено перевіркою. | Перевірте джерело аудіо та `trace_id` завдання; не прирівнюйте вже створеного кандидата до можливості експорту всієї композиції. |
| `too_many_requests`（429）                                                      | Запит обмежено за частотою.                   | Спочатку запитайте початкове завдання, а потім вирішіть, чи ініціювати нову операцію з новим ключем ідемпотентності.                |
| `studio_unavailable` / `studio_model_unavailable`（503）                        | Обробка проєкту або вибрана модель тимчасово недоступні.             | Збережіть результат початкового завдання; пізніше виконайте явну повторну спробу, не перемикайте модель автоматично.                |
| `studio_processing_failed` / тайм-аут（500/504）                                      | Обробка не вдалася або кінцевий стан невизначений.                 | Виконайте запит за `task_id` або початковим ключем ідемпотентності, щоб уникнути повторної платної генерації.          |

Проєкти й кандидати прив’язані до застосунку та середовища виконання, які їх створили, тому не можна припускати повторне використання між застосунками або автоматичне перемикання при відмові. Будь ласка, зберігайте остаточний URL успішно експортованого аудіо та зберігайте `trace_id` для полегшення діагностики.
