---

SUNO дозволяє отримувати музичні файли у форматі wav. У цьому документі описано методи інтеграції відповідного API.

Основним вхідним параметром цього API є `audio_id`, який є офіційно згенерованим ідентифікатором пісні; додатково підтримується необов’язковий параметр `callback_url` для асинхронного зворотного виклику.

У цьому прикладі ми використовуємо `audio_id` зі значенням `4e43116a-bf09-472c-8e1c-655eabf02682`.

```python
import requests

url = "https://api.acedata.cloud/suno/wav"

headers = {
    "accept": "application/json",
    "authorization": "Bearer aa287fa4cc54401087a9fab3f99630af",
    "content-type": "application/json"
}

payload = {
    "audio_id": "4e43116a-bf09-472c-8e1c-655eabf02682"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Результат:

```json
{
  "success": true,
  "task_id": "6a5a2099-d6d3-4930-9709-a30ac5dc7de5",
  "trace_id": "3fa70e81-6bb7-4ca8-b718-dd16a4eda7e8",
  "data": [
    {
      "file_url": "https://platform.cdn.acedata.cloud/suno/6a5a2099-d6d3-4930-9709-a30ac5dc7de5.wav"
    }
  ]
}
```

Як видно, поле `file_url` у `data` містить URL музичного файлу у форматі wav, який є публічно доступною адресою CDN.

> **Про збереження посилання на WAV**
>
> WAV-файли на upstream CDN Suno (`https://cdn1.suno.ai/{audio_id}.wav`) зберігаються лише кілька днів, після чого видаляються, і при зверненні повертається помилка 403.
> Щоб уникнути втрати посилання, цей API перед поверненням автоматично копіює upstream WAV-файл на власний CDN (`https://platform.cdn.acedata.cloud/suno/{task_id}.wav`), і повертає `file_url` зі стабільною адресою, яка не залежить від терміну зберігання upstream CDN.
> У разі невдачі копіювання (дуже рідко) повертається оригінальний upstream URL, що відповідає історичній поведінці.
