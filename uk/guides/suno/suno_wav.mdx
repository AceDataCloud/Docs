SUNO дозволяє нам отримувати музичні файли у форматі wav, цей документ пояснює методи інтеграції відповідних API.

Основним вхідним параметром цього API є `audio_id`, це офіційно згенерований ID пісні; також підтримується необов'язковий параметр `callback_url` для асинхронного зворотного виклику.

Тут ми вводимо `audio_id` як `4e43116a-bf09-472c-8e1c-655eabf02682`.

```python
import requests

url = "https://api.acedata.cloud/suno/wav"

headers = {
    "accept": "application/json",
    "authorization": "Bearer YOUR_API_KEY",
    "content-type": "application/json"
}

payload = {
    "audio_id": "4e43116a-bf09-472c-8e1c-655eabf02682"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Результат виглядає так:

```json
{
  "success": true,
  "task_id": "6a5a2099-d6d3-4930-9709-a30ac5dc7de5",
  "trace_id": "3fa70e81-6bb7-4ca8-b718-dd16a4eda7e8",
  "data": [
    {
      "file_url": "https://cdn.acedata.cloud/e724d7f13d.png?example=image-001"
    }
  ]
}
```

Можна побачити, що поле `file_url` в `data` є отриманим музичним файлом у форматі wav, це публічно доступна адреса CDN.

> **Щодо збереження посилання на WAV**
> Платформа спочатку зберігає остаточний WAV файл на Ace Data Cloud CDN перед поверненням. Вищезазначене URL лише демонструє формат відповіді, не представляючи собою довгостроковий реальний об'єкт. Лише в разі, якщо збереження на CDN не завершено, і оригінальна медіа-адреса за миттєвою перевіркою все ще може завантажити дійсний WAV файл, `file_url` може зберегти цю адресу; якщо адреса стала недійсною або перевірка файлу не вдалася, запит поверне помилку або тайм-аут, не вважаючи недоступну адресу успішним результатом. Будь ласка, завантажте та належним чином збережіть файл після завершення завдання, конкретний термін зберігання визначається поточною політикою зберігання платформи.
