Основна функція Suno Tasks API полягає в запиті статусу виконання завдання шляхом введення ID завдання, згенерованого Suno Audios Generation API або Suno Lyrics Generation API.

У цьому документі буде детально представлено інструкції з інтеграції Suno Tasks API, щоб допомогти вам легко інтегрувати та повною мірою використовувати потужні можливості цього API. За допомогою Suno Tasks API ви можете легко реалізувати запит статусу виконання завдань Suno Lyrics Generation API або Suno Audios Generation API.

## Процес подання заявки

Щоб використовувати Suno Audios Generation API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token і зберегти його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, немає потреби подавати окрему заявку для кожного сервісу.** Під час першого подання заявки надаються безкоштовні квоти для безкоштовного тестування; коли квоти недостатньо, ви можете поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Приклад запиту

Suno Tasks API можна використовувати для запиту результатів двох API: Suno Audios Generation API і Suno Lyrics Generation API. Щодо того, як використовувати Suno Audios Generation API, зверніться до документації [Suno Audios Generation API ](https://platform.acedata.cloud/documents/suno-audios-integration). Щодо того, як використовувати Suno Lyrics Generation API, зверніться до [Suno Lyrics Generation API ](https://platform.acedata.cloud/documents/suno-lyrics-generation-integration).

Ми візьмемо як приклад один ID завдання, повернений сервісом Suno Audios Generation API, щоб продемонструвати, як використовувати цей API. Припустімо, у нас є ID завдання: eae26f89-b64b-404d-a80c-761996660b1c, далі буде продемонстровано, як шляхом передавання ID завдання.

### Налаштування заголовків запиту та тіла запиту

**Request Headers** включають:

- `accept`: вказує отримання результату відповіді у форматі JSON, тут заповнюється як `application/json`.
- `authorization`: ключ для виклику API, після подання заявки його можна безпосередньо вибрати зі спадного списку.

**Request Body** включає:

- `id`: ID завантаженого завдання.
- `action`: спосіб операції над завданням.

### Приклад коду

Можна побачити, що в правій частині сторінки вже автоматично згенеровано код різними мовами, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/p6vi9o.png" width="500" className="m-auto" /></p>

Деякі приклади коду наведено нижче:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/suno/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "eae26f89-b64b-404d-a80c-761996660b1c",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/suno/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "eae26f89-b64b-404d-a80c-761996660b1c",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Результат, що повертається, містить кілька полів. Поле `request` — це request body під час запуску завдання, а поле `response` — це response body, що повертається після завершення завдання. Опис полів наведено нижче.

- `id` — ID завдання генерації цієї пісні, що використовується для унікальної ідентифікації цього завдання генерації пісні.
- `request` — інформація про запит у завданні запиту пісні.
- `response` — інформація про відповідь у завданні запиту пісні.
- `created_at` — час створення завдання, Unix timestamp (секунди, з плаваючою комою).
- `started_at` — час початку виконання завдання, Unix timestamp (секунди, з плаваючою комою).
- `finished_at` — час завершення завдання, Unix timestamp (секунди, з плаваючою комою). Це поле не повертається, якщо завдання не завершено.
- `elapsed` — час виконання завдання, у секундах (з плаваючою комою, із збереженням 3 знаків після коми). Це поле не повертається, якщо завдання не завершено.

- `ids`: масив завантажених ID завдань.
- `action`: спосіб операції із завданням.

Результат, що повертається, містить кілька полів, серед яких `items` містить детальну інформацію про пакетні завдання пісень, конкретна інформація про кожне завдання пісні така сама, як поля вище, а інформація про поля наведена нижче.

- `items` — вся детальна інформація про пакетні завдання пісень. Це масив, формат кожного елемента масиву такий самий, як формат результату, що повертається під час запиту одного завдання вище.
- `count` — кількість завдань пісень у цьому пакетному запиті.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API повертає відповідний код помилки та повідомлення. Наприклад:

- `400 token_mismatched`：Некоректний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Некоректний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Занадто багато запитів, ви перевищили ліміт частоти запитів.
- `500 api_error`：Внутрішня помилка сервера, на сервері щось пішло не так.
