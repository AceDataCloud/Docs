У міру поширення застосування ШІ різні програми ШІ поступово набули популярності. ШІ дедалі глибше проникає в усі аспекти роботи та життя людей. А галузей, яких стосується ШІ, також стає дедалі більше: від початкового письменництва до медицини й освіти, а тепер — до музики.

Suno — це професійна високоякісна платформа для створення пісень і музики за допомогою ШІ. Користувачам достатньо ввести прості текстові підказки, щоб на основі жанрового стилю та тексту пісні генерувати пісні з вокалом. Цей генератор музики ШІ розроблено членами команди з відомих технологічних компаній, таких як Meta, TikTok, Kensho тощо, з метою не потребувати жодних інструментів чи музичних інструментів, щоб кожен міг створювати чудову музику.

Нижче наведено прогрес оновлення моделей:

| ------- | --------------- | ---------- | -------- | -------- | ------ |
| v6      | chirp-v6        | 2026.09.09 | —        | —        | —      |
| v6 Wild | chirp-v6-wild   | 2026.09.09 | —        | —        | —      |

> Обмеження `lyric` і `style` у таблиці вище є верхніми межами в користувацькому режимі (`custom` дорівнює `true`). У некористувацькому режимі натхнення (`custom` дорівнює `false`) заповнюється лише `prompt`, а його максимальна довжина становить 500 символів (однаково для всіх моделей).

Suno тепер підтримує `chirp-v6`, `chirp-v6-wild` і `chirp-v6-mini`. Рекомендовано використовувати `chirp-v6`; назви старих моделей і надалі сумісні.

Проте офіційно Suno не надає API, AceDataCloud надає набір API Suno, що імітує інтеграцію з офіційним Suno та дає змогу зручно й швидко генерувати потрібну музику.

## Подання заявки та використання

Щоб використовувати Suno Audios Generation API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати свій API Token і зберегти його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу, де вам буде запропоновано зареєструватися та увійти, після завершення вас буде автоматично повернуто на поточну сторінку.

**Один API Token дає змогу викликати всі сервіси платформи, не потрібно подавати заявку окремо для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт, який можна використати для безкоштовного ознайомлення; коли ліміту недостатньо, можна поповнити універсальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

## Базове використання

Які пісні ви хочете, можете довільно ввести текст, наприклад, якщо я хочу згенерувати пісню про Різдво, можна ввести `a song for Christmas`, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Тут можна побачити, що ми налаштували Request Headers, зокрема:

- `accept`: у якому форматі ви хочете отримати результат відповіді, тут зазначено `application/json`, тобто формат JSON.
- `authorization`: ключ для виклику API, після подання заявки його можна безпосередньо вибрати зі спадного списку.

Також налаштовано Request Body, зокрема:
- `action`: тип аудіозавдання, за замовчуванням — `generate`. Підтримує такі операції, як генерація, продовження, кавер, з'єднання, поділ на доріжки, додавання аудіодоріжки, вилучення вказаної аудіодоріжки, генерація звукових ефектів і налаштування швидкості тощо; усі вони викликаються через `POST /suno/audios`.
- `prompt`: підказка для режиму натхнення Suno (діє, коли `custom` має значення `false`), максимум 500 символів.
- `model`: модель для цього завдання генерації музики. Серія v6 містить `chirp-v6`, `chirp-v6-wild` і `chirp-v6-mini`; старі назви моделей залишаються сумісними.
- `max_mode`: режим посиленої генерації. Для `generate` увімкнений лише тоді, коли і `custom`, і `max_mode` мають значення `true`, вартість — 1.12 Credits; для `add_stem` може бути увімкнений безпосередньо, вартість — 1.344 Credits. У разі вимкнення або пропуску вартість становить відповідно 0.56 і 0.672 Credits.
- `variety`: інтенсивність різноманітності результатів генерації, доступні значення: `off`, `normal`, `high`, `extra`, `max`. Використовується лише для `generate` і `add_stem`, передавання для інших action поверне 400.
- `lyric`: текст пісні для користувацького режиму Suno. Для `chirp-v3-5` і `chirp-v4` — максимум 3000 символів; для `chirp-v4-5` і вище (включно з `chirp-v5`, `chirp-v5-5`) — максимум 5000 символів.
- `custom`: чи використовувати користувацький режим, за замовчуванням: `false`.
- `instrumental`: опція інструментальної музики для режиму натхнення Suno.
- `title`: назва музики для користувацького режиму Suno. Для `chirp-v3-5`, `chirp-v4` — максимум 80 символів; для `chirp-v4-5` і вище — максимум 100 символів.
- `style`: музичний стиль для користувацького режиму Suno. Для `chirp-v3-5` і `chirp-v4` — максимум 200 символів; для `chirp-v4-5` і вище (включно з `chirp-v5`, `chirp-v5-5`) — максимум 1000 символів.
- `negative_tags`: музичні стилі або жанри, які потрібно виключити з результатів генерації в користувацькому режимі (коли `custom` має значення `true`).
- `audio_weight`: вага впливу аудіо або голосових характеристик, діапазон 0-1; `0` також є допустимим значенням. Може використовуватися для таких операцій, як генерація, продовження, кавер, додавання аудіодоріжки та узгодженість голосу; за відсутності еталонного аудіо або голосових характеристик модель може послабити або проігнорувати це значення.
- `audio_id`: ID еталонної музики.
- `overpainting_start`/`overpainting_end`: час початку й завершення додавання вокалу до наявної інструментальної музики, в секундах.
- `underpainting_start`/`underpainting_end`: час початку й завершення додавання акомпанементу до акапельного виконання, в секундах.
- `persona_id`: ID пісні виконавця.
- `continue_at`: межа продовження, у секундах. Наприклад, 213.5 означає почати генерацію наступного фрагмента з позначки 3 хвилини 33.5 секунди. `lyric` і `style` спрямовують лише новий вміст після межі й не замінюють текст або вокал до межі у вихідному аудіо.
- `style_influence`: вплив стилю в користувацькому режимі, діапазон 0-1; що більше значення, то зазвичай точніше відповідність вибраному стилю; `0` передається як допустиме значення.
- `replace_section_end`: кінцевий час фрагмента для заміни.
- `replace_section_start`: початковий час фрагмента для заміни.
- `vocal_gender`: керує перевагою жіночого або чоловічого голосу: жіночий голос — `f`, чоловічий — `m`; діє для моделей 4.5 і вище; це параметр переваги, суворе дотримання не гарантується.
- `weirdness`: рівень дивності в користувацькому режимі, діапазон 0-1; що більше значення, то зазвичай більше креативності та експериментальності; `0` передається як допустиме значення.
- `duration`: очікувана тривалість пісні, у секундах, має бути цілим числом у діапазоні від 10 до 360. Цей параметр використовується для генерації пісень у користувацькому режимі (коли `custom` має значення `true`). Це орієнтовна підказка, а не жорстке обмеження: модель враховуватиме її, але не гарантує досягнення, фактична тривалість готового результату визначається полем `duration` у відповіді та зазвичай є коротшою за очікуване значення.

### Область застосування розширених параметрів

| Параметр                | Значення                                          | Підтримувані action                              | Опис                              |
| ----------------- | ------------------------------------------- | --------------------------------------- | ------------------------------- |
| `weirdness`       | 0-1                                         | Необов'язково                                      | Регулює експериментальність, `0` є допустимим значенням; ефект залежить від операції, режиму та моделі    |
| `style_influence` | 0-1                                         | Необов'язково                                      | Регулює схильність до дотримання стилю, `0` є допустимим значенням; ефект залежить від операції, режиму та моделі |
| `audio_weight`    | 0-1                                         | Необов'язково                                      | Регулює вплив аудіо або голосових характеристик; без еталонної інформації може бути проігнорований моделлю      |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`, `add_stem`                   | Регулює стильову різноманітність між результатами                     |
| `max_mode`        | boolean                                     | `generate` (потрібно `custom=true`), `add_stem` | Посилює узгодженість і тарифікується за посиленим режимом                   |
| `vocal_gender`    | `f` / `m`                                   | Операції генерації з підтримкою керування вокалом                             | Параметр переваги, суворе дотримання не гарантується                     |
| `duration`        | ціле число 10-360                                   | Необов'язково                                      | Очікувана тривалість; конкретна операція, режим або модель можуть ігнорувати             |

Платформа перевіряє типи параметрів і діапазони значень, але не відхиляє ці необов'язкові параметри налаштування лише через відмінність action; конкретний ефект визначається операцією, режимом і моделлю.

- `lyric_prompt`: prompt для генерації тексту пісні, діє тоді й лише тоді, коли `custom` має значення `true` і `lyric` не передано.
- `callback_url`: URL, на який потрібно надіслати результат зворотним викликом.
- `async`: необов'язково; якщо встановити `true`, інтерфейс негайно повертає `task_id`, без потреби надавати `callback_url`, після чого результат отримується шляхом опитування через відповідний інтерфейс запиту завдань.

## Користувацьке створення

Якщо ви хочете користувацьки створити текст пісні, можна ввести текст:

У цей момент у поле `lyric` можна передати приблизно такий вміст:

```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> Зверніть увагу, що `\n` у тексті пісні тут є символом нового рядка. Якщо ви не знаєте, як створити текст пісні, можете скористатися API генерації текстів пісень, наданим AceDataCloud, щоб створити текст за допомогою prompt; API: [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Далі, щоб користувацьки створити пісню на основі тексту, назви та стилю, можна вказати такий вміст:

- lyric：текст пісні
- custom：вказати `true`, що означає користувацьке створення; параметр за замовчуванням має значення false, що означає створення за допомогою `prompt`.
- title：назва пісні.
- style：стиль пісні, необов'язково.

Відповідний код:

```shell
curl -X POST 'https://api.acedata.cloud/suno/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "A song for Christmas",
  "model": "chirp-v4-5",
  "lyric": "[Verse]\\nSnowflakes falling all around\\nGlistening white\\nCovering the ground\\nChildren laughing\\nFull of delight\\nIn this winter wonderland tonight\\nSanta's sleigh\\nUp in the sky\\nRudolph's nose shining bright\\nOh my\\nHear the jingle bells\\nRinging so clear\\nBringing joy and holiday cheer\\n[Verse 2]\\nRoasting chestnuts by the fire's glow\\nChristmas lights\\nThey twinkle and show\\nFamilies gathering with love and cheer\\nSpreading warmth to everyone near",
  "custom": true
}'
```

## Функція продовження генерації

Якщо ви хочете продовжити генерацію вже згенерованої пісні Suno, можна встановити параметр `action` як `extend` і ввести ID пісні, яку потрібно продовжити генерувати; ID пісні отримується відповідно до базового використання, з наведеного вище можна дізнатися, що в цей момент ID пісні має вигляд:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Зверніть увагу, тут `id` у тексті пісні є ID згенерованої пісні; якщо ви не знаєте, як генерувати пісню, можете звернутися до базового використання вище для генерації пісні.

Якщо ви хочете продовжити генерацію для пісні, завантаженої вами власноруч, можна встановити параметр `action` як `upload_extend` і ввести ID власноруч завантаженої пісні, яку потрібно продовжити генерувати; ID пісні отримується за допомогою [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), як показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Далі обов’язково потрібно заповнити текст пісні для фрагмента продовження, а також можна вказати стиль:

- lyric: використовується лише для спрямування тексту пісні новозгенерованого фрагмента після `continue_at`, не замінює текст пісні в оригінальному аудіо до цієї часової точки.
- custom: заповнення значенням `true` означає користувацьку генерацію, за замовчуванням цей параметр має значення false, що означає генерацію з використанням `prompt`.
- style: стиль пісні фрагмента продовження, необов’язковий.
- continue_at: межа продовження, одиниця вимірювання — секунди. Наприклад, 213.5 означає початок генерації наступного фрагмента з 3 хвилин 33,5 секунди.

> `extend` використовується для продовження творчої роботи над наявною піснею, а не для заміни тексту всієї пісні. Якщо ви хочете використати новий текст для всієї пісні від початку, використовуйте `generate` для повторної генерації; якщо ви хочете переосмислити пісню, спираючись на наявну, можна використати `cover`. Під час передавання цілого нового тексту пісні оригінальний текст до `continue_at` усе одно не буде замінений.

Приклад заповнення наведено нижче:

<p><img src="https://cdn.acedata.cloud/zp9s42.png" width="500" className="m-auto" /></p>

Після заповнення код автоматично генерується наступним чином:
<p><img src="https://cdn.acedata.cloud/wwpw78.png" width="500" className="m-auto" /></p>

Нижче збережено знімок реального історичного виклику, у якому `continue_at` дорівнює 2 секундам, тому лише перші 2 секунди належать до вихідного вмісту до межі продовження. Під час фактичного продовження ближче до кінця пісні це значення слід встановити на секунду, з якої очікується початок продовження, і в `lyric` надавати лише новий фрагмент, який має виконуватися після межі.

## Заміна фрагмента

Коли після генерації пісні потрібне вторинне творче редагування з окремою операцією заміни фрагмента пісні, можна виконати операцію заміни певного фрагмента пісні.

> ⚠️ **Увага**: `replace_section_result_mode` за замовчуванням має значення `full_song`: система окремо з’єднає 2 новостворені варіанти та поверне 2 повні пісні. Якщо потрібні лише ще не з’єднані варіанти замінених фрагментів, явно встановіть значення `candidates`, а потім виберіть варіант і викличте [з’єднання музики](#音乐拼接).

Опис параметрів такий:

- action: значення — `replace_section`.
- audio_id: ID оригінальної пісні (вихідної пісні, у якій виконується заміна).
- model: модель генерації пісні.
- lyric: повний текст пісні після заміни (включно із заміненим фрагментом і його контекстом, узгоджений із вмістом у `prompt`).
- prompt: новий текст пісні для фрагмента, який потрібно замінити.
- style: стиль пісні, необов’язковий.
- replace_section_start: час початку заміненого фрагмента в оригінальній пісні (секунди).
- replace_section_end: час завершення заміненого фрагмента в оригінальній пісні (секунди).
- replace_section_result_mode: режим повернення, за замовчуванням — `full_song`. `full_song` окремо з’єднує 2 варіанти та повертає 2 повні пісні; `candidates` повертає 2 ще не з’єднані фрагменти-варіанти.

## Керування тривалістю пісні

За замовчуванням тривалість згенерованої пісні визначається самою моделлю, зазвичай від 30 секунд до 4 хвилин. Якщо потрібен довший або коротший готовий результат, можна вказати бажану тривалість за допомогою параметра `duration`, одиниця вимірювання — секунди, значенням є ціле число від 10 до 360.

Цей параметр використовується для генерації пісень у користувацькому режимі (`custom` дорівнює `true`). Особливо слід зазначити, що `duration` є **схильнісною підказкою, а не жорстким обмеженням**: модель враховуватиме це значення під час створення, але не гарантує його досягнення; у практичних тестах фактична тривалість зазвичай помітно коротша за очікуване значення, а тривалість двох пісень, повернутих одним запитом, також може відрізнятися в кілька разів. Навіть для абсолютно однакових запитів тривалість, отримана після кількох відправлень, також може мати великі відмінності. Тому не використовуйте його як точне керування тривалістю; якщо для бізнесу потрібна фіксована тривалість, після отримання готового результату самостійно обріжте його або повторіть спробу.

Відповідний код Python:
```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Слід зауважити, що `duration` у запиті — це **очікувана тривалість**, тоді як поле `duration` кожної пісні у відповіді `data` — це **фактична тривалість** цієї пісні. Їхні назви однакові, але значення різні; фактична тривалість не гарантується рівною очікуваному значенню. Довжина тексту пісні є одним з основних факторів, що впливають на тривалість готового результату; якщо потрібен довший готовий результат, рекомендується одночасно надати повніший текст пісні.

Інтерфейс перевіряє, що `duration` має бути цілим числом від 10 до 360; це все ще лише ціль генерації, а не гарантія тривалості готового результату.

## Функція творчості на основі натхнення Inspo

Функція творчості на основі натхнення Inspo може генерувати нову музику на основі 1–4 повних референсних аудіозаписів і підтримує перетягування або завантаження аудіо як джерела натхнення. API використовує наявну дію `inspo`: клієнт надає загальнодоступні URL-адреси аудіо, а сервіс автоматично виконує підготовку референсного аудіо та створення, без потреби клієнту окремо зчитувати текст, стиль або тривалість, а потім формувати запит. Вона відрізняється від описаного вище семплування за проміжком, а також від Cover, що відтворює стиль оригінальної пісні. Під час використання потрібно заповнити такі параметри:

- action: значення `inspo`.
- audio_urls: список URL-адрес референсних аудіо; потрібно надати від 1 до 4 загальнодоступних аудіоадрес.
- model: використовувана модель, рекомендовано `chirp-v6`.
- prompt: текст пісні або підказка для створення (необов’язково).

> Примітка: референсне аудіо має бути загальнодоступним аудіофайлом. Якщо референсне аудіо повністю збігається з відомим записом у музичній бібліотеці платформи, Suno може відмовити в генерації через перевірку авторських прав; рекомендується використовувати власне аудіо або аудіо, згенероване Suno, як джерело натхнення.

Відповідний код Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Асинхронний зворотний виклик

Оскільки Suno генерує музику відносно довго, приблизно 1–2 хвилини, якщо API тривалий час не відповідає, HTTP-запит постійно підтримуватиме з'єднання, що призводить до додаткового споживання системних ресурсів, тому цей API також підтримує асинхронні зворотні виклики.

Загальний процес такий: коли клієнт надсилає запит, він додатково вказує поле `callback_url`; після того як клієнт надсилає API-запит, API негайно повертає результат, який містить поле `task_id`, що представляє ID поточного завдання. Після завершення завдання результат генерації музики буде надіслано у форматі POST JSON на вказаний клієнтом `callback_url`, де також міститиметься поле `task_id`, тож результати завдань можна буде пов'язати за ID.

Нижче ми на прикладі розглянемо, як саме це виконати.

Спочатку Webhook-зворотний виклик — це сервіс, здатний приймати HTTP-запити, розробник має замінити його на URL власного розгорнутого HTTP-сервера. Тут для зручності демонстрації використовується публічний сайт прикладу Webhook https://webhook.site/; відкривши цей сайт, можна отримати Webhook URL, як показано на зображенні:

![](https://cdn.acedata.cloud/fwfqin.png)

Скопіювавши цей URL, його можна використовувати як Webhook; приклад тут — https://webhook.site/03e60575-3d96-4132-b681-b713d78116e2。

Далі ми можемо встановити для поля `callback_url` вищезазначений Webhook URL і одночасно заповнити `prompt`, як показано на зображенні:
