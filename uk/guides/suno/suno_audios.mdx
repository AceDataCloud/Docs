Із розширенням застосування AI різні AI-програми поступово набули поширення. AI поступово проник у всі аспекти роботи та життя людей. А галузей, яких стосується AI, також стає дедалі більше — від початкового письма до медицини й освіти, а тепер і музики.

Suno — це професійна високоякісна платформа для створення AI-пісень і музики. Користувачам достатньо ввести прості текстові підказки, щоб на основі жанрового стилю та тексту пісні генерувати пісні з вокалом. Цей AI-генератор музики розроблено членами команди з відомих технологічних компаній, таких як Meta, TikTok, Kensho тощо, з метою не потребувати жодних інструментів чи музичних інструментів, щоб усі могли створювати чудову музику.

Нижче наведено прогрес оновлення моделей:

| ------- | --------------- | ---------- | -------- | -------- | ------ |
| v6      | chirp-v6        | 2026.09.09 | —        | —        | —      |
| v6 Wild | chirp-v6-wild   | 2026.09.09 | —        | —        | —      |
| v6 Mini | chirp-v6-mini   | 2026.09.09 | —        | —        | —      |
| v5.5    | chirp-v5-5      | 2026.03.27 | 5000     | 1000     | 8 хвилин   |
| v5      | chirp-v5        | 2025.09.23 | 5000     | 1000     | 8 хвилин   |

> Обмеження `lyric` та `style` у таблиці вище є верхніми межами в користувацькому режимі (коли `custom` дорівнює `true`). У некористувацькому режимі натхнення (коли `custom` дорівнює `false`) заповнюється лише `prompt`, а його максимальна довжина становить 500 символів (однакова для всіх моделей).

Suno тепер підтримує `chirp-v6`, `chirp-v6-wild` і `chirp-v6-mini`. Рекомендується використовувати `chirp-v6`; назви старих моделей залишаються сумісними.

Однак офіційний Suno не надає API, AceDataCloud надає набір API Suno, який імітує інтеграцію з офіційним Suno та дає змогу зручно й швидко генерувати бажану музику.

Щоб використовувати Suno Audios Generation API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token і зберегти його про запас.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, немає потреби подавати заявку окремо для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт, який можна безкоштовно випробувати; коли ліміту недостатньо, у [консолі](https://platform.acedata.cloud/console/coin) можна поповнити загальний баланс.

## Базове використання

Які пісні хочете, можна довільно ввести фрагмент тексту, наприклад, якщо я хочу згенерувати пісню про Різдво, можна ввести `a song for Christmas`, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Тут можна побачити, що ми налаштували Request Headers, зокрема:

- `accept`: у якому форматі хочете отримати результат відповіді; тут указано `application/json`, тобто формат JSON.
- `authorization`: ключ для виклику API, після подання заявки його можна безпосередньо вибрати зі спадного списку.

Додатково налаштовано Request Body, зокрема:
- `action`: дія цього завдання з генерації музики, за замовчуванням `generate`, переважно включає: `extend`, `upload_extend`, `cover`, `upload_cover`, `replace_section`, `replace_section`, `concat`, `stems`, `all_stems`, `remaster`.
- `prompt`: підказка режиму натхнення Suno (діє, коли `custom` має значення `false`), максимум 500 символів.
- `model`: модель цього завдання з генерації музики. Серія v6 включає `chirp-v6`, `chirp-v6-wild` і `chirp-v6-mini`; назви старих моделей продовжують підтримуватися.
- `lyric`: текст пісні в користувацькому режимі Suno. Для `chirp-v3-5` і `chirp-v4` максимум 3000 символів; для `chirp-v4-5` і вище (включно з `chirp-v5`, `chirp-v5-5`) максимум 5000 символів.
- `custom`: чи використовувати користувацький режим, за замовчуванням: `false`.
- `instrumental`: опція інструментальної музики в режимі натхнення Suno.
- `title`: назва музики в користувацькому режимі Suno. Для `chirp-v3-5`, `chirp-v4` максимум 80 символів; для `chirp-v4-5` і вище максимум 100 символів.
- `style`: музичний стиль у користувацькому режимі Suno. Для `chirp-v3-5` і `chirp-v4` максимум 200 символів; для `chirp-v4-5` і вище (включно з `chirp-v5`, `chirp-v5-5`) максимум 1000 символів.
- `negative_tags`: музичні стилі або жанри, які потрібно виключити з результату генерації в користувацькому режимі (коли `custom` має значення `true`).
- `audio_weight`: частка завантаженого еталонного аудіо, діапазон 0-1, чим більше значення, тим більша залежність від еталонного аудіо.
- `audio_id`: ID еталонної музики.
- `overpainting_start`/`overpainting_end`: час початку та завершення додавання вокалу до наявної інструментальної музики, в секундах.
- `underpainting_start`/`underpainting_end`: час початку та завершення додавання акомпанементу до співу акапела, в секундах.
- `persona_id`: ID пісні виконавця.
- `continue_at`: межа продовження, в секундах. Наприклад, 213.5 означає генерування наступного фрагмента, починаючи з 3 хвилин 33.5 секунди. `lyric` і `style` спрямовують лише новий вміст після межі та не замінюють текст пісні або вокал у вихідному аудіо до межі.
- `style_influence`: розширений параметр «Style Influence» у користувацькому режимі, діапазон 0-1, чим більше значення, тим точніше відповідатиме вибраному стилю.
- `replace_section_end`: кінцевий час фрагмента для заміни.
- `replace_section_start`: початковий час фрагмента для заміни.
- `vocal_gender`: керує перевагою жіночого або чоловічого голосу, жіночий голос — `f`, чоловічий голос — `m`, діє для моделей 4.5 і вище; є параметром переваги та не гарантує суворого дотримання.
- `weirdness`: розширений параметр «Weirdness» у користувацькому режимі, діапазон 0-1, чим більше значення, тим більше креативності та експериментальності.
- `duration`: бажана тривалість пісні, в секундах, має бути цілим числом, допустимий діапазон від 10 до 360. Цей параметр використовується для генерації пісень у користувацькому режимі (коли `custom` має значення `true`). Це орієнтовна підказка, а не жорстке обмеження: модель враховуватиме її, але не гарантує досягнення; фактична тривалість готового результату визначається полем `duration` у відповіді та зазвичай є коротшою за бажане значення.
- `lyric_prompt`: prompt для генерації тексту пісні, діє тоді й лише тоді, коли `custom` має значення `true` і `lyric` не передано.
- `callback_url`: URL, на який потрібно надіслати результат через callback.
- `async`: необов’язково, коли встановлено `true`, інтерфейс негайно повертає `task_id`, не потрібно надавати `callback_url`, після чого результат отримується шляхом опитування відповідного інтерфейсу запиту завдань.

## Користувацька генерація

Якщо ви хочете користувацьки згенерувати текст пісні, можна ввести текст:

У цей час у поле `lyric` можна передати вміст, подібний до такого:

```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> Зверніть увагу, що `\n` у тексті тут є символом нового рядка. Якщо ви не знаєте, як генерувати текст пісні, можна використовувати API генерації текстів пісень, наданий AceDataCloud, щоб генерувати тексти через prompt; API: [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Далі, щоб користувацьки згенерувати пісню на основі тексту, назви та стилю, можна вказати такий вміст:

- lyric：текст пісні
- custom：вказати `true`, що означає користувацьку генерацію; значення цього параметра за замовчуванням — false, що означає генерацію за допомогою `prompt`.
- title：назва пісні.
- style：стиль пісні, необов’язково.

## Функція користувацької генерації стилю виконавця
Якщо ви хочете використовувати стиль співака для генерування пісень, спочатку згенеруйте пісню за допомогою базового використання вище,  
зрештою потрібно налаштувати цю пісню як стиль співака, потім потрібно перейти до [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona), щоб на основі згенерованого офіційно ID музики `audio_id` створити параметр ID стилю співака `persona_id`, конкретні параметри показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Після заповнення автоматично генерується такий код:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

Відповідний код Python:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Натиснувши запуск, можна побачити, що буде отримано результат, як показано нижче:

```json
{
  "success": true,
  "task_id": "7628b754-4fe7-4e79-bda4-806d0dd8bf6e",
  "data": {
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b"
  }
}
```

Ми використовуємо наведені вище `audio_id` та `persona_id`, а саме `97efc9f4-0e8d-4b3e-88df-14568fa1b11f` і `e0d7319e-aa2a-44cb-b00a-916218d7cb0b`, як приклад даних цього разу. Потім можна встановити параметр `action` на `artist_consistency` (якщо це нова версія стилю співака Persona-v2-vox, `action` необхідно встановити на `artist_consistency_vox`), а також ввести ID пісні, яку потрібно продовжити генерувати, і ID стилю співака, приклад заповнення наведено нижче:

<p><img src="https://cdn.acedata.cloud/fukijq.png" width="500" className="m-auto" /></p>

Після заповнення автоматично генерується такий код:

<p><img src="https://cdn.acedata.cloud/5uzk9d.png" width="500" className="m-auto" /></p>

Відповідний код Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "artist_consistency",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b",
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Натиснувши запуск, можна побачити, що буде отримано результат, як показано нижче:


## Функція продовження генерування

Якщо ви хочете продовжити генерування вже згенерованої пісні Suno, можна встановити параметр `action` на `extend` і ввести ID пісні, яку потрібно продовжити генерувати; ID пісні отримується відповідно до базового використання, з наведеного вище можна дізнатися, що в цей момент ID пісні має такий вигляд:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Зверніть увагу, тут `id` у тексті пісні є ID пісні після генерування; якщо ви не знаєте, як генерувати пісню, можете звернутися до базового використання вище, щоб згенерувати пісню.

Якщо ви хочете продовжити генерування власноруч завантаженої пісні, можна встановити параметр `action` на `upload_extend` і ввести ID власноруч завантаженої пісні, яку потрібно продовжити генерувати; ID пісні отримується за допомогою [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), як показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Далі необхідно заповнити текст пісні для фрагмента продовження, а також можна вказати стиль:

- lyric：використовується лише для спрямування тексту пісні нового згенерованого фрагмента після `continue_at`, не замінює текст у вихідному аудіо до цієї точки часу.
- custom：значення `true` означає користувацьке генерування, за замовчуванням цей параметр має значення false, що означає генерування за допомогою `prompt`.
- style：стиль пісні фрагмента продовження, необов’язково.
- continue_at：межа продовження, одиниця вимірювання — секунди. Наприклад, 213.5 означає початок генерування наступного фрагмента з 3 хвилин 33.5 секунди.

> `extend` використовується для продовження творчої роботи після наявної пісні, а не для заміни тексту всієї пісні. Якщо ви хочете використати новий текст для всієї пісні від початку, використовуйте `generate` для повторного генерування; якщо ви хочете переінтерпретувати пісню з посиланням на наявну пісню, можна використати `cover`. Під час передавання повного нового тексту оригінальний текст до `continue_at` усе одно не буде замінено.

Нижче збережено знімок реального історичного виклику, у якому `continue_at` дорівнює 2 секундам, тому лише перші 2 секунди належать до вихідного вмісту до межі продовження. Коли фактично виконується продовження поблизу кінця пісні, це значення слід встановити на секунду, з якої очікується початок продовження, і надавати в `lyric` лише новий фрагмент, який потрібно співати після межі.

Відповідний код Python:

```python
    "content-type": "application/json"
}

    "action": "extend",

    "lyric": "[Verse]\\nSnowflakes falling all around\\nGlistening white\\nCovering the ground\\nChildren laughing\\nFull of delight\\nIn this winter wonderland tonight\\nSanta's sleigh\\nUp in the sky\\nRudolph's nose shining bright\\nOh my\\nHear the jingle bells\\nRinging so clear\\nBringing joy and holiday cheer\\n[Verse 2]\\nRoasting chestnuts by the fire's glow\\nChristmas lights\\nThey twinkle and show\\nFamilies gathering with love and cheer\\nSpreading warmth to everyone near",
    "custom": True,
    "instrumental": False

```

## Отримання повної пісні

Результат `extend` поточної моделі зазвичай уже містить вихідне аудіо до `continue_at` і новий вміст після межі, тому спочатку визначте за фактичною тривалістю та вмістом поверненого аудіо, чи це вже повна пісня. Якщо повертається окремий фрагмент продовження або потрібно явно об’єднати історію кількох продовжень в одну пісню, тоді скористайтеся функцією з’єднання:

- action: вмістом є `concat`.
- audio_id: ID останнього фрагмента продовження.

Наприклад, якщо ID розширеної пісні: 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, тоді параметри можна встановити так:

```json
{
  "action": "concat",
  "audio_id": "0a1e1b10-c36a-41c9-9bfb-b26d9d25db98"
}
```

## Кавер-версія музики

Після продовження генерації пісні на основі початкової пісні стиль повернутої пісні може бути не зовсім відповідним. Якщо потрібно зробити кавер-версію раніше згенерованої пісні (також підтримується користувацька завантажена музика), потрібно використовувати метод створення кавер-версії музики, за допомогою якого можна вказати такий вміст:

- action：значення `cover`; якщо виконується операція створення кавер-версії для користувацької завантаженої музики, обов’язково потрібно вказати значення：`upload_cover`。
- audio_id：ID раніше згенерованої пісні。

Наприклад, якщо ID раніше згенерованої пісні：0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, тоді можна встановити параметри так:

```json
{
  "action": "cover",
  "audio_id": "0a1e1b10-c36a-41c9-9bfb-b26d9d25db98",
  "prompt": "A song for Christmas",
  "model": "chirp-v4-5"
```

## Заміна фрагмента

Коли після генерації пісні потрібно виконати вторинне створення з окремою операцією заміни фрагмента пісні, можна виконати операцію заміни певного фрагмента пісні.

> ⚠️ **Увага**：`replace_section_result_mode` за замовчуванням має значення `full_song`：система окремо з’єднає 2 новозгенеровані варіанти та поверне 2 повні пісні. Якщо потрібні лише варіанти фрагментів заміни, які ще не були з’єднані, явно встановіть значення `candidates`, а потім виберіть варіант і викличте [З’єднання музики](#音乐拼接)。

Опис параметрів такий:

- action：значення `replace_section`。
- audio_id：ID оригінальної пісні (вихідної пісні, що замінюється)。
- model: модель генерації пісні。
- lyric: повний текст пісні після заміни (включно із заміненим фрагментом і його контекстом, узгоджений із вмістом у `prompt`)。
- prompt：новий текст тієї частини, яку потрібно замінити。
- style：стиль пісні, необов’язково。
- replace_section_start：час початку замінюваного фрагмента в оригінальній пісні (секунди)。
- replace_section_end：час завершення замінюваного фрагмента в оригінальній пісні (секунди)。
- replace_section_result_mode：режим повернення, за замовчуванням `full_song`。`full_song` окремо з’єднує 2 варіанти та повертає 2 повні пісні；`candidates` повертає 2 фрагменти-варіанти, які ще не були з’єднані。

## Керування тривалістю пісні

За замовчуванням тривалість згенерованої пісні визначається моделлю самостійно, зазвичай вона становить від 30 секунд до 4 хвилин. Якщо потрібен довший або коротший готовий результат, можна вказати бажану тривалість через параметр `duration`, одиниця вимірювання — секунди, значенням є ціле число від 10 до 360.

Цей параметр використовується для генерації пісень у користувацькому режимі (`custom` має значення `true`). Слід особливо зазначити, що `duration` є **орієнтовною підказкою, а не жорстким обмеженням**: модель враховуватиме це значення під час створення, але не гарантує його досягнення; на практиці фактична тривалість зазвичай помітно коротша за бажане значення, а тривалість двох пісень, повернутих в одному запиті, також може відрізнятися в кілька разів. Навіть для повністю однакових запитів тривалість, отримана внаслідок кількох надсилань, може істотно відрізнятися. Тому не слід використовувати його як точний контроль тривалості; якщо для бізнесу потрібна фіксована тривалість, після отримання готового результату виконайте обрізання самостійно або повторіть спробу.

Відповідний код Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Слід зазначити, що `duration` у запиті — це **бажана тривалість**, а поле `duration` кожної пісні в `data` відповіді — це **фактична тривалість** цієї пісні. Назви в них однакові, але значення різні; фактична тривалість не гарантується рівною бажаному значенню. Довжина тексту пісні є одним з основних факторів, що впливають на тривалість готового результату; якщо потрібен довший готовий результат, рекомендується одночасно надати повніший текст пісні.

Інтерфейс не виконує додаткової перевірки `duration`, параметр буде передано моделі без змін. Якщо передано значення, яке не підтримується поточним режимом або моделлю, це може проявитися як ігнорування цього значення; рекомендується спочатку підтвердити ефект одним запитом, а потім використовувати масово.

## Функція творчості на основі натхнення Inspo

Функція творчості на основі натхнення Inspo може генерувати нову музику на основі від 1 до 4 повних еталонних аудіозаписів, підтримуючи перетягування або завантаження аудіо як джерела натхнення. API використовує наявну дію `inspo`: клієнт надає загальнодоступні URL-адреси аудіо, а сервіс автоматично виконує підготовку еталонного аудіо та створення, без потреби клієнту окремо зчитувати текст, стиль або тривалість, а потім формувати запит. Вона відрізняється як від описаного вище інтервального семплювання, так і від Cover, що відтворює стиль оригінальної пісні. Під час використання потрібно заповнити такі параметри:

- action: значення — `inspo`.
- audio_urls: список URL-адрес еталонного аудіо; потрібно надати від 1 до 4 загальнодоступних аудіоадрес.
- model: використовувана модель, рекомендовано `chirp-v6`.
- prompt: текст пісні або підказка для творчості (необов’язково).

> Примітка: еталонне аудіо має бути загальнодоступним аудіофайлом. Якщо еталонне аудіо повністю збігається з відомим записом у музичній бібліотеці платформи, Suno може відмовити в генерації через перевірку авторських прав; рекомендується використовувати власне аудіо або аудіо, згенероване Suno, як джерело натхнення.

Відповідний код Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Асинхронний зворотний виклик

Оскільки Suno генерує музику відносно довго, приблизно 1–2 хвилини, якщо API тривалий час не відповідає, HTTP-запит постійно підтримуватиме з’єднання, що призводить до додаткового споживання системних ресурсів, тому цей API також підтримує асинхронні зворотні виклики.

Загальний процес такий: коли клієнт надсилає запит, він додатково вказує поле `callback_url`, після того як клієнт надсилає API-запит, API одразу повертає результат, що містить інформацію про поле `task_id`, яке представляє ID поточного завдання. Після завершення завдання результат генерації музики буде надіслано у вигляді POST JSON на вказаний клієнтом `callback_url`, який також містить поле `task_id`, таким чином результати завдання можна пов’язати за ID.

Нижче ми на прикладі розглянемо, як саме це зробити.

Спочатку Webhook-зворотний виклик — це сервіс, який може отримувати HTTP-запити, розробнику слід замінити його на URL власного розгорнутого HTTP-сервера. Для зручності демонстрації тут використовується публічний зразковий вебсайт Webhook https://webhook.site/, відкривши цей вебсайт, можна отримати Webhook URL, як показано на зображенні:
