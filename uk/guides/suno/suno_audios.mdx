Зі зростанням застосування ШІ різні програми ШІ поступово набули поширення. ШІ поступово проник у всі аспекти роботи та життя людей. А галузей, яких стосується ШІ, також стає дедалі більше: від початкового письменництва, до медицини й освіти, і аж до нинішньої музики.

Suno — це професійна високоякісна платформа для створення пісень і музики за допомогою ШІ. Користувачам достатньо ввести прості текстові підказки, щоб на основі жанру, стилю та тексту пісні генерувати пісні з вокалом. Цей генератор музики на основі ШІ розроблений членами команди з відомих технологічних компаній, таких як Meta, TikTok, Kensho тощо, з метою не потребувати жодних інструментів чи музичних інструментів, щоб кожен міг створювати чудову музику.

Нижче наведено прогрес оновлення моделей:

| Версія      | model           | Час запуску       | Обмеження lyric | Обмеження style | Максимальна тривалість пісні |
| ------- | --------------- | ---------- | -------- | -------- | ------ |
| v6      | chirp-v6        | 2026.09.09 | —        | —        | —      |
| v6 Wild | chirp-v6-wild   | 2026.09.09 | —        | —        | —      |
| v6 Mini | chirp-v6-mini   | 2026.09.09 | —        | —        | —      |
| v5.5    | chirp-v5-5      | 2026.03.27 | 5000     | 1000     | 8 хвилин   |
| v5      | chirp-v5        | 2025.09.23 | 5000     | 1000     | 8 хвилин   |
| v4.5+   | chirp-v4-5-plus | 2025.07.17 | 5000     | 1000     | 8 хвилин   |

| v3.5    | chirp-v3-5      | ---        | 3000     | 200      | 120 секунд  |

> Обмеження `lyric` і `style` у наведеній вище таблиці є верхніми межами в користувацькому режимі (`custom` дорівнює `true`). У некористувацькому режимі натхнення (`custom` дорівнює `false`) заповнюється лише `prompt`, а його максимальна довжина становить 500 символів (однаково для всіх моделей).

Suno тепер підтримує `chirp-v6`, `chirp-v6-wild` і `chirp-v6-mini`. Рекомендується використовувати `chirp-v6`; назви старих моделей залишаються сумісними.

Однак офіційно Suno не надає API, а AceDataCloud надає набір API для Suno, що імітує інтеграцію з офіційним Suno та дає змогу зручно й швидко генерувати бажану музику.

## Подання заявки та використання

Щоб використовувати Suno Audios Generation API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати свій API Token, і збережіть його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли в систему або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу для реєстрації та входу, а після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, не потрібно подавати заявку окремо для кожного сервісу.** Під час першого подання заявки надається безкоштовна квота для безкоштовного тестування; якщо квоти недостатньо, можна поповнити універсальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

## Базове використання

Яку пісню ви хочете, можна довільно ввести фрагмент тексту. Наприклад, якщо я хочу згенерувати пісню про Різдво, можна ввести `a song for Christmas`, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Тут можна побачити, що ми налаштували Request Headers, зокрема:

- `accept`: у якому форматі хочете отримати результат відповіді; тут вказано `application/json`, тобто формат JSON.
- `authorization`: ключ для виклику API, після подання заявки його можна безпосередньо вибрати зі спадного списку.

Також налаштовано Request Body, зокрема:
- `action`: тип аудіозавдання, за замовчуванням — `generate`. Підтримує операції генерації, продовження, кавер-версії, поєднання, поділу на доріжки, додавання аудіодоріжки, вилучення вказаної аудіодоріжки, генерації звукових ефектів і налаштування швидкості тощо, усе викликається через `POST /suno/audios`.
- `prompt`: підказка режиму натхнення Suno (діє, коли `custom` має значення `false`), максимум 500 символів.
- `model`: модель для цього завдання генерації музики. Серія v6 включає `chirp-v6`, `chirp-v6-wild` і `chirp-v6-mini`; назви старих моделей і надалі сумісні.
- `max_mode`: режим покращеної генерації. Для `generate` вмикається лише тоді, коли і `custom`, і `max_mode` мають значення `true`, вартість становить 1.12 Credits; для `add_stem` може вмикатися безпосередньо, вартість становить 1.344 Credits. Якщо вимкнено або пропущено, вартість відповідно становить 0.56 і 0.672 Credits.
- `variety`: інтенсивність різноманітності результатів генерації, можливі значення `off`, `normal`, `high`, `extra`, `max`. Використовується лише для `generate` і `add_stem`; передавання для інших action поверне 400.
- `lyric`: вміст тексту пісні для користувацького режиму Suno. Для `chirp-v3-5` і `chirp-v4` максимум 3000 символів; для `chirp-v4-5` і вище (включно з `chirp-v5`, `chirp-v5-5`) максимум 5000 символів.
- `custom`: чи використовувати користувацький режим, за замовчуванням: `false`.
- `instrumental`: опція інструментальної музики режиму натхнення Suno.
- `title`: назва музики для користувацького режиму Suno. Для `chirp-v3-5`, `chirp-v4` максимум 80 символів; для `chirp-v4-5` і вище максимум 100 символів.
- `style`: музичний стиль користувацького режиму Suno. Для `chirp-v3-5` і `chirp-v4` максимум 200 символів; для `chirp-v4-5` і вище (включно з `chirp-v5`, `chirp-v5-5`) максимум 1000 символів.
- `negative_tags`: музичні стилі або жанри, які потрібно виключити під час користувацької генерації, також може використовуватися для `replace_section`. Наразі цей інтерфейс не встановлює фіксованого обмеження кількості символів для цього поля; надто довгий вміст усе одно може не обробитися, рекомендується зберігати опис стислим.
- `audio_weight`: вага впливу аудіо або характеристик голосу, діапазон 0-1, `0` також є дійсним значенням. Може використовуватися для генерації, продовження, кавер-версії, додавання аудіодоріжки та узгодженості голосу тощо; за відсутності референсного аудіо або характеристик голосу модель може послабити або проігнорувати це значення.
- `audio_id`: ID референсної музики, використовується для подальших операцій, таких як кавер-версія, продовження, поділ на доріжки тощо. Аудіофайл усе ще може бути доступний для завантаження, але це не означає, що подальша обробка цього ID завжди доступна; якщо повертається `suno_processing_unavailable`, збережіть `task_id` і `trace_id` та зверніться до підтримки.
- `overpainting_start`/`overpainting_end`: час початку та завершення додавання вокалу до наявної інструментальної музики, у секундах.
- `underpainting_start`/`underpainting_end`: час початку та завершення додавання акомпанементу до акапельного співу, у секундах.
- `persona_id`: ID голосу, отриманий через інтерфейс створення Persona або голосу, а не `audio_id` пісні.
- `continue_at`: межа продовження, у секундах. Наприклад, 213.5 означає генерувати наступний фрагмент, починаючи з 3 хвилин 33.5 секунди. `lyric` і `style` спрямовують лише новий вміст після межі та не замінюють текст пісні або спів до межі у вихідному аудіо.
- `style_influence`: вплив стилю в користувацькому режимі, діапазон 0-1; чим більше значення, тим зазвичай точніше відповідність вибраному стилю; `0` передається як дійсне значення.
- `replace_section_end`: кінцевий час фрагмента для заміни.
- `replace_section_start`: початковий час фрагмента для заміни.
- `vocal_gender`: керує перевагою жіночого або чоловічого голосу, жіночий голос — `f`, чоловічий голос — `m`, діє для моделей 4.5 і вище; є параметром переваги, суворе дотримання не гарантується.
- `weirdness`: рівень дивності в користувацькому режимі, діапазон 0-1; чим більше значення, тим зазвичай більше творчості та експериментальності; `0` передається як дійсне значення.
- `duration`: бажана тривалість пісні, у секундах, має бути цілим числом, діапазон значень від 10 до 360. Наразі цей параметр використовує лише `generate`, конкретний ефект залежить від режиму та моделі. Це орієнтовна підказка, а не жорстке обмеження: модель зважатиме на неї, але не гарантує досягнення, фактична тривалість готового результату визначається полем `duration` у відповіді та зазвичай є коротшою за бажане значення.

### Сфера застосування ID голосу

`generate`, `cover`, `upload_cover`, `artist_consistency`, `artist_consistency_vox` можуть використовувати `persona_id`. Останні два action повинні надавати `persona_id`; також можна одночасно надати `audio_id` пісні, використаної під час створення цього Persona.

`extend`, `upload_extend` не використовують додатковий `persona_id`. Чи підтримують `mashup`, `inspo` ID голосу, залежить від вибраного сервісного каналу; для інших action застосування цього поля не гарантується, використовуйте відповідно до опису кожної операції. `vocal_gender` є необов’язковою гендерною перевагою та не може замінити ID голосу.

Подальші операції створення потребують дійсного вихідного `audio_id`; `mashup` потребує щонайменше два `mashup_audio_ids`. За відсутності необхідного джерела або параметрів часу буде повернено HTTP 400.

### Сфера застосування розширених параметрів
| Параметр                | Значення                                          | Підтримувані action                              | Опис                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | Необов’язково                                      | Регулює експериментальність, `0` є допустимим значенням; ефект залежить від операції, режиму та моделі      |
| `style_influence` | 0-1                                         | Необов’язково                                      | Регулює схильність до дотримання стилю, `0` є допустимим значенням; ефект залежить від операції, режиму та моделі   |
| `audio_weight`    | 0-1                                         | Необов’язково                                      | Регулює вплив аудіо або голосових характеристик; без довідкової інформації може бути проігноровано моделлю        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`、`add_stem`                   | Регулює стильову різноманітність між результатами                       |
| `max_mode`        | boolean                                     | `generate`（потребує `custom=true`）、`add_stem` | Підвищує узгодженість і тарифікується за посиленим режимом                     |
| `vocal_gender`    | `f` / `m`                                   | Операції генерації, що підтримують керування вокалом                             | Налаштування переваги, суворе дотримання не гарантується                       |
| `duration`        | Ціле число 10-360                                   | `generate`                              | Бажана тривалість; інші action наразі не використовують це поле, фактична довжина визначається результатом |

Платформа перевіряє типи параметрів і діапазони значень, але не відхиляє ці необов’язкові налаштування лише через різницю в action; конкретний ефект залежить від операції, режиму та моделі.

- `lyric_prompt`：prompt для генерації тексту пісні, діє тоді і лише тоді, коли `custom` має значення `true` і `lyric` не передано.
- `callback_url`：URL, на який потрібно надіслати результат зворотним викликом.
- `async`：необов’язково, якщо встановити значення `true`, інтерфейс негайно повертає `task_id`, без потреби надавати `callback_url`, після чого результат можна отримати шляхом опитування через відповідний інтерфейс запиту завдань.

## Власна генерація

Якщо ви хочете власноруч задати генерацію тексту пісні, можна ввести текст пісні:

У цей момент у поле `lyric` можна передати вміст, подібний до наведеного нижче:

## Функція продовження генерації
Якщо ви хочете продовжити вже згенеровану пісню Suno, можна встановити параметр `action` на `extend` і ввести ID пісні, яку потрібно продовжити. ID пісні отримується відповідно до базового використання; як видно з наведеного вище, у цей момент можна побачити, що ID пісні має значення:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Зверніть увагу, що `id` у тексті пісні тут є ID пісні після її генерації. Якщо ви не знаєте, як генерувати пісні, можете звернутися до наведеного вище базового використання для генерації пісні.

Якщо ви хочете продовжити пісню, яку завантажили самостійно, можна встановити параметр `action` на `upload_extend` і ввести ID завантаженої користувацької пісні, яку потрібно продовжити. ID пісні отримується за допомогою [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), як показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Далі необхідно заповнити текст продовжуваного фрагмента, а також можна вказати стиль:

- lyric：використовується лише для спрямування тексту новоствореного фрагмента після `continue_at`, не замінюватиме текст у вихідному аудіо до цієї часової точки.
- custom：значення `true` означає користувацьку генерацію; значення цього параметра за замовчуванням — false, що означає генерацію з використанням `prompt`.
- style：стиль пісні для продовжуваного фрагмента, необов’язково.
- continue_at：межа продовження, у секундах. Наприклад, 213.5 означає початок генерації наступного фрагмента з позначки 3 хвилини 33.5 секунди.

Значення `continue_at` для `extend` і `upload_extend` має бути більшим за 0, підтримуються дробові секунди, наприклад `30.792`; під час надсилання значення не округлюється.

> `extend` використовується для продовження творчої роботи після наявної пісні, а не для заміни тексту всієї пісні. Якщо ви хочете використати новий текст для всієї пісні від початку, використовуйте `generate` для повторної генерації; якщо ви хочете переосмислити пісню з посиланням на наявну, можна використати `cover`. У разі передавання цілого нового тексту оригінальний текст до `continue_at` усе одно не буде замінений.

Після завершення заповнення код автоматично генерується так:

<p><img src="https://cdn.acedata.cloud/wwpw78.png" width="500" className="m-auto" /></p>

Нижче збережено знімок одного реального історичного виклику, у якому `continue_at` дорівнює 2 секундам, тому лише перші 2 секунди належать до оригінального вмісту перед межею продовження. Під час фактичного продовження ближче до кінця пісні це значення слід встановити на секунду, з якої очікується початок продовження, і надавати в `lyric` лише новий фрагмент, який має виконуватися після межі.

```python
    "content-type": "application/json"
}

    "action": "extend",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "continue_at": 2,
    "lyric": "[Verse]\\nSnowflakes falling all around\\nGlistening white\\nCovering the ground\\nChildren laughing\\nFull of delight\\nIn this winter wonderland tonight\\nSanta's sleigh\\nUp in the sky\\nRudolph's nose shining bright\\nOh my\\nHear the jingle bells\\nRinging so clear\\nBringing joy and holiday cheer\\n[Verse 2]\\nRoasting chestnuts by the fire's glow\\nChristmas lights\\nThey twinkle and show\\nFamilies gathering with love and cheer\\nSpreading warmth to everyone near",
    "custom": True,
    "instrumental": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Кавер-версія музики

Коли пісня генерується далі на основі наявної пісні, стиль поверненої пісні може бути не зовсім відповідним. Якщо потрібно створити кавер-версію раніше згенерованої пісні (також підтримується власноруч завантажена музика), потрібно використовувати метод кавер-версії музики, за допомогою якого можна вказати такий вміст:

- action：значення — `cover`, а під час створення кавер-версії власноруч завантаженої музики обов’язково потрібно вказати значення: `upload_cover`。
- audio_id：ID раніше згенерованої пісні.

Якщо потрібно виконати кавер із використанням указаного голосу, можна також передати `persona_id`. Приватний голос, створений через `/suno/voices`, потрібно спочатку використати для завантаження оригінальної пісні в `/suno/upload` із тим самим `persona_id`, а потім використати повернений `audio_id` для `upload_cover`. На всіх етапах потрібно використовувати той самий сервісний канал. Не потрібно додатково вказувати `vocal_gender`, перевага статі не може замінити ID голосу.

Наприклад, якщо ID раніше згенерованої пісні: 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, тоді параметри можна встановити так:

```json
{
  "action": "cover",
  "audio_id": "0a1e1b10-c36a-41c9-9bfb-b26d9d25db98",
  "prompt": "A song for Christmas",
  "model": "chirp-v4-5"
}
```

## Заміна фрагмента

`replace_section` повторно генерує вибраний фрагмент відповідно до часового інтервалу вихідної пісні та з’єднує результат назад з оригінальною композицією. `replace_section_result_mode` за замовчуванням має значення `full_song`, повертаючи 2 повні пісні, які можна відтворювати безпосередньо, без потреби повторно викликати `concat`.

### Як заповнити введення
- `action`: `replace_section`.
- `audio_id`: повний ID пісні, яку потрібно редагувати. Під час повторного редагування використовуйте `data[].id` повної пісні, вибраної минулого разу, а не `task_id`.
- `model`: модель генерації пісні, наприклад `chirp-v6`.
- `lyric`: **локальний новий текст** для виконання у вибраному інтервалі. Не потрібно передавати текст усієї пісні, щоб отримати повну пісню.
- `prompt`: чітко вказує локальний новий текст, який цього разу замінюється. Під час зміни тексту рекомендується вказувати той самий вміст, що й у `lyric`, щоб уникнути вираження різного тексту в двох полях. Існуючі запити, що передають лише локальний `lyric` і пропускають `prompt`, все ще можна використовувати, але додавання самого `prompt` не гарантує успіху зміни тексту.
- `style`, `negative_tags`: необов’язковий опис стилю та виключення; `prompt` у цій операції не є звичайним описом натхнення під час створення пісні.
- `replace_section_start`, `replace_section_end`: час початку та завершення вибраного інтервалу у вихідній пісні цього разу, у секундах, підтримуються дробові значення. Початкова точка не може бути меншою за 0, кінцева точка має бути більшою за початкову та не може перевищувати тривалість вихідної пісні.
- `replace_section_result_mode`: `full_song` (за замовчуванням) повертає 2 повні пісні; `candidates` повертає 2 кандидати на заміну, які ще не з’єднані.

Не використовуйте «`lyric` має бути повним текстом після заміни, а `prompt` має бути локальним текстом» як загальний спосіб використання. Введення повного тексту в деяких завданнях може створити надто довгий вміст заміни, що після з’єднання значно подовжить всю пісню. Локальне введення також не гарантує фіксованої тривалості або дослівного дотримання тексту; це генеративне редагування, потрібно перевіряти фактичне аудіо.

### Створення завдання та отримання повної пісні

Нижче наведено приклад формату запиту. Замініть `YOUR_COMPLETED_AUDIO_ID` і часовий інтервал на власний ID вихідної пісні та фактичний вибраний інтервал; приклад припускає, що секунди 30–50 відповідають наведеним нижче чотирьом рядкам.

```json
{
  "action": "replace_section",
  "audio_id": "YOUR_COMPLETED_AUDIO_ID",
  "model": "chirp-v6",
  "custom": false,
  "instrumental": false,
  "lyric": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "prompt": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "replace_section_start": 30.0,
  "replace_section_end": 50.0,
  "replace_section_result_mode": "full_song",
  "async": true
}
```

Після надсилання використовуйте повернений `task_id` для запиту до `/suno/tasks`, тіло запиту: `{"action":"retrieve","id":"YOUR_TASK_ID"}`. Після завершення завдання отримайте `id`, `audio_url` і `duration` двох повних пісень у `response.data` відповіді завдання, прослухайте їх і виберіть одну з них. `success: true` означає, що завдання успішно виконано, але не означає, що новий текст заспівано дослівно або що тривалість відповідає очікуванням.

### Вибраний інтервал, перевірка результатів і повторне редагування

1. Спочатку прослухайте вихідну пісню, потім визначте вибраний інтервал на основі часової інформації з `/suno/timing`, намагаючись охопити повні музичні фрази. Не вибирайте інтервал за фіксованими індексами масиву текстів і не замінюйте кількома рядками інтервал, що містить більше музичних фраз, очікуючи, що ритм залишиться повністю незмінним.
2. Кількість рядків, кількість символів і ритм нового тексту мають якомога більше відповідати наявному вмісту вибраного інтервалу. Навіть якщо змінено лише кілька символів, потрібна перевірка прослуховуванням; на цій підставі не можна гарантувати успіх.
3. Перевірте, чи заспівано новий текст у цільовому інтервалі, чи природно з’єднуються частини до і після нього, а також чи є тривалість усієї пісні обґрунтованою. `full_song` означає повернення повної пісні, а не те, що вона має таку саму тривалість, як оригінал; якщо замінений фрагмент подовжується, друга половина відповідно зміщується пізніше. Параметр запиту `duration` використовується лише для звичайної генерації та не може зафіксувати тривалість заміненого фрагмента.
4. Повернений `lyric` є метаданими тексту; у режимі повної пісні повний текст буде скомпоновано, якщо можна отримати часову інформацію вихідного тексту; якщо її неможливо отримати, він може бути порожнім. Це не є транскрипцією аудіо, поява нового тексту не доводить, що в аудіо вже заспівано новий текст. Інформацію про часову синхронізацію також слід звіряти з прослуховуванням, особливо для вже відредагованих результатів.
5. Під час повторного редагування використовуйте вибраний **повний ID готового результату** як новий `audio_id`, повторно перевірте тривалість і вибраний інтервал цього готового результату. Не копіюйте часові координати до редагування і не використовуйте безпосередньо весь `lyric`, повернений минулого разу, як локальне введення цього разу.

Якщо завдання завершено, але все ще виконується старий текст, пропущено текст або тривалість значно збільшилася, спочатку перевірте ID вихідної пісні, вибраний інтервал і локальний текст, а потім перевірте інший результат. Збільшення частоти запитів завдання не змінить уже згенерований вміст. Якщо аномалія все ще зберігається, збережіть `task_id`, ID вихідної пісні, поля запиту, вибраний інтервал і результуюче аудіо для полегшення перевірки.

### Необов’язково: спочатку отримати кандидатів, потім з’єднати вручну

Лише якщо потрібно самостійно вибрати кандидата на заміну, встановіть `replace_section_result_mode: "candidates"`. Кандидати можуть містити контекст, тому не можна вважати їх повними піснями лише на підставі тривалості кандидата. Після вибору викличте `concat` з `data[].id` кандидата, а потім отримайте повний готовий результат.

`full_song` за замовчуванням уже завершив з’єднання, тому цей крок виконувати не потрібно.

## Розділення вокалу та музики

Оплата: після успішного виконання `action=stems` стандартна вартість кожного запиту становить **0.56 Credits**; вокал і акомпанемент, повернуті в одному запиті, разом рахуються як один раз. Застосовні знижки на використання визначаються фактичним рахунком, за невдалі запити плата не стягується. `all_stems` і `extract_stem` оплачуються за власними тарифами.

```json
{
```

## Додавання аудіодоріжки

`add_stem` генерує цільову інструментальну або звукову доріжку для вказаного аудіо через виклик `POST /suno/audios`.
- Обов’язкові: `action`, `audio_id`, `stem_type`。
- Необов’язкові: `model`, `prompt`, `title`, `style`, `negative_tags`, `weirdness`, `style_influence`, `audio_weight`, `max_mode`, `variety`。
- Тарифікація: звичайний режим 0.672 Credits; коли `max_mode` має значення `true` — 1.344 Credits。

```json
{
  "action": "add_stem",

  "style": "minimal piano pulse with warm bass guitar",
  "negative_tags": "vocals",

}
```

## Вилучення аудіодоріжки

`extract_stem` вилучає цільову аудіодоріжку із зазначеного аудіо, одночасно повертаючи додаткову версію після видалення цієї аудіодоріжки, викликається через `POST /suno/audios`。

## Налаштування швидкості аудіо
`adjust_speed` регулює швидкість відтворення вказаного аудіо, викликається через `POST /suno/audios`.

- Обов’язкові: `action`, `audio_id`, `speed_multiplier`, `title`.
- Необов’язковий: `keep_pitch`.
- `speed_multiplier`: діапазон 0.25–4.
- Вартість: 0.28 Credits.

```json
{
  "action": "adjust_speed",

  "keep_pitch": true,

  "async": true
```

## Розширені параметри для користувацької генерації

Офіційно дозволено використовувати розширені параметри `weirdness`==>`Weirdness`, `style_influence`==>`Style Influence`, `audio_weight`==>`Audio Influence` для генерації в користувацькому режимі, відповідні офіційні приклади наведено нижче:

<p><img src="https://cdn.acedata.cloud/1xonxy.png" width="500" className="m-auto" /></p>

Усі розширені параметри мають діапазон від 0 до 1, конкретні параметри показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/7i94ih.png" width="500" className="m-auto" /></p>

Після заповнення код автоматично генерується наступним чином:

<p><img src="https://cdn.acedata.cloud/2dlbo6.png" width="500" className="m-auto" /></p>

Відповідний код Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v4-5",
    "lyric": "Hello Hello Hello ",
    "custom": True,
    "weirdness": 0.4,
    "style_influence": 0.4,
    "audio_weight": 0.4
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Керування тривалістю пісні

За замовчуванням тривалість згенерованої пісні визначається самою моделлю, зазвичай від 30 секунд до 4 хвилин. Якщо потрібен довший або коротший готовий результат, можна вказати бажану тривалість через параметр `duration`, одиниця вимірювання — секунди, значення — ціле число від 10 до 360.

Цей параметр використовується для генерації пісень у користувацькому режимі (`custom` має значення `true`). Особливо слід зазначити, що `duration` є **орієнтовною підказкою, а не жорстким обмеженням**: модель враховуватиме це значення під час створення, але не гарантує його досягнення; у тестах фактична тривалість зазвичай помітно коротша за очікуване значення, а тривалість двох пісень, повернених одним запитом, також може відрізнятися в кілька разів. Навіть для повністю однакових запитів тривалість, отримана внаслідок кількох надсилань, також може значно відрізнятися. Тому не використовуйте його як точне керування тривалістю; якщо для бізнесу потрібна фіксована тривалість, самостійно обріжте результат або повторіть спробу після отримання готового матеріалу.

Відповідний код Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Слід зазначити, що `duration` у запиті є **очікуваною тривалістю**, тоді як поле `duration` кожної пісні в `data` відповіді є **фактичною тривалістю** цієї пісні. Назви в них однакові, але значення різне; фактична тривалість не гарантується рівною очікуваному значенню. Довжина тексту пісні є одним з основних чинників, що впливають на тривалість готового результату; якщо потрібен довший результат, рекомендується водночас надати повніший текст пісні.

Інтерфейс перевіряє, що `duration` має бути цілим числом від 10 до 360; він усе ще є лише ціллю генерації, а не гарантією тривалості готового результату.

## Функція творчості на основі натхнення Inspo

Функція творчості на основі натхнення Inspo може генерувати нову музику на основі від 1 до 4 повних еталонних аудіозаписів, підтримує перетягування або завантаження аудіо як джерела натхнення. API використовує наявну дію `inspo`: клієнт надає загальнодоступні URL-адреси аудіо, а сервіс автоматично виконує підготовку еталонних аудіо та створення, без потреби клієнту окремо зчитувати текст, стиль або тривалість, а потім збирати запит. Вона відрізняється від вибірки діапазону вище, а також від Cover, що відтворює стиль оригінальної пісні. Під час використання потрібно заповнити такі параметри:

- action: значення `inspo`.
- audio_urls: список URL-адрес еталонних аудіо, потрібно надати від 1 до 4 загальнодоступних аудіоадрес.
- model: використовувана модель, рекомендовано `chirp-v6`.
- prompt: текст пісні або підказка для створення (необов’язково).
- instrumental: якщо встановити `true`, генерація виконується за запитом на інструментальну музику, без використання тексту пісні.
- persona_id: використовувати вказаний голос у каналі сервісу, що підтримує цю комбінацію; еталонне аудіо буде прив’язане на етапі підготовки до ресурсного середовища, потрібного для цього голосу.
- lyric_prompt: коли `custom=true` і не надано `lyric`, використовується для автоматичної генерації тексту пісні.

> Примітка: еталонне аудіо має бути загальнодоступним аудіофайлом. Якщо еталонне аудіо повністю збігається з відомим записом у музичній бібліотеці платформи, Suno може відхилити генерацію через перевірку авторських прав; рекомендовано використовувати власне аудіо або аудіо, згенероване Suno, як джерело натхнення.

Відповідний код Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Асинхронний зворотний виклик

Оскільки Suno генерує музику відносно довго, приблизно 1–2 хвилини, якщо API довго не відповідає, HTTP-запит постійно підтримуватиме з'єднання, що призводить до додаткового споживання системних ресурсів, тому цей API також надає підтримку асинхронних зворотних викликів.

Загальний процес такий: коли клієнт надсилає запит, він додатково вказує поле `callback_url`; після того як клієнт надсилає API-запит, API негайно повертає результат, що містить поле `task_id`, яке представляє ID поточного завдання. Коли завдання буде завершено, результат генерації музики буде надіслано у форматі POST JSON на `callback_url`, вказаний клієнтом, де також міститься поле `task_id`, тож результати завдання можна пов'язати за ID.

Нижче ми на прикладі дізнаємося, як саме це зробити.

Спочатку Webhook-зворотний виклик — це сервіс, який може приймати HTTP-запити; розробник має замінити його на URL власного HTTP-сервера. Тут для зручності демонстрації використовується публічний сайт-приклад Webhook https://webhook.site/; відкривши цей сайт, можна отримати Webhook URL, як показано на зображенні:

![](https://cdn.acedata.cloud/fwfqin.png)
