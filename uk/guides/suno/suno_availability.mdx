---
title: "API перевірки доступності аудіо Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` шукає за `audio_id` позитивні докази того, що аудіо може бути продовжене для обробки на поточному маршруті. Можна викликати перед такими операціями, як продовження, кавер тощо; результат відображає лише стан на момент перевірки та не гарантує, що певна конкретна операція обов’язково буде успішною. Цей інтерфейс синхронно повертає відповідь, потребує API Token і наразі не списує Credits.

`audio_id` — це ID пісні, повернений завершеним завданням Suno, а не `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Приклад успішної відповіді:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

Коли перевірка успішна, `data.available` може бути лише `true`. Статус «не в мережі», який повертають деякі маршрути, не може довести, що подальші операції, як-от продовження, не можуть бути успішними, тому цей інтерфейс повертає `503 availability_unknown`, коли неможливо підтвердити, і не повертає `false`. Помилка формату `audio_id` повертає 400, обмеження швидкості або збій у висхідному сервісі також повертають відповідь із помилкою. Стан усе ще може змінитися між завершенням перевірки та фактичною операцією.
