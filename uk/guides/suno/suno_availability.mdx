---
title: "API перевірки доступності аудіо та голосу Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` приймає ID ресурсу. Для перевірки пісні передайте `audio_id`, для перевірки голосу — `persona_id`; один із них є обов’язковим. Перевірка виконується синхронно, потребує API Token і наразі не списує Credits.

## Запит

`audio_id` походить із завершеного завдання пісні та може використовуватися для перевірки перед продовженням або кавером.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

`persona_id` походить із результату створення голосу. Використовуйте початковий застосунок та ідентичність викликача, і на маршруті створення, що підтримує запити голосів, надішліть такий JSON-запит.

```json
{"persona_id":"33333333-3333-4333-8333-333333333333"}
```

## Відповідь

Обидва типи запитів використовують одну й ту саму успішну відповідь. `data.id` — це ID ресурсу в цьому запиті.

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

`available: true` означає, що ця перевірка отримала позитивні докази. Для голосів перевірка підтверджує належність створення та підтверджує, що пов’язаний обліковий запис наразі позначено як онлайн. Фактичний результат генерації все одно визначається завданням генерації.

Приватні клоновані голоси, створені через `/suno/voices`, залежать від облікового запису, що їх створив. Коли підтверджено, що цей обліковий запис наразі офлайн, інтерфейс повертає HTTP 200, а приклад `data` наведено нижче.

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

Клієнт може позначити цей голос як наразі недоступний і перевірити його пізніше.

Коли підтвердження неможливе, повертаються HTTP 503 та `availability_unknown`, наприклад, якщо ресурс не знайдено, у старому записі відсутній маршрут створення або сплив час очікування запиту. Публічні стилі співаків можуть використовуватися між обліковими записами; коли обліковий запис створення офлайн, також повертається 503. Запити пісень, як і раніше, повертають `available: true` лише за підтвердженої доступності.

Для кожного запиту надсилайте лише один дійсний UUID. Коли всі маршрути отримують запит з обома ID або без обох ID, вони повертають HTTP 400. Коли маршрути, що підтримують лише запити пісень, отримують запит, який містить лише `persona_id`, вони повертають HTTP 400. У разі HTTP 429 зменште частоту запитів.
