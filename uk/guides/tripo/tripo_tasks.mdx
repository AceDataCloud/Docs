---
title: "Запит завдання моделі Tripo"
description: "Tripo 3D API guide - Ace Data Cloud"
---

Викличте `POST /tripo/tasks` за допомогою токена AceDataCloud. Запит безкоштовний, використовуйте той самий обліковий запис, що й для генерації. Для окремого завдання використовуйте `id` або `trace_id`, значення `action` за замовчуванням — `retrieve`.

```bash
curl -X POST https://api.acedata.cloud/tripo/tasks \
  -H "Authorization: Bearer ${ACEDATACLOUD_API_TOKEN}" \
  -H "Content-Type: application/json" \
  -d "{\"action\":\"retrieve\",\"id\":\"${TASK_ID}\"}"
```

Результат запиту окремого завдання — це запис завдання, який містить `id`, `type`, `trace_id`, початковий запит `request`, `started_at` і `progress`. Під час обробки можна продовжувати надсилати запити з інтервалом у кілька секунд. Після завершення перевірте `response.success`: у разі успіху `response.data[0].model_url` містить адресу для завантаження, у разі невдачі `response.error` містить код і повідомлення про помилку. Часові позначки, `finished_at` і тривалість `elapsed` розташовані на верхньому рівні запису завдання та вимірюються в секундах. Якщо виникає `submission_unknown`, збережіть початковий ID завдання для перевірки.

Для пакетного запиту використовуйте `{"action":"retrieve_batch","ids":["<ID завдання 1>","<ID завдання 2>"]}`, також можна використовувати `trace_ids`; за один раз — не більше 100 записів. Відповідь має вигляд `{"items":[...],"count":2}` і зберігає порядок введення та дублікати. Для завдань, які не знайдено або на читання яких немає дозволу, окремий запит повертає `{}`, а пакетний запит — `null` у відповідній позиції.

Значення `type` у записі завдання — `generations`, `models` або `animations`. Для перевірки скелета читайте `response.data[0].riggable`, для операцій із файлами — `response.data[0].model_url`.
