Google Gemini — це дуже потужна система AI-діалогів, яка може за кілька секунд генерувати плавні та природні відповіді шляхом введення підказок. Цей документ переважно описує спосіб використання API Gemini Generate Content — це офіційний нативний формат API Google, який підтримує дві кінцеві точки: `generateContent` і `streamGenerateContent`.

## Відмінності від Chat Completions API

Gemini Generate Content API використовує офіційний нативний формат запитів Google (поле `contents`), а не формат, сумісний з OpenAI (поле `messages`). Якщо ви вже використовуєте Google Gemini SDK або знайомі з офіційним форматом API, ви можете безпосередньо використовувати цей API без зміни формату запитів.

## Поточний обсяг підтримки

Інтерфейс приймає текстовий, графічний, відео- та аудіоввід (через `inlineData` або `fileData`), конфігурацію міркувань і користувацькі оголошення функцій. Для таких нативних полів, як аудіовивід, вбудовані інструменти та явне кешування контексту, ще немає гарантії уніфікованої доступності; орієнтуйтеся на фактичну відповідь конкретної моделі.

Під час подання аудіо та інших файлів за допомогою `fileData.fileUri` переконайтеся, що файл доступний безпосередньо через HTTPS, не залежить від стану входу в систему, а термін дії підписаного посилання покриває весь час обробки запиту. Непотоковий аналіз аудіо повертає результат лише після завершення обробки моделлю, що може зайняти понад 90 секунд; клієнт повинен встановлювати достатньо тривалий загальний тайм-аут відповідно до розміру файлу та бізнес-сценарію, щоб уникнути розриву з’єднання, поки сервер все ще обробляє запит.

## Процес подання заявки

Перед використанням Gemini Generate Content API спочатку відвідайте сторінку [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api), натисніть кнопку «Отримати», щоб отримати облікові дані, необхідні для запиту.

Якщо ви ще не увійшли в систему або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу. Під час першого подання заявки надається безкоштовна квота.

## Базове використання

### Non-Streaming（непотоковий режим）

Надішліть POST-запит до `/v1beta/models/{model}:generateContent`:

> **Підказка**: flash із серії `gemini-3.x` є моделлю міркувань і спочатку споживає reasoning tokens; установіть `generationConfig.maxOutputTokens` на рівні понад 512, інакше може повернутися лише порожній вміст.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Приклад результату відповіді:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Поля token у `usageMetadata` тарифікуються відповідно до нативної семантики Gemini:

- `promptTokenCount` включає `cachedContentTokenCount`; частина, що потрапила в кеш, обчислюється за ціною читання з кешу та не буде повторно врахована як звичайний ввід.
- `promptTokensDetails` і `cacheTokensDetails` буде нормалізовано до `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` та відповідних деталей `cached_*` у межах `usage.prompt_tokens_details`. Ці значення відповідно входять до `prompt_tokens` і `cached_tokens`; різні модальності перераховуються лише за власними цінами та не тарифікуються повторно.
- `candidatesTokenCount` і `thoughtsTokenCount` обидва обчислюються за ціною вихідних token.
- `toolUsePromptTokenCount` — це незалежні token введення інструментів, які обчислюються за ціною вхідних token.

Ace Data Cloud додатково повертає нормалізований об’єкт `usage`, а витрати на цей виклик уніфіковано між протоколами моделей зчитуються з `usage.cost`. `cost` є необов’язковим попереднім переглядом витрат; коли попередній перегляд ціни тимчасово недоступний, відповідь моделі все одно повертається нормально, але може не містити цього поля. Остаточне виставлення рахунку здійснюється згідно із записами про використання.

### Streaming（потоковий режим）

Надішліть POST-запит до `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

Потокова відповідь поступово повертатиме вміст у форматі SSE (Server-Sent Events). Проміжні події зазвичай містять лише інкрементальний вміст; фінальна подія з достовірними даними про використання міститиме `usageMetadata` і нормалізований `usage`, а витрати, як і раніше, розташовані в `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

Закриття з’єднання означає завершення потоку; нативний потік Gemini не надсилає `data: [DONE]`. Якщо попередній перегляд ціни у фінальному стані тимчасово недоступний, `usage` все одно поверне використання token, але не включатиме `cost`.

Після відновлення нативного виклику надсилайте запити відповідно до контракту інтерфейсу на цій сторінці та окремо перевіряйте потрібні введення й параметри. Офіційне виведення мільйона Token для long decode не включено до поточного контракту інтерфейсу. Обидві моделі підтримують лише неявне кешування, Token міркувань обчислюються за ціною виведення; підготовлені правила ціноутворення використовують однакову ціну Token введення для кожної модальності введення, а влучання в кеш обчислюються за ціною читання з кешу, дивіться поточну сторінку цін.

### Внутрішнє мислення та підсумок міркувань

Внутрішнє мислення моделі та повернення підсумку міркувань викликачеві — це два незалежні налаштування:

- `thinkingBudget` або `thinkingLevel` контролюють внутрішній бюджет або глибину міркувань моделі, а підтримувані поля та значення залежать від моделі.
- `includeThoughts` контролює, чи повертати підсумок міркувань, за замовчуванням це `false`. Коли це поле пропущено або передано `false`, ані звичайні JSON-, ані потокові SSE-відповіді не повертатимуть текст, позначений як `thought: true`; ці тексти зберігаються лише за явної передачі булевого значення `true`.

Коли в запиті не встановлено `includeThoughts`, інтерфейс за замовчуванням передає `false` моделям генерації, що підтримують конфігурацію міркувань, щоб уникнути запиту непотрібних підсумків; значення, явно передані клієнтом, бюджет міркувань і рівень зберігаються. До відомої моделі `gemini-2.5-flash-image`, яка не підтримує конфігурацію міркувань, це поле не додається автоматично, і до запитів `countTokens` також не додається конфігурація генерації.

Вимкнення підсумків не дорівнює вимкненню внутрішнього мислення та не гарантує зменшення token внутрішнього мислення. Якщо відповідь усе ще містить незапитаний текст міркувань, звичайні JSON- і SSE-виходи додатково його відфільтрують, зберігаючи звичайну відповідь, підписи та фактичне використання.

Коли потрібно переглянути підсумок, явно увімкніть його наступним чином. Якщо модель не згенерувала доступний підсумок, тексту міркувань може не бути навіть після увімкнення:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` — це зашифрований стан, потрібний для наступних раундів, а не текст підсумку міркувань, і він не контролюється перемикачем `includeThoughts`. Підпис може міститися у звичайній відповіді, виклику функції або Part із порожнім текстом; під час фільтрації тексту міркувань підпис та інші поля того самого Part зберігаються, тому у відповіді все ще можуть бути Part, які містять лише підпис і мають порожній текст. У разі ручного ведення історії кількох раундів слід зберігати порядок цих Part і розташування підписів, не переміщувати підписи та не об’єднувати їх.

`usageMetadata` і `usage` все ще фіксують фактичне використання. Приховування підсумків не обнуляє `thoughtsTokenCount`, а розрахунок вартості все одно виконується за фактичним використанням і поточними правилами ціноутворення.

Дивіться офіційні Google [пояснення щодо мислення та підсумків міркувань](https://firebase.google.com/docs/ai-logic/thinking) і [правила підписів міркувань](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

## Налаштування безпеки

Фільтрацією вмісту можна керувати за допомогою `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Обробка помилок

| Код стану HTTP | Значення             |
| -------- | -------------- |
| 400      | Недійсні параметри запиту         |
| 401      | Помилка автентифікації, перевірте Token |
| 403      | Вміст заблоковано фільтром безпеки     |
| 429      | Запити надходять надто часто         |
| 500      | Внутрішня помилка сервера        |
