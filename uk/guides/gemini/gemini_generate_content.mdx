Google Gemini — це дуже потужна система AI-діалогів, яка може генерувати плавні та природні відповіді за лічені секунди шляхом введення підказки. Цей документ переважно описує спосіб використання Gemini Generate Content API — це офіційний нативний формат API Google, який підтримує два ендпоїнти: `generateContent` і `streamGenerateContent`.

## Відмінності від Chat Completions API

Gemini Generate Content API використовує офіційний нативний формат запитів Google (поле `contents`), а не формат, сумісний з OpenAI (поле `messages`). Якщо ви вже використовуєте Google Gemini SDK або знайомі з офіційним форматом API, ви можете безпосередньо використовувати цей API без зміни формату запиту.

## Поточна сфера підтримки

Інтерфейс приймає текстові, графічні, відео- та аудіовходи (`inlineData` або `fileData`), конфігурації мислення та декларації користувацьких функцій. Нативні поля, такі як аудіовихід, вбудовані інструменти та явне кешування контексту, поки що не мають гарантії уніфікованої доступності; орієнтуйтеся на фактичні відповіді конкретної моделі.

Під час надсилання аудіо та інших файлів через `fileData.fileUri` переконайтеся, що файл доступний безпосередньо через HTTPS, не залежить від стану входу та що термін дії підписаного посилання покриває весь час обробки запиту. Непотоковий аналіз аудіо повертає результат лише після завершення обробки моделлю, що може тривати понад 90 секунд; клієнт повинен встановити достатньо тривалий загальний тайм-аут відповідно до розміру файлу та бізнес-сценарію, щоб уникнути розриву з’єднання, коли сервер все ще обробляє запит.

## Процес отримання

Перед використанням Gemini Generate Content API спершу відвідайте сторінку [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) і натисніть кнопку «Отримати», щоб отримати облікові дані, необхідні для запиту.

Якщо ви ще не ввійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу. Для першого отримання доступна безкоштовна квота.

## Базове використання

### Non-Streaming（непотоковий）

Надішліть POST-запит до `/v1beta/models/{model}:generateContent`:

> **Підказка**：серія `gemini-3.x` flash є моделями мислення, які спочатку споживають reasoning tokens; установіть `generationConfig.maxOutputTokens` на значення понад 512, інакше може повертатися лише порожній вміст.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Приклад результату, що повертається:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Поля token у `usageMetadata` тарифікуються відповідно до нативної семантики Gemini:

- `promptTokenCount` включає `cachedContentTokenCount`; частина, для якої спрацював кеш, розраховується за ціною читання кешу та не буде повторно зарахована як звичайний вхід.
- `promptTokensDetails` і `cacheTokensDetails` буде нормалізовано до `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` і відповідних деталей `cached_*` у `usage.prompt_tokens_details`. Ці значення відповідно включаються до `prompt_tokens` і `cached_tokens`; різні модальності перераховуються лише за власними цінами й не тарифікуються повторно.
- `candidatesTokenCount` і `thoughtsTokenCount` обидва розраховуються за ціною output token.
- `toolUsePromptTokenCount` — це незалежні tool input token, які розраховуються за ціною input token.

Ace Data Cloud додатково повертає нормалізований об’єкт `usage`; для різних протоколів моделей витрати цього виклику уніфіковано читаються з `usage.cost`. `cost` — це необов’язковий попередній перегляд вартості; коли попередній перегляд ціни тимчасово недоступний, відповідь моделі все одно нормально повертається, але може не містити цього поля. Остаточне виставлення рахунків здійснюється згідно із записами про використання.

### Streaming（потоковий）

Надішліть POST-запит до `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

Потокова відповідь поступово повертатиме вміст у форматі SSE（Server-Sent Events）. Проміжні події зазвичай містять лише інкрементний вміст; подія кінцевого стану з авторитетними даними про використання міститиме `usageMetadata` і нормалізований `usage`, а вартість, як і раніше, розташована в `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

Закриття з’єднання означає завершення потоку; нативний потік Gemini не надсилає `data: [DONE]`. Якщо попередній перегляд ціни кінцевого стану тимчасово недоступний, `usage` усе одно повертатиме використання token, але не міститиме `cost`.

### Внутрішнє міркування та підсумок міркувань

Внутрішнє міркування моделі та повернення підсумку міркувань викликачеві — це два незалежні налаштування:

- `thinkingBudget` або `thinkingLevel` контролюють бюджет або глибину внутрішнього міркування моделі; підтримувані поля та значення залежать від моделі.
- `includeThoughts` контролює, чи повертати підсумок міркувань; за замовчуванням — `false`. Якщо це поле пропущено або передано `false`, звичайні відповіді JSON та потокові відповіді SSE не повертатимуть текст, позначений як `thought: true`; цей текст зберігається лише за явної передачі булевого значення `true`.

Коли в запиті не задано `includeThoughts`, API за замовчуванням передає `false` моделям генерації, які підтримують конфігурацію міркувань, щоб уникнути запиту непотрібних підсумків; явно передане клієнтом значення, бюджет і рівень міркування зберігаються. Відомій моделі `gemini-2.5-flash-image`, яка не підтримує конфігурацію міркувань, це поле не додається автоматично, а до запитів `countTokens` також не додається конфігурація генерації.

Вимкнення підсумків не дорівнює вимкненню внутрішнього міркування та не гарантує зменшення токенів внутрішнього міркування. Якщо відповідь усе ще містить незапитаний текст міркувань, звичайні виходи JSON і SSE додатково його відфільтровуватимуть, зберігаючи звичайну відповідь, підписи та фактичне використання.

Коли потрібно переглянути підсумок, явно ввімкніть його таким чином. Якщо модель не згенерувала доступного підсумку, текст міркувань може бути відсутнім навіть за ввімкнення:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` — це зашифрований стан, необхідний для наступних ходів, а не текст підсумку міркувань, і він також не контролюється перемикачем `includeThoughts`. Підпис може міститися у звичайній відповіді, виклику функції або порожньому текстовому Part; під час фільтрації тексту міркувань підпис та інші поля того самого Part зберігаються, тому у відповіді можуть усе ще бути Part, що містять лише підпис і мають порожній текст. Під час ручного ведення багатораундової історії слід зберігати порядок цих Part і позиції підписів, не переміщуйте підписи та не об’єднуйте їх.

`usageMetadata` і `usage` усе ще записують фактичне використання. Приховування підсумків не обнуляє `thoughtsTokenCount`; тарифікація все одно обчислюється за фактичним використанням і поточними правилами ціноутворення.

Дивіться офіційні [пояснення Google щодо міркувань і підсумків міркувань](https://firebase.google.com/docs/ai-logic/thinking) та [правила підписів міркувань](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

## Налаштування безпеки

Вмістом фільтрації можна керувати через `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Обробка помилок

| Код стану HTTP | Значення             |
| -------- | -------------- |
| 400      | Недійсні параметри запиту         |
| 401      | Помилка автентифікації, перевірте Token |
| 403      | Вміст заблоковано фільтром безпеки     |
| 429      | Запити надто часті         |
| 500      | Внутрішня помилка сервера        |
