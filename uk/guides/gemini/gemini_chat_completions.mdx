Google Gemini — це надзвичайно потужна система ШІ для діалогів, яка лише за допомогою введення промпту може за кілька секунд генерувати плавні та природні відповіді. Gemini може надавати вражаючу інтелектуальну допомогу, значно підвищуючи ефективність роботи та творчість людей.

У цьому документі переважно представлено процес використання Gemini Chat Completion API, за допомогою якого ми можемо легко використовувати функції діалогу офіційного Gemini.

## Процес подання заявки

Щоб використовувати Gemini Chat Completion API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати свій API Token, і збережіть його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не ввійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та ввійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, не потрібно подавати заявку окремо для кожного сервісу.** Під час першого подання заявки надається безкоштовний ліміт, який можна використати для безкоштовного тестування; коли ліміту недостатньо, можна поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

## Базове використання

Далі можна заповнити відповідний вміст в інтерфейсі, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

Під час першого використання цього інтерфейсу нам потрібно заповнити щонайменше три поля: одне з них — `authorization`, його достатньо безпосередньо вибрати у випадаючому списку. Інший параметр — `model`, `model` — це категорія моделі з офіційного сайту Gemini, яку ми обираємо для використання; доступні моделі визначаються переліком `model` у документації інтерфейсу. Останній параметр — `messages`, `messages` — це масив введених нами запитів; це масив, який означає, що можна одночасно завантажити кілька запитів, кожен запит містить `role` і `content`, де `role` означає роль того, хто ставить запитання; ми надаємо три ролі: `user`, `assistant`, `system`. Інший `content` — це конкретний зміст нашого запитання.

Водночас ви можете помітити, що праворуч генерується відповідний код виклику; ви можете скопіювати код і запустити його безпосередньо, або безпосередньо натиснути кнопку «Try» для тестування.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

> **Підказка**: flash серії `gemini-3.x` є моделями мислення, які спочатку споживають reasoning tokens; установіть `max_tokens` вище 512, інакше може повертатися лише порожній вміст. `gemini-3.8-flash` — це поточна рекомендована Flash-модель, яка підтримує до 1 мільйона Token контексту, введення зображень, виклики інструментів і потокові відповіді; наразі викликається через інтерфейс Chat Completions.

`gemini-4-argon` також можна використовувати для Chat Completions, він підтримує звичайні та потокові текстові відповіді. Він може використовувати частину бюджету виводу для мислення, тому для складних завдань залишайте достатньо місця для `max_tokens`; Google рекомендує для звичайних завдань цієї моделі щонайменше 32768. Не ототожнюйте цей інтерфейс із функцією тривалого фонового виводу Google Interactions API.

## Розуміння зображень (мультимодальне введення)

Gemini — це нативна мультимодальна модель, яка може безпосередньо «бачити зображення». Щоб передати зображення, змініть `content` певного повідомлення з рядка на **масив блоків вмісту**, у якому одночасно розмістіть блок `text` і блок `image_url` — це повністю відповідає OpenAI, а також формату сумісності з OpenAI офіційного Gemini.

`image_url.url` підтримує два способи написання:
- **base64 `data:` URI（рекомендовано, найстабільніше）**：формат `data:&lt;тип медіа>;base64,&lt;дані>`，наприклад `data:image/jpeg;base64,/9j/4AAQ...`。**тип медіа（MIME）вже вказано в префіксі `data:`**，тому окреме поле `media_type` не потрібне й не існує。
- **Публічно доступний URL зображення**：наприклад `https://cdn.acedata.cloud/4hfydw.jpg`。

Підтримувані типи зображень：`png`、`jpeg`、`webp`、`heic`、`heif`。

Приклад коду виклику Python（base64 data URI）：

```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# 把本地图片读成 base64 data URI
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Також можна безпосередньо передати публічно доступний URL зображення：

```python

                {"type": "image_url", "image_url": {"url": "https://cdn.acedata.cloud/4hfydw.jpg"}}
            ]
        }

```

> 💡 `image_url` приймає лише поле `url`（значенням може бути URL зображення або base64 `data:` URI），а також необов’язкове поле `detail`。**Не передавайте `media_type`**——це поле зображення Anthropic Claude, яке не належить до формату `image_url` OpenAI / Gemini。

## Потокова відповідь

Цей інтерфейс також підтримує потокову відповідь, що дуже корисно для інтеграції з вебсторінками та дає змогу реалізувати на вебсторінці ефект посимвольного відображення。

Якщо потрібно повертати відповідь потоково, можна змінити параметр `stream ` у заголовку запиту на `true`。

Зміни показано на зображенні, але код виклику потрібно відповідно змінити, щоб підтримувати потокову відповідь。

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

Після зміни `stream` на `true` API повертатиме відповідні дані JSON рядок за рядком, і на рівні коду нам потрібно внести відповідні зміни, щоб отримувати результати по рядках。

Приклад коду виклику Python：

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Можна побачити, що у відповіді є багато `data`, а `choices` у `data` — це найновіший вміст відповіді, що узгоджується з описаним вище вмістом. `choices` — це доданий вміст відповіді, ви можете на основі результату інтегрувати його у свою систему. - `choices` — інформація відповіді, надана Gemini на запит.

JavaScript також підтримується, наприклад, код потокового виклику Node.js наведено нижче:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизований доступ, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Забагато запитів, ви перевищили ліміт частоти запитів.
- `500 api_error`：Внутрішня помилка сервера, на сервері щось пішло не так.

### Приклад відповіді з помилкою
```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
