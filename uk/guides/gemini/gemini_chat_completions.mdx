Google Gemini — це дуже потужна система AI-діалогів, яка здатна генерувати плавні та природні відповіді всього за кілька секунд після введення підказки. Gemini може надавати вражаючу інтелектуальну допомогу, значно підвищуючи ефективність роботи та творчість людей.

У цьому документі переважно представлено процес використання операцій Gemini Chat Completion API, за допомогою якого ми можемо легко використовувати функцію діалогів офіційного Gemini.

## Процес подання заявки

Щоб використовувати Gemini Chat Completion API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token і зберегти його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли в систему або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти в систему, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, не потрібно подавати окрему заявку для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт для безкоштовного ознайомлення; коли ліміту недостатньо, ви можете поповнити універсальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## Базове використання

Далі ви можете заповнити відповідний вміст в інтерфейсі, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

Під час першого використання цього інтерфейсу нам потрібно заповнити щонайменше три поля: одне з них — `authorization`, його можна безпосередньо вибрати у спадному списку. Інший параметр — `model`, `model` — це категорія моделі з офіційного сайту Gemini, яку ми вибираємо для використання; доступні моделі визначаються переліком `model` у документації інтерфейсу. Останній параметр — `messages`, `messages` — це масив введених нами запитів, він є масивом і означає, що можна одночасно завантажувати кілька запитів; кожен запит містить `role` і `content`, де `role` означає роль запитувача, ми надаємо три типи ролей: `user`, `assistant`, `system`. Інший параметр `content` — це конкретний вміст нашого запитання.

Водночас ви можете помітити, що праворуч генерується відповідний код виклику, ви можете скопіювати код і запустити його безпосередньо або натиснути кнопку «Try» для тестування.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

## Розуміння зображень (мультимодальне введення)

Gemini є нативною мультимодальною моделлю та може безпосередньо «бачити зображення». Щоб передати зображення, змініть `content` певного повідомлення з рядка на **масив блоків вмісту**, одночасно додавши до масиву блок `text` і блок `image_url` — це повністю відповідає формату сумісності з OpenAI та офіційним Gemini OpenAI.

`image_url.url` підтримує два способи запису:

- **base64 `data:` URI (рекомендовано, найбільш стабільно)**: формат — `data:&lt;тип медіа>;base64,&lt;дані>`, наприклад `data:image/jpeg;base64,/9j/4AAQ...`. **Тип медіа (MIME) уже вказано у префіксі `data:`**, тому окреме поле `media_type` не потрібне й не існує.
- **Загальнодоступний URL зображення**: наприклад `https://cdn.acedata.cloud/4hfydw.jpg`.

Підтримувані типи зображень: `png`, `jpeg`, `webp`, `heic`, `heif`.

Приклад коду виклику Python (base64 data URI):
```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# 把本地图片读成 base64 data URI
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Також можна безпосередньо передати публічно доступний URL-адрес зображення:

```python
payload = {
    "model": "gemini-3.1-pro-preview",

                {"type": "image_url", "image_url": {"url": "https://cdn.acedata.cloud/4hfydw.jpg"}}
            ]
        }

```

> 💡 `image_url` приймає лише поле `url` (значенням може бути URL-адреса зображення або base64 `data:` URI), а також необов’язкове поле `detail`. **Не передавайте `media_type`** — це поле зображення Anthropic Claude, воно не належить до формату `image_url` OpenAI / Gemini.

## Потокова відповідь

Цей інтерфейс також підтримує потокові відповіді, що дуже корисно для інтеграції з вебсторінками та дає змогу реалізувати ефект посимвольного відображення.

Якщо потрібно повертати відповідь потоково, можна змінити параметр `stream ` у заголовку запиту на `true`.

Зміни показано на зображенні, однак код виклику також потребує відповідних змін для підтримки потокової відповіді.

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

Після зміни `stream` на `true` API повертатиме відповідні JSON-дані рядок за рядком, і на рівні коду потрібно внести відповідні зміни, щоб отримувати результати рядок за рядком.

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Як можна побачити, у відповіді є багато `data`, а `choices` всередині `data` є найновішим вмістом відповіді, що відповідає описаному вище. `choices` — це новий вміст відповіді, який ви можете інтегрувати у свою систему на основі результату. Водночас завершення потокової відповіді визначається за вмістом `data`: якщо вмістом є `[DONE]`, це означає, що потокова відповідь повністю завершена. Повернений результат `data` містить кілька полів, опис яких наведено нижче:
- `id`，ID завдання цього діалогу, що генерується, використовується для унікальної ідентифікації завдання цього діалогу.
- `model `，вибрана модель Gemini з офіційного сайту.
- `choices`，інформація про відповіді, надані Gemini на запит.

JavaScript також підтримується, наприклад, код потокового виклику Node.js наведено нижче:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`: Неправильний запит, можливо через відсутні або недійсні параметри.
- `400 api_not_implemented`: Неправильний запит, можливо через відсутні або недійсні параметри.
- `401 invalid_token`: Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`: Забагато запитів, ви перевищили ліміт частоти запитів.
- `500 api_error`: Внутрішня помилка сервера, на сервері щось пішло не так.
