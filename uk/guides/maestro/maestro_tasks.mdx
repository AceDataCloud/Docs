Основна функція API запиту завдань Maestro — через ID завдання, повернений [API генерації відео Maestro](/uk/guides/maestro/maestro_videos) (`POST /maestro/videos`), запитувати статус виконання та кінцевий результат цього завдання.

У цьому документі буде детально представлено інструкцію з інтеграції API запиту завдань Maestro. Оскільки генерація відео є асинхронним завданням, після надсилання потрібно використовувати цей інтерфейс для опитування та отримання прогресу й готового відео, **опитування безкоштовне та не витрачає кредити.**

`POST https://api.acedata.cloud/maestro/tasks`

## Процес подання заявки

Щоб використовувати API запиту завдань Maestro, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати свій API Token, і збережіть його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не ввійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та ввійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, не потрібно подавати окрему заявку для кожного сервісу.** Під час першого отримання буде надано безкоштовний ліміт для безкоштовного тестування; якщо ліміту недостатньо, можна поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [API запиту завдань Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Запит одного завдання

Щодо створення відеозавдання зверніться до документації [API генерації відео Maestro](/uk/guides/maestro/maestro_videos). Як приклад візьмемо один ID завдання, який він повертає: `f57e99c4f60f4373a15517742ce2357d`, щоб продемонструвати, як запитувати його статус і результат.

### Налаштування заголовків і тіла запиту

**Request Headers** включають:

- `accept`: указує на отримання результату відповіді у форматі JSON, тут указується `application/json`.
- `authorization`: ключ для виклику API, після отримання його можна безпосередньо вибрати зі спадного списку.
- `content-type`: формат тіла запиту, тут указується `application/json`.

**Request Body** включає:

| Поле       | Тип     | Обов’язкове під час запиту одного завдання | Опис                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | так | `task_id`, повернений `POST /maestro/videos`              |
| `action` | string | ні         | `retrieve` (за замовчуванням, запит одного завдання); під час запиту історичного списку фіксовано `retrieve_batch` |

### Приклад коду

Відповідний код CURL має такий вигляд:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Відповідний код Python має такий вигляд:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Приклад відповіді

Після успішного запиту API поверне статус і результат цього відеозавдання. Приклад відповіді після завершення завдання має такий вигляд (масив `variants` містить один готовий відеоролик):

```json
{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "started_at": 1769262721.823,
  "finished_at": 1769264698.3,
  "elapsed": 1976.477,
  "status": "succeeded",
  "progress": {
    "percent": 100,
    "stage": "producing",
    "message": "rendering scene 2"
  },
  "request": {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": [
      "zh-cn"
    ],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        {
          "lang": "zh-cn",
          "aspect": "9:16",
          "kind": "video",
          "title": "什么是向量数据库",
          "output_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4?example=video-001"
        }
      ],
      "project": {
        "tarball_url": null,
        "outputs": [
          "https://…/zh.mp4"
        ]
      },
      "percent": 100,
      "stage": "producing",
      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }
  }
}
```

Опис полів результату, що повертається, наведено нижче:

- `id`: ID цього відеозавдання, використовується для унікальної ідентифікації цього завдання генерації відео.
- `status`: статус завдання, можливі значення: `pending → planning → producing → succeeded` (або `failed`). Чи завершене завдання, визначається за цим статусом верхнього рівня `status`.
- `elapsed`: час, витрачений завданням (секунди).
- `progress`: об’єкт прогресу верхнього рівня; `percent` (0–100) після успішного виконання завдання буде гарантовано встановлено на 100; `stage` і `message` відображають останню подію прогресу AI-режисера (тому після успішного виконання `stage` може все ще бути останнім етапом виконання, наприклад `producing`), їх можна безпосередньо використовувати для відображення індикатора прогресу.
- `request`: тіло запиту під час запуску завдання.
- `response`: інформація про відповідь завдання.
  - `success`: чи було завдання успішним.
  - `data.variants`: містить об’єкт готового відео вибраною мовою, зокрема `lang`, `aspect`, `title`, `output_url` (адреса завантаження готового відео) тощо.
  - `data.project`: результати всього проєкту, зокрема `tarball_url` (пакет проєкту) та `outputs` (посилання на готові відео).
  - `data.progress`: масив подій прогресу, що додаються за етапами (журнал лише з додаванням), який можна використовувати для відображення детального прогресу в реальному часі.
- `created_at`: час створення завдання, Unix-мітка часу (секунди).
- `started_at`: час початку виконання завдання, Unix-мітка часу (секунди). До початку завдання — null.
- `finished_at`: час завершення завдання, Unix-мітка часу (секунди). До завершення завдання — null.

## Запит історичного списку

Передайте `action: retrieve_batch`, щоб отримати останні завдання поточного виконавця, який увійшов у систему (у зворотному порядку за часом створення); це можна використовувати для сторінки списку «Мої відео». Історичні списки ізольовані за ідентифікатором входу.

**Request Body** включає:

| Поле               | Тип     | Обов’язкове  | Опис                              |
| ---------------- | ------ | --- | ------------------------------- |
| `action`         | string | так   | фіксовано `retrieve_batch`            |
| `limit`          | int    | ні   | кількість записів, що повертаються, за замовчуванням 20; допустимий діапазон 1–100          |
| `created_at_max` | int    | ні   | повертати лише завдання, строго раніші за цю Unix-мітку часу (без граничного значення, для пагінації) |
| `created_at_min` | int    | ні   | повертати лише завдання, строго пізніші за цю Unix-мітку часу (без граничного значення)     |

### Приклад коду

Відповідний код CURL має такий вигляд:
```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### Приклад відповіді

Після успішного запиту API поверне список історичних завдань поточного користувача:

```json
{
  "count": 2,
  "items": [
    {
      "id": "f57e99c4f60f4373a15517742ce2357d",
      "started_at": 1769262721.823,
      "finished_at": 1769264698.3,
      "elapsed": 1976.477,
      "status": "succeeded",
      "progress": {
        "percent": 100,
        "stage": "producing",
        "message": "rendering scene 2"
      },
      "request": {
        "prompt": "…",
        "langs": [
          "zh-cn"
        ],
        "aspect": "9:16",
        "duration": 20
      },
      "response": {
        "success": true,
        "data": {
          "variants": [
            {
              "lang": "zh-cn",
              "output_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4?example=video-003"
            }
          ]
        }
      }
    }
  ]
}
```

Опис полів результату, що повертається, наведено нижче:

- `count`: загальна кількість завдань, видимих поточному авторизованому виконавцю, не залежить від умов часу або `limit`.
- `items`: масив завдань, відфільтрованих за умовами часу та `limit`, відсортований у зворотному хронологічному порядку за часом створення; формат кожного елемента відповідає результату, що повертається в «Запиті одного завдання».

## Рекомендації щодо опитування

Оскільки створення відео займає тривалий час, `status` проходитиме через `pending → planning → producing → succeeded` (або `failed`). Рекомендується виконувати опитування кожні 5–10 секунд, доки `status` не зміниться на `succeeded` або `failed`. Для відображення індикатора виконання в реальному часі можна використовувати `progress.percent` верхнього рівня. **Опитування цього інтерфейсу є безкоштовним і не витрачає бали.**

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та повідомлення. Наприклад:

- `401 invalid_token`: Неавторизовано, недійсний або відсутній токен авторизації.
- `404 not_found`: Завдання не знайдено, вказаний task_id не існує.
- `429 too_many_requests`: Забагато запитів, ви перевищили ліміт швидкості.
- `500 api_error`: Внутрішня помилка сервера, щось пішло не так на сервері.

### Приклад відповіді з помилкою

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
