Основна функція Maestro завдання запиту API полягає в тому, щоб за допомогою [Maestro відео генерації API](development_maestro_videos.md) (`POST /maestro/videos`) отримати ID завдання, щоб перевірити статус виконання та остаточний результат цього завдання.

Цей документ детально описує інтеграцію Maestro завдання запиту API. Оскільки генерація відео є асинхронним завданням, після подання потрібно використовувати цей інтерфейс для опитування прогресу та готового відео, **опитування безкоштовне, не витрачає бали.**

`POST https://api.acedata.cloud/maestro/tasks`

## Процес подачі заявки

Щоб використовувати Maestro завдання запиту API, спочатку перейдіть до [Ace Data Cloud консолі](https://platform.acedata.cloud/console/applications) для отримання вашого API токена, зберігайте його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли в систему або не зареєстровані, вас автоматично перенаправлять на сторінку входу, щоб запросити реєстрацію та вхід, після чого ви будете автоматично повернені на цю сторінку.

**Один API токен достатній для виклику всіх послуг платформи, не потрібно окремо запитувати для кожної послуги.** Перший запит надає безкоштовний ліміт, щоб ви могли безкоштовно спробувати; коли ліміт закінчиться, ви можете поповнити загальний баланс в [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Maestro завдання запиту API →](https://platform.acedata.cloud/documents/maestro-tasks)

## Запит одного завдання

Щоб дізнатися, як створити відеозавдання, будь ласка, зверніться до документа [Maestro відео генерації API](development_maestro_videos.md). Ми візьмемо один ID завдання, який він повертає: `f57e99c4f60f4373a15517742ce2357d`, щоб продемонструвати, як перевірити його статус та результат.

### Налаштування заголовків запиту та тіла запиту

**Request Headers** включає:

- `accept`: вказує на прийняття відповіді у форматі JSON, тут вказується `application/json`.
- `authorization`: ключ для виклику API, після запиту можна вибрати з випадаючого списку.
- `content-type`: формат тіла запиту, тут вказується `application/json`.

**Request Body** включає:

| Поле       | Тип     | Обов'язкове  | Опис                                                |
| -------- | ------ | --- | ------------------------------------------------- |
| `id`     | string | Так   | `task_id`, повернений `POST /maestro/videos`              |
| `action` | string | Ні   | `retrieve` (за замовчуванням, запит одного завдання) / `retrieve_batch` (запит списку історичних завдань) |

### Приклад коду

Відповідний CURL код виглядає так:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Відповідний Python код виглядає так:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Приклад відповіді

Після успішного запиту API поверне статус та результат цього відеозавдання. Приклад відповіді, коли завдання завершено, виглядає так (кожна мова відповідає одному `variant`):

```json
{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "started_at": 1769262721.823,
  "finished_at": 1769264698.3,
  "elapsed": 1976.477,
  "status": "succeeded",
  "progress": {
    "percent": 100,
    "stage": "producing",
    "message": "rendering scene 2"
  },
  "request": {
    "prompt": "Поясніть, що таке векторна база даних за 20 секунд, підходить для глядачів без підготовки, на кінець дайте одну запам'ятовувальну фразу",
    "langs": [
      "zh-cn",
      "en"
    ],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        {
          "lang": "zh-cn",
          "aspect": "9:16",
          "kind": "video",
          "title": "Що таке векторна база даних",
          "output_url": "https://…/zh.mp4"
        },
        {
          "lang": "en",
          "aspect": "9:16",
          "kind": "video",
          "title": "What is a vector database",
          "output_url": "https://…/en.mp4"
        }
      ],
      "project": {
        "tarball_url": "https://…/project.tar.gz",
        "outputs": [
          "https://…/zh.mp4",
          "https://…/en.mp4"
        ]
      },
      "percent": 100,
      "stage": "producing",
      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }
  }
}
```

Опис полів у повернутому результаті виглядає так:

- `id`: ID цього відеозавдання, що використовується для унікальної ідентифікації цього завдання на генерацію відео.
- `status`: статус завдання, значення `pending → planning → producing → succeeded` (або `failed`). Завдання вважається завершеним, якщо верхній рівень `status` вказує на це.
- `elapsed`: час, витрачений на завдання (секунди).
- `progress`: об'єкт прогресу верхнього рівня, `percent` (0–100) після успішного завершення завдання буде зафіксовано на 100; `stage` та `message` відображають останню подію прогресу AI-режисера (тому після успішного завершення `stage` може залишатися останнім етапом виконання, наприклад, `producing`), що може бути безпосередньо використано для відображення прогресу.
- `request`: тіло запиту під час ініціювання завдання.
- `response`: інформація про повернення завдання.
  - `success`: чи було завдання успішним.
  - `data.variants`: для кожної мови відповідає один об'єкт готового відео, що містить `lang`, `aspect`, `title`, `output_url` (посилання для завантаження готового відео) тощо.
  - `data.project`: весь продукт проекту, що містить `tarball_url` (архів проекту) та `outputs` (всі посилання на готові відео).
  - `data.progress`: масив подій прогресу, що додаються по етапах (лог, що додається лише), може бути використаний для відображення детального реального прогресу.
- `created_at`: час створення завдання, Unix-часовий штамп (секунди).
- `started_at`: час початку виконання завдання, Unix-часовий штамп (секунди). Якщо завдання ще не почалося, то null.
- `finished_at`: час завершення завдання, Unix-часовий штамп (секунди). Якщо завдання не завершено, то null.

## Запит історичного списку

Передайте `action: retrieve_batch`, щоб отримати останні завдання поточного користувача (за часом створення у зворотному порядку), що може бути використано для сторінки «Мої відео».

**Request Body** включає:

| Поле               | Тип     | Обов'язкове  | Опис                      |
| ---------------- | ------ | --- | ----------------------- |
| `action`         | string | Так   | Фіксоване значення `retrieve_batch`    |
| `limit`          | int    | Ні   | Кількість повернених записів, за замовчуванням 20              |
| `created_at_max` | int    | Ні   | Повертає лише завдання, створені раніше цього Unix-часового штампу (для пагінації) |
| `created_at_min` | int    | Ні   | Повертає лише завдання, створені пізніше цього Unix-часового штампу      |

### Приклад коду

Відповідний CURL код виглядає так:
```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

```json
{
  "count": 2,
  "items": [
    {
      "id": "f57e99c4f60f4373a15517742ce2357d",
      "started_at": 1769262721.823,
      "finished_at": 1769264698.3,
      "elapsed": 1976.477,
      "status": "succeeded",
      "progress": {
        "percent": 100,
        "stage": "producing",
        "message": "rendering scene 2"
      },
      "request": {
        "prompt": "…",
        "langs": [
          "zh-cn",
          "en"
        ],
        "aspect": "9:16",
        "duration": 20
      },
      "response": {
        "success": true,
        "data": {
          "variants": [
            {

              "output_url": "https://…/zh.mp4"
```

Поля у повернутому результаті описані нижче:

- `items`：Масив завдань, кожен елемент форматується так само, як і результат «запиту одного завдання».

## Рекомендації щодо опитування

Оскільки виробництво відео займає багато часу, `status` проходитиме через `pending → planning → producing → succeeded` (або `failed`). Рекомендується опитувати кожні 5–10 секунд, поки `status` не зміниться на `succeeded` або `failed`. Можна використовувати верхній `progress.percent` для відображення реального прогресу. **Опитування цього інтерфейсу безкоштовне, не витрачає бали.**

## Обробка помилок

При виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `404 not_found`：Завдання не знайдено, вказаний task_id не існує.
- `429 too_many_requests`：Занадто багато запитів, ви перевищили ліміт запитів.
- `500 api_error`：Внутрішня помилка сервера, щось пішло не так на сервері.

### Приклад помилки у відповіді

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
