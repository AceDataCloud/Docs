Основна функція API запиту завдань Maestro полягає в тому, щоб за ID завдання, поверненим [API генерації відео Maestro](development_maestro_videos.md) (`POST /maestro/videos`), запитувати статус виконання та кінцевий результат цього завдання.

Цей документ детально описує інструкцію з інтеграції API запиту завдань Maestro. Оскільки генерація відео є асинхронним завданням, після надсилання потрібно використовувати цей інтерфейс для опитування та отримання прогресу й готового відео, **опитування безкоштовне та не витрачає бали.**

`POST https://api.acedata.cloud/maestro/tasks`

## Процес подання заявки

Щоб використовувати API запиту завдань Maestro, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати свій API Token, і збережіть його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не ввійшли або не зареєструвалися, вас автоматично буде перенаправлено на сторінку входу, де буде запропоновано зареєструватися та ввійти; після завершення вас автоматично буде повернено на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, немає потреби подавати заявку окремо для кожного сервісу.** Під час першого подання заявки надається безкоштовна квота для безкоштовного тестування; якщо квоти недостатньо, ви можете поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [API запиту завдань Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Запит одного завдання

Щодо того, як створити відеозавдання, зверніться до документації [API генерації відео Maestro](development_maestro_videos.md). Ми візьмемо як приклад один ID завдання, який він повертає: `f57e99c4f60f4373a15517742ce2357d`, щоб продемонструвати, як запитати його статус і результат.

### Налаштування заголовків запиту та тіла запиту

**Request Headers** включають:

- `accept`: указує на отримання результату відповіді у форматі JSON, тут слід вказати `application/json`.
- `authorization`: ключ для виклику API, після подання заявки його можна безпосередньо вибрати зі спадного списку.
- `content-type`: формат тіла запиту, тут слід вказати `application/json`.

**Request Body** включає:

| Поле       | Тип     | Обов’язкове        | Опис                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | обов’язкове під час запиту одного завдання | `task_id`, повернений `POST /maestro/videos`              |
| `action` | string | ні         | `retrieve` (за замовчуванням, запит одного завдання); під час запиту списку історії фіксовано `retrieve_batch` |

### Приклад коду

Відповідний CURL-код такий:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Відповідний Python-код такий:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Приклад відповіді

Після успішного запиту API поверне статус і результат цього відеозавдання. Приклад відповіді після завершення завдання такий (кожній мові відповідає один `variant`):

```json
{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "started_at": 1769262721.823,
  "finished_at": 1769264698.3,
  "elapsed": 1976.477,
  "status": "succeeded",
  "progress": {
    "percent": 100,
    "stage": "producing",
    "message": "rendering scene 2"
  },
  "request": {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": [
      "zh-cn",
      "en"
    ],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        {
          "lang": "zh-cn",
          "aspect": "9:16",
          "kind": "video",
          "title": "什么是向量数据库",
          "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-001"
        },
        {
          "lang": "en",
          "aspect": "9:16",
          "kind": "video",
          "title": "What is a vector database",
          "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-002"
        }
      ],
      "project": {
        "tarball_url": null,
        "outputs": [
          "https://…/zh.mp4",
          "https://…/en.mp4"
        ]
      },
      "percent": 100,
      "stage": "producing",
      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }
  }
}
```

Опис полів результату, що повертається, такий:

- `id`: ID цього відеозавдання, використовується для унікальної ідентифікації цього завдання генерації відео.
- `status`: статус завдання, значення: `pending → planning → producing → succeeded` (або `failed`). Чи завершено завдання, визначається цим верхньорівневим `status`.
- `elapsed`: час, уже витрачений на завдання (секунди).
- `progress`: верхньорівневий об’єкт прогресу, `percent` (0–100) після успішного виконання завдання буде встановлено як 100; `stage` і `message` відображають останню подію прогресу AI-режисера (тому після успішного виконання `stage` все ще може бути останнім етапом виконання, таким як `producing`), їх можна безпосередньо використовувати для відображення індикатора прогресу.
- `request`: тіло запиту під час запуску завдання.
- `response`: інформація відповіді завдання.
  - `success`: чи успішне завдання.
  - `data.variants`: кожній мові відповідає один об’єкт готового відео, що містить `lang`, `aspect`, `title`, `output_url` (адреса завантаження готового відео) тощо.
  - `data.project`: результати всього проєкту, містить `tarball_url` (пакет проєкту) та `outputs` (усі посилання на готові відео).
  - `data.progress`: масив подій прогресу, що додаються за етапами (журнал лише для додавання), може використовуватися для відображення докладного прогресу в реальному часі.
- `created_at`: час створення завдання, Unix-мітка часу (секунди).
- `started_at`: час початку виконання завдання, Unix-мітка часу (секунди). Якщо завдання ще не почалося, значення null.
- `finished_at`: час завершення завдання, Unix-мітка часу (секунди). Якщо завдання не завершено, значення null.

## Запит списку історії

Передайте `action: retrieve_batch`, щоб отримати останні завдання поточного виконавця, який увійшов у систему (у зворотному порядку за часом створення); це можна використовувати для сторінки списку «Мої відео». Список історії ізольований за ідентичністю входу.

**Request Body** включає:
| Поле               | Тип     | Обов’язкове  | Опис                              |
| ---------------- | ------ | --- | ------------------------------- |
| `action`         | string | Так   | Фіксоване значення `retrieve_batch`            |
| `limit`          | int    | Ні   | Кількість записів у відповіді, за замовчуванням 20; допустимий діапазон 1–100          |
| `created_at_max` | int    | Ні   | Повертати лише завдання, створені строго раніше за цю Unix-мітку часу (без граничного значення, для пагінації) |
| `created_at_min` | int    | Ні   | Повертати лише завдання, створені строго пізніше за цю Unix-мітку часу (без граничного значення)     |

### Приклад коду

Відповідний код CURL наведено нижче:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### Приклад відповіді

Після успішного запиту API поверне список історичних завдань поточного користувача:

```json
{
  "count": 2,
  "items": [
    {
      "id": "f57e99c4f60f4373a15517742ce2357d",
      "started_at": 1769262721.823,
      "finished_at": 1769264698.3,
      "elapsed": 1976.477,
      "status": "succeeded",
      "progress": {
        "percent": 100,
        "stage": "producing",
        "message": "rendering scene 2"
      },
      "request": {
        "prompt": "…",
        "langs": [
          "zh-cn",
          "en"
        ],
        "aspect": "9:16",
        "duration": 20
      },
      "response": {
        "success": true,
        "data": {
          "variants": [
            {
              "lang": "zh-cn",
              "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-003"
            }
          ]
        }
      }
    }
  ]
}
```

Опис полів результату, що повертається, наведено нижче:

- `count`: загальна кількість завдань, видимих для поточного авторизованого виконавця, не залежить від часових умов або `limit`.
- `items`: масив завдань, відфільтрованих за часовими умовами та `limit`, відсортований за часом створення у зворотному порядку; формат кожного елемента збігається з результатом, що повертається для «Запиту одного завдання».

## Рекомендації щодо опитування

Оскільки створення відео займає тривалий час, `status` проходитиме через `pending → planning → producing → succeeded` (або `failed`). Рекомендується виконувати опитування кожні 5–10 секунд, доки `status` не зміниться на `succeeded` або `failed`. Для відображення індикатора прогресу в реальному часі можна використати верхньорівневий `progress.percent`. **Опитування цього інтерфейсу безкоштовне та не витрачає бали.**

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та повідомлення. Наприклад:

- `401 invalid_token`: Неавторизовано, недійсний або відсутній токен авторизації.
- `404 not_found`: Завдання не знайдено, вказаний task_id не існує.
- `429 too_many_requests`: Забагато запитів, ви перевищили ліміт частоти.
- `500 api_error`: Внутрішня помилка сервера, щось пішло не так на сервері.

### Приклад відповіді з помилкою

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
