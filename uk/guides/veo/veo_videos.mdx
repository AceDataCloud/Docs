Щоб використовувати Veo Videos Generation API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token і зберегти його для подальшого використання.

**Один API Token може викликати всі сервіси платформи, немає потреби подавати заявку окремо для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт для безкоштовного ознайомлення; якщо ліміту недостатньо, ви можете поповнити універсальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

## Базове використання

Спочатку розглянемо базовий спосіб використання: введіть промпт `prompt`, дію генерації `action`, масив зображень для посилань на перший і останній кадри `image_urls`, а також модель `model`, і ви отримаєте оброблений результат. Спочатку потрібно просто передати поле `action` зі значенням `text2video`, воно переважно містить три дії: генерація відео з тексту (`text2video`), генерація відео із зображення (`image2video`), отримання відео 1080p (`get1080p`), далі також потрібно ввести модель `model`; наразі доступні моделі `veo31-fast`, `veo3`, `veo31`, `veo3-fast` і `veo31-fast-ingredients`, конкретний вміст наведено нижче:

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

Тут можна побачити, що ми налаштували Request Headers, зокрема:

- `accept`: у якому форматі бажано отримати результат відповіді; тут вказано `application/json`, тобто формат JSON.
- `authorization`: ключ для виклику API, після отримання заявки його можна безпосередньо вибрати зі спадного списку.

Також налаштовано Request Body, зокрема:

- `model`: модель для генерації відео; основними є моделі `veo31-fast`, `veo3`, `veo31`, `veo3-fast` і `veo31-fast-ingredients`.
- `action`: дія цього завдання з генерації відео; переважно містить три дії: генерація відео з тексту (`text2video`), генерація відео із зображення (`image2video`), отримання відео 1080p (`get1080p`).
- `image_urls`: посилання на зображення для завантаження, яке обов’язково потрібне при виборі дії генерації відео із зображення `image2video`. Для `veo31-fast-ingredients` — максимум 3 зображення (об’єднання кількох зображень), для інших моделей — максимум 2 зображення (режим першого й останнього кадрів).
- `resolution`: вибір роздільної здатності генерованого відео; серед них модель veo31 підтримує роздільну здатність 4k, інші моделі її не підтримують, усі моделі підтримують роздільні здатності 1080p і gif; якщо це значення не передано, за замовчуванням використовується роздільна здатність 720p; основні варіанти: `1080p`, `gif`, `4k`.
- `prompt`: промпт.
- `callback_url`: URL, на який потрібно отримати результат зворотного виклику.
- `async`: необов’язково; коли встановлено значення `true`, інтерфейс негайно повертає `task_id`, без необхідності надавати `callback_url`, після чого результат отримується шляхом опитування через відповідний інтерфейс запиту завдання.

### 🔑 Пояснення ключових правил

1. **Загальна логіка**:
   - **Без введення зображень** → автоматично активується режим генерації відео з тексту.
   - **З введенням зображень** → активується режим генерації відео із зображення (конкретна поведінка визначається кількістю зображень).
2. **Типи режиму генерації відео із зображення**:
   - **Режим першого кадру** (1 зображення): перший кадр фіксується як введене зображення.
   - **Режим першого й останнього кадрів** (2 зображення): перший і останній кадри фіксуються як введені зображення.
   - **Режим об’єднання кількох зображень** (1-3 зображення): підтримується лише `veo31-fast-ingredients`, генерує відео шляхом об’єднання вмісту кількох зображень.
3. **Класифікація режимів**:

  - **Режим Fast**: `veo3-fast`, `veo31-fast`, `veo31-fast-ingredients`.
   - **Режим Quality**: `veo3`, `veo31` (вища якість генерації).

### ⚠️ Примітки

- **Єдина модель з обов’язковим передаванням зображень**: для `veo31-fast-ingredients` необхідно передати зображення (1-3), інакше вона не зможе працювати.
- **Обмеження кількості зображень**:
  - `veo31-fast-ingredients` підтримує введення **1-3 зображень** (режим об’єднання кількох зображень).
  - Інші моделі підтримують максимум **2 зображення** (режим першого й останнього кадрів).

## Функція генерації відео із зображень

Якщо ви хочете генерувати відео на основі зображень першого та останнього кадрів, можна встановити параметр `action` як `image2video` і ввести масив посилань на зображення першого та останнього кадрів `image_urls`。

Далі нам потрібно обов’язково заповнити підказки, які необхідно розширити на наступному кроці, щоб налаштувати генерацію відео, можна вказати такий вміст：

- `model`：модель для генерації відео, основні: `veo31-fast`、`veo3`、`veo31`、`veo3-fast` і `veo31-fast-ingredients`。
- `image_urls`：коли вибрано дію генерації відео із зображень `image2video`, обов’язково потрібні посилання на завантажені еталонні зображення。
- `prompt`：підказка。

Приклад заповнення наведено нижче：

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

Після завершення заповнення автоматично генерується такий код：

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

Відповідний код Python：

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo31-fast",
    "prompt": "Let it dance",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Асинхронний зворотний виклик

Оскільки час генерування Veo Videos Generation API є відносно тривалим, приблизно 1–2 хвилини, якщо API тривалий час не відповідає, HTTP-запит постійно підтримуватиме з’єднання, що призводить до додаткового споживання системних ресурсів, тому цей API також підтримує асинхронні зворотні виклики.

Загальний процес такий: коли клієнт ініціює запит, він додатково вказує поле `callback_url`; після того як клієнт надсилає API-запит, API негайно повертає результат, що містить поле `task_id`, яке представляє ID поточного завдання. Після завершення завдання результат генерування відео буде надіслано у форматі POST JSON до `callback_url`, вказаного клієнтом, де також міститиметься поле `task_id`, таким чином результати завдання можна пов’язати за ID.

Нижче ми на прикладі розглянемо, як саме це зробити.

Спочатку, зворотний виклик Webhook — це сервіс, який може приймати HTTP-запити, і розробник має замінити його на URL власного HTTP-сервера. Для зручності демонстрації тут використовується публічний зразковий сайт Webhook https://webhook.site/; відкривши цей сайт, можна отримати Webhook URL, як показано на зображенні:

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Занадто багато запитів, ви перевищили ліміт частоти.
- `500 api_error`：Внутрішня помилка сервера, на сервері щось пішло не так.

### Приклад відповіді з помилкою

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
