Основна функція API Veo Tasks полягає в тому, щоб за допомогою введеного ID завдання, згенерованого API Veo Videos Generation, перевіряти стан виконання цього завдання.

Цей документ детально описує інтеграцію API Veo Tasks, щоб допомогти вам легко інтегрувати та повністю використовувати потужні можливості цього API. За допомогою API Veo Tasks ви можете легко реалізувати перевірку стану виконання завдань API Veo Videos Generation.

## Процес подачі заявки

Щоб використовувати API Veo Tasks, спочатку потрібно перейти на сторінку подачі заявки [Veo Videos Generation API](https://platform.acedata.cloud/documents/veo-videos) для отримання відповідної послуги, а потім скопіювати ID завдання API Veo Videos Generation, як показано на малюнку:

<p><img src="https://cdn.acedata.cloud/txlg6g.png" width="500" className="m-auto" /></p>

Нарешті, перейдіть на сторінку Tasks API [Veo Tasks API](https://platform.acedata.cloud/documents/veo-tasks) для отримання відповідної послуги, після входу на сторінку натисніть кнопку «Acquire», як показано на малюнку:

![Сторінка подачі заявки](https://cdn.acedata.cloud/rci31i.png)

Якщо ви ще не увійшли в систему або не зареєструвалися, вас автоматично перенаправлять на [сторінку входу](https://platform.acedata.cloud), запрошуючи вас зареєструватися та увійти. Після входу або реєстрації ви автоматично повернетеся на поточну сторінку.

При першій подачі заявки вам буде надано безкоштовний ліміт, який дозволяє безкоштовно використовувати цей API.

## Приклад запиту

API Veo Tasks можна використовувати для перевірки результатів API Veo Videos Generation. Щоб дізнатися, як використовувати API Veo Videos Generation, будь ласка, зверніться до документа [Veo Videos Generation API](https://platform.acedata.cloud/documents/veo-videos).

Розглянемо приклад з ID завдання, яке повертає сервіс API Veo Videos Generation. Припустимо, у нас є ID завдання: 1ebe4f2b-59ba-4385-a4ea-0ce8a3fe12ed, далі демонструємо, як передати цей ID завдання.

### Налаштування заголовків запиту та тіла запиту

**Request Headers** включає:

- `accept`: вказує на прийняття відповіді у форматі JSON, тут вказується `application/json`.
- `authorization`: ключ для виклику API, після подачі заявки можна вибрати з випадаючого списку.

**Request Body** включає:

- `id`: ID завдання, яке було завантажено.
- `action`: спосіб виконання завдання.

Налаштування, як показано на малюнку:

### Приклад коду

Можна помітити, що на правій стороні сторінки вже автоматично згенеровано код на різних мовах, як показано на малюнку:

<p><img src="https://cdn.acedata.cloud/bsqh3i.png" width="500" className="m-auto" /></p>

Деякі приклади коду наведені нижче:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/veo/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1ebe4f2b-59ba-4385-a4ea-0ce8a3fe12ed",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/veo/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "1ebe4f2b-59ba-4385-a4ea-0ce8a3fe12ed",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Помилка обробка

При виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Занадто багато запитів, ви перевищили ліміт запитів.
- `500 api_error`：Внутрішня помилка сервера, щось пішло не так на сервері.
