Основна функція Producer Tasks API полягає в запиті статусу виконання завдання шляхом введення ID завдання, згенерованого Producer Audios Generation API.

У цьому документі буде детально представлено інструкції з інтеграції Producer Tasks API, щоб допомогти вам легко інтегруватися та повною мірою використовувати потужні можливості цього API. За допомогою Producer Tasks API ви можете легко реалізувати запит статусу виконання завдань Producer Audios Generation API.

## Процес подання заявки

Щоб використовувати Producer Audios Generation API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token і зберегти його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли в систему або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти в систему, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, немає потреби подавати заявку окремо для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт, яким можна безкоштовно скористатися для ознайомлення; якщо ліміту недостатньо, ви можете поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Приклад запиту

Producer Tasks API можна використовувати для запиту результатів Producer Audios Generation API. Щодо того, як використовувати Producer Audios Generation API, зверніться до документації [Producer Audios Generation API ](https://platform.acedata.cloud/documents/producer-audios-integration)。

Ми візьмемо як приклад один ID завдання, повернений сервісом Producer Audios Generation API, щоб продемонструвати, як використовувати цей API. Припустимо, ми маємо ID завдання: 1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad, далі буде продемонстровано, як шляхом передавання ID завдання.

### Налаштування заголовків запиту та тіла запиту

**Request Headers** включають:

- `accept`: указує отримання результату відповіді у форматі JSON, тут заповнюється як `application/json`.
- `authorization`: ключ для виклику API, після подання заявки його можна безпосередньо вибрати зі спадного списку.

**Request Body** включає:

- `id`: ID завантаженого завдання.
- `action`: спосіб операції над завданням.

Налаштування показано на зображенні нижче:

### Приклад коду

Можна побачити, що в правій частині сторінки вже автоматично згенеровано код різними мовами, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/u4pb2f.png" width="500" className="m-auto" /></p>

Частину прикладів коду наведено нижче:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

## Обробка помилок

Під час виклику API, якщо виникає помилка, API повертає відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Некоректний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Некоректний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Занадто багато запитів, ви перевищили ліміт частоти.
- `500 api_error`：Внутрішня помилка сервера, щось пішло не так на сервері.
