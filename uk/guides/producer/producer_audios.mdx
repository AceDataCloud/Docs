У цій статті буде представлено інструкцію з інтеграції Producer Audios Generation API, за допомогою якого можна генерувати офіційну музику Producer, вводячи власні параметри.

## Процес подання заявки

Щоб використовувати Producer Audios Generation API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token, і збережіть його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли в систему або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, не потрібно подавати заявку окремо для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт для безкоштовного тестування; коли ліміту недостатньо, можна поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Обов’язкові параметри залежно від операції

Коли `action=generate` і `custom=false` (за замовчуванням), надайте `prompt`; коли `custom=true`
і `instrumental=false`, надайте `lyric`. Для створення власної інструментальної музики можна встановити
`custom=true, instrumental=true`, без потреби вигадувати текст пісні або додаткові підказки.
Для `action=extend` потрібні `audio_id` і `continue_at`, більше за 0, а в неінструментальному режимі також потрібен
`lyric`. Кавер, варіація, заміна фрагмента, обмін партіями та розділення аудіодоріжок усі потребують вихідного `audio_id`;
текст пісні та підказки не повинні бути безумовно обов’язковими для всіх операцій.

У MCP `producer_extend_music` і `producer_replace_section`, коли надається `lyric`,
вибирають режим власного тексту пісні; для продовження інструментальної музики можна передати `instrumental=true` і не вказувати текст пісні.

## Базове використання

Яку пісню ви хочете, можна довільно ввести текст, наприклад, якщо я хочу згенерувати пісню про Різдво, можна ввести `a song for Christmas`, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Тут можна побачити, що ми встановили Request Headers, зокрема:

- `accept`: у якому форматі ви хочете отримати результат відповіді, тут указано `application/json`, тобто формат JSON.
- `authorization`: ключ для виклику API, після подання заявки його можна безпосередньо вибрати зі спадного списку.

Крім того, параметри Request Body включають:

- `action`: дія цього завдання з генерації музики, для генерації пісні використовується `generate`.
- `model`: модель, яка використовується для створення пісні, наразі основними є: **FUZZ-2.0 Pro**、**FUZZ-2.0**、**FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**、**FUZZ-1.0 Pro**、**FUZZ-1.0**、**FUZZ-1.1**、**FUZZ-0.8**。
- `lyric`: зміст тексту пісні.
- `custom`: чи використовувати власний спосіб для генерації пісні.
- `prompt`: підказка в режимі натхнення.
- `title`: інформація про назву пісні.
- `audio_id`: ID еталонної пісні, використовується для таких операцій, як продовження/кавер тощо.
- `continue_at`: продовження пісні з указаного числа секунд.
- `replace_section_start`/`replace_section_end`: час початку та завершення фрагмента для заміни, в секундах.
- `lyrics_strength`: сила тексту пісні, позначає ступінь впливу тексту пісні на генерацію аудіо, доступний діапазон від 0 до 1, за замовчуванням 0.7.
- `sound_strength`: сила аудіопідказки, доступний діапазон від 0.2 до 1, за замовчуванням 0.7.
- `cover_strength`: сила каверу, від 0.2 до 1, за замовчуванням 1.
- `weirdness`: ступінь незвичності стилю, доступний діапазон від 0 до 1, за замовчуванням 0.5
- `callback_url`: URL, на який потрібен зворотний виклик результату.
- `async`: необов’язково, якщо встановити `true`, інтерфейс негайно поверне `task_id`, не потрібно надавати `callback_url`, після чого результат можна отримати шляхом опитування через відповідний інтерфейс запиту завдань.
- `instrumental`: чи це режим без тексту пісні.

Можна побачити, що ми отримали інформацію про музику, яку хотіли згенерувати; нам потрібно лише отримати згенеровану музику Producer за адресою посилання на музику в `data` результату.

Крім того, якщо ви хочете згенерувати відповідний код інтеграції, його можна безпосередньо скопіювати, наприклад, код CURL має такий вигляд:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Кавер-версії пісень

Якщо ви хочете виконати операцію створення кавер-версії вже згенерованої пісні, можна ввести згенеровану вище пісню для створення кавер-версії, далі ми користувацьки генеруватимемо пісні на основі тексту та назви.

Якщо ви хочете продовжити створювати кавер-версію пісні, завантаженої самостійно, можна встановити параметр `action` як `upload_cover` і ввести ID пісні, завантаженої користувацьки, для якої потрібно продовжити створення кавер-версії. ID пісні отримується за допомогою [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), як показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Можна вказати такий вміст:

- action：дія цього завдання пісні; наразі підтримуються: generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation; для цього створення кавер-версії використовується параметр `cover`.
- lyric：текст пісні
- title：назва пісні.
- custom：чи використовувати користувацький режим для генерації, за замовчуванням — false.
- audio_id：ID пісні, для якої потрібно створити кавер-версію.

## Продовження пісні

Якщо ви хочете продовжити власноруч завантажену пісню, можна встановити для параметра `action` значення `upload_extend`, а також ввести ID власноруч завантаженої пісні, яку потрібно продовжити. ## Асинхронний зворотний виклик

Оскільки час генерації Producer Audios Generation API іноді може бути відносно тривалим, якщо API довгий час не відповідає, HTTP-запит постійно підтримуватиме з'єднання, що призводить до додаткового споживання системних ресурсів, тому цей API також надає підтримку асинхронного зворотного виклику.

Загальний процес такий: коли клієнт ініціює запит, він додатково вказує поле `callback_url`; після того як клієнт ініціює API-запит, API негайно повертає результат, що містить інформацію поля `task_id`, яке представляє ID поточного завдання. Коли завдання завершено, результат завдання генерації буде надіслано у формі POST JSON на вказаний клієнтом `callback_url`, який також містить поле `task_id`, таким чином результати завдання можна пов'язати за ID.

Далі ми розглянемо на прикладі, як саме виконати цю операцію.

Спочатку Webhook-зворотний виклик — це сервіс, який може приймати HTTP-запити; розробник повинен замінити його на URL власного HTTP-сервера. Для зручності демонстрації тут використовується публічний сайт-приклад Webhook [https://webhook.site/](https://webhook.site/); відкривши цей сайт, можна отримати Webhook URL, як показано на зображенні:

![](https://cdn.acedata.cloud/tbcnai.png)

Далі ми можемо встановити значення поля `callback_url` як зазначений вище Webhook URL і водночас заповнити відповідні параметри; конкретний вміст показано на зображенні:

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Забагато запитів, ви перевищили ліміт частоти запитів.
- `500 api_error`：Внутрішня помилка сервера, на сервері щось пішло не так.
