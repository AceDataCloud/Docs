У цій статті буде представлено інструкцію з інтеграції Producer Audios Generation API, який може генерувати офіційну музику Producer шляхом введення користувацьких параметрів.

## Процес подання заявки

Щоб використовувати Producer Audios Generation API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token і зберегти його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу, де вам буде запропоновано зареєструватися та увійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, не потрібно подавати заявку окремо для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт для безкоштовного тестування; якщо ліміту недостатньо, ви можете поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Базове використання

Які пісні ви хочете, можна довільно ввести текст, наприклад, якщо я хочу згенерувати пісню про Різдво, можна ввести `a song for Christmas`, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Можна побачити, що тут ми налаштували Request Headers, зокрема:

- `accept`: у якому форматі ви хочете отримати результат відповіді, тут указано `application/json`, тобто формат JSON.
- `authorization`: ключ для виклику API, після подання заявки його можна безпосередньо вибрати зі спадного списку.

Крім того, параметри Request Body включають:

- `action`: дія цього завдання з генерації музики, для генерації пісні це `generate`.
- `model`: модель, яка використовується для створення пісні, наразі основними є: **FUZZ-2.0 Pro**、**FUZZ-2.0**、**FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**、**FUZZ-1.0 Pro**、**FUZZ-1.0**、**FUZZ-1.1**、**FUZZ-0.8**。
- `lyric`: зміст тексту пісні.
- `custom`: чи використовувати користувацький спосіб для генерації пісні.
- `prompt`: підказка в режимі натхнення.
- `title`: інформація про назву пісні.
- `audio_id`: ID еталонної пісні, використовується для продовження/каверу та інших операцій.
- `continue_at`: продовжити написання пісні з вказаної секунди.
- `replace_section_start`/`replace_section_end`: час початку й завершення фрагмента для заміни, в секундах.
- `lyrics_strength`: сила тексту, означає ступінь впливу тексту на генерацію аудіо, може бути від 0 до 1, за замовчуванням 0.7.
- `sound_strength`: сила аудіопідказки, може бути від 0.2 до 1, за замовчуванням 0.7.
- `cover_strength`: сила каверу, від 0.2 до 1, за замовчуванням 1.
- `weirdness`: ступінь незвичайності стилю, може бути від 0 до 1, за замовчуванням 0.5
- `callback_url`: URL, на який потрібно повернути результат через callback.
- `async`: необов’язково, якщо встановлено `true`, інтерфейс негайно повертає `task_id`, немає потреби надавати `callback_url`, після чого результат отримується шляхом опитування через відповідний інтерфейс запиту завдань.
- `instrumental`: чи це режим без тексту пісні.

Результат, що повертається, містить кілька полів, описаних нижче:

    - `lyric`, інформація про текст пісні в завданні з генерації музики на цей момент.

Можна побачити, що ми отримали бажану інформацію про згенеровану музику, нам лише потрібно отримати згенеровану музику Producer за адресою посилання на музику в `data` результату.

Крім того, якщо ви хочете згенерувати відповідний код інтеграції, можете безпосередньо скопіювати згенерований, наприклад, код CURL наведено нижче:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Кавер пісні

Якщо ви хочете виконати операцію створення каверу для вже згенерованої пісні, можете ввести згенеровану вище пісню для створення каверу; далі ми користувацьки згенеруємо пісню на основі тексту та назви.

Якщо ви хочете продовжити створення каверу для власноруч завантаженої пісні, можете встановити параметр `action` як `upload_cover` , а також ввести ID користувацьки завантаженої пісні, для якої потрібно продовжити створення каверу. ID пісні отримується за допомогою [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), як показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Тоді можна вказати такий вміст:

- action：дія цього завдання пісні, наразі підтримуються: generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation, для цього каверу використовується параметр `cover`.
- lyric：текст пісні
- title：назва пісні。
- custom：чи використовувати режим користувацької генерації, за замовчуванням false。
- audio_id：ID пісні, для якої потрібно створити кавер。

## Продовження пісні

Якщо потрібно продовжити пісню, завантажену власноруч, можна встановити для параметра `action` значення `upload_extend` і ввести ID власноруч завантаженої пісні, яку потрібно продовжити. ## Асинхронний зворотний виклик

Оскільки час генерації Producer Audios Generation API іноді може бути відносно тривалим, якщо API довгий час не відповідає, HTTP-запит постійно підтримуватиме з’єднання, що призводить до додаткового споживання системних ресурсів, тому цей API також надає підтримку асинхронних зворотних викликів.

Загальний процес такий: коли клієнт ініціює запит, він додатково вказує поле `callback_url`; після того як клієнт ініціює API-запит, API негайно повертає результат, що містить інформацію про поле `task_id`, яке представляє ID поточного завдання. Після завершення завдання результат завдання генерації буде надіслано у формі POST JSON на вказаний клієнтом `callback_url`, де також міститься поле `task_id`, таким чином результати завдання можна пов’язати за ID.

Далі ми дізнаємося, як саме це зробити, на прикладі.

Спочатку Webhook-зворотний виклик — це сервіс, який може приймати HTTP-запити, розробник має замінити його на URL власного розгорнутого HTTP-сервера. Тут для зручності демонстрації використовується публічний приклад вебсайту Webhook [https://webhook.site/](https://webhook.site/); відкривши цей вебсайт, можна отримати Webhook URL, як показано на зображенні:

![](https://cdn.acedata.cloud/tbcnai.png)

Можна побачити, що в результаті є поле `task_id`, інші поля схожі на наведені вище, за допомогою цього поля можна реалізувати зв’язування завдань.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Забагато запитів, ви перевищили ліміт частоти.
- `500 api_error`：Внутрішня помилка сервера, щось пішло не так на сервері.

### Приклад відповіді з помилкою

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
