OpenAI нещодавно представила інтерфейс для створення відповідей моделі. Надавайте текстові або зображувальні вхідні дані для генерування текстових або зображувальних вихідних даних. Дозвольте моделі викликати ваш власний користувацький код або використовувати вбудовані інструменти, такі як вебпошук або пошук файлів, щоб використовувати ваші власні дані як вхідні дані для відповідей моделі.

Цей документ переважно описує процес використання OpenAI Responses API, за допомогою якого ми можемо легко використовувати офіційну функцію OpenAI для створення відповідей моделі.

## Процес подання заявки

Щоб використовувати OpenAI Responses API, спершу перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати свій API Token і зберегти його про запас.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не ввійшли або не зареєструвалися, вас автоматично буде перенаправлено на сторінку входу із запрошенням зареєструватися та ввійти, а після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, немає потреби подавати заявку окремо для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт для безкоштовного ознайомлення; якщо ліміту недостатньо, можна поповнити універсальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Базове використання

Далі можна заповнити відповідний вміст в інтерфейсі, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Під час першого використання цього інтерфейсу нам щонайменше потрібно заповнити три поля: одне з них — `authorization`, його можна безпосередньо вибрати у спадному списку. Інший параметр — `model`, `model` — це категорія моделі OpenAI ChatGPT з офіційного сайту, яку ми обираємо для використання; тут ми переважно маємо 20 моделей, детальніше можна переглянути в моделях, які ми надаємо. Останній параметр — `input`, `input` — це масив введених нами запитів, це масив, що означає можливість одночасного завантаження кількох запитів, кожен запит містить `role` і `content`, де `role` позначає роль того, хто ставить запитання, ми надаємо три ролі: `user`, `assistant`, `system`. Інший параметр, `content`, — це конкретний вміст нашого запитання.

Водночас ви можете звернути увагу, що праворуч генерується відповідний код виклику, ви можете скопіювати код і запустити його безпосередньо, або ж одразу натиснути кнопку «Try» для тестування.

Поширені необов’язкові параметри:

- `max_tokens`: обмежує максимальну кількість токенів в одній відповіді.
- `temperature`: випадковість генерації, у межах 0–2, чим більше значення, тим більш розосереджений результат.
- `n`: скільки кандидатів відповідей генерувати за один раз.
- `response_format`: налаштування формату повернення.
- `tools`: визначення викликів функцій/інструментів.
- `background`: чи запускати асинхронно у фоновому режимі.

## Потокова відповідь

Цей інтерфейс також підтримує потокові відповіді, що дуже корисно для інтеграції з вебсторінками та дозволяє реалізувати ефект посимвольного відображення на вебсторінці.

Якщо ви хочете повертати відповідь потоково, можна змінити параметр `stream ` у заголовку запиту на `true`.

Зміну показано на зображенні, однак код виклику потребує відповідних змін, щоб підтримувати потокову відповідь.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Після зміни `stream` на `true` API повертатиме відповідні дані JSON рядок за рядком, і на рівні коду нам потрібно внести відповідні зміни, щоб отримувати результат рядок за рядком.

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Можна побачити, що у відповіді є багато `data`, а `delta` всередині `data` є найновішим вмістом відповіді, що відповідає описаному вище вмісту. `delta` — це доданий вміст відповіді, ви можете інтегрувати його у свою систему відповідно до результату. Потокова відповідь має `response.completed` або `response.incomplete` як кінцевий стан; `usage` у кінцевому стані є остаточним використанням token для цього запиту, а також основою для розрахунку вартості.

Якщо клієнт розриває з’єднання до настання кінцевого стану, цей запит реєструється як закритий клієнтом (499), і для розрахунку вартості не використовуватиметься локальна оцінка token; якщо з’єднання завершується нормально, але кінцевий стан і остаточний `usage` не отримано, цей запит реєструється як неповна відповідь (502), і для розрахунку вартості також не використовуватиметься оцінка token. У разі виникнення цих двох ситуацій повторно ініціюйте запит.

Повернений результат `data` загалом має кілька полів, описаних нижче:

- `item_id` — ID згенерованого завдання цього діалогу, що використовується для унікальної ідентифікації цього завдання діалогу.
- `type` — тип згенерованого завдання Responses цього діалогу.
- `model ` — вибрана модель OpenAI ChatGPT з офіційного вебсайту.
- `delta` — інформація відповіді, надана ChatGPT на запит.

JavaScript також підтримується, наприклад, код потокового виклику Node.js наведено нижче:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Багатораундовий діалог

Якщо ви хочете інтегрувати функцію багатораундового діалогу, вам потрібно передати кілька запитів у полі `input`, конкретний приклад кількох запитів показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/1jqwnf.png" width="400" className="m-auto" /></p>

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"},{"role":"assistant","content":"Hello! How can I help you today? 😊"},{"role":"user","content":"What did I just say?"}]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Можна побачити, що інформація, яку містить `output`, відповідає вмісту базового використання; це містить конкретний вміст відповіді ChatGPT на кілька діалогів, тому можна відповідати на відповідні запитання на основі вмісту кількох діалогів.

## Візуальна модель

gpt-4o — це мультимодальна велика мовна модель, розроблена OpenAI, вона додає можливості візуального розуміння на основі GPT-4. Ця модель може одночасно обробляти текстові та графічні вхідні дані, реалізуючи міжмодальне розуміння та генерацію.
Обробка тексту з використанням моделі gpt-4o узгоджується з базовим використанням, описаним вище; нижче буде коротко представлено, як використовувати можливості моделі для обробки зображень.

Можливості обробки зображень моделі gpt-4o головним чином використовуються шляхом додавання поля `type` на основі початкового вмісту `content`; за допомогою цього поля можна визначити, чи завантажено текст або зображення, щоб таким чином використовувати можливості обробки зображень моделі gpt-4o. Нижче переважно описано виклик цієї функції двома способами: Curl і Python.

- Спосіб за допомогою скрипта Curl


- Спосіб за допомогою скрипта Python

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Обробка помилок

Під час виклику API, якщо виникає помилка, API повертає відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`: Неправильний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`: Неправильний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`: Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`: Забагато запитів, ви перевищили ліміт частоти.
- `500 api_error`: Внутрішня помилка сервера, щось пішло не так на сервері.
