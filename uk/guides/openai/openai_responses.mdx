Сумісні запити до моделей, які приймає платформа, оплачуються відповідно до обсягу введення, виведення та кешування моделі. Загальний обсяг введення Responses включає повідомлені кешовані token, а кешована частина розраховується за відповідною ціною кешування; зміна формату інтерфейсу не перетворює тарифікацію на оплату за фіксовану кількість викликів. Вартість визначається поточними цінами моделей у консолі та `usage.cost` у відповіді.

OpenAI нещодавно надала інтерфейс для створення відповідей моделі. Надавайте текстові або графічні вхідні дані для генерування текстових або графічних вихідних даних. Дозвольте моделі викликати ваш власний користувацький код або використовувати вбудовані інструменти, як-от вебпошук або пошук файлів, щоб використовувати власні дані як вхідні дані для відповіді моделі.

Цей документ переважно знайомить із процесом використання OpenAI Responses API; за його допомогою ми можемо легко використовувати офіційну функцію OpenAI для створення відповідей моделі.

## GPT-6.1 Terra

Використовуйте `model: "gpt-6.1-terra"` для вибору цієї моделі. Підтримуються текстовий і графічний ввід, потокове виведення, інструменти функцій і структуроване виведення. Рівні міркування підтримують `low`, `medium`, `high`, `xhigh` і `max`; рекомендовано почати з `reasoning: {"effort": "low"}`; `none` або `minimal` не підтримуються. Коли введення перевищує 272,000 tokens, застосовується ціна за довгий контекст; фактична вартість визначається поточною ціною в консолі та використанням у відповіді.

## GPT-6.1 Sol

Використовуйте `model: "gpt-6.1-sol"` для вибору цієї моделі. Підтримуються потокове виведення, виклики функцій, структуроване виведення та графічний ввід. Протягом першого тижня після відкриття доступ надається лише верифікованим власникам ACE T1+ (щонайменше 100,000 ACE) або авторизованим користувачам; конкретний час відкриття визначається підказками доступу в консолі.

Рівні міркування підтримують `low`, `medium`, `high`, `xhigh` і `max`, `none` або `minimal` наразі не підтримуються. Рекомендовано почати з `reasoning: {"effort": "low"}`. Коли введення перевищує 272,000 tokens, до всього запиту застосовується ціна за довгий контекст, а вартість визначається поточною ціною в консолі.

## Процес подання заявки

Щоб використовувати OpenAI Responses API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token, і збережіть його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не ввійшли в систему або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із запрошенням зареєструватися та увійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, не потрібно подавати окрему заявку для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт для безкоштовного тестування; коли ліміту недостатньо, ви можете поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Базове використання

Далі можна заповнити відповідний вміст в інтерфейсі, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Під час першого використання цього інтерфейсу нам потрібно заповнити щонайменше три елементи: один із них — `authorization`, який можна безпосередньо вибрати у випадаючому списку. Інший параметр — `model`; `model` — це категорія моделі з офіційного сайту OpenAI ChatGPT, яку ми вибираємо для використання, тут ми переважно маємо 20 моделей, деталі можна переглянути в наданих нами моделях. Останній параметр — `input`; `input` — це масив введених нами запитів, він є масивом, що означає можливість одночасно завантажувати кілька запитів, кожен запит містить `role` і `content`, де `role` позначає роль того, хто ставить запитання, ми надаємо три ідентичності: `user`, `assistant`, `system`. Інший `content` — це конкретний зміст нашого запитання.

Водночас ви можете звернути увагу, що праворуч генерується відповідний код виклику; ви можете скопіювати код і запустити його безпосередньо, або безпосередньо натиснути кнопку «Try» для тестування.

Поширені необов’язкові параметри:

- `max_tokens`: обмежує максимальну кількість token в одній відповіді.
- `temperature`: випадковість генерації, від 0 до 2, чим більше значення, тим більш розсіяний результат.
- `n`: скільки варіантів відповідей генерувати за один раз.
- `response_format`: налаштування формату відповіді.
- `tools`: визначення викликів функцій/інструментів.
- `background`: чи запускати асинхронно у фоновому режимі.

## Потокова відповідь

Цей інтерфейс також підтримує потокову відповідь, що дуже корисно для інтеграції з вебсторінками та дозволяє вебсторінці реалізувати ефект поступового відображення символ за символом.

Якщо ви хочете повертати відповідь потоково, можна змінити параметр `stream ` у заголовку запиту на `true`.

Зміни показано на зображенні, але код виклику потребує відповідних змін для підтримки потокової відповіді.
<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Після зміни `stream` на `true` API повертатиме відповідні дані JSON рядок за рядком, і на рівні коду нам потрібно внести відповідні зміни, щоб отримати результати рядок за рядком.

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Як можна побачити, у відповіді є багато `data`, а `delta` у `data` є найновішим вмістом відповіді, що узгоджується з вищезазначеним описом. `delta` — це доданий вміст відповіді, ви можете на основі результату інтегрувати його у свою систему. Потокова відповідь має `response.completed` або `response.incomplete` як кінцевий стан; `usage` у кінцевому стані є остаточним використанням токенів для цього запиту, а також основою для виставлення рахунків.

Якщо клієнт відключається до досягнення кінцевого стану, цей запит буде записано як закритий клієнтом (499), і плата не стягуватиметься на основі локально оцінених токенів; якщо з’єднання нормально завершується, але кінцевий стан і остаточне `usage` не отримано, цей запит буде записано як неповна відповідь (502), і плата також не стягуватиметься на основі оцінених токенів. У разі виникнення цих двох ситуацій надішліть запит повторно.

Повернений результат `data` має кілька полів, описаних нижче:

- `item_id` — ID згенерованого завдання цього діалогу, що використовується для унікальної ідентифікації цього завдання діалогу.
- `type` — тип згенерованого завдання Responses цього діалогу.
- `model ` — вибрана модель з офіційного сайту OpenAI ChatGPT.
- `delta` — інформація відповіді, надана ChatGPT на запит.

JavaScript також підтримується, наприклад, код потокового виклику для Node.js наведено нижче:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

Приклад коду Java:

```java

OkHttpClient client = new OkHttpClient();
```

Якщо ви хочете інтегрувати функцію багатораундового діалогу, вам потрібно передати кілька запитів у поле `input`; конкретний приклад кількох запитів показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/1jqwnf.png" width="400" className="m-auto" /></p>

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"},{"role":"assistant","content":"Hello! How can I help you today? 😊"},{"role":"user","content":"What did I just say?"}]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Візуальна модель

gpt-4o — це мультимодальна велика мовна модель, розроблена OpenAI, яка додає можливість візуального розуміння на основі GPT-4. Ця модель може одночасно обробляти текстовий і графічний вхід, реалізуючи міжмодальне розуміння та генерацію.

Текстова обробка з використанням моделі gpt-4o узгоджується зі змістом базового використання вище; нижче буде коротко представлено, як використовувати можливості моделі для обробки зображень.

Можливість обробки зображень моделі gpt-4o переважно реалізується шляхом додавання поля `type` на основі початкового вмісту `content`; за допомогою цього поля можна дізнатися, чи завантажено текст або зображення, і таким чином використовувати можливість обробки зображень моделі gpt-4o. Нижче переважно описано виклик цієї функції двома способами: Curl і Python.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`: Неправильний запит, можливо через відсутні або недійсні параметри.
- `400 api_not_implemented`: Неправильний запит, можливо через відсутні або недійсні параметри.
- `401 invalid_token`: Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`: Забагато запитів, ви перевищили обмеження швидкості.
- `500 api_error`: Внутрішня помилка сервера, на сервері щось пішло не так.
