OpenAI нещодавно надав інтерфейс для створення відповідей моделі. Надавайте текстові або зображувальні вхідні дані для генерування текстових або зображувальних вихідних даних. Дозвольте моделі викликати ваш власний користувацький код або використовувати вбудовані інструменти, як-от вебпошук або пошук файлів, щоб використовувати ваші власні дані як вхідні дані для відповідей моделі.

Цей документ переважно описує процес використання OpenAI Responses API. Використовуючи його, ми можемо легко застосовувати офіційну функцію OpenAI для створення відповідей моделі.

## Процес подання заявки

Щоб використовувати OpenAI Responses API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token, і збережіть його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли або не зареєструвалися, вас автоматично буде перенаправлено на сторінку входу із запрошенням зареєструватися та увійти, після завершення вас буде автоматично повернуто на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, не потрібно подавати окрему заявку для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт для безкоштовного ознайомлення; коли ліміту недостатньо, ви можете поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Базове використання

Далі ви можете заповнити відповідний вміст в інтерфейсі, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Під час першого використання цього інтерфейсу нам щонайменше потрібно заповнити три поля: одне з них — `authorization`, яке можна безпосередньо вибрати у спадному списку. Інший параметр — `model`, `model` — це категорія моделі OpenAI ChatGPT з офіційного сайту, яку ми обираємо для використання; тут ми переважно маємо 20 моделей, детальніше можна переглянути надані нами моделі. Останній параметр — `input`, `input` — це масив введених нами запитів, він є масивом, що означає можливість одночасного завантаження кількох запитів; кожен запит містить `role` і `content`, де `role` представляє роль запитувача, ми надаємо три ролі: `user`, `assistant`, `system`. Інший `content` — це конкретний вміст нашого запиту.

Водночас ви можете звернути увагу, що праворуч генерується відповідний код виклику: ви можете скопіювати код і запустити його безпосередньо або натиснути кнопку «Try» для тестування.

Поширені необов’язкові параметри:

- `max_tokens`: обмежує максимальну кількість токенів в одній відповіді.
- `temperature`: випадковість генерації, від 0 до 2, чим більше значення, тим більш розгалуженим є результат.
- `n`: скільки варіантів відповідей генерувати за один раз.
- `response_format`: налаштування формату повернення.
- `tools`: визначення викликів функцій/інструментів.
- `background`: чи запускати асинхронно у фоновому режимі.

## Потокова відповідь

Цей інтерфейс також підтримує потокову відповідь, що дуже корисно для інтеграції з вебсторінками та дозволяє реалізувати ефект посимвольного відображення на вебсторінці.

Якщо ви хочете повертати відповідь потоково, можна змінити параметр `stream ` у заголовку запиту на `true`.

Зміни показано на зображенні, однак код виклику потребує відповідних змін для підтримки потокової відповіді.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Після зміни `stream` на `true` API повертатиме відповідні JSON-дані рядок за рядком, а на рівні коду нам потрібно внести відповідні зміни, щоб отримати результати по рядках.

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

可以看到，响应里面有许多 `data` ，`data` 里面的 `delta` 即为最新的回答内容，与上文介绍的内容一致。`delta` 是新增的回答内容，您可以根据结果来对接到您的系统中。流式响应以 `response.completed` 或 `response.incomplete` 作为终态；终态中的 `usage` 是本次请求的最终 token 用量，也是计费依据。

如果客户端在终态到达前断开连接，本次请求记录为客户端已关闭（499），不会使用本地估算 token 计费；如果连接正常结束但没有收到终态及最终 `usage`，本次请求记录为响应不完整（502），同样不会使用估算 token 计费。遇到这两种情况时，请重新发起请求。

返回的 `data` 结果一共有多个字段，介绍如下：

- `item_id`，生成此次对话任务的 ID，用于唯一标识此次对话任务。
- `type`，生成此次对话 Responses 任务的类型。
- `model `，选择的 OpenAI ChatGPT 官网模型。
- `delta`，ChatGPT 针对提问词给于的回答信息。

JavaScript 也是支持的，比如 Node.js 的流式调用代码如下：

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

```java

OkHttpClient client = new OkHttpClient();

System.out.print(response.body!!.string())
```

## Багатораундовий діалог

Якщо ви хочете підключити функцію багатораундового діалогу, вам потрібно передати кілька запитів у поле `input`; конкретний приклад кількох запитів показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/1jqwnf.png" width="400" className="m-auto" /></p>

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"},{"role":"assistant","content":"Hello! How can I help you today? 😊"},{"role":"user","content":"What did I just say?"}]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Візуальна модель

gpt-4o — це мультимодальна велика мовна модель, розроблена OpenAI, яка на основі GPT-4 отримала можливість візуального розуміння. Ця модель може одночасно обробляти текстові та зображувальні вхідні дані, реалізуючи міжмодальне розуміння та генерацію.
Обробка тексту з використанням моделі gpt-4o узгоджується з основним використанням, описаним вище. Нижче буде коротко представлено, як використовувати можливості моделі з обробки зображень.

Використання можливостей обробки зображень моделі gpt-4o переважно здійснюється шляхом додавання поля `type` на основі початкового вмісту `content`. За допомогою цього поля можна визначити, чи завантажується текст або зображення, і таким чином використовувати можливості обробки зображень моделі gpt-4o. Нижче головним чином описано виклик цієї функції двома способами: Curl і Python.

- Спосіб за допомогою скрипту Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Спосіб за допомогою скрипту Python

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Обробка помилок

Під час виклику API, якщо виникає помилка, API повертає відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизований доступ, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Занадто багато запитів, ви перевищили ліміт частоти.
- `500 api_error`：Внутрішня помилка сервера, щось пішло не так на сервері.
