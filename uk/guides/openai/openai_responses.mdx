OpenAI нещодавно надав інтерфейс для створення відповідей моделі. Надавайте текстовий або графічний ввід для генерації текстового або графічного виводу. Дозвольте моделі викликати ваш власний користувацький код або використовувати вбудовані інструменти, такі як web-пошук або пошук файлів, щоб використовувати ваші власні дані як ввід для відповіді моделі.

У цьому документі переважно представлено процес використання OpenAI Responses API, за допомогою якого ми можемо легко використовувати офіційну функцію OpenAI для створення відповідей моделі.

## GPT-6.1 Sol

Використовуйте `model: "gpt-6.1-sol"` для вибору цієї моделі. Підтримуються потоковий вивід, виклик функцій, структурований вивід і графічний ввід. Протягом першого тижня після відкриття вона доступна лише підтвердженим власникам ACE T1+ (щонайменше 100 000 ACE) або авторизованим користувачам; конкретний час відкриття визначається підказкою доступу в консолі.

Рівні міркування підтримують `low`, `medium`, `high`, `xhigh` і `max`, наразі не підтримуються `none` або `minimal`. Рекомендується почати з `reasoning: {"effort": "low"}`. Коли ввід перевищує 272 000 tokens, до всього запиту застосовується ціна за довгий контекст, а вартість визначається поточною ціною в консолі.

## Процес подання заявки

Щоб використовувати OpenAI Responses API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати ваш API Token і зберегти його як резервний.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не ввійшли або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу з запрошенням зареєструватися та ввійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, не потрібно подавати окрему заявку для кожного сервісу.** Під час першого подання заявки буде надано безкоштовний ліміт, який можна використати для безкоштовного ознайомлення; коли ліміту недостатньо, ви можете поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Базове використання

Далі можна заповнити відповідний вміст в інтерфейсі, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Під час першого використання цього інтерфейсу нам потрібно заповнити щонайменше три поля: одне з них — `authorization`, яке можна безпосередньо вибрати у спадному списку. Інший параметр — `model`, `model` — це категорія моделі на офіційному сайті OpenAI ChatGPT, яку ми обираємо для використання; тут ми переважно маємо 20 моделей, деталі можна переглянути серед наданих нами моделей. Останній параметр — `input`, `input` — це масив введених нами запитів, він є масивом, що означає можливість одночасно завантажити кілька запитів; кожен запит містить `role` і `content`, де `role` позначає роль того, хто ставить запитання, ми надаємо три ідентичності: `user`, `assistant`, `system`. Інший `content` — це конкретний вміст нашого запитання.

Водночас ви можете помітити, що праворуч генерується відповідний код виклику, ви можете скопіювати код і запустити його безпосередньо, а також можете прямо натиснути кнопку «Try» для тестування.

Поширені необов’язкові параметри:

- `max_tokens`: обмежує максимальну кількість token в одній відповіді.
- `temperature`: випадковість генерації, від 0 до 2, чим більше значення, тим більш розсіяний результат.
- `n`: скільки варіантів відповідей генерувати за один раз.
- `response_format`: налаштування формату повернення.
- `tools`: визначення виклику функцій/інструментів.
- `background`: чи запускати асинхронно у фоновому режимі.

## Потокова відповідь

Цей інтерфейс також підтримує потокові відповіді, що дуже корисно для інтеграції з вебсторінками та дозволяє реалізувати на вебсторінці ефект посимвольного відображення.

Якщо ви хочете повертати відповіді потоково, можна змінити параметр `stream ` у заголовку запиту на `true`.

Зміна показана на зображенні, однак код виклику потребує відповідних змін для підтримки потокових відповідей.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Після зміни `stream` на `true` API повертатиме відповідні JSON-дані рядок за рядком, і на рівні коду нам потрібно внести відповідні зміни, щоб отримувати результати по рядках.

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Можна побачити, що у відповіді є багато `data`, а `delta` у `data` є найновішим вмістом відповіді, що узгоджується з описаним вище. `delta` — це доданий вміст відповіді, ви можете інтегрувати його у свою систему відповідно до результату. Потокова відповідь має `response.completed` або `response.incomplete` як кінцевий стан; `usage` у кінцевому стані є остаточним використанням token для цього запиту, а також основою для виставлення рахунку.

Якщо клієнт розриває з’єднання до досягнення кінцевого стану, цей запит буде записано як закритий клієнтом (499), і плата не стягуватиметься на основі локально оцінених token; якщо з’єднання нормально завершується, але кінцевий стан і остаточний `usage` не отримано, цей запит буде записано як неповна відповідь (502), і плата також не стягуватиметься на основі оцінених token. У разі виникнення цих двох ситуацій, будь ласка, повторно надішліть запит.

Повернений результат `data` містить кілька полів, описаних нижче:

- `item_id` — ID згенерованого завдання цього діалогу, що використовується для унікальної ідентифікації цього завдання діалогу.
- `type` — тип згенерованого завдання Responses цього діалогу.
- `model ` — вибрана модель OpenAI ChatGPT з офіційного сайту.
- `delta` — інформація відповіді, надана ChatGPT на запитання.

JavaScript також підтримується, наприклад, код потокового виклику для Node.js наведено нижче:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Багатораундовий діалог

Якщо ви хочете інтегрувати функціональність багатораундового діалогу, потрібно передати кілька запитань у поле `input`; конкретний приклад кількох запитань показано на зображенні нижче:

<p><img src="https://cdn.acedata.cloud/1jqwnf.png" width="400" className="m-auto" /></p>

Приклад коду виклику Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"},{"role":"assistant","content":"Hello! How can I help you today? 😊"},{"role":"user","content":"What did I just say?"}]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Візуальна модель

gpt-4o — це мультимодальна велика мовна модель, розроблена OpenAI, яка отримала можливості візуального розуміння на основі GPT-4. Ця модель може одночасно обробляти текстові та графічні вхідні дані, реалізуючи міжмодальне розуміння та генерування.
Використання текстової обробки моделі gpt-4o відповідає базовому способу використання, описаному вище, нижче буде коротко представлено, як використовувати можливості моделі з обробки зображень.

Використання можливостей обробки зображень моделі gpt-4o головним чином здійснюється шляхом додавання поля `type` на основі початкового вмісту `content`, за допомогою цього поля можна дізнатися, чи завантажується текст або зображення, і таким чином використовувати можливості обробки зображень моделі gpt-4o. Нижче головним чином описано виклик цієї функції двома способами: за допомогою Curl і Python.

- Спосіб зі скриптом Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Спосіб зі скриптом Python

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Неправильний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Забагато запитів, ви перевищили ліміт частоти запитів.
- `500 api_error`：Внутрішня помилка сервера, на сервері щось пішло не так.
