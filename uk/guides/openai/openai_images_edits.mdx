## 3. Завантаження локального зображення

Використовуйте `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` можна передавати повторно, серія GPT Image підтримує до 16 еталонних зображень. `image` у JSON-запиті може бути одним URL або масивом URL; локальні файли завантажуються через multipart.

### Моделі та способи тарифікації

| Модель                                | Застосовні сценарії та спосіб тарифікації                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | Канал зворотної інженерії за замовчуванням, фіксована тарифікація за кількістю успішних зображень                               |
| `gpt-image-2:reverse`             | Явний вибір каналу зворотної інженерії, фіксована тарифікація за кількістю успішних зображень                             |
| `gpt-image-2:official`            | Канал офіційного API, вища стабільність, тарифікація за фактичним використанням Token                   |
| `gpt-image-2.5-flare`             | Акцент на швидкості генерації, фіксована тарифікація за кількістю успішних зображень                               |
| `gpt-image-2.6-flare`             | Акцент на швидкості генерації, фіксована тарифікація за кількістю успішних зображень                               |
| `gpt-image-2.5-flare:reverse`     | Явний псевдонім зворотної інженерії, еквівалентний `gpt-image-2.5-flare`, фіксована тарифікація за кількістю успішних зображень    |
| `gpt-image-2.6-flare:reverse`     | Явний псевдонім зворотної інженерії, еквівалентний `gpt-image-2.6-flare`, фіксована тарифікація за кількістю успішних зображень    |
| `gpt-image-2.5-flare:official`    | Канал офіційного API, вища стабільність і акцент на швидкості генерації, тарифікація за фактичним використанням Token            |
| `gpt-image-2.6-flare:official`    | Канал офіційного API, вища стабільність і акцент на швидкості генерації, тарифікація за фактичним використанням Token            |

| `gpt-image-2.6-sunburst`          | Акцент на високій точності та детальному контролі, фіксована тарифікація за кількістю успішних зображень                           |
| `gpt-image-2.5-sunburst:reverse`  | Явний псевдонім зворотної інженерії, еквівалентний `gpt-image-2.5-sunburst`, фіксована тарифікація за кількістю успішних зображень |
| `gpt-image-2.6-sunburst:reverse`  | Явний псевдонім зворотної інженерії, еквівалентний `gpt-image-2.6-sunburst`, фіксована тарифікація за кількістю успішних зображень |
| `gpt-image-2.5-sunburst:official` | Канал офіційного API, вища стабільність і акцент на високій точності та детальному контролі, тарифікація за фактичним використанням Token        |
| `gpt-image-2.6-sunburst:official` | Канал офіційного API, вища стабільність і акцент на високій точності та детальному контролі, тарифікація за фактичним використанням Token        |

Моделі зворотної інженерії 2.0 / 2.5 (включно з псевдонімами `:reverse`) можуть використовувати GPT Image 2.5 Flare для виконання запиту під час автоматичного відновлення; модель запиту та спосіб фіксованої тарифікації за кількістю успішних зображень залишаються незмінними.

Ціна на сторінці каналу офіційного API є оцінкою до запиту; остаточна сума визначається фактичним використанням Token у відповіді та записами про використання.

`quality` підтримує `auto`, `low`, `medium`, `high`; Flare і Sunburst 2.5 / 2.6 (включно з варіантами `:reverse` і `:official`) додатково підтримують `xhigh`, `max`. Це поле можна передавати як у JSON-редагуванні зображень за URL, так і в multipart-редагуванні файлів; офіційний канал тарифікується за фактичним використанням Token.

## 4. Локальне редагування за допомогою маски

Офіційний інтерфейс Images Edit визначає область, яку дозволено змінювати, через `mask`. Моделі Ace Data Cloud `:official` дотримуються такого самого multipart-контракту:

- `mask` має бути PNG з Alpha-каналом, розміром не більше 4MB;
- розмір маски має повністю збігатися з першою `image`;
- прозорі пікселі з Alpha, що дорівнює `0`, означають, що редагування дозволено, а непрозорі пікселі означають, що їх слід зберегти;
- RGB-зображення, які мають лише чорно-білий колір, але не мають прозорого каналу, не можуть використовуватися як дійсна маска;
- підказка повинна описувати очікуване повне зображення, водночас чітко вказуючи локальні зміни та вміст, який має залишитися незмінним.

Нижче спочатку з оригінального зображення генерується маска. У прикладі центральний прямокутник зроблено прозорим, що дозволяє моделі змінювати лише цю область:
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Потім завантажте разом оригінальне зображення та маску:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Також можна використати спосіб виклику `images.edit` з офіційного Python SDK OpenAI, лише вказавши для `base_url` Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Під час використання `mask` оригінальне зображення та маску потрібно завантажити в одному multipart-запиті через `image=@input.png` і `mask=@mask.png` відповідно. Не передавайте разом URL оригінального зображення та локальний файл маски; запити редагування лише з URL не підтримують додавання локального файлу `mask`. Маска обмежує область редагування, але модель генерації все одно може природно поєднувати краї; якщо потрібні суворі межі, слід використовувати чіткі Alpha-краї та повторно вказати в підказці, який вміст має залишатися незмінним.

Наведений вище спосіб виклику відповідає прикладам масок в [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) та [офіційному Cookbook GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Поширені параметри

| Поле                | Опис                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (швидше) або `gpt-image-2.5-sunburst` (вища точність і контроль); для всіх трьох доступні відповідні варіанти `:official`, а `gpt-image-2` також підтримує `:reverse` |
| `image`           | JSON використовує один URL або масив до 16 URL; multipart використовує одне чи кілька полів файлу `image`. Під час використання `mask` необхідно завантажити локальний файл зображення                                              |
| `mask`            | Необов’язкова PNG-маска, лише для multipart-завантаження файлів; повинна мати Alpha-канал, той самий розмір, що й перше `image`, і не перевищувати 4 МБ                                                                 |
| `prompt`          | Інструкція для редагування                                                                                                                             |
| `size`            | `auto` або `WIDTHxHEIGHT`, що відповідає обмеженням                                                                                                     |
| `n`               | 1–10; за `response_format=b64_json` підтримується лише 1                                                                                           |
| `response_format` | `url` або `b64_json`                                                                                                               |
| `callback_url`    | Необов’язкова адреса асинхронного зворотного виклику                                                                                                                         |

Правила розмірів такі самі, як для інтерфейсу генерації: ширина й висота мають бути кратними 16, довша сторона не повинна перевищувати 3840, загальна кількість пікселів має становити 655 360–8 294 400, а співвідношення сторін не повинно перевищувати 3:1. Якщо не вказати `size` або використати `auto`, модель вибере формат кадру на основі підказки та першого еталонного зображення.

За `gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` і їхні псевдоніми `:reverse` стягується плата за кількістю успішно створених зображень; для `gpt-image-2:official`, `gpt-image-2.5-flare:official` і `gpt-image-2.5-sunburst:official` оплата розраховується за фактичними Token текстового вводу, вводу еталонних зображень і виводу зображень, остаточним є запис про використання.

## 6. Асинхронні зворотні виклики та усунення помилок

До довгих завдань у запиті можна додати:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Асинхронна відповідь 200 має вигляд `{"task_id": "..."}`; після завершення зворотний виклик повертає остаточний результат. Синхронні запити натомість повертають `created` і `data`.

| Статус  | Перевірка                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Формат/кількість зображень, комбінація параметрів і формат розмірів; під час використання `mask` перевірте Alpha-канал PNG, обмеження 4 МБ і відповідність її розміру першому оригінальному зображенню |
| 401 | API Key і Bearer Header                                           |
| 429 | Частота запитів                                                              |
| 504 | Перейдіть на асинхронний зворотний виклик                                                            |

Відповідь про помилку містить `trace_id`. Під час повідомлення про проблему надайте цей ID, не надавайте API Key.

Повний перелік полів і актуальні значення дивіться на сторінці [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Для генерації зображень із простого тексту дивіться [генерацію зображень GPT Image 2 / 2.5 / 2.6](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 використовує ті самі інтерфейси генерації, редагування, асинхронних завдань і тарифікації, що й 2.5:

| Модель                                                          | Тарифікація                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0.22 Credits/зображення                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0.22 Credits/зображення                   |
| `gpt-image-2.6-flare:official`                              | Така сама, як для 2.5 official, оплата за фактичне використання Token |
| `gpt-image-2.6-sunburst:official`                           | Така сама, як для 2.5 official, оплата за фактичне використання Token |

Для якості доступні `auto`, `low`, `medium`, `high`, `xhigh`, `max`; для розміру використовуйте `auto` або `WIDTHxHEIGHT`, що відповідає зазначеним вище обмеженням. Цей інтерфейс підтримує `png`, `jpeg`, `webp`, але наразі не підтримує SVG/GIF. Редагування підтримує URL зображень JSON і multipart-завантаження файлів. `:reverse` є явним псевдонімом звичайної версії з тією самою назвою. Використовуйте повну назву моделі, не передавайте `gpt-image-2.6`.
