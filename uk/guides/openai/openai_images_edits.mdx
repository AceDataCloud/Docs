Відкрийте [список застосунків Ace Data Cloud](https://platform.acedata.cloud/console/applications), увійдіть в доступний застосунок і скопіюйте API Key.

curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \

## 3. Завантаження локального зображення

Використовуйте `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` можна передавати повторно, серія GPT Image підтримує до 16 еталонних зображень. `image` у JSON-запиті може бути одним URL або масивом URL; локальні файли завантажуються через multipart.

## 4. Локальне редагування з використанням маски

Офіційний інтерфейс Images Edit використовує `mask` для вказання ділянки, яку дозволено змінювати. Моделі Ace Data Cloud `:official` дотримуються такого самого multipart-контракту:

- `mask` має бути PNG із альфа-каналом, розміром не більше 4MB;
- розмір маски має повністю збігатися з першою `image`;
- прозорі пікселі з Alpha, що дорівнює `0`, означають, що редагування дозволено, непрозорі пікселі означають, що їх слід зберегти;
- RGB-зображення лише з чорно-білими кольорами, але без каналу прозорості, не можуть використовуватися як дійсні маски;
- підказка має описувати бажане повне зображення, водночас чітко вказуючи локальні зміни та вміст, який потрібно залишити незмінним.

Нижче спочатку створюється маска з оригінального зображення. Приклад робить центральний прямокутник прозорим, дозволяючи моделі змінювати лише цю ділянку:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Потім завантажте оригінальне зображення й маску разом:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Також можна використовувати спосіб виклику `images.edit` з офіційного Python SDK OpenAI, лише вказавши Ace Data Cloud як `base_url`:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Під час використання `mask` оригінальне зображення й маску потрібно завантажувати в одному multipart-запиті окремо через `image=@input.png` та `mask=@mask.png`. Не передавайте разом URL оригінального зображення та локальний файл маски; запити редагування лише з URL не підтримують додавання локального файлу `mask`. Маска обмежує область редагування, але модель генерації все одно може природно змішувати краї; якщо потрібні суворі межі, слід використовувати чіткі альфа-краї та повторно вказати в підказці, який вміст має залишитися незмінним.

Наведений вище спосіб виклику відповідає прикладам масок у [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) і [офіційному Cookbook GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Поширені параметри

| Поле                | Опис                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (швидше) або `gpt-image-2.5-sunburst` (вища точність і контроль); для всіх трьох можна вибрати відповідний варіант `:official`, а `gpt-image-2` також підтримує `:reverse` |
| `image`           | JSON використовує один URL або масив до 16 URL; multipart використовує одне або кілька полів файлу `image`. Під час використання `mask` необхідно завантажити локальний файл зображення                                              |
| `mask`            | Необов’язкова PNG-маска, лише для завантаження multipart-файлом; має містити альфа-канал, мати такий самий розмір, як перша `image`, і не перевищувати 4MB                                                                 |
| `prompt`          | Інструкція з редагування                                                                                                                             |
| `size`            | `auto` або `WIDTHxHEIGHT`, що відповідає обмеженням                                                                                                     |
| `n`               | 1–10; при `response_format=b64_json` підтримується лише 1                                                                                           |
| `response_format` | `url` або `b64_json`                                                                                                               |
| `callback_url`    | Необов’язкова адреса асинхронного зворотного виклику                                                         |
Правила розмірів узгоджуються з інтерфейсом генерації: ширина й висота мають бути кратними 16, довша сторона не повинна перевищувати 3840, загальна кількість пікселів становить 655 360–8 294 400, співвідношення сторін не перевищує 3:1. Якщо `size` пропущено або використовується `auto`, модель вибере формат кадру на основі підказки та першого референсного зображення.

За `gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` і `gpt-image-2:reverse` плата стягується за кількістю успішних зображень; `gpt-image-2:official`, `gpt-image-2.5-flare:official` і `gpt-image-2.5-sunburst:official` розраховуються за фактичними Token текстового вводу, вводу референсних зображень і виводу зображень, остаточні дані визначаються записами про використання.

## 6. Асинхронний зворотний виклик і налагодження

Для тривалих завдань до запиту можна додати:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Асинхронна відповідь 200 має вигляд `{"task_id": "..."}`; після завершення зворотний виклик повертає фінальний результат. Синхронні запити натомість повертають `created` і `data`.

| Статус  | Перевірка                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Формат/кількість зображень, комбінації параметрів і формат розмірів; у разі використання `mask` перевірте канал PNG Alpha, обмеження 4MB і відповідність його розмірів першому оригінальному зображенню |
| 401 | API Key і Bearer Header                                           |
| 429 | Частота запитів                                                              |
| 504 | Перейдіть на асинхронний зворотний виклик                                                            |

Відповідь про помилку міститиме `trace_id`. Під час повідомлення про проблему надайте цей ID, не надавайте API Key.

Повний перелік полів і актуальні переліки значень наведено на сторінці [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Для генерації зображень із простого тексту перегляньте [Генерація зображень GPT Image 2 / 2.5](https://platform.acedata.cloud/documents/openai-images-generations).
