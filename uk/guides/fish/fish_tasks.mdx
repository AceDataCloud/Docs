Основною функцією Fish Tasks API є запит стану виконання завдання шляхом введення ID завдання, згенерованого Fish Audios Generation API.

У цьому документі буде детально представлено інструкції з інтеграції Fish Tasks API, щоб допомогти вам легко інтегрувати та повністю використовувати потужні можливості цього API. За допомогою Fish Tasks API ви можете легко реалізувати запит стану виконання завдань Fish Audios Generation API.

## Процес подання заявки

Щоб використовувати Fish Audios Generation API, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати свій API Token і зберегти його для подальшого використання.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли в систему або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу, де вам буде запропоновано зареєструватися та увійти, після завершення ви автоматично повернетеся на поточну сторінку.

**Один API Token може викликати всі сервіси платформи, не потрібно подавати заявку окремо для кожного сервісу.** Під час першого подання заявки буде надано безкоштовну квоту для безкоштовного ознайомлення; коли квоти недостатньо, можна поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Fish Audios Generation API →](https://platform.acedata.cloud/documents/fish-tts)

## Приклад запиту

Fish Tasks API можна використовувати для запиту результатів Fish Audios Generation API. Щодо того, як використовувати Fish Audios Generation API, зверніться до документації [Fish Videos Generation API ](https://platform.acedata.cloud/documents/fish-tts-integration)。

Візьмемо як приклад один ID завдання, повернений сервісом Fish Audios Generation API, щоб продемонструвати, як використовувати цей API. Припустімо, ми маємо ID завдання: 2725a2d3-f87e-4905-9c53-9988d5a7b2f5, далі продемонструємо, як шляхом передавання одного ID завдання.

### Налаштування заголовків запиту та тіла запиту

**Request Headers** включає:

- `accept`: вказує на отримання результату відповіді у форматі JSON, тут заповнюється як `application/json`.
- `authorization`: ключ для виклику API, після подання заявки його можна безпосередньо вибрати у випадаючому списку.

**Request Body** включає:

- `id`: ID завантаженого завдання.
- `action`: спосіб операції із завданням.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/fish/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2725a2d3-f87e-4905-9c53-9988d5a7b2f5",
  "action": "retrieve"
}'
```

```json
    ]
  }

```

Результат, що повертається, загалом має кілька полів, поле request — це request body під час запуску завдання, водночас поле response — це response body, повернене після завершення завдання. Опис полів наведено нижче.

- `id` — ID, що генерує це завдання, використовується для унікальної ідентифікації цього завдання генерації.
- `request` — інформація про запит у завданні запиту.
- `response` — інформація про відповідь у завданні запиту; після остаточного успіху `cost.amount` у ньому є Credits, фактично списаними за цей синтез.
- `created_at` — час створення завдання, Unix timestamp (секунди, число з рухомою комою).
- `started_at` — час початку виконання завдання, Unix timestamp (секунди, число з рухомою комою).
- `finished_at` — час завершення завдання, Unix timestamp (секунди, число з рухомою комою). Це поле не повертається, якщо завдання не завершено.
- `elapsed` — тривалість виконання завдання, в одиницях секунд (число з рухомою комою, з точністю до 3 знаків після коми). Це поле не повертається, якщо завдання не завершено.

## Операція пакетного запиту

Це призначено для запиту деталей завдань за кількома ID завдань, відмінність від вищезазначеного полягає в тому, що action потрібно вибрати як retrieve_batch

**Request Body** включає:

- `ids`: масив ID завантажених завдань.
- `action`: спосіб операції із завданням.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API поверне відповідний код та повідомлення про помилку. Наприклад:

- `400 token_mismatched`：Некоректний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Некоректний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Забагато запитів, ви перевищили ліміт частоти запитів.
- `500 api_error`：Внутрішня помилка сервера, щось пішло не так на сервері.
