У цій статті буде представлено інструкцію з інтеграції SeeDream Images Generation API, який може генерувати офіційні зображення SeeDream шляхом введення користувацьких параметрів.

## Процес подання заявки

**Один API Token дозволяє викликати всі сервіси платформи, не потрібно подавати окрему заявку для кожного сервісу.** Під час першого подання заявки надається безкоштовний ліміт для безкоштовного ознайомлення; якщо ліміту недостатньо, ви можете поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

## Базове використання

Спочатку ознайомимося з базовим способом використання: введіть промпт `prompt`、 дію генерації `action`、розмір зображення `size`, і ви зможете отримати оброблений результат. Спочатку потрібно просто передати поле `action` зі значенням `generate`, а потім також потрібно ввести промпт. Конкретний вміст наведено нижче:

<p><img src="https://cdn.acedata.cloud/seedream_request_body.png" width="500" className="m-auto" /></p>

Тут видно, що ми налаштували Request Headers, зокрема:

- `accept`: у якому форматі бажано отримати результат відповіді; тут вказано `application/json`, тобто формат JSON.
- `authorization`: ключ для виклику API, після подання заявки його можна безпосередньо вибрати зі спадного списку.

Також налаштовано Request Body, зокрема:

- `prompt`: промпт.
- `model`: модель генерації, за замовчуванням `doubao-seedream-5-0-lite-260128` (SeeDream 5.0 Lite, найновіша). Підтримуються `doubao-seedream-5-0-pro-260628`, `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828`. Серед них `doubao-seedream-5-0-pro-260628` (SeeDream 5.0 Pro) є флагманською моделлю для одного зображення, генерує лише одне зображення та **не підтримує групи зображень (`sequential_image_generation`), потоковий режим (`stream`) і вебпошук (`tools`)**. **У `model` потрібно передавати повний рядок моделі (наприклад, `doubao-seedream-5-0-lite-260128`); передавання скорочення на кшталт `doubao-seedream-5.0-lite` поверне 400.**
- `image`: інформація про вхідне зображення, підтримуються URL або кодування Base64. `doubao-seedream-5-0-pro-260628` підтримує введення одного або кількох зображень (максимум 10), `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` підтримують введення одного або кількох зображень.
- `size`: указує інформацію про розмір згенерованого зображення; підтримуються два наведені нижче способи, їх не можна змішувати. Спосіб 1 | Указати роздільну здатність згенерованого зображення та описати співвідношення сторін зображення природною мовою в prompt. **Підтримувані пресети відрізняються залежно від моделі**: `doubao-seedream-5-0-pro-260628` підтримує `1K`/`1.5K`/`2K`; `doubao-seedream-5-0-lite-260128` підтримує `2K`/`3K`/`4K`; `doubao-seedream-4-5-251128` підтримує лише `2K`/`4K`; `doubao-seedream-4-0-250828` підтримує `1K`/`2K`/`4K`. Спосіб 2 | Указати значення ширини та висоти згенерованого зображення в пікселях: за замовчуванням `2048x2048`, діапазон загальної кількості пікселів і співвідношення сторін відрізняється залежно від моделі (наприклад, для 5.0 Pro діапазон загальної кількості пікселів становить [921600, 4624220], нижня межа загальної кількості пікселів для 5.0 Lite / 4.5 — 3,686,400, а для 4.0 — 921,600).
- `sequential_image_generation`: група зображень: група пов’язаних за змістом зображень, що генеруються на основі введеного вами вмісту. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` підтримують цей параметр, за замовчуванням `disabled`.
- `stream`: керує тим, чи вмикати режим потокового виведення. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` підтримують цей параметр, за замовчуванням `false`.
- `response_format`: указує формат повернення згенерованого зображення. За замовчуванням `url`, також підтримується `b64_json`.
- `watermark`: чи додавати водяний знак до згенерованого зображення. За замовчуванням `true`.
- `output_format`: указує формат файлу згенерованого зображення; підтримуються `jpeg` (за замовчуванням) і `png`. Підтримується лише `doubao-seedream-5-0-pro-260628` та `doubao-seedream-5-0-lite-260128`.
- `tools`: налаштовує інструменти, які має викликати модель; наразі підтримується `web_search` (вебпошук). Підтримується лише Seedream 5.0 Lite.
- `optimize_prompt_options`: конфігурація оптимізації промпту. 5.0 Pro підтримує `standard`/`fast`; 5.0 Lite і 4.5 підтримують лише `standard`; 4.0 підтримує `standard`/`fast`.
- `background`: підтримується лише для редагування одного зображення в 5.0 Pro. `transparent` вимагає введення PNG із прозорим каналом, а `output_format` має бути `png`; `opaque` — звичайний непрозорий фон.
- `layer_decomposition`: підтримується лише 5.0 Pro. Якщо встановити `true`, потрібно ввести PNG/JPEG; можна не передавати `prompt` для автоматичного розділення або вказати елементи природною мовою/`<bbox>`; `size` підтримує `auto`/`1K`/`1.5K`/`2K`. Цей режим не можна використовувати разом із групами зображень, потоковим режимом, вебпошуком або `background`.
- `callback_url`: URL, на який потрібно надіслати результат зворотного виклику.
- `async`: чи обробляти в асинхронному режимі. Якщо встановити `true`, інтерфейс негайно поверне `task_id`, не потрібно надавати `callback_url`, після чого результат можна отримати шляхом опитування через `/seedream/tasks`.

Після вибору можна побачити, що праворуч також згенеровано відповідний код, як показано на зображенні:

<p><img src="https://cdn.acedata.cloud/seedream_image.png" width="500" className="m-auto" /></p>

Натисніть кнопку «Try», щоб провести тестування. Як показано на зображенні вище, тут ми отримали такий результат:
```json
{
  "success": true,
  "task_id": "80ceeed1-17d4-4eb7-82e0-18b34290f36e",
  "trace_id": "96b7fdc8-0fc8-4e2e-82a9-83c0a82f0a08",
  "data": [
    {
      "prompt": "A single matte blue cube centered on a clean white studio background, neutral lighting",
      "size": "2048x2048",

    }
  ]

```

Результат повертає загалом кілька полів, опис яких наведено нижче:

- `success` — поточний статус завдання генерації відео.
- `task_id` — ID поточного завдання генерації відео.
- `trace_id` — ID відстеження поточної генерації відео.
- `data` — список результатів поточного завдання генерації зображень.
  - `image_url` — посилання поточного завдання генерації зображення.
  - `prompt` — промпт.
  - `size`: пікселі згенерованого зображення

Можна побачити, що ми отримали задовільну інформацію про зображення, нам потрібно лише отримати згенероване зображення SeeDream за адресою посилання на зображення в `data` результату.

Крім того, якщо ви хочете згенерувати відповідний код інтеграції, його можна безпосередньо скопіювати та згенерувати, наприклад, код CURL наведено нижче:

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "doubao-seedream-5-0-lite-260128",
  "prompt": "A single matte blue cube centered on a clean white studio background, neutral lighting"
}'
```

## Завдання редагування зображень

Якщо ви хочете відредагувати певне зображення, спочатку до параметра `image` потрібно передати посилання на зображення, яке необхідно відредагувати

- model: модель, що використовується для цього завдання редагування зображення, `doubao-seedream-5-0-pro-260628`, `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` усі підтримують введення зображень.
- image: завантажте зображення, яке потрібно відредагувати, одне або кілька

Приклад заповнення наведено нижче:

<p><img src="https://cdn.acedata.cloud/seedream_edit.png" width="500" className="m-auto" /></p>

Відповідний код:

```python
import requests

url = "https://api.acedata.cloud/seedream/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedream-4-0-250828",
  "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
  "image": ["https://ark-project.tos-cn-beijing.volces.com/doc_image/seedream4_5_imageToimage.png"],
  "size": "2K",
  "watermark": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Натиснувши запуск, можна побачити, що результат буде отримано негайно, як показано нижче:

```json

  "trace_id": "131a40c3-2eaf-44c9-af28-c9b408577286",
  "data": [
    {
      "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
      "size": "2048x2048",
      "image_url": "https://platform.cdn.acedata.cloud/seedream/3e88db7e-4771-4f6a-adbd-5ae4590c5d59.jpg"
```

Можна побачити, що згенерований ефект є ефектом редагування оригінального зображення, а результат аналогічний описаному вище.

## Розділення шарів (Seedream 5.0 Pro)

Розділення шарів розділяє одне вхідне зображення на 1 фонове зображення та до 16 незалежно редагованих прозорих шарів PNG. Наведений нижче запит дозволяє моделі автоматично розпізнавати основні елементи; якщо потрібно вказати елементи, можна додати `prompt`, а також можна використовувати нормалізовані координати `<bbox>` у промпті.

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "https://example.com/poster.png",
  "layer_decomposition": true,
  "size": "2K",
  "watermark": false
}'
```

Повернений `data` упорядкований за `z_index` від нижнього до верхнього. `z_index` фонового зображення дорівнює 0; шари також містять `name`, `description` і `bounding_box.absolute`/`normalized`. Під час повторного компонування з використанням абсолютних координат масштабуйте шари до `[right-left, bottom-top]`, розмістіть їх у `[left, top]`, а потім накладайте у порядку зростання `z_index`. Якщо генерація будь-якого шару не вдається, усе розділення завершується невдачею.

## Потокове виведення

Коли для Lite/4.x встановлено `stream: true`, у заголовку запиту використовуйте `accept: application/x-ndjson`. Інтерфейс повертає рядок за рядком `image_generation.partial_succeeded` або `image_generation.partial_failed`, а наприкінці повертає унікальну подію `image_generation.completed` і остаточний `usage`; лише подія завершення запускає одноразове списання коштів. Потоковий режим не можна використовувати разом з `async` або `callback_url`.

## Асинхронний зворотний виклик

Оскільки API генерації зображень SeeDream Images Generation API має відносно тривалий час генерації, приблизно 1–2 хвилини, якщо API довго не відповідає, HTTP-запит постійно підтримуватиме з’єднання, що призводить до додаткового споживання системних ресурсів, тому цей API також підтримує асинхронні зворотні виклики.

Загальний процес такий: коли клієнт ініціює запит, він додатково вказує поле `callback_url`; після того як клієнт ініціює API-запит, API негайно повертає результат, що містить поле `task_id`, яке представляє ID поточного завдання. Після завершення завдання результат згенерованого зображення буде надіслано у вигляді POST JSON на `callback_url`, указаний клієнтом, який також включає поле `task_id`, таким чином результати завдання можна пов’язати за ID.

Якщо у вас немає загальнодоступної адреси для зворотного виклику, ви також можете не вказувати `callback_url`, а встановити в запиті поле `async` у значення `true`. У такому разі інтерфейс також негайно поверне `task_id`, але не надсилатиме результат, вам потрібно буде передати цей `task_id` для виклику інтерфейсу `/seedream/tasks`, щоб опитувати статус завдання й отримати остаточний результат.

Нижче ми дізнаємося з прикладу, як саме це зробити.

Натиснувши запуск, можна побачити, що результат буде отримано негайно, як показано нижче:

```
{
  "task_id": "c9aaffa2-b8ac-40ff-8468-43e77cb9ddde"
}
```

Вміст наведено нижче:
```json
{
    "success": true,
    "task_id": "c9aaffa2-b8ac-40ff-8468-43e77cb9ddde",
    "trace_id": "131a40c3-2eaf-44c9-af28-c9b408577286",
    "data": [
        {
            "prompt": "Збережіть незмінними позу моделі та текучу форму рідкого одягу. Змініть матеріал одягу зі срібного металу на повністю прозору воду (або скло). Крізь рідкий потік видно деталі шкіри моделі. Ефект світла й тіні зміщується від відбиття до заломлення.",
            "size": "2048x2048",
            "image_url": "https://platform.cdn.acedata.cloud/seedream/3e88db7e-4771-4f6a-adbd-5ae4590c5d59.jpg"
```

Можна побачити, що в результаті є поле `task_id`, інші поля подібні до наведених вище, за допомогою цього поля можна реалізувати пов’язування завдань.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API повертає відповідний код помилки та інформацію. Наприклад:

- `400 token_mismatched`：Некоректний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`：Некоректний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`：Неавторизовано, недійсний або відсутній токен авторизації.
- `429 too_many_requests`：Занадто багато запитів, ви перевищили ліміт швидкості.
- `500 api_error`：Внутрішня помилка сервера, щось пішло не так на сервері.

### Приклад відповіді з помилкою

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
