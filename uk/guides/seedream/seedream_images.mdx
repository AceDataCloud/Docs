У цій статті буде представлено інструкцію з інтеграції API генерації зображень SeeDream, за допомогою якого можна створювати офіційні зображення SeeDream, вводячи власні параметри.

## Процес отримання доступу

Щоб використовувати API генерації зображень SeeDream, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications), щоб отримати свій API Token і зберегти його для подальшого використання.

![]()

Якщо ви ще не ввійшли в систему або не зареєструвалися, вас буде автоматично перенаправлено на сторінку входу із пропозицією зареєструватися та увійти. Після завершення процесу ви автоматично повернетеся на поточну сторінку.

**Одного API Token достатньо для виклику всіх сервісів платформи, немає потреби окремо отримувати ключ для кожного сервісу.** Під час першого отримання доступу надається безкоштовний ліміт для ознайомлення; коли ліміту буде недостатньо, ви можете поповнити загальний баланс у [консолі](https://platform.acedata.cloud/console/coin).

## Вибір моделі

| Модель | Сценарії використання |
| ----------------------------------------------------------- | ------------------------------- |
| `doubao-seedream-5-5-261028` | Багатоетапне редагування, генерація зображень із прозорим фоном за текстовим описом, редагування прозорих зображень із кількома референсами, розділення шарів і розпізнавання текстових шарів |
| `doubao-seedream-5-0-flash-260915` | Генерація одного зображення з низькою затримкою, редагування з кількома референсами, редагування прозорих зображень і розділення шарів |
| `doubao-seedream-5-0-pro-260628` | Генерація одного зображення, детальне редагування, редагування прозорих зображень і розділення шарів |
| `doubao-seedream-5-0-lite-260128` | Одне зображення, група зображень, потокове виведення та пошук в Інтернеті |
| `doubao-seedream-4-5-251128` / `doubao-seedream-4-0-250828` | Генерація та редагування зображень попередніх версій |

5.5 і 5.0 Flash використовують однаковий `POST /seedream/images`, обидві підтримують `1K`, `1.5K`, `2K` і до 10 референсних зображень. Завдання розділення шарів для обох моделей приймають лише одне зображення та повертають URL. Для 5.5 можна встановити `layer_decomposition_options: {"max_images": 12, "text_recognition": true}`. Можна отримати до 100 зображень (включно з базовим зображенням), а розпізнані текстові шари повертатимуться в `data[].text_recognition` у вигляді тексту та стилів із розбивкою на рядки. 5.0 Flash повертає максимум 1 базове зображення та 16 шарів.

5.5 підтримує безпосередню генерацію прозорих PNG за допомогою `background: "transparent"`. Для редагування прозорих зображень у 5.0 Flash потрібне одне референсне зображення з альфа-каналом. 5.5 стягує плату відповідно до піксельного рівня успішно згенерованого зображення та додатково 0.13 Credits за кожне вхідне референсне зображення. 5.0 Flash стягує 0.31 Credits за кожне успішно згенероване зображення, референсні зображення безкоштовні. Розділення шарів оплачується відповідно до фактичної кількості успішно згенерованих зображень, включно з базовим зображенням. Див. [актуальні ціни](https://platform.acedata.cloud/services/seedream?tab=pricing).

## Основне використання

Спочатку ознайомимося з базовим способом використання: достатньо ввести текстовий запит `prompt`, дію генерації `action` і розмір зображення `size`, щоб отримати оброблений результат. Спочатку потрібно просто передати поле `action` зі значенням `generate`, а потім ввести текстовий запит. Конкретний вміст наведено нижче:

<p><img src="https://cdn.acedata.cloud/seedream_request_body.png" width="500" className="m-auto" /></p>

Як бачите, тут ми налаштували Request Headers, зокрема:

- `accept`: формат відповіді, який ви хочете отримати. Тут вказано `application/json`, тобто формат JSON.
- `authorization`: ключ для виклику API, який після отримання можна безпосередньо вибрати зі спадного списку.

Крім того, налаштовано Request Body, зокрема:

- `prompt`: текстовий запит.
- `model`: передайте повний ідентифікатор моделі з наведеної вище таблиці.
- `image`: URL вхідного зображення, рядок Base64 або масив. 5.5, 5.0 Pro і 5.0 Flash підтримують до 10 референсних зображень.
- `size`: рівень роздільної здатності або `ширинаxвисота`. 5.5, 5.0 Pro і 5.0 Flash підтримують `1K`, `1.5K`, `2K`. 5.0 Lite підтримує `2K`, `3K`, `4K`.
- `sequential_image_generation`: група зображень: на основі введеного вами вмісту генерується група пов’язаних між собою зображень. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` підтримують цей параметр, значення за замовчуванням — `disabled`.
- `stream`: керує тим, чи вмикати режим потокового виведення. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` підтримують цей параметр, значення за замовчуванням — `false`.
- `response_format`: визначає формат повернення згенерованого зображення. За замовчуванням — `url`, також підтримується `b64_json`.
- `watermark`: визначає, чи додавати водяний знак до згенерованого зображення. За замовчуванням — `true`.
- `output_format`: формат виведення — `jpeg` або `png`. Для 5.5 за замовчуванням PNG, для 5.0 Pro/Flash/Lite — JPEG.
- `tools`: налаштування інструментів, які викликає модель. Наразі підтримується `web_search` (пошук в Інтернеті). Підтримується лише Seedream 5.0 Lite.
- `optimize_prompt_options`: налаштування оптимізації текстового запиту. 5.0 Pro підтримує `standard`/`fast`; 5.5, 5.0 Flash, 5.0 Lite та 4.5 підтримують лише `standard`; 4.0 підтримує `standard`/`fast`.
- `background`: підтримує `transparent` і `opaque`. 5.5 додатково підтримує `auto`. Для прозорого виведення використовується PNG.
- `layer_decomposition`: підтримується 5.5, 5.0 Pro і 5.0 Flash. Якщо встановлено значення `true`, необхідно передати одне зображення PNG/JPEG. Можна не передавати `prompt`, щоб автоматично розділити зображення на шари, або вказати елементи за допомогою природної мови чи `<bbox>`; параметр `size` підтримує `auto`/`1K`/`1.5K`/`2K`. Цей режим не можна використовувати одночасно з груповою генерацією зображень, потоковим виведенням, пошуком в Інтернеті або `background`.
- `callback_url`: URL-адреса для отримання результатів зворотного виклику.
- `async`: визначає, чи обробляти запит в асинхронному режимі. Якщо встановлено значення `true`, інтерфейс одразу повертає `task_id`, без необхідності надавати `callback_url`. Після цього результати можна отримати шляхом опитування через `/seedream/tasks`.

Крім того, якщо ви хочете згенерувати відповідний код для інтеграції, його можна просто скопіювати. Наприклад, код CURL наведено нижче:


## Завдання з редагування зображень

Якщо ви хочете відредагувати певне зображення, насамперед потрібно передати посилання на зображення, яке необхідно відредагувати, у параметрі `image`.

- model: передайте повний ID моделі, яка підтримує редагування зображень, із наведеної вище таблиці.
- image: завантажте зображення, яке потрібно відредагувати, одне або кілька.

Приклад заповнення наведено нижче:

<p><img src="https://cdn.acedata.cloud/seedream_edit.png" width="500" className="m-auto" /></p>

Відповідний код:

```python
import requests

url = "https://api.acedata.cloud/seedream/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedream-4-0-250828",
  "prompt": "Збережіть незмінними позу моделі та форму струменистого рідкого одягу. Змініть матеріал одягу зі сріблястого металу на повністю прозору воду (або скло). Крізь потік рідини мають бути видимі деталі шкіри моделі. Ефект світла й тіні має змінитися з відбиття на заломлення.",
  "image": ["https://ark-project.tos-cn-beijing.volces.com/doc_image/seedream4_5_imageToimage.png"],
  "size": "2K",
  "watermark": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Розділення на шари (Seedream 5.0 Pro)

Розділення на шари перетворює одне вхідне зображення на 1 базове зображення та до 16 прозорих PNG-шарів, які можна редагувати незалежно один від одного. У наведеному нижче запиті модель автоматично розпізнає основні елементи; якщо потрібно вказати конкретні елементи, можна додати `prompt`, а також використовувати нормалізовані координати `<bbox>` у текстовому запиті.

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "https://example.com/poster.png",
  "layer_decomposition": true,
  "size": "2K",
  "watermark": false
}'
```

Повернуті дані `data` впорядковані за `z_index` від нижнього шару до верхнього. Базове зображення має `z_index`, що дорівнює 0; шари також містять `name`, `description` і `bounding_box.absolute`/`normalized`. Для відновлення зображення за абсолютними координатами масштабуйте шар до розміру `[right-left, bottom-top]`, розмістіть його в позиції `[left, top]`, а потім накладайте шари в порядку зростання `z_index`. Якщо генерація будь-якого шару завершиться невдало, уся операція розділення завершиться помилкою.

## Потокове виведення

Якщо для Lite/4.x встановлено `stream: true`, у заголовку запиту потрібно використовувати `accept: application/x-ndjson`. Інтерфейс повертає події по одному рядку: `image_generation.partial_succeeded` або `image_generation.partial_failed`, а наприкінці повертає єдину подію `image_generation.completed` та остаточне значення `usage`; оплата стягується лише один раз після події завершення. Потоковий режим не можна використовувати одночасно з `async` або `callback_url`.

## Асинхронний зворотний виклик

Оскільки генерація через SeeDream Images Generation API займає відносно багато часу — приблизно 1–2 хвилини, — якщо API тривалий час не відповідає, HTTP-запит залишатиметься відкритим, що призведе до додаткового споживання системних ресурсів. Тому цей API також підтримує асинхронні зворотні виклики.

Загальний процес такий: під час надсилання запиту клієнт додатково вказує поле `callback_url`. Після того як клієнт надсилає API-запит, API негайно повертає результат, що містить поле `task_id`, яке позначає ID поточного завдання. Після завершення завдання результат генерації зображення надсилається на вказаний клієнтом `callback_url` у форматі POST JSON, який також містить поле `task_id`. Таким чином, результати завдань можна пов'язати за допомогою ID.

Якщо у вас немає загальнодоступної мережевої адреси для зворотного виклику, ви також можете не вказувати `callback_url`, а натомість встановити поле `async` у значення `true` у запиті. У цьому випадку інтерфейс також негайно поверне `task_id`, але результат не буде надіслано автоматично. Вам потрібно передати цей `task_id` в інтерфейс `/seedream/tasks`, щоб періодично перевіряти стан завдання й отримати остаточний результат.

Нижче розглянемо на прикладі, як саме це зробити.

Натиснувши кнопку запуску, можна побачити, що результат буде отримано миттєво, як показано нижче:


Як видно з результату, він містить поле `task_id`, тоді як усі інші поля аналогічні наведеним вище. За допомогою цього поля можна пов’язати завдання між собою.

## Обробка помилок

Під час виклику API, якщо виникає помилка, API повертає відповідний код і повідомлення про помилку. Наприклад:

- `400 token_mismatched`: Неправильний запит, можливо, через відсутні або недійсні параметри.
- `400 api_not_implemented`: Неправильний запит, можливо, через відсутні або недійсні параметри.
- `401 invalid_token`: Неавторизований доступ, недійсний або відсутній токен авторизації.
- `429 too_many_requests`: Забагато запитів, перевищено обмеження частоти запитів.
- `500 api_error`: Внутрішня помилка сервера, під час роботи сервера щось пішло не так.

### Приклад відповіді з помилкою

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
