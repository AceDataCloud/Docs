`POST https://api.acedata.cloud/webextrator/extract`

API інтелектуального вилучення WebExtrator перетворює URL на **типізований структурований результат** — статтю, товар,
рецепт, відео, обговорення, вакансію тощо, а також надає очищений Markdown і звичайний текст. Це потрібний інтерфейс, коли вам потрібні «чисті структуровані дані», а не вихідний HTML.

## Процес подачі заявки

Щоб використовувати сторінку послуг WebExtrator, спочатку перейдіть до [консолі Ace Data Cloud](https://platform.acedata.cloud/console/applications) для отримання вашого API токена, залиште його на випадок потреби.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Якщо ви ще не увійшли або не зареєструвалися, вас автоматично перенаправлять на сторінку входу, запрошуючи вас зареєструватися та увійти, після чого ви автоматично повернетеся на поточну сторінку.

**Один API токен дозволяє викликати всі послуги платформи, без необхідності окремо подавати заявку на кожну послугу.** Перша заявка надає безкоштовний ліміт, щоб ви могли безкоштовно спробувати; коли ліміт закінчиться, ви можете поповнити загальний баланс в [консолі](https://platform.acedata.cloud/console/coin).

> 📘 Повна документація: [Сторінка послуг WebExtrator →](https://platform.acedata.cloud/service/webextrator)

## Аутентифікація

```
Authorization: Bearer YOUR_API_KEY
Content-Type:  application/json
```

## Параметри запиту

Extract приймає **усі** параметри [Render API](/uk/guides/webextrator/webextrator_render)
（`url`、`user_agent`、`timeout`、`wait_until`、`delay`、`wait_for_selector`、
`block_resources`、`headers`、`cookies`、`callback_url`、`bypass_cache`、
`cache_ttl_seconds`、`async`），а також два поля, специфічні для Extract:

| Поле | Тип | Обов’язково | За замовчуванням | Опис |
|------|------|:----:|------|------|
| `expected_type` | enum | ❌ | Автоматичне визначення | Підказка щодо типу сторінки: `product` / `article` / `general`. Укажіть очікуваний тип результату. |
| `enable_llm` | boolean | ❌ | `false` | Дозволяє виклик LLM для вилучення даних, коли schema.org не знаходить збігів. На сторінках без JSON-LD, таких як Amazon / HN / Greenhouse, це потрібно ввімкнути, щоб отримати типізовані результати. |

### Поля верхнього рівня

| Поле | Тип | Опис |
|------|------|------|
| `kind` | string | Фіксоване значення `"extract"`. |
| `url` | string | URL-адреса, яку ви надіслали. |
| `finalUrl` | string | Кінцева URL-адреса після перенаправлення. |
| `contentType` | enum | Тип сторінки: `product` / `article` / `general`. |
| `title` | string | Заголовок сторінки. |
| `description` | string? | Опис або резюме сторінки. |
| `byline` | string? | Автор, канал або компанія. |
| `language` | string? | `<html lang>`.  |
| `siteName` | string? | `og:site_name`.  |
| `publishedAt` | string? | Час публікації у форматі ISO 8601. |
| `images` | string[] | До 50 `<img src />`, проаналізованих як абсолютні URL-адреси, без дублікатів і з відкиданням URI `data:`. |
| `links` | string[] | До 100 зовнішніх посилань із відфільтрованими фрагментами / `javascript:` / `mailto:` / `tel:`. |
| `markdown` | string | Markdown-вміст сторінки. |
| `text` | string | Звичайний текст сторінки. |
| `structured` | object | Повний структурований результат, див. нижче. |
| `rawSignals` | object | Діагностична інформація для налагодження. |
| `cached` | boolean? | У разі влучання в кеш — `true`. |
| `cacheStoredAt` | number? | Unix-мітка часу в мілісекундах, коли запис кешу було вперше створено. |

### Підполя `data.structured`

| Підполе | Коли з’являється | Опис |
|--------|---------|------|
| `schemaOrg` | Завжди | `{ primary, breadcrumbs, all }`. `primary` — типізована сутність із найвищим пріоритетом; якщо її не знайдено, використовується `null`. |
| `openGraph` | Завжди | `{ title, description, image, type }`, отримано з `<meta property="og:*" />`. |
| `jsonLd` | Завжди | Необроблений JSON-масив усіх блоків `<script type="application/ld+json">`. |
| `llm` | Коли LLM було запущено й виконано успішно | `{ kind, data, model, promptCharCount }`, типізований результат. |
| `llmError` | Коли LLM було запущено, але виконання завершилося помилкою | `{ kind, error, model }`, запит усе одно може повертати інші витягнуті поля. |
| `amazon` | Коли URL — `amazon.*` | Застарілий результат розширення Amazon; для нових інтеграцій використовуйте типізовані результати. |

## Типи результатів schema.org

`structured.schemaOrg.primary` підтримує такі типи результатів:

| Тип schema.org | kind | Поля виводу |
|----------------|----------|----------|
| `Product` | product | `name, sku, gtin, model, color, brand, url, images, offer.{price,currency,availability,condition,seller}, rating.{value,count}, reviews[], properties[]` |
| `Recipe` | recipe | `name, description, image, datePublished, author, cookTime, prepTime, totalTime, recipeYield, ingredients[], instructions[], nutrition, rating, keywords, recipeCategory, recipeCuisine` |
| `VideoObject` | video | `name, description, thumbnailUrl, uploadDate, duration, embedUrl, contentUrl, channel, interactionCount` |
| `JobPosting` | job | `title, description, datePosted, validThrough, hiringOrganization, jobLocation, baseSalary, employmentType` |
| `Event` (включно з `*Event`) | event | `name, description, startDate, endDate, location.{name,address}, organizer, offer.{url,price,currency}` |
| `Article` / `NewsArticle` / `BlogPosting` / `ScholarlyArticle` / `TechArticle` / `Report` / `*NewsArticle` | article | `subtype, headline, description, datePublished, dateModified, author, publisher, image[], url, sameAs[]` |
| `FAQPage` | faq | `questions[{question, answer}]` |
| `BreadcrumbList` | (прикріплено до sibling) | Завжди виводиться до `structured.schemaOrg.breadcrumbs[]` і не буде primary. |

## Типи результатів LLM

Коли `enable_llm: true` і на сторінці немає доступних структурованих даних schema.org, можуть повертатися результати вилучення таких типів:

| Kind | Обов’язкові поля | Необов’язкові поля |
|------|---------|---------|
| `article` | `headline` | `description, byline, publishedAt, language, topics[], sections[{heading,summary}]` |
| `product` | `name` | `description, brand, sku, price, currency, availability, rating.{value,count}, bullets[], specifications[{name,value}]` |
| `discussion` | `title` | `author, postedAt, points, commentCount, body, url` |
| `recipe` | `name` | `description, author, cookTime, prepTime, totalTime, recipeYield, ingredients[], instructions[], nutrition, rating, keywords[]` |
| `video` | `name` | `description, channel, uploadDate, duration, viewCount, likeCount, thumbnailUrl, transcript` |
| `job` | `title` | `description, company, location, remote, employmentType, datePosted, validThrough, salaryMin, salaryMax, salaryCurrency, salaryPeriod, responsibilities[], qualifications[]` |

## Кеш

Для однакових URL, параметрів запиту, `cookies` і `headers` можна повторно використовувати кешовані результати; `async`, `bypass_cache` і `cache_ttl_seconds` використовуються для керування способом виконання та поведінкою кешу.

| Поле | Ефект |
|------|------|
| `bypass_cache: true` | Пропустити читання; результат цього разу все одно буде записано в кеш, і наступний ідентичний запит зможе потрапити в кеш. |
| `cache_ttl_seconds: 0` | Ця відповідь **не кешується**. |
| `cache_ttl_seconds: N` | Налаштувати TTL для цього запису (за замовчуванням 3600 секунд). |

Відповіді, отримані з кешу, міститимуть `data.cached: true` і `data.cacheStoredAt: <unix-ms>`.

## Асинхронний режим та зворотний виклик

Встановіть `async: true`, щоб увійти в асинхронний режим (надання `callback_url` також автоматично активує). Платформа негайно повертає (HTTP 200):

```json
{
  "success": true,
  "task_id": "550e8400-...",
  "trace_id": "6ba7b810-...",
  "started_at": 1777717800.123
}
```

Коли завдання завершено, повний envelope `POST` на ваш `callback_url` (якщо налаштовано). Також можна
потім активно запитати через [`/webextrator/tasks`](/uk/guides/webextrator/webextrator_tasks).

  -H "Content-Type: application/json" \

### Python (requests)

```python
import os, requests

API_KEY = os.environ["ACEDATA_API_KEY"]

resp = requests.post(
    "https://api.acedata.cloud/webextrator/extract",
    headers={
        "Authorization": f"Bearer {API_KEY}",
        "Content-Type": "application/json",
    },
    json={
        "url": "https://en.wikipedia.org/wiki/Diffbot",
        "expected_type": "article",
    },
    timeout=120,
)
resp.raise_for_status()
data = resp.json()["data"]

primary = (data.get("structured") or {}).get("schemaOrg", {}).get("primary")
print("contentType:", data["contentType"])
print("title:      ", data["title"])
print("byline:     ", data.get("byline"))
print("publishedAt:", data.get("publishedAt"))
if primary and primary["kind"] == "article":
    print("headline:    ", primary["headline"])
    print("dateModified:", primary.get("dateModified"))
```

### Node.js (fetch)

```js
const apiKey = process.env.ACEDATA_API_KEY;

const res = await fetch('https://api.acedata.cloud/webextrator/extract', {

```

## Підказки та підводні камені

- **Передавайте `expected_type`, коли потрібно вказати тип сторінки.** Наприклад, для сторінки статті використовуйте `article`, а для сторінки товару — `product`.
- **`enable_llm: true` є безкоштовним для сторінок, що відповідають schema.org.** LLM викликається лише тоді, коли в schema.org
  немає primary, тому його безпечно залишати увімкненим за замовчуванням.
- **Під час налагодження спершу перевіряйте `rawSignals.hasJsonLd`.** Якщо це `true`, але `structured.schemaOrg.primary`
  має значення `null`, це означає, що `@type` сторінки наразі не підтримується; ви можете повідомити нам про це.
- **`structured.llmError` має інформаційний характер.** Запит усе одно може успішно повернути інші витягнуті поля. Перегляньте
  `llmError.error`, щоб визначити причину (тайм-аут, помилка аналізу JSON, помилка перевірки структури).
- **Для `links[]` не-статейних сторінок не виконується ранжування за релевантністю.** Виконується лише очищення за принципом «до 100 записів + фільтрація недійсних протоколів»
  у межах можливого.
- **За потрапляння в кеш також стягується плата.**
