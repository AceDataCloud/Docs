この記事では、MiniMax H3 タスククエリ API の接続と使用について説明します。このインターフェースは、[MiniMax H3 ビデオ生成 API](/documents/minimax-videos-integration) によって作成された非同期タスクを照会、バッチリスト、または削除するために使用されます。

## 申請プロセス

MiniMax H3 タスククエリ API を使用するには、まず [Ace Data Cloud コンソール](https://platform.acedata.cloud/console/applications) にアクセスして、API トークンを取得し、保管してください。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

まだログインしていない場合や登録していない場合は、自動的にログインページにリダイレクトされ、登録とログインを促されます。完了後、現在のページに自動的に戻ります。

**1つの API トークンでプラットフォームのすべてのサービスを呼び出すことができ、各サービスごとに個別に申請する必要はありません。** 初回申請時には無料枠が付与され、無料で体験できます。枠が不足した場合は、[コンソール](https://platform.acedata.cloud/console/coin) で共通残高をチャージできます。

> 📘 完全なドキュメント：[MiniMax H3 タスククエリ API →](https://platform.acedata.cloud/documents/minimax-tasks-integration)

タスクを照会する際は、そのタスクを作成したのと同じトークンを使用する必要があります。トークンは環境変数として保存することをお勧めします。ソースコードに書き込んだり、バージョン管理システムにコミットしたりしないでください：

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## インターフェース概要

- **Base URL**：`https://api.acedata.cloud`
- **エンドポイント**：`POST /minimax/tasks`
- **認証方式**：HTTP ヘッダーに `authorization: Bearer {token}` を含める
- **リクエストヘッダー**：
  - `accept: application/json`
  - `content-type: application/json`
- **単一タスクの照会**：`action=retrieve`、`id` を渡す
- **バッチタスクの照会**：`action=retrieve_batch`、タスク ID、時間範囲、ページング条件でフィルタリング可能
- **タスクの削除**：`action=delete`、`id` を渡す
- **課金説明**：タスクの照会は無料で、重複課金は発生しません

ビデオを作成した後は、`task_id` を保存する必要があります。約 10 秒ごとに照会することをお勧めします。タスクが最終状態に入るまで続けてください。

## リクエストパラメータ

| パラメータ            | タイプ      | 必須   | 適用アクション           | 説明                                                   |
| ------------------ | -------- | ---- | ------------------- | ---------------------------------------------------- |
| `action`           | string   | 否    | すべて                  | `retrieve`、`retrieve_batch` または `delete`；デフォルトは `retrieve` |
| `id`               | string   | 条件必須 | `retrieve`、`delete` | 単一タスク ID                                              |
| `ids`              | string[] | 否    | `retrieve_batch`    | 指定されたタスク ID のみを返す；省略時は他の条件でタスクをリスト                              |
| `limit`            | integer  | 否    | `retrieve_batch`    | 今回最大で返すタスクの数                                          |
| `offset`           | integer  | 否    | `retrieve_batch`    | 結果リストからスキップするタスクの数、ページング用                                   |
| `created_at_min`   | number   | 否    | `retrieve_batch`    | 作成時間の下限、Unix タイムスタンプ、単位は秒                                 |
| `created_at_max`   | number   | 否    | `retrieve_batch`    | 作成時間の上限、Unix タイムスタンプ、単位は秒                                 |

3つのアクションの用途は以下の通りです：

| `action`           | 用途                 | 必要なパラメータ                     | 応答構造                                  |
| ------------------ | ------------------ | ------------------------------ | ------------------------------------- |
| `retrieve`         | 単一タスクの状態と結果を照会       | `id`                           | `{ "task": {...} }`                   |
| `retrieve_batch`   | タスク ID、時間、ページング条件でバッチ照会 | オプションの `ids`、時間範囲、`offset`、`limit` | `{ "items": [...], "total": number }` |
| `delete`           | タスクの現在の状態に基づいてタスク記録をキャンセルまたは削除  | `id`                           | `{ "id": "...", "deleted": true }`    |

## 単一タスクの照会

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f5977217-ed2c-40da-adbe-93d08235618f"
  }'
```

## タスクの状態

| `status`    | 意味         | クライアント処理                      |
| ----------- | ---------- | -------------------------- |
| `queued`    | キューに入った、実行待ち | 継続的にポーリング                       |
| `running`   | 生成中       | 継続的にポーリング                       |
| `succeeded` | 生成成功       | `task.content.url` を読み取り、ポーリングを停止 |
| `failed`    | 生成失敗       | `task.error` を読み取り、ポーリングを停止       |
| `cancelled` | タスクがキャンセルされた      | ポーリングを停止                       |

`succeeded`、`failed`、および `cancelled` はすべて最終状態です。最終状態に入った後はポーリングを続けないでください。

## task 応答フィールド

| フィールド                    | タイプ      | 説明                              |
| ------------------------- | ------- | ------------------------------- |
| `id`                      | string  | タスク ID                           |
| `model`                   | string  | タスクで使用されるモデル、現在は `MiniMax-H3`        |
| `status`                  | string  | 現在のタスク状態                          |
| `error.code`              | string  | 失敗エラーコード、失敗時のみ返される                    |
| `error.message`           | string  | 失敗理由、失敗時のみ返される                     |
| `created_at`              | integer | 作成時間、Unix タイムスタンプ、単位は秒              |
| `updated_at`              | integer | 最後の状態更新時間、Unix タイムスタンプ、単位は秒        |
| `content.url`             | string  | 成功後のビデオアドレス                        |
| `resolution`              | string  | 出力解像度、`768P` または `2K`             |
| `duration`                | integer | 出力ビデオの長さ、単位は秒                     |
| `usage.total_seconds`     | integer | 総費用量、入力ビデオの秒数と出力秒数の合計           |
| `usage.input_seconds`     | integer | 参考ビデオ入力による費用量                   |
| `usage.output_seconds`    | integer | 出力ビデオによる費用量                     |
| `usage.input_image_count` | integer | 課金統計における入力画像の数                    |
| `ratio`                   | string  | 実際の出力アスペクト比；`adaptive` 使用時はここでの結果が基準 |
| `task_type`               | string  | ビデオ生成タスクは `generation`            |
| `modality`                | string  | ビデオタスクは `video`                   |

## Python ポーリング完全サンプル
以下コードは環境変数からTokenを読み取り、タスクを作成した後、10秒ごとにクエリを実行します：

```python
import os
import time

import requests

BASE_URL = "https://api.acedata.cloud"
HEADERS = {
    "Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_KEY']}",
    "Content-Type": "application/json",
}

create_response = requests.post(
    f"{BASE_URL}/minimax/videos",
    headers=HEADERS,
    json={
        "model": "MiniMax-H3",
        "content": [
            {
                "type": "text",
                "text": "清晨の海辺、一艘の白い帆船が静かな海面を渡っていく、カメラがゆっくりと横に移動する",
            }
        ],
        "resolution": "768P",
        "duration": 4,
        "ratio": "16:9",
    },
    timeout=30,
)
create_response.raise_for_status()
task_id = create_response.json()["task_id"]

while True:
    time.sleep(10)
    query_response = requests.post(
        f"{BASE_URL}/minimax/tasks",
        headers=HEADERS,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    query_response.raise_for_status()
    task = query_response.json()["task"]
    print(f"task={task_id} status={task['status']}")

    if task["status"] == "succeeded":
        print(f"video_url={task['content']['url']}")
        break
    if task["status"] in ("failed", "cancelled"):
        raise RuntimeError(task.get("error") or task["status"])
```

本番環境ではポーリング設定の総タイムアウトを設定し、`429`および一時的な`5xx`に対して指数バックオフを使用する必要があります。ネットワークタイムアウトは生成失敗とは異なり、同じ`task_id`を使用してクエリを続けることができます。

## バッチクエリ

複数のタスクIDを指定します：

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve_batch",
    "ids": ["TASK_ID_1", "TASK_ID_2"],
    "offset": 0,
    "limit": 20
  }'
```

時間範囲でタスクをページングしてリストします：

```json
{
  "action": "retrieve_batch",
  "created_at_min": 1786000000,
  "created_at_max": 1786200000,
  "offset": 0,
  "limit": 20
}
```

バッチ応答の`items`は単一タスククエリと同じtaskフィールドを使用し、`total`はフィルタ条件に一致するタスクの総数です：

```json
{
  "items": [
    {
      "id": "TASK_ID_1",
      "model": "MiniMax-H3",
      "status": "running",
      "resolution": "2K",
      "duration": 5,
      "ratio": "adaptive",
      "task_type": "generation",
      "modality": "video"
    }
  ],
  "total": 1
}
```

タスククエリウィンドウは最近7日間です。このウィンドウを超えた`task_id`は無効なタスクを返す可能性があります。ビジネスシステムはタスクを作成する際にIDを保存し、成功後に結果URLを迅速に永続化する必要があります。

## タスクのキャンセルまたは削除

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "delete",
    "id": "YOUR_TASK_ID"
  }'
```

アクションはタスクの現在の状態に依存します：

| 現在の状態        | 行動            |
| ----------- | ------------- |
| `queued`    | 開始されていないタスクをキャンセルする     |
| `succeeded` | タスク記録を削除する        |
| `failed`    | タスク記録を削除する        |
| `running`   | 削除またはキャンセルは許可されず、エラーを返す |
| `cancelled` | 重複操作は許可されず、エラーを返す  |

削除成功の例：

```json
{
  "id": "YOUR_TASK_ID",
  "deleted": true
}
```

タスク記録を削除しても、すでに完了した請求を取り消すことはできず、保存されたビデオコピーが同時に削除されることも保証されません。

## 失敗応答とトラブルシューティング

失敗したタスクは依然としてHTTP 200でタスクオブジェクトを返し、`task.error`に理由が示されます：

```json
{
  "task": {
    "id": "YOUR_TASK_ID",
    "model": "MiniMax-H3",
    "status": "failed",
    "error": {
      "code": "1026",
      "message": "video description contains sensitive content"
    },
    "task_type": "generation",
    "modality": "video"
  }
}
```

インターフェース自体が`400`を返す場合は`action`と条件パラメータを確認し、`401`はTokenが無効であることを示し、`429`はクエリが頻繁すぎることを示し、`500`はサービスが一時的に利用できないことを示します。生成に失敗したタスクは請求されず、成功したタスクは最終的な`usage`に基づいて使用量が記録されます。
