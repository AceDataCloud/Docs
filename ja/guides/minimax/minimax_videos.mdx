この記事では、MiniMax H3 ビデオ生成 API の連携と使用方法について説明します。このインターフェースは、テキストからビデオを生成し、先頭と末尾のフレームを制御し、マルチモーダルな参照ビデオをサポートし、統一された V2 マルチモーダル `content` 構造を使用してタスクを作成します。

## 申請プロセス

MiniMax H3 ビデオ生成 API を使用するには、まず [Ace Data Cloud コンソール](https://platform.acedata.cloud/console/applications) にアクセスして API トークンを取得し、保管してください。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

まだログインまたは登録していない場合は、自動的にログインページにリダイレクトされ、登録とログインを促されます。完了後、現在のページに自動的に戻ります。

**1つの API トークンでプラットフォームのすべてのサービスを呼び出すことができ、各サービスごとに個別に申請する必要はありません。** 初回申請時には無料のクレジットが付与され、無料で体験できます。クレジットが不足した場合は、[コンソール](https://platform.acedata.cloud/console/coin) で一般残高をチャージできます。

> 📘 完全なドキュメント：[MiniMax H3 ビデオ生成 API →](https://platform.acedata.cloud/documents/minimax-videos-integration)

トークンは環境変数として保存し、ソースコードに書き込んだり、バージョン管理システムにコミットしたりしないでください：

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## インターフェース概要

- **Base URL**：`https://api.acedata.cloud`
- **エンドポイント**：`POST /minimax/videos`
- **認証方式**：HTTP ヘッダーに `authorization: Bearer {token}` を含める
- **リクエストヘッダー**：
  - `accept: application/json`
  - `content-type: application/json`
- **モデル（model）**：`MiniMax-H3`
- **入力構造**：`content` を通じてテキスト、画像、ビデオ、音声を統一的に渡す
- **出力モード**：デフォルトでは生成が完了するまで待機し、完全な `task` を返す；`async: true` または `callback_url` を渡すと、即座に `task_id` と `trace_id` を返す
- **結果の照会**： [MiniMax H3 タスク照会 API](/documents/minimax-tasks-integration) を通じて状態と完成品を取得
- **非同期コールバック**：オプションで、`callback_url` を通じて最終タスク結果を受信

`action` を渡して生成モードを選択する必要はなく、インターフェースは `content` 内の素材タイプと `role` に基づいて自動的に用途を判断します。

## 適したシーン

| シーン         | 入力の組み合わせ              | 一般的な用途                      |
| ---------- | --------------------- | ------------------------- |
| テキストからビデオ       | テキスト                    | 広告のアイデア、ストーリーボード、短編ビデオ、雰囲気ショット        |
| 先頭フレーム画像からビデオ     | テキスト + 先頭画像             | 商品画像、ポスター、人物写真またはイラストを自然に動かす      |
| 末尾フレーム / 先尾フレームビデオ | テキスト + 末尾フレーム、またはテキスト + 先頭フレーム + 末尾フレーム | オープニングとエンディングの制御、トランジション、成長の変化と前後の比較      |
| マルチモーダル参照ビデオ   | テキスト + 参照画像 / ビデオ / 音声   | キャラクターと製品の一貫性を保ち、動作、カメラワーク、音色または編集リズムを再現 |

## 呼び出しプロセス

デフォルトで `async` を渡さない場合、`/minimax/videos` は生成が完了するまで待機し、完全な `task` を直接返します。接続を即座に解放する必要がある場合は、`async: true` または `callback_url` を渡します：

1. 即時応答内の `task_id` と `trace_id` を保存します。
2. コールバックが設定されていない場合、約 10 秒ごとに `/minimax/tasks` を呼び出して状態を照会します。
3. `task.status` が `succeeded` に変わったら、`task.content.url` からビデオを取得します。
4. 状態が `failed` または `cancelled` の場合はポーリングを停止し、`task.error` を読み取ります。

## トップレベルリクエストパラメータ

| パラメータ         | タイプ       | 必須   | デフォルト値        | 説明                                                |
| -------------- | -------- | ---- | ---------- | ------------------------------------------------- |
| `model`        | string   | はい    | -          | 固定で `MiniMax-H3`                                  |
| `content`      | object[] | はい    | -          | マルチモーダルコンテンツの配列、必ず1つの非空の `text` 項目を含む必要があります                         |
| `resolution`   | string   | はい    | -          | `768P` または `2K`                                     |
| `duration`     | integer  | はい    | -          | 生成時間、4-15 秒の整数                                     |
| `ratio`        | string   | 条件付き必須 | `adaptive` | `adaptive`、`21:9`、`16:9`、`4:3`、`1:1`、`3:4`、`9:16` |
| `async`        | boolean  | いいえ    | `false`    | `true` の場合、タスク識別子を即座に返し、タスクインターフェースを通じて結果を取得                       |
| `callback_url` | string   | いいえ    | -          | 最終タスク結果を受信するためのパブリックコールバック URL；提供すると自動的に非同期モードが有効になります                     |

`ratio` のルールはワークフローによって異なります：

- **テキストからビデオ**：必須で、`adaptive` にはできません。
- **先頭フレーム、末尾フレームまたは先尾フレームビデオ**：アスペクト比は入力画像によって決まるため、推奨されるのは省略または `adaptive` を渡すことです。
- **マルチモーダル参照ビデオ**：省略可能で、デフォルトは `adaptive`；特定の固定比率を明示的に指定することもできます。

インターフェースは旧版または互換性のあるフィールド（例：`prompt`、`image_urls`、`audio_urls`、`messages`、`first_frame_image`）を受け付けません。このようなパラメータエラーが発生した場合は、古いフィールドを削除し、`content` に移行してください；例えば、`"prompt": "一只猫挥手"` を `"content": [{"type": "text", "text": "一只猫挥手"}]` に変更します。新旧両方の形式を同時に送信しないでください。

## content 内容項パラメータ

各内容項には `type` が必要で、残りのフィールドはタイプによって決まります：

| `type`      | データフィールド            | `role`            | 説明                                     |
| ----------- | --------------- | ----------------- | -------------------------------------- |
| `text`      | `text`          | 送信しない                | 各リクエストには1つの非空のテキスト項目が含まれている必要があり、最大 7000 文字まで             |
| `image_url` | `image_url.url` | `first_frame`     | 先頭画像；1枚の画像のみで `role` を省略した場合も先頭フレームとして処理されます         |
| `image_url` | `image_url.url` | `last_frame`      | 末尾画像；単独で使用することも、`first_frame` と組み合わせて起点と終点を制御することもできます |
| `image_url` | `image_url.url` | `reference_image` | 参照対象、キャラクター、製品、衣服、シーンまたはスタイル                    |
| `video_url` | `video_url.url` | `reference_video` | 参照動作、カメラワーク、パフォーマンスまたは編集構造                        |
| `audio_url` | `audio_url.url` | `reference_audio` | 参照音色、セリフ、音楽またはリズム                          |

メディアアドレスは3つの形式をサポートします：

- 公開アクセス可能な HTTPS URL、特に大きなファイルに推奨されます。
- `mm_file://{file_id}`、すでにアップロードされたファイルまたは結果を参照します。
- 対応するメディアタイプの Base64 データ URI。Base64 はサイズを約三分の一増加させるため、リクエスト全体のサイズが 64 MB を超えないようにしてください。

## 素材仕様と数量制限
| 素材  | 格式                                          | 单文件限制     | 尺寸 / 时长                                                         | 数量限制                        |
| --- | ------------------------------------------- | --------- | --------------------------------------------------------------- | --------------------------- |
| 画像  | JPG、JPEG、PNG、WEBP、HEIC、HEIF                 | 30 MB 以下 | 幅高均为 256-5760 px；幅高比 0.4-2.5                                    | 首帧最多 1 张、尾帧最多 1 张、参考图最多 9 张 |
| 動画  | MP4、MOV；H.264/AVC または H.265/HEVC；音声トラック AAC または MP3 | 50 MB 以下 | 各セクション 2-15 秒、合計 15 秒以下；幅高均为 256-5760 px；幅高比 0.4-2.5；23.976-60 fps | 参考動画は最大 3 セクション                  |
| 音声  | WAV、MP3                                     | 15 MB 以下 | 各セクション 2-15 秒、合計 15 秒以下                                            | 参考音声は最大 3 セクション                  |

多モーダル参考シーンの画像、動画、音声は合計で最大 12 ファイル。首尾フレームシーンと参考素材シーンは排他的です：`reference_image`、`reference_video` または `reference_audio` を使用すると、`first_frame` または `last_frame` を使用できなくなり、その逆も同様です。

## プロダクションレベルの能力展示

以下は概念図やプレースホルダー素材ではなく、MiniMax H3 の公式プロダクションレベルの能力サンプルの実際の参考入力と実際の動画出力です。3つのケースはそれぞれブランド短編、実写ストーリーテリング、ファッションEコマースをカバーしており、商業制作におけるモデルの最も重要な能力を評価するのに適しています。

| 能力       | 重点観察                        |
| -------- | --------------------------- |
| 人物と顔の一貫性 | 多角度の切り替え後の五官、髪型、メイク、人物の気質が安定しているか     |
| 顔の演技     | 近距離での目の動き、微表情、感情の緊張感と自然な頭の動き      |
| 商品構造の保持   | メガネ、ハンドバッグなどの商品の輪郭、素材、装着関係と鏡面反射    |
| ブランドビジュアルの実行   | シーンの雰囲気、映画の粒子、色彩、ロゴと編集のリズムが統一されているか |
| 映画的ストーリーテリング    | ショットの変化、人物の配置、カメラワーク、リズムと音声が完全な段落を形成できるか  |

ここでの「顔の能力」とは、動画生成における人物の外観の一貫性、顔の詳細、演技の制御を指し、身元認識、顔の照合または顔交換インターフェースではありません。

## テキストから動画生成

テキスト項目が一つだけの場合、それはテキストから動画生成となる。アイデア、スクリプト、またはショットの説明から直接映像を生成するのに適している。プロンプトは「主体 + 動作 + シーン + カメラ + 光 + 音」の順序で整理できる。

```bash
curl -X POST 'https://api.acedata.cloud/minimax/videos' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MiniMax-H3",
    "content": [
      {
        "type": "text",
        "text": "15 秒映画級香水広告：清晨海岸の黒い岩の上に、透明な香水瓶が薄霧と波に囲まれている。マクロで瓶の水滴とガラスの屈折を見せ、カメラは製品のクローズアップからゆっくりと広大な海面に引き上げる；銀青色のトーン、自然光、上品で抑制された、最後に製品を固定する。"
      }
    ],
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }'
```

デフォルトの同期モードでは、生成が完了した後に完全なタスクを返す：

```json
{
  "task": {
    "id": "f5977217-ed2c-40da-adbe-93d08235618f",
    "model": "MiniMax-H3",
    "status": "succeeded",
    "content": { "url": "https://cdn.acedata.cloud/minimax/f5977217.mp4" },
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }
}
```

リクエストに `"async": true` を追加すると、インターフェースはすぐに返す：

```json
{
  "task_id": "f5977217-ed2c-40da-adbe-93d08235618f",
  "trace_id": "trace_7f8c2b1a"
}
```

## 初フレーム画像から動画生成

画像を `first_frame` としてマークすると、モデルはその画面から生成を開始する。ポスター、商品画像、キャラクター設定画像、写真作品を自然に動かすのに適している。

```json
{
```

## 終フレームと初終フレーム動画
只提供 `last_frame` はモデルが指定された画面に自然に生成することを可能にします。同時に `first_frame` と `last_frame` を提供することで、起点と終点を明確に制御できます。転換、形状変化、成長過程、または製品の前後比較に適しています。

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "女の子が幼少期から自然に青年に成長し、時間が滑らかに流れ、人物は常に画面の中央に位置する"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_FIRST_FRAME_URL" },
      "role": "first_frame"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_LAST_FRAME_URL" },
      "role": "last_frame"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

初フレームと最終フレームのサイズとアスペクト比はできるだけ一致させ、主体の位置、構図、光の差異が大きくならないようにすることで、自然な遷移を得やすくなります。

## マルチモーダル参考生動画

参考素材は組み合わせて使用できます：参考画像はキャラクターや製品の外観を制御し、参考動画は動作やカメラワークを制御し、参考音声はセリフの音色、音楽、または編集のリズムを制御します。プロンプトには各素材が何を制御するかを明確に記載し、素材をアップロードするだけで関連関係を示さないことを避けてください。

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "参考人物の顔の特徴、髪型、服装を一致させ、参考動画の演技動作に従ってファッショナブルな短編を完成させる；カメラのリズムは参考音声に従い、クローズアップで自然な表情を強調する"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_CHARACTER_IMAGE_URL" },
      "role": "reference_image"
    },
    {
      "type": "video_url",
      "video_url": { "url": "YOUR_PERFORMANCE_VIDEO_URL" },
      "role": "reference_video"
    },
    {
      "type": "audio_url",
      "audio_url": { "url": "YOUR_AUDIO_URL" },
      "role": "reference_audio"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

## コールバック通知

`callback_url` を渡すと非同期モードが自動的に有効になります：作成インターフェースはすぐに `task_id` と `trace_id` を返し、タスクが完了した後にそのアドレスに最終結果をPOSTします。構造はタスククエリ応答と一致します。

コールバック内の最終状態は `succeeded`、`failed` または `cancelled` です。コールバックを使用しても `task_id` を保存することをお勧めします。これにより、積極的にクエリを行ったり、通知を見逃した場合の補償が可能です。

## 一般的なエラー

| HTTP ステータスコード | 意味           | 処理提案                           |
| -------- | ------------ | ------------------------------ |
| `400`    | パラメータエラーまたは素材の組み合わせが不正 | 必須フィールド、`role`、素材の数と形式を確認する          |
| `401`    | トークンが欠落または無効  | `Authorization: Bearer ...` を確認する |
| `402`    | 残高またはクレジット不足      | コンソールで一般的な残高を補充                     |
| `422`    | コンテンツセキュリティチェックに失敗    | プロンプトや素材を調整して再提出                  |
| `429`    | リクエストが多すぎる       | 指数バックオフの後に再試行；タスクポーリングの推奨間隔は約 10 秒         |
| `500`    | サービスが一時的に利用できない      | リクエスト情報を保持し、後で再試行                    |

同期応答の `task.status: succeeded` は動画が生成されたことを示します；非同期確認はタスクがキューに入ったことを示すだけです。タスクが最終的に成功した場合のみ料金が発生し、タスクのクエリ自体は無料で、重複して料金が発生することはありません。
