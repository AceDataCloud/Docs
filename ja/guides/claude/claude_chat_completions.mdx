Anthropic Claude は非常に強力な AI 対話システムであり、プロンプトを入力するだけで、わずか数秒で流暢かつ自然な応答を生成できます。Claude はその優れた言語理解および生成能力により業界で際立っており、現在では、Claude はすでにさまざまな業界や分野で広く活用され、その影響力はますます顕著になっています。日常会話、クリエイティブライティング、専門的なコンサルティング、コードプログラミングのいずれにおいても、Claude は驚くべき知的支援を提供し、人間の作業効率と創造性を大幅に向上させます。

本ドキュメントでは主に Claude Chat Completion API 操作の使用手順を紹介します。これを利用することで、公式 Claude の対話機能を簡単に使用できます。

## 申請手順

Claude Chat Completion API を使用するには、まず [Ace Data Cloud コンソール](https://platform.acedata.cloud/console/applications) にアクセスして API Token を取得し、控えておいてください。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

まだログインまたは登録していない場合は、自動的にログインページに移動して登録とログインを促され、完了後に現在のページへ自動的に戻ります。

**1 つの API Token でプラットフォーム上のすべてのサービスを呼び出せるため、サービスごとに個別に申請する必要はありません。** 初回申請時には無料枠が付与され、無料で体験できます。枠が不足した場合は [コンソール](https://platform.acedata.cloud/console/coin) で共通残高をチャージできます。

> 📘 完全なドキュメント：[Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## 基本的な使用方法

次に、図のように画面上で対応する内容を入力できます。

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

このインターフェースを初めて使用する際は、少なくとも 3 つの項目を入力する必要があります。1 つは `authorization` で、ドロップダウンリストから直接選択できます。もう 1 つのパラメータは `model` で、最新フラッグシップの `claude-fable-5-1` の使用を推奨します。従来の `claude-fable-5` も引き続き呼び出せます。最後のパラメータは `messages` で、質問文の配列です。各要素には `role` と `content` が含まれます。`role` は `user`、`assistant`、`system` をサポートし、`content` は具体的な内容です。Claude Fable 5.1 は 100 万 Token のコンテキストと最大 128K Token の出力をサポートします。

同時に、右側には対応する呼び出しコードが生成されていることに気づくでしょう。コードをコピーして直接実行することも、「Try」ボタンを直接クリックしてテストすることもできます。

よく使用されるオプションパラメータ：

- `max_tokens`：1 回の応答での最大 token 数を制限します。
- `temperature`：生成のランダム性。0～2 の間で、値が大きいほど発散します。
- `n`：一度に生成する候補応答の数。
- `response_format`：返却形式の設定。

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

呼び出し後、返却結果は以下のようになります。

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }
}
```

返却結果には複数のフィールドがあり、以下のとおりです。

- `id`、今回の対話タスクを生成する ID で、今回の対話タスクを一意に識別するために使用されます。
- `model `、選択した Claude 公式サイトのモデル。
- `choices`、Claude が質問文に対して提供する回答情報。
- `usage `：今回の質疑応答における token の統計情報。

Chat Completions 形式では、`usage.prompt_tokens` は入力総量です。`prompt_tokens_details.cached_tokens` と `prompt_tokens_details.cache_write_tokens` はそれぞれキャッシュの読み取りおよび書き込みの詳細を記録します。`completion_tokens_details.reasoning_tokens` は `completion_tokens` のサブセットであり、総量または料金を計算する際に再度加算しないでください。非ストリーミング応答では `usage.cost` オブジェクトが返される場合もあり、そのうち `amount` は実際のクレジット消費量、`currency` は計量単位、`list_amount` は割引前の金額（該当する場合）です。

Chat-compatible のフィールド名は `reasoning_tokens` です。ネイティブ Messages API では `output_tokens_details.thinking_tokens` を使用します。両方のプロトコルの wire schema は異なるため、クライアントではフィールド名を混在させないでください。

このうち `choices` には Claude の回答情報が含まれており、その中の `choices` は Claude の具体的な回答情報です。図のように確認できます。

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

確認できるように、`choices` 内の `content` フィールドには Claude の応答の具体的な内容が含まれています。

## ストリーミング応答

このインターフェースはストリーミング応答もサポートしており、Web ページとの連携に非常に便利で、Web ページでの逐次表示効果を実現できます。

応答をストリーミングで返したい場合は、リクエストヘッダー内の `stream ` パラメータを変更し、`true` に設定します。

図のように変更しますが、ストリーミング応答をサポートするためには、呼び出しコードにも対応する変更が必要です。

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

`stream` を `true` に変更すると、API は対応する JSON データを 1 行ずつ返します。コードレベルでは、1 行ずつの結果を取得するために対応する変更を行う必要があります。

Python サンプル呼び出しコード：

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## 深い思考
新世代の Claude モデルは、モデルのデフォルト戦略に従って推論を行う可能性があり、`-thinking` モデルサフィックスでトリガーする必要はありません。Chat-compatible のレスポンスでは、OpenAI 互換の usage フィールド `completion_tokens_details.reasoning_tokens` を使用します。`reasoning_tokens` はすでに `completion_tokens` に含まれているため、重複して加算しないでください。推論と可視本文は出力 token の上限を共有するため、`max_tokens` が小さい場合は本文が空になる、または切り詰められる可能性があります。このような場合は出力予算を増やすか、使用するモデルが対応している場合はより低い推論投入量を選択してください。

ネイティブの `thinking`、`output_config.effort`、thinking コンテンツブロックおよび署名の返却が必要な場合は、`/v1/messages` を使用してください。Messages に対応する usage フィールドは `output_tokens_details.thinking_tokens` です。Chat-compatible の `completion_tokens_details.reasoning_tokens` と混在させないでください。

## ビジョンモデル

claude-sonnet-4-20250514 は Claude が開発したマルチモーダル大規模言語モデルであり、claude-4 をベースに視覚理解能力を追加しています。このモデルはテキストと画像の入力を同時に処理でき、クロスモーダルな理解と生成を実現します。

## エラー処理

API を呼び出す際にエラーが発生した場合、API は対応するエラーコードと情報を返します。例：

- `400 token_mismatched`：Bad request、パラメータの欠落または無効が原因である可能性があります。
- `400 api_not_implemented`：Bad request、パラメータの欠落または無効が原因である可能性があります。
- `401 invalid_token`：Unauthorized、認証トークンが無効または欠落しています。
- `429 too_many_requests`：リクエストが多すぎます。レート制限を超えています。
- `500 api_error`：内部サーバーエラー、サーバーで何らかの問題が発生しました。
