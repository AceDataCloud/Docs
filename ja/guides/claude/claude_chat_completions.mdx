Anthropic Claude は非常に強力な AI 対話システムであり、プロンプトを入力するだけで、わずか数秒で流暢かつ自然な応答を生成できます。Claude は優れた言語理解力と生成能力により業界で独自の地位を築いており、現在ではすでにさまざまな業界や分野で広く活用され、その影響力はますます顕著になっています。日常会話、創作執筆、専門的な相談、コードプログラミングのいずれにおいても、Claude は驚くべき知的支援を提供し、人類の作業効率と創造性を大幅に向上させます。

本ドキュメントでは主に Claude Chat Completion API 操作の使用フローを紹介します。これを利用することで、公式 Claude の対話機能を簡単に使用できます。

## Claude Fable 5.2

完全なモデル名 `claude-fable-5-2` を使用します。このモデルは複雑な推論および長期タスクに適しています。ネイティブの思考コンテンツブロックとツールインタラクションが必要な場合は、Messages を優先して使用してください。適応的思考は常に有効であり、`temperature`、`top_p`、`top_k` は省略し、ツール選択には `auto` を使用し、ツールを強制指定しないでください。`max_tokens` は思考と最終テキストの両方を対象とします。現在、このモデルでは Responses および Count Tokens インターフェースは提供されていません。

現在の最大プラン（142,800 Credits／$13,584）に基づく換算では、Fable 5.2 の通常入力は $3.20、出力は $16／100 万 token です。キャッシュ読み取りは $0.08、5 分／1 時間のキャッシュ書き込みはそれぞれ $4／$6.40／100 万 token です。上記価格は公式標準 API 単価の 40%（60% 割引）です。その他のプランおよびアカウントの追加割引については、モデル価格ページと請求書をご確認ください。

## 基本的な使用方法

続いて、図のようにインターフェース上で対応する内容を入力できます。

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

このインターフェースを初めて使用する場合、少なくとも 3 つの内容を入力する必要があります。1 つは `authorization` で、ドロップダウンリストから直接選択できます。もう 1 つのパラメータは `model` で、`claude-opus-5-5`、`claude-fable-5-1` などの公開モデルを選択できます。旧 `claude-fable-5` も引き続き呼び出すことができます。最後のパラメータは `messages` で、質問文の配列です。各要素には `role` と `content` が含まれます。`role` は `user`、`assistant`、`system` をサポートし、`content` は具体的な内容です。完全な Claude の思考コンテンツブロック、署名、ネイティブツールのセマンティクスが必要な場合は、引き続き Messages API を使用してください。

同時に、右側には対応する呼び出しコードが生成されていることに気付くでしょう。コードをコピーして直接実行することも、「Try」ボタンを直接クリックしてテストすることもできます。

よく使用されるオプションパラメータ：

- `max_tokens`：1 回の応答で生成される最大 token 数を制限します。
- `temperature`：生成のランダム性。0-2 の範囲で、値が大きいほど発散します。
- `n`：一度に生成する候補応答の数。
- `response_format`：返却形式の設定。

`claude-opus-5-5` は通常およびストリーミングの Chat Completions をサポートします。このモデルでは `n=1` のみ許可されます。1 未満の `temperature` やデフォルト以外の `top_p` を設定しないでください。ツール呼び出しには `tool_choice: "auto"` を使用し、ツールを強制指定しないでください。Chat 互換インターフェースではネイティブの思考コンテンツブロックは返されません。

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

呼び出し後、返却結果は以下のとおりです。

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }
}
```

返却結果には複数のフィールドがあり、以下のとおりです。

- `id`、この対話タスクの生成 ID。この対話タスクを一意に識別するために使用されます。
- `model `、選択した Claude 公式サイトのモデル。
- `choices`、Claude が質問文に対して提供する回答情報。
- `usage `：今回の質疑応答における token の統計情報。

Chat Completions 形式では、`usage.prompt_tokens` は入力総量です。`prompt_tokens_details.cached_tokens` と `prompt_tokens_details.cache_write_tokens` はそれぞれキャッシュ読み取りと書き込みの詳細を記録します。`completion_tokens_details.reasoning_tokens` は `completion_tokens` のサブセットであり、総量または費用を計算する際に再度加算しないでください。非ストリーミング応答では、`usage.cost` オブジェクトが返される場合もあります。ここで `amount` は実際のクレジット消費量、`currency` は計量単位、`list_amount` は割引前の金額です（該当する場合）。

Chat-compatible のフィールド名は `reasoning_tokens` です。ネイティブ Messages API では `output_tokens_details.thinking_tokens` を使用します。2 つのプロトコルの wire schema は異なるため、クライアントはフィールド名を混用すべきではありません。

このうち `choices` には Claude の回答情報が含まれており、その中の `choices` は Claude の回答の具体的な情報です。図のように確認できます。

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

ご覧のとおり、`choices` 内の `content` フィールドには Claude の返信の具体的な内容が含まれています。

## ストリーミング応答

このインターフェースはストリーミング応答もサポートしており、Web ページとの連携に非常に役立ちます。これにより、Web ページで一文字ずつ表示する効果を実現できます。

応答をストリーミングで返したい場合は、リクエストヘッダー内の `stream ` パラメータを変更し、`true` に設定できます。

図のように変更しますが、呼び出しコードもストリーミング応答をサポートするために対応する変更が必要です。

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>
`stream` を `true` に変更した後、API は対応する JSON データを行ごとに返します。コードレベルでは、行ごとの結果を取得するために対応する修正を行う必要があります。

Python サンプル呼び出しコード：

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## 深い思考

新世代の Claude モデルは、モデルのデフォルト戦略に従って推論を行う可能性があり、`-thinking` モデル接尾辞によるトリガーは不要です。Chat-compatible レスポンスでは、OpenAI 互換の usage フィールド `completion_tokens_details.reasoning_tokens` を使用します。`reasoning_tokens` はすでに `completion_tokens` に含まれているため、重複して加算しないでください。推論と可視本文は出力 token の上限を共有するため、`max_tokens` が小さい場合、本文が空になる、または切り詰められる可能性があります。このような場合は出力予算を増やすか、使用するモデルが対応している場合は低い推論投入量を選択してください。

ネイティブの `thinking`、`output_config.effort`、thinking コンテンツブロックおよび署名の返却が必要な場合は、`/v1/messages` を使用してください。Messages に対応する usage フィールドは `output_tokens_details.thinking_tokens` であり、Chat-compatible の `completion_tokens_details.reasoning_tokens` と混在させないでください。

## エラー処理

API を呼び出す際にエラーが発生した場合、API は対応するエラーコードと情報を返します。例：

- `400 token_mismatched`：不正なリクエスト。パラメータの欠落または無効が原因である可能性があります。
- `400 api_not_implemented`：不正なリクエスト。パラメータの欠落または無効が原因である可能性があります。
- `401 invalid_token`：未認証。認証トークンが無効または欠落しています。
- `429 too_many_requests`：リクエストが多すぎます。レート制限を超過しています。
- `500 api_error`：内部サーバーエラー。サーバーで問題が発生しました。
