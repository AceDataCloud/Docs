Google Gemini は非常に強力な AI 対話システムであり、プロンプトを入力するだけで数秒以内に流暢で自然な応答を生成できます。本ドキュメントでは主に Gemini Generate Content API の使用方法について説明します。これは Google 公式のネイティブ API 形式であり、`generateContent` と `streamGenerateContent` の 2 つのエンドポイントをサポートしています。

## Chat Completions API との違い

Gemini Generate Content API は、OpenAI 互換形式（`messages` フィールド）ではなく、Google 公式のネイティブリクエスト形式（`contents` フィールド）を使用します。すでに Google Gemini SDK を使用している、または公式 API 形式に慣れている場合は、リクエスト形式を変更せずにこの API を直接使用できます。

## 現在のサポート範囲

インターフェースはテキスト、画像、動画、音声入力（`inlineData` または `fileData`）、思考設定、およびカスタム関数宣言を受け付けます。音声出力、組み込みツール、明示的なコンテキストキャッシュなどのネイティブフィールドについては、まだ統一された利用可能性の保証はありません。具体的なモデルの実際の返却内容を基準にしてください。

`fileData.fileUri` を使用して音声などのファイルを送信する場合、ファイルが HTTPS 経由で直接アクセス可能であり、ログイン状態に依存せず、署名付きリンクの有効期間がリクエスト処理時間全体をカバーしていることを確認してください。非ストリーミングの音声分析は、モデルが処理を完了してから結果を返す必要があるため、90 秒を超える場合があります。クライアントはファイルサイズとビジネスシナリオに応じて十分に長い合計タイムアウトを設定し、サーバーがまだ処理中に接続を切断しないようにしてください。

## 申請プロセス

Gemini Generate Content API を使用する前に、まず [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) ページにアクセスし、「取得」ボタンをクリックしてリクエストに必要な認証情報を取得してください。

まだログインまたは登録していない場合は、自動的にログインページへリダイレクトされます。初回申請には無料枠があります。

## 基本的な使用方法

### Non-Streaming（非ストリーミング）

`/v1beta/models/{model}:generateContent` に POST リクエストを送信します：

> **ヒント**：`gemini-3.x` シリーズの flash は思考モデルであり、最初に reasoning tokens を消費します。`generationConfig.maxOutputTokens` を 512 以上に設定してください。設定しない場合、空のコンテンツしか返されない可能性があります。

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

返却結果の例：

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

`usageMetadata` 内の token フィールドは、ネイティブ Gemini のセマンティクスに従って課金されます：

- `promptTokenCount` には `cachedContentTokenCount` が含まれます。キャッシュヒットした部分はキャッシュ読み取り価格で計算され、通常の入力として重複計上されません。
- `promptTokensDetails` と `cacheTokensDetails` は、`usage.prompt_tokens_details` 配下の `text_tokens`、`image_tokens`、`video_tokens`、`audio_tokens` および対応する `cached_*` 明細に正規化されます。これらの値はそれぞれ `prompt_tokens` と `cached_tokens` に含まれます。異なるモダリティはそれぞれの価格でのみ再計算され、重複課金されません。
- `candidatesTokenCount` と `thoughtsTokenCount` は、いずれも出力 token の価格で計算されます。
- `toolUsePromptTokenCount` は独立したツール入力 token であり、入力 token の価格で計算されます。

Ace Data Cloud は追加で正規化された `usage` オブジェクトを返します。モデルプロトコルをまたいで、今回の呼び出し料金は `usage.cost` から統一的に読み取ります。`cost` は任意の料金プレビューです。価格プレビューが一時的に利用できない場合でも、モデル応答は通常どおり返されますが、このフィールドが含まれない可能性があります。最終的な請求は使用量記録に基づきます。

### Streaming（ストリーミング）

`/v1beta/models/{model}:streamGenerateContent?alt=sse` に POST リクエストを送信します：

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

ストリーミング返却では、SSE（Server-Sent Events）形式でコンテンツが段階的に返されます。中間イベントには通常、増分コンテンツのみが含まれます。権威ある使用量を含む終端イベントには `usageMetadata` と正規化された `usage` が含まれ、料金は引き続き `usage.cost` に格納されます：

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

接続が閉じられた時点でストリームの終了を示します。ネイティブ Gemini ストリームは `data: [DONE]` を送信しません。終端の価格プレビューが一時的に利用できない場合でも、`usage` は token 使用量を返しますが、`cost` は省略されます。

### 内部思考と思考要約

モデルの内部思考と、呼び出し元への思考要約の返却は、2 つの独立した設定です：

- `thinkingBudget` または `thinkingLevel` はモデル内部の思考予算または深度を制御します。サポートされるフィールドと値はモデルによって異なります。
- `includeThoughts` は思考要約を返すかどうかを制御し、デフォルトは `false` です。このフィールドを省略するか `false` を渡した場合、通常の JSON と SSE ストリーミングレスポンスのいずれも、`thought: true` とマークされたテキストを返しません。これらのテキストを保持するのは、明示的にブール値 `true` を渡した場合のみです。

リクエストで `includeThoughts` が設定されていない場合、インターフェースは思考設定をサポートする生成モデルに対してデフォルトで `false` を渡し、リクエストが不要な要約を取得することを防ぎます。顧客が明示的に渡した値、思考予算、レベルは保持されます。思考設定をサポートしないことが判明している `gemini-2.5-flash-image` には、このフィールドは自動追加されず、`countTokens` リクエストにも生成設定は追加されません。

要約をオフにすることは、内部思考をオフにすることと同じではなく、内部思考 token の削減も保証しません。レスポンスに依然としてリクエストされていない思考テキストが含まれる場合、通常の JSON と SSE 出力ではさらにフィルタリングされ、通常の回答、署名、実際の使用量が保持されます。

要約を確認する必要がある場合は、以下の方法で明示的にオンにしてください。モデルが利用可能な要約を生成しなかった場合、オンにしていても思考テキストが存在しない可能性があります：

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` は後続のターンで必要となる暗号化状態であり、思考要約テキストではなく、`includeThoughts` スイッチによっても制御されません。署名は通常の回答、関数呼び出し、または空のテキスト Part に存在する可能性があります。思考テキストをフィルタリングする際、署名および同じ Part の他のフィールドは保持されるため、レスポンスには署名のみを持ち、テキストが空の Part が依然として存在する可能性があります。複数ターンの履歴を手動で管理する場合、これらの Part の順序と署名位置を保持し、署名を移動または統合しないでください。

`usageMetadata` と `usage` は引き続き実際の使用量を記録します。要約を非表示にしても `thoughtsTokenCount` はゼロにならず、課金は引き続き実際の使用量および現在の価格ルールに従って計算されます。

Google 公式の[思考と思考要約の説明](https://firebase.google.com/docs/ai-logic/thinking)および[思考署名ルール](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures)を参照してください。

## 安全設定

コンテンツフィルタリングは `safetySettings` で制御できます：

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## エラー処理

| HTTP ステータスコード | 意味             |
| -------- | -------------- |
| 400      | リクエストパラメータが無効         |
| 401      | 認証に失敗しました。Token を確認してください |
| 403      | コンテンツが安全フィルタによってブロックされた     |
| 429      | リクエストが頻繁すぎる         |
| 500      | サーバー内部エラー        |
