Google Gemini は非常に強力な AI 対話システムであり、プロンプトを入力するだけで数秒以内に流暢で自然な応答を生成できます。本ドキュメントでは主に Gemini Generate Content API の使用方法について説明します。これは Google 公式ネイティブ API 形式であり、`generateContent` と `streamGenerateContent` の 2 つのエンドポイントをサポートしています。

## Chat Completions API との違い

Gemini Generate Content API は、OpenAI 互換形式（`messages` フィールド）ではなく、Google 公式ネイティブリクエスト形式（`contents` フィールド）を使用します。すでに Google Gemini SDK を使用している、または公式 API 形式に精通している場合は、リクエスト形式を変更せずに直接この API を使用できます。

## 現在のサポート範囲

インターフェースは、テキスト、画像、動画、音声入力（`inlineData` または `fileData`）、思考設定、およびカスタム関数宣言を受け付けます。音声出力、組み込みツール、明示的なコンテキストキャッシュなどのネイティブフィールドについては、まだ統一された可用性保証がありません。具体的なモデルの実際の戻り値をご確認ください。

`fileData.fileUri` を使用して音声などのファイルを送信する際は、ファイルが HTTPS 経由で直接アクセス可能であり、ログイン状態に依存しないことを確認し、署名付きリンクの有効期限がリクエスト処理時間全体をカバーするようにしてください。非ストリーミングの音声分析は、モデルが処理を完了してから結果を返す必要があるため、90 秒を超える可能性があります。クライアントはファイルサイズとビジネスシナリオに応じて十分に長い総タイムアウトを設定し、サーバーがまだ処理中である間に接続が切断されないようにしてください。

## 申請フロー

Gemini Generate Content API を使用する前に、まず [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) ページにアクセスし、「取得」ボタンをクリックして、リクエストに必要な認証情報を取得してください。

まだログインまたは登録していない場合は、自動的にログインページへリダイレクトされます。初回申請時には無料枠があります。

## 基本的な使用方法

### Non-Streaming（非ストリーミング）

`/v1beta/models/{model}:generateContent` に POST リクエストを送信します：

> **ヒント**：`gemini-3.x` シリーズの flash は思考モデルであり、まず reasoning tokens を消費します。`generationConfig.maxOutputTokens` を 512 以上に設定してください。そうしない場合、空のコンテンツしか返されない可能性があります。

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

戻り結果の例：

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

`usageMetadata` 内の token フィールドは、ネイティブ Gemini のセマンティクスに従って課金されます：

- `promptTokenCount` には `cachedContentTokenCount` が含まれます。キャッシュヒットした部分はキャッシュ読み取り価格で計算され、通常の入力として重複計上されません。
- `promptTokensDetails` と `cacheTokensDetails` は、`usage.prompt_tokens_details` 配下の `text_tokens`、`image_tokens`、`video_tokens`、`audio_tokens` および対応する `cached_*` 明細に正規化されます。これらの値はそれぞれ `prompt_tokens` と `cached_tokens` に含まれます。異なるモダリティはそれぞれの価格でのみ再計算され、重複課金されません。
- `candidatesTokenCount` と `thoughtsTokenCount` は、いずれも出力 token の価格で計算されます。
- `toolUsePromptTokenCount` は独立したツール入力 token であり、入力 token の価格で計算されます。

Ace Data Cloud はさらに、正規化された `usage` オブジェクトを返します。モデルプロトコルをまたいで、今回の呼び出し費用は `usage.cost` から統一して読み取ります。`cost` はオプションの費用プレビューです。価格プレビューが一時的に利用できない場合でも、モデルレスポンスは正常に返されますが、このフィールドが含まれない可能性があります。最終的な請求は使用量記録に基づきます。

### Streaming（ストリーミング）

`/v1beta/models/{model}:streamGenerateContent?alt=sse` に POST リクエストを送信します：

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

ストリーミングの戻り値は SSE（Server-Sent Events）形式で段階的にコンテンツを返します。中間イベントには通常、増分コンテンツのみが含まれます。権威ある使用量を含む終端イベントには `usageMetadata` と正規化された `usage` が含まれ、費用は引き続き `usage.cost` にあります：

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

接続が閉じられるとストリームの終了を意味します。ネイティブ Gemini ストリームは `data: [DONE]` を送信しません。終端の価格プレビューが一時的に利用できない場合でも、`usage` は token 使用量を返しますが、`cost` は省略されます。

### 内部思考と思考要約

モデルの内部思考と呼び出し元に思考要約を返すことは、2つの独立した設定です：

- `thinkingBudget` または `thinkingLevel` はモデル内部の思考予算または深度を制御し、サポートされるフィールドと値はモデルによって異なります。
- `includeThoughts` は思考要約を返すかどうかを制御し、デフォルトは `false` です。このフィールドを省略するか `false` を渡した場合、通常の JSON と SSE ストリーミングレスポンスのどちらも `thought: true` とマークされたテキストを返しません；これらのテキストが保持されるのは、ブール値 `true` を明示的に渡した場合のみです。

リクエストで `includeThoughts` が設定されていない場合、インターフェースは思考設定をサポートする生成モデルにデフォルトで `false` を渡し、リクエストが不要とする要約を回避します；クライアントが明示的に渡した値、思考予算およびレベルは保持されます。思考設定をサポートしないことが判明している `gemini-2.5-flash-image` にはこのフィールドが自動追加されず、`countTokens` リクエストにも生成設定は追加されません。

要約をオフにすることは内部思考をオフにすることと同義ではなく、内部思考 token の削減を保証するものでもありません。レスポンスに依然としてリクエストされていない思考テキストが含まれる場合、通常の JSON と SSE 出力ではさらにフィルタリングを行い、通常の回答、署名および実際の使用量を保持します。

要約を確認する必要がある場合は、以下のように明示的に有効にします。モデルが利用可能な要約を生成しなかった場合、有効にしていても思考テキストがない可能性があります：

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "量子もつれを説明して"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` は後続のターンで必要となる暗号化状態であり、思考要約テキストではなく、`includeThoughts` スイッチの制御も受けません。署名は通常の回答、関数呼び出し、または空のテキスト Part 上に存在する可能性があります；思考テキストをフィルタリングする際、署名および同じ Part の他のフィールドは保持されるため、レスポンスには署名のみを持ち、テキストが空の Part が依然として存在する可能性があります。複数ターンの履歴を手動で管理する場合は、これらの Part の順序と署名の位置を保持し、署名を移動したり統合したりしないでください。

`usageMetadata` と `usage` は引き続き実際の使用量を記録します。要約を非表示にしても `thoughtsTokenCount` はゼロにならず、課金は引き続き実際の使用量および現在の料金ルールに基づいて計算されます。

Google 公式の[思考と思考要約の説明](https://firebase.google.com/docs/ai-logic/thinking)および[思考署名ルール](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures)を参照してください。

## 安全設定

` safetySettings` を通じてコンテンツフィルタリングを制御できます：

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## エラー処理

| HTTP ステータスコード | 意味             |
| -------- | -------------- |
| 400      | リクエストパラメータが無効         |
| 401      | 認証に失敗しました。Token を確認してください |
| 403      | コンテンツが安全フィルターによってブロックされた     |
| 429      | リクエストが頻繁すぎる         |
| 500      | サーバー内部エラー        |
