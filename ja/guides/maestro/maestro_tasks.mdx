Maestro タスククエリ API の主な機能は、[Maestro ビデオ生成 API](development_maestro_videos.md)（`POST /maestro/videos`）から返されたタスク ID を使用して、そのタスクの実行状態と最終結果を照会することです。

この記事では、Maestro タスククエリ API の接続説明を詳しく紹介します。ビデオ生成は非同期タスクであるため、提出後はこのインターフェースを使用して進捗と完成品をポーリングする必要があります。**ポーリングは無料で、ポイントを消費しません。**

`POST https://api.acedata.cloud/maestro/tasks`

## 申請フロー

Maestro タスククエリ API を使用するには、まず [Ace Data Cloud コンソール](https://platform.acedata.cloud/console/applications) で API トークンを取得し、保管しておきます。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

まだログインしていない場合や登録していない場合は、自動的にログインページにリダイレクトされ、登録とログインを促されます。完了後、現在のページに自動的に戻ります。

**1つの API トークンでプラットフォームのすべてのサービスを呼び出すことができ、各サービスごとに個別に申請する必要はありません。** 初回申請時には無料のクレジットが付与され、無料で体験できます。クレジットが不足した場合は、[コンソール](https://platform.acedata.cloud/console/coin) で共通残高をチャージできます。

> 📘 完全なドキュメント：[Maestro タスククエリ API →](https://platform.acedata.cloud/documents/maestro-tasks)

## 単一タスクの照会

ビデオタスクの作成方法については、[Maestro ビデオ生成 API](development_maestro_videos.md) のドキュメントを参照してください。ここでは、その返されたタスク ID の例として `f57e99c4f60f4373a15517742ce2357d` を使用し、状態と結果を照会する方法を示します。

### リクエストヘッダーとリクエストボディの設定

**Request Headers** には以下が含まれます：

- `accept`：JSON形式のレスポンス結果を受け取ることを指定します。ここには `application/json` を記入します。
- `authorization`：APIを呼び出すためのキーで、申請後に直接ドロップダウンから選択できます。
- `content-type`：リクエストボディの形式で、ここには `application/json` を記入します。

**Request Body** には以下が含まれます：

| フィールド   | タイプ     | 必須  | 説明                                                |
| -------- | ------ | --- | ------------------------------------------------- |
| `id`     | string | はい   | `POST /maestro/videos` から返された `task_id`              |
| `action` | string | いいえ   | `retrieve`（デフォルト、単一タスクを照会）/ `retrieve_batch`（履歴タスクリストを照会） |

### コード例

対応する CURL コードは以下の通りです：

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

対応する Python コードは以下の通りです：

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### レスポンス例

リクエストが成功した場合、API はそのビデオタスクの状態と結果を返します。タスクが完了した際の返却例は以下の通りです（各言語に対応する `variant` が含まれます）：

```json
{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "started_at": 1769262721.823,
  "finished_at": 1769264698.3,
  "elapsed": 1976.477,
  "status": "succeeded",
  "progress": {
    "percent": 100,
    "stage": "producing",
    "message": "rendering scene 2"
  },
  "request": {
    "prompt": "20秒でベクトルデータベースとは何かを説明し、初心者向けに、最後に記憶に残る一言を",
    "langs": [
      "zh-cn",
      "en"
    ],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        {
          "lang": "zh-cn",
          "aspect": "9:16",
          "kind": "video",
          "title": "ベクトルデータベースとは",
          "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-001"
        },
        {
          "lang": "en",
          "aspect": "9:16",
          "kind": "video",
          "title": "What is a vector database",
          "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-002"
        }
      ],
      "project": {
        "tarball_url": null,
        "outputs": [
          "https://…/zh.mp4",
          "https://…/en.mp4"
        ]
      },
      "percent": 100,
      "stage": "producing",
      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }
  }
}
```

返却結果のフィールドの説明は以下の通りです：

- `id`：このビデオタスクの ID で、今回のビデオ生成タスクを一意に識別します。
- `status`：タスクの状態で、値は `pending → planning → producing → succeeded`（または `failed`）です。タスクが完了しているかどうかは、この最上位の `status` に基づきます。
- `elapsed`：タスクの経過時間（秒）。
- `progress`：最上位の進捗オブジェクトで、`percent`（0–100）はタスク成功後に 100 に固定されます；`stage` と `message` は AI ディレクターの最近の進捗イベントを反映します（したがって成功後も `stage` は最後の実行段階である `producing` である可能性があります）、進捗バーの表示に直接使用できます。
- `request`：タスクを発起した際のリクエストボディ。
- `response`：タスクの返却情報。
  - `success`：タスクが成功したかどうか。
  - `data.variants`：各言語に対応する完成品オブジェクトで、`lang`、`aspect`、`title`、`output_url`（完成品のダウンロードリンク）などが含まれます。
  - `data.project`：全体のプロジェクト成果物で、`tarball_url`（プロジェクトパッケージ）と `outputs`（すべての完成品リンク）が含まれます。
  - `data.progress`：段階ごとの進捗イベントの配列（追加専用ログ）で、詳細なリアルタイム進捗の表示に使用できます。
- `created_at`：タスク作成時間、Unix タイムスタンプ（秒）。
- `started_at`：タスク開始実行時間、Unix タイムスタンプ（秒）。タスクがまだ開始されていない場合は null。
- `finished_at`：タスク完了時間、Unix タイムスタンプ（秒）。タスクが未完了の場合は null。

## 履歴リストの照会

`action: retrieve_batch` を渡すことで、現在のユーザーの最近のタスクを取得できます（作成時間の降順で）、これは「マイビデオ」リストページに使用できます。

**Request Body** には以下が含まれます：
| フィールド           | タイプ     | 必須  | 説明                      |
| ---------------- | ------ | --- | ----------------------- |
| `action`         | string | はい   | 固定で `retrieve_batch`    |
| `limit`          | int    | いいえ   | 戻り値の件数、デフォルトは 20              |
| `created_at_max` | int    | いいえ   | この Unix タイムスタンプより前のタスクのみを返す（ページング用） |
| `created_at_min` | int    | いいえ   | この Unix タイムスタンプより後のタスクのみを返す      |

### コード例

対応する CURL コードは以下の通りです：

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

      "progress": {
        "percent": 100,
        "stage": "producing",
        "message": "シーン 2 をレンダリング中"
      },

## ポーリングの推奨

動画生成には時間がかかるため、`status` は `pending → planning → producing → succeeded`（または `failed`）を経ます。5～10秒ごとにポーリングすることをお勧めします。`status` が `succeeded` または `failed` に変わるまで。トップレベルの `progress.percent` を利用してリアルタイムの進捗バーを表示できます。**このインターフェースのポーリングは無料で、ポイントを消費しません。**

## エラーハンドリング

API を呼び出す際にエラーが発生した場合、API は対応するエラーコードとメッセージを返します。例えば：

- `401 invalid_token`：Unauthorized, invalid or missing authorization token.
- `404 not_found`：タスクが見つかりません、指定された task_id は存在しません。
- `429 too_many_requests`：リクエストが多すぎます、レート制限を超えました。
- `500 api_error`：内部サーバーエラー、サーバーで何かがうまくいきませんでした。

### エラーレスポンス例

```json
{
  "success": false,
  "error": {

}
```
