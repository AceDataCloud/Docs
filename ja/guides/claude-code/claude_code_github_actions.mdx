## 1. API キーの取得

[Ace Data Cloud アプリケーションリスト](https://platform.acedata.cloud/console/applications)を開き、利用可能なアプリにアクセスして API キーをコピーします。

![Ace Data Cloud API キーの取得](https://cdn.acedata.cloud/dvc3cg.jpg)

対象の GitHub リポジトリの **Settings → Secrets and variables → Actions** で新しい Secret を作成します：

```text
ACEDATACLOUD_API_KEY
```

## 2. GitHub アプリのインストール

[Claude GitHub アプリ](https://github.com/apps/claude)をインストールし、対象リポジトリに権限を付与します。この公式アプリは固定の完全な権限セットを要求します。その中で Claude Code Action は実際に Contents、Issues、Pull requests の権限を使用します。GitHub のインストールページではこれらの三項目だけを選択することはできません。組織が最小権限を要求する場合は、公式ドキュメントに従ってカスタム GitHub アプリを作成してください。

## 3. ワークフローの追加

`.github/workflows/claude.yml` を作成します：

```yaml
name: Claude Code

on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]

jobs:
  claude:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: write
      actions: read
      id-token: write
    env:
      ANTHROPIC_BASE_URL: https://api.acedata.cloud
      ANTHROPIC_CUSTOM_HEADERS: "Authorization: Bearer ${{ secrets.ACEDATACLOUD_API_KEY }}"
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: dummy-not-used
```

`claude-code-action` には非空の `anthropic_api_key` 入力が必要です；ここでのプレースホルダーはプラットフォームの認証には使用されません。`ANTHROPIC_CUSTOM_HEADERS` は Ace Data Cloud に必要な Bearer ヘッダーを上書きし、実際のキーは GitHub Secret からのみ取得されます。

## 4. 検証

ワークフローを提出した後、Issue または PR コメントに次のように送信します：

```text
@claude Reply only OK
```

成功した場合、Actions ワークフローは完了し、対応する Issue/PR に結果が更新されます。Action が資格情報が不足していると表示された場合は、`dummy-not-used` がまだ存在することを確認してください；401 エラーの場合は `ACEDATACLOUD_API_KEY` Secret を確認してください。ログに Secret を印刷しないでください。必要に応じて `claude_args` を使用して `--max-turns` を設定したり、現在利用可能なモデルを選択したりできますが、接続テンプレートは固定モデルではありません。
