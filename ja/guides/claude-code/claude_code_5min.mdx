このドキュメントの目的はただ一つ：**5分以内に** AceData Cloud プロキシを使って最初の Claude Code コマンドを実行することです。完全なチュートリアルは各 IDE のサブドキュメントをご覧ください（[VS Code](https://platform.acedata.cloud/documents/claude-code-vscode-integrations) / [Cursor](https://platform.acedata.cloud/documents/claude-code-cursor-integration) / [JetBrains](https://platform.acedata.cloud/documents/claude-code-jetbrains-integrations)）。本稿では「**ターミナル CLI** + **VS Code 拡張機能**」の最速ルートのみを扱います。

> **なぜ AceData Cloud プロキシで Claude Code を使うのか**：
> - 国内から直接接続可能で、VPN を用意する必要なし
> - 公式よりも安価（プラットフォームのトークン課金）
> - 同じキーで Claude Messages API と Claude Code トークンプロトコルの両方をサポート

## 1分目：認証情報の申請

[Claude Messages サービスページ](https://platform.acedata.cloud/documents/claude-messages)を開き、「**Acquire**」ボタンをクリック：

![](https://cdn.acedata.cloud/nyq0xz.png)

プラットフォームが自動的に Application を作成し、無料クレジットを付与します。詳細ページにある **Base URL** と **API Token** の2つを控えてください —— 以降の5ステップで使用します。

| フィールド | 値 | 用途 |
|------|------|------|
| `BASE_URL` | `https://api.acedata.cloud` | Claude Messages 互換エンドポイント |
| `API_TOKEN` | `sk-...`（詳細ページからコピー可能） | Anthropic 互換認証ヘッダー |

## 2分目：Claude Code のインストール

macOS / Linux / WSL：

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows（ネイティブ PowerShell）：

```powershell
irm https://claude.ai/install.ps1 | iex
```

インストール完了後、新しいターミナルを開いて動作確認：

```bash
claude --version
```

> バージョン番号が表示されれば成功です。Claude Code は Node.js ランタイムを内蔵しており、マシン上の Node バージョンに依存しません。

## 3分目：環境変数を AceData Cloud に向ける

公式の `claude login` フローは使わず、環境変数で上書きします。以下のいずれかを選択してください：

**方法 A：一時的（現在のシェルセッションのみ）**

```bash
export ANTHROPIC_BASE_URL="https://api.acedata.cloud"
export ANTHROPIC_AUTH_TOKEN="sk-あなたの-Token"
```

**方法 B：永続化（推奨）**

上記2行を `~/.zshrc` または `~/.bashrc` に追記し、`source` コマンドで反映させます。

> **よくある落とし穴**：環境変数名は `ANTHROPIC_AUTH_TOKEN` であり、`ANTHROPIC_API_KEY` ではありません。誤った名前を使うと Claude Code は公式エンドポイントにフォールバックし、401 エラーになります。

## 4分目：最初のコマンドを実行

任意の Git リポジトリに入り、以下を実行：

```bash
claude
```

初回起動時にログインを求められたら、`Esc` キーでスキップ。その後、以下を入力：

```
現在のプロジェクトの依存関係をリストアップし、それぞれの用途を簡単に説明してください。
```

正常なら Claude が `read_file` / `glob` / `grep` などのツールを使ってリポジトリを調査し、リストを返します。モデルが正しく応答し、401 エラーが出なければプロキシが有効です。

## 5分目：VS Code 拡張機能も接続する

1. VS Code を開き、拡張機能パネルで「Claude Code」を検索し、Anthropic 公式のものをインストール；
2. VS Code を再起動するか、コマンドパレットで `Developer: Reload Window` を実行し、3分目で設定した `~/.claude/settings.json` を読み込ませる；
3. エディタ右上の ✦ Spark アイコン、またはステータスバーの「✱ Claude Code」をクリックしてパネルを開く；
4. 初回は公式アカウントのログインを求められますが、`Esc` でスキップ可能 —— 拡張機能は自動的に3分目の `ANTHROPIC_BASE_URL` と `ANTHROPIC_AUTH_TOKEN` を使用します。

> **ヒント**：VS Code 拡張と CLI は同じ `~/.claude/settings.json` を共有するため、VS Code 内で別途設定する必要はありません。プロジェクト単位で設定を上書きしたい場合は、リポジトリのルートに `.claude/settings.local.json`（gitignore済み）を作成してください。

成功すればパネル内でファイルをドラッグして質問したり、`@-mention` でファイルを参照して修正提案ができます。すべての課金は AceData Cloud 経由です。

## プロキシを確実に使っているか確認する

`--debug` モードで一度起動し、リクエストが実際に AceData Cloud に送られているか確認：

```bash
claude --debug -p "say hi" 2>&1 | grep -iE 'base.?url|api\.acedata|anthropic\.com' | head
```

`https://api.acedata.cloud` の文字列が見えればプロキシが有効です。`api.anthropic.com` が出たり 401 エラーが返る場合は、3分目の環境変数名（必ず `ANTHROPIC_AUTH_TOKEN`）を再確認し、`~/.claude/.credentials.json` に公式トークンが書かれていないか確認してください（あれば削除）。

## よくある質問トップ5

**Q：`claude login` 後に環境変数を AceData に変えたが反映されない？**  
A：`claude login` は `~/.claude/.credentials.json` に公式トークンを書き込み、環境変数より優先されます。ファイルを削除し、`source ~/.zshrc` すれば反映されます。

**Q：`--model claude-opus-4-7` のようなモデル名は使えますか？**  
A：使えます。AceData Cloud プロキシは model フィールドを透過的に通し、すべての Anthropic 公開モデルと拡張モデル `claude-opus-4-7` / `claude-haiku-4-5` / `claude-sonnet-4-5` をサポートします。

**Q：複数のプロファイル（個人＋会社）を設定できますか？**  
A：可能です。Claude Code は `~/.claude/settings.json` で複数プロファイルをサポートしています。もっと簡単には、2つのシェル関数 `claude_personal` / `claude_work` を作り、それぞれ異なる `ANTHROPIC_AUTH_TOKEN` を export して `claude $@` を呼び出す方法もあります。

**Q：GitHub Actions で使えますか？**  
A：使えます。詳細は [Claude Code GitHub Actions 設定チュートリアル](https://platform.acedata.cloud/documents/claude-code-github-actions-integration) を参照してください。

**Q：無料クレジットがなくなったら？**  
A：[アプリ管理](https://platform.acedata.cloud/applications) → 対象の Claude Application を選択 → Topup でチャージ（トークン消費に応じて課金）、またはポイントサブスクリプションに切り替え可能です。
