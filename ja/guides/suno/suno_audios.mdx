AI の応用が広がるにつれて、各種 AI プログラムはすでに徐々に普及している。AI はすでに徐々に人々の仕事や生活のあらゆる面に深く入り込んでいる。そして AI が関わる業界もますます増えており、最初の執筆から、医療・教育、そして現在の音楽に至るまで広がっている。

Suno はプロフェッショナルで高品質な AI 楽曲・音楽制作プラットフォームであり、ユーザーは簡単なテキストプロンプトを入力するだけで、ジャンルスタイルと歌詞に基づいてボーカル付きの楽曲を生成できる。この AI 音楽生成器は、Meta、TikTok、Kensho などの有名テクノロジー企業出身のチームメンバーによって開発されており、いかなる楽器ツールも必要とせず、すべての人が素晴らしい音楽を作れることを目標としている。

しかし Suno 公式は API を提供しておらず、AceDataCloud は Suno の API 一式を提供し、Suno 公式との連携をシミュレートしており、必要な音楽を便利かつ迅速に生成できる。

## 申請と使用

Suno Audios Generation API を使用するには、まず [Ace Data Cloud コンソール](https://platform.acedata.cloud/console/applications) であなたの API Token を取得し、予備として保存する。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

まだログインまたは登録していない場合は、ログインページへ自動的に移動して登録とログインを案内され、完了後は自動的に現在のページへ戻る。

**1 つの API Token でプラットフォームのすべてのサービスを呼び出すことができ、サービスごとに個別申請する必要はない。** 初回申請時には無料枠が付与され、無料で体験できる；枠が不足した場合は [コンソール](https://platform.acedata.cloud/console/coin) で共通残高をチャージできる。

> 📘 完全なドキュメント：[Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## 基本的な使用方法

どのような楽曲を考えても、任意の文章を入力できる。たとえばクリスマスに関する楽曲を生成したい場合は、`a song for Christmas` と入力すればよく、図のとおりである：

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

ここでは Request Headers を設定していることが分かり、以下を含む：

- `accept`：どの形式のレスポンス結果を受け取りたいか。ここでは `application/json`、つまり JSON 形式を入力する。
- `authorization`：API を呼び出すためのキーであり、申請後に直接プルダウンから選択できる。

また Request Body を設定しており、以下を含む：
- `action`：オーディオタスクのタイプ。デフォルトは `generate`。生成、続きの作成、カバー、結合、ステム分離、オーディオトラックの追加、指定オーディオトラックの抽出、効果音の生成、速度調整などの操作をサポートし、すべて `POST /suno/audios` を通じて呼び出します。
- `prompt`：Suno 公式のインスピレーションモードのプロンプト（`custom` が `false` の場合に有効）。最大 500 文字。
- `model`：今回の音楽生成タスクのモデル。v6 シリーズには `chirp-v6`、`chirp-v6-wild`、`chirp-v6-mini` が含まれます。旧モデル名も引き続き互換性があります。
- `max_mode`：拡張生成モード。`generate` は `custom` と `max_mode` がともに `true` の場合にのみ有効で、料金は 1.12 Credits です。`add_stem` は直接有効化でき、料金は 1.344 Credits です。無効または省略時は、それぞれ 0.56 および 0.672 Credits です。
- `variety`：生成結果の多様性の強度。`off`、`normal`、`high`、`extra`、`max` から選択可能。`generate` と `add_stem` にのみ使用され、その他の action で渡すと 400 が返されます。
- `lyric`：Suno 公式のカスタムモードの歌詞内容。`chirp-v3-5` と `chirp-v4` は最大 3000 文字、`chirp-v4-5` 以降（`chirp-v5`、`chirp-v5-5` を含む）は最大 5000 文字。
- `custom`：カスタムモードを使用するかどうか。デフォルトは: `false`。
- `instrumental`：Suno 公式のインスピレーションモードのインストゥルメンタルオプション。
- `title`：Suno 公式のカスタムモードの楽曲タイトル。`chirp-v3-5`、`chirp-v4` は最大 80 文字、`chirp-v4-5` 以降は最大 100 文字。
- `style`：Suno 公式のカスタムモードの音楽スタイル。`chirp-v3-5` と `chirp-v4` は最大 200 文字、`chirp-v4-5` 以降（`chirp-v5`、`chirp-v5-5` を含む）は最大 1000 文字。
- `negative_tags`：カスタムモード（`custom` が `true`）で、生成結果から除外したい音楽スタイルまたはジャンル。
- `audio_weight`：オーディオまたは音声特徴の影響の重み。範囲は 0-1 で、`0` も有効な値です。生成、続きの作成、カバー、オーディオトラックの追加、音声一貫性などの操作に使用できます。参照オーディオまたは音声特徴がない場合、モデルはこの値を弱めたり無視したりする可能性があります。
- `audio_id`：参照音楽の ID。
- `overpainting_start`/`overpainting_end`：既存のインストゥルメンタル音楽にボーカルを追加する開始・終了時刻。単位は秒。
- `underpainting_start`/`underpainting_end`：アカペラに伴奏を追加する開始・終了時刻。単位は秒。
- `persona_id`：アーティストの楽曲 ID。
- `continue_at`：続きの作成境界。単位は秒。たとえば、213.5 は 3 分 33.5 秒の位置から後続のセグメントを生成することを示します。`lyric` と `style` は境界以降の新しい内容のみをガイドし、元のオーディオ内で境界より前の歌詞や歌唱を置き換えることはありません。
- `style_influence`：カスタムモードでのスタイル影響力。範囲は 0-1 で、大きいほど通常は選択したスタイルにより沿います。`0` も有効な値として渡されます。
- `replace_section_end`：置換するセグメントの最終時刻。
- `replace_section_start`：置換するセグメントの開始時刻。
- `vocal_gender`：女性・男性ボーカルの好みを制御します。女性ボーカルは `f`、男性ボーカルは `m` で、4.5 以降のモデルで有効です。これは好みの項目であり、厳密な遵守は保証されません。
- `weirdness`：カスタムモードでの奇抜さ。範囲は 0-1 で、大きいほど通常はより創造的・実験的になります。`0` も有効な値として渡されます。
- `duration`：期待する楽曲の長さ。単位は秒で、整数である必要があり、値の範囲は 10 から 360 です。このパラメータは、カスタムモード（`custom` が `true`）の楽曲生成に使用されます。これは厳格な制約ではなく傾向を示すプロンプトです。モデルはこれを参照しますが、達成を保証するものではありません。実際の完成品の長さはレスポンス内の `duration` フィールドに従い、通常は期待値より短くなります。

### 高度なパラメータの適用範囲

| パラメータ                | 値                                          | サポートされる action                              | 説明                              |
| ----------------- | ------------------------------------------- | --------------------------------------- | ------------------------------- |
| `weirdness`       | 0-1                                         | 任意                                      | 実験性を調整。`0` は有効な値。効果は操作、モード、モデルに依存    |
| `style_influence` | 0-1                                         | 任意                                      | スタイルへの追従傾向を調整。`0` は有効な値。効果は操作、モード、モデルに依存 |
| `audio_weight`    | 0-1                                         | 任意                                      | オーディオまたは音声特徴の影響を調整。参照情報がない場合はモデルに無視される可能性がある      |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`、`add_stem`                   | 結果間のスタイルの多様性を調整                     |
| `max_mode`        | boolean                                     | `generate`（`custom=true` が必要）、`add_stem` | 一貫性を強化し、拡張モード料金で課金される                   |
| `vocal_gender`    | `f` / `m`                                   | ボーカル制御をサポートする生成操作                             | 好みの項目であり、厳密な遵守は保証されない                     |
| `duration`        | 整数 10-360                                   | 任意                                      | 期待する長さ。具体的な操作、モード、またはモデルによっては無視される可能性がある             |

プラットフォームはパラメータの型と数値範囲を検証しますが、action が異なることのみを理由にこれらの任意の調整項目を拒否することはありません。具体的な効果は操作、モード、モデルによって決まります。

- `lyric_prompt`：歌詞を生成するための prompt。`custom` が `true` であり、かつ `lyric` が渡されていない場合に限り有効です。
- `callback_url`：結果をコールバックする必要がある URL。
- `async`：任意。`true` に設定すると、インターフェースは直ちに `task_id` を返します。`callback_url` を提供する必要はなく、その後、対応するタスク照会インターフェースを通じてポーリングして結果を取得します。

## カスタム生成

歌詞をカスタム生成したい場合は、歌詞を入力できます：

この時、`lyric` フィールドには以下のような内容を渡すことができます：

```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> 注意：ここでの歌詞内の `\n` は改行文字です。歌詞を生成する方法がわからない場合は、AceDataCloud が提供する歌詞生成 API を使用して、prompt から歌詞を生成できます。API は [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics) です。

続いて、歌詞、タイトル、スタイルに基づいて楽曲をカスタム生成するには、以下の内容を指定できます：

- lyric：歌詞テキスト
- custom：`true` を入力するとカスタム生成を表します。このパラメータのデフォルトは false で、`prompt` を使用した生成を表します。
- title：楽曲のタイトル。
- style：楽曲のスタイル。任意です。

入力例は以下のとおりです：

<p><img src="https://cdn.acedata.cloud/qp3iba.png" width="500" className="m-auto" /></p>

入力完了後、自動生成されたコードは以下のとおりです：

```shell
curl -X POST 'https://api.acedata.cloud/suno/audios' \

-H 'authorization: Bearer {token}' \

-d '{
  "action": "generate",
  "prompt": "A song for Christmas",
  "model": "chirp-v4-5",
  "lyric": "[Verse]\\nSnowflakes falling all around\\nGlistening white\\nCovering the ground\\nChildren laughing\\nFull of delight\\nIn this winter wonderland tonight\\nSanta's sleigh\\nUp in the sky\\nRudolph's nose shining bright\\nOh my\\nHear the jingle bells\\nRinging so clear\\nBringing joy and holiday cheer\\n[Verse 2]\\nRoasting chestnuts by the fire's glow\\nChristmas lights\\nThey twinkle and show\\nFamilies gathering with love and cheer\\nSpreading warmth to everyone near",
  "custom": true

```

## カスタム歌手スタイル生成機能
歌手スタイルを使用して楽曲を生成したい場合、まず上記の基本的な使用方法で楽曲を生成し、
最後にこの楽曲を歌手スタイルに設定する必要があります。その後、[Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) にアクセスし、公式で生成された音楽 ID `audio_id` に基づいて歌手スタイルの id パラメータ `persona_id` を生成する必要があります。具体的なパラメータは以下の図のとおりです：

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

入力が完了すると、以下のコードが自動生成されます：

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

対応する Python コード：

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

実行をクリックすると、以下のような結果が得られることがわかります：

```json
{
  "success": true,
  "task_id": "7628b754-4fe7-4e79-bda4-806d0dd8bf6e",
  "data": {
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b"
  }
```

## 続きを生成する機能

すでに生成された Suno 楽曲に対して続きを生成したい場合は、パラメータ `action` を `extend` に設定し、続けて生成する必要がある楽曲の ID を入力できます。楽曲 ID は基本的な使用方法に基づいて取得します。上記から、この時点で楽曲の ID は以下であることがわかります：

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> 注意：ここで歌詞中の `id` は生成後の楽曲の ID です。楽曲の生成方法がわからない場合は、上記の基本的な使用方法を参考にして楽曲を生成できます。

自分でアップロードした楽曲に対して続きを生成したい場合は、パラメータ `action` を `upload_extend` に設定し、続けて生成する必要があるカスタムアップロード済み楽曲の ID を入力できます。楽曲 ID は [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload) を使用して取得します。以下の図のとおりです：

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

次に、続きのセグメントの歌詞を必ず入力する必要があり、スタイルを指定することもできます：

- lyric：`continue_at` 以降に新しく生成されるセグメントの歌詞を誘導するためだけに使用され、元の音声におけるこの時点以前の歌詞は置き換えられません。
- custom：`true` を入力するとカスタム生成を表します。このパラメータのデフォルトは false であり、`prompt` を使用して生成することを表します。
- style：続きのセグメントの楽曲スタイル、任意入力です。
- continue_at：続きの生成境界で、単位は秒です。例えば、213.5 は 3 分 33.5 秒の位置から後続セグメントを生成することを表します。

> `extend` は既存の楽曲の続きを後方に作成するためのものであり、楽曲全体の歌詞を変更するものではありません。楽曲全体を最初から新しい歌詞で作成したい場合は、`generate` を使用して再生成してください。既存の楽曲を参考にして再演奏したい場合は、`cover` を使用できます。楽曲全体の新しい歌詞を渡した場合でも、`continue_at` より前の元の歌詞は置き換えられません。

入力が完了すると、以下のコードが自動生成されます：

## セクションの置換

楽曲の生成後、楽曲セクションの置換を個別に行う二次創作が必要な場合は、楽曲のあるセクションに対して置換操作を行えます。

> ⚠️ **注意**：`replace_section_result_mode` のデフォルトは `full_song` です：システムは新たに生成された 2 つの候補をそれぞれ結合し、2 曲の完全な楽曲を返します。まだ結合されていない置換セクション候補のみが必要な場合は、明示的に `candidates` に設定し、その後候補を選択して[音楽結合](#音楽結合)を呼び出してください。

パラメータの説明は以下のとおりです：

- action：内容は `replace_section` です。
- audio_id：元の楽曲（置換されるソース楽曲）の ID。
- model: 楽曲生成モデル。
- lyric: 置換後の完全な歌詞（置換されるセクションおよびそのコンテキストを含み、`prompt` 内の内容と一致させます）。
- prompt：置換するセクションの新しい歌詞。
- style：楽曲のスタイル、任意。
- replace_section_start：置換されるセクションの元の楽曲内での開始時間（秒）。
- replace_section_end：置換されるセクションの元の楽曲内での終了時間（秒）。
- replace_section_result_mode：返却モード、デフォルトは `full_song` です。`full_song` は 2 つの候補をそれぞれ結合して 2 曲の完全な楽曲を返します；`candidates` はまだ結合されていない 2 つの候補セクションを返します。

完全な楽曲を直接取得したい場合は、ステップ1で `replace_section_result_mode` を `full_song` に設定できます。インターフェースはそれぞれ2つの候補を結合し、2曲の完全な楽曲を返します。この場合、`concat` を再度呼び出す必要はありません。

### ステップ2：置換セグメントを元の楽曲に結合する

上で選択したセグメント（例：`364f9d8b-ca25-463b-9a5e-d0b7139e2d6a`）に対して、[音楽の結合](#音楽の結合) セクションの方法に従い、`concat` タスクを開始します。

```json
  "action": "concat",
  "audio_id": "364f9d8b-ca25-463b-9a5e-d0b7139e2d6a",
  "model": "chirp-v5-5"
}
```

## 楽曲の長さの制御

デフォルトでは、生成される楽曲の長さはモデルが自動的に決定し、通常は 30 秒から 4 分の間です。より長いまたは短い完成品が必要な場合は、`duration` パラメータで希望する長さを指定できます。単位は秒で、値は 10 から 360 までの整数です。

このパラメータは、カスタムモード（`custom` が `true`）での楽曲生成に使用されます。特に説明が必要なのは、`duration` は**傾向を示すヒントであり、厳密な制約ではない**ということです：モデルは作曲時にこの値を参照しますが、達成されることは保証されず、実測では実際の長さは通常、希望値より明らかに短くなります。同一のリクエストで返される 2 曲の長さにも数倍の差が生じる可能性があります。完全に同じリクエストであっても、複数回送信した場合に得られる長さには大きな差が生じる可能性があります。したがって、これを正確な長さの制御として使用しないでください。業務上、固定の長さが必要な場合は、完成品を取得した後に自分でトリミングするか、再試行してください。

対応する Python コード：
```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

注意すべき点として、リクエスト内の `duration` は**希望する長さ**であり、レスポンスの `data` にある各楽曲の `duration` フィールドはその楽曲の**実際の長さ**です。両者は同じ名前ですが意味は異なり、実際の長さが希望値と等しいことは保証されません。歌詞の長さは完成品の長さに影響する主な要因の一つであり、より長い完成品が必要な場合は、より完全な歌詞も同時に提供することを推奨します。

インターフェースは `duration` が 10 から 360 までの整数であることを検証します。これはあくまで生成目標であり、完成品の長さを保証するものではありません。

## Inspo インスピレーション作曲機能

Inspo インスピレーション作曲機能では、1〜4本の完全な参照オーディオに基づいて新しい音楽を生成できます。オーディオをドラッグ＆ドロップするかアップロードして、インスピレーション源として使用できます。API は既存の `inspo` action を使用します。クライアントは公開アクセス可能なオーディオ URL を提供し、サービスが参照オーディオの準備と作曲を自動的に完了するため、クライアント側で歌詞、スタイル、長さを個別に読み取ってリクエストを組み立てる必要はありません。これは上記の区間サンプリングとも、原曲のスタイルを再現する Cover とも異なります。使用時には、以下のパラメータを入力する必要があります。

- action：内容は `inspo`。
- audio_urls：参照オーディオの URL リスト。公開アクセス可能なオーディオアドレスを1〜4件指定する必要があります。
- model：使用するモデル。`chirp-v6` を推奨します。
- prompt：歌詞または作曲用プロンプト（任意）。

> 注意：参照オーディオは公開アクセス可能なオーディオファイルである必要があります。参照オーディオがプラットフォームの楽曲ライブラリ内の既知の録音と完全に一致する場合、Suno は著作権チェックにより生成を拒否することがあります。インスピレーション源として、自身が所有するオーディオまたは Suno が生成したオーディオを使用することを推奨します。

対応する Python コード：

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {

    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
```

## 非同期コールバック

Suno による音楽生成には比較的長い時間がかかり、約 1～2 分を要します。API が長時間応答しない場合、HTTP リクエストは接続を維持し続けるため、追加のシステムリソースが消費されます。そのため、本 API では非同期コールバックもサポートしています。

全体のフローは次のとおりです。クライアントがリクエストを開始する際に、追加で `callback_url` フィールドを指定します。クライアントが API リクエストを開始した後、API は直ちに結果を返し、その中には現在のタスク ID を表す `task_id` フィールド情報が含まれます。タスク完了後、生成された音楽の結果は POST JSON の形式でクライアントが指定した `callback_url` に送信され、その中にも `task_id` フィールドが含まれるため、タスク結果を ID によって関連付けることができます。

以下では、具体的な操作方法を例を通して見ていきます。

まず、Webhook コールバックは HTTP リクエストを受信できるサービスです。開発者は自身で構築した HTTP サーバーの URL に置き換える必要があります。ここではデモを容易にするため、公開 Webhook サンプルサイト https://webhook.site/ を使用します。このサイトを開くと、図のように Webhook URL を取得できます。

![](https://cdn.acedata.cloud/fwfqin.png)

この URL をコピーすれば、Webhook として使用できます。ここでのサンプルは https://webhook.site/03e60575-3d96-4132-b681-b713d78116e2 です。
