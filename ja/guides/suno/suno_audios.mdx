AI の応用が広がるにつれ、さまざまな AI プログラムが徐々に普及しています。AI は人々の仕事や生活のあらゆる側面に徐々に浸透しています。また、AI が関わる業界もますます増えており、初期の執筆から、医療・教育、そして現在の音楽にまで及んでいます。

Suno は、専門的で高品質な AI 楽曲・音楽制作プラットフォームです。ユーザーは簡単なテキストプロンプトを入力するだけで、ジャンルスタイルと歌詞に基づいてボーカル付きの楽曲を生成できます。この AI 音楽生成器は、Meta、TikTok、Kensho などの著名なテクノロジー企業出身のチームメンバーによって開発されており、楽器やツールを必要とせず、誰もが美しい音楽を作れることを目標としています。

Suno は現在、`chirp-v6`、`chirp-v6-wild`、および `chirp-v6-mini` をサポートしています。`chirp-v6` の使用を推奨します。旧モデル名も引き続き互換性があります。

しかし、Suno 公式は API を提供していません。AceDataCloud は Suno の API セットを提供しており、Suno 公式との連携をシミュレートすることで、必要な音楽を便利かつ迅速に生成できます。

## 基本的な使用方法

どのような曲を考えていても、任意の文章を入力できます。たとえば、クリスマスに関する曲を生成したい場合は、`a song for Christmas` と入力できます。図のとおりです：

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

ここでは Request Headers を設定していることがわかります。内容は以下のとおりです：

- `accept`：どの形式のレスポンス結果を受け取りたいかを指定します。ここでは `application/json`、つまり JSON 形式を入力します。
- `authorization`：API を呼び出すためのキーです。申請後、直接ドロップダウンから選択できます。

さらに Request Body を設定します。内容は以下のとおりです：
- `action`：オーディオタスクの種類。デフォルトは `generate`。生成、続きの作成、カバー、マッシュアップ、ステム分離、オーディオトラックの追加、指定オーディオトラックの抽出、効果音の生成、速度調整などの操作をサポートし、すべて `POST /suno/audios` を通じて呼び出します。
- `prompt`：Suno 公式のインスピレーションモード用プロンプト（`custom` が `false` の場合に有効）。最大 500 文字。
- `model`：今回の音楽生成タスクのモデル。v6 シリーズには `chirp-v6`、`chirp-v6-wild`、`chirp-v6-mini` が含まれます。旧モデル名も引き続き互換性があります。
- `max_mode`：拡張生成モード。`generate` は `custom` と `max_mode` の両方が `true` の場合にのみ有効になり、費用は 1.12 Credits。`add_stem` は直接有効にでき、費用は 1.344 Credits。無効または省略時は、それぞれ 0.56 および 0.672 Credits です。
- `variety`：生成結果の多様性の強度。`off`、`normal`、`high`、`extra`、`max` から選択可能。`generate` と `add_stem` にのみ使用され、その他の action で渡すと 400 が返されます。
- `lyric`：Suno 公式のカスタムモード用の歌詞内容。`chirp-v3-5` と `chirp-v4` は最大 3000 文字、`chirp-v4-5` 以降（`chirp-v5`、`chirp-v5-5` を含む）は最大 5000 文字。
- `custom`：カスタムモードを使用するかどうか。デフォルトは: `false`。
- `instrumental`：Suno 公式のインスピレーションモードのインストゥルメンタルオプション。
- `title`：Suno 公式のカスタムモード用の楽曲タイトル。`chirp-v3-5`、`chirp-v4` は最大 80 文字、`chirp-v4-5` 以降は最大 100 文字。
- `style`：Suno 公式のカスタムモード用の音楽スタイル。`chirp-v3-5` と `chirp-v4` は最大 200 文字、`chirp-v4-5` 以降（`chirp-v5`、`chirp-v5-5` を含む）は最大 1000 文字。
- `negative_tags`：カスタム生成時に除外したい音楽スタイルまたはジャンル。`replace_section` にも使用できます。本インターフェースでは現在、このフィールドに固定の文字数上限は設定されていません。内容が長すぎる場合は処理できない可能性があるため、説明は簡潔に保つことを推奨します。
- `audio_weight`：オーディオまたは音声特性の影響の重み。範囲は 0～1 で、`0` も有効な値です。生成、続きの作成、カバー、オーディオトラックの追加、音声の一貫性などの操作に使用できます。参照オーディオまたは音声特性がない場合、モデルはこの値を弱めるか無視する可能性があります。
- `audio_id`：カバー、続きの作成、ステム分離などの後続操作に使用する参照楽曲の ID。オーディオファイルは引き続きダウンロードできますが、この ID の後続処理が常に利用可能であることを意味するものではありません。`suno_processing_unavailable` が返された場合は、`task_id` と `trace_id` を保管してサポートにお問い合わせください。
- `overpainting_start`/`overpainting_end`：既存のインストゥルメンタル音源にボーカルを追加する開始・終了時間。単位は秒。
- `underpainting_start`/`underpainting_end`：アカペラに伴奏を加える開始・終了時間。単位は秒。
- `persona_id`：Persona または音声作成インターフェースを通じて取得した音声 ID であり、楽曲の `audio_id` ではありません。
- `continue_at`：続きの作成の境界。単位は秒。たとえば、213.5 は 3 分 33.5 秒の位置から後続のセグメントを生成することを示します。`lyric` と `style` は境界以降の新しい内容のみを誘導し、元のオーディオ内の境界以前の歌詞や歌唱を置き換えることはありません。
- `style_influence`：カスタムモードにおけるスタイルの影響力。範囲は 0～1 で、大きいほど通常は選択したスタイルにより近くなります。`0` は有効な値として渡されます。
- `replace_section_end`：置換するセグメントの最終時間。
- `replace_section_start`：置換するセグメントの開始時間。
- `vocal_gender`：男女ボーカルの好みを制御します。女性ボーカルは `f`、男性ボーカルは `m`。4.5 以降のモデルで有効です。あくまで優先項目であり、厳密な遵守は保証されません。
- `weirdness`：カスタムモードにおける奇抜さ。範囲は 0～1 で、大きいほど通常はより創造的かつ実験的になります。`0` は有効な値として渡されます。
- `duration`：期待する楽曲の長さ。単位は秒で、整数である必要があり、値の範囲は 10～360。現在、このパラメータを使用するのは `generate` のみで、具体的な効果はモードとモデルによって異なります。これは厳密な制約ではなく傾向を示すプロンプトです。モデルはこれを参照しますが、達成は保証されません。実際の完成曲の長さはレスポンス内の `duration` フィールドに従い、通常は期待値より短くなります。

### 音声 ID の適用範囲

`generate`、`cover`、`upload_cover`、`artist_consistency`、`artist_consistency_vox` は `persona_id` を使用できます。後者 2 つの action では `persona_id` の指定が必須です。Persona の作成時に使用した楽曲の `audio_id` も同時に指定できます。

`extend`、`upload_extend` では追加の `persona_id` を使用しません。`mashup`、`inspo` が音声 ID をサポートするかどうかは、選択したサービスチャネルによって異なります。その他の action ではこのフィールドが適用される保証はないため、各操作の説明に従って使用してください。`vocal_gender` は任意の性別の好みであり、音声 ID の代わりにはなりません。

後続の作成操作には有効なソース `audio_id` が必要です。`mashup` には少なくとも 2 つの `mashup_audio_ids` が必要です。必要なソースまたは時間パラメータが不足している場合、HTTP 400 が返されます。

### 高度なパラメータの適用範囲
| パラメータ                | 値                                          | 対応する action                              | 説明                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | 任意                                      | 実験性を調整し、`0` は有効な値です。効果は操作、モード、モデルによって異なります      |
| `style_influence` | 0-1                                         | 任意                                      | スタイルへの追従傾向を調整し、`0` は有効な値です。効果は操作、モード、モデルによって異なります   |
| `audio_weight`    | 0-1                                         | 任意                                      | 音声またはサウンド特性の影響を調整します。参照情報がない場合、モデルによって無視される可能性があります        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`、`add_stem`                   | 結果間のスタイルの多様性を調整します                       |

プラットフォームはパラメータの型と数値範囲を検証しますが、action が異なることだけを理由にこれらの任意の調整項目を拒否することはありません。具体的な効果は操作、モード、モデルによって異なります。

- `lyric_prompt`：歌詞を生成するための prompt で、`custom` が `true` かつ `lyric` が渡されていない場合にのみ有効です。
- `callback_url`：結果のコールバックを受け取る URL。
- `async`：任意で、`true` に設定するとインターフェースは直ちに `task_id` を返します。`callback_url` を提供する必要はなく、その後対応するタスク照会インターフェースを通じてポーリングし、結果を取得します。

## カスタム生成

歌詞をカスタムで生成したい場合は、歌詞を入力できます：

この場合、`lyric` フィールドには以下のような内容を渡すことができます：

> 注意：ここでの歌詞内の `\n` は改行文字です。歌詞の生成方法が分からない場合は、AceDataCloud が提供する歌詞生成 API を使用して、prompt を通じて歌詞を生成できます。API は [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics) です。

- title：楽曲のタイトル。
- style：楽曲のスタイル。任意です。

## カスタム歌手スタイル生成機能

歌手スタイルを使用して楽曲を生成したい場合は、まず上記の基本的な使用方法で1曲生成し、
最後にこの楽曲を歌手スタイルとして設定する必要があります。次に、[Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) にアクセスし、公式が生成した音楽 ID `audio_id` に基づいて、歌手スタイルの id パラメータ `persona_id` を生成する必要があります。具体的なパラメータは以下の図のとおりです：

入力が完了すると、以下のコードが自動生成されます：

対応する Python コード：

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
```

## 続きの生成機能
すでに生成された Suno の楽曲を続けて生成したい場合は、パラメータ `action` を `extend` に設定し、続けて生成したい楽曲の ID を入力します。楽曲 ID は基本的な使用方法に従って取得できます。上記から、このとき楽曲の ID は次のとおりであることが確認できます：

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> 注意：ここでの歌詞内の `id` は、生成後の楽曲の ID です。楽曲の生成方法が分からない場合は、上記の基本的な使用方法を参照して楽曲を生成できます。

自分でアップロードした楽曲を続けて生成したい場合は、パラメータ `action` を `upload_extend` に設定し、続けて生成したいカスタムアップロード楽曲の ID を入力します。楽曲 ID は [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload) を使用して取得します。下図のとおりです：

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

次に、続きのセグメントの歌詞を必ず入力する必要があり、スタイルも指定できます：

- lyric：`continue_at` より後に新たに生成されるセグメントの歌詞を誘導するためにのみ使用され、元の音声におけるこの時点より前の歌詞は置き換えられません。
- custom：`true` を指定するとカスタム生成を表します。このパラメータのデフォルトは false であり、`prompt` を使用して生成することを表します。
- style：続きのセグメントの楽曲スタイル。任意。
- continue_at：続き生成の境界。単位は秒です。たとえば、213.5 は 3 分 33.5 秒の位置から後続セグメントの生成を開始することを表します。

`extend` と `upload_extend` の `continue_at` は 0 より大きくなければならず、`30.792` のような小数秒をサポートします。送信時に丸められることはありません。

> `extend` は既存の楽曲の後に続けて制作するためのものであり、楽曲全体の歌詞を変更するものではありません。楽曲全体を最初から新しい歌詞で作成したい場合は、`generate` を使用して再生成してください。既存の楽曲を参考にして再演奏したい場合は、`cover` を使用できます。新しい歌詞を1曲分すべて渡した場合でも、`continue_at` より前の元の歌詞は置き換えられません。

## セクションの置換

`replace_section` は、元の楽曲の時間区間に基づいて選択したセクションを再生成し、その結果を元曲に結合し直します。`replace_section_result_mode` のデフォルトは `full_song` で、直接再生できる2曲の完全な楽曲が返され、`concat` を再度呼び出す必要はありません。

### 入力の記入方法
- `action`：`replace_section`。
- `audio_id`：編集する完全な楽曲 ID。再編集時は、前回選択した完全な楽曲の `data[].id` を使用し、`task_id` ではありません。
- `model`：楽曲生成モデル。例：`chirp-v6`。
- `lyric`：選択区間で歌う**局所的な新しい歌詞**。完全な楽曲を得るために曲全体の歌詞を渡す必要はありません。
- `prompt`：今回の置換における局所的な新しい歌詞を明確に指定します。歌詞を変更する際は、2 つのフィールドで異なる歌詞を表現しないよう、`lyric` と同じ内容を入力することを推奨します。局所的な `lyric` のみを渡し、`prompt` を省略する既存のリクエストも引き続き使用できますが、`prompt` を追加すること自体は歌詞変更の成功を保証しません。
- `style`、`negative_tags`：任意のスタイル説明と除外項目。`prompt` はこの操作では通常の楽曲制作時のインスピレーション説明ではありません。
- `replace_section_start`、`replace_section_end`：今回の元楽曲における選択区間の開始・終了時間。単位は秒で、小数をサポートします。開始点は 0 未満にできず、終了点は開始点より大きく、かつ元楽曲の長さを超えてはなりません。
- `replace_section_result_mode`：`full_song`（デフォルト）は 2 曲の完全な楽曲を返します。`candidates` はまだ結合されていない 2 つの置換候補を返します。

「`lyric` は置換後の完全な歌詞である必要があり、`prompt` は局所的な歌詞である必要がある」を一般的な使い方として扱わないでください。完全な歌詞の入力は、一部のタスクで置換内容が長くなりすぎ、結合後に曲全体が著しく長くなる場合があります。局所的な入力でも、固定の長さや歌詞の一字一句への追従は保証されません。これは生成的編集であり、実際の音声を確認する必要があります。

### タスクを開始して完全な楽曲を取得する

以下はリクエスト形式の例です。`YOUR_COMPLETED_AUDIO_ID` と時間区間を自身の元楽曲 ID と実際の選択区間に置き換えてください。この例では、30～50 秒が以下の 4 行に対応すると仮定しています。

```json
{
  "action": "replace_section",
  "audio_id": "YOUR_COMPLETED_AUDIO_ID",
  "model": "chirp-v6",
  "custom": false,
  "instrumental": false,
  "lyric": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "prompt": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "replace_section_start": 30.0,
  "replace_section_end": 50.0,
  "replace_section_result_mode": "full_song",
  "async": true
}
```

送信後、返された `task_id` を使用して `/suno/tasks` を照会します。リクエスト本文は `{"action":"retrieve","id":"YOUR_TASK_ID"}` です。タスク完了後、タスク応答の `response.data` から 2 曲の完全な楽曲の `id`、`audio_url`、`duration` を取得し、試聴後にそのうち 1 曲を選択します。`success: true` はタスクの実行成功を示し、新しい歌詞が一字一句歌われたことや、長さが想定どおりであることを意味するものではありません。

### 選択区間、結果確認、および再編集

1. まず元楽曲を試聴し、その後 `/suno/timing` の時間情報と組み合わせて選択区間を決定し、できるだけ完全なフレーズをカバーしてください。歌詞配列の固定インデックスで選択区間を決めないでください。また、数行の歌詞でより多くのフレーズを含む区間を置換し、リズムが完全に変わらないと期待しないでください。
2. 新しい歌詞の行数、文字数、リズムは、選択区間の元の内容にできるだけ近づけてください。数文字だけ変更する場合でも、試聴による検証が必要であり、それによって成功を保証することはできません。
3. 対象区間で新しい歌詞が歌われているか、前後の接続が自然か、曲全体の長さが妥当かを確認してください。`full_song` は完全な楽曲が返されることを意味し、元曲と同じ長さであることを意味しません。置換片が長くなると、後半部分もそれに応じて後ろへずれます。`duration` リクエストパラメータは通常の生成にのみ使用され、置換片の長さを固定することはできません。
4. 返される `lyric` は歌詞メタデータです。完全な楽曲モードでは、元の歌詞の時間情報を取得できる場合に完全な歌詞が組み合わされます。取得できない場合は空になることがあります。これは音声の文字起こしではなく、新しい歌詞が表示されていても、音声で新しい歌詞が歌われていることの証明にはなりません。時間アラインメント情報も試聴と併せて確認してください。特に、すでに編集された生成物については注意が必要です。
5. 再編集時は、選択した**完全な完成品 ID** を新しい `audio_id` として使用し、その完成品の長さと選択区間をあらためて確認してください。編集前の時間座標をそのまま使わないでください。また、前回返された曲全体の `lyric` を今回の局所的な入力として直接使用しないでください。

タスクが完了しても古い歌詞が歌われる、歌詞が抜ける、または著しく長くなる場合は、まず元楽曲 ID、選択区間、局所的な歌詞を確認し、次にもう一方の結果を確認してください。タスク照会頻度を増やしても、すでに生成された内容は変わりません。それでも異常が続く場合は、`task_id`、元楽曲 ID、リクエストフィールド、選択区間、および結果音声を保持しておくと、確認に役立ちます。

### 任意：先に候補を取得し、その後手動で結合する

置換候補を自分で選択する必要がある場合にのみ、`replace_section_result_mode: "candidates"` を設定してください。候補にはコンテキストが含まれる場合があり、候補の長さだけで完全な楽曲として扱うことはできません。選定後、候補の `data[].id` を用いて `concat` を呼び出し、その後に完全な完成品を取得します。

デフォルトの `full_song` はすでに結合を完了しているため、この手順を実行する必要はありません。

## ボーカル・伴奏分離

課金：`action=stems` が成功した後、各リクエストの標準料金は **0.56 Credits** です。同一リクエストで返されるボーカルと伴奏は合わせて 1 回として計上されます。適用される消費割引は実際の請求額に従い、失敗したリクエストは課金されません。`all_stems` と `extract_stem` はそれぞれの価格に従って課金されます。

楽曲生成後、伴奏とボーカルを個別に扱う二次創作を行う必要がある場合、インストゥルメンタル伴奏とアカペラボーカルを分離できます。以下の内容を指定できます：

- action：内容は `stems`。
- audio_id：以前に生成した楽曲の ID。

```json
{
  "action": "stems",
  "audio_id": "ec13e502-d043-4eb2-92ee-e900c6da69d1"
}
```

```json
{
  "action": "all_stems",
```

## 曲の長さを制御する

デフォルトでは、生成される曲の長さはモデルによって決定され、通常は 30 秒から 4 分の間です。より長い、またはより短い完成品が必要な場合は、`duration` パラメータで期待する長さを指定できます。単位は秒で、値は 10 から 360 の間の整数です。

このパラメータは、カスタムモード（`custom` が `true`）での曲生成に使用されます。特に説明が必要なのは、`duration` は**傾向を示すヒントであり、厳密な制約ではない**ということです：モデルは作成時にこの値を参照しますが、到達することを保証しません。実測では実際の長さは通常、期待値よりも明らかに短く、同一リクエストで返される 2 曲の長さも数倍異なる場合があります。完全に同一のリクエストであっても、複数回送信して得られる長さには大きな差が生じる可能性があります。そのため、これを正確な長さの制御として使用しないでください。業務上固定の長さが必要な場合は、完成品を取得した後に自らトリミングするか、再試行してください。

対応する Python コード：

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

注意が必要なのは、リクエスト内の `duration` は**期待する長さ**であり、レスポンス `data` 内の各曲の `duration` フィールドはその曲の**実際の長さ**です。両者は同じ名前ですが意味が異なり、実際の長さが期待値と等しくなることは保証されません。歌詞の長さは完成品の長さに影響する主な要因の一つであり、より長い完成品が必要な場合は、より完全な歌詞を同時に提供することを推奨します。

インターフェースは、`duration` が 10 から 360 の整数であることを検証します；これは依然として生成の目標にすぎず、完成品の長さを保証するものではありません。

## Inspo インスピレーション創作機能

Inspo インスピレーション創作機能は、1～4本の完全な参照音声に基づいて新しい音楽を生成でき、音声をドラッグ＆ドロップまたはアップロードしてインスピレーションソースとして使用できます。API は既存の `inspo` action を使用します。クライアントは公開アクセス可能な音声 URL を提供し、サービスが参照音声の準備と創作を自動的に完了するため、クライアントが歌詞、スタイル、または長さを個別に読み取ってリクエストを組み立てる必要はありません。これは上記の区間サンプリングとも、原曲のスタイルを再現する Cover とも異なります。使用時には以下のパラメータを指定する必要があります。

- action：内容は `inspo`。
- audio_urls：参照音声の URL リスト。公開アクセス可能な音声アドレスを1～4件提供する必要があります。
- model：使用するモデル。`chirp-v6` を推奨します。
- prompt：歌詞または創作プロンプト（任意）。
- instrumental：`true` に設定した場合、歌詞を使用せずインストゥルメンタルとして生成をリクエストします。
- persona_id：この組み合わせをサポートするサービスチャネルで指定した声を使用します。参照音声は準備段階で、その声に必要なリソース環境にバインドされます。
- lyric_prompt：`custom=true` かつ `lyric` が提供されていない場合に、歌詞を自動生成するために使用します。

> 説明：参照音声は公開アクセス可能な音声ファイルである必要があります。参照音声がプラットフォームの楽曲ライブラリ内の既知の録音と完全に一致する場合、Suno は著作権チェックにより生成を拒否する可能性があります。自作の音声、または Suno によって生成された音声をインスピレーションソースとして使用することを推奨します。

対応する Python コード：

```python
url = "https://api.acedata.cloud/suno/audios"

headers = {

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
```

## 非同期コールバック

Suno による音楽生成には比較的長い時間がかかり、およそ 1～2 分必要です。API が長時間応答しない場合、HTTP リクエストは接続を維持し続けるため、追加のシステムリソースを消費します。そのため、本 API では非同期コールバックもサポートしています。

全体のフローは以下のとおりです。クライアントがリクエストを開始する際に、追加で `callback_url` フィールドを指定します。クライアントが API リクエストを開始すると、API はすぐに結果を返します。結果には現在のタスク ID を表す `task_id` フィールド情報が含まれます。タスクが完了すると、生成された音楽の結果は POST JSON 形式でクライアントが指定した `callback_url` に送信され、その中にも `task_id` フィールドが含まれるため、タスク結果を ID によって関連付けることができます。

以下の例で、具体的な操作方法を確認しましょう。

まず、Webhook コールバックは HTTP リクエストを受信できるサービスです。開発者は自身で構築した HTTP サーバーの URL に置き換える必要があります。ここではデモの便宜上、公開 Webhook サンプルサイト https://webhook.site/ を使用します。このサイトを開くと、図のように Webhook URL を取得できます。

![](https://cdn.acedata.cloud/fwfqin.png)

この URL をコピーすると、Webhook として使用できます。ここでのサンプルは https://webhook.site/03e60575-3d96-4132-b681-b713d78116e2 です。

次に、フィールド `callback_url` を上記の Webhook URL に設定し、同時に `prompt` を入力します。図のとおりです。

```json
  "success": false,
```
