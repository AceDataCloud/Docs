AI の応用が広がるにつれ、さまざまな AI プログラムが徐々に普及しています。AI は人々の仕事や生活のあらゆる側面に徐々に浸透しています。また、AI が関わる業界もますます増えており、初期の執筆から医療・教育、そして現在の音楽にまで及んでいます。

Suno は、専門的で高品質な AI 楽曲・音楽制作プラットフォームです。ユーザーは簡単なテキストプロンプトを入力するだけで、ジャンルスタイルや歌詞に基づいてボーカル付きの楽曲を生成できます。この AI 音楽生成器は、Meta、TikTok、Kensho などの著名なテクノロジー企業出身のチームメンバーによって開発されており、いかなる楽器ツールも必要とせず、すべての人が素晴らしい音楽を作れるようにすることを目標としています。

> 上表の `lyric` と `style` の制限は、カスタムモード（`custom` が `true`）における上限です。非カスタムのインスピレーションモード（`custom` が `false`）では `prompt` のみを入力し、その長さの上限は 500 文字です（すべてのモデルで共通）。

Suno は現在、`chirp-v6`、`chirp-v6-wild`、および `chirp-v6-mini` をサポートしています。`chirp-v6` の使用を推奨します。旧モデル名も引き続き互換性があります。

しかし、Suno 公式は API を提供していません。AceDataCloud は Suno の API セットを提供しており、Suno 公式との連携をシミュレートして、必要な音楽を簡単かつ迅速に生成できます。

## 申請と使用

Suno Audios Generation API を使用するには、まず [Ace Data Cloud コンソール](https://platform.acedata.cloud/console/applications) にアクセスして、予備として API Token を取得してください。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

まだログインまたは登録していない場合は、自動的にログインページへ移動し、登録とログインを促されます。完了後、自動的に現在のページへ戻ります。

**1 つの API Token でプラットフォーム上のすべてのサービスを呼び出すことができ、サービスごとに個別申請する必要はありません。** 初回申請時には無料枠が付与され、無料で体験できます。枠が不足した場合は、[コンソール](https://platform.acedata.cloud/console/coin) で共通残高をチャージできます。

> 📘 完全なドキュメント：[Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## 基本的な使用方法

どのような楽曲を考えていても、任意の文章を入力できます。たとえば、クリスマスに関する楽曲を生成したい場合は、`a song for Christmas` と入力できます。下図のとおりです：

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

ここでは Request Headers を設定していることがわかります。内容は以下のとおりです：

- `accept`：受け取りたいレスポンス結果の形式です。ここでは `application/json`、つまり JSON 形式を入力します。
- `authorization`：API を呼び出すためのキーです。申請後、直接ドロップダウンから選択できます。

さらに Request Body を設定します。内容は以下のとおりです：
- `action`：オーディオタスクの種類。デフォルトは `generate`。生成、継続、カバー、マッシュアップ、ステム分離、オーディオトラック追加、指定オーディオトラック抽出、効果音生成、速度調整などの操作をサポートし、すべて `POST /suno/audios` を通じて呼び出します。
- `prompt`：Suno 公式のインスピレーションモードのプロンプト（`custom` が `false` の場合に有効）。最大 500 文字。
- `model`：今回の音楽生成タスクのモデル。v6 シリーズには `chirp-v6`、`chirp-v6-wild`、`chirp-v6-mini` が含まれます。旧モデル名も引き続き互換性があります。
- `max_mode`：強化生成モード。`generate` は `custom` と `max_mode` がともに `true` の場合にのみ有効になり、料金は 1.12 Credits です。`add_stem` は直接有効にでき、料金は 1.344 Credits です。無効または省略時は、それぞれ 0.56 および 0.672 Credits です。
- `variety`：生成結果の多様性の強度。`off`、`normal`、`high`、`extra`、`max` から選択可能。`generate` と `add_stem` にのみ使用され、その他の action で渡すと 400 が返されます。
- `lyric`：Suno 公式のカスタムモードの歌詞内容。`chirp-v3-5` と `chirp-v4` は最大 3000 文字、`chirp-v4-5` 以降（`chirp-v5`、`chirp-v5-5` を含む）は最大 5000 文字。
- `custom`：カスタムモードを使用するかどうか。デフォルトは: `false`。
- `instrumental`：Suno 公式のインスピレーションモードのインストゥルメンタルオプション。
- `title`：Suno 公式のカスタムモードの音楽タイトル。`chirp-v3-5`、`chirp-v4` は最大 80 文字、`chirp-v4-5` 以降は最大 100 文字。
- `style`：Suno 公式のカスタムモードの音楽スタイル。`chirp-v3-5` と `chirp-v4` は最大 200 文字、`chirp-v4-5` 以降（`chirp-v5`、`chirp-v5-5` を含む）は最大 1000 文字。
- `negative_tags`：カスタム生成時に除外したい音楽スタイルまたはジャンル。`replace_section` にも使用できます。本インターフェースでは現在、このフィールドに固定の文字数上限は設定されていません。内容が長すぎる場合は処理できない可能性があるため、説明は簡潔に保つことを推奨します。
- `audio_weight`：オーディオまたは音声特徴の影響ウェイト。範囲は 0～1 で、`0` も有効な値です。生成、継続、カバー、オーディオトラック追加、音声一貫性などの操作に使用できます。参照オーディオまたは音声特徴がない場合、モデルはこの値を弱める、または無視する可能性があります。
- `audio_id`：参照音楽の ID。カバー、継続、ステム分離などの後続操作に使用します。オーディオファイルは引き続きダウンロードできる場合でも、その ID の後続処理が常に利用可能であることを意味しません。`suno_processing_unavailable` が返された場合は、`task_id` と `trace_id` を保存してサポートにお問い合わせください。
- `overpainting_start`/`overpainting_end`：既存のインストゥルメンタル音楽にボーカルを追加する開始・終了時間。単位は秒。
- `underpainting_start`/`underpainting_end`：アカペラに伴奏を追加する開始・終了時間。単位は秒。
- `persona_id`：Persona または音声作成インターフェースを通じて取得した音声 ID であり、楽曲の `audio_id` ではありません。
- `continue_at`：継続の境界。単位は秒。たとえば、213.5 は 3 分 33.5 秒の位置から後続セグメントの生成を開始することを示します。`lyric` と `style` は境界以降の新しい内容のみを誘導し、元のオーディオ内の境界以前の歌詞または歌唱を置き換えることはありません。
- `style_influence`：カスタムモードでのスタイル影響力。範囲は 0～1 で、値が大きいほど通常は選択したスタイルにより適合します。`0` も有効な値として渡されます。
- `replace_section_end`：置換セグメントの最終時間。
- `replace_section_start`：置換セグメントの開始時間。
- `vocal_gender`：男女ボーカルの好みを制御します。女性ボーカルは `f`、男性ボーカルは `m`。4.5 以降のモデルで有効です。あくまで優先項目であり、厳密な遵守は保証されません。
- `weirdness`：カスタムモードでの奇抜さ。範囲は 0～1 で、値が大きいほど通常はより創造的かつ実験的になります。`0` も有効な値として渡されます。
- `duration`：希望する楽曲の長さ。単位は秒で、整数である必要があり、値の範囲は 10～360 です。現在、このパラメータを使用するのは `generate` のみで、具体的な効果はモードとモデルによって異なります。これは厳密な制約ではなく傾向を示すプロンプトです。モデルはこれを参照しますが、達成を保証するものではありません。実際の完成曲の長さはレスポンス内の `duration` フィールドに従い、通常は希望値より短くなります。

### 音声 ID の適用範囲

`generate`、`cover`、`upload_cover`、`artist_consistency`、`artist_consistency_vox` は `persona_id` を使用できます。後者 2 つの action では `persona_id` の提供が必須です。これらの Persona 作成時に使用した楽曲の `audio_id` も同時に提供できます。

`extend`、`upload_extend` では追加の `persona_id` を使用しません。`mashup`、`inspo` が音声 ID をサポートするかどうかは、選択したサービスチャネルによって異なります。その他の action でこのフィールドが適用される保証はないため、各操作の説明に従って使用してください。`vocal_gender` は任意の性別の好みであり、音声 ID の代わりにはなりません。

後続の作成操作には有効なソース `audio_id` が必要です。`mashup` には少なくとも 2 つの `mashup_audio_ids` が必要です。必要なソースまたは時間パラメータが不足している場合、HTTP 400 が返されます。

### 高度なパラメータの適用範囲
| パラメータ                | 値                                          | サポートする action                              | 説明                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | 任意                                      | 実験性を調整する。`0` は有効な値である。効果は操作、モード、モデルに依存する      |
| `style_influence` | 0-1                                         | 任意                                      | スタイル追従の傾向を調整する。`0` は有効な値である。効果は操作、モード、モデルに依存する   |
| `audio_weight`    | 0-1                                         | 任意                                      | 音声またはサウンド特性の影響を調整する。参照情報がない場合、モデルに無視される可能性がある        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`、`add_stem`                   | 結果間のスタイルの多様性を調整する                       |
| `max_mode`        | boolean                                     | `generate`（`custom=true` が必要）、`add_stem` | 一貫性を強化し、強化モードとして課金される                     |
| `vocal_gender`    | `f` / `m`                                   | ボーカル制御をサポートする生成操作                             | 優先項目であり、厳密な追従は保証されない                       |
| `duration`        | 整数 10-360                                   | `generate`                              | 希望する長さ。他の action は現在このフィールドを使用せず、実際の長さは結果に準拠する |

プラットフォームはパラメータの型と数値範囲を検証しますが、action が異なることだけを理由にこれらの任意調整項目を拒否することはありません。具体的な効果は、操作、モード、モデルによって決まります。

- `lyric_prompt`：歌詞を生成するための prompt。`custom` が `true` であり、かつ `lyric` が渡されていない場合にのみ有効です。
- `callback_url`：結果のコールバックが必要な URL。
- `async`：任意。`true` に設定すると、インターフェースは直ちに `task_id` を返します。`callback_url` を提供する必要はなく、その後対応するタスク照会インターフェースを通じてポーリングし、結果を取得します。

## カスタム生成

歌詞をカスタム生成したい場合は、歌詞を入力できます：

この場合、`lyric` フィールドには以下のような内容を渡すことができます：
```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> 注意：ここでの歌詞内の `\n` は改行文字です。歌詞の生成方法が分からない場合は、AceDataCloud が提供する歌詞生成 API を使用して、prompt から歌詞を生成できます。API は [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics) です。

次に、歌詞、タイトル、スタイルに基づいてカスタムで曲を生成する場合は、以下の内容を指定できます。

- lyric：歌詞テキスト
- custom：`true` を設定します。カスタム生成を表します。このパラメータのデフォルトは false で、`prompt` を使用した生成を表します。
- title：曲のタイトル。
- style：曲のスタイル。任意。

入力例は以下のとおりです。

<p><img src="https://cdn.acedata.cloud/qp3iba.png" width="500" className="m-auto" /></p>

入力が完了すると、以下のコードが自動生成されます。

対応するコード：

```shell
curl -X POST 'https://api.acedata.cloud/suno/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "A song for Christmas",
  "model": "chirp-v4-5",
  "lyric": "[Verse]\\nSnowflakes falling all around\\nGlistening white\\nCovering the ground\\nChildren laughing\\nFull of delight\\nIn this winter wonderland tonight\\nSanta's sleigh\\nUp in the sky\\nRudolph's nose shining bright\\nOh my\\nHear the jingle bells\\nRinging so clear\\nBringing joy and holiday cheer\\n[Verse 2]\\nRoasting chestnuts by the fire's glow\\nChristmas lights\\nThey twinkle and show\\nFamilies gathering with love and cheer\\nSpreading warmth to everyone near",
  "custom": true
}'
```

テストは許可されており、生成結果は類似したものになります。

## カスタム歌手スタイル生成機能

歌手スタイルを使用して曲を生成したい場合は、まず上記の基本的な使用方法で1曲生成し、

## 続きの生成機能
すでに生成された Suno の楽曲を継続生成したい場合は、パラメータ `action` を `extend` に設定し、継続生成したい楽曲の ID を入力できます。楽曲 ID の取得は基本的な使用方法に従って取得し、上記から、このとき楽曲の ID が以下であることを確認できます。

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> 注意：ここでの歌詞中の `id` は生成後の楽曲の ID です。楽曲の生成方法がわからない場合は、上記の基本的な使用方法を参照して楽曲を生成できます。

自分でアップロードした楽曲を継続生成したい場合は、パラメータ `action` を `upload_extend` に設定し、継続生成したいカスタムアップロード楽曲の ID を入力できます。楽曲 ID の取得には [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload) を使用します。以下の図のとおりです。

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

次に、継続するセグメントの歌詞を必ず入力する必要があり、スタイルも指定できます。

- lyric：`continue_at` より後に新しく生成されるセグメントの歌詞を導くためにのみ使用され、元の音声内におけるこの時点より前の歌詞は置き換えられません。
- custom：`true` を入力するとカスタム生成を表します。このパラメータのデフォルトは false であり、`prompt` を使用した生成を表します。
- style：継続するセグメントの楽曲スタイル。任意です。
- continue_at：継続境界。単位は秒です。たとえば、213.5 は 3 分 33.5 秒の位置から後続セグメントの生成を開始することを表します。

`extend` と `upload_extend` の `continue_at` は 0 より大きくなければならず、`30.792` のような小数秒をサポートします。送信時に丸められることはありません。

> `extend` は既存の楽曲に続けて後ろへ創作するためのものであり、楽曲全体の歌詞を置き換えるものではありません。楽曲全体を最初から新しい歌詞で作成したい場合は、`generate` を使用して再生成してください。既存の楽曲を参考にして再演したい場合は、`cover` を使用できます。新しい歌詞全体を渡した場合でも、`continue_at` より前の元の歌詞は置き換えられません。

- action：内容は `cover`。カスタムアップロードした音楽に対してカバー操作を行う場合は、内容を必ず `upload_cover` と指定してください。

## 片段の置換

曲を生成した後、曲の片段を置換する個別操作として二次創作を行う必要がある場合は、曲のある片段に対して置換操作を行うことができます。
> ⚠️ **注意**：`replace_section_result_mode` のデフォルトは `full_song` です：システムは新しく生成された 2 つの候補をそれぞれ連結し、2 曲の完全な楽曲を返します。まだ連結されていない置換セグメント候補のみが必要な場合は、明示的に `candidates` に設定してから、候補を選んで[音楽の連結](#音楽の連結)を呼び出してください。

パラメータの説明は以下のとおりです：

- action：内容は `replace_section`。
- audio_id：元の楽曲（置換される元楽曲）の ID。
- model: 楽曲生成モデル。
- lyric: 置換後の完全な歌詞（置換されるセグメントおよびそのコンテキストを含み、`prompt` 内の内容と一致させる）。
- prompt：置換するそのセグメントの新しい歌詞。
- style：楽曲のスタイル、任意。
- negative_tags：除外したいスタイルまたはジャンル、任意。
- replace_section_start：置換されるセグメントの元曲内での開始時間（秒）。必須であり、0 未満にはできません。
- replace_section_end：置換されるセグメントの元曲内での終了時間（秒）。必須であり、開始時間より大きくなければなりません。
- replace_section_result_mode：返却モード。デフォルトは `full_song`。`full_song` は 2 つの候補をそれぞれ連結して 2 曲の完全な楽曲を返します；`candidates` はまだ連結されていない 2 つの候補セグメントを返します。

```json

  "audio_id": "18db7ed0-2b8a-41db-91c1-b0781dcca0d4",

  "custom": false,
  "instrumental": false,
  "lyric": "[Intro]\n锣鼓喧天 红灯高挂\n[Verse 1]\n爆竹声声辞旧岁\n春风暖暖入万家\n红包压岁笑开颜\n金蛇起舞贺新春\n[Chorus]\n梅花绽放春意洋溢满地\n梅花绽放春意洋溢满地\n梅花绽放春意洋溢满地\n梅花绽放春意洋溢满地\n[Verse 2]\n饺子飘香年夜饭\n灯笼摇曳照团圆",
  "prompt": "梅花绽放春意洋溢满地\n梅花绽放春意洋溢满地\n梅花绽放春意洋溢满地\n梅花绽放春意洋溢满地",
  "replace_section_start": 30.0,
  "replace_section_end": 60.0,
  "replace_section_result_mode": "full_song"
}
```

デフォルトでは、2 つの候補をそれぞれ連結して完成した 2 曲の完全な楽曲が返されます。`replace_section_result_mode` を `candidates` に設定した場合は、まだ連結されていない 2 つの置換セグメントが返され、その構造は以下の例と一致します：

```json
{
  "success": true,
  "task_id": "dd067075-a295-4160-8375-d5504327d55b",
  "trace_id": "c34f589b-9195-4d0b-af78-9c890e77609c",
```

完全な楽曲を直接取得したい場合は、ステップ 1 で `replace_section_result_mode` を `full_song` に設定できます。インターフェースは 2 つの候補をそれぞれ連結して 2 曲の完全な楽曲を返します；この場合、`concat` を再度呼び出す必要はありません。

## 楽曲の長さを制御する

デフォルトでは、生成される楽曲の長さはモデルによって決定され、通常は30秒から4分の間です。より長い、またはより短い完成品が必要な場合は、`duration` パラメータで希望する長さを指定できます。単位は秒で、値は10から360までの整数です。

このパラメータは、カスタムモード（`custom` が `true`）での楽曲生成に使用されます。特に説明が必要なのは、`duration` は**傾向を示すヒントであり、厳密な制約ではない**ということです：モデルは作曲時にこの値を参照しますが、到達を保証するものではありません。実測では実際の長さは通常、希望値より明らかに短く、同一リクエストで返される2曲の長さも数倍異なる場合があります。完全に同じリクエストであっても、複数回送信して得られる長さには大きな差が出る可能性があります。したがって、これを正確な長さの制御として使用しないでください。業務上固定の長さが必要な場合は、完成品を取得した後に自分でトリミングするか、再試行してください。

対応する Python コード：

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

注意が必要なのは、リクエスト内の `duration` は**希望する長さ**であり、レスポンスの `data` 内にある各楽曲の `duration` フィールドはその楽曲の**実際の長さ**であることです。両者は同じ名前ですが意味は異なり、実際の長さが希望値と等しくなることは保証されません。歌詞の長さは完成品の長さに影響する主な要因の一つであり、より長い完成品が必要な場合は、より完全な歌詞も同時に提供することを推奨します。

インターフェースは `duration` が10から360までの整数であることを検証します；これは依然として生成目標にすぎず、完成品の長さを保証するものではありません。

## Inspo インスピレーション創作機能

Inspo インスピレーション創作機能では、1～4本の完全な参照音声に基づいて新しい音楽を生成できます。ドラッグ＆ドロップまたは音声のアップロードをインスピレーション元としてサポートしています。API は既存の `inspo` action を使用します。クライアントは公開アクセス可能な音声 URL を提供し、サービスが参照音声の準備と創作を自動的に完了するため、クライアント側で歌詞、スタイル、または長さをそれぞれ取得してリクエストを組み立てる必要はありません。これは上記の区間サンプリングとも、原曲のスタイルを再現する Cover とも異なります。使用時には次のパラメータを指定する必要があります：

- action：内容は `inspo`。
- audio_urls：参照音声の URL リスト。公開アクセス可能な音声アドレスを 1～4 個提供する必要があります。
- model：使用するモデル。`chirp-v6` を推奨します。
- prompt：歌詞または創作プロンプト（任意）。
- instrumental：`true` に設定すると、歌詞を使用せずインストゥルメンタルとして生成をリクエストします。
- persona_id：この組み合わせをサポートするサービスチャネルで指定した声を使用します。参照音声は準備段階で、その声に必要なリソース環境にバインドされます。
- lyric_prompt：`custom=true` かつ `lyric` が提供されていない場合に、歌詞を自動生成するために使用します。

> 注：参照音声は公開アクセス可能な音声ファイルである必要があります。参照音声がプラットフォームの楽曲ライブラリ内の既知の録音と完全に一致する場合、Suno は著作権チェックにより生成を拒否する可能性があります。独自の音声、または Suno によって生成された音声をインスピレーション元として使用することを推奨します。

対応する Python コード：

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## 非同期コールバック

Suno による音楽生成には比較的長い時間がかかり、およそ 1～2 分必要です。API が長時間応答しない場合、HTTP リクエストは接続を維持し続け、追加のシステムリソースを消費することになります。そのため、本 API では非同期コールバックもサポートしています。

全体のフローは次のとおりです。クライアントがリクエストを開始する際に、追加で `callback_url` フィールドを指定します。クライアントが API リクエストを開始した後、API はすぐに `task_id` フィールド情報を含む結果を返します。これは現在のタスク ID を表します。タスクが完了すると、生成された音楽の結果は POST JSON の形式でクライアントが指定した `callback_url` に送信され、その中にも `task_id` フィールドが含まれます。これにより、タスク結果を ID によって関連付けることができます。

以下では、例を通じて具体的な操作方法を見ていきます。

まず、Webhook コールバックは HTTP リクエストを受信できるサービスです。開発者は自身で構築した HTTP サーバーの URL に置き換える必要があります。ここではデモの便宜上、公開 Webhook サンプルサイト https://webhook.site/ を使用します。このサイトを開くと、図のように Webhook URL を取得できます。

![](https://cdn.acedata.cloud/fwfqin.png)
