`POST https://api.acedata.cloud/suno/projects` は、マルチトラックプロジェクトを管理するための Beta インターフェースです。`action` によって作成、保存、候補生成、候補のコミット、エクスポートを区別します。

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: <每次写操作的新 UUID>
```

`retrieve` を除き、**すべての操作で** `Idempotency-Key` が必要です。同じキーかつ同じリクエストの場合は元の結果のみが再取得され、同じキーで異なるリクエストの場合は 409 が返されます。課金対象の生成でネットワークタイムアウトまたはコミット結果が不明な場合は、まず元のタスク ID または同じ冪等キーで照会し、直接キーを変更して再送してはいけません。

## 識別子と時間単位

| 名称                             | 取得元                                                                                      | 使用先                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | `create` レスポンスの `data.id`                                                               | 現在のプロジェクトに対するすべての後続リクエスト                           |
| `version_id`                   | 直近の `retrieve`、`save`、`add_track`、`commit_candidate` または `remove_track` の `data.version_id` | 変更、候補生成、エクスポート。必ず最新バージョンを使用                        |
| `audio_id` / `source_audio_id` | `upload` の終端状態における `response.data.candidate.audio_id`、または既存の完了済み音声 ID                          | `add_track`、生成、または置換時に元音声を参照                        |
| `render_audio_id`              | `render` の終端状態における `response.data.audio_id`                                                       | `generate_track` のプロジェクトミックス参照                         |
| `operation_id`                 | `generate_track` または `replace_section` の終端状態における `response.data.operation_id`                       | `commit_candidate`。通常は生成タスクの `task_id` と同じですが、返却値を読み取る必要があります |
| `candidate_id`                 | 生成終端状態における `response.data.candidates[].id`                                                       | コミットする候補を選択                                         |
| `track_id`                     | プロジェクトの `data.state.tracks[].id`                                                                | 候補のコミットまたはトラックの削除                                        |
| `task_id`                      | 非同期操作の送信レスポンス                                                                                   | `/suno/tasks` を使用して終端状態を照会。これはプロジェクト ID ではありません                   |

`start_seconds` / `end_seconds` は**元音声内の秒数**です。`start_beats` / `end_beats` は**プロジェクトタイムライン上の拍数**です。`state.timing.bps` は 1 秒あたりの拍数で、デフォルトは 2 です。たとえば、41 秒のクリップが第 0 拍から始まる場合、デフォルトの終点は第 82 拍です。`generate_track` の秒数範囲は生成参照を指定するために使用され、候補がその範囲だけの長さであることを保証するものではありません。

## 操作フロー

| 順序  | `action`                             | 役割                         | 返却方法         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | 空のプロジェクトを作成                      | 同期プロジェクトデータ       |
| 2   | `retrieve`                           | 最新バージョンと完全な `state` を取得          | 同期プロジェクトデータ       |
| 3   | `save`                               | 初回保存または変更後の `state` 全体を保存      | 同期プロジェクトデータ       |
| 4   | `upload`                             | HTTPS 音声アドレスから素材を作成           | 非同期タスク         |
| 5   | `add_track`                          | 素材音声をプロジェクトに配置                  | 非同期タスク、バージョン更新    |
| 6   | `save`                               | 新しいトラック候補を受け取る必要がある場合、先に空の対象トラックを保存        | 同期プロジェクトデータ、バージョン更新  |
| 7   | `render`                             | 現在再生可能なトラックをエクスポートし、ミックス参照 `audio_id` を取得 | 非同期タスク         |
| 8   | `generate_track` または `replace_section` | それぞれ新しいトラック候補または部分置換候補を生成            | 非同期タスク、プロジェクトはまだ変更しない  |
| 9   | `commit_candidate`                   | 候補を 1 つ選択してコミット                  | 非同期タスク、成功後にバージョン更新 |
| 任意  | `remove_track`                       | 指定トラックを削除                     | 同期プロジェクトデータ、バージョン更新 |

部分置換のみを行う場合、利用可能な元音声がすでにあれば、先に `render` を行う必要はありません。元音声がすでにプロジェクト内にある場合は、`upload` と `add_track` も省略できます。`render_audio_id` は `generate_track` 専用の必須参照です。

非同期操作の送信時には、まず `{ "task_id": "...", "trace_id": "..." }` が返されますが、**これは生成の成功を意味しません**。ポーリング：

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步返回的 task_id"}
```

タスクレコードに `finished_at` があり、その中の `response.success` が `true` である場合にのみ成功とみなされます。`response.success=false` の場合は `response.error` を読み取ります。`save` には `task_id` が含まれる場合がありますが、このインターフェース内では同期的に完了します。`upload`、`render`、`generate_track`、`replace_section` はプロジェクトバージョンを変更しません。`save`、`add_track`、`commit_candidate`、`remove_track` の成功後は、新しい `version_id` を取得する必要があります。

## リクエスト規約

| パラメータ                | 型と適用範囲                                                                                   | 説明                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | 必須文字列                                                                                     | 本ページに記載された操作名のいずれかに固定されます。1 回のリクエストで実行できる操作は 1 つだけです。                                      |
| `id`              | `create` を除き必須文字列                                                                         | プロジェクト ID。`create.data.id` から取得します。                                      |
| `version_id`      | 変更、候補生成、エクスポート時は必須文字列。初回の空プロジェクト `save` では省略可能                                                         | 最新バージョンを使用します。古いバージョンは拒否されます。`retrieve` には不要です。                                 |
| `Idempotency-Key` | `retrieve` を除き必須リクエストヘッダー、1～128 文字                                                              | 新しい操作ごとに新しいキーを使用します。同じキーかつ同じリクエストでは元の結果を再取得し、再生成または課金は行われません。                                   |
| `async`           | `upload`、`add_track`、`generate_track`、`replace_section`、`commit_candidate`、`render` で任意の真偽値 | これらの操作は常に非同期です。`false` でも生成が同期に変わることはありません。                                    |
| `callback_url`    | 非同期操作で任意の URL                                                                                | 終端状態の通知を受信します。省略した場合は `task_id` により `/suno/tasks` を照会します。引き続き `response.success` を確認する必要があります。 |

以下の例は、各操作間における ID とバージョンの引き渡しを連続して示しています。レスポンスには現在のステップに関係するフィールドのみを記載しています。統合時には、現在のアプリケーションのレスポンス値で例の ID を置き換えてください。

## プロジェクト状態を保存

| パラメータ | 型と説明 |
|---|---|
| `state` | 必須オブジェクト。部分パッチではなく、**完全なプロジェクト状態**を送信します。直近の読み取りまたは変更操作で返された `data.state` を基にし、不明なフィールドを保持します。 |
| `title` | 任意の文字列。省略時は `state.title` を引き継ぎ、それもない場合はデフォルトのタイトルを使用します。 |
| `version_id` | 初回保存で新しい空のプロジェクトを作成する場合は省略できます。その後は最新バージョンを使用する必要があります。 |

`state.timing.bps` は正の数でなければならず、デフォルトは 2 です。`state.tracks` はトラック配列です。既存のオーディオクリップの `clipId` はオーディオ ID を参照し、`startBeats`、`endBeats`、`readStartBeats` はプロジェクトの拍単位を使用します。最も安全な編集方法は、完全な `state` を読み取り、対象のトラックまたはクリップのみを変更してから、全体を `save` することです。新しい空のターゲットトラックには、少なくとも一意の `id`、`type:"audio"`、`clips:[]` が必要です。完全な空トラック構造については、「新しいオーディオトラックを生成」の例を参照してください。オーディオ分析結果の拍点を直接プロジェクトタイムライン座標として使用しないでください。

## オーディオをアップロードしてトラックを追加

| 操作 | パラメータ | 型と説明 |
|---|---|---|
| `upload` | `audio_url` | 必須の HTTPS URL。公開アクセス可能で、かつ使用権限を持つオーディオを指します。最終状態の `candidate.audio_id` はトラックの追加に使用できます。 |
| `add_track` | `audio_id` | 必須文字列。URL ではなく、処理済み素材のオーディオ ID です。 |
| `add_track` | `name`、`color` | 任意の文字列。トラック名はデフォルトでオーディオタイトルになり、色は `#RRGGBB` を推奨し、デフォルトは `#7251F7` です。 |
| `add_track` | `title` | 任意の文字列。同時にプロジェクトタイトルを変更します。通常は省略します。 |
| `add_track` | `start_beats`、`end_beats` | 任意の非負数。終点は始点より大きくなければなりません。デフォルトでは 0 拍目から開始し、終点はオーディオの長さと `timing.bps` に基づいて計算されます。 |
| `add_track` | `gain` | 任意の非負数。デフォルトは 1 です。クリップおよびトラックの音量係数です。 |

## 新しいオーディオトラックを生成

候補と生成時のプロジェクトバージョンは紐付けられます。まず候補を受け取る空のトラックを保存し、次に現在のミックスを生成参照用としてエクスポートします。生成完了後、候補を 1 つ選んでその空トラックに送信します。

### ターゲットトラックを予約：`save`

`generate_track` の候補は現在のプロジェクトバージョンに紐付けられます。前の `add_track` の最終状態で返された**完全な** `state` に以下の空トラックを `state.tracks` へ追加してから、`save` で保存します。他の既存フィールドはそのまま保持します：

### 候補の生成：`generate_track`

| パラメータ | 型と説明 |
|---|---|
| `source_audio_id` | 必須；完了済みのソースオーディオ ID。まずソースオーディオをプロジェクトに追加し、その後で候補の位置を確定できる。 |
| `render_audio_id` | 必須；上記 `render` 終端状態の `response.data.audio_id` であり、オーディオ URL ではない。 |
| `model` | 必須；`chirp-v3-5`、`chirp-v4`、`chirp-v4-5`、`chirp-v4-5-plus`、`chirp-v5`、`chirp-v5-5`、`chirp-v6`、`chirp-v6-wild`、`chirp-v6-mini` から選択可能。具体的な組み合わせが利用可能かどうかはタスク終端状態に従う。 |
| `start_seconds`、`end_seconds` | 必須数値、`0 ≤ start_seconds < end_seconds`；ソースオーディオ内の秒数区間であり、プロジェクトの拍数ではなく、出力時間も保証されない。 |
| `stem_control_tags` | 必須文字列；`add Piano`、`add Drums`、`add Bass` などの追加パートの説明であり、固定列挙ではない。 |
| `batch_size` | 任意の整数 1～4、デフォルトは 2；候補数。 |
| `instrumental`、`vocal_gender` | 任意；インストゥルメンタルのデフォルトは `true`、ボーカルの好みには `f`、`m`、`unspecified` を指定でき、デフォルトは `unspecified`。 |
| `title`、`tags`、`negative_tags`、`prompt` | 任意文字列；それぞれ候補タイトル、期待するスタイル、避けるスタイル、新しいパートのテキストまたは歌詞プロンプト。 |

```

&#123;
"action": "generate_track",
"id": "af0e104a-2a4c-40e0-9c70-7614566824a6",
"version_id": "cb0a82c9-aa5b-48cc-9395-0528675fc18d",

## エラーと復旧

| 結果 | 意味 | 次の手順 |
|---|---|---|
| `project_version_conflict` / `project_candidate_stale`（409） | 工程バージョンが変更された、または候補が現在のバージョンに属していません。 | 最新の工程を `retrieve` し、変更を再計画してください。古い候補を再実行しないでください。 |
| `bad_request` / `studio_state_invalid` / `studio_model_unsupported`（通常 400） | パラメータ、トラック状態、候補の長さ、またはモデルが操作と一致していません。 | タスク終端状態のエラーを確認し、入力を修正してください。候補を安全に結合できない場合は、元の工程を保持してください。 |
| `studio_audio_unavailable` / `studio_access_denied` / `content_rejected`（403） | 参照音声がその工程操作に利用できない、アクセス権がない、またはコンテンツチェックで拒否されました。 | 音声の出所とタスクの `trace_id` を確認してください。すでに生成された候補を、曲全体がエクスポート可能であることと同一視しないでください。 |
| `too_many_requests`（429） | リクエストがレート制限を受けています。 | まず元のタスクを照会し、その後、新しい冪等キーで新しい操作を開始するかどうかを決定してください。 |
| `studio_unavailable` / `studio_model_unavailable`（503） | 工程処理または選択したモデルが一時的に利用できません。 | 元のタスク結果を保持してください。後で明示的に再試行し、モデルを自動的に切り替えないでください。 |
| `studio_processing_failed` / タイムアウト（500/504） | 処理に失敗したか、終端状態が不確実です。 | `task_id` または元の冪等キーで照会し、重複課金の生成を避けてください。 |

工程および候補は、それらを作成したアプリケーションおよび実行環境に紐付けられており、アプリケーション間での再利用や自動フェイルオーバーを前提とすることはできません。正常にエクスポートされた最終音声 URL を永続化し、調査しやすいように `trace_id` を保持してください。
```
