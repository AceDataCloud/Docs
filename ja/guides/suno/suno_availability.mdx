`POST /suno/availability` はリソース ID を受け取ります。楽曲を確認する場合は `audio_id` を、音色を確認する場合は `persona_id` を渡し、いずれか一方が必須です。チェックは同期的に完了し、API Token が必要です。現在 Credits は消費されません。

## リクエスト

`audio_id` は完了済みの楽曲タスクから取得され、続きを作成する前またはカバーする前の確認に使用できます。

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

`persona_id` は音色作成結果から取得されます。元のアプリケーションと呼び出し元の ID を使用し、音色クエリに対応する作成ルートで以下のリクエストボディを送信します。

```json
{"persona_id":"33333333-3333-4333-8333-333333333333"}
```

## レスポンス

両方のリクエストは同じ成功レスポンスを使用します。`data.id` は今回のクエリ対象のリソース ID です。

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

`available: true` は、今回のチェックで肯定的な証拠が得られたことを示します。音色については、チェックにより作成元の帰属を検証し、関連アカウントが現在オンラインであると報告されていることを確認します。実際の生成結果は引き続き生成タスクに従います。

`/suno/voices` を通じて作成されたプライベートクローン音色は、作成アカウントに依存します。そのアカウントが現在オフラインであることが確認された場合、インターフェースは HTTP 200 を返し、`data` の例は以下のとおりです。

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

クライアントはこの音色を現在利用不可としてマークし、後で再度確認できます。

確認できない場合は HTTP 503 と `availability_unknown` が返されます。たとえば、リソースが見つからない、古い記録に作成ルートがない、またはクエリがタイムアウトした場合です。公開歌手スタイルはアカウントをまたいで使用できますが、作成アカウントがオフラインの場合も 503 が返されます。楽曲クエリは、利用可能であることが確認された場合にのみ `available: true` を返します。

各リクエストでは有効な UUID を 1 つだけ送信します。すべてのルートで、両方の ID を含むリクエスト、または両方の ID が欠けているリクエストは HTTP 400 を返します。楽曲クエリのみに対応するルートでは、`persona_id` のみを含むリクエストを受信すると HTTP 400 を返します。HTTP 429 が発生した場合は、クエリ頻度を下げてください。
