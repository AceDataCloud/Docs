`POST https://api.acedata.cloud/webextrator/extract`

WebExtrator インテリジェント抽出 API は、URL を記事、商品、
レシピ、動画、ディスカッション、求人などの**型付き構造化結果**に変換し、クリーンアップ済みの Markdown とプレーンテキストも提供します。生の HTML ではなく「クリーンな構造化データ」が必要な場合に使用する API です。

## 申請プロセス

WebExtrator サービスページを使用するには、まず [Ace Data Cloud コンソール](https://platform.acedata.cloud/console/applications) で API トークンを取得し、バックアップとして保管してください。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

まだログインまたは登録していない場合、自動的にログインページにリダイレクトされ、登録とログインを促されます。完了後、現在のページに自動的に戻ります。

**1つの API トークンでプラットフォームのすべてのサービスを呼び出すことができ、各サービスごとに個別に申請する必要はありません。** 初回申請時には無料枠が付与され、無料で体験できます。枠が不足した場合は、[コンソール](https://platform.acedata.cloud/console/coin) で一般残高をチャージできます。

> 📘 完全なドキュメント：[WebExtrator サービスページ →](https://platform.acedata.cloud/service/webextrator)

## 認証

```
Authorization: Bearer YOUR_API_KEY
Content-Type:  application/json
```

## リクエストパラメータ

Extract は [Render API](/ja/guides/webextrator/webextrator_render) の**すべて**のパラメータを受け付けます
（`url`、`user_agent`、`timeout`、`wait_until`、`delay`、`wait_for_selector`、
`block_resources`、`headers`、`cookies`、`callback_url`、`bypass_cache`、
`cache_ttl_seconds`、`async`）に加え、Extract 専用のフィールドが 2 つあります：

| フィールド | 型 | 必須 | デフォルト | 説明 |
|------|------|:----:|------|------|
| `expected_type` | enum | ❌ | 自動判定 | ページタイプのヒント：`product` / `article` / `general`。期待する結果タイプを指定します。 |
| `enable_llm` | boolean | ❌ | `false` | schema.org に該当しない場合に、LLM による抽出を許可します。Amazon / HN / Greenhouse のような JSON-LD のないページでは、型付きの結果を取得するために有効にする必要があります。 |

### トップレベルフィールド

| フィールド | 型 | 説明 |
|------|------|------|
| `kind` | string | 常に `"extract"`。 |
| `url` | string | 送信した URL。 |
| `finalUrl` | string | リダイレクト後の最終 URL。 |
| `contentType` | enum | ページタイプ：`product` / `article` / `general`。 |
| `title` | string | ページタイトル。 |
| `description` | string? | ページの説明または要約。 |
| `byline` | string? | 著者、チャンネル、または会社。 |
| `language` | string? | `<html lang>`。 |
| `siteName` | string? | `og:site_name`。 |
| `publishedAt` | string? | 公開日時（ISO 8601 形式）。 |
| `images` | string[] | 最大 50 件の `<img src />`。絶対 URL に解決され、重複が除去され、`data:` URI は除外されます。 |
| `links` | string[] | 最大 100 件の外部リンク。フラグメント / `javascript:` / `mailto:` / `tel:` はフィルタリングされます。 |
| `markdown` | string | ページの Markdown コンテンツ。 |
| `text` | string | ページのプレーンテキスト。 |
| `structured` | object | 完全な構造化結果。以下を参照。 |
| `rawSignals` | object | デバッグ用の診断情報。 |
| `cached` | boolean? | キャッシュヒット時は `true`。 |
| `cacheStoredAt` | number? | キャッシュエントリが最初に書き込まれた Unix ミリ秒タイムスタンプ。 |

### `data.structured` のサブフィールド

| サブフィールド | いつ出現するか | 説明 |
|--------|---------|------|
| `schemaOrg` | 常に | `{ primary, breadcrumbs, all }`。`primary` は最優先の型付きエンティティであり、見つからない場合は `null`。 |
| `openGraph` | 常に | `{ title, description, image, type }`。`<meta property="og:*" />` に由来します。 |
| `jsonLd` | 常に | すべての `<script type="application/ld+json">` ブロックの生 JSON 配列。 |
| `llm` | LLM が実行され、成功した場合 | `{ kind, data, model, promptCharCount }`。型付き結果。 |
| `llmError` | LLM が実行されたが、失敗した場合 | `{ kind, error, model }` の場合でも、リクエストは他の抽出済みフィールドを返すことができます。 |
| `amazon` | URL が `amazon.*` の場合 | レガシー Amazon 拡張結果です。新しい統合では型付き結果を使用してください。 |

## schema.org の結果タイプ

`structured.schemaOrg.primary` は以下の結果タイプをサポートしています。

| schema.org タイプ | kind | 出力フィールド |
|----------------|----------|----------|
| `Product` | product | `name, sku, gtin, model, color, brand, url, images, offer.{price,currency,availability,condition,seller}, rating.{value,count}, reviews[], properties[]` |
| `Recipe` | recipe | `name, description, image, datePublished, author, cookTime, prepTime, totalTime, recipeYield, ingredients[], instructions[], nutrition, rating, keywords, recipeCategory, recipeCuisine` |
| `VideoObject` | video | `name, description, thumbnailUrl, uploadDate, duration, embedUrl, contentUrl, channel, interactionCount` |
| `JobPosting` | job | `title, description, datePosted, validThrough, hiringOrganization, jobLocation, baseSalary, employmentType` |
| `Event`（`*Event` を含む） | event | `name, description, startDate, endDate, location.{name,address}, organizer, offer.{url,price,currency}` |
| `Article` / `NewsArticle` / `BlogPosting` / `ScholarlyArticle` / `TechArticle` / `Report` / `*NewsArticle` | article | `subtype, headline, description, datePublished, dateModified, author, publisher, image[], url, sameAs[]` |
| `FAQPage` | faq | `questions[{question, answer}]` |
| `BreadcrumbList` | （sibling に付加） | 常に `structured.schemaOrg.breadcrumbs[]` に出力され、primary にはなりません。 |

## LLM の結果タイプ

`enable_llm: true` で、ページに利用可能な schema.org 構造化データがない場合、以下のタイプの抽出結果を返すことができます。

| Kind | 必須フィールド | 任意フィールド |
|------|---------|---------|
| `article` | `headline` | `description, byline, publishedAt, language, topics[], sections[{heading,summary}]` |
| `product` | `name` | `description, brand, sku, price, currency, availability, rating.{value,count}, bullets[], specifications[{name,value}]` |
| `discussion` | `title` | `author, postedAt, points, commentCount, body, url` |
| `recipe` | `name` | `description, author, cookTime, prepTime, totalTime, recipeYield, ingredients[], instructions[], nutrition, rating, keywords[]` |
| `video` | `name` | `description, channel, uploadDate, duration, viewCount, likeCount, thumbnailUrl, transcript` |
| `job` | `title` | `description, company, location, remote, employmentType, datePosted, validThrough, salaryMin, salaryMax, salaryCurrency, salaryPeriod, responsibilities[], qualifications[]` |

## キャッシュ

同一の URL、リクエストパラメータ、`cookies`、`headers` ではキャッシュ結果を再利用できます。`async`、`bypass_cache`、`cache_ttl_seconds` は、実行方法とキャッシュ動作を制御するために使用されます。

| フィールド | 効果 |
|------|------|
| `bypass_cache: true` | 読み取りをスキップします。今回の結果は引き続きキャッシュに書き戻され、次回の同一リクエストでヒットします。 |
| `cache_ttl_seconds: 0` | 今回のレスポンスは**キャッシュされません**。 |
| `cache_ttl_seconds: N` | このエントリの TTL をカスタマイズします（デフォルトは 3600 秒）。 |

キャッシュにヒットしたレスポンスには `data.cached: true` と `data.cacheStoredAt: <unix-ms>` が付与されます。

## 非同期モードとコールバック

`async: true` を設定すると非同期モードに入り（`callback_url` を提供すると自動的に入る）。プラットフォームはすぐに返す（HTTP 200）：

```json
{
  "success": true,
  "task_id": "550e8400-...",
  "trace_id": "6ba7b810-...",
  "started_at": 1777717800.123
}
```

タスクが完了すると、完全なエンベロープをあなたの `callback_url` に `POST` する（設定されている場合）。また、後で [`/webextrator/tasks`](/ja/guides/webextrator/webextrator_tasks) を通じて積極的にクエリすることもできる。

## 例

### 1. Wikipedia 記事（schema.org にヒットし、LLM は必要ない）

```bash
curl -X POST https://api.acedata.cloud/webextrator/extract \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://en.wikipedia.org/wiki/Diffbot",
    "expected_type": "article"
  }'
```


### Python (requests)

```python
import os, requests

API_KEY = os.environ["ACEDATA_API_KEY"]

resp = requests.post(
    "https://api.acedata.cloud/webextrator/extract",
    headers={
        "Authorization": f"Bearer {API_KEY}",
        "Content-Type": "application/json",
    },
    json={
        "url": "https://en.wikipedia.org/wiki/Diffbot",
        "expected_type": "article",
    },
    timeout=120,
)
resp.raise_for_status()
data = resp.json()["data"]

primary = (data.get("structured") or {}).get("schemaOrg", {}).get("primary")
print("contentType:", data["contentType"])
print("title:      ", data["title"])
print("byline:     ", data.get("byline"))
print("publishedAt:", data.get("publishedAt"))
if primary and primary["kind"] == "article":
    print("headline:    ", primary["headline"])
    print("dateModified:", primary.get("dateModified"))
```

### Node.js (fetch)

```js
const apiKey = process.env.ACEDATA_API_KEY;

const res = await fetch('https://api.acedata.cloud/webextrator/extract', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${apiKey}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    url: 'https://www.allrecipes.com/recipe/16354/easy-meatloaf/',
  }),
});
const { data } = await res.json();
const recipe = data?.structured?.schemaOrg?.primary;
console.log(recipe.name, recipe.cookTime, recipe.ingredients.length, '種類の材料');
```

## ヒントと注意点

- **ページタイプを指定する必要がある場合は `expected_type` を渡してください。** たとえば、記事ページには `article`、商品ページには `product` を使用します。
- **schema.org にヒットするページでは `enable_llm: true` は無料です。** LLM は schema.org に
  primary がない場合にのみ呼び出されるため、デフォルトで有効にしておいても安全です。
- **デバッグ時はまず `rawSignals.hasJsonLd` を確認してください。** `true` であるにもかかわらず `structured.schemaOrg.primary`
  が `null` の場合、そのページの `@type` は現在サポートされていません。フィードバックをお寄せください。
- **`structured.llmError` は参考情報です。** リクエストは、抽出済みの他のフィールドを返して成功する場合があります。以下を確認してください：
  `llmError.error` で原因を特定します（タイムアウト、JSON 解析の失敗、構造検証の失敗）。
- **記事ページ以外の `links[]` では関連性によるソートは行われません。** 「最大 100 件 + 無効なプロトコルの除外」のみで
  可能な限りクリーンアップされます。
- **キャッシュヒットにも課金されます。**
