AI Chat v2 API（`/aichat2/conversations`）は新世代の対話インターフェースであり、[AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations) の全面アップグレード版です。v1 のシンプルさとマルチターン対話のホスティングをベースに、以下を拡張しています：

- **マルチモーダルなユーザー入力**：構造化された `message` フィールドを通じて、テキスト + 画像 + ファイルブロックを直接送信でき、事前に `references` を使用して間接的に添付する必要はありません。
- **Agent 化されたツール呼び出し**：ネットワーク検索、ウェブページ取得、ファイル読み取りなどのツール一式を内蔵し、ユーザー認可済みの MCP サーバー（Google Drive、Notion、Slack、GitHub など）もマウントできます。モデルは1回のリクエスト内で複数回自律的にツールを呼び出し、複雑なタスクを完了できます。
- **構造化ストリーミングイベント**：`accept: text/event-stream` または `application/x-ndjson` により、token ごとの `text_delta`、`tool_use`、`tool_result`、`thinking`、`citation`、`card`、`artifact` などのイベントを取得でき、フロントエンドで対応する種類ごとに個別にレンダリングできます。
- **中断 / 再開可能**：モデルはユーザーによる情報の補足が必要な場合、`ask_user_question` イベントを送信して一時停止します。次回の呼び出しで `tool_results` を通じて回答を返送すれば、続行できます。
- **新しい CRUD アクション**：同一の endpoint で `action` フィールドを通じて `retrieve` / `retrieve_batch` / `update` / `delete` を実行でき、追加の会話管理 API は不要です。
- **継続的に更新されるモデル一覧**：デフォルトで GPT-5.4、Claude Opus 4.8、Claude Sonnet 4.6、Gemini 3.1 Pro、GLM 5.1、DeepSeek V4、Kimi K3 などの現代的なモデルに接続されています。

同時に、リクエストボディのレベルで**完全に v1 と後方互換**です：`model` + `question`（+ 任意の `stateful` / `id` / `references` / `preset`）のみを渡せば、v1 と同等の `{answer, id}` JSON レスポンスを取得できます。そのため、`/aichat/conversations` から移行する際にクライアントを書き直す必要はなく、パスを `/aichat2/conversations` に変更するだけです。

> 現在 `/aichat/conversations` を使用している場合、旧インターフェースも引き続き提供されるため、ご自身のペースで移行できます。

## 基本的な使用方法

最も簡単な使い方は v1 と完全に同じです：`model` + `question` を渡し、`{answer, id}` を取得します。

CURL の例：

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

返り値：

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python の例：

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

利用可能な `model` の値は、右側の Try パネルのドロップダウンで直接確認できます。一般的なカテゴリは以下を含みます：

## マルチターン対話

v1 と同様に、`stateful: true` を渡して会話保存を有効にすると、API は `id` を返します。以降のリクエストで `id` を渡し戻すだけで会話を継続でき、自分で messages の履歴を管理する必要はありません。

最初のリクエスト：

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

返り値：

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

2回目のリクエストでは、同じ `id` を渡します：
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` のデフォルトは `true` であり、省略することは明示的に `true` を渡すことと同等です。`stateful: false` を設定すると、以前の会話履歴の読み込みをスキップします。これは今回の結果が保存されないことを意味するものではなく、一時停止後に継続する必要があるツールフローにも適用されません。

### 長い会話と原文の保持

コンテキスト圧縮は、今回モデルに送信する内容のみを整理し、保存済みのチャット履歴を置き換えることはありません。`action: retrieve` を通じて、完全な保存済みメッセージを引き続き読み取れます。明示的な編集や会話の削除は、引き続きリクエストどおりに有効になります。

モデルは現在の会話内で、履歴の原文を検索し、ページ単位で読み取ることができます。記事の修正を継続する場合、数字を引用する場合、または公開の準備をする場合は、対応する原文を読み取る必要があり、本文の代わりに要約を使用することはできません。この機能は、古いバージョンですでに失われたメッセージを自動的に復元しません。

コンテキストの整理に失敗した場合は、会話 ID を保持し、`error` イベントを確認してください。サービスが空の要約で原文を上書きすることはありません。失敗前に完了したツール操作は引き続き有効な可能性があるため、重複生成や重複公開を避けるために、まずその結果を照会してください。単一の会話がストレージ上限に達した場合は明確にエラーが返され、既存の保存済み記録はトリミングによって容量を確保しません。必要な内容をエクスポートした後、新しい会話を開始できます。

## ストリーミングレスポンス

v2 は 2 種類のストリーミング形式をサポートしており、`accept` ヘッダーに応じて選択します。

| シナリオ                    | `accept`               | データ形式                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web フロントエンド / EventSource  | `text/event-stream`    | `data: {json}\n\n`、最後の行は `data: [DONE]\n\n` |
| サーバーサイド / CLI / Node ストリーミング解析 | `application/x-ndjson` | 1 行につき 1 つの JSON オブジェクト                               |
| ストリーミング不要                 | `application/json`（デフォルト） | 一度に `{answer, id}` を返す                       |

### NDJSON の例

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

NDJSON の各行は構造化イベントであり、最も一般的なのは `text_delta` です。

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE の例

ブラウザ側で `EventSource` を使用する場合、カスタムリクエストボディはサポートされないため、`fetch` + 手動で `\n\n` ごとに分割して解析することを推奨します。

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### ストリーミングイベントの種類

| `type`              | 意味                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | アシスタントの回答の増分テキスト断片。`content` は追加された内容です。v1 との互換性のため、同じイベントには `delta_answer`（`content` と等しい）および `id` も含まれます。                                        |
| `thinking`          | モデルの思考プロセス（選択したモデルが reasoning を公開する場合にのみ出現します）。                                                                                      |
| `tool_use`          | モデルがツールの呼び出しを決定したことを示し、イベントには `tool_id`、`tool_name`、`input` が含まれます。                                                                        |
| `tool_result`       | ツールの実行結果。前の `tool_use` と `tool_id` によって対応付けられ、`is_error` は失敗したかどうかを示します。                                                             |
| `card`              | ツールによって生成された構造化カード（画像、リンクプレビューなど）であり、直接レンダリングするのに適しています。                                                                                          |
| `citation`          | 対応するテキスト断片の引用元 URL を補足するために使用されます。                                                                                                  |
| `ask_user_question` | モデルがユーザーに追加情報を求める際に発行され、会話は `awaiting_user_input` 状態に入ります。詳細は下記の[一時停止した会話の再開](#一時停止した会話の再開)を参照してください。                                                 |
| `artifact`          | モデルが生成した独立した成果物（コードブロック、ドキュメントなど）で、保存またはダウンロードできます。                                                                                            |
| `system_message`    | システムメッセージ（ユーザーおよびアシスタントの内容ではない）であり、UI の通知にのみ使用されます。                                                                                           |
| `compact`           | モデルのコンテキストが整理されました。保存済みの元メッセージは変更されず、クライアント側でチャット履歴を削除する必要はありません。                                                                                    |
| `error`             | 今回エラーが発生しました。`message` がエラー内容を説明します。                                                                                              |
| `done`              | 今回の最終会話記録の保存に成功しました。`usage`（`prompt_tokens` / `completion_tokens` / `total_tokens` を含む）および `terminal_reason` を伴います。タスクが完了したかどうかは、引き続き終了理由に基づいて判断する必要があります。 |
最終回答だけを気にするクライアントの場合、すべての `text_delta` の `content` を連結すれば、`application/json` モードの `answer` と等価です。

## マルチモーダル入力

ユーザー入力に画像またはファイルが含まれる場合、`question` の代わりに `message`（配列）を渡します。各配列要素はコンテンツブロックです：

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

サポートされるブロックタイプ：

- `text` — 通常のテキスト。`text` フィールドが必須です。
- `image_url` — 画像。`image_url.url` が必須です。
- `file_url` — ファイル（PDF、CSV、TXT など）。`file_url.url` が必須です。

### v1 `references` との関係

旧クライアントとの互換性のため、v2 は引き続き `references: ["https://...", ...]` フィールドを認識します：

- URL の拡張子が `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif` の場合、自動的に `image_url` ブロックに変換されます；
- その他の拡張子は `file_url` ブロックに変換されます；
- 同時に `question` も提供されている場合、それを先頭の `text` ブロックとして追加します。

したがって、v1 から移行したいだけでリクエストボディを変更したくない場合は、パスを `/aichat2/conversations` に変更するだけで、元の `references` の使い方はこれまでどおり機能します。

より細かな制御が必要な場合（たとえば複数の画像をテキストの間に配置する、または順序が重要である場合）は、直接 `message` 配列を使用してください。

## ツール呼び出しと MCP

v2 の中核的な強化点は、モデルがツールを自律的に呼び出して複数ステップのタスクを完了できることです。**これはデフォルトで有効**であり、クライアント側でリクエストに追加設定を行う必要はありません。一般的なシナリオ：

- ユーザーが「最近上海でどんな新しい展示があるか調べて」→ モデルが内蔵 web search を呼び出す → 結果を整理して回答する。
- ユーザーが「この PDF を読んで要約を書いて」→ モデルが file_read を呼び出す → 要約を書く。
- ユーザーが [Connections](https://platform.acedata.cloud/connections) で Google Drive / GitHub / Notion などを認可済み → モデルは対応する MCP ツールを呼び出してそのデータを読み書きできる。

NDJSON / SSE ストリームでは、ツール呼び出しは `tool_use` と `tool_result` の2種類のイベントで表現されます。例：

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

フロントエンドでツール呼び出しの詳細を表示したくない場合は、`tool_use` / `tool_result` / `card` / `citation` のこれらのイベントを無視すればよく、モデルの最終出力は引き続き `text_delta` でストリームされます。

`max_turns` は、今回のリクエストでモデルが自らツールを呼び出せる最大ラウンド数を制限できます。範囲は 1～500 で、省略時のデフォルトは 500 です。これを小さく設定（たとえば `max_turns: 1`）すると、単一回答を強制し、いかなるツール呼び出しも許可しないことができます。

## 非同期実行と無人承認

呼び出し元がアラート Webhook、CI/CD、監視システム、またはその他のバックグラウンドタスクである場合、`async: true` を設定すると、インターフェースは即座にタスク ID を返し、バックグラウンドで実行を継続します：

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

返却例：

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

その後、`action: retrieve` + `id` を使用して会話結果を照会できます；`callback_url` を提供することもでき、タスク完了後にプラットフォームは `{ status, answer, usage, error }` をコールバックアドレスへ POST します。`callback_url` は `http` / `https` を使用する必要があり、`localhost` またはプライベート IP リテラルアドレスを直接指定することはできません。

バックグラウンドタスクでは通常、確認をクリックできる人がいません。特定の Skill または MCP Server に、無人モードで送信、公開、書き込みなどのアクションを実行させたい場合は、リクエストボディで明示的に事前承認リストを渡してください：

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

`allowed_skills` 内の値は接続済み Skill の slug です；`allowed_mcp_servers` 内の値は接続済み MCP Server の slug です。事前承認リストに含まれていない Skill / MCP Server は、無人モードでは依然としてプレビュー、dry-run、または書き込み操作の実行拒否のみとなります。

より細かな制御が必要な場合は、等価な `unattended_policy` オブジェクトを使用することもできます：

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

事前承認は、この2つのリストそのものです：リストが空であれば、いかなる機能も承認しないことを意味し、追加のスイッチフィールドは不要です。

注意：事前承認は、「今回のリクエストでこれらの機能が無人モードにおいて人間による確認をスキップすることを許可する」ことだけを意味します。具体的な Skill は依然として `--unattended-confirm` または対応する安全機構をサポートしている必要があります；そうでない場合は、引き続き dry-run となり、書き込み操作を直接実行することはありません。

## 一時停止した会話の再開

一部のツールはモデルに「ユーザーへの質問」をさせます。このときモデルは `ask_user_question` イベントを発行し、会話は `awaiting_user_input` 状態で凍結されます：

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

フロントエンドでこのイベントをカードとしてレンダリングし、ユーザーに回答を選ばせた後、同じ `id` を使用して次のリクエストを開始し、回答を `tool_results` を通じて戻します：
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

リクエストボディ内の `tool_use_id` は、一時停止時の `tool_id` と**完全に一致**している必要があります。一致しない場合は 400 が返されます。リクエスト内に `tool_results` が同時に存在する場合、`question` / `message` / `references` はすべて無視されます。

ユーザーがこの質問を放棄することを決めた場合は、新しい `question` / `message` を直接渡すだけでよく、プラットフォームは一時停止中のツール呼び出しを自動的に「ユーザーがスキップ」とマークします。

## セッション管理（CRUD）

v2 は同じ endpoint 上で `action` フィールドを通じて軽量なセッション管理を提供し、別途 API を開設する必要はありません。

### `action: retrieve` —— セッションを 1 つ取得

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

完全なセッションドキュメント（`messages` 履歴、`model`、`title`、`tools_used` などを含む）を返します。

### `action: retrieve_batch` —— セッションの要約を一覧表示

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

`{ items: [...], total }` を返します。**要約には `messages` は含まれません**。サイドバーのリストに適しています。ユーザーが特定のセッションを開いた場合は、`action: retrieve` を使用してその完全なメッセージを個別に取得します。

任意のフィルターパラメータ：`user_id`、`application_id`、`model_group`、`model`。

### `action: update` —— タイトルの変更または履歴の書き換え

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

`messages` も渡せますが、サーバー側で厳格な schema 検証が行われます（折りたたまれた `ToolUseContent` 形式である必要があります）。適合しない場合は 400 が返されます。通常は `title` の変更にのみ使用することを推奨します。

### `action: delete` —— セッションを 1 つ削除

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

`{ id, success: true }` を返します。削除後は復元できないため、確認してから呼び出してください。

## v1 からのスムーズな移行

すでに [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations) を使用している場合、v2 への移行ではほとんどコードを変更する必要がありません。

1. URL を `https://api.acedata.cloud/aichat/conversations` から `https://api.acedata.cloud/aichat2/conversations` に変更します。
2. 以前に v1 のモデル名（`gpt-3.5`、`gpt-4-browsing` など）を渡していた場合、v2 への切り替え時に現行モデル（`gpt-5.4`、`claude-opus-4-8`、`gemini-3.1-pro-preview` など）へアップグレードすることを推奨します。
3. NDJSON ストリームのフィールドは後方互換性を維持しています。各 `text_delta` イベントには引き続き `delta_answer` と `id` が含まれるため、従来行ごとに `delta_answer` を解析していたクライアントは変更不要です。

移行後は、必要に応じて v2 の新機能（マルチモーダル `message`、SSE、ツール呼び出し、`action` CRUD）を有効にでき、段階的に進めることができます。

## エラー処理

エラーレスポンスは統一して以下の形式です。

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

よくあるエラー：

- `400 bad_request`：必須フィールドの不足、`tool_use_id` の不一致、`messages` schema の不正など。
- `401 invalid_token`：`authorization` ヘッダーが正しくありません。
- `404 not_found`：`action: retrieve / update / delete` の際に、`id` に対応するセッションが存在しません。
- `413 conversation_storage_limit`：セッションがストレージ制限を超過しており、既存の保存済み記録は上書きされていません。
- `429 too_many_requests`：レート制限が発動しました。
- `503 context_compaction_failed`：コンテキストの整理に失敗しました。既存の記録は保持されます。
- `500 conversation_persist_failed`：今回の最終保存に失敗しました。テキストを受信済みであっても、最終記録が正常に保存されたことを意味するわけではありません。セッション ID で照会してください。
- `500 chat_error`：サービスが一時的に利用できないか、今回コンテンツが生成されませんでした（課金されません）。

ストリーミングレスポンスでは、エラーは `{"type":"error","message":"..."}` イベントとして送信され、その後ストリームは終了します。`[DONE]` は転送の終了のみを示します。`error` がある場合は成功と見なすことはできず、成功の `done` イベントも送信されません。

## 結論

AI Chat v2 API は、v1 との後方互換性を維持しながら、対話を「単一ターン / 複数ターンの質疑応答」から「Agent 化された可観測な対話」へとアップグレードします。マルチモーダル入力、ツール呼び出し、一時停止 / 再開、ストリーミング構造化イベント、組み込み CRUD を備えています。新規導入では v2 を直接使用することを推奨します。既存の v1 統合は段階的にスムーズに移行できます。ご不明な点がございましたら、いつでも技術サポートチームまでお問い合わせください。
