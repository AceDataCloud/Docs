## 動的モデルカタログ

まずは [モデルカタログ](https://platform.acedata.cloud/models) を開き、`claude-opus-5`、`gpt-6-sol` などの現在のモデル名を確認できます。Coding の認証情報と API プロトコルが一致するか確認する必要がある場合は、有効な Coding Application 認証情報を使用してリクエストしてください：

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_TOKEN"
```

モデルカタログは継続的に変更されるため、本稿では固定数または静的なモデル一覧を管理しません。レスポンス内の各エントリの `id` は、API の `model` パラメータに直接渡せる**モデル名**です。例えば、`{"id":"deepseek-v4-pro"}` の場合は `deepseek-v4-pro` を指定します。これはサービス、API、または Application の UUID ではありません。`/v1/models` はグローバルモデルカタログを返すため、Coding 認証情報に応じて自動的に絞り込まれることはありません。設定前に、認証情報の API scope、選択したプロトコル、およびクライアントの互換範囲と照らし合わせて確認する必要があります。

## よくあるトラブルシューティング

- **残高不足**：[Applications コンソール](https://platform.acedata.cloud/console/applications) にアクセスし、Coding Application を見つけて積極的に更新購入してください。
- **クライアントが引き続き元のアドレスにリクエストする**：設定がクライアントを起動した同一のユーザーおよびワークスペースに属していることを確認し、完全に終了してからクライアントを再起動してください。
- **モデル名が利用できない**：`/v1/models` を再度リクエストし、入力したモデル名がカタログ内の `id` と完全に一致していること、認証情報の API scope、およびクライアントがサポートするプロトコルを確認してください。
- **Token でインターフェースを呼び出せない**：認証情報が Coding Application に属していることを確認し、`allowed_api_ids` とアプリケーションの API 権限を確認してください。
