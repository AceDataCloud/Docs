Kimiは、月之暗面（Moonshot AI）が提供するAIモデルシリーズです。現在は、長時間にわたるプログラミング、複雑な推論、視覚理解、知識業務に適した `kimi-k3.1-pro` を推奨しています。`kimi-k3` も引き続き使用できます。OpenAI互換のChat Completions APIを通じて呼び出すことができます。

本ドキュメントでは、Kimi Chat Completion APIの操作と使用手順を主に紹介します。これを利用することで、公式Kimiの対話機能を簡単に使用できます。

## 対応モデル

現在、`kimi-k3.1-pro`、`kimi-k3`、`kimi-k2.6`、`kimi-k2.7-code` の4つのモデルに対応しています。K2.7 Codeはプログラミングおよびツール呼び出しのシナリオ向けで、K2.6と同じ価格帯で課金されます。リクエストでは `thinking` スイッチや `reasoning_effort` を指定しないでください。その他のKimiモデルはすでにサポートを終了しているため、クライアント側でこれら4つのモデルのいずれかを明示的に選択してください。

## 申請手順

Kimi Chat Completion APIを使用するには、まず[Ace Data Cloudコンソール](https://platform.acedata.cloud/console/applications)にアクセスし、API Tokenを取得して、後で使用できるように保存してください。

![]()

まだログインまたは登録していない場合は、自動的にログインページに移動し、登録とログインを求められます。完了すると、自動的に現在のページに戻ります。

**1つのAPI Tokenですべてのプラットフォームサービスを呼び出すことができ、サービスごとに個別に申請する必要はありません。** 初回申請時には無料利用枠が付与され、無料でお試しいただけます。利用枠が不足した場合は、[コンソール](https://platform.acedata.cloud/console/coin)で共通残高をチャージできます。

> 📘 完全なドキュメント：[Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## 基本的な使用方法

続いて、画面上で対応する内容を入力します。以下の図をご覧ください。

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

このインターフェースを初めて使用する場合、少なくとも3つの項目を入力する必要があります。`authorization` はドロップダウンリストから直接選択できます。`model` はKimiモデルを選択するための項目で、`kimi-k3.1-pro` の使用を推奨します。`messages` は会話メッセージの配列であり、各メッセージには `role` と `content` が含まれます。このうち、`role` は `user`、`assistant`、`system`、`tool` に対応しています。

また、右側には対応する呼び出しコードが自動生成されていることがわかります。コードをコピーして直接実行することも、「Try」ボタンをクリックして直接テストすることもできます。

<p><img src="https://cdn.acedata.cloud/six7e3.png" width="400" className="m-auto" /></p>

以下は、`reasoning_effort: max` を使用して取得した実際のK3レスポンスです（使用していない拡張フィールドは省略しています）。

```json
{
  "id": "msg_2D4Btbg1WgvkNE3tCYkR4xGA",
  "object": "chat.completion",
  "created": 1784466588,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 86,
    "completion_tokens": 206,
    "total_tokens": 292
  }
}
```

返される結果には複数のフィールドが含まれています。以下に説明します。

- `id`：今回の会話タスクに生成されたIDで、今回の会話タスクを一意に識別するために使用されます。
- `model `：選択されたKimi公式モデルです。
- `choices`：Kimiが入力された質問に対して返す回答情報です。
- `usage `：今回の質疑応答におけるトークン使用量の統計情報です。

このうち、`choices` にはKimiの回答情報が含まれています。その中の `choices` はKimiが返した具体的な回答情報です。以下の図をご覧ください。

<p><img src="https://cdn.acedata.cloud/tv9rul.png" width="400" className="m-auto" /></p>

`choices` 内の `content` フィールドに、Kimiが返信した具体的な内容が含まれていることがわかります。また、K3では推論プロセスを表す `reasoning_content` が返される場合もあります。

## K3.1 Proの推論強度

`kimi-k3.1-pro` では、推論が常に有効になっています。リクエストボディのトップレベルで `reasoning_effort` を `low`、`high`、または `max` に設定できます。推論を無効にする設定は指定しないでください。このモデルは最大1,048,576トークンのコンテキストに対応していますが、実際のリクエスト上限は現在のインターフェースの仕様に従います。料金は入力、出力、キャッシュヒットの使用量に基づいて計算されます。詳細については、モデル一覧のPricingカードをご確認ください。

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

以下のK3の例は、既存の統合環境向けに残してあります。サンプルレスポンスは、実際にK3へのリクエストによって取得されたものです。

## K3の推論強度

`kimi-k3` では、推論が常に有効になっています。リクエストボディのトップレベルで `reasoning_effort` フィールドを指定できます。現在サポートされている値は `max` のみです。このフィールドを省略した場合も、同様に `max` が使用されます。サポートされている値を使用してください。

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

OpenAI SDKを使用する場合は、このフィールドを直接渡すことができます。

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

複数ターンの会話やツール呼び出しを行う場合は、前のターンのassistantメッセージ全体を `reasoning_content` と `tool_calls` を含めて `messages` に返してください。

### 公式参考資料

- [Thinking Effort（推論強度）](https://platform.kimi.ai/docs/guide/use-thinking-effort)：Kimi K3では推論が常に有効になっており、現在 `reasoning_effort` でサポートされている値は `max` のみであることを説明しています。
- [Model Parameter Reference（モデルパラメータリファレンス）](https://platform.kimi.ai/docs/api/models-overview)：K3とK2シリーズの推論パラメータ、コンテキストウィンドウ、ツール呼び出しの違いを比較しています。
- [Create Chat Completion（チャット補完の作成）](https://platform.kimi.ai/docs/api/chat)：Moonshot公式のChat Completionsリクエスト、レスポンス、およびOpenAPIフィールドの定義です。

## ストリーミングレスポンス

このインターフェースはストリーミングレスポンスにも対応しています。これはWebページとの連携に非常に便利で、Webページ上で文字を1文字ずつ表示する効果を実現できます。

レスポンスをストリーミング形式で返したい場合は、リクエストヘッダー内の `stream ` パラメータを変更し、`true` に設定してください。

以下の図のように変更します。ただし、ストリーミングレスポンスに対応させるには、呼び出しコードにも対応する変更を加える必要があります。

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>
`stream` を `true` に変更すると、API は対応する JSON データを1行ずつ返すようになります。コードレベルでも、1行ずつ結果を取得するために適切な変更を行う必要があります。

Python のサンプル呼び出しコード：

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

以下は、同一の実際の K3 Max ストリーミングレスポンスから抜粋した、開始、推論、本文、終了、および使用量のデータチャンクです。

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

ご覧のとおり、レスポンスには複数の `data` が含まれており、`data` 内の `choices` が最新の回答内容となります。これは上記で説明した内容と一致しています。`choices` には新たに生成された回答内容が含まれており、その結果に基づいてご自身のシステムに連携できます。また、ストリーミングレスポンスの終了は `data` の内容によって判断します。内容が `[DONE]` の場合、ストリーミングレスポンスによる回答がすべて終了したことを意味します。返される `data` の結果には複数のフィールドが含まれており、以下のとおりです。

- `id`、今回の会話タスクを生成する ID であり、今回の会話タスクを一意に識別するために使用します。
- `model `、選択した Kimi 公式サイトのモデル。
- `choices`、Kimi が入力プロンプトに対して返す回答情報。

JavaScript にも対応しています。例えば、Node.js のストリーミング呼び出しコードは以下のとおりです。

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Java のサンプルコード：

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

その他の言語についても、ご自身で適宜書き換えることができます。基本的な仕組みはすべて同じです。

## 複数ターンの会話

複数ターンの会話機能を連携したい場合は、`messages` フィールドに複数のプロンプトをアップロードする必要があります。複数のプロンプトの具体例を以下の図に示します。

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Python のサンプル呼び出しコード：

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

複数のプロンプトをアップロードすることで、複数ターンの会話を簡単に実現できます。以下は、このリクエストによって取得された実際の K3 Max レスポンスです（未使用の拡張フィールドは省略しています）。

```json
{
  "id": "msg_Rqp8nPGBDHWwBlL4VpxuafOp",
  "object": "chat.completion",
  "created": 1784466628,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "I’m Kimi, an AI assistant developed by Moonshot AI (月之暗面). I don’t have a specific public model version identifier to share from here."
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 134,
    "completion_tokens": 346,
    "total_tokens": 480
  }
}
```

ご覧のとおり、`choices` に含まれる情報は基本的な使用方法の場合と一致しています。ここには、複数の会話に対して Kimi が返した具体的な回答内容が含まれており、複数の会話内容に基づいて、それぞれの質問に回答できるようになります。

## エラー処理

API の呼び出し時にエラーが発生した場合、API は対応するエラーコードと情報を返します。例えば：

- `400 token_mismatched`：Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`：Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`：Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`：Too many requests, you have exceeded the rate limit.
- `500 api_error`：Internal server error, something went wrong on the server.
