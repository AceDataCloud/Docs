---
title: "AceDataCloud Application のグローバル残高共有を設定する"
description: "Platform API guide - Ace Data Cloud"
---

`allow_consume_global` を設定します。有効化すると、条件を満たす従量制 Application は自身の残高が不足している場合にアカウントのグローバル残高を引き続き使用できます。

## 準備作業

- [Account Token](https://platform.acedata.cloud/documents/platform-token) を作成し、安全に保存します。
- [サービス申請リスト](https://platform.acedata.cloud/documents/platform-application-list)から本人が所有する `application_id` を取得します。

```shell
export PLATFORM_TOKEN='あなたのアカウントトークン'
export APPLICATION_ID='あなたの Application ID'
```

## インターフェース概要

| 項目    | 内容                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------- |
| メソッド   | `POST`                                                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/applications/{application_id}/update-allow-consume-global/` |
| 認証   | Account Token                                                                                      |
| Body | JSON                                                                                               |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/applications/${APPLICATION_ID}/update-allow-consume-global/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"allow_consume_global": true}'
```

成功時は更新後の Application オブジェクトが返されます。リクエスト値が必ず保存されると仮定せず、レスポンス内の `allow_consume_global` を基準にしてください。

> `Period` タイプの Application はグローバル残高を消費できません。`true` をリクエストしても、サーバー側はこのフィールドを `false` のまま保持します。

## エラー処理

- `401`：Account Token が無効または欠落しています。
- `403`：現在のアカウントはこの Application の所有者ではありません。
- `404`：Application ID が存在しません。

グローバル残高のチャージ入口および利用可能なプランは、プラットフォームコンソールおよび[注文作成](https://platform.acedata.cloud/documents/platform-order-create)で返される実際のプランに従ってください。`Wallet` タイプのプランが存在すると仮定しないでください。

## 透支が許可されているアプリケーション

従量制アプリケーションの読み取り専用フィールド `allow_overdraft=true` の場合、このアプリケーションは残高がマイナスになっても自身の残高から引き続き課金できます。残高不足によってグローバルアカウントへ切り替わることはありません。透支が有効でないアプリケーションは引き続き `allow_consume_global` に従います。切り替え後に透支が許可されるかどうかは、実際に課金されるグローバル Application の設定に従います。
