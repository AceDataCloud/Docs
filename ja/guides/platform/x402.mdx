X402 は HTTP `402 Payment Required` に基づくオンチェーン決済プロトコルです。Ace Data Cloud の X402 機能を通じて、呼び出し側は API Token を作成したり、アカウント残高を事前チャージしたりすることなく、各 API リクエストで直接 USDC を使用してオンチェーン決済できます。

このドキュメント群は実際の統合順序に従って構成されています。まず最小リクエストを一度実行し、次に SDK を統合し、その後ネットワーク、料金プラン、注文決済、Facilitator を理解します。以下の表を上から下へ読むことを推奨します。

| チュートリアル               | 適用シナリオ                                              | リンク                                                                                |
| ------------------------ | ----------------------------------------------------- | --------------------------------------------------------------------------------- |
| クイックスタート             | 最小リクエストで 402、`accepts`、`PAYMENT-SIGNATURE` のフローを理解する | [X402 クイックスタート](https://platform.acedata.cloud/documents/x402-quickstart)             |
| TypeScript SDK           | ブラウザ、Node.js、またはフロントエンドアプリケーションで Ace Data Cloud API を呼び出す | [TypeScript SDK 統合](https://platform.acedata.cloud/documents/x402-typescript-sdk) |
| Python SDK               | Python サービス、スクリプト、Agent、またはデータパイプラインで API を呼び出す                | [Python SDK 統合](https://platform.acedata.cloud/documents/x402-python-sdk)         |
| 注文決済                     | X402 を使用して Ace Data Cloud コンソールの注文を決済する                    | [注文決済チュートリアル](https://platform.acedata.cloud/documents/x402-order-payment)             |

## 推奨統合パス

Ace Data Cloud API を呼び出すだけの場合は、公式 SDK を優先して使用してください。

- TypeScript：`@acedatacloud/sdk` + `@acedatacloud/x402-client`
- Python：`acedatacloud` + `acedatacloud-x402`

公開ソースコードとパッケージのアドレス：

| プロジェクト                 | アドレス                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| Ace Data Cloud SDK | [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)                                         |
| X402 Client        | [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)                           |
| X402 Facilitator   | [https://github.com/AceDataCloud/FacilitatorX402](https://github.com/AceDataCloud/FacilitatorX402)                 |
| npm SDK            | [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)                 |
| npm X402 Client    | [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client) |
| PyPI SDK           | [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)                                   |
| PyPI X402 Client   | [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)                         |

SDK は、最初の認証なしリクエスト、`402 Payment Required` の解析、payment handler の呼び出し、`PAYMENT-SIGNATURE` を付与した再試行というステップを自動的に完了します。USDC を保有するウォレットを用意し、使用したいネットワークを選択するだけです。

独自の API でも X402 受取をサポートしたい場合は、Facilitator ドキュメントを読み、`paymentRequirements`、`paymentPayload`、`/verify`、`/settle` の関係を理解する必要があります。

## サポート状況

Ace Data Cloud X402 は、公開 API、公式 SDK、Facilitator、およびオンチェーン決済フローで検証を完了しています。以下の表は、開発者が統合時に最もよく使用する機能の観点から現在の状況をまとめたものです。

| 機能                       | 状態                  | 説明                                                                 |
| ------------------------ | ------------------- | ------------------------------------------------------------------ |
| Facilitator capabilities | 利用可能                  | `https://facilitator.acedata.cloud/.well-known/x402` は決済ネットワークとプロトコルエンドポイントを返します。  |
| API 402 `accepts`        | 利用可能                  | 未決済リクエストは Base と Solana の利用可能な payment requirement を返します。                    |
| TypeScript SDK           | 利用可能                  | `@acedatacloud/sdk` と `@acedatacloud/x402-client` は 402、署名、再試行を自動的に処理できます。 |
| Python SDK               | 利用可能                  | `acedatacloud` と `acedatacloud-x402` は 402、署名、再試行を自動的に処理できます。              |
| Base `exact`             | オンチェーンで検証済み               | 固定金額 API と注文決済に適しています。                                                  |
| Base `upto`              | オンチェーンで検証済み               | チャット補完などの後払い計量 API に適しており、現在 `upto` を提供する唯一のネットワークです。                                 |
| Solana `exact`           | HTTP paid retry 検証済み | API paid retry とモデルレスポンスは検証済みです。オンチェーン署名の確認には、独自の Solana RPC による照合を推奨します。               |
| 注文決済                     | オンチェーンで検証済み               | Base `exact` の注文決済は、オンチェーン決済を完了し、注文状態を更新しています。                                   |

## 統合時の注意事項

開発者が統合する際は、ドキュメント内のサンプル金額やアドレスをコピーするのではなく、現在のリクエストが返すリアルタイムの支払い要件を優先して確認してください：

- `accepts[].maxAmountRequired` は、現在のリクエストで署名可能な最大金額です。
- `accepts[].asset` は、今回のリクエストで使用する USDC コントラクトまたは mint です。
- `accepts[].extra.chainId`、`accepts[].extra.facilitatorAddress`、および `accepts[].extra.verifyingContract` は EVM typed data 署名に関与します。
- `upto` では、ウォレットがまず対象チェーンの USDC を Permit2 に承認する必要があります。未承認の場合は `PERMIT2_ALLOWANCE_REQUIRED` が返されます。
- 後払い計量を明示的に使用したい場合は、TypeScript SDK で `preferScheme: 'upto'` を渡してください。そうしない場合、SDK はそのネットワークでサーバーが返した最初の利用可能な requirement を選択します。

## 公開検証できる範囲

統合前に、これらの公開エントリポイントと SDK の動作を先に検証できます：

- `Authorization` または `PAYMENT-SIGNATURE` を付与しない API リクエストは `402 Payment Required` を返し、レスポンス内の `accepts` が今回のリクエストにおける唯一の署名根拠です。
- TypeScript SDK と Python SDK はいずれも payment handler を提供しており、SDK のトランスポート層は 402 を受信すると handler を呼び出して一度再試行します。
- `https://facilitator.acedata.cloud/.well-known/x402`：Facilitator がサポートするネットワーク、scheme、プロトコルエンドポイントを返します。API の価格は引き続き対象リクエストがリアルタイムで返す 402 に従います。
- `https://facilitator.acedata.cloud/supported`：Facilitator がサポートするネットワークと scheme を返します。
- X402Client リポジトリには高度なオンチェーン検証ツールが含まれており、署名、再試行、settlement の動作を確認するために使用できます。ツールの出力はオンライン API が返す `accepts` の代わりにはなりません。

`upto` は後払い計量決済に属し、チャット補完、モデル呼び出しなど、実際の使用量がレスポンス後に判明する API に適しています。現在 `upto` を提供しているのは Base のみです。署名検証に失敗した場合は、chain id、facilitator アドレス、spender、USDC コントラクト、および Permit2 allowance が 402 レスポンスと一致しているか確認してください。
