X402 は HTTP `402 Payment Required` に基づくオンチェーン支払いプロトコルです。Ace Data Cloud の X402 機能を通じて、呼び出し元は API トークンを作成せず、アカウントの残高を事前にチャージすることなく、毎回の API リクエストで直接 USDC を使用してオンチェーン支払いを行うことができます。

このドキュメントは、実際の接続順序に従って整理されています：まず最小リクエストを通して、次に SDK を接続し、その後ネットワーク、料金プラン、注文支払い、Facilitator を理解します。以下の表に従って上から下へ読むことをお勧めします。

| チュートリアル         | 適用シーン                                          | リンク                                                                                  |
| ------------------ | --------------------------------------------- | ------------------------------------------------------------------------------------- |
| クイックスタート         | 最小リクエストを使用して 402、`accepts` および `PAYMENT-SIGNATURE` フローを理解する | [X402 クイックスタート](https://platform.acedata.cloud/documents/x402-quickstart)             |
| TypeScript SDK     | ブラウザ、Node.js またはフロントエンドアプリで Ace Data Cloud API を呼び出す        | [TypeScript SDK 接続](https://platform.acedata.cloud/documents/x402-typescript-sdk) |
| Python SDK         | Python サービス、スクリプト、エージェントまたはデータパイプラインで API を呼び出す  | [Python SDK 接続](https://platform.acedata.cloud/documents/x402-python-sdk)         |
| 注文支払い             | X402 を使用して Ace Data Cloud コンソールの注文を支払う                | [注文支払いチュートリアル](https://platform.acedata.cloud/documents/x402-order-payment)             |
| ネットワークと支払い方法    | Base、SKALE、Solana の資産、署名および適用シーンを理解する                | [ネットワークと支払い方法](https://platform.acedata.cloud/documents/x402-networks)                 |
| `exact` と `upto` | 固定価格 API と使用量後払い API を区別する                          | [料金プラン説明](https://platform.acedata.cloud/documents/x402-metered-upto)              |

| E2E とトラブルシューティング  | 公開エンドポイントを確認し、高度な検証ツールを実行して一般的な 402、署名および決済の問題を特定する | [E2E 検証とトラブルシューティング](https://platform.acedata.cloud/documents/x402-e2e-troubleshooting)  |

## 推奨接続パス

Ace Data Cloud API を呼び出したいだけの場合は、公式 SDK を優先して使用してください：

- TypeScript：`@acedatacloud/sdk` + `@acedatacloud/x402-client`
- Python：`acedatacloud` + `acedatacloud-x402`

公開ソースコードとパッケージのアドレス：

| プロジェクト             | アドレス                                                                                                               |
| -------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Ace Data Cloud SDK   | [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)                                         |
| X402 Client          | [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)                           |
| X402 Facilitator     | [https://github.com/AceDataCloud/FacilitatorX402](https://github.com/AceDataCloud/FacilitatorX402)                 |
| npm SDK              | [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)                 |
| npm X402 Client      | [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client) |
| PyPI SDK             | [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)                                   |
| PyPI X402 Client     | [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)                         |

SDK は最初の認証なしリクエスト、`402 Payment Required` の解析、支払いハンドラーの呼び出し、`PAYMENT-SIGNATURE` を持ってこれらのステップを再試行することを自動的に行います。あなたは USDC を持つウォレットを準備し、使用したいネットワークを選択するだけです。

自分の API でも X402 受取をサポートさせたい場合は、Facilitator ドキュメントを読み、`paymentRequirements`、`paymentPayload`、`/verify` および `/settle` の関係を理解する必要があります。

Ace Data Cloud X402 は公開 API、公式 SDK、Facilitator およびオンチェーン決済パスで検証を完了しました。以下の表は、開発者が接続時に最もよく使用する機能の次元に基づいて現在の状況をまとめています。

## 接続時の注意事項

開発者が接続する際は、ドキュメント内のサンプル金額やアドレスをコピーするのではなく、現在のリクエストが返すリアルタイムの支払い要件に優先的に注意してください：

- `accepts[].maxAmountRequired` は現在のリクエストで署名可能な最大金額です。
- `accepts[].asset` は今回のリクエストで使用する USDC コントラクトまたはミントです。
- `accepts[].extra.chainId`、`accepts[].extra.facilitatorAddress` および `accepts[].extra.verifyingContract` は EVM タイプデータの署名に関与します。
- `upto` では、ウォレットが最初にターゲットチェーンの USDC に対して Permit2 を承認する必要があります。未承認の場合は `PERMIT2_ALLOWANCE_REQUIRED` が返されます。
- 明示的に後置計量を使用したい場合は、TypeScript SDK に `preferScheme: 'upto'` を渡してください。そうでない場合、SDK はそのネットワークでサーバーが返した最初の利用可能な要件を選択します。

## 公開検証可能な範囲

接続前にこれらの公開エンドポイントと SDK の動作を検証できます：

- `Authorization` または `PAYMENT-SIGNATURE` を持たない API リクエストは `402 Payment Required` を返し、レスポンス内の `accepts` は今回のリクエストの唯一の署名根拠です。
- TypeScript SDK と Python SDK はどちらも支払いハンドラーを提供し、SDK のトランスポート層は 402 を受け取るとハンドラーを呼び出し、再試行を行います。
- `https://facilitator.acedata.cloud/.well-known/x402`：ファシリテーターがサポートするネットワーク、スキーム、およびプロトコルエンドポイントを返します。API 価格は依然としてターゲットリクエストがリアルタイムで返す 402 に基づきます。
- `https://facilitator.acedata.cloud/supported`：ファシリテーターがサポートするネットワークとスキームを返します。
- X402Client リポジトリには、高度なチェーン上検証ツールが含まれており、署名、再試行、および決済動作を確認するために使用できます。ツールの出力はオンライン API が返す `accepts` を代替するものではありません。

`upto` は後置計量決済に属し、チャット補完、モデル呼び出しなど、実際の使用量が応答後にのみわかる API に適しています。現在、Base のみが `upto` を提供しています。署名検証が失敗した場合は、チェーン ID、ファシリテーターアドレス、支出者、USDC コントラクト、および Permit2 アローワンスが 402 レスポンスと一致しているか確認してください。
