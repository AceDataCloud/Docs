Service UUID を通じてページネーションで、そのサービスで現在有効かつ非推奨ではない API を返します。alias のみがある場合は、まず[サービス詳細](https://platform.acedata.cloud/documents/platform-service-detail)を呼び出して `id` を取得します。

## インターフェース概要

| 項目   | 内容                                                                  |
| --- | ------------------------------------------------------------------- |
| メソッド  | `GET`                                                               |
| URL | `https://platform.acedata.cloud/api/v1/services/{service_id}/apis/` |
| 認証  | 公開、アカウントトークン不要                                                           |
| ページネーション  | `count` + `items`                                                   |

## パラメータ

| パラメータ           | 位置    | 必須  | 説明                               |
| ------------ | ----- | --- | -------------------------------- |
| `service_id` | path  | はい   | Service UUID、alias はサポートされない           |
| `limit`      | query | いいえ   | 1 ページあたりの件数、最大 100                      |
| `offset`     | query | いいえ   | ページネーションのオフセット                            |
| `ordering`   | query | いいえ   | Django のソート式；`rank` または `-rank` を推奨 |

現在、このインターフェースは `stage` フィルタリングをサポートしていません；すでに `Deprecated` API を除外しています。

```shell
export SERVICE_ID='あなたの Service ID'
curl --get "https://platform.acedata.cloud/api/v1/services/${SERVICE_ID}/apis/" \
  --data-urlencode 'limit=100' \
  --data-urlencode 'ordering=rank' \
  -H 'Accept: application/json'
```

リスト項目は[プラットフォーム API 一覧](https://platform.acedata.cloud/documents/platform-api-list)と同じインデックス構造を使用し、現在は `definition` を含みます。単一の API に対する安定したエントリが必要な場合は、引き続き `/api/v1/apis/{api_id}` を呼び出してください。

## エラー処理

- サービスが存在しない、または現在のサイトから見えない：`404`。
- `service_id` は UUID である必要があります；alias はこの action では解決されません。
