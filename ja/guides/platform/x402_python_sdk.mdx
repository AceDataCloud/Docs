Python SDK は、バックエンドサービス、データタスク、自動化 Agent、バッチ処理スクリプトに適しています。`acedatacloud` は API 呼び出しを担当し、`acedatacloud-x402` は `PAYMENT-SIGNATURE` リクエストヘッダーの署名を担当します。

ソースコードとパッケージのアドレス：

- SDK リポジトリ：[https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- X402 Client リポジトリ：[https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- PyPI SDK：[https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)
- PyPI X402 Client：[https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)

## 依存関係のインストール

```bash
pip install acedatacloud acedatacloud-x402
```

`upto` を使用する場合は、Permit2 approve CLI を一度呼び出す必要があり、この CLI は `web3` に依存します：

```bash
pip install 'acedatacloud-x402[cli]'
```

クリーンな Python venv でのインストールおよびインポート確認出力：

```text
acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
approve-permit2  One-time ERC-20 approve(Permit2, amount) needed before signing upto payments.
```

結果の説明：

- `acedatacloud` と `acedatacloud-x402` はどちらも PyPI からインストールおよびインポートできます。
- `pip install 'acedatacloud-x402[cli]'` は `approve-permit2` CLI を含め、`upto` の事前承認に使用します。

## Base の例

以下の例では API Token は不要です。ウォレットの秘密鍵はローカルでの署名にのみ使用され、Ace Data Cloud には送信されません。

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)

print(res["choices"][0]["message"]["content"])
```

Python SDK は現在 `dict` を返すため、例では `res["choices"][0]["message"]["content"]` を使用しています。必ず `.choices` 属性を持つと直接仮定しないでください。

## Solana の例

Solana は base58 エンコードされた secret key を使用します：

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import SolanaKeypairSigner, create_x402_payment_handler

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="solana",
        solana_signer=SolanaKeypairSigner.from_base58(os.environ["SOLANA_SECRET_KEY"]),
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

Solana のパスでは、SPL USDC の `TransferChecked` トランザクションを構築して送信し、その後トランザクション署名を `PAYMENT-SIGNATURE` envelope に格納します。

Solana paid retry は本番 API で HTTP 200 と `ADC_SOLANA_E2E_OK` を返しています。今回の公開 RPC クエリではレート制限が発生し、オンチェーン signature を安定して確認できませんでした。照合が必要な場合は、自身の Solana RPC を使用してそのトランザクションを照会してください。

## Async クライアント

同じ payment handler は `AsyncAceDataCloud` にも使用できます：

```python
import os

from acedatacloud import AsyncAceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AsyncAceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = await client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

## `upto` 後払い計量の使用

チャット補完、モデル呼び出しなどの API の実際のコストは、レスポンスが完了するまで判明しない場合があります。この場合、API は `exact` と `upto` を同時に返す可能性があります。`upto` を優先して使用する場合：

```python
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
        prefer_scheme="upto",
    )
)
```

Base `upto` のプログラム実行結果：

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
settlement tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
settled value 3 atomic USDC
```

オンチェーン確認：

```text
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
transfer value 3 atomic USDC
```

結果の説明：

- `content ADC_BASE_UPTO_OK` は、リクエストが実際にモデル API に到達したことを示します。
- `settled value 3 atomic USDC` は、`upto` が上限全額を差し引くのではなく、実際の使用量に応じて決済することを示します。
- `settlement tx` は BaseScan で開くことができ、照合時には tx hash、payer、completion id、リクエスト要約を保存してください。

`upto` は Permit2 を使用して上限額を承認し、実際の決済額はこの上限を超えることはできません。初回使用前に、対象チェーン上の USDC に対して一度 `approve(Permit2, amount)` を行う必要があります。

CLI 方式：

```bash
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

プログラム方式：

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

この helper は冪等です。allowance がすでに十分である場合、`{"skipped": true}` を返し、オンチェーントランザクションを重複して送信しません。

## 低レベル署名

SDK を使用しない場合でも、低レベル署名関数を直接呼び出せます：

```python
import base64
import json

from acedatacloud_x402 import EVMAccountSigner, sign_evm_payment

envelope = sign_evm_payment(requirement, EVMAccountSigner.from_private_key("0x..."))
x_payment = base64.b64encode(json.dumps(envelope, separators=(",", ":")).encode()).decode()
```

低レベル関数は、テスト、プロキシレイヤー、ゲートウェイ統合、または公式 SDK 以外での利用に適しています。通常の業務コードでは `create_x402_payment_handler` を優先して使用してください。
