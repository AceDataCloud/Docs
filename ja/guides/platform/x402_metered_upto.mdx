---
title: "X402 の `exact` および `upto` 課金スキーム"
description: "Platform API guide - Ace Data Cloud"
---

Ace Data Cloud X402 は現在、`exact` と `upto` の 2 種類の scheme を使用しています。これらは異なる課金問題を解決します。

## `exact`

`exact` は、今回のリクエストの価格が対象 API に到達する前に確定できることを意味します。クライアントが署名する金額が最終的な引き落とし金額です。

適しているケース：

- 固定価格の画像生成；
- 固定価格の動画タスク作成；
- 固定価格の検索またはツール API；
- 注文支払い。

EVM `exact` は USDC EIP-3009 `TransferWithAuthorization` を使用します：

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "exact",
    "network": "eip155:8453"
  },
  "payload": {
    "authorization": {
      "from": "0x...",
      "to": "0x...",
      "value": "95215",
      "validAfter": "1780237345",
      "validBefore": "1780240945",
      "nonce": "0x..."
    },
    "signature": "0x..."
  }
}
```

Facilitator は `/verify` 段階で署名と金額を検証し、`/settle` 段階でこの承認をチェーン上に送信します。

## `upto`

`upto` は、クライアントが最大上限を承認し、Ace Data Cloud がリクエスト完了後に実際の使用量に基づいて決済することを意味します。実際の引き落とし額は上限を超えることはできません。

適しているケース：

- チャット補完：最終価格は prompt tokens と completion tokens に依存します；
- ストリーミング応答：実際の出力長が終了するまでわかりません；
- 将来の後払い計量 API。

`upto` は Permit2 `PermitWitnessTransferFrom` を使用します。クライアントが署名するのは固定送金ではなく、witness を伴う上限承認です：

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "upto",
    "network": "eip155:8453"
  },
  "payload": {
    "permit2Authorization": {
      "from": "0x...",
      "spender": "0x4020A4f3b7b90ccA423B9fabCc0CE57C6C240002",
      "nonce": "123456789",
      "deadline": "1780240945",
      "permitted": {
        "token": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
        "amount": "95215"
      },
      "witness": {
        "to": "0x...",
        "facilitator": "0x...",
        "validAfter": "1780237345"
      }
    },
    "signature": "0x..."
  }
}
```

`permitted.amount` は上限であり、最終的な引き落とし額とは限りません。Gateway は `/record` 段階で実際の使用量を `amount` に変換して Facilitator に渡します。Facilitator は `amount &lt;= permitted.amount` の決済のみを許可します。

Base `upto` のプログラム実行結果：

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
signed ceiling 95215 atomic USDC
transfer value 3 atomic USDC
```

説明：

- 402 で返される承認上限は `95215` atomic USDC であり、クライアントはこの上限で署名します。
- モデルが実際に応答した後、`3` atomic USDC のみが決済され、オンチェーン取引はすでに BaseScan で確認できます。
- この結果は `upto` の重要な違いを示しています：署名金額は上限であり、オンチェーン settlement は上限を下回ることができます。
- 実際の使用量が上限を超える場合、Facilitator は settlement を拒否すべきであり、クライアントはより高い上限で再度承認する必要があります。

`upto` は現在 Base でのみ提供されています。後払い計量が必要な場合は、Base を使用してください。

## Permit2 approve が必要な理由

`upto` は最終的に x402 proxy により Permit2 を通じて支払いウォレットから USDC を引き出します。初回使用前に、支払いウォレットは Permit2 に一度 ERC-20 allowance を付与する必要があります。

Python CLI：

```bash
pip install 'acedatacloud-x402[cli]'
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

プログラムによる方法：

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

承認完了後も、nonce、deadline、witness、および金額上限はすべて異なるため、各リクエストでは引き続き新しい `upto` envelope に署名する必要があります。

## ゼロ金額決済

`upto` は実際の金額が 0 のケースをサポートします。たとえば、対象 API が課金可能な使用量を正常に生成しなかった場合、Gateway は `amount = "0"` を渡すことができます。Facilitator は成功を返しますが、オンチェーン取引は送信しません。

これにより、「リクエストが成功しなかったにもかかわらずオンチェーン料金が引き落とされる」という問題を回避できます。

## 選択の推奨

| シナリオ                   | 推奨                       |
| ------------------------ | ------------------------ |
| 固定価格 API                | `exact` を使用します。ロジックが簡単です。 |
| 注文支払い                  | `exact` を使用します。           |
| チャット補完、token 単位の課金    | Base `upto` を使用します。      |
| まだ Permit2 approve をしていない | まず `exact` で動作確認し、その後 `upto` に切り替えます。 |

どちらを選ぶべきかわからない場合は、まず SDK のデフォルト動作を使用してください；SDK はサーバーが返す一致するネットワークの payment requirement を選択します。

## Base `upto` チェックリスト

統合またはトラブルシューティング時は、以下のパラメータが同一の 402 応答から取得され、クライアント署名時に一貫していることを確認してください：

| パラメータ                     | チェックポイント                                      |
| ---------------------------- | ---------------------------------------------- |
| `network`                    | `eip155:8453` である必要があります。                       |
| `scheme`                     | `upto` である必要があります。                              |
| `extra.chainId`              | Base chain id は `8453` です。                    |
| `asset`                      | 402 応答内の Base USDC コントラクトアドレスを使用します。             |
| `extra.facilitatorAddress`   | witness に含まれる必要があり、Facilitator の `/supported` と一致する必要があります。 |
| Permit2 allowance            | 支払いウォレットは事前に Base USDC について Permit2 を承認する必要があります。 |

よくあるエラーと対処方法：

| エラー                                           | 対処方法                                                                          |
| ---------------------------------------------- | ----------------------------------------------------------------------------- |
| `invalid_upto_evm_payload_invalid_signature` | chain id、facilitator アドレス、Permit2 domain、spender、署名アカウント、および witness が 402 応答と一致しているか確認してください。 |
| `PERMIT2_ALLOWANCE_REQUIRED`                 | 対象チェーンの USDC に対して Permit2 approve を実行した後、リクエストを再度開始してください。                              |
| `amount exceeds permitted amount`            | 実際の使用量が署名上限を超えています。より高い上限で再度署名する必要があります。                                              |
