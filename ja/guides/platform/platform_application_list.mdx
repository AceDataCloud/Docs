アカウントが所有している、または使用を許可されている Application を、残高、ステータス、サービス概要、関連する認証情報とともにページネーションで返します。一括残高監視、Application ID の検索、認証情報管理へのアクセスに適しています。

## 準備作業

1. [AceDataCloud プラットフォーム](https://platform.acedata.cloud)にログインします。
2. [Account Token コンソール](https://platform.acedata.cloud/console/platform-tokens)でアカウントトークンを作成します。
3. 一般ユーザーは `user_id=me` を使用します。`GET /api/v1/platform-tokens/me/` から自身の UUID を取得することもできます。

```shell
export PLATFORM_TOKEN='あなたのアカウントトークン'
```

## API 概要

| 項目   | 内容                                                    |
| --- | ----------------------------------------------------- |
| メソッド  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| 認証  | Account Token、OAuth token には `applications:read` が必要       |
| ページネーション  | `count` + `items`                                     |

一般ユーザーは `user_id=me` を指定する必要があります。指定しない場合、クエリは最初にアカウントで絞り込まれず、ページネーション中に権限のないオブジェクトに遭遇すると `403` が返される可能性があります。管理者は指定しない場合、テーブル全体を表示できます。

## クエリパラメータ

| パラメータ            | 型          | 必須     | 説明                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | 一般ユーザーは必須 | クエリ対象；繰り返しパラメータをサポート                                         |
| `affiliation` | string      | いいえ      | `owner`（デフォルト）または `granted`；両方を繰り返し渡して和集合を取得でき、`user_id` がある場合にのみ有効 |
| `service_id`  | UUID        | いいえ      | サービスでフィルタリング；繰り返しパラメータをサポート                                        |
| `scope`       | string      | いいえ      | `Individual` または `Global`；繰り返しパラメータをサポート                      |
| `type`        | string      | いいえ      | `Usage` または `Period`；繰り返しパラメータをサポート                           |
| `limit`       | integer     | いいえ      | 1 ページあたりの件数、最大 100                                         |
| `offset`      | integer     | いいえ      | ページネーションのオフセット                                               |
| `ordering`    | string      | いいえ      | `created_at` または `-created_at` のみサポート                    |

`paid`、`disabled`、`expired`、`low_balance`、および `tag` は現在サーバー側のフィルタリングパラメータではありません。残高アラートでは、一覧を取得した後、各 Application の `remaining_amount`、`service.unit`、および業務上のしきい値に基づいてクライアント側で判断する必要があります。

## リクエスト例

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

自身が所有する Application と、他者から自身に許可された Application を同時に表示するには：

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## レスポンスの説明

レスポンスは `{count, items}` です。各項目には Application モデルフィールドに加えて、以下が含まれます：

- `service`：`id`、`alias`、`title`、`type`、`unit`、`icon_url`；
- `credentials`：現在の呼び出し元が閲覧権限を持つ認証情報の概要；
- `paid`、`remaining_amount`、`used_amount`、`disabled`、`allow_consume_global`、`allow_overdraft`；
- `scope` の実際の値は `Individual` または `Global`；
- `type` の実際の値は `Usage` または `Period`。

`allow_overdraft` は管理者が制御する読み取り専用のブールフィールドであり、デフォルトは `false` です。透過が有効化されている従量制（`Usage`）アプリケーションでは、残高不足でも呼び出しはブロックされず、実際の使用量に応じて引き続き課金されます。負の残高は、決済待ちの利用枠を表します。無効化、有効期限切れ、および API 認証情報の上限は引き続き有効です。

`remaining_amount` は空である可能性があります。クライアントは数値比較を行う前に、必ず null を確認する必要があります。利用枠の単位は `service.unit` によって決まります。
