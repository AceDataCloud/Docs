`Pending` 注文の支払いセッションを作成または更新します。支払いアクションは支払いチャネルにアクセスし、注文状態を変更する可能性があるため、呼び出す前に注文 ID、金額、支払い方法を確認する必要があります。

## API 概要

| 項目   | 内容                                                             |
| ---- | -------------------------------------------------------------- |
| メソッド   | `POST`                                                         |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/` |
| 認証   | ホスト型リダイレクト決済は匿名で可能；その他の方法にはログイン状態または Account Token が必要                            |
| Body | JSON、未払い注文は `pay_way` を指定する必要があります                                       |

## 匿名支払いの境界

匿名アクセスは、コピーされた支払いリンクを開いた後にログイン状態が失われたケースに使用され、長期 Account Token を携帯する必要はなく、また携帯すべきではありません。匿名呼び出し：

- サーバー側で設定されたホスト型リダイレクト決済方式のみ許可されます；
- 常にデスクトップ支払いページを使用します；
- 無料注文を受け取ることはできません；
- IP および単一注文ごとのレート制限を受けます；
- 最小限の注文プロジェクションを返し、アカウント、Application、または内部 metadata を含みません。

認証済みの呼び出し元は、注文所有者またはスーパー管理者である必要があります。X402、報酬交換など、ユーザーコンテキストを必要とする方式は匿名で呼び出すことができません。

## リクエスト例

```shell
export ORDER_ID='あなたの Pending 注文 ID'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"Stripe"}'
```

認証が必要な支払い方式：

```shell
export PLATFORM_TOKEN='あなたのアカウントトークン'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"X402"}'
```

`pay_way` には、注文モデルでサポートされている実際の値を使用します。例：`WechatPay`、`AliPay`、`Stripe`、`Card`、`Airwallex`、`X402`、`PayPal`、`AppleIAP`、`Reward`、`BankTransfer`。すべての値が匿名リクエストまたはすべてのサイトで利用できるわけではありません。

## レスポンス説明

成功レスポンスは更新後の注文オブジェクトであり、通常は `pay_url` によって次のステップの入口が提供されます；支払い方法によっては、制御されたフィールドにクライアントが支払いを継続するために必要な情報が返される場合もあります。匿名レスポンスは最小限のフィールドホワイトリストを使用し、認証された所有者は完全な詳細を取得します。

`payment_url`、`qr_code_url`、`payment_method` などの古いフィールド名に依存しないでください；現在の Order 契約では `pay_url` と `pay_way` を使用します。

## 銀行振込

ログイン済みの個人アカウントと法人アカウントのどちらも `BankTransfer` を使用でき、法人認証は不要です。中国国内の人民元振込および国際米ドル振込はいずれも、注文金額が少なくとも 300 米ドルである必要があります；人民元の支払い金額は、支払い時に表示される金額に従います。

支払い前に、`GET /api/v1/orders/{order_id}/payment-options/` を通じて、現在の注文で利用可能な振込ルートおよび金額しきい値を確認できます。銀行振込は注文所有者がログイン後に開始する必要があり、受取チャネルの設定およびプランの適用範囲による制限を受けます；匿名リクエストでは使用できません。

## iOS アプリ内課金

ログイン済みの注文所有者は `pay_way: "AppleIAP"` を渡すことができます。このリクエストは、選択されたプランの `metadata.apple_price` に従って未払い注文を更新し、割引をクリアします。課金は発生せず、クレジットも付与されず、支払いリンクも返されません。古い未払い注文は、まずこのステップを完了してから、Apple ネイティブ決済を開始する必要があります。Apple 商品と価格が設定された Usage プランを 1 つのみサポートします；サポートされていないプランまたは一括注文は `400` を返します。

Apple ネイティブ決済後、`/api/v1/orders/{id}/apple-verify/` を通じて `transaction_id` を送信し、サーバー側の検証とクレジット付与を完了します。クレジット数はプランに基づきます；金額には Apple の独立した米ドルのプリセット価格が使用され、会員割引またはサイト上乗せ料金は加算されません。その他の地域における現地通貨での課金額は、Apple の確認ページに従います。

## エラーと再試行

- 注文が `Pending` ではない：`400` を返します；支払いセッションを繰り返し作成しないでください。
- `pay_way` が指定されていない：ゼロ以外の金額の注文は `400` を返します。
- 匿名呼び出しで許可されていない方式または無料注文を使用した：`403` を返します。ログイン後、所有者が再試行してください。
- 認証済みだが注文所有者ではない：`403` を返します。
- 支払いチャネルが失敗した：むやみに繰り返し送信しないでください；まず注文詳細を照会し、依然として `Pending` であることを確認してから再試行してください。
