`Pending` 注文の支払いセッションを作成または更新します。支払いアクションは支払いチャネルにアクセスし、注文状態を変更する可能性があります。呼び出す前に、注文 ID、金額、支払い方法を必ず確認してください。

## インターフェース概要

| 項目    | 内容                                                             |
| ---- | -------------------------------------------------------------- |
| メソッド   | `POST`                                                         |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/` |
| 認証   | ホスト型リダイレクト支払いは匿名で可能です。その他の方法にはログイン状態または Account Token が必要です                            |
| Body | JSON、未払い注文では `pay_way` の指定が必須です                                       |

## 匿名支払いの境界

匿名アクセスは、コピーした支払いリンクを開いた後にログイン状態が失われたシナリオ向けであり、長期 Account Token を携帯する必要はなく、携帯すべきでもありません。匿名呼び出しでは：

- サーバー側で設定されたホスト型リダイレクト支払い方法のみ許可されます；
- 常にデスクトップ支払いページが使用されます；
- 無料注文を受け取ることはできません；
- IP および単一注文ごとのレート制限を受けます；
- アカウント、Application、または内部 metadata を含まない最小限の注文プロジェクションが返されます。

認証済みの呼び出し元は、注文所有者またはスーパー管理者である必要があります。X402、報酬交換など、ユーザーコンテキストを必要とする方法は匿名で呼び出せません。

## リクエスト例

```shell
export ORDER_ID='你的 Pending 订单 ID'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"Stripe"}'
```

認証が必要な支払い方法：

```shell
export PLATFORM_TOKEN='你的账户令牌'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"X402"}'
```

`pay_way` には、`WechatPay`、`AliPay`、`Stripe`、`Card`、`Airwallex`、`X402`、`PayPal`、`AppleIAP`、`Reward`、`BankTransfer` など、注文モデルでサポートされる実際の値を使用します。すべての値が匿名リクエストまたはすべてのサイトで利用可能とは限りません。

## レスポンスの説明

成功レスポンスは更新後の注文オブジェクトであり、通常は `pay_url` を通じて次のステップへの入口を提供します。支払い方法によっては、制御されたフィールド内でクライアントが支払いを継続するために必要な情報が返される場合もあります。匿名レスポンスでは最小限のフィールドホワイトリストが使用され、認証済みの所有者は完全な詳細を取得します。

`payment_url`、`qr_code_url`、`payment_method` などの旧フィールド名に依存しないでください。現在の Order 契約では `pay_url` と `pay_way` を使用します。

## iOS アプリ内課金

ログイン済みの注文所有者は `pay_way: "AppleIAP"` を渡すことができます。このリクエストは、選択したプランの `metadata.apple_price` に従って未払い注文を更新し、割引をクリアします。課金は発生せず、クレジットも付与されず、支払いリンクも返されません。古い未払い注文では、Apple ネイティブ支払いを開始する前にこのステップを完了する必要があります。設定済みの Apple 商品と価格を持つ Usage プランのみがサポートされます。サポートされていないプランまたは一括注文は `400` を返します。

Apple ネイティブ支払い後、`/api/v1/orders/{id}/apple-verify/` を通じて `transaction_id` を送信し、サーバー側の検証とクレジット付与を完了します。クレジット数はプランに基づきます。金額には Apple の独立した米ドル固定価格が使用され、会員割引やサイト加算額は重複適用されません。その他の地域での現地通貨の課金額は、Apple の確認画面に従います。

## エラーと再試行

- 注文が `Pending` ではない：`400` が返されます。支払いセッションを繰り返し作成しないでください。
- `pay_way` が提供されていない：ゼロ以外の金額の注文では `400` が返されます。
- 匿名呼び出しで許可されていない方法または無料注文が使用された：`403` が返されます。ログイン後に所有者が再試行してください。
- 認証済みでも注文所有者ではない：`403` が返されます。
- 支払いチャネルが失敗した：むやみに繰り返し送信しないでください。まず注文詳細を照会し、引き続き `Pending` であることを確認してから再試行してください。
