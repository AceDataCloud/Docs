このチュートリアルでは、最小限の API リクエストを使って Ace Data Cloud X402 の完全なフローを説明します。目的は先に複雑なコードを書くことではなく、まず理解することです：なぜ最初のリクエストは 402 を返すのか、`accepts` には何があるのか、そして `PAYMENT-SIGNATURE` はどのようにして同じ API リクエストを支払い済みリクエストに変えるのか。

## 準備

以下を準備する必要があります：

| 項目   | 説明                                                   |
| ---- | ---------------------------------------------------- |
| ウォレット   | 対象ネットワークをサポートするウォレット。Base は EVM ウォレット、Solana は Solana ウォレットを使用します。      |
| USDC | ウォレットには十分な USDC が必要です。実際の金額は 402 レスポンス内の `maxAmountRequired` に従います。 |
| 開発環境 | TypeScript には Node.js 18+ を推奨；Python には Python 3.10+ を推奨します。    |
| SDK  | 公式 SDK の使用を推奨し、署名の詳細を手書きすることは推奨しません。                                |

X402 で Ace Data Cloud API を呼び出す際に API Token は不要です。SDK の最初のリクエストには `Authorization` が含まれず、Gateway は `402 Payment Required` と支払い要件を返します；SDK は署名後に自動で再試行します。

## SDK のインストール

ソースコードとパッケージのアドレス：

- SDK リポジトリ：[https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- X402 Client リポジトリ：[https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm：`@acedatacloud/sdk`、`@acedatacloud/x402-client`
- PyPI：`acedatacloud`、`acedatacloud-x402`

TypeScript：

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client ethers
```

Python：

```bash
pip install acedatacloud acedatacloud-x402
```

Solana を使用する場合は、対応する依存関係もインストールする必要があります：

```bash
npm install @solana/web3.js
```

Python バージョンの Solana signer 依存関係はすでに `acedatacloud-x402` に含まれています。

クリーンな一時環境でのインストールおよびインポート確認の出力：

```text
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4

```

結果の説明：

- npm パッケージと PyPI パッケージはいずれも実際に公開されているパッケージであり、ドキュメント内のプレースホルダー名ではありません。
- `acedatacloud-x402[cli]` は CLI をインストールし、`approve-permit2` サブコマンドは `upto` シナリオでの Permit2 承認に使用できます。

## 最初のリクエストは 402 を返します

まず `curl` を使って、未払いリクエストが何を返すか確認できます。以下の例では `PAYMENT-SIGNATURE` を含めていないため、課金は発生しません：

```bash
curl -sS -X POST https://x402.acedata.cloud/openai/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "hi"}],
    "max_tokens": 1
  }'
```

レスポンスボディには `accepts` 配列が含まれ、一般的な構造は以下のとおりです：

```json
{
  "x402Version": 2,
  "resource": {
    "url": "/openai/chat/completions",
    "description": "AceDataCloud API call",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "maxAmountRequired": "95215",
      "amount": "95215",
      "maxTimeoutSeconds": 3600,
      "resource": "/openai/chat/completions",
      "description": "...",
      "payTo": "0x...",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913"
      }
    }
  ],
  "error": "PAYMENT-SIGNATURE header is required"
}
```

同じチャレンジ内容は base64 形式でも `PAYMENT-REQUIRED` レスポンスヘッダーに格納され、クライアントが body を解析せずに支払い要件を読み取れるようになっています。

本番 API の未払いリクエストに対するプログラム出力の要約は以下のとおりです：

```text
status=402
x402Version 2
accepts [
  ('eip155:8453', 'exact', '95215'),
  ('eip155:8453', 'upto', '95215'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '95215'),
]
```

結果の説明：

- 最初のリクエストには `Authorization` または `PAYMENT-SIGNATURE` が含まれていないため、HTTP 402 が返され、課金は発生しません。
- `accepts` は今回のリクエストにおける唯一信頼できる署名の根拠であり、選択可能なネットワーク、scheme、金額上限、受取先アドレス、および資産アドレスを含みます。
- `network` は CAIP-2 識別子であり、クライアントはネットワークを選択する際に CAIP-2 文字列で一致させる必要があります。
- 今回の `gpt-4o-mini` の最小チャットリクエストの上限金額は `95215` atomic USDC、つまり `0.095215` USDC です。
- 毎回のリクエストでその時の 402 レスポンスを読み取るべきであり、サンプル金額を業務コードにハードコードしないでください。

フィールドの意味：

| フィールド                  | 説明                                                             |
| ------------------- | -------------------------------------------------------------- |
| `scheme`            | 支払いスキーム。`exact` は固定金額を表し、`upto` は承認上限を表し、実際の使用量に応じて精算されます。                     |
| `network`           | 支払いネットワークの CAIP-2 識別子。例：`eip155:8453`、`solana:5eykt4...`。           |
| `maxAmountRequired` | 最大支払い金額。単位は USDC atomic units であり、`95215` は `0.095215` USDC を表します。       |
| `amount`            | 今回精算する金額；`exact` は `maxAmountRequired` と同じであり、`upto` は精算段階で実際の使用量に応じて書き換えられます。 |
| `payTo`             | 受取先アドレス。                                                          |
| `asset`             | USDC コントラクトアドレスまたは Solana mint アドレス。                                     |
| `extra`             | 署名に必要なチェーン ID、EIP-712 domain、Permit2 アドレスなどの拡張情報。                      |

## SDK を使用して支払い再試行を完了する

以下は最小の TypeScript の例です。`network: 'base'` を指定しており、handler は今回の 402 レスポンスから Base の payment requirement を選択します；実際の金額と受取先アドレスは引き続き `accepts` に従います：
```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const response = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Reply with exactly: hello' }],
  max_tokens: 8
});

console.log(response.choices[0].message.content);
```

このコードの背後では、4つのステップが発生します：

1. SDK は、`Authorization` を付けずに通常の API リクエストを送信します。
2. Gateway は `402 Payment Required` と `accepts` を返します。
3. `createX402PaymentHandler` は `network = 'base'` の payment requirement を選択し、`PAYMENT-SIGNATURE` を署名します。
4. SDK は同じリクエストボディで再試行し、Gateway は Facilitator を呼び出して検証と決済を行った後、対象 API へのアクセスを許可します。

## Facilitator のサポート機能を確認する

X402 API はリソースディレクトリに依存しません。クライアントは既知の API を直接呼び出し、そのリクエストによってリアルタイムで返される
`402 Payment Required` と `accepts` を唯一の価格および署名の根拠とします。

Facilitator の機能宣言は以下にあります：

```bash
curl https://facilitator.acedata.cloud/.well-known/x402
```

これは `/supported`、`/verify`、`/settle` および現在有効な支払いネットワークのみを説明しており、API リソースは列挙しません。

Ace Data Cloud の本番 Facilitator アドレスは以下です：

```text
https://facilitator.acedata.cloud
```

サポートしているネットワークと scheme は以下で確認できます：

```bash
curl https://facilitator.acedata.cloud/supported
```

返される `kinds` には、Facilitator がサポートするネットワークと scheme が列挙されます。実際の呼び出し時には、引き続き API が返す `accepts` を基準とします。

Facilitator の `/supported` 出力：

```text
kinds [
  ('eip155:8453', 'exact'),
  ('eip155:8453', 'upto', {'facilitatorAddress': '0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708'}),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact')
]
```

結果の説明：

- `/supported` は、Facilitator がこれらのネットワークと scheme の検証・決済機能を備えていることを示します。
- Base と Solana はどちらも `exact` をサポートしています。`upto` は現在 Base でのみ提供されています。
- 特定の API があるネットワークを許可するかどうかは、引き続きその API の 402 `accepts` を基準とします。
