このドキュメントでは、X402 を使用して Ace Data Cloud API を呼び出す際に、価格がどのように設定されるか、またプラットフォームの通常の **Credits**（クレジット）価格とどのような関係にあるかを説明します。

## 核心的な結論

X402 は独立した価格体系ではありません。各 API 呼び出しにはもともと **Credits** で表されるコストがあり、これはすべての課金方式（API Token によるクレジット消費、アカウント残高、X402 オンチェーン決済）で共通する唯一の価格ソースです。X402 はこの Credits コストを固定為替レートでオンチェーン USDC に換算しているだけです：

> **1 Credit = 0.095215 USDC**（すなわち `95215` atomic USDC、USDC は小数点以下 6 桁）

つまり：

```text
X402 価格 (USDC) = その呼び出しの Credits コスト × 0.095215
```

この為替レートは恣意的に設定されたものではなく、プラットフォームの **最優遇階層（大口）Credits 単価**に等しいものです。そのため、X402 で支払うこと ≈ 最優遇階層の単価で Credits を購入してから消費することとなり、**X402 の割増料金はありません**。むしろ、最も安い Credits 単価が直接適用され、事前チャージも API Token も不要です。

## 価格設定の基準

| 項目        | 値                              | 説明                                                    |
| --------- | ------------------------------ | ----------------------------------------------------- |
| 換算レート      | `1 Credit = 0.095215 USDC`     | プラットフォームで一律に設定された固定レート                                           |
| atomic 単位 | `1 Credit = 95215 atomic USDC` | USDC は小数点以下 6 桁、`atomic = floor(credits × 0.095215 × 1e6)` |
| 最小請求      | `1 atomic USDC`（$0.000001）     | コストが非常に低い場合でも、最低 1 atomic が決済される                                 |
| 請求通貨      | USDC                           | Base は ERC-20 USDC、Solana は SPL USDC                  |

換算はプラットフォームで一律に行われ、金額は対応するすべてのネットワーク（Base、Solana）で同一です。ネットワークごとに異なるのはアセットコントラクトと署名方式のみであり、価格は同じです。

### 通常の Credits 単価との関係

プラットフォームの Credits は、「利用量が多いほど、単価が低くなる」段階制で販売されます。X402 の呼び出しごとの課金では、一律で最優遇階層の単価が使用されます：

| 購入/支払い方式        | おおよその Credits 単価            | 説明                   |
| -------------- | ------------------------ | -------------------- |
| 入門 / 少額チャージ      | 約 `$0.13 / Credit`       | リスト価格、少額で Credits を購入する際の単価 |
| 大口 / 最優遇階層       | `$0.095215 / Credit`     | 最も安い単価               |
| **X402 呼び出しごとの支払い** | **`$0.095215 / Credit`** | **常に最優遇階層の単価と等しい**        |

言い換えると、X402 はすべての呼び出しを最優遇階層の Credits 単価で決済します。少額チャージで Credits を購入するユーザーの単価は X402 より高くなり、大口チャージのユーザーの単価のみが X402 と一致します。

## 2 種類の価格形態：`exact` と `upto`

X402 の 402 レスポンスにおいて、`maxAmountRequired` は署名する必要がある金額です。これには 2 種類の形態があります：

- **`exact`（固定価格）**：リクエスト処理前に価格を確定できるもの（画像、動画、音楽、検索、注文決済）。`maxAmountRequired = その呼び出しの Credits コスト × 0.095215`、すなわちその呼び出しで支払うべき金額です（成功レスポンス内の `cost.amount` と一致します）。
- **`upto`（利用量の後払い計測）**：チャット補完のような「レスポンス終了時に初めて何 token 使用したか分かる」インターフェース。`maxAmountRequired` は**上限**です（そのモデルに設定された上限クレジットを換算：上限 Credits × 0.095215）。実際には実使用量に応じて決済され、上限を超えることはありません。

これら 2 種類の scheme のプロトコル詳細については、[`exact` と `upto` 課金方式](https://platform.acedata.cloud/documents/x402-metered-upto)をご覧ください。以下では価格のみを説明します。

## Chat（チャット補完）価格

チャット補完は `upto` 計測です：prompt / completion token の実際の使用量に応じて課金されます。100 万（1M）token あたりの価格 = `そのモデルの 1M token あたりの Credits コスト × 0.095215` であり、プラットフォームの公開モデルカタログ（`/api/v1/models?with_pricing=true`）に表示される USD 単価と完全に一致します。

以下の表は実際の価格です（モデルカタログから取得し、X402 の為替レートで計算）。単位は USD / 1M token：

| モデル                | 入力 / 1M | 出力 / 1M  | `upto` 上限             |
| ----------------- | ------- | -------- | --------------------- |
| gpt-4o-mini       | $0.0796 | $0.3183  | 1 Credit（$0.095215）   |
| gemini-2.5-flash  | $0.1591 | $1.3262  | 5 Credits（$0.476074）  |
| gpt-5 / gpt-5.1   | $0.6631 | $5.3050  | 20 Credits（$1.904299） |
| gemini-2.5-pro    | $0.6631 | $5.3050  | 50 Credits（$4.760750） |
| gpt-4.1           | $1.0610 | $4.2440  | 20 Credits（$1.904299） |
| claude-sonnet-4-5 | $0.6006 | $3.0028  | 50 Credits（$4.760750） |
| grok-4            | $1.5915 | $7.9574  | 10 Credits（$0.952149） |
| claude-opus-4-1   | $3.0028 | $15.0140 | 50 Credits（$4.760750） |

説明：

- 表内は token ごとの従量単価です。1 回のリクエスト料金 = 入力 token × 入力単価 + 出力 token × 出力単価。
- `upto` 上限は、そのモデルで 1 回のリクエストに対して署名できる最大金額です。実際の請求額ではなく、大半のリクエストは上限を大きく下回ります。
- 上限は「最大でいくら請求される可能性があるか」のみを決定し、実際の決済は token 使用量に基づいて計算されます。

### 例：見積もりと請求額は一致する（`exact`）

以下は、公式 X402Client を使用して `serp/google` に対して行った**実際の有料呼び出し**です（Base `exact`）。これは、402 の見積もり、署名金額、および成功レスポンスで返される `cost` の 3 つが一致することを示しています。

```text
# 1) 未決済リクエスト -> 402、見積もりを取得（請求なし）
POST /serp/google  ->  402
base/exact maxAmountRequired = 952 atomic = $0.000952 = 0.01 Credit
# 0.01 × 0.095215 = 0.00095215、atomic に切り捨て = 952

# 2) ウォレットで 952 atomic の PAYMENT-SIGNATURE に署名し、再試行
POST /serp/google (PAYMENT-SIGNATURE) -> 200
body.cost = {"amount": 0.000952, "currency": "usdc", "settlement": "authorized"}
```
レスポンスで返される `cost.amount`（0.000952 USDC）は、402 見積もり、および `Credits × 0.095215` と完全に一致します。`settlement` フィールドはこの支払いの決済ステータスです（`authorized` = 承認済み）；オンチェーン決済はプラットフォームによって処理され、その仕組みは [`exact` と `upto` の課金方式](https://platform.acedata.cloud/documents/x402-metered-upto) を参照してください。

### `upto` 見積もり計算（チャット）

チャットは token 単位で計量されます。あるリクエストの見積もり（上限ではない）は、次式で計算されます（gpt-4o-mini を例とする）：

```text
Credits = 1e-6 × (0.835733 × prompt_tokens + 3.342933 × completion_tokens)
USDC    = Credits × 0.095215
```

500 prompt + 200 completion token の1回のリクエスト：

```text
Credits = 1e-6 × (0.835733 × 500 + 3.342933 × 200) ≈ 0.001086 Credits
报价 USDC ≈ 0.001086 × 0.095215 ≈ $0.0001034
```

クライアントは `upto` 上限（gpt-4o-mini では 1 Credit = `95215` atomic）で署名します。これは**最大でいくら引き落とされる可能性があるか**にすぎません；このリクエストの実際の見積もり（上例では約 $0.0001）は上限を大きく下回り、token 使用量に応じて決済されます。`upto` のオンチェーン決済の仕組みは、[`exact` と `upto` の課金方式](https://platform.acedata.cloud/documents/x402-metered-upto) を参照してください。

## その他サービス価格（固定価格 `exact`）

画像、動画、音楽、検索のような API は、リクエスト時に価格を確定できるため、`exact` を使用します。以下の表は実際の価格であり、未払いリクエストに対してオンライン API が返す 402 の `maxAmountRequired` から取得したものです（見積もりの照会では料金は発生しません）：

| サービス   | 例となるモデル / パラメータ                   | Credits | USDC      | atomic  |
| ---- | --------------------------- | ------- | --------- | ------- |
| ウェブ検索 | serp/google，≤10 件の結果         | 0.01    | $0.000952 | 952     |
| 画像   | nano-banana                 | 0.14    | $0.013330 | 13330   |
| 画像   | gpt-image-1，1024×1024       | 0.20    | $0.019043 | 19043   |
| 画像   | flux-dev                    | 0.24    | $0.022851 | 22851   |
| 画像   | midjourney imagine          | 0.27    | $0.025708 | 25708   |
| 画像   | seedream-4                  | 0.32    | $0.030468 | 30468   |
| 音楽   | suno generate               | 0.55    | $0.052368 | 52368   |
| 音楽   | producer generate           | 0.68    | $0.064746 | 64746   |
| 動画   | luma                        | 1.19    | $0.113305 | 113305  |
| 動画   | hailuo（minimax-hailuo-2-3）  | 1.72    | $0.163769 | 163769  |
| 動画   | kling-v2-6 std              | 2.10    | $0.199951 | 199951  |
| 動画   | kling-v3 std                | 4.20    | $0.399903 | 399903  |
| 動画   | veo-3 text→video            | 5.00    | $0.476074 | 476074  |
| 動画   | seedance-1-0-pro，1080p / 5s | 5.60    | $0.533204 | 533204  |
| 動画   | wan2.6-t2v                  | 13.50   | $1.285402 | 1285402 |

説明：

- 同一サービスの価格は、**モデル、解像度、長さ、動作**によって変わります（特に動画）。上表はある一組のパラメータにおける実際の値であり、規模感の参考用にすぎません。
- この種の固定価格（`exact`）API では、そのリクエストの 402 レスポンス内の `maxAmountRequired` がその回の支払額です（成功レスポンスの `cost.amount` と一致し、前節ですでに実測済み）。
- 各価格はすべて、`Credits × 0.095215` を atomic 単位へ切り捨てて得られます（上記の価格基準を参照）。チャットと同じ換算体系を使用しています。浮動小数点表現と丸めのため、個別の値は単純な積と 1 atomic（$0.000001）差が出る場合がありますが、すべて 402 の戻り値を基準としてください。

## 注文支払い価格

X402 でコンソール注文（プランの購入 / Credits のチャージ）を支払う場合、価格は注文ページの表示を基準とし、402 の `amount` が最終的な署名根拠となります。注文支払いはプラットフォーム API を経由し、アカウントトークンが必要です。詳細は [注文支払いチュートリアル](https://platform.acedata.cloud/documents/x402-order-payment) を参照してください。

注文支払いチュートリアル内の実際の例（10 Credits を購入）：

```text
description Ace Data Cloud Credits x 10.0
created price 1.26          # 订单创建价（USD）
settled    1.20 USDC        # 最终签名/结算金额（= 402 amount）
            = 1200000 atomic USDC
```

注意：**呼び出しごとの課金**（上記の Chat / その他サービス）と**注文支払い**は、異なる2つの経路です。呼び出しごとの課金では一律 `0.095215`/Credit の最適段階単価を使用します；注文支払いはプラン価格に従い、その作成価格と最終決済金額の差異は [注文支払いチュートリアル](https://platform.acedata.cloud/documents/x402-order-payment) を基準としてください。

## リアルタイムで価格を取得する方法

価格はモデルおよびパラメータに応じて変わるため、ハードコードせず、プログラムでリアルタイムに取得してください：

- **呼び出しごとの価格**：対象 API に対し、`PAYMENT-SIGNATURE` なし（`Authorization` もなし）のリクエストを1回送信し、返される 402 の `accepts[].maxAmountRequired` を読み取ります。この手順では料金は発生しません。`exact` API ではこれが最終価格です；`upto` API（チャット）ではこれが上限であり、実際には使用量に応じて決済されます。
- **チャットの token ごとの単価**：`GET https://platform.acedata.cloud/api/v1/models?with_pricing=true&type=chat`、各モデルの `pricing.input_usd` / `pricing.output_usd` を読み取ります（すでに `credit_usd_rate` に基づいて計算済み）。
- **換算の検証**：`atomic = floor(Credits × 0.095215 × 1e6)`、`USDC = atomic / 1e6`（すなわち `USDC ≈ Credits × 0.095215`）。

価格取得の最小リクエスト例：

```bash
curl -sS -X POST https://x402.acedata.cloud/midjourney/imagine \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "a cat"}'
# 返回 402，accepts[].maxAmountRequired 即为该次（exact）调用价格
```

## まとめ
- X402 価格 = その呼び出しの Credits コスト × `0.095215` であり、通常の Credits 課金と**同一の価格**ですが、オンチェーン USDC で決済するだけです。
- `0.095215`/Credit はプラットフォームの**最優遇段階**（大口）の Credits 単価です。少額チャージで Credits を購入する場合は単価がより高くなるため、X402 は最優遇単価を自動的に適用することに相当します。
- `exact` インターフェース（画像 / 動画 / 音楽 / 検索 / 注文）の署名金額はその回に支払うべき金額です。`upto` インターフェース（チャット）の署名金額は上限であり、実際の使用量に基づいて決済されます。
- 権威ある価格は 402 が返す `maxAmountRequired` に準拠します。`exact` は支払うべき金額です（成功レスポンスの `cost.amount` と一致し、実測済み）。`upto` は上限であり、成功レスポンスの `cost.amount` が使用量に基づいて決済される実際の金額です（≤ 上限）。
