ドキュメント UUID または alias を通じて、単一ドキュメントの完全な内容とナビゲーション関係を取得します。既知の alias がある場合は、リストから先にフィルタリングする必要なく直接リクエストできます。

## インターフェース概要

| 項目   | 内容                                                              |
| --- | --------------------------------------------------------------- |
| メソッド  | `GET`                                                           |
| URL | `https://platform.acedata.cloud/api/v1/documents/{id_or_alias}` |
| 認証  | 公開；UUID または alias が分かれば直接読み取り可能                                       |

## パラメータ

- `id_or_alias`：ドキュメント UUID、現在の alias、または `redirect_from` に保持されている古い alias。
- `lang`：オプションの言語ヒント；`Accept-Language` も使用できます。最終的なコンテンツ言語はレスポンスの `content_locale` に準拠します。

```shell
curl --get 'https://platform.acedata.cloud/api/v1/documents/platform-token' \
  --data-urlencode 'lang=zh-CN' \
  -H 'Accept: application/json'
```

## レスポンス説明

詳細は単一オブジェクトでレスポンスされ、現在は以下を含みます：

- `id`、`alias`、`redirect_from`、`name`、`title`、`type`、`rank`、`tags`；
- `content`、`content_mode`、`content_locale`、`content_hash`；
- `parent`、`sibling`、および rank によってソートされた公開 `children` の要約；
- `api` / `proxy` / `dataset` / `integration` の関連、および `agent`（存在する場合）。

レスポンスには `breadcrumbs` フィールドはありません。パンくずリストを構築する場合は、`parent` からその詳細を続けて読み取るか、キャッシュ済みのドキュメントディレクトリ関係を使用できます。

## エラー処理

- ID/alias が存在しない、または現在のサイト可視性に適合しない場合：`404`。`private` はリストの可視性のみを制御し、リンクを知っている人が直接読み取ることを妨げないため、機密境界として使用できません。
- 現在のルートは末尾スラッシュなしの形式を使用しています；プロキシ層が自動的にスラッシュを追加することに依存しないでください。
