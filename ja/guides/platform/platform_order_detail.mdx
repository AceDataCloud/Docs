注文 ID を使用して注文を照会します。このエンドポイントは 2 種類の読み取りモードをサポートしています：匿名アクセスでは支払いページに必要な最小限のフィールドのみを返し、注文所有者が Account Token を携帯している場合は完全な詳細を返します。

## インターフェース概要

| 項目   | 内容                                                        |
| --- | --------------------------------------------------------- |
| メソッド  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| 認証  | 任意；匿名は最小プロジェクション、認証済みの所有者は完全プロジェクション                                    |

`/orders/{id}` と `/orders/{id}/` は現在どちらも利用可能です。注文 ID は支払いリンクの一部であり、機密性のある不透明な識別子として扱い、公開的に拡散しないでください。

## 匿名照会

支払いページはログイン状態が失われた場合でも直接読み取ることができます：

```shell
export ORDER_ID='あなたの注文 ID'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

匿名レスポンスには `id`、`description`、`price`、`state`、`pay_way`、`pay_url`、`expired_at`、`created_at` のみが含まれます。アカウント、Application、Package、支払い内部識別子、または metadata は返されません。

## 認証済み照会

```shell
export PLATFORM_TOKEN='あなたのアカウントトークン'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

注文所有者は、`application` / `applications`、`package` / `packages`、`bank_details`、`invoice_automation` およびモデルフィールドを含む完全な Order 詳細を受け取ります。認証済みであるものの注文所有者ではない場合は `403` を返します；スーパー管理者は除きます。

## 主要フィールド

| フィールド            | 説明                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`、`Paid`、`Finished`、`Expired`、`Failed` または `Refunded` |
| `pay_way`     | 注文の現在の支払い方法；フィールド名は `payment_method` ではありません                             |
| `pay_url`     | ホストされた支払いページまたは QR コードのアドレスであり、空の場合があります                                           |
| `price`       | 注文の最終支払金額であり、現在の注文モデルでは `final_price` フィールドは提供されません                         |
| `amount`      | パッケージのクォータ数量；認証済みの完全レスポンスでのみ表示されます                                            |
| `finished_at` | 注文の完了時刻；フィールド名は `paid_at` ではありません                                      |

完全レスポンスには支払い方法に応じて追加フィールドが含まれる場合があり、クライアントは必要に応じて読み取り、完全レスポンス内の機密性のある metadata を常に記録しないようにしてください。

## エラー処理

- `404`：注文 ID が存在しません。
- `403`：ログイン済みですが、注文所有者ではありません。
- 匿名リクエストは `401` を返しません；最小限の公開プロジェクションのみを取得します。
