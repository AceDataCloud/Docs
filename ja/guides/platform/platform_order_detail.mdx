注文 ID を通じて注文を照会します。このエンドポイントは 2 種類の読み取りモードをサポートしています：匿名アクセスでは支払いページに必要な最小フィールドのみを返し、注文所有者が Account Token を携帯する場合は完全な詳細を返します。

## インターフェース概要

| 項目   | 内容                                                        |
| --- | --------------------------------------------------------- |
| メソッド  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| 認証  | 任意；匿名では最小プロジェクション、認証済み所有者では完全プロジェクション                                    |

`/orders/{id}` と `/orders/{id}/` は現在どちらも利用可能です。注文 ID は支払いリンクの一部であり、機密性のある不透明な識別子として扱い、公開して拡散しないでください。

## 匿名照会

支払いページはログイン状態が失われた場合でも直接読み取ることができます：

```shell
export ORDER_ID='あなたの注文 ID'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

匿名レスポンスには `id`、`description`、`price`、`state`、`pay_way`、`pay_url`、`expired_at`、`created_at` のみが含まれます。アカウント、Application、Package、支払い内部識別子、または metadata は返されません。

## 認証済み照会

```shell
export PLATFORM_TOKEN='あなたのアカウントトークン'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

注文所有者は、`application` / `applications`、`package` / `packages`、`bank_details`、`invoice_automation` およびモデルフィールドを含む完全な Order 詳細を受け取ります。認証済みであっても注文所有者でない場合は `403` が返されます；スーパ管理者を除きます。

## 主要フィールド

| フィールド            | 説明                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`、`Paid`、`Finished`、`Expired`、`Failed` または `Refunded` |
| `pay_way`     | 注文の現在の支払い方法；フィールド名は `payment_method` ではありません                             |
| `pay_url`     | ホストされた支払いページまたは QR コードのアドレスであり、空の場合があります                                           |
| `price`       | 注文の最終支払金額であり、現在の注文モデルは `final_price` フィールドを提供しません                         |
| `amount`      | パッケージのクォータ数量；認証済みの完全レスポンスでのみ確認可能です                                            |
| `finished_at` | 注文完了時刻；フィールド名は `paid_at` ではありません                                      |

完全レスポンスには、支払い方法に応じて追加フィールドが含まれる場合があります。クライアントは必要に応じて読み取り、完全レスポンス内の機密 metadata を常に記録しないようにしてください。

## エラー処理

- `404`：注文 ID が存在しません。
- `403`：ログイン済みですが、注文所有者ではありません。
- 匿名リクエストでは `401` は返されません；最小公開プロジェクションのみを取得します。

## 請求書の赤字訂正と再申請

`GET /api/v1/orders/{order_id}/invoice/` を通じて、注文の現在の請求書を読み取ることができます。自動赤字訂正が送信された後も、請求書は `Issued` のままであり、`red_state` が赤字訂正の進捗を示します；送信成功は赤字訂正の完了を意味しません。確認待ち、赤字請求書の発行、またはアーカイブ中は、注文は再度請求書を申請できません。

管理者が宛名や納税者番号などの請求情報の誤りにより赤字訂正を申請する場合、赤字訂正の理由は「請求書の誤り」です；注文の返金によりトリガーされる自動赤字訂正では、引き続き「サービス中止」を使用します。

赤字請求書の発行およびアーカイブが正常に完了すると、元の請求書は `Voided` になり、注文は再度申請できるようになります。元の請求書は請求書履歴で確認できます。赤字訂正が失敗した場合、または結果の確認待ちである場合は、財務確認によって処理され、注文の請求書発行制限が事前に解除されることはありません。手動で発行された請求書は、まず税務または請求書発行システムで取消または赤字訂正を完了し、その後に財務がプラットフォームで確認する必要があります。
