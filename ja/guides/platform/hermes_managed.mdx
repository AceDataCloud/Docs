各 Application ごとに独立した Hermes コンテナインスタンスを作成します。デフォルトでは固定リリースバージョンのベースイメージを使用し、ネイティブ機能を保持します。プラットフォームは購入、更新、永続ストレージおよびデプロイ管理を提供します。

## 作成と購入

1. [Hermes デプロイ](https://platform.acedata.cloud/services/hermes) を開き、Application を作成します。
2. 購入ページで期間プランを選択し、支払いを完了します。
3. 設定ページに戻り、ドロップダウンリストからプラットフォームのチャットモデルを選択し、現在のモデル価格を確認できます。プラットフォームはこのインスタンス用に独立した API 認証情報を作成します。プラットフォーム接続をオフにして、ネイティブコンソールで自身で設定することもできます。
4. アクセス認証情報を自動生成するか、自身の強力なパスワード/Token を設定し、確認後にデプロイを開始します。アクセス認証情報とモデル API 認証情報は互いに独立しています。
5. インスタンスの準備が完了したら、管理ページからアクセスアドレスとログイン認証情報を取得します。
6. ネイティブコンソールにログインし、自身のモデルプロバイダー、キーおよびチャネルを設定します。

デプロイ料金はプラン期間に応じて課金され、具体的な米ドル価格と期間は購入ページに準じます。モデル呼び出し料金は別途かかります。デプロイ期間を購入してもモデル利用枠は付与されません。プラットフォーム接続を有効にした場合、専用 API 認証情報では選択したモデルに対応するチャットインターフェースのみが公開され、呼び出しはプラットフォーム残高から別途課金されます。各 Application はそれぞれ購入、更新および管理します。

## パスワード、認証情報および後続設定

アクセス認証情報は初回起動前に設定されます。自動生成方式ではランダムな認証情報を使用し、カスタムパスワードは少なくとも 16 文字、OpenClaw Token は少なくとも 32 文字必要です。下書きにはパスワードは保存されません。ページを切り替えた後、再入力が必要になる場合があります。デプロイ後、アクセス認証情報を確認できるのは Application 所有者と管理者のみです。

各インスタンスのモデル API 認証情報は共有されず、デプロイの更新に伴って有効期限が延長され、インスタンス削除時に取り消されます。デプロイ初期化後は、ネイティブコンソールでモデルとチャネルを変更してください。他サービスのモデルに変更する場合は、先にプラットフォームの認証情報管理で対応するインターフェースの認可を調整するか、対応する認証情報を使用してください。通常の再デプロイではネイティブ設定は上書きされません。公開検証を通過していないデプロイ環境は、新規デプロイを一時的に拒否します。サポートにお問い合わせください。

## バージョンとデータ

設定ページには現在リリースされているイメージバージョンが表示されます。新規インスタンスはサービスの現在のリリースバージョンを使用します。既存インスタンスはカタログ更新に伴って自動的に置き換えられません。再デプロイでは現在のサービスバージョンが適用されるため、事前にバックアップを取り、使用するバージョンのアップグレード要件を確認してください。

各インスタンスにはデフォルトで 1 CPU、2 GiB のメモリ上限、および 10 GiB の永続ストレージが提供されます。再起動してもインスタンスデータは保持されます。デプロイを能動的に削除した場合、または期限切れで回収された場合はストレージが削除されるため、保持が必要なデータは事前にエクスポートしてください。

## 更新と期限切れ

現在の Application の購入ページで更新すると、有効期限はプラットフォームの既存の期間ルールに従って延長されます。期限切れ後はアクセス入口が一時停止し、猶予期間内に更新すればアクセスが復元されます。猶予期間を超えるとインスタンスとデータが回収されます。管理ページの期限日時、課金ステータスおよび削除通知に従ってください。

## 管理画面へのログイン

デプロイ管理ページで Dashboard アドレス、ユーザー名 `admin` およびパスワードをコピーし、開いてログインします。ログイン情報は、その Application の所有者およびプラットフォーム管理者にのみ提供されます。モデル、スキルおよびチャネルは Hermes のネイティブ画面で設定します。

## よくある質問

- **なぜ新しいインスタンスはまだ応答できないのですか？** デプロイ完了はコンテナの準備が完了したことを意味します。使用を開始するには、ネイティブ画面でモデルと認証情報を設定する必要があります。
- **追加プラグインまたはモデル fallback はプリインストールされていますか？** デフォルトでは追加されません。必要に応じてネイティブ画面で設定してください。
- **既存インスタンスはどのように更新しますか？** 既存の Application と注文は保持され、再デプロイ時には現在のサービスバージョンが使用されます。アップグレード前にデータをバックアップし、バージョン互換性を確認してください。
- **起動に失敗した場合はどうすればよいですか？** まずデプロイログとイベントを確認し、インスタンスの準備完了後にモデルを設定してください。公開コメントやスクリーンショットでインスタンスのパスワードやキーを公開しないでください。
