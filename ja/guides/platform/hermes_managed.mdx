各 Application ごとに独立した Hermes コンテナインスタンスを作成します。デフォルトでは固定リリースバージョンのベースイメージを使用し、ネイティブ機能を維持します。プラットフォームは購入、更新、永続ストレージおよびデプロイ管理を提供します。

## 作成と購入

1. [Hermes デプロイ](https://platform.acedata.cloud/services/hermes) を開き、Application を作成します。
2. 購入ページで期間プランを選択し、支払いを完了します。
3. 設定ページに戻り、ドロップダウンリストからプラットフォームのチャットモデルを選択し、現在のモデル価格を確認できます。プラットフォームはこのインスタンス用に独立した API 認証情報を作成します。プラットフォーム連携をオフにし、ネイティブコンソールで自分で設定することもできます。
4. アクセス認証情報の自動生成を選択するか、自分の強力なパスワード/Token を設定します。必要に応じて A2A と EnvarPay にチェックを入れ、確認後にデプロイを開始します。アクセス認証情報とモデル API 認証情報は相互に独立しています。
5. インスタンスの準備が完了したら、管理ページからアクセスアドレスとログイン認証情報を取得します。
6. ネイティブコンソールにログインしてチャネルを設定します。デプロイ時にプラットフォームモデル連携をオフにした場合、チャットを使用するにはモデルプロバイダーと認証情報も自分で設定する必要があります。

デプロイ料金はプラン期間に応じて課金され、具体的な米ドル価格と期間は購入ページを基準とします。モデル呼び出し料金は別途です。デプロイ期間を購入してもモデル利用枠は付与されません。プラットフォーム連携を有効にした場合、専用 API 認証情報では選択したモデルに対応するチャットインターフェースのみが公開され、呼び出しはプラットフォーム残高から別途課金されます。各 Application はそれぞれ購入、更新、管理されます。

## パスワード、認証情報および後続設定

アクセス認証情報は初回起動前に設定されます。自動生成方式ではランダムな認証情報を使用し、カスタムパスワードは少なくとも 16 文字、OpenClaw Token は少なくとも 32 文字必要です。下書きにはパスワードは保存されません。ページを切り替えた後、再入力が必要になる場合があります。デプロイ後、アクセス認証情報を確認できるのは Application の所有者と管理者のみです。

各インスタンスのモデル API 認証情報は共有されず、デプロイの更新に伴って有効期限が延長され、インスタンス削除時に失効します。初回デプロイ時にプラットフォームモデルへ接続しなかった場合、その Application の設定ページでプラットフォームモデルを選択して再デプロイできます。プラットフォームはデフォルトモデルを更新し、会話およびその他のネイティブ設定を保持します。その後はネイティブコンソールでモデルとチャネルを変更してください。他サービスのモデルに変更する場合は、先にプラットフォーム認証情報管理で対応するインターフェースの権限を調整するか、対応する認証情報を使用してください。通常の再デプロイではネイティブ設定は上書きされません。リリース検証を通過していないデプロイ環境では、新規デプロイが一時的に拒否されます。サポートにお問い合わせください。

## オプションのデプロイコンポーネント

A2A にチェックを入れると、デプロイテンプレートが Hermes ネイティブ A2A ゲートウェイを起動し、管理ページで所有者トークンを提供します。EnvarPay にチェックを入れると、独立したサービスコンテナと永続化された台帳が追加でインストールされ、先に A2A を有効にする必要があります。EnvarPay は初期状態では所有者のアクセス認証情報のみを持ち、サービスまたは受取人のアイデンティティはなく、自動課金や代理購入は行いません。どちらのオプションもインスタンスを Envar に自動登録しません。既存のインスタンスは管理ページから設定に入り、有効化後に再デプロイできます。有効化済みのコンポーネントは、現時点ではこのウィザードでオフにできません。

## バージョンとデータ

設定ページには現在リリースされているイメージバージョンが表示されます。新規インスタンスはサービスの現在のリリースバージョンを使用します。既存インスタンスはカタログ更新に伴って自動的に置き換えられません。再デプロイでは現在のサービスバージョンが適用されるため、事前にバックアップを取り、使用するバージョンのアップグレード要件を確認してください。

各インスタンスにはデフォルトで 1 CPU、2 GiB のメモリ上限、および 10 GiB の永続ストレージが提供されます。再起動後もインスタンスデータは保持されます。デプロイを手動で削除した場合、または期限切れにより回収された場合はストレージも削除されるため、保持が必要なデータは事前にエクスポートしてください。

## 更新と期限切れ

現在の Application の購入ページで更新すると、有効期間はプラットフォームの既存の期間ルールに従って延長されます。期限切れ後はアクセス入口が停止し、猶予期間内に更新するとアクセスが復元されます。猶予期間を超えると、インスタンスとデータが回収されます。管理ページの有効期限、請求状態、および削除通知を基準としてください。

## 管理画面へのログイン

デプロイ管理ページで Dashboard アドレス、ユーザー名 `admin`、およびパスワードをコピーし、開いてログインします。ログイン情報は、その Application の所有者とプラットフォーム管理者にのみ提供されます。モデル、スキル、およびチャネルは Hermes ネイティブ画面で設定します。

## よくある質問

- **なぜ新しいインスタンスはまだ応答できないのですか？** デプロイ完了はコンテナの準備完了のみを意味します。デプロイ時にプラットフォームモデル連携をオフにした場合は、設定ページでプラットフォームモデルを追加選択して再デプロイするか、ネイティブ画面でモデルと認証情報を自分で設定する必要があります。
- **追加プラグインやモデル fallback は事前インストールされていますか？** デフォルトでは追加されません。必要に応じてネイティブ画面で設定してください。
- **既存インスタンスはどのように更新しますか？** 既存の Application と注文は保持され、再デプロイ時には現在のサービスバージョンが使用されます。アップグレード前にデータをバックアップし、バージョン互換性を確認してください。
- **起動に失敗した場合はどうすればよいですか？** まずデプロイログとイベントを確認し、インスタンスの準備完了後にモデルを設定してください。公開コメントやスクリーンショットでインスタンスのパスワードやキーを公開しないでください。
