各 Application に対して独立した Hermes コンテナインスタンスを作成します。デフォルトでは固定リリースバージョンのベースイメージを使用し、ネイティブ機能を保持します。プラットフォームは購入、更新、永続ストレージおよびデプロイ管理を提供します。

## 作成と購入

1. [Hermes デプロイ](https://platform.acedata.cloud/services/hermes) を開き、Application を作成します。
2. 購入ページで期間プランを選択し、支払いを完了します。
3. 設定ページに戻り、ドロップダウンリストからプラットフォームのチャットモデルを選択し、現在のモデル価格を確認できます。プラットフォームはこのインスタンス用に独立した API 認証情報を作成します。プラットフォーム連携を無効にし、ネイティブコンソールで自分で設定することもできます。
4. アクセス認証情報を自動生成するか、自分の強力なパスワード/Token を設定します。必要に応じて A2A と EnvarPay にチェックを入れ、確認後にデプロイを開始します。アクセス認証情報とモデル API 認証情報は相互に独立しています。
5. インスタンスの準備が完了したら、管理ページからアクセスアドレスとログイン認証情報を取得します。
6. ネイティブコンソールにログインしてチャネルを設定します。デプロイ時にプラットフォームモデル連携を無効にした場合、チャットを利用するにはモデルプロバイダーと認証情報も自分で設定する必要があります。

デプロイ料金はプラン期間に応じて課金されます。具体的な米ドル価格と期間は購入ページを基準とします。モデル呼び出し料金は別途発生します。デプロイ期間を購入してもモデル利用枠は付与されません。プラットフォーム連携を有効にした場合、専用 API 認証情報では選択したモデルに対応するチャットインターフェースのみが公開され、呼び出しはプラットフォーム残高から別途課金されます。各 Application はそれぞれ購入、更新、管理します。

## パスワード、認証情報と後続設定

アクセス認証情報は初回起動前に設定されます。自動生成方式ではランダムな認証情報を使用し、カスタムパスワードは最低 16 文字、OpenClaw Token は最低 32 文字必要です。下書きにはパスワードは保存されません。ページを切り替えた後、再入力が必要になる場合があります。デプロイ後、アクセス認証情報を確認できるのは Application の所有者と管理者のみです。

各インスタンスのモデル API 認証情報は共有されず、デプロイの更新に伴って有効期限が延長され、インスタンス削除時に失効します。初回デプロイ時にプラットフォームモデルへ接続しなかった場合、その Application の設定ページでプラットフォームモデルを選択して再デプロイできます。プラットフォームはデフォルトモデルを更新し、会話およびその他のネイティブ設定を保持します。その後はネイティブコンソールでモデルとチャネルを変更してください。他サービスのモデルを選択する場合は、先にプラットフォームの認証情報管理で対応インターフェースの認可を調整するか、対応する認証情報を使用してください。通常の再デプロイではネイティブ設定は上書きされません。公開検証を通過していないデプロイ環境は、新しいデプロイを一時的に拒否します。サポートへお問い合わせください。

## 任意のデプロイコンポーネント

A2A にチェックを入れると、デプロイテンプレートは Hermes ネイティブ A2A ゲートウェイを起動し、管理ページで所有者トークンを提供します。EnvarPay にチェックを入れると、独立したサービスコンテナと永続的な台帳が追加でインストールされ、先に A2A を有効にする必要があります。EnvarPay には初期状態では所有者アクセス認証情報のみがあり、サービスまたは受取身份は存在せず、自動課金や代理購入は行いません。どちらのオプションもインスタンスを Envar に自動登録しません。既存インスタンスは管理ページから設定に入り、有効化後に再デプロイできます。有効化済みのコンポーネントは、現時点ではこのウィザードで無効にできません。

A2A を有効にしてインスタンスの準備が完了すると、管理ページのアクセスアドレスカードにコピー可能な Agent Card アドレスが表示されます。Hermes ネイティブ A2A は独立した公開アドレスを使用します。Dashboard のログインアドレスは Agent Card アドレスとして使用できません。EnvarPay も同時に有効にした場合、管理ページには対応する「Envar 接続アドレス」も表示されます。Envar 接続サービスへ接続する際は、優先してこの URL をコピーしてください。

## バージョンとデータ

設定ページには現在リリースされているイメージバージョンが表示されます。新規インスタンスはサービスの現在のリリースバージョンを使用します。既存インスタンスはカタログの更新に伴って自動的に置き換えられません。再デプロイでは現在のサービスバージョンが適用されます。事前にバックアップを行い、使用するバージョンのアップグレード要件を確認してください。

各インスタンスにはデフォルトで 1 CPU、2 GiB のメモリ上限、および 10 GiB の永続ストレージが提供されます。再起動してもインスタンスデータは保持されます。デプロイを手動で削除した場合、または期限切れで回収された場合はストレージが削除されるため、保持が必要なデータは事前にエクスポートしてください。

## 更新と期限切れ

現在の Application の購入ページで更新すると、有効期限はプラットフォームの既存の期間ルールに従って延長されます。期限切れ後はアクセス入口が一時停止され、猶予期間内に更新すればアクセスが復旧します。猶予期間を超えると、インスタンスとデータが回収されます。管理ページの期限日時、請求状態および削除に関する通知を基準としてください。

## 管理画面へのログイン

デプロイ管理ページで Dashboard アドレス、ユーザー名 `admin` およびパスワードをコピーし、開いてログインします。ログイン情報は、その Application の所有者およびプラットフォーム管理者にのみ提供されます。モデル、スキル、チャネルは Hermes ネイティブ画面で設定します。

## よくある質問

- **新しいインスタンスがまだ応答しないのはなぜですか？** デプロイの完了は、コンテナの準備ができたことのみを示します。デプロイ時にプラットフォームモデル連携を無効にした場合は、設定ページでプラットフォームモデルを追加選択して再デプロイするか、ネイティブ画面でモデルと認証情報を設定してください。
- **追加プラグインは事前インストールされていますか？** デフォルトでは追加されません。必要に応じて管理画面で設定できます。
- **既存のインスタンスはどのように更新しますか？** 既存の Application と注文は保持されます。再デプロイ時には現在のサービスバージョンが使用されます。アップグレード前にデータをバックアップし、バージョン互換性を確認してください。
- **起動に失敗した場合はどうすればよいですか？** まずデプロイログとイベントを確認し、インスタンスの準備が完了してからモデルを設定してください。公開コメントやスクリーンショットでインスタンスのパスワードやキーを公開しないでください。
