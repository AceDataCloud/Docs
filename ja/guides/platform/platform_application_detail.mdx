Application ID を通じて単一のサービス申請の完全なステータスを取得します——リスト API よりも `service` 完全オブジェクト（`packages` プランを含む）などのフィールドが追加されており、詳細ページに適しています。

> ℹ️ 本 API は **AceDataCloud プラットフォーム管理 API** に属し、統一プレフィックスは `https://platform.acedata.cloud/api/v1/` です。完全な API インデックスは[AceDataCloud プラットフォームドキュメント一覧の取得](https://platform.acedata.cloud/documents/platform-document-list)をご覧ください。

## API 概要

| 項目   | 内容                                                                    |
| --- | --------------------------------------------------------------------- |
| メソッド  | `GET`                                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/{application_id}` |
| 認証  | ✅ アカウントトークンが必要                                                              |

`/applications/{id}` と `/applications/{id}/` は現在どちらも利用可能です。例では末尾スラッシュなしの形式を統一して使用します。

## 認証の説明（アカウントトークンの取得方法）

リクエストヘッダー：

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

詳細な取得方法は[管理 AceDataCloud プラットフォームアカウントトークン](https://platform.acedata.cloud/documents/platform-token)をご覧ください。

> ℹ️ リスト API とは異なり、**詳細 API の権限チェックは単一オブジェクトに対して直接行われる**ため、`?user_id=` を渡す必要はありません。ただし、他人の申請にアクセスすると `403 permission_denied` が返されます。

## パスパラメータ

| パラメータ               | 型   | 必須  | 説明             |
| ---------------- | ---- | --- | -------------- |
| `application_id` | UUID | ✅   | Application ID |

## リクエスト例

### cURL

```shell
curl 'https://platform.acedata.cloud/api/v1/applications/82f57141-2323-4453-8730-60f7d833a2da' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

app_id = "82f57141-2323-4453-8730-60f7d833a2da"
resp = requests.get(
    f"https://platform.acedata.cloud/api/v1/applications/{app_id}",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}",
    },
    timeout=10,
)
app = resp.json()
print(f"サービス：{app['service']['title']}")
print(f"残り {app['remaining_amount']} {app['service']['unit']} / 使用済み {app['used_amount']}")
```

### Node.js

```javascript
const appId = '82f57141-2323-4453-8730-60f7d833a2da'
const r = await fetch(`https://platform.acedata.cloud/api/v1/applications/${appId}`, {
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log(await r.json())
```

## レスポンスフィールドの説明

フィールドの意味は[リスト API](https://platform.acedata.cloud/documents/platform-application-list)と同じで、以下が追加で含まれます：

| フィールド        | 型     | 説明                                                        |
| --------- | ------ | --------------------------------------------------------- |
| `service` | object | 完全なサービスオブジェクト（`packages` プラン、`unit`、`free_amount` を含む）。サービス詳細パネルを直接レンダリングできます |

## エラー処理

| HTTP | code                | 意味                  |
| ---- | ------------------- | ------------------- |
| 401  | `not_authenticated` | アカウントトークンが不足している              |
| 403  | `permission_denied` | この Application はあなたに属していない  |
| 404  | `not_found`         | Application が存在しない、または削除されている |

## 実用的なヒント

- **一括監視にはリストを優先して使用**：一度に Application リストを取得し、各サービスの単位としきい値に基づいて判断することで、詳細を個別にリクエストすることを避けます。
- **認証情報の数を確認する必要がある場合**：[API 認証情報リスト](https://platform.acedata.cloud/documents/platform-credential-list)を使用して `application_id` でフィルタリングします。
- **`disabled=true` の調査方法**：リスク管理、未払い、規約違反の呼び出しにより停止されたかどうか、チケット / メール通知を確認してください。API で解除することはできず、カスタマーサポートへの連絡が必須です。
