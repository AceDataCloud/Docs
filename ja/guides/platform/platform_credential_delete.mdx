---
title: "AceDataCloud プラットフォーム API 認証情報を削除する"
description: "Platform API guide - Ace Data Cloud"
---

API 認証情報を 1 件完全に削除します。削除後は**即座に復元不可能**となり、この Token を使用中のすべての業務インターフェースは直ちに `401` を受け取ります。

> ℹ️ 本インターフェースは **AceDataCloud プラットフォーム管理 API** に属し、共通プレフィックスは `https://platform.acedata.cloud/api/v1/` です。

## インターフェース概要

| 項目   | 内容                                                                  |
| --- | ------------------------------------------------------------------- |
| メソッド  | `DELETE`                                                            |
| URL | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}` |
| 認証  | ✅ アカウントトークンが必要                                                            |

`/credentials/{id}` と `/credentials/{id}/` は現在どちらも利用可能です。例では末尾スラッシュなしの形式に統一しています。

## 認証説明（アカウントトークンの取得方法）

リクエストヘッダー：

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

取得方法については、[AceDataCloud プラットフォームアカウントトークンを管理する](https://platform.acedata.cloud/documents/platform-token)を参照してください。

## パスパラメータ

| パラメータ              | 型   | 必須  | 説明        |
| --------------- | ---- | --- | --------- |
| `credential_id` | UUID | ✅   | 削除する認証情報 ID |

## リクエスト例

### cURL

```shell
curl -X DELETE 'https://platform.acedata.cloud/api/v1/credentials/df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

cred_id = "df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6"
resp = requests.delete(
    f"https://platform.acedata.cloud/api/v1/credentials/{cred_id}",
    headers={"authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    timeout=10,
)
assert resp.status_code == 204, resp.text
print("✅ 已删除")
```

### Node.js

```javascript
const credId = 'df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6'
const r = await fetch(`https://platform.acedata.cloud/api/v1/credentials/${credId}`, {
  method: 'DELETE',
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log('status:', r.status) // 204
```

## レスポンス

- **成功**：`HTTP 204 No Content`、**レスポンスボディなし**。
- **失敗**：エラー JSON を返します。下表を参照してください。

## エラー処理

| HTTP | code                | 意味         |
| ---- | ------------------- | ---------- |
| 401  | `not_authenticated` | アカウントトークンがない     |
| 403  | `permission_denied` | この認証情報はあなたに属していない    |
| 404  | `not_found`         | 認証情報が存在しない、またはすでに削除されている |

## 実用的なヒント

- **削除は元に戻せません**——プラットフォームは Token のコピーを保持しません。漏洩が疑われるものの監視データを保持したい場合は、削除ではなく[AceDataCloud プラットフォーム API 認証情報をローテーションする](https://platform.acedata.cloud/documents/platform-credential-rotate)を使用してください。
- **削除してもこの認証情報ですでに消費された利用枠は返還されません**。Application 残高は消費に応じてリアルタイムで差し引かれ、認証情報の削除は残高の帳簿に影響しません。
- 削除後は、[API 認証情報リスト](https://platform.acedata.cloud/documents/platform-credential-list)から `application_id` により残りの認証情報を再確認できます。
- **一括クリーンアップの前に呼び出し元を確認してください**：リストには現在、最終使用時刻フィールドがありません。デプロイ設定と呼び出し記録を組み合わせて認証情報が使用されなくなったことを確認してから、1 件ずつ削除してください。
