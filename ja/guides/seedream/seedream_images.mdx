この記事では、SeeDream Images Generation API の連携方法について説明します。この API は、カスタムパラメータを入力することで、SeeDream 公式の画像を生成できます。

## 申請手順

SeeDream Images Generation API を使用するには、まず [Ace Data Cloud コンソール](https://platform.acedata.cloud/console/applications) にアクセスし、API Token を取得して、後で使用できるように保存してください。

![]()

まだログインまたは登録していない場合は、自動的にログインページに移動し、登録とログインを促す画面が表示されます。完了すると、自動的に現在のページに戻ります。

**1 つの API Token でプラットフォーム上のすべてのサービスを呼び出すことができ、サービスごとに個別に申請する必要はありません。** 初回申請時には無料利用枠が付与され、無料でお試しいただけます。利用枠が不足した場合は、[コンソール](https://platform.acedata.cloud/console/coin) から共通残高をチャージできます。

> 📘 完全なドキュメント：[SeeDream Images Generation API →](https://platform.acedata.cloud/documents/seedream-images)

## モデルの選択

| モデル | 適用シーン |
| ----------------------------------------------------------- | ------------------------------- |
| `doubao-seedream-5-5-261028` | 複数回の編集、テキストからの透明画像生成、複数の参照画像を使用した透明画像編集、レイヤー分割とテキストレイヤー認識 |
| `doubao-seedream-5-0-flash-260915` | 低遅延の単一画像生成、複数の参照画像を使用した編集、透明画像編集とレイヤー分割 |
| `doubao-seedream-5-0-pro-260628` | 単一画像生成、精密な編集、透明画像編集とレイヤー分割 |
| `doubao-seedream-5-0-lite-260128` | 単一画像、画像セット、ストリーミング出力とWeb検索 |
| `doubao-seedream-4-5-251128` / `doubao-seedream-4-0-250828` | 旧バージョンの画像生成と編集 |

5.5 と 5.0 Flash は同じ `POST /seedream/images` を使用し、どちらも `1K`、`1.5K`、`2K` および最大 10 枚の参照画像に対応しています。両モデルのレイヤー分割タスクでは、画像を 1 枚のみ受け付け、URL を返します。5.5 では `layer_decomposition_options: {"max_images": 12, "text_recognition": true}` を設定できます。最大 100 枚の画像（ベース画像を含む）を出力でき、認識可能なテキストレイヤーについては、`data[].text_recognition` で行ごとのテキストとスタイルが返されます。5.0 Flash では、ベース画像 1 枚と最大 16 個のレイヤーが返されます。

5.5 は `background: "transparent"` を使用して、透明な PNG を直接生成できます。5.0 Flash で透明画像を編集するには、アルファチャンネルを持つ参照画像が 1 枚必要です。5.5 は正常に出力された画像のピクセルサイズの区分に応じて課金され、入力参照画像 1 枚ごとに 0.13 Credits が追加されます。5.0 Flash は正常に出力された画像 1 枚につき 0.31 Credits が課金され、参照画像は無料です。レイヤー分割は実際に正常出力された枚数に基づいて課金され、ベース画像も含まれます。[リアルタイム料金](https://platform.acedata.cloud/services/seedream?tab=pricing) を参照してください。

## 基本的な使い方

まず、基本的な使用方法を確認しましょう。プロンプト `prompt`、生成動作 `action`、画像サイズ `size` を入力することで、処理後の結果を取得できます。最初に `action` フィールドを簡単に渡す必要があり、その値は `generate` に設定します。次に、プロンプトを入力します。具体的な内容は以下のとおりです。

<p><img src="https://cdn.acedata.cloud/seedream_request_body.png" width="500" className="m-auto" /></p>

ここでは、Request Headers に以下の項目を設定していることがわかります。

- `accept`：受信するレスポンス結果の形式を指定します。ここでは JSON 形式を意味する `application/json` を入力します。
- `authorization`：API を呼び出すためのキーです。申請後は、ドロップダウンから直接選択できます。

また、Request Body には以下の項目を設定しています。

- `prompt`：プロンプト。
- `model`：上記の表に記載されている完全なモデル ID を入力してください。
- `image`：入力画像の URL、Base64 文字列、または配列。5.5、5.0 Pro、5.0 Flash は最大 10 枚の参照画像に対応しています。
- `size`：解像度の区分、または `幅x高さ`。5.5、5.0 Pro、5.0 Flash は `1K`、`1.5K`、`2K` に対応しています。5.0 Lite は `2K`、`3K`、`4K` に対応しています。
- `sequential_image_generation`：画像セット。入力した内容に基づいて、相互に関連する一連の画像を生成します。`doubao-seedream-5-0-lite-260128`、`doubao-seedream-4-5-251128`、`doubao-seedream-4-0-250828` がこのパラメータに対応しており、デフォルト値は `disabled` です。
- `stream`：ストリーミング出力モードを有効にするかどうかを制御します。`doubao-seedream-5-0-lite-260128`、`doubao-seedream-4-5-251128`、`doubao-seedream-4-0-250828` がこのパラメータに対応しており、デフォルト値は `false` です。
- `response_format`：生成画像の返却形式を指定します。デフォルトは `url` で、`b64_json` にも対応しています。
- `watermark`：生成画像にウォーターマークを追加するかどうかを指定します。デフォルト値は `true` です。
- `output_format`：出力形式は `jpeg` または `png` です。5.5 のデフォルトは PNG、5.0 Pro/Flash/Lite のデフォルトは JPEG です。
- `tools`：モデルが呼び出すツールを設定します。現在は `web_search`（Web検索）に対応しています。Seedream 5.0 Lite のみ対応しています。
- `optimize_prompt_options`：プロンプト最適化の設定です。5.0 Pro は `standard`/`fast` に対応しています。5.5、5.0 Flash、5.0 Lite、4.5 は `standard` のみ対応し、4.0 は `standard`/`fast` に対応しています。
- `background`：`transparent` と `opaque` に対応しています。5.5 では `auto` にも対応しています。透明画像の出力には PNG が使用されます。
- `layer_decomposition`：5.5、5.0 Pro、5.0 Flash が対応しています。`true` に設定する場合は、PNG/JPEG 画像を 1 枚入力する必要があります。`prompt` を省略して自動的に分割することも、自然言語または `<bbox>` を使用して要素を指定することもできます。`size` は `auto`/`1K`/`1.5K`/`2K` に対応しています。このモードは、画像セット、ストリーミング、Web検索、または `background` と同時に使用することはできません。
- `callback_url`：結果を受け取るためのコールバック URL。
- `async`：非同期モードで処理するかどうかを指定します。`true` に設定すると、インターフェースは直ちに `task_id` を返します。`callback_url` を指定する必要はなく、その後 `/seedream/tasks` を通じてポーリングし、結果を取得できます。

```shell
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \

  "model": "doubao-seedream-5-0-lite-260128",

```

## 画像編集タスク

画像を編集したい場合は、まずパラメータ `image` に編集対象の画像リンクを渡す必要があります。

- model：上記の表で画像編集に対応している完全なモデル ID を渡します。
- image：編集する画像を1枚または複数枚アップロードします。

入力例は以下のとおりです。

<p><img src="https://cdn.acedata.cloud/seedream_edit.png" width="500" className="m-auto" /></p>

対応するコード：

```python
import requests

url = "https://api.acedata.cloud/seedream/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedream-4-0-250828",
  "prompt": "モデルのポーズと、液体状の衣服の流れる形状はそのまま維持してください。衣服の素材を銀色の金属から完全に透明な水（またはガラス）に変更してください。液体の流れを通して、モデルの肌の細部が見えるようにしてください。光と影の効果を反射から屈折へと変化させてください。",
  "image": ["https://ark-project.tos-cn-beijing.volces.com/doc_image/seedream4_5_imageToimage.png"],
  "size": "2K",
  "watermark": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## レイヤー分解（Seedream 5.0 Pro）

レイヤー分解では、入力画像1枚をベース画像1枚と、個別に編集可能な透明 PNG レイヤー最大16枚に分解します。以下のリクエストでは、モデルに主要な要素を自動認識させます。要素を指定する必要がある場合は、`prompt` を追加することも、プロンプト内で正規化された `<bbox>` 座標を使用することもできます。

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "https://example.com/poster.png",
  "layer_decomposition": true,
  "size": "2K",
  "watermark": false
}'
```

返される `data` は `z_index` の小さい順、つまり下から上の順に並んでいます。ベース画像の `z_index` は 0 です。各レイヤーには `name`、`description`、および `bounding_box.absolute` / `normalized` も含まれます。絶対座標を使用して再構成する場合は、レイヤーを `[right-left, bottom-top]` のサイズに拡大縮小し、`[left, top]` の位置に配置したうえで、`z_index` の昇順に重ねます。いずれかのレイヤーの生成に失敗した場合、分解処理全体が失敗します。

## ストリーミング出力

Lite/4.x で `stream: true` を設定する場合、リクエストヘッダーには `accept: application/x-ndjson` を使用します。API は1行ずつ `image_generation.partial_succeeded` または `image_generation.partial_failed` を返し、最後に唯一の `image_generation.completed` イベントと最終的な `usage` を返します。課金が発生するのは完了イベントがトリガーされた場合の1回のみです。ストリーミングモードは `async` または `callback_url` と併用できません。

## 非同期コールバック

SeeDream Images Generation API の生成には比較的長い時間がかかり、約1～2分を要します。API が長時間応答しない場合、HTTP リクエストの接続が維持され続け、余分なシステムリソースを消費するため、この API では非同期コールバックにも対応しています。

全体的な流れは次のとおりです。クライアントがリクエストを送信する際に、追加で `callback_url` フィールドを指定します。クライアントが API リクエストを送信すると、API は `task_id` フィールドを含む結果を直ちに返します。これは現在のタスク ID を表します。タスクが完了すると、生成された画像の結果が POST JSON 形式で、クライアントが指定した `callback_url` に送信されます。この結果にも `task_id` フィールドが含まれているため、ID を使ってタスク結果を関連付けることができます。

コールバック用のパブリックネットワークアドレスがない場合は、`callback_url` を指定せず、リクエスト内の `async` フィールドを `true` に設定することもできます。この場合も、API は `task_id` を直ちに返しますが、結果はプッシュされません。最終結果を取得するには、その `task_id` を使用して `/seedream/tasks` API を呼び出し、タスクのステータスをポーリングする必要があります。

以下の例を通じて、具体的な操作方法を確認してみましょう。

実行すると、以下のようにすぐに結果が得られることがわかります。

```
{

}
```

内容は以下のとおりです。

```json
        {
```

## エラー処理

API の呼び出し時にエラーが発生した場合、API は対応するエラーコードと情報を返します。例えば：

- `400 token_mismatched`：不正なリクエストです。パラメータが不足しているか、無効である可能性があります。
- `400 api_not_implemented`：不正なリクエストです。パラメータが不足しているか、無効である可能性があります。
- `401 invalid_token`：認証されていません。認証トークンが無効または不足しています。
- `429 too_many_requests`：リクエストが多すぎます。レート制限を超過しました。
- `500 api_error`：サーバー内部エラーです。サーバー上で問題が発生しました。

### エラーレスポンスの例

```json
}
```
