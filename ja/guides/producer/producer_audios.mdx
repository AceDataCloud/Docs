本稿では、カスタムパラメータを入力して Producer 公式の音楽を生成できる Producer Audios Generation API の連携ガイドを紹介します。

## 申請手順

Producer Audios Generation API を使用するには、まず [Ace Data Cloud コンソール](https://platform.acedata.cloud/console/applications) で API Token を取得し、控えておいてください。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

まだログインまたは登録していない場合は、ログインページに自動的に移動して登録とログインを促され、完了後は現在のページに自動的に戻ります。

**1 つの API Token でプラットフォーム上のすべてのサービスを呼び出すことができ、サービスごとに個別で申請する必要はありません。** 初回申請時には無料クレジットが付与され、無料で体験できます。クレジットが不足した場合は、[コンソール](https://platform.acedata.cloud/console/coin) で共通残高をチャージできます。

> 📘 完全なドキュメント：[Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## 操作に応じた必須パラメータの選択

`action=generate` かつ `custom=false`（デフォルト）の場合は `prompt` を指定します。`custom=true`
かつ `instrumental=false` の場合は `lyric` を指定します。カスタムのインストゥルメンタル音楽は
`custom=true, instrumental=true` を設定でき、架空の歌詞や追加のプロンプトは不要です。
`action=extend` には `audio_id` と 0 より大きい `continue_at` が必要で、インストゥルメンタル以外のモードでは
`lyric` も必要です。カバー、バリエーション、セクション置換、パート交換、および音源分離はいずれも元の `audio_id` が必要です。
歌詞とプロンプトは、すべての操作で無条件に必須にすべきではありません。

MCP では、`producer_extend_music` と `producer_replace_section` は `lyric`
を指定するとカスタム歌詞モードを選択します。インストゥルメンタルの続き生成では、`instrumental=true` を渡して歌詞を省略できます。

## 基本的な使用方法

どのような曲を考えていても、任意のテキストを入力できます。たとえば、クリスマスに関する曲を生成したい場合は、`a song for Christmas` と入力できます。以下の図のとおりです。

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

ここでは Request Headers を設定していることが確認できます。内容は以下のとおりです。

- `accept`：受け取りたいレスポンス結果の形式です。ここでは JSON 形式である `application/json` を入力します。
- `authorization`：API を呼び出すためのキーです。申請後に直接プルダウンから選択できます。

また、Request Body のパラメータには以下が含まれます。

- `action`：今回の音楽生成タスクの操作です。曲を生成する場合は `generate` です。
- `model`：曲の作成に使用するモデルです。現在は主に以下があります： **FUZZ-2.0 Pro**、**FUZZ-2.0**、**FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**、**FUZZ-1.0 Pro**、**FUZZ-1.0**、**FUZZ-1.1**、**FUZZ-0.8**。
- `lyric`：曲の歌詞内容です。
- `custom`：カスタム方式で曲を生成するかどうかです。
- `prompt`：インスピレーションモードでのプロンプトです。
- `title`：曲のタイトル情報です。
- `audio_id`：参照する曲の ID です。続き生成／カバーなどの操作に使用します。
- `continue_at`：指定した秒数から曲の続きを生成します。
- `replace_section_start`/`replace_section_end`：置換するセクションの開始時間と終了時間です。単位は秒です。
- `lyrics_strength`：歌詞の強度です。音声生成における歌詞の影響度を示し、0～1 から選択可能で、デフォルトは 0.5 です。
- `sound_strength`：音声プロンプトの強度です。0.2～1 から選択可能で、デフォルトは 0.5 です。
- `cover_strength`：カバーの強度です。0.2～1 の範囲で、デフォルトは 1 です。
- `weirdness`：スタイルの奇抜さです。0～1 から選択可能で、デフォルトは 0.5 です。
- `callback_url`：結果のコールバックを受け取る URL です。
- `async`：任意です。`true` に設定すると、インターフェースは直ちに `task_id` を返します。`callback_url` を指定する必要はなく、その後、対応するタスク照会インターフェースを通じてポーリングし、結果を取得します。
- `instrumental`：歌詞なしモードかどうかです。

また、対応する連携コードを生成したい場合は、直接コピーして生成できます。たとえば、CURL のコードは以下のとおりです。

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## 楽曲をカバーする

すでに生成された楽曲に対してカバー操作を行いたい場合は、上記で生成した楽曲を入力してカバーできます。次に、歌詞とタイトルに基づいてカスタムで楽曲を生成します。

自分でアップロードした楽曲をさらにカバーしたい場合は、パラメータ `action` を `upload_cover` に設定し、さらにカバーしたいカスタムアップロード楽曲の ID を入力します。楽曲 ID は [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload) を使用して取得します。以下の図のとおりです：

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

以下の内容を指定できます：

- action：今回の楽曲タスクの操作です。現在対応しているのは：generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation です。今回のカバーでは `cover` パラメータを使用します。
- lyric：歌詞テキスト
- title：楽曲のタイトル。
- custom：カスタムモードで生成するかどうかです。デフォルトは false です。
- audio_id：カバーする楽曲の楽曲 ID。

curl -X POST 'https://api.acedata.cloud/producer/audios' \

## 非同期コールバック

Producer Audios Generation API の生成時間は、場合によっては比較的長くなることがあります。API が長時間応答しない場合、HTTP リクエストは接続を維持し続け、追加のシステムリソースを消費することになります。そのため、本 API は非同期コールバックもサポートしています。

全体的な流れは次のとおりです。クライアントがリクエストを開始する際に、追加で `callback_url` フィールドを指定します。クライアントが API リクエストを開始すると、API はすぐに結果を返します。その結果には現在のタスク ID を表す `task_id` フィールド情報が含まれます。タスクが完了すると、生成タスクの結果は POST JSON の形式でクライアントが指定した `callback_url` に送信され、その中にも `task_id` フィールドが含まれます。これにより、タスク結果を ID によって関連付けることができます。

以下の例を通じて、具体的な操作方法を確認します。

## エラー処理

API の呼び出し時にエラーが発生した場合、API は対応するエラーコードと情報を返します。例：

- `400 token_mismatched`：不正なリクエスト。パラメータの欠落または無効が原因である可能性があります。
- `400 api_not_implemented`：不正なリクエスト。パラメータの欠落または無効が原因である可能性があります。
- `401 invalid_token`：未認証。認証トークンが無効または欠落しています。
- `429 too_many_requests`：リクエストが多すぎます。レート制限を超過しています。
- `500 api_error`：内部サーバーエラー。サーバーで問題が発生しました。

### エラーレスポンスの例

```json
{
  "success": false,
  "error": {

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
