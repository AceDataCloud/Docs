本文將介紹一種 Midjourney Edits API 對接說明，它是可以透過輸入提示詞來編輯傳入的圖片進行生成。

## 申請流程

要使用 API，需要先到 [Midjourney Edits API](https://platform.acedata.cloud/documents/midjourney-edits) 對應頁面申請對應的服務，進入頁面之後，點擊「Acquire」按鈕，如圖所示：

![](https://cdn.acedata.cloud/q6ytrc.png)

如果你尚未登入或註冊，會自動跳轉到登入頁面邀請您來註冊和登入，登入註冊之後會自動返回當前頁面。

在首次申請時會有免費額度贈送，可以免費使用該 API。

## 基本使用

首先先了解下基本的使用方式，就是輸入提示詞 `prompt`、 生成行為 `action`、參考圖片 `image_url`，便可獲得處理後的結果，首先需要簡單地傳遞一個 `action` 欄位，它的值為 `generate`，具體的內容如下：

<p><img src="https://cdn.acedata.cloud/m44i6n.png" width="500" className="m-auto" /></p>

可以看到這裡我們設定了 Request Headers，包括：

- `accept`：想要接收怎樣格式的響應結果，這裡填寫為 `application/json`，即 JSON 格式。
- `authorization`：調用 API 的密鑰，申請之後可以直接下拉選擇。

另外設定了 Request Body，包括：

- `mask`：可以指定圖像區域的掩碼位置以進行編輯和重新生成。
- `split_images`：將生成的圖像分割成多個圖像，通過sub_image_urls欄位返回。缺省情況下，為false。
- `action`：此次編輯圖片生成任務的行為，默認是 `generate`。
- `image_url`：需要編輯的圖片鏈接。
- `prompt`：提示詞。
- `mode`：生成模式，可選 `fast`/`relax`/`turbo`。
- `callback_url`：需要回調結果的URL。

返回結果一共有多個欄位，介紹如下：

- `success`，此時圖片編輯生成任務的狀態情況。
- `task_id`，此時圖片編輯生成任務ID。
- `image_id`，此次圖片編輯任務的圖片ID。
- `sub_image_urls`，圖片生成任務的多個圖片結果。
- `image_url`，圖片生成結果的圖片鏈接。
- `image_width`，圖片生成結果的寬度。
- `image_height`，圖片生成結果的高度。
- `progress`，此時圖片編輯生成任務的進度欄位。

可以看到我們得到了滿意的圖片信息，我們只需要根據結果中 `image_url` 的圖片鏈接地址獲取生成的圖片即可。

另外如果想生成對應的對接代碼，可以直接複製生成，例如 CURL 的代碼如下：

```shell
curl -X POST 'https://api.acedata.cloud/midjourney/edits' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "A cat sitting on a table",
  "split_images": true,
  "image_url": "https://cdn.acedata.cloud/jgo1cw.jpg",
  "action": "generate"
}'
```

## 非同步回調

由於 Midjourney Edits API生成的時間相對較長，大約需要 1-2 分鐘，如果 API 長時間無響應，HTTP 請求會一直保持連接，導致額外的系統資源消耗，所以本 API 也提供了非同步回調的支持。

整體流程是：客戶端發起請求的時候，額外指定一個 `callback_url` 欄位，客戶端發起 API 請求之後，API 會立馬返回一個結果，包含一個 `task_id` 的欄位信息，代表當前的任務 ID。當任務完成之後，生成視頻的結果會通過 POST JSON 的形式發送到客戶端指定的 `callback_url`，其中也包括了 `task_id` 欄位，這樣任務結果就可以通過 ID 關聯起來了。

## 錯誤處理

在調用 API 時，如果遇到錯誤，API 會返回相應的錯誤代碼和信息。例如：

- `400 token_mismatched`：錯誤的請求，可能是由於缺少或無效的參數。
- `400 api_not_implemented`：錯誤的請求，可能是由於缺少或無效的參數。
- `401 invalid_token`：未授權，無效或缺少授權令牌。
- `429 too_many_requests`：請求過多，您已超過速率限制。
- `500 api_error`：內部伺服器錯誤，伺服器出現問題。

### 錯誤響應示例

```json
{
  "success": false,
  "error": {

}
```
