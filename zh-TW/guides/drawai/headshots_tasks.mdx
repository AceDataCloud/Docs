AI 證件照 Task API 的主要功能是通過輸入 AI 證件照製作 API 生成的任務 ID 來查詢該任務的執行情況。

本文檔將詳細介紹 AI 證件照 Task API 的對接說明，幫助您輕鬆集成並充分利用該 API 的強大功能。通過 AI 證件照 Task API，您可以輕鬆實現查詢 AI 證件照製作 API 的任務執行情況。

## 申請流程

要使用 AI 證件照 Task API，需要先到 申請頁面 [AI 證件照製作 API](https://platform.acedata.cloud/documents/bf7214a3-8447-4157-8a75-f5bb39d5ed1b) 申請相應的服務，然後複製 AI 證件照製作 API 的任務 ID，如圖所示：

<p><img src="https://cdn.acedata.cloud/7ezmmn.png" width="500" class="m-auto"></p>

最後進入 Tasks API 頁面 [AI 證件照 Task API](https://platform.acedata.cloud/documents/3a23ee34-8689-406b-9042-7954224348ad) 申請相應的服務，進入頁面之後，點擊「Acquire」按鈕，如圖所示：

![申請頁面](https://cdn.acedata.cloud/rci31i.png)

如果您尚未登錄或註冊，會自動跳轉到 [登錄頁面](https://platform.acedata.cloud) 邀請您來註冊和登錄，登錄註冊之後會自動返回當前頁面。

首次申請時會有免費額度贈送，可以免費使用該 API。

## 請求示例

AI 證件照 Task API 可以用於查詢 AI 證件照製作 API 的結果。關於怎樣使用 AI 證件照製作 API，請參考文檔 [AI 證件照製作 API](https://platform.acedata.cloud/documents/d6ea75a4-836e-490a-aee5-7ca911a808fd)。

我們以 AI 證件照製作 API 服務返回的任務 ID 一個為例，演示如何使用該 API。假設我們有一個任務 ID：`16f96e95-d95c-46ef-b183-139b9bd1aebd`，接下來演示如何通過傳入一個任務 ID 來。

### 設置請求頭和請求體

**Request Headers** 包括：

- `accept`：指定接收 JSON 格式的響應結果，這裡填寫為 `application/json`。
- `authorization`：調用 API 的密鑰，申請之後可以直接下拉選擇。

**Request Body** 包括：

- `id`：上傳的任務 ID。
- `action`：對任務的操作方式。

可以發現，在頁面右側已經自動生成了各種語言的代碼，如圖所示：

部分代碼示例如下：

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/headshots/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "16f96e95-d95c-46ef-b183-139b9bd1aebd",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/headshots/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "16f96e95-d95c-46ef-b183-139b9bd1aebd",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## 錯誤處理

在調用 API 時，如果遇到錯誤，API 會返回相應的錯誤代碼和信息。例如：

- `400 token_mismatched`：Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`：Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`：Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`：Too many requests, you have exceeded the rate limit.
- `500 api_error`：Internal server error, something went wrong on the server.
