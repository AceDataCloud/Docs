Η κύρια λειτουργία του Kling Tasks API είναι η υποβολή ερωτήματος για την κατάσταση εκτέλεσης μιας εργασίας μέσω της εισαγωγής του ID εργασίας που δημιουργήθηκε από το Kling Videos Generation API.

Αυτό το έγγραφο θα παρουσιάσει λεπτομερώς τις οδηγίες ενσωμάτωσης του Kling Tasks API, βοηθώντας σας να ενσωματώσετε εύκολα και να αξιοποιήσετε πλήρως τις ισχυρές δυνατότητες αυτού του API. Μέσω του Kling Tasks API, μπορείτε εύκολα να υλοποιήσετε την υποβολή ερωτήματος για την κατάσταση εκτέλεσης εργασιών του Kling Videos Generation API.

## Διαδικασία αίτησης

Για να χρησιμοποιήσετε το Kling Videos Generation API, μεταβείτε πρώτα στην [κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας και κρατήστε το για μελλοντική χρήση.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε ακόμη συνδεθεί ή εγγραφεί, θα ανακατευθυνθείτε αυτόματα στη σελίδα σύνδεσης, η οποία θα σας προσκαλέσει να εγγραφείτε και να συνδεθείτε, και μετά την ολοκλήρωση θα επιστρέψετε αυτόματα στην τρέχουσα σελίδα.

**Ένα API Token μπορεί να καλέσει όλες τις υπηρεσίες της πλατφόρμας, χωρίς να απαιτείται ξεχωριστή αίτηση για κάθε υπηρεσία.** Η πρώτη αίτηση προσφέρει δωρεάν πίστωση, ώστε να μπορείτε να το δοκιμάσετε δωρεάν· όταν η πίστωση δεν επαρκεί, μπορείτε να επαναφορτίσετε το γενικό υπόλοιπο στην [κονσόλα](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Παράδειγμα αιτήματος

Το Kling Tasks API μπορεί να χρησιμοποιηθεί για την υποβολή ερωτήματος για τα αποτελέσματα του Kling Videos Generation API. Για τον τρόπο χρήσης του Kling Videos Generation API, ανατρέξτε στην τεκμηρίωση [Kling Videos Generation API](https://platform.acedata.cloud/documents/kling-videos).

Θα χρησιμοποιήσουμε ως παράδειγμα ένα ID εργασίας που επιστρέφεται από την υπηρεσία Kling Videos Generation API, για να δείξουμε πώς να χρησιμοποιήσετε αυτό το API. Ας υποθέσουμε ότι έχουμε ένα ID εργασίας: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, στη συνέχεια θα δείξουμε πώς να το κάνετε μέσω της εισαγωγής ενός ID εργασίας.

### Ορισμός κεφαλίδων αιτήματος και σώματος αιτήματος

Τα **Request Headers** περιλαμβάνουν:

- `accept`: Καθορίζει τη λήψη αποτελεσμάτων απόκρισης σε μορφή JSON, εδώ συμπληρώνεται ως `application/json`.
- `authorization`: Το κλειδί για την κλήση του API, μετά την αίτηση μπορείτε να το επιλέξετε απευθείας από την αναπτυσσόμενη λίστα.

Το **Request Body** περιλαμβάνει:

- `id`: Το ID της μεταφορτωμένης εργασίας.
- `action`: Ο τρόπος ενέργειας στην εργασία.

Οι ρυθμίσεις εμφανίζονται στην παρακάτω εικόνα:

### Παράδειγμα κώδικα

Μπορείτε να διαπιστώσετε ότι στη δεξιά πλευρά της σελίδας έχει ήδη δημιουργηθεί αυτόματα κώδικας σε διάφορες γλώσσες, όπως φαίνεται στην εικόνα:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Το αποτέλεσμα επιστροφής περιλαμβάνει συνολικά πολλαπλά πεδία, το πεδίο `request` είναι το request body κατά την εκκίνηση της εργασίας, ενώ το πεδίο `response` είναι το response body που επιστρέφεται μετά την ολοκλήρωση της εργασίας. Η περιγραφή των πεδίων είναι η εξής.

- `id`, το ID που δημιουργεί αυτήν την εργασία βίντεο, χρησιμοποιείται για τη μοναδική αναγνώριση αυτής της εργασίας δημιουργίας βίντεο.
- `request`, οι πληροφορίες αιτήματος στην εργασία υποβολής ερωτήματος βίντεο.
- `response`, οι πληροφορίες επιστροφής στην εργασία υποβολής ερωτήματος βίντεο.
- `created_at`, χρόνος δημιουργίας εργασίας, χρονική σήμανση Unix (δευτερόλεπτα, κινητής υποδιαστολής).
- `started_at`, χρόνος έναρξης εκτέλεσης εργασίας, χρονική σήμανση Unix (δευτερόλεπτα, κινητής υποδιαστολής).
- `finished_at`, χρόνος ολοκλήρωσης εργασίας, χρονική σήμανση Unix (δευτερόλεπτα, κινητής υποδιαστολής). Αυτό το πεδίο δεν επιστρέφεται όταν η εργασία δεν έχει ολοκληρωθεί.
- `elapsed`, χρόνος εκτέλεσης εργασίας, σε δευτερόλεπτα (κινητής υποδιαστολής, διατηρεί 3 δεκαδικά ψηφία). Αυτό το πεδίο δεν επιστρέφεται όταν η εργασία δεν έχει ολοκληρωθεί.

## Χειρισμός σφαλμάτων

Κατά την κλήση του API, εάν προκύψει σφάλμα, το API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`：Εσφαλμένο αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`：Εσφαλμένο αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`：Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διακριτικό εξουσιοδότησης.
- `429 too_many_requests`：Πάρα πολλά αιτήματα, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`：Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.
