Αυτό το άρθρο θα παρουσιάσει έναν τρόπο ενσωμάτωσης του Kling Motion Generation API, το οποίο μπορεί να δημιουργήσει επίσημα βίντεο Kling μέσω εισαγωγής προσαρμοσμένων παραμέτρων.

## Διαδικασία αίτησης

Για να χρησιμοποιήσετε το Kling Motion Generation API, μεταβείτε πρώτα στην [Κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας και κρατήστε το για μελλοντική χρήση.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε ακόμη συνδεθεί ή εγγραφεί, θα ανακατευθυνθείτε αυτόματα στη σελίδα σύνδεσης για να εγγραφείτε και να συνδεθείτε, και μετά την ολοκλήρωση θα επιστρέψετε αυτόματα στην τρέχουσα σελίδα.

**Ένα API Token μπορεί να καλέσει όλες τις υπηρεσίες της πλατφόρμας, χωρίς να χρειάζεται να υποβάλετε ξεχωριστή αίτηση για κάθε υπηρεσία.** Η πρώτη αίτηση προσφέρει δωρεάν μονάδες για δωρεάν δοκιμή· όταν οι μονάδες δεν επαρκούν, μπορείτε να επαναφορτίσετε το γενικό υπόλοιπο στην [Κονσόλα](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [Kling Motion Generation API →](https://platform.acedata.cloud/documents/kling-motion)

## Βασική χρήση

Αρχικά, ας κατανοήσουμε τη βασική μέθοδο χρήσης: εισάγοντας τη λέξη-κλειδί `prompt`, την εικόνα αναφοράς `image_url` και τον σύνδεσμο βίντεο αναφοράς `video_url`, μπορείτε να λάβετε το επεξεργασμένο αποτέλεσμα. Στη συνέχεια, χρειάζεται επίσης να εισαγάγουμε το μοντέλο `mode`, και επί του παρόντος υπάρχουν κυρίως τα μοντέλα `std`, `pro`, με τις συγκεκριμένες λεπτομέρειες ως εξής:

<p><img src="https://cdn.acedata.cloud/5qlpjt.png" width="500" className="m-auto" /></p>

Μπορούμε να δούμε ότι εδώ έχουμε ορίσει τα Request Headers, τα οποία περιλαμβάνουν:

- `accept`: τη μορφή του αποτελέσματος απόκρισης που θέλετε να λάβετε, εδώ συμπληρώνεται ως `application/json`, δηλαδή μορφή JSON.
- `authorization`: το κλειδί για την κλήση του API, το οποίο μπορείτε να επιλέξετε απευθείας από την αναπτυσσόμενη λίστα μετά την αίτηση.

Επιπλέον, έχουν οριστεί τα Request Body, τα οποία περιλαμβάνουν:

- `image_url`: URL εικόνας αναφοράς εμφάνισης χαρακτήρα. Υποστηρίζει JPG/JPEG/PNG, αρχείο ≤50MB, πλάτος και ύψος αμφότερα ≥300px, αναλογία διαστάσεων 1:2.5～2.5:1· ο χαρακτήρας πρέπει να εμφανίζει καθαρά το πάνω μέρος του σώματος ή ολόκληρο το σώμα και το κεφάλι.
- `video_url`: URL βίντεο αναφοράς κίνησης. Υποστηρίζει MP4/MOV, αρχείο ≤100MB, πλάτος και ύψος από 340–3850px, τουλάχιστον 3 δευτερόλεπτα· όταν `character_orientation=image`, έως 10 δευτερόλεπτα, και όταν `character_orientation=video`, έως 30 δευτερόλεπτα. Συνιστάται η χρήση συνεχούς βίντεο μονού πλάνου, στο οποίο ο χαρακτήρας παραμένει πάντα εντός του κάδρου.
- `mode`: η λειτουργία δημιουργίας βίντεο, με τις δύο κύριες επιλογές να είναι η τυπική λειτουργία `std` και η λειτουργία υψηλής ταχύτητας `pro`.
- `keep_original_sound`: μπορείτε να επιλέξετε αν θα διατηρηθεί ο αρχικός ήχος του βίντεο, τιμές απαρίθμησης: yes, no.
- `character_orientation`: ο προσανατολισμός του χαρακτήρα στο παραγόμενο βίντεο, μπορείτε να επιλέξετε να είναι ίδιος με την εικόνα ή ίδιος με το βίντεο, τιμές απαρίθμησης: image, video.
- `prompt`: λέξη-κλειδί.
- `callback_url`: το URL που χρειάζεται να λάβει τα αποτελέσματα επανάκλησης.
- `async`: προαιρετικό, όταν οριστεί σε `true`, η διεπαφή επιστρέφει αμέσως το `task_id`, χωρίς να απαιτείται η παροχή `callback_url`, και στη συνέχεια το αποτέλεσμα λαμβάνεται με περιοδικά αιτήματα μέσω της αντίστοιχης διεπαφής ερωτήματος εργασίας.

Μετά την επιλογή, μπορείτε να διαπιστώσετε ότι δημιουργείται και ο αντίστοιχος κώδικας στη δεξιά πλευρά, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/buwczd.png" width="500" className="m-auto" /></p>

Κάντε κλικ στο κουμπί «Try» για να πραγματοποιήσετε τη δοκιμή. Όπως φαίνεται στην παραπάνω εικόνα, εδώ λάβαμε το ακόλουθο αποτέλεσμα:

```json
{
  "success": true,
  "video_id": "842578800134742051",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "5.066",
  "state": "succeed",
  "task_id": "363c7a84-e880-472e-a4d4-098e50cfc292"
}
```

Το επιστρεφόμενο αποτέλεσμα έχει συνολικά πολλά πεδία, τα οποία παρουσιάζονται ως εξής:

- `success`, η κατάσταση της εργασίας δημιουργίας βίντεο αυτή τη στιγμή.
- `task_id`, το ID της εργασίας δημιουργίας βίντεο αυτή τη στιγμή.
- `video_id`, το ID βίντεο της εργασίας δημιουργίας βίντεο αυτή τη στιγμή.
- `video_url`, ο σύνδεσμος βίντεο της εργασίας δημιουργίας βίντεο αυτή τη στιγμή.
- `duration`, η διάρκεια του συνδέσμου βίντεο της εργασίας δημιουργίας βίντεο αυτή τη στιγμή.
- `state`, η κατάσταση της εργασίας δημιουργίας βίντεο αυτή τη στιγμή.

Μπορούμε να δούμε ότι λάβαμε ικανοποιητικές πληροφορίες βίντεο. Χρειάζεται μόνο να λάβουμε το παραγόμενο βίντεο Kling μέσω της διεύθυνσης συνδέσμου βίντεο του `data` στα αποτελέσματα.

Επιπλέον, εάν θέλετε να δημιουργήσετε τον αντίστοιχο κώδικα ενσωμάτωσης, μπορείτε να αντιγράψετε απευθείας τον παραγόμενο κώδικα, για παράδειγμα ο κώδικας CURL είναι ο εξής:

```shell
curl -X POST 'https://api.acedata.cloud/kling/motion' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
  "video_url": "https://cdn.acedata.cloud/odwfm5.mp4",
  "prompt": "让画面生动起来",
  "mode": "std",
  "character_orientation": "image"
}'
```

## Ασύγχρονη επανάκληση

Καθώς ο χρόνος δημιουργίας του Kling Motion Generation API είναι σχετικά μεγάλος, απαιτώντας περίπου 1-2 λεπτά, εάν το API δεν ανταποκρίνεται για μεγάλο χρονικό διάστημα, το HTTP αίτημα θα διατηρεί συνεχώς τη σύνδεση, προκαλώντας πρόσθετη κατανάλωση πόρων συστήματος, επομένως αυτό το API παρέχει επίσης υποστήριξη για ασύγχρονη επανάκληση.

Η συνολική διαδικασία είναι η εξής: όταν ο πελάτης ξεκινά ένα αίτημα, καθορίζει επιπλέον ένα πεδίο `callback_url`. Αφού ο πελάτης ξεκινήσει το αίτημα API, το API επιστρέφει αμέσως ένα αποτέλεσμα, το οποίο περιλαμβάνει πληροφορίες πεδίου `task_id`, που αντιπροσωπεύει το τρέχον ID εργασίας. Όταν ολοκληρωθεί η εργασία, το αποτέλεσμα του παραγόμενου βίντεο αποστέλλεται στο `callback_url` που καθορίζει ο πελάτης σε μορφή POST JSON, το οποίο περιλαμβάνει επίσης το πεδίο `task_id`, έτσι ώστε τα αποτελέσματα της εργασίας να μπορούν να συσχετιστούν μέσω του ID.

Παρακάτω, θα κατανοήσουμε μέσω ενός παραδείγματος πώς να εκτελέσουμε συγκεκριμένα τη διαδικασία.

Αρχικά, η επανάκληση Webhook είναι μια υπηρεσία που μπορεί να λαμβάνει HTTP αιτήματα, και οι προγραμματιστές θα πρέπει να την αντικαταστήσουν με το URL του HTTP διακομιστή που έχουν δημιουργήσει οι ίδιοι. Εδώ, για διευκόλυνση της επίδειξης, χρησιμοποιείται ένας δημόσιος ιστότοπος δείγματος Webhook https://webhook.site/. Ανοίγοντας αυτόν τον ιστότοπο, μπορείτε να λάβετε ένα Webhook URL, όπως φαίνεται στην εικόνα:

![](https://cdn.acedata.cloud/tbcnai.png)

Αντιγράψτε αυτό το URL και μπορείτε να το χρησιμοποιήσετε ως Webhook. Το δείγμα εδώ είναι `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Στη συνέχεια, μπορούμε να ορίσουμε το πεδίο `callback_url` ως το παραπάνω Webhook URL, και ταυτόχρονα να συμπληρώσουμε τις αντίστοιχες παραμέτρους. Το συγκεκριμένο περιεχόμενο φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Κάντε κλικ στην εκτέλεση και μπορείτε να διαπιστώσετε ότι θα λάβετε αμέσως ένα αποτέλεσμα, ως εξής:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Περιμένετε λίγο και μπορούμε να παρατηρήσουμε το αποτέλεσμα του παραγόμενου βίντεο στο `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, όπως φαίνεται στην εικόνα:

![](https://cdn.acedata.cloud/zv5u2q.png)

Το περιεχόμενο είναι ως εξής:
```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Μπορείτε να δείτε ότι υπάρχει ένα πεδίο `task_id` στο αποτέλεσμα, τα άλλα πεδία είναι παρόμοια με τα παραπάνω και η συσχέτιση εργασιών μπορεί να υλοποιηθεί μέσω αυτού του πεδίου.

## Χειρισμός σφαλμάτων

Κατά την κλήση του API, εάν παρουσιαστεί σφάλμα, το API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και μήνυμα. Για παράδειγμα:

- `400 token_mismatched`：Μη έγκυρο αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`：Μη έγκυρο αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`：Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διακριτικό εξουσιοδότησης.
- `429 too_many_requests`：Πάρα πολλά αιτήματα, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`：Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.

### Παράδειγμα απόκρισης σφάλματος

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
