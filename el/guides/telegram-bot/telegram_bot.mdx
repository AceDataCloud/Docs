Ο διακομιστής μεσολάβησης λογαριασμού Telegram παρέχει ανεξάρτητες, μόνιμες διεπαφές MCP και REST για τον προσωπικό λογαριασμό Telegram που σας ανήκει. Κάθε στιγμιότυπο εξυπηρετεί μόνο έναν λογαριασμό· το κοντέινερ δεν περιέχει AI και η συνεδρία σύνδεσης αποθηκεύεται στον ανεξάρτητο μόνιμο τόμο αυτού του στιγμιότυπου.

> Αυτό δεν είναι bot του Telegram Bot API. Μην το χρησιμοποιείτε για ανεπιθύμητα μηνύματα, μαζικά ψυχρά μηνύματα ή παράκαμψη περιορισμών του Telegram. Πριν από την αποστολή, επεξεργασία ή διαγραφή περιεχομένου προς τρίτους, ο Agent σας θα πρέπει να λαμβάνει ρητή επιβεβαίωση.

## Ανάπτυξη και σύνδεση

1. Δημιουργήστε έναν διακομιστή μεσολάβησης λογαριασμού Telegram στο [Κονσόλα → Εφαρμογές](https://platform.acedata.cloud/console/applications), ενεργοποιήστε τη συνδρομή και, στη συνέχεια, κάντε κλικ στην ανάπτυξη. Οι πόροι του στιγμιότυπου ρυθμίζονται αυτόματα από την πλατφόρμα.
2. Αφού το στιγμιότυπο είναι έτοιμο, κάντε κλικ στο «Δημιουργία κωδικού QR σύνδεσης». Ο κωδικός QR ισχύει για σύντομο χρονικό διάστημα και μπορεί να δημιουργηθεί ξανά μετά τη λήξη του.
3. Στο Telegram, ανοίξτε **Ρυθμίσεις → Συσκευές → Σύνδεση συσκευής επιτραπέζιου υπολογιστή** και σαρώστε τον κωδικό QR.
4. Εάν η κατάσταση αλλάξει σε `password_required`, εισαγάγετε στην κονσόλα τον κωδικό επαλήθευσης σε δύο βήματα του Telegram. Ο κωδικός υποβάλλεται μόνο στο στιγμιότυπο του μισθωτή σας και δεν εγγράφεται στις ρυθμίσεις της πλατφόρμας.
5. Αφού η κατάσταση αλλάξει σε `authenticated`, η κονσόλα εμφανίζει τον τρέχοντα λογαριασμό, τη διεύθυνση MCP και το διακριτικό πρόσβασης Bearer.

Η εξουσιοδοτημένη συνεδρία αποθηκεύεται στον μόνιμο τόμο και επαναχρησιμοποιείται σε κανονικές επανεκκινήσεις και αναβαθμίσεις. Η επιλογή «Αποσύνδεση λογαριασμού» στην κονσόλα καλεί το `/api/auth/logout` για την ανάκληση της συνεδρίας Telegram· η επιλογή «Καταστροφή στιγμιότυπου» διαγράφει επίσης το φορτίο εργασίας και τον μόνιμο τόμο.

## Έλεγχος ταυτότητας και έλεγχος υγείας

Εκτός από τα `/health` και `/readyz`, οι διεπαφές σύνδεσης, REST και MCP απαιτούν όλες:

```text
Authorization: Bearer <διακριτικό πρόσβασης>
```

Η υπηρεσία δέχεται έλεγχο ταυτότητας μόνο μέσω κεφαλίδων αιτήματος και δεν υποστηρίζει την προσθήκη του διακριτικού στο URL. Προστατεύστε το όπως θα προστατεύατε τον κωδικό πρόσβασης του λογαριασμού σας.

```bash
curl https://telegram-bot-xxxxxxxxxxxx.app.acedata.cloud/health
curl https://telegram-bot-xxxxxxxxxxxx.app.acedata.cloud/readyz
```

Το `/health` υποδεικνύει μόνο ότι η διεργασία HTTP είναι ενεργή:

```json
{"status":"ok"}
```

Το `/readyz` υποδεικνύει εάν η σύνδεση MTProto είναι διαθέσιμη. Όταν είναι συνδεδεμένο, επιστρέφει HTTP 200, ακόμη και αν ο λογαριασμός εξακολουθεί να σαρώνει τον κωδικό ή να αναμένει επαλήθευση σε δύο βήματα:

```json
{"status":"ready","gateway_connected":true,"login_state":"login_required"}
```

Όταν η σύνδεση διακόπτεται, η άμεση διερεύνηση του Pod από το Kubernetes επιστρέφει HTTP 503 και το στιγμιότυπο επανασυνδέεται αυτόματα στο παρασκήνιο. Σε αυτήν την περίπτωση, το Pod αφαιρείται προσωρινά από τη δημόσια Service και δεν εγγυάται ότι μπορείτε να διαβάσετε το διαγνωστικό JSON μέσω του ονόματος τομέα του στιγμιότυπου· περιμένετε στην κονσόλα να επιστρέψει το Deployment σε Ready. Οι συνήθεις τιμές του `login_state` περιλαμβάνουν `login_required`, `waiting_scan`, `password_required`, `authenticated`· πριν από την εκτέλεση λειτουργιών μηνυμάτων λογαριασμού, πρέπει και πάλι να επιτευχθεί η κατάσταση `authenticated`.

## Σύνδεση προγράμματος-πελάτη MCP

### Claude Code

```bash
claude mcp add \
  --transport http \
  --header "Authorization: Bearer <διακριτικό πρόσβασης>" \
  telegram \
  https://telegram-bot-xxxxxxxxxxxx.app.acedata.cloud/mcp
```

### Cursor και άλλοι πελάτες που υποστηρίζουν στατικές κεφαλίδες αιτήματος

Ρυθμίστε τη διεύθυνση Streamable HTTP σύμφωνα με την τρέχουσα τεκμηρίωση του προγράμματος-πελάτη και προσθέστε την κεφαλίδα αιτήματος `Authorization`. Για παράδειγμα, πελάτες που υποστηρίζουν την ακόλουθη δομή μπορούν να χρησιμοποιήσουν:

```json
{
  "mcpServers": {
    "telegram": {
      "type": "http",
      "url": "https://telegram-bot-xxxxxxxxxxxx.app.acedata.cloud/mcp",
      "headers": {"Authorization": "Bearer <διακριτικό πρόσβασης>"}
    }
  }
}
```

Αυτή δεν είναι μια καθολική μορφή ρύθμισης για όλους τους πελάτες MCP. Οι απομακρυσμένοι σύνδεσμοι του Claude Desktop / Claude.ai δημιουργούνται από το cloud και δεν διαβάζουν οποιαδήποτε κεφαλίδα αιτήματος HTTP στο τοπικό `claude_desktop_config.json`· προς το παρόν, εάν χρειάζεστε στατική κεφαλίδα Bearer, χρησιμοποιήστε το Claude Code ή έναν πελάτη που υποστηρίζει ρητά αυτήν τη δυνατότητα.

## Εργαλεία MCP

| Εργαλείο                         | Λειτουργία                |
| -------------------------- | ----------------- |
| `telegram_whoami`          | Προβολή του τρέχοντος εξουσιοδοτημένου λογαριασμού          |
| `telegram_list_chats`      | Εμφάνιση πρόσφατων συνομιλιών, με δυνατότητα προβολής μόνο των μη αναγνωσμένων      |
| `telegram_contacts`        | Εμφάνιση επαφών             |
| `telegram_read_messages`   | Ανάγνωση πρόσφατων μηνυμάτων από καθορισμένη συνομιλία       |
| `telegram_search_messages` | Αναζήτηση σε μία συνομιλία ή σε όλες τις συνομιλίες       |
| `telegram_send_message`    | Αποστολή μηνύματος, με δυνατότητα απάντησης σε καθορισμένο μήνυμα      |
| `telegram_edit_message`    | Επεξεργασία μηνύματος που στάλθηκε από τον τρέχοντα λογαριασμό       |
| `telegram_delete_message`  | Διαγραφή μηνύματος για το οποίο υπάρχει δικαίωμα διαγραφής        |
| `telegram_react`           | Αντίδραση σε μήνυμα με Unicode emoji |
| `telegram_mark_read`       | Επισήμανση συνομιλίας ως αναγνωσμένης          |

Το `target` μπορεί να είναι ID συνομιλίας, όνομα χρήστη ή **ακριβές** όνομα συνομιλίας· όταν το όνομα είναι αμφίσημο, προτιμήστε τη χρήση ID ή ονόματος χρήστη.

## REST API

Όλες οι επιτυχημένες αποκρίσεις χρησιμοποιούν `{"data": ...}`, ενώ οι αποτυχημένες αποκρίσεις χρησιμοποιούν `{"error": "..."}`.

### Παραδείγματα

```bash
# Τρέχων λογαριασμός
curl https://telegram-bot-xxxxxxxxxxxx.app.acedata.cloud/api/whoami \
  -H "Authorization: Bearer $PROXY_ACCESS_TOKEN"

# Πρόσφατες συνομιλίες
curl "https://telegram-bot-xxxxxxxxxxxx.app.acedata.cloud/api/chats?limit=20&unread_only=false" \
  -H "Authorization: Bearer $PROXY_ACCESS_TOKEN"

# Αποστολή δοκιμαστικού μηνύματος στα Αποθηκευμένα μηνύματα
curl -X POST https://telegram-bot-xxxxxxxxxxxx.app.acedata.cloud/api/messages \
  -H "Authorization: Bearer $PROXY_ACCESS_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"target":"me","text":"Hello from my Telegram proxy"}'
```

### Πλήρεις διεπαφές

| Μέθοδος και διαδρομή                                                      | Κύριες παράμετροι                      | Λειτουργία                    |
| ---------------------------------------------------------- | ------------------------- | --------------------- |
| `POST /api/auth/qr`                                        | —                         | Δημιουργία URL κωδικού QR σύνδεσης           |
| `GET /api/auth/status`                                     | —                         | Ερώτημα κατάστασης σύνδεσης και πληροφοριών λογαριασμού           |
| `POST /api/auth/password`                                  | `{password}`              | Υποβολή κωδικού επαλήθευσης σε δύο βήματα              |
| `POST /api/auth/logout`                                    | —                         | Ανάκληση συνεδρίας που έχει αποθηκευτεί στο στιγμιότυπο             |
| `GET /api/whoami`                                          | —                         | Προβολή τρέχοντος λογαριασμού                |
| `GET /api/chats`                                           | `?limit=&unread_only=`    | Εμφάνιση συνομιλιών και αριθμού μη αναγνωσμένων              |
| `GET /api/contacts`                                        | —                         | Εμφάνιση επαφών                 |
| `GET /api/chats/{target}/messages`                         | `?limit=`                 | Ανάγνωση μηνυμάτων                  |
| `GET /api/messages/search`                                 | `?q=&target=&limit=`      | Αναζήτηση μηνυμάτων· η παράλειψη του target πραγματοποιεί αναζήτηση σε όλες τις συνομιλίες |
| `POST /api/messages`                                       | `{target,text,reply_to?}` | Αποστολή ή απάντηση σε μήνυμα               |
| `PATCH /api/chats/{target}/messages/{message_id}`          | `{text}`                  | Επεξεργασία μηνύματος                  |
| `DELETE /api/chats/{target}/messages/{message_id}`         | —                         | Διαγραφή μηνύματος                  |
| `POST /api/chats/{target}/messages/{message_id}/reactions` | `{emoji}`                 | Προσθήκη αντίδρασης με Unicode emoji       |
| `POST /api/chats/{target}/read`                            | —                         | Επισήμανση συνομιλίας ως αναγνωσμένης                |

## Συχνές ερωτήσεις
- **401**：Το Bearer token λείπει ή είναι λανθασμένο. Επιβεβαιώστε ότι το token τοποθετείται στην κεφαλίδα του αιτήματος, όχι στις παραμέτρους αναζήτησης URL.
- **503**：Το token πρόσβασης μεσολάβησης δεν έχει ρυθμιστεί ή ο πελάτης Telegram δεν είναι ακόμη έτοιμος. Ελέγξτε πρώτα το `/readyz`· εάν το token πρόσβασης μεσολάβησης δεν έχει ρυθμιστεί, οι προστατευμένες διεπαφές θα επιστρέφουν επίσης 503.
- **400**：Οι παράμετροι ή το JSON είναι μη έγκυρα· η αναζήτηση πρέπει να παρέχει `q`, και το `limit` πρέπει να είναι ακέραιος μεγαλύτερος ή ίσος με 1.
- **403 / 404**：Ο τρέχων λογαριασμός δεν έχει δικαιώματα ή το target / message ID δεν υπάρχει.
- **429**：Ενεργοποιήθηκε ο περιορισμός συχνότητας του Telegram. Διαβάστε το `retry_after` και περιμένετε, μην επαναλαμβάνετε τις προσπάθειες ταυτόχρονα.
- **Ο κωδικός QR παραμένει συνεχώς ημιτελής**：Δημιουργήστε ξανά τον κωδικό QR και επιβεβαιώστε ότι χρησιμοποιείτε την είσοδο σάρωσης Telegram «Σύνδεση συσκευής επιφάνειας εργασίας».
- **Απαιτείται εκ νέου σύνδεση μετά την επανεκκίνηση**：Ελέγξτε αν ο μόνιμος τόμος της παρουσίας λειτουργεί κανονικά· απαιτείται εκ νέου σάρωση μετά από ενεργή αποσύνδεση, ανάκληση της συνεδρίας στη λίστα συσκευών Telegram ή λήξη της συνεδρίας.

## Εύρος επαλήθευσης

Ο πηγαίος κώδικας και οι αυτοματοποιημένες δοκιμές καλύπτουν την κατάσταση σύνδεσης, το Bearer fail-close, την επικύρωση παραμέτρων REST, την αντιστοίχιση σφαλμάτων και την υλοποίηση μονιμότητας συνεδρίας. Η χρήση στην παραγωγή θα πρέπει και πάλι πρώτα να ολοκληρώνει smoke μόνο για ανάγνωση και δημιουργία/επεξεργασία/διαγραφή μηνυμάτων στο `target=me` (Αποθηκευμένα μηνύματα), πριν επιτραπεί στον Agent να χειρίζεται συνεδρίες τρίτων.
