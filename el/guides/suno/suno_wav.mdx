Η SUNO μας επιτρέπει να λαμβάνουμε αρχεία μουσικής σε μορφή wav. Αυτό το έγγραφο εξηγεί τον τρόπο ενσωμάτωσης του σχετικού API.

Η βασική παράμετρος εισόδου αυτού του API είναι το `audio_id`, το οποίο είναι το επίσημο αναγνωριστικό τραγουδιού που δημιουργείται από την υπηρεσία. Επιπλέον, υποστηρίζεται προαιρετικά η παράμετρος `callback_url` για ασύγχρονη επιστροφή κλήσης.

Εδώ, το `audio_id` που εισάγουμε είναι `4e43116a-bf09-472c-8e1c-655eabf02682`.

```python
import requests

url = "https://api.acedata.cloud/suno/wav"

headers = {
    "accept": "application/json",
    "authorization": "Bearer aa287fa4cc54401087a9fab3f99630af",
    "content-type": "application/json"
}

payload = {
    "audio_id": "4e43116a-bf09-472c-8e1c-655eabf02682"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Το αποτέλεσμα είναι το εξής:

```json
{
  "success": true,
  "task_id": "6a5a2099-d6d3-4930-9709-a30ac5dc7de5",
  "trace_id": "3fa70e81-6bb7-4ca8-b718-dd16a4eda7e8",
  "data": [
    {
      "file_url": "https://platform.cdn.acedata.cloud/suno/6a5a2099-d6d3-4930-9709-a30ac5dc7de5.wav"
    }
  ]
}
```

Όπως φαίνεται, το πεδίο `file_url` μέσα στο `data` είναι το αρχείο μουσικής σε μορφή wav που λαμβάνουμε, και είναι μια διεύθυνση CDN με δημόσια πρόσβαση.

> **Σχετικά με τη διατήρηση των συνδέσμων WAV**
>
> Τα αρχεία WAV στο upstream Suno CDN (`https://cdn1.suno.ai/{audio_id}.wav`) διατηρούνται μόνο για λίγες ημέρες και στη συνέχεια ανακτώνται, με αποτέλεσμα την επιστροφή κωδικού 403 κατά την πρόσβαση.
> Για να αποφευχθεί η λήξη των συνδέσμων, αυτό το API μεταφέρει αυτόματα το upstream αρχείο WAV στο δικό μας CDN (`https://platform.cdn.acedata.cloud/suno/{task_id}.wav`) πριν την επιστροφή, και το επιστρεφόμενο `file_url` είναι η σταθερή διεύθυνση μετά τη μεταφορά, η οποία δεν λήγει λόγω του upstream CDN.
> Σε περίπτωση αποτυχίας της μεταφοράς (πολύ σπάνια), το API επιστρέφει τον αρχικό upstream URL, διατηρώντας την προηγούμενη συμπεριφορά.
