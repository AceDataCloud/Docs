Το API έργου Suno Studio διαχειρίζεται πολυκάναλα μουσικά έργα μέσω ενός σημείου εισόδου:

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
```

Το `action` στο αίτημα καθορίζει τον τύπο λειτουργίας. Το πρωτεύον κλειδί του Project χρησιμοποιεί ενιαία το `id`· το `version_id` υποδηλώνει την τρέχουσα έκδοση έργου, και όλες οι λειτουργίες τροποποίησης και εξαγωγής πρέπει να υποβάλλουν την πιο πρόσφατη έκδοση, ώστε να αποφεύγεται η ταυτόχρονη αντικατάσταση.

## Επισκόπηση λειτουργιών

| action             | Τρόπος  | Χρήση                      |
| ------------------ | --- | ----------------------- |
| `create`           | Σύγχρονο  | Δημιουργία κενού έργου                   |
| `retrieve`         | Σύγχρονο  | Ανάγνωση έργου και πλήρους επεξεργάσιμου `state`      |
| `save`             | Σύγχρονο  | Αποθήκευση πλήρους κατάστασης έργου                |
| `upload`           | Ασύγχρονο  | Αρχικοποίηση υλικού που μπορεί να προστεθεί στο έργο από διεύθυνση ήχου HTTPS |
| `add_track`        | Ασύγχρονο  | Προσθήκη υπάρχοντος ήχου στο έργο               |
| `generate_track`   | Ασύγχρονο  | Δημιουργία νέων υποψηφίων ηχητικού κομματιού για καθορισμένο διάστημα            |
| `replace_section`  | Ασύγχρονο  | Δημιουργία υποψηφίων τοπικής αντικατάστασης                |
| `commit_candidate` | Ασύγχρονο  | Υποβολή του επιλεγμένου υποψηφίου στο έργο             |
| `remove_track`     | Σύγχρονο  | Διαγραφή καθορισμένου κομματιού                  |
| `render`           | Ασύγχρονο  | Εξαγωγή αποθηκευμένης έκδοσης ως πλήρες τραγούδι           |

Οι ασύγχρονες λειτουργίες επιστρέφουν αμέσως `task_id`. Χρησιμοποιήστε τη δωρεάν διεπαφή `/suno/tasks` για polling ή περάστε `callback_url` για να λάβετε το τελικό αποτέλεσμα.

## Δημιουργία και ανάγνωση

```json
{"action":"create","title":"My Studio Project"}
```

Όλες οι λειτουργίες τροποποίησης πρέπει να στέλνουν μοναδικό Header `Idempotency-Key`. Μετά την επιτυχή δημιουργία, το `data.id` στην απόκριση είναι το Project ID. Ένα νέο κενό έργο ενδέχεται να μην έχει `version_id` πριν από την πρώτη αποθήκευση.

```json
{"action":"retrieve","id":"PROJECT_ID"}
```

Η απόκριση ανάγνωσης περιλαμβάνει το πλήρες `state`. Ένα νέο κενό έργο επιστρέφει `{"tracks":[],"timing":{"bps":2}}`, το οποίο μπορεί να χρησιμοποιηθεί απευθείας για την πρώτη αποθήκευση. Το `timing.bps` υποδηλώνει τους χτύπους ανά δευτερόλεπτο, με προεπιλογή το 2 (120 BPM), και πρέπει να είναι θετικός αριθμός· τα `startBeats`, `endBeats` και `readStartBeats` των αποσπασμάτων χρησιμοποιούν τη μονάδα χτύπων του έργου και δεν μπορείτε να αντιμετωπίζετε απευθείας τις θέσεις μέτρων στην ανάλυση ήχου ως συντεταγμένες χρονογραμμής.

## Αποθήκευση πλήρους κατάστασης

```json
{
  "action":"save",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "title":"Edited Project",
  "state":{"tracks":[],"timing":{"bps":2}}
}
```

Η πρώτη αποθήκευση ενός νέου κενού έργου μπορεί να παραλείπει το `version_id`· αφού η πρώτη αποθήκευση δημιουργήσει έκδοση, οι επόμενες αποθηκεύσεις πρέπει να υποβάλλουν την πιο πρόσφατη τιμή. Εάν η έκδοση έχει ήδη αλλάξει, η διεπαφή επιστρέφει HTTP 409. Σε αυτήν την περίπτωση, εκτελέστε ξανά `retrieve`, συγχωνεύστε τις τροποποιήσεις και υποβάλετε ξανά με νέο κλειδί idempotency· μην επαναλαμβάνετε τυφλά το παλιό αίτημα.

## Μεταφόρτωση και προσθήκη κομματιών

```json
{
  "action":"upload",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "audio_url":"https://cdn.example.com/reference.mp3",
  "async":true
}
```

Μετά την επιτυχή μεταφόρτωση, διαβάστε το ID ήχου από το `response.data.candidate.audio_id`. Στη συνέχεια, προσθέστε το στο έργο:

```json
{
  "action": "add_track",
  "id": "PROJECT_ID",
  "version_id": "CURRENT_VERSION_ID",
  "audio_id": "AUDIO_ID",
  "name": "Backing Vocals"
}
```

Η προσθήκη κομματιού διατηρεί από προεπιλογή την ταχύτητα αναπαραγωγής του ήχου και μετατρέπει τη διάρκεια του ήχου σε χτύπους με βάση το `timing.bps` του έργου. Μετά από κάθε `save`, `add_track`, `commit_candidate` ή `remove_track`, πρέπει να χρησιμοποιείτε το νέο `version_id` στην απόκριση.

## Δημιουργία και αντικατάσταση

Το `generate_track` δημιουργεί υποψηφίους ηχητικού κομματιού για διάστημα έργου· το `replace_section` επιστρέφει δύο υποψηφίους τοπικής αντικατάστασης. Καμία από τις δύο λειτουργίες δεν επιλέγει αυτόματα καλλιτεχνικό αποτέλεσμα. Το μοντέλο πρέπει να χρησιμοποιεί δημόσια ονόματα: `chirp-v3-5`, `chirp-v4`, `chirp-v4-5`, `chirp-v4-5-plus`, `chirp-v5`, `chirp-v5-5`, `chirp-v6`, `chirp-v6-wild` ή `chirp-v6-mini`· η διαθεσιμότητα για συγκεκριμένη λειτουργία εξακολουθεί να καθορίζεται από την τελική κατάσταση της εργασίας, ενώ τα μη υποστηριζόμενα ονόματα επιστρέφουν 400 πριν από την υποβολή. Δεν γίνεται αυτόματη αλλαγή σε άλλο μοντέλο.

```json
{
  "action":"replace_section",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "source_audio_id":"AUDIO_ID",
  "start_seconds":35.12,
  "end_seconds":48.76,
  "model":"chirp-v6",
  "replacement_lyrics":"新的歌词片段",
  "async":true
}
```

Το `generate_track` πρέπει επίσης να παρέχει `render_audio_id` (ολοκληρωμένος ήχος εξαγωγής έργου), `stem_control_tags` και το ID πηγαίου ήχου `source_audio_id`. Το `batch_size` είναι 1–4, με προεπιλογή το 2· τα `start_seconds`, `end_seconds` είναι δευτερόλεπτα του πηγαίου ήχου. Το διάστημα αντικατάστασης με `fixed=true` πρέπει να είναι μικρότερο από 26 δευτερόλεπτα.

Υποβάλετε μετά την επιλογή υποψηφίου:

```json
{
  "action":"commit_candidate",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "operation_id":"OPERATION_ID",
  "candidate_id":"CANDIDATE_ID",
  "track_id":"TRACK_ID"
}
```

Οι υποψήφιοι συνδέονται με την έκδοση έργου κατά τη δημιουργία. Όταν το έργο έχει ήδη αλλάξει, οι παλιοί υποψήφιοι δεν μπορούν να υποβληθούν απευθείας.

Οι υποψήφιοι τοπικής αντικατάστασης υποβάλλονται στο αρχικό κομμάτι που περιέχει το μοναδικό πηγαίο απόσπασμα, ενώ οι υποψήφιοι πλήρους take διατηρούν την αρχική θέση και αντικαθιστούν το αρχικό απόσπασμα· οι υποψήφιοι διαστήματος αντικαθιστούν μόνο το ζητούμενο διάστημα και διατηρούν τα αποσπάσματα πριν και μετά. Όταν δεν είναι δυνατή η αξιόπιστη αντιστοίχιση της διάρκειας, επιστρέφεται 400 και διατηρείται το αρχικό έργο· σε αυτήν την περίπτωση μην περάσετε `start_beats`, `end_beats`. Οι υποψήφιοι νέου κομματιού πρέπει να υποβάλλονται σε κενό κομμάτι που έχει αποθηκευτεί εκ των προτέρων, χρησιμοποιώντας από προεπιλογή την αρχή του πηγαίου αποσπάσματος ή περνώντας ρητά ένα εύρος χωρίς επικάλυψη· η επικάλυψη με υπάρχοντα αποσπάσματα στο ίδιο κομμάτι επιστρέφει 400. Μην δημιουργείτε πρώτα και έπειτα νέο κομμάτι, διαφορετικά η αλλαγή έκδοσης θα καταστήσει τον υποψήφιο ληγμένο.

## Εξαγωγή πλήρους τραγουδιού

```json
{
  "action":"render",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "title":"Final Mix",
  "lyrics":"[Instrumental]",
  "async":true,
  "callback_url":"https://example.com/webhooks/suno"
}
```

Ο διακομιστής διαβάζει την έγκυρη κατάσταση έργου της καθορισμένης έκδοσης και συνθέτει τις παραμέτρους εξαγωγής. Όταν παραλείπονται τα `start_beats`, `end_beats`, εξάγεται από προεπιλογή το νωρίτερο σημείο έναρξης έως το τελευταίο σημείο λήξης όλων των ακουστών αποσπασμάτων· τα σιωπηλά κομμάτια/αποσπάσματα δεν συμμετέχουν και, όταν υπάρχουν solo κομμάτια, επιλέγονται μόνο τα solo κομμάτια. Κενό έργο ή έργο χωρίς έγκυρα ακουστά κομμάτια επιστρέφει 400. Το τελικό αποτέλεσμα περιλαμβάνει `render_id`, `audio_id`, `audio_url` και διάρκεια. Το έργο συνδέεται με το περιβάλλον εκτέλεσης κατά τη δημιουργία και δεν μπορεί να μεταφερθεί μεταξύ περιβαλλόντων ή να πραγματοποιήσει αυτόματη εναλλαγή σε περίπτωση αστοχίας.

> Μπορείτε να μεταφορτώνετε ή να επεξεργάζεστε μόνο ήχο για τον οποίο διαθέτετε νόμιμο δικαίωμα χρήσης. Το API έργων βρίσκεται επί του παρόντος σε Beta· αποθηκεύστε μόνιμα τα τελικά URL ήχου στα σημαντικά αποτελέσματα.

## Polling και αποκατάσταση αποτυχίας

```json
{"action":"retrieve","id":"TASK_ID"}
```
Στείλτε το παραπάνω αίτημα στο `/suno/tasks`. Μια εργασία Projects θεωρείται επιτυχής όταν υπάρχει `finished_at` και `response.success=true`· το `response.success=false` υποδηλώνει αποτυχία. Η επιστροφή HTTP 200 ή `task_id` κατά την υποβολή σημαίνει μόνο ότι το αίτημα έγινε δεκτό, όχι ότι ο ήχος έχει ολοκληρωθεί.

Το ίδιο `Idempotency-Key` με το ίδιο αίτημα θα επιστρέψει ξανά το αρχικό αποτέλεσμα (συμπεριλαμβανομένων των αποτυχιών), χωρίς αυτόματη επαναδημιουργία ή διπλή χρέωση. Για να επαναλάβετε ρητά μια αποτυχημένη ενέργεια, πρώτα ελέγξτε την αρχική εργασία για να επιβεβαιώσετε την αποτυχία και έπειτα χρησιμοποιήστε νέο κλειδί· μην υποβάλετε ξανά όσο η αρχική εργασία εξακολουθεί να επεξεργάζεται ή το αποτέλεσμα είναι αβέβαιο.

Οι κατηγορίες σφαλμάτων περιλαμβάνουν `studio_unavailable` / `studio_model_unavailable` (503, προσωρινή αδυναμία επεξεργασίας ή μη διαθεσιμότητα μοντέλου), `studio_model_unsupported` (400, το μοντέλο δεν υποστηρίζει αυτή την ενέργεια), `studio_state_invalid` (400, μη έγκυρη κατάσταση έργου ή εύρος εξαγωγής), `too_many_requests` (429), `studio_audio_unavailable` (403, ο αναφερόμενος ήχος δεν μπορεί να χρησιμοποιηθεί για εξαγωγή έργου) και `content_rejected` (403). Διατηρήστε το `trace_id` για διερεύνηση.
