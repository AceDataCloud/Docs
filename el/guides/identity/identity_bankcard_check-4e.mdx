Αυτό το έγγραφο θα εισαγάγει μια μέθοδο σύνδεσης API επαλήθευσης τεσσάρων στοιχείων κάρτας, η οποία μπορεί να χρησιμοποιηθεί για την εισαγωγή αριθμού κάρτας, ονόματος, αριθμού ταυτότητας και αριθμού τηλεφώνου, για την επαλήθευση της γνησιότητας και της συνέπειας των πληροφοριών.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το API επαλήθευσης τεσσάρων στοιχείων κάρτας, πρώτα πηγαίνετε στην [Κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας, το οποίο θα κρατήσετε για μελλοντική χρήση.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης που σας προσκαλεί να εγγραφείτε και να συνδεθείτε, και μετά θα επιστρέψετε αυτόματα στη σελίδα που βρίσκεστε.

**Ένα API Token αρκεί για να καλέσετε όλες τις υπηρεσίες της πλατφόρμας, χωρίς να χρειάζεται να ζητήσετε ξεχωριστά για κάθε υπηρεσία.** Η πρώτη αίτηση θα σας δώσει δωρεάν πιστώσεις για να δοκιμάσετε δωρεάν. Όταν οι πιστώσεις σας εξαντληθούν, μπορείτε να ανανεώσετε το γενικό σας υπόλοιπο στην [κονσόλα](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [API Επαλήθευσης Τεσσάρων Στοιχείων Κάρτας →](https://platform.acedata.cloud/documents/identity-bankcard-check-4e)

## Βασική Χρήση

Πρώτα πρέπει να κατανοήσετε τη βασική μέθοδο χρήσης, δηλαδή να εισάγετε τις πληροφορίες του αριθμού κάρτας, για να λάβετε την επεξεργασμένη εικόνα αποτελέσματος, χρειάζεται απλώς να περάσετε ένα πεδίο `bank_card`. Στη συνέχεια, μπορούμε να συμπληρώσουμε τα αντίστοιχα περιεχόμενα στην διεπαφή, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/1pl0y5.png" width="500" className="m-auto" /></p>

Μπορείτε να δείτε ότι έχουμε ρυθμίσει τα Request Headers, που περιλαμβάνουν:

- `accept`: ποια μορφή απάντησης θέλετε να λάβετε, εδώ συμπληρώνεται ως `application/json`, δηλαδή σε μορφή JSON.
- `authorization`: το κλειδί για την κλήση του API, μπορείτε να το επιλέξετε απευθείας μετά την αίτηση.

Επιπλέον, έχουμε ρυθμίσει το Request Body, που περιλαμβάνει:

- `bank_card`: οι πληροφορίες του αριθμού κάρτας που χρειάζονται επεξεργασία, είναι υποχρεωτική παράμετρος.
- `id_card`: αριθμός ταυτότητας, είναι υποχρεωτική παράμετρος.
- `name`: το όνομα του χρήστη, είναι υποχρεωτική παράμετρος.
- `phone`: αριθμός τηλεφώνου.
- `cert_type`: τύπος ταυτότητας, πρέπει να είναι συμβατός με την ταυτότητα.
- `encryption`: προαιρετικό, παράμετρος κρυπτογράφησης ευαίσθητων πεδίων (εάν χρειάζεται να στείλετε κρυπτογραφημένα δεδομένα).

Αφού επιλέξετε, μπορείτε να δείτε ότι έχει παραχθεί ο αντίστοιχος κώδικας στα δεξιά, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/slajgv.png" width="500" className="m-auto" /></p>

Κάντε κλικ στο κουμπί «Δοκιμή» για να κάνετε δοκιμές, όπως φαίνεται στην παραπάνω εικόνα, εδώ έχουμε λάβει το εξής αποτέλεσμα:

```json
{
  "result": "0",
  "description": "Η πιστοποίηση είναι επιτυχής"
}
```

Η επιστρεφόμενη απάντηση περιλαμβάνει πολλά πεδία, που περιγράφονται ως εξής:

- `result`, κωδικός αποτελέσματος πιστοποίησης, οι χρεώσεις είναι οι εξής.
    - Κωδικοί χρέωσης:
        - 0: Η πιστοποίηση είναι επιτυχής
        - -1: Η πιστοποίηση δεν είναι επιτυχής
        - -4: Λάθος πληροφορίες κατόχου κάρτας
        - -5: Δεν έχει ενεργοποιηθεί η πληρωμή χωρίς κάρτα
        - -6: Αυτή η κάρτα έχει κατασχεθεί
        - -7: Μη έγκυρος αριθμός κάρτας
        - -8: Αυτή η κάρτα δεν έχει αντίστοιχη τράπεζα εκδότρια
        - -9: Αυτή η κάρτα δεν έχει αρχικοποιηθεί ή είναι ανενεργή
        - -10: Κάρτα απάτης, κατάσχεση κάρτας
        - -11: Αυτή η κάρτα έχει δηλωθεί ως χαμένη
        - -12: Αυτή η κάρτα έχει λήξει
        - -13: Περιορισμένη κάρτα
        - -14: Υπερβολικές αποτυχημένες προσπάθειες κωδικού
        - -15: Η τράπεζα εκδότρια δεν υποστηρίζει αυτή τη συναλλαγή
    - Κωδικοί χωρίς χρέωση:
        - -2: Η επαλήθευση του ονόματος δεν είναι επιτυχής
        - -3: Λάθος αριθμός τραπεζικής κάρτας
        - -16: Η υπηρεσία επαλήθευσης είναι απασχολημένη
        - -17: Υπερβολικές προσπάθειες επαλήθευσης, παρακαλώ δοκιμάστε ξανά την επόμενη μέρα
- `description`, περιγραφή του επιχειρηματικού αποτελέσματος.

Μπορείτε να δείτε ότι ο αριθμός της κάρτας, το όνομα, ο αριθμός ταυτότητας και ο αριθμός τηλεφώνου αυτής της κάρτας έχουν γνησιότητα και συνέπεια.

Επιπλέον, εάν θέλετε να δημιουργήσετε τον αντίστοιχο κώδικα σύνδεσης, μπορείτε να τον αντιγράψετε απευθείας, όπως ο κώδικας CURL παρακάτω:

```shell
curl -X POST 'https://api.acedata.cloud/identity/bankcard/check-4e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "phone": "***",
  "id_card": "***",
  "bank_card": "***"
}'
```

Ο κώδικας σύνδεσης Python είναι ως εξής:

```python
import requests

url = "https://api.acedata.cloud/identity/bankcard/check-4e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "name": "胡印福",
    "phone": "***",
    "id_card": "***",
    "bank_card": "***"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Διαχείριση Σφαλμάτων

Κατά την κλήση του API, εάν προκύψουν σφάλματα, το API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές token εξουσιοδότησης.
- `429 too_many_requests`: Υπερβολικές αιτήσεις, έχετε ξεπεράσει το όριο ρυθμού.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.

### Παράδειγμα Σφάλματος Απόκρισης

```json
{

  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
