Αυτό το έγγραφο θα παρουσιάσει μια μέθοδο σύνδεσης API επαλήθευσης φωτογραφίας ταυτότητας, η οποία μπορεί να χρησιμοποιηθεί για την εισαγωγή φωτογραφίας της ταυτότητας, την αναγνώριση των πληροφοριών στη φωτογραφία της ταυτότητας και τη σύγκριση του ονόματος, του αριθμού ταυτότητας και της φωτογραφίας της ταυτότητας με τις φωτογραφίες από την εξουσιοδοτημένη βάση δεδομένων, προκειμένου να επαληθευτεί αν ανήκουν στο ίδιο άτομο, επιβεβαιώνοντας έτσι την αυθεντικότητα των πληροφοριών της ταυτότητας.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το API, πρέπει πρώτα να επισκεφθείτε τη σελίδα [API Επαλήθευσης Φωτογραφίας Ταυτότητας](https://platform.acedata.cloud/documents/7a3f14f7-f1eb-41c2-816c-9f18caca6883) και να ζητήσετε την αντίστοιχη υπηρεσία. Αφού εισέλθετε στη σελίδα, κάντε κλικ στο κουμπί «Acquire», όπως φαίνεται στην εικόνα:

![](https://cdn.acedata.cloud/q6ytrc.png)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα ανακατευθυνθείτε αυτόματα στη σελίδα σύνδεσης για να εγγραφείτε και να συνδεθείτε. Μετά την εγγραφή και τη σύνδεση, θα επιστρέψετε αυτόματα στη σελίδα.

Κατά την πρώτη αίτηση, θα λάβετε δωρεάν πιστώσεις για να χρησιμοποιήσετε το API χωρίς χρέωση.

## Βασική Χρήση

Αρχικά, πρέπει να κατανοήσετε τη βασική μέθοδο χρήσης, δηλαδή να εισάγετε τον σύνδεσμο της φωτογραφίας της ταυτότητας, για να λάβετε το αποτέλεσμα επαλήθευσης. Πρέπει πρώτα να περάσετε ένα πεδίο `image_url`, και στη συνέχεια μπορείτε να συμπληρώσετε τα αντίστοιχα περιεχόμενα στην διεπαφή, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/zjxg3k.png" width="500" class="m-auto"></p>

Μπορείτε να δείτε ότι έχουμε ρυθμίσει τα Request Headers, που περιλαμβάνουν:

- `accept`: τη μορφή της απάντησης που θέλετε να λάβετε, εδώ συμπληρώνεται ως `application/json`, δηλαδή σε μορφή JSON.
- `authorization`: το κλειδί για την κλήση του API, το οποίο μπορείτε να επιλέξετε απευθείας από την αναπτυσσόμενη λίστα μετά την αίτηση.

Επιπλέον, έχουμε ρυθμίσει το Request Body, που περιλαμβάνει:

- `image_url`: τον σύνδεσμο της φωτογραφίας της ταυτότητας που χρειάζεται επεξεργασία.
- `config`: προαιρετική ρύθμιση, πεδίο boolean, με προεπιλεγμένη τιμή false, υποστηρίζει `copy_warn`, `border_check_warn`, `reshoot_warn`, `detect_ps_warn`, `temp_id_warn`, `quality` (όριο 0-100).

Αφού επιλέξετε, μπορείτε να δείτε ότι έχει παραχθεί ο αντίστοιχος κώδικας στα δεξιά, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/4yh23p.png" width="500" class="m-auto"></p>

Κάντε κλικ στο κουμπί «Try» για να κάνετε δοκιμή, όπως φαίνεται στην παραπάνω εικόνα, και εδώ έχουμε λάβει το εξής αποτέλεσμα:

```json
{
  "sim": 99.76,
  "result": "Success",
  "description": "Επιτυχία",
  "name": "Όνομα ταυτότητας",
  "sex": "Φύλο ταυτότητας",
  "nation": "Εθνότητα ταυτότητας",
  "birth": "Ημερομηνία γέννησης ταυτότητας",
  "address": "Διεύθυνση κατοικίας ταυτότητας",
  "id_num": "Αριθμός ταυτότητας",
  "portrait": "/9j/4AAQSkZJRgABAQAAAQABAAD/2wBDAAEBAQEBAQEBAQEBAQEBAQEBAQEBA.....DEhE2lbPMcOtG3f/DLT/yX8if7Kxn/AD7h85wdttPifRf1e6//2Q==",
  "warnings": "",
  "quality": 0,
  "encryption": null
}
```

Το επιστρεφόμενο αποτέλεσμα περιλαμβάνει πολλά πεδία, τα οποία περιγράφονται ως εξής:

- `sim`, ο βαθμός ομοιότητας, με εύρος τιμών [0.00, 100.00]. Συνιστάται ο βαθμός ομοιότητας να είναι μεγαλύτερος ή ίσος με 70 για να θεωρείται το ίδιο άτομο, μπορείτε να προσαρμόσετε το όριο ανάλογα με την συγκεκριμένη περίπτωση (το όριο 70 έχει ποσοστό ψευδούς αποδοχής 0.1%, το όριο 80 έχει ποσοστό ψευδούς αποδοχής 0.01%).
- `result`, κωδικός σφάλματος επιχείρησης, σε περίπτωση επιτυχίας επιστρέφει Success, σε περίπτωση σφάλματος ανατρέξτε στην ενότητα κωδικών σφαλμάτων παρακάτω στην κατηγορία FailedOperation.
- `description`, το αποτέλεσμα της επαλήθευσης του ονόματος και του αριθμού ταυτότητας.
- `name`, οι πληροφορίες ονόματος στην ταυτότητα, αν δεν έχει ανέβει φωτογραφία ταυτότητας είναι κενό.
- `sex`, οι πληροφορίες φύλου στην ταυτότητα, αν δεν έχει ανέβει φωτογραφία ταυτότητας είναι κενό.
- `nation`, οι πληροφορίες εθνότητας στην ταυτότητα, αν δεν έχει ανέβει φωτογραφία ταυτότητας είναι κενό.
- `birth`, οι πληροφορίες ημερομηνίας γέννησης στην ταυτότητα, αν δεν έχει ανέβει φωτογραφία ταυτότητας είναι κενό.
- `address`, οι πληροφορίες διεύθυνσης κατοικίας στην ταυτότητα, αν δεν έχει ανέβει φωτογραφία ταυτότητας είναι κενό.
- `id_num`, οι πληροφορίες αριθμού ταυτότητας στην ταυτότητα, αν δεν έχει ανέβει φωτογραφία ταυτότητας είναι κενό.
- `portrait`, η base64 κωδικοποίηση της φωτογραφίας της ταυτότητας, αν η αποκοπή της εικόνας αποτύχει, θα χρησιμοποιηθεί η ολόκληρη φωτογραφία της ταυτότητας για σύγκριση και θα επιστραφεί κενό.
- `warnings`, πληροφορίες προειδοποίησης, όταν έχει ρυθμιστεί προειδοποίηση στο Config, η σύγκριση προσώπου θα σταματήσει, το Result θα επιστρέψει σφάλμα (FailedOperation.OcrWarningOccurred) και θα έχει αυτή την προειδοποίηση.
- `quality`, βαθμολογία ποιότητας εικόνας, όταν έχει ρυθμιστεί προειδοποίηση θολότητας στο Config, αυτή η παράμετρος έχει νόημα, εύρος τιμών (0-100), το προεπιλεγμένο όριο είναι 50, αν είναι κάτω από 50 θα ενεργοποιηθεί η προειδοποίηση θολότητας.
- `encryption`, πληροφορίες κρυπτογράφησης ευαίσθητων δεδομένων.

Μπορείτε να δείτε ότι οι πληροφορίες της ταυτότητας έχουν πολύ υψηλή αυθεντικότητα.

Επιπλέον, αν θέλετε να δημιουργήσετε τον αντίστοιχο κώδικα σύνδεσης, μπορείτε να τον αντιγράψετε απευθείας, για παράδειγμα, ο κώδικας CURL είναι ο εξής:

```shell
curl -X POST 'https://api.acedata.cloud/identity/idcard/check-1e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": {image_url}
}'
```

Ο κώδικας σύνδεσης Python είναι ο εξής:

```python
import requests

url = "https://api.acedata.cloud/identity/idcard/check-1e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "image_url": {image_url}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Διαχείριση Σφαλμάτων

Κατά την κλήση του API, αν προκύψει σφάλμα, το API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διαπιστευτήριο εξουσιοδότησης.
- `429 too_many_requests`: Πάρα πολλές αιτήσεις, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.
