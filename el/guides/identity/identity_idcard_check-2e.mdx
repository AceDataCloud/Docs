Αυτό το έγγραφο θα παρουσιάσει μια μέθοδο για την ταυτότητα πληροφοριών και τον έλεγχο ισχύος API, η οποία μπορεί να χρησιμοποιηθεί για την επαλήθευση της γνησιότητας και της συνέπειας του ονόματος, του αριθμού ταυτότητας και της ημερομηνίας λήξης της ταυτότητας.

## Διαδικασία αίτησης

Για να χρησιμοποιήσετε το API ταυτότητας πληροφοριών και ελέγχου ισχύος, πρώτα πηγαίνετε στο [Ace Data Cloud Console](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας, το οποίο θα κρατήσετε για μελλοντική χρήση.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης που σας προσκαλεί να εγγραφείτε και να συνδεθείτε, και μετά την ολοκλήρωση θα επιστρέψετε αυτόματα στη τρέχουσα σελίδα.

**Ένα API Token αρκεί για να καλέσετε όλες τις υπηρεσίες της πλατφόρμας, χωρίς να χρειάζεται να κάνετε ξεχωριστή αίτηση για κάθε υπηρεσία.** Η πρώτη αίτηση θα σας δώσει δωρεάν πίστωση, ώστε να μπορείτε να δοκιμάσετε δωρεάν. Όταν η πίστωση εξαντληθεί, μπορείτε να ανανεώσετε το γενικό υπόλοιπο στο [Console](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [API ταυτότητας πληροφοριών και ελέγχου ταυτότητας →](https://platform.acedata.cloud/documents/identity-idcard-check-2e)

## Βασική χρήση

Πρώτα πρέπει να κατανοήσετε τη βασική μέθοδο χρήσης, δηλαδή να εισάγετε τον σύνδεσμο εικόνας της ταυτότητας, για να αποκτήσετε το αποτέλεσμα επαλήθευσης μετά την επεξεργασία. Πρέπει πρώτα να περάσετε ένα πεδίο `name`, και στη συνέχεια μπορούμε να συμπληρώσουμε το αντίστοιχο περιεχόμενο στην οθόνη, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/llvy1l.png" width="500" className="m-auto" /></p>

Μπορείτε να δείτε ότι έχουμε ρυθμίσει τα Request Headers, που περιλαμβάνουν:

- `accept`: ποια μορφή απάντησης θέλετε να λάβετε, εδώ συμπληρώνεται ως `application/json`, δηλαδή σε μορφή JSON.
- `authorization`: το κλειδί για την κλήση του API, το οποίο μπορείτε να επιλέξετε απευθείας μετά την αίτηση.

Επιπλέον, έχουμε ρυθμίσει το Request Body, που περιλαμβάνει:

- `name`: όνομα.
- `id_card`: αριθμός ταυτότητας.
- `image_url`: σύνδεσμος εικόνας προσώπου που χρειάζεται επεξεργασία.
- `validity_end`: ημερομηνία λήξης της ταυτότητας, μορφή: YYYYMMDD, για μακροχρόνια χρήση χρησιμοποιήστε "00000000";
- `validity_begin`: ημερομηνία έναρξης ισχύος της ταυτότητας, μορφή: YYYYMMDD.
- `encryption`: προαιρετικό, παράμετρος κρυπτογράφησης ευαίσθητων πεδίων (εάν χρειάζεται να στείλετε κρυπτογραφημένα δεδομένα).

Αφού επιλέξετε, μπορείτε να δείτε ότι έχει παραχθεί ο αντίστοιχος κώδικας στα δεξιά, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/l77q0u.png" width="500" className="m-auto" /></p>

Κάντε κλικ στο κουμπί «Try» για να κάνετε δοκιμή, όπως φαίνεται στην παραπάνω εικόνα, και εδώ έχουμε λάβει το εξής αποτέλεσμα:

```json
{
  "result": "0",
  "description": "Συμφωνία"
}
```

Η επιστρεφόμενη απάντηση περιλαμβάνει πολλά πεδία, που περιγράφονται ως εξής:

- `result`, κωδικός αποτελέσματος πιστοποίησης, οι χρεώσεις είναι οι εξής.
    - Κωδικοί χρέωσης:
        - 0: Το όνομα και ο αριθμός ταυτότητας συμφωνούν
        - -1: Το όνομα και ο αριθμός ταυτότητας δεν συμφωνούν
    - Κωδικοί χωρίς χρέωση:
        - -2: Μη έγκυρος αριθμός ταυτότητας (μήκος, ψηφίο ελέγχου κ.λπ. δεν είναι σωστά)
        - -3: Μη έγκυρο όνομα (μήκος, μορφή κ.λπ. δεν είναι σωστά)
        - -4: Σφάλμα υπηρεσίας βάσης δεδομένων εγγράφων
        - -5: Δεν υπάρχει καταγραφή αυτού του αριθμού ταυτότητας στη βάση δεδομένων
        - -6: Το σύστημα αυθεντικής σύγκρισης αναβαθμίζεται, παρακαλώ δοκιμάστε ξανά αργότερα
        - -7: Ο αριθμός πιστοποίησης υπερβαίνει το ημερήσιο όριο.
- `description`, το αποτέλεσμα της επαλήθευσης του ονόματος και του αριθμού ταυτότητας.

Μπορείτε να δείτε ότι το όνομα, ο αριθμός ταυτότητας και η ημερομηνία λήξης της ταυτότητας έχουν γνησιότητα και συνέπεια.

Επιπλέον, εάν θέλετε να δημιουργήσετε τον αντίστοιχο κώδικα σύνδεσης, μπορείτε να τον αντιγράψετε απευθείας, όπως ο κώδικας CURL παρακάτω:

```shell
curl -X POST 'https://api.acedata.cloud/identity/idcard/check-2e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "id_card": "***",
  "validity_begin": "***",
  "validity_end": "***"
}'
```

Ο κώδικας σύνδεσης Python είναι ως εξής:

```python
import requests

url = "https://api.acedata.cloud/identity/idcard/check-2e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "name": "***",
    "id_card": "***",
    "validity_begin": "***",
    "validity_end": "***"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Διαχείριση σφαλμάτων

Κατά την κλήση του API, εάν προκύψει σφάλμα, το API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διαπιστευτήριο εξουσιοδότησης.
- `429 too_many_requests`: Πάρα πολλές αιτήσεις, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.

### Παράδειγμα σφάλματος απόκρισης

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
