Αυτό το έγγραφο θα παρουσιάσει μια μέθοδο σύνδεσης API επαλήθευσης τριών στοιχείων κάρτας τράπεζας, η οποία μπορεί να χρησιμοποιηθεί για την επαλήθευση της γνησιότητας και της συνέπειας των στοιχείων αριθμού κάρτας τράπεζας, ονόματος και αριθμού ταυτότητας.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το API επαλήθευσης τριών στοιχείων κάρτας τράπεζας, πρώτα πηγαίνετε στο [Ace Data Cloud Console](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας, το οποίο θα κρατήσετε για μελλοντική χρήση.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης που σας προσκαλεί να εγγραφείτε και να συνδεθείτε, και μετά θα επιστρέψετε αυτόματα στη τρέχουσα σελίδα.

**Ένα API Token αρκεί για να καλέσετε όλες τις υπηρεσίες της πλατφόρμας, χωρίς να χρειάζεται να ζητήσετε ξεχωριστά για κάθε υπηρεσία.** Η πρώτη αίτηση θα σας δώσει δωρεάν πιστώσεις για να δοκιμάσετε δωρεάν. Όταν οι πιστώσεις σας εξαντληθούν, μπορείτε να ανανεώσετε το γενικό σας υπόλοιπο στο [Console](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [API Επαλήθευσης Τριών Στοιχείων Κάρτας Τράπεζας →](https://platform.acedata.cloud/documents/identity-bankcard-check-3e)

## Βασική Χρήση

Πρώτα πρέπει να κατανοήσετε τη βασική μέθοδο χρήσης, δηλαδή να εισάγετε τον αριθμό της κάρτας τράπεζας, ώστε να λάβετε την επεξεργασμένη εικόνα αποτελέσματος. Πρέπει πρώτα να μεταβιβάσετε ένα πεδίο `bank_card`. Στη συνέχεια, μπορούμε να συμπληρώσουμε τα αντίστοιχα περιεχόμενα στην διεπαφή, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/3kh6i2.png" width="500" className="m-auto" /></p>

Μπορείτε να δείτε ότι έχουμε ρυθμίσει τα Request Headers, που περιλαμβάνουν:

- `accept`: ποια μορφή απάντησης θέλετε να λάβετε, εδώ συμπληρώνεται ως `application/json`, δηλαδή σε μορφή JSON.
- `authorization`: το κλειδί για την κλήση του API, το οποίο μπορείτε να επιλέξετε απευθείας μετά την αίτηση.

Επιπλέον, έχουμε ρυθμίσει το Request Body, που περιλαμβάνει:

- `bank_card`: οι πληροφορίες αριθμού κάρτας τράπεζας που χρειάζονται επεξεργασία, είναι υποχρεωτική παράμετρος.
- `id_card`: αριθμός ταυτότητας, είναι υποχρεωτική παράμετρος.
- `name`: το όνομα του χρήστη, είναι υποχρεωτική παράμετρος.
- `cert_type`: τύπος ταυτότητας, πρέπει να είναι συμβατός με την ταυτότητα, αλλιώς δεν μπορεί να επαληθευτεί.
- `encryption`: προαιρετικό, παράμετρος κρυπτογράφησης ευαίσθητων πεδίων (εάν χρειάζεται να στείλετε κρυπτογραφημένα δεδομένα).

Αφού επιλέξετε, μπορείτε να δείτε ότι έχει παραχθεί ο αντίστοιχος κώδικας στα δεξιά, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/cpvguu.png" width="500" className="m-auto" /></p>

Κάντε κλικ στο κουμπί «Try» για να κάνετε δοκιμή, όπως φαίνεται στην παραπάνω εικόνα, και εδώ έχουμε λάβει το εξής αποτέλεσμα:

```json
{
  "result": "0",
  "description": "Πιστοποίηση επιτυχής"
}
```

Η επιστρεφόμενη απάντηση περιλαμβάνει πολλά πεδία, τα οποία περιγράφονται ως εξής:

- `result`, κωδικός αποτελέσματος πιστοποίησης, οι χρεώσεις είναι οι εξής.
    - Κωδικοί χρέωσης:
        - 0: Πιστοποίηση επιτυχής
        - -1: Πιστοποίηση αποτυχημένη
        - -4: Λάθος πληροφορίες κατόχου κάρτας
        - -5: Δεν έχει ενεργοποιηθεί η πληρωμή χωρίς κάρτα
        - -6: Αυτή η κάρτα έχει κατασχεθεί
        - -7: Μη έγκυρος αριθμός κάρτας
        - -8: Αυτή η κάρτα δεν έχει αντίστοιχη τράπεζα εκδότρια
        - -9: Αυτή η κάρτα δεν έχει αρχικοποιηθεί ή είναι ανενεργή
        - -10: Κάρτα απάτης, κατάσχεση κάρτας
        - -11: Αυτή η κάρτα έχει δηλωθεί ως χαμένη
        - -12: Αυτή η κάρτα έχει λήξει
        - -13: Περιορισμένη κάρτα
        - -14: Υπερβολικές αποτυχημένες προσπάθειες κωδικού
        - -15: Η τράπεζα εκδότρια δεν υποστηρίζει αυτή τη συναλλαγή
    - Κωδικοί χωρίς χρέωση:
        - -2: Αποτυχία επαλήθευσης ονόματος
        - -3: Λάθος αριθμός κάρτας τράπεζας
        - -16: Υπηρεσία επαλήθευσης απασχολημένη
        - -17: Υπερβολικές προσπάθειες επαλήθευσης, παρακαλώ δοκιμάστε ξανά την επόμενη μέρα
- `description`, περιγραφή αποτελέσματος επιχείρησης.

Μπορείτε να δείτε ότι η γνησιότητα και η συνέπεια των στοιχείων αριθμού κάρτας τράπεζας, ονόματος και αριθμού ταυτότητας έχουν επιβεβαιωθεί.

Επιπλέον, εάν θέλετε να δημιουργήσετε τον αντίστοιχο κώδικα σύνδεσης, μπορείτε να τον αντιγράψετε απευθείας, όπως ο κώδικας CURL παρακάτω:

```shell
curl -X POST 'https://api.acedata.cloud/identity/bankcard/check-3e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "bank_card": "***",
  "id_card": "***"
}'
```

Ο κώδικας σύνδεσης Python είναι ως εξής:

```python
import requests

url = "https://api.acedata.cloud/identity/bankcard/check-3e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "name": "***",
    "bank_card": "***",
    "id_card": "***"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Διαχείριση Σφαλμάτων

Κατά την κλήση του API, εάν προκύψουν σφάλματα, το API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές token εξουσιοδότησης.
- `429 too_many_requests`: Υπερβολικές αιτήσεις, έχετε ξεπεράσει το όριο ρυθμού.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.

### Παράδειγμα Απόκρισης Σφάλματος

```json
{

    "message": "fetch failed"
  },

}
```
