Αυτό το έγγραφο θα παρουσιάσει μια μέθοδο για την επιβεβαίωση των στοιχείων της τραπεζικής κάρτας μέσω του API, το οποίο μπορεί να χρησιμοποιηθεί για την επαλήθευση της γνησιότητας και της συνέπειας των στοιχείων αριθμού τραπεζικής κάρτας, ονόματος και αριθμού ταυτότητας.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το API, πρέπει πρώτα να επισκεφθείτε τη σελίδα [API Τριπλής Επιβεβαίωσης Στοιχείων Τραπεζικής Κάρτας](https://platform.acedata.cloud/documents/eb9c6677-68db-4549-a207-41f8a1084634) και να ζητήσετε την αντίστοιχη υπηρεσία. Αφού εισέλθετε στη σελίδα, κάντε κλικ στο κουμπί «Acquire», όπως φαίνεται στην εικόνα:

![](https://cdn.acedata.cloud/q6ytrc.png)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης για να εγγραφείτε και να συνδεθείτε. Μετά την εγγραφή και σύνδεση, θα επιστρέψετε αυτόματα στη σελίδα.

Κατά την πρώτη αίτηση, θα υπάρχει δωρεάν πίστωση που μπορείτε να χρησιμοποιήσετε δωρεάν για το API.

## Βασική Χρήση

Αρχικά, πρέπει να κατανοήσετε τη βασική μέθοδο χρήσης, δηλαδή να εισάγετε τον αριθμό της τραπεζικής κάρτας, ώστε να λάβετε την επεξεργασμένη εικόνα αποτελέσματος. Πρέπει απλώς να μεταφέρετε ένα πεδίο `bank_card`. Στη συνέχεια, μπορείτε να συμπληρώσετε τα αντίστοιχα περιεχόμενα στην οθόνη, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/3kh6i2.png" width="500" className="m-auto" /></p>

Μπορείτε να δείτε ότι έχουμε ρυθμίσει τα Request Headers, που περιλαμβάνουν:

- `accept`: ποια μορφή απάντησης θέλετε να λάβετε, εδώ συμπληρώνεται ως `application/json`, δηλαδή σε μορφή JSON.
- `authorization`: το κλειδί για την κλήση του API, το οποίο μπορείτε να επιλέξετε απευθείας από την αναπτυσσόμενη λίστα μετά την αίτηση.

Επιπλέον, έχουμε ρυθμίσει το Request Body, που περιλαμβάνει:

- `bank_card`: τον αριθμό της τραπεζικής κάρτας που χρειάζεται επεξεργασία, είναι υποχρεωτική παράμετρος.
- `id_card`: τον αριθμό ταυτότητας, είναι υποχρεωτική παράμετρος.
- `name`: το όνομα του χρήστη, είναι υποχρεωτική παράμετρος.
- `cert_type`: τον τύπο ταυτότητας, πρέπει να είναι συμβατός με την ταυτότητα, αλλιώς δεν μπορεί να επαληθευτεί.
- `encryption`: προαιρετικό, παράμετρος κρυπτογράφησης ευαίσθητων πεδίων (εάν χρειάζεται να στείλετε κρυπτογραφημένα δεδομένα).

Αφού επιλέξετε, μπορείτε να δείτε ότι έχει παραχθεί ο αντίστοιχος κώδικας στα δεξιά, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/cpvguu.png" width="500" className="m-auto" /></p>

Κάντε κλικ στο κουμπί «Try» για να κάνετε δοκιμή, όπως φαίνεται στην παραπάνω εικόνα, και εδώ έχουμε λάβει το εξής αποτέλεσμα:

```json
{
  "result": "0",
  "description": "Πιστοποίηση επιτυχής"
}
```

Η επιστρεφόμενη απάντηση περιλαμβάνει πολλά πεδία, τα οποία περιγράφονται ως εξής:

- `result`, κωδικός αποτελέσματος πιστοποίησης, οι χρεώσεις είναι οι εξής.
  - Κωδικοί χρέωσης:
    - 0: Πιστοποίηση επιτυχής
    - -1: Πιστοποίηση αποτυχημένη
    - -4: Λάθος στοιχεία κατόχου
    - -5: Δεν έχει ενεργοποιηθεί η πληρωμή χωρίς κάρτα
    - -6: Αυτή η κάρτα έχει κατασχεθεί
    - -7: Μη έγκυρος αριθμός κάρτας
    - -8: Αυτή η κάρτα δεν έχει αντίστοιχη τράπεζα εκδότρια
    - -9: Αυτή η κάρτα δεν έχει αρχικοποιηθεί ή είναι ανενεργή
    - -10: Κάρτα απάτης, κατάσχεση κάρτας
    - -11: Αυτή η κάρτα έχει δηλωθεί ως χαμένη
    - -12: Αυτή η κάρτα έχει λήξει
    - -13: Περιορισμένη κάρτα
    - -14: Υπερβολικές αποτυχημένες προσπάθειες κωδικού
    - -15: Η τράπεζα εκδότρια δεν υποστηρίζει αυτή τη συναλλαγή
  - Κωδικοί χωρίς χρέωση:
    - -2: Αποτυχία επαλήθευσης ονόματος
    - -3: Λάθος αριθμός τραπεζικής κάρτας
    - -16: Υπηρεσία επαλήθευσης απασχολημένη
    - -17: Υπερβολικές προσπάθειες επαλήθευσης, παρακαλώ δοκιμάστε ξανά την επόμενη μέρα
- `description`, περιγραφή αποτελέσματος επιχείρησης.

Μπορείτε να δείτε ότι η γνησιότητα και η συνέπεια των στοιχείων αριθμού τραπεζικής κάρτας, ονόματος και αριθμού ταυτότητας έχουν επιβεβαιωθεί.

Επιπλέον, εάν θέλετε να δημιουργήσετε τον αντίστοιχο κώδικα σύνδεσης, μπορείτε να τον αντιγράψετε απευθείας, όπως ο κώδικας CURL παρακάτω:

```shell
curl -X POST 'https://api.acedata.cloud/identity/bankcard/check-3e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "bank_card": "***",
  "id_card": "***"
}'
```

Ο κώδικας σύνδεσης Python είναι ο εξής:

```python
import requests

url = "https://api.acedata.cloud/identity/bankcard/check-3e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "name": "***",
    "bank_card": "***",
    "id_card": "***"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Διαχείριση Σφαλμάτων

Κατά την κλήση του API, εάν προκύψουν σφάλματα, το API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διαπιστευτήριο εξουσιοδότησης.
- `429 too_many_requests`: Υπερβολικές αιτήσεις, έχετε ξεπεράσει το όριο ρυθμού.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.

```json
  },

}
```
