Αυτό το έγγραφο θα παρουσιάσει μια μέθοδο για τη διευκρίνιση της API επαλήθευσης δύο στοιχείων τηλεφώνου, η οποία μπορεί να χρησιμοποιηθεί για την επαλήθευση της γνησιότητας και της συνέπειας του αριθμού τηλεφώνου και του ονόματος.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε την API, πρέπει πρώτα να επισκεφθείτε τη σελίδα [API Επαλήθευσης Δύο Στοιχείων Τηλεφώνου](https://platform.acedata.cloud/documents/1f39c948-6d9b-48f5-83fb-0719da4f6ab0) και να ζητήσετε την αντίστοιχη υπηρεσία. Αφού εισέλθετε στη σελίδα, κάντε κλικ στο κουμπί «Acquire», όπως φαίνεται στην εικόνα:

![](https://cdn.acedata.cloud/q6ytrc.png)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης για να εγγραφείτε και να συνδεθείτε. Μετά την εγγραφή και τη σύνδεση, θα επιστρέψετε αυτόματα στη σελίδα.

Κατά την πρώτη αίτηση, θα υπάρχει δωρεάν πίστωση που μπορείτε να χρησιμοποιήσετε δωρεάν για αυτήν την API.

## Βασική Χρήση

Αρχικά, πρέπει να κατανοήσετε τη βασική μέθοδο χρήσης, δηλαδή να εισάγετε τον αριθμό τηλεφώνου για να λάβετε το επεξεργασμένο αποτέλεσμα. Πρέπει πρώτα να περάσετε ένα πεδίο `mobile`. Στη συνέχεια, μπορείτε να συμπληρώσετε τα αντίστοιχα περιεχόμενα στην διεπαφή, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/v6k96j.png" width="500" className="m-auto" /></p>

Μπορείτε να δείτε ότι έχουμε ρυθμίσει τα Request Headers, συμπεριλαμβανομένων:

- `accept`: ποια μορφή απάντησης θέλετε να λάβετε, εδώ συμπληρώνεται ως `application/json`, δηλαδή σε μορφή JSON.
- `authorization`: το κλειδί για την κλήση της API, το οποίο μπορείτε να επιλέξετε απευθείας από την αναπτυσσόμενη λίστα μετά την αίτηση.

Επιπλέον, έχουμε ρυθμίσει το Request Body, το οποίο περιλαμβάνει:

- `name`: το όνομα του χρήστη που πρέπει να επεξεργαστεί, είναι υποχρεωτική παράμετρος.
- `mobile`: ο αριθμός τηλεφώνου που πρέπει να επεξεργαστεί, είναι υποχρεωτική παράμετρος.
- `encryption`: προαιρετικό, παράμετρος κρυπτογράφησης ευαίσθητων πεδίων (εάν χρειάζεται να στείλετε κρυπτογραφημένα δεδομένα).

Αφού επιλέξετε, μπορείτε να δείτε ότι έχει παραχθεί ο αντίστοιχος κώδικας στα δεξιά, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/lq800o.png" width="500" className="m-auto" /></p>

Κάντε κλικ στο κουμπί «Try» για να κάνετε δοκιμή, όπως φαίνεται στην παραπάνω εικόνα, και εδώ έχουμε λάβει το εξής αποτέλεσμα:

```json
{
  "result": "0",
  "description": "Η επαλήθευση είναι συνεπής"
}
```

Η επιστρεφόμενη απάντηση περιλαμβάνει πολλά πεδία, τα οποία περιγράφονται ως εξής:

- `result`, κωδικός αποτελέσματος επαλήθευσης, οι χρεώσεις είναι οι εξής.
  - Κωδικοί χρέωσης:
    - 0: Η επαλήθευση είναι συνεπής
    - 1: Η επαλήθευση δεν είναι συνεπής
  - Κωδικοί χωρίς χρέωση:
    - -1: Δεν βρέθηκαν αρχεία
    - -2: Άγνωστο σφάλμα μηχανής
    - -3: Σφάλμα υπηρεσίας μηχανής
    - -4: Η επαλήθευση του ονόματος απέτυχε
    - -5: Ο αριθμός τηλεφώνου δεν είναι έγκυρος
    - -6: Ο αριθμός επαληθεύσεων έχει ξεπεράσει το ημερήσιο όριο, παρακαλώ δοκιμάστε ξανά αύριο
- `description`, περιγραφή του επιχειρηματικού αποτελέσματος.

Μπορείτε να δείτε ότι η γνησιότητα και η συνέπεια του αριθμού τηλεφώνου και του ονόματος έχουν ήδη ελεγχθεί.

Επιπλέον, εάν θέλετε να δημιουργήσετε τον αντίστοιχο κώδικα σύνδεσης, μπορείτε να τον αντιγράψετε απευθείας, όπως ο κώδικας CURL παρακάτω:

```shell
curl -X POST 'https://api.acedata.cloud/identity/phone/check-2e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "mobile": "***"
}'
```

Ο κώδικας σύνδεσης Python είναι ως εξής:

```python
import requests

url = "https://api.acedata.cloud/identity/phone/check-2e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "name": "***",
    "mobile": "***"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Διαχείριση Σφαλμάτων

Κατά την κλήση της API, εάν προκύψουν σφάλματα, η API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διαπιστευτήριο εξουσιοδότησης.
- `429 too_many_requests`: Πάρα πολλές αιτήσεις, έχετε ξεπεράσει το όριο ρυθμού.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.
