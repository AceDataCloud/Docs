Το Discord Agent Proxy είναι μια υπηρεσία **ανεξάρτητης ανάπτυξης**: αποθηκεύει τα διαπιστευτήρια του δικού σας λογαριασμού Discord, διατηρεί μια μόνιμη σύνδεση με το Discord και εκθέτει τις δυνατότητες αυτού του λογαριασμού μέσω δύο διεπαφών, **MCP** και **REST API**, επιτρέποντας σε AI ή προγράμματα να χειρίζονται το Discord εκ μέρους σας.

Το κοντέινερ **δεν περιλαμβάνει κανένα μοντέλο AI**· είναι υπεύθυνο μόνο για την εκτέλεση — οι κλήσεις πραγματοποιούνται από τον AI client σας (Claude, Cursor κ.λπ.) ή από το δικό σας πρόγραμμα.

```
AI client  ──MCP /mcp──┐
                       ├─→ Discord Agent Proxy ──→ Discord
Το πρόγραμμά σας ──REST /api───┘      （Αποθηκεύει τα διαπιστευτήρια του λογαριασμού σας）
```

## ⚠️ Απαραίτητη ανάγνωση πριν από τη χρήση

Η αυτοματοποίηση ενός **προσωπικού λογαριασμού** (self-bot) με προγράμματα παραβιάζει τους Όρους Παροχής Υπηρεσιών του Discord και υπάρχει κίνδυνος αποκλεισμού του λογαριασμού. Αυτή είναι η εγγενής προϋπόθεση της υπηρεσίας: παρέχετε τα διαπιστευτήρια του δικού σας λογαριασμού και αναλαμβάνετε τον κίνδυνο.

**Συνιστάται θερμά να χρησιμοποιήσετε έναν αποκλειστικό δευτερεύοντα λογαριασμό και όχι τον κύριο λογαριασμό σας.**

## Ανάπτυξη της υπηρεσίας

Μεταβείτε στο [Κονσόλα → Εφαρμογές](https://platform.acedata.cloud/console/applications), βρείτε το Discord Agent Proxy και δημιουργήστε μια εφαρμογή. Μετά τη δημιουργία, ενεργοποιήστε πρώτα τη συνδρομή και, στη συνέχεια, μεταβείτε στη σελίδα διαμόρφωσης για να εισαγάγετε τα διαπιστευτήρια του λογαριασμού σας Discord και να κάνετε την ανάπτυξη. Οι πόροι της παρουσίας διαμορφώνονται αυτόματα από την πλατφόρμα και δεν χρειάζεται να επιλέξετε προδιαγραφές.

Μετά την υποβολή της ανάπτυξης, θα μεταβείτε στη σελίδα διαχείρισης της εφαρμογής, με την ίδια διάταξη «Επισκόπηση / Αρχεία καταγραφής / Τεκμηρίωση» που χρησιμοποιείται για την ανάπτυξη Telegram και WeChat. Η «Επισκόπηση» εμφανίζει την κατάσταση της παρουσίας και της συνδρομής και επιβεβαιώνει μέσω ερωτήματος λογαριασμού αν το Discord έχει συνδεθεί· η κανονική λειτουργία του κοντέινερ δεν σημαίνει απαραίτητα ότι ο λογαριασμός έχει συνδεθεί.

Η κάρτα λογαριασμού Discord στην «Επισκόπηση» παρέχει δύο στοιχεία σύνδεσης:

| Στοιχείο       | Παράδειγμα                                                       | Χρήση         |
| -------- | -------------------------------------------------------- | ---------- |
| Διεύθυνση σύνδεσης MCP | `https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/mcp` | Ρύθμιση στον AI client |
| Διακριτικό πρόσβασης     | `V0p7kAWY...`                                            | Για αυθεντικοποίηση, δείτε παρακάτω     |

### Προβολή και δοκιμή διεπαφών στην κονσόλα

Ανοίξτε την καρτέλα «Τεκμηρίωση» αυτής της εφαρμογής για να δείτε τις παραμέτρους αιτήματος, τη δομή απόκρισης και παραδείγματα σε Shell, Python, JavaScript και άλλες γλώσσες και για τις 14 λειτουργίες REST. Η διεύθυνση της παρουσίας και το διακριτικό πρόσβασης συμπληρώνονται αυτόματα· το διακριτικό είναι κρυφό από προεπιλογή.

Επιλέξτε `GET /api/whoami` και κάντε κλικ στο «Δοκιμή» για να επιβεβαιώσετε τον λογαριασμό που έχει συνδέσει ο proxy. Ενέργειες όπως η αποστολή, η επεξεργασία ή η διαγραφή μηνυμάτων εφαρμόζονται στον πραγματικό λογαριασμό Discord· επιβεβαιώστε το περιεχόμενο του αιτήματος πριν από τη δοκιμή.

Η «Λήψη OpenAPI (JSON)» επιτρέπει την εξαγωγή του πλήρους ορισμού της διεπαφής. Το αρχείο περιλαμβάνει τη διεύθυνση της παρουσίας, αλλά δεν περιλαμβάνει το διακριτικό πρόσβασης. Αν χρειάζεται να αλλάξετε τα διαπιστευτήρια του λογαριασμού Discord, επιλέξτε «Επαν-ανάπτυξη» στην «Επισκόπηση», συμπληρώστε τα νέα διαπιστευτήρια και υποβάλετε.

### Πώς να αποκτήσετε διαπιστευτήρια λογαριασμού Discord

1. Συνδεθείτε στο Discord σε πρόγραμμα περιήγησης υπολογιστή ([discord.com/app](https://discord.com/app))
2. Πατήστε `F12` για να ανοίξετε τα εργαλεία προγραμματιστή και μεταβείτε στον πίνακα **Network（Δίκτυο）**
3. Κάντε κλικ σε οποιοδήποτε κανάλι στο Discord και παρατηρήστε τη λίστα αιτημάτων
4. Ανοίξτε οποιοδήποτε αίτημα προς το `discord.com/api` και βρείτε το πεδίο `authorization` στα **Request Headers（Κεφαλίδες αιτήματος）**
5. Αντιγράψτε την τιμή του

Αυτή η συμβολοσειρά διαπιστευτηρίων ισοδυναμεί με την κατάσταση σύνδεσης του λογαριασμού σας· **μην τη μοιραστείτε με κανέναν**. Αν διαρρεύσει, η αλλαγή κωδικού πρόσβασης στο Discord θα την καταστήσει αμέσως άκυρη.

## Μέθοδος αυθεντικοποίησης

Εκτός από τα `/health` και `/readyz`, όλες οι διεπαφές απαιτούν να συμπεριλάβετε το διακριτικό πρόσβασης στις **κεφαλίδες αιτήματος**:

```
Authorization: Bearer <το διακριτικό πρόσβασής σας>
```

> **Σημείωση: Αυτή η υπηρεσία δέχεται αυθεντικοποίηση μόνο μέσω κεφαλίδων αιτήματος και δεν υποστηρίζει την προσθήκη διακριτικού στο τέλος της διεύθυνσης URL με τρόπο όπως `?token=xxx`.** Το άνοιγμα της διεύθυνσης μιας διεπαφής απευθείας στο πρόγραμμα περιήγησης θα επιστρέψει `401 unauthorized`, κάτι που είναι φυσιολογικό και δεν σημαίνει ότι η ανάπτυξη απέτυχε. Για να επιβεβαιώσετε αν η διεργασία είναι ενεργή, επισκεφθείτε το `/health`· για να επιβεβαιώσετε αν η σύνδεση Discord μπορεί να επεξεργαστεί αιτήματα, επισκεφθείτε το `/readyz`. Και οι δύο αυτοί έλεγχοι δεν απαιτούν αυθεντικοποίηση. Όταν το διακριτικό πρόσβασης του proxy δεν έχει διαμορφωθεί, οι προστατευμένες διεπαφές επιστρέφουν `503` και δεν ανοίγουν ανώνυμα.

## Έλεγχος κατάστασης υπηρεσίας

```bash
curl https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/health
curl https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/readyz
```

Το `/health` υποδεικνύει μόνο ότι η διεργασία HTTP είναι ενεργή:

```json
{ "status": "ok" }
```

Το `/readyz` υποδεικνύει αν το Discord Gateway είναι διαθέσιμο. Όταν η σύνδεση είναι κανονική, επιστρέφει HTTP 200:

```json
{ "status": "ready", "gateway_ready": true }
```

Κατά τη σύνδεση, όταν τα διαπιστευτήρια είναι άκυρα ή όταν η σύνδεση διακοπεί, ο άμεσος έλεγχος του Kubernetes προς το Pod επιστρέφει HTTP 503 και το παρασκήνιο της παρουσίας επαναλαμβάνει αυτόματα την προσπάθεια. Σε αυτήν την περίπτωση, το Pod αφαιρείται προσωρινά από το δημόσιο Service, επομένως δεν εγγυάται ότι μπορείτε να διαβάσετε αυτό το διαγνωστικό JSON μέσω του ονόματος τομέα της παρουσίας· ελέγξτε την κατάσταση Deployment στην κονσόλα και καλέστε ξανά MCP / REST αφού αποκατασταθεί το Ready.

## Χρήση σε AI client (MCP)

Χρησιμοποιώντας το Claude Code ως παράδειγμα:

```bash
claude mcp add --transport http discord \
  https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/mcp \
  --header "Authorization: Bearer <το διακριτικό πρόσβασής σας>"
```

Για clients όπως το Cursor που υποστηρίζουν στατικές κεφαλίδες αιτήματος, διαμορφώστε τη διεύθυνση Streamable HTTP σύμφωνα με την τρέχουσα τεκμηρίωσή τους. Clients που δέχονται την ακόλουθη δομή μπορούν να χρησιμοποιήσουν:

```json
{
  "mcpServers": {
    "discord": {
      "type": "http",
      "url": "https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/mcp",
      "headers": {
        "Authorization": "Bearer <το διακριτικό πρόσβασής σας>"
      }
    }
  }
}
```

Αυτή δεν είναι μια καθολική μορφή διαμόρφωσης για όλους τους MCP clients. Οι απομακρυσμένοι σύνδεσμοι του Claude Desktop / Claude.ai δημιουργούνται από το cloud και δεν διαβάζουν καμία κεφαλίδα αιτήματος HTTP από το τοπικό `claude_desktop_config.json`· προς το παρόν, αν χρειάζεστε στατική κεφαλίδα Bearer, χρησιμοποιήστε το Claude Code ή έναν client που υποστηρίζει ρητά αυτή τη δυνατότητα.

Αφού ολοκληρωθεί η διαμόρφωση, μπορείτε να δίνετε απευθείας εντολές σε AI με φυσική γλώσσα για τον χειρισμό του Discord, για παράδειγμα:

> Δες αν έχω νέα μηνύματα στο κανάλι «Συζήτηση έργου» και, αν κάποιος ρωτήσει για την ημερομηνία κυκλοφορίας, βοήθησέ με να απαντήσω ότι είναι αυτή την Παρασκευή.

## Χρήση σε πρόγραμμα (REST API)

Όλες οι διεπαφές REST είναι προσαρτημένες κάτω από το `/api`, το σώμα επιστροφής είναι ενιαία `{"data": ...}`, και σε περίπτωση σφάλματος είναι `{"error": "..."}`.

### Προβολή τρέχοντος λογαριασμού

```bash
curl https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/api/whoami \
  -H "Authorization: Bearer <το διακριτικό πρόσβασής σας>"
```

### Αποστολή μηνύματος

```bash
curl -X POST https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/api/messages \
  -H "Authorization: Bearer <το διακριτικό πρόσβασής σας>" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: <το μοναδικό ID λειτουργίας για αυτήν την αποστολή>" \
  -d '{"channel_id": "1234567890", "content": "Γεια"}'
```

Όταν επαναλαμβάνετε την ίδια αποστολή, επαναχρησιμοποιήστε το ίδιο `Idempotency-Key`, και η διεργασία θα επιστρέψει το πρώτο αποτέλεσμα χωρίς να στείλει ξανά. Η επανεκκίνηση της παρουσίας θα εκκαθαρίσει έως και 5.000 εγγραφές αποδιπλοποίησης στη μνήμη, επομένως ο καλών εξακολουθεί να πρέπει να παρακολουθεί μόνος του τη μακροπρόθεσμη κατάσταση παράδοσης.

Η προαιρετική παράμετρος `reply_to` χρησιμοποιείται για απάντηση σε καθορισμένο μήνυμα:

```json
{ "channel_id": "1234567890", "content": "Ελήφθη", "reply_to": "9876543210" }
```

### Ανάγνωση μηνυμάτων

```bash
curl "https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/api/channels/1234567890/messages?limit=20" \
  -H "Authorization: Bearer <το διακριτικό πρόσβασής σας>"
```

### Πώς να αποκτήσετε ID καναλιού και ID χρήστη

Στον πελάτη Discord, ανοίξτε διαδοχικά **Ρυθμίσεις χρήστη → Σύνθετες ρυθμίσεις** και ενεργοποιήστε τη **Λειτουργία προγραμματιστή**. Στη συνέχεια, κάντε δεξί κλικ σε οποιοδήποτε κανάλι ή χρήστη, και στο μενού θα εμφανιστεί η επιλογή «Αντιγραφή ID».

Μπορείτε επίσης να καλέσετε απευθείας τα `GET /api/guilds` και `GET /api/guilds/{guild_id}/channels` για απαρίθμηση.

## Συχνές ερωτήσεις

**Επιστρέφεται `401 unauthorized`**

Το διακριτικό πρόσβασης είναι λανθασμένο ή μεταδόθηκε με τρόπο `?token=`. Επιβεβαιώστε ότι το διακριτικό μεταδίδεται μέσω της κεφαλίδας αιτήματος `Authorization: Bearer &lt;διακριτικό>` και ότι συμφωνεί με αυτό που εμφανίζεται στην κονσόλα.

**Επιστρέφεται `503`**

Η σύνδεση με το Discord δεν έχει ακόμη δημιουργηθεί. Επισκεφθείτε πρώτα το `/readyz` για να δείτε το `gateway_ready`. Εάν παραμένει `false` για μεγάλο χρονικό διάστημα, συνήθως τα διαπιστευτήρια του λογαριασμού έχουν καταστεί άκυρα· αποκτήστε τα ξανά και επαναναπτύξτε.

**Επιστρέφεται `403` ή `404`**

Ο ίδιος ο λογαριασμός δεν έχει τα αντίστοιχα δικαιώματα (για παράδειγμα, δεν βρίσκεται στον συγκεκριμένο διακομιστή ή δεν έχει δικαίωμα να μιλήσει στο συγκεκριμένο κανάλι), ή το ID έχει συμπληρωθεί λανθασμένα. Αυτά τα σφάλματα προέρχονται από το Discord, δεν είναι πρόβλημα της υπηρεσίας πράκτορα.

**Επιστρέφεται `429`**

Ενεργοποιήθηκε ο περιορισμός συχνότητας του Discord. Το πεδίο `retry_after` στην απόκριση παρέχει τον προτεινόμενο αριθμό δευτερολέπτων αναμονής. Μειώστε τη συχνότητα κλήσεων.

**Ο λογαριασμός αποκλείστηκε μετά την αποστολή μηνυμάτων**

Όπως αναφέρθηκε προηγουμένως, οι αυτοματοποιημένες λειτουργίες σε προσωπικούς λογαριασμούς παραβιάζουν τους Όρους Παροχής Υπηρεσιών του Discord. Χρησιμοποιήστε ειδικό δευτερεύοντα λογαριασμό και ελέγξτε τη συχνότητα λειτουργιών, αποφεύγοντας ευαίσθητες συμπεριφορές όπως η μαζική αποστολή.

## Εύρος επαλήθευσης

Το smoke παραγωγής της 1ης Αυγούστου 2026 επαλήθευσε, με ειδικό λογαριασμό, λογαριασμούς, διακομιστές, κανάλια, μέλη, ανάγνωση μηνυμάτων, αναζήτηση, αποστολή, επεξεργασία, αντιδράσεις και διαγραφή. Οι αυτοματοποιημένες δοκιμές καλύπτουν έλεγχο ταυτότητας, επικύρωση παραμέτρων, αντιστοίχιση σφαλμάτων και υπογραφές της τρέχουσας βιβλιοθήκης εξαρτήσεων· μετά από αλλαγές σε worker ή chart, το smoke πρέπει να εκτελείται ξανά και η ιστορική επαλήθευση δεν μπορεί να θεωρείται απόδειξη συνεχούς διαθεσιμότητας.
