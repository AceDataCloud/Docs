Αυτό το άρθρο παρουσιάζει την ενσωμάτωση και χρήση του API ερωτήματος εργασιών MiniMax H3. Αυτή η διεπαφή χρησιμοποιείται για την αναζήτηση, μαζική καταχώριση ή διαγραφή ασύγχρονων εργασιών που δημιουργούνται από το [API δημιουργίας βίντεο MiniMax H3](https://platform.acedata.cloud/documents/minimax-videos-integration).

## Διαδικασία αίτησης

Για να χρησιμοποιήσετε το API ερωτήματος εργασιών MiniMax H3, μεταβείτε πρώτα στην [κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας και κρατήστε το για μελλοντική χρήση.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε ακόμη συνδεθεί ή εγγραφεί, θα ανακατευθυνθείτε αυτόματα στη σελίδα σύνδεσης για να εγγραφείτε και να συνδεθείτε, και μετά την ολοκλήρωση θα επιστρέψετε αυτόματα στην τρέχουσα σελίδα.

**Ένα API Token αρκεί για την κλήση όλων των υπηρεσιών της πλατφόρμας, χωρίς να χρειάζεται ξεχωριστή αίτηση για κάθε υπηρεσία.** Η πρώτη αίτηση θα σας προσφέρει δωρεάν υπόλοιπο, ώστε να μπορείτε να το δοκιμάσετε δωρεάν· όταν το υπόλοιπο δεν επαρκεί, μπορείτε να επαναφορτίσετε το γενικό υπόλοιπο στην [κονσόλα](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [API ερωτήματος εργασιών MiniMax H3 →](https://platform.acedata.cloud/documents/minimax-tasks-integration)

Κατά την αναζήτηση μιας εργασίας θα πρέπει να χρησιμοποιείτε το ίδιο Token που δημιούργησε την εργασία. Συνιστάται να αποθηκεύσετε το Token ως μεταβλητή περιβάλλοντος και να μην το γράψετε στον πηγαίο κώδικα ή το υποβάλετε στο αποθετήριο εκδόσεων:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Επισκόπηση διεπαφής

- **Base URL**：`https://api.acedata.cloud`
- **Endpoint**：`POST /minimax/tasks`
- **Μέθοδος πιστοποίησης**：Μεταφέρετε το `authorization: Bearer {token}` στο HTTP Header
- **Κεφαλίδες αιτήματος**：
  - `accept: application/json`
  - `content-type: application/json`
- **Ερώτημα μεμονωμένης εργασίας**：`action=retrieve`, μεταβιβάστε το `id`
- **Μαζικό ερώτημα εργασιών**：`action=retrieve_batch`, μπορείτε να φιλτράρετε κατά ID εργασίας, χρονικό εύρος και συνθήκες σελιδοποίησης
- **Διαγραφή εργασίας**：`action=delete`, μεταβιβάστε το `id`
- **Σημείωση χρέωσης**：Τα ερωτήματα εργασιών είναι δωρεάν και δεν θα προκύψει επαναλαμβανόμενη χρέωση

Μετά τη δημιουργία βίντεο, πρέπει να αποθηκεύσετε το `task_id`. Συνιστάται να πραγματοποιείτε ένα ερώτημα περίπου κάθε 10 δευτερόλεπτα, έως ότου η εργασία εισέλθει σε τελική κατάσταση.

## Παράμετροι αιτήματος

| Παράμετρος               | Τύπος       | Υποχρεωτικό υπό όρους   | Εφαρμόσιμη ενέργεια                | Περιγραφή                                                   |
| ---------------- | -------- | ---- | ------------------- | ---------------------------------------------------- |
| `action`         | string   | Όχι    | Όλες                  | `retrieve`, `retrieve_batch` ή `delete`· προεπιλογή `retrieve` |
| `id`             | string   | Υποχρεωτικό υπό όρους | `retrieve`, `delete` | ID μεμονωμένης εργασίας                                              |
| `ids`            | string[] | Όχι    | `retrieve_batch`    | Επιστρέφει μόνο τα καθορισμένα ID εργασιών· όταν παραλείπεται, παραθέτει εργασίες βάσει άλλων συνθηκών                              |
| `limit`          | integer  | Όχι    | `retrieve_batch`    | Ο μέγιστος αριθμός εργασιών που επιστρέφονται αυτή τη φορά                                          |
| `offset`         | integer  | Όχι    | `retrieve_batch`    | Ο αριθμός εργασιών που παραλείπονται από τη λίστα αποτελεσμάτων, για σελιδοποίηση                                   |
| `created_at_min` | number   | Όχι    | `retrieve_batch`    | Κάτω όριο χρόνου δημιουργίας, Unix timestamp, σε δευτερόλεπτα                                 |
| `created_at_max` | number   | Όχι    | `retrieve_batch`    | Άνω όριο χρόνου δημιουργίας, Unix timestamp, σε δευτερόλεπτα                                 |

Οι χρήσεις των τριών ενεργειών είναι οι εξής:

| `action`         | Χρήση                 | Απαραίτητες παράμετροι                           | Δομή απόκρισης                                  |
| ---------------- | ------------------ | ------------------------------ | ------------------------------------- |
| `retrieve`       | Ερώτημα κατάστασης και αποτελέσματος μιας εργασίας       | `id`                           | `{ "task": {...} }`                   |
| `retrieve_batch` | Μαζικό ερώτημα βάσει ID εργασίας, χρόνου και συνθηκών σελιδοποίησης | Προαιρετικά `ids`, χρονικό εύρος, `offset`, `limit` | `{ "items": [...], "total": number }` |
| `delete`         | Ακύρωση ή διαγραφή εγγραφής εργασίας βάσει της τρέχουσας κατάστασης της εργασίας  | `id`                           | `{ "id": "...", "deleted": true }`    |

## Ερώτημα μεμονωμένης εργασίας

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f5977217-ed2c-40da-adbe-93d08235618f"
  }'
```

    "model": "MiniMax-H3",
    "status": "succeeded",

    "updated_at": 1786184758,
    "content": {
      "url": "https://cdn.acedata.cloud/assets/examples/minimax/f5977217-ed2c-40da-adbe-93d08235618f-b080c998dde2.mp4"

      "total_seconds": 4,

    },

    "task_type": "generation",

## Κατάσταση εργασίας

| `status`    | Σημασία         | Διαχείριση από τον πελάτη                      |
| ----------- | ---------- | -------------------------- |
| `queued`    | Έχει εισέλθει στην ουρά, αναμένει εκτέλεση | Συνεχίστε την περιοδική αναζήτηση                       |
| `running`   | Δημιουργείται       | Συνεχίστε την περιοδική αναζήτηση                       |
| `succeeded` | Η δημιουργία ολοκληρώθηκε επιτυχώς       | Διαβάστε το `task.content.url`, σταματήστε την περιοδική αναζήτηση |
| `failed`    | Η δημιουργία απέτυχε       | Διαβάστε το `task.error`, σταματήστε την περιοδική αναζήτηση       |
| `cancelled` | Η εργασία ακυρώθηκε      | Σταματήστε την περιοδική αναζήτηση                       |

Τα `succeeded`, `failed` και `cancelled` είναι όλα τελικές καταστάσεις. Μην συνεχίζετε την περιοδική αναζήτηση μετά την είσοδο σε τελική κατάσταση.

## Πεδία απόκρισης task

| Πεδίο                        | Τύπος      | Περιγραφή                              |
| ------------------------- | ------- | ------------------------------- |
| `id`                      | string  | ID εργασίας                           |
| `model`                   | string  | Το μοντέλο που χρησιμοποιεί η εργασία, επί του παρόντος `MiniMax-H3`        |
| `status`                  | string  | Τρέχουσα κατάσταση εργασίας                          |
| `error.code`              | string  | Κωδικός σφάλματος αποτυχίας, επιστρέφεται μόνο σε περίπτωση αποτυχίας                    |
| `error.message`           | string  | Αιτία αποτυχίας, επιστρέφεται μόνο σε περίπτωση αποτυχίας                     |
| `created_at`              | integer | Χρόνος δημιουργίας, Unix timestamp, σε δευτερόλεπτα              |
| `updated_at`              | integer | Χρόνος τελευταίας ενημέρωσης κατάστασης, Unix timestamp, σε δευτερόλεπτα        |
| `content.url`             | string  | Διεύθυνση βίντεο μετά την επιτυχία                        |
| `resolution`              | string  | Ανάλυση εξόδου, `768P` ή `2K`             |
| `duration`                | integer | Διάρκεια βίντεο εξόδου, σε δευτερόλεπτα                     |
| `usage.total_seconds`     | integer | Συνολική χρεώσιμη ποσότητα, ίση με το άθροισμα των δευτερολέπτων βίντεο εισόδου και των δευτερολέπτων εξόδου           |
| `usage.input_seconds`     | integer | Χρεώσιμη ποσότητα που παράγεται από την είσοδο βίντεο αναφοράς                   |
| `usage.output_seconds`    | integer | Χρεώσιμη ποσότητα που παράγεται από το βίντεο εξόδου                     |
| `usage.input_image_count` | integer | Αριθμός εικόνων εισόδου στα στατιστικά χρέωσης                    |
| `ratio`                   | string  | Πραγματικός λόγος διαστάσεων εξόδου· όταν χρησιμοποιείται το `adaptive`, υπερισχύει το αποτέλεσμα εδώ |
| `task_type`               | string  | Για εργασίες δημιουργίας βίντεο είναι `generation`            |
| `modality`                | string  | Για εργασίες βίντεο είναι `video`                   |
## Πλήρες παράδειγμα polling σε Python

Ο παρακάτω κώδικας διαβάζει το Token από μεταβλητές περιβάλλοντος, δημιουργεί μια εργασία και έπειτα πραγματοποιεί ένα ερώτημα κάθε 10 δευτερόλεπτα:

```python
import os
import time

import requests

BASE_URL = "https://api.acedata.cloud"
HEADERS = {
    "Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_KEY']}",
    "Content-Type": "application/json",
}

create_response = requests.post(
    f"{BASE_URL}/minimax/videos",
    headers=HEADERS,
    json={
        "model": "MiniMax-H3",
        "content": [
            {
                "type": "text",
                "text": "清晨的海边，一艘白色帆船驶过平静海面，镜头缓慢横移",
            }
        ],
        "resolution": "768P",
        "duration": 4,
        "ratio": "16:9",
    },
    timeout=30,
)
create_response.raise_for_status()
task_id = create_response.json()["task_id"]

while True:
    time.sleep(10)
    query_response = requests.post(
        f"{BASE_URL}/minimax/tasks",
        headers=HEADERS,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    query_response.raise_for_status()
    task = query_response.json()["task"]
    print(f"task={task_id} status={task['status']}")

    if task["status"] == "succeeded":
        print(f"video_url={task['content']['url']}")
        break
    if task["status"] in ("failed", "cancelled"):
        raise RuntimeError(task.get("error") or task["status"])
```

Το περιβάλλον παραγωγής θα πρέπει να ορίζει συνολικό χρονικό όριο για το polling και να χρησιμοποιεί εκθετική υποχώρηση για `429` και προσωρινά `5xx`. Το χρονικό όριο δικτύου δεν ισοδυναμεί με αποτυχία δημιουργίας· μπορείτε να συνεχίσετε το ερώτημα χρησιμοποιώντας το ίδιο `task_id`.

## Μαζικό ερώτημα

Καθορίστε πολλαπλά ID εργασιών:

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve_batch",
    "ids": ["TASK_ID_1", "TASK_ID_2"],
    "offset": 0,
    "limit": 20
  }'
```

Καταγράψτε εργασίες με σελιδοποίηση κατά εύρος χρόνου:

```json
{
  "action": "retrieve_batch",
  "created_at_min": 1786000000,
  "created_at_max": 1786200000,
  "offset": 0,
  "limit": 20
}
```

Το `items` στη μαζική απόκριση χρησιμοποιεί τα ίδια πεδία task με το ερώτημα μίας εργασίας, και το `total` είναι ο συνολικός αριθμός εργασιών που αντιστοιχούν στα κριτήρια φιλτραρίσματος:

```json
{
  "items": [
    {
      "id": "TASK_ID_1",
      "model": "MiniMax-H3",
      "status": "running",
      "resolution": "2K",
      "duration": 5,
      "ratio": "adaptive",
      "task_type": "generation",
      "modality": "video"
    }
  ],
  "total": 1
}
```

Το παράθυρο ερωτήματος εργασιών αφορά τις τελευταίες 7 ημέρες. Τα `task_id` πέρα από αυτό το παράθυρο μπορεί να επιστρέψουν μη έγκυρες εργασίες· το επιχειρησιακό σύστημα θα πρέπει να αποθηκεύει το ID κατά τη δημιουργία της εργασίας και να διατηρεί έγκαιρα το URL του αποτελέσματος μετά την επιτυχία.

## Ακύρωση ή διαγραφή εργασίας

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "delete",
    "id": "YOUR_TASK_ID"
  }'
```

Η ενέργεια εξαρτάται από την τρέχουσα κατάσταση της εργασίας:

| Τρέχουσα κατάσταση | Συμπεριφορά |
| ----------- | ------------- |
| `queued`    | Ακύρωση εργασίας που δεν έχει ξεκινήσει ακόμη |
| `succeeded` | Διαγραφή εγγραφής εργασίας |
| `failed`    | Διαγραφή εγγραφής εργασίας |
| `running`   | Δεν επιτρέπεται διαγραφή ή ακύρωση, επιστρέφεται σφάλμα |
| `cancelled` | Δεν επιτρέπεται επαναλαμβανόμενη ενέργεια, επιστρέφεται σφάλμα |

Παράδειγμα επιτυχούς διαγραφής:

```json
{
  "id": "YOUR_TASK_ID",
  "deleted": true
}
```

Η διαγραφή της εγγραφής εργασίας δεν αναιρεί τη χρέωση που έχει ήδη ολοκληρωθεί, ούτε μπορεί να εγγυηθεί ότι τα αποθηκευμένα αντίγραφα του βίντεο θα διαγραφούν ταυτόχρονα.

## Αποκρίσεις αποτυχίας και αντιμετώπιση προβλημάτων

Οι αποτυχημένες εργασίες εξακολουθούν να επιστρέφουν αντικείμενο task με HTTP 200 και παρέχουν την αιτία στο `task.error`:

```json
{
  "task": {
    "id": "YOUR_TASK_ID",
    "model": "MiniMax-H3",
    "status": "failed",
    "error": {
      "code": "1026",
      "message": "video description contains sensitive content"
    },
    "task_type": "generation",
    "modality": "video"
  }
}
```

Όταν το ίδιο το API επιστρέφει `400`, θα πρέπει να ελεγχθούν το `action` και οι παράμετροι συνθηκών· το `401` υποδεικνύει μη έγκυρο Token, το `429` υποδεικνύει ότι τα ερωτήματα είναι υπερβολικά συχνά και το `500` υποδεικνύει ότι η υπηρεσία είναι προσωρινά μη διαθέσιμη. Οι εργασίες που αποτυγχάνουν κατά τη δημιουργία δεν χρεώνονται· οι επιτυχημένες εργασίες καταγράφουν τη χρήση σύμφωνα με το τελικό `usage`.
