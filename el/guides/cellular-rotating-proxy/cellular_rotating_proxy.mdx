Καθώς η αντιπαράθεση μεταξύ των ροών δεδομένων και των μεθόδων προστασίας από ροές γίνεται όλο και πιο έντονη, οι έλεγχοι κινδύνου των μεγάλων ιστοσελίδων και εφαρμογών γίνονται όλο και πιο ισχυροί, με μία από τις μεθόδους να είναι η απαγόρευση IP.

Για να επιλυθεί το πρόβλημα της απαγόρευσης IP, μία αποτελεσματική μέθοδος είναι η ρύθμιση διακομιστή μεσολάβησης (proxy). Με τη ρύθμιση διακομιστή μεσολάβησης, οι ροές μπορούν να χρησιμοποιούν τη διεύθυνση IP του διακομιστή μεσολάβησης για να αποκρύψουν τη δική τους πραγματική διεύθυνση IP, παρακάμπτοντας έτσι τους περιορισμούς της προστασίας από ροές.

Ωστόσο, η ποιότητα των διακομιστών μεσολάβησης ποικίλλει, καθώς οι δωρεάν διακομιστές μεσολάβησης που κυκλοφορούν στην αγορά είναι σχεδόν όλοι μη διαθέσιμοι ή έχουν απαγορευτεί, ενώ ορισμένοι κανονικοί πληρωμένοι διακομιστές μεσολάβησης έχουν επίσης προστεθεί στις μαύρες λίστες κινδύνου των μεγάλων ιστοσελίδων και εφαρμογών. Έτσι, οι διαθέσιμοι διακομιστές μεσολάβησης υψηλής ποιότητας για την εξαγωγή δεδομένων μειώνονται συνεχώς. Αυτή τη στιγμή, οι κυριότεροι τύποι διακομιστών μεσολάβησης υψηλής ποιότητας στην αγορά είναι οι αποκλειστικοί διακομιστές, οι διακομιστές ADSL και οι κινητοί κυψελωτοί διακομιστές.

Η υπηρεσία διακομιστή μεσολάβησης βασίζεται σε ένα σύστημα εναλλαγής διακομιστών μεσολάβησης που λειτουργεί σε κινητά δίκτυα (4G, 5G). Αυτό το έγγραφο θα περιγράψει τη διαδικασία αίτησης και χρήσης αυτής της υπηρεσίας.

## Κινητός Κυψελωτός Διακομιστής

Ο κινητός κυψελωτός διακομιστής είναι στην πραγματικότητα μια υπηρεσία διακομιστή μεσολάβησης που βασίζεται σε δεδομένα κινητής τηλεφωνίας, όπου όλες οι διευθύνσεις IP των διακομιστών μεσολάβησης είναι οι πραγματικές διευθύνσεις IP των κινητών τηλεφώνων. Αυτού του είδους οι διακομιστές μεσολάβησης χρησιμοποιούνται σχετικά σπάνια στον τομέα των ροών, επομένως η πιθανότητα απαγόρευσης είναι μικρότερη, καθιστώντας τους πολύ αποτελεσματικούς για την εξαγωγή δεδομένων από ιστοσελίδες και εφαρμογές με αυστηρούς ελέγχους κινδύνου.

Η υπηρεσία διακομιστή μεσολάβησης βασίζεται σε μια μεγάλη κλίμακα κινητών τηλεφώνων που ελέγχονται ομαδικά, με όλη την κυκλοφορία να προωθείται μέσω καθαρών δεδομένων κινητής τηλεφωνίας, υποστηρίζοντας σχεδόν όλα τα αιτήματα δεδομένων από ιστοσελίδες και εφαρμογές στην αγορά, με εξαιρετική ποιότητα διακομιστή, μειώνοντας σημαντικά την πιθανότητα κινδύνου.

Αυτός ο κινητός κυψελωτός διακομιστής είναι ένας εναλλασσόμενος διακομιστής, επομένως κατά τη χρήση του χρειάζεται να ρυθμίσετε μόνο μια σταθερή διεύθυνση διακομιστή και θύρα, οι οποίες είναι cellular.proxy.acedata.cloud και 30000. Αυτός ο διακομιστής είναι διακομιστής HTTP/HTTPS/SOCKS και μπορεί να χρησιμοποιηθεί για αιτήματα σε ιστοσελίδες που υποστηρίζουν τα πρωτόκολλα HTTP και HTTPS.

## Δοκιμή Εντολών

Αφού έχετε το όνομα χρήστη και τον κωδικό πρόσβασης του διακομιστή, ο πιο βολικός τρόπος είναι να κάνετε δοκιμή μέσω της εντολής curl. Εάν δεν έχετε εγκαταστήσει το curl, μπορείτε να ανατρέξετε στο [https://curl.se/](https://curl.se/) για να το εγκαταστήσετε.

Αν υποθέσουμε ότι το όνομα χρήστη και ο κωδικός πρόσβασης του τρέχοντος διακομιστή είναι `1f78266a:eff0896726224fa2a99fe82dd1f07562`, μπορούμε να κάνουμε δοκιμή με την παρακάτω εντολή curl:

```shell
curl -x 1f78266a:eff0896726224fa2a99fe82dd1f07562@cellular.proxy.acedata.cloud:30000 https://ipinfo.io
```

Εδώ χρησιμοποιούμε την παράμετρο `-x` του curl για να καθορίσουμε τη διεύθυνση του διακομιστή μεσολάβησης, με το πρωτόκολλο διακομιστή να είναι προεπιλεγμένα HTTP/HTTPS. Η διεύθυνση URL που ζητάμε είναι [https://ipinfo.io](https://ipinfo.io), η οποία μπορεί να επιστρέψει τη διεύθυνση IP και την τοποθεσία της διεύθυνσης IP που έκανε την αίτηση.

> Σημείωση: Ο παραπάνω κωδικός χρήστη και κωδικός πρόσβασης μπορεί να είναι άκυρος, παρακαλώ αντικαταστήστε τον με τον δικό σας κωδικό χρήστη και κωδικό πρόσβασης.

Το αποτέλεσμα της εκτέλεσης είναι το εξής:

```json
{
  "ip": "39.144.10.182",
  "city": "Shanghai",
  "region": "Shanghai",
  "country": "CN",
  "loc": "31.2222,121.4581",
  "org": "AS9808 China Mobile Communications Group Co., Ltd.",
  "postal": "200000",
  "timezone": "Asia/Shanghai",
  "readme": "https://ipinfo.io/missingauth"
}
```

Μπορείτε να δείτε ότι το πεδίο country της επιστροφής είναι CN, που αντιπροσωπεύει την Κίνα, και το org είναι China Mobile, που αντιπροσωπεύει το δίκτυο κινητής τηλεφωνίας της Κίνας, επιβεβαιώνοντας ότι είναι έξοδος από κυψελωτό διακομιστή.

Αν εκτελέσετε ξανά, μπορείτε να λάβετε διαφορετικά αποτελέσματα, καθώς κάθε αίτημα έχει τυχαία έξοδο IP.

## Σύνδεση Κώδικα

Παρακάτω παρατίθεται ένα παράδειγμα ρύθμισης του κυψελωτού εναλλασσόμενου διακομιστή με Python:

```python
import requests

proxy = 'http://{proxy_username}:{proxy_password}@cellular.proxy.acedata.cloud:30000'

proxies = {
    'http': proxy,
    'https': proxy
}

for _ in range(3):
    resp = requests.get('https://ipinfo.io', proxies=proxies)
    print(resp.text)

```

Εδώ δηλώνουμε πρώτα τη διεύθυνση URL του διακομιστή και την ορίζουμε ως μεταβλητή proxy, με το πρωτόκολλο να είναι http, ακολουθούμενη από το όνομα χρήστη και τον κωδικό πρόσβασης του εναλλασσόμενου διακομιστή (δηλαδή το όνομα χρήστη και τον κωδικό πρόσβασης που εμφανίζονται στην κονσόλα, διαχωρισμένα με άνω και κάτω τελεία), ακολουθούμενη από το σύμβολο `@`, και τέλος τη διεύθυνση και τη θύρα του διακομιστή.

Στη συνέχεια, δηλώνουμε μια μεταβλητή proxies, ρυθμίζοντας δύο ζεύγη κλειδιών, με τα ονόματα κλειδιών να είναι http και https, και οι τιμές τους να είναι και οι δύο proxy, που αντιπροσωπεύει ότι για τις ιστοσελίδες που υποστηρίζουν τα πρωτόκολλα HTTP και HTTPS, θα χρησιμοποιείται ο διακομιστής που ορίζεται από τη μεταβλητή proxy για τα αιτήματα.

Στη συνέχεια, ορίζουμε τρεις επαναλήψεις για τη δοκιμή του διακομιστή, με τη διεύθυνση URL που ζητάμε να είναι [https://ipinfo.io](https://ipinfo.io), η οποία μπορεί να επιστρέψει τη διεύθυνση IP και την τοποθεσία της διεύθυνσης IP που έκανε την αίτηση.

Φυσικά, η παραπάνω ρύθμιση του διακομιστή μεσολάβησης είναι στην πραγματικότητα μια σχετικά απλή ρύθμιση.

Στην πραγματικότητα, ο παραπάνω κώδικας είναι ισοδύναμος με την ρύθμιση ενός επιπλέον Headers - Proxy Authorization κατά την αίτηση, οπότε ο παραπάνω κώδικας μπορεί επίσης να ξαναγραφεί ως εξής:

```python
import requests
import base64

proxy_host = 'cellular.proxy.acedata.cloud'
proxy_port = '30000'
proxy_username = '{proxy_username}' # 8 χαρακτήρες όνομα χρήστη
proxy_password = '{proxy_password}' # 32 χαρακτήρες κωδικός

credentials = base64.b64encode(
    f'{proxy_username}:{proxy_password}'.encode()).decode()

proxies = {
    'http': f'http://{proxy_host}:{proxy_port}',
    'https': f'http://{proxy_host}:{proxy_port}'
}

headers = {
    'Proxy-Authorization': f'Basic {credentials}'
}

for _ in range(3):
    resp = requests.get('https://ipinfo.io',
                        proxies=proxies, headers=headers)
    print(resp.text)

```

Μπορείτε να δείτε ότι εδώ έχουμε ρυθμίσει επιπλέον το όνομα χρήστη και τον κωδικό του διακομιστή μεσολάβησης μέσω του Header Proxy-Authorization (χρειάζεται Base64 κωδικοποίηση), και η εκτέλεση αυτού του κώδικα έχει το ίδιο αποτέλεσμα.

Για άλλες γλώσσες, όπως το axios της JavaScript, μπορείτε επίσης να χρησιμοποιήσετε παρόμοιο τρόπο ρύθμισης:

```javascript
const axios = require("axios");
const base64 = require("base64");

const proxy_host = "cellular.proxy.acedata.cloud";
const proxy_port = "30000";
const proxy_username = "{proxy_username}"; // 8 χαρακτήρες όνομα χρήστη
const proxy_password = "{proxy_password}"; // 32 χαρακτήρες κωδικός

const credentials = base64.encode(`${proxy_username}:${proxy_password}`);

const proxies = {
  http: `http://${proxy_host}:${proxy_port}`,
  https: `http://${proxy_host}:${proxy_port}`,
};

const headers = {
  "Proxy-Authorization": `Basic ${credentials}`,
};

for (let i = 0; i < 3; i++) {
  axios
    .get("https://ipinfo.io", { proxies, headers })
    .then((resp) => console.log(resp.data))
    .catch((err) => console.error(err));
}
```

Το αποτέλεσμα εκτέλεσης είναι το ίδιο.

Για τις ρυθμίσεις άλλων γλωσσών, παρακαλώ ανατρέξτε στο παραπάνω κείμενο και τροποποιήστε το ανάλογα.
