Αυτό το άρθρο θα παρουσιάσει μια οδηγία σύνδεσης για το API αναγνώρισης πρωτοκόλλου Recaptcha2, που επιτρέπει στους χρήστες να ολοκληρώνουν την επαλήθευση χωρίς να αναγνωρίζουν και να επιλέγουν τις εικόνες κωδικών Recaptcha2, απλά υποβάλλοντας το Website Key για αυτόματη αποκωδικοποίηση στο παρασκήνιο.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το API αναγνώρισης πρωτοκόλλου Recaptcha2, πρώτα επισκεφθείτε την [Κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας, το οποίο θα κρατήσετε για μελλοντική χρήση.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης που σας προσκαλεί να εγγραφείτε και να συνδεθείτε, και μετά θα επιστρέψετε αυτόματα στη τρέχουσα σελίδα.

**Ένα API Token αρκεί για να καλέσετε όλες τις υπηρεσίες της πλατφόρμας, χωρίς να χρειάζεται να υποβάλετε ξεχωριστές αιτήσεις για κάθε υπηρεσία.** Η πρώτη αίτηση θα σας δώσει δωρεάν πιστώσεις για να δοκιμάσετε δωρεάν; όταν οι πιστώσεις σας εξαντληθούν, μπορείτε να ανανεώσετε το γενικό σας υπόλοιπο στην [κονσόλα](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [API αναγνώρισης πρωτοκόλλου Recaptcha2 →](https://platform.acedata.cloud/documents/captcha-token-recaptcha2)

## Βασική Χρήση

Πρώτα πρέπει να κατανοήσετε τη βασική μέθοδο χρήσης, δηλαδή να εισάγετε το URL της ιστοσελίδας που χρειάζεται επεξεργασία κωδικών, για να λάβετε το επεξεργασμένο αποτέλεσμα. Αρχικά, πρέπει να μεταβιβάσετε απλά ένα πεδίο `website_url`, η δοκιμαστική μας ιστοσελίδα είναι: `https://www.google.com/recaptcha/api2/demo`, πρέπει να αποκτήσουμε το `website_key` από τη σελίδα `website_url`, πρώτα ανοίγουμε αυτή τη σελίδα, πατάμε F12 για να εισέλθουμε στην κονσόλα, και στη συνέχεια κάνουμε παγκόσμια αναζήτηση στη σελίδα Element για το `recaptcha-demo`, μπορούμε να πάρουμε το παρακάτω αποτέλεσμα:

<p><img src="https://cdn.acedata.cloud/hvx41c.png" width="500" className="m-auto" /></p>

Όπου η αλφαριθμητική συμβολοσειρά που αντιστοιχεί στο `data-sitekey` είναι η τιμή του `website_key`, παρακάτω είναι τα συγκεκριμένα αποτελέσματα παραμέτρων:

<p><img src="https://cdn.acedata.cloud/8oowyw.png" width="500" className="m-auto" /></p>

Μπορούμε να δούμε ότι εδώ έχουμε ρυθμίσει τα Request Headers, που περιλαμβάνουν:

- `accept`: ποια μορφή απάντησης θέλουμε να λάβουμε, εδώ συμπληρώνουμε `application/json`, δηλαδή σε μορφή JSON.
- `authorization`: το κλειδί για την κλήση του API, το οποίο μπορείτε να επιλέξετε απευθείας από την αναπτυσσόμενη λίστα μετά την αίτηση.

Επιπλέον, έχουμε ρυθμίσει το Request Body, που περιλαμβάνει:

- `website_url`: το URL της ιστοσελίδας που χρειάζεται επεξεργασία κωδικών.
- `website_key`: ο αναγνωριστικός κωδικός της ιστοσελίδας στο Recaptcha2.
- `proxy`: προαιρετικό, φέρτε τον δικό σας proxy (Bring Your Own Proxy). Μετά τη ρύθμιση, η υπηρεσία θα χρησιμοποιήσει τη διεύθυνση IP του proxy που παρέχετε για να αποκωδικοποιήσει τον κωδικό, για να ελέγξει την ποιότητα της εξόδου IP (π.χ. για να αποφευχθεί η επιστροφή `410 Gone` λόγω δημόσιων proxy IP που έχουν αποκλειστεί από τον στόχο). Η μορφή είναι `scheme://[user:pass@]host:port`, το `scheme` υποστηρίζει `http`/`https`/`socks4`/`socks5`, π.χ. `http://user:pass@1.2.3.4:8080`. Αν δεν συμπληρωθεί, θα χρησιμοποιηθεί ο προεπιλεγμένος proxy της πλατφόρμας.

Αφού επιλέξετε, μπορείτε να δείτε ότι έχει παραχθεί ο αντίστοιχος κώδικας στα δεξιά, όπως φαίνεται στην εικόνα:

Τα αποτελέσματα περιλαμβάνουν πολλαπλά πεδία, όπως περιγράφεται παρακάτω:

- `token`, το αποτέλεσμα της επεξεργασίας του Recaptcha2 captcha.
- `started_at`, `finished_at`: οι χρόνοι έναρξης και ολοκλήρωσης της επεξεργασίας του αιτήματος, Unix χρονική σφραγίδα (δευτερόλεπτα, κινητό).
- `elapsed`: ο συνολικός χρόνος επεξεργασίας (δευτερόλεπτα).

Μπορούμε να δούμε ότι λάβαμε το αποτέλεσμα επεξεργασίας του Recaptcha2 captcha, το οποίο μπορούμε να χρησιμοποιήσουμε για POST ή να το προσομοιώσουμε για υποβολή στον στόχο ιστότοπο, είναι μίας χρήσης, με διάρκεια 120 δευτερόλεπτα, προτείνεται να χρησιμοποιηθεί εντός 60 δευτερολέπτων. Στη συνέχεια, θα παρέχουμε ένα τμήμα Python που θα υποβάλει το επεξεργασμένο token στον στόχο ιστότοπο για να περάσει το Recaptcha2 captcha.

Αρχικά, πρέπει να κατανοήσουμε πώς ο ιστότοπος στέλνει το POST αίτημα, έτσι ώστε να μπορέσουμε να περάσουμε το παραγόμενο token. Πρέπει πρώτα να ανοίξουμε την κονσόλα F12 και να κάνουμε μια χειροκίνητη επαλήθευση. Στο τέλος, μπορούμε να δούμε ότι ο ιστότοπος έστειλε ένα POST αίτημα. Πρέπει απλώς να ελέγξουμε τη δομή αυτού του POST αιτήματος, η διαδικασία είναι η εξής:

- Πρώτα κάνουμε χειροκίνητη επαλήθευση, όπως φαίνεται στην παρακάτω εικόνα:

- Στη συνέχεια, κάνουμε κλικ στο submit και παρακολουθούμε τις αλλαγές στο δίκτυο της κονσόλας, όπως φαίνεται στην παρακάτω εικόνα:
<p><img src="https://cdn.acedata.cloud/6hm5kj.png" width="500" className="m-auto" /></p>

- Αναλύστε τη δομή του POST αιτήματος που υποβλήθηκε, στο τέλος μπορείτε να κάνετε δεξί κλικ σε αυτό το αίτημα για να αντιγράψετε τον κώδικα CURL, συγκεκριμένα όπως φαίνεται στην παρακάτω εικόνα:

<p><img src="https://cdn.acedata.cloud/m7y35w.png" width="500" className="m-auto" /></p>

Από την παραπάνω ανάλυση, μπορούμε να δούμε ότι το URL του POST αιτήματος είναι: `https://www.google.com/recaptcha/api2/demo`, χρειαζόμαστε μόνο να υποβάλουμε την παράμετρο `g-recaptcha-response`, και στη συνέχεια απλά πρέπει να περάσουμε το επεξεργασμένο token στα παρακάτω δεδομένα, ο κώδικας CURL για την κλήση του token για επαλήθευση είναι ο εξής:

```shell
curl 'https://www.google.com/recaptcha/api2/demo' \
  --data-raw 'g-recaptcha-response={token}’
```

Ο κώδικας Python για την κλήση του token για επαλήθευση είναι ο εξής:

```python
import requests

token = '{token}'

data = {
    'g-recaptcha-response': token,
}

response = requests.post('https://www.google.com/recaptcha/api2/demo',data=data)

if response.status_code:
    print(response.text)

```

Στη συνέχεια, εκτελούμε τον κώδικα και παρατηρούμε ότι η κονσόλα έχει αυτό το αποτέλεσμα:

<p><img src="https://cdn.acedata.cloud/ku22tk.png" width="500" className="m-auto" /></p>

Τελικά, περάσαμε την επαλήθευση του πρωτοκόλλου Recaptcha2.

Επιπλέον, αν θέλετε να δημιουργήσετε τον αντίστοιχο κώδικα διασύνδεσης, μπορείτε να τον αντιγράψετε απευθείας, για παράδειγμα, ο κώδικας CURL είναι ο εξής:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo"
}'
```

Ο κώδικας Python για τη διασύνδεση είναι ο εξής:

```python
import requests

url = "https://api.acedata.cloud/captcha/token/recaptcha2"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
    "website_url": "https://www.google.com/recaptcha/api2/demo"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Ασύγχρονη λειτουργία (async)

Από προεπιλογή, το API είναι συγχρονισμένο και μπλοκαρισμένο: ένα αίτημα θα περιμένει μέχρι να ολοκληρωθεί η επεξεργασία του token πριν επιστρέψει. Αν κάνετε πολλαπλή εναλλαγή κωδικοποιητών (multi-solver rotation) και θέλετε «να λάβετε αμέσως το task_id μετά την υποβολή του αιτήματος, να προγραμματίσετε άλλους κωδικοποιητές και αργότερα να επιστρέψετε για να διαβάσετε το αποτέλεσμα», μπορείτε να περάσετε `async: true` στο σώμα του αιτήματος.

Αφού περάσετε `async: true`, η διεπαφή θα επιστρέψει αμέσως ένα `task_id`, χωρίς να μπλοκάρει την αναμονή:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

Αν χρειαστεί να ελέγξετε την πρόοδο, μπορείτε να χρησιμοποιήσετε το `task_id` για να ελέγξετε το `POST /captcha/tasks` (συνιστάται κάθε 3~5 δευτερόλεπτα). Αυτή η διεπαφή δεν θα ενεργοποιήσει ή θα προχωρήσει την επεξεργασία του αιτήματος. Ακόμα και αν δεν ελέγξετε, διακοπεί η σύνδεση ή κλείσετε τον πελάτη, ο διακομιστής θα συνεχίσει την επεξεργασία:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Κατά την επεξεργασία θα επιστραφεί `status: processing`:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

Όταν ολοκληρωθεί η επεξεργασία, θα επιστραφεί `status: ready` και token:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "token": "03AFcWeA5kjJyDQ9S1a9UYimR6nuxnpEnAs5x2Pixao0dXZhMB......"
}
```

Πληροφορίες χρέωσης: Στην ασύγχρονη λειτουργία, η δημιουργία αιτήματος και η ανάγνωση της κατάστασης «σε επεξεργασία» δεν χρεώνονται. **Η χρέωση γίνεται μία φορά όταν ο πελάτης διαβάσει επιτυχώς το αποτέλεσμα για πρώτη φορά** (σύμφωνα με την υπάρχουσα συμπεριφορά και την τιμή της συγχρονισμένης λειτουργίας). Ο διακομιστής θα προχωρήσει αυτόματα την επεξεργασία του αιτήματος, αλλά δεν θα χρεώσει νωρίτερα επειδή ολοκληρώθηκε πρώτα στο παρασκήνιο. Αν το αίτημα δεν ολοκληρωθεί επιτυχώς εντός 120 δευτερολέπτων, θα τερματιστεί με HTTP 504 `timeout`, χωρίς χρέωση. Το `/captcha/tasks` δεν είναι υπεύθυνο για την προώθηση του αιτήματος.

## Διαχείριση σφαλμάτων

Κατά την κλήση του API, αν προκύψει σφάλμα, το API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διαπιστευτήριο εξουσιοδότησης.
- `429 too_many_requests`: Πάρα πολλές αιτήσεις, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.

### Παράδειγμα σφάλματος

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
