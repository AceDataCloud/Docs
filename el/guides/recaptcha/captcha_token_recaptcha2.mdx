Αυτό το άρθρο θα παρουσιάσει μια μέθοδο σύνδεσης API αναγνώρισης πρωτοκόλλου Recaptcha2, η οποία επιτρέπει στους χρήστες να μην χρειάζεται να αναγνωρίζουν και να επιλέγουν τις εικόνες κωδικών επαλήθευσης Recaptcha2, αλλά να ολοκληρώνουν την επαλήθευση υποβάλλοντας απλώς το Website Key, επιτυγχάνοντας αυτόματη αποκωδικοποίηση στο παρασκήνιο.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το API, πρέπει πρώτα να επισκεφθείτε τη σελίδα [API Αναγνώρισης Πρωτοκόλλου Recaptcha2](https://platform.acedata.cloud/documents/597b8f11-26d8-4a1d-9a83-8d33bc4b8af7) και να ζητήσετε την αντίστοιχη υπηρεσία. Αφού εισέλθετε στη σελίδα, κάντε κλικ στο κουμπί «Acquire», όπως φαίνεται στην εικόνα:

![](https://cdn.acedata.cloud/q6ytrc.png)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης, προσκαλώντας σας να εγγραφείτε και να συνδεθείτε. Μετά την εγγραφή και τη σύνδεση, θα επιστρέψετε αυτόματα στη σελίδα.

Κατά την πρώτη αίτηση, θα λάβετε δωρεάν πιστώσεις, επιτρέποντάς σας να χρησιμοποιήσετε το API δωρεάν.

## Βασική Χρήση

Αρχικά, πρέπει να κατανοήσετε τη βασική μέθοδο χρήσης, δηλαδή να εισάγετε το URL της ιστοσελίδας που χρειάζεται επεξεργασία κωδικών επαλήθευσης, για να λάβετε το επεξεργασμένο αποτέλεσμα. Πρέπει πρώτα να μεταβιβάσετε ένα πεδίο `website_url`. Η ιστοσελίδα παραδείγματός μας είναι: `https://www.google.com/recaptcha/api2/demo`. Πρέπει να αποκτήσουμε το `website_key` από τη σελίδα `website_url`, ανοίγοντας αυτή τη σελίδα, πατώντας F12 για να εισέλθουμε στην κονσόλα και κάνοντας παγκόσμια αναζήτηση στο Element για το `recaptcha-demo`. Μπορούμε να λάβουμε το παρακάτω αποτέλεσμα:

<p><img src="https://cdn.acedata.cloud/hvx41c.png" width="500" className="m-auto" /></p>

Η αλφαριθμητική συμβολοσειρά που αντιστοιχεί στο `data-sitekey` είναι η τιμή του `website_key`. Ακολουθούν τα συγκεκριμένα αποτελέσματα παραμέτρων:

<p><img src="https://cdn.acedata.cloud/8oowyw.png" width="500" className="m-auto" /></p>

Μπορούμε να δούμε ότι έχουμε ρυθμίσει τα Request Headers, τα οποία περιλαμβάνουν:

- `accept`: ποια μορφή απάντησης θέλουμε να λάβουμε, εδώ συμπληρώνουμε `application/json`, δηλαδή σε μορφή JSON.
- `authorization`: το κλειδί API που χρησιμοποιείται για την κλήση του API, το οποίο μπορείτε να επιλέξετε απευθείας από την αναπτυσσόμενη λίστα μετά την αίτηση.

Επιπλέον, έχουμε ρυθμίσει το Request Body, το οποίο περιλαμβάνει:

- `website_url`: το URL της ιστοσελίδας που χρειάζεται επεξεργασία κωδικών επαλήθευσης.
- `website_key`: ο αναγνωριστικός δείκτης του κλειδιού της ιστοσελίδας στο Recaptcha2.

Η επιστροφή αποτελεσμάτων περιλαμβάνει πολλαπλά πεδία, όπως περιγράφεται παρακάτω:

- `token`, το αποτέλεσμα της επεξεργασίας του Recaptcha2 captcha.

Μπορούμε να δούμε ότι λάβαμε το αποτέλεσμα της επεξεργασίας του Recaptcha2 captcha, το οποίο μπορούμε να χρησιμοποιήσουμε για POST ή προσομοίωση υποβολής στον στόχο ιστότοπο, είναι μιας χρήσης, με διάρκεια 120 δευτερόλεπτα, προτείνεται να χρησιμοποιηθεί εντός 60 δευτερολέπτων. Στη συνέχεια, θα παρέχουμε ένα τμήμα Python που θα υποβάλει το επεξεργασμένο token στον στόχο ιστότοπο για να περάσει το Recaptcha2 captcha.

Αρχικά, πρέπει να κατανοήσουμε πώς ο ιστότοπος στέλνει το POST αίτημα, έτσι ώστε να μπορέσουμε να περάσουμε το παραγόμενο token. Πρέπει πρώτα να ανοίξουμε την κονσόλα F12 και να κάνουμε μια χειροκίνητη επαλήθευση, στο τέλος θα δούμε ότι ο ιστότοπος έχει στείλει ένα POST αίτημα. Πρέπει να εξετάσουμε τη δομή αυτού του POST αιτήματος, η διαδικασία είναι η εξής:

- Πρώτα κάνουμε χειροκίνητη επαλήθευση, όπως φαίνεται στην παρακάτω εικόνα:

<p><img src="https://cdn.acedata.cloud/gwiflr.png" width="500" className="m-auto" /></p>

- Στη συνέχεια, κάνουμε κλικ στο submit και παρακολουθούμε τις αλλαγές στο δίκτυο της κονσόλας, όπως φαίνεται στην παρακάτω εικόνα:

<p><img src="https://cdn.acedata.cloud/6hm5kj.png" width="500" className="m-auto" /></p>

- Αναλύουμε τη δομή του POST αιτήματος που υποβλήθηκε, στο τέλος μπορούμε να κάνουμε δεξί κλικ σε αυτό το αίτημα και να αντιγράψουμε τον κώδικα CURL, όπως φαίνεται στην παρακάτω εικόνα:
<p><img src="https://cdn.acedata.cloud/m7y35w.png" width="500" className="m-auto" /></p>

Από την παραπάνω εικόνα, μπορούμε να αναλύσουμε ότι το URL του POST αιτήματος είναι: `https://www.google.com/recaptcha/api2/demo`, χρειαζόμαστε μόνο να υποβάλουμε την παράμετρο `g-recaptcha-response`, και στη συνέχεια απλά πρέπει να περάσουμε το επεξεργασμένο token στα παρακάτω δεδομένα, η συγκεκριμένη κωδικοποίηση CURL για την επαλήθευση του token είναι η εξής:

```shell
curl 'https://www.google.com/recaptcha/api2/demo' \
  --data-raw 'g-recaptcha-response={token}’
```

Η αντίστοιχη κωδικοποίηση Python για την επαλήθευση του token είναι η εξής:

```python
import requests

token = '{token}'

data = {
    'g-recaptcha-response': token,
}

response = requests.post('https://www.google.com/recaptcha/api2/demo',data=data)

if response.status_code:
    print(response.text)

```

Στη συνέχεια, τρέχουμε τον κώδικα και παρατηρούμε ότι η κονσόλα έχει το εξής αποτέλεσμα:

<p><img src="https://cdn.acedata.cloud/ku22tk.png" width="500" className="m-auto" /></p>

Τελικά, περάσαμε την επαλήθευση του πρωτοκόλλου Recaptcha2.

Επιπλέον, αν θέλετε να δημιουργήσετε τον αντίστοιχο κώδικα σύνδεσης, μπορείτε να τον αντιγράψετε απευθείας, όπως ο κώδικας CURL παρακάτω:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo"
}'
```

Ο κώδικας σύνδεσης Python είναι ο εξής:

```python
import requests

url = "https://api.acedata.cloud/captcha/token/recaptcha2"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
    "website_url": "https://www.google.com/recaptcha/api2/demo"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Διαχείριση σφαλμάτων

Κατά την κλήση της API, αν προκύψει σφάλμα, η API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές token εξουσιοδότησης.
- `429 too_many_requests`: Πάρα πολλές αιτήσεις, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.
