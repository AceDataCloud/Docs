Kimi είναι ένα πολύ ισχυρό σύστημα AI συνομιλίας, απλά εισάγοντας λέξεις-κλειδιά, μπορεί να δημιουργήσει ομαλές και φυσικές απαντήσεις σε λίγα δευτερόλεπτα. Η Kimi μπορεί να προσφέρει εκπληκτική έξυπνη βοήθεια, αυξάνοντας σημαντικά την παραγωγικότητα και τη δημιουργικότητα των ανθρώπων.

Αυτό το έγγραφο περιγράφει κυρίως τη διαδικασία χρήσης του Kimi Chat Completion API, με το οποίο μπορούμε να χρησιμοποιήσουμε εύκολα τη λειτουργία συνομιλίας της επίσημης Kimi.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το Gemini Chat Completion API, μπορείτε πρώτα να επισκεφθείτε τη σελίδα [Kimi Chat Completion API](https://platform.acedata.cloud/documents/b23bbfa3-c820-47ee-b307-6c6dedc9d0cf) και να κάνετε κλικ στο κουμπί «Acquire» για να αποκτήσετε τα απαραίτητα διαπιστευτήρια:

![](https://cdn.acedata.cloud/nyq0xz.png)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης για να σας προσκαλέσουν να εγγραφείτε και να συνδεθείτε, και μετά την εγγραφή και σύνδεση θα επιστρέψετε αυτόματα στη σελίδα.

Κατά την πρώτη αίτηση, θα υπάρχει δωρεάν πίστωση που μπορείτε να χρησιμοποιήσετε δωρεάν για αυτό το API.

## Βασική Χρήση

Στη συνέχεια, μπορείτε να συμπληρώσετε τα αντίστοιχα περιεχόμενα στην διεπαφή, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" class="m-auto"></p>

Κατά την πρώτη χρήση αυτού του API, πρέπει τουλάχιστον να συμπληρώσουμε τρία περιεχόμενα, ένα είναι το `authorization`, το οποίο μπορείτε να επιλέξετε απευθείας από τη λίστα. Ένα άλλο παράμετρο είναι το `model`, το `model` είναι η κατηγορία μοντέλου που επιλέγουμε να χρησιμοποιήσουμε από την επίσημη ιστοσελίδα της Kimi, εδώ έχουμε κυρίως 7 μοντέλα, περισσότερες λεπτομέρειες μπορείτε να δείτε στα μοντέλα που παρέχουμε. Η τελευταία παράμετρος είναι το `messages`, το `messages` είναι ο πίνακας των ερωτήσεων που εισάγουμε, είναι ένας πίνακας που δηλώνει ότι μπορείτε να ανεβάσετε πολλές ερωτήσεις ταυτόχρονα, κάθε ερώτηση περιλαμβάνει το `role` και το `content`, όπου το `role` δηλώνει το ρόλο του ερωτώντος, παρέχουμε τρεις ταυτότητες, δηλαδή `user`, `assistant`, `system`. Το άλλο `content` είναι το συγκεκριμένο περιεχόμενο της ερώτησής μας.

Μπορείτε επίσης να παρατηρήσετε ότι στα δεξιά υπάρχει η αντίστοιχη γεννήτρια κώδικα κλήσης, μπορείτε να αντιγράψετε τον κώδικα και να τον εκτελέσετε απευθείας ή να κάνετε κλικ στο κουμπί «Try» για να δοκιμάσετε.

## Ροή Απόκρισης

Αυτή η διεπαφή υποστηρίζει επίσης ροή απόκρισης, κάτι που είναι πολύ χρήσιμο για την ενσωμάτωσή της σε ιστοσελίδες, καθώς μπορεί να επιτρέψει την εμφάνιση αποτελεσμάτων λέξη προς λέξη.

Εάν θέλετε να επιστρέψετε την απόκριση με ροή, μπορείτε να αλλάξετε την παράμετρο `stream` στην κεφαλίδα του αιτήματος σε `true`.

Η αλλαγή είναι όπως φαίνεται στην εικόνα, αλλά ο κώδικας κλήσης χρειάζεται να έχει τις αντίστοιχες αλλαγές για να υποστηρίξει τη ροή απόκρισης.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" class="m-auto"></p>

Αφού αλλάξετε το `stream` σε `true`, το API θα επιστρέφει γραμμή προς γραμμή τα αντίστοιχα δεδομένα JSON, και σε επίπεδο κώδικα θα χρειαστεί να κάνουμε τις αντίστοιχες αλλαγές για να αποκτήσουμε τα αποτελέσματα γραμμή προς γραμμή.

Παράδειγμα κώδικα κλήσης σε Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k2.5",
    "messages": [{"role":"user","content":"Γειά σου"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Μπορείτε να δείτε ότι στην απάντηση υπάρχουν πολλά `data`, το `data` περιέχει τις `choices`, οι οποίες είναι το πιο πρόσφατο περιεχόμενο απάντησης, σύμφωνα με την προηγούμενη περιγραφή. Οι `choices` είναι το νέο περιεχόμενο απάντησης, μπορείτε να το συνδέσετε με το σύστημά σας ανάλογα με τα αποτελέσματα. Ταυτόχρονα, το τέλος της ροής απάντησης κρίνεται από το περιεχόμενο του `data`, αν το περιεχόμενο είναι `[DONE]`, τότε σημαίνει ότι η ροή απάντησης έχει ολοκληρωθεί. Τα αποτελέσματα του επιστρεφόμενου `data` περιλαμβάνουν πολλά πεδία, τα οποία περιγράφονται παρακάτω:

- `id`, το ID που δημιουργεί την τρέχουσα εργασία συνομιλίας, χρησιμοποιείται για την μοναδική αναγνώριση της τρέχουσας εργασίας συνομιλίας.
- `model`, το επιλεγμένο μοντέλο από την επίσημη ιστοσελίδα της Kimi.
- `choices`, οι πληροφορίες απάντησης που παρέχει η Kimi για τις ερωτήσεις.

Η JavaScript υποστηρίζεται επίσης, για παράδειγμα, ο κώδικας ροής κλήσης του Node.js είναι ο εξής:

```javascript
const options = {
  method: "post",
  headers: {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    "model": "kimi-k2.5",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": true
  })
};

fetch("https://api.acedata.cloud/kimi/chat/completions", options)
  .then(response => response.json())
  .then(response => console.log(response))
  .catch(err => console.error(err));
```


## Πολυδιάστατη συνομιλία

Αν θέλετε να συνδέσετε τη λειτουργία πολυδιάστατης συνομιλίας, πρέπει να ανεβάσετε πολλαπλές ερωτήσεις στο πεδίο `messages`, οι συγκεκριμένες ερωτήσεις είναι όπως φαίνεται στην παρακάτω εικόνα:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" class="m-auto"></p>

Παράδειγμα κώδικα Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k2.5",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Διαχείριση σφαλμάτων

Κατά την κλήση της API, αν συναντήσετε σφάλματα, η API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διαπιστευτήριο εξουσιοδότησης.
- `429 too_many_requests`: Πάρα πολλές αιτήσεις, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.
