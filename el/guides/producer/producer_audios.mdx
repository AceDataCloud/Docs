Αυτό το έγγραφο θα παρουσιάσει μια μέθοδο σύνδεσης με το API Δημιουργίας Ήχων Παραγωγού, το οποίο μπορεί να δημιουργήσει τη μουσική του επίσημου παραγωγού μέσω εισαγωγής προσαρμοσμένων παραμέτρων.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το API, πρέπει πρώτα να επισκεφθείτε τη σελίδα [API Δημιουργίας Ήχων Παραγωγού](https://platform.acedata.cloud/documents/producer-audios) και να ζητήσετε την αντίστοιχη υπηρεσία. Αφού μπείτε στη σελίδα, κάντε κλικ στο κουμπί «Acquire», όπως φαίνεται στην εικόνα:

![](https://cdn.acedata.cloud/q6ytrc.png)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης για να εγγραφείτε και να συνδεθείτε. Μετά την εγγραφή και σύνδεση, θα επιστρέψετε αυτόματα στη σελίδα.

Κατά την πρώτη αίτηση, θα υπάρχει δωρεάν πίστωση που μπορείτε να χρησιμοποιήσετε δωρεάν για αυτό το API.

## Βασική Χρήση

Μπορείτε να εισάγετε οποιοδήποτε κείμενο για να δημιουργήσετε τραγούδια. Για παράδειγμα, αν θέλετε να δημιουργήσετε ένα τραγούδι για τα Χριστούγεννα, μπορείτε να εισάγετε `a song for Christmas`, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" class="m-auto"></p>

Μπορείτε να δείτε ότι έχουμε ρυθμίσει τα Request Headers, συμπεριλαμβανομένων:

- `accept`: ποια μορφή απάντησης θέλετε να λάβετε, εδώ συμπληρώνεται ως `application/json`, δηλαδή σε μορφή JSON.
- `authorization`: το κλειδί για την κλήση του API, το οποίο μπορείτε να επιλέξετε απευθείας από το αναπτυσσόμενο μενού μετά την αίτηση.

Επιπλέον, οι παράμετροι του Request Body περιλαμβάνουν:

- `action`: η ενέργεια της τρέχουσας εργασίας δημιουργίας μουσικής, η δημιουργία τραγουδιού είναι `generate`.
- `model`: το μοντέλο που χρησιμοποιείται για τη δημιουργία του τραγουδιού, αυτή τη στιγμή υπάρχουν κυρίως: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**, **FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: το περιεχόμενο των στίχων του τραγουδιού.
- `custom`: αν θα χρησιμοποιηθεί η προσαρμοσμένη μέθοδος για τη δημιουργία του τραγουδιού.
- `prompt`: οι λέξεις-κλειδιά στην κατάσταση έμπνευσης.
- `title`: οι πληροφορίες τίτλου του τραγουδιού.
- `audio_id`: το ID του αναφοράς του τραγουδιού, για συνέχιση/αντιγραφή κ.λπ.
- `continue_at`: να συνεχίσει τη δημιουργία του τραγουδιού από συγκεκριμένο δευτερόλεπτο.
- `replace_section_start`/`replace_section_end`: η αρχή και το τέλος του χρόνου αντικατάστασης, σε δευτερόλεπτα.
- `lyrics_strength`: η ένταση των στίχων, που δηλώνει την επιρροή των στίχων στη δημιουργία ήχου, επιλέξιμο από 0-1, προεπιλογή 0.7.
- `sound_strength`: η ένταση των λέξεων-κλειδιών ήχου, επιλέξιμο από 0.2-1, προεπιλογή 0.7.
- `cover_strength`: η ένταση της διασκευής από 0.2-1, προεπιλογή 1.
- `weirdness`: η ιδιαιτερότητα του στυλ, επιλέξιμο από 0-1, προεπιλογή 0.5.
- `callback_url`: το URL για την επιστροφή των αποτελεσμάτων.
- `instrumental`: αν είναι σε λειτουργία χωρίς στίχους.

Αφού επιλέξετε, μπορείτε να δείτε ότι έχει παραχθεί ο αντίστοιχος κώδικας στα δεξιά, όπως φαίνεται στην εικόνα:

Επιπλέον, αν θέλετε να δημιουργήσετε τον αντίστοιχο κώδικα σύνδεσης, μπορείτε να τον αντιγράψετε απευθείας, για παράδειγμα, ο κώδικας CURL είναι ως εξής:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## 翻唱歌曲

Αν θέλετε να κάνετε κάλυψη σε ένα ήδη παραγόμενο τραγούδι, μπορείτε να εισάγετε το παραγόμενο τραγούδι παραπάνω για να κάνετε κάλυψη, στη συνέχεια θα πρέπει να προσαρμόσουμε την παραγωγή του τραγουδιού με βάση τους στίχους και τον τίτλο.

Αν θέλετε να συνεχίσετε την κάλυψη ενός τραγουδιού που έχετε ανεβάσει, μπορείτε να ρυθμίσετε την παράμετρο `action` σε `upload_cover` και να εισάγετε το ID του τραγουδιού που θέλετε να συνεχίσετε να καλύπτετε, το ID του τραγουδιού μπορεί να αποκτηθεί χρησιμοποιώντας το [Producer Upload API](https://platform.acedata.cloud/documents/7fd2cb52-772e-4cc4-a018-e2626ff6f447) όπως φαίνεται στην παρακάτω εικόνα:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" class="m-auto"></p>

Μπορείτε να καθορίσετε τα εξής περιεχόμενα:

- action: Η ενέργεια του τραγουδιού αυτή τη φορά, υποστηρίζονται επί του παρόντος: generate, cover, extend, upload_cover, upload_extend, replace_section, swap_vocals, swap_instrumentals, variation, αυτή τη φορά η κάλυψη χρησιμοποιεί την παράμετρο `cover`.
- lyric: Κείμενο στίχων
- title: Ο τίτλος του τραγουδιού.
- custom: Εάν θα χρησιμοποιηθεί η προσαρμοσμένη λειτουργία παραγωγής, προεπιλογή είναι false.
- audio_id: Το ID του τραγουδιού που χρειάζεται κάλυψη.

## Συμπλήρωση τραγουδιού

Αν θέλετε να συμπληρώσετε το τραγούδι, πρέπει να περάσουμε την παράμετρο `action` με τιμή: `extend`, στη συνέχεια θα πρέπει να προσαρμόσουμε τη δημιουργία του τραγουδιού με βάση τους στίχους, τον τίτλο και το στυλ.

Αν θέλετε να συνεχίσετε τη συμπλήρωση ενός τραγουδιού που έχετε ανεβάσει, μπορείτε να ρυθμίσετε την παράμετρο `action` σε `upload_extend` και να εισάγετε το ID του τραγουδιού που θέλετε να συνεχίσετε, το ID του τραγουδιού μπορείτε να το αποκτήσετε χρησιμοποιώντας το [Producer Upload API](https://platform.acedata.cloud/documents/7fd2cb52-772e-4cc4-a018-e2626ff6f447), όπως φαίνεται στην παρακάτω εικόνα:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" class="m-auto"></p>

Το δείγμα συμπλήρωσης είναι το εξής:

<p><img src="https://cdn.acedata.cloud/r3ux6z.png" width="500" class="m-auto"></p>

Αφού συμπληρωθεί, αυτόματα δημιουργείται ο παρακάτω κώδικας:

<p><img src="https://cdn.acedata.cloud/fsww0u.png" width="500" class="m-auto"></p>

Ο αντίστοιχος κώδικας:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "extend",
```

## Ασύγχρονη κλήση επιστροφής

Δεδομένου ότι η API Δημιουργίας Ήχου Producer μπορεί να χρειαστεί αρκετό χρόνο για να παραχθεί, αν η API δεν απαντήσει για μεγάλο χρονικό διάστημα, το HTTP αίτημα θα διατηρεί τη σύνδεση, προκαλώντας επιπλέον κατανάλωση πόρων συστήματος, γι' αυτό η API παρέχει επίσης υποστήριξη για ασύγχρονη κλήση επιστροφής.

Η συνολική διαδικασία είναι: όταν ο πελάτης υποβάλλει το αίτημα, προσδιορίζει επιπλέον ένα πεδίο `callback_url`, μετά την υποβολή του API, η API θα επιστρέψει αμέσως ένα αποτέλεσμα που περιλαμβάνει μια πληροφορία πεδίου `task_id`, που αντιπροσωπεύει το τρέχον ID εργασίας. Όταν ολοκληρωθεί η εργασία, το αποτέλεσμα της δημιουργίας εργασίας θα αποσταλεί μέσω POST JSON στη διεύθυνση `callback_url` που έχει καθορίσει ο πελάτης, η οποία περιλαμβάνει επίσης το πεδίο `task_id`, έτσι ώστε το αποτέλεσμα της εργασίας να μπορεί να συσχετιστεί μέσω του ID.

Ας δούμε πώς να το κάνουμε με ένα παράδειγμα.

Πρώτον, η κλήση Webhook είναι μια υπηρεσία που μπορεί να δέχεται HTTP αιτήματα, οι προγραμματιστές θα πρέπει να την αντικαταστήσουν με το URL του HTTP διακομιστή που έχουν δημιουργήσει. Για ευκολία, χρησιμοποιούμε έναν δημόσιο ιστότοπο παραδείγματος Webhook [https://webhook.site/](https://webhook.site/), ανοίγοντας αυτόν τον ιστότοπο μπορείτε να αποκτήσετε ένα Webhook URL, όπως φαίνεται στην εικόνα:

![](https://cdn.acedata.cloud/tbcnai.png)

## 错误处理

在调用 API 时，如果遇到错误，API 会返回相应的错误代码和信息。例如：

- `400 token_mismatched`：Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`：Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`：Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διαπιστευτήριο εξουσιοδότησης.
- `429 too_many_requests`：Πάρα πολλές αιτήσεις, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`：Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.

### 错误响应示例

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "η λήψη απέτυχε"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
