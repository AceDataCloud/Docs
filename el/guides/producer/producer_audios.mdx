Αυτό το άρθρο θα παρουσιάσει έναν τρόπο ενσωμάτωσης του Producer Audios Generation API, το οποίο μπορεί να δημιουργήσει επίσημη μουσική του Producer μέσω εισαγωγής προσαρμοσμένων παραμέτρων.

## Διαδικασία αίτησης

Για να χρησιμοποιήσετε το Producer Audios Generation API, μεταβείτε πρώτα στην [κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας και κρατήστε το για μελλοντική χρήση.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε ακόμη συνδεθεί ή εγγραφεί, θα ανακατευθυνθείτε αυτόματα στη σελίδα σύνδεσης για να προσκληθείτε να εγγραφείτε και να συνδεθείτε, και μετά την ολοκλήρωση θα επιστρέψετε αυτόματα στην τρέχουσα σελίδα.

**Ένα API Token αρκεί για την κλήση όλων των υπηρεσιών της πλατφόρμας, χωρίς να χρειάζεται ξεχωριστή αίτηση για κάθε υπηρεσία.** Η πρώτη αίτηση προσφέρει δωρεάν υπόλοιπο, για δωρεάν δοκιμή· όταν το υπόλοιπο δεν επαρκεί, μπορείτε να επαναφορτίσετε το γενικό υπόλοιπο στην [κονσόλα](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Βασική χρήση

Όποιο τραγούδι θέλετε να σκεφτείτε, μπορείτε να εισαγάγετε αυθαίρετα ένα κείμενο, για παράδειγμα αν θέλω να δημιουργήσω ένα τραγούδι για τα Χριστούγεννα, μπορώ να εισαγάγω `a song for Christmas`, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Μπορείτε να δείτε ότι εδώ ορίσαμε τα Request Headers, που περιλαμβάνουν:

- `accept`: ποια μορφή αποτελέσματος απόκρισης θέλετε να λάβετε, εδώ συμπληρώνεται ως `application/json`, δηλαδή μορφή JSON.
- `authorization`: το κλειδί για την κλήση του API, μετά την αίτηση μπορείτε να το επιλέξετε απευθείας από την αναπτυσσόμενη λίστα.

Επιπλέον, οι παράμετροι του Request Body περιλαμβάνουν:

- `action`: η ενέργεια αυτής της εργασίας δημιουργίας μουσικής, για τη δημιουργία τραγουδιού είναι `generate`.
- `model`: το μοντέλο που χρησιμοποιείται για τη δημιουργία τραγουδιού, προς το παρόν περιλαμβάνει κυρίως: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: το περιεχόμενο των στίχων του τραγουδιού.
- `custom`: αν χρησιμοποιείται προσαρμοσμένος τρόπος για τη δημιουργία τραγουδιού.
- `prompt`: οι λέξεις προτροπής στη λειτουργία έμπνευσης.
- `title`: οι πληροφορίες τίτλου του τραγουδιού.
- `audio_id`: το ID του τραγουδιού αναφοράς, που χρησιμοποιείται για ενέργειες όπως συνέχιση/διασκευή.
- `continue_at`: συνέχιση του τραγουδιού από το καθορισμένο δευτερόλεπτο.
- `replace_section_start`/`replace_section_end`: ο χρόνος έναρξης και λήξης του τμήματος αντικατάστασης, σε δευτερόλεπτα.
- `lyrics_strength`: η ένταση των στίχων, που υποδηλώνει τον βαθμό επιρροής των στίχων στη δημιουργία ήχου, προαιρετικά μεταξύ 0-1, προεπιλογή 0.7.
- `sound_strength`: η ένταση των λέξεων προτροπής ήχου, προαιρετικά μεταξύ 0.2-1, προεπιλογή 0.7.
- `cover_strength`: η ένταση διασκευής μεταξύ 0.2-1, προεπιλογή 1.
- `weirdness`: ο βαθμός ιδιαιτερότητας του στυλ, προαιρετικά μεταξύ 0-1, προεπιλογή 0.5
- `callback_url`: το URL που χρειάζεται να λάβει το αποτέλεσμα μέσω callback.
- `async`: προαιρετικό, όταν οριστεί σε `true`, η διεπαφή επιστρέφει αμέσως `task_id`, χωρίς να χρειάζεται να παρέχετε `callback_url`, και στη συνέχεια το αποτέλεσμα λαμβάνεται μέσω polling από την αντίστοιχη διεπαφή ερωτήματος εργασίας.
- `instrumental`: αν είναι λειτουργία χωρίς στίχους.

Μετά την επιλογή, μπορείτε να διαπιστώσετε ότι ο αντίστοιχος κώδικας δημιουργήθηκε επίσης στα δεξιά, όπως φαίνεται στην εικόνα:

    - `lyric`, οι πληροφορίες στίχων της εργασίας δημιουργίας μουσικής αυτή τη στιγμή.

Μπορείτε να δείτε ότι λάβαμε τις πληροφορίες της μουσικής που θέλουμε να δημιουργήσουμε, και χρειάζεται μόνο να αποκτήσουμε τη δημιουργημένη μουσική Producer σύμφωνα με τη διεύθυνση συνδέσμου μουσικής του `data` στο αποτέλεσμα.

Επιπλέον, εάν θέλετε να δημιουργήσετε τον αντίστοιχο κώδικα ενσωμάτωσης, μπορείτε να τον αντιγράψετε απευθείας, για παράδειγμα ο κώδικας CURL είναι ο εξής:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Διασκευή τραγουδιού

Αν θέλετε να πραγματοποιήσετε διασκευή σε ένα τραγούδι που έχει ήδη δημιουργηθεί, μπορείτε να εισαγάγετε το τραγούδι που δημιουργήθηκε παραπάνω για διασκευή· στη συνέχεια θα δημιουργήσουμε προσαρμοσμένα το τραγούδι με βάση τους στίχους και τον τίτλο.

Αν θέλετε να συνεχίσετε τη διασκευή ενός τραγουδιού που ανεβάσατε εσείς, μπορείτε να ορίσετε την παράμετρο `action` σε `upload_cover` και να εισαγάγετε το ID του προσαρμοσμένα ανεβασμένου τραγουδιού που χρειάζεται περαιτέρω διασκευή. Η λήψη του ID του τραγουδιού γίνεται με χρήση του [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), όπως φαίνεται στην παρακάτω εικόνα:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Μπορείτε να καθορίσετε το ακόλουθο περιεχόμενο:

- action：η ενέργεια αυτής της εργασίας τραγουδιού, προς το παρόν υποστηρίζει: generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation· αυτή η διασκευή χρησιμοποιεί την παράμετρο `cover`.
- lyric：κείμενο στίχων
- title：ο τίτλος του τραγουδιού.
- custom：αν θα χρησιμοποιηθεί η λειτουργία προσαρμοσμένης δημιουργίας, η προεπιλογή είναι false.
- audio_id：το ID του τραγουδιού που χρειάζεται διασκευή.

## Συνέχιση τραγουδιού

Αν θέλουμε να συνεχίσουμε ένα τραγούδι, πρέπει να περάσουμε την τιμή της παραμέτρου `action` ως: `extend`, και στη συνέχεια μπορούμε να δημιουργήσουμε προσαρμοσμένα ένα τραγούδι με βάση τους στίχους, τον τίτλο και το στυλ.

Αν θέλουμε να συνεχίσουμε ένα τραγούδι που έχουμε ανεβάσει εμείς οι ίδιοι, μπορούμε να ορίσουμε την παράμετρο `action` ως `upload_extend`, και η είσοδος πρέπει να περιλαμβάνει το ID του προσαρμοσμένου ανεβασμένου τραγουδιού που χρειάζεται να συνεχιστεί. Η απόκτηση του ID τραγουδιού γίνεται μέσω του [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), όπως φαίνεται παρακάτω:

<p><img src="https://cdn.acedata.cloud/r3ux6z.png" width="500" className="m-auto" /></p>

## Ασύγχρονη επανάκληση

Επειδή ο χρόνος δημιουργίας του Producer Audios Generation API ενδέχεται μερικές φορές να είναι σχετικά μεγάλος, αν το API δεν αποκρίνεται για μεγάλο χρονικό διάστημα, το HTTP αίτημα θα διατηρεί συνεχώς τη σύνδεση, με αποτέλεσμα πρόσθετη κατανάλωση πόρων του συστήματος, επομένως αυτό το API παρέχει επίσης υποστήριξη για ασύγχρονες επανακλήσεις.

Η συνολική ροή είναι: όταν ο πελάτης υποβάλλει ένα αίτημα, καθορίζει επιπλέον ένα πεδίο `callback_url`, αφού ο πελάτης υποβάλει το API αίτημα, το API θα επιστρέψει αμέσως ένα αποτέλεσμα, το οποίο περιλαμβάνει πληροφορίες πεδίου `task_id`, που αντιπροσωπεύει το τρέχον ID εργασίας. Όταν ολοκληρωθεί η εργασία, το αποτέλεσμα της εργασίας δημιουργίας θα σταλεί με τη μορφή POST JSON στο `callback_url` που καθορίζει ο πελάτης, το οποίο επίσης περιλαμβάνει το πεδίο `task_id`, ώστε το αποτέλεσμα της εργασίας να μπορεί να συσχετιστεί μέσω του ID.

Παρακάτω θα κατανοήσουμε μέσω ενός παραδείγματος πώς ακριβώς γίνεται η λειτουργία.

Αρχικά, η επανάκληση Webhook είναι μια υπηρεσία που μπορεί να λαμβάνει HTTP αιτήματα, και ο προγραμματιστής θα πρέπει να την αντικαταστήσει με το URL του HTTP διακομιστή που έχει δημιουργήσει ο ίδιος. Εδώ, για ευκολία επίδειξης, χρησιμοποιείται ένας δημόσιος ιστότοπος παραδείγματος Webhook [https://webhook.site/](https://webhook.site/), ανοίγοντας αυτόν τον ιστότοπο μπορείτε να λάβετε ένα Webhook URL, όπως φαίνεται στην εικόνα:

![](https://cdn.acedata.cloud/tbcnai.png)

Αντιγράψτε αυτό το URL και μπορεί να χρησιμοποιηθεί ως Webhook, το παράδειγμα εδώ είναι [https://webhook.site/#!/view/0d73431d-f833-4be4-9276-b6e1690d55c1](https://webhook.site/#!/view/0d73431d-f833-4be4-9276-b6e1690d55c1).

Στη συνέχεια, μπορούμε να ορίσουμε το πεδίο `callback_url` στο παραπάνω Webhook URL, ενώ ταυτόχρονα να συμπληρώσουμε τις αντίστοιχες παραμέτρους, το συγκεκριμένο περιεχόμενο φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/wuzd4y.png" width="500" className="m-auto" /></p>

  "task_id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad"

## Χειρισμός σφαλμάτων

Κατά την κλήση του API, εάν προκύψει κάποιο σφάλμα, το API θα επιστρέψει τον αντίστοιχο κωδικό και μήνυμα σφάλματος. Για παράδειγμα:

- `400 token_mismatched`：Μη έγκυρο αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`：Μη έγκυρο αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`：Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διακριτικό εξουσιοδότησης.
- `429 too_many_requests`：Πάρα πολλά αιτήματα, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`：Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.
