GLM (Γενικό Γλωσσικό Μοντέλο) είναι η νέα γενιά σειράς μεγάλων γλωσσικών μοντέλων που κυκλοφόρησε η Zhipu AI (Zhipu AI / Z.ai), διαθέτοντας ισχυρές ικανότητες κατανόησης και παραγωγής σε κινέζικα και αγγλικά, με εξαιρετική απόδοση σε καθήκοντα όπως η κινέζικη σκηνή, η παραγωγή κώδικα, η λογική και οι πολυδιάστατες συνομιλίες. Τα νέα μοντέλα GLM-5.3, GLM-5.2, GLM-4.7 κ.λπ. έχουν υποστεί πολλές βελτιώσεις σε μακροχρόνιο πλαίσιο, κλήσεις εργαλείων και καθήκοντα κώδικα, και μπορούν να εφαρμοστούν ευρέως σε έξυπνες ερωτήσεις και απαντήσεις, δημιουργία περιεχομένου, υποστήριξη κώδικα, ρομπότ εξυπηρέτησης πελατών κ.λπ.

Αυτό το έγγραφο περιγράφει κυρίως τη διαδικασία χρήσης του GLM Chat Completion API, επιτρέποντάς σας να καλείτε εύκολα τα μοντέλα GLM μέσω μιας ενιαίας συμβατής διεπαφής OpenAI.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το GLM Chat Completion API, πρώτα πηγαίνετε στο [Ace Data Cloud Console](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας, το οποίο θα κρατήσετε για μελλοντική χρήση.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης που σας προσκαλεί να εγγραφείτε και να συνδεθείτε, και μετά θα επιστρέψετε αυτόματα στη σελίδα.

**Ένα API Token αρκεί για να καλέσετε όλες τις υπηρεσίες της πλατφόρμας, χωρίς να χρειάζεται να κάνετε ξεχωριστές αιτήσεις για κάθε υπηρεσία.** Η πρώτη αίτηση θα σας δώσει δωρεάν πιστώσεις για να δοκιμάσετε δωρεάν. Όταν οι πιστώσεις σας εξαντληθούν, μπορείτε να ανανεώσετε το γενικό υπόλοιπο στο [Console](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [GLM Chat Completion API →](https://platform.acedata.cloud/documents/glm-chat-completions)

## Βασική Χρήση

Η διεύθυνση αίτησης του GLM Chat Completion API είναι `https://api.acedata.cloud/glm/chat/completions`, χρησιμοποιώντας έλεγχο ταυτότητας Bearer Token, το σώμα της αίτησης είναι συμβατό με το πρωτόκολλο OpenAI Chat Completions.

Κατά την πρώτη χρήση αυτής της διεπαφής, πρέπει τουλάχιστον να συμπληρώσουμε τρία περιεχόμενα:

- `authorization`: επιλέξτε απευθείας το Bearer Token από την αναπτυσσόμενη λίστα.
- `model`: επιλέξτε το GLM μοντέλο που θέλετε να καλέσετε, τα υποστηριζόμενα μοντέλα περιλαμβάνουν:
  - `glm-5.3`: το πιο πρόσφατο ναυαρχίδα μοντέλο, υποστηρίζει 1M πλαίσιο και μέγιστη έξοδο 128K, κατάλληλο για πολύπλοκες λογικές, κώδικα και καθήκοντα Agent. Η λογική είναι πάντα ενεργοποιημένη, μπορείτε να επιλέξετε `reasoning_effort` ως `low`, `high` ή `max`.
  - `glm-5.2`: το προηγούμενο ναυαρχίδα μοντέλο, με ισχυρές συνολικές ικανότητες.
  - `glm-5.1`: ώριμο ναυαρχίδα μοντέλο, κατάλληλο για γενικά πολύπλοκα καθήκοντα.
  - `glm-4.7`: εξαιρετική απόδοση σε λογική, κλήσεις εργαλείων και καθήκοντα κώδικα.
  - `glm-4.6`: γενικό μοντέλο συνομιλίας, ισορροπεί την απόδοση και το κόστος.
  - `glm-3-turbo`: κλασικό μοντέλο συνομιλίας, κατάλληλο για γενικά καθήκοντα παραγωγής κειμένου.
- `messages`: πίνακας προτροπών, κάθε μήνυμα περιλαμβάνει `role` και `content`, το `role` υποστηρίζει τρεις ρόλους: `user`, `assistant`, `system`.

Συνηθισμένες προαιρετικές παράμετροι:

- `max_tokens`: περιορίζει τον μέγιστο αριθμό tokens σε μία απάντηση.
- `temperature`: τυχαιότητα παραγωγής, μεταξύ 0-2, όσο μεγαλύτερη η τιμή, τόσο πιο διασκορπισμένη είναι η παραγωγή.
- `top_p`: παράμετρος πυρήνα δειγματοληψίας, ελέγχει το σωρευτικό όριο πιθανότητας των υποψηφίων tokens.
- `n`: πόσες υποψήφιες απαντήσεις θα παραχθούν ταυτόχρονα.
- `stream`: αν θα ενεργοποιηθεί η ροή απάντησης, προεπιλογή `false`.
- `stop`: προσαρμοσμένη ακολουθία διακοπής.

Ακολουθεί ένα απλό παράδειγμα κλήσης σε Python:

```python
import requests

url = "https://api.acedata.cloud/glm/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "glm-5.2",
    "messages": [
        {"role": "user", "content": "hello"}
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Μετά την κλήση, διαπιστώνουμε ότι το αποτέλεσμα επιστροφής είναι το εξής:

```json
{
  "id": "msg_202604262252030313862701a04e33",
  "model": "glm-5.2",
  "object": "chat.completion",
  "created": 1777215124,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! 👋 How can I assist you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 10,
    "completion_tokens": 23,
    "total_tokens": 33
  }
}
```

Η περιγραφή των κύριων πεδίων του αποτελέσματος επιστροφής είναι ως εξής:

- `id`: το μοναδικό ID της τρέχουσας συνομιλίας.
- `created`: η ώρα δημιουργίας της τρέχουσας συνομιλίας (Unix timestamp, δευτερόλεπτα).
- `model`: το όνομα του GLM μοντέλου που κλήθηκε.
- `choices`: η λίστα των απαντήσεων που παράγει το μοντέλο. `choices[i].message.content` είναι το συγκεκριμένο κείμενο της απάντησης του μοντέλου, το `finish_reason` υποδεικνύει τον λόγο ολοκλήρωσης (stop, length, tool_calls, content_filter κ.λπ.).
- `usage`: στατιστικά χρήσης tokens για την τρέχουσα αίτηση, περιλαμβάνει `prompt_tokens`, `completion_tokens`, `total_tokens`.

## Ροή Απάντησης

Αυτή η διεπαφή υποστηρίζει ροή απάντησης (Server-Sent Events), κάτι που είναι πολύ χρήσιμο για την ενσωμάτωσή της σε ιστοσελίδες, επιτρέποντας την εμφάνιση των απαντήσεων λέξη προς λέξη.

Εάν θέλετε να επιστρέψετε την απάντηση σε ροή, απλά ρυθμίστε την παράμετρο `stream` στο σώμα της αίτησης σε `true`.

Κώδικας παραδείγματος κλήσης σε Python:

```python
import requests

url = "https://api.acedata.cloud/glm/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "glm-4.7",
    "messages": [{"role": "user", "content": "hi"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers, stream=True)
for line in response.iter_lines():
    if line:
        print(line.decode("utf-8"))
```

Το αποτέλεσμα είναι το εξής (αποσπασματικά):
```text
data: {"id": "msg_2026042622521271f765bbc3734ce1", "object": "chat.completion.chunk", "created": 1777215133, "model": "glm-4.7", "choices": [{"delta": {"content": "", "role": "assistant"}, "finish_reason": null, "index": 0}], "usage": null}

data: {"id": "msg_2026042622521271f765bbc3734ce1", "object": "chat.completion.chunk", "created": 1777215133, "model": "glm-4.7", "choices": [{"delta": {"content": "Γειά σου! Υπάρχει κάτι που μπορώ να"}, "finish_reason": null, "index": 0}], "usage": null}

data: {"id": "msg_2026042622521271f765bbc3734ce1", "object": "chat.completion.chunk", "created": 1777215133, "model": "glm-4.7", "choices": [{"delta": {"content": "βοηθήσω"}, "finish_reason": null, "index": 0}], "usage": null}

data: {"id": "msg_2026042622521271f765bbc3734ce1", "object": "chat.completion.chunk", "created": 1777215133, "model": "glm-4.7", "choices": [{"delta": {"content": "με;"},"finish_reason": null, "index": 0}], "usage": null}

data: {"id": "msg_2026042622521271f765bbc3734ce1", "object": "chat.completion.chunk", "created": 1777215133, "model": "glm-4.7", "choices": [{"delta": {}, "finish_reason": "stop", "index": 0}], "usage": null}

data: {"id": "msg_2026042622521271f765bbc3734ce1", "object": "chat.completion.chunk", "created": 1777215133, "model": "glm-4.7", "choices": [], "usage": {"prompt_tokens": 1420, "completion_tokens": 18, "total_tokens": 1438}}

```

Μπορείτε να δείτε ότι η απάντηση περιέχει πολλές `data`, κάθε `data` περιέχει ένα κομμάτι αύξησης. Το `choices[i].delta.content` είναι το τρέχον κομμάτι κειμένου που προστέθηκε, μπορείτε να συνδυάσετε αυτά τα κομμάτια για να σχηματίσετε μια πλήρη απάντηση. Όταν το περιεχόμενο της `data` είναι `[DONE]`, σημαίνει ότι η ροή της απάντησης έχει τελειώσει. Η τελευταία γραμμή με `usage` θα συνοψίσει τη χρήση των tokens για αυτήν την αίτηση.

Παράδειγμα JavaScript (Node.js):

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "glm-4.7",
    messages: [{ role: "user", content: "hi" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/glm/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Παράδειγμα κώδικα Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "glm-4.7");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "hi")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/glm/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Άλλες γλώσσες μπορούν να τροποποιηθούν ανάλογα, η αρχή είναι η ίδια.

## Πολυδιάστατος διάλογος

Εάν θέλετε να υλοποιήσετε τη λειτουργία πολυδιάστατου διαλόγου, πρέπει να τοποθετήσετε τις ιστορικές συνομιλίες διαδοχικά στον πίνακα `messages`, διατηρώντας τη σειρά εναλλαγής μεταξύ `user` και `assistant`.

Παράδειγμα κώδικα κλήσης Python:

```python
import requests

url = "https://api.acedata.cloud/glm/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "glm-4.7",
    "messages": [
        {"role": "user", "content": "Γειά σου"},
        {"role": "assistant", "content": "Γειά σου! Πώς μπορώ να σε βοηθήσω σήμερα;"},
        {"role": "user", "content": "Τι είπα μόλις τώρα;"}
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Ανεβάζοντας πολλές ερωτήσεις, μπορείτε εύκολα να επιτύχετε πολυδιάστατο διάλογο και να λάβετε την εξής απάντηση:

```json
{
  "id": "msg_20260426225208b95324e9945a48d3",
  "model": "glm-4.7",
  "object": "chat.completion",
  "created": 1777215128,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Είπες: **\"Γειά σου\"** 😊\n\nΕνημέρωσέ με αν χρειάζεσαι κάτι άλλο!"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 48,
    "completion_tokens": 37,
    "total_tokens": 85
  }
}
```

Μπορείτε να δείτε ότι οι πληροφορίες που περιέχονται στο `choices` είναι συνεπείς με τη βασική χρήση, το μοντέλο παρέχει απάντηση με βάση την πλήρη ιστορία συνομιλίας, υποστηρίζοντας έτσι την πολυδιάστατη αλληλεπίδραση.

## Σύστημα προτροπής (System Prompt)

Μπορείτε να προσθέσετε ένα μήνυμα με `role` ως `system` στην αρχή του `messages`, για να περιορίσετε το ρόλο, το στυλ ή τη συμπεριφορά του μοντέλου:

```python
payload = {
    "model": "glm-4.7",
    "messages": [
        {"role": "system", "content": "Είσαι ένας έμπειρος βοηθός συγγραφής στα ελληνικά, παρακαλώ απάντησε με συνοπτικό και επαγγελματικό τόνο."},
        {"role": "user", "content": "Παρακαλώ παρουσίασε το μοντέλο GLM σε τρεις προτάσεις."}
    ]
}
```

## Κλήση εργαλείων (Function Calling)

Το μοντέλο GLM υποστηρίζει κλήσεις εργαλείων συμβατές με το OpenAI, μπορείτε να δηλώσετε τις κλήσεις που είναι διαθέσιμες μέσω της παραμέτρου `tools`, το μοντέλο θα επιστρέψει δομημένες πληροφορίες κλήσης εργαλείων στο `choices[i].message.tool_calls` όταν χρειάζεται.

```python
payload = {
    "model": "glm-4.7",
    "messages": [
        {"role": "user", "content": "Πώς είναι ο καιρός σήμερα στο Πεκίνο;"}
    ],
    "tools": [
        {
            "type": "function",
            "function": {
                "name": "get_weather",
                "description": "Ελέγξτε τον καιρό σε συγκεκριμένη πόλη",
                "parameters": {
                    "type": "object",
                    "properties": {
                        "city": {"type": "string", "description": "Όνομα πόλης"}
                    },
                    "required": ["city"]
                }
            }
        }
    ]
}
```

Εάν το μοντέλο αποφασίσει να καλέσει ένα εργαλείο, ο λόγος ολοκλήρωσης θα αλλάξει σε `tool_calls`, και θα δώσει το όνομα της συνάρτησης και τις παραμέτρους σε μορφή JSON στο `message.tool_calls`. Μπορείτε να εκτελέσετε αυτή τη συνάρτηση και να επιστρέψετε το αποτέλεσμα ως μήνυμα με `role` ως `tool` στο μοντέλο, ολοκληρώνοντας έτσι τον κύκλο κλήσης εργαλείων.

## Συστάσεις επιλογής μοντέλου
```
| Μοντέλο         | Εφαρμοσμένα σενάρια                               |
| ------------- | -------------------------------------------- |
| `glm-5.3`     | Νέα ναυαρχίδα, 1M συμφραζόμενα, μέγιστη έξοδος 128K, συνιστάται για πολύπλοκες λογικές, κώδικα και καθήκοντα Agent |
| `glm-5.2`     | Προηγούμενη ναυαρχίδα, κατάλληλη για πολύπλοκες λογικές, κώδικα και καθήκοντα Agent                    |
| `glm-5.1`     | Ωριμασμένη ναυαρχίδα, κατάλληλη για πολύπλοκες λογικές, ανάλυση μεγάλων εγγράφων                            |
| `glm-4.7`     | Κλήσεις εργαλείων, δημιουργία κώδικα, συντονισμός Agent και άλλα καθήκοντα                        |
| `glm-4.6`     | Ισορροπημένη επιλογή για γενικές συνομιλίες και δημιουργία περιεχομένου                               |
| `glm-3-turbo` | Γενικά καθήκοντα δημιουργίας κειμένου, σε σενάρια ευαίσθητα στο κόστος                            |

## Διαχείριση σφαλμάτων

Κατά την κλήση του API, εάν προκύψει σφάλμα, το API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`: Λείπουν ή είναι άκυρες παράμετροι αιτήματος.
- `400 api_not_implemented`: Χρησιμοποιήθηκαν παράμετροι ή μοντέλο που δεν υποστηρίζονται.
- `401 invalid_token`: Μη εξουσιοδοτημένο, λείπει ή έχει λήξει το Bearer Token.
- `429 too_many_requests`: Ενεργοποιήθηκε περιορισμός συχνότητας, παρακαλώ δοκιμάστε ξανά αργότερα.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή ή προσωρινά μη διαθέσιμο upstream.

### Παράδειγμα απόκρισης σφάλματος

```json
&#123;
  "trace_id": "69ea9bcf-c5da-41a3-be97-c80912a08523",
  "error": &#123;
    "code": "api_error",
    "message": "Η υπηρεσία είναι προσωρινά μη διαθέσιμη, παρακαλώ δοκιμάστε ξανά αργότερα."
  &#125;
&#125;
```

Όταν επιστρέφεται `api_error` και το μήνυμα είναι `Η υπηρεσία είναι προσωρινά μη διαθέσιμη, παρακαλώ δοκιμάστε ξανά αργότερα.`, συνήθως σημαίνει ότι η υπηρεσία GLM upstream είναι προσωρινά μη διαθέσιμη, συνιστάται να δοκιμάσετε ξανά με εκθετική καθυστέρηση ή να αλλάξετε σε άλλο διαθέσιμο μοντέλο GLM (π.χ. από `glm-5.1` προσωρινά σε `glm-4.7` ή `glm-4.6`).
