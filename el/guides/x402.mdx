x402 είναι ένα πρωτόκολλο πληρωμών σε blockchain βασισμένο στο πρότυπο HTTP 402 Payment Required, που επιτρέπει στον καλούντα να ολοκληρώσει την πληρωμή στο blockchain ταυτόχρονα με την εκκίνηση του API request, ιδανικό για σενάρια χρέωσης ανά κλήση μεταξύ αυτοματοποιημένων προγραμμάτων, AI Agents και μικροϋπηρεσιών. Μέσω αυτού του οδηγού, μπορείτε να ολοκληρώσετε προγραμματισμένα τις πληρωμές παραγγελιών AceDataCloud στο σύστημά σας, επιτυγχάνοντας την εμπειρία «αίτημα και πληρωμή».

Επίσημες πληροφορίες αναφοράς:

- Έγγραφο επισκόπησης x402: [https://docs.cdp.coinbase.com/x402/docs/overview](https://docs.cdp.coinbase.com/x402/docs/overview)
- Ανοιχτό παράδειγμα x402: [https://github.com/coinbase/x402](https://github.com/coinbase/x402)

Αυτό το έγγραφο απευθύνεται σε προγραμματιστές που χρειάζονται να ενσωματώσουν τη δυνατότητα πληρωμών x402 της πλατφόρμας AceDataCloud στην επιχείρησή τους, περιγράφοντας τη διαδικασία από την προετοιμασία του περιβάλλοντος έως την ολοκλήρωση της κλήσης πληρωμής, και παρέχοντας παραδείγματα κώδικα για Axios, Fetch, Python requests και httpx. Κύρια σημεία:

- Η πληρωμή ολοκληρώνεται στο **Base Mainnet**, με χρήση **USDC**;
- Πρέπει να χρησιμοποιηθεί το **EVM ιδιωτικό κλειδί** του πορτοφολιού που κατέχει τα νομίσματα για τη δημιουργία του υπογραφικού κεφαλίδας `X-PAYMENT`;
- Όλα τα API βρίσκονται κάτω από το domain `https://platform.acedata.cloud`, η κεφαλίδα `Authorization` πρέπει να περιλαμβάνει το **Platform Token**.

## Ι. Προετοιμασία

### 1. Δείτε την παραγγελία και καταγράψτε τις πληροφορίες πληρωμής

Συνδεθείτε στην κονσόλα [https://platform.acedata.cloud](https://platform.acedata.cloud), στη λίστα παραγγελιών ή στη σελίδα λεπτομερειών παραγγελίας μπορείτε να δείτε τις παραγγελίες που χρειάζονται πληρωμή. Οι λεπτομέρειες της παραγγελίας θα εμφανίσουν:

- ID παραγγελίας (π.χ. `7744945e-5e77-4dcc-a9c4-528692d17b34`);
- Διεύθυνση πληρωμής `pay_to` (θα επιστραφεί επίσης στην απάντηση 402, προτείνεται να βασιστείτε στις πληροφορίες της σελίδας).

Παρακαλώ καταγράψτε το ID παραγγελίας και επιβεβαιώστε τη διεύθυνση `pay_to`, καθώς θα χρειαστεί για την υπογραφή αργότερα.

### 2. Προετοιμάστε το πορτοφόλι πληρωμής και τα κεφάλαια

- Προετοιμάστε ένα πορτοφόλι EVM που υποστηρίζει το Base Mainnet και εξάγετε το ιδιωτικό κλειδί που θα χρησιμοποιηθεί;
- Κάντε κατάθεση επαρκούς ποσού **USDC** στο Base Mainnet (η μονάδα πληρωμής είναι η ελάχιστη μονάδα 6 δεκαδικών);
- Ο x402 Facilitator θα καλύψει τα τέλη δικτύου, το πορτοφόλι πληρωμής χρειάζεται μόνο να διατηρεί επαρκή USDC;
- Το ιδιωτικό κλειδί χρησιμοποιείται μόνο για τοπική υπογραφή, παρακαλώ φυλάξτε το με ασφάλεια, αποφεύγοντας την έκθεση σε πρόγραμμα περιήγησης ή αναξιόπιστο περιβάλλον.

### 3. Δημιουργία Platform Token

Το Platform Token χρησιμοποιείται για την κλήση του API της πλατφόρμας, παρόμοιο με τη λειτουργία του Token χρήστη που χρησιμοποιείται στο πρόγραμμα περιήγησης μετά την είσοδο, αλλά δεν λήγει. Ακολουθήστε τα παρακάτω βήματα για να το δημιουργήσετε:

1. Ανοίξτε τη σελίδα κονσόλας [https://platform.acedata.cloud/console/platform-tokens](https://platform.acedata.cloud/console/platform-tokens);
2. Κάντε κλικ στο «Δημιουργία Token», συμπληρώστε τις πληροφορίες σημειώσεων σύμφωνα με τις οδηγίες και δημιουργήστε το;
3. Αντιγράψτε το παραγόμενο Token (π.χ. `platform-v1-xxxx`), φυλάξτε το ως `platform_token`.

![platform-token](https://cdn.acedata.cloud/6g86oz.png)

Σε όλες τις μελλοντικές κλήσεις API, η κεφαλίδα πρέπει να περιλαμβάνει:

```
Authorization: Bearer {platform_token}
```

### 4. Αίτηση βασικών πληροφοριών

- Βασικό domain API: `https://platform.acedata.cloud`
- Διαδρομή αιτήματος πληρωμής: `/api/v1/orders/{order_id}/pay/`
- Το αίτημα και η απάντηση χρησιμοποιούν JSON, κωδικοποιημένο σε UTF-8.

## ΙΙ. Επισκόπηση διαδικασίας πληρωμής

1. **Εκκίνηση αιτήματος πληρωμής**: Πρώτη `POST` αίτηση χωρίς κεφαλίδα `X-PAYMENT`, ενεργοποιεί την πλατφόρμα να επιστρέψει 402 Payment Required;
2. **Ανάγνωση απαιτήσεων πληρωμής**: Αναλύστε τον πίνακα `accepts` στην απάντηση 402, επιβεβαιώστε ότι το `network` είναι `base`, το `asset` είναι USDC, το `payTo` είναι το ίδιο με τη σελίδα παραγγελίας;
3. **Δημιουργία `X-PAYMENT`**: Χρησιμοποιήστε το ιδιωτικό κλειδί του πορτοφολιού πληρωμής, τις απαιτήσεις από το σώμα της απάντησης, τις πληροφορίες EIP-712 που επιστρέφει ο Facilitator κ.λπ. για να δημιουργήσετε την υπογραφή (συνήθως με τη βοήθεια του επίσημου SDK);
4. **Επαναλαμβανόμενη αίτηση με υπογραφή**: Προσθέστε την κεφαλίδα `X-PAYMENT` στην αίτηση της ίδιας διαδρομής, η πλατφόρμα θα επιστρέψει 200 μετά την επιτυχία της επαλήθευσης;
5. **Ανάλυση αποτελέσματος**: Διαβάστε την κεφαλίδα απάντησης `X-PAYMENT-RESPONSE`, μπορείτε να αποκτήσετε το hash της συναλλαγής στο blockchain, το πραγματικό ποσό χρέωσης κ.λπ. για τη συμφωνία.

## ΙΙΙ. Παράδειγμα αλληλεπίδρασης

### 1. Πρώτη αίτηση (ενεργοποίηση 402)

```http
POST https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/
Authorization: Bearer {platform_token}
Content-Type: application/json

{
  "pay_way": "X402"
}
```

Τυπική απάντηση 402 (η σειρά των πεδίων μπορεί να διαφέρει ελαφρώς):

```json
{
  "error": "Payment required for this order.",
  "accepts": [
    {
      "scheme": "exact",
      "network": "base",
      "asset": "0x833589fcd6edb6e08f4c7c32d4f71b54b268aa0e",
      "maxAmountRequired": "1250000",
      "payTo": "0x302afdd980aaefca3afa8df7222a6002774f6724",
      "extra": {
        "eip712": { "...": "..." }
      }
    }
  ],
  "paywall": { ... }
}
```

Επεξήγηση κρίσιμων πεδίων:

- `network`: Πρέπει να είναι `base` (Base Mainnet);
- `asset`: Διεύθυνση συμβολαίου Base USDC (παράδειγμα η επίσημη διεύθυνση συμβολαίου του mainnet);
- `maxAmountRequired`: Η απαιτούμενη μονάδα USDC για αυτή την πληρωμή (1 USDC = 1,000,000 ατομικές μονάδες);
- `payTo`: Διεύθυνση πληρωμής της πλατφόρμας, πρέπει να είναι ίδια με τη σελίδα λεπτομερειών παραγγελίας;
- `extra`: Πληροφορίες EIP-712 που απαιτούνται για την υπογραφή κ.λπ.

### 2. Δημιουργία `X-PAYMENT`

Συνηθισμένη πρακτική είναι η χρήση του επίσημου SDK (όπως `x402-js`, `x402-fetch`, `x402.clients` κ.λπ.):

1. Μετατρέψτε το ιδιωτικό κλειδί του πορτοφολιού πληρωμής σε αντικείμενο λογαριασμού;
2. Καταγράψτε τα δεδομένα `accepts` από την απάντηση 402, επιλέξτε την επιλογή πληρωμής όπου `network == "base"`;
3. Καλέστε τη συνάρτηση υπογραφής που παρέχει το SDK για να δημιουργήσετε τη συμβολοσειρά `X-PAYMENT` κωδικοποιημένη σε Base64 (δεν απαιτείται άμεση σύνδεση του πελάτη με τον facilitator; η πλατφόρμα θα αναλάβει την κλήση του facilitator για να ολοκληρώσει την επαλήθευση/ρύθμιση);
4. Συνιστάται να ελέγξετε αν το `maxAmountRequired` είναι εντός αποδεκτού εύρους, αν υπερβαίνει, να ενημερώσετε τον χρήστη να καταθέσει.

Αν χρειαστεί να το υλοποιήσετε χειροκίνητα, ανατρέξτε στην επίσημη τεκμηρίωση x402, κατασκευάστε τη δομή EIP-712 σύμφωνα με τις πληροφορίες πεδίου που παρέχονται στο `extra.eip712` και στη συνέχεια υπογράψτε.

### 3. Επαναλαμβανόμενη αίτηση με υπογραφή

```http
POST https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/
Authorization: Bearer {platform_token}
Content-Type: application/json
X-PAYMENT: {base64_signed_payload}

{
  "pay_way": "X402"
}
```

Εάν η πληρωμή είναι επιτυχής, η κατάσταση απάντησης είναι 200, το σώμα της απάντησης επιστρέφει τις ενημερωμένες πληροφορίες παραγγελίας και περιλαμβάνει:

```
X-PAYMENT-RESPONSE: eyJ0cmFuc2FjdGlvbiI6IjB4...==
```

Η `X-PAYMENT-RESPONSE` μπορεί να χρησιμοποιηθεί με τη συνάρτηση αποκωδικοποίησης του SDK για να αποκτήσετε το hash της συναλλαγής στο blockchain, το δίκτυο πληρωμής, τη διεύθυνση του πληρωτή κ.λπ., για την καταχώριση ή την εμφάνιση στην επιχείρηση.

## IV. Πολυγλωσσικά παραδείγματα κώδικα

Τα παρακάτω παραδείγματα υποθέτουν ότι οι μεταβλητές περιβάλλοντος ή τα αρχεία ρυθμίσεων έχουν εισαχθεί:
- `ACE_PLATFORM_TOKEN`：Token Πλατφόρμας；
- `ACE_X402_ORDER_ID`：ID Παραγγελίας；
- `ACE_X402_PRIVATE_KEY`：Ιδιωτικό κλειδί πορτοφολιού πληρωμής (με πρόθεμα `0x`).

### 1. Axios（TypeScript）

```ts
import axios from "axios";
import { Hex } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { buildPaymentHeader, decodePaymentResponse } from "x402-js";

const baseURL = "https://platform.acedata.cloud";
const orderId = process.env.ACE_X402_ORDER_ID!;
const platformToken = process.env.ACE_PLATFORM_TOKEN!;
const privateKey = process.env.ACE_X402_PRIVATE_KEY as Hex;

const account = privateKeyToAccount(privateKey);
const api = axios.create({
  baseURL,
  headers: {
    Authorization: `Bearer ${platformToken}`,
    "Content-Type": "application/json",
  },
});

async function payOrder() {
  const payPath = `/api/v1/orders/${orderId}/pay/`;

  const initial = await api.post(
    payPath,
    { pay_way: "X402" },
    { validateStatus: () => true }
  );
  if (initial.status !== 402) {
    throw new Error(`unexpected status ${initial.status}`);
  }

  const requirement = initial.data.accepts.find(
    (item: any) => item.network === "base"
  );
  if (!requirement) {
    throw new Error("no base requirement returned");
  }

  const paymentHeader = await buildPaymentHeader({
    account,
    requirement,
  });

  const final = await api.post(
    payPath,
    { pay_way: "X402" },
    { headers: { "X-PAYMENT": paymentHeader } }
  );

  if (final.status >= 400) {
    throw new Error(`x402 payment failed: ${final.status} ${final.statusText}`);
  }
  const receipt = decodePaymentResponse(final.headers["x-payment-response"]);
  console.log("x402 receipt", receipt);
}

payOrder().catch(console.error);
```

### 2. Fetch（JavaScript）

```ts
import { wrapFetchWithPayment, decodePaymentResponse } from "x402-fetch";
import { privateKeyToAccount } from "viem/accounts";

const account = privateKeyToAccount(process.env.ACE_X402_PRIVATE_KEY!);
const platformToken = process.env.ACE_PLATFORM_TOKEN!;
const orderId = process.env.ACE_X402_ORDER_ID!;
const fetchWithPayment = wrapFetchWithPayment(fetch, account);

async function payOrder() {
  const url = `https://platform.acedata.cloud/api/v1/orders/${orderId}/pay/`;

  const response = await fetchWithPayment(url, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${platformToken}`,
    },
    body: JSON.stringify({ pay_way: "X402" }),
  });

  if (!response.ok) {
    const errorBody = await response.text();
    throw new Error(`x402 payment failed: ${response.status} ${errorBody}`);
  }

  const receipt = decodePaymentResponse(
    response.headers.get("x-payment-response")!
  );
  console.log("x402 receipt", receipt);
}

payOrder().catch(console.error);
```

### 3. Python requests

```python
import os
from eth_account import Account
from x402.clients.requests import x402_requests
from x402.clients.base import decode_x_payment_response

order_id = os.environ["ACE_X402_ORDER_ID"]
platform_token = os.environ["ACE_PLATFORM_TOKEN"]
account = Account.from_key(os.environ["ACE_X402_PRIVATE_KEY"])

session = x402_requests(
    account,
    payment_requirements_selector=lambda accepts, **_: next(
        req for req in accepts if req.network == "base" and req.scheme == "exact"
    ),
)

response = session.post(
    f"https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/",
    json={"pay_way": "X402"},
    headers={"Authorization": f"Bearer {platform_token}"},
)

response.raise_for_status()
receipt_header = response.headers.get("X-PAYMENT-RESPONSE")
if receipt_header:
    print("x402 receipt:", decode_x_payment_response(receipt_header))
```

### 4. Python httpx（异步）

```python
import asyncio
import os
from eth_account import Account
from x402.clients.httpx import x402HttpxClient
from x402.clients.base import decode_x_payment_response

async def pay_order() -> None:
    order_id = os.environ["ACE_X402_ORDER_ID"]
    platform_token = os.environ["ACE_PLATFORM_TOKEN"]
    account = Account.from_key(os.environ["ACE_X402_PRIVATE_KEY"])

    async with x402HttpxClient(
        account=account,
        base_url="https://platform.acedata.cloud",
        headers={"Authorization": f"Bearer {platform_token}"},
        payment_requirements_selector=lambda accepts, **_: next(
            req for req in accepts if req.network == "base"
        ),
    ) as client:
        response = await client.post(
            f"/api/v1/orders/{order_id}/pay/",
            json={"pay_way": "X402"},
        )
        response.raise_for_status()
        receipt_header = response.headers.get("X-PAYMENT-RESPONSE")
        if receipt_header:
            print("x402 receipt:", decode_x_payment_response(receipt_header))

asyncio.run(pay_order())
```

> Το παράδειγμα δείχνει μόνο τις βασικές κλήσεις, στο παραγωγικό περιβάλλον παρακαλείστε να προσθέσετε χειρισμό εξαιρέσεων, στρατηγικές επαναλήψεων, καταγραφή και έλεγχο ασφαλείας.

## Πέντε, επιβεβαίωση μετά την επιτυχία πληρωμής

- **Επιβεβαίωση κονσόλας**: Επισκεφθείτε τη σελίδα λεπτομερειών παραγγελίας `https://platform.acedata.cloud/console/orders/{order_id}`, αν η σελίδα δείχνει «Πληρωμή επιτυχής» ή η κατάσταση της παραγγελίας έχει αλλάξει σε πληρωμένη/ολοκληρωμένη, αυτό σημαίνει ότι η διακανονιστική διαδικασία στην αλυσίδα έχει ολοκληρωθεί.
- **Επιβεβαίωση API**: Καλέστε `GET https://platform.acedata.cloud/api/v1/orders/{order_id}/` και φέρτε το `Authorization: Bearer {platform_token}`, ελέγξτε το πεδίο `state` στην απόκριση (το `PAID` ή `FINISHED` υποδηλώνει επιτυχία πληρωμής).
- **Επιστροφή κεφαλίδας**: Διαβάστε το `X-PAYMENT-RESPONSE` στην απόκριση της επιτυχούς πληρωμής, μπορείτε να αποκωδικοποιήσετε το hash της συναλλαγής στην αλυσίδα ως τελικό αποδεικτικό στοιχείο; προτείνεται να αποθηκεύσετε αυτή την πληροφορία στα αρχεία καταγραφής του συστήματος για σκοπούς συμφωνίας.

## Έξι, κοινές ερωτήσεις και έλεγχοι

- **Επιστρέφει ακόμα 402**: Επιβεβαιώστε ότι η διεύθυνση πληρωμής έχει αρκετό USDC στο δίκτυο Base, ελέγξτε αν το `maxAmountRequired` υπερβαίνει το υπόλοιπο του πορτοφολιού ή το προσαρμοσμένο όριο.
- **Αποτυχία υπογραφής**: Βεβαιωθείτε ότι το ιδιωτικό κλειδί έχει πρόθεμα `0x`; κατά την υπογραφή, χρησιμοποιήστε αυστηρά το `extra` (το πεδίο EIP-712) και το `payTo` που περιλαμβάνονται στην απόκριση, μην αλλάξετε τη σειρά των πεδίων.
- **Μη συμβατό δίκτυο**: Μπορεί να υπάρχουν πολλές απαιτήσεις στο `accepts`, επιλέξτε την επιλογή `network === "base"`.
- **Λείπει το `X-PAYMENT-RESPONSE`**: Αυτό υποδηλώνει ότι η πληρωμή δεν έχει πραγματοποιηθεί, μπορείτε να επαναλάβετε την αίτηση με βάση το σφάλμα στο σώμα της απόκρισης; αν αντιμετωπίσετε συμφόρηση στην αλυσίδα, παρακαλώ δοκιμάστε ξανά αργότερα.
- **Μη έγκυρο Token πλατφόρμας**: Επιβεβαιώστε ότι το Token δεν έχει διαγραφεί και αρχίζει με το πρόθεμα `platform-v1-`; αν η διεπαφή επιστρέφει 401, μπορείτε να το αναγεννήσετε στην κονσόλα.
