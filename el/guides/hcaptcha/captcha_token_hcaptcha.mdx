Αυτό το άρθρο θα παρουσιάσει μια οδηγία σύνδεσης για το hCaptcha πρωτόκολλο αναγνώρισης API, που επιτρέπει στους χρήστες να μην χρειάζεται να αναγνωρίζουν και να επιλέγουν εικόνες captcha hCaptcha, αλλά να ολοκληρώνουν την επαλήθευση απλά υποβάλλοντας το Website Key.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το hCaptcha πρωτόκολλο αναγνώρισης API, πρώτα πηγαίνετε στο [Ace Data Cloud κονσόλα](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας, το οποίο θα κρατήσετε για μελλοντική χρήση.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης που σας προσκαλεί να εγγραφείτε και να συνδεθείτε, και μετά θα επιστρέψετε αυτόματα στη τρέχουσα σελίδα.

**Ένα API Token αρκεί για να καλέσετε όλες τις υπηρεσίες της πλατφόρμας, χωρίς να χρειάζεται να κάνετε ξεχωριστή αίτηση για κάθε υπηρεσία.** Η πρώτη αίτηση θα σας δώσει δωρεάν πιστώσεις για να δοκιμάσετε δωρεάν; όταν οι πιστώσεις εξαντληθούν, μπορείτε να ανανεώσετε το γενικό υπόλοιπο στην [κονσόλα](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [hCaptcha Πρωτόκολλο Αναγνώρισης API →](https://platform.acedata.cloud/documents/captcha-token-hcaptcha)

## Βασική Χρήση

Πρώτα πρέπει να κατανοήσετε τη βασική μέθοδο χρήσης, δηλαδή να εισάγετε το URL της ιστοσελίδας που χρειάζεται να επεξεργαστεί το hCaptcha captcha, για να λάβετε το επεξεργασμένο αποτέλεσμα. Πρώτα πρέπει να περάσετε απλά ένα πεδίο `website_url`, η δοκιμαστική μας ιστοσελίδα είναι: `https://accounts.hcaptcha.com/demo`, πρέπει να αποκτήσουμε το `website_key` από τη σελίδα `website_url`, πρώτα ανοίγουμε αυτή τη σελίδα, πατάμε F12 για να μπούμε στην κονσόλα, και τέλος κάνουμε παγκόσμια αναζήτηση στην καρτέλα Element για το `hcaptcha-demo`, μπορούμε να πάρουμε το παρακάτω αποτέλεσμα:

<p><img src="https://cdn.acedata.cloud/bmx7ik.png" width="500" className="m-auto" /></p>

Όπου η αλφαριθμητική συμβολοσειρά που αντιστοιχεί στο `data-sitekey` είναι η τιμή του `website_key`, παρακάτω είναι τα συγκεκριμένα αποτελέσματα παραμέτρων:

<p><img src="https://cdn.acedata.cloud/st6q7a.png" width="500" className="m-auto" /></p>

Μπορούμε να δούμε ότι εδώ έχουμε ρυθμίσει τα Request Headers, που περιλαμβάνουν:

- `accept`: ποια μορφή απάντησης θέλετε να λάβετε, εδώ συμπληρώνεται ως `application/json`, δηλαδή σε μορφή JSON.
- `authorization`: το κλειδί για την κλήση του API, μπορείτε να το επιλέξετε απευθείας από την αναπτυσσόμενη λίστα μετά την αίτηση.

Επιπλέον, έχουμε ρυθμίσει το Request Body, που περιλαμβάνει:

- `website_url`: το URL της ιστοσελίδας που χρειάζεται να επεξεργαστεί το captcha.
- `website_key`: ο αναγνωριστικός παράγοντας του κλειδιού της ιστοσελίδας στο hCaptcha.
- `rqdata`: προαιρετικό. Η πρόκληση hCaptcha Enterprise μπορεί να παρέχει `data-rqdata` στη σελίδα, σε περίπτωση που συναντήσετε τέτοιες προκλήσεις, συμπληρώστε την αρχική τιμή της; η κανονική hCaptcha δεν χρειάζεται να συμπληρωθεί.
- `proxy`: προαιρετικό, φέρτε τον δικό σας proxy (Bring Your Own Proxy). Αφού ρυθμιστεί, το σύστημα θα χρησιμοποιήσει τη διεύθυνση IP του proxy που παρέχετε για να αποκωδικοποιήσει το captcha, για να ελέγξει την ποιότητα της εξόδου IP (π.χ. για να αποφευχθεί η επιστροφή `410 Gone` λόγω δημόσιας IP proxy που έχει αποκλειστεί από τον στόχο). Η μορφή είναι `scheme://[user:pass@]host:port`, το `scheme` υποστηρίζει `http`/`https`/`socks4`/`socks5`, π.χ. `http://user:pass@1.2.3.4:8080`. Αν δεν συμπληρωθεί, θα χρησιμοποιηθεί ο προεπιλεγμένος proxy της πλατφόρμας.

Από την ανάλυση της παραπάνω εικόνας, το URL του POST αιτήματος είναι: `https://accounts.hcaptcha.com/demo`. Χρειάζεται μόνο να υποβάλουμε τις παραμέτρους `g-recaptcha-response`, `h-captcha-response` και `email`, και απλά να περάσουμε το επεξεργασμένο token στο πεδίο data παρακάτω. Ο αντίστοιχος κώδικας CURL για την επαλήθευση token είναι:

```shell
curl 'https://accounts.hcaptcha.com/demo' \
  --data-raw 'email=&g-recaptcha-response={token}&h-captcha-response={token}'
```

Ο αντίστοιχος κώδικας Python για την επαλήθευση token είναι:

```python
import requests

token = '{token}'

data = {
    'email': '',
    'g-recaptcha-response': token,
    'h-captcha-response': token
}

response = requests.post('https://accounts.hcaptcha.com/demo',
                        data=data)

if response.status_code == 200:
    print(response.text)

```

Επιπλέον, αν θέλετε να δημιουργήσετε τον αντίστοιχο κώδικα σύνδεσης, μπορείτε να τον αντιγράψετε απευθείας, για παράδειγμα ο κώδικας CURL είναι:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/hcaptcha' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "a5f74b19-9e45-40e0-b45d-47ff91b7a6c2",
  "website_url": "https://accounts.hcaptcha.com/demo"
}'
```

Ο κώδικας Python για τη σύνδεση είναι:

```python
import requests

url = "https://api.acedata.cloud/captcha/token/hcaptcha"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_key": "a5f74b19-9e45-40e0-b45d-47ff91b7a6c2",
    "website_url": "https://accounts.hcaptcha.com/demo"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Ασύγχρονη λειτουργία (async)

Κανονικά, το API είναι συγχρονισμένο και μπλοκάρει: ένα αίτημα περιμένει μέχρι να ολοκληρωθεί η επεξεργασία του token πριν επιστρέψει. Αν κάνετε εναλλαγή πολλών λύσεων captcha (multi-solver rotation) και θέλετε «να πάρετε αμέσως το task_id μετά την υποβολή, να προγραμματίσετε άλλους λύτες και να επιστρέψετε αργότερα για να διαβάσετε το αποτέλεσμα», μπορείτε να περάσετε `async: true` στο σώμα του αιτήματος.

Με το `async: true`, το API επιστρέφει αμέσως ένα `task_id` χωρίς να μπλοκάρει:

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

Για να ελέγξετε την πρόοδο, χρησιμοποιήστε το `task_id` για να κάνετε ερώτημα στο `POST /captcha/tasks` (συνιστάται κάθε 3~5 δευτερόλεπτα). Αυτό το endpoint δεν ενεργοποιεί ή προωθεί την επεξεργασία της εργασίας· ακόμα και αν δεν ερωτηθείτε, αποσυνδεθείτε ή κλείσετε τον πελάτη, ο διακομιστής συνεχίζει την επεξεργασία:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Κατά την επεξεργασία επιστρέφεται `status: processing`:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

Όταν ολοκληρωθεί, επιστρέφεται `status: ready` και το token:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "token": "P1_eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1Ni......"
}
```

Πληρωμή: Στην ασύγχρονη λειτουργία, η δημιουργία εργασίας και η ανάγνωση κατάστασης «σε επεξεργασία» δεν χρεώνονται· **η πρώτη επιτυχημένη ανάγνωση αποτελέσματος από τον πελάτη χρεώνεται μία φορά** (όπως και στη συγχρονισμένη λειτουργία). Ο διακομιστής προωθεί την εργασία αυτόνομα, αλλά δεν χρεώνει νωρίτερα αν ολοκληρωθεί στο παρασκήνιο. Αν η εργασία δεν ολοκληρωθεί εντός 120 δευτερολέπτων, τερματίζεται με HTTP 504 `timeout` χωρίς χρέωση. Το `/captcha/tasks` δεν προωθεί την εργασία.

## Διαχείριση σφαλμάτων

Κατά την κλήση του API, αν προκύψει σφάλμα, το API επιστρέφει τον αντίστοιχο κωδικό και μήνυμα σφάλματος. Για παράδειγμα:

- `400 token_mismatched`: Κακό αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακό αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, άκυρο ή ελλιπές token εξουσιοδότησης.
- `429 too_many_requests`: Πάρα πολλά αιτήματα, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.

### Παράδειγμα απάντησης σφάλματος

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
