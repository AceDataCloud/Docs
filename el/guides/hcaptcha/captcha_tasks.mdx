Αυτό το έγγραφο περιγράφει τη διεπαφή αναζήτησης ασύγχρονων εργασιών CAPTCHA `POST /captcha/tasks`. Όταν καλείτε οποιαδήποτε διεπαφή CAPTCHA (σειρά token ή σειρά αναγνώρισης) και εισάγετε `async: true`, η διεπαφή θα επιστρέψει αμέσως ένα `task_id`, ο διακομιστής θα αναλάβει αμέσως και θα συνεχίσει την επεξεργασία. Μπορείτε να χρησιμοποιήσετε αυτό το `task_id` για να ελέγξετε το τελικό αποτέλεσμα, αλλά η αναζήτηση δεν είναι προϋπόθεση για τη συνέχιση της εκτέλεσης της εργασίας. Είναι κατάλληλο για σενάρια εναλλαγής πολλών αναγνωριστών (multi-solver rotation): υποβάλετε την εργασία και λάβετε αμέσως το `task_id`, στη συνέχεια προγραμματίστε άλλους αναγνωριστές και επιστρέψτε αργότερα για να διαβάσετε το αποτέλεσμα.

> 📘 Πλήρης διαδραστική τεκμηρίωση (συμπεριλαμβανομένης της διαδικτυακής αποσφαλμάτωσης): [API αναζήτησης εργασιών CAPTCHA →](https://platform.acedata.cloud/documents/captcha-tasks)

## Διαδικασία αίτησης

Για να χρησιμοποιήσετε αυτή τη διεπαφή, επισκεφθείτε την [κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας, το οποίο θα κρατήσετε για μελλοντική χρήση. **Ένα API Token αρκεί για να καλέσετε όλες τις υπηρεσίες της πλατφόρμας, χωρίς να χρειάζεται να υποβάλετε αίτηση για κάθε υπηρεσία ξεχωριστά.**

## Βασική χρήση

### Πρώτο βήμα: Δημιουργία εργασίας με ασύγχρονο τρόπο

Στο σώμα του αιτήματος οποιασδήποτε διεπαφής CAPTCHA, εισάγετε `async: true`, και η διεπαφή θα επιστρέψει αμέσως το `task_id` (HTTP 201), χωρίς να μπλοκάρει την αναμονή:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

### Δεύτερο βήμα (προαιρετικό): Ερώτηση αποτελέσματος με το task_id

Αν χρειάζεται να δείτε ενεργά την πρόοδο, μπορείτε να χρησιμοποιήσετε το `task_id` που επιστράφηκε στο προηγούμενο βήμα για να ελέγξετε το `POST /captcha/tasks` (συνιστάται κάθε 3~5 δευτερόλεπτα). Αυτή η διεπαφή δεν θα ενεργοποιήσει ή θα προχωρήσει την επεξεργασία της εργασίας. Όταν διαβάζετε το έτοιμο αποτέλεσμα, ακολουθείτε τη συνήθη διαδικασία εκκαθάρισης:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Κατά την επεξεργασία θα επιστραφεί `status: processing`:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "processing"
}
```

Όταν ολοκληρωθεί η επεξεργασία, θα επιστραφεί `status: ready` και το αντίστοιχο πεδίο αποτελέσματος — η δομή των πεδίων είναι απολύτως ίδια με αυτή της συγχρονισμένης λειτουργίας:

- **σειρά token** (hcaptcha, recaptcha2, recaptcha3) επιστρέφει `token`:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "started_at": 1784885653.0,
  "finished_at": 1784885665.4,
  "elapsed": 12.4,
  "token": "03AFcWeA5kjJyDQ9S1a9UYimR6nuxnpEnAs5x2Pixao0dXZhMB......"
}
```

- **κατηγορία αναγνώρισης** (recognition/recaptcha2, recognition/hcaptcha) επιστρέφει `solution`; **recognition/image2text** επιστρέφει `text`.

`/captcha/tasks` είναι κοινό για όλες τις διεπαφές CAPTCHA (σειρές token και αναγνώρισης), μπορείτε να κάνετε polling με το ίδιο `task_id`.

Ο διακομιστής συνεχίζει την επεξεργασία από τη στιγμή της δημιουργίας, με μέγιστο χρόνο 120 δευτερόλεπτα. Αν στην τελευταία αναζήτηση πριν από την προθεσμία δεν έχετε λάβει αποτέλεσμα, θα επιστραφεί HTTP 504. Αυτή η κατάσταση είναι τελική, ο πελάτης θα πρέπει να σταματήσει το polling. Η επαναλαμβανόμενη αναζήτηση του ίδιου `task_id` θα επιστρέφει σταθερά το ίδιο αποτυχημένο αποτέλεσμα:

```json
{
  "detail": "The captcha task timed out.",
  "code": "timeout",
  "success": false,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "failed",
  "started_at": 1784885653.0,
  "finished_at": 1784885765.4,
  "elapsed": 112.4
}
```

Οι τελικές απαντήσεις `status: ready` και HTTP 504 θα περιλαμβάνουν τα πεδία χρονομέτρησης.

- `started_at`, χρόνος έναρξης επεξεργασίας της εργασίας, Unix timestamp (δευτερόλεπτα, float).
- `finished_at`, χρόνος παραγωγής αποτελέσματος της εργασίας, Unix timestamp (δευτερόλεπτα, float). Δεν επιστρέφεται αυτό το πεδίο όταν είναι σε επεξεργασία.
- `elapsed`, χρόνος επεξεργασίας της εργασίας, μονάδα σε δευτερόλεπτα (float, με 3 δεκαδικά ψηφία). Δεν επιστρέφεται αυτό το πεδίο όταν είναι σε επεξεργασία.

## Περιγραφή χρέωσης

Στη λειτουργία ασύγχρονης, η δημιουργία εργασίας και η ανάγνωση της κατάστασης «σε επεξεργασία» δεν χρεώνονται. **Η χρέωση γίνεται μία φορά όταν ο πελάτης διαβάσει επιτυχώς το αποτέλεσμα για πρώτη φορά** (σύμφωνα με την υπάρχουσα συμπεριφορά και την τιμή της συγχρονισμένης λειτουργίας). Ο διακομιστής θα προχωρήσει αυτόματα την εργασία, αλλά δεν θα χρεώσει νωρίτερα επειδή ολοκληρώθηκε στο παρασκήνιο. Οι εργασίες που δεν ολοκληρώθηκαν εντός 120 δευτερολέπτων προθεσμίας τερματίζονται με HTTP 504 και δεν χρεώνονται.

## Διαχείριση σφαλμάτων

Κατά την κλήση αυτής της διεπαφής, αν προκύψει σφάλμα, θα επιστραφεί ο αντίστοιχος κωδικός σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 invalid_request`: Η αίτηση λείπει το παράμετρο `task_id`.
- `401 invalid_token`: Μη εξουσιοδοτημένο, το εξουσιοδοτημένο Token είναι άκυρο ή λείπει.
- `404 not_found`: Το `task_id` δεν υπάρχει ή δεν ανήκει στον τρέχοντα λογαριασμό.
- `504 timeout`: Η εργασία έχει τερματιστεί και δεν έχει παραχθεί αποτέλεσμα. Παρακαλώ σταματήστε το polling αυτού του `task_id`. Αυτή η αποτυχία δεν θα χρεωθεί.

### Παράδειγμα απάντησης σφάλματος

```json
{
  "success": false,
  "error": {
    "code": "not_found",
    "message": "task not found"
  }
}
```
