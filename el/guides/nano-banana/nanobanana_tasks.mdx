Η κύρια λειτουργία του Nano Banana Tasks API είναι να ερωτά την κατάσταση εκτέλεσης ενός έργου μέσω του ID έργου που παράγεται από το Nano Banana Images API.

Αυτό το έγγραφο θα περιγράψει λεπτομερώς τις οδηγίες διασύνδεσης του Nano Banana Tasks API, βοηθώντας σας να ενσωματώσετε εύκολα και να αξιοποιήσετε πλήρως τη δύναμη αυτού του API. Μέσω του Nano Banana Tasks API, μπορείτε εύκολα να ελέγξετε την κατάσταση εκτέλεσης των έργων του Nano Banana Images API.

## Παράδειγμα αιτήματος

Το Nano Banana Tasks API μπορεί να χρησιμοποιηθεί για να ελέγξει τα αποτελέσματα του Nano Banana Images API. Για πληροφορίες σχετικά με τη χρήση του Nano Banana Images API, ανατρέξτε στο έγγραφο [Nano Banana Images API](https://platform.acedata.cloud/documents/veo-videos).

Θα χρησιμοποιήσουμε ένα παράδειγμα με το ID έργου που επιστρέφεται από την υπηρεσία Nano Banana Images API. Ας υποθέσουμε ότι έχουμε ένα ID έργου: 4d320ead-4af4-4a55-8f3e-f2afebdf4fd0, και θα δείξουμε πώς να το χρησιμοποιήσουμε περνώντας ένα ID έργου.

### Ρύθμιση κεφαλίδων αιτήματος και σώματος αιτήματος

**Request Headers** περιλαμβάνουν:

- `accept`: καθορίζει ότι θα ληφθεί απάντηση σε μορφή JSON, εδώ συμπληρώνεται ως `application/json`.
- `authorization`: το κλειδί API για την κλήση του API, το οποίο μπορείτε να επιλέξετε απευθείας μετά την αίτηση.

**Request Body** περιλαμβάνει:

- `id`: το ID του έργου που έχει ανέβει.
- `action`: ο τρόπος λειτουργίας του έργου.

### Παράδειγμα κώδικα

Μπορείτε να παρατηρήσετε ότι στη δεξιά πλευρά της σελίδας έχουν παραχθεί αυτόματα διάφορες γλώσσες κώδικα, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/r1u4vl.png" width="500" className="m-auto" /></p>

Ορισμένα παραδείγματα κώδικα είναι τα εξής:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/nano-banana/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "4d320ead-4af4-4a55-8f3e-f2afebdf4fd0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/nano-banana/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "4d320ead-4af4-4a55-8f3e-f2afebdf4fd0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

```json
    "action": "generate",

  },

      }

```

Η επιστρεφόμενη απάντηση περιλαμβάνει πολλά πεδία, το πεδίο request είναι το σώμα του αιτήματος κατά την εκκίνηση του έργου, ενώ το πεδίο response είναι το σώμα της απάντησης που επιστρέφεται μετά την ολοκλήρωση του έργου. Η περιγραφή των πεδίων είναι ως εξής.

- `id`, το ID που δημιουργεί αυτό το έργο, χρησιμοποιείται για την μοναδική αναγνώριση αυτού του έργου.
- `request`, πληροφορίες αιτήματος στο έργο.
- `response`, πληροφορίες απάντησης στο έργο.
- `created_at`, χρόνος δημιουργίας του έργου, Unix χρονική σφραγίδα (δευτερόλεπτα, δεκαδικό).
- `started_at`, χρόνος έναρξης εκτέλεσης του έργου, Unix χρονική σφραγίδα (δευτερόλεπτα, δεκαδικό).
- `finished_at`, χρόνος ολοκλήρωσης του έργου, Unix χρονική σφραγίδα (δευτερόλεπτα, δεκαδικό). Δεν επιστρέφεται αυτό το πεδίο αν το έργο δεν έχει ολοκληρωθεί.
- `elapsed`, χρόνος εκτέλεσης του έργου, μονάδα σε δευτερόλεπτα (δεκαδικό, διατηρεί 3 δεκαδικά ψηφία). Δεν επιστρέφεται αυτό το πεδίο αν το έργο δεν έχει ολοκληρωθεί.

## Μαζική λειτουργία ερωτήματος

**Request Body** περιλαμβάνει:

- `ids`: πίνακας ID έργων που έχουν ανέβει.
- `action`: ο τρόπος λειτουργίας του έργου.

Το παράδειγμα είναι το εξής:

```bash
curl -X POST 'https://api.acedata.cloud/nano-banana/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["1ebe4f2b-59ba-4385-a4ea-0ce8a3fe12ed","1ebe4f2b-59ba-4385-a4ea-0ce8a3fe12ed"],
  "action": "retrieve_batch"
}'
```

## Σφάλματα

Κατά την κλήση του API, εάν προκύψουν σφάλματα, το API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διαπιστευτήριο εξουσιοδότησης.
- `429 too_many_requests`: Πάρα πολλές αιτήσεις, έχετε υπερβεί το όριο ρυθμού.
- `403 forbidden`: Η εγγενής πολιτική ασφαλείας του παρόχου απέρριψε την αίτηση ή τη δημιουργία αποτελέσματος. Εάν όλες οι κλήσεις δημιουργίας απορριφθούν, η εργασία αποθηκεύεται σε κατάσταση αποτυχίας, χωρίς εικόνες και χωρίς χρέωση. Στις αιτήσεις πολλών εικόνων, οι υπόλοιπες επιτυχείς κλήσεις μπορούν να επιστραφούν και να χρεωθούν σύμφωνα με τον πραγματικό αριθμό.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.
