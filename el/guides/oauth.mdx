---
title: "Ενσωμάτωση «Σύνδεση με Ace Data Cloud» (OAuth 2.0)"
---

Υποστηρίξτε στο δικό σας προϊόν τη «Σύνδεση με Ace Data Cloud» και, μετά την εξουσιοδότηση του χρήστη, **εκ μέρους του χρήστη** διαβάστε και γράψτε τους πόρους του στο Ace Data Cloud (προφίλ, API Token, συνδρομές, χρήση, παραγγελίες κ.λπ.). Η υποκείμενη τεχνολογία είναι το τυπικό **OAuth 2.0 Authorization Code + PKCE**, με ακριβώς την ίδια ενσωμάτωση όπως η σύνδεση με GitHub / Google — μπορείτε να χρησιμοποιήσετε απευθείας οποιαδήποτε βιβλιοθήκη OAuth client έχετε ήδη.

> **Κατάλληλα σενάρια**: Δημιουργείτε μια εφαρμογή τρίτου μέρους / Agent / MCP client / αυτοματοποιημένη ροή εργασίας και θέλετε οι χρήστες να συνδέονται με ένα κλικ χρησιμοποιώντας τον λογαριασμό Ace Data Cloud, και να έχουν πρόσβαση κατ’ απαίτηση στους πόρους τους στην πλατφόρμα, χωρίς να χρειάζεται να αντιγράφουν και να επικολλούν χειροκίνητα API Key.

## Γρήγορη αναφορά όρων & endpoints

Όλα τα endpoints βρίσκονται στο `https://auth.acedata.cloud` και μπορείτε να λαμβάνετε τις πιο πρόσφατες διευθύνσεις οποιαδήποτε στιγμή μέσω του endpoint ανακάλυψης (Discovery):

```bash
curl https://auth.acedata.cloud/.well-known/oauth-authorization-server
```

| Χρήση                 | Endpoint                                                |
| ------------------ | ------------------------------------------------- |
| Έγγραφο ανακάλυψης (Discovery)    | `GET /.well-known/oauth-authorization-server`     |
| Σελίδα εξουσιοδότησης χρήστη (ανακατεύθυνση browser)       | `GET https://auth.acedata.cloud/oauth2/authorize` |
| Endpoint token (ανταλλαγή / ανανέωση token) | `POST https://auth.acedata.cloud/oauth2/token`    |
| Ανάκληση token               | `POST https://auth.acedata.cloud/oauth2/revoke`   |
| Πληροφορίες χρήστη (UserInfo)     | `GET https://auth.acedata.cloud/api/v1/users/me`  |
| Διαχείριση εγγραφής εφαρμογών (αυτοεξυπηρέτηση)         | `https://auth.acedata.cloud/user/oauth-apps`      |

Υποστηριζόμενες δυνατότητες: `response_type=code`, `grant_types=authorization_code, refresh_token`, `code_challenge_methods=S256, plain`, μέθοδοι πιστοποίησης client `client_secret_post` (εμπιστευτικοί clients) / `none` (δημόσιοι clients PKCE).

## Εύρος δικαιωμάτων (Scope)

Ζητήστε βάσει της «ελάχιστης απαιτούμενης άδειας», και ο χρήστης θα βλέπει κάθε δικαίωμα που ζητάτε στη σελίδα εξουσιοδότησης.

**Κατηγορία ταυτότητας (συμβατή με OIDC)**

| Scope     | Σημασία      | Πεδία που επιστρέφει το `/users/me`                                           |
| --------- | ------- | ---------------------------------------------------------- |
| `openid`  | Μοναδικό αναγνωριστικό χρήστη  | `id`                                                       |
| `profile` | Βασικά στοιχεία    | `username`、`nickname`、`avatar`、`is_verified`、`date_joined` |
| `email`   | Email      | `email`                                                    |
| `phone`   | Αριθμός κινητού (ευαίσθητο) | `phone`、`region`                                           |

**Κατηγορία πόρων πλατφόρμας**

| Scope                                      | Σημασία                     |
| ------------------------------------------ | ---------------------- |
| `applications:read` / `applications:write` | Ανάγνωση / τροποποίηση των συνδρομών υπηρεσιών και των ορίων του χρήστη       |
| `credentials:read` / `credentials:write`   | Ανάγνωση / δημιουργία και ανάκληση API Token του χρήστη |
| `usage:read`                               | Ανάγνωση ιστορικού κλήσεων του χρήστη               |
| `orders:read` / `orders:write`             | Ανάγνωση παραγγελιών / υποβολή παραγγελιών και έναρξη πληρωμής          |

**Κατηγορία συνδυαστικών δικαιωμάτων (αυτόματη ανάπτυξη)**

| Scope            | Αναπτύσσεται σε                                                                     |
| ---------------- | ----------------------------------------------------------------------- |
| `platform:read`  | `applications:read` + `credentials:read` + `usage:read` + `orders:read` |
| `platform:write` | `applications:write` + `credentials:write` + `orders:write`             |
| `platform`       | `platform:read` + `platform:write`                                      |

**Ειδικό**

| Scope            | Σημασία                                                 |
| ---------------- | -------------------------------------------------- |
| `offline_access` | Εκδίδει **Refresh Token** (αν δεν ζητηθεί, εκδίδεται μόνο Access Token και απαιτείται νέα εξουσιοδότηση μετά τη λήξη) |

> Τυπικοί συνδυασμοί: σύνδεση τρίτου μέρους «με ένα κλικ» = `openid profile`· MCP / IDE client που χρειάζεται αυτόματη ρύθμιση Key = `openid profile credentials:read credentials:write`· πλήρης πίνακας διαχείρισης = `openid profile email platform offline_access`.

## Βήμα 1: Καταχωρίστε μια εφαρμογή OAuth

Ανοίξτε το [auth.acedata.cloud/user/oauth-apps](https://auth.acedata.cloud/user/oauth-apps) → «Δημιουργία εφαρμογής» και συμπληρώστε:

1. **Όνομα εφαρμογής / περιγραφή / Logo**: Θα εμφανίζονται στη σελίδα συναίνεσης εξουσιοδότησης του χρήστη.
2. **Τύπος client (Client Type)**:
   - **Εμπιστευτικός (confidential)** — έχετε backend και μπορείτε να διατηρήσετε με ασφάλεια το `client_secret` (υπηρεσίες Web, υπηρεσίες backend).
   - **Δημόσιος (public)** — αμιγώς frontend / desktop / CLI / mobile, **δεν μπορεί** να διατηρήσει μυστικά και πρέπει να χρησιμοποιεί **PKCE**.
3. **Διευθύνσεις callback (Redirect URIs)**: Η διεύθυνση στην οποία ανακατευθύνεται ο χρήστης μετά την ολοκλήρωση της εξουσιοδότησης, η οποία **πρέπει να είναι απολύτως ίδια με το `redirect_uri` που στέλνετε όταν ξεκινάτε την εξουσιοδότηση**· μπορείτε να συμπληρώσετε πολλές.
4. **Εύρη δικαιωμάτων (Scopes)**: Επιλέξτε τα scopes που χρειάζεστε από την προηγούμενη ενότητα.

Μετά την αποθήκευση λαμβάνετε το **`client_id`**· οι εμπιστευτικοί clients θα εμφανίζουν επίσης **μία μόνο φορά** το **`client_secret`** — αποθηκεύστε το αμέσως, καθώς δεν μπορείτε να το προβάλετε ξανά μετά το κλείσιμο (μπορείτε να το δημιουργήσετε ξανά από τη σελίδα λεπτομερειών με «Περιστροφή μυστικού / Rotate Secret», και το παλιό μυστικό ακυρώνεται αμέσως).

> Κάθε λογαριασμός μπορεί να δημιουργήσει έως **20** εφαρμογές OAuth.

## Βήμα 2: Ανακατευθύνετε τον χρήστη στη σελίδα εξουσιοδότησης

Στην εφαρμογή σας, ανακατευθύνετε τον browser του χρήστη στη σελίδα εξουσιοδότησης, προσθέτοντας παραμέτρους query:

```
https://auth.acedata.cloud/oauth2/authorize
  ?response_type=code
  &client_id=<你的 client_id>
  &redirect_uri=<你注册的回调地址>
  &scope=openid%20profile%20credentials:read
  &state=<随机防 CSRF 串>
  &code_challenge=<PKCE 挑战值>          # 公开客户端必填
  &code_challenge_method=S256            # 公开客户端必填
```

- `state`: Δημιουργήστε εσείς μια τυχαία συμβολοσειρά, η οποία επιστρέφεται αυτούσια κατά το callback και χρησιμοποιείται για προστασία από CSRF· **φροντίστε οπωσδήποτε να την επαληθεύσετε**.
- **PKCE (υποχρεωτικό για δημόσιους clients, συνιστάται επίσης για εμπιστευτικούς clients)**: Πρώτα δημιουργήστε ένα τυχαίο `code_verifier` και έπειτα υπολογίστε
  `code_challenge = BASE64URL( SHA256( code_verifier ) )`, τοποθετήστε το `code_challenge` στο URL εξουσιοδότησης,
  και κρατήστε το `code_verifier` για χρήση στο βήμα 4.

Αφού ο χρήστης συνδεθεί και πατήσει «Συμφωνώ», ο browser θα ανακατευθυνθεί πίσω:

```
<redirect_uri>?code=<授权码>&state=<原样返回的 state>
```

Αν ο χρήστης αρνηθεί: `<redirect_uri>?error=access_denied&error_description=...&state=...`.

> Ο κωδικός εξουσιοδότησης ισχύει για **10 λεπτά** και **μπορεί να χρησιμοποιηθεί μόνο μία φορά**.

## Βήμα 3: Ανταλλάξτε τον κωδικό εξουσιοδότησης με token

Στο **backend** σας (εμπιστευτικός client) ή στον client (δημόσιος client PKCE), καλέστε το endpoint token με το `code`.

**Εμπιστευτικός client (με client_secret):**

```bash
curl -X POST https://auth.acedata.cloud/oauth2/token \
  -d grant_type=authorization_code \
  -d code=<上一步拿到的 code> \
  -d client_id=<你的 client_id> \
  -d client_secret=<你的 client_secret> \
  -d redirect_uri=<和第 2 步完全一致的回调地址>
```

**Δημόσιος client (PKCE, χωρίς client_secret):**
```bash
curl -X POST https://auth.acedata.cloud/oauth2/token \
  -d grant_type=authorization_code \
  -d code=<code> \
  -d client_id=<你的 client_id> \
  -d code_verifier=<第 2 步生成的 code_verifier> \
  -d redirect_uri=<回调地址>
```

Επιτυχής επιστροφή (`refresh_token` εμφανίζεται μόνο όταν έχει ζητηθεί το `offline_access`):

```json
{
  "access_token": "<JWT>",
  "token_type": "Bearer",
  "expires_in": 1296000,
  "scope": "openid profile credentials:read",
  "refresh_token": "<JWT，仅 offline_access 时>"
}
```

Το `access_token` είναι ένα JWT και περιέχει τη δήλωση `scope`· η περίοδος ισχύος είναι **15 ημέρες** (δευτερόλεπτα `expires_in`). Το Refresh Token έχει ισχύ **30 ημερών**.

## Βήμα 4: Κλήση διεπαφών με Access Token

Απλώς τοποθετήστε το token στην κεφαλίδα `Authorization: Bearer`.

**Ανάγνωση πληροφοριών χρήστη (UserInfo, τα πεδία φιλτράρονται σύμφωνα με το εξουσιοδοτημένο scope):**

```bash
curl https://auth.acedata.cloud/api/v1/users/me \
  -H "Authorization: Bearer <access_token>"
```

**Κλήση διεπαφών πόρων της πλατφόρμας** (`platform.acedata.cloud`, εξουσιοδότηση βάσει scope). Για παράδειγμα, εάν έχει χορηγηθεί `credentials:read`:

```bash
curl "https://platform.acedata.cloud/api/v1/credentials/?user_id=<UserInfo返回的id>" \
  -H "Authorization: Bearer <access_token>"
```

Το backend της πλατφόρμας θα επαληθεύσει τη δήλωση `scope` μέσα στο JWT — το token μπορεί να προσπελάσει μόνο τους πόρους που έχει εξουσιοδοτήσει ο χρήστης. Εάν προσπελαστεί μη εξουσιοδοτημένος πόρος, θα επιστραφεί `403`.

## Ανανέωση token

Αφού λήξει το Access Token, χρησιμοποιήστε το Refresh Token για να ανταλλάξετε ένα νέο ζεύγος token (πρέπει να είχε αρχικά ζητηθεί το `offline_access`):

```bash
curl -X POST https://auth.acedata.cloud/oauth2/token \
  -d grant_type=refresh_token \
  -d refresh_token=<你的 refresh_token>
```

Η δομή επιστροφής είναι ίδια με το βήμα 3· το scope θα διατηρηθεί **ακριβώς ως έχει** από την αρχική εξουσιοδότηση. Μετά την ανανέωση, το παλιό Refresh Token καθίσταται άκυρο (rotation), αποθηκεύστε το νέο.

## Ανάκληση token

```bash
curl -X POST https://auth.acedata.cloud/oauth2/revoke \
  -d token=<access_token 或 refresh_token>
```

## Πραγματικό παράδειγμα: έτσι συνδέονται οι δικοί μας MCP servers

Οι 15+ MCP servers του Ace Data Cloud (NanoBanana, Midjourney, Suno, Seedance, Kling…) χρησιμοποιούν ακριβώς αυτή τη ροή για τη σύνδεση «Sign in with Ace Data Cloud» που εμφανίζεται στο Claude Desktop / Cursor: όλοι είναι καταχωρημένοι ως OAuth εφαρμογές τύπου **δημόσιου (PKCE)**, ζητούν scope σχετικό με `credentials`, και αφού ο χρήστης δώσει εξουσιοδότηση, ο MCP server μπορεί να καλεί το `api.acedata.cloud` εκ μέρους του χρήστη — χωρίς ο χρήστης να χρειάζεται να επικολλήσει χειροκίνητα API Key. Ο τρόπος σύνδεσής σας είναι ακριβώς ίδιος με τον δικό τους.

## Συνήθη σφάλματα

Οι αποκρίσεις σφαλμάτων έχουν ενιαία μορφή `{ "error": "<code>", "error_description": "&lt;ανθρώπινα αναγνώσιμη περιγραφή>" }`:

| error                    | Σημασία / έλεγχος                                                        |
| ------------------------ | ----------------------------------------------------------------------- |
| `invalid_request`        | Λείπουν ή είναι μη έγκυρες παράμετροι (π.χ. δεν δόθηκε `code` / `client_id`) |
| `invalid_client`         | Το `client_id` δεν υπάρχει, η εφαρμογή έχει απενεργοποιηθεί ή το `client_secret` είναι λανθασμένο |
| `invalid_grant`          | Ο κωδικός εξουσιοδότησης δεν υπάρχει / έχει λήξει (>10 λεπτά) / έχει ήδη χρησιμοποιηθεί / απέτυχε η επαλήθευση PKCE / το `redirect_uri` δεν συμφωνεί με αυτό κατά την εξουσιοδότηση |
| `access_denied`          | Ο χρήστης πάτησε «Απόρριψη» στη σελίδα εξουσιοδότησης                    |
| `unsupported_grant_type` | Το `grant_type` δεν είναι `authorization_code` ή `refresh_token`        |

## Γρήγορη αναφορά περιορισμών

| Στοιχείο                 | Τιμή                            |
| ------------------------ | ------------------------------- |
| Μέγιστος αριθμός OAuth εφαρμογών ανά λογαριασμό | 20                              |
| Διάρκεια ισχύος κωδικού εξουσιοδότησης | 10 λεπτά, μία χρήση              |
| Διάρκεια ισχύος Access Token | 15 ημέρες                       |
| Διάρκεια ισχύος Refresh Token | 30 ημέρες (rotation)            |
| `redirect_uri`           | Πρέπει να ταιριάζει ακριβώς με την καταχωρημένη τιμή |
| `client_secret`          | Εμφανίζεται μόνο μία φορά κατά τη δημιουργία / rotation, ο διακομιστής το αποθηκεύει ως hash SHA-256 |

## Ενσωμάτωση OAuth εφαρμογών τρίτων στην αρχική σελίδα του Studio

Στο Studio, στις «Ρυθμίσεις → Αρχική σελίδα → Στοιχεία ιστότοπου», μπορείτε να ενεργοποιήσετε OAuth και να ρυθμίσετε το `client_id` της εφαρμογής τρίτου μέρους και την καταχωρημένη διεύθυνση callback.
Ο ιστότοπος και το callback πρέπει να χρησιμοποιούν HTTPS, να έχουν την ίδια προέλευση (πρωτόκολλο, όνομα τομέα και θύρα) και να έχουν διαφορετική προέλευση από το Studio.
Δεν πρέπει να συμπληρώνεται `client_secret` στη ρύθμιση· το κλειδί της εφαρμογής μπορεί να αποθηκεύεται μόνο στο backend του τρίτου μέρους.

Τα δικαιώματα που ζητά το στοιχείο είναι `profile:read credentials:read`. Κάθε επισκέπτης πρέπει να συναινεί ξεχωριστά· η ρύθμιση του στοιχείου από τον διαχειριστή του ιστότοπου δεν αντιπροσωπεύει εξουσιοδότηση από τους επισκέπτες.
Η σελίδα τρίτου μέρους δημιουργεί τυχαίο `state` και PKCE verifier και στέλνει S256 challenge στο Studio. Το Studio φιλοξενεί την επίσημη σελίδα εξουσιοδότησης
στην περιοχή του στοιχείου. Αφού ο χρήστης συναινέσει, το τρίτο μέρος λαμβάνει έναν κωδικό εξουσιοδότησης μίας χρήσης και καλεί το endpoint token για να ανταλλάξει OAuth access token, έπειτα προσπελαύνει
το `GET https://platform.acedata.cloud/api/v1/credentials/?user_id=&lt;用户ID>` για να διαβάσει το υπάρχον API Key.
Το ID χρήστη προέρχεται από το `id` που επιστρέφεται από το προηγούμενο βήμα `GET https://auth.acedata.cloud/api/v1/users/me`· η διεπαφή λίστας διαπιστευτηρίων δεν δέχεται `user_id=me`.
Το Studio δεν μεταφέρει στο τρίτο μέρος το δικό του token σύνδεσης ούτε διαβάζει και εισάγει απευθείας το Key του χρήστη.

Οι δημόσιοι clients πρέπει να χρησιμοποιούν **S256 PKCE**. Κατά την ανταλλαγή token, πρέπει να μεταβιβάζεται `redirect_uri` ακριβώς ίδιο με εκείνο του αιτήματος εξουσιοδότησης.
Ο κωδικός εξουσιοδότησης μπορεί να ανταλλαχθεί μόνο μία φορά. Πριν από την εξουσιοδότηση, θα ελεγχθεί εάν η διεύθυνση callback έχει καταχωρηθεί.

Η σελίδα τρίτου μέρους πρέπει να υλοποιεί το πρωτόκολλο μηνυμάτων· οποιαδήποτε υπάρχουσα ιστοσελίδα δεν μπορεί να ενσωματωθεί αυτόματα μόνο με τη συμπλήρωση ενός URL.
Για πλήρες παράδειγμα, δείτε τον [Οδηγό ενσωμάτωσης στοιχείου Studio OAuth](https://github.com/AceDataCloud/Nexior/blob/main/docs/integrations/studio-home-oauth.md).

**Η εξουσιοδότηση ανάγνωσης API Key ισοδυναμεί με την άδεια στο τρίτο μέρος να αποθηκεύει και να χρησιμοποιεί αυτό το Key. Η ακύρωση της εξουσιοδότησης OAuth δεν καθιστά άκυρα τα Key που έχει ήδη αντιγράψει το τρίτο μέρος·
ο χρήστης πρέπει επιπλέον να ανακαλέσει ή να εναλλάξει το Key.**
