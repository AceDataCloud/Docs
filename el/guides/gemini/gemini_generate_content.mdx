Το Google Gemini είναι ένα πολύ ισχυρό σύστημα διαλόγου AI, το οποίο μπορεί να δημιουργεί ομαλές και φυσικές απαντήσεις μέσα σε λίγα δευτερόλεπτα μέσω εισαγωγής προτροπών. Αυτό το έγγραφο περιγράφει κυρίως τον τρόπο χρήσης του Gemini Generate Content API, το οποίο είναι η επίσημη εγγενής μορφή API της Google και υποστηρίζει τα δύο endpoints `generateContent` και `streamGenerateContent`.

## Διαφορές από το Chat Completions API

Το Gemini Generate Content API χρησιμοποιεί την επίσημη εγγενή μορφή αιτήματος της Google (πεδίο `contents`), αντί για τη μορφή συμβατή με OpenAI (πεδίο `messages`). Εάν χρησιμοποιείτε ήδη το Google Gemini SDK ή είστε εξοικειωμένοι με την επίσημη μορφή API, μπορείτε να χρησιμοποιήσετε απευθείας αυτό το API χωρίς να τροποποιήσετε τη μορφή αιτήματος.

## Τρέχον εύρος υποστήριξης

Η διεπαφή δέχεται εισόδους κειμένου, εικόνας, βίντεο και ήχου (`inlineData` ή `fileData`), διαμόρφωση σκέψης και δηλώσεις προσαρμοσμένων συναρτήσεων. Δεν υπάρχει ακόμη εγγύηση ενιαίας διαθεσιμότητας για εγγενή πεδία όπως η έξοδος ήχου, τα ενσωματωμένα εργαλεία και η ρητή προσωρινή αποθήκευση περιβάλλοντος· ανατρέξτε στην πραγματική απόκριση του συγκεκριμένου μοντέλου.

Όταν υποβάλλετε αρχεία όπως ήχο με `fileData.fileUri`, βεβαιωθείτε ότι το αρχείο είναι άμεσα προσβάσιμο μέσω HTTPS, δεν εξαρτάται από κατάσταση σύνδεσης και ότι η περίοδος ισχύος του υπογεγραμμένου συνδέσμου καλύπτει ολόκληρο τον χρόνο επεξεργασίας του αιτήματος. Η μη ροϊκή ανάλυση ήχου επιστρέφει αποτέλεσμα μόνο αφού το μοντέλο ολοκληρώσει την επεξεργασία, γεγονός που μπορεί να υπερβεί τα 90 δευτερόλεπτα· ο πελάτης θα πρέπει να ορίζει επαρκώς μεγάλο συνολικό χρονικό όριο ανάλογα με το μέγεθος του αρχείου και το επιχειρησιακό σενάριο, ώστε να αποφεύγεται η διακοπή της σύνδεσης ενώ ο διακομιστής συνεχίζει την επεξεργασία.

## Διαδικασία αίτησης

Πριν χρησιμοποιήσετε το Gemini Generate Content API, επισκεφθείτε πρώτα τη σελίδα [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) και κάντε κλικ στο κουμπί "获取" για να λάβετε τα διαπιστευτήρια που απαιτούνται για το αίτημα.

Εάν δεν έχετε ακόμη συνδεθεί ή εγγραφεί, θα ανακατευθυνθείτε αυτόματα στη σελίδα σύνδεσης. Η πρώτη αίτηση περιλαμβάνει δωρεάν ποσό χρήσης.

## Βασική χρήση

### Non-Streaming（μη ροϊκή）

Στείλτε ένα αίτημα POST στο `/v1beta/models/{model}:generateContent`:

> **Συμβουλή**：Η σειρά `gemini-3.x` flash είναι μοντέλο σκέψης και καταναλώνει πρώτα reasoning tokens· ορίστε το `generationConfig.maxOutputTokens` σε τιμή άνω του 512, διαφορετικά ενδέχεται να επιστρέφεται μόνο κενό περιεχόμενο.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Παράδειγμα αποτελέσματος επιστροφής:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Τα πεδία token στο `usageMetadata` χρεώνονται σύμφωνα με τη εγγενή σημασιολογία του Gemini:

- Το `promptTokenCount` περιλαμβάνει το `cachedContentTokenCount`, ενώ το τμήμα που αντιστοιχεί σε επιτυχημένη χρήση προσωρινής μνήμης υπολογίζεται με την τιμή ανάγνωσης προσωρινής μνήμης και δεν υπολογίζεται ξανά ως συνηθισμένη είσοδος.
- Τα `promptTokensDetails` και `cacheTokensDetails` κανονικοποιούνται σε `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` και τις αντίστοιχες λεπτομέρειες `cached_*` κάτω από το `usage.prompt_tokens_details`. Αυτές οι τιμές περιλαμβάνονται αντίστοιχα στα `prompt_tokens` και `cached_tokens`· οι διαφορετικές μορφές δεδομένων επαναϋπολογίζονται μόνο με βάση τις δικές τους τιμές και δεν χρεώνονται διπλά.
- Τα `candidatesTokenCount` και `thoughtsTokenCount` υπολογίζονται και τα δύο με την τιμή output token.
- Το `toolUsePromptTokenCount` είναι ανεξάρτητο token εισόδου εργαλείου και υπολογίζεται με την τιμή input token.

Το Ace Data Cloud επιστρέφει επιπλέον ένα κανονικοποιημένο αντικείμενο `usage`, και το κόστος αυτής της κλήσης διαβάζεται ενιαία μεταξύ πρωτοκόλλων μοντέλων από το `usage.cost`. Το `cost` είναι μια προαιρετική προεπισκόπηση κόστους· όταν η προεπισκόπηση τιμής δεν είναι προσωρινά διαθέσιμη, η απόκριση του μοντέλου εξακολουθεί να επιστρέφεται κανονικά, αλλά ενδέχεται να μην περιλαμβάνει αυτό το πεδίο. Η τελική χρέωση βασίζεται στα αρχεία χρήσης.

### Streaming（ροϊκή）

Στείλτε ένα αίτημα POST στο `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

Η ροϊκή απόκριση θα επιστρέφει σταδιακά περιεχόμενο σε μορφή SSE（Server-Sent Events）. Τα ενδιάμεσα συμβάντα συνήθως περιλαμβάνουν μόνο σταδιακό περιεχόμενο· το τελικό συμβάν που περιέχει την έγκυρη χρήση θα περιλαμβάνει `usageMetadata` και κανονικοποιημένο `usage`, ενώ το κόστος εξακολουθεί να βρίσκεται στο `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

Το κλείσιμο της σύνδεσης υποδηλώνει το τέλος της ροής· η εγγενής ροή Gemini δεν στέλνει `data: [DONE]`. Εάν η προεπισκόπηση τελικής τιμής δεν είναι προσωρινά διαθέσιμη, το `usage` θα εξακολουθεί να επιστρέφει τη χρήση token, αλλά θα παραλείπει το `cost`.

Οι επίσημες προδιαγραφές μοντέλων αναφέρουν εισόδους κειμένου, εικόνας, βίντεο, ήχου και PDF, καθώς και έξοδο κειμένου· αυτό δεν σημαίνει ότι η τρέχουσα πλατφόρμα έχει επαληθεύσει όλους τους τύπους εισόδου. Μετά την αποκατάσταση της εγγενούς κλήσης, υποβάλετε αιτήματα σύμφωνα με το συμβόλαιο διεπαφής αυτής της σελίδας και επαληθεύστε ξεχωριστά τις απαιτούμενες εισόδους και παραμέτρους. Η επίσημη έξοδος ενός εκατομμυρίου Token για long decode δεν περιλαμβάνεται στο τρέχον συμβόλαιο διεπαφής. Και τα δύο υποστηρίζουν μόνο έμμεση προσωρινή αποθήκευση, ενώ τα Token σκέψης χρεώνονται σύμφωνα με την τιμή εξόδου· οι προετοιμασμένοι κανόνες τιμολόγησης χρησιμοποιούν την ίδια τιμή εισόδου ανά Token για κάθε τροπικότητα εισόδου και οι επιτυχίες προσωρινής αποθήκευσης υπολογίζονται σύμφωνα με την τιμή ανάγνωσης προσωρινής αποθήκευσης, δείτε την τρέχουσα σελίδα τιμών για λεπτομέρειες.

### Εσωτερική σκέψη και περίληψη σκέψης

Η εσωτερική σκέψη του μοντέλου και η επιστροφή περίληψης σκέψης στον καλούντα είναι δύο ανεξάρτητες ρυθμίσεις:

- Το `thinkingBudget` ή το `thinkingLevel` ελέγχει τον προϋπολογισμό ή το βάθος της εσωτερικής σκέψης του μοντέλου· τα υποστηριζόμενα πεδία και τιμές εξαρτώνται από το μοντέλο.
- Το `includeThoughts` ελέγχει αν επιστρέφεται περίληψη σκέψης, με προεπιλογή το `false`. Όταν το πεδίο παραλείπεται ή περνάει το `false`, ούτε η κανονική JSON ούτε η ροϊκή απόκριση SSE επιστρέφει κείμενο με επισήμανση `thought: true`· αυτά τα κείμενα διατηρούνται μόνο όταν περνάει ρητά η δυαδική τιμή `true`.

Όταν το αίτημα δεν ορίζει το `includeThoughts`, η διεπαφή περνάει από προεπιλογή το `false` στα μοντέλα δημιουργίας που υποστηρίζουν διαμόρφωση σκέψης, αποφεύγοντας περιλήψεις που δεν ζητούνται από το αίτημα· η τιμή που περνάει ρητά ο πελάτης, ο προϋπολογισμός σκέψης και το επίπεδο διατηρούνται. Το γνωστό `gemini-2.5-flash-image`, το οποίο δεν υποστηρίζει διαμόρφωση σκέψης, δεν θα έχει αυτό το πεδίο προστεθεί αυτόματα, ενώ ούτε στα αιτήματα `countTokens` θα προστεθεί διαμόρφωση δημιουργίας.

Η απενεργοποίηση της περίληψης δεν ισοδυναμεί με απενεργοποίηση της εσωτερικής σκέψης και δεν εγγυάται μείωση των token εσωτερικής σκέψης. Αν η απόκριση εξακολουθεί να περιέχει μη ζητημένο κείμενο σκέψης, οι έξοδοι κανονικού JSON και SSE θα το φιλτράρουν περαιτέρω, διατηρώντας την κανονική απάντηση, την υπογραφή και την πραγματική χρήση.

Όταν χρειάζεται να προβάλετε την περίληψη, ενεργοποιήστε την ρητά με τον ακόλουθο τρόπο. Όταν το μοντέλο δεν έχει δημιουργήσει διαθέσιμη περίληψη, ενδέχεται να μην υπάρχει κείμενο σκέψης ακόμη και αν είναι ενεργοποιημένη:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

Το `thoughtSignature` είναι κρυπτογραφημένη κατάσταση που απαιτείται για τους επόμενους γύρους, δεν είναι κείμενο περίληψης σκέψης και δεν ελέγχεται από τον διακόπτη `includeThoughts`. Η υπογραφή μπορεί να βρίσκεται σε κανονική απάντηση, κλήση συνάρτησης ή Part κενού κειμένου· κατά το φιλτράρισμα κειμένου σκέψης, διατηρούνται η υπογραφή και τα άλλα πεδία του ίδιου Part, επομένως η απόκριση μπορεί να εξακολουθεί να περιέχει Part που φέρουν μόνο υπογραφή και έχουν κενό κείμενο. Κατά τη μη αυτόματη διατήρηση ιστορικού πολλαπλών γύρων, πρέπει να διατηρείτε τη σειρά αυτών των Part και τη θέση της υπογραφής· μην μετακινείτε τις υπογραφές και μην τις συγχωνεύετε.

Τα `usageMetadata` και `usage` εξακολουθούν να καταγράφουν την πραγματική χρήση. Η απόκρυψη της περίληψης δεν μηδενίζει το `thoughtsTokenCount` και η χρέωση εξακολουθεί να υπολογίζεται βάσει της πραγματικής χρήσης και των τρεχόντων κανόνων τιμολόγησης.

Δείτε τις επίσημες οδηγίες της Google για τη [σκέψη και τις περιλήψεις σκέψης](https://firebase.google.com/docs/ai-logic/thinking) και τους [κανόνες υπογραφής σκέψης](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

## Ρυθμίσεις ασφαλείας

Η φιλτραρίσματος περιεχομένου μπορεί να ελεγχθεί μέσω του `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Χειρισμός σφαλμάτων

| Κωδικός κατάστασης HTTP | Σημασία             |
| -------- | -------------- |
| 400      | Μη έγκυρες παράμετροι αιτήματος         |
| 401      | Αποτυχία πιστοποίησης, ελέγξτε το Token |
| 403      | Το περιεχόμενο αποκλείστηκε από το φίλτρο ασφαλείας     |
| 429      | Τα αιτήματα είναι υπερβολικά συχνά         |
| 500      | Εσωτερικό σφάλμα διακομιστή        |
