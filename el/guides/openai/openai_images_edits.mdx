Η υπηρεσία επεξεργασίας εικόνων OpenAI επιτρέπει την εισαγωγή οποιουδήποτε αριθμού εικόνων και εντολών, με έξοδο τις τροποποιημένες εικόνες. Η διεπαφή υποστηρίζει ταυτόχρονα τα `dall-e-2`, `gpt-image-1`, το νεότερο **`gpt-image-2`**, καθώς και τη σειρά μοντέλων **`nano-banana` / `nano-banana-2` / `nano-banana-pro`** που ενσωματώνονται μέσω της ίδιας διεπαφής.

Αυτό το έγγραφο παρουσιάζει κυρίως τη διαδικασία χρήσης του OpenAI Images Edits API, με το οποίο μπορούμε εύκολα να χρησιμοποιήσουμε τις επίσημες λειτουργίες επεξεργασίας εικόνων της OpenAI.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το OpenAI Images Edits API, μπορείτε πρώτα να μεταβείτε στη σελίδα [OpenAI Images Edits API](https://platform.acedata.cloud/documents/251f1efa-aaa6-462e-8af4-66854b1bc94d) και να κάνετε κλικ στο κουμπί «Acquire» για να λάβετε τα διαπιστευτήρια που απαιτούνται για το αίτημα:

![](https://cdn.acedata.cloud/nyq0xz.png)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης για να εγγραφείτε και να συνδεθείτε. Μετά τη σύνδεση ή εγγραφή, θα επιστρέψετε αυτόματα στην τρέχουσα σελίδα.

Κατά την πρώτη αίτηση, παρέχεται δωρεάν όριο χρήσης, ώστε να μπορείτε να χρησιμοποιήσετε το API δωρεάν.

## Μοντέλο GPT-Image-2

Το `gpt-image-2` παρουσιάζει σημαντική βελτίωση σε σχέση με το `gpt-image-1` στο σενάριο επεξεργασίας εικόνων:

- **Σταθερότερη διατήρηση δομής**: Αλλαγή δέρματος, χρωμάτων ή φόντου σχεδόν δεν καταστρέφει τη διάταξη και τη σύνθεση της αρχικής εικόνας.
- **Πιο ακριβής διατήρηση κειμένου**: Σε εικόνες με κείμενο όπως πληροφοριακά γραφήματα, αφίσες, μενού, το κείμενο παραμένει καθαρό και ευανάγνωστο μετά την επεξεργασία.
- **Υποστήριξη απευθείας URL**: Εκτός από την παραδοσιακή μεταφόρτωση αρχείων με `multipart/form-data`, το `gpt-image-2` **υποστηρίζει επιπλέον την εισαγωγή URL εικόνας μέσω JSON**, χωρίς να χρειάζεται να κατεβάσετε πρώτα την εικόνα τοπικά, ιδανικό για ενσωμάτωση σε server-side pipelines.
- **Υποστήριξη ανασχεδίασης υψηλής ανάλυσης**: Μπορείτε να εισάγετε μια εικόνα 1K και να ζητήσετε έξοδο 2K / 4K μέσω της παραμέτρου `size`, με το μοντέλο να πραγματοποιεί ταυτόχρονα μεγέθυνση κατά την επεξεργασία.

### Υποστηριζόμενες τιμές `size` και επίπεδα χρέωσης

Οι περιορισμοί της παραμέτρου `size` στην επεξεργασία είναι ίδιοι με αυτούς της δημιουργίας εικόνων — το `gpt-image-2` δέχεται `size` ως `auto`, κενό ή σε μορφή `WIDTHxHEIGHT`. Οποιαδήποτε άλλη μορφή επιστρέφει σφάλμα 400. Η χρέωση χωρίζεται σε δύο επίπεδα, ανεξάρτητα από την ανάλυση της αρχικής εικόνας, μόνο με βάση την τιμή `size`:

- **Τιμή 1K (τυπική)**: Οποιοδήποτε από τα προτεινόμενα μεγέθη 1K στον παρακάτω πίνακα ή κοινά συνώνυμα 1K (π.χ. `1254x1254`, `1672x941`, `941x1672`).
- **Άλλο επίπεδο (1.5×)**: Περιλαμβάνει τα προτεινόμενα μεγέθη 2K / 4K στον πίνακα, καθώς και οποιοδήποτε προσαρμοσμένο `WIDTHxHEIGHT`.

Ισχύουν επίσης οι περιορισμοί του upstream για προσαρμοσμένα μεγέθη: πλάτος και ύψος πολλαπλάσια του 16, μέγιστο μήκος πλευράς ≤ 3840, και συνολικός αριθμός pixel ≤ 8.294.400.

| Αναλογία | 1K (Τυπική Τιμή) | 2K Προτεινόμενο (×1.5) | 4K Προτεινόμενο (×1.5) |
| --- | --- | --- | --- |
| 1:1 | `1024x1024` | `2048x2048` | `2880x2880` |
| 4:3 | `1536x1024` | `2048x1536` | `3264x2448` |
| 3:4 | `1024x1536` | `1536x2048` | `2448x3264` |
| 16:9 | `1792x1024` | `2048x1152` | `3840x2160` |
| 9:16 | `1024x1792` | `1152x2048` | `2160x3840` |

> Παράδειγμα: Αν η αρχική εικόνα είναι `1024x1024` και το `size` είναι `2048x2048`, το μοντέλο θα επανασχεδιάσει και θα παράγει εικόνα 2K, με χρέωση στο «άλλο» επίπεδο. Αν το `size` είναι `3840x2160`, παράγεται εικόνα 4K οριζόντια, επίσης με χρέωση «άλλο». Αν το `size` είναι `auto` ή παραληφθεί, η χρέωση είναι στο τυπικό επίπεδο 1K.

> **Σχετικά με την παράμετρο `n`**
>
> Το `gpt-image-2` δεν υποστηρίζει το `n > 1` στην επεξεργασία: αυτή η παράμετρος αγνοείται σιωπηλά και ανεξάρτητα αν περάσετε `n=1` ή `n=10`, κάθε αίτημα επιστρέφει μόνο 1 εικόνα και χρεώνεται ως 1 εικόνα. Αν χρειάζεστε πολλαπλές υποψήφιες επεξεργασίες, πρέπει να κάνετε πολλαπλά παράλληλα αιτήματα. Ο περιορισμός αυτός ισχύει επίσης για τα `gpt-image-1` / `gpt-image-1.5` και τη σειρά `nano-banana` / `nano-banana-2` / `nano-banana-pro`. Το `dall-e-2` είναι το μόνο μοντέλο που υποστηρίζει εγγενώς `n > 1`.

Παρακάτω παρουσιάζονται δύο πραγματικά παραδείγματα που δείχνουν τις δυνατότητες επεξεργασίας του `gpt-image-2`.

### Τρόπος κλήσης 1: JSON + URL εικόνας (συνιστάται)

Στέλνετε απευθείας αίτημα με `application/json`, με το πεδίο `image` να περιέχει το URL μιας εικόνας. Το μοντέλο θα ανακτήσει την εικόνα και θα την επεξεργαστεί σύμφωνα με το `prompt`.

Για παράδειγμα, η παρακάτω αρχική εικόνα είναι ένα επιστημονικό infographic που δημιουργήθηκε με `gpt-image-2`:

<p><img src="https://platform.cdn.acedata.cloud/gpt-image/5c9fa635-8794-4c6d-88f8-584d7f4716c6_0.png" width="500" className="m-auto" /></p>

Θέλουμε να την αλλάξουμε σε «νυχτερινή λειτουργία». Κλήση:

```shell
curl -X POST "https://api.acedata.cloud/openai/images/edits" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://platform.cdn.acedata.cloud/gpt-image/5c9fa635-8794-4c6d-88f8-584d7f4716c6_0.png",
    "prompt": "Convert this infographic to dark mode: dark navy background, light cream text, deep gray rounded module cards with soft shadows. Keep all layout, structure, and module arrangement identical — only invert the color scheme.",
    "size": "1024x1536"
  }'
```

Ή με Python:

```python
import requests

url = "https://api.acedata.cloud/openai/images/edits"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-image-2",
    "image": "https://platform.cdn.acedata.cloud/gpt-image/5c9fa635-8794-4c6d-88f8-584d7f4716c6_0.png",
    "prompt": "Convert this infographic to dark mode: dark navy background, light cream text, deep gray rounded module cards with soft shadows. Keep all layout, structure, and module arrangement identical — only invert the color scheme.",
    "size": "1024x1536"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Τρόπος κλήσης 3: multipart/form-data (συμβατό με OpenAI SDK)

Αν χρησιμοποιείτε ήδη το επίσημο OpenAI Python SDK, η παραδοσιακή μέθοδος μεταφόρτωσης αρχείων με `multipart/form-data` εξακολουθεί να ισχύει, απλώς αλλάξτε το `model` σε `gpt-image-2`:

```python
import base64
from openai import OpenAI
client = OpenAI()

result = client.images.edit(
    model="gpt-image-2",
    image=[open("test.png", "rb")],
    prompt="Convert this image to dark mode while keeping the layout intact."
)

image_base64 = result.data[0].b64_json
image_bytes = base64.b64decode(image_base64)
with open("edited.png", "wb") as f:
    f.write(image_bytes)
```

Για χρήση με SDK, πρέπει να ορίσετε δύο μεταβλητές περιβάλλοντος: `OPENAI_BASE_URL` στο `https://api.acedata.cloud/openai` και `OPENAI_API_KEY` στο token που λάβατε:

```shell
export OPENAI_BASE_URL=https://api.acedata.cloud/openai
export OPENAI_API_KEY={token}
```

## Σειρά Μοντέλων Nano Banana

Η σειρά `nano-banana` επίσης ενσωματώνεται στο `/openai/images/edits`, απλώς αλλάξτε το `model` σε οποιοδήποτε από τα παρακάτω:

| Μοντέλο | Χρέωση (Credits / αίτημα) | Κατάλληλο σενάριο |
| --- | --- | --- |
| `nano-banana` | 0.14 | Κανονική επεξεργασία εικόνας, ταχύτερο και οικονομικότερο |
| `nano-banana-2` | 0.28 | Βελτιωμένη ποιότητα και λεπτομέρεια |
| `nano-banana-pro` | 0.35 | Ναυαρχίδα της σειράς, καλύτερη διατήρηση δομής, κειμένου και στυλ |

> **Σημαντικό: Υποστηριζόμενες παράμετροι**
>
> Το Nano Banana συνδέεται μέσω προσαρμοστικού επιπέδου στο πρωτόκολλο OpenAI και υποστηρίζει μόνο τις παραμέτρους: `model`, `prompt`, `image`.
>
> - Το `image` μπορεί να ανέβει είτε ως αρχείο με `multipart/form-data` (στον worker μετατρέπεται σε `data:<mime>;base64,...` για το upstream), είτε ως URL εικόνας σε πεδίο φόρμας.
> - Δεν υποστηρίζονται `mask`, `n`, `size`, `response_format` κ.ά. — αγνοούνται αν συμπληρωθούν.
> - Η δομή απάντησης ακολουθεί το πρότυπο OpenAI (`data[].url`), αλλά το `created` είναι πάντα `0`, δεν επιστρέφεται `b64_json` και το `revised_prompt` ισούται πάντα με το αρχικό `prompt`.

### Ασύγχρονη Επιστροφή Αποτελεσμάτων (Callback)

Ο μηχανισμός ασύγχρονης επιστροφής `callback_url` ισχύει και για το nano-banana, με την ίδια διαδικασία που περιγράφεται στην ενότητα [Ασύγχρονη Επιστροφή Αποτελεσμάτων](#ασύγχρονη-επιστροφή).

## Βασική Χρήση

Μπορείτε να καλέσετε το API με κώδικα. Παράδειγμα με CURL:

```curl
curl -s -D >(grep -i x-request-id >&2) \
  -o >(jq -r '.data[0].b64_json' | base64 --decode > gift-basket.png) \
  -X POST "https://api.acedata.cloud/v1/images/edits" \
  -H "Authorization: Bearer {token}" \
  -F "model=gpt-image-1" \
  -F "image[]=@test.png" \
  -F 'prompt=Create a lovely gift basket with these this items in it'
```

Κατά την πρώτη χρήση, πρέπει να συμπληρώσετε τέσσερα στοιχεία: `authorization` (επιλέγεται από λίστα), `model` (το μοντέλο που θα χρησιμοποιήσετε, εδώ κυρίως ένα μοντέλο, δείτε τα διαθέσιμα), `prompt` (η περιγραφή για τη δημιουργία εικόνας) και `image` (η διαδρομή της εικόνας προς επεξεργασία). Η εικόνα προς επεξεργασία φαίνεται παρακάτω:

<p><img src="https://cdn.acedata.cloud/jw9iwu.png" width="500" className="m-auto" /></p>

Παρόμοιο παράδειγμα με Python:

```python
import base64
from openai import OpenAI
client = OpenAI()

prompt = """
Generate a photorealistic image of a gift basket on a white background 
labeled 'Relax & Unwind' with a ribbon and handwriting-like font, 
containing all the items in the reference pictures.
"""

result = client.images.edit(
    model="gpt-image-1",
    image=[
        open("test.png", "rb")
    ],
    prompt=prompt
)

image_base64 = result.data[0].b64_json
image_bytes = base64.b64decode(image_base64)

# Αποθήκευση εικόνας σε αρχείο
with open("gift-basket.png", "wb") as f:
    f.write(image_bytes)
```

Για χρήση Python, πρέπει να ορίσετε δύο μεταβλητές περιβάλλοντος: `OPENAI_BASE_URL` στο `https://api.acedata.cloud/openai` και `OPENAI_API_KEY` στο token που λάβατε. Σε Mac OS:

```shell
export OPENAI_BASE_URL=https://api.acedata.cloud/openai
export OPENAI_API_KEY={token} 
```

Μετά την κλήση, θα δημιουργηθεί το αρχείο `gift-basket.png` στον τρέχοντα φάκελο, με το παρακάτω αποτέλεσμα:

<p><img src="https://cdn.acedata.cloud/574s8h.png" width="500" className="m-auto" /></p>

Έτσι ολοκληρώσαμε την επεξεργασία εικόνας. Το Edits API υποστηρίζει τρία μοντέλα: `dall-e-2`, `gpt-image-1` και `gpt-image-2`, με το `gpt-image-2` να είναι το συνιστώμενο, όπως περιγράφεται στην ενότητα [GPT-Image-2 Μοντέλο](#μοντέλο-gpt-image-2).

## Ασύγχρονη Επιστροφή Αποτελεσμάτων (Callback)

Η επεξεργασία εικόνων μπορεί να διαρκέσει αρκετά, και αν το API δεν απαντά για μεγάλο διάστημα, η HTTP σύνδεση παραμένει ανοιχτή, καταναλώνοντας πόρους. Γι’ αυτό το API υποστηρίζει ασύγχρονη επιστροφή αποτελεσμάτων.

Η διαδικασία είναι: ο πελάτης στέλνει το αίτημα με επιπλέον πεδίο `callback_url`. Το API επιστρέφει αμέσως ένα αποτέλεσμα με `task_id` που αντιπροσωπεύει το ID της εργασίας. Όταν ολοκληρωθεί η εργασία, το αποτέλεσμα αποστέλλεται με POST σε JSON μορφή στο `callback_url`, περιλαμβάνοντας το ίδιο `task_id` για συσχέτιση.

Παρακάτω ένα παράδειγμα.

Το Webhook callback είναι μια υπηρεσία που δέχεται HTTP αιτήματα. Ο προγραμματιστής πρέπει να αντικαταστήσει το URL με το δικό του HTTP server. Για επίδειξη, χρησιμοποιούμε το δημόσιο https://webhook.site/, όπου λαμβάνουμε ένα URL Webhook, π.χ.:

![](https://cdn.acedata.cloud/cjjfly.png)

Αντιγράψτε το URL, π.χ. `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`.

Ορίζουμε το πεδίο `callback_url` σε αυτό το URL μαζί με τα υπόλοιπα πεδία, π.χ.:

```shell
curl -X POST "https://api.acedata.cloud/v1/images/edits" \
  -H "Authorization: Bearer {token}" \
  -F "model=gpt-image-1" \
  -F "image[]=@test.png" \
  -F "prompt=Create a lovely gift basket with these items in it" \
  -F "callback_url=https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab"
```

Η άμεση απάντηση:

```json
{
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c"
}
```

Μετά από λίγο, στο Webhook URL θα δείτε το αποτέλεσμα επεξεργασίας:

```json
{
```

## Διαχείριση Σφαλμάτων

Σε περίπτωση σφάλματος, το API επιστρέφει κωδικό και μήνυμα σφάλματος, π.χ.:

- `400 token_mismatched`: Κακό αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακό αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διαπιστευτήριο.
- `429 too_many_requests`: Πάρα πολλά αιτήματα, υπερβήκατε το όριο ρυθμού.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή.
