Η OpenAI παρέχει πρόσφατα μια διεπαφή για τη δημιουργία αποκρίσεων μοντέλων. Παρέχετε εισόδους κειμένου ή εικόνας για τη δημιουργία εξόδων κειμένου ή εικόνας. Επιτρέψτε στο μοντέλο να καλέσει τον δικό σας προσαρμοσμένο κώδικα ή να χρησιμοποιήσει ενσωματωμένα εργαλεία, όπως αναζήτηση web ή αναζήτηση αρχείων, ώστε να χρησιμοποιήσει τα δικά σας δεδομένα ως εισόδους για τις αποκρίσεις του μοντέλου.

Αυτό το έγγραφο παρουσιάζει κυρίως τη διαδικασία χρήσης των λειτουργιών του OpenAI Responses API. Με αυτό, μπορούμε να χρησιμοποιήσουμε εύκολα την επίσημη λειτουργία δημιουργίας αποκρίσεων μοντέλων της OpenAI.

## GPT-6.1 Sol

Χρησιμοποιήστε `model: "gpt-6.1-sol"` για να επιλέξετε αυτό το μοντέλο. Υποστηρίζει ροή εξόδου, κλήση συναρτήσεων, δομημένη έξοδο και είσοδο εικόνας. Κατά την πρώτη εβδομάδα διάθεσης, είναι διαθέσιμο μόνο σε επαληθευμένους κατόχους ACE T1+ (τουλάχιστον 100.000 ACE) ή σε εξουσιοδοτημένους χρήστες· ο συγκεκριμένος χρόνος διάθεσης εξαρτάται από την ένδειξη πρόσβασης στην κονσόλα.

Τα επίπεδα συλλογισμού υποστηρίζουν `low`, `medium`, `high`, `xhigh` και `max`, ενώ προσωρινά δεν υποστηρίζονται τα `none` ή `minimal`. Συνιστάται να ξεκινήσετε με `reasoning: {"effort": "low"}`. Όταν η είσοδος υπερβαίνει τα 272.000 tokens, εφαρμόζεται η τιμολόγηση μεγάλου περιβάλλοντος για ολόκληρο το αίτημα, και η χρέωση εξαρτάται από την τρέχουσα τιμή στην κονσόλα.

## Διαδικασία αίτησης

Για να χρησιμοποιήσετε το OpenAI Responses API, μεταβείτε πρώτα στην [κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας και κρατήστε το ως εφεδρικό.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε ακόμη συνδεθεί ή εγγραφεί, θα ανακατευθυνθείτε αυτόματα στη σελίδα σύνδεσης, όπου θα σας προσκαλέσει να εγγραφείτε και να συνδεθείτε· αφού ολοκληρώσετε, θα επιστρέψετε αυτόματα στην τρέχουσα σελίδα.

**Ένα API Token αρκεί για την κλήση όλων των υπηρεσιών της πλατφόρμας, χωρίς να χρειάζεται να υποβάλετε ξεχωριστή αίτηση για κάθε υπηρεσία.** Η πρώτη αίτηση προσφέρει δωρεάν πίστωση, ώστε να μπορείτε να το δοκιμάσετε δωρεάν· όταν η πίστωση δεν επαρκεί, μπορείτε να επαναφορτίσετε το γενικό υπόλοιπο στην [κονσόλα](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Βασική χρήση

Στη συνέχεια, μπορείτε να συμπληρώσετε το αντίστοιχο περιεχόμενο στη διεπαφή, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Κατά την πρώτη χρήση αυτής της διεπαφής, πρέπει να συμπληρώσουμε τουλάχιστον τρία στοιχεία. Το ένα είναι το `authorization`, το οποίο μπορεί να επιλεγεί απευθείας από την αναπτυσσόμενη λίστα. Μια άλλη παράμετρος είναι το `model`, το `model` είναι η κατηγορία μοντέλου του επίσημου ιστότοπου OpenAI ChatGPT που επιλέγουμε να χρησιμοποιήσουμε· εδώ διαθέτουμε κυρίως 20 μοντέλα και για λεπτομέρειες μπορείτε να δείτε τα μοντέλα που παρέχουμε. Η τελευταία παράμετρος είναι το `input`, το `input` είναι ο πίνακας των ερωτημάτων που εισάγουμε· είναι ένας πίνακας, που σημαίνει ότι μπορούν να μεταφορτωθούν ταυτόχρονα πολλαπλά ερωτήματα, και κάθε ερώτημα περιλαμβάνει `role` και `content`, όπου το `role` υποδεικνύει τον ρόλο του ερωτώντος· παρέχουμε τρεις ταυτότητες, συγκεκριμένα `user`, `assistant`, `system`. Το άλλο, `content`, είναι το συγκεκριμένο περιεχόμενο της ερώτησής μας.

Παράλληλα, μπορείτε να παρατηρήσετε ότι στη δεξιά πλευρά υπάρχει η αντίστοιχη δημιουργία κώδικα κλήσης. Μπορείτε να αντιγράψετε τον κώδικα και να τον εκτελέσετε απευθείας ή να κάνετε απευθείας κλικ στο κουμπί «Try» για δοκιμή.

Συνήθεις προαιρετικές παράμετροι:

- `max_tokens`: Περιορίζει τον μέγιστο αριθμό token σε μία απάντηση.
- `temperature`: Τυχαιότητα παραγωγής, μεταξύ 0-2· όσο μεγαλύτερη η τιμή, τόσο μεγαλύτερη η απόκλιση.
- `n`: Πόσες υποψήφιες απαντήσεις θα παραχθούν κάθε φορά.
- `response_format`: Ρύθμιση μορφής επιστροφής.
- `tools`: Ορισμός κλήσης συναρτήσεων/εργαλείων.
- `background`: Αν θα εκτελείται ασύγχρονα στο παρασκήνιο.

## Απόκριση ροής

Αυτή η διεπαφή υποστηρίζει επίσης απόκριση ροής, κάτι που είναι πολύ χρήσιμο για τη σύνδεση με ιστοσελίδες και επιτρέπει την υλοποίηση εφέ εμφάνισης χαρακτήρα προς χαρακτήρα.

Εάν θέλετε να επιστρέφετε απαντήσεις σε ροή, μπορείτε να αλλάξετε την παράμετρο `stream ` στην κεφαλίδα του αιτήματος σε `true`.

Η τροποποίηση φαίνεται στην εικόνα, αλλά ο κώδικας κλήσης πρέπει να τροποποιηθεί αντίστοιχα για να υποστηρίζει απόκριση ροής.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Αφού αλλάξετε το `stream` σε `true`, το API θα επιστρέφει τα αντίστοιχα δεδομένα JSON γραμμή προς γραμμή, και στο επίπεδο κώδικα πρέπει να κάνουμε τις αντίστοιχες τροποποιήσεις για να λάβουμε τα αποτελέσματα ανά γραμμή.

Δείγμα κώδικα κλήσης Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Μπορείτε να δείτε ότι υπάρχουν πολλά `data` στην απόκριση, και το `delta` μέσα στο `data` είναι το πιο πρόσφατο περιεχόμενο της απάντησης, σε συμφωνία με το περιεχόμενο που παρουσιάστηκε παραπάνω. Το `delta` είναι το νέο περιεχόμενο της απάντησης και μπορείτε να το ενσωματώσετε στο σύστημά σας βάσει των αποτελεσμάτων. Η ροϊκή απόκριση έχει ως τελική κατάσταση το `response.completed` ή το `response.incomplete`· το `usage` στην τελική κατάσταση είναι η τελική χρήση token για αυτό το αίτημα και αποτελεί επίσης τη βάση χρέωσης.

Εάν ο πελάτης διακόψει τη σύνδεση πριν φτάσει η τελική κατάσταση, αυτό το αίτημα καταγράφεται ως ο πελάτης έκλεισε (499) και δεν θα χρεωθεί βάσει τοπικά εκτιμώμενων token· εάν η σύνδεση ολοκληρωθεί κανονικά αλλά δεν ληφθεί η τελική κατάσταση και το τελικό `usage`, αυτό το αίτημα καταγράφεται ως ελλιπής απόκριση (502) και επίσης δεν θα χρεωθεί βάσει εκτιμώμενων token. Όταν συναντήσετε αυτές τις δύο περιπτώσεις, παρακαλούμε ξεκινήστε ξανά το αίτημα.

Το επιστρεφόμενο αποτέλεσμα `data` έχει συνολικά πολλά πεδία, τα οποία παρουσιάζονται ως εξής:

- `item_id`, το ID που δημιουργείται για αυτήν την εργασία συνομιλίας και χρησιμοποιείται για τη μοναδική αναγνώριση αυτής της εργασίας συνομιλίας.
- `type`, ο τύπος της εργασίας Responses που δημιουργείται για αυτήν τη συνομιλία.
- `model `, το επιλεγμένο μοντέλο του επίσημου ιστότοπου OpenAI ChatGPT.
- `delta`, οι πληροφορίες απάντησης που παρέχει το ChatGPT για την ερώτηση.

Υποστηρίζεται επίσης η JavaScript, για παράδειγμα, ο κώδικας ροϊκής κλήσης για Node.js είναι ο εξής:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```


## Συνομιλία πολλαπλών γύρων

Εάν θέλετε να ενσωματώσετε τη λειτουργία συνομιλίας πολλαπλών γύρων, πρέπει να ανεβάσετε πολλαπλές ερωτήσεις στο πεδίο `input`. Το συγκεκριμένο παράδειγμα πολλαπλών ερωτήσεων φαίνεται στην παρακάτω εικόνα:

<p><img src="https://cdn.acedata.cloud/1jqwnf.png" width="400" className="m-auto" /></p>

Δείγμα κώδικα κλήσης Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"},{"role":"assistant","content":"Hello! How can I help you today? 😊"},{"role":"user","content":"What did I just say?"}]
}

response = requests.post(url, json=payload, headers=headers)
```

## Μοντέλο όρασης

Το gpt-4o είναι ένα πολυτροπικό μεγάλο γλωσσικό μοντέλο που αναπτύχθηκε από την OpenAI· προσθέτει δυνατότητες οπτικής κατανόησης πάνω στη βάση του GPT-4. Αυτό το μοντέλο μπορεί να επεξεργάζεται ταυτόχρονα εισόδους κειμένου και εικόνας, επιτυγχάνοντας διατροπική κατανόηση και παραγωγή.
Η επεξεργασία κειμένου με το μοντέλο gpt-4o είναι σύμφωνη με το βασικό περιεχόμενο χρήσης που αναφέρθηκε παραπάνω· παρακάτω θα παρουσιαστεί συνοπτικά ο τρόπος χρήσης των δυνατοτήτων επεξεργασίας εικόνας του μοντέλου.

Η χρήση των δυνατοτήτων επεξεργασίας εικόνας του μοντέλου gpt-4o γίνεται κυρίως με την προσθήκη ενός πεδίου `type` στο αρχικό περιεχόμενο `content`. Μέσω αυτού του πεδίου μπορεί να αναγνωριστεί αν αυτό που μεταφορτώνεται είναι κείμενο ή εικόνα, ώστε να χρησιμοποιηθούν οι δυνατότητες επεξεργασίας εικόνας του μοντέλου gpt-4o. Παρακάτω περιγράφονται κυρίως δύο τρόποι κλήσης αυτής της λειτουργίας, με Curl και Python.

- Μέθοδος σεναρίου Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Μέθοδος σεναρίου Python

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Διαχείριση σφαλμάτων

Κατά την κλήση του API, εάν παρουσιαστεί σφάλμα, το API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`：Μη έγκυρο αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`：Μη έγκυρο αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`：Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διακριτικό εξουσιοδότησης.
- `429 too_many_requests`：Πάρα πολλά αιτήματα, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`：Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.
