## Δυναμικός κατάλογος μοντέλων

Μπορείτε πρώτα να ανοίξετε τον [κατάλογο μοντέλων](https://platform.acedata.cloud/models) για να δείτε τα τρέχοντα ονόματα μοντέλων, για παράδειγμα `claude-opus-5`, `gpt-6-sol`. Όταν χρειάζεται να επιβεβαιώσετε ότι τα διαπιστευτήρια Coding και το πρωτόκολλο API ταιριάζουν, χρησιμοποιήστε έγκυρα διαπιστευτήρια Coding Application για να υποβάλετε αίτημα:

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_TOKEN"
```

Ο κατάλογος μοντέλων θα αλλάζει συνεχώς· δεν διατηρείται σε αυτό το κείμενο σταθερός αριθμός ή στατική λίστα μοντέλων. Το `id` κάθε εγγραφής στην απόκριση είναι το **όνομα μοντέλου** που μπορεί να περαστεί απευθείας στην παράμετρο API `model`, για παράδειγμα το `{"id":"deepseek-v4-pro"}` αντιστοιχεί στη συμπλήρωση `deepseek-v4-pro`· δεν είναι UUID υπηρεσίας, API ή Application. Το `/v1/models` επιστρέφει τον παγκόσμιο κατάλογο μοντέλων και δεν φιλτράρεται αυτόματα βάσει των διαπιστευτηρίων Coding· πριν από τη διαμόρφωση, εξακολουθεί να απαιτείται διασταυρωμένη επιβεβαίωση με το API scope των διαπιστευτηρίων, το επιλεγμένο πρωτόκολλο και το εύρος συμβατότητας του πελάτη.

## Συνήθης αντιμετώπιση προβλημάτων

- **Ανεπαρκές υπόλοιπο**: Μεταβείτε στην [κονσόλα Applications](https://platform.acedata.cloud/console/applications), βρείτε το Coding Application και ανανεώστε ενεργά την αγορά.
- **Ο πελάτης εξακολουθεί να ζητά την αρχική διεύθυνση**: Επιβεβαιώστε ότι η διαμόρφωση ανήκει στον ίδιο χρήστη και χώρο εργασίας που εκκινεί τον πελάτη, και επανεκκινήστε τον πελάτη αφού τον τερματίσετε πλήρως.
- **Το όνομα μοντέλου δεν είναι διαθέσιμο**: Υποβάλετε ξανά αίτημα στο `/v1/models`, ελέγξτε αν το συμπληρωμένο όνομα μοντέλου είναι ακριβώς ίδιο με το `id` στον κατάλογο, το API scope των διαπιστευτηρίων και το πρωτόκολλο που υποστηρίζει ο πελάτης.
- **Το Token δεν μπορεί να καλέσει τη διεπαφή**: Επιβεβαιώστε ότι τα διαπιστευτήρια ανήκουν σε Coding Application και ελέγξτε το `allowed_api_ids` και τα δικαιώματα API της εφαρμογής.
