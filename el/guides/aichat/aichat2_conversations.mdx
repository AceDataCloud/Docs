Αναπλήρωση



Το API AI Chat v2 (`/aichat2/conversations`) είναι μια νέα γενιά διεπαφής συνομιλιών και αποτελεί μια ολοκληρωμένη αναβάθμιση του [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Βασίζεται στην απλότητα και τη φιλοξενία συνομιλιών πολλαπλών γύρων του v1 και επεκτείνει τις δυνατότητές του με:

- **Πολυτροπική είσοδο χρήστη**: Μέσω του δομημένου πεδίου `message`, μπορείτε να μεταφέρετε απευθείας κείμενο + εικόνες + μπλοκ αρχείων, χωρίς να χρειάζεται να τα επισυνάψετε έμμεσα μέσω του `references` εκ των προτέρων.
- **Κλήσεις εργαλείων τύπου Agent**: Περιλαμβάνει ενσωματωμένο σύνολο εργαλείων για αναζήτηση στο διαδίκτυο, ανάκτηση ιστοσελίδων, ανάγνωση αρχείων κ.λπ., ενώ μπορεί επίσης να συνδεθεί με διακομιστές MCP που έχουν εξουσιοδοτηθεί από τον χρήστη (Google Drive, Notion, Slack, GitHub κ.λπ.). Το μοντέλο μπορεί να καλέσει αυτόνομα εργαλεία πολλές φορές μέσα σε ένα μόνο αίτημα, προκειμένου να ολοκληρώσει σύνθετες εργασίες.
- **Δομημένα συμβάντα ροής**: Μέσω των `accept: text/event-stream` ή `application/x-ndjson`, μπορείτε να λαμβάνετε συμβάντα ανά token, όπως `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` κ.λπ., διευκολύνοντας την ξεχωριστή απόδοση κάθε τύπου στην πλευρά του frontend.
- **Δυνατότητα διακοπής / συνέχισης**: Όταν το μοντέλο χρειάζεται πρόσθετες πληροφορίες από τον χρήστη, εκπέμπει ένα συμβάν `ask_user_question` και διακόπτει προσωρινά την εκτέλεση. Στην επόμενη κλήση, αρκεί να συμπληρώσετε την απάντηση μέσω του `tool_results` για να συνεχιστεί η διαδικασία.
- **Νέες ενέργειες CRUD**: Στο ίδιο endpoint, μπορείτε να χρησιμοποιήσετε το πεδίο `action` για να ολοκληρώσετε τις λειτουργίες `retrieve` / `retrieve_batch` / `update` / `delete`, χωρίς να χρειάζεστε πρόσθετο API διαχείρισης συνομιλιών.
- **Συνεχώς ενημερωμένη λίστα μοντέλων**: Από προεπιλογή, υποστηρίζονται σύγχρονα μοντέλα όπως GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 κ.λπ.

Ταυτόχρονα, στο επίπεδο του σώματος του αιτήματος, είναι **πλήρως συμβατό προς τα πίσω με το v1**: αρκεί να μεταφέρετε μόνο τα `model` + `question` (+ προαιρετικά `stateful` / `id` / `references` / `preset`) για να λάβετε μια ισοδύναμη απόκριση JSON `{answer, id}` με εκείνη του v1. Επομένως, η μετάβαση από το `/aichat/conversations` δεν απαιτεί επανεγγραφή του client· αρκεί να αλλάξετε τη διαδρομή σε `/aichat2/conversations`.

> Εάν χρησιμοποιείτε αυτήν τη στιγμή το `/aichat/conversations`, η παλιά διεπαφή θα εξακολουθήσει να υποστηρίζεται. Μπορείτε να πραγματοποιήσετε τη μετάβαση με τον δικό σας ρυθμό.

## Διαδικασία αίτησης

Για να χρησιμοποιήσετε το API AI Chat v2, μεταβείτε πρώτα στην [κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας και να το φυλάξετε για μελλοντική χρήση.

![]()

Εάν δεν έχετε συνδεθεί ή εγγραφεί ακόμη, θα ανακατευθυνθείτε αυτόματα στη σελίδα σύνδεσης, όπου θα σας ζητηθεί να εγγραφείτε και να συνδεθείτε. Μόλις ολοκληρωθεί η διαδικασία, θα επιστρέψετε αυτόματα στην τρέχουσα σελίδα.

**Ένα API Token αρκεί για να καλέσετε όλες τις υπηρεσίες της πλατφόρμας, χωρίς να χρειάζεται να υποβάλετε ξεχωριστή αίτηση για κάθε υπηρεσία.** Κατά την πρώτη αίτηση παρέχεται δωρεάν πίστωση, ώστε να μπορείτε να δοκιμάσετε την υπηρεσία δωρεάν. Όταν η διαθέσιμη πίστωση δεν επαρκεί, μπορείτε να προσθέσετε γενικό υπόλοιπο μέσω της [Κονσόλας](https://platform.acedata.cloud/console/coin).

## Βασική χρήση

Η απλούστερη μέθοδος χρήσης είναι ακριβώς ίδια με εκείνη του v1: μεταφέρετε τα `model` + `question` και λαμβάνετε `{answer, id}`.

Παράδειγμα CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Αποτέλεσμα επιστροφής:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Παράδειγμα Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Συνομιλίες πολλαπλών γύρων

Όπως και στο v1, μεταφέρετε `stateful: true` για να ενεργοποιήσετε την αποθήκευση της συνομιλίας. Το API θα επιστρέψει ένα `id`. Στα επόμενα αιτήματα, αρκεί να συμπεριλάβετε ξανά το `id` για να συνεχίσετε τη συνομιλία, χωρίς να χρειάζεται να διαχειρίζεστε μόνοι σας το ιστορικό των messages.

Πρώτο αίτημα:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Απάντηση:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Δεύτερο αίτημα, συμπεριλαμβάνοντας το ίδιο `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "Ποιος είναι ο αριθμός που σου ζήτησα να θυμάσαι μόλις τώρα;"
  }'
```

```json
{
  "answer": "Ο αριθμός που μου ζήτησες να θυμάμαι είναι 42.",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> Το `stateful` είναι `true` από προεπιλογή. Η παράλειψή του ισοδυναμεί με τη ρητή μεταβίβαση της τιμής `true`. Η ρύθμιση `stateful: false` παραλείπει τη φόρτωση του ιστορικού προηγούμενων συνομιλιών· αυτό δεν σημαίνει ότι το αποτέλεσμα του τρέχοντος γύρου δεν θα αποθηκευτεί, ούτε ισχύει για ροές εργαλείων που απαιτούν παύση και συνέχιση.

### Μεγάλες συνομιλίες και διατήρηση του αρχικού κειμένου

Η συμπίεση του περιβάλλοντος απλώς οργανώνει το περιεχόμενο που αποστέλλεται στο μοντέλο στον τρέχοντα γύρο· δεν αντικαθιστά το αποθηκευμένο ιστορικό συνομιλίας. Μέσω της `action: retrieve` εξακολουθεί να είναι δυνατή η ανάγνωση όλων των αποθηκευμένων μηνυμάτων· η ρητή επεξεργασία ή διαγραφή μιας συνομιλίας εξακολουθεί να ισχύει σύμφωνα με το αίτημα.

Το μοντέλο μπορεί να αναζητήσει και να διαβάσει τμηματικά το αρχικό ιστορικό μέσα στην τρέχουσα συνομιλία. Όταν χρειάζεται να συνεχιστεί η επεξεργασία ενός άρθρου, να γίνει παραπομπή σε αριθμούς ή να προετοιμαστεί κάτι για δημοσίευση, πρέπει να αναγνωστεί το αντίστοιχο αρχικό κείμενο και δεν πρέπει να αντικαθίσταται το κυρίως κείμενο από μια σύνοψη. Αυτή η δυνατότητα δεν επαναφέρει αυτόματα μηνύματα που έχουν ήδη χαθεί σε παλαιότερες εκδόσεις.

Εάν αποτύχει η οργάνωση του περιβάλλοντος, διατηρήστε το αναγνωριστικό συνομιλίας και ελέγξτε το συμβάν `error`· η υπηρεσία δεν θα αντικαταστήσει το αρχικό κείμενο με μια κενή σύνοψη. Οι λειτουργίες εργαλείων που ολοκληρώθηκαν πριν από την αποτυχία ενδέχεται να εξακολουθούν να ισχύουν. Ελέγξτε πρώτα τα αποτελέσματά τους, ώστε να αποφύγετε τη διπλή δημιουργία ή δημοσίευση. Όταν μια μεμονωμένη συνομιλία φτάσει το όριο αποθήκευσης, θα εμφανιστεί σαφές μήνυμα σφάλματος. Οι ήδη αποθηκευμένες εγγραφές δεν θα διαγραφούν μέσω περικοπής για να ελευθερωθεί χώρος· μπορείτε να εξαγάγετε το απαραίτητο περιεχόμενο και στη συνέχεια να ξεκινήσετε μια νέα συνομιλία.

## Αποκρίσεις σε ροή

Η v2 υποστηρίζει δύο μορφές ροής, οι οποίες επιλέγονται μέσω της κεφαλίδας `accept`:

| Σενάριο | `accept` | Μορφή δεδομένων |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web frontend / EventSource | `text/event-stream` | `data: {json}\n\n`, με τελική γραμμή `data: [DONE]\n\n` |
| Διακομιστής / CLI / ανάλυση ροής Node | `application/x-ndjson` | Ένα αντικείμενο JSON ανά γραμμή |
| Χωρίς ανάγκη ροής | `application/json` (προεπιλογή) | Επιστρέφει ταυτόχρονα `{answer, id}` |

### Παράδειγμα NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "Παρουσίασε το Hangzhou σε τρεις προτάσεις.",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # Συμβατό με την v1: τα τμηματικά αποσπάσματα παρέχονται ταυτόχρονα μέσω του πεδίου delta_answer
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Κάθε γραμμή NDJSON είναι ένα δομημένο συμβάν. Το συνηθέστερο είναι το `text_delta`:

```json
{"type":"text_delta","content":"Χαν","delta_answer":"Χαν","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"γκ","delta_answer":"γκ","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"τζ","delta_answer":"τζ","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Παράδειγμα SSE

Στα προγράμματα περιήγησης, το `EventSource` δεν υποστηρίζει προσαρμοσμένο σώμα αιτήματος. Συνιστάται η χρήση του `fetch` σε συνδυασμό με χειροκίνητη ανάλυση και διαχωρισμό σε τμήματα μέσω του `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "Παρουσίασε το Hangzhou σε τρεις προτάσεις.",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Τύποι συμβάντων ροής

| `type` | Σημασία |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta` | Τμηματικό κείμενο της απάντησης του βοηθού. Το `content` περιέχει το νέο περιεχόμενο· για συμβατότητα με την v1, το ίδιο συμβάν περιλαμβάνει επίσης τα `delta_answer` (ίσο με το `content`) και `id`. |
| `thinking` | Η διαδικασία σκέψης του μοντέλου (εμφανίζεται μόνο όταν το επιλεγμένο μοντέλο εκθέτει τη λειτουργία reasoning). |
| `tool_use` | Το μοντέλο αποφασίζει να καλέσει ένα εργαλείο. Το συμβάν περιλαμβάνει τα `tool_id`, `tool_name`, `input`. |
| `tool_result` | Το αποτέλεσμα εκτέλεσης του εργαλείου, το οποίο αντιστοιχίζεται με το προηγούμενο `tool_use` μέσω του `tool_id`. Το `is_error` υποδεικνύει εάν υπήρξε αποτυχία. |
| `card` | Δομημένη κάρτα που παράγεται από ένα εργαλείο (όπως εικόνες ή προεπισκοπήσεις συνδέσμων), κατάλληλη για άμεση απόδοση. |
| `citation` | URL πηγής που χρησιμοποιείται για να συμπληρώσει τις παραπομπές του αντίστοιχου τμήματος κειμένου. |
| `ask_user_question` | Εκπέμπεται όταν το μοντέλο χρειάζεται πρόσθετες πληροφορίες από τον χρήστη. Η συνομιλία μεταβαίνει στην κατάσταση `awaiting_user_input`. Για λεπτομέρειες, ανατρέξτε παρακάτω στην ενότητα [Συνέχιση μιας συνομιλίας σε παύση](#恢复暂停的对话). |
| `artifact` | Αυτοτελές παραγόμενο αποτέλεσμα του μοντέλου (όπως μπλοκ κώδικα ή έγγραφα), το οποίο μπορεί να αποθηκευτεί ή να ληφθεί. |
| `system_message` | Μήνυμα πληροφοριών συστήματος (όχι περιεχόμενο χρήστη ή βοηθού), που χρησιμοποιείται μόνο για ειδοποιήσεις στο UI. |
| `compact` | Το περιβάλλον του μοντέλου έχει οργανωθεί· τα αποθηκευμένα αρχικά μηνύματα παραμένουν αμετάβλητα και ο πελάτης δεν χρειάζεται να διαγράψει το ιστορικό συνομιλίας. |
| `error` | Παρουσιάστηκε σφάλμα στον τρέχοντα γύρο και το `message` περιγράφει το περιεχόμενο του σφάλματος. |
| `done` | Η τελική εγγραφή συνομιλίας του τρέχοντος γύρου αποθηκεύτηκε με επιτυχία. Περιλαμβάνει το `usage` (με τα `prompt_tokens` / `completion_tokens` / `total_tokens`) και το `terminal_reason`· πρέπει και πάλι να αξιολογηθεί ο λόγος τερματισμού για να διαπιστωθεί εάν η εργασία ολοκληρώθηκε. |
Για τους clients που ενδιαφέρονται μόνο για την τελική απάντηση, η συνένωση των `content` όλων των `text_delta` είναι ισοδύναμη με το `answer` στη λειτουργία `application/json`.

## Είσοδος πολλαπλών μορφών (Multimodal Input)

Εάν η είσοδος του χρήστη περιλαμβάνει εικόνες ή αρχεία, μεταβιβάστε το `message` (πίνακας) αντί για το `question`. Κάθε στοιχείο του πίνακα είναι ένα μπλοκ περιεχομένου:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "Πόσες γάτες υπάρχουν σε αυτήν την εικόνα;" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Υποστηριζόμενοι τύποι μπλοκ:

- `text` — Απλό κείμενο, απαιτείται το πεδίο `text`.
- `image_url` — Εικόνα, απαιτείται το `image_url.url`.
- `file_url` — Αρχείο (PDF, CSV, TXT κ.λπ.), απαιτείται το `file_url.url`.

### Σχέση με το `references` της v1

Για συμβατότητα με παλαιότερους clients, η v2 εξακολουθεί να αναγνωρίζει το πεδίο `references: ["https://...", ...]`:

- Οι καταλήξεις URL `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif` μετατρέπονται αυτόματα σε μπλοκ `image_url`.
- Οι υπόλοιπες επεκτάσεις μετατρέπονται σε μπλοκ `file_url`.
- Εάν παρέχεται ταυτόχρονα και το `question`, προστίθεται στην αρχή ως μπλοκ `text`.

Επομένως, εάν θέλετε απλώς να μεταβείτε από τη v1 χωρίς να αλλάξετε το σώμα του αιτήματος, αρκεί να αλλάξετε τη διαδρομή σε `/aichat2/conversations` και η αρχική χρήση του `references` θα συνεχίσει να λειτουργεί κανονικά.

Εάν χρειάζεστε πιο λεπτομερή έλεγχο (για παράδειγμα, να τοποθετήσετε πολλές εικόνες ανάμεσα σε τμήματα κειμένου ή όταν η σειρά έχει σημασία), χρησιμοποιήστε απευθείας τον πίνακα `message`.

## Κλήσεις εργαλείων και MCP

Η βασική βελτίωση της v2 είναι ότι το μοντέλο μπορεί να καλεί αυτόνομα εργαλεία για να ολοκληρώνει εργασίες πολλαπλών βημάτων. **Αυτό είναι ενεργοποιημένο από προεπιλογή** και δεν απαιτεί καμία πρόσθετη ρύθμιση από τον client στο αίτημα. Συνήθη σενάρια:

- Ο χρήστης ρωτά «Βοήθησέ με να αναζητήσω πρόσφατες νέες εκθέσεις στη Σαγκάη» → Το μοντέλο καλεί την ενσωματωμένη αναζήτηση ιστού → Οργανώνει τα αποτελέσματα σε απάντηση.
- Ο χρήστης ρωτά «Διάβασε αυτό το PDF και, στη συνέχεια, γράψε μια περίληψη» → Το μοντέλο καλεί το file_read → Συντάσσει την περίληψη.
- Ο χρήστης έχει ήδη εξουσιοδοτήσει το Google Drive / GitHub / Notion κ.λπ. στις [Connections](https://platform.acedata.cloud/connections) → Το μοντέλο μπορεί να καλεί τα αντίστοιχα εργαλεία MCP για να διαβάζει και να γράφει τα δεδομένα του.

Στη ροή NDJSON / SSE, οι κλήσεις εργαλείων εμφανίζονται μέσω δύο τύπων συμβάντων: `tool_use` και `tool_result`, για παράδειγμα:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Εάν δεν θέλετε να εμφανίζετε στο frontend τις λεπτομέρειες των κλήσεων εργαλείων, απλώς αγνοήστε τις κατηγορίες συμβάντων `tool_use` / `tool_result` / `card` / `citation`. Η τελική έξοδος του μοντέλου εξακολουθεί να μεταδίδεται μέσω της ροής `text_delta`.

Το `max_turns` μπορεί να περιορίσει τον μέγιστο αριθμό γύρων αυτοματοποιημένων κλήσεων εργαλείων του μοντέλου στο συγκεκριμένο αίτημα, με εύρος 1–500. Εάν παραλειφθεί, η προεπιλεγμένη τιμή είναι 500. Η ρύθμισή του σε μικρή τιμή (για παράδειγμα, `max_turns: 1`) μπορεί να επιβάλει μία μόνο απάντηση, χωρίς να επιτρέπονται κλήσεις εργαλείων.

## Ασύγχρονη εκτέλεση και εξουσιοδότηση χωρίς επίβλεψη

Εάν η κλήση σας προέρχεται από ένα Alert Webhook, CI/CD, ένα σύστημα παρακολούθησης ή άλλη εργασία παρασκηνίου, μπορείτε να ορίσετε `async: true`, ώστε το API να επιστρέψει αμέσως ένα αναγνωριστικό εργασίας και η εκτέλεση να συνεχιστεί στο παρασκήνιο:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Η υπηρεσία μου εξέπεμψε συναγερμό. Ειδοποίησε την ομάδα WeChat «AceDataCloud团队» χρησιμοποιώντας τον προσωπικό μου λογαριασμό WeChat……"
}
```

Παράδειγμα επιστροφής:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Στη συνέχεια, μπορείτε να χρησιμοποιήσετε το `action: retrieve` + `id` για να ανακτήσετε τα αποτελέσματα της συνομιλίας. Μπορείτε επίσης να παρέχετε ένα `callback_url`, στο οποίο η πλατφόρμα θα στείλει ένα POST με `{ status, answer, usage, error }` μόλις ολοκληρωθεί η εργασία. Το `callback_url` πρέπει να χρησιμοποιεί `http` / `https` και δεν μπορεί να είναι απευθείας η διεύθυνση `localhost` ή μια ιδιωτική διεύθυνση IP σε μορφή literal.

Συνήθως, οι εργασίες παρασκηνίου δεν έχουν κάποιον διαθέσιμο να κάνει κλικ για επιβεβαίωση. Εάν θέλετε ορισμένα Skill ή MCP Server να εκτελούν ενέργειες όπως αποστολή, δημοσίευση, εγγραφή κ.λπ. χωρίς επίβλεψη, παρακαλούμε να μεταβιβάσετε ρητά μια λίστα προεξουσιοδότησης στο σώμα του αιτήματος:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Η υπηρεσία μου εξέπεμψε συναγερμό. Ειδοποίησε την ομάδα WeChat «AceDataCloud团队» χρησιμοποιώντας τον προσωπικό μου λογαριασμό WeChat……"
}
```

Οι τιμές στο `allowed_skills` είναι τα slug των συνδεδεμένων Skill. Οι τιμές στο `allowed_mcp_servers` είναι τα slug των συνδεδεμένων MCP Server. Τα Skill / MCP Server που δεν περιλαμβάνονται στη λίστα προεξουσιοδότησης μπορούν, στη λειτουργία χωρίς επίβλεψη, μόνο να εμφανίζουν προεπισκόπηση, να εκτελούν dry-run ή να αρνούνται την εκτέλεση λειτουργιών εγγραφής.

Εάν χρειάζεστε πιο λεπτομερή έλεγχο, μπορείτε επίσης να χρησιμοποιήσετε το ισοδύναμο αντικείμενο `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Η προεξουσιοδότηση αποτελείται αποκλειστικά από αυτές τις δύο λίστες: εάν μια λίστα είναι κενή, δεν εξουσιοδοτείται καμία δυνατότητα και δεν απαιτείται πρόσθετο πεδίο ενεργοποίησης/απενεργοποίησης.

Σημείωση: Η προεξουσιοδότηση σημαίνει μόνο ότι «το συγκεκριμένο αίτημα επιτρέπει σε αυτές τις δυνατότητες να παρακάμπτουν την ανθρώπινη επιβεβαίωση στη λειτουργία χωρίς επίβλεψη». Το συγκεκριμένο Skill εξακολουθεί να πρέπει να υποστηρίζει το `--unattended-confirm` ή τον αντίστοιχο μηχανισμό ασφαλείας. Διαφορετικά, θα συνεχίσει να εκτελεί dry-run και δεν θα πραγματοποιεί απευθείας λειτουργίες εγγραφής.

## Συνέχιση των παγωμένων συνομιλιών

Ορισμένα εργαλεία επιτρέπουν στο μοντέλο να «κάνει μια ερώτηση στον χρήστη». Σε αυτήν την περίπτωση, το μοντέλο εκπέμπει ένα συμβάν `ask_user_question` και η συνομιλία παγώνει στην κατάσταση `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Θέλετε η αναφορά που θα δημιουργηθεί να είναι στα Κινεζικά ή στα Αγγλικά;",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Στο frontend, αποδώστε αυτό το συμβάν ως κάρτα, ώστε ο χρήστης να επιλέξει μια απάντηση. Στη συνέχεια, ξεκινήστε το επόμενο αίτημα χρησιμοποιώντας το ίδιο `id` και συμπληρώστε την απάντηση μέσω του `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

Το `tool_use_id` στο σώμα του αιτήματος **πρέπει** να είναι ακριβώς ίδιο με το `tool_id` κατά την παύση· διαφορετικά, θα επιστραφεί σφάλμα 400. Όταν το αίτημα περιλαμβάνει ταυτόχρονα `tool_results`, τα πεδία `question` / `message` / `references` θα αγνοηθούν.

Εάν ο χρήστης αποφασίσει να εγκαταλείψει αυτό το ερώτημα, αρκεί να στείλει απευθείας ένα νέο `question` / `message` και η πλατφόρμα θα επισημάνει αυτόματα την κλήση εργαλείου που βρίσκεται σε παύση ως «παραλείφθηκε από τον χρήστη».

## Διαχείριση συνεδριών (CRUD)

Η v2 παρέχει ελαφριά διαχείριση συνεδριών μέσω του πεδίου `action` στο ίδιο endpoint, χωρίς να απαιτείται ξεχωριστό API.

### `action: retrieve` —— Ανάκτηση μιας συνεδρίας

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Επιστρέφει το πλήρες έγγραφο της συνεδρίας (συμπεριλαμβανομένου του ιστορικού `messages`, του `model`, του `title`, του `tools_used` κ.λπ.).

### `action: retrieve_batch` —— Λίστα περιλήψεων συνεδριών

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Επιστρέφει `{ items: [...], total }`. **Οι περιλήψεις δεν περιλαμβάνουν το `messages`**, επομένως είναι κατάλληλες για λίστες πλευρικής γραμμής· όταν ο χρήστης ανοίξει μια συνεδρία, χρησιμοποιήστε στη συνέχεια το `action: retrieve` για να ανακτήσετε ξεχωριστά τα πλήρη μηνύματά της.

Προαιρετικές παράμετροι φιλτραρίσματος: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Αλλαγή τίτλου ή επανεγγραφή ιστορικού

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Σχέδιο ταξιδιού στη Χανγκζού"
}
```

Μπορεί επίσης να μεταβιβαστεί το `messages`, αλλά ο διακομιστής θα εκτελέσει αυστηρή επικύρωση του schema (πρέπει να έχει τη μορφή `ToolUseContent` μετά τη συγχώνευση), διαφορετικά θα επιστραφεί σφάλμα 400. Γενικά, συνιστάται η χρήση του μόνο για την αλλαγή του `title`.

### `action: delete` —— Διαγραφή μιας συνεδρίας

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Επιστρέφει `{ id, success: true }`. Μετά τη διαγραφή, η συνεδρία δεν μπορεί να ανακτηθεί, επομένως επιβεβαιώστε πριν από την κλήση.

## Ομαλή μετάβαση από την v1

Εάν χρησιμοποιείτε ήδη το [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), η μετάβαση στην v2 απαιτεί σχεδόν μηδενικές αλλαγές στον κώδικα:

1. Αλλάξτε το URL από `https://api.acedata.cloud/aichat/conversations` σε `https://api.acedata.cloud/aichat2/conversations`.
2. Εάν προηγουμένως χρησιμοποιούσατε ονόματα μοντέλων της v1 (όπως `gpt-3.5`, `gpt-4-browsing` κ.λπ.), κατά τη μετάβαση στην v2 συνιστάται να αναβαθμίσετε σε σύγχρονα μοντέλα (όπως `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` κ.λπ.).
3. Τα πεδία της ροής NDJSON παραμένουν συμβατά προς τα πίσω: κάθε συμβάν `text_delta` εξακολουθεί να περιλαμβάνει τα `delta_answer` και `id`, επομένως οι υπάρχοντες clients που αναλύουν το `delta_answer` ανά γραμμή δεν χρειάζονται αλλαγές.

Μετά τη μετάβαση, μπορείτε να ενεργοποιήσετε τις νέες δυνατότητες της v2 ανάλογα με τις ανάγκες σας (πολυτροπικό `message`, SSE, κλήσεις εργαλείων, CRUD μέσω `action`) και να προχωρήσετε σταδιακά.

## Διαχείριση σφαλμάτων

Οι αποκρίσεις σφαλμάτων έχουν ενιαία μορφή:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Συνήθη σφάλματα:

- `400 bad_request`: Λείπουν υποχρεωτικά πεδία, το `tool_use_id` δεν ταιριάζει, το schema του `messages` είναι μη έγκυρο κ.λπ.
- `401 invalid_token`: Η κεφαλίδα `authorization` δεν είναι σωστή.
- `404 not_found`: Η συνεδρία που αντιστοιχεί στο `id` δεν υπάρχει κατά την εκτέλεση του `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: Η συνεδρία υπερβαίνει το όριο αποθήκευσης και δεν έχουν αντικατασταθεί οι υπάρχουσες αποθηκευμένες εγγραφές.
- `429 too_many_requests`: Έχει ενεργοποιηθεί ο περιορισμός ρυθμού αιτημάτων.
- `503 context_compaction_failed`: Η συμπύκνωση του περιβάλλοντος απέτυχε, αλλά οι υπάρχουσες εγγραφές διατηρούνται.
- `500 conversation_persist_failed`: Η τελική αποθήκευση αυτού του γύρου απέτυχε· η λήψη κειμένου δεν σημαίνει ότι η τελική εγγραφή αποθηκεύτηκε επιτυχώς. Αναζητήστε τη συνεδρία χρησιμοποιώντας το ID της.
- `500 chat_error`: Η υπηρεσία δεν είναι προσωρινά διαθέσιμη ή δεν δημιουργήθηκε περιεχόμενο σε αυτόν τον γύρο (δεν θα υπάρξει χρέωση).

Στις αποκρίσεις ροής, τα σφάλματα αποστέλλονται ως συμβάντα `{"type":"error","message":"..."}` και στη συνέχεια η ροή τερματίζεται. Το `[DONE]` υποδηλώνει μόνο ότι ολοκληρώθηκε η μετάδοση· όταν υπάρχει `error`, δεν πρέπει να θεωρείται επιτυχία και δεν θα αποσταλεί επιτυχές συμβάν `done`.

## Συμπέρασμα

Το AI Chat v2 API, διατηρώντας τη συμβατότητα προς τα πίσω με την v1, αναβαθμίζει τις συνομιλίες από «ερωταπαντήσεις ενός / πολλών γύρων» σε «παρατηρήσιμες συνομιλίες τύπου Agent»: πολυτροπικές είσοδοι, κλήσεις εργαλείων, δυνατότητα παύσης / συνέχισης, δομημένα συμβάντα ροής και ενσωματωμένο CRUD. Συνιστάται οι νέες ενσωματώσεις να χρησιμοποιούν απευθείας την v2· οι υπάρχουσες ενσωματώσεις της v1 μπορούν να μεταβούν ομαλά σε αυτήν σταδιακά. Εάν έχετε οποιεσδήποτε ερωτήσεις, μη διστάσετε να επικοινωνήσετε με την ομάδα τεχνικής υποστήριξής μας.
