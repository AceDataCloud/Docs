Το AI Chat v2 API (`/aichat2/conversations`) είναι η νέας γενιάς διεπαφή συνομιλίας και μια πλήρως αναβαθμισμένη έκδοση του [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Με βάση την απλότητα και τη διαχειριζόμενη πολυγύρικη συνομιλία του v1, επεκτείνει:

- **Πολυτροπική είσοδο χρήστη**: Χρησιμοποιήστε το δομημένο πεδίο `message` για να στείλετε απευθείας μπλοκ κειμένου + εικόνων + αρχείων, χωρίς να χρειάζεται πρώτα έμμεση επισύναψη μέσω `references`.
- **Κλήση εργαλείων τύπου Agent**: Περιλαμβάνει ένα ενσωματωμένο σύνολο εργαλείων για διαδικτυακή αναζήτηση, ανάκτηση ιστοσελίδων, ανάγνωση αρχείων κ.λπ., και μπορεί να προσαρτήσει διακομιστές MCP που έχουν εξουσιοδοτηθεί από τον χρήστη (Google Drive, Notion, Slack, GitHub κ.λπ.). Το μοντέλο μπορεί να καλεί αυτόνομα εργαλεία σε πολλούς γύρους μέσα σε ένα αίτημα για να ολοκληρώνει σύνθετες εργασίες.
- **Δομημένα συμβάντα ροής**: Μέσω `accept: text/event-stream` ή `application/x-ndjson`, μπορείτε να λάβετε συμβάντα όπως `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` κ.λπ. ανά token, διευκολύνοντας την ξεχωριστή απόδοση στο frontend ανάλογα με τον αντίστοιχο τύπο.
- **Διακοπτόμενο / ανακτήσιμο**: Όταν το μοντέλο χρειάζεται από τον χρήστη συμπληρωματικές πληροφορίες, εκπέμπει το συμβάν `ask_user_question` και τίθεται σε παύση. Στην επόμενη κλήση, απλώς συμπληρώστε ξανά την απάντηση μέσω `tool_results` για να συνεχίσει.
- **Νέες ενέργειες CRUD**: Στο ίδιο endpoint, ολοκληρώστε `retrieve` / `retrieve_batch` / `update` / `delete` μέσω του πεδίου `action`, χωρίς να απαιτείται πρόσθετο API διαχείρισης συνεδριών.
- **Συνεχώς ενημερωμένη λίστα μοντέλων**: Από προεπιλογή ενσωματώνει σύγχρονα μοντέλα όπως GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 κ.λπ.

Παράλληλα, είναι **πλήρως συμβατό προς τα πίσω με το v1** σε επίπεδο σώματος αιτήματος: στείλτε μόνο `model` + `question` (+ προαιρετικά `stateful` / `id` / `references` / `preset`) για να λάβετε μια JSON απόκριση `{answer, id}` ισοδύναμη με του v1. Επομένως, για μετεγκατάσταση από το `/aichat/conversations`, δεν χρειάζεται να ξαναγράψετε τον client· απλώς αλλάξτε τη διαδρομή σε `/aichat2/conversations`.

> Εάν χρησιμοποιείτε επί του παρόντος το `/aichat/conversations`, η παλιά διεπαφή θα συνεχίσει να παρέχεται και μπορείτε να μετεγκατασταθείτε με τον δικό σας ρυθμό.

## Διαδικασία αίτησης

Για να χρησιμοποιήσετε το AI Chat v2 API, μεταβείτε πρώτα στην [κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/applications) για να λάβετε το API Token σας και κρατήστε το ως εφεδρικό.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε ακόμη συνδεθεί ή εγγραφεί, θα ανακατευθυνθείτε αυτόματα στη σελίδα σύνδεσης, όπου θα σας ζητηθεί να εγγραφείτε και να συνδεθείτε. Μετά την ολοκλήρωση, θα επιστρέψετε αυτόματα στην τρέχουσα σελίδα.

**Ένα API Token μπορεί να καλέσει όλες τις υπηρεσίες της πλατφόρμας, χωρίς να χρειάζεται ξεχωριστή αίτηση για κάθε υπηρεσία.** Η πρώτη αίτηση παρέχει δωρεάν πίστωση για δωρεάν δοκιμή· όταν η πίστωση δεν επαρκεί, μπορείτε να επαναφορτίσετε το γενικό υπόλοιπο στην [κονσόλα](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [AI Chat v2 API →](https://platform.acedata.cloud/documents/aichat2-conversations)

## Βασική χρήση

Η απλούστερη χρήση είναι απολύτως ίδια με το v1: στείλτε `model` + `question` και λάβετε `{answer, id}`.

Παράδειγμα CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Αποτέλεσμα επιστροφής:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Παράδειγμα Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Πολυγύρικη συνομιλία

Όπως και στο v1, στείλτε `stateful: true` για να ενεργοποιήσετε την αποθήκευση συνομιλίας και το API θα επιστρέψει ένα `id`· στα επόμενα αιτήματα, συμπεριλάβετε ξανά το `id` για να συνεχίσετε τη συνομιλία, χωρίς να χρειάζεται να διαχειρίζεστε μόνοι σας το ιστορικό messages.

Πρώτο αίτημα:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Επιστρέφει:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Δεύτερο αίτημα, συμπεριλάβετε το ίδιο `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> Το `stateful` είναι από προεπιλογή `true`· η παράλειψή του και η ρητή μετάδοση του `true` είναι ισοδύναμες. Η ρύθμιση `stateful: false` θα παραλείψει τη φόρτωση του προηγούμενου ιστορικού συνομιλίας· αυτό δεν σημαίνει ότι τα αποτελέσματα του τρέχοντος γύρου δεν θα αποθηκευτούν, ούτε εφαρμόζεται σε ροές εργαλείων που χρειάζονται συνέχιση μετά από παύση.

### Μακρές συνομιλίες και διατήρηση του αρχικού κειμένου

Η συμπίεση περιβάλλοντος οργανώνει μόνο το περιεχόμενο που αποστέλλεται στο μοντέλο στον τρέχοντα γύρο και δεν αντικαθιστά τα ήδη αποθηκευμένα αρχεία συνομιλίας. Μέσω του `action: retrieve` εξακολουθεί να είναι δυνατή η ανάγνωση των πλήρων αποθηκευμένων μηνυμάτων· η ρητή επεξεργασία ή διαγραφή συνομιλιών εξακολουθεί να ισχύει σύμφωνα με το αίτημα.

Το μοντέλο μπορεί να αναζητά και να διαβάζει σε σελίδες το αρχικό ιστορικό μέσα στην τρέχουσα συνομιλία. Όταν χρειάζεται να συνεχίσει την επεξεργασία ενός άρθρου, να παραθέσει αριθμούς ή να προετοιμάσει δημοσίευση, πρέπει να διαβάσει το αντίστοιχο αρχικό κείμενο και δεν μπορεί να χρησιμοποιήσει περίληψη αντί για το κυρίως κείμενο. Αυτή η δυνατότητα δεν επαναφέρει αυτόματα μηνύματα που έχουν ήδη χαθεί σε παλιές εκδόσεις.

Εάν η οργάνωση του περιβάλλοντος αποτύχει, διατηρήστε το ID της συνομιλίας και ελέγξτε το συμβάν `error`· η υπηρεσία δεν θα αντικαταστήσει το αρχικό κείμενο με κενή περίληψη. Οι λειτουργίες εργαλείων που ολοκληρώθηκαν πριν από την αποτυχία μπορεί να εξακολουθούν να ισχύουν· ελέγξτε πρώτα τα αποτελέσματά τους, ώστε να αποφύγετε διπλή δημιουργία ή διπλή δημοσίευση. Όταν μία μεμονωμένη συνομιλία φτάσει το όριο αποθήκευσης, θα αναφερθεί ρητά σφάλμα και τα υπάρχοντα αποθηκευμένα αρχεία δεν θα ελευθερώσουν χώρο μέσω περικοπής· μπορείτε να εξαγάγετε το απαιτούμενο περιεχόμενο και κατόπιν να ανοίξετε νέα συνομιλία.

## Ροϊκές αποκρίσεις

Το v2 υποστηρίζει δύο μορφές ροής, οι οποίες επιλέγονται σύμφωνα με την κεφαλίδα `accept`:

| Σενάριο                    | `accept`               | Μορφή δεδομένων                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web frontend / EventSource  | `text/event-stream`    | `data: {json}\n\n`, με τελευταία γραμμή `data: [DONE]\n\n` |
| Διακομιστής / CLI / ανάλυση ροής Node | `application/x-ndjson` | Ένα αντικείμενο JSON ανά γραμμή                               |
| Δεν απαιτείται ροή                 | `application/json`（προεπιλογή） | Επιστρέφει εφάπαξ `{answer, id}`                       |

### Παράδειγμα NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Κάθε γραμμή του NDJSON είναι ένα δομημένο συμβάν, με το συνηθέστερο να είναι το `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Παράδειγμα SSE

Η χρήση `EventSource` στο πρόγραμμα περιήγησης δεν υποστηρίζει προσαρμοσμένο σώμα αιτήματος· συνιστάται η χρήση `fetch` + χειροκίνητη ανάλυση τεμαχίζοντας με `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Τύποι ροϊκών συμβάντων

| `type`              | Σημασία                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Αυξητικό τμήμα κειμένου της απάντησης του βοηθού. Το `content` είναι το νέο περιεχόμενο· για συμβατότητα με το v1, το ίδιο συμβάν φέρει επίσης το `delta_answer` (ίσο με το `content`) και το `id`.                                        |
| `thinking`          | Η διαδικασία σκέψης του μοντέλου (εμφανίζεται μόνο όταν το επιλεγμένο μοντέλο εκθέτει reasoning).                                                                                      |
| `tool_use`          | Το μοντέλο αποφασίζει να καλέσει ένα εργαλείο· το συμβάν φέρει `tool_id`, `tool_name`, `input`.                                                                        |
| `tool_result`       | Το αποτέλεσμα εκτέλεσης εργαλείου, συζευγμένο με το προηγούμενο `tool_use` μέσω του `tool_id`· το `is_error` υποδεικνύει αν απέτυχε.                                                             |
| `card`              | Δομημένη κάρτα που παράγεται από εργαλείο (όπως εικόνα, προεπισκόπηση συνδέσμου), κατάλληλη για άμεση απόδοση.                                                                                          |
| `citation`          | Το URL της πηγής που χρησιμοποιείται για τη συμπλήρωση παραπομπών στο αντίστοιχο τμήμα κειμένου.                                                                                                  |
| `ask_user_question` | Εκδίδεται όταν το μοντέλο χρειάζεται ο χρήστης να συμπληρώσει πληροφορίες· η συνομιλία εισέρχεται στην κατάσταση `awaiting_user_input`, δείτε παρακάτω [Συνέχιση μιας συνομιλίας σε παύση](#恢复暂停的对话)。                                                 |
| `artifact`          | Ανεξάρτητο παραγόμενο αποτέλεσμα του μοντέλου (όπως μπλοκ κώδικα, έγγραφο), το οποίο μπορεί να αποθηκευτεί ή να ληφθεί.                                                                                            |
| `system_message`    | Μήνυμα προτροπής συστήματος (όχι περιεχόμενο χρήστη και βοηθού), μόνο για ειδοποίηση UI.                                                                                           |
| `compact`           | Το περιβάλλον του μοντέλου έχει οργανωθεί· τα αποθηκευμένα αρχικά μηνύματα παραμένουν αμετάβλητα και ο πελάτης δεν χρειάζεται να διαγράψει το ιστορικό συνομιλίας.                                                                                    |
| `error`             | Παρουσιάστηκε σφάλμα στον τρέχοντα γύρο· το `message` περιγράφει το περιεχόμενο του σφάλματος.                                                                                              |
| `done`              | Η τελική εγγραφή συνομιλίας του τρέχοντος γύρου αποθηκεύτηκε επιτυχώς· φέρει το `usage` (συμπεριλαμβανομένων των `prompt_tokens` / `completion_tokens` / `total_tokens`) και το `terminal_reason`· εξακολουθεί να απαιτείται κρίση για το αν ολοκληρώθηκε η εργασία με βάση τον λόγο τερματισμού. |
Για τους πελάτες που ενδιαφέρονται μόνο για την τελική απάντηση, η συνένωση όλων των `content` του `text_delta` είναι ισοδύναμη με το `answer` στη λειτουργία `application/json`.

## Πολυτροπική είσοδος

Αν η είσοδος του χρήστη περιέχει εικόνες ή αρχεία, περάστε `message` (πίνακα) αντί για `question`. Κάθε στοιχείο του πίνακα είναι ένα μπλοκ περιεχομένου:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Υποστηριζόμενοι τύποι μπλοκ:

- `text` — Απλό κείμενο, απαιτεί το πεδίο `text`.
- `image_url` — Εικόνα, απαιτεί το `image_url.url`.
- `file_url` — Αρχείο (PDF, CSV, TXT κ.λπ.), απαιτεί το `file_url.url`.

### Σχέση με τα `references` του v1

Για συμβατότητα με παλιούς πελάτες, το v2 εξακολουθεί να αναγνωρίζει το πεδίο `references: ["https://...", ...]`:

- Αν η κατάληξη του URL είναι `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, μετατρέπεται αυτόματα σε μπλοκ `image_url`.
- Άλλες επεκτάσεις μετατρέπονται σε μπλοκ `file_url`.
- Αν παρέχεται ταυτόχρονα και `question`, τότε προστίθεται στην αρχή ως μπλοκ `text`.

Επομένως, αν θέλετε μόνο να μεταβείτε από το v1 χωρίς να αλλάξετε το σώμα του αιτήματος, αρκεί να αλλάξετε τη διαδρομή σε `/aichat2/conversations`, και η αρχική χρήση του `references` θα συνεχίσει να λειτουργεί κανονικά.

Αν χρειάζεστε πιο λεπτομερή έλεγχο (για παράδειγμα, να τοποθετήσετε πολλές εικόνες ανάμεσα σε κείμενο ή αν η σειρά είναι σημαντική), χρησιμοποιήστε απευθείας τον πίνακα `message`.

## Κλήση εργαλείων και MCP

Η βασική βελτίωση του v2 είναι ότι το μοντέλο μπορεί να καλεί αυτόνομα εργαλεία για να ολοκληρώνει εργασίες πολλών βημάτων, **και αυτό είναι ενεργοποιημένο από προεπιλογή**, χωρίς να απαιτείται οποιαδήποτε πρόσθετη ρύθμιση από τον πελάτη στο αίτημα. Συνήθη σενάρια:

- Ο χρήστης ρωτά «Βοήθησέ με να βρω τι νέες εκθέσεις υπάρχουν πρόσφατα στη Σαγκάη» → Το μοντέλο καλεί το ενσωματωμένο web search → Οργανώνει τα αποτελέσματα σε απάντηση.
- Ο χρήστης ρωτά «Διάβασε αυτό το PDF και μετά γράψε μια περίληψη» → Το μοντέλο καλεί το file_read → Γράφει περίληψη.
- Ο χρήστης έχει ήδη εξουσιοδοτήσει Google Drive / GitHub / Notion κ.λπ. στο [Connections](https://platform.acedata.cloud/connections) → Το μοντέλο μπορεί να καλέσει τα αντίστοιχα εργαλεία MCP για ανάγνωση και εγγραφή των δεδομένων του.

Στη ροή NDJSON / SSE, οι κλήσεις εργαλείων εμφανίζονται μέσω δύο τύπων συμβάντων, `tool_use` και `tool_result`, για παράδειγμα:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Αν δεν θέλετε να εμφανίζονται στο frontend οι λεπτομέρειες των κλήσεων εργαλείων, απλώς αγνοήστε τα συμβάντα `tool_use` / `tool_result` / `card` / `citation`. Η τελική έξοδος του μοντέλου εξακολουθεί να μεταδίδεται μέσω `text_delta`.

Το `max_turns` μπορεί να περιορίσει τον μέγιστο αριθμό γύρων στους οποίους το μοντέλο μπορεί να καλέσει εργαλεία από μόνο του στο συγκεκριμένο αίτημα, με εύρος 1–500 και προεπιλεγμένη τιμή 500 όταν παραλείπεται. Αν το ορίσετε μικρό (για παράδειγμα, `max_turns: 1`), μπορείτε να επιβάλετε μία μόνο απάντηση και να μην επιτρέψετε καμία κλήση εργαλείου.

## Ασύγχρονη εκτέλεση και εξουσιοδότηση χωρίς επίβλεψη

Αν η κλήση σας προέρχεται από Webhook ειδοποίησης, CI/CD, σύστημα παρακολούθησης ή άλλη εργασία παρασκηνίου, μπορείτε να ορίσετε `async: true` ώστε η διεπαφή να επιστρέψει αμέσως ένα ID εργασίας και να συνεχίσει η εκτέλεση στο παρασκήνιο:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Παράδειγμα επιστροφής:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Στη συνέχεια, μπορείτε να χρησιμοποιήσετε `action: retrieve` + `id` για να αναζητήσετε το αποτέλεσμα της συνομιλίας. Μπορείτε επίσης να παρέχετε `callback_url`, και όταν ολοκληρωθεί η εργασία η πλατφόρμα θα κάνει POST το `{ status, answer, usage, error }` στη διεύθυνση επανάκλησής σας. Το `callback_url` πρέπει να χρησιμοποιεί `http` / `https` και δεν μπορεί να συμπληρώνεται απευθείας με `localhost` ή κυριολεκτική διεύθυνση ιδιωτικής IP.

Συνήθως δεν υπάρχει κανείς στις εργασίες παρασκηνίου που να μπορεί να κάνει κλικ για επιβεβαίωση. Αν θέλετε ορισμένα Skill ή MCP Server να εκτελούν ενέργειες όπως αποστολή, δημοσίευση και εγγραφή σε λειτουργία χωρίς επίβλεψη, περάστε ρητά μια λίστα προεξουσιοδότησης στο σώμα του αιτήματος:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Οι τιμές στο `allowed_skills` είναι τα slug των συνδεδεμένων Skill. Οι τιμές στο `allowed_mcp_servers` είναι τα slug των συνδεδεμένων MCP Server. Skill / MCP Server που δεν περιλαμβάνονται στην προεξουσιοδότηση μπορούν στη λειτουργία χωρίς επίβλεψη μόνο να προβάλλουν προεπισκόπηση, να εκτελούν dry-run ή να αρνούνται την εκτέλεση ενεργειών εγγραφής.

Αν χρειάζεστε λεπτομερέστερο έλεγχο, μπορείτε επίσης να χρησιμοποιήσετε το ισοδύναμο αντικείμενο `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Η προεξουσιοδότηση είναι οι ίδιες αυτές οι δύο λίστες: κενές λίστες σημαίνουν ότι δεν εξουσιοδοτείται καμία δυνατότητα και δεν απαιτείται επιπλέον πεδίο διακόπτη.

Σημείωση: Η προεξουσιοδότηση σημαίνει μόνο ότι «το συγκεκριμένο αίτημα επιτρέπει σε αυτές τις δυνατότητες να παρακάμψουν την ανθρώπινη επιβεβαίωση στη λειτουργία χωρίς επίβλεψη». Το συγκεκριμένο Skill πρέπει ακόμη να υποστηρίζει `--unattended-confirm` ή τον αντίστοιχο μηχανισμό ασφαλείας· διαφορετικά, θα συνεχίσει να κάνει dry-run και δεν θα εκτελέσει απευθείας ενέργειες εγγραφής.

## Συνέχιση παγωμένων συνομιλιών

Ορισμένα εργαλεία κάνουν το μοντέλο να «ρωτήσει ξανά τον χρήστη». Τότε το μοντέλο θα εκδώσει ένα συμβάν `ask_user_question` και η συνομιλία παγώνει στην κατάσταση `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Στο frontend αποδώστε αυτό το συμβάν ως κάρτα ώστε ο χρήστης να επιλέξει απάντηση και, στη συνέχεια, χρησιμοποιήστε το ίδιο `id` για να ξεκινήσετε το επόμενο αίτημα, συμπληρώνοντας ξανά την απάντηση μέσω `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

Στο σώμα του αιτήματος, το `tool_use_id` **πρέπει** να είναι απολύτως ίδιο με το `tool_id` κατά την παύση· σε περίπτωση ασυμφωνίας επιστρέφεται 400. Όταν στο αίτημα υπάρχει ταυτόχρονα `tool_results`, τα `question` / `message` / `references` θα αγνοηθούν όλα.

Εάν ο χρήστης αποφασίσει να εγκαταλείψει αυτή την ερώτηση, αρκεί να περάσει απευθείας ένα νέο `question` / `message`, και η πλατφόρμα θα επισημάνει αυτόματα την κλήση εργαλείου που βρίσκεται σε παύση ως «παραλείφθηκε από τον χρήστη».

## Διαχείριση συνεδριών (CRUD)

Το v2 παρέχει ελαφριά διαχείριση συνεδριών στο ίδιο endpoint μέσω του πεδίου `action`, χωρίς να απαιτείται επιπλέον API.

### `action: retrieve` —— Ανάκτηση μιας συνεδρίας

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Επιστρέφει το πλήρες έγγραφο της συνεδρίας (συμπεριλαμβανομένων του ιστορικού `messages`, του `model`, του `title`, του `tools_used` κ.λπ.).

### `action: retrieve_batch` —— Καταχώριση περιλήψεων συνεδριών

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Επιστρέφει `{ items: [...], total }`. **Οι περιλήψεις δεν περιλαμβάνουν `messages`**, και είναι κατάλληλες για λίστες πλευρικής γραμμής· εάν ο χρήστης ανοίξει μια συγκεκριμένη συνεδρία, χρησιμοποιήστε έπειτα το `action: retrieve` για να ανακτήσετε ξεχωριστά τα πλήρη μηνύματά της.

Προαιρετικές παράμετροι φιλτραρίσματος: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Αλλαγή τίτλου ή επανεγγραφή ιστορικού

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

Μπορεί επίσης να περαστεί το `messages`, αλλά ο διακομιστής θα εκτελέσει αυστηρό έλεγχο schema (πρέπει να είναι στη συμπτυγμένη μορφή `ToolUseContent`)· αν δεν συμμορφώνεται, θα επιστραφεί 400. Γενικά συνιστάται να χρησιμοποιείται μόνο για την αλλαγή του `title`.

### `action: delete` —— Διαγραφή μιας συνεδρίας

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Επιστρέφει `{ id, success: true }`. Μετά τη διαγραφή δεν μπορεί να γίνει ανάκτηση, παρακαλούμε επιβεβαιώστε πριν καλέσετε.

## Ομαλή μετάβαση από το v1

Εάν χρησιμοποιείτε ήδη το [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), η μετάβαση στο v2 σχεδόν δεν απαιτεί αλλαγές κώδικα:

1. Αλλάξτε το URL από `https://api.acedata.cloud/aichat/conversations` σε `https://api.acedata.cloud/aichat2/conversations`.
2. Εάν προηγουμένως περνούσατε ονόματα μοντέλων v1 (όπως `gpt-3.5`, `gpt-4-browsing` κ.λπ.), κατά τη μετάβαση στο v2 συνιστάται η αναβάθμιση σε σύγχρονα μοντέλα (όπως `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` κ.λπ.).
3. Τα πεδία της ροής NDJSON παραμένουν συμβατά προς τα πίσω: κάθε συμβάν `text_delta` εξακολουθεί να περιέχει `delta_answer` και `id`, επομένως οι υπάρχοντες πελάτες που αναλύουν γραμμή προς γραμμή το `delta_answer` δεν χρειάζονται αλλαγές.

Μετά τη μετάβαση, μπορείτε να ενεργοποιήσετε κατά περίπτωση τις νέες δυνατότητες του v2 (πολυτροπικό `message`, SSE, κλήσεις εργαλείων, `action` CRUD) και να προχωρήσετε με τον δικό σας ρυθμό.

## Διαχείριση σφαλμάτων

Οι αποκρίσεις σφαλμάτων έχουν ενιαία μορφή:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Συνηθισμένα σφάλματα:

- `400 bad_request`: Λείπουν υποχρεωτικά πεδία, ασυμφωνία `tool_use_id`, μη έγκυρο schema `messages` κ.λπ.
- `401 invalid_token`: Η κεφαλίδα `authorization` είναι λανθασμένη.
- `404 not_found`: Η συνεδρία που αντιστοιχεί στο `id` δεν υπάρχει κατά το `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: Η συνεδρία υπερβαίνει το όριο αποθήκευσης και οι υπάρχουσες αποθηκευμένες εγγραφές δεν αντικαταστάθηκαν.
- `429 too_many_requests`: Ενεργοποιήθηκε το όριο ρυθμού αιτημάτων.
- `503 context_compaction_failed`: Απέτυχε η οργάνωση του πλαισίου και οι υπάρχουσες εγγραφές διατηρήθηκαν.
- `500 conversation_persist_failed`: Απέτυχε η τελική αποθήκευση αυτού του γύρου· το ότι έχει ήδη ληφθεί κείμενο δεν σημαίνει ότι η τελική εγγραφή αποθηκεύτηκε επιτυχώς, παρακαλούμε ελέγξτε με βάση το ID της συνεδρίας.
- `500 chat_error`: Η υπηρεσία είναι προσωρινά μη διαθέσιμη ή δεν δημιουργήθηκε περιεχόμενο σε αυτόν τον γύρο (δεν θα υπάρξει χρέωση).

Στη ροϊκή απόκριση, τα σφάλματα αποστέλλονται ως συμβάντα `{"type":"error","message":"..."}`, και στη συνέχεια η ροή τερματίζεται. Το `[DONE]` υποδηλώνει μόνο ότι η μεταφορά ολοκληρώθηκε· όταν υπάρχει `error`, δεν μπορεί να θεωρηθεί επιτυχία και δεν θα αποσταλεί επιτυχές συμβάν `done`.

## Συμπέρασμα

Το AI Chat v2 API, διατηρώντας τη συμβατότητα προς τα πίσω με το v1, αναβαθμίζει τη συνομιλία από «ερωταπαντήσεις μίας / πολλαπλών γύρων» σε «παρατηρήσιμη συνομιλία με Agent»: πολυτροπική είσοδος, κλήσεις εργαλείων, δυνατότητα παύσης / συνέχισης, ροϊκά δομημένα συμβάντα, ενσωματωμένο CRUD. Συνιστάται οι νέες ενσωματώσεις να χρησιμοποιούν απευθείας το v2· οι υπάρχουσες ενσωματώσεις v1 μπορούν να μεταβούν ομαλά σταδιακά. Εάν έχετε οποιεσδήποτε ερωτήσεις, παρακαλούμε επικοινωνήστε με την ομάδα τεχνικής υποστήριξής μας ανά πάσα στιγμή.
