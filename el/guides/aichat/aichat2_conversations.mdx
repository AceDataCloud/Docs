Το AI Chat v2 API (`/aichat2/conversations`) είναι η νέα γενιά διεπαφής διαλόγου, μια πλήρης αναβάθμιση του [AI Chat API](https://platform.acedata.cloud/documents/59fb1199-6694-4afb-a222-3554d7f7d05a). Βασιζόμενο στην απλότητα και τη διαχείριση πολλαπλών γύρων διαλόγου της έκδοσης v1, επεκτείνει τις δυνατότητες με:

- **Πολυτροπική είσοδο χρήστη**: Μέσω του δομημένου πεδίου `message` μπορείτε να στείλετε απευθείας κείμενο + εικόνες + αρχεία, χωρίς να χρειάζεται να χρησιμοποιήσετε το `references` ως ενδιάμεσο.
- **Κλήση εργαλείων με Agent**: Περιλαμβάνει ενσωματωμένα εργαλεία όπως διαδικτυακή αναζήτηση, web scraping, ανάγνωση αρχείων, και μπορεί να συνδεθεί με εξουσιοδοτημένους MCP servers (Google Drive, Notion, Slack, GitHub κ.ά.), επιτρέποντας στο μοντέλο να καλεί εργαλεία αυτόνομα σε πολλαπλούς γύρους μέσα σε ένα αίτημα για ολοκλήρωση σύνθετων εργασιών.
- **Δομημένα ροή γεγονότων**: Με `accept: text/event-stream` ή `application/x-ndjson` λαμβάνετε γεγονότα όπως `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` κ.ά., διευκολύνοντας την απόδοση στο frontend ανά τύπο.
- **Διακοπή / Ανάκτηση**: Όταν το μοντέλο χρειάζεται συμπληρωματικές πληροφορίες, εκπέμπει το γεγονός `ask_user_question` και παύει, ενώ η επόμενη κλήση με `tool_results` επιτρέπει την επανεκκίνηση.
- **Νέες ενέργειες CRUD**: Στο ίδιο endpoint, μέσω του πεδίου `action` υλοποιούνται οι ενέργειες `retrieve` / `retrieve_batch` / `update` / `delete` χωρίς επιπλέον API διαχείρισης διαλόγων.
- **Συνεχής ενημέρωση μοντέλων**: Υποστήριξη μοντέλων όπως GPT-5.4, Claude Opus 4.7, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K2.5 κ.ά.

Παράλληλα, το API είναι **πλήρως συμβατό με το v1** σε επίπεδο σώματος αιτήματος: αρκεί να στείλετε `model` + `question` (+ προαιρετικά `stateful` / `id` / `references` / `preset`) για να λάβετε την ίδια απάντηση `{answer, id}` όπως στο v1. Έτσι, η μετάβαση από `/aichat/conversations` σε `/aichat2/conversations` δεν απαιτεί αλλαγές στον πελάτη, μόνο αλλαγή της διαδρομής.

> Αν χρησιμοποιείτε ακόμα το `/aichat/conversations`, η παλιά διεπαφή παραμένει ενεργή και μπορείτε να μεταβείτε με τον δικό σας ρυθμό.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το API, επισκεφθείτε τη σελίδα του [AI Chat v2 API](https://platform.acedata.cloud/documents/e4a7c2b9-3f1d-4e8a-9b6c-a5d2f8e1b4c7) και κάντε κλικ στο κουμπί «Acquire» για να λάβετε τα διαπιστευτήρια που απαιτούνται για τα αιτήματα.

Αν δεν έχετε συνδεθεί ή εγγραφεί, θα ανακατευθυνθείτε αυτόματα στη σελίδα σύνδεσης. Μετά την εγγραφή και σύνδεση, θα επιστρέψετε αυτόματα στη σελίδα.

Κατά την πρώτη αίτηση παρέχεται δωρεάν όριο χρήσης για το API.

## Βασική Χρήση

Η απλούστερη χρήση είναι ίδια με το v1: στείλτε `model` + `question` και λάβετε `{answer, id}`.

Παράδειγμα CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Απάντηση:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Παράδειγμα Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Πολλαπλοί Γύροι Διαλόγου

Όπως και στο v1, στείλτε `stateful: true` για να ενεργοποιήσετε την αποθήκευση διαλόγου. Το API επιστρέφει ένα `id`, το οποίο επιστρέφετε στα επόμενα αιτήματα για συνέχιση χωρίς να χρειάζεται να διαχειρίζεστε το ιστορικό μηνυμάτων.

Πρώτο αίτημα:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Απάντηση:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Δεύτερο αίτημα με το ίδιο `id`:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

Απάντηση:

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> Η προεπιλογή του `stateful` είναι `true`. Αν δεν θέλετε να αποθηκεύεται η συνομιλία, ορίστε ρητά `stateful: false`.

## Ροή Απαντήσεων (Streaming)

Το v2 υποστηρίζει δύο μορφές streaming, επιλέγονται μέσω της κεφαλίδας `accept`:

| Σενάριο | `accept` | Μορφή δεδομένων |
| :--- | :--- | :--- |
| Web frontend / EventSource | `text/event-stream` | `data: {json}\n\n`, τελευταία γραμμή `data: [DONE]\n\n` |
| Server / CLI / Node streaming parsing | `application/x-ndjson` | Κάθε γραμμή ένα JSON αντικείμενο |
| Χωρίς streaming | `application/json` (προεπιλογή) | Επιστρέφει `{answer, id}` μονομιάς |

### Παράδειγμα NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # Συμβατό με v1: το τμηματικό κείμενο παρέχεται και στο πεδίο delta_answer
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Κάθε γραμμή NDJSON είναι ένα δομημένο γεγονός, το πιο συνηθισμένο είναι `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Παράδειγμα SSE

Στον browser, το `EventSource` δεν υποστηρίζει προσαρμοσμένο σώμα αιτήματος, προτείνεται χρήση `fetch` με χειροκίνητη ανάλυση κατά `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Τύποι Γεγονότων Streaming

| `type` | Περιγραφή |
| :--- | :--- |
| `text_delta` | Τμηματικό κείμενο απάντησης από τον βοηθό. Το `content` είναι το νέο περιεχόμενο. Για συμβατότητα με v1, το ίδιο γεγονός περιέχει `delta_answer` (ίδιο με `content`) και `id`. |
| `thinking` | Διαδικασία σκέψης του μοντέλου (εμφανίζεται μόνο αν το μοντέλο εκθέτει reasoning). |
| `tool_use` | Το μοντέλο αποφασίζει να καλέσει ένα εργαλείο, το γεγονός περιέχει `tool_id`, `tool_name`, `input`. |
| `tool_result` | Αποτέλεσμα εργαλείου, αντιστοιχεί στο προηγούμενο `tool_use` μέσω `tool_id`, με `is_error` για σφάλματα. |
| `card` | Δομημένη κάρτα από εργαλείο (π.χ. εικόνα, προεπισκόπηση συνδέσμου), κατάλληλη για άμεση απόδοση. |
| `citation` | Πηγή URL για το αντίστοιχο τμήμα κειμένου. |
| `ask_user_question` | Το μοντέλο ζητά συμπληρωματικές πληροφορίες από τον χρήστη, η συνομιλία μπαίνει σε κατάσταση `awaiting_user_input`. Βλ. [Ανάκτηση παύσης διαλόγου](#ανάκτηση-παύσης-διαλόγου). |
| `artifact` | Ανεξάρτητο παραγόμενο αντικείμενο (π.χ. μπλοκ κώδικα, έγγραφο), μπορεί να αποθηκευτεί ή να κατέβει. |
| `system_message` | Μηνύματα συστήματος (όχι περιεχόμενο χρήστη ή βοηθού), για UI ειδοποιήσεις. |
| `compact` | Συμπιεσμένο εσωτερικό πλαίσιο, δεν απαιτεί ειδική επεξεργασία. |
| `error` | Σφάλμα στην τρέχουσα συνεδρία, το `message` περιγράφει το πρόβλημα. |
| `done` | Τέλος ροής, περιλαμβάνει `usage` (με `prompt_tokens` / `completion_tokens` / `total_tokens`) και `terminal_reason`. |

Για πελάτες που ενδιαφέρονται μόνο για το τελικό αποτέλεσμα, αρκεί να ενώσουν όλα τα `content` από τα `text_delta` γεγονότα, που ισοδυναμεί με το `answer` σε μορφή `application/json`.

## Πολυτροπική Είσοδος

Αν η είσοδος περιλαμβάνει εικόνες ή αρχεία, στείλτε `message` (πίνακα) αντί για `question`. Κάθε στοιχείο του πίνακα είναι ένα block περιεχομένου:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Υποστηριζόμενοι τύποι block:

- `text` — Απλό κείμενο, απαιτείται το πεδίο `text`.
- `image_url` — Εικόνα, απαιτείται `image_url.url`.
- `file_url` — Αρχείο (PDF, CSV, TXT κ.ά.), απαιτείται `file_url.url`.

### Σχέση με το v1 `references`

Για συμβατότητα με παλιούς πελάτες, το v2 εξακολουθεί να αναγνωρίζει το πεδίο `references: ["https://...", ...]`:

- URLs με κατάληξη `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif` μετατρέπονται αυτόματα σε block `image_url`.
- Άλλες επεκτάσεις γίνονται block `file_url`.
- Αν υπάρχει και `question`, προστίθεται ως πρώτο block `text`.

Επομένως, αν θέλετε απλώς μετάβαση από v1 χωρίς αλλαγή σώματος αιτήματος, αλλάξτε μόνο το endpoint σε `/aichat2/conversations` και το παλιό `references` θα λειτουργεί κανονικά.

Για πιο λεπτομερή έλεγχο (π.χ. τοποθέτηση πολλών εικόνων ανάμεσα σε κείμενο ή σημαντική σειρά), χρησιμοποιήστε απευθείας τον πίνακα `message`.

## Κλήση Εργαλείων και MCP

Η βασική βελτίωση του v2 είναι ότι το μοντέλο μπορεί αυτόνομα να καλεί εργαλεία για πολυβηματικές εργασίες, **ενεργοποιημένο από προεπιλογή**, χωρίς επιπλέον ρυθμίσεις από τον πελάτη. Συνηθισμένα σενάρια:

- Ο χρήστης ρωτά «Βρες μου πρόσφατες εκθέσεις στη Σαγκάη» → το μοντέλο καλεί την ενσωματωμένη αναζήτηση web → συνθέτει απάντηση.
- Ο χρήστης ζητά «Διάβασε αυτό το PDF και γράψε περίληψη» → το μοντέλο καλεί file_read → δημιουργεί περίληψη.
- Ο χρήστης έχει εξουσιοδοτήσει Google Drive / GitHub / Notion κ.ά. μέσω [Connections](https://platform.acedata.cloud/connections) → το μοντέλο καλεί τα αντίστοιχα MCP εργαλεία για ανάγνωση/εγγραφή.

Στο NDJSON / SSE stream, η κλήση εργαλείων εμφανίζεται με γεγονότα `tool_use` και `tool_result`, π.χ.:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Αν δεν θέλετε να εμφανίζετε λεπτομέρειες εργαλείων στο frontend, αγνοήστε τα γεγονότα `tool_use` / `tool_result` / `card` / `citation`. Το τελικό κείμενο εξάγεται πάντα μέσω `text_delta`.

Η παράμετρος `max_turns` περιορίζει πόσες φορές το μοντέλο μπορεί να καλέσει εργαλεία μέσα σε ένα αίτημα. Η προεπιλογή καθορίζεται από την πλατφόρμα. Μικρή τιμή (π.χ. `max_turns: 1`) αναγκάζει απάντηση χωρίς κλήση εργαλείων.

## Ανάκτηση Παύσης Διαλόγου

Ορισμένα εργαλεία επιτρέπουν στο μοντέλο να «ρωτάει» τον χρήστη. Τότε το μοντέλο εκπέμπει το γεγονός `ask_user_question` και η συνομιλία παγώνει σε κατάσταση `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Στο frontend, εμφανίστε αυτό το γεγονός ως κάρτα για επιλογή απάντησης από τον χρήστη. Στη συνέχεια, στείλτε νέο αίτημα με το ίδιο `id`, επιστρέφοντας την απάντηση μέσω `tool_results`:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

Το `tool_use_id` στο αίτημα πρέπει **να ταιριάζει ακριβώς** με το `tool_id` της παύσης. Διαφορετικά επιστρέφεται σφάλμα 400. Όταν υπάρχουν `tool_results` στο αίτημα, τα πεδία `question` / `message` / `references` αγνοούνται.

Αν ο χρήστης θέλει να παρακάμψει την ερώτηση, στείλτε νέο `question` ή `message` και η πλατφόρμα θα μαρκάρει την παύση ως «παρακάμφθηκε από τον χρήστη».

## Διαχείριση Συνομιλιών (CRUD)

Το v2 υποστηρίζει ελαφριά διαχείριση συνομιλιών μέσω του πεδίου `action` στο ίδιο endpoint, χωρίς επιπλέον API.

### `action: retrieve` — Ανάκτηση συνομιλίας

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Επιστρέφει πλήρες έγγραφο συνομιλίας (με ιστορικό `messages`, `model`, `title`, `tools_used` κ.ά.).

### `action: retrieve_batch` — Λίστα συνομιλιών (περίληψη)

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Επιστρέφει `{ items: [...], total }`. **Η περίληψη δεν περιλαμβάνει `messages`**, κατάλληλη για λίστα στο sidebar. Για λεπτομέρειες, χρησιμοποιήστε `action: retrieve`.

Προαιρετικά φίλτρα: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` — Ενημέρωση τίτλου ή ιστορικού

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

Μπορεί να σταλούν και `messages`, αλλά ο server κάνει αυστηρό έλεγχο schema (πρέπει να είναι σε μορφή `ToolUseContent` μετά από σύμπτυξη). Αν δεν είναι σωστό, επιστρέφεται 400. Συνήθως χρησιμοποιείται μόνο για αλλαγή τίτλου.

### `action: delete` — Διαγραφή συνομιλίας

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Επιστρέφει `{ id, success: true }`. Η διαγραφή είναι μη αναστρέψιμη, επιβεβαιώστε πριν καλέσετε.

## Ομαλή Μετάβαση από v1

Αν ήδη χρησιμοποιείτε [`/aichat/conversations`](https://platform.acedata.cloud/documents/59fb1199-6694-4afb-a222-3554d7f7d05a), η μετάβαση σε v2 απαιτεί ελάχιστες αλλαγές:

1. Αλλάξτε το URL από `https://api.acedata.cloud/aichat/conversations` σε `https://api.acedata.cloud/aichat2/conversations`.
2. Αν χρησιμοποιούσατε μοντέλα v1 (π.χ. `gpt-3.5`, `gpt-4-browsing`), προτείνεται αναβάθμιση σε σύγχρονα μοντέλα v2 (π.χ. `gpt-5.4`, `claude-opus-4-7`, `gemini-3.1-pro`).
3. Τα πεδία του NDJSON stream παραμένουν συμβατά: κάθε `text_delta` περιέχει ακόμα `delta_answer` και `id`, οπότε οι πελάτες που αναλύουν `delta_answer` ανά γραμμή δεν χρειάζεται να αλλάξουν.

Μετά τη μετάβαση, μπορείτε σταδιακά να ενεργοποιήσετε τις νέες δυνατότητες του v2 (πολυτροπικά `message`, SSE, κλήσεις εργαλείων, CRUD με `action`).

## Διαχείριση Σφαλμάτων

Τα σφάλματα επιστρέφονται με τη μορφή:

```json
{
  "error": {
    "code": "chat_error",
    "message": "upstream LLM returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Συνηθισμένα σφάλματα:

- `400 bad_request`: Έλλειψη υποχρεωτικών πεδίων, ασυμφωνία `tool_use_id`, μη έγκυρο schema `messages` κ.ά.
- `401 invalid_token`: Λανθασμένη κεφαλίδα `authorization`.
- `404 not_found`: Μη ύπαρξη συνομιλίας για `action: retrieve / update / delete` με το δοσμένο `id`.
- `429 too_many_requests`: Υπέρβαση ορίου ρυθμού αιτημάτων.
- `500 chat_error`: Σφάλμα upstream LLM ή `completion_tokens=0` (θεωρείται μη κατανάλωση, χωρίς χρέωση).

Σε streaming απαντήσεις, τα σφάλματα εκπέμπονται ως γεγονός `{"type":"error","message":"..."}` και ακολουθεί άμεσο τέλος ροής.

## Συμπέρασμα

Το AI Chat v2 API διατηρεί πλήρη συμβατότητα με το v1, ενώ αναβαθμίζει τη συνομιλία από «μονό ή πολυγλωσσική ερώτηση-απάντηση» σε «Agent-based παρατηρήσιμο διάλογο»: πολυτροπική είσοδο, κλήση εργαλείων, δυνατότητα παύσης/ανάκτησης, δομημένα γεγονότα ροής, ενσωματωμένο CRUD. Συνιστάται η απευθείας χρήση του v2 για νέες ενσωματώσεις, ενώ οι υπάρχουσες μπορούν να μεταβούν ομαλά σταδιακά. Για οποιαδήποτε απορία, επικοινωνήστε με την τεχνική υποστήριξη.
