Το AI Chat v2 API (`/aichat2/conversations`) είναι η νέας γενιάς διεπαφή συνομιλίας και η πλήρως αναβαθμισμένη έκδοση του [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Με βάση την απλότητα και τη διαχειριζόμενη πολυγυρική συνομιλία του v1, επεκτείνει:

- **Πολυτροπική είσοδος χρήστη**: Μέσω του δομημένου πεδίου `message` μπορείτε να στείλετε απευθείας μπλοκ κειμένου + εικόνων + αρχείων, χωρίς να χρειάζεται πρώτα να τα επισυνάψετε έμμεσα με `references`.
- **Κλήση εργαλείων τύπου Agent**: Περιλαμβάνει ένα ενσωματωμένο σύνολο εργαλείων για διαδικτυακή αναζήτηση, ανάκτηση ιστοσελίδων, ανάγνωση αρχείων κ.λπ., και μπορεί να προσαρτήσει διακομιστές MCP που έχουν εξουσιοδοτηθεί από τον χρήστη (Google Drive, Notion, Slack, GitHub κ.λπ.). Το μοντέλο μπορεί να καλεί αυτόνομα εργαλεία σε πολλούς γύρους μέσα σε ένα αίτημα, ώστε να ολοκληρώνει σύνθετες εργασίες.
- **Δομημένα συμβάντα ροής**: Μέσω `accept: text/event-stream` ή `application/x-ndjson` μπορείτε να λάβετε συμβάντα όπως `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` κ.λπ. ανά token, διευκολύνοντας την ξεχωριστή απόδοσή τους στο frontend ανά αντίστοιχο τύπο.
- **Διακόψιμο / επαναλήψιμο**: Όταν το μοντέλο χρειάζεται από τον χρήστη συμπληρωματικές πληροφορίες, εκπέμπει ένα συμβάν `ask_user_question` και παύει. Στην επόμενη κλήση, αρκεί να συμπληρώσετε την απάντηση μέσω `tool_results` για να συνεχίσει.
- **Νέες ενέργειες CRUD**: Στο ίδιο endpoint, ολοκληρώστε `retrieve` / `retrieve_batch` / `update` / `delete` μέσω του πεδίου `action`, χωρίς να χρειάζεται επιπλέον API διαχείρισης συνομιλιών.
- **Λίστα μοντέλων που ενημερώνεται συνεχώς**: Από προεπιλογή ενσωματώνονται σύγχρονα μοντέλα όπως GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 κ.λπ.

Παράλληλα, στο επίπεδο του σώματος αιτήματος είναι **πλήρως συμβατό προς τα πίσω με το v1**: αρκεί να στείλετε `model` + `question` (+ προαιρετικά `stateful` / `id` / `references` / `preset`) για να λάβετε απόκριση JSON `{answer, id}` ισοδύναμη με το v1. Επομένως, για μετεγκατάσταση από το `/aichat/conversations`, δεν χρειάζεται να ξαναγράψετε τον client· αρκεί να αλλάξετε τη διαδρομή σε `/aichat2/conversations`.

> Εάν χρησιμοποιείτε αυτήν τη στιγμή το `/aichat/conversations`, η παλιά διεπαφή θα συνεχίσει να παρέχεται και μπορείτε να μετεγκατασταθείτε με τον δικό σας ρυθμό.

## Διαδικασία αίτησης

Για να χρησιμοποιήσετε το AI Chat v2 API, μεταβείτε πρώτα στην [κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/applications) για να αποκτήσετε το API Token σας και κρατήστε το ως εφεδρικό.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε ακόμη συνδεθεί ή εγγραφεί, θα ανακατευθυνθείτε αυτόματα στη σελίδα σύνδεσης για να εγγραφείτε και να συνδεθείτε. Μετά την ολοκλήρωση, θα επιστρέψετε αυτόματα στην τρέχουσα σελίδα.

**Ένα API Token αρκεί για την κλήση όλων των υπηρεσιών της πλατφόρμας, χωρίς να χρειάζεται ξεχωριστή αίτηση για κάθε υπηρεσία.** Με την πρώτη αίτηση παρέχεται δωρεάν υπόλοιπο για δωρεάν δοκιμή· όταν το υπόλοιπο δεν επαρκεί, μπορείτε να φορτίσετε γενικό υπόλοιπο στην [κονσόλα](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [AI Chat v2 API →](https://platform.acedata.cloud/documents/aichat2-conversations)

## Βασική χρήση

Η απλούστερη χρήση είναι ακριβώς ίδια με το v1: στείλτε `model` + `question` και λάβετε `{answer, id}`.

Παράδειγμα CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Αποτέλεσμα επιστροφής:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Παράδειγμα Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Πολυγυρική συνομιλία

Όπως και στο v1, στείλτε `stateful: true` για να ενεργοποιήσετε την αποθήκευση συνομιλίας. Το API θα επιστρέψει ένα `id`· στα επόμενα αιτήματα, επιστρέψτε το `id` για να συνεχίσετε τη συνομιλία, χωρίς να χρειάζεται να διαχειρίζεστε μόνοι σας το ιστορικό messages.

Πρώτο αίτημα:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Επιστροφή:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Δεύτερο αίτημα, συμπεριλάβετε το ίδιο `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> Το `stateful` είναι από προεπιλογή `true`· η παράλειψή του είναι ισοδύναμη με τη ρητή μετάδοση του `true`. Εάν δεν θέλετε ο διακομιστής να αποθηκεύσει αυτόν τον γύρο συνομιλίας, μπορείτε να ορίσετε ρητά `stateful: false`.

## Ροϊκή απόκριση

Η v2 υποστηρίζει δύο μορφές ροής, οι οποίες επιλέγονται σύμφωνα με την κεφαλίδα `accept`:

| Σενάριο                    | `accept`               | Μορφή δεδομένων                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web frontend / EventSource  | `text/event-stream`    | `data: {json}\n\n`, η τελευταία γραμμή είναι `data: [DONE]\n\n` |
| Διακομιστής / CLI / ανάλυση ροής Node | `application/x-ndjson` | Ένα αντικείμενο JSON ανά γραμμή                               |
| Δεν απαιτείται ροή                 | `application/json`（προεπιλογή） | Εφάπαξ επιστροφή `{answer, id}`                       |

### Παράδειγμα NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Κάθε γραμμή NDJSON είναι ένα δομημένο συμβάν, με το πιο συνηθισμένο να είναι το `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Παράδειγμα SSE

Η χρήση `EventSource` στο πρόγραμμα περιήγησης δεν υποστηρίζει προσαρμοσμένο σώμα αιτήματος· συνιστάται η χρήση `fetch` + χειροκίνητη ανάλυση σε τμήματα με βάση το `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Τύποι ροϊκών συμβάντων

| `type`              | Σημασία                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `text_delta`        | Αυξητικό τμήμα κειμένου της απάντησης του βοηθού. Το `content` είναι το νέο περιεχόμενο· για συμβατότητα με v1, το ίδιο συμβάν περιλαμβάνει επίσης το `delta_answer` (ίσο με `content`) και το `id`.                  |
| `thinking`          | Η διαδικασία σκέψης του μοντέλου (εμφανίζεται μόνο όταν το επιλεγμένο μοντέλο εκθέτει reasoning).                                                                |
| `tool_use`          | Το μοντέλο αποφασίζει να καλέσει ένα εργαλείο· το συμβάν περιλαμβάνει `tool_id`, `tool_name`, `input`.                                                  |
| `tool_result`       | Το αποτέλεσμα εκτέλεσης του εργαλείου, αντιστοιχίζεται με το προηγούμενο `tool_use` μέσω του `tool_id`, και το `is_error` υποδεικνύει εάν απέτυχε.                                       |
| `card`              | Δομημένη κάρτα που παράγεται από το εργαλείο (όπως εικόνες, προεπισκοπήσεις συνδέσμων), κατάλληλη για άμεση απόδοση.                                                                    |
| `citation`          | URL πηγής που χρησιμοποιείται για τη συμπλήρωση παραπομπών για το αντίστοιχο τμήμα κειμένου.                                                                            |
| `ask_user_question` | Εκδίδεται όταν το μοντέλο χρειάζεται ο χρήστης να συμπληρώσει πληροφορίες· η συνομιλία εισέρχεται στην κατάσταση `awaiting_user_input`, δείτε παρακάτω [Επαναφορά συνομιλίας σε παύση](#恢复暂停的对话).                           |
| `artifact`          | Ανεξάρτητο παραγόμενο αποτέλεσμα του μοντέλου (όπως μπλοκ κώδικα, έγγραφα), το οποίο μπορεί να αποθηκευτεί ή να ληφθεί.                                                                      |
| `system_message`    | Μήνυμα συστήματος (όχι περιεχόμενο χρήστη ή βοηθού), χρησιμοποιείται μόνο για ειδοποιήσεις UI.                                                                     |
| `compact`           | Συμβάν όπου το εσωτερικό πλαίσιο έχει συμπιεστεί, χωρίς να απαιτείται ειδικός χειρισμός.                                                                             |
| `error`             | Παρουσιάστηκε σφάλμα σε αυτόν τον γύρο· το `message` περιγράφει το περιεχόμενο του σφάλματος.                                                                        |
| `done`              | Η ροϊκή απόκριση ολοκληρώνεται, περιλαμβάνοντας `usage` (με `prompt_tokens` / `completion_tokens` / `total_tokens`) και `terminal_reason`. |

Για πελάτες που ενδιαφέρονται μόνο για την τελική απάντηση, η συνένωση των `content` όλων των `text_delta` είναι ισοδύναμη με το `answer` στη λειτουργία `application/json`.

## Πολυτροπική είσοδος

Εάν η είσοδος χρήστη περιλαμβάνει εικόνες ή αρχεία, μεταδώστε `message` (πίνακα) αντί για `question`. Κάθε στοιχείο του πίνακα είναι ένα μπλοκ περιεχομένου:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Υποστηριζόμενοι τύποι μπλοκ:

- `text` — Απλό κείμενο, απαιτείται το πεδίο `text`.
- `image_url` — Εικόνα, απαιτείται το `image_url.url`.
- `file_url` — Αρχείο (PDF, CSV, TXT κ.λπ.), απαιτείται το `file_url.url`.

### Σχέση με το `references` της v1

Για συμβατότητα με παλαιότερους πελάτες, η v2 εξακολουθεί να αναγνωρίζει το πεδίο `references: ["https://...", ...]`:
- Το επίθημα URL είναι `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, μετατρέπεται αυτόματα σε μπλοκ `image_url`·
- Άλλες επεκτάσεις μετατρέπονται σε μπλοκ `file_url`·
- Εάν παρέχεται ταυτόχρονα και `question`, τότε τοποθετείται μπροστά ως μπλοκ `text`.

Επομένως, αν θέλετε μόνο να μεταβείτε από το v1 χωρίς να αλλάξετε το σώμα του αιτήματος, αρκεί να αλλάξετε τη διαδρομή σε `/aichat2/conversations`, και η αρχική χρήση του `references` συνεχίζει να λειτουργεί κανονικά.

Αν χρειάζεστε πιο λεπτομερή έλεγχο (για παράδειγμα να τοποθετήσετε πολλές εικόνες ανάμεσα σε κείμενο, ή αν η σειρά είναι σημαντική), χρησιμοποιήστε απευθείας τον πίνακα `message`.

## Κλήση εργαλείων και MCP

Η βασική ενίσχυση του v2 είναι ότι το μοντέλο μπορεί να καλεί αυτόνομα εργαλεία για την ολοκλήρωση εργασιών πολλαπλών βημάτων, **αυτό είναι ενεργοποιημένο από προεπιλογή**, και δεν απαιτείται καμία πρόσθετη ρύθμιση από τον πελάτη στο αίτημα. Συνηθισμένα σενάρια:

- Ο χρήστης ρωτά «Βοήθησέ με να ψάξω τι νέες εκθέσεις υπάρχουν πρόσφατα στη Σαγκάη» → το μοντέλο καλεί το ενσωματωμένο web search → οργανώνει τα αποτελέσματα σε απάντηση.
- Ο χρήστης ρωτά «Διάβασε αυτό το PDF και μετά γράψε μια περίληψη» → το μοντέλο καλεί το file_read → γράφει περίληψη.
- Ο χρήστης έχει ήδη εξουσιοδοτήσει Google Drive / GitHub / Notion κ.λπ. στο [Connections](https://platform.acedata.cloud/connections) → το μοντέλο μπορεί να καλέσει τα αντίστοιχα εργαλεία MCP για ανάγνωση και εγγραφή των δεδομένων του.

Στη ροή NDJSON / SSE, οι κλήσεις εργαλείων παρουσιάζονται μέσω δύο τύπων συμβάντων, `tool_use` και `tool_result`, για παράδειγμα:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Αν δεν θέλετε να εμφανίζετε τις λεπτομέρειες των κλήσεων εργαλείων στο frontend, αρκεί να αγνοήσετε τα συμβάντα `tool_use` / `tool_result` / `card` / `citation`, και η τελική έξοδος του μοντέλου συνεχίζει να ρέει μέσω `text_delta`.

Το `max_turns` μπορεί να περιορίσει πόσους γύρους μπορεί το μοντέλο να καλέσει μόνο του εργαλεία σε αυτό το αίτημα· το προεπιλεγμένο ανώτατο όριο καθορίζεται από την πλατφόρμα. Αν το ορίσετε χαμηλά (για παράδειγμα `max_turns: 1`), μπορείτε να επιβάλετε μία μόνο απάντηση και να μην επιτρέψετε καμία κλήση εργαλείου.

## Ασύγχρονη εκτέλεση και εξουσιοδότηση χωρίς επίβλεψη

Αν η κλήση σας προέρχεται από Webhook ειδοποιήσεων, CI/CD, σύστημα παρακολούθησης ή άλλες εργασίες παρασκηνίου, μπορείτε να ορίσετε `async: true` ώστε το API να επιστρέψει αμέσως ένα ID εργασίας και να συνεχίσει η εκτέλεση στο παρασκήνιο:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Η υπηρεσία μου έστειλε ειδοποίηση συναγερμού, ειδοποίησε την ομάδα WeChat «AceDataCloud团队» με προσωπικό WeChat……"
}
```

Παράδειγμα επιστροφής:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Στη συνέχεια μπορείτε να χρησιμοποιήσετε `action: retrieve` + `id` για να αναζητήσετε το αποτέλεσμα της συνομιλίας· μπορείτε επίσης να παρέχετε `callback_url`, και αφού ολοκληρωθεί η εργασία, η πλατφόρμα θα κάνει POST το `{ status, answer, usage, error }` στη διεύθυνση callback σας. Το `callback_url` πρέπει να χρησιμοποιεί `http` / `https`, και δεν μπορεί να συμπληρωθεί απευθείας με `localhost` ή ιδιωτική κυριολεκτική διεύθυνση IP.

Συνήθως δεν υπάρχει κανείς για να κάνει κλικ στην επιβεβαίωση στις εργασίες παρασκηνίου. Αν θέλετε ορισμένα Skill ή MCP Server να εκτελούν ενέργειες όπως αποστολή, δημοσίευση ή εγγραφή σε λειτουργία χωρίς επίβλεψη, παραδώστε ρητά μια λίστα προεξουσιοδότησης στο σώμα του αιτήματος:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Η υπηρεσία μου έστειλε ειδοποίηση συναγερμού, ειδοποίησε την ομάδα WeChat «AceDataCloud团队» με προσωπικό WeChat……"
}
```

Οι τιμές στο `allowed_skills` είναι τα slug των συνδεδεμένων Skill· οι τιμές στο `allowed_mcp_servers` είναι τα slug των συνδεδεμένων MCP Server. Τα Skill / MCP Server που δεν περιλαμβάνονται στην προεξουσιοδότηση, σε λειτουργία χωρίς επίβλεψη, μπορούν ακόμη μόνο να κάνουν προεπισκόπηση, dry-run ή να αρνηθούν την εκτέλεση ενεργειών εγγραφής.

Αν χρειάζεστε λεπτομερέστερο έλεγχο, μπορείτε επίσης να χρησιμοποιήσετε το ισοδύναμο αντικείμενο `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Η προεξουσιοδότηση είναι αυτές οι δύο λίστες καθαυτές: κενές λίστες σημαίνουν ότι δεν εξουσιοδοτείται καμία δυνατότητα, χωρίς να απαιτείται πρόσθετο πεδίο διακόπτη.

Σημείωση: η προεξουσιοδότηση σημαίνει μόνο ότι «αυτό το αίτημα επιτρέπει σε αυτές τις δυνατότητες να παρακάμψουν την ανθρώπινη επιβεβαίωση σε λειτουργία χωρίς επίβλεψη». Το συγκεκριμένο Skill πρέπει ακόμη να υποστηρίζει `--unattended-confirm` ή τον αντίστοιχο μηχανισμό ασφαλείας· διαφορετικά, θα συνεχίσει το dry-run και δεν θα εκτελέσει απευθείας ενέργειες εγγραφής.

## Επανάληψη συνομιλιών σε παύση

Ορισμένα εργαλεία κάνουν το μοντέλο να «ρωτά τον χρήστη», και το μοντέλο τότε εκπέμπει ένα συμβάν `ask_user_question`, ενώ η συνομιλία παγώνει στην κατάσταση `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Θέλετε η αναφορά που θα δημιουργηθεί να είναι στα κινέζικα ή στα αγγλικά;",
  "options": ["Κινέζικα", "Αγγλικά"],
  "id": "f2f4b3e8-..."
}
```

Αποδώστε αυτό το συμβάν ως κάρτα στο frontend ώστε ο χρήστης να επιλέξει απάντηση, και έπειτα ξεκινήστε το επόμενο αίτημα με το ίδιο `id`, συμπληρώνοντας ξανά την απάντηση μέσω `tool_results`:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

Το `tool_use_id` στο σώμα του αιτήματος **πρέπει** να είναι ακριβώς το ίδιο με το `tool_id` κατά την παύση· διαφορετικά θα επιστραφεί 400. Όταν στο αίτημα υπάρχει ταυτόχρονα `tool_results`, τα `question` / `message` / `references` αγνοούνται όλα.

Αν ο χρήστης αποφασίσει να εγκαταλείψει αυτή την ερώτηση, αρκεί να περάσει απευθείας ένα νέο `question` / `message`, και η πλατφόρμα θα επισημάνει αυτόματα την κλήση εργαλείου σε παύση ως «παραλείφθηκε από τον χρήστη».

## Διαχείριση συνομιλιών (CRUD)

Το v2 παρέχει ελαφριά διαχείριση συνομιλιών στο ίδιο endpoint μέσω του πεδίου `action`, χωρίς να χρειάζεται να ανοίξετε επιπλέον API.

### `action: retrieve` —— Ανάκτηση μιας συνομιλίας
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Επιστρέφει το πλήρες έγγραφο συνομιλίας (συμπεριλαμβανομένου του ιστορικού `messages`, του `model`, του `title`, του `tools_used` κ.λπ.).

### `action: retrieve_batch` —— Παράθεση περιλήψεων συνομιλιών

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Επιστρέφει `{ items: [...], total }`. **Οι περιλήψεις δεν περιλαμβάνουν `messages`**, επομένως είναι κατάλληλες για λίστες πλευρικής γραμμής· εάν ο χρήστης ανοίξει μια συνομιλία, χρησιμοποιήστε στη συνέχεια το `action: retrieve` για να ανακτήσετε ξεχωριστά τα πλήρη μηνύματά της.

Προαιρετικές παράμετροι φιλτραρίσματος: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Αλλαγή τίτλου ή επανεγγραφή ιστορικού

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Σχέδιο ταξιδιού στη Χανγκζού"
}
```

Μπορεί επίσης να περάσει το `messages`, αλλά ο διακομιστής θα εκτελέσει αυστηρό έλεγχο schema (πρέπει να είναι στη συμπτυγμένη μορφή `ToolUseContent`) και θα επιστρέψει 400 εάν δεν συμμορφώνεται. Γενικά συνιστάται να χρησιμοποιείται μόνο για την αλλαγή του `title`.

### `action: delete` —— Διαγραφή μιας συνομιλίας

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Επιστρέφει `{ id, success: true }`. Μετά τη διαγραφή δεν είναι δυνατή η ανάκτηση, επομένως επιβεβαιώστε πριν καλέσετε.

## Ομαλή μετεγκατάσταση από το v1

Εάν χρησιμοποιείτε ήδη το [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), η μετεγκατάσταση στο v2 σχεδόν δεν απαιτεί αλλαγές στον κώδικα:

1. Αλλάξτε το URL από `https://api.acedata.cloud/aichat/conversations` σε `https://api.acedata.cloud/aichat2/conversations`.
2. Εάν προηγουμένως περνούσατε ονόματα μοντέλων v1 (όπως `gpt-3.5`, `gpt-4-browsing` κ.λπ.), συνιστάται κατά τη μετάβαση στο v2 να αναβαθμίσετε σε σύγχρονα μοντέλα (όπως `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` κ.λπ.).
3. Τα πεδία της ροής NDJSON παραμένουν συμβατά προς τα πίσω: κάθε συμβάν `text_delta` εξακολουθεί να περιέχει `delta_answer` και `id`, επομένως οι υπάρχοντες πελάτες που αναλύουν γραμμή προς γραμμή το `delta_answer` δεν χρειάζονται αλλαγές.

Μετά τη μετεγκατάσταση, μπορείτε να ενεργοποιήσετε κατά περίπτωση τις νέες δυνατότητες του v2 (πολυτροπικό `message`, SSE, κλήσεις εργαλείων, `action` CRUD), προχωρώντας με τον δικό σας ρυθμό.

## Χειρισμός σφαλμάτων

Οι αποκρίσεις σφαλμάτων έχουν ενιαία μορφή:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Συνηθισμένα σφάλματα:

- `400 bad_request`: Λείπουν υποχρεωτικά πεδία, το `tool_use_id` δεν ταιριάζει, το schema του `messages` είναι μη έγκυρο κ.λπ.
- `401 invalid_token`: Η κεφαλίδα `authorization` δεν είναι σωστή.
- `404 not_found`: Κατά το `action: retrieve / update / delete`, η συνομιλία που αντιστοιχεί στο `id` δεν υπάρχει.
- `429 too_many_requests`: Ενεργοποιήθηκε ο περιορισμός ρυθμού.
- `500 chat_error`: Σφάλμα από το ανάντη LLM ή `completion_tokens=0` σε αυτόν τον γύρο (θεωρείται ότι δεν καταναλώθηκε και δεν θα υπάρξει χρέωση).

Στη ροϊκή απόκριση, τα σφάλματα εκπέμπονται ως συμβάντα `{"type":"error","message":"..."}` και αμέσως μετά η ροή τερματίζεται.

## Συμπέρασμα

Το AI Chat v2 API, διατηρώντας τη συμβατότητα προς τα πίσω με το v1, αναβαθμίζει τις συνομιλίες από «ερωτήσεις και απαντήσεις μίας / πολλαπλών γύρων» σε «παρατηρήσιμες συνομιλίες με Agent»: πολυτροπική είσοδος, κλήσεις εργαλείων, δυνατότητα παύσης / συνέχισης, ροϊκά δομημένα συμβάντα, ενσωματωμένο CRUD. Συνιστάται οι νέες ενσωματώσεις να χρησιμοποιούν απευθείας το v2· οι υπάρχουσες ενσωματώσεις v1 μπορούν να μετεγκατασταθούν ομαλά σταδιακά. Εάν έχετε οποιεσδήποτε ερωτήσεις, επικοινωνήστε ανά πάσα στιγμή με την ομάδα τεχνικής υποστήριξής μας.
