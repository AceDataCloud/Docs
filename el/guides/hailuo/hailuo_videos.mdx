Αυτό το έγγραφο θα παρουσιάσει μια μέθοδο σύνδεσης με το API Δημιουργίας Βίντεο Hailuo, το οποίο μπορεί να δημιουργήσει βίντεο από την επίσημη Hailuo μέσω εισαγωγής προσαρμοσμένων παραμέτρων.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το API, πρέπει πρώτα να επισκεφθείτε τη σελίδα [API Δημιουργίας Βίντεο Hailuo](https://platform.acedata.cloud/documents/ee06377b-9185-438f-ac84-3376bcb1275e) και να ζητήσετε την αντίστοιχη υπηρεσία. Αφού μπείτε στη σελίδα, κάντε κλικ στο κουμπί «Acquire», όπως φαίνεται στην εικόνα:

![](https://cdn.acedata.cloud/q6ytrc.png)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης για να εγγραφείτε και να συνδεθείτε. Μετά την εγγραφή και σύνδεση, θα επιστρέψετε αυτόματα στη τρέχουσα σελίδα.

Κατά την πρώτη αίτηση, θα υπάρχει δωρεάν πίστωση που μπορείτε να χρησιμοποιήσετε δωρεάν για αυτό το API.

## Βασική Χρήση

Αρχικά, πρέπει να κατανοήσετε τη βασική μέθοδο χρήσης, δηλαδή να εισάγετε τη λέξη-κλειδί `prompt`, τη δράση `action`, τη διεύθυνση URL της πρώτης εικόνας `first_image_url` και το μοντέλο `model`, για να λάβετε το επεξεργασμένο αποτέλεσμα. Πρώτα, πρέπει να περάσετε ένα πεδίο `action`, του οποίου η τιμή είναι `generate`. Στη συνέχεια, πρέπει να εισάγουμε το μοντέλο, το οποίο είναι κυρίως το μοντέλο βίντεο από εικόνα `minimax-i2v` και το μοντέλο βίντεο από κείμενο `minimax-t2v`, οι λεπτομέρειες είναι οι εξής:

<p><img src="https://cdn.acedata.cloud/7jyu0n.png" width="500" class="m-auto"></p>

Μπορείτε να δείτε ότι έχουμε ρυθμίσει τα Request Headers, που περιλαμβάνουν:

- `accept`: ποια μορφή απάντησης θέλετε να λάβετε, εδώ συμπληρώνεται ως `application/json`, δηλαδή σε μορφή JSON.
- `authorization`: το κλειδί για την κλήση του API, το οποίο μπορείτε να επιλέξετε απευθείας μετά την αίτηση.

Επιπλέον, έχουμε ρυθμίσει το Request Body, που περιλαμβάνει:

- `model`: το μοντέλο για τη δημιουργία του βίντεο, κυρίως τα μοντέλα βίντεο από εικόνα `minimax-i2v` και βίντεο από κείμενο `minimax-t2v`.
- `action`: η δράση της τρέχουσας εργασίας δημιουργίας βίντεο.
- `first_image_url`: η διεύθυνση URL της πρώτης εικόνας αναφοράς που πρέπει να ανεβεί όταν επιλέγεται το μοντέλο βίντεο από εικόνα `minimax-i2v`, δεν υποστηρίζει κωδικοποίηση Base64.
- `prompt`: η λέξη-κλειδί.
- `callback_url`: η διεύθυνση URL στην οποία χρειάζεται να επιστραφούν τα αποτελέσματα.

Αφού επιλέξετε, μπορείτε να δείτε ότι έχει παραχθεί ο αντίστοιχος κώδικας στα δεξιά, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/8psuxw.png" width="500" class="m-auto"></p>

Κάντε κλικ στο κουμπί «Try» για να κάνετε δοκιμή, όπως φαίνεται στην παραπάνω εικόνα, και εδώ έχουμε λάβει το εξής αποτέλεσμα:

```json
{
  "success": true,
  "task_id": "baf1034c-684c-46be-ae6d-89ebb89b690d",
  "trace_id": "3221eb74-1a25-447a-ba69-7d9b310e306c",
  "data": [
    {
      "id": "0pv8yhe4fdrge0cmckpv23pd2g",
      "model": "minimax-t2v",
      "prompt": "Internal heat",
      "video_url": "https://file.aigpai.com/czjl/qoueLWBokF3ud6tdVD6VJTZuXTnK5HaMO2qAOS46Ef8VSBFUA/tmp9e3u11c1.output.mp4",
      "state": "succeeded"
    }
  ]
}
```

Η επιστρεφόμενη απάντηση περιλαμβάνει πολλά πεδία, τα οποία περιγράφονται ως εξής:

- `success`, η κατάσταση της τρέχουσας εργασίας δημιουργίας βίντεο.
- `task_id`, το ID της τρέχουσας εργασίας δημιουργίας βίντεο.
- `trace_id`, το ID παρακολούθησης της τρέχουσας εργασίας δημιουργίας βίντεο.
- `data`, η λίστα αποτελεσμάτων της τρέχουσας εργασίας δημιουργίας βίντεο.
  - `id`, το ID του βίντεο της τρέχουσας εργασίας δημιουργίας βίντεο.
  - `prompt`, η λέξη-κλειδί της τρέχουσας εργασίας δημιουργίας βίντεο.
  - `model`, ο σύνδεσμος του εξωφύλλου της τρέχουσας εργασίας δημιουργίας βίντεο.
  - `video_url`, ο σύνδεσμος του βίντεο της τρέχουσας εργασίας δημιουργίας βίντεο.
  - `state`, η κατάσταση της τρέχουσας εργασίας δημιουργίας βίντεο.

Μπορείτε να δείτε ότι έχουμε λάβει ικανοποιητικές πληροφορίες βίντεο, και απλά πρέπει να αποκτήσουμε το παραγόμενο βίντεο Hailuo από τη διεύθυνση URL του βίντεο στο `data`.

Επιπλέον, εάν θέλετε να δημιουργήσετε τον αντίστοιχο κώδικα σύνδεσης, μπορείτε να τον αντιγράψετε απευθείας, όπως ο παρακάτω κώδικας CURL:

```shell
curl -X POST 'https://api.acedata.cloud/hailuo/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "Internal heat"
}'
```

## Ασύγχρονη Επιστροφή

Δεδομένου ότι ο χρόνος δημιουργίας του API Δημιουργίας Βίντεο Hailuo είναι σχετικά μεγάλος, περίπου 1-2 λεπτά, εάν το API δεν απαντήσει για μεγάλο χρονικό διάστημα, το HTTP αίτημα θα διατηρεί τη σύνδεση, προκαλώντας επιπλέον κατανάλωση πόρων συστήματος. Έτσι, αυτό το API παρέχει επίσης υποστήριξη για ασύγχρονη επιστροφή.

Η συνολική διαδικασία είναι: όταν ο πελάτης υποβάλλει το αίτημα, προσδιορίζει επιπλέον ένα πεδίο `callback_url`. Μετά την υποβολή του αιτήματος API, το API θα επιστρέψει αμέσως ένα αποτέλεσμα που περιλαμβάνει ένα πεδίο `task_id`, το οποίο αντιπροσωπεύει το ID της τρέχουσας εργασίας. Όταν ολοκληρωθεί η εργασία, το αποτέλεσμα του παραγόμενου βίντεο θα αποσταλεί μέσω POST JSON στη διεύθυνση URL `callback_url` που έχει καθορίσει ο πελάτης, η οποία περιλαμβάνει επίσης το πεδίο `task_id`, έτσι ώστε το αποτέλεσμα της εργασίας να μπορεί να συσχετιστεί μέσω του ID.

Ας δούμε πώς να το κάνουμε αυτό μέσω ενός παραδείγματος.

Αρχικά, η επιστροφή Webhook είναι μια υπηρεσία που μπορεί να δέχεται HTTP αιτήματα, οι προγραμματιστές θα πρέπει να την αντικαταστήσουν με τη διεύθυνση URL του HTTP διακομιστή που έχουν δημιουργήσει. Για ευκολία, χρησιμοποιούμε έναν δημόσιο ιστότοπο παραδείγματος Webhook https://webhook.site/, ανοίγοντας αυτόν τον ιστότοπο μπορείτε να λάβετε μια διεύθυνση URL Webhook, όπως φαίνεται στην εικόνα:

![](https://cdn.acedata.cloud/cjjfly.png)

Αντιγράψτε αυτή τη διεύθυνση URL και μπορείτε να τη χρησιμοποιήσετε ως Webhook, το παράδειγμα εδώ είναι `https://webhook.site/580b81f5-596e-4321-b03f-606770b0bb83`.

Στη συνέχεια, μπορούμε να ρυθμίσουμε το πεδίο `callback_url` στην παραπάνω διεύθυνση URL Webhook, ενώ συμπληρώνουμε τις αντίστοιχες παραμέτρους, οι λεπτομέρειες είναι όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/odabh3.png" width="500" class="m-auto"></p>

Κάνοντας κλικ στην εκτέλεση, μπορείτε να δείτε ότι θα λάβετε αμέσως ένα αποτέλεσμα, όπως παρακάτω:

```
{
  "task_id": "05aff65c-5e84-442b-8e29-3a5d27130840"
}
```

Μετά από λίγο, μπορείτε να παρακολουθήσετε το αποτέλεσμα του παραγόμενου βίντεο στη διεύθυνση `https://webhook.site/580b81f5-596e-4321-b03f-606770b0bb83`, όπως φαίνεται στην εικόνα:

![](https://cdn.acedata.cloud/7jngb4.png)

Το περιεχόμενο είναι ως εξής:

```json
{
    "success": true,
    "task_id": "05aff65c-5e84-442b-8e29-3a5d27130840",
    "trace_id": "b9856b8a-725d-45c9-befe-e789d9fd9ffb",
    "data": [
        {
            "id": "t80jhsf96srg80cmcm6b0rk8gm",
            "model": "minimax-t2v",
            "prompt": "Internal heat",
            "video_url": "https://file.aigpai.com/czjl/YPaUz2DcwpJqItTXAG9XHAoEoj3dbF0XPU69LT5nefCMzBFUA/tmp8s_59jez.output.mp4",
            "state": "succeeded"
        }
    ]
}
```

Μπορείτε να δείτε ότι το αποτέλεσμα περιλαμβάνει ένα πεδίο `task_id`, και τα υπόλοιπα πεδία είναι παρόμοια με τα παραπάνω, μέσω αυτού του πεδίου μπορείτε να επιτύχετε τη συσχέτιση της εργασίας.

## Διαχείριση Σφαλμάτων
Κατά την κλήση του API, εάν προκύψει σφάλμα, το API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διαπιστευτήριο εξουσιοδότησης.
- `429 too_many_requests`: Πάρα πολλές αιτήσεις, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.

### Παράδειγμα σφάλματος απόκρισης

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
