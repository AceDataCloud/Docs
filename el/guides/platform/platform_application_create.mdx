Η «αίτηση (Application)» υποδηλώνει τη σχέση συνδρομής του τρέχοντος λογαριασμού με μια υπηρεσία — πρέπει πρώτα να υποβάλετε αίτηση, πριν μπορέσετε να δημιουργήσετε διαπιστευτήρια API για αυτήν την αίτηση και να καλέσετε επιχειρηματικά interfaces. Κατά την πρώτη αίτηση για μια υπηρεσία, το Application θα λάβει το τρέχον διαμορφωμένο `free_amount` της υπηρεσίας· αυτή η τιμή μπορεί να είναι 0.

> ℹ️ Αυτό το interface ανήκει στο **API διαχείρισης πλατφόρμας AceDataCloud**, με ενιαίο πρόθεμα `https://platform.acedata.cloud/api/v1/`. Για το πλήρες ευρετήριο interfaces, δείτε [Λήψη λίστας εγγράφων πλατφόρμας AceDataCloud](https://platform.acedata.cloud/documents/platform-document-list).

## Πλήρης ροή ενσωμάτωσης

Οι νέοι χρήστες συνήθως ακολουθούν αυτά τα 5 βήματα από την εγγραφή έως την επιτυχή κλήση του πρώτου επιχειρηματικού interface:

1. **Λήψη token λογαριασμού** → [Διαχείριση token λογαριασμού πλατφόρμας AceDataCloud](https://platform.acedata.cloud/documents/platform-token)
2. **Επιλογή υπηρεσίας** → [Λήψη λίστας υπηρεσιών πλατφόρμας AceDataCloud](https://platform.acedata.cloud/documents/platform-service-list)
3. **Δημιουργία αίτησης** (αυτό το έγγραφο) → Λήψη αρχικού ορίου σύμφωνα με τη διαμόρφωση της υπηρεσίας
4. **Δημιουργία διαπιστευτηρίων API** → [Δημιουργία διαπιστευτηρίων API πλατφόρμας AceDataCloud](https://platform.acedata.cloud/documents/platform-credential-create)
5. **Κλήση επιχειρηματικού interface** → Χρησιμοποιήστε το ληφθέν Token 32 χαρακτήρων για κλήση του `https://api.acedata.cloud/<path>`

## Επισκόπηση interface

| Στοιχείο            | Περιεχόμενο                                           |
| ------------------ | ----------------------------------------------------- |
| Μέθοδος            | `POST`                                                |
| URL                | `https://platform.acedata.cloud/api/v1/applications/` |
| Αυθεντικοποίηση    | ✅ Απαιτείται token λογαριασμού                       |
| Content-Type       | `application/json`                                    |

## Οδηγίες αυθεντικοποίησης (πώς να αποκτήσετε token λογαριασμού)

Κεφαλίδα αιτήματος:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Το token λογαριασμού (Account Token) είναι το «κλειδί επιπέδου λογαριασμού» μέσω του οποίου οι προγραμματιστές διαχειρίζονται τους πόρους του λογαριασμού τους μέσω API. Τρόποι απόκτησης:

1. **Δημιουργία με ένα κλικ από την κονσόλα (συνιστάται)**: Συνδεθείτε στην [πλατφόρμα AceDataCloud](https://platform.acedata.cloud) → [Κονσόλα Account Token](https://platform.acedata.cloud/console/platform-tokens) → κάντε κλικ στο «Δημιουργία» για να αποκτήσετε ένα token που αρχίζει με `platform-v1-`.
2. **Δημιουργία μέσω API**: Χρησιμοποιήστε ένα υπάρχον token λογαριασμού ή JWT κατάστασης σύνδεσης προγράμματος περιήγησης για να καλέσετε το `POST /api/v1/platform-tokens/`, δείτε λεπτομέρειες στο [Διαχείριση token λογαριασμού πλατφόρμας AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

> ⚠️ Το token λογαριασμού είναι εξίσου ευαίσθητο με τον κωδικό πρόσβασης και απαγορεύεται να καταγράφεται σε κώδικα frontend ή δημόσια αποθετήρια. Σε περίπτωση διαρροής, διαγράψτε το αμέσως από την κονσόλα και δημιουργήστε νέο.

## Σώμα αιτήματος

| Παράμετρος       | Τύπος | Υποχρεωτικό | Περιγραφή                                                                                              |
| --------------- | ----- | ---------- | ------------------------------------------------------------------------------------------------------ |
| `service_id`    | UUID  | ✅         | Το ID της υπηρεσίας για την οποία θα υποβληθεί αίτηση. Μπορεί να ληφθεί από το `items[].id` της [λίστας υπηρεσιών](https://platform.acedata.cloud/documents/platform-service-list) |

## Παράδειγμα αιτήματος

### cURL

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/applications/' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'content-type: application/json' \
  -d '{"service_id": "38ecf158-36f2-42f2-8e7f-6786cdfc2452"}'
```

### Python

```python
import os
import requests

PLATFORM_TOKEN = os.environ["PLATFORM_TOKEN"]
SERVICE_ID = "38ecf158-36f2-42f2-8e7f-6786cdfc2452"

resp = requests.post(
    "https://platform.acedata.cloud/api/v1/applications/",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {PLATFORM_TOKEN}",
        "content-type": "application/json",
    },
    json={"service_id": SERVICE_ID},
    timeout=10,
)

if resp.status_code == 201:
    app = resp.json()
    print(f"申请成功！application_id={app['id']}")
    print(f"初始额度：{app['remaining_amount']} {app.get('service', {}).get('unit', '')}")
elif resp.status_code == 400 and resp.json().get("code") == "duplication":
    print("⚠️ 已经申请过此服务，请到 /applications/ 列表里找到现成的 application_id")
else:
    print(f"申请失败：HTTP {resp.status_code} - {resp.text}")
```

### Node.js

```javascript
const PLATFORM_TOKEN = process.env.PLATFORM_TOKEN
const SERVICE_ID = '38ecf158-36f2-42f2-8e7f-6786cdfc2452'

const resp = await fetch('https://platform.acedata.cloud/api/v1/applications/', {
  method: 'POST',
  headers: {
    accept: 'application/json',
    authorization: `Bearer ${PLATFORM_TOKEN}`,
    'content-type': 'application/json',
  },
  body: JSON.stringify({ service_id: SERVICE_ID }),
})

if (resp.status === 201) {
  const app = await resp.json()
  console.log('application_id =', app.id)
} else {
  console.error(await resp.text())
}
```

### Έχει ήδη υποβληθεί αίτηση (HTTP 400)

```json
{
  "detail": "Item already exists.",
  "code": "duplication",
  "trace_id": "1a87524f8cbba0b790b2951e2e43117e"
}
```

Αυτό αποτελεί αυστηρό περιορισμό σχεδιασμού: **κάθε χρήστης μπορεί να έχει μόνο ένα Application για κάθε υπηρεσία**. Αν υπάρχει ήδη, αναζητήστε το υπάρχον μέσω της [Λίστας αιτήσεων υπηρεσίας πλατφόρμας AceDataCloud](https://platform.acedata.cloud/documents/platform-application-list).

### Η υπηρεσία δεν υπάρχει (HTTP 404)

```json
{
  "detail": "Service not found.",
  "code": "not_found",
  "trace_id": "..."
}
```

### Η υπηρεσία απαιτεί έγκριση (HTTP 403)

```json
{
  "detail": "This service requires manual verification.",
  "code": "need_verify",
  "trace_id": "..."
}
```

Εάν η υπηρεσία έχει `need_verify=true` (το πεδίο αυτό είναι ορατό στη λίστα υπηρεσιών), πρέπει να ακολουθήσετε τη διαδικασία ticket για αίτηση λευκής λίστας.

## Χειρισμός σφαλμάτων
| HTTP | κωδικός            | Σημασία                   |
| ---- | ------------------- | ------------------------- |
| 400  | `duplication`       | Η υπηρεσία έχει ήδη αιτηθεί από τον τρέχοντα λογαριασμό |
| 400  | `invalid`           | Το `service_id` λείπει ή έχει εσφαλμένη μορφή |
| 401  | `not_authenticated` | Λείπει το διακριτικό λογαριασμού ή το διακριτικό έχει διαγραφεί |
| 403  | `need_verify`       | Η υπηρεσία χρειάζεται έγκριση, παρακαλούμε ακολουθήστε τη διαδικασία αιτήματος |
| 404  | `not_found`         | Η υπηρεσία δεν υπάρχει ή έχει αποσυρθεί |

Ενιαία μορφή απόκρισης σφάλματος:

```json
{
  "detail": "...",
  "code": "...",
  "trace_id": "..."
}
```

## Χρήσιμες συμβουλές

- **Η ίδια η δημιουργία δεν χρεώνεται**: κατά την πρώτη δημιουργία, το αρχικό όριο ορίζεται σύμφωνα με το τρέχον `free_amount` της υπηρεσίας· αυτή η τιμή μπορεί να είναι 0, και η εκ νέου δημιουργία Application του ίδιου τύπου δεν εγγυάται επαναλαμβανόμενη δωρεάν παροχή.
- **Το αν απαιτείται πληρωμή εξαρτάται από το πεδίο `paid`**: αμέσως μετά την αίτηση `paid=false`, και μετά την κλήση [Δημιουργία εντολής επαναφόρτισης της πλατφόρμας AceDataCloud](https://platform.acedata.cloud/documents/platform-order-create) για την ολοκλήρωση της πληρωμής γίνεται `true`.
- **Το `disabled=true` υποδηλώνει ότι έχει απενεργοποιηθεί προσωρινά**—για παράδειγμα, λόγω ενεργοποίησης ελέγχου κινδύνου, οφειλών κ.λπ. Όταν είναι απενεργοποιημένο, η επιχειρηματική διεπαφή θα επιστρέφει `403`.
- **Μην δημιουργείτε χωρίς όρια ταυτόχρονα**: πρώτα αποκτήστε το στοχευμένο `service_id` από τη σελιδοποιημένη λίστα υπηρεσιών και, στη συνέχεια, υποβάλετε αιτήσεις ανά στοιχείο σύμφωνα με τις επιχειρηματικές ανάγκες· όταν συναντάτε `duplication`, επαναχρησιμοποιήστε το υπάρχον Application.
