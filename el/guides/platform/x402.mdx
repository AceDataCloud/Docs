Το X402 είναι ένα πρωτόκολλο πληρωμής σε blockchain βασισμένο στο HTTP `402 Payment Required`. Μέσω των δυνατοτήτων X402 της Ace Data Cloud, οι καλούντες μπορούν να ολοκληρώσουν πληρωμές σε blockchain με USDC απευθείας σε κάθε αίτημα API, χωρίς να χρειάζεται να δημιουργήσουν API Token ή να προφορτίσουν το υπόλοιπο του λογαριασμού.

Αυτή η ομάδα εγγράφων είναι οργανωμένη με βάση τη σειρά πραγματικής ενσωμάτωσης: πρώτα εκτελέστε ένα ελάχιστο αίτημα, στη συνέχεια ενσωματώστε το SDK, και μετά κατανοήστε το δίκτυο, τα σχέδια χρέωσης, τις πληρωμές παραγγελιών και τον Facilitator. Συνιστάται να διαβάσετε τον παρακάτω πίνακα από πάνω προς τα κάτω.

## Συνιστώμενη Διαδρομή Ενσωμάτωσης

Εάν θέλετε απλώς να καλέσετε το Ace Data Cloud API, προτιμήστε να χρησιμοποιήσετε το επίσημο SDK:

- TypeScript: `@acedatacloud/sdk` + `@acedatacloud/x402-client`
- Python: `acedatacloud` + `acedatacloud-x402`

Δημόσιες διευθύνσεις κώδικα και πακέτων:

| Έργο                 | Διεύθυνση                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| Ace Data Cloud SDK | [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)                                         |
| X402 Client        | [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)                           |
| X402 Facilitator   | [https://github.com/AceDataCloud/FacilitatorX402](https://github.com/AceDataCloud/FacilitatorX402)                 |
| npm SDK            | [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)                 |
| npm X402 Client    | [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client) |
| PyPI SDK           | [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)                                   |
| PyPI X402 Client   | [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)                         |

Το SDK θα ολοκληρώσει αυτόματα την πρώτη αίτηση χωρίς πιστοποίηση, θα αναλύσει το `402 Payment Required`, θα καλέσει τον διαχειριστή πληρωμών και θα επαναλάβει αυτά τα βήματα με το `PAYMENT-SIGNATURE`. Απλώς χρειάζεστε ένα πορτοφόλι με USDC και να επιλέξετε το δίκτυο που επιθυμείτε να χρησιμοποιήσετε.

Εάν θέλετε να υποστηρίξει το API σας και πληρωμές X402, θα χρειαστεί να διαβάσετε την τεκμηρίωση του Facilitator, κατανοώντας τη σχέση μεταξύ `paymentRequirements`, `paymentPayload`, `/verify` και `/settle`.

## Κατάσταση Υποστήριξης

Το Ace Data Cloud X402 έχει ολοκληρώσει την επαλήθευση σε δημόσια API, επίσημα SDK, Facilitator και διαδρομές διακανονισμού σε blockchain. Ο παρακάτω πίνακας συνοψίζει την τρέχουσα κατάσταση με βάση τις πιο συχνά χρησιμοποιούμενες δυνατότητες κατά την ενσωμάτωσή τους από προγραμματιστές.

| Δυνατότητα                   | Κατάσταση              | Σημείωση                                                                 |
| ------------------------ | ------------------- | ------------------------------------------------------------------ |
| Δυνατότητες Facilitator | Διαθέσιμες            | `https://facilitator.acedata.cloud/.well-known/x402` επιστρέφει τα δίκτυα πληρωμών και τα σημεία πρωτοκόλλου.  |
| API 402 `accepts`        | Διαθέσιμες            | Ανεξόφλητα αιτήματα επιστρέφουν διαθέσιμες απαιτήσεις πληρωμής για Base, SKALE και Solana.              |
| TypeScript SDK           | Διαθέσιμες            | `@acedatacloud/sdk` και `@acedatacloud/x402-client` μπορούν να διαχειριστούν αυτόματα το 402, τις υπογραφές και τις επαναλήψεις. |
| Python SDK               | Διαθέσιμες            | `acedatacloud` και `acedatacloud-x402` μπορούν να διαχειριστούν αυτόματα το 402, τις υπογραφές και τις επαναλήψεις.              |
| Base `exact`             | Επαληθευμένο σε blockchain | Κατάλληλο για API σταθερού ποσού και πληρωμές παραγγελιών.                                                  |
| Base `upto`              | Επαληθευμένο σε blockchain | Κατάλληλο για API με χρέωση μετά την κατανάλωση, το μοναδικό δίκτυο που προσφέρει `upto`.                                 |
| SKALE `exact`            | Επαληθευμένο σε blockchain | Κατάλληλο για σενάρια πληρωμών EVM με χαμηλό κόστος gas.                                              |
| Solana `exact`           | Επαληθευμένο HTTP paid retry | Επαληθευμένο API paid retry με απόκριση μοντέλου; προτείνεται η χρήση του δικού σας Solana RPC για συμφωνία.               |
| Πληρωμή Παραγγελίας         | Επαληθευμένο σε blockchain | Η πληρωμή παραγγελίας Base `exact` έχει ολοκληρώσει τον διακανονισμό σε blockchain και έχει ενημερώσει την κατάσταση της παραγγελίας.                                   |

- Τα πακέτα npm και PyPI έχουν εγκατασταθεί και εισαχθεί επιτυχώς σε καθαρό περιβάλλον.
- Η μη πληρωμένη API αίτηση επιστρέφει 402, το `accepts` περιλαμβάνει διαθέσιμους τρόπους πληρωμής για Base, SKALE και Solana.
- Το `accepts[].network` είναι η αναγνώριση CAIP-2, οι πελάτες πρέπει να ταιριάζουν με τη συμβολοσειρά CAIP-2 κατά την επιλογή δικτύου.
- Τα TypeScript SDK και Python SDK μπορούν αυτόματα να διαχειριστούν το 402 και να ολοκληρώσουν την πληρωμή επαναλαμβάνοντας.
- Οι διευθύνσεις εξερεύνησης για Base `exact`, SKALE `exact`, Base `upto` και πληρωμή παραγγελίας είναι δημόσιες.
- Το ανώτατο όριο υπογραφής για το Base `upto` είναι `95215` ατομικά USDC, η πραγματική διακανονιστική αξία είναι `3` ατομικά USDC, που αντικατοπτρίζει τη δυνατότητα διακανονισμού με βάση την πραγματική κατανάλωση.
- Το Solana `exact` έχει επαληθευτεί HTTP 402 -> HTTP 200 και έξοδο μοντέλου. Δεδομένου ότι οι δημόσιες RPC ερωτήσεις μπορεί να περιορίζονται, προτείνεται η χρήση ιδιωτικού Solana RPC ή καταγραφών διακανονισμού της πλατφόρμας για την επιβεβαίωση υπογραφής συναλλαγής.

## Σημειώσεις για την πρόσβαση

Κατά την πρόσβαση των προγραμματιστών, παρακαλούμε να δώσουν προτεραιότητα στις τρέχουσες απαιτήσεις πληρωμής που επιστρέφονται σε πραγματικό χρόνο, αντί να αντιγράψουν τα παραδείγματα ποσών ή διευθύνσεων από το έγγραφο:

- Το `accepts[].maxAmountRequired` είναι το μέγιστο ποσό που μπορεί να υπογραφεί για την τρέχουσα αίτηση.
- Το `accepts[].asset` είναι το συμβόλαιο ή το mint USDC που θα χρησιμοποιηθεί για αυτή την αίτηση.
- Τα `accepts[].extra.chainId`, `accepts[].extra.facilitatorAddress` και `accepts[].extra.verifyingContract` θα συμμετάσχουν στην υπογραφή δεδομένων τύπου EVM.
- Το `upto` απαιτεί πρώτα την εξουσιοδότηση Permit2 για το USDC της στοχευμένης αλυσίδας από το πορτοφόλι; αν δεν έχει εξουσιοδοτηθεί, θα επιστραφεί `PERMIT2_ALLOWANCE_REQUIRED`.
- Εάν επιθυμείτε σαφώς να χρησιμοποιήσετε τη μέτρηση μετά, παρακαλώ περάστε `preferScheme: 'upto'` στο TypeScript SDK, αλλιώς το SDK θα επιλέξει την πρώτη διαθέσιμη απαίτηση που επιστρέφεται από τον διακομιστή κάτω από αυτό το δίκτυο.

## Δημόσια επαλήθευση

Πριν από την πρόσβαση, μπορείτε να επαληθεύσετε αυτές τις δημόσιες εισόδους και τη συμπεριφορά του SDK:

- Οι API αιτήσεις χωρίς `Authorization` ή `PAYMENT-SIGNATURE` θα επιστρέφουν `402 Payment Required`, το `accepts` στην απόκριση είναι η μοναδική βάση υπογραφής για αυτή την αίτηση.
- Τα TypeScript SDK και Python SDK παρέχουν χειριστή πληρωμών, το επίπεδο μεταφοράς του SDK θα καλέσει τον χειριστή και θα επαναλάβει μία φορά μετά την παραλαβή του 402.
- `https://facilitator.acedata.cloud/.well-known/x402`: επιστρέφει τα δίκτυα, τα σχέδια και τα σημεία πρωτοκόλλου που υποστηρίζει ο Facilitator; η τιμή API εξακολουθεί να ισχύει σύμφωνα με το 402 που επιστρέφεται σε πραγματικό χρόνο για την στοχευμένη αίτηση.
- `https://facilitator.acedata.cloud/supported`: επιστρέφει τα δίκτυα και τα σχέδια που υποστηρίζει ο Facilitator.
- Το αποθετήριο X402Client περιέχει εργαλεία υψηλού επιπέδου για την επαλήθευση της υπογραφής, την επανάληψη και τη συμπεριφορά του διακανονισμού; η έξοδος εργαλείων δεν αντικαθιστά την επιστροφή του API σε απευθείας σύνδεση του `accepts`.

Το `upto` ανήκει στη μέτρηση μετά, κατάλληλη για API όπως η ολοκλήρωση συνομιλιών, οι κλήσεις μοντέλων κ.λπ., όπου η πραγματική κατανάλωση είναι γνωστή μόνο μετά την απόκριση. Αυτή τη στιγμή μόνο το Base παρέχει `upto`; εάν η επαλήθευση υπογραφής αποτύχει, παρακαλώ ελέγξτε αν το chain id, η διεύθυνση facilitator, ο spender, το συμβόλαιο USDC και η επιτρεπόμενη Permit2 συμφωνούν με την απόκριση 402.
```
