Το X402 είναι ένα πρωτόκολλο πληρωμών on-chain βασισμένο στο HTTP `402 Payment Required`. Μέσω της δυνατότητας X402 του Ace Data Cloud, ο καλών δεν χρειάζεται να δημιουργήσει API Token ή να προφορτίσει το υπόλοιπο του λογαριασμού του, αλλά μπορεί να ολοκληρώνει απευθείας πληρωμές on-chain με USDC σε κάθε αίτημα API.

Αυτό το σύνολο εγγράφων οργανώνεται σύμφωνα με την πραγματική σειρά ενσωμάτωσης: πρώτα εκτελέστε ένα ελάχιστο αίτημα, έπειτα ενσωματώστε το SDK και στη συνέχεια κατανοήστε τα δίκτυα, τα μοντέλα χρέωσης, την πληρωμή παραγγελιών και το Facilitator. Συνιστάται να διαβάσετε από πάνω προς τα κάτω σύμφωνα με τον παρακάτω πίνακα.

| ---------------- | ------------------------------------------------- | --------------------------------------------------------------------------------- |

## Προτεινόμενη διαδρομή ενσωμάτωσης

Αν θέλετε απλώς να καλέσετε το Ace Data Cloud API, δώστε προτεραιότητα στη χρήση του επίσημου SDK:

- TypeScript：`@acedatacloud/sdk` + `@acedatacloud/x402-client`
- Python：`acedatacloud` + `acedatacloud-x402`

Δημόσιος πηγαίος κώδικας και διευθύνσεις πακέτων:

| Έργο                 | Διεύθυνση                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| Ace Data Cloud SDK | [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)                                         |
| X402 Client        | [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)                           |
| X402 Facilitator   | [https://github.com/AceDataCloud/FacilitatorX402](https://github.com/AceDataCloud/FacilitatorX402)                 |
| npm SDK            | [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)                 |
| npm X402 Client    | [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client) |
| PyPI SDK           | [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)                                   |
| PyPI X402 Client   | [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)                         |

Το SDK θα ολοκληρώσει αυτόματα αυτά τα βήματα: το πρώτο μη αυθεντικοποιημένο αίτημα, την ανάλυση του `402 Payment Required`, την κλήση του payment handler και την επανάληψη με `PAYMENT-SIGNATURE`. Χρειάζεται μόνο να προετοιμάσετε ένα πορτοφόλι με USDC και να επιλέξετε το δίκτυο που θέλετε να χρησιμοποιήσετε.

Αν θέλετε το δικό σας API να υποστηρίζει επίσης εισπράξεις X402, τότε πρέπει να διαβάσετε την τεκμηρίωση Facilitator για να κατανοήσετε τη σχέση μεταξύ `paymentRequirements`, `paymentPayload`, `/verify` και `/settle`.

## Κατάσταση υποστήριξης

Το Ace Data Cloud X402 έχει επαληθευτεί σε δημόσια API, επίσημα SDK, Facilitator και διαδρομές εκκαθάρισης on-chain. Ο παρακάτω πίνακας συνοψίζει την τρέχουσα κατάσταση σύμφωνα με τις δυνατότητες που χρησιμοποιούνται συχνότερα κατά την ενσωμάτωση από προγραμματιστές.

| Δυνατότητα                       | Κατάσταση                  | Περιγραφή                                                                 |
| ------------------------ | ------------------- | ------------------------------------------------------------------ |
| Facilitator capabilities | Διαθέσιμο                  | Το `https://facilitator.acedata.cloud/.well-known/x402` επιστρέφει δίκτυα πληρωμών και endpoints πρωτοκόλλου.  |
| API 402 `accepts`        | Διαθέσιμο                  | Τα μη πληρωμένα αιτήματα επιστρέφουν διαθέσιμα payment requirement για Base και Solana.                    |
| TypeScript SDK           | Διαθέσιμο                  | Τα `@acedatacloud/sdk` και `@acedatacloud/x402-client` μπορούν να χειριστούν αυτόματα 402, υπογραφή και επανάληψη. |
| Python SDK               | Διαθέσιμο                  | Τα `acedatacloud` και `acedatacloud-x402` μπορούν να χειριστούν αυτόματα 402, υπογραφή και επανάληψη.              |
| Base `exact`             | Επαληθευμένο on-chain               | Κατάλληλο για API σταθερού ποσού και πληρωμή παραγγελιών.                                                  |
| Base `upto`              | Επαληθευμένο on-chain               | Κατάλληλο για API μεταγενέστερης μέτρησης, όπως συμπλήρωση συνομιλίας, και επί του παρόντος το μοναδικό δίκτυο που παρέχει `upto`.                                 |
| Solana `exact`           | Έχει επαληθευτεί το HTTP paid retry | Έχει επαληθευτεί το API paid retry και η απόκριση μοντέλου· για επιβεβαίωση υπογραφής on-chain συνιστάται συμφωνία με δικό σας Solana RPC.               |
| Πληρωμή παραγγελίας                     | Επαληθευμένο on-chain               | Η πληρωμή παραγγελίας Base `exact` έχει ολοκληρώσει εκκαθάριση on-chain και έχει ενημερώσει την κατάσταση παραγγελίας.                                   |

Σημειώσεις:

- Τα πακέτα npm και PyPI έχουν εγκατασταθεί και εισαχθεί επιτυχώς σε καθαρό περιβάλλον.
- Τα μη πληρωμένα αιτήματα API επιστρέφουν 402, και το `accepts` περιλαμβάνει τις διαθέσιμες μεθόδους πληρωμής για Base και Solana.
- Το `accepts[].network` είναι αναγνωριστικό CAIP-2· ο πελάτης πρέπει να κάνει αντιστοίχιση κατά την επιλογή δικτύου με τη συμβολοσειρά CAIP-2.
- Τόσο το TypeScript SDK όσο και το Python SDK μπορούν να χειριστούν αυτόματα το 402 και να ολοκληρώσουν paid retry.
- Τα Base `exact`, Base `upto` και η πληρωμή παραγγελίας διαθέτουν διευθύνσεις explorer που μπορούν να ανοίξουν δημόσια.
- Το υπογεγραμμένο ανώτατο όριο του Base `upto` είναι `95215` atomic USDC, ενώ το πραγματικό settlement είναι `3` atomic USDC, αντικατοπτρίζοντας το χαρακτηριστικό της μεταγενέστερης μέτρησης και εκκαθάρισης βάσει πραγματικής χρήσης.
- Το Solana `exact` έχει επαληθεύσει το HTTP 402 -> HTTP 200 και την έξοδο του μοντέλου. Επειδή τα δημόσια ερωτήματα RPC μπορεί να υπόκεινται σε περιορισμό ρυθμού, για αυστηρή συμφωνία συνιστάται η χρήση ιδιόκτητου Solana RPC ή η επιβεβαίωση της υπογραφής συναλλαγής μέσω των εγγραφών settlement στην πλευρά της πλατφόρμας.

## Σημεία προσοχής ενσωμάτωσης

Κατά την ενσωμάτωση από προγραμματιστές, δώστε προτεραιότητα στις απαιτήσεις πληρωμής σε πραγματικό χρόνο που επιστρέφονται από το τρέχον αίτημα, αντί να αντιγράφετε τα παραδείγματα ποσών ή διευθύνσεων στην τεκμηρίωση:

- Το `accepts[].maxAmountRequired` είναι το μέγιστο ποσό που μπορεί να υπογραφεί για το τρέχον αίτημα.
- Το `accepts[].asset` είναι το συμβόλαιο USDC ή το mint που πρέπει να χρησιμοποιηθεί για αυτό το αίτημα.
- Τα `accepts[].extra.chainId`, `accepts[].extra.facilitatorAddress` και `accepts[].extra.verifyingContract` θα συμμετέχουν στην υπογραφή EVM typed data.
- Το `upto` απαιτεί το πορτοφόλι να εξουσιοδοτήσει πρώτα το Permit2 για το USDC της αλυσίδας-στόχου· όταν δεν υπάρχει εξουσιοδότηση, επιστρέφεται `PERMIT2_ALLOWANCE_REQUIRED`.
- Εάν επιθυμείτε ρητά να χρησιμοποιήσετε μεταγενέστερη μέτρηση, περάστε `preferScheme: 'upto'` στο TypeScript SDK· διαφορετικά, το SDK θα επιλέξει το πρώτο διαθέσιμο requirement που επιστρέφει ο διακομιστής σε αυτό το δίκτυο.

## Εύρος που μπορεί να επαληθευτεί δημόσια

Πριν από την ενσωμάτωση, μπορείτε πρώτα να επαληθεύσετε αυτά τα δημόσια σημεία εισόδου και τη συμπεριφορά του SDK:

- Αιτήματα API χωρίς `Authorization` ή `PAYMENT-SIGNATURE` επιστρέφουν `402 Payment Required`, και το `accepts` στην απόκριση είναι η μοναδική βάση υπογραφής για αυτό το αίτημα.
- Τόσο το TypeScript SDK όσο και το Python SDK παρέχουν payment handler· το επίπεδο μεταφοράς του SDK καλεί τον handler και επαναλαμβάνει μία φορά όταν λάβει 402.
- `https://facilitator.acedata.cloud/.well-known/x402`: επιστρέφει τα δίκτυα, το scheme και τα πρωτοκολλικά endpoints που υποστηρίζει ο Facilitator· η τιμή του API εξακολουθεί να βασίζεται στο 402 που επιστρέφεται σε πραγματικό χρόνο από το αίτημα-στόχο.
- `https://facilitator.acedata.cloud/supported`: επιστρέφει τα δίκτυα και τα scheme που υποστηρίζει ο Facilitator.
- Το αποθετήριο X402Client περιλαμβάνει προηγμένα εργαλεία επαλήθευσης on-chain, τα οποία μπορούν να χρησιμοποιηθούν για την επιβεβαίωση υπογραφών, επαναλήψεων και συμπεριφοράς settlement· η έξοδος των εργαλείων δεν υποκαθιστά το `accepts` που επιστρέφει το online API.

Το `upto` ανήκει σε settlement μεταγενέστερης μέτρησης και είναι κατάλληλο για API όπου η πραγματική χρήση γίνεται γνωστή μόνο μετά την απόκριση, όπως συμπληρώσεις συνομιλίας και κλήσεις μοντέλων. Προς το παρόν μόνο το Base παρέχει `upto`· εάν η επαλήθευση υπογραφής αποτύχει, ελέγξτε εάν το chain id, η διεύθυνση facilitator, το spender, το συμβόλαιο USDC και το Permit2 allowance συμφωνούν με την απόκριση 402.
