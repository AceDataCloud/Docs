**Το Διακριτικό Λογαριασμού (Account Token, παλαιότερα ονομαζόταν Platform Token)** είναι το «κλειδί επιπέδου λογαριασμού» με το οποίο οι προγραμματιστές διαχειρίζονται μέσω προγραμματισμού πόρους της πλατφόρμας AceDataCloud (αιτήσεις υπηρεσιών, διαπιστευτήρια API, παραγγελίες, αρχεία κλήσεων, υπόλοιπο, αρχεία κ.λπ.). Ο ρόλος του είναι παρόμοιος με το Token χρήστη μετά τη σύνδεση στο frontend και, από προεπιλογή, δεν έχει χρόνο λήξης· οι απλοί χρήστες μπορούν να διαχειρίζονται μόνο τα δικά τους διακριτικά, ενώ οι υπερδιαχειριστές μπορούν να διαχειρίζονται διακριτικά άλλων λογαριασμών σύμφωνα με τα δικαιώματά τους.

Το διακριτικό λογαριασμού προσπελαύνει τις διεπαφές της πλατφόρμας με τα τρέχοντα δικαιώματα του λογαριασμού στον οποίο ανήκει: τα βασικά δικαιώματα, τα άμεσα εκχωρημένα δικαιώματα και τα δικαιώματα των ομάδων χρηστών στις οποίες ανήκει εφαρμόζονται συνδυαστικά· μετά την ένταξη ή την αφαίρεση από ομάδα, το επόμενο αίτημα κρίνεται αμέσως βάσει των νέων δικαιωμάτων. Η πρόσβαση σε συγκεκριμένους πόρους, όπως αιτήσεις και παραγγελίες, εξακολουθεί να απαιτεί έλεγχο ιδιοκτησίας. Τα διακριτικά λογαριασμού δεν λήγουν από προεπιλογή· χρησιμοποιείτε τα μόνο σε αξιόπιστα περιβάλλοντα και φυλάσσετέ τα σωστά.

> ℹ️ Αυτή η διεπαφή ανήκει στο **API διαχείρισης πλατφόρμας AceDataCloud**, με ενιαίο πρόθεμα `https://platform.acedata.cloud/api/v1/`. Για το πλήρες ευρετήριο διεπαφών, δείτε [Λήψη λίστας εγγράφων πλατφόρμας AceDataCloud](https://platform.acedata.cloud/documents/platform-document-list).

## Διακριτικό Λογαριασμού vs Διαπιστευτήρια API

Οι δύο τύποι κλειδιών που συγχέουν ευκολότερα οι αρχάριοι· δείτε πρώτα καθαρά:

| Διάσταση   | **Διακριτικό Λογαριασμού** (αυτό το έγγραφο)                                                               | **Διαπιστευτήρια API (Credential)**                                                                           |
| ---- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Χρήση   | Κλήση διεπαφών διαχείρισης `https://platform.acedata.cloud/**`                                | Κλήση επιχειρησιακών διεπαφών `https://api.acedata.cloud/**` (OpenAI, Midjourney, Suno, Veo κ.λπ.)                             |
| Μορφή   | `platform-v1-` + 64 δεκαεξαδικοί χαρακτήρες (σύνολο 76 χαρακτήρες)                                          | 32 δεκαεξαδικοί χαρακτήρες                                                                                         |
| Ένας λογαριασμός | Συνήθως 1–2 διακριτικά                                                                    | 1–N διαπιστευτήρια για κάθε αίτηση υπηρεσίας                                                                                     |
| Σημείο δημιουργίας | [Κονσόλα Account Token](https://platform.acedata.cloud/console/platform-tokens) | [Δημιουργία διαπιστευτηρίων API πλατφόρμας AceDataCloud](https://platform.acedata.cloud/documents/platform-credential-create) |
| Συνθήκες ακύρωσης | Ακυρώνεται αμέσως μετά τη διαγραφή· λήγει όταν το `expiration` δεν είναι κενό                                                | Μπορούν να οριστούν όριο ποσού, χρόνος λήξης, δεσμευμένη IP προέλευσης                                                                             |

Αν θέλετε απλώς να καλέσετε το GPT-4.1, χρειάζεστε **διαπιστευτήρια API**, όχι διακριτικό λογαριασμού.
Αν θέλετε να γράψετε αυτοματοποιημένο script για διαχείριση ανανεώσεων υπολοίπου, προβολή μηνιαίων λογαριασμών ή μαζική αποστολή διαπιστευτηρίων σε μέλη ομάδας, τότε χρησιμοποιείτε διακριτικό λογαριασμού.

## Δημιουργία με ένα κλικ στην κονσόλα (συνιστάται)

1. Συνδεθείτε στο [https://platform.acedata.cloud](https://platform.acedata.cloud).
2. Μεταβείτε στην πλευρική γραμμή → «Προγραμματιστής» → «[Account Token](https://platform.acedata.cloud/console/platform-tokens)».
3. Κάντε κλικ στο κουμπί «Δημιουργία» επάνω δεξιά για να λάβετε αμέσως ένα διακριτικό `platform-v1-...`, **πατήστε το κουμπί αντιγραφής και αποθηκεύστε το στον διαχειριστή κωδικών σας**.

![Κονσόλα Account Token](https://cdn.acedata.cloud/6g86oz.png)

> ⚠️ Επί του παρόντος, οι αποκρίσεις δημιουργίας, λίστας και λεπτομερειών επιστρέφουν όλες το διακριτικό σε απλό κείμενο. Αντιμετωπίστε ολόκληρη την απόκριση ως μυστικό, μην τη γράφετε σε αρχεία καταγραφής, πλατφόρμες αναλύσεων ή μόνιμη αποθήκευση frontend· ο client δεν πρέπει επίσης να βασίζεται στη μακροχρόνια επιστροφή απλού κειμένου από τη λίστα.

## Δημιουργία διακριτικού λογαριασμού με API

### Επισκόπηση διεπαφής

| Στοιχείο    | Περιεχόμενο                                                       |
| ---- | -------------------------------------------------------- |
| Μέθοδος   | `POST`                                                   |
| URL  | `https://platform.acedata.cloud/api/v1/platform-tokens/` |
| Αυθεντικοποίηση   | ✅ Οποιοδήποτε υπάρχον διακριτικό λογαριασμού ή JWT κατάστασης σύνδεσης προγράμματος περιήγησης                                 |
| Body | `application/json` (μπορεί να σταλεί κενό αντικείμενο `{}`)                           |

### Επεξήγηση αυθεντικοποίησης (πρόβλημα κότας και αυγού)

> Πώς αποκτάτε το πρώτο διακριτικό; Η απάντηση είναι **μέσω της κονσόλας** — μετά τη σύνδεση στο πρόγραμμα περιήγησης, η κονσόλα καλεί το `POST /platform-tokens/` με αυθεντικοποίηση JWT και σας εκδίδει το πρώτο διακριτικό.
> Στη συνέχεια, μπορείτε να χρησιμοποιήσετε οποιοδήποτε υπάρχον διακριτικό `platform-v1-...` για να δημιουργήσετε περισσότερα.

Μορφή κεφαλίδων αιτήματος:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
Content-Type: application/json
```

### Παράδειγμα αιτήματος

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/platform-tokens/' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'content-type: application/json' \
  -d '{}'
```

### Απόκριση (HTTP 201)

```json
{
  "id": "3264f1aa-cbe1-4e2c-a434-95adba4f8304",
  "token": "platform-v1-<REDACTED>",
  "expiration": null,
  "user_id": "89518d07-5560-4b05-92c1-667f3ddf6a4b",
  "created_at": "2026-04-26T15:50:11.123456Z",
  "updated_at": "2026-04-26T15:50:11.123456Z",
  "used_at": null
}
```

### Περιγραφή πεδίων

| Πεδίο           | Τύπος                 | Περιγραφή                                                   |
| ------------ | ------------------ | ---------------------------------------------------- |
| `id`         | UUID               | Πρωτεύον κλειδί διακριτικού, χρησιμοποιείται κατά τη διαγραφή / ερώτημα λεπτομερειών                                     |
| `token`      | string             | Απλό κείμενο διακριτικού λογαριασμού. Μορφή `platform-v1-` + 64 δεκαεξαδικοί χαρακτήρες (σύνολο 76 χαρακτήρες), πρέπει να αντιμετωπίζεται ως μυστικό |
| `expiration` | int \| null        | Χρόνος λήξης (χρονική σήμανση σε δευτερόλεπτα). Το `null` δηλώνει ότι δεν έχει οριστεί χρόνος λήξης                         |
| `user_id`    | UUID               | ID του χρήστη στον οποίο ανήκει. Είναι επίσης η τιμή της παραμέτρου `?user_id=` που πρέπει να περάσει σε όλες τις επόμενες διεπαφές λίστας               |
| `created_at` | datetime (ISO8601) | Χρόνος δημιουργίας                                                 |
| `updated_at` | datetime (ISO8601) | Χρόνος ενημέρωσης                                                 |
| `used_at`    | datetime \| null   | Χρόνος τελευταίας χρήσης για αυθεντικοποίηση. Αν δεν έχει χρησιμοποιηθεί ποτέ, είναι `null`, και μπορεί να χρησιμοποιηθεί για τον εντοπισμό «διακριτικών-ζόμπι»                |

## Λήψη λίστας διακριτικών λογαριασμού

### Επισκόπηση διεπαφής

| Στοιχείο   | Περιεχόμενο                                                       |
| --- | -------------------------------------------------------- |
| Μέθοδος  | `GET`                                                    |
| URL | `https://platform.acedata.cloud/api/v1/platform-tokens/` |
| Αυθεντικοποίηση  | ✅ Απαιτείται διακριτικό λογαριασμού                                                 |

### Υποχρεωτική παράμετρος ερωτήματος

> ⚠️ **Πρέπει να περιλαμβάνεται `?user_id=<your_user_id>`**. Αιτία: η διεπαφή λίστας εκτελεί έλεγχο δικαιωμάτων **ανά αντικείμενο** στα αποτελέσματα σελιδοποίησης· όταν δεν περιλαμβάνεται το `user_id`, το πρώτο αντικείμενο που δεν σας ανήκει θα απορριφθεί και θα επιστραφεί `403 permission_denied`.

Πώς να αποκτήσετε το `user_id`:

1. Ανοίξτε στο πρόγραμμα περιήγησης το [https://auth.acedata.cloud/user/profile](https://auth.acedata.cloud/user/profile), όπου το πλήρες UUID εμφανίζεται στο επάνω μέρος της σελίδας.
2. Εναλλακτικά, συμπληρώστε απευθείας το πεδίο `user_id` από την τιμή επιστροφής του `POST /platform-tokens/`.

### Παράμετροι ερωτήματος
| Παράμετρος         | Υποχρεωτικό  | Τύπος     | Περιγραφή                    |
| ---------- | --- | ------ | --------------------- |
| `user_id`  | ✅   | UUID   | Αναγνωριστικό χρήστη του τρέχοντος λογαριασμού            |
| `limit`    | ❌   | int    | Αριθμός εγγραφών ανά σελίδα, προεπιλογή 10, μέγιστο 100     |
| `offset`   | ❌   | int    | Μετατόπιση                    |
| `ordering` | ❌   | string | Πεδίο ταξινόμησης, προεπιλογή `-created_at` |

### Παράδειγμα αιτήματος

```shell
curl 'https://platform.acedata.cloud/api/v1/platform-tokens/?user_id=89518d07-5560-4b05-92c1-667f3ddf6a4b&limit=5' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Απόκριση（HTTP 200）

```json
{
  "count": 2,
  "items": [
    {
      "id": "51c575a2-801c-4211-bc47-711452a8c8c9",
      "token": "platform-v1-<REDACTED>",
      "expiration": null,
      "user_id": "89518d07-5560-4b05-92c1-667f3ddf6a4b",
      "created_at": "2026-04-26T15:41:32.761705Z",
      "updated_at": "2026-04-26T15:41:32.761726Z",
      "used_at": null
    }
  ]
}
```

> Η σελιδοποιημένη απόκριση αυτού του API χρησιμοποιεί `count` + `items`. Άλλα API της πλατφόρμας ενδέχεται να χρησιμοποιούν διαφορετική δομή· ανατρέξτε στην αντίστοιχη τεκμηρίωση και στην πραγματική απόκριση.

## Λήψη λεπτομερειών διακριτικού λογαριασμού

| Στοιχείο   | Περιεχόμενο                                                                      |
| --- | ----------------------------------------------------------------------- |
| Μέθοδος  | `GET`                                                                   |
| URL | `https://platform.acedata.cloud/api/v1/platform-tokens/<id>`（**χωρίς κάθετο στο τέλος**） |
| Εξουσιοδότηση  | ✅ Μόνο ο δημιουργός του διακριτικού ή ο υπερδιαχειριστής έχει πρόσβαση                                                       |

```shell
curl 'https://platform.acedata.cloud/api/v1/platform-tokens/51c575a2-801c-4211-bc47-711452a8c8c9' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

Η δομή επιστροφής είναι ίδια με το στοιχείο της λίστας, `HTTP 200`.

## Διαγραφή διακριτικού λογαριασμού

| Στοιχείο   | Περιεχόμενο                                                                      |
| --- | ----------------------------------------------------------------------- |
| Μέθοδος  | `DELETE`                                                                |
| URL | `https://platform.acedata.cloud/api/v1/platform-tokens/<id>`（**χωρίς κάθετο στο τέλος**） |
| Εξουσιοδότηση  | ✅ Μόνο ο δημιουργός του διακριτικού ή ο υπερδιαχειριστής μπορεί να διαγράψει                                                       |

```shell
curl -X DELETE 'https://platform.acedata.cloud/api/v1/platform-tokens/3264f1aa-cbe1-4e2c-a434-95adba4f8304' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

- Σε περίπτωση επιτυχίας επιστρέφει `HTTP 204 No Content`, χωρίς σώμα απόκρισης.
- Μετά τη διαγραφή, το διακριτικό **ακυρώνεται αμέσως** και όλες οι υπηρεσίες που το χρησιμοποιούν θα λάβουν αμέσως `401`.
- Η εκ νέου αναζήτηση αυτού του `id` θα επιστρέψει `404`.

> ⚠️ Η διαγραφή είναι μη αναστρέψιμη. Εάν υποψιάζεστε διαρροή του διακριτικού, μπορείτε **να δημιουργήσετε πρώτα ένα νέο, να αλλάξετε την πλευρά της υπηρεσίας και έπειτα να διαγράψετε το παλιό**.

## Μη υποστηριζόμενες ενέργειες

| Ενέργεια         | HTTP | Περιγραφή                                  |
| ---------- | ---- | ----------------------------------- |
| Τροποποίηση `PATCH` | 405  | Μετά τη δημιουργία ενός διακριτικού λογαριασμού, **δεν υποστηρίζεται η τροποποίηση οποιουδήποτε πεδίου**. Για χρήσεις όπως η μετονομασία, διαγράψτε το και δημιουργήστε το ξανά |
| Αντικατάσταση `PUT`   | 405  | Όπως παραπάνω                                  |

---

## Γρήγορη αναφορά κωδικών σφάλματος

| HTTP | `code`               | Συνήθης αιτία                          |
| ---- | -------------------- | ----------------------------- |
| 401  | `not_authenticated`  | Δεν περιλαμβάνεται κεφαλίδα `Authorization` ή το διακριτικό έχει διαγραφεί  |
| 403  | `permission_denied`  | Το API λίστας δεν περιλαμβάνει `?user_id=` ή γίνεται πρόσβαση στις λεπτομέρειες διακριτικού άλλου χρήστη |
| 404  | `not_found`          | Το `id` δεν υπάρχει ή έχει διαγραφεί                 |
| 405  | `method_not_allowed` | Στο API λεπτομερειών στάλθηκε `PATCH`/`PUT`         |

Ενιαία μορφή απόκρισης σφάλματος:

```json
{
  "detail": "You do not have permission to perform this action.",
  "code": "permission_denied",
  "trace_id": "0a88956213edf6e62b71695ee2df0eff"
}
```

Κατά τη διερεύνηση, δώστε το `trace_id` στην εξυπηρέτηση πελατών ή επικολλήστε το στο αίτημα υποστήριξης για γρήγορο εντοπισμό των αρχείων καταγραφής.

## Πλήρες παράδειγμα κώδικα

### Python

```python
import os
import requests

BASE = "https://platform.acedata.cloud/api/v1"
PLATFORM_TOKEN = os.environ["PLATFORM_TOKEN"]
USER_ID = "89518d07-5560-4b05-92c1-667f3ddf6a4b"

headers = {
    "accept": "application/json",
    "authorization": f"Bearer {PLATFORM_TOKEN}",
    "content-type": "application/json",
}

# 1. 创建新令牌
created = requests.post(f"{BASE}/platform-tokens/", headers=headers, json={}).json()
print("新令牌：", created["token"])
print("UserID：", created["user_id"])

# 2. 列表
listing = requests.get(
    f"{BASE}/platform-tokens/",
    headers=headers,
    params={"user_id": USER_ID, "limit": 50},
).json()
print(f"共 {listing['count']} 枚令牌")

# 3. 删除（注意末尾无斜杠）
resp = requests.delete(f"{BASE}/platform-tokens/{created['id']}", headers=headers)
assert resp.status_code == 204, resp.text
```

### Node.js

```javascript
const BASE = 'https://platform.acedata.cloud/api/v1'
const PLATFORM_TOKEN = process.env.PLATFORM_TOKEN
const USER_ID = '89518d07-5560-4b05-92c1-667f3ddf6a4b'

const headers = {
  accept: 'application/json',
  authorization: `Bearer ${PLATFORM_TOKEN}`,
  'content-type': 'application/json',
}

// 创建
const created = await fetch(`${BASE}/platform-tokens/`, {
  method: 'POST',
  headers,
  body: '{}',
}).then((r) => r.json())

// 列表
const url = new URL(`${BASE}/platform-tokens/`)
url.searchParams.set('user_id', USER_ID)
const listing = await fetch(url, { headers }).then((r) => r.json())
console.log(`共 ${listing.count} 枚令牌`)

// 删除（末尾无斜杠）
await fetch(`${BASE}/platform-tokens/${created.id}`, { method: 'DELETE', headers })
```

## Χρήση σε άλλα API της πλατφόρμας

Τοποθετήστε απευθείας το `platform-v1-...` στην κεφαλίδα `Authorization: Bearer ...` για να καλέσετε οποιοδήποτε API της πλατφόρμας που απαιτεί εξουσιοδότηση:

```shell
curl 'https://platform.acedata.cloud/api/v1/applications/?user_id=89518d07-5560-4b05-92c1-667f3ddf6a4b' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

> Είναι **εντελώς διαφορετικό** από τα 32ψήφια δεκαεξαδικά διαπιστευτήρια API που χρησιμοποιούνται από τα επιχειρησιακά API `https://api.acedata.cloud/**` (OpenAI, Midjourney, Suno, Veo κ.λπ.). Μην τα συγχέετε — αν γράψετε ένα διακριτικό λογαριασμού σε ένα επιχειρησιακό API, θα λάβετε `401`, και το αντίστροφο.
