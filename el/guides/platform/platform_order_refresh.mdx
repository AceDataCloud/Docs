title: "Ανανέωση κατάστασης παραγγελίας πλατφόρμας AceDataCloud"

Ενεργή αναζήτηση της πιο πρόσφατης κατάστασης του τρόπου πληρωμής που αντιστοιχεί στην παραγγελία και συγχρονισμός της στην πλατφόρμα. Αυτό το αίτημα ενδέχεται να προσπελάσει την υπηρεσία πληρωμών και να αλλάξει την κατάσταση της παραγγελίας· χρησιμοποιήστε το μόνο όταν η επανάκληση καθυστερεί ή απαιτείται άμεση επιβεβαίωση.

## Προετοιμασία

- Χρησιμοποιήστε το [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Λάβετε το δικό σας ID παραγγελίας από τη [λίστα παραγγελιών](https://platform.acedata.cloud/documents/platform-order-list).

```shell
export PLATFORM_TOKEN='你的账户令牌'
export ORDER_ID='你的订单 ID'
```

## Επισκόπηση διεπαφής

| Στοιχείο    | Περιεχόμενο                                                        |
| ---- | ------------------------------------------------------------------ |
| Μέθοδος   | `POST`                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/refresh/` |
| Εξουσιοδότηση   | Ιδιοκτήτης παραγγελίας ή υπερδιαχειριστής                                                        |
| Body | Συνήθως κενό· στο σενάριο επανάκλησης PayPal μπορεί να απαιτείται `payer_id` / `PayerID`                         |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/refresh/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Σε περίπτωση επιτυχίας επιστρέφεται το πλήρες ανανεωμένο αντικείμενο Order. Χρησιμοποιήστε το `state` για να κρίνετε το αποτέλεσμα και το `finished_at` ως χρόνο ολοκλήρωσης· το τρέχον μοντέλο δεν διαθέτει πεδίο `paid_at`. Οι τιμές κατάστασης περιλαμβάνουν `Pending`, `Paid`, `Finished`, `Expired`, `Failed`, `Refunded`.

Η προθεσμία πληρωμής αλλάζει μόνο παραγγελίες που εξακολουθούν να βρίσκονται σε `Pending` σε `Expired`. Οι επιστραφείσες παραγγελίες `Refunded` παραμένουν σε κατάσταση επιστροφής χρημάτων μετά από ανανέωση ή μετά τη λήψη καθυστερημένης επανάκλησης πληρωμής.

## Προτάσεις επανάληψης

- Για κανονικές πληρωμές, βασιστείτε κατά προτεραιότητα στην επανάκληση της πλατφόρμας· εκτελέστε ενεργά refresh μόνο όταν η κατάσταση δεν ενημερώνεται για μεγάλο διάστημα.
- Μην χρησιμοποιείτε σταθερή υψηλής συχνότητας δημοσκόπηση. Συνιστάται εκθετική υποχώρηση και διακοπή αφού επιβεβαιωθεί σαφής τελική κατάσταση.
- Το `401` υποδηλώνει ότι το διακριτικό δεν είναι έγκυρο· το `403` υποδηλώνει ότι δεν είστε ο ιδιοκτήτης της παραγγελίας· το `404` υποδηλώνει ότι η παραγγελία δεν υπάρχει.
- Όταν αποτυγχάνει το ερώτημα προς την υπηρεσία πληρωμών, διατηρήστε το ID παραγγελίας και το trace ID και δοκιμάστε ξανά αργότερα· μην δημιουργείτε διπλότυπες παραγγελίες ως υποκατάστατο της επιβεβαίωσης κατάστασης.
