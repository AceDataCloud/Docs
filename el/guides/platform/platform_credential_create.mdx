Δημιουργήστε διαπιστευτήρια επιχειρηματικού API για ένα Application. Η απόκριση δημιουργίας μπορεί να περιλαμβάνει Token που μπορεί να καλέσει απευθείας το `https://api.acedata.cloud/**`, ή όνομα χρήστη/κωδικό πρόσβασης για διαπιστευτήρια τύπου Proxy· πρέπει να αντιμετωπίζονται ως μυστικά.

## Προετοιμασία

1. Δημιουργήστε ένα [Account Token](https://platform.acedata.cloud/documents/platform-token).
2. Λάβετε το `application_id` που σας ανήκει από τη [λίστα Application](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='το token λογαριασμού σας'
export APPLICATION_ID='το Application ID σας'
```

## Επισκόπηση διεπαφής

| Στοιχείο    | Περιεχόμενο                                                   |
| ---- | ---------------------------------------------------- |
| Μέθοδος   | `POST`                                               |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/` |
| Αυθεντικοποίηση   | Account Token, το OAuth token απαιτεί `credentials:write`      |
| Body | JSON                                                 |

## Σώμα αιτήματος

| Πεδίο                  | Τύπος              | Υποχρεωτικό  | Περιγραφή                            |
| ------------------- | --------------- | --- | ----------------------------- |
| `application_id`    | UUID            | Ναι   | Στοχευόμενο Application                |
| `name`              | string          | Όχι   | Εμφανιζόμενο όνομα διαπιστευτηρίων                         |
| `limited_amount`    | number / null   | Όχι   | Όριο χρήσης ανά διαπιστευτήριο· το `null` σημαίνει ότι δεν ορίζεται ανεξάρτητο όριο       |
| `expired_at`        | datetime / null | Όχι   | Χρόνος λήξης ISO 8601                 |
| `allowed_api_ids`   | UUID[] / null   | Όχι   | Επιτρέπεται η κλήση μόνο αυτών των API· ένας κενός πίνακας κανονικοποιείται ως χωρίς περιορισμό       |
| `host`              | string          | Όχι   | Πληροφορίες host διαπιστευτηρίων                    |
| `for_user_id`       | string          | Όχι   | Χρησιμοποιείται όταν ο ιδιοκτήτης του Application εκδίδει εξουσιοδοτημένα διαπιστευτήρια για άλλον χρήστη |
| `tags` / `metadata` | array / object  | Όχι   | Προσαρμοσμένα επεκτάσιμα δεδομένα                       |

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/credentials/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"name\":\"production\",\"limited_amount\":50}"
```

## Περιγραφή απόκρισης

Σε περίπτωση επιτυχίας επιστρέφεται `201` και ένα αντικείμενο Credential:

- Οι υπηρεσίες τύπου API/Agent συνήθως επιστρέφουν `type=Token` και `token`;
- Οι υπηρεσίες τύπου Proxy συνήθως επιστρέφουν `type=Identity` και `username` / `password`, και ένα Proxy Application επιτρέπει μόνο ένα διαπιστευτήριο;
- Τα πεδία `id`, `user_id`, `creator_id`, `used_amount` και τα πεδία χρόνου δημιουργούνται από τον διακομιστή.

Οι τρέχουσες διεπαφές λίστας και λεπτομερειών επιστρέφουν επίσης τα διαπιστευτήρια σε απλό κείμενο, αλλά ο πελάτης δεν θα πρέπει να βασίζεται σε αυτή την ιστορική συμπεριφορά. Αποθηκεύστε τα αμέσως μετά τη δημιουργία, αποφύγετε την εγγραφή της απόκρισης στα αρχεία καταγραφής· οι μελλοντικές διεπαφές ενδέχεται να αλλάξουν ώστε να επιστρέφουν δεδομένα με απόκρυψη.

## Χειρισμός σφαλμάτων

- `400`: Λανθασμένη μορφή πεδίου, άγνωστα `allowed_api_ids`, το Proxy Application έχει ήδη διαπιστευτήριο ή άλλους περιορισμούς δημιουργίας.
- `401`: Το Account Token δεν είναι έγκυρο.
- `403/404`: Δεν έχετε δικαίωμα πρόσβασης στο στοχευόμενο Application ή το Application/εξουσιοδοτημένος χρήστης δεν υπάρχει.
