Το TypeScript είναι ένας από τους πιο προτεινόμενους τρόπους για την ενσωμάτωση του Ace Data Cloud X402. Το επίσημο SDK είναι υπεύθυνο για τις κανονικές κλήσεις API, την αναμονή εργασιών, την επεξεργασία σφαλμάτων και την αυτόματη επανάληψη. Το `@acedatacloud/x402-client` είναι υπεύθυνο για την υπογραφή του αιτήματος `PAYMENT-SIGNATURE` όταν προκύπτει `402 Payment Required`.

Διεύθυνση πηγαίου κώδικα και πακέτου:

- Αποθετήριο SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Αποθετήριο X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm SDK: [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)
- npm X402 Client: [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client)

## Εγκατάσταση Εξαρτήσεων

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client
```

Αν χρησιμοποιείτε Base ή SKALE, χρειάζεστε ικανότητα υπογραφής EVM:

```bash
npm install ethers
```

Αν χρησιμοποιείτε Solana, χρειάζεστε τον adapter πορτοφολιού Solana ή το `@solana/web3.js`:

```bash
npm install @solana/web3.js
```

Έξοδος ελέγχου εγκατάστασης και εισαγωγής καθαρού έργου npm:

```text
imports_ok true true true true true
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4
```

Επεξήγηση αποτελεσμάτων:

- Το `@acedatacloud/sdk` και το `@acedatacloud/x402-client` μπορούν να εγκατασταθούν από το npm και να εισαχθούν από το Node.js.
- Το `ethers` χρησιμοποιείται για υπογραφή δεδομένων τύπου EVM, το `@solana/web3.js` χρησιμοποιείται για κατασκευή συναλλαγών Solana.

## Παράδειγμα Base ή SKALE

Μπορείτε να χρησιμοποιήσετε απευθείας το `window.ethereum` στον περιηγητή. Στο Node.js μπορείτε να χρησιμοποιήσετε το `ethers.Wallet` για να τυλίξετε έναν provider στυλ EIP-1193.

```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});

console.log(result.choices[0].message.content);
```

Το αποτέλεσμα εκτέλεσης αυτού του παραδείγματος:

```text
payer 0xd0479FA9FD8C678303d477433d24C15e3723CC1C
elapsed_ms 6782
content ADC_TS_SDK_X402_OK
id chatcmpl-DlcVLO4PQWvmjPDQpy9yQw2QdLGAT
```

Επεξήγηση αποτελεσμάτων:

- Το πρόγραμμα πρώτα ενεργοποιεί την 402 χωρίς πιστοποίηση, στη συνέχεια ο handler υπογράφει το `PAYMENT-SIGNATURE`, και τέλος επαναλαμβάνει με το ίδιο σώμα αιτήματος.
- Το `content ADC_TS_SDK_X402_OK` είναι η σταθερή συμβολοσειρά που επιστρέφει το μοντέλο, υποδεικνύοντας ότι το αίτημα μετά την επανάληψη εισήλθε στο στοχευμένο API.
- Το `id chatcmpl-DlcVLO4PQWvmjPDQpy9yQw2QdLGAT` είναι το ID της απάντησης chat completion, που μπορεί να χρησιμοποιηθεί για αντιπαραβολή με τα αρχεία χρήσης της πλατφόρμας.
- Τα αποτελέσματα διακανονισμού στο blockchain μπορείτε να δείτε [E2E επαλήθευση και αποσφαλμάτωση](https://platform.acedata.cloud/documents/x402-e2e-troubleshooting).

Απλά αλλάξτε το `network` σε `skale` για να χρησιμοποιήσετε το SKALE. Το πλεονέκτημα του SKALE είναι το χαμηλό κόστος gas για συναλλαγές στο blockchain. Το πλεονέκτημα του Base είναι η ρευστότητα USDC και η υποστήριξη πορτοφολιών είναι πιο ώριμη, και μόνο το Base προσφέρει `upto` για μετρήσεις μετά.

Σημειώστε: Το SKALE υποστηρίζει μόνο `exact` αυτή τη στιγμή. Αν περάσετε `preferScheme: 'upto'` κάτω από `network: 'skale'`, ο handler δεν θα βρει το `upto` και θα υποχωρήσει σιωπηλά στο `exact`, χωρίς να αναφέρει σφάλμα—σενάρια όπως η ολοκλήρωση συνομιλιών που μετρούν ανά token θα διακανονιστούν με σταθερή τιμή, αντί για πραγματική χρήση. Για μετρήσεις μετά, παρακαλώ χρησιμοποιήστε το Base.

## Παράδειγμα Πορτοφολιού Περιηγητή

Όταν χρησιμοποιείτε MetaMask, Coinbase Wallet ή WalletConnect σε εφαρμογές frontend, συνήθως περνάτε απευθείας τον provider EIP-1193:

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const [address] = await window.ethereum.request({ method: 'eth_requestAccounts' });

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider: window.ethereum,
    evmAddress: address
  })
});

const image = await client.images.generate({
  provider: 'nano-banana',
  prompt: 'a yellow banana on a white background'
});
```

Ο πορτοφολιού περιηγητή θα εμφανίσει ένα παράθυρο επιβεβαίωσης υπογραφής. Ο χρήστης δεν υπογράφει οποιοδήποτε μήνυμα, αλλά την πληρωμή που επιστρέφει το API: η διεύθυνση παραλαβής, το συμβόλαιο USDC, το ποσό, η διάρκεια και το nonce περιλαμβάνονται στην υπογραφή.

## Παράδειγμα Solana

Η Solana χρησιμοποιεί το SPL USDC `TransferChecked`. Ο adapter πορτοφολιού που παρέχεται πρέπει να εκθέτει `publicKey` και `signAndSendTransaction`.

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'solana',
    solanaWallet: phantomWallet
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});
```

Η διαδρομή Solana υποστηρίζει μόνο `exact`, δεν υποστηρίζει `upto`. Αν το API επιστρέψει πολλές `accepts`, ο handler θα επιλέξει την επιλογή `network = 'solana'`.

Η διαδρομή Solana έχει επαληθευτεί σε δημόσιο API για paid retry που μπορεί να επιστρέψει HTTP 200 και `ADC_SOLANA_E2E_OK`. Δημόσιες RPC ερωτήσεις μπορεί να περιορίζονται, γι' αυτό δεν αναγράφεται το hash συναλλαγής Solana εδώ; αν χρειάζεστε συμφωνία στο blockchain, παρακαλώ χρησιμοποιήστε τη δική σας RPC Solana ή καταγράψτε την επιβεβαίωση από την κονσόλα.

## Επιλογή `exact` ή `upto`

Ο τρέχων TypeScript handler θα επιλέξει την πρώτη απαιτούμενη πληρωμή που επιστρέφει ο διακομιστής και ταιριάζει με το δίκτυο. Η API του Ace Data Cloud συνήθως τοποθετεί το `exact` του ίδιου δικτύου πριν από το `upto`, επομένως αν θέλετε σαφώς να χρησιμοποιήσετε μετρήσεις μετά, πρέπει να περάσετε `preferScheme: 'upto'`.

Παράδειγμα:

```ts
const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address,
    preferScheme: 'upto'
  })
});
```

Αν ο διακομιστής δεν επιστρέψει την απαιτούμενη πληρωμή `upto` για αυτό το δίκτυο, ο handler θα υποχωρήσει αυτόματα στην πρώτη διαθέσιμη απαιτούμενη πληρωμή για αυτό το δίκτυο, που είναι συνήθως το `exact`.

Το `upto` απαιτεί μία φορά εξουσιοδότηση Permit2. Το `upto` παρέχεται μόνο στο Base αυτή τη στιγμή, επομένως χρειάζεται να εξουσιοδοτήσετε μόνο το Base USDC μία φορά:
```bash
npx tsx scripts/approve-permit2.ts --network base
```

Η βάση `upto` έχει ολοκληρώσει την δημόσια επαλήθευση API: HTTP 402 -> HTTP 200, η μεταγενέστερη συναλλαγή settlement είναι `0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036`. Πλήρης έξοδος μπορείτε να δείτε στην περιγραφή του σχεδίου χρέωσης.

## Τι έκανε το SDK

Ο transport του `@acedatacloud/sdk` θα εκτελέσει μία φορά τον payment handler όταν λάβει 402:

```ts
type PaymentHandler = (ctx: {
  url: string;
  method: string;
  body?: unknown;
  accepts: PaymentRequirement[];
}) => Promise<{ headers: Record<string, string> }>;
```

Ο handler που επιστρέφει το `@acedatacloud/x402-client` θα:

1. Επιλέξει την απαιτούμενη πληρωμή του στόχου δικτύου από το `ctx.accepts`.
2. Κατασκευάσει την υπογραφή EVM EIP-712 ή τη συναλλαγή μεταφοράς Solana ανάλογα με το δίκτυο.
3. Σειριοποιήσει το envelope σε Base64.
4. Επιστρέψει `{ headers: { 'PAYMENT-SIGNATURE': '<base64>' } }`.
5. Το SDK θα επαναλάβει αυτόματα με το αρχικό σώμα αιτήματος.

Αυτό σημαίνει ότι ο επιχειρηματικός κώδικας χρειάζεται να γραφτεί όπως μια κανονική κλήση SDK, χωρίς να χρειάζεται να διαχειριστεί χειροκίνητα την επανάληψη 402.
