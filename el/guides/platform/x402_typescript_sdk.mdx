Το TypeScript είναι ένας από τους πλέον προτεινόμενους τρόπους για την ενσωμάτωση του Ace Data Cloud X402. Το επίσημο SDK είναι υπεύθυνο για κανονικές κλήσεις API, polling εργασιών, διαχείριση σφαλμάτων και αυτόματες επαναλήψεις· το `@acedatacloud/x402-client` είναι υπεύθυνο για την υπογραφή του request header `PAYMENT-SIGNATURE` όταν συναντά `402 Payment Required`.

Πηγαίος κώδικας και διευθύνσεις πακέτων:

- Αποθετήριο SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Αποθετήριο X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm SDK: [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)
- npm X402 Client: [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client)

## Εγκατάσταση εξαρτήσεων

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client
```

Αν χρησιμοποιείτε Base, χρειάζεστε δυνατότητα υπογραφής EVM:

```bash
npm install ethers
```

Αν χρησιμοποιείτε Solana, χρειάζεστε Solana wallet adapter ή `@solana/web3.js`:

```bash
npm install @solana/web3.js
```

Έξοδος ελέγχου εγκατάστασης και εισαγωγών για καθαρό npm project:

```text
imports_ok true true true true true
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4
```

Επεξήγηση αποτελεσμάτων:

- Τα `@acedatacloud/sdk` και `@acedatacloud/x402-client` μπορούν και τα δύο να εγκατασταθούν από npm και να εισαχθούν από το Node.js.
- Το `ethers` χρησιμοποιείται για υπογραφή EVM typed data, ενώ το `@solana/web3.js` χρησιμοποιείται για κατασκευή Solana transaction.

## Παράδειγμα Base

Στον browser μπορείτε να χρησιμοποιήσετε απευθείας το `window.ethereum`. Στο Node.js μπορείτε να τυλίξετε το `ethers.Wallet` σε έναν provider τύπου EIP-1193.

```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});

console.log(result.choices[0].message.content);
```

## Παράδειγμα browser wallet

Όταν χρησιμοποιείτε MetaMask, Coinbase Wallet ή WalletConnect σε εφαρμογή frontend, συνήθως περνάτε απευθείας τον EIP-1193 provider:

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const [address] = await window.ethereum.request({ method: 'eth_requestAccounts' });

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider: window.ethereum,
    evmAddress: address
  })
});

const image = await client.images.generate({
  provider: 'nano-banana',
  prompt: 'a yellow banana on a white background'
});
```

Το browser wallet θα εμφανίσει επιβεβαίωση υπογραφής. Αυτό που υπογράφει ο χρήστης δεν είναι ένα αυθαίρετο μήνυμα, αλλά η απαίτηση πληρωμής που επιστρέφει το API: η διεύθυνση παραλήπτη, το USDC contract, το ποσό, η περίοδος ισχύος και το nonce περιλαμβάνονται όλα στην υπογραφή.

## Παράδειγμα Solana

Το Solana χρησιμοποιεί SPL USDC `TransferChecked`. Ο παρεχόμενος wallet adapter πρέπει να εκθέτει `publicKey` και `signAndSendTransaction`.

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'solana',
    solanaWallet: phantomWallet
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});
```

Η διαδρομή Solana υποστηρίζει προς το παρόν μόνο `exact`, και δεν υποστηρίζει `upto`. Αν το API επιστρέψει πολλαπλά `accepts`, ο handler θα επιλέξει εκείνο με `network = 'solana'`.

Η διαδρομή Solana έχει ήδη επαληθευτεί στο ίδιο δημόσιο API ότι το paid retry μπορεί να επιστρέψει HTTP 200 και `ADC_SOLANA_E2E_OK`. Τα δημόσια RPC queries ενδέχεται να υπόκεινται σε rate limiting, επομένως αυτό το άρθρο δεν αναφέρει Solana tx hash· όταν χρειάζεστε συμφωνία on-chain, χρησιμοποιήστε το δικό σας Solana RPC ή επιβεβαιώστε μέσω των καταγραφών της κονσόλας.

## Επιλογή `exact` ή `upto`

Ο τρέχων TypeScript handler θα επιλέξει το πρώτο payment requirement του αντίστοιχου δικτύου που επιστρέφει ο server. Τα API του Ace Data Cloud συνήθως τοποθετούν το `exact` του ίδιου δικτύου πριν από το `upto`, επομένως αν θέλετε ρητά να χρησιμοποιήσετε μεταγενέστερη μέτρηση, πρέπει να περάσετε `preferScheme: 'upto'`.

Παράδειγμα:

```ts
const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address,
    preferScheme: 'upto'
  })
});
```

Αν ο server δεν επιστρέψει `upto` requirement για αυτό το δίκτυο, ο handler θα επιστρέψει αυτόματα στο πρώτο διαθέσιμο requirement αυτού του δικτύου, συνήθως το `exact`.

Το `upto` απαιτεί εφάπαξ εξουσιοδότηση Permit2. Το `upto` παρέχεται προς το παρόν μόνο στο Base, επομένως χρειάζεται να εκτελέσετε εξουσιοδότηση μόνο μία φορά για το Base USDC:

```bash
npx tsx scripts/approve-permit2.ts --network base
```

Το Base `upto` έχει ολοκληρώσει δημόσια επαλήθευση API: HTTP 402 -> HTTP 200, και το μεταγενέστερο settlement tx είναι `0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036`. Δείτε την περιγραφή του σχήματος χρέωσης για την πλήρη έξοδο.

## Τι κάνει το SDK

Το transport του `@acedatacloud/sdk` θα εκτελέσει μία φορά έναν payment handler όταν λάβει 402:

```ts
type PaymentHandler = (ctx: {
  url: string;
  method: string;
  body?: unknown;
  accepts: PaymentRequirement[];
}) => Promise<{ headers: Record<string, string> }>;
```

Ο handler που επιστρέφεται από το `@acedatacloud/x402-client` θα:

1. Επιλέξει το payment requirement του στόχου δικτύου από το `ctx.accepts`.
2. Κατασκευάσει υπογραφή EVM EIP-712 ή Solana transfer transaction ανάλογα με το δίκτυο.
3. Σειριοποιήσει το envelope σε Base64.
4. Επιστρέψει `{ headers: { 'PAYMENT-SIGNATURE': '<base64>' } }`.
5. Το SDK θα κάνει αυτόματα retry με το αρχικό request body.

Αυτό σημαίνει ότι ο επιχειρηματικός κώδικας χρειάζεται μόνο να γραφτεί όπως μια συνηθισμένη κλήση SDK, χωρίς να απαιτείται χειροκίνητη διαχείριση των 402 retries.
