Δημιουργήστε ή ανανεώστε μια συνεδρία πληρωμής για μια παραγγελία `Pending`. Η ενέργεια πληρωμής θα προσπελάσει το κανάλι πληρωμής και ενδέχεται να αλλάξει την κατάσταση της παραγγελίας· πριν από την κλήση, πρέπει να επιβεβαιώσετε το ID παραγγελίας, το ποσό και τη μέθοδο πληρωμής.

## Επισκόπηση διεπαφής

| Στοιχείο    | Περιεχόμενο                                                   |
| ---------- | ------------------------------------------------------------ |
| Μέθοδος    | `POST`                                                       |
| URL        | `https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/` |
| Εξουσιοδότηση | Οι φιλοξενούμενες πληρωμές ανακατεύθυνσης μπορούν να είναι ανώνυμες· άλλες μέθοδοι απαιτούν κατάσταση σύνδεσης ή Account Token |
| Body       | JSON, οι μη πληρωμένες παραγγελίες πρέπει να παρέχουν `pay_way` |

## Όρια ανώνυμης πληρωμής

Η ανώνυμη πρόσβαση χρησιμοποιείται για περιπτώσεις όπου η κατάσταση σύνδεσης χάνεται μετά το άνοιγμα ενός αντιγραμμένου συνδέσμου πληρωμής· δεν απαιτείται ούτε πρέπει να μεταφέρεται μακρόχρονο Account Token. Οι ανώνυμες κλήσεις:

- Επιτρέπουν μόνο φιλοξενούμενες μεθόδους πληρωμής ανακατεύθυνσης που έχουν ρυθμιστεί από τον διακομιστή·
- Χρησιμοποιούν σταθερά τη σελίδα πληρωμής επιτραπέζιου υπολογιστή·
- Δεν μπορούν να διεκδικήσουν παραγγελίες μηδενικής αξίας·
- Υπόκεινται σε περιορισμό ρυθμού ανά IP και ανά μεμονωμένη παραγγελία·
- Επιστρέφουν ελάχιστη προβολή παραγγελίας, χωρίς λογαριασμό, Application ή εσωτερικά metadata.

Οι πιστοποιημένοι καλούντες πρέπει να είναι ο ιδιοκτήτης της παραγγελίας ή υπερδιαχειριστής. Μέθοδοι όπως X402 και εξαργύρωση ανταμοιβών, που απαιτούν περιβάλλον χρήστη, δεν μπορούν να κληθούν ανώνυμα.

## Παράδειγμα αιτήματος

```shell
export ORDER_ID='το ID της Pending παραγγελίας σας'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"Stripe"}'
```

Μέθοδοι πληρωμής που απαιτούν πιστοποίηση:

```shell
export PLATFORM_TOKEN='το διακριτικό λογαριασμού σας'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"X402"}'
```

Το `pay_way` χρησιμοποιεί πραγματικές τιμές που υποστηρίζονται από το μοντέλο παραγγελίας, όπως `WechatPay`, `AliPay`, `Stripe`, `Card`, `Airwallex`, `X402`, `PayPal`, `AppleIAP`, `Reward`, `BankTransfer`. Δεν είναι κάθε τιμή διαθέσιμη για ανώνυμα αιτήματα ή για κάθε ιστότοπο.

## Περιγραφή απόκρισης

Η επιτυχημένη απόκριση είναι το ενημερωμένο αντικείμενο παραγγελίας, που συνήθως παρέχει το σημείο εισόδου για το επόμενο βήμα μέσω του `pay_url`· διαφορετικές μέθοδοι πληρωμής ενδέχεται επίσης να επιστρέφουν, σε ελεγχόμενα πεδία, τις πληροφορίες που απαιτούνται για να συνεχίσει ο πελάτης την πληρωμή. Η ανώνυμη απόκριση χρησιμοποιεί ελάχιστη λίστα επιτρεπόμενων πεδίων, ενώ ο πιστοποιημένος ιδιοκτήτης λαμβάνει πλήρεις λεπτομέρειες.

Μην βασίζεστε σε παλιά ονόματα πεδίων όπως `payment_url`, `qr_code_url` ή `payment_method`· το τρέχον συμβόλαιο Order χρησιμοποιεί `pay_url` και `pay_way`.

## Αγορές εντός εφαρμογής iOS

Ο συνδεδεμένος ιδιοκτήτης της παραγγελίας μπορεί να μεταβιβάσει `pay_way: "AppleIAP"`. Αυτό το αίτημα ενημερώνει την παραγγελία προς πληρωμή σύμφωνα με το `metadata.apple_price` του επιλεγμένου πακέτου και καταργεί τις εκπτώσεις, δεν πραγματοποιεί χρέωση, δεν εκδίδει πιστώσεις και δεν επιστρέφει σύνδεσμο πληρωμής. Οι παλιές παραγγελίες προς πληρωμή πρέπει πρώτα να ολοκληρώσουν αυτό το βήμα και έπειτα να ξεκινήσει η εγγενής πληρωμή Apple. Υποστηρίζεται μόνο ένα πακέτο Usage με ρυθμισμένο προϊόν και τιμή Apple· μη υποστηριζόμενα πακέτα ή μαζικές παραγγελίες επιστρέφουν `400`.

Μετά την εγγενή πληρωμή Apple, υποβάλετε το `transaction_id` μέσω του `/api/v1/orders/{id}/apple-verify/` για να ολοκληρωθεί η επαλήθευση από τον διακομιστή και η έκδοση πιστώσεων. Η ποσότητα πιστώσεων προέρχεται από το πακέτο· το ποσό χρησιμοποιεί την ανεξάρτητη προκαθορισμένη τιμή Apple σε δολάρια ΗΠΑ, χωρίς να προστίθενται εκπτώσεις μέλους ή προσαυξήσεις ιστότοπου, ενώ το ποσό χρέωσης σε τοπικό νόμισμα σε άλλες περιοχές καθορίζεται από τη σελίδα επιβεβαίωσης της Apple.

## Σφάλματα και επαναλήψεις

- Η παραγγελία δεν είναι `Pending`: επιστρέφεται `400`· μην δημιουργείτε επανειλημμένα συνεδρίες πληρωμής.
- Δεν παρέχεται `pay_way`: οι παραγγελίες μη μηδενικού ποσού επιστρέφουν `400`.
- Ανώνυμη κλήση χρησιμοποιεί μη επιτρεπόμενη μέθοδο ή παραγγελία μηδενικής αξίας: επιστρέφεται `403`, συνδεθείτε και επαναλάβετε από τον ιδιοκτήτη.
- Έχει γίνει πιστοποίηση αλλά δεν είστε ο ιδιοκτήτης της παραγγελίας: επιστρέφεται `403`.
- Αποτυχία καναλιού πληρωμής: μην υποβάλετε ξανά τυφλά· πρώτα ελέγξτε τις λεπτομέρειες της παραγγελίας και επαναλάβετε μόνο αφού επιβεβαιώσετε ότι εξακολουθεί να είναι `Pending`.
