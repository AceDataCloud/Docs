Δημιουργήστε ή ανανεώστε μια συνεδρία πληρωμής για μια παραγγελία `Pending`. Η ενέργεια πληρωμής θα προσπελάσει το κανάλι πληρωμής και ενδέχεται να αλλάξει την κατάσταση της παραγγελίας· πριν από την κλήση, πρέπει να επιβεβαιώσετε το ID παραγγελίας, το ποσό και τον τρόπο πληρωμής.

## Επισκόπηση διεπαφής

| Στοιχείο    | Περιεχόμενο                                                             |
| ---- | -------------------------------------------------------------- |
| Μέθοδος   | `POST`                                                         |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/` |
| Αυθεντικοποίηση   | Οι πληρωμές με φιλοξενούμενη ανακατεύθυνση μπορούν να είναι ανώνυμες· οι άλλοι τρόποι απαιτούν κατάσταση σύνδεσης ή Account Token                            |
| Body | JSON, οι απλήρωτες παραγγελίες πρέπει να παρέχουν `pay_way`                                       |

## Όρια ανώνυμης πληρωμής

Η ανώνυμη πρόσβαση χρησιμοποιείται για το σενάριο όπου η κατάσταση σύνδεσης χάνεται μετά το άνοιγμα ενός αντιγραμμένου συνδέσμου πληρωμής, και δεν απαιτεί ούτε πρέπει να μεταφέρει μακροχρόνιο Account Token. Οι ανώνυμες κλήσεις:

- Επιτρέπουν μόνο τρόπους πληρωμής με φιλοξενούμενη ανακατεύθυνση που έχουν διαμορφωθεί από τον διακομιστή·
- Χρησιμοποιούν σταθερά τη σελίδα πληρωμής για υπολογιστή·
- Δεν μπορούν να διεκδικήσουν παραγγελίες μηδενικής αξίας·
- Υπόκεινται σε περιορισμό ρυθμού ανά IP και ανά μεμονωμένη παραγγελία·
- Επιστρέφουν ελάχιστη προβολή παραγγελίας, χωρίς λογαριασμό, Application ή εσωτερικά metadata.

Οι αυθεντικοποιημένοι καλούντες πρέπει να είναι ο ιδιοκτήτης της παραγγελίας ή υπερδιαχειριστής. Τρόποι όπως X402 και εξαργύρωση ανταμοιβών που απαιτούν περιβάλλον χρήστη δεν μπορούν να κληθούν ανώνυμα.

## Παράδειγμα αιτήματος

```shell
export ORDER_ID='το ID της Pending παραγγελίας σας'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"Stripe"}'
```

Τρόποι πληρωμής που απαιτούν αυθεντικοποίηση:

```shell
export PLATFORM_TOKEN='το token λογαριασμού σας'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"X402"}'
```

Το `pay_way` χρησιμοποιεί πραγματικές τιμές που υποστηρίζονται από το μοντέλο παραγγελίας, όπως `WechatPay`, `AliPay`, `Stripe`, `Card`, `Airwallex`, `X402`, `PayPal`, `AppleIAP`, `Reward`, `BankTransfer`. Δεν είναι κάθε τιμή διαθέσιμη για ανώνυμα αιτήματα ή για κάθε ιστότοπο.

## Περιγραφή απόκρισης

Η επιτυχής απόκριση είναι το ενημερωμένο αντικείμενο παραγγελίας, το οποίο συνήθως παρέχει το επόμενο σημείο εισόδου μέσω του `pay_url`· διαφορετικοί τρόποι πληρωμής ενδέχεται επίσης να επιστρέφουν, σε ελεγχόμενα πεδία, τις πληροφορίες που απαιτούνται ώστε ο πελάτης να συνεχίσει την πληρωμή. Οι ανώνυμες αποκρίσεις χρησιμοποιούν ελάχιστη λίστα επιτρεπόμενων πεδίων, ενώ ο αυθεντικοποιημένος ιδιοκτήτης λαμβάνει πλήρεις λεπτομέρειες.

Μην βασίζεστε σε παλαιά ονόματα πεδίων όπως `payment_url`, `qr_code_url` ή `payment_method`· το τρέχον συμβόλαιο Order χρησιμοποιεί `pay_url` και `pay_way`.

## Τραπεζική μεταφορά

Οι συνδεδεμένοι προσωπικοί λογαριασμοί και εταιρικοί λογαριασμοί μπορούν και οι δύο να χρησιμοποιήσουν `BankTransfer`, χωρίς να απαιτείται εταιρική επαλήθευση. Τόσο οι εγχώριες μεταφορές σε RMB όσο και οι διεθνείς μεταφορές σε USD απαιτούν το ποσό της παραγγελίας να είναι τουλάχιστον 300 USD· το οφειλόμενο ποσό σε RMB καθορίζεται από το ποσό που εμφανίζεται κατά την πληρωμή.

Πριν από την πληρωμή, μπορείτε να ερωτήσετε τις διαθέσιμες διαδρομές μεταφοράς και τα όρια ποσού για την τρέχουσα παραγγελία μέσω `GET /api/v1/orders/{order_id}/payment-options/`. Η τραπεζική μεταφορά πρέπει να ξεκινήσει αφού συνδεθεί ο ιδιοκτήτης της παραγγελίας και υπόκειται στη διαμόρφωση του καναλιού είσπραξης και στο πεδίο εφαρμογής του πακέτου· δεν μπορεί να χρησιμοποιηθεί σε ανώνυμα αιτήματα.

## Αγορές εντός εφαρμογής iOS

Ο συνδεδεμένος ιδιοκτήτης της παραγγελίας μπορεί να μεταβιβάσει `pay_way: "AppleIAP"`. Αυτό το αίτημα ενημερώνει την εκκρεμή προς πληρωμή παραγγελία σύμφωνα με το `metadata.apple_price` του επιλεγμένου πακέτου και καταργεί την έκπτωση, δεν πραγματοποιεί χρέωση, δεν αποδίδει μονάδες και δεν επιστρέφει σύνδεσμο πληρωμής. Οι παλαιές εκκρεμείς προς πληρωμή παραγγελίες πρέπει πρώτα να ολοκληρώσουν αυτό το βήμα και έπειτα να ξεκινήσουν την εγγενή πληρωμή Apple. Υποστηρίζεται μόνο ένα πακέτο Usage με διαμορφωμένο προϊόν Apple και τιμή· μη υποστηριζόμενα πακέτα ή μαζικές παραγγελίες επιστρέφουν `400`.

Μετά την εγγενή πληρωμή Apple, υποβάλετε το `transaction_id` μέσω του `/api/v1/orders/{id}/apple-verify/` για να ολοκληρώσετε την επαλήθευση από τον διακομιστή και την απόδοση μονάδων. Η ποσότητα μονάδων προέρχεται από το πακέτο· το ποσό χρησιμοποιεί την ανεξάρτητη προκαθορισμένη τιμή Apple σε USD, χωρίς να προστίθενται εκπτώσεις μέλους ή προσαυξήσεις ιστότοπου, ενώ το ποσό χρέωσης σε τοπικό νόμισμα για άλλες περιοχές καθορίζεται από τη σελίδα επιβεβαίωσης της Apple.

## Σφάλματα και επανάληψη

- Η παραγγελία δεν είναι `Pending`: επιστρέφεται `400`· μην δημιουργείτε επανειλημμένα συνεδρίες πληρωμής.
- Δεν παρέχεται `pay_way`: οι παραγγελίες με ποσό διαφορετικό από μηδέν επιστρέφουν `400`.
- Η ανώνυμη κλήση χρησιμοποίησε μη επιτρεπόμενο τρόπο ή παραγγελία μηδενικής αξίας: επιστρέφεται `403`, συνδεθείτε και επαναλάβετε ως ιδιοκτήτης.
- Υπάρχει αυθεντικοποίηση αλλά δεν είστε ο ιδιοκτήτης της παραγγελίας: επιστρέφεται `403`.
- Αποτυχία καναλιού πληρωμής: μην επαναλαμβάνετε την υποβολή στα τυφλά· πρώτα ερωτήστε τις λεπτομέρειες της παραγγελίας και επαναλάβετε μόνο αφού επιβεβαιώσετε ότι παραμένει `Pending`.
