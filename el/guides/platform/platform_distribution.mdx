Το AceDataCloud προς το παρόν δεν διαθέτει συγκεντρωτικό endpoint `/api/v1/distribution/`. Τα δεδομένα ανταμοιβών παραπομπής αποτελούνται από τέσσερις ομάδες διεπαφών: κατάσταση, ιστορικό, επίπεδο και εξαργύρωση· παρακαλούμε καλέστε σύμφωνα με τον απαιτούμενο πόρο και αποφύγετε την εξάρτηση από μια ανύπαρκτη συγκεντρωτική απόκριση.

## Προετοιμασία

1. Δημιουργήστε και αποθηκεύστε ένα Account Token στην [κονσόλα Account Token](https://platform.acedata.cloud/console/platform-tokens).
2. Χρησιμοποιήστε `GET /api/v1/platform-tokens/me/` για να λάβετε το UUID του τρέχοντος λογαριασμού.

```shell
export PLATFORM_TOKEN='你的账户令牌'
export USER_ID='你的账户 UUID'
```

## Διαθέσιμες διεπαφές

| Μέθοδος     | URL                                                  | Χρήση                                   |
| ------ | ---------------------------------------------------- | ------------------------------------ |
| `GET`  | `/api/v1/distribution-statuses/?user_id=${USER_ID}`  | Συνολικό ποσό παραπομπών, ανταμοιβές και επίπεδο του τρέχοντος λογαριασμού                     |
| `POST` | `/api/v1/distribution-statuses/initialize/`          | Αρχικοποίηση για πρώτη φορά ή ανανέωση του επιπέδου του τρέχοντος λογαριασμού· θα εγγράψει δεδομένα                 |
| `GET`  | `/api/v1/distribution-histories/?user_id=${USER_ID}` | Ιστορικό ανταμοιβών παραπομπής                               |
| `GET`  | `/api/v1/distribution-levels/`                       | Κανόνες επιπέδων και ποσοστών                              |
| `GET`  | `/api/v1/distribution-redemptions/preview/`          | Προεπισκόπηση των ανταμοιβών που είναι επί του παρόντος διαθέσιμες για εξαργύρωση· προαιρετικό `amount`                |
| `GET`  | `/api/v1/distribution-redemptions/`                  | Ολοκληρωμένα αρχεία εξαργύρωσης                             |
| `POST` | `/api/v1/distribution-redemptions/redeem/`           | Επιβεβαίωση εξαργύρωσης· απαιτεί `idempotency_key`, θα δημιουργήσει μη αναστρέψιμη εξαργύρωση |

## Παραδείγματα αιτημάτων μόνο για ανάγνωση

```shell
curl --get 'https://platform.acedata.cloud/api/v1/distribution-statuses/' \
  --data-urlencode "user_id=${USER_ID}" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"

curl --get 'https://platform.acedata.cloud/api/v1/distribution-histories/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"

curl 'https://platform.acedata.cloud/api/v1/distribution-levels/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"

curl 'https://platform.acedata.cloud/api/v1/distribution-redemptions/preview/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Η μορφή απόκρισης που έχει επαληθευτεί online είναι:

- status, history, level, redemption list: `{count, items}`;
- redemption preview: ένα μεμονωμένο αντικείμενο, που περιλαμβάνει πεδία όπως `eligible`, `reason`, `reward_amount`, `credit_amount`, `credits_per_usd`, `currency`, `package`, `global_application`.

Τα στοιχεία κατάστασης και ιστορικού θα επεκτείνονται σύμφωνα με τον έλεγχο κινδύνου παραπομπών, τις αποζημιώσεις και τους κανόνες ανταμοιβής· ο πελάτης πρέπει να διαβάζει κατά περίπτωση και να μην εξαρτάται από συγκεντρωτικά πεδία όπως `referral_url`, `recent_orders`, `withdrawable_balance` που δεν επιστρέφονται από τη διεπαφή στα παλαιά έγγραφα.

> Η αρχικοποίηση και η εξαργύρωση είναι και οι δύο λειτουργίες εγγραφής. Τα σενάρια παραγωγής πρέπει πρώτα να καλούν διεπαφές μόνο για ανάγνωση για να ελέγχουν την κατάσταση και να διατηρούν ένα μοναδικό `idempotency_key` για αιτήματα εξαργύρωσης· μην επαναλαμβάνετε αυτόματα εξαργυρώσεις με άγνωστο αποτέλεσμα.

## Παραγγελίες με προσαύξηση τιμής υποσταθμού

Για παραγγελίες υποσταθμών στις οποίες εφαρμόζονται οι νέοι κανόνες, η προμήθεια παραπομπής υπολογίζεται με βάση την αρχική τιμή μετά την έκπτωση, ενώ η διαφορά προσαύξησης μετά την έκπτωση αποδίδεται εξ ολοκλήρου στον διαχειριστή του υποσταθμού κατά τη δημιουργία της παραγγελίας. Τα δύο μέρη της ανταμοιβής για τον ίδιο δικαιούχο συγχωνεύονται στην αρχική εγγραφή διανομής και το ιστορικό διανομής θα εμφανίζει τη σύνθεση· οι παραγγελίες χωρίς προσαύξηση τιμής και οι ιστορικές παραγγελίες διατηρούν τους αρχικούς κανόνες.

Για παράδειγμα, με αρχική τιμή 100 και τιμή μετά την προσαύξηση 120, εάν ο διαχειριστής του υποσταθμού είναι ταυτόχρονα ο μοναδικός παραπέμπων και το ποσοστό είναι 10%, η ανταμοιβή για αυτή την παραγγελία είναι 10 + 20 = 30. Όταν ο διαχειριστής του υποσταθμού και ο παραπέμπων δεν είναι το ίδιο πρόσωπο, οι δύο λαμβάνουν αντίστοιχα τις αντίστοιχες ανταμοιβές.

Ο διακανονισμός σε μετρητά εξακολουθεί να διεκπεραιώνεται χειροκίνητα από την πλατφόρμα. Η πλατφόρμα προβαίνει σε χειροκίνητη πληρωμή αφού αφαιρέσει το διαθέσιμο ποσό αυτής της φοράς από τον αρχικό λογαριασμό ανταμοιβών· το μέρος που έχει ήδη εξαργυρωθεί σε μονάδες δεν μπορεί να πληρωθεί ξανά σε μετρητά. Εάν μετά από επιστροφή χρημάτων εμφανιστεί έλλειμμα ανταμοιβής, αυτό θα συμψηφιστεί πρώτα με επόμενες ανταμοιβές.
