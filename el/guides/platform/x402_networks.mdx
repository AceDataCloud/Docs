Το Ace Data Cloud X402 πραγματοποιεί επί του παρόντος διακανονισμό γύρω από το USDC και υποστηρίζει δύο τύπους αλυσίδων, EVM και Solana. Ο τρόπος υπογραφής, οι διευθύνσεις περιουσιακών στοιχείων, η συμπεριφορά gas και τα κατάλληλα σενάρια διαφέρουν ανά δίκτυο, επομένως πρέπει να επιλέξετε δίκτυο πριν από την ενσωμάτωση.

## Τα αναγνωριστικά δικτύου χρησιμοποιούν CAIP-2

Το `accepts[].network` του x402 v2 είναι αναγνωριστικό CAIP-2 και όχι συντομογραφίες όπως `base`, `solana`. Κατά την αντιστοίχιση δικτύων, ο πελάτης πρέπει να συγκρίνει με βάση τη συμβολοσειρά CAIP-2:

| Δίκτυο             | Αναγνωριστικό CAIP-2                       |
| ------------------ | ------------------------------------------ |
| Base               | `eip155:8453`                              |
| Solana mainnet     | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp`  |

## Πίνακας υποστήριξης

| Δίκτυο | scheme  | Περιουσιακό στοιχείο | Τρόπος υπογραφής                       | Κατάλληλα σενάρια                         |
| ------ | ------- | -------------------- | -------------------------------------- | ------------------------------------------ |
| Base   | `exact` | Base USDC            | EIP-3009 `TransferWithAuthorization`  | Προεπιλεγμένη σύσταση, ώριμη υποστήριξη πορτοφολιών και ρευστότητας. |
| Base   | `upto`  | Base USDC + Permit2  | Permit2 `PermitWitnessTransferFrom`   | API μεταγενέστερης μέτρησης, όπως συνομιλία και μοντέλα. |
| Solana | `exact` | Solana USDC          | SPL `TransferChecked`                 | Πορτοφόλια Solana, Agent ή σενάρια εφαρμογών on-chain. |

Το `upto` παρέχεται επί του παρόντος μόνο στο Base. Τα πραγματικά διαθέσιμα στοιχεία υπερισχύουν σύμφωνα με το `accepts` που επιστρέφει το API. Μπορείτε επίσης να δείτε το Facilitator:

```bash
curl https://facilitator.acedata.cloud/supported
```

Η επιστροφή του Facilitator `/supported`:

```json
{
  "kinds": [
    { "x402Version": 2, "scheme": "exact", "network": "eip155:8453" },
    {
      "x402Version": 2,
      "scheme": "upto",
      "network": "eip155:8453",
      "extra": { "facilitatorAddress": "0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708" }
    },
    {
      "x402Version": 2,
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "extra": { "feePayer": "3SPm6qbgsDkj24MuR8Ss4sH97fziqyCiqFKDyeVU2igq" }
    }
  ]
}
```

Επεξήγηση αποτελεσμάτων:

- Τα `exact` του Base και του Solana είναι διαδρομές πληρωμής σταθερού ποσού.
- Μόνο το Base παρέχει τη διαδρομή μεταγενέστερης μέτρησης `upto`, η οποία εξαρτάται από Permit2 approve.
- Το `extra.facilitatorAddress` στην καταχώριση `upto` είναι η διεύθυνση που πρέπει να εγγραφεί στο witness κατά την υπογραφή από τον πελάτη και πρέπει να συμφωνεί με την τιμή που επιστρέφει ο διακομιστής.

## Base

Το Base χρησιμοποιεί το επίσημο συμβόλαιο USDC:

```text
0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
```

Στο σχήμα `exact`, ο πελάτης υπογράφει EIP-712 `TransferWithAuthorization`. Το περιεχόμενο υπογραφής περιλαμβάνει:

- `from`: διεύθυνση πορτοφολιού πληρωμής
- `to`: διεύθυνση είσπραξης του Ace Data Cloud
- `value`: ποσό της τρέχουσας πληρωμής
- `validAfter` / `validBefore`: χρονικό παράθυρο ισχύος υπογραφής
- `nonce`: τυχαίο nonce 32 byte

Αφού το Facilitator επαληθεύσει την υπογραφή, θα καλέσει on-chain το `transferWithAuthorization` του USDC για να ολοκληρώσει τη μεταφορά.

Το Base είναι το πιο συνιστώμενο δίκτυο για επίσημη ενσωμάτωση, ιδιαίτερα κατάλληλο για μεταγενέστερη μέτρηση `upto`, επειδή τα οικοσυστήματα Permit2, USDC και πορτοφολιών είναι πιο ώριμα.

Παράδειγμα αποτελέσματος επαλήθευσης Base `exact`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
content ADC_BASE_E2E_OK
tx 0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
block 46726299
explorer https://basescan.org/tx/0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
transfer value 95215 atomic USDC
```

Επεξήγηση αποτελεσμάτων:

- Το API paid retry επιστρέφει το περιεχόμενο μοντέλου `ADC_BASE_E2E_OK`.
- Η on-chain συναλλαγή είναι διαθέσιμη στο BaseScan και ο αριθμός block είναι `46726299`.
- Τα `95215` atomic USDC αντιστοιχούν σε `0.095215` USDC και είναι το πραγματικό ποσό διακανονισμού αυτής της κλήσης API.

Αποτέλεσμα εκτέλεσης προγράμματος για πληρωμή παραγγελίας Base `exact`:

```text
order 78481793-304e-47f7-bc0c-8231aec9cc1e
state Finished
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer value 1200000 atomic USDC
```

Επεξήγηση αποτελεσμάτων:

- Η τελική κατάσταση της παραγγελίας της πλατφόρμας είναι `Finished`.
- Το `pay_id` της παραγγελίας εγγράφεται στο ίδιο hash συναλλαγής Base.
- Τα `1200000` atomic USDC αντιστοιχούν σε `1.2` USDC και είναι το ιστορικό πραγματικά πληρωμένο ποσό αυτής της παραγγελίας 10 Credits υπό την παλιά πολιτική· οι νέες παραγγελίες δεν απολαμβάνουν πλέον επιπλέον έκπτωση για τη μέθοδο πληρωμής X402 και το συγκεκριμένο ποσό υπογραφής υπερισχύει σύμφωνα με την τρέχουσα απόκριση 402.

## Solana

Το Solana χρησιμοποιεί SPL USDC `TransferChecked`. Ο πελάτης θα κατασκευάσει μια συναλλαγή μεταφοράς, θα την υπογράψει και θα την υποβάλει, και έπειτα θα τοποθετήσει την υπογραφή συναλλαγής ή τη σειριοποιημένη συναλλαγή στο envelope `PAYMENT-SIGNATURE`.

Χαρακτηριστικά του Solana:

- Χρήση Solana wallet adapter ή base58 secret key·
- Το περιουσιακό στοιχείο είναι Solana USDC mint·
- Προς το παρόν υποστηρίζεται μόνο το `exact`·
- Το Facilitator θα ελέγξει το mint, το destination, το authority και το amount της transfer instruction.

Αν χρησιμοποιείται η λειτουργία wallet fee payer, το πορτοφόλι θα υποβάλει απευθείας τη συναλλαγή και το Facilitator θα είναι υπεύθυνο για την επιβεβαίωση της συναλλαγής και την επιστροφή του αποτελέσματος settlement.

Παράδειγμα αποτελέσματος επαλήθευσης Solana `exact`:

```text
payer AY2RmGm2zPxB1uKvvF4dKyYdr2VySyL3wcD1MKJZoLRd
HTTP 402 -> HTTP 200
content ADC_SOLANA_E2E_OK
chain signature not confirmed in this run
```

Επεξήγηση αποτελεσμάτων:

- Το paid retry έχει ήδη επιστρέψει HTTP 200 και το μοντέλο εξήγαγε `ADC_SOLANA_E2E_OK`.
- Κατά την αναζήτηση του on-chain signature μέσω δημόσιου RPC μπορεί να προκύψει περιορισμός ρυθμού.
- Επειδή τα ερωτήματα δημόσιου RPC μπορεί να περιοριστούν, δεν αναγράφεται εδώ Solana explorer. Όταν απαιτείται αυστηρή συμφωνία, χρησιμοποιήστε δικό σας Solana RPC ή τα αρχεία settlement της πλατφόρμας για να επιβεβαιώσετε το signature συναλλαγής.

## Πώς να επιλέξετε

| Τι θέλετε να κάνετε                  | Προτεινόμενο δίκτυο |
| ------------------------------------ | ------------------- |
| Γρήγορη ολοκλήρωση της ελάχιστης ροής | Base `exact`        |
| Για συνηθισμένους χρήστες Web3       | Base                |
| Μεταγενέστερη μέτρηση για συμπληρώσεις συνομιλίας κ.λπ. | Base `upto` |
| Εφαρμογές οικοσυστήματος Solana      | Solana `exact`      |

Ανεξάρτητα από την αλυσίδα που θα επιλέξετε, μην κάνετε hardcode τις τιμές στον πελάτη. Η τιμή καθορίζεται από το `accepts[].maxAmountRequired` που επιστρέφει ο διακομιστής.

## Προσθήκη νέου δικτύου EVM
Η υποστήριξη κώδικα για πληρωμές σταθερού ποσού με εγγενές USDC στα παρακάτω δίκτυα έχει παρασχεθεί και ανοίγει ανά δίκτυο.
Η διαθεσιμότητα εξαρτάται από το `accepts` που επιστρέφει η παραγγελία ή το API· δεν σημαίνει ότι όλα τα δίκτυα έχουν ενεργοποιηθεί στην παραγωγή.

| Δίκτυο       | Ψευδώνυμο   | CAIP-2         | Εγγενές USDC                                |
| ------------ | ---------- | -------------- | -------------------------------------------- |
| Arbitrum One | `arbitrum` | `eip155:42161` | `0xaf88d065e77c8cC2239327C5EDb3A432268e5831` |

Αυτά τα δίκτυα υποστηρίζουν μόνο `exact`, με ακρίβεια νομίσματος 6. Μη χρησιμοποιείτε bridged USDC με το ίδιο όνομα.
Όταν χρησιμοποιείτε τον επίσημο TypeScript/Python X402 Client, μπορείτε να περάσετε το σύντομο όνομα ή το αναγνωριστικό CAIP-2 στον πίνακα.
Ο client κατασκευάζει την υπογραφή χρησιμοποιώντας το ID της αλυσίδας προορισμού· το πορτοφόλι πρέπει να υποστηρίζει το δίκτυο προορισμού.

Ο επίσημος πίνακας υποστήριξης του πορτοφολιού επέκτασης Phantom περιλαμβάνει τα Arbitrum και Polygon· τα Optimism, Avalanche
δεν περιλαμβάνονται επί του παρόντος σε αυτόν τον πίνακα· μπορείτε να χρησιμοποιήσετε Rabby ή MetaMask που υποστηρίζει την αλυσίδα προορισμού. Οι διευθύνσεις EVM μπορούν να είναι ίδιες σε διαφορετικές αλυσίδες,
αλλά τα υπόλοιπα είναι ανεξάρτητα μεταξύ τους, και οι διευθύνσεις Solana δεν ισχύουν για EVM USDC.
Δείτε τον [πίνακα υποστήριξης πορτοφολιού Phantom](https://docs.phantom.com/wallet-sdks-overview#chain-support).

### Είσοδος σταδιακής διάθεσης νέου δικτύου

Η είσοδος νέας αλυσίδας είναι κρυφή από προεπιλογή. Κατά την πρόσβαση στην κονσόλα ή το Studio, μπορείτε να χρησιμοποιήσετε `?features=x402-arbitrum`
για να ενεργοποιήσετε την αντίστοιχη αλυσίδα, με πολλαπλά flags διαχωρισμένα με κόμματα. Για να απενεργοποιήσετε μία αλυσίδα, χρησιμοποιήστε `?features=-x402-arbitrum`,
και για να καθαρίσετε την τοπική παράκαμψη χρησιμοποιήστε `?features=none`. Οι διακόπτες αποθηκεύονται ξεχωριστά για κάθε domain.
Η προσφορά παραγγελίας και η επανάληψη πληρωμής χρησιμοποιούν τον ίδιο διακόπτη, ενώ ο διακομιστής θα εκτελέσει ανεξάρτητο έλεγχο· τα υπάρχοντα αρχεία πληρωμών εξακολουθούν να είναι ορατά.
Η ενεργοποίηση μόνο του flag της σελίδας δεν θα ενεργοποιήσει αλυσίδες που δεν έχουν ακόμη ρυθμιστεί, και τα συγκεκριμένα πληρωτέα δίκτυα εξακολουθούν να εξαρτώνται από το πραγματικού χρόνου `accepts`.
