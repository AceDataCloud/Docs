Επιστρέφει σελιδοποιημένα τα Application που ο λογαριασμός κατέχει ή έχει εξουσιοδοτηθεί να χρησιμοποιεί, συμπεριλαμβανομένων του υπολοίπου, της κατάστασης, της σύνοψης υπηρεσίας και των συσχετισμένων διαπιστευτηρίων. Κατάλληλο για μαζική παρακολούθηση υπολοίπου, εύρεση Application ID και είσοδο στη διαχείριση διαπιστευτηρίων.

## Προετοιμασία

1. Συνδεθείτε στην [πλατφόρμα AceDataCloud](https://platform.acedata.cloud).
2. Δημιουργήστε ένα διακριτικό λογαριασμού στην [κονσόλα Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. Οι απλοί χρήστες χρησιμοποιούν `user_id=me`· μπορείτε επίσης να λάβετε το δικό σας UUID από το `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='το διακριτικό λογαριασμού σας'
```

## Επισκόπηση διεπαφής

| Στοιχείο   | Περιεχόμενο                                                  |
| --- | ----------------------------------------------------- |
| Μέθοδος  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Πιστοποίηση  | Account Token, το OAuth token απαιτεί `applications:read`       |
| Σελιδοποίηση  | `count` + `items`                                     |

Οι απλοί χρήστες πρέπει να περάσουν `user_id=me`. Αν δεν περαστεί, το ερώτημα δεν περιορίζεται πρώτα ανά λογαριασμό και η σελιδοποίηση μπορεί να επιστρέψει `403` όταν συναντήσει αντικείμενα χωρίς δικαίωμα πρόσβασης· οι διαχειριστές μπορούν να δουν ολόκληρο τον πίνακα αν δεν το περάσουν.

## Παράμετροι ερωτήματος

| Παράμετρος            | Τύπος          | Υποχρεωτικό     | Περιγραφή                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Υποχρεωτικό για απλούς χρήστες | Υποκείμενο ερωτήματος· υποστηρίζει επαναλαμβανόμενες παραμέτρους                                         |
| `affiliation` | string      | Όχι      | `owner` (προεπιλογή) ή `granted`· και τα δύο μπορούν να περαστούν επανειλημμένα για ένωση, ισχύει μόνο όταν υπάρχει `user_id` |
| `service_id`  | UUID        | Όχι      | Φιλτράρισμα ανά υπηρεσία· υποστηρίζει επαναλαμβανόμενες παραμέτρους                                        |
| `scope`       | string      | Όχι      | `Individual` ή `Global`· υποστηρίζει επαναλαμβανόμενες παραμέτρους                      |
| `type`        | string      | Όχι      | `Usage` ή `Period`· υποστηρίζει επαναλαμβανόμενες παραμέτρους                           |
| `limit`       | integer     | Όχι      | Αριθμός στοιχείων ανά σελίδα, μέγιστο 100                                         |
| `offset`      | integer     | Όχι      | Μετατόπιση σελιδοποίησης                                               |
| `ordering`    | string      | Όχι      | Υποστηρίζει μόνο `created_at` ή `-created_at`                    |

Τα `paid`, `disabled`, `expired`, `low_balance` και `tag` δεν είναι προς το παρόν παράμετροι φιλτραρίσματος από τον διακομιστή. Οι ειδοποιήσεις υπολοίπου θα πρέπει, μετά την ανάκτηση της λίστας, να αξιολογούνται στον πελάτη σύμφωνα με τα `remaining_amount`, `service.unit` και τα επιχειρηματικά όρια κάθε Application.

## Παράδειγμα αιτήματος

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Δείτε ταυτόχρονα τα Application που κατέχετε και αυτά που άλλοι έχουν εξουσιοδοτήσει για εσάς:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Περιγραφή απόκρισης

Η απόκριση είναι `{count, items}`. Κάθε στοιχείο περιλαμβάνει τα πεδία του μοντέλου Application και επιπλέον:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`·
- `credentials`: σύνοψη των διαπιστευτηρίων που ο τρέχων καλών έχει δικαίωμα να δει·
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`, `allow_overdraft`·
- η πραγματική τιμή του `scope` είναι `Individual` ή `Global`·
- η πραγματική τιμή του `type` είναι `Usage` ή `Period`.

Το `allow_overdraft` είναι ένα μόνο για ανάγνωση λογικό πεδίο που ελέγχεται από διαχειριστές, με προεπιλεγμένη τιμή `false`. Για εφαρμογές χρέωσης βάσει χρήσης (`Usage`) με ενεργοποιημένη υπερανάληψη, το ανεπαρκές υπόλοιπο δεν θα εμποδίσει την κλήση και η χρέωση εξακολουθεί να γίνεται σύμφωνα με την πραγματική χρήση· το αρνητικό υπόλοιπο υποδηλώνει πίστωση προς εκκαθάριση. Η απενεργοποίηση, η λήξη και τα όρια των API διαπιστευτηρίων εξακολουθούν να ισχύουν.

Το `remaining_amount` μπορεί να είναι κενό· ο πελάτης πρέπει πρώτα να ελέγξει για κενή τιμή και έπειτα να κάνει αριθμητική σύγκριση. Η μονάδα του ορίου καθορίζεται από το `service.unit`.
