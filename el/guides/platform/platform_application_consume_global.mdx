Ρυθμίστε το `allow_consume_global`. Μετά την ενεργοποίηση, τα επιλέξιμα Application χρέωσης βάσει χρήσης μπορούν να συνεχίσουν να χρησιμοποιούν το καθολικό υπόλοιπο του λογαριασμού όταν το δικό τους υπόλοιπο είναι ανεπαρκές.

## Προετοιμασία

- Δημιουργήστε και αποθηκεύστε με ασφάλεια το [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Λάβετε το `application_id` που σας ανήκει από τη [λίστα αιτήσεων υπηρεσίας](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='το Account Token σας'
export APPLICATION_ID='το Application ID σας'
```

## Επισκόπηση διεπαφής

| Στοιχείο | Περιεχόμενο                                                                                       |
| ---- | -------------------------------------------------------------------------------------------------- |
| Μέθοδος   | `POST`                                                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/applications/{application_id}/update-allow-consume-global/` |
| Πιστοποίηση   | Account Token                                                                                      |
| Body | JSON                                                                                               |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/applications/${APPLICATION_ID}/update-allow-consume-global/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"allow_consume_global": true}'
```

Σε περίπτωση επιτυχίας επιστρέφεται το ενημερωμένο αντικείμενο Application. Χρησιμοποιήστε το `allow_consume_global` στην απόκριση ως αναφορά, αντί να υποθέσετε ότι η τιμή του αιτήματος αποθηκεύτηκε οπωσδήποτε.

> Application τύπου `Period` δεν επιτρέπεται να καταναλώνει καθολικό υπόλοιπο. Ακόμη και αν ζητηθεί `true`, ο διακομιστής θα διατηρήσει αυτό το πεδίο ως `false`.

## Χειρισμός σφαλμάτων

- `401`: Το Account Token είναι μη έγκυρο ή λείπει.
- `403`: Ο τρέχων λογαριασμός δεν είναι ο ιδιοκτήτης αυτού του Application.
- `404`: Το Application ID δεν υπάρχει.

Η είσοδος επαναφόρτισης για το καθολικό υπόλοιπο και τα διαθέσιμα πακέτα βασίζονται στην κονσόλα της πλατφόρμας και στα πραγματικά πακέτα που επιστρέφονται από τη [δημιουργία παραγγελίας](https://platform.acedata.cloud/documents/platform-order-create)· μην υποθέτετε ότι υπάρχει πακέτο τύπου `Wallet`.

## Εφαρμογές με εγκεκριμένη υπερανάληψη

Όταν το πεδίο μόνο για ανάγνωση `allow_overdraft=true` ενός Application χρέωσης βάσει χρήσης είναι ενεργό, το Application μπορεί να συνεχίσει να χρεώνει από το δικό του υπόλοιπο, ακόμη και αν αυτό γίνει αρνητικό, και δεν θα μεταβεί στον καθολικό λογαριασμό λόγω ανεπαρκούς υπολοίπου. Τα Application χωρίς ενεργοποιημένη υπερανάληψη εξακολουθούν να ακολουθούν το `allow_consume_global`· μετά τη μετάβαση, το αν επιτρέπεται υπερανάληψη βασίζεται στη ρύθμιση του καθολικού Application από το οποίο πραγματοποιείται η πραγματική χρέωση.

## Όριο ταυτόχρονων αιτημάτων για δοκιμαστικούς λογαριασμούς

Το σύστημα χρησιμοποιεί τη σημαία χρήστη μόνο για ανάγνωση `has_recharged` για να καταγράφει αν έχει ολοκληρωθεί ποτέ επιτυχώς πληρωμένη επαναφόρτιση ή αν έχουν προστεθεί χειροκίνητα πιστώσεις από διαχειριστή· η σημαία ενημερώνεται μετά την επιτυχή ολοκλήρωση της ενέργειας και οι ιστορικοί χρήστες θα ενημερώνονται ενιαία βάσει παραγγελιών ή σαφών εγγραφών προσθήκης πιστώσεων. Για λογαριασμούς που δεν έχουν πραγματοποιήσει ούτε πληρωμένη επαναφόρτιση ούτε χειροκίνητη προσθήκη πιστώσεων από διαχειριστή, επιτρέπεται να εκτελείται ταυτόχρονα μόνο ένα χρεώσιμο αίτημα σε ολόκληρο τον λογαριασμό· διαφορετικά API Key και διαφορετικές υπηρεσίες μοιράζονται αυτή τη μία θέση. Οι ανταμοιβές, οι κάρτες εξαργύρωσης και τα μεταφερόμενα υπόλοιπα δεν θεωρούνται πληρωμένες επαναφορτίσεις. Λογαριασμοί που έχουν ήδη ολοκληρώσει πληρωμένη επαναφόρτιση ή έχουν λάβει χειροκίνητη προσθήκη πιστώσεων από διαχειριστή δεν υπόκεινται σε αυτό το όριο δοκιμαστικής ταυτόχρονης εκτέλεσης και εξακολουθούν να ακολουθούν τους αρχικούς ελέγχους υπολοίπου και ορίων διαπιστευτηρίων.

Όταν υπάρχει ήδη αίτημα σε εκτέλεση, ένα νέο αίτημα επιστρέφει `429 too_many_requests`. Οι δωρεάν διεπαφές περιοδικού ελέγχου, όπως η αναζήτηση εργασιών, μπορούν να καλούνται κανονικά. Η πιστοποίηση σύνδεσης του Realtime ακολουθεί την υπάρχουσα διαδικασία χρέωσης ανά γύρο και δεν καταλαμβάνει αυτή τη θέση κανονικού αιτήματος.

Όταν μια ασύγχρονη διεπαφή επιστρέφει «έγινε αποδοχή», η εργασία εξακολουθεί να εκτελείται και πρέπει να περιμένετε το τελικό αποτέλεσμα πριν υποβάλετε το επόμενο αίτημα δημιουργίας. Η αποσύνδεση δικτύου ή το timeout του proxy δεν σημαίνει ότι η εργασία έχει σταματήσει· αν η εργασία δεν έχει τελική κατάσταση για μεγάλο χρονικό διάστημα, παρέχετε το `trace_id` και επικοινωνήστε με την υποστήριξη για έλεγχο.

Αυτός ο περιορισμός δεν αλλάζει τις διεπαφές που είναι διαθέσιμες για δοκιμή, ούτε αλλάζει τους αρχικούς κανόνες χρέωσης. Οι χρεώσεις εξακολουθούν να εκκαθαρίζονται μετά το τέλος του αιτήματος βάσει της πραγματικής χρήσης.
