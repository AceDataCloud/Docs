Αυτό το σεμινάριο χρησιμοποιεί ένα ελάχιστο αίτημα API για να εξηγήσει την πλήρη ροή του Ace Data Cloud X402. Ο στόχος δεν είναι να γραφτεί πρώτα σύνθετος κώδικας, αλλά να κατανοηθεί πρώτα: γιατί το πρώτο αίτημα επιστρέφει 402, τι περιέχει το `accepts` και πώς το `PAYMENT-SIGNATURE` μετατρέπει το ίδιο αίτημα API σε πληρωμένο αίτημα.

## Προετοιμασία

Χρειάζεται να προετοιμάσετε:

| Στοιχείο   | Περιγραφή                                                   |
| ---- | ---------------------------------------------------- |
| Πορτοφόλι   | Ένα πορτοφόλι που υποστηρίζει το δίκτυο-στόχο. Το Base χρησιμοποιεί πορτοφόλι EVM, το Solana χρησιμοποιεί πορτοφόλι Solana.      |
| USDC | Πρέπει να υπάρχει αρκετό USDC στο πορτοφόλι. Το πραγματικό ποσό βασίζεται στο `maxAmountRequired` της απόκρισης 402. |
| Περιβάλλον ανάπτυξης | Για TypeScript προτείνεται Node.js 18+· για Python προτείνεται Python 3.10+.    |
| SDK  | Προτείνεται η χρήση του επίσημου SDK, δεν συνιστάται η χειροκίνητη υλοποίηση των λεπτομερειών υπογραφής.                                |

Κατά την κλήση του Ace Data Cloud API μέσω X402 δεν απαιτείται API Token. Το πρώτο αίτημα του SDK δεν περιλαμβάνει `Authorization`, το Gateway επιστρέφει `402 Payment Required` και απαιτήσεις πληρωμής· το SDK επαναλαμβάνει αυτόματα το αίτημα μετά την υπογραφή.

## Εγκατάσταση SDK

Πηγαίος κώδικας και διευθύνσεις πακέτων:

- Αποθετήριο SDK：[https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Αποθετήριο X402 Client：[https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm：`@acedatacloud/sdk`、`@acedatacloud/x402-client`
- PyPI：`acedatacloud`、`acedatacloud-x402`

TypeScript：

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client ethers
```

Python：

```bash
pip install acedatacloud acedatacloud-x402
```

Αν θέλετε να χρησιμοποιήσετε Solana, χρειάζεται επίσης να εγκαταστήσετε τις αντίστοιχες εξαρτήσεις:

```bash
npm install @solana/web3.js
```

Η εξάρτηση Solana signer της έκδοσης Python περιλαμβάνεται ήδη στο `acedatacloud-x402`.

Η έξοδος ελέγχου εγκατάστασης και εισαγωγής σε καθαρό προσωρινό περιβάλλον:


Επεξήγηση αποτελεσμάτων:

- Τα πακέτα npm και PyPI είναι και τα δύο πραγματικά δημοσιευμένα πακέτα, όχι ονόματα-πλαίσια τεκμηρίωσης.
- Το `acedatacloud-x402[cli]` εγκαθιστά το CLI και η υποεντολή `approve-permit2` μπορεί να χρησιμοποιηθεί για εξουσιοδότηση Permit2 σε σενάρια `upto`.

## Το πρώτο αίτημα θα επιστρέψει 402

Μπορείτε πρώτα να χρησιμοποιήσετε `curl` για να δείτε τι επιστρέφει ένα μη πληρωμένο αίτημα. Το παρακάτω παράδειγμα δεν θα επιφέρει χρέωση, επειδή δεν μεταφέρει `PAYMENT-SIGNATURE`:

```bash
curl -sS -X POST https://x402.acedata.cloud/openai/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "hi"}],
    "max_tokens": 1
  }'
```

Το σώμα απόκρισης θα περιλαμβάνει τον πίνακα `accepts`, με συνηθισμένη δομή ως εξής:

```json
{
  "x402Version": 2,
  "resource": {
    "url": "/openai/chat/completions",
    "description": "AceDataCloud API call",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "maxAmountRequired": "95215",
      "amount": "95215",
      "maxTimeoutSeconds": 3600,
      "resource": "/openai/chat/completions",
      "description": "...",
      "payTo": "0x...",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913"
      }
    }
  ],
  "error": "PAYMENT-SIGNATURE header is required"
}
```

Το ίδιο περιεχόμενο πρόκλησης τοποθετείται επίσης σε μορφή base64 στην κεφαλίδα απόκρισης `PAYMENT-REQUIRED`, ώστε ο πελάτης να μπορεί να διαβάσει τις απαιτήσεις πληρωμής χωρίς να αναλύσει το body.

Η σύνοψη εξόδου προγράμματος για μη πληρωμένο αίτημα του production API είναι η εξής:

```text
status=402
x402Version 2
accepts [
  ('eip155:8453', 'exact', '95215'),
  ('eip155:8453', 'upto', '95215'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '95215'),
]
```

Επεξήγηση αποτελεσμάτων:

- Το πρώτο αίτημα δεν μεταφέρει `Authorization` ή `PAYMENT-SIGNATURE`, επομένως επιστρέφει HTTP 402 και δεν επιφέρει χρέωση.
- Το `accepts` είναι η μοναδική αξιόπιστη βάση υπογραφής για αυτό το αίτημα και περιλαμβάνει προαιρετικά δίκτυα, scheme, ανώτατο όριο ποσού, διεύθυνση παραλήπτη και διεύθυνση asset.
- Το `network` είναι αναγνωριστικό CAIP-2 και ο πελάτης πρέπει να αντιστοιχίσει βάσει της συμβολοσειράς CAIP-2 όταν επιλέγει δίκτυο.
- Το ανώτατο ποσό για αυτό το ελάχιστο αίτημα συνομιλίας `gpt-4o-mini` είναι `95215` atomic USDC, δηλαδή `0.095215` USDC.
- Κάθε αίτημα πρέπει να διαβάζει την απόκριση 402 εκείνης της φοράς· μην ενσωματώνετε σκληρά τα ποσά του παραδείγματος στον επιχειρησιακό κώδικα.

Σημασία πεδίων:

| Πεδίο                  | Περιγραφή                                                             |
| ------------------- | -------------------------------------------------------------- |
| `scheme`            | Σχήμα πληρωμής. Το `exact` υποδηλώνει σταθερό ποσό, ενώ το `upto` υποδηλώνει ανώτατο όριο εξουσιοδότησης και διακανονισμό βάσει της πραγματικής χρήσης.                     |
| `network`           | Αναγνωριστικό CAIP-2 του δικτύου πληρωμής, για παράδειγμα `eip155:8453`、`solana:5eykt4...`。           |
| `maxAmountRequired` | Μέγιστο ποσό πληρωμής, σε USDC atomic units· το `95215` υποδηλώνει `0.095215` USDC。       |
| `amount`            | Το ποσό προς διακανονισμό αυτή τη φορά· το `exact` είναι ίδιο με το `maxAmountRequired`, ενώ το `upto` ξαναγράφεται στο στάδιο διακανονισμού βάσει της πραγματικής χρήσης. |
| `payTo`             | Διεύθυνση παραλήπτη.                                                          |
| `asset`             | Διεύθυνση συμβολαίου USDC ή διεύθυνση mint Solana.                                     |
| `extra`             | Εκτεταμένες πληροφορίες που απαιτούνται για την υπογραφή, όπως chain ID, EIP-712 domain και διεύθυνση Permit2.                      |

## Ολοκλήρωση επανάληψης πληρωμής με SDK

Ακολουθεί ένα ελάχιστο παράδειγμα TypeScript. Καθορίζει `network: 'base'`, και ο handler επιλέγει την payment requirement του Base από την απόκριση 402 αυτής της φοράς· το πραγματικό ποσό και η διεύθυνση παραλήπτη εξακολουθούν να βασίζονται στο `accepts`:
```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const response = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Reply with exactly: hello' }],
  max_tokens: 8
});

console.log(response.choices[0].message.content);
```

Πίσω από αυτόν τον κώδικα συμβαίνουν τέσσερα βήματα:

1. Το SDK στέλνει ένα συνηθισμένο αίτημα API, χωρίς `Authorization`.
2. Το Gateway επιστρέφει `402 Payment Required` και `accepts`.
3. Το `createX402PaymentHandler` επιλέγει το payment requirement με `network = 'base'` και υπογράφει το `PAYMENT-SIGNATURE`.
4. Το SDK επαναλαμβάνει την προσπάθεια με το ίδιο σώμα αιτήματος, και το Gateway καλεί το Facilitator για επαλήθευση και εκκαθάριση πριν επιτρέψει την πρόσβαση στο API προορισμού.

## Προβολή δυνατοτήτων που υποστηρίζει το Facilitator

Το X402 API δεν εξαρτάται από κατάλογο πόρων. Ο πελάτης καλεί απευθείας το γνωστό API και χρησιμοποιεί τα
`402 Payment Required` και `accepts` που επιστρέφονται σε πραγματικό χρόνο από αυτό το αίτημα ως τη μοναδική βάση για την τιμή και την υπογραφή.

Η δήλωση δυνατοτήτων του Facilitator βρίσκεται στη διεύθυνση:

```bash
curl https://facilitator.acedata.cloud/.well-known/x402
```

Περιγράφει μόνο τα `/supported`, `/verify`, `/settle` και τα επί του παρόντος ενεργοποιημένα δίκτυα πληρωμών, χωρίς να παραθέτει πόρους API.

Η διεύθυνση του παραγωγικού Facilitator του Ace Data Cloud είναι:

```text
https://facilitator.acedata.cloud
```

Μπορείτε να δείτε ποια δίκτυα και scheme υποστηρίζει:

```bash
curl https://facilitator.acedata.cloud/supported
```

Το `kinds` που επιστρέφεται παραθέτει τα δίκτυα και τα scheme που υποστηρίζει το Facilitator. Κατά τις πραγματικές κλήσεις, εξακολουθεί να ισχύει το `accepts` που επιστρέφεται από το API.

Έξοδος του Facilitator `/supported`:

```text
kinds [
  ('eip155:8453', 'exact'),
  ('eip155:8453', 'upto', {'facilitatorAddress': '0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708'}),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact')
]
```

Τα αποτελέσματα υποδεικνύουν:

- Το `/supported` υποδεικνύει ότι το Facilitator έχει δυνατότητες επαλήθευσης και εκκαθάρισης για αυτά τα δίκτυα και scheme.
- Τόσο το Base όσο και το Solana υποστηρίζουν `exact`· το `upto` παρέχεται επί του παρόντος μόνο στο Base.
- Το αν ένα συγκεκριμένο API επιτρέπει ένα δίκτυο εξακολουθεί να καθορίζεται από το 402 `accepts` αυτού του API.
