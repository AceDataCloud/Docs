Αυτό το σεμινάριο περιγράφει τη διαδικασία του Ace Data Cloud X402 με ένα ελάχιστο API αίτημα. Ο στόχος δεν είναι να γράψουμε περίπλοκο κώδικα, αλλά να κατανοήσουμε: γιατί η πρώτη αίτηση επιστρέφει 402, τι περιέχει το `accepts`, και πώς το `PAYMENT-SIGNATURE` μετατρέπει την ίδια αίτηση API σε αίτηση που έχει πληρωθεί.

## Προετοιμασία

Πρέπει να προετοιμάσετε:

| Στοιχείο | Περιγραφή                                                      |
| ---- | ------------------------------------------------------- |
| Πορτοφόλι | Ένα πορτοφόλι που υποστηρίζει το επιθυμητό δίκτυο. Το Base / SKALE χρησιμοποιεί EVM πορτοφόλι, το Solana χρησιμοποιεί Solana πορτοφόλι. |
| USDC | Το πορτοφόλι πρέπει να έχει αρκετό USDC. Το πραγματικό ποσό καθορίζεται από το `maxAmountRequired` στην απάντηση 402.    |
| Αναπτυξιακό περιβάλλον | TypeScript προτείνεται Node.js 18+; Python προτείνεται Python 3.10+.       |
| SDK  | Συνιστάται η χρήση του επίσημου SDK, δεν προτείνεται η χειροκίνητη υπογραφή λεπτομερειών.                                   |

Η κλήση X402 στο Ace Data Cloud API δεν απαιτεί API Token. Η πρώτη αίτηση του SDK δεν περιέχει `Authorization`, η Πύλη θα επιστρέψει `402 Payment Required` και τις απαιτήσεις πληρωμής; το SDK θα επαναλάβει αυτόματα μετά την υπογραφή.

## Εγκατάσταση SDK

Διεύθυνση πηγαίου κώδικα και πακέτου:

- Αποθετήριο SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Αποθετήριο X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm: `@acedatacloud/sdk`, `@acedatacloud/x402-client`
- PyPI: `acedatacloud`, `acedatacloud-x402`

TypeScript:

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client ethers
```

Python:

```bash
pip install acedatacloud acedatacloud-x402
```

Αν θέλετε να χρησιμοποιήσετε το Solana, θα χρειαστεί να εγκαταστήσετε τις αντίστοιχες εξαρτήσεις:

```bash
npm install @solana/web3.js
```

Η έκδοση Python του Solana signer περιλαμβάνεται ήδη στο `acedatacloud-x402`.

Έξοδος ελέγχου εγκατάστασης και εισαγωγής σε καθαρό προσωρινό περιβάλλον:

```text
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4

acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
```

Επεξήγηση αποτελεσμάτων:

- Τα πακέτα npm και PyPI είναι πραγματικά δημοσιευμένα πακέτα, δεν είναι ονόματα θέσης στα έγγραφα.
- Το `acedatacloud-x402[cli]` θα εγκαταστήσει το CLI, η υποεντολή `approve-permit2` μπορεί να χρησιμοποιηθεί για την εξουσιοδότηση Permit2 σε σενάρια `upto`.

## Η πρώτη αίτηση θα επιστρέψει 402

Μπορείτε πρώτα να χρησιμοποιήσετε το `curl` για να δείτε τι επιστρέφει μια μη πληρωμένη αίτηση. Το παρακάτω παράδειγμα δεν θα προκαλέσει χρέωση, καθώς δεν περιέχει `PAYMENT-SIGNATURE`:

```bash
curl -sS -X POST https://x402.acedata.cloud/openai/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "hi"}],
    "max_tokens": 1
  }'
```

Η απάντηση θα περιέχει τον πίνακα `accepts`, με μια κοινή δομή όπως παρακάτω:

```json
{
  "x402Version": 2,
  "resource": {
    "url": "/openai/chat/completions",
    "description": "AceDataCloud API call",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "maxAmountRequired": "95215",
      "amount": "95215",
      "maxTimeoutSeconds": 3600,
      "resource": "/openai/chat/completions",
      "description": "...",
      "payTo": "0x...",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913"
      }
    }
  ],
  "error": "PAYMENT-SIGNATURE header is required"
}
```

Η ίδια πρόκληση θα τοποθετηθεί επίσης σε μορφή base64 στην κεφαλίδα `PAYMENT-REQUIRED`, διευκολύνοντας τον πελάτη να διαβάσει τις απαιτήσεις πληρωμής χωρίς να αναλύσει το σώμα.

Η έξοδος του προγράμματος για μη πληρωμένες αιτήσεις API παραγωγής είναι η εξής:

```text
status=402
x402Version 2
accepts [
  ('eip155:8453', 'exact', '95215'),
  ('eip155:8453', 'upto', '95215'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '95215'),
  ('eip155:1187947933', 'exact', '95215')
]
```

Επεξήγηση αποτελεσμάτων:

- Η πρώτη αίτηση δεν περιείχε `Authorization` ή `PAYMENT-SIGNATURE`, επομένως επιστρέφει HTTP 402 και δεν θα προκαλέσει χρέωση.
- Το `accepts` είναι η μοναδική αξιόπιστη υπογραφή για αυτή την αίτηση, περιλαμβάνει διαθέσιμα δίκτυα, scheme, ανώτατο ποσό, διεύθυνση πληρωμής και διεύθυνση περιουσιακού στοιχείου.
- Το `network` είναι η CAIP-2 αναγνώριση, ο πελάτης πρέπει να ταιριάζει με τη συμβολοσειρά CAIP-2 κατά την επιλογή δικτύου.
- Το ανώτατο ποσό για την ελάχιστη αίτηση συνομιλίας `gpt-4o-mini` είναι `95215` atomic USDC, δηλαδή `0.095215` USDC.
- Κάθε αίτηση θα πρέπει να διαβάζει την απάντηση 402 της τρέχουσας αίτησης, μην σκληροκωδικοποιείτε το ποσό παραδείγματος στον επιχειρηματικό κώδικα.

Σημασία πεδίων:

| Πεδίο                  | Περιγραφή                                                                       |
| ------------------- | ------------------------------------------------------------------------ |
| `scheme`            | Σχέδιο πληρωμής. `exact` σημαίνει σταθερό ποσό, `upto` σημαίνει ανώτατο όριο εξουσιοδότησης, υπολογίζεται με βάση την πραγματική χρήση.                               |
| `network`           | CAIP-2 αναγνώριση του δικτύου πληρωμής, π.χ. `eip155:8453`, `eip155:1187947933`, `solana:5eykt4...`. |
| `maxAmountRequired` | Μέγιστο ποσό πληρωμής, μονάδα είναι τα atomic units USDC, `95215` σημαίνει `0.095215` USDC.                 |
| `amount`            | Το ποσό που θα υπολογιστεί αυτή τη φορά; `exact` είναι το ίδιο με το `maxAmountRequired`, `upto` θα τροποποιηθεί κατά την φάση υπολογισμού με βάση την πραγματική χρήση.           |
| `payTo`             | Διεύθυνση πληρωμής.                                                                    |
| `asset`             | Διεύθυνση συμβολαίου USDC ή διεύθυνση mint Solana.                                               |
| `extra`             | Επιπλέον πληροφορίες που απαιτούνται για την υπογραφή, όπως ID αλυσίδας, τομέας EIP-712, διεύθυνση Permit2 κ.λπ.                                |

## Ολοκλήρωση πληρωμής με SDK

Ακολουθεί το ελάχιστο παράδειγμα TypeScript. Καθορίζει `network: 'skale'`, ο χειριστής θα επιλέξει την απαίτηση πληρωμής SKALE από την τρέχουσα απάντηση 402; το πραγματικό ποσό και η διεύθυνση πληρωμής θα παραμείνουν σύμφωνα με το `accepts`.
```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.SKALE_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'skale',
    evmProvider,
    evmAddress: wallet.address
  })
});

const response = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Reply with exactly: hello' }],
  max_tokens: 8
});

console.log(response.choices[0].message.content);
```

Το αποτέλεσμα της εκτέλεσης του προγράμματος με το SDK TypeScript στην ίδια διαδρομή:

```text
payer 0xd0479FA9FD8C678303d477433d24C15e3723CC1C
elapsed_ms 6782
content ADC_TS_SDK_X402_OK
id chatcmpl-DlcVLO4PQWvmjPDQpy9yQw2QdLGAT
```

Επεξήγηση αποτελέσματος:

- `content ADC_TS_SDK_X402_OK` είναι η σταθερή συμβολοσειρά που επιστρέφει το μοντέλο σύμφωνα με την προτροπή, υποδεικνύοντας ότι η πληρωμή επαναλήφθηκε και το αίτημα πραγματικά εισήλθε στο API του μοντέλου.
- `payer` είναι η διεύθυνση του τοπικού υπογεγραμμένου πορτοφολιού, το ιδιωτικό κλειδί δεν έχει σταλεί στην Ace Data Cloud.
- Το SDK ολοκλήρωσε την ανάλυση 402, την υπογραφή `PAYMENT-SIGNATURE` και την επαναλαμβανόμενη αρχική αίτηση; ο επιχειρηματικός κώδικας εξακολουθεί να είναι γραμμένος με τον κανονικό τρόπο κλήσης SDK.

Πίσω από αυτόν τον κώδικα συνέβησαν τέσσερα βήματα:

1. Το SDK στέλνει μία κανονική αίτηση API, χωρίς `Authorization`.
2. Η πύλη επιστρέφει `402 Payment Required` και `accepts`.
3. Η `createX402PaymentHandler` επιλέγει την απαίτηση πληρωμής `network = 'skale'` και υπογράφει το `PAYMENT-SIGNATURE`.
4. Το SDK επαναλαμβάνει με το ίδιο σώμα αιτήματος, η πύλη καλεί τον Facilitator για επαλήθευση και διακανονισμό και στη συνέχεια επιτρέπει την πρόσβαση στο στόχο API.

## Δείτε τις δυνατότητες του Facilitator

Η X402 API δεν εξαρτάται από τον κατάλογο πόρων. Ο πελάτης καλεί απευθείας γνωστά API και χρησιμοποιεί την `402 Payment Required` και `accepts` που επιστρέφονται σε πραγματικό χρόνο ως μοναδική βάση τιμής και υπογραφής.

Η δήλωση ικανοτήτων του Facilitator βρίσκεται στο:

```bash
curl https://facilitator.acedata.cloud/.well-known/x402
```

Περιγράφει μόνο τα `/supported`, `/verify`, `/settle` και τα τρέχοντα ενεργοποιημένα δίκτυα πληρωμών, χωρίς να απαριθμεί πόρους API.

Η διεύθυνση παραγωγής του Facilitator της Ace Data Cloud είναι:

```text
https://facilitator.acedata.cloud
```

Μπορείτε να δείτε ποια δίκτυα και σχήματα υποστηρίζει:

```bash
curl https://facilitator.acedata.cloud/supported
```

Η επιστρεφόμενη `kinds` θα απαριθμήσει τα δίκτυα και σχήματα που υποστηρίζει ο Facilitator. Κατά την πραγματική κλήση, εξακολουθεί να ισχύει η `accepts` που επιστρέφεται από το API.

Η έξοδος του Facilitator `/supported`:

```text
kinds [
  ('eip155:8453', 'exact'),
  ('eip155:8453', 'upto', {'facilitatorAddress': '0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708'}),
  ('eip155:1187947933', 'exact'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact')
]
```

Επεξήγηση αποτελέσματος:

- Το `/supported` υποδεικνύει ότι ο Facilitator διαθέτει αυτές τις ικανότητες επαλήθευσης και διακανονισμού για τα δίκτυα και σχήματα.
- Το Base, SKALE και Solana υποστηρίζουν το `exact`; το `upto` παρέχεται προς το παρόν μόνο στο Base.
- Εάν ένα συγκεκριμένο API επιτρέπει ένα δίκτυο, εξακολουθεί να ισχύει η `402 accepts` αυτού του API.
