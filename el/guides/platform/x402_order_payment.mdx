Εκτός από την άμεση πληρωμή ανά αίτημα API, το Ace Data Cloud υποστηρίζει επίσης την πληρωμή παραγγελιών μέσω X402. Το βασικό πρωτόκολλο για την πληρωμή παραγγελιών και τις κλήσεις API είναι το ίδιο: το πρώτο αίτημα επιστρέφει 402, ο πελάτης υπογράφει το `PAYMENT-SIGNATURE` και στη συνέχεια επαναλαμβάνει το αίτημα με το ίδιο αίτημα.

Η διαφορά είναι ότι η πληρωμή παραγγελίας ανήκει στο API της πλατφόρμας και απαιτεί διακριτικό λογαριασμού· ενώ η άμεση κλήση του AI API `x402.acedata.cloud` μπορεί να χρησιμοποιεί μόνο X402, χωρίς να απαιτεί API Token.

## Προετοιμασία παραγγελίας

Μεταβείτε στην [κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/orders), επιλέξτε την παραγγελία που πρέπει να πληρωθεί και καταγράψτε το ID της παραγγελίας.

Εάν δεν έχετε ακόμη παραγγελία, μπορείτε να δημιουργήσετε μια εκκρεμή προς πληρωμή παραγγελία στη σελίδα πακέτων. Η τιμή της παραγγελίας υπόκειται σε ό,τι εμφανίζεται στη σελίδα και το `amount` στην απόκριση X402 402 είναι η τελική βάση για την υπογραφή.

## Δημιουργία διακριτικού λογαριασμού

Τα αιτήματα πληρωμής παραγγελιών απαιτούν διακριτικό λογαριασμού. Ανοίξτε τη [σελίδα Token της πλατφόρμας](https://platform.acedata.cloud/console/platform-tokens) και δημιουργήστε ένα token στη μορφή `platform-v1-...`.

Για τα επόμενα αιτήματα χρησιμοποιήστε:

```http
Authorization: Bearer {platform_token}
```

Το διακριτικό λογαριασμού διαφέρει από το κανονικό API Token. Το κανονικό API Token χρησιμοποιείται για την κατανάλωση ποσοστώσεων API· το διακριτικό λογαριασμού χρησιμοποιείται για την εκπροσώπηση του λογαριασμού σας κατά τη λειτουργία πόρων της πλατφόρμας, όπως η πληρωμή παραγγελιών.

## Ενεργοποίηση 402

Πρώτα στείλτε ένα αίτημα χωρίς `PAYMENT-SIGNATURE`:

```http
POST https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/
Authorization: Bearer {platform_token}
Content-Type: application/json

{
  "pay_way": "X402"
}
```

Η κατάσταση επιστροφής είναι 402 και η απόκριση περιλαμβάνει `accepts`:

```json
{
  "x402Version": 2,
  "error": "Payment required for this order.",
  "resource": {
    "url": "http://platform.acedata.cloud/api/v1/orders/.../pay/",
    "description": "Ace Data Cloud Credits x 10.0",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "amount": "1200000",
      "payTo": "0x...",
      "maxTimeoutSeconds": 120,
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
        "decimals": 6
      }
    }
  ],
  "paywall": {
    "app_name": "Ace Data Cloud",
    "app_logo": "https://cdn.acedata.cloud/favicon.ico"
  }
}
```

Η πληρωμή παραγγελίας χρησιμοποιεί το επίσημο x402 v2: το `x402Version` είναι `2`, το `network` χρησιμοποιεί αναγνωριστικό CAIP-2 και το πεδίο ποσού είναι το `amount`.

Αποτέλεσμα εκτέλεσης του προγράμματος για τη δημιουργία παραγγελίας 10 Credits και την ενεργοποίηση 402:

> Οι ακόλουθες καταγραφές συναλλαγών είναι ιστορικά δείγματα πραγματικών δοκιμών βάσει της παλιάς πολιτικής· τα ποσά και τα hashes συναλλαγών διατηρούνται ως έχουν. Οι νέες παραγγελίες X402 δεν παρέχουν πλέον έκπτωση μεθόδου πληρωμής· χρησιμοποιήστε το `amount` της τρέχουσας απόκρισης 402 ως βάση για υπογραφή και πληρωμή.

```text
created order 78481793-304e-47f7-bc0c-8231aec9cc1e
created state Pending
created price 1.26

http_status=402
x402Version 2
error Payment required for this order.
accepts [
  ('eip155:8453', 'exact', '1200000', '0x4F0E2D3477a1B94CF33d16E442CEe4733dadCeE7'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '1200000', '5iVXFrYaYWX2GUTbkQj8mDBoBhAX8bneYigS2LJTia43')
]
description Ace Data Cloud Credits x 10.0
```

Επεξήγηση αποτελεσμάτων:

- Μετά την επιτυχή δημιουργία της παραγγελίας, η κατάσταση είναι `Pending` και δεν υπάρχει ακόμη πληρωμή στην αλυσίδα.
- Το πρώτο αίτημα `pay/` δεν περιέχει `PAYMENT-SIGNATURE`, επομένως επιστρέφει HTTP 402.
- Το `accepts` παρέχει ταυτόχρονα Base `exact` και Solana `exact`· αυτό το εγχειρίδιο επιλέγει στη συνέχεια το Base.
- Η τιμή κατά τη δημιουργία της παραγγελίας είναι `1.26` και, κατά την περίοδο της παλιάς πολιτικής έκπτωσης πληρωμής X402, το πραγματικό ποσό υπογραφής και εκκαθάρισης ήταν `1.2` USDC, που αντιστοιχεί σε `1200000` atomic USDC.

Σημειώστε ότι εδώ το `resource` είναι πεδίο που επιστρέφεται από τον διακομιστή και συμμετέχει στην υπογραφή· ο πελάτης δεν πρέπει να ξαναγράψει μόνος του το πρωτόκολλο, τη διαδρομή ή το ID παραγγελίας που περιέχει.

## Υπογραφή και επανάληψη

Η πληρωμή παραγγελίας μπορεί να επαναχρησιμοποιήσει τη συνάρτηση υπογραφής χαμηλού επιπέδου του `@acedatacloud/x402-client` ή του `acedatacloud-x402`. Ακολουθεί ένα παράδειγμα TypeScript:

```ts
import { Wallet } from 'ethers';
import { signEVMPayment } from '@acedatacloud/x402-client';

const platformToken = process.env.ACE_PLATFORM_TOKEN!;
const orderId = process.env.ACE_ORDER_ID!;
const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const url = `https://platform.acedata.cloud/api/v1/orders/${orderId}/pay/`;
const body = { pay_way: 'X402' };

const first = await fetch(url, {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${platformToken}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify(body)
});

if (first.status !== 402) {
  throw new Error(`expected 402, got ${first.status}`);
}

const paymentRequired = await first.json();
const requirement = paymentRequired.accepts.find(
  (item: any) => item.network === 'eip155:8453' && item.scheme === 'exact'
);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') throw new Error(`unsupported method: ${method}`);
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const envelope = await signEVMPayment(requirement, evmProvider, wallet.address);
const xPayment = Buffer.from(JSON.stringify(envelope), 'utf8').toString('base64');

const paid = await fetch(url, {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${platformToken}`,
    'Content-Type': 'application/json',
    'PAYMENT-SIGNATURE': xPayment
  },
  body: JSON.stringify(body)
});

if (!paid.ok) {
  throw new Error(`payment failed: ${paid.status} ${await paid.text()}`);
}

console.log(await paid.json());
```

Αποτέλεσμα εκτέλεσης του προγράμματος μετά την υπογραφή και επανάληψη της ίδιας παραγγελίας με Base `exact`:

```text
status 200
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
has_x_payment_response True
settle_header {'success': True, 'network': 'base', 'transaction': '0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151', 'errorReason': None}
order {'id': '78481793-304e-47f7-bc0c-8231aec9cc1e', 'state': 'Finished', 'pay_way': 'X402', 'price': 1.2, 'pay_id': '0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151'}
```

Αποτέλεσμα επιβεβαίωσης στην αλυσίδα:
```text
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
status 1
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer {"from":"0x5d4f08D5c2bb60703284bc06671Eb680fA41B105","to":"0x4F0E2D3477a1B94CF33d16E442CEe4733dadCeE7","value":"1200000"}
```

Επεξήγηση αποτελέσματος:

- Το `status 200` υποδεικνύει ότι το API πληρωμής παραγγελίας της πλατφόρμας αποδέχτηκε αυτήν την `PAYMENT-SIGNATURE`.
- Το `has_x_payment_response True` υποδεικνύει ότι οι κεφαλίδες απόκρισης περιλαμβάνουν την απόδειξη `PAYMENT-RESPONSE` με κωδικοποίηση Base64.
- Το `settle_header.success=True` και το `network=base` υποδεικνύουν ότι ο Facilitator έχει ολοκληρώσει το Base settlement.
- Η τελική κατάσταση της παραγγελίας είναι `Finished`, το `pay_way` είναι `X402` και το `pay_id` καταγράφει το hash της on-chain συναλλαγής.
- Το συμβάν `Transfer` στο BaseScan δείχνει ότι η διεύθυνση πληρωμής μετέφερε `1200000` atomic USDC στη διεύθυνση είσπραξης της πλατφόρμας, δηλαδή `1.2` USDC.

## Επιτυχής απόκριση και απόδειξη

Μετά την επιτυχή πληρωμή της παραγγελίας, το σώμα απόκρισης περιέχει τις πληροφορίες της παραγγελίας. Η πλατφόρμα μεταφέρει επίσης στην κεφαλίδα απόκρισης `PAYMENT-RESPONSE` την απόκριση settlement με κωδικοποίηση Base64, της οποίας τα συνήθη πεδία μετά την αποκωδικοποίηση περιλαμβάνουν:

| Πεδίο            | Περιγραφή                           |
| ------------- | ---------------------------- |
| `success`     | Αν το Facilitator settlement ήταν επιτυχές. |
| `transaction` | Hash της on-chain συναλλαγής settlement.                    |
| `network`     | Δίκτυο πληρωμής.                        |
| `payer`       | Διεύθυνση πορτοφολιού πληρωτή.                      |
| `amount`      | Πραγματικό ποσό settlement, με χρήση atomic units.      |

Αν χρειάζεστε συμφωνία λογαριασμών, συνιστάται να αποθηκεύετε ταυτόχρονα το ID παραγγελίας, τη διεύθυνση πορτοφολιού πληρωτή, το `transaction` και την τελική κατάσταση της παραγγελίας.

## Σημειώσεις

- Η πληρωμή παραγγελίας απαιτεί διακριτικό λογαριασμού της πλατφόρμας και δεν μπορεί να ολοκληρωθεί μόνο με υπογραφή πορτοφολιού X402.
- Το `amount` χρησιμοποιεί USDC atomic units· το `1200000` αντιστοιχεί σε `1.2` USDC.
- Μη συνθέτετε μόνοι σας τη διεύθυνση είσπραξης ή τη διεύθυνση asset· χρησιμοποιήστε ως βάση το `accepts` στην απόκριση 402.
- Αν η ίδια `PAYMENT-SIGNATURE` υποβληθεί επανειλημμένα, ο Facilitator θα εκτελέσει προστασία επανάληψης με βάση το nonce.

## Απόκριση αποτυχίας πληρωμής

Το πρώτο HTTP 402 χωρίς `PAYMENT-SIGNATURE` είναι μια κανονική πρόκληση πληρωμής και δεν υποδηλώνει αποτυχία πληρωμής. Η αποτυχία επαλήθευσης ή settlement μετά την υπογραφή διατηρεί το τυπικό string `error` ως συμβατό fallback και επιστρέφει σταθερή δομή σφάλματος στο `extensions.acedatacloud.paymentError`:

```json
{
  "code": "insufficient_token_balance",
  "params": { "network": "eip155:8453" },
  "stage": "verify",
  "retryable": true,
  "charged": false
}
```

Ο πελάτης θα πρέπει κατά προτεραιότητα να προσαρμόζει τοπικά βάσει του `code`, ενώ για άγνωστο code να επιστρέφει σε γενική αποτυχία πληρωμής. Το `charged` είναι πεδίο τριών καταστάσεων: μόνο όταν υπάρχει ρητή απόρριψη πριν το settlement θα επιστρέφεται `false`· η απουσία του πεδίου υποδηλώνει ότι η κατάσταση χρέωσης είναι άγνωστη και δεν μπορεί να ερμηνευτεί ως «δεν χρεώθηκε». Αφού η τρέχουσα παραγγελία εισέλθει σε `Failed`, δεν μπορεί να επαναληφθεί η ίδια παραγγελία· δημιουργήστε νέα παραγγελία αφού διορθώσετε το πρόβλημα του πορτοφολιού.

Τα `metadata.x402.last_error` και `metadata.x402.errors` στη λίστα και στις λεπτομέρειες παραγγελιών διατηρούν το ίδιο σύνολο `code`, `stage`, `retryable`, `charged` και `params`· το δημόσιο επεξηγηματικό κείμενο αποθηκεύεται στο `reason` και ο χρόνος εμφάνισης αποθηκεύεται στο `timestamp`. Για παράδειγμα, το `insufficient_token_balance` υποδηλώνει ανεπαρκές υπόλοιπο USDC στο επιλεγμένο δίκτυο, ενώ το `invalid_signature` υποδηλώνει μη έγκυρη υπογραφή πληρωμής· η εκ νέου ανάγνωση της παραγγελίας δεν θα τα αλλάξει σε γενικό `payment_failed`.

Μην καταγράφετε ή υποβάλλετε πλήρη `PAYMENT-SIGNATURE`, υπογραφή πορτοφολιού, authorization payload, πρωτογενή διαγνωστικά Facilitator ή απόκριση RPC. Για έλεγχο από την εξυπηρέτηση πελατών απαιτούνται μόνο το ID παραγγελίας και το δημόσιο `code` σφάλματος.

## Επαναγορά και καύση ACE για πληρωμές Base και Solana

Αφού ενεργοποιηθεί η στρατηγική επαναγοράς, το 3% των πραγματικών εισπραχθέντων ποσών από επιλέξιμα Circle USDC του Base mainnet και USDC του Solana mainnet χρησιμοποιείται για την αγορά και καύση ACE, χωρίς επιπλέον χρέωση στο πορτοφόλι πληρωτή. Η πρόβλεψη γίνεται μία φορά κατά την ανανέωση· η μετέπειτα χρήση αυτών των Credits για κλήση API δεν δημιουργεί επαναλαμβανόμενη πρόβλεψη· οι ιστορικές παραγγελίες με έκπτωση και οι παραγγελίες παλαιάς πολιτικής δεν λαμβάνουν αυτόματη αναδρομική πρόβλεψη.

Οι πληρωμές Base διατηρούν την απόδειξη πληρωμής στην αλυσίδα Base, ενώ η αγορά και καύση ACE εκτελούνται ασύγχρονα στο Solana. Οι επιλέξιμες πληρωμές προβλέπουν με ακρίβεια 3% βάσει του πραγματικού εισπραχθέντος ποσού, χωρίς σταθερό ανώτατο όριο ποσού επαναγοράς ανά συναλλαγή ή ανά ημέρα· τα διαθέσιμα κεφάλαια, οι τιμές αγοράς και οι on-chain επιβεβαιώσεις ενδέχεται να επηρεάζουν τον χρόνο ολοκλήρωσης. Το αντικείμενο `ace_burn` στις λεπτομέρειες παραγγελίας παρέχει `settlement_network`, `settlement_transaction` και `execution_network`, και μετά την ολοκλήρωση παρέχει `swap_signature` και `burn_signature`. Το `Pending` ή το `Processing` δεν υποδηλώνει ότι έχει ήδη γίνει καύση· μόνο το `Completed` αντιπροσωπεύει ότι έχει επαληθευτεί η τελική on-chain απόδειξη. Όταν η πληρωμή Base δεν έχει ακόμη φτάσει σε τελική επιβεβαίωση, η επαναγορά θα περιμένει την επιβεβαίωση, αλλά αυτό δεν επηρεάζει τα Credits που έχουν ήδη πιστωθεί.
