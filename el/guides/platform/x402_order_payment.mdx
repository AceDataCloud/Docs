Εκτός από την απευθείας πληρωμή ανά αίτημα API, το Ace Data Cloud υποστηρίζει επίσης τη χρήση του X402 για την πληρωμή παραγγελιών στην κονσόλα. Το βασικό πρωτόκολλο για την πληρωμή παραγγελιών και τις κλήσεις API είναι το ίδιο: το πρώτο αίτημα επιστρέφει 402, ο πελάτης υπογράφει το `PAYMENT-SIGNATURE` και στη συνέχεια επαναλαμβάνει το αίτημα με το ίδιο αίτημα.

Η διαφορά είναι ότι η πληρωμή παραγγελιών ανήκει στο API πλατφόρμας και απαιτεί διακριτικό λογαριασμού· ενώ η απευθείας κλήση του AI API `x402.acedata.cloud` μπορεί να χρησιμοποιεί μόνο X402, χωρίς να απαιτείται API Token.

## Προετοιμασία παραγγελίας

Μεταβείτε στην [κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/orders), επιλέξτε την παραγγελία που πρέπει να πληρωθεί και καταγράψτε το ID της παραγγελίας.

Αν δεν έχετε ακόμη παραγγελία, μπορείτε να δημιουργήσετε μια παραγγελία προς πληρωμή στη σελίδα πακέτων. Η τιμή της παραγγελίας υπόκειται σε αυτήν που εμφανίζεται στη σελίδα και το `amount` στην απόκριση X402 402 είναι η τελική βάση για την υπογραφή.

## Δημιουργία διακριτικού λογαριασμού

Το αίτημα πληρωμής παραγγελίας απαιτεί διακριτικό λογαριασμού. Ανοίξτε τη [σελίδα Token της πλατφόρμας](https://platform.acedata.cloud/console/platform-tokens) και δημιουργήστε ένα token σε μορφή `platform-v1-...`.

Για τα επόμενα αιτήματα χρησιμοποιήστε:

```http
Authorization: Bearer {platform_token}
```

Το διακριτικό λογαριασμού διαφέρει από το συνηθισμένο API Token. Το συνηθισμένο API Token χρησιμοποιείται για την κατανάλωση ποσοστώσεων API· το διακριτικό λογαριασμού χρησιμοποιείται για την εκπροσώπηση του λογαριασμού σας κατά τη λειτουργία πόρων πλατφόρμας, όπως η πληρωμή παραγγελιών.

## Ενεργοποίηση 402

Αρχικά στείλτε ένα αίτημα χωρίς `PAYMENT-SIGNATURE`:

```http
POST https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/
Authorization: Bearer {platform_token}
Content-Type: application/json

{
  "pay_way": "X402"
}
```

Η επιστρεφόμενη κατάσταση είναι 402 και η απόκριση περιλαμβάνει το `accepts`:

```json
{
  "x402Version": 2,
  "error": "Payment required for this order.",
  "resource": {
    "url": "http://platform.acedata.cloud/api/v1/orders/.../pay/",
    "description": "Ace Data Cloud Credits x 10.0",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "amount": "1200000",
      "payTo": "0x...",
      "maxTimeoutSeconds": 120,
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
        "decimals": 6
      }
    }
  ],
  "paywall": {
    "app_name": "Ace Data Cloud",
    "app_logo": "https://cdn.acedata.cloud/favicon.ico"
  }
}
```

Η πληρωμή παραγγελιών χρησιμοποιεί το επίσημο x402 v2: το `x402Version` είναι `2`, το `network` χρησιμοποιεί αναγνωριστικό CAIP-2 και το πεδίο ποσού είναι το `amount`.

Αποτέλεσμα εκτέλεσης προγράμματος για τη δημιουργία παραγγελίας 10 Credits και την ενεργοποίηση 402:

> Τα παρακάτω αρχεία συναλλαγών είναι ιστορικά δείγματα πραγματικών δοκιμών υπό την παλιά πολιτική· τα ποσά και τα hashes συναλλαγών διατηρούνται ως είχαν. Οι νέες παραγγελίες X402 δεν παρέχουν πλέον εκπτώσεις με βάση τον τρόπο πληρωμής· χρησιμοποιήστε το `amount` της τρέχουσας απόκρισης 402 ως βάση για την υπογραφή και την πληρωμή.

```text
created order 78481793-304e-47f7-bc0c-8231aec9cc1e
created state Pending
created price 1.26

http_status=402
x402Version 2
error Payment required for this order.
accepts [
  ('eip155:8453', 'exact', '1200000', '0x4F0E2D3477a1B94CF33d16E442CEe4733dadCeE7'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '1200000', '5iVXFrYaYWX2GUTbkQj8mDBoBhAX8bneYigS2LJTia43')
]
description Ace Data Cloud Credits x 10.0
```

Επεξήγηση αποτελεσμάτων:

- Αφού δημιουργηθεί επιτυχώς η παραγγελία, η κατάστασή της είναι `Pending` και δεν υπάρχει ακόμη πληρωμή στην αλυσίδα.
- Το πρώτο αίτημα `pay/` δεν περιέχει `PAYMENT-SIGNATURE`, επομένως επιστρέφει HTTP 402.
- Το `accepts` παρέχει ταυτόχρονα Base `exact` και Solana `exact`· σε αυτόν τον οδηγό επιλέγεται στη συνέχεια το Base.
- Η τιμή κατά τη δημιουργία της παραγγελίας είναι `1.26` και, κατά την περίοδο της παλιάς πολιτικής έκπτωσης πληρωμών X402, το πραγματικό ποσό υπογραφής και εκκαθάρισης ήταν `1.2` USDC, που αντιστοιχεί σε `1200000` atomic USDC.

Σημειώστε ότι εδώ το `resource` είναι πεδίο που επιστρέφεται από τον διακομιστή και συμμετέχει στην υπογραφή· ο πελάτης δεν πρέπει να τροποποιεί μόνος του το πρωτόκολλο, τη διαδρομή ή το ID παραγγελίας που περιέχει.

## Υπογραφή και επανάληψη

Η πληρωμή παραγγελιών μπορεί να επαναχρησιμοποιήσει τις συναρτήσεις υπογραφής χαμηλού επιπέδου του `@acedatacloud/x402-client` ή του `acedatacloud-x402`. Παρακάτω είναι ένα παράδειγμα TypeScript:

```ts
import { Wallet } from 'ethers';
import { signEVMPayment } from '@acedatacloud/x402-client';

const platformToken = process.env.ACE_PLATFORM_TOKEN!;
const orderId = process.env.ACE_ORDER_ID!;
const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const url = `https://platform.acedata.cloud/api/v1/orders/${orderId}/pay/`;
const body = { pay_way: 'X402' };

const first = await fetch(url, {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${platformToken}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify(body)
});

if (first.status !== 402) {
  throw new Error(`expected 402, got ${first.status}`);
}

const paymentRequired = await first.json();
const requirement = paymentRequired.accepts.find(
  (item: any) => item.network === 'eip155:8453' && item.scheme === 'exact'
);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') throw new Error(`unsupported method: ${method}`);
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const envelope = await signEVMPayment(requirement, evmProvider, wallet.address);
const xPayment = Buffer.from(JSON.stringify(envelope), 'utf8').toString('base64');

const paid = await fetch(url, {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${platformToken}`,
    'Content-Type': 'application/json',
    'PAYMENT-SIGNATURE': xPayment
  },
  body: JSON.stringify(body)
});

if (!paid.ok) {
  throw new Error(`payment failed: ${paid.status} ${await paid.text()}`);
}

console.log(await paid.json());
```

Αποτέλεσμα εκτέλεσης προγράμματος μετά την υπογραφή και επανάληψη της ίδιας παραγγελίας με Base `exact`:

```text
status 200
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
has_x_payment_response True
settle_header {'success': True, 'network': 'base', 'transaction': '0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151', 'errorReason': None}
order {'id': '78481793-304e-47f7-bc0c-8231aec9cc1e', 'state': 'Finished', 'pay_way': 'X402', 'price': 1.2, 'pay_id': '0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151'}
```

Αποτέλεσμα επιβεβαίωσης στην αλυσίδα:
```text
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
status 1
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer {"from":"0x5d4f08D5c2bb60703284bc06671Eb680fA41B105","to":"0x4F0E2D3477a1B94CF33d16E442CEe4733dadCeE7","value":"1200000"}
```

Επεξήγηση αποτελέσματος:

- Το `status 200` υποδηλώνει ότι η διεπαφή πληρωμής παραγγελιών της πλατφόρμας αποδέχθηκε αυτό το `PAYMENT-SIGNATURE`.
- Το `has_x_payment_response True` υποδηλώνει ότι η κεφαλίδα απόκρισης περιλαμβάνει απόδειξη `PAYMENT-RESPONSE` κωδικοποιημένη σε Base64.
- Τα `settle_header.success=True` και `network=base` υποδηλώνουν ότι ο Facilitator ολοκλήρωσε το Base settlement.
- Η τελική κατάσταση της παραγγελίας είναι `Finished`, το `pay_way` είναι `X402` και το `pay_id` γράφει το hash της συναλλαγής on-chain.
- Το συμβάν `Transfer` στο BaseScan δείχνει ότι η διεύθυνση πληρωμής μετέφερε `1200000` atomic USDC στη διεύθυνση είσπραξης της πλατφόρμας, δηλαδή `1.2` USDC.

## Επιτυχής απόκριση και απόδειξη

Αφού η πληρωμή της παραγγελίας ολοκληρωθεί επιτυχώς, το σώμα απόκρισης είναι οι πληροφορίες της παραγγελίας. Η πλατφόρμα θα μεταφέρει επίσης στην κεφαλίδα απόκρισης `PAYMENT-RESPONSE` ένα settlement response κωδικοποιημένο σε Base64, του οποίου τα συνήθη πεδία μετά την αποκωδικοποίηση περιλαμβάνουν:

| Πεδίο            | Περιγραφή                           |
| ------------- | ---------------------------- |
| `success`     | Αν το Facilitator settlement είναι επιτυχές. |
| `transaction` | Hash της συναλλαγής εκκαθάρισης on-chain.                    |
| `network`     | Δίκτυο πληρωμής.                        |
| `payer`       | Διεύθυνση πορτοφολιού πληρωτή.                      |
| `amount`      | Πραγματικό ποσό εκκαθάρισης, με χρήση atomic units.      |

Αν χρειάζεστε συμφωνία λογαριασμών, συνιστάται να αποθηκεύσετε ταυτόχρονα το ID παραγγελίας, τη διεύθυνση πορτοφολιού πληρωμής, το `transaction` και την τελική κατάσταση της παραγγελίας.

## Σημειώσεις

- Η πληρωμή της παραγγελίας απαιτεί διακριτικό λογαριασμού πλατφόρμας και δεν μπορεί να ολοκληρωθεί μόνο με υπογραφή πορτοφολιού X402.
- Το `amount` χρησιμοποιεί USDC atomic units, το `1200000` αντιστοιχεί σε `1.2` USDC.
- Μη συνθέτετε μόνοι σας τη διεύθυνση είσπραξης ή τη διεύθυνση του asset· να βασίζεστε στο `accepts` της απόκρισης 402.
- Εάν το ίδιο `PAYMENT-SIGNATURE` υποβληθεί επανειλημμένα, ο Facilitator θα εφαρμόσει προστασία επανάληψης βάσει nonce.

## Απόκριση αποτυχίας πληρωμής

Το πρώτο HTTP 402 χωρίς `PAYMENT-SIGNATURE` είναι μια κανονική πρόκληση πληρωμής και δεν υποδηλώνει αποτυχία πληρωμής. Η αποτυχία επαλήθευσης ή εκκαθάρισης μετά την υπογραφή διατηρεί ακόμη το τυπικό string `error` ως συμβατό fallback, και επιστρέφει μια σταθερή δομή σφάλματος στο `extensions.acedatacloud.paymentError`:

```json
{
  "code": "insufficient_token_balance",
  "params": { "network": "eip155:8453" },
  "stage": "verify",
  "retryable": true,
  "charged": false
}
```

Ο πελάτης θα πρέπει κατά προτεραιότητα να πραγματοποιεί τοπικοποίηση βάσει του `code`, ενώ για άγνωστο code να επιστρέφει σε γενική αποτυχία πληρωμής. Το `charged` είναι πεδίο τριών καταστάσεων: μόνο όταν υπάρχει σαφής απόρριψη πριν από την εκκαθάριση επιστρέφεται `false`· η απουσία του πεδίου υποδηλώνει ότι η κατάσταση χρέωσης είναι άγνωστη και δεν μπορεί να ερμηνευθεί ως «δεν χρεώθηκε». Αφού η τρέχουσα παραγγελία εισέλθει σε `Failed`, δεν μπορεί να επαναληφθεί η αρχική παραγγελία· δημιουργήστε νέα παραγγελία αφού διορθώσετε το πρόβλημα του πορτοφολιού.

Μην καταγράφετε ή υποβάλλετε το πλήρες `PAYMENT-SIGNATURE`, την υπογραφή πορτοφολιού, το authorization payload, τα ακατέργαστα διαγνωστικά του Facilitator ή τις αποκρίσεις RPC. Για διερεύνηση από την υποστήριξη απαιτούνται μόνο το ID παραγγελίας και το δημόσιο `code` σφάλματος.
