---
title: "X402 `exact` και `upto` σχέδια χρέωσης"
description: "Platform API guide - Ace Data Cloud"
---

Η Ace Data Cloud X402 χρησιμοποιεί αυτή τη στιγμή δύο τύπους σχεδίων: `exact` και `upto`. Αυτά επιλύουν διαφορετικά προβλήματα χρέωσης.

## `exact`

`exact` σημαίνει ότι η τιμή της τρέχουσας αίτησης μπορεί να προσδιοριστεί πριν εισέλθει στο στόχο API. Το ποσό που υπογράφει ο πελάτης είναι το τελικό ποσό χρέωσης.

Κατάλληλο για:

- Δημιουργία εικόνας με σταθερή τιμή;
- Δημιουργία βίντεο με σταθερή τιμή;
- Σταθερές τιμές για API αναζητήσεων ή εργαλείων;
- Πληρωμή παραγγελίας.

Η EVM `exact` χρησιμοποιεί USDC EIP-3009 `TransferWithAuthorization`:

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "exact",
    "network": "eip155:8453"
  },
  "payload": {
    "authorization": {
      "from": "0x...",
      "to": "0x...",
      "value": "95215",
      "validAfter": "1780237345",
      "validBefore": "1780240945",
      "nonce": "0x..."
    },
    "signature": "0x..."
  }
}
```

Ο Facilitator επαληθεύει την υπογραφή και το ποσό στη φάση `/verify`, και υποβάλλει αυτή την εξουσιοδότηση στην αλυσίδα στη φάση `/settle`.

## `upto`

`upto` σημαίνει ότι ο πελάτης εξουσιοδοτεί ένα μέγιστο όριο, και η Ace Data Cloud χρεώνει με βάση την πραγματική χρήση μετά την ολοκλήρωση της αίτησης, με το πραγματικό ποσό χρέωσης να μην μπορεί να υπερβεί το όριο.

Κατάλληλο για:

- Συμπλήρωση συνομιλίας: Η τελική τιμή εξαρτάται από τα prompt tokens και τα completion tokens;
- Ροές απαντήσεων: Η πραγματική διάρκεια εξόδου γνωρίζεται μόνο μετά την ολοκλήρωση;
- Μελλοντικά API με μεταγενέστερη μέτρηση.

Το `upto` χρησιμοποιεί Permit2 `PermitWitnessTransferFrom`. Ο πελάτης δεν υπογράφει μια σταθερή μεταφορά, αλλά μια εξουσιοδότηση με μάρτυρα:

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "upto",
    "network": "eip155:8453"
  },
  "payload": {
    "permit2Authorization": {
      "from": "0x...",
      "spender": "0x4020A4f3b7b90ccA423B9fabCc0CE57C6C240002",
      "nonce": "123456789",
      "deadline": "1780240945",
      "permitted": {
        "token": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
        "amount": "95215"
      },
      "witness": {
        "to": "0x...",
        "facilitator": "0x...",
        "validAfter": "1780237345"
      }
    },
    "signature": "0x..."
  }
}
```

Το `permitted.amount` είναι το όριο, δεν είναι απαραίτητα το τελικό ποσό χρέωσης. Ο Gateway στη φάση `/record` θα μετατρέψει την πραγματική χρήση σε `amount` και θα το στείλει στον Facilitator. Ο Facilitator επιτρέπει μόνο την εκκαθάριση `amount &lt;= permitted.amount`.

Το αποτέλεσμα εκτέλεσης του προγράμματος Base `upto`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
signed ceiling 95215 atomic USDC
transfer value 3 atomic USDC
```

Επεξήγηση:

- Το όριο εξουσιοδότησης που επιστρέφεται στο 402 είναι `95215` atomic USDC, και ο πελάτης υπογράφει με βάση αυτό το όριο.
- Μετά την πραγματική απάντηση του μοντέλου, χρεώνεται μόνο `3` atomic USDC, και η συναλλαγή στην αλυσίδα μπορεί να ελεγχθεί στο BaseScan.
- Αυτό το αποτέλεσμα δείχνει τη βασική διαφορά του `upto`: το ποσό υπογραφής είναι το όριο, και η εκκαθάριση στην αλυσίδα μπορεί να είναι μικρότερη από το όριο.
- Εάν η πραγματική χρήση υπερβεί το όριο, ο Facilitator θα πρέπει να απορρίψει την εκκαθάριση, και ο πελάτης θα χρειαστεί να εξουσιοδοτήσει ξανά με υψηλότερο όριο.

Το `upto` παρέχεται αυτή τη στιγμή μόνο στο Base. Το SKALE παρέχει μόνο `exact`, εάν χρειάζεστε μεταγενέστερη μέτρηση, παρακαλώ χρησιμοποιήστε το Base.

## Γιατί χρειάζεται το Permit2 approve

Το `upto` τελικά ανακτά USDC από το πορτοφόλι πληρωμής μέσω του x402 proxy μέσω του Permit2. Πριν από την πρώτη χρήση, το πορτοφόλι πληρωμής πρέπει να δώσει μια φορά άδεια ERC-20 στο Permit2.

Python CLI:

```bash
pip install 'acedatacloud-x402[cli]'
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Προγραμματιστικός τρόπος:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Αφού ολοκληρωθεί η εξουσιοδότηση, κάθε αίτηση θα χρειαστεί να υπογραφεί με ένα νέο `upto` envelope, καθώς το nonce, η προθεσμία, ο μάρτυρας και το όριο ποσού είναι διαφορετικά.

## Εκκαθάριση μηδενικού ποσού

Το `upto` υποστηρίζει περιπτώσεις όπου το πραγματικό ποσό είναι 0. Για παράδειγμα, εάν το στόχο API δεν παράγει επιτυχώς μετρήσιμη ποσότητα, ο Gateway μπορεί να περάσει `amount = "0"`. Ο Facilitator θα επιστρέψει επιτυχία, αλλά δεν θα εκδώσει συναλλαγή στην αλυσίδα.

Αυτό μπορεί να αποτρέψει το πρόβλημα "η αίτηση δεν ήταν επιτυχής αλλά εξακολουθεί να χρεώνεται στην αλυσίδα".

## Συστάσεις επιλογής

| Σενάριο                   | Σύσταση                       |
| -------------------- | ------------------------ |
| Σταθερό API τιμής             | Χρησιμοποιήστε `exact`, η λογική είναι απλή.         |
| Πληρωμή παραγγελίας                 | Χρησιμοποιήστε `exact`.              |
| Συμπλήρωση συνομιλίας, χρέωση ανά token      | Χρησιμοποιήστε Base `upto`.          |
| Δεν έχετε κάνει Permit2 approve | Πρώτα χρησιμοποιήστε `exact` για να λειτουργήσει, και μετά αλλάξτε σε `upto`. |
| Χρειάζεστε μεταγενέστερη μέτρηση στο SKALE      | Δεν υποστηρίζεται προς το παρόν, το SKALE παρέχει μόνο `exact`.  |

Εάν δεν είστε σίγουροι ποιο να επιλέξετε, χρησιμοποιήστε πρώτα τη προεπιλεγμένη συμπεριφορά του SDK; το SDK θα επιλέξει την απαιτούμενη πληρωμή που επιστρέφεται από τον διακομιστή.

## Λίστα ελέγχου Base `upto`

Κατά την ένταξη ή την επίλυση προβλημάτων, παρακαλώ επιβεβαιώστε ότι οι παρακάτω παράμετροι προέρχονται από την ίδια απάντηση 402 και διατηρούνται συνεπείς κατά την υπογραφή από τον πελάτη:

| Παράμετρος                         | Σημείο ελέγχου                                          |
| -------------------------- | -------------------------------------------- |
| `network`                  | Πρέπει να είναι `eip155:8453`.                           |
| `scheme`                   | Πρέπει να είναι `upto`.                                  |
| `extra.chainId`            | Το chain id του Base είναι `8453`.                      |
| `asset`                    | Χρησιμοποιήστε τη διεύθυνση συμβολαίου Base USDC από την απάντηση 402.                  |
| `extra.facilitatorAddress` | Πρέπει να συμμετέχει ως μάρτυρας και να είναι συνεπής με τον Facilitator `/supported`. |
| Permit2 allowance          | Το πορτοφόλι πληρωμής πρέπει πρώτα να εξουσιοδοτήσει το Permit2 για το Base USDC.               |

Συχνά σφάλματα και τρόποι αντιμετώπισης:

| Σφάλμα                                           | Τρόπος αντιμετώπισης                                                                          |
| -------------------------------------------- | ----------------------------------------------------------------------------- |
| `invalid_upto_evm_payload_invalid_signature` | Ελέγξτε αν το chain id, η διεύθυνση facilitator, το Permit2 domain, ο spender, ο λογαριασμός υπογραφής και ο μάρτυρας είναι συνεπή με την απάντηση 402. |
| `PERMIT2_ALLOWANCE_REQUIRED`                 | Εκτελέστε Permit2 approve για το USDC του στόχου αλυσίδας και επαναλάβετε την αίτηση.                                         |
| `amount exceeds permitted amount`            | Η πραγματική χρήση υπερβαίνει το όριο υπογραφής, χρειάζεται να υπογραφεί ξανά με υψηλότερο όριο.                                                       |
