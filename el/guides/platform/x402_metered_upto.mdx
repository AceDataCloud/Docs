title: "Σχήματα χρέωσης X402 `exact` και `upto`"

Το Ace Data Cloud X402 χρησιμοποιεί επί του παρόντος δύο τύπους scheme: `exact` και `upto`. Επιλύουν διαφορετικά προβλήματα χρέωσης.

## `exact`

Το `exact` σημαίνει ότι η τιμή μπορεί να προσδιοριστεί πριν αυτό το αίτημα εισέλθει στο API προορισμού. Το ποσό που υπογράφει ο πελάτης είναι το τελικό ποσό χρέωσης.

Κατάλληλο για:

- Δημιουργία εικόνων με σταθερή τιμή·
- Δημιουργία εργασιών βίντεο με σταθερή τιμή·
- API αναζήτησης ή εργαλείων με σταθερή τιμή·
- Πληρωμές παραγγελιών.

Το EVM `exact` χρησιμοποιεί το USDC EIP-3009 `TransferWithAuthorization`:

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "exact",
    "network": "eip155:8453"
  },
  "payload": {
    "authorization": {
      "from": "0x...",
      "to": "0x...",
      "value": "95215",
      "validAfter": "1780237345",
      "validBefore": "1780240945",
      "nonce": "0x..."
    },
    "signature": "0x..."
  }
}
```

Ο Facilitator επαληθεύει την υπογραφή και το ποσό στο στάδιο `/verify`, και υποβάλλει αυτή την εξουσιοδότηση on-chain στο στάδιο `/settle`.

## `upto`

Το `upto` σημαίνει ότι ο πελάτης εξουσιοδοτεί ένα μέγιστο όριο, και το Ace Data Cloud εκκαθαρίζει βάσει της πραγματικής χρήσης μετά την ολοκλήρωση του αιτήματος· η πραγματική χρέωση δεν μπορεί να υπερβαίνει το όριο.

Κατάλληλο για:

- Συμπλήρωση συνομιλίας: η τελική τιμή εξαρτάται από τα prompt tokens και τα completion tokens·
- Ροϊκές αποκρίσεις: το πραγματικό μήκος εξόδου γίνεται γνωστό μόνο μετά το τέλος·
- Μελλοντικά API εκ των υστέρων μέτρησης.

Το `upto` χρησιμοποιεί το Permit2 `PermitWitnessTransferFrom`. Αυτό που υπογράφει ο πελάτης δεν είναι μια σταθερή μεταφορά, αλλά μια εξουσιοδότηση ορίου με witness:

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "upto",
    "network": "eip155:8453"
  },
  "payload": {
    "permit2Authorization": {
      "from": "0x...",
      "spender": "0x4020A4f3b7b90ccA423B9fabCc0CE57C6C240002",
      "nonce": "123456789",
      "deadline": "1780240945",
      "permitted": {
        "token": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
        "amount": "95215"
      },
      "witness": {
        "to": "0x...",
        "facilitator": "0x...",
        "validAfter": "1780237345"
      }
    },
    "signature": "0x..."
  }
}
```

Το `permitted.amount` είναι το όριο και δεν είναι απαραίτητα η τελική χρέωση. Το Gateway, στο στάδιο `/record`, μετατρέπει την πραγματική χρήση σε `amount` και τη μεταβιβάζει στον Facilitator. Ο Facilitator επιτρέπει εκκαθάριση μόνο όταν `amount &lt;= permitted.amount`.

Αποτέλεσμα εκτέλεσης του προγράμματος Base `upto`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
signed ceiling 95215 atomic USDC
transfer value 3 atomic USDC
```

Επεξήγηση:

- Το όριο εξουσιοδότησης που επιστρέφεται στο 402 είναι `95215` atomic USDC, και ο πελάτης υπογράφει με αυτό το όριο.
- Μετά την πραγματική απόκριση του μοντέλου, εκκαθαρίζονται μόνο `3` atomic USDC, και η on-chain συναλλαγή είναι διαθέσιμη στο BaseScan.
- Αυτό το αποτέλεσμα δείχνει την κρίσιμη διαφορά του `upto`: το υπογεγραμμένο ποσό είναι το όριο και το on-chain settlement μπορεί να είναι μικρότερο από το όριο.
- Εάν η πραγματική χρήση υπερβαίνει το όριο, ο Facilitator θα πρέπει να απορρίψει το settlement και ο πελάτης πρέπει να εξουσιοδοτήσει ξανά με υψηλότερο όριο.

Το `upto` παρέχεται επί του παρόντος μόνο στο Base. Όταν απαιτείται εκ των υστέρων μέτρηση, χρησιμοποιήστε το Base.

## Γιατί απαιτείται Permit2 approve

Το `upto` τελικά επιτρέπει στο x402 proxy να αντλεί USDC από το πορτοφόλι πληρωμής μέσω Permit2. Πριν από την πρώτη χρήση, το πορτοφόλι πληρωμής πρέπει να δώσει στο Permit2 μία ERC-20 allowance.

Python CLI:

```bash
pip install 'acedatacloud-x402[cli]'
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Προγραμματιστικά:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Μετά την ολοκλήρωση της εξουσιοδότησης, κάθε αίτημα εξακολουθεί να χρειάζεται να υπογράφει ένα νέο `upto` envelope, επειδή το nonce, το deadline, το witness και το ανώτατο όριο ποσού είναι όλα διαφορετικά.

## Εκκαθάριση μηδενικού ποσού

Το `upto` υποστηρίζει περιπτώσεις όπου το πραγματικό ποσό είναι 0. Για παράδειγμα, εάν το API προορισμού δεν παράγει επιτυχώς χρεώσιμη χρήση, το Gateway μπορεί να μεταβιβάσει `amount = "0"`. Ο Facilitator θα επιστρέψει επιτυχία, αλλά δεν θα εκδώσει on-chain συναλλαγή.

Αυτό μπορεί να αποφύγει το πρόβλημα «το αίτημα δεν ολοκληρώθηκε επιτυχώς, αλλά εξακολουθούν να χρεώνονται on-chain τέλη».

## Προτάσεις επιλογής

| Σενάριο                   | Πρόταση                       |
| ------------------------ | ---------------------------- |
| API σταθερής τιμής        | Χρησιμοποιήστε `exact`, η λογική είναι απλή. |
| Πληρωμή παραγγελίας       | Χρησιμοποιήστε `exact`.      |
| Συμπλήρωση συνομιλίας, χρέωση ανά token | Χρησιμοποιήστε Base `upto`.  |
| Δεν έχει γίνει ακόμη Permit2 approve | Χρησιμοποιήστε πρώτα `exact` για να λειτουργήσει, και μετά μεταβείτε σε `upto`. |

Εάν δεν είστε βέβαιοι ποιο να επιλέξετε, χρησιμοποιήστε πρώτα την προεπιλεγμένη συμπεριφορά του SDK· το SDK θα επιλέξει το payment requirement του αντίστοιχου δικτύου που επιστρέφει ο διακομιστής.

## Λίστα ελέγχου Base `upto`

Κατά την ενσωμάτωση ή την αντιμετώπιση προβλημάτων, επιβεβαιώστε ότι οι ακόλουθες παράμετροι προέρχονται από την ίδια απόκριση 402 και παραμένουν συνεπείς κατά την υπογραφή από τον πελάτη:

| Παράμετρος                 | Σημείο ελέγχου                                      |
| -------------------------- | --------------------------------------------------- |
| `network`                  | Πρέπει να είναι `eip155:8453`.                      |
| `scheme`                   | Πρέπει να είναι `upto`.                             |
| `extra.chainId`            | Το Base chain id είναι `8453`.                      |
| `asset`                    | Χρησιμοποιήστε τη διεύθυνση συμβολαίου Base USDC από την απόκριση 402. |
| `extra.facilitatorAddress` | Πρέπει να συμμετέχει στο witness και να συμφωνεί με το Facilitator `/supported`. |
| Permit2 allowance          | Το πορτοφόλι πληρωμής πρέπει πρώτα να εξουσιοδοτήσει το Permit2 για Base USDC. |

Συνήθη σφάλματα και τρόποι αντιμετώπισης:

| Σφάλμα                                           | Τρόπος αντιμετώπισης                                                                          |
| -------------------------------------------- | ----------------------------------------------------------------------------- |
| `invalid_upto_evm_payload_invalid_signature` | Ελέγξτε εάν το chain id, η διεύθυνση facilitator, το Permit2 domain, το spender, ο λογαριασμός υπογραφής και το witness συμφωνούν με την απόκριση 402. |
| `PERMIT2_ALLOWANCE_REQUIRED`                 | Εκτελέστε Permit2 approve για το USDC της αλυσίδας προορισμού και υποβάλετε ξανά το αίτημα. |
| `amount exceeds permitted amount`            | Η πραγματική χρήση υπερβαίνει το υπογεγραμμένο όριο· απαιτείται νέα υπογραφή με υψηλότερο όριο. |
