title: "Ανάκτηση λεπτομερειών παραγγελίας από την πλατφόρμα AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Αναζητήστε μια παραγγελία μέσω του ID παραγγελίας. Αυτό το endpoint υποστηρίζει δύο λειτουργίες ανάγνωσης: η ανώνυμη πρόσβαση επιστρέφει μόνο τα ελάχιστα πεδία που απαιτούνται από τη σελίδα πληρωμής· όταν ο κάτοχος της παραγγελίας παρέχει Account Token, επιστρέφονται πλήρεις λεπτομέρειες.

## Επισκόπηση διεπαφής

| Στοιχείο   | Περιεχόμενο                                                        |
| --- | --------------------------------------------------------- |
| Μέθοδος  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| Αυθεντικοποίηση  | Προαιρετική· η ανώνυμη πρόσβαση παρέχει ελάχιστη προβολή, ενώ ο αυθεντικοποιημένος κάτοχος παρέχει πλήρη προβολή                                    |

Τα `/orders/{id}` και `/orders/{id}/` είναι και τα δύο διαθέσιμα προς το παρόν. Το ID παραγγελίας αποτελεί μέρος του συνδέσμου πληρωμής και πρέπει να θεωρείται ευαίσθητο αδιαφανές αναγνωριστικό· μην το διαδίδετε δημόσια.

## Ανώνυμη αναζήτηση

Η σελίδα πληρωμής μπορεί να διαβαστεί απευθείας όταν χαθεί η κατάσταση σύνδεσης:

```shell
export ORDER_ID='το ID παραγγελίας σας'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

Η ανώνυμη απόκριση περιλαμβάνει μόνο τα `id`, `description`, `price`, `state`, `pay_way`, `pay_url`, `expired_at`, `created_at`. Δεν επιστρέφει λογαριασμό, Application, Package, εσωτερικά αναγνωριστικά πληρωμής ή metadata.

## Αυθεντικοποιημένη αναζήτηση

```shell
export PLATFORM_TOKEN='το διακριτικό λογαριασμού σας'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Ο κάτοχος της παραγγελίας λαμβάνει πλήρεις λεπτομέρειες Order, συμπεριλαμβανομένων των `application` / `applications`, `package` / `packages`, `bank_details`, `invoice_automation` και των πεδίων του μοντέλου. Εάν υπάρχει αυθεντικοποίηση αλλά δεν είναι ο κάτοχος της παραγγελίας, επιστρέφεται `403`· εξαιρούνται οι υπερδιαχειριστές.

## Βασικά πεδία

| Πεδίο            | Περιγραφή                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`, `Paid`, `Finished`, `Expired`, `Failed` ή `Refunded` |
| `pay_way`     | Η τρέχουσα μέθοδος πληρωμής της παραγγελίας· το όνομα του πεδίου δεν είναι `payment_method`                             |
| `pay_url`     | Διεύθυνση της φιλοξενούμενης σελίδας πληρωμής ή του κωδικού QR, και ενδέχεται να είναι κενή                                           |
| `price`       | Το τελικό πληρωτέο ποσό της παραγγελίας· το τρέχον μοντέλο παραγγελίας δεν παρέχει πεδίο `final_price`                         |
| `amount`      | Η ποσότητα πίστωσης του πακέτου· ορατή μόνο στην πλήρη αυθεντικοποιημένη απόκριση                                            |
| `finished_at` | Χρόνος ολοκλήρωσης της παραγγελίας· το όνομα του πεδίου δεν είναι `paid_at`                                      |

Η πλήρης απόκριση ενδέχεται να περιλαμβάνει πρόσθετα πεδία ανάλογα με τη μέθοδο πληρωμής. Οι πελάτες πρέπει να τα διαβάζουν όπως απαιτείται και να αποφεύγουν πάντοτε την καταγραφή ευαίσθητων metadata στην πλήρη απόκριση.

## Χειρισμός σφαλμάτων

- `404`: Το ID παραγγελίας δεν υπάρχει.
- `403`: Υπάρχει σύνδεση, αλλά δεν είναι ο κάτοχος της παραγγελίας.
- Τα ανώνυμα αιτήματα δεν επιστρέφουν `401`· λαμβάνουν μόνο την ελάχιστη δημόσια προβολή.

## Ακύρωση τιμολογίου με πιστωτικό και νέα αίτηση

Μέσω του `GET /api/v1/orders/{order_id}/invoice/` μπορείτε να ανακτήσετε το τρέχον τιμολόγιο της παραγγελίας. Μετά την υποβολή της αυτόματης ακύρωσης με πιστωτικό, το τιμολόγιο παραμένει `Issued` και το `red_state` υποδεικνύει την πρόοδο της ακύρωσης με πιστωτικό· η επιτυχής υποβολή δεν ισοδυναμεί με ολοκλήρωση της ακύρωσης. Κατά την αναμονή επιβεβαίωσης, την έκδοση πιστωτικού τιμολογίου ή την αρχειοθέτηση, η παραγγελία δεν μπορεί να υποβάλει ξανά αίτηση για τιμολόγιο.

Όταν ο διαχειριστής αιτείται ακύρωση με πιστωτικό λόγω σφάλματος σε στοιχεία τιμολόγησης, όπως η επωνυμία ή ο φορολογικός αριθμός, ο λόγος ακύρωσης με πιστωτικό είναι «σφάλμα τιμολόγησης»· η αυτόματη ακύρωση με πιστωτικό που ενεργοποιείται από επιστροφή χρημάτων της παραγγελίας εξακολουθεί να χρησιμοποιεί το «διακοπή υπηρεσίας».

Μετά την επιτυχή έκδοση και αρχειοθέτηση του πιστωτικού τιμολογίου, το αρχικό τιμολόγιο γίνεται `Voided` και μόνο τότε η παραγγελία μπορεί να υποβάλει νέα αίτηση. Το αρχικό τιμολόγιο μπορεί να προβληθεί στο ιστορικό τιμολογίων. Εάν η ακύρωση με πιστωτικό αποτύχει ή το αποτέλεσμα εκκρεμεί επαλήθευση, θα χειριστεί τον έλεγχο το οικονομικό τμήμα και η παραγγελία δεν θα απαλλαγεί πρόωρα από τον περιορισμό τιμολόγησης. Τα χειροκίνητα εκδοθέντα τιμολόγια πρέπει πρώτα να ακυρωθούν ή να πιστωθούν στο φορολογικό ή τιμολογιακό σύστημα και στη συνέχεια να επιβεβαιωθούν από το οικονομικό τμήμα στην πλατφόρμα.
