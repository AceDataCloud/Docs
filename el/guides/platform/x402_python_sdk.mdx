Το Python SDK είναι κατάλληλο για υπηρεσίες backend, εργασίες δεδομένων, αυτοματοποιημένους πράκτορες και σενάρια μαζικής επεξεργασίας. `acedatacloud` είναι υπεύθυνο για τις κλήσεις API, ενώ το `acedatacloud-x402` είναι υπεύθυνο για την υπογραφή του αιτήματος `PAYMENT-SIGNATURE`.

Διευθύνσεις πηγαίου κώδικα και πακέτου:

- Αποθετήριο SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Αποθετήριο X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- PyPI SDK: [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)
- PyPI X402 Client: [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)

## Εγκατάσταση Εξαρτήσεων

```bash
pip install acedatacloud acedatacloud-x402
```

Αν θέλετε να χρησιμοποιήσετε το `upto`, θα χρειαστεί να καλέσετε μία φορά το Permit2 approve CLI, το οποίο εξαρτάται από το `web3`:

```bash
pip install 'acedatacloud-x402[cli]'
```

Έξοδος εγκατάστασης και ελέγχου εισαγωγής σε καθαρό Python venv:

```text
acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
approve-permit2  One-time ERC-20 approve(Permit2, amount) needed before signing upto payments.
```

Επεξήγηση αποτελεσμάτων:

- Τα `acedatacloud` και `acedatacloud-x402` μπορούν να εγκατασταθούν και να εισαχθούν από το PyPI.
- Το `pip install 'acedatacloud-x402[cli]'` θα περιλαμβάνει το CLI `approve-permit2`, το οποίο χρησιμοποιείται για την προεξουσιοδότηση του `upto`.

## Παράδειγμα Base ή SKALE

Το παρακάτω παράδειγμα δεν απαιτεί API Token. Το ιδιωτικό κλειδί του πορτοφολιού υπογράφεται τοπικά και δεν αποστέλλεται στην Ace Data Cloud.

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)

print(res["choices"][0]["message"]["content"])
```

Το τρέχον SDK Python επιστρέφει ένα `dict`, οπότε το παράδειγμα χρησιμοποιεί το `res["choices"][0]["message"]["content"]`. Μην υποθέτετε απευθείας ότι έχει σίγουρα την ιδιότητα `.choices`.

Αποτέλεσμα εκτέλεσης κλήσης SKALE:

```text
payer 0xd0479FA9FD8C678303d477433d24C15e3723CC1C
elapsed_ms 4786
content ADC_PY_SDK_X402_OK
id chatcmpl-DlcWajqAHOop3iebmO19XRfT5bTPz
```

Επεξήγηση αποτελεσμάτων:

- Το πρόγραμμα ολοκλήρωσε την ανάλυση 402, την υπογραφή `PAYMENT-SIGNATURE` και την επαναλαμβανόμενη αίτηση.
- `content ADC_PY_SDK_X402_OK` είναι η σταθερή συμβολοσειρά που επιστρέφει το μοντέλο, υποδεικνύοντας ότι το αίτημα έχει περάσει μέσω του X402 πληρωμής στην στοχοθετημένη API.
- `id chatcmpl-DlcWajqAHOop3iebmO19XRfT5bTPz` είναι το ID της απάντησης chat completion αυτή τη φορά.

Όταν χρησιμοποιείτε SKALE, χρειάζεται μόνο να αλλάξετε το όνομα του δικτύου:

```python
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="skale",
        evm_signer=signer,
    )
)
```

## Παράδειγμα Solana

Η Solana χρησιμοποιεί κωδικοποίηση base58 για το μυστικό κλειδί:

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import SolanaKeypairSigner, create_x402_payment_handler

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="solana",
        solana_signer=SolanaKeypairSigner.from_base58(os.environ["SOLANA_SECRET_KEY"]),
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

Η διαδρομή Solana θα κατασκευάσει και θα υποβάλει τη συναλλαγή SPL USDC `TransferChecked`, και στη συνέχεια θα τοποθετήσει την υπογραφή της συναλλαγής στο envelope `PAYMENT-SIGNATURE`.

Η επαναλαμβανόμενη πληρωμή Solana έχει επιστρέψει HTTP 200 και `ADC_SOLANA_E2E_OK` στην παραγωγική API. Αυτή η δημόσια RPC ερώτηση συνάντησε περιορισμούς, δεν επιβεβαίωσε σταθερά την υπογραφή στην αλυσίδα. Για συμφωνία, παρακαλώ χρησιμοποιήστε τη δική σας Solana RPC για να ελέγξετε αυτή τη συναλλαγή.

## Async Πελάτης

Ο ίδιος χειριστής πληρωμών μπορεί να χρησιμοποιηθεί για το `AsyncAceDataCloud`:

```python
import os

from acedatacloud import AsyncAceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AsyncAceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = await client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

## Χρήση `upto` για Μετρήσεις

Το πραγματικό κόστος των API όπως η ολοκλήρωση συνομιλιών και οι κλήσεις μοντέλου μπορεί να χρειαστεί να περιμένετε μέχρι να ολοκληρωθεί η απάντηση για να το γνωρίζετε. Σε αυτή την περίπτωση, η API μπορεί να επιστρέψει ταυτόχρονα `exact` και `upto`. Αν θέλετε να προτιμήσετε τη χρήση του `upto`:

```python
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
        prefer_scheme="upto",
    )
)
```

Αποτέλεσμα εκτέλεσης προγράμματος Base `upto`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
settlement tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
settled value 3 atomic USDC
```

Επιβεβαίωση στην αλυσίδα:

```text
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
transfer value 3 atomic USDC
```

Επεξήγηση αποτελεσμάτων:

- `content ADC_BASE_UPTO_OK` υποδεικνύει ότι το αίτημα έχει πραγματικά εισέλθει στην API του μοντέλου.
- `settled value 3 atomic USDC` υποδεικνύει ότι το `upto` έχει εκκαθαριστεί με βάση την πραγματική χρήση, και όχι με την πλήρη ανώτατη τιμή.
- Το `settlement tx` μπορεί να ανοίξει στο BaseScan, αποθηκεύστε το tx hash, τον πληρωτή, το completion id και την περίληψη του αιτήματος για συμφωνία.

Η χρήση του `upto` απαιτεί την εξουσιοδότηση ενός ανώτατου ορίου μέσω του Permit2, και το πραγματικό ποσό εκκαθάρισης δεν μπορεί να υπερβεί αυτό το ανώτατο όριο. Πριν από την πρώτη χρήση, απαιτείται να κάνετε μία `approve(Permit2, amount)` για το USDC στην στοχοθετημένη αλυσίδα.

Μέθοδος CLI:

```bash
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Μέθοδος προγράμματος:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Αυτή η helper είναι ιδεατή. Αν η allowance είναι ήδη επαρκής, θα επιστρέψει `{"skipped": true}`, χωρίς να επαναλάβει τη συναλλαγή στην αλυσίδα.

## Χαμηλού Επιπέδου Υπογραφή
Αν δεν χρησιμοποιείτε το SDK, μπορείτε να καλέσετε απευθείας τις χαμηλού επιπέδου συναρτήσεις υπογραφής:

```python
import base64
import json

from acedatacloud_x402 import EVMAccountSigner, sign_evm_payment

envelope = sign_evm_payment(requirement, EVMAccountSigner.from_private_key("0x..."))
x_payment = base64.b64encode(json.dumps(envelope, separators=(",", ":")).encode()).decode()
```

Οι χαμηλού επιπέδου συναρτήσεις είναι κατάλληλες για δοκιμές, επίπεδα μεσολάβησης, ενσωμάτωσης πύλης ή μη επίσημα SDK. Ο κανονικός επιχειρηματικός κώδικας προτιμά να χρησιμοποιεί το `create_x402_payment_handler`.
