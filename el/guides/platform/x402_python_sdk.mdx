Το Python SDK είναι κατάλληλο για backend υπηρεσίες, εργασίες δεδομένων, αυτοματοποιημένα Agent και σενάρια μαζικής επεξεργασίας. Το `acedatacloud` είναι υπεύθυνο για τις κλήσεις API, ενώ το `acedatacloud-x402` είναι υπεύθυνο για την υπογραφή του request header `PAYMENT-SIGNATURE`.

Διευθύνσεις πηγαίου κώδικα και πακέτων:

- Αποθετήριο SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Αποθετήριο X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- PyPI SDK: [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)
- PyPI X402 Client: [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)

## Εγκατάσταση εξαρτήσεων

```bash
pip install acedatacloud acedatacloud-x402
```

Αν θέλετε να χρησιμοποιήσετε το `upto`, πρέπει επίσης να καλέσετε μία φορά το Permit2 approve CLI, το οποίο εξαρτάται από το `web3`:

```bash
pip install 'acedatacloud-x402[cli]'
```

Έξοδος ελέγχου εγκατάστασης και εισαγωγής σε καθαρό Python venv:

```text
acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
approve-permit2  One-time ERC-20 approve(Permit2, amount) needed before signing upto payments.
```

Επεξήγηση αποτελεσμάτων:

- Τα `acedatacloud` και `acedatacloud-x402` μπορούν και τα δύο να εγκατασταθούν και να εισαχθούν από το PyPI.
- Το `pip install 'acedatacloud-x402[cli]'` περιλαμβάνει το CLI `approve-permit2`, για την προαπαιτούμενη εξουσιοδότηση του `upto`.

## Παράδειγμα Base

Το παρακάτω παράδειγμα δεν απαιτεί API Token. Το ιδιωτικό κλειδί του πορτοφολιού χρησιμοποιείται μόνο για τοπική υπογραφή και δεν αποστέλλεται στο Ace Data Cloud.

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)

print(res["choices"][0]["message"]["content"])
```

Το Python SDK επιστρέφει επί του παρόντος `dict`, επομένως το παράδειγμα χρησιμοποιεί `res["choices"][0]["message"]["content"]`. Μην υποθέτετε απευθείας ότι διαθέτει οπωσδήποτε ιδιότητα `.choices`.

## Παράδειγμα Solana

Το Solana χρησιμοποιεί secret key κωδικοποιημένο σε base58:

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import SolanaKeypairSigner, create_x402_payment_handler

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="solana",
        solana_signer=SolanaKeypairSigner.from_base58(os.environ["SOLANA_SECRET_KEY"]),
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

Η διαδρομή Solana κατασκευάζει και υποβάλλει συναλλαγή SPL USDC `TransferChecked`, και στη συνέχεια τοποθετεί την υπογραφή της συναλλαγής στο envelope `PAYMENT-SIGNATURE`.

Το Solana paid retry έχει ήδη επιστρέψει HTTP 200 και `ADC_SOLANA_E2E_OK` στο production API. Το δημόσιο RPC query αυτής της φοράς αντιμετώπισε περιορισμό ρυθμού, επομένως δεν επιβεβαιώθηκε σταθερά το on-chain signature· όταν απαιτείται συμφωνία στοιχείων, χρησιμοποιήστε το δικό σας Solana RPC για να ελέγξετε τη συγκεκριμένη συναλλαγή.

## Async πελάτης

Ο ίδιος payment handler μπορεί να χρησιμοποιηθεί με το `AsyncAceDataCloud`:

```python
import os

from acedatacloud import AsyncAceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AsyncAceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = await client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

## Χρήση της μεταγενέστερης μέτρησης `upto`

Το πραγματικό κόστος API όπως οι συμπληρώσεις συνομιλίας και οι κλήσεις μοντέλων μπορεί να γίνει γνωστό μόνο αφού ολοκληρωθεί η απόκριση. Σε αυτήν την περίπτωση, το API μπορεί να επιστρέψει ταυτόχρονα `exact` και `upto`. Αν θέλετε να προτιμήσετε το `upto`:

```python
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
        prefer_scheme="upto",
    )
)
```

Αποτέλεσμα εκτέλεσης του προγράμματος Base `upto`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
settlement tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
settled value 3 atomic USDC
```

On-chain επιβεβαίωση:

```text
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
transfer value 3 atomic USDC
```

Επεξήγηση αποτελεσμάτων:

- Το `content ADC_BASE_UPTO_OK` δείχνει ότι το αίτημα εισήλθε πραγματικά στο model API.
- Το `settled value 3 atomic USDC` δείχνει ότι το `upto` διακανονίζεται σύμφωνα με την πραγματική χρήση, αντί να χρεώνει ολόκληρο το ανώτατο όριο.
- Το `settlement tx` μπορεί να ανοίξει στο BaseScan· κατά τη συμφωνία στοιχείων, αποθηκεύστε το tx hash, το payer, το completion id και τη σύνοψη του αιτήματος.

Το `upto` χρησιμοποιεί εξουσιοδότηση Permit2 για ένα ανώτατο όριο και το πραγματικό ποσό διακανονισμού δεν μπορεί να υπερβαίνει αυτό το όριο. Πριν από την πρώτη χρήση, πρέπει να εκτελέσετε μία φορά `approve(Permit2, amount)` για το USDC στην αλυσίδα προορισμού.

Τρόπος CLI:

```bash
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Τρόπος προγράμματος:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Αυτό το helper είναι ιδιοσυγκρασιακό. Αν το allowance είναι ήδη επαρκές, θα επιστρέψει `{"skipped": true}` και δεν θα στείλει επαναλαμβανόμενα on-chain συναλλαγές.

## Υπογραφή χαμηλού επιπέδου

Αν δεν χρησιμοποιείτε το SDK, μπορείτε επίσης να καλέσετε απευθείας τη συνάρτηση υπογραφής χαμηλού επιπέδου:

```python
import base64
import json

from acedatacloud_x402 import EVMAccountSigner, sign_evm_payment

envelope = sign_evm_payment(requirement, EVMAccountSigner.from_private_key("0x..."))
x_payment = base64.b64encode(json.dumps(envelope, separators=(",", ":")).encode()).decode()
```

Οι συναρτήσεις χαμηλού επιπέδου είναι κατάλληλες για δοκιμές, επίπεδα proxy, ενσωμάτωση gateway ή μη επίσημα SDK. Για συνηθισμένο επιχειρηματικό κώδικα, προτιμήστε το `create_x402_payment_handler`.
