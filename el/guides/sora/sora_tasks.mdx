Η κύρια λειτουργία του Sora Tasks API είναι να ελέγχει την κατάσταση εκτέλεσης ενός έργου μέσω της εισαγωγής του ID έργου που έχει παραχθεί από το Sora Videos Generation API.

Αυτό το έγγραφο θα περιγράψει λεπτομερώς τις οδηγίες σύνδεσης του Sora Tasks API, βοηθώντας σας να ενσωματώσετε εύκολα και να αξιοποιήσετε πλήρως τη δύναμη αυτού του API. Μέσω του Sora Tasks API, μπορείτε εύκολα να ελέγξετε την κατάσταση εκτέλεσης των έργων του Sora Videos Generation API.

## Διαδικασία Αίτησης

Για να χρησιμοποιήσετε το Sora Tasks API, πρέπει πρώτα να επισκεφθείτε τη σελίδα αίτησης [Sora Videos Generation API](https://platform.acedata.cloud/documents/99a24421-2e22-4028-8201-e19cb834b67e) για να ζητήσετε την αντίστοιχη υπηρεσία και στη συνέχεια να αντιγράψετε το ID έργου του Sora Videos Generation API, όπως φαίνεται στην εικόνα:

<p><img src="https://cdn.acedata.cloud/za62pb.png" width="500" class="m-auto"></p>

Τέλος, επισκεφθείτε τη σελίδα Tasks API [Sora Tasks API](https://platform.acedata.cloud/documents/c9d81bad-9064-4796-86b6-4fb43cc93a16) για να ζητήσετε την αντίστοιχη υπηρεσία. Αφού εισέλθετε στη σελίδα, κάντε κλικ στο κουμπί «Acquire», όπως φαίνεται στην εικόνα:

![Σελίδα Αίτησης](https://cdn.acedata.cloud/rci31i.png)

Εάν δεν έχετε συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη [σελίδα σύνδεσης](https://platform.acedata.cloud) για να σας προσκαλέσει να εγγραφείτε και να συνδεθείτε. Μετά την εγγραφή και σύνδεση, θα επιστρέψετε αυτόματα στη τρέχουσα σελίδα.

Κατά την πρώτη αίτηση, θα λάβετε δωρεάν πιστώσεις, ώστε να μπορείτε να χρησιμοποιήσετε δωρεάν αυτό το API.

## Παράδειγμα Αίτησης

Το Sora Tasks API μπορεί να χρησιμοποιηθεί για να ελέγξει τα αποτελέσματα του Sora Videos Generation API. Για πληροφορίες σχετικά με το πώς να χρησιμοποιήσετε το Sora Videos Generation API, ανατρέξτε στο έγγραφο [Sora Videos Generation API](https://platform.acedata.cloud/documents/sora-videos-integration).

Θα χρησιμοποιήσουμε ένα παράδειγμα με το ID έργου που επιστρέφει η υπηρεσία Sora Videos Generation API. Ας υποθέσουμε ότι έχουμε ένα ID έργου: b8976e18-32dc-4718-9ed8-1ea090fcb6ea, και στη συνέχεια θα δείξουμε πώς να το χρησιμοποιήσουμε περνώντας ένα ID έργου.

### Ρύθμιση Κεφαλίδων Αίτησης και Σώματος Αίτησης

**Request Headers** περιλαμβάνουν:

- `accept`: καθορίζει ότι θα δεχθείτε την απάντηση σε μορφή JSON, εδώ συμπληρώνεται ως `application/json`.
- `authorization`: το κλειδί για την κλήση του API, το οποίο μπορείτε να επιλέξετε απευθείας από το αναπτυσσόμενο μενού μετά την αίτηση.

**Request Body** περιλαμβάνει:

- `id`: το ID του έργου που έχει ανέβει.
- `action`: ο τρόπος λειτουργίας του έργου.

### Παράδειγμα Κώδικα

Μπορείτε να παρατηρήσετε ότι στη δεξιά πλευρά της σελίδας έχουν παραχθεί αυτόματα διάφορες γλώσσες κώδικα, όπως φαίνεται στην εικόνα:

Ορισμένα παραδείγματα κώδικα είναι τα εξής:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/sora/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/sora/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Διαχείριση σφαλμάτων

Κατά την κλήση του API, εάν προκύψει σφάλμα, το API θα επιστρέψει τον αντίστοιχο κωδικό σφάλματος και πληροφορίες. Για παράδειγμα:

- `400 token_mismatched`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`: Κακή αίτηση, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`: Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διαπιστευτήριο εξουσιοδότησης.
- `429 too_many_requests`: Πάρα πολλές αιτήσεις, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`: Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.
