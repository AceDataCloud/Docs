Η κύρια λειτουργία του Fish Tasks API είναι η αναζήτηση της κατάστασης εκτέλεσης μιας εργασίας μέσω της εισαγωγής του ID εργασίας που δημιουργείται από το Fish Audios Generation API.

Αυτό το έγγραφο θα παρουσιάσει λεπτομερώς τις οδηγίες ενσωμάτωσης του Fish Tasks API, βοηθώντας σας να ενσωματώσετε εύκολα και να αξιοποιήσετε πλήρως τις ισχυρές λειτουργίες αυτού του API. Μέσω του Fish Tasks API, μπορείτε εύκολα να υλοποιήσετε την αναζήτηση της κατάστασης εκτέλεσης εργασιών του Fish Audios Generation API.

## Διαδικασία αίτησης

Για να χρησιμοποιήσετε το Fish Audios Generation API, αποκτήστε πρώτα το API Token σας από την [κονσόλα Ace Data Cloud](https://platform.acedata.cloud/console/applications) και κρατήστε το για χρήση.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Εάν δεν έχετε ακόμη συνδεθεί ή εγγραφεί, θα μεταφερθείτε αυτόματα στη σελίδα σύνδεσης, όπου θα σας προσκαλέσει να εγγραφείτε και να συνδεθείτε. Μετά την ολοκλήρωση, θα επιστρέψετε αυτόματα στην τρέχουσα σελίδα.

**Ένα API Token μπορεί να καλέσει όλες τις υπηρεσίες της πλατφόρμας, χωρίς να χρειάζεται ξεχωριστή αίτηση για κάθε υπηρεσία.** Με την πρώτη αίτηση θα λάβετε δωρεάν υπόλοιπο για δωρεάν δοκιμή· όταν το υπόλοιπο δεν επαρκεί, μπορείτε να ανανεώσετε το γενικό υπόλοιπο στην [κονσόλα](https://platform.acedata.cloud/console/coin).

> 📘 Πλήρης τεκμηρίωση: [Fish Audios Generation API →](https://platform.acedata.cloud/documents/fish-tts)

## Παράδειγμα αιτήματος

Το Fish Tasks API μπορεί να χρησιμοποιηθεί για την αναζήτηση των αποτελεσμάτων του Fish Audios Generation API. Για τον τρόπο χρήσης του Fish Audios Generation API, ανατρέξτε στην τεκμηρίωση [Fish Videos Generation API ](https://platform.acedata.cloud/documents/fish-tts-integration).

Θα χρησιμοποιήσουμε ως παράδειγμα ένα ID εργασίας που επιστρέφεται από την υπηρεσία Fish Audios Generation API, για να δείξουμε πώς να χρησιμοποιήσετε αυτό το API. Ας υποθέσουμε ότι έχουμε ένα ID εργασίας: 2725a2d3-f87e-4905-9c53-9988d5a7b2f5, στη συνέχεια θα δείξουμε πώς μέσω της εισαγωγής ενός ID εργασίας.

### Ρύθμιση κεφαλίδων αιτήματος και σώματος αιτήματος

Τα **Request Headers** περιλαμβάνουν:

- `accept`: καθορίζει την αποδοχή αποτελεσμάτων απόκρισης σε μορφή JSON, εδώ συμπληρώνεται ως `application/json`.
- `authorization`: το κλειδί για την κλήση του API, μετά την αίτηση μπορείτε να το επιλέξετε απευθείας από την αναπτυσσόμενη λίστα.

Το **Request Body** περιλαμβάνει:

- `id`: το ID της μεταφορτωμένης εργασίας.
- `action`: ο τρόπος ενέργειας στην εργασία.

Οι ρυθμίσεις εμφανίζονται στο παρακάτω σχήμα:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/fish/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2725a2d3-f87e-4905-9c53-9988d5a7b2f5",
  "action": "retrieve"
}'
```


Το επιστρεφόμενο αποτέλεσμα περιέχει πολλαπλά πεδία. Το πεδίο `request` είναι το request body κατά την εκκίνηση της εργασίας, ενώ το πεδίο `response` είναι το response body που επιστρέφεται μετά την ολοκλήρωση της εργασίας. Η περιγραφή των πεδίων είναι η εξής.

- `id`, το ID που δημιουργεί αυτή την εργασία, χρησιμοποιείται για τη μοναδική αναγνώριση αυτής της εργασίας δημιουργίας.
- `request`, οι πληροφορίες αιτήματος στην εργασία αναζήτησης.
- `response`, οι πληροφορίες επιστροφής στην εργασία αναζήτησης· κατά την τελική επιτυχία, το `cost.amount` σε αυτό είναι τα Credits που αφαιρέθηκαν πραγματικά για αυτή τη σύνθεση.
- `created_at`, η ώρα δημιουργίας της εργασίας, Unix timestamp (δευτερόλεπτα, κινητής υποδιαστολής).
- `started_at`, η ώρα έναρξης εκτέλεσης της εργασίας, Unix timestamp (δευτερόλεπτα, κινητής υποδιαστολής).
- `finished_at`, η ώρα ολοκλήρωσης της εργασίας, Unix timestamp (δευτερόλεπτα, κινητής υποδιαστολής). Αυτό το πεδίο δεν επιστρέφεται όταν η εργασία δεν έχει ολοκληρωθεί.
- `elapsed`, ο χρόνος εκτέλεσης της εργασίας, σε δευτερόλεπτα (κινητής υποδιαστολής, με διατήρηση 3 δεκαδικών ψηφίων). Αυτό το πεδίο δεν επιστρέφεται όταν η εργασία δεν έχει ολοκληρωθεί.

## Χειρισμός σφαλμάτων

Κατά την κλήση του API, εάν προκύψει σφάλμα, το API θα επιστρέψει τον αντίστοιχο κωδικό και μήνυμα σφάλματος. Για παράδειγμα:

- `400 token_mismatched`：Εσφαλμένο αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `400 api_not_implemented`：Εσφαλμένο αίτημα, πιθανώς λόγω ελλιπών ή μη έγκυρων παραμέτρων.
- `401 invalid_token`：Μη εξουσιοδοτημένο, μη έγκυρο ή ελλιπές διακριτικό εξουσιοδότησης.
- `429 too_many_requests`：Πάρα πολλά αιτήματα, έχετε υπερβεί το όριο ρυθμού.
- `500 api_error`：Εσωτερικό σφάλμα διακομιστή, κάτι πήγε στραβά στον διακομιστή.
