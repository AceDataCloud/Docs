`POST /suno/availability` prihvata jedan ID resursa. Za proveru pesme prosledite `audio_id`, za proveru glasa prosledite `persona_id`, jedan od njih je obavezan. Provera se završava sinhrono, zahteva API Token i trenutno ne naplaćuje Credits.

## Zahtev

`audio_id` dolazi iz završenog zadatka pesme i može se koristiti za proveru pre nastavka ili obrade pesme.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

`persona_id` dolazi iz rezultata kreiranja glasa. Koristeći originalnu aplikaciju i identitet pozivaoca, pošaljite sledeće telo zahteva na liniji za kreiranje koja podržava upite za glasove.

```json
{"persona_id":"33333333-3333-4333-8333-333333333333"}
```

## Odgovor

Obe vrste zahteva koriste isti uspešan odgovor. `data.id` je ID resursa za ovaj upit.

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

`available: true` označava da je ova provera dobila pozitivne dokaze. Za glasove, provera će potvrditi pripadnost kreiranja i potvrditi da je povezani nalog trenutno prijavljen kao online. Stvarni rezultat generisanja i dalje zavisi od zadatka generisanja.

Privatni klonirani glasovi kreirani putem `/suno/voices` zavise od naloga za kreiranje. Kada se potvrdi da je taj nalog trenutno offline, interfejs vraća HTTP 200, a primer `data` je sledeći.

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

Klijent može označiti taj glas kao trenutno nedostupan i proveriti ponovo kasnije.

Kada potvrda nije moguća, vraća se HTTP 503 i `availability_unknown`, na primer kada resurs nije pronađen, starom zapisu nedostaje linija za kreiranje ili upit istekne. Stilovi javnih pevača mogu se koristiti između naloga, a kada je nalog za kreiranje offline, takođe se vraća 503. Upiti za pesme i dalje vraćaju `available: true` samo kada je dostupnost potvrđena.

Svaki zahtev šalje samo jedan važeći UUID. Sve linije vraćaju HTTP 400 za zahteve koji sadrže oba ID-ja ili kojima nedostaju oba ID-ja. Linije koje podržavaju samo upite za pesme vraćaju HTTP 400 kada prime zahtev koji sadrži samo `persona_id`. Ako naiđete na HTTP 429, smanjite učestalost upita.
