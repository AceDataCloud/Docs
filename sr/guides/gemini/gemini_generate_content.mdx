Google Gemini je veoma moćan AI sistem za razgovor, koji može da generiše tečne i prirodne odgovore za nekoliko sekundi unosom upita. Ovaj dokument uglavnom opisuje način korišćenja Gemini Generate Content API-ja, što je Google-ov zvanični nativni API format, koji podržava dve krajnje tačke: `generateContent` i `streamGenerateContent`.

## Razlika u odnosu na Chat Completions API

Gemini Generate Content API koristi Google-ov zvanični nativni format zahteva (polje `contents`), umesto formata kompatibilnog sa OpenAI-jem (polje `messages`). Ako već koristite Google Gemini SDK ili ste upoznati sa zvaničnim API formatom, možete direktno koristiti ovaj API bez izmene formata zahteva.

## Trenutno podržani opseg

Interfejs prihvata tekstualne, slikovne, video i audio ulaze (`inlineData` ili `fileData`), konfiguraciju razmišljanja i deklaracije prilagođenih funkcija. Za nativna polja kao što su audio izlaz, ugrađeni alati i eksplicitno keširanje konteksta još ne postoji garancija jedinstvene dostupnosti; oslonite se na stvarni odgovor konkretnog modela.

Kada koristite `fileData.fileUri` za slanje datoteka kao što je audio, osigurajte da datoteka može direktno da se pristupi putem HTTPS-a, da ne zavisi od stanja prijave i da period važenja potpisanog linka pokriva celokupno vreme obrade zahteva. Neprotočna audio analiza vraća rezultat tek nakon što model završi obradu, što može trajati duže od 90 sekundi; klijent treba da postavi dovoljno dugo ukupno vremensko ograničenje prema veličini datoteke i poslovnom scenariju, kako bi se izbeglo prekidanje veze dok server i dalje obrađuje zahtev.

## Proces prijave

Pre korišćenja Gemini Generate Content API-ja, prvo posetite stranicu [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api), kliknite na dugme „Preuzmi“ da biste dobili akreditive potrebne za zahtev.

Ako još niste prijavljeni ili registrovani, automatski ćete biti preusmereni na stranicu za prijavu. Prva prijava uključuje besplatni kredit.

## Osnovna upotreba

### Non-Streaming (neprotočno)

Pošaljite POST zahtev na `/v1beta/models/{model}:generateContent`:

> **Napomena**: flash iz serije `gemini-3.x` su modeli za razmišljanje, koji će prvo potrošiti reasoning tokene; postavite `generationConfig.maxOutputTokens` na 512 ili više, u suprotnom može biti vraćen samo prazan sadržaj.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Primer vraćenog rezultata:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Token polja u `usageMetadata` naplaćuju se prema nativnoj Gemini semantici:

- `promptTokenCount` uključuje `cachedContentTokenCount`, deo pogođen iz keša računa se po ceni čitanja iz keša i neće se ponovo računati kao običan ulaz.
- `promptTokensDetails` i `cacheTokensDetails` biće normalizovani kao `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` i odgovarajuće stavke `cached_*` pod `usage.prompt_tokens_details`. Ove vrednosti su uključene u `prompt_tokens` odnosno `cached_tokens`; različiti modaliteti se preračunavaju samo prema sopstvenim cenama i neće biti dvostruko naplaćeni.
- I `candidatesTokenCount` i `thoughtsTokenCount` računaju se po ceni izlaznih tokena.
- `toolUsePromptTokenCount` je nezavisan token za ulaz alata i računa se po ceni ulaznih tokena.

Ace Data Cloud dodatno vraća normalizovani objekat `usage`, pri čemu se trošak ovog poziva ujednačeno čita iz `usage.cost` kroz protokole modela. `cost` je opciona pretpregledna procena troška; kada pregled cene privremeno nije dostupan, odgovor modela će i dalje biti normalno vraćen, ali možda neće sadržati ovo polje. Konačni račun zavisi od evidencije potrošnje.

### Streaming (protočno)

Pošaljite POST zahtev na `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

Protočni odgovor će postepeno vraćati sadržaj u SSE (Server-Sent Events) formatu. Međudogađaji obično sadrže samo inkrementalni sadržaj; završni događaj koji sadrži autoritativnu potrošnju uključivaće `usageMetadata` i normalizovani `usage`, a trošak se i dalje nalazi u `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

Zatvaranje veze označava kraj toka; nativni Gemini tok ne šalje `data: [DONE]`. Ako završni pregled cene privremeno nije dostupan, `usage` će i dalje vratiti potrošnju tokena, ali će izostaviti `cost`.

### Interno razmišljanje i sažetak razmišljanja

Interno razmišljanje modela i vraćanje sažetka razmišljanja pozivaocu su dve nezavisne postavke:

- `thinkingBudget` ili `thinkingLevel` kontrolišu budžet ili dubinu internog razmišljanja modela; podržana polja i vrednosti zavise od modela.
- `includeThoughts` kontroliše da li se vraća sažetak razmišljanja, podrazumevano je `false`. Kada se ovo polje izostavi ili se prosledi `false`, ni obični JSON ni SSE strimovani odgovor neće vratiti tekst označen kao `thought: true`; ovaj tekst se zadržava samo kada se eksplicitno prosledi logička vrednost `true`.

Kada zahtev nema postavljen `includeThoughts`, interfejs podrazumevano prosleđuje `false` modelima za generisanje koji podržavaju konfiguraciju razmišljanja, kako bi se izbeglo traženje nepotrebnih sažetaka; vrednosti koje klijent eksplicitno prosledi, kao i budžet i nivo razmišljanja, zadržavaju se. Poznatom modelu `gemini-2.5-flash-image`, koji ne podržava konfiguraciju razmišljanja, ovo polje neće biti automatski dodato, a ni zahtevima `countTokens` neće biti dodata konfiguracija generisanja.

Isključivanje sažetaka ne znači isključivanje internog razmišljanja, niti garantuje smanjenje tokena internog razmišljanja. Ako odgovor i dalje sadrži netraženi tekst razmišljanja, obični JSON i SSE izlazi će ga dodatno filtrirati, zadržavajući normalan odgovor, potpise i stvarnu potrošnju.

Kada je potrebno videti sažetak, eksplicitno ga uključite na sledeći način. Kada model ne generiše dostupan sažetak, možda neće biti teksta razmišljanja čak ni kada je uključen:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` je šifrovano stanje potrebno za naredne runde, a ne tekst sažetka razmišljanja, i njime ne upravlja prekidač `includeThoughts`. Potpis se može nalaziti na normalnom odgovoru, pozivu funkcije ili praznom tekstualnom Part-u; pri filtriranju teksta razmišljanja, potpis i druga polja istog Part-a se zadržavaju, pa odgovor i dalje može sadržati Part-ove koji nose samo potpis i imaju prazan tekst. Pri ručnom održavanju istorije u više rundi, treba zadržati redosled ovih Part-ova i položaj potpisa, bez pomeranja potpisa ili njihovog spajanja.

`usageMetadata` i `usage` i dalje beleže stvarnu potrošnju. Skriveni sažeci ne postavljaju `thoughtsTokenCount` na nulu; naplata se i dalje obračunava prema stvarnoj potrošnji i važećim pravilima određivanja cena.

Pogledajte Google-ovo zvanično [objašnjenje razmišljanja i sažetaka razmišljanja](https://firebase.google.com/docs/ai-logic/thinking) i [pravila za potpise razmišljanja](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

## Bezbednosne postavke

Filtriranje sadržaja se može kontrolisati putem `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Obrada grešaka

| HTTP statusni kod | Značenje             |
| -------- | -------------- |
| 400      | Nevažeći parametri zahteva |
| 401      | Autentifikacija nije uspela, proverite Token |
| 403      | Sadržaj je presretnut bezbednosnim filterom |
| 429      | Zahtevi su previše česti |
| 500      | Interna greška servera |
