Ace Data Cloud X402 trenutno koristi USDC poravnanje i podržava dve vrste lanaca: EVM i Solana. Metode potpisivanja, adrese sredstava, gas ponašanje i scenariji primene razlikuju se između mreža, pa je potrebno izabrati mrežu pre integracije.

## Identifikatori mreže koriste CAIP-2

`accepts[].network` u x402 v2 je CAIP-2 identifikator, a ne skraćeni naziv poput `base` ili `solana`. Klijent mora porediti mreže prema CAIP-2 stringu:

| Mreža             | CAIP-2 identifikator                       |
| -------------- | ----------------------------------------- |
| Base           | `eip155:8453`                             |
| Solana mainnet | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` |

## Matrica podrške

| Mreža     | scheme  | Sredstvo                  | Metoda potpisivanja                         | Scenario primene                     |
| ------ | ------- | ------------------- | ------------------------------------ | ------------------------ |
| Base   | `exact` | Base USDC           | EIP-3009 `TransferWithAuthorization` | Podrazumevano preporučeno, zrela podrška za novčanike i likvidnost.         |
| Base   | `upto`  | Base USDC + Permit2 | Permit2 `PermitWitnessTransferFrom`  | API-ji sa naknadnim merenjem, poput ćaskanja i modela.          |
| Solana | `exact` | Solana USDC         | SPL `TransferChecked`                | Solana novčanici, Agent ili scenariji on-chain aplikacija. |

`upto` je trenutno dostupan samo na Base-u. Stvarno dostupne stavke zavise od `accepts` koje vraća API. Takođe možete pogledati Facilitator:

```bash
curl https://facilitator.acedata.cloud/supported
```

Povratna vrednost Facilitator `/supported`:

```json
{
  "kinds": [
    { "x402Version": 2, "scheme": "exact", "network": "eip155:8453" },
    {
      "x402Version": 2,
      "scheme": "upto",
      "network": "eip155:8453",
      "extra": { "facilitatorAddress": "0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708" }
    },
    {
      "x402Version": 2,
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "extra": { "feePayer": "3SPm6qbgsDkj24MuR8Ss4sH97fziqyCiqFKDyeVU2igq" }
    }
  ]
}
```

Objašnjenje rezultata:

- `exact` za Base i Solana je put plaćanja fiksnog iznosa.
- Samo Base pruža put naknadnog merenja `upto`, koji zavisi od Permit2 approve.
- `extra.facilitatorAddress` u `upto` stavci je adresa koju klijent treba da upiše u witness prilikom potpisivanja i mora biti ista kao vrednost koju vraća server.

## Base

Base koristi zvanični USDC ugovor:

```text
0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
```

U `exact` šemi, klijent potpisuje EIP-712 `TransferWithAuthorization`. Sadržaj potpisa uključuje:

- `from`: adresu novčanika platioca
- `to`: adresu primaoca Ace Data Cloud
- `value`: iznos ove uplate
- `validAfter` / `validBefore`: vremenski prozor važenja potpisa
- `nonce`: nasumični nonce od 32 bajta

Nakon što Facilitator verifikuje potpis, on će na lancu pozvati USDC `transferWithAuthorization` da završi transfer.

Base je najpreporučenija mreža za zvaničnu integraciju, naročito pogodna za naknadno merenje `upto`, jer su Permit2, USDC i ekosistem novčanika zreliji.

Primer rezultata Base `exact` verifikacije:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
content ADC_BASE_E2E_OK
tx 0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
block 46726299
explorer https://basescan.org/tx/0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
transfer value 95215 atomic USDC
```

Objašnjenje rezultata:

- API paid retry vraća sadržaj modela `ADC_BASE_E2E_OK`.
- On-chain transakcija je dostupna na BaseScan-u, a broj bloka je `46726299`.
- `95215` atomic USDC odgovara `0.095215` USDC, što je stvarni iznos poravnanja za ovaj API poziv.

Rezultat izvršavanja programa za plaćanje porudžbine Base `exact`:

```text
order 78481793-304e-47f7-bc0c-8231aec9cc1e
state Finished
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer value 1200000 atomic USDC
```

Objašnjenje rezultata:

- Konačni status porudžbine na platformi je `Finished`.
- `pay_id` porudžbine je upisan u isti Base hash transakcije.
- `1200000` atomic USDC odgovara `1.2` USDC, što je istorijski stvarno plaćeni iznos za ovu porudžbinu od 10 Credits prema staroj politici; nove porudžbine više ne uživaju dodatni popust za X402 metod plaćanja, a konkretan iznos potpisa zavisi od ovog 402 odgovora.

## Solana

Solana koristi SPL USDC `TransferChecked`. Klijent će konstruisati transakciju transfera, potpisati je i poslati, a zatim staviti potpis transakcije ili serijalizovanu transakciju u `PAYMENT-SIGNATURE` envelope.

Karakteristike Solane:

- koristi Solana wallet adapter ili base58 secret key;
- sredstvo je Solana USDC mint;
- trenutno podržava samo `exact`;
- Facilitator će proveriti mint, destination, authority i amount instrukcije transfera.

Ako se koristi režim wallet fee payer, novčanik će direktno poslati transakciju, a Facilitator je odgovoran za potvrđivanje transakcije i vraćanje rezultata poravnanja.

Primer rezultata Solana `exact` verifikacije:

```text
payer AY2RmGm2zPxB1uKvvF4dKyYdr2VySyL3wcD1MKJZoLRd
HTTP 402 -> HTTP 200
content ADC_SOLANA_E2E_OK
chain signature not confirmed in this run
```

Objašnjenje rezultata:

- paid retry je već vratio HTTP 200, a model je ispisao `ADC_SOLANA_E2E_OK`.
- Pri upitu on-chain signature preko javnog RPC-a može doći do ograničenja broja zahteva.
- Pošto javni RPC upiti mogu biti ograničeni, ovde se ne navodi Solana explorer. Kada je potrebno strogo usklađivanje, koristite sopstveni Solana RPC ili potvrdite potpis transakcije preko evidencije poravnanja na strani platforme.

## Kako odabrati

| Šta želite da uradite        | Preporučena mreža           |
| ------------ | -------------- |
| Brzo pokretanje minimalnog toka     | Base `exact`   |
| Namenjeno običnim Web3 korisnicima | Base           |
| Naknadno merenje za dopunjavanje ćaskanja i slično   | Base `upto`    |
| Solana ekosistemske aplikacije  | Solana `exact` |

Bez obzira na to koji lanac izaberete, nemojte hardkodirati cenu u klijentu. Cenu određuje `accepts[].maxAmountRequired` koji vraća server.

## Dodavanje EVM mreža
Kod podrška je obezbeđena za plaćanja fiksnog iznosa nativnim USDC-om na sledećim mrežama, koja se otvaraju pojedinačno po mreži.
Da li je dostupno zavisi od `accepts` vraćenog putem porudžbine ili API-ja; to ne znači da su sve mreže omogućene u produkciji.

| Mreža        | Alias      | CAIP-2         | Nativni USDC                                 |
| ------------ | ---------- | -------------- | -------------------------------------------- |
| Arbitrum One | `arbitrum` | `eip155:42161` | `0xaf88d065e77c8cC2239327C5EDb3A432268e5831` |

Ove mreže podržavaju samo `exact`, a preciznost valute je 6. Nemojte koristiti premošćeni USDC istog naziva.
Kada koristite zvanični TypeScript/Python X402 Client, možete proslediti skraćeni naziv iz tabele ili CAIP-2 identifikator.
Klijent koristi ID ciljnog lanca za konstruisanje potpisa; novčanik mora podržavati ciljnu mrežu.

Tabela zvanične podrške za Phantom ekstenziju novčanika navodi Arbitrum i Polygon; Optimism i Avalanche
trenutno nisu navedeni u toj tabeli, pa se može koristiti Rabby ili MetaMask koji podržava ciljni lanac. EVM adrese mogu biti iste na različitim lancima,
ali su stanja međusobno nezavisna, a Solana adrese nisu primenljive na EVM USDC.
Pogledajte [tabelu podrške za Phantom novčanik](https://docs.phantom.com/wallet-sdks-overview#chain-support).

### Ulaz za postepeno uvođenje novih mreža

Ulaz za nove lance je podrazumevano skriven. Prilikom pristupanja kontrolnoj tabli ili Studiju, možete koristiti `?features=x402-arbitrum`
da omogućite odgovarajući lanac, a više flagova se odvaja zarezima. Za isključivanje pojedinačnog lanca koristite `?features=-x402-arbitrum`,
a za brisanje lokalnih podešavanja koristite `?features=none`. Prekidači se čuvaju zasebno za svaki domen.
Ponude porudžbina i ponovni pokušaji plaćanja koriste isti prekidač, a server će nezavisno izvršiti proveru; postojeći zapisi o plaćanju i dalje mogu da se pregledaju.
Samo uključivanje flag-a stranice neće omogućiti lanac koji još nije konfigurisan; konkretne mreže na kojima se može platiti i dalje zavise od `accepts` u realnom vremenu.
