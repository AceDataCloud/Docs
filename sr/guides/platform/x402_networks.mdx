Ace Data Cloud X402 trenutno se fokusira na poravnanje u USDC-u i podržava dve vrste lanaca: EVM i Solana. Način potpisivanja, adrese sredstava, ponašanje gas-a i primenljivi scenariji razlikuju se među mrežama, pa je potrebno prvo odabrati mrežu pre integracije.

## Identifikatori mreže koriste CAIP-2

`accepts[].network` u x402 v2 je CAIP-2 identifikator, a ne skraćeni nazivi poput `base` ili `skale`. Klijenti moraju upoređivati mreže prema CAIP-2 stringovima:

| Mreža             | CAIP-2 identifikator                       |
| -------------- | ----------------------------------------- |
| Base           | `eip155:8453`                             |
| SKALE Base     | `eip155:1187947933`                       |
| Solana mainnet | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` |

## Matrica podrške

| Mreža     | scheme  | Sredstvo                  | Način potpisivanja                                 | Primenljivi scenariji                        |
| ------ | ------- | ------------------- | ------------------------------------ | --------------------------- |
| Base   | `exact` | Base USDC           | EIP-3009 `TransferWithAuthorization` | Podrazumevano preporučeno, podrška za novčanike i likvidnost su zrele.            |
| Base   | `upto`  | Base USDC + Permit2 | Permit2 `PermitWitnessTransferFrom`  | API-ji za naknadno merenje, kao što su četovi i modeli.             |
| SKALE  | `exact` | SKALE bridged USDC  | EIP-3009 `TransferWithAuthorization` | Niski troškovi gas-a, pogodno za EVM verifikaciju plaćanja i jeftine pozive. |
| Solana | `exact` | Solana USDC         | SPL `TransferChecked`                | Solana novčanici, Agent ili scenariji aplikacija na lancu.    |

`upto` je trenutno dostupan samo na Base-u. Stvarno dostupne stavke zavise od `accepts` koje vraća API. Takođe možete pogledati Facilitator:

```bash
curl https://facilitator.acedata.cloud/supported
```

Odgovor Facilitator `/supported`:

```json
{
  "kinds": [
    { "x402Version": 2, "scheme": "exact", "network": "eip155:8453" },
    {
      "x402Version": 2,
      "scheme": "upto",
      "network": "eip155:8453",
      "extra": { "facilitatorAddress": "0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708" }
    },
    { "x402Version": 2, "scheme": "exact", "network": "eip155:1187947933" },
    {
      "x402Version": 2,
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "extra": { "feePayer": "3SPm6qbgsDkj24MuR8Ss4sH97fziqyCiqFKDyeVU2igq" }
    }
  ]
}
```

Objašnjenje rezultata:

- `exact` za Base, SKALE i Solana je putanja plaćanja fiksnog iznosa.
- Samo Base pruža putanju naknadnog merenja `upto`, koja zavisi od Permit2 approve.
- `extra.facilitatorAddress` u stavci `upto` je adresa koja se upisuje u witness prilikom potpisivanja od strane klijenta i mora biti ista kao vrednost koju vraća server.

## Base

Base koristi zvanični USDC ugovor:

```text
0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
```

U šemi `exact`, klijent potpisuje EIP-712 `TransferWithAuthorization`. Sadržaj potpisa uključuje:

- `from`: adresu novčanika platioca
- `to`: adresu primaoca Ace Data Cloud-a
- `value`: iznos ove uplate
- `validAfter` / `validBefore`: vremenski prozor važenja potpisa
- `nonce`: nasumični nonce od 32 bajta

Nakon što Facilitator verifikuje potpis, on na lancu poziva USDC `transferWithAuthorization` da završi transfer.

Base je najpreporučenija mreža za produkcionu integraciju, naročito pogodna za naknadno merenje `upto`, jer su Permit2, USDC i ekosistem novčanika zreliji.

Primer rezultata verifikacije Base `exact`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
content ADC_BASE_E2E_OK
tx 0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
block 46726299
explorer https://basescan.org/tx/0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
transfer value 95215 atomic USDC
```

Objašnjenje rezultata:

- API paid retry vraća sadržaj modela `ADC_BASE_E2E_OK`.
- Transakcija na lancu je dostupna na BaseScan-u, a broj bloka je `46726299`.
- `95215` atomic USDC odgovara vrednosti `0.095215` USDC, što je stvarni iznos poravnanja za ovaj API poziv.

Rezultat pokretanja programa za plaćanje porudžbine putem Base `exact`:

```text
order 78481793-304e-47f7-bc0c-8231aec9cc1e
state Finished
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer value 1200000 atomic USDC
```

Objašnjenje rezultata:

- Konačni status porudžbine na platformi je `Finished`.
- `pay_id` porudžbine upisuje isti Base heš transakcije.
- `1200000` atomic USDC odgovara vrednosti `1.2` USDC, što je istorijski stvarno plaćeni iznos za ovu porudžbinu od 10 Credits prema staroj politici; nove porudžbine više ne dobijaju dodatni popust za X402 način plaćanja, a konkretan iznos potpisa zavisi od ovog 402 odgovora.

## SKALE

SKALE koristi bridged USDC, a način potpisivanja je sličan Base-u, takođe EIP-3009. Pogodan je za EVM scenarije plaćanja sa niskim troškovima gas-a; stvarni pozivi i dalje zavise od `accepts` koje vraća API.

Tipični SKALE 402 `accepts` će sadržati:

```json
{
  "network": "eip155:1187947933",
  "scheme": "exact",
  "extra": {
    "name": "Bridged USDC (SKALE Bridge)",
    "version": "2",
    "chainId": 1187947933,
    "verifyingContract": "0x85889c8c714505E0c94b30fcfcF64fE3Ac8FCb20"
  }
}
```

SKALE trenutno pruža samo `exact`. Ako vam je potrebno naknadno merenje, koristite Base `upto`.

Primer rezultata verifikacije SKALE `exact`:

```text
content ADC_SKALE_E2E_OK
tx 0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
block 1969317
explorer https://skale-base-explorer.skalenodes.com/tx/0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
paid 0.095215 USDC
```

Objašnjenje rezultata:
- API plaćeni ponovni pokušaj vraća sadržaj modela `ADC_SKALE_E2E_OK`。
- Transakcija se može pronaći u SKALE explorer-u, broj bloka je `1969317`。
- Iznos poravnanja za ovu `exact` uplatu je `0.095215` USDC。

## Solana

Solana koristi SPL USDC `TransferChecked`。Klijent konstruše transakciju prenosa, potpisuje je i šalje, a zatim stavlja potpis transakcije ili serijalizovanu transakciju u `PAYMENT-SIGNATURE` envelope。

Karakteristike Solane：

- Koristi Solana wallet adapter ili base58 secret key；
- Imovina je Solana USDC mint；
- Trenutno podržava samo `exact`；
- Facilitator proverava mint, destination, authority i amount instrukcije prenosa。

Ako se koristi režim wallet fee payer, novčanik će direktno poslati transakciju, a Facilitator je odgovoran za potvrđivanje transakcije i vraćanje rezultata poravnanja。

Primer rezultata `exact` verifikacije za Solanu：

```text
payer AY2RmGm2zPxB1uKvvF4dKyYdr2VySyL3wcD1MKJZoLRd
HTTP 402 -> HTTP 200
content ADC_SOLANA_E2E_OK
chain signature not confirmed in this run
```

Objašnjenje rezultata：

- Plaćeni ponovni pokušaj je već vratio HTTP 200, a model je ispisao `ADC_SOLANA_E2E_OK`。
- Prilikom upita za on-chain signature preko javnog RPC-a može doći do ograničavanja zahteva。
- Pošto javni RPC upiti mogu biti ograničeni, ovde se ne navodi Solana explorer。Kada je potrebno strogo usklađivanje, koristite sopstveni Solana RPC ili zapise o poravnanju na strani platforme da biste potvrdili potpis transakcije。

## Kako izabrati

| Šta želite da uradite        | Preporučena mreža                         |
| ------------ | ---------------------------- |
| Brzo proći minimalni tok     | SKALE `exact` ili Base `exact` |
| Za obične Web3 korisnike | Base                         |
| Za naknadno merenje, poput dopuna za čet | Base `upto`                  |
| Aplikacije u Solana ekosistemu  | Solana `exact`               |
| Niskotroškovna EVM verifikacija plaćanja | SKALE `exact`                |

Bez obzira na to koji lanac izaberete, nemojte hardkodirati cenu u klijentu。Cena je određena vrednošću `accepts[].maxAmountRequired` koju vraća server。

## Dodavanje EVM mreža

Plaćanja fiksnog iznosa u nativnom USDC-u za sledeće mreže imaju podršku u kodu i biće otvarana pojedinačno po mreži。
Dostupnost zavisi od `accepts` koje vraća porudžbina ili API；to ne znači da su sve mreže omogućene u produkciji。

| Mreža      | Alias      | CAIP-2         | Nativni USDC                                  |
| ------------ | ---------- | -------------- | -------------------------------------------- |
| Arbitrum One | `arbitrum` | `eip155:42161` | `0xaf88d065e77c8cC2239327C5EDb3A432268e5831` |

Ove mreže podržavaju samo `exact`, a preciznost valute je 6。Nemojte koristiti bridged USDC sa istim imenom。
Kada koristite zvanični TypeScript/Python X402 Client, možete proslediti skraćeni naziv iz tabele ili CAIP-2 identifikator。
Klijent koristi ID ciljnog lanca za konstruisanje potpisa；novčanik mora podržavati ciljnu mrežu。

Tabela zvanične podrške za Phantom ekstenziju novčanika navodi Arbitrum i Polygon；Optimism i Avalanche
trenutno nisu navedeni u toj tabeli, možete koristiti Rabby ili MetaMask koji podržavaju ciljnu mrežu。EVM adrese mogu biti iste na različitim lancima，
ali stanja su međusobno nezavisna, a Solana adrese nisu primenljive na EVM USDC。
Pogledajte [tabelu podrške za Phantom novčanik](https://docs.phantom.com/wallet-sdks-overview#chain-support)。

### Ulaz za postepeno uvođenje nove mreže

Ulaz za nove lance je podrazumevano skriven。Kada pristupate kontrolnoj tabli ili Studio-u, možete koristiti `?features=x402-arbitrum`
da omogućite odgovarajući lanac, a više flag-ova razdvojite zarezima。Za isključivanje jednog lanca koristite `?features=-x402-arbitrum`，
a za brisanje lokalnih override-ova koristite `?features=none`。Prekidači se čuvaju odvojeno za svaki domen。
Ponude porudžbina i ponovni pokušaji plaćanja koriste isti prekidač, a server vrši nezavisnu validaciju；postojeći zapisi o plaćanju i dalje se mogu pregledati。
Samo omogućavanje page flag-a neće omogućiti lanac koji još nije konfigurisan, a konkretne mreže na kojima je moguće platiti i dalje zavise od `accepts` u realnom vremenu。
