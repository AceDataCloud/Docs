[X402](https://www.x402.org/) je protokol za plaćanje na lancu „naplata putem HTTP 402“ koji je predložio Coinbase: server vraća `402 Payment Required` za zahteve bez tokena, uz polje `accepts: [...]` koje navodi prihvatljive lance / imovinu / cenu; klijent lokalno potpisuje autorizaciju (na EVM-u Permit2 / EIP-712, na Solani SPL token transfer autorizaciju), stavlja base64 envelope u zaglavlje `PAYMENT-SIGNATURE` i ponovo šalje zahtev. Nakon verifikacije, server zaista vrši poravnanje na lancu, a zatim vraća poslovni rezultat.

> X402 klijent Ace Data Cloud-a direktno poziva ciljni API i koristi `402 Payment Required` i `accepts` vraćene u realnom vremenu tim zahtevom kao osnov za cenu i potpisivanje. Mogućnost plaćanja Facilitator-a može se proveriti na [`/.well-known/x402`](https://facilitator.acedata.cloud/.well-known/x402).

I `@acedatacloud/sdk` i `acedatacloud` izlažu kukicu `paymentHandler`: kada zahtev koji SDK sam šalje primi `402`, poziva handler koji ste ubacili da dobije zaglavlje `PAYMENT-SIGNATURE`, a zatim ponovo šalje originalni zahtev. Kombinovanjem `@acedatacloud/x402-client` / `acedatacloud-x402` sa SDK-om, **ceo proces je potpuno transparentan za poslovni kod**——koristite samo `client.openai.chat.completions.create(...)`, izgleda potpuno isto kao token režim, ali se u pozadini plaća po pozivu i nije potrebna prethodna dopuna.

Ovaj članak:

- Zaista prolazi kroz TS tok „bez tokena + ubacivanje X402 handler-a“ ([T12 verifikacija](#četiri-verifikacija-stvarnog-izvršavanja))
- Navodi razlike između dva toka potpisivanja za EVM / Solana
- Daje tri prilagođavanja: `viem` režim privatnog ključa, režim novčanika u pregledaču, Python `EVMAccountSigner` režim
- Jasno objašnjava polje `preferScheme` / `prefer_scheme`, na kojem je lako pogrešiti

## I. Pregled protokola (obavezno pročitati)

Jedan uspešan X402 poziv uključuje **3 HTTP RTT-a**:

```text
1. SDK -> /openai/v1/chat/completions               (bez Authorization)
   <- 402 Payment Required
      { accepts: [{ scheme:'upto', network:'eip155:8453', maxAmountRequired:'10000', ... }] }

2. SDK interno -> paymentHandler({ url, method, body, accepts })   (lokalno potpisivanje, 0 RTT)
   <- { headers: { 'PAYMENT-SIGNATURE': '<base64-envelope>' } }

3. SDK -> /openai/v1/chat/completions               (ubacivanje PAYMENT-SIGNATURE zaglavlja)
   <- 200 + poslovni odgovor   (poravnanje se završava na serveru)
```

X402 envelope je JSON segment, koji se nakon base64 kodiranja stavlja u zaglavlje `PAYMENT-SIGNATURE`. Struktura (izvod):

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "upto",
    "network": "eip155:8453"
  },
  "payload": {
    "permit2": {
      "permitted": [{ "token": "0x...USDC", "amount": "10000" }],
      "nonce": "...",
      "deadline": "..."
    },
    "witness": { "...metered-billing-fields..." },
    "signature": "0x..."
  }
}
```

Na vrhu envelope-a je `x402Version: 2`, a objekat `accepted` se koristi za deklarisanje `scheme` i `network` (CAIP-2 identifikator) izabranih ovog puta.

| scheme  | Značenje                                                                                               |
| ------- | ------------------------------------------------------------------------------------------------ |
| `exact` | Fiksna cena (scenariji sa određenom cenom, kao što su generisanje slika / videa, pretraga itd.). Potpisani iznos = iznos koji server zahteva.                                                         |
| `upto`  | Mereno obračunavanje (chat completions / token tip). Potpisuje se iznos kao **gornja granica**, a stvarno se poravnava samo iskorišćeni deo (zasnovano na Permit2 + witness). **Snažno preporučeno** za API-je tipa sesije. |

`preferScheme` / `prefer_scheme` se koristi za odabir preferencije kada server **istovremeno nudi više scheme-ova**. Ako server izlaže samo `exact`, ovo polje se ignoriše; ako je postavljeno `upto`, ali ga server ne izlaže, vraća se na prvu odgovarajuću stavku.

## II. TypeScript: dve upotrebe, novčanik u pregledaču + serverski viem

### Instalacija

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client
```

Testirane verzije:

```text
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
```

### Potpis `createX402PaymentHandler` u celosti

```ts
export interface X402PaymentHandlerOptions {
  network: 'solana' | 'base';
  solanaWallet?: SolanaWalletAdapter;       // obavezno za network='solana'
  evmProvider?: EVMProvider;                // obavezno za network='base', EIP-1193
  evmAddress?: string;                      // obavezno za network='base'
  preferScheme?: 'exact' | 'upto';
}
```

Povratna vrednost je `(ctx) => Promise&lt;{ headers: Record<string, string> }>`, što se tačno poklapa sa potpisom SDK kukice `paymentHandler`.

### Upotreba 1: pregledač (MetaMask / WalletConnect)

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

// 1. Neka korisnik poveže novčanik
const accounts: string[] = await (window as any).ethereum.request({
  method: 'eth_requestAccounts'
});
const userAddress = accounts[0];

// 2. Prebaci na Base glavnu mrežu
await (window as any).ethereum.request({
  method: 'wallet_switchEthereumChain',
  params: [{ chainId: '0x2105' }]   // 8453 = Base
});

// 3. Kreiraj SDK klijent, ubaci X402 handler
//    Napomena: ne prosleđuj apiToken, da SDK ide 402 putanjom
const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider: (window as any).ethereum,
    evmAddress: userAddress,
    preferScheme: 'upto'   // chat tip mora izabrati upto
  })
});

// 4. Pozovi normalno
const res: any = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'hi' }],
  max_tokens: 20
});
console.log(res.choices[0].message.content);
```

Prvi poziv u pregledaču će **prikazati dva zahteva za potpisivanje**: prvi je jednokratni Permit2 approve za USDC (iznos je `MaxUint256`, upisuje se na lanac); drugi je EIP-712 potpis X402 envelope-a (ne ide na lanac, služi samo da ga facilitator verifikuje). Naknadni pozivi zahtevaju samo drugo potpisivanje, pa je iskustvo „kliknite jednom za potpis → dobijete rezultat“.

### Upotreba 2: Node server + viem privatni ključ (pogodno za backend / CLI)

`@acedatacloud/x402-client` na TS strani **prihvata samo EIP-1193 provider**——ne upravlja direktno privatnim ključevima. U Node / CLI scenariju, standardni pristup je da se koristi [`viem`](https://viem.sh/) za pakovanje privatnog ključa kao `WalletClient`, a zatim se koristi [`@ethereumjs/util`](https://www.npmjs.com/package/@ethereumjs/util) ili viem-ov interni EIP-1193 adapter.
```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';
import { createWalletClient, http } from 'viem';
import { base } from 'viem/chains';
import { privateKeyToAccount } from 'viem/accounts';

const account = privateKeyToAccount(process.env.EVM_PRIVATE_KEY as `0x${string}`);
const walletClient = createWalletClient({
  account,
  chain: base,
  transport: http(process.env.BASE_RPC_URL)
});

// viem WalletClient 自带 EIP-1193 兼容的 .request()，可以直接当 evmProvider
const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider: walletClient as any,   // walletClient.request 满足 EIP-1193
    evmAddress: account.address,
    preferScheme: 'upto'
  })
});

const res: any = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'hi' }],
  max_tokens: 20
});
console.log(res.choices[0].message.content);
```

> Ako smatrate da viem-ova EIP-1193 prilagodba nije dovoljno stabilna, možete ići i preko nižeg nivoa [`signEVMUptoPayment`](https://github.com/AceDataCloud/SDK/blob/main/typescript/packages/x402-client/src/evm.ts) i sami povezati putanju `accepts → signed envelope → PAYMENT-SIGNATURE header`, preskačući SDK kukicu; ipak se preporučuje da prvi izbor bude `createX402PaymentHandler`, kako ne biste sami održavali nadogradnje protokola.

### Upotreba 3: Solana

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';
import { Keypair } from '@solana/web3.js';

const kp = Keypair.fromSecretKey(/* Uint8Array */);

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'solana',
    solanaWallet: {
      publicKey: kp.publicKey,
      signTransaction: async (tx) => {
        tx.sign([kp]);
        return tx;
      }
    }
  })
});
```

Na Solana lancu je trenutno **izložen samo `exact` scheme**, tako da `preferScheme` nema efekta na Solani.

## III. Python: režim privatnog ključa

Python `acedatacloud-x402` koristi pristup **direktnog potpisivanja privatnim ključem** (bez EIP-1193 apstrakcije), što je pogodnije za serversku stranu / izvršavače zadataka.

### Instalacija

```bash
pip install acedatacloud acedatacloud-x402
```

Testirani brojevi verzija:

```text
acedatacloud==2026.4.26.1
acedatacloud-x402==2026.5.31.3
```

### EVM (Base)

```python
import os
from acedatacloud import AceDataCloud
from acedatacloud_x402 import (
    create_x402_payment_handler,
    EVMAccountSigner,
)

# 1. 从私钥构造签名器
signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

# 2. 构造 SDK：不传 api_token，让 SDK 走 402 路径
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
        prefer_scheme="upto",   # chat 类一定选 upto
    )
)

# 3. 正常调
res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "hi"}],
    max_tokens=20,
)
print(res["choices"][0]["message"]["content"])
```

### Solana

```python
import os
from acedatacloud import AceDataCloud
from acedatacloud_x402 import (
    create_x402_payment_handler,
    SolanaKeypairSigner,
)

signer = SolanaKeypairSigner.from_secret_key_base58(os.environ["SOLANA_PRIVATE_KEY"])

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="solana",
        solana_signer=signer,
        rpc_url="https://api.mainnet-beta.solana.com",  # 可选
    )
)
```

### Jednokratni approve (samo pri prvoj upotrebi EVM-a)

X402 na EVM Base-u koristi Permit2, pa novčanik mora jednom da izvrši `MaxUint256` approve za USDC prema Permit2 ugovoru. `acedatacloud-x402` ima ugrađen `approve_permit2`:

```python
from acedatacloud_x402 import approve_permit2

tx_hash = approve_permit2(
    evm_signer=signer,
    rpc_url=os.environ["BASE_RPC_URL"],
)
print("permit2_approve_tx", tx_hash)
```

Ovu transakciju je potrebno poslati samo jednom, a sva naredna X402 EVM plaćanja koristiće ovo ovlašćenje. Solana to ne zahteva.

## IV. Provera stvarnog pokretanja

Cilj testa: **TS SDK ne prosleđuje token, ubrizgava X402 handler i može normalno da konstruiše i pokrene zahtev** (lagana provera koja ne troši pravi USDC na lancu).

```ts
// /tmp/sdk-tests/ts/x402-wire-test.ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const handler = createX402PaymentHandler({
  network: 'base',
  evmProvider: { request: async () => '0x0' } as any,   // 占位 provider
  evmAddress: '0x0000000000000000000000000000000000000000',
  preferScheme: 'upto'
});

console.log('handler_type', typeof handler);   // function

const client = new AceDataCloud({
  paymentHandler: handler
});

console.log('client_ctor_ok', client.constructor.name);   // AceDataCloud
```

Izlaz:

```text
handler_type function
client_ctor_ok AceDataCloud
```

Rezultat pokazuje:

- `apiToken` nije prosleđen i SDK konstrukcija **ne prijavljuje grešku**, što dokazuje da je X402 režim zaista legitimna zamena za token.
- `createX402PaymentHandler` vraća funkciju (kukicu), koju SDK poziva tek kada primi 402.
- End-to-end test sa uspešnim stvarnim plaćanjem na lancu nije uključen u ovaj vodič, jer uključuje stvarno zaduženje USDC-a; možete pogledati e2e primer u [vodiču za X402 integraciju](https://platform.acedata.cloud/documents/x402-integration).

> Python `create_x402_payment_handler` je prošao istu proveru — povratna vrednost funkcije je callable, a konstrukcija `AceDataCloud(...)` ne prijavljuje grešku kada se ubrizga `payment_handler=...`. Semantika je usklađena na obe strane.

## V. Poređenje sa režimom „Bearer token“

| Dimenzija              | API Token                                                         | X402                                            |
| --------------- | ----------------------------------------------------------------- | ----------------------------------------------- |
| Primena            | Sopstveni backend, dugoročni projekti                                                         | Programeri trećih strana, plaćanje po pozivu po potrebi, Agentic pozivi                        |
| Registracija              | Potrebno je podneti zahtev u [konzoli](https://platform.acedata.cloud/console/applications) | Nije potrebno; dovoljan je novčanik na lancu                                     |
| Preciznost naplate            | Unapred dopunjavanje, prema tabeli tokena                                                   | U realnom vremenu, po pozivu na lancu                                         |
| Stanje              | Može se pregledati u konzoli                                                           | Gleda se USDC u novčaniku na lancu                                      |
| Početni trošak            | Registracija e-poštom odmah daje besplatni kredit                                                        | Potrebno je premostiti USDC na Base, prvi Permit2 approve              |
| Pogodno za chat tip       | ✅                                                                 | ✅ (obavezno `preferScheme=upto`)                       |
| Pogodno za jednokratno plaćanje / plaćanje u ime drugog naloga | ❌                                                                 | ✅                                               |
| Izmene koda            | `apiToken: '...'`                                                 | `paymentHandler: createX402PaymentHandler(...)` |
Dva režima mogu koegzistirati — u istom procesu, dovoljno je različitim instancama `client` dodeliti različite metode autentifikacije.

## VI. Uobičajene zamke

1. **chat klasa mora koristiti `preferScheme=upto`**: korišćenje `exact` će naterati facilitator da naplati USDC prema `maxAmountRequired` (a ne stvarnoj potrošnji).
2. **Na Node strani nemojte prosleđivati goli privatni ključ u `createX402PaymentHandler`**: TS paket ne prihvata `{ privateKey }`, već ga je neophodno upakovati kao EIP-1193 provider (preporučuje se viem `WalletClient`).
3. **Prvi poziv ima dvostruko potpisivanje**: prvo se potpisuje Permit2 approve (na lancu, ima gas), a zatim X402 envelope (nije na lancu). Naredni pozivi zadržavaju samo drugo.
4. **Solana nema koncept Permit2**: direktno se potpisuje SPL token transfer autorizacija, bez potrebe za approve; ali trenutno Solana lanac podržava samo `exact`.
5. **Razlikujte poslovne greške i greške plaćanja**: 402 → neuspeh handlera baca `X402SignError` (konkretan tip zavisi od lanca); greške poslovnog interfejsa nakon naknadnog slanja (401 / 422 / 5xx) i dalje se klasifikuju kao obični SDK izuzeci.
6. **Najstabilniji način prilagođavanja za `viem`**: `evmProvider: walletClient as any` gubi proveru tipova, ali ima najbolju kompatibilnost; ako želite zadržati tipove, zasebno upakujte viem `.transport.request` u objekat `{ request }` i prosledite ga.
