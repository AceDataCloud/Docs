title: "Osvežavanje statusa porudžbine na AceDataCloud platformi"
description: "Platform API guide - Ace Data Cloud"

Aktivno upitajte najnoviji status načina plaćanja koji odgovara porudžbini i sinhronizujte ga sa platformom. Ovaj zahtev može pristupiti usluzi plaćanja i promeniti status porudžbine, koristite ga samo kada je povratni poziv odložen ili je potrebna trenutna potvrda.

## Pripremni radovi

- Koristite [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Preuzmite svoj ID porudžbine iz [liste porudžbina](https://platform.acedata.cloud/documents/platform-order-list).

```shell
export PLATFORM_TOKEN='你的账户令牌'
export ORDER_ID='你的订单 ID'
```

## Pregled interfejsa

| Stavka    | Sadržaj                                                            |
| -------- | ------------------------------------------------------------------ |
| Metod   | `POST`                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/refresh/` |
| Autorizacija   | Vlasnik porudžbine ili super administrator                                                        |
| Body | Obično prazan; u scenariju PayPal povratnog poziva može biti potreban `payer_id` / `PayerID`                         |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/refresh/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Uspešno se vraća kompletan osvežen objekat Order. Koristite `state` za određivanje rezultata, a `finished_at` kao vreme završetka; trenutni model nema polje `paid_at`. Vrednosti statusa uključuju `Pending`, `Paid`, `Finished`, `Expired`, `Failed`, `Refunded`.

Rok za plaćanje će samo porudžbine koje su još u stanju `Pending` promeniti u `Expired`. Već refundirane porudžbine `Refunded` ostaju u refundiranom stanju i nakon osvežavanja ili prijema odloženog povratnog poziva plaćanja.

## Preporuke za ponovno pokušavanje

- Za normalna plaćanja prioritetno se oslanjajte na povratni poziv platforme; aktivno refresh-ujte samo kada se status dugo ne ažurira.
- Nemojte koristiti fiksno visokofrekventno anketiranje. Preporučuje se eksponencijalno odlaganje i zaustavljanje nakon jasnog konačnog stanja.
- `401` znači da je token nevažeći; `403` znači da niste vlasnik porudžbine; `404` znači da porudžbina ne postoji.
- Kada upit usluge plaćanja ne uspe, sačuvajte ID porudžbine i trace ID, pokušajte ponovo kasnije; nemojte kreirati duplikate porudžbina kao zamenu za potvrdu statusa.
