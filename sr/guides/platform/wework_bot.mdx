Postavite sopstvenu instancu WeCom naloga, prijavite se skeniranjem pomoću mobilnog WeCom-a i čitajte nalog, kontakte, razgovore i lokalno sinhronizovane poruke putem REST API-ja ili MCP-a. Instanca odgovara običnom WeCom nalogu, bez potrebe za privatizovanim serverom ili konfiguracijom domena poslovne e-pošte.

Trenutno je Alpha. Čitanje naloga je završilo verifikaciju stvarnih razgovora; slanje teksta od strane vlasnika i povratno čitanje događaja su završili stvarno prihvatanje; operacije nad drugim kontaktima, grupama i oporavak novih instanci još zahtevaju prihvatanje u okruženju za postavljanje. Slanje medija, odgovor sa citatom, stvarno @, upravljanje članovima grupe i potvrde isporuke još nisu dostupni. Merodavna je povratna vrednost instance `/api/capabilities`.

## Postavljanje i prijava

Otvorite uslugu u kategoriji Deployment i izaberite paket trajanja instance. Nakon postavljanja otvorite stranicu za upravljanje i skenirajte kod pomoću WeCom-a vlasnika naloga; ako je potrebna potvrda na telefonu ili drugi koraci prijave, otvorite udaljenu radnu površinu i unesite lozinku radne površine te instance. API akreditivi i lozinka radne površine su nezavisni. Podaci za prijavu se čuvaju na disku instance, ponovno kreiranje kontejnera zadržava disk; brisanje diska će obrisati lokalnu sesiju.

Svaka instanca se naplaćuje zasebno i radi u skladu sa kupljenim trajanjem. REST / MCP pozivi se ne naplaćuju dodatno po poruci, a stvarna cena je određena stranicom paketa. Trenutno se podrazumevano referiše na pakete trajanja WeChat robota, a pre konačnog otvaranja potrebno je potvrditi cene u kombinaciji sa resursima za rad.

## API i MCP

Koristite API adresu instance na stranici za upravljanje, a svi interfejsi naloga nose `Authorization: Bearer <API token instance>`. Ove putanje pripadaju namenskoj instanci, a ne deljenom API mrežnom prolazu. MCP adresa je adresa instance sa dodatkom `/mcp/` i koristi isti Bearer token.

| Interfejs                                                       | Namena                                          |
| -------------------------------------------------------- | ------------------------------------------- |
| `GET /api/status`、`GET /api/auth/status`                 | Da li je nalog spreman i lista mogućnosti                                 |
| `GET /api/auth/qr`                                       | PNG Base64 trenutnog QR koda za prijavu                          |
| `GET /api/account`                                       | Trenutni nalog                                        |
| `GET /api/contacts?kind=all`                             | Interni kolege i eksterni kontakti, može se navesti internal / external          |
| `GET /api/conversations`                                 | Lokalni razgovori, zadržavaju originalni ID razgovora                              |
| `GET /api/messages`                                      | Lokalno sinhronizovane poruke; parametri conversation_id, after_rowid, limit |
| `POST /api/search`                                       | Pretraga kontakata, razgovora i lokalnog teksta                               |
| `POST /api/messages`                                     | Asinhroni zadatak slanja teksta, mora se navesti Idempotency-Key               |
| `POST /api/messages/send`                                | Isti ulaz za slanje, podržava jedan ili više ciljeva                            |
| `GET /api/groups/{conversation_id}`                      | Lokalno sinhronizovane informacije o grupi i članovi                                 |
| `GET /api/tasks`                                         | Nedavni zadaci i rezultati za svaki cilj                                 |
| `GET /api/tasks/{id}`                                    | Upit rezultata slanja                                      |
| `POST /api/tasks/{id}/cancel`                            | Otkazivanje zadatka koji još nije započet                                   |
| `POST /api/runtime/pause`、`POST /api/runtime/resume`     | Pauziranje automatizacije; nastavak nakon verifikacije vlasnika                               |
| `GET /api/diagnostics`、`GET /api/diagnostics/screenshot` | Stanje instance i trenutni ekran, oba zahtevaju autentifikaciju                              |
| `GET /api/events?after=0`                                | Događaji poruka sa kursorom koji se može nastaviti                                  |
| `WS /ws`                                                 | Tok događaja poruka, Bearer autentifikacija                             |

Telo za slanje sadrži `target`, `type: "text"` i `text`. `target` prihvata ID razgovora, ID kontakta, ID poslovnog korisnika ili jedinstveno puno ime; prednost imaju ID-jevi; kada prikazano ime i dalje ne može jedinstveno odrediti cilj, instanca će odbiti operaciju i neće nagađati objekat. Kontakt bez lokalnog razgovora će prvo otvoriti razgovor putem klijenta, a zatim poslati poruku nakon provere stvarnog ID-ja razgovora. Zaglavlje zahteva `Idempotency-Key` sastoji se od 8–128 slova, brojeva ili `_.:-`. Ponovljeni zahtevi za istu operaciju moraju ponovo koristiti isti ključ i isto telo zahteva.

Zamenom `target` nizom `targets` može se serijski slati na 1–50 jasno navedenih ciljeva. Oba se ne mogu navesti istovremeno. Svi ciljevi prvo završavaju razrešavanje identiteta, a različiti pseudonimi koji upućuju na isti objekat biće odbijeni. Nakon neuspeha jednog cilja, naredna slanja se zaustavljaju, a rezultat zadatka po stavkama beleži `succeeded`, `failed`, `unknown` ili `not_attempted`; delimičan uspeh nemojte smatrati potpunim uspehom. Ovaj proces takođe treba da završi stvarno prihvatanje navedenih kontakata u okruženju za postavljanje.

Zadaci mogu biti u stanju queued, running, submitting, succeeded, failed, unknown ili cancelled. `succeeded` znači da su nakon slanja u odgovarajućem zapisu razgovora pronađeni tačan tekst i ID poruke servera, dok je `delivered` i dalje null, što ne znači da je druga strana primila poruku. unknown znači da rezultat nije jasan; proverite istoriju zapisa i nemojte ponavljati slanje sa novim ključem. Instanca neće automatski ponovo slati prekinute zadatke.

Istorija uključuje samo sadržaj koji je klijent već sinhronizovao i ne može garantovati kompletnu istoriju. Netekstualne poruke mogu vratiti tip unknown, a preuzimanje priloga još nije dostupno. Događaji zadržavaju najnovijih 10.000 stavki, a `gap` označava da je kursor već izašao iz prozora zadržavanja. Prvo povezivanje neće ponovo emitovati staru istoriju kao nove poruke.

`server_accepted` i `server_id` u istoriji poruka mogu se koristiti za proveru da li je server prihvatio lokalnu poruku; kada postoji samo lokalni zapis bez ID-ja servera, slanje se ne može smatrati uspešnim. Ova polja ne predstavljaju da je primalac poruku primio ili pročitao. Zapisi događaja zadržavaju stanje u trenutku generisanja; za upit trenutnog stanja potvrde treba koristiti interfejs istorije poruka.

## Nalog i akreditivi

Prijavite samo naloge nad kojima vlasnik ima ovlašćenje za rad. Konfigurišite API token u pouzdanim aplikacijama; on može pristupiti podacima naloga te instance. Ne objavljujte lozinke, QR kodove ili snimke ekrana razgovora na javnim mestima. Pauziranje instance će prekinuti događaje u realnom vremenu. Nakon odjave naloga ili uklanjanja uređaja na mobilnoj strani, potrebno je ponovo se prijaviti.

Trenutni unos teksta podržava samo jedan red, a novi redovi će biti izričito odbijeni pre slanja. Kada klijent zahteva bezbednosnu verifikaciju ili ponovnu prijavu, vlasnik naloga to treba da završi na udaljenoj radnoj površini; instanca neće zaobići verifikaciju. Zadaci nakon prekida verifikacije mogu vratiti unknown, prvo proverite zapise poruka i nemojte ponovo slati sa novim ključem idempotentnosti.

Nakon prepoznavanja upita za bezbednosnu verifikaciju, odjave naloga ili promene, red automatizacije će trajno biti pauziran. Nakon završetka verifikacije telefonom, možete nastaviti još neizvršene zadatke putem opcije „Nastavi nakon verifikacije” na konzoli instance; zadaci koji su već poslati, ali čiji je rezultat neizvestan, neće biti ponovo poslati. Uobičajen rad na daljinu takođe može pokrenuti WeCom bezbednosnu verifikaciju. Period od 24 sata bez ponovnog zaključavanja nakon verifikacije, naveden u zvaničnom objašnjenju, ne znači da je detekcija već uklonjena, niti znači da instanca može garantovati dugoročni rad bez nadzora.
