Straničeno vraća Application objekte koje nalog poseduje ili za čije je korišćenje ovlašćen, uključujući stanje, status, sažetak usluge i povezane akreditive. Pogodno za grupno praćenje stanja, pronalaženje Application ID-ja i ulazak u upravljanje akreditivima.

## Priprema

1. Prijavite se na [AceDataCloud platformu](https://platform.acedata.cloud).
2. Kreirajte token naloga u [Account Token konzoli](https://platform.acedata.cloud/console/platform-tokens).
3. Obični korisnici koriste `user_id=me`; takođe možete dobiti sopstveni UUID putem `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='你的账户令牌'
```

## Pregled interfejsa

| Stavka   | Sadržaj                                                    |
| --- | ----------------------------------------------------- |
| Metod  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Autentikacija  | Account Token, OAuth token zahteva `applications:read`       |
| Straničenje  | `count` + `items`                                     |

Obični korisnici treba da proslede `user_id=me`. Ako se ne prosledi, upit se prvo ne sužava prema nalogu, pa straničenje može vratiti `403` kada naiđe na objekte bez ovlašćenja; administratori bez prosleđivanja mogu videti celu tabelu.

## Parametri upita

| Parametar            | Tip          | Obavezno     | Opis                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Obavezno za obične korisnike | Subjekat upita; podržava ponovljene parametre                                         |
| `affiliation` | string      | Ne      | `owner` (podrazumevano) ili `granted`; oba se mogu proslediti više puta radi unije, važi samo kada postoji `user_id` |
| `service_id`  | UUID        | Ne      | Filtriranje prema usluzi; podržava ponovljene parametre                                        |
| `scope`       | string      | Ne      | `Individual` ili `Global`; podržava ponovljene parametre                      |
| `type`        | string      | Ne      | `Usage` ili `Period`; podržava ponovljene parametre                           |
| `limit`       | integer     | Ne      | Broj stavki po stranici, najviše 100                                         |
| `offset`      | integer     | Ne      | Pomak straničenja                                               |
| `ordering`    | string      | Ne      | Podržava samo `created_at` ili `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` i `tag` trenutno nisu parametri filtriranja na serveru. Upozorenja za stanje treba utvrditi na klijentu nakon preuzimanja liste, na osnovu `remaining_amount`, `service.unit` i poslovnog praga svakog Application objekta.

## Primer zahteva

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Istovremeni pregled Application objekata koje posedujete i onih koje su vam drugi odobrili:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Objašnjenje odgovora

Odgovor je `{count, items}`. Svaka stavka sadrži polja Application modela, uz dodatno:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: sažetak akreditiva koje trenutni pozivalac ima pravo da vidi;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`;
- stvarna vrednost za `scope` je `Individual` ili `Global`;
- stvarna vrednost za `type` je `Usage` ili `Period`.

`remaining_amount` može biti prazan; klijent mora prvo proveriti da li je prazan, a zatim izvršiti numeričko poređenje. Jedinicu kvote određuje `service.unit`.
