Straničeno vraća Application objekte koje nalog poseduje ili za čije je korišćenje ovlašćen, uključujući stanje, status, sažetak usluge i povezane akreditive. Pogodno za grupno praćenje stanja, pronalaženje Application ID-ja i pristup upravljanju akreditivima.

## Priprema

1. Prijavite se na [AceDataCloud platformu](https://platform.acedata.cloud).
2. Kreirajte token naloga u [Account Token konzoli](https://platform.acedata.cloud/console/platform-tokens).
3. Obični korisnici koriste `user_id=me`; takođe možete dobiti sopstveni UUID putem `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='vaš token naloga'
```

## Pregled interfejsa

| Stavka   | Sadržaj                                                    |
| --- | ----------------------------------------------------- |
| Metod  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Autentifikacija  | Account Token, OAuth token zahteva `applications:read`       |
| Paginacija  | `count` + `items`                                     |

Obični korisnici treba da proslede `user_id=me`. Ako se ne prosledi, upit se prvo ne sužava po nalogu, a paginacija može vratiti `403` kada naiđe na objekte bez ovlašćenja; administratori mogu pregledati celu tabelu ako ne proslede ovaj parametar.

## Parametri upita

| Parametar            | Tip          | Obavezno     | Opis                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Obavezno za obične korisnike | Subjekt upita; podržava ponovljene parametre                                         |
| `affiliation` | string      | Ne      | `owner` (podrazumevano) ili `granted`; oba se mogu ponoviti za uniju, važi samo kada postoji `user_id` |
| `service_id`  | UUID        | Ne      | Filtriranje po usluzi; podržava ponovljene parametre                                        |
| `scope`       | string      | Ne      | `Individual` ili `Global`; podržava ponovljene parametre                      |
| `type`        | string      | Ne      | `Usage` ili `Period`; podržava ponovljene parametre                           |
| `limit`       | integer     | Ne      | Broj stavki po stranici, najviše 100                                         |
| `offset`      | integer     | Ne      | Pomeraj paginacije                                               |
| `ordering`    | string      | Ne      | Podržava samo `created_at` ili `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` i `tag` trenutno nisu parametri filtriranja na serveru. Za upozorenja o stanju, nakon preuzimanja liste treba na klijentu proceniti vrednosti `remaining_amount`, `service.unit` i poslovne pragove za svaki Application.

## Primer zahteva

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Istovremeno pregledajte Application objekte koje posedujete i one koje su vam drugi odobrili:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Opis odgovora

Odgovor je `{count, items}`. Svaka stavka sadrži polja Application modela, uz dodatno:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: sažetak akreditiva koje trenutni pozivalac ima pravo da vidi;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`, `allow_overdraft`;
- stvarna vrednost `scope` je `Individual` ili `Global`;
- stvarna vrednost `type` je `Usage` ili `Period`.

`allow_overdraft` je administratorski kontrolisano polje samo za čitanje tipa Boolean, čija je podrazumevana vrednost `false`. Za aplikacije zasnovane na potrošnji (`Usage`) sa omogućenim prekoračenjem, nedovoljno stanje neće sprečiti poziv; trošak se i dalje obračunava prema stvarnoj potrošnji. Negativno stanje predstavlja iznos koji čeka poravnanje. Onemogućavanje, istek i ograničenja API akreditiva i dalje važe.

`remaining_amount` može biti prazan; klijent mora prvo proveriti da li je prazan, pre numeričkog poređenja. Jedinica kvote određena je sa `service.unit`.
