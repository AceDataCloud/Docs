---
title: "Podešavanje deljenja globalnog salda za AceDataCloud Application"
description: "Platform API guide - Ace Data Cloud"
---

Podesite `allow_consume_global`. Nakon omogućavanja, Application koji ispunjava uslove i koristi obračun po potrošnji može nastaviti da koristi globalni saldo naloga kada mu sopstveni saldo nije dovoljan.

## Priprema

- Kreirajte i bezbedno sačuvajte [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Preuzmite svoj `application_id` sa [liste zahteva za uslugu](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='vaš token naloga'
export APPLICATION_ID='vaš Application ID'
```

## Pregled interfejsa

| Stavka | Sadržaj                                                                                             |
| ---- | -------------------------------------------------------------------------------------------------- |
| Metod   | `POST`                                                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/applications/{application_id}/update-allow-consume-global/` |
| Autentifikacija   | Account Token                                                                                      |
| Body | JSON                                                                                               |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/applications/${APPLICATION_ID}/update-allow-consume-global/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"allow_consume_global": true}'
```

U slučaju uspeha vraća se ažurirani Application objekat. Oslonite se na `allow_consume_global` iz odgovora, umesto da pretpostavite da je vrednost zahteva sigurno sačuvana.

> Application tipa `Period` ne može da troši globalni saldo. Čak i ako se zatraži `true`, server će ovo polje zadržati kao `false`.

## Obrada grešaka

- `401`: Account Token je nevažeći ili nedostaje.
- `403`: Trenutni nalog nije vlasnik ovog Application-a.
- `404`: Application ID ne postoji.

Ulaz za dopunu globalnog salda i dostupni paketi određuju se prema stvarnim paketima u platformskom kontrolnom panelu i onima vraćenim kroz [kreiranje porudžbine](https://platform.acedata.cloud/documents/platform-order-create); nemojte pretpostavljati da postoji paket tipa `Wallet`.

## Aplikacije sa odobrenim prekoračenjem

Kada je polje aplikacije samo za čitanje `allow_overdraft=true`, aplikacija može nastaviti da naplaćuje sa sopstvenog salda, čak i ako saldo postane negativan, i neće se prebaciti na globalni nalog zbog nedovoljnog salda. Aplikacije bez omogućenog prekoračenja i dalje prate `allow_consume_global`; nakon prebacivanja, da li je prekoračenje dozvoljeno određuje se podešavanjem globalnog Application-a sa kojeg se stvarno vrši naplata.

## Ograničenje istovremenosti za probne naloge

Sistem koristi oznaku korisnika samo za čitanje `has_recharged` da evidentira da li je ikada uspešno izvršena plaćena dopuna ili je administrator ručno dodao kredite; oznaka se ažurira nakon uspešnog izvršenja operacije, a istorijskim korisnicima se jedinstveno dopunjava na osnovu porudžbina ili jasnih evidencija o dodavanju kredita. Nalozi koji nisu izvršili plaćenu dopunu niti im je administrator ručno dodao kredite mogu imati samo jedan istovremeni zahtev za naplatu na nivou celog naloga; različiti API Key-evi i različite usluge dele ovo jedno mesto. Nagrade, kartice za zamenu i preneta sredstva ne smatraju se plaćenom dopunom. Nalozi koji su već izvršili plaćenu dopunu ili im je administrator ručno dodao kredite ne podležu ovom ograničenju istovremenosti za probni period, već i dalje prate postojeće provere salda i kvote kredencijala.

Dok se postojeći zahtev izvršava, novi zahtev vraća `429 too_many_requests`. Besplatni interfejsi za anketiranje, kao što je upit zadataka, i dalje se mogu normalno pozivati. Autentifikacija Realtime veze prati postojeći proces naplate po rundama i ne zauzima ovo mesto za običan zahtev.

Kada asinhroni interfejs vrati „prihvaćeno“, zadatak se i dalje izvršava i potrebno je sačekati konačni rezultat pre slanja sledećeg zahteva za generisanje. Prekid mreže ili istek vremena posredničkog servera ne znači da je zadatak zaustavljen; ako zadatak dugo nema završno stanje, dostavite `trace_id` i kontaktirajte podršku radi provere.

Ovo ograničenje ne menja interfejse dostupne za probu niti postojeća pravila naplate. Troškovi se i dalje obračunavaju po stvarnoj potrošnji nakon završetka zahteva.
