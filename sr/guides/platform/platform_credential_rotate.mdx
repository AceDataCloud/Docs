Generišite novi Token ili lozinku za postojeći Credential. ID kredencijala, Application povezivanje, kvote i druga polja ostaju nepromenjeni, stara tajna odmah postaje nevažeća.

> Rotiranje će prekinuti rad klijenata koji i dalje koriste staru tajnu. Najpre pripremite bezbednu distribuciju i plan vraćanja, pa zatim izvršite operaciju pisanja.

## Pregled interfejsa

| Stavka    | Sadržaj                                                                  |
| ---- | --------------------------------------------------------------------------- |
| Metod   | `POST`                                                                      |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}/rotate/` |
| Autentifikacija   | Account Token                                                               |
| Body | Nema ili `{}`                                                                     |

Preuzmite `credential_id` iz [liste kredencijala](https://platform.acedata.cloud/documents/platform-credential-list):

```shell
export PLATFORM_TOKEN='你的账户令牌'
export CREDENTIAL_ID='要轮换的 Credential ID'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/credentials/${CREDENTIAL_ID}/rotate/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Uspešan odgovor vraća ažurirani Credential. Kada je `type=Token`, pročitajte novi `token`; kada je `type=Identity`, pročitajte novu `password`. Tretirajte kompletan odgovor kao tajnu i odmah ažurirajte pozivaoca.

## Obrada grešaka

- `401`: Account Token je nevažeći.
- `403`: Nemate pravo da upravljate tim kredencijalom.
- `404`: Credential ID ne postoji.
