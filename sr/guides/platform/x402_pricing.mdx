Овај документ објашњава како се цена одређује када се X402 користи за позивање Ace Data Cloud API, као и каква је веза између тога и цене обичних **Credits** (кредита) на платформи.

## Кључни закључак

X402 није независан ценовни систем. Свакој API позиву већ постоји трошак изражен у **Credits**, што је једини извор цена који се дели међу свим методама наплате (одузимање кредита API токена, стање на рачуну, X402 плаћање на ланцу). X402 само претвара овај трошак у Credits по фиксном курсу у ланчаном USDC:

> **1 Credit = 0.095215 USDC** (тј. `95215` атомских USDC, USDC има 6 децимала)

То значи:

```text
X402 цена (USDC) = трошак Credits за овај позив × 0.095215
```

Овај курс није произвољно одређен, он је једнак **најповољнијој (великим количинама) цени Credits** на платформи. Дакле, плаћање X402 ≈ куповина Credits по најповољнијој цени и потпуно без X402 премије, а корисници уживају у најнијој цени Credits без потребе за предплаћивањем или API токеном.

## Основица за наплату

| Пројекат        | Вредност                          | Објашњење                                              |
| --------------- | -------------------------------- | ----------------------------------------------------- |
| Претварање курса | `1 Credit = 0.095215 USDC`       | Фиксни курс који је одредила платформа                          |
| атомска јединица | `1 Credit = 95215 атомских USDC` | USDC 6 децимала, `атомска = floor(credits × 0.095215 × 1e6)` |
| Минимална наплата | `1 атомски USDC` ($0.000001)     | Чак и ако је трошак веома низак, минимално се наплаћује 1 атомски |
| Валута наплате   | USDC                             | Base / SKALE је ERC-20 USDC, Solana је SPL USDC      |

Претварање обавља платформа, а износи су идентични за све подржане мреже (Base, SKALE, Solana); различите мреже само имају различите уговоре о имовини и начине потписивања, али цена остаје иста.

### Веза са ценом обичних Credits

Платформа продаје Credits по принципу „што већа потрошња, нижа цена“. Када се X402 наплаћује по позиву, користи се најповољнија цена:

| Начин куповине/плаћања | Приближна цена Credits          | Објашњење               |
| ---------------------- | ------------------------------- | ---------------------- |
| Увод / мали депозит    | око `$0.13 / Credit`           | Цене за мале куповине Credits |
| Велики / најповољнији  | `$0.095215 / Credit`           | Најнижа цена               |
| **X402 плаћање по позиву** | **`$0.095215 / Credit`**     | **увек једнако најповољнијој цени** |

Другим речима, X402 сваку позив наплаћује по најповољнијој цени Credits. Корисници који купују Credits по малим депозитима плаћају већу цену од X402; само корисници који купују велике количине имају исту цену као X402.

## Две форме цена: `exact` и `upto`

У X402 одговору, `maxAmountRequired` је износ који треба да потпишете. Има две форме:

- **`exact` (фиксна цена)**: Цена се може одредити пре обраде захтева (слике, видео, музика, претрага, плаћање налога). `maxAmountRequired = трошак Credits за овај позив × 0.095215`, тј. износ који треба платити (сагласан са `cost.amount` у успешном одговору).
- **`upto` (потрошња после мерења)**: Интерфејси као што је допуњавање чата где „знамо колико токена је потрошено тек на крају одговора“. `maxAmountRequired` је **горња граница** (претворена према горњој граници постављеној по овом моделу: горња граница Credits × 0.095215), а стварна наплата се врши према стварној потрошњи, али не прелази горњу границу.

Детаље о протоколу за ова два шеме видите у [ `exact` и `upto` плану наплате](https://platform.acedata.cloud/documents/x402-metered-upto). Испод се говори само о ценама.

## Chat (допуњавање чата) цена

Допуњавање чата је `upto` мерење: наплата се врши према стварној потрошњи токена / завршетка. Цена за милион (1M) токена = `трошак Credits за 1M токена по овом моделу × 0.095215`, што је у потпуности у складу са USD ценом приказаном у јавном каталогу модела платформе (`/api/v1/models?with_pricing=true`).

Следећа табела показује стварне цене (узете из каталога модела, према X402 курсу), јединица USD / 1M токена:

| Модел                | Улаз / 1M | Излаз / 1M  | `upto` горња граница       |
| ------------------- | -------- | --------- | -------------------------- |
| gpt-4o-mini         | $0.0796  | $0.3183   | 1 Credit ($0.095215)      |
| gemini-2.5-flash    | $0.1591  | $1.3262   | 5 Credits ($0.476074)     |
| gpt-5 / gpt-5.1     | $0.6631  | $5.3050   | 20 Credits ($1.904299)    |
| gemini-2.5-pro      | $0.6631  | $5.3050   | 50 Credits ($4.760750)    |
| gpt-4.1             | $1.0610  | $4.2440   | 20 Credits ($1.904299)    |
| claude-sonnet-4-5   | $0.6006  | $3.0028   | 50 Credits ($4.760750)    |
| grok-4              | $1.5915  | $7.9574   | 10 Credits ($0.952149)    |
| claude-opus-4-1     | $3.0028  | $15.0140  | 50 Credits ($4.760750)    |

Објашњење:

- У табели су цене по токену; трошак једног захтева = улазни токен × улазна цена + излазни токен × излазна цена.
- `upto` горња граница је максимални износ који модел дозвољава за потписивање у једном захтеву; то није стварна наплата, већина захтева је далеко испод горње границе.
- Горња граница одређује само „максимално могуће одузимање“, а стварна наплата се врши према потрошњи токена.

### Пример: цена и наплата су у складу (`exact`)

Испод је пример правог плаћања путем званичног X402Client за `serp/google` (Base `exact`). Он демонстрира сагласност три ствари: 402 цена, потписани износ и `cost` који се враћа у успешном одговору.

```text
# 1) Неплаћени захтев -> 402, добијање цене (без наплате)
POST /serp/google  ->  402
base/exact maxAmountRequired = 952 атомских = $0.000952 = 0.01 Credit
# 0.01 × 0.095215 = 0.00095215, округлено на атомске = 952

# 2) Потписивање 952 атомских са WALLET SIGNATURE, поновно покушај
POST /serp/google (PAYMENT-SIGNATURE) -> 200
body.cost = {"amount": 0.000952, "currency": "usdc", "settlement": "authorized"}
```
响应返回的 `cost.amount`（0.000952 USDC） са 402 понудом, и са `Credits × 0.095215` потпуно идентични. `settlement` поље је статус обрачуна ове уплате (`authorized` = одобрено); обрачун на ланцу обрађује платформа, механизам види [`exact` и `upto` тарифне планове](https://platform.acedata.cloud/documents/x402-metered-upto).

### `upto` понуда за обрачун (разговор)

Разговор се мери по токенима. Понуда за одређени захтев (није горња граница) се обрачунава по следећој формули (узимајући gpt-4o-mini као пример):

```text
Credits = 1e-6 × (0.835733 × prompt_tokens + 3.342933 × completion_tokens)
USDC    = Credits × 0.095215
```

Захтев за 500 prompt + 200 completion токена:

```text
Credits = 1e-6 × (0.835733 × 500 + 3.342933 × 200) ≈ 0.001086 Credits
Понуда USDC ≈ 0.001086 × 0.095215 ≈ $0.0001034
```

Клијент потписује по `upto` горњој граници (gpt-4o-mini је 1 Credit = `95215` атомских) што је само **максимално могуће одбијање**; стварна понуда за овај захтев (горњи пример око $0.0001) је далеко испод горње границе, обрачунава се по потрошњи токена. Механизам обрачуна на ланцу за `upto` види [`exact` и `upto` тарифне планове](https://platform.acedata.cloud/documents/x402-metered-upto).

## Остале цене услуга (фиксна цена `exact`)

Интерфејси као што су слике, видео, музика, претрага имају цену која се може одредити при захтеву, користећи `exact`. Долња табела показује стварне цене, преузете из онлајн интерфејса за неплаћене захтеве који враћају 402 `maxAmountRequired` (упит за понуду неће изазвати наплату):

| ---- | --------------------------- | ------- | --------- | ------- |
| Веб претрага | serp/google, ≤10 резултата         | 0.01    | $0.000952 | 952     |
| Слика   | nano-banana                 | 0.14    | $0.013330 | 13330   |
| Слика   | gpt-image-1, 1024×1024       | 0.20    | $0.019043 | 19043   |
| Слика   | flux-dev                    | 0.24    | $0.022851 | 22851   |
| Слика   | midjourney imagine          | 0.27    | $0.025708 | 25708   |
| Слика   | seedream-4                  | 0.32    | $0.030468 | 30468   |
| Музика   | suno generate               | 0.55    | $0.052368 | 52368   |
| Музика   | producer generate           | 0.68    | $0.064746 | 64746   |
| Видео   | luma                        | 1.19    | $0.113305 | 113305  |
| Видео   | hailuo（minimax-hailuo-2-3）  | 1.72    | $0.163769 | 163769  |
| Видео   | kling-v2-6 std              | 2.10    | $0.199951 | 199951  |
| Видео   | kling-v3 std                | 4.20    | $0.399903 | 399903  |
| Видео   | veo-3 text→video            | 5.00    | $0.476074 | 476074  |
| Видео   | seedance-1-0-pro, 1080p / 5s | 5.60    | $0.533204 | 533204  |
| Видео   | wan2.6-t2v                  | 13.50   | $1.285402 | 1285402 |

Објашњење:

- Цене исте услуге се мењају у зависности од **модела, резолуције, трајања, акције** (посебно видео). Долња табела показује стварне вредности за одређену групу параметара, само за референцу.
- За ове фиксне цене (`exact`) интерфејсе, 402 одговор у `maxAmountRequired` је износ који треба платити (сагласан са успешним одговором `cost.amount`, већ је тестирано у претходном делу).
- Свака цена се добија од `Credits × 0.095215` округљено на атомску јединицу (види горе наведене референтне цене), користи се иста формула као и за разговор. Због представе у покретној тачки и округљања, поједине вредности могу се разликовати од простог производа за 1 атом (0.000001 USD), увек се узима у обзир 402 враћена вредност.

## Цена плаћања поруџбине

Када плаћате поруџбине у X402 контролној табли (куповина пакета / допуна Credits), цена се узима као што је приказано на страници поруџбине, 402 `amount` је коначна основа за потпис. Плаћање поруџбине иде преко платформског API-а, потребан је токен налога, детаљи у [упутству за плаћање поруџбине](https://platform.acedata.cloud/documents/x402-order-payment).

Један стварни пример из упутства за плаћање поруџбине (куповина 10 Credits):

```text
description Ace Data Cloud Credits x 10.0
created price 1.26          # цена при креирању поруџбине (USD)
settled    1.20 USDC        # коначни потпис/износ за обрачун (= 402 amount)
            = 1200000 атомских USDC
```

Напомена: **плаћање по позиву** (горе наведени разговор / друге услуге) и **плаћање поруџбине** су два различита пута. Плаћање по позиву се униформно користи `0.095215`/Credit као оптимална цена; плаћање поруџбине се одређује по ценовнику пакета, разлика између цене при креирању и коначног износа обрачуна се узима у обзир у [упутству за плаћање поруџбине](https://platform.acedata.cloud/documents/x402-order-payment).

## Како у реалном времену добити цену

Цене се мењају у зависности од модела и параметара, молимо вас да користите програм за реално добијање, немојте хардкодирати:

- **Цена по позиву**: пошаљите један захтев за циљни API **без** `PAYMENT-SIGNATURE` (такође без `Authorization`), прочитајте враћени 402 `accepts[].maxAmountRequired`. Овај корак неће изазвати наплату. За `exact` интерфејс то је коначна цена; за `upto` интерфејс (разговор) то је горња граница, стварно се обрачунава по потрошњи.
- **Цена по токену за разговор**: `GET https://platform.acedata.cloud/api/v1/models?with_pricing=true&type=chat`, прочитајте `pricing.input_usd` / `pricing.output_usd` за сваки модел (већ израчунато по `credit_usd_rate`).
- **Проверка конверзије**: `atomic = floor(Credits × 0.095215 × 1e6)`, `USDC = atomic / 1e6` (тј. `USDC ≈ Credits × 0.095215`).

Минимални пример захтева за добијање цене:

```bash
curl -sS -X POST https://x402.acedata.cloud/midjourney/imagine \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "a cat"}'
# Враћа 402, accepts[].maxAmountRequired је цена за овај (exact) позив
```

## Закључак
- X402 цена = Трошак Credits за овај позив × `0.095215`, иста је као и обична цена Credits, само се обрачунава у USDC на ланцу.
- `0.095215`/Credit је **оптимална цена** (велики износ) за Credits; мала допуна купује Credits по вишој цени, тако да X402 аутоматски добија оптималну цену.
- `exact` интерфејс (слика / видео / музика / претрага / поруџбина) потписана сума је износ који треба платити; `upto` интерфејс (разговор) потписује горњу границу, обрачунава се по стварној потрошњи.
- Ауторитативна цена се утврђује према `maxAmountRequired` који се враћа из 402: `exact` је износ који треба платити (сагласан са успешним одговором `cost.amount`, тестирано); `upto` је горња граница, успешан одговор `cost.amount` је стварни износ обрачунавања по потрошњи (≤ горња граница).
