Trajno obrišite jedan API akreditiv. Nakon brisanja je **odmah nepovratan**, a svi poslovni interfejsi koji koriste ovaj Token će odmah dobiti `401`.

> ℹ️ Ovaj interfejs pripada **API-ju za upravljanje AceDataCloud platformom**, sa jedinstvenim prefiksom `https://platform.acedata.cloud/api/v1/`.

## Pregled interfejsa

| Stavka   | Sadržaj                                                              |
| --- | ------------------------------------------------------------------- |
| Metod  | `DELETE`                                                            |
| URL | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}` |
| Autentifikacija  | ✅ Potreban je token naloga                                                            |

`/credentials/{id}` i `/credentials/{id}/` su trenutno oba dostupna; primeri ujednačeno koriste oblik bez završne kose crte.

## Objašnjenje autentifikacije (kako dobiti token naloga)

Zaglavlje zahteva:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Za način dobijanja pogledajte [Upravljanje tokenom naloga AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-token).

## Parametri putanje

| Parametar              | Tip   | Obavezno  | Opis        |
| --------------- | ---- | --- | --------- |
| `credential_id` | UUID | ✅   | ID akreditiva koji se briše |

## Primeri zahteva

### cURL

```shell
curl -X DELETE 'https://platform.acedata.cloud/api/v1/credentials/df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

cred_id = "df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6"
resp = requests.delete(
    f"https://platform.acedata.cloud/api/v1/credentials/{cred_id}",
    headers={"authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    timeout=10,
)
assert resp.status_code == 204, resp.text
print("✅ 已删除")
```

### Node.js

```javascript
const credId = 'df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6'
const r = await fetch(`https://platform.acedata.cloud/api/v1/credentials/${credId}`, {
  method: 'DELETE',
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log('status:', r.status) // 204
```

## Odgovor

- **Uspeh**: `HTTP 204 No Content`, **bez tela odgovora**.
- **Neuspeh**: vraća JSON greške, pogledajte tabelu u nastavku.

## Obrada grešaka

| HTTP | code                | Značenje         |
| ---- | ------------------- | ---------- |
| 401  | `not_authenticated` | Nedostaje token naloga     |
| 403  | `permission_denied` | Ovaj akreditiv vam ne pripada    |
| 404  | `not_found`         | Akreditiv ne postoji ili je već obrisan |

## Praktični saveti

- **Brisanje je nepovratno** — platforma ne čuva kopije Tokena. Ako samo sumnjate na curenje, a želite da zadržite podatke praćenja, trebalo bi da koristite [Rotiranje API akreditiva AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-credential-rotate) umesto brisanja.
- **Brisanje ne vraća već potrošeni limit ovog akreditiva**. Stanje Application-a se odbija u realnom vremenu prema potrošnji, a brisanje akreditiva ne utiče na knjigovodstveno stanje.
- Nakon brisanja možete putem [Liste API akreditiva](https://platform.acedata.cloud/documents/platform-credential-list) ponovo potvrditi preostale akreditive prema `application_id`.
- **Pre masovnog čišćenja prvo proverite pozivaoce**: lista trenutno nema polje vremena poslednje upotrebe; potrebno je kombinovati konfiguraciju implementacije i evidenciju poziva kako biste potvrdili da se akreditiv više ne koristi, a zatim ih brisati jedan po jedan.
