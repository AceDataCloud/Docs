Pretražite detalje poslovnih API poziva trenutnog naloga u poslednjih 60 dana, pogodno za proveru naplate, lociranje neuspešnih zahteva i rešavanje problema po usluzi, Application-u, API-ju ili akreditivu.

> Ova stranica pretražuje tokove poziva sopstvenog naloga. Ako želite da vidite samo javnu statistiku poziva određenog API-ja na celoj platformi, koristite [statistiku API poziva](https://platform.acedata.cloud/documents/platform-api-usage).

## Opseg čuvanja podataka

Zapisi poziva i sažeci naplate čuvaju se poslednjih 60 dana; tela zahteva i odgovora čuvaju se poslednjih 30 dana. Za zapise stare 30–60 dana i dalje je moguće pretraživati sažetke kao što su trace, status, vreme, model, upotreba i stvarno naplaćeni iznos, ali `metadata.request` i `metadata.response` u detaljima se više ne vraćaju. Sažeci potrebni za agregaciju modela i statistiku važećih rezultata čuvaju se pre isteka tela. Ako je potrebno dugoročno čuvanje tela, sačuvajte ih sami prilikom poziva.

## Priprema

### 1. Kreiranje tokena naloga

Ovaj interfejs pripada API-ju za upravljanje platformom i zahteva korišćenje **Account Token-a (tokena naloga)**:

1. Prijavite se na [AceDataCloud platformu](https://platform.acedata.cloud).
2. Otvorite [Account Token konzolu](https://platform.acedata.cloud/console/platform-tokens).
3. Kliknite na „Kreiraj“ i odmah sačuvajte token u menadžer lozinki ili Secret Manager.

Za kompletno uputstvo pogledajte [upravljanje tokenima naloga AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-token). Tokeni naloga se koriste za `platform.acedata.cloud/api/v1/**`; za pozivanje poslovnih interfejsa `api.acedata.cloud/**` koriste se API akreditivi (Credential), i ne mogu se mešati.

```shell
export PLATFORM_TOKEN='vaš token naloga'
```

Nemojte upisivati token u frontend kod, logove ili javne repozitorijume; ako procuri, odmah ga izbrišite i ponovo kreirajte u konzoli.

### 2. Priprema ID-ova za filtriranje (opciono)

Bez prosleđivanja uslova filtriranja možete videti zapise koje trenutni nalog ima pravo da vidi. Kada je potrebno suziti opseg:

- `application_id`: preuzmite sa [liste prijava usluga](https://platform.acedata.cloud/documents/platform-application-list);
- `credential_id`: preuzmite sa [liste API akreditiva](https://platform.acedata.cloud/documents/platform-credential-list);
- `api_id`: preuzmite sa [liste API-ja](https://platform.acedata.cloud/documents/platform-api-list);
- `service_id`: preuzmite sa [liste usluga](https://platform.acedata.cloud/documents/platform-service-list).

Obični korisnici ne moraju prosleđivati `user_id`; ako se eksplicitno prosledi, mora se podudarati sa trenutnim nalogom, u suprotnom se vraća `403`. Administratori mogu koristiti ovaj parametar za filtriranje kroz različite naloge.

## Pregled interfejsa

| Stavka           | Sadržaj                                                   |
| ---------------- | --------------------------------------------------------- |
| Metod            | `GET`                                                     |
| URL              | `https://platform.acedata.cloud/api/v1/usage/apis/`       |
| Autentifikacija  | `Authorization: Bearer ${PLATFORM_TOKEN}`                 |
| OAuth Scope      | `usage:read` (`platform:read` / `platform` može prošireno uključivati) |
| Paginacija       | `count` + `items`, podrazumevano 10 stavki po stranici    |

## Opseg upita

| `perspective` | Značenje                                             |
| ------------- | ---------------------------------------------------- |
| `both`        | Podrazumevana vrednost; vraća zapise koje trenutni nalog plaća ili je stvarno pozvao |
| `billing`     | Vraća samo zapise koje trenutni nalog plaća          |
| `actor`       | Vraća samo zapise koje je trenutni nalog stvarno pozvao |

## Parametri upita

| Parametar         | Tip      | Obavezno | Podrazumevano | Opis                                      |
| ----------------- | -------- | ------- | -------------- | ----------------------------------------- |
| `perspective`     | string   | Ne      | `both`         | `billing`, `actor` ili `both`             |
| `user_id`         | UUID     | Ne      | —              | Samo administratori filtriraju po korisniku; podržava ponovljene parametre |
| `service_id`      | UUID     | Ne      | —              | Filtriranje po usluzi; podržava ponovljene parametre |
| `application_id`  | UUID     | Ne      | —              | Filtriranje po Application-u; podržava ponovljene parametre |
| `api_id`          | UUID     | Ne      | —              | Filtriranje po API-ju; podržava ponovljene parametre |
| `credential_id`   | UUID     | Ne      | —              | Filtriranje po API akreditivu; podržava ponovljene parametre |
| `status_code`     | integer  | Ne      | —              | Filtriranje po HTTP statusnom kodu; podržava ponovljene vrednosti ili vrednosti razdvojene zarezom |
| `created_at_from` | datetime | Ne      | —              | Donja granica vremena kreiranja, ISO 8601 |
| `created_at_to`   | datetime | Ne      | —              | Gornja granica vremena kreiranja, ISO 8601 |
| `limit`           | integer  | Ne      | 10             | Broj stavki po stranici, najviše 100      |
| `offset`          | integer  | Ne      | 0              | Pomak paginacije                          |
| `ordering`        | string   | Ne      | `-created_at`  | Opadajući redosled po vremenu kreiranja   |

Kada je vreme zahteva starije od poslednjih 60 dana, interfejs vraća grešku validacije polja `400`, uz obaveštenje da se potpuni detalji poziva čuvaju samo 60 dana.

## Primeri zahteva

Pretraživanje poslednjih 100 zapisa:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/' \
  --data-urlencode 'perspective=both' \
  --data-urlencode 'limit=100' \
  --data-urlencode 'ordering=-created_at' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Filtriranje po vremenu, Application-u i neuspešnom statusu:

```shell
export APPLICATION_ID='vaš Application ID'

curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/' \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'created_at_from=2026-09-01T00:00:00Z' \
  --data-urlencode 'created_at_to=2026-09-02T00:00:00Z' \
  --data-urlencode 'status_code=500' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Python primer paginacije:

```python
import os
import requests

url = "https://platform.acedata.cloud/api/v1/usage/apis/"
headers = {"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"}
params = {"perspective": "both", "limit": 100, "offset": 0}

response = requests.get(url, headers=headers, params=params, timeout=30)
response.raise_for_status()
data = response.json()

for usage in data["items"]:
    print(usage["created_at"], usage["status_code"], usage["deducted_amount"], usage["trace_id"])

if params["offset"] + len(data["items"]) < data["count"]:
    params["offset"] += len(data["items"])
```

## Ključna polja

| Polje                            | Opis                                  |
| -------------------------------- | ----------------------------------- |
| `user_id`                        | Nalog koji snosi ovu naplatu                           |
| `actor_user_id`                  | Nalog koji je stvarno pokrenuo poziv; može se razlikovati od `user_id` kada je drugima odobreno korišćenje akreditiva |
| `used_amount`                    | Količina korišćenja za ovaj poziv izračunata prema originalnim pravilima                       |
| `original_amount`                | Originalna količina korišćenja pre popusta aplikacije                          |
| `deducted_amount`                | Iznos koji je na kraju stvarno oduzet                           |
| `remaining_amount`               | Preostali iznos aplikacije nakon završetka ove naplate           |
| `elapsed`                        | Trajanje poziva koje je zabeležio server, u sekundama                     |
| `trace_id`                       | Identifikator praćenja koji se koristi pri istraživanju pojedinačnog zahteva                      |
| `metadata`                       | Javni metapodaci; lista neće vratiti potpuni sadržaj zahteva ili odgovora               |
| `api` / `service` / `credential` | Sažetak povezanih objekata za lakši prikaz; može biti prazan ako povezani objekat više ne postoji           |

Jedinicu iznosa određuje `service.unit` odgovarajuće aplikacije i ne treba je podrazumevano smatrati američkim dolarima.

## Greške i ponovni pokušaji

| HTTP | `error`                   | Značenje             | Način postupanja                               |
| ---- | ------------------------- | -------------- | ---------------------------------- |
| 400  | Greška validacije polja                    | Opseg upita je stariji od perioda čuvanja od 60 dana | Prilagodite vreme početka tako da bude unutar poslednjih 60 dana                  |
| 401  | `not_authenticated`       | Token naloga nedostaje ili je nevažeći      | Proverite Account Token, nemojte pogrešno koristiti poslovni Credential |
| 403  | `permission_denied`       | Zahtev sadrži zapise za koje nemate ovlašćenje za pregled    | Uklonite neovlašćene uslove filtriranja korisnika                       |
| 429  | `usage_query_in_progress` | Potpuno isti upit se još izvršava    | Sačekajte `Retry-After`, a zatim ponovite pokušaj sa odlaganjem             |
| 503  | `usage_query_timeout`     | Upit premašuje bezbednosno vremensko ograničenje servera    | Suzite vremenski opseg ili dodajte uslove filtriranja, pa pokušajte ponovo                   |

Za isti skup parametara upita može postojati najviše jedan zahtev u toku. Za upite velikog opsega prvenstveno koristite prozor od jednog dana ili manji i nemojte preklapati iste zahteve u fiksnim intervalima.
