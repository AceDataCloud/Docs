„Prijava (Application)“ predstavlja odnos pretplate trenutnog naloga na određenu uslugu — prvo morate podneti prijavu, da biste zatim mogli da kreirate API kredencijale za ovu prijavu i pozivate poslovne interfejse. Pri prvom podnošenju prijave za određenu uslugu, Application će dobiti trenutno konfigurisani `free_amount` te usluge; ova vrednost može biti 0.

> ℹ️ Ovaj interfejs pripada **AceDataCloud API-ju za upravljanje platformom**, sa jedinstvenim prefiksom `https://platform.acedata.cloud/api/v1/`. Kompletan indeks interfejsa pogledajte u [Preuzimanje liste dokumenata AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-document-list).

## Kompletan proces integracije

Novi korisnici obično prolaze kroz ovih 5 koraka od registracije do uspešnog pozivanja prvog poslovnog interfejsa:

1. **Preuzmite token naloga** → [Upravljanje tokenima naloga AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-token)
2. **Izaberite uslugu** → [Preuzimanje liste usluga AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-service-list)
3. **Kreirajte prijavu** (ovaj dokument) → Dobijte početni iznos prema konfiguraciji usluge
4. **Kreirajte API kredencijale** → [Kreiranje API kredencijala AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-credential-create)
5. **Pozovite poslovni interfejs** → Koristite dobijeni 32-bitni Token za pozivanje `https://api.acedata.cloud/<path>`

## Pregled interfejsa

| Stavka            | Sadržaj                                               |
| ------------ | ----------------------------------------------------- |
| Metoda           | `POST`                                                |
| URL          | `https://platform.acedata.cloud/api/v1/applications/` |
| Autentifikacija           | ✅ Potreban je token naloga                                              |
| Content-Type | `application/json`                                    |

## Objašnjenje autentifikacije (kako dobiti token naloga)

Zaglavlje zahteva:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Token naloga (Account Token) je „ključ na nivou naloga“ koji programeri koriste za upravljanje resursima sopstvenog naloga putem API-ja. Načini dobijanja:

1. **Kreiranje jednim klikom u konzoli (preporučeno)**: Prijavite se na [AceDataCloud platformu](https://platform.acedata.cloud) → [Account Token konzola](https://platform.acedata.cloud/console/platform-tokens) → kliknite na „Kreiraj“ da biste dobili token koji počinje sa `platform-v1-`.
2. **Kreiranje putem API-ja**: Koristite postojeći token naloga ili JWT sesiju prijave u pregledaču za pozivanje `POST /api/v1/platform-tokens/`; detalje pogledajte u [Upravljanje tokenima naloga AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-token).

> ⚠️ Token naloga je jednako osetljiv kao lozinka i zabranjeno je upisivati ga u frontend kod ili javna spremišta. U slučaju curenja, odmah ga obrišite i ponovo kreirajte u konzoli.

## Telo zahteva

| Parametar           | Tip   | Obavezno  | Opis                                                                                                  |
| ------------ | ---- | --- | --------------------------------------------------------------------------------------------------- |
| `service_id` | UUID | ✅   | ID usluge za koju se podnosi prijava. Može se dobiti iz `items[].id` na [listi usluga](https://platform.acedata.cloud/documents/platform-service-list) |

## Primer zahteva

### cURL

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/applications/' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'content-type: application/json' \
  -d '{"service_id": "38ecf158-36f2-42f2-8e7f-6786cdfc2452"}'
```

### Python

```python
import os
import requests

PLATFORM_TOKEN = os.environ["PLATFORM_TOKEN"]
SERVICE_ID = "38ecf158-36f2-42f2-8e7f-6786cdfc2452"

resp = requests.post(
    "https://platform.acedata.cloud/api/v1/applications/",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {PLATFORM_TOKEN}",
        "content-type": "application/json",
    },
    json={"service_id": SERVICE_ID},
    timeout=10,
)

if resp.status_code == 201:
    app = resp.json()
    print(f"申请成功！application_id={app['id']}")
    print(f"初始额度：{app['remaining_amount']} {app.get('service', {}).get('unit', '')}")
elif resp.status_code == 400 and resp.json().get("code") == "duplication":
    print("⚠️ 已经申请过此服务，请到 /applications/ 列表里找到现成的 application_id")
else:
    print(f"申请失败：HTTP {resp.status_code} - {resp.text}")
```

### Node.js

```javascript
const PLATFORM_TOKEN = process.env.PLATFORM_TOKEN
const SERVICE_ID = '38ecf158-36f2-42f2-8e7f-6786cdfc2452'

const resp = await fetch('https://platform.acedata.cloud/api/v1/applications/', {
  method: 'POST',
  headers: {
    accept: 'application/json',
    authorization: `Bearer ${PLATFORM_TOKEN}`,
    'content-type': 'application/json',
  },
  body: JSON.stringify({ service_id: SERVICE_ID }),
})

if (resp.status === 201) {
  const app = await resp.json()
  console.log('application_id =', app.id)
} else {
  console.error(await resp.text())
}
```

### Već je podneta prijava (HTTP 400)

```json
{
  "detail": "Item already exists.",
  "code": "duplication",
  "trace_id": "1a87524f8cbba0b790b2951e2e43117e"
}
```

Ovo je strogo ograničenje u dizajnu: **svaki korisnik može imati samo jedan Application za svaku uslugu**. Ako već postoji, pronađite postojeći putem [Preuzimanje liste prijava za AceDataCloud platformsku uslugu](https://platform.acedata.cloud/documents/platform-application-list).

### Usluga ne postoji (HTTP 404)

```json
{
  "detail": "Service not found.",
  "code": "not_found",
  "trace_id": "..."
}
```

### Usluga zahteva odobrenje (HTTP 403)

```json
{
  "detail": "This service requires manual verification.",
  "code": "need_verify",
  "trace_id": "..."
}
```

Ako usluga ima `need_verify=true` (ovo polje je vidljivo na listi usluga), potrebno je proći kroz proces tiketa za podnošenje zahteva za belu listu.

## Obrada grešaka
| HTTP | kod                 | Značenje                   |
| ---- | ------------------- | -------------------------- |
| 400  | `duplication`       | Ovu uslugu je trenutni nalog već zatražio |
| 400  | `invalid`           | `service_id` nedostaje ili je format pogrešan |
| 401  | `not_authenticated` | Nedostaje token naloga ili je token obrisan |
| 403  | `need_verify`       | Usluga zahteva odobrenje, molimo koristite proces tiketa |
| 404  | `not_found`         | Usluga ne postoji ili je povučena |

Jedinstveni format odgovora greške:

```json
{
  "detail": "...",
  "code": "...",
  "trace_id": "..."
}
```

## Praktični saveti

- **Samo kreiranje se ne naplaćuje**: pri prvom kreiranju početni limit se postavlja prema trenutnom `free_amount` usluge; ova vrednost može biti 0, a ponovno kreiranje iste vrste Application ne garantuje ponavljanje poklona.
- **Da li je potrebno plaćanje, proverite u polju `paid`**: odmah nakon prijave `paid=false`, a nakon pozivanja [Kreiranje naloga za dopunu AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-order-create) i završetka plaćanja postaje `true`.
- **`disabled=true` označava da je privremeno onemogućeno** — na primer, aktiviranje kontrole rizika, dugovanja itd. Kada je onemogućeno, poslovni interfejs će vratiti `403`.
- **Nemojte kreirati bez ograničenja paralelno**: prvo preuzmite ciljni `service_id` iz paginirane liste usluga, a zatim podnesite prijavu za svaku stavku prema poslovnim potrebama; kada naiđete na `duplication`, ponovo koristite postojeći Application.
