„Zahtev (Application)“ predstavlja odnos pretplate trenutnog naloga na određenu uslugu — najpre morate podneti zahtev, da biste zatim za taj zahtev mogli da kreirate API akreditive i pozivate poslovne interfejse. Prilikom prvog podnošenja zahteva za određenu uslugu, Application će dobiti trenutno konfigurisani `free_amount` te usluge; ova vrednost može biti 0.

> ℹ️ Ovaj interfejs pripada **API-ju za upravljanje AceDataCloud platformom**, sa jedinstvenim prefiksom `https://platform.acedata.cloud/api/v1/`. Za kompletan indeks interfejsa pogledajte [Preuzimanje liste AceDataCloud platformskih dokumenata](https://platform.acedata.cloud/documents/platform-document-list).

## Kompletan proces integracije

Novi korisnici od registracije do uspešnog pozivanja prvog poslovnog interfejsa obično prolaze kroz ovih 5 koraka:

1. **Preuzmite token naloga** → [Upravljanje tokenima naloga AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-token)
2. **Odaberite uslugu** → [Preuzimanje liste usluga AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-service-list)
3. **Kreirajte zahtev** (ovaj dokument) → Dobijte početnu kvotu prema konfiguraciji usluge
4. **Kreirajte API akreditive** → [Kreiranje API akreditiva AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-credential-create)
5. **Pozovite poslovni interfejs** → Koristite dobijeni 32-bitni Token za pozivanje `https://api.acedata.cloud/<path>`

## Pregled interfejsa

| Stavka            | Sadržaj                                               |
| ----------------- | ----------------------------------------------------- |
| Metod             | `POST`                                                |
| URL               | `https://platform.acedata.cloud/api/v1/applications/` |
| Autentifikacija   | ✅ Potreban je token naloga                           |
| Content-Type      | `application/json`                                    |

## Objašnjenje autentifikacije (kako dobiti token naloga)

Zaglavlje zahteva:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Token naloga (Account Token) je „ključ na nivou naloga“ koji programeri koriste za upravljanje resursima sopstvenog naloga putem API-ja. Načini dobijanja:

1. **Kreiranje jednim klikom u konzoli (preporučeno)**: Prijavite se na [AceDataCloud platformu](https://platform.acedata.cloud) → [Account Token konzola](https://platform.acedata.cloud/console/platform-tokens) → kliknite na „Kreiraj“ da biste dobili token koji počinje sa `platform-v1-`.
2. **Kreiranje putem API-ja**: Koristite postojeći token naloga ili JWT iz stanja prijave u pregledaču da pozovete `POST /api/v1/platform-tokens/`; za detalje pogledajte [Upravljanje tokenima naloga AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-token).

> ⚠️ Token naloga je jednako osetljiv kao i lozinka i ne sme se unositi u frontend kod ili javne repozitorijume. U slučaju curenja, odmah ga obrišite u konzoli i kreirajte novi.

## Telo zahteva

| Parametar    | Tip  | Obavezno | Opis                                                                                                  |
| ------------ | ---- | -------- | ----------------------------------------------------------------------------------------------------- |
| `service_id` | UUID | ✅       | ID usluge za koju se podnosi zahtev. Može se preuzeti iz `items[].id` u [listi usluga](https://platform.acedata.cloud/documents/platform-service-list) |

## Primeri zahteva

### cURL

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/applications/' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'content-type: application/json' \
  -d '{"service_id": "38ecf158-36f2-42f2-8e7f-6786cdfc2452"}'
```

### Python

```python
import os
import requests

PLATFORM_TOKEN = os.environ["PLATFORM_TOKEN"]
SERVICE_ID = "38ecf158-36f2-42f2-8e7f-6786cdfc2452"

resp = requests.post(
    "https://platform.acedata.cloud/api/v1/applications/",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {PLATFORM_TOKEN}",
        "content-type": "application/json",
    },
    json={"service_id": SERVICE_ID},
    timeout=10,
)

if resp.status_code == 201:
    app = resp.json()
    print(f"申请成功！application_id={app['id']}")
    print(f"初始额度：{app['remaining_amount']} {app.get('service', {}).get('unit', '')}")
elif resp.status_code == 400 and resp.json().get("code") == "duplication":
    print("⚠️ 已经申请过此服务，请到 /applications/ 列表里找到现成的 application_id")
else:
    print(f"申请失败：HTTP {resp.status_code} - {resp.text}")
```

### Node.js

```javascript
const PLATFORM_TOKEN = process.env.PLATFORM_TOKEN
const SERVICE_ID = '38ecf158-36f2-42f2-8e7f-6786cdfc2452'

const resp = await fetch('https://platform.acedata.cloud/api/v1/applications/', {
  method: 'POST',
  headers: {
    accept: 'application/json',
    authorization: `Bearer ${PLATFORM_TOKEN}`,
    'content-type': 'application/json',
  },
  body: JSON.stringify({ service_id: SERVICE_ID }),
})

if (resp.status === 201) {
  const app = await resp.json()
  console.log('application_id =', app.id)
} else {
  console.error(await resp.text())
}
```

### Već je podnet zahtev (HTTP 400)

```json
{
  "detail": "Item already exists.",
  "code": "duplication",
  "trace_id": "1a87524f8cbba0b790b2951e2e43117e"
}
```

Ovo je strogo ograničenje po dizajnu: **svaki korisnik može imati samo jedan Application za svaku uslugu**. Ako već postoji, pronađite postojeći putem [Preuzimanja liste zahteva za AceDataCloud platformsku uslugu](https://platform.acedata.cloud/documents/platform-application-list).

### Usluga ne postoji (HTTP 404)

```json
{
  "detail": "Service not found.",
  "code": "not_found",
  "trace_id": "..."
}
```

### Usluga zahteva odobrenje (HTTP 403)

```json
{
  "detail": "This service requires manual verification.",
  "code": "need_verify",
  "trace_id": "..."
}
```

Ako je za uslugu `need_verify=true` (ovo polje se može videti u listi usluga), potrebno je proći kroz proces tiketa za podnošenje zahteva za belu listu.

## Obrada grešaka
| HTTP | kod                | Značenje                   |
| ---- | ------------------- | -------------------- |
| 400  | `duplication`       | Uslugu je već zatražio trenutni nalog         |
| 400  | `invalid`           | `service_id` nedostaje ili je format neispravan |
| 401  | `not_authenticated` | Nedostaje token naloga ili je token obrisan        |
| 403  | `need_verify`       | Usluga zahteva odobrenje, molimo pratite proces putem tiketa        |
| 404  | `not_found`         | Usluga ne postoji ili je povučena            |

Jedinstveni format odgovora za greške:

```json
{
  "detail": "...",
  "code": "...",
  "trace_id": "..."
}
```

## Praktični saveti

- **Samo kreiranje se ne naplaćuje**: pri prvom kreiranju se postavlja početna kvota prema trenutnom `free_amount` usluge; ova vrednost može biti 0, a ponovljeno kreiranje iste vrste Application ne garantuje ponovnu dodelu.
- **Da li je potrebno plaćanje proverava se putem polja `paid`**: odmah nakon prijave `paid=false`, a nakon što pozovete [Kreiranje naloga za dopunu na AceDataCloud platformi](https://platform.acedata.cloud/documents/platform-order-create) i završite plaćanje, postaje `true`.
- **`disabled=true` znači da je privremeno onemogućeno** — na primer, zbog aktiviranja kontrole rizika, neplaćenih dugovanja itd. Kada je onemogućeno, poslovni interfejs vraća `403`.
- **Nemojte kreirati neograničeno paralelno**: prvo iz paginirane liste usluga preuzmite ciljni `service_id`, zatim podnosite zahteve stavku po stavku prema poslovnim potrebama; kada naiđete na `duplication`, ponovo upotrebite postojeći Application.
