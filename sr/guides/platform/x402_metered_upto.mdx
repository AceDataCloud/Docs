Ace Data Cloud X402 trenutno koristi dve vrste scheme: `exact` i `upto`. One rešavaju različite probleme naplate.

## `exact`

`exact` znači da se cena za ovaj zahtev može odrediti pre nego što uđe u ciljni API. Iznos koji klijent potpisuje je konačni iznos naplate.

Pogodno za:

- generisanje slika sa fiksnom cenom;
- kreiranje video zadataka sa fiksnom cenom;
- API-je za pretragu ili alate sa fiksnom cenom;
- plaćanje porudžbine.

EVM `exact` koristi USDC EIP-3009 `TransferWithAuthorization`:

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "exact",
    "network": "eip155:8453"
  },
  "payload": {
    "authorization": {
      "from": "0x...",
      "to": "0x...",
      "value": "95215",
      "validAfter": "1780237345",
      "validBefore": "1780240945",
      "nonce": "0x..."
    },
    "signature": "0x..."
  }
}
```

Facilitator u fazi `/verify` proverava potpis i iznos, a u fazi `/settle` podnosi ovu autorizaciju na blockchain.

## `upto`

`upto` znači da klijent autorizuje maksimalnu gornju granicu, a Ace Data Cloud nakon završetka zahteva vrši naplatu prema stvarnoj potrošnji; stvarna naplata ne može premašiti gornju granicu.

Pogodno za:

- dopunjavanje četa: konačna cena zavisi od prompt tokena i completion tokena;
- striming odgovore: stvarna dužina izlaza je poznata tek po završetku;
- buduće API-je sa naknadnim merenjem potrošnje.

`upto` koristi Permit2 `PermitWitnessTransferFrom`. Klijent ne potpisuje fiksni prenos, već autorizaciju gornje granice sa witness-om:

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "upto",
    "network": "eip155:8453"
  },
  "payload": {
    "permit2Authorization": {
      "from": "0x...",
      "spender": "0x4020A4f3b7b90ccA423B9fabCc0CE57C6C240002",
      "nonce": "123456789",
      "deadline": "1780240945",
      "permitted": {
        "token": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
        "amount": "95215"
      },
      "witness": {
        "to": "0x...",
        "facilitator": "0x...",
        "validAfter": "1780237345"
      }
    },
    "signature": "0x..."
  }
}
```

`permitted.amount` je gornja granica, a ne nužno konačna naplata. Gateway će u fazi `/record` stvarnu potrošnju pretvoriti u `amount` i proslediti ga Facilitator-u. Facilitator dozvoljava samo naplatu gde je `amount &lt;= permitted.amount`.

Rezultat izvršavanja Base `upto` programa:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
signed ceiling 95215 atomic USDC
transfer value 3 atomic USDC
```

Objašnjenje:

- Gornja granica autorizacije vraćena u 402 je `95215` atomic USDC, i klijent potpisuje prema toj gornjoj granici.
- Nakon stvarnog odgovora modela naplaćeno je samo `3` atomic USDC, a transakcija na blockchainu se može pronaći na BaseScan-u.
- Ovaj rezultat pokazuje ključnu razliku `upto` modela: potpisani iznos je gornja granica, a settlement na blockchainu može biti manji od gornje granice.
- Ako stvarna potrošnja premaši gornju granicu, Facilitator treba da odbije settlement, a klijent mora ponovo autorizovati višu gornju granicu.

`upto` je trenutno dostupan samo na Base-u. Kada je potrebno naknadno merenje potrošnje, koristite Base.

## Zašto je potreban Permit2 approve

`upto` na kraju omogućava x402 proxy-ju da preko Permit2 povuče USDC iz novčanika platioca. Pre prve upotrebe, novčanik platioca treba jednom da dodeli ERC-20 allowance Permit2-u.

Python CLI:

```bash
pip install 'acedatacloud-x402[cli]'
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Programski način:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Nakon završetka autorizacije, svaki zahtev i dalje mora potpisati novi `upto` envelope, jer su nonce, deadline, witness i gornja granica iznosa različiti.

## Naplata nultog iznosa

`upto` podržava slučaj kada je stvarni iznos 0. Na primer, ako ciljni API nije uspešno proizveo naplativu potrošnju, Gateway može proslediti `amount = "0"`. Facilitator će vratiti uspeh, ali neće poslati transakciju na blockchain.

Ovo može izbeći problem „zahtev nije uspeo, ali su i dalje naplaćene naknade na blockchainu“.

## Preporuke za izbor

| Scenario                   | Preporuka                       |
| -------------------------- | ------------------------------- |
| API sa fiksnom cenom       | Koristite `exact`, logika je jednostavna. |
| Plaćanje porudžbine        | Koristite `exact`.              |
| Dopunjavanje četa, naplata po tokenu | Koristite Base `upto`.          |
| Permit2 approve još nije urađen | Prvo pokrenite `exact`, a zatim pređite na `upto`. |

Ako niste sigurni koji da izaberete, prvo koristite podrazumevano ponašanje SDK-a; SDK će izabrati payment requirement odgovarajuće mreže koji server vrati.

## Kontrolna lista za Base `upto`

Prilikom integracije ili otklanjanja problema, potvrdite da sledeći parametri dolaze iz istog 402 odgovora i da ostaju dosledni prilikom potpisivanja od strane klijenta:

| Parametar                  | Tačka provere                                          |
| -------------------------- | ------------------------------------------------------ |
| `network`                  | Mora biti `eip155:8453`.                               |
| `scheme`                   | Mora biti `upto`.                                      |
| `extra.chainId`            | Base chain id je `8453`.                               |
| `asset`                    | Koristite Base USDC adresu ugovora iz 402 odgovora.    |
| `extra.facilitatorAddress` | Mora učestvovati u witness-u i odgovarati Facilitator `/supported`. |
| Permit2 allowance          | Novčanik platioca mora prvo autorizovati Permit2 za Base USDC. |

Uobičajene greške i načini rešavanja:

| Greška                                        | Način rešavanja                                                                          |
| -------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `invalid_upto_evm_payload_invalid_signature` | Proverite da li su chain id, adresa facilitator-a, Permit2 domain, spender, nalog potpisa i witness u skladu sa 402 odgovorom. |
| `PERMIT2_ALLOWANCE_REQUIRED`                 | Nakon izvršavanja Permit2 approve za USDC na ciljnom lancu, ponovo pokrenite zahtev.     |
| `amount exceeds permitted amount`            | Stvarna potrošnja premašuje potpisanu gornju granicu; potrebno je ponovo potpisati višu gornju granicu. |
