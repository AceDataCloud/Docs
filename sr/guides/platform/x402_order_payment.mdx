Pored direktnog plaćanja po API zahtevu, Ace Data Cloud takođe podržava plaćanje narudžbina pomoću X402. Osnovni protokol za plaćanje narudžbina i API pozive je isti: prvi zahtev vraća 402, klijent potpisuje `PAYMENT-SIGNATURE`, a zatim ponavlja zahtev sa istim zahtevom.

Razlika je u tome što plaćanje narudžbina pripada platformskom API-ju i zahteva token naloga; dok AI API koji direktno poziva `x402.acedata.cloud` može koristiti samo X402, bez potrebe za API tokenom.

## Priprema narudžbine

Uđite u [Ace Data Cloud konzolu](https://platform.acedata.cloud/console/orders), izaberite narudžbinu koju treba platiti i zabeležite ID narudžbine.

Ako još nemate narudžbinu, možete kreirati narudžbinu na čekanju za plaćanje na stranici paketa. Cena narudžbine zavisi od prikaza na stranici, a `amount` u X402 402 odgovoru je konačna osnova za potpisivanje.

## Kreiranje tokena naloga

Zahtev za plaćanje narudžbine zahteva token naloga. Otvorite [stranicu platformskih tokena](https://platform.acedata.cloud/console/platform-tokens), kreirajte token u formatu `platform-v1-...`.

Za naredne zahteve koristite:

```http
Authorization: Bearer {platform_token}
```

Token naloga se razlikuje od običnog API tokena. Običan API token se koristi za trošenje API kredita; token naloga se koristi za predstavljanje vašeg naloga pri upravljanju resursima platforme, kao što je plaćanje narudžbina.

## Pokretanje 402

Prvo pošaljite zahtev bez `PAYMENT-SIGNATURE`:

```http
POST https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/
Authorization: Bearer {platform_token}
Content-Type: application/json

{
  "pay_way": "X402"
}
```

Vraćeni status je 402, a odgovor sadrži `accepts`:

```json
{
  "x402Version": 2,
  "error": "Payment required for this order.",
  "resource": {
    "url": "http://platform.acedata.cloud/api/v1/orders/.../pay/",
    "description": "Ace Data Cloud Credits x 10.0",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "amount": "1200000",
      "payTo": "0x...",
      "maxTimeoutSeconds": 120,
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
        "decimals": 6
      }
    }
  ],
  "paywall": {
    "app_name": "Ace Data Cloud",
    "app_logo": "https://cdn.acedata.cloud/favicon.ico"
  }
}
```

Plaćanje narudžbine koristi zvanični x402 v2: `x402Version` je `2`, `network` koristi CAIP-2 identifikator, a polje iznosa je `amount`.

Rezultat izvršavanja programa za kreiranje narudžbine od 10 Credits i pokretanje 402:

> Sledeći zapisi transakcija su istorijski uzorci stvarnih testiranja prema staroj politici, a iznosi i heševi transakcija zadržani su u izvornom obliku. Nove X402 narudžbine više nemaju popust na način plaćanja; koristite `amount` iz ovog 402 odgovora kao osnovu za potpisivanje i plaćanje.

```text
created order 78481793-304e-47f7-bc0c-8231aec9cc1e
created state Pending
created price 1.26

http_status=402
x402Version 2
error Payment required for this order.
accepts [
  ('eip155:8453', 'exact', '1200000', '0x4F0E2D3477a1B94CF33d16E442CEe4733dadCeE7'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '1200000', '5iVXFrYaYWX2GUTbkQj8mDBoBhAX8bneYigS2LJTia43')
]
description Ace Data Cloud Credits x 10.0
```

Objašnjenje rezultata:

- Nakon uspešnog kreiranja narudžbine, status je `Pending`, i u tom trenutku još nema plaćanja na lancu.
- Prvi `pay/` zahtev ne sadrži `PAYMENT-SIGNATURE`, pa vraća HTTP 402.
- `accepts` istovremeno daje Base `exact` i Solana `exact`, a ovaj vodič u nastavku bira Base.
- Cena pri kreiranju narudžbine je `1.26`, a tokom stare politike popusta za X402 plaćanje, stvarni potpisani i obračunati iznos je `1.2` USDC, što odgovara `1200000` atomic USDC.

Imajte na umu da je ovde `resource` polje koje vraća server i koje učestvuje u potpisivanju, klijent ne treba samostalno menjati protokol, putanju ili ID narudžbine u njemu.

## Potpisivanje i ponavljanje

Plaćanje narudžbine može ponovo koristiti funkcije potpisivanja niskog nivoa iz `@acedatacloud/x402-client` ili `acedatacloud-x402`. U nastavku je TypeScript primer:

```ts
import { Wallet } from 'ethers';
import { signEVMPayment } from '@acedatacloud/x402-client';

const platformToken = process.env.ACE_PLATFORM_TOKEN!;
const orderId = process.env.ACE_ORDER_ID!;
const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const url = `https://platform.acedata.cloud/api/v1/orders/${orderId}/pay/`;
const body = { pay_way: 'X402' };

const first = await fetch(url, {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${platformToken}`,
    'Content-Type': 'application/json'
  },
  body: JSON.stringify(body)
});

if (first.status !== 402) {
  throw new Error(`expected 402, got ${first.status}`);
}

const paymentRequired = await first.json();
const requirement = paymentRequired.accepts.find(
  (item: any) => item.network === 'eip155:8453' && item.scheme === 'exact'
);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') throw new Error(`unsupported method: ${method}`);
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const envelope = await signEVMPayment(requirement, evmProvider, wallet.address);
const xPayment = Buffer.from(JSON.stringify(envelope), 'utf8').toString('base64');

const paid = await fetch(url, {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${platformToken}`,
    'Content-Type': 'application/json',
    'PAYMENT-SIGNATURE': xPayment
  },
  body: JSON.stringify(body)
});

if (!paid.ok) {
  throw new Error(`payment failed: ${paid.status} ${await paid.text()}`);
}

console.log(await paid.json());
```

Rezultat izvršavanja programa nakon potpisivanja i ponavljanja iste narudžbine sa Base `exact`:

```text
status 200
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
has_x_payment_response True
settle_header {'success': True, 'network': 'base', 'transaction': '0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151', 'errorReason': None}
order {'id': '78481793-304e-47f7-bc0c-8231aec9cc1e', 'state': 'Finished', 'pay_way': 'X402', 'price': 1.2, 'pay_id': '0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151'}
```

Rezultat potvrde na lancu:
```text
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
status 1
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer {"from":"0x5d4f08D5c2bb60703284bc06671Eb680fA41B105","to":"0x4F0E2D3477a1B94CF33d16E442CEe4733dadCeE7","value":"1200000"}
```

Objašnjenje rezultata:

- `status 200` označava da je interfejs za plaćanje narudžbine platforme prihvatio ovaj `PAYMENT-SIGNATURE`.
- `has_x_payment_response True` označava da zaglavlje odgovora sadrži Base64 kodiranu potvrdu `PAYMENT-RESPONSE`.
- `settle_header.success=True` i `network=base` označavaju da je Facilitator završio Base settlement.
- Konačni status narudžbine je `Finished`, `pay_way` je `X402`, a `pay_id` upisuje heš transakcije na lancu.
- Događaj `Transfer` na BaseScan-u pokazuje da je adresa platioca prenela `1200000` atomic USDC na adresu platforme za prijem uplata, odnosno `1.2` USDC.

## Uspešan odgovor i potvrda

Nakon uspešnog plaćanja narudžbine, telo odgovora sadrži informacije o narudžbini. Platforma će takođe u zaglavlju odgovora `PAYMENT-RESPONSE` preneti Base64 kodirani settlement response, a uobičajena polja nakon dekodiranja uključuju:

| Polje            | Objašnjenje                           |
| ------------- | ---------------------------- |
| `success`     | Da li je Facilitator settlement uspešan. |
| `transaction` | Heš transakcije settlementa na lancu.                    |
| `network`     | Mreža plaćanja.                        |
| `payer`       | Adresa novčanika platioca.                      |
| `amount`      | Stvarni iznos settlementa, koristi atomic units.      |

Ako vam je potrebno usklađivanje, preporučuje se da istovremeno sačuvate ID narudžbine, adresu novčanika platioca, `transaction` i konačni status narudžbine.

## Napomene

- Za plaćanje narudžbine je potreban token naloga platforme, ne može se izvršiti samo pomoću X402 potpisa novčanika.
- `amount` koristi USDC atomic units, `1200000` predstavlja `1.2` USDC.
- Nemojte sami sastavljati adresu primaoca ili adresu sredstva, već se oslonite na `accepts` u odgovoru 402.
- Ako se isti `PAYMENT-SIGNATURE` ponovo pošalje, Facilitator će koristiti nonce za zaštitu od ponavljanja.

## Odgovor pri neuspešnom plaćanju

Prvi HTTP 402 bez `PAYMENT-SIGNATURE` je normalan izazov za plaćanje i ne predstavlja neuspeh plaćanja. Neuspeh verifikacije ili settlementa nakon potpisivanja i dalje zadržava standardni string `error` kao kompatibilnu rezervnu opciju, a stabilna struktura greške se vraća u `extensions.acedatacloud.paymentError`:

```json
{
  "code": "insufficient_token_balance",
  "params": { "network": "eip155:8453" },
  "stage": "verify",
  "retryable": true,
  "charged": false
}
```

Klijent treba prvenstveno da lokalizuje prema `code`, a za nepoznat code da se vrati na opšti neuspeh plaćanja. `charged` je trostano polje: `false` će biti vraćeno samo kada je plaćanje izričito odbijeno pre settlementa; odsustvo polja znači da je status naplate nepoznat i ne može se tumačiti kao „nije naplaćeno“. Nakon što trenutna narudžbina pređe u `Failed`, ne može se pokušati ponovo sa istom narudžbinom; nakon ispravljanja problema sa novčanikom, kreirajte novu narudžbinu.

`metadata.x402.last_error` i `metadata.x402.errors` u listi i detaljima narudžbina zadržavaju istu grupu `code`, `stage`, `retryable`, `charged` i `params`; javni opisni tekst se čuva u `reason`, a vreme nastanka se čuva u `timestamp`. Na primer, `insufficient_token_balance` označava nedovoljan USDC saldo na izabranoj mreži, a `invalid_signature` označava nevažeći potpis plaćanja; ponovno čitanje narudžbine ih neće promeniti u opšti `payment_failed`.

Nemojte beležiti niti slati potpuni `PAYMENT-SIGNATURE`, potpis novčanika, autorizacioni payload, izvorne Facilitator dijagnostike ili RPC odgovore. Korisničkoj podršci su za proveru potrebni samo ID narudžbine i javni `code` greške.

## ACE otkup i spaljivanje za Base i Solana plaćanja

Nakon omogućavanja strategije otkupa, 3% stvarno primljenog iznosa prihvatljivog Circle USDC na Base glavnoj mreži i USDC na Solana glavnoj mreži koristi se za kupovinu i spaljivanje ACE, bez dodatne naplate novčaniku platioca. Obračun se vrši jednom prilikom dopune, a kasnije korišćenje ovih Credits za pozivanje API-ja ne obračunava se ponovo; istorijske narudžbine sa popustom i narudžbine po starim strategijama se ne obračunavaju retroaktivno.

Base plaćanja zadržavaju potvrde o plaćanju na Base lancu, dok se kupovina i spaljivanje ACE izvršavaju asinhrono na Solana mreži. Za prihvatljiva plaćanja precizno se obračunava 3% prema stvarno primljenom iznosu, bez fiksnog ograničenja iznosa otkupa po transakciji ili dnevno; raspoloživa sredstva, tržišne kotacije i potvrde na lancu i dalje mogu uticati na vreme završetka. Objekat `ace_burn` u detaljima narudžbine pruža `settlement_network`, `settlement_transaction` i `execution_network`, a nakon završetka pruža `swap_signature` i `burn_signature`. `Pending` ili `Processing` ne znači da je spaljivanje izvršeno; samo `Completed` predstavlja da je konačni dokaz na lancu proverен. Kada Base plaćanje još nije dostiglo konačnu potvrdu, otkup će čekati potvrdu, ali to ne utiče na već pristigle Credits.
