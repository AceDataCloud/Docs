Ovo uputstvo koristi minimalan API zahtev da objasni kompletan tok Ace Data Cloud X402. Cilj nije da se prvo piše složen kod, već da se prvo razume: zašto prvi zahtev vraća 402, šta se nalazi u `accepts` i kako `PAYMENT-SIGNATURE` pretvara isti API zahtev u plaćeni zahtev.

## Priprema

Potrebno je da pripremite:

| Stavka   | Objašnjenje                                                   |
| ---- | ---------------------------------------------------- |
| Novčanik   | Novčanik koji podržava ciljnu mrežu. Base koristi EVM novčanik, Solana koristi Solana novčanik.      |
| USDC | U novčaniku mora biti dovoljno USDC-a. Stvarni iznos zavisi od `maxAmountRequired` u odgovoru 402. |
| Razvojno okruženje | Za TypeScript se preporučuje Node.js 18+; za Python se preporučuje Python 3.10+.    |
| SDK  | Preporučuje se korišćenje zvaničnog SDK-a, ne preporučuje se ručno pisanje detalja potpisa.                                |

X402 pozivanje Ace Data Cloud API-ja ne zahteva API Token. SDK pri prvom zahtevu ne šalje `Authorization`, Gateway vraća `402 Payment Required` i zahteve za plaćanje; SDK nakon potpisivanja automatski ponavlja zahtev.

## Instaliranje SDK-a

Izvorni kod i adrese paketa:

- SDK repozitorijum: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- X402 Client repozitorijum: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm: `@acedatacloud/sdk`、`@acedatacloud/x402-client`
- PyPI: `acedatacloud`、`acedatacloud-x402`

TypeScript:

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client ethers
```

Python:

```bash
pip install acedatacloud acedatacloud-x402
```

Ako želite da koristite Solana, potrebno je instalirati i odgovarajuće zavisnosti:

```bash
npm install @solana/web3.js
```

Zavisnost za Solana signer u Python verziji već je uključena u `acedatacloud-x402`.

Izlaz provere instalacije i uvoza u čistom privremenom okruženju:

```text
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4

acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
```

Objašnjenje rezultata:

- I npm paketi i PyPI paketi su stvarno objavljeni paketi, a ne nazivi rezervisani u dokumentaciji.
- `acedatacloud-x402[cli]` instalira CLI, a potkomanda `approve-permit2` može se koristiti za Permit2 autorizaciju u `upto` scenarijima.

## Prvi zahtev vraća 402

Možete prvo koristiti `curl` da vidite šta vraća neplaćeni zahtev. Primer u nastavku neće izazvati naplatu, jer ne nosi `PAYMENT-SIGNATURE`:

```bash
curl -sS -X POST https://x402.acedata.cloud/openai/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "hi"}],
    "max_tokens": 1
  }'
```

Telo odgovora će sadržati niz `accepts`, sa uobičajenom strukturom kao što je sledeća:

```json
{
  "x402Version": 2,
  "resource": {
    "url": "/openai/chat/completions",
    "description": "AceDataCloud API call",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "maxAmountRequired": "95215",
      "amount": "95215",
      "maxTimeoutSeconds": 3600,
      "resource": "/openai/chat/completions",
      "description": "...",
      "payTo": "0x...",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913"
      }
    }
  ],
  "error": "PAYMENT-SIGNATURE header is required"
}
```

Isti sadržaj izazova takođe se nalazi u base64 formatu u odgovornom zaglavlju `PAYMENT-REQUIRED`, što klijentu olakšava čitanje zahteva za plaćanje bez parsiranja body-ja.

Sažetak programskog izlaza za neplaćeni zahtev produkcionog API-ja je sledeći:

```text
status=402
x402Version 2
accepts [
  ('eip155:8453', 'exact', '95215'),
  ('eip155:8453', 'upto', '95215'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '95215'),
]
```

Objašnjenje rezultata:

- Prvi zahtev ne nosi `Authorization` niti `PAYMENT-SIGNATURE`, zato vraća HTTP 402 i neće izazvati naplatu.
- `accepts` je jedina pouzdana osnova za potpisivanje ovog zahteva i sadrži dostupne mreže, scheme, gornju granicu iznosa, adresu primaoca i adresu sredstva.
- `network` je CAIP-2 identifikator i klijent pri izboru mreže mora da ga podudari prema CAIP-2 stringu.
- Gornji iznos za ovaj minimalni chat zahtev `gpt-4o-mini` je `95215` atomic USDC, odnosno `0.095215` USDC.
- Za svaki zahtev treba pročitati trenutni odgovor 402, a ne hardkodirati primer iznosa u poslovni kod.

Značenje polja:

| Polje                  | Objašnjenje                                                             |
| ------------------- | -------------------------------------------------------------- |
| `scheme`            | Šema plaćanja. `exact` označava fiksni iznos, a `upto` označava gornju granicu autorizacije i obračun prema stvarnoj potrošnji.                     |
| `network`           | CAIP-2 identifikator mreže za plaćanje, na primer `eip155:8453`、`solana:5eykt4...`.           |
| `maxAmountRequired` | Maksimalni iznos plaćanja, u USDC atomic units; `95215` označava `0.095215` USDC.       |
| `amount`            | Iznos koji se obračunava ovog puta; `exact` je isti kao `maxAmountRequired`, dok se `upto` u fazi obračuna prepisuje prema stvarnoj potrošnji. |
| `payTo`             | Adresa primaoca.                                                          |
| `asset`             | Adresa USDC ugovora ili Solana mint adresa.                                     |
| `extra`             | Proširene informacije potrebne za potpisivanje, kao što su chain ID, EIP-712 domain i Permit2 adresa.                      |

## Dovršavanje ponovnog pokušaja plaćanja pomoću SDK-a

U nastavku je minimalni TypeScript primer. On navodi `network: 'base'`, a handler će iz trenutnog odgovora 402 izabrati Base payment requirement; stvarni iznos i adresa primaoca i dalje zavise od `accepts`:
```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const response = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Reply with exactly: hello' }],
  max_tokens: 8
});

console.log(response.choices[0].message.content);
```

Iza ovog koda dešavaju se četiri koraka:

1. SDK šalje jedan običan API zahtev, bez `Authorization`.
2. Gateway vraća `402 Payment Required` i `accepts`.
3. `createX402PaymentHandler` bira payment requirement za `network = 'base'` i potpisuje `PAYMENT-SIGNATURE`.
4. SDK ponavlja pokušaj sa istim telom zahteva, a Gateway poziva Facilitator radi verifikacije i poravnanja, nakon čega propušta zahtev do ciljnog API-ja.

## Pregled podržanih mogućnosti Facilitator-a

X402 API ne zavisi od direktorijuma resursa. Klijent direktno poziva poznati API i koristi
`402 Payment Required` i `accepts` koje taj zahtev vrati u realnom vremenu kao jedinu osnovu za cenu i potpis.

Izjava o mogućnostima Facilitator-a nalazi se na:

```bash
curl https://facilitator.acedata.cloud/.well-known/x402
```

Ona opisuje samo `/supported`, `/verify`, `/settle` i trenutno omogućene mreže za plaćanje, bez navođenja API resursa.

Adresa produkcionog Facilitator-a za Ace Data Cloud je:

```text
https://facilitator.acedata.cloud
```

Možete proveriti koje mreže i scheme podržava:

```bash
curl https://facilitator.acedata.cloud/supported
```

Vraćeni `kinds` navodi mreže i scheme koje Facilitator podržava. Pri stvarnom pozivu i dalje se kao merodavan koristi `accepts` koji vraća API.

Izlaz Facilitator `/supported`:

```text
kinds [
  ('eip155:8453', 'exact'),
  ('eip155:8453', 'upto', {'facilitatorAddress': '0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708'}),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact')
]
```

Rezultat pokazuje:

- `/supported` pokazuje da Facilitator ima mogućnosti verifikacije i poravnanja za ove mreže i scheme.
- Base i Solana oba podržavaju `exact`; `upto` je trenutno dostupan samo na Base-u.
- Da li određeni API dozvoljava konkretnu mrežu i dalje zavisi od 402 `accepts` tog API-ja.
