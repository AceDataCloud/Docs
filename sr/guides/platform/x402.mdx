X402 је на основу HTTP `402 Payment Required` ланчаног плаћања протокол. Кроз X402 способности Ace Data Cloud, позиваоци могу да изврше ланчано плаћање директно са USDC без креирања API токена или пре-плаћања стања на рачуну у свакој API захтеву.

Ова група докумената је организована по редоследу реалне интеграције: прво извршите минимални захтев, затим интегришите SDK, а потом разумите мрежу, тарифне планове, плаћање поруџбина и Facilitator. Препоручује се да читате по табли од горе ка доле.

## Препоручени пут интеграције

Ако само желите да позовете Ace Data Cloud API, прво користите званични SDK:

- TypeScript: `@acedatacloud/sdk` + `@acedatacloud/x402-client`
- Python: `acedatacloud` + `acedatacloud-x402`

Јавни изворни код и адресе пакета:

| Пројекат              | Адреса                                                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Ace Data Cloud SDK  | [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)                                         |
| X402 Клијент        | [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)                           |
| X402 Facilitator     | [https://github.com/AceDataCloud/FacilitatorX402](https://github.com/AceDataCloud/FacilitatorX402)                 |
| npm SDK             | [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)                 |
| npm X402 Клијент    | [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client) |
| PyPI SDK            | [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)                                   |
| PyPI X402 Клијент   | [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)                         |

SDK ће аутоматски завршити први захтев без аутентификације, анализирати `402 Payment Required`, позвати payment handler, и поново покушати ове кораке са `PAYMENT-SIGNATURE`. Само треба да припремите новчаник са USDC и изаберете мрежу коју желите да користите.

Ако желите да ваш API такође подржи X402 пријем, потребно је да прочитате документацију о Facilitator-у, разумете однос `paymentRequirements`, `paymentPayload`, `/verify` и `/settle`.

## Статус подршке

Ace Data Cloud X402 је верификован у јавном API-ју, званичном SDK-ју, Facilitator-у и ланчаним обрачунским путевима. У следећој табели су сажети тренутни статуси по најчешће коришћеним способностима током интеграције програмера.

| Способност                  | Статус                | Објашњење                                                               |
| ------------------------- | ------------------- | -------------------------------------------------------------------- |
| Facilitator способности    | Доступно            | `https://facilitator.acedata.cloud/.well-known/x402` враћа платне мреже и протоколске крајне тачке.  |
| API 402 `accepts`         | Доступно            | Неплаћени захтеви ће вратити доступне захтеве за плаћање за Base, SKALE и Solana.              |
| TypeScript SDK            | Доступно            | `@acedatacloud/sdk` и `@acedatacloud/x402-client` могу аутоматски обрадити 402, потписе и поновне покушаје. |
| Python SDK                | Доступно            | `acedatacloud` и `acedatacloud-x402` могу аутоматски обрадити 402, потписе и поновне покушаје.              |
| Base `exact`              | Верификовано на ланцу | Погодно за API фиксног износа и плаћање поруџбина.                                                  |
| Base `upto`               | Верификовано на ланцу | Погодно за API са накнадним обрачуном као што је допуњавање чата, тренутно једина мрежа која нуди `upto`.                                 |
| SKALE `exact`             | Верификовано на ланцу | Погодно за сцене плаћања са ниским гасним трошковима EVM.                                              |
| Solana `exact`            | HTTP paid retry верификовано | Верификовани API paid retry и одговор модела; за ланчану потврду потписа препоручује се коришћење сопственог Solana RPC за обрачун.               |
| Плаћање поруџбина          | Верификовано на ланцу | Base `exact` плаћање поруџбина је завршено ланчаним обрачуном и ажурирањем статуса поруџбине.                                   |

## Napomene za integraciju

Kada se integriraju, programeri treba da se fokusiraju na trenutne zahteve za plaćanje koji se vraćaju u realnom vremenu, a ne da kopiraju primer iz dokumentacije:

- `prihvata[].maxAmountRequired` je maksimalni iznos koji se može potpisati za trenutni zahtev.
- `prihvata[].sredstvo` je USDC ugovor ili mint koji se koristi za ovaj zahtev.
- `prihvata[].extra.chainId`, `prihvata[].extra.facilitatorAddress` i `prihvata[].extra.verifyingContract` će učestvovati u EVM tipiziranom potpisu podataka.
- `do` zahteva da novčanik prvo odobri USDC na ciljanom lancu Permit2; ako nije odobreno, vraća `PERMIT2_ALLOWANCE_REQUIRED`.
- Ako želite da koristite obračun prema stvarnoj potrošnji, prosledite `preferScheme: 'do'` u TypeScript SDK, inače će SDK izabrati prvi dostupni zahtev koji server vraća na toj mreži.

## Opseg javne verifikacije

Pre integracije, možete proveriti ove javne ulaze i ponašanje SDK-a:

- API zahtevi bez `Authorization` ili `PAYMENT-SIGNATURE` će vraćati `402 Payment Required`, a `prihvata` u odgovoru je jedini potpisni osnov za ovaj zahtev.
- TypeScript SDK i Python SDK pružaju payment handler, a transportni sloj SDK-a će pozvati handler i ponovo pokušati nakon što primi 402.
- `https://facilitator.acedata.cloud/.well-known/x402`: vraća mreže, scheme i protokolne tačke koje podržava Facilitator; cena API-a se i dalje zasniva na 402 koja se vraća u realnom vremenu za ciljani zahtev.
- `https://facilitator.acedata.cloud/supported`: vraća mreže i scheme koje podržava Facilitator.
- X402Client repozitorij sadrži napredne alate za verifikaciju na lancu, koji se mogu koristiti za potvrdu potpisa, ponovni pokušaj i ponašanje poravnanja; izlaz alata ne zamenjuje `prihvata` koje vraća online API.

`do` pripada obračunu prema stvarnoj potrošnji, pogodno za chat dopunu, pozive modela i druge API-jeve čija se stvarna potrošnja saznaje tek nakon odgovora. Trenutno samo Osnova pruža `do`; ako verifikacija potpisa ne uspe, proverite da li se chain id, facilitator adresa, spender, USDC ugovor i Permit2 allowance poklapaju sa 402 odgovorom.
