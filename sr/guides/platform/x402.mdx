X402 je protokol za plaćanje na lancu zasnovan na HTTP `402 Payment Required`. Putem X402 mogućnosti Ace Data Cloud-a, pozivalac ne mora da kreira API Token niti unapred dopunjava stanje računa, već direktno koristi USDC za plaćanje na lancu u svakom API zahtevu.

Ova grupa dokumenata je organizovana prema stvarnom redosledu integracije: prvo pokrenite minimalni zahtev, zatim integrišite SDK, a potom razumejte mreže, modele naplate, plaćanje porudžbina i Facilitator. Preporučuje se čitanje odozgo nadole prema tabeli ispod.

## Preporučeni put integracije

Ako samo želite da pozivate Ace Data Cloud API, prednost dajte zvaničnom SDK-u:

- TypeScript：`@acedatacloud/sdk` + `@acedatacloud/x402-client`
- Python：`acedatacloud` + `acedatacloud-x402`

Javni izvorni kod i adrese paketa:

| Projekat                 | Adresa                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| Ace Data Cloud SDK | [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)                                         |
| X402 Client        | [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)                           |
| X402 Facilitator   | [https://github.com/AceDataCloud/FacilitatorX402](https://github.com/AceDataCloud/FacilitatorX402)                 |
| npm SDK            | [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)                 |
| npm X402 Client    | [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client) |
| PyPI SDK           | [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)                                   |
| PyPI X402 Client   | [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)                         |

SDK će automatski obaviti korake prvog neautentifikovanog zahteva, parsiranja `402 Payment Required`, pozivanja payment handler-a i ponovnog pokušaja sa `PAYMENT-SIGNATURE`. Potrebno je samo da pripremite novčanik sa USDC-om i izaberete mrežu koju želite da koristite.

Ako želite da i vaš API podržava X402 naplatu, potrebno je da pročitate Facilitator dokumentaciju kako biste razumeli odnos između `paymentRequirements`, `paymentPayload`, `/verify` i `/settle`.

## Status podrške

Ace Data Cloud X402 je validiran na javnim API-jima, zvaničnim SDK-ovima, Facilitator-u i putanjama poravnanja na lancu. Tabela ispod rezimira trenutni status prema dimenzijama mogućnosti koje se najčešće koriste tokom integracije od strane programera.

| Mogućnost                       | Status                  | Objašnjenje                                                                 |
| ------------------------ | ------------------- | ------------------------------------------------------------------ |
| Facilitator capabilities | Dostupno                  | `https://facilitator.acedata.cloud/.well-known/x402` vraća mreže za plaćanje i krajnje tačke protokola.  |
| API 402 `accepts`        | Dostupno                  | Neplaćeni zahtevi vraćaju dostupne payment requirement-e za Base i Solana.                    |
| TypeScript SDK           | Dostupno                  | `@acedatacloud/sdk` i `@acedatacloud/x402-client` mogu automatski obraditi 402, potpise i ponovne pokušaje. |
| Python SDK               | Dostupno                  | `acedatacloud` i `acedatacloud-x402` mogu automatski obraditi 402, potpise i ponovne pokušaje.              |
| Base `exact`             | Validirano na lancu               | Pogodno za API-je sa fiksnim iznosom i plaćanje porudžbina.                                                  |
| Base `upto`              | Validirano na lancu               | Pogodno za API-je sa naknadnim merenjem, kao što su dopune četa; trenutno jedina mreža koja pruža `upto`.                                 |
| Solana `exact`           | HTTP paid retry validiran | API paid retry i odgovor modela su validirani; za potvrdu potpisa na lancu preporučuje se usklađivanje putem sopstvenog Solana RPC-a.               |
| Plaćanje porudžbine                     | Validirano na lancu               | Plaćanje Base `exact` porudžbine je završilo poravnanje na lancu i ažuriralo status porudžbine.                                   |

Objašnjenje:

- npm i PyPI paketi su uspešno instalirani i uvezeni u čistom okruženju.
- Neplaćeni API zahtev vraća 402, a `accepts` sadrži dostupne načine plaćanja za Base i Solana.

- Solana `exact` je potvrdio HTTP 402 -> HTTP 200 i izlaz modela. Pošto javni RPC upiti mogu biti ograničeni, za strogo usklađivanje preporučuje se korišćenje sopstvenog Solana RPC-a ili potvrda potpisa transakcije putem evidencije poravnanja na strani platforme.

## Napomene za integraciju

Prilikom integracije, programeri treba prvenstveno da obrate pažnju na zahteve za plaćanje u realnom vremenu koje vraća trenutni zahtev, umesto da kopiraju primer iznosa ili adrese iz dokumentacije:

- `accepts[].maxAmountRequired` je maksimalni iznos koji se može potpisati za trenutni zahtev.
- `accepts[].asset` je USDC ugovor ili mint koji treba koristiti za ovaj zahtev.
- `accepts[].extra.chainId`, `accepts[].extra.facilitatorAddress` i `accepts[].extra.verifyingContract` učestvuju u EVM typed data potpisu.
- `upto` zahteva da novčanik prvo odobri Permit2 za USDC na ciljnom lancu; kada odobrenje ne postoji, vraća se `PERMIT2_ALLOWANCE_REQUIRED`.
- Ako izričito želite da koristite naknadni obračun, prosledite `preferScheme: 'upto'` u TypeScript SDK-u; u suprotnom, SDK će izabrati prvi dostupan requirement koji server vrati za tu mrežu.

## Opseg koji se može javno proveriti

Pre integracije, možete prvo proveriti ove javne ulazne tačke i ponašanje SDK-a:

- API zahtev bez `Authorization` ili `PAYMENT-SIGNATURE` vraća `402 Payment Required`, a `accepts` u odgovoru je jedina osnova za potpis za ovaj zahtev.
- I TypeScript SDK i Python SDK pružaju payment handler, a transportni sloj SDK-a će nakon prijema 402 pozvati handler i pokušati ponovo jednom.
- `https://facilitator.acedata.cloud/.well-known/x402`: vraća mreže, scheme i krajnje tačke protokola koje Facilitator podržava; API cena i dalje zavisi od 402 odgovora koji ciljni zahtev vraća u realnom vremenu.
- `https://facilitator.acedata.cloud/supported`: vraća mreže i scheme koje Facilitator podržava.
- X402Client repozitorijum sadrži napredne alate za on-chain verifikaciju, koji se mogu koristiti za potvrđivanje potpisa, ponovnih pokušaja i settlement ponašanja; izlaz alata ne zamenjuje `accepts` koji vraća online API.

`upto` pripada naknadnom obračunskom settlement-u i pogodan je za API-je kao što su dopune razgovora i pozivi modela, kod kojih je stvarna potrošnja poznata tek nakon odgovora. Trenutno samo Base pruža `upto`; ako verifikacija potpisa ne uspe, proverite da li su chain id, facilitator adresa, spender, USDC ugovor i Permit2 allowance usklađeni sa 402 odgovorom.
