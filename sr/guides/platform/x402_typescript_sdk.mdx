TypeScript je jedan od najpreporučenijih načina za integraciju Ace Data Cloud X402. Zvanični SDK je zadužen za obične API pozive, anketiranje zadataka, obradu grešaka i automatsko ponovno pokušavanje; `@acedatacloud/x402-client` je zadužen za potpisivanje zaglavlja zahteva `PAYMENT-SIGNATURE` kada se naiđe na `402 Payment Required`.

Izvorni kod i adrese paketa:

- SDK repozitorijum: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- X402 Client repozitorijum: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm SDK: [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)
- npm X402 Client: [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client)

## Instaliranje zavisnosti

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client
```

Ako koristite Base, potrebna je EVM mogućnost potpisivanja:

```bash
npm install ethers
```

Ako koristite Solana, potreban je Solana wallet adapter ili `@solana/web3.js`:

```bash
npm install @solana/web3.js
```

Izlaz provere instalacije i uvoza u čistom npm projektu:

```text
imports_ok true true true true true
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4
```

Objašnjenje rezultata:

- `@acedatacloud/sdk` i `@acedatacloud/x402-client` se mogu instalirati iz npm-a i uvesti u Node.js.
- `ethers` se koristi za EVM typed data potpisivanje, a `@solana/web3.js` za konstrukciju Solana transakcija.

## Base primer

U pregledaču se može direktno koristiti `window.ethereum`. U Node.js se može koristiti `ethers.Wallet` za obavijanje providera u EIP-1193 stilu.

```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});

console.log(result.choices[0].message.content);
```

## Primer novčanika u pregledaču

Kada se u frontend aplikaciji koriste MetaMask, Coinbase Wallet ili WalletConnect, EIP-1193 provider se obično prosleđuje direktno:

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const [address] = await window.ethereum.request({ method: 'eth_requestAccounts' });

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider: window.ethereum,
    evmAddress: address
  })
});

const image = await client.images.generate({
  provider: 'nano-banana',
  prompt: 'a yellow banana on a white background'
});
```

Novčanik u pregledaču će prikazati potvrdu za potpisivanje. Ono što korisnik potpisuje nije proizvoljna poruka, već zahtev za plaćanje koji vraća API: adresa primaoca, USDC ugovor, iznos, rok važenja i nonce su svi uključeni u potpis.

## Solana primer

Solana koristi SPL USDC `TransferChecked`. Prosleđeni wallet adapter mora izložiti `publicKey` i `signAndSendTransaction`.

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'solana',
    solanaWallet: phantomWallet
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});
```

Solana putanja trenutno podržava samo `exact`, a ne podržava `upto`. Ako API vrati više `accepts`, handler će izabrati onu stavku sa `network = 'solana'`.

Solana putanja je na istom javnom API-ju potvrdila da plaćeni retry može vratiti HTTP 200 i `ADC_SOLANA_E2E_OK`. Upiti javnom RPC-u mogu biti ograničeni stopom, stoga ovaj tekst ne navodi Solana tx hash; kada je potrebno usklađivanje na lancu, koristite svoj Solana RPC ili potvrdite putem zapisa u konzoli.

## Izbor `exact` ili `upto`

Trenutni TypeScript handler će izabrati prvi payment requirement odgovarajuće mreže koji vrati server. Ace Data Cloud API obično postavlja `exact` iste mreže ispred `upto`, stoga, ako izričito želite naknadno merenje, morate proslediti `preferScheme: 'upto'`.

Primer:

```ts
const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address,
    preferScheme: 'upto'
  })
});
```

Ako server ne vrati `upto` requirement za tu mrežu, handler će automatski preći na prvi dostupni requirement za tu mrežu, što je obično `exact`.

`upto` zahteva jednokratno Permit2 odobrenje. `upto` je trenutno dostupan samo na Base-u, stoga je potrebno izvršiti samo jedno odobrenje za Base USDC:

```bash
npx tsx scripts/approve-permit2.ts --network base
```

Base `upto` je završio verifikaciju javnog API-ja: HTTP 402 -> HTTP 200, a naknadna settlement tx je `0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036`. Kompletan izlaz pogledajte u opisu plana naplate.

## Šta SDK radi

Transport modula `@acedatacloud/sdk` će jednom izvršiti payment handler kada primi 402:

```ts
type PaymentHandler = (ctx: {
  url: string;
  method: string;
  body?: unknown;
  accepts: PaymentRequirement[];
}) => Promise<{ headers: Record<string, string> }>;
```

Handler koji vraća `@acedatacloud/x402-client` će:

1. Izabrati payment requirement ciljne mreže iz `ctx.accepts`.
2. Konstruisati EVM EIP-712 potpis ili Solana transfer transakciju prema mreži.
3. Serijalizovati envelope u Base64.
4. Vratiti `{ headers: { 'PAYMENT-SIGNATURE': '<base64>' } }`.
5. SDK automatski ponavlja zahtev sa originalnim telom zahteva.

To znači da poslovni kod treba samo da se piše kao običan SDK poziv, bez potrebe za ručnom obradom 402 ponovnih pokušaja.
