Sumira broj zahteva i stvarno oduzete kredite trenutnog naloga po datumu i API-ju, pogodno za izradu mesečnih izveštaja, grafikona trendova i analizu troškova. Kada je potrebno otklanjati greške za svaki zapis pojedinačno, koristite [listu zapisa poziva](https://platform.acedata.cloud/documents/platform-usage-list), a kada su potrebni potpuni detalji van mreže, koristite [izvoz obima poziva](https://platform.acedata.cloud/documents/platform-usage-export).

Opseg upita za zapise poziva i sažetke naplate je poslednjih 60 dana; tela zahteva i odgovora se zasebno čuvaju poslednjih 30 dana. Istek tela ne menja stvarnu naplatu, potrošnju ili zbirnu statistiku tog zapisa.

## Priprema

1. Prijavite se na [AceDataCloud platformu](https://platform.acedata.cloud).
2. Kreirajte token naloga u [Account Token konzoli](https://platform.acedata.cloud/console/platform-tokens) i odmah ga sačuvajte.
3. Ako je potrebno suziti opseg, preuzmite odgovarajući ID iz [liste prijava za usluge](https://platform.acedata.cloud/documents/platform-application-list), [liste API akreditiva](https://platform.acedata.cloud/documents/platform-credential-list) ili [liste API-ja](https://platform.acedata.cloud/documents/platform-api-list).

Potpuno objašnjenje tokena pogledajte u [upravljanju tokenima naloga](https://platform.acedata.cloud/documents/platform-token). Ovaj interfejs koristi Account Token, a ne poslovni Credential.

```shell
export PLATFORM_TOKEN='你的账户令牌'
```

## Pregled interfejsa

| Stavka           | Sadržaj                                                       |
| ---------------- | ------------------------------------------------------------- |
| Metod            | `GET`                                                         |
| URL              | `https://platform.acedata.cloud/api/v1/usage/apis/aggregate/` |
| Autentikacija    | `Authorization: Bearer ${PLATFORM_TOKEN}`                     |
| OAuth Scope      | `usage:read`（`platform:read` / `platform` može prošireno uključivati）              |
| Opseg ovlašćenja | Za obične korisnike je fiksiran na njihovu sopstvenu plaćenu potrošnju; administratori mogu proslediti `user_id`                                |

## Parametri upita

| Parametar         | Tip             | Obavezan | Podrazumevano                         | Opis                                   |
| ----------------- | --------------- | ------- | ------------------------------------- | -------------------------------------- |
| `created_at_from` | date / datetime | Ne      | Prvi dan tekućeg meseca u izabranoj vremenskoj zoni | Vreme početka, preporučeni naziv parametra |
| `created_at_to`   | date / datetime | Ne      | Trenutno vreme                        | Vreme završetka, preporučeni naziv parametra |
| `timezone`        | string          | Ne      | `UTC`                                 | IANA vremenska zona, na primer `Asia/Shanghai`; nevažeće vrednosti vraćaju na UTC |
| `service_id`      | UUID            | Ne      | —                                     | Filtriranje po usluzi; podržava ponovljene parametre |
| `application_id`  | UUID            | Ne      | —                                     | Filtriranje po Application-u; podržava ponovljene parametre |
| `api_id`          | UUID            | Ne      | —                                     | Filtriranje po API-ju; podržava ponovljene parametre |
| `credential_id`   | UUID            | Ne      | —                                     | Filtriranje po API akreditivu; podržava ponovljene parametre |
| `include_models`  | boolean         | Ne      | `false`                               | Da li dodatno izračunati zbir po dimenziji modela; povećava trošak upita |
| `user_id`         | UUID            | Ne      | Za obične korisnike fiksirano na njih same; za administratore, ako se ne prosledi, obuhvata sve naloge | Samo administratori mogu navesti bilo koji nalog |

`start_time` / `end_time` se i dalje mogu koristiti kao kompatibilni pseudonimi za stare klijente, a nove integracije treba ujednačeno da koriste `created_at_from` / `created_at_to`. Oblik datuma za `created_at_to` uključuje taj kalendarski dan, odnosno kao granicu koristi ponoć narednog dana.

## Primeri zahteva

Upit za dnevni/API zbir tekućeg meseca po pekinškom vremenu, uz dimenziju modela:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  --data-urlencode 'include_models=true' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Upit za potrošnju tokom jedne sedmice za određeni Application:

```shell
export APPLICATION_ID='你的 Application ID'

curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'created_at_from=2026-09-01' \
  --data-urlencode 'created_at_to=2026-09-07' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Python primer:

```python
import os
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/usage/apis/aggregate/",
    headers={"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    params={
        "created_at_from": "2026-09-01",
        "created_at_to": "2026-09-07",
        "timezone": "Asia/Shanghai",
        "include_models": "true",
    },
    timeout=30,
)
response.raise_for_status()
data = response.json()
print("requests:", data["requests"], "deducted:", data["total"])
for row in data["items"]:
    print(row["date"], row["api_id"], row["amount"])
```

## Primer odgovora

```json
{
  "items": [
    {
      "date": "2026-09-01",
      "api_id": "00000000-0000-4000-8000-000000000001",
      "amount": 12.5
    }
  ],
  "total": 12.5,
  "apis": {
    "00000000-0000-4000-8000-000000000001": {
      "title": "Example API"
    }
  },
  "requests": 42,
  "models": [
    {
      "model": "example-model",
      "amount": 12.5,
      "requests": 42
    }
  ]
}
```

## Polja odgovora

| Polje        | Opis                                                         |
| ------------ | ------------------------------------------------------------ |
| `items`      | Grupisano po datumu izabrane vremenske zone i `api_id`; svaki red sadrži `date`, `api_id`, `amount` |
| `total`      | Zbir `deducted_amount` u opsegu upita                       |
| `apis`       | Mapiranje API ID-ja na sažetak naslova, radi lakšeg prikaza `items` |
| `requests`   | Ukupan broj zahteva u opsegu upita                           |
| `models`     | Izračunava se samo kada je `include_models=true`; svaka stavka sadrži `model`, `amount`, `requests` |

Jedinica kredita zavisi od `service.unit` povezanog Application-a. Ako upit obuhvata usluge sa različitim jedinicama, prvo statistiku razdvojite po `service_id` ili `application_id`, kako biste izbegli direktno poređenje ili sabiranje.

Kada vreme završetka nije veće od vremena početka, interfejs vraća potpunu praznu strukturu: `items=[]`, `total=0`, `apis={}`, `requests=0`, `models=[]`.

## Greške i preporuke za performanse

| HTTP | `error`                 | Način postupanja                               |
| ---- | ----------------------- | ---------------------------------------------- |
| 400  | `usage_history_expired` | Prilagodite vremenski opseg nakon `available_from` iz odgovora |
| 401  | `not_authenticated`     | Proverite Account Token, nemojte greškom koristiti poslovni Credential |
| 403  | `permission_denied`     | Obični korisnici ne mogu upitivati druge naloge |

- Podrazumevano nemojte uključivati `include_models`; omogućite ga tek kada izveštaj zaista zahteva podelu po modelima.
- Za upite velikog opsega, prvenstveno ih razdvojite po `service_id` ili `application_id`, čime se izbegava mešanje jedinica i smanjuje trošak upita.
- Datumi bez poziva se ne dopunjuju automatski nulama; klijent treba da dopuni osu datuma pre crtanja grafikona.
