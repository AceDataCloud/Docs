---
title: "Kreiranje API akreditiva za AceDataCloud platformu"
description: "Platform API guide - Ace Data Cloud"
---

Kreirajte poslovne API akreditive za Application. Odgovor pri kreiranju može sadržati Token koji se može direktno koristiti za pozivanje `https://api.acedata.cloud/**`, ili korisničko ime/lozinku za akreditive tipa Proxy; moraju se tretirati kao tajna.

## Priprema

1. Kreirajte [Account Token](https://platform.acedata.cloud/documents/platform-token).
2. Preuzmite `application_id` Application-a koji posedujete iz [liste Application-a](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='vaš token naloga'
export APPLICATION_ID='vaš Application ID'
```

## Pregled interfejsa

| Stavka | Sadržaj                                                   |
| ---- | ---------------------------------------------------- |
| Metod   | `POST`                                               |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/` |
| Autentifikacija   | Account Token, OAuth token zahteva `credentials:write`      |
| Body | JSON                                                 |

## Telo zahteva

| Polje                  | Tip              | Obavezno  | Opis                            |
| ------------------- | --------------- | --- | ----------------------------- |
| `application_id`    | UUID            | Da   | Ciljni Application                |
| `name`              | string          | Ne   | Prikazano ime akreditiva                         |
| `limited_amount`    | number / null   | Ne   | Ograničenje potrošnje po jednom akreditivu; `null` znači da se ne postavlja zasebno ograničenje       |
| `expired_at`        | datetime / null | Ne   | ISO 8601 vreme isteka                 |
| `allowed_api_ids`   | UUID[] / null   | Ne   | Dozvoljeno je pozivanje samo ovih API-ja; prazan niz će se normalizovati kao bez ograničenja       |
| `host`              | string          | Ne   | Host informacije akreditiva                    |
| `for_user_id`       | string          | Ne   | Koristi se kada vlasnik Application-a izdaje autorizacione akreditive za drugog korisnika |
| `tags` / `metadata` | array / object  | Ne   | Prilagođeni podaci za proširenje                       |

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/credentials/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"name\":\"production\",\"limited_amount\":50}"
```

## Objašnjenje odgovora

Uspešan odgovor vraća `201` i Credential objekat:

- Usluge tipa API/Agent obično vraćaju `type=Token` i `token`;
- Usluge tipa Proxy obično vraćaju `type=Identity` i `username` / `password`, a jedan Proxy Application dozvoljava samo jedan akreditiv;
- `id`, `user_id`, `creator_id`, `used_amount` i vremenska polja generiše server.

Trenutni interfejsi za listu i detalje takođe vraćaju običan tekst akreditiva, ali klijent ne treba da se oslanja na ovo istorijsko ponašanje. Sačuvajte ih odmah nakon kreiranja i izbegavajte upisivanje odgovora u logove; budući interfejsi mogu biti izmenjeni tako da vraćaju maskirane vrednosti.

## Obrada grešaka

- `400`: Greška u formatu polja, nepoznati `allowed_api_ids`, Proxy Application već ima akreditiv ili druga ograničenja kreiranja.
- `401`: Account Token nije važeći.
- `403/404`: Nemate pravo pristupa ciljnom Application-u ili Application/autorizovani korisnik ne postoji.
