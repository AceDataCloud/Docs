**Token naloga (Account Token, ranije nazvan Platform Token)** je „ključ na nivou naloga” pomoću kojeg programeri programski upravljaju resursima AceDataCloud platforme (zahtevi za usluge, API akreditivi, porudžbine, zapisi poziva, stanje, fajlovi itd.). Njegova funkcija je slična korisničkom Token-u nakon prijave na frontend i podrazumevano nema vreme isteka; obični korisnici mogu upravljati samo svojim tokenima, dok super administratori mogu upravljati tokenima drugih naloga prema ovlašćenjima.

Token naloga pristupa API interfejsima platforme sa trenutnim ovlašćenjima pripadajućeg naloga: osnovna ovlašćenja, direktno dodeljena ovlašćenja i ovlašćenja pripadajuće korisničke grupe primenjuju se objedinjeno; nakon pridruživanja ili uklanjanja iz grupe, sledeći zahtev se procenjuje prema novim ovlašćenjima. Pristup konkretnim resursima poput zahteva i porudžbina i dalje zahteva proveru pripadnosti. Token naloga podrazumevano ne ističe, zato ga koristite samo u pouzdanom okruženju i pažljivo ga čuvajte.

> ℹ️ Ovaj interfejs pripada **AceDataCloud API-ju za upravljanje platformom**, sa jedinstvenim prefiksom `https://platform.acedata.cloud/api/v1/`. Za potpuni indeks interfejsa pogledajte [Preuzimanje liste dokumenata AceDataCloud platforme](https://platform.acedata.cloud/documents/platform-document-list).

## Token naloga vs API akreditivi

Dve vrste ključeva koje početnici najlakše pomešaju, prvo ih jasno razlikujte:

| Dimenzija   | **Token naloga** (ovaj dokument)                                                               | **API akreditivi (Credential)**                                                                           |
| ---- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| Namena   | Pozivanje upravljačkih interfejsa `https://platform.acedata.cloud/**`                                | Pozivanje poslovnih interfejsa `https://api.acedata.cloud/**` (OpenAI, Midjourney, Suno, Veo itd.)                             |
| Format   | `platform-v1-` + 64 heksadecimalna znaka (ukupno 76 znakova)                                          | 32 heksadecimalna znaka                                                                                         |
| Jedan nalog | Obično 1–2 komada                                                                    | 1–N komada za svaki zahtev za uslugu                                                                                     |
| Ulaz za kreiranje | [Account Token konzola](https://platform.acedata.cloud/console/platform-tokens) | [Kreiranje AceDataCloud platformskih API akreditiva](https://platform.acedata.cloud/documents/platform-credential-create) |
| Uslovi prestanka važenja | Odmah prestaje da važi nakon brisanja; ističe kada `expiration` nije prazan                                                | Mogu se postaviti gornja granica kvote, vreme isteka i vezana izvorna IP adresa                                                                             |

Ako samo želite da pozovete GPT-4.1, potrebni su vam **API akreditivi**, a ne token naloga.
Ako želite da pišete automatizovane skripte za upravljanje dopunama, pregled mesečnih računa ili grupno slanje akreditiva članovima tima, tada koristite token naloga.

## Kreiranje jednim klikom u konzoli (preporučeno)

1. Prijavite se na [https://platform.acedata.cloud](https://platform.acedata.cloud).
2. Idite na bočnu traku → „Programer” → „[Account Token](https://platform.acedata.cloud/console/platform-tokens)”.
3. Kliknite dugme „Kreiraj” u gornjem desnom uglu da odmah dobijete `platform-v1-...` token, **kliknite dugme za kopiranje i sačuvajte ga u menadžeru lozinki**.

![Account Token konzola](https://cdn.acedata.cloud/6g86oz.png)

> ⚠️ Trenutni odgovori za kreiranje, listu i detalje vraćaju token u čistom tekstu. Tretirajte ceo odgovor kao tajnu, nemojte ga upisivati u logove, analitičke platforme ili frontend perzistentno skladište; klijent takođe ne bi trebalo da se oslanja na to da lista dugoročno vraća čisti tekst.

## Kreiranje tokena naloga pomoću API-ja

### Pregled interfejsa

| Stavka    | Sadržaj                                                       |
| ---- | -------------------------------------------------------- |
| Metoda   | `POST`                                                   |
| URL  | `https://platform.acedata.cloud/api/v1/platform-tokens/` |
| Autentikacija   | ✅ Bilo koji postojeći token naloga ili JWT stanje prijave u pregledaču                                 |
| Body | `application/json` (može se poslati prazan objekat `{}`)                           |

### Objašnjenje autentikacije (problem kokoške i jajeta)

> Kako dobiti prvi token? Odgovor je **putem konzole** — nakon prijave u pregledaču, konzola poziva `POST /platform-tokens/` uz JWT autentikaciju i dodeljuje vam prvi token.
> Nakon toga možete koristiti bilo koji postojeći `platform-v1-...` token za kreiranje dodatnih tokena.

Format zaglavlja zahteva:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
Content-Type: application/json
```

### Primer zahteva

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/platform-tokens/' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'content-type: application/json' \
  -d '{}'
```

### Odgovor (HTTP 201)

```json
{
  "id": "3264f1aa-cbe1-4e2c-a434-95adba4f8304",
  "token": "platform-v1-<REDACTED>",
  "expiration": null,
  "user_id": "89518d07-5560-4b05-92c1-667f3ddf6a4b",
  "created_at": "2026-04-26T15:50:11.123456Z",
  "updated_at": "2026-04-26T15:50:11.123456Z",
  "used_at": null
}
```

### Objašnjenje polja

| Polje           | Tip                 | Objašnjenje                                                   |
| ------------ | ------------------ | ---------------------------------------------------- |
| `id`         | UUID               | Primarni ključ tokena, koristi se pri brisanju / upitu detalja                                     |
| `token`      | string             | Čisti tekst tokena naloga. Format `platform-v1-` + 64 heksadecimalna znaka (ukupno 76 znakova), mora se tretirati kao tajna |
| `expiration` | int \| null        | Vreme isteka (vremenska oznaka u sekundama). `null` označava da vreme isteka nije postavljeno                         |
| `user_id`    | UUID               | ID pripadajućeg korisnika. To je takođe vrednost parametra `?user_id=` koja se mora proslediti svim narednim interfejsima liste               |
| `created_at` | datetime (ISO8601) | Vreme kreiranja                                                 |
| `updated_at` | datetime (ISO8601) | Vreme ažuriranja                                                 |
| `used_at`    | datetime \| null   | Vreme kada je poslednji put korišćen za autentikaciju. Ako nikada nije korišćen, vrednost je `null`, što se može koristiti za pronalaženje „zombi tokena”                |

## Preuzimanje liste tokena naloga

### Pregled interfejsa

| Stavka   | Sadržaj                                                       |
| --- | -------------------------------------------------------- |
| Metoda  | `GET`                                                    |
| URL | `https://platform.acedata.cloud/api/v1/platform-tokens/` |
| Autentikacija  | ✅ Potreban je token naloga                                                 |

### Obavezan parametar upita

> ⚠️ **Obavezno dodajte `?user_id=<your_user_id>`**. Razlog: interfejs liste vrši proveru ovlašćenja **za svaki objekat pojedinačno** nad rezultatima paginacije; kada se ne prosledi `user_id`, prvi objekat koji vam ne pripada biće odbijen i vratiće se `403 permission_denied`.

Kako preuzeti `user_id`:

1. Otvorite [https://auth.acedata.cloud/user/profile](https://auth.acedata.cloud/user/profile) u pregledaču; potpuni UUID je prikazan na vrhu stranice.
2. Ili direktno popunite vrednost iz polja `user_id` u povratnoj vrednosti `POST /platform-tokens/`.

### Parametri upita
| Parametar         | Obavezno  | Tip     | Opis                    |
| ---------- | --- | ------ | --------------------- |
| `user_id`  | ✅   | UUID   | Korisnički ID trenutnog naloga            |
| `limit`    | ❌   | int    | Broj stavki po stranici, podrazumevano 10, maksimalno 100     |
| `offset`   | ❌   | int    | Pomak                    |
| `ordering` | ❌   | string | Polje za sortiranje, podrazumevano `-created_at` |

### Primer zahteva

```shell
curl 'https://platform.acedata.cloud/api/v1/platform-tokens/?user_id=89518d07-5560-4b05-92c1-667f3ddf6a4b&limit=5' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Odgovor (HTTP 200)

```json
{
  "count": 2,
  "items": [
    {
      "id": "51c575a2-801c-4211-bc47-711452a8c8c9",
      "token": "platform-v1-<REDACTED>",
      "expiration": null,
      "user_id": "89518d07-5560-4b05-92c1-667f3ddf6a4b",
      "created_at": "2026-04-26T15:41:32.761705Z",
      "updated_at": "2026-04-26T15:41:32.761726Z",
      "used_at": null
    }
  ]
}
```

> Paginirani odgovor ovog interfejsa koristi `count` + `items`. Drugi interfejsi platforme mogu koristiti drugačiju strukturu, pa se vodite odgovarajućom dokumentacijom i stvarnim odgovorom.

## Preuzimanje detalja tokena naloga

| Stavka   | Sadržaj                                                                      |
| --- | ----------------------------------------------------------------------- |
| Metoda  | `GET`                                                                   |
| URL | `https://platform.acedata.cloud/api/v1/platform-tokens/<id>`（**bez kose crte na kraju**） |
| Autentifikacija  | ✅ Pristup imaju samo kreator tokena ili superadministrator                                                       |

```shell
curl 'https://platform.acedata.cloud/api/v1/platform-tokens/51c575a2-801c-4211-bc47-711452a8c8c9' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

Vraćena struktura je ista kao element liste, `HTTP 200`.

## Brisanje tokena naloga

| Stavka   | Sadržaj                                                                      |
| --- | ----------------------------------------------------------------------- |
| Metoda  | `DELETE`                                                                |
| URL | `https://platform.acedata.cloud/api/v1/platform-tokens/<id>`（**bez kose crte na kraju**） |
| Autentifikacija  | ✅ Samo kreator tokena ili superadministrator mogu da ga obrišu                                                       |

```shell
curl -X DELETE 'https://platform.acedata.cloud/api/v1/platform-tokens/3264f1aa-cbe1-4e2c-a434-95adba4f8304' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

- Uspešno vraća `HTTP 204 No Content`, bez tela odgovora.
- Nakon brisanja, token **odmah postaje nevažeći**, a svi servisi koji ga koriste odmah će dobiti `401`.
- Ponovni upit za taj `id` vraća `404`.

> ⚠️ Brisanje je nepovratno. Ako sumnjate da je token procureo, možete **najpre kreirati novi, prebaciti poslovnu stranu, a zatim obrisati stari**.

## Nepodržane operacije

| Operacija         | HTTP | Opis                                  |
| ---------- | ---- | ----------------------------------- |
| `PATCH` izmena | 405  | Nakon kreiranja tokena naloga **nisu podržane izmene nijednog polja**. Za potrebe poput preimenovanja, obrišite ga pa ga ponovo kreirajte |
| `PUT` zamena   | 405  | Isto kao gore                                  |

---

## Brzi pregled kodova grešaka

| HTTP | `code`               | Čest razlog                          |
| ---- | -------------------- | ----------------------------- |
| 401  | `not_authenticated`  | Nije poslato zaglavlje `Authorization`, ili je token obrisan  |
| 403  | `permission_denied`  | Interfejs liste nema `?user_id=`, ili se pristupa detaljima tuđeg tokena |
| 404  | `not_found`          | `id` ne postoji ili je obrisan                 |
| 405  | `method_not_allowed` | Interfejsu detalja je poslat `PATCH`/`PUT`         |

Jedinstveni format odgovora o grešci:

```json
{
  "detail": "You do not have permission to perform this action.",
  "code": "permission_denied",
  "trace_id": "0a88956213edf6e62b71695ee2df0eff"
}
```

Prilikom rešavanja problema, dostavite `trace_id` korisničkoj podršci ili ga nalepite u tiket da biste brzo locirali zapise.

## Kompletni primeri koda

### Python

```python
import os
import requests

BASE = "https://platform.acedata.cloud/api/v1"
PLATFORM_TOKEN = os.environ["PLATFORM_TOKEN"]
USER_ID = "89518d07-5560-4b05-92c1-667f3ddf6a4b"

headers = {
    "accept": "application/json",
    "authorization": f"Bearer {PLATFORM_TOKEN}",
    "content-type": "application/json",
}

# 1. 创建新令牌
created = requests.post(f"{BASE}/platform-tokens/", headers=headers, json={}).json()
print("新令牌：", created["token"])
print("UserID：", created["user_id"])

# 2. 列表
listing = requests.get(
    f"{BASE}/platform-tokens/",
    headers=headers,
    params={"user_id": USER_ID, "limit": 50},
).json()
print(f"共 {listing['count']} 枚令牌")

# 3. 删除（注意末尾无斜杠）
resp = requests.delete(f"{BASE}/platform-tokens/{created['id']}", headers=headers)
assert resp.status_code == 204, resp.text
```

### Node.js

```javascript
const BASE = 'https://platform.acedata.cloud/api/v1'
const PLATFORM_TOKEN = process.env.PLATFORM_TOKEN
const USER_ID = '89518d07-5560-4b05-92c1-667f3ddf6a4b'

const headers = {
  accept: 'application/json',
  authorization: `Bearer ${PLATFORM_TOKEN}`,
  'content-type': 'application/json',
}

// 创建
const created = await fetch(`${BASE}/platform-tokens/`, {
  method: 'POST',
  headers,
  body: '{}',
}).then((r) => r.json())

// 列表
const url = new URL(`${BASE}/platform-tokens/`)
url.searchParams.set('user_id', USER_ID)
const listing = await fetch(url, { headers }).then((r) => r.json())
console.log(`共 ${listing.count} 枚令牌`)

// 删除（末尾无斜杠）
await fetch(`${BASE}/platform-tokens/${created.id}`, { method: 'DELETE', headers })
```

## Upotreba u drugim API-jima platforme

Stavite `platform-v1-...` direktno u zaglavlje `Authorization: Bearer ...` kako biste pozvali bilo koji interfejs platforme koji zahteva autentifikaciju:

```shell
curl 'https://platform.acedata.cloud/api/v1/applications/?user_id=89518d07-5560-4b05-92c1-667f3ddf6a4b' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

> Potpuno se razlikuje od 32-bitnih heksadecimalnih API akreditiva koje koriste poslovni interfejsi `https://api.acedata.cloud/**` (OpenAI, Midjourney, Suno, Veo itd.). Nemojte ih mešati — upisivanje tokena naloga u poslovni interfejs rezultiraće kodom `401`, i obrnuto.
