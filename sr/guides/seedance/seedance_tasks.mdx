Главна функција SeeDance Tasks API је да омогући проверу статуса извршења задатка путем ID-a задатка генерисаног од SeeDance Video Generation API.

Овај документ ће детаљно описати упутство за интеграцију SeeDance Tasks API, помажући вам да лако интегришете и максимално искористите моћне функције овог API. Користећи SeeDance Tasks API, можете лако проверити статус извршења задатка SeeDance Video Generation API.

## Процес пријаве

Да бисте користили SeeDance Video Generation API, прво идите на [Ace Data Cloud контролни панел](https://platform.acedata.cloud/console/applications) да добијете ваш API токен, који ћете задржати за каснију употребу.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Ако се још нисте пријавили или регистровали, аутоматски ћете бити преусмерени на страницу за пријаву која вас позива да се региструјете и пријавите, а након тога ћете бити аутоматски враћени на тренутну страницу.

**Један API токен је довољан за позивање свих услуга платформе, без потребе да се за сваку услугу посебно пријављујете.** При првом захтеву добијате бесплатну квоту, коју можете бесплатно испробати; када вам квота понестане, можете допунити општи баланс на [контролном панелу](https://platform.acedata.cloud/console/coin).

> 📘 Пуна документација: [SeeDance Video Generation API →](https://platform.acedata.cloud/documents/seedance-videos)

## Пример захтева

SeeDance Tasks API може се користити за проверу резултата SeeDance Video Generation API. За информације о томе како користити SeeDance Video Generation API, молимо вас да се упутите на документацију [SeeDance Video Generation API](https://platform.acedata.cloud/documents/seedance-videos-integration).

Узимамо за пример ID задатка који је вратила услуга SeeDance Video Generation API, да демонстрирамо како користити овај API. Хајде да претпоставимо да имамо ID задатка: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, а затим ћемо демонстрирати како да пренесемо ID задатка.

### Постављање заглавља захтева и тела захтева

**Request Headers** укључује:

- `accept`: одређује да се примају одговори у JSON формату, овде се попуњава као `application/json`.
- `authorization`: кључ за позивање API, који можете директно изабрати након пријаве.

**Request Body** укључује:

- `id`: ID задатка који се преноси.
- `action`: начин операције над задатком.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/seedance/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "a6e0d456-189b-4c78-9232-2fe72166ab39",
  "action": "retrieve"
}'
```

Враћени резултат садржи више поља, поље request представља тело захтева при покретању задатка, док поље response представља тело одговора након завршетка задатка. Опис поља је следећи.

- `id`, ID генерисаног задатка, који служи за јединствено идентификовање овог генерисаног задатка.
- `request`, информације о захтеву у задатку.
- `response`, информације о одговору у задатку.
- `created_at`, време креирања задатка, Unix временски жиг (секунде, флотантно).
- `started_at`, време почетка извршења задатка, Unix временски жиг (секунде, флотантно).
- `finished_at`, време завршетка задатка, Unix временски жиг (секунде, флотантно). Ово поље се не враћа ако задатак није завршен.
- `elapsed`, време извршења задатка, у секундама (флотантно, са 3 децималне цифре). Ово поље се не враћа ако задатак није завршен.

- `ids`: низ ID-ова задатака који се преносе.

## Obrada grešaka

Kada pozivate API, ako naiđete na grešku, API će vratiti odgovarajući kod greške i informacije. Na primer:

- `400 token_mismatched`: Neispravna zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `400 api_not_implemented`: Neispravna zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `401 invalid_token`: Neautorizovano, nevalidan ili nedostajući autorizacioni token.
- `429 too_many_requests`: Previše zahteva, premašili ste limit brzine.
- `500 api_error`: Interna greška servera, nešto nije u redu sa serverom.
