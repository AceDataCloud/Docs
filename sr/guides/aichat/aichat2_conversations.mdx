AI Chat v2 API (`/aichat2/conversations`) je nova generacija interfejsa za razgovor i predstavlja potpuno unapređenu verziju [AI Chat API-ja](https://platform.acedata.cloud/documents/aichat-conversations). Na osnovu jednostavnog v1 upravljanja višekružnim razgovorima, proširen je sa:

- **Multimodalnim korisničkim unosom**: direktno prenesite tekst + slike + blokove datoteka putem strukturisanog polja `message`, bez potrebe za prethodnim indirektnim dodavanjem putem `references`.
- **Agentizovanim pozivanjem alata**: ugrađen je skup alata za pretragu interneta, preuzimanje veb-stranica, čitanje datoteka itd., a mogu se povezati i MCP serveri koje je korisnik autorizovao (Google Drive, Notion, Slack, GitHub itd.), tako da model može autonomno pozivati alate više puta u jednom zahtevu kako bi završio složene zadatke.
- **Strukturisanim strim događajima**: putem `accept: text/event-stream` ili `application/x-ndjson` mogu se dobiti događaji kao što su `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` itd. token po token, što olakšava njihovo zasebno renderovanje na frontendu prema odgovarajućim tipovima.
- **Mogućnošću prekida / nastavka**: kada model zahteva da korisnik dopuni informacije, šalje događaj `ask_user_question` i pauzira; pri sledećem pozivu odgovor se može vratiti putem `tool_results` kako bi se nastavilo.
- **Novim CRUD radnjama**: putem polja `action` na istom endpointu mogu se izvršiti `retrieve` / `retrieve_batch` / `update` / `delete`, bez potrebe za dodatnim API-jem za upravljanje razgovorima.
- **Kontinuirano ažuriranom listom modela**: podrazumevano su povezani savremeni modeli kao što su GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 itd.

Istovremeno je na nivou tela zahteva **u potpunosti kompatibilan unazad sa v1**: dovoljno je poslati samo `model` + `question` (+ opcionalno `stateful` / `id` / `references` / `preset`) da biste dobili JSON odgovor `{answer, id}` ekvivalentan v1, tako da prilikom migracije sa `/aichat/conversations` nije potrebno prepisivati klijent — dovoljno je promeniti putanju u `/aichat2/conversations`.

> Ako trenutno koristite `/aichat/conversations`, stari interfejs će i dalje ostati dostupan, pa možete migrirati svojim tempom.

## Proces prijave

Da biste koristili AI Chat v2 API, najpre preuzmite svoj API Token u [Ace Data Cloud konzoli](https://platform.acedata.cloud/console/applications) i sačuvajte ga za kasniju upotrebu.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Ako još niste prijavljeni ili registrovani, automatski ćete biti preusmereni na stranicu za prijavu gde ćete biti pozvani da se registrujete i prijavite, a nakon završetka automatski ćete se vratiti na trenutnu stranicu.

**Jedan API Token može pozivati sve usluge platforme, bez potrebe za zasebnom prijavom za svaku uslugu.** Pri prvoj prijavi dobijate besplatni kredit za besplatno isprobavanje; kada kredit nije dovoljan, možete dopuniti zajednički saldo u [konzoli](https://platform.acedata.cloud/console/coin).

## Osnovna upotreba

Najjednostavniji način upotrebe je potpuno isti kao kod v1: prosledite `model` + `question` i dobijete `{answer, id}`.

CURL primer:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Povratni rezultat:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python primer:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Višekružni razgovor

Kao i kod v1, prosledite `stateful: true` da biste uključili čuvanje razgovora; API će vratiti `id`; u narednim zahtevima dovoljno je vratiti `id` da biste nastavili razgovor, bez potrebe da sami održavate istoriju messages.

Prvi zahtev:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Povratna vrednost:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Drugi zahtev, uz isti `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> Podrazumevana vrednost za `stateful` je `true`, izostavljanje i eksplicitno prosleđivanje `true` su ekvivalentni. Postavljanje `stateful: false` će preskočiti učitavanje prethodne istorije sesije; to ne znači da rezultat ovog kruga neće biti sačuvan, niti se primenjuje na tokove alata koji zahtevaju nastavak nakon pauze.

### Duge sesije i zadržavanje originalnog teksta

Sažimanje konteksta samo organizuje sadržaj poslat modelu u ovom krugu i ne zamenjuje već sačuvane zapise razgovora. Potpune sačuvane poruke i dalje se mogu pročitati putem `action: retrieve`; eksplicitno uređivanje i brisanje sesija i dalje se izvršava prema zahtevu.

Model može da pretražuje i učitava originalni tekst istorije po stranicama unutar trenutne sesije. Kada je potrebno nastaviti uređivanje članka, citirati brojeve ili se pripremiti za objavljivanje, treba učitati odgovarajući originalni tekst i ne može se koristiti sažetak umesto glavnog teksta. Ova mogućnost ne vraća automatski poruke koje su već izgubljene u starim verzijama.

Ako organizovanje konteksta ne uspe, zadržite ID sesije i proverite događaj `error`; usluga neće prepisati originalni tekst praznim sažetkom. Operacije alata koje su već završene pre neuspeha možda su i dalje važeće, zato prvo proverite njihove rezultate kako biste izbegli ponovljeno generisanje ili objavljivanje. Kada jedna sesija dostigne ograničenje skladišta, biće prijavljena jasna greška; postojeći sačuvani zapisi neće osloboditi prostor skraćivanjem; možete izvesti potreban sadržaj, a zatim pokrenuti novu sesiju.

## Strimovani odgovor

v2 podržava dva formata strimovanja, koji se biraju prema zaglavlju `accept`:

| Scenario                    | `accept`               | Oblik podataka                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web frontend / EventSource  | `text/event-stream`    | `data: {json}\n\n`, poslednji red `data: [DONE]\n\n` |
| Serverska strana / CLI / Node strimovano parsiranje | `application/x-ndjson` | Jedan JSON objekat po redu                               |
| Strimovanje nije potrebno                 | `application/json`（podrazumevano） | Jednokratno vraća `{answer, id}`                       |

### NDJSON primer

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Svaki red NDJSON-a je strukturirani događaj, a najčešći je `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE primer

`EventSource` na strani pregledača ne podržava prilagođeno telo zahteva, preporučuje se korišćenje `fetch` + ručno parsiranje po segmentima `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Tipovi strimovanih događaja

| `type`              | Značenje                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Inkrementalni tekstualni segment odgovora asistenta. `content` je novi sadržaj; radi kompatibilnosti sa v1, isti događaj takođe nosi `delta_answer` (jednak `content`) i `id`.                                        |
| `thinking`          | Proces razmišljanja modela (pojavljuje se samo kada izabrani model izlaže reasoning).                                                                                      |
| `tool_use`          | Model odlučuje da pozove alat, a događaj nosi `tool_id`, `tool_name`, `input`.                                                                        |
| `tool_result`       | Rezultat izvršavanja alata, uparen sa prethodnim `tool_use` putem `tool_id`; `is_error` označava da li je došlo do neuspeha.                                                             |
| `card`              | Strukturirana kartica koju je proizveo alat (kao što su slike, pregledi linkova), pogodna za direktno renderovanje.                                                                                          |
| `citation`          | URL izvora koji se koristi za dopunu citata odgovarajućeg tekstualnog segmenta.                                                                                                  |
| `ask_user_question` | Emituje se kada modelu trebaju dodatne informacije od korisnika; razgovor ulazi u stanje `awaiting_user_input`, detalje pogledajte u nastavku [nastavljanje pauziranog razgovora](#恢复暂停的对话).                                                 |
| `artifact`          | Samostalni proizvod koji je generisao model (kao što je blok koda, dokument), koji se može sačuvati ili preuzeti.                                                                                            |
| `system_message`    | Informacija sistemskog obaveštenja (nije sadržaj korisnika ni asistenta), koristi se samo za UI obaveštenja.                                                                                           |
| `compact`           | Kontekst modela je organizovan; sačuvane originalne poruke ostaju nepromenjene i klijent ne mora da briše zapise razgovora.                                                                                    |
| `error`             | Došlo je do greške u ovom krugu, `message` opisuje sadržaj greške.                                                                                              |
| `done`              | Konačni zapis sesije ovog kruga je uspešno sačuvan, nosi `usage` (uključujući `prompt_tokens` / `completion_tokens` / `total_tokens`) i `terminal_reason`; i dalje je potrebno proceniti da li je zadatak završen prema razlogu završetka. |
Za klijente kojima je stalo samo do konačnog odgovora, spajanje svih `content` vrednosti iz `text_delta` je ekvivalentno `answer` vrednosti u režimu `application/json`.

## Multimodalni unos

Ako korisnički unos sadrži slike ili fajlove, prosledite `message` (niz) umesto `question`. Svaki element niza je blok sadržaja:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Podržani tipovi blokova:

- `text` — običan tekst, polje `text` je obavezno.
- `image_url` — slika, `image_url.url` je obavezno.
- `file_url` — fajl (PDF, CSV, TXT itd.), `file_url.url` je obavezno.

### Odnos sa v1 `references`

Radi kompatibilnosti sa starim klijentima, v2 i dalje prepoznaje polje `references: ["https://...", ...]`:

- Ako je ekstenzija URL-a `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, automatski se pretvara u blok `image_url`;
- Druge ekstenzije se pretvaraju u blok `file_url`;
- Ako je istovremeno obezbeđen i `question`, on se dodaje na početak kao blok `text`.

Stoga, ako želite samo da migrirate sa v1 bez izmene tela zahteva, dovoljno je da putanju zamenite sa `/aichat2/conversations`, a originalni način korišćenja `references` će nastaviti da radi.

Ako je potrebna preciznija kontrola (na primer, postavljanje više slika između tekstova ili kada je redosled veoma važan), direktno koristite niz `message`.

## Pozivanje alata i MCP

Ključno poboljšanje v2 je to što model može samostalno da poziva alate kako bi završio zadatke u više koraka, **ovo je podrazumevano uključeno** i klijent ne mora da vrši nikakvu dodatnu konfiguraciju u zahtevu. Uobičajeni scenariji:

- Korisnik pita „Pomozi mi da pretražim koje su nove izložbe nedavno u Šangaju“ → model poziva ugrađenu web pretragu → organizuje rezultate u odgovor.
- Korisnik pita „Pročitaj ovaj PDF i zatim napiši sažetak“ → model poziva file_read → piše sažetak.
- Korisnik je već autorizovao Google Drive / GitHub / Notion itd. u [Connections](https://platform.acedata.cloud/connections) → model može da pozove odgovarajuće MCP alate za čitanje i pisanje njihovih podataka.

U NDJSON / SSE toku, pozivi alata se prikazuju kroz dve vrste događaja, `tool_use` i `tool_result`, na primer:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Ako ne želite da prikazujete detalje pozivanja alata u frontendu, dovoljno je da ignorišete događaje `tool_use` / `tool_result` / `card` / `citation`; konačni izlaz modela će i dalje stizati kroz tok `text_delta`.

`max_turns` može da ograniči koliko najviše rundi model može sam da poziva alate u ovom zahtevu; opseg je 1–500, a ako se izostavi, podrazumevana vrednost je 500. Ako ga postavite na malu vrednost (na primer `max_turns: 1`), možete nametnuti jednokratni odgovor i ne dozvoliti nikakvo pozivanje alata.

## Asinhrono izvršavanje i autorizacija bez nadzora

Ako vaš poziv dolazi iz Webhook-a za upozorenja, CI/CD-a, sistema za nadzor ili drugih pozadinskih zadataka, možete postaviti `async: true` kako bi interfejs odmah vratio ID zadatka, a izvršavanje se nastavilo u pozadini:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Primer odgovora:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Nakon toga možete koristiti `action: retrieve` + `id` za upit rezultata razgovora; takođe možete obezbediti `callback_url`, pa će platforma po završetku zadatka poslati `{ status, answer, usage, error }` metodom POST na vašu adresu za povratni poziv. `callback_url` mora da koristi `http` / `https` i ne može direktno da navodi `localhost` ili literalnu adresu privatne IP mreže.

Pozadinski zadaci obično nemaju osobu koja može da klikne na potvrdu. Ako želite da određeni Skill ili MCP Server izvršava radnje kao što su slanje, objavljivanje i upisivanje u režimu bez nadzora, eksplicitno prosledite listu prethodnih autorizacija u telo zahteva:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Vrednosti u `allowed_skills` su slug vrednosti povezanih Skill-ova; vrednosti u `allowed_mcp_servers` su slug vrednosti povezanih MCP Server-a. Skill / MCP Server koji nije naveden u prethodnoj autorizaciji u režimu bez nadzora i dalje može samo da pregleda, izvrši dry-run ili odbije izvršavanje operacija upisivanja.

Ako je potrebna detaljnija kontrola, možete koristiti i ekvivalentni objekat `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Prethodna autorizacija se sastoji upravo od ove dve liste: prazne liste znače da nije autorizovana nijedna mogućnost, bez potrebe za dodatnim poljem prekidača.

Napomena: prethodna autorizacija samo znači „ovaj zahtev dozvoljava ovim mogućnostima da preskoče ljudsku potvrdu u režimu bez nadzora“. Konkretni Skill i dalje mora da podržava `--unattended-confirm` ili odgovarajući bezbednosni mehanizam; u suprotnom će nastaviti sa dry-run režimom i neće direktno izvršiti operacije upisivanja.

## Nastavljanje pauziranog razgovora

Neki alati mogu navesti model da „postavi protivpitanje korisniku“, pri čemu model emituje događaj `ask_user_question`, a razgovor se zamrzava u stanju `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

U frontendu prikažite ovaj događaj kao karticu kako bi korisnik izabrao odgovor, a zatim pokrenite sledeći zahtev sa istim `id` i popunite odgovor nazad putem `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

`tool_use_id` u telu zahteva **mora** biti potpuno isti kao `tool_id` u trenutku pauziranja; u suprotnom će biti vraćena greška 400. Kada `tool_results` istovremeno postoji u zahtevu, `question` / `message` / `references` će svi biti ignorisani.

Ako korisnik odluči da odustane od ovog pitanja, dovoljno je direktno proslediti novi `question` / `message`, a platforma će automatski označiti pauzirani poziv alata kao „korisnik je preskočio“.

## Upravljanje sesijama (CRUD)

v2 pruža lagano upravljanje sesijama preko polja `action` na istom endpoint-u, bez potrebe za dodatnim API-jem.

### `action: retrieve` —— Preuzimanje jedne sesije

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Vraća kompletan dokument sesije (uključujući istoriju `messages`, `model`, `title`, `tools_used` itd.).

### `action: retrieve_batch` —— Izlistavanje sažetaka sesija

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Vraća `{ items: [...], total }`. **Sažeci ne sadrže `messages`**, pogodni su za listu u bočnoj traci; ako korisnik otvori neku sesiju, zatim upotrebite `action: retrieve` da zasebno preuzmete njene kompletne poruke.

Opcioni parametri filtriranja: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Promena naslova ili ponovno pisanje istorije

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Plan putovanja u Hangdžou"
}
```

Može se proslediti i `messages`, ali će server izvršiti strogu schema validaciju (mora biti u sažetom obliku `ToolUseContent`); ako ne odgovara, biće vraćena greška 400. Uopšteno se preporučuje da se koristi samo za promenu `title`.

### `action: delete` —— Brisanje jedne sesije

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Vraća `{ id, success: true }`. Nakon brisanja nije moguće vratiti sesiju, zato pozovite tek nakon potvrde.

## Postepena migracija sa v1

Ako već koristite [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), migracija na v2 gotovo da ne zahteva izmene koda:

1. Promenite URL iz `https://api.acedata.cloud/aichat/conversations` u `https://api.acedata.cloud/aichat2/conversations`.
2. Ako ste prethodno prosleđivali naziv v1 modela (kao što su `gpt-3.5`, `gpt-4-browsing` itd.), preporučuje se nadogradnja na savremeni model pri prelasku na v2 (kao što su `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` itd.).
3. Polja NDJSON toka ostaju kompatibilna unazad: svaki `text_delta` događaj i dalje sadrži `delta_answer` i `id`, stoga klijente koji originalno parsiraju `delta_answer` red po red nije potrebno menjati.

Nakon migracije možete po potrebi omogućiti nove mogućnosti v2 (multimodalni `message`, SSE, pozivanje alata, `action` CRUD) i postepeno ih uvoditi.

## Rukovanje greškama

Odgovori sa greškom imaju jedinstveni format:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Česte greške:

- `400 bad_request`: nedostaju obavezna polja, `tool_use_id` se ne podudara, schema za `messages` nije validna itd.
- `401 invalid_token`: zaglavlje `authorization` nije ispravno.
- `404 not_found`: sesija koja odgovara `id` ne postoji pri `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: sesija je premašila ograničenje skladištenja, postojeći sačuvani zapisi nisu prepisani.
- `429 too_many_requests`: aktivirano je ograničenje brzine zahteva.
- `503 context_compaction_failed`: sređivanje konteksta nije uspelo, postojeći zapisi su sačuvani.
- `500 conversation_persist_failed`: konačno čuvanje ovog kruga nije uspelo; primljeni tekst ne znači da je konačni zapis uspešno sačuvan, proverite po ID-u sesije.
- `500 chat_error`: usluga je privremeno nedostupna ili u ovom krugu nije generisan sadržaj (neće biti naplate).

U strimovanom odgovoru, greška se šalje kao događaj `{"type":"error","message":"..."}`, nakon čega se tok završava. `[DONE]` samo označava kraj prenosa; kada postoji `error`, ne može se smatrati uspehom, niti će biti poslat uspešan `done` događaj.

## Zaključak

AI Chat v2 API, uz kompatibilnost unazad sa v1, unapređuje razgovore iz „jednokratnih / višekratnih pitanja i odgovora“ u „Agentizovane, posmatrane razgovore“: multimodalni unos, pozivanje alata, mogućnost pauziranja / nastavljanja, strimovani strukturisani događaji, ugrađeni CRUD. Preporučuje se da nove integracije direktno koriste v2; postojeće v1 integracije mogu postepeno i glatko migrirati. Ako imate bilo kakvih pitanja, slobodno kontaktirajte naš tim tehničke podrške.
