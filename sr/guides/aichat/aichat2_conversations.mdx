AI Chat v2 API (`/aichat2/conversations`) je nova generacija interfejsa za razgovore i potpuno unapređena verzija [AI Chat API-ja](https://platform.acedata.cloud/documents/aichat-conversations). Na osnovu jednostavnosti i hostovanog višekružnog razgovora v1, proširuje:

- **Multimodalni korisnički unos**: Putem strukturisanog polja `message` direktno šalje tekst + sliku + blokove datoteka, bez potrebe za prethodnim indirektnim dodavanjem preko `references`.
- **Agentizovane pozive alata**: Ugrađen je skup alata za pretragu interneta, preuzimanje veb-stranica, čitanje datoteka itd., uz mogućnost povezivanja MCP servera koje je korisnik autorizovao (Google Drive, Notion, Slack, GitHub itd.), a model može autonomno pozivati alate u više krugova unutar jednog zahteva kako bi završio složene zadatke.
- **Strukturisane strim događaje**: Putem `accept: text/event-stream` ili `application/x-ndjson` mogu se dobiti događaji po tokenu kao što su `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` itd., što olakšava njihovo odvojeno prikazivanje po odgovarajućim tipovima na frontendu.
- **Mogućnost prekida / nastavka**: Kada model zahteva da korisnik dopuni informacije, emitovaće događaj `ask_user_question` i pauzirati; pri sledećem pozivu dovoljno je popuniti odgovor kroz `tool_results` da bi se nastavilo.
- **Nove CRUD akcije**: Na istom endpoint-u, putem polja `action`, izvršavaju se `retrieve` / `retrieve_batch` / `update` / `delete`, bez potrebe za dodatnim API-jem za upravljanje razgovorima.
- **Kontinuirano ažurirana lista modela**: Podrazumevano uključuje savremene modele kao što su GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 itd.

Istovremeno je na nivou tela zahteva **potpuno unazad kompatibilan sa v1**: dovoljno je poslati samo `model` + `question` (+ opcionalno `stateful` / `id` / `references` / `preset`) da biste dobili `{answer, id}` JSON odgovor ekvivalentan v1, tako da pri migraciji sa `/aichat/conversations` nije potrebno prepisivati klijent — dovoljno je samo promeniti putanju u `/aichat2/conversations`.

> Ako trenutno koristite `/aichat/conversations`, stari interfejs će i dalje ostati u funkciji i možete migrirati sopstvenim tempom.

Da biste koristili AI Chat v2 API, najpre preuzmite svoj API Token u [Ace Data Cloud konzoli](https://platform.acedata.cloud/console/applications) i sačuvajte ga za kasniju upotrebu.

## Osnovna upotreba

Najjednostavnija upotreba je potpuno ista kao u v1: pošaljite `model` + `question` i dobijte `{answer, id}`.

CURL primer:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Povratni rezultat:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python primer:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Višekružni razgovor

Kao i u v1, prosledite `stateful: true` da biste omogućili čuvanje razgovora; API će vratiti `id`; u narednim zahtevima samo vratite taj `id` kako biste nastavili razgovor, bez potrebe da sami održavate istoriju poruka.

Prvi zahtev:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Povratni odgovor:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Drugi zahtev, uz isti `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> Podrazumevana vrednost za `stateful` je `true`; izostavljanje i eksplicitno prosleđivanje `true` su ekvivalentni. Ako ne želite da server sačuva ovaj krug razgovora, možete eksplicitno postaviti `stateful: false`.

## Strimovani odgovor

v2 podržava dva formata strimovanja, koji se biraju prema zaglavlju `accept`:

| Scenario                    | `accept`               | Oblik podataka                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web frontend / EventSource  | `text/event-stream`    | `data: {json}\n\n`, poslednji red je `data: [DONE]\n\n` |
| Serverska strana / CLI / Node strimovano parsiranje | `application/x-ndjson` | Jedan JSON objekat po redu                               |
| Strimovanje nije potrebno                 | `application/json`（podrazumevano） | Jednokratno vraća `{answer, id}`                       |

### NDJSON primer

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Svaki red NDJSON-a je strukturisani događaj, a najčešći je `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE primer

Upotreba `EventSource` u pregledaču ne podržava prilagođeno telo zahteva; preporučuje se korišćenje `fetch` + ručno parsiranje po delovima `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Tipovi strimovanih događaja

| `type`              | Značenje                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `text_delta`        | Inkrementalni tekstualni segment odgovora asistenta. `content` je novododati sadržaj; radi kompatibilnosti sa v1, isti događaj nosi i `delta_answer` (jednak `content`) i `id`.                  |
| `thinking`          | Proces razmišljanja modela (pojavljuje se samo kada izabrani model izlaže reasoning).                                                                |
| `tool_use`          | Model odlučuje da pozove alat; događaj nosi `tool_id`, `tool_name`, `input`.                                                  |
| `tool_result`       | Rezultat izvršavanja alata, uparen sa prethodnim `tool_use` putem `tool_id`; `is_error` označava da li je došlo do neuspeha.                                       |
| `card`              | Strukturisana kartica koju proizvodi alat (kao što su slike i pregledi linkova), pogodna za direktno renderovanje.                                                                    |
| `citation`          | URL izvora koji se koristi za dopunu citata odgovarajućeg tekstualnog segmenta.                                                                            |
| `ask_user_question` | Šalje se kada modelu trebaju dodatne informacije od korisnika; razgovor ulazi u stanje `awaiting_user_input`, detalje pogledajte niže u [Nastavljanje pauziranog razgovora](#恢复暂停的对话).                           |
| `artifact`          | Nezavisan artefakt koji generiše model (kao što su blok koda ili dokument), koji se može sačuvati ili preuzeti.                                                                      |
| `system_message`    | Sistemska poruka (nije sadržaj korisnika ni asistenta), koristi se samo za UI obaveštenja.                                                                     |
| `compact`           | Događaj u kojem je interni kontekst sažet, nije potrebna posebna obrada.                                                                             |
| `error`             | U ovom krugu je došlo do greške; `message` opisuje sadržaj greške.                                                                        |
| `done`              | Strimovani odgovor je završen; nosi `usage` (uključujući `prompt_tokens` / `completion_tokens` / `total_tokens`) i `terminal_reason`. |

Za klijente koje zanima samo konačan odgovor, spajanje `content` iz svih `text_delta` događaja je ekvivalentno `answer` u režimu `application/json`.

## Multimodalni unos

Ako korisnički unos sadrži slike ili datoteke, prosledite `message` (niz) umesto `question`. Svaki element niza je blok sadržaja:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Podržani tipovi blokova:

- `text` — običan tekst, polje `text` je obavezno.
- `image_url` — slika, `image_url.url` je obavezno.
- `file_url` — datoteka (PDF, CSV, TXT itd.), `file_url.url` je obavezno.

### Odnos sa v1 `references`

Radi kompatibilnosti sa starim klijentima, v2 i dalje prepoznaje polje `references: ["https://...", ...]`:
- Ako URL nastavak glasi `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, automatski se pretvara u blok `image_url`;
- Ostali nastavci se pretvaraju u blok `file_url`;
- Ako je istovremeno dostavljen i `question`, onda se on postavlja ispred kao blok `text`.

Stoga, ako samo želite da pređete sa v1 bez izmene tela zahteva, dovoljno je da promenite putanju u `/aichat2/conversations`, a originalna upotreba `references` nastavlja da radi kao i obično.

Ako je potrebna preciznija kontrola (na primer, postavljanje više slika između teksta ili ako je redosled veoma važan), direktno koristite niz `message`.

## Pozivanje alata i MCP

Ključno poboljšanje v2 je to što model može samostalno da poziva alate kako bi završio zadatke u više koraka, **ovo je podrazumevano uključeno**, i nije potrebna nikakva dodatna konfiguracija u zahtevu klijenta. Uobičajeni scenariji:

- Korisnik pita „Pomozi mi da pretražim koje nove izložbe su nedavno u Šangaju“ → model poziva ugrađenu web pretragu → organizuje rezultate u odgovor.
- Korisnik pita „Pročitaj ovaj PDF, a zatim napiši sažetak“ → model poziva file_read → piše sažetak.
- Korisnik je već autorizovao Google Drive / GitHub / Notion itd. u [Connections](https://platform.acedata.cloud/connections) → model može da poziva odgovarajuće MCP alate za čitanje i pisanje njihovih podataka.

U NDJSON / SSE toku, pozivi alata se prikazuju kroz dve vrste događaja, `tool_use` i `tool_result`, na primer:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Ako ne želite da na frontendu prikažete detalje poziva alata, dovoljno je da ignorišete događaje tipa `tool_use` / `tool_result` / `card` / `citation`; konačni izlaz modela i dalje se emituje kroz `text_delta`.

`max_turns` može ograničiti maksimalan broj rundi u kojima model može samostalno da poziva alate u ovom zahtevu; opseg je 1–500, a podrazumevana vrednost je 500 kada se izostavi. Ako ga postavite na manju vrednost (na primer, `max_turns: 1`), možete nametnuti jednokratni odgovor i ne dozvoliti nikakve pozive alata.

## Asinhrono izvršavanje i autorizacija bez nadzora

Ako vaš poziv dolazi iz Webhook upozorenja, CI/CD-a, sistema za nadzor ili drugih pozadinskih zadataka, možete postaviti `async: true` kako bi interfejs odmah vratio ID zadatka, dok se izvršavanje nastavlja u pozadini:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Moj servis je alarmirao, obavesti WeChat grupu „AceDataCloud团队“ putem ličnog WeChata……"
}
```

Primer odgovora:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Nakon toga možete koristiti `action: retrieve` + `id` da biste upitali rezultat razgovora; možete takođe navesti `callback_url`, a nakon završetka zadatka platforma će POST metodom poslati `{ status, answer, usage, error }` na vašu adresu za povratni poziv. `callback_url` mora koristiti `http` / `https` i ne može direktno da navede `localhost` ili literalnu adresu privatne IP mreže.

Pozadinski zadaci obično nemaju osobu koja može da klikne na potvrdu. Ako želite da određeni Skill ili MCP Server izvršava radnje poput slanja, objavljivanja i upisivanja u režimu bez nadzora, eksplicitno prosledite listu prethodnih ovlašćenja u telu zahteva:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Moj servis je alarmirao, obavesti WeChat grupu „AceDataCloud团队“ putem ličnog WeChata……"
}
```

Vrednosti u `allowed_skills` su slug-ovi povezanih Skill-ova; vrednosti u `allowed_mcp_servers` su slug-ovi povezanih MCP Server-a. Skill / MCP Server koji nije naveden u prethodnom ovlašćenju u režimu bez nadzora i dalje može samo da pregleda, izvrši dry-run ili odbije izvršavanje operacija upisivanja.

Ako je potrebna preciznija kontrola, možete koristiti i ekvivalentni objekat `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Prethodno ovlašćenje su same ove dve liste: prazna lista znači da se ne ovlašćuje nijedna mogućnost i nije potrebno dodatno polje prekidača.

Napomena: prethodno ovlašćenje samo znači „ovaj zahtev dozvoljava ovim mogućnostima da preskoče ljudsku potvrdu u režimu bez nadzora“. Konkretni Skill i dalje mora podržavati `--unattended-confirm` ili odgovarajući bezbednosni mehanizam; u suprotnom će nastaviti sa dry-run i neće direktno izvršiti operaciju upisivanja.

## Nastavljanje pauziranog razgovora

Neki alati mogu navesti model da „postavi protivpitanje korisniku“; model tada emituje događaj `ask_user_question`, a razgovor se zamrzava u stanju `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Da li želite da generisani izveštaj bude na kineskom ili engleskom?",
  "options": ["kineski", "engleski"],
  "id": "f2f4b3e8-..."
}
```

Na frontendu prikažite ovaj događaj kao karticu kako bi korisnik izabrao odgovor, a zatim pokrenite sledeći zahtev sa istim `id`, popunjavajući odgovor putem `tool_results`:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

`tool_use_id` u telu zahteva **mora** biti potpuno isti kao `tool_id` u trenutku pauziranja; ako nije isti, vraća se 400. Kada `tool_results` istovremeno postoji u zahtevu, `question` / `message` / `references` će svi biti ignorisani.

Ako korisnik odluči da odustane od ovog pitanja, dovoljno je direktno proslediti novi `question` / `message`, a platforma će automatski označiti pauzirani poziv alata kao „korisnik je preskočio“.

## Upravljanje razgovorima (CRUD)

v2 pruža lagano upravljanje razgovorima putem polja `action` na istom endpoint-u, bez potrebe za dodatnim API-jem.
### `action: retrieve` —— Preuzimanje jedne konverzacije

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Vraća kompletan dokument konverzacije (uključujući istoriju `messages`, `model`, `title`, `tools_used` itd.).

### `action: retrieve_batch` —— Izlistavanje sažetaka konverzacija

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Vraća `{ items: [...], total }`. **Sažeci ne sadrže `messages`**, pogodni su za listu na bočnoj traci; ako korisnik otvori određenu konverzaciju, zatim koristite `action: retrieve` da zasebno preuzmete njene kompletne poruke.

Opcioni parametri za filtriranje: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Promena naslova ili prepisivanje istorije

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Plan putovanja u Hangdžou"
}
```

Može se proslediti i `messages`, ali server vrši strogu schema validaciju (mora biti u sažetom obliku `ToolUseContent`), a ako ne odgovara vratiće 400. Generalno se preporučuje korišćenje samo za izmenu `title`.

### `action: delete` —— Brisanje jedne konverzacije

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Vraća `{ id, success: true }`. Nakon brisanja nije moguće vraćanje, pozovite tek nakon potvrde.

## Glatka migracija sa v1

Ako već koristite [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), migracija na v2 gotovo da ne zahteva izmene koda:

1. Promenite URL sa `https://api.acedata.cloud/aichat/conversations` na `https://api.acedata.cloud/aichat2/conversations`.
2. Ako ste prethodno prosleđivali naziv v1 modela (kao što su `gpt-3.5`, `gpt-4-browsing` itd.), pri prelasku na v2 preporučuje se nadogradnja na savremene modele (kao što su `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` itd.).
3. Polja NDJSON toka ostaju unazad kompatibilna: svaki `text_delta` događaj i dalje sadrži `delta_answer` i `id`, tako da klijenti koji su prethodno parsirali `delta_answer` po redovima ne zahtevaju izmene.

Nakon migracije možete po potrebi omogućiti nove mogućnosti v2 (multimodalni `message`, SSE, pozivanje alata, `action` CRUD) i napredovati svojim tempom.

## Obrada grešaka

Odgovor na grešku je ujednačenog formata:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Česte greške:

- `400 bad_request`: nedostaju obavezna polja, `tool_use_id` se ne podudara, schema za `messages` nije validna itd.
- `401 invalid_token`: zaglavlje `authorization` nije ispravno.
- `404 not_found`: konverzacija koja odgovara `id` ne postoji pri `action: retrieve / update / delete`.
- `429 too_many_requests`: aktivirano je ograničenje brzine.
- `500 chat_error`: uzvodni LLM je prijavio grešku ili je u ovoj rundi `completion_tokens=0` (tretira se kao nepotrošeno i neće biti naplaćeno).

U strimovanom odgovoru, greška se šalje kao događaj `{"type":"error","message":"..."}`, nakon čega se tok odmah završava.

## Zaključak

AI Chat v2 API, uz zadržavanje kompatibilnosti sa v1, unapređuje konverzacije sa „jednokratnih / višekratnih pitanja i odgovora“ na „Agentizovane, posmatrane konverzacije“: multimodalni unos, pozivanje alata, mogućnost pauziranja / nastavljanja, strimovani strukturirani događaji, ugrađeni CRUD. Preporučuje se da nove integracije direktno koriste v2; postojeće v1 integracije mogu glatko migrirati po fazama. Ako imate bilo kakvih pitanja, slobodno se obratite našem timu tehničke podrške.
