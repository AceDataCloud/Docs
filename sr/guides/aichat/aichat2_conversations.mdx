AI Chat v2 API (`/aichat2/conversations`) predstavlja novu generaciju interfejsa za razgovore i sveobuhvatnu nadogradnju [AI Chat API-ja](https://platform.acedata.cloud/documents/aichat-conversations). Na osnovu jednostavnog v1 interfejsa koji podržava upravljanje višekružnim razgovorima, proširuje sledeće mogućnosti:

- **Multimodalni korisnički unos**: Direktno prosleđivanje teksta + slika + blokova datoteka putem strukturiranog polja `message`, bez potrebe za prethodnim posrednim dodavanjem pomoću `references`.
- **Agentizovano pozivanje alata**: Ugrađen je skup alata za internet pretragu, preuzimanje veb-stranica, čitanje datoteka i druge funkcije, uz mogućnost povezivanja MCP servera koje je korisnik ovlastio (Google Drive, Notion, Slack, GitHub itd.). Model može samostalno da poziva alate u više krugova tokom jednog zahteva kako bi izvršio složene zadatke.
- **Strukturirani događaji toka**: Putem `accept: text/event-stream` ili `application/x-ndjson` mogu se dobiti događaji kao što su `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` itd. koji se emituju token po token, što olakšava njihovo zasebno prikazivanje na frontendu prema odgovarajućem tipu.
- **Mogućnost prekidanja / nastavljanja**: Kada modelu zatrebaju dodatne informacije od korisnika, emitovaće događaj `ask_user_question` i pauzirati rad. Prilikom sledećeg poziva dovoljno je popuniti odgovor putem `tool_results` da bi se razgovor nastavio.
- **Nove CRUD akcije**: Na istoj krajnjoj tački, putem polja `action`, mogu se izvršavati `retrieve` / `retrieve_batch` / `update` / `delete`, bez potrebe za dodatnim API-jem za upravljanje sesijama.
- **Lista modela koja se kontinuirano ažurira**: Podrazumevano su dostupni savremeni modeli kao što su GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 i drugi.

Istovremeno, na nivou tela zahteva, ovaj API je **potpuno kompatibilan sa starijom verzijom v1**: dovoljno je proslediti samo `model` + `question` (+ opciono `stateful` / `id` / `references` / `preset`) da biste dobili JSON odgovor `{answer, id}` ekvivalentan onom iz v1. Zbog toga prilikom migracije sa `/aichat/conversations` nije potrebno ponovo pisati klijentski kod, već je dovoljno promeniti putanju u `/aichat2/conversations`.

> Ako trenutno koristite `/aichat/conversations`, stari interfejs će i dalje biti dostupan, tako da možete izvršiti migraciju sopstvenim tempom.

## Osnovna upotreba

Najjednostavniji način korišćenja potpuno je isti kao kod v1: prosledite `model` + `question` i dobijete `{answer, id}`.

CURL primer:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Rezultat odgovora:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python primer:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Višekružni razgovori

Kao i kod v1, prosledite `stateful: true` da biste omogućili čuvanje sesije. API će vratiti jedan `id`; u narednim zahtevima dovoljno je ponovo proslediti isti `id` da biste nastavili razgovor, bez potrebe da sami održavate istoriju poruka `messages`.

Prvi zahtev:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Odgovor:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Drugi zahtev, uz prosleđivanje istog `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "Koji je broj koji sam ti malopre rekao da zapamtiš?"
  }'
```

```json
{
  "answer": "Broj koji si mi rekao da zapamtim je 42.",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` je podrazumevano `true`, a izostavljanje i eksplicitno prosleđivanje vrednosti `true` imaju isto značenje. Podešavanje `stateful: false` preskače učitavanje prethodne istorije razgovora; to ne znači da rezultati ovog kruga neće biti sačuvani, niti se odnosi na tokove alata koje je potrebno pauzirati i kasnije nastaviti.

### Dugi razgovori i očuvanje originalnog teksta

Kompresija konteksta samo sređuje sadržaj koji se u ovom krugu šalje modelu, ne zamenjuje sačuvanu istoriju razgovora. Korišćenjem `action: retrieve` i dalje je moguće pročitati sve sačuvane poruke; eksplicitno uređivanje ili brisanje razgovora i dalje se izvršava u skladu sa zahtevom.

Model može da pretražuje i stranicu po stranicu čita originalni tekst istorije unutar trenutnog razgovora. Kada je potrebno nastaviti uređivanje članka, citirati brojeve ili pripremiti objavu, treba pročitati odgovarajući originalni tekst, a sažetak ne sme da zameni glavni tekst. Ova mogućnost ne vraća automatski poruke koje su već izgubljene u starijim verzijama.

Ako sređivanje konteksta ne uspe, sačuvajte ID razgovora i proverite `error` događaj; servis neće zameniti originalni tekst praznim sažetkom. Radnje alata koje su završene pre greške i dalje mogu biti važeće, zato prvo proverite njihove rezultate kako biste izbegli ponovljeno generisanje ili objavljivanje. Kada pojedinačni razgovor dostigne ograničenje skladištenja, biće prikazana jasna greška, a prostor se neće osloboditi skraćivanjem postojećih sačuvanih zapisa; možete izvesti potreban sadržaj, a zatim započeti novi razgovor.

## Striming odgovori

v2 podržava dva formata striminga, koji se biraju pomoću `accept` zaglavlja:

| Scenario                    | `accept`               | Oblik podataka                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web frontend / EventSource  | `text/event-stream`    | `data: {json}\n\n`, poslednji red `data: [DONE]\n\n` |
| Server / CLI / Node striming analiza | `application/x-ndjson` | Jedan JSON objekat po redu                               |
| Nije potreban striming                 | `application/json`（podrazumevano） | Jednokratni odgovor `{answer, id}`                       |

### NDJSON primer

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "Predstavi Hangzhou u tri rečenice.",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # Kompatibilno sa v1: inkrementalni segment se istovremeno dostavlja putem polja delta_answer
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Svaki red NDJSON-a predstavlja strukturirani događaj, a najčešći je `text_delta`:

```json
{"type":"text_delta","content":"Han","delta_answer":"Han","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"g","delta_answer":"g","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"zhou","delta_answer":"zhou","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE primer

Pošto `EventSource` u pregledaču ne podržava prilagođeno telo zahteva, preporučuje se korišćenje `fetch` + ručno razdvajanje i parsiranje po `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "Predstavi Hangzhou u tri rečenice.",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Tipovi striming događaja

| `type`              | Značenje                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Inkrementalni tekstualni segment odgovora asistenta. `content` predstavlja novi sadržaj; radi kompatibilnosti sa v1, isti događaj sadrži i `delta_answer` (jednak `content`) i `id`.                                        |
| `thinking`          | Proces razmišljanja modela (pojavljuje se samo kada izabrani model izlaže reasoning).                                                                                      |
| `tool_use`          | Model odlučuje da pozove alat; događaj sadrži `tool_id`, `tool_name`, `input`.                                                                        |
| `tool_result`       | Rezultat izvršavanja alata, povezan sa prethodnim `tool_use` događajem putem `tool_id`; `is_error` označava da li je došlo do greške.                                                             |
| `card`              | Strukturirana kartica koju generiše alat (kao što su slike i pregledi linkova), pogodna za direktno prikazivanje.                                                                                          |
| `citation`          | URL izvora koji dopunjuje citat odgovarajućeg tekstualnog segmenta.                                                                                                  |
| `ask_user_question` | Emituje se kada modelu trebaju dodatne informacije od korisnika; razgovor prelazi u stanje `awaiting_user_input`. Za detalje pogledajte odeljak [Nastavak pauziranog razgovora](#nastavak-pauziranog-razgovora).                                                 |
| `artifact`          | Samostalan rezultat koji je generisao model (kao što su blokovi koda i dokumenti), koji se može sačuvati ili preuzeti.                                                                                            |
| `system_message`    | Sistemska informativna poruka (nije sadržaj korisnika ni asistenta), koristi se samo za UI obaveštenja.                                                                                           |
| `compact`           | Kontekst modela je sređen; sačuvane originalne poruke ostaju nepromenjene, klijent ne mora da briše istoriju razgovora.                                                                                    |
| `error`             | Došlo je do greške u ovom krugu, a `message` opisuje sadržaj greške.                                                                                              |
| `done`              | Konačni zapis ovog kruga razgovora uspešno je sačuvan, uz `usage` (koji sadrži `prompt_tokens` / `completion_tokens` / `total_tokens`) i `terminal_reason`; i dalje je potrebno proceniti da li je zadatak završen na osnovu razloga završetka.                                                                      |
Za klijente koje zanima samo konačan odgovor, spajanje sadržaja svih `text_delta` događaja (`content`) ekvivalentno je polju `answer` u režimu `application/json`.

## Višemodalni unos

Ako korisnički unos sadrži sliku ili datoteku, prosledite `message` (niz) umesto `question`. Svaki element niza predstavlja jedan blok sadržaja:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "Koliko mačaka ima na ovoj slici?" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Podržani tipovi blokova:

- `text` — običan tekst, obavezno polje `text`.
- `image_url` — slika, obavezno polje `image_url.url`.
- `file_url` — datoteka (PDF, CSV, TXT itd.), obavezno polje `file_url.url`.

### Odnos sa v1 `references`

Radi kompatibilnosti sa starim klijentima, v2 i dalje prepoznaje polje `references: ["https://...", ...]`:

- URL-ovi sa ekstenzijama `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif` automatski se pretvaraju u blokove `image_url`;
- Ostale ekstenzije pretvaraju se u blokove `file_url`;
- Ako je istovremeno prosleđen i `question`, on se dodaje na početak kao blok `text`.

Dakle, ako želite samo da pređete sa v1, a da pritom ne menjate telo zahteva, dovoljno je da promenite putanju u `/aichat2/conversations`, a postojeća upotreba `references` nastavlja da funkcioniše na isti način.

Ako vam je potrebna preciznija kontrola (na primer, postavljanje više slika između tekstualnih delova ili određivanje redosleda), direktno koristite niz `message`.

## Pozivi alata i MCP

Osnovno poboljšanje u v2 jeste to što model može samostalno da poziva alate kako bi izvršio zadatke u više koraka. **Ova funkcija je podrazumevano uključena** i nije potrebno da klijent obavlja bilo kakvu dodatnu konfiguraciju u zahtevu. Uobičajeni scenariji:

- Korisnik pita: „Pretraži najnovije izložbe u Šangaju“ → model poziva ugrađenu web pretragu → organizuje rezultate u odgovor.
- Korisnik pita: „Pročitaj ovaj PDF i napiši sažetak“ → model poziva file_read → piše sažetak.
- Korisnik je već odobrio pristup Google Drive / GitHub / Notion itd. u [Connections](https://platform.acedata.cloud/connections) → model može da poziva odgovarajuće MCP alate za čitanje i pisanje njihovih podataka.

U NDJSON / SSE toku, pozivi alata prikazuju se kroz dve vrste događaja: `tool_use` i `tool_result`, na primer:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"Šangaj prolećne izložbe 2026"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"Trenutno","delta_answer":"Trenutno","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"u Šangaju","delta_answer":"u Šangaju","id":"f2f4b3e8-..."}
...
```

Ako ne želite da prikazujete detalje poziva alata na frontendu, jednostavno ignorišite događaje `tool_use` / `tool_result` / `card` / `citation`. Konačni izlaz modela i dalje će biti emitovan kroz `text_delta`.

`max_turns` može da ograniči maksimalan broj ciklusa samostalnog pozivanja alata modela u okviru ovog zahteva. Opseg je od 1 do 500, a podrazumevana vrednost je 500 ako se polje izostavi. Postavljanjem manje vrednosti (na primer, `max_turns: 1`) možete da nametnete odgovor u jednom koraku, bez dozvole za bilo kakve pozive alata.

## Asinhrono izvršavanje i ovlašćenje bez nadzora

Ako vaš poziv dolazi iz Alert Webhook-a, CI/CD sistema, sistema za nadzor ili drugog pozadinskog zadatka, možete postaviti `async: true` kako bi interfejs odmah vratio ID zadatka, dok se izvršavanje nastavlja u pozadini:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Moj servis je aktivirao alarm, obavesti WeChat grupu „AceDataCloud tim“ koristeći moj lični WeChat nalog…"
}
```

Primer odgovora:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Nakon toga možete koristiti `action: retrieve` + `id` da biste preuzeli rezultate razgovora. Takođe možete navesti `callback_url`, a kada se zadatak završi, platforma će poslati `{ status, answer, usage, error }` POST zahtevom na vašu povratnu adresu. `callback_url` mora koristiti `http` / `https` i ne može direktno sadržati `localhost` ili privatnu IP adresu.

Pozadinski zadaci obično nemaju osobu koja može da klikne na potvrdu. Ako želite da određeni Skill ili MCP Server izvršava radnje kao što su slanje, objavljivanje, upisivanje itd. bez nadzora, u telu zahteva morate eksplicitno proslediti listu prethodno odobrenih stavki:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Moj servis je aktivirao alarm, obavesti WeChat grupu „AceDataCloud tim“ koristeći moj lični WeChat nalog…"
}
```

Vrednosti u `allowed_skills` predstavljaju slug-ove povezanih Skill-ova; vrednosti u `allowed_mcp_servers` predstavljaju slug-ove povezanih MCP Server-a. Skill / MCP Server koji nije naveden na listi prethodno odobrenih stavki i dalje može samo da prikaže pregled, izvrši dry-run ili odbije operacije upisivanja u režimu bez nadzora.

Ako vam je potrebna detaljnija kontrola, možete koristiti i ekvivalentni objekat `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Prethodno odobrenje predstavljaju upravo ove dve liste: prazna lista znači da nijedna mogućnost nije odobrena i nije potrebno dodatno polje za uključivanje ili isključivanje.

Napomena: prethodno odobrenje samo znači da je „ovim zahtevom dozvoljeno da navedene mogućnosti u režimu bez nadzora preskoče ručnu potvrdu“. Konkretni Skill i dalje mora da podržava `--unattended-confirm` ili odgovarajući bezbednosni mehanizam. U suprotnom će nastaviti da izvršava samo dry-run i neće direktno sprovoditi operacije upisivanja.

## Nastavak pauziranih razgovora

Neki alati mogu da navedu model da „postavi dodatno pitanje korisniku“. U tom slučaju model će emitovati događaj `ask_user_question`, a razgovor će biti zamrznut u stanju `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Da li želite da generisani izveštaj bude na kineskom ili engleskom jeziku?",
  "options": ["Kineski", "Engleski"],
  "id": "f2f4b3e8-..."
}
```

Na frontendu prikažite ovaj događaj kao karticu kako bi korisnik mogao da izabere odgovor, a zatim pokrenite sledeći zahtev koristeći isti `id` i prosledite odgovor kroz `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

U telu zahteva, `tool_use_id` **mora** u potpunosti da se poklapa sa `tool_id` vrednošću iz trenutka pauziranja; u suprotnom će biti vraćen odgovor 400. Kada zahtev istovremeno sadrži `tool_results`, `question` / `message` / `references` biće ignorisani.

Ako korisnik odluči da odustane od ovog pitanja, dovoljno je da direktno pošalje novo `question` / `message`, a platforma će automatski označiti pauzirani poziv alata kao „korisnik je preskočio“.

## Upravljanje sesijama (CRUD)

v2 pruža jednostavno upravljanje sesijama putem polja `action` na istom endpoint-u, bez potrebe za otvaranjem dodatnog API-ja.

### `action: retrieve` —— Preuzimanje jedne sesije

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Vraća kompletan dokument sesije (uključujući istoriju `messages`, `model`, `title`, `tools_used` i druge podatke).

### `action: retrieve_batch` —— Prikaz sažetaka sesija

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Vraća `{ items: [...], total }`. **Sažetak ne sadrži `messages`**, što ga čini pogodnim za prikaz liste u bočnoj traci; kada korisnik otvori neku sesiju, koristite `action: retrieve` da zasebno preuzmete njene kompletne poruke.

Opcioni parametri za filtriranje: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Promena naslova ili prepisivanje istorije

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

Može se proslediti i `messages`, ali server će izvršiti strogu proveru šeme (mora biti u sažetom obliku `ToolUseContent`); ako ne ispunjava uslove, biće vraćen odgovor 400. Uopšteno, preporučuje se korišćenje ove funkcije samo za promenu `title`.

### `action: delete` —— Brisanje jedne sesije

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Vraća `{ id, success: true }`. Nakon brisanja nije moguće izvršiti oporavak, zato potvrdite pre pozivanja.

## Jednostavna migracija sa v1

Ako već koristite [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), migracija na v2 gotovo da ne zahteva izmene koda:

1. Promenite URL sa `https://api.acedata.cloud/aichat/conversations` na `https://api.acedata.cloud/aichat2/conversations`.
2. Ako ste ranije prosleđivali nazive modela iz v1 (kao što su `gpt-3.5`, `gpt-4-browsing` itd.), preporučuje se da prilikom prelaska na v2 nadogradite na savremene modele (kao što su `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` itd.).
3. Polja u NDJSON toku ostaju kompatibilna sa starijim verzijama: svaki `text_delta` događaj i dalje sadrži `delta_answer` i `id`, tako da klijenti koji su ranije parsirali `delta_answer` po linijama ne zahtevaju nikakve izmene.

Nakon migracije, možete po potrebi da omogućite nove mogućnosti v2 (multimodalni `message`, SSE, pozivanje alata, `action` CRUD) i uvodite ih postepeno, sopstvenim tempom.

## Obrada grešaka

Odgovori sa greškama imaju jedinstven format:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Uobičajene greške:

- `400 bad_request`: nedostaje obavezno polje, `tool_use_id` se ne poklapa, nevažeća `messages` šema itd.
- `401 invalid_token`: zaglavlje `authorization` nije ispravno.
- `404 not_found`: sesija koja odgovara vrednosti `id` ne postoji prilikom izvršavanja `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: sesija je premašila ograničenje skladištenja, a postojeći sačuvani zapisi nisu prepisani.
- `429 too_many_requests`: aktivirano je ograničenje brzine zahteva.
- `503 context_compaction_failed`: sažimanje konteksta nije uspelo, postojeći zapisi su sačuvani.
- `500 conversation_persist_failed`: konačno čuvanje ovog kruga nije uspelo; primanje teksta ne znači da je konačni zapis uspešno sačuvan, proverite ga prema ID-u sesije.
- `500 chat_error`: usluga je privremeno nedostupna ili sadržaj nije generisan u ovom krugu (naplata se neće izvršiti).

U striming odgovoru, greške se šalju u obliku događaja `{"type":"error","message":"..."}`, nakon čega se tok završava. `[DONE]` označava samo završetak prenosa; kada postoji `error`, odgovor se ne može smatrati uspešnim i neće biti poslat uspešan `done` događaj.

## Zaključak

AI Chat v2 API, uz očuvanje kompatibilnosti sa starijim verzijama v1, unapređuje razgovor iz „jednokratnog / višekružnog sistema pitanja i odgovora“ u „opservabilni razgovor zasnovan na Agent arhitekturi“: multimodalni unos, pozivanje alata, mogućnost pauziranja / nastavljanja, strukturirani događaji u striming režimu i ugrađeni CRUD. Preporučuje se da nove integracije direktno koriste v2; postojeće v1 integracije mogu postepeno i bez poteškoća da pređu na novu verziju. Ako imate bilo kakvih pitanja, slobodno kontaktirajte naš tim tehničke podrške.
