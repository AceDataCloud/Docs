AI Chat v2 API (`/aichat2/conversations`) je nova generacija interfejsa za razgovor i predstavlja sveobuhvatno unapređenu verziju [AI Chat API-ja](https://platform.acedata.cloud/documents/aichat-conversations). Na osnovu jednostavnosti v1 i hostovanih višekružnih razgovora, proširuje:

- **Multimodalni korisnički unos**: direktno šaljite tekst + slike + blokove fajlova putem strukturiranog polja `message`, bez potrebe da ih prethodno indirektno prilažete pomoću `references`.
- **Pozivanje alata u Agent režimu**: ugrađen je skup alata za pretragu interneta, preuzimanje veb stranica, čitanje fajlova itd., a mogu se priključiti i MCP serveri za koje je korisnik dao ovlašćenje (Google Drive, Notion, Slack, GitHub itd.); model može autonomno pozivati alate više puta unutar jednog zahteva kako bi završio složene zadatke.
- **Strukturirani strimovani događaji**: putem `accept: text/event-stream` ili `application/x-ndjson` mogu se dobiti događaji kao što su `text_delta` po tokenu, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` itd., što olakšava njihovo zasebno prikazivanje prema odgovarajućem tipu na frontendu.
- **Mogućnost prekida / nastavka**: kada model treba da korisnik dopuni informacije, emitovaće događaj `ask_user_question` i pauzirati; pri sledećem pozivu, dovoljno je popuniti odgovor kroz `tool_results` da bi se nastavilo.
- **Nove CRUD radnje**: na istom endpoint-u, putem polja `action`, mogu se izvršiti `retrieve` / `retrieve_batch` / `update` / `delete`, bez potrebe za dodatnim API-jem za upravljanje razgovorima.
- **Lista modela koja se kontinuirano ažurira**: podrazumevano uključuje savremene modele kao što su GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 itd.

Istovremeno je na nivou tela zahteva **u potpunosti unazad kompatibilan sa v1**: dovoljno je poslati `model` + `question` (+ opciono `stateful` / `id` / `references` / `preset`) da biste dobili JSON odgovor `{answer, id}` ekvivalentan v1, tako da pri migraciji sa `/aichat/conversations` nije potrebno prepisivati klijent; potrebno je samo promeniti putanju u `/aichat2/conversations`.

> Ako trenutno koristite `/aichat/conversations`, stari interfejs će i dalje ostati dostupan, pa možete migrirati svojim tempom.

## Proces prijave

Da biste koristili AI Chat v2 API, prvo preuzmite svoj API Token u [Ace Data Cloud konzoli](https://platform.acedata.cloud/console/applications) i sačuvajte ga za kasniju upotrebu.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Ako još niste prijavljeni ili registrovani, automatski ćete biti preusmereni na stranicu za prijavu gde ćete biti pozvani da se registrujete i prijavite; nakon završetka automatski ćete se vratiti na trenutnu stranicu.

**Jedan API Token može pozivati sve usluge platforme; nije potrebno posebno se prijavljivati za svaku uslugu.** Pri prvoj prijavi dobićete besplatni kredit za besplatno isprobavanje; kada kredit nije dovoljan, možete dopuniti opšti saldo u [konzoli](https://platform.acedata.cloud/console/coin).

## Osnovna upotreba

Najjednostavnija upotreba je potpuno ista kao u v1: pošaljite `model` + `question` i dobijte `{answer, id}`.

CURL primer:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Rezultat povratka:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python primer:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Višekružni razgovor

Kao i u v1, pošaljite `stateful: true` da omogućite čuvanje razgovora; API će vratiti `id`; u narednim zahtevima dovoljno je vratiti `id` da biste nastavili razgovor, bez potrebe da sami održavate istoriju messages.

Prvi zahtev:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Povratak:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Drugi zahtev, sa istim `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> Podrazumevana vrednost za `stateful` je `true`, izostavljanje i eksplicitno prosleđivanje `true` su ekvivalentni. Ako ne želite da server sačuva ovaj krug razgovora, možete eksplicitno postaviti `stateful: false`.

## Striming odgovor

v2 podržava dva formata striminga, koji se biraju prema zaglavlju `accept`:

| Scenario                    | `accept`               | Oblik podataka                                  |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web frontend / EventSource  | `text/event-stream`    | `data: {json}\n\n`, poslednji red je `data: [DONE]\n\n` |
| Server / CLI / Node analiza striminga | `application/x-ndjson` | Jedan JSON objekat po redu                               |
| Striming nije potreban                 | `application/json`（podrazumevano） | Jednokratno vraća `{answer, id}`                       |

### NDJSON primer

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Svaki red NDJSON-a je strukturisani događaj, a najčešći je `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE primer

Korišćenje `EventSource` u pregledaču ne podržava prilagođeno telo zahteva, preporučuje se korišćenje `fetch` + ručna analiza po isečcima `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Tipovi striming događaja

| `type`              | Značenje                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `text_delta`        | Inkrementalni tekstualni segment odgovora asistenta. `content` je novi sadržaj; radi kompatibilnosti sa v1, isti događaj nosi i `delta_answer` (jednako `content`) i `id`.                  |
| `thinking`          | Proces razmišljanja modela (pojavljuje se samo kada izabrani model izlaže reasoning).                                                                |
| `tool_use`          | Model odlučuje da pozove alat, događaj nosi `tool_id`, `tool_name`, `input`.                                                  |
| `tool_result`       | Rezultat izvršavanja alata, uparen sa prethodnim `tool_use` putem `tool_id`, `is_error` označava da li je neuspešan.                                       |
| `card`              | Strukturisana kartica koju alat generiše (kao što su slike, pregledi linkova), pogodna za direktno renderovanje.                                                                    |
| `citation`          | URL izvora koji se koristi za dopunjavanje citata odgovarajućeg tekstualnog segmenta.                                                                            |
| `ask_user_question` | Šalje se kada modelu treba da korisnik dopuni informacije, razgovor ulazi u stanje `awaiting_user_input`; detalje pogledajte u nastavku [nastavljanje pauziranog razgovora](#nastavljanje-pauziranog-razgovora).                           |
| `artifact`          | Nezavisan artefakt koji model generiše (kao što su blokovi koda, dokumenti), koji se može sačuvati ili preuzeti.                                                                      |
| `system_message`    | Informacija sistemske poruke (nije sadržaj korisnika ni asistenta), koristi se samo za UI obaveštenja.                                                                     |
| `compact`           | Događaj u kojem je interni kontekst sažet, nije potrebna posebna obrada.                                                                             |
| `error`             | Došlo je do greške u ovom krugu, `message` opisuje sadržaj greške.                                                                        |
| `done`              | Striming odgovor je završen, nosi `usage` (uključujući `prompt_tokens` / `completion_tokens` / `total_tokens`) i `terminal_reason`. |

Za klijente kojima je stalo samo do konačnog odgovora, spajanje `content` iz svih `text_delta` događaja ekvivalentno je vrednosti `answer` u režimu `application/json`.

## Multimodalni unos

Ako korisnički unos sadrži slike ili datoteke, prosledite `message` (niz) umesto `question`. Svaki element niza je blok sadržaja:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Podržani tipovi blokova:

- `text` — običan tekst, polje `text` je obavezno.
- `image_url` — slika, `image_url.url` je obavezno.
- `file_url` — datoteka (PDF, CSV, TXT itd.), `file_url.url` je obavezno.

### Odnos sa v1 `references`

Radi kompatibilnosti sa starim klijentima, v2 i dalje prepoznaje polje `references: ["https://...", ...]`:
- URL sufiks je `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, automatski se pretvara u `image_url` blok;
- Ostale ekstenzije se pretvaraju u `file_url` blok;
- Ako je istovremeno naveden i `question`, onda se on postavlja na početak kao `text` blok.

Stoga, ako samo želite da migrirate sa v1 i ne želite da menjate telo zahteva, dovoljno je da putanju zamenite sa `/aichat2/conversations`, a originalna upotreba `references` nastavlja da radi kao i obično.

Ako vam je potrebna preciznija kontrola (na primer, postavljanje više slika između teksta ili kada je redosled veoma važan), direktno koristite niz `message`.

## Pozivanje alata i MCP

Ključno unapređenje v2 je to što model može samostalno da poziva alate za izvršavanje zadataka u više koraka, **ovo je podrazumevano uključeno**, i ne zahteva nikakvu dodatnu konfiguraciju od klijenta u zahtevu. Uobičajeni scenariji:

- Korisnik pita „Pomozi mi da potražim koje su nove izložbe nedavno u Šangaju“ → model poziva ugrađeni web search → organizuje rezultate u odgovor.
- Korisnik pita „Pročitaj ovaj PDF, a zatim napiši sažetak“ → model poziva file_read → piše sažetak.
- Korisnik je već autorizovao Google Drive / GitHub / Notion itd. u [Connections](https://platform.acedata.cloud/connections) → model može da poziva odgovarajuće MCP alate za čitanje i pisanje njihovih podataka.

U NDJSON / SSE toku, pozivi alata se prikazuju putem dve vrste događaja, `tool_use` i `tool_result`, na primer:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Ako ne želite da prikazujete detalje pozivanja alata na frontendu, dovoljno je da ignorišete događaje `tool_use` / `tool_result` / `card` / `citation`; konačni izlaz modela i dalje teče kroz `text_delta`.

`max_turns` može da ograniči maksimalan broj krugova u kojima model može sam da poziva alate u ovom zahtevu, opseg je 1–500, a podrazumevana vrednost kada se izostavi je 500. Ako ga postavite na manju vrednost (na primer `max_turns: 1`), možete prinuditi jednokratan odgovor i ne dozvoliti nikakve pozive alata.

## Asinhrono izvršavanje i autorizacija bez nadzora

Ako vaš poziv dolazi iz Webhook upozorenja, CI/CD-a, sistema za nadzor ili drugih pozadinskih zadataka, možete postaviti `async: true` kako bi interfejs odmah vratio ID zadatka, dok se izvršavanje nastavlja u pozadini:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Primer odgovora:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Nakon toga možete koristiti `action: retrieve` + `id` za upit rezultata razgovora; možete navesti i `callback_url`, a platforma će po završetku zadatka POST metodom poslati `{ status, answer, usage, error }` na vašu adresu povratnog poziva. `callback_url` mora koristiti `http` / `https` i ne može direktno navesti `localhost` ili literalnu adresu privatnog IP-a.

Za pozadinske zadatke obično nema nikoga ko može da klikne potvrdu. Ako želite da određeni Skill ili MCP Server izvršava radnje poput slanja, objavljivanja i upisivanja u režimu bez nadzora, eksplicitno prosledite listu prethodnog odobrenja u telu zahteva:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Vrednosti u `allowed_skills` su slug-ovi povezanih Skill-ova; vrednosti u `allowed_mcp_servers` su slug-ovi povezanih MCP Servera. Skill / MCP Server koji nije naveden u prethodnom odobrenju u režimu bez nadzora i dalje može samo da pregleda, izvrši dry-run ili odbije izvršavanje operacija pisanja.

Ako je potrebna detaljnija kontrola, možete koristiti i ekvivalentni objekat `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Prethodno odobrenje su same ove dve liste: prazne liste ne odobravaju nijednu mogućnost i nije potrebno dodatno polje prekidača.

Napomena: prethodno odobrenje samo znači „ovaj zahtev dozvoljava ovim mogućnostima da preskoče ljudsku potvrdu u režimu bez nadzora“. Konkretni Skill i dalje mora podržavati `--unattended-confirm` ili odgovarajući bezbednosni mehanizam; u suprotnom će nastaviti sa dry-run režimom i neće direktno izvršiti operacije pisanja.

## Nastavljanje pauziranog razgovora

Neki alati mogu navesti model da „postavi protivpitanje korisniku“, pri čemu model emituje događaj `ask_user_question`, a razgovor se zamrzava u stanju `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Na frontendu prikažite ovaj događaj kao karticu kako bi korisnik izabrao odgovor, a zatim pokrenite sledeći zahtev sa istim `id`, popunjavajući odgovor putem `tool_results`:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

`tool_use_id` u telu zahteva **mora** u potpunosti odgovarati `tool_id` u trenutku pauziranja; nepodudaranje vraća 400. Kada u zahtevu istovremeno postoji `tool_results`, `question` / `message` / `references` će svi biti ignorisani.

Ako korisnik odluči da odustane od ovog pitanja, dovoljno je direktno proslediti novi `question` / `message`, a platforma će automatski označiti pauzirani poziv alata kao „korisnik je preskočio“.

## Upravljanje razgovorima (CRUD)

v2 pruža lagano upravljanje razgovorima putem polja `action` na istom endpoint-u, bez potrebe za dodatnim API-jem.
### `action: retrieve` —— preuzimanje jedne konverzacije

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Vraća kompletan dokument konverzacije (uključujući istoriju `messages`, `model`, `title`, `tools_used` itd.).

### `action: retrieve_batch` —— izlistavanje sažetaka konverzacija

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Vraća `{ items: [...], total }`. **Sažeci ne sadrže `messages`**, pogodni su za listu na bočnoj traci; ako korisnik otvori određenu konverzaciju, zatim upotrebite `action: retrieve` da zasebno preuzmete njene kompletne poruke.

Opcioni parametri filtriranja: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— promena naslova ili ponovno pisanje istorije

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Plan putovanja u Hangdžou"
}
```

`messages` se takođe može proslediti, ali će server vršiti strogu schema validaciju (mora biti u sažetom obliku `ToolUseContent`), a u slučaju neusaglašenosti vratiće 400. Generalno se preporučuje da se koristi samo za promenu `title`.

### `action: delete` —— brisanje jedne konverzacije

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Vraća `{ id, success: true }`. Nakon brisanja nije moguće vraćanje, potvrdite pre poziva.

## Glatka migracija sa v1

Ako već koristite [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), migracija na v2 gotovo da ne zahteva izmene koda:

1. Promenite URL sa `https://api.acedata.cloud/aichat/conversations` na `https://api.acedata.cloud/aichat2/conversations`.
2. Ako ste prethodno prosleđivali v1 nazive modela (kao što su `gpt-3.5`, `gpt-4-browsing` itd.), preporučuje se da pri prelasku na v2 nadogradite na savremene modele (kao što su `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` itd.).
3. Polja NDJSON toka ostaju kompatibilna unazad: svaki `text_delta` događaj i dalje sadrži `delta_answer` i `id`, stoga klijenti koji su prvobitno parsirali `delta_answer` red po red ne zahtevaju izmene.

Nakon migracije možete po potrebi omogućiti nove mogućnosti v2 (multimodalni `message`, SSE, pozivanje alata, `action` CRUD) i napredovati sopstvenim tempom.

## Obrada grešaka

Odgovori na greške imaju jedinstveni format:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Uobičajene greške:

- `400 bad_request`: nedostaju obavezna polja, `tool_use_id` se ne podudara, schema za `messages` je neispravna itd.
- `401 invalid_token`: zaglavlje `authorization` nije ispravno.
- `404 not_found`: konverzacija koja odgovara `id` ne postoji pri `action: retrieve / update / delete`.
- `429 too_many_requests`: aktivirano je ograničenje brzine zahteva.
- `500 chat_error`: uzvodni LLM je prijavio grešku ili je u ovoj rundi `completion_tokens=0` (tretira se kao nepotrošeno i neće biti naplaćeno).

U strimovanom odgovoru, greška se šalje kao događaj `{"type":"error","message":"..."}`, nakon čega se tok odmah završava.

## Zaključak

AI Chat v2 API, uz zadržavanje kompatibilnosti unazad sa v1, unapređuje razgovore od „jednokratnih / višekratnih pitanja i odgovora“ do „Agentizovanih, posmatranih konverzacija“: multimodalni unos, pozivanje alata, mogućnost pauziranja / nastavljanja, strimovani strukturirani događaji, ugrađeni CRUD. Preporučuje se da nove integracije direktno koriste v2; postojeće v1 integracije mogu glatko migrirati u fazama. Ako imate bilo kakvih pitanja, slobodno kontaktirajte naš tim tehničke podrške.
