Discord Agent Proxy je **nezavisno postavljena** usluga: čuva podatke za pristup vašem sopstvenom Discord nalogu, održava stalnu vezu sa Discord-om i izlaže mogućnosti tog naloga putem dva interfejsa, **MCP** i **REST API**, omogućavajući AI-ju ili programu da upravlja Discord-om umesto vas.

Kontejner **ne sadrži nikakav AI model**, već je odgovoran samo za izvršavanje — pozive pokreće vaš AI klijent (Claude, Cursor itd.) ili sopstveni program.

```
AI 客户端  ──MCP /mcp──┐
                       ├─→ Discord Agent Proxy ──→ Discord
你的程序 ──REST /api───┘      （保管你的账号凭据）
```

## ⚠️ Obavezno pročitati pre korišćenja

Automatizovanje radnji na **ličnom nalogu** (self-bot) putem programa krši Discord-ove uslove korišćenja i postoji rizik od zabrane naloga. Ovo je osnovna pretpostavka ove usluge: vi pružate podatke za pristup sopstvenom nalogu i sami snosite rizik.

**Toplo se preporučuje korišćenje posebnog sekundarnog naloga, a ne glavnog naloga.**

## Postavljanje usluge

Otvorite [kontrolna tabla → aplikacije](https://platform.acedata.cloud/console/applications), pronađite Discord Agent Proxy i kreirajte aplikaciju. Nakon kreiranja najpre aktivirajte pretplatu, zatim otvorite stranicu za konfiguraciju, unesite podatke za pristup svom Discord nalogu i postavite uslugu. Resurse instance platforma automatski konfiguriše, bez potrebe za izborom specifikacija.

Nakon slanja postavljanja, otvoriće se stranica za upravljanje aplikacijom, sa istim rasporedom „Pregled / Dnevnici / Dokumentacija“ koji se koristi za postavljanje Telegram-a i WeChat-a. „Pregled“ prikazuje status instance i pretplate, a putem upita za nalog potvrđuje da li je Discord povezan; normalan rad kontejnera ne znači nužno da je nalog povezan.

Kartica Discord naloga u odeljku „Pregled“ pruža dve informacije za pristup:

| Stavka       | Primer                                                       | Namena         |
| -------- | -------------------------------------------------------- | ---------- |
| MCP adresa za pristup | `https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/mcp` | Konfigurisanje u AI klijentu |
| Pristupni token     | `V0p7kAWY...`                                            | Za autentifikaciju, videti u nastavku     |

### Pregled i testiranje interfejsa na kontrolnoj tabli

Otvorite karticu „Dokumentacija“ ove aplikacije da biste pregledali parametre zahteva, strukture odgovora i primere za Shell, Python, JavaScript i druge jezike za svih 14 REST operacija. Adresa instance i pristupni token biće automatski popunjeni; token je podrazumevano skriven.

Izaberite `GET /api/whoami` i kliknite na „Testiraj“ da biste potvrdili nalog povezan sa proxy-jem. Operacije kao što su slanje, uređivanje ili brisanje poruka delovaće na stvarni Discord nalog, zato potvrdite sadržaj zahteva pre testiranja.

„Preuzmi OpenAPI (JSON)“ može izvesti kompletnu definiciju interfejsa. Datoteka sadrži adresu instance, ali ne sadrži pristupni token. Ako je potrebno promeniti podatke za pristup Discord nalogu, u „Pregledu“ izaberite „Ponovo postavi“, unesite nove podatke i pošaljite zahtev.

### Kako dobiti podatke za pristup Discord nalogu

1. Prijavite se na Discord u pregledaču na računaru ([discord.com/app](https://discord.com/app))
2. Pritisnite `F12` da otvorite razvojne alate i prebacite se na panel **Network（mreža）**
3. Proizvoljno kliknite na jedan kanal u Discord-u i posmatrajte listu zahteva
4. Otvorite bilo koji zahtev poslat na `discord.com/api` i pronađite polje `authorization` u **Request Headers（zaglavlja zahteva）**
5. Kopirajte njegovu vrednost

Ovaj niz podataka je jednak stanju prijave na vaš nalog, **ne delite ga ni sa kim**. Ako dođe do curenja, promena lozinke u Discord-u će ga odmah učiniti nevažećim.

## Način autentifikacije

Osim `/health` i `/readyz`, svi interfejsi zahtevaju da se pristupni token prenese u **zaglavlju zahteva**:

```
Authorization: Bearer <你的访问令牌>
```

> **Napomena: ova usluga prihvata samo autentifikaciju putem zaglavlja zahteva i ne podržava način dodavanja tokena na kraj URL-a poput `?token=xxx`.** Direktno otvaranje adrese interfejsa u pregledaču vratiće `401 unauthorized`, što je normalna pojava i ne znači da postavljanje nije uspelo. Ako želite da potvrdite da li je proces aktivan, pristupite `/health`; ako želite da potvrdite da li Discord veza može da obradi zahteve, pristupite `/readyz`. Za obe ove provere nije potrebna autentifikacija. Kada pristupni token proxy-ja nije konfigurisan, zaštićeni interfejsi vraćaju `503` i neće biti anonimno otvoreni.

## Provera statusa usluge

```bash
curl https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/health
curl https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/readyz
```

`/health` samo označava da je HTTP proces aktivan:

```json
{ "status": "ok" }
```

`/readyz` označava da li je Discord Gateway dostupan. Kada je veza normalna, vraća HTTP 200:

```json
{ "status": "ready", "gateway_ready": true }
```

Kada je povezivanje u toku, podaci za pristup nisu važeći ili je veza prekinuta, direktna Kubernetes provera Pod-a vraća HTTP 503, a pozadina instance automatski pokušava ponovo. U tom trenutku Pod se privremeno uklanja iz javnog Service-a, pa nije garantovano da se ovaj dijagnostički JSON može pročitati preko domena instance; proverite status Deployment-a na kontrolnoj tabli i pozovite MCP / REST nakon što se stanje Ready vrati.

## Korišćenje u AI klijentu (MCP)

Kao primer, Claude Code:

```bash
claude mcp add --transport http discord \
  https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/mcp \
  --header "Authorization: Bearer <你的访问令牌>"
```

Za klijente kao što je Cursor koji podržavaju statička zaglavlja zahteva, konfigurišite Streamable HTTP adresu prema njihovoj trenutnoj dokumentaciji. Klijenti koji prihvataju sledeću strukturu mogu koristiti:

```json
{
  "mcpServers": {
    "discord": {
      "type": "http",
      "url": "https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/mcp",
      "headers": {
        "Authorization": "Bearer <你的访问令牌>"
      }
    }
  }
}
```

Ovo nije univerzalni format konfiguracije za sve MCP klijente. Udaljeni konektori za Claude Desktop / Claude.ai uspostavljaju se iz oblaka i ne čitaju nijedno HTTP zaglavlje zahteva iz lokalnog `claude_desktop_config.json`; ako su vam trenutno potrebna statička Bearer zaglavlja zahteva, koristite Claude Code ili klijent koji izričito podržava tu mogućnost.

Nakon završetka konfiguracije, možete direktno koristiti prirodni jezik da naložite AI-ju da upravlja Discord-om, na primer:

> Proveri da li imam novih poruka na kanalu „projektna diskusija“ i, ako je neko pitao za datum objavljivanja, pomozi mi da odgovorim da je ovog petka.

## Korišćenje u programu (REST API)

Svi REST interfejsi su montirani pod `/api`, telo odgovora je ujednačeno `{"data": ...}`, a u slučaju greške je `{"error": "..."}`.

### Pregled trenutnog naloga

```bash
curl https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/api/whoami \
  -H "Authorization: Bearer <你的访问令牌>"
```

### Slanje poruke

```bash
curl -X POST https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/api/messages \
  -H "Authorization: Bearer <你的访问令牌>" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: <本次发送的唯一操作 ID>" \
  -d '{"channel_id": "1234567890", "content": "你好"}'
```

Pri ponovnom pokušaju istog slanja ponovo koristite isti `Idempotency-Key`, proces će vratiti prvi rezultat bez ponovnog slanja. Ponovno pokretanje instance će obrisati memorijske zapise za deduplikaciju od najviše 5.000 stavki, stoga pozivalac i dalje mora sam pratiti dugoročni status isporuke.

Opcioni parametar `reply_to` koristi se za odgovor na određenu poruku:

```json
{ "channel_id": "1234567890", "content": "收到", "reply_to": "9876543210" }
```

### Čitanje poruka

```bash
curl "https://discord-bot-xxxxxxxxxxxx.app.acedata.cloud/api/channels/1234567890/messages?limit=20" \
  -H "Authorization: Bearer <你的访问令牌>"
```

### Kako dobiti ID kanala i ID korisnika

U Discord klijentu redom otvorite **Korisnička podešavanja → Napredna podešavanja**, i uključite **Režim za programere**. Nakon toga desnim klikom na bilo koji kanal ili korisnika, u meniju će se pojaviti „Kopiraj ID“.

Takođe možete direktno pozvati `GET /api/guilds` i `GET /api/guilds/{guild_id}/channels` radi nabrajanja.

## Česta pitanja

**Vraća se `401 unauthorized`**

Pristupni token nije ispravan ili je prenet putem `?token=`. Potvrdite da se token prenosi putem zaglavlja zahteva `Authorization: Bearer &lt;令牌>` i da se podudara sa onim prikazanim u konzoli.

**Vraća se `503`**

Veza sa Discordom još nije uspostavljena. Prvo pristupite `/readyz` da proverite `gateway_ready`; ako je dugo `false`, najčešće su akreditivi naloga nevažeći, pa ih ponovo pribavite i ponovo postavite.

**Vraća se `403` ili `404`**

Sam nalog nema odgovarajuću dozvolu (na primer, nije na tom serveru ili nema pravo da šalje poruke na tom kanalu), ili je ID pogrešno unet. Ove greške dolaze od Discorda, a nisu problem proxy usluge.

**Vraća se `429`**

Aktivirano je Discord ograničenje učestalosti, polje `retry_after` u odgovoru daje preporučeni broj sekundi čekanja. Smanjite učestalost poziva.

**Nalog je blokiran nakon slanja poruke**

Kao što je prethodno navedeno, automatizovane operacije nad ličnim nalogom krše Discord uslove korišćenja. Koristite namenski sekundarni nalog i kontrolišite učestalost operacija, izbegavajući osetljiva ponašanja poput masovnog slanja poruka.
