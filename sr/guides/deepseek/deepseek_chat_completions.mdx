DeepSeek је веома моћан AI систем за разговор, који може генерисати текуће и природне одговоре у року од неколико секунди само уношењем упутства. DeepSeek-V3 се истиче у индустрији својим изузетним способностима разумевања и генерисања језика, а данас се DeepSeek-V3 већ широко примењује у различитим индустријама и областима, а његов утицај постаје све значајнији. Без обзира да ли се ради о свакодневном разговору, креативном писању, или стручном консалтинг, кодирању, DeepSeek-V3 може пружити импресивну интелигентну помоћ, значајно повећавајући људску продуктивност и креативност.

Овај документ углавном описује процес коришћења DeepSeek Chat Completion API, а користећи га можемо лако користити званичну DeepSeek функцију разговора.

## Процес пријаве

Да бисте користили DeepSeek Chat Completion API, прво можете отићи на [DeepSeek Chat Completion API](https://platform.acedata.cloud/documents/2d6a9bae-9a70-4aaa-bd72-28e5bd60fa67) страницу и кликнути на „Acquire“ дугме да бисте добили акредитиве потребне за захтев:

![](https://cdn.acedata.cloud/nyq0xz.png)

Ако нисте пријављени или регистровани, аутоматски ћете бити преусмерени на страницу за пријаву која вас позива да се региструјете и пријавите, а након пријаве или регистрације аутоматски ћете се вратити на тренутну страницу.

При првом захтеву добићете бесплатну квоту, што вам омогућава да бесплатно користите овај API.

## Основна употреба

Након тога можете попунити одговарајуће садржаје на интерфејсу, као што је приказано на слици:

<p><img src="https://cdn.acedata.cloud/m9kxkz.png" width="400" class="m-auto"></p>

Када први пут користите овај интерфејс, потребно је да попуните најмање три садржаја, један је `authorization`, који можете директно изабрати из падајућег менија. Други параметар је `model`, `model` је категорија модела коју одаберете да користите са DeepSeek званичне странице, овде имамо 4 главна модела, детаље можете видети у нашим понуђеним моделима. Последњи параметар је `messages`, `messages` је низ упитника који уносимо, то је низ који представља могућност да се истовремено отпреми више упитника, сваки упитник садржи `role` и `content`, где `role` представља улогу питаоца, а ми нудимо три идентификације: `user`, `assistant`, `system`. Други `content` је конкретан садржај нашег питања.

Такође можете приметити да се на десној страни генерише одговарајући код за позив, можете копирати код и директно га покренути, или можете директно кликнути на „Try“ дугме за тестирање.

Често коришћени опционални параметри:

- `max_tokens`: ограничава максималан број токена у једном одговору.
- `temperature`: генерише случајност, између 0-2, већа вредност значи веће распршивање.
- `n`: колико кандидата одговора генерише одједном.
- `response_format`: подешавање формата повратка.

<p><img src="https://cdn.acedata.cloud/93k4xi.png" width="400" class="m-auto"></p>

Након позива, открили смо да је повратни резултат следећи:

```json

  "choices": [
    {
      "index": 0,

      "logprobs": null,

      "service_tier": null

```

Повратни резултат има више поља, описана као:

- `id`, ID генерисаног дијалога, који служи за јединствено идентификовање овог дијалога.
- `created`, информације о времену креирања овог дијалога.
- `model`, одабрани DeepSeek модел.
- `choices`, информације о одговору које DeepSeek даје на упит.
- `usage`: статистичке информације о токенима за овај упит.

Унутар `choices` налази се информација о одговору DeepSeek, а унутар `choices` су одговори DeepSeek, што можете видети на слици.

<p><img src="https://cdn.acedata.cloud/0pd4q5.png" width="400" class="m-auto"></p>

Можете видети да поље `content` унутар `choices` садржи конкретан садржај одговора DeepSeek.

## Стриминг одговора

Овај интерфејс такође подржава стреаминг одговора, што је веома корисно за веб интеграцију, јер омогућава веб страници да реализује ефекат приказивања по словима.

Ако желите да добијете одговор у стреаминг формату, можете променити параметар `stream` у заглављу захтева на `true`.

Промена је приказана на слици, али код позива мора бити одговарајуће измене да би подржао стреаминг одговор.

<p><img src="https://cdn.acedata.cloud/dsoiqw.png" width="400" class="m-auto"></p>

Након промене `stream` на `true`, API ће враћати одговарајуће JSON податке ред по ред. На нивоу кода, потребно је направити одговарајуће измене да бисте добили редне резултате.

Python пример кода за позив:

```python
import requests

url = "https://api.acedata.cloud/deepseek/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "deepseek-v3",
    "messages": [{"role":"user","content":"hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Možete videti da odgovor sadrži mnogo `data`, a `data` unutar `choices` predstavlja najnoviji sadržaj odgovora, u skladu sa prethodno opisanim sadržajem. `choices` su novi odgovori koje možete povezati sa vašim sistemom. Takođe, završetak strimovane odgovore se određuje prema sadržaju `data`, ako je sadržaj `[DONE]`, to znači da je strimovani odgovor potpuno završen. Vraćeni `data` rezultati imaju više polja, a opis je sledeći:

- `id`, ID koji generiše ovu razgovornu zadatak, koristi se za jedinstveno identifikovanje ovog razgovora.
- `model`, izabrani model sa DeepSeek zvanične stranice.
- `choices`, odgovori koje DeepSeek daje na postavljena pitanja.

JavaScript takođe podržava, na primer, kod za strimovano pozivanje u Node.js je sledeći:

```javascript
const options = {
  method: "post",
  headers: {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    "model": "deepseek-v3",
    "messages": [{"role":"user","content":"zdravo"}],
    "stream": true
  })
};

fetch("https://api.acedata.cloud/deepseek/chat/completions", options)
  .then(response => response.json())
  .then(response => console.log(response))
  .catch(err => console.error(err));
```

Java uzorak koda:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "deepseek-v3");
jsonObject.put("messages", [{"role":"user","content":"zdravo"}]);
jsonObject.put("stream", true);
MediaType mediaType = "application/json; charset=utf-8".toMediaType();
RequestBody body = jsonObject.toString().toRequestBody(mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/deepseek/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.print(response.body!!.string())
```

Ostali jezici mogu se prepraviti na sličan način, princip je isti.

## Višekratni razgovor

Ako želite da povežete funkcionalnost višekratnog razgovora, potrebno je da u `messages` polje pošaljete više pitanja, konkretni primeri više pitanja su prikazani na sledećoj slici:
<p><img src="https://cdn.acedata.cloud/7yyhl4.png" width="400" class="m-auto"></p>

Python пример кода за позив:

```python
import requests

url = "https://api.acedata.cloud/deepseek/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "deepseek-v3",
    "messages": [{"role":"user","content":"Zdravo"},{"role":"assistant","content":"Zdravo! Kako mogu da vam pomognem danas?"},{"role":"user","content":"Šta sam upravo rekao?"}]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Kroz učitavanje više pitanja, lako se može ostvariti višekratni razgovor, a može se dobiti sledeći odgovor:

## Obrada grešaka

Kada pozivate API, ako naiđete na grešku, API će vratiti odgovarajući kod greške i informacije. Na primer:

- `400 token_mismatched`: Neispravna zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `400 api_not_implemented`: Neispravna zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `401 invalid_token`: Neautorizovano, nevalidan ili nedostajući autorizacioni token.
- `429 too_many_requests`: Previše zahteva, premašili ste limit brzine.
- `500 api_error`: Interna greška servera, nešto nije u redu sa serverom.
