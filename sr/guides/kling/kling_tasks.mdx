Главна функција Kling Tasks API је да омогући проверу статуса извршења задатка путем ID-a задатка генерисаног од Kling Videos Generation API.

Овај документ ће детаљно описати упутство за интеграцију Kling Tasks API, помажући вам да лако интегришете и максимално искористите моћне функције овог API. Користећи Kling Tasks API, можете лако проверити статус извршења задатака Kling Videos Generation API.

## Процес пријаве

Да бисте користили Kling Tasks API, прво морате да се пријавите на страници [Kling Videos Generation API](https://platform.acedata.cloud/documents/3b921a16-a411-4557-8335-53f21d3f9e46) за одговарајућу услугу, а затим копирајте ID задатка Kling Videos Generation API, као што је приказано на слици:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

На крају, идите на страницу Tasks API [Pika Tasks API](https://platform.acedata.cloud/documents/6b43ff7b-8298-49c8-a390-83df85c2c5e5) да бисте затражили одговарајућу услугу, а након уласка на страницу, кликните на дугме „Acquire“, као што је приказано на слици:

![Пријавна страница](https://cdn.acedata.cloud/rci31i.png)

Ако се још нисте пријавили или регистровали, аутоматски ћете бити преусмерени на [страницу за пријаву](https://platform.acedata.cloud) која вас позива да се региструјете и пријавите, а након пријаве и регистрације аутоматски ћете се вратити на тренутну страницу.

При првом захтеву добићете бесплатну количину, коју можете користити без накнаде.

## Пример захтева

Kling Tasks API може се користити за проверу резултата Kling Videos Generation API. За информације о томе како користити Kling Videos Generation API, молимо вас да се упутите на документ [Kling Videos Generation API](https://platform.acedata.cloud/documents/3b921a16-a411-4557-8335-53f21d3f9e46).

Узмимо за пример ID задатка који је вратила услуга Kling Videos Generation API, и демонстрираћемо како користити овај API. Хајде да претпоставимо да имамо ID задатка: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, а затим ћемо демонстрирати како да пренесемо ID задатка.

### Постављање заглавља захтева и тела захтева

**Request Headers** укључује:

- `accept`: одређује да се примају одговори у JSON формату, овде се попуњава као `application/json`.
- `authorization`: кључ за позивање API, који можете директно изабрати након пријаве.

**Request Body** укључује:

- `id`: ID задатка који се преноси.
- `action`: начин операције над задатком.

Поставите као што је приказано на слици:

### Пример кода

Можете приметити да су на десној страни странице аутоматски генерисани кодови на различитим језицима, као што је приказано на слици:

<p><img src="https://cdn.acedata.cloud/bsqh3i.png" width="500" className="m-auto" /></p>

Делимични примери кода су следећи:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Greška u obradi

Kada pozivate API, ako naiđete na grešku, API će vratiti odgovarajući kod greške i informacije. Na primer:

- `400 token_mismatched`：Loš zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `400 api_not_implemented`：Loš zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `401 invalid_token`：Neautorizovano, nevalidan ili nedostajući autorizacioni token.
- `429 too_many_requests`：Previše zahteva, premašili ste limit brzine.
- `500 api_error`：Interna greška servera, nešto nije u redu sa serverom.
