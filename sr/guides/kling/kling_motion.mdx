Овај документ ће представити упутство за интеграцију Kling Motion Generation API, који може генерисати Kling званичне видео записе уношењем прилагођених параметара.

## Процес пријаве

Да бисте користили API, прво идите на [Kling Motion Generation API](https://platform.acedata.cloud/documents/d3f2c369-102d-4856-9565-702ac5f2df63) страницу за пријаву на одговарајућу услугу, након што уђете на страницу, кликните на дугме „Acquire“, као што је приказано на слици:

![](https://cdn.acedata.cloud/q6ytrc.png)

Ако још нисте пријављени или регистровани, аутоматски ћете бити преусмерени на страницу за пријаву која вас позива да се региструјете и пријавите, након пријаве или регистрације, аутоматски ћете се вратити на тренутну страницу.

При првом захтеву добићете бесплатну квоту, која вам омогућава да бесплатно користите овај API.

## Основна употреба

Прво, упознајте се са основним начином коришћења, што подразумева унос кључне речи `prompt`, референтне слике `image_url` и линка на референтни видео `video_url`, чиме добијате обрађени резултат, а затим треба да унесете модел `mode`, који тренутно укључује `std` и `pro` моделе, конкретно:

<p><img src="https://cdn.acedata.cloud/5qlpjt.png" width="500" class="m-auto"></p>

Можете видети да смо овде подесили Request Headers, укључујући:

- `accept`: каквог формата желите да примите одговор, овде је написано `application/json`, што значи JSON формат.
- `authorization`: кључ за позивање API, који можете директно изабрати након пријаве.

Такође смо подесили Request Body, укључујући:

- `image_url`: референтна слика, елементи као што су особе и позадина у генерисаном видеу су засновани на овој слици.
- `video_url`: линк за добијање референтног видеа. Покрети особа у генерисаном видеу ће бити у складу са референтним видеом.
- `mode`: режим генерисања видеа, углавном постоје стандардни режим `std` и супер брзи режим `pro`.
- `keep_original_sound`: можете изабрати да ли да задржите оригинални звук видеа, вредности: yes, no.
- `character_orientation`: оријентација особа у генерисаном видеу, можете изабрати да буде у складу са сликом или видеом, вредности: image, video.
- `prompt`: кључна реч.
- `callback_url`: URL на који треба да се врати резултат.

Након избора, можете приметити да је на десној страни генерисан одговарајући код, као што је приказано на слици:

Ако желите да генеришете одговарајући код за интеграцију, можете га директно копирати, на пример, CURL код је следећи:

```shell
curl -X POST 'https://api.acedata.cloud/kling/motion' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": "https://sourceyoya.wenge.com/2025/06/03/683e9f76e4b0684509ab1aca.jpg",
  "video_url": "https://cdn.acedata.cloud/odwfm5.mp4",
  "prompt": "оживите слику",
  "mode": "std",
  "character_orientation": "image"
}'
```

## Асинхрони повратни позив

Пошто време генерисања Kling Motion Generation API-а траје релативно дуго, око 1-2 минута, ако API дуго не одговара, HTTP захтев ће задржати везу, што доводи до додатне потрошње системских ресурса, па овај API такође пружа подршку за асинхрони повратни позив.

Цела процедура је: када клијент покрене захтев, додатно одређује поље `callback_url`, након што клијент покрене API захтев, API ће одмах вратити резултат, који садржи информације о пољу `task_id`, што представља ID тренутног задатка. Када задатак буде завршен, резултат генерисаног видеа ће бити послат на `callback_url` који је клијент одредио у POST JSON формату, а у томе ће бити укључено и поље `task_id`, тако да се резултат задатка може повезати преко ID-а.

Испод ћемо кроз пример објаснити како конкретно да поступите.

Прво, Webhook повратни позив је услуга која може примати HTTP захтеве, програмери би требали заменити URL сопственог HTTP сервера. Овде, ради лакшег демонстрирања, користи се јавни Webhook пример веб сајта https://webhook.site/, отворите тај сајт и добићете Webhook URL, као што је приказано на слици:

![](https://cdn.acedata.cloud/tbcnai.png)
Копирајте овај URL и можете га користити као Webhook, пример је `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Након тога, можемо подесити поље `callback_url` на горњи Webhook URL, истовремено попуњавајући одговарајуће параметре, конкретан садржај је приказан на слици:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" class="m-auto"></p>

Кликните на покрени, и можете приметити да ћете одмах добити резултат, као што је приказано:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Након кратког чекања, можемо наћи резултат генерисаног видеа на `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, као што је приказано на слици:

![](https://cdn.acedata.cloud/zv5u2q.png)

Садржај је следећи:

```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7822108635/text2video/CjJzzGfBfqcAAAAAAKdVMQ-0_raw_video_1.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Можете видети да у резултату постоји поље `task_id`, а остала поља су слична као у претходном тексту, преко овог поља можете остварити повезаност задатка.

## Обрада грешака

Када позивате API, ако наиђете на грешку, API ће вратити одговарајући код грешке и информације. На пример:

- `400 token_mismatched`: Лош захтев, могуће због недостајућих или неважећих параметара.
- `400 api_not_implemented`: Лош захтев, могуће због недостајућих или неважећих параметара.
- `401 invalid_token`: Неправилно овлашћење, неважећи или недостајући токен за овлашћење.
- `429 too_many_requests`: Превише захтева, прелазите лимит.
- `500 api_error`: Унутрашња грешка сервера, нешто није у реду на серверу.

### Пример одговора на грешку

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
