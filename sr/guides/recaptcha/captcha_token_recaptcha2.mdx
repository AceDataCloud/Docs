Овај документ ће представити начин интеграције Recaptcha2 протокола идентификације API, који омогућава корисницима да не морају да идентификују и кликну на Recaptcha2 верификационе слике, већ само да поднесу Website Key како би се реализовала аутоматска декодирања у позадини и завршила верификација.

## Процес пријаве

Да бисте користили Recaptcha2 протокол идентификације API, прво идите на [Ace Data Cloud контролни панел](https://platform.acedata.cloud/console/applications) да добијете ваш API Token, који ћете задржати за резерву.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Ако се још нисте пријавили или регистровали, аутоматски ћете бити преусмерени на страницу за пријаву која вас позива да се региструјете и пријавите, а након тога ћете бити аутоматски враћени на тренутну страницу.

**Један API Token је довољан за позивање свих услуга платформе, без потребе да се за сваку услугу посебно пријављујете.** При првом захтеву добићете бесплатан кредит, који можете бесплатно испробати; када вам кредит буде недовољан, можете допунити општи баланс на [контролном панелу](https://platform.acedata.cloud/console/coin).

> 📘 Пуна документација: [Recaptcha2 протокол идентификације API →](https://platform.acedata.cloud/documents/captcha-token-recaptcha2)

## Основна употреба

Прво, упознајте се са основним начином коришћења, а то је уношење URL адресе веб странице која захтева обраду верификационог кода, чиме добијате обрађени резултат. Прво је потребно једноставно проследити поље `website_url`, наша пример веб страница је: `https://www.google.com/recaptcha/api2/demo`, потребно је да на `website_url` страници добијете `website_key`, прво отворите ову веб страницу, притисните F12 да уђете у конзолу, а затим у Element страници извршите глобалну претрагу за `recaptcha-demo`, добићемо следећи резултат:

<p><img src="https://cdn.acedata.cloud/hvx41c.png" width="500" className="m-auto" /></p>

Ту `data-sitekey` одговара низу знакова који представљају вредност `website_key`, испод су конкретни параметри резултата:

<p><img src="https://cdn.acedata.cloud/8oowyw.png" width="500" className="m-auto" /></p>

Можете видети да смо овде поставили Request Headers, укључујући:

- `accept`: каквог формата желите да примите одговор, овде је написано `application/json`, што значи JSON формат.
- `authorization`: кључ за позивање API, након пријаве можете директно изабрати из падајућег менија.

Такође смо поставили Request Body, укључујући:

- `website_url`: URL адреса веб странице која захтева обраду верификационог кода.
- `website_key`: идентификатор веб кључа у Recaptcha2.
- `proxy`: опционално, доноси сопствени прокси (Bring Your Own Proxy). Након постављања, услуга ће користити прокси IP који сте навели за решавање верификационог кода, што се користи за контролу квалитета излазног IP (на пример, избегавање блокирања од стране циљне странице због јавног прокси IP-а који враћа `410 Gone`). Формат је `scheme://[user:pass@]host:port`, `scheme` подржава `http`/`https`/`socks4`/`socks5`, на пример `http://user:pass@1.2.3.4:8080`. Ако не попуните, користиће се подразумевани прокси платформе.

Из горње слике можемо закључити да је URL овог POST захтева: `https://www.google.com/recaptcha/api2/demo`, потребно је само да пошаљемо параметар `g-recaptcha-response`, а затим само треба да пренесемо обрађени токен у доњи data, а конкретан CURL код за верификацију токена је следећи:

```shell
curl 'https://www.google.com/recaptcha/api2/demo' \
  --data-raw 'g-recaptcha-response={token}’
```

Код за верификацију токена у Python-у је следећи:

```python
import requests

token = '{token}'

data = {
    'g-recaptcha-response': token,
}

response = requests.post('https://www.google.com/recaptcha/api2/demo',data=data)

if response.status_code:
    print(response.text)

```

Ако желите да генеришете одговарајући код за интеграцију, можете директно копирати генерисани код, на пример CURL код је следећи:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo"
}'
```

Python код за интеграцију је следећи:

```python
import requests

url = "https://api.acedata.cloud/captcha/token/recaptcha2"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
    "website_url": "https://www.google.com/recaptcha/api2/demo"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Асинхрони мод

По подразумеваној поставци, API је синхроног блокирајућег типа: један захтев ће чекати све док обрада токена не буде завршена. Ако радите ротацију више решавача (multi-solver rotation) и желите „одмах добити task_id након подношења задатка, прво да распоредите друге решаваче, а касније се вратите да прочитате резултат“, можете у телу захтева послати `async: true`.

Када пошаљете `async: true`, интерфејс ће одмах вратити `task_id`, а неће блокирати чекање:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

Ако желите активно да проверите напредак, можете користити тај `task_id` за упит `POST /captcha/tasks` (препоручује се сваких 3~5 секунди). Овај интерфејс неће покренути или напредовати обраду задатка; чак и ако не упитате, прекинете интернет или напустите клијента, сервер ће наставити обраду:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Током обраде враћаће `status: processing`:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

Када се обрада заврши, враћаће `status: ready` и токен:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "token": "03AFcWeA5kjJyDQ9S1a9UYimR6nuxnpEnAs5x2Pixao0dXZhMB......"
}
```

Објашњење наплате: у асинхроном режиму, креирање задатка и читање статуса „обрађује се“ не наплаћује се; **клијент ће бити наплаћен једном када први пут прочита успешан резултат** (што је у складу са постојећим понашањем и ценом синхроног режима). Сервер ће самостално напредовати задатак, али неће наплатити унапред само зато што је задатак завршен у позадини. Задатак који не буде успешан у року од 120 секунди биће прекинут са HTTP 504 `timeout`, без наплате. `/captcha/tasks` не одговара за напредовање задатка.

## Обрада грешака

Када позивате API, ако наиђете на грешку, API ће вратити одговарајући код грешке и информације. На пример:

- `400 token_mismatched`: Лош захтев, могуће због недостајућих или неважећих параметара.
- `400 api_not_implemented`: Лош захтев, могуће због недостајућих или неважећих параметара.
- `401 invalid_token`: Неправилно, неважећи или недостајући ауторизациони токен.
- `429 too_many_requests`: Превише захтева, прелазите лимит.
- `500 api_error`: Унутрашња грешка сервера, нешто није у реду на серверу.

### Пример одговора на грешку

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
