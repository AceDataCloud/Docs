Овај документ ће представити начин интеграције Recaptcha2 протокола идентификације API, који омогућава корисницима да не морају да идентификују и кликну на Recaptcha2 верификационе слике, већ само да поднесу Website Key како би се реализовала аутоматска декодирања у позадини и завршила верификација.

## Процес пријаве

Да бисте користили API, прво морате да одете на [Recaptcha2 протокол идентификације API](https://platform.acedata.cloud/documents/597b8f11-26d8-4a1d-9a83-8d33bc4b8af7) одговарајућу страницу и затражите одговарајућу услугу, након уласка на страницу, кликните на дугме „Acquire“, као што је приказано на слици:

![](https://cdn.acedata.cloud/q6ytrc.png)

Ако се још нисте пријавили или регистровали, аутоматски ћете бити преусмерени на страницу за пријаву која вас позива да се региструјете и пријавите, након пријаве или регистрације аутоматски ћете се вратити на тренутну страницу.

При првом захтеву биће вам додељен бесплатан кредит, који можете користити за API.

## Основна употреба

Прво, потребно је разумети основни начин коришћења, а то је уношење URL адресе веб странице која треба да обради верификацију, чиме добијате обрађени резултат. Прво је потребно једноставно проследити поље `website_url`, наша пример веб страница је: `https://www.google.com/recaptcha/api2/demo`, потребно је да на `website_url` страници добијете `website_key`, прво отворите ову веб страницу, притисните F12 да уђете у конзолу, а затим у Element страници извршите глобалну претрагу за `recaptcha-demo`, добићемо следећи резултат:

<p><img src="https://cdn.acedata.cloud/hvx41c.png" width="500" className="m-auto" /></p>

Где `data-sitekey` одговарајућа низ стрингова је вредност `website_key`, испод су конкретни параметри резултата:

<p><img src="https://cdn.acedata.cloud/8oowyw.png" width="500" className="m-auto" /></p>

Можете видети да смо овде поставили Request Headers, укључујући:

- `accept`: каквог формата желите да примите одговор, овде је написано `application/json`, тј. JSON формат.
- `authorization`: кључ за позивање API, након захтева можете директно изабрати из падајућег менија.

Такође је подешен Request Body, укључујући:

- `website_url`: URL адреса веб странице која треба да обради верификацију.
- `website_key`: идентификатор веб кључа у Recaptcha2.

Из горње слике можемо закључити да је URL за POST захтев: `https://www.google.com/recaptcha/api2/demo`, потребно је само да пошаљемо параметар `g-recaptcha-response`, а затим само треба да пренесемо обрађени токен у доњи data, а конкретан CURL код за верификацију токена изгледа овако:

```shell
curl 'https://www.google.com/recaptcha/api2/demo' \
  --data-raw 'g-recaptcha-response={token}’
```

Код у Питону за верификацију токена изгледа овако:

```python
import requests

token = '{token}'

data = {
    'g-recaptcha-response': token,
}

response = requests.post('https://www.google.com/recaptcha/api2/demo',data=data)

if response.status_code:
    print(response.text)

```

Ако желите да генеришете одговарајући код за интеграцију, можете директно копирати генерисани код, на пример CURL код изгледа овако:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo"
}'
```

Питон код за интеграцију изгледа овако:

```python
import requests

url = "https://api.acedata.cloud/captcha/token/recaptcha2"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
    "website_url": "https://www.google.com/recaptcha/api2/demo"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Обрада грешака

Када позивате API, ако наиђете на грешку, API ће вратити одговарајући код грешке и информације. На пример:

- `400 token_mismatched`: Лош захтев, могуће због недостајућих или неважећих параметара.
- `400 api_not_implemented`: Лош захтев, могуће због недостајућих или неважећих параметара.
- `401 invalid_token`: Неправилно, неважећи или недостајући токен за ауторизацију.
- `429 too_many_requests`: Превише захтева, прелазите лимит.
- `500 api_error`: Унутрашња грешка сервера, нешто није у реду на серверу.

### Пример одговора на грешку

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
