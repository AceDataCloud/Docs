Ovaj dokument će predstaviti način integracije Recaptcha2 API za prepoznavanje slika, koji može da vrati koordinate malih slika koje treba kliknuti na osnovu sadržaja koji korisnik unese i Recaptcha2 CAPTCHA slike, čime se završava verifikacija.

## Proces prijave

Da biste koristili Recaptcha2 API za prepoznavanje slika, prvo idite na [Ace Data Cloud kontrolnu tablu](https://platform.acedata.cloud/console/applications) da dobijete svoj API Token, koji čuvate za kasniju upotrebu.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Ako se još niste prijavili ili registrovali, automatski ćete biti preusmereni na stranicu za prijavu koja vas poziva da se registrujete i prijavite, a nakon toga ćete se automatski vratiti na trenutnu stranicu.

**Jedan API Token može da pozove sve usluge platforme, nije potrebno da se za svaku uslugu posebno prijavljujete.** Prilikom prve prijave dobijate besplatni kredit, koji možete besplatno isprobati; kada vam ponestane kredita, možete dopuniti opšti saldo na [kontrolnoj tabli](https://platform.acedata.cloud/console/coin).

> 📘 Potpuna dokumentacija: [Recaptcha2 API za prepoznavanje slika →](https://platform.acedata.cloud/documents/captcha-recognition-recaptcha2)

## Osnovna upotreba

Prvo se upoznajte sa osnovnim načinom korišćenja, potrebno je da snimite Recaptcha2 CAPTCHA sliku sa veb sajta, ovde je URL primer sajta: `https://www.google.com/recaptcha/api2/demo`, a konkretna stranica je prikazana na sledećem slici:

<p><img src="https://cdn.acedata.cloud/3mgkjk.png" width="500" className="m-auto" /></p>

Moramo da kliknemo na kvadratić za CAPTCHA da bi se pojavila CAPTCHA slika, a u gornjoj slici žutom strelicom je označen deo teksta, koji predstavlja vrednost `question` u nastavku. Prvo je potrebno jednostavno proslediti polje `image`, što je konkretna Recaptcha2 CAPTCHA slika, koja je označena crvenom strelicom na gornjoj slici, a slika mora biti skalirana na standardnu veličinu (100x100, 300x300, 450x450), tako da usluga može da odredi tip slike, a kompresiju slike morate izvršiti sami. U ovom dokumentu preporučujemo jedan [sajt za kompresiju](https://www.photopea.com/), gde možete izvršiti promene u dimenzijama i veličini slike, a rezultat kompresije je prikazan na slici ispod:

![](https://cdn.acedata.cloud/l7aotl.png)

Možemo videti da smo ovde postavili Request Headers, uključujući:

- `accept`: format odgovora koji želite da primite, ovde je uneto `application/json`, što znači JSON format.
- `authorization`: ključ za pozivanje API-ja, koji možete direktno izabrati nakon prijave.

Takođe je postavljen Request Body, uključujući:

- `image`: CAPTCHA slika kodirana u Base64.
- `question`: ID pitanja, molimo proverite tabelu, počinje sa /m/.

Nakon izbora, možete primetiti da je sa desne strane generisan odgovarajući kod, kao što je prikazano na slici ispod:

<p><img src="https://cdn.acedata.cloud/bsp8g9.png" width="500" className="m-auto" /></p>

Kliknite na dugme „Try“ da biste izvršili test, kao što je prikazano na slici, ovde smo dobili sledeći rezultat:

```json

    "size": 300,
    "label": "/m/01pns0",
    "confidences": [
      0,

      1,

      1,
      0,

    ],
    "objects": [
      2,
      5,
      7
    ],
    "type": "multi"
  }

```

Vraćeni rezultat sadrži više polja, koja su objašnjena u nastavku:

- `solution`, rezultat verifikacije nakon obrade Recaptcha2 CAPTCHA slike.
    - `size`, dimenzije Recaptcha2 CAPTCHA slike.
    - `label`, sadržaj prepoznat na Recaptcha2 CAPTCHA slici.
    - `confidences`, stepen poverenja u prepoznate oblasti na Recaptcha2 CAPTCHA slici, oblasti počinju od 0.
    - `objects`, oblasti koje zadovoljavaju prepoznate sadržaje na Recaptcha2 CAPTCHA slici, oblasti počinju od 0.
    - `type`, tip zadatka za Recaptcha2 CAPTCHA sliku, kada ima više oblasti, označava se kao `multi`.
- `started_at`, `finished_at`: vreme kada je zahtev započeo obradu i kada je rezultat proizveden, Unix vremenski pečat (sekunde, decimalni).
- `elapsed`: ukupno vreme obrade (sekunde).

Možemo videti da smo dobili rezultat verifikacije za obradu Recaptcha2 CAPTCHA slike, prvo delimo CAPTCHA sliku na oblasti, kao što je prikazano na slici ispod:

<p><img src="https://cdn.acedata.cloud/2d6qhx.png" width="500" className="m-auto" /></p>

Možemo primetiti da oblasti počinju od 0, a iz rezultata `objects` dobijamo 2, 5, 7, što znači da je potrebno simulirati klik na ta tri područja da bismo prošli verifikaciju.

Takođe, ako želite da generišete odgovarajući kod za integraciju, možete jednostavno kopirati generisani kod, na primer, CURL kod je sledeći:
```shell
curl -X POST 'https://api.acedata.cloud/captcha/recognition/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "question": "/m/01pns0",
  "image": "iVBORw0KGgoAAAANSUhEUgAAASoAAAEsCAIAAAD7AWllAAAAAX..."
}'
```

Python код за интеграцију изгледа овако:

```python
import requests

url = "https://api.acedata.cloud/captcha/recognition/recaptcha2"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "question": "/m/01pns0",
    "image": "iVBORw0KGgoAAAANSUhEUgAAASoAAAEsCAIAAAD7AWllAAAAAX..."
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asinhroni režim (async)

Podrazumevano, API je sinhrono blokirajući: jedan zahtev će čekati dok se obrada rezultata prepoznavanja ne završi. Ako radite sa višestrukim rešenjima (multi-solver rotation) i želite da „odmah dobijete task_id nakon slanja zadatka, a zatim pređete na raspoređivanje drugih rešenja, a kasnije se vratite po rezultate“, možete u telu zahteva dodati `async: true`.

Kada se unese `async: true`, interfejs će odmah vratiti `task_id`, a neće blokirati čekajući:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/recognition/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "question": "/m/01pns0",
  "image": "iVBORw0KGgoAAAANSUhEUgAAASoAAAEsCAIAAAD7AWllAAAAAX...",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

Ako želite aktivno da proverite napredak, možete koristiti taj `task_id` za upit `POST /captcha/tasks` (preporučuje se svake 3~5 sekundi). Ovaj interfejs neće pokrenuti ili ubrzati obradu zadatka; čak i ako ne proveravate, izgubite internet ili napustite klijent, server će i dalje nastaviti sa obradom:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Tokom obrade biće vraćeno `status: processing`:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

Kada se obrada završi, biće vraćeno `status: ready` i rezultat prepoznavanja `solution` (struktura polja je potpuno identična onoj u sinhronom režimu):

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "solution": {
    "size": 300,
    "label": "/m/01pns0",
    "objects": [2, 5, 7],
    "type": "multi"
  }
}
```

Objašnjenje naplate: u asinhronom režimu, kreiranje zadatka i čitanje statusa „u obradi“ se ne naplaćuju; **klijent se naplaćuje kada prvi put uspešno pročita rezultat** (što je u skladu sa postojećim ponašanjem i cenama sinhronog režima). Server će samostalno napredovati sa zadatkom, ali neće naplatiti unapred samo zato što je pozadina završila. Ako zadatak ne uspe u roku od 120 sekundi, biće prekinut sa HTTP 504 `timeout`, bez naplate. `/captcha/tasks` nije odgovoran za napredovanje zadatka.

## Obrada grešaka

Kada pozivate API, ako naiđete na grešku, API će vratiti odgovarajući kod greške i informacije. Na primer:

- `400 token_mismatched`: Neispravan zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `400 api_not_implemented`: Neispravan zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `401 invalid_token`: Neautorizovano, nevalidan ili nedostajući autorizacioni token.
- `429 too_many_requests`: Previše zahteva, premašili ste limit brzine.
- `500 api_error`: Interna greška servera, nešto nije u redu sa serverom.

### Primer greške u odgovoru

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
