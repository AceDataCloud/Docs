Овај документ ће представити начин интеграције Recaptcha3 протокола идентификације API, који омогућава корисницима да не морају да идентификују и кликну на Recaptcha3 CAPTCHA слике, већ само да поднесу Website Key како би се реализовала аутоматска декодирања у позадини и завршила верификација.

## Процес пријаве

Да бисте користили Recaptcha3 протокол идентификације API, прво идите на [Ace Data Cloud контролни панел](https://platform.acedata.cloud/console/applications) да бисте добили ваш API Token, који ћете задржати за резерву.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Ако се још нисте пријавили или регистровали, аутоматски ћете бити преусмерени на страницу за пријаву која вас позива да се региструјете и пријавите, а након тога ћете бити аутоматски враћени на тренутну страницу.

**Један API Token је довољан за позивање свих услуга платформе, без потребе да се за сваку услугу посебно пријављујете.** При првом захтеву добићете бесплатну квоту, коју можете бесплатно испробати; када вам квота понестане, можете допунити општи баланс на [контролном панелу](https://platform.acedata.cloud/console/coin).

> 📘 Пуна документација: [Recaptcha3 протокол идентификације API →](https://platform.acedata.cloud/documents/captcha-token-recaptcha3)

## Основна употреба

Прво, упознајте се са основним начином коришћења. У поређењу са Recaptcha2, потребно је додати још један параметар `page_action`, а овај параметар се добија из кода. URL за демонстрацију мреже је: `https://recaptcha-demo.appspot.com/recaptcha-v3-request-scores.php`, а испод је приказан један од начина за добијање:

### Брзи метод:

Отворите f12, а затим у Element страници претражите `.execute(`, у области обележеној црвеним оквиром можемо видети параметар `action`, а иза execute-а следи низ знакова, што је такође садржај који нам је потребан, конкретно, као што је приказано на слици испод.

<p><img src="https://cdn.acedata.cloud/imwlto.png" width="500" className="m-auto" /></p>

Затим је потребно унети URL веб странице на којој се обрађује CAPTCHA, како бисте добили обрађени резултат. Прво је потребно једноставно проследити поље `website_url`, а на крају је потребно унети параметар `website_key`, који се може добити из горњег текста, такође као низ знакова иза execute-а. Сада можемо попунити одговарајуће садржаје на интерфејсу, као што је приказано на слици:

<p><img src="https://cdn.acedata.cloud/1hw2uo.png" width="500" className="m-auto" /></p>

Можете видети да смо овде подесили Request Headers, укључујући:

- `accept`: какве формате одговора желите да примите, овде је написано `application/json`, што значи JSON формат.
- `authorization`: кључ за позивање API-а, који можете директно изабрати након пријаве.

Такође смо подесили Request Body, укључујући:

- `page_action`: потребно је добити из кода веб странице на којој се обрађује CAPTCHA.
- `website_url`: URL веб странице на којој се обрађује CAPTCHA.
- `website_key`: идентификатор веб кључа у Recaptcha3.

Након избора, можете приметити да је на десној страни генерисан одговарајући код, као што је приказано на слици:

Rezultat sadrži više polja, opisana kao:

- `token`, rezultat verifikacije nakon obrade Recaptcha3.
- `started_at`, `finished_at`: vreme početka obrade i dobijanja rezultata, Unix vremenski pečat (sekunde, decimalni).
- `elapsed`: ukupno vreme obrade (sekunde).

Možemo videti da smo dobili rezultat verifikacije Recaptcha3, koji možemo koristiti za POST ili GET simulaciju slanja na ciljnu veb stranicu, jednokratna upotreba, važenje 120s, preporučuje se korišćenje unutar 60s. U nastavku je kratak opis jednog načina kako poslati generisani token na ciljnu veb stranicu:

Pozivajući Python kod koji odgovara verifikaciji tokena:

```python
import requests

url = "https://recaptcha-demo.appspot.c/recaptcha-v3-verify.php?action=examples/v3scores&token='{token}'"

r = requests.get(url)
if r.status_code == 200:
    return r.text
```

Tako možemo dobiti rezultat:

```json
{
  "success": true,
  "hostname": "recaptcha-demo.appspot.com",
  "challenge_ts": "2024-09-14T08:52:26Z",
  "apk_package_name": null,
  "score": 0.9,
  "action": "examples/v3scores",
  "error-codes": []
}
```
Možete videti da `success` označava rezultat obrade verifikacije na ovom mestu, što znači da smo uspešno prošli verifikaciju Recaptcha3.

Pored toga, ako želite da generišete odgovarajući kod za integraciju, možete ga direktno kopirati, na primer, CURL kod je sledeći:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha3' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_url": "https://recaptcha-demo.appspot.com/recaptcha-v3-request-scores.php",
  "website_key": "6LdKlZEpAAAAAAOQjzC2v_d36tWxCl6dWsozdSy9",
  "page_action": "examples/v3scores"
}'
```

Python kod za integraciju je sledeći:

```python
import requests

url = "https://api.acedata.cloud/captcha/token/recaptcha3"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_url": "https://recaptcha-demo.appspot.com/recaptcha-v3-request-scores.php",
    "website_key": "6LdKlZEpAAAAAAOQjzC2v_d36tWxCl6dWsozdSy9",
    "page_action": "examples/v3scores"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asinhroni režim (async)

Podrazumevano, API je sinhrono blokirajući: jedan zahtev će čekati dok se token ne obradi pre nego što se vrati. Ako radite sa višestrukim rešenjima (multi-solver rotation) i želite da „odmah dobijete task_id nakon slanja zadatka, a zatim idete da rasporedite druge reševe, a kasnije se vratite da pročitate rezultate“, možete u telu zahteva uneti `async: true`.

Kada se unese `async: true`, interfejs će odmah vratiti `task_id`, a neće blokirati čekajući:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha3' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_url": "https://recaptcha-demo.appspot.com/recaptcha-v3-request-scores.php",
  "website_key": "6LdKlZEpAAAAAAOQjzC2v_d36tWxCl6dWsozdSy9",
  "page_action": "examples/v3scores",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

Ako želite da aktivno pratite napredak, možete koristiti taj `task_id` da upitite `POST /captcha/tasks` (preporučuje se svake 3~5 sekundi). Ovaj interfejs neće pokrenuti ili unaprediti obradu zadatka; čak i ako ne upitujete, prekinete vezu ili izađete iz klijenta, server će i dalje nastaviti sa obradom:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Tokom obrade biće vraćeno `status: processing`:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

Kada se obrada završi, biće vraćeno `status: ready` i token:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "token": "03AFcWeA5mfdNlQD0RGX9PTWPs0l65QukjwbYObCue5hygRuA6......"
}
```

Objašnjenje naplate: u asinhronom režimu, kreiranje zadatka i čitanje „u obradi“ statusa se ne naplaćuje; **klijent se naplaćuje jednom kada prvi put pročita uspešan rezultat** (što je u skladu sa postojećim ponašanjem i cenama u sinhronom režimu). Server će samostalno unaprediti zadatak, ali neće naplatiti unapred samo zato što je pozadinski zadatak završen. Ako zadatak ne uspe u roku od 120 sekundi, biće prekinut sa HTTP 504 `timeout`, bez naplate. `/captcha/tasks` nije odgovoran za unapređenje zadatka.

## Obrada grešaka

Kada pozivate API, ako naiđete na grešku, API će vratiti odgovarajući kod greške i informacije. Na primer:

- `400 token_mismatched`: Neispravna zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `400 api_not_implemented`: Neispravna zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `401 invalid_token`: Neautorizovano, nevalidan ili nedostajući autorizacioni token.
- `429 too_many_requests`: Previše zahteva, premašili ste limit brzine.
- `500 api_error`: Interna greška servera, nešto nije u redu sa serverom.

### Primer greške u odgovoru

```json
    "message": "fetch failed"
  },

}
```
