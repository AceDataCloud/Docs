Овај документ ће представити упутство за интеграцију Veo Videos Generation API, који може генерисати званичне Veo видео записе уношењем прилагођених параметара.

## Процес пријаве

Да бисте користили API, прво морате да одете на [Veo Videos Generation API](https://platform.acedata.cloud/documents/63e01dc3-eb21-499e-8049-3025c460058f) одговарајућу страницу и затражите одговарајућу услугу. Када уђете на страницу, кликните на дугме „Acquire“, као што је приказано на слици:

![](https://cdn.acedata.cloud/q6ytrc.png)

Ако се још нисте пријавили или регистровали, аутоматски ћете бити преусмерени на страницу за пријаву која вас позива да се региструјете и пријавите. Након пријаве или регистрације, аутоматски ћете се вратити на тренутну страницу.

При првом захтеву добићете бесплатну квоту, коју можете користити за API.

## Основна употреба

Прво, потребно је разумети основни начин коришћења, а то је унос кључне речи `prompt`, акције `action`, низа референтних слика `image_urls` и модела `model`, како бисте добили обрађени резултат. Прво је потребно једноставно проследити поље `action`, чија вредност је `text2video`. Ово углавном укључује три врсте акција: генерисање видео записа из текста (`text2video`), генерисање видео записа из слика (`image2video`), добијање 1080p видео записа (`get1080p`). Затим, потребно је унети модел `model`, који тренутно укључује `veo2`, `veo2-fast`, `veo3`, `veo31`, `veo31-fast`, `veo31-fast-ingredients` и `veo3-fast`, а конкретни садржаји су следећи:

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

Можете видети да смо подесили Request Headers, укључујући:

- `accept`: каквог формата желите да примите одговор, овде је написано `application/json`, што значи JSON формат.
- `authorization`: кључ за позивање API, који можете директно изабрати након захтева.

Такође смо подесили Request Body, укључујући:

- `model`: модел за генерисање видео записа, углавном `veo2`, `veo2-fast`, `veo3`, `veo31`, `veo31-fast`, `veo31-fast-ingredients` и `veo3-fast`.
- `action`: акција за генерисање видео записа, која углавном укључује три акције: генерисање видео записа из текста (`text2video`), генерисање видео записа из слика (`image2video`), добијање 1080p видео записа (`get1080p`).
- `image_urls`: када изаберете акцију генерисања видео записа из слика `image2video`, морате да отпремите референтне слике за прву и последњу слику, максимално три референтне слике.
- `resolution`: изаберите резолуцију генерисаног видео записа, где модел veo31 подржава 4k резолуцију, остали модели не подржавају, сви модели подржавају 1080p и gif резолуцију, ако не пренесете ову вредност, подразумевано ће се користити 720p резолуција, главне категорије су: `1080p`, `gif`, `4k`.
- `prompt`: кључна реч.
- `callback_url`: URL на који треба да се врати резултат.

### 📌 Резиме објашњења модела

| **veo31-fast**             | Генерисање видео записа из текста (без слика)<br>Генерисање видео записа из слика (са сликама)           | **1 слика** → Режим прве слике<br>**3 слике** → Режим прве и последње слике |

| **veo3**                   | Генерисање видео записа из текста (без слика)<br>Генерисање видео записа из слика (са сликама)           | **1 слика** → Режим прве слике<br>**3 слике** → Режим прве и последње слике |
| **veo31**                  | Генерисање видео записа из текста (без слика)<br>Генерисање видео записа из слика (са сликама)           | **1 слика** → Режим прве слике<br>**3 слике** → Режим прве и последње слике |

---

### 🔑 Објашњење кључних правила

1. **Општа логика**:
   - **Без уноса слика** → Аутоматски активирање режима генерисања видео записа из текста.
   - **С уносом слика** → Активирање режима генерисања видео записа из слика (конкретна акција зависи од броја слика).
2. **Типови режима генерисања видео записа из слика**:
   - **Режим прве слике** (1 слика): Прва слика је фиксна и представља унету слику.
   - **Режим прве и последње слике** (2 слике): Прва и последња слика су фиксне и представљају унету слику.
   - **Режим интеграције више слика** (1-3 слике): Само `veo31-fast-ingredients` подржава, интегрише садржај више слика за генерисање видео записа.
3. **Класификација режима**:
   - **Fast режим**: `veo2-fast`, `veo3-fast`, `veo31-fast`, `veo31-fast-ingredients`.
   - **Quality режим**: `veo2`, `veo3`, `veo31` (виша квалитета генерисања).

---

### ⚠️ Напомене

- **Једини модел који обавезно захтева слике**: `veo31-fast-ingredients` мора да прими слике (1-3 слике), у противном неће радити.
- **Ограничење броја слика**:
  - Осим `veo31-fast-ingredients`, остали модели подржавају максимално **3 слике** уноса.

## Funkcija generisanja videa iz slika

Ako želite da generišete video na osnovu slika sa početnog i krajnjeg okvira, možete postaviti parametar `action` na `image2video` i uneti niz veza do slika sa početnog i krajnjeg okvira `image_urls`.

Sledeće što treba da uradimo je da popunimo sledeći korak potrebnim proširenim ključnim rečima kako bismo prilagodili generisanje videa, tako da možemo odrediti sledeće sadržaje:

- `model`：model za generisanje videa, uglavnom `veo2`, `veo2-fast`, `veo3` i `veo3-fast`.
- `image_urls`：kada se odabere ponašanje generisanja videa `image2video`, potrebno je da se učitaju slike sa početnog i krajnjeg okvira.
- `prompt`：ključna reč.

Primer popunjavanja je sledeći:

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

Nakon popunjavanja automatski je generisan kod kao što je prikazano u nastavku:

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

Odgovarajući Python kod:

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo2",
    "prompt": "Neka pleše",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Klikom na pokretanje, možemo primetiti da ćemo dobiti rezultat kao što je prikazano u nastavku:

  "data": [
    {
      "id": "59f12222b1fa4fbe9331ff2400ad1583",

      "created_at": "2025-07-25 16:13:07",

Možemo primetiti da su sadržaji rezultata u skladu sa prethodnim, što takođe omogućava funkciju generisanja videa iz slika.

## Asinhroni povratni poziv

Zbog toga što vreme generisanja putem Veo Videos Generation API-a relativno dugo traje, otprilike 1-2 minuta, ako API dugo ne odgovara, HTTP zahtev će zadržati vezu, što dovodi do dodatne potrošnje sistemskih resursa, pa ovaj API takođe pruža podršku za asinhrone povratne pozive.

Celokupni proces je: kada klijent pokrene zahtev, dodatno se navodi polje `callback_url`, nakon što klijent pošalje API zahtev, API će odmah vratiti rezultat koji sadrži informacije o polju `task_id`, koje predstavlja trenutni ID zadatka. Kada zadatak bude završen, rezultat generisanog videa biće poslat klijentu na navedeni `callback_url` putem POST JSON-a, a takođe će sadržati i polje `task_id`, tako da se rezultati zadatka mogu povezati putem ID-a.

U nastavku ćemo kroz primer razumeti kako konkretno postupiti.

Prvo, Webhook povratni poziv je usluga koja može primati HTTP zahteve, programeri bi trebali zameniti URL svoje HTTP servera. Ovde, radi lakšeg prikaza, koristi se javni Webhook uzorak sa sajta https://webhook.site/, otvaranjem tog sajta dobijate Webhook URL, kao što je prikazano na slici:

## Obrada grešaka

Kada pozivate API, ako naiđete na grešku, API će vratiti odgovarajući kod greške i informacije. Na primer:

- `400 token_mismatched`: Neispravan zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `400 api_not_implemented`: Neispravan zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `401 invalid_token`: Neautorizovano, nevalidan ili nedostajući autorizacioni token.
- `429 too_many_requests`: Previše zahteva, premašili ste limit brzine.
- `500 api_error`: Interna greška servera, nešto nije u redu sa serverom.

### Primer greške u odgovoru

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
