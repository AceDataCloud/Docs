Ovaj dokument će predstaviti način integracije API za verifikaciju fotografija lične karte, koji se može koristiti za unos fotografije lica sa lične karte, prepoznavanje informacija sa fotografije lične karte i upoređivanje imena, broja lične karte i fotografije lica sa zvaničnom bazom podataka, kako bi se utvrdilo da li pripada istoj osobi, čime se verifikuje autentičnost informacija sa lične karte.

## Proces prijave

Da biste koristili API za verifikaciju fotografija lične karte, prvo idite na [Ace Data Cloud kontrolnu tablu](https://platform.acedata.cloud/console/applications) da dobijete svoj API Token, koji čuvate za kasniju upotrebu.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Ako se još niste prijavili ili registrovali, automatski ćete biti preusmereni na stranicu za prijavu koja vas poziva da se registrujete i prijavite, a nakon toga ćete se automatski vratiti na trenutnu stranicu.

**Jedan API Token može se koristiti za pozivanje svih usluga na platformi, bez potrebe da se za svaku uslugu posebno prijavljujete.** Prilikom prve prijave dobijate besplatnu kvotu, koju možete besplatno isprobati; kada kvota postane nedovoljna, možete dopuniti opšti saldo na [kontrolnoj tabli](https://platform.acedata.cloud/console/coin).

> 📘 Puna dokumentacija: [API za verifikaciju fotografija lične karte →](https://platform.acedata.cloud/documents/identity-idcard-check-1e)

## Osnovna upotreba

Prvo se upoznajte sa osnovnim načinom korišćenja, što podrazumeva unos linka do fotografije lične karte, kako biste dobili obrađene rezultate verifikacije. Prvo je potrebno jednostavno proslediti polje `image_url`, a zatim možemo popuniti odgovarajući sadržaj na interfejsu, kao što je prikazano na slici:

<p><img src="https://cdn.acedata.cloud/zjxg3k.png" width="500" className="m-auto" /></p>

Možete videti da smo ovde postavili Request Headers, uključujući:

- `accept`: kakav format odgovora želite da primite, ovde je uneto `application/json`, što znači JSON format.
- `authorization`: ključ za pozivanje API-ja, koji možete direktno izabrati nakon prijave.

Takođe je postavljen Request Body, koji uključuje:

- `image_url`: link do fotografije lične karte koja treba da se obradi.
- `config`: opcioni konfiguracioni parametar, boolean polje, podrazumevano je false, podržava `copy_warn`, `border_check_warn`, `reshoot_warn`, `detect_ps_warn`, `temp_id_warn`, `quality` (prag 0-100).

Nakon izbora, možete primetiti da je sa desne strane generisan odgovarajući kod, kao što je prikazano na slici:

<p><img src="https://cdn.acedata.cloud/4yh23p.png" width="500" className="m-auto" /></p>

Klikom na dugme „Try“ možete izvršiti testiranje, kao što je prikazano na gornjoj slici, ovde smo dobili sledeći rezultat:

```json
{
  "sim": 99.76,
  "result": "Success",
  "description": "Uspešno",
  "name": "Ime sa lične karte",
  "sex": "Pol sa lične karte",
  "nation": "Nacionalnost sa lične karte",
  "birth": "Datum rođenja sa lične karte",
  "address": "Adresa stanovanja sa lične karte",
  "id_num": "Broj lične karte",
  "portrait": "/9j/4AAQSkZJRgABAQAAAQABAAD/2wBDAAEBAQEBAQEBAQEBAQEBAQEBAQEBA.....DEhE2lbPMcOtG3f/DLT/yX8if7Kxn/AD7h85wdttPifRf1e6//2Q==",
  "warnings": "",
  "quality": 0,
  "encryption": null
}
```

Vraćeni rezultati sadrže više polja, koja su opisana kao:

- `sim`, sličnost, opseg vrednosti [0.00, 100.00]. Preporučuje se da se sličnost od 70 ili više može smatrati istom osobom, prag se može prilagoditi prema specifičnom scenariju (prag 70 ima stopu lažnog prolaza od jedan na hiljadu, prag 80 ima stopu lažnog prolaza od jedan na deset hiljada).
- `result`, poslovni kod greške, u slučaju uspeha vraća Success, u slučaju greške molimo vas da se obratite listi kodova grešaka u delu FailedOperation.
- `description`, ovde je rezultat verifikacije imena i broja lične karte.
- `name`, informacija o imenu sa lične karte, ako nije učitana fotografija lične karte, biće prazno.
- `sex`, informacija o polu sa lične karte, ako nije učitana fotografija lične karte, biće prazno.
- `nation`, informacija o nacionalnosti sa lične karte, ako nije učitana fotografija lične karte, biće prazno.
- `birth`, informacija o datumu rođenja sa lične karte, ako nije učitana fotografija lične karte, biće prazno.
- `address`, informacija o adresi stanovanja sa lične karte, ako nije učitana fotografija lične karte, biće prazno.
- `id_num`, informacija o broju lične karte, ako nije učitana fotografija lične karte, biće prazno.
- `portrait`, base64 kodiranje fotografije lica sa lične karte, ako je izrezivanje slike neuspešno, koristiće se cela fotografija lične karte za upoređivanje i vraćati prazno.
- `warnings`, informacije o upozorenju, kada je u konfiguraciji postavljeno upozorenje, upoređivanje lica će se zaustaviti, a rezultat će vratiti grešku (FailedOperation.OcrWarningOccurred) i imati ovo upozorenje.
- `quality`, ocena kvaliteta slike, kada je u konfiguraciji postavljeno upozorenje o zamućenju slike, ovaj parametar ima smisla, opseg vrednosti (0-100), trenutno je podrazumevani prag 50, ispod 50 će izazvati upozorenje o zamućenju.
- `encryption`, informacije o enkripciji osetljivih podataka.

Može se primetiti da informacije sa lične karte imaju visoku autentičnost.

Takođe, ako želite da generišete odgovarajući kod za integraciju, možete ga direktno kopirati, na primer, CURL kod je sledeći:

```shell
curl -X POST 'https://api.acedata.cloud/identity/idcard/check-1e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": {image_url}
}'
```

Python kod za integraciju je sledeći:

```python
import requests

url = "https://api.acedata.cloud/identity/idcard/check-1e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "image_url": {image_url}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Obrada grešaka

Kada pozivate API, ako naiđete na grešku, API će vratiti odgovarajući kod greške i informacije. Na primer:

- `400 token_mismatched`: Neispravna zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `400 api_not_implemented`: Neispravna zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `401 invalid_token`: Neautorizovano, nevalidan ili nedostajući autorizacioni token.
- `429 too_many_requests`: Previše zahteva, premašili ste limit brzine.
- `500 api_error`: Interna greška servera, nešto nije u redu sa serverom.
