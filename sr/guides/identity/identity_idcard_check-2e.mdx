Овај документ ће представити упутство за интеграцију API за проверу идентификационих информација и важења, који се може користити за проверу истинитости и доследности имена, броја личне карте и периода важења личне карте.

## Процес пријаве

Да бисте користили API, прво морате да одете на [страницу API за проверу идентификационих информација и важења](https://platform.acedata.cloud/documents/667017a4-017f-4af0-870e-807034f70632) и затражите одговарајућу услугу. Када уђете на страницу, кликните на дугме „Acquire“, као што је приказано на слици:

![](https://cdn.acedata.cloud/q6ytrc.png)

Ако се још нисте пријавили или регистровали, аутоматски ћете бити преусмерени на страницу за пријаву која вас позива да се региструјете и пријавите. Након пријаве или регистрације, аутоматски ћете се вратити на тренутну страницу.

При првом захтеву добићете бесплатну квоту, коју можете користити за API.

## Основна употреба

Прво, упознајте се са основним начином коришћења, а то је уношење линка до слике личне карте, након чега ћете добити обрађене резултате верификације. Прво је потребно једноставно проследити поље `name`, а затим можемо попунити одговарајуће садржаје на интерфејсу, као што је приказано на слици:

<p><img src="https://cdn.acedata.cloud/llvy1l.png" width="500" className="m-auto" /></p>

Можете видети да смо овде подесили заглавља захтева, укључујући:

- `accept`: у каквом формату желите да примите одговор, овде је написано `application/json`, што значи JSON формат.
- `authorization`: кључ за позивање API, који можете директно изабрати након захтева.

Такође смо подесили тело захтева, укључујући:

- `name`: име.
- `id_card`: број личне карте.
- `image_url`: линк до слике лица која треба да се обради.
- `validity_end`: датум истека важења личне карте, формат: YYYYMMDD, за дугорочно користите „00000000“;
- `validity_begin`: датум почетка важења личне карте, формат: YYYYMMDD.
- `encryption`: опционално, параметар за шифровање осетљивих поља (ако је потребно послати шифровани текст).

Након избора, можете приметити да је на десној страни генерисан одговарајући код, као што је приказано на слици:

<p><img src="https://cdn.acedata.cloud/l77q0u.png" width="500" className="m-auto" /></p>

Кликните на дугме „Try“ да бисте извршили тест, као што је приказано на горњој слици, и добићете следећи резултат:

```json
{
  "result": "0",
  "description": "доследно"
}
```

Враћени резултат има више поља, а описује се као:

- `result`, код резултата верификације, накнаде су следеће.
  - Кодови резултата са накнадом:
    - 0: Име и број личне карте се слажу
    - -1: Име и број личне карте се не слажу
  - Кодови резултата без накнаде:
    - -2: Неправилан број личне карте (дужина, контролна цифра итд. нису исправни)
    - -3: Неправилно име (дужина, формат итд. нису исправни)
    - -4: Аномалија у служби базе докумената
    - -5: Нема записа о овој личној карти у бази докумената
    - -6: Ауторитативни систем за упоређивање се надограђује, покушајте поново касније
    - -7: Број верификација је превазиђен за дан.
- `description`, резултат верификације имена и броја личне карте.

Можете видети да име, број личне карте и период важења у личној карти имају истинитост и доследност.

Ако желите да генеришете одговарајући код за интеграцију, можете га директно копирати, на пример, CURL код је следећи:

```shell
curl -X POST 'https://api.acedata.cloud/identity/idcard/check-2e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "id_card": "***",
  "validity_begin": "***",
  "validity_end": "***"
}'
```

Python код за интеграцију је следећи:

```python
import requests

url = "https://api.acedata.cloud/identity/idcard/check-2e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "name": "***",
    "id_card": "***",
    "validity_begin": "***",
    "validity_end": "***"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Обрада грешака

Када позивате API, ако наиђете на грешку, API ће вратити одговарајући код грешке и информације. На пример:

- `400 token_mismatched`: Лош захтев, могуће због недостајућих или неважећих параметара.
- `400 api_not_implemented`: Лош захтев, могуће због недостајућих или неважећих параметара.
- `401 invalid_token`: Неправилно, неважећи или недостајући ауторизациони токен.
- `429 too_many_requests`: Превише захтева, превазишли сте лимит.
- `500 api_error`: Унутрашња грешка сервера, нешто није у реду на серверу.

### Пример одговора на грешку

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
