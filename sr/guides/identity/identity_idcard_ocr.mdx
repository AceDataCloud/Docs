Ovaj dokument će predstaviti način integracije API za prepoznavanje lične karte i verifikaciju informacija, koji može proveriti autentičnost i usklađenost imena i broja lične karte putem unosa slike lične karte ili imena i broja lične karte. Ovaj interfejs se koristi za proveru autentičnosti i usklađenosti imena i broja lične karte, možete uneti ime i broj lične karte ili poslati sliku lica sa lične karte kako biste pružili potrebne informacije za verifikaciju.

## Proces prijave

Da biste koristili API za prepoznavanje lične karte i verifikaciju informacija, prvo idite na [Ace Data Cloud kontrolnu tablu](https://platform.acedata.cloud/console/applications) da dobijete svoj API Token, koji čuvate za kasniju upotrebu.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Ako se još niste prijavili ili registrovali, automatski ćete biti preusmereni na stranicu za prijavu koja vas poziva da se registrujete i prijavite, a nakon toga ćete se automatski vratiti na trenutnu stranicu.

**Jedan API Token može pozvati sve usluge platforme, nije potrebno posebno se prijavljivati za svaku uslugu.** Prilikom prve prijave dobijate besplatnu kvotu, možete besplatno isprobati; kada kvota postane nedovoljna, možete dopuniti opšti saldo na [kontrolnoj tabli](https://platform.acedata.cloud/console/coin).

> 📘 Puna dokumentacija: [API za prepoznavanje lične karte i verifikaciju informacija →](https://platform.acedata.cloud/documents/identity-idcard-ocr)

## Osnovna upotreba

Prvo se upoznajte sa osnovnim načinom korišćenja, što podrazumeva unos linka slike lične karte, kako biste dobili obrađene rezultate verifikacije. Prvo je potrebno jednostavno proslediti polje `image_url`, a zatim možemo popuniti odgovarajuće sadržaje na interfejsu, kao što je prikazano na slici:

<p><img src="https://cdn.acedata.cloud/qxy9rh.png" width="500" className="m-auto" /></p>

Možete videti da smo ovde postavili Request Headers, uključujući:

- `accept`: format odgovora koji želite da primite, ovde je uneto `application/json`, što znači JSON format.
- `authorization`: ključ za pozivanje API-ja, koji možete direktno izabrati nakon prijave.

Takođe je postavljen Request Body, uključujući:

- `image_url`: link slike lične karte koja treba da se obradi.
- `encryption`: opcionalno, parametar za enkripciju osetljivih polja (ako je potrebno poslati šifrovani tekst).

Nakon izbora, možete primetiti da je sa desne strane generisan odgovarajući kod, kao što je prikazano na slici:

<p><img src="https://cdn.acedata.cloud/uw90il.png" width="500" className="m-auto" /></p>

Kliknite na dugme „Try“ da biste izvršili test, kao što je prikazano na slici, ovde smo dobili sledeći rezultat:

```json
{
  "result": "0",
  "description": "Ime i broj lične karte se poklapaju",
  "name": "Ime na ličnoj karti",
  "id_card": "Broj lične karte",
  "sex": "Pol na ličnoj karti",
  "nation": "Nacionalnost na ličnoj karti",
  "birth": "Datum rođenja na ličnoj karti",
  "address": "Adresa na ličnoj karti"
}
```

Vraćeni rezultati sadrže više polja, objašnjeno u nastavku:

- `result`, kod rezultata verifikacije, troškovi su sledeći.
    - Kodovi rezultata sa troškovima:
        - 0: Ime i broj lične karte se poklapaju
        - -1: Ime i broj lične karte se ne poklapaju
    - Kodovi rezultata bez troškova:
        - -2: Nevažeći broj lične karte (dužina, kontrolna cifra itd. nisu ispravni)
        - -3: Nevažeće ime (dužina, format itd. nisu ispravni)
        - -4: Izuzetak u usluzi baze dokumenata
        - -5: Nema zapisa o ovoj ličnoj karti u bazi dokumenata
        - -6: Sistem za autoritativno poređenje se ažurira, pokušajte ponovo kasnije
        - -7: Broj verifikacija premašuje dnevno ograničenje.
- `description`, ovde je rezultat verifikacije imena i broja lične karte.
- `name`, informacija o imenu na ličnoj karti, ako slika lične karte nije otpremljena, biće prazna.
- `id_card`, informacija o broju lične karte, ako slika lične karte nije otpremljena, biće prazna.
- `sex`, informacija o polu na ličnoj karti, ako slika lične karte nije otpremljena, biće prazna.
- `nation`, informacija o nacionalnosti na ličnoj karti, ako slika lične karte nije otpremljena, biće prazna.
- `birth`, informacija o datumu rođenja na ličnoj karti, ako slika lične karte nije otpremljena, biće prazna.
- `address`, informacija o adresi na ličnoj karti, ako slika lične karte nije otpremljena, biće prazna.

Može se primetiti da su informacije o imenu i broju lične karte usklađene i važeće, a takođe su korišćene OCR tehnologije za ekstrakciju drugih informacija i njihovo prikazivanje.

Takođe, ako želite da generišete odgovarajući kod za integraciju, možete ga direktno kopirati, na primer, CURL kod je sledeći:

```shell
curl -X POST 'https://api.acedata.cloud/identity/idcard/ocr' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": {image_url}
}'
```

Python kod za integraciju je sledeći:

```python
import requests

url = "https://api.acedata.cloud/identity/idcard/ocr"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "image_url": {image_url}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Verifikacija prilagođenih informacija

Takođe pružamo način verifikacije koji ne otkriva informacije o slici lične karte, možete samo uneti ime `name` i broj lične karte `id_card` kako biste proverili autentičnost i usklađenost imena i broja lične karte, ispod su uneti konkretni podaci:

<p><img src="https://cdn.acedata.cloud/mc5bbw.png" width="500" className="m-auto" /></p>

Klikom na pokretanje dobijate sledeći rezultat:

```json
{
    "address": "",
    "birth": "",
    "description": "Ime i broj lične karte se poklapaju",
    "id_card": "Broj lične karte",
    "name": "Ime na ličnoj karti",
    "nation": "",
    "result": "0",
    "sex": ""
 }
```

Tako da iz rezultata ne otkriva druge privatne informacije, ovo takođe može završiti verifikaciju autentičnosti i usklađenosti imena i broja lične karte.

## Obrada grešaka

Kada pozivate API, ako naiđete na grešku, API će vratiti odgovarajući kod greške i informacije. Na primer:

- `400 token_mismatched`: Neispravna zahtev, moguće zbog nedostajućih ili neispravnih parametara.
- `400 api_not_implemented`: Neispravna zahtev, moguće zbog nedostajućih ili neispravnih parametara.
- `401 invalid_token`: Neautorizovano, neispravan ili nedostajući autorizacioni token.
- `429 too_many_requests`: Previše zahteva, premašili ste ograničenje brzine.
- `500 api_error`: Interna greška servera, nešto nije u redu sa serverom.

### Primer greške u odgovoru

```json

  "error": {

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
