Овај документ представља упутство за интеграцију API-ја за верификацију четири елемента банковне картице, који се користи за унос броја банковне картице, имена, броја идентификационог документа и броја телефона повезаног са рачуном, ради провере аутентичности и усклађености информација.

## Процес пријаве

Да бисте користили API за верификацију четири елемента банковне картице, прво посетите [Ace Data Cloud контролни панел](https://platform.acedata.cloud/console/applications) и преузмите свој API Token за каснију употребу.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Ако нисте пријављени или регистровани, аутоматски ћете бити преусмерени на страницу за пријаву где можете да се региструјете и пријавите, након чега ћете бити враћени на тренутну страницу.

**Један API Token омогућава приступ свим услугама платформе, није потребно посебно тражити за сваку услугу.** При првом захтеву добијате бесплатни кредит за тестирање; када кредит понестане, можете га допунити на [контролном панелу](https://platform.acedata.cloud/console/coin).

> 📘 Комплетна документација: [API за верификацију четири елемента банковне картице →](https://platform.acedata.cloud/documents/identity-bankcard-check-4e)

## Основна употреба

Прво, упознајмо се са основним начином коришћења: уносом броја банковне картице добијате обрађени резултат у виду слике. Потребно је једноставно проследити поље `bank_card`. Затим можете унети одговарајуће податке у интерфејс, као што је приказано на слици:

<p><img src="https://cdn.acedata.cloud/1pl0y5.png" width="500" className="m-auto" /></p>

Овде смо подесили Request Headers, који укључују:

- `accept`: формат одговора који желите да примите, овде је `application/json`, односно JSON формат.
- `authorization`: кључ за позивање API-ја, који можете изабрати након пријаве.

Такође, подешен је Request Body, који укључује:

- `bank_card`: број банковне картице који се обрађује, обавезан параметар.
- `id_card`: број идентификационог документа, обавезан параметар.
- `name`: име корисника, обавезан параметар.
- `phone`: резервисани број телефона.
- `cert_type`: тип идентификационог документа, мора бити у складу са документом за отварање рачуна.
- `encryption`: опционално, параметар за шифровање осетљивих података (ако је потребно послати шифроване податке).

Након избора, приметићете да је са десне стране генерисан одговарајући код, као што је приказано на слици:

<p><img src="https://cdn.acedata.cloud/slajgv.png" width="500" className="m-auto" /></p>

Кликните на дугме „Try“ да бисте тестирали, као што је приказано на слици, добићете следећи резултат:

```json
{
  "result": "0",
  "description": "认证通过"
}
```

Резултат садржи више поља, која су описана у наставку:

- `result`, код резултата верификације, са следећим значењима:
    - Плаћени кодови:
        - 0: Верификација успешна
        - -1: Верификација није успела
        - -4: Подаци власника картице нису тачни
        - -5: Нема омогућену услугу безкартичног плаћања
        - -6: Картица је одузета
        - -7: Неважећи број картице
        - -8: Картица нема одговарајућу издавачку банку
        - -9: Картица није иницијализована или је у стању мировања
        - -10: Превара или заглављена картица
        - -11: Картица је пријављена као изгубљена
        - -12: Картица је истекла
        - -13: Ограничена картица
        - -14: Прекорачен број неуспелих покушаја уноса ПИН-а
        - -15: Издавачка банка не подржава ову трансакцију
    - Бесплатни кодови:
        - -2: Неуспешна провера имена
        - -3: Погрешан број банковне картице
        - -16: Центар за верификацију је заузет
        - -17: Прекорачен број покушаја, покушајте сутра поново
- `description`, опис резултата пословања.

Ово показује да су број банковне картице, име, број идентификационог документа и број телефона повезани са рачуном аутентични и усклађени.

Ако желите да генеришете одговарајући код за интеграцију, можете га директно копирати, на пример CURL код изгледа овако:

```shell
curl -X POST 'https://api.acedata.cloud/identity/bankcard/check-4e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "phone": "***",
  "id_card": "***",
  "bank_card": "***"
}'
```

Python пример интеграције изгледа овако:

```python
import requests

url = "https://api.acedata.cloud/identity/bankcard/check-4e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "name": "胡印福",
    "phone": "***",
    "id_card": "***",
    "bank_card": "***"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Обрада грешака

При позиву API-ја, у случају грешке, API ће вратити одговарајући код грешке и поруку. На пример:

- `400 token_mismatched`: Лош захтев, могуће због недостајућих или неважећих параметара.
- `400 api_not_implemented`: Лош захтев, могуће због недостајућих или неважећих параметара.
- `401 invalid_token`: Неовлашћен приступ, неважећи или недостајући authorization token.
- `429 too_many_requests`: Прекорачен број захтева, премашен лимит.
- `500 api_error`: Унутрашња грешка сервера.

### Пример одговора са грешком

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
