Ovaj dokument će predstaviti API za verifikaciju tri elementa mobilnog broja, koji se može koristiti za proveru autentičnosti i usklađenosti mobilnog broja, imena i broja lične karte.

## Proces prijave

Da biste koristili API, prvo idite na [API za verifikaciju tri elementa mobilnog broja](https://platform.acedata.cloud/documents/b4c50108-dda5-4ddb-ba84-776060fb0151) i zatražite odgovarajuću uslugu. Kada uđete na stranicu, kliknite na dugme „Acquire“, kao što je prikazano na slici:

![](https://cdn.acedata.cloud/q6ytrc.png)

Ako još niste prijavljeni ili registrovani, automatski ćete biti preusmereni na stranicu za prijavu koja vas poziva da se registrujete i prijavite. Nakon prijave ili registracije, automatski ćete se vratiti na trenutnu stranicu.

Prilikom prve prijave dobićete besplatnu kvotu koja vam omogućava besplatno korišćenje ovog API-ja.

## Osnovna upotreba

Prvo, upoznajte se sa osnovnim načinom korišćenja, što podrazumeva unos mobilnog broja kako biste dobili obrađeni rezultat. Prvo je potrebno jednostavno proslediti polje `phone`. Zatim možemo popuniti odgovarajući sadržaj na interfejsu, kao što je prikazano na slici:

<p><img src="https://cdn.acedata.cloud/3xbffj.png" width="500" class="m-auto"></p>

Možete videti da smo ovde postavili Request Headers, uključujući:

- `accept`: format odgovora koji želite da primite, ovde je uneto `application/json`, što znači JSON format.
- `authorization`: ključ za pozivanje API-ja, koji možete direktno izabrati nakon prijave.

Takođe smo postavili Request Body, uključujući:

- `name`: ime korisnika koje treba obraditi, obavezno polje.
- `phone`: mobilni broj koji treba obraditi, obavezno polje.
- `id_card`: broj lične karte korisnika koji treba obraditi, obavezno polje.
- `verify_mode`: način verifikacije (duga verzija/kratka verzija).
- `encrypt_list`/`ciphertext_blob`/`iv`: opcioni parametri za enkripciju, po potrebi za enkripciju osetljivih polja.

Nakon izbora, možete primetiti da je na desnoj strani generisan odgovarajući kod, kao što je prikazano na slici:

<p><img src="https://cdn.acedata.cloud/0cp9z1.png" width="500" class="m-auto"></p>

Kliknite na dugme „Try“ da biste izvršili testiranje, kao što je prikazano na gornjoj slici, ovde smo dobili sledeći rezultat:

```json
{
  "result": "0",
  "description": "Autentifikacija uspešna",
  "isp": "Mobilni",
  "result_detail": null
}
```

Vraćeni rezultat ima više polja, koja su opisana kao što sledi:

- `result`, kod rezultata autentifikacije, naplata je sledeća.
  - Kodovi rezultata naplate:
    - 0: Rezultat verifikacije se poklapa
    - 1: Rezultat verifikacije se ne poklapa
  - Kodovi rezultata bez naplate:
    - -1: Nema podataka
    - -2: Nepoznata greška u motoru
    - -3: Abnormalna usluga motora
    - -4: Verifikacija imena nije prošla
    - -5: Mobilni broj nije validan
    - -6: Broj autentifikacija premašuje dnevno ograničenje, pokušajte ponovo sutra
- `description`, opis poslovnog rezultata.

Može se primetiti da su informacije o autentičnosti i usklađenosti mobilnog broja, imena i broja lične karte već proverene.

Takođe, ako želite da generišete odgovarajući kod za integraciju, možete ga direktno kopirati, na primer, CURL kod je sledeći:

```shell
curl -X POST 'https://api.acedata.cloud/identity/phone/check-3e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "phone": "***",
  "id_card": "***"
}'
```

Python kod za integraciju je sledeći:

```python
import requests

url = "https://api.acedata.cloud/identity/phone/check-3e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "name": "***",
    "phone": "***",
    "id_card": "***"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Obrada grešaka

Kada pozivate API, ako naiđete na grešku, API će vratiti odgovarajući kod greške i informacije. Na primer:

- `400 token_mismatched`: Neispravna zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `400 api_not_implemented`: Neispravna zahtev, moguće zbog nedostajućih ili nevalidnih parametara.
- `401 invalid_token`: Neautorizovano, nevalidan ili nedostajući autorizacioni token.
- `429 too_many_requests`: Previše zahteva, premašili ste limit brzine.
- `500 api_error`: Interna greška servera, nešto nije u redu sa serverom.

### Primer greške u odgovoru
