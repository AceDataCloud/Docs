Овај документ ће представити упутство за интеграцију API за основне информације о банковним картicama, које се може користити за упит основних информација о банковним картicama.

## Процес пријаве

Да бисте користили API за основне информације о банковним картicama, прво идите на [Ace Data Cloud контролни панел](https://platform.acedata.cloud/console/applications) да бисте добили ваш API токен, који ћете задржати за резерву.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Ако се још нисте пријавили или регистровали, аутоматски ћете бити преусмерени на страницу за пријаву која вас позива да се региструјете и пријавите, а након завршетка ћете бити аутоматски враћени на тренутну страницу.

**Један API токен је довољан за позивање свих услуга платформе, није потребно посебно пријављивати за сваку услугу.** При првом захтеву добићете бесплатну квоту, можете бесплатно тестирати; када вам квота понестане, можете допунити општи баланс на [контролном панелу](https://platform.acedata.cloud/console/coin).

> 📘 Пуна документација: [API за основне информације о банковним картicama →](https://platform.acedata.cloud/documents/identity-bankcard-check-1e)

## Основна употреба

Прво, упознајте се са основним начином коришћења, а то је уношење броја банковне картice, чиме добијате обрађену потврду резултата. Прво је потребно једноставно пренети поље `bank_card`, а затим можемо попунити одговарајући садржај на интерфејсу, као што је приказано на слици:

<p><img src="https://cdn.acedata.cloud/h41nrh.png" width="500" className="m-auto" /></p>

Можете видети да смо овде поставили Request Headers, укључујући:

- `accept`: каквог формата желите да примите одговор, овде је написано `application/json`, што значи JSON формат.
- `authorization`: кључ за позивање API, након пријаве можете директно изабрати из падајућег менија.

Такође смо поставили Request Body, укључујући:

- `bank_card`: број банковне картice.
- `encryption`: опционално, параметар за шифровање осетљивих поља (ако је потребно послати шифровани текст).

Након избора, можете приметити да је на десној страни генерисан одговарајући код, као што је приказано на слици:

<p><img src="https://cdn.acedata.cloud/grfra7.png" width="500" className="m-auto" /></p>

Кликните на дугме „Пробај“ да бисте извршили тест, као што је приказано на горњој слици, овде смо добили следећи резултат:

```json
{
  "result": "0",
  "description": "Упит успешан",
  "account_bank": "Прометна банка",
  "account_type": 1
}
```

Враћени резултат има више поља, описаних у наставку:

- `result`, код резултата аутентификације, накнаде су следеће.
    - Кодови резултата накнаде:
        - 0: Упит успешан
        - -1: Нема информација
    - Кодови без накнаде:
        - -2: Услуга центра за верификацију је заузета
        - -3: Банковна картica не постоји
- `description`, опис резултата пословања.
- `account_bank`, банка у којој је отворен рачун.
- `account_type`, природа картice: 1. Дебитна картica; 2. Кредитна картica; 3. Предплаћена картica; 4. Картica за одобрење.

Можете видети да су основне информације о банковној картici већ упитане.

Ако желите да генеришете одговарајући код за интеграцију, можете га директно копирати, на пример, CURL код је следећи:

```shell
curl -X POST 'https://api.acedata.cloud/identity/bankcard/check-1e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "bank_card": "****"
}'
```

Python код за интеграцију је следећи:

```python
import requests

url = "https://api.acedata.cloud/identity/bankcard/check-1e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "bank_card": "****"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Обрада грешака

Када позивате API, ако наиђете на грешку, API ће вратити одговарајући код грешке и информације. На пример:

- `400 token_mismatched`: Лош захтев, могуће због недостајућих или неважећих параметара.
- `400 api_not_implemented`: Лош захтев, могуће због недостајућих или неважећих параметара.
- `401 invalid_token`: Неправилно, неважећи или недостајући ауторизациони токен.
- `429 too_many_requests`: Превише захтева, прелазите лимит.
- `500 api_error`: Унутрашња грешка сервера, нешто није у реду на серверу.

### Пример одговора на грешку

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "подаци нису могли бити преузети"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
