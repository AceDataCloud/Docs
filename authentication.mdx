所有 Ace Data Cloud API 请求都通过 `api.acedata.cloud` 网关接入，采用 **Bearer Token** 认证。

## 网关域名

<CardGroup cols={2}>
  <Card title="主网关" icon="globe">
    `https://api.acedata.cloud`

    推荐用于大多数请求。
  </Card>
  <Card title="平台与登录" icon="browser">
    `https://platform.acedata.cloud`

    控制台、订阅、凭证管理。
  </Card>
  <Card title="身份认证" icon="key">
    `https://auth.acedata.cloud`

    OAuth2 / 单点登录端点。
  </Card>
  <Card title="状态页" icon="signal">
    `https://status.acedata.cloud`

    服务可用性与历史故障。
  </Card>
</CardGroup>

<Note>
  所有网关仅支持 **HTTPS**。HTTP 请求会被 301 重定向并丢弃 Authorization 头。
</Note>

## 获取 API Token

<Steps>
  <Step title="注册账号">
    访问 [platform.acedata.cloud](https://platform.acedata.cloud) 注册账号。新账号通常会获得免费试用额度。
  </Step>
  <Step title="订阅服务">
    打开服务详情页（如 Midjourney、Suno），点击「获取」完成订阅。
  </Step>
  <Step title="创建凭证">
    进入服务的「凭证」页面，点击「创建凭证」。复制返回的 Token——这是你之后调用该服务用到的 API Key。
  </Step>
</Steps>

## 凭证类型

| 类型 | 用途 | 适用场景 |
|---|---|---|
| **服务凭证** | 绑定到单个服务，扣费走该服务的订阅额度 | 默认推荐，最小权限 |
| **全局凭证** | 跨所有已订阅服务共用，从余额扣费 | 同时调用多个 AI 服务时方便 |
| **平台 Token**（`platform-*` 前缀） | 平台管理操作（账号、订阅） | 仅用于平台管理 API，**不要用于业务调用** |

## 请求头

所有请求都需要带 Authorization 头：

```
Authorization: Bearer YOUR_API_TOKEN
Content-Type: application/json
```

字段说明：

| 字段 | 是否必需 | 说明 |
|---|---|---|
| `Authorization` | 必需 | `Bearer ` 前缀 + 你的 Token，**大小写敏感** |
| `Content-Type` | POST/PUT 必需 | 一律使用 `application/json`，编码 UTF-8 |
| `Accept-Language` | 可选 | 控制错误信息的语言，例如 `zh-CN`、`en` |
| `X-Request-Id` | 可选 | 自定义请求 ID，便于和我们的支持团队对账日志 |

## 请求规则

| 规则 | 要求 |
|---|---|
| 协议 | HTTPS only |
| 方法 | 按各 API 文档定义 |
| 编码 | UTF-8 |
| 主体格式 | `application/json` |
| 文件上传 | 直接传公网可访问的 URL，或先上传到我们的对象存储 |

## 常见认证错误

### 401 Unauthorized

```json
{
  "success": false,
  "error": {
    "code": "unauthorized",
    "message": "Authentication credentials were not provided or are invalid."
  }
}
```

原因：

- 缺少 `Authorization` 头
- Token 拼写错误（注意 `Bearer ` 后必须有一个空格）
- Token 已被撤销
- 把平台 Token（`platform-*`）当成业务 Token 使用

### 402 Payment Required

```json
{
  "success": false,
  "error": {
    "code": "insufficient_balance",
    "message": "Application balance is not enough for this request."
  }
}
```

订阅额度或全局余额不足。去 [platform.acedata.cloud](https://platform.acedata.cloud) 充值或购买套餐。

### 403 Forbidden

```json
{
  "success": false,
  "error": {
    "code": "forbidden",
    "message": "Content moderation rejected this request."
  }
}
```

常见原因：

- 内容审核拒绝（敏感词、版权材料、被屏蔽的艺术家名）
- 凭证所属订阅未授权访问该服务

### 429 Too Many Requests

```json
{
  "success": false,
  "error": {
    "code": "rate_limited",
    "message": "Request rate exceeded. Please retry later."
  }
}
```

触发了上游或网关的速率限制。请实施指数退避重试，详见 [并发与速率](/faq/concurrency)。

## 安全最佳实践

- **永远不要**在浏览器、移动端 App 等客户端代码里硬编码 Token——一定要走自己的后端中转
- 用环境变量或密钥管理服务（如 Vault、AWS Secrets Manager）存储 Token
- 为开发、预发布、生产分别建立独立 Token
- 定期到平台「凭证」页面轮换 Token
- 怀疑泄漏时立刻撤销并重新生成
