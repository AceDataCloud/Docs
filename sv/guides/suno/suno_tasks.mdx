Huvudfunktionen för Suno Tasks API är att fråga efter körningsstatusen för uppgiften genom att ange uppgifts-ID:t som genererats av Suno Audios Generation API eller Suno Lyrics Generation API.

Detta dokument kommer att introducera integreringsanvisningarna för Suno Tasks API i detalj, för att hjälpa dig att enkelt integrera och fullt ut utnyttja de kraftfulla funktionerna i detta API. Genom Suno Tasks API kan du enkelt fråga efter uppgiftskörningsstatusen för Suno Lyrics Generation API eller Suno Audios Generation API.

## Ansökningsprocess

För att använda Suno Audios Generation API, gå först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API-token och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig kommer du automatiskt att omdirigeras till inloggningssidan för att bli inbjuden att registrera dig och logga in. När detta är klart återvänder du automatiskt till den aktuella sidan.

**En API-token kan anropa alla plattformens tjänster, utan att behöva ansöka separat för varje tjänst.** Vid den första ansökan ges en kostnadsfri kvot, som kan användas för att prova tjänsten gratis; när kvoten inte räcker till kan du fylla på det allmänna saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Begäransexempel

Suno Tasks API kan användas för att fråga efter resultaten från både Suno Audios Generation API och Suno Lyrics Generation API. För information om hur du använder Suno Audios Generation API, se dokumentationen [Suno Audios Generation API ](https://platform.acedata.cloud/documents/suno-audios-integration). För information om hur du använder Suno Lyrics Generation API, se [Suno Lyrics Generation API ](https://platform.acedata.cloud/documents/suno-lyrics-generation-integration).

Vi använder ett uppgifts-ID som returneras av tjänsten Suno Audios Generation API som exempel för att visa hur detta API används. Anta att vi har ett uppgifts-ID: eae26f89-b64b-404d-a80c-761996660b1c, därefter visar vi hur man genom att skicka in ett uppgifts-ID kan.

### Ställ in begärandehuvuden och begärandetext

**Request Headers** inkluderar:

- `accept`: Anger att svarsresultat i JSON-format ska tas emot, här anges `application/json`.
- `authorization`: Nyckeln för att anropa API:t, efter ansökan kan den väljas direkt från rullgardinsmenyn.

**Request Body** inkluderar:

- `id`: Det uppladdade uppgifts-ID:t.
- `action`: Åtgärdssättet för uppgiften.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/suno/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "eae26f89-b64b-404d-a80c-761996660b1c",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/suno/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "eae26f89-b64b-404d-a80c-761996660b1c",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Resultatet innehåller flera fält. Fältet `request` är request body när uppgiften initieras, medan fältet `response` är response body som returneras efter att uppgiften har slutförts. Fältbeskrivningarna är följande.

- `id`, ID:t för uppgiften som genererar denna låt, som används för att unikt identifiera denna låtgenereringsuppgift.
- `request`, begärandeinformation i frågan av låtuppgiften.
- `response`, returinformation i frågan av låtuppgiften.
- `created_at`, tidpunkt då uppgiften skapades, Unix-tidsstämpel (sekunder, flyttal).
- `started_at`, tidpunkt då uppgiften började köras, Unix-tidsstämpel (sekunder, flyttal).
- `finished_at`, tidpunkt då uppgiften slutfördes, Unix-tidsstämpel (sekunder, flyttal). Detta fält returneras inte när uppgiften inte är slutförd.
- `elapsed`, tidsåtgång för uppgiftens körning, i sekunder (flyttal, behåll 3 decimaler). Detta fält returneras inte när uppgiften inte är slutförd.

## Felhantering

Vid anrop av API:t returnerar API:t motsvarande felkod och information om ett fel uppstår. Till exempel:

- `400 token_mismatched`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.
