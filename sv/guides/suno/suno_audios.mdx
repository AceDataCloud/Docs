I takt med att AI används allt mer har olika typer av AI-program gradvis blivit vanliga. AI har gradvis trängt in i alla aspekter av människors arbete och liv. Och de branscher som AI berör blir också allt fler, från det ursprungliga skrivandet, till medicin och utbildning, och vidare till dagens musik.

Suno är en professionell AI-plattform av hög kvalitet för skapande av låtar och musik. Användare behöver bara ange enkla textpromptar för att kunna generera låtar med sång utifrån genre, stil och låttext. Denna AI-musikgenerator utvecklas av teammedlemmar från välkända teknikföretag som Meta, TikTok och Kensho, med målet att inga instrumentverktyg ska behövas och att alla ska kunna skapa fantastisk musik.

Suno erbjuder dock officiellt ingen API, AceDataCloud erbjuder en uppsättning API:er för Suno som simulerar integration med Suno officiellt och gör det enkelt och snabbt att generera önskad musik.

## Ansökan och användning

För att använda Suno Audios Generation API, hämta först din API Token i [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) och spara den för användning senare.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig omdirigeras du automatiskt till inloggningssidan där du uppmanas att registrera dig och logga in. När det är klart återgår du automatiskt till den aktuella sidan.

**En API Token kan anropa alla plattformens tjänster, utan att behöva ansöka separat för varje tjänst.** Vid den första ansökan får du gratis kredit för att kunna prova utan kostnad; när krediten inte räcker till kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Grundläggande användning

Vilka låtar du vill ha kan du skriva in en valfri text för. Om jag till exempel vill generera en låt om jul kan jag skriva in `a song for Christmas`, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Här kan vi se att vi har ställt in Request Headers, inklusive:

- `accept`: vilket format på svarsresultatet du vill ta emot, här anges `application/json`, alltså JSON-format.
- `authorization`: nyckeln för att anropa API:et, efter ansökan kan den väljas direkt i rullgardinsmenyn.

Dessutom har Request Body ställts in, inklusive:
- `action`: Typ av ljuduppgift, standardvärdet är `generate`. Stöder åtgärder som generering, fortsättning, cover, sammanslagning, separering av spår, tillägg av ljudspår, extrahering av angivet ljudspår, generering av ljudeffekter och justering av hastighet, som alla anropas via `POST /suno/audios`.
- `prompt`: Sunos officiella prompt för inspirationsläge (gäller när `custom` är `false`), högst 500 tecken.
- `model`: Modellen för denna musikgenereringsuppgift. v6-serien omfattar `chirp-v6`, `chirp-v6-wild` och `chirp-v6-mini`; äldre modellnamn fortsätter att vara kompatibla.
- `max_mode`: Förbättrat genereringsläge. `generate` aktiveras endast när både `custom` och `max_mode` är `true`, till en kostnad av 1.12 Credits; `add_stem` kan aktiveras direkt, till en kostnad av 1.344 Credits. När det är avstängt eller utelämnat är kostnaderna 0.56 respektive 0.672 Credits.
- `variety`: Mångfaldsintensiteten för genereringsresultaten, valen är `off`, `normal`, `high`, `extra`, `max`. Används endast för `generate` och `add_stem`; om det skickas för andra action returneras 400.
- `lyric`: Textinnehållet i Sunos officiella anpassade läge. `chirp-v3-5` och `chirp-v4` har högst 3000 tecken; `chirp-v4-5` och senare (inklusive `chirp-v5`, `chirp-v5-5`) har högst 5000 tecken.
- `custom`: Om anpassat läge används, standardvärdet är: `false`.
- `instrumental`: Alternativet för instrumental musik i Sunos officiella inspirationsläge.
- `title`: Musiktiteln i Sunos officiella anpassade läge. `chirp-v3-5`, `chirp-v4` har högst 80 tecken; `chirp-v4-5` och senare har högst 100 tecken.
- `style`: Musikstil i Sunos officiella anpassade läge. `chirp-v3-5` och `chirp-v4` har högst 200 tecken; `chirp-v4-5` och senare (inklusive `chirp-v5`, `chirp-v5-5`) har högst 1000 tecken.
- `negative_tags`: Musikstilar eller genrer som ska uteslutas vid anpassad generering, kan även användas för `replace_section`. Detta gränssnitt har för närvarande ingen fast teckengräns för detta fält; alltför långt innehåll kan fortfarande inte behandlas, så beskrivningen bör hållas kortfattad.
- `audio_weight`: Påverkansvikten för ljud- eller röstegenskaper, intervallet är 0–1, och `0` är också ett giltigt värde. Kan användas för åtgärder som generering, fortsättning, cover, tillägg av ljudspår och röstkonsistens; utan referensljud eller röstegenskaper kan modellen försvaga eller ignorera detta värde.
- `audio_id`: ID:t för referensmusiken, används för efterföljande åtgärder som cover, fortsättning och separering av spår. Ljudfiler kan fortfarande laddas ner, men det betyder inte att efterföljande behandling av detta ID alltid är tillgänglig; om `suno_processing_unavailable` returneras, behåll `task_id` och `trace_id` och kontakta supporten.
- `overpainting_start`/`overpainting_end`: Start- och sluttid för att lägga till sång till befintlig instrumental musik, i sekunder.
- `underpainting_start`/`underpainting_end`: Start- och sluttid för att lägga till ackompanjemang till a cappella, i sekunder.
- `persona_id`: Röst-ID:t som erhålls via gränssnittet för att skapa Persona eller röst, inte låtens `audio_id`.
- `continue_at`: Gräns för fortsättning, i sekunder. Till exempel innebär 213.5 att efterföljande segment genereras från 3 minuter och 33.5 sekunder. `lyric` och `style` vägleder endast nytt innehåll efter gränsen och ersätter inte text eller sång före gränsen i källjudet.
- `style_influence`: Stilpåverkan i anpassat läge, intervallet är 0–1; ju större värde, desto närmare följer resultatet vanligtvis den valda stilen; `0` skickas som ett giltigt värde.
- `replace_section_end`: Sluttiden för ersättningssegmentet.
- `replace_section_start`: Starttiden för ersättningssegmentet.
- `vocal_gender`: Styr preferensen för kvinnlig eller manlig röst, kvinnlig röst `f`, manlig röst `m`, gäller för modeller 4.5 och senare; det är en preferens och strikt efterlevnad garanteras inte.
- `weirdness`: Grad av märklighet i anpassat läge, intervallet är 0–1; ju större värde, desto mer kreativt och experimentellt är resultatet vanligtvis; `0` skickas som ett giltigt värde.
- `duration`: Önskad låtlängd, i sekunder, måste vara ett heltal och ligga mellan 10 och 360. För närvarande använder endast `generate` denna parameter, och den specifika effekten beror på läge och modell. Det är en vägledande prompt snarare än en hård begränsning: modellen tar hänsyn till den, men garanterar inte att den uppnås. Den faktiska längden på den färdiga produkten styrs av fältet `duration` i svaret och är vanligtvis kortare än det önskade värdet.

### Tillämpningsområde för röst-ID

`generate`, `cover`, `upload_cover`, `artist_consistency`, `artist_consistency_vox` kan använda `persona_id`. De två senare action måste ange `persona_id`; de kan också samtidigt ange `audio_id` för låten som användes när denna Persona skapades.

`extend`, `upload_extend` använder inte något ytterligare `persona_id`. Om `mashup`, `inspo` stöder röst-ID beror på den valda tjänstkanalen; andra action garanterar inte att detta fält tillämpas, använd det enligt beskrivningen för respektive åtgärd. `vocal_gender` är en valfri könspreferens och kan inte ersätta röst-ID.

Efterföljande skapandeåtgärder kräver ett giltigt käll-`audio_id`; `mashup` kräver minst två `mashup_audio_ids`. Om nödvändiga källor eller tidsparametrar saknas returneras HTTP 400.

### Tillämpningsområde för avancerade parametrar
| Parameter                | Värden                                      | Stödda action                              | Beskrivning                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | Valfritt                                      | Justerar experimentalitet, `0` är ett giltigt värde; effekten beror på åtgärd, läge och modell      |
| `style_influence` | 0-1                                         | Valfritt                                      | Justerar tendensen att följa stil, `0` är ett giltigt värde; effekten beror på åtgärd, läge och modell   |
| `audio_weight`    | 0-1                                         | Valfritt                                      | Justerar påverkan från ljud- eller röstegenskaper; kan ignoreras av modellen när referensinformation saknas        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`、`add_stem`                   | Justerar stilmässig variation mellan resultaten                       |
| `max_mode`        | boolean                                     | `generate`（kräver `custom=true`）、`add_stem` | Förbättrar konsekvensen och debiteras enligt förbättrat läge                     |
| `vocal_gender`    | `f` / `m`                                   | Genereringsåtgärder som stöder röststyrning                             | Preferensalternativ, strikt efterlevnad garanteras inte                       |
| `duration`        | heltal 10-360                                   | `generate`                              | Önskad längd; andra action använder för närvarande inte detta fält, den faktiska längden avgörs av resultatet |

Plattformen validerar parametertyper och värdeintervall, men avvisar inte dessa valfria justeringsalternativ enbart på grund av olika action; den konkreta effekten avgörs av åtgärd, läge och modell.

- `lyric_prompt`: prompt för att generera låttexter, gäller om och endast om `custom` är `true` och `lyric` inte har skickats.
- `callback_url`: URL som behöver återkopplingsresultat.
- `async`: valfritt, när den är satt till `true` returnerar gränssnittet omedelbart `task_id`, utan att `callback_url` behöver anges, varefter resultatet hämtas genom polling via motsvarande gränssnitt för uppgiftsfrågor.

## Anpassad generering

Om du vill anpassa genereringen av låttexter kan du ange låttexter:

Vid denna tidpunkt kan fältet `lyric` skickas med innehåll som följande:
```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> Observera, `\n` i låttexten här är radbrytningar. Om du inte vet hur man genererar låttexter kan du använda API:et för låttextgenerering som tillhandahålls av AceDataCloud för att generera låttexter via en prompt. API:et är [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Därefter ska vi generera en låt baserat på låttexten, titeln och stilen, och då kan följande innehåll anges:

- lyric: låttexten
- custom: fyll i `true`, vilket representerar anpassad generering. Denna parameter är som standard false, vilket representerar användning av `prompt` för generering.
- title: låtens titel.
- style: låtens stil, valfritt.

## Anpassad funktion för generering av sångarstil

Om du vill använda en sångarstil för att generera en låt ska du först generera en låt genom den grundläggande användningen ovan.\
Till sist behöver du ställa in denna låt som sångarstil, och sedan gå till [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) för att, baserat på musik-ID:t `audio_id` som genererats officiellt, skapa en ID-parameter `persona_id` för sångarstil. De specifika parametrarna visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Efter ifyllnad genereras följande kod automatiskt:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Sedan kan parametern `action` ställas in på `artist_consistency` (om det är den nya sångarstilen Persona-v2-vox måste `action` ställas in på `artist_consistency_vox`), och du anger ID:t för låten som behöver fortsätta genereras samt sångarstil-ID:t.
```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "artist_consistency",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b",
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Funktion för fortsatt generering
Om du vill fortsätta generera en redan genererad Suno-låt kan du ställa parametern `action` till `extend` och ange ID:t för låten som behöver fortsätta genereras. Låt-ID:t hämtas enligt den grundläggande användningen. Av ovanstående framgår att du vid detta tillfälle kan se att låtens ID är:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Observera att `id` i texten här är ID:t för den genererade låten. Om du inte vet hur man genererar en låt kan du hänvisa till den grundläggande användningen ovan för att generera en låt.

Om du vill fortsätta generera en låt som du själv har laddat upp kan du ställa parametern `action` till `upload_extend` och ange ID:t för den anpassat uppladdade låten som behöver fortsätta genereras. Låt-ID:t hämtas med [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), som visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Därefter måste du fylla i texten för fortsättningssegmentet och kan ange stil:

- lyric: används endast för att vägleda texten för det nygenererade segmentet efter `continue_at` och ersätter inte texten före denna tidpunkt i källjudet.
- custom: ange `true`, vilket innebär anpassad generering. Denna parameter är som standard false, vilket innebär generering med `prompt`.
- style: musikstilen för fortsättningssegmentet, valfri.
- continue_at: fortsättningsgräns, i sekunder. Till exempel innebär 213.5 att efterföljande segment börjar genereras vid 3 minuter och 33,5 sekunder.

`continue_at` för `extend` och `upload_extend` måste vara större än 0 och stöder decimalsekunder, till exempel `30.792`; värdet avrundas inte vid inskickning.

> `extend` används för att fortsätta skapa efter en befintlig låt, inte för att byta ut texten för hela låten. Om du vill använda ny text för hela låten från början ska du använda `generate` för att generera på nytt; om du vill nytolka med hänvisning till en befintlig låt kan du använda `cover`. När en helt ny låttext skickas in ersätts fortfarande inte den ursprungliga texten före `continue_at`.

Exempel på ifyllnad är följande:

<p><img src="https://cdn.acedata.cloud/zp9s42.png" width="500" className="m-auto" /></p>

Efter ifyllnad genereras följande kod automatiskt:

## Musikcover

När en låt har fortsatt genereras baserat på en befintlig låt kan stilen på den returnerade låten vara mindre lämplig. Om du vill göra en coverversion av den tidigare genererade låten (det stöds även för egenuppladdad musik) behöver du använda metoden för musikcover, och kan ange följande innehåll:

- action：innehållet är `cover`; när en coveråtgärd utförs på egenuppladdad musik måste innehållet anges som: `upload_cover`.
- audio_id：ID:t för den tidigare genererade låten.

Om du vill använda en angiven röst för covern kan du samtidigt skicka in `persona_id`. Privata röster som skapats via `/suno/voices` måste först användas för att ladda upp originallåten i `/suno/upload` med samma `persona_id`, och sedan används det returnerade `audio_id` för `upload_cover`. {

## Ersätt segment

När en låt har genererats och det behövs en sekundär skapandeprocess där ett låtsegment ersätts separat, kan ett visst segment i låten ersättas.
> ⚠️ **Obs**: `replace_section_result_mode` är som standard `full_song`: systemet sammanfogar separat 2 nygenererade kandidater och returnerar 2 kompletta låtar. Om du endast behöver kandidater för ersättningssegment som ännu inte har sammanfogats, ange uttryckligen `candidates`, och välj sedan en kandidat för att anropa [musiksammanfogning](#musiksammanfogning).

Parameterbeskrivningen är följande:

- action: Innehållet är `replace_section`.
- audio_id: ID:t för den ursprungliga låten (källåten som ersätts).
- model: Modell för låtgenerering.
- lyric: Den kompletta texten efter ersättning (inklusive det ersatta segmentet och dess kontext, i överensstämmelse med innehållet i `prompt`).
- prompt: Den nya texten för segmentet som ska ersättas.
- style: Låtens stil, valfritt.
- negative_tags: Stilar eller genrer som ska exkluderas, valfritt.
- replace_section_start: Starttiden för det ersatta segmentet i originallåten (sekunder), obligatoriskt och får inte vara mindre än 0.
- replace_section_end: Sluttiden för det ersatta segmentet i originallåten (sekunder), obligatoriskt och måste vara större än starttiden.
- replace_section_result_mode: Returläge, standard är `full_song`. `full_song` sammanfogar separat 2 kandidater och returnerar 2 kompletta låtar; `candidates` returnerar 2 kandidatssegment som ännu inte har sammanfogats.

## Separation av sång och musik för alla spår

- action: Innehållet är `all_stems`.

```json
{
  "action": "all_stems",
  "audio_id": "bdf23a5a-59f5-4103-b452-054a824a7f9f"
```

## Extrahera ljudspår

`extract_stem` extraherar målspåret från angivet ljud och returnerar samtidigt en kompletterande version där spåret har tagits bort, anropas via `POST /suno/audios`.

- Obligatoriskt: `action`, `audio_id`, `stem_type`.
- Valfritt: `audio_format`, det nuvarande offentliga tvåkanalsavtalet stöder endast `mp3`.
- Debitering: 1.12 Credits.

```json
{
  "action": "extract_stem",
  "audio_id": "dead4ee5-df4d-417b-8f7e-717722fae51a",
  "stem_type": "bass",
  "audio_format": "mp3",
  "async": true
}
```

`data` i svaret i slutläge behåller en platt ljudlista, och `stem_sets` anger motsvarigheten mellan målspåret och det kompletterande ljudspåret:

## Kontrollera låtlängden

Som standard bestäms längden på den genererade låten av modellen själv, vanligtvis mellan 30 sekunder och 4 minuter. Om en längre eller kortare färdig produkt behövs kan den önskade längden anges via parametern `duration`, i sekunder, med heltalsvärden från 10 till 360.

Den här parametern används för låtgenerering i anpassat läge (`custom` är `true`). Det bör särskilt förklaras att `duration` är en **riktgivande ledtråd, inte en hård begränsning**: modellen refererar till detta värde när den skapar, men garanterar inte att det uppnås. I praktiska tester är den faktiska längden vanligtvis märkbart kortare än det önskade värdet, och längderna på de två låtar som returneras i samma begäran kan också skilja sig med flera gånger. Även vid helt identiska begäranden kan längderna från flera inskick skilja sig avsevärt. Använd därför inte detta som exakt längdkontroll; om verksamheten kräver en fast längd, klipp eller försök igen själv efter att ha fått den färdiga produkten.

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Det bör noteras att `duration` i begäran är den **önskade längden**, medan fältet `duration` för varje låt i svarets `data` är den **faktiska längden** för den låten. De har samma namn men olika innebörd, och den faktiska längden garanteras inte vara lika med det önskade värdet. Textlängden är en av de huvudsakliga faktorerna som påverkar den färdiga produktens längd. Om en längre färdig produkt behövs rekommenderas att samtidigt tillhandahålla mer kompletta låttexter.

Gränssnittet validerar att `duration` måste vara ett heltal mellan 10 och 360; det är fortfarande bara ett genereringsmål, inte en garanti för den färdiga produktens längd.

## Inspo-funktionen för inspirationsskapande

Inspo-funktionen för inspirationsskapande kan generera ny musik baserat på 1 till 4 kompletta referensljudfiler och stöder att dra och släppa eller ladda upp ljud som inspirationskälla. API:t använder den befintliga `inspo`-åtgärden: klienten tillhandahåller en offentligt tillgänglig ljud-URL, och tjänsten slutför automatiskt förberedelsen av referensljudet och skapandet, utan att klienten behöver läsa in text, stil eller längd separat och sedan sätta ihop begäran. Den skiljer sig från intervallsamplingen ovan och från Cover som återskapar originalsångens stil. Följande parametrar behöver fyllas i vid användning:

- action: innehållet är `inspo`.
- audio_urls: en lista med URL:er till referensljud, där 1 till 4 offentligt tillgängliga ljudadresser måste tillhandahållas.
- model: modellen som används, `chirp-v6` rekommenderas.
- prompt: låttext eller kreativ uppmaning (valfritt).
- instrumental: när den sätts till `true` genereras enligt en begäran om instrumental musik utan att använda låttext.
- persona_id: använder den angivna rösten i tjänstekanaler som stöder denna kombination; referensljudet binds under förberedelsefasen till den resursmiljö som krävs för rösten.
- lyric_prompt: används för att automatiskt generera låttext när `custom=true` och `lyric` inte har angetts.

> Obs: Referensljudet måste vara en offentligt tillgänglig ljudfil. Om referensljudet helt överensstämmer med en känd inspelning i plattformens musikbibliotek kan Suno avvisa genereringen på grund av upphovsrättskontroll. Det rekommenderas att använda eget ljud eller ljud som genererats av Suno som inspirationskälla.

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynkront återanrop

Eftersom det tar relativt lång tid för Suno att generera musik, cirka 1–2 minuter, kommer HTTP-begäran att hållas ansluten om API:t inte svarar under en längre tid, vilket leder till ytterligare förbrukning av systemresurser. Därför erbjuder detta API även stöd för asynkrona återanrop.

Det övergripande flödet är: när klienten initierar en begäran anges dessutom fältet `callback_url`. Efter att klienten har initierat API-begäran returnerar API:t omedelbart ett resultat som innehåller fältinformationen `task_id`, vilket representerar ID:t för den aktuella uppgiften. När uppgiften är klar skickas resultatet av den genererade musiken till den `callback_url` som klienten har angett i form av POST JSON, vilket också inkluderar fältet `task_id`, så att uppgiftsresultatet kan kopplas ihop via ID:t.
