I takt med att AI:s användning blir mer utbredd har olika AI-program gradvis blivit vanliga. AI har gradvis trängt in i alla aspekter av människors arbetsliv och vardagsliv. De branscher som AI berör blir också allt fler, från det ursprungliga skrivandet, till medicin och utbildning, och nu även musik.

Suno är en professionell AI-plattform av hög kvalitet för skapande av låtar och musik. Användare behöver bara ange enkla textprompter för att, baserat på genre, stil och låttext, generera låtar med sång. Denna AI-musikgenerator har utvecklats av teammedlemmar från välkända teknikföretag som Meta, TikTok och Kensho, med målet att ingen ska behöva några instrumentverktyg och att alla ska kunna skapa fantastisk musik.

Suno stöder nu `chirp-v6`, `chirp-v6-wild` och `chirp-v6-mini`. `chirp-v6` rekommenderas; äldre modellnamn är fortsatt kompatibla.

Suno erbjuder dock officiellt ingen API, men AceDataCloud erbjuder en uppsättning Suno-API:er som simulerar integrationen med Suno officiellt och gör det möjligt att snabbt och enkelt generera önskad musik.

## Ansökan och användning

För att använda Suno Audios Generation API ska du först hämta din API Token i [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte är inloggad eller registrerad omdirigeras du automatiskt till inloggningssidan där du uppmanas att registrera dig och logga in. När det är klart återvänder du automatiskt till den aktuella sidan.

**En API Token kan anropa plattformens alla tjänster, utan att du behöver ansöka separat för varje tjänst.** Vid den första ansökan får du gratis kredit som du kan använda för att prova tjänsten kostnadsfritt; när krediten inte räcker till kan du fylla på det allmänna saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Grundläggande användning

Vilka låtar du än vill ha kan du ange valfri text, till exempel om jag vill generera en låt om jul kan jag ange `a song for Christmas`, som bilden visar:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Här kan vi se att vi har angett Request Headers, inklusive:

- `accept`: vilket format på svarsresultatet som ska tas emot. Här anges `application/json`, alltså JSON-format.
- `authorization`: nyckeln för att anropa API:t, som kan väljas direkt från rullgardinsmenyn efter ansökan.

Dessutom har vi angett Request Body, inklusive:
- `action`: Åtgärden för denna musikgenereringsuppgift, standardvärdet är `generate`, omfattar huvudsakligen: `extend`, `upload_extend`, `cover`, `upload_cover`, `replace_section`, `replace_section`, `concat`, `stems`, `all_stems`, `remaster`.
- `prompt`: Sunos officiella prompt för inspirationsläge (gäller när `custom` är `false`), maximalt 500 tecken.
- `model`: Modellen för denna musikgenereringsuppgift. v6-serien omfattar `chirp-v6`, `chirp-v6-wild` och `chirp-v6-mini`; äldre modellnamn fortsätter att stödjas.
- `lyric`: Textinnehållet för Sunos officiella anpassade läge. `chirp-v3-5` och `chirp-v4` har högst 3 000 tecken; `chirp-v4-5` och senare (inklusive `chirp-v5`, `chirp-v5-5`) har högst 5 000 tecken.
- `custom`: Om anpassat läge ska användas, standardvärdet är: `false`.
- `instrumental`: Alternativet för instrumentalmusik i Sunos officiella inspirationsläge.
- `title`: Musiktiteln för Sunos officiella anpassade läge. `chirp-v3-5` och `chirp-v4` har högst 80 tecken; `chirp-v4-5` och senare har högst 100 tecken.
- `style`: Musikstil för Sunos officiella anpassade läge. `chirp-v3-5` och `chirp-v4` har högst 200 tecken; `chirp-v4-5` och senare (inklusive `chirp-v5`, `chirp-v5-5`) har högst 1 000 tecken.
- `negative_tags`: Musikstilar eller genrer som önskas uteslutas från genereringsresultatet i anpassat läge (när `custom` är `true`).
- `audio_weight`: Andelen av det uppladdade referensljudet, inom intervallet 0–1; ju större värde, desto mer förlitar den sig på referensljudet.
- `audio_id`: ID för referensmusiken.
- `overpainting_start`/`overpainting_end`: Start- och sluttid för att lägga till sång till befintlig instrumentalmusik, i sekunder.
- `underpainting_start`/`underpainting_end`: Start- och sluttid för att lägga till ackompanjemang till a cappella, i sekunder.
- `persona_id`: Låt-ID för artisten.
- `continue_at`: Gräns för fortsättning, i sekunder. Till exempel innebär 213.5 att efterföljande segment börjar genereras vid 3 minuter och 33.5 sekunder. `lyric` och `style` vägleder endast nytt innehåll efter gränsen och ersätter inte texten eller sången före gränsen i källjudet.
- `style_influence`: Den avancerade parametern ”Style Influence” i anpassat läge, inom intervallet 0–1; ju större värde, desto närmare den valda stilen.
- `replace_section_end`: Sluttiden för segmentet som ska ersättas.
- `replace_section_start`: Starttiden för segmentet som ska ersättas.
- `vocal_gender`: Styr preferensen för kvinnlig eller manlig röst: kvinnlig röst `f`, manlig röst `m`; gäller för modeller 4.5 och senare; är ett preferensalternativ och strikt efterlevnad garanteras inte.
- `weirdness`: Den avancerade parametern ”Weirdness” i anpassat läge, inom intervallet 0–1; ju större värde, desto mer kreativ och experimentell.
- `duration`: Önskad låtlängd, i sekunder, måste vara ett heltal och ligga inom intervallet 10 till 360. Denna parameter används för låtgenerering i anpassat läge (när `custom` är `true`). Den är en vägledande uppmaning snarare än en hård begränsning: modellen kommer att referera till den, men garanterar inte att den uppnås. Den faktiska längden på den färdiga produkten avgörs av fältet `duration` i svaret och är vanligtvis kortare än det önskade värdet.
- `lyric_prompt`: Prompt för att generera låttext, gäller om och endast om `custom` är `true` och `lyric` inte har skickats.
- `callback_url`: URL som behöver återkallas med resultatet.
- `async`: Valfritt, när den är satt till `true` returnerar gränssnittet omedelbart `task_id`; det finns inget behov av att ange `callback_url`, och resultatet hämtas sedan genom polling via motsvarande gränssnitt för uppgiftsfrågor.

## Anpassad generering

Om du vill anpassa genereringen av sångtext kan du mata in sångtexten:

Vid denna tidpunkt kan fältet `lyric` ta emot innehåll som följande:

```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> Observera att `\n` i sångtexten här är radbrytningstecken. Om du inte vet hur du genererar sångtext kan du använda API:t för sångtextgenerering som tillhandahålls av AceDataCloud för att generera sångtext via prompt. API:t är [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Därefter, om vi vill anpassa genereringen av en låt baserat på sångtext, titel och stil, kan följande innehåll anges:

- lyric: Sångtext
- custom: Ange `true`, vilket representerar anpassad generering. Den här parametern är som standard false, vilket representerar generering med `prompt`.
- title: Låtens titel.
- style: Låtens stil, valfritt.

slutligen får du att du behöver ställa in denna låt som en sångarstil, därefter behöver du gå in i [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) för att generera en sångarstil-ID-parameter `persona_id` baserat på musik-ID:t `audio_id` som genererats officiellt, de specifika parametrarna visas i bilden nedan:

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Funktionen för fortsatt generering

Om du vill fortsätta generera en redan genererad Suno-låt kan du ställa in parametern `action` på `extend`, och ange ID:t för låten som ska fortsätta genereras. Låt-ID:t hämtas enligt grundläggande användning. Genom ovanstående kan man se att låtens ID vid denna tidpunkt är:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Observera att `id` i texten här är ID:t för låten efter generering. Om du inte vet hur man genererar en låt kan du hänvisa till den grundläggande användningen ovan för att generera en låt.

Om du vill fortsätta generera en låt som du själv har laddat upp kan du ställa in parametern `action` på `upload_extend`, och ange ID:t för den anpassat uppladdade låten som ska fortsätta genereras. Låt-ID:t hämtas med [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), som visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Därefter måste du fylla i texten för fortsättningssegmentet och kan ange stil:

- lyric: Används endast för att vägleda texten i det nygenererade segmentet efter `continue_at`, och ersätter inte texten i källjudet före denna tidpunkt.
- custom: Fyll i `true`, vilket representerar anpassad generering. Standardvärdet för denna parameter är false, vilket representerar generering med `prompt`.
- style: Låtstil för fortsättningssegmentet, valfritt.
- continue_at: Fortsättningsgräns, i sekunder. Till exempel innebär 213.5 att efterföljande segment genereras från 3 minuter och 33,5 sekunder.

> `extend` används för att fortsätta skapa efter en befintlig låt, inte för att byta text för hela låten. Om du vill använda ny text från början för hela låten ska du använda `generate` för att generera på nytt; om du vill referera till en befintlig låt för en ny tolkning kan du använda `cover`. När du skickar in en helt ny låttext kommer den ursprungliga texten före `continue_at` fortfarande inte att ersättas.

Exempel på ifyllning visas nedan:

<p><img src="https://cdn.acedata.cloud/zp9s42.png" width="500" className="m-auto" /></p>

Efter att ha fyllt i detta genereras följande kod automatiskt:

<p><img src="https://cdn.acedata.cloud/wwpw78.png" width="500" className="m-auto" /></p>
Nedan sparas en verklig historisk anropsögonblicksbild, där `continue_at` är 2 sekunder, därför tillhör endast de första 2 sekunderna det ursprungliga innehållet före fortsättningsgränsen. När man faktiskt fortsätter skriva nära slutet av en låt, bör detta värde ställas in på det antal sekunder där fortsättningen förväntas börja, och endast det nya avsnittet som ska sjungas efter gränsen ska anges i `lyric`.

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
```

## Ersätt segment

När en låt har genererats och en separat andra skapelse behöver utföras för att ersätta ett låtsegment, kan ett visst segment i låten ersättas.

> ⚠️ **Observera**: `replace_section_result_mode` är som standard `full_song`: systemet sammanfogar separat 2 nygenererade kandidater och returnerar 2 kompletta låtar. Om du endast behöver kandidater för ersättningssegment som ännu inte har sammanfogats, ange uttryckligen `candidates`, och välj sedan en kandidat för att anropa [musiksammanfogning](#音乐拼接).

Parameterbeskrivningen är följande:

- action: Innehållet är `replace_section`.
- audio_id: ID:t för originallåten (källåten som ersätts).
- model: Modellen för låtgenerering.
- lyric: Den fullständiga texten efter ersättningen (inklusive det ersatta avsnittet och dess sammanhang, i överensstämmelse med innehållet i `prompt`).
- prompt: Den nya texten för avsnittet som behöver ersättas.
- style: Låtens stil, valfritt.
- replace_section_start: Starttiden (sekunder) för det ersatta segmentet i originallåten.
- replace_section_end: Sluttiden (sekunder) för det ersatta segmentet i originallåten.
- replace_section_result_mode: Returläge, standardvärdet är `full_song`. `full_song` sammanfogar separat 2 kandidater och returnerar 2 kompletta låtar; `candidates` returnerar 2 kandidatsegment som ännu inte har sammanfogats.

## Kontrollera låtens längd

Som standard bestäms längden på den genererade låten av modellen själv, vanligtvis mellan 30 sekunder och 4 minuter. Om du behöver en längre eller kortare färdig produkt kan du ange önskad längd via parametern `duration`, där enheten är sekunder och värdet är ett heltal mellan 10 och 360.

Denna parameter används för låtgenerering i anpassat läge (`custom` är `true`). Det behöver särskilt förklaras att `duration` är en **tendensmässig uppmaning, inte en hård begränsning**: modellen refererar till detta värde när den skapar, men det finns ingen garanti för att det uppnås. I tester är den faktiska längden vanligtvis märkbart kortare än det förväntade värdet, och längden på de två låtar som returneras av samma begäran kan också skilja sig flera gånger om. Även vid helt identiska begäranden kan längden som erhålls vid flera inskick skilja sig avsevärt. Använd den därför inte som en exakt längdkontroll; om verksamheten kräver en fast längd, beskär eller försök igen själv efter att du har fått den färdiga produkten.

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Det bör noteras att `duration` i begäran är den **förväntade längden**, medan fältet `duration` för varje låt i svarets `data` är den låtens **faktiska längd**. De har samma namn men olika betydelse, och den faktiska längden garanteras inte vara lika med det förväntade värdet. Textens längd är en av de huvudsakliga faktorerna som påverkar den färdiga produktens längd; om du behöver en längre färdig produkt rekommenderas att du samtidigt tillhandahåller mer fullständiga låttexter.

Gränssnittet utför ingen ytterligare validering av `duration`, och parametern skickas till modellen som den är. Om ett värde som inte stöds av det aktuella läget eller modellen anges, kan det visa sig genom att värdet ignoreras. Det rekommenderas att först använda en begäran för att bekräfta effekten innan du använder det i batcher.

## Funktionen Lägg till instrumental

I augusti 2025 lanserade suno den nya funktionen Add Instrumental. Först behöver du ladda upp en låt med enbart sång utan bakgrundsmusik, så att suno kan lägga till musik åt dig. Du kan först gå till [Suno Upload API](https://platform.acedata.cloud/documents/suno-upload) för att ladda upp en låt med enbart sång utan bakgrundsmusik. Motsvarande åtgärder visas i bilden nedan:

Till sist erhålls ett `audio_id`: 92254cab-3372-4d9e-bce9-cdcfdbc39070, och sedan behöver vi även fylla i följande parametrar:
- action：innehållet är `underpainting`。
- underpainting_start：starttiden för att lägga till ackompanjemang till den uppladdade låten, standardvärdet är 0。
- underpainting_end：sluttiden för att lägga till ackompanjemang till den uppladdade låten, måste vara mindre än låtens totala längd。
- audio_id：ID för den uppladdade a cappella-låten utan röstpålägg。
- style：stilen på ackompanjemanget, det är bäst att inte använda sångtext eftersom det trots allt är röstpålägg。

## Add Vocals-funktion

I augusti 2025 lanserade suno en ny Add Vocals-funktion. Först behöver du ladda upp ett rent musikstycke och låta suno skriva text och skapa sång med mänsklig röst. Du kan först gå till [Suno Upload API](https://platform.acedata.cloud/documents/suno-upload) för att ladda upp en a cappella-låt utan ackompanjemang, motsvarande operation visas i bilden nedan：

## Inspo-funktionen för inspirationsskapande

Inspo-funktionen för inspirationsskapande kan generera ny musik baserat på 1 till 4 kompletta referensljudfiler och stöder dra och släpp eller uppladdning av ljud som inspirationskälla. API:et använder den befintliga `inspo`-åtgärden: klienten tillhandahåller offentligt åtkomliga ljud-URL:er, och tjänsten slutför automatiskt förberedelsen av referensljudet och skapandet, utan att klienten behöver läsa låttext, stil eller längd separat och sedan sätta ihop begäran. Den skiljer sig från intervallsamplingen ovan och även från Cover som återskapar originalsångens stil. Följande parametrar behöver fyllas i vid användning:

- action: innehållet är `inspo`.
- audio_urls: en lista med URL:er för referensljud, där 1 till 4 offentligt åtkomliga ljudadresser måste tillhandahållas.
- model: modellen som används, `chirp-v6` rekommenderas.
- prompt: låttext eller kreativ prompt (valfritt).

> Obs: Referensljudet måste vara en offentligt åtkomlig ljudfil. Om referensljudet exakt matchar en känd inspelning i plattformens låtbibliotek kan Suno vägra att generera på grund av upphovsrättskontroll. Det rekommenderas att använda eget ljud eller ljud som genererats av Suno som inspirationskälla.

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynkron återuppringning

Eftersom Suno tar relativt lång tid på sig att generera musik, ungefär 1–2 minuter, kommer HTTP-begäran att fortsätta hålla anslutningen öppen om API:t inte svarar under en längre tid, vilket leder till ytterligare förbrukning av systemresurser. Därför erbjuder detta API även stöd för asynkrona återuppringningar.

Det övergripande flödet är: när klienten initierar en begäran anges dessutom fältet `callback_url`. Efter att klienten har initierat API-begäran returnerar API:t omedelbart ett resultat som innehåller fältet `task_id`, vilket representerar ID:t för den aktuella uppgiften. När uppgiften är klar skickas resultatet av musikgenereringen till klientens angivna `callback_url` i form av POST JSON, där även fältet `task_id` ingår, så att uppgiftsresultaten kan kopplas samman via ID:t.

Nedan använder vi ett exempel för att förstå hur man gör mer specifikt.
