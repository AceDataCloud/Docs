I takt med att AI används allt mer har olika AI-program gradvis blivit vanliga. AI har gradvis trängt in i alla aspekter av människors arbete och vardagsliv. Och AI omfattar också allt fler branscher, från det ursprungliga skrivandet till medicin och utbildning, och nu även musik.

Suno är en professionell AI-plattform för högkvalitativ låt- och musikskapande. Användare behöver bara ange enkla textprompter för att, baserat på genre, stil och låttext, generera låtar med sång. Denna AI-musikgenerator utvecklas av teammedlemmar från välkända teknikföretag som Meta, TikTok och Kensho, med målet att alla ska kunna skapa vacker musik utan några instrument eller verktyg.

Suno erbjuder dock inte officiellt något API. AceDataCloud erbjuder en uppsättning Suno-API:er som simulerar integration med Suno officiellt och gör det enkelt och snabbt att generera önskad musik.

## Ansökan och användning

För att använda Suno Audios Generation API, hämta först din API Token i [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig omdirigeras du automatiskt till inloggningssidan för att registrera dig och logga in. När detta är klart återgår du automatiskt till den aktuella sidan.

**En API Token kan användas för att anropa alla plattformens tjänster, utan att behöva ansöka separat för varje tjänst.** Vid första ansökan ges en kostnadsfri kvot som kan användas för att prova tjänsten gratis; om kvoten inte räcker till kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Grundläggande användning

Vilken typ av låtar du vill ha kan du skriva in som valfri text. Om jag till exempel vill generera en låt om jul kan jag skriva `a song for Christmas`, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Här kan vi se att vi har angett Request Headers, inklusive:

- `accept`: vilket format för svarsresultatet som ska tas emot. Här anges `application/json`, alltså JSON-format.
- `authorization`: nyckeln för att anropa API:et, som kan väljas direkt i rullgardinsmenyn efter ansökan.

Dessutom har Request Body angetts, inklusive:
- `action`: Typ av ljuduppgift, standardvärdet är `generate`. Stöder åtgärder som generering, fortsättning, cover, sammanslagning, stämseparering, tillägg av ljudspår, extrahering av angivet ljudspår, generering av ljudeffekter och hastighetsjustering, som alla anropas via `POST /suno/audios`.
- `prompt`: Sunos officiella prompt för inspirationsläge (gäller när `custom` är `false`), högst 500 tecken.
- `model`: Modellen för denna musikgenereringsuppgift. v6-serien omfattar `chirp-v6`, `chirp-v6-wild` och `chirp-v6-mini`; äldre modellnamn är fortsatt kompatibla.
- `max_mode`: Förbättrat genereringsläge. `generate` aktiveras endast när både `custom` och `max_mode` är `true`, till en kostnad av 1.12 Credits; `add_stem` kan aktiveras direkt, till en kostnad av 1.344 Credits. När det är avstängt eller utelämnat är kostnaderna respektive 0.56 och 0.672 Credits.
- `variety`: Intensiteten för variation i genereringsresultaten, med alternativen `off`, `normal`, `high`, `extra`, `max`. Används endast för `generate` och `add_stem`; om det skickas för andra action returneras 400.
- `lyric`: Textinnehåll för Sunos officiella anpassade läge. `chirp-v3-5` och `chirp-v4` har högst 3000 tecken; `chirp-v4-5` och senare (inklusive `chirp-v5`, `chirp-v5-5`) har högst 5000 tecken.
- `custom`: Om anpassat läge ska användas, standardvärdet är: `false`.
- `instrumental`: Alternativet för instrumental musik i Sunos officiella inspirationsläge.
- `title`: Musiktitel för Sunos officiella anpassade läge. `chirp-v3-5`, `chirp-v4` har högst 80 tecken; `chirp-v4-5` och senare har högst 100 tecken.
- `style`: Musikstil för Sunos officiella anpassade läge. `chirp-v3-5` och `chirp-v4` har högst 200 tecken; `chirp-v4-5` och senare (inklusive `chirp-v5`, `chirp-v5-5`) har högst 1000 tecken.
- `negative_tags`: Musikstilar eller genrer som ska uteslutas vid anpassad generering, och kan även användas för `replace_section`. Detta gränssnitt har för närvarande ingen fast gräns för antal tecken för detta fält; alltför långt innehåll kan fortfarande inte behandlas, så beskrivningen bör hållas kortfattad.
- `audio_weight`: Påverkansvikt för ljud- eller röstegenskaper, inom intervallet 0–1, där även `0` är ett giltigt värde. Kan användas för åtgärder som generering, fortsättning, cover, tillägg av ljudspår och röstkonsistens; utan referensljud eller röstegenskaper kan modellen försvaga eller ignorera detta värde.
- `audio_id`: ID för referensmusik, som används för efterföljande åtgärder såsom cover, fortsättning och stämseparering. Ljudfilen kan fortfarande laddas ner, men det innebär inte att efterföljande bearbetning för detta ID alltid är tillgänglig; om `suno_processing_unavailable` returneras, spara `task_id` och `trace_id` och kontakta supporten.
- `overpainting_start`/`overpainting_end`: Start- och sluttid för att lägga till sång till befintlig instrumentalmusik, i sekunder.
- `underpainting_start`/`underpainting_end`: Start- och sluttid för att lägga till ackompanjemang till a cappella-sång, i sekunder.
- `persona_id`: Röst-ID som erhålls via gränssnittet för att skapa Persona eller röst, och är inte låtens `audio_id`.
- `continue_at`: Gräns för fortsättning, i sekunder. Till exempel innebär 213.5 att efterföljande segment genereras från 3 minuter och 33.5 sekunder. `lyric` och `style` vägleder endast nytt innehåll efter gränsen och ersätter inte text eller sång före gränsen i källjudet.
- `style_influence`: Stilpåverkan i anpassat läge, inom intervallet 0–1; ett högre värde följer vanligtvis den valda stilen närmare; `0` skickas som ett giltigt värde.
- `replace_section_end`: Sluttid för ersättningssegmentet.
- `replace_section_start`: Starttid för ersättningssegmentet.
- `vocal_gender`: Styr preferensen för kvinnlig eller manlig röst, kvinnlig röst `f`, manlig röst `m`, giltigt för modeller 4.5 och senare; är en preferens och garanteras inte att följas strikt.
- `weirdness`: Grad av märklighet i anpassat läge, inom intervallet 0–1; ett högre värde är vanligtvis mer kreativt och experimentellt; `0` skickas som ett giltigt värde.
- `duration`: Önskad låtlängd, i sekunder, måste vara ett heltal och ligga inom intervallet 10 till 360. För närvarande använder endast `generate` denna parameter, och den specifika effekten beror på läge och modell. Det är en vägledande prompt snarare än en hård begränsning: modellen tar hänsyn till den, men garanterar inte att den uppnås. Den faktiska längden på den färdiga produkten baseras på fältet `duration` i svaret och är vanligtvis kortare än det önskade värdet.

### Tillämpningsområde för röst-ID

`generate`, `cover`, `upload_cover`, `artist_consistency`, `artist_consistency_vox` kan använda `persona_id`. De två sistnämnda action måste ange `persona_id`; de kan också samtidigt ange `audio_id` för låten som användes när denna Persona skapades.

`extend`, `upload_extend` använder inte något ytterligare `persona_id`. Huruvida `mashup`, `inspo` stöder röst-ID beror på den valda tjänstekanalen; andra action garanterar inte att detta fält tillämpas, använd det enligt instruktionerna för varje åtgärd. `vocal_gender` är en valfri könspreferens och kan inte ersätta röst-ID.

Efterföljande kreativa åtgärder kräver ett giltigt käll-`audio_id`; `mashup` kräver minst två `mashup_audio_ids`. Om nödvändiga källor eller tidsparametrar saknas returneras HTTP 400.

### Tillämpningsområde för avancerade parametrar
| Parameter                | Värde                                          | Stödda action                              | Beskrivning                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | Valfritt                                      | Justerar experimentnivån, `0` är ett giltigt värde; effekten beror på åtgärd, läge och modell      |
| `style_influence` | 0-1                                         | Valfritt                                      | Justerar tendensen att följa stil, `0` är ett giltigt värde; effekten beror på åtgärd, läge och modell   |
| `audio_weight`    | 0-1                                         | Valfritt                                      | Justerar påverkan från ljud- eller röstegenskaper; kan ignoreras av modellen när referensinformation saknas        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`, `add_stem`                   | Justerar stilmässig variation mellan resultaten                       |
| `max_mode`        | boolean                                     | `generate` (kräver `custom=true`), `add_stem` | Förbättrar konsekvensen och debiteras enligt förbättrat läge                     |
| `vocal_gender`    | `f` / `m`                                   | Genereringsåtgärder som stöder röststyrning                             | Preferensalternativ, strikt efterlevnad garanteras inte                       |
| `duration`        | Heltal 10-360                                   | `generate`                              | Önskad längd; andra action använder för närvarande inte detta fält, faktisk längd beror på resultatet |

Plattformen validerar parametertyper och värdeintervall, men avvisar inte dessa valfria justeringsalternativ enbart på grund av olika action; den specifika effekten beror på åtgärd, läge och modell.

- `lyric_prompt`: prompt för att generera sångtexter, gäller endast när `custom` är `true` och `lyric` inte har skickats.
- `callback_url`: URL som behöver återanropas med resultatet.
- `async`: valfritt, när det sätts till `true` returnerar gränssnittet omedelbart `task_id`, utan att `callback_url` behöver anges, varefter resultatet hämtas genom polling via motsvarande gränssnitt för uppgiftsfrågor.

## Anpassad generering

Om du vill anpassa genereringen av sångtexter kan du ange sångtext:

Vid denna tidpunkt kan fältet `lyric` ta emot innehåll som följande:
```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> Observera, `\n` i låttexten här är radbrytningar. Om du inte vet hur man genererar låttexter kan du använda API:et för låttextgenerering som tillhandahålls av AceDataCloud för att generera låttexter via en prompt. API:et är [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Därefter ska vi generera en låt baserat på låttext, titel och stil, och kan då ange följande innehåll:

- lyric: låttext
- custom: ange som `true`, vilket innebär anpassad generering. Denna parameter är som standard false, vilket innebär att `prompt` används för generering.
- title: låtens titel.
- style: låtens stil, valfritt.

## Funktion för anpassad generering med sångarstil

Om du vill använda en sångarstil för att generera en låt ska du först generera en låt genom den grundläggande användningen ovan.\
Till slut behöver du ställa in den här låten som sångarstil, och sedan gå till [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) för att generera en id-parameter för sångarstilen, `persona_id`, baserat på musik-ID:t `audio_id` som genererats officiellt. De specifika parametrarna visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Efter ifyllnad genereras följande kod automatiskt:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Därefter kan parametern `action` ställas in på `artist_consistency` (om det är den nya sångarstilen Persona-v2-vox måste `action` ställas in på `artist_consistency_vox`), och ID:t för låten som behöver fortsätta genereras samt sångarstil-ID:t anges.
```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "artist_consistency",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b",
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Funktion för fortsatt generering
Om du vill fortsätta generera en redan skapad Suno-låt kan du ange parametern `action` som `extend` och ange ID:t för låten som behöver fortsätta genereras. Låt-ID:t hämtas enligt den grundläggande användningen. Av ovanstående framgår att låtens ID då är:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Observera att `id` i texten här är ID:t för låten efter generering. Om du inte vet hur man genererar en låt kan du hänvisa till den grundläggande användningen ovan för att generera en låt.

Om du vill fortsätta generera en låt som du själv har laddat upp kan du ange parametern `action` som `upload_extend` och ange ID:t för den anpassat uppladdade låten som behöver fortsätta genereras. Låt-ID:t hämtas med [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), som visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Därefter måste du fylla i texten för fortsättningssegmentet och kan ange en stil:

- lyric: används endast för att vägleda texten i det nyligen genererade segmentet efter `continue_at`, och ersätter inte texten före denna tidpunkt i källjudet.
- custom: ange `true`, vilket representerar anpassad generering. Denna parameter är som standard false, vilket representerar generering med `prompt`.
- style: låtstil för fortsättningssegmentet, valfri.
- continue_at: fortsättningsgräns, i sekunder. Till exempel innebär 213.5 att efterföljande segment börjar genereras vid 3 minuter och 33,5 sekunder.

`continue_at` för `extend` och `upload_extend` måste vara större än 0 och stöder decimalsekunder, till exempel `30.792`; värdet avrundas inte vid inskickning.

> `extend` används för att fortsätta skapa efter en befintlig låt, inte för att byta ut texten för hela låten. Om du vill använda ny text från början för hela låten ska du använda `generate` för att generera på nytt; om du vill tolka om med hänvisning till en befintlig låt kan du använda `cover`. När en helt ny låttext skickas in ersätts fortfarande inte den ursprungliga texten före `continue_at`.

Efter ifyllnad genereras följande kod automatiskt:

## Ersätt segment

`replace_section` genererar om det valda segmentet baserat på källåtens tidsintervall och fogar tillbaka resultatet till originallåten. `replace_section_result_mode` är som standard `full_song` och returnerar 2 kompletta låtar som kan spelas upp direkt, utan att `concat` behöver anropas igen.

### Hur indata fylls i
- `action`: `replace_section`.
- `audio_id`: Det fullständiga låt-ID:t för låten som ska redigeras. Vid redigering igen, använd `data[].id` för den fullständiga låt som valdes förra gången, inte `task_id`.
- `model`: Modellen för låtgenerering, till exempel `chirp-v6`.
- `lyric`: Den **lokala nya sångtext** som ska sjungas i det valda intervallet. Du behöver inte skicka in hela sångtexten för att få en komplett låt.
- `prompt`: Ange tydligt den lokala nya sångtext som ska ersättas denna gång. Vid textändring rekommenderas att samma innehåll fylls i som i `lyric`, för att undvika att de två fälten uttrycker olika sångtexter. Befintliga förfrågningar som endast skickar lokal `lyric` och utelämnar `prompt` kan fortfarande användas, men att lägga till `prompt` i sig garanterar inte att textändringen lyckas.
- `style`, `negative_tags`: Valfria stilbeskrivningar och undantag; `prompt` är i denna åtgärd inte en vanlig inspirationsbeskrivning vid låtskapande.
- `replace_section_start`, `replace_section_end`: Start- och sluttiden för det valda intervallet i källåten denna gång, i sekunder och med stöd för decimaler. Startpunkten får inte vara mindre än 0, slutpunkten måste vara större än startpunkten och får inte överstiga källåtens längd.
- `replace_section_result_mode`: `full_song` (standard) returnerar 2 kompletta låtar; `candidates` returnerar 2 ännu inte sammanfogade ersättningskandidater.

Använd inte ”`lyric` måste vara den fullständiga sångtexten efter ersättning, `prompt` måste vara lokal sångtext” som allmän användning. Inmatning av fullständig sångtext kan i vissa uppgifter skapa ett för långt ersättningsinnehåll, vilket gör hela låten avsevärt längre efter sammanfogning. Lokal inmatning garanterar inte heller fast längd eller att sångtexten följs ord för ord; detta är generativ redigering och det faktiska ljudet behöver kontrolleras.

### Starta uppgiften och hämta den kompletta låten

Nedan följer ett exempel på begärandeformat. Ersätt `YOUR_COMPLETED_AUDIO_ID` och tidsintervallet med ditt eget källåt-ID och faktiska valda intervall; exemplet antar att 30–50 sekunder motsvarar följande fyra rader.

```json
{
  "action": "replace_section",
  "audio_id": "YOUR_COMPLETED_AUDIO_ID",
  "model": "chirp-v6",
  "custom": false,
  "instrumental": false,
  "lyric": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "prompt": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "replace_section_start": 30.0,
  "replace_section_end": 50.0,
  "replace_section_result_mode": "full_song",
  "async": true
}
```

Efter inskickning använder du det returnerade `task_id` för att fråga `/suno/tasks`, med begärandetexten `{"action":"retrieve","id":"YOUR_TASK_ID"}`. När uppgiften är klar hämtar du `id`, `audio_url` och `duration` för de två kompletta låtarna från `response.data` i uppgiftssvaret, lyssnar på dem och väljer en av dem. `success: true` betyder att uppgiften har körts framgångsrikt, inte att den nya sångtexten har sjungits ord för ord eller att längden uppfyller förväntningarna.

### Valt intervall, resultatkontroll och redigering igen

1. Lyssna först på källåten och använd sedan tidsinformationen från `/suno/timing` för att bestämma det valda intervallet, och försök att täcka hela musikfraser. Välj inte intervall utifrån fasta index i sångtextarrayen, och ersätt inte heller ett intervall som innehåller fler musikfraser med några få rader sångtext och förvänta dig att rytmen förblir helt oförändrad.
2. Försök att hålla antalet rader, antal tecken och rytmen i den nya sångtexten nära det ursprungliga innehållet i det valda intervallet. Även om bara några få tecken ändras behöver resultatet verifieras genom lyssning; framgång kan inte garanteras utifrån detta.
3. Kontrollera om den nya texten sjungs i målintervallet, om övergångarna före och efter är naturliga samt om hela låtens längd är rimlig. `full_song` betyder att en komplett låt returneras, inte att den har samma längd som originallåten; när ersättningssegmentet blir längre flyttas den senare delen framåt i motsvarande grad. Begärandeparametern `duration` används endast för vanlig generering och kan inte låsa ersättningssegmentets längd.
4. Den returnerade `lyric` är metadata för sångtexten; läget för komplett låt kombinerar den fullständiga sångtexten när tidsinformation för källtexten kan hämtas, och kan vara tom när den inte kan hämtas. Den är inte en ljudtranskribering; att ny text visas bevisar inte att ljudet faktiskt har sjungit den nya texten. Tidsjusteringsinformation bör också verifieras genom lyssning, särskilt för resultat som redan har redigerats.
5. Vid redigering igen använder du den valda **fullständiga färdiga produktens ID** som nytt `audio_id` och kontrollerar på nytt produktens längd och valda intervall. Återanvänd inte tidskoordinaterna från före redigeringen, och använd inte heller direkt hela `lyric` som returnerades förra gången som lokal inmatning denna gång.

Om uppgiften är klar men fortfarande sjunger den gamla texten, utelämnar text eller blir avsevärt längre, kontrollera först källåt-ID, valt intervall och lokal sångtext, och kontrollera sedan det andra resultatet. Att öka frekvensen för uppgiftsfrågor ändrar inte innehållet som redan har genererats. Om problemet kvarstår, behåll `task_id`, källåt-ID, begärandefält, valt intervall och resultatljud för att underlätta granskning.

### Valfritt: hämta först kandidater och sammanfoga manuellt

Ställ endast in `replace_section_result_mode: "candidates"` när du behöver välja ersättningskandidat själv. Kandidater kan innehålla kontext och bör inte betraktas som kompletta låtar enbart utifrån kandidatens längd. Efter val anropar du `concat` med kandidatens `data[].id` och hämtar sedan den kompletta färdiga produkten.

Standardvärdet `full_song` har redan slutfört sammanfogningen, så detta steg behöver inte utföras.

## Separering av sång och musik

## Separation av sång och musik för alla spår

Uppgiften väntar tills alla ljudspår har genererats färdigt innan den returnerar ett lyckat slutstatus. Att en spelbar adress visas under bearbetningen innebär inte att hela gruppen av ljudspår redan är färdig.

När en låt har genererats och separation av sång och musik för alla spår behöver utföras, kan följande innehåll anges:

- action: innehållet är `all_stems`.
- audio_id: ID:t för den tidigare genererade låten.

Om ID:t för den ursprungligen genererade låten till exempel är: bdf23a5a-59f5-4103-b452-054a824a7f9f, kan parametrarna ställas in enligt följande:

```json
{
  "action": "all_stems",
  "audio_id": "bdf23a5a-59f5-4103-b452-054a824a7f9f"
}
```

## Lägg till ljudspår

- Obligatoriskt: `action`, `audio_id`, `stem_type`.
- Valfritt: `model`, `prompt`, `title`, `style`, `negative_tags`, `weirdness`, `style_influence`, `audio_weight`, `max_mode`, `variety`.

## Extrahera ljudspår

`extract_stem` extraherar målljudspåret från angivet ljud och returnerar samtidigt en kompletterande version där ljudspåret har tagits bort, via anropet `POST /suno/audios`.

- Obligatoriskt: `action`, `audio_id`, `stem_type`.
- Valfritt: `audio_format`, det nuvarande offentliga tvåkanalskontraktet stöder endast `mp3`.

```json
{
  "action": "extract_stem",
```

## Kontrollera låtlängden

Som standard bestäms längden på den genererade låten av modellen själv, vanligtvis mellan 30 sekunder och 4 minuter. Om du behöver en längre eller kortare färdig produkt kan du ange önskad längd med parametern `duration`, i sekunder, med heltalsvärden från 10 till 360.

Den här parametern används för låtgenerering i anpassat läge (`custom` är `true`). Det bör särskilt förklaras att `duration` är en **vägledande antydan, inte en hård begränsning**: modellen refererar till detta värde vid skapandet, men garanterar inte att det uppnås. I praktiska tester är den faktiska längden vanligtvis betydligt kortare än det önskade värdet, och längderna på de två låtar som returneras i samma förfrågan kan också skilja sig flera gånger om. Även vid helt identiska förfrågningar kan längderna som erhålls vid flera inskick skilja sig avsevärt. Använd därför inte detta som exakt längdkontroll; om verksamheten kräver fast längd ska du trimma eller försöka igen själv efter att ha fått den färdiga produkten.

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Det är viktigt att notera att `duration` i förfrågan är den **önskade längden**, medan fältet `duration` för varje låt i svarets `data` är den **faktiska längden** för den låten. De har samma namn men olika innebörd, och den faktiska längden garanteras inte vara lika med det önskade värdet. Längden på texten är en av de viktigaste faktorerna som påverkar den färdiga produktens längd. Om en längre färdig produkt behövs rekommenderas att samtidigt tillhandahålla mer kompletta låttexter.

API:et validerar att `duration` måste vara ett heltal mellan 10 och 360; det är fortfarande endast ett genereringsmål, inte en garanti för den färdiga produktens längd.

## Inspo-funktionen för inspirationsskapande

Inspo-funktionen för inspirationsskapande kan generera ny musik baserat på 1 till 4 kompletta referensljudfiler och stöder att dra och släppa eller ladda upp ljud som inspirationskälla. API:et använder den befintliga `inspo`-åtgärden: klienten tillhandahåller en offentligt tillgänglig ljud-URL, och tjänsten slutför automatiskt förberedelsen av referensljudet och skapandet, utan att klienten behöver läsa in låttext, stil eller längd separat och sedan sätta ihop begäran. Den skiljer sig från intervallsampling ovan och även från Cover som återskapar originalsångens stil. Följande parametrar behöver fyllas i vid användning:

- action: Innehållet är `inspo`.
- audio_urls: En lista med URL:er till referensljud; 1 till 4 offentligt tillgängliga ljudadresser måste tillhandahållas.
- model: Modellen som används, `chirp-v6` rekommenderas.
- prompt: Låttext eller prompt för skapande (valfritt).
- instrumental: När den sätts till `true` genereras det enligt en begäran om instrumentalmusik, utan att använda låttext.
- persona_id: Använder det angivna ljudet i tjänstekanaler som stöder denna kombination; referensljudet binds under förberedelsefasen till den resursmiljö som krävs för det ljudet.
- lyric_prompt: När `custom=true` och `lyric` inte har angetts används detta för att automatiskt generera låttext.

> Obs: Referensljudet måste vara en offentligt tillgänglig ljudfil. Om referensljudet exakt matchar en känd inspelning i plattformens musikbibliotek kan Suno avvisa genereringen på grund av upphovsrättskontroll. Det rekommenderas att använda eget ljud eller ljud som genererats av Suno som inspirationskälla.

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynkront återanrop

Eftersom det tar relativt lång tid för Suno att generera musik, ungefär 1–2 minuter, kommer HTTP-begäran att hållas ansluten om API:et inte svarar under en längre tid, vilket leder till ytterligare förbrukning av systemresurser. Därför erbjuder detta API även stöd för asynkrona återanrop.

Det övergripande flödet är: när klienten initierar en begäran anges dessutom ett `callback_url`-fält. Efter att klienten har initierat API-begäran returnerar API:et omedelbart ett resultat som innehåller fältinformationen `task_id`, vilket representerar det aktuella uppgifts-ID:t. När uppgiften är slutförd skickas resultatet av den genererade musiken i form av POST JSON till den `callback_url` som klienten har angett, vilket också inkluderar fältet `task_id`, så att uppgiftsresultatet kan kopplas samman via ID:t.
