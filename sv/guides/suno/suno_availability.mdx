---
title: "API för kontroll av tillgänglighet för Suno-ljud och röstklanger"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` accepterar ett resurs-ID. Skicka `audio_id` för att kontrollera en låt och `persona_id` för att kontrollera en röstklang; ett av dem måste anges. Kontrollen slutförs synkront, kräver en API-token och drar för närvarande inga Credits.

## Begäran

`audio_id` kommer från en slutförd låtuppgift och kan användas för kontroll före fortsättning eller cover.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

`persona_id` kommer från resultatet av skapandet av en röstklang. Använd den ursprungliga applikationen och anroparidentiteten och skicka följande begärandetext på en skapanderutt som stöder frågor om röstklanger.

```json
{
  "persona_id": "33333333-3333-4333-8333-333333333333"
}
```

## Svar

Båda begärandetyperna använder samma lyckade svar. `data.id` är resurs-ID:t för denna fråga.

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

`available: true` innebär att denna kontroll har fått positiva bevis. För röstklanger verifierar kontrollen skapandeägarskapet och bekräftar att det associerade kontot för närvarande rapporteras vara online. Det faktiska genereringsresultatet avgörs fortfarande av genereringsuppgiften.

Privata klonade röstklanger som skapas via `/suno/voices` är beroende av skapandekontot. När det bekräftas att kontot för närvarande är offline returnerar gränssnittet HTTP 200, med följande exempel på `data`.

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

Klienten kan markera denna röstklang som för närvarande otillgänglig och kontrollera igen senare.

När det inte går att bekräfta returneras HTTP 503 och `availability_unknown`, till exempel om resursen inte kan hittas, äldre poster saknar skapanderutt eller frågan får timeout. Offentliga sångarstilar kan användas mellan konton och returnerar också 503 när skapandekontot är offline. Låtförfrågningar returnerar fortfarande endast `available: true` när tillgänglighet bekräftas.

Varje begäran skickar endast ett giltigt UUID. Alla rutter returnerar HTTP 400 när de tar emot en begäran med dubbla ID:n eller med båda ID:n saknade. Rutter som endast stöder låtförfrågningar returnerar HTTP 400 när de tar emot en begäran som endast innehåller `persona_id`. Vid HTTP 429, minska frågefrekvensen.
