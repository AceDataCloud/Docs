---
title: "Suno API för kontroll av ljudtillgänglighet"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` söker efter positiva bevis på att ljudet kan fortsätta bearbetas i den aktuella rutten baserat på `audio_id`. Kan anropas före åtgärder som fortsättning, coverversioner osv.; resultatet återspeglar endast statusen vid kontrolltillfället och garanterar inte att en specifik åtgärd kommer att lyckas. Detta gränssnitt returnerar synkront, kräver API Token och drar för närvarande inga Credits.

`audio_id` är låt-ID:t som returneras av en slutförd Suno-uppgift, inte `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Exempel på lyckat svar:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

När kontrollen lyckas kan `data.available` endast vara `true`. Statusen ”inte online” som returneras av vissa rutter kan inte bevisa att efterföljande åtgärder som fortsättning inte kan lyckas, därför returnerar detta gränssnitt `503 availability_unknown` när det inte går att bekräfta, och returnerar inte `false`. Felaktigt `audio_id`-format returnerar 400, och begränsning av anropsfrekvens eller fel hos uppströmsleverantören returnerar också felsvar. Statusen kan fortfarande ändras mellan att kontrollen slutförs och den faktiska åtgärden.
