SUNO gör det möjligt för oss att skapa anpassade röstkaraktärer genom valfria ljudfiler och använda röstkloning för musikgenerering. Till skillnad från det befintliga Persona API:t (som använder `audio_id` genererat av Suno) accepterar detta API en offentligt tillgänglig `audio_url`, det vill säga din egen inspelning av en mänsklig röst. Detta dokument förklarar hur röstklonings-API:t integreras.

## Steg 1: Skapa en röstkaraktär

Detta API har tre indataparametrar: `audio_url` (obligatorisk), vilket är en offentligt tillgänglig URL till en ljudfil i MP3- eller WAV-format som innehåller en tydlig röst från en ensam person; `name` och `description` (valfria), som är namnet och beskrivningen för röstkaraktären.

> **Krav på ljudfilen**
> - Ljudformatet måste vara `WAV` eller `MP3`
> - Ljudets längd måste vara mellan `10~240 sekunder`; rena inspelningar av en ensam röst på `30~60 sekunder` rekommenderas
> - Ljudet bör innehålla**tydligt, igenkännbart tal eller sång från en ensam person**
> - Undvik noggrant**bakgrundsljud, ackompanjemang, eko och efterklang**; hela låtar med ackompanjemang kan vanligtvis inte klara röstavtrycksverifieringen
> - Inkludera inte**flera talare**eller**flera röster**
> - Material med för låg volym, otydligt tal eller för mycket brus kan leda till**misslyckad kloning**eller**sämre genereringsresultat**
> **Beskrivning av användningsbegränsningar**
> - Röstkaraktärer som skapas genom uppladdning av ljud är**privata resurser**
> - Denna röstkaraktär**stöder inte återanvändning mellan konton**
> - Det rekommenderas att använda den så snart som möjligt efter att skapandet har lyckats; om den inte används under lång tid kan den**upphöra att gälla eller bli otillgänglig**
> - Det returnerade `name` genereras automatiskt av systemet; använd den returnerade `persona_id` som referens

> **Försök igen först när anropet misslyckas**
> Röstkloning är en beräkningsintensiv uppgift, och även om materialet är helt kompatibelt finns det en viss sannolikhet för tillfälliga fel, med vanliga svar som
> `voices_sound_different` (röstavtrycksverifieringen misslyckades) och liknande. **Den här typen av fel är inte relaterade till ljudkvaliteten, och det räcker vanligtvis att försöka igen med samma material för att lyckas**,
> det rekommenderas att implementera 1~2 automatiska återförsök för misslyckade resultat vid integrering. Misslyckade förfrågningar debiteras inte.

```bash
curl -X POST 'https://api.acedata.cloud/suno/voices' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3",
  "name": "My Voice",
  "description": "单人清晰人声示例"
}'
```

> Ovanstående `https://cdn.acedata.cloud/suno_demo.mp3` är exempelmaterial som kan anropas direkt (MP3, 41 sekunder, ensam torr röst).
> Om du behöver ett exempel i `WAV`-format kan du använda
> `https://cdn.acedata.cloud/uploads/82d23b97-ec1c-4b41-91b8-989fc51f8765` (WAV, 41 sekunder, mono 44,1 kHz).

Resultatet är följande:

```json
{
  "success": true,
  "task_id": "0fa609a6-c8d9-4bb5-8574-e4c93bb55d02",
  "data": {
    "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16",
    "name": "VOICE_20260803037676",
    "is_public": false
  }
}
```

Som du kan se är fältet `persona_id` i `data` ID:t för den skapade röstkaraktären. Fältet `is_public` är alltid `false`, eftersom röstkaraktärer som skapas genom uppladdning av ljud är privata. Observera att det returnerade `name` genereras automatiskt av systemet; använd därefter `persona_id` för att referera till denna röstkaraktär.

## Steg 2: Generera musik med röstkaraktären

Efter att ha fått röstkaraktärens ID kan vi använda [Suno Audios Generation API](https://platform.acedata.cloud/documents/suno-audios) för att generera musik. Sätt `action` till `generate` och `persona_id` till ID:t för röstkaraktären som returnerades ovan, så kommer den genererade låten att sjungas med den klonade rösten.

> **Observera:** Röstkloning stöder endast modellerna `chirp-v4-5` och senare (såsom `chirp-v4-5`, `chirp-v5`, `chirp-v5-5`), och stöder inte `chirp-v4`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "chirp-v5-5",
  "prompt": "A warm synth-pop song about city nights",
  "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16"
}'
```

Resultatet är följande:

```json
{
  "success": true,
  "task_id": "53d8a334-a972-43c5-895e-60c4454e88d5",
  "data": [
    {
      "id": "16463960-077c-4700-bbb3-3c7897b943d3",
      "title": "Soft Neon on My Skin",
      "audio_url": "https://cdn.acedata.cloud/assets/examples/fish/5ade0339-5f11-487e-aacc-06a908271706-8e3fcb0e5547.mp3",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "model": "chirp-v5-5",
      "state": "succeeded",
      "prompt": "A warm synth-pop song about city nights",
      "duration": 156.28
    }
  ]
}
```

Som du kan se använder den genererade låten den klonade rösten för sången. `persona_id` kan också användas tillsammans med åtgärden `cover` för att skapa en cover av en befintlig låt med den klonade rösten.
