SUNO låter oss skapa anpassade röstkaraktärer via valfria ljudfiler och implementera röstkloning för musikgenerering. Till skillnad från det befintliga Persona API:t (som använder Suno-genererat `audio_id`) accepterar detta API en offentligt tillgänglig `audio_url`, det vill säga din egen inspelning av en mänsklig röst. Detta dokument förklarar hur du integrerar röstkloning API:t.

I skapandeflöden som stöder kontroll av röstklang kan du, med den ursprungliga applikationen och anroparens identitet, skicka `persona_id` från skapanderesultatet till `POST /suno/availability`. När det associerade kontot är online returneras `data.available=true`, och när det bekräftas vara offline returneras `data.available=false`. [Guide för kontroll av röstklangstillgänglighet](https://platform.acedata.cloud/documents/suno-availability-integration)

## Steg 1: Skapa en röstkaraktär

Debitering: Efter att en röstkaraktär har skapats framgångsrikt är standardkostnaden för varje begäran **0.15 Credits**. Tillämpliga förbrukningsrabatter baseras på den faktiska fakturan, och misslyckade begäranden debiteras inte.

Detta API har tre inmatningsparametrar: `audio_url` (obligatorisk), en offentligt tillgänglig URL till en ljudfil i MP3- eller WAV-format som innehåller en tydlig mänsklig röst från en enda person; `name` och `description` (valfria), som är röstkaraktärens namn och beskrivning.

> **Krav för ljudfilen**
> - Ljudformatet måste vara `WAV` eller `MP3`
> - Ljudlängden måste vara mellan `10~240 sekunder`, och det rekommenderas att använda rent torrt röstmaterial från en enda person på `30~60 sekunder`
> - Ljudet bör innehålla**tydligt, identifierbart tal eller sång från en enda person**
> - Se till att undvika**bakgrundsbrus, ackompanjemang, eko och efterklang**; kompletta låtar med ackompanjemang kan vanligtvis inte godkännas vid röstavtryckskontroll
> - Inkludera inte**flera talare**eller**flera röster**
> - Material med för låg volym, otydligt tal eller för mycket brus kan leda till**misslyckad kloning**eller**sämre genereringsresultat**
> **Beskrivning av användningsbegränsningar**
> - Röstkaraktärer som skapas genom att ladda upp ljud är**privata resurser**
> - Denna röstkaraktär**stöder inte återanvändning mellan konton**
> - Det rekommenderas att använda den snarast möjligt efter framgångsrik skapelse; om den inte används under lång tid kan den bli**ogiltig eller otillgänglig**
> - Returnerat `name` genereras automatiskt av systemet, använd returnerat `persona_id` som referens

> **Hantera fel enligt den tydliga återförsöksmarkeringen**
> `retryable` i felobjektet är ett valfritt booleskt fält. När `error.retryable` är `true` betyder det att detta fel tillåter att samma material och samma parametrar används för att skicka en ny begäran senare. Uttryckligen ej accepterad upptagen tjänst eller vissa tillfälliga misslyckanden i röstavtryckskontrollen kan ha denna markering; det rekommenderas att använda backoff-intervall och begränsa antalet återförsök.
> När `retryable` är `false` eller fältet saknas ska du inte automatiskt skicka om en begäran enbart baserat på HTTP 500, `busy` eller feltexten. Problem med format, längd, tydlighet, upprepade inspelningar och innehållsgranskning bör först korrigeras; vid timeout för inskickning, avbruten anslutning eller oklart skaperesultat bör du i första hand använda det ursprungliga `task_id` för att fråga efter uppgiften för att undvika att skapa samma röstklang flera gånger. Misslyckade begäranden debiteras inte, och lyckade återförsök debiteras enligt vanliga regler.

```bash
curl -X POST 'https://api.acedata.cloud/suno/voices' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3",
  "name": "My Voice",
  "description": "单人清晰人声示例"
}'
```

> Ovanstående `https://cdn.acedata.cloud/suno_demo.mp3` är exempelmaterial som kan anropas direkt (MP3, 41 sekunder, torr röst från en enda person).
> Om du behöver ett exempel i `WAV`-format kan du använda
> `https://cdn.acedata.cloud/uploads/82d23b97-ec1c-4b41-91b8-989fc51f8765` (WAV, 41 sekunder, mono 44.1kHz).

Resultatet är följande:

```json
{
  "success": true,
  "task_id": "0fa609a6-c8d9-4bb5-8574-e4c93bb55d02",
  "data": {
    "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16",
    "name": "VOICE_20260803037676",
    "is_public": false
  }
}
```

Som du kan se är fältet `persona_id` i `data` ID:t för den skapade röstkaraktären. Fältet `is_public` är alltid `false`, eftersom röstkaraktärer som skapas genom att ladda upp ljud är privata. Observera att returnerat `name` genereras automatiskt av systemet; använd `persona_id` för att hänvisa till denna röstkaraktär framöver.

## Steg 2: Använd röstkaraktären för att generera musik

Efter att du har ett ID för röstkaraktären kan vi använda [Suno Audios Generation API](https://platform.acedata.cloud/documents/suno-audios) för musikgenerering. Ange `action` till `generate` och `persona_id` till ID:t för röstkaraktären som returnerades ovan, så kommer den genererade låten att sjungas med den klonade rösten.

> **Observera:** Röstkloning stöder endast modellerna `chirp-v4-5` och senare (såsom `chirp-v4-5`, `chirp-v5`, `chirp-v5-5`), och stöder inte `chirp-v4`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "chirp-v5-5",
  "prompt": "A warm synth-pop song about city nights",
  "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16"
}'
```

Resultatet är följande:

```json
{
  "success": true,
  "task_id": "53d8a334-a972-43c5-895e-60c4454e88d5",
  "data": [
    {
      "id": "16463960-077c-4700-bbb3-3c7897b943d3",
      "title": "Soft Neon on My Skin",
      "audio_url": "https://cdn.acedata.cloud/assets/examples/fish/5ade0339-5f11-487e-aacc-06a908271706-8e3fcb0e5547.mp3",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "model": "chirp-v5-5",
      "state": "succeeded",
      "prompt": "A warm synth-pop song about city nights",
      "duration": 156.28
    }
  ]
}
```

`persona_id` kan användas för `generate`-generering och även för coverversioner med `cover` / `upload_cover`. När en röst anges behöver `vocal_gender` inte fyllas i samtidigt; röstlikheten beror fortfarande på referensmaterialet och genereringsresultatet.

Röster som skapas via detta gränssnitt är privata resurser. Innan du gör en coverversion av en befintlig låt ska du först anropa `/suno/upload` och skicka den ursprungliga låtens `audio_url` och röstens `persona_id`; efter lyckad uppladdning använder du returnerat `data.audio_id` och samma `persona_id` för att anropa `/suno/audios`:
```json
{
  "action": "upload_cover",
  "model": "chirp-v6",
  "audio_id": "<audio_id som returneras efter uppladdning associerad med detta ljud>",
  "persona_id": "<persona_id som returneras av gränssnittet för att skapa ljud>",
  "custom": true,
  "instrumental": false,
  "lyric": "[Verse]\nAnge sångtexten som ska sjungas",
  "async": true
}
```

Att skapa ljud, ladda upp originalsånger och göra covers måste använda samma tjänstekanal. Återanvänd inte direkt tidigare låt-ID:n som inte är associerade med detta privata ljud; se mer information i [Suno uppladdning av referensljud](https://platform.acedata.cloud/documents/suno-upload).
