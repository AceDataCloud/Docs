SUNO gör det möjligt för oss att skapa anpassade röstroller via valfria ljudfiler och använda röstkloning för musikgenerering. Till skillnad från det befintliga Persona API:t (som använder Suno-genererat `audio_id`) accepterar detta API en offentligt tillgänglig `audio_url`, det vill säga din egen inspelning av en mänsklig röst. Detta dokument förklarar hur du integrerar API:t för röstkloning.

## Steg 1: Skapa en röstroll

Detta API har tre indataparametrar: `audio_url` (obligatorisk), en offentligt tillgänglig URL till en ljudfil i MP3- eller WAV-format som innehåller en tydlig röst från en enskild person; `name` och `description` (valfria), som är röstrollens namn och beskrivning.

> **Krav för ljudfiler**
> - Ljudformatet måste vara `WAV` eller `MP3`
> - Ljudets längd måste vara mellan `10~240 sekunder`, och det rekommenderas att använda `30~60 sekunder` rent torrt ljudmaterial med en enskild röst
> - Ljudet ska innehålla**tydligt, identifierbart tal eller sång från en enskild person**
> - Se till att undvika**bakgrundsbrus, ackompanjemang, eko och efterklang**; kompletta låtar med ackompanjemang kan vanligtvis inte klara röstavtrycksvalideringen
> - Inkludera inte**flera talare**eller**flera röster**
> - Material med för låg volym, otydligt tal eller för mycket brus kan leda till**misslyckad kloning**eller**sämre genereringsresultat**
> **Beskrivning av användningsbegränsningar**
> - Röstroller som skapas genom att ladda upp ljud är**privata resurser**
> - Röstrollen**stödjer inte återanvändning mellan konton**
> - Det rekommenderas att använda den så snart som möjligt efter att den har skapats; om den inte används under lång tid kan den bli**ogiltig eller otillgänglig**
> - Det returnerade `name` genereras automatiskt av systemet, använd det returnerade `persona_id` som referens

> **Försök igen först när anropet misslyckas**
> Röstkloning är en beräkningsintensiv uppgift, och även om materialet är helt kompatibelt finns det en viss sannolikhet för tillfälliga fel, vanliga svar är till exempel
> `voices_sound_different` (röstavtrycksvalideringen misslyckades) och liknande. **Denna typ av fel har inget att göra med ljudkvaliteten, och att försöka igen med samma material brukar lyckas**,
> det rekommenderas att implementera 1~2 automatiska återförsök för misslyckade resultat vid integrering. Misslyckade förfrågningar debiteras inte.

```bash
curl -X POST 'https://api.acedata.cloud/suno/voices' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3",
  "name": "My Voice",
  "description": "单人清晰人声示例"
}'
```

> Ovanstående `https://cdn.acedata.cloud/suno_demo.mp3` är exempelmaterial som kan anropas direkt (MP3, 41 sekunder, torr röst från en enskild person).
> Om du behöver ett exempel i `WAV`-format kan du använda
> `https://cdn.acedata.cloud/uploads/82d23b97-ec1c-4b41-91b8-989fc51f8765` (WAV, 41 sekunder, mono 44,1 kHz).

Resultatet är följande:

```json
{
  "success": true,
  "task_id": "0fa609a6-c8d9-4bb5-8574-e4c93bb55d02",
  "data": {
    "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16",
    "name": "VOICE_20260803037676",
    "is_public": false
  }
}
```

Som du kan se är fältet `persona_id` i `data` ID:t för den skapade röstrollen. Fältet `is_public` är alltid `false`, eftersom röstroller som skapas genom uppladdning av ljud är privata. Observera att det returnerade `name` genereras automatiskt av systemet, använd `persona_id` för att referera till röstrollen framöver.

## Steg 2: Använd röstrollen för att generera musik

Efter att ha fått röstrollens ID kan vi använda [Suno Audios Generation API](https://platform.acedata.cloud/documents/suno-audios) för att generera musik. Sätt `action` till `generate` och `persona_id` till ID:t för röstrollen som returnerades ovan, så kommer den genererade låten att sjungas med den klonade rösten.

> **Observera:** Röstkloning stöder endast modellerna `chirp-v4-5` och högre (såsom `chirp-v4-5`, `chirp-v5`, `chirp-v5-5`), och stöder inte `chirp-v4`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "chirp-v5-5",
  "prompt": "A warm synth-pop song about city nights",
  "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16"
}'
```

Resultatet är följande:

```json
{
  "success": true,
  "task_id": "53d8a334-a972-43c5-895e-60c4454e88d5",
  "data": [
    {
      "id": "16463960-077c-4700-bbb3-3c7897b943d3",
      "title": "Soft Neon on My Skin",
      "audio_url": "https://cdn.acedata.cloud/assets/examples/fish/5ade0339-5f11-487e-aacc-06a908271706-8e3fcb0e5547.mp3",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "model": "chirp-v5-5",
      "state": "succeeded",
      "prompt": "A warm synth-pop song about city nights",
      "duration": 156.28
    }
  ]
}
```

`persona_id` kan användas för `generate`-generering och även för `cover` / `upload_cover`-covers. När en röst anges behöver `vocal_gender` inte fyllas i samtidigt; röstlikheten beror fortfarande på referensmaterialet och genereringsresultatet.

Röster som skapas via detta gränssnitt är privata resurser. Innan du gör en cover av en befintlig låt ska du först anropa `/suno/upload` och ange originalets `audio_url` samt röstens `persona_id`; efter en lyckad uppladdning använder du det returnerade `data.audio_id` och samma `persona_id` för att anropa `/suno/audios`:

```json
{
  "action": "upload_cover",
  "model": "chirp-v6",
  "audio_id": "<与该声音关联上传后返回的 audio_id>",
  "persona_id": "<声音创建接口返回的 persona_id>",
  "custom": true,
  "instrumental": false,
  "lyric": "[Verse]\n填写要演唱的歌词",
  "async": true
}
```

Skapande av röst, uppladdning av originalet och cover måste använda samma tjänstekanal. Återanvänd inte direkt tidigare låt-ID:n som inte har kopplats till denna privata röst; se [Suno uppladdning av referensljud](https://platform.acedata.cloud/documents/suno-upload) för detaljer.
