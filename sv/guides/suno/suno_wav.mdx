SUNO tillåter oss att hämta musik i wav-format. Denna dokumentation förklarar hur man integrerar med den relaterade API:n.

Kärnparametern för API:et är `audio_id`, vilket är det officiellt genererade låt-ID:t; valfritt stöds även `callback_url` för asynkron callback.

Här anger vi `audio_id` som `4e43116a-bf09-472c-8e1c-655eabf02682`.

```python
import requests

url = "https://api.acedata.cloud/suno/wav"

headers = {
    "accept": "application/json",
    "authorization": "Bearer aa287fa4cc54401087a9fab3f99630af",
    "content-type": "application/json"
}

payload = {
    "audio_id": "4e43116a-bf09-472c-8e1c-655eabf02682"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Resultatet är följande:

```json
{
  "success": true,
  "task_id": "6a5a2099-d6d3-4930-9709-a30ac5dc7de5",
  "trace_id": "3fa70e81-6bb7-4ca8-b718-dd16a4eda7e8",
  "data": [
    {
      "file_url": "https://platform.cdn.acedata.cloud/suno/6a5a2099-d6d3-4930-9709-a30ac5dc7de5.wav"
    }
  ]
}
```

Som vi kan se är `file_url` i `data` fältet länken till musikfilen i wav-format, vilket är en publikt tillgänglig CDN-adress.

> **Om persistens för WAV-länken**
>
> WAV-filerna på upstream Suno CDN (`https://cdn1.suno.ai/{audio_id}.wav`) sparas endast i några dagar och tas sedan bort, vilket leder till 403-fel vid åtkomst.
> För att undvika att länken upphör att gälla kopierar detta API automatiskt upstream WAV-filen till vår egen CDN (`https://platform.cdn.acedata.cloud/suno/{task_id}.wav`) innan den returneras. Den returnerade `file_url` är alltså en stabil adress som inte påverkas av att upstream CDN:en upphör.
> Vid kopieringsfel (mycket ovanligt) återgår systemet till den ursprungliga upstream URL:en, vilket är samma beteende som tidigare.
