Midjourney Tasks API:s huvudfunktion är att genom att ange det uppgift-ID som genererats av Midjourney Imagine API eller Midjourney Describe API, kunna fråga om statusen för den uppgiften.

Detta dokument kommer att ge en detaljerad beskrivning av Midjourney Tasks API:s integrationsanvisningar, för att hjälpa dig att enkelt integrera och fullt utnyttja denna APIs kraftfulla funktioner. Genom Midjourney Tasks API kan du enkelt fråga om statusen för uppgifter från Midjourney Imagine API eller Midjourney Describe API.

## Ansökningsprocess

För att använda Midjourney Imagine API, börja med att gå till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API-token, som du ska spara.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Om du inte har loggat in eller registrerat dig, kommer du automatiskt att omdirigeras till inloggningssidan för att registrera dig och logga in, och efter att ha slutfört detta kommer du automatiskt att återvända till den aktuella sidan.

**En API-token räcker för att anropa alla tjänster på plattformen, du behöver inte ansöka separat för varje tjänst.** Första ansökan ger en gratis kvot för att prova; när kvoten är slut kan du ladda på allmän balans i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Midjourney Imagine API →](https://platform.acedata.cloud/documents/midjourney-imagine)

## Begärningsexempel

Midjourney Tasks API kan användas för att fråga om resultaten från både Midjourney Imagine API och Midjourney Describe API. För information om hur man använder Midjourney Imagine API, se dokumentationen [Midjourney Imagine API](https://platform.acedata.cloud/documents/midjourney-imagine-integration). För information om hur man använder Midjourney Describe, se [Midjourney Describe API](https://platform.acedata.cloud/documents/midjourney-describe-integration).

Vi tar ett exempel med ett uppgift-ID som returnerats av Midjourney Imagine API-tjänsten, för att demonstrera hur man använder denna API. Anta att vi har ett uppgift-ID: 7489df4c-ef03-4de0-b598-e9a590793434, och vi visar hur man gör detta genom att skicka in ett uppgift-ID.

### Ställ in begärningshuvuden och begärningskropp

**Begärningshuvuden** inkluderar:

- `accept`: anger att du tar emot svar i JSON-format, här anges som `application/json`.
- `authorization`: nyckeln för att anropa API:t, som kan väljas direkt efter ansökan.

**Begärningskropp** inkluderar:

- `id`: det uppladdade uppgift-ID:t.
- `ids`: array av uppgift-ID:n för batchfrågor.
- `action`: åtgärden för uppgiften, stöder `retrieve` (enskild fråga) och `retrieve_batch` (batch).

Inställningarna visas som på bilden nedan:

Några kodexempel är som följer:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/midjourney/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "7489df4c-ef03-4de0-b598-e9a590793434",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/midjourney/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "7489df4c-ef03-4de0-b598-e9a590793434",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Det returnerade resultatet innehåller flera fält, där `request`-fältet är begärningsinformationen vid uppgiftsstart, medan `response`-fältet är svaret som returneras efter att uppgiften har slutförts. Fälten beskrivs nedan.

- `id`, ID:t för den bildgenererande uppgiften, används för att unikt identifiera denna bildgenereringsuppgift.
- `type`, om `type = imagine` representerar det resultatet från Midjourney Imagine API, om `type = describe` representerar det resultatet från Midjourney Describe API.
- `job_id`, ID:t för den bildfrågeuppgift som genererades, används för att unikt identifiera denna bildfrågeuppgift.

- `request`, begärningsinformationen för bilduppgiften.
- `response`, svarsinformationen för bilduppgiften.
- `created_at`, tidpunkten då uppgiften skapades, Unix-tidsstämpel (sekunder, flyttal).
- `started_at`, tidpunkten då uppgiften började utföras, Unix-tidsstämpel (sekunder, flyttal).
- `finished_at`, tidpunkten då uppgiften slutfördes, Unix-tidsstämpel (sekunder, flyttal). Detta fält returneras inte om uppgiften inte är slutförd.
- `elapsed`, den tid som uppgiften tog att utföra, i sekunder (flyttal, med 3 decimaler). Detta fält returneras inte om uppgiften inte är slutförd.

## Felhantering

Vid anrop av API:et, om ett fel uppstår, kommer API:et att returnera motsvarande felkod och information. Till exempel:

- `400 token_mismatched`：Felaktig begäran, möjligtvis på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`：Felaktig begäran, möjligtvis på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`：Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`：För många begärningar, du har överskridit hastighetsgränsen.
- `500 api_error`：Intern serverfel, något gick fel på servern.
