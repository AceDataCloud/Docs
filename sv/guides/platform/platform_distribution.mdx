AceDataCloud har för närvarande ingen aggregerad `/api/v1/distribution/`-slutpunkt. Rekommendationsbelöningsdata består av fyra grupper av gränssnitt: status, historik, nivåer och inlösen; anropa de resurser som behövs och undvik att förlita dig på ett sammanfattande svar som inte finns.

## Förberedelser

1. Skapa och spara en Account Token i [Account Token-konsolen](https://platform.acedata.cloud/console/platform-tokens).
2. Använd `GET /api/v1/platform-tokens/me/` för att hämta den aktuella kontots UUID.

```shell
export PLATFORM_TOKEN='你的账户令牌'
export USER_ID='你的账户 UUID'
```

## Tillgängliga gränssnitt

| Metod     | URL                                                  | Användning                                   |
| ------ | ---------------------------------------------------- | ------------------------------------ |
| `GET`  | `/api/v1/distribution-statuses/?user_id=${USER_ID}`  | Aktuellt kontos ackumulerade rekommendationsbelopp, belöningar och nivå                     |
| `POST` | `/api/v1/distribution-statuses/initialize/`          | Första initialisering eller uppdatering av aktuellt kontos nivå; skriver data                 |
| `GET`  | `/api/v1/distribution-histories/?user_id=${USER_ID}` | Transaktionshistorik för rekommendationsbelöningar                               |
| `GET`  | `/api/v1/distribution-levels/`                       | Nivå- och proportionsregler                              |
| `GET`  | `/api/v1/distribution-redemptions/preview/`          | Förhandsgranska för närvarande inlösningsbara belöningar; valfri `amount`                |
| `GET`  | `/api/v1/distribution-redemptions/`                  | Slutförda inlösenposter                             |
| `POST` | `/api/v1/distribution-redemptions/redeem/`           | Bekräfta inlösen; kräver `idempotency_key` och skapar en oåterkallelig inlösen |

## Exempel på skrivskyddade begäranden

```shell
curl --get 'https://platform.acedata.cloud/api/v1/distribution-statuses/' \
  --data-urlencode "user_id=${USER_ID}" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"

curl --get 'https://platform.acedata.cloud/api/v1/distribution-histories/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"

curl 'https://platform.acedata.cloud/api/v1/distribution-levels/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"

curl 'https://platform.acedata.cloud/api/v1/distribution-redemptions/preview/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Svarformatet som verifierats online är:

- status, history, level, redemption list: `{count, items}`;
- redemption preview: ett enskilt objekt som innehåller fält som `eligible`, `reason`, `reward_amount`, `credit_amount`, `credits_per_usd`, `currency`, `package`, `global_application` och andra.

Statusposter och historikposter kan utökas enligt rekommendationsriskkontroll, kompensation och belöningsregler; klienten bör läsa efter behov och inte förlita sig på aggregerade fält som `referral_url`, `recent_orders`, `withdrawable_balance` och andra som nämns i äldre dokumentation men inte returneras av gränssnittet.

> Initialisering och inlösen är båda skrivoperationer. Produktionsskript bör först anropa skrivskyddade gränssnitt för att kontrollera status och spara en unik `idempotency_key` för inlösenbegäranden; försök inte automatiskt igen med inlösen vars resultat är okänt.

## Order med prispåslag för underwebbplatser

För order från underwebbplatser som omfattas av de nya reglerna beräknas rekommendationsprovisionen utifrån baspriset efter rabatt, medan hela mellanskillnaden från prispåslaget efter rabatt tillfaller webbplatsägaren vid tidpunkten då ordern skapades. De två delarna av belöningen för samma förmånstagare slås samman i den ursprungliga distributionsposten, och distributionshistoriken visar sammansättningen; order utan prispåslag och historiska order behåller de ursprungliga reglerna.

Till exempel, om baspriset är 100 och priset efter påslag är 120, webbplatsägaren samtidigt är den enda rekommendatören och andelen är 10 %, blir belöningen för denna order 10 + 20 = 30. Om webbplatsägaren och rekommendatören inte är samma person får de var sin motsvarande belöning.

Kontantavräkning hanteras fortfarande manuellt av plattformen. Plattformen gör en manuell utbetalning efter att ha dragit av det tillgängliga beloppet för denna gång från det ursprungliga belöningskontot; delar som redan har lösts in till poäng kan inte betalas ut kontant igen. Om ett belöningsunderskott uppstår efter en återbetalning dras det först av från efterföljande belöningar.
