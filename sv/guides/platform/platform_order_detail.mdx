Fråga efter en order via order-ID. Denna endpoint stöder två läslägen: anonym åtkomst returnerar endast de minimala fält som krävs för betalningssidan; när orderägaren använder en Account Token returneras fullständiga detaljer.

## API-översikt

| Post   | Innehåll                                                        |
| --- | --------------------------------------------------------- |
| Metod  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| Autentisering  | Valfritt; anonym är minimal projektion, autentiserad ägare är fullständig projektion                                    |

`/orders/{id}` och `/orders/{id}/` är båda tillgängliga för närvarande. Order-ID:t är en del av betalningslänken och ska behandlas som en känslig, ogenomskinlig identifierare och inte spridas offentligt.

## Anonym förfrågan

Betalningssidan kan läsa direkt när inloggningssessionen har förlorats:

```shell
export ORDER_ID='你的订单 ID'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

Det anonyma svaret innehåller endast `id`, `description`, `price`, `state`, `pay_way`, `pay_url`, `expired_at`, `created_at`. Det returnerar inte konto, Application, Package, interna betalningsidentifierare eller metadata.

## Autentiserad förfrågan

```shell
export PLATFORM_TOKEN='你的账户令牌'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Orderägaren får fullständiga Order-detaljer, inklusive `application` / `applications`, `package` / `packages`, `bank_details`, `invoice_automation` och modellfält. Om användaren är autentiserad men inte är orderägaren returneras `403`; superadministratörer är undantagna.

## Viktiga fält

| Fält            | Beskrivning                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`, `Paid`, `Finished`, `Expired`, `Failed` eller `Refunded` |
| `pay_way`     | Orderns aktuella betalningsmetod; fältnamnet är inte `payment_method`                             |
| `pay_url`     | Adress till den värdbaserade betalningssidan eller QR-koden, kan vara tom                                           |
| `price`       | Orderns slutliga belopp att betala; den aktuella ordermodellen tillhandahåller inte fältet `final_price`                         |
| `amount`      | Antal paketkrediter; synligt endast i autentiserade fullständiga svar                                            |
| `finished_at` | Tidpunkt då ordern slutfördes; fältnamnet är inte `paid_at`                                      |

Fullständiga svar kan innehålla ytterligare fält beroende på betalningsmetod. Klienter bör läsa dem vid behov och alltid undvika att logga känsliga metadata i fullständiga svar.

## Felhantering

- `404`: Order-ID:t finns inte.
- `403`: Inloggad men inte orderägaren.
- Anonyma begäranden returnerar inte `401`; de får endast den minimala offentliga projektionen.

## Kreditfaktura och ny ansökan

Via `GET /api/v1/orders/{order_id}/invoice/` kan orderns aktuella faktura läsas. Efter att en automatisk kreditfaktura har skickats in förblir fakturan `Issued`, och `red_state` anger kreditfakturans förlopp; en lyckad inlämning innebär inte att kreditfakturan är slutförd. Under väntan på bekräftelse, utfärdande av kreditfaktura eller arkivering kan ordern inte ansöka om faktura igen.

När administratören ansöker om kreditfaktura på grund av felaktig faktureringsinformation, såsom fakturahuvud eller skattenummer, är orsaken till kreditfakturan ”felaktig fakturering”; automatiska kreditfakturor som utlöses av orderåterbetalningar använder fortfarande ”tjänsten avbruten”.

Efter att kreditfakturan har utfärdats och arkiverats framgångsrikt blir den ursprungliga fakturan `Voided`, och först då kan ordern ansöka igen. Den ursprungliga fakturan kan ses i fakturahistoriken. Om kreditfakturan misslyckas eller resultatet inväntar kontroll hanteras det genom ekonomigranskning, och faktureringsbegränsningen för ordern hävs inte i förväg. Manuellt utfärdade fakturor måste först annulleras eller krediteras i skatte- eller faktureringssystemet och därefter bekräftas av ekonomiavdelningen på plattformen.
