Returnerar sidvis de Application som kontot äger eller har beviljats behörighet att använda, inklusive saldo, status, tjänstesammanfattning och associerade autentiseringsuppgifter. Lämpligt för batchövervakning av saldo, sökning efter Application ID och åtkomst till hantering av autentiseringsuppgifter.

## Förberedelser

1. Logga in på [AceDataCloud-plattformen](https://platform.acedata.cloud).
2. Skapa en kontotoken i [Account Token-konsolen](https://platform.acedata.cloud/console/platform-tokens).
3. Vanliga användare använder `user_id=me`; du kan även hämta din egen UUID från `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='din kontotoken'
```

## API-översikt

| Post   | Innehåll                                                    |
| --- | ----------------------------------------------------- |
| Metod  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Autentisering  | Account Token, OAuth token kräver `applications:read`       |
| Sidindelning  | `count` + `items`                                     |

Vanliga användare bör skicka `user_id=me`. Om det inte skickas begränsas frågan inte först efter konto, och sidindelningen kan returnera `403` när objekt utan behörighet påträffas; om administratörer inte skickar det kan de se hela tabellen.

## Frågeparametrar

| Parameter            | Typ          | Obligatorisk     | Beskrivning                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Obligatorisk för vanliga användare | Frågesubjekt; stöder upprepade parametrar                                         |
| `affiliation` | string      | Nej      | `owner` (standard) eller `granted`; båda kan skickas upprepade gånger för union, gäller endast när `user_id` finns |
| `service_id`  | UUID        | Nej      | Filtrera efter tjänst; stöder upprepade parametrar                                        |
| `scope`       | string      | Nej      | `Individual` eller `Global`; stöder upprepade parametrar                      |
| `type`        | string      | Nej      | `Usage` eller `Period`; stöder upprepade parametrar                           |
| `limit`       | integer     | Nej      | Antal poster per sida, maximalt 100                                         |
| `offset`      | integer     | Nej      | Offset för sidindelning                                               |
| `ordering`    | string      | Nej      | Stöder endast `created_at` eller `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` och `tag` är för närvarande inte filtreringsparametrar på serversidan. Saldoalarm bör hämta listan och sedan avgöra på klientsidan utifrån varje Applications `remaining_amount`, `service.unit` och verksamhetströskel.

## Begäransexempel

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Visa samtidigt de Application du äger och de som andra har auktoriserat dig för:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Svarsbeskrivning

Svaret är `{count, items}`. Varje post innehåller fälten i Application-modellen och lägger till:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: sammanfattning av autentiseringsuppgifter som den aktuella anroparen har behörighet att se;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`, `allow_overdraft`;
- det verkliga värdet för `scope` är `Individual` eller `Global`;
- det verkliga värdet för `type` är `Usage` eller `Period`.

`allow_overdraft` är ett skrivskyddat booleskt fält som styrs av administratören och är som standard `false`. För användningsbaserade (`Usage`) applikationer med aktiverad övertrassering hindrar inte otillräckligt saldo anrop, utan avgifter dras fortfarande enligt faktisk användning; negativt saldo innebär kredit som väntar på avräkning. Inaktivering, utgång och begränsningar för API-autentiseringsuppgifter gäller fortfarande.

`remaining_amount` kan vara tomt; klienten måste först kontrollera om värdet är tomt och sedan göra numeriska jämförelser. Kvotenheten bestäms av `service.unit`.
