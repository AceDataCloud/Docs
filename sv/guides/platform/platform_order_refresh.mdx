---
title: "Uppdatera orderstatus på AceDataCloud-plattformen"
description: "Platform API guide - Ace Data Cloud"
---

Fråga aktivt efter den senaste statusen för betalningsmetoden som motsvarar ordern och synkronisera den till plattformen. Denna begäran kan komma åt betaltjänsten och ändra orderstatusen, använd den endast när återanropet är fördröjt eller om omedelbar bekräftelse krävs.

## Förberedelser

- Använd [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Hämta ditt order-ID från [orderlistan](https://platform.acedata.cloud/documents/platform-order-list).

```shell
export PLATFORM_TOKEN='din kontotoken'
export ORDER_ID='ditt order-ID'
```

## API-översikt

| Objekt    | Innehåll                                                                 |
| ---- | ------------------------------------------------------------------ |
| Metod   | `POST`                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/refresh/` |
| Auktorisering   | Orderägare eller superadministratör                                                        |
| Body | Vanligtvis tom; PayPal-återanropsscenarier kan kräva `payer_id` / `PayerID`                         |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/refresh/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Vid lyckat resultat returneras det fullständiga uppdaterade Order-objektet. Använd `state` för att avgöra resultatet och `finished_at` som slutförandetid; den aktuella modellen har inget fält `paid_at`. Statusvärden inkluderar `Pending`, `Paid`, `Finished`, `Expired`, `Failed`, `Refunded`.

Betalningsdeadline ändrar endast order som fortfarande är i `Pending` till `Expired`. Återbetalade `Refunded`-order behåller återbetald status även vid uppdatering eller när ett fördröjt betalningsåteranrop tas emot.

## Rekommendationer för återförsök

- För normala betalningar ska du i första hand förlita dig på plattformens återanrop; initiera endast refresh när statusen inte uppdateras på länge.
- Använd inte fast högfrekvent polling. Exponentiell backoff rekommenderas, och stoppa när ett tydligt slutstatus har uppnåtts.
- `401` betyder att token är ogiltig; `403` betyder att du inte är orderägaren; `404` betyder att ordern inte finns.
- Om frågan till betaltjänsten misslyckas, behåll order-ID och trace-ID och försök igen senare; skapa inte dubblettorder som ersättning för statusbekräftelse.
