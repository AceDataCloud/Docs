TypeScript är ett av de mest rekommenderade sätten att integrera Ace Data Cloud X402. Det officiella SDK:t ansvarar för vanliga API-anrop, uppgiftspollning, felhantering och automatiska återförsök; `@acedatacloud/x402-client` ansvarar för att signera begärandehuvudet `PAYMENT-SIGNATURE` när `402 Payment Required` påträffas.

Källkod och paketadresser:

- SDK-repository: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- X402 Client-repository: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm SDK: [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)
- npm X402 Client: [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client)

## Installera beroenden

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client
```

Om Base används krävs EVM-signeringsfunktionalitet:

```bash
npm install ethers
```

Om Solana används krävs en Solana wallet adapter eller `@solana/web3.js`:

```bash
npm install @solana/web3.js
```

Installations- och importkontrollutdata för ett rent npm-projekt:

```text
imports_ok true true true true true
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4
```

Förklaring av resultaten:

- Både `@acedatacloud/sdk` och `@acedatacloud/x402-client` kan installeras från npm och importeras av Node.js.
- `ethers` används för EVM typed data-signering, och `@solana/web3.js` används för konstruktion av Solana-transaktioner.

## Base-exempel

I webbläsaren kan `window.ethereum` användas direkt. I Node.js kan `ethers.Wallet` användas för att omsluta en provider i EIP-1193-stil.

```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});

console.log(result.choices[0].message.content);
```

## Exempel med webbläsarplånbok

När MetaMask, Coinbase Wallet eller WalletConnect används i frontend-applikationer skickas vanligtvis en EIP-1193-provider direkt:

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const [address] = await window.ethereum.request({ method: 'eth_requestAccounts' });

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider: window.ethereum,
    evmAddress: address
  })
});

const image = await client.images.generate({
  provider: 'nano-banana',
  prompt: 'a yellow banana on a white background'
});
```

Webbläsarplånboken visar en bekräftelse för signering. Det användaren signerar är inte ett godtyckligt meddelande, utan API:ets returnerade betalningskrav: mottagaradress, USDC-kontrakt, belopp, giltighetstid och nonce ingår alla i signaturen.

## Solana-exempel

Solana använder SPL USDC `TransferChecked`. Den överlämnade wallet adaptern måste exponera `publicKey` och `signAndSendTransaction`.

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'solana',
    solanaWallet: phantomWallet
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});
```

Solana-flödet stöder för närvarande endast `exact`, inte `upto`. Om API:et returnerar flera `accepts` väljer handlern posten med `network = 'solana'`.

Solana-flödet har verifierats på samma offentliga API där paid retry kan returnera HTTP 200 och `ADC_SOLANA_E2E_OK`. Offentliga RPC-frågor kan vara hastighetsbegränsade, därför anges ingen Solana tx hash i denna artikel; när avstämning på kedjan krävs, använd din egen Solana RPC eller bekräfta via konsolposter.

## Välj `exact` eller `upto`

Den nuvarande TypeScript-handlern väljer det första payment requirement för ett matchande nätverk som returneras av servern. Ace Data Clouds API placerar vanligtvis `exact` för samma nätverk före `upto`, så om du uttryckligen vill använda efterföljande mätning måste du ange `preferScheme: 'upto'`.

Exempel:

```ts
const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address,
    preferScheme: 'upto'
  })
});
```

Om servern inte returnerar ett `upto` requirement för det nätverket återgår handlern automatiskt till det första tillgängliga requirement för nätverket, vanligtvis `exact`.

`upto` kräver en engångsauktorisering för Permit2. `upto` erbjuds för närvarande endast på Base, så det behöver bara göras en auktorisering för Base USDC:

```bash
npx tsx scripts/approve-permit2.ts --network base
```

Base `upto` har slutfört offentlig API-verifiering: HTTP 402 -> HTTP 200, och den efterföljande settlement tx är `0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036`. Fullständig utdata finns i beskrivningen av faktureringsschemat.

## Vad SDK:t gör

Transporten i `@acedatacloud/sdk` kör en payment handler en gång när den tar emot 402:

```ts
type PaymentHandler = (ctx: {
  url: string;
  method: string;
  body?: unknown;
  accepts: PaymentRequirement[];
}) => Promise<{ headers: Record<string, string> }>;
```

Handlern som returneras av `@acedatacloud/x402-client` kommer att:

1. Välja payment requirement för målnätverket från `ctx.accepts`.
2. Konstruera en EVM EIP-712-signatur eller en Solana transfer transaction baserat på nätverket.
3. Serialisera envelopen till Base64.
4. Returnera `{ headers: { 'PAYMENT-SIGNATURE': '<base64>' } }`.
5. SDK:t gör automatiskt ett nytt försök med den ursprungliga begärandetexten.

Detta innebär att affärskoden bara behöver skrivas som vanliga SDK-anrop, utan att manuellt hantera 402-återförsök.
