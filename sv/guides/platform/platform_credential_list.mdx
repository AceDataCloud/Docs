---
title: "Hämta listan över API-autentiseringsuppgifter för AceDataCloud-plattformen"
description: "Platform API guide - Ace Data Cloud"
---

Lista affärs-API-autentiseringsuppgifter med paginering. Svaret innehåller för närvarande känsliga fält för Token- eller Identity-autentiseringsuppgifter och måste endast hanteras på serversidan; det är förbjudet att skriva dem till loggar, analysplattformar, frontend-lagring eller offentliga kodarkiv.

## Förberedelser

Skapa en [Account Token](https://platform.acedata.cloud/documents/platform-token) och hämta UUID för det aktuella kontot via `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='din kontotoken'
export USER_ID='ditt konto-UUID'
```

## API-översikt

| Objekt   | Innehåll                                                   |
| --- | ---------------------------------------------------- |
| Metod  | `GET`                                                |
| URL | `https://platform.acedata.cloud/api/v1/credentials/` |
| Autentisering  | Account Token, OAuth-token kräver `credentials:read`       |
| Paginering  | `count` + `items`                                    |

Vanliga användare bör ange sitt eget `user_id` eller ett auktoriserat `application_id`, annars kan `403` returneras när pagineringen stöter på objekt utan behörighet.

## Frågeparametrar

| Parameter                 | Typ      | Obligatorisk  | Beskrivning                             |
| ------------------ | ------- | --- | ------------------------------ |
| `user_id`          | string  | Beroende på scenario | Ägare av autentiseringsuppgifterna; upprepade parametrar stöds                   |
| `application_id`   | UUID    | Nej   | Filtrera efter Application; upprepade parametrar stöds        |
| `host`             | string  | Nej   | Exakt filtrering efter host; upprepade parametrar stöds             |
| `name`             | string  | Nej   | Exakt filtrering efter namn; upprepade parametrar stöds                 |
| `granted`          | boolean | Nej   | `true` är autentiseringsuppgifter beviljade till andra, `false` är autentiseringsuppgifter för eget bruk |
| `limit` / `offset` | integer | Nej   | Paginering                             |
| `ordering`         | string  | Nej   | `created_at` eller `-created_at`   |

`service_id`, `disabled` och `expired` är för närvarande inte filterparametrar.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/credentials/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Svarsbeskrivning

Det verifierade produktionssvaret är `{count, items}`. Varje post innehåller `id`, `application_id`, `application`, `user_id`, `creator_id`, `name`, `type`, `limited_amount`, `used_amount`, `expired_at`, `allowed_api_ids`, `host`, `granted`, `granted_to_user_id`, `tags`, `metadata` och tidsfält, och returnerar `token` eller `username/password` beroende på typ.

> Det aktuella listsvar returnerar fullständiga känsliga värden. Visa dem inte i webbläsarkonsolen eller insamlingssystem, och förlita dig inte på att återställa klartext via listan; klienter bör vara kompatibla med framtida maskeringsstrategier.
