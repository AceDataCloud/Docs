Fråga efter den aktuella kontots användningsposter under tjänster av typen Proxy. För vanliga API-anrop, använd [API-anropsposter](https://platform.acedata.cloud/documents/platform-usage-list). Om tjänsttypen är osäker kan du först kontrollera `type` i [tjänstdetaljer](https://platform.acedata.cloud/documents/platform-service-detail).

## Förberedelser

1. Logga in på [AceDataCloud-plattformen](https://platform.acedata.cloud).
2. Skapa en kontotoken i [Account Token-konsolen](https://platform.acedata.cloud/console/platform-tokens), och spara den omedelbart i en lösenordshanterare eller Secret Manager.
3. Öppna [profilsidan](https://auth.acedata.cloud/user/profile), kopiera UUID för det aktuella kontot och spara det som `USER_ID`. `user_id` i svaret när kontotoken skapas kan också användas.
4. Hämta `application_id` för tjänster av typen Proxy från [listan över tjänsteansökningar](https://platform.acedata.cloud/documents/platform-application-list). Om filtrering efter Proxy-slutpunkt krävs, hämta `proxy_id` från [Proxy-listan under tjänsten](https://platform.acedata.cloud/documents/platform-service-proxies).

Fullständig tokeninformation finns i [Hantera kontotoken](https://platform.acedata.cloud/documents/platform-token). Detta gränssnitt använder Account Token, inte Credential som används för att anropa affärs-API:er.

```shell
export PLATFORM_TOKEN='din kontotoken'
export USER_ID='ditt konto-UUID'
export APPLICATION_ID='ditt Proxy Application ID'
```

## API-översikt

| Punkt     | Innehåll                                                     |
| ----- | ------------------------------------------------------ |
| Metod    | `GET`                                                  |
| URL   | `https://platform.acedata.cloud/api/v1/usage/proxies/` |
| Autentisering    | `Authorization: Bearer ${PLATFORM_TOKEN}`              |
| Scope | `usage:read`                                           |
| Sidindelning    | `count` + `items`, 10 poster per sida som standard                            |

När Application-ägaren frågar med `application_id` synkroniserar servern först tillgängliga poster för denna Application och returnerar sedan listan. Därför kan svarstiden vara längre än för vanliga API usage-listor. Auktoriserade användare kan läsa befintliga synliga poster, men utlöser inte synkronisering på ägarsidan.

## Frågeparametrar

| Parameter               | Typ      | Obligatorisk     | Standard            | Beskrivning                            |
| ---------------- | ------- | ------ | ------------- | ----------------------------- |
| `user_id`        | UUID    | Obligatorisk för vanliga användare | —             | UUID för aktuellt konto; att skicka ett annat konto returnerar `403`     |
| `application_id` | UUID    | Rekommenderas     | —             | Filtrera efter Proxy Application; upprepade parametrar stöds |
| `proxy_id`       | UUID    | Nej      | —             | Filtrera efter Proxy-slutpunkt; upprepade parametrar stöds           |
| `limit`          | integer | Nej      | 10            | Antal poster per sida, högst 100                   |
| `offset`         | integer | Nej      | 0             | Sidförskjutning                         |
| `ordering`       | string  | Nej      | `-created_at` | Fallande ordning efter skapandetid                       |

Det aktuella gränssnittet stöder inte direkt filtrering efter modell, HTTP-statuskod, Credential eller tidsintervall, och stöder inte heller parametern `perspective` från API usage-gränssnittet. Lägg inte till dessa parametrar som inte stöds i begäran och anta att de har trätt i kraft.

## Begäransexempel

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/proxies/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'limit=100' \
  --data-urlencode 'ordering=-created_at' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Python-exempel för sidindelning:

```python
import os
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/usage/proxies/",
    headers={"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    params={
        "user_id": os.environ["USER_ID"],
        "application_id": os.environ["APPLICATION_ID"],
        "limit": 100,
    },
    timeout=60,
)
response.raise_for_status()
data = response.json()

for usage in data["items"]:
    print(usage["created_at"], usage["deducted_amount"], usage["remaining_amount"])
```

## Nyckelfält

| Fält                       | Beskrivning                       |
| ------------------------ | ------------------------ |
| `user_id`                | Kontot som står för denna debitering                |
| `actor_user_id`          | Den faktiska anroparen; äldre poster kan vara tomma            |
| `application_id`         | Proxy Application som genererade denna post |
| `proxy_id`               | Motsvarande Proxy-slutpunkt             |
| `credential_id`          | ID för associerad autentiseringsuppgift; äldre poster kan vara tomma          |
| `used_amount`            | Användning i den ursprungliga posten; kan vara tom             |
| `deducted_amount`        | Slutligt faktiskt avdragen kvot                 |
| `remaining_amount`       | Application återstående kvot efter debitering    |
| `metadata`               | Offentliga metadata; kan vara tomma               |
| `service` / `credential` | Sammanfattning av associerade objekt för enkel visning; kan vara tom när det associerade objektet inte finns |

Kvotenheten bestäms av `service.unit` för motsvarande Application.

## Felhantering

| HTTP | Betydelse         | Hantering                                        |
| ---- | ---------- | ------------------------------------------- |
| 401  | Kontotoken saknas eller är ogiltig  | Kontrollera Account Token, använd inte av misstag affärs-Credential          |
| 403  | Saknar behörighet att visa posterna i begäran | Använd Application som tillhör det aktuella kontot, ta bort obehörig `user_id`      |
| 5xx  | Synkronisering eller fråga misslyckades tillfälligt  | Behåll filtreringsvillkoren och försök igen med backoff; vid fortsatta fel, ange Application ID och tid till supportpersonalen |
