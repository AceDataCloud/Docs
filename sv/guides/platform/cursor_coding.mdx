Cursor erbjuder för närvarande OpenAI API-nyckel och **Override OpenAI Base URL** inställningar, vilket möjliggör anslutning till OpenAI-kompatibla tjänster. Denna funktionalitet finns, men olika versioner hanterar `/chat/completions`, `/responses`, modellista samt Agent/Composer och andra lägen inte helt konsekvent.

Kompatibiliteten mellan olika Cursor-versioner, operativsystem och begärningslägen kan variera. Vänligen följ konfigurationen på denna sida för att slutföra den faktiska lägeskontrollen, och dra inte slutsatser om att alla funktioner är tillgängliga baserat på en enstaka lyckad chatt.

## Vad Cursor officiellt garanterar för BYOK

Enligt [Cursor officiella Bring your own API key-dokumentation](https://cursor.com/help/models-and-usage/api-keys):

- Stöd för OpenAI, Anthropic, Google, Azure OpenAI och AWS Bedrock autentiseringar;
- Anpassad API-nyckel används endast för chattmodeller, Tab completion fortsätter att använda Cursor inbyggda modeller;
- API-nyckeln lagras inte på Cursor-servern, men skickas med varje begäran till Cursor-backend för slutlig promptbyggnad;
- När du använder din egen nyckel gäller inte Cursor's Zero Data Retention-policy, databehandling följer den valda leverantörens policy.

## Konfiguration

1. Öppna Cursor-inställningar → Modeller.
2. Fyll i din Ace Data Cloud API-token i OpenAI API-nyckeln.
3. Aktivera **Override OpenAI Base URL**, fyll i `https://api.acedata.cloud/v1`.
4. Välj eller lägg till en exakt modell-ID som är kompatibel med den aktuella Cursor-protokollet.
5. Skicka först `Reply only OK`, och testa sedan Ask/Edit/Agent och andra lägen som du faktiskt använder.

## Nuvarande gränser

- Anpassad API-nyckel används endast för chattmodeller, Tab completion fortsätter att använda Cursor inbyggda modeller.
- Cursor kan fortfarande slutföra den slutliga promptbyggnaden på serversidan; vänligen utvärdera datapathen i kombination med den officiella sekretessbeskrivningen.
- Base URL Override kan endast täcka vissa begärningar, eller på grund av versionsändringar växla mellan Chat Completions/Responses.
- Man bör inte enbart basera på en lyckad chattbegäran för att påstå att Agent, Auto, Composer eller bakgrundsuppgifter är anslutna.

## Fullständig kompatibilitetskontroll

För långsiktig användning i produktionsarbetsflöden, slutför följande kontroller:

1. Fast Cursor-version och operativsystem;
2. Genomför verklig klient-smoke för den versionen och dokumentera slutlig begärningsprotokoll och väg;
3. Exakt modellens Chat Completions-begäran lyckas;
4. Verktygsanrop och Agent-begärningar går verkligen genom mål-endpoint;
5. Användning och debitering kan verifieras;
6. Tydligt dokumentera om begäran passerade Cursor-servern och motsvarande sekretessbegränsningar.

Klientuppgraderingar bör åtföljas av dessa kontroller för att bekräfta att begärningsprotokoll, verktygsanrop och datapath inte har förändrats.
