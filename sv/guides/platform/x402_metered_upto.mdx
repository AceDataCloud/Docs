title: "X402 `exact` och `upto` debiteringsscheman"

Ace Data Cloud X402 använder för närvarande två typer av scheme: `exact` och `upto`. De löser olika debiteringsproblem.

## `exact`

`exact` innebär att priset för denna begäran kan fastställas innan den går in i mål-API:t. Beloppet som klienten signerar är det slutliga debiteringsbeloppet.

Lämpligt för:

- Bildgenerering med fast pris;
- Skapande av videouppgifter med fast pris;
- Sök- eller verktygs-API:er med fast pris;
- Orderbetalning.

EVM `exact` använder USDC EIP-3009 `TransferWithAuthorization`:

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "exact",
    "network": "eip155:8453"
  },
  "payload": {
    "authorization": {
      "from": "0x...",
      "to": "0x...",
      "value": "95215",
      "validAfter": "1780237345",
      "validBefore": "1780240945",
      "nonce": "0x..."
    },
    "signature": "0x..."
  }
}
```

Facilitator validerar signaturen och beloppet i `/verify`-fasen och skickar denna auktorisering till kedjan i `/settle`-fasen.

## `upto`

`upto` innebär att klienten auktoriserar en maximal gräns, och Ace Data Cloud avräknar enligt faktisk användning efter att begäran har slutförts; den faktiska debiteringen får inte överstiga gränsen.

Lämpligt för:

- Chattkomplettering: slutpriset beror på prompt tokens och completion tokens;
- Strömmande svar: den verkliga utdata-längden är känd först när den avslutas;
- Framtida API:er med efterhandsmätning.

`upto` använder Permit2 `PermitWitnessTransferFrom`. Det klienten signerar är inte en fast överföring, utan en gränsauktorisering med witness:

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "upto",
    "network": "eip155:8453"
  },
  "payload": {
    "permit2Authorization": {
      "from": "0x...",
      "spender": "0x4020A4f3b7b90ccA423B9fabCc0CE57C6C240002",
      "nonce": "123456789",
      "deadline": "1780240945",
      "permitted": {
        "token": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
        "amount": "95215"
      },
      "witness": {
        "to": "0x...",
        "facilitator": "0x...",
        "validAfter": "1780237345"
      }
    },
    "signature": "0x..."
  }
}
```

`permitted.amount` är gränsen, och är inte nödvändigtvis den slutliga debiteringen. Gateway konverterar den faktiska användningen till `amount` och skickar den till Facilitator i `/record`-fasen. Facilitator tillåter endast avräkning när `amount &lt;= permitted.amount`.

Programkörningsresultatet för Base `upto`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
signed ceiling 95215 atomic USDC
transfer value 3 atomic USDC
```

Förklaring:

- Auktoriseringsgränsen som returneras i 402 är `95215` atomic USDC, och klienten signerar enligt denna gräns.
- Efter det faktiska modellsvar avräknas endast `3` atomic USDC, och kedjetransaktionen kan redan kontrolleras på BaseScan.
- Detta resultat visar den viktigaste skillnaden för `upto`: det signerade beloppet är en gräns, och settlement på kedjan kan vara mindre än gränsen.
- Om den faktiska användningen överstiger gränsen ska Facilitator neka settlement, och klienten behöver auktorisera igen enligt en högre gräns.

`upto` erbjuds för närvarande endast på Base. När efterhandsmätning krävs, använd Base.

## Varför Permit2 approve behövs

`upto` hämtar slutligen USDC från betalningsplånboken via Permit2 genom x402 proxy. Före första användningen behöver betalningsplånboken ge Permit2 en ERC-20 allowance en gång.

Python CLI:

```bash
pip install 'acedatacloud-x402[cli]'
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Programmässigt:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Efter att auktoriseringen har slutförts behöver varje begäran fortfarande signera ett nytt `upto` envelope, eftersom nonce, deadline, witness och beloppsgräns är olika.

## Avräkning med nollbelopp

`upto` stöder situationer där det faktiska beloppet är 0. Om mål-API:t till exempel inte lyckas producera debiterbar användning kan Gateway skicka in `amount = "0"`. Facilitator returnerar framgång, men skickar ingen kedjetransaktion.

Detta kan undvika problemet med ”begäran lyckades inte men avgifter på kedjan debiteras ändå”.

## Rekommendationer för val

| Scenario                   | Rekommendation                       |
| -------------------------- | ------------------------------------ |
| API med fast pris          | Använd `exact`, logiken är enkel.    |
| Orderbetalning             | Använd `exact`.                      |
| Chattkomplettering, debitering per token | Använd Base `upto`.       |
| Permit2 approve har ännu inte gjorts | Använd först `exact` för att få det att fungera, och växla sedan till `upto`. |

Om du är osäker på vilket du ska välja, använd först SDK:ns standardbeteende; SDK:t väljer det matchande nätverkets payment requirement som servern returnerar.

## Checklista för Base `upto`

Vid integration eller felsökning, bekräfta att följande parametrar kommer från samma 402-svar och håll dem konsekventa vid klientsignering:

| Parameter                  | Kontrollpunkt                                          |
| -------------------------- | ----------------------------------------------------- |
| `network`                  | Måste vara `eip155:8453`.                             |
| `scheme`                   | Måste vara `upto`.                                    |
| `extra.chainId`            | Base chain id är `8453`.                              |
| `asset`                    | Använd Base USDC-kontraktsadressen från 402-svaret.   |
| `extra.facilitatorAddress` | Måste delta i witness och stämma överens med Facilitator `/supported`. |
| Permit2 allowance          | Betalningsplånboken måste först auktorisera Permit2 för Base USDC. |

Vanliga fel och hanteringssätt:

| Fel                                           | Hanteringssätt                                                                          |
| -------------------------------------------- | --------------------------------------------------------------------------------------- |
| `invalid_upto_evm_payload_invalid_signature` | Kontrollera om chain id, facilitator-adress, Permit2 domain, spender, signeringskonto och witness stämmer överens med 402-svaret. |
| `PERMIT2_ALLOWANCE_REQUIRED`                 | Utför Permit2 approve för USDC på målkedjan och initiera sedan begäran igen.            |
| `amount exceeds permitted amount`            | Den faktiska användningen överstiger den signerade gränsen, och en ny signering enligt en högre gräns krävs. |
