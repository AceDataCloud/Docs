---
title: "Skapa API-autentiseringsuppgifter för AceDataCloud-plattformen"
description: "Platform API guide - Ace Data Cloud"
---

Skapa affärs-API-autentiseringsuppgifter för en Application. Skapandesvaret kan innehålla en Token som kan användas direkt för att anropa `https://api.acedata.cloud/**`, eller användarnamn/lösenord för autentiseringsuppgifter av Proxy-typ; de måste behandlas som hemligheter.

## Förberedelser

1. Skapa en [Account Token](https://platform.acedata.cloud/documents/platform-token).
2. Hämta det `application_id` som du äger från [Application-listan](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='din kontotoken'
export APPLICATION_ID='ditt Application-ID'
```

## API-översikt

| Post    | Innehåll                                             |
| ---- | ---------------------------------------------------- |
| Metod   | `POST`                                               |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/` |
| Autentisering   | Account Token, OAuth token kräver `credentials:write`      |
| Body | JSON                                                 |

## Begärandetext

| Fält                  | Typ              | Obligatoriskt  | Beskrivning                            |
| ------------------- | --------------- | --- | ----------------------------- |
| `application_id`    | UUID            | Ja   | Mål-Application                |
| `name`              | string          | Nej   | Visningsnamn för autentiseringsuppgifter                         |
| `limited_amount`    | number / null   | Nej   | Användningsgräns per autentiseringsuppgift; `null` betyder att ingen separat gräns anges       |
| `expired_at`        | datetime / null | Nej   | ISO 8601-utgångstid                 |
| `allowed_api_ids`   | UUID[] / null   | Nej   | Tillåt endast anrop till dessa API:er; tom array normaliseras till obegränsad       |
| `host`              | string          | Nej   | Host-information för autentiseringsuppgifterna                    |
| `for_user_id`       | string          | Nej   | Används när Application-ägaren utfärdar auktoriseringsuppgifter för en annan användare |
| `tags` / `metadata` | array / object  | Nej   | Anpassade utökningsdata                       |

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/credentials/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"name\":\"production\",\"limited_amount\":50}"
```

## Svarsbeskrivning

Vid framgång returneras `201` och ett Credential-objekt:

- Tjänster av API-/Agent-typ returnerar vanligtvis `type=Token` och `token`;
- Tjänster av Proxy-typ returnerar vanligtvis `type=Identity` och `username` / `password`, och en Proxy Application tillåter endast en autentiseringsuppgift;
- `id`, `user_id`, `creator_id`, `used_amount` och tidsfält genereras av servern.

De nuvarande list- och detalj-API:erna returnerar också autentiseringsuppgifterna i klartext, men klienter bör inte förlita sig på detta historiska beteende. Spara dem omedelbart efter skapandet och undvik att skriva svaret till loggar; framtida API:er kan ändras till att returnera maskerade värden.

## Felhantering

- `400`: Felaktigt fältformat, okända `allowed_api_ids`, Proxy Application har redan autentiseringsuppgifter eller andra skapandebegränsningar.
- `401`: Account Token är ogiltig.
- `403/404`: Ingen behörighet att komma åt mål-Application, eller så finns inte Application/användaren för auktorisering.
