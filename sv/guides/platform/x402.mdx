X402 är ett kedjebaserat betalningsprotokoll baserat på HTTP `402 Payment Required`. Genom Ace Data Clouds X402-funktionalitet kan anropande part genomföra kedjebaserade betalningar direkt med USDC i varje API-förfrågan utan att skapa en API-token eller förladda kontobalansen.

Denna dokumentation är organiserad i den ordning som en verklig integration skulle ske: först genomföra en minimal förfrågan, sedan integrera SDK, och därefter förstå nätverk, prissättningsmodeller, orderbetalningar och Facilitator. ## Rekommenderad integrationsväg

Om du bara vill anropa Ace Data Cloud API, använd först den officiella SDK:

- TypeScript: `@acedatacloud/sdk` + `@acedatacloud/x402-client`
- Python: `acedatacloud` + `acedatacloud-x402`

Offentliga källkoder och paketadresser:

| Projekt               | Adress                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| Ace Data Cloud SDK | [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)                                         |
| X402 Client        | [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)                           |
| X402 Facilitator   | [https://github.com/AceDataCloud/FacilitatorX402](https://github.com/AceDataCloud/FacilitatorX402)                 |
| npm SDK            | [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)                 |
| npm X402 Client    | [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client) |
| PyPI SDK           | [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)                                   |
| PyPI X402 Client   | [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)                         |

SDK:n kommer automatiskt att hantera den första förfrågan utan autentisering, tolka `402 Payment Required`, anropa betalningshanteraren och återförsöka dessa steg med `PAYMENT-SIGNATURE`. Du behöver bara förbereda en plånbok med USDC och välja det nätverk du vill använda.

Om du vill att din egen API också ska stödja X402-betalningar, behöver du läsa Facilitator-dokumentationen för att förstå relationen mellan `paymentRequirements`, `paymentPayload`, `/verify` och `/settle`.

- npm och PyPI-paket har installerats och importerats framgångsrikt i en ren miljö.
- Obetald API-förfrågan returnerar 402, `accepts` innehåller tillgängliga betalningsmetoder för Bas, SKALE och Solana.

## Anslutningsanvisningar

Utvecklare bör prioritera att fokusera på de aktuella betalningskraven som returneras i realtid, snarare än att kopiera exempelbelopp eller adresser från dokumentationen:

- `accepts[].maxAmountRequired` är det maximala belopp som kan signeras för den aktuella förfrågan.
- `accepts[].asset` är den USDC-kontrakt eller mint som ska användas för denna förfrågan.
- `accepts[].extra.chainId`, `accepts[].extra.facilitatorAddress` och `accepts[].extra.verifyingContract` kommer att delta i EVM-typad data signering.
- `upp till` kräver att plånboken först ger tillstånd för målchain USDC med Permit2; om det inte är auktoriserat kommer det att returnera `PERMIT2_ALLOWANCE_REQUIRED`.
- Om det tydligt önskas att använda efterhandsmätning, vänligen skicka in `preferScheme: 'upp till'` i TypeScript SDK, annars kommer SDK att välja det första tillgängliga kravet som returneras av servern under det nätverket.

## Områden som kan verifieras offentligt

Innan anslutning kan dessa offentliga ingångar och SDK-beteenden verifieras:

- API-förfrågningar utan `Authorization` eller `PAYMENT-SIGNATURE` kommer att returnera `402 Payment Required`, och `accepts` i svaret är den enda signeringsgrunden för denna förfrågan.
- TypeScript SDK och Python SDK erbjuder båda en betalningshanterare, SDK:s transportlager kommer att anropa hanteraren och försöka igen efter att ha mottagit 402.
- `https://facilitator.acedata.cloud/.well-known/x402`: returnerar Facilitatorns stöd för nätverk, schema och protokolländpunkter; API-priserna baseras fortfarande på den aktuella 402 som returneras av målförfrågan.
- `https://facilitator.acedata.cloud/supported`: returnerar Facilitatorns stöd för nätverk och schema.
- X402Client-förvaret innehåller avancerade verktyg för verifiering på kedjan, som kan användas för att bekräfta signaturer, omförsök och avräkningsbeteende; verktygens utdata ersätter inte den online API:s returnerade `accepts`.

`upp till` tillhör efterhandsmätning avräkning, lämplig för chattkomplettering, modellanrop och andra verkliga användningar som endast är kända efter svaret. För närvarande erbjuder endast Bas `upp till`; om signaturverifieringen misslyckas, kontrollera att chain id, facilitatoradress, spenderare, USDC-kontrakt och Permit2-tillstånd överensstämmer med 402-svaret.
