Skapa eller uppdatera en betalningssession för en `Pending`-order. Betalningsåtgärden kommer att åtkomma betalningskanalen och kan ändra orderstatusen; före anropet måste order-ID, belopp och betalningsmetod bekräftas.

## API-översikt

| Post    | Innehåll                                                             |
| ---- | -------------------------------------------------------------- |
| Metod   | `POST`                                                         |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/` |
| Autentisering   | Hanterade omdirigeringsbaserade betalningar kan vara anonyma; andra metoder kräver inloggningssession eller Account Token                            |
| Body | JSON, obetalda ordrar måste tillhandahålla `pay_way`                                       |

## Gränser för anonym betalning

Anonym åtkomst används för scenarier där inloggningssessionen går förlorad efter att en kopierad betalningslänk har öppnats, och kräver inte och bör inte inkludera en långvarig Account Token. Anonyma anrop:

- tillåter endast hanterade omdirigeringsbaserade betalningsmetoder som konfigurerats på servern;
- använder alltid betalningssidan för dator;
- kan inte hämta ordrar med nollpris;
- begränsas av IP och enskild order;
- returnerar en minimal orderprojektion, utan konto, Application eller intern metadata.

Autentiserade anropare måste vara orderägaren eller superadministratör. Metoder som X402 och belöningsinlösen, vilka kräver användarkontext, kan inte anropas anonymt.

## Exempel på begäran

```shell
export ORDER_ID='ditt Pending-order-ID'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"Stripe"}'
```

Betalningsmetoder som kräver autentisering:

```shell
export PLATFORM_TOKEN='din kontotoken'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"X402"}'
```

`pay_way` använder verkliga värden som stöds av ordermodellen, till exempel `WechatPay`, `AliPay`, `Stripe`, `Card`, `Airwallex`, `X402`, `PayPal`, `AppleIAP`, `Reward`, `BankTransfer`. Inte alla värden är tillgängliga för anonyma begäranden eller på varje webbplats.

## Svarsbeskrivning

Ett lyckat svar är det uppdaterade orderobjektet, som vanligtvis tillhandahåller nästa steg via `pay_url`; olika betalningsmetoder kan även returnera information i kontrollerade fält som klienten behöver för att fortsätta betalningen. Anonyma svar använder en minimal vitlista med fält, medan autentiserade ägare får fullständig information.

Förlita dig inte på gamla fältnamn som `payment_url`, `qr_code_url` eller `payment_method`; det aktuella Order-kontraktet använder `pay_url` och `pay_way`.

## Banköverföring

Inloggade privata konton och företagskonton kan båda använda `BankTransfer`, utan företagsverifiering. Både inhemska RMB-överföringar och internationella USD-överföringar kräver att orderbeloppet är minst 300 USD; det RMB-belopp som ska betalas baseras på det belopp som visas vid betalningstillfället.

Före betalning kan du fråga efter tillgängliga överföringsrutter och beloppströsklar för den aktuella ordern via `GET /api/v1/orders/{order_id}/payment-options/`. Banköverföringar måste initieras av orderägaren efter inloggning och begränsas av konfigurationen för mottagningskanalen och paketets tillämpningsområde; anonyma begäranden kan inte använda dem.

## iOS-köp i appen

Den inloggade orderägaren kan ange `pay_way: "AppleIAP"`. Denna begäran uppdaterar den obetalda ordern enligt det valda paketets `metadata.apple_price` och tar bort rabatten, utan att skapa någon debitering, utfärda krediter eller returnera en betalningslänk. Äldre obetalda ordrar ska först slutföra detta steg och sedan initiera Apples inbyggda betalning. Endast ett Usage-paket med en konfigurerad Apple-produkt och ett pris stöds; paket som inte stöds eller batchordrar returnerar `400`.

Efter Apples inbyggda betalning skickas `transaction_id` via `/api/v1/orders/{id}/apple-verify/` för att slutföra serververifiering och utfärdande av krediter. Antalet krediter kommer från paketet; beloppet använder Apples separata förinställda USD-pris, utan medlemsrabatter eller webbplatsprispåslag, och det lokala debiteringsbeloppet i andra regioner baseras på Apples bekräftelsesida.

## Fel och återförsök

- Ordern är inte `Pending`: returnerar `400`; skapa inte betalningssessionen igen.
- `pay_way` har inte angetts: ordrar med belopp som inte är noll returnerar `400`.
- Ett anonymt anrop använder en otillåten metod eller en order med nollpris: returnerar `403`, försök igen efter inloggning som ägaren.
- Autentiserad men inte orderägaren: returnerar `403`.
- Betalningskanalen misslyckas: skicka inte in upprepade gånger utan eftertanke; fråga först efter orderdetaljerna och försök igen efter att ha bekräftat att den fortfarande är `Pending`.
