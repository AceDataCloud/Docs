Den här handledningen använder en minimal API-begäran för att beskriva hela flödet för Ace Data Cloud X402. Målet är inte att först skriva komplex kod, utan att först förstå: varför den första begäran returnerar 402, vad som finns i `accepts`, och hur `PAYMENT-SIGNATURE` gör samma API-begäran till en betald begäran.

## Förberedelser

Du behöver förbereda:

| Objekt   | Beskrivning                                                   |
| ---- | ---------------------------------------------------- |
| Plånbok   | En plånbok som stöder målnätverket. Base använder en EVM-plånbok, Solana använder en Solana-plånbok.      |
| USDC | Plånboken måste ha tillräckligt med USDC. Det faktiska beloppet baseras på `maxAmountRequired` i 402-svaret. |
| Utvecklingsmiljö | TypeScript rekommenderar Node.js 18+; Python rekommenderar Python 3.10+.    |
| SDK  | Det rekommenderas att använda det officiella SDK:t, det rekommenderas inte att skriva signaturdetaljer för hand.                                |

X402 kräver ingen API Token vid anrop till Ace Data Cloud API. SDK:ts första begäran innehåller inte `Authorization`, Gateway returnerar `402 Payment Required` och betalningskrav; SDK:t försöker automatiskt igen efter signering.

## Installera SDK

Källkod och paketadresser:

- SDK-arkiv: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- X402 Client-arkiv: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm: `@acedatacloud/sdk`、`@acedatacloud/x402-client`
- PyPI: `acedatacloud`、`acedatacloud-x402`

TypeScript:

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client ethers
```

Python:

```bash
pip install acedatacloud acedatacloud-x402
```

Om du vill använda Solana behöver du även installera motsvarande beroenden:

```bash
npm install @solana/web3.js
```

Python-versionens Solana signer-beroenden ingår redan i `acedatacloud-x402`.

Installations- och importkontrollutdata i en ren temporär miljö:

```text

@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4

imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
```

Resultatbeskrivning:

- Både npm-paketen och PyPI-paketen är faktiskt publicerade paket, inte platshållarnamn i dokumentationen.
- `acedatacloud-x402[cli]` installerar CLI:t, och underkommandot `approve-permit2` kan användas för Permit2-auktorisering i `upto`-scenarier.

## Den första begäran returnerar 402

Du kan först använda `curl` för att se vad en obetald begäran returnerar. Exemplet nedan medför ingen debitering eftersom det inte innehåller `PAYMENT-SIGNATURE`:

```bash
curl -sS -X POST https://x402.acedata.cloud/openai/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "hi"}],
    "max_tokens": 1
  }'
```

Svarskroppen innehåller en `accepts`-array, med en vanlig struktur enligt följande:

```json
{
  "x402Version": 2,
  "resource": {
    "url": "/openai/chat/completions",
    "description": "AceDataCloud API call",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "maxAmountRequired": "95215",
      "amount": "95215",
      "maxTimeoutSeconds": 3600,
      "resource": "/openai/chat/completions",
      "description": "...",
      "payTo": "0x...",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913"
      }
    }
  ],
  "error": "PAYMENT-SIGNATURE header is required"
}
```

Samma challenge-innehåll placeras också i base64-format i svarsheadern `PAYMENT-REQUIRED`, så att klienten kan läsa betalningskraven utan att parsa body.

Programutdatasammanfattningen för en obetald begäran till produktions-API:t är följande:

```text
status=402
x402Version 2
accepts [
  ('eip155:8453', 'exact', '95215'),
  ('eip155:8453', 'upto', '95215'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '95215'),
]
```

Resultatbeskrivning:

- Den första begäran innehåller inte `Authorization` eller `PAYMENT-SIGNATURE`, så den returnerar HTTP 402 och medför ingen debitering.
- `accepts` är den enda tillförlitliga signaturgrunden för den här begäran och innehåller valbara nätverk, scheme, beloppsgräns, mottagaradress och tillgångsadress.
- `network` är en CAIP-2-identifierare, klienten måste matcha enligt CAIP-2-strängen när den väljer nätverk.
- Det maximala beloppet för denna minimala chattbegäran med `gpt-4o-mini` är `95215` atomic USDC, det vill säga `0.095215` USDC.
- Varje begäran bör läsa det aktuella 402-svaret, hårdkoda inte exempelbelopp i affärskoden.

Fältens betydelse:

| Fält                  | Beskrivning                                                             |
| ------------------- | -------------------------------------------------------------- |
| `scheme`            | Betalningsschema. `exact` anger ett fast belopp, `upto` anger en auktoriseringsgräns och avräkning baserat på faktisk användning.                     |
| `network`           | CAIP-2-identifieraren för betalningsnätverket, till exempel `eip155:8453`、`solana:5eykt4...`.           |
| `maxAmountRequired` | Maximalt betalningsbelopp, enheten är USDC atomic units, `95215` betyder `0.095215` USDC.       |
| `amount`            | Beloppet som ska avräknas denna gång; `exact` är samma som `maxAmountRequired`, och `upto` skrivs om utifrån faktisk användning under avräkningsfasen. |
| `payTo`             | Mottagaradress.                                                          |
| `asset`             | USDC-kontraktsadress eller Solana mint-adress.                                     |
| `extra`             | Utökad information som krävs för signering, såsom chain ID, EIP-712 domain och Permit2-adress.                      |

## Slutför betalningsförsök igen med SDK

Nedan är ett minimalt TypeScript-exempel. Det anger `network: 'base'`, handlern väljer Base payment requirement från det aktuella 402-svaret; det faktiska beloppet och mottagaradressen baseras fortfarande på `accepts`:
```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const response = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Reply with exactly: hello' }],
  max_tokens: 8
});

console.log(response.choices[0].message.content);
```

Fyra steg sker bakom den här koden:

1. SDK:t skickar en vanlig API-begäran utan `Authorization`.
2. Gateway returnerar `402 Payment Required` och `accepts`.
3. `createX402PaymentHandler` väljer payment requirement för `network = 'base'` och signerar `PAYMENT-SIGNATURE`.
4. SDK:t försöker igen med samma begärandetext, och Gateway anropar Facilitator för att verifiera och reglera innan den släpper igenom till mål-API:t.

## Visa Facilitators funktioner som stöds

X402 API är inte beroende av en resurskatalog. Klienten anropar direkt ett känt API och använder
`402 Payment Required` och `accepts` som returneras i realtid av den begäran som enda grund för pris och signatur.

Facilitators funktionsdeklaration finns på:

```bash
curl https://facilitator.acedata.cloud/.well-known/x402
```

Den beskriver endast `/supported`, `/verify`, `/settle` och de betalningsnätverk som för närvarande är aktiverade, och listar inte API-resurser.

Ace Data Clouds produktionsadress för Facilitator är:

```text
https://facilitator.acedata.cloud
```

Du kan se vilka nätverk och scheman den stöder:

```bash
curl https://facilitator.acedata.cloud/supported
```

De returnerade `kinds` listar de nätverk och scheman som Facilitator stöder. Vid faktiska anrop gäller fortfarande det `accepts` som returneras av API:t.

Utdata från Facilitator `/supported`:

```text
kinds [
  ('eip155:8453', 'exact'),
  ('eip155:8453', 'upto', {'facilitatorAddress': '0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708'}),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact')
]
```

Resultatet innebär:

- `/supported` visar att Facilitator har kapacitet att verifiera och reglera dessa nätverk och scheman.
- Både Base och Solana stöder `exact`; `upto` erbjuds för närvarande endast på Base.
- Huruvida ett specifikt API tillåter ett visst nätverk avgörs fortfarande av API:ts 402 `accepts`.
