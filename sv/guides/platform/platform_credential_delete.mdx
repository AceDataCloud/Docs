Ta bort en API-autentiseringsuppgift permanent. Efter borttagning kan den **inte återställas omedelbart**, och alla affärsgränssnitt som använder denna Token kommer genast att få `401`.

> ℹ️ Detta gränssnitt tillhör **AceDataCloud-plattformens hanterings-API**, med det enhetliga prefixet `https://platform.acedata.cloud/api/v1/`.

## API-översikt

| Post   | Innehåll                                                            |
| --- | ------------------------------------------------------------------- |
| Metod  | `DELETE`                                                            |
| URL | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}` |
| Autentisering  | ✅ Kontotoken krävs                                                            |

`/credentials/{id}` och `/credentials/{id}/` är för närvarande båda tillgängliga; exemplen använder enhetligt formen utan avslutande snedstreck.

## Autentiseringsbeskrivning (hur man hämtar kontotoken)

Begärandehuvud:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Se [Hantera AceDataCloud-plattformens kontotoken](https://platform.acedata.cloud/documents/platform-token) för hämtmetod.

## Sökvägsparametrar

| Parameter              | Typ   | Obligatorisk  | Beskrivning        |
| --------------- | ---- | --- | --------- |
| `credential_id` | UUID | ✅   | ID för autentiseringsuppgiften som ska tas bort |

## Begäransexempel

### cURL

```shell
curl -X DELETE 'https://platform.acedata.cloud/api/v1/credentials/df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

cred_id = "df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6"
resp = requests.delete(
    f"https://platform.acedata.cloud/api/v1/credentials/{cred_id}",
    headers={"authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    timeout=10,
)
assert resp.status_code == 204, resp.text
print("✅ 已删除")
```

### Node.js

```javascript
const credId = 'df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6'
const r = await fetch(`https://platform.acedata.cloud/api/v1/credentials/${credId}`, {
  method: 'DELETE',
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log('status:', r.status) // 204
```

## Svar

- **Lyckat**: `HTTP 204 No Content`, **ingen svarskropp**.
- **Misslyckat**: Returnerar fel-JSON, se tabellen nedan.

## Felhantering

| HTTP | code                | Betydelse         |
| ---- | ------------------- | ---------- |
| 401  | `not_authenticated` | Kontotoken saknas     |
| 403  | `permission_denied` | Denna autentiseringsuppgift tillhör inte dig    |
| 404  | `not_found`         | Autentiseringsuppgiften finns inte eller har tagits bort |

## Praktiska tips

- **Borttagning kan inte ångras** — plattformen behåller inga Token-kopior. Om du bara misstänker ett läckage och fortfarande vill behålla övervakningsdata bör du använda [Rotera API-autentiseringsuppgifter för AceDataCloud-plattformen](https://platform.acedata.cloud/documents/platform-credential-rotate) i stället för att ta bort dem.
- **Borttagning återbetalar inte den kvot som redan har förbrukats av autentiseringsuppgiften**. Application-saldot dras av i realtid baserat på förbrukning, och borttagning av autentiseringsuppgiften påverkar inte saldot i bokföringen.
- Efter borttagning kan du via [listan över API-autentiseringsuppgifter](https://platform.acedata.cloud/documents/platform-credential-list) bekräfta återstående autentiseringsuppgifter på nytt enligt `application_id`.
- **Kontrollera först anroparna före massrensning**: listan har för närvarande inget fält för senaste användningstid; du bör bekräfta att autentiseringsuppgifterna inte längre används med hjälp av distributionskonfiguration och anropsloggar, och sedan ta bort dem en i taget.
