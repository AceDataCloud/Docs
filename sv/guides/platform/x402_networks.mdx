Ace Data Cloud X402 avräknar för närvarande med USDC och stöder två typer av kedjor: EVM och Solana. Signeringsmetoder, tillgångsadresser, gas-beteende och tillämpliga scenarier skiljer sig mellan olika nätverk, så du behöver välja nätverk innan integration.

## Nätverksidentifierare använder CAIP-2

`accepts[].network` i x402 v2 är en CAIP-2-identifierare, inte förkortningar som `base` eller `skale`. Klienten måste jämföra nätverk enligt CAIP-2-strängen:

| Nätverk             | CAIP-2-identifierare                       |
| -------------- | ----------------------------------------- |
| Base           | `eip155:8453`                             |
| SKALE Base     | `eip155:1187947933`                       |
| Solana mainnet | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` |

## Stödmatris

| Nätverk     | scheme  | Tillgång                  | Signeringsmetod                         | Tillämpligt scenario                        |
| ------ | ------- | ------------------- | ------------------------------------ | --------------------------- |
| Base   | `exact` | Base USDC           | EIP-3009 `TransferWithAuthorization` | Standardrekommendation, moget stöd för plånböcker och likviditet.            |
| Base   | `upto`  | Base USDC + Permit2 | Permit2 `PermitWitnessTransferFrom`  | API:er med efterföljande mätning, såsom chatt och modeller.             |
| SKALE  | `exact` | SKALE bridged USDC  | EIP-3009 `TransferWithAuthorization` | Låg gas-kostnad, lämpligt för EVM-betalningsverifiering och lågkostnadsanrop. |
| Solana | `exact` | Solana USDC         | SPL `TransferChecked`                | Scenarier med Solana-plånböcker, Agent eller applikationer på kedjan.    |

`upto` erbjuds för närvarande endast på Base. De faktiskt tillgängliga alternativen beror på de `accepts` som API:et returnerar. Du kan även kontrollera Facilitator:

```bash
curl https://facilitator.acedata.cloud/supported
```

Returen från Facilitator `/supported`:

```json
{
  "kinds": [
    { "x402Version": 2, "scheme": "exact", "network": "eip155:8453" },
    {
      "x402Version": 2,
      "scheme": "upto",
      "network": "eip155:8453",
      "extra": { "facilitatorAddress": "0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708" }
    },
    { "x402Version": 2, "scheme": "exact", "network": "eip155:1187947933" },
    {
      "x402Version": 2,
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "extra": { "feePayer": "3SPm6qbgsDkj24MuR8Ss4sH97fziqyCiqFKDyeVU2igq" }
    }
  ]
}
```

Resultatförklaring:

- `exact` för Base, SKALE och Solana är betalningsvägar med fast belopp.
- Endast Base erbjuder mätvägen `upto` med efterföljande avräkning, som är beroende av Permit2 approve.
- `extra.facilitatorAddress` i posten för `upto` är adressen som klienten ska skriva in i witness vid signering och måste överensstämma med värdet som returneras av servern.

## Base

Base använder det officiella USDC-kontraktet:

```text
0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
```

I schemat `exact` signerar klienten EIP-712 `TransferWithAuthorization`. Signaturinnehållet omfattar:

- `from`: den betalande plånbokens adress
- `to`: Ace Data Clouds mottagaradress
- `value`: betalningsbeloppet för denna gång
- `validAfter` / `validBefore`: signaturens giltighetstidsfönster
- `nonce`: slumpmässig nonce på 32 byte

Efter att Facilitator har verifierat signaturen anropar den USDC:s `transferWithAuthorization` på kedjan för att slutföra överföringen.

Base är det mest rekommenderade nätverket för produktionsintegration, särskilt för efterföljande mätning med `upto`, eftersom ekosystemen för Permit2, USDC och plånböcker är mer mogna.

Exempel på verifieringsresultat för Base `exact`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
content ADC_BASE_E2E_OK
tx 0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
block 46726299
explorer https://basescan.org/tx/0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
transfer value 95215 atomic USDC
```

Resultatförklaring:

- API:ets betalda retry returnerar modellinnehållet `ADC_BASE_E2E_OK`.
- Transaktionen på kedjan kan kontrolleras på BaseScan och blocknumret är `46726299`.
- `95215` atomic USDC motsvarar `0.095215` USDC och är det faktiska avräkningsbeloppet för detta API-anrop.

Programkörningsresultat för orderbetalning med Base `exact`:

```text
order 78481793-304e-47f7-bc0c-8231aec9cc1e
state Finished
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer value 1200000 atomic USDC
```

Resultatförklaring:

- Plattformens slutliga orderstatus är `Finished`.
- Orderns `pay_id` skrivs in med samma Base-transaktionshash.
- `1200000` atomic USDC motsvarar `1.2` USDC och är det historiskt faktiskt betalda beloppet för denna order på 10 Credits enligt den gamla policyn; nya ordrar får inte längre någon extra rabatt för betalningsmetoden X402, och det specifika signerade beloppet beror på 402-svaret denna gång.

## SKALE

SKALE använder bridged USDC och signeringsmetoden liknar Base, det vill säga också EIP-3009. Det lämpar sig för EVM-betalningsscenarier med låg gas-kostnad; faktiska anrop beror fortfarande på de `accepts` som API:et returnerar.

Typiska 402 `accepts` för SKALE innehåller:

```json
{
  "network": "eip155:1187947933",
  "scheme": "exact",
  "extra": {
    "name": "Bridged USDC (SKALE Bridge)",
    "version": "2",
    "chainId": 1187947933,
    "verifyingContract": "0x85889c8c714505E0c94b30fcfcF64fE3Ac8FCb20"
  }
}
```

SKALE erbjuder för närvarande endast `exact`. Om du behöver efterföljande mätning, använd Base `upto`.

Exempel på verifieringsresultat för SKALE `exact`:

```text
content ADC_SKALE_E2E_OK
tx 0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
block 1969317
explorer https://skale-base-explorer.skalenodes.com/tx/0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
paid 0.095215 USDC
```

Resultatförklaring:
- API:s betalda återförsök returnerar modellinnehållet `ADC_SKALE_E2E_OK`.
- Transaktionen kan hittas i SKALE explorer, och blocknumret är `1969317`.
- Avräkningsbeloppet för denna `exact`-betalning är `0.095215` USDC.

## Solana

Solana använder SPL USDC `TransferChecked`. Klienten bygger en överföringstransaktion, signerar och skickar den, och lägger sedan transaktionssignaturen eller den serialiserade transaktionen i `PAYMENT-SIGNATURE` envelope.

Egenskaper för Solana:

- använder Solana wallet adapter eller base58 secret key;
- tillgången är Solana USDC mint;
- stöder för närvarande endast `exact`;
- Facilitator validerar överföringsinstruktionens mint, destination, authority och amount.

Om läget med wallet fee payer används skickar plånboken transaktionen direkt, och Facilitator ansvarar för att bekräfta transaktionen och returnera settlement-resultatet.

Exempel på valideringsresultat för Solana `exact`:

```text
payer AY2RmGm2zPxB1uKvvF4dKyYdr2VySyL3wcD1MKJZoLRd
HTTP 402 -> HTTP 200
content ADC_SOLANA_E2E_OK
chain signature not confirmed in this run
```

Resultatförklaring:

- det betalda återförsöket har redan returnerat HTTP 200, och modellutdata är `ADC_SOLANA_E2E_OK`.
- Vid förfrågan av signature på kedjan via offentlig RPC kan rate limiting förekomma.
- Eftersom offentliga RPC-förfrågningar kan begränsas skrivs ingen Solana explorer här. När strikt avstämning krävs, använd en egen Solana RPC eller plattformens settlement-poster för att bekräfta transaktionssignaturen.

## Hur man väljer

| Vad du vill göra        | Rekommenderat nätverk                         |
| ------------ | ---------------------------- |
| Snabbt köra igenom minsta flödet     | SKALE `exact` eller Base `exact` |
| Rikta sig till vanliga Web3-användare | Base                         |
| Utföra eftermätning för exempelvis chattkompletteringar   | Base `upto`                  |
| Solana-ekosystemapplikationer  | Solana `exact`               |
| Betalningsvalidering med låg EVM-kostnad | SKALE `exact`                |

Oavsett vilken kedja som väljs, hårdkoda inte priset i klienten. Priset avgörs av `accepts[].maxAmountRequired` som returneras av servern.

## Nya EVM-nätverk

Betalningar med fast belopp i inbyggd USDC för följande nätverk har kodstöd och öppnas nätverk för nätverk.
Tillgängligheten avgörs av ordern eller API:ets returnerade `accepts`; det innebär inte att alla nätverk redan är aktiverade i produktion.

| Nätverk      | Alias      | CAIP-2         | Inbyggd USDC                                  |
| ------------ | ---------- | -------------- | -------------------------------------------- |
| Arbitrum One | `arbitrum` | `eip155:42161` | `0xaf88d065e77c8cC2239327C5EDb3A432268e5831` |

Dessa nätverk stöder endast `exact`, och valutaprecisionen är 6. Använd inte bryggad USDC med samma namn.
När den officiella TypeScript/Python X402 Client används kan förkortningen i tabellen eller CAIP-2-identifieraren skickas in.
Klienten använder mål-kedje-ID:t för att skapa signaturen; plånboken måste stödja målnätverket.

Phantom-tilläggsplånbokens officiella stödtabell listar Arbitrum och Polygon; Optimism, Avalanche
finns för närvarande inte med i tabellen, och Rabby eller MetaMask som stöder målkedjan kan användas. EVM-adresser kan vara samma på olika kedjor,
men saldona är oberoende av varandra, och Solana-adresser gäller inte för EVM USDC.
Se [Phantom-plånbokens stödtabell](https://docs.phantom.com/wallet-sdks-overview#chain-support).

### Gradvis aktiveringsingång för nya nätverk

Ingångar för nya kedjor är dolda som standard. När du öppnar konsolen eller Studio kan du använda `?features=x402-arbitrum`
för att aktivera motsvarande kedja, och flera flaggor separeras med kommatecken. Stäng av en enskild kedja med `?features=-x402-arbitrum`,
och rensa lokala åsidosättningar med `?features=none`. Växlar sparas separat för varje domän.
Orderofferter och betalningsåterförsök använder samma växel, och servern validerar dem separat; befintliga betalningsposter kan fortfarande visas.
Att endast aktivera sidans flagga aktiverar inte kedjor som ännu inte har konfigurerats; vilka nätverk som faktiskt kan användas för betalning avgörs fortfarande av `accepts` i realtid.
