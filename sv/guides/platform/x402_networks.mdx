Ace Data Cloud X402 avvecklar för närvarande kring USDC och stöder två typer av kedjor: EVM och Solana. Olika nätverk har olika signeringsmetoder, tillgångsadresser, gas-beteenden och användningsscenarier, så nätverket måste väljas innan integration.

## Nätverksidentifierare använder CAIP-2

`accepts[].network` i x402 v2 är en CAIP-2-identifierare, inte förkortningar som `base` eller `solana`. Klienter måste jämföra nätverk enligt CAIP-2-strängen:

| Nätverk             | CAIP-2-identifierare                                 |
| -------------- | ----------------------------------------- |
| Base           | `eip155:8453`                             |
| Solana mainnet | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` |

## Stödmatris

| Nätverk     | scheme  | Tillgång                  | Signeringsmetod                                 | Användningsscenario                     |
| ------ | ------- | ------------------- | ------------------------------------ | ------------------------ |
| Base   | `exact` | Base USDC           | EIP-3009 `TransferWithAuthorization` | Standardrekommendation, med mogen support för plånböcker och likviditet.         |
| Base   | `upto`  | Base USDC + Permit2 | Permit2 `PermitWitnessTransferFrom`  | API:er för efterhandsmätning såsom chatt och modeller.          |
| Solana | `exact` | Solana USDC         | SPL `TransferChecked`                | Solana-plånböcker, Agent eller användningsscenarier för on-chain-applikationer. |

`upto` tillhandahålls för närvarande endast på Base. Faktiskt tillgängliga alternativ avgörs av API:ets returnerade `accepts`. Du kan även kontrollera Facilitator:

```bash
curl https://facilitator.acedata.cloud/supported
```

Returnerat från Facilitator `/supported`:

```json
{
  "kinds": [
    { "x402Version": 2, "scheme": "exact", "network": "eip155:8453" },
    {
      "x402Version": 2,
      "scheme": "upto",
      "network": "eip155:8453",
      "extra": { "facilitatorAddress": "0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708" }
    },
    {
      "x402Version": 2,
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "extra": { "feePayer": "3SPm6qbgsDkj24MuR8Ss4sH97fziqyCiqFKDyeVU2igq" }
    }
  ]
}
```

Förklaring av resultaten:

- `exact` för Base och Solana är betalningsflöden med fast belopp.
- Endast Base erbjuder flödet för efterhandsmätning `upto`, vilket är beroende av Permit2 approve.
- `extra.facilitatorAddress` i `upto`-posten är adressen som klienten ska skriva in i witness vid signering och måste stämma överens med värdet som returneras av servern.

## Base

Base använder det officiella USDC-kontraktet:

```text
0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
```

I `exact`-schemat signerar klienten EIP-712 `TransferWithAuthorization`. Signeringsinnehållet inkluderar:

- `from`: betalande plånboksadress
- `to`: Ace Data Clouds mottagaradress
- `value`: betalningsbeloppet denna gång
- `validAfter` / `validBefore`: signaturens giltighetsperiod
- `nonce`: 32-byte slumpmässig nonce

Efter att Facilitator har verifierat signaturen anropas USDC:s `transferWithAuthorization` on-chain för att slutföra överföringen.

Base är det mest rekommenderade nätverket för produktionsintegration, särskilt lämpligt för efterhandsmätning med `upto`, eftersom Permit2, USDC och plånboksekosystemet är mer mogna.

Exempel på Base `exact`-verifieringsresultat:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
content ADC_BASE_E2E_OK
tx 0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
block 46726299
explorer https://basescan.org/tx/0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
transfer value 95215 atomic USDC
```

Förklaring av resultaten:

- API:ets betalda återförsök returnerar modellinnehållet `ADC_BASE_E2E_OK`.
- On-chain-transaktionen kan hittas på BaseScan och blocknumret är `46726299`.
- `95215` atomic USDC motsvarar `0.095215` USDC, vilket är det faktiska avvecklade beloppet för detta API-anrop.

Programkörningsresultat för orderbetalning med Base `exact`:

```text
order 78481793-304e-47f7-bc0c-8231aec9cc1e
state Finished
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer value 1200000 atomic USDC
```

Förklaring av resultaten:

- Plattformens slutliga orderstatus är `Finished`.
- Orderns `pay_id` skrivs in i samma Base-transaktionshash.
- `1200000` atomic USDC motsvarar `1.2` USDC, vilket är det historiska faktiskt betalda beloppet för denna order på 10 Credits enligt den gamla policyn; nya ordrar får inte längre ytterligare rabatt för betalningsmetoden X402, och det specifika signerade beloppet ska baseras på detta 402-svar.

## Solana

Solana använder SPL USDC `TransferChecked`. Klienten konstruerar en överföringstransaktion, signerar och skickar in den, och lägger sedan transaktionssignaturen eller den serialiserade transaktionen i envelopen `PAYMENT-SIGNATURE`.

Egenskaper för Solana:

- Använder Solana wallet adapter eller base58 secret key;
- Tillgången är Solana USDC mint;
- För närvarande stöds endast `exact`;
- Facilitator validerar transfer instruction:s mint, destination, authority och amount.

Vid användning av läget wallet fee payer skickar plånboken in transaktionen direkt, och Facilitator ansvarar för att bekräfta transaktionen och returnera settlement-resultatet.

Exempel på Solana `exact`-verifieringsresultat:

```text
payer AY2RmGm2zPxB1uKvvF4dKyYdr2VySyL3wcD1MKJZoLRd
HTTP 402 -> HTTP 200
content ADC_SOLANA_E2E_OK
chain signature not confirmed in this run
```

Förklaring av resultaten:

- Det betalda återförsöket har returnerat HTTP 200, och modellen har producerat `ADC_SOLANA_E2E_OK`.
- Vid sökning efter on-chain-signature via offentlig RPC kan hastighetsbegränsning förekomma.
- Eftersom offentliga RPC-sökningar kan begränsas anges ingen Solana explorer här. Vid strikt avstämning, använd egen Solana RPC eller bekräfta transaktionssignaturen via plattformens settlement-poster.

## Hur du väljer

| Vad du vill göra        | Rekommenderat nätverk           |
| ------------ | -------------- |
| Snabbt få igång minsta möjliga flöde     | Base `exact`   |
| Riktat till vanliga Web3-användare | Base           |
| Göra efterhandsmätning för exempelvis chattkomplettering   | Base `upto`    |
| Solana-ekosystemapplikationer  | Solana `exact` |

Oavsett vilken kedja du väljer ska priser inte hårdkodas i klienten. Priset bestäms av `accepts[].maxAmountRequired` som returneras av servern.

## Lägg till nya EVM-nätverk
Kodstöd har tillhandahållits för betalningar med fasta belopp i inhemsk USDC på följande nätverk, och öppnas ett nätverk i taget.
Tillgänglighet avgörs av `accepts` som returneras av ordern eller API:et; det innebär inte att alla nätverk har aktiverats i produktion.

| Nätverk      | Alias      | CAIP-2         | Inhemsk USDC                                |
| ------------ | ---------- | -------------- | -------------------------------------------- |
| Arbitrum One | `arbitrum` | `eip155:42161` | `0xaf88d065e77c8cC2239327C5EDb3A432268e5831` |

Dessa nätverk stöder endast `exact`, och valutans precision är 6. Använd inte bryggad USDC med samma namn.
Vid användning av den officiella TypeScript/Python X402 Client kan du ange förkortningen eller CAIP-2-identifieraren i tabellen.
Klienten använder mål-kedje-ID:t för att konstruera signaturen; plånboken måste stödja målnätverket.

Den officiella stödtabellen för Phantom-tilläggsplånboken listar Arbitrum och Polygon; Optimism, Avalanche
finns för närvarande inte med i tabellen, och Rabby eller MetaMask som stöder målkedjan kan användas. EVM-adresser kan vara samma på olika kedjor,
men saldona är oberoende av varandra, och Solana-adresser är inte tillämpliga för EVM USDC.
Se [Phantom-plånbokens stödtabell](https://docs.phantom.com/wallet-sdks-overview#chain-support).

### Gradvis lanseringsingång för nya nätverk

Ingången för nya kedjor är dold som standard. När du öppnar konsolen eller Studio kan du använda `?features=x402-arbitrum`
för att aktivera motsvarande kedja, och flera flaggor separeras med kommatecken. Stäng av en enskild kedja med `?features=-x402-arbitrum`,
och rensa lokala åsidosättningar med `?features=none`. Inställningarna sparas separat för varje domän.
Orderofferter och återförsök av betalningar använder samma inställning, och servern validerar oberoende; befintliga betalningsposter kan fortfarande visas.
Att endast aktivera sidflaggan aktiverar inte en kedja som ännu inte har konfigurerats; de specifika betalbara nätverken avgörs fortfarande av `accepts` i realtid.
