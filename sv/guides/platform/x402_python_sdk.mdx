Python SDK passar för backendtjänster, datauppgifter, automatiserade agenter och batchskript. `acedatacloud` ansvarar för API-anrop, och `acedatacloud-x402` ansvarar för att signera begärandehuvudet `PAYMENT-SIGNATURE`.

Källkod och paketadresser:

- SDK-lagringsplats: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- X402 Client-lagringsplats: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- PyPI SDK: [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)
- PyPI X402 Client: [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)

## Installera beroenden

```bash
pip install acedatacloud acedatacloud-x402
```

Om du vill använda `upto` måste du även köra Permit2 approve CLI en gång, och denna CLI är beroende av `web3`:

```bash
pip install 'acedatacloud-x402[cli]'
```

Installations- och importkontrollutdata för en ren Python venv:

```text
acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
approve-permit2  One-time ERC-20 approve(Permit2, amount) needed before signing upto payments.
```

Resultatförklaring:

- Både `acedatacloud` och `acedatacloud-x402` kan installeras och importeras från PyPI.
- `pip install 'acedatacloud-x402[cli]'` inkluderar CLI:n `approve-permit2`, som används för förauktorisering av `upto`.

## Base-exempel

Exemplet nedan behöver ingen API-token. Plånbokens privata nyckel används endast för lokal signering och skickas inte till Ace Data Cloud.

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)

print(res["choices"][0]["message"]["content"])
```

Python SDK returnerar för närvarande en `dict`, så exemplet använder `res["choices"][0]["message"]["content"]`. Anta inte direkt att den nödvändigtvis har attributet `.choices`.

## Solana-exempel

Solana använder en base58-kodad secret key:

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import SolanaKeypairSigner, create_x402_payment_handler

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="solana",
        solana_signer=SolanaKeypairSigner.from_base58(os.environ["SOLANA_SECRET_KEY"]),
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

Solana-flödet bygger och skickar en SPL USDC-`TransferChecked`-transaktion och lägger sedan transaktionssignaturen i `PAYMENT-SIGNATURE`-envelope.

Solana paid retry har redan returnerat HTTP 200 och `ADC_SOLANA_E2E_OK` på produktions-API:t. Denna publika RPC-förfrågan stötte på hastighetsbegränsning, så signaturen på kedjan kunde inte bekräftas stabilt; använd din egen Solana RPC för att fråga denna transaktion när avstämning behövs.

## Async-klient

Samma payment handler kan användas för `AsyncAceDataCloud`:

```python
import os

from acedatacloud import AsyncAceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AsyncAceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = await client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

## Använd `upto` för efterföljande mätning

Den faktiska kostnaden för API:er som chattkompletteringar och modellanrop kanske inte är känd förrän svaret har avslutats. Vid detta tillfälle kan API:t returnera både `exact` och `upto`. Om du vill prioritera `upto`:

```python
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
        prefer_scheme="upto",
    )
)
```

Programkörningsresultat för Base `upto`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
settlement tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
settled value 3 atomic USDC
```

Bekräftelse på kedjan:

```text
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
transfer value 3 atomic USDC
```

Resultatförklaring:

- `content ADC_BASE_UPTO_OK` visar att begäran faktiskt nådde modell-API:t.
- `settled value 3 atomic USDC` visar att `upto` avräknas enligt faktisk användning, i stället för att hela gränsen debiteras.
- `settlement tx` kan öppnas i BaseScan; spara tx-hash, payer, completion id och begärandesammanfattning vid avstämning.

`upto` använder Permit2 för att auktorisera en övre gräns, och det faktiska avräkningsbeloppet får inte överstiga denna gräns. Före första användningen måste USDC på målkedjan få en engångs-`approve(Permit2, amount)`.

CLI-sätt:

```bash
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Programsätt:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Denna helper är idempotent. Om allowance redan är tillräcklig returnerar den `{"skipped": true}` och skickar inte någon upprepad on-chain-transaktion.

## Lågnivåsignering

Om du inte använder SDK kan du även direkt anropa lågnivåsigneringsfunktionen:

```python
import base64
import json

from acedatacloud_x402 import EVMAccountSigner, sign_evm_payment

envelope = sign_evm_payment(requirement, EVMAccountSigner.from_private_key("0x..."))
x_payment = base64.b64encode(json.dumps(envelope, separators=(",", ":")).encode()).decode()
```

Lågnivåfunktioner passar för testning, proxylager, gateway-integrationer eller inofficiella SDK:er. Vanlig affärskod bör i första hand använda `create_x402_payment_handler`.
