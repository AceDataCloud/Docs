OpenAI har nyligen tillhandahållit ett gränssnitt för att skapa modellsvar. Tillhandahåll text- eller bildindata för att generera text- eller bildutdata. Låt modellen anropa din egen anpassade kod eller använda inbyggda verktyg, såsom webbsökning eller filsökning, för att använda dina egna data som indata för modellsvar.

Detta dokument introducerar främst användningsprocessen för OpenAI Responses API-operationer, med hjälp av det kan vi enkelt använda den officiella OpenAI-funktionen för att skapa modellsvar.

## Ansökningsprocess

För att använda OpenAI Responses API, gå först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API Token och spara den som reserv.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig, kommer du automatiskt att omdirigeras till inloggningssidan där du uppmanas att registrera dig och logga in, och när det är klart återvänder du automatiskt till den aktuella sidan.

**En API Token kan anropa alla plattformens tjänster, utan att behöva ansöka separat för varje tjänst.** Vid första ansökan får du gratis kredit och kan uppleva tjänsten kostnadsfritt; när krediten är otillräcklig kan du fylla på det allmänna saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Grundläggande användning

Därefter kan du fylla i motsvarande innehåll i gränssnittet, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

När vi använder detta gränssnitt för första gången behöver vi minst fylla i tre innehåll, ett är `authorization`, som kan väljas direkt i rullgardinslistan. En annan parameter är `model`, `model` är den modellkategori på OpenAI ChatGPT:s officiella webbplats som vi väljer att använda, här har vi främst 20 modeller, detaljer kan ses i de modeller vi tillhandahåller. Den sista parametern är `input`, `input` är den array av frågeord som vi matar in, den är en array, vilket innebär att flera frågeord kan laddas upp samtidigt, varje frågeord innehåller `role` och `content`, där `role` anger frågeställarens roll, vi tillhandahåller tre identiteter, nämligen `user`, `assistant`, `system`. Den andra `content` är det konkreta innehållet i vår fråga.

Samtidigt kan du notera att det finns motsvarande generering av anropskod till höger, du kan kopiera koden och köra den direkt, eller också direkt klicka på knappen ”Try” för att testa.

Vanliga valfria parametrar:

- `max_tokens`: Begränsar det maximala antalet tokens i ett enskilt svar.
- `temperature`: Genereringsslumpmässighet, mellan 0 och 2, ju större värde desto mer divergent.
- `n`: Hur många kandidatsvar som genereras på en gång.
- `response_format`: Inställning för returformat.
- `tools`: Definition för funktions-/verktygsanrop.
- `background`: Om det ska köras asynkront i bakgrunden.

## Strömmande svar

Detta gränssnitt stöder också strömmande svar, vilket är mycket användbart för webbanslutning och kan låta webbsidan uppnå en effekt där text visas tecken för tecken.

Om du vill returnera svar strömmande kan du ändra parametern `stream ` i begärandehuvudet till `true`.

Ändringen visas i bilden, men anropskoden behöver motsvarande ändringar för att stödja strömmande svar.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Efter att ha ändrat `stream` till `true` kommer API:t att returnera motsvarande JSON-data rad för rad, och på kodnivå behöver vi göra motsvarande ändringar för att få resultatet rad för rad.

Python-exempel på anropskod:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Du kan se att det finns mycket `data` i svaret, och `delta` i `data` är det senaste svarsinnhållet, vilket överensstämmer med innehållet som introducerades ovan. `delta` är det tillagda svarsinnhållet, och du kan integrera det i ditt system utifrån resultatet. Det strömmande svaret använder `response.completed` eller `response.incomplete` som slutstatus; `usage` i slutstatusen är den slutliga token-användningen för denna begäran och utgör även grunden för debitering.

Om klienten kopplar från innan slutstatusen har nåtts registreras denna begäran som klienten har stängt (499), och lokal uppskattad token-användning används inte för debitering; om anslutningen avslutas normalt men slutstatusen och slutlig `usage` inte tas emot registreras denna begäran som ofullständigt svar (502), och uppskattad token-användning används inte heller för debitering. När dessa två situationer uppstår, skicka begäran igen.

Det returnerade `data`-resultatet har flera fält, som introduceras nedan:

- `item_id`, ID:t som genereras för denna dialoguppgift och används för att unikt identifiera denna dialoguppgift.
- `type`, typen av den genererade Responses-uppgiften för denna dialog.
- `model `, den valda modellen från OpenAI ChatGPT:s officiella webbplats.
- `delta`, svarsinformationen som ChatGPT ger på frågan.

JavaScript stöds också, till exempel är koden för strömmande anrop i Node.js följande:

```javascript
const options = {
  method: "post",

  },

  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Visuell modell

gpt-4o är en multimodal stor språkmodell utvecklad av OpenAI, som har fått visuell förståelseförmåga på grundval av GPT-4. Denna modell kan samtidigt bearbeta text- och bildinmatningar och uppnår förståelse och generering över flera modaliteter.
Textbehandling med modellen gpt-4o är i grunden densamma som användningen som beskrivs ovan. Nedan följer en kort introduktion till hur man använder modellens bildbehandlingsfunktioner.

Bildbehandlingsfunktionerna i modellen gpt-4o används främst genom att lägga till ett fält `type` baserat på det ursprungliga `content`-innehållet. Genom detta fält kan man veta om det som laddas upp är text eller en bild, och därmed använda bildbehandlingsfunktionerna i modellen gpt-4o. Nedan beskrivs främst två sätt att anropa denna funktion: med Curl och Python.

- Curl-skriptmetod

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

## Felhantering

När API:et anropas, om ett fel uppstår, returnerar API:et motsvarande felkod och information. Till exempel:

- `400 token_mismatched`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.
