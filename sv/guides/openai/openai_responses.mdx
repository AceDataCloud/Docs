OpenAI har nyligen tillhandahållit ett gränssnitt för att skapa modellsvar. Tillhandahåll text- eller bildindata för att generera text- eller bildutdata. Låt modellen anropa din egen anpassade kod eller använda inbyggda verktyg, såsom webbsökning eller filsökning, för att använda dina egna data som indata för modellsvar.

Detta dokument introducerar huvudsakligen användningsprocessen för OpenAI Responses API. Med hjälp av det kan vi enkelt använda OpenAI:s officiella funktion för att skapa modellsvar.

## GPT-6.1 Sol

Använd `model: "gpt-6.1-sol"` för att välja denna modell. Den stöder strömmande utdata, funktionsanrop, strukturerade utdata och bildindata. Under den första veckan efter lanseringen är den endast tillgänglig för verifierade ACE T1+-innehavare (minst 100 000 ACE) eller auktoriserade användare; den specifika tillgänglighetstiden avgörs av åtkomstmeddelandet i konsolen.

Resonemangsnivåerna stöder `low`, `medium`, `high`, `xhigh` och `max`, och stöder för närvarande inte `none` eller `minimal`. Det rekommenderas att börja med `reasoning: {"effort": "low"}`. När indata överstiger 272 000 tokens tillämpas prissättning för lång kontext för hela begäran, och avgifterna följer det aktuella priset i konsolen.

## Ansökningsprocess

För att använda OpenAI Responses API går du först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API Token och spara den som reserv.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig kommer du automatiskt att omdirigeras till inloggningssidan för att registrera dig och logga in, och efter slutförandet återvänder du automatiskt till den aktuella sidan.

**En API Token kan anropa alla plattformens tjänster, utan att behöva ansöka separat för varje tjänst.** Vid första ansökan får du en gratis kvot för kostnadsfri testning; när kvoten är otillräcklig kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Grundläggande användning

Därefter kan du fylla i motsvarande innehåll i gränssnittet, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

När vi använder detta gränssnitt för första gången behöver vi minst fylla i tre saker. Den ena är `authorization`, som du kan välja direkt i rullgardinslistan. En annan parameter är `model`; `model` är den modellkategori från OpenAI ChatGPT:s officiella webbplats som vi väljer att använda. Här har vi huvudsakligen 20 modeller, och detaljer finns i modellerna vi tillhandahåller. Den sista parametern är `input`; `input` är matrisen av frågeord som vi matar in. Det är en matris, vilket innebär att flera frågeord kan laddas upp samtidigt. Varje frågeord innehåller `role` och `content`, där `role` anger frågeställarens roll. Vi tillhandahåller tre identiteter: `user`, `assistant` och `system`. Den andra, `content`, är det specifika innehållet i vår fråga.

Samtidigt kan du märka att det finns motsvarande genererad anropskod på höger sida. Du kan kopiera koden och köra den direkt, eller direkt klicka på knappen ”Try” för att testa.

Vanliga valfria parametrar:

- `max_tokens`: begränsar det maximala antalet tokens för ett enskilt svar.
- `temperature`: slumpmässighet vid generering, mellan 0 och 2; ju högre värde, desto mer spritt.
- `n`: hur många kandidatsvar som genereras på en gång.
- `response_format`: inställning för svarsformat.
- `tools`: definition av funktions-/verktygsanrop.
- `background`: om det ska köras asynkront i bakgrunden.

## Strömmande svar

Detta gränssnitt stöder även strömmande svar, vilket är mycket användbart för webbintegration och kan göra det möjligt för webbsidan att implementera en effekt där text visas tecken för tecken.

Om du vill returnera svar strömmande kan du ändra parametern `stream ` i begärans header till `true`.

Ändringen visas i bilden, men anropskoden behöver ändras motsvarande för att stödja strömmande svar.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Efter att ha ändrat `stream` till `true` returnerar API:t motsvarande JSON-data rad för rad. På kodnivå behöver vi göra motsvarande ändringar för att få resultatet rad för rad.

Exempel på anropskod i Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Du kan se att svaret innehåller många `data`, och `delta` i `data` är det senaste svarsinhållet, vilket överensstämmer med innehållet som presenterades ovan. `delta` är det nytillagda svarsinnhållet, och du kan integrera det i ditt system baserat på resultatet. Det strömmande svaret använder `response.completed` eller `response.incomplete` som slutstatus; `usage` i slutstatusen är den slutliga token-användningen för denna begäran och utgör även grunden för debitering.

Om klienten kopplar från innan slutstatusen har anlänt registreras denna begäran som klienten stängd (499), och lokal uppskattad token-användning används inte för debitering; om anslutningen avslutas normalt men slutstatusen och den slutliga `usage` inte tas emot registreras denna begäran som ofullständigt svar (502), och uppskattad token-användning används inte heller för debitering. När dessa två situationer uppstår ska du skicka begäran på nytt.

Det returnerade `data`-resultatet har flera fält, som beskrivs nedan:

- `item_id`, ID:t för den genererade konversationsuppgiften, som används för att unikt identifiera denna konversationsuppgift.
- `type`, typen för den genererade Responses-uppgiften för denna konversation.
- `model `, den valda modellen från OpenAI ChatGPT:s officiella webbplats.
- `delta`, svarsinformationen som ChatGPT ger för frågan.

JavaScript stöds också, till exempel är koden för strömmande anrop i Node.js följande:


## Visuell modell

gpt-4o är en multimodal stor språkmodell utvecklad av OpenAI. Den har utökats med visuell förståelseförmåga baserat på GPT-4. Denna modell kan samtidigt bearbeta text- och bildinmatning och möjliggör multimodal förståelse och generering.
Textbearbetning med modellen gpt-4o överensstämmer med det grundläggande användningsinnehållet ovan. Nedan ges en kort introduktion till hur man använder modellens bildbehandlingsfunktioner.

Bildbehandlingsfunktionerna i modellen gpt-4o används huvudsakligen genom att lägga till ett fält `type` till det ursprungliga innehållet i `content`. Genom detta fält kan man veta om det som laddas upp är text eller bild, och därmed använda bildbehandlingsfunktionerna i modellen gpt-4o. Nedan beskrivs huvudsakligen hur denna funktion anropas med de två metoderna Curl och Python.

- Curl-skriptmetod

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Python-skriptmetod

## Felhantering

Vid anrop av API:et, om ett fel uppstår, returnerar API:et motsvarande felkod och information. Till exempel:

- `400 token_mismatched`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.
