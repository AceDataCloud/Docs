OpenAI har nyligen tillhandahållit ett gränssnitt för att skapa modellsvar. Tillhandahåll text- eller bildindata för att generera text- eller bildutdata. Låt modellen anropa din egen anpassade kod eller använda inbyggda verktyg, såsom webbsökning eller filsökning, för att använda dina egna data som indata för modellsvar.

Detta dokument introducerar främst användningsprocessen för OpenAI Responses API. Med hjälp av det kan vi enkelt använda den officiella OpenAI-funktionen för att skapa modellsvar.

## Ansökningsprocess

För att använda OpenAI Responses API, hämta först din API Token från [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig omdirigeras du automatiskt till inloggningssidan för att registrera och logga in, och återvänder automatiskt till den aktuella sidan efter slutförandet.

**En API Token kan anropa alla plattformens tjänster, utan att behöva ansöka separat för varje tjänst.** Vid första ansökan får du en gratis kredit som kan användas för att prova tjänsten kostnadsfritt; när krediten inte räcker till kan du fylla på ditt allmänna saldo i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Grundläggande användning

Därefter kan du fylla i motsvarande innehåll i gränssnittet, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

När du använder detta gränssnitt för första gången behöver vi minst fylla i tre saker. Den ena är `authorization`, som du direkt kan välja i rullgardinslistan. En annan parameter är `model`, `model` är den officiella OpenAI ChatGPT-modellkategori som vi väljer att använda. Här har vi huvudsakligen 20 modeller, och du kan se de modeller vi tillhandahåller för mer information. Den sista parametern är `input`, `input` är den array med frågeord som vi matar in. Det är en array, vilket innebär att flera frågeord kan laddas upp samtidigt. Varje frågeord innehåller `role` och `content`, där `role` representerar frågeställarens roll. Vi erbjuder tre identiteter: `user`, `assistant` och `system`. Den andra, `content`, är det specifika innehållet i vår fråga.

Samtidigt kan du se att det finns motsvarande genererad anropskod till höger. Du kan kopiera koden och köra den direkt, eller klicka direkt på knappen ”Try” för att testa.

Vanliga valfria parametrar:

- `max_tokens`: Begränsar det maximala antalet token i ett enskilt svar.
- `temperature`: Slumpmässighet vid generering, mellan 0 och 2; ju högre värde, desto mer spritt.
- `n`: Hur många kandidatsvar som genereras åt gången.
- `response_format`: Inställning för returformat.
- `tools`: Definition av funktions-/verktygsanrop.
- `background`: Om den ska köras asynkront i bakgrunden.

## Strömmande svar

Detta gränssnitt stöder även strömmande svar, vilket är mycket användbart för webbintegration och gör det möjligt för webbsidor att visa text tecken för tecken.

Om du vill returnera svar strömmande kan du ändra parametern `stream ` i begärandehuvudet till `true`.

Ändringen visas i bilden, men anropskoden behöver motsvarande ändringar för att stödja strömmande svar.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Efter att `stream` har ändrats till `true` returnerar API:et motsvarande JSON-data rad för rad. På kodnivå behöver vi göra motsvarande ändringar för att få resultatet rad för rad.

Python-exempel på anropskod:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Du kan se att det finns många `data` i svaret, och `delta` i `data` är det senaste svarsinnhållet, vilket överensstämmer med innehållet som beskrivits ovan. `delta` är det tillagda svarsinnhållet, och du kan integrera det i ditt system baserat på resultatet. Strömmande svar använder `response.completed` eller `response.incomplete` som slutstatus; `usage` i slutstatusen är den slutliga token-användningen för denna begäran och utgör också grunden för debitering.

Om klienten kopplar från innan slutstatusen har nåtts, registreras denna begäran som klienten stängd (499), och lokal uppskattad token-debitering används inte; om anslutningen avslutas normalt men slutstatusen och slutlig `usage` inte tas emot, registreras denna begäran som ofullständigt svar (502), och uppskattad token-debitering används inte heller. När du stöter på dessa två situationer ska du skicka begäran igen.

Det returnerade `data`-resultatet har flera fält, som beskrivs nedan:

- `item_id`, ID:t för den genererade konversationsuppgiften, som används för att unikt identifiera denna konversationsuppgift.
- `type`, typen av den genererade Responses-uppgiften för denna konversation.
- `model `, den valda modellen från OpenAI ChatGPT:s officiella webbplats.
- `delta`, svarsinformationen som ChatGPT ger för frågan.

JavaScript stöds också, till exempel ser koden för strömmande anrop i Node.js ut så här:

```javascript
const options = {
  method: "post",
  headers: {

  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Visuell modell

gpt-4o är en multimodal stor språkmodell utvecklad av OpenAI. Den har lagt till visuell förståelseförmåga baserat på GPT-4. Denna modell kan samtidigt bearbeta text- och bildinmatningar och uppnår förståelse och generering över olika modaliteter.
Textbehandling med modellen gpt-4o är i grunden densamma som användningen som beskrivs ovan. Nedan följer en kort introduktion till hur man använder modellens bildbehandlingsfunktioner.

Bildbehandlingsfunktionerna i modellen gpt-4o används huvudsakligen genom att lägga till ett `type`-fält i det ursprungliga `content`-innehållet. Genom detta fält kan man avgöra om det som laddas upp är text eller en bild, och därmed använda bildbehandlingsfunktionerna i modellen gpt-4o. Nedan beskrivs huvudsakligen hur funktionen anropas med de två metoderna Curl och Python.

- Curl-skriptmetod

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

## Felhantering

När du anropar API:et, om ett fel uppstår, returnerar API:et motsvarande felkod och information. Till exempel:

- `400 token_mismatched`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`：Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`：För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`：Internt serverfel, något gick fel på servern.
