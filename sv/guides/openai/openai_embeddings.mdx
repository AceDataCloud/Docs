OpenAI:s ordinbäddningstjänst används för att generera ordinbäddningsresultat som representerar inmatad text.

Detta dokument introducerar främst användningsprocessen för OpenAI Embeddings API. Med hjälp av det kan vi skapa inbäddningsvektorer som representerar inmatad text。。

## Ansökningsprocess

För att använda OpenAI Embeddings API, gå först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API-token och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig, omdirigeras du automatiskt till inloggningssidan där du uppmanas att registrera dig och logga in. När det är klart återgår du automatiskt till den aktuella sidan.

**En API-token kan anropa alla tjänster på plattformen, utan att behöva ansöka separat för varje tjänst.** Vid första ansökan får du gratis kredit för att kunna prova tjänsten kostnadsfritt; när krediten inte räcker till kan du ladda på ett gemensamt saldo i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [OpenAI Embeddings API →](https://platform.acedata.cloud/documents/openai-embeddings)

## Grundläggande användning

Därefter kan du fylla i motsvarande innehåll i gränssnittet, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/4qtbvr.png" width="500" className="m-auto" /></p>

När vi använder detta gränssnitt för första gången behöver vi minst fylla i tre delar. Den ena är `authorization`, som kan väljas direkt i rullgardinslistan. En annan parameter är `model`; `model` är den officiella OpenAI-modellkategori vi väljer att använda. De modeller som för närvarande är tillgängliga är `text-embedding-3-small` och `text-embedding-3-large`. `text-embedding-ada-002` erbjuds inte längre; om ett befintligt vektorindex använder denna äldre modell kan det inte direkt blandas med vektorer från de nya modellerna, utan indexet måste byggas om. Den sista parametern är `input`, och `input` är den text som vi behöver omvandla till ordinbäddningar.

Samtidigt kan du se att det finns motsvarande genererad anropskod till höger. Du kan kopiera koden och köra den direkt, eller klicka direkt på knappen ”Try” för att testa.

Valfria parametrar:

- `dimensions`: beskär vektordimensioner, fullständig dimension returneras som standard.
- `encoding_format`: returformat, kan vara `float` eller `base64`.

<p><img src="https://cdn.acedata.cloud/gqulm9.png" width="500" className="m-auto" /></p>

Exempel på Python-anropskod:

```python
import requests

url = "https://api.acedata.cloud/openai/embeddings"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "input": "The food was delicious and the waiter...",
    "model": "text-embedding-3-small",
    "encoding_format": "float"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Returresultatet har flera fält, som introduceras nedan:

- `model`, modellen som används för att omvandla denna text till ordinbäddningar.
- `usage`, tokeninformationen som används för att omvandla denna text till ordinbäddningar.
- `data`, resultatet av ordinbäddningarna efter textomvandlingen.

Bland dessa är `data` den specifika informationen som innehåller ordinbäddningarna som motsvarar texten, och dess `embedding` är det specifika genererade resultatet för ordinbäddningarna.

## Felhantering

Vid anrop av API:t, om ett fel uppstår, returnerar API:t motsvarande felkod och information. Till exempel:

- `400 token_mismatched`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.

### Exempel på felsvar

```json

  },

}
```
