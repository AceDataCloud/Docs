## 3. Ladda upp lokal bild

Använd `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` kan skickas in upprepade gånger, GPT Image-serien stöder upp till 16 referensbilder. `image` i JSON-begäran kan vara en enskild URL eller en URL-array; lokala filer laddas upp med multipart.

### Modeller och faktureringsmetoder

| Modell                                | Tillämpliga scenarier och faktureringsmetoder                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | Standardkanal för omvänd teknik, fast debitering per antal lyckade bilder                               |
| `gpt-image-2:reverse`             | Väljer uttryckligen kanalen för omvänd teknik, fast debitering per antal lyckade bilder                             |
| `gpt-image-2:official`            | Officiell API-kanal, högre stabilitet, debitering enligt faktisk tokenanvändning                   |
| `gpt-image-2.5-flare`             | Fokus på genereringshastighet, fast debitering per antal lyckade bilder                               |
| `gpt-image-2.6-flare`             | Fokus på genereringshastighet, fast debitering per antal lyckade bilder                               |
| `gpt-image-2.5-flare:reverse`     | Uttryckligt alias för omvänd teknik, likvärdigt med `gpt-image-2.5-flare`, fast debitering per antal lyckade bilder    |
| `gpt-image-2.6-flare:reverse`     | Uttryckligt alias för omvänd teknik, likvärdigt med `gpt-image-2.6-flare`, fast debitering per antal lyckade bilder    |
| `gpt-image-2.5-flare:official`    | Officiell API-kanal, högre stabilitet och fokus på genereringshastighet, debitering enligt faktisk tokenanvändning            |
| `gpt-image-2.6-flare:official`    | Officiell API-kanal, högre stabilitet och fokus på genereringshastighet, debitering enligt faktisk tokenanvändning            |
| `gpt-image-2.5-sunburst`          | Fokus på hög återgivningstrohet och detaljerad kontroll, fast debitering per antal lyckade bilder                           |
| `gpt-image-2.6-sunburst`          | Fokus på hög återgivningstrohet och detaljerad kontroll, fast debitering per antal lyckade bilder                           |
| `gpt-image-2.5-sunburst:reverse`  | Uttryckligt alias för omvänd teknik, likvärdigt med `gpt-image-2.5-sunburst`, fast debitering per antal lyckade bilder |
| `gpt-image-2.6-sunburst:reverse`  | Uttryckligt alias för omvänd teknik, likvärdigt med `gpt-image-2.6-sunburst`, fast debitering per antal lyckade bilder |
| `gpt-image-2.5-sunburst:official` | Officiell API-kanal, högre stabilitet och fokus på hög återgivningstrohet och detaljerad kontroll, debitering enligt faktisk tokenanvändning        |
| `gpt-image-2.6-sunburst:official` | Officiell API-kanal, högre stabilitet och fokus på hög återgivningstrohet och detaljerad kontroll, debitering enligt faktisk tokenanvändning        |

Sidans pris för den officiella API-kanalen är en uppskattning före begäran, och det slutliga priset baseras på den faktiska tokenanvändningen i svaret och användningsregistren.

`quality` stöder `auto`, `low`, `medium`, `high`; 2.5 / 2.6 Flare och Sunburst (inklusive varianterna `:reverse` och `:official`) stöder dessutom `xhigh`, `max`. Både JSON-redigering med bild-URL och multipart-redigering av filer kan skicka in detta fält; den officiella kanalen debiteras enligt faktisk tokenanvändning.

## 4. Använd mask för lokal redigering

Det officiella Images Edit-gränssnittet anger området som får ändras via `mask`. Ace Data Clouds `:official`-modeller följer samma multipart-kontrakt:

- `mask` måste vara en PNG med alfakanal och får inte överstiga 4 MB;
- Maskens storlek måste vara exakt densamma som den första `image`;
- Transparanta pixlar med alfa `0` anger att redigering är tillåten, icke-transparenta pixlar anger att de ska behållas;
- RGB-bilder som endast är svartvita men saknar transparent kanal kan inte användas som giltiga masker;
- Prompten bör beskriva den kompletta önskade bilden och samtidigt tydligt ange den lokala ändringen och innehållet som behöver förbli oförändrat.

Generera först en mask från originalbilden nedan. Exemplet gör den centrala rektangeln transparent och tillåter endast modellen att ändra det området:
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Ladda sedan upp originalbilden och masken tillsammans:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Du kan också fortsätta använda anropssättet `images.edit` i OpenAI:s officiella Python SDK; du behöver bara peka `base_url` mot Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

När `mask` används måste originalbilden och masken laddas upp separat i samma multipart-begäran via `image=@input.png` och `mask=@mask.png`. Blanda inte en originalbild via URL med en lokal maskfil; rena URL-redigeringsbegäranden har inte stöd för att lägga till en lokal `mask`-fil. Masken begränsar redigeringsområdet, men genereringsmodellen kan fortfarande utföra naturlig sammanfogning vid kanterna; när strikta gränser krävs bör du använda tydliga Alpha-kanter och upprepa i prompten vilket innehåll som måste förbli oförändrat.

Ovanstående anropssätt överensstämmer med maskexemplen i [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) och [GPT Image officiella Cookbook](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Vanliga parametrar

| Fält                | Beskrivning                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (snabbare) eller `gpt-image-2.5-sunburst` (högre återgivningstrohet och kontroll); alla tre kan välja motsvarande `:official`-variant, och `gpt-image-2` har även stöd för `:reverse` |
| `image`           | JSON använder en enskild URL eller en array med upp till 16 URL:er; multipart använder ett eller flera `image`-filfält. När `mask` används måste lokala bildfiler laddas upp                                              |
| `mask`            | Valfri PNG-mask, endast för multipart-filuppladdning; måste ha Alpha-kanal, samma storlek som den första `image` och inte överstiga 4 MB                                                                 |
| `prompt`          | Redigeringsinstruktion                                                                                                                             |
| `size`            | `auto` eller `WIDTHxHEIGHT` som uppfyller begränsningarna                                                                                                     |
| `n`               | 1–10; endast 1 stöds när `response_format=b64_json` används                                                                                           |
| `response_format` | `url` eller `b64_json`                                                                                                               |
| `callback_url`    | Valfri asynkron callback-adress                                                                                                                         |

Storleksreglerna är desamma som för genereringsgränssnittet: bredd och höjd måste vara multiplar av 16, den längsta sidan får inte överstiga 3840, det totala antalet pixlar ska vara 655 360–8 294 400 och bildförhållandet får inte överstiga 3:1. När `size` utelämnas eller `auto` används väljer modellen format baserat på prompten och den första referensbilden.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` och deras `:reverse`-alias debiteras per antal framgångsrikt genererade bilder; `gpt-image-2:official`, `gpt-image-2.5-flare:official` och `gpt-image-2.5-sunburst:official` debiteras baserat på den faktiska tokenanvändningen för textinmatning, referensbildsinmatning och bildutmatning, med användningsloggen som slutgiltig grund.

## 6. Asynkrona callbacks och felsökning

Långa uppgifter kan inkludera följande i begäran:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Det asynkrona 200-svaret är `{"task_id": "..."}`; det slutliga resultatet skickas via callback när uppgiften är klar. Synkrona begäranden returnerar däremot `created` och `data`.

| Status  | Kontroll                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Bildformat/antal, parameterkombinationer och storleksformat; kontrollera PNG Alpha-kanalen, 4 MB-gränsen och att storleken matchar den första originalbilden när `mask` används |
| 401 | API Key och Bearer Header                                           |
| 429 | Begärandefrekvens                                                              |
| 504 | Byt till asynkron callback                                                            |

Felsvar innehåller `trace_id`. Ange detta ID när du rapporterar problem, men ange inte API Key.

Fullständiga fält och realtidsuppräkningar finns på sidan [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). För bildgenerering från ren text, se [GPT Image 2 / 2.5 / 2.6 bildgenerering](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 använder samma gränssnitt som 2.5 för generering, redigering, asynkrona uppgifter och debitering:

| Modell                                                          | Debitering                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0.22 Credits/bild                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0.22 Credits/bild                   |
| `gpt-image-2.6-flare:official`                              | Samma som 2.5 official, debiteras enligt faktisk tokenanvändning |
| `gpt-image-2.6-sunburst:official`                           | Samma som 2.5 official, debiteras enligt faktisk tokenanvändning |

Kvaliteten kan väljas som `auto`, `low`, `medium`, `high`, `xhigh`, `max`; för storlek används `auto` eller `WIDTHxHEIGHT` som uppfyller ovanstående begränsningar. Detta gränssnitt stöder `png`, `jpeg`, `webp`; GPT Image 2.6 stöder även inbyggda animerade `gif`-bilder, men SVG stöds för närvarande inte. Redigering stöder JSON-bild-URL:er och multipart-filuppladdning. `:reverse` är ett uttryckligt alias för den vanliga versionen med samma namn. Använd den fullständiga modellbeteckningen och skicka inte `gpt-image-2.6`.

### GPT Image 2.6 bild till animerad GIF
GPT Image 2.6 Flare, Sunbursts standardversion, `:reverse`, `:official` kan alla använda `output_format: "gif"`. Animationsbilder, loopinformation och uppspelningstid bevaras; `frame_count` anger antalet bildrutor, `frame_duration_ms` anger millisekunder per bildruta, antalet bildrutor måste vara ett heltal mellan 2–16, tiden per bildruta måste vara ett heltal mellan 20–655350 millisekunder, och används endast för GIF; kodningen avrundas till närmaste 10 ms. När det inte anges är standardvärdet 9 bildrutor, 200 millisekunder per bildruta; när GIF:s size utelämnas eller är auto används förinställningen 512x512.

Det rekommenderas att först använda `size: "512x512"`, `frame_count: 9`, `frame_duration_ms: 200`. GIF har separata begränsningar för storlek och antal bildrutor, och kan inte direkt använda statiska 4K-specifikationer; vissa modeller justerar den faktiska utdatastorleken. `n` anger antalet GIF-filer som returneras, inte antalet animationsbildrutor. Standardversionen och `:reverse` debiteras fortfarande enligt antalet lyckade filer, den officiella versionen debiteras enligt faktisk Token-användning.

```json
{
  "model": "gpt-image-2.6-flare",
  "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
  "prompt": "Animate the mug gently moving left and right. Keep its appearance and the background, no text.",
  "output_format": "gif",
  "size": "512x512",
  "quality": "medium",
  "frame_count": 9,
  "frame_duration_ms": 200,
  "n": 1,
  "async": true
}
```

### GPT Image 2.6 4K-stillbilder

Flare, Sunburst och deras `:reverse`-, `:official`-varianter kan alla använda de tidigare nämnda 4K-pixelförinställningarna, till exempel `3840x2160` och `2160x3840`. Både generering och redigering skickar in specifika pixlar via `size`; `4K` är inte ett giltigt `size`-värde, och `4096x4096` överskrider också den nuvarande pixelgränsen. Ovanstående 4K-specifikationer gäller för statiska PNG/JPEG/WebP, för GIF ska dess särskilda parametrar användas.

### GPT Image 2.6 kompositionskomplexitet

`complexity` kan vara `low`, `medium`, `high`, och när det utelämnas används modellens standardvärde `high`. Det styr planeringskomplexiteten och är oberoende av `quality`-renderingskvaliteten; det medför ingen extra debitering per gång, den officiella versionen debiteras fortfarande enligt faktisk Token-användning. Andra modeller stöder inte denna parameter.

GIF stöder inte mask, markeringsbild, anpassad komprimering, omskrivning av prompt eller partiell bildstreaming; inkompatibla kombinationer avvisas före generering. Storlek, antal bildrutor och antal begränsas gemensamt av modellens pixelbudget; standard-Flare med `1024x1024` och 2 bildrutor har verifierats fungera, men denna slutsats kan inte utvidgas till alla 1K-kombinationer eller 4K-GIF.

### Markeringsstyrd redigering

GPT Image 2.6 statisk redigering stöder `markup`. Ladda upp en transparent PNG med samma storlek som den första referensbilden, markera platsen som ska ändras i ett separat lager och beskriv ändringskraven i `prompt`. Markeringslagret måste innehålla transparenta pixlar; de två bilderna får vardera inte överstiga 16777216 pixlar, och markeringsbilden får inte överstiga 40MB. JSON kan skicka en HTTPS-URL, en PNG base64-data-URL eller `{ "image_url": "https://..." }`; multipart laddar upp filen via `markup`. Plattformen skickar markeringslagret i filformat. `markup` kan inte användas tillsammans med `mask`, GIF eller `prompt_rewriter`, och stöder inte `file_id`.

`input_fidelity` gäller inte för GPT Image 2.6, utelämna det.
