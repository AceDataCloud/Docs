## 2. Redigera med bild-URL

Originalbild:

![GPT Image 2 originalbild för redigering](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://platform2.cdn.acedata.cloud/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0.png",
```

## 3. Ladda upp lokal bild

Använd `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` kan skickas in upprepade gånger, och GPT Image-serien stöder upp till 16 referensbilder. `image` i JSON-förfrågningar kan vara en enskild URL eller en URL-array; lokala filer laddas upp via multipart.

## 4. Använd mask för lokal redigering

Det officiella Images Edit-gränssnittet anger området som får ändras via `mask`. Ace Data Clouds `:official`-modeller följer samma multipart-kontrakt:

- `mask` måste vara en PNG med Alpha-kanal och får inte vara större än 4 MB;
- maskstorleken måste vara exakt samma som den första `image`;
- transparenta pixlar med Alpha `0` anger att redigering är tillåten, medan icke-transparenta pixlar anger att innehållet ska behållas;
- RGB-bilder som endast är svartvita men saknar transparenskanal kan inte användas som giltiga masker;
- prompten bör beskriva den fullständiga önskade bilden, samtidigt som den lokala ändringen och innehållet som ska förbli oförändrat tydligt anges.

Skapa först en mask från originalbilden nedan. Exemplet gör den centrala rektangeln transparent och tillåter endast modellen att ändra det området:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Ladda sedan upp originalbilden och masken tillsammans:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Du kan också fortsätta använda OpenAI:s officiella Python SDK-anropssätt `images.edit`; du behöver bara peka `base_url` mot Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

När `mask` används måste originalbilden och masken laddas upp separat i samma multipart-förfrågan via `image=@input.png` respektive `mask=@mask.png`. Blanda inte URL-originalbilder med lokala maskfiler; rena URL-redigeringsförfrågningar stöder inte att ytterligare lokala `mask`-filer bifogas. Masken begränsar redigeringsområdet, men den generativa modellen kan fortfarande skapa naturliga övergångar vid kanterna; när strikta gränser krävs bör tydliga Alpha-kanter användas och prompten upprepat ange vilket innehåll som måste förbli oförändrat.

Ovanstående anropssätt överensstämmer med maskexemplen i [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) och [GPT Images officiella Cookbook](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Vanliga parametrar

| Fält                | Beskrivning                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (snabbare) eller `gpt-image-2.5-sunburst` (högre återgivningstrohet och kontroll); alla tre kan välja motsvarande `:official`-variant, och `gpt-image-2` stöder även `:reverse` |
| `image`           | JSON använder en enskild URL eller en array med upp till 16 URL:er; multipart använder ett eller flera `image`-filfält. Vid användning av `mask` måste lokala bildfiler laddas upp                                              |
| `mask`            | Valfri PNG-mask, endast för multipart-filuppladdning; måste ha Alpha-kanal, samma storlek som den första `image` och inte överstiga 4 MB                                                                 |
| `prompt`          | Redigeringsinstruktion                                                                                                                             |
| `size`            | `auto` eller `WIDTHxHEIGHT` som uppfyller begränsningarna                                                                                                     |
| `n`               | 1–10; när `response_format=b64_json` används stöds endast 1                                                                                           |
| `response_format` | `url` eller `b64_json`                                                                                                               |
| `callback_url`    | Valfri asynkron återanropsadress                                                                                                                         |
Storleksreglerna är samma som för genereringsgränssnittet: bredd och höjd måste vara multiplar av 16, den längsta sidan får inte överstiga 3840, det totala antalet pixlar är 655 360–8 294 400 och bildförhållandet får inte överstiga 3:1. När `size` utelämnas eller `auto` används väljer modellen bildformat baserat på prompten och den första referensbilden.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` och `gpt-image-2:reverse` debiteras per antal lyckade bilder; `gpt-image-2:official`, `gpt-image-2.5-flare:official` och `gpt-image-2.5-sunburst:official` debiteras utifrån faktisk Token-användning för textinmatning, referensbildsinmatning och bildutmatning, och den slutliga beräkningen baseras på användningsposterna.

## 6. Asynkrona återanrop och felsökning

Långa uppgifter kan lägga till följande i begäran:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Det asynkrona 200-svaret är `{"task_id": "..."}`; det slutliga resultatet skickas tillbaka via återanrop när uppgiften är klar. Synkrona begäranden returnerar i stället `created` och `data`.

| Status  | Kontrollera                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Bildformat/antal, parameterkombinationer och storleksformat; när `mask` används, kontrollera PNG Alpha-kanalen, gränsen på 4 MB och om dess storlek överensstämmer med den första originalbilden |
| 401 | API Key och Bearer Header                                           |
| 429 | Begärandefrekvens                                                              |
| 504 | Byt till asynkront återanrop                                                            |

Felsvar innehåller `trace_id`. Ange detta ID när du rapporterar problem, men ange inte API Key.

För fullständiga fält och realtidsuppräkningar, se sidan [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). För att generera bilder från enbart text, se [GPT Image 2 / 2.5 bildgenerering](https://platform.acedata.cloud/documents/openai-images-generations).
