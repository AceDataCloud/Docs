Denna artikel beskriver integration och användning av MiniMax H3 uppgiftsfråge API. Detta gränssnitt används för att fråga, lista eller ta bort [MiniMax H3 video-generering API](/documents/minimax-videos-integration) skapade asynkrona uppgifter.

## Ansökningsprocess

För att använda MiniMax H3 uppgiftsfråge API, börja med att gå till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API-token, som du ska spara för framtida bruk.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du inte är inloggad eller registrerad kommer du automatiskt att omdirigeras till inloggningssidan som bjuder in dig att registrera dig och logga in, och efter att ha slutfört detta kommer du automatiskt att återvända till den aktuella sidan.

**En API-token räcker för att anropa alla tjänster på plattformen, du behöver inte ansöka separat för varje tjänst.** Första ansökan ger en gratis kvot, så att du kan prova gratis; när kvoten är slut kan du ladda på allmän balans i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [MiniMax H3 Uppgiftsfråge API →](https://platform.acedata.cloud/documents/minimax-tasks-integration)

När du frågar efter uppgifter bör du använda samma token som skapade uppgiften. Det rekommenderas att spara token som en miljövariabel, skriv inte in den i källkoden eller skicka den till versionskontroll:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Gränssnittsöversikt

- **Bas-URL**: `https://api.acedata.cloud`
- **Endpoint**: `POST /minimax/tasks`
- **Autentisering**: HTTP-header med `authorization: Bearer {token}`
- **Begärningshuvud**:
  - `accept: application/json`
  - `content-type: application/json`
- **Fråga enskild uppgift**: `action=retrieve`, skicka in `id`
- **Batchfråga uppgifter**: `action=retrieve_batch`, kan filtreras efter uppgifts-ID, tidsintervall och pagineringsvillkor
- **Ta bort uppgift**: `action=delete`, skicka in `id`
- **Avgiftsbeskrivning**: Uppgiftsfrågor är gratis och genererar ingen dubbelavgift

Efter att ha skapat en video måste `task_id` sparas. Det rekommenderas att fråga var 10:e sekund tills uppgiften når ett slutligt tillstånd.

## Begärningsparametrar

| Parameter           | Typ       | Obligatorisk | Tillämpad åtgärd          | Beskrivning                                           |
| ------------------ | -------- | ------------ | ------------------------ | ---------------------------------------------------- |
| `action`           | string   | Nej          | Alla                    | `retrieve`, `retrieve_batch` eller `delete`; standard `retrieve` |
| `id`               | string   | Villkorligt  | `retrieve`, `delete`    | Enskilt uppgifts-ID                                   |
| `ids`              | string[] | Nej          | `retrieve_batch`        | Returnera endast angivna uppgifts-ID; om utelämnat, lista uppgifter enligt andra villkor |
| `limit`            | integer  | Nej          | `retrieve_batch`        | Max antal uppgifter som returneras denna gång        |
| `offset`           | integer  | Nej          | `retrieve_batch`        | Antal uppgifter som ska hoppas över i resultatlistan, används för paginering |
| `created_at_min`   | number   | Nej          | `retrieve_batch`        | Lägsta skapelsedatum, Unix-tidsstämpel, i sekunder  |
| `created_at_max`   | number   | Nej          | `retrieve_batch`        | Högsta skapelsedatum, Unix-tidsstämpel, i sekunder  |

De tre åtgärdernas syften är som följer:

| `action`           | Syfte                          | Nödvändiga parametrar                | Svarsstruktur                               |
| ------------------ | ----------------------------- | ------------------------------------ | ------------------------------------------ |
| `retrieve`         | Fråga status och resultat för en uppgift | `id`                                | `{ "task": {...} }`                        |
| `retrieve_batch`   | Batchfråga efter uppgifts-ID, tid och pagineringsvillkor | Valfria `ids`, tidsintervall, `offset`, `limit` | `{ "items": [...], "total": number }`     |
| `delete`           | Avbryt eller ta bort uppgiftspost baserat på nuvarande status | `id`                                | `{ "id": "...", "deleted": true }`        |

## Fråga enskild uppgift

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f5977217-ed2c-40da-adbe-93d08235618f"
  }'
```

## Uppgiftsstatus

| `status`    | Betydelse                  | Klienthantering                |
| ----------- | ------------------------- | ------------------------------ |
| `queued`    | Har kommit in i kön, väntar på att utföras | Fortsätt att fråga              |
| `running`   | Håller på att generera     | Fortsätt att fråga              |
| `succeeded` | Generering lyckades        | Läs `task.content.url`, sluta fråga |
| `failed`    | Generering misslyckades     | Läs `task.error`, sluta fråga   |
| `cancelled` | Uppgiften har avbrutits    | Sluta fråga                    |

`succeeded`, `failed` och `cancelled` är alla slutliga tillstånd. Fortsätt inte att fråga efter att ha nått ett slutligt tillstånd.

## task Svarsfält

| Fält                        | Typ      | Beskrivning                          |
| ------------------------- | ------- | ----------------------------------- |
| `id`                      | string  | Uppgifts-ID                         |
| `model`                   | string  | Modellen som används för uppgiften, för närvarande `MiniMax-H3` |
| `status`                  | string  | Aktuell uppgiftsstatus              |
| `error.code`              | string  | Felkod vid misslyckande, returneras endast vid misslyckande |
| `error.message`           | string  | Orsak till misslyckande, returneras endast vid misslyckande |
| `created_at`              | integer | Skapelsedatum, Unix-tidsstämpel, i sekunder |
| `updated_at`              | integer | Senaste statusuppdatering, Unix-tidsstämpel, i sekunder |
| `content.url`             | string  | Videoadress efter lyckad generering |
| `resolution`              | string  | Utdataupplösning, `768P` eller `2K` |
| `duration`                | integer | Utdata videolängd, i sekunder      |
| `usage.total_seconds`     | integer | Totala kostnader, lika med summan av in- och utdata sekunder |
| `usage.input_seconds`     | integer | Kostnader för indata video         |
| `usage.output_seconds`    | integer | Kostnader för utdata video         |
| `usage.input_image_count` | integer | Antal indata bilder i kostnadsstatistik |
| `ratio`                   | string  | Faktisk utdata bildförhållande; när `adaptive` används, är detta resultatet |
| `task_type`               | string  | Videogenereringsuppgift är `generation` |
| `modality`                | string  | Videouppgift är `video`           |

## Python Polling Fullständigt Exempel
以下代码 från miljövariabler läser Token, skapar en uppgift och frågar var 10:e sekund:

```python
import os
import time

import requests

BASE_URL = "https://api.acedata.cloud"
HEADERS = {
    "Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_KEY']}",
    "Content-Type": "application/json",
}

create_response = requests.post(
    f"{BASE_URL}/minimax/videos",
    headers=HEADERS,
    json={
        "model": "MiniMax-H3",
        "content": [
            {
                "type": "text",
                "text": "Vid havet på morgonen, en vit segelbåt glider över den stilla havsytan, kameran rör sig långsamt horisontellt",
            }
        ],
        "resolution": "768P",
        "duration": 4,
        "ratio": "16:9",
    },
    timeout=30,
)
create_response.raise_for_status()
task_id = create_response.json()["task_id"]

while True:
    time.sleep(10)
    query_response = requests.post(
        f"{BASE_URL}/minimax/tasks",
        headers=HEADERS,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    query_response.raise_for_status()
    task = query_response.json()["task"]
    print(f"task={task_id} status={task['status']}")

    if task["status"] == "succeeded":
        print(f"video_url={task['content']['url']}")
        break
    if task["status"] in ("failed", "cancelled"):
        raise RuntimeError(task.get("error") or task["status"])
```

Produktionsmiljön bör ha en total timeout för polling och använda exponentiell backoff för `429` och temporära `5xx`. Nätverks timeout innebär inte att genereringen har misslyckats, samma `task_id` kan användas för att fortsätta fråga.

## Batchfråga

Ange flera uppgifts-ID:

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve_batch",
    "ids": ["TASK_ID_1", "TASK_ID_2"],
    "offset": 0,
    "limit": 20
  }'
```

Lista uppgifter i paginerad form baserat på tidsintervall:

```json
{
  "action": "retrieve_batch",
  "created_at_min": 1786000000,
  "created_at_max": 1786200000,
  "offset": 0,
  "limit": 20
}
```

I batchsvaret används `items` samma task-fält som för enstaka uppgiftsfrågor, `total` är det totala antalet uppgifter som matchar filtreringsvillkoren:

```json
{
  "items": [
    {
      "id": "TASK_ID_1",
      "model": "MiniMax-H3",
      "status": "running",
      "resolution": "2K",
      "duration": 5,
      "ratio": "adaptive",
      "task_type": "generation",
      "modality": "video"
    }
  ],
  "total": 1
}
```

Uppgiftsfrågevindue är de senaste 7 dagarna. `task_id` som överskrider detta fönster kan returnera ogiltiga uppgifter; affärssystemet bör spara ID vid skapandet av uppgifter och snabbt persistenta resultat-URL:er efter framgång.

## Avbryta eller ta bort uppgifter

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "delete",
    "id": "YOUR_TASK_ID"
  }'
```

Åtgärden beror på uppgiftens nuvarande status:

| Nuvarande status | Beteende                     |
| ---------------- | ---------------------------- |
| `queued`         | Avbryt uppgifter som inte har påbörjats |
| `succeeded`      | Ta bort uppgiftsposten      |
| `failed`         | Ta bort uppgiftsposten      |
| `running`        | Ej tillåten att ta bort eller avbryta, returnera fel |
| `cancelled`      | Ej tillåten att upprepa åtgärden, returnera fel |

Exempel på lyckad borttagning:

```json
{
  "id": "YOUR_TASK_ID",
  "deleted": true
}
```

Att ta bort uppgiftsposten återkallar inte redan genomförd debitering och kan inte garantera att redan sparade videokopior också tas bort.

## Misslyckade svar och felsökning

Misslyckade uppgifter returneras fortfarande med HTTP 200 och ger task-objektet, och orsaken anges i `task.error`:

```json
{
  "task": {
    "id": "YOUR_TASK_ID",
    "model": "MiniMax-H3",
    "status": "failed",
    "error": {
      "code": "1026",
      "message": "videobeskrivningen innehåller känsligt innehåll"
    },
    "task_type": "generation",
    "modality": "video"
  }
}
```

Om gränssnittet returnerar `400` bör `action` och villkorsparametrar kontrolleras, `401` indikerar att Token är ogiltig, `429` indikerar att frågorna är för frekventa, `500` indikerar att tjänsten är tillfälligt otillgänglig. Misslyckade uppgifter debiteras inte; framgångsrika uppgifter registreras enligt den slutliga `usage`.
