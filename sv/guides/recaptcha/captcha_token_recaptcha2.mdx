Denna artikel kommer att introducera en Recaptcha2 protokolligenkänning API integration instruktion, som gör att användare kan genomföra verifiering utan att behöva identifiera och klicka på Recaptcha2 verifieringsbilden, utan endast genom att skicka in Website Key för att möjliggöra automatisk avkodning i bakgrunden.

## Ansökningsprocess

För att använda Recaptcha2 protokolligenkänning API, börja med att gå till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API-token, som du kan spara för framtida bruk.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du inte är inloggad eller registrerad kommer du automatiskt att omdirigeras till inloggningssidan för att registrera dig och logga in, och efter att ha slutfört detta kommer du automatiskt att återvända till den aktuella sidan.

**En API-token räcker för att anropa alla plattformens tjänster, det behövs ingen separat ansökan för varje tjänst.** Första ansökan ger en gratis kvot, så att du kan prova gratis; när kvoten är slut kan du ladda på allmän balans i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Recaptcha2 protokolligenkänning API →](https://platform.acedata.cloud/documents/captcha-token-recaptcha2)

## Grundläggande användning

Först bör du förstå den grundläggande användningsmetoden, vilket är att ange URL:en för den webbplats som behöver hantera verifieringskoden, så får du det bearbetade resultatet. Först behöver du enkelt skicka ett `website_url` fält, vår exempelwebbplats är: `https://www.google.com/recaptcha/api2/demo`, vi behöver hämta `website_key` från `website_url`-sidan, först öppna denna webbsida, tryck på F12 för att gå till konsolen, och gör sedan en global sökning på Element-sidan efter `recaptcha-demo`, så får vi följande resultat:

<p><img src="https://cdn.acedata.cloud/hvx41c.png" width="500" className="m-auto" /></p>

Där `data-sitekey` motsvarar en sträng som är värdet av `website_key`, nedan är de specifika parameterresultaten:

<p><img src="https://cdn.acedata.cloud/8oowyw.png" width="500" className="m-auto" /></p>

Här kan vi se att vi har ställt in Request Headers, inklusive:

- `accept`: vilken typ av svar du vill ta emot, här anges `application/json`, det vill säga JSON-format.
- `authorization`: nyckeln för att anropa API, efter ansökan kan du direkt välja från rullgardinsmenyn.

Dessutom har vi ställt in Request Body, inklusive:

- `website_url`: URL:en för den webbplats som behöver hantera verifieringskoden.
- `website_key`: webbplatsens nyckelidentifierare i Recaptcha2.
- `proxy`: valfritt, ta med egen proxy (Bring Your Own Proxy). När det är inställt kommer upstream att använda den proxy-IP du tillhandahåller för att lösa verifieringskoden, för att kontrollera kvaliteten på utgångs-IP (till exempel för att undvika att den offentliga proxy-IP:n blockeras av målsidan och returnerar `410 Gone`). Formatet är `scheme://[user:pass@]host:port`, där `scheme` stöder `http`/`https`/`socks4`/`socks5`, till exempel `http://user:pass@1.2.3.4:8080`. Om det inte fylls i används plattformens standardproxy.

Nästa steg är att tillhandahålla en Python-version som skickar den behandlade token till målsidan för att passera Recaptcha2-koden.

Först behöver vi ta reda på hur webbplatsen skickar POST-begäran, så att vi kan föra in den genererade token. Vi behöver först öppna F12-konsolen och sedan manuellt genomföra verifieringen. Slutligen kan vi se att webbplatsen skickade en POST-begäran, och vi behöver bara titta på konstruktionen av denna POST-begäran. Den specifika processen är som följer:

- Genomför först verifieringen manuellt, som visas i bilden nedan:

- Klicka sedan på skicka, och observera förändringarna i nätverket i konsolen, som visas i bilden nedan:
<p><img src="https://cdn.acedata.cloud/6hm5kj.png" width="500" className="m-auto" /></p>

- Analysera konstruktionen av POST-förfrågan i denna inlämning, och du kan högerklicka på förfrågan för att kopiera CURL-koden, som visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/m7y35w.png" width="500" className="m-auto" /></p>

Från bilden ovan kan vi se att URL:en för denna POST-förfrågan är: `https://www.google.com/recaptcha/api2/demo`, vi behöver bara skicka parametern `g-recaptcha-response`, och sedan behöver vi bara överföra den bearbetade token i datan nedan, CURL-koden för att anropa token för verifiering ser ut som följer:

```shell
curl 'https://www.google.com/recaptcha/api2/demo' \
  --data-raw 'g-recaptcha-response={token}’
```

Koden för att anropa token-verifiering i Python ser ut som följer:

```python
import requests

token = '{token}'

data = {
    'g-recaptcha-response': token,
}

response = requests.post('https://www.google.com/recaptcha/api2/demo', data=data)

if response.status_code:
    print(response.text)

```

Sedan kör vi koden och observerar att konsolen visar ett sådant resultat:

<p><img src="https://cdn.acedata.cloud/ku22tk.png" width="500" className="m-auto" /></p>

Till slut har vi genomfört verifieringen av Recaptcha2-koden.

Om du vill generera motsvarande integrationskod kan du direkt kopiera den som genereras, till exempel CURL-koden ser ut som följer:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo"
}'
```

Python-integrationskoden ser ut som följer:

```python
import requests

url = "https://api.acedata.cloud/captcha/token/recaptcha2"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
    "website_url": "https://www.google.com/recaptcha/api2/demo"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynkront läge (async)

Som standard är API:et synkront och blockerande: en förfrågan kommer att vänta tills token-behandlingen är klar innan den returneras. Om du gör en multipel kodare rotation (multi-solver rotation) och vill "få task_id omedelbart efter att ha skickat uppgiften, först schemalägga andra kodare och sedan återkomma för att hämta resultatet", kan du skicka `async: true` i begäran.

Genom att skicka `async: true` kommer gränssnittet omedelbart att returnera ett `task_id` utan att blockera väntan:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

Använd sedan detta `task_id` för att pollera `POST /captcha/tasks` (rekommenderas var 3-5 sekund) för att hämta resultatet:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Under bearbetning kommer det att returnera `status: processing`:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

När bearbetningen är klar kommer det att returnera `status: ready` och token:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "token": "03AFcWeA5kjJyDQ9S1a9UYimR6nuxnpEnAs5x2Pixao0dXZhMB......"
}
```

Avgiftsinformation: I asynkront läge debiteras inte skapandet av uppgifter och polling "bearbetning"; **debiteras endast en gång när resultatet har hämtats framgångsrikt** (samma pris som i synkront läge). Därför kommer avbokning av uppgifter som ännu inte har slutförts under rotationen inte att medföra kostnader. `/captcha/tasks` är gemensam för alla captcha-gränssnitt (token och recognition-serier) och du kan pollera med samma `task_id`.

## Felhantering

När du anropar API:et, om du stöter på fel, kommer API:et att returnera motsvarande felkod och information. Till exempel:

- `400 token_mismatched`: Bad request, möjligtvis på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Bad request, möjligtvis på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många förfrågningar, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.

### Exempel på felrespons

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
