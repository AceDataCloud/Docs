Denna artikel kommer att introducera en digital engelsk verifieringskod igenkänning API integration instruktion, som är baserad på djupinlärningsteknik och kan användas för att känna igen variabla längd engelska siffror och bokstäver verifieringskoder. Inmatning av verifieringskodens bildinnehåll ger utdata av verifieringskodens resultat.

## Ansökningsprocess

För att använda den digitala engelska verifieringskod igenkänning API, börja med att gå till [Ace Data Cloud kontrollpanelen](https://platform.acedata.cloud/console/applications) för att få din API-token, som du ska spara för framtida bruk.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Om du inte har loggat in eller registrerat dig, kommer du automatiskt att omdirigeras till inloggningssidan som bjuder in dig att registrera dig och logga in, och efter att ha slutfört detta kommer du automatiskt att återvända till den aktuella sidan.

**En API-token kan användas för att anropa alla tjänster på plattformen, utan att behöva ansöka separat för varje tjänst.** Första ansökan ger en gratis kvot för att prova; när kvoten är slut kan du ladda på allmän balans i [kontrollpanelen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Digital engelsk verifieringskod igenkänning API →](https://platform.acedata.cloud/documents/captcha-recognition-image2text)

## Grundläggande användning

Först bör du förstå den grundläggande användningsmetoden, vilket innebär att du matar in den bild av den variabla längden engelska siffror och bokstäver verifieringskoden som behöver bearbetas, så får du det bearbetade resultatet. Först behöver du enkelt överföra ett `image`-fält, vilket är den specifika bilden av den engelska siffrorna och bokstäver verifieringskoden, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/c50hi9.png" width="500" className="m-auto" /></p>

Sedan behöver vi konvertera verifieringskodens bild till Base64-kodad verifieringskodens bild. För att konvertera till Base64-kod rekommenderas det att använda Google Chrome-tillägget FeHelper, och den specifika användningen kan refereras till bilden nedan:

<p><img src="https://cdn.acedata.cloud/zy2jwh.png" width="500" className="m-auto" /></p>

<p><img src="https://cdn.acedata.cloud/pr73gn.png" width="500" className="m-auto" /></p>

<p><img src="https://cdn.acedata.cloud/ic4dbw.png" width="500" className="m-auto" /></p>

Därefter kan du kopiera den Base64-kod som erhållits från Google Chrome-tillägget FeHelp, kom ihåg att den inte inkluderar prefixet data:image/png;base64, den specifika innehållet är som följer:

<p><img src="https://cdn.acedata.cloud/5h4x4w.png" width="500" className="m-auto" /></p>

Här kan vi se att vi har ställt in Request Headers, inklusive:

- `accept`: vilken format av svarresultat du vill ta emot, här fylls det i som `application/json`, det vill säga JSON-format.
- `authorization`: nyckeln för att anropa API, efter ansökan kan du direkt välja från rullgardinsmenyn.

Dessutom har vi ställt in Request Body, inklusive:

- `image`: Base64-kodad verifieringskodens bild (utan prefixet data:image/png;base64).

När du har valt kan du se att motsvarande kod också har genererats till höger, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/202y3d.png" width="500" className="m-auto" /></p>

Klicka på "Try" knappen för att testa, som visas i bilden ovan, här har vi fått följande resultat:

```json
{
  "text": "7364"
}
```

Det returnerade resultatet har flera fält, som beskrivs nedan:

- `text`, textinnehållet efter att ha bearbetat den variabla längden engelska siffrorna och bokstäver verifieringskodens bild.

Vi kan se att vi har fått verifieringsresultatet för den bearbetade variabla längden engelska siffrorna och bokstäver verifieringskodens bild, vi behöver bara använda textinnehållet i `text` för att klara verifieringen.

Om du vill generera motsvarande integrationskod kan du direkt kopiera den som genererats, till exempel CURL-koden är som följer:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/recognition/image2text' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image": "iVBORw0KGgoAAAANSUhEUgAAAgUAAAE3CAYAAAA6xjI2AAAAAX..."
}'
```

Python integrationskoden är som följer:

```python
import requests

url = "https://api.acedata.cloud/captcha/recognition/image2text"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "image": "iVBORw0KGgoAAAANSUhEUgAAAgUAAAE3CAYAAAA6xjI2AAAAAX..."
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynkron läge (async)

Som standard är API:et synkront och blockerande: en begäran kommer att vänta tills igenkänningens resultat har bearbetats klart innan det returneras. Om du gör en rotation av flera kodare (multi-solver rotation) och vill "skicka uppgiften och omedelbart få task_id, först schemalägga andra kodare och sedan återvända för att hämta resultatet senare", kan du skicka in `async: true` i begärningskroppen.

När du skickar in `async: true` kommer gränssnittet omedelbart att returnera ett `task_id`, utan att blockera och vänta:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/recognition/image2text' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image": "iVBORw0KGgoAAAANSUhEUgAAAgUAAAE3CAYAAAA6xjI2AAAAAX...",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

Använd sedan det `task_id` för att pollera `POST /captcha/tasks` (rekommenderas var 3-5 sekund) för att hämta resultatet:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Under bearbetning kommer det att returnera `status: processing`:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

När bearbetningen är klar kommer det att returnera `status: ready` och igenkänningsresultatet `text` (fältstrukturen är helt identisk med det synkrona läget):

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "text": "7364"
}
```

Avgiftsbeskrivning: I asynkront läge debiteras inte skapandet av uppgifter och polling "bearbetning" avgifter; **endast när du framgångsrikt får igenkänningsresultatet debiteras en gång** (samma pris som det synkrona läget). Därför kommer avbokning av uppgifter som inte har slutförts under rotationen inte att medföra kostnader. `/captcha/tasks` är gemensam för alla verifieringskod API:er (token och igenkänning serie) och du kan pollera med samma `task_id`.

## Felhantering

När du anropar API:et, om du stöter på fel, kommer API:et att returnera motsvarande felkod och information. Till exempel:

- `400 token_mismatched`: Bad request, möjligtvis på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Bad request, möjligtvis på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många begärningar, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.

### Exempel på felrespons
```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "hämtning misslyckades"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
