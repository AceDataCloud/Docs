Det här dokumentet har ett enda mål: att låta dig **på 5 minuter** använda AceData Cloud-proxy för att köra ditt första Claude Code-kommando. Kompletta guider finns i respektive IDE-dokument ([VS Code](https://platform.acedata.cloud/documents/claude-code-vscode-integrations) / [Cursor](https://platform.acedata.cloud/documents/claude-code-cursor-integration) / [JetBrains](https://platform.acedata.cloud/documents/claude-code-jetbrains-integrations)); här går vi bara igenom den snabbaste vägen med "**Terminal CLI** + **VS Code-tillägg**".

> **Varför använda AceData Cloud som proxy för Claude Code**:
> - Direktanslutning inom Kina, inget behov av egen VPN
> - Lägre pris jämfört med officiellt (debitering baserat på plattformens token)
> - Samma nyckel stödjer både Claude Messages API + Claude Code Token-protokoll

## Minut 1: Ansök om autentiseringsuppgifter

Öppna [Claude Messages-tjänstsidan](https://platform.acedata.cloud/documents/claude-messages) och klicka på knappen "**Acquire**":

![](https://cdn.acedata.cloud/nyq0xz.png)

Plattformen skapar automatiskt en Application åt dig och ger gratis kvot. Notera **Base URL** + **API Token** från detaljsidan — du behöver dessa i de följande stegen.

| Fält | Värde | Användning |
|------|-------|------------|
| `BASE_URL` | `https://api.acedata.cloud` | Ingång för Claude Messages-kompatibilitet |
| `API_TOKEN` | `sk-...` (kan kopieras från detaljsidan) | Anthropic-kompatibel autentiseringstoken |

## Minut 2: Installera Claude Code

macOS / Linux / WSL:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows (PowerShell):

```powershell
irm https://claude.ai/install.ps1 | iex
```

När installationen är klar, öppna en ny terminal och verifiera:

```bash
claude --version
```

> Om du ser versionsnumret är allt okej. Claude Code levereras med inbyggd Node.js-runtime och är inte beroende av Node-versionen på din maskin.

## Minut 3: Pekar miljövariablerna mot AceData Cloud

Hoppa över den officiella `claude login`-processen och skriv över med miljövariabler. Välj ett av följande två sätt:

**Alternativ A: Temporärt (endast aktuell shell-session)**

```bash
export ANTHROPIC_BASE_URL="https://api.acedata.cloud"
export ANTHROPIC_AUTH_TOKEN="sk-din-token"
```

**Alternativ B: Permanent (rekommenderas)**

Lägg till ovanstående två rader i `~/.zshrc` eller `~/.bashrc` och kör sedan `source` på filen.

> **Vanligt misstag**: Miljövariabeln heter `ANTHROPIC_AUTH_TOKEN`, inte `ANTHROPIC_API_KEY`; fel namn gör att Claude Code faller tillbaka till den officiella endpointen och ger 401.

## Minut 4: Kör ditt första kommando

Gå till valfri Git-repo och kör:

```bash
claude
```

Om du uppmanas att logga in första gången, tryck `Esc` för att hoppa över. Skriv sedan:

```
Lista beroenden i det aktuella projektet och förklara kort vad varje används till.
```

Normalt kommer Claude att använda verktyg som `read_file` / `glob` / `grep` för att undersöka repot och sedan ge dig en lista. Om modellen svarar korrekt och inte ger 401, betyder det att proxyn fungerar.

## Minut 5: Koppla även VS Code-tillägget

1. Öppna VS Code → Extensions-panel → sök efter `Claude Code` och installera det officiella Anthropic-tillägget;
2. Starta om VS Code eller kör `Developer: Reload Window` i kommandopaletten för att ladda in `~/.claude/settings.json` som du konfigurerade i minut 3;
3. Klicka på ✦ Spark-ikonen uppe till höger i editorn eller på statusfältet där det står "✱ Claude Code" för att öppna panelen;
4. Första gången kan du bli ombedd att logga in med ett officiellt konto, tryck `Esc` för att hoppa över — tillägget använder automatiskt `ANTHROPIC_BASE_URL` och `ANTHROPIC_AUTH_TOKEN` från minut 3.

> **Tips**: VS Code-tillägget och CLI delar samma `~/.claude/settings.json`, så du behöver inte konfigurera det separat i VS Code. Vill du använda projekt-specifik konfiguration kan du skapa `.claude/settings.local.json` i repo-roten (den är gitignored).

När det fungerar kan du dra filer i panelen för att ställa frågor och använda `@-mention` för att referera filer vid ändringsförslag. All debitering sker via AceData Cloud.

## Verifiera att du verkligen använder proxyn

Starta en gång med `--debug` för att kontrollera att förfrågningarna går till AceData Cloud:

```bash
claude --debug -p "say hi" 2>&1 | grep -iE 'base.?url|api\.acedata|anthropic\.com' | head
```

Om du ser `https://api.acedata.cloud` betyder det att proxyn är aktiv; om du ser `api.anthropic.com` eller får 401, gå tillbaka till minut 3 och kontrollera att miljövariabeln heter `ANTHROPIC_AUTH_TOKEN` (inte `ANTHROPIC_API_KEY`) och att `~/.claude/.credentials.json` inte innehåller någon officiell token (ta bort filen om så är fallet).

## 5 vanligaste frågorna

**Q: Jag körde `claude login` men ändrade sedan miljövariablerna till AceData, varför fungerar det inte?**  
A: `claude login` sparar officiell token i `~/.claude/.credentials.json`, vilket har högre prioritet än miljövariabler. Ta bort den filen och kör `source ~/.zshrc` igen.

**Q: Kan jag använda modellnamn som `--model claude-opus-4-7`?**  
A: Ja. AceData Cloud-proxyn vidarebefordrar model-fältet, alla offentliga Anthropic-modeller plus våra tillägg `claude-opus-4-7` / `claude-haiku-4-5` / `claude-sonnet-4-5` stöds.

**Q: Kan jag konfigurera flera profiler (privat + jobb)?**  
A: Ja. Claude Code stödjer flera profiler i `~/.claude/settings.json`; enklast är att definiera två shell-funktioner `claude_personal` / `claude_work` som exporterar olika `ANTHROPIC_AUTH_TOKEN` och sedan anropar `claude $@`.

**Q: Kan jag köra detta i GitHub Actions?**  
A: Ja. Se [Claude Code GitHub Actions-konfigurationsguide](https://platform.acedata.cloud/documents/claude-code-github-actions-integration).

**Q: Vad händer när gratiskvoten är slut?**  
A: Gå till [Application Management](https://platform.acedata.cloud/applications) → välj din Claude Application → Topup för att fylla på (debitering baserat på tokenförbrukning), eller byt till prenumerationsplan.
