Codex CLI är en öppen källkod lokal programmeringsagent lanserad av OpenAI, som körs i din terminal. Den kan läsa kod, ändra filer, köra kommandon, förklara fel och hjälpa till med dagliga utvecklingsuppgifter.

Codex CLI stöder anpassade modellleverantörer, och du kan använda den via en OpenAI Responses-kompatibel proxy som tillhandahålls av Ace Data Cloud, utan att behöva prenumerera på ett separat OpenAI-konto. När konfigurationen är klar skickar Codex CLI förfrågningar till `https://api.acedata.cloud/v1`.

## Ansökningsprocess

För att använda Codex CLI kan du först gå till [Ace Data Cloud Kontrollpanel](https://platform.acedata.cloud/console/applications) för att få din API Token, som du sparar för framtiden.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Om du inte är inloggad eller inte har registrerat dig, omdirigeras du automatiskt till inloggningssidan för att registrera och logga in. Efter inloggning och registrering återgår du automatiskt till den aktuella sidan.

Vid första ansökan får du en gratis kredit för att prova Codex CLI-tjänsten utan kostnad.

## Installera Codex CLI

Codex CLI stöder macOS, Linux, Windows och WSL. Du kan installera via npm eller använda Homebrew (endast macOS).

### npm-installation (rekommenderas)

Om du redan har Node.js installerat kan du installera direkt via npm. Denna metod kräver Node.js 18 eller senare.

```bash
npm install -g @openai/codex
```

### Homebrew-installation (macOS)

Mac-användare kan även använda Homebrew:

```bash
brew install --cask codex
```

### Kontrollera installationen

Efter installation, öppna om terminalen och kontrollera att kommandot fungerar:

```bash
codex --version
```

Om du får meddelandet `command not found`, är det troligt att den aktuella terminalen ännu inte har laddat den nya PATH. Stäng och öppna terminalen igen, eller kontrollera PATH-inställningarna i installationsutdata.

## Konfigurera Codex CLI

Efter installationen försöker Codex CLI som standard ansluta till OpenAI:s officiella tjänst. För att använda Ace Data Cloud måste du i Codex:s konfigurationsfil ange en anpassad `model_provider` och placera API Token i motsvarande miljövariabel.

### Steg 1: Sätt miljövariabel

Det rekommenderas att skriva API Token i din shell-konfigurationsfil, exempelvis `~/.zshrc`, `~/.bashrc` eller `~/.bash_profile`:

```bash
export ACEDATACLOUD_API_KEY="{token}"
```

Ersätt `{token}` med den API Token du kopierade från Ace Data Cloud Kontrollpanel.

Efter konfigurationen, öppna om terminalen eller kör:

```bash
source ~/.zshrc
```

### Steg 2: Redigera Codex-konfigurationsfil

Codex CLI använder `~/.codex/config.toml` som global konfigurationsfil. Om den inte finns, skapa den:

```bash
mkdir -p ~/.codex
touch ~/.codex/config.toml
```

Lägg till följande i `~/.codex/config.toml`:

```toml
model_provider = "acedatacloud"
model = "gpt-5"
model_reasoning_effort = "high"

[model_providers.acedatacloud]
name = "Ace Data Cloud"
base_url = "https://api.acedata.cloud/v1"
env_key = "ACEDATACLOUD_API_KEY"
wire_api = "responses"
```

Fältbeskrivning:

| Fält | Beskrivning |
| --- | --- |
| `model_provider` | Standardleverantörens namn, motsvarar nyckeln i `[model_providers.<name>]` |
| `model` | Standardmodellens ID |
| `model_reasoning_effort` | Tänkandets intensitet, vanliga värden är `low`, `medium`, `high` |
| `[model_providers.acedatacloud].base_url` | Ace Data Cloud:s OpenAI Responses-proxyadress |
| `[model_providers.acedatacloud].env_key` | Miljövariabelnamnet för API Token för Codex CLI |
| `[model_providers.acedatacloud].wire_api` | Protokolltyp, måste vara `responses` för OpenAI Responses API |

### Rensa cachead OpenAI-inloggning

Om du tidigare loggat in med ett OpenAI-konto kan det finnas en lokal cache (vanligen i `~/.codex/auth.json`). Innan du byter till Ace Data Cloud rekommenderas att rensa den gamla inloggningen:

```bash
codex logout
```

Om kommandot inte fungerar kan du manuellt ta bort cache-filen:

```bash
rm -f ~/.codex/auth.json
```

Om du aldrig loggat in med ett OpenAI-konto kan du hoppa över detta steg.

### Starta session

Gå till din projektmapp och starta Codex CLI:

```bash
cd /path/to/your/project
codex
```

När du ser Codex:s interaktiva gränssnitt kan du direkt skriva in dina behov, exempelvis:

```text
Förklara den här projektmappens katalogstruktur
```

### Verifiera konfigurationen

När du är i Codex CLI, kan du kontrollera vilken modell och leverantör som används:

```text
/model
```

Du bör se att modellen kommer från `acedatacloud`, exempelvis:

```text
Model: gpt-5
Provider: acedatacloud
```

Om leverantören inte är `acedatacloud`, har konfigurationen inte fungerat. Kontrollera att `~/.codex/config.toml` är sparad korrekt och att `ACEDATACLOUD_API_KEY` är tillgänglig i den aktuella terminalen:

```bash
echo $ACEDATACLOUD_API_KEY
```

Du kan även använda [Ace Data Cloud Kontrollpanel - Användningshistorik](https://platform.acedata.cloud/console/usages) för att se förfrågningsloggar och kostnadsdetaljer, samt [Ace Data Cloud Kontrollpanel - Applikationslista](https://platform.acedata.cloud/console/applications) för att se kvarvarande krediter.

## Hur det fungerar

Codex CLI använder ursprungligen OpenAI Responses API-protokollet. Ace Data Cloud tillhandahåller en proxy på `https://api.acedata.cloud/v1/responses` som är kompatibel med OpenAI Responses API, så Codex CLI behöver varken lokal proxy eller extra plugin.

Arbetsflödet är:

1. Codex CLI läser `model_provider` från `~/.codex/config.toml` och laddar motsvarande `[model_providers.acedatacloud]`.
2. Den hämtar API Token från miljövariabeln `ACEDATACLOUD_API_KEY`.
3. Anropet skickas via `wire_api = "responses"` till `base_url + /responses`, alltså `https://api.acedata.cloud/v1/responses`.
4. Ace Data Cloud verifierar identitet, kontrollerar kredit och vidarebefordrar förfrågan till tillgänglig modell.
5. Efter att förfrågan är slutförd registreras användning och krediter dras.

Det innebär att du fortfarande använder samma `codex`-kommando och den ursprungliga interaktiva upplevelsen, men underliggande modellservice är bytt till Ace Data Cloud.

## Konfigurera modeller

`~/.codex/config.toml`-filen `model`-fält bestämmer vilken modell Codex använder som standard. Ace Data Cloud:s OpenAI Responses-tjänst stöder flera modeller, exempelvis:

| Modell | Beskrivning |
| --- | --- |
| `gpt-5` | Rekommenderad standardmodell, passar för de flesta kodningsuppgifter |
| `gpt-4.1-mini` | Lättare, snabbare svar, för enklare uppgifter |
| `gpt-5.5` | Uppdaterad version med bättre kapacitet |
| `gpt-5.5-pro` | Förbättrad version för komplexa resonemang |
| `gpt-4.1` | Föregående generation, huvudmodell |
| `o3` | Förstärkt resonemang, för djupare analys |
| `o4-mini-high-all` | Lätt resonemangsmodell |

För tillfällig modellväxling kan du starta Codex med parameter:

```bash
codex --model gpt-4.1-mini
```

Eller ändra `model`-fältet i `~/.codex/config.toml` och starta om. En komplett lista över modeller finns i [Ace Data Cloud OpenAI-dokumentation](https://platform.acedata.cloud/documents/openai).

## Projektets tillitsnivå

Codex CLI tillåter att du sätter olika tillitsnivåer för olika projekt, vilket styr vilka operationer Agent kan utföra. Lägg till i slutet av `~/.codex/config.toml`:

```toml
[projects."/path/to/trusted/project"]
trust_level = "trusted"

[projects."/path/to/untrusted/project"]
trust_level = "untrusted"
```

- `trusted`: Agent har fulla rättigheter, kan köra kommandon och ändra filer.
- `untrusted`: Begränsad agent, bättre för okända projekt.
