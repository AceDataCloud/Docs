Codex är en programmeringsagent från OpenAI. Förutom terminal-CLI erbjuder den även ett VS Code-tillägg som låter dig chatta, läsa filer, referera kontext, generera ändringar och förhandsgranska dem i sidopanelen i editorn.

Denna guide beskriver hur du konfigurerar och använder Codex-tillägget i VS Code via Ace Data Cloud:s OpenAI Responses-kompatibla proxy. Codex VS Code-tillägget och Codex CLI använder samma lokala konfigurationssystem, så genom att peka `~/.codex/config.toml` till Ace Data Cloud kan Codex i VS Code använda `https://api.acedata.cloud/v1`.

## Ansökningsprocess

För att använda Codex kan du först gå till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) och hämta din API-token för framtida bruk.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Om du inte är inloggad eller registrerad omdirigeras du automatiskt till inloggningssidan där du kan registrera dig och logga in. Efter inloggning återvänder du automatiskt till aktuell sida.

Vid första ansökan får du en gratis kvot för att prova Codex-tjänsten kostnadsfritt.

## Installera Codex-tillägget

Sök efter `Codex` i VS Codes tilläggsmarknad och installera OpenAI:s **Codex - OpenAI's coding agent**-tillägg. Marketplace-ID är:

```text
openai.chatgpt
```

Du kan även installera via kommandoraden:

```bash
code --install-extension openai.chatgpt
```

När installationen är klar, starta om eller ladda om VS Code. Om du inte ser Codex-ikonen kan du öppna kommandopaletten (macOS: `Cmd+Shift+P`, Windows/Linux: `Ctrl+Shift+P`) och köra:

```text
Codex: Open Codex Sidebar
```

Codex visas som standard i högra sidopanelen i VS Code. Du kan även dra den till vänstra aktivitetsfältet.

## Installera Codex CLI (för verifiering)

Enligt officiell dokumentation använder Codex VS Code-tillägget och Codex CLI samma konfigurationslager. För att verifiera API-token och modell innan du konfigurerar VS Code rekommenderas att installera Codex CLI.

Ett rekommenderat sätt är att installera via npm, vilket kräver Node.js 18 eller senare:

```bash
npm install -g @openai/codex
```

macOS-användare kan även installera via Homebrew:

```bash
brew install --cask codex
```

Efter installation, kontrollera att kommandot fungerar:

```bash
codex --version
```

Om du endast vill använda VS Code-tillägget kan du hoppa över CLI-verifieringen; samma `~/.codex/config.toml` används ändå.

## Konfigurera Ace Data Cloud API

Codex VS Code-tillägget och Codex CLI delar konfigurationsfil. Som standard uppmanar Codex att logga in med OpenAI-konto eller konfigurera officiell API-nyckel. För att använda Ace Data Cloud behöver du konfigurera API-token och `~/.codex/config.toml`.

### Steg 1: Sätt miljövariabel

Det rekommenderas att skriva API-token i din shell-konfigurationsfil, t.ex. `~/.zshrc`, `~/.bashrc` eller `~/.bash_profile`:

```bash
export ACEDATACLOUD_API_KEY="{token}"
```

Byt ut `{token}` mot din API-token från Ace Data Cloud-konsolen.

Efter konfiguration, öppna terminalen på nytt eller kör `source` för att ladda inställningarna omedelbart:

```bash
source ~/.zshrc
```

Om VS Code redan är öppet, starta om eller ladda om det för att tillägget ska läsa in den nya miljövariabeln.

### Steg 2: Redigera Codex-konfigurationsfilen

Användarkonfigurationsfilen för Codex finns i `~/.codex/config.toml`. Om filen inte finns, skapa den:

```bash
mkdir -p ~/.codex
touch ~/.codex/config.toml
```

Skriv in följande konfiguration:

```toml
model_provider = "acedatacloud"
model = "gpt-5"
model_reasoning_effort = "high"
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[model_providers.acedatacloud]
name = "Ace Data Cloud"
base_url = "https://api.acedata.cloud/v1"
env_key = "ACEDATACLOUD_API_KEY"
wire_api = "responses"
```

Fältförklaringar:

| Fält | Beskrivning |
| --- | --- |
| `model_provider` | Standardmodellleverantör, motsvarar `[model_providers.acedatacloud]` nedan |
| `model` | Standardmodell-ID |
| `model_reasoning_effort` | Inferensintensitet, vanliga värden är `low`, `medium`, `high` |
| `approval_policy` | Bekräftelsepolicy före kommandokörning, rekommenderas `on-request` för dagligt bruk |
| `sandbox_mode` | Sandbox-behörigheter vid kommandokörning, rekommenderas `workspace-write` för utveckling |
| `base_url` | Ace Data Clouds OpenAI-kompatibla API-adress |
| `env_key` | Miljövariabelnamn för API-token |
| `wire_api` | Protokolltyp, för OpenAI Responses API måste detta vara `responses` |

Du kan också klicka på kugghjulet uppe till höger i Codex-tillägget och välja **Codex Settings > Open config.toml** för att öppna konfigurationsfilen direkt i VS Code.

### Projekt-specifik konfiguration

Om du vill använda en annan konfiguration för ett specifikt projekt kan du skapa `.codex/config.toml` i projektets rotmapp. Codex prioriterar projektkonfiguration, men projektet måste vara markerat som trusted för att ladda `.codex/`-konfigurationen.

Exempel:

```toml
model = "gpt-5-mini"
model_reasoning_effort = "medium"
```

Det rekommenderas att lägga personliga tokens i miljövariabler och inte i projektets repository. Projektets `.codex/config.toml` bör hanteras enligt teamets policy.

## Rensa cachad OpenAI-inloggning

Om du tidigare loggat in med OpenAI-konto i Codex-tillägget kan lokal inloggningsstatus finnas kvar. Innan du byter till Ace Data Cloud-proxy kan du köra i terminalen:

```bash
codex logout
```

Om kommandot inte finns kan du ta bort cachefilen manuellt:

```bash
rm -f ~/.codex/auth.json
```

Starta om eller ladda om VS Code efteråt.

## Grundläggande användning

När konfigurationen är klar, öppna Codex-panelen i VS Code (vänster eller höger sida) och skriv in din fråga eller uppgift, t.ex.:

```text
Förklara projektets katalogstruktur och ange huvudingångsfilen.
```

Codex-tillägget kan använda filer och markerad kod i editorn som kontext. Du kan även referera filer i inmatningsfältet med `@`, t.ex.:

```text
Referera till @src/App.vue och hjälp mig dela upp sidan i tydligare komponenter.
```

Om du markerar kod kan du via kommandopaletten köra:

```text
Codex: Add to Codex Thread
```

Eller:

```text
Codex: Add File to Codex Thread
```

för att lägga till hela filen i kontexten.

## Byta modell och inferensintensitet

Codex VS Code-tillägget låter dig byta modell och justera reasoning effort via en modellväljare under inmatningsfältet. Vid användning av Ace Data Cloud rekommenderas att först ange standardmodell i `~/.codex/config.toml` och sedan byta vid behov i gränssnittet. Rekommenderade standarder:

| Scenario | Rekommenderad modell | Inferensintensitet |
| --- | --- | --- |
| Daglig kodgranskning och småändringar | `gpt-5-mini` | `medium` |
| Vanliga utvecklingsuppgifter | `gpt-5` | `high` |
| Komplex omstrukturering och djup inferens | `gpt-5.5` eller `gpt-5.5-pro` | `high` |
| Inferensförstärkta uppgifter | `o3` | `high` |

Om önskad modell inte visas i gränssnittet kan du ändra `model` i `~/.codex/config.toml` och starta om eller ladda om VS Code. Komplett modellista finns i [Ace Data Cloud OpenAI-dokumentation](https://platform.acedata.cloud/documents/openai).

## Välj arbetsläge

Codex-tillägget stödjer olika arbetslägen. Vanliga lägen:

| Läge | Användningsområde |
| --- | --- |
| `Chat` | Endast diskussion och kodförklaring, inga direkta filändringar |
| `Agent` | Codex läser filer, ändrar kod och kör nödvändiga kommandon, rekommenderas för dagligt utvecklingsarbete |
| `Agent (Full Access)` | Ger högre behörigheter och nätverksåtkomst, för situationer där du är medveten om riskerna |

För dagligt bruk rekommenderas `Agent` med `approval_policy = "on-request"`. Då frågar Codex om bekräftelse innan känsliga kommandon, åtkomst utanför arbetsytan eller nätverksanrop.

## Verifiera konfiguration

Du kan verifiera att Codex fungerar med Ace Data Cloud i terminalen:

```bash
codex exec --model gpt-5-mini "Reply with exactly: ADC_Codex_OK"
```

Om konfigurationen är korrekt bör du få svaret:

```text
ADC_Codex_OK
```

Gå sedan tillbaka till VS Code, öppna Codex-panelen och skriv en enkel fråga:

```text
Beskriv syftet med den aktuella arbetsytan med en mening.
```

Du kan även se förfrågningshistorik och kostnadsdetaljer i [Ace Data Cloud-konsolen - Användningshistorik](https://platform.acedata.cloud/console/usages) och återstående kvot i [Ace Data Cloud-konsolen - Applikationslista](https://platform.acedata.cloud/console/applications).

## Hur det fungerar

Codex VS Code-tillägget är inte en separat modellkonfiguration. Det använder den lokala Codex CLI:n och delar konfigurationslager:

1. VS Code-tillägget startar Codex och läser användarens `~/.codex/config.toml`.
2. Om projektet är trusted och innehåller `.codex/config.toml` laddas även projektkonfiguration.
3. Om `model_provider` är `acedatacloud` läser Codex API-token från `ACEDATACLOUD_API_KEY`.
4. Förfrågningar skickas via OpenAI Responses-protokollet till `https://api.acedata.cloud/v1/responses`.
5. Ace Data Cloud verifierar identitet, kontrollerar kvot, vidarebefordrar förfrågningar och loggar användning.

Därför behöver du normalt bara konfigurera en gång. När terminal-CLI är verifierad använder VS Code-tillägget samma inställningar.
