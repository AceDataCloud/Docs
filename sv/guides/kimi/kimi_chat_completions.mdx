Kimi är en AI-modellserie lanserad av Moonshot AI. För närvarande rekommenderas `kimi-k3.1-pro`, lämplig för långvarig programmering, komplex slutledning, visuell förståelse och kunskapsarbete; `kimi-k3` kan fortfarande användas. Anropas via det OpenAI-kompatibla Chat Completions API.

Detta dokument introducerar främst användningsprocessen för Kimi Chat Completion API, med vilket vi enkelt kan använda den officiella Kimi-chattfunktionen.

## Ansökningsprocess

För att använda Kimi Chat Completion API, hämta först din API-token i [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) och spara den som reserv.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig kommer du automatiskt att omdirigeras till inloggningssidan för att registrera dig och logga in, och när detta är klart återvänder du automatiskt till den aktuella sidan.

**En API-token kan anropa alla plattformstjänster, utan att behöva ansökas separat för varje tjänst.** Vid den första ansökan får du gratis kredit och kan prova kostnadsfritt; när krediten inte räcker till kan du ladda på det allmänna saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Grundläggande användning

Därefter kan du fylla i motsvarande innehåll i gränssnittet, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

När du använder detta gränssnitt för första gången behöver du minst fylla i tre saker: `authorization` kan väljas direkt från rullgardinslistan; `model` används för att välja Kimi-modell, och det rekommenderas att använda `kimi-k3.1-pro`; `messages` är en array med chattmeddelanden, där varje meddelande innehåller `role` och `content`, och `role` stöder `user`, `assistant`, `system` och `tool`.

Samtidigt kan du lägga märke till att det finns motsvarande genererad anropskod på höger sida. Du kan kopiera koden och köra den direkt, eller klicka direkt på knappen ”Try” för att testa.

<p><img src="https://cdn.acedata.cloud/six7e3.png" width="400" className="m-auto" /></p>

Följande är ett verkligt K3-svar som erhållits med `reasoning_effort: max` (oanvända utökade fält har utelämnats):

```json
{
  "id": "msg_2D4Btbg1WgvkNE3tCYkR4xGA",
  "object": "chat.completion",
  "created": 1784466588,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 86,
    "completion_tokens": 206,
    "total_tokens": 292
  }
}
```

Det returnerade resultatet har flera fält, som introduceras nedan:

- `id`, ID:t som genereras för denna chattuppgift och används för att unikt identifiera denna chattuppgift.
- `model `, den valda Kimi-modellen från den officiella webbplatsen.
- `choices`, svarsinformationen som Kimi ger på frågan.
- `usage `: statistisk information om token för denna fråge- och svarsomgång.

Där `choices` innehåller Kimis svarsinformation, och dess `choices` är den konkreta informationen i Kimis svar, vilket kan ses i bilden.

<p><img src="https://cdn.acedata.cloud/tv9rul.png" width="400" className="m-auto" /></p>

Det går att se att fältet `content` i `choices` innehåller det konkreta innehållet i Kimis svar; K3 kan även returnera `reasoning_content`, som används för att representera slutledningsprocessen.

## K3.1 Pro-slutledningsintensitet

`kimi-k3.1-pro` aktiverar alltid slutledning. Du kan ange `reasoning_effort` i toppnivån av förfrågningens body till `low`, `high` eller `max`; skicka inte in en konfiguration som stänger av slutledning. Modellen stöder som mest 1 048 576 token i kontext, men den faktiska gränsen för förfrågningar gäller fortfarande enligt det aktuella gränssnittet. Priset beräknas utifrån användning för indata, utdata och cacheträffar, se Pricing-kortet i modellkatalogen för detaljer.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Följande K3-exempel behålls för befintliga integrationer, och exempelsvaret erhölls verkligen genom en K3-förfrågan.

## K3-slutledningsintensitet

`kimi-k3` aktiverar alltid slutledning. Toppnivån i förfrågningens body stöder fältet `reasoning_effort`, och det enda värde som för närvarande stöds är `max`; om fältet utelämnas används också `max`. `standard`, `high` eller andra strängar kan accepteras flexibelt av vissa kompatibla uppströmskällor, men garanteras inte förändra slutledningsbeteendet, så förlita dig inte på dem.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

Vid användning av OpenAI SDK kan detta fält skickas direkt:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

Vid flerrundeschattar och verktygsanrop ska hela assistant-meddelandet från föregående omgång skickas tillbaka till `messages`, inklusive `reasoning_content` och `tool_calls`.

### Officiella referenser

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort)：förklarar att Kimi K3 alltid aktiverar slutledning och att det enda värde som för närvarande stöds för `reasoning_effort` är `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview)：jämför slutledningsparametrar, kontextfönster och skillnader i verktygsanrop mellan K3- och K2-serierna.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat)：Moonshots officiella definitioner av Chat Completions-förfrågningar, svar och OpenAPI-fält.

## Strömmande svar

Detta gränssnitt stöder även strömmande svar, vilket är mycket användbart för webbintegration och gör att webbsidan kan implementera en visningseffekt tecken för tecken.

Om du vill returnera svar strömmande kan du ändra parametern `stream ` i förfrågningshuvudet till `true`.

Ändringen visas i bilden, men anropskoden behöver ändras på motsvarande sätt för att stödja strömmande svar.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>

Efter att `stream` har ändrats till `true` kommer API:t att returnera motsvarande JSON-data rad för rad, och på kodnivå behöver vi göra motsvarande ändringar för att få resultatet rad för rad.

Python-exempel på anropskod:
```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Nedan följer utdrag från start-, resonemangs-, brödtext-, slut- och användningsdatablocken i samma verkliga strömmande K3 Max-svar:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Som du kan se finns det många `data` i svaret, och `choices` i `data` är det senaste svarsinnehållet, vilket överensstämmer med innehållet som beskrivits ovan. `choices` är det nytillagda svarsinnehållet, och du kan ansluta det till ditt system baserat på resultaten. Samtidigt avgörs slutet på det strömmande svaret utifrån innehållet i `data`; om innehållet är `[DONE]` innebär det att det strömmande svaret har avslutats helt. Det returnerade `data`-resultatet innehåller flera fält, som beskrivs nedan:

- `id`, ID:t som genereras för denna dialoguppgift och används för att unikt identifiera denna dialoguppgift.
- `model `, den valda modellen från Kimi:s officiella webbplats.
- `choices`, svarsinformationen som Kimi ger på frågan.

JavaScript stöds också, till exempel är koden för strömmande anrop i Node.js följande:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Exempelkod för Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Andra språk kan skrivas om separat, principen är densamma.

## Fleromgångsdialog

Om du vill ansluta funktionen för flervägsdialog behöver du skicka flera frågor i fältet `messages`; ett specifikt exempel på flera frågor visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Exempelkod för Python-anrop:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Felhantering

Vid anrop av API:et, om ett fel uppstår, returnerar API:et motsvarande felkod och information. Till exempel:

- `400 token_mismatched`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`：Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`：För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`：Internt serverfel, något gick fel på servern.
