Kimi är en serie AI-modeller som lanserats av Moonshot AI. För närvarande rekommenderas `kimi-k3.1-pro`, som är lämplig för långsiktig programmering, komplexa resonemang, visuell förståelse och kunskapsarbete; `kimi-k3` kan fortfarande användas. Anrop görs via ett OpenAI-kompatibelt Chat Completions API.

Det här dokumentet presenterar huvudsakligen arbetsflödet för användning av Kimi Chat Completion API, vilket gör det enkelt för oss att använda den officiella Kimi-tjänstens konversationsfunktioner.

## Modeller som stöds

För närvarande stöds fyra modeller: `kimi-k3.1-pro`, `kimi-k3`, `kimi-k2.6` och `kimi-k2.7-code`. K2.7 Code är avsedd för programmering och verktygsanrop och debiteras enligt samma prisnivå som K2.6. Skicka inte med inställningen `thinking` eller `reasoning_effort` i förfrågningar till den här modellen. Stödet för övriga Kimi-modeller har upphört. Välj uttryckligen en av dessa fyra modeller i klienten.

## Ansökningsprocess

För att använda Kimi Chat Completion API måste du först gå till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) och hämta din API-token för senare användning.

![]()

Om du inte har loggat in eller registrerat dig ännu kommer du automatiskt att omdirigeras till inloggningssidan, där du kan registrera dig och logga in. När detta är klart återgår du automatiskt till den aktuella sidan.

**En enda API-token räcker för att anropa alla plattformens tjänster. Du behöver inte ansöka separat för varje tjänst.** Vid den första ansökan får du en kostnadsfri kredit som du kan använda för att prova tjänsten. När krediten inte räcker till kan du fylla på ditt allmänna saldo via [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Grundläggande användning

Därefter kan du fylla i motsvarande uppgifter i gränssnittet, enligt bilden nedan:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

Första gången du använder detta gränssnitt behöver du fylla i minst tre fält: `authorization` kan väljas direkt från rullgardinsmenyn; `model` används för att välja Kimi-modell, och vi rekommenderar `kimi-k3.1-pro`; `messages` är en array med konversationsmeddelanden, där varje meddelande innehåller `role` och `content`. Bland dessa stöder `role` värdena `user`, `assistant`, `system` och `tool`.

Samtidigt kan du se att motsvarande anropskod genereras till höger. Du kan kopiera koden och köra den direkt eller klicka på knappen ”Try” för att testa.

Nedan visas ett verkligt K3-svar som erhållits med `reasoning_effort: max` (oanvända utökade fält har utelämnats):


Returresultatet innehåller flera fält, som beskrivs nedan:

- `id`: ID:t för den genererade konversationsuppgiften, som används för att unikt identifiera den aktuella konversationsuppgiften.
- `model `: Den valda Kimi-modellen från den officiella webbplatsen.
- `choices`: Svarsinformationen som Kimi ger på frågan.
- `usage `: Statistik över antalet token som används i den aktuella fråge- och svarssessionen.

Bland dessa innehåller `choices` Kimi:s svarsinformation. Dess `choices` innehåller den specifika informationen om Kimi:s svar, vilket framgår av bilden nedan.

<p><img src="https://cdn.acedata.cloud/tv9rul.png" width="400" className="m-auto" /></p>

Som du kan se innehåller fältet `content` i `choices` det specifika innehållet i Kimi:s svar; K3 kan även returnera `reasoning_content`, som används för att representera resonemangsprocessen.

## Resonemangsnivå för K3.1 Pro

`kimi-k3.1-pro` har alltid resonemang aktiverat. Du kan ange `reasoning_effort` på den översta nivån i förfrågans innehåll med värdet `low`, `high` eller `max`. Skicka inte någon konfiguration som stänger av resonemanget. Modellen stöder ett kontextfönster på upp till 1 048 576 token, men den faktiska gränsen för förfrågningar beror fortfarande på det aktuella API-gränssnittet. Priset beräknas utifrån användningen av indata, utdata och cacheträffar. Se priskortet Pricing i modellkatalogen för mer information.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Följande K3-exempel behålls för befintliga integrationer. Exempelsvaret har verkligen erhållits genom en K3-förfrågan.

## Resonemangsnivå för K3

`kimi-k3` har alltid resonemang aktiverat. Fältet `reasoning_effort` stöds på den översta nivån i förfrågans innehåll. Det enda värde som för närvarande stöds är `max`; om fältet utelämnas används också `max`. Använd ett värde som stöds.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

När du använder OpenAI SDK kan du skicka fältet direkt:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

Vid flerstegskonversationer och verktygsanrop ska du skicka tillbaka hela föregående assistant-meddelandet till `messages`, inklusive `reasoning_content` och `tool_calls`.

### Officiella referenser

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort): Förklarar att Kimi K3 alltid har resonemang aktiverat och att det enda värde som för närvarande stöds för `reasoning_effort` är `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview): Jämför skillnaderna mellan K3- och K2-serierna vad gäller resonemangsparametrar, kontextfönster och verktygsanrop.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat): Moonshots officiella definitioner av Chat Completions-förfrågningar, svar och OpenAPI-fält.

## Strömmande svar

Det här gränssnittet stöder även strömmande svar, vilket är mycket användbart vid integration med webbsidor och gör det möjligt att visa texten tecken för tecken på webbsidan.

Om du vill returnera svar i strömningsformat kan du ändra parametern `stream ` i förfrågningshuvudet till `true`.

Ändringen visas i bilden nedan, men anropskoden måste också ändras på motsvarande sätt för att stödja strömmande svar.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>
Efter att ha ändrat `stream` till `true` kommer API:et att returnera motsvarande JSON-data rad för rad. På kodnivå behöver vi göra motsvarande ändringar för att få resultaten rad för rad.

Exempel på anropskod i Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Nedan följer utdrag från de inledande data-, resonemangs-, innehålls-, avslutnings- och användningsdatablocken i samma verkliga K3 Max-strömningssvar:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Som du kan se innehåller svaret flera `data`-objekt. `choices` i `data` innehåller det senaste svarsinnehållet, vilket överensstämmer med beskrivningen ovan. `choices` innehåller det nya svarsinnehållet, som du kan använda för att integrera resultatet i ditt system. Samtidigt avgörs slutet på strömningssvaret utifrån innehållet i `data`. Om innehållet är `[DONE]` betyder det att strömningssvaret har avslutats helt. De returnerade `data`-resultaten innehåller flera fält, som beskrivs nedan:

- `id`, ID:t som genereras för den aktuella konversationsuppgiften och används för att unikt identifiera den.
- `model `, den valda modellen från Kimi:s officiella webbplats.
- `choices`, informationen i Kimi:s svar på frågan.

JavaScript stöds också. Nedan följer exempel på strömningsanrop med Node.js:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Exempelkod i Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

För andra programmeringsspråk kan du själv anpassa koden. Principen är densamma.

## Fleromgångsdialog

Om du vill integrera funktionen för fleromgångsdialoger behöver du skicka flera frågeord i fältet `messages`. Ett konkret exempel på flera frågeord visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Exempel på anropskod i Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Genom att skicka flera frågeord kan du enkelt implementera fleromgångsdialoger. Nedan visas det verkliga K3 Max-svar som erhölls från denna begäran (oanvända utökade fält har utelämnats):

## Felhantering

Om ett fel uppstår när API:et anropas returnerar API:et motsvarande felkod och information. Till exempel:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.
