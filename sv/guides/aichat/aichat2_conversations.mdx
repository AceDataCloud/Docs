AI Chat v2 API (`/aichat2/conversations`) är den nya generationens konversationsgränssnitt och en omfattande uppgraderad version av [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Utifrån v1:s enkla, hanterade flerrundskonversationer utökar det med:

- **Multimodala användarinmatningar**: Skicka text + bild + filblock direkt via det strukturerade fältet `message`, utan att först bifoga dem indirekt med `references`.
- **Agentbaserade verktygsanrop**: Inbyggd uppsättning verktyg för webbsökning, hämtning av webbsidor, filläsning med mera, samt möjlighet att ansluta MCP-servrar som användaren har godkänt (Google Drive, Notion, Slack, GitHub osv.). Modellen kan självständigt anropa verktyg över flera rundor i en enda begäran för att slutföra komplexa uppgifter.
- **Strukturerade strömmande händelser**: Via `accept: text/event-stream` eller `application/x-ndjson` kan du få token-för-token-händelser som `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` med mera, vilket gör det enkelt att rendera dem separat i frontend enligt respektive typ.
- **Avbrytbar / återupptagbar**: När modellen behöver att användaren kompletterar information skickar den en `ask_user_question`-händelse och pausar. Vid nästa anrop kan den fortsätta genom att fylla i svaret via `tool_results`.
- **Nya CRUD-åtgärder**: Slutför `retrieve` / `retrieve_batch` / `update` / `delete` genom fältet `action` på samma endpoint, utan ytterligare API för konversationshantering.
- **En kontinuerligt uppdaterad modellista**: Ansluter som standard till moderna modeller som GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 med flera.

Samtidigt är det på begärandetextnivå **helt bakåtkompatibelt med v1**: genom att bara skicka `model` + `question` (+ valfritt `stateful` / `id` / `references` / `preset`) kan du få ett `{answer, id}` JSON-svar som motsvarar v1. Därför behöver du inte skriva om klienten vid migrering från `/aichat/conversations`; byt bara sökvägen till `/aichat2/conversations`.

> Om du för närvarande använder `/aichat/conversations` kommer den gamla endpointen fortfarande att behållas, så du kan migrera i din egen takt.

## Ansökningsprocess

För att använda AI Chat v2 API går du först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API-token och spara den som reserv.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig omdirigeras du automatiskt till inloggningssidan, där du uppmanas att registrera dig och logga in. När det är klart återgår du automatiskt till den aktuella sidan.

**En API-token kan anropa alla plattformens tjänster, utan att behöva ansöka separat för varje tjänst.** Vid första ansökan får du en gratis kvot för kostnadsfri utvärdering; när kvoten är otillräcklig kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

## Grundläggande användning

Den enklaste användningen är exakt densamma som i v1: skicka `model` + `question` och få `{answer, id}`.

CURL-exempel:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Returresultat:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python-exempel:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Flerrundskonversationer

Precis som i v1 skickar du `stateful: true` för att aktivera sparande av konversationen, och API:t returnerar ett `id`; i efterföljande begäranden behöver du bara skicka tillbaka `id` för att fortsätta konversationen, utan att själv behöva underhålla meddelandehistoriken.

Första begäran:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Retur:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Andra begäran, med samma `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "Vilket nummer bad jag dig just komma ihåg?"
  }'
```

```json
{
  "answer": "Numret du bad mig komma ihåg är 42.",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` är som standard `true`; att utelämna det är likvärdigt med att uttryckligen skicka `true`. Om du inte vill att servern ska spara denna samtalsrunda kan du uttryckligen ange `stateful: false`.

## Strömmande svar

v2 stöder två strömmande format, som väljs enligt `accept`-huvudet:

| Scenario                    | `accept`               | Dataformat                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Webbfrontend / EventSource  | `text/event-stream`    | `data: {json}\n\n`, sista raden `data: [DONE]\n\n` |
| Server / CLI / Node-strömmande tolkning | `application/x-ndjson` | Ett JSON-objekt per rad                               |
| Strömning behövs inte                 | `application/json`（standard） | Returnerar `{answer, id}` på en gång                       |

### NDJSON-exempel

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "Presentera Hangzhou med tre meningar.",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # Kompatibilitet med v1: inkrementella segment tillhandahålls även via fältet delta_answer
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Varje rad i NDJSON är en strukturerad händelse, där den vanligaste är `text_delta`:

```json
{"type":"text_delta","content":"Hang","delta_answer":"Hang","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"zhou","delta_answer":"zhou","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"är","delta_answer":"är","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE-exempel

`EventSource` i webbläsaren stöder inte anpassade begärandekroppar, så det rekommenderas att använda `fetch` + manuell tolkning genom uppdelning på `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "Presentera Hangzhou med tre meningar.",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Typer av strömmande händelser

| `type`              | Betydelse                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `text_delta`        | Inkrementellt textsegment i assistentens svar. `content` är nytt innehåll; för kompatibilitet med v1 innehåller samma händelse även `delta_answer` (lika med `content`) och `id`.                  |
| `thinking`          | Modellens tankeprocess (visas endast när den valda modellen exponerar reasoning).                                                                |
| `tool_use`          | Modellen beslutar att anropa ett verktyg; händelsen innehåller `tool_id`, `tool_name`, `input`.                                                  |
| `tool_result`       | Resultatet av verktygskörningen paras ihop med föregående `tool_use` via `tool_id`; `is_error` anger om den misslyckades.                                       |
| `card`              | Strukturerade kort som produceras av verktyg (t.ex. bilder, länkförhandsvisningar), lämpliga för direkt rendering.                                                                    |
| `citation`          | Används för att komplettera käll-URL:er för hänvisningar till motsvarande textsegment.                                                                            |
| `ask_user_question` | Skickas när modellen behöver att användaren kompletterar information; samtalet övergår till tillståndet `awaiting_user_input`. Se [återuppta pausade samtal](#återuppta-pausade-samtal) nedan.                           |
| `artifact`          | Ett fristående resultat som genereras av modellen (t.ex. kodblock, dokument), som kan sparas eller laddas ned.                                                                      |
| `system_message`    | Systemmeddelande (inte innehåll från användare eller assistent), endast för UI-aviseringar.                                                                     |
| `compact`           | Händelse där intern kontext komprimeras, ingen särskild hantering krävs.                                                                             |
| `error`             | Ett fel uppstår i denna runda; `message` beskriver felinnehållet.                                                                        |
| `done`              | Det strömmande svaret avslutas och innehåller `usage` (inklusive `prompt_tokens` / `completion_tokens` / `total_tokens`) och `terminal_reason`. |

För klienter som endast bryr sig om det slutliga svaret är det likvärdigt att sammanfoga `content` från alla `text_delta` med `answer` i läget `application/json`.

## Multimodal inmatning

Om användarinmatningen innehåller bilder eller filer ska du skicka `message` (en array) i stället för `question`. Varje arrayelement är ett innehållsblock:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "Hur många katter finns det i den här bilden?" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Blocktyper som stöds:

- `text` — Vanlig text, fältet `text` krävs.
- `image_url` — Bild, `image_url.url` krävs.
- `file_url` — Fil (PDF, CSV, TXT osv.), `file_url.url` krävs.

### Relation till v1 `references`

För kompatibilitet med äldre klienter känner v2 fortfarande igen fältet `references: ["https://...", ...]`:
- URL-suffixet är `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, konvertera automatiskt till ett `image_url`-block;
- Andra filändelser konverteras till ett `file_url`-block;
- Om även `question` tillhandahålls samtidigt, placera det först som ett `text`-block.

Därför, om du bara vill migrera från v1 och inte vill ändra request body, behöver du bara byta sökvägen till `/aichat2/conversations`, och den ursprungliga användningen av `references` fungerar som vanligt.

Om mer detaljerad kontroll behövs (till exempel att placera flera bilder mellan texter, eller om ordningen är viktig) använd direkt `message`-arrayen.

## Verktygsanrop och MCP

Den centrala förbättringen i v2 är att modellen självständigt kan anropa verktyg för att slutföra uppgifter i flera steg, **detta är aktiverat som standard**, och klienten behöver inte göra någon ytterligare konfiguration i begäran. Vanliga scenarier:

- Användaren frågar ”Hjälp mig att söka efter vilka nya utställningar som nyligen finns i Shanghai” → Modellen anropar inbyggd web search → Sammanställer resultaten till ett svar.
- Användaren frågar ”Läs den här PDF:en och skriv sedan en sammanfattning” → Modellen anropar file_read → Skriver en sammanfattning.
- Användaren har redan auktoriserat Google Drive / GitHub / Notion osv. i [Connections](https://platform.acedata.cloud/connections) → Modellen kan anropa motsvarande MCP-verktyg för att läsa och skriva dess data.

I NDJSON-/SSE-strömmen presenteras verktygsanrop genom de två typerna av händelser `tool_use` och `tool_result`, till exempel:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Om du inte vill visa detaljer om verktygsanrop i frontend räcker det att ignorera händelserna `tool_use` / `tool_result` / `card` / `citation`; modellens slutliga utdata strömmas fortfarande ut via `text_delta`.

`max_turns` kan begränsa hur många omgångar modellen som mest får anropa verktyg själv i denna begäran, med intervallet 1–500 och standardvärdet 500 om det utelämnas. Om du sätter det lågt (till exempel `max_turns: 1`) kan du tvinga fram ett enskilt svar och förbjuda alla verktygsanrop.

## Asynkron körning och obevakad auktorisering

Om ditt anrop kommer från en larm-Webhook, CI/CD, ett övervakningssystem eller någon annan bakgrundsuppgift kan du sätta `async: true` så att gränssnittet omedelbart returnerar ett uppgifts-ID och fortsätter körningen i bakgrunden:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Exempel på svar:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Därefter kan du använda `action: retrieve` + `id` för att hämta konversationsresultatet; du kan också ange `callback_url`, och när uppgiften är klar kommer plattformen att POST:a `{ status, answer, usage, error }` till din callback-adress. `callback_url` måste använda `http` / `https`, och du får inte ange `localhost` eller en privat IP-literal direkt.

Det finns vanligtvis ingen som kan klicka för att bekräfta bakgrundsuppgifter. Om du vill att vissa Skills eller MCP Servers ska utföra åtgärder som att skicka, publicera eller skriva i obevakat läge, ska du uttryckligen skicka en lista över förhandsgodkännanden i request body:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Värdena i `allowed_skills` är sluggar för anslutna Skills; värdena i `allowed_mcp_servers` är sluggar för anslutna MCP Servers. Skills / MCP Servers som inte finns med i förhandsgodkännandet kan i obevakat läge fortfarande endast förhandsgranska, köra dry-run eller vägra att utföra skrivåtgärder.

Om mer detaljerad kontroll behövs kan du också använda det likvärdiga objektet `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Förhandsgodkännandet är just dessa två listor: en tom lista betyder att inga funktioner godkänns, utan behov av ytterligare växlingsfält.

Observera: Förhandsgodkännande betyder endast att ”denna begäran tillåter att dessa funktioner hoppar över manuell bekräftelse i obevakat läge”. Den specifika Skill måste fortfarande stödja `--unattended-confirm` eller motsvarande säkerhetsmekanism; annars fortsätter den med dry-run och utför inte skrivåtgärder direkt.

## Återuppta pausade konversationer

Vissa verktyg gör att modellen ”ställer en motfråga till användaren”. Modellen skickar då en `ask_user_question`-händelse, och konversationen fryses i tillståndet `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Rendera denna händelse som ett kort i frontend så att användaren kan välja ett svar, och använd sedan samma `id` för att starta nästa begäran och fyll tillbaka svaret via `tool_results`:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

`tool_use_id` i request body **måste** vara exakt samma som `tool_id` när pausen inträffade; om de inte stämmer överens returneras 400. När `tool_results` samtidigt finns i begäran ignoreras `question` / `message` / `references`.

Om användaren bestämmer sig för att avstå från denna fråga räcker det att direkt skicka en ny `question` / `message`, så markerar plattformen automatiskt det pausade verktygsanropet som ”användaren hoppade över”.

## Konversationshantering (CRUD)

v2 erbjuder lättviktig konversationshantering på samma endpoint via fältet `action`, utan att behöva skapa ett separat API.
### `action: retrieve` —— hämta en konversation

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Returnerar det fullständiga konversationsdokumentet (inklusive `messages`-historik, `model`, `title`, `tools_used` osv.).

### `action: retrieve_batch` —— lista konversationssammanfattningar

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Returnerar `{ items: [...], total }`. **Sammanfattningar innehåller inte `messages`**, vilket är lämpligt för sidofältslistor; om användaren öppnar en viss konversation, använd sedan `action: retrieve` för att hämta dess fullständiga meddelanden separat.

Valfria filterparametrar: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— ändra titel eller skriv om historik

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

`messages` kan också skickas, men servern utför strikt schema-validering (måste vara i den hopfällda formen `ToolUseContent`); annars returneras 400. Generellt rekommenderas det endast för att ändra `title`.

### `action: delete` —— ta bort en konversation

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Returnerar `{ id, success: true }`. Borttagning kan inte återställas, bekräfta innan du anropar.

## Smidig migrering från v1

Om du redan använder [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations) kräver migrering till v2 nästan inga kodändringar:

1. Ändra URL:en från `https://api.acedata.cloud/aichat/conversations` till `https://api.acedata.cloud/aichat2/conversations`.
2. Om du tidigare skickade v1-modellnamn (som `gpt-3.5`, `gpt-4-browsing` osv.), rekommenderas det att uppgradera till moderna modeller vid byte till v2 (som `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` osv.).
3. Fälten i NDJSON-strömmen förblir bakåtkompatibla: varje `text_delta`-händelse innehåller fortfarande `delta_answer` och `id`, så klienter som tidigare tolkar `delta_answer` rad för rad behöver inte ändras.

Efter migreringen kan du vid behov aktivera v2:s nya funktioner (multimodal `message`, SSE, verktygsanrop, `action` CRUD) och gå vidare i lämplig takt.

## Felhantering

Felsvar är enhetligt formaterade som:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Vanliga fel:

- `400 bad_request`: obligatoriska fält saknas, `tool_use_id` matchar inte, `messages`-schemat är ogiltigt osv.
- `401 invalid_token`: `authorization`-huvudet är felaktigt.
- `404 not_found`: konversationen som motsvarar `id` finns inte vid `action: retrieve / update / delete`.
- `429 too_many_requests`: hastighetsbegränsningen har utlösts.
- `500 chat_error`: uppströms-LLM rapporterar ett fel eller `completion_tokens=0` för denna omgång (behandlas som ej förbrukat och debiteras inte).

I strömmande svar skickas fel som händelsen `{"type":"error","message":"..."}`, varefter strömmen omedelbart avslutas.

## Slutsats

AI Chat v2 API uppgraderar dialoger från ”enkelrunds- / flerrundsfrågor och svar” till ”agentbaserade observerbara dialoger”, samtidigt som det är bakåtkompatibelt med v1: multimodala indata, verktygsanrop, möjlighet att pausa / återuppta, strömmande strukturerade händelser och inbyggd CRUD. Det rekommenderas att nya integrationer använder v2 direkt; befintliga v1-integrationer kan migreras smidigt i etapper. Om du har några frågor, kontakta gärna vårt tekniska supportteam när som helst.
