AI Chat v2 API (`/aichat2/conversations`) är den nya generationens konversationsgränssnitt och en helt uppgraderad version av [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Utöver v1:s enkla, hanterade flerrundskonversationer utökar det med:

- **Multimodala användarindata**: Skicka direkt text- + bild- + filblock via det strukturerade `message`-fältet, utan att först behöva bifoga dem indirekt med `references`.
- **Agentbaserade verktygsanrop**: Innehåller en uppsättning verktyg för internetsökning, webbsidehämtning, filläsning med mera, och kan ansluta MCP-servrar som användaren har godkänt (Google Drive, Notion, Slack, GitHub m.fl.). Modellen kan självständigt anropa verktyg i flera omgångar inom en enda begäran för att slutföra komplexa uppgifter.
- **Strukturerade strömmande händelser**: Via `accept: text/event-stream` eller `application/x-ndjson` kan du få händelser som `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` med flera, token för token, vilket underlättar separat rendering i frontenden enligt respektive typ.
- **Avbrytbar / återupptagbar**: När modellen behöver att användaren kompletterar information skickar den händelsen `ask_user_question` och pausar. Vid nästa anrop kan svaret fyllas tillbaka via `tool_results` för att fortsätta.
- **Nya CRUD-åtgärder**: Utför `retrieve` / `retrieve_batch` / `update` / `delete` via fältet `action` på samma endpoint, utan något extra API för konversationshantering.
- **Kontinuerligt uppdaterad modellista**: Ansluter som standard till aktuella modeller såsom GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4 och Kimi K3.

Samtidigt är det på begäranivå **helt bakåtkompatibelt med v1**: genom att endast skicka `model` + `question` (+ valfria `stateful` / `id` / `references` / `preset`) får du ett JSON-svar `{answer, id}` som motsvarar v1. Därför behöver du inte skriva om klienten vid migrering från `/aichat/conversations`; det räcker att ändra sökvägen till `/aichat2/conversations`.

> Om du för närvarande använder `/aichat/conversations` kommer det gamla gränssnittet fortsatt att vara tillgängligt, och du kan migrera i din egen takt.

## Ansökningsprocess

För att använda AI Chat v2 API ska du först hämta din API Token i [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte är inloggad eller registrerad omdirigeras du automatiskt till inloggningssidan där du uppmanas att registrera dig och logga in. När det är klart återgår du automatiskt till den aktuella sidan.

**En API Token kan anropa alla plattformens tjänster, och du behöver inte ansöka separat för varje tjänst.** Vid första ansökan får du gratis kredit för att prova tjänsten kostnadsfritt; om krediten inte räcker kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

## Grundläggande användning

Den enklaste användningen är exakt densamma som i v1: skicka `model` + `question` och få `{answer, id}`.

CURL-exempel:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Returresultat:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python-exempel:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
```

## Flerrundskonversation

Precis som i v1 aktiverar du sparande av konversationen genom att skicka `stateful: true`; API:et returnerar ett `id`. I efterföljande begäranden behöver du bara skicka tillbaka `id` för att fortsätta konversationen, utan att själv underhålla messages-historiken.

Första begäran:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Svar:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Andra begäran, med samma `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` är `true` som standard; att utelämna det är likvärdigt med att uttryckligen skicka `true`. Att ange `stateful: false` hoppar över inläsning av tidigare konversationshistorik; detta betyder inte att resultatet från denna omgång inte sparas och gäller inte heller för verktygsflöden som behöver fortsätta efter en paus.

### Långa konversationer och bevarande av originaltext

Kontextkomprimering organiserar endast innehållet som skickas till modellen i denna omgång och ersätter inte redan sparade chattloggar. Du kan fortfarande läsa alla sparade meddelanden via `action: retrieve`; uttrycklig redigering eller borttagning av konversationer gäller fortfarande enligt begäran.

Modellen kan söka efter och läsa originaltext från historiken med sidindelning inom den aktuella konversationen. När du behöver fortsätta redigera en artikel, citera siffror eller förbereda publicering ska du läsa motsvarande originaltext och får inte ersätta brödtexten med en sammanfattning. Denna funktion återställer inte automatiskt meddelanden som redan har gått förlorade i äldre versioner.

Om kontextorganiseringen misslyckas, behåll konversations-ID:t och kontrollera händelsen `error`; tjänsten skriver inte över originaltexten med en tom sammanfattning. Verktygsåtgärder som slutfördes före felet kan fortfarande vara giltiga, så kontrollera först deras resultat för att undvika dubblerad generering eller publicering. När en enskild konversation når lagringsgränsen rapporteras ett tydligt fel; befintliga sparade poster frigör inte utrymme genom beskärning. Du kan exportera det innehåll som behövs och sedan starta en ny konversation.

## Strömmande svar

v2 stöder två strömmande format, som väljs via `accept`-huvudet:

| Scenario                    | `accept`               | Dataformat                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web-frontend / EventSource  | `text/event-stream`    | `data: {json}\n\n`, sista raden `data: [DONE]\n\n` |
| Server / CLI / Node-strömmande parsning | `application/x-ndjson` | Ett JSON-objekt per rad                               |
| Strömning behövs inte                 | `application/json`（standard） | Returnerar `{answer, id}` på en gång                       |

### NDJSON-exempel

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Varje rad i NDJSON är en strukturerad händelse, där den vanligaste är `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE-exempel

`EventSource` i webbläsaren stöder inte anpassade begärandekroppar, så det rekommenderas att använda `fetch` + manuell parsning genom att dela upp på `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Typer av strömmande händelser

| `type`              | Betydelse                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Inkrementellt textsegment i assistentens svar. `content` är nytt innehåll; för kompatibilitet med v1 innehåller samma händelse även `delta_answer` (lika med `content`) och `id`.                                        |
| `thinking`          | Modellens tankeprocess (visas endast när den valda modellen exponerar reasoning).                                                                                      |
| `tool_use`          | Modellen beslutar att anropa ett verktyg; händelsen innehåller `tool_id`, `tool_name`, `input`.                                                                        |
| `tool_result`       | Resultatet av verktygskörningen, paras ihop med föregående `tool_use` via `tool_id`; `is_error` anger om det misslyckades.                                                             |
| `card`              | Strukturerade kort som produceras av verktyg (t.ex. bilder, länkförhandsvisningar), lämpliga att rendera direkt.                                                                                          |
| `citation`          | Käll-URL för att komplettera citat för motsvarande textsegment.                                                                                                  |
| `ask_user_question` | Skickas när modellen behöver ytterligare information från användaren; konversationen går in i tillståndet `awaiting_user_input`, se [återuppta pausade konversationer](#恢复暂停的对话) nedan.                                                 |
| `artifact`          | Ett fristående resultat som modellen genererar (t.ex. kodblock, dokument), som kan sparas eller laddas ned.                                                                                            |
| `system_message`    | Systemmeddelande (inte användar- eller assistentinnehåll), används endast för UI-meddelanden.                                                                                           |
| `compact`           | Modellens kontext har organiserats; sparade originalmeddelanden förblir oförändrade och klienten behöver inte radera chattloggar.                                                                                    |
| `error`             | Ett fel inträffade i denna omgång; `message` beskriver felet.                                                                                              |
| `done`              | Den slutliga konversationsposten för denna omgång har sparats; innehåller `usage` (inklusive `prompt_tokens` / `completion_tokens` / `total_tokens`) och `terminal_reason`; du måste fortfarande bedöma om uppgiften är slutförd utifrån avslutsorsaken. |
För klienter som endast bryr sig om det slutliga svaret är sammanfogning av `content` från alla `text_delta` likvärdigt med `answer` i läget `application/json`.

## Multimodala indata

Om användarens indata innehåller bilder eller filer, skicka `message` (en array) i stället för `question`. Varje element i arrayen är ett innehållsblock:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Blocktyper som stöds:

- `text` — vanlig text, fältet `text` är obligatoriskt.
- `image_url` — bild, `image_url.url` är obligatoriskt.
- `file_url` — fil (PDF, CSV, TXT osv.), `file_url.url` är obligatoriskt.

### Relation till v1 `references`

För kompatibilitet med äldre klienter känner v2 fortfarande igen fältet `references: ["https://...", ...]`:

- URL-suffixet är `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, konverteras automatiskt till ett `image_url`-block;
- andra filändelser konverteras till ett `file_url`-block;
- om `question` också tillhandahålls, placeras den först som ett `text`-block.

Om du därför bara vill migrera från v1 utan att ändra förfrågningskroppen räcker det att byta sökvägen till `/aichat2/conversations`, så fungerar den ursprungliga användningen av `references` som vanligt.

Om du behöver mer detaljerad kontroll (till exempel att placera flera bilder mellan textstycken, eller om ordningen är viktig) använder du direkt arrayen `message`.

## Verktygsanrop och MCP

Den centrala förbättringen i v2 är att modellen självständigt kan anropa verktyg för att slutföra uppgifter i flera steg, **detta är aktiverat som standard**, och klienten behöver inte göra någon extra konfiguration i förfrågan. Vanliga scenarier:

- Användaren frågar ”Hjälp mig att söka efter vilka nya utställningar som nyligen finns i Shanghai” → modellen anropar inbyggd webbsökning → organiserar resultaten till ett svar.
- Användaren frågar ”Läs denna PDF och skriv sedan en sammanfattning” → modellen anropar file_read → skriver en sammanfattning.
- Användaren har auktoriserat Google Drive / GitHub / Notion osv. i [Connections](https://platform.acedata.cloud/connections) → modellen kan anropa motsvarande MCP-verktyg för att läsa och skriva deras data.

I NDJSON-/SSE-strömmen representeras verktygsanrop av de två händelsetyperna `tool_use` och `tool_result`, till exempel:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Om du inte vill visa detaljer om verktygsanrop i frontend räcker det att ignorera händelsetyperna `tool_use` / `tool_result` / `card` / `citation`; modellens slutliga utdata strömmas fortfarande via `text_delta`.

`max_turns` kan begränsa hur många rundor modellen som mest får anropa verktyg själv i denna förfrågan; intervallet är 1–500 och standardvärdet är 500 om det utelämnas. Om du anger ett lågt värde (till exempel `max_turns: 1`) kan du tvinga fram ett enda svar och förhindra alla verktygsanrop.

## Asynkront utförande och obemannad auktorisering

Om ditt anrop kommer från en webhook för larm, CI/CD, övervakningssystem eller andra bakgrundsuppgifter kan du ange `async: true` så att gränssnittet omedelbart returnerar ett uppgifts-ID medan körningen fortsätter i bakgrunden:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Exempel på svar:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Därefter kan du använda `action: retrieve` + `id` för att hämta samtalsresultatet; du kan också ange `callback_url`, och när uppgiften är klar kommer plattformen att POST:a `{ status, answer, usage, error }` till din återanropsadress. `callback_url` måste använda `http` / `https` och får inte direkt ange `localhost` eller en privat IP-literaladress.

Bakgrundsuppgifter har vanligtvis ingen som kan klicka på bekräfta. Om du vill att vissa Skills eller MCP Server ska utföra åtgärder som att skicka, publicera eller skriva i obemannat läge ska du uttryckligen skicka en lista över förauktoriseringar i förfrågningskroppen:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Värdena i `allowed_skills` är slug för anslutna Skills; värdena i `allowed_mcp_servers` är slug för anslutna MCP Server. Skills / MCP Server som inte ingår i förauktoriseringen kan i obemannat läge fortfarande endast förhandsgranska, köra dry-run eller nekas att utföra skrivåtgärder.

Om mer detaljerad kontroll behövs kan du också använda det likvärdiga objektet `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Förauktoriseringen består av dessa två listor: en tom lista innebär att inga funktioner auktoriseras, utan behov av ytterligare växlingsfält.

Observera: Förauktorisering innebär endast att ”denna förfrågan tillåter att dessa funktioner hoppar över manuell bekräftelse i obemannat läge”. Den specifika Skill måste fortfarande stödja `--unattended-confirm` eller motsvarande säkerhetsmekanism; annars fortsätter den med dry-run och utför inte skrivåtgärder direkt.

## Återuppta pausade samtal

Vissa verktyg får modellen att ”ställa en motfråga till användaren”. Modellen skickar då en händelse `ask_user_question`, och samtalet fryses i tillståndet `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Rendera denna händelse som ett kort i frontend så att användaren kan välja ett svar, och gör sedan nästa förfrågan med samma `id` genom att fylla tillbaka svaret via `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

`tool_use_id` i begärandetexten **måste** vara exakt samma som `tool_id` vid pausning; om de inte stämmer överens returneras 400. När `tool_results` samtidigt finns i begäran ignoreras `question` / `message` / `references`.

Om användaren beslutar att avstå från denna fråga räcker det att direkt skicka en ny `question` / `message`, så markerar plattformen automatiskt det pausade verktygsanropet som ”användaren hoppade över”.

## Konversationshantering (CRUD)

v2 erbjuder lättviktig konversationshantering på samma endpoint via fältet `action`, utan behov av att öppna ytterligare ett API.

### `action: retrieve` —— hämta en konversation

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Returnerar det fullständiga konversationsdokumentet (inklusive `messages`-historik, `model`, `title`, `tools_used` osv.).

### `action: retrieve_batch` —— lista konversationssammanfattningar

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Returnerar `{ items: [...], total }`. **Sammanfattningen innehåller inte `messages`**, vilket lämpar sig för sidofältslistor; om användaren öppnar en konversation, använd sedan `action: retrieve` för att hämta dess fullständiga meddelanden separat.

Valfria filterparametrar: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— ändra titel eller skriv om historiken

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

`messages` kan också skickas, men servern utför strikt schema-validering (måste vara i den hopfällda `ToolUseContent`-formen); om det inte uppfylls returneras 400. I allmänhet rekommenderas det endast för att ändra `title`.

### `action: delete` —— ta bort en konversation

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Returnerar `{ id, success: true }`. Efter borttagning kan den inte återställas, bekräfta innan du anropar.

## Smidig migrering från v1

Om du redan använder [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations) kräver migrering till v2 nästan inga kodändringar:

1. Ändra URL:en från `https://api.acedata.cloud/aichat/conversations` till `https://api.acedata.cloud/aichat2/conversations`.
2. Om du tidigare skickade v1-modellnamn (som `gpt-3.5`, `gpt-4-browsing` osv.) rekommenderas det att uppgradera till moderna modeller vid byte till v2 (som `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` osv.).
3. Fälten i NDJSON-strömmen förblir bakåtkompatibla: varje `text_delta`-händelse innehåller fortfarande `delta_answer` och `id`, så klienter som tidigare tolkar `delta_answer` rad för rad behöver inte ändras.

Efter migreringen kan du efter behov aktivera v2:s nya funktioner (multimodal `message`, SSE, verktygsanrop, `action` CRUD) och gå vidare i den takt som passar.

## Felhantering

Felsvar har ett enhetligt format:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Vanliga fel:

- `400 bad_request`: saknade obligatoriska fält, `tool_use_id` stämmer inte överens, ogiltigt `messages`-schema osv.
- `401 invalid_token`: `authorization`-huvudet är felaktigt.
- `404 not_found`: konversationen som motsvarar `id` finns inte vid `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: konversationen överskrider lagringsgränsen, befintliga sparade poster har inte skrivits över.
- `429 too_many_requests`: hastighetsgränsen har utlösts.
- `503 context_compaction_failed`: kontextkomprimering misslyckades, befintliga poster behålls.
- `500 conversation_persist_failed`: slutlig sparning för denna omgång misslyckades; mottagen text innebär inte att den slutliga posten har sparats. Fråga efter konversations-ID.
- `500 chat_error`: tjänsten är tillfälligt otillgänglig, eller så genererades inget innehåll i denna omgång (ingen debitering sker).

I strömmande svar skickas fel som händelsen `{"type":"error","message":"..."}`, varefter strömmen avslutas. `[DONE]` betyder endast att överföringen är avslutad; vid `error` får det inte betraktas som framgång, och ingen lyckad `done`-händelse skickas heller.

## Slutsats

AI Chat v2 API uppgraderar, samtidigt som det är bakåtkompatibelt med v1, dialoger från ”enkelrunds- / flerrundsfrågor och svar” till ”observerbara agentbaserade dialoger”: multimodal inmatning, verktygsanrop, pausbar / återupptagbar, strömmande strukturerade händelser och inbyggd CRUD. Nya integrationer rekommenderas att direkt använda v2; befintliga v1-integrationer kan migreras smidigt i etapper. Om du har några frågor, kontakta gärna vårt tekniska supportteam när som helst.
