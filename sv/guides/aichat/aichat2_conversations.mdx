AI Chat v2 API (`/aichat2/conversations`) är ett nytt generations konversationsgränssnitt och en omfattande uppgradering av [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Utöver den enkla, hanterade flerkonversationsfunktionaliteten i v1 utökas det med:

- **Multimodal användarinmatning**: Skicka text + bilder + filblock direkt via det strukturerade fältet `message`, utan att först behöva bifoga dem indirekt med `references`.
- **Agentbaserade verktygsanrop**: Inbyggda verktyg för webbsökning, webbsideshämtning, filläsning med mera. Det stöder även anslutning av MCP-servrar som auktoriserats av användaren (Google Drive, Notion, Slack, GitHub med flera), så att modellen självständigt kan anropa verktyg flera gånger inom en enda begäran för att slutföra komplexa uppgifter.
- **Strukturerade strömningshändelser**: Genom `accept: text/event-stream` eller `application/x-ndjson` kan du få händelser som `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` och andra token för token, vilket gör det enklare att återge dem separat i frontend efter motsvarande typ.
- **Kan avbrytas / återupptas**: När modellen behöver kompletterande information från användaren skickar den en `ask_user_question`-händelse och pausar. Vid nästa anrop kan svaret fyllas i via `tool_results` för att fortsätta.
- **Nya CRUD-åtgärder**: Genom fältet `action` på samma endpoint kan du utföra `retrieve` / `retrieve_batch` / `update` / `delete` utan ytterligare API:er för sessionshantering.
- **Kontinuerligt uppdaterad modellista**: Som standard finns moderna modeller som GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 med flera tillgängliga.

Samtidigt är det **helt bakåtkompatibelt med v1 på begäransnivå**: Skicka bara `model` + `question` (+ valfria `stateful` / `id` / `references` / `preset`) för att få ett JSON-svar av typen `{answer, id}` som motsvarar v1. Därför behöver du inte skriva om klienten när du migrerar från `/aichat/conversations`; det räcker att ändra sökvägen till `/aichat2/conversations`.

> Om du för närvarande använder `/aichat/conversations` kommer det gamla gränssnittet fortfarande att vara tillgängligt. Du kan migrera i din egen takt.

## Ansökningsprocess

För att använda AI Chat v2 API går du först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API-token och spara den för senare användning.

![]()

Om du ännu inte har loggat in eller registrerat dig kommer du automatiskt att omdirigeras till inloggningssidan för att registrera dig och logga in. När du är klar återgår du automatiskt till den aktuella sidan.

**En enda API-token räcker för att anropa alla plattformens tjänster. Du behöver inte ansöka separat för varje tjänst.** Vid den första ansökan får du gratis krediter som du kan använda för att prova tjänsten kostnadsfritt. När krediterna inte räcker kan du fylla på det allmänna saldot i [konsolen](https://platform.acedata.cloud/console/coin).

## Grundläggande användning

Det enklaste användningssättet är exakt detsamma som i v1: skicka `model` + `question` och få `{answer, id}`.

CURL-exempel:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Returresultat:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python-exempel:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

    "accept": "application/json",
    "authorization": "Bearer {token}",
```

## Flerkonversationsdialoger

Precis som i v1 aktiverar du sparande av konversationer genom att skicka `stateful: true`. API:et returnerar ett `id`. Vid efterföljande förfrågningar behöver du bara skicka tillbaka samma `id` för att fortsätta konversationen, utan att själv behöva hantera historiken för messages.

Första begäran:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Retur:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Andra begäran, med samma `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "Vilket var numret som jag bad dig komma ihåg nyss?"
  }'
```

```json
{
  "answer": "Numret som du bad mig komma ihåg är 42.",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` är `true` som standard. Att utelämna det och att uttryckligen skicka `true` är likvärdigt. Att ställa in `stateful: false` innebär att den tidigare konversationshistoriken inte läses in. Det betyder inte att resultatet från den aktuella omgången inte kommer att sparas, och det gäller inte verktygsflöden som kräver att man pausar och fortsätter senare.

### Långa konversationer och bevarande av originaltext

Kontextkomprimering organiserar endast innehållet som skickas till modellen under den aktuella omgången. Den ersätter inte de sparade chattmeddelandena. Genom `action: retrieve` kan du fortfarande läsa alla sparade meddelanden i sin helhet. Uttryckliga begäranden om att redigera eller radera en konversation gäller fortfarande.

Modellen kan söka i historiken inom den aktuella konversationen och läsa originaltexten i sidindelade delar. När du behöver fortsätta redigera en artikel, hänvisa till siffror eller förbereda publicering bör du läsa motsvarande originaltext. Sammanfattningar får inte ersätta brödtexten. Denna funktion återställer inte automatiskt meddelanden som redan har gått förlorade i äldre versioner.

Om kontextorganiseringen misslyckas ska du behålla konversations-ID:t och kontrollera `error`-händelsen. Tjänsten kommer inte att skriva över originaltexten med en tom sammanfattning. Verktygsåtgärder som slutfördes innan felet kan fortfarande vara giltiga. Kontrollera först deras resultat för att undvika att generera eller publicera samma sak flera gånger. När en enskild konversation når lagringsgränsen visas ett tydligt felmeddelande. Befintliga sparade poster frigör inte utrymme genom att beskäras. Du kan exportera det innehåll du behöver och sedan starta en ny konversation.

## Strömmande svar

v2 stöder två strömningsformat, som väljs med hjälp av `accept`-huvudet:

| Scenario | `accept` | Dataformat |
| --------------------- | ---------------------- | ------------------------------------------ |
| Webbgränssnitt / EventSource | `text/event-stream` | `data: {json}\n\n`, sista raden `data: [DONE]\n\n` |
| Server / CLI / Node-strömningsparsning | `application/x-ndjson` | Ett JSON-objekt per rad |
| Ingen strömning behövs | `application/json` (standard) | Returnerar `{answer, id}` på en gång |

### NDJSON-exempel

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "Presentera Hangzhou med tre meningar.",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # Kompatibilitet med v1: inkrementella fragment tillhandahålls samtidigt via fältet delta_answer
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Varje rad i NDJSON är en strukturerad händelse. Den vanligaste är `text_delta`:

```json
{"type":"text_delta","content":"Hang","delta_answer":"Hang","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"zhou","delta_answer":"zhou","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"är","delta_answer":"är","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE-exempel

I webbläsaren stöder `EventSource` inte anpassade förfrågningskroppar. Därför rekommenderas `fetch` + manuell parsning genom att dela upp innehållet vid `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "Presentera Hangzhou med tre meningar.",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Typer av strömningshändelser

| `type` | Betydelse |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta` | Inkrementella textfragment i assistentens svar. `content` innehåller det nya innehållet. För kompatibilitet med v1 innehåller samma händelse även `delta_answer` (lika med `content`) och `id`. |
| `thinking` | Modellens tankeprocess (visas endast när den valda modellen exponerar resonemang). |
| `tool_use` | Modellen beslutar att anropa ett verktyg. Händelsen innehåller `tool_id`, `tool_name` och `input`. |
| `tool_result` | Resultatet av verktygskörningen, kopplat till föregående `tool_use` via `tool_id`. `is_error` anger om körningen misslyckades. |
| `card` | Strukturerade kort som genereras av verktyg (till exempel bilder och länkförhandsvisningar), lämpliga för direkt återgivning. |
| `citation` | Käll-URL:er som kompletterar hänvisningar till motsvarande textfragment. |
| `ask_user_question` | Skickas när modellen behöver kompletterande information från användaren. Konversationen går då in i tillståndet `awaiting_user_input`. Se nedan [Återuppta en pausad konversation](#恢复暂停的对话). |
| `artifact` | Fristående resultat som genereras av modellen (till exempel kodblock och dokument), som kan sparas eller laddas ned. |
| `system_message` | Systemmeddelande (inte användar- eller assistentinnehåll), som endast används för UI-meddelanden. |
| `compact` | Modellens kontext har organiserats. De sparade originalmeddelandena förblir oförändrade, och klienten behöver inte radera chatthistoriken. |
| `error` | Ett fel inträffade under den aktuella omgången. `message` beskriver felet. |
| `done` | Den slutliga konversationsposten för den aktuella omgången har sparats. Innehåller `usage` (med `prompt_tokens` / `completion_tokens` / `total_tokens`) och `terminal_reason`. Du måste fortfarande bedöma om uppgiften har slutförts utifrån avslutningsorsaken. |
För klienter som endast bryr sig om det slutliga svaret är det likvärdigt med `answer` i läget `application/json` att sammanfoga `content` från alla `text_delta`.

## Multimodala indata

Om användarens indata innehåller bilder eller filer ska du skicka `message` (en array) i stället för `question`. Varje element i arrayen är ett innehållsblock:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "Hur många katter finns det på den här bilden?" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Typer av block som stöds:

- `text` — vanlig text, det obligatoriska fältet är `text`.
- `image_url` — bild, det obligatoriska fältet är `image_url.url`.
- `file_url` — fil (PDF, CSV, TXT osv.), det obligatoriska fältet är `file_url.url`.

### Förhållandet till v1 `references`

För kompatibilitet med äldre klienter känner v2 fortfarande igen fältet `references: ["https://...", ...]`:

- URL:er som slutar på `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif` konverteras automatiskt till block av typen `image_url`;
- andra filändelser konverteras till block av typen `file_url`;
- om `question` också anges läggs det till som ett `text`-block först.

Om du därför bara vill migrera från v1 utan att ändra förfrågans innehåll räcker det att byta sökvägen till `/aichat2/conversations`. Den ursprungliga användningen av `references` fungerar som vanligt.

Om du behöver mer exakt kontroll (till exempel att placera flera bilder mellan textavsnitt eller när ordningen är viktig) använder du direkt arrayen `message`.

## Verktygsanrop och MCP

Den viktigaste förbättringen i v2 är att modellen självständigt kan anropa verktyg för att utföra flerstegsuppgifter. **Detta är aktiverat som standard**, och klienten behöver inte göra några ytterligare inställningar i förfrågan. Vanliga scenarier:

- Användaren frågar: ”Sök efter nya utställningar i Shanghai på sistone” → modellen anropar den inbyggda webbsökningen → sammanställer resultaten till ett svar.
- Användaren frågar: ”Läs den här PDF-filen och skriv sedan en sammanfattning” → modellen anropar file_read → skriver en sammanfattning.
- Användaren har redan auktoriserat Google Drive / GitHub / Notion osv. under [Connections](https://platform.acedata.cloud/connections) → modellen kan anropa motsvarande MCP-verktyg för att läsa och skriva data.

I NDJSON / SSE-strömmar visas verktygsanrop genom två typer av händelser: `tool_use` och `tool_result`. Exempel:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"Shanghai Spring Exhibitions 2026"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"För närvarande","delta_answer":"För närvarande","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"Shanghai","delta_answer":"Shanghai","id":"f2f4b3e8-..."}
...
```

Om du inte vill visa detaljer om verktygsanrop i frontend kan du ignorera följande typer av händelser: `tool_use` / `tool_result` / `card` / `citation`. Modellens slutliga utdata kommer fortfarande att strömmas genom `text_delta`.

`max_turns` kan begränsa hur många omgångar modellen som mest får anropa verktyg själv under den aktuella förfrågan. Intervallet är 1–500 och standardvärdet är 500 om det utelämnas. Om du anger ett lågt värde (till exempel `max_turns: 1`) kan du tvinga fram ett enda svar och förhindra alla verktygsanrop.

## Asynkron körning och obevakad auktorisering

Om ditt anrop kommer från en larm-Webhook, ett CI/CD-system, ett övervakningssystem eller någon annan bakgrundsuppgift kan du ange `async: true` så att gränssnittet omedelbart returnerar ett uppgifts-ID medan körningen fortsätter i bakgrunden:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Min tjänst har utlöst ett larm. Använd mitt personliga WeChat-konto för att meddela WeChat-gruppen ”AceDataCloud-teamet” …"
}
```

Exempel på returvärde:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Därefter kan du använda `action: retrieve` + `id` för att hämta konversationsresultatet. Du kan också ange `callback_url`. När uppgiften är slutförd skickar plattformen ett POST-anrop med `{ status, answer, usage, error }` till din callback-adress. `callback_url` måste använda `http` / `https` och får inte direkt ange `localhost` eller en privat IP-adress i klartext.

Bakgrundsuppgifter har vanligtvis ingen person som kan klicka för att bekräfta. Om du vill att vissa Skills eller MCP Servers ska kunna utföra åtgärder som att skicka, publicera eller skriva data i obevakat läge måste du uttryckligen ange en lista över förhandsgodkända behörigheter i förfrågans innehåll:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Min tjänst har utlöst ett larm. Använd mitt personliga WeChat-konto för att meddela WeChat-gruppen ”AceDataCloud-teamet” …"
}
```

Värdena i `allowed_skills` är sluggar för anslutna Skills, medan värdena i `allowed_mcp_servers` är sluggar för anslutna MCP Servers. Skills / MCP Servers som inte finns med i listan över förhandsgodkända behörigheter får i obevakat läge endast förhandsgranska, utföra dry-run eller avvisa skrivåtgärder.

Om du behöver mer detaljerad kontroll kan du även använda det motsvarande objektet `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Förhandsgodkännandet utgörs enbart av dessa två listor: om en lista är tom innebär det att inga behörigheter beviljas, och inget ytterligare aktiveringsfält behövs.

Observera: Förhandsgodkännandet innebär endast att ”den aktuella förfrågan tillåter dessa funktioner att hoppa över manuell bekräftelse i obevakat läge”. Den aktuella Skill måste fortfarande ha stöd för `--unattended-confirm` eller motsvarande säkerhetsmekanism. Annars fortsätter den att utföra dry-run och genomför inte skrivåtgärder direkt.

## Återuppta pausade konversationer

Vissa verktyg kan få modellen att ”ställa en motfråga till användaren”. Då skickar modellen en händelse av typen `ask_user_question`, och konversationen fryses i tillståndet `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Vill du att rapporten ska genereras på kinesiska eller engelska?",
  "options": ["Kinesiska", "Engelska"],
  "id": "f2f4b3e8-..."
}
```

Återge denna händelse som ett kort i frontend så att användaren kan välja ett svar. Skicka sedan en ny förfrågan med samma `id` och fyll i svaret via `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

I begärandekroppen måste `tool_use_id` **vara** exakt identiskt med `tool_id` vid pausen. Om de inte överensstämmer returneras 400. När `tool_results` finns samtidigt i begäran ignoreras `question` / `message` / `references`.

Om användaren beslutar sig för att överge den här frågan räcker det att skicka en ny `question` / `message` direkt. Plattformen markerar då automatiskt det pausade verktygsanropet som ”användaren hoppade över”.

## Sessionshantering (CRUD)

v2 tillhandahåller lättviktig sessionshantering via fältet `action` på samma endpoint, utan att något separat API behöver öppnas.

### `action: retrieve` —— Hämta en session

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Returnerar hela sessionsdokumentet (inklusive historiken `messages`, `model`, `title`, `tools_used` osv.).

### `action: retrieve_batch` —— Lista sessionssammanfattningar

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Returnerar `{ items: [...], total }`. **Sammanfattningarna innehåller inte `messages`**, vilket gör dem lämpliga för listor i sidofältet. Om användaren öppnar en session hämtar du dess fullständiga meddelanden separat med `action: retrieve`.

Valfria filtreringsparametrar: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Ändra titel eller skriva om historiken

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Reseplan för Hangzhou"
}
```

Det går även att skicka `messages`, men servern utför en strikt schema-validering (de måste ha den hopfällda formen `ToolUseContent`). Om formatet inte stämmer returneras 400. I allmänhet rekommenderas att endast använda detta för att ändra `title`.

### `action: delete` —— Ta bort en session

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Returnerar `{ id, success: true }`. När sessionen har tagits bort kan den inte återställas. Bekräfta därför innan anropet görs.

## Smidig migrering från v1

Om du redan använder [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations) krävs nästan inga kodändringar för att migrera till v2:

1. Ändra URL:en från `https://api.acedata.cloud/aichat/conversations` till `https://api.acedata.cloud/aichat2/conversations`.
2. Om du tidigare använde modellnamn från v1 (t.ex. `gpt-3.5`, `gpt-4-browsing` osv.) rekommenderas att du uppgraderar till moderna modeller när du byter till v2 (t.ex. `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` osv.).
3. Fälten i NDJSON-strömmen är fortsatt bakåtkompatibla: varje `text_delta`-händelse innehåller fortfarande `delta_answer` och `id`. Därför behöver klienter som tidigare parsade `delta_answer` rad för rad inte ändras.

Efter migreringen kan du aktivera de nya funktionerna i v2 efter behov (multimodalt `message`, SSE, verktygsanrop, `action` CRUD) och införa dem i din egen takt.

## Felhantering

Felsvar har ett enhetligt format:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Vanliga fel:

- `400 bad_request`: Obligatoriska fält saknas, `tool_use_id` stämmer inte överens, `messages`-schemat är ogiltigt osv.
- `401 invalid_token`: `authorization`-huvudet är felaktigt.
- `404 not_found`: Sessionen som motsvarar `id` finns inte vid `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: Sessionen överskrider lagringsgränsen; befintliga sparade poster har inte skrivits över.
- `429 too_many_requests`: Hastighetsbegränsningen har utlösts.
- `503 context_compaction_failed`: Kontextkomprimeringen misslyckades; befintliga poster behålls.
- `500 conversation_persist_failed`: Den slutliga sparningen av den här omgången misslyckades. Att text har tagits emot innebär inte att den slutliga posten har sparats. Kontrollera sessionen med hjälp av dess ID.
- `500 chat_error`: Tjänsten är tillfälligt otillgänglig eller så genererades inget innehåll under den här omgången (ingen debitering sker).

I strömmande svar skickas fel som händelser i formatet `{"type":"error","message":"..."}`, varefter strömmen avslutas. `[DONE]` betyder endast att överföringen är avslutad. Om ett `error` förekommer kan svaret inte betraktas som lyckat, och ingen lyckad `done`-händelse skickas.

## Slutsats

AI Chat v2 API uppgraderar, samtidigt som bakåtkompatibiliteten med v1 bibehålls, konversationer från ”enstaka / flerrundiga frågor och svar” till ”Agent-baserade, observerbara konversationer”: multimodala indata, verktygsanrop, möjlighet att pausa / återuppta, strukturerade strömhändelser och inbyggd CRUD. Vi rekommenderar att nya integrationer använder v2 direkt. Befintliga v1-integrationer kan migreras smidigt i etapper. Om du har några frågor är du alltid välkommen att kontakta vårt tekniska supportteam.
