AI Chat v2 API (`/aichat2/conversations`) är den nya generationens konversationsgränssnitt och en fullständig uppgraderingsversion av [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Utöver v1:s enkla, hanterade flerrundskonversationer utökar den med:

- **Multimodala användarinmatningar**: Skicka text + bild- + filblock direkt via det strukturerade fältet `message`, utan att först behöva bifoga dem indirekt med `references`.
- **Agentbaserade verktygsanrop**: Har en inbyggd uppsättning verktyg för webbsökning, hämtning av webbsidor, filläsning med mera, och kan ansluta MCP-servrar som användaren har auktoriserat (Google Drive, Notion, Slack, GitHub etc.). Modellen kan självständigt anropa verktyg i flera omgångar inom en enda begäran för att slutföra komplexa uppgifter.
- **Strukturerade strömmande händelser**: Via `accept: text/event-stream` eller `application/x-ndjson` kan du få händelser som `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` med flera, token för token, vilket underlättar separat rendering av respektive typ i frontend.
- **Kan avbrytas / återupptas**: När modellen behöver att användaren kompletterar information skickar den händelsen `ask_user_question` och pausar. Vid nästa anrop kan du fortsätta genom att fylla i svaret via `tool_results`.
- **Nya CRUD-åtgärder**: Utför `retrieve` / `retrieve_batch` / `update` / `delete` via fältet `action` på samma endpoint, utan behov av ytterligare API:er för konversationshantering.
- **Kontinuerligt uppdaterad modellista**: Har som standard stöd för moderna modeller såsom GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 med flera.

Samtidigt är den på begäranivå **helt bakåtkompatibel med v1**: skicka endast `model` + `question` (+ valfritt `stateful` / `id` / `references` / `preset`) för att få ett JSON-svar `{answer, id}` som motsvarar v1. Därför behöver du inte skriva om klienten när du migrerar från `/aichat/conversations`; byt bara sökvägen till `/aichat2/conversations`.

> Om du för närvarande använder `/aichat/conversations` kommer det gamla gränssnittet fortfarande att behållas, och du kan migrera i din egen takt.

## Ansökningsprocess

För att använda AI Chat v2 API, gå först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API-token och spara den för framtida bruk.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte är inloggad eller registrerad omdirigeras du automatiskt till inloggningssidan där du uppmanas att registrera dig och logga in. När det är klart återvänder du automatiskt till den aktuella sidan.

**En API-token kan anropa alla tjänster på plattformen; du behöver inte ansöka separat för varje tjänst.** Vid första ansökan får du kostnadsfria krediter för en gratis testperiod; om krediterna inte räcker kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

## Grundläggande användning

Den enklaste användningen är exakt densamma som v1: skicka `model` + `question` och få `{answer, id}`.

CURL-exempel:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Returresultat:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python-exempel:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",

response = requests.post(url, json=payload, headers=headers)
```

## Flerrundskonversation

Precis som i v1 skickar du `stateful: true` för att aktivera konversationslagring. API:t returnerar ett `id`; inkludera sedan `id` i efterföljande begäranden för att fortsätta konversationen, utan att själv behöva underhålla historiken för messages.

Första begäran:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Svar:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Andra begäran, inkludera samma `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` är som standard `true`; att utelämna det är likvärdigt med att uttryckligen skicka `true`. Om du inte vill att servern sparar denna samtalsrunda kan du uttryckligen ange `stateful: false`.

## Strömmande svar

v2 stöder två strömmande format, som väljs utifrån `accept`-huvudet:

| Scenario                    | `accept`               | Dataformat                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Webbsidans frontend / EventSource  | `text/event-stream`    | `data: {json}\n\n`, sista raden `data: [DONE]\n\n` |
| Serversida / CLI / Node-strömmande tolkning | `application/x-ndjson` | Ett JSON-objekt per rad                               |
| Strömning behövs inte                 | `application/json`（standard） | Returnerar `{answer, id}` på en gång                       |

### NDJSON-exempel

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Varje rad i NDJSON är en strukturerad händelse, den vanligaste är `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE-exempel

`EventSource` på klientsidan i webbläsaren stöder inte anpassade begärandekroppar; det rekommenderas att använda `fetch` + manuell tolkning genom segmentering vid `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Typer av strömmande händelser

| `type`              | Betydelse                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `text_delta`        | Inkrementellt textsegment i assistentens svar. `content` är nytt innehåll; för kompatibilitet med v1 innehåller samma händelse även `delta_answer` (lika med `content`) och `id`.                  |
| `thinking`          | Modellens tankeprocess (visas endast när den valda modellen exponerar resonemang).                                                                |
| `tool_use`          | Modellen beslutar att anropa ett verktyg; händelsen innehåller `tool_id`, `tool_name`, `input`.                                                  |
| `tool_result`       | Verktygets körningsresultat, parat med föregående `tool_use` via `tool_id`; `is_error` anger om det misslyckades.                                       |
| `card`              | Strukturerade kort som genereras av verktyg (t.ex. bilder, länkförhandsvisningar), lämpliga för direkt rendering.                                                                    |
| `citation`          | Käll-URL:er som används för att komplettera hänvisningar till motsvarande textsegment.                                                                            |
| `ask_user_question` | Skickas när modellen behöver att användaren kompletterar information; samtalet går in i tillståndet `awaiting_user_input`, se [Återuppta pausade samtal](#återuppta-pausade-samtal) nedan.                           |
| `artifact`          | Ett fristående resultat som genereras av modellen (t.ex. kodblock, dokument), som kan sparas eller laddas ner.                                                                      |
| `system_message`    | Systemmeddelande (inte innehåll från användaren eller assistenten), används endast för UI-notiser.                                                                     |
| `compact`           | Händelse där intern kontext komprimeras, kräver ingen särskild hantering.                                                                             |
| `error`             | Ett fel uppstod under denna omgång, `message` beskriver felinnehållet.                                                                        |
| `done`              | Det strömmande svaret avslutas och innehåller `usage` (inklusive `prompt_tokens` / `completion_tokens` / `total_tokens`) och `terminal_reason`. |

För klienter som endast bryr sig om det slutliga svaret är det likvärdigt att sammanfoga `content` för alla `text_delta` med `answer` i läget `application/json`.

## Multimodal inmatning

Om användarens inmatning innehåller bilder eller filer ska `message` (en matris) skickas i stället för `question`. Varje matriselement är ett innehållsblock:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Blocktyper som stöds:

- `text` — Vanlig text, fältet `text` är obligatoriskt.
- `image_url` — Bild, `image_url.url` är obligatoriskt.
- `file_url` — Fil (PDF, CSV, TXT osv.), `file_url.url` är obligatoriskt.

### Relation till v1 `references`

För kompatibilitet med äldre klienter känner v2 fortfarande igen fältet `references: ["https://...", ...]`:
- URL-suffixet är `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, konverteras automatiskt till ett `image_url`-block;
- Andra filändelser konverteras till ett `file_url`-block;
- Om `question` också tillhandahålls, placeras den först som ett `text`-block.

Om du därför bara vill migrera från v1 utan att ändra request body, räcker det att byta sökvägen till `/aichat2/conversations`, så fungerar den ursprungliga användningen av `references` som vanligt.

Om du behöver mer detaljerad kontroll (till exempel att placera flera bilder mellan texter, eller om ordningen är viktig) använder du direkt arrayen `message`.

## Verktygsanrop och MCP

Kärnförbättringen i v2 är att modellen självständigt kan anropa verktyg för att slutföra uppgifter i flera steg, **detta är aktiverat som standard**, och kräver ingen extra konfiguration från klienten i begäran. Vanliga scenarier:

- Användaren frågar ”hjälp mig att söka efter vilka nya utställningar som finns i Shanghai nyligen” → modellen anropar inbyggd webbsökning → sammanställer resultaten till ett svar.
- Användaren frågar ”läs denna PDF och skriv sedan en sammanfattning” → modellen anropar file_read → skriver en sammanfattning.
- Användaren har auktoriserat Google Drive / GitHub / Notion med flera i [Connections](https://platform.acedata.cloud/connections) → modellen kan anropa motsvarande MCP-verktyg för att läsa och skriva deras data.

I NDJSON- / SSE-strömmar presenteras verktygsanrop genom två typer av händelser, `tool_use` och `tool_result`, till exempel:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Om du inte vill visa detaljer om verktygsanrop i frontend räcker det att ignorera händelsetyperna `tool_use` / `tool_result` / `card` / `citation`; modellens slutliga utdata strömmas fortfarande ut via `text_delta`.

`max_turns` kan begränsa hur många omgångar modellen som mest får anropa verktyg själv i denna begäran, med intervallet 1–500 och standardvärdet 500 om det utelämnas. Om du sätter det lågt (till exempel `max_turns: 1`) kan du tvinga fram ett enstaka svar och förbjuda alla verktygsanrop.

## Asynkron körning och obemannad auktorisering

Om ditt anrop kommer från en larm-Webhook, CI/CD, övervakningssystem eller annan bakgrundsuppgift, kan du ange `async: true` så att gränssnittet omedelbart returnerar ett uppgifts-ID och fortsätter körningen i bakgrunden:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Min tjänst har larmat, meddela WeChat-gruppen ”AceDataCloud团队” via personligt WeChat ……"
}
```

Exempel på returvärde:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Därefter kan du använda `action: retrieve` + `id` för att hämta konversationsresultatet; du kan också ange `callback_url`, så POST:ar plattformen `{ status, answer, usage, error }` till din callback-adress när uppgiften är slutförd. `callback_url` måste använda `http` / `https` och får inte direkt ange `localhost` eller en privat IP-literaladress.

För bakgrundsuppgifter finns det vanligtvis ingen som kan klicka på bekräftelse. Om du vill att vissa Skill eller MCP Server ska utföra åtgärder som att skicka, publicera eller skriva i obemannat läge, ska du uttryckligen skicka en lista över förhandsgodkännanden i request body:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Min tjänst har larmat, meddela WeChat-gruppen ”AceDataCloud团队” via personligt WeChat ……"
}
```

Värdena i `allowed_skills` är slug för anslutna Skill; värdena i `allowed_mcp_servers` är slug för anslutna MCP Server. Skill / MCP Server som inte listas i förhandsgodkännandet kan i obemannat läge fortfarande bara förhandsgranska, köra dry-run eller nekas att utföra skrivåtgärder.

Om mer detaljerad kontroll behövs kan du även använda det likvärdiga objektet `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Förhandsgodkännandet består av dessa två listor i sig: en tom lista innebär att inga funktioner godkänns, utan behov av ytterligare växlingsfält.

Observera: förhandsgodkännande betyder endast att ”denna begäran tillåter dessa funktioner att hoppa över manuell bekräftelse i obemannat läge”. Den specifika Skill måste fortfarande stödja `--unattended-confirm` eller motsvarande säkerhetsmekanism; annars fortsätter den som dry-run och utför inte skrivåtgärden direkt.

## Återuppta pausade konversationer

Vissa verktyg får modellen att ”ställa en motfråga till användaren”; modellen skickar då en `ask_user_question`-händelse och konversationen fryses i tillståndet `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Vill du att den genererade rapporten ska vara på kinesiska eller engelska?",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Rendera denna händelse som ett kort i frontend så att användaren kan välja ett svar, och gör sedan nästa begäran med samma `id`, där svaret fylls tillbaka via `tool_results`:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

`tool_use_id` i request body **måste** vara helt identiskt med `tool_id` när pausen inträffade; om de inte stämmer överens returneras 400. När `tool_results` finns i begäran samtidigt ignoreras både `question` / `message` / `references`.

Om användaren beslutar sig för att överge denna fråga räcker det att direkt skicka en ny `question` / `message`; plattformen markerar automatiskt det pausade verktygsanropet som ”användaren hoppade över”.

## Konversationshantering (CRUD)

v2 tillhandahåller lättviktig konversationshantering via fältet `action` på samma endpoint, utan att behöva öppna ett separat API.
### `action: retrieve` —— Hämta en konversation

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Returnerar det fullständiga konversationsdokumentet (inklusive historiken `messages`, `model`, `title`, `tools_used` osv.).

### `action: retrieve_batch` —— Lista konversationssammanfattningar

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Returnerar `{ items: [...], total }`. **Sammanfattningar innehåller inte `messages`**, lämpligt för sidofältslistor; om användaren öppnar en konversation använder du sedan `action: retrieve` för att hämta dess fullständiga meddelanden separat.

Valfria filterparametrar: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Ändra titel eller skriv om historiken

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

`messages` kan också skickas, men servern utför strikt schema-validering (måste vara i den hopfällda formen `ToolUseContent`), och returnerar 400 om det inte uppfyller kraven. Det rekommenderas vanligtvis endast att använda detta för att ändra `title`.

### `action: delete` —— Ta bort en konversation

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Returnerar `{ id, success: true }`. Det går inte att återställa efter borttagning, bekräfta innan du anropar.

## Smidig migrering från v1

Om du redan använder [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations) kräver migrering till v2 nästan inga kodändringar:

1. Ändra URL:en från `https://api.acedata.cloud/aichat/conversations` till `https://api.acedata.cloud/aichat2/conversations`.
2. Om du tidigare skickade v1-modellnamn (som `gpt-3.5`, `gpt-4-browsing` osv.) rekommenderas du att uppgradera till moderna modeller när du byter till v2 (som `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` osv.).
3. Fälten i NDJSON-strömmen förblir bakåtkompatibla: varje `text_delta`-händelse innehåller fortfarande `delta_answer` och `id`, så klienter som tidigare tolkar `delta_answer` rad för rad behöver inte ändras.

Efter migreringen kan du vid behov aktivera v2:s nya funktioner (multimodalt `message`, SSE, verktygsanrop, `action` CRUD) och gå vidare i din egen takt.

## Felhantering

Felsvar har en enhetlig form:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Vanliga fel:

- `400 bad_request`: Obligatoriska fält saknas, `tool_use_id` matchar inte, `messages`-schemat är ogiltigt osv.
- `401 invalid_token`: `authorization`-headern är felaktig.
- `404 not_found`: Konversationen som motsvarar `id` finns inte vid `action: retrieve / update / delete`.
- `429 too_many_requests`: Hastighetsbegränsningen har utlösts.
- `500 chat_error`: Uppströms-LLM rapporterar ett fel eller `completion_tokens=0` i denna omgång (behandlas som ej förbrukat och debiteras inte).

I strömmande svar skickas fel som händelsen `{"type":"error","message":"..."}`, varefter strömmen avslutas direkt.

## Slutsats

AI Chat v2 API uppgraderar, samtidigt som det är bakåtkompatibelt med v1, konversationer från ”enkelrunds- / flerrundsfrågor och svar” till ”agentifierade observerbara konversationer”: multimodala indata, verktygsanrop, möjlighet att pausa / återuppta, strömmande strukturerade händelser och inbyggd CRUD. Det rekommenderas att nya integrationer använder v2 direkt; befintliga v1-integrationer kan migreras smidigt i etapper. Om du har några frågor, kontakta gärna vårt tekniska supportteam när som helst.
