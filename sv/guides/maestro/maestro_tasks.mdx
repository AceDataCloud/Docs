Maestro API för uppgiftsfrågor har som huvudfunktion att, via uppgifts-ID:t som returneras av [Maestro API för videogenerering](development_maestro_videos.md) (`POST /maestro/videos`), fråga efter uppgiftens körstatus och slutresultat.

Detta dokument kommer att i detalj introducera integrationsanvisningarna för Maestro API för uppgiftsfrågor. Eftersom videogenerering är en asynkron uppgift behöver du efter inskickning använda detta gränssnitt för att polla och hämta förloppet och den färdiga videon, **pollning är gratis och förbrukar inga poäng.**

`POST https://api.acedata.cloud/maestro/tasks`

## Ansökningsprocess

För att använda Maestro API för uppgiftsfrågor, gå först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API Token och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig kommer du automatiskt att omdirigeras till inloggningssidan där du uppmanas att registrera dig och logga in, och därefter återvänder du automatiskt till den aktuella sidan.

**En API Token kan anropa alla plattformens tjänster, utan att behöva ansöka separat för varje tjänst.** Vid den första ansökan får du gratis kredit för att kunna prova kostnadsfritt; om krediten är otillräcklig kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Maestro API för uppgiftsfrågor →](https://platform.acedata.cloud/documents/maestro-tasks)

## Fråga efter en enskild uppgift

För information om hur du skapar en videouppgift, se dokumentationen [Maestro API för videogenerering](development_maestro_videos.md). Vi använder ett uppgifts-ID som returneras av det som exempel: `f57e99c4f60f4373a15517742ce2357d`, för att visa hur du frågar efter dess status och resultat.

### Ställ in begärandehuvuden och begärandetext

**Request Headers** inkluderar:

- `accept`: anger att svar i JSON-format ska tas emot, ange här `application/json`.
- `authorization`: nyckeln för att anropa API:t, kan väljas direkt från rullgardinsmenyn efter ansökan.
- `content-type`: formatet på begärandetexten, ange här `application/json`.

**Request Body** inkluderar:

| Fält       | Typ     | Obligatoriskt        | Beskrivning                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | Obligatoriskt vid fråga av en enskild uppgift | `task_id` som returneras av `POST /maestro/videos`              |
| `action` | string | Nej         | `retrieve` (standard, frågar efter en enskild uppgift); fast värde `retrieve_batch` vid fråga av historiklista |

### Kodexempel

Motsvarande CURL-kod är följande:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Motsvarande Python-kod är följande:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Fälten i returresultatet introduceras enligt följande:

- `id`: ID:t för denna videouppgift, används för att unikt identifiera denna videogenereringsuppgift.
- `status`: uppgiftsstatus, värdena är `pending → planning → producing → succeeded` (eller `failed`). Huruvida uppgiften har slutförts avgörs av denna översta `status`.
- `elapsed`: uppgiftens förflutna tid (sekunder).
- `progress`: förloppsobjekt på toppnivå, `percent` (0–100) sätts till 100 som reserv efter att uppgiften har lyckats; `stage` och `message` återspeglar den senaste förloppshändelsen från AI-regissören (därför kan `stage` efter lyckad körning fortfarande vara det sista körningsstadiet, såsom `producing`), och kan användas direkt för att visa förloppsindikatorn.
- `request`: begärandetexten när uppgiften initierades.
- `response`: uppgiftens returinformation.
  - `success`: huruvida uppgiften lyckades.
  - `data.variants`: varje språk motsvarar ett färdigt videoobjekt, inklusive `lang`, `aspect`, `title`, `output_url` (nedladdningsadress för färdig video) med mera.
  - `data.project`: hela projektets resultat, inklusive `tarball_url` (projektpaket) och `outputs` (alla länkar till färdiga videor).
  - `data.progress`: en array med förloppshändelser som läggs till per steg (append-only-logg), kan användas för att visa detaljerat förlopp i realtid.
- `created_at`: tidpunkt då uppgiften skapades, Unix-tidsstämpel (sekunder).
- `started_at`: tidpunkt då uppgiften började köras, Unix-tidsstämpel (sekunder). Är null när uppgiften ännu inte har startat.
- `finished_at`: tidpunkt då uppgiften slutfördes, Unix-tidsstämpel (sekunder). Är null när uppgiften inte är slutförd.

## Fråga efter historiklista

Genom att skicka `action: retrieve_batch` kan du hämta den senast utförda uppgiften för den aktuella inloggade utföraren (i omvänd kronologisk ordning efter skapandetid), vilket kan användas för listsidan ”Mina videor”. Historiklistan är isolerad per inloggningsidentitet.

**Request Body** inkluderar:
| Fält               | Typ     | Obligatoriskt  | Beskrivning                              |
| ---------------- | ------ | --- | ------------------------------- |
| `action`         | string | Ja   | Fast värde `retrieve_batch`            |
| `limit`          | int    | Nej   | Antal returnerade poster, standard är 20; giltigt intervall är 1–100          |
| `created_at_max` | int    | Nej   | Returnerar endast uppgifter strikt före denna Unix-tidsstämpel (exklusive gränsvärdet, för sidindelning) |
| `created_at_min` | int    | Nej   | Returnerar endast uppgifter strikt efter denna Unix-tidsstämpel (exklusive gränsvärdet)     |

### Kodexempel

Motsvarande CURL-kod är följande:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

## Rekommendationer för polling

Eftersom videoproduktion tar lång tid kommer `status` att gå igenom `pending → planning → producing → succeeded` (eller `failed`). Det rekommenderas att polla en gång var 5–10:e sekund tills `status` blir `succeeded` eller `failed`. Du kan använda `progress.percent` på toppnivå för att visa en förloppsindikator i realtid. **Polling av detta gränssnitt är kostnadsfri och förbrukar inga poäng.**

## Felhantering

När du anropar API:t returnerar API:t motsvarande felkod och information om ett fel uppstår. Till exempel:

- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `404 not_found`: Uppgiften hittades inte, det angivna task_id finns inte.
- `429 too_many_requests`: För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.

### Exempel på felsvar

