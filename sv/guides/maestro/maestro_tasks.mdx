Maestro uppgiftsfråge-API:s huvudsakliga funktion är att hämta status och slutresultat för en uppgift via det uppgifts-ID som returneras av [Maestro video-genererings-API](development_maestro_videos.md) (`POST /maestro/videos`).

Detta dokument kommer att ge en detaljerad beskrivning av Maestro uppgiftsfråge-API:s integrationsanvisningar. Eftersom video-generering är en asynkron uppgift, behöver man använda detta gränssnitt för att pollera för att få framsteg och slutprodukt, **polling är gratis och förbrukar inga poäng.**

`POST https://api.acedata.cloud/maestro/tasks`

## Ansökningsprocess

För att använda Maestro uppgiftsfråge-API, börja med att hämta din API-token från [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för framtida bruk.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Om du inte har loggat in eller registrerat dig, kommer du automatiskt att omdirigeras till inloggningssidan som bjuder in dig att registrera dig och logga in, och efter att ha slutfört detta kommer du automatiskt att återvända till den aktuella sidan.

**En API-token räcker för att anropa alla tjänster på plattformen, det behövs ingen separat ansökan för varje tjänst.** Första ansökan ger en gratis kvot för att prova; när kvoten är slut kan du ladda på allmänna saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Maestro uppgiftsfråge-API →](https://platform.acedata.cloud/documents/maestro-tasks)

## Fråga enskild uppgift

För information om hur man skapar video-uppgifter, se dokumentet [Maestro video-genererings-API](development_maestro_videos.md). Vi tar ett exempel med ett uppgifts-ID som returnerades: `f57e99c4f60f4373a15517742ce2357d`, och visar hur man frågar efter dess status och resultat.

### Ställ in begärningshuvuden och begärningskropp

**Begärningshuvuden** inkluderar:

- `accept`: specificera att du tar emot svar i JSON-format, här anges som `application/json`.
- `authorization`: nyckeln för att anropa API:t, kan väljas direkt efter ansökan.
- `content-type`: formatet för begärningskroppen, här anges som `application/json`.

**Begärningskropp** inkluderar:

| Fält       | Typ     | Obligatoriskt  | Beskrivning                                                |
| -------- | ------ | --- | ------------------------------------------------- |
| `id`     | string | Ja   | `task_id` som returnerades av `POST /maestro/videos`              |
| `action` | string | Nej   | `retrieve` (standard, fråga enskild uppgift) / `retrieve_batch` (fråga historisk uppgiftslista) |

### Kodexempel

Den motsvarande CURL-koden ser ut så här:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Den motsvarande Python-koden ser ut så här:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Svarsexempel

När begäran lyckas kommer API:t att returnera status och resultat för den videouppgiften. Exemplet på svar när uppgiften är slutförd ser ut så här (varje språk motsvarar en `variant`):

```json
{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "status": "succeeded",
  "elapsed": 312,
  "progress": { "percent": 100, "stage": "producing", "message": "rendering scene 2" },
  "request": {
    "prompt": "Förklara vad en vektordatabas är på 20 sekunder, lämplig för nybörjare, avsluta med en minnespunkt",
    "langs": ["zh-cn", "en"],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        { "lang": "zh-cn", "aspect": "9:16", "kind": "video", "title": "Vad är en vektordatabas", "output_url": "https://…/zh.mp4" },
        { "lang": "en", "aspect": "9:16", "kind": "video", "title": "What is a vector database", "output_url": "https://…/en.mp4" }
      ],
      "project": { "tarball_url": "https://…/project.tar.gz", "outputs": ["https://…/zh.mp4", "https://…/en.mp4"] },
      "percent": 100,
      "stage": "producing",
      "progress": [ { "stage": "producing", "message": "rendering scene 2", "pct": 60, "t": 1750000000 } ]
    }
  }
}
```

Beskrivningen av fälten i det returnerade resultatet är som följer:

- `id`: ID för denna videouppgift, används för att unikt identifiera denna video-genereringsuppgift.
- `status`: uppgiftens status, värdena är `pending → planning → producing → succeeded` (eller `failed`). Om uppgiften är slutförd, baseras det på den översta `status`.
- `elapsed`: tid som uppgiften har tagit (i sekunder).
- `progress`: övergripande progressobjekt, `percent` (0–100) kommer att sättas till 100 efter att uppgiften har lyckats; `stage` och `message` återspeglar den senaste progresshändelsen från AI-regissören (därför kan `stage` fortfarande vara den sista utförda fasen som `producing` efter att den har lyckats), kan direkt användas för att visa en progressbar.
- `request`: begärningskroppen vid uppgiftsstart.
- `response`: informationen som returneras av uppgiften.
  - `success`: om uppgiften lyckades.
  - `data.variants`: varje språk motsvarar ett slutresultatsobjekt, innehåller `lang`, `aspect`, `title`, `output_url` (nedladdningslänk för slutprodukten) etc.
  - `data.project`: hela projektprodukten, innehåller `tarball_url` (projektpaket) och `outputs` (alla slutproduktionslänkar).
  - `data.progress`: en array av progresshändelser som läggs till per fas (append-only logg), kan användas för att visa detaljerad realtidsprogress.

## Fråga historisk lista

Genom att ange `action: retrieve_batch` kan du hämta de senaste uppgifterna för den aktuella användaren (i omvänd skapelsedatumordning), vilket kan användas för "Mina videor"-sidan.

**Begärningskropp** inkluderar:

| Fält               | Typ     | Obligatoriskt  | Beskrivning                      |
| ---------------- | ------ | --- | ----------------------- |
| `action`         | string | Ja   | Fastställt till `retrieve_batch`    |
| `limit`          | int    | Nej   | Antal som returneras, standard 20              |
| `created_at_max` | int    | Nej   | Endast returnera uppgifter som är tidigare än denna Unix-tidsstämpel (för paginering) |
| `created_at_min` | int    | Nej   | Endast returnera uppgifter som är senare än denna Unix-tidsstämpel      |

### Kodexempel

Den motsvarande CURL-koden ser ut så här:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### Svarsexempel

När begäran lyckas kommer API:t att returnera den historiska uppgiftslistan för den aktuella användaren:
```json
{
  "count": 2,
  "items": [
    {
      "id": "f57e99c4f60f4373a15517742ce2357d",
      "status": "succeeded",
      "progress": { "percent": 100, "stage": "producing", "message": "rendering scene 2" },
      "request": { "prompt": "…", "langs": ["zh-cn", "en"], "aspect": "9:16", "duration": 20 },
      "response": { "success": true, "data": { "variants": [ { "lang": "zh-cn", "output_url": "https://…/zh.mp4" } ] } }
    }
  ]
}
```

Fälten i det returnerade resultatet beskrivs som följer:

- `count`: Det totala antalet uppgifter för den aktuella användaren.
- `items`: Uppgiftsarray, där varje element har samma format som resultatet av "fråga enskild uppgift".

## Pollingförslag

Eftersom videoproduktionen tar tid kommer `status` att genomgå `pending → planning → producing → succeeded` (eller `failed`). Det rekommenderas att pollera var 5–10 sekund tills `status` ändras till `succeeded` eller `failed`. Du kan använda den övergripande `progress.percent` för att visa en realtids framstegsindikator. **Polling av detta gränssnitt är gratis och förbrukar inga poäng.**

## Felhantering

När du anropar API:et, om du stöter på ett fel, kommer API:et att returnera motsvarande felkod och meddelande. Till exempel:

- `401 invalid_token`: Obefogad, ogiltig eller saknad auktoriseringstoken.
- `404 not_found`: Uppgift hittades inte, det angivna task_id existerar inte.
- `429 too_many_requests`: För många förfrågningar, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.

### Exempel på felrespons

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
