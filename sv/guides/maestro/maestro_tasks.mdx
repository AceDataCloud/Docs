Maestro uppgiftsfråge-API:s huvudsakliga funktion är att genom [Maestro videoproduktions-API](development_maestro_videos.md) (`POST /maestro/videos`) returnerade uppgifts-ID, fråga om status och slutresultat för den uppgiften.

Detta dokument kommer att detaljerat beskriva integrationsbeskrivningen för Maestro uppgiftsfråge-API. Eftersom videoproduktion är en asynkron uppgift, behöver man använda detta gränssnitt för att pollera för att få framsteg och slutprodukt, **polling är gratis och förbrukar inga poäng.**

`POST https://api.acedata.cloud/maestro/tasks`

## Ansökningsprocess

För att använda Maestro uppgiftsfråge-API, börja med att gå till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att få din API-token, som du kan spara för framtida bruk.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du inte är inloggad eller registrerad, kommer du automatiskt att omdirigeras till inloggningssidan som bjuder in dig att registrera dig och logga in, och efter att ha slutfört detta kommer du automatiskt att återvända till den aktuella sidan.

**En API-token räcker för att anropa alla tjänster på plattformen, det behövs ingen separat ansökan för varje tjänst.** Första ansökan ger en gratis kvot, så att du kan prova gratis; när kvoten är slut kan du ladda på allmänna saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Maestro uppgiftsfråge-API →](https://platform.acedata.cloud/documents/maestro-tasks)

## Fråga enskild uppgift

För information om hur man skapar videouppgifter, se dokumentet [Maestro videoproduktions-API](development_maestro_videos.md). Vi tar ett exempel med ett uppgifts-ID som returnerades: `f57e99c4f60f4373a15517742ce2357d`, och visar hur man frågar om dess status och resultat.

### Ställ in begärningshuvuden och begärningskropp

**Begärningshuvuden** inkluderar:

- `accept`: specificera att du tar emot svar i JSON-format, här anges som `application/json`.
- `authorization`: nyckeln för att anropa API:t, kan väljas direkt efter ansökan.
- `content-type`: formatet för begärningskroppen, här anges som `application/json`.

**Begärningskropp** inkluderar:

| Fält       | Typ     | Obligatoriskt  | Beskrivning                                                |
| -------- | ------ | --- | ------------------------------------------------- |
| `id`     | string | Ja   | `task_id` som returnerades av `POST /maestro/videos`              |
| `action` | string | Nej   | `retrieve` (standard, fråga enskild uppgift) / `retrieve_batch` (fråga historisk uppgiftslista) |

### Kodexempel

Den motsvarande CURL-koden ser ut så här:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Den motsvarande Python-koden ser ut så här:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Svarsexempel

Vid en lyckad begäran kommer API:t att returnera status och resultat för den videouppgiften. Exemplet på svar när uppgiften är slutförd ser ut så här (varje språk motsvarar en `variant`):

```json
  "status": "succeeded",

    "message": "rendering scene 2"
  },
  "request": {
    "prompt": "Förklara vad en vektordatabas är på 20 sekunder, lämpligt för nybörjare, avsluta med en minnespunkt",
    "langs": [
      "zh-cn",
      "en"
    ],
    "aspect": "9:16",

          "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-002"
        }
      ],

        "tarball_url": null,
        "outputs": [
          "https://…/zh.mp4",

        ]
      },
      "percent": 100,
      "stage": "producing",
      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }

```

Beskrivningen av fälten i returresultatet är som följer:

- `id`: ID för denna videouppgift, används för att unikt identifiera denna videoproduktionsuppgift.
- `status`: uppgiftens status, värdena är `pending → planning → producing → succeeded` (eller `failed`). Om uppgiften är slutförd, baseras det på den översta `status`.
- `elapsed`: tid som uppgiften har tagit (i sekunder).
- `progress`: övergripande progressobjekt, `percent` (0–100) kommer att sättas till 100 efter att uppgiften har lyckats; `stage` och `message` återspeglar den senaste framstegshändelsen från AI-regissören (därför kan `stage` fortfarande vara den sista utförda fasen som `producing` efter att den har lyckats), kan direkt användas för att visa en progressbar.
- `request`: begärningskroppen vid uppstart av uppgiften.
- `response`: informationen som returneras av uppgiften.
  - `success`: om uppgiften lyckades.
  - `data.variants`: varje språk motsvarar ett slutresultatsobjekt, innehåller `lang`, `aspect`, `title`, `output_url` (nedladdningslänk för slutprodukten) etc.
  - `data.project`: hela projektprodukten, innehåller `tarball_url` (projektpaket) och `outputs` (alla slutproduktionslänkar).
  - `data.progress`: en array av framstegshändelser som läggs till per fas (append-only logg), kan användas för att visa detaljerad realtidsprogress.
- `created_at`: tidpunkten då uppgiften skapades, Unix-tidsstämpel (i sekunder).
- `started_at`: tidpunkten då uppgiften började utföras, Unix-tidsstämpel (i sekunder). Om uppgiften ännu inte har påbörjats är den null.
- `finished_at`: tidpunkten då uppgiften slutfördes, Unix-tidsstämpel (i sekunder). Om uppgiften inte är slutförd är den null.

## Fråga historisk lista

Genom att ange `action: retrieve_batch` kan du få de senaste uppgifterna för den aktuella användaren (i omvänd ordning efter skapelsedatum), vilket kan användas för sidan "Mina videor".

**Begärningskropp** inkluderar:
| Fält               | Typ     | Obligatoriskt  | Beskrivning                      |
| ---------------- | ------ | --- | ----------------------- |
| `action`         | string | Ja   | Fastställt till `retrieve_batch`    |
| `limit`          | int    | Nej   | Antal som returneras, standard 20              |
| `created_at_max` | int    | Nej   | Returnera endast uppgifter som är tidigare än denna Unix-tidsstämpel (för paginering) |
| `created_at_min` | int    | Nej   | Returnera endast uppgifter som är senare än denna Unix-tidsstämpel      |

### Kodexempel

Motsvarande CURL-kod ser ut som följer:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

## Pollingförslag

Eftersom videoproduktion tar tid kommer `status` att genomgå `pending → planning → producing → succeeded` (eller `failed`). Det rekommenderas att pollera var 5–10 sekund tills `status` ändras till `succeeded` eller `failed`. Du kan använda den övergripande `progress.percent` för att visa en realtids framstegsindikator. **Polling av detta gränssnitt är gratis och förbrukar inga poäng.**

## Felhantering

Vid anrop av API:et, om ett fel uppstår, kommer API:et att returnera motsvarande felkod och information. Till exempel:

- `401 invalid_token`: Obefogad, ogiltig eller saknad auktoriseringstoken.
- `404 not_found`: Uppgift hittades inte, det angivna task_id existerar inte.
- `429 too_many_requests`: För många begärningar, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.

### Felrespons exempel

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
