Luma Tasks API:s huvudfunktion är att genom att ange det uppdrag ID som genererats av Luma Videos Generation API för att kontrollera statusen för det uppdraget.

Detta dokument kommer att detaljerat beskriva Luma Tasks API:s integrationsanvisningar, för att hjälpa dig att enkelt integrera och fullt utnyttja denna APIs kraftfulla funktioner. Genom Luma Tasks API kan du enkelt kontrollera statusen för uppdrag som utförs av Luma Videos Generation API.

## Ansökningsprocess

För att använda Luma Videos Generation API, börja med att gå till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att få din API-token, som du kan spara för framtida bruk.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du inte har loggat in eller registrerat dig, kommer du automatiskt att omdirigeras till inloggningssidan för att registrera dig och logga in, och efter att ha slutfört detta kommer du automatiskt att återvända till den aktuella sidan.

**En API-token räcker för att anropa alla tjänster på plattformen, du behöver inte ansöka separat för varje tjänst.** Första ansökan ger en gratis kvot, så att du kan prova gratis; när kvoten är otillräcklig kan du ladda på allmän balans i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Luma Videos Generation API →](https://platform.acedata.cloud/documents/luma-videos)

## Begärningsexempel

Luma Tasks API kan användas för att kontrollera resultaten från Luma Videos Generation API. För information om hur man använder Luma Videos Generation API, se dokumentationen [Luma Videos Generation API](https://platform.acedata.cloud/documents/luma-videos-integration).

Vi tar ett exempel med ett uppdrag ID som returnerats av Luma Videos Generation API, för att demonstrera hur man använder denna API. Anta att vi har ett uppdrag ID: 50fc6182-fa86-4c7d-ac12-2fa27ec2f151, och vi visar hur man gör detta genom att ange ett uppdrag ID.

### Ställ in begärningshuvuden och begärningskropp

**Begärningshuvuden** inkluderar:

- `accept`: anger att du tar emot svar i JSON-format, här anges som `application/json`.
- `authorization`: nyckeln för att anropa API:t, som kan väljas direkt efter ansökan.

**Begärningskropp** inkluderar:

- `id`: det uppladdade uppdrag ID:t.
- `action`: hur uppdraget ska hanteras.

Inställningarna visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/g6ev5b.png" width="500" className="m-auto" /></p>

### Kodexempel

Det kan noteras att olika språkets kod redan har genererats automatiskt på höger sida av sidan, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/i4fxqf.png" width="500" className="m-auto" /></p>

Några kodexempel är som följer:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/luma/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "50fc6182-fa86-4c7d-ac12-2fa27ec2f151",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/luma/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "50fc6182-fa86-4c7d-ac12-2fa27ec2f151",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Det returnerade resultatet innehåller flera fält, där `request`-fältet är begärningskroppen vid uppdragets start, medan `response`-fältet är svaret som returneras efter att uppdraget har slutförts, vars resultat överensstämmer med begäran och svaret från Luma Videos Generation API. Fälten beskrivs nedan.

- `id`, ID:t för att generera detta videouppdrag, används för att unikt identifiera detta videogenereringsuppdrag.
- `video_id`, den unika identifieraren för videon i det här videouppdraget, som behövs för framtida utvidgningsoperationer av videon.
- `request`, begärningsinformationen i videouppdraget.
- `response`, svarsinformationen i videouppdraget.
- `created_at`, tidpunkten då uppdraget skapades, Unix-tidsstämpel (sekunder, flyttal).
- `started_at`, tidpunkten då uppdraget började utföras, Unix-tidsstämpel (sekunder, flyttal).
- `finished_at`, tidpunkten då uppdraget slutfördes, Unix-tidsstämpel (sekunder, flyttal). Detta fält returneras inte om uppdraget inte är slutfört.
- `elapsed`, den tid som uppdraget tog, i sekunder (flyttal, med 3 decimaler). Detta fält returneras inte om uppdraget inte är slutfört.

## Felhantering

Vid anrop av API:et, om det uppstår ett fel, kommer API:et att returnera motsvarande felkod och information. Till exempel:

- `400 token_mismatched`：Felaktig begäran, möjligtvis på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`：Felaktig begäran, möjligtvis på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`：Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`：För många begärningar, du har överskridit hastighetsgränsen.
- `500 api_error`：Intern serverfel, något gick fel på servern.
