Denna artikel kommer att introducera en Veo Videos Generation API integrationsbeskrivning, som kan generera officiella Veo-videor genom att ange anpassade parametrar.

## Ansökningsprocess

För att använda Veo Videos Generation API, börja med att gå till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API-token, som du ska spara.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Om du inte har loggat in eller registrerat dig, kommer du automatiskt att omdirigeras till inloggningssidan där du uppmanas att registrera dig och logga in. När detta är klart kommer du automatiskt att återvända till den aktuella sidan.

**En API-token kan användas för att anropa alla tjänster på plattformen, det krävs ingen separat ansökan för varje tjänst.** Första ansökan ger en gratis kvot för att prova; när kvoten är slut kan du ladda på allmän balans i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Veo Videos Generation API →](https://platform.acedata.cloud/documents/veo-videos)

## Grundläggande användning

Först bör du förstå den grundläggande användningen, vilket innebär att ange en prompt `prompt`, en åtgärd `action`, en array av referensbilder för första och sista bild `image_urls` samt modellen `model`, för att få det bearbetade resultatet. Först behöver du enkelt skicka ett `action`-fält, vars värde är `text2video`, som huvudsakligen innehåller tre typer av åtgärder: text till video (`text2video`), bild till video (`image2video`), hämta 1080p-video (`get1080p`). Sedan behöver vi också ange modellen `model`, som för närvarande huvudsakligen inkluderar `veo31-fast`, `veo3`, `veo31`, `veo3-fast` och `veo31-fast-ingredients`, med specifikt innehåll som följer:

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

Här kan vi se att vi har ställt in Request Headers, inklusive:

- `accept`: vilken format av svar du vill ta emot, här anges som `application/json`, det vill säga JSON-format.
- `authorization`: nyckeln för att anropa API:et, som kan väljas direkt efter ansökan.

Dessutom har vi ställt in Request Body, inklusive:

- `model`: modellen för att generera videon, huvudsakligen `veo31-fast`, `veo3`, `veo31`, `veo3-fast` och `veo31-fast-ingredients`.
- `action`: åtgärden för denna videogenereringsuppgift, som huvudsakligen innehåller tre typer av åtgärder: text till video (`text2video`), bild till video (`image2video`), hämta 1080p-video (`get1080p`).
- `image_urls`: när bild till video-åtgärden `image2video` väljs, måste referensbildlänkar laddas upp. `veo31-fast-ingredients` stöder upp till 3 bilder (flera bildfusioner), medan övriga modeller stöder upp till 2 bilder (första och sista bildläge).
- `resolution`: välj upplösningen för den genererade videon, där veo31-modellen stöder 4k-upplösning, medan andra modeller inte gör det. Alla modeller stöder 1080p och gif-upplösning, om detta värde inte anges används 720p som standard, som huvudsakligen delas in i: `1080p`, `gif`, `4k`.
- `prompt`: promptord.
- `callback_url`: URL för att få tillbaka resultatet.
- `async`: valfritt, om det sätts till `true` returnerar gränssnittet omedelbart `task_id`, utan att behöva ange `callback_url`, och sedan kan resultatet hämtas genom att fråga motsvarande uppgiftsgränssnitt.

### 📌 Modellbeskrivning Sammanfattning

| **Modellnamn**                   | **Stödda lägen**                          | **Bildinmatningsregler**                        |
| -------------------------- | --------------------------------- | --------------------------------- |
| **veo3-fast**              | Text till video (utan bild)<br />Bild till video-läge (med bild)           | **1 bild** → Första bildläge<br />**2 bilder** → Första och sista bildläge |
| **veo31-fast**             | Text till video (utan bild)<br />Bild till video-läge (med bild)           | **1 bild** → Första bildläge<br />**2 bilder** → Första och sista bildläge |
| **veo31-fast-ingredients** | ❌ Text till video (stöds inte)<br />✅ **Tvingad flera bildfusioner** (måste skicka bild) | **1-3 bilder** → Flera bildfusioner (max 3 bilder)        |
| **veo3**                   | Text till video (utan bild)<br />Bild till video-läge (med bild)           | **1 bild** → Första bildläge<br />**2 bilder** → Första och sista bildläge |
| **veo31**                  | Text till video (utan bild)<br />Bild till video-läge (med bild)           | **1 bild** → Första bildläge<br />**2 bilder** → Första och sista bildläge |

---

### 🔑 Viktiga regler

1. **Allmän logik**:
   - **Ingen bildinmatning** → Automatisk aktivering av text till video-läge.
   - **Med bildinmatning** → Aktiverar bild till video-läge (specifik åtgärd bestäms av antalet bilder).
2. **Typer av bild till video-läge**:
   - **Första bildläge** (1 bild): Första bilden är fastställd som inmatad bild.
   - **Första och sista bildläge** (2 bilder): Första och sista bilden är fastställda som inmatade bilder.
   - **Flera bildfusioner** (1-3 bilder): Endast `veo31-fast-ingredients` stöder detta, fusionerar flera bildinnehåll för att generera video.
3. **Klassificering av lägen**:

  - **Snabbt läge**: `veo3-fast`, `veo31-fast`, `veo31-fast-ingredients`.
   - **Kvalitetsläge**: `veo3`, `veo31` (genererar högre kvalitet).

---

### ⚠️ Viktiga punkter

- **Enda tvingande bildmodell**: `veo31-fast-ingredients` måste ha bilder (1-3 bilder), annars kan den inte köras.
- **Begränsning av antal bilder**:
  - `veo31-fast-ingredients` stöder **1-3 bilder** inmatning (flera bildfusioner).
  - Övriga modeller stöder högst **2 bilder** inmatning (första och sista bildläge).

```shell
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \

  "model": "veo31-fast",
  "prompt": "Vit keramik kaffekopp på glänsande marmorarbetsyta med morgonljus från fönstret. Kameran roterar långsamt 360 grader runt koppen och pausar kort vid handtaget."
}'
```

## Funktion för att generera video från bilder

Om du vill generera en video baserat på första och sista bildramar kan du ställa in parametern `action` till `image2video` och ange en array av bildlänkar för första och sista bildramar `image_urls`.

Därefter måste vi fylla i nästa steg med de utökade promptarna för att anpassa den genererade videon, så att vi kan specificera följande innehåll:

- `model`：modellen för den genererade videon, huvudsakligen `veo31-fast`、`veo3`、`veo31`、`veo3-fast` och `veo31-fast-ingredients`.
- `image_urls`：när du väljer videogenerering från bilder `image2video` måste du ladda upp referensbildlänkar.
- `prompt`：prompt.

Exempel på ifyllning:

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

När du har fyllt i det genereras automatiskt koden nedan:

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo31-fast",
    "prompt": "Låt den dansa",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynkron återkoppling

Eftersom Veo Videos Generation API:s genereringstid är relativt lång, cirka 1-2 minuter, om API:t inte svarar under en längre tid, kommer HTTP-förfrågan att hålla anslutningen öppen, vilket leder till extra systemresursförbrukning, så detta API erbjuder också stöd för asynkron återkoppling.

Den övergripande processen är: när klienten initierar en begäran, specificerar den ett extra `callback_url`-fält, efter att klienten har initierat API-förfrågan kommer API:t omedelbart att returnera ett resultat som innehåller ett `task_id`-fält, vilket representerar det aktuella uppdragets ID. När uppdraget är slutfört kommer resultatet av den genererade videon att skickas till klientens angivna `callback_url` i POST JSON-format, vilket också inkluderar `task_id`-fältet, så att uppdragsresultatet kan kopplas ihop med ID.

Nedan kommer vi att förstå hur man gör detta genom ett exempel.

Först är Webhook-återkoppling en tjänst som kan ta emot HTTP-förfrågningar, utvecklare bör ersätta med URL:en till sin egen byggda HTTP-server. ## Felhantering

Vid anrop av API:t, om ett fel uppstår, kommer API:t att returnera motsvarande felkod och information. Till exempel:

- `400 token_mismatched`: Bad request, möjligtvis på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Bad request, möjligtvis på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många förfrågningar, du har överskridit hastighetsgränsen.
- `500 api_error`: Intern serverfel, något gick fel på servern.

### Exempel på felrespons

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
