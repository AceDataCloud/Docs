Den här artikeln introducerar en anslutningsinstruktion för Veo Videos Generation API, som kan generera Veos officiella videor genom att ange anpassade parametrar.

## Ansökningsprocess

För att använda Veo Videos Generation API, gå först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API-token och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte är inloggad eller registrerad omdirigeras du automatiskt till inloggningssidan, där du uppmanas att registrera dig och logga in. När detta är klart återgår du automatiskt till den aktuella sidan.

**En API-token kan anropa alla plattformstjänster, och du behöver inte ansöka separat för varje tjänst.** Vid den första ansökan får du gratis kredit för att prova tjänsten kostnadsfritt; när krediten är otillräcklig kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Veo Videos Generation API →](https://platform.acedata.cloud/documents/veo-videos)

## Grundläggande användning

Lär först känna den grundläggande användningen: genom att ange prompten `prompt`, genereringsåtgärden `action`, referensbildarrayen för första och sista bildrutan `image_urls` samt modellen `model` kan du få det bearbetade resultatet. Först behöver du enkelt ange ett `action`-fält med värdet `text2video`. Det omfattar huvudsakligen tre åtgärder: text-till-video (`text2video`), bild-till-video (`image2video`) och hämta 1080p-video (`get1080p`). Därefter behöver vi även ange modellen `model`. För närvarande finns huvudsakligen modellerna `veo31-fast`, `veo3`, `veo31`, `veo3-fast` och `veo31-fast-ingredients`, och det specifika innehållet är följande:

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

Här kan vi se att vi har ställt in Request Headers, inklusive:

- `accept`: vilket format på svarsresultatet som ska tas emot, här anges `application/json`, det vill säga JSON-format.
- `authorization`: nyckeln för att anropa API:t, som kan väljas direkt i rullgardinsmenyn efter ansökan.

Dessutom har Request Body ställts in, inklusive:

- `model`: modellen för att generera video, huvudsakligen modellerna `veo31-fast`, `veo3`, `veo31`, `veo3-fast` och `veo31-fast-ingredients`.
- `action`: åtgärden för denna videogenreringsuppgift, som huvudsakligen omfattar tre åtgärder: text-till-video (`text2video`), bild-till-video (`image2video`) och hämta 1080p-video (`get1080p`).
- `image_urls`: länkar till referensbilder som måste laddas upp när åtgärden bild-till-video `image2video` väljs. `veo31-fast-ingredients` stöder högst 3 bilder (flerbildsfusion), medan övriga modeller stöder högst 2 bilder (läge för första och sista bildruta).
- `resolution`: välj videoupplösningen som ska genereras. Modellen veo31 stöder 4k-upplösning, medan andra modeller inte stöder det. Alla modeller stöder 1080p- och gif-upplösning. Om detta värde inte anges används 720p-upplösning som standard. Alternativen är huvudsakligen: `1080p`, `gif`, `4k`.
- `prompt`: prompt.
- `callback_url`: URL:en som ska ta emot återanropsresultatet.
- `async`: valfritt; när den sätts till `true` returnerar gränssnittet omedelbart `task_id`, utan att `callback_url` behöver anges. Resultatet hämtas sedan genom polling via motsvarande gränssnitt för uppgiftsfrågor.

### 📌 Sammanfattning av modellbeskrivning

| **Modellnamn**                   | **Lägen som stöds**                          | **Regler för bildinmatning**                        |
| -------------------------- | --------------------------------- | --------------------------------- |
| **veo3-fast**              | Text-till-video (utan bild)<br />Bild-till-video-läge (med bild)           | **1 bild** → läge för första bildruta<br />**2 bilder** → läge för första och sista bildruta |
| **veo31-fast**             | Text-till-video (utan bild)<br />Bild-till-video-läge (med bild)           | **1 bild** → läge för första bildruta<br />**2 bilder** → läge för första och sista bildruta |
| **veo31-fast-ingredients** | ❌ Text-till-video (stöds inte)<br />✅ **Obligatorisk flerbildsfusion** (bilder måste anges) | **1–3 bilder** → flerbildsfusionsläge (högst 3 bilder)        |
| **veo3**                   | Text-till-video (utan bild)<br />Bild-till-video-läge (med bild)           | **1 bild** → läge för första bildruta<br />**2 bilder** → läge för första och sista bildruta |
| **veo31**                  | Text-till-video (utan bild)<br />Bild-till-video-läge (med bild)           | **1 bild** → läge för första bildruta<br />**2 bilder** → läge för första och sista bildruta |

---

### 🔑 Förklaring av viktiga regler

1. **Allmän logik**:
   - **Ingen bildinmatning** → utlöser automatiskt text-till-video-läge.
   - **Bildinmatning finns** → utlöser bild-till-video-läge (det specifika beteendet avgörs av antalet bilder).
2. **Lägestyper för bild-till-video**:
   - **Läge för första bildruta** (1 bild): den första bildrutan fixeras till den inmatade bilden.
   - **Läge för första och sista bildruta** (2 bilder): den första och sista bildrutan fixeras till de inmatade bilderna.
   - **Flerbildsfusionsläge** (1–3 bilder): stöds endast av `veo31-fast-ingredients` och genererar video genom att sammanfoga innehållet från flera bilder.
3. **Lägesklassificering**:

  - **Fast-läge**: `veo3-fast`, `veo31-fast`, `veo31-fast-ingredients`.
   - **Quality-läge**: `veo3`, `veo31` (högre genereringskvalitet).

---

### ⚠️ Observera

- **Den enda modellen som kräver bildinmatning**: `veo31-fast-ingredients` måste ta emot bilder (1–3 bilder), annars kan den inte köras.
- **Begränsning av antal bilder**:
  - `veo31-fast-ingredients` stöder **1–3 bilder** som inmatning (flerbildsfusionsläge).
  - Övriga modeller stöder högst **2 bilder** som inmatning (läge för första och sista bildruta).

  "model": "veo31-fast",

## Bild-till-video-funktion

Om du vill generera en video baserat på bilder för första och sista bildrutan kan du ställa in parametern `action` till `image2video` och ange länkarrayen `image_urls` för bilderna i första och sista bildrutan.

Därefter måste vi fylla i de promptord som behöver utökas i nästa steg för att anpassa videogenereringen, och då kan följande innehåll anges:

- `model`: modellen för att generera video, huvudsakligen `veo31-fast`, `veo3`, `veo31`, `veo3-fast` och `veo31-fast-ingredients`.
- `image_urls`: när bild-till-video-åtgärden `image2video` väljs måste länkar till de referensbilder som ska laddas upp anges.
- `prompt`: promptord.

Ett ifyllningsexempel är följande:

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

Efter ifyllning genereras följande kod automatiskt:

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo31-fast",
    "prompt": "Let it dance",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynkron återuppringning

Eftersom genereringstiden för Veo Videos Generation API är relativt lång, cirka 1–2 minuter, kommer HTTP-begäran att fortsätta hålla anslutningen öppen om API:t inte svarar under en längre tid, vilket leder till ytterligare förbrukning av systemresurser. Därför erbjuder detta API även stöd för asynkrona återuppringningar.

Det övergripande flödet är: när klienten initierar en begäran anger den dessutom ett fält `callback_url`. Efter att klienten har initierat API-begäran returnerar API:t omedelbart ett resultat som innehåller fältinformationen `task_id`, vilket representerar det aktuella uppgifts-ID:t. När uppgiften är klar skickas resultatet av den genererade videon till den `callback_url` som klienten har angett i form av POST JSON, vilket också inkluderar fältet `task_id`, så att uppgiftsresultaten kan kopplas samman via ID:t.

Nedan ska vi genom exempel förstå hur man utför detta specifikt.

Först är Webhook-återuppringningen en tjänst som kan ta emot HTTP-begäranden, och utvecklaren bör ersätta den med URL:en till sin egen HTTP-server. ## Felhantering

Vid anrop av API:t, om ett fel uppstår, returnerar API:t motsvarande felkod och information. Till exempel:

- `400 token_mismatched`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`：Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`：För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`：Internt serverfel, något gick fel på servern.

### Exempel på felsvar

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
