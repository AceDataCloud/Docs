Anthropic Claude är ett mycket kraftfullt AI-konversationssystem som kan generera flytande och naturliga svar på bara några sekunder genom att mata in promptord. Claude utmärker sig i branschen med sin enastående förmåga att förstå och generera språk. I dag används Claude redan brett inom olika branscher och områden, och dess inflytande blir alltmer framträdande. Oavsett om det gäller vardagliga samtal, kreativt skrivande eller professionell rådgivning och kodprogrammering kan Claude erbjuda häpnadsväckande intelligent assistans, vilket avsevärt förbättrar människors arbetseffektivitet och kreativitet.

Detta dokument introducerar främst användningsflödet för Claude Chat Completion API-operationer. Med det kan vi enkelt använda den officiella Claudes konversationsfunktioner.

## Claude Fable 5.2

Använd det fullständiga modellnamnet `claude-fable-5-2`. Denna modell är lämplig för komplexa resonemang och långvariga uppgifter; när inbyggda tankeinnehållsblock och verktygsinteraktion krävs, prioritera Messages. Adaptivt tänkande är kontinuerligt aktiverat, utelämna `temperature`, `top_p`, `top_k`, använd `auto` för verktygsval och tvinga inte fram ett specifikt verktyg. `max_tokens` omfattar både tänkande och slutlig text. Responses- och Count Tokens-gränssnitten erbjuds för närvarande inte för denna modell.

Omräknat enligt det nuvarande största paketet (142,800 Credits／$13,584) kostar vanlig inmatning för Fable 5.2 $3.20 och utmatning $16／miljon token; cacheläsning kostar $0.08, och cacheskrivning för 5 minuter／1 timme kostar respektive $4／$6.40／miljon token. Ovanstående priser är 40 % av den officiella standard-API-enhetskostnaden (60 % billigare); för andra paket och ytterligare kontorabatter, se modellprissidan och fakturan.

## Ansökningsprocess

För att använda Claude Chat Completion API ska du först hämta din API Token i [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) och spara den som reserv.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig, omdirigeras du automatiskt till inloggningssidan där du uppmanas att registrera dig och logga in. När detta är klart återgår du automatiskt till den aktuella sidan.

**En API Token kan anropa alla plattformens tjänster, utan att behöva ansökas separat för varje tjänst.** Vid första ansökan får du gratis kredit för att kunna prova gratis; när krediten inte räcker till kan du fylla på ditt allmänna saldo i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Grundläggande användning

Därefter kan du fylla i motsvarande innehåll i gränssnittet, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

När du använder detta gränssnitt för första gången behöver vi minst fylla i tre delar. Den ena är `authorization`, som kan väljas direkt i rullgardinslistan. En annan parameter är `model`, där du kan välja offentliga modeller som `claude-opus-5-5`, `claude-fable-5-1` och andra; den tidigare `claude-fable-5` kan fortfarande anropas. Den sista parametern är `messages`, som är en frågeordsarray där varje element innehåller `role` och `content`; `role` stöder `user`, `assistant`, `system`, och `content` är det konkreta innehållet. När fullständiga Claude-tankeinnehållsblock, signaturer och inbyggd verktygssemantik behövs, använd fortfarande Messages API.

Samtidigt kan du notera att det finns motsvarande genererad anropskod på höger sida. Du kan kopiera koden och köra den direkt, eller klicka direkt på knappen ”Try” för att testa.

Vanliga valfria parametrar:

- `max_tokens`: Begränsar det maximala antalet token för ett enskilt svar.
- `temperature`: Slumpmässighet för generering, mellan 0 och 2; ju större värde, desto mer spritt.
- `n`: Hur många kandidatsvar som genereras åt gången.
- `response_format`: Inställning för returformat.

`claude-opus-5-5` stöder vanliga och strömmande Chat Completions; denna modell tillåter endast `n=1`. Ange inte `temperature` lägre än 1 eller ett icke-standardvärde för `top_p` för den; använd `tool_choice: "auto"` för verktygsanrop och tvinga inte fram ett specifikt verktyg. Det Chat-kompatibla gränssnittet returnerar inte inbyggda tankeinnehållsblock.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Returresultatet har flera fält, vilka presenteras nedan:

- `id`, ID:t som genereras för denna konversationsuppgift och används för att unikt identifiera denna konversationsuppgift.
- `model `, den valda Claude-modellen på den officiella webbplatsen.
- `choices`, svarsinformationen som Claude ger för frågeorden.
- `usage `: Statistik över token för denna fråge- och svarsomgång.

I Chat Completions-formatet är `usage.prompt_tokens` den totala inmatningsmängden; `prompt_tokens_details.cached_tokens` och `prompt_tokens_details.cache_write_tokens` registrerar respektive detaljer för cacheläsning och cacheskrivning. `completion_tokens_details.reasoning_tokens` är en delmängd av `completion_tokens`; lägg inte till dem igen när du beräknar total mängd eller kostnad. Icke-strömmande svar kan även returnera objektet `usage.cost`, där `amount` är den faktiska kreditförbrukningen, `currency` är mätenheten och `list_amount` är beloppet före rabatt (om tillämpligt).

Fältnamnet för Chat-compatible är `reasoning_tokens`; det inbyggda Messages API använder `output_tokens_details.thinking_tokens`. Wire-schemat för de två protokollen skiljer sig åt, och klienten bör inte blanda fältnamnen.

Bland dessa innehåller `choices` Claudes svarsinformation, och `choices` inuti det är den konkreta informationen i Claudes svar, vilket kan ses i bilden.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Det går att se att fältet `content` i `choices` innehåller det konkreta innehållet i Claudes svar.

## Strömmande svar

Detta gränssnitt stöder även strömmande svar, vilket är mycket användbart för webbintegration och gör det möjligt för webbsidor att visa text ord för ord.

Om du vill returnera svar strömmande kan du ändra parametern `stream ` i begärandehuvudet till `true`.

Ändringen visas i bilden, men anropskoden behöver motsvarande ändringar för att stödja strömmande svar.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>
Efter att ha ändrat `stream` till `true` kommer API:t att returnera motsvarande JSON-data rad för rad. På kodnivå behöver vi göra motsvarande ändringar för att få resultaten rad för rad.

Python-exempel på anropskod:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Djupgående tänkande

Den nya generationens Claude-modeller kan resonera enligt modellens standardstrategi utan att behöva aktiveras via modellsuffixet `-thinking`. Chat-compatible-svar använder det OpenAI-kompatibla usage-fältet `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` ingår redan i `completion_tokens`, lägg inte ihop dem dubbelt. Resonemang och synlig brödtext delar den övre gränsen för output-token, så när `max_tokens` är lågt kan brödtexten vara tom eller trunkerad; höj i så fall output-budgeten, eller välj en lägre resonemangsinsats när modellen som används har stöd för det.

Om du behöver inbyggd `thinking`, `output_config.effort`, thinking-innehållsblock och signaturretur, använd `/v1/messages`. Usage-fältet som motsvarar Messages är `output_tokens_details.thinking_tokens`; blanda inte ihop det med Chat-compatible:s `completion_tokens_details.reasoning_tokens`.

## Visuell modell

claude-sonnet-4-20250514 är en multimodal stor språkmodell utvecklad av Claude. Den har lagt till visuell förståelseförmåga på grunden av claude-4. Denna modell kan samtidigt bearbeta text- och bildinmatning och uppnår förståelse och generering över flera modaliteter.

Textbearbetningen med modellen claude-sonnet-4-20250514 är densamma som den grundläggande användningen ovan. Nedan introduceras kort hur modellens bildbearbetningsförmåga används.

Bildbearbetningsförmågan i modellen claude-sonnet-4-20250514 används huvudsakligen genom att lägga till ett `type`-fält på grundval av det ursprungliga `content`-innehållet. Genom detta fält kan det fastställas om det som laddas upp är text eller en bild, så att bildbearbetningsförmågan i modellen claude-sonnet-4-20250514 kan användas. Nedan beskrivs huvudsakligen hur denna funktion anropas med Curl och Python.

- Curl-skriptmetod

```

-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "claude-sonnet-4-20250514",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "What'\''s in this image?"
          },
          {
            "type": "image_url",
            "image_url": {
              "url": "https://cdn.acedata.cloud/ueugot.png"
            }
          }
        ]
      }
    ]
  }'
```

## Felhantering

Om ett fel uppstår vid anrop av API:et returnerar API:et motsvarande felkod och information. Till exempel:

- `400 token_mismatched`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.
