Anthropic Claude är ett mycket kraftfullt AI-konversationssystem som kan generera flytande och naturliga svar på bara några sekunder genom att mata in en prompt. Claude utmärker sig i branschen med sin enastående förmåga att förstå och generera språk. I dag används Claude redan brett inom olika branscher och områden, och dess inflytande blir alltmer betydande. Oavsett om det gäller vardagliga samtal, kreativt skrivande eller professionell rådgivning och kodprogrammering kan Claude erbjuda häpnadsväckande intelligent assistans, vilket avsevärt förbättrar människors arbetseffektivitet och kreativitet.

Detta dokument introducerar främst användningsflödet för Claude Chat Completion API. Med hjälp av det kan vi enkelt använda den officiella Claude-konversationsfunktionen.

## Ansökningsprocess

För att använda Claude Chat Completion API går du först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API Token och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig omdirigeras du automatiskt till inloggningssidan för att registrera och logga in dig. När det är klart återgår du automatiskt till den aktuella sidan.

**En API Token kan anropa alla plattformens tjänster, utan att du behöver ansöka separat för varje tjänst.** Vid första ansökan får du gratis kredit för att prova kostnadsfritt; när krediten inte räcker till kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Grundläggande användning

Därefter kan du fylla i motsvarande innehåll i gränssnittet, som visas på bilden:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

När vi använder detta gränssnitt för första gången behöver vi minst fylla i tre saker. Den ena är `authorization`, som kan väljas direkt i rullgardinslistan. En annan parameter är `model`, där du kan välja offentliga modeller som `claude-opus-5-5`, `claude-fable-5-1` med flera; den tidigare `claude-fable-5` kan fortfarande anropas. Den sista parametern är `messages`, som är en frågeordsarray där varje element innehåller `role` och `content`; `role` stöder `user`, `assistant`, `system`, och `content` är det konkreta innehållet. När fullständiga Claude-tankeinnehållsblock, signaturer och inbyggd verktygssemantik behövs, använd fortfarande Messages API.

Samtidigt kan du se att det finns motsvarande genererad anropskod på höger sida. Du kan kopiera koden och köra den direkt, eller klicka direkt på knappen ”Try” för att testa.

Vanliga valfria parametrar:

- `max_tokens`: Begränsar det maximala antalet token för ett enskilt svar.
- `temperature`: Slumpmässighet i genereringen, mellan 0 och 2; ju högre värde, desto mer varierat.
- `n`: Hur många kandidatsvar som genereras åt gången.
- `response_format`: Inställningar för returformatet.

`claude-opus-5-5` stöder vanliga och strömmande Chat Completions; denna modell tillåter endast `n=1`. Ange inte en `temperature` lägre än 1 eller ett icke-standardiserat `top_p` för den, och använd `tool_choice: "auto"` för verktygsanrop utan att tvinga fram ett specifikt verktyg. Det Chat-kompatibla gränssnittet returnerar inte inbyggda tankeinnehållsblock.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Efter anropet ser vi att returresultatet är följande:


Returresultatet har flera fält, vilka beskrivs nedan:

- `id`, ID:t som genereras för denna konversationsuppgift och används för att unikt identifiera denna konversationsuppgift.
- `model `, den valda Claude-modellen från den officiella webbplatsen.
- `choices`, svarsinformation som Claude ger för prompten.
- `usage `: Statistik över token för denna fråga och svar.

I Chat Completions-formatet är `usage.prompt_tokens` den totala inmatningsmängden; `prompt_tokens_details.cached_tokens` och `prompt_tokens_details.cache_write_tokens` registrerar respektive detaljer för läsning från och skrivning till cache. `completion_tokens_details.reasoning_tokens` är en delmängd av `completion_tokens`; lägg inte till dem igen vid beräkning av totalmängd eller kostnad. Icke-strömmande svar kan även returnera objektet `usage.cost`, där `amount` är den faktiska kreditförbrukningen, `currency` är måttenheten och `list_amount` är beloppet före rabatt (om tillämpligt).

Det Chat-kompatibla fältnamnet är `reasoning_tokens`; det inbyggda Messages API använder `output_tokens_details.thinking_tokens`. De två protokollen har olika wire schema, och klienter bör inte blanda fältnamnen.

Bland dessa innehåller `choices` Claudes svarsinformation, och `choices` inuti det är den konkreta informationen i Claudes svar, vilket kan ses på bilden.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Du kan se att fältet `content` i `choices` innehåller det konkreta innehållet i Claudes svar.

## Strömmande svar

Detta gränssnitt stöder även strömmande svar, vilket är mycket användbart för webbintegration och gör att webbsidan kan uppnå en effekt där text visas tecken för tecken.

Om du vill returnera svaret strömmande kan du ändra parametern `stream ` i begärans huvud.

Ändra den till `true`.

Ändringen visas på bilden, men anropskoden behöver ändras på motsvarande sätt för att stödja strömmande svar.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

Efter att `stream` har ändrats till `true` returnerar API:t motsvarande JSON-data rad för rad. På kodnivå behöver vi göra motsvarande ändringar för att få resultatet rad för rad.

Exempel på Python-anropskod:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Djupgående resonemang
Den nya generationen av Claude-modeller kan resonera enligt modellens standardstrategi utan att behöva aktiveras via modellsuffixet `-thinking`. Chat-compatible-svar använder det OpenAI-kompatibla usage-fältet `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` ingår redan i `completion_tokens`, lägg inte ihop dem dubbelt. Resonemang och synlig brödtext delar den maximala gränsen för output-token, så när `max_tokens` är litet kan brödtexten vara tom eller avkortad; om detta inträffar, öka outputbudgeten eller välj en lägre resonemangsinsats när modellen som används stöder det.

Om du behöver inbyggd `thinking`, `output_config.effort`, thinking-innehållsblock och återlämning av signaturer, använd `/v1/messages`. Motsvarande usage-fält för Messages är `output_tokens_details.thinking_tokens`; blanda inte ihop det med Chat-compatible-fältet `completion_tokens_details.reasoning_tokens`.

## Visuell modell

claude-sonnet-4-20250514 är en multimodal stor språkmodell utvecklad av Claude, den har lagt till visuell förståelse baserat på claude-4. Den här modellen kan samtidigt behandla text- och bildindata och uppnå förståelse och generering över flera modaliteter.

Textbearbetning med modellen claude-sonnet-4-20250514 överensstämmer med det grundläggande användningsinnehållet ovan, nedan följer en kort introduktion till hur man använder modellens bildbehandlingsförmåga.

Bildbehandlingsförmågan i modellen claude-sonnet-4-20250514 används huvudsakligen genom att lägga till ett `type`-fält på basis av det ursprungliga `content`-innehållet. Genom detta fält kan man veta om det som laddas upp är text eller en bild och därmed använda bildbehandlingsförmågan i modellen claude-sonnet-4-20250514. Nedan beskrivs huvudsakligen två sätt att anropa denna funktion med Curl och Python.

- Curl-skriptmetod

```
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "claude-sonnet-4-20250514",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "What'\''s in this image?"
          },
          {
            "type": "image_url",
            "image_url": {
              "url": "https://cdn.acedata.cloud/ueugot.png"
            }
          }
        ]
      }
    ]
  }'
```

- Python-skriptmetod

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-sonnet-4-20250514",
    "messages": [
        {
            "role": "user",
            "content": [
                {
                    "type": "text", "text": "What's in this image?"
                },
                {
                    "type": "image_url",
                    "image_url": {
                        "url": "https://cdn.acedata.cloud/ueugot.png"
                    }
                },
            ],
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Felhantering

När API:t anropas, om ett fel uppstår, returnerar API:t motsvarande felkod och information. Till exempel:

- `400 token_mismatched`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.
