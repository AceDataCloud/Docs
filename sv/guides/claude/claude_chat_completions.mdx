Anthropic Claude är ett mycket kraftfullt AI-konversationssystem som kan generera flytande och naturliga svar på bara några sekunder genom att mata in promptord. Claude utmärker sig i branschen med sin enastående språkförståelse och genereringsförmåga. I dag används Claude redan brett inom olika branscher och områden, och dess inflytande blir allt mer betydande. Oavsett om det gäller vardagliga samtal, kreativt skrivande eller professionell rådgivning och kodprogrammering kan Claude erbjuda häpnadsväckande intelligent hjälp, vilket avsevärt förbättrar människors arbetseffektivitet och kreativitet.

Detta dokument introducerar främst användningsflödet för Claude Chat Completion API-operationer. Med hjälp av det kan vi enkelt använda den officiella Claude:s konversationsfunktion.

## Ansökningsprocess

För att använda Claude Chat Completion API, gå först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API Token och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig kommer du automatiskt att omdirigeras till inloggningssidan för att registrera och logga in dig. När det är klart återvänder du automatiskt till den aktuella sidan.

**En API Token kan anropa alla plattformstjänster, utan att behöva ansöka separat för varje tjänst.** Vid första ansökan får du gratis kredit och kan prova kostnadsfritt; när krediten inte räcker till kan du ladda på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Grundläggande användning

Därefter kan du fylla i motsvarande innehåll i gränssnittet, som visas i figuren:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Vid första användningen av detta gränssnitt behöver vi åtminstone fylla i tre saker. Den ena är `authorization`, som du direkt kan välja i rullgardinslistan. Den andra parametern är `model`, och det rekommenderas att använda den senaste flaggskeppsmodellen `claude-fable-5-1`; den tidigare `claude-fable-5` kan fortfarande anropas. Den sista parametern är `messages`, som är en frågeordsarray där varje element innehåller `role` och `content`; `role` stöder `user`, `assistant`, `system`, och `content` är det konkreta innehållet. Claude Fable 5.1 stöder 1 miljon Token kontext och högst 128K Token utdata.

Samtidigt kan du observera att det finns motsvarande genererad anropskod till höger. Du kan kopiera koden och köra den direkt, eller direkt klicka på knappen ”Try” för att testa.

Vanliga valfria parametrar:

- `max_tokens`: Begränsar det maximala antalet token i ett enskilt svar.
- `temperature`: Slumpmässighet vid generering, mellan 0 och 2, ju större värde desto mer spridd.
- `n`: Hur många kandidatsvar som genereras åt gången.
- `response_format`: Inställningar för returformat.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Returresultatet har flera fält, som introduceras nedan:

- `id`, ID:t för den genererade konversationsuppgiften, används för att unikt identifiera denna konversationsuppgift.
- `model `, den valda modellen från Claudes officiella webbplats.
- `choices`, svarsinformation som Claude ger för promptorden.
- `usage `: Statistik över token för denna frågestund.

I Chat Completions-formatet är `usage.prompt_tokens` den totala inmatningsmängden; `prompt_tokens_details.cached_tokens` och `prompt_tokens_details.cache_write_tokens` registrerar respektive detaljer för läsning och skrivning av cache. `completion_tokens_details.reasoning_tokens` är en delmängd av `completion_tokens`, och ska inte adderas igen vid beräkning av total mängd eller kostnad. Icke-strömmande svar kan också returnera objektet `usage.cost`, där `amount` är den faktiska kreditförbrukningen, `currency` är mätenheten och `list_amount` är beloppet före rabatt (om tillämpligt).

Det Chat-kompatibla fältnamnet är `reasoning_tokens`; det ursprungliga Messages API använder `output_tokens_details.thinking_tokens`. De två protokollen har olika wire schema, och klienten bör inte blanda fältnamnen.

Bland dessa innehåller `choices` Claudes svarsinformation, och `choices` i den är den konkreta informationen i Claudes svar, vilket kan ses som i figuren.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Det går att se att fältet `content` i `choices` innehåller det konkreta innehållet i Claudes svar.

## Strömmande svar

Detta gränssnitt stöder också strömmande svar, vilket är mycket användbart för webbanslutning och gör att webbsidan kan uppnå en effekt där text visas tecken för tecken.

Om du vill returnera svaret strömmande kan du ändra parametern `stream ` i begärandehuvudet till `true`.

Ändringen visas i figuren, men anropskoden behöver ändras på motsvarande sätt för att stödja strömmande svar.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

Efter att `stream` har ändrats till `true` returnerar API:et motsvarande JSON-data rad för rad, och på kodnivå behöver vi göra motsvarande ändringar för att få resultatet rad för rad.

Exempel på Python-anropskod:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Djupgående tänkande
Den nya generationen av Claude-modeller kan möjligen resonera enligt modellens standardstrategi, utan att behöva aktiveras genom modelländelsen `-thinking`. Chat-compatible-svar använder det OpenAI-kompatibla usage-fältet `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` ingår redan i `completion_tokens`, lägg inte ihop dem två gånger. Resonemang och synlig brödtext delar gränsen för output-token, därför kan brödtexten vara tom eller avkortad när `max_tokens` är lågt; om detta inträffar, öka output-budgeten eller välj en lägre resonemangsinsats när modellen som används stöder det.

Om du behöver inbyggt `thinking`, `output_config.effort`, thinking-innehållsblock och återföring av signaturer, använd `/v1/messages`. Usage-fältet som motsvarar Messages är `output_tokens_details.thinking_tokens`, blanda inte ihop det med Chat-compatible:s `completion_tokens_details.reasoning_tokens`.

## Visuell modell

claude-sonnet-4-20250514 är en multimodal stor språkmodell utvecklad av Claude, den har lagt till visuell förståelseförmåga på basis av claude-4. Denna modell kan samtidigt behandla text- och bildindata och har uppnått förståelse och generering över olika modaliteter.

Textbehandling med modellen claude-sonnet-4-20250514 är förenlig med det grundläggande användningsinnehållet ovan, nedan följer en kort introduktion till hur man använder modellens bildbehandlingsförmåga.

Bildbehandlingsförmågan hos modellen claude-sonnet-4-20250514 används huvudsakligen genom att lägga till ett `type`-fält på basis av det ursprungliga `content`-innehållet. Genom detta fält kan man veta om det som laddas upp är text eller bild och därmed använda bildbehandlingsförmågan hos modellen claude-sonnet-4-20250514. Nedan beskrivs huvudsakligen hur denna funktion anropas med två metoder: Curl och Python.

- Curl-skriptmetod

```
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "claude-sonnet-4-20250514",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "What'\''s in this image?"
          },
          {
            "type": "image_url",
            "image_url": {
              "url": "https://cdn.acedata.cloud/ueugot.png"
            }
          }
        ]
      }
    ]
  }'
```

- Python-skriptmetod

```python

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-sonnet-4-20250514",
    "messages": [
        {
            "role": "user",
            "content": [
                {
                    "type": "text", "text": "What's in this image?"

                {
                    "type": "image_url",
                    "image_url": {

                    }
                },

response = requests.post(url, json=payload, headers=headers)

```

## Felhantering

Vid anrop av API:t kommer API:t, om ett fel uppstår, att returnera motsvarande felkod och information. Till exempel:

- `400 token_mismatched`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.
