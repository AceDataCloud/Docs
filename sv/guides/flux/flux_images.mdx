Den här artikeln introducerar en typ av instruktioner för integrering av Flux Images Generation API, som kan generera officiella Flux-bilder genom att ange anpassade parametrar.

## Ansökningsprocess

För att använda Flux Images Generation API ska du först hämta din API Token från [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig omdirigeras du automatiskt till inloggningssidan där du uppmanas att registrera dig och logga in. När det är klart återgår du automatiskt till den aktuella sidan.

**En API Token kan anropa alla plattformens tjänster, utan att behöva ansöka separat för varje tjänst.** Vid den första ansökan får du gratis kredit för att kunna prova kostnadsfritt; när krediten inte räcker till kan du fylla på det allmänna saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Grundläggande användning

Låt oss först förstå det grundläggande användningssättet: genom att ange prompten `prompt`, genereringsåtgärden `action` och bildstorleken `size` kan du få det bearbetade resultatet. Först behöver du enkelt ange ett `action`-fält med värdet `generate`, och sedan behöver vi även ange en prompt. Det specifika innehållet är följande:

<p><img src="https://cdn.acedata.cloud/wz85jt.png" width="500" className="m-auto" /></p>

Här kan vi se att vi har angett Request Headers, inklusive:

- `accept`: vilket format på svarsresultatet du vill ta emot, här anges `application/json`, det vill säga JSON-format.
- `authorization`: nyckeln för att anropa API:et, som kan väljas direkt i rullgardinsmenyn efter ansökan.

Dessutom har Request Body angetts, inklusive:

- `action`: åtgärden för denna bildgenereringsuppgift.
- `size`: storleken på bildgenereringsresultatet. **Serierna `flux-2-flex` / `flux-2-pro` / `flux-2-max` måste ange ett bildförhållande (till exempel `1:1`, `16:9`) och accepterar inte pixeldimensioner som `1024x1024`; om det utelämnas returneras 400.**
- `count`: antalet bilder som ska genereras, standardvärdet är 1. Den här parametern gäller endast för bildgenereringsuppgifter och är ogiltig för redigeringsuppgifter.
- `prompt`: prompt.
- `model`: genereringsmodell, standard är `flux-dev`; de senaste flaggskeppen är `flux-2-pro` och `flux-2-max` (högre bildkvalitet, måste användas tillsammans med bildförhållandet `size`).
- `callback_url`: URL:en som behöver få återkopplingsresultatet.
- `async`: valfritt; när den anges som `true` returnerar gränssnittet omedelbart `task_id`, utan att du behöver ange `callback_url`, och därefter hämtas resultatet genom polling via motsvarande gränssnitt för uppgiftsfrågor.

Parametern `size` har vissa särskilda begränsningar och delas huvudsakligen in i två typer: bredd- och höjdförhållandet `width x height` samt bildförhållandet `x:y`. Detaljerna är följande:

| Modell               | Omfattning                                         |
| ---------------- | ------------------------------------------ |
| flux-dev         | Stöder bredd- och höjdförhållandena 1024x1024, 1024x1792, 1792x1024 eller bildförhållande |
| flux-pro         | Stöder bredd- och höjdförhållandena 1024x1024, 1024x1792, 1792x1024 eller bildförhållande |
| flux-2-flex      | Stöder endast bildförhållande                                    |
| flux-2-pro       | Stöder endast bildförhållande                                    |
| flux-2-max       | Stöder endast bildförhållande                                    |
| flux-kontext-pro | Stöder endast bildförhållande                                    |
| flux-kontext-max | Stöder endast bildförhållande                                    |

Referensbildförhållanden: "21:9", "16:9", "4:3", "3:2", "1:1", "2:3", "3:4", "9:16", "9:21".

Efter att ha valt parametrar genereras motsvarande kod automatiskt till höger. Kontrollera före kopiering att auktoriseringshuvudet använder din egen API Key, och att verkliga autentiseringsuppgifter inte förekommer i dokumentation och skärmbilder.

Klicka på knappen ”Try” för att testa. Här får vi följande resultat:

```json
{
  "success": true,
  "task_id": "5456c749-3bbb-4f10-9eb8-cfbcac297500",
  "trace_id": "ae4eecb8-1dd6-45b4-bfb3-a1c48872536e",
  "data": [
    {
      "image_url": "https://cdn.acedata.cloud/assets/examples/flux/5456c749-3bbb-4f10-9eb8-cfbcac297500-d0ef60485f73.jpg"
    }
  ]
}
```

Det returnerade resultatet har flera fält, som beskrivs nedan:

- `success`, statusen för videogenereringsuppgiften vid detta tillfälle.
- `task_id`, ID:t för videogenereringsuppgiften vid detta tillfälle.
- `trace_id`, spårnings-ID:t för videogenereringen vid detta tillfälle.
- `data`, resultatlistan för bildgenereringsuppgiften vid detta tillfälle.
  - `image_url`, länken för bildgenereringsuppgiften vid detta tillfälle.
  - `prompt`, prompt.

Vi kan se att vi har fått tillfredsställande bildinformation. Vi behöver bara hämta den genererade Flux-bilden utifrån bildlänkadressen i resultatets `data`.

Om du dessutom vill generera motsvarande integrationskod kan du kopiera den direkt. Exempelvis är CURL-koden följande:

```shell
curl -X POST 'https://api.acedata.cloud/flux/images' \
-H 'authorization: Bearer {token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "A photorealistic studio product shot of a frosted-glass perfume bottle on wet black slate, single softbox key light, water droplets, dark moody background, 85mm macro.",
  "model": "flux-2-pro",
  "size": "1:1"
}'
```

## Uppgift för bildredigering

Om du vill redigera en bild måste parametern `image_url` först innehålla länken till bilden som ska redigeras. Vid detta tillfälle stöder `action` endast `edit`, och du kan ange följande innehåll:

- model: modellen som används för denna bildredigeringsuppgift, stöder `flux-dev`, `flux-pro`, `flux-kontext-pro`, `flux-kontext-max`, `flux-2-flex`, `flux-2-pro`, `flux-2-max`.
- image_url: ladda upp bilden som behöver redigeras.

Ett ifyllnadsexempel är följande:

<p><img src="https://cdn.acedata.cloud/jn9da5.png" width="500" className="m-auto" /></p>

När ifyllningen är klar genereras följande kod automatiskt:

<p><img src="https://cdn.acedata.cloud/6cwxb8.png" width="500" className="m-auto" /></p>

Motsvarande kod:

```python
import requests

url = "https://api.acedata.cloud/flux/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "edit",
    "prompt": "a white siamese cat",
    "model": "flux-kontext-pro",
    "image_url": "https://cdn.acedata.cloud/ytj2qy.png"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Klicka på kör för att se att ett resultat erhålls omedelbart, enligt följande:

```json
{
  "success": true,
  "task_id": "2a7979ff-1f77-4380-92c6-a2dc37c3b4c8",
  "trace_id": "732b65c0-48d9-49f7-b568-64e5acffe4c0",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "timings": 1752744073
    }
  ]
}
```
Det kan ses att den genererade effekten är en effekt där originalbilden redigeras, och resultatet liknar det ovan.

## Asynkron återuppringning

Eftersom Flux Images Generation API har en relativt lång genereringstid, cirka 1–2 minuter, kommer HTTP-begäran att fortsätta hålla anslutningen öppen om API:et inte svarar under en längre tid, vilket leder till ytterligare förbrukning av systemresurser. Därför erbjuder detta API även stöd för asynkrona återuppringningar.

Det övergripande flödet är: när klienten initierar en begäran anges dessutom fältet `callback_url`. Efter att klienten har initierat API-begäran returnerar API:et omedelbart ett resultat som innehåller fältet `task_id`, vilket representerar ID:t för den aktuella uppgiften. När uppgiften är slutförd skickas resultatet av den genererade bilden till den `callback_url` som klienten har angett i form av POST JSON, där även fältet `task_id` ingår, så att uppgiftsresultatet kan kopplas samman via ID:t.

Nedan går vi igenom ett exempel för att förstå hur man gör.

Först är Webhook-återuppringningen en tjänst som kan ta emot HTTP-begäranden. Utvecklare bör ersätta den med URL:en till sin egen konfigurerade HTTP-server. För att underlätta demonstrationen används här en offentlig exempelwebbplats för Webhook, https://webhook.site/. Öppna webbplatsen för att få en Webhook-URL, som visas i bilden:

![](https://cdn.acedata.cloud/cjjfly.png)

Kopiera denna URL så kan den användas som Webhook. Exemplet här är `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`.

Därefter kan vi ange fältet `callback_url` som ovanstående Webhook-URL och samtidigt fylla i motsvarande parametrar. Det specifika innehållet visas i bilden:

<p><img src="https://cdn.acedata.cloud/wm6caw.png" width="500" className="m-auto" /></p>

Klicka på kör, så kan du se att ett resultat erhålls omedelbart, enligt följande:

```
{
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c"
}
```

Vänta en stund, så kan vi observera resultatet av den genererade bilden på `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`, som visas i bilden:

![](https://cdn.acedata.cloud/v23lot.png)

Innehållet är följande:

  "data": [
    {
      "prompt": "a white siamese cat",

Det kan ses att det finns ett fält `task_id` i resultatet. Övriga fält liknar de ovan, och uppgifterna kan kopplas samman genom detta fält.

## Felhantering

Om ett fel uppstår vid anrop av API:et returnerar API:et motsvarande felkod och information. Till exempel:

- `400 token_mismatched`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`：Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`：För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`：Internt serverfel, något gick fel på servern.

### Exempel på felsvar

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
