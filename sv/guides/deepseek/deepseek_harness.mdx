[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) är en programmeringsagent som körs lokalt. Den läser arbetsytan, anropar verktyg och utför kommandon, och anropar modellen via OpenAI-kompatibla Chat Completions-gränssnittet.

> Denna artikel gäller `deepseek-harness-sdk==0.1.0rc6` och `deepseek-harness-runtime-bin==0.1.0rc6`. Efter att ha uppgraderat klienten, vänligen slutför nedanstående test av skrivskyddade filer.

## Stödområde

| Projekt        | Konfiguration                             |
| -------------- | ---------------------------------------- |
| API Bas URL    | `https://api.acedata.cloud/v1`         |
| Modell         | `deepseek-v4-pro`                       |
| Protokoll      | OpenAI-kompatibla Chat Completions (strömmande) |
| Förmåga        | Text, resonemang, funktionsanrop, lokal Bash-verktygscykel, användningsstatistik |

Modellkatalogen kan förändras. Kontrollera den aktuella katalogen med en exklusiv nyckel för Integreringsplanen innan du kör:

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY"
```

Bekräfta att svaret innehåller `deepseek-v4-pro`. Använd inte `deepseek-v4-flash` som en likvärdig ersättning för verktygsmoden i denna artikel; i den här fasta versionsvalideringen har dess fleromgångars resonemangshistorik och verktygsåterspelning inte godkänts.

## 1. Förbered exklusiv nyckel

Öppna [Integreringsplanens applikation](https://platform.acedata.cloud/console/applications), gå till den köpta Coding Application, och skapa eller kopiera den exklusiva API-nyckeln för den applikationen. Integreringsplanen använder inte allmänna saldon, och nycklar från andra applikationer kan inte representera paketbehörigheter.

Sätt bara nyckeln i den aktuella shellen:

```bash
export ACEDATACLOUD_API_KEY="PASTE_YOUR_CODING_KEY_HERE"
export DEEPSEEK_BASE_URL="https://api.acedata.cloud/v1"
export DEEPSEEK_API_KEY="$ACEDATACLOUD_API_KEY"
```

Skriv inte den verkliga nyckeln i skript, konfigurationsförråd, terminalskärmdumpar eller sessioninspelningar.

## 2. Skapa isolerad arbetsyta

Harness bundlade runtime innehåller lokala Bash-verktyg. Vid första valideringen, peka inte på verkliga projekt eller huvudkatalogen; skapa en engångskatalog utan hemligheter:

```bash
mkdir -p /tmp/deepseek-harness-demo/workspace
mkdir -p /tmp/deepseek-harness-demo/sessions
printf 'compatibility fixture\n' > /tmp/deepseek-harness-demo/workspace/fixture.txt
python3 -m venv /tmp/deepseek-harness-demo/venv
/tmp/deepseek-harness-demo/venv/bin/pip install \
  "deepseek-harness-sdk==0.1.0rc6"
```

Om företagsnätverket använder en privat PyPI-mirror, kontrollera först att samma version av `deepseek-harness-runtime-bin` också finns i mirrorn. Använd inte `danger-full-access` för att utöka filåtkomstområdet; exemplen i denna artikel ger endast engångskatalogen till `cwd`.

## 3. Kör officiella Python SDK

Spara följande innehåll som `/tmp/deepseek-harness-demo/run.py`:

```python
import os

from deepseek_harness import DeepSeekHarness

with DeepSeekHarness(
    provider="deepseek-official",
    model="deepseek-v4-pro",
    max_tokens=160,
    cwd="/tmp/deepseek-harness-demo/workspace",
    session_root="/tmp/deepseek-harness-demo/sessions",
    base_url=os.environ["DEEPSEEK_BASE_URL"],
    api_key=os.environ["DEEPSEEK_API_KEY"],
    request_timeout_seconds=180,
) as harness:
    result = harness.run(
        "Read fixture.txt once, then reply with exactly: sdk-harness-ok",
        session_id="acedatacloud-compat",
    )

print(result.final_response)
print(result.finish_reason)
```

Kör:

```bash
/tmp/deepseek-harness-demo/venv/bin/python \
  /tmp/deepseek-harness-demo/run.py
```

Förväntat resultat:

```text
sdk-harness-ok
completed
```

Detta steg validerar samtidigt Bearer-autentisering, `/v1/chat/completions`, SSE, resonemangsinnehåll, verktygsanrop och verktygsresultatåterföring. När det är klart kan du ta bort `/tmp/deepseek-harness-demo`; om sessionkatalogen innehåller projektkontext bör den också förvaras med samma känslighetsnivå som kodförrådet.

## Vanliga frågor

- **401**: Kontrollera om `ACEDATACLOUD_API_KEY` är exporterad till samma shell som kör Python.
- **403 eller kvotmeddelande**: Bekräfta att nyckeln tillhör den aktuella Coding Application, att paketet fortfarande är giltigt och har kvarvarande kvot.
- **Modell otillgänglig**: Fråga om `/v1/models` igen, gissa inte modellnamnet baserat på gamla skärmdumpar.
- **`reasoning_content` / verktygsåterspelningsfel**: Bekräfta att SDK/runtime är den fasta versionen i denna artikel och använd `deepseek-v4-pro`.
- **Onormal verktygsanvändning**: Stoppa körningen av uppgifter som kan ha biverkningar, och validera först den aktuella tjänsteversionen med den skrivskyddade fixture.
- **Installationsfel**: Bekräfta att Python 3.10+, operativsystemets arkitektur stöds av den aktuella hjulet, och kontrollera att SDK/runtime-versionerna är konsekventa.

## Förmågegränser

Denna artikel validerar endast den lokala Python SDK till Chat Completions text och verktygscykel. Bilder, Files API, `/v1/responses`, `/v1/messages`, fjärrarbetsytor och hanterade sandboxar ingår inte i detta tutorials åtagande; arbetsytans behörigheter och lokala kommandorisker ansvaras av maskinen och konfigurationen som kör Harness.
