Google Gemini är ett mycket kraftfullt AI-konversationssystem som kan generera flytande och naturliga svar på bara några sekunder genom att mata in promptord. Gemini kan erbjuda imponerande intelligent assistans och avsevärt förbättra människors arbetseffektivitet och kreativitet.

Detta dokument introducerar främst användningsflödet för Gemini Chat Completion API-operationer. Med hjälp av det kan vi enkelt använda den officiella Gemini-konversationsfunktionen.

## Ansökningsprocess

För att använda Gemini Chat Completion API, gå först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API Token och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig, omdirigeras du automatiskt till inloggningssidan där du uppmanas att registrera dig och logga in. När detta är klart återgår du automatiskt till den aktuella sidan.

**En API Token kan anropa alla plattformstjänster, utan att du behöver ansöka separat för varje tjänst.** Vid första ansökan får du gratis kredit för att kunna prova utan kostnad; när krediten inte räcker till kan du ladda på gemensamt saldo i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## Grundläggande användning

Därefter kan du fylla i motsvarande innehåll i gränssnittet, som visas på bilden:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

När vi använder detta gränssnitt för första gången behöver vi minst fylla i tre saker. Den ena är `authorization`, som du kan välja direkt i rullgardinslistan. En annan parameter är `model`, där `model` är den kategori av modeller från Geminis officiella webbplats som vi väljer att använda. De valbara modellerna följer `model`-uppräkningen i gränssnittsdokumentationen. Den sista parametern är `messages`, där `messages` är den array med frågeord som vi matar in. Det är en array, vilket innebär att flera frågeord kan laddas upp samtidigt. Varje frågeord innehåller `role` och `content`, där `role` anger frågeställarens roll. Vi erbjuder tre identiteter: `user`, `assistant`, `system`. Den andra, `content`, är det specifika innehållet i vår fråga.

Samtidigt kan du se att motsvarande anropskod genereras till höger. Du kan kopiera koden och köra den direkt, eller klicka direkt på knappen ”Try” för att testa.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

> **Tips**: `gemini-3.x`-seriens flash är resonemangsmodeller och förbrukar först reasoning tokens; ställ in `max_tokens` till över 512, annars kan endast tomt innehåll returneras. `gemini-3.8-flash` är den för närvarande rekommenderade Flash-modellen och stöder upp till 1 miljon Token-kontext, bildindata, verktygsanrop och strömmande svar; den anropas för närvarande via Chat Completions-gränssnittet.

`gemini-4-argon` kan också användas för Chat Completions och stöder vanliga och strömmande textsvar. Den kan använda en del av utmatningsbudgeten för resonemang, så lämna tillräckligt med utrymme för `max_tokens` vid komplexa uppgifter; Google rekommenderar minst 32768 för vanliga uppgifter med denna modell. Likställ inte detta gränssnitt med funktionen för långa utdata i bakgrunden i Google Interactions API.

## Bildförståelse (multimodal indata)

Gemini är en ursprungligt multimodal modell som direkt kan ”se bilder”. För att skicka in en bild ändrar du `content` i ett meddelande från en sträng till en **array med innehållsblock**, och lägger både ett `text`-block och ett `image_url`-block i arrayen – detta är helt konsekvent med OpenAI och Geminis officiella OpenAI-kompatibla format.

`image_url.url` stöder två skrivsätt:
- **base64-`data:`-URI (rekommenderas, mest stabilt)**: Formatet är `data:<medietyp>;base64,<data>`, till exempel `data:image/jpeg;base64,/9j/4AAQ...`. **Medietypen (MIME) är redan angiven i `data:`-prefixet**, så det behövs inte och finns inget separat `media_type`-fält.
- **Offentligt tillgänglig bild-URL**: Till exempel `https://cdn.acedata.cloud/4hfydw.jpg`.

Bildtyper som stöds: `png`, `jpeg`, `webp`, `heic`, `heif`.

Exempel på anropskod i Python (base64-data-URI):

```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# 把本地图片读成 base64 data URI
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Du kan också direkt skicka en offentligt tillgänglig bild-URL:

```python
payload = {

    "messages": [
```

> 💡 `image_url` accepterar endast fältet `url` (värdet kan vara en bild-URL eller base64-`data:`-URI), samt det valfria fältet `detail`. **Skicka inte `media_type`** — det är Anthropic Claudes bildfält och tillhör inte formatet `image_url` för OpenAI / Gemini.

## Strömmande svar

Detta gränssnitt stöder även strömmande svar, vilket är mycket användbart för webbintegration och gör det möjligt för webbsidor att visa text ord för ord.

Om du vill returnera svaret strömmande kan du ändra parametern `stream ` i begärans huvud.

Ändra den till `true`.

Ändringen visas i bilden, men anropskoden behöver motsvarande ändringar för att stödja strömmande svar.

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

Efter att `stream` har ändrats till `true` returnerar API:t motsvarande JSON-data rad för rad, och på kodnivå behöver vi göra motsvarande ändringar för att få resultaten rad för rad.

Exempel på anropskod i Python:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

JavaScript stöds också, till exempel är koden för strömmande anrop i Node.js följande:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

## Gemini-3.1 multimodal modell

`gemini-3.1-pro-preview` är det officiella modell-ID:t för nuvarande Gemini 3.1 Pro och stöder multimodala indata såsom text, bilder och video, vilket passar för komplexa resonemang, kodning och förståelseuppgifter.

Begäransexempel:

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "图片的内容是什么？"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/qzx2z1.png"
          }
        }
      ]
    }
  ],
  "stream": false
}
```

Gemini 3.1 Pro stöder även videoförståelse:

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "视频的内容是什么？"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/58yioe.mp4"
          }
        }
      ]
    }
  ],
  "stream": false
}
```

Returformatet är detsamma som för Gemini 3.0 Pro; se beskrivningen ovan i avsnittet om Gemini-3.0 multimodal modell.

## Felhantering

Vid anrop av API:t returnerar API:t motsvarande felkod och information om ett fel uppstår. Till exempel:

- `400 token_mismatched`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`：Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`：För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`：Internt serverfel, något gick fel på servern.

### Exempel på felsvar
```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
