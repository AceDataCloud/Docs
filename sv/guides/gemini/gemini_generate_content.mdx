Google Gemini är ett mycket kraftfullt AI-konversationssystem som kan generera flytande och naturliga svar på några sekunder genom att ange en prompt. Detta dokument beskriver främst hur Gemini Generate Content API används. Det är Googles officiella inbyggda API-format och stöder två ändpunkter: `generateContent` och `streamGenerateContent`.

## Skillnader jämfört med Chat Completions API

Gemini Generate Content API använder Googles officiella inbyggda begärandeformat (fältet `contents`) i stället för det OpenAI-kompatibla formatet (fältet `messages`). Om du redan använder Google Gemini SDK eller är bekant med det officiella API-formatet kan du använda detta API direkt utan att ändra begärandeformatet.

## Nuvarande stödomfattning

Gränssnittet accepterar text-, bild-, video- och ljudindata (`inlineData` eller `fileData`), tankekonfigurationer och anpassade funktionsdeklarationer. Enhetlig tillgänglighet för inbyggda fält såsom ljudutdata, inbyggda verktyg och explicit kontextcache kan ännu inte garanteras; se det faktiska svaret från den specifika modellen.

När du skickar ljudfiler och andra filer med `fileData.fileUri`, se till att filerna är direkt åtkomliga via HTTPS, inte är beroende av inloggningsstatus och att den signerade länkens giltighetstid täcker hela begärandets behandlingstid. Icke-strömmande ljudanalys returnerar resultat först efter att modellen har slutfört bearbetningen, vilket kan ta mer än 90 sekunder; klienten bör ange en tillräckligt lång total timeout baserat på filstorlek och affärsscenario för att undvika att anslutningen stängs medan servern fortfarande bearbetar.

## Ansökningsprocess

Innan du använder Gemini Generate Content API ska du först besöka sidan [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) och klicka på knappen "Hämta" för att få de autentiseringsuppgifter som krävs för begäran.

Om du ännu inte har loggat in eller registrerat dig omdirigeras du automatiskt till inloggningssidan. Den första ansökan inkluderar gratis kvot.

## Grundläggande användning

### Non-Streaming（icke-strömmande）

Skicka en POST-begäran till `/v1beta/models/{model}:generateContent`:

> **Tips**: flash i serien `gemini-3.x` är tankemodeller och förbrukar först reasoning tokens; ställ in `generationConfig.maxOutputTokens` på minst 512, annars kan endast tomt innehåll returneras.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Exempel på returnerat resultat:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [
          {
            "text": "你好！很高兴与你交流。"
          }
        ]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Tokenfälten i `usageMetadata` debiteras enligt den inbyggda Gemini-semantiken:

- `promptTokenCount` innehåller `cachedContentTokenCount`; den cacheträffade delen beräknas enligt priset för cacheläsning och räknas inte dubbelt som vanlig indata.
- `promptTokensDetails` och `cacheTokensDetails` normaliseras till `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` och motsvarande `cached_*`-detaljer under `usage.prompt_tokens_details`. Dessa värden ingår respektive i `prompt_tokens` och `cached_tokens`; olika modaliteter beräknas endast enligt sina egna priser och debiteras inte dubbelt.
- Både `candidatesTokenCount` och `thoughtsTokenCount` beräknas enligt priset för output tokens.
- `toolUsePromptTokenCount` är en separat token för verktygsindata och beräknas enligt priset för input tokens.

Ace Data Cloud returnerar dessutom ett normaliserat `usage`-objekt. Läs kostnaden för detta anrop enhetligt mellan modellprotokoll från `usage.cost`. `cost` är en valfri kostnadsförhandsvisning; när prisförhandsvisningen tillfälligt inte är tillgänglig returneras modellsvar fortfarande normalt, men fältet kan saknas. Den slutliga faktureringen baseras på användningsregistren.

### Streaming（strömmande）

Skicka en POST-begäran till `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

Det strömmande svaret returnerar innehåll stegvis i SSE-format (Server-Sent Events). Mellanhändelser innehåller vanligtvis endast inkrementellt innehåll; den slutliga händelsen med auktoritativ användning innehåller `usageMetadata` och normaliserat `usage`, medan kostnaden fortfarande finns i `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

Att anslutningen stängs betyder att strömmen är slut; den inbyggda Gemini-strömmen skickar inte `data: [DONE]`. Om den slutliga prisförhandsvisningen tillfälligt inte är tillgänglig returneras fortfarande tokenanvändningen i `usage`, men `cost` utelämnas.

`gemini-4-carbon` och `gemini-4-hydrogen` kan för närvarande anropas via Chat Completions, native Generate Content är tillfälligt inte tillgängligt. De officiella modellspecifikationerna listar text-, bild-, video-, ljud- och PDF-indata samt textutdata; detta innebär inte att den nuvarande plattformen har verifierat alla indatatyper. När native-anrop återställs, skicka begäranden enligt gränssnittskontraktet på denna sida och verifiera separat de indatatyper och parametrar som behövs. Officiell long decode med utdata på en miljon token omfattas inte av det nuvarande gränssnittskontraktet. Båda stöder endast implicit cachning, tänkande-token debiteras enligt utdata-priset; de förberedda prisreglerna använder samma pris per indata-token för varje indatamodalitet, cacheträffar beräknas enligt priset för cacheläsning, se den aktuella prissidan för detaljer.

### Internt tänkande och sammanfattning av tänkande

Modellens interna tänkande och att returnera en sammanfattning av tänkandet till anroparen är två oberoende inställningar:

- `thinkingBudget` eller `thinkingLevel` styr modellens interna budget eller djup för tänkande; vilka fält och värden som stöds beror på modellen.
- `includeThoughts` styr om en sammanfattning av tänkandet returneras, standardvärdet är `false`. När fältet utelämnas eller `false` skickas, returnerar varken vanliga JSON- eller SSE-strömmande svar text markerad med `thought: true`; dessa texter behålls endast när det booleska värdet `true` uttryckligen skickas.

När begäran inte anger `includeThoughts` skickar gränssnittet som standard `false` till genereringsmodeller som stöder tänkandekonfiguration, för att undvika att begära sammanfattningar som inte behövs; värden, budgetar och nivåer för tänkande som kunden uttryckligen skickar bevaras. För den kända modellen `gemini-2.5-flash-image`, som inte stöder tänkandekonfiguration, läggs inte detta fält automatiskt till, och genereringskonfiguration läggs inte heller till i `countTokens`-begäranden.

Att stänga av sammanfattningar är inte samma sak som att stänga av internt tänkande, och garanterar inte färre token för internt tänkande. Om svaret fortfarande innehåller obegärd tanketext filtreras den ytterligare vid vanliga JSON- och SSE-utgångar, medan normala svar, signaturer och faktisk användning behålls.

När du behöver se sammanfattningen, aktivera den uttryckligen på följande sätt. Om modellen inte genererar någon tillgänglig sammanfattning kan tanketext saknas även om den är aktiverad:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` är krypterat tillstånd som behövs i efterföljande turer, inte texten i sammanfattningen av tänkandet, och styrs inte heller av växeln `includeThoughts`. Signaturen kan finnas på ett normalt svar, ett funktionsanrop eller en tom text-Part; vid filtrering av tanketext behålls signaturen och övriga fält i samma Part, därför kan svaret fortfarande innehålla Part som endast bär en signatur och har tom text. När historik för flera turer underhålls manuellt bör ordningen på dessa Part och signaturernas positioner bevaras; flytta inte signaturer och slå inte samman dem.

`usageMetadata` och `usage` registrerar fortfarande faktisk användning. Att dölja sammanfattningar nollställer inte `thoughtsTokenCount`; debitering beräknas fortfarande enligt faktisk användning och aktuella prisregler.

Se Googles officiella [beskrivning av tänkande och sammanfattningar av tänkande](https://firebase.google.com/docs/ai-logic/thinking) och [regler för tankesignaturer](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

## Säkerhetsinställningar

Innehållsfiltrering kan styras via `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```
