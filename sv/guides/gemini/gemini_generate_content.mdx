Google Gemini är ett mycket kraftfullt AI-konversationssystem som kan generera flytande och naturliga svar på några sekunder genom att mata in en prompt. Detta dokument beskriver främst hur Gemini Generate Content API används. Detta är Googles officiella inbyggda API-format, som stöder de två ändpunkterna `generateContent` och `streamGenerateContent`.

## Skillnader från Chat Completions API

Gemini Generate Content API använder Googles officiella inbyggda begärandeformat (fältet `contents`) i stället för det OpenAI-kompatibla formatet (fältet `messages`). Om du redan använder Google Gemini SDK eller är bekant med det officiella API-formatet kan du använda detta API direkt utan att ändra begärandeformatet.

## Aktuellt stödomfång

Gränssnittet accepterar text-, bild-, video- och ljudindata (`inlineData` eller `fileData`), tankekonfigurationer och deklarationer av anpassade funktioner. Enhetlig tillgänglighet för inbyggda fält som ljudutdata, inbyggda verktyg och explicit kontextcache garanteras ännu inte; utgå från den faktiska responsen för den specifika modellen.

När du skickar ljud och andra filer med `fileData.fileUri`, se till att filen är direkt åtkomlig via HTTPS, inte är beroende av inloggningsstatus och att giltighetstiden för den signerade länken täcker hela begärandebehandlingstiden. Icke-strömmande ljudanalys returnerar resultat först efter att modellen har slutfört bearbetningen, vilket kan ta mer än 90 sekunder; klienten bör ange en tillräckligt lång total timeout utifrån filstorlek och verksamhetsscenario för att undvika att anslutningen bryts medan servern fortfarande bearbetar.

## Ansökningsprocess

Innan du använder Gemini Generate Content API ska du först besöka sidan [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) och klicka på knappen "Hämta" för att få de autentiseringsuppgifter som krävs för begäran.

Om du ännu inte har loggat in eller registrerat dig omdirigeras du automatiskt till inloggningssidan. Den första ansökan inkluderar en kostnadsfri kvot.

## Grundläggande användning

### Non-Streaming (icke-strömmande)

Skicka en POST-begäran till `/v1beta/models/{model}:generateContent`:

> **Tips**: Flash i serien `gemini-3.x` är en tänkande modell och förbrukar först reasoning tokens; ställ in `generationConfig.maxOutputTokens` till 512 eller mer, annars kan endast tomt innehåll returneras.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Exempel på returnerat resultat:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [
          {
            "text": "你好！很高兴与你交流。"
          }
        ]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Token-fälten i `usageMetadata` debiteras enligt den inbyggda Gemini-semantiken:

- `promptTokenCount` inkluderar `cachedContentTokenCount`, och den cacheträffade delen beräknas enligt priset för cacheläsning och räknas inte igen som vanlig indata.
- `promptTokensDetails` och `cacheTokensDetails` normaliseras till `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` samt motsvarande `cached_*`-detaljer under `usage.prompt_tokens_details`. Dessa värden ingår respektive i `prompt_tokens` och `cached_tokens`; olika modaliteter beräknas endast om enligt sina egna priser och debiteras inte dubbelt.
- Både `candidatesTokenCount` och `thoughtsTokenCount` beräknas enligt priset för utdata-token.
- `toolUsePromptTokenCount` är en separat token för verktygsindata och beräknas enligt priset för indata-token.

Ace Data Cloud returnerar dessutom det normaliserade objektet `usage`, där kostnaden för detta anrop konsekvent läses från `usage.cost` över olika modellprotokoll. `cost` är en valfri kostnadsförhandsvisning; när prisförhandsvisningen tillfälligt inte är tillgänglig returneras modellsvar fortfarande normalt, men fältet kan saknas. Den slutliga fakturan baseras på användningsregistren.

### Streaming (strömmande)

Skicka en POST-begäran till `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

Det strömmande svaret returnerar successivt innehåll i SSE-format (Server-Sent Events). Mellanhändelser innehåller vanligtvis endast inkrementellt innehåll; den avslutande händelsen med auktoritativa användningsdata innehåller `usageMetadata` och normaliserad `usage`, och kostnaden finns fortfarande i `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

Att anslutningen stängs innebär att strömmen är slut; den inbyggda Gemini-strömmen skickar inte `data: [DONE]`. Om den avslutande prisförhandsvisningen tillfälligt inte är tillgänglig returneras fortfarande tokenanvändningen i `usage`, men `cost` utelämnas.

### Internt tänkande och sammanfattning av tänkande

Modellens interna tänkande och återgivning av sammanfattningar av tänkande till anroparen är två oberoende inställningar:

- `thinkingBudget` eller `thinkingLevel` styr modellens interna budget eller djup för tänkande; vilka fält och värden som stöds beror på modellen.
- `includeThoughts` styr om en sammanfattning av tänkande ska returneras, och är som standard `false`. När fältet utelämnas eller `false` skickas in returnerar varken vanliga JSON- eller strömmande SSE-svar text markerad med `thought: true`; sådan text behålls endast när det booleska värdet `true` uttryckligen skickas in.

När begäran inte anger `includeThoughts` skickar gränssnittet som standard in `false` till genereringsmodeller som stöder tankekonfiguration, för att undvika att begära sammanfattningar som inte behövs; värden, tankebudgetar och nivåer som klienten uttryckligen skickar in behålls. Det kända `gemini-2.5-flash-image`, som inte stöder tankekonfiguration, får inte automatiskt detta fält tillagt, och `countTokens`-begäranden får inte heller någon genereringskonfiguration tillagd.

Att stänga av sammanfattningar är inte detsamma som att stänga av internt tänkande, och garanterar inte minskat antal tokens för internt tänkande. Om svaret fortfarande innehåller obegärd tanketext filtreras den ytterligare vid utgången för vanliga JSON och SSE, medan vanliga svar, signaturer och faktisk användning behålls.

När du behöver se sammanfattningar ska du uttryckligen aktivera dem på följande sätt. Om modellen inte har genererat en tillgänglig sammanfattning kan tanketext saknas även om detta är aktiverat:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` är ett krypterat tillstånd som krävs för efterföljande turer, inte texten i en sammanfattning av tänkande, och styrs inte heller av växeln `includeThoughts`. Signaturen kan finnas i vanliga svar, funktionsanrop eller tomma textdelar (Part); när tanketext filtreras bort behålls signaturen och andra fält i samma Part, därför kan svaret fortfarande innehålla Parts som endast bär en signatur och har tom text. När historiken för flera turer underhålls manuellt ska ordningen för dessa Parts och signaturernas positioner bevaras; flytta inte signaturerna och slå inte ihop dem.

`usageMetadata` och `usage` registrerar fortfarande den faktiska användningen. Att dölja sammanfattningar nollställer inte `thoughtsTokenCount`; debitering beräknas fortfarande enligt faktisk användning och aktuella prisregler.

Se Googles officiella [beskrivning av tänkande och sammanfattningar av tänkande](https://firebase.google.com/docs/ai-logic/thinking) och [regler för tankesignaturer](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

## Säkerhetsinställningar

Innehållsfiltrering kan styras via `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

| 403      | Innehållet blockerades av säkerhetsfiltret     |
| 429      | Begäran sker för ofta         |
