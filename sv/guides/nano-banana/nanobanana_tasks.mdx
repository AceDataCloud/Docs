Nano Banana Tasks API:s huvudfunktion är att genom att ange det uppdrag ID som genererats av Nano Banana Images API för att fråga om statusen för det uppdraget.

Detta dokument kommer att ge en detaljerad beskrivning av integrationen av Nano Banana Tasks API, vilket hjälper dig att enkelt integrera och fullt utnyttja den kraftfulla funktionen hos detta API. Genom Nano Banana Tasks API kan du enkelt fråga om statusen för uppdrag som utförts av Nano Banana Images API.

## Exempel på begäran

Nano Banana Tasks API kan användas för att fråga om resultaten från Nano Banana Images API. För information om hur man använder Nano Banana Images API, vänligen se dokumentationen [Nano Banana Images API](https://platform.acedata.cloud/documents/veo-videos).

Vi tar ett exempel med ett uppdrag ID som returnerats av Nano Banana Images API-tjänsten, och visar hur man använder detta API. Anta att vi har ett uppdrag ID: 4d320ead-4af4-4a55-8f3e-f2afebdf4fd0, och vi visar hur man gör detta genom att skicka in ett uppdrag ID.

### Ställa in begärningshuvuden och begärningskropp

**Begärningshuvuden** inkluderar:

- `accept`: anger att man tar emot svar i JSON-format, här anges som `application/json`.
- `authorization`: nyckeln för att anropa API:t, som kan väljas direkt efter ansökan.

**Begärningskropp** inkluderar:

- `id`: det uppladdade uppdrag ID:t.
- `action`: hur uppdraget ska hanteras.

### Kodexempel

Det kan noteras att olika språkets kod redan har genererats automatiskt på höger sida, som visas i bilden:

Några kodexempel är som följer:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/nano-banana/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "4d320ead-4af4-4a55-8f3e-f2afebdf4fd0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/nano-banana/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "4d320ead-4af4-4a55-8f3e-f2afebdf4fd0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Det returnerade resultatet innehåller flera fält, där `request`-fältet är begärningskroppen som skickades vid uppdragets start, medan `response`-fältet är svaret som returnerades efter att uppdraget slutfördes. Fälten beskrivs nedan.

- `id`, ID:t för att generera detta uppdrag, används för att unikt identifiera detta genererade uppdrag.
- `request`, begärningsinformationen i uppdraget.
- `response`, svarsinformationen i uppdraget.
- `created_at`, tidpunkten då uppdraget skapades, Unix-tidsstämpel (sekunder, flyttal).
- `started_at`, tidpunkten då uppdraget började utföras, Unix-tidsstämpel (sekunder, flyttal).
- `finished_at`, tidpunkten då uppdraget slutfördes, Unix-tidsstämpel (sekunder, flyttal). Detta fält returneras inte om uppdraget inte är slutfört.
- `elapsed`, den tid som uppdraget tog att utföra, i sekunder (flyttal, med 3 decimaler). Detta fält returneras inte om uppdraget inte är slutfört.

## Batchfrågeoperationer

Detta är för att fråga om detaljerna för flera uppdrag ID:n, och till skillnad från ovanstående kräver det att `action` väljs som `retrieve_batch`.

**Begärningskropp** inkluderar:

- `ids`: en array av uppladdade uppdrag ID:n.
- `action`: hur uppdraget ska hanteras.

Exemplet är som följer:

```bash
curl -X POST 'https://api.acedata.cloud/nano-banana/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["1ebe4f2b-59ba-4385-a4ea-0ce8a3fe12ed","1ebe4f2b-59ba-4385-a4ea-0ce8a3fe12ed"],
  "action": "retrieve_batch"
}'
```

- `count`, antalet batchfrågeuppgifter här.

## Felhantering

Vid anrop av API:et, om ett fel uppstår, kommer API:et att returnera motsvarande felkod och information. Till exempel:

- `400 token_mismatched`: Felaktig begäran, troligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Felaktig begäran, troligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obemyndigad, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många begärningar, du har överskridit hastighetsgränsen.
- `500 api_error`: Intern serverfel, något gick fel på servern.

### Felrespons exempel
