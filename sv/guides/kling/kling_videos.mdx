Detta dokument introducerar en typ av Kling Videos Generation API-integrationsanvisning, som kan generera Kling-officiella videor genom att ange anpassade parametrar.

## Ansökningsprocess

För att använda Kling Videos Generation API går du först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API-token och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig omdirigeras du automatiskt till inloggningssidan för att registrera dig och logga in. När det är klart återvänder du automatiskt till den aktuella sidan.

**En API-token kan anropa alla plattformens tjänster, utan att behöva ansöka separat för varje tjänst.** Vid första ansökan får du gratis kredit för en kostnadsfri testupplevelse; när krediten är otillräcklig kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Grundläggande användning

Låt oss först förstå det grundläggande användningssättet: genom att ange prompten `prompt`, genereringsåtgärden `action`, referensbilden för första bildrutan `start_image_url` samt modellen `model` kan du få det bearbetade resultatet. Först behöver du enkelt skicka ett `action`-fält vars värde är `text2video`. Det omfattar huvudsakligen tre beteenden: text-till-video (`text2video`), bild-till-video (`image2video`) och utöka video (`extend`). Sedan behöver vi även ange modellen `model`; för närvarande finns främst modellerna `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`. Det specifika innehållet är följande:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Här kan vi se att vi har angett Request Headers, inklusive:

- `accept`: vilket format på svarsresultatet som ska tas emot; här anges `application/json`, alltså JSON-format.
- `authorization`: nyckeln för att anropa API:t, som kan väljas direkt i rullgardinsmenyn efter ansökan.

Dessutom har Request Body angetts, inklusive:

- `model`: modellen för att generera video, främst modellerna `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode`: läget för att generera video; valbara värden är standardläge `std`, ultrasnabbt läge `pro` och inbyggt 4K-läge `4k`. `4k` stöder endast `kling-v3` och `kling-v3-omni`, och är inte kompatibelt med `camera_control` (kamerarörelsekontroll).
- `action`: beteendet för denna videogenereringsuppgift, som huvudsakligen omfattar tre beteenden: text-till-video (`text2video`), bild-till-video (`image2video`), utöka video (`extend`).
- `start_image_url`: länken till referensbilden för första bildrutan som måste laddas upp när bild-till-video-beteendet `image2video` väljs.
- `end_image_url`: valfritt vid bild-till-video, anger sista bildrutan.
- `duration`: videolängd, i sekunder. `kling-v3` och `kling-v3-omni` stöder heltalslängder på 3–15 sekunder; `kling-o1` stöder endast 5 sekunder; övriga modeller stöder 5 eller 10 sekunder.
- `generate_audio`: om ljud ska genereras samtidigt, valfritt, booleskt värde. Stöds av `kling-v3`, `kling-v3-omni` samt `kling-v2-6` (endast pro-läge). Standardvärdet är `false`.
- `aspect_ratio`: videons bildförhållande, valfritt, stöder `16:9`, `9:16`, `1:1`, standard är `16:9`.
- `cfg_scale`: relevansstyrka, intervall [0,1]; ju större värde, desto närmare prompten.
- `camera_control`: valfritt, objektparameter för att styra kamerarörelser, stöder type/simple-förinställningar samt konfigurationer som horizontal, vertical, pan, tilt, roll, zoom.
- `negative_prompt`: valfritt, negativ prompt för sådant som inte önskas visas, högst 200 tecken.
- `image_list`: Omni-lista över referensbilder, för modellerna `kling-o1` och `kling-v3-omni`; användning beskrivs nedan i ”Omni allsidig referens”.
- `video_list`: Omni-lista över referensvideor (stöder videoredigering), för modellerna `kling-o1` och `kling-v3-omni`; användning beskrivs nedan i ”Omni allsidig referens”.
- `prompt`: prompt.
- `callback_url`: URL för resultatåteranrop.
- `async`: valfritt; när den anges till `true` returnerar gränssnittet omedelbart `task_id`, utan att `callback_url` behöver anges, och resultatet hämtas därefter genom polling via motsvarande gränssnitt för uppgiftsförfrågan.

Efter valet kan du se att motsvarande kod även genereras på höger sida, såsom visas i bilden:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Klicka på knappen ”Try” för att testa. Som visas i bilden ovan får vi då följande resultat:

```json
{
  "success": true,
  "video_id": "900798310464749610",
  "video_url": "https://cdn.acedata.cloud/assets/examples/kling/6c68c267-065b-4423-b66b-a0e4c59ee0d5-6a664a591a53.mp4",
  "duration": "5.041",
  "state": "succeed",
  "task_id": "6c68c267-065b-4423-b66b-a0e4c59ee0d5"
}
```

Det returnerade resultatet har flera fält, som beskrivs nedan:

- `success`, statusen för videogenereringsuppgiften vid detta tillfälle.
- `task_id`, ID:t för videogenereringsuppgiften vid detta tillfälle.
- `video_id`, video-ID:t för videogenereringsuppgiften vid detta tillfälle.
- `video_url`, videolänken för videogenereringsuppgiften vid detta tillfälle.
- `duration`, videolängden för videogenereringsuppgiften vid detta tillfälle.
- `state`, statusen för videogenereringsuppgiften vid detta tillfälle.

Vi kan se att vi har fått tillfredsställande videoinformation; vi behöver bara hämta den genererade Kling-videon via videolänkadressen i resultatets `data`.

Om du dessutom vill generera motsvarande integrationskod kan du kopiera den direkt. Exempelvis är CURL-koden följande:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Matris över modellkapacitet

### Prissättning för O1 och Omni-referensvideor

`kling-o1` prissätts enligt läge och huruvida `video_list` tillhandahålls. Följande är priserna för en färdig video på 5 sekunder:

| Läge  | Utan referensvideo | Med referensvideo |
| --- | ------------: | ------------: |
| std | 4.005 Credits | 6.010 Credits |
| pro | 5.340 Credits | 8.010 Credits |
`kling-o1` och `kling-v3-omni` med referensvideor i lyckade begäranden debiteras enligt fakturerbara sekunder: std är **1.202 Credits/sekund**, pro är **1.602 Credits/sekund**. Till exempel kostar generering av 5 sekunder i std-läge 6.010 Credits. Att utelämna `video_list` utlöser inte referensvideotaxan; `image_list`, första bildrutan och sista bildrutan tillhör inte heller referensvideo. Referensvideo kan inte användas samtidigt med `generate_audio=true`.

Videoredigering med `refer_type=base` (standard) kan följa referensvideons längd, och debiteras slutligen enligt den faktiska färdiga videons längd avrundad till hela sekunder: till exempel debiteras 5.708 sekunder som 6 sekunder, och 5.041 sekunder som 5 sekunder. `refer_type=feature` använder den begärda `duration`. `usage.reference_video_seconds` i svaret anger de slutliga fakturerbara sekunderna; det uppskattade priset vid begäran kan skilja sig från den slutliga debiteringen.

Olika modeller skiljer sig avsevärt i sitt stöd för parametrar. Följande matris är sammanställd från [Klings officiella video models-dokumentation](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels), kontrollera före anrop om den aktuella kombinationen av `model` / `mode` / `duration` stöder den funktion du behöver, annars returneras fel såsom `model/mode/duration(...) is not supported with image_tail`.

| Modell                  | Läge             | `end_image_url` (första och sista bildrutan) | `generate_audio` (ljud) | `camera_control` (kamerarörelse) | Anmärkning                                           |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ Endast `duration=5` | ❌                    | ✅ Endast `duration=5` | `extend` stöder inte `negative_prompt` och `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | Video från flera bilder, `extend` tillgängligt i alla lägen                         |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Ett enda läge, endast `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Ett enda läge, endast `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | Den enda icke-v3-modellen som samtidigt stöder ljud                             |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | `duration`-intervall 3–15 sekunder                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | 4K-läge är inte kompatibelt med kamerarörelse                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Stöder endast `duration=5`                             |

Observera:

- `mode=4k` stöds endast av `kling-v3` och `kling-v3-omni`; och är ömsesidigt uteslutande med `camera_control` (kamerarörelse).
- `end_image_url` kan endast användas tillsammans med `start_image_url` när `action=image2video`. Att endast skicka `end_image_url` (utan `start_image_url`) kommer att avvisas.
- `kling-v3` / `kling-v3-omni` accepterar valfri heltals-`duration` på 3–15 sekunder; `kling-o1` accepterar endast 5; övriga modeller accepterar endast 5 eller 10.
- `generate_audio` är som standard `false`. Endast `kling-v3`, `kling-v3-omni` och `kling-v2-6` (pro-läge) stöder detta.

## Funktion för att utöka video

Om du vill fortsätta generera en redan genererad Kling-video kan du sätta parametern `action` till `extend`, och du behöver ange ID:t för videon som ska fortsätta genereras. Video-ID:t hämtas enligt den grundläggande användningen, som visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Då kan du se att videons ID är:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Observera att `video_id` i videon här är ID:t för den genererade videon. Om du inte vet hur man genererar en video kan du läsa den grundläggande användningen ovan för att generera en video.

Därefter måste vi fylla i uppmaningen som behöver utökas i nästa steg för att anpassa den genererade videon, och kan ange följande innehåll:

- `model`: Modellen för att generera videon, främst modellerna `kling-v1`, `kling-v1-5` och `kling-v1-6`.
- `mode`: Läget för att generera videon, med valen standardläge `std`, snabbläge `pro` och inbyggt 4K-läge `4k` (stöds endast av `kling-v3` och `kling-v3-omni`, och är inte kompatibelt med kamerarörelsestyrning).
- `duration`: Videolängden för denna videogenereringsuppgift, innehåller främst 5 s och 10 s.
- `start_image_url`: När du väljer videobeteendet från bild `image2video` måste du ladda upp länken till referensbilden för första bildrutan.
- `prompt`: Uppmaning.

Ett exempel på ifyllning är följande:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Efter ifyllnad genereras följande kod automatiskt:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Klicka på kör, så kan du se att du får ett resultat enligt följande:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```
Det kan ses att resultatinnehållet är konsekvent med ovanstående, vilket också implementerar videons utökade videofunktion.

## Omni allsidig referens (videoredigering / referensvideo / referens med flera bilder)

`kling-o1` och `kling-v3-omni` är två oberoende modeller, och båda stöder funktionen ”allsidig referens”. Utifrån text-till-video (`action=text2video`) kan referensbilder eller referensvideor dessutom skickas in för att implementera **referens med flera bilder, referensvideo samt direkt redigering av befintliga videor**.

**Kärnöverenskommelse**: Referensmaterial måste refereras i `prompt` i formatet `&lt;&lt;<image_1>>>`, `&lt;&lt;<video_1>>>` (numreringen börjar från 1) till materialet på motsvarande position i `image_list` / `video_list`, för att modellen ska tillämpa dessa referenser. Om endast material skickas in men inte refereras i prompten ignoreras materialet.

> Säkerhetsinformation: Det aktuella API:et öppnar inte `element_list`. ID:n i Kling Element Library är inte hyresgästisolerade. Använd `image_list` för att skicka in referensbilder för subjekt innan Element Management API med hyresgästisolering tillhandahålls.

Omni-förfrågningar stöder inte `negative_prompt`, `cfg_scale` eller `camera_control`, och kan inte heller använda `mode=4k`. När en referensvideo ingår måste `generate_audio` vara `false`.

### Referensvideo och videoredigering (`video_list`)

`video_list` används för att skicka in referensvideor och är det vanligaste användningsscenariot för denna funktion. Fälten i arrayelementen är följande:

- `video_url`: Länk till referensvideo, får inte vara tom. Högst 1 MP4/MOV-video, filstorlek ≤200MB, bildfrekvens 24–60fps. `kling-o1` kräver en längd på 3–10 sekunder samt bredd och höjd på vardera 700–2160px; `kling-v3-omni` kräver en längd på 3–15,5 sekunder, bredd och höjd på vardera 700–4553px, totalt antal pixlar ≤8 294 400 och bildförhållande 0,4–2.
- `refer_type`: Referenstyp, valfritt `base` (standard, **basvideon som ska redigeras**, dvs. ”redigera videon direkt”, där element kan läggas till/tas bort/ändras, komposition ändras, stil bytas, färger bytas, väder bytas osv.) eller `feature` (**funktionsreferens**, refererar till dess stil / kamerarörelser / fortsätter inspelningen till nästa tagning).
- `keep_original_sound`: Om originalvideons ljud ska behållas, valfritt `yes` (behåll) eller `no` (ta bort).

> Observera: När en referensvideo finns måste `generate_audio` vara `false`. En video med `refer_type=base` kan inte längre ange första bildruta / sista bildruta.

Ett CURL-exempel för att redigera en befintlig video (ändra videon till animestil) är följande:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Referens med flera bilder (`image_list`)

`image_list` används för att skicka in referensbilder (element / scen / stil osv.). Fälten i arrayelementen är följande:

- `image_url`: Länk till referensbild, får inte vara tom. Krav: format .jpg/.jpeg/.png; filstorlek ≤10MB; kortaste sidan ≥300px; bildförhållande 1:2,5 ~ 2,5:1.
- `type`: Valfritt. När det inte skickas används bilden som en ren referensbild; när `first_frame` / `end_frame` skickas används den som första bildruta / sista bildruta (motsvarar `start_image_url` / `end_image_url`).

Vid användning måste den refereras i `prompt` som `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Antalsbegränsning: när ingen referensvideo finns är referensbilder ≤ 7; när en referensvideo finns är referensbilder ≤ 4. När endast första / sista bildruta skickas kan även `start_image_url` / `end_image_url` användas direkt, men den sista bildrutan måste användas tillsammans med den första bildrutan.

> Observera: Om `start_image_url` / `end_image_url` och `image_list` skickas samtidigt placeras första / sista bildrutan före `image_list`, vilket kan påverka numreringskorrespondensen för `&lt;&lt;<image_N>>>`. Det rekommenderas att välja ett av alternativen: när första / sista bildruta behövs, ange `type` direkt i `image_list` och blanda inte med `start_image_url` / `end_image_url`.

CURL-exempel för att generera video med referens från flera bilder:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Asynkron återuppringning

Eftersom genereringstiden för Kling Videos Generation API är relativt lång, ungefär 1–2 minuter, kommer HTTP-förfrågan att behålla anslutningen om API:et inte svarar under en längre tid, vilket leder till ytterligare förbrukning av systemresurser. Därför erbjuder detta API även stöd för asynkron återuppringning.

Det övergripande flödet är: när klienten initierar en förfrågan anges dessutom fältet `callback_url`. Efter att klienten har initierat API-förfrågan returnerar API:et omedelbart ett resultat som innehåller fältet `task_id`, vilket representerar ID:t för den aktuella uppgiften. När uppgiften har slutförts skickas resultatet för den genererade videon i form av POST JSON till den `callback_url` som klienten har angett, vilket också inkluderar fältet `task_id`, så att uppgiftsresultaten kan kopplas samman via ID:t.

Nedan använder vi ett exempel för att förstå hur den konkreta hanteringen fungerar.

Först är Webhook-återuppringningen en tjänst som kan ta emot HTTP-förfrågningar, och utvecklare bör ersätta den med URL:en till sin egen HTTP-server. För att underlätta demonstrationen används här en offentlig exempelsajt för Webhook, https://webhook.site/. Öppna denna webbplats för att få en Webhook-URL, som visas i bilden:

## Felhantering

Vid anrop av API:et returnerar API:et motsvarande felkod och information om ett fel uppstår. Till exempel:

- `400 token_mismatched`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.

## Slutsats

Genom detta dokument har du lärt dig hur du använder Kling Videos Generation API för att generera videor genom att ange promptord samt en referensbild för den första bildrutan. Vi hoppas att detta dokument kan hjälpa dig att bättre integrera och använda detta API. Om du har några frågor, kontakta gärna vårt tekniska supportteam när som helst.

### Kling 3.0 Turbo

`model="kling-v3-turbo"` stöder text-till-video och bild-till-video med en första bildruta, med en varaktighet på heltal från 3–15 sekunder. `mode="std"` ger 720p, och `mode="pro"` ger 1080p. Den här modellen har inbyggt inbyggt ljud och erbjuder ingen avstängningsknapp; utelämna `generate_audio` eller ange det som `true`. Den här modellen stöder inte sista bildrutor, kamerarörelseobjekt, separata negativa promptord eller `cfg_scale`. Beskriv direkt i `prompt` innehållet som behövs eller bör undvikas.

### Videor med flera tagningar

`kling-v3` och `kling-v3-omni` stöder `multi_shot=true`. `shot_type="intelligence"` delar automatiskt upp i tagningar baserat på `prompt`; `shot_type="customize"` tillhandahåller 1–6 tagningar via `multi_prompt`, där varje post innehåller `index` som börjar från 1 och ökar kontinuerligt, `prompt` med högst 512 tecken och en heltalsbaserad `duration` på minst 1 sekund. Summan av varaktigheten för alla tagningar måste vara lika med den totala `duration`. Anpassade tagningar använder inte den globala `prompt`. Flera tagningar debiteras enligt vald modell, bildkvalitet, ljudkonfiguration och total varaktighet.
