Den här artikeln kommer att introducera en metod för integrering av Kling Videos Generation API, som kan generera Kling-officiella videor genom att ange anpassade parametrar.

## Ansökningsprocess

För att använda Kling Videos Generation API, gå först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API Token och spara den som reserv.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig, omdirigeras du automatiskt till inloggningssidan där du uppmanas att registrera dig och logga in. När det är klart återgår du automatiskt till den aktuella sidan.

**En API Token kan anropa alla plattformstjänster, utan att behöva ansöka separat för varje tjänst.** Vid den första ansökan får du gratis kredit för att prova kostnadsfritt; när krediten inte räcker till kan du fylla på det allmänna saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Grundläggande användning

Låt oss först förstå den grundläggande användningen: genom att ange promptordet `prompt`, genereringsåtgärden `action`, referensbilden för första bildrutan `start_image_url` samt modellen `model` kan du få det bearbetade resultatet. Först behöver du enkelt skicka ett fält `action` med värdet `text2video`. Det innehåller huvudsakligen tre beteenden: text-till-video (`text2video`), bild-till-video (`image2video`) och utökad video (`extend`). Därefter behöver vi även ange modellen `model`. För närvarande finns främst modellerna `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`, och det specifika innehållet är följande:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Här kan vi se att vi har ställt in Request Headers, inklusive:

- `accept`: vilket format på svarsresultatet du vill ta emot, här anges `application/json`, alltså JSON-format.
- `authorization`: nyckeln för att anropa API:et, som kan väljas direkt från rullgardinsmenyn efter ansökan.

Dessutom har Request Body ställts in, inklusive:

- `model`: modellen för videogenerering, främst modellerna `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode`: läget för videogenerering, valbara värden är standardläget `std`, snabbaste läget `pro` och det inbyggda 4K-läget `4k`. `4k` stöds endast av `kling-v3` och `kling-v3-omni`, och är inte kompatibelt med `camera_control` (kamerarörelsekontroll).
- `action`: beteendet för denna videogenereringsuppgift, vilket huvudsakligen innehåller tre beteenden: text-till-video (`text2video`), bild-till-video (`image2video`) och utökad video (`extend`).
- `start_image_url`: länken till referensbilden för första bildrutan som måste laddas upp när beteendet bild-till-video `image2video` väljs.
- `end_image_url`: valfritt vid bild-till-video, anger sista bildrutan.
- `duration`: videolängd, i sekunder. `kling-v3` och `kling-v3-omni` stöder heltalslängder på 3–15 sekunder; `kling-o1` stöder endast 5 sekunder; andra modeller stöder 5 eller 10 sekunder.
- `generate_audio`: om ljud ska genereras samtidigt, valfritt, booleskt värde. Stöds av `kling-v3`, `kling-v3-omni` och `kling-v2-6` (endast pro-läge). Standardvärdet är `false`.
- `aspect_ratio`: videons bildförhållande, valfritt, stöder `16:9`, `9:16`, `1:1`, standard är `16:9`.
- `cfg_scale`: relevansstyrka, intervall [0,1], ju större desto mer överensstämmande med promptordet.
- `camera_control`: valfritt, objektparameter för att styra kamerarörelse, stöder type/simple-förinställningar samt konfigurationer som horizontal, vertical, pan, tilt, roll och zoom.
- `negative_prompt`: valfritt, negativa promptord som du inte vill ska förekomma, högst 200 tecken.
- `image_list`: Omni-lista över referensbilder, tillämplig på modellerna `kling-o1` och `kling-v3-omni`, se avsnittet ”Omni allsidig referens” nedan för användning.
- `video_list`: Omni-lista över referensvideor (stöder videoredigering), tillämplig på modellerna `kling-o1` och `kling-v3-omni`, se avsnittet ”Omni allsidig referens” nedan för användning.
- `prompt`: promptord.
- `callback_url`: URL för resultatåteranrop.
- `async`: valfritt, när det ställs in på `true` returnerar gränssnittet omedelbart `task_id`, utan att `callback_url` behöver anges, och resultatet hämtas därefter genom polling via motsvarande gränssnitt för uppgiftsfrågor.

Efter valet kan du se att motsvarande kod även genereras på höger sida, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Klicka på knappen ”Try” för att testa. Som visas i bilden ovan får vi följande resultat:

```json
{
  "success": true,
  "video_id": "900798310464749610",
  "video_url": "https://cdn.acedata.cloud/assets/examples/kling/6c68c267-065b-4423-b66b-a0e4c59ee0d5-6a664a591a53.mp4",
  "duration": "5.041",
  "state": "succeed",
  "task_id": "6c68c267-065b-4423-b66b-a0e4c59ee0d5"
}
```

Det returnerade resultatet innehåller flera fält, som beskrivs nedan:

- `success`, statusen för videogenereringsuppgiften vid denna tidpunkt.
- `task_id`, ID:t för videogenereringsuppgiften vid denna tidpunkt.
- `video_id`, video-ID:t för videogenereringsuppgiften vid denna tidpunkt.
- `video_url`, videolänken för videogenereringsuppgiften vid denna tidpunkt.
- `duration`, längden på videolänken för videogenereringsuppgiften vid denna tidpunkt.
- `state`, statusen för videogenereringsuppgiften vid denna tidpunkt.

Vi kan se att vi har fått tillfredsställande videoinformation. Vi behöver bara hämta den genererade Kling-videon enligt videolänkadressen i resultatets `data`.

Om du dessutom vill generera motsvarande integrationskod kan du direkt kopiera den genererade koden, till exempel är CURL-koden följande:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Matris för modellfunktioner

Olika modeller har stora skillnader i stöd för parametrar. Följande matris har sammanställts från [Klings officiella dokumentation för video models](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels). Kontrollera före anrop att den aktuella kombinationen `model` / `mode` / `duration` stöder den funktion du behöver, annars returneras fel såsom `model/mode/duration(...) is not supported with image_tail`.
| Modell                  | Läge             | `end_image_url` (första och sista bildrutan) | `generate_audio` (ljudspår) | `camera_control` (kamerarörelse) | Kommentar                                           |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ Endast `duration=5`     | ❌                    | ✅ Endast `duration=5`     | `extend` stöder inte `negative_prompt` och `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | Bild-till-video med flera bilder, alla lägen för `extend` tillgängliga                         |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Enkelt läge, endast `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Enkelt läge, endast `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | Den enda modellen som inte är v3 och samtidigt stöder ljudspår                             |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | `duration`-intervall 3–15 sekunder                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | 4K-läget är inkompatibelt med kamerarörelse                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Stöder endast `duration=5`                             |

Observera:

- `mode=4k` stöds endast av `kling-v3` och `kling-v3-omni`; och är ömsesidigt uteslutande med `camera_control` (kamerarörelse).
- `end_image_url` kan endast användas tillsammans med `start_image_url` när `action=image2video`. Att endast skicka `end_image_url` (utan `start_image_url`) kommer att nekas.
- `kling-v3` / `kling-v3-omni` accepterar valfri heltals-`duration` på 3–15 sekunder; `kling-o1` accepterar endast 5; övriga modeller accepterar endast 5 eller 10.
- `generate_audio` är som standard `false`. Endast `kling-v3`, `kling-v3-omni` och `kling-v2-6` (pro-läge) stöds.

## Funktion för videoexpansion

Om du vill fortsätta generera en redan genererad Kling-video kan du ställa parametern `action` till `extend` och ange ID:t för videon som behöver fortsätta genereras. Video-ID:t hämtas enligt den grundläggande användningen, som visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Vid denna tidpunkt kan du se att videons ID är:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Observera att `video_id` i videon här är ID:t för videon efter generering. Om du inte vet hur man genererar en video kan du läsa den grundläggande användningen ovan för att generera en video.

Därefter måste vi fylla i prompten som ska utökas i nästa steg för att anpassa genererad video, och kan ange följande innehåll:

- `model`: Modellen för att generera video, främst modellerna `kling-v1`, `kling-v1-5` och `kling-v1-6`.
- `mode`: Läget för att generera video. Valbara värden är standardläget `std`, snabbläget `pro` och det inbyggda 4K-läget `4k` (stöds endast av `kling-v3` och `kling-v3-omni`, inkompatibelt med kamerarörelsekontroll).
- `duration`: Videolängden för denna videogenereringsuppgift, omfattar huvudsakligen 5 s och 10 s.
- `start_image_url`: När beteendet bild-till-video `image2video` väljs krävs en uppladdad länk till referensbilden för den första bildrutan.
- `prompt`: Prompt.

Ett exempel på ifyllnad är följande:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

När ifyllnaden är klar genereras följande kod automatiskt:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Motsvarande Python-kod:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Klicka på kör, så kan du se att ett resultat erhålls enligt följande:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```

Det kan ses att resultatets innehåll överensstämmer med det ovanstående, vilket implementerar funktionen för videoexpansion.

## Omni allsidig referens (videoredigering / referensvideo / referens med flera bilder)

`kling-o1` och `kling-v3-omni` är två oberoende modeller, och båda stöder kapaciteten ”allsidig referens”. På basis av text-till-video (`action=text2video`) kan referensbilder eller referensvideor dessutom skickas in för att uppnå **referens med flera bilder, referensvideo samt direkt redigering av befintliga videor**.

**Kärnkonvention**: Referensmaterial måste refereras i `prompt` i formen `&lt;&lt;<image_1>>>`, `&lt;&lt;<video_1>>>` (numreringen börjar från 1) till materialet på motsvarande plats i `image_list` / `video_list`, för att modellen ska tillämpa dessa referenser. Om endast material skickas utan att refereras i prompten ignoreras materialet.

> Säkerhetsanvisning: Det aktuella API:et öppnar inte `element_list`. ID:t för Kling Element Library är inte klientisolerat. Innan ett Element Management API som erbjuder klientisolering tillhandahålls, använd `image_list` för att skicka in huvudreferensbilder.

Omni-begäran stöder inte `negative_prompt`, `cfg_scale` eller `camera_control`, och kan inte heller använda `mode=4k`. När en referensvideo ingår måste `generate_audio` vara `false`.

### Referensvideo och videoredigering (`video_list`)
`video_list` används för att skicka in referensvideor och är det vanligaste scenariot för denna funktion. Fälten för matriselementen är följande:

- `video_url`: Länk till referensvideon, får inte vara tom. Högst 1 MP4/MOV-video, filstorlek ≤200MB, bildfrekvens 24–60fps. `kling-o1` kräver en längd på 3–10 sekunder och både bredd och höjd på 700–2160px; `kling-v3-omni` kräver en längd på 3–15.5 sekunder, både bredd och höjd på 700–4553px, totalt antal pixlar ≤8,294,400 och bildförhållande 0.4–2.
- `refer_type`: Referenstyp, valfri `base` (standard, **grundvideo som ska redigeras**, det vill säga ”redigera videon direkt”, där element kan läggas till/tas bort/ändras, kompositionen ändras, stilen bytas, färger bytas, vädret bytas osv.) eller `feature` (**funktionsreferens**, refererar till dess stil / kamerarörelser / fortsättning till nästa tagning).
- `keep_original_sound`: Om originalljudet i videon ska behållas, valfri `yes` (behåll) eller `no` (ta bort).

> Obs: När det finns en referensvideo måste `generate_audio` vara `false`. En video med `refer_type=base` kan inte dessutom ange första bildrutan / sista bildrutan.

Ett CURL-exempel för att redigera en befintlig video (ändra videon till animestil) är följande:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Referens med flera bilder (`image_list`)

`image_list` används för att skicka in referensbilder (element / scener / stilar osv.). Fälten för matriselementen är följande:

- `image_url`: Länk till referensbilden, får inte vara tom. Krav: format .jpg/.jpeg/.png; filstorlek ≤10MB; kortaste sidan ≥300px; bildförhållande 1:2.5 ~ 2.5:1.
- `type`: Valfritt. Används som enbart referensbild om det inte skickas med; när `first_frame` / `end_frame` skickas används de som första bildruta / sista bildruta (motsvarar `start_image_url` / `end_image_url`).

Vid användning måste du referera till dem i `prompt` med `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Antalsbegränsning: referensbilder ≤ 7 när ingen referensvideo finns; referensbilder ≤ 4 när en referensvideo finns. När endast första / sista bildrutan skickas kan även `start_image_url` / `end_image_url` användas direkt, men den sista bildrutan måste användas tillsammans med den första bildrutan.

> Obs: Om `start_image_url` / `end_image_url` och `image_list` skickas samtidigt placeras första / sista bildrutan före `image_list`, vilket kan påverka motsvarigheten för indexnumren i `&lt;&lt;<image_N>>>`. Vi rekommenderar att välja ett av alternativen: när första / sista bildrutan behövs, ange direkt `type` i `image_list` och blanda inte med `start_image_url` / `end_image_url`.

CURL-exempel för att generera video med referens från flera bilder:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Asynkron återkoppling

Eftersom Kling Videos Generation API har en relativt lång genereringstid, ungefär 1–2 minuter, kommer HTTP-begäran att hålla anslutningen öppen om API:t inte svarar under en längre tid, vilket leder till ytterligare förbrukning av systemresurser. Därför erbjuder detta API även stöd för asynkron återkoppling.

Det övergripande flödet är: När klienten initierar en begäran anges dessutom fältet `callback_url`. Efter att klienten har initierat API-begäran returnerar API:t omedelbart ett resultat som innehåller fältinformationen `task_id`, vilket representerar ID:t för den aktuella uppgiften. När uppgiften är klar skickas resultatet av den genererade videon i form av POST JSON till den `callback_url` som anges av klienten, där även fältet `task_id` ingår, så att uppgiftsresultaten kan kopplas ihop via ID:t.

Nedan får vi genom exempel lära oss hur den konkreta processen fungerar.

Först är Webhook-återkopplingen en tjänst som kan ta emot HTTP-begäranden, och utvecklaren bör ersätta den med URL:en till sin egen HTTP-server. För att underlätta demonstrationen används här en offentlig exempelsajt för Webhook, https://webhook.site/. Öppna webbplatsen för att få en Webhook-URL, som visas i bilden:

![](https://cdn.acedata.cloud/tbcnai.png)

Därefter kan vi ställa in fältet `callback_url` som ovanstående Webhook-URL och samtidigt fylla i motsvarande parametrar. Det specifika innehållet visas i bilden:

## Felhantering

Vid anrop av API:t returnerar API:t motsvarande felkod och information om ett fel uppstår. Till exempel:

- `400 token_mismatched`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.
### Exempel på felsvar

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
