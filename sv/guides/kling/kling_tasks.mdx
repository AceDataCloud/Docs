Kling Tasks API:s huvudsakliga funktion är att fråga om körstatusen för en uppgift genom att ange uppgifts-ID:t som genererats av Kling Videos Generation API.

Det här dokumentet kommer att beskriva integreringsanvisningarna för Kling Tasks API i detalj, för att hjälpa dig att enkelt integrera och fullt ut utnyttja API:ets kraftfulla funktioner. Med Kling Tasks API kan du enkelt fråga om uppgiftskörstatusen för Kling Videos Generation API.

## Ansökningsprocess

För att använda Kling Videos Generation API, gå först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API Token och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig kommer du automatiskt att omdirigeras till inloggningssidan för att registrera och logga in dig. När detta är klart återgår du automatiskt till den aktuella sidan.

**En API Token kan användas för att anropa alla tjänster på plattformen, utan att behöva ansöka separat för varje tjänst.** Vid första ansökan får du en kostnadsfri kvot för att prova tjänsten gratis; om kvoten inte räcker till kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Begäransexempel

Kling Tasks API kan användas för att fråga efter resultat från Kling Videos Generation API. För information om hur du använder Kling Videos Generation API, se dokumentationen [Kling Videos Generation API ](https://platform.acedata.cloud/documents/kling-videos).

Vi använder ett uppgifts-ID som returneras av Kling Videos Generation API-tjänsten som exempel för att visa hur detta API används. Anta att vi har ett uppgifts-ID: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, nedan visas hur man genom att ange ett uppgifts-ID.

### Ange begärandehuvuden och begärandetext

**Request Headers** omfattar:

- `accept`: anger att JSON-formaterade svarsresultat ska tas emot, fyll i `application/json` här.
- `authorization`: nyckeln för att anropa API:et, efter ansökan kan den väljas direkt från rullgardinsmenyn.

**Request Body** omfattar:

- `id`: det uppladdade uppgifts-ID:t.
- `action`: åtgärdstypen för uppgiften.

Några kodexempel är följande:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Det returnerade resultatet har flera fält. Fältet request är request body när uppgiften startas, medan fältet response är response body som returneras efter att uppgiften har slutförts. Fälten beskrivs nedan.

- `id`, ID:t för den genererade videouppgiften, används för att unikt identifiera denna videogenereringsuppgift.
- `request`, information om begäran i videouppgiften som frågas efter.
- `response`, information om svaret i videouppgiften som frågas efter.
- `created_at`, tidpunkt då uppgiften skapades, Unix-tidsstämpel (sekunder, flyttal).
- `started_at`, tidpunkt då uppgiften började köras, Unix-tidsstämpel (sekunder, flyttal).
- `finished_at`, tidpunkt då uppgiften slutfördes, Unix-tidsstämpel (sekunder, flyttal). Detta fält returneras inte när uppgiften inte är slutförd.
- `elapsed`, tidsåtgång för uppgiftskörningen, enheten är sekunder (flyttal, behåller 3 decimaler). Detta fält returneras inte när uppgiften inte är slutförd.

- `action`: åtgärdstypen för uppgiften.

## Felhantering

Vid anrop av API:t kommer API:t, om ett fel uppstår, att returnera motsvarande felkod och information. Till exempel:

- `400 token_mismatched`：Felaktig begäran, eventuellt på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`：Felaktig begäran, eventuellt på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`：Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`：För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`：Internt serverfel, något gick fel på servern.
