Denna artikel kommer att introducera en mobilnummer tre element verifiering API integration beskrivning, som kan användas för att verifiera äktheten och överensstämmelsen av mobilnummer, namn och ID-nummer.

## Ansökningsprocess

För att använda API:et måste du först gå till [Mobilnummer tre element verifiering API](https://platform.acedata.cloud/documents/identity-phone-check-3e) motsvarande sida för att ansöka om den tjänst som behövs. När du kommer till sidan, klicka på "Acquire" knappen, som visas i bilden:

![](https://cdn.acedata.cloud/q6ytrc.png)

Om du inte har loggat in eller registrerat dig, kommer du automatiskt att omdirigeras till inloggningssidan för att uppmanas att registrera dig och logga in. Efter inloggning och registrering kommer du automatiskt att återvända till den aktuella sidan.

Vid första ansökan kommer det att finnas en gratis kvot som ges, så att du kan använda API:et gratis.

## Grundläggande användning

Först bör du förstå den grundläggande användningsmetoden, vilket är att ange mobilnumret för att få det bearbetade resultatet. Du behöver först enkelt överföra ett `phone` fält. Vi kan sedan fylla i motsvarande innehåll på gränssnittet, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/3xbffj.png" width="500" className="m-auto" /></p>

Här kan vi se att vi har ställt in Request Headers, inklusive:

- `accept`: vilken format av svar du vill ta emot, här anges som `application/json`, det vill säga JSON-format.
- `authorization`: nyckeln för att anropa API:et, som kan väljas direkt efter ansökan.

Dessutom har vi ställt in Request Body, inklusive:

- `name`: namnet på användaren som ska bearbetas, är ett obligatoriskt parameter.
- `phone`: mobilnumret som ska bearbetas, är ett obligatoriskt parameter.
- `id_card`: ID-numret på användaren som ska bearbetas, är ett obligatoriskt parameter.
- `verify_mode`: verifieringsläge (lång version/kort version).
- `encrypt_list`/`ciphertext_blob`/`iv`: valfria krypteringsparametrar, kryptera känsliga fält vid behov.

Efter att ha valt kan du se att motsvarande kod också har genererats till höger, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/0cp9z1.png" width="500" className="m-auto" /></p>

Klicka på "Try" knappen för att utföra testet, som visas i bilden ovan, här får vi följande resultat:

```json
{
  "result": "0",
  "description": "Verifiering godkänd",
  "isp": "Mobil",
  "result_detail": null
}
```

Det returnerade resultatet har flera fält, som beskrivs nedan:

- `result`, verifieringsresultatkod, avgiftsinformation som följer.
  - Avgiftsresultatkod:
    - 0: Verifieringsresultatet stämmer överens
    - 1: Verifieringsresultatet stämmer inte överens
  - Ingen avgiftsresultatkod:
    - -1: Ingen post hittades
    - -2: Okänt fel i motorn
    - -3: Motorservicen är avvikande
    - -4: Namnverifiering godkändes inte
    - -5: Mobilnumret är ogiltigt
    - -6: Antalet verifieringar överskrider dagens gräns, vänligen försök igen nästa dag
- `description`, affärsresultatsbeskrivning.

Det kan ses att informationen om äktheten och överensstämmelsen av mobilnummer, namn och ID-nummer redan har hämtats.

Om du vill generera motsvarande integrationskod kan du direkt kopiera den som genererats, till exempel CURL-koden nedan:

```shell
curl -X POST 'https://api.acedata.cloud/identity/phone/check-3e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "phone": "***",
  "id_card": "***"
}'
```

Python integrationskoden ser ut som följer:

```python
import requests

url = "https://api.acedata.cloud/identity/phone/check-3e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "name": "***",
    "phone": "***",
    "id_card": "***"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Felhantering

När du anropar API:et, om du stöter på fel, kommer API:et att returnera motsvarande felkod och information. Till exempel:

- `400 token_mismatched`: Bad request, kan bero på saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Bad request, kan bero på saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många förfrågningar, du har överskridit hastighetsgränsen.
- `500 api_error`: Intern serverfel, något gick fel på servern.

### Exempel på felrespons

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "hämtning misslyckades"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
