Den här artikeln introducerar en integrationsguide för Producer Audios Generation API, som kan generera Producers officiella musik genom att ange anpassade parametrar.

## Ansökningsprocess

För att använda Producer Audios Generation API går du först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API-token och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte är inloggad eller registrerad kommer du automatiskt att omdirigeras till inloggningssidan för att registrera och logga in. När detta är klart återgår du automatiskt till den aktuella sidan.

**En API-token kan anropa alla plattformens tjänster, utan att du behöver ansöka separat för varje tjänst.** Vid första ansökan får du kostnadsfria krediter för att testa utan kostnad; när krediterna inte räcker till kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Välj obligatoriska parametrar efter åtgärd

När `action=generate` och `custom=false` (standard) används ska `prompt` anges; när `custom=true`
och `instrumental=false` används ska `lyric` anges. Anpassad instrumentalmusik kan ställas in med
`custom=true, instrumental=true`, utan behov av att hitta på sångtexter eller ytterligare promptar.
`action=extend` kräver `audio_id` och ett `continue_at` större än 0, och i icke-instrumentalt läge krävs även
`lyric`. Covers, variationer, ersättning av segment, byte av stämmor och separering av ljudspår kräver alla källans `audio_id`;
sångtexter och promptar bör inte vara ovillkorligt obligatoriska för alla åtgärder.

I MCP väljer `producer_extend_music` och `producer_replace_section` läget för anpassade sångtexter när `lyric`
anges; för instrumentala fortsättningar kan `instrumental=true` skickas och sångtext utelämnas.

## Grundläggande användning

Om du vill skapa någon typ av låt kan du fritt ange en text. Om jag till exempel vill skapa en låt om jul kan jag ange `a song for Christmas`, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Här kan vi se att vi har angett Request Headers, inklusive:

- `accept`: vilket format för svarsresultatet du vill ta emot; här anges `application/json`, alltså JSON-format.
- `authorization`: nyckeln för att anropa API:t, som kan väljas direkt i rullgardinsmenyn efter ansökan.

Dessutom omfattar parametrarna i Request Body:

- `action`: åtgärden för denna musikgenereringsuppgift; för att generera en låt används `generate`.
- `model`: modellen som används för att skapa låten. För närvarande finns främst: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: låtens sångtext.
- `custom`: om låten ska genereras på ett anpassat sätt.
- `prompt`: prompt i inspirationsläge.
- `title`: information om låttitel.
- `audio_id`: ID för referenslåten, används för åtgärder som fortsättning/cover.
- `continue_at`: fortsätt låten från angivet antal sekunder.
- `replace_section_start`/`replace_section_end`: start- och sluttid för det ersatta segmentet, i sekunder.
- `lyrics_strength`: sångtextstyrka, anger sångtextens påverkan på ljudgenereringen, valbart mellan 0 och 1, standard är 0,7.
- `sound_strength`: styrka för ljudprompt, valbart mellan 0,2 och 1, standard är 0,7.
- `cover_strength`: coverstyrka mellan 0,2 och 1, standard är 1.
- `weirdness`: grad av stilistisk egenhet, valbart mellan 0 och 1, standard är 0,5
- `callback_url`: URL som behöver återkopplingsresultat.
- `async`: valfritt; när den är inställd på `true` returnerar gränssnittet omedelbart `task_id`, utan att `callback_url` behöver anges. Resultatet hämtas sedan genom polling via motsvarande gränssnitt för uppgiftsfrågor.
- `instrumental`: om läget är utan sångtext.

Om du dessutom vill generera motsvarande integrationskod kan du kopiera den direkt. Exempelvis är CURL-koden följande:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Coverversion av låtar

Om du vill göra en coverversion av en redan genererad låt kan du ange den låt som genererades ovan för att göra en coverversion. Därefter ska vi anpassat generera en låt baserat på låttext och titel.

Om du vill fortsätta göra en coverversion av en låt som du själv har laddat upp kan du ställa parametern `action` till `upload_cover` och ange ID:t för den anpassat uppladdade låten som behöver göras till en coverversion. Låt-ID:t hämtas med [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), som visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Då kan följande innehåll anges:

- action: beteendet för denna låtuppgift. Stöds för närvarande: generate, cover, extend, upload_cover, upload_extend, replace_section, swap_vocals, swap_instrumentals, variation. För denna coverversion används parametern `cover`.
- lyric: låttext
- title: låtens titel.
- custom: om generering i anpassat läge används, standardvärdet är false.
- audio_id: låt-ID:t för låten som behöver göras till en coverversion.

## Asynkront återanrop

Eftersom genereringstiden för Producer Audios Generation API ibland kan vara relativt lång, kommer HTTP-begäran att fortsätta hålla anslutningen öppen om API:t inte svarar under lång tid, vilket leder till ytterligare förbrukning av systemresurser, därför erbjuder detta API även stöd för asynkront återanrop.

Det övergripande flödet är: när klienten initierar en begäran anges dessutom ett `callback_url`-fält, efter att klienten initierat API-begäran returnerar API:t omedelbart ett resultat som innehåller fältinformationen `task_id`, som representerar det aktuella uppgifts-ID:t. När uppgiften är klar skickas resultatet av genereringsuppgiften i form av POST JSON till den `callback_url` som klienten angett, vilket också inkluderar fältet `task_id`, så att uppgiftsresultatet kan kopplas samman via ID:t.

Nedan ska vi genom exempel förstå hur man utför den specifika åtgärden.

Först är Webhook-återanrop en tjänst som kan ta emot HTTP-begäranden, utvecklare bör ersätta den med URL:en till den HTTP-server de själva har byggt. För att underlätta demonstrationen används här en offentlig Webhook-exempelwebbplats [https://webhook.site/](https://webhook.site/), öppna webbplatsen för att få en Webhook-URL, som visas på bilden:

![](https://cdn.acedata.cloud/tbcnai.png)

## Felhantering

Vid anrop av API:et returnerar API:et motsvarande felkod och information om ett fel uppstår. Till exempel:

- `400 token_mismatched`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`：Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`：För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`：Internt serverfel, något gick fel på servern.

### Exempel på felsvar

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
