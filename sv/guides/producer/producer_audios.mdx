Den här artikeln kommer att introducera en instruktion för integrering av Producer Audios Generation API, som kan generera officiell musik från Producer genom att mata in anpassade parametrar.

## Ansökningsprocess

För att använda Producer Audios Generation API, gå först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API Token och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig, omdirigeras du automatiskt till inloggningssidan där du uppmanas att registrera dig och logga in. När detta är klart återvänder du automatiskt till den aktuella sidan.

**En API Token kan anropa alla tjänster på plattformen, utan att du behöver ansöka separat för varje tjänst.** Vid första ansökan får du gratis krediter för att testa kostnadsfritt; när krediterna inte räcker till kan du fylla på det allmänna saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Grundläggande användning

Vilken typ av låt du vill ha kan du fritt ange med en text. Om jag till exempel vill generera en låt om jul kan jag ange `a song for Christmas`, som visas i bilden:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Här kan vi se att vi har ställt in Request Headers, inklusive:

- `accept`: vilket format du vill ta emot svaret i, här anges `application/json`, det vill säga JSON-format.
- `authorization`: nyckeln för att anropa API:t, som kan väljas direkt i rullgardinsmenyn efter ansökan.

Dessutom innehåller parametrarna i Request Body:

- `action`: beteendet för denna musikgenereringsuppgift, för att generera en låt är det `generate`.
- `model`: modellen som används för att skapa låten, för närvarande främst: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: låtens låttextinnehåll.
- `custom`: om låten ska genereras med anpassat sätt.
- `prompt`: prompten i inspirationsläget.
- `title`: låttitelinformation.
- `audio_id`: referenslåtens ID, används för åtgärder som fortsättning/remake.
- `continue_at`: fortsätt låten från angivet antal sekunder.
- `replace_section_start`/`replace_section_end`: start- och sluttid för det ersatta segmentet, i sekunder.
- `lyrics_strength`: låttextstyrka, anger graden av låttextens påverkan vid ljudgenerering, valbart mellan 0 och 1, standardvärdet är 0,7.
- `sound_strength`: styrka för ljudprompten, valbart mellan 0,2 och 1, standardvärdet är 0,7.
- `cover_strength`: coverstyrka mellan 0,2 och 1, standardvärdet är 1.
- `weirdness`: stilens egenart, valbart mellan 0 och 1, standardvärdet är 0,5
- `callback_url`: URL:en som behöver få återkopplingsresultatet.
- `async`: valfritt, när det sätts till `true` returnerar gränssnittet omedelbart `task_id`, utan att `callback_url` behöver anges. Därefter hämtas resultatet genom polling via motsvarande gränssnitt för uppgiftsfrågor.
- `instrumental`: om det är läge utan låttext.

Om du dessutom vill generera motsvarande integrationskod kan du kopiera den direkt. Till exempel är CURL-koden följande:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Coverversion av sång

Om du vill utföra en coverversion av en redan genererad sång kan du ange den ovan genererade sången för att skapa en coverversion. Därefter kommer vi att skapa sången anpassat utifrån sångtext och titel.

Om du vill fortsätta skapa en coverversion av en sång som du själv har laddat upp kan du ange parametern `action` som `upload_cover` och ange ID:t för den anpassat uppladdade sång som ska fortsätta få en coverversion. Sång-ID:t hämtas med [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), som visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Då kan följande innehåll anges:

- action：åtgärden för denna sånguppgift, stöder för närvarande: generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation. Denna coverversion använder parametern `cover`.
- lyric：sångtext
- title：sångens titel.
- custom：om generering ska ske i anpassat läge, standardvärdet är false.
- audio_id：sång-ID:t för sången som ska få en coverversion.

Exempel på ifyllnad är följande:

<p><img src="https://cdn.acedata.cloud/6xl82z.png" width="500" className="m-auto" /></p>

## Asynkron återuppringning

Eftersom genereringstiden för Producer Audios Generation API ibland kan vara relativt lång, kommer HTTP-begäran att hålla anslutningen öppen om API:t inte svarar under en längre tid, vilket leder till extra förbrukning av systemresurser, därför erbjuder detta API också stöd för asynkron återuppringning.

Det övergripande flödet är: när klienten initierar en begäran anges dessutom ett `callback_url`-fält. Efter att klienten har initierat API-begäran returnerar API:t omedelbart ett resultat som innehåller ett `task_id`-fält, vilket representerar ID:t för den aktuella uppgiften. När uppgiften är klar skickas resultatet av genereringsuppgiften till den `callback_url` som klienten angett i form av POST JSON, där även fältet `task_id` ingår, så att uppgiftsresultatet kan kopplas samman via ID:t.

Nedan ska vi förstå den specifika användningen genom ett exempel.

Först och främst är Webhook-återuppringning en tjänst som kan ta emot HTTP-begäranden, och utvecklare bör ersätta den med URL:en till sin egen HTTP-server. För att underlätta demonstrationen används här en offentlig exempelwebbplats för Webhook, [https://webhook.site/](https://webhook.site/). Öppna denna webbplats för att få en Webhook-URL, som visas på bilden:

![](https://cdn.acedata.cloud/tbcnai.png)

## Felhantering

Vid anrop av API:et, om ett fel uppstår, kommer API:et att returnera motsvarande felkod och information. Till exempel:

- `400 token_mismatched`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`：Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`：För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`：Internt serverfel, något gick fel på servern.

### Exempel på felsvar

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
