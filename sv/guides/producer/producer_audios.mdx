Detta dokument introducerar en typ av instruktioner för integrering av Producer Audios Generation API, som kan generera officiell musik från Producer genom att ange anpassade parametrar.

## Ansökningsprocess

För att använda Producer Audios Generation API ska du först hämta din API Token från [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte har loggat in eller registrerat dig omdirigeras du automatiskt till inloggningssidan för att registrera och logga in. När detta är klart återgår du automatiskt till den aktuella sidan.

**En API Token kan anropa alla plattformens tjänster, utan att behöva ansöka separat för varje tjänst.** Vid första ansökan får du gratis kredit för att prova utan kostnad; när krediten inte räcker till kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Välj obligatoriska parametrar efter åtgärd

När `action=generate` och `custom=false` (standard) används ska `prompt` anges; när `custom=true`
och `instrumental=false` används ska `lyric` anges. Anpassad instrumentalmusik kan ställas in med
`custom=true, instrumental=true`, utan behov av påhittade låttexter eller ytterligare promptar.
`action=extend` kräver `audio_id` och ett `continue_at` större än 0, och icke-instrumentalt läge kräver dessutom
`lyric`. Cover, varianter, ersättning av segment, byte av stämmor och separation av ljudspår kräver alla källans `audio_id`;
låttext och prompt bör inte vara obligatoriska villkorslöst för alla åtgärder.

I MCP väljer `producer_extend_music` och `producer_replace_section` läget för anpassad låttext när `lyric`
anges; för fortsättning av instrumentalmusik kan `instrumental=true` skickas och låttext utelämnas.

## Grundläggande användning

Tänk på vilken låt du vill ha och skriv valfri text. Om jag till exempel vill generera en låt om jul kan jag ange `a song for Christmas`, som visas i figuren:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Här kan vi se att vi har ställt in Request Headers, inklusive:

- `accept`: vilket format för svar du vill ta emot, här anges `application/json`, det vill säga JSON-format.
- `authorization`: nyckeln för att anropa API:t, som kan väljas direkt i rullgardinsmenyn efter ansökan.

Dessutom omfattar parametrarna i Request Body:

- `action`: åtgärden för denna musikgenereringsuppgift, `generate` används för att generera en låt.
- `model`: modellen som används för att skapa låten, för närvarande främst: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: låttextens innehåll.
- `custom`: om låten ska genereras på ett anpassat sätt.
- `prompt`: prompt i inspirationsläget.
- `title`: information om låttitel.
- `audio_id`: ID för referenslåten, används för åtgärder som fortsättning/cover.
- `continue_at`: fortsätt låten från angivet antal sekunder.
- `replace_section_start`/`replace_section_end`: start- och sluttid för det ersatta segmentet, i sekunder.
- `lyrics_strength`: låttextstyrka, anger låttextens påverkan vid ljudgenerering, valfritt mellan 0 och 1, standard är 0.5.
- `sound_strength`: styrka för ljudprompt, valfritt mellan 0.2 och 1, standard är 0.5.
- `cover_strength`: cover-styrka mellan 0.2 och 1, standard är 1.
- `weirdness`: grad av stilmässig särprägel, valfritt mellan 0 och 1, standard är 0.5
- `callback_url`: URL som ska ta emot återkopplingsresultatet.
- `async`: valfritt, när den sätts till `true` returnerar gränssnittet omedelbart `task_id`, utan att `callback_url` behöver anges, varefter resultatet hämtas genom polling via motsvarande uppgiftsfrågegränssnitt.
- `instrumental`: om läget är utan låttext.

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Coverversion av en låt

Om du vill göra en coverversion av en redan genererad låt kan du ange den ovan genererade låten för att skapa en coverversion. Därefter ska vi anpassat generera en låt baserat på låttext och titel.

Om du vill fortsätta göra en coverversion av en låt som du själv har laddat upp kan du ställa parametern `action` till `upload_cover` och ange ID:t för den anpassat uppladdade låten som ska fortsätta coveras. Låt-ID:t hämtas med [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), som visas i bilden nedan:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Då kan följande innehåll anges:

- action: åtgärden för denna låtuppgift. Stöd finns för närvarande för: generate, cover, extend, upload_cover, upload_extend, replace_section, swap_vocals, swap_instrumentals, variation. För denna coverversion används parametern `cover`.
- lyric: låttext
- title: låtens titel.
- custom: om generering i anpassat läge används, standardvärdet är false.
- audio_id: låt-ID:t för låten som ska coveras.

Ett exempel på ifyllnad är följande:

## Asynkront återanrop

Eftersom tiden för generering med Producer Audios Generation API ibland kan vara relativt lång, och HTTP-begäran fortsätter att hålla anslutningen öppen om API:t inte svarar under en lång tid, vilket leder till ytterligare förbrukning av systemresurser, erbjuder detta API även stöd för asynkrona återanrop.

Det övergripande flödet är: när klienten initierar en begäran anges dessutom ett fält `callback_url`. Efter att klienten har initierat API-begäran returnerar API:t omedelbart ett resultat som innehåller fältinformationen `task_id`, vilket representerar det aktuella uppgifts-ID:t. När uppgiften är klar skickas resultatet av genereringsuppgiften i form av POST JSON till den `callback_url` som klienten har angett, där fältet `task_id` också ingår, så att uppgiftsresultatet kan kopplas samman via ID:t.

Nedan ska vi genom exempel förstå hur man konkret gör.

Först är Webhook-återanrop en tjänst som kan ta emot HTTP-begäranden, och utvecklaren bör ersätta den med URL:en till sin egen uppsatta HTTP-server. För att underlätta demonstrationen används här en offentlig exempelwebbplats för Webhook [https://webhook.site/](https://webhook.site/). Genom att öppna webbplatsen kan du få en Webhook-URL, som visas i figuren:

![](https://cdn.acedata.cloud/tbcnai.png)

## Felhantering

Vid anrop av API:et returnerar API:et motsvarande felkod och information om ett fel uppstår. Till exempel:

- `400 token_mismatched`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`: Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`: Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`: För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`: Internt serverfel, något gick fel på servern.

### Exempel på felsvar

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
