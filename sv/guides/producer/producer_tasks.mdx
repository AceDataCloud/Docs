Huvudfunktionen för Producer Tasks API är att fråga om exekveringsstatusen för en uppgift genom att ange uppgifts-ID:t som genererats av Producer Audios Generation API.

Detta dokument kommer att ge en detaljerad introduktion till integreringsanvisningarna för Producer Tasks API, för att hjälpa dig att enkelt integrera och fullt ut utnyttja API:ets kraftfulla funktioner. Genom Producer Tasks API kan du enkelt fråga om uppgifters exekveringsstatus i Producer Audios Generation API.

## Ansökningsprocess

För att använda Producer Audios Generation API, gå först till [Ace Data Cloud-konsolen](https://platform.acedata.cloud/console/applications) för att hämta din API-token och spara den för senare användning.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Om du ännu inte är inloggad eller registrerad omdirigeras du automatiskt till inloggningssidan där du uppmanas att registrera dig och logga in. När detta är klart återgår du automatiskt till den aktuella sidan.

**En API-token kan anropa alla tjänster på plattformen, utan att behöva ansöka separat för varje tjänst.** Vid första ansökan får du en kostnadsfri kvot för att prova tjänsten gratis; när kvoten är otillräcklig kan du fylla på det gemensamma saldot i [konsolen](https://platform.acedata.cloud/console/coin).

> 📘 Fullständig dokumentation: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Begäransexempel

Producer Tasks API kan användas för att fråga om resultaten från Producer Audios Generation API. För information om hur du använder Producer Audios Generation API, se dokumentationen [Producer Audios Generation API ](https://platform.acedata.cloud/documents/producer-audios-integration).

Vi tar ett uppgifts-ID som returneras av tjänsten Producer Audios Generation API som exempel för att visa hur API:et används. Anta att vi har ett uppgifts-ID: 1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad, nedan visas hur du gör genom att ange ett uppgifts-ID.

### Ange begärandehuvud och begärandetext

**Request Headers** inkluderar:

- `accept`: anger att svar i JSON-format ska tas emot, ange här `application/json`.
- `authorization`: nyckeln för att anropa API:et, som kan väljas direkt från rullgardinsmenyn efter ansökan.

**Request Body** inkluderar:

- `id`: det uppladdade uppgifts-ID:t.
- `action`: åtgärdssättet för uppgiften.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

Det returnerade resultatet innehåller flera fält. Fältet `request` är request body när uppgiften startas, medan fältet `response` är response body som returneras efter att uppgiften har slutförts. Fältbeskrivningarna är följande.

- `request`，begärandeinformation i frågeuppgiften.
- `response`，returinformation i frågeuppgiften.
- `created_at`，tid då uppgiften skapades, Unix-tidsstämpel (sekunder, flyttal).
- `started_at`，tid då uppgiften började köras, Unix-tidsstämpel (sekunder, flyttal).

## Åtgärd för batchfråga

Detta används för att fråga efter uppgiftsdetaljer för flera uppgifts-ID:n. Skillnaden jämfört med ovan är att `action` måste väljas som `retrieve_batch`

**Request Body** inkluderar:

- `ids`：arrayen med uppladdade uppgifts-ID:n.
- `action`：åtgärdssättet för uppgiften.

## Felhantering

När API:et anropas returnerar API:et motsvarande felkod och information om ett fel uppstår. Till exempel:

- `400 token_mismatched`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `400 api_not_implemented`：Felaktig begäran, möjligen på grund av saknade eller ogiltiga parametrar.
- `401 invalid_token`：Obehörig, ogiltig eller saknad auktoriseringstoken.
- `429 too_many_requests`：För många begäranden, du har överskridit hastighetsgränsen.
- `500 api_error`：Internt serverfel, något gick fel på servern.

### Exempel på felsvar
