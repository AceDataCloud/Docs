Die Suno Studio Project API verwaltet mehrspurige Musikprojekte über einen Einstiegspunkt:

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
```

`action` in der Anfrage bestimmt den Operationstyp. Für Project-Primärschlüssel wird einheitlich `id` verwendet; `version_id` bezeichnet die aktuelle Projektversion, und alle Änderungs- und Exportvorgänge müssen die neueste Version übermitteln, um Überschreibungen bei Parallelität zu vermeiden.

## Operationsübersicht

| action             | Modus  | Zweck                      |
| ------------------ | --- | ----------------------- |
| `create`           | synchron  | Leeres Projekt erstellen                   |
| `retrieve`         | synchron  | Projekt und vollständigen bearbeitbaren `state` lesen      |
| `save`             | synchron  | Vollständigen Projektstatus speichern                |
| `upload`           | asynchron  | Material, das dem Projekt hinzugefügt werden kann, über eine HTTPS-Audioadresse initialisieren |
| `add_track`        | asynchron  | Vorhandenes Audio zum Projekt hinzufügen               |
| `generate_track`   | asynchron  | Neue Audiospurkandidaten für einen angegebenen Bereich generieren            |
| `replace_section`  | asynchron  | Kandidaten für lokale Ersetzungen generieren                |
| `commit_candidate` | asynchron  | Ausgewählten Kandidaten in das Projekt übernehmen             |
| `remove_track`     | synchron  | Angegebene Spur löschen                  |
| `render`           | asynchron  | Gespeicherte Version als vollständigen Song exportieren           |

Asynchrone Operationen geben sofort `task_id` zurück. Verwenden Sie die kostenlose Schnittstelle `/suno/tasks` zum Abfragen, oder übergeben Sie `callback_url`, um Ergebnisse im Endzustand zu erhalten.

## Erstellen und Lesen

```json
{"action":"create","title":"My Studio Project"}
```

Alle Änderungsoperationen sollten einen eindeutigen `Idempotency-Key`-Header senden. Nach erfolgreicher Erstellung ist `data.id` in der Antwort die Project ID. Ein neu erstelltes leeres Projekt hat vor dem ersten Speichern möglicherweise keine `version_id`.

```json
{"action":"retrieve","id":"PROJECT_ID"}
```

Die Leseantwort enthält den vollständigen `state`. Es wird empfohlen, zuerst zu lesen und dann basierend auf den Rückgabewerten zu ändern und zu speichern; konstruieren Sie interne Takt- und Spurstrukturen nicht manuell von Grund auf.

## Vollständigen Status speichern

```json
{
  "action":"save",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "title":"Edited Project",
  "state":{"tracks":[],"timing":{}}
}
```

Beim ersten Speichern eines neu erstellten leeren Projekts kann `version_id` weggelassen werden; nachdem durch das erste Speichern eine Version generiert wurde, müssen nachfolgende Speichervorgänge den neuesten Wert übermitteln. Wenn sich die Version bereits geändert hat, gibt die Schnittstelle HTTP 409 zurück. Führen Sie in diesem Fall erneut `retrieve` aus, führen Sie die Änderungen zusammen und übermitteln Sie sie dann mit einem neuen Idempotenzschlüssel; wiederholen Sie die alte Anfrage nicht blind.

## Hochladen und Hinzufügen von Spuren

```json
{
  "action":"upload",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "audio_url":"https://cdn.example.com/reference.mp3",
  "async":true
}
```

Nach Abschluss des Uploads gibt das Aufgabenergebnis die Kandidaten-`audio_id` zurück. Fügen Sie sie dann dem Projekt hinzu:

```json
{
  "action":"add_track",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "audio_id":"AUDIO_ID",
  "name":"Backing Vocals"
}
```

## Generieren und Ersetzen

`generate_track` generiert Audiospurkandidaten für einen Projektbereich; `replace_section` gibt zwei Kandidaten für lokale Ersetzungen zurück. Beide Operationen wählen künstlerische Ergebnisse nicht automatisch aus.

```json
{
  "action":"replace_section",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "source_audio_id":"AUDIO_ID",
  "start_seconds":35.12,
  "end_seconds":48.76,
  "model":"chirp-v6",
  "replacement_lyrics":"新的歌词片段",
  "async":true
}
```

Nach Auswahl eines Kandidaten übernehmen Sie ihn:

```json
{
  "action":"commit_candidate",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "operation_id":"OPERATION_ID",
  "candidate_id":"CANDIDATE_ID",
  "track_id":"TRACK_ID"
}
```

Kandidaten sind an die Projektversion zum Zeitpunkt der Generierung gebunden. Wenn sich das Projekt bereits geändert hat, können alte Kandidaten nicht direkt übernommen werden.

## Vollständigen Song exportieren

```json
{
  "action":"render",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "title":"Final Mix",
  "lyrics":"[Instrumental]",
  "async":true,
  "callback_url":"https://example.com/webhooks/suno"
}
```

Der Server liest den maßgeblichen Projektstatus der angegebenen Version und stellt die Exportparameter zusammen. Das Ergebnis im Endzustand enthält `render_id`, `audio_id`, `audio_url` und die Dauer. Das Projekt ist an die Ausführungsumgebung bei der Erstellung gebunden und kann nicht umgebungsübergreifend migriert oder automatisch auf Fehler umgeschaltet werden.

> Sie dürfen nur Audio hochladen oder verarbeiten, für das Sie rechtmäßige Nutzungsrechte besitzen. Die Project API befindet sich derzeit in der Beta-Phase; speichern Sie die finalen Audio-URLs in wichtigen Ergebnissen dauerhaft.
