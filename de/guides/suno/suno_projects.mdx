`POST https://api.acedata.cloud/suno/projects` ist die Beta-Schnittstelle zur Verwaltung von Mehrspurprojekten. Ein Endpunkt unterscheidet über `action` zwischen Erstellen, Speichern, Generieren von Kandidaten, Übermitteln von Kandidaten und Exportieren. Aufrufer müssen nur die unten aufgeführten öffentlichen Felder verwenden und müssen nicht die interne Anfragestruktur des zugrunde liegenden Generierungsdienstes ausfüllen.

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: 每次修改操作使用新的 UUID
```

Außer bei `retrieve` ist für **jede Operation** ein `Idempotency-Key` erforderlich. Derselbe Schlüssel mit derselben Anfrage liest nur das ursprüngliche Ergebnis zurück; derselbe Schlüssel mit einer anderen Anfrage gibt 409 zurück. Wenn bei kostenpflichtigen Generierungen ein Netzwerk-Timeout auftritt oder das Übermittlungsergebnis ungewiss ist, fragen Sie zunächst mit der ursprünglichen Aufgaben-ID oder demselben Idempotenzschlüssel ab und senden Sie nicht direkt mit einem neuen Schlüssel erneut.

## Unterscheiden Sie zuerst diese IDs und Zeiteinheiten

| Name                             | Woher beziehen                                                                                | Wo verwenden                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | `create`-Antwort `data.id`                                                                      | Alle nachfolgenden Anfragen des aktuellen Projekts                                      |
| `version_id`                   | `data.version_id` des letzten `retrieve`, `save`, `add_track`, `commit_candidate` oder `remove_track` | Änderungen, Generierung von Kandidaten und Export; die neueste Version muss verwendet werden                              |
| `audio_id` / `source_audio_id` | `response.data.candidate.audio_id` im Endzustand von `upload` oder eine vorhandene abgeschlossene Audio-ID                                | Verweis auf das Quellaudio beim `add_track`, Generieren oder Ersetzen                          |
| `render_audio_id`              | `response.data.audio_id` im Endzustand von `render`                                                       | Referenz für den Projektmix von `generate_track`                         |
| `operation_id`                 | `response.data.operation_id` im Endzustand von `generate_track` oder `replace_section`                       | `commit_candidate`; normalerweise identisch mit der `task_id` der Generierungsaufgabe, aber der Rückgabewert sollte gelesen werden |
| `candidate_id`                 | `response.data.candidates[].id` im Generierungsendzustand                                                       | Einen Kandidaten zur Übermittlung auswählen                                         |
| `track_id`                     | `data.state.tracks[].id` des Projekts                                                                | Kandidaten übermitteln oder Spuren löschen                                        |
| `task_id`                      | Antwort bei Übermittlung einer asynchronen Operation                                                                                   | Mit `/suno/tasks` den Endzustand abfragen; dies ist keine Projekt-ID                   |

`start_seconds` / `end_seconds` sind **Sekunden innerhalb des Quellaudios**; `start_beats` / `end_beats` sind **Schläge auf der Projektzeitachse**. `state.timing.bps` ist die Anzahl der Schläge pro Sekunde, standardmäßig 2. Beispielsweise beginnt ein 41-sekündiges Segment bei Schlag 0, der Standardendpunkt liegt bei Schlag 82. Der Sekundenbereich von `generate_track` wird verwendet, um die Generierungsreferenz festzulegen, und garantiert nicht, dass der Kandidat nur die Länge dieses Bereichs hat.

## Operationsreihenfolge und Ergebnisbeurteilung

| Reihenfolge  | `action`                             | Funktion                         | Rückgabeart         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | Leeres Projekt erstellen                      | Synchrone Projektdaten       |
| 2   | `retrieve`                           | Neueste Version und vollständigen `state` lesen          | Synchrone Projektdaten       |
| 3   | `save`                               | Erstmalig speichern oder den geänderten gesamten `state` speichern      | Synchrone Projektdaten       |
| 4   | `upload`                             | Material aus einer HTTPS-Audioadresse erstellen           | Asynchrone Aufgabe         |
| 5   | `add_track`                          | Materialaudio in das Projekt einfügen                  | Asynchrone Aufgabe, aktualisiert Version    |
| 6   | `save`                               | Wenn neue Spur-Kandidaten empfangen werden sollen, zunächst eine leere Zielspur speichern        | Synchrone Projektdaten, aktualisiert Version  |
| 7   | `render`                             | Aktuell hörbare Spuren exportieren und die Mixreferenz-`audio_id` erhalten | Asynchrone Aufgabe         |
| 8   | `generate_track` oder `replace_section` | Jeweils neue Spur-Kandidaten oder Kandidaten für lokalen Ersatz generieren            | Asynchrone Aufgabe, ändert das Projekt vorerst nicht  |
| 9   | `commit_candidate`                   | Einen Kandidaten auswählen und übermitteln                  | Asynchrone Aufgabe, aktualisiert Version nach Erfolg |
| Optional  | `remove_track`                       | Angegebene Spur löschen                     | Synchrone Projektdaten, aktualisiert Version  |

Wenn nur ein lokaler Ersatz vorgenommen wird, genügt vorhandenes nutzbares Quellaudio, und `render` muss nicht zuerst ausgeführt werden; wenn das Quellaudio bereits im Projekt vorhanden ist, können auch `upload` und `add_track` übersprungen werden. `render_audio_id` ist nur die erforderliche Referenz von `generate_track`.

Bei der Übermittlung einer asynchronen Operation wird zunächst `{ "task_id": "...", "trace_id": "..." }` zurückgegeben, was **nicht bedeutet, dass die Generierung erfolgreich war**. Abfragen:

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步返回的 task_id"}
```

Erst wenn der Aufgabeneintrag `finished_at` hat und dessen `response.success` `true` ist, gilt die Operation als erfolgreich; bei `response.success=false` lesen Sie `response.error`. Obwohl `save` möglicherweise eine `task_id` enthält, wird es innerhalb dieser Schnittstelle synchron abgeschlossen. `upload`, `render`, `generate_track`, `replace_section` ändern die Projektversion nicht; nach erfolgreichem `save`, `add_track`, `commit_candidate`, `remove_track` sollte die neue `version_id` übernommen werden.

## Anfrageparameter

### Allgemeine Felder und Anfrage-Header

| Parameter                | Typ und Geltungsbereich                                                                                   | Beschreibung                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | Erforderlicher String                                                                                     | Festgelegt auf einen auf dieser Seite aufgeführten Operationsnamen; eine Anfrage führt nur eine Operation aus.                                      |
| `id`              | Erforderlicher String außer bei `create`                                                                         | Projekt-ID aus `create.data.id`.                                      |
| `version_id`      | Erforderlicher String bei Änderungen, Generierung von Kandidaten und Export; beim ersten `save` eines leeren Projekts kann es weggelassen werden                                                         | Verwenden Sie die neueste Version, alte Versionen werden abgelehnt. `retrieve` benötigt sie nicht.                                 |
| `Idempotency-Key` | Erforderlicher Anfrage-Header außer bei `retrieve`, 1–128 Zeichen                                                              | Verwenden Sie für jede neue Operation einen neuen Schlüssel; derselbe Schlüssel mit derselben Anfrage liest das ursprüngliche Ergebnis zurück und generiert nicht erneut bzw. berechnet keine Kosten erneut.                                   |
| `async`           | Optionaler Boolescher Wert für `upload`, `add_track`, `generate_track`, `replace_section`, `commit_candidate`, `render` | Diese Operationen sind immer asynchron; auch `false` macht die Generierung nicht synchron.                                    |
| `callback_url`    | Optionale URL für die Operationen mit den oben genannten optionalen asynchronen Feldern                                                                       | Empfängt Endzustandsbenachrichtigungen; wenn weggelassen, fragen Sie `/suno/tasks` anhand der `task_id` ab. `response.success` muss weiterhin überprüft werden. |

### Projekt und Material
| `action`       | Spezifischer Parameter        | Typ und Bedingungen                    | Beschreibung                                                                 |
| -------------- | --------------------------- | -------------------------------- | ------------------------------------------------------------------ |
| `create`       | `title`                     | Erforderliche Zeichenfolge, 1–200 Zeichen                   | Neuer Projekttitel.                                                             |
| `retrieve`     | Keine                           | —                                | Es werden nur `action` und die Projekt-`id` benötigt; gibt den vollständig bearbeitbaren `state` zurück.                              |
| `save`         | `state`                     | Erforderliches Objekt                             | **Vollständiges Ersetzen** des Projektstatus, kein partieller Patch. Auf Basis des zuletzt abgerufenen `retrieve.data.state` ändern und vollständig übermitteln, unbekannte Felder beibehalten. |
| `save`         | `title`                     | Optionale Zeichenfolge                            | Projekttitel; bei Auslassung wird `state.title` verwendet, andernfalls der Standardtitel.                              |
| `upload`       | `audio_url`                 | Erforderliche HTTPS-URL                     | Öffentlich zugängliche Adresse des Audiomaterials; nach Erfolg die finale `candidate.audio_id` auslesen. Der Aufrufer sollte die Nutzungsrechte für das Material besitzen.            |
| `add_track`    | `audio_id`                  | Erforderliche Zeichenfolge                            | Audio-ID von bereits abgeschlossenem Material, keine URL.                                                |
| `add_track`    | `name` / `color`            | Optionale Zeichenfolgen                            | Neuer Spurname, neue Farbe; der Name wird standardmäßig aus dem Audiotitel übernommen, für die Farbe wird `#RRGGBB` empfohlen, Standard ist `#7251F7`.                    |
| `add_track`    | `title`                     | Optionale Zeichenfolge                            | Ändert gleichzeitig den Projekttitel; wird normalerweise ausgelassen.                                                     |
| `add_track`    | `start_beats` / `end_beats` | Optionale nichtnegative Zahlen, `end_beats > start_beats` | Position des Clips auf der Projektzeitachse. Der Startpunkt ist standardmäßig 0; der Endpunkt ist standardmäßig `Startpunkt + Audiodauer × timing.bps`.                  |
| `add_track`    | `gain`                      | Optionale nichtnegative Zahl, Standard 1                      | Lautstärkefaktor für den Clip und die neue Spur.                                                       |
| `remove_track` | `track_id`                  | Erforderliche Zeichenfolge                            | ID der vorhandenen Spur, die gelöscht werden soll. Erfolgreich danach die zurückgegebene neue Version verwenden.                                           |

`state.timing.bps` muss eine positive Zahl sein, Standard ist 2. `state.tracks` ist ein Spur-Array; der `clipId` vorhandener Audioclips referenziert die Audio-ID, `startBeats`, `endBeats` und `readStartBeats` verwenden Projektschlageinheiten. Die sicherste Bearbeitungsmethode besteht darin, den vollständigen `state` abzurufen, nur die Zielspur oder den Zielclip zu ändern und anschließend vollständig zu `save`n. Eine neu hinzugefügte leere Zielspur sollte mindestens eine eindeutige `id`, `type:"audio"` und `clips:[]` haben; die vollständig nutzbare tatsächliche Struktur ist in Schritt 5 unten zu sehen. Verwenden Sie die Beatpunkte aus den Audioanalyseergebnissen nicht direkt als Koordinaten der Projektzeitachse.

### Generieren, übermitteln und exportieren
| `action`                             | Spezifische Parameter               | Typ und Bedingungen                         | Beschreibung                                                                                                                                                        |
| ------------------------------------ | ---------------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generate_track` / `replace_section` | `source_audio_id`                  | Erforderliche Zeichenfolge                    | ID des abgeschlossenen Quellaudios. Fügen Sie das Quellaudio zuerst dem Projekt hinzu, damit nachfolgende Kandidaten die entsprechende Position finden können.                                                                                                                        |
| `generate_track` / `replace_section` | `model`                            | Erforderliche Enum-Zeichenfolge                | Optional sind `chirp-v3-5`, `chirp-v4`, `chirp-v4-5`, `chirp-v4-5-plus`, `chirp-v5`, `chirp-v5-5`, `chirp-v6`, `chirp-v6-wild`, `chirp-v6-mini`. Ob das Modell und die Operation verfügbar sind, richtet sich nach dem Endstatus der Aufgabe; es wird nicht automatisch auf andere Modelle gewechselt. |
| `generate_track` / `replace_section` | `start_seconds` / `end_seconds`    | Erforderliche Zahlen, `0 ≤ start_seconds &lt; end_seconds` | Start- und Endsekunden innerhalb des Quellaudios; beim Ersetzen darf der Endpunkt außerdem die tatsächliche Dauer des Quellaudios nicht überschreiten. Sie sind keine Projektbeats und garantieren nicht die Ausgabedauer des Kandidaten.                                                                                                         |
| `generate_track`                     | `render_audio_id`                  | Erforderliche Zeichenfolge                    | `response.data.audio_id` nach einem erfolgreichen `render` des aktuellen Projekts, als Mix-Referenz bei der Generierung.                                                                                                   |
| `generate_track`                     | `stem_control_tags`                | Erforderliche Zeichenfolge                    | Beschreibung der neuen Stimme, beispielsweise `add Piano`, `add Drums`, `add Bass`; keine feste Enum.                                                                                                      |
| `generate_track`                     | `batch_size`                       | Optionale ganze Zahl 1–4, Standard 2          | Anzahl der angeforderten zu generierenden Kandidaten.                                                                                                                                                |
| `generate_track`                     | `instrumental` / `vocal_gender`    | Optionaler boolescher Wert／Enum-Zeichenfolge  | `instrumental` ist standardmäßig `true`; die Gesangspräferenz kann `f`, `m`, `unspecified` sein, standardmäßig `unspecified`. Ob die Präferenz befolgt wird, richtet sich nach dem tatsächlichen Audio.                                                                     |
| `generate_track` / `replace_section` | `title` / `tags` / `negative_tags` | Optionale Zeichenfolge                        | Kandidatentitel, Beschreibung des gewünschten Stils, Stil-Tags, die vermieden werden sollen. Wenn `tags` und `negative_tags` weggelassen werden, übergeben Sie leere Zeichenfolgen.                                                                                                  |
| `generate_track`                     | `prompt`                           | Optionale Zeichenfolge                        | Text- oder Liedtext-Prompt für die neue Stimme; bei reiner Instrumentalmusik kann er weggelassen werden.                                                                                                                                       |
| `replace_section`                    | `prompt` / `replacement_lyrics`    | Optionale Zeichenfolge                        | Ersteres ist der Liedtext oder Kontexttext des Originalsongs, letzteres ist der neue Liedtext für den zu ersetzenden Bereich; wenn weggelassen, übergeben Sie leere Zeichenfolgen.                                                                                                                      |
| `replace_section`                    | `fixed`                            | Optionaler boolescher Wert, Standard `false`   | Fordert einen Ersatz mit fester Länge an; bei `true` muss der Bereich kürzer als 26 Sekunden sein, und das ausgewählte Modell unterstützt ihn möglicherweise nicht. Das reale Beispiel dieses Mal verwendet den Standardmodus, `fixed=true` wurde noch nicht verifiziert.                                                                                    |
| `commit_candidate`                   | `operation_id` / `candidate_id`    | Erforderliche Zeichenfolge                    | Entnehmen Sie diese jeweils aus `data.operation_id` des Generierungsendstatus und der ausgewählten `data.candidates[].id`; der Kandidat muss zur aktuellen Projektversion gehören.                                                                                    |
| `commit_candidate`                   | `track_id`                         | Erforderliche Zeichenfolge                    | Kandidaten für neue Spuren sollten auf der **vor der Generierung gespeicherten leeren Spur** eingereicht werden; Kandidaten für lokalen Ersatz werden auf der Originalspur eingereicht, die das einzige Quellsegment enthält.                                                                                                              |
| `commit_candidate`                   | `start_beats` / `end_beats`        | Nur für Kandidaten neuer Spuren optionale nichtnegative Zahlen | Legt die Position des neuen Segments auf der Projekt-Timeline fest; wenn weggelassen, wird der Startpunkt des Quellsegments übernommen und der Endpunkt anhand der tatsächlichen Kandidatendauer berechnet. Es darf sich nicht mit vorhandenen Segmenten der Zielspur überschneiden. **Kandidaten für lokalen Ersatz müssen weggelassen werden**.                                                                                      |
| `commit_candidate`                   | `name` / `gain`                    | Nur für Kandidaten neuer Spuren optionale Zeichenfolge／nichtnegative Zahl | Name des generierten Segments und Lautstärkefaktor, `gain` ist standardmäßig 1.                                                                                                                                  |
| `render`                             | `title`                            | Erforderliche Zeichenfolge                    | Titel des exportierten Audios.                                                                                                                                                   |
| `render`                             | `lyrics` / `tags`                  | Optionale Zeichenfolge                        | Liedtext und Stilbeschreibung beim Export; der Liedtext ist standardmäßig `[Instrumental]`.                                                                                                                      |
| `render`                             | `start_beats` / `end_beats`        | Optionale nichtnegative Zahlen, Ende muss größer als Start sein | Exportiert den Projektbeat-Bereich; wenn weggelassen, werden der früheste Startpunkt und der späteste Endpunkt aller hörbaren Segmente verwendet. Stille Segmente werden nicht berücksichtigt; bei vorhandenen Solo-Spuren werden nur die Solo-Spuren ausgewählt.                                                                                             |

Die Generierung erzeugt nur Kandidaten, **sie werden nicht automatisch in das Projekt eingefügt**. `commit_candidate` prüft, ob der Kandidat weiterhin zur aktuellen Version gehört. Kandidaten für lokalen Ersatz können nur dann automatisch eingereicht werden, wenn ihre tatsächliche Dauer zuverlässig mit dem vollständigen Quellaudio oder dem ausgewählten Bereich abgeglichen werden kann; bei Nichtübereinstimmung bleibt das Originalprojekt erhalten und gibt einen Fehler zurück, ein erzwungenes Zusammenfügen durch manuelles Raten von Beats ist nicht möglich.

## 2026-10-09 Reale Anfragen und Antworten

Die folgenden Anfragetexte und Antwortfelder stammen alle aus realen Aufrufen desselben Projekts. Jede JSON-Gruppe besteht der Reihe nach aus Anfrage, Annahmeantwort (falls asynchron) und Antwort zum Aufgabenendstatus. Zur besseren Lesbarkeit enthalten die Antworten nur die für diesen Ablauf erforderlichen Felder; Konto-, Nutzungs- und Zeitaufwandsfelder werden nicht angezeigt. Die Beispiel-IDs gehören zu dieser Testanwendung; bei der Integration müssen die IDs aus den eigenen Anfragen und ein neuer `Idempotency-Key` verwendet werden.

### 1. Leeres Projekt erstellen und lesen: `create`, `retrieve`

`create`-Anfrage:

```json
{
  "action": "create",
  "title": "Suno Projects Documentation Verification 2026-10-09"
}
```

```json
{
  "success": true,
  "trace_id": "42408a82-988b-4127-ba68-9b89348a7c56",

        "bps": 2
```

### 5. Leere Spur zum Empfangen von Kandidaten speichern

Die Kandidaten von `generate_track` sind an die aktuelle Projektversion gebunden. Dieses Mal wird zunächst der **vollständige** über `retrieve` erhaltene `state` als Grundlage verwendet, die folgende echte leere Spur wird zu `state.tracks` hinzugefügt und dann mit `save` gespeichert; andere vorhandene Felder bleiben unverändert:

```json
{
  "id": "bdec15b5-ce96-43fa-b681-26298e013b06",
  "type": "audio",
  "name": "Generated piano",
  "clips": [],
  "takeLanes": [],
  "mute": false,
  "solo": false,
  "amplitude": 1,
  "instrument": {
    "type": "song"
  },
  "color": "#7251F7"
}
```

```json
{
  "success": true,
  "task_id": "783f8d49-cc59-4a65-9f9d-ca00e7d7b8a9",
  "trace_id": "0a9c8f13-7e4f-4915-8a40-010ce4ac61dc",
```

```json
  "version_id": "cb0a82c9-aa5b-48cc-9395-0528675fc18d",
```
