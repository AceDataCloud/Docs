Die Suno Studio-Projekt-API verwaltet mehrspurige Musikprojekte über einen einzigen Einstiegspunkt:

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
```

Das `action` in der Anfrage bestimmt den Operationstyp. Der Project-Primärschlüssel verwendet einheitlich `id`; `version_id` bezeichnet die aktuelle Projektversion. Alle Änderungs- und Exportoperationen müssen die neueste Version übermitteln, um Überschreibungen durch Parallelität zu vermeiden.

## Operationsübersicht

| action             | Modus  | Zweck                      |
| ------------------ | --- | ----------------------- |
| `create`           | synchron  | Leeres Projekt erstellen                   |
| `retrieve`         | synchron  | Projekt und vollständigen bearbeitbaren `state` lesen      |
| `save`             | synchron  | Vollständigen Projektstatus speichern                |
| `upload`           | asynchron  | Material, das zum Projekt hinzugefügt werden kann, über eine HTTPS-Audioadresse initialisieren |
| `add_track`        | asynchron  | Vorhandenes Audio zum Projekt hinzufügen               |
| `generate_track`   | asynchron  | Neue Audiospur-Kandidaten für einen angegebenen Bereich generieren            |
| `replace_section`  | asynchron  | Kandidaten für lokalen Ersatz generieren                |
| `commit_candidate` | asynchron  | Den ausgewählten Kandidaten im Projekt übernehmen             |
| `remove_track`     | synchron  | Angegebene Spur löschen                  |
| `render`           | asynchron  | Gespeicherte Version als vollständigen Song exportieren           |

Asynchrone Operationen geben sofort `task_id` zurück. Verwenden Sie die kostenlose `/suno/tasks`-Schnittstelle zum Polling oder übergeben Sie `callback_url`, um Ergebnisse im Endzustand zu empfangen.

## Erstellen und Lesen

```json
{"action":"create","title":"My Studio Project"}
```

Alle Änderungsoperationen sollten einen eindeutigen `Idempotency-Key`-Header senden. Nach erfolgreicher Erstellung ist `data.id` in der Antwort die Project-ID.

```json
{"action":"retrieve","id":"PROJECT_ID"}
```

Die Leseantwort enthält den vollständigen `state`. Es wird empfohlen, zuerst zu lesen, dann basierend auf den Rückgabewerten zu ändern und zu speichern; konstruieren Sie interne Takt- und Spurstrukturen nicht manuell von Grund auf.

## Vollständigen Status speichern

```json
{
  "action":"save",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "title":"Edited Project",
  "state":{"tracks":[],"timing":{}}
}
```

Falls sich die Version bereits geändert hat, gibt die Schnittstelle HTTP 409 zurück. Führen Sie dann erneut `retrieve` aus, führen Sie die Änderungen zusammen und übermitteln Sie sie anschließend mit einem neuen Idempotenzschlüssel; wiederholen Sie die alte Anfrage nicht blind.

## Spuren hochladen und hinzufügen

```json
{
  "action":"upload",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "audio_url":"https://cdn.example.com/reference.mp3",
  "async":true
}
```

Nach Abschluss des Uploads gibt das Aufgabenergebnis die Kandidaten-`audio_id` zurück. Fügen Sie sie anschließend zum Projekt hinzu:

```json
{
  "action":"add_track",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "audio_id":"AUDIO_ID",
  "name":"Backing Vocals"
}
```

## Generieren und Ersetzen

`generate_track` generiert Audiospur-Kandidaten für einen Projektbereich; `replace_section` gibt zwei Kandidaten für lokalen Ersatz zurück. Beide Operationen wählen keine künstlerischen Ergebnisse automatisch aus.

```json
{
  "action":"replace_section",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "source_audio_id":"AUDIO_ID",
  "start_seconds":35.12,
  "end_seconds":48.76,
  "model":"chirp-v6",
  "replacement_lyrics":"新的歌词片段",
  "async":true
}
```

Nach Auswahl eines Kandidaten übernehmen:

```json
{
  "action":"commit_candidate",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "operation_id":"OPERATION_ID",
  "candidate_id":"CANDIDATE_ID",
  "track_id":"TRACK_ID"
}
```

Kandidaten sind an die Projektversion zum Zeitpunkt der Generierung gebunden. Wenn sich das Projekt bereits geändert hat, können alte Kandidaten nicht direkt übernommen werden.

## Vollständigen Song exportieren

```json
{
  "action":"render",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "title":"Final Mix",
  "lyrics":"[Instrumental]",
  "async":true,
  "callback_url":"https://example.com/webhooks/suno"
}
```

Der Server liest den maßgeblichen Projektstatus der angegebenen Version und stellt die Exportparameter zusammen. Das Ergebnis im Endzustand enthält `render_id`, `audio_id`, `audio_url` und die Dauer. Das Projekt ist an die Ausführungsumgebung bei der Erstellung gebunden und kann nicht umgebungsübergreifend migriert oder automatisch auf Failover umgeschaltet werden.

> Sie dürfen nur Audio hochladen oder verarbeiten, für das Sie ein rechtmäßiges Nutzungsrecht besitzen. Die Projekt-API befindet sich derzeit in der Beta-Phase; bitte persistieren Sie die finalen Audio-URLs in wichtigen Ergebnissen.
