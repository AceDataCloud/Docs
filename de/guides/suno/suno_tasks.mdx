Die Hauptfunktion der Suno Tasks API besteht darin, den Ausführungsstatus einer Aufgabe abzufragen, indem die Aufgaben-ID eingegeben wird, die von der Suno Audios Generation API oder der Suno Lyrics Generation API generiert wurde.

Dieses Dokument wird die Integrationsanleitung der Suno Tasks API detailliert vorstellen und Ihnen helfen, diese API einfach zu integrieren und ihre leistungsstarken Funktionen vollständig zu nutzen. Über die Suno Tasks API können Sie einfach den Ausführungsstatus der Aufgaben der Suno Lyrics Generation API oder der Suno Audios Generation API abfragen.

## Antragsprozess

Um die Suno Audios Generation API zu verwenden, rufen Sie zunächst die [Ace Data Cloud Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihr API-Token zu erhalten und es als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zu dieser Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, es ist nicht erforderlich, für jeden Dienst separat einen Antrag zu stellen.** Beim ersten Antrag wird ein kostenloses Guthaben verschenkt, das kostenlos ausprobiert werden kann; bei unzureichendem Guthaben können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Anfragebeispiel

Die Suno Tasks API kann verwendet werden, um die Ergebnisse der beiden APIs Suno Audios Generation API und Suno Lyrics Generation API abzufragen. Informationen dazu, wie die Suno Audios Generation API verwendet wird, finden Sie in der Dokumentation [Suno Audios Generation API ](https://platform.acedata.cloud/documents/suno-audios-integration). Informationen dazu, wie die Suno Lyrics Generation API verwendet wird, finden Sie unter [Suno Lyrics Generation API ](https://platform.acedata.cloud/documents/suno-lyrics-generation-integration).

Wir nehmen eine von dem Dienst Suno Audios Generation API zurückgegebene Aufgaben-ID als Beispiel, um zu demonstrieren, wie diese API verwendet wird. Angenommen, wir haben eine Aufgaben-ID: eae26f89-b64b-404d-a80c-761996660b1c, im Folgenden wird demonstriert, wie durch die Übergabe einer Aufgaben-ID.

### Anfrage-Header und Anfrage-Body festlegen

**Request Headers** umfassen:

- `accept`: Gibt an, dass Antwortergebnisse im JSON-Format empfangen werden sollen, hier wird `application/json` eingetragen.
- `authorization`: Der Schlüssel zum Aufrufen der API, nach der Beantragung kann er direkt über die Auswahlliste ausgewählt werden.

**Request Body** umfasst:

- `id`: Die hochgeladene Aufgaben-ID.
- `action`: Die Art der Operation für die Aufgabe.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/suno/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "eae26f89-b64b-404d-a80c-761996660b1c",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/suno/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "eae26f89-b64b-404d-a80c-761996660b1c",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Das Rückgabeergebnis enthält insgesamt mehrere Felder. Das Feld `request` ist der Request Body beim Starten der Aufgabe, während das Feld `response` der nach Abschluss der Aufgabe zurückgegebene Response Body ist. Die Feldbeschreibungen lauten wie folgt.

- `id`, die ID der Aufgabe zur Generierung dieses Songs, die zur eindeutigen Kennzeichnung dieser Songgenerierungsaufgabe verwendet wird.
- `request`, die Anfrageinformationen in der Abfrage der Songaufgabe.
- `response`, die Rückgabeinformationen in der Abfrage der Songaufgabe.
- `created_at`, die Erstellungszeit der Aufgabe, Unix-Zeitstempel (Sekunden, Fließkommazahl).
- `started_at`, die Startzeit der Aufgabenausführung, Unix-Zeitstempel (Sekunden, Fließkommazahl).
- `finished_at`, die Abschlusszeit der Aufgabe, Unix-Zeitstempel (Sekunden, Fließkommazahl). Dieses Feld wird nicht zurückgegeben, wenn die Aufgabe nicht abgeschlossen ist.
- `elapsed`, die Ausführungsdauer der Aufgabe, in Sekunden (Fließkommazahl, auf 3 Dezimalstellen gerundet). Dieses Feld wird nicht zurückgegeben, wenn die Aufgabe nicht abgeschlossen ist.

## Stapelabfrageoperation

Dies dient zur Abfrage der Details von Songaufgaben anhand mehrerer Aufgaben-IDs. Der Unterschied zu oben besteht darin, dass `action` als `retrieve_batch` ausgewählt werden muss.

**Request Body** umfasst:

- `ids`: Das Array der hochgeladenen Aufgaben-IDs.
- `action`: Die Operationsmethode für die Aufgaben.

## Fehlerbehandlung

Wenn beim Aufrufen der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechenden Informationen zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort

```json
{
  "success": false,

    "message": "fetch failed"
```
