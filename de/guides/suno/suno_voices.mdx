SUNO ermöglicht es uns, über beliebige Audiodateien benutzerdefinierte Stimmcharaktere zu erstellen und Sprachklonierung für die Musikgenerierung zu nutzen. Im Gegensatz zur bestehenden Persona-API (die von Suno generierte `audio_id` verwendet) akzeptiert diese API eine öffentlich zugängliche `audio_url`, also Ihre eigene Stimmaufnahme. Dieses Dokument erläutert die Integrationsmethode der Sprachklon-API.

Auf der Erstellungsstrecke, die Klangfarbenabfragen unterstützt, kann die `persona_id` aus dem Erstellungsergebnis mit der ursprünglichen Anwendung und der Identität des Aufrufers an `POST /suno/availability` übergeben werden. Wenn das verknüpfte Konto online ist, wird `data.available=true` zurückgegeben; bei bestätigter Offline-Situation wird `data.available=false` zurückgegeben. [Leitfaden zur Abfrage der Klangfarbenverfügbarkeit](https://platform.acedata.cloud/documents/suno-availability-integration)

## Schritt 1: Stimmcharakter erstellen

Abrechnung: Nach erfolgreicher Erstellung eines Stimmcharakters beträgt die Standardgebühr pro Anfrage **0.15 Credits**. Anwendbare Verbrauchsrabatte richten sich nach der tatsächlichen Rechnung, fehlgeschlagene Anfragen werden nicht berechnet.

Diese API hat drei Eingabeparameter: `audio_url` (erforderlich), eine öffentlich zugängliche URL zu einer Audiodatei im MP3- oder WAV-Format, die eine klare Einzelstimme enthält; `name` und `description` (optional), der Name und die Beschreibung des Stimmcharakters.

> **Anforderungen an die Audiodatei**
> - Das Audioformat muss `WAV` oder `MP3` sein
> - Die Audiodauer muss zwischen `10~240 Sekunden` liegen; empfohlen werden saubere, trockene Einzelstimmaufnahmen von `30~60 Sekunden`
> - Das Audio sollte **klare, erkennbare Einzelsprecher- oder Einzelgesangsstimmen** enthalten
> - Vermeiden Sie unbedingt **Hintergrundgeräusche, Begleitung, Echo und Hall**; vollständige Songs mit Begleitung bestehen die Stimmabdruckprüfung in der Regel nicht
> - Es dürfen keine **mehreren Sprecher** oder **mehrstimmigen Stimmen** enthalten sein
> - Material mit zu niedriger Lautstärke, unklarer Sprache oder übermäßig starkem Rauschen kann zu **fehlgeschlagenem Klonen** oder **schlechteren Generierungsergebnissen** führen
> **Hinweise zu Nutzungsbeschränkungen**
> - Durch das Hochladen von Audio erstellte Stimmcharaktere sind **private Ressourcen**
> - Dieser Stimmcharakter **unterstützt keine kontoübergreifende Wiederverwendung**
> - Es wird empfohlen, ihn nach erfolgreicher Erstellung möglichst bald zu verwenden; bei längerer Nichtverwendung kann er **ungültig oder nicht verfügbar** werden
> - Das zurückgegebene `name` wird automatisch vom System generiert; maßgeblich ist die zurückgegebene `persona_id`

> **Fehler anhand eindeutiger Wiederholungskennzeichen behandeln**
> `retryable` im Fehlerobjekt ist ein optionales boolesches Feld. Wenn `error.retryable` `true` ist, bedeutet dies, dass dieser Fehler erlaubt, dieselben Materialien und Parameter später erneut anzufragen. Eindeutig nicht angenommene Dienstüberlastung oder teilweise temporäre Fehler bei der Stimmabdruckprüfung können dieses Kennzeichen tragen; es wird empfohlen, Backoff-Intervalle zu verwenden und die Anzahl der Wiederholungen zu begrenzen.
> Wenn `retryable` `false` ist oder das Feld fehlt, senden Sie nicht allein aufgrund von HTTP 500, `busy` oder Fehlermeldungstexten automatisch erneut. Probleme mit Format, Dauer, Klarheit, wiederholten Aufnahmen und Inhaltsprüfung sollten zuerst korrigiert werden; bei Übermittlungs-Timeouts, unterbrochenen Verbindungen oder unklaren Erstellungsergebnissen sollte vorrangig der ursprüngliche `task_id` zur Abfrage der Aufgabe verwendet werden, um doppelte Klangerstellungen zu vermeiden. Fehlgeschlagene Anfragen werden nicht berechnet, erfolgreiche Wiederholungsanfragen werden nach den normalen Regeln berechnet.

```bash
curl -X POST 'https://api.acedata.cloud/suno/voices' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3",
  "name": "My Voice",
  "description": "单人清晰人声示例"
}'
```

> Das obige `https://cdn.acedata.cloud/suno_demo.mp3` ist Beispielmaterial, das direkt aufgerufen werden kann (MP3, 41 Sekunden, trockene Einzelstimme).
> Falls ein Beispiel im `WAV`-Format benötigt wird, kann
> `https://cdn.acedata.cloud/uploads/82d23b97-ec1c-4b41-91b8-989fc51f8765` verwendet werden (WAV, 41 Sekunden, Mono 44.1kHz).

Das Ergebnis lautet wie folgt:

```json
{
  "success": true,
  "task_id": "0fa609a6-c8d9-4bb5-8574-e4c93bb55d02",
  "data": {
    "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16",
    "name": "VOICE_20260803037676",
    "is_public": false
  }
}
```

Wie ersichtlich ist, ist das Feld `persona_id` in `data` die ID des erstellten Stimmcharakters. Das Feld `is_public` ist immer `false`, da durch das Hochladen von Audio erstellte Stimmcharaktere privat sind. Beachten Sie, dass das zurückgegebene `name` automatisch vom System generiert wird; verwenden Sie anschließend `persona_id`, um auf diesen Stimmcharakter zu verweisen.

## Schritt 2: Mit dem Stimmcharakter Musik generieren

Nach Erhalt der Stimmcharakter-ID können wir die [Suno Audios Generation API](https://platform.acedata.cloud/documents/suno-audios) zur Musikgenerierung verwenden. Setzen Sie `action` auf `generate` und `persona_id` auf die oben zurückgegebene Stimmcharakter-ID; die generierten Songs werden mit der geklonten Stimme gesungen.

> **Hinweis:** Sprachklonierung unterstützt nur Modelle ab `chirp-v4-5` (wie `chirp-v4-5`, `chirp-v5`, `chirp-v5-5`) und unterstützt `chirp-v4` nicht.

```bash
curl -X POST 'https://api.acedata.cloud/suno/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "chirp-v5-5",
  "prompt": "A warm synth-pop song about city nights",
  "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16"
}'
```

Das Ergebnis lautet wie folgt:

```json
{
  "success": true,
  "task_id": "53d8a334-a972-43c5-895e-60c4454e88d5",
  "data": [
    {
      "id": "16463960-077c-4700-bbb3-3c7897b943d3",
      "title": "Soft Neon on My Skin",
      "audio_url": "https://cdn.acedata.cloud/assets/examples/fish/5ade0339-5f11-487e-aacc-06a908271706-8e3fcb0e5547.mp3",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "model": "chirp-v5-5",
      "state": "succeeded",
      "prompt": "A warm synth-pop song about city nights",
      "duration": 156.28
    }
  ]
}
```

`persona_id` kann für die `generate`-Generierung sowie für `cover` / `upload_cover`-Coverversionen verwendet werden. Bei Angabe einer Stimme muss `vocal_gender` nicht gleichzeitig ausgefüllt werden; die Stimmähnlichkeit hängt weiterhin vom Referenzmaterial und dem Generierungsergebnis ab.

Über diese Schnittstelle erstellte Stimmen sind private Ressourcen. Rufen Sie vor dem Covern eines bestehenden Songs zunächst `/suno/upload` auf und übergeben Sie die `audio_url` des Originalsongs sowie die `persona_id` dieser Stimme; nach erfolgreichem Upload rufen Sie `/suno/audios` mit der zurückgegebenen `data.audio_id` und derselben `persona_id` auf:
```json
{
  "action": "upload_cover",
  "model": "chirp-v6",
  "audio_id": "<与该声音关联上传后返回的 audio_id>",
  "persona_id": "<声音创建接口返回的 persona_id>",
  "custom": true,
  "instrumental": false,
  "lyric": "[Verse]\n填写要演唱的歌词",
  "async": true
}
```

Das Erstellen einer Stimme, das Hochladen des Originalsongs und das Erstellen eines Covers müssen denselben Servicekanal verwenden. Bitte verwenden Sie nicht direkt zuvor verwendete Song-IDs wieder, die nicht mit dieser privaten Stimme verknüpft sind; Einzelheiten finden Sie unter [Suno-Referenzaudio hochladen](https://platform.acedata.cloud/documents/suno-upload).
