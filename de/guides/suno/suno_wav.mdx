SUNO ermöglicht es uns, Musikdateien im WAV-Format zu erhalten. Dieses Dokument erklärt die Integration der entsprechenden API.

Der zentrale Eingabeparameter dieser API ist `audio_id`, die offizielle, generierte Song-ID; optional wird auch eine asynchrone Rückrufadresse `callback_url` unterstützt.

Hier verwenden wir als Eingabe `audio_id` den Wert `4e43116a-bf09-472c-8e1c-655eabf02682`.

```python
import requests

url = "https://api.acedata.cloud/suno/wav"

headers = {
    "accept": "application/json",
    "authorization": "Bearer aa287fa4cc54401087a9fab3f99630af",
    "content-type": "application/json"
}

payload = {
    "audio_id": "4e43116a-bf09-472c-8e1c-655eabf02682"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Das Ergebnis sieht wie folgt aus:

```json
{
  "success": true,
  "task_id": "6a5a2099-d6d3-4930-9709-a30ac5dc7de5",
  "trace_id": "3fa70e81-6bb7-4ca8-b718-dd16a4eda7e8",
  "data": [
    {
      "file_url": "https://platform.cdn.acedata.cloud/suno/6a5a2099-d6d3-4930-9709-a30ac5dc7de5.wav"
    }
  ]
}
```

Man sieht, dass das Feld `file_url` in `data` die URL zur Musikdatei im WAV-Format enthält. Diese ist eine öffentlich zugängliche CDN-Adresse.

> **Zur Persistenz des WAV-Links**
>
> Die WAV-Dateien auf dem upstream Suno CDN (`https://cdn1.suno.ai/{audio_id}.wav`) werden nur für einige Tage gespeichert und danach gelöscht; der Zugriff führt dann zu einem 403-Fehler.
> Um einen Linkverfall zu vermeiden, wird die Datei vor der Rückgabe automatisch auf unser eigenes CDN (`https://platform.cdn.acedata.cloud/suno/{task_id}.wav`) übertragen. Die zurückgegebene `file_url` ist somit eine stabile Adresse und verfällt nicht durch das Ablaufdatum des upstream CDN.
> Sollte die Übertragung fehlschlagen (sehr selten), wird auf die ursprüngliche upstream URL zurückgegriffen, was dem bisherigen Verhalten entspricht.
