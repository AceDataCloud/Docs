Mit der zunehmenden Verbreitung von KI-Anwendungen sind verschiedene KI-Programme allmählich populär geworden. KI ist schrittweise in alle Aspekte des Arbeits- und Alltagslebens der Menschen vorgedrungen. Und die Branchen, die von KI betroffen sind, werden immer vielfältiger, vom anfänglichen Schreiben über Medizin und Bildung bis hin zur heutigen Musik.

Suno ist eine professionelle, hochwertige Plattform für KI-Songs und Musikproduktion. Benutzer müssen lediglich einfache Text-Prompt-Wörter eingeben, um basierend auf Genre-Stil und Songtexten Songs mit Gesang zu generieren. Dieser KI-Musikgenerator wurde von Teammitgliedern bekannter Technologieunternehmen wie Meta, TikTok und Kensho entwickelt und hat das Ziel, dass keine Instrumente oder Werkzeuge benötigt werden, damit jeder wunderbare Musik schaffen kann.

> Die `lyric`- und `style`-Beschränkungen in der obigen Tabelle sind die Obergrenzen im benutzerdefinierten Modus (`custom` ist `true`). Im nicht benutzerdefinierten Inspirationsmodus (`custom` ist `false`) wird nur `prompt` ausgefüllt, dessen Längenobergrenze bei 500 Zeichen liegt (bei allen Modellen gleich).

Suno unterstützt jetzt `chirp-v6`, `chirp-v6-wild` und `chirp-v6-mini`. Die Verwendung von `chirp-v6` wird empfohlen; alte Modellnamen bleiben weiterhin kompatibel.

Suno selbst bietet jedoch keine offizielle API an. AceDataCloud stellt eine Reihe von Suno-APIs bereit, die die offizielle Suno-Anbindung simulieren und die gewünschte Musik bequem und schnell generieren können.

## Beantragung und Nutzung

Um die Suno Audios Generation API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten und ihn als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Bei der ersten Beantragung wird ein kostenloses Kontingent verschenkt, das kostenlos ausprobiert werden kann; wenn das Kontingent nicht ausreicht, kann in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufgeladen werden.

> 📘 Vollständige Dokumentation: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Grundlegende Verwendung

An welche Songs Sie auch denken, Sie können beliebig einen Text eingeben. Wenn ich beispielsweise einen Song über Weihnachten generieren möchte, kann ich `a song for Christmas` eingeben, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Hier sehen wir, dass wir die Request Headers festgelegt haben, einschließlich:

- `accept`: Welches Format der Antwort empfangen werden soll; hier wird `application/json` eingetragen, also das JSON-Format.
- `authorization`: Der Schlüssel zum Aufrufen der API, der nach der Beantragung direkt über das Dropdown-Menü ausgewählt werden kann.

Außerdem wurde der Request Body festgelegt, einschließlich:
- `action`: Typ der Audioaufgabe, standardmäßig `generate`. Unterstützt Vorgänge wie Generieren, Fortsetzen, Cover, Zusammenfügen, Stem-Trennung, Hinzufügen von Audiospuren, Extrahieren bestimmter Audiospuren, Generieren von Soundeffekten und Anpassen der Geschwindigkeit, einheitlich aufgerufen über `POST /suno/audios`.
- `prompt`: Sunos offizieller Prompt für den Inspirationsmodus (wirksam, wenn `custom` `false` ist), maximal 500 Zeichen.
- `model`: Das Modell für diese Musikgenerierungsaufgabe. Die v6-Serie umfasst `chirp-v6`, `chirp-v6-wild` und `chirp-v6-mini`; alte Modellnamen bleiben kompatibel.
- `max_mode`: Erweiterter Generierungsmodus. `generate` wird nur aktiviert, wenn sowohl `custom` als auch `max_mode` `true` sind, die Kosten betragen 1.12 Credits; `add_stem` kann direkt aktiviert werden, die Kosten betragen 1.344 Credits. Wenn deaktiviert oder ausgelassen, betragen sie jeweils 0.56 und 0.672 Credits.
- `variety`: Intensität der Vielfalt der Generierungsergebnisse, optional `off`, `normal`, `high`, `extra`, `max`. Nur für `generate` und `add_stem`; die Übergabe bei anderen actions gibt 400 zurück.
- `lyric`: Liedtextinhalt für Sunos offiziellen benutzerdefinierten Modus. Für `chirp-v3-5` und `chirp-v4` maximal 3000 Zeichen; für `chirp-v4-5` und höher (einschließlich `chirp-v5`, `chirp-v5-5`) maximal 5000 Zeichen.
- `custom`: Ob der benutzerdefinierte Modus verwendet wird, standardmäßig: `false`.
- `instrumental`: Die Option für reine Instrumentalmusik im offiziellen Inspirationsmodus von Suno.
- `title`: Musiktitel für Sunos offiziellen benutzerdefinierten Modus. Für `chirp-v3-5`, `chirp-v4` maximal 80 Zeichen; für `chirp-v4-5` und höher maximal 100 Zeichen.
- `style`: Musikstil für Sunos offiziellen benutzerdefinierten Modus. Für `chirp-v3-5` und `chirp-v4` maximal 200 Zeichen; für `chirp-v4-5` und höher (einschließlich `chirp-v5`, `chirp-v5-5`) maximal 1000 Zeichen.
- `negative_tags`: Musikstile oder Genres, die bei der benutzerdefinierten Generierung ausgeschlossen werden sollen; kann auch für `replace_section` verwendet werden. Diese Schnittstelle hat derzeit keine feste Obergrenze für die Zeichenanzahl dieses Felds; zu lange Inhalte können dennoch möglicherweise nicht verarbeitet werden, daher wird empfohlen, die Beschreibung kurz zu halten.
- `audio_weight`: Einflussgewicht von Audio- oder Stimmmerkmalen, Bereich 0–1, wobei auch `0` ein gültiger Wert ist. Kann für Vorgänge wie Generierung, Fortsetzen, Cover, Hinzufügen von Audiospuren und Stimmkonsistenz verwendet werden; ohne Referenzaudio oder Stimmmerkmale kann das Modell diesen Wert abschwächen oder ignorieren.
- `audio_id`: ID der Referenzmusik, verwendet für Folgeoperationen wie Cover, Fortsetzen und Stem-Trennung. Audiodateien können weiterhin heruntergeladen werden, dies bedeutet jedoch nicht, dass die Nachverarbeitung dieser ID stets verfügbar ist; wenn `suno_processing_unavailable` zurückgegeben wird, bewahren Sie bitte `task_id` und `trace_id` auf und kontaktieren Sie den Support.
- `overpainting_start`/`overpainting_end`: Start- und Endzeit zum Ergänzen von Gesang zu bestehender reiner Instrumentalmusik, in Sekunden.
- `underpainting_start`/`underpainting_end`: Start- und Endzeit zum Hinzufügen einer Begleitung zu A-cappella-Gesang, in Sekunden.
- `persona_id`: Die über die Persona- oder Stimmerstellungs-Schnittstelle erhaltene Stimm-ID, nicht die `audio_id` eines Lieds.
- `continue_at`: Grenze für das Fortsetzen, in Sekunden. Beispielsweise bedeutet 213.5, dass nachfolgende Abschnitte ab 3 Minuten und 33.5 Sekunden generiert werden. `lyric` und `style` leiten nur neue Inhalte nach der Grenze an und ersetzen weder den Liedtext noch den Gesang vor der Grenze im Quellaudio.
- `style_influence`: Stileinfluss im benutzerdefinierten Modus, Bereich 0–1; je höher, desto stärker entspricht das Ergebnis in der Regel dem ausgewählten Stil; `0` wird als gültiger Wert übergeben.
- `replace_section_end`: Endzeit des zu ersetzenden Abschnitts.
- `replace_section_start`: Startzeit des zu ersetzenden Abschnitts.
- `vocal_gender`: Steuert die Präferenz für weibliche oder männliche Stimmen, weibliche Stimme `f`, männliche Stimme `m`; wirksam für Modelle 4.5 und höher; ist eine Präferenz und garantiert keine strikte Einhaltung.
- `weirdness`: Grad der Skurrilität im benutzerdefinierten Modus, Bereich 0–1; je höher, desto kreativer und experimenteller ist das Ergebnis in der Regel; `0` wird als gültiger Wert übergeben.
- `duration`: Gewünschte Lieddauer, in Sekunden, muss eine ganze Zahl sein, Wertebereich von 10 bis 360. Derzeit verwendet nur `generate` diesen Parameter, die konkrete Wirkung hängt vom Modus und Modell ab. Es handelt sich um einen Tendenzhinweis und nicht um eine harte Einschränkung: Das Modell berücksichtigt ihn, garantiert jedoch nicht dessen Erreichen; die tatsächliche Dauer des fertigen Ergebnisses richtet sich nach dem Feld `duration` in der Antwort und ist in der Regel kürzer als der gewünschte Wert.

### Anwendungsbereich der Stimm-ID

`generate`, `cover`, `upload_cover`, `artist_consistency`, `artist_consistency_vox` können `persona_id` verwenden. Die letzten beiden actions müssen `persona_id` bereitstellen; gleichzeitig kann auch die `audio_id` des Lieds bereitgestellt werden, das bei der Erstellung dieser Persona verwendet wurde.

`extend`, `upload_extend` verwenden keine zusätzliche `persona_id`. Ob `mashup`, `inspo` Stimm-IDs unterstützen, hängt vom ausgewählten Servicekanal ab; bei anderen actions ist nicht garantiert, dass dieses Feld angewendet wird, bitte verwenden Sie es gemäß den Beschreibungen der jeweiligen Vorgänge. `vocal_gender` ist eine optionale Geschlechtspräferenz und kann die Stimm-ID nicht ersetzen.

Folgeoperationen für die Erstellung benötigen eine gültige Quell-`audio_id`; `mashup` benötigt mindestens zwei `mashup_audio_ids`. Bei fehlenden notwendigen Quellen oder Zeitparametern wird HTTP 400 zurückgegeben.

### Anwendungsbereich erweiterter Parameter
| Parameter                | Wertebereich                                  | Unterstützte action                              | Beschreibung                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | Optional                                      | Passt die Experimentalität an, `0` ist ein gültiger Wert; der Effekt hängt von Vorgang, Modus und Modell ab      |
| `style_influence` | 0-1                                         | Optional                                      | Passt die Neigung zur Stilbefolgung an, `0` ist ein gültiger Wert; der Effekt hängt von Vorgang, Modus und Modell ab   |
| `audio_weight`    | 0-1                                         | Optional                                      | Passt den Einfluss von Audio- oder Stimmeigenschaften an; ohne Referenzinformationen kann es vom Modell ignoriert werden        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`、`add_stem`                   | Passt die Stilvielfalt zwischen den Ergebnissen an                       |
| `max_mode`        | Boolean                                     | `generate`（erfordert `custom=true`）、`add_stem` | Verbessert die Konsistenz und wird nach dem erweiterten Modus abgerechnet                     |
| `vocal_gender`    | `f` / `m`                                   | Generierungsvorgänge mit unterstützter Stimmsteuerung                             | Präferenzoption, strikte Befolgung wird nicht garantiert                       |
| `duration`        | Ganzzahl 10-360                                   | `generate`                              | Erwartete Dauer; andere action verwenden dieses Feld derzeit nicht, die tatsächliche Länge richtet sich nach dem Ergebnis |

Die Plattform prüft Parametertypen und Wertebereiche, lehnt diese optionalen Anpassungsoptionen jedoch nicht allein aufgrund unterschiedlicher action ab; der konkrete Effekt wird durch Vorgang, Modus und Modell bestimmt.

- `lyric_prompt`: Der Prompt zum Generieren von Liedtexten, wird dann und nur dann wirksam, wenn `custom` `true` ist und `lyric` nicht übergeben wurde.
- `callback_url`: Die URL, an die Ergebnisse zurückgemeldet werden müssen.
- `async`: Optional; wenn auf `true` gesetzt, gibt die Schnittstelle sofort `task_id` zurück, ohne dass `callback_url` bereitgestellt werden muss. Anschließend wird das Ergebnis über die entsprechende Task-Abfrageschnittstelle per Polling abgerufen.

## Benutzerdefinierte Generierung

Wenn Sie Liedtexte benutzerdefiniert generieren möchten, können Sie Liedtexte eingeben:

Zu diesem Zeitpunkt kann das Feld `lyric` ähnliche Inhalte wie die folgenden übergeben:
```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near

Die API ist die [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Als Nächstes möchten wir basierend auf Liedtext, Titel und Stil ein Lied individuell generieren. Dafür können folgende Inhalte angegeben werden:

- lyric: Liedtext
- custom: Auf `true` setzen, bedeutet individuelle Generierung; dieser Parameter ist standardmäßig false, was bedeutet, dass `prompt` zur Generierung verwendet wird.
- title: Der Titel des Liedes.
- style: Der Stil des Liedes, optional.

## Funktion zur individuellen Generierung eines Sängerstils

Wenn du einen Sängerstil zur Generierung eines Liedes verwenden möchtest, generiere zunächst über die oben beschriebene grundlegende Verwendung ein Lied.\
Am Ende erhältst du ein Lied, das als Sängerstil festgelegt werden muss. Anschließend musst du die [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) aufrufen, um anhand der offiziell generierten Musik-ID `audio_id` einen ID-Parameter `persona_id` für einen Sängerstil zu generieren. Die konkreten Parameter sind in der folgenden Abbildung dargestellt:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Nach dem Ausfüllen wird der folgende Code automatisch generiert:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Klicke auf „Ausführen“, dann kannst du feststellen, dass du folgendes Ergebnis erhältst:

```json
{
  "success": true,
  "task_id": "7628b754-4fe7-4e79-bda4-806d0dd8bf6e",
  "data": {
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b"
  }
}
```

Wir verwenden die oben genannten `audio_id` und `persona_id`, nämlich `97efc9f4-0e8d-4b3e-88df-14568fa1b11f` und `e0d7319e-aa2a-44cb-b00a-916218d7cb0b`, jeweils als Beispieldaten für diesen Vorgang. Anschließend kannst du den Parameter `action` auf `artist_consistency` setzen (bei der neuen Sängerstil-Version Persona-v2-vox muss `action` auf `artist_consistency_vox` gesetzt werden) und die ID des Liedes, dessen Generierung fortgesetzt werden soll, sowie die Sängerstil-ID eingeben. Das Ausfüllbeispiel lautet wie folgt:

<p><img src="https://cdn.acedata.cloud/fukijq.png" width="500" className="m-auto" /></p>

Nach dem Ausfüllen wird der folgende Code automatisch generiert:

<p><img src="https://cdn.acedata.cloud/5uzk9d.png" width="500" className="m-auto" /></p>

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "artist_consistency",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b",
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Klicke auf „Ausführen“, dann kannst du feststellen, dass du folgendes Ergebnis erhältst:

```json

## Funktion zur Fortsetzung der Generierung
Wenn Sie einen bereits generierten Suno-Song weitergenerieren möchten, können Sie den Parameter `action` auf `extend` setzen und die ID des Songs eingeben, der weitergeneriert werden soll. Die Song-ID wird gemäß der grundlegenden Verwendung abgerufen. Wie oben zu sehen ist, lautet die Song-ID zu diesem Zeitpunkt:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Hinweis: Die `id` im Text hier ist die ID des nach der Generierung entstandenen Songs. Wenn Sie nicht wissen, wie man Songs generiert, können Sie sich auf die oben beschriebene grundlegende Verwendung beziehen, um einen Song zu generieren.

Wenn Sie einen selbst hochgeladenen Song weitergenerieren möchten, können Sie den Parameter `action` auf `upload_extend` setzen und die ID des benutzerdefiniert hochgeladenen Songs eingeben, der weitergeneriert werden soll. Die Song-ID wird über die [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload) abgerufen, wie in der folgenden Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Als Nächstes müssen die Lyrics des fortzusetzenden Abschnitts ausgefüllt werden, und ein Stil kann angegeben werden:

- lyric: Wird nur verwendet, um die Lyrics des neu generierten Abschnitts nach `continue_at` zu leiten, und ersetzt nicht die Lyrics vor diesem Zeitpunkt im Quellaudio.
- custom: Wenn auf `true` gesetzt, bedeutet dies benutzerdefinierte Generierung. Dieser Parameter ist standardmäßig false, was bedeutet, dass die Generierung mit `prompt` erfolgt.
- style: Der Songstil des fortzusetzenden Abschnitts, optional.
- continue_at: Fortsetzungsgrenze, in Sekunden. Beispielsweise bedeutet 213.5, dass der nachfolgende Abschnitt ab Minute 3 und Sekunde 33.5 generiert wird.

`continue_at` für `extend` und `upload_extend` muss größer als 0 sein und unterstützt Sekundenbruchteile, beispielsweise `30.792`; bei der Übermittlung wird nicht gerundet.

> `extend` wird verwendet, um einen bestehenden Song nach hinten weiterzuschreiben, nicht um den Text des gesamten Songs zu ersetzen. Wenn der gesamte Song von Anfang an mit neuen Lyrics erstellt werden soll, verwenden Sie bitte `generate`, um ihn erneut zu generieren; wenn ein bestehender Song als Referenz neu interpretiert werden soll, kann `cover` verwendet werden. Wenn ein vollständiger neuer Liedtext übergeben wird, werden die ursprünglichen Lyrics vor `continue_at` dennoch nicht ersetzt.

## Musik-Cover

Nach dem weiteren Generieren eines Songs auf Grundlage eines bestehenden Songs ist der Stil des zurückgegebenen Songs möglicherweise nicht ganz passend. Wenn der zuvor generierte Song (auch benutzerdefiniert hochgeladene Musik wird unterstützt) gecovert werden soll, muss die Musik-Cover-Methode verwendet werden. Dabei können die folgenden Inhalte angegeben werden:

- action: Der Inhalt ist `cover`; wenn ein Cover-Vorgang für benutzerdefiniert hochgeladene Musik durchgeführt wird, muss der Inhalt `upload_cover` angegeben werden.
- audio_id: Die ID des zuvor generierten Songs.

Wenn ein Cover mit einer angegebenen Stimme verwendet werden soll, kann gleichzeitig `persona_id` übergeben werden. Über `/suno/voices` erstellte private Stimmen müssen zuerst in `/suno/upload` mit derselben `persona_id` hochgeladen werden; anschließend wird die zurückgegebene `audio_id` für `upload_cover` verwendet. Alle Schritte müssen denselben Servicekanal verwenden. `vocal_gender` muss nicht zusätzlich angegeben werden, da die Geschlechtspräferenz keine Stimm-ID ersetzen kann.

Wenn beispielsweise die ID des zuvor generierten Songs lautet: 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, können die Parameter wie folgt festgelegt werden:

```json
{
  "action": "cover",
  "audio_id": "0a1e1b10-c36a-41c9-9bfb-b26d9d25db98",
  "prompt": "A song for Christmas",
  "model": "chirp-v4-5"
}

## Segment ersetzen

`replace_section` generiert das ausgewählte Segment anhand des Zeitbereichs des Quellsongs neu und fügt das Ergebnis wieder in den Originalsong ein. `replace_section_result_mode` ist standardmäßig `full_song` und gibt 2 vollständige Songs zurück, die direkt abgespielt werden können, ohne dass `concat` erneut aufgerufen werden muss.

### Wie werden die Eingaben ausgefüllt?
- `action`: `replace_section`.
- `audio_id`: Die vollständige Song-ID, die bearbeitet werden soll. Bei einer erneuten Bearbeitung verwenden Sie die `data[].id` des beim letzten Mal ausgewählten vollständigen Songs, nicht die `task_id`.
- `model`: Song-Generierungsmodell, zum Beispiel `chirp-v6`.
- `lyric`: Der **lokale neue Liedtext**, der im ausgewählten Bereich gesungen werden soll. Es ist nicht erforderlich, den gesamten Liedtext zu übergeben, um einen vollständigen Song zu erhalten.
- `prompt`: Gibt den lokalen neuen Liedtext für diese Ersetzung eindeutig an. Beim Ändern des Liedtexts wird empfohlen, denselben Inhalt wie in `lyric` einzutragen, um zu vermeiden, dass die beiden Felder unterschiedliche Liedtexte ausdrücken. Bestehende Anfragen, die nur einen lokalen `lyric` übergeben und `prompt` auslassen, können weiterhin verwendet werden, aber das Ergänzen von `prompt` selbst garantiert keinen Erfolg beim Ändern des Liedtexts.
- `style`, `negative_tags`: Optionale Stilbeschreibungen und Ausschlüsse; `prompt` ist bei dieser Operation keine Inspirationsbeschreibung wie bei der normalen Songerstellung.
- `replace_section_start`, `replace_section_end`: Start- und Endzeit des Auswahlbereichs im Quellsong dieser Bearbeitung, in Sekunden, Dezimalstellen werden unterstützt. Der Startpunkt darf nicht kleiner als 0 sein, der Endpunkt muss größer als der Startpunkt sein und darf die Dauer des Quellsongs nicht überschreiten.
- `replace_section_result_mode`: `full_song` (Standard) gibt 2 vollständige Songs zurück; `candidates` gibt 2 noch nicht zusammengefügte Ersetzungskandidaten zurück.

Verwenden Sie „`lyric` muss der vollständige Liedtext nach der Ersetzung sein, `prompt` muss der lokale Liedtext sein“ nicht als allgemeine Vorgehensweise. Die Eingabe eines vollständigen Liedtexts kann bei einigen Aufgaben zu übermäßig langem Ersetzungsinhalt führen, wodurch der gesamte Song nach dem Zusammenfügen deutlich länger wird. Auch lokale Eingaben garantieren weder eine feste Dauer noch eine wortgetreue Umsetzung des Liedtexts; dies ist generatives Bearbeiten, daher muss das tatsächliche Audio überprüft werden.

### Eine Aufgabe starten und vollständige Songs erhalten

Nachfolgend sehen Sie ein Beispiel für das Anfrageformat. Ersetzen Sie `YOUR_COMPLETED_AUDIO_ID` und den Zeitbereich durch Ihre eigene Quellsong-ID und den tatsächlichen Auswahlbereich; das Beispiel geht davon aus, dass die Sekunden 30–50 den folgenden vier Zeilen entsprechen.

```json
{
  "action": "replace_section",
  "audio_id": "YOUR_COMPLETED_AUDIO_ID",
  "model": "chirp-v6",
  "custom": false,
  "instrumental": false,
  "lyric": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "prompt": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "replace_section_start": 30.0,
  "replace_section_end": 50.0,
  "replace_section_result_mode": "full_song",
  "async": true
}
```

Verwenden Sie nach dem Absenden die zurückgegebene `task_id`, um `/suno/tasks` abzufragen; der Anfragekörper lautet `{"action":"retrieve","id":"YOUR_TASK_ID"}`. Nach Abschluss der Aufgabe erhalten Sie in `response.data` der Aufgabenantwort die `id`, `audio_url` und `duration` der zwei vollständigen Songs. Hören Sie sie an und wählen Sie einen davon aus. `success: true` bedeutet, dass die Aufgabe erfolgreich ausgeführt wurde, nicht dass der neue Liedtext wortgetreu gesungen wurde oder die Dauer den Erwartungen entspricht.

### Auswahlbereich, Ergebnisprüfung und erneute Bearbeitung

1. Hören Sie zuerst den Quellsong an und bestimmen Sie dann mithilfe der Zeitinformationen von `/suno/timing` den Auswahlbereich; versuchen Sie, vollständige musikalische Phrasen abzudecken. Wählen Sie den Bereich nicht anhand fester Indizes im Liedtext-Array aus und erwarten Sie auch nicht, dass der Rhythmus vollständig unverändert bleibt, wenn Sie einen Bereich mit mehreren musikalischen Phrasen durch nur einige Liedtextzeilen ersetzen.
2. Die Anzahl der Zeilen, Zeichen und der Rhythmus des neuen Liedtexts sollten dem ursprünglichen Inhalt des Auswahlbereichs möglichst nahekommen. Auch wenn nur einige Zeichen geändert werden, muss dies durch Anhören überprüft werden; daraus kann kein Erfolg garantiert werden.
3. Prüfen Sie, ob der neue Text im Zielbereich gesungen wird, ob die Übergänge davor und danach natürlich sind und ob die Dauer des gesamten Songs angemessen ist. `full_song` bedeutet, dass vollständige Songs zurückgegeben werden, nicht dass sie dieselbe Länge wie der Originalsong haben; wenn das Ersetzungssegment länger wird, verschiebt sich die zweite Hälfte entsprechend nach hinten. Der Anfrageparameter `duration` wird nur für die normale Generierung verwendet und kann die Dauer des Ersetzungssegments nicht festlegen.
4. Das zurückgegebene `lyric` sind Liedtext-Metadaten. Im vollständigen Song-Modus wird der vollständige Liedtext zusammengestellt, wenn Zeitinformationen zum Quellliedtext verfügbar sind; wenn diese nicht verfügbar sind, kann es leer sein. Es ist keine Audio-Transkription; das Auftreten neuer Wörter beweist nicht, dass der neue Text im Audio gesungen wurde. Auch Zeitabgleichsinformationen sollten zusammen mit dem Anhören überprüft werden, insbesondere bei bereits bearbeiteten Ergebnissen.
5. Bei einer erneuten Bearbeitung verwenden Sie die ausgewählte **vollständige fertige ID** als neue `audio_id` und überprüfen Sie die Dauer und den Auswahlbereich dieses fertigen Ergebnisses erneut. Übernehmen Sie weder die Zeitkoordinaten vor der Bearbeitung noch verwenden Sie direkt das beim letzten Mal zurückgegebene vollständige `lyric` als lokale Eingabe für dieses Mal.

Wenn die Aufgabe abgeschlossen ist, aber weiterhin der alte Text gesungen wird, Text fehlt oder die Dauer deutlich länger wird, überprüfen Sie zuerst die Quellsong-ID, den Auswahlbereich und den lokalen Liedtext und prüfen Sie dann das andere Ergebnis. Eine erhöhte Häufigkeit der Aufgabenabfragen ändert den bereits generierten Inhalt nicht. Falls weiterhin Anomalien auftreten, bewahren Sie `task_id`, Quellsong-ID, Anfragefelder, Auswahlbereich und Ergebnis-Audio zur Überprüfung auf.

### Optional: Zuerst Kandidaten abrufen, dann manuell zusammenfügen

Setzen Sie `replace_section_result_mode: "candidates"` nur dann, wenn Sie Ersetzungskandidaten selbst auswählen müssen. Kandidaten können Kontext enthalten und dürfen nicht allein anhand ihrer Kandidatendauer als vollständige Songs betrachtet werden. Rufen Sie nach der Auswahl mit der `data[].id` des Kandidaten `concat` auf und erhalten Sie dann das vollständige fertige Ergebnis.

Das standardmäßige `full_song` hat das Zusammenfügen bereits abgeschlossen; dieser Schritt muss nicht ausgeführt werden.

## Stimm- und Musiktrennung

Abrechnung: Nach erfolgreichem `action=stems` beträgt die Standardgebühr pro Anfrage **0.56 Credits**; die in derselben Anfrage zurückgegebenen Vocals und Begleitung werden zusammen als ein Vorgang berechnet. Anwendbare Verbrauchsrabatte richten sich nach der tatsächlichen Abrechnung, fehlgeschlagene Anfragen werden nicht berechnet. `all_stems` und `extract_stem` werden jeweils nach ihren eigenen Preisen berechnet.

Wenn nach der Generierung eines Songs für eine sekundäre kreative Bearbeitung Begleitung und Gesang separat bearbeitet werden müssen, können reine Instrumentalbegleitung und A-cappella-Gesang getrennt werden. Folgende Inhalte können angegeben werden:

- action: Der Inhalt ist `stems`.
- audio_id: Die ID des zuvor generierten Songs.

## Stimm-Musik-Trennung aller Spuren

- action：Der Inhalt ist `all_stems`。

```json
{
  "action": "all_stems",

}

## Audiospur extrahieren

`extract_stem` extrahiert die Ziel-Audiospur aus der angegebenen Audiodatei und gibt gleichzeitig die komplementäre Version zurück, aus der diese Audiospur entfernt wurde; der Aufruf erfolgt über `POST /suno/audios`.

- Erforderlich: `action`, `audio_id`, `stem_type`.
- Optional: `audio_format`; der aktuelle öffentliche Zweikanalvertrag unterstützt nur `mp3`.
- Abrechnung: 1.12 Credits.

```json
{
  "action": "extract_stem",
  "audio_id": "dead4ee5-df4d-417b-8f7e-717722fae51a",
  "stem_type": "bass",
  "audio_format": "mp3",
  "async": true

## Steuerung der Songdauer

Standardmäßig wird die Dauer des generierten Songs vom Modell selbst bestimmt und liegt normalerweise zwischen 30 Sekunden und 4 Minuten. Wenn ein längeres oder kürzeres Endprodukt benötigt wird, kann die gewünschte Dauer über den Parameter `duration` angegeben werden; die Einheit ist Sekunden und der Wert ist eine ganze Zahl zwischen 10 und 360.

Dieser Parameter wird für die Songgenerierung im benutzerdefinierten Modus (wenn `custom` `true` ist) verwendet. Besonders zu beachten ist, dass `duration` ein **Tendenzhinweis und keine harte Einschränkung** ist: Das Modell berücksichtigt diesen Wert beim Erstellen, garantiert jedoch nicht, ihn zu erreichen. In Tests war die tatsächliche Dauer normalerweise deutlich kürzer als der gewünschte Wert, und die Dauern der zwei Songs, die von derselben Anfrage zurückgegeben werden, können sich ebenfalls um ein Vielfaches unterscheiden. Selbst bei vollständig identischen Anfragen können die bei mehreren Übermittlungen erhaltenen Dauern stark variieren. Verwenden Sie dies daher nicht als präzise Steuerung der Dauer; wenn geschäftlich eine feste Dauer erforderlich ist, schneiden Sie das Endprodukt nach Erhalt selbst zu oder versuchen Sie es erneut.

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Beachten Sie, dass `duration` in der Anfrage die **erwartete Dauer** ist, während das Feld `duration` jedes Songs in den Antwortdaten `data` die **tatsächliche Dauer** dieses Songs ist. Beide haben denselben Namen, aber unterschiedliche Bedeutungen; die tatsächliche Dauer wird nicht garantiert dem erwarteten Wert zu entsprechen. Die Länge des Liedtexts ist einer der Hauptfaktoren, die die Dauer des Endprodukts beeinflussen. Wenn ein längeres Endprodukt benötigt wird, wird empfohlen, gleichzeitig vollständigere Liedtexte bereitzustellen.

Die Schnittstelle prüft, dass `duration` eine ganze Zahl zwischen 10 und 360 sein muss; es bleibt weiterhin lediglich ein Generierungsziel und keine Garantie für die Länge des Endprodukts.

## Inspo-Inspirationskreationsfunktion

Die Inspo-Inspirationskreationsfunktion kann auf Grundlage von 1 bis 4 vollständigen Referenz-Audiodateien neue Musik generieren und unterstützt das Ziehen oder Hochladen von Audio als Inspirationsquelle. Die API verwendet die bestehende `inspo`-Action: Der Client stellt öffentlich zugängliche Audio-URLs bereit, und der Dienst schließt die Vorbereitung der Referenz-Audiodateien sowie die Kreation automatisch ab, ohne dass der Client Liedtexte, Stil oder Dauer separat auslesen und anschließend die Anfrage zusammensetzen muss. Sie unterscheidet sich vom oben beschriebenen Bereichs-Sampling und auch vom Cover, das den Stil des Originalsongs nachbildet. Bei der Verwendung müssen folgende Parameter ausgefüllt werden:

- action：Der Inhalt ist `inspo`。
- audio_urls：Liste der URLs der Referenz-Audiodateien; es müssen 1 bis 4 öffentlich zugängliche Audioadressen bereitgestellt werden.
- model：Das verwendete Modell, empfohlen wird `chirp-v6`。
- prompt：Liedtext oder kreativer Hinweistext (optional).
- instrumental：Wenn auf `true` gesetzt, wird gemäß einer Anfrage für reine Instrumentalmusik generiert, ohne Liedtext.
- persona_id：Verwendet auf Dienstkanälen, die diese Kombination unterstützen, die angegebene Stimme; die Referenz-Audiodateien werden während der Vorbereitungsphase an die für diese Stimme erforderliche Ressourcenumgebung gebunden.
- lyric_prompt：Wird verwendet, um Liedtexte automatisch zu generieren, wenn `custom=true` und kein `lyric` bereitgestellt wurde.

> Hinweis: Referenz-Audiodateien müssen öffentlich zugängliche Audiodateien sein. Wenn eine Referenz-Audiodatei vollständig mit einer bekannten Aufnahme in der Musikbibliothek der Plattform übereinstimmt, kann Suno die Generierung aufgrund einer Urheberrechtsprüfung ablehnen. Es wird empfohlen, eigene oder von Suno generierte Audiodateien als Inspirationsquelle zu verwenden.

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynchroner Rückruf

Da Suno relativ lange für die Musikgenerierung benötigt, etwa 1–2 Minuten, bleibt die HTTP-Anfrage verbunden, wenn die API lange keine Antwort gibt, was zu zusätzlichem Verbrauch von Systemressourcen führt. Daher bietet diese API auch Unterstützung für asynchrone Rückrufe.

Der Gesamtprozess ist: Wenn der Client eine Anfrage initiiert, gibt er zusätzlich ein Feld `callback_url` an. Nachdem der Client die API-Anfrage initiiert hat, gibt die API sofort ein Ergebnis zurück, das die Feldinformation `task_id` enthält, welche die aktuelle Aufgaben-ID repräsentiert. Nachdem die Aufgabe abgeschlossen ist, wird das Ergebnis der Musikgenerierung in Form von POST JSON an die vom Client angegebene `callback_url` gesendet, die ebenfalls das Feld `task_id` enthält, sodass die Aufgabenergebnisse über die ID zugeordnet werden können.

Im Folgenden erfahren wir anhand eines Beispiels, wie dies konkret funktioniert.
