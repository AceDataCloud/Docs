Mit der zunehmenden Verbreitung von KI werden verschiedene KI-Programme allmählich immer populärer. KI dringt zunehmend in alle Aspekte des Arbeits- und Lebensalltags der Menschen ein. Und auch die Branchen, die KI betreffen, werden immer vielfältiger, von anfänglichem Schreiben über Medizin und Bildung bis hin zur heutigen Musik.

Suno ist eine professionelle und hochwertige Plattform für die KI-gestützte Erstellung von Songs und Musik. Nutzer müssen nur einfache Text-Prompts eingeben, um anhand von Genre-Stil und Liedtext Songs mit Gesang zu generieren. Dieser KI-Musikgenerator wurde von Teammitgliedern bekannter Technologieunternehmen wie Meta, TikTok und Kensho entwickelt und hat das Ziel, dass keine Instrumente oder Werkzeuge benötigt werden und jeder wunderschöne Musik erschaffen kann.

Nachfolgend ist der Fortschritt der Modell-Updates aufgeführt:

| Version      | model           | Veröffentlichungszeit | lyric-Limit | style-Limit | Maximale Songlänge |
| ------- | --------------- | ---------- | -------- | -------- | ------ |
| v6      | chirp-v6        | 2026.09.09 | —        | —        | —      |
| v6 Wild | chirp-v6-wild   | 2026.09.09 | —        | —        | —      |
| v6 Mini | chirp-v6-mini   | 2026.09.09 | —        | —        | —      |
| v5.5    | chirp-v5-5      | 2026.03.27 | 5000     | 1000     | 8 Minuten   |
| v5      | chirp-v5        | 2025.09.23 | 5000     | 1000     | 8 Minuten   |
| v4.5+   | chirp-v4-5-plus | 2025.07.17 | 5000     | 1000     | 8 Minuten   |
| v4.5    | chirp-v4-5      | 2025.05.03 | 5000     | 1000     | 4 Minuten   |
| v4      | chirp-v4        | 2024.12.17 | 3000     | 200      | 150 Sekunden  |
| v3.5    | chirp-v3-5      | ---        | 3000     | 200      | 120 Sekunden  |

> Die `lyric`- und `style`-Limits in der obigen Tabelle sind die Obergrenzen im benutzerdefinierten Modus (`custom` ist `true`). Im nicht benutzerdefinierten Inspirationsmodus (`custom` ist `false`) wird nur `prompt` ausgefüllt, dessen Längenobergrenze 500 Zeichen beträgt (bei allen Modellen gleich).

Suno unterstützt jetzt `chirp-v6`, `chirp-v6-wild` und `chirp-v6-mini`. Die Verwendung von `chirp-v6` wird empfohlen; alte Modellnamen bleiben weiterhin kompatibel.

Allerdings bietet Suno offiziell keine API an, AceDataCloud stellt eine Suno-API bereit, die die offizielle Suno-Anbindung simuliert und die gewünschte Musik bequem und schnell generieren kann.

## Beantragung und Nutzung

Um die Suno Audios Generation API zu nutzen, holen Sie sich zunächst Ihr API Token in der [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) und bewahren Sie es als Reserve auf.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, die Sie zur Registrierung und Anmeldung auffordert. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API Token kann alle Dienste der Plattform aufrufen, es ist nicht erforderlich, für jeden Dienst separat einen Antrag zu stellen.** Bei der ersten Beantragung wird ein kostenloses Guthaben verschenkt, das kostenlos ausprobiert werden kann; bei unzureichendem Guthaben kann das allgemeine Guthaben in der [Konsole](https://platform.acedata.cloud/console/coin) aufgeladen werden.

> 📘 Vollständige Dokumentation: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Grundlegende Nutzung

An welche Songs Sie auch denken, Sie können beliebig einen Text eingeben. Wenn ich beispielsweise einen Song über Weihnachten generieren möchte, kann ich `a song for Christmas` eingeben, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Hier sehen wir, dass wir Request Headers festgelegt haben, einschließlich:

- `accept`: Welches Format des Antwortergebnisses empfangen werden soll; hier wird `application/json`, also das JSON-Format, eingetragen.
- `authorization`: Der Schlüssel zum Aufrufen der API, der nach der Beantragung direkt über das Dropdown ausgewählt werden kann.

Zusätzlich wurde der Request Body festgelegt, einschließlich:
- `action`: Die Aktion dieser Musikgenerierungsaufgabe, standardmäßig `generate`, umfasst hauptsächlich: `extend`, `upload_extend`, `cover`, `upload_cover`, `replace_section`, `replace_section`, `concat`, `stems`, `all_stems`, `remaster`.
- `prompt`: Der Prompt für den Inspirationsmodus von Suno Official (wirksam, wenn `custom` auf `false` gesetzt ist), maximal 500 Zeichen.
- `model`: Das Modell dieser Musikgenerierungsaufgabe. Die v6-Serie umfasst `chirp-v6`, `chirp-v6-wild` und `chirp-v6-mini`; ältere Modellnamen bleiben kompatibel.
- `lyric`: Der Liedtext im benutzerdefinierten Modus von Suno Official. `chirp-v3-5` und `chirp-v4` maximal 3000 Zeichen; `chirp-v4-5` und höher (einschließlich `chirp-v5`, `chirp-v5-5`) maximal 5000 Zeichen.
- `custom`: Ob der benutzerdefinierte Modus verwendet wird, standardmäßig: `false`.
- `instrumental`: Die Option für reine Instrumentalmusik im Inspirationsmodus von Suno Official.
- `title`: Der Musiktitel im benutzerdefinierten Modus von Suno Official. `chirp-v3-5`, `chirp-v4` maximal 80 Zeichen; `chirp-v4-5` und höher maximal 100 Zeichen.
- `style`: Der Musikstil im benutzerdefinierten Modus von Suno Official. `chirp-v3-5` und `chirp-v4` maximal 200 Zeichen; `chirp-v4-5` und höher (einschließlich `chirp-v5`, `chirp-v5-5`) maximal 1000 Zeichen.
- `negative_tags`: Musikstile oder Genres, die im benutzerdefinierten Modus (wenn `custom` auf `true` gesetzt ist) von den Generierungsergebnissen ausgeschlossen werden sollen.
- `audio_weight`: Der Anteil des hochgeladenen Referenzaudios, Bereich 0–1; je größer, desto stärker abhängig vom Referenzaudio.
- `audio_id`: Die ID der Referenzmusik.
- `overpainting_start`/`overpainting_end`: Die Start- und Endzeit zum Ergänzen von Gesang zu vorhandener reiner Instrumentalmusik, in Sekunden.
- `underpainting_start`/`underpainting_end`: Die Start- und Endzeit zum Hinzufügen einer Begleitung zu A-cappella-Gesang, in Sekunden.
- `persona_id`: Die Song-ID des Künstlers.
- `continue_at`: Die Grenze für die Fortsetzung, in Sekunden. Beispielsweise bedeutet 213.5, dass die Generierung des nachfolgenden Abschnitts bei 3 Minuten und 33.5 Sekunden beginnt. `lyric` und `style` leiten nur neue Inhalte nach der Grenze an und ersetzen weder den Liedtext noch den Gesang vor der Grenze im Quellaudio.
- `style_influence`: Der erweiterte Parameter „Style Influence“ im benutzerdefinierten Modus, Bereich 0–1; je größer, desto stärker entspricht er dem ausgewählten Stil.
- `replace_section_end`: Die Endzeit des zu ersetzenden Abschnitts.
- `replace_section_start`: Die Startzeit des zu ersetzenden Abschnitts.
- `vocal_gender`: Steuert die Präferenz für weibliche oder männliche Stimmen, weibliche Stimme `f`, männliche Stimme `m`, wirksam für Modelle ab 4.5; ist eine Präferenz und garantiert keine strikte Einhaltung.
- `weirdness`: Der erweiterte Parameter „Weirdness“ im benutzerdefinierten Modus, Bereich 0–1; je größer, desto kreativer und experimenteller.
- `duration`: Die gewünschte Songdauer, in Sekunden, muss eine ganze Zahl sein, Wertebereich von 10 bis 360. Dieser Parameter wird für die Songgenerierung im benutzerdefinierten Modus (wenn `custom` auf `true` gesetzt ist) verwendet. Er ist ein tendenzieller Hinweis und keine harte Einschränkung: Das Modell berücksichtigt ihn, garantiert jedoch nicht, ihn zu erreichen; die tatsächliche Dauer des fertigen Ergebnisses richtet sich nach dem Feld `duration` in der Antwort und ist normalerweise kürzer als der gewünschte Wert.
- `lyric_prompt`: Der Prompt zum Generieren von Liedtexten, ist dann und nur dann wirksam, wenn `custom` auf `true` gesetzt ist und `lyric` nicht übergeben wurde.
- `callback_url`: Die URL, an die die Ergebnisse zurückgerufen werden sollen.
- `async`: Optional; wenn auf `true` gesetzt, gibt die Schnittstelle sofort `task_id` zurück, ohne dass `callback_url` angegeben werden muss; anschließend werden die Ergebnisse durch Abfragen über die entsprechende Schnittstelle zur Aufgabenabfrage abgerufen.

## Benutzerdefinierte Generierung

Wenn Sie Liedtexte benutzerdefiniert generieren möchten, können Sie Liedtexte eingeben:

Als Nächstes müssen wir Songs anhand von Liedtext, Titel und Stil benutzerdefiniert generieren und können dafür die folgenden Inhalte angeben:

- lyric：Liedtext
- custom：Auf `true` setzen, steht für benutzerdefinierte Generierung; der Standardwert dieses Parameters ist false und steht für die Generierung mithilfe von `prompt`.
- title：Der Titel des Songs.
- style：Der Stil des Songs, optional.

## Funktion zur benutzerdefinierten Generierung im Sängerstil
Wenn Sie den Sängerstil verwenden möchten, um einen Song zu generieren, generieren Sie zunächst über die grundlegende Verwendung im oberen Text einen Song,  
am Ende erhalten Sie die Notwendigkeit, diesen Song als Sängerstil festzulegen, dann müssen Sie [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) aufrufen, um anhand der offiziellen Musik-ID `audio_id` einen ID-Parameter `persona_id` für einen Sängerstil zu generieren, die konkreten Parameter sind wie in der folgenden Abbildung dargestellt:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Nach dem Ausfüllen wird der folgende Code automatisch generiert:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Funktion zur Fortsetzungsgenerierung

Wenn Sie einen bereits generierten Suno-Song weiter generieren möchten, können Sie den Parameter `action` auf `extend` setzen und die ID des Songs eingeben, der weiter generiert werden soll. Die Song-ID wird anhand der grundlegenden Verwendung abgerufen. Aus dem oberen Text ist ersichtlich, dass Sie zu diesem Zeitpunkt sehen können, dass die ID des Songs lautet:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Hinweis: Hier ist `id` in den Songdaten die ID des nach der Generierung entstandenen Songs. Wenn Sie nicht wissen, wie man einen Song generiert, können Sie sich auf die grundlegende Verwendung im oberen Text beziehen, um einen Song zu generieren.

Wenn Sie einen selbst hochgeladenen Song weiter generieren möchten, können Sie den Parameter `action` auf `upload_extend` setzen und die ID des benutzerdefiniert hochgeladenen Songs eingeben, der weiter generiert werden soll. Die Song-ID wird über [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload) abgerufen, wie in der folgenden Abbildung dargestellt:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Als Nächstes müssen Sie den Liedtext des fortzusetzenden Abschnitts ausfüllen und können einen Stil angeben:

- lyric: Wird nur verwendet, um den Liedtext des neu generierten Abschnitts nach `continue_at` zu leiten, und ersetzt nicht den Liedtext vor diesem Zeitpunkt im Quell-Audio.
- custom: Das Ausfüllen mit `true` steht für benutzerdefinierte Generierung; dieser Parameter ist standardmäßig false und steht für die Generierung mit `prompt`.
- style: Der Songstil des fortzusetzenden Abschnitts, optional.
- continue_at: Grenze der Fortsetzung, Einheit in Sekunden. Beispielsweise bedeutet 213.5, dass der nachfolgende Abschnitt ab 3 Minuten und 33,5 Sekunden generiert wird.

> `extend` wird verwendet, um einen bestehenden Song nach hinten weiter zu komponieren, nicht um den Text des gesamten Songs zu ersetzen. Wenn Sie möchten, dass der gesamte Song von Anfang an einen neuen Liedtext verwendet, verwenden Sie bitte `generate`, um ihn erneut zu generieren; wenn Sie einen bestehenden Song als Referenz neu interpretieren möchten, können Sie `cover` verwenden. Beim Übergeben eines vollständigen neuen Liedtexts wird der ursprüngliche Liedtext vor `continue_at` weiterhin nicht ersetzt.

## Musik-Cover

- action：Der Inhalt ist `cover`; bei einer Cover-Operation für benutzerdefiniert hochgeladene Musik muss der Inhalt `upload_cover` angegeben werden.
- audio_id：Die ID des zuvor generierten Songs.

```json
{
```

## Abschnitt ersetzen

Wenn nach der Songgenerierung eine sekundäre Bearbeitung erforderlich ist, bei der ein Songabschnitt separat ersetzt wird, kann ein bestimmter Abschnitt des Songs ersetzt werden.

> ⚠️ **Hinweis**: `replace_section_result_mode` ist standardmäßig `full_song`: Das System fügt jeweils 2 neu generierte Kandidaten zusammen und gibt 2 vollständige Songs zurück. Wenn nur die noch nicht zusammengefügten Ersatzabschnitt-Kandidaten benötigt werden, setzen Sie es bitte explizit auf `candidates` und wählen dann einen Kandidaten aus, um [Musik zusammenzufügen](#音乐拼接) aufzurufen.

Die Parameter werden wie folgt beschrieben:

- action：Der Inhalt ist `replace_section`.
- audio_id：Die ID des Originalsongs (des zu ersetzenden Quellsongs).
- model: Das Songgenerierungsmodell.
- lyric: Der vollständige Liedtext nach dem Ersetzen (einschließlich des ersetzten Abschnitts und seines Kontexts, konsistent mit dem Inhalt in `prompt`).
- prompt：Der neue Liedtext für den zu ersetzenden Abschnitt.
- style：Der Stil des Songs, optional.
- replace_section_start：Die Startzeit des zu ersetzenden Abschnitts im Originalsong (Sekunden).
- replace_section_end：Die Endzeit des zu ersetzenden Abschnitts im Originalsong (Sekunden).
- replace_section_result_mode：Der Rückgabemodus, standardmäßig `full_song`. `full_song` fügt jeweils 2 Kandidaten zusammen und gibt 2 vollständige Songs zurück; `candidates` gibt 2 noch nicht zusammengefügte Kandidatenabschnitte zurück.

## Steuerung der Songdauer

Standardmäßig wird die Dauer des generierten Songs vom Modell selbst bestimmt und liegt normalerweise zwischen 30 Sekunden und 4 Minuten. Wenn ein längeres oder kürzeres Endprodukt benötigt wird, kann über den Parameter `duration` die gewünschte Dauer angegeben werden, die Einheit ist Sekunden, und der Wert ist eine ganze Zahl zwischen 10 und 360.

Dieser Parameter wird für die Songgenerierung im benutzerdefinierten Modus verwendet (`custom` ist `true`). Besonders zu beachten ist, dass `duration` ein **Hinweis auf eine Tendenz und keine harte Einschränkung** ist: Das Modell wird diesen Wert bei der Erstellung berücksichtigen, garantiert aber nicht, ihn zu erreichen. In Tests war die tatsächliche Dauer normalerweise deutlich kürzer als der gewünschte Wert, und die Dauer der zwei von derselben Anfrage zurückgegebenen Songs kann ebenfalls um ein Mehrfaches variieren. Selbst bei vollständig identischen Anfragen kann die bei mehreren Übermittlungen erhaltene Dauer stark abweichen. Verwenden Sie dies daher nicht als präzise Steuerung der Dauer. Wenn geschäftlich eine feste Dauer erforderlich ist, schneiden Sie das Endprodukt nach Erhalt selbst zu oder versuchen Sie es erneut.

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Beachten Sie, dass `duration` in der Anfrage die **gewünschte Dauer** ist, während das Feld `duration` jedes Songs in den Antwortdaten `data` die **tatsächliche Dauer** dieses Songs ist. Beide haben denselben Namen, aber unterschiedliche Bedeutungen; die tatsächliche Dauer wird nicht garantiert der gewünschten Dauer entsprechen. Die Länge des Liedtexts ist einer der Hauptfaktoren, die die Dauer des Endprodukts beeinflussen. Wenn ein längeres Endprodukt benötigt wird, wird empfohlen, gleichzeitig einen vollständigeren Liedtext bereitzustellen.

Die Schnittstelle führt keine zusätzliche Validierung für `duration` durch, der Parameter wird unverändert an das Modell weitergegeben. Wenn ein Wert übergeben wird, der vom aktuellen Modus oder Modell nicht unterstützt wird, kann dies dazu führen, dass dieser Wert ignoriert wird. Es wird empfohlen, die Wirkung zunächst mit einer Anfrage zu bestätigen, bevor er in großen Mengen verwendet wird.

## Add-Insterumental-Funktion

Im August 2025 hat suno die neue Add-Insterumental-Funktion eingeführt. Zunächst muss ein Song ohne Begleitung und ohne Vertonung hochgeladen werden, damit suno ihn für Sie vertont. Zunächst können Sie über die [Suno Upload API](https://platform.acedata.cloud/documents/suno-upload) einen Song ohne Begleitung und ohne Musik hochladen. - action：Der Inhalt ist `underpainting`。
- underpainting_start：Die Startzeit zum Hinzufügen einer Begleitung zum hochgeladenen Song, der Standardwert ist 0。
- underpainting_end：Die Endzeit zum Hinzufügen einer Begleitung zum hochgeladenen Song, sie muss kleiner als die Gesamtdauer des Songs sein。
- audio_id：Die ID des hochgeladenen A-cappella-Songs ohne Begleitung。
- style：Der Stil der Begleitung, am besten ohne Liedtext, schließlich handelt es sich um eine Vertonung。

## Add-Vocals-Funktion

Im August 2025 hat suno die neue Add-Vocals-Funktion eingeführt. Zuerst muss eine rein instrumentale Musik hochgeladen werden, damit suno Liedtexte erstellt und menschlichen Gesang erzeugt. Zuerst kann über die [Suno Upload API](https://platform.acedata.cloud/documents/suno-upload) ein A-cappella-Song ohne Begleitmusik hochgeladen werden. Der entsprechende Vorgang ist wie in der folgenden Abbildung gezeigt：

- action：Der Inhalt ist `overpainting`。
- overpainting_start：Die Startzeit zum Hinzufügen von Gesang zum hochgeladenen Song, der Standardwert ist 0。
- overpainting_end：Die Endzeit zum Hinzufügen von Gesang zum hochgeladenen Song, sie muss kleiner als die Gesamtdauer des Songs sein。
- audio_id：Die ID des hochgeladenen A-cappella-Songs ohne Vertonung。
- custom：In diesem Modus muss der benutzerdefinierte Modus verwendet werden, um Liedtexte einzugeben。
- lyric：Die im benutzerdefinierten Modus eingegebenen Liedtexte。
- style：Der Stil der Begleitung。

## Inspo-Funktion für kreative Inspiration

Die Inspo-Funktion für kreative Inspiration kann auf Grundlage von 1 bis 4 vollständigen Referenzaudios neue Musik generieren und unterstützt das Ziehen oder Hochladen von Audiodateien als Inspirationsquelle. Die API verwendet die vorhandene `inspo`-Action: Der Client stellt öffentlich zugängliche Audio-URLs bereit, und der Dienst erledigt automatisch die Vorbereitung der Referenzaudios und die Erstellung, ohne dass der Client Liedtexte, Stil oder Dauer einzeln auslesen und dann die Anfrage zusammenstellen muss. Sie unterscheidet sich sowohl vom obigen Bereichs-Sampling als auch vom Cover, das den Stil des Originalsongs nachbildet. Bei der Verwendung müssen die folgenden Parameter ausgefüllt werden:

- action: Der Inhalt ist `inspo`.
- audio_urls: Liste der URLs der Referenzaudios; es müssen 1 bis 4 öffentlich zugängliche Audioadressen bereitgestellt werden.
- model: Das verwendete Modell, empfohlen wird `chirp-v6`.
- prompt: Liedtext oder kreatives Prompt (optional).

> Hinweis: Die Referenzaudios müssen öffentlich zugängliche Audiodateien sein. Wenn ein Referenzaudio vollständig mit einer bekannten Aufnahme in der Plattform-Musikbibliothek übereinstimmt, kann Suno die Generierung aufgrund einer Urheberrechtsprüfung ablehnen. Es wird empfohlen, eigene oder von Suno generierte Audios als Inspirationsquelle zu verwenden.

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynchroner Rückruf

Da Suno relativ lange zur Musikgenerierung benötigt, etwa 1–2 Minuten, bleibt die HTTP-Anfrage bei einer länger ausbleibenden API-Antwort dauerhaft verbunden, was zu zusätzlichem Verbrauch von Systemressourcen führt. Daher unterstützt diese API auch asynchrone Rückrufe.

Der gesamte Ablauf ist: Wenn der Client eine Anfrage initiiert, gibt er zusätzlich ein Feld `callback_url` an. Nachdem der Client die API-Anfrage initiiert hat, gibt die API sofort ein Ergebnis zurück, das ein Feld `task_id` enthält, welches die aktuelle Aufgaben-ID darstellt. Nachdem die Aufgabe abgeschlossen ist, wird das Ergebnis der Musikgenerierung in Form von POST JSON an die vom Client angegebene `callback_url` gesendet, die ebenfalls das Feld `task_id` enthält, sodass die Aufgabenergebnisse über die ID verknüpft werden können.

Im Folgenden erfahren wir anhand eines Beispiels, wie genau vorzugehen ist.

Zunächst ist der Webhook-Rückruf ein Dienst, der HTTP-Anfragen empfangen kann. Entwickler sollten ihn durch die URL ihres selbst eingerichteten HTTP-Servers ersetzen. ## Fehlerbehandlung

Falls ein Fehler auftritt, erhalten Sie eine ähnliche Fehlermeldung wie die folgende:

```json
{
  "success": false,
  "error": {
    "code": "forbidden",
    "message": "Song Description contained artist name: eminem"
  },
  "trace_id": "9bb7c2f4-3b7b-4965-b50a-f663874b1b6f",
  "task_id": "9bb3a2a6-c438-436d-a9f3-fa466abc077c"
}
```
