Mit der zunehmenden Anwendung von KI haben sich verschiedene KI-Programme allmählich verbreitet. KI hat sich zunehmend in alle Aspekte des Arbeits- und Lebensalltags der Menschen integriert. Die Branchen, die von KI betroffen sind, werden ebenfalls immer vielfältiger, von anfänglichem Schreiben über Gesundheitswesen und Bildung bis hin zur Musik.

Suno ist eine professionelle, hochwertige Plattform zur Erstellung von KI-Songs und Musik. Die Benutzer müssen nur einfache Textanweisungen eingeben, um basierend auf Genre-Stilen und Texten Lieder mit Gesang zu generieren. Dieser KI-Musikgenerator wurde von Teammitgliedern bekannter Technologieunternehmen wie Meta, TikTok und Kensho entwickelt, mit dem Ziel, dass jeder ohne Musikinstrumente wunderbare Musik schaffen kann.

Hier ist der Fortschritt der Modellaktualisierungen:

| Version | model           | Veröffentlichungsdatum | lyrische Begrenzung | Stilbegrenzung | Maximale Songlänge |
| ------- | --------------- | --------------------- | ------------------ | -------------- | ------------------ |
| v5.5    | chirp-v5-5      | 2026.03.27            | 5000               | 1000           | 8 Minuten          |
| v5      | chirp-v5        | 2025.09.23            | 5000               | 1000           | 8 Minuten          |
| v4.5+   | chirp-v4-5-plus | 2025.07.17            | 5000               | 1000           | 8 Minuten          |
| v4.5    | chirp-v4-5      | 2025.05.03            | 5000               | 1000           | 4 Minuten          |
| v4      | chirp-v4        | 2024.12.17            | 3000               | 200            | 150 Sekunden       |
| v3.5    | chirp-v3-5      | ---                   | 3000               | 200            | 120 Sekunden       |

> In der obigen Tabelle sind die `lyric` und `style` Begrenzungen die Obergrenze im benutzerdefinierten Modus (`custom` ist `true`). Im nicht benutzerdefinierten Inspirationsmodus (`custom` ist `false`) wird nur `prompt` ausgefüllt, dessen Längenobergrenze 500 Zeichen beträgt (bei allen Modellen gleich).

Suno unterstützt jetzt das neueste `chirp-v5-5` Modell. Um die neueste Version aufzurufen, setzen Sie den `model` Parameter auf `chirp-v5-5`; `chirp-v5` und frühere Versionen können weiterhin verwendet werden.

Allerdings bietet Suno offiziell keine API an, AceDataCloud stellt eine API für Suno zur Verfügung, die die offizielle Suno-Integration simuliert und es ermöglicht, schnell und einfach die gewünschte Musik zu generieren.

## Antrag und Nutzung

Um die Suno Audios Generation API zu nutzen, gehen Sie zuerst zur [Ace Data Cloud Konsole](https://platform.acedata.cloud/console/applications), um Ihr API-Token zu erhalten, das Sie für später aufbewahren sollten.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, die Sie zur Registrierung und Anmeldung einlädt. Nach Abschluss werden Sie automatisch zur aktuellen Seite zurückgeleitet.

**Ein API-Token reicht aus, um alle Dienste der Plattform zu nutzen, es ist nicht erforderlich, für jeden Dienst separat zu beantragen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, um es kostenlos auszuprobieren; wenn das Kontingent nicht ausreicht, können Sie im [Dashboard](https://platform.acedata.cloud/console/coin) Ihr allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Grundlegende Nutzung

Was auch immer Sie für Songs im Kopf haben, können Sie einen beliebigen Text eingeben, zum Beispiel, wenn ich ein Lied über Weihnachten generieren möchte, kann ich `a song for Christmas` eingeben, wie im Bild gezeigt:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Hier haben wir die Request-Header festgelegt, einschließlich:

- `accept`: In welchem Format Sie die Antwort erhalten möchten, hier eingetragen als `application/json`, also im JSON-Format.
- `authorization`: Der Schlüssel zum Aufrufen der API, den Sie nach der Beantragung direkt auswählen können.

Außerdem haben wir den Request-Body festgelegt, einschließlich:
- `action`：Die Aktion dieser Musikgenerierungsaufgabe, standardmäßig `generate`, umfasst hauptsächlich: `extend`, `upload_extend`, `cover`, `upload_cover`, `replace_section`, `replace_section`, `concat`, `stems`, `all_stems`, `remaster`.
- `prompt`：Die offiziellen Inspirationsmodus-Hinweise von Suno (wirksam, wenn `custom` auf `false` gesetzt ist), maximal 500 Zeichen.
- `model`：Das Modell dieser Musikgenerierungsaufgabe, standardmäßig `chirp-v4`, umfasst hauptsächlich: `chirp-v3`, `chirp-v4`, `chirp-v3-5`, `chirp-v4-5`, `chirp-v4-5-plus`, `chirp-v5`, `chirp-v5-5`.
- `lyric`：Der Inhalt der Lyrics im benutzerdefinierten Modus von Suno. `chirp-v3-5` und `chirp-v4` maximal 3000 Zeichen; `chirp-v4-5` und höher (einschließlich `chirp-v5`, `chirp-v5-5`) maximal 5000 Zeichen.
- `custom`：Ob der benutzerdefinierte Modus verwendet wird, standardmäßig: `false`.
- `instrumental`：Die reine Musikoption im Inspirationsmodus von Suno.
- `title`：Der Titel der Musik im benutzerdefinierten Modus von Suno. `chirp-v3-5`, `chirp-v4` maximal 80 Zeichen; `chirp-v4-5` und höher maximal 100 Zeichen.
- `style`：Der Musikstil im benutzerdefinierten Modus von Suno. `chirp-v3-5` und `chirp-v4` maximal 200 Zeichen; `chirp-v4-5` und höher (einschließlich `chirp-v5`, `chirp-v5-5`) maximal 1000 Zeichen.
- `negative_tags`：Musikstile oder Genres, die im benutzerdefinierten Modus (`custom` ist `true`) von den Ergebnissen ausgeschlossen werden sollen.
- `audio_weight`：Der Anteil der hochgeladenen Referenzaudio, Bereich 0-1, je größer, desto mehr wird auf die Referenzaudio vertraut.
- `audio_id`：Die ID der Referenzmusik.
- `overpainting_start`/`overpainting_end`：Die Start- und Endzeit für das Hinzufügen von Gesang zu bereits vorhandener reiner Musik, Einheit Sekunden.
- `underpainting_start`/`underpainting_end`：Die Start- und Endzeit für das Hinzufügen von Begleitmusik zu einem Gesang, Einheit Sekunden.
- `persona_id`：Die ID des Künstlersongs.
- `continue_at`：Die Fortsetzungsgrenze, Einheit Sekunden. Zum Beispiel bedeutet 213.5, dass ab 3 Minuten 33.5 Sekunden mit der Generierung des nachfolgenden Abschnitts begonnen wird. `lyric` und `style` leiten nur den neuen Inhalt nach der Grenze, ersetzen jedoch nicht die Lyrics oder den Gesang vor der Grenze im Quellaudio.
- `style_influence`：Der erweiterte Parameter „Style Influence“ im benutzerdefinierten Modus, Bereich 0-1, je größer, desto mehr entspricht es dem gewählten Stil.
- `replace_section_end`：Die Endzeit des zu ersetzenden Abschnitts.
- `replace_section_start`：Die Startzeit des zu ersetzenden Abschnitts.
- `vocal_gender`：Steuert die Präferenz für männliche oder weibliche Stimmen, weiblich `f`, männlich `m`, ab Modell 4.5 und höher wirksam; ist eine Präferenz, die nicht strikt eingehalten wird.
- `weirdness`：Der erweiterte Parameter „Weirdness“ im benutzerdefinierten Modus, Bereich 0-1, je größer, desto kreativer und experimenteller.
- `duration`：Die gewünschte Songlänge, Einheit Sekunden, muss eine ganze Zahl sein, Wertebereich 10 bis 360. Dieser Parameter wird für die Songgenerierung im benutzerdefinierten Modus (`custom` ist `true`) verwendet. Es ist ein Hinweis, kein striktes Limit: Das Modell wird sich darauf beziehen, garantiert jedoch nicht, dass es erreicht wird, die tatsächliche Länge des Endprodukts wird durch das `duration`-Feld in der Antwort bestimmt, normalerweise kürzer als der erwartete Wert.
- `lyric_prompt`：Der Prompt zur Generierung von Lyrics, der nur wirksam ist, wenn `custom` auf `true` gesetzt ist und `lyric` nicht übergeben wurde.
- `callback_url`：Die URL, an die die Ergebnisse zurückgerufen werden sollen.
- `async`：Optional, wenn auf `true` gesetzt, gibt die Schnittstelle sofort `task_id` zurück, ohne dass `callback_url` bereitgestellt werden muss, anschließend wird das Ergebnis über die entsprechende Task-Abfrage-Schnittstelle abgefragt.

## Benutzerdefinierte Generierung

Wenn Sie benutzerdefinierte Liedtexte generieren möchten, können Sie die Liedtexte eingeben:

In diesem Fall kann das `lyric`-Feld Inhalte wie folgt übergeben:

```
[Strophe]\nSchneeflocken fallen überall\nGlänzend weiß\nBedecken den Boden\nKinder lachen\nVoll von Freude\nIn diesem Winterwunderland heute Nacht\nSantas Schlitten\nHoch am Himmel\nRudolfs Nase leuchtet hell\nOh mein\nHört die Glocken\nKlingeln so klar\nBringen Freude und Feiertagsfreude\n[Strophe 2]\nKastanien rösten im Schein des Feuers\nWeihnachtslichter\nSie funkeln und zeigen\nFamilien versammeln sich mit Liebe und Freude\nVerbreiten Wärme zu jedem in der Nähe
```

> Hinweis: Hier ist `\n` das Zeilenumbruchzeichen. Wenn Sie nicht wissen, wie Sie Liedtexte generieren können, können Sie die von AceDataCloud bereitgestellte API zur Liedtextgenerierung verwenden, um durch den Prompt Liedtexte zu generieren. Die API ist [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Als nächstes möchten wir basierend auf den Liedtexten, dem Titel und dem Stil ein Lied benutzerdefiniert generieren, können Sie die folgenden Inhalte angeben:

- lyric: Liedtext
- custom: Setzen Sie auf `true`, was bedeutet, dass es sich um eine benutzerdefinierte Generierung handelt. Dieser Parameter ist standardmäßig auf false gesetzt, was bedeutet, dass der Prompt verwendet wird.
- title: Titel des Liedes.
- style: Stil des Liedes, optional.

## Funktion zur benutzerdefinierten Sängerstil-Generierung

Schließlich müssen Sie dieses Lied auf den Stil des Sängers einstellen und dann die [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) aufrufen, um anhand der offiziell generierten Musik-ID `audio_id` eine Sängerstil-ID-Parameter `persona_id` zu generieren. Die spezifischen Parameter sind wie im folgenden Bild dargestellt:

Entsprechender Python-Code:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Fortsetzungsfunktion

Wenn Sie ein bereits generiertes Suno-Lied weiter generieren möchten, können Sie den Parameter `action` auf `extend` setzen und die ID des zu generierenden Liedes eingeben. Die ID des Liedes kann anhand der grundlegenden Verwendung ermittelt werden. Wie oben erwähnt, können Sie die ID des Liedes sehen:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Beachten Sie, dass die `id` in den Texten die ID des generierten Liedes ist. Wenn Sie nicht wissen, wie man ein Lied generiert, können Sie sich auf die grundlegende Verwendung oben beziehen, um ein Lied zu generieren.

Wenn Sie ein selbst hochgeladenes Lied weiter generieren möchten, können Sie den Parameter `action` auf `upload_extend` setzen und die ID des benutzerdefinierten hochgeladenen Liedes eingeben. Die ID des Liedes kann über die [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload) abgerufen werden, wie im folgenden Bild dargestellt:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Anschließend müssen Sie den Textabschnitt für die Fortsetzung ausfüllen und können den Stil angeben:

- lyric: Wird nur verwendet, um die neuen generierten Textabschnitte nach `continue_at` zu leiten und ersetzt nicht die Texte vor diesem Zeitpunkt im Quell-Audio.
- custom: Setzen Sie auf `true`, um benutzerdefinierte Generierung anzuzeigen. Dieser Parameter ist standardmäßig auf false gesetzt, was bedeutet, dass `prompt` verwendet wird.
- style: Stil des Liedes für den Fortsetzungsteil, optional.
- continue_at: Fortsetzungsgrenze, Einheit in Sekunden. Zum Beispiel bedeutet 213.5, dass die Fortsetzung bei 3 Minuten und 33.5 Sekunden beginnt.

> `extend` wird verwendet, um mit einem bestehenden Lied weiter zu arbeiten, nicht um den gesamten Text des Liedes zu ändern. - action: Inhalt ist `cover`, wenn es sich um eine Cover-Operation für benutzerdefinierte hochgeladene Musik handelt, muss der Inhalt `upload_cover` sein.
- audio_id: ID des zuvor generierten Liedes.

## Abschnitt ersetzen

Wenn nach der Generierung eines Liedes ein bestimmter Abschnitt des Liedes ersetzt werden muss, kann eine separate kreative Bearbeitung des Liedes durchgeführt werden, indem ein Abschnitt des Liedes ersetzt wird.

> ⚠️ **Hinweis**: `replace_section` wird allein verwendet, **gibt nur den neu generierten "ersetzten Abschnitt" selbst zurück** (d.h. die neue Audioaufnahme des ersetzten Abschnitts, deren Dauer ungefähr `replace_section_end - replace_section_start` entspricht, und enthält eine kleine Menge an Kontext), **und gibt nicht das zusammengefügte gesamte Lied zurück**. Um das vollständige Endprodukt zu erhalten, das mit dem Originalstück zusammengefügt ist, muss nach dem erfolgreichen `replace_section` eine weitere [Musikzusammenfügen](#Musikzusammenfügen) Aufgabe für die zurückgegebene Abschnitts-ID gestartet werden. Der vollständige Prozess ist im Folgenden beschrieben.

Parameterbeschreibung wie folgt:

- action: Inhalt ist `replace_section`.
- audio_id: ID des ursprünglichen Liedes (des ersetzten Quellliedes).
- model: Liedgenerierungsmodell.
- lyric: Vollständiger Text nach der Ersetzung (einschließlich des ersetzten Abschnitts und seines Kontexts, der mit dem Inhalt in `prompt` übereinstimmt).
- prompt: Der neue Text, der ersetzt werden soll.
- style: Stil des Liedes, optional.
- replace_section_start: Startzeit des ersetzten Abschnitts im Originalstück (Sekunden).
- replace_section_end: Endzeit des ersetzten Abschnitts im Originalstück (Sekunden).

## Steuerung der Songlänge

Standardmäßig wird die Länge des generierten Songs vom Modell selbst bestimmt, normalerweise zwischen 30 Sekunden und 4 Minuten. Wenn ein längeres oder kürzeres Produkt benötigt wird, kann die gewünschte Länge über den Parameter `duration` angegeben werden, die Einheit ist Sekunden, der Wert ist eine ganze Zahl zwischen 10 und 360.

Dieser Parameter wird für die Generierung von Songs im benutzerdefinierten Modus (`custom` ist `true`) verwendet. Es ist besonders zu beachten, dass `duration` ein **tendenzieller Hinweis und keine strikte Einschränkung** ist: Das Modell wird diesen Wert bei der Erstellung berücksichtigen, garantiert jedoch nicht, dass er erreicht wird. In der Praxis ist die tatsächliche Länge oft deutlich kürzer als der erwartete Wert, und die Längen der beiden Songs, die in einer einzigen Anfrage zurückgegeben werden, können ebenfalls um ein Vielfaches variieren. Selbst bei identischen Anfragen kann die Länge bei mehrfachen Einreichungen erheblich variieren. Daher sollte dies nicht als präzise Längensteuerung verwendet werden. Wenn eine feste Länge geschäftlich erforderlich ist, schneiden Sie das Produkt nach Erhalt selbst zu oder versuchen Sie es erneut.

Die entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Es ist zu beachten, dass die `duration` in der Anfrage die **erwartete Länge** ist, während das `duration`-Feld in den `data` der Antwort die **tatsächliche Länge** des jeweiligen Songs ist. Beide haben denselben Namen, aber unterschiedliche Bedeutungen, die tatsächliche Länge garantiert nicht, dass sie dem erwarteten Wert entspricht. Die Länge des Textes ist einer der Hauptfaktoren, die die Länge des Endprodukts beeinflussen. Wenn ein längeres Produkt benötigt wird, wird empfohlen, gleichzeitig vollständigere Texte bereitzustellen.

Die Schnittstelle führt keine zusätzlichen Überprüfungen für `duration` durch, die Parameter werden unverändert an das Modell übergeben. Wenn Werte übergeben werden, die im aktuellen Modus oder Modell nicht unterstützt werden, kann dies dazu führen, dass dieser Wert ignoriert wird. Es wird empfohlen, zunächst eine Anfrage zu verwenden, um die Wirkung zu bestätigen, bevor Sie sie in großen Mengen verwenden.

## Add Insterumental Funktion

Im August 2025 hat Suno die Funktion Add Insterumental eingeführt. Zuerst müssen Sie ein a cappella Lied ohne Begleitstimme hochladen, damit Suno Ihnen die Musikuntermalung erstellen kann. Zuerst können Sie zur [Suno Upload API](https://platform.acedata.cloud/documents/suno-upload) gehen, um ein a cappella Lied ohne Begleitmusik hochzuladen, die entsprechenden Schritte sind wie im folgenden Bild dargestellt:

- action: Inhalt ist `underpainting`.
- underpainting_start: Der Startzeitpunkt für das Hinzufügen von Begleitmusik zum hochgeladenen Lied, der Standardwert ist 0.
- underpainting_end: Der Endzeitpunkt für das Hinzufügen von Begleitmusik zum hochgeladenen Lied, muss kleiner als die Gesamtlänge des Liedes sein.
- audio_id: ID des hochgeladenen a cappella Liedes.

## Add Vocals Funktion

Im August 2025 hat Suno die neue Add Vocals-Funktion eingeführt. Zuerst muss ein reines Musikstück hochgeladen werden, damit Suno den Text und die Gesangsstimme hinzufügen kann. Zuerst kann man zur [Suno Upload API](https://platform.acedata.cloud/documents/suno-upload) gehen, um einen a cappella-Song ohne Begleitmusik hochzuladen, die entsprechenden Schritte sind wie im folgenden Bild dargestellt:

<p><img src="https://cdn.acedata.cloud/fxl914.png" width="500" class="m-auto"></p>

<p><img src="https://cdn.acedata.cloud/47t6wj.png" width="500" class="m-auto"></p>

Schließlich haben wir eine `audio_id` erhalten: 92254cab-3372-4d9e-bce9-cdcfdbc39070, dann müssen wir die folgenden Parameter ausfüllen:

- action: Inhalt ist `overpainting`.
- overpainting_start: Der Startzeitpunkt für das Hinzufügen von Gesang zur hochgeladenen Musik, der Standardwert ist 0.
- overpainting_end: Der Endzeitpunkt für das Hinzufügen von Gesang zur hochgeladenen Musik, muss kleiner als die Gesamtdauer des Songs sein.
- audio_id: ID des hochgeladenen a cappella-Songs.
- custom: In diesem Modus muss der Text im benutzerdefinierten Modus eingegeben werden.
- lyric: Der im benutzerdefinierten Modus eingegebene Text.
- style: Der Stil der Begleitmusik.

## Inspo Kreativitätsfunktion

Die neu eingeführte Inspo Kreativitätsfunktion von Suno kann basierend auf 1 bis 4 Abschnitten Referenzaudio als Inspirationsquelle neue Musik generieren. Im Gegensatz zu Coverversionen wird Inspo das Originalstück nicht nachahmen, sondern Stil-Inspirationen aus den Referenzaudio extrahieren und neue Werke unter Berücksichtigung von Stichwörtern, Stil-Tags usw. erstellen. Bei der Verwendung müssen die folgenden Parameter ausgefüllt werden:

- action: Inhalt ist `inspo`.
- audio_urls: Liste der URLs der Referenzaudio, es müssen 1 bis 4 öffentlich zugängliche Audioadressen bereitgestellt werden.
- model: Verwendetes Modell, z.B. `chirp-v5`.
- prompt: Liedtexte oder kreative Stichwörter (optional).
- tags: Musikstil-Tags, z.B. `akustisch, folk, warm` (optional).
- title: Titel des Songs (optional).
- audio_weight: Einflussgewicht des Referenzaudio auf das generierte Ergebnis, Wertebereich 0 bis 1 (optional).

> Hinweis: Referenzaudio muss öffentlich zugängliche Audiodateien sein. Wenn das Referenzaudio mit bekannten Aufnahmen in der Plattformbibliothek vollständig übereinstimmt, kann Suno aufgrund von Urheberrechtsprüfungen die Generierung ablehnen. Es wird empfohlen, eigene oder von Suno generierte Audios als Inspirationsquelle zu verwenden.

Entsprechender Python-Code:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v5",
    "audio_urls": [
        "https://cdn1.suno.ai/935dd2f5-ddef-43cf-8e68-5a262425694d.mp3"
    ],
    "prompt": "warme akustische Folk mit sanften Vocals",
    "tags": "akustisch, folk, warm",
    "title": "Inspo Demo",
    "audio_weight": 0.6
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynchrone Rückrufe

Da die Musikgenerierung durch Suno relativ lange dauert, etwa 1-2 Minuten, bleibt die HTTP-Anfrage bei längerer Nichtreaktion des API verbunden, was zu einem zusätzlichen Verbrauch von Systemressourcen führt. Daher bietet dieses API auch Unterstützung für asynchrone Rückrufe.

Der gesamte Ablauf ist: Wenn der Client die Anfrage startet, gibt er zusätzlich ein Feld `callback_url` an. Nachdem der Client die API-Anfrage gestartet hat, gibt das API sofort ein Ergebnis zurück, das ein Feld `task_id` enthält, das die aktuelle Aufgaben-ID darstellt. Wenn die Aufgabe abgeschlossen ist, wird das Ergebnis der Musikgenerierung in Form von POST JSON an die vom Client angegebene `callback_url` gesendet, wobei auch das Feld `task_id` enthalten ist, sodass das Aufgabenergebnis über die ID verknüpft werden kann.

Lassen Sie uns anhand eines Beispiels verstehen, wie dies konkret funktioniert.

Zunächst ist der Webhook-Rückruf ein Dienst, der HTTP-Anfragen empfangen kann. Entwickler sollten die URL ihres eigenen HTTP-Servers ersetzen. ![](https://cdn.acedata.cloud/fwfqin.png)
