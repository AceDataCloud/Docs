Mit der zunehmenden Verbreitung von KI-Anwendungen sind verschiedene KI-Programme allmählich populär geworden. KI ist nach und nach in alle Aspekte des Arbeits- und Lebensalltags der Menschen eingedrungen. Auch die Branchen, die von KI betroffen sind, werden immer vielfältiger, von anfänglichem Schreiben über Medizin und Bildung bis hin zur heutigen Musik.

Suno ist eine professionelle, hochwertige Plattform für KI-Song- und Musikproduktion. Nutzer müssen lediglich einfache Text-Prompts eingeben, um basierend auf Genre-Stil und Liedtext Songs mit Gesang zu generieren. Dieser KI-Musikgenerator wurde von Teammitgliedern bekannter Technologieunternehmen wie Meta, TikTok und Kensho entwickelt und verfolgt das Ziel, dass keine Instrumente erforderlich sind und jeder wunderschöne Musik erschaffen kann.

> Die `lyric`- und `style`-Beschränkungen in der obigen Tabelle sind die Obergrenzen im benutzerdefinierten Modus (`custom` ist `true`). Im nicht benutzerdefinierten Inspirationsmodus (`custom` ist `false`) wird nur `prompt` ausgefüllt, dessen Längenbegrenzung bei 500 Zeichen liegt (bei allen Modellen identisch).

Suno unterstützt jetzt `chirp-v6`, `chirp-v6-wild` und `chirp-v6-mini`. Die Verwendung von `chirp-v6` wird empfohlen; alte Modellnamen bleiben weiterhin kompatibel.

Suno bietet jedoch offiziell keine API an. AceDataCloud stellt eine Reihe von Suno-APIs bereit, die die offizielle Suno-Integration simulieren und die gewünschte Musik bequem und schnell generieren können.

## Beantragung und Nutzung

Um die Suno Audios Generation API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten und für die spätere Verwendung aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Bei der ersten Beantragung wird ein kostenloses Kontingent vergeben, das kostenlos getestet werden kann; bei unzureichendem Kontingent kann das allgemeine Guthaben in der [Konsole](https://platform.acedata.cloud/console/coin) aufgeladen werden.

## Grundlegende Verwendung

Wenn Sie einen beliebigen Song im Sinn haben, können Sie einen beliebigen Text eingeben. Wenn ich beispielsweise einen Song über Weihnachten generieren möchte, kann ich `a song for Christmas` eingeben, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Hier sehen wir, dass wir die Request Headers festgelegt haben, einschließlich:

- `accept`: Welches Format der Antwort empfangen werden soll; hier wird `application/json`, also das JSON-Format, eingetragen.
- `authorization`: Der Schlüssel zum Aufrufen der API, der nach der Beantragung direkt über das Dropdown ausgewählt werden kann.

Außerdem wurde der Request Body festgelegt, einschließlich:
- `action`: Audioaufgabentyp, standardmäßig `generate`. Unterstützt Vorgänge wie Generieren, Fortsetzen, Cover, Zusammenfügen, Stem-Trennung, Hinzufügen von Audiospuren, Extrahieren bestimmter Audiospuren, Generieren von Soundeffekten und Anpassen der Geschwindigkeit; einheitlich über `POST /suno/audios` aufgerufen.
- `prompt`: Sunos offizieller Prompt für den Inspirationsmodus (wirksam, wenn `custom` `false` ist), maximal 500 Zeichen.
- `model`: Das Modell für diese Musikgenerierungsaufgabe. Die v6-Serie umfasst `chirp-v6`, `chirp-v6-wild` und `chirp-v6-mini`; alte Modellnamen bleiben kompatibel.
- `max_mode`: Erweiterter Generierungsmodus. `generate` wird nur aktiviert, wenn sowohl `custom` als auch `max_mode` `true` sind, die Kosten betragen 1.12 Credits; `add_stem` kann direkt aktiviert werden, die Kosten betragen 1.344 Credits. Wenn deaktiviert oder ausgelassen, betragen sie jeweils 0.56 und 0.672 Credits.
- `variety`: Diversitätsintensität der Generierungsergebnisse, optional `off`, `normal`, `high`, `extra`, `max`. Nur für `generate` und `add_stem`; die Übergabe bei anderen actions gibt 400 zurück.
- `lyric`: Liedtextinhalt für Sunos offiziellen benutzerdefinierten Modus. `chirp-v3-5` und `chirp-v4` maximal 3000 Zeichen; `chirp-v4-5` und höher (einschließlich `chirp-v5`, `chirp-v5-5`) maximal 5000 Zeichen.
- `custom`: Ob der benutzerdefinierte Modus verwendet wird, standardmäßig: `false`.
- `instrumental`: Option für reine Instrumentalmusik im offiziellen Inspirationsmodus von Suno.
- `title`: Musiktitel für Sunos offiziellen benutzerdefinierten Modus. `chirp-v3-5`, `chirp-v4` maximal 80 Zeichen; `chirp-v4-5` und höher maximal 100 Zeichen.
- `style`: Musikstil für Sunos offiziellen benutzerdefinierten Modus. `chirp-v3-5` und `chirp-v4` maximal 200 Zeichen; `chirp-v4-5` und höher (einschließlich `chirp-v5`, `chirp-v5-5`) maximal 1000 Zeichen.
- `negative_tags`: Musikstile oder Genres, die bei der benutzerdefinierten Generierung ausgeschlossen werden sollen, kann auch für `replace_section` verwendet werden. Diese Schnittstelle hat derzeit keine feste Zeichenobergrenze für dieses Feld festgelegt; zu lange Inhalte können dennoch möglicherweise nicht verarbeitet werden, daher wird empfohlen, die Beschreibung knapp zu halten.
- `audio_weight`: Einflussgewicht von Audio- oder Klangmerkmalen, Bereich 0–1, auch `0` ist ein gültiger Wert. Kann für Vorgänge wie Generierung, Fortsetzung, Cover, Hinzufügen von Audiospuren und Stimmkonsistenz verwendet werden; ohne Referenzaudio oder Klangmerkmale kann das Modell diesen Wert abschwächen oder ignorieren.
- `audio_id`: ID der Referenzmusik, wird für Folgeoperationen wie Cover, Fortsetzung und Stem-Trennung verwendet. Die Audiodatei kann weiterhin heruntergeladen werden, dies bedeutet jedoch nicht, dass die Nachverarbeitung dieser ID stets verfügbar ist; wenn `suno_processing_unavailable` zurückgegeben wird, bewahren Sie bitte `task_id` und `trace_id` auf und kontaktieren Sie den Support.
- `overpainting_start`/`overpainting_end`: Start- und Endzeit zum Ergänzen von Gesang zu vorhandener reiner Instrumentalmusik, in Sekunden.
- `underpainting_start`/`underpainting_end`: Start- und Endzeit zum Hinzufügen von Begleitung zu A-cappella-Gesang, in Sekunden.
- `persona_id`: Die über die Persona- oder Stimmerstellungs-Schnittstelle erhaltene Stimm-ID, nicht die `audio_id` eines Songs.
- `continue_at`: Grenze für die Fortsetzung, in Sekunden. Beispielsweise bedeutet 213.5, dass nachfolgende Segmente ab 3 Minuten und 33.5 Sekunden generiert werden. `lyric` und `style` leiten nur neue Inhalte nach der Grenze an und ersetzen nicht den Liedtext oder Gesang vor der Grenze im Quellaudio.
- `style_influence`: Stileinfluss im benutzerdefinierten Modus, Bereich 0–1; je größer, desto eher entspricht er normalerweise dem ausgewählten Stil; `0` wird als gültiger Wert übergeben.
- `replace_section_end`: Endzeit des zu ersetzenden Segments.
- `replace_section_start`: Startzeit des zu ersetzenden Segments.
- `vocal_gender`: Steuert die Präferenz für weibliche oder männliche Stimmen, weibliche Stimme `f`, männliche Stimme `m`, wirksam für Modelle ab 4.5; ist eine Präferenz und die strikte Einhaltung wird nicht garantiert.
- `weirdness`: Grad der Skurrilität im benutzerdefinierten Modus, Bereich 0–1; je größer, desto kreativer und experimenteller normalerweise; `0` wird als gültiger Wert übergeben.
- `duration`: Erwartete Songlänge, in Sekunden, muss eine ganze Zahl sein, Wertebereich von 10 bis 360. Derzeit verwendet nur `generate` diesen Parameter, die konkrete Wirkung hängt vom Modus und Modell ab. Es handelt sich um einen tendenziellen Hinweis und nicht um eine harte Einschränkung: Das Modell berücksichtigt ihn, garantiert jedoch nicht dessen Erreichen; die tatsächliche Länge des Ergebnisses richtet sich nach dem Feld `duration` in der Antwort und ist normalerweise kürzer als der Erwartungswert.

### Anwendungsbereich der Stimm-ID

`generate`, `cover`, `upload_cover`, `artist_consistency`, `artist_consistency_vox` können `persona_id` verwenden. Die letzten beiden actions müssen `persona_id` bereitstellen; gleichzeitig kann auch die `audio_id` des Songs bereitgestellt werden, der bei der Erstellung dieser Persona verwendet wurde.

`extend`, `upload_extend` verwenden keine zusätzliche `persona_id`. Ob `mashup`, `inspo` Stimm-IDs unterstützen, hängt vom ausgewählten Servicekanal ab; bei anderen actions wird die Anwendung dieses Feldes nicht garantiert, bitte gemäß den Beschreibungen der jeweiligen Vorgänge verwenden. `vocal_gender` ist eine optionale Geschlechtspräferenz und kann keine Stimm-ID ersetzen.

Nachfolgende kreative Vorgänge benötigen eine gültige Quell-`audio_id`; `mashup` benötigt mindestens zwei `mashup_audio_ids`. Wenn notwendige Quellen oder Zeitparameter fehlen, wird HTTP 400 zurückgegeben.

### Anwendungsbereich erweiterter Parameter
| Parameter                | Values                                      | Supported actions                              | Description                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | Optional                                      | Adjusts experimentalism; `0` is a valid value; the effect depends on the action, mode, and model      |
| `style_influence` | 0-1                                         | Optional                                      | Adjusts the tendency to follow style; `0` is a valid value; the effect depends on the action, mode, and model   |
| `audio_weight`    | 0-1                                         | Optional                                      | Adjusts the influence of audio or sound features; may be ignored by the model when there is no reference information        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`, `add_stem`                   | Adjusts style diversity between results                       |
| `max_mode`        | boolean                                     | `generate` (requires `custom=true`), `add_stem` | Enhances consistency and is billed according to enhanced mode                     |
| `vocal_gender`    | `f` / `m`                                   | Generation actions that support vocal control                             | Preference setting, strict adherence is not guaranteed                       |
| `duration`        | Integer 10-360                                   | `generate`                              | Expected duration; other actions currently do not use this field, actual length is subject to the result |

The platform validates parameter types and value ranges, but does not reject these optional adjustment items solely because the action differs; the specific effect depends on the action, mode, and model.

- `lyric_prompt`: Prompt for generating lyrics, takes effect if and only if `custom` is `true` and `lyric` is not provided.
- `callback_url`: URL that requires callback results.
- `async`: Optional; when set to `true`, the API immediately returns `task_id`, without requiring `callback_url`, and the result can then be obtained by polling through the corresponding task query API.

## Funktion zur individuellen Generierung im Sängerstil

Wenn du den Sängerstil zur Generierung von Liedern verwenden möchtest, generiere zunächst über die oben beschriebene grundlegende Verwendung ein Lied.\
Am Ende musst du dieses Lied als Sängerstil festlegen, dann musst du die [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) aufrufen, um anhand der von der offiziellen Seite generierten Musik-ID `audio_id` einen ID-Parameter `persona_id` für den Sängerstil zu generieren. Die konkreten Parameter sind in der folgenden Abbildung dargestellt:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Nach dem Ausfüllen wird der folgende Code automatisch generiert:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Klicke auf Ausführen, und du wirst feststellen, dass du ein Ergebnis wie folgt erhältst:

```json

  "task_id": "7628b754-4fe7-4e79-bda4-806d0dd8bf6e",
  "data": {
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b"
  }
}
```

Wir verwenden die oben genannten `audio_id` und `persona_id`, nämlich `97efc9f4-0e8d-4b3e-88df-14568fa1b11f` und `e0d7319e-aa2a-44cb-b00a-916218d7cb0b`, jeweils als Beispieldaten für diesen Vorgang. Dann kann der Parameter `action` auf `artist_consistency` gesetzt werden (bei der neuen Sängerstil-Version Persona-v2-vox muss `action` auf `artist_consistency_vox` gesetzt werden), und es müssen die ID des Liedes, dessen Generierung fortgesetzt werden soll, sowie die Sängerstil-ID eingegeben werden. Das Ausfüllbeispiel sieht wie folgt aus:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "artist_consistency",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b",
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Funktion zur Fortsetzungsgenerierung
Wenn Sie einen bereits generierten Suno-Song weitergenerieren möchten, können Sie den Parameter `action` auf `extend` setzen und die ID des Songs eingeben, der weitergeneriert werden soll. Die Song-ID wird gemäß der grundlegenden Verwendung abgerufen. Wie oben ersichtlich, können Sie zu diesem Zeitpunkt sehen, dass die ID des Songs lautet:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Hinweis: Die `id` in den Lyrics hier ist die ID des generierten Songs. Wenn Sie nicht wissen, wie man einen Song generiert, können Sie sich auf die grundlegende Verwendung oben beziehen, um einen Song zu generieren.

Wenn Sie einen selbst hochgeladenen Song weitergenerieren möchten, können Sie den Parameter `action` auf `upload_extend` setzen und die ID des benutzerdefiniert hochgeladenen Songs eingeben, der weitergeneriert werden soll. Die Song-ID wird mithilfe der [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload) abgerufen, wie in der folgenden Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Als Nächstes müssen die Lyrics des fortzusetzenden Abschnitts ausgefüllt werden, und es kann ein Stil angegeben werden:

- lyric: Wird nur verwendet, um die Lyrics des neu generierten Abschnitts nach `continue_at` zu steuern, und ersetzt nicht die Lyrics vor diesem Zeitpunkt im Quellaudio.
- custom: Wenn auf `true` gesetzt, steht dies für eine benutzerdefinierte Generierung. Dieser Parameter ist standardmäßig false, was für die Generierung mit `prompt` steht.
- style: Der Songstil des fortzusetzenden Abschnitts, optional.
- continue_at: Fortsetzungsgrenze, in Sekunden. Beispielsweise bedeutet 213.5, dass der nachfolgende Abschnitt ab 3 Minuten und 33,5 Sekunden generiert wird.

`continue_at` für `extend` und `upload_extend` muss größer als 0 sein und unterstützt Sekundenbruchteile, beispielsweise `30.792`; beim Absenden wird nicht gerundet.

> `extend` wird verwendet, um auf Grundlage eines bestehenden Songs weiter zu komponieren, und nicht, um den Text des gesamten Songs zu ändern. Wenn Sie den gesamten Song von Anfang an mit neuen Lyrics versehen möchten, verwenden Sie bitte `generate`, um ihn erneut zu generieren; wenn Sie einen bestehenden Song als Referenz neu interpretieren möchten, können Sie `cover` verwenden. Wenn ein vollständiger neuer Liedtext übergeben wird, werden die ursprünglichen Lyrics vor `continue_at` dennoch nicht ersetzt.

## Musik-Cover

Nach der weiteren Generierung eines Songs auf Grundlage eines bestehenden Songs ist der Stil des zurückgegebenen Songs möglicherweise nicht ganz passend. Wenn der zuvor generierte Song (auch benutzerdefiniert hochgeladene Musik wird unterstützt) gecovert werden soll, muss die Musik-Cover-Methode verwendet werden; dabei können die folgenden Inhalte angegeben werden:

- action: Der Inhalt ist `cover`; bei einem Cover-Vorgang für benutzerdefiniert hochgeladene Musik muss der Inhalt `upload_cover` sein.
- audio_id: Die ID des zuvor generierten Songs.

Wenn ein Cover mit einer bestimmten Stimme verwendet werden soll, kann gleichzeitig `persona_id` übergeben werden. Private Stimmen, die über `/suno/voices` erstellt wurden, müssen zunächst in `/suno/upload` mit derselben `persona_id` hochgeladen werden; anschließend wird die zurückgegebene `audio_id` für `upload_cover` verwendet. Alle Schritte müssen denselben Servicekanal verwenden. `vocal_gender` muss nicht zusätzlich angegeben werden; die Geschlechtspräferenz kann keine Stimmen-ID ersetzen.

```json
{
  "action": "cover",
```

## Segmente ersetzen

Wenn nach der Generierung eines Songs für eine sekundäre Bearbeitung ein Songsegment separat ersetzt werden muss, kann ein bestimmtes Segment des Songs ersetzt werden.
> ⚠️ **Hinweis**: `replace_section_result_mode` ist standardmäßig auf `full_song` gesetzt: Das System fügt jeweils 2 neu generierte Kandidaten zusammen und gibt 2 vollständige Songs zurück. Wenn nur die noch nicht zusammengefügten Ersatzsegment-Kandidaten benötigt werden, setzen Sie dies bitte ausdrücklich auf `candidates`, wählen Sie dann einen Kandidaten aus und rufen Sie [Musik zusammenfügen](#音乐拼接) auf.

Die Parameter werden wie folgt beschrieben:

- action: Der Inhalt ist `replace_section`.
- audio_id: Die ID des ursprünglichen Songs (des Quell-Songs, der ersetzt wird).
- model: Das Song-Generierungsmodell.
- lyric: Der vollständige Liedtext nach dem Ersetzen (einschließlich des ersetzten Abschnitts und seines Kontexts, konsistent mit dem Inhalt in `prompt`).
- prompt: Der neue Liedtext für den Abschnitt, der ersetzt werden soll.
- style: Der Stil des Songs, optional.
- negative_tags: Stile oder Genres, die ausgeschlossen werden sollen, optional.
- replace_section_start: Die Startzeit des ersetzten Segments im Originalsong (Sekunden), erforderlich und darf nicht kleiner als 0 sein.
- replace_section_end: Die Endzeit des ersetzten Segments im Originalsong (Sekunden), erforderlich und muss größer als die Startzeit sein.
- replace_section_result_mode: Rückgabemodus, standardmäßig `full_song`. `full_song` fügt jeweils 2 Kandidaten zusammen und gibt 2 vollständige Songs zurück; `candidates` gibt 2 noch nicht zusammengefügte Kandidatensegmente zurück.

## Trennung von Gesang und Musik aller Spuren

Die Aufgabe kehrt erst dann in den erfolgreichen Endstatus zurück, wenn die Generierung aller Audiospuren abgeschlossen ist. Eine während der Verarbeitung erscheinende abspielbare Adresse bedeutet nicht, dass die gesamte Gruppe von Audiospuren bereits fertiggestellt wurde.

Wenn nach der Generierung eines Songs eine Trennung von Gesang und Musik für alle Spuren durchgeführt werden muss, kann der folgende Inhalt angegeben werden:

- action：Der Inhalt ist `all_stems`。
- audio_id：Die ID des zuvor generierten Songs.

Wenn beispielsweise die ID des zuvor generierten Songs lautet: bdf23a5a-59f5-4103-b452-054a824a7f9f, können die Parameter wie folgt festgelegt werden:

```json
{
  "action": "all_stems",
  "audio_id": "bdf23a5a-59f5-4103-b452-054a824a7f9f"
}
```

## Audiospur extrahieren

`extract_stem` extrahiert die Zielaudiospur aus dem angegebenen Audio und gibt gleichzeitig die ergänzende Version nach Entfernung dieser Audiospur zurück; der Aufruf erfolgt über `POST /suno/audios`.

- Erforderlich: `action`, `audio_id`, `stem_type`.
- Optional: `audio_format`; der aktuelle öffentliche Zweikanal-Vertrag unterstützt nur `mp3`.
- Abrechnung: 1.12 Credits.

```json
{
  "action": "extract_stem",
  "audio_id": "dead4ee5-df4d-417b-8f7e-717722fae51a",
  "stem_type": "bass",
  "audio_format": "mp3",
  "async": true
```

## Steuerung der Songlänge

Standardmäßig wird die Länge des generierten Songs vom Modell selbst bestimmt und liegt normalerweise zwischen 30 Sekunden und 4 Minuten. Wenn ein längeres oder kürzeres Endprodukt benötigt wird, kann die gewünschte Länge über den Parameter `duration` angegeben werden; die Einheit ist Sekunden, und der Wert ist eine ganze Zahl zwischen 10 und 360.

Dieser Parameter wird für die Songgenerierung im benutzerdefinierten Modus (`custom` ist `true`) verwendet. Besonders zu beachten ist, dass `duration` ein **Hinweis auf eine Tendenz und keine harte Einschränkung** ist: Das Modell wird diesen Wert beim Erstellen berücksichtigen, garantiert jedoch nicht, ihn zu erreichen. In Tests ist die tatsächliche Länge normalerweise deutlich kürzer als der gewünschte Wert, und die Längen der zwei von derselben Anfrage zurückgegebenen Songs können sich ebenfalls um ein Mehrfaches unterscheiden. Selbst bei vollständig identischen Anfragen können die Längen bei mehrfacher Übermittlung stark variieren. Verwenden Sie dies daher nicht als präzise Längensteuerung; wenn geschäftlich eine feste Länge erforderlich ist, schneiden Sie das Endprodukt nach Erhalt selbst zu oder versuchen Sie es erneut.

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Beachten Sie, dass `duration` in der Anfrage die **erwartete Länge** ist, während das Feld `duration` jedes Songs in den Antwortdaten `data` die **tatsächliche Länge** dieses Songs ist. Beide haben denselben Namen, aber unterschiedliche Bedeutungen; die tatsächliche Länge wird nicht garantiert der erwarteten Länge entsprechen. Die Liedtextlänge ist einer der Hauptfaktoren, die die Länge des Endprodukts beeinflussen. Wenn ein längeres Endprodukt benötigt wird, wird empfohlen, gleichzeitig vollständigere Liedtexte bereitzustellen.

Die Schnittstelle prüft, dass `duration` eine ganze Zahl zwischen 10 und 360 sein muss; es bleibt lediglich ein Generierungsziel und keine Garantie für die Länge des Endprodukts.

## Inspo-Funktion zur kreativen Inspiration

Die Inspo-Funktion zur kreativen Inspiration kann anhand von 1 bis 4 vollständigen Referenzaudiodateien neue Musik generieren und unterstützt das Ziehen und Ablegen oder Hochladen von Audio als Inspirationsquelle. Die API verwendet die bestehende `inspo`-Action: Der Client stellt öffentlich zugängliche Audio-URLs bereit, und der Dienst schließt die Vorbereitung der Referenzaudiodateien und die Erstellung automatisch ab, ohne dass der Client Liedtexte, Stil oder Dauer einzeln auslesen und dann die Anfrage zusammensetzen muss. Sie unterscheidet sich sowohl vom obigen Bereichs-Sampling als auch vom Cover, das den Stil des Originalsongs nachbildet. Bei der Verwendung müssen die folgenden Parameter ausgefüllt werden:

- action: Der Inhalt ist `inspo`.
- audio_urls: Eine Liste der URLs der Referenzaudiodateien; es müssen 1 bis 4 öffentlich zugängliche Audioadressen bereitgestellt werden.
- model: Das verwendete Modell, empfohlen wird `chirp-v6`.
- prompt: Liedtext oder kreativer Hinweistext (optional).
- instrumental: Wenn auf `true` gesetzt, wird auf Anfrage reine Instrumentalmusik generiert, ohne Liedtext zu verwenden.
- persona_id: Verwendet auf Dienstkanälen, die diese Kombination unterstützen, eine angegebene Stimme; die Referenzaudiodateien werden während der Vorbereitungsphase an die für diese Stimme erforderliche Ressourcenumgebung gebunden.
- lyric_prompt: Wird zur automatischen Generierung von Liedtexten verwendet, wenn `custom=true` und kein `lyric` bereitgestellt wurde.

> Hinweis: Referenzaudiodateien müssen öffentlich zugängliche Audiodateien sein. Wenn eine Referenzaudiodatei vollständig mit einer bekannten Aufnahme in der Musikbibliothek der Plattform übereinstimmt, kann Suno die Generierung aufgrund einer Urheberrechtsprüfung ablehnen. Es wird empfohlen, eigene oder von Suno generierte Audiodateien als Inspirationsquelle zu verwenden.

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynchroner Rückruf

Da Suno relativ lange zur Musikgenerierung benötigt, etwa 1–2 Minuten, bleibt die HTTP-Anfrage bei einer längeren Nichtreaktion der API stets verbunden, was zu zusätzlichem Verbrauch von Systemressourcen führt. Daher bietet diese API auch Unterstützung für asynchrone Rückrufe.

Der gesamte Ablauf ist: Wenn der Client eine Anfrage initiiert, gibt er zusätzlich ein Feld `callback_url` an. Nachdem der Client die API-Anfrage initiiert hat, gibt die API sofort ein Ergebnis zurück, das ein Feld `task_id` enthält, welches die aktuelle Aufgaben-ID repräsentiert. Wenn die Aufgabe abgeschlossen ist, wird das Ergebnis der Musikgenerierung als POST-JSON an die vom Client angegebene `callback_url` gesendet, die ebenfalls das Feld `task_id` enthält. Auf diese Weise können die Aufgabenergebnisse über die ID zugeordnet werden.

Im Folgenden sehen wir uns anhand eines Beispiels an, wie genau vorzugehen ist.
