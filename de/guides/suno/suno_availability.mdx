---
title: "Suno Audio-Verfügbarkeitsprüfungs-API"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` sucht anhand von `audio_id` nach positiven Nachweisen dafür, dass das Audio auf der aktuellen Route weiterverarbeitet werden kann. Kann vor Vorgängen wie Fortsetzung, Cover usw. aufgerufen werden; das Ergebnis spiegelt nur den Status zum Zeitpunkt der Prüfung wider und garantiert nicht, dass ein bestimmter Vorgang unbedingt erfolgreich ist. Diese Schnittstelle gibt synchron zurück, benötigt ein API-Token und zieht derzeit keine Credits ab.

`audio_id` ist die Song-ID, die von einer abgeschlossenen Suno-Aufgabe zurückgegeben wird, nicht `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Beispiel für eine erfolgreiche Antwort:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

Bei erfolgreicher Prüfung kann `data.available` nur `true` sein. Der von einigen Routen zurückgegebene „nicht online“-Status kann nicht beweisen, dass nachfolgende Vorgänge wie Fortsetzungen nicht erfolgreich sein können; daher gibt diese Schnittstelle bei fehlender Bestätigung `503 availability_unknown` zurück und gibt nicht `false` zurück. Bei einem falschen `audio_id`-Format wird 400 zurückgegeben, bei Ratenbegrenzung oder Upstream-Fehlern wird ebenfalls eine Fehlerantwort zurückgegeben. Der Status kann sich zwischen Abschluss der Prüfung und dem tatsächlichen Vorgang weiterhin ändern.
