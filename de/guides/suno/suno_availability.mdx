title: "Suno Audio- und Stimmverfügbarkeitsprüfungs-API"

---

`POST /suno/availability` akzeptiert eine Ressourcen-ID. Übergeben Sie für Songs `audio_id`, für Stimmen `persona_id`; eines von beiden ist erforderlich. Die Prüfung wird synchron abgeschlossen, erfordert einen API-Token und zieht derzeit keine Credits ab.

## Anfrage

`audio_id` stammt aus einer abgeschlossenen Song-Aufgabe und kann für eine Prüfung vor dem Fortsetzen oder Covern verwendet werden.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

`persona_id` stammt aus dem Ergebnis der Stimmerstellung. Verwenden Sie die ursprüngliche Anwendung und Anruferidentität und senden Sie den folgenden Anfragekörper über einen Erstellungspfad, der Stimmabfragen unterstützt.

```json
{"persona_id":"33333333-3333-4333-8333-333333333333"}
```

## Antwort

Beide Anfragearten verwenden dieselbe erfolgreiche Antwort. `data.id` ist die Ressourcen-ID dieser Abfrage.

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

`available: true` bedeutet, dass diese Prüfung positive Nachweise erhalten hat. Bei Stimmen prüft die Abfrage die Erstellungszugehörigkeit und bestätigt, dass das zugehörige Konto aktuell als online gemeldet wird. Die tatsächlichen Generierungsergebnisse richten sich weiterhin nach der Generierungsaufgabe.

Private geklonte Stimmen, die über `/suno/voices` erstellt wurden, hängen vom Erstellungskonto ab. Wenn bestätigt wird, dass dieses Konto aktuell offline ist, gibt die Schnittstelle HTTP 200 zurück, und `data` sieht beispielsweise wie folgt aus.

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

Clients können diese Stimme als aktuell nicht verfügbar markieren und später erneut abfragen.

Wenn keine Bestätigung möglich ist, werden HTTP 503 und `availability_unknown` zurückgegeben, beispielsweise wenn die Ressource nicht gefunden werden kann, bei alten Datensätzen der Erstellungspfad fehlt oder die Abfrage ein Timeout erreicht. Öffentliche Sänger-Stile können kontenübergreifend verwendet werden und geben ebenfalls 503 zurück, wenn das Erstellungskonto offline ist. Song-Abfragen geben weiterhin nur dann `available: true` zurück, wenn die Verfügbarkeit bestätigt ist.

Senden Sie pro Anfrage nur eine gültige UUID. Wenn alle Pfade Anfragen mit beiden IDs oder ohne beide IDs erhalten, geben sie HTTP 400 zurück. Pfade, die nur Song-Abfragen unterstützen, geben HTTP 400 zurück, wenn sie eine Anfrage erhalten, die nur `persona_id` enthält. Verringern Sie bei HTTP 429 die Abfragefrequenz.
