---
title: "Suno-Audioverfügbarkeitsprüfungs-API"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` sucht anhand von `audio_id` nach positiven Hinweisen darauf, dass Audio auf der aktuellen Route weiterverarbeitet werden kann. Die API kann vor Vorgängen wie Fortsetzungen oder Coverversionen aufgerufen werden; das Ergebnis spiegelt nur den Status zum Prüfzeitpunkt wider und garantiert nicht, dass ein bestimmter Vorgang erfolgreich sein wird. Diese Schnittstelle antwortet synchron, erfordert ein API-Token und verbraucht derzeit keine Credits.

`audio_id` ist die Song-ID einer abgeschlossenen Suno-Aufgabe, nicht `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Beispiel für eine erfolgreiche Antwort:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

Wenn die Prüfung erfolgreich ist, lautet `data.available` `true`; wenn keine Bestätigung möglich ist, wird `503 availability_unknown` zurückgegeben und `false` nicht zurückgegeben. Bei einem ungültigen Format von `audio_id` wird 400 zurückgegeben; auch bei Ratenbegrenzungen oder Dienstfehlern wird eine Fehlerantwort zurückgegeben. Der Status kann sich zwischen dem Abschluss der Prüfung und dem tatsächlichen Vorgang weiterhin ändern.
