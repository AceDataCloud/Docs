Die AI Chat v2 API (`/aichat2/conversations`) ist eine neue Generation der Konversationsschnittstelle und stellt ein umfassendes Upgrade der [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations) dar. Auf Grundlage der einfachen, verwalteten Mehrfachkonversationen von v1 erweitert sie die Funktionen um:

- **Multimodale Benutzereingaben**: Über das strukturierte Feld `message` können Text-, Bild- und Dateiblöcke direkt übertragen werden, ohne sie zuvor indirekt über `references` anhängen zu müssen.
- **Agentenbasierte Tool-Aufrufe**: Eine integrierte Sammlung von Tools für die Online-Suche, das Abrufen von Webseiten, das Lesen von Dateien usw. ist enthalten. Außerdem können vom Benutzer autorisierte MCP-Server (Google Drive, Notion, Slack, GitHub usw.) eingebunden werden. Das Modell kann innerhalb einer einzigen Anfrage autonom mehrere Tool-Aufrufe durchführen, um komplexe Aufgaben zu erledigen.
- **Strukturierte Streaming-Ereignisse**: Über `accept: text/event-stream` oder `application/x-ndjson` können Ereignisse wie `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card` und `artifact` Token für Token abgerufen werden, sodass sie im Frontend entsprechend ihrem jeweiligen Typ separat dargestellt werden können.
- **Unterbrechbar / Wiederaufnehmbar**: Wenn das Modell zusätzliche Informationen vom Benutzer benötigt, sendet es ein `ask_user_question`-Ereignis und pausiert. Beim nächsten Aufruf kann die Antwort über `tool_results` zurückgegeben werden, damit die Verarbeitung fortgesetzt werden kann.
- **Neue CRUD-Aktionen**: Über das Feld `action` können auf demselben Endpoint die Aktionen `retrieve` / `retrieve_batch` / `update` / `delete` ausgeführt werden, ohne dass eine zusätzliche API zur Sitzungsverwaltung erforderlich ist.
- **Kontinuierlich aktualisierte Modellliste**: Standardmäßig werden aktuelle Modelle wie GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4 und Kimi K3 unterstützt.

Gleichzeitig ist die API auf Ebene des Anfrage-Bodys **vollständig abwärtskompatibel mit v1**: Es genügt, nur `model` + `question` (+ optional `stateful` / `id` / `references` / `preset`) zu übermitteln, um eine mit v1 gleichwertige JSON-Antwort im Format `{answer, id}` zu erhalten. Daher ist bei der Migration von `/aichat/conversations` keine Neuentwicklung des Clients erforderlich. Es muss lediglich der Pfad in `/aichat2/conversations` geändert werden.

> Wenn Sie derzeit `/aichat/conversations` verwenden, bleibt die alte Schnittstelle weiterhin verfügbar. Sie können die Migration nach Ihrem eigenen Zeitplan durchführen.

Um die AI Chat v2 API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihr API-Token abzurufen und für die spätere Verwendung bereitzuhalten.

## Grundlegende Verwendung

Die einfachste Verwendung ist vollständig identisch mit v1: Übermitteln Sie `model` + `question` und erhalten Sie `{answer, id}`.

CURL-Beispiel:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Rückgabeergebnis:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python-Beispiel:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Mehrfachkonversationen

Wie bei v1 können Sie `stateful: true` übermitteln, um die Speicherung der Konversation zu aktivieren. Die API gibt eine `id` zurück. Bei nachfolgenden Anfragen müssen Sie lediglich dieselbe `id` erneut übermitteln, um die Konversation fortzusetzen, ohne den Nachrichtenverlauf selbst verwalten zu müssen.

Erste Anfrage:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Rückgabe:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Zweite Anfrage: Übermitteln Sie dieselbe `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "Wie lautet die Zahl, die ich dich gerade gebeten habe, dir zu merken?"
  }'
```

```json
{
  "answer": "Die Zahl, die du mich gebeten hast, mir zu merken, ist 42.",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` ist standardmäßig `true`. Das Weglassen des Parameters ist gleichbedeutend mit der expliziten Angabe von `true`. Wenn `stateful: false` festgelegt wird, wird das Laden des bisherigen Gesprächsverlaufs übersprungen. Dies bedeutet nicht, dass das Ergebnis dieser Runde nicht gespeichert wird, und gilt nicht für Tool-Abläufe, die nach einer Unterbrechung fortgesetzt werden müssen.

### Lange Gespräche und Beibehaltung des Originaltexts

Die Kontextkomprimierung organisiert lediglich die Inhalte, die in dieser Runde an das Modell gesendet werden, und ersetzt nicht die gespeicherten Chatverläufe. Über `action: retrieve` können weiterhin alle vollständig gespeicherten Nachrichten abgerufen werden; explizite Bearbeitungen und Löschungen von Gesprächen werden weiterhin entsprechend der Anfrage ausgeführt.

Das Modell kann innerhalb des aktuellen Gesprächs den ursprünglichen Verlauf durchsuchen und seitenweise auslesen. Wenn ein Artikel weiterbearbeitet, auf Zahlen verwiesen oder eine Veröffentlichung vorbereitet werden soll, muss der entsprechende Originaltext ausgelesen werden. Eine Zusammenfassung darf den vollständigen Text nicht ersetzen. Diese Funktion stellt keine Nachrichten automatisch wieder her, die bereits in älteren Versionen verloren gegangen sind.

Falls die Kontextorganisation fehlschlägt, behalte die Sitzungs-ID bei und überprüfe das `error`-Ereignis. Der Dienst wird den Originaltext nicht durch eine leere Zusammenfassung überschreiben. Tool-Operationen, die vor dem Fehler bereits abgeschlossen wurden, können weiterhin wirksam sein. Bitte überprüfe zuerst deren Ergebnisse, um eine doppelte Generierung oder Veröffentlichung zu vermeiden. Wenn eine einzelne Sitzung das Speicherlimit erreicht, wird eine eindeutige Fehlermeldung ausgegeben. Bereits gespeicherte Datensätze schaffen durch Kürzung keinen zusätzlichen Speicherplatz. Du kannst die benötigten Inhalte exportieren und anschließend eine neue Sitzung starten.

## Streaming-Antworten

v2 unterstützt zwei Streaming-Formate, die über den `accept`-Header ausgewählt werden:

| Szenario                    | `accept`               | Datenformat                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web-Frontend / EventSource  | `text/event-stream`    | `data: {json}\n\n`, letzte Zeile `data: [DONE]\n\n` |
| Server / CLI / Node-Streaming-Parsing | `application/x-ndjson` | Ein JSON-Objekt pro Zeile                               |
| Kein Streaming erforderlich                 | `application/json` (Standard) | Einmalige Rückgabe von `{answer, id}`                       |

### NDJSON-Beispiel

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "Stelle Hangzhou in drei Sätzen vor.",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # Kompatibel mit v1: Das inkrementelle Fragment wird gleichzeitig über das Feld delta_answer bereitgestellt
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Jede NDJSON-Zeile ist ein strukturiertes Ereignis. Am häufigsten tritt `text_delta` auf:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE-Beispiel

Da `EventSource` im Browser keine benutzerdefinierten Request-Bodys unterstützt, wird empfohlen, `fetch` mit einer manuellen Aufteilung anhand von `\n\n` zu verwenden:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "Stelle Hangzhou in drei Sätzen vor.",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Streaming-Ereignistypen

| `type`              | Bedeutung                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Inkrementelles Textfragment der Assistentenantwort. `content` enthält den neu hinzugefügten Inhalt. Zur Kompatibilität mit v1 enthält dasselbe Ereignis auch `delta_answer` (entspricht `content`) und `id`. |
| `thinking`          | Denkprozess des Modells (wird nur angezeigt, wenn das ausgewählte Modell Reasoning offenlegt).                                                                                      |
| `tool_use`          | Das Modell entscheidet, ein Tool aufzurufen. Das Ereignis enthält `tool_id`, `tool_name` und `input`.                                                                        |
| `tool_result`       | Ergebnis der Tool-Ausführung, wird über `tool_id` dem vorherigen `tool_use` zugeordnet. `is_error` kennzeichnet, ob ein Fehler aufgetreten ist.                                                             |
| `card`              | Strukturierte Karte, die von einem Tool erzeugt wurde (z. B. Bild- oder Linkvorschau), geeignet für die direkte Darstellung.                                                                                          |
| `citation`          | Ergänzt die Quellen-URL für das entsprechende Textfragment.                                                                                                  |
| `ask_user_question` | Wird ausgegeben, wenn das Modell zusätzliche Informationen vom Benutzer benötigt. Das Gespräch wechselt in den Status `awaiting_user_input`. Weitere Informationen findest du unten unter [Unterbrochene Gespräche fortsetzen](#恢复暂停的对话).                                                 |
| `artifact`          | Eigenständiges, vom Modell generiertes Ergebnis (z. B. Codeblock oder Dokument), das gespeichert oder heruntergeladen werden kann.                                                                                            |
| `system_message`    | Systemhinweis (kein Inhalt von Benutzer oder Assistent), der ausschließlich für UI-Hinweise verwendet wird.                                                                                           |
| `compact`           | Der Modellkontext wurde organisiert; die gespeicherten Originalnachrichten bleiben unverändert. Der Client muss den Chatverlauf nicht löschen.                                                                                    |
| `error`             | In dieser Runde ist ein Fehler aufgetreten. `message` beschreibt den Fehlerinhalt.                                                                                              |
| `done`              | Der endgültige Gesprächsdatensatz dieser Runde wurde erfolgreich gespeichert. Enthält `usage` (einschließlich `prompt_tokens` / `completion_tokens` / `total_tokens`) und `terminal_reason`. Ob die Aufgabe abgeschlossen wurde, muss weiterhin anhand des Beendigungsgrundes beurteilt werden.              |
Für Clients, die sich nur für die endgültige Antwort interessieren, ist das Zusammenfügen aller `content`-Felder aus `text_delta` gleichbedeutend mit dem `answer` im Modus `application/json`.

## Multimodale Eingaben

Wenn die Benutzereingabe Bilder oder Dateien enthält, übergib statt `question` das Feld `message` (als Array). Jedes Array-Element ist ein Inhaltsblock:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "Wie viele Katzen sind auf diesem Bild?" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Unterstützte Blocktypen:

- `text` — Normaler Text, das Feld `text` ist erforderlich.
- `image_url` — Bild, `image_url.url` ist erforderlich.
- `file_url` — Datei (PDF, CSV, TXT usw.), `file_url.url` ist erforderlich.

### Beziehung zu v1 `references`

Aus Gründen der Abwärtskompatibilität mit älteren Clients erkennt v2 weiterhin das Feld `references: ["https://...", ...]`:

- URL-Endungen `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif` werden automatisch in `image_url`-Blöcke umgewandelt;
- andere Dateiendungen werden in `file_url`-Blöcke umgewandelt;
- wenn gleichzeitig `question` angegeben wird, wird es als vorangestellter `text`-Block eingefügt.

Wenn du also nur von v1 migrieren möchtest, ohne den Request-Body zu ändern, musst du lediglich den Pfad in `/aichat2/conversations` ändern. Die bisherige Verwendung von `references` funktioniert weiterhin wie gewohnt.

Wenn du eine genauere Kontrolle benötigst (z. B. mehrere Bilder zwischen Textabschnitten platzieren oder eine bestimmte Reihenfolge einhalten möchtest), verwende direkt das `message`-Array.

## Tool-Aufrufe und MCP

Die wichtigste Erweiterung von v2 besteht darin, dass das Modell eigenständig Tools aufrufen kann, um mehrstufige Aufgaben zu erledigen. **Diese Funktion ist standardmäßig aktiviert** und erfordert keine zusätzlichen Konfigurationen im Request des Clients. Häufige Anwendungsfälle:

- Der Benutzer fragt: „Suche bitte nach aktuellen neuen Ausstellungen in Shanghai“ → Das Modell ruft die integrierte Websuche auf → Fasst die Ergebnisse zu einer Antwort zusammen.
- Der Benutzer fragt: „Lies diese PDF-Datei und schreibe anschließend eine Zusammenfassung“ → Das Modell ruft `file_read` auf → Erstellt die Zusammenfassung.
- Der Benutzer hat Google Drive / GitHub / Notion usw. unter [Connections](https://platform.acedata.cloud/connections) autorisiert → Das Modell kann die entsprechenden MCP-Tools aufrufen, um deren Daten zu lesen und zu schreiben.

In NDJSON- / SSE-Streams werden Tool-Aufrufe durch zwei Ereignistypen dargestellt: `tool_use` und `tool_result`, beispielsweise:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Wenn du die Details der Tool-Aufrufe nicht im Frontend anzeigen möchtest, kannst du die Ereignistypen `tool_use` / `tool_result` / `card` / `citation` einfach ignorieren. Die endgültige Ausgabe des Modells wird weiterhin über `text_delta` gestreamt.

Mit `max_turns` kannst du begrenzen, wie viele Runden das Modell während dieser Anfrage maximal eigenständig Tools aufrufen darf. Der zulässige Bereich liegt bei 1–500. Wenn der Wert weggelassen wird, beträgt der Standardwert 500. Wenn du einen kleinen Wert festlegst (z. B. `max_turns: 1`), kannst du eine einmalige Antwort erzwingen, bei der keine Tool-Aufrufe erlaubt sind.

## Asynchrone Ausführung und Autorisierung für unbeaufsichtigte Aufgaben

Wenn dein Aufruf von einem Alert-Webhook, einem CI/CD-System, einem Überwachungssystem oder einer anderen Hintergrundaufgabe stammt, kannst du `async: true` festlegen, damit die Schnittstelle sofort eine Aufgaben-ID zurückgibt, während die Ausführung im Hintergrund fortgesetzt wird:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Mein Dienst hat einen Alarm ausgelöst. Benachrichtige die WeChat-Gruppe „AceDataCloud团队“ über mein persönliches WeChat-Konto …"
}
```

Beispiel für eine Rückgabe:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Anschließend kannst du mit `action: retrieve` und `id` das Sitzungsergebnis abrufen. Alternativ kannst du `callback_url` angeben. Nach Abschluss der Aufgabe sendet die Plattform dann `{ status, answer, usage, error }` per POST an deine Callback-Adresse. `callback_url` muss `http` / `https` verwenden und darf weder direkt auf `localhost` noch auf eine private IP-Adresse als Literal verweisen.

Bei Hintergrundaufgaben gibt es normalerweise niemanden, der eine Bestätigung anklicken kann. Wenn du möchtest, dass bestimmte Skills oder MCP Server im unbeaufsichtigten Modus Aktionen wie Senden, Veröffentlichen oder Schreiben ausführen dürfen, übermittle ausdrücklich eine Liste der vorab autorisierten Elemente im Request-Body:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Mein Dienst hat einen Alarm ausgelöst. Benachrichtige die WeChat-Gruppe „AceDataCloud团队“ über mein persönliches WeChat-Konto …"
}
```

Die Werte in `allowed_skills` sind die Slugs der verbundenen Skills; die Werte in `allowed_mcp_servers` sind die Slugs der verbundenen MCP Server. Skills / MCP Server, die nicht in der Liste der vorab autorisierten Elemente enthalten sind, dürfen im unbeaufsichtigten Modus weiterhin nur eine Vorschau oder einen Dry-Run ausführen oder Schreibvorgänge ablehnen.

Wenn du eine detailliertere Steuerung benötigst, kannst du auch das gleichwertige Objekt `unattended_policy` verwenden:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Die Vorabautorisierung besteht ausschließlich aus diesen beiden Listen: Ist eine Liste leer, werden keine entsprechenden Berechtigungen erteilt. Ein zusätzliches Aktivierungsfeld ist nicht erforderlich.

Hinweis: Die Vorabautorisierung bedeutet lediglich, dass diese Fähigkeiten bei der aktuellen Anfrage im unbeaufsichtigten Modus die manuelle Bestätigung umgehen dürfen. Der jeweilige Skill muss weiterhin `--unattended-confirm` oder einen entsprechenden Sicherheitsmechanismus unterstützen. Andernfalls führt er weiterhin nur einen Dry-Run aus und nimmt keine Schreibvorgänge direkt vor.

## Fortsetzen pausierter Unterhaltungen

Bei bestimmten Tools kann das Modell dem Benutzer eine Rückfrage stellen. In diesem Fall gibt das Modell ein `ask_user_question`-Ereignis aus, und die Unterhaltung wird im Status `awaiting_user_input` eingefroren:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Möchtest du den Bericht auf Chinesisch oder Englisch erstellen?",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Stelle dieses Ereignis im Frontend als Karte dar, damit der Benutzer eine Antwort auswählen kann. Starte anschließend mit derselben `id` die nächste Anfrage und übermittle die Antwort über `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

Die `tool_use_id` im Request-Body **muss** exakt mit der `tool_id` zum Zeitpunkt der Unterbrechung übereinstimmen; andernfalls wird ein Fehler 400 zurückgegeben. Wenn die Anfrage gleichzeitig `tool_results` enthält, werden `question` / `message` / `references` ignoriert.

Wenn der Benutzer beschließt, diese Frage aufzugeben, kann einfach eine neue `question` / `message` übergeben werden. Die Plattform markiert den pausierten Tool-Aufruf automatisch als „vom Benutzer übersprungen“.
