Die AI Chat v2 API (`/aichat2/conversations`) ist eine Dialogschnittstelle der neuen Generation und eine umfassend aktualisierte Version der [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Auf Grundlage der Einfachheit und der verwalteten Mehrfachdialoge von v1 erweitert sie:

- **Multimodale Benutzereingaben**: Text + Bild + Dateiblöcke können direkt über das strukturierte Feld `message` übergeben werden, ohne sie zuvor indirekt über `references` anzuhängen.
- **Agent-basierte Tool-Aufrufe**: Enthält eine integrierte Reihe von Tools für Online-Suche, Webseitenerfassung, Dateilesen usw. und kann außerdem vom Benutzer autorisierte MCP-Server (Google Drive, Notion, Slack, GitHub usw.) einbinden. Das Modell kann Tools innerhalb einer Anfrage mehrfach autonom aufrufen, um komplexe Aufgaben zu erledigen.
- **Strukturierte Streaming-Ereignisse**: Über `accept: text/event-stream` oder `application/x-ndjson` können Ereignisse wie `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` usw. Token für Token abgerufen werden, damit sie im Frontend nach dem jeweiligen Typ separat gerendert werden können.
- **Unterbrechbar / fortsetzbar**: Wenn das Modell zusätzliche Informationen vom Benutzer benötigt, sendet es ein `ask_user_question`-Ereignis und pausiert. Beim nächsten Aufruf kann die Antwort über `tool_results` zurückgefüllt werden, um fortzufahren.
- **Neue CRUD-Aktionen**: Über das Feld `action` können auf demselben Endpoint `retrieve` / `retrieve_batch` / `update` / `delete` ausgeführt werden, ohne dass eine zusätzliche API zur Sitzungsverwaltung erforderlich ist.
- **Kontinuierlich aktualisierte Modellliste**: Standardmäßig sind moderne Modelle wie GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 usw. angebunden.

Gleichzeitig ist sie auf Request-Body-Ebene **vollständig abwärtskompatibel mit v1**: Wenn nur `model` + `question` (+ optional `stateful` / `id` / `references` / `preset`) übergeben werden, erhalten Sie eine zu v1 äquivalente JSON-Antwort `{answer, id}`. Daher muss beim Wechsel von `/aichat/conversations` kein Client neu geschrieben werden; es genügt, den Pfad auf `/aichat2/conversations` zu ändern.

> Wenn Sie derzeit `/aichat/conversations` verwenden, bleibt die alte Schnittstelle weiterhin verfügbar und Sie können in Ihrem eigenen Tempo migrieren.

## Antragsprozess

Um die AI Chat v2 API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten und ihn als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zu dieser Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen; Sie müssen nicht für jeden Dienst separat einen Antrag stellen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Guthaben zum kostenlosen Testen; bei unzureichendem Guthaben können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) das allgemeine Guthaben aufladen.

## Grundlegende Verwendung

Die einfachste Verwendung ist vollständig identisch mit v1: Übergeben Sie `model` + `question` und erhalten Sie `{answer, id}`.

CURL-Beispiel:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Rückgabeergebnis:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python-Beispiel:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Mehrfachdialoge

Wie bei v1 aktiviert die Übergabe von `stateful: true` die Sitzungsspeicherung, und die API gibt eine `id` zurück; bei nachfolgenden Anfragen genügt es, die `id` erneut mitzusenden, um den Dialog fortzusetzen, ohne den Nachrichtenverlauf selbst verwalten zu müssen.

Erste Anfrage:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Rückgabe:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Zweite Anfrage, mit derselben `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "Welche Zahl habe ich dich gerade gebeten, dir zu merken?"
  }'
```

```json
{
  "answer": "Die Zahl, die du mich gebeten hast, mir zu merken, ist 42.",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` ist standardmäßig `true`; das Weglassen ist gleichbedeutend mit der expliziten Übergabe von `true`. Das Setzen von `stateful: false` überspringt das Laden des vorherigen Gesprächsverlaufs; dies bedeutet nicht, dass das Ergebnis dieser Runde nicht gespeichert wird, und gilt auch nicht für Tool-Abläufe, die nach einer Pause fortgesetzt werden müssen.

### Lange Gespräche und Beibehaltung des Originaltexts

Die Kontextkomprimierung organisiert nur die in dieser Runde an das Modell gesendeten Inhalte und ersetzt nicht die gespeicherten Chat-Aufzeichnungen. Über `action: retrieve` können weiterhin die vollständig gespeicherten Nachrichten gelesen werden; explizites Bearbeiten oder Löschen von Gesprächen bleibt entsprechend der Anfrage wirksam.

Das Modell kann innerhalb des aktuellen Gesprächs suchen und den historischen Originaltext seitenweise lesen. Wenn ein Artikel weiter bearbeitet, Zahlen zitiert oder eine Veröffentlichung vorbereitet werden soll, sollte der entsprechende Originaltext gelesen werden; eine Zusammenfassung darf nicht anstelle des Haupttexts verwendet werden. Diese Fähigkeit stellt Nachrichten, die in alten Versionen bereits verloren gegangen sind, nicht automatisch wieder her.

Falls die Kontextorganisation fehlschlägt, behalten Sie die Gesprächs-ID bei und prüfen Sie das Ereignis `error`; der Dienst überschreibt den Originaltext nicht mit einer leeren Zusammenfassung. Tool-Operationen, die vor dem Fehler bereits abgeschlossen wurden, können weiterhin wirksam sein; fragen Sie zuerst ihre Ergebnisse ab, um eine doppelte Generierung oder Veröffentlichung zu vermeiden. Wenn ein einzelnes Gespräch das Speicherlimit erreicht, wird ein eindeutiger Fehler gemeldet; bereits gespeicherte Aufzeichnungen schaffen nicht durch Kürzung Platz. Exportieren Sie die benötigten Inhalte und starten Sie anschließend ein neues Gespräch.

## Streaming-Antworten

v2 unterstützt zwei Streaming-Formate, die über den `accept`-Header ausgewählt werden:

| Szenario                    | `accept`               | Datenform                                        |
| --------------------------- | ---------------------- | ------------------------------------------------ |
| Web-Frontend / EventSource  | `text/event-stream`    | `data: {json}\n\n`, letzte Zeile `data: [DONE]\n\n` |
| Server / CLI / Node-Streaming-Parsing | `application/x-ndjson` | Ein JSON-Objekt pro Zeile                        |
| Kein Streaming erforderlich | `application/json`（Standard） | Einmalige Rückgabe von `{answer, id}`            |

### NDJSON-Beispiel

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "Stelle Hangzhou in drei Sätzen vor.",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # Kompatibel mit v1: Inkrementelle Fragmente werden gleichzeitig über das Feld delta_answer bereitgestellt
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Jede NDJSON-Zeile ist ein strukturiertes Ereignis; am häufigsten ist `text_delta`:

```json
{"type":"text_delta","content":"Hang","delta_answer":"Hang","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"zhou","delta_answer":"zhou","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"ist","delta_answer":"ist","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE-Beispiel

`EventSource` unterstützt im Browser keine benutzerdefinierten Request-Bodies; empfohlen wird `fetch` + manuelles Parsen in Abschnitten anhand von `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "Stelle Hangzhou in drei Sätzen vor.",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Streaming-Ereignistypen

| `type`              | Bedeutung                                                                                                                    |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Inkrementelles Textfragment der Assistentenantwort. `content` enthält den neuen Inhalt; zur Kompatibilität mit v1 enthält dasselbe Ereignis auch `delta_answer` (gleich `content`) und `id`. |
| `thinking`          | Denkprozess des Modells (erscheint nur, wenn das ausgewählte Modell Reasoning offenlegt).                                    |
| `tool_use`          | Das Modell entscheidet sich, ein Tool aufzurufen; das Ereignis enthält `tool_id`, `tool_name`, `input`.                     |
| `tool_result`       | Tool-Ausführungsergebnis, über `tool_id` mit dem vorherigen `tool_use` gekoppelt; `is_error` kennzeichnet, ob es fehlgeschlagen ist. |
| `card`              | Vom Tool erzeugte strukturierte Karte (z. B. Bild, Link-Vorschau), geeignet für direktes Rendern.                           |
| `citation`          | Quell-URL zur Ergänzung der Zitate des entsprechenden Textfragments.                                                        |
| `ask_user_question` | Wird ausgegeben, wenn das Modell zusätzliche Informationen vom Nutzer benötigt; das Gespräch wechselt in den Status `awaiting_user_input`, siehe unten [Pausierte Gespräche fortsetzen](#pausierte-gespräche-fortsetzen). |
| `artifact`          | Eigenständiges vom Modell erzeugtes Artefakt (z. B. Codeblock, Dokument), das gespeichert oder heruntergeladen werden kann. |
| `system_message`    | Systemhinweis (kein Nutzer- oder Assistenteninhalt), nur für UI-Hinweise.                                                   |
| `compact`           | Der Modellkontext wurde organisiert; gespeicherte Originalnachrichten bleiben unverändert, der Client muss keine Chat-Aufzeichnungen löschen. |
| `error`             | In dieser Runde ist ein Fehler aufgetreten; `message` beschreibt den Fehlerinhalt.                                          |
| `done`              | Die endgültige Gesprächsaufzeichnung dieser Runde wurde erfolgreich gespeichert und enthält `usage` (einschließlich `prompt_tokens` / `completion_tokens` / `total_tokens`) sowie `terminal_reason`; es muss weiterhin anhand des Beendigungsgrundes beurteilt werden, ob die Aufgabe abgeschlossen ist. |
Für Clients, die sich nur um die endgültige Antwort kümmern, ist das Zusammenfügen aller `content` von `text_delta` äquivalent zu `answer` im Modus `application/json`.

## Multimodale Eingabe

Wenn die Benutzereingabe Bilder oder Dateien enthält, übergeben Sie `message` (Array) anstelle von `question`. Jedes Array-Element ist ein Inhaltsblock:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Unterstützte Blocktypen:

- `text` — Klartext, Feld `text` erforderlich.
- `image_url` — Bild, `image_url.url` erforderlich.
- `file_url` — Datei (PDF, CSV, TXT usw.), `file_url.url` erforderlich.

### Beziehung zu v1 `references`

Um mit alten Clients kompatibel zu bleiben, erkennt v2 weiterhin das Feld `references: ["https://...", ...]`:

- Die URL-Endung ist `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, wird automatisch in einen `image_url`-Block umgewandelt;
- andere Erweiterungen werden in `file_url`-Blöcke umgewandelt;
- wenn gleichzeitig noch `question` bereitgestellt wird, wird es als `text`-Block vorangestellt.

Wenn Sie daher nur von v1 migrieren möchten und den Request-Body nicht ändern wollen, wechseln Sie einfach den Pfad zu `/aichat2/conversations`; die bisherige Verwendung von `references` funktioniert weiterhin wie gewohnt.

Wenn Sie eine präzisere Steuerung benötigen (z. B. mehrere Bilder zwischen Text platzieren oder wenn die Reihenfolge wichtig ist), verwenden Sie direkt das `message`-Array.

## Tool-Aufrufe und MCP

Die zentrale Erweiterung von v2 besteht darin, dass das Modell Tools selbstständig aufrufen kann, um mehrstufige Aufgaben zu erledigen, **dies ist standardmäßig aktiviert**, und der Client muss keine zusätzliche Konfiguration im Request vornehmen. Häufige Szenarien:

- Der Benutzer fragt „Hilf mir, nachzusehen, welche neuen Ausstellungen es kürzlich in Shanghai gibt“ → Das Modell ruft die integrierte Websuche auf → Es bereitet die Ergebnisse als Antwort auf.
- Der Benutzer fragt „Lies dieses PDF und schreibe dann eine Zusammenfassung“ → Das Modell ruft file_read auf → Es schreibt eine Zusammenfassung.
- Der Benutzer hat in [Connections](https://platform.acedata.cloud/connections) Google Drive / GitHub / Notion usw. autorisiert → Das Modell kann die entsprechenden MCP-Tools aufrufen, um deren Daten zu lesen und zu schreiben.

Im NDJSON-/SSE-Stream werden Tool-Aufrufe durch die beiden Ereignistypen `tool_use` und `tool_result` dargestellt, zum Beispiel:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Wenn Sie die Details der Tool-Aufrufe nicht im Frontend anzeigen möchten, ignorieren Sie einfach die Ereignistypen `tool_use` / `tool_result` / `card` / `citation`; die endgültige Ausgabe des Modells wird weiterhin über `text_delta` gestreamt.

`max_turns` kann die maximale Anzahl an Runden begrenzen, in denen das Modell innerhalb dieser Anfrage selbst Tools aufruft; der Bereich liegt bei 1–500, bei Auslassung ist der Standardwert 500. Wenn Sie ihn klein setzen (z. B. `max_turns: 1`), können Sie eine einmalige Antwort erzwingen und jegliche Tool-Aufrufe verbieten.

## Asynchrone Ausführung und unbeaufsichtigte Autorisierung

Wenn Ihr Aufruf von einem Alarm-Webhook, CI/CD, Überwachungssystem oder einer anderen Hintergrundaufgabe stammt, können Sie `async: true` setzen, damit die Schnittstelle sofort eine Aufgaben-ID zurückgibt und die Ausführung im Hintergrund fortsetzt:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Rückgabebeispiel:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Danach können Sie mit `action: retrieve` + `id` das Konversationsergebnis abfragen; Sie können auch `callback_url` bereitstellen, und nach Abschluss der Aufgabe wird die Plattform `{ status, answer, usage, error }` per POST an Ihre Callback-Adresse senden. `callback_url` muss `http` / `https` verwenden und darf nicht direkt mit `localhost` oder einer privaten IP-Literaladresse angegeben werden.

Bei Hintergrundaufgaben kann normalerweise niemand zur Bestätigung klicken. Wenn Sie möchten, dass bestimmte Skills oder MCP Server im unbeaufsichtigten Modus Aktionen wie Senden, Veröffentlichen oder Schreiben ausführen, übergeben Sie bitte explizit eine vorautorisierte Liste im Request-Body:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Die Werte in `allowed_skills` sind die Slugs der verbundenen Skills; die Werte in `allowed_mcp_servers` sind die Slugs der verbundenen MCP Server. Skills / MCP Server, die nicht in der Vorautorisierungsliste enthalten sind, können im unbeaufsichtigten Modus weiterhin nur Vorschauen anzeigen, dry-run ausführen oder Schreiboperationen ablehnen.

Wenn eine feinere Steuerung erforderlich ist, können Sie auch das gleichwertige `unattended_policy`-Objekt verwenden:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Die Vorautorisierung besteht aus diesen beiden Listen selbst: Eine leere Liste autorisiert keine Fähigkeiten, ein zusätzliches Schalterfeld ist nicht erforderlich.

Hinweis: Die Vorautorisierung bedeutet nur, dass „diese Fähigkeiten bei dieser Anfrage im unbeaufsichtigten Modus die manuelle Bestätigung überspringen dürfen“. Der konkrete Skill muss weiterhin `--unattended-confirm` oder einen entsprechenden Sicherheitsmechanismus unterstützen; andernfalls wird er weiterhin dry-run ausführen und keine Schreiboperationen direkt ausführen.

## Pausierte Konversationen fortsetzen

Einige Tools veranlassen das Modell dazu, dem Benutzer „eine Rückfrage zu stellen“. Das Modell sendet dann ein `ask_user_question`-Ereignis, und die Konversation wird im Status `awaiting_user_input` eingefroren:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Rendern Sie dieses Ereignis im Frontend als Karte, damit der Benutzer eine Antwort auswählen kann, und starten Sie dann mit derselben `id` die nächste Anfrage, wobei Sie die Antwort über `tool_results` zurückfüllen:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

Die `tool_use_id` im Request-Body **muss** exakt mit der `tool_id` beim Anhalten übereinstimmen; bei Abweichung wird 400 zurückgegeben. Wenn im Request gleichzeitig `tool_results` vorhanden ist, werden `question` / `message` / `references` alle ignoriert.

Wenn der Benutzer beschließt, diese Frage aufzugeben, übergeben Sie einfach eine neue `question` / `message`; die Plattform markiert den angehaltenen Tool-Aufruf automatisch als „vom Benutzer übersprungen“.

## Sitzungsverwaltung (CRUD)

v2 bietet über das Feld `action` auf demselben Endpoint eine leichtgewichtige Sitzungsverwaltung, ohne dass eine zusätzliche API erforderlich ist.

### `action: retrieve` —— Eine Sitzung abrufen

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Gibt das vollständige Sitzungsdokument zurück (einschließlich `messages`-Verlauf, `model`, `title`, `tools_used` usw.).

### `action: retrieve_batch` —— Sitzungszusammenfassungen auflisten

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Gibt `{ items: [...], total }` zurück. **Zusammenfassungen enthalten keine `messages`** und eignen sich für Seitenleistenlisten; wenn der Benutzer eine Sitzung öffnet, rufen Sie ihre vollständigen Nachrichten anschließend separat mit `action: retrieve` ab.

Optionale Filterparameter: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Titel ändern oder Verlauf überschreiben

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Reiseplan für Hangzhou"
}
```

`messages` kann ebenfalls übergeben werden, aber der Server führt eine strenge Schema-Validierung durch (es muss die zusammengeführte `ToolUseContent`-Form sein); bei Abweichungen wird 400 zurückgegeben. Im Allgemeinen wird empfohlen, dies nur zum Ändern von `title` zu verwenden.

### `action: delete` —— Eine Sitzung löschen

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Gibt `{ id, success: true }` zurück. Nach dem Löschen ist keine Wiederherstellung möglich; bitte rufen Sie dies erst nach Bestätigung auf.

## Reibungslose Migration von v1

Wenn Sie bereits [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations) verwenden, erfordert die Migration zu v2 kaum Codeänderungen:

1. Ändern Sie die URL von `https://api.acedata.cloud/aichat/conversations` zu `https://api.acedata.cloud/aichat2/conversations`.
2. Falls Sie zuvor einen v1-Modellnamen (wie `gpt-3.5`, `gpt-4-browsing` usw.) übergeben haben, wird beim Wechsel zu v2 empfohlen, auf aktuelle Modelle (wie `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` usw.) umzusteigen.
3. Die Felder des NDJSON-Streams bleiben abwärtskompatibel: Jedes `text_delta`-Ereignis enthält weiterhin `delta_answer` und `id`, daher müssen Clients, die ursprünglich zeilenweise `delta_answer` parsen, nicht angepasst werden.

Nach der Migration können Sie die neuen Fähigkeiten von v2 (multimodales `message`, SSE, Tool-Aufrufe, `action` CRUD) nach Bedarf aktivieren und schrittweise vorgehen.

## Fehlerbehandlung

Fehlerantworten haben ein einheitliches Format:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Häufige Fehler:

- `400 bad_request`: Fehlende Pflichtfelder, nicht übereinstimmende `tool_use_id`, ungültiges `messages`-Schema usw.
- `401 invalid_token`: Der `authorization`-Header ist nicht korrekt.
- `404 not_found`: Die Sitzung, die der `id` bei `action: retrieve / update / delete` entspricht, existiert nicht.
- `413 conversation_storage_limit`: Die Sitzung überschreitet das Speicherlimit; vorhandene gespeicherte Einträge wurden nicht überschrieben.
- `429 too_many_requests`: Das Ratenlimit wurde ausgelöst.
- `503 context_compaction_failed`: Die Kontextaufbereitung ist fehlgeschlagen; vorhandene Einträge bleiben erhalten.
- `500 conversation_persist_failed`: Das endgültige Speichern dieser Runde ist fehlgeschlagen; bereits empfangener Text bedeutet nicht, dass der endgültige Eintrag erfolgreich gespeichert wurde. Bitte fragen Sie anhand der Sitzungs-ID ab.
- `500 chat_error`: Der Dienst ist vorübergehend nicht verfügbar, oder in dieser Runde wurde kein Inhalt erzeugt (es entstehen keine Kosten).

In der Streaming-Antwort werden Fehler als Ereignis `{"type":"error","message":"..."}` ausgegeben, anschließend endet der Stream. `[DONE]` bedeutet lediglich, dass die Übertragung beendet ist; bei einem `error` darf dies nicht als Erfolg betrachtet werden, und es wird auch kein erfolgreiches `done`-Ereignis gesendet.

## Fazit

Die AI Chat v2 API bleibt abwärtskompatibel zu v1 und erweitert Gespräche von „Einzelrunden- / Mehrfachrunden-Frage-Antwort“ zu „beobachtbaren Agent-Gesprächen“: multimodale Eingaben, Tool-Aufrufe, pausierbar / fortsetzbar, strukturierte Streaming-Ereignisse und integriertes CRUD. Für neue Integrationen wird empfohlen, v2 direkt zu verwenden; bestehende v1-Integrationen können schrittweise reibungslos migriert werden. Bei Fragen kontaktieren Sie jederzeit unser technisches Support-Team.
