Die AI Chat v2 API (`/aichat2/conversations`) ist eine Dialogschnittstelle der neuen Generation und eine umfassend aktualisierte Version der [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Basierend auf der einfachen, gehosteten Mehrfachdialog-Funktion von v1 erweitert sie:

- **Multimodale Benutzereingaben**: Text- + Bild- + Dateiblöcke direkt über das strukturierte Feld `message` übergeben, ohne sie zuvor indirekt über `references` anzuhängen.
- **Agentisierte Tool-Aufrufe**: Integriert eine Reihe von Tools wie Internetsuche, Webseitenabruf, Dateilesen usw. und kann vom Benutzer autorisierte MCP-Server (Google Drive, Notion, Slack, GitHub usw.) einbinden. Das Modell kann in einer Anfrage eigenständig mehrere Tool-Aufrufe durchführen, um komplexe Aufgaben abzuschließen.
- **Strukturierte Streaming-Ereignisse**: Über `accept: text/event-stream` oder `application/x-ndjson` können tokenweise Ereignisse wie `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` usw. abgerufen werden, um sie im Frontend nach Typ getrennt zu rendern.
- **Unterbrechbar / fortsetzbar**: Wenn das Modell zusätzliche Informationen vom Benutzer benötigt, sendet es ein `ask_user_question`-Ereignis und pausiert. Beim nächsten Aufruf kann die Antwort über `tool_results` zurückgegeben werden, um fortzufahren.
- **Neue CRUD-Aktionen**: Über das Feld `action` können auf demselben Endpoint `retrieve` / `retrieve_batch` / `update` / `delete` ausgeführt werden, ohne dass eine zusätzliche API zur Sitzungsverwaltung erforderlich ist.
- **Kontinuierlich aktualisierte Modellliste**: Standardmäßig integriert mit aktuellen Modellen wie GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 usw.

Gleichzeitig ist sie auf Anfrageebene **vollständig abwärtskompatibel mit v1**: Wenn nur `model` + `question` (+ optional `stateful` / `id` / `references` / `preset`) übergeben werden, erhalten Sie eine zu v1 gleichwertige `{answer, id}`-JSON-Antwort. Daher muss beim Wechsel von `/aichat/conversations` nicht der Client neu geschrieben werden; es genügt, den Pfad zu `/aichat2/conversations` zu ändern.

> Wenn Sie derzeit `/aichat/conversations` verwenden, bleibt die alte Schnittstelle weiterhin verfügbar, und Sie können in Ihrem eigenen Tempo migrieren.

## Antragsprozess

Um die AI Chat v2 API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten und als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Danach kehren Sie automatisch zu dieser Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen; es ist nicht erforderlich, für jeden Dienst separat einen Antrag zu stellen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Guthaben, das Sie kostenlos ausprobieren können; bei unzureichendem Guthaben können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

## Grundlegende Verwendung

Die einfachste Verwendung ist vollständig identisch mit v1: `model` + `question` übergeben und `{answer, id}` erhalten.

CURL-Beispiel:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Rückgabeergebnis:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python-Beispiel:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Mehrfachdialog

Wie bei v1 wird durch die Übergabe von `stateful: true` das Speichern der Sitzung aktiviert, und die API gibt eine `id` zurück; bei nachfolgenden Anfragen genügt es, die `id` wieder mitzugeben, um den Dialog fortzusetzen, ohne den Nachrichtenverlauf selbst verwalten zu müssen.

Erste Anfrage:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Rückgabe:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Zweite Anfrage, mit derselben `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` ist standardmäßig `true`; das Weglassen entspricht der expliziten Übergabe von `true`. Wenn du nicht möchtest, dass der Server diese Gesprächsrunde speichert, kannst du explizit `stateful: false` setzen.

## Streaming-Antworten

v2 unterstützt zwei Streaming-Formate, die über den `accept`-Header ausgewählt werden:

| Szenario                    | `accept`               | Datenformat                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web-Frontend / EventSource  | `text/event-stream`    | `data: {json}\n\n`, letzte Zeile `data: [DONE]\n\n` |
| Server / CLI / Node-Streaming-Parsing | `application/x-ndjson` | Ein JSON-Objekt pro Zeile                               |
| Kein Streaming erforderlich                 | `application/json`（Standard） | Einmalige Rückgabe von `{answer, id}`                       |

### NDJSON-Beispiel

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Jede NDJSON-Zeile ist ein strukturiertes Ereignis; am häufigsten ist `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE-Beispiel

Die Verwendung von `EventSource` im Browser unterstützt keine benutzerdefinierten Request-Bodys; es wird empfohlen, `fetch` + manuelles Parsen nach `\n\n`-Abschnitten zu verwenden:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Streaming-Ereignistypen

| `type`              | Bedeutung                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `text_delta`        | Inkrementelles Textfragment der Assistentenantwort. `content` ist der neu hinzugefügte Inhalt; zur Kompatibilität mit v1 enthält dasselbe Ereignis außerdem `delta_answer` (gleich `content`) und `id`.                  |
| `thinking`          | Der Denkprozess des Modells (tritt nur auf, wenn das ausgewählte Modell Reasoning offenlegt).                                                                |
| `tool_use`          | Das Modell entscheidet sich, ein Tool aufzurufen; das Ereignis enthält `tool_id`, `tool_name`, `input`.                                                  |
| `tool_result`       | Das Tool-Ausführungsergebnis wird über `tool_id` mit dem vorherigen `tool_use` gepaart; `is_error` kennzeichnet, ob es fehlgeschlagen ist.                                       |
| `card`              | Vom Tool erzeugte strukturierte Karte (z. B. Bilder, Link-Vorschauen), geeignet zur direkten Darstellung.                                                                    |
| `citation`          | Quell-URL zur Ergänzung der Referenz für das entsprechende Textfragment.                                                                            |
| `ask_user_question` | Wird ausgegeben, wenn das Modell zusätzliche Informationen vom Benutzer benötigt; das Gespräch wechselt in den Status `awaiting_user_input`, siehe unten [Pausierte Gespräche fortsetzen](#pausierte-gespräche-fortsetzen).                           |
| `artifact`          | Ein vom Modell erzeugtes eigenständiges Artefakt (z. B. Codeblöcke, Dokumente), das gespeichert oder heruntergeladen werden kann.                                                                      |
| `system_message`    | Systemhinweis (kein Benutzer- oder Assistenteninhalt), nur für UI-Hinweise verwendet.                                                                     |
| `compact`           | Ein Ereignis, bei dem der interne Kontext komprimiert wurde; keine besondere Behandlung erforderlich.                                                                             |
| `error`             | In dieser Runde ist ein Fehler aufgetreten; `message` beschreibt den Fehlerinhalt.                                                                        |
| `done`              | Die Streaming-Antwort endet und enthält `usage` (einschließlich `prompt_tokens` / `completion_tokens` / `total_tokens`) sowie `terminal_reason`. |

Für Clients, die sich nur für die endgültige Antwort interessieren, entspricht das Zusammenfügen von `content` aller `text_delta`-Ereignisse dem `answer` im Modus `application/json`.

## Multimodale Eingaben

Wenn die Benutzereingabe Bilder oder Dateien enthält, übergib `message` (ein Array) anstelle von `question`. Jedes Array-Element ist ein Inhaltsblock:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Unterstützte Blocktypen:

- `text` — Normaler Text, das Feld `text` ist erforderlich.
- `image_url` — Bild, `image_url.url` ist erforderlich.
- `file_url` — Datei (PDF, CSV, TXT usw.), `file_url.url` ist erforderlich.

### Beziehung zu v1 `references`

Zur Kompatibilität mit älteren Clients erkennt v2 weiterhin das Feld `references: ["https://...", ...]`:
- URL-Suffix ist `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, wird automatisch in einen `image_url`-Block umgewandelt;
- andere Erweiterungen werden in einen `file_url`-Block umgewandelt;
- wenn gleichzeitig noch `question` bereitgestellt wird, wird es als `text`-Block vorangestellt.

Wenn man daher nur von v1 migrieren möchte und den Request-Body nicht ändern will, genügt es, den Pfad auf `/aichat2/conversations` zu ändern, die ursprüngliche Verwendung von `references` funktioniert wie gewohnt.

Wenn eine präzisere Steuerung benötigt wird (zum Beispiel mehrere Bilder zwischen Texten platzieren oder die Reihenfolge sehr wichtig ist), verwendet direkt das `message`-Array.

## Tool-Aufrufe und MCP

Der Kernverbesserungspunkt von v2 ist, dass das Modell Tools selbstständig aufrufen kann, um mehrstufige Aufgaben abzuschließen, **dies ist standardmäßig aktiviert**, der Client muss im Request keine zusätzliche Konfiguration vornehmen. Häufige Szenarien:

- Der Benutzer fragt „Hilf mir zu suchen, welche neuen Ausstellungen es kürzlich in Shanghai gibt“ → Das Modell ruft die integrierte Websuche auf → Bereitet die Ergebnisse als Antwort auf.
- Der Benutzer fragt „Lies dieses PDF und schreibe dann eine Zusammenfassung“ → Das Modell ruft file_read auf → Schreibt eine Zusammenfassung.
- Der Benutzer hat in [Connections](https://platform.acedata.cloud/connections) Google Drive / GitHub / Notion usw. autorisiert → Das Modell kann die entsprechenden MCP-Tools aufrufen, um deren Daten zu lesen und zu schreiben.

Im NDJSON- / SSE-Stream werden Tool-Aufrufe durch die zwei Ereignistypen `tool_use` und `tool_result` dargestellt, zum Beispiel:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Wenn du die Details von Tool-Aufrufen nicht im Frontend anzeigen möchtest, ignoriere einfach die Ereignistypen `tool_use` / `tool_result` / `card` / `citation`, die endgültige Ausgabe des Modells wird weiterhin über `text_delta` gestreamt.

`max_turns` kann begrenzen, wie viele Runden das Modell in dieser Anfrage höchstens selbst Tools aufrufen darf, der Bereich liegt bei 1–500, bei Auslassung ist der Standardwert 500. Wenn du es klein setzt (zum Beispiel `max_turns: 1`), kannst du eine einmalige Antwort erzwingen und keinerlei Tool-Aufrufe erlauben.

## Asynchrone Ausführung und unbeaufsichtigte Autorisierung

Wenn dein Aufruf von einem Alarm-Webhook, CI/CD, Überwachungssystem oder einer anderen Hintergrundaufgabe stammt, kannst du `async: true` setzen, damit die Schnittstelle sofort die Aufgaben-ID zurückgibt und im Hintergrund weiter ausgeführt wird:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Rückgabebeispiel:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Danach kann `action: retrieve` + `id` verwendet werden, um das Gesprächsergebnis abzufragen; es kann auch `callback_url` bereitgestellt werden, nach Abschluss der Aufgabe wird die Plattform `{ status, answer, usage, error }` per POST an deine Callback-Adresse senden. `callback_url` muss `http` / `https` verwenden und darf nicht direkt mit `localhost` oder einer privaten IP-Literaladresse angegeben werden.

Bei Hintergrundaufgaben kann normalerweise niemand zur Bestätigung klicken. Wenn du möchtest, dass bestimmte Skills oder MCP-Server im unbeaufsichtigten Modus Aktionen wie Senden, Veröffentlichen oder Schreiben ausführen, übergib bitte im Request-Body ausdrücklich eine Vorautorisierungsliste:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Die Werte in `allowed_skills` sind die Slugs verbundener Skills; die Werte in `allowed_mcp_servers` sind die Slugs verbundener MCP-Server. Nicht in die Vorautorisierung aufgenommene Skills / MCP-Server können im unbeaufsichtigten Modus weiterhin nur Vorschauen anzeigen, dry-run ausführen oder Schreiboperationen ablehnen.

Wenn eine feinere Steuerung benötigt wird, kann auch das äquivalente Objekt `unattended_policy` verwendet werden:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Die Vorautorisierung besteht aus diesen beiden Listen selbst: Eine leere Liste autorisiert keine Fähigkeiten, es sind keine zusätzlichen Schalterfelder erforderlich.

Hinweis: Die Vorautorisierung bedeutet nur, dass „diese Anfrage diesen Fähigkeiten erlaubt, im unbeaufsichtigten Modus die menschliche Bestätigung zu überspringen“. Der konkrete Skill muss weiterhin `--unattended-confirm` oder den entsprechenden Sicherheitsmechanismus unterstützen; andernfalls bleibt er bei dry-run und führt Schreiboperationen nicht direkt aus.

## Pausierte Gespräche fortsetzen

Einige Tools veranlassen das Modell dazu, „den Benutzer rückzufragen“, das Modell sendet dann ein `ask_user_question`-Ereignis, und das Gespräch wird im Status `awaiting_user_input` eingefroren:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Rendere dieses Ereignis im Frontend als Karte, damit der Benutzer eine Antwort auswählen kann, und starte dann mit derselben `id` die nächste Anfrage, wobei die Antwort über `tool_results` zurückübergeben wird:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

`tool_use_id` im Request-Body **muss** vollständig mit der `tool_id` zum Zeitpunkt der Pausierung übereinstimmen; bei Nichtübereinstimmung wird 400 zurückgegeben. Wenn im Request gleichzeitig `tool_results` vorhanden ist, werden `question` / `message` / `references` alle ignoriert.

Wenn der Benutzer beschließt, diese Frage aufzugeben, übergib direkt eine neue `question` / `message`, die Plattform markiert den pausierten Tool-Aufruf automatisch als „vom Benutzer übersprungen“.

## Gesprächsverwaltung (CRUD)

v2 bietet über das Feld `action` auf demselben Endpoint eine leichtgewichtige Gesprächsverwaltung, ohne eine zusätzliche API bereitzustellen.
### `action: retrieve` —— Eine Unterhaltung abrufen

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Gibt das vollständige Unterhaltungsdokument zurück (einschließlich `messages`-Verlauf, `model`, `title`, `tools_used` usw.).

### `action: retrieve_batch` —— Unterhaltungszusammenfassungen auflisten

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Gibt `{ items: [...], total }` zurück. **Die Zusammenfassung enthält keine `messages`**, sie eignet sich für Seitenleistenlisten; wenn der Benutzer eine Unterhaltung öffnet, rufen Sie ihre vollständigen Nachrichten anschließend separat mit `action: retrieve` ab.

Optionale Filterparameter: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Titel ändern oder Verlauf überschreiben

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Reiseplan für Hangzhou"
}
```

`messages` kann ebenfalls übergeben werden, aber der Server führt eine strenge Schema-Validierung durch (es muss die zusammengeführte Form von `ToolUseContent` sein); bei Abweichungen wird 400 zurückgegeben. Im Allgemeinen wird empfohlen, dies nur zum Ändern von `title` zu verwenden.

### `action: delete` —— Eine Unterhaltung löschen

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Gibt `{ id, success: true }` zurück. Nach dem Löschen kann sie nicht wiederhergestellt werden, bestätigen Sie dies bitte vor dem Aufruf.

## Reibungslose Migration von v1

Wenn Sie bereits [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations) verwenden, erfordert die Migration zu v2 kaum Codeänderungen:

1. Ändern Sie die URL von `https://api.acedata.cloud/aichat/conversations` zu `https://api.acedata.cloud/aichat2/conversations`.
2. Wenn Sie zuvor v1-Modellnamen (wie `gpt-3.5`, `gpt-4-browsing` usw.) übergeben haben, wird empfohlen, beim Wechsel zu v2 auf aktuelle Modelle (wie `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` usw.) zu aktualisieren.
3. Die Felder des NDJSON-Streams bleiben abwärtskompatibel: Jedes `text_delta`-Ereignis enthält weiterhin `delta_answer` und `id`, daher müssen Clients, die ursprünglich `delta_answer` zeilenweise analysieren, nicht geändert werden.

Nach der Migration können Sie bei Bedarf die neuen Fähigkeiten von v2 (multimodale `message`, SSE, Tool-Aufrufe, `action` CRUD) aktivieren und schrittweise vorgehen.

## Fehlerbehandlung

Fehlerantworten sind einheitlich wie folgt:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Häufige Fehler:

- `400 bad_request`: Fehlende Pflichtfelder, nicht übereinstimmende `tool_use_id`, ungültiges `messages`-Schema usw.
- `401 invalid_token`: Der `authorization`-Header ist nicht korrekt.
- `404 not_found`: Die Unterhaltung, die der `id` bei `action: retrieve / update / delete` entspricht, existiert nicht.
- `429 too_many_requests`: Das Ratenlimit wurde ausgelöst.
- `500 chat_error`: Der vorgelagerte LLM hat einen Fehler gemeldet oder `completion_tokens=0` in dieser Runde (wird als nicht verbraucht behandelt und nicht berechnet).

In der Streaming-Antwort werden Fehler als `{"type":"error","message":"..."}`-Ereignis gesendet, woraufhin der Stream unmittelbar endet.

## Fazit

Die AI Chat v2 API bleibt mit v1 abwärtskompatibel und erweitert Unterhaltungen von „einzelnen / mehreren Fragerunden und Antworten“ zu „Agent-basierten beobachtbaren Unterhaltungen“: multimodale Eingaben, Tool-Aufrufe, pausierbar / fortsetzbar, strukturierte Streaming-Ereignisse, integriertes CRUD. Für neue Integrationen wird empfohlen, direkt v2 zu verwenden; bestehende v1-Integrationen können schrittweise und reibungslos migriert werden. Bei Fragen kontaktieren Sie bitte jederzeit unser technisches Support-Team.
