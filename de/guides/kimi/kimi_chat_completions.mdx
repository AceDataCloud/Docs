Kimi ist eine von Moonshot AI eingeführte AI-Modellreihe. Aktuell wird `kimi-k3.1-pro` empfohlen, geeignet für langfristiges Programmieren, komplexes Schlussfolgern, visuelles Verständnis und Wissensarbeit; `kimi-k3` kann weiterhin verwendet werden. Der Aufruf erfolgt über die OpenAI-kompatible Chat-Completions-API.

Dieses Dokument stellt hauptsächlich den Nutzungsprozess der Kimi Chat Completion API vor, mit der wir die offiziellen Dialogfunktionen von Kimi einfach verwenden können.

## Antragsprozess

Um die Kimi Chat Completion API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten, und bewahren Sie ihn als Reserve auf.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden; nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Bei der ersten Beantragung wird ein kostenloses Kontingent gewährt, das kostenlos ausprobiert werden kann; bei unzureichendem Kontingent kann in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufgeladen werden.

> 📘 Vollständige Dokumentation: [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Grundlegende Nutzung

Als Nächstes können Sie die entsprechenden Inhalte in der Oberfläche ausfüllen, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

Bei der ersten Verwendung dieser Schnittstelle müssen mindestens drei Inhalte ausgefüllt werden: `authorization` kann direkt aus der Dropdown-Liste ausgewählt werden; `model` wird zur Auswahl des Kimi-Modells verwendet, empfohlen wird `kimi-k3.1-pro`; `messages` ist ein Array von Dialognachrichten, wobei jede Nachricht `role` und `content` enthält und `role` `user`, `assistant`, `system` und `tool` unterstützt.

Gleichzeitig können Sie feststellen, dass auf der rechten Seite entsprechender Aufrufcode generiert wird. Sie können den Code kopieren und direkt ausführen oder direkt auf die Schaltfläche „Try“ klicken, um ihn zu testen.

<p><img src="https://cdn.acedata.cloud/six7e3.png" width="400" className="m-auto" /></p>

Im Folgenden ist eine echte K3-Antwort aufgeführt, die mit `reasoning_effort: max` erhalten wurde (nicht verwendete Erweiterungsfelder ausgelassen):

```json
{
  "id": "msg_2D4Btbg1WgvkNE3tCYkR4xGA",
  "object": "chat.completion",
  "created": 1784466588,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 86,
    "completion_tokens": 206,
    "total_tokens": 292
  }
}
```

Das Rückgabeergebnis enthält mehrere Felder, die wie folgt beschrieben werden:

- `id`, die ID der generierten Dialogaufgabe, die zur eindeutigen Identifizierung dieser Dialogaufgabe verwendet wird.
- `model `, das ausgewählte Kimi-Modell der offiziellen Website.
- `choices` die Antwortinformationen, die Kimi auf die Anfrage gibt.
- `usage `: statistische Informationen zu den Tokens dieses Frage-und-Antwort-Vorgangs.

Dabei enthält `choices` die Antwortinformationen von Kimi, und die darin enthaltenen `choices` sind die konkreten Informationen der Kimi-Antwort, wie in der Abbildung gezeigt.

<p><img src="https://cdn.acedata.cloud/tv9rul.png" width="400" className="m-auto" /></p>

Man kann sehen, dass das Feld `content` in `choices` den konkreten Inhalt der Kimi-Antwort enthält; K3 kann außerdem `reasoning_content` zurückgeben, um den Schlussfolgerungsprozess darzustellen.

## K3.1 Pro Schlussfolgerungsstärke

`kimi-k3.1-pro` aktiviert Schlussfolgern immer. Im obersten Bereich des Anfragebodys kann `reasoning_effort` auf `low`, `high` oder `max` gesetzt werden; übergeben Sie keine Konfiguration zum Deaktivieren des Schlussfolgerns. Das Modell unterstützt bis zu 1.048.576 Token Kontext, aber das tatsächliche Anfragelimit richtet sich weiterhin nach der aktuellen Schnittstelle. Die Preise werden anhand der Nutzung von Eingabe, Ausgabe und Cache-Treffern berechnet; Einzelheiten finden Sie auf der Pricing-Karte im Modellkatalog.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Die folgenden K3-Beispiele bleiben für bestehende Integrationen erhalten; die Beispielantwort wurde tatsächlich durch eine K3-Anfrage erhalten.

## K3 Schlussfolgerungsstärke

`kimi-k3` aktiviert Schlussfolgern immer. Der oberste Bereich des Anfragebodys unterstützt das Feld `reasoning_effort`, wobei der derzeit einzig unterstützte Wert `max` ist; wenn dieses Feld ausgelassen wird, wird ebenfalls `max` verwendet. `standard`, `high` oder andere Zeichenfolgen werden möglicherweise von einigen kompatiblen Upstreams tolerant akzeptiert, es wird jedoch nicht garantiert, dass sie das Schlussfolgerungsverhalten ändern; verlassen Sie sich nicht darauf.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

Bei Verwendung des OpenAI SDK kann dieses Feld direkt übergeben werden:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

Bei mehrstufigen Dialogen und Werkzeugaufrufen geben Sie bitte die vollständige `assistant`-Nachricht der vorherigen Runde an `messages` zurück, einschließlich `reasoning_content` und `tool_calls`.

### Offizielle Referenzen

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort): Erläutert, dass Kimi K3 Schlussfolgern immer aktiviert und der derzeit einzig unterstützte Wert von `reasoning_effort` `max` ist.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview): Vergleicht die Schlussfolgerungsparameter, Kontextfenster und Unterschiede bei Werkzeugaufrufen zwischen K3 und der K2-Serie.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat): Offizielle Moonshot-Definitionen für Chat-Completions-Anfragen, -Antworten und OpenAPI-Felder.

## Streaming-Antwort

Diese Schnittstelle unterstützt auch Streaming-Antworten, was für die Webanbindung sehr nützlich ist und es Webseiten ermöglicht, einen Effekt der zeichenweisen Anzeige zu realisieren.

Wenn Sie Antworten als Stream zurückgeben möchten, können Sie den Parameter `stream ` im Anfrageheader ändern und auf `true` setzen.

Die Änderung ist in der Abbildung dargestellt, allerdings muss der Aufrufcode entsprechend geändert werden, um Streaming-Antworten zu unterstützen.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>

Nachdem `stream` auf `true` geändert wurde, gibt die API die entsprechenden JSON-Daten zeilenweise zurück. Auf Codeebene müssen wir entsprechende Änderungen vornehmen, um zeilenweise Ergebnisse zu erhalten.

Python-Beispielaufrufcode:
```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Nachfolgend sind die Start-, Denk-, Text-, End- und Nutzungsdatenblöcke aus derselben echten K3-Max-Streaming-Antwort aufgeführt:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Wie zu sehen ist, enthält die Antwort viele `data`, und die `choices` innerhalb von `data` sind der neueste Antwortinhalt, was mit dem zuvor beschriebenen Inhalt übereinstimmt. `choices` enthält den neu hinzugefügten Antwortinhalt, den Sie anhand des Ergebnisses an Ihr System anbinden können. Gleichzeitig wird das Ende der Streaming-Antwort anhand des Inhalts von `data` bestimmt; wenn der Inhalt `[DONE]` ist, bedeutet dies, dass die Streaming-Antwort vollständig beendet ist. Das zurückgegebene `data`-Ergebnis enthält mehrere Felder, die wie folgt beschrieben werden:

- `id`, die ID zur Generierung dieser Dialogaufgabe, die zur eindeutigen Identifizierung dieser Dialogaufgabe verwendet wird.
- `model `, das ausgewählte Kimi-Modell der offiziellen Website.
- `choices`, die Antwortinformationen, die Kimi auf den Prompt gibt.

Auch JavaScript wird unterstützt, beispielsweise lautet der Code für den Streaming-Aufruf in Node.js wie folgt:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Java-Beispielcode:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Andere Sprachen können entsprechend selbst angepasst werden, das Prinzip ist überall dasselbe.

## Mehrere Gesprächsrunden

Wenn Sie die Funktion für mehrere Gesprächsrunden anbinden möchten, müssen Sie mehrere Prompts im Feld `messages` übermitteln. Ein konkretes Beispiel für mehrere Prompts ist in der folgenden Abbildung dargestellt:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Python-Beispielcode für den Aufruf:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Durch das Übermitteln mehrerer Prompts können Sie auf einfache Weise mehrere Gesprächsrunden implementieren. Nachfolgend ist die echte K3-Max-Antwort, die durch diese Anfrage erhalten wurde (nicht verwendete Erweiterungsfelder wurden weggelassen):

```json

  "object": "chat.completion",
  "created": 1784466628,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "I’m Kimi, an AI assistant developed by Moonshot AI (月之暗面). I don’t have a specific public model version identifier to share from here."
      },
      "logprobs": null,
      "finish_reason": "stop"
```

Wie zu sehen ist, stimmen die in `choices` enthaltenen Informationen mit dem grundlegenden Nutzungsinhalt überein. Dies enthält den konkreten Inhalt von Kimis Antworten auf mehrere Dialoge, sodass entsprechende Fragen anhand mehrerer Dialoginhalte beantwortet werden können.

## Fehlerbehandlung

Wenn beim Aufruf der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechenden Informationen zurück. Zum Beispiel:

- `400 token_mismatched`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`：Nicht autorisiert, ungültiges oder fehlendes Autorisierungs-Token.
- `429 too_many_requests`：Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`：Interner Serverfehler, auf dem Server ist ein Fehler aufgetreten.

### Beispiel für eine Fehlerantwort

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
