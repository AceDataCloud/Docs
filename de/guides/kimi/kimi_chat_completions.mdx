Kimi ist eine von Moonshot AI entwickelte KI-Modellreihe. Derzeit wird `kimi-k3.1-pro` empfohlen. Es eignet sich für langfristige Programmieraufgaben, komplexe Schlussfolgerungen, visuelles Verständnis und Wissensarbeit. `kimi-k3` kann weiterhin verwendet werden. Der Aufruf erfolgt über eine OpenAI-kompatible Chat Completions API.

Dieses Dokument beschreibt hauptsächlich den Ablauf zur Verwendung der Kimi Chat Completion API. Damit können wir die offiziellen Kimi-Dialogfunktionen ganz einfach nutzen.

## Unterstützte Modelle

Derzeit werden vier Modelle unterstützt: `kimi-k3.1-pro`, `kimi-k3`, `kimi-k2.6` und `kimi-k2.7-code`. K2.7 Code ist auf Programmier- und Tool-Aufrufszenarien ausgerichtet und wird zum gleichen Preis wie K2.6 abgerechnet. Übergeben Sie bei Anfragen keine `thinking`-Einstellung oder `reasoning_effort` für dieses Modell. Andere Kimi-Modelle werden nicht mehr unterstützt. Bitte wählen Sie im Client ausdrücklich eines dieser vier Modelle aus.

## Beantragungsprozess

Um die Kimi Chat Completion API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihr API-Token abzurufen und für die spätere Verwendung aufzubewahren.

![]()

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, wo Sie zur Registrierung und Anmeldung eingeladen werden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Mit einem einzigen API-Token können Sie alle Dienste der Plattform aufrufen. Sie müssen keinen separaten Antrag für jeden Dienst stellen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Guthaben, mit dem Sie den Dienst kostenlos testen können. Wenn das Guthaben nicht ausreicht, können Sie Ihr allgemeines Guthaben in der [Konsole](https://platform.acedata.cloud/console/coin) aufladen.

> 📘 Vollständige Dokumentation: [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Grundlegende Verwendung

Anschließend können Sie die entsprechenden Inhalte direkt in der Benutzeroberfläche eingeben, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

Bei der erstmaligen Verwendung dieser Schnittstelle müssen mindestens drei Angaben gemacht werden: `authorization` kann direkt aus der Dropdown-Liste ausgewählt werden; `model` dient zur Auswahl des Kimi-Modells, wobei `kimi-k3.1-pro` empfohlen wird; `messages` ist ein Array mit Dialognachrichten, wobei jede Nachricht `role` und `content` enthält. Für `role` werden `user`, `assistant`, `system` und `tool` unterstützt.

Gleichzeitig können Sie feststellen, dass auf der rechten Seite der entsprechende Aufrufcode generiert wird. Sie können den Code kopieren und direkt ausführen oder auf die Schaltfläche „Try“ klicken, um einen Test durchzuführen.

<p><img src="https://cdn.acedata.cloud/six7e3.png" width="400" className="m-auto" /></p>

Nachfolgend finden Sie eine echte K3-Antwort, die mit `reasoning_effort: max` erzielt wurde (nicht verwendete zusätzliche Felder wurden weggelassen):

```json
{
  "id": "msg_2D4Btbg1WgvkNE3tCYkR4xGA",
  "object": "chat.completion",
  "created": 1784466588,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 86,
    "completion_tokens": 206,
    "total_tokens": 292
  }
}
```

Das zurückgegebene Ergebnis enthält mehrere Felder, die im Folgenden erläutert werden:

- `id`: Die ID der generierten Dialogaufgabe, die zur eindeutigen Identifizierung dieser Dialogaufgabe dient.
- `model `: Das ausgewählte Kimi-Modell der offiziellen Website.
- `choices`: Die Antwortinformationen von Kimi auf die gestellte Frage.
- `usage `: Die statistischen Informationen zur Token-Nutzung dieser Frage-Antwort-Runde.

Dabei enthält `choices` die Antwortinformationen von Kimi. Das darin enthaltene `choices` umfasst die konkreten Informationen zur Antwort von Kimi, wie in der Abbildung zu sehen ist.

<p><img src="https://cdn.acedata.cloud/tv9rul.png" width="400" className="m-auto" /></p>

Wie zu sehen ist, enthält das Feld `content` innerhalb von `choices` den konkreten Inhalt der Antwort von Kimi. K3 kann außerdem `reasoning_content` zurückgeben, um den Schlussfolgerungsprozess darzustellen.

## K3.1 Pro – Stärke der Schlussfolgerungen

`kimi-k3.1-pro` aktiviert Schlussfolgerungen immer. Im obersten Bereich des Request-Bodys kann `reasoning_effort` auf `low`, `high` oder `max` gesetzt werden. Übergeben Sie keine Konfiguration, die Schlussfolgerungen deaktiviert. Das Modell unterstützt ein Kontextfenster von bis zu 1.048.576 Token. Die tatsächliche Anfragegrenze richtet sich jedoch weiterhin nach der aktuellen Schnittstelle. Die Preise werden anhand der Nutzung von Eingabe-, Ausgabe- und Cache-Treffern berechnet. Weitere Informationen finden Sie in der Pricing-Karte des Modellkatalogs.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Das folgende K3-Beispiel bleibt für bestehende Integrationen erhalten. Die Beispielantwort wurde tatsächlich durch eine K3-Anfrage erzeugt.

## K3 – Stärke der Schlussfolgerungen

`kimi-k3` aktiviert Schlussfolgerungen immer. Das oberste Feld `reasoning_effort` im Request-Body wird unterstützt. Derzeit ist ausschließlich der Wert `max` zulässig. Wenn dieses Feld weggelassen wird, wird ebenfalls `max` verwendet. Bitte verwenden Sie einen unterstützten Wert.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

Bei Verwendung des OpenAI SDK kann dieses Feld direkt übergeben werden:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

Bei mehrstufigen Dialogen und Tool-Aufrufen geben Sie bitte die vollständige assistant-Nachricht der vorherigen Runde erneut in `messages` zurück, einschließlich `reasoning_content` und `tool_calls`.

### Offizielle Referenzen

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort): Erläutert, dass Kimi K3 Schlussfolgerungen immer aktiviert und dass der einzige derzeit unterstützte Wert für `reasoning_effort` `max` ist.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview): Vergleicht die Schlussfolgerungsparameter, Kontextfenster und Unterschiede bei Tool-Aufrufen zwischen der K3- und der K2-Modellreihe.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat): Definitionen der offiziellen Moonshot-Chat-Completions-Anfragen, Antworten und OpenAPI-Felder.

## Streaming-Antworten

Diese Schnittstelle unterstützt auch Streaming-Antworten, was für die Integration in Webseiten sehr nützlich ist, da dadurch eine zeichenweise Anzeige auf der Webseite ermöglicht wird.

Wenn Sie eine Streaming-Antwort erhalten möchten, können Sie den Parameter `stream ` im Request-Header ändern und auf `true` setzen.

Nehmen Sie die Änderung wie in der Abbildung gezeigt vor. Allerdings muss auch der Aufrufcode entsprechend angepasst werden, damit Streaming-Antworten unterstützt werden.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>
Nachdem Sie `stream` auf `true` geändert haben, gibt die API die entsprechenden JSON-Daten zeilenweise zurück. Auf Codeebene müssen wir entsprechende Änderungen vornehmen, um die Ergebnisse zeilenweise zu erhalten.

Python-Beispielcode für den API-Aufruf:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Im Folgenden sind Auszüge aus den Anfangs-, Denkprozess-, Text-, End- und Nutzungsdatenblöcken derselben echten K3-Max-Streaming-Antwort aufgeführt:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Wie zu sehen ist, enthält die Antwort zahlreiche `data`-Einträge. Das Feld `choices` innerhalb von `data` enthält jeweils den neuesten Antwortinhalt und entspricht damit den zuvor beschriebenen Inhalten. `choices` enthält die neu hinzugefügten Antwortinhalte, die Sie anhand der Ergebnisse in Ihr System integrieren können. Gleichzeitig wird das Ende der Streaming-Antwort anhand des Inhalts von `data` erkannt. Lautet der Inhalt `[DONE]`, bedeutet dies, dass die Streaming-Antwort vollständig abgeschlossen ist. Das zurückgegebene `data`-Ergebnis enthält mehrere Felder, die im Folgenden beschrieben werden:

- `id`: Die ID der generierten Dialogaufgabe, die zur eindeutigen Identifizierung dieser Dialogaufgabe dient.
- `model `: Das ausgewählte Kimi-Modell der offiziellen Website.
- `choices`: Die Antwortinformationen, die Kimi auf die Eingabeaufforderung gibt.

Auch JavaScript wird unterstützt. Der folgende Code zeigt beispielsweise einen Streaming-Aufruf mit Node.js:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Java-Beispielcode:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Andere Sprachen können entsprechend angepasst werden. Das Prinzip ist bei allen gleich.

## Mehrstufige Dialoge

Wenn Sie die Funktion für mehrstufige Dialoge integrieren möchten, müssen Sie mehrere Eingabeaufforderungen im Feld `messages` übermitteln. Ein konkretes Beispiel für mehrere Eingabeaufforderungen sehen Sie in der folgenden Abbildung:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Python-Beispielcode für den API-Aufruf:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Durch die Übermittlung mehrerer Eingabeaufforderungen können Sie problemlos mehrstufige Dialoge realisieren. Im Folgenden sehen Sie die echte K3-Max-Antwort auf diese Anfrage (nicht verwendete zusätzliche Felder wurden weggelassen):

```json

  "object": "chat.completion",
  "created": 1784466628,
  "model": "kimi-k3",
  "choices": [
    {

        "content": "I’m Kimi, an AI assistant developed by Moonshot AI (月之暗面). I don’t have a specific public model version identifier to share from here."
      },
      "logprobs": null,
```

Wie zu sehen ist, entsprechen die in `choices` enthaltenen Informationen denen der grundlegenden Verwendung. Sie umfassen die konkreten Antworten von Kimi auf mehrere Dialogeingaben. Auf diese Weise können die entsprechenden Fragen anhand des Inhalts mehrerer Dialoge beantwortet werden.

## Fehlerbehandlung

Wenn bei einem API-Aufruf ein Fehler auftritt, gibt die API einen entsprechenden Fehlercode und eine Fehlermeldung zurück. Zum Beispiel:

- `400 token_mismatched`: Bad request, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Bad request, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, das Ratenlimit wurde überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist ein Fehler aufgetreten.

### Beispiel einer Fehlerantwort

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
