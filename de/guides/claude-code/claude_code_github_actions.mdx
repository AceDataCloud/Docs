## 1. API-Schlüssel abrufen

Öffnen Sie die [Ace Data Cloud Anwendungsübersicht](https://platform.acedata.cloud/console/applications), gehen Sie zu den verfügbaren Anwendungen und kopieren Sie den API-Schlüssel.

![API-Schlüssel von Ace Data Cloud abrufen](https://cdn.acedata.cloud/dvc3cg.jpg)

Erstellen Sie im Ziel-GitHub-Repository unter **Einstellungen → Geheimnisse und Variablen → Aktionen** ein neues Geheimnis:

```text
ACEDATACLOUD_API_KEY
```

## 2. GitHub-App installieren

Installieren Sie die [Claude GitHub-App](https://github.com/apps/claude) und autorisieren Sie das Ziel-Repository. Diese offizielle App fordert einen festen vollständigen Berechtigungsumfang an; dabei verwendet die Claude Code Action tatsächlich die Berechtigungen für Inhalte, Probleme und Pull-Requests, die GitHub-Installationsseite kann nicht nur diese drei Punkte auswählen. Wenn die Organisation minimale Berechtigungen verlangt, erstellen Sie bitte eine benutzerdefinierte GitHub-App gemäß der offiziellen Dokumentation.

## 3. Workflow hinzufügen

Erstellen Sie `.github/workflows/claude.yml`:

```yaml
name: Claude Code

on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]

jobs:
  claude:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: write
      actions: read
      id-token: write
    env:
      ANTHROPIC_BASE_URL: https://api.acedata.cloud
      ANTHROPIC_CUSTOM_HEADERS: "Authorization: Bearer ${{ secrets.ACEDATACLOUD_API_KEY }}"
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: dummy-not-used
```

`claude-code-action` benötigt eine nicht leere Eingabe für `anthropic_api_key`; der Platzhalterwert hier wird nicht zur Plattformauthentifizierung verwendet. `ANTHROPIC_CUSTOM_HEADERS` wird überschrieben, um den für Ace Data Cloud erforderlichen Bearer-Header bereitzustellen, der echte Schlüssel stammt nur aus dem GitHub-Geheimnis.

## 4. Überprüfung

Nach dem Einreichen des Workflows senden Sie in einem Issue oder PR-Kommentar:

```text
@claude Antworte nur mit OK
```

Bei Erfolg wird der Actions-Workflow abgeschlossen und das Ergebnis im entsprechenden Issue/PR aktualisiert. Wenn die Action auf fehlende Anmeldeinformationen hinweist, überprüfen Sie, ob `dummy-not-used` weiterhin vorhanden ist; bei 401 überprüfen Sie das Geheimnis `ACEDATACLOUD_API_KEY`. Drucken Sie das Geheimnis nicht in die Protokolle. Sie können `claude_args` nach Bedarf verwenden, um `--max-turns` festzulegen oder das derzeit verfügbare Modell auszuwählen, aber die Anbindung an die Vorlage ist nicht auf ein festes Modell beschränkt.
