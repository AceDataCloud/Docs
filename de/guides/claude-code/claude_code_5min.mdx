Dieses Dokument hat nur ein Ziel: Dir **innerhalb von 5 Minuten** zu zeigen, wie Du mit dem AceData Cloud Proxy den ersten Claude Code Befehl ausführst. Eine vollständige Anleitung findest Du in den jeweiligen IDE-Unterdokumenten ([VS Code](https://platform.acedata.cloud/documents/claude-code-vscode-integrations) / [Cursor](https://platform.acedata.cloud/documents/claude-code-cursor-integration) / [JetBrains](https://platform.acedata.cloud/documents/claude-code-jetbrains-integrations)); hier gehen wir nur den schnellsten Weg mit „**Terminal CLI** + **VS Code Erweiterung**“.

> **Warum AceData Cloud als Proxy für Claude Code nutzen**:
> - Direkte Verbindung innerhalb Chinas, kein eigener VPN nötig
> - Günstiger als die offizielle Abrechnung (Token-basiert über die Plattform)
> - Ein einziger Key unterstützt gleichzeitig Claude Messages API + Claude Code Token-Protokoll

## Minute 1: Zugangsdaten beantragen

Öffne die [Claude Messages Service-Seite](https://platform.acedata.cloud/documents/claude-messages) und klicke auf den Button „**Acquire**“:

![](https://cdn.acedata.cloud/nyq0xz.png)

Die Plattform erstellt automatisch eine Application für Dich und schenkt Dir ein kostenloses Guthaben. Notiere Dir die beiden Werte **Base URL** + **API Token** aus der Detailseite — sie werden in den nächsten 5 Schritten benötigt.

| Feld | Wert | Zweck |
|------|------|-------|
| `BASE_URL` | `https://api.acedata.cloud` | Claude Messages kompatibler Endpunkt |
| `API_TOKEN` | `sk-...` (kann auf der Detailseite kopiert werden) | Anthropic-kompatibler Authentifizierungs-Token |

## Minute 2: Claude Code installieren

macOS / Linux / WSL:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows (PowerShell nativ):

```powershell
irm https://claude.ai/install.ps1 | iex
```

Nach der Installation öffne ein neues Terminal und prüfe die Version:

```bash
claude --version
```

> Wenn die Versionsnummer angezeigt wird, ist alles in Ordnung. Claude Code bringt eine eigene Node.js Laufzeit mit und ist nicht von der Node-Version auf Deinem Rechner abhängig.

## Minute 3: Umgebungsvariablen auf AceData Cloud setzen

Nutze nicht den offiziellen `claude login`-Prozess, sondern überschreibe die Umgebungsvariablen. Wähle eine der beiden Methoden:

**Variante A: Temporär (nur aktuelle Shell-Sitzung)**

```bash
export ANTHROPIC_BASE_URL="https://api.acedata.cloud"
export ANTHROPIC_AUTH_TOKEN="sk-dein-Token"
```

**Variante B: Persistierend (empfohlen)**

Füge die beiden Zeilen in Deine `~/.zshrc` oder `~/.bashrc` ein und führe anschließend `source` aus.

> **Häufige Fehlerquelle**: Der Variablenname lautet `ANTHROPIC_AUTH_TOKEN`, nicht `ANTHROPIC_API_KEY`. Bei falschem Namen fällt Claude Code auf den offiziellen Endpunkt zurück und gibt 401 zurück.

## Minute 4: Ersten Befehl ausführen

Wechsle in ein beliebiges Git-Repository und führe aus:

```bash
claude
```

Falls beim ersten Start eine Login-Abfrage erscheint, drücke `Esc` zum Überspringen. Gib dann ein:

```
Liste die Abhängigkeiten des aktuellen Projekts auf und erkläre kurz den Zweck jeder einzelnen.
```

Normalerweise siehst Du, wie Claude `read_file` / `glob` / `grep` usw. nutzt, um das Repository zu durchsuchen, und anschließend eine Liste ausgibt. In der Statusleiste unten sollte „connected to api.acedata.cloud“ stehen — das ist das wichtige Zeichen, dass der Proxy aktiv ist.

## Minute 5: VS Code Erweiterung einrichten

1. Öffne VS Code → Erweiterungen → Suche nach „Claude Code“ und installiere die offizielle Anthropic-Erweiterung;
2. **Cmd+Shift+P** → Tippe `Claude Code: Set Custom API Endpoint`;
3. Gib `https://api.acedata.cloud` ein und bestätige mit Enter;
4. Führe erneut `Claude Code: Set API Token` aus und gib Deinen Token ein.

Nach erfolgreicher Einrichtung erscheint das Claude Code Panel in der Seitenleiste. Du kannst Dateien per Drag & Drop hineinziehen, Fragen stellen oder mit `@-mention` Änderungsvorschläge für eine Datei machen. Die Abrechnung läuft komplett über AceData Cloud.

## Überprüfen, ob der Proxy aktiv ist

Gib im Claude Code Chat ein:

```
Rufe https://api.acedata.cloud/whoami auf und teile mir mit, was zurückkommt.
```

Wenn Deine eigenen Kontoinformationen (`{user_id, plan, ...}`) zurückgegeben werden, läuft die Anfrage tatsächlich über den AceData Cloud Edge. Falls stattdessen ein 401 vom offiziellen Domain erscheint, überprüfe nochmal die Umgebungsvariablen aus Minute 3.

## 5 häufig gestellte Fragen

**Q: Ich habe `claude login` ausgeführt und danach die Umgebungsvariablen auf AceData geändert, warum funktioniert es nicht?**  
A: `claude login` schreibt den offiziellen Token in `~/.claude/.credentials.json`, der Vorrang vor Umgebungsvariablen hat. Lösche diese Datei und lade die Shell-Konfiguration neu (`source ~/.zshrc`).

**Q: Kann ich Modellnamen wie `--model claude-opus-4-7` verwenden?**  
A: Ja. Der AceData Cloud Proxy leitet das `model`-Feld durch. Alle öffentlich verfügbaren Anthropic-Modelle plus unsere Erweiterungen `claude-opus-4-7` / `claude-haiku-4-5` / `claude-sonnet-4-5` werden unterstützt.

**Q: Kann ich mehrere Profile (privat + beruflich) konfigurieren?**  
A: Ja. Claude Code unterstützt mehrere Profile in `~/.claude/settings.json`. Oder ganz einfach: Schreibe zwei Shell-Funktionen `claude_personal` / `claude_work`, die jeweils unterschiedliche `ANTHROPIC_AUTH_TOKEN` exportieren und dann `claude $@` aufrufen.

**Q: Kann ich das in GitHub Actions verwenden?**  
A: Ja. Siehe [Claude Code GitHub Actions Konfigurationsanleitung](https://platform.acedata.cloud/documents/claude-code-github-actions-integration).

**Q: Was passiert, wenn das kostenlose Guthaben aufgebraucht ist?**  
A: Gehe zu [Anwendungsverwaltung](https://platform.acedata.cloud/applications) → wähle die Claude Application → Topup aufladen (Abrechnung nach tatsächlichem Token-Verbrauch) oder wechsle zu einem Punktabonnement.
