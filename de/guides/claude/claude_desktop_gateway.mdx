Diese Anleitung konfiguriert das **Third-Party Inference Gateway** von Claude Desktop, nicht Claude Code und auch nicht den MCP Connector von Claude Desktop.

## 1. API Key abrufen

Öffnen Sie die [Ace Data Cloud Anwendungsliste](https://platform.acedata.cloud/console/applications), rufen Sie die verfügbare Anwendung auf und kopieren Sie den API Key.

![Ace Data Cloud API Key abrufen](https://cdn.acedata.cloud/dvc3cg.jpg)

## 2. Drittanbieter-Inferenzkonfiguration öffnen

Öffnen Sie auf der Anmeldeseite von Claude Desktop nacheinander **Help → Troubleshooting → Enable Developer Mode** und wählen Sie anschließend **Developer → Configure Third-Party Inference…** aus.

![Third-Party Inference in Claude Desktop öffnen](https://cdn.acedata.cloud/713ffd7104a3.png)

> Das Bild stammt aus dem Bifrost-Apache-2.0-Repository und dient nur zur Orientierung bei den Claude-Desktop-Menüs; die Benutzeroberfläche kann je nach Version leicht abweichen.

## 3. Gateway konfigurieren

Wählen Sie **Gateway** und füllen Sie anschließend Folgendes aus:

| Feld                  | Wert                           |
| ------------------- | --------------------------- |
| Gateway base URL    | `https://api.acedata.cloud` |
| Gateway API key     | Der gerade kopierte API Key               |
| Gateway auth scheme | `bearer`                    |
| Credential kind     | `Static API key`            |

![Claude Desktop Gateway-Konfigurationsoberfläche](https://cdn.acedata.cloud/68d41fe682cb.png)

Klicken Sie auf **Apply Changes** und anschließend auf **Save & Restart**.

## 4. Überprüfen

Wählen Sie nach dem Neustart ein verfügbares Modell aus, erstellen Sie eine neue Unterhaltung und senden Sie `Reply only OK`; führen Sie anschließend eine einfache Tool-Aufgabe aus. Die Aufrufhistorie kann unter [Nutzungsverlauf](https://platform.acedata.cloud/console/usages) eingesehen werden.

Das Ace Data Cloud Gateway unterstützt `/v1/models`, das von Claude Desktop verwendet wird, Bearer-authentifizierte Streaming-Anfragen an `/v1/messages`, Tool-Aufrufe und die Fortsetzung mit `tool_result`. Prompt-Caching-Felder werden beibehalten; wenn sowohl die Cache-Schreib- als auch die Lesewerte 0 sind, bedeutet dies nicht, dass ein Cache-Treffer erfolgt ist.

401 bedeutet normalerweise, dass der Key nicht korrekt ist; wenn ein Modell nicht gefunden wird, überprüfen Sie die Konfiguration erneut und starten Sie Claude Desktop vollständig neu. Geben Sie bei der Meldung von Problemen die trace ID aus der Aufrufhistorie an, aber nicht den API Key.
