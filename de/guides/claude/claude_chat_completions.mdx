Anthropic Claude ist ein sehr leistungsstarkes KI-Dialogsystem, das durch die bloße Eingabe von Prompts innerhalb weniger Sekunden flüssige und natürliche Antworten generieren kann. Claude hebt sich in der Branche durch sein hervorragendes Sprachverständnis und seine Generierungsfähigkeiten hervor. Heute wird Claude bereits in verschiedenen Branchen und Bereichen umfassend eingesetzt, und sein Einfluss wird immer deutlicher. Ob alltägliche Gespräche, kreatives Schreiben oder professionelle Beratung und Code-Programmierung – Claude kann beeindruckende intelligente Unterstützung bieten und die Arbeitseffizienz und Kreativität der Menschen erheblich steigern.

Dieses Dokument stellt hauptsächlich den Nutzungsablauf der Claude Chat Completion API vor. Mit ihr können wir die Dialogfunktionen des offiziellen Claude einfach nutzen.

## Claude Fable 5.2

Verwenden Sie die vollständige Modellbezeichnung `claude-fable-5-2`. Dieses Modell eignet sich für komplexes Schlussfolgern und langfristige Aufgaben; wenn native Denk-Inhaltsblöcke und Werkzeuginteraktionen erforderlich sind, verwenden Sie vorrangig Messages. Adaptives Denken ist dauerhaft aktiviert; lassen Sie `temperature`, `top_p` und `top_k` weg, verwenden Sie für die Werkzeugauswahl `auto` und erzwingen Sie keine bestimmten Werkzeuge. `max_tokens` deckt gleichzeitig das Denken und den endgültigen Text ab. Derzeit werden für dieses Modell keine Responses- und Count-Tokens-Schnittstellen bereitgestellt.

Umgerechnet auf das aktuelle größte Paket (142,800 Credits／$13,584) kostet Fable 5.2 für reguläre Eingaben $3.20 und für Ausgaben $16／pro Million Token; Cache-Lesezugriffe kosten $0.08, und Cache-Schreibvorgänge für 5 Minuten／1 Stunde kosten jeweils $4／$6.40／pro Million Token. Die oben genannten Preise entsprechen 40 % des offiziellen Standard-API-Preises (60 % günstiger); für weitere Pakete und zusätzliche Kontorabatte beachten Sie bitte die Modellpreis-Seite und die Rechnung.

## Beantragungsprozess

Um die Claude Chat Completion API zu nutzen, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten und ihn als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zu dieser Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Bei der ersten Beantragung wird ein kostenloses Kontingent vergeben, das kostenlos getestet werden kann; wenn das Kontingent nicht ausreicht, können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Grundlegende Nutzung

Als Nächstes können Sie die entsprechenden Inhalte in der Oberfläche ausfüllen, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Bei der ersten Nutzung dieser Schnittstelle müssen wir mindestens drei Inhalte ausfüllen. Einer davon ist `authorization`, das direkt in der Dropdown-Liste ausgewählt werden kann. Ein weiterer Parameter ist `model`, wobei öffentliche Modelle wie `claude-opus-5-5`, `claude-fable-5-1` usw. auswählbar sind; das ursprüngliche `claude-fable-5` kann weiterhin aufgerufen werden. Der letzte Parameter ist `messages`, ein Array von Frage-Prompts, wobei jedes Element `role` und `content` enthält; `role` unterstützt `user`, `assistant`, `system`, und `content` ist der konkrete Inhalt. Wenn vollständige Claude-Denk-Inhaltsblöcke, Signaturen und native Werkzeugsemantik erforderlich sind, verwenden Sie weiterhin die Messages API.

Gleichzeitig können Sie feststellen, dass auf der rechten Seite entsprechender Aufrufcode generiert wird. Sie können den Code kopieren und direkt ausführen oder direkt auf die Schaltfläche „Try“ klicken, um ihn zu testen.

Häufig verwendete optionale Parameter:

- `max_tokens`: Begrenzt die maximale Anzahl von Token für eine einzelne Antwort.
- `temperature`: Zufälligkeit der Generierung, zwischen 0 und 2; je größer der Wert, desto stärker die Streuung.
- `n`: Wie viele Kandidatenantworten auf einmal generiert werden.
- `response_format`: Einstellung des Rückgabeformats.

`claude-opus-5-5` unterstützt reguläre und gestreamte Chat Completions; dieses Modell erlaubt nur `n=1`. Setzen Sie dafür keine `temperature` unter 1 und kein nicht standardmäßiges `top_p`; verwenden Sie für Werkzeugaufrufe `tool_choice: "auto"` und erzwingen Sie keine bestimmten Werkzeuge. Die Chat-kompatible Schnittstelle gibt keine nativen Denk-Inhaltsblöcke zurück.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Nach dem Aufruf stellen wir fest, dass das Rückgabeergebnis wie folgt lautet:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }
}
```

Das Rückgabeergebnis enthält mehrere Felder, die wie folgt vorgestellt werden:

- `id`, die ID der generierten Dialogaufgabe, die zur eindeutigen Identifizierung dieser Dialogaufgabe verwendet wird.
- `model `, das ausgewählte Claude-Modell der offiziellen Website.
- `choices`, die Antwortinformationen, die Claude für den Frage-Prompt bereitstellt.
- `usage `: Statistische Informationen zu Token für diese Frage-und-Antwort-Runde.

Im Chat-Completions-Format ist `usage.prompt_tokens` die gesamte Eingabemenge; `prompt_tokens_details.cached_tokens` und `prompt_tokens_details.cache_write_tokens` erfassen jeweils die Details von Cache-Lese- und Schreibvorgängen. `completion_tokens_details.reasoning_tokens` ist eine Teilmenge von `completion_tokens` und darf bei der Berechnung der Gesamtmenge oder Kosten nicht erneut addiert werden. Nicht gestreamte Antworten können außerdem ein `usage.cost`-Objekt zurückgeben, wobei `amount` der tatsächliche Kontingentverbrauch, `currency` die Maßeinheit und `list_amount` der Betrag vor Rabatt ist (falls vorhanden).

Der Feldname bei Chat-compatible lautet `reasoning_tokens`; die native Messages API verwendet `output_tokens_details.thinking_tokens`. Die Wire-Schemas der beiden Protokolle unterscheiden sich, und Clients sollten Feldnamen nicht vermischen.

Dabei enthält `choices` die Antwortinformationen von Claude, und die darin enthaltenen `choices` sind die konkreten Informationen der Claude-Antwort, wie in der Abbildung gezeigt.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Es ist zu sehen, dass das Feld `content` in `choices` den konkreten Inhalt der Claude-Antwort enthält.

## Gestreamte Antworten

Diese Schnittstelle unterstützt auch gestreamte Antworten, was für die Web-Anbindung sehr nützlich ist und es Webseiten ermöglicht, einen Effekt der zeichenweisen Anzeige zu erzielen.

Wenn Sie Antworten gestreamt zurückgeben möchten, können Sie den Parameter `stream ` im Request-Header ändern und auf `true` setzen.

Die Änderung ist wie in der Abbildung gezeigt, allerdings muss der Aufrufcode entsprechend geändert werden, um gestreamte Antworten zu unterstützen.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>
Nachdem `stream` auf `true` gesetzt wurde, gibt die API die entsprechenden JSON-Daten zeilenweise zurück. Auf Code-Ebene müssen wir entsprechende Änderungen vornehmen, um die zeilenweisen Ergebnisse zu erhalten.

Python-Beispielaufrufcode:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```


## Tiefgehendes Denken

Die Claude-Modelle der neuen Generation können gemäß der Standardstrategie des Modells schlussfolgern, ohne dass dies durch das Modell-Suffix `-thinking` ausgelöst werden muss. Chat-kompatible Antworten verwenden das OpenAI-kompatible usage-Feld `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` sind bereits in `completion_tokens` enthalten und dürfen nicht erneut addiert werden. Schlussfolgerungen und sichtbarer Haupttext teilen sich die Obergrenze für Ausgabe-Token, daher kann der Haupttext bei einem niedrigen `max_tokens` leer sein oder abgeschnitten werden; erhöhen Sie in diesem Fall das Ausgabebudget oder wählen Sie, sofern das verwendete Modell dies unterstützt, einen geringeren Schlussfolgerungsaufwand.

Falls natives `thinking`, `output_config.effort`, Thinking-Inhaltsblöcke sowie die Rückgabe von Signaturen benötigt werden, verwenden Sie bitte `/v1/messages`. Das entsprechende usage-Feld für Messages lautet `output_tokens_details.thinking_tokens`; vermischen Sie es nicht mit `completion_tokens_details.reasoning_tokens` von Chat-kompatiblen Antworten.

## Visuelles Modell

claude-sonnet-4-20250514 ist ein von Claude entwickeltes multimodales großes Sprachmodell, das auf Grundlage von claude-4 um visuelle Verständnisfähigkeiten erweitert wurde. ## Fehlerbehandlung

Wenn beim Aufrufen der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Information zurück. Zum Beispiel:

- `400 token_mismatched`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`：Nicht autorisiert, ungültiges oder fehlendes Autorisierungs-Token.
- `429 too_many_requests`：Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`：Interner Serverfehler, auf dem Server ist ein Fehler aufgetreten.

### Beispiel für Fehlerantwort

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
