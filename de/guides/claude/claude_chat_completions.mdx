Anthropic Claude ist ein sehr leistungsstarkes KI-Dialogsystem, das in nur wenigen Sekunden flüssige und natürliche Antworten generieren kann, solange Sie einen Prompt eingeben. Claude zeichnet sich in der Branche durch sein hervorragendes Sprachverständnis und seine Generierungsfähigkeiten aus. Heute wird Claude bereits in verschiedenen Branchen und Bereichen weit verbreitet eingesetzt, und sein Einfluss wird immer deutlicher. Ob bei alltäglichen Gesprächen, kreativem Schreiben oder professioneller Beratung und Code-Programmierung – Claude kann beeindruckende intelligente Unterstützung bieten und die Arbeitseffizienz und Kreativität der Menschen erheblich steigern.

Dieses Dokument stellt hauptsächlich den Nutzungsablauf der Claude Chat Completion API vor. Mit ihr können wir die Dialogfunktion des offiziellen Claude ganz einfach nutzen.

## Beantragungsprozess

Um die Claude Chat Completion API zu verwenden, rufen Sie zuerst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten und ihn als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zu dieser Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, das kostenlos getestet werden kann; wenn das Kontingent nicht ausreicht, können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) das allgemeine Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Grundlegende Nutzung

Als Nächstes können Sie die entsprechenden Inhalte in der Oberfläche ausfüllen, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Bei der ersten Verwendung dieser Schnittstelle müssen wir mindestens drei Inhalte ausfüllen. Einer davon ist `authorization`, der direkt in der Dropdown-Liste ausgewählt werden kann. Ein weiterer Parameter ist `model`, wobei öffentliche Modelle wie `claude-opus-5-5`, `claude-fable-5-1` usw. auswählbar sind; das ursprüngliche `claude-fable-5` kann weiterhin aufgerufen werden. Der letzte Parameter ist `messages`, ein Array von Fragen, bei dem jedes Element `role` und `content` enthält; `role` unterstützt `user`, `assistant`, `system`, und `content` ist der konkrete Inhalt. Wenn vollständige Claude-Denkblöcke, Signaturen und native Werkzeugsemantik benötigt werden, verwenden Sie weiterhin die Messages API.

Gleichzeitig können Sie feststellen, dass auf der rechten Seite entsprechender generierter Aufrufcode vorhanden ist. Sie können den Code kopieren und direkt ausführen oder zum Testen direkt auf die Schaltfläche „Try“ klicken.

Häufig verwendete optionale Parameter:

- `max_tokens`: Begrenzt die maximale Anzahl von Tokens für eine einzelne Antwort.
- `temperature`: Generierungszufälligkeit, zwischen 0 und 2; je größer der Wert, desto stärker die Streuung.
- `n`: Wie viele Kandidatenantworten auf einmal generiert werden.
- `response_format`: Einstellung des Rückgabeformats.

`claude-opus-5-5` unterstützt reguläre und gestreamte Chat Completions; dieses Modell erlaubt nur `n=1`. Setzen Sie für dieses Modell keine `temperature` unter 1 und kein nicht standardmäßiges `top_p`; verwenden Sie für Werkzeugaufrufe `tool_choice: "auto"` und erzwingen Sie keine Werkzeugauswahl. Die Chat-kompatible Schnittstelle gibt keine nativen Denkblöcke zurück.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Nach dem Aufruf stellen wir fest, dass das Rückgabeergebnis wie folgt aussieht:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }
}
```

Das Rückgabeergebnis enthält mehrere Felder, die wie folgt vorgestellt werden:

- `id`, die ID der generierten Dialogaufgabe, die zur eindeutigen Identifizierung dieser Dialogaufgabe verwendet wird.
- `model `, das ausgewählte Modell der offiziellen Claude-Website.
- `choices`, die Antwortinformationen, die Claude für den Prompt bereitstellt.
- `usage `: Statistische Informationen zu Tokens für diese Frage und Antwort.

Im Chat-Completions-Format ist `usage.prompt_tokens` die gesamte Eingabemenge; `prompt_tokens_details.cached_tokens` und `prompt_tokens_details.cache_write_tokens` erfassen jeweils die Details des Cache-Lesens und -Schreibens. `completion_tokens_details.reasoning_tokens` ist eine Teilmenge von `completion_tokens` und sollte bei der Berechnung der Gesamtmenge oder Kosten nicht erneut addiert werden. Nicht gestreamte Antworten können außerdem ein `usage.cost`-Objekt zurückgeben, wobei `amount` der tatsächliche Kontingentverbrauch, `currency` die Maßeinheit und `list_amount` der Betrag vor Rabatt ist (falls vorhanden).

Der Feldname bei Chat-compatible lautet `reasoning_tokens`; die native Messages API verwendet `output_tokens_details.thinking_tokens`. Die Wire-Schemas der beiden Protokolle unterscheiden sich, daher sollten Clients die Feldnamen nicht vermischen.

Dabei enthält `choices` die Antwortinformationen von Claude, und das darin enthaltene `choices` sind die konkreten Informationen der Claude-Antwort, wie in der Abbildung zu sehen ist.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Es ist zu sehen, dass das Feld `content` in `choices` den konkreten Inhalt der Claude-Antwort enthält.

## Gestreamte Antwort

Diese Schnittstelle unterstützt auch gestreamte Antworten, was für die Anbindung von Webseiten sehr nützlich ist und es Webseiten ermöglicht, einen Effekt der zeichenweisen Anzeige zu erzielen.

Wenn Sie die Antwort gestreamt zurückgeben möchten, können Sie den Parameter `stream ` im Request-Header auf `true` ändern.

Die Änderung ist wie in der Abbildung gezeigt, allerdings muss der Aufrufcode entsprechend geändert werden, um gestreamte Antworten zu unterstützen.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

Nachdem `stream` auf `true` geändert wurde, gibt die API die entsprechenden JSON-Daten zeilenweise zurück. Auf Codeebene müssen wir entsprechende Änderungen vornehmen, um die zeilenweisen Ergebnisse zu erhalten.

Python-Beispielaufrufcode:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

```javascript
const options = {
  method: "post",

    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "claude-opus-4-20250514",
    messages: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/v1/chat/completions", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Mehrere Dialogrunden

Wenn Sie die Funktion für mehrere Dialogrunden anbinden möchten, müssen Sie mehrere Eingabeaufforderungen im Feld `messages` hochladen. Ein konkretes Beispiel für mehrere Eingabeaufforderungen ist in der folgenden Abbildung dargestellt:

Python-Beispielaufrufcode:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
```

## Tiefgehendes Denken
Modelle der neuen Generation von Claude können gemäß der Standardstrategie des Modells schlussfolgern, ohne dass dies über das Modellsuffix `-thinking` ausgelöst werden muss. Chat-kompatible Antworten verwenden das OpenAI-kompatible usage-Feld `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` ist bereits in `completion_tokens` enthalten, bitte nicht doppelt addieren. Schlussfolgerungen und sichtbarer Haupttext teilen sich die Obergrenze für Ausgabe-Token, daher kann der Haupttext bei einem niedrigen `max_tokens` leer sein oder abgeschnitten werden; erhöhen Sie in diesem Fall das Ausgabebudget oder wählen Sie, wenn das verwendete Modell dies unterstützt, einen geringeren Schlussfolgerungsaufwand.

Wenn Sie natives `thinking`, `output_config.effort`, thinking-Inhaltsblöcke und die Rückgabe von Signaturen benötigen, verwenden Sie bitte `/v1/messages`. Das entsprechende usage-Feld für Messages lautet `output_tokens_details.thinking_tokens`; vermischen Sie es nicht mit `completion_tokens_details.reasoning_tokens` von Chat-kompatiblen Antworten.

## Visuelle Modelle

claude-sonnet-4-20250514 ist ein von Claude entwickeltes multimodales großes Sprachmodell, das auf Basis von claude-4 um visuelle Verständnisfähigkeiten erweitert wurde. Dieses Modell kann Text- und Bildeingaben gleichzeitig verarbeiten und ermöglicht multimodales Verstehen und Generieren.

Die Textverarbeitung bei Verwendung des Modells claude-sonnet-4-20250514 entspricht dem oben beschriebenen grundlegenden Inhalt zur Nutzung. Im Folgenden wird kurz erläutert, wie die Bildverarbeitungsfähigkeiten des Modells verwendet werden.

Die Bildverarbeitungsfähigkeit des Modells claude-sonnet-4-20250514 wird hauptsächlich genutzt, indem dem ursprünglichen `content`-Inhalt ein `type`-Feld hinzugefügt wird. Über dieses Feld kann erkannt werden, ob Text oder ein Bild hochgeladen wurde, um dadurch die Bildverarbeitungsfähigkeit des Modells claude-sonnet-4-20250514 zu nutzen. Im Folgenden wird hauptsächlich beschrieben, wie diese Funktion auf zwei Arten, mit Curl und Python, aufgerufen wird.

## Fehlerbehandlung

Wenn beim Aufrufen der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Information zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungs-Token.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
