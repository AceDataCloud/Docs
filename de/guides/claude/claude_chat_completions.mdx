Anthropic Claude ist ein sehr leistungsstarkes KI-Dialogsystem, das durch die einfache Eingabe von Prompts innerhalb weniger Sekunden flüssige und natürliche Antworten generieren kann. Claude hebt sich in der Branche durch sein hervorragendes Sprachverständnis und seine Generierungsfähigkeiten hervor. Heute wird Claude bereits in zahlreichen Branchen und Bereichen umfassend eingesetzt, und sein Einfluss wird immer deutlicher. Ob bei alltäglichen Gesprächen, kreativem Schreiben, professioneller Beratung oder Code-Programmierung – Claude kann beeindruckende intelligente Unterstützung bieten und die Arbeitseffizienz und Kreativität der Menschen erheblich steigern.

Dieses Dokument stellt hauptsächlich den Nutzungsprozess der Claude Chat Completion API vor. Mit ihr können wir die Dialogfunktion des offiziellen Claude einfach nutzen.

## Beantragungsprozess

Um die Claude Chat Completion API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten und ihn für später bereitzuhalten.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, wo Sie zur Registrierung und Anmeldung aufgefordert werden. Nach Abschluss kehren Sie automatisch zu dieser Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen; es ist nicht erforderlich, jeden Dienst einzeln zu beantragen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, das Sie kostenlos testen können; bei unzureichendem Kontingent können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Grundlegende Verwendung

Als Nächstes können Sie die entsprechenden Inhalte in der Oberfläche ausfüllen, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Bei der ersten Verwendung dieser Schnittstelle müssen wir mindestens drei Inhalte ausfüllen. Einer davon ist `authorization`, das direkt in der Dropdown-Liste ausgewählt werden kann. Ein weiterer Parameter ist `model`; empfohlen wird das neueste Flaggschiffmodell `claude-fable-5-1`; das bisherige `claude-fable-5` kann weiterhin aufgerufen werden. Der letzte Parameter ist `messages`, ein Array von Frage-Prompts, dessen jedes Element `role` und `content` enthält; `role` unterstützt `user`, `assistant`, `system`, und `content` ist der konkrete Inhalt. Claude Fable 5.1 unterstützt 1 Million Token Kontext und eine maximale Ausgabe von 128K Token.

Gleichzeitig können Sie feststellen, dass auf der rechten Seite entsprechender Aufrufcode generiert wird. Sie können den Code kopieren und direkt ausführen oder direkt auf die Schaltfläche „Try“ klicken, um ihn zu testen.

Häufig verwendete optionale Parameter:

- `max_tokens`: Begrenzt die maximale Anzahl von Tokens für eine einzelne Antwort.
- `temperature`: Generierungszufälligkeit, zwischen 0 und 2; je größer der Wert, desto stärker die Streuung.
- `n`: Wie viele Kandidatenantworten auf einmal generiert werden.
- `response_format`: Einstellung des Rückgabeformats.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Nach dem Aufruf stellen wir fest, dass das Rückgabeergebnis wie folgt aussieht:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }
}
```

Das Rückgabeergebnis enthält mehrere Felder, die wie folgt vorgestellt werden:

- `id`, die ID der generierten Dialogaufgabe, die zur eindeutigen Kennzeichnung dieser Dialogaufgabe verwendet wird.
- `model `, das ausgewählte Modell von der offiziellen Claude-Website.
- `choices`, die Antwortinformationen, die Claude für den Frage-Prompt bereitstellt.
- `usage `: Statistische Informationen zu den Tokens dieser Frage und Antwort.

Im Chat-Completions-Format ist `usage.prompt_tokens` die Gesamteingabemenge; `prompt_tokens_details.cached_tokens` und `prompt_tokens_details.cache_write_tokens` erfassen jeweils die Details des Cache-Lesens und -Schreibens. `completion_tokens_details.reasoning_tokens` ist eine Teilmenge von `completion_tokens` und sollte bei der Berechnung der Gesamtmenge oder der Kosten nicht erneut hinzuaddiert werden. Nicht-streamende Antworten können außerdem ein `usage.cost`-Objekt zurückgeben, wobei `amount` der tatsächliche Kontingentverbrauch, `currency` die Maßeinheit und `list_amount` der Betrag vor Rabatt ist (falls vorhanden).

Der Feldname von Chat-compatible lautet `reasoning_tokens`; die native Messages API verwendet `output_tokens_details.thinking_tokens`. Die Wire-Schemas der beiden Protokolle unterscheiden sich, und Clients sollten die Feldnamen nicht vermischen.

Dabei enthält `choices` die Antwortinformationen von Claude, und das darin enthaltene `choices` sind die konkreten Informationen der Claude-Antwort, wie in der Abbildung gezeigt.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Wie zu sehen ist, enthält das Feld `content` in `choices` den konkreten Inhalt der Claude-Antwort.

## Streaming-Antworten

Diese Schnittstelle unterstützt auch Streaming-Antworten, was für die Anbindung von Webseiten sehr nützlich ist und es Webseiten ermöglicht, einen Effekt der zeichenweisen Anzeige zu realisieren.

Wenn Sie Antworten als Stream zurückgeben möchten, können Sie den Parameter `stream ` im Request-Header ändern und auf `true` setzen.

Die Änderung ist wie in der Abbildung gezeigt, allerdings muss der Aufrufcode entsprechend angepasst werden, damit Streaming-Antworten unterstützt werden.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

Nachdem `stream` auf `true` gesetzt wurde, gibt die API die entsprechenden JSON-Daten zeilenweise zurück. Auf Codeebene müssen wir entsprechende Änderungen vornehmen, um die zeilenweisen Ergebnisse zu erhalten.

Beispiel-Aufrufcode für Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

```javascript
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Tiefes Nachdenken
Die neue Generation der Claude-Modelle kann gemäß der Standardstrategie des Modells schlussfolgern, ohne dass dies durch das Modell-Suffix `-thinking` ausgelöst werden muss. Chat-kompatible Antworten verwenden das OpenAI-kompatible usage-Feld `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` sind bereits in `completion_tokens` enthalten, bitte nicht doppelt addieren. Schlussfolgerungen und sichtbarer Haupttext teilen sich das Ausgabetoken-Limit, daher kann bei einem kleinen `max_tokens` der Haupttext leer sein oder abgeschnitten werden; erhöhen Sie in diesem Fall das Ausgabebudget oder wählen Sie, sofern das verwendete Modell dies unterstützt, einen geringeren Schlussfolgerungsaufwand.

Wenn Sie natives `thinking`, `output_config.effort`, thinking-Inhaltsblöcke und die Rückgabe von Signaturen benötigen, verwenden Sie bitte `/v1/messages`. Das entsprechende usage-Feld für Messages ist `output_tokens_details.thinking_tokens`, nicht mit `completion_tokens_details.reasoning_tokens` von Chat-kompatiblen Aufrufen vermischen.

## Visuelle Modelle

claude-sonnet-4-20250514 ist ein von Claude entwickeltes multimodales großes Sprachmodell, das auf Basis von claude-4 über ein zusätzliches visuelles Verständnis verfügt. Dieses Modell kann Text- und Bildeingaben gleichzeitig verarbeiten und ermöglicht so modalitätsübergreifendes Verstehen und Generieren.

Die Textverarbeitung mit dem Modell claude-sonnet-4-20250514 entspricht den grundlegenden Verwendungsinhalten oben. Im Folgenden wird kurz erläutert, wie die Bildverarbeitungsfähigkeit des Modells verwendet wird.

Die Bildverarbeitungsfähigkeit des Modells claude-sonnet-4-20250514 wird hauptsächlich genutzt, indem auf Grundlage des ursprünglichen `content`-Inhalts ein `type`-Feld hinzugefügt wird. Über dieses Feld kann erkannt werden, ob Text oder ein Bild hochgeladen wurde, sodass die Bildverarbeitungsfähigkeit des Modells claude-sonnet-4-20250514 genutzt werden kann. Im Folgenden wird hauptsächlich beschrieben, wie diese Funktion auf zwei Arten, mit Curl und Python, aufgerufen wird.

## Fehlerbehandlung

Wenn beim Aufruf der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und Informationen zurück. Zum Beispiel:

- `400 token_mismatched`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`：Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`：Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`：Interner Serverfehler, auf dem Server ist ein Fehler aufgetreten.

### Beispiel für eine Fehlerantwort

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
