Dieser Artikel beschreibt die Integrationsanleitung für die Sora Videos Generation API. Mit dieser API können benutzerdefinierte Parameter eingegeben werden, um offizielle Sora-Videos zu generieren. Diese API unterstützt zwei Versionen:

- **Version 1 (Klassischer Modus)**: Unterstützt `duration` (10/15/25 Sekunden), `orientation` (Querformat/Hochformat), `size` (small/large Auflösung), Referenzbilder `image_urls`, Charakter-**###** `character_url` und weitere Parameter.
- **Version 2 (Partner-Modus)**: Unterstützt `seconds` (4/8/12 Sekunden), pixelgenaue Auflösung `size` (z. B. 1280x720), Referenzbilder `input_reference` und weitere Parameter.

## Antragsprozess

Um die Sora Videos Generation API zu nutzen, müssen Sie zunächst im [Ace Data Cloud Dashboard](https://platform.acedata.cloud/console/applications) Ihr API-Token abrufen und für später aufbewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss werden Sie automatisch zur aktuellen Seite zurückgeleitet.

**Ein API-Token reicht aus, um alle Dienste der Plattform zu nutzen, es ist nicht erforderlich, für jeden Dienst separat zu beantragen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, um es kostenlos auszuprobieren; wenn das Kontingent erschöpft ist, können Sie im [Dashboard](https://platform.acedata.cloud/console/coin) Ihr Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Sora Videos Generation API →](https://platform.acedata.cloud/documents/sora-videos)

## Grundlegende Nutzung (Version 1)

Zunächst sollten Sie die grundlegende Nutzung von Version 1 verstehen, indem Sie das Eingabewort `prompt`, das Array der Referenzbild-Links `image_urls` und das Modell `model` eingeben, um das verarbeitete Ergebnis zu erhalten. Die spezifischen Inhalte sind wie folgt:

<p><img src="https://cdn.acedata.cloud/h8dyz3.png" width="500" className="m-auto" /></p>

Hier sehen wir, dass wir die Request-Header festgelegt haben, einschließlich:

- `accept`: In welchem Format Sie die Antwort erhalten möchten, hier eingetragen als `application/json`, also im JSON-Format.
- `authorization`: Der Schlüssel zur API, den Sie nach der Beantragung direkt auswählen können.

Zusätzlich haben wir den Request-Body festgelegt, einschließlich:

- `model`: Das Modell zur Generierung des Videos, unterstützt `sora-2` (Standardmodus) und `sora-2-pro` (HD-Modus). Dabei kann `sora-2-pro` Videos mit einer `duration` von 25 Sekunden unterstützen, während `sora-2` nur 10 und 15 Sekunden unterstützt.
- `size`: Die Videoauflösung, `small` für Standardauflösung, `large` für HD-Auflösung (nur Version 1).
- `duration`: Die Videolänge, unterstützt 10, 15, 25 Sekunden, wobei 25 Sekunden nur von `sora-2-pro` unterstützt werden (nur Version 1).
- `orientation`: Die Bildausrichtung, unterstützt `landscape` (Querformat), `portrait` (Hochformat) (nur Version 1).
- `image_urls`: Array der Referenzbild-Links, verwendet für die Bild-zu-Video-Generierung (nur Version 1).
- `character_url`: Charakter-**###**-Link, echte Personen dürfen im Video nicht erscheinen (nur Version 1).
- `character_start`/`character_end`: Die Start- und Endsekunden des Charakters, der Bereich beträgt 1-3 Sekunden (nur Version 1).
- `prompt`: Eingabewort (erforderlich).
- `callback_url`: URL für die asynchrone Rückmeldung des Ergebnisses.
- `async`: Optional, wenn auf `true` gesetzt, gibt die Schnittstelle sofort `task_id` zurück, ohne dass `callback_url` bereitgestellt werden muss, und das Ergebnis kann dann über die entsprechende Task-Abfrage-Schnittstelle abgefragt werden.
- `version`: API-Version, `"1.0"` (Standard) oder `"2.0"`.

## Bild-zu-Video-Aufgabe (Version 1)

Wenn Sie eine Bild-zu-Video-Aufgabe durchführen möchten, muss zunächst der Parameter `image_urls` mit den Links zu den Referenzbildern übergeben werden, um die folgenden Inhalte anzugeben:

- `image_urls`: Das Array der Referenzbild-Links, das für diese Bild-zu-Video-Aufgabe verwendet wird. Beachten Sie, dass keine echten Bilder von Personen mit Gesichtern übergeben werden dürfen, da dies zu einem Fehlschlag der Aufgabe führen kann.

Ein Beispiel für die Eingabe sieht wie folgt aus:

<p><img src="https://cdn.acedata.cloud/ch7x3t.png" width="500" className="m-auto" /></p>

Nach dem Ausfüllen wurde automatisch der folgende Code generiert:

<p><img src="https://cdn.acedata.cloud/z1ud8l.png" width="500" className="m-auto" /></p>

Der entsprechende Code:
```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "size": "large",
    "duration": 15,
    "orientation": "landscape",
    "prompt": "Katze, die am Fluss läuft",
    "model": "sora-2",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Charakter-Generierung Videoaufgabe (Version 1)

Wenn Sie eine Charakter-Generierung Videoaufgabe durchführen möchten, muss zuerst der Parameter `character_url` mit dem Video-Link, der zur Erstellung des Charakters benötigt wird, übergeben werden. Beachten Sie, dass im Video auf keinen Fall echte Menschen erscheinen dürfen, sonst schlägt es fehl. Sie können den folgenden Inhalt angeben:

- character_url: Der Video-Link, der zur Erstellung des Charakters benötigt wird. Beachten Sie, dass im Video auf keinen Fall echte Menschen erscheinen dürfen, sonst schlägt es fehl.

Ein Beispiel für die Eingabe sieht wie folgt aus:

## Version 2.0 Modus

Neben dem oben genannten Version 1.0 Modus unterstützt diese API auch den Version 2.0 Modus, der durch Setzen des Parameters `version` auf `"2.0"` aktiviert werden kann. Der Version 2.0 Modus unterstützt kürzere Videolängen und pixelgenaue Auflösungssteuerung.

### Version 2.0 Parameterbeschreibung

| Parameter        | Typ      | Pflichtfeld | Beschreibung                                           |
| ---------------- | ------- | ----------- | ----------------------------------------------------- |
| `version`        | string  | Ja          | Setzen auf `"2.0"`                                   |
| `prompt`         | string  | Ja          | Hinweis für die Generierung des Videos                |
| `model`          | string  | Nein        | `sora-2` (Standard) oder `sora-2-pro`                |
| `duration`       | integer | Nein        | Videolänge: `4` (Standard), `8`, `12` Sekunden        |
| `size`           | string  | Nein        | Auflösung: `720x1280` (Standard), `1280x720`, `1024x1792`, `1792x1024` |
| `image_urls`     | array   | Nein        | Array von Referenzbild-URLs, nur das erste Bild verwenden, die Bildgröße muss mit dem `size` Parameter übereinstimmen |
| `callback_url`   | string  | Nein        | Asynchrone Rückruf-URL                                |

### Grundbeispiel

```shell
curl -X POST 'https://api.acedata.cloud/sora/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "version": "2.0",
  "prompt": "Katze, die am Fluss läuft",
  "model": "sora-2",
  "duration": 8,
  "size": "1280x720"
}'
```

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "version": "2.0",
    "prompt": "Katze, die am Fluss läuft",
    "model": "sora-2",
    "seconds": 8,
    "size": "1280x720"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Der entsprechende JavaScript-Code:


### Verwendung von Referenzbildern (Version 2.0)

Im Modus Version 2.0 können Referenzbilder über den Parameter `image_urls` übergeben werden, um die Videoerstellung zu steuern (nur das erste Bild verwenden):

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "version": "2.0",
    "prompt": "eine Person, die durch einen schönen Garten geht",
    "model": "sora-2",
    "duration": 4,
    "size": "1280x720",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

> **Hinweis**: Die Größe der Referenzbilder sollte mit dem Parameter `size` übereinstimmen, z. B. wenn `size` `1280x720` ist, sollte die Größe des Referenzbildes 1280×720 betragen.

### Vergleich der Parameter zwischen Version 1.0 und Version 2.0

| Parameter         | Version 1.0           | Version 2.0                             |
| ---------------- | --------------------- | --------------------------------------- |
| `version`        | 1.0 (Standard)        | 2.0                                     |
| `prompt`         | ✅                     | ✅                                       |
| `model`          | ✅ sora-2 / sora-2-pro | ✅ sora-2 / sora-2-pro                   |
| `duration`       | ✅ 10/15/25 Sekunden    | ✅ 4/8/12 Sekunden                        |
| `orientation`    | ✅ Landschaft/Hochformat | ❌                                       |
| `size`           | ✅ klein/groß         | ✅ 720x1280/1280x720/1024x1792/1792x1024 |
| `image_urls`     | ✅ mehrere Referenzbilder | ✅ nur das erste Bild                     |
| `character_url`  | ✅                     | ❌                                       |
| `callback_url`   | ✅                     | ✅                                       |

## Asynchrone Rückrufe

Da die von der Sora Videos Generation API erzeugte Zeit relativ lang ist, etwa 1-2 Minuten, bleibt die HTTP-Anfrage bei längerer Nichtreaktion der API verbunden, was zu einem zusätzlichen Verbrauch von Systemressourcen führt. Daher bietet diese API auch Unterstützung für asynchrone Rückrufe.

Der gesamte Ablauf ist: Wenn der Client die Anfrage stellt, gibt er zusätzlich ein Feld `callback_url` an. Nachdem der Client die API-Anfrage gestellt hat, gibt die API sofort ein Ergebnis zurück, das ein Feld `task_id` enthält, das die aktuelle Aufgaben-ID darstellt. Wenn die Aufgabe abgeschlossen ist, wird das Ergebnis des generierten Videos in Form von POST JSON an die vom Client angegebene `callback_url` gesendet, wobei auch das Feld `task_id` enthalten ist, sodass die Aufgabenergebnisse über die ID miteinander verknüpft werden können.

Lassen Sie uns anhand eines Beispiels verstehen, wie dies konkret funktioniert.

Zunächst ist der Webhook-Rückruf ein Dienst, der HTTP-Anfragen empfangen kann. Entwickler sollten die URL ihres eigenen HTTP-Servers ersetzen. ## Fehlerbehandlung

Wenn beim Aufruf der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die Informationen zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Unbefugt, ungültiger oder fehlender Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Kontingent überschritten.
- `500 api_error`: Interner Serverfehler, etwas ist auf dem Server schiefgelaufen.

### Beispiel für eine Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "Abruf fehlgeschlagen"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
