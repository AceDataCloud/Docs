Dieser Artikel beschreibt die Integrationsmethode für die HappyHorse Videos API. Diese Schnittstelle unterstützt die Erstellung von Videos aus Text, die Erstellung von Videos aus dem ersten Bild, die Erstellung von Videos aus Referenzbildern und die Videobearbeitung über den einheitlichen Eingang `/happyhorse/videos` und den Parameter `action`.

## Antragsprozess

Um die HappyHorse Videos API zu nutzen, müssen Sie zunächst Ihr API-Token im [Ace Data Cloud Dashboard](https://platform.acedata.cloud/console/applications) abrufen und für zukünftige Verwendung aufbewahren.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss werden Sie automatisch zur aktuellen Seite zurückgeleitet.

**Ein API-Token reicht aus, um alle Dienste der Plattform zu nutzen, es ist nicht erforderlich, für jeden Dienst separat zu beantragen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, um es kostenlos auszuprobieren; wenn das Kontingent nicht ausreicht, können Sie im [Dashboard](https://platform.acedata.cloud/console/coin) Ihr Guthaben aufladen.

> 📘 Vollständige Dokumentation: [HappyHorse Videos API →](https://platform.acedata.cloud/documents/happyhorse-videos)

## Operationstypen

`action` bestimmt den Generierungsmodus dieser Anfrage:

- `generate`: Video aus Text, Standardaktion, unterstützt `happyhorse-1.0-t2v` und `happyhorse-1.1-t2v`, `prompt` muss übergeben werden.
- `image_to_video`: Video aus dem ersten Bild, unterstützt `happyhorse-1.0-i2v` und `happyhorse-1.1-i2v`, `image_url` muss übergeben werden.
- `reference_to_video`: Video aus Referenzbildern, unterstützt `happyhorse-1.0-r2v` und `happyhorse-1.1-r2v`, `prompt` und 1–9 `image_urls` müssen übergeben werden.
- `video_edit`: Videobearbeitung, unterstützt `happyhorse-1.0-video-edit`, `prompt` und `video_url` müssen übergeben werden, optional können 0–5 Referenzbilder `image_urls` übergeben werden.

Jede Aktion verwendet standardmäßig das Modell 1.1; `video_edit` unterstützt derzeit nur `happyhorse-1.0-video-edit`.

## Grundlegende Verwendung

Für die Erstellung von Videos aus Text muss nur `prompt` bereitgestellt werden, es können auch Parameter wie `resolution`, `ratio`, `duration` usw. angegeben werden:

```json
{
  "action": "generate",
  "model": "happyhorse-1.1-t2v",
  "prompt": "Ein filmischer weißer Hengst hebt seinen Kopf, die Mähne bewegt sich sanft im Wind der Morgensonne, langsame Kamerafahrt, warmes Filmlicht",
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}
```

Ein Beispiel für das Rückgabeergebnis:

```json
{
  "success": true,
  "task_id": "27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1",
  "trace_id": "6071ab5e-2f37-46f0-9e07-f1e378112e69",
  "data": [
    {
      "id": "9650580f-6d9e-4bc1-823a-29011790c5cb",
      "video_url": "https://platform2.cdn.acedata.cloud/happyhorse/27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1.mp4",
      "state": "succeeded",
      "duration": 5,
      "resolution": "720P",
      "ratio": null
    }
  ]
}
```

Feldbeschreibung:

- `success`: Ob die Anfrage erfolgreich war.
- `task_id`: Die Task-ID auf der Ace Data Cloud-Seite, die zur Abfrage des Taskstatus verwendet werden kann.
- `trace_id`: Die Verfolgungs-ID dieser Anfrage, die zur Fehlersuche verwendet wird.
- `data`: Liste der Videoergebnisse.
  - `id`: Die Task-ID auf der HappyHorse-Seite.
  - `video_url`: CDN-Link zur generierten Video.
  - `state`: Status der Aufgabe, wählbar zwischen `pending` / `succeeded` / `error`.
  - `duration`: Abrechnungsdauer des Videos, in Sekunden; `video_edit` ist die Summe der Eingangs- und Ausgangsdauer des Videos.
  - `resolution`: Ausgaberesolution.
  - `ratio`: Ausgabeverhältnis.

Der entsprechende CURL-Code sieht wie folgt aus:

```shell
curl -X POST 'https://api.acedata.cloud/happyhorse/videos' \
-H 'authorization: Bearer ${bearer_token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "happyhorse-1.1-t2v",
  "prompt": "Ein filmischer weißer Hengst hebt seinen Kopf, die Mähne bewegt sich sanft im Wind der Morgensonne, langsame Kamerafahrt, warmes Filmlicht",
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}'
```

Der entsprechende Python-Code sieht wie folgt aus:

```python
import requests

url = "https://api.acedata.cloud/happyhorse/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "action": "generate",
    "model": "happyhorse-1.1-t2v",
    "prompt": "Ein filmischer weißer Hengst hebt seinen Kopf, die Mähne bewegt sich sanft im Wind der Morgensonne, langsame Kamerafahrt, warmes Filmlicht",
    "resolution": "720P",
    "ratio": "16:9",
    "duration": 5,
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Video aus dem ersten Bild

Bei der Verwendung von `image_to_video` wird `image_url` als erstes Bild des Videos verwendet. Das Ausgabeverhältnis wird versuchen, dem Bild des ersten Bildes zu folgen, daher muss `ratio` nicht übergeben werden.

```json
{
  "action": "image_to_video",
  "model": "happyhorse-1.1-i2v",
  "image_url": "https://cdn.acedata.cloud/b1c82e4937.png",
  "prompt": "Ein filmischer weißer Hengst hebt seinen Kopf, die Mähne bewegt sich sanft im Wind der Morgensonne, langsame Kamerafahrt, warmes Filmlicht",
  "resolution": "1080P",
  "duration": 5
}
```

## Video aus Referenzbildern

Bei der Verwendung von `reference_to_video` können `image_urls` 1–9 Referenzbilder übergeben werden. In den Hinweisen können die Bilder in der entsprechenden Reihenfolge mit `character1`, `character2` usw. referenziert werden.

```json
{
  "action": "reference_to_video",
  "model": "happyhorse-1.1-r2v",
  "prompt": "character1 geht durch eine Wiese bei Sonnenaufgang mit dem warmen Leder- und Goldverzierung-Stil von character2",
  "image_urls": [
    "https://cdn.acedata.cloud/b1c82e4937.png",
    "https://cdn.acedata.cloud/eb75d88a3f.png"
  ],
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}
```

## Videobearbeitung

Bei der Verwendung von `video_edit` müssen die zu bearbeitende Video-URL `video_url` und die Bearbeitungsabsicht `prompt` übergeben werden. Optionale `image_urls` dienen als Referenzbilder, z. B. für Kostümwechsel, Stilübertragungen oder Teilersetzungen. `audio_setting` kann `auto` oder `origin` sein, wobei `origin` bedeutet, dass der Originalton des Videos beibehalten wird.

```json
{
  "action": "video_edit",
  "model": "happyhorse-1.0-video-edit",
  "prompt": "Wenden Sie den warmen Leder- und Goldverzierung-Stil des Referenzbildes an, während Sie die ursprüngliche Kamerabewegung beibehalten",
  "video_url": "https://platform2.cdn.acedata.cloud/happyhorse/27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1.mp4",
  "image_urls": [
    "https://cdn.acedata.cloud/eb75d88a3f.png"
  ],
  "resolution": "720P",
  "audio_setting": "auto"
}
```

## Asynchrone Rückrufe
Die Videoerstellung benötigt eine gewisse Verarbeitungszeit. Wenn Sie nicht lange warten möchten, können Sie `callback_url` übergeben. In diesem Fall gibt die API sofort `task_id` zurück, und nach Abschluss der Aufgabe wird das endgültige Ergebnis an diese Adresse POST gesendet:

```json
{
  "action": "generate",
  "prompt": "Ein Pferd, das durch einen verschneiten Wald läuft",
  "duration": 5,
  "callback_url": "https://your-domain.com/callback/happyhorse"
}
```

Das sofort zurückgegebene Ergebnis sieht wie folgt aus:

```json
{
  "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea"
}
```

Wenn Sie nur polling wünschen und keinen Callback benötigen, können Sie `"async": true` übergeben und anschließend die Ergebnisse der Aufgabe über die [HappyHorse Tasks API](https://platform.acedata.cloud/documents/happyhorse-tasks) abfragen.

## Abrechnungsinformationen

HappyHorse berechnet nach der Anzahl der ausgegebenen Videosekunden und der Auflösung:

- `720P`: ab etwa $0.105 / Sekunde.
- `1080P`: ab etwa $0.18 / Sekunde.
- `video_edit`: wird basierend auf der Gesamtdauer des Eingabe- und Ausgabenvideos berechnet, die tatsächliche Abrechnungsdauer richtet sich nach der Statistik nach Abschluss der Aufgabe.

Fehlgeschlagene Aufgaben werden nicht abgerechnet und beanspruchen auch nicht das kostenlose Kontingent.

## Fehlerbehandlung

Wenn bei der Anfrage ein Problem auftritt, gibt die API den entsprechenden Fehlercode und die Beschreibung zurück, häufige sind:

- `400`: Anfrageparameter sind fehlerhaft, z. B. stimmt action nicht mit model überein, `prompt` / `image_url` / `video_url` fehlt oder `duration` überschreitet den Bereich von 3–15 Sekunden.
- `401`: Authentifizierung fehlgeschlagen, Token ungültig oder stimmt nicht mit der API überein.
- `403`: Unzureichendes Guthaben oder der Hinweis wurde aufgrund von Inhaltsüberprüfung abgelehnt.
- `429`: Anfragen sind zu häufig, es wurde eine Drosselung ausgelöst, bitte später erneut versuchen.
- `500`: Interner Serverfehler oder Erstellung fehlgeschlagen.
