Die Hauptfunktion der Artistic QR Tasks API besteht darin, den Status der Ausführung eines Auftrags anhand der von der Artistic QR Generation API generierten Auftrags-ID abzufragen.

Dieses Dokument wird die Anbindung der Artistic QR Tasks API im Detail erläutern und Ihnen helfen, diese API einfach zu integrieren und ihre leistungsstarken Funktionen voll auszuschöpfen. Mit der Artistic QR Tasks API können Sie den Status der Ausführung von Aufträgen der Artistic QR Generation API problemlos abfragen.

## Antragsprozess

Um die Artistic QR Tasks API zu nutzen, müssen Sie zunächst auf die Anmeldeseite [Artistic QR Generation API](https://platform.acedata.cloud/documents/qrart-generate) gehen und den entsprechenden Dienst beantragen, dann kopieren Sie die Auftrags-ID der Artistic QR Generation API, wie im Bild gezeigt:

<p><img src="https://cdn.acedata.cloud/2wicjy.png" width="500" className="m-auto" /></p>

Gehen Sie schließlich zur Seite der Artistic QR Tasks API [Artistic QR Tasks API](https://platform.acedata.cloud/documents/qrart-tasks), um den entsprechenden Dienst zu beantragen. Klicken Sie nach dem Betreten der Seite auf die Schaltfläche „Acquire“, wie im Bild gezeigt:

![Anmeldeseite](https://cdn.acedata.cloud/rci31i.png)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur [Anmeldeseite](https://platform.acedata.cloud) weitergeleitet, um sich zu registrieren und anzumelden. Nach der Anmeldung werden Sie automatisch zur aktuellen Seite zurückgeleitet.

Bei der ersten Antragstellung gibt es ein kostenloses Kontingent, mit dem Sie die API kostenlos nutzen können.

## Anfragebeispiel

Die Artistic QR Tasks API kann verwendet werden, um das Ergebnis einer API der Artistic QR Generation API abzufragen. Informationen zur Nutzung der Artistic QR Generation API finden Sie im Dokument [Artistic QR Generation API](https://platform.acedata.cloud/documents/qrart-generate).

Wir nehmen als Beispiel eine von der Artistic QR Generation API zurückgegebene Auftrags-ID und demonstrieren, wie man diese API verwendet. Angenommen, wir haben eine Auftrags-ID: e2c65b20-a970-431e-99c1-76721e799df8, im Folgenden zeigen wir, wie man durch Eingabe einer Auftrags-ID vorgeht.

### Anforderungsheader und Anforderungstext festlegen

**Request Headers** umfassen:

- `accept`: Gibt an, dass die Antwort im JSON-Format empfangen werden soll, hier eingetragen als `application/json`.
- `authorization`: Der Schlüssel zur API, der nach der Beantragung direkt ausgewählt werden kann.

**Request Body** umfasst:

- `id`: Die hochgeladene Auftrags-ID.
- `action`: Die Art der Operation auf dem Auftrag.

Einstellung wie im folgenden Bild gezeigt:

Es kann festgestellt werden, dass auf der rechten Seite der Seite bereits automatisch Code in verschiedenen Sprachen generiert wurde, wie im Bild gezeigt:

Einige Codebeispiele sind wie folgt:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/qrart/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "e2c65b20-a970-431e-99c1-76721e799df8",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/qrart/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "e2c65b20-a970-431e-99c1-76721e799df8",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

- `request`, die Anfrageinformationen im QR-Code-Auftrag.
- `response`, die Rückgabeinformationen im QR-Code-Auftrag.

- `action`: Die Art der Operation auf dem Auftrag.

## Fehlerbehandlung

Bei der Verwendung der API, wenn ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die Informationen zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Unbefugt, ungültiger oder fehlender Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Rate-Limit überschritten.
- `500 api_error`: Interner Serverfehler, etwas ist auf dem Server schiefgelaufen.

### Fehlerantwort Beispiel

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "Abruf fehlgeschlagen"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
