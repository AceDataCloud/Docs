Dieser Artikel stellt eine Anleitung zur Integration der Kling Motion Generation API vor, mit der durch die Eingabe benutzerdefinierter Parameter offizielle Kling-Videos generiert werden können.

## Antragsprozess

Um die Kling Motion Generation API zu verwenden, rufen Sie zunächst die [Ace Data Cloud Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihr API-Token zu erhalten und es als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zu dieser Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass jeder Dienst einzeln beantragt werden muss.** Bei der ersten Beantragung wird ein kostenloses Guthaben verschenkt, das kostenlos ausprobiert werden kann; bei unzureichendem Guthaben kann in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufgeladen werden.

> 📘 Vollständige Dokumentation: [Kling Motion Generation API →](https://platform.acedata.cloud/documents/kling-motion)

## Grundlegende Verwendung

Lernen wir zunächst die grundlegende Verwendung kennen: Geben Sie den Prompt `prompt`, das Referenzbild `image_url` sowie den Referenzvideo-Link `video_url` ein, um das verarbeitete Ergebnis zu erhalten. Anschließend müssen wir auch das Modell `mode` eingeben. Derzeit gibt es hauptsächlich die Modelle `std` und `pro`, die konkreten Inhalte sind wie folgt:

<p><img src="https://cdn.acedata.cloud/5qlpjt.png" width="500" className="m-auto" /></p>

Hier sehen wir, dass wir die Request Headers festgelegt haben, einschließlich:

- `accept`: Welches Format das empfangene Antwortergebnis haben soll; hier wird `application/json` eingetragen, also das JSON-Format.
- `authorization`: Der Schlüssel zum Aufrufen der API, der nach der Beantragung direkt per Dropdown ausgewählt werden kann.

Zusätzlich wurde der Request Body festgelegt, einschließlich:

- `image_url`: URL des Referenzbilds für das Aussehen der Person. Unterstützt JPG/JPEG/PNG, Datei ≤50MB, Breite und Höhe jeweils ≥300px, Seitenverhältnis 1:2.5～2.5:1; die Person sollte Oberkörper oder Ganzkörper sowie Kopf klar zeigen.
- `video_url`: URL des Aktionsreferenzvideos. Unterstützt MP4/MOV, Datei ≤100MB, Breite und Höhe jeweils 340–3850px, mindestens 3 Sekunden; bei `character_orientation=image` maximal 10 Sekunden, bei `character_orientation=video` maximal 30 Sekunden. Es wird empfohlen, ein kontinuierliches Video mit einer einzigen Aufnahme zu verwenden, in dem die Person stets im Bild bleibt.
- `mode`: Der Modus zum Generieren von Videos, hauptsächlich der Standardmodus `std` und der Hochgeschwindigkeitsmodus `pro`.
- `keep_original_sound`: Es kann ausgewählt werden, ob der Originalton des Videos beibehalten wird, Enum-Werte: yes, no.
- `character_orientation`: Die Ausrichtung der Person im generierten Video; es kann ausgewählt werden, ob sie dem Bild oder dem Video entspricht, Enum-Werte: image, video.
- `prompt`: Prompt.
- `callback_url`: URL, an die das Ergebnis zurückgerufen werden soll.
- `async`: Optional; wenn auf `true` gesetzt, gibt die Schnittstelle sofort `task_id` zurück, ohne dass `callback_url` bereitgestellt werden muss. Anschließend wird das Ergebnis durch Abfragen der entsprechenden Task-Abfrage-Schnittstelle per Polling abgerufen.

Nach der Auswahl können Sie feststellen, dass auf der rechten Seite auch der entsprechende Code generiert wurde, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/buwczd.png" width="500" className="m-auto" /></p>

Klicken Sie auf die Schaltfläche „Try“, um einen Test durchzuführen. Wie in der obigen Abbildung gezeigt, erhalten wir hier folgendes Ergebnis:

```json
{
  "success": true,
  "video_id": "842578800134742051",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "5.066",
  "state": "succeed",
  "task_id": "363c7a84-e880-472e-a4d4-098e50cfc292"
}
```

Das zurückgegebene Ergebnis enthält mehrere Felder, die wie folgt vorgestellt werden:

- `success`: Der Status der Video-Generierungsaufgabe zu diesem Zeitpunkt.
- `task_id`: Die ID der Video-Generierungsaufgabe zu diesem Zeitpunkt.
- `video_id`: Die Video-ID der Video-Generierungsaufgabe zu diesem Zeitpunkt.
- `video_url`: Der Video-Link der Video-Generierungsaufgabe zu diesem Zeitpunkt.
- `duration`: Die Videolänge der Video-Generierungsaufgabe zu diesem Zeitpunkt.
- `state`: Der Status der Video-Generierungsaufgabe zu diesem Zeitpunkt.

Wir sehen, dass wir zufriedenstellende Videoinformationen erhalten haben. Wir müssen lediglich über die Video-Link-Adresse von `data` im Ergebnis das generierte Kling-Video abrufen.

Wenn Sie außerdem den entsprechenden Integrationscode generieren möchten, können Sie ihn direkt kopieren, zum Beispiel lautet der CURL-Code wie folgt:

```shell
curl -X POST 'https://api.acedata.cloud/kling/motion' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
  "video_url": "https://cdn.acedata.cloud/odwfm5.mp4",
  "prompt": "让画面生动起来",
  "mode": "std",
  "character_orientation": "image"
}'
```

## Asynchroner Rückruf

Da die Generierung durch die Kling Motion Generation API relativ lange dauert, etwa 1–2 Minuten, bleibt die HTTP-Anfrage bei einer längeren Nichtreaktion der API dauerhaft verbunden, was zu zusätzlichem Verbrauch von Systemressourcen führt. Daher bietet diese API auch Unterstützung für asynchrone Rückrufe.

Der gesamte Ablauf ist: Wenn der Client eine Anfrage initiiert, wird zusätzlich ein Feld `callback_url` angegeben. Nachdem der Client eine API-Anfrage initiiert hat, gibt die API sofort ein Ergebnis zurück, das ein Feld `task_id` enthält und die aktuelle Aufgaben-ID darstellt. Nachdem die Aufgabe abgeschlossen ist, wird das Ergebnis des generierten Videos in Form von POST JSON an die vom Client angegebene `callback_url` gesendet, wobei auch das Feld `task_id` enthalten ist. Dadurch kann das Aufgabenergebnis über die ID verknüpft werden.

Im Folgenden erfahren wir anhand eines Beispiels, wie der konkrete Vorgang funktioniert.

Zunächst einmal ist der Webhook-Rückruf ein Dienst, der HTTP-Anfragen empfangen kann. Entwickler sollten ihn durch die URL eines selbst aufgebauten HTTP-Servers ersetzen. Zur bequemen Demonstration wird hier eine öffentliche Webhook-Beispielwebsite https://webhook.site/ verwendet. Beim Öffnen dieser Website erhalten Sie eine Webhook-URL, wie in der Abbildung gezeigt:

![](https://cdn.acedata.cloud/tbcnai.png)

Kopieren Sie diese URL, dann kann sie als Webhook verwendet werden. Das Beispiel hier lautet `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Als Nächstes können wir das Feld `callback_url` auf die obige Webhook-URL setzen und gleichzeitig die entsprechenden Parameter eingeben. Die konkreten Inhalte sind wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Klicken Sie auf Ausführen, und Sie werden feststellen, dass sofort ein Ergebnis erhalten wird, wie folgt:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Warten Sie einen Moment, dann können wir unter `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3` das Ergebnis des generierten Videos beobachten, wie in der Abbildung gezeigt:

![](https://cdn.acedata.cloud/zv5u2q.png)

Der Inhalt lautet wie folgt:
```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Man kann sehen, dass es in den Ergebnissen ein Feld `task_id` gibt. Die anderen Felder sind dem obigen ähnlich, und über dieses Feld kann die Verknüpfung von Aufgaben realisiert werden.

## Fehlerbehandlung

Wenn beim Aufruf der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechenden Informationen zurück. Zum Beispiel:

- `400 token_mismatched`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`：Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`：Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`：Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
