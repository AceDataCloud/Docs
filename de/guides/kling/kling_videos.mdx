In diesem Artikel wird eine Anleitung zur Integration der Kling Videos Generation API vorgestellt, mit der durch die Eingabe benutzerdefinierter Parameter offizielle Kling-Videos generiert werden können.

## Antragsprozess

Um die Kling Videos Generation API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihr API-Token zu erhalten, und bewahren Sie es als Reserve auf.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zu dieser Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen; es ist nicht erforderlich, für jeden Dienst separat einen Antrag zu stellen.** Bei der ersten Beantragung wird ein kostenloses Kontingent vergeben, das kostenlos ausprobiert werden kann; wenn das Kontingent nicht ausreicht, kann in der [Konsole](https://platform.acedata.cloud/console/coin) allgemeines Guthaben aufgeladen werden.

> 📘 Vollständige Dokumentation: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Grundlegende Verwendung

Lernen wir zunächst die grundlegende Verwendung kennen: Durch die Eingabe des Prompt-Worts `prompt`, der Generierungsaktion `action`, des Referenzbilds für das erste Frame `start_image_url` sowie des Modells `model` können Sie das verarbeitete Ergebnis erhalten. Zunächst muss einfach ein Feld `action` übergeben werden, dessen Wert `text2video` lautet. Es umfasst hauptsächlich drei Aktionen: Text-zu-Video (`text2video`), Bild-zu-Video (`image2video`) und Video erweitern (`extend`). Anschließend müssen wir auch das Modell `model` eingeben. Derzeit gibt es hauptsächlich die Modelle `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`; die konkreten Inhalte sind wie folgt:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Hier ist zu sehen, dass wir Request Headers festgelegt haben, einschließlich:

- `accept`: Welches Format des Antwortergebnisses empfangen werden soll; hier wird `application/json` angegeben, also das JSON-Format.
- `authorization`: Der Schlüssel zum Aufrufen der API, der nach der Beantragung direkt über ein Dropdown ausgewählt werden kann.

Zusätzlich wurde der Request Body festgelegt, einschließlich:

- `model`: Das Modell zur Videogenerierung; es gibt hauptsächlich die Modelle `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode`: Der Modus zur Videogenerierung; mögliche Werte sind der Standardmodus `std`, der Schnellmodus `pro` und der native 4K-Modus `4k`. Dabei wird `4k` nur von `kling-v3` und `kling-v3-omni` unterstützt und ist nicht mit `camera_control` (Kamerabewegungssteuerung) kompatibel.
- `action`: Die Aktion dieser Videogenerierungsaufgabe, die hauptsächlich drei Aktionen umfasst: Text-zu-Video (`text2video`), Bild-zu-Video (`image2video`) und Video erweitern (`extend`).
- `start_image_url`: Der Link zum Referenzbild für das erste Frame, das beim Auswählen der Bild-zu-Video-Aktion `image2video` hochgeladen werden muss.
- `end_image_url`: Bei Bild-zu-Video optional, um das letzte Frame festzulegen.
- `duration`: Videodauer in Sekunden. `kling-v3` und `kling-v3-omni` unterstützen ganzzahlige Dauern von 3–15 Sekunden; `kling-o1` unterstützt nur 5 Sekunden; andere Modelle unterstützen 5 oder 10 Sekunden.
- `generate_audio`: Ob gleichzeitig Audio generiert werden soll, optionaler boolescher Wert. Unterstützt `kling-v3`, `kling-v3-omni` sowie `kling-v2-6` (nur im Pro-Modus). Standardmäßig `false`.
- `aspect_ratio`: Seitenverhältnis des Videos, optional; unterstützt `16:9`, `9:16`, `1:1`, Standard ist `16:9`.
- `cfg_scale`: Korrelationsstärke, Bereich [0,1]; je größer, desto besser entspricht es dem Prompt-Wort.
- `camera_control`: Optionaler Objektparameter zur Steuerung der Kamerabewegung; unterstützt type/simple-Voreinstellungen sowie Konfigurationen wie horizontal, vertical, pan, tilt, roll, zoom usw.
- `negative_prompt`: Optionales negatives Prompt-Wort für Inhalte, die nicht erscheinen sollen, maximal 200 Zeichen.
- `image_list`: Omni-Referenzbildliste, geeignet für die Modelle `kling-o1` und `kling-v3-omni`; zur Verwendung siehe unten „Omni-Allzweckreferenz“.
- `video_list`: Omni-Referenzvideoliste (unterstützt Videobearbeitung), geeignet für die Modelle `kling-o1` und `kling-v3-omni`; zur Verwendung siehe unten „Omni-Allzweckreferenz“.
- `prompt`: Prompt-Wort.
- `callback_url`: Die URL, an die das Ergebnis zurückgemeldet werden soll.
- `async`: Optional; wenn auf `true` gesetzt, gibt die Schnittstelle sofort `task_id` zurück, ohne dass `callback_url` angegeben werden muss; anschließend wird das Ergebnis durch Polling über die entsprechende Aufgabenabfrageschnittstelle abgerufen.

Nach der Auswahl können Sie feststellen, dass auch auf der rechten Seite entsprechender Code generiert wurde, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Klicken Sie auf die Schaltfläche „Try“, um einen Test durchzuführen. Wie in der obigen Abbildung gezeigt, erhalten wir hier das folgende Ergebnis:

```json
{
  "success": true,
  "video_id": "900798310464749610",
  "video_url": "https://cdn.acedata.cloud/assets/examples/kling/6c68c267-065b-4423-b66b-a0e4c59ee0d5-6a664a591a53.mp4",
  "duration": "5.041",
  "state": "succeed",
  "task_id": "6c68c267-065b-4423-b66b-a0e4c59ee0d5"
}
```

Das Rückgabeergebnis enthält mehrere Felder, die wie folgt vorgestellt werden:

- `success`: Der Status der aktuellen Videogenerierungsaufgabe.
- `task_id`: Die ID der aktuellen Videogenerierungsaufgabe.
- `video_id`: Die Video-ID der aktuellen Videogenerierungsaufgabe.
- `video_url`: Der Videolink der aktuellen Videogenerierungsaufgabe.
- `duration`: Die Dauer des Videolinks der aktuellen Videogenerierungsaufgabe.
- `state`: Der Status der aktuellen Videogenerierungsaufgabe.

Es ist zu sehen, dass wir zufriedenstellende Videoinformationen erhalten haben. Wir müssen nur die generierten Kling-Videos über die Videolink-Adresse von `data` im Ergebnis abrufen.

Wenn Sie außerdem entsprechenden Integrationscode generieren möchten, können Sie ihn direkt kopieren; beispielsweise lautet der CURL-Code wie folgt:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Modellfähigkeitsmatrix

Die Unterstützung von Parametern unterscheidet sich je nach Modell erheblich. Die folgende Matrix wurde aus der offiziellen [Kling-Dokumentation zu Video-Modellen](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels) zusammengestellt. Bitte prüfen Sie vor dem Aufruf zunächst, ob die aktuelle Kombination aus `model` / `mode` / `duration` die von Ihnen benötigte Funktion unterstützt, da andernfalls Fehler wie `model/mode/duration(...) is not supported with image_tail` zurückgegeben werden.
| Modell              | Modus          | `end_image_url`（Anfangs- und Endbild） | `generate_audio`（Begleitton） | `camera_control`（Kamerafahrt） | Anmerkungen                                      |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ Nur `duration=5`     | ❌                    | ✅ Nur `duration=5`     | `extend` unterstützt `negative_prompt` und `cfg_scale` nicht |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | Bild-zu-Video mit mehreren Bildern, `extend` in allen Modi verfügbar                         |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Einzelner Modus, nur `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Einzelner Modus, nur `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | Einziges Nicht-v3-Modell, das gleichzeitig Begleitton unterstützt                             |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | `duration`-Bereich 3–15 Sekunden                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | Der 4K-Modus ist nicht mit Kamerafahrten kompatibel                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Unterstützt nur `duration=5`                             |

Hinweise:

- `mode=4k` wird nur von `kling-v3` und `kling-v3-omni` unterstützt; außerdem ist es mit `camera_control`（Kamerafahrt）nicht kombinierbar.
- `end_image_url` kann nur bei `action=image2video` zusammen mit `start_image_url` verwendet werden. Die alleinige Übergabe von `end_image_url`（ohne `start_image_url`）wird abgelehnt.
- `kling-v3` / `kling-v3-omni` akzeptieren jede ganzzahlige `duration` von 3–15 Sekunden; `kling-o1` akzeptiert nur 5; die übrigen Modelle akzeptieren nur 5 oder 10.
- `generate_audio` ist standardmäßig `false`. Nur `kling-v3`, `kling-v3-omni` und `kling-v2-6`（Pro-Modus）werden unterstützt.

## Funktion zum Erweitern von Videos

Wenn Sie ein bereits generiertes Kling-Video weitergenerieren möchten, können Sie den Parameter `action` auf `extend` setzen und die ID des Videos eingeben, das weitergeneriert werden soll. Die Video-ID erhalten Sie über die grundlegende Verwendung, wie in der folgenden Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Hier können Sie sehen, dass die ID des Videos lautet:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Hinweis: Die `video_id` im Video hier ist die ID des generierten Videos. Wenn Sie nicht wissen, wie man ein Video generiert, können Sie sich auf die oben beschriebene grundlegende Verwendung beziehen, um ein Video zu generieren.

Als Nächstes müssen wir unbedingt den Prompt eingeben, der im nächsten Schritt erweitert werden soll, um das generierte Video anzupassen. Dann können Sie die folgenden Inhalte festlegen:

- `model`：Das Modell zum Generieren von Videos, hauptsächlich die Modelle `kling-v1`、`kling-v1-5` und `kling-v1-6`.
- `mode`：Der Modus zum Generieren von Videos; die optionalen Werte sind Standardmodus `std`, Schnellmodus `pro` und nativer 4K-Modus `4k`（nur von `kling-v3` und `kling-v3-omni` unterstützt und nicht mit der Steuerung von Kamerafahrten kompatibel）.
- `duration`：Die Videolänge dieser Video-Generierungsaufgabe, hauptsächlich 5 s und 10 s.
- `start_image_url`：Wenn das Bild-zu-Video-Verhalten `image2video` ausgewählt wird, ist der Link zum hochzuladenden Referenzbild des ersten Frames erforderlich.
- `prompt`：Prompt.

Ein Ausfüllbeispiel ist wie folgt:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Nach dem Ausfüllen wird automatisch der folgende Code generiert:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Klicken Sie auf Ausführen, dann können Sie feststellen, dass Sie ein Ergebnis wie folgt erhalten:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```

Wie zu sehen ist, stimmt der Ergebnisinhalt mit dem oben beschriebenen überein, wodurch die Funktion zum Erweitern von Videos realisiert wird.

## Omni-Allzweckreferenz（Videobearbeitung / Referenzvideo / Mehrbildreferenz）

`kling-o1` und `kling-v3-omni` sind zwei unabhängige Modelle, die beide die Fähigkeit zur „Allzweckreferenz“ unterstützen. Auf Grundlage von Text-zu-Video（`action=text2video`）können zusätzlich Referenzbilder oder Referenzvideos übergeben werden, um **Mehrbildreferenzen, Referenzvideos sowie die direkte Bearbeitung bestehender Videos** zu ermöglichen.

**Kernvereinbarung**：Referenzmaterial muss im `prompt` in der Form `&lt;&lt;<image_1>>>`、`&lt;&lt;<video_1>>>`（die Nummerierung beginnt bei 1）auf das Material an der entsprechenden Position in `image_list` / `video_list` verweisen, damit das Modell diese Referenzen anwendet. Wenn nur Material übergeben wird, ohne im Prompt darauf zu verweisen, wird das Material ignoriert.

> Sicherheitshinweis: Die aktuelle API stellt `element_list` nicht bereit. Die IDs der Kling Element Library sind nicht mandantenisoliert. Bevor eine mandantenisolierte Element-Management-API bereitgestellt wird, verwenden Sie bitte `image_list`, um Referenzbilder des Hauptobjekts zu übergeben.

Omni-Anfragen unterstützen weder `negative_prompt`, `cfg_scale` noch `camera_control` und können auch nicht `mode=4k` verwenden. Wenn ein Referenzvideo enthalten ist, muss `generate_audio` auf `false` gesetzt werden.

### Referenzvideo und Videobearbeitung（`video_list`）
`video_list` wird zum Übergeben von Referenzvideos verwendet und ist das häufigste Szenario dieser Funktion. Die Felder der Array-Elemente sind wie folgt:

- `video_url`: Link zum Referenzvideo, darf nicht leer sein. Maximal 1 MP4/MOV-Video, Dateigröße ≤200MB, Bildrate 24–60fps. `kling-o1` erfordert eine Dauer von 3–10 Sekunden sowie Breite und Höhe jeweils von 700–2160px; `kling-v3-omni` erfordert eine Dauer von 3–15,5 Sekunden, Breite und Höhe jeweils von 700–4553px, Gesamtpixel ≤8.294.400 und ein Seitenverhältnis von 0,4–2.
- `refer_type`: Referenztyp, optional `base` (Standard, **zu bearbeitendes Basisvideo**, d. h. „das Video direkt bearbeiten“, Elemente können hinzugefügt/gelöscht/geändert, die Komposition, der Stil, die Farben, das Wetter usw. geändert werden) oder `feature` (**Merkmalsreferenz**, referenziert dessen Stil / Kameraführung / Fortsetzung der nächsten Einstellung).
- `keep_original_sound`: Ob die Audioaufnahme des Originalvideos beibehalten werden soll, optional `yes` (beibehalten) oder `no` (entfernen).

> Hinweis: Wenn ein Referenzvideo vorhanden ist, muss `generate_audio` auf `false` gesetzt sein. Für ein Video mit `refer_type=base` dürfen keine Startbilder / Endbilder mehr angegeben werden.

Das CURL-Beispiel für die Bearbeitung eines vorhandenen Videos (Änderung des Videos in einen Anime-Stil) lautet wie folgt:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Mehrbildreferenz (`image_list`)

`image_list` wird zum Übergeben von Referenzbildern verwendet (Elemente / Szenen / Stile usw.). Die Felder der Array-Elemente sind wie folgt:

- `image_url`: Link zum Referenzbild, darf nicht leer sein. Anforderungen: Format .jpg/.jpeg/.png; Dateigröße ≤10MB; kürzeste Seite ≥300px; Seitenverhältnis 1:2,5 ~ 2,5:1.
- `type`: Optional. Wenn nicht übergeben, wird es als reines Referenzbild verwendet; bei Übergabe von `first_frame` / `end_frame` wird es jeweils als Startbild / Endbild verwendet (entspricht `start_image_url` / `end_image_url`).

Bei der Verwendung muss im `prompt` mit `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>` darauf verwiesen werden. Mengenbeschränkung: Ohne Referenzvideo sind Referenzbilder ≤ 7; mit Referenzvideo sind Referenzbilder ≤ 4. Wenn nur das Startbild / Endbild übergeben wird, können auch direkt `start_image_url` / `end_image_url` verwendet werden, das Endbild muss jedoch zusammen mit dem Startbild verwendet werden.

> Hinweis: Wenn gleichzeitig `start_image_url` / `end_image_url` und `image_list` übergeben werden, werden die Startbilder / Endbilder vor `image_list` eingeordnet, was möglicherweise die Zuordnung der Nummerierung von `&lt;&lt;<image_N>>>` beeinflusst. Es wird empfohlen, eine der beiden Optionen zu wählen: Wenn Startbilder / Endbilder benötigt werden, geben Sie den `type` direkt in `image_list` an und verwenden Sie ihn nicht zusammen mit `start_image_url` / `end_image_url`.

CURL-Beispiel für die Videogenerierung mit Mehrbildreferenz:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Asynchroner Callback

Da die Generierungszeit der Kling Videos Generation API relativ lang ist und etwa 1–2 Minuten beträgt, bleibt die HTTP-Anfrage bei einer längeren Nichtantwort der API dauerhaft verbunden, was zu zusätzlichem Verbrauch von Systemressourcen führt. Daher bietet diese API auch Unterstützung für asynchrone Callbacks.

Der gesamte Ablauf ist wie folgt: Wenn der Client eine Anfrage initiiert, gibt er zusätzlich ein Feld `callback_url` an. Nachdem der Client die API-Anfrage initiiert hat, gibt die API sofort ein Ergebnis zurück, das ein Feld `task_id` enthält, welches die aktuelle Aufgaben-ID darstellt. Nachdem die Aufgabe abgeschlossen ist, wird das Ergebnis des generierten Videos als POST JSON an die vom Client angegebene `callback_url` gesendet, die ebenfalls das Feld `task_id` enthält, sodass die Aufgabenergebnisse über die ID verknüpft werden können.

Im Folgenden erfahren wir anhand eines Beispiels, wie dies konkret funktioniert.

Zunächst ist der Webhook-Callback ein Dienst, der HTTP-Anfragen empfangen kann. Entwickler sollten ihn durch die URL ihres selbst eingerichteten HTTP-Servers ersetzen. Zur bequemen Demonstration wird hier eine öffentliche Webhook-Beispielwebsite https://webhook.site/ verwendet. Beim Öffnen dieser Website erhalten Sie eine Webhook-URL, wie in der Abbildung gezeigt:

![](https://cdn.acedata.cloud/tbcnai.png)

Kopieren Sie diese URL, dann kann sie als Webhook verwendet werden. Das Beispiel hier lautet `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Als Nächstes können wir das Feld `callback_url` auf die oben genannte Webhook-URL setzen und gleichzeitig die entsprechenden Parameter ausfüllen. Der konkrete Inhalt ist in der Abbildung dargestellt:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Klicken Sie auf Ausführen, und Sie werden feststellen, dass sofort ein Ergebnis zurückgegeben wird, wie folgt:

```

  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Warten Sie einen Moment, dann können wir unter `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3` das Ergebnis des generierten Videos beobachten, wie in der Abbildung gezeigt:

![](https://cdn.acedata.cloud/zv5u2q.png)

Wie zu sehen ist, enthält das Ergebnis ein Feld `task_id`. Die anderen Felder sind ähnlich wie oben. Über dieses Feld kann die Verknüpfung der Aufgaben realisiert werden.

## Fehlerbehandlung

Wenn bei der API-Nutzung ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Meldung zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist ein Fehler aufgetreten.
### Beispiel für eine Fehlerantwort

