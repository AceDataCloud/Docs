Dieser Artikel stellt eine Anleitung zur Integration der Kling Videos Generation API vor, mit der Sie offizielle Kling-Videos durch Eingabe benutzerdefinierter Parameter generieren können.

## Antragsverfahren

Um die API zu nutzen, müssen Sie zunächst auf der entsprechenden Seite [Kling Videos Generation API](https://platform.acedata.cloud/documents/3b921a16-a411-4557-8335-53f21d3f9e46) den Dienst beantragen. Nach dem Aufruf der Seite klicken Sie auf die Schaltfläche „Acquire“, wie im Bild gezeigt:

![](https://cdn.acedata.cloud/q6ytrc.png)

Wenn Sie noch nicht eingeloggt oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach der Anmeldung kehren Sie automatisch zur aktuellen Seite zurück.

Beim ersten Antrag erhalten Sie ein kostenloses Kontingent, mit dem Sie die API kostenlos nutzen können.

## Grundlegende Nutzung

Zunächst lernen wir die grundlegende Nutzung kennen: Durch Eingabe des Prompt `prompt`, der Aktion `action`, der Startbild-Referenz `start_image_url` sowie des Modells `model` erhalten Sie das verarbeitete Ergebnis. Zunächst muss ein Feld `action` mit dem Wert `text2video` übergeben werden. Dieses Feld umfasst drei Hauptaktionen: Text-zu-Video (`text2video`), Bild-zu-Video (`image2video`) und Videoerweiterung (`extend`). Außerdem müssen wir das Modell `model` angeben. Derzeit stehen hauptsächlich die Modelle `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni` und `kling-video-o1` zur Verfügung. Details siehe unten:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Hier sehen wir, dass wir die Request-Header setzen, darunter:

- `accept`: Gibt an, in welchem Format die Antwort erwartet wird. Hier `application/json` für JSON-Format.
- `authorization`: Der API-Schlüssel für den Aufruf, der nach Antrag direkt ausgewählt werden kann.

Außerdem wird der Request-Body gesetzt mit:

- `model`: Das Modell zur Videoerstellung, hauptsächlich `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni` und `kling-video-o1`.
- `mode`: Der Modus der Videoerstellung, wählbar zwischen Standardmodus `std`, Schnellmodus `pro` und nativer 4K-Modus `4k`. Der `4k`-Modus wird nur von `kling-v3` und `kling-v3-omni` unterstützt und ist nicht kompatibel mit `camera_control` (Kamerasteuerung).
- `action`: Die Aktion der Videoerstellung, umfasst die drei Hauptaktionen Text-zu-Video (`text2video`), Bild-zu-Video (`image2video`) und Videoerweiterung (`extend`).
- `start_image_url`: Bei Auswahl der Aktion Bild-zu-Video (`image2video`) ist ein Link zum Startbild erforderlich.
- `end_image_url`: Optional bei Bild-zu-Video, definiert das Endbild.
- `duration`: Videolänge in Sekunden. Für die Modelle `kling-v3` und `kling-v3-omni` sind flexible Längen von 3-15 Sekunden (ganzzahlig) möglich, andere Modelle unterstützen 5 oder 10 Sekunden.
- `generate_audio`: Optional, ob gleichzeitig Audio generiert werden soll, boolescher Wert. Unterstützt von `kling-v3`, `kling-v3-omni` und `kling-v2-6` (nur im pro-Modus). Standard ist `false`.
- `aspect_ratio`: Seitenverhältnis des Videos, optional, unterstützt `16:9`, `9:16` und `1:1`, Standard ist `16:9`.
- `cfg_scale`: Stärke der Relevanz, Bereich [0,1], je größer desto stärker an den Prompt angepasst.
- `camera_control`: Optional, Parameter zur Steuerung der Kamerabewegung, unterstützt Typ/Simple-Voreinstellungen sowie Konfigurationen wie horizontal, vertical, pan, tilt, roll, zoom.
- `negative_prompt`: Optional, unerwünschte negative Stichwörter, maximal 200 Zeichen.
- `element_list`: Hauptreferenzliste, nur für Modell `kling-video-o1` anwendbar, Details siehe [offizielle Dokumentation](https://docs.qingque.cn/d/home/eZQAyImcbaS0fz-8ANjXvU5ed?identityId=1oEG9JKKMFv#section=h.5t7wme23nn6z).
- `video_list`: Referenzvideos per URL, nur für Modell `kling-video-o1` anwendbar, Details siehe [offizielle Dokumentation](https://docs.qingque.cn/d/home/eZQAyImcbaS0fz-8ANjXvU5ed?identityId=1oEG9JKKMFv#section=h.5t7wme23nn6z).
- `prompt`: Der Eingabe-Prompt.
- `callback_url`: URL für Rückruf der Ergebnisse.

Nach Auswahl wird auf der rechten Seite der entsprechende Code generiert, wie im Bild gezeigt:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Mit Klick auf „Try“ kann der Test durchgeführt werden. Im Beispiel erhalten wir folgendes Ergebnis:

```json
{
  "success": true,
  "video_id": "af9a1af0-9aa0-4638-81c1-d41d6143c508",

  "state": "succeed",
  "task_id": "e3a575aa-a4bd-49c8-9b12-cde38d5462e0"

```

Die Antwort enthält mehrere Felder, die wie folgt erklärt werden:

- `success`: Status der Videoerstellung.
- `task_id`: ID der Videoerstellungsaufgabe.
- `video_id`: Video-ID der erstellten Aufgabe.
- `video_url`: Link zum erstellten Video.
- `duration`: Videolänge.
- `state`: Status der Videoerstellung.

Sie sehen, dass wir die gewünschten Video-Informationen erhalten haben. Sie können das generierte Kling-Video über den Link im Feld `data` abrufen.

Wenn Sie den entsprechenden Integrationscode generieren möchten, können Sie diesen direkt kopieren. Beispiel CURL-Code:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v1",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Videoerweiterungsfunktion

Wenn Sie ein bereits generiertes Kling-Video weiter generieren möchten, setzen Sie den Parameter `action` auf `extend` und geben die Video-ID des zu erweiternden Videos ein. Die Video-ID erhalten Sie gemäß der grundlegenden Nutzung, wie im Bild gezeigt:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Die Video-ID lautet hier:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Hinweis: Die Video-ID `video_id` ist die ID des generierten Videos. Falls Sie nicht wissen, wie man ein Video generiert, siehe die grundlegende Nutzung oben.

Anschließend müssen Sie den Prompt für die Erweiterung eingeben, um das Video individuell weiter zu generieren. Folgende Parameter sind möglich:

- `model`: Modell zur Videoerstellung, hauptsächlich `kling-v1`, `kling-v1-5` und `kling-v1-6`.
- `mode`: Modus der Videoerstellung, wählbar zwischen Standardmodus `std`, Schnellmodus `pro` und nativer 4K-Modus `4k` (nur `kling-v3` und `kling-v3-omni` unterstützt, nicht kompatibel mit Kamerasteuerung).
- `duration`: Videolänge der Aufgabe, hauptsächlich 5s oder 10s.
- `start_image_url`: Bei Bild-zu-Video (`image2video`) erforderlich, Link zum Startbild.
- `prompt`: Eingabe-Prompt.

Beispielhafte Eingabe:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Nach Eingabe wird automatisch folgender Code generiert:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Python-Beispielcode:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Nach Ausführung erhalten Sie ein Ergebnis wie folgt:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7822108635/extendVideo/Cjil4mfBfs0AAAAAAKhr6A-0_raw_video_1.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```

Das Ergebnis entspricht dem oben beschriebenen, womit die Videoerweiterungsfunktion realisiert wird.

## Asynchrone Callback-Funktion

Da die Erstellung von Videos mit der Kling Videos Generation API relativ lange dauert (ca. 1-2 Minuten), kann bei langem Warten auf eine Antwort die HTTP-Verbindung offen bleiben, was zu zusätzlichem Ressourcenverbrauch führt. Daher unterstützt die API auch asynchrone Callbacks.

Der Ablauf ist folgender: Der Client gibt bei der Anfrage zusätzlich ein Feld `callback_url` an. Nach dem API-Aufruf gibt die API sofort eine Antwort mit einem `task_id` zurück, das die aktuelle Aufgabe identifiziert. Nach Abschluss der Aufgabe wird das Ergebnis per POST-JSON an die angegebene `callback_url` gesendet, inklusive des `task_id`, sodass die Aufgabe zugeordnet werden kann.

Im Folgenden ein Beispiel zur Veranschaulichung.

Zunächst ist der Webhook-Callback ein HTTP-Service, der HTTP-Anfragen empfangen kann. Entwickler sollten die URL ihres eigenen HTTP-Servers verwenden. Zur Demonstration wird hier die öffentliche Webhook-Beispielseite https://webhook.site/ verwendet. Nach Aufruf der Seite erhalten Sie eine Webhook-URL, wie im Bild gezeigt:

![](https://cdn.acedata.cloud/tbcnai.png)

Diese URL kopieren Sie und verwenden sie als Webhook. Beispiel: `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Anschließend setzen wir das Feld `callback_url` auf die obige Webhook-URL und füllen die übrigen Parameter aus, wie im Bild gezeigt:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Nach Klick auf Ausführen erhalten wir sofort eine Antwort:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Nach kurzer Wartezeit sehen wir auf `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3` das Ergebnis der Videoerstellung, wie im Bild gezeigt:

![](https://cdn.acedata.cloud/zv5u2q.png)

Inhalt:

```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7822108635/text2video/CjJzzGfBfqcAAAAAAKdVMQ-0_raw_video_1.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Man sieht, dass das Ergebnis ein Feld `task_id` enthält, die anderen Felder sind ähnlich wie oben. Über dieses Feld kann die Aufgabe zugeordnet werden.

## Fehlerbehandlung

Bei API-Aufrufen gibt die API bei Fehlern entsprechende Fehlercodes und Meldungen zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise fehlende oder ungültige Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise fehlende oder ungültige Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiger oder fehlender Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Limit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel einer Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
