Dieser Artikel stellt eine Anleitung zur Integration der Kling Videos Generation API vor, mit der durch die Eingabe benutzerdefinierter Parameter offizielle Videos von Kling generiert werden können.

## Antragsprozess

Um die Kling Videos Generation API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten und ihn als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, wo Sie zur Registrierung und Anmeldung eingeladen werden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Beim ersten Antrag wird ein kostenloses Guthaben verschenkt, das kostenlos ausprobiert werden kann; bei unzureichendem Guthaben können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Grundlegende Verwendung

Zunächst lernen wir die grundlegende Verwendung kennen: Durch die Eingabe des Prompt-Worts `prompt`, der Generierungsaktion `action`, des Referenzbilds des ersten Frames `start_image_url` sowie des Modells `model` können die verarbeiteten Ergebnisse erhalten werden. Zunächst muss einfach ein Feld `action` übergeben werden, dessen Wert `text2video` ist. Es umfasst hauptsächlich drei Aktionen: Text-zu-Video (`text2video`), Bild-zu-Video (`image2video`) und Video-Erweiterung (`extend`). Anschließend müssen wir auch das Modell `model` eingeben. Derzeit gibt es hauptsächlich die Modelle `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`. Die konkreten Inhalte sind wie folgt:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Hier sehen wir, dass wir die Request Headers festgelegt haben, einschließlich:

- `accept`: Welches Format der Antwortergebnisse empfangen werden soll; hier wird `application/json`, also das JSON-Format, eingetragen.
- `authorization`: Der Schlüssel zum Aufrufen der API, der nach der Beantragung direkt über ein Dropdown ausgewählt werden kann.

Zusätzlich wurde der Request Body festgelegt, einschließlich:

- `model`: Das Modell zur Videogenerierung, hauptsächlich die Modelle `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode`: Der Modus zur Videogenerierung. Die optionalen Werte sind der Standardmodus `std`, der Schnellmodus `pro` und der native 4K-Modus `4k`. Dabei unterstützt `4k` nur `kling-v3` und `kling-v3-omni` und ist nicht mit `camera_control` (Kamerabewegungssteuerung) kompatibel.
- `action`: Die Aktion dieser Videogenerierungsaufgabe, die hauptsächlich drei Aktionen umfasst: Text-zu-Video (`text2video`), Bild-zu-Video (`image2video`) und Video-Erweiterung (`extend`).
- `start_image_url`: Der Link zum hochzuladenden Referenzbild des ersten Frames, der erforderlich ist, wenn die Bild-zu-Video-Aktion `image2video` ausgewählt wird.
- `end_image_url`: Optional bei Bild-zu-Video, legt den Endframe fest.
- `duration`: Videolänge in Sekunden. `kling-v3` und `kling-v3-omni` unterstützen ganzzahlige Längen von 3–15 Sekunden; `kling-o1` unterstützt nur 5 Sekunden; andere Modelle unterstützen 5 oder 10 Sekunden.
- `generate_audio`: Ob gleichzeitig Audio generiert werden soll, optionaler boolescher Wert. Unterstützt `kling-v3`, `kling-v3-omni` sowie `kling-v2-6` (nur im pro-Modus). Standardmäßig `false`.
- `aspect_ratio`: Seitenverhältnis des Videos, optional, unterstützt `16:9`, `9:16`, `1:1`, Standardwert ist `16:9`.
- `cfg_scale`: Korrelationsstärke, Bereich [0,1]; je größer der Wert, desto stärker entspricht es dem Prompt-Wort.
- `camera_control`: Optionaler Objektparameter zur Steuerung der Kamerabewegung, unterstützt type/simple-Voreinstellungen sowie Konfigurationen wie horizontal, vertical, pan, tilt, roll, zoom usw.
- `negative_prompt`: Optionales negatives Prompt-Wort für unerwünschte Inhalte, maximal 200 Zeichen.
- `image_list`: Omni-Referenzbildliste, anwendbar auf die Modelle `kling-o1` und `kling-v3-omni`; die Verwendung siehe unten unter „Omni-Allzweckreferenz“.
- `video_list`: Omni-Referenzvideoliste (unterstützt Videobearbeitung), anwendbar auf die Modelle `kling-o1` und `kling-v3-omni`; die Verwendung siehe unten unter „Omni-Allzweckreferenz“.
- `prompt`: Prompt-Wort.
- `callback_url`: URL, die die Ergebnisse zurückrufen muss.
- `async`: Optional. Wenn auf `true` gesetzt, gibt die Schnittstelle sofort `task_id` zurück, ohne dass `callback_url` bereitgestellt werden muss; anschließend werden die Ergebnisse durch Abfrage der entsprechenden Aufgabenschnittstelle per Polling abgerufen.

Nach der Auswahl können Sie feststellen, dass auf der rechten Seite ebenfalls der entsprechende Code generiert wurde, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Klicken Sie auf die Schaltfläche „Try“, um einen Test durchzuführen. Wie in der obigen Abbildung gezeigt, erhalten wir hier folgendes Ergebnis:

```json
{
  "success": true,
  "video_id": "900798310464749610",
  "video_url": "https://cdn.acedata.cloud/assets/examples/kling/6c68c267-065b-4423-b66b-a0e4c59ee0d5-6a664a591a53.mp4",
  "duration": "5.041",
  "state": "succeed",
  "task_id": "6c68c267-065b-4423-b66b-a0e4c59ee0d5"
}
```

Das zurückgegebene Ergebnis hat insgesamt mehrere Felder, die wie folgt vorgestellt werden:

- `success`, der Status der aktuellen Videogenerierungsaufgabe.
- `task_id`, die ID der aktuellen Videogenerierungsaufgabe.
- `video_id`, die Video-ID der aktuellen Videogenerierungsaufgabe.
- `video_url`, der Videolink der aktuellen Videogenerierungsaufgabe.
- `duration`, die Videolänge des Videolinks der aktuellen Videogenerierungsaufgabe.
- `state`, der Status der aktuellen Videogenerierungsaufgabe.

Wir sehen, dass wir zufriedenstellende Videoinformationen erhalten haben. Wir müssen lediglich die generierten Kling-Videos über die Videolinkadresse von `data` im Ergebnis abrufen.

Wenn Sie außerdem entsprechenden Integrationscode generieren möchten, können Sie ihn direkt kopieren. Der Code für CURL lautet beispielsweise wie folgt:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Modellfähigkeitsmatrix

### Abrechnung für O1 und Omni-Referenzvideos

`kling-o1` wird nach Modus und danach abgerechnet, ob `video_list` bereitgestellt wird. Nachfolgend sind die Preise für ein 5-sekündiges fertiges Video aufgeführt:

| Modus  | Ohne Referenzvideo | Mit Referenzvideo |
| --- | ------------: | ------------: |
| std | 4.005 Credits | 6.010 Credits |
| pro | 5.340 Credits | 8.010 Credits |
Erfolgreiche Anfragen mit Referenzvideo für `kling-o1` und `kling-v3-omni` werden nach den abgerechneten Sekunden berechnet: std kostet **1.202 Credits/Sekunde**, pro kostet **1.602 Credits/Sekunde**. Beispielsweise kostet die Generierung von 5 Sekunden im std-Modus 6.010 Credits. Das Weglassen von `video_list` löst keine Referenzvideo-Stufe aus; `image_list`, das Startbild und das Endbild gehören ebenfalls nicht zu Referenzvideos. Referenzvideos können nicht gleichzeitig mit `generate_audio=true` verwendet werden.

Bei der Videobearbeitung mit `refer_type=base` (Standard) kann die Länge des Referenzvideos übernommen werden; final wird nach der tatsächlichen fertigen Videolänge auf ganze Sekunden gerundet abgerechnet: Beispielsweise werden 5.708 Sekunden als 6 Sekunden und 5.041 Sekunden als 5 Sekunden berechnet. `refer_type=feature` verwendet das angeforderte `duration`. `usage.reference_video_seconds` in der Antwort gibt die final abgerechneten Sekunden an; der geschätzte Preis bei der Anfrage kann von der finalen Abbuchung abweichen.

Die Unterstützung von Parametern unterscheidet sich je nach Modell erheblich. Die folgende Matrix wurde aus der offiziellen [Kling-Dokumentation zu Video Models](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels) zusammengestellt. Prüfen Sie vor dem Aufruf, ob die aktuelle Kombination aus `model` / `mode` / `duration` die benötigte Funktion unterstützt, da andernfalls Fehler wie `model/mode/duration(...) is not supported with image_tail` zurückgegeben werden.

| Modell              | Modus          | `end_image_url` (Start- und Endbild) | `generate_audio` (Ton) | `camera_control` (Kamerafahrt) | Anmerkungen                                      |
| ------------------- | -------------- | ------------------------------------ | ---------------------- | ------------------------------ | ------------------------------------------------ |
| `kling-v1`          | std / pro      | ✅ Nur `duration=5`                   | ❌                     | ✅ Nur `duration=5`             | `extend` unterstützt `negative_prompt` und `cfg_scale` nicht |
| `kling-v1-6`        | std            | ❌                                    | ❌                     | ❌                             | Mehrbild-zu-Video, `extend` in allen Modi verfügbar |
| `kling-v1-6`        | pro            | ✅                                    | ❌                     | ❌                             |                                                  |
| `kling-v2-master`   | —              | ❌                                    | ❌                     | ❌                             | Einzelmodus, nur `duration=5/10`                 |
| `kling-v2-1-master` | —              | ❌                                    | ❌                     | ❌                             | Einzelmodus, nur `duration=5/10`                 |
| `kling-v2-5-turbo`  | std            | ❌                                    | ❌                     | ❌                             |                                                  |
| `kling-v2-5-turbo`  | pro            | ✅                                    | ❌                     | ❌                             |                                                  |
| `kling-v2-6`        | std            | ❌                                    | ❌                     | ❌                             |                                                  |
| `kling-v2-6`        | pro            | ✅                                    | ✅                     | ❌                             | Einziges Nicht-v3-Modell, das gleichzeitig Ton unterstützt |
| `kling-v3`          | std / pro      | ✅                                    | ✅                     | ✅                             | `duration`-Bereich 3–15 Sekunden                 |
| `kling-v3`          | 4k             | ✅                                    | ✅                     | ❌                             | Der 4K-Modus ist nicht mit Kamerafahrten kompatibel |
| `kling-v3-omni`     | std / pro / 4k | ✅                                    | ✅                     | ❌                             |                                                  |
| `kling-o1`          | std / pro      | ✅                                    | ❌                     | ❌                             | Unterstützt nur `duration=5`                     |

Hinweise:

- `mode=4k` wird nur von `kling-v3` und `kling-v3-omni` unterstützt; außerdem ist es mit `camera_control` (Kamerafahrt) nicht kombinierbar.
- `end_image_url` kann nur bei `action=image2video` zusammen mit `start_image_url` verwendet werden. Die alleinige Übergabe von `end_image_url` (ohne `start_image_url`) wird abgelehnt.
- `kling-v3` / `kling-v3-omni` akzeptieren jede ganzzahlige `duration` von 3–15 Sekunden; `kling-o1` akzeptiert nur 5; die übrigen Modelle akzeptieren nur 5 oder 10.
- `generate_audio` ist standardmäßig `false`. Nur `kling-v3`, `kling-v3-omni` und `kling-v2-6` (pro-Modus) werden unterstützt.

## Funktion zur Videoerweiterung

Wenn Sie ein bereits generiertes Kling-Video weitergenerieren möchten, können Sie den Parameter `action` auf `extend` setzen und die ID des Videos eingeben, das weitergeneriert werden soll. Die Video-ID erhalten Sie über die grundlegende Verwendung, wie in der folgenden Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Hier können Sie sehen, dass die ID des Videos lautet:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Hinweis: Die `video_id` im Video hier ist die ID des generierten Videos. Wenn Sie nicht wissen, wie man ein Video generiert, können Sie sich auf die oben beschriebene grundlegende Verwendung beziehen, um ein Video zu generieren.

Als Nächstes müssen wir unbedingt den Prompt eingeben, der im nächsten Schritt erweitert werden soll, um das generierte Video individuell anzupassen. Dabei können die folgenden Inhalte angegeben werden:

- `model`: Das Modell zur Videogenerierung, hauptsächlich die Modelle `kling-v1`, `kling-v1-5` und `kling-v1-6`.
- `mode`: Der Modus zur Videogenerierung. Die optionalen Werte sind Standardmodus `std`, Schnellmodus `pro` und nativer 4K-Modus `4k` (nur von `kling-v3` und `kling-v3-omni` unterstützt und nicht mit der Kamerafahrtsteuerung kompatibel).
- `duration`: Die Videolänge dieser Videogenerierungsaufgabe, hauptsächlich 5s und 10s.
- `start_image_url`: Beim Auswählen der Bild-zu-Video-Aktion `image2video` muss der Link zum hochzuladenden Referenzbild des ersten Frames angegeben werden.
- `prompt`: Prompt.

Ein Ausfüllbeispiel sieht wie folgt aus:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Nach dem Ausfüllen wird der folgende Code automatisch generiert:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Klicken Sie auf Ausführen; Sie werden feststellen, dass Sie ein Ergebnis wie folgt erhalten:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```
Wie man sehen kann, stimmt der Ergebnisinhalt mit dem vorherigen überein, wodurch die Funktion zur Videoerweiterung realisiert wird.

## Omni-All-in-One-Referenz (Videobearbeitung / Referenzvideo / Mehrbildreferenz)

`kling-o1` und `kling-v3-omni` sind zwei unabhängige Modelle, die beide die Fähigkeit zur „All-in-One-Referenz“ unterstützen. Auf Grundlage von Text-zu-Video (`action=text2video`) können zusätzlich Referenzbilder oder Referenzvideos übergeben werden, um **Mehrbildreferenzen, Referenzvideos sowie die direkte Bearbeitung vorhandener Videos** zu ermöglichen.

**Kernvereinbarung**: Referenzmaterialien müssen im `prompt` in der Form `&lt;&lt;<image_1>>>`, `&lt;&lt;<video_1>>>` (Nummerierung beginnt bei 1) referenziert werden, um das Material an der entsprechenden Position in `image_list` / `video_list` zu verwenden; nur dann wendet das Modell diese Referenzen an. Wenn nur Material übergeben, aber nicht im Prompt referenziert wird, wird das Material ignoriert.

> Sicherheitshinweis: Die aktuelle API stellt `element_list` nicht bereit. Die IDs der Kling Element Library sind nicht mandantenisoliert. Bitte verwenden Sie `image_list`, um Referenzbilder für Subjekte zu übergeben, bis eine mandantenisolierte Element-Management-API bereitgestellt wird.

Omni-Anfragen unterstützen weder `negative_prompt`, `cfg_scale` noch `camera_control`, und auch `mode=4k` kann nicht verwendet werden. Wenn ein Referenzvideo enthalten ist, muss `generate_audio` auf `false` gesetzt werden.

### Referenzvideo und Videobearbeitung (`video_list`)

`video_list` wird zum Übergeben eines Referenzvideos verwendet und ist das häufigste Szenario dieser Funktion. Die Felder der Array-Elemente lauten wie folgt:

- `video_url`: Link zum Referenzvideo, darf nicht leer sein. Maximal 1 MP4/MOV-Video, Dateigröße ≤200MB, Bildrate 24–60fps. `kling-o1` erfordert eine Dauer von 3–10 Sekunden sowie Breite und Höhe jeweils von 700–2160px; `kling-v3-omni` erfordert eine Dauer von 3–15,5 Sekunden, Breite und Höhe jeweils von 700–4553px, Gesamtpixel ≤8.294.400 und ein Seitenverhältnis von 0,4–2.
- `refer_type`: Referenztyp, optional `base` (Standard, **das zu bearbeitende Basisvideo**, d. h. „Video direkt bearbeiten“, wobei Elemente hinzugefügt/entfernt/geändert, die Komposition angepasst, der Stil, die Farben, das Wetter usw. geändert werden können) oder `feature` (**Merkmalsreferenz**, zur Referenzierung seines Stils / seiner Kameraführung / zur Fortsetzung mit der nächsten Einstellung).
- `keep_original_sound`: Ob der Originalton des Videos beibehalten werden soll, optional `yes` (beibehalten) oder `no` (entfernen).

> Hinweis: Wenn ein Referenzvideo vorhanden ist, muss `generate_audio` auf `false` gesetzt werden. Für ein Video mit `refer_type=base` dürfen kein Startbild / Endbild mehr angegeben werden.

Das CURL-Beispiel für die Bearbeitung eines vorhandenen Videos (Änderung des Videos in einen Anime-Stil) lautet wie folgt:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Mehrbildreferenz (`image_list`)

`image_list` wird zum Übergeben von Referenzbildern verwendet (Elemente / Szenen / Stile usw.). Die Felder der Array-Elemente lauten wie folgt:

- `image_url`: Link zum Referenzbild, darf nicht leer sein. Anforderungen: Format .jpg/.jpeg/.png; Dateigröße ≤10MB; kürzeste Seite ≥300px; Seitenverhältnis 1:2,5 ~ 2,5:1.
- `type`: Optional. Wenn nicht übergeben, wird es als reines Referenzbild verwendet; bei Übergabe von `first_frame` / `end_frame` wird es jeweils als Startbild / Endbild verwendet (entspricht `start_image_url` / `end_image_url`).

Bei der Verwendung muss im `prompt` mit `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>` referenziert werden. Mengenbegrenzung: Wenn kein Referenzvideo vorhanden ist, sind Referenzbilder ≤ 7; wenn ein Referenzvideo vorhanden ist, sind Referenzbilder ≤ 4. Wenn nur ein Start- / Endbild übergeben wird, können auch direkt `start_image_url` / `end_image_url` verwendet werden, aber das Endbild muss zusammen mit dem Startbild verwendet werden.

> Hinweis: Wenn gleichzeitig `start_image_url` / `end_image_url` und `image_list` übergeben werden, werden Start- / Endbilder vor `image_list` eingeordnet, was möglicherweise die Zuordnung der Nummerierung von `&lt;&lt;<image_N>>>` beeinflusst. Es wird empfohlen, nur eine der beiden Varianten zu verwenden: Wenn Start- / Endbilder benötigt werden, geben Sie `type` direkt in `image_list` an und mischen Sie dies nicht mit `start_image_url` / `end_image_url`.

CURL-Beispiel zur Videogenerierung mit Mehrbildreferenz:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Asynchroner Callback

Da die Generierung durch die Kling Videos Generation API relativ lange dauert, ungefähr 1–2 Minuten, bleibt die HTTP-Anfrage bei einer längeren Nichtantwort der API dauerhaft verbunden, was zu zusätzlichem Verbrauch von Systemressourcen führt. Daher bietet diese API auch Unterstützung für asynchrone Callbacks.

Der gesamte Ablauf ist: Wenn der Client eine Anfrage initiiert, gibt er zusätzlich ein Feld `callback_url` an. Nachdem der Client die API-Anfrage initiiert hat, gibt die API sofort ein Ergebnis zurück, das ein Feld `task_id` enthält, welches die aktuelle Aufgaben-ID darstellt. Nachdem die Aufgabe abgeschlossen ist, wird das Ergebnis des generierten Videos in Form von POST JSON an die vom Client angegebene `callback_url` gesendet, wobei ebenfalls das Feld `task_id` enthalten ist, sodass das Aufgabenergebnis über die ID zugeordnet werden kann.

Im Folgenden erfahren wir anhand eines Beispiels, wie genau dies durchgeführt wird.

Zunächst ist der Webhook-Callback ein Dienst, der HTTP-Anfragen empfangen kann. Entwickler sollten ihn durch die URL ihres selbst eingerichteten HTTP-Servers ersetzen. Zur bequemen Demonstration wird hier eine öffentliche Webhook-Beispielwebsite https://webhook.site/ verwendet. Beim Öffnen dieser Website erhält man eine Webhook-URL, wie in der Abbildung gezeigt:

![](https://cdn.acedata.cloud/tbcnai.png)

Kopieren Sie diese URL, dann kann sie als Webhook verwendet werden. Das Beispiel hier lautet `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Als Nächstes können wir das Feld `callback_url` auf die oben genannte Webhook-URL setzen und gleichzeitig die entsprechenden Parameter ausfüllen. Der konkrete Inhalt ist in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Klicken Sie auf Ausführen. Sie können feststellen, dass sofort ein Ergebnis wie folgt erhalten wird:

```

  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
```

## Fehlerbehandlung

Wenn beim Aufrufen der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Information zurück. Zum Beispiel:

- `400 token_mismatched`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`：Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`：Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`：Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## Fazit

Durch dieses Dokument haben Sie bereits erfahren, wie Sie die Kling Videos Generation API verwenden können, um durch die Eingabe von Prompt-Wörtern sowie einem Referenzbild des ersten Frames Videos zu generieren. Wir hoffen, dass dieses Dokument Ihnen dabei helfen kann, diese API besser anzubinden und zu verwenden. Bei Fragen kontaktieren Sie bitte jederzeit unser technisches Support-Team.

### Kling 3.0 Turbo

`model="kling-v3-turbo"` unterstützt Text-zu-Video und Bild-zu-Video mit dem ersten Frame, mit einer Dauer von ganzzahligen 3–15 Sekunden. `mode="std"` gibt 720p aus, `mode="pro"` gibt 1080p aus. Dieses Modell verfügt über natives Audio und bietet keinen Schalter zum Deaktivieren; lassen Sie `generate_audio` weg oder setzen Sie es auf `true`. Dieses Modell unterstützt weder den letzten Frame, Kamerafahrtsobjekte, unabhängige negative Prompts noch `cfg_scale`. Beschreiben Sie in `prompt` direkt die Inhalte, die erscheinen oder vermieden werden sollen.

### Multi-Shot-Video

`kling-v3` und `kling-v3-omni` unterstützen `multi_shot=true`. `shot_type="intelligence"` erstellt auf Grundlage von `prompt` automatisch ein Storyboard; `shot_type="customize"` stellt über `multi_prompt` 1–6 Storyboards bereit, wobei jeder Eintrag einen ab 1 fortlaufend erhöhten `index`, einen `prompt` mit maximal 512 Zeichen und eine ganzzahlige `duration` von mindestens 1 Sekunde enthält. Die Summe der Dauer aller Storyboards muss der gesamten `duration` entsprechen. Benutzerdefinierte Storyboards verwenden nicht das globale `prompt`. Multi-Shot wird nach dem ausgewählten Modell, der Bildqualität, der Audiokonfiguration und der Gesamtdauer abgerechnet.
