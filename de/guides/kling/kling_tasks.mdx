Die Hauptfunktion der Kling Tasks API besteht darin, den Ausführungsstatus einer Aufgabe durch Eingabe der von der Kling Videos Generation API generierten Aufgaben-ID abzufragen.

Dieses Dokument stellt die Integrationsanleitung der Kling Tasks API detailliert vor und hilft Ihnen, diese API einfach zu integrieren und ihre leistungsstarken Funktionen vollständig zu nutzen. Über die Kling Tasks API können Sie einfach den Ausführungsstatus von Aufgaben der Kling Videos Generation API abfragen.

## Antragsprozess

Um die Kling Videos Generation API zu verwenden, rufen Sie zunächst Ihren API-Token in der [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) ab und bewahren Sie ihn zur späteren Verwendung auf.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, wo Sie zur Registrierung und Anmeldung eingeladen werden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass Sie ihn für jeden Dienst separat beantragen müssen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Guthaben, um den Dienst kostenlos zu testen; bei unzureichendem Guthaben können Sie Ihr allgemeines Guthaben in der [Konsole](https://platform.acedata.cloud/console/coin) aufladen.

> 📘 Vollständige Dokumentation: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Anfragebeispiel

Die Kling Tasks API kann verwendet werden, um die Ergebnisse der Kling Videos Generation API abzufragen. Wie Sie die Kling Videos Generation API verwenden, erfahren Sie in der Dokumentation [Kling Videos Generation API ](https://platform.acedata.cloud/documents/kling-videos)。

Wir verwenden eine von der Kling Videos Generation API zurückgegebene Aufgaben-ID als Beispiel, um zu demonstrieren, wie diese API verwendet wird. Angenommen, wir haben eine Aufgaben-ID: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0. Im Folgenden wird demonstriert, wie durch Übergabe einer Aufgaben-ID vorgegangen wird.

### Anfrage-Header und Anfrage-Body festlegen

**Request Headers** umfassen:

- `accept`: Gibt an, dass Antwortergebnisse im JSON-Format empfangen werden sollen; hier wird `application/json` eingetragen.
- `authorization`: Der Schlüssel zum Aufrufen der API, der nach der Beantragung direkt über die Auswahlliste ausgewählt werden kann.

**Request Body** umfasst:

- `id`: Die hochgeladene Aufgaben-ID.
- `action`: Die Operationsmethode für die Aufgabe.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Das zurückgegebene Ergebnis enthält mehrere Felder. Das Feld `request` ist der Request Body beim Starten der Aufgabe, während das Feld `response` der nach Abschluss der Aufgabe zurückgegebene Response Body ist. Die Feldbeschreibungen sind wie folgt.

- `id`: Die ID zur Generierung dieser Videoaufgabe, die zur eindeutigen Kennzeichnung dieser Videogenerierungsaufgabe verwendet wird.
- `request`: Die Anfrageinformationen in der Abfrage der Videoaufgabe.
- `response`: Die Rückgabeinformationen in der Abfrage der Videoaufgabe.
- `created_at`: Zeitpunkt der Aufgabenerstellung, Unix-Zeitstempel (Sekunden, Gleitkommazahl).
- `started_at`: Zeitpunkt des Ausführungsbeginns der Aufgabe, Unix-Zeitstempel (Sekunden, Gleitkommazahl).
- `finished_at`: Zeitpunkt des Aufgabenabschlusses, Unix-Zeitstempel (Sekunden, Gleitkommazahl). Dieses Feld wird nicht zurückgegeben, wenn die Aufgabe nicht abgeschlossen ist.
- `elapsed`: Ausführungsdauer der Aufgabe, in Sekunden (Gleitkommazahl, auf 3 Dezimalstellen gerundet). Dieses Feld wird nicht zurückgegeben, wenn die Aufgabe nicht abgeschlossen ist.

## Batch-Abfrageoperation

Dies dient zur Abfrage von Details zu Videoaufgaben für mehrere Aufgaben-IDs. Im Unterschied zu oben muss action auf retrieve_batch ausgewählt werden.

**Request Body** umfasst:

- `ids`: Das Array der hochgeladenen Aufgaben-IDs.
- `action`: Die Operationsmethode für die Aufgabe.

## Fehlerbehandlung

Wenn beim Aufrufen der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Information zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
