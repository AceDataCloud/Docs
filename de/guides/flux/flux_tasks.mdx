Die Hauptfunktion der Flux Tasks API besteht darin, den Ausführungsstatus der Aufgabe durch Eingabe der von der Flux Images Generation API oder Flux Videos API zurückgegebenen Plattform-Aufgaben-ID abzufragen.

Dieses Dokument stellt die Integrationshinweise für die Flux Tasks API ausführlich vor und hilft Ihnen, diese API einfach zu integrieren und ihre leistungsstarken Funktionen voll auszuschöpfen. Über die Flux Tasks API können Sie einfach den Aufgabenausführungsstatus der Flux Images Generation API abfragen.

Ein vollständiges Beispiel für die Videoübermittlung und das Polling finden Sie im [Flux Videos API Integrationsleitfaden](https://platform.acedata.cloud/documents/flux-videos-integration). Für die Abfrage bestehender Aufgaben fallen keine zusätzlichen Generierungskosten an.

## Antragsverfahren

Um die Flux Images Generation API zu verwenden, rufen Sie zunächst in der [Ace Data Cloud Konsole](https://platform.acedata.cloud/console/applications) Ihren API-Token ab und bewahren Sie ihn als Reserve auf.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Plattformdienste aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Beim ersten Antrag erhalten Sie ein kostenloses Guthaben und können es kostenlos testen; bei unzureichendem Guthaben können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) das allgemeine Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Anfragebeispiel

Die Flux Tasks API kann verwendet werden, um die Ergebnisse der Flux Images Generation API abzufragen. Informationen zur Verwendung der Flux Images Generation API finden Sie in der Dokumentation [Flux Images Generation API ](https://platform.acedata.cloud/documents/flux-images-integration).

### Anfrage-Header und Anfrage-Body festlegen

**Request Headers** umfassen:

- `accept`: Gibt an, dass die Antwortergebnisse im JSON-Format empfangen werden, hier wird `application/json` eingetragen.
- `authorization`: Der Schlüssel zum Aufrufen der API, nach dem Antrag kann er direkt über das Dropdown ausgewählt werden.

**Request Body** umfasst:

- `id`: Die hochgeladene Aufgaben-ID.
- `action`: Die Operationsmethode für die Aufgabe.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/flux/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/flux/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Das zurückgegebene Ergebnis enthält insgesamt mehrere Felder. Das Feld `request` ist der Request Body beim Starten der Aufgabe, während das Feld `response` der nach Abschluss der Aufgabe zurückgegebene Response Body ist. Die Feldbeschreibungen lauten wie folgt.

- `id`, die ID zur Generierung dieser Bildaufgabe, dient zur eindeutigen Kennzeichnung dieser Bildgenerierungsaufgabe.
- `request`, die Anfrageinformationen in der abgefragten Bildaufgabe.
- `response`, die Rückgabeinformationen in der abgefragten Bildaufgabe.
- `created_at`, Erstellungszeit der Aufgabe, Unix-Zeitstempel (Sekunden, Gleitkommazahl).
- `started_at`, Startzeit der Aufgabenausführung, Unix-Zeitstempel (Sekunden, Gleitkommazahl).
- `finished_at`, Abschlusszeit der Aufgabe, Unix-Zeitstempel (Sekunden, Gleitkommazahl). Wenn die Aufgabe nicht abgeschlossen ist, wird dieses Feld nicht zurückgegeben.
- `elapsed`, Ausführungsdauer der Aufgabe, in Sekunden (Gleitkommazahl, auf 3 Dezimalstellen genau). Wenn die Aufgabe nicht abgeschlossen ist, wird dieses Feld nicht zurückgegeben.

- `ids`: Das hochgeladene Aufgaben-ID-Array.

## Fehlerbehandlung

Wenn bei der API-Aufrufung ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Information zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben die Ratenbegrenzung überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel einer Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
