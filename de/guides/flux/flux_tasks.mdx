Die Hauptfunktion der Flux Tasks API besteht darin, den Status der Ausführung eines Auftrags anhand der von der Flux Images Generation API generierten Auftrags-ID abzufragen.

Dieses Dokument wird die Integrationsanleitung der Flux Tasks API detailliert beschreiben, um Ihnen zu helfen, diese API einfach zu integrieren und ihre leistungsstarken Funktionen voll auszuschöpfen. Mit der Flux Tasks API können Sie den Status der Ausführung von Aufträgen der Flux Images Generation API problemlos abfragen.

## Antragsprozess

Um die Flux Images Generation API zu nutzen, müssen Sie zunächst im [Ace Data Cloud Dashboard](https://platform.acedata.cloud/console/applications) Ihr API-Token abrufen und für zukünftige Verwendung aufbewahren.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, wo Sie zur Registrierung und Anmeldung eingeladen werden. Nach Abschluss werden Sie automatisch zur aktuellen Seite zurückgeleitet.

**Ein API-Token reicht aus, um auf alle Dienste der Plattform zuzugreifen, ohne dass für jeden Dienst separat ein Antrag gestellt werden muss.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, um die Dienste kostenlos auszuprobieren; wenn das Kontingent erschöpft ist, können Sie im [Dashboard](https://platform.acedata.cloud/console/coin) Ihr Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Anfragebeispiel

Die Flux Tasks API kann verwendet werden, um die Ergebnisse der Flux Images Generation API abzufragen. Informationen zur Verwendung der Flux Images Generation API finden Sie in der Dokumentation [Flux Images Generation API](https://platform.acedata.cloud/documents/flux-images-integration).

Wir nehmen als Beispiel eine von der Flux Images Generation API zurückgegebene Auftrags-ID und zeigen, wie man diese API verwendet. Angenommen, wir haben eine Auftrags-ID: 2db0168c-2373-4367-8d9a-9dc778802e8a, im Folgenden zeigen wir, wie man durch Eingabe einer Auftrags-ID vorgeht.

### Anfrageheader und Anfragekörper festlegen

**Request Headers** umfassen:

- `accept`: Gibt an, dass die Antwort im JSON-Format empfangen werden soll, hier eingetragen als `application/json`.
- `authorization`: Der Schlüssel zur Aufrufung der API, nach der Beantragung kann dieser direkt ausgewählt werden.

**Request Body** umfasst:

- `id`: Die hochgeladene Auftrags-ID.
- `action`: Die Art der Operation auf dem Auftrag.

Einige Codebeispiele sind wie folgt:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/flux/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/flux/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Die Rückgabe enthält mehrere Felder, das Feld request ist der request body, der beim Starten des Auftrags gesendet wurde, während das Feld response der response body ist, der nach Abschluss des Auftrags zurückgegeben wird. Die Feldbeschreibung ist wie folgt.

- `id`, die ID des Bildauftrags, die zur eindeutigen Identifizierung dieses Bildgenerierungsauftrags dient.
- `request`, Informationen zur Anfrage im Bildauftrag.
- `response`, Informationen zur Rückgabe im Bildauftrag.
- `created_at`, Erstellungszeit des Auftrags, Unix-Zeitstempel (Sekunden, Fließkomma).
- `started_at`, Beginn der Ausführung des Auftrags, Unix-Zeitstempel (Sekunden, Fließkomma).
- `finished_at`, Abschlusszeit des Auftrags, Unix-Zeitstempel (Sekunden, Fließkomma). Dieses Feld wird nicht zurückgegeben, wenn der Auftrag nicht abgeschlossen ist.
- `elapsed`, die für die Ausführung des Auftrags benötigte Zeit, gemessen in Sekunden (Fließkomma, auf 3 Dezimalstellen gerundet). Dieses Feld wird nicht zurückgegeben, wenn der Auftrag nicht abgeschlossen ist.

## Fehlerbehandlung

Bei der Verwendung der API, wenn ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die Informationen zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Unbefugt, ungültiger oder fehlender Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Rate-Limit überschritten.
- `500 api_error`: Interner Serverfehler, etwas ist auf dem Server schiefgelaufen.

### Fehlerantwort Beispiel

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "Abruf fehlgeschlagen"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
