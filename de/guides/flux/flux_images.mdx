Dieser Artikel stellt eine Anleitung zur Integration der Flux Images Generation API vor, mit der durch die Eingabe benutzerdefinierter Parameter offizielle Bilder von Flux generiert werden können.

## Antragsprozess

Um die Flux Images Generation API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten, und bewahren Sie ihn als Reserve auf.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, wo Sie zur Registrierung und Anmeldung eingeladen werden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent zur kostenlosen Nutzung; bei unzureichendem Kontingent können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Grundlegende Verwendung

Lernen Sie zunächst die grundlegende Verwendung kennen: Geben Sie das Prompt `prompt`, die Generierungsaktion `action` und die Bildgröße `size` ein, um das verarbeitete Ergebnis zu erhalten. Zunächst müssen Sie einfach ein Feld `action` übergeben, dessen Wert `generate` ist, und dann müssen wir auch ein Prompt eingeben. Der konkrete Inhalt lautet wie folgt:

<p><img src="https://cdn.acedata.cloud/wz85jt.png" width="500" className="m-auto" /></p>

Hier sehen Sie, dass wir die Request Headers festgelegt haben, einschließlich:

- `accept`: Welches Format des Antwortergebnisses empfangen werden soll; hier wird `application/json` eingetragen, also das JSON-Format.
- `authorization`: Der Schlüssel zum Aufrufen der API, der nach der Beantragung direkt aus der Auswahlliste ausgewählt werden kann.

Außerdem wurde der Request Body festgelegt, einschließlich:

- `action`: Die Aktion dieser Bildgenerierungsaufgabe.
- `size`: Die Größe des Bildgenerierungsergebnisses. **Die Serien `flux-2-flex` / `flux-2-pro` / `flux-2-max` müssen ein Bildseitenverhältnis übergeben (z. B. `1:1`, `16:9`) und akzeptieren keine Pixelgröße wie `1024x1024`; bei Auslassung wird 400 zurückgegeben.**
- `count`: Die Anzahl der generierten Bilder; der Standardwert ist 1. Dieser Parameter ist nur bei Bildgenerierungsaufgaben wirksam und bei Bearbeitungsaufgaben ungültig.
- `prompt`: Das Prompt.
- `model`: Das Generierungsmodell, standardmäßig `flux-dev`; die neuesten Flaggschiffe sind `flux-2-pro`, `flux-2-max` (höhere Bildqualität, muss mit dem Bildseitenverhältnis `size` verwendet werden).
- `callback_url`: Die URL, an die das Ergebnis zurückgerufen werden soll.
- `async`: Optional. Wenn auf `true` gesetzt, gibt die Schnittstelle sofort `task_id` zurück; es muss keine `callback_url` bereitgestellt werden. Anschließend kann das Ergebnis durch Polling über die entsprechende Schnittstelle zur Aufgabenabfrage abgerufen werden.

Der Parameter `size` hat einige besondere Einschränkungen und wird hauptsächlich in zwei Typen unterteilt: das Breite-x-Höhe-Seitenverhältnis `width x height` und das Bildseitenverhältnis `x:y`. Die Details sind wie folgt:

| Modell               | Bereich                                         |
| ---------------- | ------------------------------------------ |
| flux-dev         | Unterstützt Breite-x-Höhe-Seitenverhältnisse 1024x1024, 1024x1792, 1792x1024 oder Bildseitenverhältnisse |
| flux-pro         | Unterstützt Breite-x-Höhe-Seitenverhältnisse 1024x1024, 1024x1792, 1792x1024 oder Bildseitenverhältnisse |
| flux-2-flex      | Unterstützt nur Bildseitenverhältnisse                                    |
| flux-2-pro       | Unterstützt nur Bildseitenverhältnisse                                    |
| flux-2-max       | Unterstützt nur Bildseitenverhältnisse                                    |
| flux-kontext-pro | Unterstützt nur Bildseitenverhältnisse                                    |
| flux-kontext-max | Unterstützt nur Bildseitenverhältnisse                                    |

Referenz-Bildseitenverhältnisse: "21:9", "16:9", "4:3", "3:2", "1:1", "2:3", "3:4", "9:16", "9:21".

Nach Auswahl der Parameter wird auf der rechten Seite automatisch der entsprechende Code generiert. Bestätigen Sie vor dem Kopieren, dass der Autorisierungs-Header Ihren eigenen API-Key verwendet; in Dokumenten und Screenshots dürfen keine echten Zugangsdaten erscheinen.

Klicken Sie auf die Schaltfläche „Try“, um einen Test durchzuführen. Hier erhalten wir das folgende Ergebnis:

```json
{
  "success": true,
  "task_id": "5456c749-3bbb-4f10-9eb8-cfbcac297500",
  "trace_id": "ae4eecb8-1dd6-45b4-bfb3-a1c48872536e",
  "data": [
    {
      "image_url": "https://cdn.acedata.cloud/assets/examples/flux/5456c749-3bbb-4f10-9eb8-cfbcac297500-d0ef60485f73.jpg"
    }
  ]
}
```

Das Rückgabeergebnis enthält mehrere Felder, die wie folgt vorgestellt werden:

- `success`: Der Status der aktuellen Videogenerierungsaufgabe.
- `task_id`: Die ID der aktuellen Videogenerierungsaufgabe.
- `trace_id`: Die Tracking-ID der aktuellen Videogenerierung.
- `data`: Die Ergebnisliste der aktuellen Bildgenerierungsaufgabe.
  - `image_url`: Der Link der aktuellen Bildgenerierungsaufgabe.
  - `prompt`: Das Prompt.

Sie sehen, dass wir zufriedenstellende Bildinformationen erhalten haben. Wir müssen nur die generierten Flux-Bilder über die Bildlink-Adresse in `data` des Ergebnisses abrufen.

Wenn Sie außerdem den entsprechenden Integrationscode generieren möchten, können Sie ihn direkt kopieren. Beispielsweise lautet der CURL-Code wie folgt:

```shell
curl -X POST 'https://api.acedata.cloud/flux/images' \
-H 'authorization: Bearer {token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "A photorealistic studio product shot of a frosted-glass perfume bottle on wet black slate, single softbox key light, water droplets, dark moody background, 85mm macro.",
  "model": "flux-2-pro",
  "size": "1:1"
}'
```

## Bildbearbeitungsaufgabe

Wenn Sie ein bestimmtes Bild bearbeiten möchten, muss zunächst der Parameter `image_url` mit dem Link des zu bearbeitenden Bildes übergeben werden. Zu diesem Zeitpunkt unterstützt `action` nur `edit`, dann können die folgenden Inhalte angegeben werden:

- model: Das Modell, das für diese Bildbearbeitungsaufgabe verwendet wird, unterstützt `flux-dev`, `flux-pro`, `flux-kontext-pro`, `flux-kontext-max`, `flux-2-flex`, `flux-2-pro`, `flux-2-max`.
- image_url: Das hochzuladende zu bearbeitende Bild.

Das Ausfüllbeispiel lautet wie folgt:

<p><img src="https://cdn.acedata.cloud/jn9da5.png" width="500" className="m-auto" /></p>

Nach dem Ausfüllen wird automatisch der folgende Code generiert:

<p><img src="https://cdn.acedata.cloud/6cwxb8.png" width="500" className="m-auto" /></p>

Der entsprechende Code:

```python
import requests

url = "https://api.acedata.cloud/flux/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "edit",
    "prompt": "a white siamese cat",
    "model": "flux-kontext-pro",
    "image_url": "https://cdn.acedata.cloud/ytj2qy.png"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Klicken Sie auf Ausführen, und Sie werden feststellen, dass sofort ein Ergebnis wie folgt erhalten wird:

```json
{
  "success": true,
  "task_id": "2a7979ff-1f77-4380-92c6-a2dc37c3b4c8",
  "trace_id": "732b65c0-48d9-49f7-b568-64e5acffe4c0",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "timings": 1752744073
    }
  ]
}
```
Wie zu sehen ist, besteht der generierte Effekt darin, das Originalbild zu bearbeiten, und das Ergebnis ähnelt dem obigen.

## Asynchroner Rückruf

Da die Generierungszeit der Flux Images Generation API relativ lang ist und etwa 1–2 Minuten benötigt, bleibt die HTTP-Anfrage bei einer längeren Nichtreaktion der API weiterhin verbunden, was zu zusätzlichem Verbrauch von Systemressourcen führt. Daher bietet diese API auch Unterstützung für asynchrone Rückrufe.

Der gesamte Ablauf ist folgender: Wenn der Client eine Anfrage startet, gibt er zusätzlich ein Feld `callback_url` an. Nachdem der Client die API-Anfrage gestartet hat, gibt die API sofort ein Ergebnis zurück, das ein Feld `task_id` enthält, welches die aktuelle Aufgaben-ID darstellt. Nach Abschluss der Aufgabe wird das Ergebnis der Bildgenerierung in Form von POST JSON an die vom Client angegebene `callback_url` gesendet, wobei ebenfalls das Feld `task_id` enthalten ist, sodass die Aufgabenergebnisse über die ID verknüpft werden können.

Im Folgenden erfahren wir anhand eines Beispiels, wie dies konkret funktioniert.

Zunächst ist der Webhook-Rückruf ein Dienst, der HTTP-Anfragen empfangen kann. Entwickler sollten ihn durch die URL eines selbst eingerichteten HTTP-Servers ersetzen. Zur einfachen Demonstration wird hier eine öffentliche Webhook-Beispielwebsite https://webhook.site/ verwendet. Beim Öffnen dieser Website erhalten Sie eine Webhook-URL, wie in der Abbildung gezeigt:

![](https://cdn.acedata.cloud/cjjfly.png)

Kopieren Sie diese URL, dann kann sie als Webhook verwendet werden. Das Beispiel hier lautet `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`.

Als Nächstes können wir das Feld `callback_url` auf die oben genannte Webhook-URL setzen und gleichzeitig die entsprechenden Parameter ausfüllen. Der konkrete Inhalt ist in der Abbildung dargestellt:

<p><img src="https://cdn.acedata.cloud/wm6caw.png" width="500" className="m-auto" /></p>

Klicken Sie auf Ausführen. Sie werden feststellen, dass sofort ein Ergebnis zurückgegeben wird, wie folgt:

```
{
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c"
}
```

Nach einem kurzen Moment können wir unter `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab` das Ergebnis der Bildgenerierung beobachten, wie in der Abbildung gezeigt:

![](https://cdn.acedata.cloud/v23lot.png)

Der Inhalt lautet wie folgt:

```json
{
  "success": true,
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c",
  "trace_id": "9b4b1ff3-90f2-470f-b082-1061ec2948cc",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "seed": 1698551532,
      "timings": {
        "inference": 3.328
      }
    }
  ]
}
```

Wie zu sehen ist, enthält das Ergebnis ein Feld `task_id`. Die anderen Felder ähneln alle den obigen. Über dieses Feld kann die Verknüpfung der Aufgaben realisiert werden.

## Fehlerbehandlung

Wenn beim Aufrufen der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Information zurück. Zum Beispiel:

- `400 token_mismatched`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`：Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`：Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`：Interner Serverfehler, auf dem Server ist ein Fehler aufgetreten.

### Beispiel für eine Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
