[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) ist ein lokal ausgeführter Programm-Agent. Er liest den Arbeitsbereich, ruft Werkzeuge auf und führt Befehle aus, und ruft dann über die OpenAI-kompatible Chat Completions-Schnittstelle das Modell auf.

> Dieser Artikel gilt für `deepseek-harness-sdk==0.1.0rc6` und `deepseek-harness-runtime-bin==0.1.0rc6`. Nach dem Upgrade des Clients führen Sie bitte die untenstehenden Tests für schreibgeschützte Dateien erneut durch.

## Unterstützungsbereich

| Projekt        | Konfiguration                             |
| -------------- | ---------------------------------------- |
| API Basis-URL  | `https://api.acedata.cloud/v1`         |
| Modell         | `deepseek-v4-pro`                       |
| Protokoll      | OpenAI-kompatible Chat Completions (streaming) |
| Fähigkeiten    | Text, Schlussfolgerungsprozess, Funktionsaufrufe, lokale Bash-Werkzeugschleifen, Nutzungstatistiken |

Das Modellverzeichnis kann sich ändern. Überprüfen Sie vor dem Ausführen mit dem speziellen Schlüssel des Coding Plans das aktuelle Verzeichnis:

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY"
```

Bestätigen Sie, dass die Antwort `deepseek-v4-pro` enthält. Verwenden Sie `deepseek-v4-flash` nicht als gleichwertigen Ersatz für den Werkzeugmodus in diesem Artikel; in dieser festen Versionsvalidierung hat seine mehrstufige Schlussfolgerungsgeschichte und Werkzeugwiedergabe nicht bestanden.

## 1. Bereiten Sie den speziellen Schlüssel vor

Öffnen Sie die [Coding Plan Anwendung](https://platform.acedata.cloud/console/applications), gehen Sie zur gekauften Coding-Anwendung und erstellen oder kopieren Sie den speziellen API-Schlüssel dieser Anwendung. Der Coding Plan verwendet kein allgemeines Guthaben, Schlüssel anderer Anwendungen können die Paketberechtigungen nicht repräsentieren.

Fügen Sie den Schlüssel nur in die aktuelle Shell ein:

```bash
export ACEDATACLOUD_API_KEY="PASTE_YOUR_CODING_KEY_HERE"
export DEEPSEEK_BASE_URL="https://api.acedata.cloud/v1"
export DEEPSEEK_API_KEY="$ACEDATACLOUD_API_KEY"
```

Schreiben Sie den echten Schlüssel nicht in Skripte, Konfigurationsrepositorys, Terminal-Screenshots oder Sitzungsprotokolle.

## 2. Erstellen Sie einen isolierten Arbeitsbereich

Das gebündelte Runtime von Harness enthält lokale Bash-Werkzeuge. Verweisen Sie beim ersten Test nicht auf echte Projekte oder das Hauptverzeichnis; erstellen Sie ein einmaliges Verzeichnis ohne Geheimnisse:

```bash
mkdir -p /tmp/deepseek-harness-demo/workspace
mkdir -p /tmp/deepseek-harness-demo/sessions
printf 'compatibility fixture\n' > /tmp/deepseek-harness-demo/workspace/fixture.txt
python3 -m venv /tmp/deepseek-harness-demo/venv
/tmp/deepseek-harness-demo/venv/bin/pip install \
  "deepseek-harness-sdk==0.1.0rc6"
```

Wenn das Unternehmensnetzwerk ein privates PyPI-Image verwendet, stellen Sie sicher, dass die gleiche Version von `deepseek-harness-runtime-bin` ebenfalls im Image vorhanden ist. Verwenden Sie nicht `danger-full-access`, um den Dateizugriff zu erweitern; das Beispiel in diesem Artikel übergibt nur das einmalige Verzeichnis an `cwd`.

## 3. Führen Sie das offizielle Python SDK aus

Speichern Sie den folgenden Inhalt als `/tmp/deepseek-harness-demo/run.py`:

```python
import os

from deepseek_harness import DeepSeekHarness

with DeepSeekHarness(
    provider="deepseek-official",
    model="deepseek-v4-pro",
    max_tokens=160,
    cwd="/tmp/deepseek-harness-demo/workspace",
    session_root="/tmp/deepseek-harness-demo/sessions",
    base_url=os.environ["DEEPSEEK_BASE_URL"],
    api_key=os.environ["DEEPSEEK_API_KEY"],
    request_timeout_seconds=180,
) as harness:
    result = harness.run(
        "Read fixture.txt once, then reply with exactly: sdk-harness-ok",
        session_id="acedatacloud-compat",
    )

print(result.final_response)
print(result.finish_reason)
```

Führen Sie aus:

```bash
/tmp/deepseek-harness-demo/venv/bin/python \
  /tmp/deepseek-harness-demo/run.py
```

Erwartetes Ergebnis:

```text
sdk-harness-ok
completed
```

Dieser Schritt validiert gleichzeitig die Bearer-Authentifizierung, `/v1/chat/completions`, SSE, Schlussfolgerungsinhalte, Werkzeugaufrufe und die Rückgabe von Werkzeugergebnissen. Nach Abschluss können Sie `/tmp/deepseek-harness-demo` löschen; wenn das Sitzungsverzeichnis Projektkontext enthält, sollte es ebenfalls gemäß dem gleichen Sensibilitätsgrad wie das Code-Repository aufbewahrt werden.

## Häufige Fragen

- **401**: Überprüfen Sie, ob `ACEDATACLOUD_API_KEY` in die gleiche Shell exportiert wurde, in der Python ausgeführt wird.
- **403 oder Kontingentmeldung**: Bestätigen Sie, dass der Schlüssel zur aktuellen Coding-Anwendung gehört, das Paket noch gültig ist und über ein verbleibendes Guthaben verfügt.
- **Modell nicht verfügbar**: Überprüfen Sie erneut `/v1/models`, raten Sie nicht anhand alter Screenshots auf den Modellnamen.
- **`reasoning_content` / Werkzeugwiedergabefehler**: Bestätigen Sie, dass SDK/runtime die in diesem Artikel festgelegte Version sind und `deepseek-v4-pro` verwenden.
- **Ungewöhnliche Anzahl von Werkzeugausführungen**: Stoppen Sie die Ausführung von Aufgaben, die Nebenwirkungen verursachen könnten, und verwenden Sie zunächst die schreibgeschützte Fixture, um die aktuelle Serviceversion zu validieren.
- **Installation fehlgeschlagen**: Bestätigen Sie, dass Python 3.10+, die Betriebssystemarchitektur von dem aktuellen Wheel unterstützt wird, und überprüfen Sie die Übereinstimmung der SDK/runtime-Versionen.

## Fähigkeitsgrenzen

Dieser Artikel validiert nur den lokalen Python SDK zu Chat Completions in Bezug auf Text und Werkzeugschleifen. Bilder, Files API, `/v1/responses`, `/v1/messages`, Remote-Arbeitsbereiche und gehostete Sandboxes fallen nicht in den versprochenen Rahmen dieses Tutorials; die Berechtigungen des Arbeitsbereichs und die Risiken lokaler Befehle liegen in der Verantwortung der Maschine und Konfiguration, die Harness ausführt.
