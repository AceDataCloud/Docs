Maestro ist eine **Agent-native** Video-Produktionsschnittstelle: Sie beschreiben das gewünschte Video mit einem natürlichen Sprach `prompt` (optional mit `file_urls` zur Verfügung gestellten Referenzbildern / Videos / Audios), und ein kopfloser „AI-Regisseur“ erledigt automatisch die Themenwahl, das Schreiben des Skripts, die Erstellung der Bilder, die Vertonung, die Musik, die Komposition und das Rendering, um schließlich ein fertiges Video mit Untertiteln zu produzieren und es auf das CDN hochzuladen.

Dieser Artikel wird die Integrationsanleitung der Maestro Video-Generierungs-API im Detail vorstellen, um Ihnen zu helfen, diese API schnell zu integrieren und ihre Fähigkeiten voll auszuschöpfen.

Dies ist eine **asynchrone Aufgaben**-Schnittstelle: Nach der Einreichung wird sofort eine `task_id` zurückgegeben, und anschließend können Sie über die [Maestro Aufgabenabfrage-API](development_maestro_tasks.md) (`POST /maestro/tasks`) die Ergebnisse abfragen (Abfragen sind kostenlos und werden nicht berechnet). Um auf einem vorhandenen Video weiterzuarbeiten, können Sie `action: remix` / `edit` / `extend` zusammen mit `ref_task_id` verwenden.

## Antragsprozess

Um die Maestro Video-Generierungs-API zu nutzen, müssen Sie zunächst im [Ace Data Cloud Dashboard](https://platform.acedata.cloud/console/applications) Ihr API-Token abrufen und für zukünftige Verwendung aufbewahren.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss werden Sie automatisch zur aktuellen Seite zurückgeleitet.

**Ein API-Token reicht aus, um auf alle Dienste der Plattform zuzugreifen, ohne dass für jeden Dienst separat beantragt werden muss.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, um es kostenlos auszuprobieren; wenn das Kontingent erschöpft ist, können Sie im [Dashboard](https://platform.acedata.cloud/console/coin) Ihr Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Maestro Video-Generierungs-API →](https://platform.acedata.cloud/documents/maestro-videos)

## Grundlegende Nutzung

`POST https://api.acedata.cloud/maestro/videos`

Die grundlegendste Verwendung erfordert nur die Übermittlung eines natürlichen Sprach `prompt`, der AI-Regisseur entscheidet automatisch über das Skript, die Bilder, die Vertonung und den Schnitt. Hier erfahren wir zunächst, welche Header und den Body der Anfrage gesetzt werden müssen.

**Request Headers** umfassen:

- `accept`: In welchem Format Sie die Antwort erhalten möchten, hier als `application/json`, also im JSON-Format.
- `authorization`: Der Schlüssel zur API, den Sie nach der Beantragung direkt auswählen können.
- `content-type`: Das Format des Anfragekörpers, hier als `application/json`.

**Request Body** umfasst hauptsächlich:

- `prompt`: Beschreiben Sie das Video in natürlicher Sprache (Thema, was gezeigt werden soll, Stil, Zielgruppe).
- `langs`: Array der Ausgabesprachen, wie `["zh-cn", "en"]`, standardmäßig `["zh-cn"]`.
- `aspect`: Bildverhältnis, `9:16` (Standard) / `16:9` / `1:1`.
- `duration`: Zielzeit (Sekunden), standardmäßig 30.

Die vollständigen Felder des Anfragekörpers sind in der folgenden Tabelle dargestellt:

| Feld            | Typ       | Pflicht  | Beschreibung                                                                                                                                                                                                                           |
| ------------- | -------- | --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`      | string   | Ja   | Beschreiben Sie das Video in natürlicher Sprache (Thema, was gezeigt werden soll, Stil, Zielgruppe). Skript, Bilder, Vertonung und Schnitt werden von der AI entschieden.                                                                                                                                                                             |
| `action`      | string   | Nein   | `generate` (Standard, neues Video generieren) / `remix` / `edit` / `extend` (Iterieren auf einem vorhandenen Video, muss mit `ref_task_id` kombiniert werden).                                                                                                                                                |
| `ref_task_id` | string   | Nein   | Muss ausgefüllt werden, wenn `action` remix / edit / extend ist: die `task_id` der historischen Aufgabe, die als Ausgangspunkt dient.                                                                                                                                                                   |
| `file_urls`   | string[] | Nein   | Referenzmedien (Bilder / Videos / Audio-URLs), z. B. Produktbilder, Logos oder Materialabschnitte, die untertitelt werden sollen.                                                                                                                                                                             |
| `langs`       | string[] | Nein   | Ausgabesprachen, wie `["zh-cn", "en"]`, standardmäßig `["zh-cn"]`. Die erste ist die Hauptsprache; für jede zusätzliche Sprache wird das Bild wiederverwendet, es kommen nur Vertonung + Rendering hinzu, **jede zusätzliche +6 Punkte**.                                                                                                                                          |
| `aspect`      | string   | Nein   | `9:16` (Standard) / `16:9` / `1:1` (Hinweis zum Bildverhältnis, die AI kann basierend auf dem Prompt anpassen).                                                                                                                                                                         |
| `duration`    | int      | Nein   | Zielzeit (Sekunden, **1–600**, also maximal 10 Minuten), standardmäßig 30. **Die Abrechnung erfolgt basierend auf der tatsächlichen Videolänge**, je länger, desto teurer (siehe Abrechnung unten).                                                                                                                                                                  |
| `quality`     | string   | Nein   | Produktionsstufe (Multiplikator auf den Preis basierend auf der Dauer): `draft` (schnelle Vorschau, grober Schnitt, etwa **0.5×** des Standardpreises) / `standard` (Standard, ausgewogen, **1×**) / `premium` (feiner, auffälliger, dauert länger, etwa **2×** des Standardpreises).                                                                                                             |
| `scenario`    | string   | Nein   | Hinweis zur Videoart (nur als Hinweis, der AI-Regisseur entscheidet weiterhin über die endgültige Struktur): `auto` (Standard) / `narrated` (mehrere Szenen mit echten Fotos + Voiceover + Datenkarte) / `drama` (Charaktere + Dialoge in einem Kurzdrama) / `avatar` (digitale Person / Sprachübertragung, muss mit `file_urls` übermittelt werden) / `motion` (abstrakte dynamische Untertitel / Daten / Logo-Animation) / `slideshow` (Präsentation / Roadshow-Deck).                               |
| `style`       | string   | Nein   | Voreinstellung des visuellen Stils: `auto` (Standard) / `cinematic` / `glass` / `luxury` / `swiss` / `modern` / `editorial` / `warm` / `vibrant` / `neon` / `mono` / `pastel` / `bold` / `industrial` / `futuristic` / `retro`, akzeptiert auch Freitext als weichen Hinweis. Steht orthogonal zu `scenario`, ändert die Route nicht. |
| `voice`       | string   | Nein   | Stimme für das Voiceover (sprachunabhängig, über Sprachen hinweg verwendbar): `auto` (Standard) / `warm-female` / `bright-female` / `anchor-female` / `clean-female` / `calm-male` / `deep-male` / `documentary-male` / `energetic-male` / `storyteller-male`.                                    |

Hier ist ein konkretes Beispiel zur Veranschaulichung. Angenommen, wir möchten ein zweisprachiges, vertikales, 20-sekündiges Wissenschaftsvideo generieren, der entsprechende CURL-Code lautet wie folgt:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "Erklären Sie in 20 Sekunden, was eine Vektordatenbank ist, geeignet für Zuschauer ohne Vorkenntnisse, und geben Sie am Ende einen Merksatz.",
  "langs": ["zh-cn", "en"],
  "aspect": "9:16",
  "duration": 20
}'
```

Der entsprechende Python-Code lautet wie folgt:
```python
import requests

url = "https://api.acedata.cloud/maestro/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "prompt": "Erkläre in 20 Sekunden, was eine Vektordatenbank ist, geeignet für Zuschauer ohne Vorkenntnisse, am Ende einen einprägsamen Satz geben",
    "langs": ["zh-cn", "en"],
    "aspect": "9:16",
    "duration": 20
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Wenn Sie auf Ausführen klicken, werden Sie sofort ein Ergebnis erhalten, wie folgt:

```json
{
  "success": true,
  "task_id": "f57e99c4f60f4373a15517742ce2357d",
  "trace_id": "70e1cb12-c619-4292-a416-90191205996b"
}
```

Die Felder der Rückgabeergebnisse sind wie folgt beschrieben:

- `success`: Ob die Aufgabe erfolgreich eingereicht wurde.
- `task_id`: Die ID der Videoerzeugungsaufgabe, die später zur Abfrage der Ergebnisse über die [Maestro Task Query API](development_maestro_tasks.md) verwendet wird.
- `trace_id`: Die Verfolgungs-ID dieser Anfrage, die bei Problemen dem technischen Support zur Lokalisierung bereitgestellt werden kann.

Da die Videoerstellung länger dauert, gibt die Schnittstelle hier **sofort `task_id` zurück** und wartet nicht, bis das Video gerendert ist. Als nächstes müssen Sie `task_id` verwenden, um die Ergebnisse abzufragen, siehe Abschnitt „Ergebnisse abrufen“.

## Bestimmen des Videoformats und -stils (Szenario / Stil)

Wenn `scenario` nicht übergeben wird, wird es von der KI automatisch bestimmt (entspricht `auto`); wenn Sie das Video auf einen bestimmten Typ festlegen möchten, geben Sie es explizit an. Zum Beispiel, um ein **Hochformat-Kurzdrama** zu erstellen, können Sie die folgenden Inhalte angeben:

- `scenario`: Videoformat, hier auf `drama` (Charaktere + Dialoge des Kurzdramas) gesetzt.
- `style`: Visueller Stil, hier auf `cinematic` (filmische Qualität) gesetzt.

Ein Beispiel für den CURL-Code sieht wie folgt aus:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "Zwei Mitbewohner streiten sich wegen einer Katze und versöhnen sich wieder, drei Akte mit Wendungen, das Ende ist warmherzig",
  "scenario": "drama",
  "style": "cinematic",
  "aspect": "9:16",
  "duration": 40
}'
```

Häufige Kombinationen:

- Kurzdrama: `scenario: "drama"` (Charaktere + Dialoge).
- Digitale Menschen / Voiceover: `scenario: "avatar"` und über `file_urls` ein Porträt übergeben.
- Dynamische Untertitel / Datenanimation: `scenario: "motion"`; Präsentation / Roadshow: `scenario: "slideshow"`.
- `style` ist eine visuelle Stilvorgabe (z. B. `modern` / `neon` / `luxury`), ändert nicht den Typ, beeinflusst nur die Wahrnehmung.
- `voice` wird verwendet, um den Erzählton anzugeben (z. B. `warm-female` / `deep-male`), unabhängig von der Sprache, sprachübergreifend.

Die Rückgabeergebnisse sind wie bei „Grundlegende Nutzung“ identisch, ebenfalls wird sofort `task_id` zurückgegeben.

## Mehrsprachige Ausgabe

Indem Sie mehrere Sprachen in `langs` übergeben, können Sie gleichzeitig mehrsprachige Versionen erstellen. Die erste Sprache ist die Hauptsprache, jede zusätzliche Sprache wird **mit demselben Bildmaterial wiederverwendet**, nur mit zusätzlicher Vertonung + Rendering, daher **kostet jede zusätzliche Sprache nur +6 Punkte**. Beispiel:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "Stellen Sie unser intelligentes Kundenservicetool vor und heben Sie 3 Kernmerkmale hervor",
  "langs": ["zh-cn", "en", "ja"],
  "aspect": "16:9",
  "duration": 30
}'
```

Nach Abschluss der Aufgabe wird jede Sprache einem `variant` im Ergebnis entsprechen (siehe [Maestro Task Query API](development_maestro_tasks.md)).

## Iteration über bestehende Videos (Remix / Bearbeiten / Erweitern)

Geben Sie `action` und die `ref_task_id` der letzten Aufgabe ein, um auf der Grundlage des ursprünglichen Projekts differenzierte Änderungen vorzunehmen (z. B. „Ändern Sie den Titel des 2. Aktes“ „Ändern Sie die Vertonung“ „Gesamtes Bild dunkler machen“). Kleine Änderungen sind schnell, große Änderungen werden neu gemacht:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "remix",
  "ref_task_id": "f57e99c4f60f4373a15517742ce2357d",
  "prompt": "Ändern Sie den Eröffnungstitel in einen eindrucksvolleren Satz, die gesamte Farbgebung etwas dunkler"
}'
```

- `remix`: Neuinterpretation der ursprünglichen Videostruktur (Thema beibehalten, Darstellung anpassen).
- `edit`: Feinschliff an bestimmten Teilen (z. B. Titel ändern, Vertonung ändern, Farbkorrektur).
- `extend`: Erweiterung des Inhalts auf der Grundlage des ursprünglichen Videos.

Die Rückgabeergebnisse sind ebenfalls sofort ein neuer `task_id`, mit dem Sie die Ergebnisse der Iteration abrufen können.

## Ergebnisse abrufen

Da die Videoerstellung länger dauert, gibt diese Schnittstelle nach der Einreichung sofort `task_id` zurück, die Sie verwenden müssen, um die Ergebnisse über die [Maestro Task Query API](development_maestro_tasks.md) abzufragen:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d"
}'
```

Wenn die Aufgabe abgeschlossen ist, werden die Informationen zum Endprodukt zurückgegeben (jede Sprache entspricht einem `variant`). `status` wird `pending → planning → producing → succeeded` (oder `failed`) durchlaufen, **Abfragen sind kostenlos und verbrauchen keine Punkte**. Für das vollständige Antwortformat und die Abfrage der Historie siehe die [Anleitung zur Integration der Maestro Task Query API](development_maestro_tasks.md).

## Abrechnung

**Die Abrechnung erfolgt nach tatsächlichem Endprodukt, fehlgeschlagene Aufgaben werden nicht berechnet.** Die Abrechnung erfolgt basierend auf der tatsächlichen Dauer des gelieferten Endprodukts und der tatsächlichen Anzahl der produzierten Sprachen – zum Beispiel, wenn 600 Sekunden angefordert werden, aber das endgültige Produkt 50 Sekunden beträgt, wird nur für etwa 50 Sekunden abgerechnet; wenn eine Sprache letztendlich nicht produziert wird, wird auch keine zusätzliche Gebühr von +6 für diese Sprache erhoben. Die Einreichung der Aufgabe selbst wird nicht separat berechnet (Ergebnisse können kostenlos über `/maestro/tasks` abgefragt werden).

Die Punkte für ein einzelnes Endprodukt werden ungefähr nach folgender Formel geschätzt:

```
Punkte ≈ 0.85 × Dauer des Endprodukts in Sekunden × Qualitätsmultiplikator × Szenenmultiplikator + 6 × max(Anzahl der Sprachen − 1, 0)
```

- Qualitätsmultiplikator: `draft` 0.5× / `standard` 1× (Standard) / `premium` 2×.
- Szenenmultiplikator: `drama` 1.35× / `avatar` 1.15× / andere 1×.

Beispiel für Standardqualität, kein Kurzdrama / digitale Menschen, eine Sprache, die Punkte für unterschiedliche Endproduktlängen ungefähr betragen: 
```
| Dauer des Films                  | Standardpunktzahl |
| --------------------------- | ----- |
| 30s                         | 25.5  |
| 60s                         | 51    |
| 120s (2 Minuten)                  | 102   |
| 300s (5 Minuten)                  | 255   |
| 600s (10 Minuten, Obergrenze)      | 510   |
| Jede zusätzliche Sprache (`langs` über 1) | +6    |
| `/maestro/tasks` Abfrage         | Kostenlos    |

## Fehlerbehandlung

Bei der API-Nutzung, wenn ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die Informationen zurück. Zum Beispiel:

- `400 invalid_request`: Ungültige Anfrage, möglicherweise aufgrund eines fehlenden `prompt` oder ungültiger Parameter.
- `401 invalid_token`: Unbefugt, ungültiges oder fehlendes Autorisierungstoken.
- `403 forbidden`: Verboten, unzureichendes Guthaben oder Zugriff.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Rate-Limit überschritten.
- `500 api_error`: Interner Serverfehler, etwas ist auf dem Server schiefgelaufen.

### Beispiel für eine Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "Abruf fehlgeschlagen"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
