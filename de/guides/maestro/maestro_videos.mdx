Maestro ist eine **Agent-native** Video-Produktionsschnittstelle: Sie beschreiben das gewünschte Video mit einem natürlichen Sprach-`prompt` (optional mit `file_urls` zur Bereitstellung von Referenzbildern / Videos / Audios), und ein kopfloser „AI-Regisseur“ erledigt automatisch die Themenwahl, das Schreiben des Skripts, die Erstellung der Bilder, die Vertonung, die Musikuntermalung, die Komposition und das Rendering, um schließlich ein fertiges Video mit Untertiteln zu produzieren und es auf das CDN hochzuladen.

Dieser Artikel wird die Integrationsanleitung der Maestro Video-Generierungs-API im Detail vorstellen, um Ihnen zu helfen, diese API schnell zu integrieren und ihre Fähigkeiten voll auszuschöpfen.

Dies ist eine **asynchrone Aufgaben**-Schnittstelle: Nach der Einreichung wird sofort eine `task_id` zurückgegeben, und anschließend können Sie über die [Maestro Aufgabenabfrage-API](development_maestro_tasks.md) (`POST /maestro/tasks`) die Ergebnisse abfragen (Abfragen sind kostenlos und werden nicht berechnet). Um auf einem vorhandenen Video weiterzuarbeiten, können Sie `action: remix` / `edit` / `extend` zusammen mit `ref_task_id` verwenden.

## Antragsprozess

Um die Maestro Video-Generierungs-API zu nutzen, müssen Sie zunächst im [Ace Data Cloud Dashboard](https://platform.acedata.cloud/console/applications) Ihr API-Token abrufen und für zukünftige Verwendung aufbewahren.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, die Sie zur Registrierung und Anmeldung einlädt. Nach Abschluss werden Sie automatisch zur aktuellen Seite zurückgeleitet.

**Ein API-Token reicht aus, um auf alle Dienste der Plattform zuzugreifen, ohne dass für jeden Dienst separat beantragt werden muss.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, um es kostenlos auszuprobieren; wenn das Kontingent erschöpft ist, können Sie im [Dashboard](https://platform.acedata.cloud/console/coin) Ihr Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Maestro Video-Generierungs-API →](https://platform.acedata.cloud/documents/maestro-videos)

## Grundlegende Nutzung

`POST https://api.acedata.cloud/maestro/videos`

Die grundlegendste Verwendung erfordert nur die Übermittlung eines natürlichen Sprach-`prompt`, und der AI-Regisseur entscheidet automatisch über das Skript, die Bilder, die Vertonung und den Schnitt. Hier erfahren wir zunächst, welche Header und den Body der Anfrage gesetzt werden müssen.

**Request Headers** umfassen:

- `accept`: In welchem Format Sie die Antwort erhalten möchten, hier als `application/json`, also im JSON-Format.
- `authorization`: Der Schlüssel zur API, den Sie nach der Beantragung direkt auswählen können.
- `content-type`: Das Format des Anfragekörpers, hier als `application/json`.

**Request Body** umfasst hauptsächlich:

- `prompt`: Beschreiben Sie das Video in natürlicher Sprache (Thema, was gezeigt werden soll, Stil, Zielgruppe).
- `langs`: Array der Ausgabesprachen, wie `["zh-cn", "en"]`, standardmäßig `["zh-cn"]`.
- `aspect`: Bildverhältnis, `9:16` (Standard) / `16:9` / `1:1`.
- `duration`: Zielzeitdauer (Sekunden), standardmäßig 30.

Die vollständigen Felder des Anfragekörpers sind in der folgenden Tabelle dargestellt:

| Feld            | Typ       | Pflicht  | Beschreibung                                                                                                                                                                                                                           |
| ------------- | -------- | --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`      | string   | Ja   | Beschreiben Sie das Video in natürlicher Sprache (Thema, was gezeigt werden soll, Stil, Zielgruppe). Skript, Bilder, Vertonung und Schnitt werden vom AI entschieden.                                                                                                                                                                             |
| `action`      | string   | Nein   | `generate` (Standard, neues Video generieren) / `remix` / `edit` / `extend` (Iterieren auf einem vorhandenen Video, muss mit `ref_task_id` kombiniert werden).                                                                                                                                                |
| `ref_task_id` | string   | Nein   | Muss ausgefüllt werden, wenn `action` remix / edit / extend ist: `task_id` der historischen Aufgabe, die als Ausgangspunkt dient.                                                                                                                                                                   |
| `file_urls`   | string[] | Nein   | Referenzmedien (Bilder / Videos / Audio-URLs), z. B. Produktbilder, Logos oder Materialabschnitte, die untertitelt werden sollen.                                                                                                                                                                             |
| `langs`       | string[] | Nein   | Ausgabesprachen, wie `["zh-cn", "en"]`, standardmäßig `["zh-cn"]`. Die erste Sprache ist die Hauptsprache; für jede zusätzliche Sprache wird das Bild wiederverwendet, es gibt nur zusätzliche Vertonung + Rendering, **jede zusätzliche +6 Punkte**.                                                                                                                                          |
| `aspect`      | string   | Nein   | `9:16` (Standard) / `16:9` / `1:1`. Lite gibt 720p/24fps aus, Standard und Pro geben 1080p/30fps aus.                                                                                                                                                  |
| `duration`    | int      | Nein   | Zielzeitdauer (Sekunden), standardmäßig 30. Lite für **5–30 Sekunden**, Standard für **5–120 Sekunden**, Pro für **5–300 Sekunden**. Abgerechnet wird nach der tatsächlichen Videolänge, jedoch nicht mehr als die angeforderte Länge.                                                                                                                                 |
| `quality`     | string   | Nein   | Produktionsstufe: `lite` (schnelle Kurzvideos, 0.20 Punkte/Sekunde) / `standard` (Standard, ausgewogene Produktion, 0.60 Punkte/Sekunde) / `pro` (hochwertige Produktion, 1.20 Punkte/Sekunde).                                                                                                                                           |
| `scenario`    | string   | Nein   | Videoart: Lite unterstützt `auto` / `narrated` / `captions`; Standard fügt `avatar` hinzu; Pro fügt `drama` hinzu. `captions` erfordert das Quellvideo, `avatar` erfordert ein Porträt.                                                                                                             |
| `style`       | string   | Nein   | Voreinstellung des visuellen Stils: `auto` (Standard) / `cinematic` / `glass` / `luxury` / `swiss` / `modern` / `editorial` / `warm` / `vibrant` / `neon` / `mono` / `pastel` / `bold` / `industrial` / `futuristic` / `retro`, akzeptiert auch Freitext als weichen Hinweis. Ist orthogonal zu `scenario` und ändert die Route nicht. |
| `voice`       | string   | Nein   | Erzählstimme (sprachunabhängig, über Sprachen hinweg verwendbar): `auto` (Standard) / `warm-female` / `bright-female` / `anchor-female` / `clean-female` / `calm-male` / `deep-male` / `documentary-male` / `energetic-male` / `storyteller-male`.                                    |

Hier ist ein konkretes Beispiel zur Veranschaulichung. Angenommen, wir möchten ein zweisprachiges, vertikales, 20-sekündiges Wissenschaftsvideo generieren, der entsprechende CURL-Code lautet:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "Erklären Sie in 20 Sekunden, was eine Vektordatenbank ist, geeignet für Zuschauer ohne Vorkenntnisse, und geben Sie am Ende einen einprägsamen Punkt an.",
  "langs": ["zh-cn", "en"],
  "aspect": "9:16",
  "duration": 20
}'
```

Der entsprechende Python-Code lautet:
```python
import requests

url = "https://api.acedata.cloud/maestro/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "prompt": "Erkläre in 20 Sekunden, was eine Vektordatenbank ist, geeignet für Zuschauer ohne Vorkenntnisse, am Ende einen einprägsamen Satz geben",
    "langs": ["zh-cn", "en"],
    "aspect": "9:16",
    "duration": 20
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Klicke auf Ausführen, um sofort ein Ergebnis zu erhalten, wie folgt:

```json
{
  "success": true,
  "task_id": "f57e99c4f60f4373a15517742ce2357d",
  "trace_id": "70e1cb12-c619-4292-a416-90191205996b"
}
```

Die Felder der Rückgabeergebnisse sind wie folgt beschrieben:

- `success`: Ob die Aufgabe erfolgreich eingereicht wurde.
- `task_id`: Die ID der Videoerzeugungsaufgabe, die später zur Abfrage der Ergebnisse über die [Maestro Task Query API](development_maestro_tasks.md) verwendet wird.
- `trace_id`: Die Verfolgungs-ID dieser Anfrage, die bei Problemen dem technischen Support zur Verfügung gestellt werden kann.

Da die Videoerstellung länger dauert, gibt die Schnittstelle hier **sofort `task_id`** zurück und wartet nicht, bis das Video gerendert ist. Als Nächstes muss `task_id` verwendet werden, um die Ergebnisse abzufragen, siehe Abschnitt „Ergebnisse abrufen“.

## Bestimmen des Videoformats und -stils (Szenario / Stil)

Wenn `scenario` nicht übergeben wird, entscheidet die KI automatisch (entspricht `auto`); wenn das Video auf einen bestimmten Typ festgelegt werden soll, muss dies explizit übergeben werden. Zum Beispiel, um ein **Hochformat-Kurzdrama** zu erstellen, kann der folgende Inhalt angegeben werden:

- `scenario`: Videoformat, hier auf `drama` (Charaktere + Dialoge des Kurzdramas) gesetzt.
- `style`: Visueller Stil, hier auf `cinematic` (filmische Qualität) gesetzt.

Ein Beispiel für den CURL-Code sieht wie folgt aus:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "Zwei Mitbewohner streiten sich wegen einer Katze und versöhnen sich wieder, drei Akte mit Wendungen, das Ende ist warmherzig",
  "scenario": "drama",
  "style": "cinematic",
  "aspect": "9:16",
  "duration": 40
}'
```

Häufige Kombinationen:

- Erklärvideo: `scenario: "narrated"`, Lite / Standard / Pro unterstützen alle.
- Automatische Untertitel: `scenario: "captions"`, erfordert `file_urls`, um das Quellvideo zu übergeben, Lite / Standard / Pro unterstützen alle.
- Digitale Menschen / Sprachübertragung: `scenario: "avatar"`, erfordert `file_urls`, um ein Porträt zu übergeben, Standard / Pro unterstützen.
- Kurzdrama: `scenario: "drama"` (Charaktere + Dialoge), nur Pro unterstützt.
- `style` ist eine visuelle Stilvorgabe (z. B. `modern` / `neon` / `luxury`), ändert nicht den Typ, beeinflusst nur die Wahrnehmung.
- `voice` wird verwendet, um den Erzählton anzugeben (z. B. `warm-female` / `deep-male`), unabhängig von der Sprache, sprachübergreifend.

Die Rückgabeergebnisse sind identisch mit denen der „Grundlegenden Nutzung“ und geben ebenfalls sofort `task_id` zurück.

## Mehrsprachige Ausgabe

Indem mehrere Sprachen in `langs` übergeben werden, können mehrere Sprachversionen auf einmal erstellt werden. Die erste Sprache ist die Hauptsprache, jede zusätzliche Sprache wird **mit demselben Bildmaterial** wiederverwendet, nur die Sprachaufnahme + das Rendering werden zusätzlich durchgeführt, daher **kostet jede zusätzliche Sprache nur +6 Punkte**. Beispiel:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "Stelle unser intelligentes Kundenservice-Produkt vor und hebe 3 zentrale Verkaufsargumente hervor",
  "langs": ["zh-cn", "en", "ja"],
  "aspect": "16:9",
  "duration": 30
}'
```

Nach Abschluss der Aufgabe wird jede Sprache einem `variant` im Ergebnis zugeordnet (siehe [Maestro Task Query API](development_maestro_tasks.md)).

## Iteration über vorhandene Videos (Remix / Bearbeiten / Erweitern)

Durch die Übergabe von `action` und der `ref_task_id` der letzten Aufgabe können differenzierte Änderungen auf der Grundlage des ursprünglichen Projekts vorgenommen werden (z. B. „Ändere den Titel des 2. Aktes“ oder „Wechsle die Sprachaufnahme“ oder „Dunkle das Gesamtbild ab“). Kleine Änderungen sind schnell, große Änderungen erfordern eine Neugestaltung:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "remix",
  "ref_task_id": "f57e99c4f60f4373a15517742ce2357d",
  "prompt": "Ändere den Eröffnungstitel in einen eindrucksvolleren Satz, die Gesamtfarbgebung sollte dunkler sein"
}'
```

- `remix`: Neuinterpretation der ursprünglichen Video-Struktur (Thema beibehalten, Darstellung anpassen).
- `edit`: Feinarbeit an einem bestimmten Teil (z. B. Titel ändern, Sprachaufnahme ändern, Farbkorrektur).
- `extend`: Erweiterung des Inhalts auf der Grundlage des ursprünglichen Videos.

Die Rückgabeergebnisse geben ebenfalls sofort eine neue `task_id` zurück, mit der die iterierte Endversion abgerufen werden kann.

## Ergebnisse abrufen

Da die Videoerstellung länger dauert, gibt diese Schnittstelle nach der Einreichung sofort `task_id` zurück, die zur Abfrage der Ergebnisse über die [Maestro Task Query API](development_maestro_tasks.md) verwendet werden muss:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d"
}'
```

Wenn die Aufgabe abgeschlossen ist, werden die Informationen zum Endprodukt zurückgegeben (jede Sprache entspricht einem `variant`). `status` wird `pending → planning → producing → succeeded` (oder `failed`) durchlaufen, **Abfragen sind kostenlos und verbrauchen keine Punkte**. Für das vollständige Antwortformat und die Abfrage der Historie siehe die [Maestro Task Query API Integrationsanleitung](development_maestro_tasks.md).

## Abrechnung

**Die Abrechnung erfolgt nach tatsächlicher Fertigstellung des Endprodukts, fehlgeschlagene Aufgaben werden nicht berechnet.** Die Abrechnung erfolgt basierend auf der tatsächlichen Dauer des gelieferten Endprodukts und der Anzahl der Sprachen, und die Abrechnungsdauer überschreitet nicht die angeforderte Dauer. Wenn eine Sprache letztendlich nicht produziert wird, wird auch keine zusätzliche Gebühr von +6 Punkten für diese Sprache erhoben. Die Einreichung der Aufgabe selbst wird nicht separat berechnet, die Abfrage über `/maestro/tasks` ist kostenlos.

Die Punkte für ein einzelnes Endprodukt werden nach folgender Formel berechnet:

```
Punkte = Dauer des Endprodukts in Sekunden × SKU Preis pro Sekunde × Szenenmultiplikator + 6 × max(Anzahl der Sprachen − 1, 0)
```
| SKU        |    Preis pro Sekunde |  Maximale Dauer | Ausgabe             | Szenen und Aktionen                           |
| ---------- | ------: | ----: | ----------------- | ------------------------------------ |
| `lite`     | 0.20 Punkte |  30 Sekunden | 720p / 24fps      | auto, narrativ, Untertitel; generieren, bearbeiten |
| `standard` | 0.60 Punkte | 120 Sekunden | 1080p / 30fps     | Avatar hinzufügen; Remix hinzufügen                   |
| `pro`      | 1.20 Punkte | 300 Sekunden | 1080p / 30fps hohe Bitrate | Drama hinzufügen; erweitern hinzufügen                   |

Szenenmultiplikatoren: `drama` 1.35× / `avatar` 1.15× / andere 1×.

| Beispiel                  |  Punkte |
| ------------------- | --: |
| Lite 30 Sekunden           |   6 |
| Standard 30 Sekunden       |  18 |
| Standard 60 Sekunden       |  36 |
| Standard 120 Sekunden      |  72 |
| Pro 30 Sekunden            |  36 |
| Pro 300 Sekunden           | 360 |
| Jede zusätzliche tatsächlich gelieferte Sprache          |  +6 |
| `/maestro/tasks` Abfrage |  Kostenlos |

## Fehlerbehandlung

Bei der API-Anruf, wenn ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die Informationen zurück. Zum Beispiel:

- `400 invalid_request`: Ungültige Anfrage, möglicherweise aufgrund eines fehlenden `prompt` oder ungültiger Parameter.
- `401 invalid_token`: Unbefugt, ungültiges oder fehlendes Autorisierungstoken.
- `403 forbidden`: Verboten, unzureichendes Guthaben oder Zugriff.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Rate-Limit überschritten.
- `500 api_error`: Interner Serverfehler, etwas ist auf dem Server schiefgelaufen.

### Fehlerantwort Beispiel

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "Abruf fehlgeschlagen"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
