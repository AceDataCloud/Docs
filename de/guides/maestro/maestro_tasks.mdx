Die Hauptfunktion der Maestro Aufgabenabfrage API besteht darin, den Ausführungsstatus und das Endergebnis einer Aufgabe abzufragen, die durch die [Maestro Videoerzeugungs-API](development_maestro_videos.md) (`POST /maestro/videos`) zurückgegebene Aufgaben-ID identifiziert wird.

Dieses Dokument beschreibt detailliert die Integrationsanleitung für die Maestro Aufgabenabfrage API. Da die Videoerzeugung eine asynchrone Aufgabe ist, muss nach der Einreichung dieser Schnittstelle verwendet werden, um den Fortschritt und das Endprodukt abzufragen. **Die Abfrage ist kostenlos und verbraucht keine Punkte.**

`POST https://api.acedata.cloud/maestro/tasks`

## Antragsprozess

Um die Maestro Aufgabenabfrage API zu verwenden, müssen Sie zunächst Ihr API-Token im [Ace Data Cloud Dashboard](https://platform.acedata.cloud/console/applications) abrufen und für zukünftige Verwendung aufbewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss werden Sie automatisch zur aktuellen Seite zurückgeleitet.

**Ein API-Token reicht aus, um auf alle Dienste der Plattform zuzugreifen, es ist nicht erforderlich, für jeden Dienst separat zu beantragen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, um es kostenlos auszuprobieren; wenn das Kontingent erschöpft ist, können Sie im [Dashboard](https://platform.acedata.cloud/console/coin) Ihr allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Maestro Aufgabenabfrage API →](https://platform.acedata.cloud/documents/maestro-tasks)

## Abfrage einer einzelnen Aufgabe

Wie man eine Videoaufgabe erstellt, erfahren Sie im Dokument [Maestro Videoerzeugungs-API](development_maestro_videos.md). Wir verwenden eine von ihr zurückgegebene Aufgaben-ID als Beispiel: `f57e99c4f60f4373a15517742ce2357d`, um zu demonstrieren, wie man ihren Status und ihr Ergebnis abfragt.

### Anfrageheader und Anfragekörper festlegen

**Request Headers** umfassen:

- `accept`: Gibt an, dass die Antwort im JSON-Format empfangen werden soll, hier eingetragen als `application/json`.
- `authorization`: Der Schlüssel zur API, der nach der Beantragung direkt ausgewählt werden kann.
- `content-type`: Das Format des Anfragekörpers, hier eingetragen als `application/json`.

**Request Body** umfasst:

| Feld       | Typ     | Pflicht  | Beschreibung                                          |
| -------- | ------ | --- | ------------------------------------------------- |
| `id`     | string | Ja   | `task_id`, das von `POST /maestro/videos` zurückgegeben wird              |
| `action` | string | Nein  | `retrieve` (Standard, Abfrage einer einzelnen Aufgabe) / `retrieve_batch` (Abfrage der Liste historischer Aufgaben) |

### Codebeispiel

Der entsprechende CURL-Code lautet wie folgt:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Der entsprechende Python-Code lautet wie folgt:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Beispielantwort

Nach erfolgreicher Anfrage gibt die API den Status und das Ergebnis dieser Videoaufgabe zurück. Ein Beispiel für die Rückgabe, wenn die Aufgabe abgeschlossen ist, sieht wie folgt aus (jede Sprache entspricht einem `variant`):

```json
    "langs": [

      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }
  }

```

Die Beschreibung der Rückgabefelder lautet wie folgt:

- `id`: Die ID dieser Videoaufgabe, die zur eindeutigen Identifizierung dieser Videoerzeugungsaufgabe dient.
- `status`: Der Status der Aufgabe, Werte sind `pending → planning → producing → succeeded` (oder `failed`). Ob die Aufgabe abgeschlossen ist, wird durch den obersten `status` bestimmt.
- `elapsed`: Die bereits vergangene Zeit der Aufgabe (in Sekunden).
- `progress`: Oberstes Fortschrittsobjekt, `percent` (0–100) wird nach erfolgreichem Abschluss auf 100 gesetzt; `stage` und `message` spiegeln das zuletzt gemeldete Fortschrittsereignis des KI-Regisseurs wider (daher kann `stage` nach dem Erfolg weiterhin die letzte ausgeführte Phase wie `producing` sein), und kann direkt zur Anzeige eines Fortschrittsbalkens verwendet werden.
- `request`: Der Anfragekörper zum Zeitpunkt der Aufgabenstellung.
- `response`: Die Rückgabedaten der Aufgabe.
  - `success`: Ob die Aufgabe erfolgreich war.
  - `data.variants`: Jedes Sprachvariant entspricht einem Endproduktobjekt, das `lang`, `aspect`, `title`, `output_url` (Downloadlink des Endprodukts) usw. enthält.
  - `data.project`: Das gesamte Projektprodukt, das `tarball_url` (Projektpaket) und `outputs` (alle Endproduktlinks) enthält.
  - `data.progress`: Ein Array von Fortschrittsereignissen, die nach Phasen hinzugefügt werden (append-only Protokoll), das zur Anzeige detaillierter Echtzeitfortschritte verwendet werden kann.
- `created_at`: Erstellungszeit der Aufgabe, Unix-Zeitstempel (in Sekunden).
- `started_at`: Zeit, zu der die Aufgabe zu laufen begann, Unix-Zeitstempel (in Sekunden). Wenn die Aufgabe noch nicht begonnen hat, ist dies null.
- `finished_at`: Zeit, zu der die Aufgabe abgeschlossen wurde, Unix-Zeitstempel (in Sekunden). Wenn die Aufgabe nicht abgeschlossen ist, ist dies null.

## Abfrage der Historienliste

Durch die Übermittlung von `action: retrieve_batch` können die letzten Aufgaben des aktuellen Benutzers (in umgekehrter Reihenfolge nach Erstellungszeit) abgerufen werden, die für die Seite „Meine Videos“ verwendet werden können.

**Request Body** umfasst:
| Feld               | Typ     | Pflicht  | Beschreibung                      |
| ---------------- | ------ | --- | ----------------------- |
| `action`         | string | Ja   | Festgelegt auf `retrieve_batch`    |
| `limit`          | int    | Nein  | Anzahl der zurückgegebenen Einträge, standardmäßig 20              |
| `created_at_max` | int    | Nein  | Gibt nur Aufgaben zurück, die vor diesem Unix-Zeitstempel liegen (für Paging) |
| `created_at_min` | int    | Nein  | Gibt nur Aufgaben zurück, die nach diesem Unix-Zeitstempel liegen      |

### Codebeispiel

Der entsprechende CURL-Code lautet wie folgt:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

## Polling-Empfehlung

Da die Videoproduktion zeitaufwändig ist, wird der `status` die Phasen `pending → planning → producing → succeeded` (oder `failed`) durchlaufen. Es wird empfohlen, alle 5–10 Sekunden zu pollieren, bis der `status` auf `succeeded` oder `failed` wechselt. Die oberste `progress.percent` kann verwendet werden, um einen Echtzeit-Fortschrittsbalken anzuzeigen. **Das Polling dieser Schnittstelle ist kostenlos und verbraucht keine Punkte.**

## Fehlerbehandlung

Wenn beim Aufruf der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die Fehlermeldung zurück. Zum Beispiel:

- `401 invalid_token`: Unbefugt, ungültiges oder fehlendes Autorisierungstoken.
- `404 not_found`: Aufgabe nicht gefunden, die angegebene task_id existiert nicht.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Rate-Limit überschritten.
- `500 api_error`: Interner Serverfehler, etwas ist auf dem Server schiefgelaufen.

### Fehlerantwortbeispiel

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
