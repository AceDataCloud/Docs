Dieser Artikel stellt eine Anleitung zur Integration der Veo Videos Generation API vor, mit der offizielle Veo-Videos durch die Eingabe benutzerdefinierter Parameter generiert werden können.

## Antragsprozess

Um die Veo Videos Generation API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihr API-Token zu erhalten und es als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen; es ist nicht erforderlich, für jeden Dienst separat einen Antrag zu stellen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, das kostenlos getestet werden kann; bei unzureichendem Kontingent können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Veo Videos Generation API →](https://platform.acedata.cloud/documents/veo-videos)

## Grundlegende Verwendung

Lernen wir zunächst die grundlegende Verwendung kennen: Durch die Eingabe des Prompt-Worts `prompt`, der Generierungsaktion `action`, des Referenzbild-Arrays für Anfangs- und Endframes `image_urls` sowie des Modells `model` können Sie das verarbeitete Ergebnis erhalten. Zunächst müssen Sie einfach ein Feld `action` übergeben, dessen Wert `text2video` ist. Es umfasst hauptsächlich drei Aktionen: Text-zu-Video (`text2video`), Bild-zu-Video (`image2video`) und Abrufen eines 1080p-Videos (`get1080p`). Anschließend müssen wir außerdem das Modell `model` eingeben. Derzeit gibt es hauptsächlich die Modelle `veo31-fast`, `veo3`, `veo31`, `veo3-fast` und `veo31-fast-ingredients`; die konkreten Inhalte sind wie folgt:

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

Hier sehen wir, dass wir die Request Headers festgelegt haben, einschließlich:

- `accept`: Welches Format das Antwortergebnis haben soll; hier wird `application/json` eingetragen, also das JSON-Format.
- `authorization`: Der Schlüssel zum Aufrufen der API, der nach der Beantragung direkt per Dropdown ausgewählt werden kann.

Zusätzlich wurden Request Body-Einstellungen vorgenommen, einschließlich:

- `model`: Das Modell zur Videogenerierung; hauptsächlich gibt es die Modelle `veo31-fast`, `veo3`, `veo31`, `veo3-fast` und `veo31-fast-ingredients`.
- `action`: Die Aktion dieser Videogenerierungsaufgabe umfasst hauptsächlich drei Aktionen: Text-zu-Video (`text2video`), Bild-zu-Video (`image2video`) und Abrufen eines 1080p-Videos (`get1080p`).
- `image_urls`: Wenn die Bild-zu-Video-Aktion `image2video` ausgewählt wird, muss ein Link zu einem hochzuladenden Referenzbild angegeben werden. `veo31-fast-ingredients` unterstützt maximal 3 Bilder (Mehrbildfusion), die übrigen Modelle maximal 2 Bilder (Anfangs- und Endframe-Modus).
- `resolution`: Auswahl der Auflösung des generierten Videos; das veo31-Modell unterstützt eine 4k-Auflösung, andere Modelle unterstützen diese nicht. Alle Modelle unterstützen sowohl 1080p als auch gif-Auflösung. Wenn dieser Wert nicht übergeben wird, wird standardmäßig die 720p-Auflösung verwendet. Hauptsächlich gibt es: `1080p`, `gif`, `4k`.
- `prompt`: Prompt-Wort.
- `callback_url`: Die URL, an die das Ergebnis zurückgemeldet werden soll.
- `async`: Optional; wenn auf `true` gesetzt, gibt die Schnittstelle sofort `task_id` zurück, ohne dass `callback_url` angegeben werden muss. Anschließend wird das Ergebnis durch Polling über die entsprechende Aufgabenabfrageschnittstelle abgerufen.

### 📌 Zusammenfassung der Modellbeschreibung

| **Modellname**                   | **Unterstützte Modi**                          | **Regeln für die Bildeingabe**                        |
| -------------------------- | --------------------------------- | --------------------------------- |
| **veo3-fast**              | Text-zu-Video (ohne Bild)<br />Bild-zu-Video-Modus (mit Bild)           | **1 Bild** → Anfangsframe-Modus<br />**2 Bilder** → Anfangs- und Endframe-Modus |
| **veo31-fast**             | Text-zu-Video (ohne Bild)<br />Bild-zu-Video-Modus (mit Bild)           | **1 Bild** → Anfangsframe-Modus<br />**2 Bilder** → Anfangs- und Endframe-Modus |
| **veo31-fast-ingredients** | ❌ Text-zu-Video (nicht unterstützt)<br />✅ **Erzwungene Mehrbildfusion** (Bilder müssen übergeben werden) | **1-3 Bilder** → Mehrbildfusionsmodus (maximal 3 Bilder)        |
| **veo3**                   | Text-zu-Video (ohne Bild)<br />Bild-zu-Video-Modus (mit Bild)           | **1 Bild** → Anfangsframe-Modus<br />**2 Bilder** → Anfangs- und Endframe-Modus |
| **veo31**                  | Text-zu-Video (ohne Bild)<br />Bild-zu-Video-Modus (mit Bild)           | **1 Bild** → Anfangsframe-Modus<br />**2 Bilder** → Anfangs- und Endframe-Modus |

---

### 🔑 Beschreibung der wichtigsten Regeln

1. **Allgemeine Logik**:
   - **Keine Bildeingabe** → Löst automatisch den Text-zu-Video-Modus aus.
   - **Bildeingabe vorhanden** → Löst den Bild-zu-Video-Modus aus (das konkrete Verhalten wird durch die Anzahl der Bilder bestimmt).
2. **Modustypen für Bild-zu-Video**:
   - **Anfangsframe-Modus** (1 Bild): Der Anfangsframe wird auf das Eingabebild festgelegt.
   - **Anfangs- und Endframe-Modus** (2 Bilder): Der Anfangs- und Endframe werden auf die Eingabebilder festgelegt.
   - **Mehrbildfusionsmodus** (1-3 Bilder): Wird nur von `veo31-fast-ingredients` unterstützt und generiert Videos durch die Fusion von Mehrbildinhalten.
3. **Modusklassifizierung**:

  - **Fast-Modus**: `veo3-fast`, `veo31-fast`, `veo31-fast-ingredients`.
   - **Quality-Modus**: `veo3`, `veo31` (höhere Generierungsqualität).

---

### ⚠️ Hinweise

- **Einziges Modell mit obligatorischer Bildübergabe**: `veo31-fast-ingredients` muss Bilder (1-3 Stück) übergeben bekommen, andernfalls kann es nicht ausgeführt werden.
- **Beschränkung der Bildanzahl**:
  - `veo31-fast-ingredients` unterstützt **1-3 Bilder** als Eingabe (Mehrbildfusionsmodus).
  - Andere Modelle unterstützen maximal **2 Bilder** als Eingabe (Anfangs- und Endframe-Modus).


## Bild-zu-Video-Funktion

Wenn Sie ein Video anhand von Bildern des ersten und letzten Frames generieren möchten, können Sie den Parameter `action` auf `image2video` setzen und das Link-Array `image_urls` für die Bilder des ersten und letzten Frames eingeben.

Als Nächstes müssen wir die Hinweise ausfüllen, die im nächsten Schritt erweitert werden müssen, um die Videogenerierung anzupassen. Dabei können die folgenden Inhalte angegeben werden:

- `model`: Das Modell zur Videogenerierung, hauptsächlich `veo31-fast`, `veo3`, `veo31`, `veo3-fast` und `veo31-fast-ingredients`.
- `image_urls`: Wenn die Bild-zu-Video-Aktion `image2video` ausgewählt wird, sind die hochzuladenden Referenzbildlinks erforderlich.
- `prompt`: Der Hinweistext.

Ein Ausfüllbeispiel lautet wie folgt:

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

Nach dem Ausfüllen wird der folgende Code automatisch generiert:

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

Der entsprechende Python-Code:

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo31-fast",
    "prompt": "Let it dance",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynchroner Rückruf

Da die Generierungszeit der Veo Videos Generation API relativ lang ist und etwa 1–2 Minuten benötigt, würde die HTTP-Anfrage bei einer langen Nichtreaktion der API die Verbindung dauerhaft aufrechterhalten, was zu zusätzlichem Verbrauch von Systemressourcen führt. Daher bietet diese API auch Unterstützung für asynchrone Rückrufe.

Der Gesamtprozess ist: Wenn der Client eine Anfrage initiiert, gibt er zusätzlich ein Feld `callback_url` an. Nachdem der Client die API-Anfrage initiiert hat, gibt die API sofort ein Ergebnis zurück, das ein Feld `task_id` enthält, welches die aktuelle Aufgaben-ID repräsentiert. Nachdem die Aufgabe abgeschlossen ist, wird das Ergebnis des generierten Videos in Form von POST JSON an die vom Client angegebene `callback_url` gesendet, wobei ebenfalls das Feld `task_id` enthalten ist. Auf diese Weise können die Aufgabenergebnisse über die ID verknüpft werden.

Im Folgenden erfahren wir anhand eines Beispiels, wie die konkrete Vorgehensweise aussieht.

Zunächst ist der Webhook-Rückruf ein Dienst, der HTTP-Anfragen empfangen kann. Entwickler sollten ihn durch die URL ihres selbst erstellten HTTP-Servers ersetzen. Zur leichteren Demonstration wird hier eine öffentliche Webhook-Beispielwebsite https://webhook.site/ verwendet. ## Fehlerbehandlung

Wenn bei der Aufrufung der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Information zurück. Zum Beispiel:

- `400 token_mismatched`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`：Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`：Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`：Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
