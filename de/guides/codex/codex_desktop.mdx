Codex Desktop verwendet die gleiche `~/.codex/config.toml` wie Codex CLI.

## 1. API-Schlüssel abrufen

Öffnen Sie die [Ace Data Cloud Anwendungsübersicht](https://platform.acedata.cloud/console/applications), gehen Sie zu einer verfügbaren Anwendung und kopieren Sie den API-Schlüssel.

![API-Schlüssel von Ace Data Cloud abrufen](https://cdn.acedata.cloud/dvc3cg.jpg)

## 2. API-Schlüssel festlegen

macOS：

```bash
launchctl setenv ACEDATACLOUD_API_KEY "Ihr API-Schlüssel"
```

Windows PowerShell：

```powershell
setx ACEDATACLOUD_API_KEY "Ihr API-Schlüssel"
```

## 3. AceDataCloud konfigurieren

Bearbeiten Sie `~/.codex/config.toml` (unter Windows `%USERPROFILE%\.codex\config.toml`), fügen Sie hinzu:

```toml
model_provider = "acedatacloud"

[model_providers.acedatacloud]
name = "acedatacloud"
base_url = "https://api.acedata.cloud/v1"

[model_providers.acedatacloud.auth]
command = "sh"
args = ["-c", "echo $ACEDATACLOUD_API_KEY"]
```

Ändern Sie unter Windows die letzten beiden Zeilen in:

```toml
command = "powershell"
args = ["-NoProfile", "-Command", "Write-Output $env:ACEDATACLOUD_API_KEY"]
```

Es ist nicht erforderlich, `model` auszufüllen; wählen Sie das Modell direkt nach dem Öffnen von Codex aus.

## 4. Neustart und Überprüfung

Beenden Sie Codex Desktop vollständig und öffnen Sie es erneut, erstellen Sie eine lokale Aufgabe und senden Sie eine einfache Nachricht. Der Provider sollte als `acedatacloud` angezeigt werden; echte Aufrufe können in der [Nutzungsverlauf](https://platform.acedata.cloud/console/usages) eingesehen werden.

Wenn die Konfiguration nicht wirksam wird, stellen Sie sicher, dass Sie die `~/.codex/config.toml` des aktuellen Benutzers geändert haben, die Umgebungsvariable gesetzt ist und starten Sie die Anwendung erneut vollständig neu. Cloud-Aufgaben oder Automatisierungen, die in unterschiedlichen Umgebungen ausgeführt werden, müssen den Schlüssel separat in der entsprechenden Umgebung konfigurieren.
