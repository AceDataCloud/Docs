Codex ist ein von OpenAI entwickelter Programmier-Agent. Neben dem CLI-Terminal bietet er auch eine VS Code-Erweiterung, mit der man im Editor-Seitenbereich chatten, Dateien lesen, Kontext referenzieren, Änderungen generieren und Vorschauen anzeigen kann.

Dieser Artikel beschreibt, wie man über den OpenAI Responses-kompatiblen Proxy von Ace Data Cloud die Codex-Erweiterung in VS Code konfiguriert und verwendet. Die Codex VS Code-Erweiterung und das Codex CLI verwenden dasselbe lokale Konfigurationssystem. Wenn Sie also `~/.codex/config.toml` auf Ace Data Cloud verweisen, nutzt Codex in VS Code die URL `https://api.acedata.cloud/v1`.

## Anmeldeprozess

Um Codex zu verwenden, können Sie zunächst im [Ace Data Cloud Console](https://platform.acedata.cloud/console/applications) Ihren API-Token erhalten und für spätere Verwendung speichern.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach der Anmeldung kehren Sie automatisch zur aktuellen Seite zurück.

Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, um den Codex-Dienst kostenlos zu testen.

## Installation der Codex-Erweiterung

Suchen Sie im VS Code Erweiterungsmarkt nach `Codex` und installieren Sie die von OpenAI veröffentlichte **Codex - OpenAI's coding agent** Erweiterung. Die Marketplace-ID lautet:

```text
openai.chatgpt
```

Alternativ können Sie die Erweiterung auch über die Kommandozeile installieren:

```bash
code --install-extension openai.chatgpt
```

Nach der Installation starten Sie VS Code neu oder laden es neu. Falls Sie den Codex-Einstiegspunkt nicht sehen, öffnen Sie die Befehls-Palette (macOS: `Cmd+Shift+P`, Windows/Linux: `Ctrl+Shift+P`) und führen Sie aus:

```text
Codex: Open Codex Sidebar
```

Standardmäßig erscheint Codex in der rechten Seitenleiste von VS Code. Sie können es auch in die linke Activity Bar ziehen.

## Installation des Codex CLI (zur Verifikation)

Die offizielle Dokumentation erklärt, dass die Codex VS Code-Erweiterung und das Codex CLI dieselbe Konfigurationsebene verwenden. Um vor der Konfiguration von VS Code die Verfügbarkeit des API-Tokens und Modells zu prüfen, empfiehlt sich die Installation des Codex CLI.

Eine empfohlene Methode ist die Installation über npm, wobei Node.js 18 oder höher erforderlich ist:

```bash
npm install -g @openai/codex
```

macOS-Nutzer können alternativ Homebrew verwenden:

```bash
brew install --cask codex
```

Nach der Installation prüfen Sie im Terminal, ob der Befehl verfügbar ist:

```bash
codex --version
```

Wenn Sie nur die VS Code-Erweiterung verwenden möchten, können Sie diesen Schritt überspringen; die Konfiguration erfolgt weiterhin über dieselbe `~/.codex/config.toml`.

## Konfiguration der Ace Data Cloud API

Die Codex VS Code-Erweiterung und das Codex CLI teilen sich die Konfigurationsdatei. Standardmäßig fordert Codex zur Anmeldung mit einem offiziellen OpenAI-Konto oder zur Eingabe eines offiziellen API-Schlüssels auf. Um stattdessen Ace Data Cloud zu verwenden, müssen Sie den API-Token und `~/.codex/config.toml` konfigurieren.

### Schritt 1: Umgebungsvariable setzen

Es wird empfohlen, den API-Token in der Shell-Konfigurationsdatei zu speichern, z. B. in `~/.zshrc`, `~/.bashrc` oder `~/.bash_profile`:

```bash
export ACEDATACLOUD_API_KEY="{token}"
```

Ersetzen Sie `{token}` durch den API-Token, den Sie aus der Ace Data Cloud Console kopiert haben.

Öffnen Sie anschließend das Terminal neu oder führen Sie den entsprechenden `source`-Befehl aus, damit die Änderung sofort wirksam wird:

```bash
source ~/.zshrc
```

Wenn VS Code bereits geöffnet ist, starten Sie es neu oder laden es neu, damit die Erweiterung die neue Umgebungsvariable erkennt.

### Schritt 2: Codex-Konfigurationsdatei bearbeiten

Die benutzerspezifische Codex-Konfigurationsdatei befindet sich unter `~/.codex/config.toml`. Falls die Datei nicht existiert, können Sie sie neu anlegen:

```bash
mkdir -p ~/.codex
touch ~/.codex/config.toml
```

Fügen Sie folgende Konfiguration ein:

```toml
model_provider = "acedatacloud"
model = "gpt-5"
model_reasoning_effort = "high"
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[model_providers.acedatacloud]
name = "Ace Data Cloud"
base_url = "https://api.acedata.cloud/v1"
env_key = "ACEDATACLOUD_API_KEY"
wire_api = "responses"
```

Erklärung der Felder:

| Feld | Beschreibung |
| --- | --- |
| `model_provider` | Standardmäßig verwendeter Modellanbieter, verweist auf `[model_providers.acedatacloud]` |
| `model` | Standardmäßig verwendete Modell-ID |
| `model_reasoning_effort` | Inferenzstärke, übliche Werte sind `low`, `medium`, `high` |
| `approval_policy` | Bestätigungsstrategie vor Ausführung von Befehlen, für den Alltag empfohlen `on-request` |
| `sandbox_mode` | Sandbox-Berechtigungen bei Ausführung von Befehlen, für die tägliche Entwicklung empfohlen `workspace-write` |
| `base_url` | OpenAI-kompatible API-Adresse von Ace Data Cloud |
| `env_key` | Name der Umgebungsvariable, aus der Codex den API-Token liest |
| `wire_api` | Protokolltyp, für OpenAI Responses API muss `responses` gesetzt sein |

Alternativ können Sie in der Codex-Erweiterung oben rechts auf das Zahnradsymbol klicken und **Codex Settings > Open config.toml** wählen, um die Konfigurationsdatei direkt in VS Code zu öffnen.

### Projektbezogene Konfiguration

Wenn Sie nur für ein bestimmtes Projekt eine andere Konfiguration verwenden möchten, können Sie im Projektstammverzeichnis eine `.codex/config.toml` anlegen. Codex lädt diese projektbezogene Konfiguration bevorzugt, allerdings nur, wenn das Projekt als vertrauenswürdig markiert ist.

Beispiel:

```toml
model = "gpt-5-mini"
model_reasoning_effort = "medium"
```

Es wird empfohlen, persönliche Tokens in Umgebungsvariablen zu speichern und nicht in das Projekt-Repository zu schreiben. Ob die projektbezogene `.codex/config.toml` ins Repository aufgenommen wird, sollte teamabhängig entschieden werden.

## Löschen zwischengespeicherter OpenAI-Anmeldedaten

Falls Sie zuvor in der Codex-Erweiterung mit einem offiziellen OpenAI-Konto angemeldet waren, sind möglicherweise noch lokale Anmeldedaten gespeichert. Vor dem Wechsel zum Ace Data Cloud-Proxy können Sie im Terminal ausführen:

```bash
codex logout
```

Ist der Befehl nicht verfügbar, löschen Sie alternativ die lokale Cache-Datei:

```bash
rm -f ~/.codex/auth.json
```

Starten Sie anschließend VS Code neu oder laden es neu.

## Grundlegende Verwendung

Nach der Konfiguration öffnen Sie das Codex-Panel in VS Code (links oder rechts) und geben Ihre Anfragen direkt ein. Beispiel:

```text
Erkläre die Verzeichnisstruktur des aktuellen Projekts und nenne die Haupt-Einstiegsdatei.
```

Die Codex-Erweiterung kann Dateien und ausgewählten Code im Editor als Kontext verwenden. Sie können auch mit `@` auf Dateien verweisen, z. B.:

```text
Beziehe dich auf @src/App.vue und hilf mir, diese Seite in klarere Komponenten aufzuteilen.
```

Wenn Sie einen Codeabschnitt markieren, können Sie über die Befehls-Palette ausführen:

```text
Codex: Add to Codex Thread
```

Oder auch:

```text
Codex: Add File to Codex Thread
```

um die gesamte aktuelle Datei als Kontext hinzuzufügen.

## Modell- und Inferenzstärke wechseln

Die Codex VS Code-Erweiterung unterstützt das Wechseln des Modells und der Inferenzstärke über den Modellumschalter unterhalb des Eingabefelds. Bei Verwendung des benutzerdefinierten Ace Data Cloud-Anbieters empfiehlt es sich, das Standardmodell in `~/.codex/config.toml` festzulegen und bei Bedarf in der Oberfläche zu wechseln. Empfohlene Standardwerte:

| Szenario | Empfohlenes Modell | Inferenzstärke |
| --- | --- | --- |
| Tägliches Code-Lesen und kleine Änderungen | `gpt-5-mini` | `medium` |
| Normale Entwicklungsaufgaben | `gpt-5` | `high` |
| Komplexe Refaktorierung und tiefgehende Inferenz | `gpt-5.5` oder `gpt-5.5-pro` | `high` |
| Aufgaben mit verstärkter Inferenz | `o3` | `high` |

Wenn das gewünschte Modell in der Oberfläche nicht angezeigt wird, ändern Sie direkt das `model`-Feld in `~/.codex/config.toml` und starten VS Code neu oder laden es neu. Eine vollständige Modellübersicht finden Sie in der [Ace Data Cloud OpenAI-Dokumentation](https://platform.acedata.cloud/documents/openai).

## Arbeitsmodus wählen

Die Codex-Erweiterung unterstützt verschiedene Arbeitsmodi. Gängige Modi:

| Modus | Anwendungsfall |
| --- | --- |
| `Chat` | Nur Diskussion, Code-Erklärung, Planung ohne direkte Dateiänderungen |
| `Agent` | Codex liest Dateien, ändert Code und führt notwendige Befehle aus, empfohlen für den Alltag |
| `Agent (Full Access)` | Erlaubt höhere Berechtigungen und Netzwerkzugriff, geeignet wenn Sie die Risiken kennen |

Für den Alltag wird `Agent` mit `approval_policy = "on-request"` empfohlen. So fragt Codex vor der Ausführung sensibler Befehle, beim Zugriff außerhalb des Arbeitsbereichs oder bei Netzwerkzugriff um Bestätigung.

## Konfiguration prüfen

Sie können im Terminal mit derselben Konfiguration testen, ob Codex über Ace Data Cloud funktioniert:

```bash
codex exec --model gpt-5-mini "Reply with exactly: ADC_Codex_OK"
```

Bei korrekter Konfiguration sollte die Antwort lauten:

```text
ADC_Codex_OK
```

Wechseln Sie dann zurück zu VS Code, öffnen Sie das Codex-Panel und stellen Sie eine einfache Frage:

```text
Beschreibe den Zweck des aktuellen Arbeitsbereichs in einem Satz.
```

Sie können Ihre Anfragen und Abrechnungen auch im [Ace Data Cloud Console - Nutzungsverlauf](https://platform.acedata.cloud/console/usages) einsehen und Ihr verbleibendes Kontingent im [Ace Data Cloud Console - Anwendungsübersicht](https://platform.acedata.cloud/console/applications) prüfen.

## Funktionsweise

Die Codex VS Code-Erweiterung verwendet keine eigenständige Modellkonfiguration. Sie nutzt das lokale Codex CLI und teilt dessen Konfiguration:

1. Die VS Code-Erweiterung startet Codex und liest die benutzerspezifische `~/.codex/config.toml`.
2. Ist das Projekt als vertrauenswürdig markiert und enthält eine `.codex/config.toml`, wird diese projektbezogene Konfiguration zusätzlich geladen.
3. Zeigt `model_provider` auf `acedatacloud`, liest Codex den API-Token aus `ACEDATACLOUD_API_KEY`.
4. Anfragen werden per OpenAI Responses-Protokoll an `https://api.acedata.cloud/v1/responses` gesendet.
5. Ace Data Cloud authentifiziert, prüft Kontingente, leitet weiter und protokolliert die Nutzung.

Daher ist normalerweise nur eine Konfiguration für CLI und VS Code-Erweiterung erforderlich. Nach erfolgreicher CLI-Verifikation verwendet auch die VS Code-Erweiterung dieselbe Konfiguration.
