Codex CLI ist ein Open-Source-lokaler Programmierungs-Agent, der von OpenAI bereitgestellt wird und in deinem Terminal läuft. Er kann Code lesen, Dateien ändern, Befehle ausführen, Fehler erklären und bei der Erledigung alltäglicher Entwicklungsaufgaben unterstützen.

Codex CLI unterstützt benutzerdefinierte Modellanbieter. Du kannst es über einen OpenAI Responses-kompatiblen Proxy verwenden, der von Ace Data Cloud bereitgestellt wird, ohne ein separates OpenAI-Konto abonnieren zu müssen. Nach der Konfiguration sendet Codex CLI Anfragen an `https://api.acedata.cloud/v1`.

## Antragsprozess

Um Codex CLI zu verwenden, kannst du zunächst im [Ace Data Cloud Dashboard](https://platform.acedata.cloud/console/applications) deinen API-Token erhalten und als Backup aufbewahren.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Wenn du noch nicht eingeloggt oder registriert bist, wirst du automatisch zur Login-Seite weitergeleitet, um dich zu registrieren und anzumelden. Nach dem Login wirst du automatisch auf die aktuelle Seite zurückgeleitet.

Beim ersten Antrag erhältst du ein kostenloses Kontingent, um den Codex CLI-Service kostenlos zu testen.

## Installation von Codex CLI

Codex CLI unterstützt macOS, Linux, Windows und WSL. Du kannst es via npm installieren oder Homebrew (nur macOS) verwenden.

### npm-Installation (empfohlen)

Wenn Node.js bereits installiert ist, kannst du es direkt via npm installieren. Diese Methode erfordert Node.js Version 18 oder höher.

```bash
npm install -g @openai/codex
```

### Homebrew-Installation (macOS)

macOS-Nutzer können auch Homebrew verwenden:

```bash
brew install --cask codex
```

### Überprüfung der Installation

Nach der Installation öffne dein Terminal erneut und prüfe, ob der Befehl verfügbar ist:

```bash
codex --version
```

Wenn die Meldung `command not found` erscheint, ist dein aktuelles Terminal wahrscheinlich noch nicht mit dem neuen PATH aktualisiert. Schließe das Terminal und öffne es erneut oder überprüfe die PATH-Konfiguration, die im Installationsprozess ausgegeben wurde.

## Konfiguration von Codex CLI

Nach der Installation versucht Codex CLI standardmäßig, sich mit den offiziellen OpenAI-Servern zu verbinden. Um stattdessen Ace Data Cloud zu verwenden, musst du in der Konfigurationsdatei einen benutzerdefinierten `model_provider` angeben und den API-Token in die entsprechende Umgebungsvariable setzen.

### Schritt 1: Umgebungsvariable setzen

Es wird empfohlen, den API-Token in deine Shell-Konfigurationsdatei einzufügen, z.B. `~/.zshrc`, `~/.bashrc` oder `~/.bash_profile`:

```bash
export ACEDATACLOUD_API_KEY="{token}"
```

Ersetze `{token}` durch den API-Token, den du im Ace Data Cloud Dashboard kopiert hast.

Nach der Konfiguration öffne dein Terminal neu oder führe den folgenden Befehl aus, um die Änderungen sofort zu aktivieren:

```bash
source ~/.zshrc
```

### Schritt 2: Konfigurationsdatei bearbeiten

Codex CLI verwendet `~/.codex/config.toml` als globale Konfigurationsdatei. Falls diese noch nicht existiert, kannst du sie erstellen:

```bash
mkdir -p ~/.codex
touch ~/.codex/config.toml
```

Füge den folgenden Inhalt in `~/.codex/config.toml` ein:

```toml
model_provider = "acedatacloud"
model = "gpt-5"
model_reasoning_effort = "high"

[model_providers.acedatacloud]
name = "Ace Data Cloud"
base_url = "https://api.acedata.cloud/v1"
env_key = "ACEDATACLOUD_API_KEY"
wire_api = "responses"
```

Erläuterung der Felder:

| Feld | Beschreibung |
| --- | --- |
| `model_provider` | Standardanbieter-Name, entspricht dem Schlüssel im `[model_providers.<name>]`-Abschnitt |
| `model` | Standardmodell-ID |
| `model_reasoning_effort` | Schwierigkeitsgrad der Schlussfolgerung, übliche Werte: `low`, `medium`, `high` |
| `[model_providers.acedatacloud].base_url` | Adresse des Ace Data Cloud OpenAI Responses-Proxy |
| `[model_providers.acedatacloud].env_key` | Name der Umgebungsvariable, die den API-Token enthält |
| `[model_providers.acedatacloud].wire_api` | Protokolltyp, muss `responses` sein, um OpenAI Responses API zu verwenden |

### Cache der OpenAI-Anmeldung löschen

Wenn du dich zuvor mit einem offiziellen OpenAI-Konto bei Codex CLI angemeldet hast, ist möglicherweise eine lokale Cache-Datei (`~/.codex/auth.json`) vorhanden. Vor dem Wechsel zu Ace Data Cloud solltest du diese alte Anmeldung löschen:

```bash
codex logout
```

Falls der Befehl `codex logout` nicht verfügbar ist, kannst du die Cache-Datei auch manuell entfernen:

```bash
rm -f ~/.codex/auth.json
```

Wenn du dich noch nie mit einem OpenAI-Konto angemeldet hast, kannst du diesen Schritt überspringen.

### Sitzung starten

Gehe in dein Projektverzeichnis und starte Codex CLI:

```bash
cd /pfad/zu/deinem/projekt
codex
```

Sobald die Codex-Oberfläche erscheint, kannst du direkt deine Anforderungen eingeben, z.B.:

```text
Erkläre die Verzeichnisstruktur dieses Projekts
```

### Konfiguration überprüfen

Nach dem Start kannst du im interaktiven Modus den aktuellen Modell- und Anbieterstatus prüfen:

```text
/model
```

Du solltest eine Ausgabe ähnlich wie folgt sehen:

```text
Model: gpt-5
Provider: acedatacloud
```

Wenn ein anderer Anbieter angezeigt wird, ist die Konfiguration nicht wirksam. Überprüfe in diesem Fall nochmals die Datei `~/.codex/config.toml` sowie die Umgebungsvariable `ACEDATACLOUD_API_KEY`:

```bash
echo $ACEDATACLOUD_API_KEY
```

Außerdem kannst du die Anfragehistorie und Abrechnungsdetails im [Ace Data Cloud Dashboard - Nutzungshistorie](https://platform.acedata.cloud/console/usages) einsehen und die verbleibenden Kontingente im [Ace Data Cloud Dashboard - Anwendungen](https://platform.acedata.cloud/console/applications).

## Funktionsweise

Codex CLI nutzt native das OpenAI Responses API-Protokoll. Ace Data Cloud bietet unter `https://api.acedata.cloud/v1/responses` einen Proxy, der mit dem OpenAI Responses API kompatibel ist. Damit ist kein lokaler Proxy oder zusätzliche Plugins erforderlich.

Der Ablauf ist wie folgt:

1. Codex CLI liest `model_provider` aus `~/.codex/config.toml` und lädt den entsprechenden Abschnitt `[model_providers.acedatacloud]`.
2. Es liest den API-Token aus der in `env_key` angegebenen Umgebungsvariable (`ACEDATACLOUD_API_KEY`).
3. Anfragen werden im `responses`-Protokoll an `base_url + /responses` gesendet, also `https://api.acedata.cloud/v1/responses`.
4. Ace Data Cloud überprüft den API-Token, validiert das Kontingent und leitet die Anfrage an den verfügbaren Upstream-Modelkanal weiter.
5. Nach Abschluss der Anfrage werden die Nutzung und Abzüge anhand des tatsächlichen Verbrauchs erfasst.

Das bedeutet, du nutzt weiterhin den ursprünglichen `codex`-Befehl und die native Interaktion, nur dass die zugrunde liegenden Modellservices auf Ace Data Cloud umgestellt sind.

## Modelle konfigurieren

Der `model`-Eintrag in `~/.codex/config.toml` bestimmt das Standardmodell. Der OpenAI Responses-Service von Ace Data Cloud unterstützt verschiedene Modelle, z.B.:

| Modell | Beschreibung |
| --- | --- |
| `gpt-5` | Empfohlenes Standardmodell, geeignet für die meisten Codierungsaufgaben |
| `gpt-4.1-mini` | Leichtgewichtig, schnelle Antwort, geeignet für einfache Aufgaben |
| `gpt-5.5` | Neuere Version, stärkere Fähigkeiten |
| `gpt-5.5-pro` | Erweiterte Version, geeignet für komplexe Schlussfolgerungen |
| `gpt-4.1` | Vorgängermodell, bewährt |
| `o3` | Für tiefgehende Schlussfolgerungen optimiert |
| `o4-mini-high-all` | Leichtgewichtiges Modell für spezielle Anforderungen |

Möchtest du das Modell temporär ändern, kannst du beim Starten von Codex die `--model`-Option verwenden:

```bash
codex --model gpt-4.1-mini
```

Oder du änderst den `model`-Eintrag in `~/.codex/config.toml` und startest neu. Eine vollständige Modellliste findest du in der [Ace Data Cloud OpenAI-Dokumentation](https://platform.acedata.cloud/documents/openai).

## Vertrauensstufen für Projekte

Codex CLI ermöglicht es, für verschiedene Projekte unterschiedliche Vertrauensstufen zu setzen, um zu steuern, welche Aktionen der Agent ausführen darf. Füge dazu in `~/.codex/config.toml` am Ende hinzu:

```toml
[projects."/pfad/zum/trusted/project"]
trust_level = "trusted"

[projects."/pfad/zum/untrusted/project"]
trust_level = "untrusted"
```

- `trusted`: Der Agent hat volle Berechtigungen, kann Befehle ausführen und Dateien ändern.
- `untrusted`: Der Agent ist eingeschränkt, geeignet für Projekte, bei denen du dem Agent nicht voll vertraust.
