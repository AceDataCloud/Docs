Die Hauptfunktion der Luma Tasks API besteht darin, den Status der Ausführung eines Tasks abzufragen, indem die Task-ID eingegeben wird, die durch die Luma Videos Generation API generiert wurde.

Dieses Dokument wird die Integrationsanleitung der Luma Tasks API detailliert beschreiben, um Ihnen zu helfen, diese API einfach zu integrieren und ihre leistungsstarken Funktionen voll auszuschöpfen. Mit der Luma Tasks API können Sie den Status der Ausführung von Tasks der Luma Videos Generation API einfach abfragen.

## Antragsprozess

Um die Luma Tasks API zu nutzen, müssen Sie zunächst auf die Anmeldeseite [Luma Videos Generation API](https://platform.acedata.cloud/documents/5bd3597d-1ff8-44ad-a580-b66b48393e7f) gehen und den entsprechenden Service beantragen, dann kopieren Sie die Task-ID der Luma Videos Generation API, wie im Bild gezeigt:

![](https://cdn.acedata.cloud/ynk4ow.png)

Gehen Sie schließlich zur Tasks API-Seite [Luma Tasks API](https://platform.acedata.cloud/documents/7d32369c-4ead-4364-a4c5-652bc768b3ff), um den entsprechenden Service zu beantragen. Klicken Sie nach dem Betreten der Seite auf die Schaltfläche „Acquire“, wie im Bild gezeigt:

![Anmeldeseite](https://cdn.acedata.cloud/rci31i.png)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur [Anmeldeseite](https://platform.acedata.cloud) weitergeleitet, um sich zu registrieren und anzumelden. Nach der Anmeldung werden Sie automatisch zur aktuellen Seite zurückgeleitet.

Bei der ersten Beantragung gibt es ein kostenloses Kontingent, mit dem Sie diese API kostenlos nutzen können.

## Anfragebeispiel

Die Luma Tasks API kann verwendet werden, um die Ergebnisse der Luma Videos Generation API abzufragen. Informationen zur Verwendung der Luma Videos Generation API finden Sie im Dokument [Luma Videos Generation API](https://platform.acedata.cloud/documents/16bb0108-1f09-45b3-97ac-16a668750a8c).

Wir nehmen eine von der Luma Videos Generation API zurückgegebene Task-ID als Beispiel und demonstrieren, wie man diese API verwendet. Angenommen, wir haben eine Task-ID: 50fc6182-fa86-4c7d-ac12-2fa27ec2f151, im Folgenden zeigen wir, wie man durch Eingabe einer Task-ID vorgeht.

### Anfrageheader und Anfragekörper festlegen

**Request Headers** umfassen:

- `accept`: Gibt an, dass die Antwort im JSON-Format empfangen werden soll, hier eingetragen als `application/json`.
- `authorization`: Der Schlüssel zum Aufrufen der API, nach der Beantragung kann dieser direkt ausgewählt werden.

**Request Body** umfasst:

- `id`: Die hochgeladene Task-ID.
- `action`: Die Art der Operation auf der Task.

Einstellung wie im folgenden Bild gezeigt:

<p><img src="https://cdn.acedata.cloud/g6ev5b.png" width="500" className="m-auto" /></p>

### Codebeispiel

Es kann festgestellt werden, dass auf der rechten Seite der Seite bereits automatisch Code in verschiedenen Sprachen generiert wurde, wie im Bild gezeigt:

<p><img src="https://cdn.acedata.cloud/i4fxqf.png" width="500" className="m-auto" /></p>

Einige Codebeispiele sind wie folgt:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/luma/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "50fc6182-fa86-4c7d-ac12-2fa27ec2f151",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/luma/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "50fc6182-fa86-4c7d-ac12-2fa27ec2f151",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Die Feldbeschreibung ist wie folgt.

- `request`, die Anfrageinformationen im Video-Task.
- `response`, die Rückgabeinformationen im Video-Task.

## Fehlerbehandlung

Bei der Verwendung der API, wenn ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die Informationen zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Unbefugt, ungültiger oder fehlender Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Limit überschritten.
- `500 api_error`: Interner Serverfehler, etwas ist auf dem Server schiefgelaufen.

### Fehlerantwort Beispiel

```json
{
  "success": false,
  "error": {

    "message": "Abruf fehlgeschlagen"
  },

}
```
