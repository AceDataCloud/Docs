Die Hauptfunktion der SeeDance Tasks API besteht darin, den Status der Ausführung eines Auftrags abzufragen, indem die Auftrags-ID eingegeben wird, die über die SeeDance Video Generation API generiert wurde.

Dieses Dokument wird die Integrationsanleitung der SeeDance Tasks API detailliert beschreiben, um Ihnen zu helfen, diese API einfach zu integrieren und ihre leistungsstarken Funktionen voll auszuschöpfen. Mit der SeeDance Tasks API können Sie den Status der Auftragsausführung der SeeDance Video Generation API einfach abfragen.

## Antragsprozess

Um die SeeDance Tasks API zu nutzen, müssen Sie zunächst auf die Anmeldeseite [SeeDance Video Generation API](https://platform.acedata.cloud/documents/seedance-videos) gehen und den entsprechenden Dienst beantragen, dann kopieren Sie die Auftrags-ID der SeeDance Video Generation API, wie im Bild gezeigt:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Gehen Sie schließlich zur Tasks API-Seite [SeeDance Tasks API](https://platform.acedata.cloud/documents/seedance-tasks), um den entsprechenden Dienst zu beantragen. Klicken Sie nach dem Betreten der Seite auf die Schaltfläche „Acquire“, wie im Bild gezeigt:

![Anmeldeseite](https://cdn.acedata.cloud/rci31i.png)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur [Anmeldeseite](https://platform.acedata.cloud) weitergeleitet, um sich zu registrieren und anzumelden. Nach der Anmeldung werden Sie automatisch zur aktuellen Seite zurückgeleitet.

Bei der ersten Beantragung gibt es ein kostenloses Kontingent, mit dem Sie die API kostenlos nutzen können.

## Anfragebeispiel

Die SeeDance Tasks API kann verwendet werden, um die Ergebnisse der SeeDance Video Generation API abzufragen. Informationen zur Nutzung der SeeDance Video Generation API finden Sie im Dokument [SeeDance Video Generation API](https://platform.acedata.cloud/documents/seedance-videos-integration).

Wir nehmen eine von der SeeDance Video Generation API zurückgegebene Auftrags-ID als Beispiel und demonstrieren, wie man diese API verwendet. Angenommen, wir haben eine Auftrags-ID: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, im Folgenden zeigen wir, wie man durch Eingabe einer Auftrags-ID vorgeht.

### Anfrageheader und Anfragekörper festlegen

**Request Headers** umfassen:

- `accept`: Gibt an, dass die Antwort im JSON-Format empfangen werden soll, hier eingetragen als `application/json`.
- `authorization`: Der Schlüssel zur API-Nutzung, der nach der Beantragung direkt ausgewählt werden kann.

**Request Body** umfasst:

- `id`: Die hochgeladene Auftrags-ID.
- `action`: Die Art der Operation für den Auftrag.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/seedance/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "a6e0d456-189b-4c78-9232-2fe72166ab39",
  "action": "retrieve"
}'
```

Die Rückgabe enthält mehrere Felder, das Feld request ist der request body, der beim Starten des Auftrags gesendet wurde, während das Feld response der response body ist, der nach Abschluss des Auftrags zurückgegeben wird. Die Feldbeschreibung ist wie folgt.

- `id`, die ID des generierten Auftrags, die zur eindeutigen Identifizierung dieses Generierungsauftrags verwendet wird.
- `request`, die Anfrageinformationen im Auftrag.
- `response`, die Rückgabeinformationen im Auftrag.

Fehlerbehandlung

Bei der API-Nutzung, wenn ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die Informationen zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Unbefugt, ungültiger oder fehlender Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Kontingent überschritten.
- `500 api_error`: Interner Serverfehler, etwas ist auf dem Server schiefgelaufen.

### Fehlerantwort Beispiel

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "Abruf fehlgeschlagen"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
