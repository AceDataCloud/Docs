Die Hauptfunktion der SeeDance Tasks API besteht darin, den Status der Ausführung eines Auftrags abzufragen, indem die Auftrags-ID eingegeben wird, die durch die SeeDance Video Generation API generiert wurde.

Dieses Dokument wird die Integrationsanleitung der SeeDance Tasks API detailliert beschreiben, um Ihnen zu helfen, diese API einfach zu integrieren und ihre leistungsstarken Funktionen voll auszuschöpfen. Mit der SeeDance Tasks API können Sie den Status der Auftragsausführung der SeeDance Video Generation API problemlos abfragen.

## Antragsprozess

Um die SeeDance Video Generation API zu nutzen, müssen Sie zunächst Ihr API-Token im [Ace Data Cloud Dashboard](https://platform.acedata.cloud/console/applications) abrufen und für zukünftige Verwendung aufbewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, die Sie zur Registrierung und Anmeldung einlädt. Nach Abschluss werden Sie automatisch zur aktuellen Seite zurückgeleitet.

**Ein API-Token reicht aus, um auf alle Dienste der Plattform zuzugreifen, ohne dass für jeden Dienst separat ein Antrag gestellt werden muss.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, um die Dienste kostenlos auszuprobieren; wenn das Kontingent erschöpft ist, können Sie im [Dashboard](https://platform.acedata.cloud/console/coin) Ihr allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [SeeDance Video Generation API →](https://platform.acedata.cloud/documents/seedance-videos)

## Anfragebeispiel

Die SeeDance Tasks API kann verwendet werden, um die Ergebnisse der SeeDance Video Generation API abzufragen. Informationen zur Verwendung der SeeDance Video Generation API finden Sie in der Dokumentation [SeeDance Video Generation API](https://platform.acedata.cloud/documents/seedance-videos-integration).

Wir nehmen als Beispiel eine von der SeeDance Video Generation API zurückgegebene Auftrags-ID und demonstrieren, wie man diese API verwendet. Angenommen, wir haben eine Auftrags-ID: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, im Folgenden zeigen wir, wie man durch Eingabe einer Auftrags-ID vorgeht.

### Anfrageheader und Anfragekörper festlegen

**Request Headers** umfassen:

- `accept`: Gibt an, dass die Antwort im JSON-Format empfangen werden soll, hier eingetragen als `application/json`.
- `authorization`: Der Schlüssel zur Aufrufung der API, nach der Beantragung kann dieser direkt ausgewählt werden.

**Request Body** umfasst:

- `id`: Die hochgeladene Auftrags-ID.
- `action`: Die Art der Operation auf dem Auftrag.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/seedance/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "a6e0d456-189b-4c78-9232-2fe72166ab39",
  "action": "retrieve"
}'
```

Die Rückgabe enthält mehrere Felder, das Feld request ist der request body, der beim Starten des Auftrags gesendet wurde, während das Feld response der response body ist, der nach Abschluss des Auftrags zurückgegeben wird. Die Feldbeschreibung ist wie folgt.

- `id`, die ID des generierten Auftrags, die zur eindeutigen Identifizierung dieses Generierungsauftrags dient.
- `request`, die Anfrageinformationen im Auftrag.
- `response`, die Rückgabeinformationen im Auftrag.
- `created_at`, die Erstellungszeit des Auftrags, Unix-Zeitstempel (Sekunden, Fließkomma).
- `started_at`, die Startzeit der Auftragsausführung, Unix-Zeitstempel (Sekunden, Fließkomma).
- `finished_at`, die Abschlusszeit des Auftrags, Unix-Zeitstempel (Sekunden, Fließkomma). Dieses Feld wird nicht zurückgegeben, wenn der Auftrag nicht abgeschlossen ist.
- `elapsed`, die Ausführungszeit des Auftrags, gemessen in Sekunden (Fließkomma, auf 3 Dezimalstellen gerundet). Dieses Feld wird nicht zurückgegeben, wenn der Auftrag nicht abgeschlossen ist.

## Fehlerbehandlung

Bei der Verwendung der API, wenn ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die Informationen zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Unbefugt, ungültiger oder fehlender Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Kontingent überschritten.
- `500 api_error`: Interner Serverfehler, etwas ist auf dem Server schiefgelaufen.

### Fehlerantwort Beispiel

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "Abruf fehlgeschlagen"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
