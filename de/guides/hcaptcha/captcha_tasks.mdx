Dieser Artikel beschreibt die API zur Abfrage von asynchronen Captcha-Aufgaben `POST /captcha/tasks`. Wenn Sie bei der Verwendung einer beliebigen Captcha-Schnittstelle (Token-Serie oder Erkennungsserie) `async: true` übergeben, gibt die Schnittstelle sofort eine `task_id` zurück, die Sie dann verwenden können, um diese Schnittstelle abzufragen und das endgültige Ergebnis zu erhalten. Dies eignet sich für Szenarien wie die Rotation mehrerer Solver: Nachdem Sie die Aufgabe eingereicht haben, erhalten Sie sofort die `task_id`, um andere Solver zu beauftragen und später das Ergebnis abzurufen.

> 📘 Vollständige interaktive Dokumentation (einschließlich Online-Debugging): [API zur Abfrage von Captcha-Aufgaben →](https://platform.acedata.cloud/documents/captcha-tasks)

## Antragsprozess

Um diese Schnittstelle zu nutzen, gehen Sie zuerst zur [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications), um Ihr API-Token zu erhalten, das Sie zur Sicherheit aufbewahren sollten. **Ein API-Token reicht aus, um alle Dienste der Plattform zu nutzen, es ist nicht erforderlich, für jeden Dienst separat zu beantragen.**

## Grundlegende Nutzung

### Schritt 1: Aufgabe asynchron erstellen

Übergeben Sie in der Anfrage an eine beliebige Captcha-Schnittstelle `async: true`, die Schnittstelle gibt sofort eine `task_id` zurück (HTTP 201), ohne zu blockieren:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

### Schritt 2: Ergebnisse mit task_id abfragen

Verwenden Sie die in Schritt 1 zurückgegebene `task_id`, um `POST /captcha/tasks` abzufragen (empfohlen alle 3-5 Sekunden):

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Während der Verarbeitung wird `status: processing` zurückgegeben:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "processing"
}
```

Nach Abschluss der Verarbeitung wird `status: ready` und das entsprechende Ergebnisfeld zurückgegeben – die Feldstruktur ist identisch mit der im synchronen Modus:

- **Token-Serie** (hcaptcha, recaptcha2, recaptcha3) gibt `token` zurück:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "started_at": 1784885653.0,
  "finished_at": 1784885665.4,
  "elapsed": 12.4,
  "token": "03AFcWeA5kjJyDQ9S1a9UYimR6nuxnpEnAs5x2Pixao0dXZhMB......"
}
```

- **Erkennungs-Kategorie** (recognition/recaptcha2, recognition/hcaptcha) gibt `solution` zurück; **recognition/image2text** gibt `text` zurück.

`/captcha/tasks` ist für alle Captcha-Schnittstellen (Token- und Erkennungsserie) allgemein gültig, Sie können dasselbe `task_id` zur Abfrage verwenden.

Wenn die Aufgabe nicht innerhalb der gültigen Zeit abgeschlossen werden kann, wird HTTP 504 zurückgegeben. Dieser Status ist terminal, der Client sollte die Abfrage einstellen; wiederholte Abfragen derselben `task_id` geben stabil dasselbe Fehlermeldung zurück:

```json
{
  "detail": "Die Captcha-Aufgabe ist abgelaufen.",
  "code": "timeout",
  "success": false,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "failed",
  "started_at": 1784885653.0,
  "finished_at": 1784885765.4,
  "elapsed": 112.4
}
```

Sowohl die terminale Antwort `status: ready` als auch HTTP 504 enthalten Zeitstempelfelder.

- `started_at`, Zeitpunkt des Beginns der Aufgabenbearbeitung, Unix-Zeitstempel (Sekunden, Fließkomma).
- `finished_at`, Zeitpunkt der Ergebnisproduktion der Aufgabe, Unix-Zeitstempel (Sekunden, Fließkomma). Wird während der Verarbeitung nicht zurückgegeben.
- `elapsed`, Zeitaufwand für die Aufgabenbearbeitung, Einheit in Sekunden (Fließkomma, auf 3 Dezimalstellen gerundet). Wird während der Verarbeitung nicht zurückgegeben.

## Abrechnungsinformationen

Im asynchronen Modus werden die Erstellung von Aufgaben und die Abfrage des „Verarbeitungs“-Status nicht berechnet; **es wird nur einmal berechnet, wenn das Ergebnis erfolgreich abgerufen wird** (zum gleichen Preis wie im synchronen Modus). Der terminale Fehlerstatus HTTP 504 wird ebenfalls nicht berechnet. Daher entstehen bei der Stornierung von noch nicht abgeschlossenen Aufgaben oder bei endgültigem Fehlschlag der Aufgaben keine Kosten.

## Fehlerbehandlung

Wenn beim Aufruf dieser Schnittstelle ein Fehler auftritt, wird der entsprechende Fehlercode und die Fehlermeldung zurückgegeben. Zum Beispiel:

- `400 invalid_request`: Anfrage fehlt das `task_id`-Parameter.
- `401 invalid_token`: Nicht autorisiert, der Autorisierungs-Token ist ungültig oder fehlt.
- `404 not_found`: `task_id` existiert nicht oder gehört nicht zum aktuellen Konto.
- `504 timeout`: Die Aufgabe wurde abgebrochen und hat kein Ergebnis produziert; bitte stoppen Sie die Abfrage dieser `task_id`. Dieser Fehler wird nicht berechnet.

### Beispiel für eine Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "not_found",
    "message": "Aufgabe nicht gefunden"
  }
}
```
