Dieser Artikel beschreibt die Integration und Nutzung der MiniMax H3 Aufgabenabfrage API. Diese Schnittstelle dient dazu, asynchrone Aufgaben abzufragen, in großen Mengen aufzulisten oder zu löschen, die durch die [MiniMax H3 Videoerzeugungs-API](/documents/minimax-videos-integration) erstellt wurden.

## Antragsprozess

Um die MiniMax H3 Aufgabenabfrage API zu nutzen, müssen Sie zunächst Ihr API-Token im [Ace Data Cloud Dashboard](https://platform.acedata.cloud/console/applications) abrufen und für zukünftige Verwendung aufbewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, die Sie zur Registrierung und Anmeldung einlädt. Nach Abschluss werden Sie automatisch zur aktuellen Seite zurückgeleitet.

**Ein API-Token reicht aus, um auf alle Dienste der Plattform zuzugreifen, es ist nicht erforderlich, für jeden Dienst separat zu beantragen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, um es kostenlos auszuprobieren; wenn das Kontingent erschöpft ist, können Sie im [Dashboard](https://platform.acedata.cloud/console/coin) Ihr Guthaben aufladen.

> 📘 Vollständige Dokumentation: [MiniMax H3 Aufgabenabfrage API →](https://platform.acedata.cloud/documents/minimax-tasks-integration)

Beim Abfragen von Aufgaben sollte dasselbe Token verwendet werden, mit dem die Aufgabe erstellt wurde. Es wird empfohlen, das Token als Umgebungsvariable zu speichern und nicht in den Quellcode zu schreiben oder in ein Versionskontrollsystem einzufügen:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Schnittstellenübersicht

- **Basis-URL**: `https://api.acedata.cloud`
- **Endpunkt**: `POST /minimax/tasks`
- **Authentifizierungsmethode**: HTTP-Header mit `authorization: Bearer {token}`
- **Anforderungsheader**:
  - `accept: application/json`
  - `content-type: application/json`
- **Abfrage einer einzelnen Aufgabe**: `action=retrieve`, übergeben Sie `id`
- **Batch-Abfrage von Aufgaben**: `action=retrieve_batch`, Filterung nach Aufgaben-ID, Zeitrahmen und Paginierungsbedingungen möglich
- **Aufgabe löschen**: `action=delete`, übergeben Sie `id`
- **Abrechnungsinformationen**: Die Abfrage von Aufgaben ist kostenlos und führt nicht zu doppelter Abrechnung

Nach der Erstellung des Videos muss `task_id` gespeichert werden. Es wird empfohlen, alle 10 Sekunden eine Abfrage durchzuführen, bis die Aufgabe in den Endzustand eintritt.

## Anforderungsparameter

| Parameter            | Typ       | Pflicht | Anwendbare Aktion         | Beschreibung                                           |
| ------------------- | -------- | ------ | --------------------- | ---------------------------------------------------- |
| `action`            | string   | Nein   | Alle                  | `retrieve`, `retrieve_batch` oder `delete`; Standard `retrieve` |
| `id`                | string   | Bedingte Pflicht | `retrieve`, `delete` | Einzelne Aufgaben-ID                                   |
| `ids`               | string[] | Nein   | `retrieve_batch`      | Gibt nur die angegebenen Aufgaben-IDs zurück; wenn weggelassen, werden Aufgaben nach anderen Kriterien aufgelistet |
| `limit`             | integer  | Nein   | `retrieve_batch`      | Maximale Anzahl der zurückgegebenen Aufgaben in dieser Anfrage |
| `offset`            | integer  | Nein   | `retrieve_batch`      | Anzahl der Aufgaben, die aus der Ergebnisliste übersprungen werden, zur Paginierung |
| `created_at_min`    | number   | Nein   | `retrieve_batch`      | Untergrenze der Erstellungszeit, Unix-Zeitstempel, in Sekunden |
| `created_at_max`    | number   | Nein   | `retrieve_batch`      | Obergrenze der Erstellungszeit, Unix-Zeitstempel, in Sekunden |

Die Verwendung der drei Aktionen ist wie folgt:

| `action`            | Verwendung                          | Notwendige Parameter                  | Antwortstruktur                             |
| ------------------- | ---------------------------------- | ------------------------------------ | ------------------------------------------ |
| `retrieve`          | Abfrage des Status und Ergebnisses einer Aufgabe | `id`                                | `{ "task": {...} }`                        |
| `retrieve_batch`    | Batch-Abfrage nach Aufgaben-ID, Zeit und Paginierungsbedingungen | Optionale `ids`, Zeitrahmen, `offset`, `limit` | `{ "items": [...], "total": number }`    |
| `delete`            | Stornierung oder Löschung des Aufgabenprotokolls basierend auf dem aktuellen Status der Aufgabe | `id`                                | `{ "id": "...", "deleted": true }`       |

## Abfrage einer einzelnen Aufgabe

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f5977217-ed2c-40da-adbe-93d08235618f"
  }'
```

## Aufgabenstatus

| `status`    | Bedeutung                     | Client-Verarbeitung                |
| ----------- | ----------------------------- | --------------------------------- |
| `queued`    | In der Warteschlange, wartet auf Ausführung | Weiterhin abfragen                |
| `running`   | Wird generiert                | Weiterhin abfragen                |
| `succeeded` | Erfolgreich generiert         | Lesen Sie `task.content.url`, stoppen Sie die Abfrage |
| `failed`    | Generierung fehlgeschlagen     | Lesen Sie `task.error`, stoppen Sie die Abfrage       |
| `cancelled` | Aufgabe wurde storniert       | Stoppen Sie die Abfrage           |

`succeeded`, `failed` und `cancelled` sind Endzustände. Führen Sie nach dem Erreichen eines Endzustands keine weiteren Abfragen durch.

## task Antwortfelder

| Feld                        | Typ      | Beschreibung                          |
| ------------------------- | ------- | ----------------------------------- |
| `id`                      | string  | Aufgaben-ID                          |
| `model`                   | string  | Modell, das für die Aufgabe verwendet wird, derzeit `MiniMax-H3` |
| `status`                  | string  | Aktueller Status der Aufgabe         |
| `error.code`              | string  | Fehlercode bei Misserfolg, nur bei Misserfolg zurückgegeben |
| `error.message`           | string  | Grund für das Scheitern, nur bei Misserfolg zurückgegeben |
| `created_at`              | integer | Erstellungszeit, Unix-Zeitstempel, in Sekunden |
| `updated_at`              | integer | Letzte Aktualisierungszeit des Status, Unix-Zeitstempel, in Sekunden |
| `content.url`             | string  | URL des Videos nach erfolgreicher Erstellung |
| `resolution`              | string  | Ausgabeauflösung, `768P` oder `2K` |
| `duration`                | integer | Dauer des ausgegebenen Videos, in Sekunden |
| `usage.total_seconds`     | integer | Gesamte Kostenmenge, gleich der Summe der Eingangs- und Ausgangssekunden |
| `usage.input_seconds`     | integer | Kostenmenge, die durch das Eingangsvideo verursacht wird |
| `usage.output_seconds`    | integer | Kostenmenge, die durch das Ausgangsvideo verursacht wird |
| `usage.input_image_count` | integer | Anzahl der Eingabebilder in der Abrechnung |
| `ratio`                   | string  | Tatsächliches Ausgabe-Seitenverhältnis; bei Verwendung von `adaptive` ist dies das maßgebliche Ergebnis |
| `task_type`               | string  | Videoerzeugungsaufgabe ist `generation` |
| `modality`                | string  | Videoaufgabe ist `video`           |

## Python Polling Vollständiges Beispiel
以下代码 liest das Token aus den Umgebungsvariablen und fragt alle 10 Sekunden nach der Aufgabe:

```python
import os
import time

import requests

BASE_URL = "https://api.acedata.cloud"
HEADERS = {
    "Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_KEY']}",
    "Content-Type": "application/json",
}

create_response = requests.post(
    f"{BASE_URL}/minimax/videos",
    headers=HEADERS,
    json={
        "model": "MiniMax-H3",
        "content": [
            {
                "type": "text",
                "text": "Am frühen Morgen am Meer fährt ein weißes Segelboot über die ruhige Wasseroberfläche, die Kamera schwenkt langsam.",
            }
        ],
        "resolution": "768P",
        "duration": 4,
        "ratio": "16:9",
    },
    timeout=30,
)
create_response.raise_for_status()
task_id = create_response.json()["task_id"]

while True:
    time.sleep(10)
    query_response = requests.post(
        f"{BASE_URL}/minimax/tasks",
        headers=HEADERS,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    query_response.raise_for_status()
    task = query_response.json()["task"]
    print(f"task={task_id} status={task['status']}")

    if task["status"] == "succeeded":
        print(f"video_url={task['content']['url']}")
        break
    if task["status"] in ("failed", "cancelled"):
        raise RuntimeError(task.get("error") or task["status"])
```

In der Produktionsumgebung sollte eine Gesamtzeitüberschreitung für das Polling festgelegt werden, und für `429` und temporäre `5xx` sollte eine exponentielle Rückoff-Strategie verwendet werden. Netzwerkzeitüberschreitungen bedeuten nicht, dass die Erstellung fehlgeschlagen ist; es kann mit derselben `task_id` weiter abgefragt werden.

## Batch-Abfrage

Geben Sie mehrere Aufgaben-IDs an:

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve_batch",
    "ids": ["TASK_ID_1", "TASK_ID_2"],
    "offset": 0,
    "limit": 20
  }'
```

Listen Sie Aufgaben nach Zeitbereich paginiert auf:

```json
{
  "action": "retrieve_batch",
  "created_at_min": 1786000000,
  "created_at_max": 1786200000,
  "offset": 0,
  "limit": 20
}
```

In der Batch-Antwort verwenden die `items` dasselbe task-Feld wie bei der Einzelabfrage, `total` ist die Gesamtzahl der Aufgaben, die den Filterkriterien entsprechen:

```json
{
  "items": [
    {
      "id": "TASK_ID_1",
      "model": "MiniMax-H3",
      "status": "running",
      "resolution": "2K",
      "duration": 5,
      "ratio": "adaptive",
      "task_type": "generation",
      "modality": "video"
    }
  ],
  "total": 1
}
```

Das Abfragefenster für Aufgaben beträgt die letzten 7 Tage. `task_id`, die über dieses Fenster hinausgeht, kann ungültige Aufgaben zurückgeben; das Geschäftssystem sollte die ID beim Erstellen der Aufgabe speichern und die Ergebnis-URL nach dem Erfolg zeitnah persistieren.

## Aufgaben abbrechen oder löschen

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "delete",
    "id": "YOUR_TASK_ID"
  }'
```

Die Aktion hängt vom aktuellen Status der Aufgabe ab:

| Aktueller Status | Verhalten                     |
| ---------------- | ----------------------------- |
| `queued`         | Abbrechen von noch nicht gestarteten Aufgaben |
| `succeeded`      | Löschen des Aufgabenprotokolls |
| `failed`         | Löschen des Aufgabenprotokolls |
| `running`        | Löschen oder Abbrechen nicht erlaubt, Fehler zurückgeben |
| `cancelled`      | Wiederholte Operation nicht erlaubt, Fehler zurückgeben |

Beispiel für eine erfolgreiche Löschung:

```json
{
  "id": "YOUR_TASK_ID",
  "deleted": true
}
```

Das Löschen des Aufgabenprotokolls hebt keine bereits abgeschlossenen Abrechnungen auf und garantiert nicht, dass die gespeicherten Videokopien gleichzeitig gelöscht werden.

## Fehlgeschlagene Antworten und Fehlersuche

Fehlgeschlagene Aufgaben geben weiterhin ein HTTP 200 zurück und liefern das task-Objekt mit dem Grund in `task.error`:

```json
{
  "task": {
    "id": "YOUR_TASK_ID",
    "model": "MiniMax-H3",
    "status": "failed",
    "error": {
      "code": "1026",
      "message": "Die Videobeschreibung enthält sensible Inhalte"
    },
    "task_type": "generation",
    "modality": "video"
  }
}
```

Wenn die Schnittstelle selbst `400` zurückgibt, sollten `action` und die Bedingungsparameter überprüft werden, `401` bedeutet, dass das Token ungültig ist, `429` bedeutet, dass die Abfragen zu häufig sind, `500` bedeutet, dass der Dienst vorübergehend nicht verfügbar ist. Fehlgeschlagene Aufgaben werden nicht abgerechnet; erfolgreiche Aufgaben werden gemäß dem endgültigen `usage` erfasst.
