Dieser Artikel stellt eine Anleitung zur Integration der SeeDream Images Generation API vor, mit der durch die Eingabe benutzerdefinierter Parameter offizielle Bilder von SeeDream generiert werden können.

## Antragsprozess

Um die SeeDream Images Generation API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API Token zu erhalten und ihn als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um Sie zur Registrierung und Anmeldung einzuladen. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API Token kann alle Dienste der Plattform aufrufen, es ist nicht erforderlich, für jeden Dienst separat einen Antrag zu stellen.** Bei der ersten Beantragung wird ein kostenloses Kontingent verschenkt, das kostenlos getestet werden kann; wenn das Kontingent nicht ausreicht, können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [SeeDream Images Generation API →](https://platform.acedata.cloud/documents/seedream-images)

## Grundlegende Verwendung

Lernen wir zunächst die grundlegende Verwendung kennen: Durch die Eingabe des Prompt-Worts `prompt`, der Generierungsaktion `action` und der Bildgröße `size` können Sie das verarbeitete Ergebnis erhalten. Zunächst muss einfach ein Feld `action` übergeben werden, dessen Wert `generate` ist, und dann müssen wir auch ein Prompt-Wort eingeben. Der konkrete Inhalt lautet wie folgt:

<p><img src="https://cdn.acedata.cloud/seedream_request_body.png" width="500" className="m-auto" /></p>

Hier sehen wir, dass wir die Request Headers festgelegt haben, einschließlich:

- `accept`: Welches Format des Antwortergebnisses empfangen werden soll. Hier wird `application/json` eingetragen, also das JSON-Format.
- `authorization`: Der Schlüssel zum Aufrufen der API, der nach der Beantragung direkt über das Dropdown-Menü ausgewählt werden kann.

Zusätzlich wurde der Request Body festgelegt, einschließlich:

- `prompt`: Prompt-Wort.
- `model`: Generierungsmodell, standardmäßig `doubao-seedream-5-0-lite-260128` (SeeDream 5.0 Lite, neueste Version). Unterstützt `doubao-seedream-5-0-pro-260628`, `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828`. Dabei ist `doubao-seedream-5-0-pro-260628` (SeeDream 5.0 Pro) ein Flaggschiff-Modell für Einzelbilder, das nur Einzelbilder generiert und **keine Bildgruppen (`sequential_image_generation`), Streaming (`stream`) und Websuche (`tools`) unterstützt**. **`model` muss mit der vollständigen Modellzeichenfolge übergeben werden (z. B. `doubao-seedream-5-0-lite-260128`); Kurzformen wie `doubao-seedream-5.0-lite` geben 400 zurück.**
- `image`: Informationen zum eingegebenen Bild, unterstützt URL oder Base64-Kodierung. `doubao-seedream-5-0-pro-260628` unterstützt die Eingabe eines oder mehrerer Bilder (maximal 10 Bilder), `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` unterstützen die Eingabe eines oder mehrerer Bilder.
- `size`: Gibt die Größeninformationen des generierten Bildes an und unterstützt die folgenden zwei Methoden, die nicht gemischt verwendet werden können. Methode 1 | Gibt die Auflösung des generierten Bildes an und beschreibt das Seitenverhältnis des Bildes in natürlicher Sprache im Prompt. **Die von den einzelnen Modellen unterstützten Voreinstellungen unterscheiden sich**: `doubao-seedream-5-0-pro-260628` unterstützt `1K`/`1.5K`/`2K`; `doubao-seedream-5-0-lite-260128` unterstützt `2K`/`3K`/`4K`; `doubao-seedream-4-5-251128` unterstützt nur `2K`/`4K`; `doubao-seedream-4-0-250828` unterstützt `1K`/`2K`/`4K`. Methode 2 | Gibt die Pixelwerte für Breite und Höhe des generierten Bildes an: Standardmäßig `2048x2048`, der Wertebereich der Gesamtpixel und des Seitenverhältnisses variiert je nach Modell (beispielsweise beträgt der Gesamtpixelbereich von 5.0 Pro [921600, 4624220], die Untergrenze der Gesamtpixel für 5.0 Lite / 4.5 beträgt 3,686,400, für 4.0 921,600).
- `sequential_image_generation`: Bildgruppe: Eine Gruppe inhaltlich zusammenhängender Bilder, die basierend auf den von Ihnen eingegebenen Inhalten generiert wird. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` unterstützen diesen Parameter, standardmäßig `disabled`.
- `stream`: Steuert, ob der Streaming-Ausgabemodus aktiviert wird. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` unterstützen diesen Parameter, standardmäßig ist er `false`.
- `response_format`: Gibt das Rückgabeformat des generierten Bildes an. Standardmäßig ist es `url`, auch `b64_json` wird unterstützt.
- `watermark`: Ob dem generierten Bild ein Wasserzeichen hinzugefügt wird. Standardmäßig ist es `true`.
- `output_format`: Gibt das Dateiformat des generierten Bildes an und unterstützt `jpeg` (Standard) und `png`. Wird nur von `doubao-seedream-5-0-pro-260628` und `doubao-seedream-5-0-lite-260128` unterstützt.
- `tools`: Konfiguriert die vom Modell aufzurufenden Tools, derzeit wird `web_search` (Websuche) unterstützt. Wird nur von Seedream 5.0 Lite unterstützt.
- `optimize_prompt_options`: Konfiguration der Prompt-Optimierung. 5.0 Pro unterstützt `standard`/`fast`; 5.0 Lite und 4.5 unterstützen nur `standard`; 4.0 unterstützt `standard`/`fast`.
- `background`: Wird nur von der Einzelbildbearbeitung in 5.0 Pro unterstützt. `transparent` erfordert die Eingabe eines PNG mit transparentem Kanal, und `output_format` muss `png` sein; `opaque` steht für einen gewöhnlichen undurchsichtigen Hintergrund.
- `layer_decomposition`: Wird nur von 5.0 Pro unterstützt. Wenn es auf `true` gesetzt ist, muss ein PNG/JPEG eingegeben werden; `prompt` kann weggelassen werden, um automatisch aufzuteilen, oder Elemente können in natürlicher Sprache/mit `<bbox>` angegeben werden; `size` unterstützt `auto`/`1K`/`1.5K`/`2K`. Dieser Modus kann nicht zusammen mit Bildgruppen, Streaming, Websuche oder `background` verwendet werden.
- `callback_url`: Die URL, an die das Ergebnis zurückgerufen werden soll.
- `async`: Ob im asynchronen Modus verarbeitet wird. Wenn es auf `true` gesetzt ist, gibt die Schnittstelle sofort `task_id` zurück, ohne dass `callback_url` bereitgestellt werden muss; anschließend wird das Ergebnis über `/seedream/tasks` durch Polling abgerufen.

Nach der Auswahl können Sie feststellen, dass auf der rechten Seite ebenfalls der entsprechende Code generiert wurde, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/seedream_image.png" width="500" className="m-auto" /></p>

Klicken Sie auf die Schaltfläche „Try“, um einen Test durchzuführen. Wie in der obigen Abbildung gezeigt, erhalten wir hier das folgende Ergebnis:

```json
    }

```

Das zurückgegebene Ergebnis enthält mehrere Felder, die wie folgt beschrieben werden:

- `success`, der Status der Videoerstellungsaufgabe zu diesem Zeitpunkt.
- `task_id`, die ID der Videoerstellungsaufgabe zu diesem Zeitpunkt.
- `trace_id`, die Tracking-ID der Videoerstellung zu diesem Zeitpunkt.
- `data`, die Ergebnisliste der Bildgenerierungsaufgabe zu diesem Zeitpunkt.
  - `image_url`, der Link der Bildgenerierungsaufgabe zu diesem Zeitpunkt.
  - `prompt`, der Prompt.
  - `size`: die Pixel des generierten Bildes

Man sieht, dass wir zufriedenstellende Bildinformationen erhalten haben. Wir müssen nur die SeeDream-Bilder anhand der Bildlink-Adresse in `data` im Ergebnis abrufen.

Wenn Sie außerdem den entsprechenden Integrationscode generieren möchten, können Sie ihn direkt kopieren und generieren, beispielsweise lautet der CURL-Code wie folgt:

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "doubao-seedream-5-0-lite-260128",
  "prompt": "A single matte blue cube centered on a clean white studio background, neutral lighting"
}'
```

## Bildbearbeitungsaufgabe

Wenn Sie ein bestimmtes Bild bearbeiten möchten, muss zunächst der Parameter `image` mit dem Link des zu bearbeitenden Bildes übergeben werden.

- model：Das Modell, das für diese Bildbearbeitungsaufgabe verwendet wird; `doubao-seedream-5-0-pro-260628`, `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128` und `doubao-seedream-4-0-250828` unterstützen alle Bildeingaben.
- image：Laden Sie ein oder mehrere zu bearbeitende Bilder hoch.

Das Ausfüllbeispiel lautet wie folgt:

<p><img src="https://cdn.acedata.cloud/seedream_edit.png" width="500" className="m-auto" /></p>

Der entsprechende Code:

```python
import requests

url = "https://api.acedata.cloud/seedream/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedream-4-0-250828",
  "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
  "image": ["https://ark-project.tos-cn-beijing.volces.com/doc_image/seedream4_5_imageToimage.png"],
  "size": "2K",
  "watermark": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Klicken Sie auf Ausführen, und Sie werden feststellen, dass sofort ein Ergebnis wie folgt erhalten wird:

```json

  "data": [
    {
      "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
      "size": "2048x2048",
      "image_url": "https://platform.cdn.acedata.cloud/seedream/3e88db7e-4771-4f6a-adbd-5ae4590c5d59.jpg"
```

Man sieht, dass der generierte Effekt ein Bearbeitungseffekt des ursprünglichen Bildes ist, und das Ergebnis dem obigen ähnlich ist.

## Ebenenzerlegung (Seedream 5.0 Pro)

Die Ebenenzerlegung zerlegt ein Eingabebild in 1 Hintergrundbild und bis zu 16 unabhängig bearbeitbare transparente PNG-Ebenen. Die folgende Anfrage lässt das Modell die Hauptelemente automatisch erkennen; wenn Elemente angegeben werden sollen, kann `prompt` hinzugefügt werden, und es können auch normalisierte `<bbox>`-Koordinaten im Prompt verwendet werden.

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "https://example.com/poster.png",
  "layer_decomposition": true,
  "size": "2K",
  "watermark": false
}'
```

Die zurückgegebenen `data` sind nach `z_index` von unten nach oben angeordnet. Der `z_index` des Hintergrundbildes ist 0; Ebenen enthalten außerdem `name`, `description` und `bounding_box.absolute`/`normalized`. Beim Neuzusammensetzen mit absoluten Koordinaten werden die Ebenen auf `[right-left, bottom-top]` skaliert, bei `[left, top]` platziert und dann in aufsteigender Reihenfolge nach `z_index` gestapelt. Wenn die Generierung einer beliebigen Ebene fehlschlägt, schlägt die gesamte Zerlegung fehl.

## Streaming-Ausgabe

Wenn bei Lite/4.x `stream: true` festgelegt wird, verwendet der Anforderungsheader `accept: application/x-ndjson`. Die Schnittstelle gibt zeilenweise `image_generation.partial_succeeded` oder `image_generation.partial_failed` zurück und gibt zuletzt das einzige Ereignis `image_generation.completed` sowie die endgültige `usage` zurück; nur das Abschlussereignis löst eine einmalige Abrechnung aus. Der Streaming-Modus kann nicht zusammen mit `async` oder `callback_url` verwendet werden.

## Asynchroner Callback

Da die Generierungszeit der SeeDream Images Generation API relativ lang ist und ungefähr 1–2 Minuten benötigt, bleibt die HTTP-Anfrage bei einer längeren Nichtantwort der API stets verbunden, was zusätzlichen Verbrauch von Systemressourcen verursacht. Daher bietet diese API auch Unterstützung für asynchrone Callbacks.

Der gesamte Ablauf ist: Wenn der Client eine Anfrage initiiert, gibt er zusätzlich ein Feld `callback_url` an. Nachdem der Client eine API-Anfrage initiiert hat, gibt die API sofort ein Ergebnis zurück, das ein Feld `task_id` enthält, welches die aktuelle Aufgaben-ID darstellt. Nachdem die Aufgabe abgeschlossen ist, wird das Ergebnis der Bildgenerierung in Form von POST JSON an die vom Client angegebene `callback_url` gesendet, die ebenfalls das Feld `task_id` enthält, sodass das Aufgabenergebnis über die ID verknüpft werden kann.

Wenn Sie keine öffentliche Adresse für Callbacks haben, können Sie `callback_url` auch nicht angeben und stattdessen in der Anfrage das Feld `async` auf `true` setzen. Zu diesem Zeitpunkt gibt die Schnittstelle ebenfalls sofort `task_id` zurück, pusht jedoch kein Ergebnis. Sie müssen diese `task_id` mitführen und die Schnittstelle `/seedream/tasks` aufrufen, um den Aufgabenstatus per Polling abzufragen und das endgültige Ergebnis zu erhalten.

Im Folgenden erfahren wir anhand eines Beispiels, wie genau vorzugehen ist.

Klicken Sie auf Ausführen, und Sie werden feststellen, dass sofort ein Ergebnis wie folgt erhalten wird:

```

  "task_id": "c9aaffa2-b8ac-40ff-8468-43e77cb9ddde"
}
```

Der Inhalt lautet wie folgt:
```json
{
    "success": true,
    "task_id": "c9aaffa2-b8ac-40ff-8468-43e77cb9ddde",
    "trace_id": "131a40c3-2eaf-44c9-af28-c9b408577286",
    "data": [
        {
            "prompt": "Behalten Sie die Pose des Models und die fließende Form des Flüssigkeitskleids unverändert bei. Ändern Sie das Kleidungsmaterial von silbernem Metall zu vollständig transparentem Wasser (oder Glas). Durch den Flüssigkeitsfluss sind die Details der Haut des Models sichtbar. Der Licht- und Schatteneffekt verschiebt sich von Reflexion zu Brechung.",
            "size": "2048x2048",
```

Im Ergebnis ist ein Feld `task_id` zu sehen, die anderen Felder sind ähnlich wie oben. Über dieses Feld kann die Zuordnung der Aufgabe realisiert werden.

## Fehlerbehandlung

Wenn bei der Aufrufung der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die Informationen zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
