---
title: "Details einer AceDataCloud-Plattform-Serviceanfrage abrufen"
description: "Platform API guide - Ace Data Cloud"
---

Ruft über die Application ID den vollständigen Status einer einzelnen Serviceanfrage ab — im Vergleich zur Listen-Schnittstelle enthält dies zusätzliche Felder wie das vollständige `service`-Objekt (einschließlich `packages`-Paketen) und eignet sich für Detailseiten.

> ℹ️ Diese Schnittstelle gehört zur **AceDataCloud-Plattformverwaltungs-API** und verwendet einheitlich das Präfix `https://platform.acedata.cloud/api/v1/`. Den vollständigen Schnittstellenindex finden Sie unter [AceDataCloud-Plattformdokumentenliste abrufen](https://platform.acedata.cloud/documents/platform-document-list).

## Schnittstellenübersicht

| Element   | Inhalt                                                                |
| --- | --------------------------------------------------------------------- |
| Methode  | `GET`                                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/{application_id}` |
| Authentifizierung  | ✅ Kontotoken erforderlich                                                              |

`/applications/{id}` und `/applications/{id}/` sind derzeit beide verfügbar; in den Beispielen wird einheitlich die Form ohne abschließenden Schrägstrich verwendet.

## Hinweise zur Authentifizierung (wie man ein Kontotoken erhält)

Request-Header:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Detaillierte Informationen zum Abruf finden Sie unter [AceDataCloud-Plattform-Kontotoken verwalten](https://platform.acedata.cloud/documents/platform-token).

> ℹ️ Anders als bei der Listen-Schnittstelle wird die Berechtigungsprüfung der **Detail-Schnittstelle direkt für ein einzelnes Objekt durchgeführt**, sodass `?user_id=` nicht übergeben werden muss. Wenn Sie jedoch auf die Anfrage einer anderen Person zugreifen, erhalten Sie `403 permission_denied`.

## Pfadparameter

| Parameter               | Typ   | Erforderlich  | Beschreibung             |
| ---------------- | ---- | --- | -------------- |
| `application_id` | UUID | ✅   | Application ID |

## Request-Beispiele

### cURL

```shell
curl 'https://platform.acedata.cloud/api/v1/applications/82f57141-2323-4453-8730-60f7d833a2da' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

app_id = "82f57141-2323-4453-8730-60f7d833a2da"
resp = requests.get(
    f"https://platform.acedata.cloud/api/v1/applications/{app_id}",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}",
    },
    timeout=10,
)
app = resp.json()
print(f"服务：{app['service']['title']}")
print(f"剩余 {app['remaining_amount']} {app['service']['unit']} / 已用 {app['used_amount']}")
```

### Node.js

```javascript
const appId = '82f57141-2323-4453-8730-60f7d833a2da'
const r = await fetch(`https://platform.acedata.cloud/api/v1/applications/${appId}`, {
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log(await r.json())
```

## Beschreibung der Antwortfelder

Die Feldbedeutungen entsprechen der [Listen-Schnittstelle](https://platform.acedata.cloud/documents/platform-application-list), zusätzlich enthalten:

| Feld        | Typ     | Beschreibung                                                        |
| --------- | ------ | --------------------------------------------------------- |
| `service` | object | Vollständiges Serviceobjekt (einschließlich `packages`-Paketen, `unit`, `free_amount`), das direkt zur Darstellung des Service-Detailpanels verwendet werden kann |

## Fehlerbehandlung

| HTTP | code                | Bedeutung                  |
| ---- | ------------------- | ------------------- |
| 401  | `not_authenticated` | Kontotoken fehlt              |
| 403  | `permission_denied` | Diese Application gehört Ihnen nicht  |
| 404  | `not_found`         | Application existiert nicht oder wurde gelöscht |

## Praktische Hinweise

- **Für die Massenüberwachung bevorzugt die Liste verwenden**: Rufen Sie die Application-Liste einmal ab und beurteilen Sie anhand der Einheiten und Schwellenwerte der jeweiligen Services, um einzelne Detailanfragen zu vermeiden.
- **Wenn die Anzahl der Zugangsdaten geprüft werden muss**: Verwenden Sie die [API-Zugangsdatenliste](https://platform.acedata.cloud/documents/platform-credential-list) und filtern Sie nach `application_id`.
- **Vorgehensweise bei `disabled=true`**: Prüfen Sie Tickets / E-Mail-Benachrichtigungen darauf, ob der Service aufgrund von Risikokontrolle, Zahlungsrückständen oder regelwidrigen Aufrufen deaktiviert wurde; eine Aufhebung über die API ist nicht möglich, kontaktieren Sie unbedingt den Kundenservice.
