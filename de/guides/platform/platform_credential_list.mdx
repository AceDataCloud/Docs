Geschäftliche API-Anmeldedaten paginiert auflisten. Diese Antwort enthält derzeit sensible Felder von Token- oder Identity-Anmeldedaten und muss ausschließlich serverseitig verarbeitet werden; das Schreiben in Logs, Analyseplattformen, Frontend-Persistenz oder öffentliche Repositories ist untersagt.

## Vorbereitung

Erstellen Sie einen [Account Token](https://platform.acedata.cloud/documents/platform-token) und rufen Sie über `GET /api/v1/platform-tokens/me/` die UUID des aktuellen Kontos ab.

```shell
export PLATFORM_TOKEN='Ihr Konto-Token'
export USER_ID='Ihre Konto-UUID'
```

## Schnittstellenübersicht

| Element   | Inhalt                                                   |
| --- | ---------------------------------------------------- |
| Methode  | `GET`                                                |
| URL | `https://platform.acedata.cloud/api/v1/credentials/` |
| Authentifizierung  | Account Token, OAuth-Token benötigt `credentials:read`       |
| Paginierung  | `count` + `items`                                    |

Normale Benutzer sollten ihre eigene `user_id` oder eine autorisierte `application_id` übergeben, andernfalls kann bei der Paginierung ein `403` zurückgegeben werden, wenn nicht berechtigte Objekte auftreten.

## Abfrageparameter

| Parameter                 | Typ      | Erforderlich  | Beschreibung                             |
| ------------------ | ------- | --- | ------------------------------ |
| `user_id`          | string  | je nach Szenario | Inhaber der Anmeldedaten; wiederholte Parameter werden unterstützt                   |
| `application_id`   | UUID    | Nein   | Nach Application filtern; wiederholte Parameter werden unterstützt        |
| `host`             | string  | Nein   | Exakt nach Host filtern; wiederholte Parameter werden unterstützt             |
| `name`             | string  | Nein   | Exakt nach Name filtern; wiederholte Parameter werden unterstützt                 |
| `granted`          | boolean | Nein   | `true` für anderen gewährte Anmeldedaten, `false` für eigene Anmeldedaten |
| `limit` / `offset` | integer | Nein   | Paginierung                             |
| `ordering`         | string  | Nein   | `created_at` oder `-created_at`   |

`service_id`, `disabled` und `expired` sind derzeit keine Filterparameter.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/credentials/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Antwortbeschreibung

Die online verifizierte Antwort lautet `{count, items}`. Jeder Eintrag enthält `id`, `application_id`, `application`, `user_id`, `creator_id`, `name`, `type`, `limited_amount`, `used_amount`, `expired_at`, `allowed_api_ids`, `host`, `granted`, `granted_to_user_id`, `tags`, `metadata` und Zeitfelder und gibt je nach Typ `token` oder `username/password` zurück.

> Die aktuelle Listenantwort gibt vollständige sensible Werte zurück. Zeigen Sie diese nicht in der Browser-Konsole oder in Erfassungssystemen an und verlassen Sie sich nicht darauf, Klartext über die Liste wiederherzustellen; Clients sollten mit zukünftigen Strategien zur Maskierung kompatibel sein.
