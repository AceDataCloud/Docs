---
title: "Aktualisieren des Bestellstatus auf der AceDataCloud-Plattform"
description: "Platform API guide - Ace Data Cloud"
---

Fragen Sie proaktiv den neuesten Status der der Bestellung entsprechenden Zahlungsmethode ab und synchronisieren Sie ihn mit der Plattform. Diese Anfrage kann auf Zahlungsdienste zugreifen und den Bestellstatus ändern; verwenden Sie sie nur bei verzögerten Rückrufen oder wenn eine sofortige Bestätigung erforderlich ist.

## Vorbereitungen

- Verwenden Sie den [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Rufen Sie Ihre Bestell-ID aus der [Bestellliste](https://platform.acedata.cloud/documents/platform-order-list) ab.

```shell
export PLATFORM_TOKEN='Ihr Konto-Token'
export ORDER_ID='Ihre Bestell-ID'
```

## Schnittstellenübersicht

| Element    | Inhalt                                                             |
| ---------- | ------------------------------------------------------------------ |
| Methode    | `POST`                                                             |
| URL        | `https://platform.acedata.cloud/api/v1/orders/{order_id}/refresh/` |
| Authentifizierung | Bestellinhaber oder Superadministrator                         |
| Body       | Normalerweise leer; im PayPal-Rückruf-Szenario kann `payer_id` / `PayerID` erforderlich sein |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/refresh/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Bei Erfolg wird das vollständige aktualisierte Order-Objekt zurückgegeben. Verwenden Sie `state`, um das Ergebnis zu bestimmen, und `finished_at` als Abschlusszeitpunkt; das aktuelle Modell hat kein Feld `paid_at`. Zu den Statuswerten gehören `Pending`, `Paid`, `Finished`, `Expired`, `Failed` und `Refunded`.

Die Zahlungsfrist ändert nur Bestellungen, die sich weiterhin im Status `Pending` befinden, in `Expired`. Bereits erstattete Bestellungen im Status `Refunded` bleiben auch nach einer Aktualisierung oder dem Empfang eines verspäteten Zahlungsrückrufs im erstatteten Status.

## Wiederholungsempfehlungen

- Verlassen Sie sich bei normalen Zahlungen vorrangig auf Plattform-Rückrufe; führen Sie nur dann aktiv ein Refresh durch, wenn der Status lange nicht aktualisiert wird.
- Verwenden Sie kein festes hochfrequentes Polling. Es wird exponentielles Backoff empfohlen, und stoppen Sie bei einem eindeutigen Endstatus.
- `401` bedeutet, dass das Token ungültig ist; `403` bedeutet, dass Sie nicht der Bestellinhaber sind; `404` bedeutet, dass die Bestellung nicht existiert.
- Wenn die Abfrage des Zahlungsdienstes fehlschlägt, bewahren Sie die Bestell-ID und die Trace-ID auf und versuchen Sie es später erneut; erstellen Sie keine doppelten Bestellungen als Ersatz für die Statusbestätigung.
