---
title: "Globale Guthabenfreigabe für AceDataCloud Application festlegen"
description: "Platform API guide - Ace Data Cloud"
---

Legen Sie `allow_consume_global` fest. Nach der Aktivierung können berechtigte nutzungsbasierte Applications bei unzureichendem eigenem Guthaben weiterhin das globale Kontoguthaben verwenden.

## Vorbereitung

- Erstellen und speichern Sie sicher einen [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Erhalten Sie aus der [Dienstantragsliste](https://platform.acedata.cloud/documents/platform-application-list) die `application_id`, die Ihnen gehört.

```shell
export PLATFORM_TOKEN='你的账户令牌'
export APPLICATION_ID='你的 Application ID'
```

## Schnittstellenübersicht

| Element    | Inhalt                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------- |
| Methode   | `POST`                                                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/applications/{application_id}/update-allow-consume-global/` |
| Authentifizierung   | Account Token                                                                                      |
| Body | JSON                                                                                               |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/applications/${APPLICATION_ID}/update-allow-consume-global/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"allow_consume_global": true}'
```

Bei Erfolg wird das aktualisierte Application-Objekt zurückgegeben. Maßgeblich ist `allow_consume_global` in der Antwort, statt anzunehmen, dass der Anforderungswert unbedingt gespeichert wurde.

> Applications vom Typ `Period` dürfen kein globales Guthaben verbrauchen. Selbst wenn `true` angefordert wird, hält der Server dieses Feld auf `false`.

## Fehlerbehandlung

- `401`: Account Token ist ungültig oder fehlt.
- `403`: Das aktuelle Konto ist nicht der Eigentümer dieser Application.
- `404`: Application ID existiert nicht.

Der Aufladezugang für globales Guthaben und die verfügbaren Pakete richten sich nach der Plattformkonsole sowie den tatsächlich von [Bestellung erstellen](https://platform.acedata.cloud/documents/platform-order-create) zurückgegebenen Paketen; nehmen Sie nicht an, dass Pakete vom Typ `Wallet` existieren.

## Anwendungen mit autorisiertem Überziehen

Wenn das schreibgeschützte Feld `allow_overdraft=true` einer nutzungsbasierten Anwendung entspricht, kann diese Anwendung weiterhin Gebühren von ihrem eigenen Guthaben abziehen, auch wenn das Guthaben negativ wird, und wechselt nicht aufgrund unzureichenden Guthabens zum globalen Konto. Anwendungen ohne aktiviertes Überziehen folgen weiterhin `allow_consume_global`; ob Überziehen nach dem Wechsel erlaubt ist, richtet sich nach der Einstellung der tatsächlich belasteten globalen Application.

## Parallelitätslimit für Testkonten

Das System verwendet das schreibgeschützte Benutzermerkmal `has_recharged`, um zu erfassen, ob jemals eine kostenpflichtige Aufladung erfolgreich abgeschlossen oder Credits manuell durch einen Administrator hinzugefügt wurden. Das Merkmal wird nach erfolgreicher Durchführung aktualisiert; bei bestehenden Benutzern wird es anhand von Bestellungen oder eindeutigen Aufzeichungen über hinzugefügte Credits einheitlich ergänzt. Für Konten, die weder kostenpflichtig aufgeladen wurden noch manuell durch einen Administrator Credits erhalten haben, darf im gesamten Konto gleichzeitig nur eine abrechenbare Anfrage ausgeführt werden; unterschiedliche API Keys und unterschiedliche Dienste teilen sich diesen einen Platz. Belohnungen, Einlösekarten und übertragene Guthaben gelten nicht als kostenpflichtige Aufladung. Konten, die bereits eine kostenpflichtige Aufladung abgeschlossen haben oder deren Credits manuell durch einen Administrator erhöht wurden, unterliegen diesem Test-Parallelitätslimit nicht und folgen weiterhin den ursprünglichen Guthaben- und Anmeldeinformationskontrollen.

Wenn bereits eine Anfrage ausgeführt wird, gibt eine neue Anfrage `429 too_many_requests` zurück. Kostenlose Polling-Schnittstellen wie Aufgabenabfragen können weiterhin normal aufgerufen werden. Die Verbindungsautorisierung von Realtime folgt weiterhin dem ursprünglichen Abrechnungsprozess pro Runde und belegt diesen Platz für gewöhnliche Anfragen nicht.

Wenn eine asynchrone Schnittstelle „akzeptiert“ zurückgibt, wird die Aufgabe weiterhin ausgeführt; warten Sie auf das Endergebnis, bevor Sie die nächste Generierungsanfrage senden. Eine Netzwerkunterbrechung oder ein Proxy-Timeout bedeutet nicht, dass die Aufgabe bereits beendet wurde; wenn eine Aufgabe längere Zeit keinen Endstatus hat, geben Sie `trace_id` an und kontaktieren Sie den Support zur Überprüfung.

Dieses Limit ändert weder die testbaren Schnittstellen noch die ursprünglichen Abrechnungsregeln. Die Gebühren werden weiterhin nach Abschluss der Anfrage entsprechend der tatsächlichen Nutzung abgerechnet.
