Gibt die Aufladebestellungen des Kontos paginiert zurück, geeignet zum Auffinden von Bestell-IDs, Überprüfen des Zahlungsstatus und Abgleichen.

## Vorbereitung

Erstellen Sie einen [Account Token](https://platform.acedata.cloud/documents/platform-token) und rufen Sie die UUID des aktuellen Kontos über `GET /api/v1/platform-tokens/me/` ab.

```shell
export PLATFORM_TOKEN='Ihr Konto-Token'
export USER_ID='Ihre Konto-UUID'
```

## Schnittstellenübersicht

| Element   | Inhalt                                          |
| --- | ----------------------------------------------- |
| Methode  | `GET`                                           |
| URL | `https://platform.acedata.cloud/api/v1/orders/` |
| Authentifizierung  | Account Token, OAuth-Token benötigt `orders:read`       |
| Paginierung  | `count` + `items`                               |

Normale Benutzer müssen ihre eigene `user_id` übergeben; andernfalls kann bei der Paginierung bei nicht berechtigten Objekten möglicherweise `403` zurückgegeben werden.

## Abfrageparameter

| Parameter                    | Typ       | Erforderlich     | Beschreibung                                                        |
| --------------------- | -------- | ------ | --------------------------------------------------------- |
| `user_id`             | UUID     | Für normale Benutzer erforderlich | Konto, zu dem die Bestellung gehört; unterstützt wiederholte Parameter                                             |
| `pay_way`             | string   | Nein      | Nach Zahlungsart filtern; unterstützt wiederholte oder durch Kommas getrennte Werte                                        |
| `state`               | string   | Nein      | Nach Status filtern; unterstützt wiederholte oder durch Kommas getrennte Werte                                          |
| `created_at_from/to`  | datetime | Nein      | Erstellungszeitraum                                                    |
| `finished_at_from/to` | datetime | Nein      | Abschlusszeitraum                                                    |
| `limit` / `offset`    | integer  | Nein      | Paginierung                                                        |
| `ordering`            | string   | Nein      | `created_at`, `-created_at`, `finished_at` oder `-finished_at` |

Die aktuelle Liste unterstützt keine Filterung nach `application_id`, `service_id`, `package_id`, `payment_method` oder `tag`; der Feldname für die Zahlungsart lautet `pay_way`.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/orders/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'state=Paid,Finished' \
  --data-urlencode 'pay_way=Stripe' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Antwortbeschreibung

Die Antwort lautet `{count, items}`. Die Listeneinträge in der Produktion enthalten `id`, `user_id`, `application_id/application_ids`, `package_id/package_ids`, `price`, `amount`, `discount`, `remaining_amount`, `state`, `pay_way`, `pay_id`, `pay_url`, `finished_at`, `expired_at`, `invoice`, `metadata` und Zeitfelder.

- Die tatsächlichen Status sind `Pending`, `Paid`, `Finished`, `Expired`, `Failed`, `Refunded`; es gibt kein `Cancelled`.
- Die Feldnamen lauten `pay_way`, `finished_at`, `discount` und `price`, nicht `payment_method`, `paid_at`, `discount_rate` oder `final_price`.
- `price` ist der endgültige Preis, der in der Bestellung erfasst ist; Währung und Abrechnungsdetails können sich in kontrollierten Metadaten befinden und dürfen nicht allein anhand der Zahlungsart selbst abgeleitet werden.
