Generieren Sie einen neuen Token oder ein neues Passwort für vorhandene Credentials. Credential-ID, Application-Zuordnung, Limits und andere Felder bleiben unverändert, das alte Geheimnis wird sofort ungültig.

> Die Rotation unterbricht Clients, die noch das alte Geheimnis verwenden. Bereiten Sie zuerst eine sichere Verteilung und einen Rollback-Plan vor und führen Sie dann den Schreibvorgang aus.

## Schnittstellenübersicht

| Element    | Inhalt                                                                      |
| ---------- | --------------------------------------------------------------------------- |
| Methode    | `POST`                                                                      |
| URL        | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}/rotate/` |
| Authentifizierung | Account Token                                                               |
| Body       | Keine oder `{}`                                                             |

Beziehen Sie die `credential_id` aus der [Credential-Liste](https://platform.acedata.cloud/documents/platform-credential-list):

```shell
export PLATFORM_TOKEN='你的账户令牌'
export CREDENTIAL_ID='要轮换的 Credential ID'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/credentials/${CREDENTIAL_ID}/rotate/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Bei Erfolg wird das aktualisierte Credential zurückgegeben. Lesen Sie bei `type=Token` den neuen `token`; lesen Sie bei `type=Identity` das neue `password`. Behandeln Sie die vollständige Antwort als Geheimnis und aktualisieren Sie die Aufrufer sofort.

## Fehlerbehandlung

- `401`: Account Token ungültig.
- `403`: Keine Berechtigung zur Verwaltung dieses Credentials.
- `404`: Credential-ID existiert nicht.
