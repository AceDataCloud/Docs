title: "Abrufen der Liste der AceDataCloud-Plattform-Serviceanträge"
description: "Platform API guide - Ace Data Cloud"

Gibt paginiert die Applications zurück, die das Konto besitzt oder deren Nutzung ihm autorisiert wurde, einschließlich Guthaben, Status, Servicezusammenfassung und zugehörigen Zugangsdaten. Geeignet für die Batch-Guthabenüberwachung, das Auffinden von Application-IDs und den Zugriff auf die Zugangsdatenverwaltung.

## Vorbereitungen

1. Melden Sie sich bei der [AceDataCloud-Plattform](https://platform.acedata.cloud) an.
2. Erstellen Sie in der [Account-Token-Konsole](https://platform.acedata.cloud/console/platform-tokens) einen Account-Token.
3. Normale Benutzer verwenden `user_id=me`; Sie können auch über `GET /api/v1/platform-tokens/me/` Ihre eigene UUID abrufen.

```shell
export PLATFORM_TOKEN='你的账户令牌'
```

## API-Übersicht

| Element   | Inhalt                                                    |
| --- | ----------------------------------------------------- |
| Methode  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Authentifizierung  | Account-Token, OAuth-Token benötigt `applications:read`       |
| Paginierung  | `count` + `items`                                     |

Normale Benutzer sollten `user_id=me` übergeben. Wenn dies nicht übergeben wird, wird die Abfrage nicht zuerst nach Konto eingeschränkt, und bei der Paginierung können nicht berechtigte Objekte `403` zurückgeben; Administratoren können ohne Übergabe die gesamte Tabelle einsehen.

## Abfrageparameter

| Parameter            | Typ          | Erforderlich     | Beschreibung                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Für normale Benutzer erforderlich | Abfragesubjekt; unterstützt wiederholte Parameter                                         |
| `affiliation` | string      | Nein      | `owner` (Standard) oder `granted`; beide können wiederholt übergeben werden, um die Vereinigungsmenge zu erhalten, und sind nur wirksam, wenn `user_id` vorhanden ist |
| `service_id`  | UUID        | Nein      | Nach Service filtern; unterstützt wiederholte Parameter                                        |
| `scope`       | string      | Nein      | `Individual` oder `Global`; unterstützt wiederholte Parameter                      |
| `type`        | string      | Nein      | `Usage` oder `Period`; unterstützt wiederholte Parameter                           |
| `limit`       | integer     | Nein      | Anzahl der Einträge pro Seite, maximal 100                                         |
| `offset`      | integer     | Nein      | Paginierungs-Offset                                               |
| `ordering`    | string      | Nein      | Unterstützt nur `created_at` oder `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` und `tag` sind derzeit keine serverseitigen Filterparameter. Für Guthabenwarnungen sollte nach dem Abrufen der Liste anhand von `remaining_amount`, `service.unit` und geschäftlichen Schwellenwerten jedes Application-Objekts clientseitig entschieden werden.

## Anfragebeispiele

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Gleichzeitig die Applications anzeigen, die man selbst besitzt und die andere einem selbst autorisiert haben:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Antwortbeschreibung

Die Antwort lautet `{count, items}`. Jeder Eintrag enthält die Application-Modellfelder und zusätzlich:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: die Zugangsdatenzusammenfassung, die der aktuelle Aufrufer sehen darf;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`;
- der tatsächliche Wert von `scope` ist `Individual` oder `Global`;
- der tatsächliche Wert von `type` ist `Usage` oder `Period`.

`remaining_amount` kann leer sein; der Client muss zuerst auf einen leeren Wert prüfen und anschließend Zahlen vergleichen. Die Einheit des Kontingents wird durch `service.unit` bestimmt.
