Gibt API-Endpunkte zurück, die auf der aktuellen Website sichtbar sind. Geeignet zum Suchen von APIs nach Geschäftspfad, Service oder Bereitstellungsphase; wenn Sie nur die vollständige Definition einer API benötigen, rufen Sie direkt die [API-Details](https://platform.acedata.cloud/documents/platform-api-detail) auf.

## Schnittstellenübersicht

| Element   | Inhalt                                        |
| --- | --------------------------------------------- |
| Methode  | `GET`                                         |
| URL | `https://platform.acedata.cloud/api/v1/apis/` |
| Authentifizierung  | Öffentlich, kein Kontotoken erforderlich                                     |
| Paginierung  | `count` + `items`                             |

## Abfrageparameter

| Parameter        | Typ      | Erforderlich  | Beschreibung                    |
| --------- | ------- | --- | --------------------- |
| `path`    | string  | Nein   | Exakte Übereinstimmung mit `path` oder `path2` |
| `service` | string  | Nein   | Service-Alias oder UUID       |
| `stage`   | string  | Nein   | Nach Bereitstellungsphase filtern; mehrere Werte können wiederholt übergeben werden      |
| `limit`   | integer | Nein   | Anzahl pro Seite, maximal 100           |
| `offset`  | integer | Nein   | Paginierungsversatz                 |

`id`, `service_id` und `tag` sind derzeit keine Listenfilterparameter; ihre Übergabe erzeugt keinen entsprechenden Filtereffekt.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/apis/' \
  --data-urlencode 'service=midjourney' \
  --data-urlencode 'stage=Production' \
  --data-urlencode 'limit=20' \
  -H 'Accept: application/json'
```

```python
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/apis/",
    params={"service": "midjourney", "limit": 20},
    timeout=30,
)
response.raise_for_status()
for api in response.json()["items"]:
    print(api["id"], api["method"], api["path"])
```

## Antwortbeschreibung

Die Produktionsantwort verwendet `{count, items}`. Jeder Listeneintrag enthält derzeit die API-Modellfelder sowie:

- `document_id`: Zugehörige Entwicklerdokument-ID, kann leer sein;
- `service_id` / `service`: Primäre Service-ID und Zusammenfassung, können leer sein;
- `definition`: OpenAPI-Definition, kann groß sein;
- `method`, `path`, `path2`, `stage`, `cost`, `tags`, `metadata` usw.

Der Listen-Serializer enthält derzeit `definition`; beim Abrufen des vollständigen Katalogs sollten Sie paginieren und ein Timeout festlegen. Felder können abwärtskompatibel hinzugefügt werden; der Client liest nur die benötigten Felder.
