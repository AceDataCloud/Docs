---
title: "API-Anmeldedaten für die AceDataCloud-Plattform erstellen"
description: "Platform API guide - Ace Data Cloud"
---

Erstellen Sie geschäftliche API-Anmeldedaten für eine Application. Die Erstellungsausgabe kann ein Token enthalten, das `https://api.acedata.cloud/**` direkt aufrufen kann, oder einen Benutzernamen/ein Passwort für Anmeldedaten vom Typ Proxy; diese müssen als Geheimnisse behandelt werden.

## Vorbereitungen

1. Erstellen Sie einen [Account Token](https://platform.acedata.cloud/documents/platform-token).
2. Rufen Sie aus der [Application-Liste](https://platform.acedata.cloud/documents/platform-application-list) die Ihnen gehörende `application_id` ab.

```shell
export PLATFORM_TOKEN='Ihr Account-Token'
export APPLICATION_ID='Ihre Application-ID'
```

## Schnittstellenübersicht

| Element    | Inhalt                                                   |
| ---- | ---------------------------------------------------- |
| Methode   | `POST`                                               |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/` |
| Authentifizierung   | Account Token, OAuth-Token benötigt `credentials:write`      |
| Body | JSON                                                 |

## Request-Body

| Feld                  | Typ              | Erforderlich  | Beschreibung                            |
| ------------------- | --------------- | --- | ----------------------------- |
| `application_id`    | UUID            | Ja   | Ziel-Application                |
| `name`              | string          | Nein   | Anzeigename der Anmeldedaten                         |
| `limited_amount`    | number / null   | Nein   | Nutzungslimit pro Anmeldedatum; `null` bedeutet kein separates Limit       |
| `expired_at`        | datetime / null | Nein   | ISO-8601-Ablaufzeit                 |
| `allowed_api_ids`   | UUID[] / null   | Nein   | Nur Aufrufe dieser APIs zulassen; ein leeres Array wird zu keiner Einschränkung normalisiert       |
| `host`              | string          | Nein   | Host-Informationen der Anmeldedaten                    |
| `for_user_id`       | string          | Nein   | Wird verwendet, wenn der Application-Eigentümer Autorisierungsanmeldedaten für einen anderen Benutzer ausstellt |
| `tags` / `metadata` | array / object  | Nein   | Benutzerdefinierte Erweiterungsdaten                       |

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/credentials/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"name\":\"production\",\"limited_amount\":50}"
```

## Beschreibung der Antwort

Bei Erfolg werden `201` und ein Credential-Objekt zurückgegeben:

- Dienste vom Typ API/Agent geben normalerweise `type=Token` und `token` zurück;
- Dienste vom Typ Proxy geben normalerweise `type=Identity` und `username` / `password` zurück, und eine Proxy-Application erlaubt nur eine Anmeldedatum;
- `id`, `user_id`, `creator_id`, `used_amount` und Zeitfelder werden serverseitig generiert.

Die aktuellen Listen- und Detail-Schnittstellen geben ebenfalls die Klartext-Anmeldedaten zurück, aber Clients sollten sich nicht auf dieses historische Verhalten verlassen. Speichern Sie sie unmittelbar nach der Erstellung und vermeiden Sie es, die Antwort in Protokolle zu schreiben; zukünftige Schnittstellen können zu einer maskierten Rückgabe geändert werden.

## Fehlerbehandlung

- `400`: Fehlerhaftes Feldformat, unbekannte `allowed_api_ids`, die Proxy-Application besitzt bereits Anmeldedaten oder andere Erstellungseinschränkungen.
- `401`: Account Token ist ungültig.
- `403/404`: Keine Berechtigung für den Zugriff auf die Ziel-Application, oder die Application/der autorisierte Benutzer existiert nicht.
