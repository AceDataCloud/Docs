---
title: "Erstellen einer AceDataCloud-Plattform-Aufladebestellung"
description: "Platform API guide - Ace Data Cloud"
---

Erstellen Sie eine unbezahlte Bestellung für eine oder mehrere Applications. Die Erstellung schreibt die Bestellung, führt die Zahlung jedoch nicht automatisch aus; vor der Zahlung sollten `price`, das Paket und die Application in der Antwort überprüft werden.

## Vorbereitung

- Erstellen Sie einen [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Rufen Sie die `application_id` aus der [Application-Liste](https://platform.acedata.cloud/documents/platform-application-list) ab.
- Wählen Sie aus den `packages` der [Service-Details](https://platform.acedata.cloud/documents/platform-service-detail) eine kaufbare `package_id` aus, die zum Application-Typ passt.

```shell
export PLATFORM_TOKEN='你的账户令牌'
export APPLICATION_ID='你的 Application ID'
export PACKAGE_ID='你的 Package ID'
```

## Schnittstellenübersicht

| Element    | Inhalt                                          |
| ---------- | ----------------------------------------------- |
| Methode    | `POST`                                          |
| URL        | `https://platform.acedata.cloud/api/v1/orders/` |
| Authentifizierung | Account Token, OAuth token benötigt `orders:write` |
| Body       | JSON                                            |

## Request-Body

Für Bestellungen einer einzelnen Application verwenden Sie `application_id` + `package_id`; für Batch-Bestellungen verwenden Sie `application_ids` + `package_ids` mit entsprechenden Längen. Bei normalen Bestellungen wird die Zahlungsmethode in der anschließenden `/pay/`-Anfrage ausgewählt. Bei iOS-In-App-Kauf-Bestellungen übergeben Sie bei der Erstellung `pay_way: "AppleIAP"` und können nur ein Usage-Paket mit `metadata.apple_product_id` und `metadata.apple_price` auswählen. Apple-In-App-Käufe verwenden unabhängige voreingestellte Preise in US-Dollar und kombinieren keine Mitgliederrabatte, Zahlungsmethodenrabatte oder Standortaufschläge; der Abbuchungsbetrag in der lokalen Währung anderer Regionen richtet sich nach der Apple-Zahlungsbestätigungsseite.

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/orders/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"package_id\":\"${PACKAGE_ID}\"}"
```

## Beschreibung der Antwort

Bei Erfolg werden `201` und das neu erstellte Order-Objekt zurückgegeben. Zu den wichtigen Feldern gehören `id`, `price`, `discount`, `state`, `application_id/application_ids`, `package_id/package_ids`, `expired_at` und Zeitfelder. Neue Bestellungen sind normalerweise `Pending`; rufen Sie anschließend [Bestellung bezahlen](https://platform.acedata.cloud/documents/platform-order-pay) auf.

- `price` ist der vom Server anhand des Pakets, des Standortaufschlags und der Rabatte berechnete zu zahlende Betrag; berechnen Sie ihn nicht selbst auf dem Client.
- Wenn Package und Application-Service oder -Typ nicht übereinstimmen, wird `400` zurückgegeben.
- Kostenlose und vom System verwaltete Packages können nicht über die öffentliche Bestellschnittstelle selbst bezogen werden.
- Das Erstellen einer Bestellung für eine Application, die nicht zum aktuellen Konto gehört, wird abgelehnt.
