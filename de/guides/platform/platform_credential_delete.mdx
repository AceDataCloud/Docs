Eine API-Anmeldeinformation dauerhaft löschen. Nach dem Löschen ist sie **sofort nicht wiederherstellbar**, und alle Geschäftsschnittstellen, die dieses Token verwenden, erhalten umgehend `401`.

> ℹ️ Diese Schnittstelle gehört zur **AceDataCloud-Plattformverwaltungs-API**, mit dem einheitlichen Präfix `https://platform.acedata.cloud/api/v1/`.

## Schnittstellenübersicht

| Punkt   | Inhalt                                                              |
| --- | ------------------------------------------------------------------- |
| Methode  | `DELETE`                                                            |
| URL | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}` |
| Authentifizierung  | ✅ Kontotoken erforderlich                                                            |

`/credentials/{id}` und `/credentials/{id}/` sind derzeit beide verfügbar; die Beispiele verwenden einheitlich die Form ohne abschließenden Schrägstrich.

## Authentifizierungshinweise (wie man ein Kontotoken erhält)

Request-Header:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Informationen zur Beschaffung finden Sie unter [AceDataCloud-Plattform-Kontotoken verwalten](https://platform.acedata.cloud/documents/platform-token).

## Pfadparameter

| Parameter              | Typ   | Erforderlich  | Beschreibung        |
| --------------- | ---- | --- | --------- |
| `credential_id` | UUID | ✅   | ID der zu löschenden Anmeldeinformation |

## Request-Beispiele

### cURL

```shell
curl -X DELETE 'https://platform.acedata.cloud/api/v1/credentials/df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

cred_id = "df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6"
resp = requests.delete(
    f"https://platform.acedata.cloud/api/v1/credentials/{cred_id}",
    headers={"authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    timeout=10,
)
assert resp.status_code == 204, resp.text
print("✅ 已删除")
```

### Node.js

```javascript
const credId = 'df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6'
const r = await fetch(`https://platform.acedata.cloud/api/v1/credentials/${credId}`, {
  method: 'DELETE',
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log('status:', r.status) // 204
```

## Antwort

- **Erfolg**: `HTTP 204 No Content`, **kein Antworttext**.
- **Fehler**: Gibt Fehler-JSON zurück, siehe Tabelle unten.

## Fehlerbehandlung

| HTTP | code                | Bedeutung         |
| ---- | ------------------- | ---------- |
| 401  | `not_authenticated` | Kontotoken fehlt     |
| 403  | `permission_denied` | Diese Anmeldeinformation gehört nicht Ihnen    |
| 404  | `not_found`         | Die Anmeldeinformation existiert nicht oder wurde bereits gelöscht |

## Praktische Hinweise

- **Das Löschen ist unumkehrbar**——die Plattform behält keine Token-Kopien. Wenn Sie lediglich einen möglichen Leak vermuten und Überwachungsdaten behalten möchten, sollten Sie [AceDataCloud-Plattform-API-Anmeldedaten rotieren](https://platform.acedata.cloud/documents/platform-credential-rotate), statt sie zu löschen.
- **Das Löschen erstattet nicht das bereits von dieser Anmeldeinformation verbrauchte Kontingent**. Das Application-Guthaben wird entsprechend dem Verbrauch in Echtzeit abgezogen; das Löschen der Anmeldeinformation hat keinen Einfluss auf den ausgewiesenen Guthabenstand.
- Nach dem Löschen können Sie über die [API-Anmeldedatenliste](https://platform.acedata.cloud/documents/platform-credential-list) anhand von `application_id` die verbleibenden Anmeldeinformationen erneut bestätigen.
- **Vor einer Massenbereinigung zunächst die Aufrufer prüfen**: Die Liste enthält derzeit kein Feld für die letzte Nutzungszeit; Sie sollten anhand der Bereitstellungskonfiguration und Aufrufprotokolle bestätigen, dass die Anmeldeinformation nicht mehr verwendet wird, bevor Sie sie einzeln löschen.
