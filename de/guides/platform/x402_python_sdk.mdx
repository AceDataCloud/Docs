Das Python SDK eignet sich für Backend-Dienste, Datenaufgaben, automatisierte Agents und Batch-Skripte. `acedatacloud` ist für API-Aufrufe zuständig, `acedatacloud-x402` ist für das Ausstellen des Request-Headers `PAYMENT-SIGNATURE` zuständig.

Quellcode- und Paketadressen:

- SDK-Repository: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- X402-Client-Repository: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- PyPI SDK: [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)
- PyPI X402 Client: [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)

## Abhängigkeiten installieren

```bash
pip install acedatacloud acedatacloud-x402
```

Um `upto` zu verwenden, muss außerdem einmalig die Permit2-approve-CLI aufgerufen werden; diese CLI hängt von `web3` ab:

```bash
pip install 'acedatacloud-x402[cli]'
```

Installations- und Importprüfungs-Ausgabe einer sauberen Python-venv:

```text
acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
approve-permit2  One-time ERC-20 approve(Permit2, amount) needed before signing upto payments.
```

Ergebniserklärung:

- Sowohl `acedatacloud` als auch `acedatacloud-x402` können von PyPI installiert und importiert werden.
- `pip install 'acedatacloud-x402[cli]'` installiert die CLI `approve-permit2`, die für die vorherige Autorisierung von `upto` verwendet wird.

## Base-Beispiel

Das folgende Beispiel benötigt kein API-Token. Der private Schlüssel der Wallet wird nur lokal signiert und nicht an Ace Data Cloud gesendet.

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)

print(res["choices"][0]["message"]["content"])
```

Das Python SDK gibt derzeit ein `dict` zurück, daher verwendet das Beispiel `res["choices"][0]["message"]["content"]`. Gehe nicht direkt davon aus, dass es zwingend ein Attribut `.choices` hat.

## Solana-Beispiel

Solana verwendet einen base58-kodierten Secret Key:

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import SolanaKeypairSigner, create_x402_payment_handler

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="solana",
        solana_signer=SolanaKeypairSigner.from_base58(os.environ["SOLANA_SECRET_KEY"]),
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

Der Solana-Pfad erstellt und übermittelt eine SPL-USDC-`TransferChecked`-Transaktion und legt anschließend die Transaktionssignatur in den `PAYMENT-SIGNATURE`-Envelope.

Der kostenpflichtige Solana-Retry hat auf der Produktions-API bereits HTTP 200 und `ADC_SOLANA_E2E_OK` zurückgegeben. Bei dieser öffentlichen RPC-Abfrage trat Rate Limiting auf, daher konnte die On-Chain-Signatur nicht stabil bestätigt werden; verwende bei Bedarf für den Abgleich deinen eigenen Solana RPC, um diese Transaktion abzufragen.

## Async-Client

Derselbe Payment Handler kann für `AsyncAceDataCloud` verwendet werden:

```python
import os

from acedatacloud import AsyncAceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AsyncAceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = await client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

## Nachgelagerte Abrechnung mit `upto` verwenden

Die tatsächlichen Kosten von APIs wie Chat Completions und Modellaufrufen können möglicherweise erst nach Abschluss der Antwort bestimmt werden. In diesem Fall kann die API gleichzeitig `exact` und `upto` zurückgeben. Um `upto` bevorzugt zu verwenden:

```python
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
        prefer_scheme="upto",
    )
)
```

Programmausgabe von Base `upto`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
settlement tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
settled value 3 atomic USDC
```

On-Chain-Bestätigung:

```text
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
transfer value 3 atomic USDC
```

Ergebniserklärung:

- `content ADC_BASE_UPTO_OK` zeigt, dass die Anfrage tatsächlich die Modell-API erreicht hat.
- `settled value 3 atomic USDC` zeigt, dass `upto` nach der tatsächlichen Nutzung abrechnet, anstatt den vollständigen Höchstbetrag abzuziehen.
- `settlement tx` kann in BaseScan geöffnet werden; speichere beim Abgleich den Tx-Hash, den Payer, die Completion-ID und die Anfragezusammenfassung.

`upto` verwendet eine Permit2-Autorisierung für einen Höchstbetrag, und der tatsächlich abgerechnete Betrag darf diesen Höchstbetrag nicht überschreiten. Vor der ersten Verwendung muss für USDC auf der Ziel-Chain einmal `approve(Permit2, amount)` ausgeführt werden.

CLI-Methode:

```bash
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Programmatische Methode:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Dieser Helper ist idempotent. Wenn die Allowance bereits ausreicht, wird `{"skipped": true}` zurückgegeben, und es wird keine weitere On-Chain-Transaktion gesendet.

## Signierung auf niedriger Ebene

Wenn du das SDK nicht verwendest, kannst du auch direkt die Signierfunktion auf niedriger Ebene aufrufen:

```python
import base64
import json

from acedatacloud_x402 import EVMAccountSigner, sign_evm_payment

envelope = sign_evm_payment(requirement, EVMAccountSigner.from_private_key("0x..."))
x_payment = base64.b64encode(json.dumps(envelope, separators=(",", ":")).encode()).decode()
```

Funktionen auf niedriger Ebene eignen sich für Tests, Proxy-Schichten, Gateway-Integrationen oder nicht offizielle SDKs. Für normalen Geschäftscode sollte vorrangig `create_x402_payment_handler` verwendet werden.
