title: "Dateien auf die AceDataCloud-Plattform-CDN hochladen"

Laden Sie lokale Dateien auf die AceDataCloud-Plattform-CDN hoch, um eine öffentlich zugängliche URL zu erhalten (im Stil von `https://cdn.acedata.cloud/xxxxxx.png`), die sofort in Parametern wie `image_url`, `reference_url` usw. anderer Geschäfts-APIs (z. B. Midjourney, Suno, Flux) referenziert werden kann.

Anwendungsfälle:

- Laden Sie vor dem Aufruf von Midjourney `/midjourney/imagine` zuerst das Referenzbild auf die CDN hoch, um die URL zu erhalten.
- Zwischenspeichern Sie das im vorherigen Schritt generierte Video, um es als Eingabe für den nächsten Schritt zu verwenden.
- Hosten Sie von Benutzern hochgeladene Materialien temporär, um den Aufbau eines eigenen S3 zu vermeiden.

> ℹ️ Diese Schnittstelle gehört zur **AceDataCloud-Plattformverwaltungs-API**, mit dem einheitlichen Präfix `https://platform.acedata.cloud/api/v1/`.

## Schnittstellenübersicht

| Element            | Inhalt                                             |
| ------------ | ---------------------------------------------- |
| Methode           | `POST`                                         |
| URL          | `https://platform.acedata.cloud/api/v1/files/` |
| Authentifizierung           | ✅ Kontotoken erforderlich                                       |
| Content-Type | `multipart/form-data`（**kein JSON**）             |

## Hinweise zur Authentifizierung (wie man einen Kontotoken erhält)

Anfrage-Header:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Bezugsmethode: Melden Sie sich bei der [AceDataCloud-Plattform](https://platform.acedata.cloud) an → [Account-Token-Konsole](https://platform.acedata.cloud/console/platform-tokens) → Klicken Sie auf die Schaltfläche „Erstellen“. Details siehe [AceDataCloud-Plattformkontotoken verwalten](https://platform.acedata.cloud/documents/platform-token).

## Anfragekörper（multipart/form-data）

| Feld     | Typ   | Erforderlich  | Beschreibung                        |
| ------ | ---- | --- | ------------------------- |
| `file` | file | ✅   | Binärer Dateistream. **Das Standardlimit pro Datei beträgt 100 MB** |

## Anfragebeispiele

### cURL

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/files/' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}" \
  -F 'file=@./photo.jpg'
```

### Python

```python
import os
import requests

PLATFORM_TOKEN = os.environ["PLATFORM_TOKEN"]

with open("photo.jpg", "rb") as f:
    resp = requests.post(
        "https://platform.acedata.cloud/api/v1/files/",
        headers={
            "accept": "application/json",
            "authorization": f"Bearer {PLATFORM_TOKEN}",
        },
        files={"file": ("photo.jpg", f, "image/jpeg")},
        timeout=60,
    )

data = resp.json()
print(f"✅ 上传成功：{data['file_url']}")
# 直接用于其他业务接口：
# requests.post("https://api.acedata.cloud/midjourney/imagine",
#     json={"prompt": "...", "image_urls": [data["file_url"]]}, ...)
```

### Node.js

```javascript
const fs = require('fs')
const FormData = require('form-data')

const form = new FormData()
form.append('file', fs.createReadStream('./photo.jpg'))

const r = await fetch('https://platform.acedata.cloud/api/v1/files/', {
  method: 'POST',
  headers: {
    authorization: `Bearer ${process.env.PLATFORM_TOKEN}`,
    ...form.getHeaders(),
  },
  body: form,
})
const data = await r.json()
console.log('CDN URL:', data.file_url)
```

## Antwortbeispiel（HTTP 200）

```json
{
  "file_url": "https://cdn.acedata.cloud/qrd7gw.jpg"
}
```

Nehmen Sie einfach das Feld `file_url` und verwenden Sie es in anderen Geschäfts-APIs — die CDN-URL ist derzeit öffentlich zugänglich und erfordert keine Authentifizierung; betrachten Sie sie nicht als Zusage für eine dauerhafte Archivierung.

## Beschreibung der Antwortfelder

| Feld         | Typ     | Beschreibung         |
| ---------- | ------ | ---------- |
| `file_url` | string | CDN-Zugriffs-URL |

## Fehlerbehandlung

| HTTP | Antwortbeispiel                                         | Bedeutung                 |
| ---- | -------------------------------------------- | ------------------ |
| 400  | `{"error":"No file provided"}`               | Das Feld `file` wurde nicht angehängt oder der Feldname ist falsch |
| 401  | DRF-Authentifizierungsfehlerantwort                                   | Kontotoken fehlt oder ist ungültig       |
| 413  | `{"error":"File too large","max_bytes":...}` | Datei überschreitet 100 MB (Standard)    |

## Praktische Hinweise

- **Bilder als Referenzbilder hochladen**: Midjourney `image_urls`, Flux `image_url`, Veo `reference_url` akzeptieren alle CDN-URLs, **nicht** base64. Zuerst über diese Schnittstelle eine URL zu erhalten, ist die übliche Vorgehensweise.
- **Keine sensiblen Daten hochladen**: Die zurückgegebene URL ist öffentlich zugänglich; die Aufbewahrungsdauer richtet sich nach der aktuellen Speicherstrategie der Plattform. Verwenden Sie für die Langzeitarchivierung Ihren eigenen Objektspeicher.
- **Uploads großer Mengen**: Begrenzen Sie die Parallelität und legen Sie für jeden Upload ein Timeout fest; der Durchsatz hängt von Dateigröße und Netzwerkumgebung ab.

## Verwandte Schnittstellen

- [AceDataCloud-Plattformdienstliste abrufen](https://platform.acedata.cloud/documents/platform-service-list) — Geschäftsservices finden, die URL-Eingaben akzeptieren
- [AceDataCloud-Plattform-API-Anmeldedaten erstellen](https://platform.acedata.cloud/documents/platform-credential-create) — Nach dem Upload besteht der nächste Schritt normalerweise darin, Anmeldedaten zu erstellen, um Geschäfts-APIs aufzurufen
