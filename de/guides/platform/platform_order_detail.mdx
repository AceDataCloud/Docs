---
title: "Details einer AceDataCloud-Plattformbestellung abrufen"
description: "Platform API guide - Ace Data Cloud"
---

Eine Bestellung über die Bestell-ID abfragen. Dieser Endpunkt unterstützt zwei Lesemodi: Anonymer Zugriff gibt nur die für die Zahlungsseite erforderlichen Minimalfelder zurück; der Bestellinhaber erhält mit einem Account-Token vollständige Details.

## Schnittstellenübersicht

| Punkt   | Inhalt                                                        |
| --- | --------------------------------------------------------- |
| Methode  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| Authentifizierung  | Optional; anonym mit minimaler Projektion, authentifizierter Inhaber mit vollständiger Projektion                                    |

`/orders/{id}` und `/orders/{id}/` sind derzeit beide verfügbar. Die Bestell-ID ist Teil des Zahlungslinks und sollte als sensible intransparente Kennung betrachtet und nicht öffentlich verbreitet werden.

## Anonyme Abfrage

Die Zahlungsseite kann bei Verlust des Anmeldestatus direkt lesen:

```shell
export ORDER_ID='deine Bestell-ID'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

Die anonyme Antwort enthält nur `id`, `description`, `price`, `state`, `pay_way`, `pay_url`, `expired_at`, `created_at`. Sie gibt weder Konto, Application, Package, interne Zahlungskennungen noch metadata zurück.

## Authentifizierte Abfrage

```shell
export PLATFORM_TOKEN='dein Kontotoken'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Der Bestellinhaber erhält vollständige Order-Details, einschließlich `application` / `applications`, `package` / `packages`, `bank_details`, `invoice_automation` und Modellfeldern. Wenn authentifiziert, aber nicht der Bestellinhaber, wird `403` zurückgegeben; Superadministratoren sind ausgenommen.

## Schlüsselfelder

| Feld            | Beschreibung                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`, `Paid`, `Finished`, `Expired`, `Failed` oder `Refunded` |
| `pay_way`     | Aktuelle Zahlungsmethode der Bestellung; der Feldname ist nicht `payment_method`                             |
| `pay_url`     | Gehostete Zahlungsseite oder QR-Code-Adresse, kann leer sein                                           |
| `price`       | Endgültig zu zahlender Betrag der Bestellung; das aktuelle Bestellmodell stellt kein Feld `final_price` bereit                         |
| `amount`      | Anzahl der Paketkontingente; nur in der vollständig authentifizierten Antwort sichtbar                                            |
| `finished_at` | Zeitpunkt des Bestellabschlusses; der Feldname ist nicht `paid_at`                                      |

Die vollständige Antwort kann je nach Zahlungsmethode zusätzliche Felder enthalten. Clients sollten diese bei Bedarf lesen und stets vermeiden, sensible metadata aus der vollständigen Antwort zu protokollieren.

## Fehlerbehandlung

- `404`: Die Bestell-ID existiert nicht.
- `403`: Angemeldet, aber nicht der Bestellinhaber.
- Anonyme Anfragen geben kein `401` zurück; sie erhalten nur die minimale öffentliche Projektion.
