[NextChat](https://github.com/ChatGPTNextWeb/NextChat) (früher ChatGPT-Next-Web) ist ein Open-Source-AI-Client, der auf Vercel, Cloudflare oder Docker bereitgestellt werden kann. Es unterstützt benutzerdefinierte OpenAI-kompatible Endpunkte und kann daher mit Ace Data Cloud verbunden werden. Dieser Artikel stellt den Konfigurationsprozess vor.

## Antragsprozess

Um Ace Data Cloud in NextChat einzubinden, gehen Sie zunächst zur [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications), holen Sie sich Ihren API-Token und bewahren Sie ihn als Reserve auf.

![Ace Data Cloud API Key abrufen](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach der Anmeldung und Registrierung kehren Sie automatisch zu dieser Seite zurück.

Bei der ersten Beantragung wird ein kostenloses Guthaben verschenkt, mit dem Sie die Modelldienste von Ace Data Cloud kostenlos ausprobieren können.

## NextChat herunterladen

Sie können die Desktop-Version verwenden (auf der [Releases-Seite](https://github.com/ChatGPTNextWeb/NextChat/releases) `.exe` / `.dmg` / AppImage herunterladen), die [Online-Webversion](https://app.nextchat.club/) nutzen oder selbst auf Vercel / Cloudflare / Docker bereitstellen (siehe erweiterten Abschnitt unten).

## Ace Data Cloud konfigurieren

Starten Sie NextChat und gehen Sie zu **Einstellungen → Modelldienst**:

| Feld          | Wert                           | Beschreibung                              |
| ----------- | --------------------------- | ------------------------------- |
| Modellanbieter       | `OpenAI`                    | OpenAI-kompatibles Protokoll verwenden                  |
| OpenAI-Schnittstellenadresse | `https://api.acedata.cloud` | Nur die Root-Domain eintragen, **ohne `/openai`, ohne `/v1`** |
| API Key     | Ihr Ace Data Cloud-Token     | Aus der Konsole kopierter Token                    |

![NextChat Ace Data Cloud-Konfigurationsoberfläche](https://cdn.acedata.cloud/47e0aed34570.png)

NextChat fügt automatisch `/v1/chat/completions` an die Schnittstellenadresse an, daher genügt die Root-Domain:

| Schnittstellenadresse                                  | Tatsächliche Anfrage                                                      | Ergebnis                       |
| ------------------------------------- | --------------------------------------------------------- | ------------------------ |
| `https://api.acedata.cloud`           | `https://api.acedata.cloud/v1/chat/completions`           | Korrekt                       |
| `https://api.acedata.cloud/openai`    | `https://api.acedata.cloud/openai/v1/chat/completions`    | 404 (unter `/openai` gibt es kein `/v1`) |
| `https://api.acedata.cloud/openai/v1` | `https://api.acedata.cloud/openai/v1/v1/chat/completions` | 404                      |

Tragen Sie im Feld „Benutzerdefinierter Modellname“ die Modelle durch englische Kommas getrennt ein. NextChat unterstützt eine spezielle Syntax: `+Modellname` zum Hinzufügen, `-Modellname` zum Ausblenden, `Modellname=Anzeigename` zum Anpassen des Anzeigenamens, `-all` zum vorherigen Ausblenden aller Modelle. Die empfohlene sauberste Schreibweise:

```text
-all,+MODEL_ID=显示名称
```

## Modell auswählen

Der Modellkatalog wird fortlaufend aktualisiert. Verwenden Sie bevorzugt die automatisch vom Client geladene Modellliste; wenn eine manuelle Eingabe erforderlich ist, fragen Sie zunächst mit `GET https://api.acedata.cloud/v1/models` die aktuelle Modell-ID ab und wählen Sie dann entsprechend den vom Client unterstützten Fähigkeiten für Kontext, Bilder und Tool-Aufrufe.

## Integration überprüfen

Wenn Sie nicht sicher sind, ob das Problem bei NextChat oder im Netzwerk liegt, können Sie zunächst den Endpunkt direkt mit curl überprüfen (ersetzen Sie `{token}` durch Ihren Token):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

Wenn ein OpenAI-kompatibles `chat.completion`-Objekt zurückgegeben wird, sind Token und Endpunkt bereit; wird hingegen `HTTP 403 used_up` zurückgegeben, bedeutet dies, dass der Token gültig ist, aber das Guthaben nicht ausreicht. Laden Sie einfach in der [Konsole](https://platform.acedata.cloud/console/applications) Guthaben auf.

## Erweitert: Mit einem Klick auf der eigenen Domain bereitstellen

NextChat unterstützt die Bereitstellung einer eigenen AI-Website. Als Beispiel mit Docker (ersetzen Sie `{token}` durch Ihren Token):

```bash
docker run -d \
  --name nextchat \
  -p 3000:3000 \
  -e OPENAI_API_KEY={token} \
  -e BASE_URL=https://api.acedata.cloud \
  -e CODE=your-password \
  -e CUSTOM_MODELS="-all,+MODEL_ID=显示名称" \
  yidadaa/chatgpt-next-web
```

Bei der Bereitstellung auf Vercel / Cloudflare konfigurieren Sie einfach dieselben `OPENAI_API_KEY`, `BASE_URL`, `CODE` und `CUSTOM_MODELS` in den Umgebungsvariablen des Projekts. `CODE` unterstützt mehrere durch englische Kommas getrennte Zugriffspasswörter, was die Nutzungsstatistik nach Personen erleichtert. Die vollständige Beschreibung der oben genannten Umgebungsvariablen (Standardwert von `BASE_URL` ist `https://api.openai.com`, Syntax von `+/-/=/-all/+all` für `CUSTOM_MODELS`) entnehmen Sie bitte der [offiziellen NextChat README](https://github.com/ChatGPTNextWeb/NextChat#environment-variables).

## Häufige Fragen

### Meldung 404 Not Found

Normalerweise wurde die Schnittstellenadresse als `.../openai` oder `.../openai/v1` angegeben. Ändern Sie sie in `https://api.acedata.cloud`, damit NextChat selbst `/v1/chat/completions` anhängt.

### Das hinzugefügte Modell erscheint nicht im Modell-Dropdown

Überprüfen Sie das Format von `CUSTOM_MODELS`: Vor jedem Modell muss ein `+` stehen; falls Sie `-all` verwendet haben, stellen Sie sicher, dass Sie die benötigten Modelle anschließend mit `+` wieder hinzufügen.

### Meldung 401 Unauthorized

Bitte bestätigen Sie, dass im API Key der Ace Data Cloud-Token eingefügt ist (ohne das Präfix `Bearer` und ohne zusätzliche Leerzeichen) und dass das Guthaben der zugehörigen Anwendung ausreichend ist.
