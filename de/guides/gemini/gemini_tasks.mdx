Die Hauptfunktion der Gemini Tasks API besteht darin, den Ausführungsstatus einer Aufgabe anhand der von der Gemini Videos Generation API generierten Aufgaben-ID abzufragen.

Dieses Dokument beschreibt detailliert die Integration der Gemini Tasks API und hilft Ihnen, die Ausführung von Aufgaben der Gemini Videos Generation API einfach zu integrieren und abzufragen.

## Antragsprozess

Um die Gemini Tasks API zu nutzen, müssen Sie zunächst auf der Antragsseite [Gemini Videos Generation API](https://platform.acedata.cloud/documents/gemini-videos) den entsprechenden Dienst beantragen und die von der Gemini Videos Generation API zurückgegebene Aufgaben-ID kopieren.

Anschließend beantragen Sie den entsprechenden Dienst auf der Seite [Gemini Tasks API](https://platform.acedata.cloud/documents/gemini-tasks). Nach dem Aufrufen der Seite klicken Sie auf die Schaltfläche „Acquire“.

Falls Sie noch nicht eingeloggt oder registriert sind, werden Sie automatisch zur [Login-Seite](https://platform.acedata.cloud) weitergeleitet, um sich zu registrieren oder anzumelden. Nach der Anmeldung oder Registrierung kehren Sie automatisch zur aktuellen Seite zurück.

Bei der ersten Antragstellung erhalten Sie ein kostenloses Kontingent, mit dem Sie die API kostenlos nutzen können.

## Beispielanfrage

Die Gemini Tasks API kann verwendet werden, um die Ergebnisse der Gemini Videos Generation API abzufragen.

### Festlegen von Request-Headern und Request-Body

**Request Headers** umfassen:

- `accept`: Gibt an, dass die Antwort im JSON-Format erwartet wird, hier `application/json`.
- `authorization`: Der API-Schlüssel zur Authentifizierung, der nach der Beantragung direkt aus einer Dropdown-Liste ausgewählt werden kann.

**Request Body** umfasst:

- `id`: Die abzufragende Aufgaben-ID.
- `action`: Die Aktion für die Aufgabe, bei Einzelabfrage `retrieve`.

### CURL-Beispielcode

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### Beispielantwort

Nach erfolgreicher Anfrage gibt die API die Detailinformationen der Aufgabe zurück. Das Feld `request` enthält den Request-Body der ursprünglichen Aufgabe, das Feld `response` den Response-Body nach Abschluss der Aufgabe, zum Beispiel:

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "request": {
    "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
    "model": "omni-flash",
    "aspect_ratio": "16:9"
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "omni-flash:job_01k777hjrbfrgs2060q5zvf2a5",
        "video_url": "https://cdn.acedata.cloud/gemini/example-video.mp4",
        "state": "succeeded"
      }
    ]
  }
}
```

Beschreibung der Felder:

- `id`: Die ID der generierten Aufgabe, die diese Aufgabe eindeutig identifiziert.
- `request`: Die Anfragedaten der abgefragten Aufgabe.
- `response`: Die Antwortdaten der abgefragten Aufgabe.

## Batch-Abfrage

Für die Abfrage von Details mehrerer Aufgaben-IDs setzen Sie `action` auf `retrieve_batch` und übergeben die Aufgaben-IDs als Array im Feld `ids`:

**Request Body** umfasst:

- `ids`: Array der abzufragenden Aufgaben-IDs.
- `action`: Die Aktion für die Aufgabe, bei Batch-Abfrage `retrieve_batch`.

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```
