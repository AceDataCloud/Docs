Google Gemini ist ein sehr leistungsstarkes KI-Dialogsystem, das durch die Eingabe von Prompt-Wörtern innerhalb weniger Sekunden flüssige und natürliche Antworten generieren kann. Gemini kann erstaunliche intelligente Unterstützung bieten und die Arbeitseffizienz und Kreativität von Menschen erheblich steigern.

Dieses Dokument stellt hauptsächlich den Nutzungsprozess der Gemini Chat Completion API vor, mit der wir die Dialogfunktion des offiziellen Gemini einfach nutzen können.

## Beantragungsprozess

Um die Gemini Chat Completion API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API Token zu erhalten und ihn als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, auf der Sie zur Registrierung und Anmeldung eingeladen werden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Bei der ersten Beantragung wird ein kostenloses Kontingent verschenkt, das kostenlos getestet werden kann; bei unzureichendem Kontingent kann in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufgeladen werden.

> 📘 Vollständige Dokumentation: [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## Grundlegende Nutzung

Anschließend können Sie die entsprechenden Inhalte in der Oberfläche ausfüllen, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

Bei der ersten Verwendung dieser Schnittstelle müssen wir mindestens drei Inhalte ausfüllen. Einer davon ist `authorization`, das direkt in der Dropdown-Liste ausgewählt werden kann. Ein weiterer Parameter ist `model`, `model` ist die Modellkategorie der Gemini-Website, die wir auswählen; die auswählbaren Modelle richten sich nach der `model`-Enumeration in der Schnittstellendokumentation. Der letzte Parameter ist `messages`, `messages` ist das Array der von uns eingegebenen Fragewörter. Es ist ein Array, das angibt, dass mehrere Fragewörter gleichzeitig hochgeladen werden können. Jedes Fragewort enthält `role` und `content`, wobei `role` die Rolle des Fragestellers darstellt. Wir bieten drei Identitäten an: `user`, `assistant`, `system`. Das andere `content` ist der konkrete Inhalt unserer Frage.

Gleichzeitig können Sie beachten, dass auf der rechten Seite entsprechender generierter Aufrufcode vorhanden ist. Sie können den Code kopieren und direkt ausführen oder direkt auf die Schaltfläche „Try“ klicken, um zu testen.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

> **Hinweis**: Flash der `gemini-3.x`-Serie sind Denkmodelle und verbrauchen zuerst reasoning tokens; setzen Sie `max_tokens` auf über 512, andernfalls wird möglicherweise nur leerer Inhalt zurückgegeben. `gemini-3.8-flash` ist das aktuell empfohlene Flash-Modell und unterstützt bis zu 1 Million Token Kontext, Bildeingabe, Werkzeugaufrufe und Streaming-Antworten; derzeit wird es über die Chat Completions-Schnittstelle aufgerufen.

## Bildverständnis (multimodale Eingabe)

Gemini ist ein natives multimodales Modell und kann direkt „Bilder sehen“. Um ein Bild zu übergeben, ändern Sie `content` einer Nachricht von einer Zeichenfolge in ein **Inhaltsblock-Array** und fügen Sie im Array gleichzeitig einen `text`-Block und einen `image_url`-Block ein – dies entspricht vollständig dem OpenAI- sowie dem OpenAI-kompatiblen Format des offiziellen Gemini.

`image_url.url` unterstützt zwei Schreibweisen:

- **base64-`data:`-URI (empfohlen, am stabilsten)**: Das Format lautet `data:<Medientyp>;base64,<Daten>`, beispielsweise `data:image/jpeg;base64,/9j/4AAQ...`. **Der Medientyp (MIME) ist bereits im Präfix `data:` enthalten**, daher ist kein separates Feld `media_type` erforderlich und es existiert auch keines.
- **Öffentlich zugängliche Bild-URL**: beispielsweise `https://cdn.acedata.cloud/4hfydw.jpg`.

Unterstützte Bildtypen: `png`, `jpeg`, `webp`, `heic`, `heif`.

Python-Beispielaufrufcode (base64 data URI):
```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# 把本地图片读成 base64 data URI
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Sie können auch direkt eine öffentlich zugängliche Bild-URL übergeben:

```python
payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [

```

> 💡 `image_url` akzeptiert nur das Feld `url` (der Wert kann eine Bild-URL oder eine base64-`data:`-URI sein) sowie das optionale Feld `detail`. **Übergeben Sie nicht `media_type`** — das ist ein Bildfeld von Anthropic Claude und gehört nicht zum `image_url`-Format von OpenAI / Gemini.

## Streaming-Antwort

Diese Schnittstelle unterstützt auch Streaming-Antworten, was für die Anbindung von Webseiten sehr nützlich ist und Webseiten einen Effekt der zeichenweisen Anzeige ermöglichen kann.

Wenn Sie die Antwort als Stream zurückgeben möchten, können Sie den Parameter `stream ` im Request-Header ändern und auf `true` setzen.

Die Änderung ist wie in der Abbildung gezeigt, allerdings muss der Aufrufcode entsprechend geändert werden, um Streaming-Antworten zu unterstützen.

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

Nachdem `stream` auf `true` geändert wurde, gibt die API die entsprechenden JSON-Daten zeilenweise zurück. Auf Codeebene müssen wir entsprechende Änderungen vornehmen, um die zeilenweisen Ergebnisse zu erhalten.

Python-Beispielaufrufcode:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

JavaScript wird ebenfalls unterstützt, zum Beispiel lautet der Code für den Streaming-Aufruf in Node.js wie folgt:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

## Mehrere Dialogrunden

Wenn Sie die Funktion für mehrere Dialogrunden anbinden möchten, müssen Sie mehrere Fragen in das Feld `messages` hochladen. Ein konkretes Beispiel für mehrere Fragen ist in der folgenden Abbildung dargestellt:

<p><img src="https://cdn.acedata.cloud/qvzu06.png" width="400" className="m-auto" /></p>

Python-Beispielaufrufcode:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello"},{"role":"assistant","content":"Hello there! How can I help you today?"},{"role":"user","content":"What model are you?"}]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Gemini-3.1-Multimodalmodell

`gemini-3.1-pro-preview` ist die offizielle aktuelle Modell-ID für Gemini 3.1 Pro und unterstützt multimodale Eingaben wie Text, Bilder und Videos; es eignet sich für komplexe Schlussfolgerungs-, Codierungs- und Verständnisaufgaben.

Anfragebeispiel:

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "Was ist der Inhalt des Bildes?"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/qzx2z1.png"
          }
        }
      ]
    }
  ],
  "stream": false
}
```

Gemini 3.1 Pro unterstützt ebenfalls Videoverständnis:

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "Was ist der Inhalt des Videos?"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/58yioe.mp4"
          }
        }
      ]
    }
  ],
  "stream": false
}
```

Das Rückgabeformat entspricht dem von Gemini 3.0 Pro. Details finden Sie in der Beschreibung im obigen Abschnitt zum Gemini-3.0-Multimodalmodell.

## Fehlerbehandlung

Wenn beim Aufruf der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechenden Informationen zurück. Zum Beispiel:

- `400 token_mismatched`: Bad Request, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Bad Request, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort
```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
