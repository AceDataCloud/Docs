Google Gemini ist ein sehr leistungsstarkes KI-Dialogsystem. Solange Sie einen Prompt eingeben, kann es innerhalb weniger Sekunden flüssige und natürliche Antworten generieren. Gemini kann erstaunliche intelligente Unterstützung bieten und die Arbeitseffizienz und Kreativität der Menschen erheblich steigern.

Dieses Dokument stellt hauptsächlich den Nutzungsprozess der Gemini Chat Completion API vor. Mit ihr können wir die Dialogfunktionen des offiziellen Gemini einfach nutzen.

## Beantragungsprozess

Um die Gemini Chat Completion API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API Token zu erhalten und ihn als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Bei der ersten Beantragung erhalten Sie ein kostenloses Guthaben, das Sie kostenlos testen können; wenn das Guthaben nicht ausreicht, können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## Grundlegende Nutzung

Anschließend können Sie die entsprechenden Inhalte in der Benutzeroberfläche ausfüllen, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

Bei der ersten Verwendung dieser Schnittstelle müssen wir mindestens drei Inhalte ausfüllen. Einer davon ist `authorization`, das direkt in der Dropdown-Liste ausgewählt werden kann. Ein weiterer Parameter ist `model`; `model` bezeichnet die Kategorie des Gemini-Website-Modells, das wir auswählen. Die optionalen Modelle richten sich nach der `model`-Enumeration in der Schnittstellendokumentation. Der letzte Parameter ist `messages`; `messages` ist das von uns eingegebene Array von Frageprompts. Es ist ein Array und bedeutet, dass mehrere Frageprompts gleichzeitig hochgeladen werden können. Jeder Frageprompt enthält `role` und `content`, wobei `role` die Rolle des Fragestellers darstellt. Wir bieten drei Identitäten an: `user`, `assistant`, `system`. Das andere Feld `content` ist der konkrete Inhalt unserer Frage.

Gleichzeitig können Sie beachten, dass auf der rechten Seite der entsprechende Aufrufcode generiert wird. Sie können den Code kopieren und direkt ausführen oder direkt auf die Schaltfläche „Try“ klicken, um ihn zu testen.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

> **Hinweis**: Flash-Modelle der `gemini-3.x`-Serie sind Denkmodelle und verbrauchen zunächst reasoning tokens; setzen Sie `max_tokens` auf über 512, da andernfalls möglicherweise nur leere Inhalte zurückgegeben werden. `gemini-3.8-flash` ist das derzeit empfohlene Flash-Modell und unterstützt bis zu 1 Million Token Kontext, Bildeingaben, Tool-Aufrufe und Streaming-Antworten; derzeit wird es über die Chat-Completions-Schnittstelle aufgerufen.

`gemini-4-argon` kann ebenfalls für Chat Completions verwendet werden und unterstützt normale sowie Streaming-Textantworten. Es kann einen Teil des Ausgabebudgets für das Denken verwenden; lassen Sie bei komplexen Aufgaben ausreichend Platz für `max_tokens`; Google empfiehlt für reguläre Aufgaben dieses Modells mindestens 32768. Setzen Sie diese Schnittstelle nicht mit der Backend-Funktion für lange Ausgaben der Google Interactions API gleich.

`gemini-4-neon` — Softwareentwicklung und Datenanalyse. Setzen Sie `model` auf diese ID und planen Sie Ausgabetokens für die Überlegungen und die Antwort ein.

`gemini-4-carbon` und `gemini-4-hydrogen` unterstützen ebenfalls normale und Streaming-Textantworten dieser Schnittstelle. Carbon ist für komplexe Schlussfolgerungs- und Engineering-Aufgaben ausgelegt, Hydrogen für alltägliche Programmierung und mehrstufige Aufgaben. Beide verbrauchen Denk-Token; für `max_tokens` sollte ein ausreichendes Budget reserviert werden; die langen Ausgaben von einer Million Token der nativen Modelle bedeuten nicht, dass diese Schnittstelle diese Funktion bereitstellt. Bild- und Tool-Aufruffelder richten sich weiterhin nach dem öffentlichen Vertrag und den tatsächlichen Rückgaben dieser Schnittstelle.

## Bildverständnis (multimodale Eingabe)
Gemini ist ein nativ multimodales Modell und kann Bilder direkt „sehen“. Um ein Bild zu übergeben, ändern Sie den `content` einer Nachricht von einem String zu einem **Inhaltsblock-Array** und fügen Sie gleichzeitig einen `text`-Block und einen `image_url`-Block in das Array ein – dies ist vollständig identisch mit OpenAI sowie dem OpenAI-kompatiblen Format des offiziellen Gemini.

`image_url.url` unterstützt zwei Schreibweisen:

- **base64-`data:`-URI (empfohlen, am stabilsten)**: Das Format lautet `data:<Medientyp>;base64,<Daten>`, zum Beispiel `data:image/jpeg;base64,/9j/4AAQ...`. **Der Medientyp (MIME) ist bereits im `data:`-Präfix enthalten**, daher wird kein separates `media_type`-Feld benötigt und ein solches existiert auch nicht.
- **Öffentlich zugängliche Bild-URL**: Zum Beispiel `https://cdn.acedata.cloud/4hfydw.jpg`.

Unterstützte Bildtypen: `png`, `jpeg`, `webp`, `heic`, `heif`.

Python-Beispielcode für den Aufruf (base64-data-URI):

```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# 把本地图片读成 base64 data URI
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Sie können auch direkt eine öffentlich zugängliche Bild-URL übergeben:

```python
payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [

```

> 💡 `image_url` akzeptiert nur das Feld `url` (dessen Wert eine Bild-URL oder eine base64-`data:`-URI sein kann) sowie das optionale Feld `detail`. **Übergeben Sie kein `media_type`** – das ist ein Bildfeld von Anthropic Claude und gehört nicht zum `image_url`-Format von OpenAI / Gemini.

## Streaming-Antworten

Diese Schnittstelle unterstützt auch Streaming-Antworten, was für die Web-Anbindung sehr nützlich ist und es Webseiten ermöglicht, einen Effekt der zeichenweisen Anzeige umzusetzen.

Wenn Sie die Antwort als Stream zurückgeben möchten, können Sie den Parameter `stream ` im Request-Header ändern und auf `true` setzen.

Ändern Sie ihn wie in der Abbildung gezeigt, allerdings muss der Aufrufcode entsprechend angepasst werden, um Streaming-Antworten zu unterstützen.

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

Nachdem `stream` auf `true` geändert wurde, gibt die API die entsprechenden JSON-Daten zeilenweise zurück. Auf Codeebene müssen wir entsprechende Änderungen vornehmen, um die zeilenweisen Ergebnisse zu erhalten.

Python-Beispielcode für den Aufruf:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Das zurückgegebene `data`-Ergebnis enthält mehrere Felder, die wie folgt beschrieben werden:

- `model `, das ausgewählte Modell auf der offiziellen Gemini-Website.
- `choices`, die Antwortinformationen, die Gemini auf die Frage gibt.

JavaScript wird ebenfalls unterstützt, zum Beispiel lautet der Code für einen Streaming-Aufruf in Node.js wie folgt:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

import requests

## Multimodales Modell Gemini-3.1

`gemini-3.1-pro-preview` ist die offizielle aktuelle Modell-ID von Gemini 3.1 Pro und unterstützt multimodale Eingaben wie Text, Bilder und Videos und eignet sich für komplexe Schlussfolgerungs-, Codierungs- und Verständnisaufgaben.

Anfragebeispiel:

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "Was ist der Inhalt des Bildes?"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/qzx2z1.png"
          }
        }
      ]
    }
  ],
  "stream": false
}
```

## Fehlerbehandlung

Wenn bei der API-Nutzung ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Information zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
