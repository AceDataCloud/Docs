Google Gemini ist ein sehr leistungsstarkes KI-Dialogsystem. Solange Sie einen Prompt eingeben, kann es in nur wenigen Sekunden flüssige und natürliche Antworten generieren. Gemini kann erstaunliche intelligente Unterstützung bieten und die Arbeitseffizienz und Kreativität von Menschen erheblich verbessern.

Dieses Dokument stellt hauptsächlich den Nutzungsprozess der Gemini Chat Completion API vor. Mit ihr können wir die Dialogfunktion des offiziellen Gemini ganz einfach nutzen.

## Beantragungsprozess

Um die Gemini Chat Completion API zu nutzen, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten und ihn als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Bei der ersten Beantragung erhalten Sie ein kostenloses Guthaben, das kostenlos getestet werden kann; wenn das Guthaben nicht ausreicht, können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## Grundlegende Nutzung

Anschließend können Sie die entsprechenden Inhalte in der Oberfläche ausfüllen, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

Bei der ersten Nutzung dieser Schnittstelle müssen wir mindestens drei Inhalte ausfüllen. Einer davon ist `authorization`, das direkt in der Dropdown-Liste ausgewählt werden kann. Ein weiterer Parameter ist `model`, `model` ist die Modellkategorie der offiziellen Gemini-Website, die wir auswählen. Die optionalen Modelle richten sich nach der `model`-Enumeration in der Schnittstellendokumentation. Der letzte Parameter ist `messages`, `messages` ist das Array der von uns eingegebenen Frageprompts. Es ist ein Array und bedeutet, dass mehrere Frageprompts gleichzeitig hochgeladen werden können. Jeder Frageprompt enthält `role` und `content`, wobei `role` die Rolle des Fragestellers darstellt. Wir bieten drei Identitäten an, nämlich `user`, `assistant`, `system`. Das andere `content` ist der konkrete Inhalt unserer Frage.

Gleichzeitig können Sie feststellen, dass auf der rechten Seite entsprechender Aufrufcode generiert wird. Sie können den Code kopieren und direkt ausführen oder direkt auf die Schaltfläche „Try“ klicken, um ihn zu testen.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

> **Hinweis**: Die Flash-Modelle der Serie `gemini-3.x` sind Denkmodelle und verbrauchen zuerst Reasoning-Tokens; bitte setzen Sie `max_tokens` auf über 512, da andernfalls möglicherweise nur leere Inhalte zurückgegeben werden. `gemini-3.8-flash` ist das derzeit empfohlene Flash-Modell und unterstützt bis zu 1 Million Token Kontext, Bildeingaben, Tool-Aufrufe und Streaming-Antworten; derzeit wird es über die Chat-Completions-Schnittstelle aufgerufen.

`gemini-4-argon` kann ebenfalls für Chat Completions verwendet werden und unterstützt normale sowie gestreamte Textantworten. Es kann einen Teil des Ausgabebudgets für das Denken verwenden; lassen Sie für komplexe Aufgaben ausreichend Platz für `max_tokens`; Google empfiehlt für reguläre Aufgaben dieses Modells mindestens 32768. Setzen Sie diese Schnittstelle nicht mit der Hintergrundfunktion für lange Ausgaben der Google Interactions API gleich.

## Bildverständnis (multimodale Eingabe)

Gemini ist ein natives multimodales Modell und kann Bilder direkt „sehen“. Um ein Bild zu übergeben, ändern Sie `content` einer Nachricht von einer Zeichenfolge in ein **Inhaltsblock-Array** und fügen Sie dem Array gleichzeitig einen `text`-Block und einen `image_url`-Block hinzu – dies entspricht vollständig dem OpenAI-Format sowie dem OpenAI-kompatiblen Format des offiziellen Gemini.

`image_url.url` unterstützt zwei Schreibweisen:
- **base64-`data:`-URI（empfohlen, am stabilsten）**：Das Format ist `data:<Medientyp>;base64,<Daten>`, zum Beispiel `data:image/jpeg;base64,/9j/4AAQ...`。**Der Medientyp（MIME）ist bereits im `data:`-Präfix angegeben**，daher wird kein separates Feld `media_type` benötigt und es existiert auch nicht.
- **Öffentlich zugängliche Bild-URL**：zum Beispiel `https://cdn.acedata.cloud/4hfydw.jpg`。

Unterstützte Bildtypen：`png`、`jpeg`、`webp`、`heic`、`heif`。

Python-Beispielaufrufcode（base64-data-URI）：

```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# 把本地图片读成 base64 data URI
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Es kann auch direkt eine öffentlich zugängliche Bild-URL übergeben werden：

```python
payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [

```

> 💡 `image_url` akzeptiert nur das Feld `url`（der Wert kann eine Bild-URL oder eine base64-`data:`-URI sein），sowie das optionale Feld `detail`。**Übergeben Sie nicht `media_type`**——das ist ein Bildfeld von Anthropic Claude und gehört nicht zum `image_url`-Format von OpenAI / Gemini。

## Streaming-Antwort

Diese Schnittstelle unterstützt auch Streaming-Antworten, was für die Webanbindung sehr nützlich ist und es Webseiten ermöglicht, einen Effekt der zeichenweisen Anzeige zu erzielen。

Wenn Sie Antworten als Stream zurückgeben möchten, können Sie den Parameter `stream ` im Anfrage-Header ändern und ihn auf `true` setzen。

Die Änderung ist wie in der Abbildung gezeigt, allerdings muss der Aufrufcode entsprechend geändert werden, um Streaming-Antworten zu unterstützen。

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

Nachdem `stream` auf `true` geändert wurde, gibt die API die entsprechenden JSON-Daten zeilenweise zurück, und auf Codeebene müssen wir entsprechende Änderungen vornehmen, um die zeilenweisen Ergebnisse zu erhalten。

Python-Beispielaufrufcode：

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

JavaScript wird ebenfalls unterstützt, beispielsweise lautet der Code für den Streaming-Aufruf in Node.js wie folgt:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

## Mehrere Dialogrunden

Wenn Sie die Funktion für mehrere Dialogrunden integrieren möchten, müssen Sie mehrere Anfragen in das Feld `messages` hochladen. Ein konkretes Beispiel für mehrere Anfragen ist in der folgenden Abbildung dargestellt:

Python-Beispielcode für den Aufruf:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello"},{"role":"assistant","content":"Hello there! How can I help you today?"},{"role":"user","content":"What model are you?"}]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Gemini-3.1-Multimodalmodell

`gemini-3.1-pro-preview` ist die offizielle Modell-ID des aktuellen Gemini 3.1 Pro und unterstützt multimodale Eingaben wie Text, Bilder und Videos, geeignet für komplexe Schlussfolgerungs-, Kodierungs- und Verständnisaufgaben.

Anfragebeispiel:

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "图片的内容是什么？"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/qzx2z1.png"
          }
        }
      ]
    }
  ],
  "stream": false
}
```

Gemini 3.1 Pro unterstützt ebenfalls Videoverständnis:

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
```

## Fehlerbehandlung

Wenn bei der API-Nutzung ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Information zurück. Zum Beispiel:

- `400 token_mismatched`: Bad Request, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Bad Request, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, du hast das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort
```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
