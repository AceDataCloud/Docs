Google Gemini ist ein sehr leistungsstarkes KI-Dialogsystem, das durch die Eingabe von Prompts innerhalb weniger Sekunden flüssige und natürliche Antworten generieren kann. Dieses Dokument beschreibt hauptsächlich die Verwendung der Gemini Generate Content API. Dies ist das offizielle native API-Format von Google und unterstützt die beiden Endpunkte `generateContent` und `streamGenerateContent`.

## Unterschiede zur Chat Completions API

Die Gemini Generate Content API verwendet das offizielle native Anfrageformat von Google (Feld `contents`) anstelle des OpenAI-kompatiblen Formats (Feld `messages`). Wenn Sie bereits das Google Gemini SDK verwenden oder mit dem offiziellen API-Format vertraut sind, können Sie diese API direkt verwenden, ohne das Anfrageformat ändern zu müssen.

## Aktuell unterstützter Umfang

Die Schnittstelle akzeptiert Text-, Bild-, Video- und Audioeingaben (`inlineData` oder `fileData`), Denk-Konfigurationen sowie benutzerdefinierte Funktionsdeklarationen. Für Audioausgaben, integrierte Tools und native Felder wie explizites Kontext-Caching gibt es noch keine einheitliche Verfügbarkeitsgarantie; maßgeblich ist die tatsächliche Rückgabe des jeweiligen Modells.

Wenn Sie Dateien wie Audio über `fileData.fileUri` einreichen, stellen Sie bitte sicher, dass die Datei direkt über HTTPS zugänglich ist, nicht vom Anmeldestatus abhängt und die Gültigkeitsdauer des signierten Links die gesamte Dauer der Anfrageverarbeitung abdeckt. Nicht-streamende Audioanalysen geben Ergebnisse erst zurück, nachdem das Modell die Verarbeitung abgeschlossen hat, und können mehr als 90 Sekunden dauern; der Client sollte entsprechend der Dateigröße und des Geschäftsszenarios eine ausreichend lange Gesamtzeitüberschreitung festlegen, um zu vermeiden, dass die Verbindung getrennt wird, während der Server noch verarbeitet.

## Antragsverfahren

Bevor Sie die Gemini Generate Content API verwenden, besuchen Sie bitte zunächst die Seite [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) und klicken Sie auf die Schaltfläche „Abrufen“, um die für die Anfrage benötigten Anmeldedaten zu erhalten.

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet. Bei der ersten Beantragung gibt es ein kostenloses Kontingent.

## Grundlegende Verwendung

### Non-Streaming (nicht-streamend)

Senden Sie eine POST-Anfrage an `/v1beta/models/{model}:generateContent`:

> **Hinweis**: Die Flash-Modelle der Serie `gemini-3.x` sind Denkmodelle und verbrauchen zunächst Reasoning-Tokens; setzen Sie `generationConfig.maxOutputTokens` auf über 512, da andernfalls möglicherweise nur leerer Inhalt zurückgegeben wird.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Beispiel für das Rückgabeergebnis:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Die Token-Felder in `usageMetadata` werden gemäß der nativen Gemini-Semantik abgerechnet:

- `promptTokenCount` enthält `cachedContentTokenCount`; der Cache-Trefferanteil wird zum Preis für Cache-Lesevorgänge berechnet und nicht erneut als gewöhnliche Eingabe gezählt.
- `promptTokensDetails` und `cacheTokensDetails` werden unter `usage.prompt_tokens_details` zu `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` sowie den entsprechenden Details `cached_*` normalisiert. Diese Werte sind jeweils in `prompt_tokens` und `cached_tokens` enthalten; unterschiedliche Modalitäten werden nur zu ihren jeweiligen Preisen neu berechnet und nicht doppelt abgerechnet.
- `candidatesTokenCount` und `thoughtsTokenCount` werden beide zum Preis für Ausgabe-Tokens berechnet.
- `toolUsePromptTokenCount` ist ein unabhängiger Tool-Eingabe-Token und wird zum Preis für Eingabe-Tokens berechnet.

Ace Data Cloud gibt zusätzlich ein normalisiertes `usage`-Objekt zurück, und die Kosten dieses Aufrufs werden modellübergreifend einheitlich aus `usage.cost` gelesen. `cost` ist eine optionale Kostenvorschau; wenn die Preisvorschau vorübergehend nicht verfügbar ist, wird die Modellantwort dennoch normal zurückgegeben, enthält dieses Feld jedoch möglicherweise nicht. Die endgültige Abrechnung richtet sich nach den Nutzungsaufzeichnungen.

### Streaming (streamend)

Senden Sie eine POST-Anfrage an `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

Die Streaming-Rückgabe gibt Inhalte schrittweise im SSE-Format (Server-Sent Events) zurück. Zwischenereignisse enthalten in der Regel nur inkrementelle Inhalte; das Endereignis mit maßgeblichen Nutzungsdaten enthält `usageMetadata` und die normalisierte `usage`, die Kosten befinden sich weiterhin in `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

Das Schließen der Verbindung zeigt das Ende des Streams an; native Gemini-Streams senden kein `data: [DONE]`. Wenn die Preisvorschau im Endzustand vorübergehend nicht verfügbar ist, gibt `usage` dennoch die Token-Nutzung zurück, lässt jedoch `cost` weg.

### Internes Denken und Denkzusammenfassungen

Das interne Denken des Modells und die Rückgabe von Denkzusammenfassungen an den Aufrufer sind zwei unabhängige Einstellungen:

- `thinkingBudget` oder `thinkingLevel` steuern das interne Denkbudget oder die Tiefe des Modells; die unterstützten Felder und Werte hängen vom Modell ab.
- `includeThoughts` steuert, ob Denkzusammenfassungen zurückgegeben werden; der Standardwert ist `false`. Wenn dieses Feld weggelassen oder `false` übergeben wird, geben weder gewöhnliche JSON- noch SSE-Streaming-Antworten Texte zurück, die als `thought: true` markiert sind; nur wenn explizit der boolesche Wert `true` übergeben wird, werden diese Texte beibehalten.

Wenn die Anfrage `includeThoughts` nicht setzt, übergibt die Schnittstelle standardmäßig `false` an Generierungsmodelle, die Denk-Konfigurationen unterstützen, um nicht benötigte Zusammenfassungen zu vermeiden; vom Kunden explizit übergebene Werte, Denkbudgets und Stufen bleiben erhalten. Dem bekanntermaßen keine Denk-Konfiguration unterstützenden `gemini-2.5-flash-image` wird dieses Feld nicht automatisch hinzugefügt, und auch `countTokens`-Anfragen wird keine Generierungskonfiguration hinzugefügt.

Das Deaktivieren von Zusammenfassungen bedeutet nicht, das interne Denken zu deaktivieren, und garantiert nicht, interne Thinking-Token zu reduzieren. Wenn die Antwort weiterhin nicht angeforderte Denktexte enthält, werden gewöhnliche JSON- und SSE-Ausgänge zusätzlich gefiltert, wobei normale Antworten, Signaturen und die tatsächliche Nutzung erhalten bleiben.

Wenn Sie Zusammenfassungen anzeigen müssen, aktivieren Sie sie explizit auf folgende Weise. Wenn das Modell keine verwendbare Zusammenfassung generiert hat, kann auch bei Aktivierung kein Denktext vorhanden sein:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` ist der verschlüsselte Zustand, der für nachfolgende Runden benötigt wird, und kein Denkzusammenfassungstext; er wird auch nicht durch den Schalter `includeThoughts` gesteuert. Die Signatur kann sich in einer normalen Antwort, einem Funktionsaufruf oder einem leeren Text-Part befinden; beim Filtern von Denktexten bleiben die Signatur und andere Felder desselben Parts erhalten, daher können in der Antwort weiterhin Parts vorhanden sein, die nur eine Signatur tragen und deren Text leer ist. Bei manueller Pflege eines mehrstufigen Verlaufs sollten Sie die Reihenfolge dieser Parts und die Positionen der Signaturen beibehalten; verschieben Sie Signaturen nicht und führen Sie sie nicht zusammen.

`usageMetadata` und `usage` erfassen weiterhin die tatsächliche Nutzung. Das Ausblenden von Zusammenfassungen setzt `thoughtsTokenCount` nicht auf null, die Abrechnung erfolgt weiterhin gemäß der tatsächlichen Nutzung und den aktuellen Preisregeln.

Siehe die offiziellen Google-[Erläuterungen zu Denken und Denkzusammenfassungen](https://firebase.google.com/docs/ai-logic/thinking) und [Regeln für Denksignaturen](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

## Sicherheitseinstellungen

Die Inhaltsfilterung kann über `safetySettings` gesteuert werden:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Fehlerbehandlung

| HTTP-Statuscode | Bedeutung             |
| -------- | -------------- |
| 400      | Ungültige Anfrageparameter         |
| 401      | Authentifizierung fehlgeschlagen, bitte Token überprüfen |
| 403      | Inhalt wurde vom Sicherheitsfilter abgefangen     |
| 429      | Anfrage zu häufig         |
| 500      | Interner Serverfehler        |
