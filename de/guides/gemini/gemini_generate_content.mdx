Google Gemini ist ein sehr leistungsstarkes KI-Dialogsystem, das durch die Eingabe von Eingabeaufforderungen in wenigen Sekunden flüssige und natürliche Antworten generieren kann. Dieses Dokument beschreibt hauptsächlich die Verwendung der Gemini Generate Content API; dies ist das offizielle native API-Format von Google und unterstützt die beiden Endpunkte `generateContent` und `streamGenerateContent`.

## Unterschiede zur Chat Completions API

Die Gemini Generate Content API verwendet das offizielle native Anfrageformat von Google (Feld `contents`) und nicht das OpenAI-kompatible Format (Feld `messages`). Wenn du bereits das Google Gemini SDK verwendest oder mit dem offiziellen API-Format vertraut bist, kannst du diese API direkt verwenden, ohne das Anfrageformat ändern zu müssen.

## Aktuell unterstützter Umfang

Die Schnittstelle akzeptiert Text-, Bild-, Video- und Audioeingaben (`inlineData` oder `fileData`), Denk-Konfigurationen und benutzerdefinierte Funktionsdeklarationen. Für native Felder wie Audioausgabe, integrierte Tools und explizites Kontext-Caching gibt es noch keine einheitliche Verfügbarkeitsgarantie; bitte orientiere dich an der tatsächlichen Rückgabe des jeweiligen Modells.

Wenn du Audio und andere Dateien über `fileData.fileUri` übermittelst, stelle bitte sicher, dass die Dateien direkt über HTTPS zugänglich sind, nicht vom Anmeldestatus abhängen und die Gültigkeitsdauer signierter Links die gesamte Verarbeitungszeit der Anfrage abdeckt. Nicht-streamende Audioanalysen geben Ergebnisse erst zurück, nachdem das Modell die Verarbeitung abgeschlossen hat, und können mehr als 90 Sekunden dauern; der Client sollte abhängig von Dateigröße und Geschäftsszenario eine ausreichend lange Gesamtauszeit festlegen, um zu vermeiden, dass die Verbindung getrennt wird, während der Server noch verarbeitet.

## Antragsprozess

Bevor du die Gemini Generate Content API verwendest, rufe bitte die Seite [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) auf und klicke auf die Schaltfläche „Abrufen“, um die für die Anfrage benötigten Zugangsdaten zu erhalten.

Wenn du noch nicht angemeldet oder registriert bist, wirst du automatisch zur Anmeldeseite weitergeleitet. Bei der ersten Beantragung gibt es ein kostenloses Kontingent.

## Grundlegende Verwendung

### Nicht-streaming (Nicht-streamend)

Sende eine POST-Anfrage an `/v1beta/models/{model}:generateContent`:

> **Hinweis**: Die flash-Modelle der Serie `gemini-3.x` sind Denkmodelle und verbrauchen zuerst reasoning tokens; setze `generationConfig.maxOutputTokens` bitte auf über 512, da andernfalls möglicherweise nur leere Inhalte zurückgegeben werden.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Beispiel für das Rückgabeergebnis:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Die Token-Felder in `usageMetadata` werden gemäß der nativen Gemini-Semantik abgerechnet:

- `promptTokenCount` enthält `cachedContentTokenCount`; der Teil mit Cache-Treffer wird zum Preis für das Lesen aus dem Cache berechnet und nicht erneut als normale Eingabe gezählt.
- `promptTokensDetails` und `cacheTokensDetails` werden unter `usage.prompt_tokens_details` in `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` sowie die entsprechenden `cached_*`-Details normalisiert. Diese Werte sind jeweils in `prompt_tokens` und `cached_tokens` enthalten; unterschiedliche Modalitäten werden nur nach ihren jeweiligen Preisen neu berechnet und nicht doppelt abgerechnet.
- `candidatesTokenCount` und `thoughtsTokenCount` werden beide nach dem Preis für Ausgabe-Token berechnet.
- `toolUsePromptTokenCount` sind unabhängige Tool-Eingabe-Token und werden nach dem Preis für Eingabe-Token berechnet.

Ace Data Cloud gibt zusätzlich ein normalisiertes `usage`-Objekt zurück; modellübergreifend werden die Kosten dieses Aufrufs einheitlich aus `usage.cost` gelesen. `cost` ist eine optionale Kostenvorschau; wenn die Preisvorschau vorübergehend nicht verfügbar ist, wird die Modellantwort dennoch normal zurückgegeben, enthält dieses Feld jedoch möglicherweise nicht. Die endgültige Abrechnung richtet sich nach den Nutzungsaufzeichnungen.

### Streaming (Streamend)

Sende eine POST-Anfrage an `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

Die Streaming-Rückgabe gibt Inhalte schrittweise im SSE-Format (Server-Sent Events) zurück. Zwischenereignisse enthalten normalerweise nur inkrementelle Inhalte; das Endereignis mit verbindlichen Nutzungsdaten enthält `usageMetadata` und das normalisierte `usage`, die Kosten befinden sich weiterhin in `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

Das Schließen der Verbindung bedeutet das Ende des Streams; native Gemini-Streams senden kein `data: [DONE]`. Wenn die Preisvorschau im Endzustand vorübergehend nicht verfügbar ist, gibt `usage` weiterhin die Token-Nutzung zurück, lässt jedoch `cost` weg.

### Internes Denken und Denkzusammenfassungen

Das interne Denken des Modells und die Rückgabe von Denkzusammenfassungen an den Aufrufer sind zwei unabhängige Einstellungen:

- `thinkingBudget` oder `thinkingLevel` steuern das Denkbudget oder die Tiefe des internen Denkens des Modells; die unterstützten Felder und Werte hängen vom Modell ab.
- `includeThoughts` steuert, ob Denkzusammenfassungen zurückgegeben werden; der Standardwert ist `false`. Wenn dieses Feld weggelassen oder `false` übergeben wird, geben weder gewöhnliche JSON- noch SSE-Streaming-Antworten Text zurück, der als `thought: true` markiert ist; diese Texte werden nur beibehalten, wenn ausdrücklich der boolesche Wert `true` übergeben wird.

Wenn eine Anfrage `includeThoughts` nicht festlegt, übergibt die Schnittstelle standardmäßig `false` an Generierungsmodelle, die Denk-Konfigurationen unterstützen, um nicht benötigte Zusammenfassungen zu vermeiden; vom Kunden ausdrücklich übergebene Werte, Denkbudgets und Stufen bleiben erhalten. Dem bekanntermaßen keine Denk-Konfigurationen unterstützenden `gemini-2.5-flash-image` wird dieses Feld nicht automatisch hinzugefügt, und `countTokens`-Anfragen wird ebenfalls keine Generierungskonfiguration hinzugefügt.

Das Deaktivieren von Zusammenfassungen bedeutet nicht, dass das interne Denken deaktiviert wird, und garantiert auch keine Verringerung der Tokens für internes Denken. Wenn die Antwort weiterhin nicht angeforderten Denktext enthält, werden gewöhnliche JSON- und SSE-Ausgaben weiter gefiltert, wobei normale Antworten, Signaturen und der tatsächliche Verbrauch erhalten bleiben.

Wenn Zusammenfassungen angezeigt werden sollen, aktivieren Sie sie ausdrücklich auf folgende Weise. Wenn das Modell keine verfügbare Zusammenfassung generiert hat, kann es auch bei Aktivierung keinen Denktext geben:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` ist ein verschlüsselter Zustand, der für nachfolgende Runden benötigt wird, und kein Denkzusammenfassungstext; er wird auch nicht durch den Schalter `includeThoughts` gesteuert. Signaturen können sich in normalen Antworten, Funktionsaufrufen oder leeren Text-Parts befinden; beim Filtern von Denktext bleiben die Signatur und andere Felder desselben Parts erhalten, sodass die Antwort weiterhin Parts enthalten kann, die nur eine Signatur tragen und deren Text leer ist. Bei der manuellen Pflege eines mehrstufigen Verlaufs sollten die Reihenfolge dieser Parts und die Position der Signaturen beibehalten werden; verschieben oder führen Sie die Signaturen nicht zusammen.

`usageMetadata` und `usage` erfassen weiterhin den tatsächlichen Verbrauch. Das Ausblenden von Zusammenfassungen setzt `thoughtsTokenCount` nicht auf null; die Abrechnung erfolgt weiterhin gemäß dem tatsächlichen Verbrauch und den aktuellen Preisregeln.

Siehe die offiziellen Google-[Erläuterungen zu Denken und Denkzusammenfassungen](https://firebase.google.com/docs/ai-logic/thinking) sowie die [Regeln für Denksignaturen](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

## Sicherheitseinstellungen

Die Inhaltsfilterung kann über `safetySettings` gesteuert werden:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Fehlerbehandlung

| HTTP-Statuscode | Bedeutung             |
| -------- | -------------- |
| 400      | Ungültige Anfrageparameter         |
| 401      | Authentifizierung fehlgeschlagen, bitte Token überprüfen |
| 403      | Inhalt wurde vom Sicherheitsfilter abgefangen     |
| 429      | Anfrage zu häufig         |
| 500      | Interner Serverfehler        |
