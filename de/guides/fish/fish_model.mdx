Diese Schnittstelle basiert auf der [Fish Audio offiziellen Model API](https://docs.fish.audio/resources/api-reference/model) und dient dazu, **einen neuen Klonklang basierend auf einer Audioprobe zu erstellen**. Die Adresse lautet `POST https://api.acedata.cloud/fish/model`.

> Für die paginierte Abfrage vorhandener Klänge siehe [Fish Model Query API](https://platform.acedata.cloud/documents/fish-model-query); für die Abfrage der Details eines einzelnen Klangs nach `_id` siehe [Fish Model Get API](https://platform.acedata.cloud/documents/fish-model-get).

## Antragsprozess

Um die Fish Model API zu nutzen, müssen Sie zunächst im [Ace Data Cloud Dashboard](https://platform.acedata.cloud/console/applications) Ihr API-Token abrufen und für zukünftige Verwendung aufbewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss werden Sie automatisch zur aktuellen Seite zurückgeleitet.

**Ein API-Token reicht aus, um auf alle Dienste der Plattform zuzugreifen, es ist nicht erforderlich, für jeden Dienst separat zu beantragen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent zur kostenlosen Nutzung; wenn das Kontingent erschöpft ist, können Sie im [Dashboard](https://platform.acedata.cloud/console/coin) Ihr Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Fish Model API →](https://platform.acedata.cloud/services/fish)

## Anfragekörperfelder

| Feld                     | Typ       | Pflicht | Beschreibung                                                                      |
| ----------------------- | -------- | ------ | -------------------------------------------------------------------------------- |
| `title`                 | string   | Ja     | Klangname, der zur Identifizierung in der Dashboard-Liste verwendet wird.        |
| `voices`                | string   | Ja     | HTTP(S) URL der Audioprobe (**einzelner String**, kein Array). Diese Schnittstelle unterstützt keinen multipart/binären Upload, bitte stellen Sie die Audioprobe in einem beliebigen öffentlich zugänglichen Objektspeicher bereit. |
| `description`           | string   | Nein   | Klangbeschreibung.                                                                 |
| `cover_image`           | string   | Nein   | HTTP(S) URL des Coverbildes.                                                      |
| `tags`                  | string[] | Nein   | Tags zur Abfrage in der öffentlichen Bibliothek, z. B. `["male","narration","zh"]`. |
| `texts`                 | string[] | Nein   | Referenztexte, die der Probe entsprechen (zur Korrektur der Aussprache).         |
| `enhance_audio_quality` | boolean  | Nein   | Ob die Probe vor dem Training in der Audioqualität verbessert werden soll.       |
| `generate_sample`       | boolean  | Nein   | Ob nach Abschluss des Trainings automatisch eine Beispiel-Audioaufnahme generiert werden soll. |

> Die Felder stimmen vollständig mit den upstream überein, bitte beachten Sie auch die [offizielle Fish-Dokumentation](https://docs.fish.audio/resources/api-reference/model).

## Beispiel: Erstellen eines privaten Klonklangs

```shell
curl -X POST 'https://api.acedata.cloud/fish/model' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "title": "Mein Klonklang",
    "description": "Ein chinesischer Klang, der aus einer Podcast-Aufnahme geklont wurde",
    "voices": "https://example.com/sample-voice.mp3",
    "cover_image": "https://cdn.acedata.cloud/e724d7f13d.png"
  }'
```

> Hinweis: `voices` muss ein **String** (einzelne Audio-URL) sein, kein Array. Wenn es als `["..."]` übergeben wird, wird es von upstream abgelehnt.

Die erfolgreiche Antwort gibt direkt das ModelEntity-Objekt der Fish-Plattform zurück (das folgende Beispiel zeigt den minimalen verwendbaren Klang, wobei einige lange Felder zur besseren Lesbarkeit entfernt wurden):

`_id` kann als Wert für das Feld `reference_id` in der nachfolgenden [Fish TTS API](https://platform.acedata.cloud/documents/fish-tts) verwendet werden, um mit diesem Klonklang Sprachsynthese durchzuführen:

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "你好，这是一段使用我刚创建的克隆音色合成的语音。",
    "reference_id": "e5c6db52c3ed417f9cb2e5a33fb04667",
    "format": "mp3"
  }'
```

## Anforderungen an die Probe

Erfahrungswerte (übereinstimmend mit upstream, siehe [offizielle Fish-Dokumentation](https://docs.fish.audio/resources/api-reference/model)):

- Die Dauer sollte idealerweise zwischen 30 Sekunden und 5 Minuten liegen; über 10 Minuten bringt nur geringe Vorteile.
- Abtastrate von 16 kHz oder höher, sowohl Mono- als auch Stereoformate sind akzeptabel.
- Der Inhalt sollte möglichst sauber sein: keine Hintergrundmusik, Echo oder deutliche Umgebungsgeräusche; dieselbe sprechende Person.
- Empfohlene Formate sind `mp3` / `wav`.

Wenn Sie sich über die Qualität der Probe unsicher sind, können Sie auch `enhance_audio_quality: true` übergeben, damit upstream zuerst eine Qualitätsverbesserung vornimmt.

## Abrechnungsinformationen

Die Erstellung eines Klangklonmodells (`POST /fish/model`) ist kostenlos und es fallen keine Gebühren an; auch die Abfrage-Schnittstellen für Klänge ([Fish Model Query](https://platform.acedata.cloud/documents/fish-model-query), [Fish Model Get](https://platform.acedata.cloud/documents/fish-model-get)) sind ebenfalls gebührenfrei. Gebühren entstehen nur bei der nachfolgenden Verwendung der [Fish TTS](https://platform.acedata.cloud/documents/fish-tts) zur Sprachsynthese.

## Fehlerbehandlung

- `400 token_mismatched`: Fehlende oder ungültige Anfrageparameter (am häufigsten ist `voices` keine URL oder wurde als Array übergeben).
- `401 invalid_token`: Authentifizierungstoken existiert nicht oder ist ungültig.
- `429 too_many_requests`: Auslösung der Kontosatzbeschränkung.
- `500 api_error`: Interner Serverfehler.

Beispiel für eine Fehlerantwort:
```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "voices ist erforderlich und muss eine HTTP(S)-URL sein, die auf eine Audiodatei verweist"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## Fazit

Um diese Schnittstelle aufzurufen, muss nur eine öffentlich zugängliche Beispiel-Audio-URL vorbereitet werden, die in das Feld `voices` eingefügt wird, um die `_id` zu erhalten, die dann als `reference_id` an `/fish/tts` übergeben wird, um den End-to-End-Prozess „Klonen → Synthese“ abzuschließen. Ein häufiger Stolperstein ist, dass `voices` ein String sein muss und kein Array sein darf.
