Die Hauptfunktion der Fish Tasks API besteht darin, durch die Eingabe der von der Fish Audios Generation API generierten Aufgaben-ID den Ausführungsstatus dieser Aufgabe abzufragen.

Dieses Dokument stellt die Integrationsanweisungen für die Fish Tasks API ausführlich vor und hilft Ihnen, diese API einfach zu integrieren und ihre leistungsstarken Funktionen voll auszuschöpfen. Über die Fish Tasks API können Sie einfach den Ausführungsstatus von Aufgaben der Fish Audios Generation API abfragen.

## Antragsprozess

Um die Fish Audios Generation API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten, und bewahren Sie ihn zur späteren Verwendung auf.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Beim ersten Antrag wird ein kostenloses Guthaben gewährt, das kostenlos ausprobiert werden kann; wenn das Guthaben nicht ausreicht, können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Fish Audios Generation API →](https://platform.acedata.cloud/documents/fish-tts)

## Anfragebeispiel

Die Fish Tasks API kann verwendet werden, um die Ergebnisse der Fish Audios Generation API abzufragen. Informationen zur Verwendung der Fish Audios Generation API finden Sie in der Dokumentation [Fish Videos Generation API ](https://platform.acedata.cloud/documents/fish-tts-integration)。

Wir verwenden eine von der Fish Audios Generation API zurückgegebene Aufgaben-ID als Beispiel, um zu demonstrieren, wie diese API verwendet wird. Angenommen, wir haben eine Aufgaben-ID: 2725a2d3-f87e-4905-9c53-9988d5a7b2f5, im Folgenden wird demonstriert, wie durch die Übergabe einer Aufgaben-ID.

### Anfrage-Header und Anfrage-Body festlegen

**Request Headers** umfassen:

- `accept`: Gibt an, dass Antwortergebnisse im JSON-Format empfangen werden sollen; hier wird `application/json` eingetragen.
- `authorization`: Der Schlüssel zum Aufrufen der API, der nach dem Antrag direkt aus der Dropdown-Liste ausgewählt werden kann.

**Request Body** umfasst:

- `id`: Die hochgeladene Aufgaben-ID.
- `action`: Die Operationsmethode für die Aufgabe.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/fish/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2725a2d3-f87e-4905-9c53-9988d5a7b2f5",
  "action": "retrieve"
}'
```


Das zurückgegebene Ergebnis enthält mehrere Felder. Das Feld `request` ist der Request Body beim Starten der Aufgabe, während das Feld `response` der nach Abschluss der Aufgabe zurückgegebene Response Body ist. Die Felder werden wie folgt beschrieben.

- `id`, die ID zur Generierung dieser Aufgabe, wird zur eindeutigen Identifizierung dieser Generierungsaufgabe verwendet.
- `request`, die Anfrageinformationen in der Abfrageaufgabe.
- `response`, die Rückgabeinformationen in der Abfrageaufgabe; bei endgültigem Erfolg ist `cost.amount` darin die für diese Synthese tatsächlich abgezogenen Credits.
- `created_at`, Zeitpunkt der Aufgabenerstellung, Unix-Zeitstempel (Sekunden, Gleitkommazahl).
- `started_at`, Zeitpunkt des Ausführungsbeginns der Aufgabe, Unix-Zeitstempel (Sekunden, Gleitkommazahl).
- `finished_at`, Zeitpunkt des Aufgabenabschlusses, Unix-Zeitstempel (Sekunden, Gleitkommazahl). Wenn die Aufgabe nicht abgeschlossen ist, wird dieses Feld nicht zurückgegeben.
- `elapsed`, Ausführungsdauer der Aufgabe, in Sekunden (Gleitkommazahl, auf 3 Dezimalstellen gerundet). Wenn die Aufgabe nicht abgeschlossen ist, wird dieses Feld nicht zurückgegeben.

## Stapelabfrageoperation

Dies dient der Abfrage von Aufgabendetails für mehrere Aufgaben-IDs. Der Unterschied zu oben besteht darin, dass action auf retrieve_batch ausgewählt werden muss.

**Request Body** umfasst:

- `ids`: Das hochgeladene Aufgaben-ID-Array.
- `action`: Die Operationsmethode für die Aufgabe.

## Fehlerbehandlung

Wenn beim Aufrufen der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Information zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
