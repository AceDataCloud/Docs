Diese Schnittstelle basiert auf der [Fish Audio offiziellen Model API](https://docs.fish.audio/resources/api-reference/model) und dient dazu, **vollständige Details eines einzelnen Klonklangs nach `_id` abzufragen**. Die Adresse lautet `GET https://api.acedata.cloud/fish/model/{id}`.

> Für die Erstellung von Klängen siehe bitte die [Fish Model Create API](https://platform.acedata.cloud/documents/fish-model); für die paginierte Abfrage siehe die [Fish Model Query API](https://platform.acedata.cloud/documents/fish-model-query).

## Antragsprozess

Um die Fish Model API zu nutzen, müssen Sie zunächst Ihr API-Token im [Ace Data Cloud Dashboard](https://platform.acedata.cloud/console/applications) abrufen und für zukünftige Verwendung aufbewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, wo Sie zur Registrierung und Anmeldung eingeladen werden. Nach Abschluss werden Sie automatisch zur aktuellen Seite zurückgeleitet.

**Ein API-Token reicht aus, um auf alle Dienste der Plattform zuzugreifen, es ist nicht erforderlich, für jeden Dienst separat zu beantragen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, um es kostenlos auszuprobieren; wenn das Kontingent erschöpft ist, können Sie im [Dashboard](https://platform.acedata.cloud/console/coin) Ihr allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Fish Model API →](https://platform.acedata.cloud/services/fish)

## Pfadparameter

| Parameter | Erforderlich | Beschreibung                                                                                                                                                                                                |
| --------- | ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`      | Ja           | Die `_id` des Klangs (32-stelliger hexadezimaler String). Kann bei der Erstellung über [Fish Model Create](https://platform.acedata.cloud/documents/fish-model) zurückgegeben oder über [Fish Model Query](https://platform.acedata.cloud/documents/fish-model-query) abgerufen werden. |

Keine Anforderungskörper, keine Abfrageparameter.

## Beispiel: Abrufen der vollständigen Details eines öffentlichen spanischen Klangs

```shell
curl 'https://api.acedata.cloud/fish/model/8d2c17a9b26d4d83888ea67a1ee565b2' \
  -H 'authorization: Bearer {token}'
```

Die erhaltene `_id` kann direkt an den `reference_id` von [Fish TTS](https://platform.acedata.cloud/documents/fish-tts) übergeben werden, um Sprache im gleichen Klang zu synthetisieren:

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "Hermanos míos, hoy es un buen día.",
    "reference_id": "8d2c17a9b26d4d83888ea67a1ee565b2",
    "format": "mp3"
  }'
```

## Unterschiede zur Listen-Schnittstelle

| Feld                                               | `GET /fish/model` (Liste) | `GET /fish/model/{id}` (Details) |
| -------------------------------------------------- | -------------------------- | --------------------------------- |
| `samples[].audio`                                  | Kurzfristige R2-Cache-URL  | Aktuelle signierte R2-Direktverbindung (mit Query-Signatur) |
| `unliked` / `liked` / `marked` / `dmca_taken_down` | Existiert ebenfalls         | Existiert ebenfalls                |
| `default_text` / `lock_visibility`                 | Existiert ebenfalls         | Existiert ebenfalls                |

Wenn Sie nur eine Vorschau hören möchten, reicht die `samples[].audio` in der Listen-Schnittstelle aus; für stabilere Download-Links wird empfohlen, diese Schnittstelle zu verwenden.

## Antwortfelder (Auszug)

| Feld            | Typ      | Beschreibung                                      |
| --------------- | -------- | ------------------------------------------------ |
| `_id`          | string   | Klang-ID (verwendet für `/fish/tts` `reference_id`). |
| `type`         | string   | Modelltyp, normalerweise `tts`.                  |
| `title`        | string   | Klangname.                                       |
| `description`  | string   | Lange Beschreibung.                               |
| `state`        | string   | Trainingsstatus: `trained` bedeutet verfügbar, `training` bedeutet noch im Training. |
| `tags`         | string[] | Tags der öffentlichen Bibliothek.                |
| `samples`      | object[] | Voreingestellte Proben, einschließlich `title`, `text`, `task_id`, `audio` Direktverbindung. |
| `languages`    | string[] | Sprachcodes, in denen der Klang gut ist.        |
| `visibility`   | string   | `public` oder `private`.                         |
| `like_count`   | integer  | Anzahl der Likes in der öffentlichen Bibliothek. |
| `task_count`   | integer  | Anzahl der historischen Synthesen (kann zur Beliebtheitsreihenfolge verwendet werden). |
| `author`       | object   | Informationen über den Autor: `_id` / `nickname` / `avatar`. |
| `created_at`   | string   | ISO 8601 Erstellungszeit.                       |
| `updated_at`   | string   | ISO 8601 letzte Aktualisierungszeit.            |

## Abrechnungsinformationen

Diese Schnittstelle ist kostenlos – die Abfrage von Einzelklangdetails nach ID ist eine kostenlose Operation. Die Erstellung von Klängen ([Fish Model Create](https://platform.acedata.cloud/documents/fish-model)) ist ebenfalls kostenlos, Kosten entstehen nur bei der Verwendung von [Fish TTS](https://platform.acedata.cloud/documents/fish-tts) zur Sprachsynthese.

## Fehlerbehandlung
- `400 token_mismatched`: Der `id` im Pfad hat kein gültiges Format oder der Upstream meldet „Model not found“.
- `401 invalid_token`: Der Authentifizierungstoken existiert nicht oder ist ungültig.
- `404 not_found`: Die angegebene `_id` ist im Fish-Upstream nicht sichtbar (Stimme wurde gelöscht, ist privat oder gehört zu einem anderen Konto).
- `429 too_many_requests`: Die Rate-Limitierung des Kontos wurde ausgelöst.
- `500 api_error`: Interner Serverfehler.

Wenn man tatsächlich eine nicht existierende ID anfragt, gibt der Upstream direkt `400 Model not found` zurück (getestet):

```shell
curl 'https://api.acedata.cloud/fish/model/test123' \
  -H 'authorization: Bearer {token}'
```

Rückgabe:

```json
{ "status": 400, "message": "Model not found" }
```

Beispiel für eine Fehlermeldung:

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## Fazit

Wenn die Stimme `_id` bekannt ist, kann man direkt über diese Schnittstelle das vollständige ModelEntity abrufen. Die häufigste Verwendung ist: (1) Anhören von `samples[].audio`, (2) die `_id` an `reference_id` von `/fish/tts` übergeben, um die Synthese abzuschließen. Wenn nur der Titel oder die Tags vorhanden sind, verwenden Sie bitte zuerst die [Fish Model Query](https://platform.acedata.cloud/documents/fish-model-query) zur Abfrage.
