## 1. API-Key abrufen

Öffnen Sie die [Ace Data Cloud Anwendungsliste](https://platform.acedata.cloud/console/applications), wechseln Sie zu einer verfügbaren Anwendung und kopieren Sie den API-Key.

## 2. Mit Bild-URL bearbeiten

Originalbild:

![GPT Image 2 Originalbild zur Bearbeitung](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://platform2.cdn.acedata.cloud/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0.png",
```

## 3. Lokale Bilder hochladen

Verwenden Sie `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` kann wiederholt übergeben werden, die GPT-Image-Serie unterstützt maximal 16 Referenzbilder. `image` in JSON-Anfragen kann eine einzelne URL oder ein URL-Array sein; lokale Dateien werden per Multipart hochgeladen.

## 4. Lokale Bearbeitung mit Maske

Die offizielle Images-Edit-Schnittstelle verwendet `mask`, um den Bereich anzugeben, der geändert werden darf. Das Modell `:official` von Ace Data Cloud folgt demselben Multipart-Vertrag:

- `mask` muss eine PNG-Datei mit Alpha-Kanal sein und darf nicht größer als 4 MB sein;
- die Maskengröße muss exakt mit der ersten `image` übereinstimmen;
- transparente Pixel mit Alpha `0` bedeuten, dass Bearbeitungen erlaubt sind, nicht transparente Pixel bedeuten, dass sie erhalten bleiben sollen;
- RGB-Bilder, die nur schwarz und weiß sind, aber keinen Transparenzkanal besitzen, können nicht als gültige Masken verwendet werden;
- der Prompt sollte das gewünschte vollständige Bild beschreiben und zugleich die lokalen Änderungen sowie die Inhalte, die unverändert bleiben müssen, klar angeben.

Im Folgenden wird zunächst aus dem Originalbild eine Maske erzeugt. Das Beispiel setzt das zentrale Rechteck auf transparent und erlaubt dem Modell nur, diesen Bereich zu ändern:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Laden Sie anschließend das Originalbild und die Maske zusammen hoch:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Sie können auch die Aufrufweise von `images.edit` des offiziellen OpenAI-Python-SDK beibehalten und lediglich `base_url` auf Ace Data Cloud verweisen lassen:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Bei Verwendung von `mask` müssen das Originalbild und die Maske im selben Multipart-Request jeweils über `image=@input.png` und `mask=@mask.png` hochgeladen werden. Übergeben Sie nicht gleichzeitig ein Originalbild per URL und eine lokale Maskendatei; reine URL-Bearbeitungsanfragen unterstützen kein zusätzlich angehängtes lokales `mask`-Dateiobjekt. Die Maske begrenzt den Bearbeitungsbereich, doch das Generierungsmodell kann die Ränder weiterhin natürlich überblenden; wenn strikte Grenzen erforderlich sind, sollten klare Alpha-Ränder verwendet und im Prompt wiederholt angegeben werden, welche Inhalte unverändert bleiben müssen.

Die obige Aufrufweise entspricht den Maskenbeispielen der [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) und des [offiziellen GPT-Image-Cookbooks](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Häufig verwendete Parameter

| Feld                | Beschreibung                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (schneller) oder `gpt-image-2.5-sunburst` (höhere Wiedergabetreue und Kontrolle); alle drei können die entsprechende Variante `:official` auswählen, `gpt-image-2` unterstützt außerdem `:reverse` |
| `image`           | JSON verwendet eine einzelne URL oder ein Array mit bis zu 16 URLs; Multipart verwendet ein oder mehrere `image`-Dateifelder. Bei Verwendung von `mask` müssen lokale Bilddateien hochgeladen werden                                              |
| `mask`            | Optionale PNG-Maske, nur für Multipart-Dateiuploads; muss einen Alpha-Kanal haben, dieselbe Größe wie die erste `image` besitzen und darf nicht größer als 4 MB sein                                                                 |
| `prompt`          | Bearbeitungsanweisung                                                                                                                             |
| `size`            | `auto` oder ein den Beschränkungen entsprechendes `WIDTHxHEIGHT`                                                                                                     |
| `n`               | 1–10; bei `response_format=b64_json` wird nur 1 unterstützt                                                                                           |
| `response_format` | `url` oder `b64_json`                                                                                                               |
| `callback_url`    | Optionale asynchrone Callback-Adresse                                                                                                                         |
Die Größenregeln entsprechen der Generierungs-Schnittstelle: Breite und Höhe müssen Vielfache von 16 sein, die lange Seite darf 3840 nicht überschreiten, die Gesamtpixelzahl beträgt 655.360–8.294.400, und das Seitenverhältnis darf 3:1 nicht überschreiten. Wenn `size` weggelassen oder `auto` verwendet wird, wählt das Modell anhand des Prompts und des ersten Referenzbilds das Bildformat.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` und `gpt-image-2:reverse` werden nach der Anzahl erfolgreich erstellter Bilder abgerechnet; `gpt-image-2:official`, `gpt-image-2.5-flare:official` und `gpt-image-2.5-sunburst:official` werden nach den tatsächlich verwendeten Token für Texteingaben, Referenzbildeingaben und Bildausgaben abgerechnet, maßgeblich sind letztlich die Nutzungsaufzeichnungen.

## 6. Asynchrone Rückrufe und Fehlerbehebung

Bei langen Aufgaben kann der Anfrage Folgendes hinzugefügt werden:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Die asynchrone 200-Antwort lautet `{"task_id": "..."}`; nach Abschluss wird das Endergebnis zurückgerufen. Synchrone Anfragen geben hingegen `created` und `data` zurück.

| Status  | Prüfung                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Bildformat/-anzahl, Parameterkombination und Größenformat; bei Verwendung von `mask` den PNG-Alpha-Kanal, das 4-MB-Limit sowie prüfen, ob dessen Größe mit dem ersten Originalbild übereinstimmt |
| 401 | API-Key und Bearer-Header                                           |
| 429 | Anfragehäufigkeit                                                              |
| 504 | Auf asynchrone Rückrufe umstellen                                                            |

Fehlerantworten enthalten `trace_id`. Geben Sie bei der Meldung von Problemen diese ID an, nicht den API-Key.

Vollständige Felder und aktuelle Aufzählungswerte finden Sie auf der Seite [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Für die reine Text-zu-Bild-Generierung siehe [GPT Image 2 / 2.5 Bildgenerierung](https://platform.acedata.cloud/documents/openai-images-generations).
