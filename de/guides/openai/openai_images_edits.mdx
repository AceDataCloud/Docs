## 1. API Key abrufen

Öffnen Sie die [Ace Data Cloud Anwendungsliste](https://platform.acedata.cloud/console/applications), rufen Sie eine verfügbare Anwendung auf und kopieren Sie den API Key.

![Ace Data Cloud API Key abrufen](https://cdn.acedata.cloud/dvc3cg.jpg)

## 2. Mit Bild-URL bearbeiten

Originalbild:

![GPT Image 2 Originalbild zur Bearbeitung](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
```

## 3. Lokales Bild hochladen

Verwenden Sie `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` kann wiederholt übergeben werden; die GPT-Image-Serie unterstützt maximal 16 Referenzbilder. `image` in JSON-Anfragen kann eine einzelne URL oder ein URL-Array sein; lokale Dateien werden per Multipart hochgeladen.

### Modelle und Abrechnungsmethoden

| Modell                                | Anwendungsszenarien und Abrechnungsmethoden                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | Standardmäßiger Reverse-Kanal, feste Abrechnung nach Anzahl erfolgreicher Bilder                               |
| `gpt-image-2:reverse`             | Explizite Auswahl des Reverse-Kanals, feste Abrechnung nach Anzahl erfolgreicher Bilder                             |
| `gpt-image-2:official`            | Offizieller API-Kanal, höhere Stabilität, Abrechnung nach tatsächlichem Token-Verbrauch                   |
| `gpt-image-2.5-flare`             | Fokus auf Generierungsgeschwindigkeit, feste Abrechnung nach Anzahl erfolgreicher Bilder                               |
| `gpt-image-2.5-flare:reverse`     | Expliziter Reverse-Alias, gleichwertig mit `gpt-image-2.5-flare`, feste Abrechnung nach Anzahl erfolgreicher Bilder    |
| `gpt-image-2.5-flare:official`    | Offizieller API-Kanal, höhere Stabilität und Fokus auf Generierungsgeschwindigkeit, Abrechnung nach tatsächlichem Token-Verbrauch            |
| `gpt-image-2.5-sunburst`          | Fokus auf hohe Wiedergabetreue und präzise Steuerung, feste Abrechnung nach Anzahl erfolgreicher Bilder                           |
| `gpt-image-2.5-sunburst:reverse`  | Expliziter Reverse-Alias, gleichwertig mit `gpt-image-2.5-sunburst`, feste Abrechnung nach Anzahl erfolgreicher Bilder |
| `gpt-image-2.5-sunburst:official` | Offizieller API-Kanal, höhere Stabilität und Fokus auf hohe Wiedergabetreue und präzise Steuerung, Abrechnung nach tatsächlichem Token-Verbrauch        |

Reverse-Modelle (einschließlich der `:reverse`-Aliase) können bei der automatischen Wiederherstellung GPT Image 2.5 Flare zur Ausführung der Anfrage verwenden; das angeforderte Modell und die Abrechnung nach Anzahl erfolgreicher Bilder bleiben unverändert.

Die auf der Seite angezeigten Preise für den offiziellen API-Kanal sind Schätzungen vor der Anfrage; maßgeblich sind letztendlich der tatsächliche Token-Verbrauch in der Antwort und die Nutzungsaufzeichnungen.

`quality` unterstützt `auto`, `low`, `medium`, `high`; nur `gpt-image-2.5-flare` und `gpt-image-2.5-sunburst` (einschließlich der Varianten `:reverse` und `:official`) unterstützen zusätzlich `xhigh`, `max`. Sowohl die Bearbeitung von Bild-URLs per JSON als auch die Bearbeitung von Multipart-Dateien können dieses Feld übergeben; der offizielle Kanal rechnet nach tatsächlichem Token-Verbrauch ab.

## 4. Lokale Bearbeitung mit Maske

Die offizielle Images-Edit-Schnittstelle verwendet `mask`, um den Bereich festzulegen, der geändert werden darf. Die `:official`-Modelle von Ace Data Cloud folgen demselben Multipart-Vertrag:

- `mask` muss eine PNG-Datei mit Alpha-Kanal sein und darf nicht größer als 4 MB sein;
- Die Maskengröße muss exakt mit dem ersten `image` übereinstimmen;
- Transparente Pixel mit Alpha `0` zeigen an, dass Bearbeitungen erlaubt sind, nicht transparente Pixel zeigen an, dass sie beibehalten werden sollen;
- RGB-Bilder, die nur schwarz-weiß sind, aber keinen Transparenzkanal haben, können nicht als gültige Masken verwendet werden;
- Der Prompt sollte das gewünschte vollständige Bild beschreiben und gleichzeitig die lokalen Änderungen sowie die Inhalte, die unverändert bleiben müssen, klar angeben.

Erstellen Sie zunächst aus dem Originalbild eine Maske. Das Beispiel setzt das zentrale Rechteck auf transparent und erlaubt dem Modell nur, diesen Bereich zu ändern:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Laden Sie dann das Originalbild und die Maske zusammen hoch:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Sie können auch die Aufrufweise von `images.edit` des offiziellen OpenAI-Python-SDKs weiterhin verwenden; Sie müssen nur `base_url` auf Ace Data Cloud verweisen lassen:
```python
from openai import OpenAI

client = OpenAI(
    api_key="Ihr API-Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Behalte die Komposition, Beleuchtung und alle Objekte außerhalb der "
            "transparenten Maske unverändert bei. Ersetze innerhalb des maskierten Bereichs "
            "die leere Tischplatte durch eine kleine blaue Keramikvase."
        ),
    )

print(result.data[0].url)
```

Bei Verwendung von `mask` müssen das Originalbild und die Maske in derselben Multipart-Anfrage jeweils über `image=@input.png` und `mask=@mask.png` hochgeladen werden. Übergeben Sie nicht ein URL-Originalbild und eine lokale Maskendatei zusammen; reine URL-Bearbeitungsanfragen unterstützen kein zusätzliches lokales `mask`-Datei. Die Maske begrenzt den Bearbeitungsbereich, aber das Generierungsmodell kann die Ränder dennoch natürlich überblenden; wenn strikte Grenzen erforderlich sind, sollten klare Alpha-Ränder verwendet und in der Eingabeaufforderung wiederholt angegeben werden, welche Inhalte unverändert bleiben müssen.

Die obige Aufrufweise entspricht den Maskenbeispielen in der [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) und im [offiziellen GPT Image Cookbook](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Häufig verwendete Parameter

| Feld                | Beschreibung                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (schneller) oder `gpt-image-2.5-sunburst` (höhere Wiedergabetreue und Kontrolle); für alle drei kann die entsprechende Variante `:official` gewählt werden, `gpt-image-2` unterstützt außerdem `:reverse` |
| `image`           | JSON verwendet eine einzelne URL oder ein Array mit bis zu 16 URLs; Multipart verwendet ein oder mehrere `image`-Dateifelder. Bei Verwendung von `mask` müssen lokale Bilddateien hochgeladen werden                                              |
| `mask`            | Optionale PNG-Maske, nur für Multipart-Dateiuploads; muss einen Alpha-Kanal haben, dieselbe Größe wie das erste `image` aufweisen und darf 4 MB nicht überschreiten                                                                 |
| `prompt`          | Bearbeitungsanweisung                                                                                                                             |
| `size`            | `auto` oder ein den Beschränkungen entsprechendes `WIDTHxHEIGHT`                                                                                                     |
| `n`               | 1–10; bei `response_format=b64_json` wird nur 1 unterstützt                                                                                           |
| `response_format` | `url` oder `b64_json`                                                                                                               |
| `callback_url`    | Optionale asynchrone Callback-Adresse                                                                                                                         |

Die Größenregeln entsprechen denen der Generierungsschnittstelle: Breite und Höhe müssen Vielfache von 16 sein, die lange Seite darf 3840 nicht überschreiten, die Gesamtpixelzahl beträgt 655.360–8.294.400 und das Seitenverhältnis darf 3:1 nicht überschreiten. Wenn `size` weggelassen oder `auto` verwendet wird, wählt das Modell anhand der Eingabeaufforderung und des ersten Referenzbilds das Bildformat.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` und ihre `:reverse`-Aliasse werden nach der Anzahl erfolgreich erstellter Bilder abgerechnet; `gpt-image-2:official`, `gpt-image-2.5-flare:official` und `gpt-image-2.5-sunburst:official` werden anhand der tatsächlichen Token für Texteingabe, Referenzbildeingabe und Bildausgabe abgerechnet, maßgeblich sind letztlich die Nutzungsaufzeichnungen.

## 6. Asynchrone Callbacks und Fehlerbehebung

Für lange Aufgaben kann der Anfrage Folgendes hinzugefügt werden:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Die asynchrone 200-Antwort lautet `{"task_id": "..."}`; nach Abschluss wird das Endergebnis per Callback übermittelt. Synchrone Anfragen geben hingegen `created` und `data` zurück.

| Status  | Prüfen                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Bildformat/-anzahl, Parameterkombinationen und Größenformat; bei Verwendung von `mask` den PNG-Alpha-Kanal, die 4-MB-Grenze und prüfen, ob seine Größe mit dem ersten Originalbild übereinstimmt |
| 401 | API-Key und Bearer-Header                                           |
| 429 | Anfragerate                                                              |
| 504 | Auf asynchrone Callbacks umstellen                                                            |

Fehlerantworten enthalten `trace_id`. Geben Sie bei der Meldung eines Problems diese ID an, nicht den API-Key.

Vollständige Felder und aktuelle Aufzählungen finden Sie auf der Seite [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Für die Bildgenerierung aus reinem Text siehe [GPT Image 2 / 2.5 Bildgenerierung](https://platform.acedata.cloud/documents/openai-images-generations).
