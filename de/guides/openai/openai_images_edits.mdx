## 3. Lokales Bild hochladen

Verwenden Sie `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` kann wiederholt übergeben werden; die GPT-Image-Serie unterstützt maximal 16 Referenzbilder. `image` in JSON-Anfragen kann eine einzelne URL oder ein URL-Array sein; lokale Dateien werden per Multipart hochgeladen.

### Modelle und Abrechnungsmethoden

| Modell                                | Geeignete Szenarien und Abrechnungsmethode                                 |
| --------------------------------- | ----------------------------------------- |
| `gpt-image-2`                     | Standardmäßiger Reverse-Kanal, feste Abrechnung nach Anzahl erfolgreicher Bilder                        |
| `gpt-image-2:reverse`             | Reverse-Kanal explizit auswählen, feste Abrechnung nach Anzahl erfolgreicher Bilder                      |
| `gpt-image-2:official`            | Offizieller API-Kanal, höhere Stabilität, Abrechnung nach tatsächlichem Token-Verbrauch            |
| `gpt-image-2.5-flare`             | Schwerpunkt auf Generierungsgeschwindigkeit, feste Abrechnung nach Anzahl erfolgreicher Bilder                        |
| `gpt-image-2.5-flare:official`    | Offizieller API-Kanal, höhere Stabilität und Schwerpunkt auf Generierungsgeschwindigkeit, Abrechnung nach tatsächlichem Token-Verbrauch     |
| `gpt-image-2.5-sunburst`          | Schwerpunkt auf hoher Wiedergabetreue und präziser Steuerung, feste Abrechnung nach Anzahl erfolgreicher Bilder                    |
| `gpt-image-2.5-sunburst:official` | Offizieller API-Kanal, höhere Stabilität und Schwerpunkt auf hoher Wiedergabetreue und präziser Steuerung, Abrechnung nach tatsächlichem Token-Verbrauch |

Die auf der Seite angezeigten Preise für offizielle API-Kanäle sind Schätzungen vor der Anfrage; maßgeblich sind letztlich der tatsächliche Token-Verbrauch in der Antwort und die Nutzungsaufzeichnungen.

## 4. Lokale Bearbeitung mit Maske verwenden

Die offizielle Images-Edit-Schnittstelle verwendet `mask`, um den Bereich festzulegen, der geändert werden darf. Die `:official`-Modelle von Ace Data Cloud folgen demselben Multipart-Vertrag:

- `mask` muss eine PNG-Datei mit Alpha-Kanal sein und darf nicht größer als 4 MB sein;
- die Maskengröße muss exakt mit der ersten `image` übereinstimmen;
- transparente Pixel mit Alpha `0` zeigen an, dass Bearbeitungen erlaubt sind, nicht transparente Pixel zeigen an, dass sie erhalten bleiben sollen;
- RGB-Bilder, die nur schwarz und weiß sind, aber keinen Transparenzkanal haben, können nicht als gültige Masken verwendet werden;
- der Prompt sollte das gewünschte vollständige Bild beschreiben und zugleich die lokale Änderung sowie den unverändert zu haltenden Inhalt klar angeben.

Im Folgenden wird zunächst eine Maske aus dem Originalbild erzeugt. Das Beispiel setzt das zentrale Rechteck auf transparent und erlaubt dem Modell nur, diesen Bereich zu ändern:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Laden Sie anschließend das Originalbild und die Maske gemeinsam hoch:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Sie können auch weiterhin die Aufrufmethode `images.edit` des offiziellen OpenAI-Python-SDK verwenden; Sie müssen nur `base_url` auf Ace Data Cloud setzen:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Bei Verwendung von `mask` müssen das Originalbild und die Maske im selben Multipart-Request jeweils über `image=@input.png` und `mask=@mask.png` hochgeladen werden. Übergeben Sie kein URL-Originalbild zusammen mit einer lokalen Maskendatei; reine URL-Bearbeitungsanfragen unterstützen nicht das zusätzliche Anhängen lokaler `mask`-Dateien. Die Maske begrenzt den Bearbeitungsbereich, aber das Generierungsmodell kann an den Rändern dennoch eine natürliche Überblendung vornehmen; wenn strikte Grenzen erforderlich sind, sollten klare Alpha-Kanten verwendet und im Prompt wiederholt angegeben werden, welche Inhalte unverändert bleiben müssen.

Die obige Aufrufmethode entspricht den Maskenbeispielen der [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) und des [offiziellen GPT Image Cookbook](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).
## 5. Häufig verwendete Parameter

| Feld                | Beschreibung                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (schneller) oder `gpt-image-2.5-sunburst` (höhere Wiedergabetreue und Kontrolle); für alle drei kann die entsprechende Variante `:official` ausgewählt werden, `gpt-image-2` unterstützt außerdem `:reverse` |
| `image`           | JSON verwendet eine einzelne URL oder ein Array mit bis zu 16 URLs; multipart verwendet ein oder mehrere `image`-Dateifelder. Bei Verwendung von `mask` muss eine lokale Bilddatei hochgeladen werden                                              |
| `mask`            | Optionale PNG-Maske, nur für multipart-Dateiuploads; muss einen Alpha-Kanal haben, dieselbe Größe wie das erste `image` aufweisen und darf 4 MB nicht überschreiten                                                                 |
| `prompt`          | Bearbeitungsanweisung                                                                                                                             |
| `size`            | `auto` oder ein den Einschränkungen entsprechendes `WIDTHxHEIGHT`                                                                                                     |
| `n`               | 1–10; bei `response_format=b64_json` wird nur 1 unterstützt                                                                                           |
| `response_format` | `url` oder `b64_json`                                                                                                               |
| `callback_url`    | Optionale asynchrone Callback-Adresse                                                                                                                         |

Die Größenregeln entsprechen denen der Generierungsschnittstelle: Breite und Höhe müssen Vielfache von 16 sein, die längere Seite darf 3840 nicht überschreiten, die Gesamtpixelzahl beträgt 655.360–8.294.400 und das Seitenverhältnis darf 3:1 nicht überschreiten. Wenn `size` weggelassen oder `auto` verwendet wird, wählt das Modell anhand des Prompts und des ersten Referenzbildes das Bildformat aus.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` und `gpt-image-2:reverse` werden nach der Anzahl erfolgreich erzeugter Bilder abgerechnet; `gpt-image-2:official`, `gpt-image-2.5-flare:official` und `gpt-image-2.5-sunburst:official` werden nach den tatsächlichen Tokens für Texteingabe, Referenzbildeingabe und Bildausgabe abgerechnet; maßgeblich sind die Nutzungsaufzeichnungen.

## 6. Asynchrone Callbacks und Fehlerbehebung

Bei lang laufenden Aufgaben kann der Anfrage Folgendes hinzugefügt werden:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Die asynchrone 200-Antwort lautet `{"task_id": "..."}`; nach Abschluss wird das endgültige Ergebnis per Callback zurückgegeben. Synchronisierte Anfragen geben dagegen `created` und `data` zurück.

| Status  | Prüfen                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Bildformat/-anzahl, Parameterkombinationen und Größenformat; bei Verwendung von `mask` den PNG-Alpha-Kanal, die 4-MB-Beschränkung sowie prüfen, ob die Größe mit dem ersten Originalbild übereinstimmt |
| 401 | API Key und Bearer Header                                           |
| 429 | Anfragehäufigkeit                                                              |
| 504 | Asynchronen Callback verwenden                                                            |

Fehlerantworten enthalten `trace_id`. Geben Sie bei der Meldung von Problemen diese ID an, nicht den API Key.

Die vollständigen Felder und Echtzeit-Enumerationen sind auf der Seite [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits) maßgeblich. Für die Bildgenerierung nur mit Text siehe [GPT Image 2 / 2.5 Bildgenerierung](https://platform.acedata.cloud/documents/openai-images-generations).
