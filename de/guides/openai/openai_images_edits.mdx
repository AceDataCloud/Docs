## 1. API Key abrufen

Öffnen Sie die [Ace Data Cloud Anwendungsliste](https://platform.acedata.cloud/console/applications), rufen Sie eine verfügbare Anwendung auf und kopieren Sie den API Key.

## 2. Mit Bild-URL bearbeiten

Originalbild:

![GPT Image 2 Originalbild zur Bearbeitung](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
```

## 3. Lokale Bilder hochladen

Verwenden Sie `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` kann wiederholt übergeben werden; die GPT-Image-Serie unterstützt maximal 16 Referenzbilder. `image` in JSON-Anfragen kann eine einzelne URL oder ein URL-Array sein; lokale Dateien werden per multipart hochgeladen.

### Modelle und Abrechnungsarten

| Modell                                | Anwendungsfall und Abrechnungsart                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | Standardmäßiger Reverse-Kanal, Festpreis pro erfolgreich generiertem Bild                               |
| `gpt-image-2:reverse`             | Explizite Auswahl des Reverse-Kanals, Festpreis pro erfolgreich generiertem Bild                             |
| `gpt-image-2:official`            | Offizieller API-Kanal, höhere Stabilität, Abrechnung nach tatsächlichem Token-Verbrauch                   |
| `gpt-image-2.5-flare`             | Schwerpunkt auf Generierungsgeschwindigkeit, Festpreis pro erfolgreich generiertem Bild                               |
| `gpt-image-2.6-flare`             | Schwerpunkt auf Generierungsgeschwindigkeit, Festpreis pro erfolgreich generiertem Bild                               |
| `gpt-image-2.5-flare:reverse`     | Expliziter Reverse-Alias, gleichwertig mit `gpt-image-2.5-flare`, Festpreis pro erfolgreich generiertem Bild    |
| `gpt-image-2.6-flare:reverse`     | Expliziter Reverse-Alias, gleichwertig mit `gpt-image-2.6-flare`, Festpreis pro erfolgreich generiertem Bild    |
| `gpt-image-2.5-flare:official`    | Offizieller API-Kanal, höhere Stabilität und Schwerpunkt auf Generierungsgeschwindigkeit, Abrechnung nach tatsächlichem Token-Verbrauch            |
| `gpt-image-2.6-flare:official`    | Offizieller API-Kanal, höhere Stabilität und Schwerpunkt auf Generierungsgeschwindigkeit, Abrechnung nach tatsächlichem Token-Verbrauch            |
| `gpt-image-2.5-sunburst`          | Schwerpunkt auf hoher Wiedergabetreue und präziser Steuerung, Festpreis pro erfolgreich generiertem Bild                           |
| `gpt-image-2.6-sunburst`          | Schwerpunkt auf hoher Wiedergabetreue und präziser Steuerung, Festpreis pro erfolgreich generiertem Bild                           |
| `gpt-image-2.5-sunburst:reverse`  | Expliziter Reverse-Alias, gleichwertig mit `gpt-image-2.5-sunburst`, Festpreis pro erfolgreich generiertem Bild |
| `gpt-image-2.6-sunburst:reverse`  | Expliziter Reverse-Alias, gleichwertig mit `gpt-image-2.6-sunburst`, Festpreis pro erfolgreich generiertem Bild |
| `gpt-image-2.5-sunburst:official` | Offizieller API-Kanal, höhere Stabilität und Schwerpunkt auf hoher Wiedergabetreue und präziser Steuerung, Abrechnung nach tatsächlichem Token-Verbrauch        |
| `gpt-image-2.6-sunburst:official` | Offizieller API-Kanal, höhere Stabilität und Schwerpunkt auf hoher Wiedergabetreue und präziser Steuerung, Abrechnung nach tatsächlichem Token-Verbrauch        |

Bei Reverse-Modellen 2.0 / 2.5 (einschließlich der `:reverse`-Aliasse) kann bei der automatischen Wiederherstellung GPT Image 2.5 Flare zur Ausführung der Anfrage verwendet werden; das angeforderte Modell und die Abrechnungsart pro erfolgreich generiertem Bild bleiben unverändert.

Der auf der Seite angezeigte Preis des offiziellen API-Kanals ist eine Schätzung vor der Anfrage; maßgeblich sind letztendlich der tatsächliche Token-Verbrauch in der Antwort und der Nutzungsnachweis.

`quality` unterstützt `auto`, `low`, `medium`, `high`; 2.5 / 2.6 Flare und Sunburst (einschließlich der Varianten `:reverse` und `:official`) unterstützen zusätzlich `xhigh`, `max`. Sowohl die Bearbeitung von Bild-URLs per JSON als auch die Bearbeitung von Dateien per multipart können dieses Feld übergeben; der offizielle Kanal rechnet nach tatsächlichem Token-Verbrauch ab.

## 4. Lokale Bearbeitung mit Masken

Die offizielle Images-Edit-Schnittstelle gibt über `mask` die Bereiche an, die geändert werden dürfen. Die `:official`-Modelle von Ace Data Cloud folgen demselben multipart-Vertrag:

- `mask` muss eine PNG-Datei mit Alpha-Kanal sein und darf nicht größer als 4 MB sein;
- Die Maskengröße muss vollständig mit der ersten `image` übereinstimmen;
- Transparente Pixel mit Alpha `0` bedeuten, dass Bearbeitung erlaubt ist, nicht transparente Pixel bedeuten, dass sie beibehalten werden sollen;
- RGB-Bilder, die nur schwarz-weiß sind, aber keinen Transparenzkanal haben, können nicht als gültige Masken verwendet werden;
- Der Prompt sollte das gewünschte vollständige Bild beschreiben und gleichzeitig die lokale Änderung sowie die Inhalte, die unverändert bleiben müssen, klar angeben.

Generieren Sie zunächst aus dem Originalbild eine Maske. Das Beispiel setzt das zentrale Rechteck auf transparent, sodass das Modell nur diesen Bereich ändern darf:
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Laden Sie dann das Originalbild und die Maske zusammen hoch:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Sie können auch die Aufrufmethode `images.edit` des offiziellen OpenAI-Python-SDKs weiterhin verwenden; Sie müssen lediglich `base_url` auf Ace Data Cloud verweisen lassen:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Bei Verwendung von `mask` müssen das Originalbild und die Maske im selben Multipart-Request jeweils über `image=@input.png` und `mask=@mask.png` hochgeladen werden. Übergeben Sie kein Originalbild per URL zusammen mit einer lokalen Maskendatei; reine URL-Bearbeitungsanfragen unterstützen kein zusätzliches lokales `mask`-File. Die Maske begrenzt den Bearbeitungsbereich, das Generierungsmodell kann jedoch weiterhin an den Rändern eine natürliche Überblendung vornehmen; wenn strikte Grenzen erforderlich sind, sollten klare Alpha-Ränder verwendet und im Prompt wiederholt angegeben werden, welche Inhalte unverändert bleiben müssen.

Die obigen Aufrufmethoden entsprechen den Maskenbeispielen der [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) und des [offiziellen GPT Image Cookbook](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Häufig verwendete Parameter

| Feld                | Beschreibung                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (schneller) oder `gpt-image-2.5-sunburst` (höhere Genauigkeit und Kontrolle); alle drei können die entsprechende Variante `:official` wählen, `gpt-image-2` unterstützt außerdem `:reverse` |
| `image`           | JSON verwendet eine einzelne URL oder ein Array mit bis zu 16 URLs; Multipart verwendet ein oder mehrere `image`-Dateifelder. Bei Verwendung von `mask` müssen lokale Bilddateien hochgeladen werden                                              |
| `mask`            | Optionale PNG-Maske, nur für Multipart-Dateiuploads; muss einen Alpha-Kanal haben, dieselbe Größe wie das erste `image` aufweisen und darf 4 MB nicht überschreiten                                                                 |
| `prompt`          | Bearbeitungsanweisung                                                                                                                             |
| `size`            | `auto` oder ein den Beschränkungen entsprechendes `WIDTHxHEIGHT`                                                                                                     |
| `n`               | 1–10; bei `response_format=b64_json` wird nur 1 unterstützt                                                                                           |
| `response_format` | `url` oder `b64_json`                                                                                                               |
| `callback_url`    | Optionale asynchrone Callback-Adresse                                                                                                                         |

Die Größenregeln entsprechen denen der Generierungsschnittstelle: Breite und Höhe müssen Vielfache von 16 sein, die lange Seite darf 3840 nicht überschreiten, die Gesamtpixelzahl beträgt 655.360–8.294.400 und das Seitenverhältnis darf 3:1 nicht überschreiten. Wenn `size` weggelassen oder `auto` verwendet wird, wählt das Modell anhand des Prompts und des ersten Referenzbilds das Bildformat.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` und ihre `:reverse`-Aliasse werden nach der Anzahl erfolgreich erzeugter Bilder abgerechnet; `gpt-image-2:official`, `gpt-image-2.5-flare:official` und `gpt-image-2.5-sunburst:official` werden anhand der tatsächlichen Token für Texteingabe, Referenzbildeingabe und Bildausgabe abgerechnet, maßgeblich sind letztlich die Nutzungsaufzeichnungen.

## 6. Asynchrone Callbacks und Fehlerbehebung

Bei lang laufenden Aufgaben kann Folgendes zur Anfrage hinzugefügt werden:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Die asynchrone 200-Antwort lautet `{"task_id": "..."}`; nach Abschluss wird das Endergebnis per Callback zurückgegeben. Synchrone Anfragen geben hingegen `created` und `data` zurück.

| Status  | Prüfen                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Bildformat/-anzahl, Parameterkombinationen und Größenformat; bei Verwendung von `mask` den PNG-Alpha-Kanal, das 4-MB-Limit sowie prüfen, ob die Größe mit dem ersten Originalbild übereinstimmt |
| 401 | API Key und Bearer-Header                                           |
| 429 | Anfragehäufigkeit                                                              |
| 504 | Auf asynchrone Callbacks umstellen                                                            |

Fehlerantworten enthalten `trace_id`. Geben Sie bei der Meldung von Problemen diese ID an, nicht den API Key.

Vollständige Felder und aktuelle Aufzählungen finden Sie auf der Seite [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Für die Bildgenerierung aus reinem Text siehe [GPT Image 2 / 2.5 / 2.6 Bildgenerierung](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 übernimmt die Schnittstellen von 2.5 für Generierung, Bearbeitung, asynchrone Aufgaben und Abrechnung:

| Modell                                                          | Abrechnung                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0.22 Credits/Bild                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0.22 Credits/Bild                   |
| `gpt-image-2.6-flare:official`                              | Wie bei 2.5 official, Abrechnung nach tatsächlichem Token-Verbrauch |
| `gpt-image-2.6-sunburst:official`                           | Wie bei 2.5 official, Abrechnung nach tatsächlichem Token-Verbrauch |

Für die Qualität stehen `auto`, `low`, `medium`, `high`, `xhigh`, `max` zur Auswahl; für die Größe verwenden Sie `auto` oder ein den obigen Beschränkungen entsprechendes `WIDTHxHEIGHT`. Diese Schnittstelle unterstützt `png`, `jpeg`, `webp`; GPT Image 2.6 unterstützt außerdem native `gif`-Animationen, SVG wird vorerst nicht unterstützt. Die Bearbeitung unterstützt JSON-Bild-URLs und Multipart-Dateiuploads. `:reverse` ist ein expliziter Alias der gleichnamigen normalen Version. Verwenden Sie die vollständige Modellbezeichnung und übergeben Sie nicht `gpt-image-2.6`.

### GPT Image 2.6 Bild-zu-GIF-Animationen
Die Standardversion von Flare, `:reverse`, `:official` sowie `gpt-image-2.6-sunburst:official` können `output_format: "gif"` verwenden. Die Standardversion von Sunburst und `:reverse` bieten GIF vorerst nicht an und unterstützen weiterhin die Generierung und Bearbeitung statischer Bilder. Animationsframes, Schleifeninformationen und Wiedergabedauer bleiben erhalten; `frame_count` bezeichnet die Anzahl der Frames, `frame_duration_ms` bezeichnet die Millisekunden pro Frame, beide müssen positive ganze Zahlen sein und werden nur für GIF verwendet. Wenn nicht angegeben, sind standardmäßig 9 Frames mit jeweils 200 Millisekunden eingestellt; wenn die `size` für GIF ausgelassen wird oder auto ist, wird die Voreinstellung 512x512 verwendet.

Es wird empfohlen, zunächst `size: "512x512"`, `frame_count: 9` und `frame_duration_ms: 200` zu verwenden. GIFs haben unabhängige Beschränkungen für Größe und Frame-Anzahl und können nicht direkt die statischen 4K-Spezifikationen übernehmen; einige Modelle passen die tatsächliche Ausgabegröße an. `n` bezeichnet die Anzahl der zurückgegebenen GIF-Dateien, nicht die Anzahl der Animationsframes. Die Standardversion und `:reverse` werden weiterhin nach der Anzahl erfolgreicher Dateien abgerechnet, die offizielle Version nach dem tatsächlichen Token-Verbrauch.

```json
{
  "model": "gpt-image-2.6-flare",
  "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
  "prompt": "Animate the mug gently moving left and right. Keep its appearance and the background, no text.",
  "output_format": "gif",
  "size": "512x512",
  "quality": "medium",
  "frame_count": 9,
  "frame_duration_ms": 200,
  "n": 1,
  "async": true
}
```

### GPT Image 2.6 4K-Standbilder

Flare, Sunburst sowie deren Varianten `:reverse` und `:official` können alle die zuvor genannten 4K-Pixelvoreinstellungen verwenden, beispielsweise `3840x2160` und `2160x3840`. Sowohl Generierung als auch Bearbeitung übergeben konkrete Pixel über `size`; `4K` ist kein gültiger `size`-Wert, und `4096x4096` überschreitet ebenfalls das aktuelle Pixel-Limit. Die oben genannten 4K-Spezifikationen gelten für statische PNG/JPEG/WebP-Dateien; für GIF verwenden Sie bitte die entsprechenden speziellen Parameter.
