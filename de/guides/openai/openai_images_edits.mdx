## 3. Lokales Bild hochladen

Verwenden Sie `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` kann wiederholt übergeben werden; die GPT-Image-Serie unterstützt maximal 16 Referenzbilder. `image` in JSON-Anfragen kann eine einzelne URL oder ein URL-Array sein; lokale Dateien werden über multipart hochgeladen.

## 4. Lokale Bearbeitung mit Maske verwenden

Die offizielle Images-Edit-Schnittstelle gibt über `mask` den Bereich an, der geändert werden darf. Die `:official`-Modelle von Ace Data Cloud folgen demselben Multipart-Vertrag:

- `mask` muss eine PNG-Datei mit Alpha-Kanal sein und darf nicht größer als 4 MB sein;
- Die Größe der Maske muss exakt mit der ersten `image` übereinstimmen;
- Transparente Pixel mit Alpha `0` zeigen an, dass Bearbeitungen erlaubt sind, nicht transparente Pixel zeigen an, dass sie beibehalten werden sollen;
- RGB-Bilder, die nur schwarz und weiß sind, aber keinen Transparenzkanal haben, können nicht als gültige Masken verwendet werden;
- Der Prompt sollte das gewünschte vollständige Bild beschreiben und gleichzeitig die lokale Änderung sowie den Inhalt, der unverändert bleiben soll, klar angeben.

Erstellen Sie zunächst eine Maske aus dem Originalbild. Das Beispiel setzt das mittlere Rechteck auf transparent und erlaubt dem Modell nur, diesen Bereich zu ändern:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Laden Sie dann das Originalbild und die Maske zusammen hoch:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Sie können auch weiterhin die Aufrufmethode `images.edit` des offiziellen OpenAI-Python-SDK verwenden; Sie müssen lediglich `base_url` auf Ace Data Cloud setzen:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

`mask` wird derzeit als Multipart-Dateifeld bereitgestellt. Wenn Sie das Originalbild per URL übergeben müssen, ändern Sie die Anfrage ebenfalls in multipart: `image` kann weiterhin als URL-Textfeld verwendet werden, `mask` wird mit `@mask.png` hochgeladen. Die Maske begrenzt den Bearbeitungsbereich, das generative Modell kann jedoch weiterhin an den Rändern natürliche Übergänge erzeugen; wenn strikte Grenzen erforderlich sind, sollten Sie klare Alpha-Ränder verwenden und im Prompt wiederholt angeben, welche Inhalte unverändert bleiben müssen.

Die obige Aufrufmethode entspricht den Maskenbeispielen der [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) und des [offiziellen GPT Image Cookbook](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Häufig verwendete Parameter

| Feld                | Beschreibung                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (schneller) oder `gpt-image-2.5-sunburst` (höhere Genauigkeit und Kontrolle); alle drei können die entsprechende `:official`-Variante wählen, `gpt-image-2` unterstützt außerdem `:reverse` |
| `image`           | JSON verwendet eine einzelne URL oder ein Array mit bis zu 16 URLs; multipart verwendet ein oder mehrere `image`-Dateifelder                                                                    |
| `prompt`          | Bearbeitungsanweisung                                                                                                                             |
| `size`            | `auto` oder ein den Einschränkungen entsprechendes `WIDTHxHEIGHT`                                                                                                     |
| `n`               | 1–10; bei `response_format=b64_json` wird nur 1 unterstützt                                                                                           |
| `response_format` | `url` oder `b64_json`                                                                                                               |
| `callback_url`    | Optionale asynchrone Callback-Adresse                                                                                                                         |

Die Größenregeln entsprechen denen der Generierungsschnittstelle: Breite und Höhe müssen Vielfache von 16 sein, die lange Seite darf 3840 nicht überschreiten, die Gesamtpixelzahl beträgt 655.360–8.294.400 und das Seitenverhältnis darf 3:1 nicht überschreiten. Wenn `size` weggelassen oder `auto` verwendet wird, wählt das Modell anhand des Prompts und des ersten Referenzbildes das Bildformat aus.
`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` und `gpt-image-2:reverse` werden nach der Anzahl erfolgreich erstellter Bilder abgerechnet; `gpt-image-2:official`, `gpt-image-2.5-flare:official` und `gpt-image-2.5-sunburst:official` werden anhand der tatsächlichen Tokens für Texteingabe, Referenzbildeingabe und Bildausgabe abgerechnet, maßgeblich sind letztlich die Nutzungsaufzeichnungen.

## 6. Asynchrone Rückrufe und Fehlersuche

Lange Aufgaben können der Anfrage Folgendes hinzufügen:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Die asynchrone 200-Antwort lautet `{"task_id": "..."}`; nach Abschluss wird das Endergebnis zurückgerufen. Synchronisierte Anfragen geben hingegen `created` und `data` zurück.

| Status  | Prüfung                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Bildformat/-anzahl, Parameterkombination und Größenformat; bei Verwendung von `mask` den PNG-Alpha-Kanal, die 4-MB-Beschränkung sowie prüfen, ob dessen Größe mit dem ersten Originalbild übereinstimmt |
| 401 | API-Key und Bearer-Header                                           |
| 429 | Anfragehäufigkeit                                                              |
| 504 | Auf asynchronen Rückruf umstellen                                                            |

Fehlerantworten enthalten `trace_id`. Geben Sie bei der Meldung von Problemen diese ID an, nicht den API-Key.

Die vollständigen Felder und Echtzeit-Enumerationen richten sich nach der Seite [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Für die Bildgenerierung aus reinem Text siehe [GPT Image 2 / 2.5 Bildgenerierung](https://platform.acedata.cloud/documents/openai-images-generations).
