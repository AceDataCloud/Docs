OpenAI-Wortvektordienst, der zum Generieren von Wortvektorergebnissen verwendet wird, welche den eingegebenen Text darstellen.

Dieses Dokument stellt hauptsächlich den Nutzungsprozess der OpenAI Embeddings API vor. Mit ihr können wir Einbettungsvektoren erstellen, die den eingegebenen Text darstellen。。

## Beantragungsprozess

Um die OpenAI Embeddings API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten, und bewahren Sie ihn zur späteren Verwendung auf.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, auf der Sie zur Registrierung und Anmeldung eingeladen werden. Nach Abschluss kehren Sie automatisch zu dieser Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen; es ist nicht erforderlich, für jeden Dienst einzeln einen Antrag zu stellen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Guthaben, das Sie zum kostenlosen Ausprobieren verwenden können; bei unzureichendem Guthaben können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [OpenAI Embeddings API →](https://platform.acedata.cloud/documents/openai-embeddings)

## Grundlegende Verwendung

Als Nächstes können Sie die entsprechenden Inhalte in der Benutzeroberfläche ausfüllen, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/4qtbvr.png" width="500" className="m-auto" /></p>

Bei der ersten Verwendung dieser Schnittstelle müssen wir mindestens drei Inhalte ausfüllen. Einer davon ist `authorization`, den Sie direkt in der Auswahlliste auswählen können. Ein weiterer Parameter ist `model`; `model` ist die Modellkategorie der offiziellen OpenAI-Website, die wir zur Verwendung auswählen. Die derzeit verfügbaren Modelle sind `text-embedding-3-small` und `text-embedding-3-large`. `text-embedding-ada-002` wird nicht mehr angeboten; wenn bestehende Vektorindizes dieses alte Modell verwenden, können die Vektoren neuer Modelle nicht direkt gemischt verwendet werden, und der Index muss neu erstellt werden. Der letzte Parameter ist `input`; `input` ist der Text, dessen Wortvektoren wir umwandeln müssen.

Gleichzeitig können Sie beachten, dass auf der rechten Seite entsprechender generierter Aufrufcode vorhanden ist. Sie können den Code kopieren und direkt ausführen oder direkt auf die Schaltfläche „Try“ klicken, um ihn zu testen.

Optionale Parameter:

- `dimensions`: Schneidet die Vektordimension zu, standardmäßig wird die vollständige Dimension ausgegeben.
- `encoding_format`: Rückgabeformat, wahlweise `float` oder `base64`.

<p><img src="https://cdn.acedata.cloud/gqulm9.png" width="500" className="m-auto" /></p>

Python-Beispielaufrufcode:

```python
import requests

url = "https://api.acedata.cloud/openai/embeddings"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "input": "The food was delicious and the waiter...",
    "model": "text-embedding-3-small",
    "encoding_format": "float"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Das Rückgabeergebnis enthält mehrere Felder, die wie folgt beschrieben werden:

- `model`, das Modell, das bei dieser Umwandlung von Text in Wortvektoren verwendet wurde.
- `usage`, die Token-Informationen, die bei dieser Umwandlung von Text in Wortvektoren verwendet wurden.
- `data`, das Ergebnis der Wortvektoren nach der Textumwandlung.

Dabei enthält `data` die spezifischen Informationen zu den Wortvektoren, die dem Text entsprechen, und das darin enthaltene `embedding` ist das konkrete Ergebnis der generierten Wortvektoren.

## Fehlerbehandlung

Wenn bei der Aufrufung der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Information zurück. Zum Beispiel:

- `400 token_mismatched`: Bad request, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Bad request, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiger oder fehlender Autorisierungs-Token.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel einer Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
