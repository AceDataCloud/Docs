OpenAI hat kürzlich eine Schnittstelle zur Erstellung von Modellantworten bereitgestellt. Stellen Sie Text- oder Bildeingaben bereit, um Text- oder Bildausgaben zu generieren. Lassen Sie das Modell Ihren eigenen benutzerdefinierten Code aufrufen oder integrierte Tools wie Websuche oder Dateisuche verwenden, um Ihre eigenen Daten als Eingabe für Modellantworten zu nutzen.

Dieses Dokument stellt hauptsächlich den Nutzungsprozess der OpenAI Responses API vor. Mit ihr können wir die offizielle Funktion von OpenAI zur Erstellung von Modellantworten einfach verwenden.

## GPT-6.1 Sol

Verwenden Sie `model: "gpt-6.1-sol"`, um dieses Modell auszuwählen. Es unterstützt Streaming-Ausgabe, Funktionsaufrufe, strukturierte Ausgabe und Bildeingaben. In der ersten Woche nach der Veröffentlichung ist es nur für verifizierte ACE-T1+-Inhaber (mindestens 100.000 ACE) oder autorisierte Benutzer verfügbar; die konkrete Verfügbarkeitszeit richtet sich nach dem Zugriffshinweis in der Konsole.

Die Reasoning-Stufen unterstützen `low`, `medium`, `high`, `xhigh` und `max`; `none` oder `minimal` werden vorerst nicht unterstützt. Es wird empfohlen, mit `reasoning: {"effort": "low"}` zu beginnen. Wenn die Eingabe 272.000 Tokens überschreitet, gilt für die gesamte Anfrage der Preis für langen Kontext; die Gebühren richten sich nach dem aktuellen Preis in der Konsole.

## Beantragungsprozess

Um die OpenAI Responses API zu verwenden, gehen Sie zunächst zur [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications), um Ihren API-Token zu erhalten, und bewahren Sie ihn als Reserve auf.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, wo Sie zur Registrierung und Anmeldung eingeladen werden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass Sie jeden Dienst einzeln beantragen müssen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, das Sie kostenlos testen können; bei unzureichendem Kontingent können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Grundlegende Verwendung

Als Nächstes können Sie die entsprechenden Inhalte in der Benutzeroberfläche ausfüllen, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Bei der ersten Verwendung dieser Schnittstelle müssen wir mindestens drei Inhalte ausfüllen. Einer davon ist `authorization`, das Sie direkt in der Dropdown-Liste auswählen können. Ein weiterer Parameter ist `model`; `model` ist die Modellkategorie der offiziellen OpenAI-ChatGPT-Website, die wir auswählen. Hier haben wir hauptsächlich 20 Modelle, Details finden Sie in den von uns bereitgestellten Modellen. Der letzte Parameter ist `input`; `input` ist das Array der von uns eingegebenen Prompt-Wörter. Es ist ein Array und bedeutet, dass mehrere Prompt-Wörter gleichzeitig hochgeladen werden können. Jedes Prompt-Wort enthält `role` und `content`, wobei `role` die Rolle des Fragestellers darstellt. Wir bieten drei Identitäten an, nämlich `user`, `assistant` und `system`. Das andere Feld `content` ist der konkrete Inhalt unserer Frage.

Gleichzeitig können Sie beachten, dass auf der rechten Seite entsprechender Aufrufcode generiert wird. Sie können den Code kopieren und direkt ausführen oder direkt auf die Schaltfläche „Try“ klicken, um ihn zu testen.

Häufig verwendete optionale Parameter:

- `max_tokens`: Begrenzt die maximale Anzahl von Tokens für eine einzelne Antwort.
- `temperature`: Zufälligkeit der Generierung, zwischen 0 und 2; je größer der Wert, desto stärker die Streuung.
- `n`: Wie viele Kandidatenantworten auf einmal generiert werden.
- `response_format`: Einstellung des Rückgabeformats.
- `tools`: Definition von Funktions-/Tool-Aufrufen.
- `background`: Ob die Ausführung asynchron im Hintergrund erfolgt.

## Streaming-Antwort

Diese Schnittstelle unterstützt auch Streaming-Antworten, was für die Anbindung von Webseiten sehr nützlich ist und Webseiten einen Effekt der zeichenweisen Anzeige ermöglichen kann.

Wenn Sie Antworten als Stream zurückgeben möchten, können Sie den Parameter `stream ` im Request-Header ändern und auf `true` setzen.

Die Änderung ist in der Abbildung gezeigt, allerdings muss der Aufrufcode entsprechend geändert werden, um Streaming-Antworten zu unterstützen.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Nachdem Sie `stream` auf `true` geändert haben, gibt die API die entsprechenden JSON-Daten zeilenweise zurück. Auf Codeebene müssen wir entsprechende Änderungen vornehmen, um die zeilenweisen Ergebnisse zu erhalten.

Python-Beispielaufrufcode:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Wenn der Client die Verbindung trennt, bevor der Endstatus eintrifft, wird diese Anfrage als vom Client geschlossen (499) aufgezeichnet, und es erfolgt keine Abrechnung anhand lokal geschätzter Token; wenn die Verbindung normal beendet wird, aber kein Endstatus und kein endgültiges `usage` empfangen werden, wird diese Anfrage als unvollständige Antwort (502) aufgezeichnet, und es erfolgt ebenfalls keine Abrechnung anhand geschätzter Token. - `item_id`, die ID der generierten Dialogaufgabe, die zur eindeutigen Identifizierung dieser Dialogaufgabe verwendet wird.
- `type`, der Typ der generierten Responses-Aufgabe dieses Dialogs.
- `model `, das ausgewählte Modell von der offiziellen OpenAI-ChatGPT-Website.
- `delta`, die Antwortinformationen, die ChatGPT auf die Frage gibt.

JavaScript wird ebenfalls unterstützt, beispielsweise lautet der Code für Streaming-Aufrufe in Node.js wie folgt:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

```java
JSONObject jsonObject = new JSONObject();

## Visuelles Modell

gpt-4o ist ein von OpenAI entwickeltes multimodales großes Sprachmodell, das auf der Grundlage von GPT-4 um visuelle Verständnisfähigkeiten erweitert wurde. Dieses Modell kann gleichzeitig Text- und Bildeingaben verarbeiten und ermöglicht modalitätsübergreifendes Verstehen und Generieren.
Die Textverarbeitung mit dem Modell gpt-4o entspricht den grundlegenden Nutzungsinhalten im oberen Abschnitt. Im Folgenden wird kurz erläutert, wie die Bildverarbeitungsfähigkeit des Modells genutzt wird.

Die Bildverarbeitungsfähigkeit des Modells gpt-4o wird hauptsächlich genutzt, indem auf Grundlage des ursprünglichen `content`-Inhalts ein Feld `type` hinzugefügt wird. Über dieses Feld kann erkannt werden, ob Text oder ein Bild hochgeladen wurde, sodass die Bildverarbeitungsfähigkeit des Modells gpt-4o verwendet werden kann. Im Folgenden wird hauptsächlich beschrieben, wie diese Funktion auf zwei Arten über Curl und Python aufgerufen wird.

- Curl-Skript-Methode

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

## Fehlerbehandlung

Beim Aufrufen der API gibt die API bei einem Fehler den entsprechenden Fehlercode und die entsprechenden Informationen zurück. Zum Beispiel:

- `400 token_mismatched`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`：Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`：Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`：Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort

```
