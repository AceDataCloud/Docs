OpenAI bietet kürzlich eine Schnittstelle zum Erstellen von Modellantworten an. Stellen Sie Text- oder Bildeingaben bereit, um Text- oder Bildausgaben zu erzeugen. Lassen Sie das Modell Ihren eigenen benutzerdefinierten Code aufrufen oder integrierte Tools wie Websuche oder Dateisuche verwenden, um Ihre eigenen Daten als Eingabe für Modellantworten zu nutzen.

Dieses Dokument stellt hauptsächlich den Nutzungsprozess der OpenAI Responses API vor. Mit ihr können wir die offizielle Funktion von OpenAI zum Erstellen von Modellantworten einfach nutzen.

## Beantragungsprozess

Um die OpenAI Responses API zu verwenden, rufen Sie zuerst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihr API-Token zu erhalten, und bewahren Sie es als Reserve auf.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Bei der ersten Beantragung wird ein kostenloses Guthaben verschenkt, das kostenlos ausprobiert werden kann; bei unzureichendem Guthaben kann ein allgemeines Guthaben in der [Konsole](https://platform.acedata.cloud/console/coin) aufgeladen werden.

> 📘 Vollständige Dokumentation: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Grundlegende Nutzung

Anschließend können Sie die entsprechenden Inhalte in der Oberfläche ausfüllen, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Bei der ersten Verwendung dieser Schnittstelle müssen wir mindestens drei Inhalte ausfüllen. Einer davon ist `authorization`, der direkt in der Dropdown-Liste ausgewählt werden kann. Der andere Parameter ist `model`, `model` ist die Modellkategorie der offiziellen OpenAI-ChatGPT-Website, die wir zur Nutzung auswählen. Hier haben wir hauptsächlich 20 Modelle, Details können Sie in den von uns bereitgestellten Modellen sehen. Der letzte Parameter ist `input`, `input` ist das Array der von uns eingegebenen Fragewörter. Es ist ein Array und bedeutet, dass mehrere Fragewörter gleichzeitig hochgeladen werden können. Jedes Fragewort enthält `role` und `content`, wobei `role` die Rolle des Fragestellers darstellt. Wir bieten drei Identitäten an, nämlich `user`, `assistant`, `system`. Das andere `content` ist der konkrete Inhalt unserer Frage.

Gleichzeitig können Sie feststellen, dass rechts entsprechender Aufrufcode generiert wird. Sie können den Code kopieren und direkt ausführen oder direkt auf die Schaltfläche „Try“ klicken, um ihn zu testen.

Häufig verwendete optionale Parameter:

- `max_tokens`: Begrenzt die maximale Anzahl von Tokens einer einzelnen Antwort.
- `temperature`: Zufälligkeit der Generierung, zwischen 0 und 2, je größer der Wert, desto stärker die Streuung.
- `n`: Wie viele Kandidatenantworten auf einmal generiert werden.
- `response_format`: Einstellung des Rückgabeformats.
- `tools`: Definition von Funktions-/Tool-Aufrufen.
- `background`: Ob die Ausführung asynchron im Hintergrund erfolgt.

## Streaming-Antwort

Diese Schnittstelle unterstützt auch Streaming-Antworten, was für die Anbindung von Webseiten sehr nützlich ist und Webseiten einen Effekt der zeichenweisen Anzeige ermöglichen kann.

Wenn Sie Antworten als Stream zurückgeben möchten, können Sie den Parameter `stream ` im Request-Header ändern und auf `true` setzen.

Die Änderung ist wie in der Abbildung gezeigt, allerdings muss der Aufrufcode entsprechend geändert werden, um Streaming-Antworten zu unterstützen.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Nachdem `stream` auf `true` geändert wurde, gibt die API die entsprechenden JSON-Daten zeilenweise zurück. Auf Codeebene müssen wir entsprechende Änderungen vornehmen, um die zeilenweisen Ergebnisse zu erhalten.

Python-Beispielaufrufcode:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Sie können sehen, dass die Antwort viele `data` enthält, und das `delta` innerhalb von `data` ist der neueste Antwortinhalt, was mit dem zuvor vorgestellten Inhalt übereinstimmt. `delta` ist der neu hinzugefügte Antwortinhalt, und Sie können ihn anhand des Ergebnisses in Ihr System integrieren. Die Streaming-Antwort verwendet `response.completed` oder `response.incomplete` als Endzustand; `usage` im Endzustand ist der endgültige Token-Verbrauch dieser Anfrage und auch die Grundlage für die Abrechnung.

Wenn der Client die Verbindung trennt, bevor der Endzustand erreicht wird, wird diese Anfrage als vom Client geschlossen (499) protokolliert, und es wird keine lokale geschätzte Token-Abrechnung verwendet; wenn die Verbindung normal endet, aber der Endzustand und die endgültige `usage` nicht empfangen wurden, wird diese Anfrage als unvollständige Antwort (502) protokolliert, und ebenfalls wird keine geschätzte Token-Abrechnung verwendet. Wenn diese beiden Situationen auftreten, starten Sie die Anfrage bitte erneut.

Das zurückgegebene `data`-Ergebnis enthält mehrere Felder, die wie folgt vorgestellt werden:

- `item_id`, die ID der für diese Konversationsaufgabe erzeugten Aufgabe, die zur eindeutigen Identifizierung dieser Konversationsaufgabe verwendet wird.
- `type`, der Typ der für diese Konversation erzeugten Responses-Aufgabe.
- `model `, das ausgewählte Modell auf der offiziellen OpenAI-ChatGPT-Website.
- `delta`, die Antwortinformationen, die ChatGPT für die Frage bereitstellt.

JavaScript wird ebenfalls unterstützt, zum Beispiel lautet der Code für den Streaming-Aufruf in Node.js wie folgt:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

Java-Beispielcode:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "gpt-4.1");
jsonObject.put("input", [{"role":"user","content":"Hello"}]);
jsonObject.put("stream", true);
MediaType mediaType = "application/json; charset=utf-8".toMediaType();
RequestBody body = jsonObject.toString().toRequestBody(mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/openai/responses")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer b82d32f570bc434d9ba9923aa0e7dce0")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.print(response.body!!.string())
```

Andere Sprachen können zudem eigenständig angepasst werden, das Prinzip ist dasselbe.

## Visuelles Modell

gpt-4o ist ein von OpenAI entwickeltes multimodales großes Sprachmodell, das auf der Grundlage von GPT-4 um visuelle Verständnisfähigkeiten erweitert wurde. Dieses Modell kann gleichzeitig Text- und Bildeingaben verarbeiten und ermöglicht modalitätsübergreifendes Verstehen und Generieren.
Die Textverarbeitung mit dem Modell gpt-4o entspricht den grundlegenden Nutzungsinhalten im vorherigen Abschnitt. Im Folgenden wird kurz vorgestellt, wie die Bildverarbeitungsfähigkeit des Modells verwendet wird.

Die Bildverarbeitungsfähigkeit des Modells gpt-4o wird hauptsächlich verwendet, indem auf Basis des ursprünglichen `content`-Inhalts ein `type`-Feld hinzugefügt wird. Durch dieses Feld kann erkannt werden, ob Text oder ein Bild hochgeladen wurde, wodurch die Bildverarbeitungsfähigkeit des Modells gpt-4o verwendet wird. Im Folgenden wird hauptsächlich beschrieben, wie diese Funktion auf zwei Arten, mit Curl und Python, aufgerufen wird.

- Curl-Skriptmethode

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Python-Skriptmethode

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }

```

## Fehlerbehandlung

Wenn beim Aufrufen der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechenden Informationen zurück. Zum Beispiel:

- `400 token_mismatched`: Bad Request, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Bad Request, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel einer Fehlerantwort

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
