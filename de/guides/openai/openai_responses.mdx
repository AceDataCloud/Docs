Die von der Plattform akzeptierten kompatiblen Modellanfragen werden nach dem Eingabe-, Ausgabe- und Cache-Verbrauch des Modells abgerechnet. Die Gesamteingabemenge von Responses umfasst die gemeldeten Cache-Token, und der Cache-Anteil wird zum entsprechenden Cache-Preis abgerechnet; ein Wechsel des Schnittstellenformats führt nicht zu einer Abrechnung nach festen Aufrufzahlen. Die Kosten richten sich nach den aktuellen Modellpreisen in der Konsole und nach `usage.cost` in der Antwort.

OpenAI hat kürzlich eine Schnittstelle zum Erstellen von Modellantworten bereitgestellt. Stellen Sie Text- oder Bildeingaben bereit, um Text- oder Bildausgaben zu generieren. Lassen Sie das Modell Ihren eigenen benutzerdefinierten Code aufrufen oder integrierte Tools wie die Websuche oder Dateisuche verwenden, um Ihre eigenen Daten als Eingabe für Modellantworten zu nutzen.

Dieses Dokument stellt hauptsächlich den Nutzungsablauf der OpenAI Responses API vor. Mit ihr können wir die offizielle Funktion von OpenAI zum Erstellen von Modellantworten problemlos nutzen.

## GPT-6.1 Terra

Verwenden Sie `model: "gpt-6.1-terra"`, um dieses Modell auszuwählen. Text- und Bildeingaben, Streaming-Ausgaben, Funktionstools und strukturierte Ausgaben werden unterstützt. Die Reasoning-Stufen unterstützen `low`, `medium`, `high`, `xhigh` und `max`; es wird empfohlen, mit `reasoning: {"effort": "low"}` zu beginnen; `none` oder `minimal` werden nicht unterstützt. Bei Eingaben über 272.000 Tokens gelten Langkontextpreise; die tatsächlichen Kosten richten sich nach den aktuellen Preisen in der Konsole und der Nutzung in der Antwort.

## GPT-6.1 Sol

Verwenden Sie `model: "gpt-6.1-sol"`, um dieses Modell auszuwählen. Streaming-Ausgaben, Funktionsaufrufe, strukturierte Ausgaben und Bildeingaben werden unterstützt. Innerhalb der ersten Woche nach der Einführung ist es nur für verifizierte ACE-T1+-Inhaber (mindestens 100.000 ACE) oder autorisierte Nutzer verfügbar; der konkrete Freigabezeitpunkt richtet sich nach dem Zugangshinweis in der Konsole.

Die Reasoning-Stufen unterstützen `low`, `medium`, `high`, `xhigh` und `max`; `none` oder `minimal` werden vorerst nicht unterstützt. Es wird empfohlen, mit `reasoning: {"effort": "low"}` zu beginnen. Bei Eingaben über 272.000 Tokens gelten Langkontextpreise für die gesamte Anfrage; die Kosten richten sich nach den aktuellen Preisen in der Konsole.

## Beantragungsprozess

Um die OpenAI Responses API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten und ihn als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen; Sie müssen ihn nicht für jeden Dienst einzeln beantragen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Guthaben, mit dem Sie den Dienst kostenlos ausprobieren können; bei unzureichendem Guthaben können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) das allgemeine Guthaben aufladen.

> 📘 Vollständige Dokumentation: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Grundlegende Verwendung

Anschließend können Sie die entsprechenden Inhalte in der Oberfläche ausfüllen, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Bei der ersten Verwendung dieser Schnittstelle müssen wir mindestens drei Inhalte ausfüllen. Einer davon ist `authorization`, das direkt in der Dropdown-Liste ausgewählt werden kann. Ein weiterer Parameter ist `model`; `model` bezeichnet die Modellkategorie der offiziellen OpenAI-ChatGPT-Website, die wir auswählen. Hier haben wir hauptsächlich 20 Modelle, Einzelheiten finden Sie bei den von uns bereitgestellten Modellen. Der letzte Parameter ist `input`; `input` ist das Array der von uns eingegebenen Prompt-Wörter. Es ist ein Array und bedeutet, dass mehrere Prompt-Wörter gleichzeitig hochgeladen werden können. Jedes Prompt-Wort enthält `role` und `content`, wobei `role` die Rolle des Fragestellers darstellt. Wir bieten drei Identitäten an, nämlich `user`, `assistant` und `system`. Das andere Element, `content`, ist der konkrete Inhalt unserer Frage.

Gleichzeitig können Sie feststellen, dass auf der rechten Seite entsprechender Aufrufcode generiert wird. Sie können den Code kopieren und direkt ausführen oder direkt auf die Schaltfläche „Try“ klicken, um ihn zu testen.

Häufig verwendete optionale Parameter:

- `max_tokens`: Begrenzt die maximale Anzahl von Tokens für eine einzelne Antwort.
- `temperature`: Zufälligkeit der Generierung, zwischen 0 und 2; je größer der Wert, desto stärker die Streuung.
- `n`: Wie viele Kandidatenantworten auf einmal generiert werden.
- `response_format`: Einstellung des Rückgabeformats.
- `tools`: Definition von Funktions-/Tool-Aufrufen.
- `background`: Ob die Ausführung asynchron im Hintergrund erfolgt.

## Streaming-Antwort

Diese Schnittstelle unterstützt auch Streaming-Antworten, was für die Webanbindung sehr nützlich ist und es Webseiten ermöglicht, einen Effekt der zeichenweisen Anzeige zu erzielen.

Wenn Sie die Antwort als Stream zurückgeben möchten, können Sie den Parameter `stream ` im Request-Header auf `true` ändern.

Die Änderung ist wie in der Abbildung gezeigt, allerdings muss der Aufrufcode entsprechend geändert werden, damit Streaming-Antworten unterstützt werden.
<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Nachdem `stream` zu `true` geändert wurde, gibt die API die entsprechenden JSON-Daten zeilenweise zurück. Auf Codeebene müssen wir entsprechende Änderungen vornehmen, um die zeilenweisen Ergebnisse zu erhalten.

Python-Beispielaufrufcode:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

- `item_id`, die ID der generierten Aufgabe für diesen Dialog, die zur eindeutigen Kennzeichnung dieser Dialogaufgabe verwendet wird.
- `type`, der Typ der generierten Responses-Aufgabe für diesen Dialog.
- `model `, das ausgewählte Modell der offiziellen OpenAI-ChatGPT-Website.
- `delta`, die Antwortinformationen, die ChatGPT auf die Frage gibt.

JavaScript wird ebenfalls unterstützt, beispielsweise lautet der Code für den Streaming-Aufruf in Node.js wie folgt:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer YOUR_API_TOKEN",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

Java-Beispielcode:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "gpt-4.1");
jsonObject.put("input", [{"role":"user","content":"Hello"}]);
jsonObject.put("stream", true);
MediaType mediaType = "application/json; charset=utf-8".toMediaType();
RequestBody body = jsonObject.toString().toRequestBody(mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/openai/responses")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer YOUR_API_TOKEN")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.print(response.body!!.string())
```

Andere Sprachen können zusätzlich selbst angepasst werden, das Prinzip ist überall gleich.

## Visuelles Modell

gpt-4o ist ein von OpenAI entwickeltes multimodales großes Sprachmodell, das auf Grundlage von GPT-4 über zusätzliche Fähigkeiten zum visuellen Verständnis verfügt. Dieses Modell kann gleichzeitig Text- und Bildeingaben verarbeiten und ermöglicht modalitätsübergreifendes Verstehen und Generieren.

Die Textverarbeitung mit dem Modell gpt-4o entspricht der im obigen Abschnitt beschriebenen grundlegenden Verwendung. Im Folgenden wird kurz erläutert, wie die Bildverarbeitungsfähigkeiten des Modells verwendet werden.

Die Bildverarbeitungsfähigkeit des gpt-4o-Modells wird hauptsächlich genutzt, indem auf Grundlage des ursprünglichen `content`-Inhalts ein Feld `type` hinzugefügt wird. Über dieses Feld lässt sich erkennen, ob Text oder ein Bild hochgeladen wurde, wodurch die Bildverarbeitungsfähigkeit des gpt-4o-Modells genutzt werden kann. Im Folgenden wird hauptsächlich beschrieben, wie diese Funktion mit Curl und Python auf zwei Arten aufgerufen wird.

- Curl-Skriptmethode

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Python-Skriptmethode

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Fehlerbehandlung

Wenn beim Aufrufen der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Information zurück. Zum Beispiel:

- `400 token_mismatched`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`：Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`：Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`：Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`：Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
