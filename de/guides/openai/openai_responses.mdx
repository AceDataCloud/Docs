OpenAI hat kürzlich eine Schnittstelle zum Erstellen von Modellantworten bereitgestellt. Stellen Sie Text- oder Bildeingaben bereit, um Text- oder Bildausgaben zu generieren. Lassen Sie das Modell Ihren eigenen benutzerdefinierten Code aufrufen oder integrierte Tools wie die Websuche oder Dateisuche verwenden, um Ihre eigenen Daten als Eingabe für Modellantworten zu nutzen.

Dieses Dokument stellt hauptsächlich den Nutzungsprozess der OpenAI Responses API vor. Damit können wir die offizielle OpenAI-Funktion zum Erstellen von Modellantworten einfach verwenden.

## Beantragungsprozess

Um die OpenAI Responses API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihr API-Token zu erhalten, und bewahren Sie es als Reserve auf.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass Sie jeden Dienst einzeln beantragen müssen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Guthaben, mit dem Sie es kostenlos testen können; bei unzureichendem Guthaben können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Grundlegende Nutzung

Anschließend können Sie die entsprechenden Inhalte in der Oberfläche ausfüllen, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Bei der ersten Nutzung dieser Schnittstelle müssen wir mindestens drei Inhalte ausfüllen. Einer davon ist `authorization`, das Sie direkt in der Dropdown-Liste auswählen können. Ein weiterer Parameter ist `model`; `model` ist die Modellkategorie der offiziellen OpenAI-ChatGPT-Website, die wir zur Nutzung auswählen. Hier haben wir hauptsächlich 20 Modelle, Details können Sie in den von uns bereitgestellten Modellen einsehen. Der letzte Parameter ist `input`; `input` ist das von uns eingegebene Array von Fragen, es ist ein Array und bedeutet, dass mehrere Fragen gleichzeitig hochgeladen werden können. Jede Frage enthält `role` und `content`, wobei `role` die Rolle des Fragestellers angibt. Wir bieten drei Identitäten an, nämlich `user`, `assistant` und `system`. Das andere Feld `content` ist der konkrete Inhalt unserer Frage.

Gleichzeitig können Sie beachten, dass rechts entsprechender generierter Aufrufcode vorhanden ist. Sie können den Code kopieren und direkt ausführen oder direkt auf die Schaltfläche „Try“ klicken, um ihn zu testen.

Häufig verwendete optionale Parameter:

- `max_tokens`: Begrenzt die maximale Anzahl von Tokens für eine einzelne Antwort.
- `temperature`: Generierungszufälligkeit, zwischen 0 und 2; je größer der Wert, desto stärker die Streuung.
- `n`: Wie viele Kandidatenantworten auf einmal generiert werden.
- `response_format`: Einstellung des Rückgabeformats.
- `tools`: Definition von Funktions-/Tool-Aufrufen.
- `background`: Ob die Ausführung asynchron im Hintergrund erfolgt.

## Streaming-Antwort

Diese Schnittstelle unterstützt auch Streaming-Antworten, was für die Webanbindung sehr nützlich ist und es Webseiten ermöglicht, einen Effekt der zeichenweisen Anzeige zu erzielen.

Wenn Sie Antworten als Stream zurückgeben möchten, können Sie den Parameter `stream ` im Request-Header ändern und auf `true` setzen.

Die Änderung ist wie in der Abbildung gezeigt, allerdings muss der Aufrufcode entsprechend geändert werden, um Streaming-Antworten zu unterstützen.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Nachdem `stream` auf `true` geändert wurde, gibt die API die entsprechenden JSON-Daten zeilenweise zurück. Auf Codeebene müssen wir entsprechende Änderungen vornehmen, um die zeilenweisen Ergebnisse zu erhalten.

Python-Beispielaufrufcode:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Die Streaming-Antwort verwendet `response.completed` oder `response.incomplete` als Endzustand; `usage` im Endzustand ist der endgültige Token-Verbrauch dieser Anfrage und zugleich die Grundlage für die Abrechnung.

Wenn der Client die Verbindung trennt, bevor der Endzustand erreicht wird, wird diese Anfrage als vom Client geschlossen (499) protokolliert, und es wird keine Abrechnung mit lokal geschätzten Tokens vorgenommen; wenn die Verbindung normal beendet wird, aber kein Endzustand und keine endgültige `usage` empfangen werden, wird diese Anfrage als unvollständige Antwort (502) protokolliert, und es wird ebenfalls keine Abrechnung mit geschätzten Tokens vorgenommen. Wenn eine dieser beiden Situationen eintritt, starten Sie die Anfrage bitte erneut.

Das zurückgegebene `data`-Ergebnis hat insgesamt mehrere Felder, die wie folgt beschrieben werden:

- `item_id`, die ID der generierten Dialogaufgabe, die zur eindeutigen Identifizierung dieser Dialogaufgabe verwendet wird.
- `type`, der Typ der generierten Responses-Aufgabe dieses Dialogs.
- `model `, das ausgewählte Modell der offiziellen OpenAI-ChatGPT-Website.
- `delta`, die Antwortinformationen, die ChatGPT auf die Frage gibt.

JavaScript wird ebenfalls unterstützt, zum Beispiel lautet der Code für einen Streaming-Aufruf in Node.js wie folgt:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

Java-Beispielcode:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "gpt-4.1");

OkHttpClient client = new OkHttpClient();

System.out.print(response.body!!.string())
```

## Visuelles Modell

gpt-4o ist ein von OpenAI entwickeltes multimodales großes Sprachmodell, das auf Grundlage von GPT-4 um visuelle Verständnisfähigkeiten erweitert wurde. Dieses Modell kann gleichzeitig Text- und Bildeingaben verarbeiten und ermöglicht ein multimodales Verständnis und eine multimodale Generierung.
Die Textverarbeitung mit dem Modell gpt-4o entspricht den grundlegenden Nutzungsinhalten oben. Im Folgenden wird kurz vorgestellt, wie die Bildverarbeitungsfähigkeit des Modells genutzt wird.

Die Bildverarbeitungsfähigkeit des Modells gpt-4o wird hauptsächlich genutzt, indem auf Grundlage des ursprünglichen `content`-Inhalts ein Feld `type` hinzugefügt wird. Über dieses Feld kann erkannt werden, ob Text oder ein Bild hochgeladen wurde, sodass die Bildverarbeitungsfähigkeit des Modells gpt-4o genutzt werden kann. Im Folgenden wird hauptsächlich erläutert, wie diese Funktion auf zwei Arten, nämlich mit Curl und Python, aufgerufen wird.

- Curl-Skriptmethode

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Python-Skriptmethode

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

    "model": "gpt-4.1",
    "input": [
      {

            "type": "input_image",

```

## Fehlerbehandlung

Wenn beim Aufruf der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und Informationen zurück. Zum Beispiel:

- `400 token_mismatched`: Bad request, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Bad request, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
