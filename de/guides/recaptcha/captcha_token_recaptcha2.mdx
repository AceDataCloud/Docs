Dieser Artikel beschreibt eine Integrationsanleitung für die Recaptcha2 Protokoll Erkennungs-API, die es Benutzern ermöglicht, die Recaptcha2 Verifizierungscode-Bilder nicht zu erkennen und auszuwählen, sondern lediglich durch die Einreichung des Website-Schlüssels eine automatische Dekodierung im Hintergrund zu erreichen und die Verifizierung abzuschließen.

## Antragsprozess

Um die Recaptcha2 Protokoll Erkennungs-API zu verwenden, müssen Sie zunächst im [Ace Data Cloud Dashboard](https://platform.acedata.cloud/console/applications) Ihr API-Token abrufen und für zukünftige Verwendung aufbewahren.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Wenn Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, die Sie zur Registrierung und Anmeldung einlädt. Nach Abschluss werden Sie automatisch zur aktuellen Seite zurückgeleitet.

**Ein API-Token reicht aus, um alle Dienste der Plattform zu nutzen, es ist nicht erforderlich, für jeden Dienst separat zu beantragen.** Bei der ersten Beantragung erhalten Sie ein kostenloses Kontingent, um es kostenlos auszuprobieren; wenn das Kontingent nicht ausreicht, können Sie im [Dashboard](https://platform.acedata.cloud/console/coin) Ihr allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Recaptcha2 Protokoll Erkennungs-API →](https://platform.acedata.cloud/documents/captcha-token-recaptcha2)

## Grundlegende Nutzung

Zunächst sollten Sie die grundlegende Nutzung verstehen, indem Sie die URL der Website eingeben, die den zu verarbeitenden Verifizierungscode enthält, um das verarbeitete Ergebnis zu erhalten. Zuerst müssen Sie einfach ein `website_url`-Feld übermitteln. Unsere Beispiel-Website ist: `https://www.google.com/recaptcha/api2/demo`, wir müssen auf der `website_url`-Seite den `website_key` abrufen. Zuerst öffnen Sie diese Webseite, drücken F12, um die Konsole zu öffnen, und suchen dann im Element-Bereich global nach `recaptcha-demo`, um das folgende Ergebnis zu erhalten:

<p><img src="https://cdn.acedata.cloud/hvx41c.png" width="500" className="m-auto" /></p>

Die `data-sitekey`-entsprechende Zeichenfolge ist der Wert des `website_key`. Hier sind die spezifischen Parameterergebnisse:

<p><img src="https://cdn.acedata.cloud/8oowyw.png" width="500" className="m-auto" /></p>

Hier haben wir die Request-Header festgelegt, einschließlich:

- `accept`: In welchem Format Sie die Antwort erhalten möchten, hier eingetragen als `application/json`, also im JSON-Format.
- `authorization`: Der Schlüssel zur API-Nutzung, den Sie nach der Beantragung direkt auswählen können.

Außerdem haben wir den Request-Body festgelegt, einschließlich:

- `website_url`: Die URL der Website, die den Verifizierungscode verarbeitet.
- `website_key`: Der Website-Schlüssel-Identifikator in Recaptcha2.
- `proxy`: Optional, bringen Sie Ihren eigenen Proxy mit (Bring Your Own Proxy). Nach der Einstellung wird der Upstream über die von Ihnen bereitgestellte Proxy-IP zur Dekodierung des Verifizierungscodes verwendet, um die Qualität der Ausgangs-IP zu steuern (z. B. um zu vermeiden, dass öffentliche Proxy-IPs von der Zielseite blockiert werden und `410 Gone` zurückgegeben wird). Das Format ist `scheme://[user:pass@]host:port`, wobei `scheme` `http`/`https`/`socks4`/`socks5` unterstützt, z. B. `http://user:pass@1.2.3.4:8080`. Wenn nicht ausgefüllt, wird der Standardproxy der Plattform verwendet.

Die Rückgabe enthält mehrere Felder, die wie folgt beschrieben werden:

- `token`, das Ergebnis der Verarbeitung der Recaptcha2-Verifizierung.
- `started_at`, `finished_at`: Die Zeit, zu der diese Anfrage verarbeitet und das Ergebnis erzeugt wurde (ISO-8601 UTC).
- `elapsed`: Die gesamte Verarbeitungszeit (in Sekunden).

Wir können sehen, dass wir das Ergebnis der Verarbeitung der Recaptcha2-Verifizierung erhalten haben, das wir dann für POST oder zur Simulation der Einreichung an die Zielwebsite verwenden können, einmalig gültig für 120 Sekunden, empfohlen innerhalb von 60 Sekunden zu verwenden. Im Folgenden wird ein Python-Skript bereitgestellt, um das verarbeitete Token an die Zielwebsite zu übermitteln, um die Recaptcha2-Verifizierung zu bestehen.

Zuerst müssen wir herausfinden, wie die Website POST-Anfragen sendet, damit wir das generierte Token einfügen können. Wir müssen zunächst die F12-Konsole öffnen und dann manuell eine Überprüfung durchführen. Schließlich können wir sehen, dass die Website eine POST-Anfrage gesendet hat. Wir müssen nur die Struktur dieser POST-Anfrage überprüfen. Der genaue Prozess ist wie folgt:

- Zuerst manuell die Überprüfung durchführen, wie im folgenden Bild gezeigt:

<p><img src="https://cdn.acedata.cloud/gwiflr.png" width="500" className="m-auto" /></p>

- Dann auf "submit" klicken und die Änderungen im Netzwerk der Konsole beobachten, wie im folgenden Bild gezeigt:
<p><img src="https://cdn.acedata.cloud/6hm5kj.png" width="500" className="m-auto" /></p>

- Analysieren Sie die Konstruktion der POST-Anfrage dieser Einreichung, schließlich können Sie mit der rechten Maustaste auf diese Anfrage klicken und den CURL-Code kopieren, wie im folgenden Bild dargestellt:

<p><img src="https://cdn.acedata.cloud/m7y35w.png" width="500" className="m-auto" /></p>

Aus der obigen Analyse ergibt sich, dass die URL dieser POST-Anfrage lautet: `https://www.google.com/recaptcha/api2/demo`, wir müssen nur den Parameter `g-recaptcha-response` übermitteln, dann müssen wir nur das verarbeitete Token in die untenstehenden Daten einfügen, um das Token zur Validierung zu verwenden. Der spezifische CURL-Code lautet wie folgt:

```shell
curl 'https://www.google.com/recaptcha/api2/demo' \
  --data-raw 'g-recaptcha-response={token}’
```

Der entsprechende Python-Code zur Token-Validierung lautet wie folgt:

```python
import requests

token = '{token}'

data = {
    'g-recaptcha-response': token,
}

response = requests.post('https://www.google.com/recaptcha/api2/demo', data=data)

if response.status_code:
    print(response.text)

```

Dann führen wir den Code aus und beobachten, dass die Konsole ein solches Ergebnis zeigt:

<p><img src="https://cdn.acedata.cloud/ku22tk.png" width="500" className="m-auto" /></p>

Schließlich haben wir die Validierung des Recaptcha2-Captcha-Protokolls bestanden.

Wenn Sie außerdem den entsprechenden Integrationscode generieren möchten, können Sie ihn direkt kopieren, zum Beispiel ist der CURL-Code wie folgt:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo"
}'
```

Der Python-Integrationscode lautet wie folgt:

```python
import requests

url = "https://api.acedata.cloud/captcha/token/recaptcha2"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
    "website_url": "https://www.google.com/recaptcha/api2/demo"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynchroner Modus (async)

Standardmäßig ist die API synchron blockierend: Eine Anfrage wartet, bis die Tokenverarbeitung abgeschlossen ist, bevor sie zurückgegeben wird. Wenn Sie mehrere Solver-Rotationen durchführen und „nach der Einreichung der Aufgabe sofort die task_id erhalten möchten, um andere Solver zu planen und später das Ergebnis abzurufen“, können Sie `async: true` im Anfragekörper übergeben.

Nach der Übergabe von `async: true` gibt die Schnittstelle sofort eine `task_id` zurück, ohne zu blockieren:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

Verwenden Sie dann diese `task_id`, um `POST /captcha/tasks` abzufragen (empfohlen alle 3-5 Sekunden), um das Ergebnis zu erhalten:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Während der Verarbeitung wird `status: processing` zurückgegeben:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

Nach Abschluss der Verarbeitung wird `status: ready` und das Token zurückgegeben:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "token": "03AFcWeA5kjJyDQ9S1a9UYimR6nuxnpEnAs5x2Pixao0dXZhMB......"
}
```

Abrechnungsinformationen: Im asynchronen Modus werden die Erstellung von Aufgaben und die Abfrage „in Bearbeitung“ nicht berechnet; **es wird nur einmal berechnet, wenn das Ergebnis erfolgreich abgerufen wird** (zum gleichen Preis wie im synchronen Modus). Daher entstehen bei der Stornierung von noch nicht abgeschlossenen Aufgaben während der Rotation keine Kosten. `/captcha/tasks` ist für alle Captcha-Schnittstellen (Token- und Erkennungsserie) allgemein und kann mit derselben `task_id` abgefragt werden.

## Fehlerbehandlung

Wenn beim Aufruf der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die Informationen zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Unbefugt, ungültiger oder fehlender Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Kontingent überschritten.
- `500 api_error`: Interner Serverfehler, etwas ist auf dem Server schiefgelaufen.

### Beispiel für eine Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
