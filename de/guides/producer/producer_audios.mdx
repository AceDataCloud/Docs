Dieser Artikel stellt eine Anleitung zur Integration der Producer Audios Generation API vor, mit der durch Eingabe benutzerdefinierter Parameter offizielle Musik von Producer generiert werden kann.

## Antragsprozess

Um die Producer Audios Generation API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten und ihn als Reserve aufzubewahren.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Falls Sie noch nicht angemeldet oder registriert sind, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden. Nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Beim ersten Antrag erhalten Sie kostenlose Guthaben, die kostenlos getestet werden können; bei unzureichendem Guthaben können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Erforderliche Parameter nach Aktion auswählen

Bei `action=generate` und `custom=false` (Standard) geben Sie `prompt` an; bei `custom=true`
und `instrumental=false` geben Sie `lyric` an. Benutzerdefinierte Instrumentalmusik kann mit
`custom=true, instrumental=true` eingestellt werden, ohne fiktive Liedtexte oder zusätzliche Eingabeaufforderungen.
`action=extend` benötigt `audio_id` und ein `continue_at` größer als 0; im nicht-instrumentalen Modus wird außerdem
`lyric` benötigt. Cover, Varianten, Abschnittsersetzung, Stimmtausch und Audiospurtrennung benötigen alle die Quell-`audio_id`;
Liedtexte und Eingabeaufforderungen sollten nicht für alle Aktionen bedingungslos erforderlich sein.

In MCP wählen `producer_extend_music` und `producer_replace_section` den Modus für benutzerdefinierte Liedtexte, wenn `lyric`
angegeben wird; für die Fortsetzung von Instrumentalmusik kann `instrumental=true` übergeben und der Liedtext weggelassen werden.

## Grundlegende Verwendung

Wenn Sie an irgendeinen Song denken, können Sie beliebig einen Text eingeben. Wenn ich beispielsweise einen Song über Weihnachten generieren möchte, kann ich `a song for Christmas` eingeben, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Sie können sehen, dass wir hier die Request Headers festgelegt haben, einschließlich:

- `accept`: Welches Format der Antwort empfangen werden soll; hier wird `application/json`, also das JSON-Format, eingetragen.
- `authorization`: Der Schlüssel zum Aufrufen der API, der nach dem Antrag direkt über das Dropdown-Menü ausgewählt werden kann.

Darüber hinaus umfassen die Parameter des Request Body:

- `action`: Das Verhalten dieser Musikgenerierungsaufgabe; zum Generieren eines Songs ist es `generate`.
- `model`: Das zur Erstellung des Songs verwendete Modell; derzeit hauptsächlich: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: Der Liedtextinhalt des Songs.
- `custom`: Ob der Song auf benutzerdefinierte Weise generiert wird.
- `prompt`: Die Eingabeaufforderung im Inspirationsmodus.
- `title`: Die Titelinformationen des Songs.
- `audio_id`: Die ID des Referenzsongs, die für Aktionen wie Fortsetzung/Neuauflage verwendet wird.
- `continue_at`: Den Song ab der angegebenen Sekunde fortsetzen.
- `replace_section_start`/`replace_section_end`: Start- und Endzeit der zu ersetzenden Passage, in Sekunden.
- `lyrics_strength`: Liedtextstärke, die den Einfluss des Liedtexts auf die Audiogenerierung darstellt; optional zwischen 0 und 1, Standardwert 0.7.
- `sound_strength`: Stärke der Audio-Eingabeaufforderung, optional zwischen 0.2 und 1, Standardwert 0.7.
- `cover_strength`: Cover-Stärke zwischen 0.2 und 1, Standardwert 1.
- `weirdness`: Grad der stilistischen Eigenart, optional zwischen 0 und 1, Standardwert 0.5
- `callback_url`: Die URL, an die das Ergebnis zurückgemeldet werden soll.
- `async`: Optional; wenn auf `true` gesetzt, gibt die Schnittstelle sofort `task_id` zurück, ohne dass `callback_url` angegeben werden muss. Anschließend wird das Ergebnis über die entsprechende Schnittstelle zur Aufgabenabfrage per Polling abgerufen.
- `instrumental`: Ob es sich um einen Modus ohne Liedtext handelt.

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Lied covern

Wenn Sie ein bereits generiertes Lied covern möchten, können Sie das oben generierte Lied für das Cover verwenden. Als Nächstes müssen wir basierend auf Liedtext und Titel ein Lied benutzerdefiniert generieren.

Wenn Sie ein selbst hochgeladenes Lied weiter covern möchten, können Sie den Parameter `action` auf `upload_cover` setzen und die ID des selbst hochgeladenen Liedes eingeben, das weiter gecovert werden soll. Die Lied-ID erhalten Sie über die [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), wie in der folgenden Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Dann können die folgenden Inhalte festgelegt werden:

- action：Das Verhalten dieser Liedaufgabe unterstützt derzeit: generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation. Für dieses Cover wird der Parameter `cover` verwendet.
- lyric：Liedtext
- title：Der Titel des Liedes.
- custom：Ob die Generierung im benutzerdefinierten Modus erfolgt, standardmäßig ist false.
- audio_id：Die Lied-ID des zu covernden Liedes.

## Song fortsetzen

## Asynchroner Rückruf

Da die von der Producer Audios Generation API benötigte Generierungszeit manchmal relativ lang sein kann, bleibt die HTTP-Anfrage bei einer längeren Nichtreaktion der API fortlaufend verbunden, was zu zusätzlichem Verbrauch von Systemressourcen führt. Daher bietet diese API auch Unterstützung für asynchrone Rückrufe.

Der gesamte Ablauf ist: Wenn der Client eine Anfrage initiiert, gibt er zusätzlich ein Feld `callback_url` an. Nachdem der Client die API-Anfrage initiiert hat, gibt die API sofort ein Ergebnis zurück, das ein Feld `task_id` enthält, welches die aktuelle Aufgaben-ID darstellt. Nach Abschluss der Aufgabe wird das Ergebnis der Generierungsaufgabe in Form von POST JSON an die vom Client angegebene `callback_url` gesendet, wobei ebenfalls das Feld `task_id` enthalten ist, sodass die Aufgabenergebnisse über die ID zugeordnet werden können.

Im Folgenden erfahren wir anhand eines Beispiels, wie dies konkret funktioniert.

Zunächst ist der Webhook-Rückruf ein Dienst, der HTTP-Anfragen empfangen kann. Entwickler sollten ihn durch die URL eines selbst eingerichteten HTTP-Servers ersetzen. Zur einfacheren Demonstration wird hier eine öffentliche Webhook-Beispielwebsite [https://webhook.site/](https://webhook.site/) verwendet. Beim Öffnen dieser Website erhalten Sie eine Webhook-URL, wie in der Abbildung gezeigt:

![](https://cdn.acedata.cloud/tbcnai.png)

## Fehlerbehandlung

Wenn beim Aufrufen der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechenden Informationen zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel einer Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
