Dieser Artikel stellt eine Anleitung zur Integration der Producer Audios Generation API vor, mit der durch die Eingabe benutzerdefinierter Parameter offizielle Musik von Producer generiert werden kann.

## Antragsprozess

Um die Producer Audios Generation API zu verwenden, rufen Sie zunächst die [Ace Data Cloud-Konsole](https://platform.acedata.cloud/console/applications) auf, um Ihren API-Token zu erhalten, und bewahren Sie ihn als Reserve auf.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Wenn Sie sich noch nicht angemeldet oder registriert haben, werden Sie automatisch zur Anmeldeseite weitergeleitet, um sich zu registrieren und anzumelden; nach Abschluss kehren Sie automatisch zur aktuellen Seite zurück.

**Ein API-Token kann alle Dienste der Plattform aufrufen, ohne dass für jeden Dienst ein separater Antrag erforderlich ist.** Beim ersten Antrag erhalten Sie ein kostenloses Kontingent, das kostenlos getestet werden kann; wenn das Kontingent nicht ausreicht, können Sie in der [Konsole](https://platform.acedata.cloud/console/coin) ein allgemeines Guthaben aufladen.

> 📘 Vollständige Dokumentation: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Pflichtparameter nach Aktion auswählen

Wenn `action=generate` und `custom=false` (Standard) gilt, geben Sie `prompt` an; bei `custom=true`
und `instrumental=false` geben Sie `lyric` an. Benutzerdefinierte Instrumentalmusik kann mit
`custom=true, instrumental=true` festgelegt werden, ohne fiktive Liedtexte oder zusätzliche Prompts.
`action=extend` benötigt `audio_id` und ein `continue_at` größer als 0; im nicht-instrumentalen Modus wird außerdem
`lyric` benötigt. Cover, Varianten, das Ersetzen von Abschnitten, der Austausch von Stimmen und die Spurtrennung benötigen jeweils die Quell-`audio_id`;
Liedtexte und Prompts sollten nicht für alle Aktionen bedingungslos erforderlich sein.

In MCP wählen `producer_extend_music` und `producer_replace_section` den Modus für benutzerdefinierte Liedtexte, wenn `lyric`
angegeben wird; für die Fortsetzung von Instrumentalmusik kann `instrumental=true` übergeben und der Liedtext weggelassen werden.

## Grundlegende Verwendung

Wenn Sie an irgendeinen Song denken, können Sie beliebig einen Text eingeben. Wenn ich beispielsweise einen Song über Weihnachten generieren möchte, kann ich `a song for Christmas` eingeben, wie in der Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Sie können sehen, dass wir hier Request Headers festgelegt haben, einschließlich:

- `accept`: Welches Format der Antwortergebnisse empfangen werden soll; hier wird `application/json`, also das JSON-Format, eingetragen.
- `authorization`: Der Schlüssel zum Aufrufen der API, der nach dem Antrag direkt über die Auswahlliste ausgewählt werden kann.

Außerdem umfassen die Parameter des Request Body:

- `action`: Das Verhalten dieser Musikgenerierungsaufgabe; zum Generieren eines Songs ist es `generate`.
- `model`: Das zur Erstellung des Songs verwendete Modell; derzeit hauptsächlich: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: Der Liedtextinhalt des Songs.
- `custom`: Ob der Song auf benutzerdefinierte Weise generiert wird.
- `prompt`: Der Prompt im Inspirationsmodus.
- `title`: Titelinformationen des Songs.
- `audio_id`: Referenz-Song-ID, die für Fortsetzungen/Neuauflagen und andere Vorgänge verwendet wird.
- `continue_at`: Den Song ab der angegebenen Sekunde fortsetzen.
- `replace_section_start`/`replace_section_end`: Start- und Endzeit des zu ersetzenden Abschnitts, in Sekunden.
- `lyrics_strength`: Liedtextstärke, die den Einfluss der Liedtexte auf die Audiogenerierung darstellt; optional zwischen 0 und 1, Standardwert 0.5.
- `sound_strength`: Stärke des Audio-Prompts, optional zwischen 0.2 und 1, Standardwert 0.5.
- `cover_strength`: Cover-Stärke zwischen 0.2 und 1, Standardwert 1.
- `weirdness`: Grad der stilistischen Eigenart, optional zwischen 0 und 1, Standardwert 0.5.
- `callback_url`: Die URL, an die Ergebnisse zurückgegeben werden müssen.
- `async`: Optional; wenn auf `true` gesetzt, gibt die Schnittstelle sofort `task_id` zurück, ohne dass `callback_url` angegeben werden muss; anschließend werden die Ergebnisse durch Abfragen der entsprechenden Task-Abfrageschnittstelle per Polling abgerufen.
- `instrumental`: Ob es sich um einen Modus ohne Liedtext handelt.

Wenn Sie außerdem den entsprechenden Integrationscode generieren möchten, können Sie ihn direkt kopieren und generieren, beispielsweise lautet der CURL-Code wie folgt:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Song-Cover

Wenn Sie einen bereits generierten Song covern möchten, können Sie den oben generierten Song für das Cover verwenden. Als Nächstes müssen wir einen Song anhand von Liedtext und Titel benutzerdefiniert generieren.

Wenn Sie einen selbst hochgeladenen Song weiter covern möchten, können Sie den Parameter `action` auf `upload_cover` setzen und die Song-ID des benutzerdefiniert hochgeladenen Songs eingeben, der weiter gecovert werden soll. Die Song-ID wird mithilfe der [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload) abgerufen, wie in der folgenden Abbildung gezeigt:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Dann können die folgenden Inhalte angegeben werden:

- action: Das Verhalten dieser Song-Aufgabe. Derzeit unterstützt: generate, cover, extend, upload_cover, upload_extend, replace_section, swap_vocals, swap_instrumentals, variation. Für dieses Cover wird der Parameter `cover` verwendet.
- lyric: Liedtext
- title: Der Titel des Songs.
- custom: Ob die Generierung im benutzerdefinierten Modus erfolgt, standardmäßig ist false.
- audio_id: Die Song-ID des zu covernden Songs.

## Asynchroner Rückruf

Da die von der Producer Audios Generation API benötigte Generierungszeit manchmal relativ lang sein kann, würde die HTTP-Anfrage bei einer längeren Nichtreaktion der API die Verbindung weiterhin aufrechterhalten, was zu zusätzlichem Verbrauch von Systemressourcen führt. Daher bietet diese API auch Unterstützung für asynchrone Rückrufe.

Der gesamte Ablauf ist: Wenn der Client eine Anfrage initiiert, gibt er zusätzlich ein Feld `callback_url` an. Nachdem der Client die API-Anfrage initiiert hat, gibt die API sofort ein Ergebnis zurück, das ein Feld `task_id` enthält, welches die aktuelle Aufgaben-ID darstellt. Nachdem die Aufgabe abgeschlossen ist, wird das Ergebnis der Generierungsaufgabe in Form von POST JSON an die vom Client angegebene `callback_url` gesendet, wobei ebenfalls das Feld `task_id` enthalten ist, sodass das Aufgabenergebnis über die ID zugeordnet werden kann.

Im Folgenden erfahren wir anhand eines Beispiels, wie genau vorzugehen ist.

Zunächst ist der Webhook-Rückruf ein Dienst, der HTTP-Anfragen empfangen kann. Entwickler sollten ihn durch die URL ihres selbst eingerichteten HTTP-Servers ersetzen. Zur einfacheren Demonstration wird hier eine öffentliche Webhook-Beispielwebsite [https://webhook.site/](https://webhook.site/) verwendet. Beim Öffnen dieser Website erhalten Sie eine Webhook-URL, wie in der Abbildung gezeigt:

![](https://cdn.acedata.cloud/tbcnai.png)

## Fehlerbehandlung

Wenn bei der Aufrufung der API ein Fehler auftritt, gibt die API den entsprechenden Fehlercode und die entsprechende Information zurück. Zum Beispiel:

- `400 token_mismatched`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `400 api_not_implemented`: Ungültige Anfrage, möglicherweise aufgrund fehlender oder ungültiger Parameter.
- `401 invalid_token`: Nicht autorisiert, ungültiges oder fehlendes Autorisierungstoken.
- `429 too_many_requests`: Zu viele Anfragen, Sie haben das Ratenlimit überschritten.
- `500 api_error`: Interner Serverfehler, auf dem Server ist etwas schiefgelaufen.

### Beispiel für eine Fehlerantwort

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
