MiMo 2.6 Pro 和 MiMo 2.6 Flash 是小米 MiMo 系列模型。本介面使用 OpenAI Chat Completions 格式，按輸入、輸出和快取命中 token 計費。

## 模型與介面

| 模型                | 定位           |
| ----------------- | ------------ |
| `mimo-v2.6-pro`   | 複雜分析、推理與工具呼叫 |
| `mimo-v2.6-flash` | 日常對話與輕量任務    |

開通 MiMo 並取得對應的 API 憑證，向 `https://api.acedata.cloud/mimo/chat/completions` 傳送請求。OpenAI SDK 的 `base_url` 可設為 `https://api.acedata.cloud/mimo`。統一 `/v1/chat/completions` 入口同樣需要相應的服務權限。

首批介面範圍為文字 Chat Completions；影像、音訊、影片、連網搜尋、Responses、Messages、Batch 與 UltraSpeed 不在本次發布範圍內。

## Python 範例

```python
import os
from openai import OpenAI

client = OpenAI(
    api_key=os.environ["ACEDATACLOUD_API_KEY"],
    base_url="https://api.acedata.cloud/mimo",
)
response = client.chat.completions.create(
    model="mimo-v2.6-pro",
    messages=[{"role": "user", "content": "解釋彩虹形成的原因。"}],
    max_completion_tokens=256,
    extra_body={"thinking": {"type": "disabled"}},
)
print(response.choices[0].message.content)
print(response.usage)
```

範例展示請求寫法；真實回應範例將在服務驗證後補充。

## 串流、推理與工具呼叫

設定 `stream=true` 接收 SSE；如需最終用量，傳入 `stream_options={"include_usage": true}`。用戶端應處理內容、推理內容和工具呼叫增量，以及最終 usage 事件。

使用 `thinking.type=enabled` 開啟推理，`disabled` 關閉。`reasoning_content` 與最終 `content` 分開返回；續接工具呼叫時保留助手訊息中的推理內容、完整 `tool_calls` 和對應的 `tool_call_id`。

僅提交 `type=function` 的工具宣告，`tool_choice` 僅支援 `auto`。應用程式負責執行工具並回傳結果；模型返回工具呼叫本身不代表工具已執行。服務內建連網搜尋尚未開放。

## 計費

`prompt_tokens` 包含快取命中的輸入；`prompt_tokens_details.cached_tokens` 按快取價格計算，其餘輸入按一般輸入價格計算。`completion_tokens` 包含推理輸出，請勿重複累加推理 token。串流呼叫也按最終實際用量結算。

價格以控制台為準，Credit 的美元成本取決於購買方案。失敗請求不應被視為成功完成；如需核對扣費，請提供回應中的追蹤識別碼。

## 錯誤處理

參數錯誤請檢查請求格式；鑑權或權限錯誤請檢查憑證與服務開通情況；遇到 429 請退避重試。無健康模型容量時可能返回 503。串流回應開始後發生中斷時，先檢查已接收結果與用量，避免盲目重複請求。
