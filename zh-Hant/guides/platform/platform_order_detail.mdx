透過訂單 ID 查詢訂單。該端點支援兩種讀取模式：匿名存取只返回支付頁所需的最小欄位；訂單擁有者攜帶 Account Token 時返回完整詳情。

## 介面概覽

| 項   | 內容                                                        |
| --- | --------------------------------------------------------- |
| 方法  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| 驗證  | 可選；匿名為最小投影，已驗證擁有者為完整投影                                    |

`/orders/{id}` 與 `/orders/{id}/` 目前皆可使用。訂單 ID 是支付連結的一部分，應視為敏感的不透明識別碼，請勿公開傳播。

## 匿名查詢

支付頁面在登入狀態遺失時可以直接讀取：

```shell
export ORDER_ID='你的訂單 ID'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

匿名回應只包含 `id`、`description`、`price`、`state`、`pay_way`、`pay_url`、`expired_at`、`created_at`。它不會返回帳戶、Application、Package、支付內部識別碼或 metadata。

## 已驗證查詢

```shell
export PLATFORM_TOKEN='你的帳戶權杖'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

訂單擁有者會收到完整 Order 詳情，包括 `application` / `applications`、`package` / `packages`、`bank_details`、`invoice_automation` 及模型欄位。若已驗證但不是訂單擁有者，返回 `403`；超級管理員除外。

## 關鍵欄位

| 欄位            | 說明                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`、`Paid`、`Finished`、`Expired`、`Failed` 或 `Refunded` |
| `pay_way`     | 訂單目前支付方式；欄位名稱不是 `payment_method`                             |
| `pay_url`     | 託管支付頁面或 QR Code 位址，可能為空                                           |
| `price`       | 訂單最終應付金額，目前訂單模型不提供 `final_price` 欄位                         |
| `amount`      | 套餐額度數量；僅已驗證完整回應可見                                            |
| `finished_at` | 訂單完成時間；欄位名稱不是 `paid_at`                                      |

完整回應可能隨支付方式附加欄位，客戶端應視需要讀取，並始終避免記錄完整回應中的敏感 metadata。

## 錯誤處理

- `404`：訂單 ID 不存在。
- `403`：已登入但不是訂單擁有者。
- 匿名請求不會返回 `401`；它只會取得最小公開投影。

## 發票紅沖與重新申請

透過 `GET /api/v1/orders/{order_id}/invoice/` 可讀取訂單目前的發票。自動紅沖提交後，發票仍為 `Issued`，`red_state` 表示紅沖進度；提交成功不等於紅沖完成。等待確認、開立紅票或歸檔期間，訂單無法再次申請發票。

管理員因抬頭或統一編號等開票資訊錯誤申請紅沖時，紅沖原因為「開票有誤」；訂單退款觸發的自動紅沖仍使用「服務中止」。

紅票開立並歸檔成功後，原發票變為 `Voided`，訂單才可以重新申請。原發票可在發票歷史中查看。紅沖失敗或結果待核實時，由財務查核處理，訂單不會提前解除開票限制。人工開立的發票須先在稅務或開票系統完成作廢或紅沖，再由財務在平台確認。
