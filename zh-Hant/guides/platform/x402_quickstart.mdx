本教學用一個最小的 API 請求說明 Ace Data Cloud X402 的完整流程。目標不是先寫複雜程式碼，而是先看懂：為什麼第一次請求會回傳 402、`accepts` 裡有什麼、`PAYMENT-SIGNATURE` 又是怎樣讓同一個 API 請求變成已付款請求的。

## 準備工作

你需要準備：

| 項目   | 說明                                                   |
| ---- | ---------------------------------------------------- |
| 錢包   | 一個支援目標網路的錢包。Base 使用 EVM 錢包，Solana 使用 Solana 錢包。      |
| USDC | 錢包中需要有足夠 USDC。實際金額以 402 回應裡的 `maxAmountRequired` 為準。 |
| 開發環境 | TypeScript 建議 Node.js 18+；Python 建議 Python 3.10+。    |
| SDK  | 建議使用官方 SDK，不建議手寫簽名細節。                                |

X402 呼叫 Ace Data Cloud API 時不需要 API Token。SDK 第一次請求不帶 `Authorization`，Gateway 會回傳 `402 Payment Required` 和付款要求；SDK 簽名後自動重試。

## 安裝 SDK

原始碼和套件位址：

- SDK 儲存庫：[https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- X402 Client 儲存庫：[https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm：`@acedatacloud/sdk`、`@acedatacloud/x402-client`
- PyPI：`acedatacloud`、`acedatacloud-x402`

TypeScript：

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client ethers
```

Python：

```bash
pip install acedatacloud acedatacloud-x402
```

如果要使用 Solana，還需要安裝對應相依套件：

```bash
npm install @solana/web3.js
```

Python 版本的 Solana signer 相依套件已經包含在 `acedatacloud-x402` 中。

乾淨暫存環境的安裝和匯入檢查輸出：


結果說明：

- npm 套件和 PyPI 套件都是真實發佈套件，不是文件裡的佔位名稱。
- `acedatacloud-x402[cli]` 會安裝 CLI，`approve-permit2` 子命令可用於 `upto` 情境的 Permit2 授權。

## 第一次請求會回傳 402

你可以先用 `curl` 看看未付款請求回傳什麼。下面範例不會產生扣款，因為它沒有攜帶 `PAYMENT-SIGNATURE`：

```bash
curl -sS -X POST https://x402.acedata.cloud/openai/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "hi"}],
    "max_tokens": 1
  }'
```

回傳主體會包含 `accepts` 陣列，常見結構如下：

```json
{
  "x402Version": 2,
  "resource": {
    "url": "/openai/chat/completions",
    "description": "AceDataCloud API call",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "maxAmountRequired": "95215",
      "amount": "95215",
      "maxTimeoutSeconds": 3600,
      "resource": "/openai/chat/completions",
      "description": "...",
      "payTo": "0x...",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913"
      }
    }
  ],
  "error": "PAYMENT-SIGNATURE header is required"
}
```

同一份挑戰內容也會以 base64 形式放在 `PAYMENT-REQUIRED` 回應標頭中，方便用戶端不解析 body 就讀取付款要求。

正式環境 API 未付款請求的程式輸出摘要如下：

```text
status=402
x402Version 2
accepts [
  ('eip155:8453', 'exact', '95215'),
  ('eip155:8453', 'upto', '95215'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '95215'),
]
```

結果說明：

- 第一次請求沒有攜帶 `Authorization` 或 `PAYMENT-SIGNATURE`，所以回傳 HTTP 402，不會產生扣款。
- `accepts` 是本次請求唯一可信的簽名依據，包含可選網路、scheme、金額上限、收款地址和資產地址。
- `network` 是 CAIP-2 識別碼，用戶端選網時必須按 CAIP-2 字串比對。
- 這次 `gpt-4o-mini` 最小聊天請求的上限金額是 `95215` atomic USDC，也就是 `0.095215` USDC。
- 每次請求都應該讀取當次 402 回應，不要把範例金額硬編碼進業務程式碼。

欄位含義：

| 欄位                  | 說明                                                             |
| ------------------- | -------------------------------------------------------------- |
| `scheme`            | 付款方案。`exact` 表示固定金額，`upto` 表示授權上限、按實際用量結算。                     |
| `network`           | 付款網路的 CAIP-2 識別碼，例如 `eip155:8453`、`solana:5eykt4...`。           |
| `maxAmountRequired` | 最大付款金額，單位是 USDC atomic units，`95215` 表示 `0.095215` USDC。       |
| `amount`            | 本次要結算的金額；`exact` 與 `maxAmountRequired` 相同，`upto` 在結算階段按實際用量改寫。 |
| `payTo`             | 收款地址。                                                          |
| `asset`             | USDC 合約地址或 Solana mint 地址。                                     |
| `extra`             | 簽名需要的鏈 ID、EIP-712 domain、Permit2 地址等擴充資訊。                      |

## 用 SDK 完成付款重試

下面是最小 TypeScript 範例。它指定 `network: 'base'`，handler 會從本次 402 回應中選擇 Base 的 payment requirement；實際金額和收款地址仍以 `accepts` 為準：
```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const response = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Reply with exactly: hello' }],
  max_tokens: 8
});

console.log(response.choices[0].message.content);
```

這段程式碼背後發生了四步：

1. SDK 發送一次一般 API 請求，不帶 `Authorization`。
2. Gateway 回傳 `402 Payment Required` 和 `accepts`。
3. `createX402PaymentHandler` 選擇 `network = 'base'` 的 payment requirement 並簽出 `PAYMENT-SIGNATURE`。
4. SDK 用同一個請求主體重試，Gateway 呼叫 Facilitator 驗證並結算後放行到目標 API。

## 查看 Facilitator 支援能力

X402 API 不依賴資源目錄。用戶端直接呼叫已知 API，並以該請求即時回傳的
`402 Payment Required` 和 `accepts` 作為唯一價格與簽名依據。

Facilitator 的能力聲明位於：

```bash
curl https://facilitator.acedata.cloud/.well-known/x402
```

它只描述 `/supported`、`/verify`、`/settle` 和目前啟用的支付網路，不列出 API 資源。

Ace Data Cloud 的生產 Facilitator 位址為：

```text
https://facilitator.acedata.cloud
```

可以查看它支援哪些網路和 scheme：

```bash
curl https://facilitator.acedata.cloud/supported
```

回傳的 `kinds` 會列出 Facilitator 支援的網路和 scheme。實際呼叫時仍以 API 回傳的 `accepts` 為準。

Facilitator `/supported` 輸出：

```text
kinds [
  ('eip155:8453', 'exact'),
  ('eip155:8453', 'upto', {'facilitatorAddress': '0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708'}),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact')
]
```

結果說明：

- `/supported` 說明 Facilitator 具備這些網路和 scheme 的驗證、結算能力。
- Base 和 Solana 都支援 `exact`；`upto` 目前只在 Base 上提供。
- 具體 API 是否允許某個網路，仍以該 API 的 402 `accepts` 為準。
