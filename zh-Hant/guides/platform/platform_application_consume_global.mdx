title: "設定 AceDataCloud Application 全域餘額共享"
description: "Platform 整合指南 - Ace Data Cloud"
---

設定 `allow_consume_global`。開啟後，符合條件的按量 Application 在自身餘額不足時可繼續使用帳戶全域餘額。

## 準備工作

- 建立並安全保存 [Account Token](https://platform.acedata.cloud/documents/platform-token)。
- 從[服務申請列表](https://platform.acedata.cloud/documents/platform-application-list)取得本人擁有的 `application_id`。

```shell
export PLATFORM_TOKEN='你的账户令牌'
export APPLICATION_ID='你的 Application ID'
```

## 介面概覽

| 項    | 內容                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------- |
| 方法   | `POST`                                                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/applications/{application_id}/update-allow-consume-global/` |
| 驗證   | Account Token                                                                                      |
| Body | JSON                                                                                               |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/applications/${APPLICATION_ID}/update-allow-consume-global/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"allow_consume_global": true}'
```

成功返回更新後的 Application 物件。請以回應中的 `allow_consume_global` 為準，而不是假設請求值一定被儲存。

> `Period` 類型的 Application 不允許消耗全域餘額。即使請求 `true`，伺服器端也會將該欄位保持為 `false`。

## 錯誤處理

- `401`：Account Token 無效或缺失。
- `403`：目前帳戶不是該 Application 的擁有者。
- `404`：Application ID 不存在。

全域餘額的儲值入口和可用方案以平台控制台及[訂單建立](https://platform.acedata.cloud/documents/platform-order-create)返回的實際方案為準；不要假設存在 `Wallet` 類型方案。

## 已授權透支的應用程式

當按量應用程式的唯讀欄位 `allow_overdraft=true` 時，該應用程式可繼續從自己的餘額扣費，即使餘額變成負數，也不會因餘額不足切換到全域帳戶。未開啟透支的應用程式仍遵循 `allow_consume_global`；切換後是否允許透支，以實際扣款的全域 Application 的設定為準。

## 試用帳戶並行限制

系統用唯讀使用者標記 `has_recharged` 記錄是否曾成功完成付費儲值或由管理員手動增加積分，標記在操作成功後更新，歷史使用者會依訂單或明確的加分記錄統一補齊。既未付費儲值、也未被管理員手動加分的帳戶，整個帳戶同時只允許一個計費請求執行；不同 API Key 和不同服務共用這一個名額。獎勵、兌換卡和轉贈額度不視為付費儲值。已經完成付費儲值或由管理員手動增加過積分的帳戶不受這項試用並行限制，仍遵循原有餘額和憑證額度檢查。

已有請求正在執行時，新請求返回 `429 too_many_requests`。任務查詢等免費輪詢介面仍可正常呼叫。Realtime 的連線驗證沿用原有逐輪計費流程，不占用這個一般請求名額。

非同步介面返回「已受理」時，任務仍在執行，需要等待最終結果後再提交下一次生成請求。網路中斷或代理逾時不代表任務已經停止；若任務長時間沒有終態，請提供 `trace_id` 聯絡支援查核。

這項限制不改變可試用的介面，也不改變原有計費規則。費用仍在請求結束後按實際用量結算。
