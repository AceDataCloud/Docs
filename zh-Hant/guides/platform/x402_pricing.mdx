這篇文件說明用 X402 呼叫 Ace Data Cloud API 時，價格是怎麼定的，以及它和平台普通 **Credits**（額度）價格是什麼關係。

## 核心結論

X402 不是一套獨立的價格體系。每個 API 呼叫本來就有一個以 **Credits** 計的成本，這是所有計費方式（API Token 扣額度、帳戶餘額、X402 鏈上支付）共用的唯一價格來源。X402 只是把這個 Credits 成本按一個固定匯率換算成鏈上 USDC：

> **1 Credit = 0.095215 USDC**（即 `95215` atomic USDC，USDC 為 6 位小數）

也就是說：

```text
X402 價格 (USDC) = 該次呼叫的 Credits 成本 × 0.095215
```

這個匯率不是憑空設定的，它等於平台 **最優檔（大額）Credits 單價**。所以用 X402 付費 ≈ 用最優檔單價買 Credits 再消費，**沒有 X402 溢價**，反而直接享受最便宜的 Credits 單價，且無需預充值、無需 API Token。

## 計價基準

| 項目        | 值                              | 說明                                                    |
| --------- | ------------------------------ | ----------------------------------------------------- |
| 換算匯率      | `1 Credit = 0.095215 USDC`     | 平台統一設定的固定匯率                                           |
| atomic 單位 | `1 Credit = 95215 atomic USDC` | USDC 6 位小數，`atomic = floor(credits × 0.095215 × 1e6)` |
| 最小扣費      | `1 atomic USDC`（$0.000001）     | 即使成本極低，也至少結算 1 atomic                                 |
| 計價幣種      | USDC                           | Base 為 ERC-20 USDC，Solana 為 SPL USDC                  |

換算由平台統一完成，金額對所有支援的網路（Base、Solana）一致；不同網路只是資產合約和簽名方式不同，價格相同。

### 和普通 Credits 單價的關係

平台 Credits 按「用量越大、單價越低」的階梯出售。X402 按呼叫計費時，統一使用階梯最優檔單價：

| 購買/支付方式        | 大致 Credits 單價            | 說明                   |
| -------------- | ------------------------ | -------------------- |
| 入門 / 小額充值      | 約 `$0.13 / Credit`       | 列表價，小額買 Credits 時的單價 |
| 大額 / 最優檔       | `$0.095215 / Credit`     | 最便宜的單價               |
| **X402 按呼叫付費** | **`$0.095215 / Credit`** | **始終等於最優檔單價**        |

換句話說，X402 把每次呼叫都按最優檔 Credits 單價結算。小額充值買 Credits 的使用者，單價會高於 X402；大額充值使用者的單價才和 X402 一致。

## 兩種價格形態：`exact` 與 `upto`

X402 的 402 回應裡，`maxAmountRequired` 就是你要簽名的金額。它有兩種形態：

- **`exact`（固定價）**：請求處理前價格就能確定（圖片、影片、音樂、搜尋、訂單支付）。`maxAmountRequired = 該呼叫 Credits 成本 × 0.095215`，即該次呼叫的應付金額（與成功回應裡的 `cost.amount` 一致）。
- **`upto`（用量後置計量）**：聊天補全這類「回應結束才知道用了多少 token」的介面。`maxAmountRequired` 是一個**上限**（按該模型設定的上限額度換算：上限 Credits × 0.095215），實際按真實用量結算，且不超過上限。

關於這兩種 scheme 的協定細節見 [`exact` 與 `upto` 計費方案](https://platform.acedata.cloud/documents/x402-metered-upto)。下面只講價格。

## Chat（聊天補全）價格

聊天補全是 `upto` 計量：按 prompt / completion token 實際用量計費。每百萬（1M）token 的價格 = `該模型每 1M token 的 Credits 成本 × 0.095215`，與平台公開模型目錄（`/api/v1/models?with_pricing=true`）展示的 USD 單價完全一致。

下表為真實價格（取自模型目錄，按 X402 匯率計），單位 USD / 1M token：

| 模型                | 輸入 / 1M | 輸出 / 1M  | `upto` 上限             |
| ----------------- | ------- | -------- | --------------------- |
| gpt-4o-mini       | $0.0796 | $0.3183  | 1 Credit（$0.095215）   |
| gemini-2.5-flash  | $0.1591 | $1.3262  | 5 Credits（$0.476074）  |
| gpt-5 / gpt-5.1   | $0.6631 | $5.3050  | 20 Credits（$1.904299） |
| gemini-2.5-pro    | $0.6631 | $5.3050  | 50 Credits（$4.760750） |
| gpt-4.1           | $1.0610 | $4.2440  | 20 Credits（$1.904299） |
| claude-sonnet-4-5 | $0.6006 | $3.0028  | 50 Credits（$4.760750） |
| grok-4            | $1.5915 | $7.9574  | 10 Credits（$0.952149） |
| claude-opus-4-1   | $3.0028 | $15.0140 | 50 Credits（$4.760750） |

說明：

- 表中為按 token 計量的單價；一次請求費用 = 輸入 token × 輸入單價 + 輸出 token × 輸出單價。
- `upto` 上限是該模型一次請求允許簽名的最大金額；它不是實際扣款，絕大多數請求遠低於上限。
- 上限只決定「最多可能扣多少」，真實結算按 token 用量計算。

### 範例：報價與扣費一致（`exact`）

下面是用官方 X402Client 對 `serp/google` 發起的一次**真實付費呼叫**（Base `exact`）。它示範了三者一致：402 報價、簽名金額、以及成功回應裡返回的 `cost`。

```text
# 1) 未支付請求 -> 402，拿到報價（不扣費）
POST /serp/google  ->  402
base/exact maxAmountRequired = 952 atomic = $0.000952 = 0.01 Credit
# 0.01 × 0.095215 = 0.00095215，向下取整到 atomic = 952

# 2) 用錢包簽名 952 atomic 的 PAYMENT-SIGNATURE，重試
POST /serp/google (PAYMENT-SIGNATURE) -> 200
body.cost = {"amount": 0.000952, "currency": "usdc", "settlement": "authorized"}
```
回應返回的 `cost.amount`（0.000952 USDC）與 402 報價、與 `Credits × 0.095215` 完全一致。`settlement` 欄位是該筆支付的結算狀態（`authorized` = 已授權）；鏈上結算由平台處理，機制見 [`exact` 與 `upto` 計費方案](https://platform.acedata.cloud/documents/x402-metered-upto)。

### `upto` 報價計算（聊天）

聊天按 token 計量。某次請求的報價（不是上限）按下式計算（以 gpt-4o-mini 為例）：

```text
Credits = 1e-6 × (0.835733 × prompt_tokens + 3.342933 × completion_tokens)
USDC    = Credits × 0.095215
```

一次 500 prompt + 200 completion token 的請求：

```text
Credits = 1e-6 × (0.835733 × 500 + 3.342933 × 200) ≈ 0.001086 Credits
報價 USDC ≈ 0.001086 × 0.095215 ≈ $0.0001034
```

客戶端按 `upto` 上限（gpt-4o-mini 為 1 Credit = `95215` atomic）簽名，這只是**最多可能扣多少**；該次請求的真實報價（上例約 $0.0001）遠低於上限，按 token 用量結算。`upto` 的鏈上結算機制見 [`exact` 與 `upto` 計費方案](https://platform.acedata.cloud/documents/x402-metered-upto)。

## 訂單支付價格

用 X402 支付控制台訂單（購買套餐 / 儲值 Credits）時，價格以訂單頁面顯示為準，402 的 `amount` 為最終簽名依據。訂單支付走平台 API、需要帳戶權杖，詳見 [訂單支付教學](https://platform.acedata.cloud/documents/x402-order-payment)。

訂單支付教學中的一個真實例子（購買 10 Credits）：

```text
description Ace Data Cloud Credits x 10.0
created price 1.26          # 訂單建立價（USD）
settled    1.20 USDC        # 最終簽名/結算金額（= 402 amount）
            = 1200000 atomic USDC
```

注意：**按呼叫付費**（上文 Chat / 其他服務）和**訂單支付**是兩條不同路徑。按呼叫付費統一用 `0.095215`/Credit 的最優檔單價；訂單支付按套餐定價，其建立價與最終結算金額的差異以 [訂單支付教學](https://platform.acedata.cloud/documents/x402-order-payment) 為準。

## 如何即時取得價格

價格隨模型和參數變化，請用程式即時取得，不要硬編碼：

- **按呼叫價格**：對目標 API 發一次**不帶** `PAYMENT-SIGNATURE`（也不帶 `Authorization`）的請求，讀取返回的 402 `accepts[].maxAmountRequired`。這一步不會扣費。對 `exact` 介面它是最終價格；對 `upto` 介面（聊天）它是上限，實際按用量結算。
- **聊天每 token 單價**：`GET https://platform.acedata.cloud/api/v1/models?with_pricing=true&type=chat`，讀取每個模型的 `pricing.input_usd` / `pricing.output_usd`（已按 `credit_usd_rate` 計算）。
- **換算校驗**：`atomic = floor(Credits × 0.095215 × 1e6)`，`USDC = atomic / 1e6`（即 `USDC ≈ Credits × 0.095215`）。

取得價格的最小請求範例：

```bash
curl -sS -X POST https://x402.acedata.cloud/midjourney/imagine \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "a cat"}'
# 返回 402，accepts[].maxAmountRequired 即為該次（exact）呼叫價格
```

## 小結
- X402 價格 = 該次呼叫的 Credits 成本 × `0.095215`，和一般 Credits 計費是**相同價格**，只是使用鏈上 USDC 結算。
- `0.095215`/Credit 是平台**最優級距**（大額）Credits 單價；小額儲值購買 Credits 的單價更高，所以 X402 等於自動取得最優單價。
- `exact` 介面（圖片 / 影片 / 音樂 / 搜尋 / 訂單）簽名金額即該次應付金額；`upto` 介面（聊天）簽名的是上限，依實際用量結算。
- 權威價格以 402 回傳的 `maxAmountRequired` 為準：`exact` 是應付金額（與成功回應的 `cost.amount` 一致，已實測）；`upto` 是上限，成功回應的 `cost.amount` 才是依用量結算的實際金額（≤ 上限）。
