## 3. 上傳本機圖片

使用 `multipart/form-data`：

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

可重複傳入 `image`，GPT Image 系列最多支援 16 張參考圖。JSON 請求中的 `image` 可以是單一 URL 或 URL 陣列；本機檔案使用 multipart 上傳。

### 模型與計費方式

| 模型                                | 適用情境與計費方式                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | 預設逆向通道，依成功圖片張數固定計費                               |
| `gpt-image-2:reverse`             | 明確選擇逆向通道，依成功圖片張數固定計費                             |
| `gpt-image-2:official`            | 官方 API 通道，穩定性更高，依實際 Token 用量計費                   |
| `gpt-image-2.5-flare`             | 側重生成速度，依成功圖片張數固定計費                               |
| `gpt-image-2.6-flare`             | 側重生成速度，依成功圖片張數固定計費                               |
| `gpt-image-2.5-flare:reverse`     | 明確逆向別名，與 `gpt-image-2.5-flare` 等價，依成功圖片張數固定計費    |
| `gpt-image-2.6-flare:reverse`     | 明確逆向別名，與 `gpt-image-2.6-flare` 等價，依成功圖片張數固定計費    |
| `gpt-image-2.5-flare:official`    | 官方 API 通道，穩定性更高且側重生成速度，依實際 Token 用量計費            |
| `gpt-image-2.6-flare:official`    | 官方 API 通道，穩定性更高且側重生成速度，依實際 Token 用量計費            |
| `gpt-image-2.5-sunburst`          | 側重高保真與精細控制，依成功圖片張數固定計費                           |
| `gpt-image-2.6-sunburst`          | 側重高保真與精細控制，依成功圖片張數固定計費                           |
| `gpt-image-2.5-sunburst:reverse`  | 明確逆向別名，與 `gpt-image-2.5-sunburst` 等價，依成功圖片張數固定計費 |
| `gpt-image-2.6-sunburst:reverse`  | 明確逆向別名，與 `gpt-image-2.6-sunburst` 等價，依成功圖片張數固定計費 |
| `gpt-image-2.5-sunburst:official` | 官方 API 通道，穩定性更高且側重高保真與精細控制，依實際 Token 用量計費        |
| `gpt-image-2.6-sunburst:official` | 官方 API 通道，穩定性更高且側重高保真與精細控制，依實際 Token 用量計費        |

官方 API 通道的頁面價格是請求前預估，最終以回應中的實際 Token 用量和使用紀錄為準。

`quality` 支援 `auto`、`low`、`medium`、`high`；2.5 / 2.6 Flare 和 Sunburst（含 `:reverse` 和 `:official` 變體）額外支援 `xhigh`、`max`。JSON 圖片 URL 編輯和 multipart 檔案編輯皆可傳入該欄位；官方通道依實際 Token 用量計費。

## 4. 使用遮罩局部編輯

官方 Images Edit 介面透過 `mask` 指定允許修改的區域。Ace Data Cloud 的 `:official` 模型遵循相同的 multipart 契約：

- `mask` 必須是帶有 Alpha 通道的 PNG，大小不得超過 4MB；
- 遮罩尺寸必須與第一張 `image` 完全一致；
- Alpha 為 `0` 的透明像素表示允許編輯，非透明像素表示應保留；
- 只有顏色為黑白、但沒有透明通道的 RGB 圖片不能作為有效遮罩；
- 提示詞應描述期望得到的完整畫面，同時明確局部修改和需要保持不變的內容。

下面先從原圖產生一個遮罩。範例將中央矩形設為透明，只允許模型修改該區域：
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

然後將原圖和遮罩一起上傳：

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

也可以沿用 OpenAI 官方 Python SDK 的 `images.edit` 呼叫方式，只需將 `base_url` 指向 Ace Data Cloud：

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

使用 `mask` 時，原圖和遮罩必須在同一個 multipart 請求中分別透過 `image=@input.png` 與 `mask=@mask.png` 上傳。不要將 URL 原圖與本機遮罩檔案混合傳入；純 URL 編輯請求不支援再附加本機 `mask` 檔案。遮罩會約束編輯區域，但生成模型仍可能對邊緣進行自然融合；需要嚴格邊界時，應使用清晰的 Alpha 邊緣，並在提示詞中重複說明哪些內容必須保持不變。

以上呼叫方式與 [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) 和 [GPT Image 官方 Cookbook](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image) 的遮罩範例一致。

## 5. 常用參數

| 欄位                | 說明                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`、`gpt-image-2.5-flare`（更快）或 `gpt-image-2.5-sunburst`（更高保真度與控制）；三者皆可選擇對應的 `:official` 變體，`gpt-image-2` 還支援 `:reverse` |
| `image`           | JSON 使用單一 URL 或最多 16 個 URL 的陣列；multipart 使用一個或多個 `image` 檔案欄位。使用 `mask` 時必須上傳本機圖片檔案                                              |
| `mask`            | 可選 PNG 遮罩，僅限 multipart 檔案上傳；須帶有 Alpha 通道、與第一張 `image` 同尺寸且不超過 4MB                                                                 |
| `prompt`          | 編輯指令                                                                                                                             |
| `size`            | `auto` 或符合限制的 `WIDTHxHEIGHT`                                                                                                     |
| `n`               | 1–10；`response_format=b64_json` 時僅支援 1                                                                                           |
| `response_format` | `url` 或 `b64_json`                                                                                                               |
| `callback_url`    | 可選的非同步回呼網址                                                                                                                         |

尺寸規則與生成介面一致：寬高須為 16 的倍數，長邊不超過 3840，總像素為 655,360–8,294,400，寬高比不超過 3:1。省略 `size` 或使用 `auto` 時，模型會結合提示詞和第一張參考圖選擇畫幅。

`gpt-image-2`、`gpt-image-2.5-flare`、`gpt-image-2.5-sunburst` 及其 `:reverse` 別名按成功張數計費；`gpt-image-2:official`、`gpt-image-2.5-flare:official` 和 `gpt-image-2.5-sunburst:official` 根據文字輸入、參考圖輸入和圖片輸出的實際 Token 結算，最終以使用紀錄為準。

## 6. 非同步回呼與疑難排解

長任務可在請求中加入：

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

非同步 200 回應為 `{"task_id": "..."}`；完成後回呼最終結果。同步請求則回傳 `created` 和 `data`。

| 狀態  | 檢查                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | 圖片格式/數量、參數組合和尺寸格式；使用 `mask` 時檢查 PNG Alpha 通道、4MB 限制及其尺寸是否與第一張原圖一致 |
| 401 | API Key 與 Bearer Header                                           |
| 429 | 請求頻率                                                              |
| 504 | 改用非同步回呼                                                            |

錯誤回應會包含 `trace_id`。回報問題時提供該 ID，不要提供 API Key。

完整欄位和即時列舉以 [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits) 頁面為準。純文字生成圖片請查看 [GPT Image 2 / 2.5 / 2.6 圖像生成](https://platform.acedata.cloud/documents/openai-images-generations)。

## GPT Image 2.6

GPT Image 2.6 沿用 2.5 的生成、編輯、非同步任務和計費介面：

| 模型                                                          | 計費                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0.22 Credits/張                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0.22 Credits/張                   |
| `gpt-image-2.6-flare:official`                              | 與 2.5 official 相同，按實際 Token 用量計費 |
| `gpt-image-2.6-sunburst:official`                           | 與 2.5 official 相同，按實際 Token 用量計費 |

品質可選 `auto`、`low`、`medium`、`high`、`xhigh`、`max`；尺寸使用 `auto` 或符合上述約束的 `WIDTHxHEIGHT`。本介面支援 `png`、`jpeg`、`webp`；GPT Image 2.6 還支援原生 `gif` 動圖，暫不支援 SVG。編輯支援 JSON 圖片 URL 和 multipart 檔案上傳。`:reverse` 是同名一般版的明確別名。請使用完整型號，不要傳入 `gpt-image-2.6`。

### GPT Image 2.6 圖片轉 GIF 動圖
GPT Image 2.6 Flare、Sunburst 的一般版、`:reverse`、`:official` 均可使用 `output_format: "gif"`。動畫影格、循環資訊和播放時長會保留；`frame_count` 表示影格數，`frame_duration_ms` 表示每影格毫秒數，影格數必須為 2–16 的整數，每影格時長必須為 20–655350 毫秒的整數，且僅用於 GIF；編碼會按最接近的 10ms 取整。未指定時預設為 9 影格、每影格 200 毫秒；GIF 的 size 省略或為 auto 時使用 512x512 預設。

建議先使用 `size: "512x512"`、`frame_count: 9`、`frame_duration_ms: 200`。GIF 有獨立的尺寸和影格數限制，不能直接套用靜態 4K 規格；部分模型會調整實際輸出尺寸。`n` 表示回傳的 GIF 檔案數量，不是動畫影格數。一般版和 `:reverse` 仍按成功檔案數量計費，官方版按實際 Token 用量計費。

```json
{
  "model": "gpt-image-2.6-flare",
  "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
  "prompt": "Animate the mug gently moving left and right. Keep its appearance and the background, no text.",
  "output_format": "gif",
  "size": "512x512",
  "quality": "medium",
  "frame_count": 9,
  "frame_duration_ms": 200,
  "n": 1,
  "async": true
}
```

### GPT Image 2.6 4K 靜態圖

Flare、Sunburst 及其 `:reverse`、`:official` 變體都可使用前述 4K 像素預設，例如 `3840x2160` 和 `2160x3840`。生成和編輯均透過 `size` 傳入具體像素；`4K` 不是有效的 `size` 值，`4096x4096` 也超出目前像素上限。上述 4K 規格適用於靜態 PNG/JPEG/WebP，GIF 請使用其專用參數。

### GPT Image 2.6 構圖複雜度

`complexity` 可選 `low`、`medium`、`high`，省略時使用模型預設 `high`。它控制規劃複雜度，與 `quality` 渲染品質獨立；不會額外按次收費，官方版仍按實際 Token 結算。其他型號不支援此參數。

GIF 不支援 mask、標註圖、自訂壓縮、提示詞重寫或部分圖像串流輸出；不相容的組合會在生成前拒絕。尺寸、影格數和數量共同受模型像素預算限制；一般 Flare 的 `1024x1024`、2 影格已驗證可用，不能把這個結論擴展到所有 1K 組合或 4K GIF。

### 標註引導編輯

GPT Image 2.6 靜態編輯支援 `markup`。上傳與第一張參考圖同尺寸的透明 PNG，在獨立圖層圈出要修改的位置，並在 `prompt` 說明修改要求。標註層必須含透明像素；兩張圖各不超過 16777216 像素，標註圖不超過 40MB。JSON 可傳 HTTPS URL、PNG base64 data URL 或 `{ "image_url": "https://..." }`；multipart 透過 `markup` 上傳檔案。平台會以檔案形式傳遞標註層。`markup` 不能與 `mask`、GIF 或 `prompt_rewriter` 同用，不支援 `file_id`。

`input_fidelity` 不適用於 GPT Image 2.6，請省略。
