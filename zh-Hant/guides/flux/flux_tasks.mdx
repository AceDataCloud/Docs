Flux Tasks API 的主要功能是透過輸入 Flux Images Generation API 或 Flux Videos API 回傳的平台任務 ID，來查詢該任務的執行情況。

本文檔將詳細介紹 Flux Tasks API 的串接說明，協助您輕鬆整合並充分利用該 API 的強大功能。透過 Flux Tasks API，您可以輕鬆實現查詢 Flux Images Generation API 的任務執行情況。

影片提交與輪詢的完整範例請參見 [Flux Videos API 整合指南](https://platform.acedata.cloud/documents/flux-videos-integration)。查詢既有任務不會另外收取生成費用。

## 申請流程

要使用 Flux Images Generation API，首先前往 [Ace Data Cloud 控制台](https://platform.acedata.cloud/console/applications) 取得您的 API Token，留作備用。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

如果您尚未登入或註冊，會自動跳轉至登入頁面邀請您註冊及登入，完成後會自動返回目前頁面。

**一個 API Token 即可呼叫平台所有服務，無須為每個服務分別申請。** 首次申請會贈送免費額度，可免費體驗；額度不足時可在 [控制台](https://platform.acedata.cloud/console/coin) 儲值通用餘額。

> 📘 完整文件：[Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

Flux Tasks API 可用於查詢 Flux Images Generation API 的結果。關於如何使用 Flux Images Generation API，請參考文件 [Flux Images Generation API ](https://platform.acedata.cloud/documents/flux-images-integration)。

### 設定請求標頭和請求主體

**Request Headers** 包括：

- `accept`：指定接收 JSON 格式的回應結果，此處填寫為 `application/json`。
- `authorization`：呼叫 API 的金鑰，申請之後可以直接下拉選擇。

**Request Body** 包括：

- `id`：上傳的任務 ID。
- `action`：對任務的操作方式。

部分程式碼範例如下：

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/flux/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/flux/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

回傳結果一共有多個欄位，request 欄位就是發起任務時的 request body，而 response 欄位則是任務完成後回傳的 response body。欄位介紹如下。

- `id`，產生此圖片任務的 ID，用於唯一識別此次圖片生成任務。
- `request`，查詢圖片任務中的請求資訊。
- `response`，查詢圖片任務中的回傳資訊。
- `created_at`，任務建立時間，Unix 時間戳記（秒，浮點）。
- `started_at`，任務開始執行時間，Unix 時間戳記（秒，浮點）。
- `finished_at`，任務完成時間，Unix 時間戳記（秒，浮點）。任務未完成時不回傳此欄位。
- `elapsed`，任務執行耗時，單位為秒（浮點，保留 3 位小數）。任務未完成時不回傳此欄位。

## 錯誤處理

在呼叫 API 時，如果遇到錯誤，API 會回傳相應的錯誤代碼和資訊。例如：

- `400 token_mismatched`：錯誤請求，可能是由於缺少或無效的參數。
- `400 api_not_implemented`：錯誤請求，可能是由於缺少或無效的參數。
- `401 invalid_token`：未授權，授權權杖無效或缺失。
- `429 too_many_requests`：請求過多，您已超出速率限制。
- `500 api_error`：內部伺服器錯誤，伺服器發生了問題。

### 錯誤回應範例
