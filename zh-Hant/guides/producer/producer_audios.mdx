本文將介紹一種 Producer Audios Generation API 串接說明，它可以透過輸入自訂參數來生成 Producer 官方的音樂。

## 申請流程

要使用 Producer Audios Generation API，首先到 [Ace Data Cloud 控制台](https://platform.acedata.cloud/console/applications) 取得您的 API Token，留作備用。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

如果你尚未登入或註冊，會自動跳轉到登入頁面邀請你註冊和登入，完成後會自動返回目前頁面。

**一個 API Token 即可呼叫平台所有服務，無需為每個服務單獨申請。** 首次申請會贈送免費額度，可免費體驗；額度不足時可在 [控制台](https://platform.acedata.cloud/console/coin) 儲值通用餘額。

> 📘 完整文件：[Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## 基本使用

想要什麼歌曲，可以任意輸入一段文字，比如我想生成一首關於聖誕節的歌曲，就可以輸入 `a song for Christmas`，如圖所示：

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

可以看到這裡我們設定了 Request Headers，包括：

- `accept`：想要接收什麼格式的回應結果，這裡填寫為 `application/json`，即 JSON 格式。
- `authorization`：呼叫 API 的金鑰，申請之後可以直接下拉選擇。

另外 Request Body 的參數包括：

- `action`：此次音樂生成任務的行為，生成歌曲是 `generate`。
- `model`：建立歌曲採用的模型，目前主要有： **FUZZ-2.0 Pro**、**FUZZ-2.0**、**FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**、**FUZZ-1.0 Pro**、**FUZZ-1.0**、**FUZZ-1.1**、**FUZZ-0.8**。
- `lyric`：歌曲的歌詞內容。
- `custom`：是否採用自訂方式生成歌曲。
- `prompt`：靈感模式下的提示詞。
- `title`：歌曲標題資訊。
- `audio_id`：參考歌曲 ID，用於續寫/翻版等操作。
- `continue_at`：從指定秒數開始續寫歌曲。
- `replace_section_start`/`replace_section_end`：替換片段的起止時間，單位秒。
- `lyrics_strength`：歌詞強度，表示歌詞在音訊生成中的影響程度，可選 0-1 之間，預設 0.7。
- `sound_strength`：音訊提示詞強度，可選 0.2-1 之間，預設 0.7。
- `cover_strength`：翻唱強度 0.2-1 之間，預設 1。
- `weirdness`：風格奇特度，可選 0-1 之間，預設 0.5
- `callback_url`：需要回呼結果的 URL。
- `async`：可選，設為 `true` 時介面立即返回 `task_id`，無需提供 `callback_url`，隨後透過對應的任務查詢介面輪詢取得結果。
- `instrumental`：是否為無歌詞模式。

另外如果想生成對應的串接程式碼，可以直接複製生成，例如 CURL 的程式碼如下：

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## 翻唱歌曲

如果想對已經生成的歌曲進行翻唱操作，可以輸入上文生成的歌曲進行翻唱，接下來我們要根據歌詞、標題自訂生成歌曲。

如果想對自己上傳的歌曲繼續進行翻唱的話，可以將參數 `action` 設定為 `upload_cover`，並且輸入需要繼續翻唱的自訂上傳歌曲 ID，歌曲 ID 的取得是使用 [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload)來取得，如下圖所示：

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

就可以指定如下內容：

- action：此次歌曲任務的行為，目前支援：generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation，此次翻唱使用`cover`參數。
- lyric：歌詞文字
- title：歌曲的標題。
- custom：是否採用自訂模式生成，預設是false。
- audio_id：需要翻唱歌曲的歌曲ID。

填寫範例如下：

## 非同步回呼

由於 Producer Audios Generation API 生成的時間有時候會相對較長，如果 API 長時間無回應，HTTP 請求會一直保持連線，導致額外的系統資源消耗，所以本 API 也提供了非同步回呼的支援。

整體流程是：用戶端發起請求的時候，額外指定一個 `callback_url` 欄位，用戶端發起 API 請求之後，API 會立刻回傳一個結果，包含一個 `task_id` 的欄位資訊，代表目前的任務 ID。當任務完成之後，生成任務的結果會透過 POST JSON 的形式傳送到用戶端指定的 `callback_url`，其中也包括了 `task_id` 欄位，這樣任務結果就可以透過 ID 關聯起來了。

下面我們透過範例來了解一下具體怎樣操作。

首先，Webhook 回呼是一個可以接收 HTTP 請求的服務，開發者應該替換為自己搭建的 HTTP 伺服器 URL。此處為了方便示範，使用一個公開的 Webhook 範例網站 [https://webhook.site/](https://webhook.site/)，開啟該網站即可得到一個 Webhook URL，如圖所示：

## 錯誤處理

在呼叫 API 時，如果遇到錯誤，API 會回傳相應的錯誤代碼和資訊。例如：

- `400 token_mismatched`：錯誤請求，可能是由於缺少或無效的參數。
- `400 api_not_implemented`：錯誤請求，可能是由於缺少或無效的參數。
- `401 invalid_token`：未授權，無效或缺少授權權杖。
- `429 too_many_requests`：請求過多，您已超過速率限制。
- `500 api_error`：內部伺服器錯誤，伺服器發生錯誤。

### 錯誤回應範例

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
