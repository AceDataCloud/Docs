本文將介紹一種 Veo Videos Generation API 串接說明，它是可以透過輸入自訂參數來生成 Veo 官方的影片。

## 申請流程

要使用 Veo Videos Generation API，首先到 [Ace Data Cloud 控制台](https://platform.acedata.cloud/console/applications) 取得您的 API Token，留作備用。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

如果您尚未登入或註冊，會自動跳轉到登入頁面邀請您註冊和登入，完成後會自動返回目前頁面。

**一個 API Token 即可呼叫平台所有服務，無需為每個服務單獨申請。** 首次申請會贈送免費額度，可免費體驗；額度不足時可在 [控制台](https://platform.acedata.cloud/console/coin) 儲值通用餘額。

> 📘 完整文件：[Veo Videos Generation API →](https://platform.acedata.cloud/documents/veo-videos)

## 基本使用

首先先了解一下基本的使用方式，就是輸入提示詞 `prompt`、生成行為 `action`、首尾幀參考圖片陣列 `image_urls` 以及模型 `model`，便可獲得處理後的結果，首先需要簡單地傳遞一個 `action` 欄位，它的值為 `text2video`，它主要包含三種行為：文字生成影片（`text2video`）、圖片生成影片（`image2video`）、取得 1080p 影片（`get1080p`），然後我們還需要輸入模型 `model`，目前主要有 `veo31-fast`、`veo3`、`veo31`、`veo3-fast` 和 `veo31-fast-ingredients` 模型，具體的內容如下：

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

可以看到這裡我們設定了 Request Headers，包括：

- `accept`：想要接收何種格式的回應結果，這裡填寫為 `application/json`，即 JSON 格式。
- `authorization`：呼叫 API 的金鑰，申請之後可以直接下拉選擇。

另外設定了 Request Body，包括：

- `model`：生成影片的模型，主要有 `veo31-fast`、`veo3`、`veo31`、`veo3-fast` 和 `veo31-fast-ingredients` 模型。
- `action`：此次影片生成任務的行為，主要包含三種行為，分別為：文字生成影片（`text2video`）、圖片生成影片（`image2video`）、取得 1080p 影片（`get1080p`）。
- `image_urls`：當選擇圖片生成影片行為 `image2video` 就必須需要上傳的參考圖片連結。`veo31-fast-ingredients` 最多 3 張（多圖融合），其餘模型最多 2 張（首尾幀模式）。
- `resolution`：選擇生成的影片解析度，其中 veo31 模型支援 4k 解析度，其他模型不支援，所有模型皆支援 1080p 以及 gif 解析度，不傳該值預設使用 720p 解析度，主要分為：`1080p`、`gif`、`4k`。
- `prompt`：提示詞。
- `callback_url`：需要回呼結果的 URL。
- `async`：可選，設為 `true` 時介面立即回傳 `task_id`，無需提供 `callback_url`，隨後透過對應的任務查詢介面輪詢取得結果。

### 📌 模型說明總結

| **模型名稱**                   | **支援模式**                          | **圖片輸入規則**                        |
| -------------------------- | --------------------------------- | --------------------------------- |
| **veo3-fast**              | 文字生成影片（無圖）<br />圖片生成影片 模式（有圖）           | **1 張** → 首幀模式<br />**2 張** → 首尾幀模式 |
| **veo31-fast**             | 文字生成影片（無圖）<br />圖片生成影片 模式（有圖）           | **1 張** → 首幀模式<br />**2 張** → 首尾幀模式 |
| **veo31-fast-ingredients** | ❌ 文字生成影片（不支援）<br />✅ **強制多圖融合**（必須傳圖） | **1-3 張** → 多圖融合模式（最多 3 張）        |
| **veo3**                   | 文字生成影片（無圖）<br />圖片生成影片 模式（有圖）           | **1 張** → 首幀模式<br />**2 張** → 首尾幀模式 |
| **veo31**                  | 文字生成影片（無圖）<br />圖片生成影片 模式（有圖）           | **1 張** → 首幀模式<br />**2 張** → 首尾幀模式 |

---

### 🔑 關鍵規則說明

1. **通用邏輯**：
   - **無圖片輸入** → 自動觸發文字生成影片模式。
   - **有圖片輸入** → 觸發 圖片生成影片 模式（具體行為由圖片數量決定）。
2. **圖片生成影片 模式類型**：
   - **首幀模式**（1 張圖）：首幀固定為輸入圖片。
   - **首尾幀模式**（2 張圖）：首幀和尾幀固定為輸入圖片。
   - **多圖融合模式**（1-3 張圖）：僅 `veo31-fast-ingredients` 支援，融合多圖內容生成影片。
3. **模式分類**：

  - **Fast 模式**：`veo3-fast`、`veo31-fast`、`veo31-fast-ingredients`。
   - **Quality 模式**：`veo3`、`veo31`（生成品質更高）。

---

### ⚠️ 注意事項

- **唯一強制傳圖模型**：`veo31-fast-ingredients` 必須傳入圖片（1-3 張），否則無法運行。
- **圖片數量限制**：
  - `veo31-fast-ingredients` 支援 **1-3 張**圖片輸入（多圖融合模式）。
  - 其他模型最多支援 **2 張**圖片輸入（首尾幀模式）。

## 圖生影片功能

如果想根據首尾幀圖片生成影片的話，可以將參數 `action` 設定為 `image2video`，並且輸入首尾幀圖片連結陣列 `image_urls`。

接下來我們必須填寫下一步需要擴展的提示詞來自訂生成影片，就可以指定如下內容：

- `model`：生成影片的模型，主要有 `veo31-fast`、`veo3`、`veo31`、`veo3-fast` 和 `veo31-fast-ingredients`。
- `image_urls`：當選擇圖生影片行為 `image2video` 時，就必須需要上傳的參考圖片連結。
- `prompt`：提示詞。

填寫範例如下：

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

填寫完畢之後自動生成了程式碼如下：

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

對應的 Python 程式碼：

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo31-fast",
    "prompt": "Let it dance",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## 非同步回呼

由於 Veo Videos Generation API 生成的時間相對較長，大約需要 1-2 分鐘，如果 API 長時間無回應，HTTP 請求會一直保持連線，導致額外的系統資源消耗，所以本 API 也提供了非同步回呼的支援。

整體流程是：用戶端發起請求的時候，額外指定一個 `callback_url` 欄位，用戶端發起 API 請求之後，API 會立刻回傳一個結果，包含一個 `task_id` 的欄位資訊，代表目前的任務 ID。當任務完成之後，生成影片的結果會透過 POST JSON 的形式傳送到用戶端指定的 `callback_url`，其中也包括了 `task_id` 欄位，這樣任務結果就可以透過 ID 關聯起來了。

下面我們透過範例來了解具體如何操作。

首先，Webhook 回呼是一個可以接收 HTTP 請求的服務，開發者應該替換為自己建置的 HTTP 伺服器 URL。此處為了方便示範，使用一個公開的 Webhook 範例網站 https://webhook.site/，開啟該網站即可得到一個 Webhook URL，如圖所示：

## 錯誤處理

在呼叫 API 時，如果遇到錯誤，API 會回傳相應的錯誤代碼和資訊。例如：

- `400 token_mismatched`：錯誤請求，可能是由於缺少或無效的參數。
- `400 api_not_implemented`：錯誤請求，可能是由於缺少或無效的參數。
- `401 invalid_token`：未授權，授權權杖無效或缺少。
- `429 too_many_requests`：請求過多，您已超過速率限制。
- `500 api_error`：內部伺服器錯誤，伺服器發生問題。

### 錯誤回應範例

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
