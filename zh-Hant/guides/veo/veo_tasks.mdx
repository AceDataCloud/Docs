Veo Tasks API 的主要功能是通過輸入 Veo Videos Generation API 生成的任務ID來查詢該任務的執行情況。

本文檔將詳細介紹 Veo Tasks API 的對接說明，幫助您輕鬆集成並充分利用該 API 的強大功能。通過 Veo Tasks API，您可以輕鬆實現查詢 Veo Videos Generation API 的任務執行情況。

## 申請流程

要使用 Veo Tasks API，需要先到 申請頁面 [Veo Videos Generation API ](https://platform.acedata.cloud/documents/veo-videos)申請相應的服務，然後複製 Veo Videos Generation API的任務ID，如圖所示：

<p><img src="https://cdn.acedata.cloud/txlg6g.png" width="500" className="m-auto" /></p>

最後進入Tasks API頁面 [Veo Tasks API ](https://platform.acedata.cloud/documents/veo-tasks)申請相應的服務，進入頁面之後，點擊「Acquire」按鈕，如圖所示：

![申請頁面](https://cdn.acedata.cloud/rci31i.png)

如果您尚未登錄或註冊，會自動跳轉到[登錄頁面](https://platform.acedata.cloud)邀請您來註冊和登錄，登錄註冊之後會自動返回當前頁面。

首次申請時會有免費額度贈送，可以免費使用該 API。

## 請求示例

Veo Tasks API 可以用於查詢 Veo Videos Generation API 的結果。關於怎樣使用 Veo Videos Generation API，請參考文檔 [Veo Videos Generation API ](https://platform.acedata.cloud/documents/veo-videos)。

我們以 Veo Videos Generation API 服務返回的任務ID一個為例，演示如何使用該 API。假設我們有一個任務ID：1ebe4f2b-59ba-4385-a4ea-0ce8a3fe12ed，接下來演示如何通過傳入一個任務ID來。

### 設置請求頭和請求體

**Request Headers** 包括：

- `accept`：指定接收 JSON 格式的響應結果，這裡填寫為 `application/json`。
- `authorization`：調用 API 的密鑰，申請之後可以直接下拉選擇。

**Request Body** 包括：

- `id`：上傳的任務ID。
- `action`：對任務的操作方式。

### 代碼示例

可以發現，在頁面右側已經自動生成了各種語言的代碼，如圖所示：

部分代碼示例如下：

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/veo/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1ebe4f2b-59ba-4385-a4ea-0ce8a3fe12ed",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/veo/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "1ebe4f2b-59ba-4385-a4ea-0ce8a3fe12ed",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## 錯誤處理

在調用 API 時，如果遇到錯誤，API 會返回相應的錯誤代碼和信息。例如：

- `400 token_mismatched`：錯誤的請求，可能是由於缺少或無效的參數。
- `400 api_not_implemented`：錯誤的請求，可能是由於缺少或無效的參數。
- `401 invalid_token`：未授權，無效或缺少授權令牌。
- `429 too_many_requests`：請求過多，您已超過速率限制。
- `500 api_error`：內部伺服器錯誤，伺服器出現問題。

### 錯誤響應示例
