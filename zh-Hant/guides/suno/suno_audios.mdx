隨著 AI 的應用變廣，各類 AI 程式已逐漸普及。AI 已逐漸深入到人們的工作生活方方面面。而 AI 涉及的行業也越來越多，從最初的寫作，到醫療教育，再到現在的音樂。

Suno 是一個專業高品質的 AI 歌曲和音樂創作平台，使用者只需輸入簡單的文字提示詞，即可根據流派風格和歌詞生成帶有人聲的歌曲。該 AI 音樂生成器由來自 Meta、TikTok、Kensho 等知名科技公司的團隊成員開發，目標是不需要任何樂器工具，讓所有人都可以創造美妙的音樂。

以下是模型更新的進度：

| 版本      | model           | 上線時間       | lyric 限制 | style 限制 | 歌曲最長時長 |
| ------- | --------------- | ---------- | -------- | -------- | ------ |
| v6      | chirp-v6        | 2026.09.09 | —        | —        | —      |
| v6 Wild | chirp-v6-wild   | 2026.09.09 | —        | —        | —      |
| v6 Mini | chirp-v6-mini   | 2026.09.09 | —        | —        | —      |
| v5.5    | chirp-v5-5      | 2026.03.27 | 5000     | 1000     | 8 分鐘   |
| v5      | chirp-v5        | 2025.09.23 | 5000     | 1000     | 8 分鐘   |

> 上表的 `lyric` 與 `style` 限制為自訂模式（`custom` 為 `true`）下的上限。非自訂的靈感模式（`custom` 為 `false`）只填 `prompt`，其長度上限為 500 字元（各模型一致）。

Suno 現已支援 `chirp-v6`、`chirp-v6-wild` 和 `chirp-v6-mini`。推薦使用 `chirp-v6`；舊模型名稱繼續相容。

然而 Suno 官方並沒有提供 API，AceDataCloud 提供了一套 Suno 的 API，模擬串接了 Suno 官方，可以方便快捷地生成想要的音樂。

## 申請和使用

要使用 Suno Audios Generation API，首先到 [Ace Data Cloud 控制台](https://platform.acedata.cloud/console/applications) 取得您的 API Token，留作備用。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

如果你尚未登入或註冊，會自動跳轉到登入頁面邀請你註冊和登入，完成後會自動返回目前頁面。

**一個 API Token 即可呼叫平台所有服務，無需為每個服務單獨申請。** 首次申請會贈送免費額度，可免費體驗；額度不足時可在 [控制台](https://platform.acedata.cloud/console/coin) 儲值通用餘額。

> 📘 完整文件：[Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## 基本使用

想什麼歌曲，可以任意輸入一段文字，比如我想生成一首關於聖誕的歌曲，就可以輸入 `a song for Christmas`，如圖所示：

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

可以看到這裡我們設定了 Request Headers，包括：

- `accept`：想要接收怎樣格式的回應結果，這裡填寫為 `application/json`，即 JSON 格式。
- `authorization`：呼叫 API 的金鑰，申請之後可以直接下拉選擇。

另外設定了 Request Body，包括：
- `action`：此次音樂生成任務的行為，預設是 `generate`，主要包含：`extend`、`upload_extend`、`cover`、`upload_cover`、`replace_section`、`replace_section`、`concat`、`stems`、`all_stems`、`remaster`。
- `prompt`：Suno 官方的靈感模式提示詞（`custom` 為 `false` 時生效），最大 500 字元。
- `model`：此次音樂生成任務的模型。v6 系列包含 `chirp-v6`、`chirp-v6-wild` 和 `chirp-v6-mini`；舊模型名稱繼續相容。
- `lyric`：Suno 官方的自訂模式的歌詞內容。`chirp-v3-5` 與 `chirp-v4` 最大 3000 字元；`chirp-v4-5` 及以上（含 `chirp-v5`、`chirp-v5-5`）最大 5000 字元。
- `custom`：是否採用自訂模式，預設是：`false`。
- `instrumental`：Suno 官方的靈感模式的純音樂選項。
- `title`：Suno 官方的自訂模式的音樂標題。`chirp-v3-5`、`chirp-v4` 最大 80 字元；`chirp-v4-5` 及以上最大 100 字元。
- `style`：Suno 官方的自訂模式音樂風格。`chirp-v3-5` 與 `chirp-v4` 最大 200 字元；`chirp-v4-5` 及以上（含 `chirp-v5`、`chirp-v5-5`）最大 1000 字元。
- `negative_tags`：自訂模式（`custom` 為 `true`）下希望從生成結果中排除的音樂風格或流派。
- `audio_weight`：上傳的參考音訊占比，範圍 0-1，越大越依賴參考音訊。
- `audio_id`：參考音樂的 ID。
- `overpainting_start`/`overpainting_end`：為已有純音樂補充人聲的起止時間，單位秒。
- `underpainting_start`/`underpainting_end`：為清唱加伴奏的起止時間，單位秒。
- `persona_id`：藝術家的歌曲 ID。
- `continue_at`：續寫邊界，單位為秒。例如，213.5 表示從第 3 分 33.5 秒處開始生成後續片段。`lyric` 和 `style` 只引導邊界之後的新內容，不會取代來源音訊中邊界之前的歌詞或演唱。
- `style_influence`：自訂模式下的「Style Influence」進階參數，範圍 0-1，越大越貼合所選風格。
- `replace_section_end`：替換片段的最終時間。
- `replace_section_start`：替換片段的起始時間。
- `vocal_gender`：控制男女聲偏好，女聲 `f`，男聲 `m`，4.5 及以上模型有效；為偏好項，不保證嚴格遵循。
- `weirdness`：自訂模式下的「Weirdness」進階參數，範圍 0-1，越大越有創意和實驗性。
- `duration`：期望的歌曲時長，單位秒，需為整數，取值範圍 10 到 360。該參數用於自訂模式（`custom` 為 `true`）的歌曲生成。它是一個傾向性提示而非硬性約束：模型會參考它，但不保證達到，實際成品時長以回應中的 `duration` 欄位為準，通常短於期望值。
- `lyric_prompt`：生成歌詞的 prompt，當且僅當 `custom` 為 `true` 並且 `lyric` 沒有傳入時生效。
- `callback_url`：需要回呼結果的 URL。
- `async`：可選，設為 `true` 時介面立即回傳 `task_id`，無需提供 `callback_url`，隨後透過對應的任務查詢介面輪詢取得結果。

## 自訂生成

如果想自訂生成歌詞，可以輸入歌詞：

這時候 `lyric` 欄位可以傳入類似如下內容：

```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

- lyric：歌詞文字
- custom：填寫為 `true`，代表自訂生成，該參數預設為 false，代表使用 `prompt` 生成。
- title：歌曲的標題。
- style：歌曲的風格，選填。

## 自訂歌手風格生成功能
如果想使用歌手風格來生成歌曲的話，首先透過上文的基本使用生成一首歌曲，
最後得到需要設定這個歌曲為歌手風格，然後需要進入[Suno Persona API](https://platform.acedata.cloud/documents/suno-persona)根據官方生成的音樂 ID `audio_id` 來生成一個歌手風格的 id 參數 `persona_id`，具體的參數如下圖所示：

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

填寫完畢之後自動生成了程式碼如下：

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

對應的 Python 程式碼：

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## 繼續生成功能

如果想對已經生成的 Suno 歌曲進行繼續生成的話，可以將參數 `action` 設定為 `extend`，並且輸入需要繼續生成歌曲的 ID，歌曲 ID 的取得是根據基本使用來取得，透過上文可知，這時候可以看到歌曲的 ID 為：

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> 注意，這裡的歌詞中 `id` 是生成後歌曲的 ID，如果你不知道如何生成歌曲，可以參考上文的基本使用來生成歌曲。

如果想對自己上傳的歌曲進行繼續生成的話，可以將參數 `action` 設定為 `upload_extend`，並且輸入需要繼續生成自訂上傳的歌曲 ID，歌曲 ID 的取得是使用 [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload)來取得，如下圖所示：

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

接下來必須填寫續寫片段的歌詞，並可以指定風格：

- lyric：只用於引導 `continue_at` 之後新生成片段的歌詞，不會取代來源音訊中該時間點之前的歌詞。
- custom：填寫為 `true`，代表自訂生成，該參數預設為 false，代表使用 `prompt` 生成。
- style：續寫片段的歌曲風格，選填。
- continue_at：續寫邊界，單位為秒。例如，213.5 表示從第 3 分 33.5 秒處開始生成後續片段。

> `extend` 用於接著已有歌曲往後創作，不是給整首歌曲換詞。若希望整首歌曲從頭使用新歌詞，請使用 `generate` 重新生成；若希望參考已有歌曲重新演繹，可使用 `cover`。傳入一整首新歌詞時，`continue_at` 之前的原歌詞仍不會被取代。

## 替換片段

當生成歌曲之後需要進行替換歌曲片段的單獨操作來進行二次創作時，可以對歌曲的某個片段進行替換操作。

> ⚠️ **注意**：`replace_section_result_mode` 預設為 `full_song`：系統會分別拼接 2 個新生成的候選，並回傳 2 首完整歌曲。若只需要尚未拼接的替換片段候選，請明確設定為 `candidates`，然後選取候選呼叫[音樂拼接](#音樂拼接)。

參數說明如下：

- action：內容為 `replace_section`。
- audio_id：原始歌曲（被替換的來源歌曲）的 ID。
- model: 歌曲生成模型。
- lyric: 替換後的完整歌詞（包含被替換段及其上下文，與 `prompt` 中的內容保持一致）。
- prompt：需要替換的那一段新歌詞。
- style：歌曲的風格，選填。
- replace_section_start：被替換片段在原曲中的起始時間（秒）。
- replace_section_end：被替換片段在原曲中的結束時間（秒）。
- replace_section_result_mode：回傳模式，預設為 `full_song`。`full_song` 分別拼接 2 個候選並回傳 2 首完整歌曲；`candidates` 回傳 2 個尚未拼接的候選片段。

## 控制歌曲時長

預設情況下生成的歌曲時長由模型自行決定，通常在 30 秒到 4 分鐘之間。如果需要更長或更短的成品，可以透過 `duration` 參數指定期望時長，單位是秒，取值為 10 到 360 之間的整數。

該參數用於自訂模式（`custom` 為 `true`）的歌曲生成。需要特別說明的是，`duration` 是一個**傾向性提示，而不是硬性約束**：模型在創作時會參考這個值，但不保證達到，實測中實際時長通常明顯短於期望值，同一次請求回傳的兩首歌曲時長也可能相差數倍。即使是完全相同的請求，多次提交得到的時長也可能有較大差異。因此不要把它當作精確的時長控制來使用，如果業務上需要固定時長，請在拿到成品後自行裁剪或重試。

對應的 Python 程式碼：

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

需要注意的是，請求中的 `duration` 是**期望時長**，而回應 `data` 中每首歌曲的 `duration` 欄位是該首歌曲的**實際時長**。兩者名稱相同但含義不同，實際時長不保證等於期望值。歌詞長度是影響成品時長的主要因素之一，若需要較長的成品，建議同時提供更完整的歌詞。

介面不會對 `duration` 做額外驗證，參數會原樣傳遞給模型。如果傳入了目前模式或模型不支援的取值，可能表現為該值被忽略，建議先用一次請求確認效果再批次使用。

## Inspo 靈感創作功能

Inspo 靈感創作功能可以根據 1 到 4 段完整參考音訊生成新的音樂，支援拖曳或上傳音訊作為靈感來源。API 使用現有 `inspo` action：用戶端提供公開可存取的音訊 URL，服務會自動完成參考音訊準備和創作，無需用戶端分別讀取歌詞、風格或時長再組裝請求。它不同於上文的區間取樣，也不同於複刻原曲風格的 Cover。使用時需要填寫如下參數：

- action：內容為 `inspo`。
- audio_urls：參考音訊的 URL 列表，需提供 1 到 4 個公開可存取的音訊位址。
- model：使用的模型，推薦 `chirp-v6`。
- prompt：歌詞或創作提示詞（可選）。

> 說明：參考音訊需為公開可存取的音訊檔案。若參考音訊與平台曲庫中的已知錄音完全符合，Suno 可能會因版權校驗而拒絕生成，建議使用自有或由 Suno 生成的音訊作為靈感來源。

對應的 Python 程式碼：

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
```

## 非同步回呼

由於 Suno 生成音樂的時間相對較長，大約需要 1-2 分鐘，如果 API 長時間無回應，HTTP 請求會一直保持連線，導致額外的系統資源消耗，所以本 API 也提供了非同步回呼的支援。

整體流程是：用戶端發起請求的時候，額外指定一個 `callback_url` 欄位，用戶端發起 API 請求之後，API 會立刻回傳一個結果，包含一個 `task_id` 的欄位資訊，代表目前的任務 ID。當任務完成之後，生成音樂的結果會透過 POST JSON 的形式傳送到用戶端指定的 `callback_url`，其中也包括了 `task_id` 欄位，這樣任務結果就可以透過 ID 關聯起來了。

下面我們透過範例來了解一下具體要怎樣操作。

首先，Webhook 回呼是一個可以接收 HTTP 請求的服務，開發者應該替換為自己建置的 HTTP 伺服器的 URL。此處為了方便示範，使用一個公開的 Webhook 範例網站 https://webhook.site/，開啟該網站即可得到一個 Webhook URL，如圖所示：
