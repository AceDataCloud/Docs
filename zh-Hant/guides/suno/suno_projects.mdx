`POST https://api.acedata.cloud/suno/projects` 是管理多軌工程的 Beta 介面。透過 `action` 區分建立、儲存、生成候選、提交候選和匯出。

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: <每次寫入操作的新 UUID>
```

除 `retrieve` 外，**每次操作都需要** `Idempotency-Key`。相同鍵和相同請求只回讀原結果；相同鍵搭配不同請求會傳回 409。收費生成遇到網路逾時或提交結果不確定時，先使用原任務 ID 或相同冪等鍵查詢，不能直接換鍵重送。

## 識別碼和時間單位

| 名稱                             | 從哪裡取得                                                                                      | 用在哪裡                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | `create` 回應 `data.id`                                                                      | 目前工程的所有後續請求                                      |
| `version_id`                   | 最近一次 `retrieve`、`save`、`add_track`、`commit_candidate` 或 `remove_track` 的 `data.version_id` | 修改、生成候選和匯出；必須使用最新版本                              |
| `audio_id` / `source_audio_id` | `upload` 終態 `response.data.candidate.audio_id`，或既有的已完成音訊 ID                                | `add_track`、生成或替換時參考原音訊                          |
| `render_audio_id`              | `render` 終態 `response.data.audio_id`                                                       | `generate_track` 的工程混音參考                         |
| `operation_id`                 | `generate_track` 或 `replace_section` 終態 `response.data.operation_id`                       | `commit_candidate`；通常與生成任務的 `task_id` 相同，但應讀取傳回值 |
| `candidate_id`                 | 生成終態 `response.data.candidates[].id`                                                       | 選擇一個候選提交                                         |
| `track_id`                     | 工程 `data.state.tracks[].id`                                                                | 提交候選或刪除軌道                                        |
| `task_id`                      | 非同步操作提交回應                                                                                   | 使用 `/suno/tasks` 查詢終態；它不是工程 ID                   |

`start_seconds` / `end_seconds` 是**來源音訊內的秒數**；`start_beats` / `end_beats` 是**工程時間軸上的拍數**。`state.timing.bps` 是每秒拍數，預設為 2。例如 41 秒的片段從第 0 拍開始，預設終點為第 82 拍。`generate_track` 的秒數區間用於指定生成參考，不保證候選只有該區間的長度。

## 操作流程

| 順序  | `action`                             | 作用                         | 傳回方式         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | 建立空工程                      | 同步工程資料       |
| 2   | `retrieve`                           | 讀取最新版本和完整 `state`          | 同步工程資料       |
| 3   | `save`                               | 首次儲存或整體儲存修改後的 `state`      | 同步工程資料       |
| 4   | `upload`                             | 從 HTTPS 音訊位址建立素材           | 非同步任務         |
| 5   | `add_track`                          | 將素材音訊放入工程                  | 非同步任務，更新版本    |
| 6   | `save`                               | 如需接收新軌候選，先儲存一個空目標軌道        | 同步工程資料，更新版本  |
| 7   | `render`                             | 匯出目前可聽軌道，取得混音參考 `audio_id` | 非同步任務         |
| 8   | `generate_track` 或 `replace_section` | 分別生成新軌候選或局部替換候選            | 非同步任務，暫不修改工程  |
| 9   | `commit_candidate`                   | 選擇並提交一個候選                  | 非同步任務，成功後更新版本 |
| 可選  | `remove_track`                       | 刪除指定軌道                     | 同步工程資料，更新版本  |

如果只做局部替換，既有可用來源音訊即可，不需要先 `render`；如果來源音訊已在工程中，也可略過 `upload` 和 `add_track`。`render_audio_id` 僅是 `generate_track` 的必填參考。

非同步操作提交時先傳回 `{ "task_id": "...", "trace_id": "..." }`，**不表示生成成功**。輪詢：

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步傳回的 task_id"}
```

任務記錄有 `finished_at`，且其中的 `response.success` 為 `true`，才算成功；`response.success=false` 時讀取 `response.error`。`save` 雖可能帶有 `task_id`，但它在本介面內同步完成。`upload`、`render`、`generate_track`、`replace_section` 不修改工程版本；`save`、`add_track`、`commit_candidate`、`remove_track` 成功後應取得新 `version_id`。

## 請求約定

| 參數                | 類型與適用範圍                                                                                   | 說明                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | 必填字串                                                                                     | 固定為本頁列出的其中一個操作名稱；一次請求只執行一個操作。                                      |
| `id`              | 除 `create` 外必填字串                                                                         | 工程 ID，來自 `create.data.id`。                                      |
| `version_id`      | 修改、生成候選、匯出時必填字串；首次空工程 `save` 可省略                                                         | 使用最新版本，舊版本會被拒絕。`retrieve` 不需要它。                                 |
| `Idempotency-Key` | 除 `retrieve` 外必填請求標頭，1–128 字元                                                              | 每個新操作使用新鍵；相同鍵相同請求回讀原結果，不重新生成或扣費。                                   |
| `async`           | `upload`、`add_track`、`generate_track`、`replace_section`、`commit_candidate`、`render` 可選布林值 | 這些操作始終為非同步；`false` 也不會將生成變成同步。                                    |
| `callback_url`    | 非同步操作可選 URL                                                                                | 接收終態通知；省略時依 `task_id` 查詢 `/suno/tasks`。仍須檢查 `response.success`。 |

下列範例串聯展示各操作之間的 ID 和版本傳遞。回應只列出與目前步驟有關的欄位；接入時請以目前應用程式的回應值替換範例 ID。

## 儲存工程狀態

| 參數 | 類型與說明 |
|---|---|
| `state` | 必填物件。提交**完整工程狀態**，不是局部修補；以最近一次讀取或修改操作回傳的 `data.state` 為基礎，保留未知欄位。 |
| `title` | 可選字串；省略時沿用 `state.title`，若也沒有則使用預設標題。 |
| `version_id` | 首次儲存新建空工程可省略；此後必須使用最新版本。 |

`state.timing.bps` 必須為正數，預設 2。`state.tracks` 是軌道陣列；已有音訊片段的 `clipId` 引用音訊 ID，`startBeats`、`endBeats`、`readStartBeats` 使用工程拍單位。最安全的編輯方式是讀取完整 `state`，只修改目標軌道或片段，再整體 `save`。新增空目標軌道至少應有唯一 `id`、`type:"audio"`、`clips:[]`；完整的空軌道結構見「生成新音軌」中的範例。不要把音訊分析結果中的拍點直接當作工程時間軸座標。

## 上傳音訊並新增軌道

| 操作 | 參數 | 類型與說明 |
|---|---|---|
| `upload` | `audio_url` | 必填 HTTPS URL，指向可公開存取且您有權使用的音訊。終態中的 `candidate.audio_id` 可用於新增軌道。 |
| `add_track` | `audio_id` | 必填字串；已完成素材的音訊 ID，不是 URL。 |
| `add_track` | `name`、`color` | 可選字串；軌道名稱預設取音訊標題，顏色建議 `#RRGGBB`，預設 `#7251F7`。 |
| `add_track` | `title` | 可選字串；同時修改工程標題，通常省略。 |
| `add_track` | `start_beats`、`end_beats` | 可選非負數字，終點須大於起點；預設從第 0 拍開始，終點依音訊時長和 `timing.bps` 計算。 |
| `add_track` | `gain` | 可選非負數字，預設 1；片段和軌道的音量係數。 |

## 生成新音軌

候選與生成時的工程版本繫結。先儲存接收候選的空軌道，再匯出目前混音作為生成參考；生成完成後選一個候選提交到該空軌道。

### 預留目標軌道：`save`

`generate_track` 的候選與目前工程版本繫結。在上一條 `add_track` 終態回傳的**完整** `state` 上，向 `state.tracks` 新增以下空軌道，再以 `save` 儲存；其他已有欄位原樣保留：

### 產生候選：`generate_track`

| 參數 | 類型與說明 |
|---|---|
| `source_audio_id` | 必填；已完成的來源音訊 ID。先將來源音訊加入工程，後續才能確定候選位置。 |
| `render_audio_id` | 必填；上述 `render` 終態中的 `response.data.audio_id`，不是音訊 URL。 |
| `model` | 必填；可選 `chirp-v3-5`、`chirp-v4`、`chirp-v4-5`、`chirp-v4-5-plus`、`chirp-v5`、`chirp-v5-5`、`chirp-v6`、`chirp-v6-wild`、`chirp-v6-mini`。具體組合是否可用以任務終態為準。 |
| `start_seconds`、`end_seconds` | 必填數字，`0 ≤ start_seconds < end_seconds`；來源音訊內的秒數區間，不是工程拍數，也不保證輸出時長。 |
| `stem_control_tags` | 必填字串；新增聲部描述，例如 `add Piano`、`add Drums`、`add Bass`，不是固定列舉。 |
| `batch_size` | 可選整數 1–4，預設為 2；候選數量。 |
| `instrumental`、`vocal_gender` | 可選；純器樂預設為 `true`，聲樂偏好可填 `f`、`m`、`unspecified`，預設為 `unspecified`。 |
| `title`、`tags`、`negative_tags`、`prompt` | 可選字串；分別是候選標題、期望風格、避開的風格、新聲部的文字或歌詞提示。 |

## 替換已有片段

`replace_section` 可以直接使用已有的來源音訊，無須先匯出混音。生成只傳回候選；提交時選擇包含唯一來源片段的原軌道。

| 參數 | 類型與說明 |
|---|---|
| `source_audio_id` | 必填；要替換的已完成來源音訊 ID。 |
| `model` | 必填；使用「生成候選」中列出的公開模型，模型與操作的可用性以任務終態為準。 |
| `start_seconds`、`end_seconds` | 必填數字，`0 ≤ start_seconds < end_seconds ≤ 來源音訊時長`；來源音訊內的秒數區間。 |
| `prompt`、`replacement_lyrics` | 可選字串；前者是原歌詞或上下文，後者是替換區間的新歌詞。 |
| `title`、`tags`、`negative_tags` | 可選字串；候選標題、期望風格和避開的風格。 |
| `fixed` | 可選布林值，預設 `false`；設為 `true` 時區間須短於 26 秒，且模型可能不支援。 |

| `studio_unavailable` / `studio_model_unavailable`（503） | 工程處理或所選模型暫時不可用。 | 保留原任務結果；稍後明確重試，不自動切換模型。 |
