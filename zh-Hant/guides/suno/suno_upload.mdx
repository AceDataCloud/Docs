SUNO 允許我們上傳參考音訊進行二次創作，本文檔講解相關 API 的串接方法。

一般上傳只需要 `audio_url`，它是一個可以公開存取的音訊 CDN 位址。`mode` 預設為 `standard`，因此現有呼叫無需修改。一般上傳成功消耗 **0.06 Credits**；上傳失敗不扣費。

這裡我們輸入的 `audio_url` 是 `https://cdn.acedata.cloud/suno_demo.mp3`，是一個可以公開存取的 CDN 位址。

```bash
curl -X POST 'https://api.acedata.cloud/suno/upload' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3"
}'
```

可以看到，`data` 始終是物件，`audio_id` 是上傳後的歌曲 ID。`lyric`、`style`、`duration`、標題和媒體 URL 等分析結果為可選欄位，具體以回傳內容為準。

有了歌曲 ID 之後，可以透過 [Suno Audios Generation API](https://platform.acedata.cloud/documents/suno-audios) 呼叫 `upload_extend`、`upload_cover` 或區間取樣等需要 `audio_id` 的操作。若要透過 Inspo 靈感創作功能，根據 1 到 4 段完整參考音訊創作新音樂，請直接呼叫 `action=inspo` 並傳入原始公開音訊 URL 清單；服務會自動完成上傳和分析，無需用戶端組裝音訊 metadata。

## 增強上傳模式

> `audio_url` 是輸入位址，會直接交給音訊處理流程，不會由終態媒體持久化服務預先轉存。請確保它在任務處理期間可公開存取。

當一般上傳無法處理您擁有或已獲授權使用的音訊時，可以設定 `mode` 為 `enhanced`。該模式還必須提供 1 至 100 個字元的 `name`，並使用公開可存取的 HTTPS `audio_url`。

增強上傳固定採用非同步處理，通常需要 2 分鐘或更長時間。成功處理消耗 **1.87 Credits**；處理失敗不扣費。

```bash
curl -X POST 'https://api.acedata.cloud/suno/upload' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3",
    "mode": "enhanced",
    "name": "My Song"
  }'
```

介面會立即回傳 `task_id` 和 `trace_id`。使用 [Suno Tasks API](https://platform.acedata.cloud/documents/suno-tasks) 查詢任務，成功後從 `response.data.audio_id` 讀取上傳後的音訊 ID。也可以提供 HTTPS `callback_url` 接收終態。

增強上傳得到的 `audio_id` 可用於 Cover、Samples 和 Mashup。伴奏與 MIDI 擷取、全軌分離以及人聲/伴奏分離仍可能受音訊所屬帳號限制；未列出的操作不保證支援跨帳號使用。音訊越短，處理成功率通常越高。
