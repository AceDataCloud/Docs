Kling Tasks API 的主要功能是透過輸入 Kling Videos Generation API 生成的任務ID來查詢該任務的執行情況。

本文檔將詳細介紹 Kling Tasks API 的串接說明，幫助您輕鬆整合並充分利用該 API 的強大功能。透過 Kling Tasks API，您可以輕鬆實現查詢 Kling Videos Generation API 的任務執行情況。

## 申請流程

要使用 Kling Videos Generation API，首先到 [Ace Data Cloud 控制台](https://platform.acedata.cloud/console/applications) 取得您的 API Token，留作備用。

![](https://cdn.acedata.cloud/dvc3cg.jpg)

如果您尚未登入或註冊，會自動跳轉至登入頁面邀請您註冊和登入，完成後會自動返回目前頁面。

**一個 API Token 即可呼叫平台所有服務，無需為每個服務個別申請。** 首次申請會贈送免費額度，可免費體驗；額度不足時可在 [控制台](https://platform.acedata.cloud/console/coin) 儲值通用餘額。

> 📘 完整文件：[Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## 請求範例

Kling Tasks API 可以用於查詢 Kling Videos Generation API 的結果。關於如何使用 Kling Videos Generation API，請參考文件 [Kling Videos Generation API ](https://platform.acedata.cloud/documents/kling-videos)。

我們以 Kling Videos Generation API 服務返回的一個任務ID為例，示範如何使用該 API。假設我們有一個任務ID：20068983-0cc9-4c6a-aeb6-9c6a3c668be0，接下來示範如何透過傳入一個任務ID來。

### 設定請求標頭和請求主體

**Request Headers** 包括：

- `accept`：指定接收 JSON 格式的回應結果，這裡填寫為 `application/json`。
- `authorization`：呼叫 API 的金鑰，申請之後可以直接下拉選擇。

**Request Body** 包括：

- `id`：上傳的任務ID。
- `action`：對任務的操作方式。

部分程式碼範例如下：

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

返回結果一共有多個欄位，request 欄位就是發起任務時的 request body，同時 response 欄位是任務完成後返回的 response body。欄位介紹如下。

- `id`，生成此影片任務的 ID，用於唯一識別此次影片生成任務。
- `request`，查詢影片任務中的請求資訊。
- `response`，查詢影片任務中的返回資訊。
- `created_at`，任務建立時間，Unix 時間戳記（秒，浮點）。
- `started_at`，任務開始執行時間，Unix 時間戳記（秒，浮點）。
- `finished_at`，任務完成時間，Unix 時間戳記（秒，浮點）。任務未完成時不返回該欄位。
- `elapsed`，任務執行耗時，單位為秒（浮點，保留 3 位小數）。任務未完成時不返回該欄位。

## 錯誤處理

在呼叫 API 時，如果遇到錯誤，API 會回傳相應的錯誤代碼和資訊。例如：

- `400 token_mismatched`：錯誤的請求，可能是由於缺少或無效的參數。
- `400 api_not_implemented`：錯誤的請求，可能是由於缺少或無效的參數。
- `401 invalid_token`：未授權，授權權杖無效或缺失。
- `429 too_many_requests`：請求過多，您已超過速率限制。
- `500 api_error`：內部伺服器錯誤，伺服器發生問題。

### 錯誤回應範例
