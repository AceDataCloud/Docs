本文將介紹如何串接 SeeDream Images Generation API，透過輸入自訂參數，即可生成 SeeDream 官方圖片。

## 申請流程

若要使用 SeeDream Images Generation API，請先前往 [Ace Data Cloud 控制台](https://platform.acedata.cloud/console/applications) 取得您的 API Token，以備後續使用。

![]()

如果您尚未登入或註冊，系統會自動跳轉至登入頁面，邀請您註冊並登入，完成後會自動返回目前頁面。

**只需一組 API Token，即可呼叫平台上的所有服務，無須為每項服務個別申請。** 首次申請時會贈送免費額度，可免費體驗；若額度不足，可前往 [控制台](https://platform.acedata.cloud/console/coin) 儲值通用餘額。

## 模型選擇

| 模型 | 適用情境 |
| ----------------------------------------------------------- | ------------------------------- |
| `doubao-seedream-5-5-261028` | 多輪編輯、文字生成透明圖片、多參考圖片透明編輯、圖層拆分與文字圖層辨識 |
| `doubao-seedream-5-0-flash-260915` | 低延遲單張圖片生成、多參考圖片編輯、透明圖片編輯與圖層拆分 |
| `doubao-seedream-5-0-pro-260628` | 單張圖片生成、精細編輯、透明圖片編輯與圖層拆分 |
| `doubao-seedream-5-0-lite-260128` | 單張圖片、組圖、串流輸出與網路搜尋 |
| `doubao-seedream-4-5-251128` / `doubao-seedream-4-0-250828` | 舊版圖片生成與編輯 |

5.5 和 5.0 Flash 使用相同的 `POST /seedream/images`，皆支援 `1K`、`1.5K`、`2K`，以及最多 10 張參考圖片。兩款模型的圖層拆分任務都只接受一張圖片，並以 URL 形式回傳結果。5.5 可設定 `layer_decomposition_options: {"max_images": 12, "text_recognition": true}`。最多可輸出 100 張圖片（包含底圖），可辨識的文字圖層會在 `data[].text_recognition` 中回傳逐行文字與樣式。5.0 Flash 最多回傳 1 張底圖和 16 個圖層。

5.5 支援使用 `background: "transparent"` 直接生成透明 PNG。5.0 Flash 的透明圖片編輯則需要一張具有透明通道的參考圖片。5.5 依據成功輸出圖片的像素級距收費，並針對每張輸入參考圖片額外收取 0.13 Credits。5.0 Flash 則依每張成功輸出的圖片收取 0.31 Credits，參考圖片免費。圖層拆分依實際成功輸出的圖片張數計費，底圖也包含在內。請參閱 [即時定價](https://platform.acedata.cloud/services/seedream?tab=pricing)。

## 基本使用方式

首先，先了解基本的使用方式，也就是輸入提示詞 `prompt`、生成動作 `action`、圖片尺寸 `size`，即可取得處理後的結果。首先，需要簡單地傳入一個 `action` 欄位，其值為 `generate`，接著還需要輸入提示詞，具體內容如下：

<p><img src="https://cdn.acedata.cloud/seedream_request_body.png" width="500" className="m-auto" /></p>

可以看到，這裡我們設定了 Request Headers，包括：

- `accept`：希望接收何種格式的回應結果，這裡填寫為 `application/json`，也就是 JSON 格式。
- `authorization`：呼叫 API 所需的金鑰，申請完成後即可直接從下拉選單中選擇。

另外，也設定了 Request Body，包括：

- `prompt`：提示詞。
- `model`：請傳入上表中的完整模型 ID。
- `image`：輸入圖片 URL、Base64 字串或陣列。5.5、5.0 Pro 和 5.0 Flash 最多支援 10 張參考圖片。
- `size`：解析度級距或 `寬x高`。5.5、5.0 Pro 和 5.0 Flash 支援 `1K`、`1.5K`、`2K`。5.0 Lite 支援 `2K`、`3K`、`4K`。
- `sequential_image_generation`：組圖：根據您輸入的內容，生成一組內容彼此相關的圖片。`doubao-seedream-5-0-lite-260128`、`doubao-seedream-4-5-251128`、`doubao-seedream-4-0-250828` 支援此參數，預設值為 `disabled`。
- `stream`：控制是否啟用串流輸出模式。`doubao-seedream-5-0-lite-260128`、`doubao-seedream-4-5-251128`、`doubao-seedream-4-0-250828` 支援此參數，預設值為 `false`。
- `response_format`：指定生成圖片的回傳格式。預設值為 `url`，也支援 `b64_json`。
- `watermark`：是否在生成的圖片中加入浮水印。預設值為 `true`。
- `output_format`：輸出格式為 `jpeg` 或 `png`。5.5 預設為 PNG，5.0 Pro/Flash/Lite 預設為 JPEG。
- `tools`：設定模型需要呼叫的工具，目前支援 `web_search`（網路搜尋）。僅 Seedream 5.0 Lite 支援。
- `optimize_prompt_options`：提示詞最佳化設定。5.0 Pro 支援 `standard`/`fast`；5.5、5.0 Flash、5.0 Lite 與 4.5 僅支援 `standard`；4.0 支援 `standard`/`fast`。
- `background`：支援 `transparent` 和 `opaque`。5.5 另外支援 `auto`。透明輸出使用 PNG 格式。
- `layer_decomposition`：5.5、5.0 Pro 和 5.0 Flash 支援。設定為 `true` 時，必須輸入一張 PNG/JPEG 圖片，可以不傳入 `prompt`，讓系統自動拆分圖層，也可以使用自然語言或 `<bbox>` 指定元素；`size` 支援 `auto`/`1K`/`1.5K`/`2K`。此模式無法與組圖、串流、網路搜尋或 `background` 同時使用。
- `callback_url`：需要接收回呼結果的 URL。
- `async`：是否以非同步模式處理。設定為 `true` 時，介面會立即回傳 `task_id`，無須提供 `callback_url`，之後可透過 `/seedream/tasks` 輪詢取得結果。

選擇完成後，可以發現右側也會產生對應的程式碼，如圖所示：

回傳結果共有多個欄位，介紹如下：

- `success`，此時影片生成任務的狀態。
- `task_id`，此時影片生成任務 ID。
- `trace_id`，此時影片生成追蹤 ID。
- `data`，此時圖片生成任務的結果清單。

  - `prompt`，提示詞。
  - `size`：生成圖片的像素尺寸。

可以看到，我們取得了令人滿意的圖片資訊，只需要根據結果中 `data` 的圖片連結網址，即可取得生成的 SeeDream 圖片。

另外，如果想生成對應的串接程式碼，可以直接複製生成，例如 CURL 的程式碼如下：

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "doubao-seedream-5-0-lite-260128",
  "prompt": "A single matte blue cube centered on a clean white studio background, neutral lighting"
}'
```

## 編輯圖片任務

如果想編輯某張圖片，首先必須在參數 `image` 中傳入需要編輯的圖片連結。

- model：傳入上表中支援圖片編輯的完整模型 ID。
- image：上傳需要編輯的圖片，可以是一張或多張。

填寫範例如下：

<p><img src="https://cdn.acedata.cloud/seedream_edit.png" width="500" className="m-auto" /></p>

對應的程式碼：

```python
import requests

url = "https://api.acedata.cloud/seedream/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedream-4-0-250828",
  "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
  "image": ["https://ark-project.tos-cn-beijing.volces.com/doc_image/seedream4_5_imageToimage.png"],
  "size": "2K",
  "watermark": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

點擊執行後，可以發現系統會立即產生結果，如下：

## 圖層拆分（Seedream 5.0 Pro）

圖層拆分會將一張輸入圖片拆分為 1 張底圖，以及最多 16 個可獨立編輯的透明 PNG 圖層。以下請求會讓模型自動識別主要元素；如需指定元素，可以新增 `prompt`，也可以在提示詞中使用正規化的 `<bbox>` 座標。

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "https://example.com/poster.png",
  "layer_decomposition": true,
  "size": "2K",
  "watermark": false
}'
```

回傳的 `data` 會依照 `z_index` 從底層到頂層排列。底圖的 `z_index` 為 0；圖層還包含 `name`、`description` 和 `bounding_box.absolute`/`normalized`。使用絕對座標重新組合時，將圖層縮放至 `[right-left, bottom-top]`，放置於 `[left, top]`，再依照 `z_index` 升冪順序疊放。只要任一圖層生成失敗，整次拆分作業就會失敗。

## 串流輸出

Lite/4.x 設定 `stream: true` 時，請求標頭使用 `accept: application/x-ndjson`。介面會逐行回傳 `image_generation.partial_succeeded` 或 `image_generation.partial_failed`，最後回傳唯一的 `image_generation.completed` 事件及最終 `usage`；只有完成事件會觸發一次計費。串流模式不能與 `async` 或 `callback_url` 同時使用。

## 非同步回呼

由於 SeeDream Images Generation API 的生成時間相對較長，大約需要 1-2 分鐘，如果 API 長時間沒有回應，HTTP 請求就會持續保持連線，導致額外的系統資源消耗，因此本 API 也提供非同步回呼功能。

整體流程如下：用戶端發起請求時，額外指定一個 `callback_url` 欄位。用戶端發出 API 請求後，API 會立即回傳一個結果，其中包含 `task_id` 欄位資訊，代表目前的任務 ID。當任務完成後，生成圖片的結果會透過 POST JSON 的形式傳送至用戶端指定的 `callback_url`，其中也包含 `task_id` 欄位，如此一來，就可以透過 ID 將任務結果關聯起來。

如果沒有可供回呼的公開網路位址，也可以不指定 `callback_url`，而是在請求中將 `async` 欄位設定為 `true`。此時介面同樣會立即回傳 `task_id`，但不會推送結果，你需要攜帶該 `task_id` 呼叫 `/seedream/tasks` 介面，輪詢任務狀態以取得最終結果。

接下來，我們透過範例來了解具體的操作方式。

## 錯誤處理

在呼叫 API 時，如果遇到錯誤，API 會傳回相應的錯誤代碼和資訊。例如：

- `400 token_mismatched`：錯誤的請求，可能是缺少或包含無效的參數。
- `400 api_not_implemented`：錯誤的請求，可能是缺少或包含無效的參數。
- `401 invalid_token`：未經授權，授權權杖無效或缺失。
- `429 too_many_requests`：請求過多，您已超出速率限制。
- `500 api_error`：伺服器內部錯誤，伺服器發生異常。

### 錯誤回應範例

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
