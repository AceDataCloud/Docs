## 動態模型目錄

可先開啟 [模型目錄](https://platform.acedata.cloud/models) 查看目前模型名稱，例如 `claude-opus-5`、`gpt-6-sol`。需要確認 Coding 憑證和 API 協定是否相符時，使用有效的 Coding Application 憑證請求：

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_TOKEN"
```

模型目錄會持續變化，本文不維護固定數量或靜態模型清單。回應中每個項目的 `id` 是可直接傳給 API `model` 參數的**模型名稱**，例如 `{"id":"deepseek-v4-pro"}` 對應填寫 `deepseek-v4-pro`；它不是服務、API 或 Application 的 UUID。`/v1/models` 回傳全域模型目錄，不會依 Coding 憑證自動裁剪；設定前仍需與憑證 API scope、所選協定和用戶端相容範圍交叉確認。

## 常見排查

- **餘額不足**：進入 [Applications 控制台](https://platform.acedata.cloud/console/applications)，找到 Coding Application 並主動續購。
- **用戶端仍請求原始位址**：確認設定屬於啟動用戶端的同一使用者和工作區，並完全結束後重新啟動用戶端。
- **模型名稱不可用**：重新請求 `/v1/models`，核對填寫的模型名稱是否與目錄中的 `id` 完全一致、憑證 API scope 和用戶端支援的協定。
- **Token 無法呼叫介面**：確認憑證屬於 Coding Application，並檢查 `allowed_api_ids` 和應用程式 API 權限。
