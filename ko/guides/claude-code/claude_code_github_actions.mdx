## 1. API Key 가져오기

[Ace Data Cloud 애플리케이션 목록](https://platform.acedata.cloud/console/applications)을 열고 사용 가능한 애플리케이션에 들어가 API Key를 복사합니다.

![Ace Data Cloud API Key 가져오기](https://cdn.acedata.cloud/dvc3cg.jpg)

대상 GitHub 저장소의 **Settings → Secrets and variables → Actions**에서 Secret을 새로 만듭니다:

```text
ACEDATACLOUD_API_KEY
```

## 2. GitHub App 설치

[Claude GitHub App](https://github.com/apps/claude)을 설치하고 대상 저장소에 권한을 부여합니다. 이 공식 App은 고정된 전체 권한 세트를 요청합니다. 그 중 Claude Code Action은 실제로 Contents, Issues 및 Pull requests 권한을 사용하며, GitHub 설치 페이지에서 이 세 가지 항목만 선택할 수는 없습니다. 조직에서 최소 권한을 요구하는 경우 공식 문서에 따라 사용자 정의 GitHub App을 생성하십시오.

## 3. Workflow 추가

`.github/workflows/claude.yml`을 생성합니다:

```yaml
name: Claude Code

on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]

jobs:
  claude:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: write
      actions: read
      id-token: write
    env:
      ANTHROPIC_BASE_URL: https://api.acedata.cloud
      ANTHROPIC_CUSTOM_HEADERS: "Authorization: Bearer ${{ secrets.ACEDATACLOUD_API_KEY }}"
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: dummy-not-used
```

`claude-code-action`은 비어 있지 않은 `anthropic_api_key` 입력이 필요합니다. 여기의 자리 표시자는 플랫폼 인증에 사용되지 않습니다. `ANTHROPIC_CUSTOM_HEADERS`는 Ace Data Cloud에 필요한 Bearer Header로 덮어쓰며, 실제 Key는 GitHub Secret에서만 가져옵니다.

## 4. 검증

Workflow를 제출한 후, Issue 또는 PR 댓글에 다음을 전송합니다:

```text
@claude Reply only OK
```

성공하면 Actions workflow가 완료되고 해당 Issue/PR에 결과가 업데이트됩니다. Action이 자격 증명이 부족하다고 알리면 `dummy-not-used`가 여전히 존재하는지 확인하십시오. 401 오류가 발생하면 `ACEDATACLOUD_API_KEY` Secret을 확인하십시오. 로그에 Secret을 출력하지 마십시오. 필요에 따라 `claude_args`를 사용하여 `--max-turns`를 설정하거나 현재 사용 가능한 모델을 선택할 수 있지만, 템플릿에 연결된 모델은 고정되지 않습니다.
