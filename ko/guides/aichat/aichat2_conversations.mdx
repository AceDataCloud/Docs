AI Chat v2 API（`/aichat2/conversations`）는 차세대 대화 인터페이스로, [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations)의 전면적인 업그레이드 버전입니다. v1의 간결하고 호스팅 방식의 다중 턴 대화를 기반으로 다음과 같은 기능이 확장되었습니다.

- **멀티모달 사용자 입력**：구조화된 `message` 필드를 통해 텍스트 + 이미지 + 파일 블록을 직접 전달할 수 있으며, 먼저 `references`를 사용하여 간접적으로 첨부할 필요가 없습니다.
- **Agent 기반 도구 호출**：인터넷 검색, 웹페이지 가져오기, 파일 읽기 등의 도구가 내장되어 있으며, 사용자가 권한을 부여한 MCP 서버（Google Drive、Notion、Slack、GitHub 등）도 연결할 수 있습니다. 모델은 한 번의 요청에서 여러 차례 자율적으로 도구를 호출하여 복잡한 작업을 완료할 수 있습니다.
- **구조화된 스트리밍 이벤트**：`accept: text/event-stream` 또는 `application/x-ndjson`을 통해 토큰 단위의 `text_delta`、`tool_use`、`tool_result`、`thinking`、`citation`、`card`、`artifact` 등의 이벤트를 가져올 수 있어 프런트엔드에서 해당 유형에 따라 각각 렌더링하기 편리합니다.
- **중단 및 복구 가능**：모델이 사용자에게 추가 정보가 필요할 때 `ask_user_question` 이벤트를 전송하고 일시 중지합니다. 다음 호출에서 `tool_results`를 통해 답변을 다시 전달하면 계속 진행할 수 있습니다.
- **새로운 CRUD 작업**：동일한 endpoint에서 `action` 필드를 통해 `retrieve` / `retrieve_batch` / `update` / `delete` 작업을 수행할 수 있으므로 별도의 세션 관리 API가 필요하지 않습니다.
- **지속적으로 업데이트되는 모델 목록**：기본적으로 GPT-5.4、Claude Opus 4.8、Claude Sonnet 4.6、Gemini 3.1 Pro、GLM 5.1、DeepSeek V4、Kimi K3 등의 최신 모델을 지원합니다.

동시에 요청 본문 수준에서 **v1과 완벽하게 하위 호환됩니다**：`model` + `question`（+ 선택 사항인 `stateful` / `id` / `references` / `preset`）만 전달하면 v1과 동일한 `{answer, id}` JSON 응답을 받을 수 있으므로 `/aichat/conversations`에서 마이그레이션할 때 클라이언트를 다시 작성할 필요 없이 경로만 `/aichat2/conversations`로 변경하면 됩니다.

> 현재 `/aichat/conversations`를 사용하고 있다면 기존 인터페이스도 계속 제공되므로 자신의 일정에 맞춰 마이그레이션할 수 있습니다.

## 신청 절차

AI Chat v2 API를 사용하려면 먼저 [Ace Data Cloud 콘솔](https://platform.acedata.cloud/console/applications)로 이동하여 API Token을 발급받아 따로 보관하세요.

이미지에 표시된 인터페이스:

- All Applications：모든 애플리케이션
- My Applications：내 애플리케이션
- Authorized to Me：내게 권한이 부여된 애플리케이션
- General Application：일반 애플리케이션
- Applies to all API services with unified key and balance management. Automatically tops up dedicated applications when their balance runs low.：통합 키 및 잔액 관리 기능을 통해 모든 API 서비스에 적용됩니다. 전용 애플리케이션의 잔액이 부족해지면 자동으로 충전합니다.
- Credits：크레딧
- App ID：애플리케이션 ID
- API KEY：API 키
- Use this key to call the API service：이 키를 사용하여 API 서비스를 호출합니다.
- View Code：코드 보기
- Usage：사용량
- Manage Keys：키 관리
- Auto Recharge：자동 충전
- Authorize：권한 부여
- Top Up：충전

아직 로그인하거나 가입하지 않은 경우 자동으로 로그인 페이지로 이동하여 가입 및 로그인을 요청하며, 완료 후 자동으로 현재 페이지로 돌아옵니다.

**하나의 API Token으로 플랫폼의 모든 서비스를 호출할 수 있으며, 각 서비스마다 별도로 신청할 필요가 없습니다.** 최초 신청 시 무료 사용량이 제공되어 무료로 체험할 수 있으며, 사용량이 부족한 경우 [콘솔](https://platform.acedata.cloud/console/coin)에서 일반 잔액을 충전할 수 있습니다.

## 기본 사용법

가장 간단한 사용법은 v1과 완전히 동일합니다：`model` + `question`을 전달하고 `{answer, id}`를 받습니다.

CURL 예제：

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

반환 결과：

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Python 예제：

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

사용 가능한 `model` 값은 오른쪽 Try 패널의 드롭다운에서 직접 확인할 수 있으며, 자주 사용하는 카테고리는 다음과 같습니다.

## 다중 턴 대화

v1과 마찬가지로 `stateful: true`를 전달하여 세션 저장을 활성화하면 API가 `id`를 반환합니다. 이후 요청에 동일한 `id`를 다시 전달하면 직접 대화를 계속할 수 있으므로 messages 기록을 직접 관리할 필요가 없습니다.

첫 번째 요청：

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

반환：

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

두 번째 요청에서는 동일한 `id`를 전달합니다：
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "내가 방금 기억하라고 한 숫자는 무엇인가요?"
  }'
```

```json
{
  "answer": "당신이 기억하라고 한 숫자는 42입니다.",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful`의 기본값은 `true`이며, 생략하는 것과 명시적으로 `true`를 전달하는 것은 동일합니다. `stateful: false`로 설정하면 이전 대화 기록을 불러오지 않습니다. 이는 이번 라운드의 결과가 저장되지 않는다는 의미가 아니며, 일시 중지 후 계속 진행해야 하는 도구 워크플로에는 적용되지 않습니다.

### 긴 대화와 원문 보존

컨텍스트 압축은 이번 라운드에서 모델에 전송되는 내용만 정리하며, 이미 저장된 채팅 기록을 대체하지 않습니다. `action: retrieve`를 통해 여전히 저장된 전체 메시지를 읽을 수 있으며, 대화를 명시적으로 편집하거나 삭제하는 작업도 요청대로 적용됩니다.

모델은 현재 대화 내에서 과거 원문을 검색하고 페이지 단위로 읽을 수 있습니다. 글을 계속 수정하거나, 숫자를 인용하거나, 게시를 준비할 때는 해당 원문을 읽어야 하며, 본문을 요약으로 대체해서는 안 됩니다. 이 기능은 이전 버전에서 이미 손실된 메시지를 자동으로 복원하지 않습니다.

컨텍스트 정리에 실패하면 대화 ID를 보존하고 `error` 이벤트를 확인하세요. 서비스는 빈 요약으로 원문을 덮어쓰지 않습니다. 실패 전에 완료된 도구 작업은 여전히 유효할 수 있으므로, 중복 생성이나 중복 게시를 방지하기 위해 먼저 해당 작업의 결과를 조회하세요. 단일 대화가 저장 용량 한도에 도달하면 명확한 오류가 반환되며, 기존 저장 기록은 내용을 잘라내어 공간을 확보하지 않습니다. 필요한 내용을 내보낸 후 새 대화를 시작할 수 있습니다.

## 스트리밍 응답

v2는 두 가지 스트리밍 형식을 지원하며, `accept` 헤더에 따라 선택합니다.

| 상황                    | `accept`               | 데이터 형식                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| 웹 프런트엔드 / EventSource  | `text/event-stream`    | `data: {json}\n\n`, 마지막 줄은 `data: [DONE]\n\n` |
| 서버 / CLI / Node 스트리밍 파싱 | `application/x-ndjson` | 한 줄당 하나의 JSON 객체                               |
| 스트리밍이 필요하지 않은 경우                 | `application/json`(기본값) | 한 번에 `{answer, id}` 반환                       |

### NDJSON 예제

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "세 문장으로 항저우를 소개해 주세요.",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # v1과의 호환성을 위해 증분 조각을 delta_answer 필드로도 제공
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

NDJSON의 각 줄은 구조화된 이벤트이며, 가장 일반적인 이벤트는 `text_delta`입니다.

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### SSE 예제

브라우저 측의 `EventSource`는 사용자 지정 요청 본문을 지원하지 않으므로, `fetch`와 `\n\n`을 기준으로 수동 분할하는 파싱 방식을 사용하는 것이 좋습니다.

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "세 문장으로 항저우를 소개해 주세요.",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### 스트리밍 이벤트 유형

| `type`              | 의미                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | 어시스턴트 답변의 증분 텍스트 조각입니다. `content`는 새로 추가된 내용입니다. v1과의 호환성을 위해 동일한 이벤트에 `delta_answer`(`content`와 동일)와 `id`도 포함됩니다. |
| `thinking`          | 모델의 사고 과정입니다(선택한 모델이 reasoning을 노출하는 경우에만 나타남).                                                                                      |
| `tool_use`          | 모델이 도구 호출을 결정했으며, 이벤트에 `tool_id`, `tool_name`, `input`이 포함됩니다.                                                                        |
| `tool_result`       | 도구 실행 결과입니다. 이전 `tool_use`와 `tool_id`를 통해 연결되며, `is_error`는 실패 여부를 나타냅니다.                                                             |
| `card`              | 도구가 생성한 구조화된 카드(예: 이미지, 링크 미리보기)로, 바로 렌더링하기에 적합합니다.                                                                                          |
| `citation`          | 해당 텍스트 조각의 인용 출처 URL을 보충하는 데 사용됩니다.                                                                                                  |
| `ask_user_question` | 모델이 사용자에게 추가 정보를 요청할 때 발생하며, 대화는 `awaiting_user_input` 상태로 전환됩니다. 자세한 내용은 아래의 [일시 중지된 대화 재개](#일시-중지된-대화-재개)를 참조하세요.                                                 |
| `artifact`          | 모델이 생성한 독립적인 결과물(예: 코드 블록, 문서)로, 저장하거나 다운로드할 수 있습니다.                                                                                            |
| `system_message`    | 시스템 안내 메시지(사용자 및 어시스턴트 콘텐츠가 아님)로, UI 안내에만 사용됩니다.                                                                                           |
| `compact`           | 모델 컨텍스트가 정리되었음을 나타냅니다. 저장된 원본 메시지는 변경되지 않으므로 클라이언트에서 채팅 기록을 삭제할 필요가 없습니다.                                                                                    |
| `error`             | 이번 라운드에서 오류가 발생했으며, `message`에 오류 내용이 설명됩니다.                                                                                              |
| `done`              | 이번 라운드의 최종 대화 기록이 성공적으로 저장되었음을 나타냅니다. `usage`(`prompt_tokens` / `completion_tokens` / `total_tokens` 포함)와 `terminal_reason`이 함께 제공됩니다. 작업 완료 여부는 여전히 종료 사유에 따라 판단해야 합니다. |
최종 답변에만 관심이 있는 클라이언트의 경우, 모든 `text_delta`의 `content`를 이어 붙인 결과는 `application/json` 모드의 `answer`와 동일합니다.

## 멀티모달 입력

사용자 입력에 이미지나 파일이 포함된 경우, `question` 대신 `message`(배열)를 전달합니다. 배열의 각 요소는 하나의 콘텐츠 블록입니다.

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "이 이미지에는 고양이가 몇 마리 있나요?" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

지원되는 블록 유형:

- `text` — 일반 텍스트이며, `text` 필드가 필수입니다.
- `image_url` — 이미지이며, `image_url.url`이 필수입니다.
- `file_url` — 파일(PDF, CSV, TXT 등)이며, `file_url.url`이 필수입니다.

### v1 `references`와의 관계

이전 클라이언트와의 호환성을 위해 v2에서도 `references: ["https://...", ...]` 필드를 계속 인식합니다.

- URL 확장자가 `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`인 경우 자동으로 `image_url` 블록으로 변환됩니다.
- 그 외의 확장자는 `file_url` 블록으로 변환됩니다.
- `question`도 함께 제공된 경우, 이를 `text` 블록으로 추가하여 맨 앞에 배치합니다.

따라서 v1에서 마이그레이션하면서 요청 본문을 변경하고 싶지 않다면, 경로만 `/aichat2/conversations`로 변경하면 됩니다. 기존 `references` 사용 방식은 그대로 작동합니다.

더 세밀하게 제어해야 하는 경우(예: 여러 이미지를 텍스트 사이에 배치하거나 순서가 중요한 경우)에는 `message` 배열을 직접 사용하면 됩니다.

## 도구 호출 및 MCP

v2의 핵심 개선 사항은 모델이 여러 단계의 작업을 완료하기 위해 자율적으로 도구를 호출할 수 있다는 점입니다. **이 기능은 기본적으로 활성화되어 있으며**, 클라이언트가 요청에 별도의 설정을 추가할 필요가 없습니다. 일반적인 사용 사례는 다음과 같습니다.

- 사용자가 「상하이에서 최근 새로 열린 전시회를 검색해 줘」라고 질문 → 모델이 내장 web search를 호출 → 결과를 정리하여 답변합니다.
- 사용자가 「이 PDF를 읽고 요약해 줘」라고 요청 → 모델이 file_read를 호출 → 요약을 작성합니다.
- 사용자가 이미 [Connections](https://platform.acedata.cloud/connections)에서 Google Drive / GitHub / Notion 등을 승인한 경우 → 모델이 해당 MCP 도구를 호출하여 데이터를 읽고 쓸 수 있습니다.

NDJSON / SSE 스트림에서 도구 호출은 다음 두 가지 이벤트 유형으로 표시됩니다. `tool_use`와 `tool_result`입니다.

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"상하이 2026 봄 전시회"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"현재","delta_answer":"현재","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"상하이","delta_answer":"상하이","id":"f2f4b3e8-..."}
...
```

프런트엔드에서 도구 호출 세부 정보를 표시하고 싶지 않다면 `tool_use` / `tool_result` / `card` / `citation` 유형의 이벤트를 무시하면 됩니다. 모델의 최종 출력은 여전히 `text_delta`를 통해 전달됩니다.

`max_turns`를 사용하면 이번 요청에서 모델이 도구를 자율적으로 호출할 수 있는 최대 횟수를 제한할 수 있습니다. 범위는 1–500이며, 생략하면 기본값은 500입니다. 값을 작게 설정하면(예: `max_turns: 1`) 단일 응답만 생성하도록 강제하여 도구 호출을 허용하지 않을 수 있습니다.

## 비동기 실행 및 무인 승인

호출이 알림 Webhook, CI/CD, 모니터링 시스템 또는 기타 백그라운드 작업에서 발생하는 경우, `async: true`를 설정하면 인터페이스가 즉시 작업 ID를 반환하고 백그라운드에서 계속 실행됩니다.

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "내 서비스에서 알림이 발생했습니다. 개인 WeChat을 사용하여 「AceDataCloud팀」 그룹 채팅에 알려 주세요……"
}
```

반환 예시:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

이후 `action: retrieve`와 `id`를 사용하여 대화 결과를 조회할 수 있습니다. 또는 `callback_url`을 제공하면 작업 완료 후 플랫폼이 `{ status, answer, usage, error }`를 해당 콜백 주소로 POST합니다. `callback_url`은 반드시 `http` / `https`를 사용해야 하며, `localhost` 또는 사설 IP 주소를 직접 지정할 수 없습니다.

백그라운드 작업에서는 일반적으로 확인 버튼을 클릭할 사람이 없습니다. 무인 모드에서 특정 Skill 또는 MCP Server가 전송, 게시, 쓰기 등의 작업을 수행하도록 하려면 요청 본문에 사전 승인 목록을 명시적으로 전달해야 합니다.

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "내 서비스에서 알림이 발생했습니다. 개인 WeChat을 사용하여 「AceDataCloud팀」 그룹 채팅에 알려 주세요……"
}
```

`allowed_skills`의 값은 연결된 Skill의 slug이며, `allowed_mcp_servers`의 값은 연결된 MCP Server의 slug입니다. 사전 승인 목록에 포함되지 않은 Skill / MCP Server는 무인 모드에서 미리보기, dry-run 또는 쓰기 작업 거부만 수행할 수 있습니다.

더 세밀하게 제어해야 하는 경우, 동일한 기능을 제공하는 `unattended_policy` 객체를 사용할 수도 있습니다.

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

사전 승인은 이 두 목록 자체로 결정됩니다. 목록이 비어 있으면 어떠한 기능도 승인되지 않으며, 별도의 활성화 필드는 필요하지 않습니다.

주의: 사전 승인은 「이번 요청에서 해당 기능이 무인 모드로 실행될 때 수동 확인을 생략할 수 있도록 허용한다」는 의미일 뿐입니다. 해당 Skill은 여전히 `--unattended-confirm` 또는 이에 상응하는 보안 메커니즘을 지원해야 합니다. 그렇지 않으면 계속 dry-run 모드로 실행되며, 쓰기 작업을 직접 수행하지 않습니다.

## 일시 중지된 대화 복구

일부 도구는 모델이 「사용자에게 추가 질문」을 하도록 합니다. 이때 모델은 `ask_user_question` 이벤트를 발생시키며, 대화는 `awaiting_user_input` 상태로 일시 중지됩니다.

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "생성할 보고서는 중국어와 영어 중 어느 언어로 작성하시겠습니까?",
  "options": ["중국어", "영어"],
  "id": "f2f4b3e8-..."
}
```

프런트엔드에서 이 이벤트를 카드 형태로 렌더링하여 사용자가 답변을 선택하도록 한 다음, 동일한 `id`를 사용하여 다음 요청을 시작하고 `tool_results`를 통해 답변을 다시 전달합니다.
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

요청 본문의 `tool_use_id`는 **반드시** 일시 중지 시점의 `tool_id`와 완전히 일치해야 합니다. 일치하지 않으면 400 오류가 반환됩니다. 요청에 `tool_results`가 포함되어 있으면 `question` / `message` / `references`는 모두 무시됩니다.

사용자가 해당 질문을 포기하기로 결정한 경우, 새로운 `question` / `message`를 직접 전달하면 됩니다. 플랫폼은 일시 중지된 도구 호출을 자동으로 「사용자 건너뛰기」로 표시합니다.

## 대화 관리（CRUD）

v2는 동일한 endpoint에서 `action` 필드를 통해 간편한 대화 관리 기능을 제공하므로 별도의 API를 추가로 개설할 필요가 없습니다.

### `action: retrieve` —— 대화 하나 가져오기

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

전체 대화 문서를 반환합니다（`messages` 기록, `model`, `title`, `tools_used` 등 포함）.

### `action: retrieve_batch` —— 대화 요약 목록 가져오기

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

`{ items: [...], total }`을 반환합니다. **요약에는 `messages`가 포함되지 않습니다**. 사이드바 목록을 표시하는 데 적합합니다. 사용자가 특정 대화를 클릭하면 `action: retrieve`를 사용해 해당 대화의 전체 메시지를 별도로 가져오면 됩니다.

선택적 필터링 매개변수: `user_id`、`application_id`、`model_group`、`model`.

### `action: update` —— 제목 변경 또는 기록 재작성

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "항저우 여행 계획"
}
```

`messages`도 전달할 수 있지만, 서버에서 엄격한 schema 검증을 수행합니다（접힌 `ToolUseContent` 형식이어야 함）. 조건에 부합하지 않으면 400 오류가 반환됩니다. 일반적으로 `title` 변경에만 사용하는 것을 권장합니다.

### `action: delete` —— 대화 하나 삭제하기

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

`{ id, success: true }`를 반환합니다. 삭제한 후에는 복구할 수 없으므로 호출하기 전에 확인하시기 바랍니다.

## v1에서 원활하게 마이그레이션하기

이미 [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations)를 사용하고 있다면 v2로 마이그레이션하는 데 코드 변경이 거의 필요하지 않습니다.

1. URL을 `https://api.acedata.cloud/aichat/conversations`에서 `https://api.acedata.cloud/aichat2/conversations`로 변경합니다.
2. 이전에 v1 모델 이름（예: `gpt-3.5`、`gpt-4-browsing` 등）을 전달했다면 v2로 전환할 때 최신 모델（예: `gpt-5.4`、`claude-opus-4-8`、`gemini-3.1-pro-preview` 등）로 업그레이드하는 것을 권장합니다.
3. NDJSON 스트림의 필드는 하위 호환성을 유지합니다. 각 `text_delta` 이벤트에는 여전히 `delta_answer`와 `id`가 포함되므로, 기존에 `delta_answer`를 줄 단위로 파싱하던 클라이언트는 수정할 필요가 없습니다.

마이그레이션 후에는 필요에 따라 v2의 새로운 기능（멀티모달 `message`、SSE、도구 호출、내장 `action` CRUD）을 활성화하고 단계적으로 도입하면 됩니다.

## 오류 처리

오류 응답은 다음 형식으로 통일됩니다.

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

일반적인 오류:

- `400 bad_request`: 필수 필드 누락, `tool_use_id` 불일치, `messages` schema 오류 등.
- `401 invalid_token`: `authorization` 헤더가 올바르지 않습니다.
- `404 not_found`: `action: retrieve / update / delete` 실행 시 `id`에 해당하는 대화가 존재하지 않습니다.
- `413 conversation_storage_limit`: 대화가 저장 용량 제한을 초과했으며, 기존에 저장된 기록은 덮어쓰지 않았습니다.
- `429 too_many_requests`: 요청 속도 제한이 적용되었습니다.
- `503 context_compaction_failed`: 컨텍스트 정리에 실패했으며, 기존 기록은 보존됩니다.
- `500 conversation_persist_failed`: 이번 대화의 최종 저장에 실패했습니다. 이미 텍스트를 수신했더라도 최종 기록의 저장 성공을 의미하지는 않으므로 대화 ID를 사용해 조회하시기 바랍니다.
- `500 chat_error`: 서비스가 일시적으로 사용할 수 없거나 이번 응답에서 콘텐츠가 생성되지 않았습니다（요금이 부과되지 않습니다）.

스트리밍 응답에서는 오류가 `{"type":"error","message":"..."}` 이벤트로 전송된 후 스트림이 종료됩니다. `[DONE]`은 전송이 종료되었음을 나타낼 뿐입니다. `error`가 있으면 성공으로 간주할 수 없으며, 성공을 나타내는 `done` 이벤트도 전송되지 않습니다.

## 결론

AI Chat v2 API는 v1과의 하위 호환성을 유지하면서 대화 기능을 「단일 턴 / 다중 턴 질의응답」에서 「관측 가능한 Agent 기반 대화」로 업그레이드했습니다. 멀티모달 입력, 도구 호출, 일시 중지 및 재개, 구조화된 스트리밍 이벤트, 내장 CRUD 기능을 제공합니다. 신규 연동에는 v2를 바로 사용하는 것을 권장하며, 기존 v1 연동은 단계적으로 원활하게 마이그레이션할 수 있습니다. 궁금한 점이 있으시면 언제든지 기술 지원팀에 문의해 주세요.
