Service UUID를 통해 페이지네이션 방식으로 해당 서비스에 마운트된 Proxy 엔드포인트를 반환합니다. alias만 있는 경우 먼저 [서비스 상세](https://platform.acedata.cloud/documents/platform-service-detail)를 호출하여 `id`를 가져옵니다.

## 인터페이스 개요

| 항목   | 내용                                                                     |
| --- | ---------------------------------------------------------------------- |
| 메서드  | `GET`                                                                  |
| URL | `https://platform.acedata.cloud/api/v1/services/{service_id}/proxies/` |
| 인증  | 공개, 계정 토큰 불필요                                                              |
| 페이지네이션  | `count` + `items`                                                      |

## 파라미터

| 파라미터                 | 위치    | 필수  | 설명                               |
| ------------------ | ----- | --- | -------------------------------- |
| `service_id`       | path  | 예   | Service UUID, alias는 지원하지 않음           |
| `limit` / `offset` | query | 아니요   | 페이지네이션                               |
| `ordering`         | query | 아니요   | Django 정렬 표현식; `rank` 또는 `-rank` 권장 |

```shell
export SERVICE_ID='당신의 Service ID'
curl --get "https://platform.acedata.cloud/api/v1/services/${SERVICE_ID}/proxies/" \
  --data-urlencode 'limit=100' \
  -H 'Accept: application/json'
```

## 응답 설명

목록 항목은 Proxy 모델로 직렬화되며, 온라인에서 검증된 필드에는 `id`, `service_id`, `title`, `endpoint`, `price`, `stage`, `rank`, `tags`, `metadata`, `document_id`, `service` 및 시간 필드가 포함됩니다.

- 비즈니스 진입 필드는 `path`가 아닌 `endpoint`입니다.
- 가격 필드는 `cost`가 아닌 `price`입니다.
- Service 유형이 Proxy가 아니거나 Proxy가 마운트되지 않은 경우 빈 `items`가 반환됩니다.

공개 통합은 `endpoint` 및 게시된 기능에만 의존해야 하며, 공개되지 않은 구현 세부 사항에 의존해서는 안 됩니다.
