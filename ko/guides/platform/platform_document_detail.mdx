문서 UUID 또는 alias를 통해 단일 문서의 전체 내용과 탐색 관계를 조회합니다. alias를 알고 있는 경우 먼저 목록에서 필터링할 필요 없이 직접 요청할 수 있습니다.

## 인터페이스 개요

| 항목   | 내용                                                              |
| --- | --------------------------------------------------------------- |
| 메서드  | `GET`                                                           |
| URL | `https://platform.acedata.cloud/api/v1/documents/{id_or_alias}` |
| 인증  | 공개; UUID 또는 alias를 알고 있으면 직접 읽을 수 있음                                       |

## 매개변수

- `id_or_alias`: 문서 UUID, 현재 alias 또는 `redirect_from`에 보존된 이전 alias입니다.
- `lang`: 선택적 언어 힌트이며, `Accept-Language`도 사용할 수 있습니다. 최종 콘텐츠 언어는 응답의 `content_locale`을 기준으로 합니다.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/documents/platform-token' \
  --data-urlencode 'lang=zh-CN' \
  -H 'Accept: application/json'
```

## 응답 설명

상세 정보는 단일 객체로 응답되며, 현재 다음을 포함합니다:

- `id`, `alias`, `redirect_from`, `name`, `title`, `type`, `rank`, `tags`;
- `content`, `content_mode`, `content_locale`, `content_hash`;
- `parent`, `sibling` 및 rank로 정렬된 공개 `children` 요약;
- `api` / `proxy` / `dataset` / `integration` 연결 및 `agent`(존재하는 경우).

응답에는 `breadcrumbs` 필드가 없습니다. 브레드크럼을 구성할 때는 `parent`에서 해당 상세 정보를 계속 조회하거나, 캐시된 문서 디렉터리 관계를 사용할 수 있습니다.

## 오류 처리

- ID/alias가 존재하지 않거나 현재 사이트 가시성에 부합하지 않는 경우: `404`. `private`는 목록 가시성만 제어하며, 링크를 아는 사람이 직접 읽는 것을 막지 않으므로 기밀 경계로 사용할 수 없습니다.
- 현재 라우트는 후행 슬래시가 없는 형식을 사용합니다. 프록시 계층이 자동으로 슬래시를 추가하는 것에 의존하지 마십시오.
