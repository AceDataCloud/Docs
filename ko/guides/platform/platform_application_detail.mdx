Application ID를 통해 단일 서비스 신청의 전체 상태를 조회합니다. 목록 인터페이스보다 `service` 전체 객체(`packages` 패키지 포함) 등의 필드가 추가로 제공되며, 상세 페이지에 적합합니다.

> ℹ️ 본 인터페이스는 **AceDataCloud 플랫폼 관리 API**에 속하며, 공통 접두사는 `https://platform.acedata.cloud/api/v1/`입니다. 전체 인터페이스 색인은 [AceDataCloud 플랫폼 문서 목록 조회](https://platform.acedata.cloud/documents/platform-document-list)를 참조하세요.

## 인터페이스 개요

| 항목  | 내용                                                                    |
| --- | --------------------------------------------------------------------- |
| 메서드 | `GET`                                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/{application_id}` |
| 인증  | ✅ 계정 토큰 필요                                                              |

`/applications/{id}`와 `/applications/{id}/`는 현재 모두 사용할 수 있습니다. 예제에서는 끝 슬래시가 없는 형식을 통일하여 사용합니다.

## 인증 설명(계정 토큰 획득 방법)

요청 헤더:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

자세한 획득 방법은 [AceDataCloud 플랫폼 계정 토큰 관리](https://platform.acedata.cloud/documents/platform-token)를 참조하세요.

> ℹ️ 목록 인터페이스와 달리, **상세 인터페이스의 권한 검증은 단일 객체에 직접 수행**되므로 `?user_id=`를 전달할 필요가 없습니다. 하지만 다른 사람의 신청에 접근하면 `403 permission_denied`를 받게 됩니다.

## 경로 매개변수

| 매개변수               | 유형   | 필수  | 설명             |
| ---------------- | ---- | --- | -------------- |
| `application_id` | UUID | ✅   | Application ID |

## 요청 예제

### cURL

```shell
curl 'https://platform.acedata.cloud/api/v1/applications/82f57141-2323-4453-8730-60f7d833a2da' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

app_id = "82f57141-2323-4453-8730-60f7d833a2da"
resp = requests.get(
    f"https://platform.acedata.cloud/api/v1/applications/{app_id}",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}",
    },
    timeout=10,
)
app = resp.json()
print(f"서비스: {app['service']['title']}")
print(f"남은 {app['remaining_amount']} {app['service']['unit']} / 사용됨 {app['used_amount']}")
```

### Node.js

```javascript
const appId = '82f57141-2323-4453-8730-60f7d833a2da'
const r = await fetch(`https://platform.acedata.cloud/api/v1/applications/${appId}`, {
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log(await r.json())
```

## 응답 필드 설명

필드 의미는 [목록 인터페이스](https://platform.acedata.cloud/documents/platform-application-list)와 같으며, 다음 항목이 추가로 포함됩니다.

| 필드        | 유형     | 설명                                                        |
| --------- | ------ | --------------------------------------------------------- |
| `service` | object | 전체 서비스 객체(`packages` 패키지, `unit`, `free_amount` 포함)로, 서비스 상세 패널을 직접 렌더링할 수 있습니다 |

## 오류 처리

| HTTP | code                | 의미                  |
| ---- | ------------------- | ------------------- |
| 401  | `not_authenticated` | 계정 토큰 누락              |
| 403  | `permission_denied` | 해당 Application은 본인 소유가 아님  |
| 404  | `not_found`         | Application이 존재하지 않거나 삭제됨 |

## 실용 팁

- **대량 모니터링에는 목록을 우선 사용**: 한 번에 Application 목록을 가져온 후 각 서비스의 단위와 임계값에 따라 판단하여, 상세 정보를 하나씩 요청하는 것을 피하세요.
- **자격 증명 수를 확인해야 할 때**: [API 자격 증명 목록](https://platform.acedata.cloud/documents/platform-credential-list)을 사용하여 `application_id`로 필터링하세요.
- **`disabled=true` 문제 해결 방향**: 티켓 / 이메일 알림을 확인하여 리스크 관리, 미납, 위반 호출로 인해 중지되었는지 확인하세요. API를 통해 해제할 수 없으며, 반드시 고객 서비스에 문의해야 합니다.
