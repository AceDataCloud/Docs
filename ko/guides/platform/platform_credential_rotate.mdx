기존 Credential에 대해 새로운 Token 또는 비밀번호를 생성합니다. 자격 증명 ID, Application 연결, 한도 및 기타 필드는 변경되지 않으며, 이전 비밀은 즉시 무효화됩니다.

> 교체는 여전히 이전 비밀을 사용하는 클라이언트를 중단시킵니다. 쓰기 작업을 실행하기 전에 안전한 배포 및 롤백 방안을 준비하세요.

## 인터페이스 개요

| 항목   | 내용                                                                          |
| ---- | --------------------------------------------------------------------------- |
| 메서드   | `POST`                                                                      |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}/rotate/` |
| 인증   | Account Token                                                               |
| Body | 없음 또는 `{}`                                                                     |

[자격 증명 목록](https://platform.acedata.cloud/documents/platform-credential-list)에서 `credential_id`를 가져옵니다:

```shell
export PLATFORM_TOKEN='귀하의 계정 토큰'
export CREDENTIAL_ID='교체할 Credential ID'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/credentials/${CREDENTIAL_ID}/rotate/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

성공하면 업데이트된 Credential을 반환합니다. `type=Token`인 경우 새로운 `token`을 읽고, `type=Identity`인 경우 새로운 `password`를 읽습니다. 전체 응답을 비밀로 처리하고 호출자를 즉시 업데이트하세요.

## 오류 처리

- `401`: Account Token이 유효하지 않습니다.
- `403`: 해당 자격 증명을 관리할 권한이 없습니다.
- `404`: Credential ID가 존재하지 않습니다.
