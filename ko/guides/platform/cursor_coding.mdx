커서는 현재 OpenAI API Key와 **Override OpenAI Base URL** 설정을 제공하여 OpenAI 호환 서비스에 연결할 수 있습니다. 이 기능은 존재하지만, 서로 다른 버전에서 `/chat/completions`, `/responses`, 모델 목록 및 Agent/Composer 등의 처리 방식이 완전히 일치하지 않습니다.

서로 다른 커서 버전, 운영 체제 및 요청 모드의 호환 범위는 다를 수 있습니다. 이 페이지의 구성을 따라 실제 모드 검사를 완료하고, 단일 채팅 성공을 기반으로 모든 기능이 사용 가능하다고 추론하지 마십시오.

## 커서 공식 BYOK 현재 보장 사항

[커서 공식 Bring your own API key 문서](https://cursor.com/help/models-and-usage/api-keys)에 따르면:

- OpenAI, Anthropic, Google, Azure OpenAI 및 AWS Bedrock의 자격 증명을 지원합니다;
- 사용자 정의 API Key는 채팅 모델에만 사용되며, Tab completion은 계속해서 커서 내장 모델을 사용합니다;
- API Key는 커서 서버에 지속적으로 저장되지 않지만, 매 요청 시 Key가 커서 백엔드로 전송되어 최종 프롬프트 빌딩에 사용됩니다;
- 자체 Key를 사용할 경우, 커서의 Zero Data Retention 정책이 적용되지 않으며, 데이터 처리는 선택한 제공자의 정책을 따릅니다.

## 구성

1. 커서 설정 → 모델을 엽니다.
2. OpenAI API Key에 당신의 에이스 데이터 클라우드 API 토큰을 입력합니다.
3. **Override OpenAI Base URL**을 활성화하고 `https://api.acedata.cloud/v1`을 입력합니다.
4. 현재 커서 프로토콜과 호환되는 정확한 모델 ID를 선택하거나 추가합니다.
5. 먼저 `Reply only OK`를 전송한 후, 실제 사용하는 Ask/Edit/Agent 모드를 각각 테스트합니다.

## 현재 경계

- 사용자 정의 API Key는 채팅 모델에만 사용되며, Tab completion은 계속해서 커서 내장 모델을 사용합니다.
- 커서는 여전히 서버 측에서 최종 프롬프트 빌딩을 완료할 수 있습니다; 공식 개인정보 보호 설명서를 참고하여 데이터 경로를 평가하십시오.
- Base URL Override는 일부 요청만 덮어쓸 수 있으며, 버전 변경으로 인해 Chat Completions/Responses 간에 전환될 수 있습니다.
- 단일 채팅 요청이 성공했다고 해서 Agent, Auto, Composer 또는 백그라운드 작업이 모두 연결되었다고 주장해서는 안 됩니다.

## 현재 선택 가능한 옵션

코딩 플랜을 사용할 때, 명확한 구성 계약과 검증 접근 권한이 있는 클라이언트를 우선 선택하십시오:

- [클로드 코드 구성 개요](https://platform.acedata.cloud/documents/claude-code-integration)
- [코덱스 구성 개요](https://platform.acedata.cloud/documents/codex-integration)
- [워크버디 구성](https://platform.acedata.cloud/documents/development_workbuddy)

## 완전 호환성 검사

생산 워크플로에서 장기적으로 사용하려면 다음 검사를 동시에 완료하십시오:

1. 고정된 커서 버전과 운영 체제;
2. 해당 버전에서 실제 클라이언트 스모크를 완료하고 최종 요청 프로토콜 및 경로를 기록합니다;
3. 정확한 모델의 Chat Completions 요청이 성공합니다;
4. 도구 호출 및 Agent 요청이 실제로 목표 엔드포인트를 통과합니다;
5. 사용량 및 요금이 확인 가능합니다;
6. 요청이 커서 서버를 통과했는지 및 해당 개인정보 제한을 명확히 기록합니다.

클라이언트 업그레이드 후에는 이러한 검사를 다시 수행하여 요청 프로토콜, 도구 호출 및 데이터 경로에 변화가 없음을 확인해야 합니다.
