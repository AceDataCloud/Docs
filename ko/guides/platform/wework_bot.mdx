자신만의 기업 위챗 계정 인스턴스를 배포하고, 휴대폰 기업 위챗으로 QR 코드를 스캔해 로그인하며, REST API 또는 MCP를 통해 계정, 연락처, 대화 및 로컬 동기화 메시지를 읽습니다. 인스턴스는 일반 기업 위챗 계정에 대응하며, 프라이빗 서버나 기업 이메일 도메인 설정이 필요하지 않습니다.

현재 Alpha입니다. 계정 읽기는 실제 대화 검증을 완료했으며, 본인 텍스트 전송 및 이벤트 읽기 회수는 실제 검수를 완료했습니다. 기타 연락처, 그룹 작업 및 새 인스턴스 복구는 아직 배포 환경 검수를 완료해야 합니다. 미디어 전송, 인용 답장, 실제 @, 그룹 구성원 관리 및 전달 확인은 아직 공개되지 않았습니다. 인스턴스의 `/api/capabilities` 반환값을 기준으로 하십시오.

## 배포 및 로그인

Deployment 분류에서 서비스를 활성화하고 인스턴스 기간 요금제를 선택합니다. 배포 후 관리 페이지를 열고 계정 본인의 기업 위챗으로 스캔합니다. 휴대폰 확인이나 기타 로그인 단계가 필요한 경우 원격 데스크톱을 열고 해당 인스턴스의 데스크톱 비밀번호를 입력하십시오. API 자격 증명과 데스크톱 비밀번호는 독립적입니다. 로그인 정보는 인스턴스 디스크에 저장되며, 컨테이너를 재구성해도 디스크는 유지됩니다. 디스크를 삭제하면 로컬 세션이 삭제됩니다.

각 인스턴스는 독립적으로 과금되며, 구매한 기간에 따라 실행됩니다. REST / MCP 호출은 메시지별로 별도 과금되지 않으며, 실제 가격은 요금제 페이지를 기준으로 합니다. 현재는 기본적으로 위챗 봇의 기간 요금제를 참고하며, 최종 공개 전 실행 리소스와 결합하여 가격 확인을 완료해야 합니다.

## API 및 MCP

관리 페이지의 인스턴스 API 주소를 사용하고, 모든 계정 인터페이스에 `Authorization: Bearer &lt;인스턴스 API token>`을 포함합니다. 이 경로들은 전용 인스턴스에 속하며, 공유 API 게이트웨이가 아닙니다. MCP 주소는 인스턴스 주소에 `/mcp/`를 더한 것이며, 동일한 Bearer token을 사용합니다.

| 인터페이스                                                       | 기능                                          |
| -------------------------------------------------------- | ------------------------------------------- |
| `GET /api/status`、`GET /api/auth/status`                 | 계정 준비 여부 및 기능 목록                                 |
| `GET /api/auth/qr`                                       | 현재 로그인 QR 코드 PNG Base64                          |
| `GET /api/account`                                       | 현재 계정                                        |
| `GET /api/contacts?kind=all`                             | 내부 동료 및 외부 연락처, internal / external 지정 가능          |
| `GET /api/conversations`                                 | 로컬 대화, 원본 대화 ID 유지                              |
| `GET /api/messages`                                      | 로컬 동기화 메시지; conversation_id, after_rowid, limit 매개변수 |
| `POST /api/search`                                       | 연락처, 대화 및 로컬 텍스트 검색                               |
| `POST /api/messages`                                     | 텍스트 전송 비동기 작업, 반드시 Idempotency-Key 제공               |
| `POST /api/messages/send`                                | 동일한 전송 엔트리, 단일 또는 다수 대상 지원                            |
| `GET /api/groups/{conversation_id}`                      | 로컬 동기화된 그룹 정보 및 구성원                                 |
| `GET /api/tasks`                                         | 최근 작업 및 각 대상의 결과                                 |
| `GET /api/tasks/{id}`                                    | 전송 결과 조회                                      |
| `POST /api/tasks/{id}/cancel`                            | 아직 시작하지 않은 작업 취소                                   |
| `POST /api/runtime/pause`、`POST /api/runtime/resume`     | 자동화 일시 중지; 본인 검증 후 재개                               |
| `GET /api/diagnostics`、`GET /api/diagnostics/screenshot` | 인스턴스 상태 및 현재 화면, 모두 인증 필요                              |
| `GET /api/events?after=0`                                | 복구 가능한 커서의 메시지 이벤트                                  |
| `WS /ws`                                                 | 메시지 이벤트 스트림, Bearer 인증                             |

전송 본문에는 `target`, `type: "text"` 및 `text`가 포함됩니다. `target`은 대화 ID, 연락처 ID, 기업 사용자 ID 또는 고유한 전체 이름을 허용합니다. ID를 우선 사용하십시오. 표시 이름으로도 고유하게 위치를 특정할 수 없는 경우, 인스턴스는 작업을 거부하며 대상을 추측하지 않습니다. 로컬 대화가 없는 연락처는 먼저 클라이언트를 통해 대화를 열고 실제 대화 ID를 확인한 후 전송합니다. 요청 헤더 `Idempotency-Key`는 8–128자의 영문자, 숫자 또는 `_.:-`입니다. 동일한 작업을 반복 요청할 때는 동일한 키와 동일한 요청 본문을 재사용해야 합니다.

`target`을 `targets` 배열로 바꾸면 명확하게 지정된 1–50개 대상에게 순차적으로 전송할 수 있습니다. 둘은 동시에 제공할 수 없습니다. 모든 대상은 먼저 신원 확인을 완료하며, 동일한 객체를 가리키는 서로 다른 별칭은 거부됩니다. 어느 한 대상이 실패하면 이후 전송을 중지하고, 작업 결과는 항목별로 `succeeded`, `failed`, `unknown` 또는 `not_attempted`를 기록합니다. 부분 성공을 전체 성공으로 간주하지 마십시오. 이 절차 역시 배포 환경에서 지정된 연락처에 대한 실제 검수를 완료해야 합니다.

작업은 queued, running, submitting, succeeded, failed, unknown 또는 cancelled 상태일 수 있습니다. `succeeded`는 제출 후 해당 대화 기록에서 정확한 텍스트 및 서버 메시지 ID를 찾았음을 의미하며, `delivered`가 여전히 null인 것은 상대방이 이미 받았음을 의미하지 않습니다. unknown은 결과가 불명확함을 의미하므로, 기록을 확인하고 새 키로 반복 전송하지 마십시오. 인스턴스는 중단된 작업을 자동으로 재전송하지 않습니다.

기록에는 클라이언트가 이미 동기화한 내용만 포함되며, 전체 기록을 보장할 수 없습니다. 텍스트가 아닌 메시지는 unknown 유형으로 반환될 수 있으며, 첨부 파일 다운로드는 아직 공개되지 않았습니다. 이벤트는 최근 10,000개를 보존하며, `gap`은 커서가 보존 창을 이미 초과했음을 의미합니다. 최초 연결은 이전 기록을 새 메시지로 다시 재생하지 않습니다.

메시지 기록의 `server_accepted` 및 `server_id`는 서버가 로컬 메시지를 이미 수락했는지 확인하는 데 사용할 수 있습니다. 로컬 기록만 있고 서버 ID가 없는 경우 전송 성공으로 판단할 수 없습니다. 이 필드들은 수신자가 이미 받았거나 읽었음을 의미하지 않습니다. 이벤트 기록은 생성 시점의 상태를 보존하며, 현재 확인 상태를 조회하려면 메시지 기록 인터페이스를 사용해야 합니다.

## 계정 및 자격 증명

본인이 작업 권한을 가진 계정에만 로그인하십시오. API token을 신뢰할 수 있는 애플리케이션에 구성하십시오. 이는 해당 인스턴스의 계정 데이터에 접근할 수 있습니다. 비밀번호, QR 코드 또는 채팅 스크린샷을 공개 위치에 게시하지 마십시오. 인스턴스를 일시 중지하면 실시간 이벤트가 중단됩니다. 계정 로그아웃 또는 휴대폰 측에서 장치를 제거한 후에는 다시 로그인해야 합니다.

현재 텍스트 입력은 한 줄만 지원하며, 줄바꿈은 전송 전에 명시적으로 거부됩니다. 클라이언트가 보안 검증 또는 재로그인을 요구할 때는 계정 본인이 원격 데스크톱에서 완료해야 합니다. 인스턴스는 검증을 우회하지 않습니다. 검증 중단 후의 작업은 unknown을 반환할 수 있으므로, 먼저 메시지 기록을 조회하고 새 멱등 키로 재전송하지 마십시오.

보안 검증 프롬프트, 계정 로그아웃 또는 변경이 감지되면 자동화 대기열은 영구적으로 일시 중지됩니다. 휴대폰 검증을 완료한 후 인스턴스 콘솔의 “검증 후 재개”를 통해 아직 실행되지 않은 작업을 계속할 수 있습니다. 이미 제출되었으나 결과가 불확실한 작업은 재전송되지 않습니다. 일반적인 원격 업무도 기업 위챗 보안 검증을 유발할 수 있습니다. 공식 안내의 검증 후 24시간 동안 다시 잠기지 않는 창은 탐지가 이미 제거되었음을 의미하지 않으며, 인스턴스가 장기간 무인 운영을 보장할 수 있음을 의미하지도 않습니다.
