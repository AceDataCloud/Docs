주문 ID를 통해 주문을 조회합니다. 이 엔드포인트는 두 가지 읽기 모드를 지원합니다. 익명 접근은 결제 페이지에 필요한 최소 필드만 반환하며, 주문 소유자가 Account Token을 지참한 경우 전체 상세 정보를 반환합니다.

## API 개요

| 항목   | 내용                                                        |
| --- | --------------------------------------------------------- |
| 메서드  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| 인증  | 선택 사항; 익명은 최소 프로젝션, 인증된 소유자는 전체 프로젝션                                    |

`/orders/{id}` 및 `/orders/{id}/`는 현재 모두 사용할 수 있습니다. 주문 ID는 결제 링크의 일부이며, 민감한 불투명 식별자로 간주해야 하므로 공개적으로 전파하지 마십시오.

## 익명 조회

결제 페이지는 로그인 상태가 유실된 경우 직접 읽을 수 있습니다:

```shell
export ORDER_ID='你的订单 ID'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

익명 응답에는 `id`, `description`, `price`, `state`, `pay_way`, `pay_url`, `expired_at`, `created_at`만 포함됩니다. 계정, Application, Package, 결제 내부 식별자 또는 metadata는 반환하지 않습니다.

## 인증된 조회

```shell
export PLATFORM_TOKEN='你的账户令牌'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

주문 소유자는 `application` / `applications`, `package` / `packages`, `bank_details`, `invoice_automation` 및 모델 필드를 포함한 전체 Order 상세 정보를 받습니다. 인증되었지만 주문 소유자가 아닌 경우 `403`을 반환합니다. 슈퍼 관리자는 예외입니다.

## 주요 필드

| 필드            | 설명                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`, `Paid`, `Finished`, `Expired`, `Failed` 또는 `Refunded` |
| `pay_way`     | 주문의 현재 결제 방식; 필드명은 `payment_method`가 아님                             |
| `pay_url`     | 호스팅된 결제 페이지 또는 QR 코드 주소이며, 비어 있을 수 있음                                           |
| `price`       | 주문의 최종 결제 금액이며, 현재 주문 모델은 `final_price` 필드를 제공하지 않음                         |
| `amount`      | 패키지 할당량 수량; 인증된 전체 응답에서만 확인 가능                                            |
| `finished_at` | 주문 완료 시간; 필드명은 `paid_at`가 아님                                      |

전체 응답에는 결제 방식에 따라 추가 필드가 포함될 수 있으므로, 클라이언트는 필요에 따라 읽어야 하며 전체 응답의 민감한 metadata를 항상 기록하지 않아야 합니다.

## 오류 처리

- `404`: 주문 ID가 존재하지 않습니다.
- `403`: 로그인되었지만 주문 소유자가 아닙니다.
- 익명 요청은 `401`을 반환하지 않으며, 최소 공개 프로젝션만 받습니다.

## 송장 상계 발행 및 재신청

`GET /api/v1/orders/{order_id}/invoice/`를 통해 주문의 현재 송장을 읽을 수 있습니다. 자동 상계 발행이 제출된 후에도 송장은 여전히 `Issued`이며, `red_state`는 상계 발행 진행 상태를 나타냅니다. 제출 성공은 상계 발행 완료를 의미하지 않습니다. 확인 대기, 적색 송장 발행 또는 보관 중에는 주문이 다시 송장을 신청할 수 없습니다.

관리자가 제목 또는 세금 식별 번호 등의 청구 정보 오류로 상계 발행을 신청하는 경우, 상계 발행 사유는 “청구 오류”입니다. 주문 환불로 인해 트리거된 자동 상계 발행은 여전히 “서비스 중단”을 사용합니다.

적색 송장이 성공적으로 발행되고 보관된 후 원래 송장은 `Voided`가 되며, 그때에만 주문이 다시 신청할 수 있습니다. 원래 송장은 송장 이력에서 확인할 수 있습니다. 상계 발행 실패 또는 결과 확인 대기 시 재무팀이 검토하여 처리하며, 주문의 송장 발행 제한은 미리 해제되지 않습니다. 수동으로 발행된 송장은 먼저 세무 또는 청구 시스템에서 무효 처리 또는 상계 발행을 완료한 후, 재무팀이 플랫폼에서 확인해야 합니다.
