이 튜토리얼은 최소한의 API 요청으로 Ace Data Cloud X402의 전체 흐름을 설명합니다. 목표는 먼저 복잡한 코드를 작성하는 것이 아니라, 먼저 이해하는 것입니다: 왜 첫 번째 요청은 402를 반환하는지, `accepts`에는 무엇이 있는지, 그리고 `PAYMENT-SIGNATURE`는 어떻게 동일한 API 요청을 결제 완료 요청으로 바꾸는지.

## 준비 사항

다음을 준비해야 합니다:

| 항목   | 설명                                                   |
| ---- | ---------------------------------------------------- |
| 지갑   | 대상 네트워크를 지원하는 지갑. Base는 EVM 지갑을 사용하고, Solana는 Solana 지갑을 사용합니다.      |
| USDC | 지갑에 충분한 USDC가 있어야 합니다. 실제 금액은 402 응답의 `maxAmountRequired`를 기준으로 합니다. |
| 개발 환경 | TypeScript는 Node.js 18+를 권장하고, Python은 Python 3.10+를 권장합니다.    |
| SDK  | 공식 SDK 사용을 권장하며, 서명 세부 사항을 직접 작성하는 것은 권장하지 않습니다.                                |

X402로 Ace Data Cloud API를 호출할 때 API Token은 필요하지 않습니다. SDK의 첫 번째 요청에는 `Authorization`이 포함되지 않으며, Gateway는 `402 Payment Required`와 결제 요구 사항을 반환합니다. SDK는 서명 후 자동으로 재시도합니다.

## SDK 설치

소스 코드 및 패키지 주소:

- SDK 저장소: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- X402 Client 저장소: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm: `@acedatacloud/sdk`, `@acedatacloud/x402-client`
- PyPI: `acedatacloud`, `acedatacloud-x402`

TypeScript:

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client ethers
```

Python:

```bash
pip install acedatacloud acedatacloud-x402
```

Solana를 사용하려면 해당 의존성도 설치해야 합니다:

```bash
npm install @solana/web3.js
```

Python 버전의 Solana signer 의존성은 이미 `acedatacloud-x402`에 포함되어 있습니다.

깨끗한 임시 환경에서의 설치 및 import 검사 출력:

```text
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4

acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
```

결과 설명:

- npm 패키지와 PyPI 패키지는 모두 실제로 배포된 패키지이며, 문서의 자리 표시자 이름이 아닙니다.
- `acedatacloud-x402[cli]`는 CLI를 설치하며, `approve-permit2` 하위 명령은 `upto` 시나리오의 Permit2 승인에 사용할 수 있습니다.

## 첫 번째 요청은 402를 반환합니다

먼저 `curl`을 사용하여 미결제 요청이 무엇을 반환하는지 확인할 수 있습니다. 아래 예시는 `PAYMENT-SIGNATURE`를 포함하지 않으므로 요금이 부과되지 않습니다:

```bash
curl -sS -X POST https://x402.acedata.cloud/openai/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "hi"}],
    "max_tokens": 1
  }'
```

응답 본문에는 `accepts` 배열이 포함되며, 일반적인 구조는 다음과 같습니다:

```json
{
  "x402Version": 2,
  "resource": {
    "url": "/openai/chat/completions",
    "description": "AceDataCloud API call",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "maxAmountRequired": "95215",
      "amount": "95215",
      "maxTimeoutSeconds": 3600,
      "resource": "/openai/chat/completions",
      "description": "...",
      "payTo": "0x...",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913"
      }
    }
  ],
  "error": "PAYMENT-SIGNATURE header is required"
}
```

동일한 챌린지 내용은 base64 형식으로 `PAYMENT-REQUIRED` 응답 헤더에도 포함되므로, 클라이언트는 body를 파싱하지 않고도 결제 요구 사항을 읽을 수 있습니다.

프로덕션 API의 미결제 요청 프로그램 출력 요약은 다음과 같습니다:

```text
status=402
x402Version 2
accepts [
  ('eip155:8453', 'exact', '95215'),
  ('eip155:8453', 'upto', '95215'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '95215'),
]
```

결과 설명:

- 첫 번째 요청에는 `Authorization` 또는 `PAYMENT-SIGNATURE`가 포함되지 않으므로 HTTP 402를 반환하며, 요금이 부과되지 않습니다.
- `accepts`는 이번 요청에서 유일하게 신뢰할 수 있는 서명 근거이며, 선택 가능한 네트워크, scheme, 금액 상한, 수금 주소 및 자산 주소를 포함합니다.
- `network`는 CAIP-2 식별자이며, 클라이언트가 네트워크를 선택할 때는 CAIP-2 문자열로 일치시켜야 합니다.
- 이번 `gpt-4o-mini` 최소 채팅 요청의 최대 금액은 `95215` atomic USDC, 즉 `0.095215` USDC입니다.
- 매 요청마다 해당 402 응답을 읽어야 하며, 예시 금액을 비즈니스 코드에 하드코딩하지 마십시오.

필드 의미:

| 필드                  | 설명                                                             |
| ------------------- | -------------------------------------------------------------- |
| `scheme`            | 결제 방식. `exact`는 고정 금액을 나타내고, `upto`는 승인 한도를 나타내며 실제 사용량에 따라 정산됩니다.                     |
| `network`           | 결제 네트워크의 CAIP-2 식별자이며, 예를 들어 `eip155:8453`, `solana:5eykt4...`가 있습니다.           |
| `maxAmountRequired` | 최대 결제 금액이며, 단위는 USDC atomic units입니다. `95215`는 `0.095215` USDC를 나타냅니다.       |
| `amount`            | 이번에 정산할 금액입니다. `exact`는 `maxAmountRequired`와 같고, `upto`는 정산 단계에서 실제 사용량에 따라 다시 작성됩니다. |
| `payTo`             | 수금 주소입니다.                                                          |
| `asset`             | USDC 컨트랙트 주소 또는 Solana mint 주소입니다.                                     |
| `extra`             | 서명에 필요한 체인 ID, EIP-712 domain, Permit2 주소 등의 확장 정보입니다.                      |

## SDK로 결제 재시도 완료하기

다음은 최소 TypeScript 예시입니다. 이는 `network: 'base'`를 지정하며, handler는 이번 402 응답에서 Base의 payment requirement를 선택합니다. 실제 금액과 수금 주소는 여전히 `accepts`를 기준으로 합니다:
```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const response = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Reply with exactly: hello' }],
  max_tokens: 8
});

console.log(response.choices[0].message.content);
```

이 코드 뒤에서는 네 단계가 발생합니다:

1. SDK가 `Authorization` 없이 일반 API 요청을 한 번 전송합니다.
2. Gateway가 `402 Payment Required` 및 `accepts`를 반환합니다.
3. `createX402PaymentHandler`가 `network = 'base'`의 payment requirement를 선택하고 `PAYMENT-SIGNATURE`를 서명합니다.
4. SDK가 동일한 요청 본문으로 재시도하고, Gateway는 Facilitator를 호출하여 검증 및 정산한 후 대상 API로 전달합니다.

## Facilitator 지원 기능 확인

X402 API는 리소스 디렉터리에 의존하지 않습니다. 클라이언트는 알려진 API를 직접 호출하고, 해당 요청에 대해 실시간으로 반환되는
`402 Payment Required` 및 `accepts`를 유일한 가격 및 서명 근거로 사용합니다.

Facilitator의 기능 선언은 다음 위치에 있습니다:

```bash
curl https://facilitator.acedata.cloud/.well-known/x402
```

이는 `/supported`, `/verify`, `/settle` 및 현재 활성화된 결제 네트워크만 설명하며, API 리소스는 나열하지 않습니다.

Ace Data Cloud의 프로덕션 Facilitator 주소는 다음과 같습니다:

```text
https://facilitator.acedata.cloud
```

지원하는 네트워크와 scheme을 확인할 수 있습니다:

```bash
curl https://facilitator.acedata.cloud/supported
```

반환되는 `kinds`는 Facilitator가 지원하는 네트워크와 scheme을 나열합니다. 실제 호출 시에는 여전히 API가 반환하는 `accepts`를 기준으로 합니다.

Facilitator `/supported` 출력:

```text
kinds [
  ('eip155:8453', 'exact'),
  ('eip155:8453', 'upto', {'facilitatorAddress': '0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708'}),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact')
]
```

결과 설명:

- `/supported`는 Facilitator가 이러한 네트워크와 scheme에 대한 검증 및 정산 기능을 갖추고 있음을 나타냅니다.
- Base와 Solana는 모두 `exact`를 지원하며, `upto`는 현재 Base에서만 제공됩니다.
- 특정 API가 특정 네트워크를 허용하는지는 여전히 해당 API의 402 `accepts`를 기준으로 합니다.
