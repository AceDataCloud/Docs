Service UUID를 통해 페이지네이션으로 해당 서비스에서 현재 활성화되어 있고 폐기되지 않은 API를 반환합니다. alias만 있는 경우 먼저 [서비스 상세](https://platform.acedata.cloud/documents/platform-service-detail)를 호출하여 `id`를 가져옵니다.

## 인터페이스 개요

| 항목   | 내용                                                                  |
| --- | ------------------------------------------------------------------- |
| 메서드  | `GET`                                                               |
| URL | `https://platform.acedata.cloud/api/v1/services/{service_id}/apis/` |
| 인증  | 공개, 계정 토큰 불필요                                                           |
| 페이지네이션  | `count` + `items`                                                   |

## 매개변수

| 매개변수           | 위치    | 필수  | 설명                               |
| ------------ | ----- | --- | -------------------------------- |
| `service_id` | path  | 예   | Service UUID, alias는 지원하지 않음           |
| `limit`      | query | 아니요   | 페이지당 항목 수, 최대 100                      |
| `offset`     | query | 아니요   | 페이지네이션 오프셋                            |
| `ordering`   | query | 아니요   | Django 정렬 표현식; `rank` 또는 `-rank` 권장 |

현재 인터페이스는 `stage` 필터링을 지원하지 않습니다. 이미 `Deprecated` API를 제외합니다.

```shell
export SERVICE_ID='당신의 Service ID'
curl --get "https://platform.acedata.cloud/api/v1/services/${SERVICE_ID}/apis/" \
  --data-urlencode 'limit=100' \
  --data-urlencode 'ordering=rank' \
  -H 'Accept: application/json'
```

목록 항목은 [플랫폼 API 목록](https://platform.acedata.cloud/documents/platform-api-list)과 동일한 인덱스 구조를 사용하며, 현재 `definition`을 포함합니다. 단일 API의 안정적인 진입점이 필요한 경우 계속해서 `/api/v1/apis/{api_id}`를 호출합니다.

## 오류 처리

- 서비스가 존재하지 않거나 현재 사이트에서 보이지 않는 경우: `404`.
- `service_id`는 UUID여야 합니다. alias는 이 action에서 해석되지 않습니다.
