OpenCode 공식 IDE 확장은 VS Code, Cursor, Windsurf, VSCodium 등의 편집기를 지원하며, OpenCode 로컬 런타임 및 Provider 구성을 재사용합니다. IDE 확장은 로컬 CLI Provider를 재사용하지만, 서로 다른 편집기 버전의 요청 체인은 다를 수 있습니다; 처음 접속할 때는 버전을 고정하고 최소 검증을 완료해야 합니다.

## Provider 구성

먼저 [OpenCode Terminal 구성](https://platform.acedata.cloud/documents/opencode-terminal-integration)에 따라 `opencode.json` 또는 `opencode.jsonc`에서 Ace Data Cloud Provider를 구성합니다:

```jsonc
{
  "provider": {
    "acedatacloud": {
      "npm": "@ai-sdk/openai-compatible",
      "options": {
        "baseURL": "https://api.acedata.cloud/v1",
        "apiKey": "{env:ACEDATACLOUD_API_KEY}"
      },
      "models": {
        "MODEL_ID": { "name": "MODEL_ID" }
      }
    }
  },
  "model": "acedatacloud/MODEL_ID"
}
```

## IDE 확장 설치

1. 편집기의 통합 터미널에서 `opencode`를 실행하여 공식 프로세스에 따라 자동으로 확장을 설치합니다; 해당 마켓플레이스에서 수동으로 설치할 수도 있습니다.
2. 편집기를 다시 로드합니다.
3. OpenCode 확장에서 `Reply only OK`를 시작합니다.
4. 파일을 읽거나 코드를 수정해야 하는 요청을 다시 실행하여 IDE 확장이 동일한 Provider와 모델을 사용하는지 확인합니다.

## 현재 경계

- Provider의 능력은 OpenCode 런타임에서 나오며, 호스트 편집기가 Ace Data Cloud를 원래 지원한다는 것을 의미하지 않습니다.
- VS Code와 각 포크의 확장 버전은 다를 수 있으므로, 각각의 버전을 기록해야 합니다.
- 일반 채팅 성공은 파일 읽기, 편집 및 도구 호출 검증을 대체할 수 없습니다.
