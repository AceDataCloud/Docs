각 Application에 대해 독립적인 Hermes 컨테이너 인스턴스를 생성합니다. 기본적으로 고정 릴리스 버전의 기본 이미지를 사용하며, 네이티브 기능을 유지합니다. 플랫폼은 구매, 갱신, 영구 스토리지 및 배포 관리를 제공합니다.

## 생성 및 구매

1. [Hermes 배포](https://platform.acedata.cloud/services/hermes)를 열고 Application을 생성합니다.
2. 구매 페이지에서 기간 패키지를 선택하고 결제를 완료합니다.
3. 구성 페이지로 돌아가 드롭다운 목록에서 플랫폼 채팅 모델을 선택하고, 현재 모델 가격을 확인할 수 있습니다. 플랫폼은 이 인스턴스를 위해 독립적인 API 자격 증명을 생성합니다. 플랫폼 연동을 끄고 네이티브 콘솔에서 직접 구성할 수도 있습니다.
4. 자동 생성 액세스 자격 증명을 선택하거나 자신의 강력한 비밀번호/Token을 설정한 후, 확인하면 배포가 시작됩니다. 액세스 자격 증명과 모델 API 자격 증명은 서로 독립적입니다.
5. 인스턴스가 준비되면 관리 페이지에서 액세스 주소와 로그인 자격 증명을 가져옵니다.
6. 네이티브 콘솔에 로그인하여 자신의 모델 제공업체, 키 및 채널을 구성합니다.

배포 요금은 패키지 기간에 따라 청구되며, 구체적인 미국 달러 가격과 기간은 구매 페이지를 기준으로 합니다. 모델 호출 요금은 별도이며, 배포 기간을 구매해도 모델 크레딧은 제공되지 않습니다. 플랫폼 연동을 활성화하면 전용 API 자격 증명은 선택한 모델에 해당하는 채팅 인터페이스만 제공하며, 호출은 플랫폼 잔액에서 별도로 청구됩니다. 각 Application은 각각 구매, 갱신 및 관리합니다.

## 비밀번호, 자격 증명 및 후속 구성

액세스 자격 증명은 최초 시작 전에 설정됩니다. 자동 생성 방식은 무작위 자격 증명을 사용하며, 사용자 지정 비밀번호는 최소 16자, OpenClaw Token은 최소 32자여야 합니다. 초안에는 비밀번호가 저장되지 않으며, 페이지를 전환한 후 다시 입력해야 할 수 있습니다. 배포 후에는 Application 소유자와 관리자만 액세스 자격 증명을 확인할 수 있습니다.

각 인스턴스의 모델 API 자격 증명은 서로 재사용되지 않으며, 배포 갱신에 따라 유효 기간이 연장되고 인스턴스 삭제 시 폐기됩니다. 배포 초기화 후 네이티브 콘솔에서 모델과 채널을 변경하십시오. 다른 서비스의 모델로 변경하는 경우, 먼저 플랫폼 자격 증명 관리에서 해당 인터페이스 권한을 조정하거나 적절한 자격 증명을 사용하십시오. 일반 재배포는 네이티브 설정을 덮어쓰지 않습니다. 게시 검증을 통과하지 않은 배포 환경은 새 배포를 일시적으로 거부하므로 지원팀에 문의하십시오.

## 버전 및 데이터

구성 페이지에는 현재 게시된 이미지 버전이 표시됩니다. 새 인스턴스는 서비스의 현재 게시 버전을 사용하며, 기존 인스턴스는 카탈로그 업데이트에 따라 자동으로 교체되지 않습니다. 재배포하면 현재 서비스 버전이 적용되므로, 먼저 백업하고 사용하는 버전의 업그레이드 요구 사항을 확인하십시오.

각 인스턴스는 기본적으로 1 CPU, 2 GiB 메모리 제한 및 10 GiB 영구 스토리지를 제공합니다. 재시작해도 인스턴스 데이터는 유지됩니다. 배포를 직접 삭제하거나 만료 후 회수되면 스토리지가 삭제되므로, 보관해야 하는 데이터는 미리 내보내십시오.

## 갱신 및 만료

현재 Application의 구매 페이지에서 갱신하면 유효 기간이 플랫폼의 기존 기간 규칙에 따라 연장됩니다. 만료 후 액세스 진입점이 일시 중지되며, 유예 기간 내에 갱신하면 액세스가 복구됩니다. 유예 기간을 초과하면 인스턴스와 데이터가 회수됩니다. 관리 페이지의 만료 시간, 청구 상태 및 삭제 안내를 기준으로 합니다.

## 관리 인터페이스 로그인

배포 관리 페이지에서 Dashboard 주소, 사용자 이름 `admin` 및 비밀번호를 복사한 후 열어서 로그인합니다. 로그인 정보는 해당 Application의 소유자와 플랫폼 관리자에게만 제공됩니다. 모델, 스킬 및 채널은 Hermes 네이티브 인터페이스에서 구성합니다.

## 자주 묻는 질문

- **왜 새 인스턴스는 아직 응답하지 않나요?** 배포 완료는 컨테이너가 준비되었음을 의미합니다. 사용을 시작하려면 네이티브 인터페이스에서 모델과 자격 증명을 구성해야 합니다.
- **추가 플러그인 또는 모델 fallback이 사전 설치되어 있나요?** 기본적으로 추가하지 않으며, 필요에 따라 네이티브 인터페이스에서 구성합니다.
- **기존 인스턴스는 어떻게 업데이트하나요?** 기존 Application과 주문은 유지되며, 재배포 시 현재 서비스 버전을 사용합니다. 업그레이드 전에 데이터를 백업하고 버전 호환성을 확인하십시오.
- **시작에 실패하면 어떻게 하나요?** 먼저 배포 로그와 이벤트를 확인하고, 인스턴스가 준비된 후 모델을 구성하십시오. 공개 댓글이나 스크린샷에 인스턴스 비밀번호와 키를 노출하지 마십시오.
