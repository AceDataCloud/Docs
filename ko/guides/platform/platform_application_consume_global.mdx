title: "AceDataCloud Application 전역 잔액 공유 설정"

`allow_consume_global`을 설정합니다. 활성화한 후 조건에 부합하는 종량제 Application은 자체 잔액이 부족할 때 계정 전역 잔액을 계속 사용할 수 있습니다.

## 준비 작업

- [Account Token](https://platform.acedata.cloud/documents/platform-token)을 생성하고 안전하게 보관합니다.
- [서비스 신청 목록](https://platform.acedata.cloud/documents/platform-application-list)에서 본인이 소유한 `application_id`를 가져옵니다.

```shell
export PLATFORM_TOKEN='당신의 계정 토큰'
export APPLICATION_ID='당신의 Application ID'
```

## 인터페이스 개요

| 항목    | 내용                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------- |
| 메서드   | `POST`                                                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/applications/{application_id}/update-allow-consume-global/` |
| 인증   | Account Token                                                                                      |
| Body | JSON                                                                                               |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/applications/${APPLICATION_ID}/update-allow-consume-global/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"allow_consume_global": true}'
```

성공하면 업데이트된 Application 객체를 반환합니다. 요청 값이 반드시 저장된다고 가정하지 말고, 응답의 `allow_consume_global`을 기준으로 하십시오.

> `Period` 유형의 Application은 전역 잔액을 소비할 수 없습니다. `true`를 요청하더라도 서버는 이 필드를 `false`로 유지합니다.

## 오류 처리

- `401`: Account Token이 유효하지 않거나 누락되었습니다.
- `403`: 현재 계정이 해당 Application의 소유자가 아닙니다.
- `404`: Application ID가 존재하지 않습니다.

전역 잔액의 충전 진입점과 사용 가능한 요금제는 플랫폼 콘솔 및 [주문 생성](https://platform.acedata.cloud/documents/platform-order-create)에서 반환되는 실제 요금제를 기준으로 하십시오. `Wallet` 유형의 요금제가 존재한다고 가정하지 마십시오.
