본 문서에서는 사용자 지정 파라미터를 입력하여 Kling 공식 비디오를 생성할 수 있는 Kling Videos Generation API 연동 설명을 소개합니다.

## 신청 절차

Kling Videos Generation API를 사용하려면 먼저 [Ace Data Cloud 콘솔](https://platform.acedata.cloud/console/applications)에서 API Token을 발급받아 예비용으로 보관하세요.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

아직 로그인 또는 회원가입을 하지 않은 경우, 로그인 페이지로 자동 이동하여 회원가입과 로그인을 안내하며, 완료 후 현재 페이지로 자동 돌아옵니다.

**하나의 API Token으로 플랫폼의 모든 서비스를 호출할 수 있으며, 각 서비스마다 별도로 신청할 필요가 없습니다.** 최초 신청 시 무료 크레딧이 제공되어 무료로 체험할 수 있으며, 크레딧이 부족한 경우 [콘솔](https://platform.acedata.cloud/console/coin)에서 공용 잔액을 충전할 수 있습니다.

> 📘 전체 문서: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## 기본 사용법

먼저 기본 사용 방식을 알아보겠습니다. 즉, 프롬프트 `prompt`, 생성 작업 `action`, 첫 프레임 참조 이미지 `start_image_url` 및 모델 `model`을 입력하면 처리된 결과를 얻을 수 있습니다. 먼저 `action` 필드를 간단히 전달해야 하며, 그 값은 `text2video`입니다. 이는 주로 세 가지 작업을 포함합니다: 텍스트-비디오(`text2video`), 이미지-비디오(`image2video`), 비디오 확장(`extend`). 그리고 모델 `model`도 입력해야 합니다. 현재 주로 `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1` 모델이 있으며, 구체적인 내용은 다음과 같습니다:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

여기에서 Request Headers를 설정한 것을 확인할 수 있으며, 다음을 포함합니다:

- `accept`: 어떤 형식의 응답 결과를 받을 것인지로, 여기서는 JSON 형식인 `application/json`으로 입력합니다.
- `authorization`: API 호출 키로, 신청 후 직접 드롭다운에서 선택할 수 있습니다.

또한 Request Body를 설정했으며, 다음을 포함합니다:

- `model`: 비디오 생성 모델로, 주로 `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1` 모델이 있습니다.
- `mode`: 비디오 생성 모드로, 선택 가능한 값은 표준 모드 `std`, 고속 모드 `pro`, 네이티브 4K 모드 `4k`입니다. 이 중 `4k`는 `kling-v3` 및 `kling-v3-omni`만 지원하며, `camera_control`(카메라 이동 제어)과 호환되지 않습니다.
- `action`: 이번 비디오 생성 작업의 동작으로, 주로 세 가지 동작을 포함하며 각각 텍스트-비디오(`text2video`), 이미지-비디오(`image2video`), 비디오 확장(`extend`)입니다.
- `start_image_url`: 이미지-비디오 작업 `image2video`를 선택한 경우 반드시 업로드해야 하는 첫 프레임 참조 이미지 링크입니다.
- `end_image_url`: 이미지-비디오 시 선택 사항이며, 마지막 프레임을 지정합니다.
- `duration`: 비디오 길이이며, 단위는 초입니다. `kling-v3` 및 `kling-v3-omni`는 3~15초의 정수 길이를 지원하며, `kling-o1`은 5초만 지원하고, 다른 모델은 5초 또는 10초를 지원합니다.
- `generate_audio`: 오디오를 동시에 생성할지 여부이며, 선택 사항인 불리언 값입니다. `kling-v3`, `kling-v3-omni` 및 `kling-v2-6`(pro 모드만)을 지원합니다. 기본값은 `false`입니다.
- `aspect_ratio`: 비디오 가로세로 비율이며, 선택 사항으로 `16:9`, `9:16`, `1:1`을 지원하고 기본값은 `16:9`입니다.
- `cfg_scale`: 관련성 강도로, 범위는 [0,1]이며 값이 클수록 프롬프트에 더 부합합니다.
- `camera_control`: 선택 사항으로, 카메라 움직임을 제어하는 객체 파라미터이며, type/simple 프리셋 및 horizontal, vertical, pan, tilt, roll, zoom 등의 구성을 지원합니다.
- `negative_prompt`: 선택 사항으로, 나타나지 않기를 원하는 네거티브 프롬프트이며 최대 200자입니다.
- `image_list`: Omni 참조 이미지 목록으로, `kling-o1` 및 `kling-v3-omni` 모델에 적용되며, 사용법은 아래의 「Omni 만능 참조」를 참조하세요.
- `video_list`: Omni 참조 비디오 목록(비디오 편집 지원)으로, `kling-o1` 및 `kling-v3-omni` 모델에 적용되며, 사용법은 아래의 「Omni 만능 참조」를 참조하세요.
- `prompt`: 프롬프트입니다.
- `callback_url`: 결과를 콜백받아야 하는 URL입니다.
- `async`: 선택 사항으로, `true`로 설정하면 인터페이스가 즉시 `task_id`를 반환하며, `callback_url`을 제공할 필요 없이 이후 해당 작업 조회 인터페이스를 통해 폴링하여 결과를 가져옵니다.

선택한 후 오른쪽에도 해당 코드가 생성된 것을 확인할 수 있습니다. 그림과 같습니다:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

「Try」 버튼을 클릭하면 테스트할 수 있습니다. 위 그림과 같이, 여기서 다음과 같은 결과를 얻었습니다:

```json
{
  "success": true,
  "video_id": "900798310464749610",
  "video_url": "https://cdn.acedata.cloud/assets/examples/kling/6c68c267-065b-4423-b66b-a0e4c59ee0d5-6a664a591a53.mp4",
  "duration": "5.041",
  "state": "succeed",
  "task_id": "6c68c267-065b-4423-b66b-a0e4c59ee0d5"
}
```

반환 결과에는 여러 필드가 있으며, 다음과 같이 소개합니다:

- `success`, 이 시점의 비디오 생성 작업 상태입니다.
- `task_id`, 이 시점의 비디오 생성 작업 ID입니다.
- `video_id`, 이 시점의 비디오 생성 작업의 비디오 ID입니다.
- `video_url`, 이 시점의 비디오 생성 작업의 비디오 링크입니다.
- `duration`, 이 시점의 비디오 생성 작업의 비디오 링크 길이입니다.
- `state`, 이 시점의 비디오 생성 작업 상태입니다.

만족스러운 비디오 정보를 얻은 것을 확인할 수 있으며, 결과의 `data`에 있는 비디오 링크 주소를 통해 생성된 Kling 비디오를 가져오기만 하면 됩니다.

또한 해당 연동 코드를 생성하려면 직접 복사할 수 있습니다. 예를 들어 CURL 코드는 다음과 같습니다:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## 모델 기능 매트릭스

모델마다 파라미터 지원 상황에 큰 차이가 있습니다. 다음 매트릭스는 [Kling 공식 video models 문서](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels)를 기반으로 정리되었습니다. 호출 전에 현재 `model` / `mode` / `duration` 조합이 필요한 기능을 지원하는지 먼저 확인하세요. 그렇지 않으면 `model/mode/duration(...) is not supported with image_tail` 등의 오류가 반환됩니다.
| 모델                  | 모드             | `end_image_url`（첫·마지막 프레임） | `generate_audio`（배경음） | `camera_control`（카메라 워크） | 비고                                           |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ `duration=5`만     | ❌                    | ✅ `duration=5`만     | `extend`는 `negative_prompt` 및 `cfg_scale`을 지원하지 않음 |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | 다중 이미지 비디오 생성, `extend` 전체 모드 사용 가능                         |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | 단일 모드, `duration=5/10`만                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | 단일 모드, `duration=5/10`만                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | 배경음을 동시에 지원하는 유일한 비 v3 모델                             |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | `duration` 범위 3–15초                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | 4K 모드는 카메라 워크와 호환되지 않음                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | `duration=5`만 지원                             |

주의 사항：

- `mode=4k`는 `kling-v3` 및 `kling-v3-omni`만 지원하며, `camera_control`（카메라 워크）과 상호 배타적입니다.
- `end_image_url`은 `action=image2video`일 때만 `start_image_url`과 함께 사용할 수 있습니다. `end_image_url`만 전달하면（`start_image_url` 없음）거부됩니다.
- `kling-v3` / `kling-v3-omni`는 3–15초 사이의 모든 정수 `duration`을 허용합니다. `kling-o1`은 5만 허용하며, 나머지 모델은 5 또는 10만 허용합니다.
- `generate_audio`의 기본값은 `false`입니다. `kling-v3`, `kling-v3-omni` 및 `kling-v2-6`（pro 모드）만 지원합니다.

## 비디오 확장 기능

이미 생성된 Kling 비디오를 계속 생성하려면, 매개변수 `action`을 `extend`로 설정하고 계속 생성할 비디오의 ID를 입력할 수 있습니다. 비디오 ID는 기본 사용 방법에 따라 가져올 수 있으며, 아래 그림과 같습니다:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

이때 비디오의 ID는 다음과 같습니다:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> 주의: 여기의 비디오 `video_id`는 생성 후 비디오의 ID입니다. 비디오를 생성하는 방법을 모른다면 위의 기본 사용 방법을 참고하여 비디오를 생성할 수 있습니다.

다음으로, 비디오 생성 맞춤 설정을 위해 다음 단계에서 확장할 프롬프트를 반드시 입력해야 하며, 다음 내용을 지정할 수 있습니다:

- `model`: 비디오를 생성하는 모델이며, 주로 `kling-v1`, `kling-v1-5` 및 `kling-v1-6` 모델이 있습니다.
- `mode`: 비디오 생성 모드이며, 선택 가능한 값은 표준 모드 `std`, 고속 모드 `pro`, 네이티브 4K 모드 `4k`입니다（`kling-v3` 및 `kling-v3-omni`만 지원하며, 카메라 워크 제어와 호환되지 않음）.
- `duration`: 이번 비디오 생성 작업의 비디오 길이이며, 주로 5s와 10s를 포함합니다.
- `start_image_url`: 이미지-비디오 생성 동작 `image2video`를 선택할 경우 반드시 업로드해야 하는 첫 프레임 참조 이미지 링크입니다.
- `prompt`: 프롬프트.

작성 예시는 다음과 같습니다:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

작성을 완료하면 다음과 같은 코드가 자동으로 생성됩니다:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

해당 Python 코드:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

실행을 클릭하면 다음과 같은 결과를 얻을 수 있습니다:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```

결과 내용이 위와 일치하는 것을 확인할 수 있으며, 이로써 비디오 확장 기능이 구현됩니다.

## Omni 전능 참조（비디오 편집 / 참조 비디오 / 다중 이미지 참조）

`kling-o1`과 `kling-v3-omni`는 두 개의 독립적인 모델이며, 둘 다 「전능 참조」 기능을 지원합니다. 텍스트-비디오 생성（`action=text2video`）을 기반으로 참조 이미지 또는 참조 비디오를 추가로 전달하여 **다중 이미지 참조, 참조 비디오 및 기존 비디오 직접 편집**을 구현할 수 있습니다.

**핵심 규약**: 참조 소재는 반드시 `prompt`에서 `&lt;&lt;<image_1>>>`, `&lt;&lt;<video_1>>>` 형식으로（번호는 1부터 시작）`image_list` / `video_list`의 해당 위치 소재를 참조해야 모델이 이러한 참조를 적용합니다. 소재만 전달하고 프롬프트에서 참조하지 않으면 소재는 무시됩니다.

> 보안 설명: 현재 API는 `element_list`를 공개하지 않습니다. Kling Element Library의 ID는 테넌트 격리가 적용되지 않으므로, 테넌트 격리가 적용된 Element Management API가 제공되기 전에는 `image_list`를 사용하여 주체 참조 이미지를 전달하십시오.

Omni 요청은 `negative_prompt`, `cfg_scale` 또는 `camera_control`을 지원하지 않으며, `mode=4k`도 사용할 수 없습니다. 참조 비디오가 포함된 경우 `generate_audio`는 반드시 `false`여야 합니다.

### 참조 비디오 및 비디오 편집（`video_list`）
`video_list`는 참조 비디오를 전달하는 데 사용되며, 본 기능에서 가장 일반적으로 사용되는 시나리오입니다. 배열 요소 필드는 다음과 같습니다:

- `video_url`: 참조 비디오 링크이며, 비워둘 수 없습니다. 최대 1개의 MP4/MOV 비디오, 파일 크기 ≤200MB, 프레임 레이트 24–60fps입니다. `kling-o1`은 길이 3–10초, 너비와 높이 각각 700–2160px를 요구합니다. `kling-v3-omni`는 길이 3–15.5초, 너비와 높이 각각 700–4553px, 총 픽셀 수 ≤8,294,400, 화면비 0.4–2를 요구합니다.
- `refer_type`: 참조 유형으로, `base`(기본값, **편집할 기본 비디오**, 즉 "비디오를 직접 편집"하며 요소 추가/삭제·수정, 구도 변경, 스타일 변경, 색상 변경, 날씨 변경 등을 할 수 있음) 또는 `feature`(**특징 참조**, 해당 스타일 / 카메라 워크 / 다음 샷 이어찍기를 참조)를 선택할 수 있습니다.
- `keep_original_sound`: 원본 비디오 오디오를 유지할지 여부이며, `yes`(유지) 또는 `no`(제거)를 선택할 수 있습니다.

> 참고: 참조 비디오가 있는 경우 `generate_audio`는 `false`여야 합니다. `refer_type=base`인 비디오는 시작 프레임 / 종료 프레임을 다시 지정할 수 없습니다.

기존 비디오를 편집하는(비디오를 애니메이션 스타일로 변경하는) CURL 예시는 다음과 같습니다:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### 다중 이미지 참조(`image_list`)

`image_list`는 참조 이미지(요소 / 장면 / 스타일 등)를 전달하는 데 사용되며, 배열 요소 필드는 다음과 같습니다:

- `image_url`: 참조 이미지 링크이며, 비워둘 수 없습니다. 요구사항: .jpg/.jpeg/.png 형식, 파일 크기 ≤10MB, 짧은 변 ≥300px, 화면비 1:2.5 ~ 2.5:1.
- `type`: 선택 사항입니다. 전달하지 않으면 순수 참조 이미지로 사용되며, `first_frame` / `end_frame`을 전달하면 각각 시작 프레임 / 종료 프레임으로 사용됩니다(`start_image_url` / `end_image_url`과 동일).

사용 시 `prompt`에서 `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`로 참조해야 합니다. 수량 제한: 참조 비디오가 없을 경우 참조 이미지 ≤ 7개, 참조 비디오가 있을 경우 참조 이미지 ≤ 4개입니다. 시작 / 종료 프레임만 전달할 때도 `start_image_url` / `end_image_url`을 직접 사용할 수 있지만, 종료 프레임은 반드시 시작 프레임과 함께 사용해야 합니다.

> 참고: `start_image_url` / `end_image_url`과 `image_list`를 동시에 전달하면 시작 / 종료 프레임이 `image_list`보다 앞에 배치되어 `&lt;&lt;<image_N>>>`의 번호 대응 관계에 영향을 줄 수 있습니다. 둘 중 하나를 선택하는 것을 권장합니다. 시작 / 종료 프레임이 필요한 경우 `image_list`에서 직접 `type`으로 지정하고, `start_image_url` / `end_image_url`과 혼용하지 마세요.

다중 이미지 참조로 비디오를 생성하는 CURL 예시:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## 비동기 콜백

Kling Videos Generation API의 생성 시간은 비교적 길며, 약 1~2분이 필요합니다. API가 오랫동안 응답하지 않으면 HTTP 요청이 계속 연결 상태를 유지하여 추가적인 시스템 리소스가 소모될 수 있으므로, 본 API는 비동기 콜백도 지원합니다.

전체 프로세스는 다음과 같습니다: 클라이언트가 요청을 시작할 때 `callback_url` 필드를 추가로 지정합니다. 클라이언트가 API 요청을 시작한 후 API는 즉시 현재 작업 ID를 나타내는 `task_id` 필드 정보를 포함한 결과를 반환합니다. 작업이 완료되면 생성된 비디오 결과는 POST JSON 형식으로 클라이언트가 지정한 `callback_url`로 전송되며, 여기에도 `task_id` 필드가 포함되므로 ID를 통해 작업 결과를 연결할 수 있습니다.

아래 예시를 통해 구체적인 작업 방법을 살펴보겠습니다.

먼저 Webhook 콜백은 HTTP 요청을 수신할 수 있는 서비스이며, 개발자는 자체 구축한 HTTP 서버의 URL로 대체해야 합니다. 여기서는 시연의 편의를 위해 공개 Webhook 예제 사이트 https://webhook.site/를 사용합니다. 해당 사이트를 열면 아래 그림과 같이 Webhook URL을 얻을 수 있습니다:

![](https://cdn.acedata.cloud/tbcnai.png)

이 URL을 복사하면 Webhook으로 사용할 수 있으며, 여기의 예시는 `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`입니다.

다음으로 `callback_url` 필드를 위의 Webhook URL로 설정하고, 동시에 해당 매개변수를 입력할 수 있습니다. 구체적인 내용은 아래 그림과 같습니다:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

실행을 클릭하면 아래와 같이 즉시 결과를 받을 수 있습니다:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

잠시 후 `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`에서 생성된 비디오 결과를 확인할 수 있으며, 아래 그림과 같습니다:

![](https://cdn.acedata.cloud/zv5u2q.png)

내용은 다음과 같습니다:

```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

결과에 `task_id` 필드가 있으며, 다른 필드는 위와 유사합니다. 이 필드를 통해 작업을 연결할 수 있습니다.

## 오류 처리

API 호출 시 오류가 발생하면 API는 해당 오류 코드와 정보를 반환합니다. 예를 들면 다음과 같습니다:

- `400 token_mismatched`: 잘못된 요청이며, 매개변수가 누락되었거나 유효하지 않을 수 있습니다.
- `400 api_not_implemented`: 잘못된 요청이며, 매개변수가 누락되었거나 유효하지 않을 수 있습니다.
- `401 invalid_token`: 인증되지 않음, 인증 토큰이 유효하지 않거나 누락되었습니다.
- `429 too_many_requests`: 요청이 너무 많으며, 속도 제한을 초과했습니다.
- `500 api_error`: 내부 서버 오류이며, 서버에서 문제가 발생했습니다.
### 오류 응답 예시

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
