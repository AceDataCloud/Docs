구체적인 자격 증명은 `allowed_api_ids` 및 애플리케이션 권한 범위의 제한도 받을 수 있습니다.

## 동적 모델 카탈로그

먼저 [모델 카탈로그](https://platform.acedata.cloud/models)를 열어 현재 모델 이름(예: `claude-opus-5`, `gpt-6-sol`)을 확인할 수 있습니다. Coding 자격 증명과 API 프로토콜이 일치하는지 확인해야 할 경우, 유효한 Coding Application 자격 증명을 사용하여 요청하십시오:

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_TOKEN"
```

모델 카탈로그는 지속적으로 변경되며, 이 문서에서는 고정된 수량이나 정적 모델 목록을 유지하지 않습니다. 응답의 각 항목에 있는 `id`는 API `model` 매개변수에 직접 전달할 수 있는 **모델 이름**입니다. 예를 들어 `{"id":"deepseek-v4-pro"}`는 `deepseek-v4-pro`를 입력하는 것에 해당합니다. 이는 서비스, API 또는 Application의 UUID가 아닙니다. `/v1/models`는 전역 모델 카탈로그를 반환하며 Coding 자격 증명에 따라 자동으로 필터링되지 않습니다. 구성 전에 자격 증명 API scope, 선택한 프로토콜 및 클라이언트 호환 범위와 계속해서 교차 확인해야 합니다.

## 일반적인 문제 해결

- **잔액 부족**: [Applications 콘솔](https://platform.acedata.cloud/console/applications)로 이동하여 Coding Application을 찾고 직접 갱신 구매하십시오.
- **클라이언트가 여전히 원래 주소로 요청함**: 구성이 클라이언트를 시작한 동일한 사용자 및 작업 공간에 속하는지 확인하고, 완전히 종료한 후 클라이언트를 다시 시작하십시오.
- **모델 이름을 사용할 수 없음**: `/v1/models`를 다시 요청하고, 입력한 모델 이름이 카탈로그의 `id`와 완전히 일치하는지, 자격 증명 API scope 및 클라이언트가 지원하는 프로토콜을 확인하십시오.
- **Token으로 인터페이스를 호출할 수 없음**: 자격 증명이 Coding Application에 속하는지 확인하고 `allowed_api_ids` 및 애플리케이션 API 권한을 점검하십시오.
