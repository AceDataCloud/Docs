Suno Studio 프로젝트 API는 하나의 엔드포인트를 통해 멀티트랙 음악 프로젝트를 관리합니다:

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
```

요청의 `action`이 작업 유형을 결정합니다. Project 기본 키는 통일하여 `id`를 사용합니다. `version_id`는 현재 프로젝트 버전을 나타내며, 모든 수정 및 내보내기 작업은 최신 버전을 제출해야 동시성 덮어쓰기를 방지할 수 있습니다.

## 작업 개요

| action             | 모드  | 용도                      |
| ------------------ | --- | ----------------------- |
| `create`           | 동기  | 빈 프로젝트 생성                   |
| `retrieve`         | 동기  | 프로젝트 및 전체 편집 가능한 `state` 읽기      |
| `save`             | 동기  | 전체 프로젝트 상태 저장                |
| `upload`           | 비동기  | HTTPS 오디오 주소에서 프로젝트에 추가할 수 있는 소스 초기화 |
| `add_track`        | 비동기  | 기존 오디오를 프로젝트에 추가               |
| `generate_track`   | 비동기  | 지정 구간에 대한 새 오디오 트랙 후보 생성            |
| `replace_section`  | 비동기  | 부분 교체 후보 생성                |
| `commit_candidate` | 비동기  | 선택한 후보를 프로젝트에 커밋             |
| `remove_track`     | 동기  | 지정 트랙 삭제                  |
| `render`           | 비동기  | 저장된 버전을 완성된 곡으로 내보내기           |

비동기 작업은 즉시 `task_id`를 반환합니다. 무료 `/suno/tasks` 인터페이스를 사용하여 폴링하거나, `callback_url`을 전달하여 최종 상태 결과를 수신하세요.

## 생성 및 읽기

```json
{"action":"create","title":"My Studio Project"}
```

모든 수정 작업은 고유한 `Idempotency-Key` Header를 전송해야 합니다. 생성에 성공한 후 응답의 `data.id`는 Project ID입니다. 새로 생성된 빈 프로젝트는 처음 저장하기 전에는 `version_id`가 없을 수 있습니다.

```json
{"action":"retrieve","id":"PROJECT_ID"}
```

읽기 응답에는 전체 `state`가 포함됩니다. 먼저 읽은 다음 반환값을 기반으로 수정하고 저장하는 것을 권장합니다. 내부 박자 및 트랙 구조를 처음부터 수동으로 구성하지 마세요.

## 전체 상태 저장

```json
{
  "action":"save",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "title":"Edited Project",
  "state":{"tracks":[],"timing":{}}
}
```

새로 생성된 빈 프로젝트의 첫 저장에서는 `version_id`를 생략할 수 있습니다. 첫 저장에서 버전이 생성된 후에는 이후 저장 시 반드시 최신 값을 제출해야 합니다. 버전이 이미 변경된 경우, 인터페이스는 HTTP 409를 반환합니다. 이때 다시 `retrieve`하고, 수정을 병합한 후 새 멱등성 키로 제출하세요. 이전 요청을 무작정 재시도하지 마세요.

## 업로드 및 트랙 추가

```json
{
  "action":"upload",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "audio_url":"https://cdn.example.com/reference.mp3",
  "async":true
}
```

업로드가 완료되면 작업 결과는 후보 `audio_id`를 반환합니다. 이후 이를 프로젝트에 추가합니다:

```json
{
  "action":"add_track",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "audio_id":"AUDIO_ID",
  "name":"Backing Vocals"
}
```

## 생성 및 교체

`generate_track`은 프로젝트 구간에 대한 오디오 트랙 후보를 생성합니다. `replace_section`은 두 개의 부분 교체 후보를 반환합니다. 두 작업 모두 예술적 결과를 자동으로 선택하지 않습니다.

```json
{
  "action":"replace_section",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "source_audio_id":"AUDIO_ID",
  "start_seconds":35.12,
  "end_seconds":48.76,
  "model":"chirp-v6",
  "replacement_lyrics":"新的歌词片段",
  "async":true
}
```

후보를 선택한 후 커밋합니다:

```json
{
  "action":"commit_candidate",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "operation_id":"OPERATION_ID",
  "candidate_id":"CANDIDATE_ID",
  "track_id":"TRACK_ID"
}
```

후보는 생성 당시의 프로젝트 버전에 연결됩니다. 프로젝트가 이미 변경된 경우, 이전 후보는 직접 커밋할 수 없습니다.

## 완성된 곡 내보내기

```json
{
  "action":"render",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "title":"Final Mix",
  "lyrics":"[Instrumental]",
  "async":true,
  "callback_url":"https://example.com/webhooks/suno"
}
```

서버는 지정된 버전의 권위 있는 프로젝트 상태를 읽고 내보내기 매개변수를 조합합니다. 최종 상태 결과에는 `render_id`, `audio_id`, `audio_url` 및 길이가 포함됩니다. 프로젝트는 생성 시의 실행 환경에 바인딩되며, 환경 간 마이그레이션 또는 자동 장애 조치를 할 수 없습니다.

> 합법적인 사용 권한을 보유한 오디오만 업로드하거나 처리할 수 있습니다. 프로젝트 API는 현재 Beta입니다. 중요한 결과의 최종 오디오 URL을 영구 저장하세요.
