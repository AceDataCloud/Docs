`POST https://api.acedata.cloud/suno/projects` 는 멀티트랙 프로젝트를 관리하는 Beta 인터페이스입니다. `action`을 통해 생성, 저장, 후보 생성, 후보 제출 및 내보내기를 구분합니다.

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: <每次写操作的新 UUID>
```

`retrieve`를 제외하고, **모든 작업에는** `Idempotency-Key`가 필요합니다. 동일한 키와 동일한 요청은 원래 결과만 다시 읽어오며, 동일한 키에 다른 요청을 사용하면 409를 반환합니다. 유료 생성에서 네트워크 시간 초과가 발생하거나 제출 결과가 불확실한 경우, 먼저 원래 작업 ID 또는 동일한 멱등성 키로 조회해야 하며, 키를 직접 변경하여 재전송할 수 없습니다.

## 식별자 및 시간 단위

| 이름                             | 어디서 가져오는지                                                                                      | 어디에 사용하는지                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | `create` 응답 `data.id`                                                                      | 현재 프로젝트의 모든 후속 요청                                      |
| `version_id`                   | 가장 최근의 `retrieve`, `save`, `add_track`, `commit_candidate` 또는 `remove_track`의 `data.version_id` | 수정, 후보 생성 및 내보내기; 반드시 최신 버전을 사용                              |
| `audio_id` / `source_audio_id` | `upload` 최종 상태의 `response.data.candidate.audio_id`, 또는 기존의 완료된 오디오 ID                                | `add_track`, 생성 또는 교체 시 원본 오디오 참조                          |
| `render_audio_id`              | `render` 최종 상태의 `response.data.audio_id`                                                       | `generate_track`의 프로젝트 믹스 참조                         |
| `operation_id`                 | `generate_track` 또는 `replace_section` 최종 상태의 `response.data.operation_id`                       | `commit_candidate`; 일반적으로 생성 작업의 `task_id`와 동일하지만 반환값을 읽어야 함 |
| `candidate_id`                 | 생성 최종 상태의 `response.data.candidates[].id`                                                       | 하나의 후보를 선택하여 제출                                         |
| `track_id`                     | 프로젝트 `data.state.tracks[].id`                                                                | 후보 제출 또는 트랙 삭제                                        |
| `task_id`                      | 비동기 작업 제출 응답                                                                                   | `/suno/tasks`를 사용하여 최종 상태 조회; 프로젝트 ID가 아님                   |

`start_seconds` / `end_seconds`는 **원본 오디오 내의 초 단위**이며, `start_beats` / `end_beats`는 **프로젝트 타임라인의 박자 수**입니다. `state.timing.bps`는 초당 박자 수이며, 기본값은 2입니다. 예를 들어 41초 길이의 클립이 0박자에서 시작하면 기본 종료 지점은 82박자입니다. `generate_track`의 초 단위 구간은 생성 참조를 지정하는 데 사용되며, 후보가 해당 구간 길이만큼만 생성되는 것을 보장하지 않습니다.

## 작업 흐름

| 순서  | `action`                             | 기능                         | 반환 방식         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | 빈 프로젝트 생성                      | 동기 프로젝트 데이터       |
| 2   | `retrieve`                           | 최신 버전 및 전체 `state` 읽기          | 동기 프로젝트 데이터       |
| 3   | `save`                               | 최초 저장 또는 수정된 `state` 전체 저장      | 동기 프로젝트 데이터       |
| 4   | `upload`                             | HTTPS 오디오 주소에서 소스 생성           | 비동기 작업         |
| 5   | `add_track`                          | 소스 오디오를 프로젝트에 추가                  | 비동기 작업, 버전 업데이트    |
| 6   | `save`                               | 새 트랙 후보를 수신해야 하는 경우, 먼저 빈 대상 트랙 저장        | 동기 프로젝트 데이터, 버전 업데이트  |
| 7   | `render`                             | 현재 청취 가능한 트랙을 내보내고 믹스 참조 `audio_id` 획득 | 비동기 작업         |
| 8   | `generate_track` 또는 `replace_section` | 각각 새 트랙 후보 또는 부분 교체 후보 생성            | 비동기 작업, 프로젝트는 아직 수정하지 않음  |
| 9   | `commit_candidate`                   | 하나의 후보 선택 및 제출                  | 비동기 작업, 성공 후 버전 업데이트 |
| 선택  | `remove_track`                       | 지정된 트랙 삭제                     | 동기 프로젝트 데이터, 버전 업데이트 |

부분 교체만 수행하는 경우 기존에 사용 가능한 원본 오디오가 있으면 되며, 먼저 `render`할 필요가 없습니다. 원본 오디오가 이미 프로젝트에 있다면 `upload`와 `add_track`도 건너뛸 수 있습니다. `render_audio_id`는 `generate_track`에만 필요한 필수 참조입니다.

비동기 작업 제출 시 먼저 `{ "task_id": "...", "trace_id": "..." }`를 반환하며, 이는 **생성 성공을 의미하지 않습니다**. 폴링:

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步返回的 task_id"}
```

작업 기록에 `finished_at`이 있고 그 안의 `response.success`가 `true`여야 성공으로 간주합니다. `response.success=false`인 경우 `response.error`를 읽습니다. `save`는 `task_id`를 포함할 수 있지만, 이 인터페이스 내에서는 동기적으로 완료됩니다. `upload`, `render`, `generate_track`, `replace_section`은 프로젝트 버전을 수정하지 않으며, `save`, `add_track`, `commit_candidate`, `remove_track`가 성공한 후에는 새 `version_id`를 가져와야 합니다.

## 요청 규약

| 파라미터                | 유형 및 적용 범위                                                                                   | 설명                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | 필수 문자열                                                                                     | 이 페이지에 나열된 작업명 중 하나로 고정됩니다. 한 요청은 하나의 작업만 수행합니다.                                      |
| `id`              | `create`를 제외하고 필수 문자열                                                                         | 프로젝트 ID이며, `create.data.id`에서 가져옵니다.                                      |
| `version_id`      | 수정, 후보 생성, 내보내기 시 필수 문자열; 최초 빈 프로젝트의 `save`에서는 생략 가능                                                         | 최신 버전을 사용해야 하며, 이전 버전은 거부됩니다. `retrieve`에는 필요하지 않습니다.                                 |
| `Idempotency-Key` | `retrieve`를 제외하고 필수 요청 헤더, 1–128자                                                              | 각 새 작업에 새 키를 사용합니다. 동일한 키와 동일한 요청은 원래 결과를 다시 읽으며, 다시 생성하거나 과금하지 않습니다.                                   |
| `async`           | `upload`, `add_track`, `generate_track`, `replace_section`, `commit_candidate`, `render`에 선택적 불리언 값 | 이러한 작업은 항상 비동기입니다. `false`도 생성을 동기로 바꾸지 않습니다.                                    |
| `callback_url`    | 비동기 작업에 선택적 URL                                                                                | 최종 상태 알림을 수신합니다. 생략하면 `task_id`로 `/suno/tasks`를 조회합니다. 여전히 `response.success`를 확인해야 합니다. |

아래 예시는 각 작업 간의 ID 및 버전 전달을 연결하여 보여줍니다. 응답에는 현재 단계와 관련된 필드만 나열됩니다. 연동 시 현재 애플리케이션의 응답 값으로 예시 ID를 교체하십시오.

## 프로젝트 상태 저장

| 매개변수 | 유형 및 설명 |
|---|---|
| `state` | 필수 객체. 부분 패치가 아닌 **전체 프로젝트 상태**를 제출합니다. 가장 최근의 읽기 또는 수정 작업에서 반환된 `data.state`를 기반으로 하며, 알 수 없는 필드는 유지합니다. |
| `title` | 선택 문자열; 생략하면 `state.title`을 따르며, 그것도 없으면 기본 제목을 사용합니다. |
| `version_id` | 새 빈 프로젝트를 처음 저장할 때는 생략할 수 있으며, 이후에는 반드시 최신 버전을 사용해야 합니다. |

`state.timing.bps`는 반드시 양수여야 하며, 기본값은 2입니다. `state.tracks`는 트랙 배열입니다. 기존 오디오 클립의 `clipId`는 오디오 ID를 참조하며, `startBeats`, `endBeats`, `readStartBeats`는 프로젝트 비트 단위를 사용합니다. 가장 안전한 편집 방식은 전체 `state`를 읽고, 대상 트랙 또는 클립만 수정한 뒤 전체를 `save`하는 것입니다. 새 빈 대상 트랙에는 최소한 고유한 `id`, `type:"audio"`, `clips:[]`가 있어야 합니다. 완전한 빈 트랙 구조는 “새 오디오 트랙 생성”의 예시를 참조하세요. 오디오 분석 결과의 비트 포인트를 프로젝트 타임라인 좌표로 직접 사용하지 마세요.

## 오디오 업로드 및 트랙 추가

| 작업 | 매개변수 | 유형 및 설명 |
|---|---|---|
| `upload` | `audio_url` | 필수 HTTPS URL이며, 공개적으로 접근 가능하고 귀하가 사용할 권리가 있는 오디오를 가리킵니다. 최종 상태의 `candidate.audio_id`는 트랙 추가에 사용할 수 있습니다. |
| `add_track` | `audio_id` | 필수 문자열; URL이 아닌, 완료된 소스의 오디오 ID입니다. |
| `add_track` | `name`, `color` | 선택 문자열; 트랙 이름은 기본적으로 오디오 제목을 사용하며, 색상은 `#RRGGBB`를 권장하고 기본값은 `#7251F7`입니다. |
| `add_track` | `title` | 선택 문자열; 프로젝트 제목도 동시에 수정하며, 일반적으로 생략합니다. |
| `add_track` | `start_beats`, `end_beats` | 선택적 음수가 아닌 숫자이며, 종료점은 시작점보다 커야 합니다. 기본적으로 0번째 비트에서 시작하며, 종료점은 오디오 길이와 `timing.bps`에 따라 계산됩니다. |
| `add_track` | `gain` | 선택적 음수가 아닌 숫자이며, 기본값은 1입니다. 클립과 트랙의 볼륨 계수입니다. |

## 새 오디오 트랙 생성

후보와 생성 시의 프로젝트 버전은 연결됩니다. 먼저 후보를 받을 빈 트랙을 저장한 다음, 현재 믹스를 생성 참조로 내보냅니다. 생성이 완료된 후 후보 하나를 선택하여 해당 빈 트랙에 제출합니다.

### 대상 트랙 예약: `save`

`generate_track`의 후보는 현재 프로젝트 버전과 연결됩니다. 이전 `add_track` 최종 상태에서 반환된 **전체** `state`에 다음 빈 트랙을 `state.tracks`에 추가한 후 `save`로 저장하세요. 그 외 기존 필드는 그대로 유지합니다:
```
&#123;
"id": "bdec15b5-ce96-43fa-b681-26298e013b06",
"type": "audio",
"name": "Generated piano",
"clips": [],
"takeLanes": [],
"mute": false,
"solo": false,
"amplitude": 1,
"instrument": &#123;
"type": "song"
&#125;,
"color": "#7251F7"
&#125;

```
저장 응답:
```

## 기존 클립 교체

`replace_section`은 먼저 믹스를 내보낼 필요 없이 기존 원본 오디오를 직접 사용할 수 있습니다. 생성은 후보만 반환하며, 제출 시에는 유일한 원본 클립을 포함하는 원래 트랙을 선택합니다.

| 매개변수 | 유형 및 설명 |
|---|---|
| `source_audio_id` | 필수; 교체할 완료된 원본 오디오 ID입니다. |
| `model` | 필수; “후보 생성”에 나열된 공개 모델을 사용하며, 모델 및 작업의 사용 가능 여부는 작업 최종 상태를 기준으로 합니다. |
| `start_seconds`、`end_seconds` | 필수 숫자; `0 ≤ start_seconds < end_seconds ≤ 원본 오디오 길이`; 원본 오디오 내의 초 단위 구간입니다. |

| `fixed` | 선택 불리언 값, 기본값은 `false`; `true`로 설정하면 구간은 26초보다 짧아야 하며, 모델이 지원하지 않을 수 있습니다. |
