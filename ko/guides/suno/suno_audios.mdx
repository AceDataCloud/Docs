AI의 응용이 넓어짐에 따라, 각종 AI 프로그램이 점차 보급되고 있습니다. AI는 점차 사람들의 업무와 생활의 모든 측면에 깊이 들어오고 있습니다. 또한 AI가 관련된 산업도 점점 더 많아지고 있으며, 초기의 글쓰기부터 의료 교육, 그리고 현재의 음악까지 이르고 있습니다.

Suno는 전문적이고 고품질의 AI 노래 및 음악 창작 플랫폼으로, 사용자는 간단한 텍스트 프롬프트만 입력하면 장르 스타일과 가사에 따라 보컬이 포함된 노래를 생성할 수 있습니다. 이 AI 음악 생성기는 Meta, TikTok, Kensho 등 유명 기술 기업 출신의 팀원들이 개발했으며, 어떠한 악기 도구도 필요 없이 모든 사람이 아름다운 음악을 창작할 수 있게 하는 것을 목표로 합니다.

Suno는 현재 `chirp-v6`, `chirp-v6-wild`, `chirp-v6-mini`를 지원합니다. `chirp-v6` 사용을 권장하며, 이전 모델 이름도 계속 호환됩니다.

하지만 Suno 공식은 API를 제공하지 않으며, AceDataCloud는 Suno 공식 연동을 시뮬레이션한 Suno API 세트를 제공하여, 원하는 음악을 편리하고 빠르게 생성할 수 있습니다.

## 기본 사용

어떤 노래를 생각하든, 임의의 텍스트를 입력할 수 있습니다. 예를 들어 크리스마스에 관한 노래를 생성하고 싶다면 `a song for Christmas`를 입력하면 되며, 그림과 같습니다:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

여기에서 Request Headers를 설정한 것을 볼 수 있으며, 다음을 포함합니다:

- `accept`: 어떤 형식의 응답 결과를 받고 싶은지이며, 여기서는 `application/json`, 즉 JSON 형식으로 입력합니다.
- `authorization`: API를 호출하는 키이며, 신청 후 직접 드롭다운에서 선택할 수 있습니다.

또한 Request Body를 설정했으며, 다음을 포함합니다:
- `action`: 이번 음악 생성 작업의 동작이며, 기본값은 `generate`이고, 주로 다음을 포함합니다: `extend`, `upload_extend`, `cover`, `upload_cover`, `replace_section`, `replace_section`, `concat`, `stems`, `all_stems`, `remaster`.
- `prompt`: Suno 공식 영감 모드 프롬프트(`custom`이 `false`일 때 적용), 최대 500자.
- `model`: 이번 음악 생성 작업의 모델입니다. v6 시리즈에는 `chirp-v6`, `chirp-v6-wild`, `chirp-v6-mini`가 포함되며, 이전 모델 이름도 계속 호환됩니다.
- `lyric`: Suno 공식 사용자 지정 모드의 가사 내용입니다. `chirp-v3-5` 및 `chirp-v4`는 최대 3000자이며, `chirp-v4-5` 이상(`chirp-v5`, `chirp-v5-5` 포함)은 최대 5000자입니다.
- `custom`: 사용자 지정 모드 사용 여부이며, 기본값은: `false`입니다.
- `instrumental`: Suno 공식 영감 모드의 순수 음악 옵션입니다.
- `title`: Suno 공식 사용자 지정 모드의 음악 제목입니다. `chirp-v3-5`, `chirp-v4`는 최대 80자이며, `chirp-v4-5` 이상은 최대 100자입니다.
- `style`: Suno 공식 사용자 지정 모드의 음악 스타일입니다. `chirp-v3-5` 및 `chirp-v4`는 최대 200자이며, `chirp-v4-5` 이상(`chirp-v5`, `chirp-v5-5` 포함)은 최대 1000자입니다.
- `negative_tags`: 사용자 지정 모드(`custom`이 `true`)에서 생성 결과에서 제외하고 싶은 음악 스타일 또는 장르입니다.
- `audio_weight`: 업로드한 참고 오디오의 비율이며, 범위는 0-1이고, 클수록 참고 오디오에 더 의존합니다.
- `audio_id`: 참고 음악의 ID입니다.
- `overpainting_start`/`overpainting_end`: 기존 순수 음악에 보컬을 보충하는 시작 및 종료 시간이며, 단위는 초입니다.
- `underpainting_start`/`underpainting_end`: 아카펠라에 반주를 추가하는 시작 및 종료 시간이며, 단위는 초입니다.
- `persona_id`: 아티스트의 곡 ID입니다.
- `continue_at`: 이어쓰기 경계이며, 단위는 초입니다. 예를 들어, 213.5는 3분 33.5초 지점부터 후속 구간 생성을 시작함을 의미합니다. `lyric`과 `style`은 경계 이후의 새 내용만 안내하며, 원본 오디오에서 경계 이전의 가사 또는 보컬은 대체하지 않습니다.
- `style_influence`: 사용자 지정 모드의 「Style Influence」고급 매개변수이며, 범위는 0-1이고, 클수록 선택한 스타일에 더 부합합니다.
- `replace_section_end`: 교체 구간의 최종 시간입니다.
- `replace_section_start`: 교체 구간의 시작 시간입니다.
- `vocal_gender`: 남녀 보컬 선호도를 제어하며, 여성 보컬은 `f`, 남성 보컬은 `m`이고, 4.5 이상 모델에서 유효합니다. 선호 항목이므로 엄격한 준수를 보장하지 않습니다.
- `weirdness`: 사용자 지정 모드의 「Weirdness」고급 매개변수이며, 범위는 0-1이고, 클수록 더 창의적이고 실험적입니다.
- `duration`: 원하는 곡 길이이며, 단위는 초이고 정수여야 하며, 값 범위는 10에서 360입니다. 이 매개변수는 사용자 지정 모드(`custom`이 `true`)의 곡 생성에 사용됩니다. 이는 강제 제약이 아닌 경향성 프롬프트입니다: 모델은 이를 참고하지만 달성을 보장하지 않으며, 실제 완성곡 길이는 응답의 `duration` 필드를 기준으로 하고, 일반적으로 기대값보다 짧습니다.
- `lyric_prompt`: 가사를 생성하는 prompt이며, `custom`이 `true`이고 `lyric`이 전달되지 않았을 때에만 적용됩니다.
- `callback_url`: 결과 콜백이 필요한 URL입니다.
- `async`: 선택 사항이며, `true`로 설정하면 인터페이스가 즉시 `task_id`를 반환하고 `callback_url`을 제공할 필요가 없으며, 이후 해당 작업 조회 인터페이스를 통해 폴링하여 결과를 가져옵니다.

## 사용자 지정 생성

가사를 사용자 지정하여 생성하려면 가사를 입력할 수 있습니다:

이때 `lyric` 필드에는 다음과 유사한 내용을 전달할 수 있습니다:

```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> 참고로, 여기 가사에서 `\n`은 줄바꿈 문자입니다. 가사를 어떻게 생성해야 할지 모르는 경우, AceDataCloud가 제공하는 가사 생성 API를 사용하여 prompt를 통해 가사를 생성할 수 있으며, API는 [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics)입니다.

다음으로 가사, 제목, 스타일에 따라 노래를 사용자 지정하여 생성하려면 다음 내용을 지정할 수 있습니다:

- lyric: 가사 텍스트
- custom: `true`로 입력하면 사용자 지정 생성을 의미하며, 이 매개변수의 기본값은 false로, `prompt`를 사용한 생성을 의미합니다.
- title: 노래 제목입니다.
- style: 노래 스타일이며, 선택 사항입니다.

## 사용자 지정 가수 스타일 생성 기능
가수 스타일을 사용하여 노래를 생성하려면, 먼저 위의 기본 사용법을 통해 노래를 생성하고,
마지막으로 이 노래를 가수 스타일로 설정해야 합니다. 그런 다음 [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona)에 들어가 공식적으로 생성된 음악 ID `audio_id`를 기반으로 가수 스타일의 id 파라미터 `persona_id`를 생성해야 하며, 구체적인 파라미터는 아래 그림과 같습니다:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

작성 완료 후 자동으로 생성된 코드는 다음과 같습니다:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

해당 Python 코드:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)

```

## 계속 생성 기능

이미 생성된 Suno 노래를 계속 생성하려면 파라미터 `action`을 `extend`로 설정하고, 계속 생성해야 하는 노래의 ID를 입력할 수 있습니다. 노래 ID는 기본 사용법을 통해 가져오며, 위의 내용을 통해 이때 노래의 ID가 다음과 같음을 확인할 수 있습니다:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> 주의: 여기에서 가사 중 `id`는 생성 후 노래의 ID입니다. 노래를 생성하는 방법을 모르는 경우, 위의 기본 사용법을 참고하여 노래를 생성할 수 있습니다.

직접 업로드한 노래를 계속 생성하려면 파라미터 `action`을 `upload_extend`로 설정하고, 계속 생성해야 하는 사용자 지정 업로드 노래 ID를 입력할 수 있습니다. 노래 ID는 [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload)를 사용하여 가져오며, 아래 그림과 같습니다:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

다음으로 반드시 이어 쓸 구간의 가사를 작성해야 하며, 스타일을 지정할 수도 있습니다:

- lyric: `continue_at` 이후 새로 생성되는 구간의 가사를 안내하는 데에만 사용되며, 원본 오디오에서 해당 시점 이전의 가사를 대체하지 않습니다.
- custom: `true`로 작성하면 사용자 지정 생성을 의미하며, 이 파라미터의 기본값은 false로, `prompt`를 사용하여 생성을 의미합니다.
- style: 이어 쓸 구간의 노래 스타일이며, 선택 사항입니다.
- continue_at: 이어 쓰기 경계이며, 단위는 초입니다. 예를 들어 213.5는 3분 33.5초 지점부터 후속 구간을 생성하는 것을 의미합니다.

> `extend`는 기존 노래에 이어서 뒤로 창작하는 데 사용되며, 전체 노래의 가사를 바꾸는 용도가 아닙니다. 전체 노래를 처음부터 새 가사로 만들고 싶다면 `generate`를 사용하여 다시 생성하십시오. 기존 노래를 참고하여 다시 연주하고 싶다면 `cover`를 사용할 수 있습니다. 전체 새 가사를 전달하더라도 `continue_at` 이전의 원래 가사는 여전히 대체되지 않습니다.

## 구간 교체

노래를 생성한 후 노래 구간을 교체하는 단독 작업의 2차 창작이 필요할 때, 노래의 특정 구간을 교체할 수 있습니다.

> ⚠️ **주의**：`replace_section_result_mode`의 기본값은 `full_song`입니다. 시스템은 새로 생성된 2개의 후보를 각각 연결하고, 완전한 노래 2곡을 반환합니다. 아직 연결되지 않은 교체 구간 후보만 필요한 경우, 명시적으로 `candidates`로 설정한 후 후보를 선택하여 [음악 연결](#음악-연결)을 호출하세요.

매개변수 설명은 다음과 같습니다:

- action：내용은 `replace_section`입니다.
- audio_id：원본 노래(교체되는 소스 노래)의 ID.
- model: 노래 생성 모델.
- lyric: 교체 후의 전체 가사(교체된 구간 및 그 문맥 포함, `prompt`의 내용과 일치하게 유지).
- prompt：교체해야 하는 해당 구간의 새 가사.
- style：노래의 스타일, 선택 사항.
- replace_section_start：원곡에서 교체되는 구간의 시작 시간(초).
- replace_section_end：원곡에서 교체되는 구간의 종료 시간(초).
- replace_section_result_mode：반환 모드이며, 기본값은 `full_song`입니다. `full_song`은 2개의 후보를 각각 연결하여 완전한 노래 2곡을 반환하며, `candidates`는 아직 연결되지 않은 후보 구간 2개를 반환합니다.

### 단계 1: 구간 교체 작업 시작

## 노래 길이 제어

기본적으로 생성되는 노래의 길이는 모델이 자체적으로 결정하며, 일반적으로 30초에서 4분 사이입니다. 더 길거나 더 짧은 완성본이 필요한 경우 `duration` 매개변수를 통해 원하는 길이를 지정할 수 있으며, 단위는 초이고 값은 10에서 360 사이의 정수입니다.

이 매개변수는 사용자 지정 모드(`custom`이 `true`)의 노래 생성에 사용됩니다. 특히 설명할 점은 `duration`이 **경향성 힌트이지, 강제 제약이 아니라는 것**입니다: 모델은 창작 시 이 값을 참고하지만, 도달을 보장하지는 않습니다. 실제 테스트에서 실제 길이는 일반적으로 기대값보다 현저히 짧으며, 동일한 요청에서 반환된 두 곡의 길이도 몇 배 차이 날 수 있습니다. 완전히 동일한 요청이라도 여러 번 제출하여 얻는 길이에 큰 차이가 있을 수 있습니다. 따라서 이를 정확한 길이 제어로 사용하지 마십시오. 비즈니스상 고정된 길이가 필요한 경우, 완성본을 받은 후 직접 자르거나 재시도하십시오.

해당 Python 코드:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

주의할 점은 요청의 `duration`은 **기대 길이**이고, 응답 `data` 내 각 노래의 `duration` 필드는 해당 노래의 **실제 길이**라는 것입니다. 두 값은 이름은 같지만 의미가 다르며, 실제 길이가 기대값과 같다고 보장되지 않습니다. 가사 길이는 완성본 길이에 영향을 미치는 주요 요인 중 하나이므로, 더 긴 완성본이 필요한 경우 더 완전한 가사를 함께 제공하는 것이 좋습니다.

인터페이스는 `duration`에 대해 추가 검증을 하지 않으며, 매개변수는 그대로 모델에 전달됩니다. 현재 모드 또는 모델이 지원하지 않는 값을 전달하면 해당 값이 무시되는 형태로 나타날 수 있으므로, 대량으로 사용하기 전에 먼저 한 번의 요청으로 효과를 확인하는 것이 좋습니다.

- audio_id：업로드한 반주 없는 아카펠라 노래 ID입니다.
- custom：이 모드에서는 반드시 사용자 지정 모드로 가사를 입력해야 합니다.
- lyric：사용자 지정 모드에서 작성하는 가사입니다.

## Inspo 영감 창작 기능

Inspo 영감 창작 기능은 1개에서 4개의 완전한 참고 오디오를 기반으로 새로운 음악을 생성할 수 있으며, 오디오를 드래그 앤 드롭하거나 업로드하여 영감의 원천으로 사용할 수 있습니다. API는 기존 `inspo` action을 사용합니다. 클라이언트는 공개적으로 접근 가능한 오디오 URL을 제공하면 되며, 서비스가 참고 오디오 준비와 창작을 자동으로 완료하므로 클라이언트가 가사, 스타일 또는 길이를 각각 읽어 요청을 조합할 필요가 없습니다. 이는 위의 구간 샘플링과도 다르고, 원곡 스타일을 복제하는 Cover와도 다릅니다. 사용할 때는 다음 매개변수를 입력해야 합니다:

- action: 내용은 `inspo`입니다.
- audio_urls: 참고 오디오의 URL 목록이며, 공개적으로 접근 가능한 오디오 주소를 1개에서 4개 제공해야 합니다.
- model: 사용하는 모델이며, `chirp-v6`를 권장합니다.
- prompt: 가사 또는 창작 프롬프트(선택 사항).

> 참고: 참고 오디오는 공개적으로 접근 가능한 오디오 파일이어야 합니다. 참고 오디오가 플랫폼 음악 라이브러리의 알려진 녹음과 완전히 일치하는 경우, Suno는 저작권 검증으로 인해 생성을 거부할 수 있으므로 자체 소유하거나 Suno가 생성한 오디오를 영감의 원천으로 사용하는 것이 좋습니다.

해당 Python 코드:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## 비동기 콜백

Suno가 음악을 생성하는 시간은 비교적 길며, 약 1~2분이 소요됩니다. API가 장시간 응답하지 않으면 HTTP 요청은 계속 연결 상태를 유지하게 되어 추가적인 시스템 리소스가 소모되므로, 본 API는 비동기 콜백도 지원합니다.

전체 프로세스는 다음과 같습니다. 클라이언트가 요청을 시작할 때 추가로 `callback_url` 필드를 지정합니다. 클라이언트가 API 요청을 시작한 후 API는 즉시 현재 작업 ID를 나타내는 `task_id` 필드 정보를 포함한 결과를 반환합니다. 작업이 완료된 후 음악 생성 결과는 POST JSON 형식으로 클라이언트가 지정한 `callback_url`에 전송되며, 이 안에도 `task_id` 필드가 포함되어 있어 작업 결과를 ID를 통해 연결할 수 있습니다.
