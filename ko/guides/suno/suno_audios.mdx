AI의 활용이 넓어짐에 따라, 각종 AI 프로그램이 점차 보급되고 있습니다. AI는 사람들의 업무와 생활의 모든 측면에 점차 깊이 들어오고 있습니다. 그리고 AI가 관련된 산업도 점점 더 많아지고 있으며, 초기의 글쓰기부터 의료 교육, 그리고 현재의 음악에 이르기까지 확장되고 있습니다.

Suno는 전문적이고 고품질의 AI 노래 및 음악 창작 플랫폼으로, 사용자는 간단한 텍스트 프롬프트만 입력하면 장르 스타일과 가사에 따라 보컬이 포함된 노래를 생성할 수 있습니다. 이 AI 음악 생성기는 Meta, TikTok, Kensho 등 유명 기술 기업의 팀원들이 개발했으며, 어떠한 악기 도구도 필요 없이 모든 사람이 아름다운 음악을 창작할 수 있도록 하는 것을 목표로 합니다.

다음은 모델 업데이트 진행 상황입니다:

| ------- | --------------- | ---------- | -------- | -------- | ------ |

> 위 표의 `lyric` 및 `style` 제한은 사용자 정의 모드(`custom`이 `true`)에서의 상한입니다. 비사용자 정의 영감 모드(`custom`이 `false`)에서는 `prompt`만 입력하며, 그 길이 상한은 500자입니다(모든 모델 동일).

Suno는 현재 `chirp-v6`, `chirp-v6-wild`, `chirp-v6-mini`를 지원합니다. `chirp-v6` 사용을 권장하며, 이전 모델 이름도 계속 호환됩니다.

그러나 Suno 공식은 API를 제공하지 않으며, AceDataCloud는 Suno 공식 연동을 시뮬레이션한 Suno API 세트를 제공하여 원하는 음악을 편리하고 빠르게 생성할 수 있습니다.

## 신청 및 사용

Suno Audios Generation API를 사용하려면 먼저 [Ace Data Cloud 콘솔](https://platform.acedata.cloud/console/applications)에서 API Token을 받아 예비로 보관하세요.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

아직 로그인하거나 가입하지 않았다면, 로그인 페이지로 자동 이동하여 가입 및 로그인을 안내하며, 완료 후 현재 페이지로 자동 돌아옵니다.

**하나의 API Token으로 플랫폼의 모든 서비스를 호출할 수 있으며, 서비스마다 별도로 신청할 필요가 없습니다.** 최초 신청 시 무료 할당량이 제공되어 무료로 체험할 수 있으며, 할당량이 부족할 경우 [콘솔](https://platform.acedata.cloud/console/coin)에서 범용 잔액을 충전할 수 있습니다.

> 📘 전체 문서: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## 기본 사용

어떤 노래를 생각하든, 임의의 문장을 입력할 수 있습니다. 예를 들어 크리스마스에 관한 노래를 생성하고 싶다면 `a song for Christmas`를 입력할 수 있으며, 그림과 같습니다:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

여기에서 Request Headers를 설정한 것을 볼 수 있으며, 다음을 포함합니다:

- `accept`: 어떤 형식의 응답 결과를 받고 싶은지이며, 여기서는 `application/json`, 즉 JSON 형식으로 입력합니다.
- `authorization`: API를 호출하는 키이며, 신청 후 직접 드롭다운에서 선택할 수 있습니다.

또한 Request Body를 설정했으며, 다음을 포함합니다:
- `action`: 오디오 작업 유형이며, 기본값은 `generate`입니다. 생성, 이어쓰기, 커버, 결합, 스템 분리, 오디오 트랙 추가, 지정 오디오 트랙 추출, 음향 효과 생성 및 속도 조절 등의 작업을 지원하며, 모두 `POST /suno/audios`를 통해 호출합니다.
- `prompt`: Suno 공식 영감 모드의 프롬프트 단어입니다(`custom`이 `false`일 때 적용). 최대 500자입니다.
- `model`: 이번 음악 생성 작업의 모델입니다. v6 시리즈에는 `chirp-v6`, `chirp-v6-wild`, `chirp-v6-mini`가 포함되며, 이전 모델 이름도 계속 호환됩니다.
- `max_mode`: 향상된 생성 모드입니다. `generate`는 `custom`과 `max_mode`가 모두 `true`일 때만 활성화되며, 비용은 1.12 Credits입니다. `add_stem`은 직접 활성화할 수 있으며, 비용은 1.344 Credits입니다. 비활성화하거나 생략할 경우 각각 0.56 및 0.672 Credits입니다.
- `variety`: 생성 결과의 다양성 강도이며, `off`, `normal`, `high`, `extra`, `max` 중에서 선택할 수 있습니다. `generate` 및 `add_stem`에만 사용되며, 다른 action에 전달하면 400이 반환됩니다.
- `lyric`: Suno 공식 사용자 지정 모드의 가사 내용입니다. `chirp-v3-5` 및 `chirp-v4`는 최대 3000자이며, `chirp-v4-5` 이상(`chirp-v5`, `chirp-v5-5` 포함)은 최대 5000자입니다.
- `custom`: 사용자 지정 모드를 사용할지 여부이며, 기본값은 `false`입니다.
- `instrumental`: Suno 공식 영감 모드의 순수 음악 옵션입니다.
- `title`: Suno 공식 사용자 지정 모드의 음악 제목입니다. `chirp-v3-5`, `chirp-v4`는 최대 80자이며, `chirp-v4-5` 이상은 최대 100자입니다.
- `style`: Suno 공식 사용자 지정 모드의 음악 스타일입니다. `chirp-v3-5` 및 `chirp-v4`는 최대 200자이며, `chirp-v4-5` 이상(`chirp-v5`, `chirp-v5-5` 포함)은 최대 1000자입니다.
- `negative_tags`: 사용자 지정 생성 시 제외하고 싶은 음악 스타일 또는 장르이며, `replace_section`에도 사용할 수 있습니다. 현재 이 인터페이스는 해당 필드에 고정 문자 수 제한을 설정하지 않았습니다. 너무 긴 내용은 여전히 처리하지 못할 수 있으므로, 설명을 간결하게 유지하는 것이 좋습니다.
- `audio_weight`: 오디오 또는 음성 특징의 영향 가중치이며, 범위는 0-1이고 `0`도 유효한 값입니다. 생성, 이어쓰기, 커버, 오디오 트랙 추가 및 음성 일관성 등의 작업에 사용할 수 있습니다. 참조 오디오 또는 음성 특징이 없으면 모델이 이 값을 약화하거나 무시할 수 있습니다.
- `audio_id`: 커버, 이어쓰기, 스템 분리 등의 후속 작업에 사용하는 참조 음악의 ID입니다. 오디오 파일을 계속 다운로드할 수 있다고 해서 해당 ID의 후속 처리가 항상 가능하다는 의미는 아닙니다. `suno_processing_unavailable`이 반환되면 `task_id`와 `trace_id`를 보관하여 지원팀에 문의하십시오.
- `overpainting_start`/`overpainting_end`: 기존 순수 음악에 보컬을 추가하는 시작 및 종료 시간이며, 단위는 초입니다.
- `underpainting_start`/`underpainting_end`: 아카펠라에 반주를 추가하는 시작 및 종료 시간이며, 단위는 초입니다.
- `persona_id`: Persona 또는 음성 생성 인터페이스를 통해 얻은 음성 ID이며, 노래의 `audio_id`가 아닙니다.
- `continue_at`: 이어쓰기 경계이며, 단위는 초입니다. 예를 들어, 213.5는 3분 33.5초 지점부터 후속 구간을 생성함을 의미합니다. `lyric` 및 `style`은 경계 이후의 새 콘텐츠만 안내하며, 소스 오디오에서 경계 이전의 가사 또는 노래를 대체하지 않습니다.
- `style_influence`: 사용자 지정 모드에서의 스타일 영향력이며, 범위는 0-1입니다. 값이 클수록 일반적으로 선택한 스타일에 더 부합하며, `0`도 유효한 값으로 전달됩니다.
- `replace_section_end`: 교체 구간의 최종 시간입니다.
- `replace_section_start`: 교체 구간의 시작 시간입니다.
- `vocal_gender`: 남성 및 여성 보컬 선호를 제어하며, 여성 보컬은 `f`, 남성 보컬은 `m`이고, 4.5 이상 모델에서 유효합니다. 선호 항목이므로 엄격한 준수를 보장하지 않습니다.
- `weirdness`: 사용자 지정 모드에서의 기이함 정도이며, 범위는 0-1입니다. 값이 클수록 일반적으로 더 창의적이고 실험적이며, `0`도 유효한 값으로 전달됩니다.
- `duration`: 기대하는 노래 길이이며, 단위는 초이고 정수여야 하며, 값 범위는 10에서 360입니다. 현재 `generate`만 이 매개변수를 사용하며, 구체적인 효과는 모드와 모델에 따라 달라집니다. 이는 강제 제약이 아닌 경향성 프롬프트입니다. 모델은 이를 참고하지만 달성을 보장하지 않으며, 실제 결과물 길이는 응답의 `duration` 필드를 기준으로 하고 일반적으로 기대값보다 짧습니다.

### 음성 ID의 적용 범위

`generate`, `cover`, `upload_cover`, `artist_consistency`, `artist_consistency_vox`는 `persona_id`를 사용할 수 있습니다. 마지막 두 action은 반드시 `persona_id`를 제공해야 하며, 해당 Persona 생성 시 사용한 노래의 `audio_id`도 동시에 제공할 수 있습니다.

`extend`, `upload_extend`는 추가 `persona_id`를 사용하지 않습니다. `mashup`, `inspo`가 음성 ID를 지원하는지는 선택한 서비스 채널에 따라 달라집니다. 다른 action은 이 필드의 적용을 보장하지 않으므로 각 작업 설명에 따라 사용하십시오. `vocal_gender`는 선택 가능한 성별 선호이며, 음성 ID를 대체할 수 없습니다.

후속 창작 작업에는 유효한 소스 `audio_id`가 필요하며, `mashup`에는 최소 두 개의 `mashup_audio_ids`가 필요합니다. 필요한 소스 또는 시간 매개변수가 없으면 HTTP 400이 반환됩니다.

### 고급 매개변수 적용 범위
| 매개변수                | 값                                          | 지원되는 action                              | 설명                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | 선택 사항                                      | 실험성을 조절하며, `0`은 유효한 값입니다. 효과는 작업, 모드 및 모델에 따라 달라집니다      |
| `style_influence` | 0-1                                         | 선택 사항                                      | 스타일 준수 경향을 조절하며, `0`은 유효한 값입니다. 효과는 작업, 모드 및 모델에 따라 달라집니다   |
| `audio_weight`    | 0-1                                         | 선택 사항                                      | 오디오 또는 음성 특징의 영향을 조절합니다. 참조 정보가 없으면 모델에서 무시될 수 있습니다        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`, `add_stem`                   | 결과 간의 스타일 다양성을 조절합니다                       |
| `max_mode`        | boolean                                     | `generate`(`custom=true` 필요), `add_stem` | 일관성을 강화하고 강화 모드로 과금됩니다                     |
| `vocal_gender`    | `f` / `m`                                   | 보컬 제어를 지원하는 생성 작업                             | 선호 항목이며, 엄격한 준수를 보장하지 않습니다                       |
| `duration`        | 정수 10-360                                   | `generate`                              | 기대 길이입니다. 다른 action은 현재 이 필드를 사용하지 않으며, 실제 길이는 결과를 기준으로 합니다 |

플랫폼은 매개변수 유형과 값 범위를 검증하지만, action이 다르다는 이유만으로 이러한 선택적 조절 항목을 거부하지는 않습니다. 구체적인 효과는 작업, 모드 및 모델에 따라 결정됩니다.

- `lyric_prompt`: 가사를 생성하는 prompt이며, `custom`이 `true`이고 `lyric`이 전달되지 않았을 때에만 적용됩니다.
- `callback_url`: 결과를 콜백으로 받을 URL입니다.
- `async`: 선택 사항이며, `true`로 설정하면 인터페이스가 즉시 `task_id`를 반환하고 `callback_url`을 제공할 필요가 없습니다. 이후 해당 작업 조회 인터페이스를 통해 폴링하여 결과를 가져옵니다.

이때 두 곡의 내용을 얻을 수 있으며, 제목, 미리보기 이미지, 가사, 오디오, 비디오 등의 내용을 포함합니다.

필드 설명은 다음과 같습니다:

- success: 생성 성공 여부이며, 성공하면 `true`, 그렇지 않으면 `false`입니다.
- data: 생성된 노래의 상세 정보를 포함하는 목록입니다.
  - state: 노래 생성 상태이며, 주로 다음의 네 가지를 포함합니다:
    - succeeded: 생성 성공
    - pending: 대기열에 있음
    - running: 실행 중
    - error: 실패
  - id: 노래 ID
  - title: 노래 제목
  - image_url: 노래의 커버 이미지
  - lyric: 노래 가사
  - audio_url: 노래의 최종 오디오 주소입니다. 플랫폼은 Ace Data Cloud CDN 주소를 우선 반환합니다. 영구 저장에 실패하면 원본 미디어 주소가 반환될 수 있으므로, 즉시 다운로드하세요.
  - video_url: 노래의 비디오 파일이며, 열면 mp4 비디오입니다.
  - created_at: 생성 시간
  - model: 사용한 모델이며, 일반적으로 최신 v3 모델입니다.
  - style: 스타일

## 계속 생성 기능
이미 생성된 Suno 노래를 이어서 생성하려면 매개변수 `action`을 `extend`로 설정하고, 이어서 생성해야 하는 노래의 ID를 입력할 수 있습니다. 노래 ID는 기본 사용법에 따라 획득하며, 위 내용을 통해 이때 노래의 ID가 다음과 같음을 확인할 수 있습니다:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> 참고로, 여기 가사에서의 `id`는 생성 후 노래의 ID입니다. 노래를 생성하는 방법을 모르는 경우, 위의 기본 사용법을 참고하여 노래를 생성할 수 있습니다.

직접 업로드한 노래를 이어서 생성하려면 매개변수 `action`을 `upload_extend`로 설정하고, 이어서 생성해야 하는 사용자 지정 업로드 노래 ID를 입력할 수 있습니다. 노래 ID는 [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload)를 사용하여 획득하며, 아래 그림과 같습니다:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

다음으로 반드시 이어쓰기 구간의 가사를 작성해야 하며, 스타일을 지정할 수도 있습니다:

- lyric: `continue_at` 이후 새로 생성되는 구간의 가사를 안내하는 데만 사용되며, 원본 오디오에서 해당 시점 이전의 가사를 대체하지 않습니다.
- custom: `true`로 작성하면 사용자 지정 생성을 의미하며, 이 매개변수는 기본값이 false이고, `prompt`를 사용하여 생성함을 의미합니다.
- style: 이어쓰기 구간의 노래 스타일이며, 선택 사항입니다.
- continue_at: 이어쓰기 경계이며, 단위는 초입니다. 예를 들어, 213.5는 3분 33.5초 지점부터 후속 구간을 생성함을 의미합니다.

`extend`와 `upload_extend`의 `continue_at`는 반드시 0보다 커야 하며, `30.792`와 같은 소수 초를 지원합니다. 제출 시 반올림되지 않습니다.

> `extend`는 기존 노래를 이어서 뒤로 창작하는 데 사용되며, 전체 노래의 가사를 바꾸는 기능이 아닙니다. 전체 노래를 처음부터 새 가사로 만들고 싶다면 `generate`를 사용하여 다시 생성하세요. 기존 노래를 참고하여 다시 연주하고 싶다면 `cover`를 사용할 수 있습니다. 전체 새 가사를 전달하더라도 `continue_at` 이전의 원래 가사는 여전히 대체되지 않습니다.

작성을 완료하면 다음과 같이 코드가 자동 생성됩니다:

## 완성된 노래 가져오기
현재 모델의 `extend` 결과에는 일반적으로 `continue_at` 이전의 원본 오디오와 경계 이후의 새 콘텐츠가 이미 포함되어 있으므로, 먼저 반환된 오디오의 실제 길이와 내용을 기준으로 이미 완전한 노래인지 판단하세요. 반환된 것이 독립적인 이어쓰기 조각이거나 여러 번의 이어쓰기 이력을 명시적으로 하나의 노래로 병합해야 하는 경우에만 연결 기능을 사용하세요:

- action: 내용은 `concat`입니다.
- audio_id: 마지막 이어쓰기 조각의 ID입니다.

예를 들어 확장 후 노래 ID가 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98인 경우, 다음과 같이 매개변수를 설정할 수 있습니다:

```json
{
  "action": "concat",
  "audio_id": "0a1e1b10-c36a-41c9-9bfb-b26d9d25db98"
}
```

다른 매개변수는 변경하지 않으며, 반환되는 것은 하나의 완전한 노래, 즉 모든 노래 조각을 연결한 결과입니다. 단, 결과는 하나의 노래만 있으며, 예시는 다음과 같습니다:

  "data": [
    {
      "id": "0efec7e0-11bf-4313-9981-2c0e7218d7dd",

## 음악 커버

기존 노래를 기반으로 계속 노래를 생성한 후, 반환된 노래의 스타일이 적절하지 않을 수 있습니다. 이전에 생성한 노래(사용자 지정 업로드 음악도 지원)를 커버하려면 음악 커버 방법을 사용해야 하며, 다음과 같이 내용을 지정할 수 있습니다:

- action: 내용은 `cover`이며, 사용자 지정 업로드 음악에 대해 커버 작업을 수행하는 경우에는 반드시 `upload_cover`로 지정해야 합니다.
- audio_id: 이전에 생성한 노래의 ID입니다.

지정된 목소리로 커버하려면 `persona_id`도 함께 전달할 수 있습니다. `/suno/voices`를 통해 생성한 비공개 목소리는 먼저 `/suno/upload`에서 동일한 `persona_id`를 포함하여 원곡을 업로드한 후, 반환된 `audio_id`를 사용하여 `upload_cover`를 수행해야 합니다. 각 단계에서는 동일한 서비스 채널을 사용해야 합니다. `vocal_gender`를 추가로 지정할 필요는 없으며, 성별 선호도는 목소리 ID를 대체할 수 없습니다.

## 구간 교체

`replace_section`은 원본 노래의 시간 구간을 기준으로 선택한 조각을 다시 생성하고, 결과를 원곡에 다시 연결합니다. `replace_section_result_mode`의 기본값은 `full_song`이며, 완전한 노래 2곡을 반환하므로 직접 재생할 수 있고 `concat`을 다시 호출할 필요가 없습니다.

### 입력은 어떻게 작성하나요
- `action`: `replace_section`.
- `audio_id`: 편집할 완성된 곡 ID입니다. 다시 편집할 때는 `task_id`가 아니라, 이전에 선택한 완성된 곡의 `data[].id`를 사용합니다.
- `model`: 곡 생성 모델입니다. 예: `chirp-v6`.
- `lyric`: 선택 구간에서 부를 **부분 새 가사**입니다. 완성된 곡을 얻기 위해 전체 가사를 전달할 필요는 없습니다.
- `prompt`: 이번 교체의 부분 새 가사를 명확히 지정합니다. 가사를 변경할 때는 두 필드가 서로 다른 가사를 표현하지 않도록 `lyric`와 동일한 내용을 입력하는 것이 권장됩니다. 이미 부분 `lyric`만 전달하고 `prompt`를 생략한 요청도 계속 사용할 수 있지만, `prompt`를 추가하는 것 자체가 가사 변경 성공을 보장하지는 않습니다.
- `style`, `negative_tags`: 선택적인 스타일 설명과 제외 항목입니다. 이 작업에서 `prompt`는 일반 곡 생성 시의 영감 설명이 아닙니다.
- `replace_section_start`, `replace_section_end`: 이번 원본 곡에서 선택 구간의 시작 및 종료 시간이며, 단위는 초이고 소수를 지원합니다. 시작점은 0보다 작을 수 없고, 종료점은 시작점보다 커야 하며 원본 곡 길이를 초과할 수 없습니다.
- `replace_section_result_mode`: `full_song`(기본값)은 완성된 곡 2개를 반환하고, `candidates`는 아직 연결되지 않은 교체 후보 2개를 반환합니다.

“`lyric`는 교체 후의 전체 가사여야 하고, `prompt`는 부분 가사여야 한다”를 일반적인 사용법으로 간주하지 마세요. 전체 가사를 입력하면 일부 작업에서 교체 내용이 너무 길어져, 연결 후 전체 곡이 현저히 길어질 수 있습니다. 부분 입력도 고정된 길이 또는 가사를 한 글자씩 따르는 것을 보장하지 않습니다. 이것은 생성형 편집이므로 실제 오디오를 확인해야 합니다.

### 작업 시작 및 완성된 곡 가져오기

아래는 요청 형식 예시입니다. `YOUR_COMPLETED_AUDIO_ID`와 시간 구간을 자신의 원본 곡 ID 및 실제 선택 구간으로 바꾸세요. 이 예시는 30–50초가 아래 네 구절에 해당한다고 가정합니다.

```json
{
  "action": "replace_section",
  "audio_id": "YOUR_COMPLETED_AUDIO_ID",
  "model": "chirp-v6",
  "custom": false,
  "instrumental": false,
  "lyric": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "prompt": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "replace_section_start": 30.0,
  "replace_section_end": 50.0,
  "replace_section_result_mode": "full_song",
  "async": true
}
```

제출 후 반환된 `task_id`를 사용하여 `/suno/tasks`를 조회합니다. 요청 본문은 `{"action":"retrieve","id":"YOUR_TASK_ID"}`입니다. 작업 완료 후 작업 응답의 `response.data`에서 완성된 두 곡의 `id`, `audio_url`, `duration`을 가져오고, 들어본 후 그중 하나를 선택합니다. `success: true`는 작업이 성공적으로 실행되었음을 의미하며, 새 가사가 한 글자씩 불렸거나 길이가 예상과 일치한다는 뜻은 아닙니다.

### 선택 구간, 결과 확인 및 재편집

1. 먼저 원본 곡을 들어본 뒤 `/suno/timing`의 시간 정보와 결합하여 선택 구간을 결정하고, 가능한 한 완전한 악구를 포함하세요. 가사 배열의 고정 인덱스로 선택 구간을 정하지 말고, 더 많은 악구를 포함한 구간을 몇 줄의 가사로 교체하면서 리듬이 완전히 동일하게 유지될 것이라고 기대하지 마세요.
2. 새 가사의 문장 수, 글자 수 및 리듬은 선택 구간의 기존 내용과 가능한 한 가깝게 맞추세요. 몇 글자만 바꾸더라도 들어보고 검증해야 하며, 이를 근거로 성공을 보장할 수는 없습니다.
3. 대상 구간에서 새 가사가 불렸는지, 앞뒤 연결이 자연스러운지, 그리고 전체 곡 길이가 합리적인지 확인하세요. `full_song`은 완성된 곡을 반환한다는 의미이지 원곡과 같은 길이라는 뜻은 아닙니다. 교체 구간이 길어지면 후반부도 그에 따라 뒤로 이동합니다. `duration` 요청 매개변수는 일반 생성에만 사용되며, 교체 구간의 길이를 고정할 수 없습니다.
4. 반환되는 `lyric`는 가사 메타데이터입니다. 완성된 곡 모드는 원본 가사 시간 정보를 얻을 수 있을 때 전체 가사를 조합하며, 얻을 수 없으면 비어 있을 수 있습니다. 이는 오디오 전사가 아니므로 새 가사가 표시되더라도 오디오에서 새 가사가 불렸다는 증거는 아닙니다. 시간 정렬 정보도 특히 이미 편집된 결과물의 경우 청취와 함께 확인해야 합니다.
5. 다시 편집할 때는 선택한 **완성된 결과물 ID**를 새 `audio_id`로 사용하고, 해당 결과물의 길이와 선택 구간을 다시 확인하세요. 편집 전의 시간 좌표를 그대로 복사하지 말고, 이전에 반환된 전체 `lyric`를 이번의 부분 입력으로 직접 사용하지 마세요.

작업이 완료되었지만 여전히 이전 가사가 불리거나, 가사가 누락되거나, 현저히 길어졌다면 먼저 원본 곡 ID, 선택 구간 및 부분 가사를 확인한 다음 다른 결과도 확인하세요. 작업 조회 빈도를 높여도 이미 생성된 내용은 변경되지 않습니다. 여전히 이상이 있다면 `task_id`, 원본 곡 ID, 요청 필드, 선택 구간 및 결과 오디오를 보관하여 검토에 활용하세요.

### 선택 사항: 먼저 후보를 가져온 후 수동으로 연결하기

직접 교체 후보를 선택해야 하는 경우에만 `replace_section_result_mode: "candidates"`를 설정하세요. 후보에는 문맥이 포함될 수 있으므로, 후보 길이만으로 이를 완성된 곡으로 간주할 수 없습니다. 선택 후 후보의 `data[].id`로 `concat`을 호출한 다음 완성된 결과물을 가져옵니다.

기본 `full_song`은 이미 연결을 완료했으므로 이 단계를 수행할 필요가 없습니다.

## 전체 트랙 보컬과 반주 분리

작업은 모든 오디오 트랙 생성이 완료된 후에야 성공 최종 상태를 반환합니다. 처리 중 재생 가능한 주소가 나타난다고 해서 전체 오디오 트랙 그룹이 이미 완료되었음을 의미하지는 않습니다.

노래를 생성한 후 전체 트랙 보컬과 반주 분리 작업이 필요한 경우, 다음과 같은 내용을 지정할 수 있습니다:

- action: 내용은 `all_stems`입니다.
- audio_id: 이전에 생성한 노래의 ID입니다.

## 곡 길이 제어

기본적으로 생성되는 곡의 길이는 모델이 자체적으로 결정하며, 일반적으로 30초에서 4분 사이입니다. 더 길거나 짧은 결과물이 필요한 경우 `duration` 파라미터를 통해 원하는 길이를 지정할 수 있으며, 단위는 초이고 값은 10에서 360 사이의 정수입니다.

이 파라미터는 사용자 정의 모드(`custom`이 `true`)의 곡 생성에 사용됩니다. 특히 설명해야 할 점은 `duration`이 **경향성 프롬프트이지, 강제 제약이 아니라는 것**입니다. 모델은 창작 시 이 값을 참고하지만 달성을 보장하지 않으며, 실제 테스트에서 실제 길이는 보통 기대값보다 눈에 띄게 짧고, 동일한 요청에서 반환된 두 곡의 길이도 몇 배 차이 날 수 있습니다. 완전히 동일한 요청이라도 여러 번 제출하여 얻는 길이에는 큰 차이가 있을 수 있습니다. 따라서 이를 정확한 길이 제어로 사용하지 마십시오. 비즈니스상 고정된 길이가 필요한 경우, 결과물을 받은 후 직접 잘라내거나 재시도하십시오.

해당 Python 코드:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

주의할 점은 요청의 `duration`은 **기대 길이**인 반면, 응답 `data`에서 각 곡의 `duration` 필드는 해당 곡의 **실제 길이**라는 것입니다. 이름은 같지만 의미가 다르며, 실제 길이가 기대값과 같다고 보장되지 않습니다. 가사 길이는 결과물 길이에 영향을 주는 주요 요인 중 하나이므로, 더 긴 결과물이 필요하다면 더 완전한 가사를 함께 제공하는 것이 좋습니다.

인터페이스는 `duration`이 반드시 10에서 360 사이의 정수인지 검증합니다. 이는 여전히 생성 목표일 뿐, 결과물 길이를 보장하는 것은 아닙니다.

## Inspo 영감 창작 기능

Inspo 영감 창작 기능은 1~4개의 완전한 참조 오디오를 기반으로 새로운 음악을 생성할 수 있으며, 오디오를 드래그 앤 드롭하거나 업로드하여 영감 소스로 사용할 수 있습니다. API는 기존 `inspo` action을 사용합니다. 클라이언트가 공개적으로 접근 가능한 오디오 URL을 제공하면 서비스가 참조 오디오 준비와 창작을 자동으로 완료하므로, 클라이언트가 가사, 스타일 또는 길이를 각각 읽어 요청을 다시 조합할 필요가 없습니다. 이는 위의 구간 샘플링과도 다르고, 원곡 스타일을 복제하는 Cover와도 다릅니다. 사용할 때 다음 매개변수를 입력해야 합니다:

- action: 내용은 `inspo`입니다.
- audio_urls: 참조 오디오의 URL 목록이며, 공개적으로 접근 가능한 오디오 주소를 1~4개 제공해야 합니다.
- model: 사용할 모델이며, `chirp-v6`를 권장합니다.
- prompt: 가사 또는 창작 프롬프트(선택 사항)입니다.
- instrumental: `true`로 설정하면 가사를 사용하지 않고 순수 음악 요청으로 생성합니다.
- persona_id: 해당 조합을 지원하는 서비스 채널에서 지정된 음성을 사용합니다. 참조 오디오는 준비 단계에서 해당 음성에 필요한 리소스 환경에 바인딩됩니다.
- lyric_prompt: `custom=true`이고 `lyric`이 제공되지 않은 경우, 가사를 자동 생성하는 데 사용됩니다.

> 설명: 참조 오디오는 공개적으로 접근 가능한 오디오 파일이어야 합니다. 참조 오디오가 플랫폼 음원 라이브러리의 알려진 녹음과 완전히 일치하는 경우, Suno는 저작권 검증으로 인해 생성을 거부할 수 있으므로 자체 소유하거나 Suno로 생성한 오디오를 영감 소스로 사용하는 것이 좋습니다.

해당하는 Python 코드:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

## 비동기 콜백

Suno가 음악을 생성하는 데 걸리는 시간은 비교적 길며, 약 1~2분이 소요됩니다. API가 오랫동안 응답하지 않으면 HTTP 요청이 계속 연결을 유지하게 되어 추가적인 시스템 리소스가 소모되므로, 본 API는 비동기 콜백도 지원합니다.

전체 과정은 다음과 같습니다. 클라이언트가 요청을 시작할 때 `callback_url` 필드를 추가로 지정합니다. 클라이언트가 API 요청을 시작한 후 API는 즉시 현재 작업 ID를 나타내는 `task_id` 필드 정보를 포함한 결과를 반환합니다. 작업이 완료되면 음악 생성 결과는 POST JSON 형식으로 클라이언트가 지정한 `callback_url`로 전송되며, 여기에도 `task_id` 필드가 포함되어 있어 ID를 통해 작업 결과를 연결할 수 있습니다.

아래에서 예시를 통해 구체적으로 어떻게 수행하는지 알아보겠습니다.

먼저 Webhook 콜백은 HTTP 요청을 받을 수 있는 서비스이며, 개발자는 이를 직접 구축한 HTTP 서버의 URL로 교체해야 합니다. 여기서는 시연의 편의를 위해 공개 Webhook 예시 사이트 https://webhook.site/를 사용합니다. 해당 사이트를 열면 아래 그림과 같이 Webhook URL을 얻을 수 있습니다.

![](https://cdn.acedata.cloud/fwfqin.png)

이 URL을 복사하면 Webhook으로 사용할 수 있으며, 여기의 예시는 https://webhook.site/03e60575-3d96-4132-b681-b713d78116e2입니다.

다음으로 필드 `callback_url`을 위의 Webhook URL로 설정하고, 동시에 `prompt`를 입력할 수 있습니다. 아래 그림과 같습니다.

![](https://cdn.acedata.cloud/x8xql1.png)

실행을 클릭하면 아래와 같이 즉시 결과를 얻을 수 있습니다.

```

  "task_id": "44472ab8-783b-4054-b861-5bf14e462f60"
}
```

## 오류 처리

오류가 발생하면 다음과 유사한 오류 정보를 받게 됩니다:

  "success": false,
  "error": {
    "code": "forbidden",
    "message": "Song Description contained artist name: eminem"
  },
  "trace_id": "9bb7c2f4-3b7b-4965-b50a-f663874b1b6f",

}
```
