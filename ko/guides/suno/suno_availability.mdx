`POST /suno/availability`는 리소스 ID 하나를 받습니다. 노래를 조회하려면 `audio_id`를 전달하고, 음색을 조회하려면 `persona_id`를 전달하며, 둘 중 하나는 필수입니다. 확인은 동기적으로 완료되며, API Token이 필요하고 현재 Credits는 차감되지 않습니다.

## 요청

`audio_id`는 완료된 노래 작업에서 가져오며, 이어쓰기 또는 커버 전 확인에 사용할 수 있습니다.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

`persona_id`는 음색 생성 결과에서 가져옵니다. 원래 애플리케이션과 호출자 신원을 사용하여, 음색 조회를 지원하는 생성 라인에서 다음 요청 본문을 전송합니다.

```json
{"persona_id":"33333333-3333-4333-8333-333333333333"}
```

## 응답

두 요청은 동일한 성공 응답을 사용합니다. `data.id`는 이번 조회의 리소스 ID입니다.

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

`available: true`는 이번 확인에서 긍정적인 증거를 얻었음을 나타냅니다. 음색의 경우, 확인은 생성 소속을 검증하고 연결된 계정이 현재 온라인으로 보고되는지 확인합니다. 실제 생성 결과는 여전히 생성 작업을 기준으로 합니다.

`/suno/voices`를 통해 생성된 비공개 복제 음색은 생성 계정에 의존합니다. 해당 계정이 현재 오프라인임이 확인되면, 인터페이스는 HTTP 200을 반환하며 `data` 예시는 다음과 같습니다.

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

클라이언트는 해당 음색을 현재 사용할 수 없음으로 표시하고 나중에 다시 조회할 수 있습니다.

확인할 수 없으면 HTTP 503 및 `availability_unknown`를 반환합니다. 예를 들어 리소스를 찾을 수 없거나, 이전 기록에 생성 라인이 없거나, 조회 시간이 초과된 경우입니다. 공개 가수 스타일은 계정을 넘어서 사용할 수 있으며, 생성 계정이 오프라인인 경우에도 503을 반환합니다. 노래 조회는 사용 가능함이 확인된 경우에만 계속해서 `available: true`를 반환합니다.

각 요청은 유효한 UUID 하나만 전송합니다. 모든 라인은 두 ID를 모두 보내거나 두 ID가 모두 누락된 요청을 받으면 HTTP 400을 반환합니다. 노래 조회만 지원하는 라인은 `persona_id`만 포함된 요청을 받으면 HTTP 400을 반환합니다. HTTP 429가 발생하면 조회 빈도를 낮추십시오.
