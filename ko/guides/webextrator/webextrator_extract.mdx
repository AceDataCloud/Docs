`POST https://api.acedata.cloud/webextrator/extract`

WebExtrator 지능형 추출 API는 하나의 URL을 **유형이 지정된 구조화된 결과**로 변환합니다. 즉, 기사, 상품,
레시피, 동영상, 토론, 채용 정보 등을 정리된 Markdown 및 일반 텍스트와 함께 제공합니다. 원시 HTML이 아닌 "깔끔한 구
조화 데이터"가 필요할 때 사용하는 인터페이스입니다.

## 신청 절차

WebExtrator 서비스 페이지를 사용하려면 먼저 [Ace Data Cloud 콘솔](https://platform.acedata.cloud/console/applications)에서 API Token을 받아두세요.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

로그인 또는 등록이 되어 있지 않으면 자동으로 로그인 페이지로 리디렉션되어 등록 및 로그인을 초대합니다. 완료 후 현재 페이지로 자동으로 돌아옵니다.

**하나의 API Token으로 플랫폼의 모든 서비스를 호출할 수 있으며, 각 서비스마다 별도로 신청할 필요가 없습니다.** 처음 신청 시 무료 할당량이 제공되어 무료로 체험할 수 있습니다; 할당량이 부족할 경우 [콘솔](https://platform.acedata.cloud/console/coin)에서 일반 잔액을 충전할 수 있습니다.

> 📘 전체 문서: [WebExtrator 서비스 페이지 →](https://platform.acedata.cloud/service/webextrator)

## 인증

```
Authorization: Bearer YOUR_API_KEY
Content-Type:  application/json
```

## 요청 매개변수

Extract는 **모든** [Render API](/ko/guides/webextrator/webextrator_render) 매개변수
（`url`、`user_agent`、`timeout`、`wait_until`、`delay`、`wait_for_selector`、
`block_resources`、`headers`、`cookies`、`callback_url`、`bypass_cache`、
`cache_ttl_seconds`、`async`）를 지원하며, Extract 전용 필드 2개가 추가됩니다:

| 필드 | 유형 | 필수 | 기본값 | 설명 |
|------|------|:----:|------|------|
| `expected_type` | enum | ❌ | 자동 감지 | 페이지 유형 힌트: `product` / `article` / `general`. 예상 결과 유형을 지정합니다. |
| `enable_llm` | boolean | ❌ | `false` | schema.org가 일치하지 않을 때 LLM 추출을 호출하도록 허용합니다. Amazon / HN / Greenhouse처럼 JSON-LD가 없는 페이지에서는 유형화된 결과를 얻으려면 이를 활성화해야 합니다. |

### 최상위 필드

| 필드 | 유형 | 설명 |
|------|------|------|
| `kind` | string | 고정값 `"extract"`. |
| `url` | string | 제출한 URL입니다. |
| `finalUrl` | string | 리디렉션 후의 최종 URL입니다. |
| `contentType` | enum | 페이지 유형: `product` / `article` / `general`. |
| `title` | string | 페이지 제목입니다. |
| `description` | string? | 페이지 설명 또는 요약입니다. |
| `byline` | string? | 작성자, 채널 또는 회사입니다. |
| `language` | string? | `<html lang>`.  |
| `siteName` | string? | `og:site_name`.  |
| `publishedAt` | string? | 게시 시간이며 ISO 8601 형식을 사용합니다. |
| `images` | string[] | 최대 50개의 `<img src />`이며, 절대 URL로 해석되고 중복이 제거되며 `data:` URI는 제외됩니다. |
| `links` | string[] | 최대 100개의 외부 링크이며, 프래그먼트 / `javascript:` / `mailto:` / `tel:`는 필터링됩니다. |
| `markdown` | string | 페이지의 Markdown 콘텐츠입니다. |
| `text` | string | 페이지 일반 텍스트입니다. |
| `structured` | object | 전체 구조화된 결과입니다. 아래를 참조하세요. |
| `rawSignals` | object | 디버깅용 진단 정보입니다. |
| `cached` | boolean? | 캐시 적중 시 `true`입니다. |
| `cacheStoredAt` | number? | 캐시 항목이 처음 기록된 Unix 밀리초 타임스탬프입니다. |

### `data.structured` 하위 필드

| 하위 필드 | 표시되는 시점 | 설명 |
|--------|---------|------|
| `schemaOrg` | 항상 | `{ primary, breadcrumbs, all }`. `primary`는 최우선 순위의 유형화된 엔터티이며, 찾을 수 없으면 `null`입니다. |
| `openGraph` | 항상 | `<meta property="og:*" />`에서 파생된 `{ title, description, image, type }`입니다. |
| `jsonLd` | 항상 | 모든 `<script type="application/ld+json">` 블록의 원본 JSON 배열입니다. |
| `llm` | LLM이 실행되어 성공한 경우 | `{ kind, data, model, promptCharCount }`, 유형화된 결과입니다. |
| `llmError` | LLM이 실행되었지만 실패한 경우 | `{ kind, error, model }`, 요청은 여전히 다른 추출된 필드를 반환할 수 있습니다. |
| `amazon` | URL이 `amazon.*`인 경우 | 레거시 Amazon 확장 결과입니다. 새 통합에는 유형화된 결과를 사용하세요. |

## schema.org 결과 유형

`structured.schemaOrg.primary`는 다음 결과 유형을 지원합니다:

| schema.org 유형 | kind | 출력 필드 |
|----------------|----------|----------|
| `Product` | product | `name, sku, gtin, model, color, brand, url, images, offer.{price,currency,availability,condition,seller}, rating.{value,count}, reviews[], properties[]` |
| `Recipe` | recipe | `name, description, image, datePublished, author, cookTime, prepTime, totalTime, recipeYield, ingredients[], instructions[], nutrition, rating, keywords, recipeCategory, recipeCuisine` |
| `VideoObject` | video | `name, description, thumbnailUrl, uploadDate, duration, embedUrl, contentUrl, channel, interactionCount` |
| `JobPosting` | job | `title, description, datePosted, validThrough, hiringOrganization, jobLocation, baseSalary, employmentType` |
| `Event`(`*Event` 포함) | event | `name, description, startDate, endDate, location.{name,address}, organizer, offer.{url,price,currency}` |
| `Article` / `NewsArticle` / `BlogPosting` / `ScholarlyArticle` / `TechArticle` / `Report` / `*NewsArticle` | article | `subtype, headline, description, datePublished, dateModified, author, publisher, image[], url, sameAs[]` |
| `FAQPage` | faq | `questions[{question, answer}]` |
| `BreadcrumbList` | (sibling에 연결됨) | 항상 `structured.schemaOrg.breadcrumbs[]`로 출력되며 primary로 사용되지 않습니다. |

## LLM 결과 유형

`enable_llm: true`이고 페이지에 사용 가능한 schema.org 구조화된 데이터가 없는 경우, 다음 유형의 추출 결과를 반환할 수 있습니다:

| Kind | 필수 필드 | 선택 필드 |
|------|---------|---------|
| `article` | `headline` | `description, byline, publishedAt, language, topics[], sections[{heading,summary}]` |
| `product` | `name` | `description, brand, sku, price, currency, availability, rating.{value,count}, bullets[], specifications[{name,value}]` |
| `discussion` | `title` | `author, postedAt, points, commentCount, body, url` |
| `recipe` | `name` | `description, author, cookTime, prepTime, totalTime, recipeYield, ingredients[], instructions[], nutrition, rating, keywords[]` |
| `video` | `name` | `description, channel, uploadDate, duration, viewCount, likeCount, thumbnailUrl, transcript` |
| `job` | `title` | `description, company, location, remote, employmentType, datePosted, validThrough, salaryMin, salaryMax, salaryCurrency, salaryPeriod, responsibilities[], qualifications[]` |

## 캐시

동일한 URL, 요청 매개변수, `cookies` 및 `headers`는 캐시된 결과를 재사용할 수 있습니다. `async`, `bypass_cache`, `cache_ttl_seconds`는 실행 방식과 캐시 동작을 제어하는 데 사용됩니다.

| 필드 | 효과 |
|------|------|
| `bypass_cache: true` | 읽기를 건너뜁니다. 이번 결과는 계속 캐시에 기록되며, 다음에 동일한 요청이 오면 캐시 적중이 가능합니다. |
| `cache_ttl_seconds: 0` | 이번 응답은 **캐시되지 않습니다**. |
| `cache_ttl_seconds: N` | 이 항목의 TTL을 직접 설정합니다(기본값: 3600초). |

캐시 적중 응답에는 `data.cached: true` 및 `data.cacheStoredAt: <unix-ms>`가 포함됩니다.

## 비동기 모드 및 콜백

`async: true`를 설정하여 비동기 모드로 전환합니다 (또한 `callback_url`을 제공하면 자동으로 전환됩니다). 플랫폼은 즉시 반환합니다 (HTTP 200):

```json
{
  "success": true,
  "task_id": "550e8400-...",
  "trace_id": "6ba7b810-...",
  "started_at": 1777717800.123
}
```

작업이 완료되면 전체 envelope을 `callback_url`로 `POST`합니다 (구성된 경우). 또한 나중에 [`/webextrator/tasks`](/ko/guides/webextrator/webextrator_tasks)에서 수동으로 조회할 수 있습니다.

### Python (requests)

```python
import os, requests

API_KEY = os.environ["ACEDATA_API_KEY"]

resp = requests.post(
    "https://api.acedata.cloud/webextrator/extract",
    headers={
        "Authorization": f"Bearer {API_KEY}",
        "Content-Type": "application/json",
    },
    json={
        "url": "https://en.wikipedia.org/wiki/Diffbot",
        "expected_type": "article",
    },
    timeout=120,
)
resp.raise_for_status()
data = resp.json()["data"]

primary = (data.get("structured") or {}).get("schemaOrg", {}).get("primary")
print("contentType:", data["contentType"])
print("title:      ", data["title"])
print("byline:     ", data.get("byline"))
print("publishedAt:", data.get("publishedAt"))
if primary and primary["kind"] == "article":
    print("headline:    ", primary["headline"])
    print("dateModified:", primary.get("dateModified"))
```

## 팁과 주의사항

- **페이지 유형을 지정해야 할 때는 `expected_type`를 전달하세요.** 예를 들어 글 페이지에는 `article`를 사용하고, 상품 페이지에는 `product`를 사용합니다.
- **schema.org에 적중하는 페이지에서는 `enable_llm: true`가 무료입니다.** LLM은 schema.org에
  primary가 없을 때만 호출되므로, 기본적으로 켜 두어도 안전합니다.
- **디버깅할 때는 먼저 `rawSignals.hasJsonLd`를 확인하세요.** `true`이지만 `structured.schemaOrg.primary`가
  `null`인 경우, 해당 페이지의 `@type`는 아직 지원되지 않는다는 의미이며 피드백을 보내주실 수 있습니다.
- **`structured.llmError`는 정보 제공용입니다.** 요청은 다른 추출된 필드와 함께 계속 성공적으로 반환될 수 있습니다. 다음을 확인하세요:
  `llmError.error`에서 원인(시간 초과, JSON 파싱 실패, 구조 검증 실패)을 파악할 수 있습니다.
- **비문서 페이지의 `links[]`는 관련성 순위를 적용하지 않습니다.** "최대 100개 + 유효하지 않은 프로토콜 필터링"만으로
  최대한 정리합니다.
- **캐시 적중에도 과금됩니다.**
