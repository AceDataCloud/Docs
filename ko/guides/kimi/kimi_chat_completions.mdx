Kimi는 Moonshot AI에서 출시한 AI 모델 시리즈입니다. 현재 `kimi-k3.1-pro`를 권장하며, 장기 프로그래밍, 복잡한 추론, 시각적 이해 및 지식 업무에 적합합니다. `kimi-k3`도 계속 사용할 수 있습니다. OpenAI 호환 Chat Completions API를 통해 호출할 수 있습니다.

이 문서에서는 주로 Kimi Chat Completion API의 사용 절차를 소개합니다. 이를 활용하면 공식 Kimi의 대화 기능을 간편하게 사용할 수 있습니다.

## 지원 모델

현재 `kimi-k3.1-pro`, `kimi-k3`, `kimi-k2.6` 및 `kimi-k2.7-code`의 네 가지 모델을 지원합니다. K2.7 Code는 프로그래밍 및 도구 호출 시나리오를 대상으로 하며, K2.6과 동일한 가격대로 요금이 부과됩니다. 요청 시 `thinking` 스위치 또는 `reasoning_effort`를 전달하지 마세요. 다른 Kimi 모델은 더 이상 지원되지 않으므로 클라이언트에서 이 네 가지 모델 중 하나를 명시적으로 선택해야 합니다.

## 기본 사용법

이제 인터페이스에서 해당 내용을 입력할 수 있습니다. 그림과 같습니다.

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

이 인터페이스를 처음 사용할 때는 최소 세 가지 항목을 입력해야 합니다. `authorization`은 드롭다운 목록에서 직접 선택할 수 있으며, `model`은 Kimi 모델을 선택하는 데 사용되고 `kimi-k3.1-pro` 사용을 권장합니다. `messages`는 대화 메시지 배열로, 각 메시지에는 `role`과 `content`가 포함되며, `role`은 `user`, `assistant`, `system` 및 `tool`을 지원합니다.

또한 오른쪽에 해당 호출 코드가 자동으로 생성되는 것을 확인할 수 있습니다. 코드를 복사하여 직접 실행하거나 「Try」 버튼을 클릭하여 테스트할 수도 있습니다.

다음은 `reasoning_effort: max`를 사용하여 얻은 실제 K3 응답입니다(사용하지 않은 확장 필드는 생략).

```json
{
  "id": "msg_2D4Btbg1WgvkNE3tCYkR4xGA",
  "object": "chat.completion",
  "created": 1784466588,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 86,
    "completion_tokens": 206,
    "total_tokens": 292
  }
}
```

반환 결과에는 여러 필드가 있으며, 다음과 같이 설명합니다.

- `id`: 이번 대화 작업의 ID를 생성하며, 이번 대화 작업을 고유하게 식별하는 데 사용됩니다.
- `model `: 선택한 Kimi 공식 웹사이트 모델입니다.
- `choices`: Kimi가 질문에 대해 제공한 답변 정보입니다.
- `usage `: 이번 질의응답에서 사용된 토큰의 통계 정보입니다.

이 중 `choices`에는 Kimi의 답변 정보가 포함되어 있습니다. 그 안의 `choices`는 Kimi가 생성한 구체적인 답변 정보이며, 그림과 같이 확인할 수 있습니다.

<p><img src="https://cdn.acedata.cloud/tv9rul.png" width="400" className="m-auto" /></p>

`choices` 내부의 `content` 필드에 Kimi가 응답한 구체적인 내용이 포함되어 있는 것을 확인할 수 있습니다. K3는 추론 과정을 나타내는 `reasoning_content`도 반환할 수 있습니다.

## K3.1 Pro 추론 강도

`kimi-k3.1-pro`는 항상 추론 기능이 활성화되어 있습니다. 요청 본문의 최상위 수준에서 `reasoning_effort`를 `low`, `high` 또는 `max`로 설정할 수 있습니다. 추론 기능을 비활성화하는 설정은 전달하지 마세요. 모델은 최대 1,048,576 token의 컨텍스트를 지원하지만, 실제 요청 한도는 현재 인터페이스의 설정을 기준으로 합니다. 요금은 입력, 출력 및 캐시 적중 사용량에 따라 계산되며, 자세한 내용은 모델 목록의 Pricing 카드를 참조하세요.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

다음 K3 예시는 기존 통합을 위해 유지되며, 예시 응답은 실제로 K3 요청을 통해 얻은 것입니다.

## K3 추론 강도

`kimi-k3`는 항상 추론 기능이 활성화되어 있습니다. 요청 본문의 최상위 수준에서 `reasoning_effort` 필드를 지원하며, 현재 지원되는 유일한 값은 `max`입니다. 해당 필드를 생략해도 `max`가 사용됩니다. 지원되는 값을 사용하세요.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

OpenAI SDK를 사용할 때는 해당 필드를 직접 전달할 수 있습니다.

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

여러 차례의 대화 및 도구 호출 시에는 이전 대화의 전체 assistant 메시지를 `reasoning_content`와 `tool_calls`를 포함하여 `messages`에 다시 전달해야 합니다.

### 공식 참고 자료

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort): Kimi K3는 항상 추론 기능이 활성화되어 있으며, 현재 `reasoning_effort`에서 지원되는 유일한 값은 `max`임을 설명합니다.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview): K3와 K2 시리즈의 추론 매개변수, 컨텍스트 창 및 도구 호출 차이를 비교합니다.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat): Moonshot 공식 Chat Completions 요청, 응답 및 OpenAPI 필드 정의입니다.

## 스트리밍 응답

이 인터페이스는 스트리밍 응답도 지원하며, 이는 웹페이지 연동에 매우 유용합니다. 웹페이지에서 글자가 하나씩 표시되는 효과를 구현할 수 있습니다.

응답을 스트리밍 방식으로 반환하려면 요청 헤더의 `stream ` 매개변수를 `true`로 변경하면 됩니다.

그림과 같이 수정하면 됩니다. 다만 스트리밍 응답을 지원하려면 호출 코드도 그에 맞게 수정해야 합니다.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>
`stream`을 `true`로 변경한 후 API는 해당 JSON 데이터를 한 줄씩 반환하며, 코드 수준에서 한 줄씩 결과를 가져오려면 이에 맞게 코드를 수정해야 합니다.

Python 샘플 호출 코드:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

다음은 동일한 실제 K3 Max 스트리밍 응답에서 발췌한 시작, 추론, 본문, 종료 및 사용량 데이터 블록입니다.

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

응답에는 여러 개의 `data`가 포함되어 있으며, `data` 내부의 `choices`가 최신 답변 내용을 나타내는 것을 확인할 수 있습니다. 이는 앞서 설명한 내용과 일치합니다. `choices`는 새롭게 생성된 답변 내용이며, 결과에 따라 사용자의 시스템에 연동할 수 있습니다. 또한 스트리밍 응답의 종료 여부는 `data`의 내용을 기준으로 판단합니다. 내용이 `[DONE]`이면 스트리밍 응답이 모두 종료되었음을 의미합니다. 반환되는 `data` 결과에는 여러 필드가 있으며, 자세한 내용은 다음과 같습니다.

- `id`: 이번 대화 작업의 ID를 생성하며, 이번 대화 작업을 고유하게 식별하는 데 사용됩니다.
- `model `: 선택한 Kimi 공식 웹사이트 모델입니다.
- `choices`: 질문에 대해 Kimi가 제공하는 답변 정보입니다.

JavaScript도 지원합니다. 예를 들어 Node.js의 스트리밍 호출 코드는 다음과 같습니다.

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Java 샘플 코드:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

다른 언어도 직접 수정하여 사용할 수 있으며, 원리는 모두 동일합니다.

다중 턴 대화 기능을 연동하려면 `messages` 필드에 여러 개의 질문을 전달해야 합니다. 여러 질문을 전달하는 구체적인 예시는 다음 그림과 같습니다.

Python 샘플 호출 코드:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",

    "content-type": "application/json"
```

## 오류 처리

API를 호출할 때 오류가 발생하면 API는 해당 오류 코드와 정보를 반환합니다. 예를 들면 다음과 같습니다.

- `400 token_mismatched`: 잘못된 요청입니다. 매개변수가 누락되었거나 유효하지 않을 수 있습니다.
- `400 api_not_implemented`: 잘못된 요청입니다. 매개변수가 누락되었거나 유효하지 않을 수 있습니다.
- `401 invalid_token`: 인증되지 않았습니다. 인증 토큰이 유효하지 않거나 누락되었습니다.
- `429 too_many_requests`: 요청이 너무 많습니다. 요청 제한을 초과했습니다.
- `500 api_error`: 서버 내부 오류입니다. 서버에서 문제가 발생했습니다.
