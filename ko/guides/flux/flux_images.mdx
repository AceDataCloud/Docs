이 글에서는 Flux Images Generation API 연동 안내를 소개합니다. 이는 사용자 정의 파라미터를 입력하여 Flux 공식 이미지를 생성할 수 있습니다.

## 신청 절차

Flux Images Generation API를 사용하려면 먼저 [Ace Data Cloud 콘솔](https://platform.acedata.cloud/console/applications)에서 API Token을 받아 예비용으로 보관하세요.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

아직 로그인 또는 등록하지 않았다면 로그인 페이지로 자동 이동하여 등록 및 로그인을 안내하며, 완료 후 현재 페이지로 자동 돌아옵니다.

**하나의 API Token으로 플랫폼의 모든 서비스를 호출할 수 있으며, 서비스마다 별도로 신청할 필요가 없습니다.** 최초 신청 시 무료 크레딧이 제공되어 무료로 체험할 수 있으며, 크레딧이 부족할 때는 [콘솔](https://platform.acedata.cloud/console/coin)에서 공용 잔액을 충전할 수 있습니다.

> 📘 전체 문서: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## 기본 사용법

먼저 기본 사용 방법을 알아보겠습니다. 즉 프롬프트 `prompt`, 생성 동작 `action`, 이미지 크기 `size`를 입력하면 처리된 결과를 얻을 수 있습니다. 먼저 간단히 `action` 필드를 전달해야 하며, 그 값은 `generate`입니다. 그리고 프롬프트도 입력해야 합니다. 구체적인 내용은 다음과 같습니다:

<p><img src="https://cdn.acedata.cloud/wz85jt.png" width="500" className="m-auto" /></p>

여기에서 Request Headers를 설정한 것을 볼 수 있으며, 다음을 포함합니다:

- `accept`: 어떤 형식의 응답 결과를 받을지로, 여기서는 `application/json`, 즉 JSON 형식으로 작성합니다.
- `authorization`: API 호출 키로, 신청 후 직접 드롭다운에서 선택할 수 있습니다.

또한 Request Body를 설정했으며, 다음을 포함합니다:

- `action`: 이번 이미지 생성 작업의 동작입니다.
- `size`: 이미지 생성 결과의 크기입니다. **`flux-2-flex` / `flux-2-pro` / `flux-2-max` 시리즈는 반드시 이미지 비율(예: `1:1`, `16:9`)을 전달해야 하며, `1024x1024`와 같은 픽셀 크기는 허용하지 않습니다. 누락 시 400이 반환됩니다.**
- `count`: 생성할 이미지 수이며, 기본값은 1입니다. 이 파라미터는 이미지 생성 작업에서만 유효하고 편집 작업에서는 유효하지 않습니다.
- `prompt`: 프롬프트입니다.
- `model`: 생성 모델이며, 기본값은 `flux-dev`입니다. 최신 플래그십은 `flux-2-pro`, `flux-2-max`이며(더 높은 화질), 이미지 비율 `size`와 함께 사용해야 합니다.
- `callback_url`: 결과를 콜백받을 URL입니다.
- `async`: 선택 사항이며, `true`로 설정하면 인터페이스가 즉시 `task_id`를 반환합니다. `callback_url`을 제공할 필요가 없으며, 이후 해당 작업 조회 인터페이스를 통해 폴링하여 결과를 가져옵니다.

파라미터 `size`에는 몇 가지 특별한 제한이 있으며, 주로 `width x height` 너비·높이 비율과 `x:y` 이미지 비율의 두 가지 유형으로 나뉩니다. 구체적인 내용은 다음과 같습니다:

| 모델               | 범위                                         |
| ---------------- | ------------------------------------------ |
| flux-dev         | 너비·높이 비율 1024x1024, 1024x1792, 1792x1024 또는 이미지 비율 지원 |
| flux-pro         | 너비·높이 비율 1024x1024, 1024x1792, 1792x1024 또는 이미지 비율 지원 |
| flux-2-flex      | 이미지 비율만 지원                                    |
| flux-2-pro       | 이미지 비율만 지원                                    |
| flux-2-max       | 이미지 비율만 지원                                    |
| flux-kontext-pro | 이미지 비율만 지원                                    |
| flux-kontext-max | 이미지 비율만 지원                                    |

참고 이미지 비율: "21:9", "16:9", "4:3", "3:2", "1:1", "2:3", "3:4", "9:16", "9:21".

파라미터를 선택하면 오른쪽에 해당 코드가 자동으로 생성됩니다. 복사하기 전에 인증 헤더가 본인의 API Key를 사용하는지 확인하고, 문서와 스크린샷에 실제 자격 증명이 나타나지 않아야 합니다.

「Try」 버튼을 클릭하면 테스트할 수 있으며, 여기서는 다음과 같은 결과를 얻었습니다:

```json
{
  "success": true,
  "task_id": "5456c749-3bbb-4f10-9eb8-cfbcac297500",
  "trace_id": "ae4eecb8-1dd6-45b4-bfb3-a1c48872536e",
  "data": [
    {
      "image_url": "https://cdn.acedata.cloud/assets/examples/flux/5456c749-3bbb-4f10-9eb8-cfbcac297500-d0ef60485f73.jpg"
    }
  ]
}
```

반환 결과에는 여러 필드가 있으며, 다음과 같이 소개합니다:

- `success`, 이때 비디오 생성 작업의 상태입니다.
- `task_id`, 이때 비디오 생성 작업 ID입니다.
- `trace_id`, 이때 비디오 생성 추적 ID입니다.
- `data`, 이때 이미지 생성 작업의 결과 목록입니다.
  - `image_url`, 이때 이미지 생성 작업의 링크입니다.
  - `prompt`, 프롬프트입니다.

만족스러운 이미지 정보를 얻은 것을 볼 수 있으며, 결과의 `data`에 있는 이미지 링크 주소를 통해 생성된 Flux 이미지를 가져오기만 하면 됩니다.

또한 해당 연동 코드를 생성하려면 직접 복사할 수 있으며, 예를 들어 CURL 코드는 다음과 같습니다:

```shell
curl -X POST 'https://api.acedata.cloud/flux/images' \
-H 'authorization: Bearer {token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "A photorealistic studio product shot of a frosted-glass perfume bottle on wet black slate, single softbox key light, water droplets, dark moody background, 85mm macro.",
  "model": "flux-2-pro",
  "size": "1:1"
}'
```

## 이미지 작업 편집

특정 이미지를 편집하려면 먼저 파라미터 `image_url`에 편집할 이미지 링크를 반드시 전달해야 합니다. 이때 `action`은 `edit`만 지원하며, 다음 내용을 지정할 수 있습니다:

- model: 이번 이미지 편집 작업에 사용하는 모델이며, `flux-dev`, `flux-pro`, `flux-kontext-pro`, `flux-kontext-max`, `flux-2-flex`, `flux-2-pro`, `flux-2-max`를 지원합니다.
- image_url: 편집할 이미지를 업로드합니다.

작성 예시는 다음과 같습니다:

<p><img src="https://cdn.acedata.cloud/jn9da5.png" width="500" className="m-auto" /></p>

작성 완료 후 다음과 같이 코드가 자동으로 생성됩니다:

<p><img src="https://cdn.acedata.cloud/6cwxb8.png" width="500" className="m-auto" /></p>

해당 코드:

```python
import requests

url = "https://api.acedata.cloud/flux/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "edit",
    "prompt": "a white siamese cat",
    "model": "flux-kontext-pro",
    "image_url": "https://cdn.acedata.cloud/ytj2qy.png"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

실행을 클릭하면 즉시 다음과 같은 결과를 얻는 것을 확인할 수 있습니다:

```json
{
  "success": true,
  "task_id": "2a7979ff-1f77-4380-92c6-a2dc37c3b4c8",
  "trace_id": "732b65c0-48d9-49f7-b568-64e5acffe4c0",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "timings": 1752744073
    }
  ]
}
```
생성된 효과는 원본 이미지를 편집한 효과이며, 결과는 위와 유사한 것을 볼 수 있습니다.

## 비동기 콜백

Flux Images Generation API의 생성 시간은 비교적 길며, 약 1~2분이 소요됩니다. API가 장시간 응답하지 않으면 HTTP 요청이 계속 연결 상태를 유지하여 추가적인 시스템 리소스가 소모될 수 있으므로, 본 API는 비동기 콜백도 지원합니다.

전체 흐름은 다음과 같습니다. 클라이언트가 요청을 시작할 때 추가로 `callback_url` 필드를 지정합니다. 클라이언트가 API 요청을 시작한 후 API는 즉시 현재 작업 ID를 나타내는 `task_id` 필드 정보를 포함한 결과를 반환합니다. 작업이 완료되면 생성된 이미지 결과는 POST JSON 형식으로 클라이언트가 지정한 `callback_url`로 전송되며, 여기에도 `task_id` 필드가 포함되어 있으므로 ID를 통해 작업 결과를 연결할 수 있습니다.

아래에서는 예제를 통해 구체적으로 어떻게 작동하는지 알아보겠습니다.

먼저 Webhook 콜백은 HTTP 요청을 수신할 수 있는 서비스이며, 개발자는 직접 구축한 HTTP 서버의 URL로 대체해야 합니다. 여기서는 시연의 편의를 위해 공개 Webhook 예제 웹사이트 https://webhook.site/를 사용합니다. 해당 웹사이트를 열면 그림과 같이 Webhook URL을 얻을 수 있습니다.

![](https://cdn.acedata.cloud/cjjfly.png)

이 URL을 복사하면 Webhook으로 사용할 수 있으며, 여기서의 예제는 `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`입니다.

다음으로 필드 `callback_url`을 위의 Webhook URL로 설정하고, 동시에 해당 매개변수를 입력할 수 있습니다. 구체적인 내용은 그림과 같습니다.

<p><img src="https://cdn.acedata.cloud/wm6caw.png" width="500" className="m-auto" /></p>

실행을 클릭하면 아래와 같이 즉시 결과를 얻는 것을 확인할 수 있습니다.

```
{
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c"
}
```

잠시 기다리면 `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`에서 그림과 같이 생성된 이미지 결과를 확인할 수 있습니다.

![](https://cdn.acedata.cloud/v23lot.png)

내용은 다음과 같습니다.

```json
{
  "success": true,
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c",
  "trace_id": "9b4b1ff3-90f2-470f-b082-1061ec2948cc",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "seed": 1698551532,
      "timings": {
        "inference": 3.328
      }
    }
  ]
}
```

결과에 `task_id` 필드가 있는 것을 볼 수 있으며, 다른 필드는 모두 위와 유사합니다. 이 필드를 통해 작업 연결을 구현할 수 있습니다.

## 오류 처리

API를 호출할 때 오류가 발생하면 API는 해당 오류 코드와 정보를 반환합니다. 예를 들면 다음과 같습니다.

- `400 token_mismatched`：잘못된 요청, 매개변수가 누락되었거나 유효하지 않을 수 있습니다.
- `400 api_not_implemented`：잘못된 요청, 매개변수가 누락되었거나 유효하지 않을 수 있습니다.
- `401 invalid_token`：인증되지 않음, 인증 토큰이 유효하지 않거나 누락되었습니다.
- `429 too_many_requests`：요청이 너무 많습니다. 요청 제한을 초과했습니다.
- `500 api_error`：내부 서버 오류, 서버에서 문제가 발생했습니다.

### 오류 응답 예시

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
