Flux Tasks API의 주요 기능은 Flux Images Generation API 또는 Flux Videos API가 반환한 플랫폼 작업 ID를 입력하여 해당 작업의 실행 상태를 조회하는 것입니다.

본 문서는 Flux Tasks API의 연동 안내를 자세히 소개하여, 귀하가 이 API의 강력한 기능을 손쉽게 통합하고 충분히 활용할 수 있도록 돕습니다. Flux Tasks API를 통해 Flux Images Generation API의 작업 실행 상태를 쉽게 조회할 수 있습니다.

동영상 제출 및 폴링의 전체 예시는 [Flux Videos API 통합 가이드](https://platform.acedata.cloud/documents/flux-videos-integration)를 참조하십시오. 기존 작업 조회에는 생성 비용이 별도로 부과되지 않습니다.

## 신청 절차

Flux Images Generation API를 사용하려면 먼저 [Ace Data Cloud 콘솔](https://platform.acedata.cloud/console/applications)에서 API Token을 발급받아 예비용으로 보관하십시오.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

아직 로그인하거나 등록하지 않은 경우, 자동으로 로그인 페이지로 이동하여 등록 및 로그인을 안내하며, 완료 후 현재 페이지로 자동으로 돌아옵니다.

**하나의 API Token으로 플랫폼의 모든 서비스를 호출할 수 있으며, 각 서비스마다 별도로 신청할 필요가 없습니다.** 최초 신청 시 무료 크레딧이 제공되어 무료로 체험할 수 있으며, 크레딧이 부족할 경우 [콘솔](https://platform.acedata.cloud/console/coin)에서 공용 잔액을 충전할 수 있습니다.

> 📘 전체 문서: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

### 요청 헤더 및 요청 본문 설정

**Request Headers**는 다음을 포함합니다:

- `accept`: JSON 형식의 응답 결과 수신을 지정하며, 여기서는 `application/json`으로 입력합니다.
- `authorization`: API 호출 키이며, 신청 후 직접 드롭다운에서 선택할 수 있습니다.

**Request Body**는 다음을 포함합니다:

- `id`: 업로드한 작업 ID입니다.
- `action`: 작업에 대한 작업 방식입니다.

### 코드 예시

페이지 오른쪽에 이미 다양한 언어의 코드가 자동으로 생성된 것을 확인할 수 있으며, 그림과 같습니다:

일부 코드 예시는 다음과 같습니다:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/flux/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/flux/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

반환 결과에는 여러 필드가 있으며, `request` 필드는 작업 시작 시의 request body이고, `response` 필드는 작업 완료 후 반환되는 response body입니다. 필드 설명은 다음과 같습니다.

- `id`: 이 이미지 작업을 생성한 ID로, 이번 이미지 생성 작업을 고유하게 식별하는 데 사용됩니다.
- `request`: 이미지 작업 조회의 요청 정보입니다.
- `response`: 이미지 작업 조회의 반환 정보입니다.
- `created_at`: 작업 생성 시간이며, Unix 타임스탬프(초, 부동 소수점)입니다.
- `started_at`: 작업 실행 시작 시간이며, Unix 타임스탬프(초, 부동 소수점)입니다.
- `finished_at`: 작업 완료 시간이며, Unix 타임스탬프(초, 부동 소수점)입니다. 작업이 완료되지 않은 경우 이 필드는 반환되지 않습니다.
- `elapsed`: 작업 실행 소요 시간이며, 단위는 초(부동 소수점, 소수점 이하 3자리 유지)입니다. 작업이 완료되지 않은 경우 이 필드는 반환되지 않습니다.

## 오류 처리

API를 호출할 때 오류가 발생하면 API는 해당 오류 코드와 정보를 반환합니다. 예를 들면 다음과 같습니다.

- `400 token_mismatched`: 잘못된 요청이며, 매개변수가 누락되었거나 유효하지 않기 때문일 수 있습니다.
- `400 api_not_implemented`: 잘못된 요청이며, 매개변수가 누락되었거나 유효하지 않기 때문일 수 있습니다.
- `401 invalid_token`: 권한이 없으며, 인증 토큰이 유효하지 않거나 누락되었습니다.
- `429 too_many_requests`: 요청이 너무 많으며, 속도 제한을 초과했습니다.
- `500 api_error`: 내부 서버 오류이며, 서버에서 문제가 발생했습니다.
