본 문서는 MiniMax H3 비디오 생성 API의 연동 및 사용에 대해 설명합니다. 이 인터페이스는 텍스트 기반 비디오, 시작 및 끝 프레임 제어, 다중 모달 참조 비디오를 지원하며, 통일된 V2 다중 모달 `content` 구조를 사용하여 작업을 생성합니다.

## 신청 절차

MiniMax H3 비디오 생성 API를 사용하려면 먼저 [Ace Data Cloud 콘솔](https://platform.acedata.cloud/console/applications)에서 API 토큰을 받아야 합니다. 이를 보관해 두십시오.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

로그인 또는 등록이 되어 있지 않은 경우, 자동으로 로그인 페이지로 리디렉션되어 등록 및 로그인을 요청합니다. 완료 후 현재 페이지로 자동으로 돌아옵니다.

**하나의 API 토큰으로 플랫폼의 모든 서비스를 호출할 수 있으며, 각 서비스마다 별도로 신청할 필요가 없습니다.** 처음 신청 시 무료 크레딧이 제공되어 무료로 체험할 수 있습니다; 크레딧이 부족할 경우 [콘솔](https://platform.acedata.cloud/console/coin)에서 일반 잔액을 충전할 수 있습니다.

> 📘 전체 문서: [MiniMax H3 비디오 생성 API →](https://platform.acedata.cloud/documents/minimax-videos-integration)

토큰을 환경 변수로 저장하는 것을 권장하며, 소스 코드에 작성하거나 버전 관리 시스템에 제출하지 마십시오:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## 인터페이스 개요

- **기본 URL**: `https://api.acedata.cloud`
- **엔드포인트**: `POST /minimax/videos`
- **인증 방식**: HTTP 헤더에 `authorization: Bearer {token}` 포함
- **요청 헤더**:
  - `accept: application/json`
  - `content-type: application/json`
- **모델(model)**: `MiniMax-H3`
- **입력 구조**: `content`를 통해 텍스트, 이미지, 비디오 및 오디오를 통일적으로 전달
- **출력 모드**: 기본적으로 생성 완료를 기다리고 전체 `task`를 반환; `async: true` 또는 `callback_url`을 전달할 경우 즉시 `task_id`와 `trace_id`를 반환
- **결과 조회**: [MiniMax H3 작업 조회 API](/documents/minimax-tasks-integration)를 통해 상태 및 결과물 확인
- **비동기 콜백**: 선택 사항으로, `callback_url`을 통해 최종 작업 결과 수신

`action`을 전달할 필요 없이, 인터페이스는 `content` 내의 소재 유형과 `role`에 따라 자동으로 용도를 판단합니다.

## 적합한 장면

| 장면         | 입력 조합                  | 일반적인 용도                      |
| ---------- | --------------------- | ------------------------- |
| 텍스트 기반 비디오       | 텍스트                    | 광고 아이디어, 스토리보드, 짧은 비디오, 분위기 장면        |
| 첫 프레임 이미지 기반 비디오     | 텍스트 + 첫 프레임 이미지             | 상품 이미지, 포스터, 인물 사진 또는 일러스트를 자연스럽게 움직이게 함      |
| 끝 프레임 / 첫 끝 프레임 비디오 | 텍스트 + 끝 프레임, 또는 텍스트 + 첫 프레임 + 끝 프레임 | 오프닝 및 엔딩 제어, 전환, 성장 변화 및 전후 비교      |
| 다중 모달 참조 비디오   | 텍스트 + 참조 이미지 / 비디오 / 오디오   | 캐릭터와 제품의 일관성 유지, 동작, 카메라 워크, 음색 또는 편집 리듬 복제 |

## 호출 절차

기본적으로 `async`를 전달하지 않으면, `/minimax/videos`는 생성 완료를 기다리고 전체 `task`를 직접 반환합니다. 즉시 연결을 해제해야 할 경우, `async: true` 또는 `callback_url`을 전달합니다:

1. 즉시 응답에서 `task_id`와 `trace_id`를 저장합니다.
2. 콜백이 설정되지 않은 경우, 약 10초마다 `/minimax/tasks`를 호출하여 상태를 조회합니다.
3. `task.status`가 `succeeded`로 변할 때, `task.content.url`에서 비디오를 가져옵니다.
4. 상태가 `failed` 또는 `cancelled`일 경우, 폴링을 중지하고 `task.error`를 읽습니다.

## 최상위 요청 매개변수

| 매개변수             | 유형       | 필수   | 기본값        | 설명                                                |
| -------------- | -------- | ---- | ---------- | ------------------------------------------------- |
| `model`        | string   | 예    | -          | 고정값 `MiniMax-H3`                                  |
| `content`      | object[] | 예    | -          | 다중 모달 콘텐츠 배열, 반드시 하나의 비어 있지 않은 `text` 항목 포함                         |
| `resolution`   | string   | 예    | -          | `768P` 또는 `2K`                                     |
| `duration`     | integer  | 예    | -          | 생성 시간, 4-15 초 정수                                     |
| `ratio`        | string   | 조건부 필수 | `adaptive` | `adaptive`, `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16` |
| `async`        | boolean  | 아니오    | `false`    | `true`일 경우 즉시 작업 식별자를 반환하며, 작업 인터페이스를 통해 결과를 가져옴                       |
| `callback_url` | string   | 아니오    | -          | 최종 작업 결과를 수신할 공용 콜백 URL; 제공 시 자동으로 비동기 모드 활성화                     |

`ratio`의 규칙은 워크플로우에 따라 다릅니다:

- **텍스트 기반 비디오**: 필수이며, `adaptive`일 수 없습니다.
- **첫 프레임, 끝 프레임 또는 첫 끝 프레임 비디오**: 화면 비율은 입력 이미지에 따라 결정되며, 생략하거나 `adaptive`를 전달하는 것이 좋습니다.
- **다중 모달 참조 비디오**: 생략 가능하며, 기본값은 `adaptive`입니다; 고정 비율을 명시적으로 지정할 수도 있습니다.

인터페이스는 구버전 또는 호환 필드를 수용하지 않으며, 예를 들어 `prompt`, `image_urls`, `audio_urls`, `messages` 및 `first_frame_image`와 같은 매개변수를 수신할 경우 오류가 발생합니다. 이러한 구식 필드를 삭제하고 `content`로 마이그레이션하십시오; 예를 들어 `"prompt": "한 마리 고양이가 손을 흔들다"`를 `"content": [{"type": "text", "text": "한 마리 고양이가 손을 흔들다"}]`로 변경하십시오. 새 형식과 구 형식을 동시에 전송하지 마십시오.

## content 내용 항목 매개변수

각 내용 항목은 `type`을 반드시 포함해야 하며, 나머지 필드는 유형에 따라 결정됩니다:

| `type`      | 데이터 필드            | `role`            | 설명                                     |
| ----------- | --------------- | ----------------- | -------------------------------------- |
| `text`      | `text`          | 전달하지 않음                | 각 요청에는 반드시 하나의 비어 있지 않은 텍스트 항목이 포함되어야 하며, 최대 7000자까지 허용             |
| `image_url` | `image_url.url` | `first_frame`     | 첫 프레임 이미지; 단일 이미지이고 `role`이 생략된 경우에도 첫 프레임으로 처리         |
| `image_url` | `image_url.url` | `last_frame`      | 끝 프레임 이미지; 단독으로 사용 가능하며, `first_frame`과 조합하여 시작점과 끝점을 제어할 수 있음 |
| `image_url` | `image_url.url` | `reference_image` | 참조 주체, 캐릭터, 제품, 의상, 장면 또는 스타일                    |
| `video_url` | `video_url.url` | `reference_video` | 참조 동작, 카메라 워크, 연기 또는 편집 구조                        |
| `audio_url` | `audio_url.url` | `reference_audio` | 참조 음색, 대화, 음악 또는 리듬                          |

미디어 주소는 세 가지 형식을 지원합니다:

- 공용으로 접근 가능한 HTTPS URL, 대용량 파일에 권장됩니다.
- `mm_file://{file_id}`로, 이미 업로드되었거나 결과가 있는 파일을 참조합니다.
- 해당 미디어 유형의 Base64 데이터 URI. Base64는 크기를 약 1/3 증가시키므로 전체 요청 본문이 64MB를 초과하지 않도록 하십시오.

## 소재 규격 및 수량 제한
| 소재  | 형식                                          | 단일 파일 제한     | 크기 / 길이                                                         | 수량 제한                        |
| --- | ------------------------------------------- | --------- | --------------------------------------------------------------- | --------------------------- |
| 이미지  | JPG, JPEG, PNG, WEBP, HEIC, HEIF                 | 30 MB 이하 | 너비와 높이 모두 256-5760 px; 종횡비 0.4-2.5                                    | 첫 프레임 최대 1장, 마지막 프레임 최대 1장, 참조 이미지 최대 9장 |
| 비디오  | MP4, MOV; H.264/AVC 또는 H.265/HEVC; 오디오 트랙 AAC 또는 MP3 | 50 MB 이하 | 각 클립 2-15초, 총합 15초 이하; 너비와 높이 모두 256-5760 px; 종횡비 0.4-2.5; 23.976-60 fps | 최대 3개 참조 비디오                  |
| 오디오  | WAV, MP3                                     | 15 MB 이하 | 각 클립 2-15초, 총합 15초 이하                                            | 최대 3개 참조 오디오                  |

다중 모달 참조 장면의 이미지, 비디오 및 오디오 총합 최대 12개 파일. 첫 마지막 프레임 장면과 참조 자료 장면은 상호 배타적입니다: `reference_image`, `reference_video` 또는 `reference_audio`를 사용하면 `first_frame` 또는 `last_frame`을 사용할 수 없으며, 그 반대도 마찬가지입니다.

## 생산급 능력 시연

아래는 개념도나 자리 표시자 자료가 아니라 MiniMax H3 공식 생산급 능력 샘플의 실제 참조 입력 및 실제 비디오 출력입니다. 세 가지 사례는 각각 브랜드 단편, 실사 내러티브 및 패션 전자상거래를 다루며, 모델이 상업 제작에서 가장 중요한 능력을 평가하는 데 적합합니다.

| 능력       | 주요 관찰                        |
| -------- | --------------------------- |
| 인물 및 얼굴 일관성 | 다중 카메라 전환 후 얼굴, 헤어스타일, 메이크업 및 인물의 기질이 안정적인지 여부     |
| 얼굴 연기     | 근접 촬영에서의 눈빛, 미세한 표정, 감정 긴장감 및 자연스러운 머리 움직임      |
| 상품 구조 유지   | 안경, 핸드백 등 제품의 윤곽, 재질, 착용 관계 및 거울 반사    |
| 브랜드 비주얼 실행   | 장면 분위기, 영화적 질감, 색상, 로고 및 편집 리듬이 일관된지 여부 |
| 영화적 내러티브    | 장면 변화, 인물 배치, 카메라 움직임, 리듬 및 소리가 완전한 단락을 형성할 수 있는지 여부  |

여기서 "얼굴 능력"은 비디오 생성에서 인물 외관 일관성, 얼굴 세부 사항 및 연기 제어를 의미하며, 신원 인식, 얼굴 비교 또는 얼굴 교체 인터페이스가 아닙니다.

### 실사 세로 화면 단편: 얼굴 일관성과 감정 연기
**제작 목표:** 15초, 9:16 다크 로맨스 단편 드라마 예고편. 남녀 주인공 참고 이미지를 통해 인물 외관을 고정하고, 고성 참고 이미지를 통해 공간을 제약한다; 중근접 촬영과 얼굴 클로즈업을 사용하여 눈빛 대치, 두려움, 억제 및 위험감을 표현한다. 이 사례는 실제 인물의 얼굴 안정성, 미세 표정, 시선 관계 및 연속 연기를 관찰하는 데 적합하다.

## 텍스트 기반 비디오

텍스트 항목이 하나일 때 텍스트 기반 비디오로 간주된다. 창의성, 스크립트 또는 촬영 설명에서 직접 이미지를 생성하는 데 적합하다. 프롬프트는 "주체 + 동작 + 장면 + 촬영 + 조명 + 소리"의 순서로 구성할 수 있다.

```bash
curl -X POST 'https://api.acedata.cloud/minimax/videos' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MiniMax-H3",
    "content": [
      {
        "type": "text",
        "text": "15초 영화급 향수 광고: 아침 해안의 검은 암석 위에, 투명한 향수 병이 안개와 파도에 둘러싸여 있다. 근접 촬영으로 병 몸체의 물방울과 유리 굴절을 보여주고, 카메라는 제품 클로즈업에서 천천히 넓은 바다로 올라간다; 은빛 파란색 조명, 자연광, 고급스럽고 억제된 느낌, 마지막에 제품을 고정한다."
      }
    ],
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }'
```

기본 동기식 모드는 생성 완료 후 전체 작업을 반환한다:

```json
{
  "task": {
    "id": "f5977217-ed2c-40da-adbe-93d08235618f",
    "model": "MiniMax-H3",
    "status": "succeeded",
    "content": { "url": "https://cdn.acedata.cloud/minimax/f5977217.mp4" },
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }
}
```

요청에 `"async": true`를 추가하면 인터페이스가 즉시 반환된다:

```json
{
  "task_id": "f5977217-ed2c-40da-adbe-93d08235618f",
  "trace_id": "trace_7f8c2b1a"
}
```

## 첫 프레임 이미지 기반 비디오

이미지를 `first_frame`으로 표시하면 모델이 해당 장면에서 생성하기 시작한다. 포스터, 상품 이미지, 캐릭터 설정 이미지 및 사진 작품이 자연스럽게 움직이도록 하는 데 적합하다.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "인물이 자연스럽게 숨을 쉬며 창밖을 바라보고, 옷자락이 미풍에 흔들리며, 카메라가 천천히 다가간다."
    },
    {
      "type": "image_url",
      "image_url": {
        "url": "https://cdn.acedata.cloud/b1c82e4937.png"
      },
      "role": "first_frame"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

## 마지막 프레임 및 첫 마지막 프레임 비디오
단지 `last_frame`만 제공하면 모델이 자연스럽게 지정된 화면으로 생성할 수 있습니다. 동시에 `first_frame`과 `last_frame`을 제공하면 시작점과 끝점을 명확하게 제어할 수 있습니다. 전환, 형태 변화, 성장 과정 또는 제품 전후 비교에 적합합니다.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "소녀가 어린 시절에서 자연스럽게 청년으로 성장하며, 시간의 흐름이 부드럽고 인물은 항상 화면 중앙에 위치합니다."
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_FIRST_FRAME_URL" },
      "role": "first_frame"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_LAST_FRAME_URL" },
      "role": "last_frame"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

첫 프레임과 마지막 프레임의 크기와 가로 세로 비율은 최대한 일치해야 하며, 주체 위치, 구성 및 조명 차이가 크지 않아야 자연스러운 전환을 얻기 쉽습니다.

## 다중 모달 참조 생비디오

참조 자료는 조합하여 사용할 수 있습니다: 참조 이미지는 캐릭터나 제품의 외관을 제어하고, 참조 비디오는 동작과 촬영을 제어하며, 참조 오디오는 대사 음색, 음악 또는 편집 리듬을 제어합니다. 프롬프트에는 각 종류의 자료가 무엇을 제어해야 하는지 명확히 설명해야 하며, 자료를 업로드하고 관계를 제공하지 않는 것을 피해야 합니다.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "참조 인물의 얼굴, 헤어스타일 및 의상을 일치시키고, 참조 비디오의 연기 동작에 따라 패션 단편 영화를 완성합니다; 카메라 리듬은 참조 오디오를 따르며, 클로즈업은 자연스러운 얼굴 표정을 강조합니다."
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_CHARACTER_IMAGE_URL" },
      "role": "reference_image"
    },
    {
      "type": "video_url",
      "video_url": { "url": "YOUR_PERFORMANCE_VIDEO_URL" },
      "role": "reference_video"
    },
    {
      "type": "audio_url",
      "audio_url": { "url": "YOUR_AUDIO_URL" },
      "role": "reference_audio"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

## 콜백 알림

`callback_url`을 전달하면 비동기 모드가 자동으로 활성화됩니다: 생성 인터페이스는 즉시 `task_id`와 `trace_id`를 반환하며, 작업이 완료되면 해당 주소로 최종 결과를 POST합니다. 구조는 작업 조회 응답과 일치합니다.

콜백의 최종 상태는 `succeeded`, `failed` 또는 `cancelled`입니다. 콜백을 사용하더라도 `task_id`를 저장하는 것이 좋으며, 이를 통해 적극적으로 조회하거나 누락된 알림을 보완할 수 있습니다.

## 일반적인 오류

| HTTP 상태 코드 | 의미           | 처리 제안                           |
| -------- | ------------ | ------------------------------ |
| `400`    | 매개변수 오류 또는 자료 조합 불법 | 필수 필드, `role`, 자료 수 및 형식 확인          |
| `401`    | 토큰 누락 또는 유효하지 않음  | `Authorization: Bearer ...` 확인 |
| `402`    | 잔액 또는 한도 부족      | 콘솔에서 일반 잔액 보충                     |
| `422`    | 콘텐츠 안전 검사 통과하지 않음    | 프롬프트 또는 자료 조정 후 재제출                  |
| `429`    | 요청이 너무 잦음       | 지수 백오프 후 재시도; 작업 폴링 제안 간격 약 10초         |
| `500`    | 서비스 일시적으로 사용 불가      | 요청 정보를 보관하고 나중에 재시도                    |

동기 응답의 `task.status: succeeded`는 비디오가 생성되었음을 나타냅니다; 비동기 확인은 작업이 대기열에 들어갔음을 나타냅니다. 작업이 최종적으로 성공할 때만 요금이 부과되며, 작업 조회는 무료로 반복 요금이 부과되지 않습니다.
