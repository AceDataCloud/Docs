Основная функция Suno Tasks API — запрашивать статус выполнения задачи путём ввода ID задачи, созданной Suno Audios Generation API или Suno Lyrics Generation API.

Этот документ подробно представит инструкции по интеграции Suno Tasks API, помогая вам легко интегрировать и в полной мере использовать мощные возможности этого API. С помощью Suno Tasks API вы можете легко реализовать запрос статуса выполнения задач Suno Lyrics Generation API или Suno Audios Generation API.

## Процесс подачи заявки

Чтобы использовать Suno Audios Generation API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications), чтобы сохранить его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти в систему, после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, без необходимости отдельно подавать заявку для каждого сервиса.** При первой заявке предоставляются бесплатные лимиты, которые можно использовать для бесплатного ознакомления; при недостатке лимитов вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Пример запроса

Suno Tasks API может использоваться для запроса результатов двух API: Suno Audios Generation API и Suno Lyrics Generation API. О том, как использовать Suno Audios Generation API, обратитесь к документации [Suno Audios Generation API ](https://platform.acedata.cloud/documents/suno-audios-integration). О том, как использовать Suno Lyrics Generation API, обратитесь к [Suno Lyrics Generation API ](https://platform.acedata.cloud/documents/suno-lyrics-generation-integration).

Мы возьмём в качестве примера ID задачи, возвращённый сервисом Suno Audios Generation API, чтобы продемонстрировать, как использовать этот API. Предположим, у нас есть ID задачи: eae26f89-b64b-404d-a80c-761996660b1c, далее продемонстрируем, как через передачу ID задачи.

### Настройка заголовков запроса и тела запроса

**Request Headers** включают:

- `accept`: указывает получение результатов ответа в формате JSON, здесь указывается `application/json`.
- `authorization`: ключ для вызова API, после получения заявки его можно напрямую выбрать в выпадающем списке.

**Request Body** включает:

- `id`: ID загруженной задачи.
- `action`: способ операции над задачей.

Некоторые примеры кода приведены ниже:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/suno/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "eae26f89-b64b-404d-a80c-761996660b1c",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/suno/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "eae26f89-b64b-404d-a80c-761996660b1c",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

```python
    "action": "retrieve_batch"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Обработка ошибок

При вызове API в случае возникновения ошибки API вернёт соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Неверный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `400 api_not_implemented`：Неверный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `401 invalid_token`：Не авторизовано, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили ограничение частоты запросов.
- `500 api_error`：Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
