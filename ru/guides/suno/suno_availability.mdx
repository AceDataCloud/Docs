---
title: "API проверки доступности аудио и голосов Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` принимает один ID ресурса. Для проверки песни передавайте `audio_id`, для проверки голоса передавайте `persona_id`, один из них обязателен. Проверка завершается синхронно, требуется API Token, в настоящее время Credits не списываются.

## Запрос

`audio_id` берётся из завершённой задачи песни и может использоваться для проверки перед продолжением или кавером.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

`persona_id` берётся из результата создания голоса. Используйте исходное приложение и личность вызывающего пользователя, и отправьте следующее тело запроса по линии создания, поддерживающей запросы голосов.

```json
{"persona_id":"33333333-3333-4333-8333-333333333333"}
```

## Ответ

Оба вида запросов используют один и тот же успешный ответ. `data.id` — это ID ресурса текущего запроса.

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

`available: true` означает, что в ходе этой проверки были получены положительные доказательства. Для голосов проверка верифицирует принадлежность создания и подтверждает, что связанный аккаунт в данный момент отмечен как онлайн. Фактический результат генерации всё равно определяется задачей генерации.

Приватные клонированные голоса, созданные через `/suno/voices`, зависят от аккаунта создания. Когда подтверждается, что этот аккаунт в данный момент офлайн, интерфейс возвращает HTTP 200, а пример `data` приведён ниже.

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

Клиент может пометить этот голос как временно недоступный и проверить позже.

Когда подтверждение невозможно, возвращаются HTTP 503 и `availability_unknown`, например если ресурс не найден, в старой записи отсутствует линия создания или запрос истёк по тайм-ауту. Публичные стили певцов могут использоваться между аккаунтами, и при офлайн-статусе аккаунта создания также возвращается 503. Запросы песен по-прежнему возвращают `available: true` только при подтверждённой доступности.

Каждый запрос отправляет только один действительный UUID. Все линии при получении запроса с двумя ID или с отсутствием обоих ID возвращают HTTP 400. Линии, поддерживающие только запросы песен, при получении запроса, содержащего только `persona_id`, возвращают HTTP 400. При HTTP 429 снизьте частоту запросов.
