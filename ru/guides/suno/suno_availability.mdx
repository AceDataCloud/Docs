---
title: "API проверки доступности аудио Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` на основе `audio_id` ищет положительные доказательства того, что аудио может быть продолжено в текущей линии. Может вызываться перед такими операциями, как продолжение, кавер и т. д.; результат отражает только состояние на момент проверки и не гарантирует, что конкретная операция обязательно будет успешной. Этот интерфейс возвращает результат синхронно, требует API Token и в настоящее время не списывает Credits.

`audio_id` — это ID песни, возвращённый завершённой задачей Suno, а не `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Пример успешного ответа:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

При успешной проверке `data.available` может быть только `true`. Статус «не в сети», возвращаемый некоторыми линиями, не может доказать, что последующие операции, такие как продолжение, не смогут быть успешными, поэтому этот интерфейс возвращает `503 availability_unknown`, когда не может подтвердить доступность, и не возвращает `false`. Ошибка формата `audio_id` возвращает 400, ограничение частоты запросов или сбой на стороне upstream также возвращают ответ с ошибкой. Состояние всё ещё может измениться между завершением проверки и фактической операцией.
