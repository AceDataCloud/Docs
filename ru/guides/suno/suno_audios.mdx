По мере расширения применения ИИ различные программы на базе ИИ постепенно становятся всё более распространёнными. ИИ постепенно проникает во все аспекты работы и жизни людей. Отраслей, связанных с ИИ, также становится всё больше: от первоначального написания текстов до медицины и образования, а теперь и музыки.

Suno — это профессиональная высококачественная платформа для создания песен и музыки с помощью ИИ. Пользователю достаточно ввести простой текстовый запрос, чтобы на основе жанра, стиля и текста песни сгенерировать композицию с вокалом. Этот генератор музыки на базе ИИ разработан командой из сотрудников известных технологических компаний, таких как Meta, TikTok, Kensho и других, с целью позволить каждому создавать прекрасную музыку без каких-либо музыкальных инструментов.

> Ограничения `lyric` и `style` в таблице выше являются верхними пределами в пользовательском режиме (`custom` имеет значение `true`). В непользовательском режиме вдохновения (`custom` имеет значение `false`) заполняется только `prompt`, а его максимальная длина составляет 500 символов (одинаково для всех моделей).

Suno теперь поддерживает `chirp-v6`, `chirp-v6-wild` и `chirp-v6-mini`. Рекомендуется использовать `chirp-v6`; старые названия моделей продолжают поддерживаться.

Однако официальный Suno не предоставляет API, поэтому AceDataCloud предоставляет набор API Suno, имитирующий официальную интеграцию Suno, что позволяет удобно и быстро генерировать нужную музыку.

## Получение и использование

Чтобы использовать Suno Audios Generation API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти в систему; после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, не нужно подавать отдельную заявку для каждого сервиса.** При первом получении предоставляется бесплатный лимит для бесплатного ознакомления; при недостатке лимита можно пополнить универсальный баланс в [консоли](https://platform.acedata.cloud/console/coin).

## Базовое использование

Можно вводить любой текст о том, какие песни вы хотите, например, если я хочу сгенерировать песню о Рождестве, можно ввести `a song for Christmas`, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Здесь можно увидеть, что мы настроили Request Headers, включая:

- `accept`: в каком формате вы хотите получить результат ответа; здесь указано `application/json`, то есть формат JSON.
- `authorization`: ключ для вызова API, после получения можно напрямую выбрать его из выпадающего списка.

Кроме того, настроен Request Body, включая:
- `action`: тип аудиозадачи, по умолчанию `generate`. Поддерживает операции генерации, продолжения, кавера, объединения, разделения на дорожки, добавления аудиодорожек, извлечения указанных аудиодорожек, генерации звуковых эффектов и регулировки скорости и т. д.; все вызываются через `POST /suno/audios`.
- `prompt`: подсказка режима вдохновения Suno (действует, когда `custom` имеет значение `false`), максимум 500 символов.
- `model`: модель для этой задачи генерации музыки. Серия v6 включает `chirp-v6`, `chirp-v6-wild` и `chirp-v6-mini`; старые названия моделей продолжают поддерживаться.
- `max_mode`: усиленный режим генерации. `generate` включается только когда и `custom`, и `max_mode` имеют значение `true`, стоимость составляет 1.12 Credits; `add_stem` можно включить напрямую, стоимость составляет 1.344 Credits. При отключении или пропуске значения составляют соответственно 0.56 и 0.672 Credits.
- `variety`: интенсивность разнообразия результатов генерации, доступны `off`, `normal`, `high`, `extra`, `max`. Используется только для `generate` и `add_stem`; передача для других action вернёт 400.
- `lyric`: текст песни в пользовательском режиме Suno. Для `chirp-v3-5` и `chirp-v4` максимум 3000 символов; для `chirp-v4-5` и выше (включая `chirp-v5`, `chirp-v5-5`) максимум 5000 символов.
- `custom`: использовать ли пользовательский режим, по умолчанию: `false`.
- `instrumental`: опция инструментальной музыки в режиме вдохновения Suno.
- `title`: название музыки в пользовательском режиме Suno. Для `chirp-v3-5`, `chirp-v4` максимум 80 символов; для `chirp-v4-5` и выше максимум 100 символов.
- `style`: музыкальный стиль пользовательского режима Suno. Для `chirp-v3-5` и `chirp-v4` максимум 200 символов; для `chirp-v4-5` и выше (включая `chirp-v5`, `chirp-v5-5`) максимум 1000 символов.
- `negative_tags`: музыкальные стили или жанры, которые нужно исключить из результатов генерации в пользовательском режиме (когда `custom` имеет значение `true`).
- `audio_weight`: вес влияния аудио- или голосовых характеристик, диапазон 0-1, `0` также является допустимым значением. Может использоваться для операций генерации, продолжения, кавера, добавления аудиодорожек и согласованности голоса и т. д.; при отсутствии эталонного аудио или голосовых характеристик модель может ослабить или проигнорировать это значение.
- `audio_id`: ID эталонной музыки.
- `overpainting_start`/`overpainting_end`: время начала и окончания добавления вокала к существующей инструментальной музыке, в секундах.
- `underpainting_start`/`underpainting_end`: время начала и окончания добавления аккомпанемента к а капелла, в секундах.
- `persona_id`: ID песни исполнителя.
- `continue_at`: граница продолжения, в секундах. Например, 213.5 означает начало генерации последующего фрагмента с отметки 3 минуты 33.5 секунды. `lyric` и `style` направляют только новое содержимое после границы и не заменяют текст или вокал до границы в исходном аудио.
- `style_influence`: влияние стиля в пользовательском режиме, диапазон 0-1; чем больше значение, тем обычно точнее соответствие выбранному стилю; `0` передаётся как допустимое значение.
- `replace_section_end`: конечное время заменяемого фрагмента.
- `replace_section_start`: начальное время заменяемого фрагмента.
- `vocal_gender`: управляет предпочтением женского или мужского вокала: женский голос `f`, мужской голос `m`; действует для моделей 4.5 и выше; является параметром предпочтения и не гарантирует строгого соблюдения.
- `weirdness`: степень необычности в пользовательском режиме, диапазон 0-1; чем больше значение, тем обычно более креативен и экспериментален результат; `0` передаётся как допустимое значение.
- `duration`: желаемая длительность песни в секундах, должна быть целым числом в диапазоне от 10 до 360. Этот параметр используется для генерации песен в пользовательском режиме (когда `custom` имеет значение `true`). Это ориентир, а не жёсткое ограничение: модель учитывает его, но не гарантирует достижения, фактическая длительность готового результата определяется полем `duration` в ответе и обычно короче желаемой.

### Область применения расширенных параметров

| Параметр                | Значение                                          | Поддерживаемые action                              | Описание                              |
| ----------------- | ------------------------------------------- | --------------------------------------- | ------------------------------- |
| `weirdness`       | 0-1                                         | Необязательно                                      | Регулирует экспериментальность, `0` является допустимым значением; эффект зависит от операции, режима и модели    |
| `style_influence` | 0-1                                         | Необязательно                                      | Регулирует тенденцию следования стилю, `0` является допустимым значением; эффект зависит от операции, режима и модели |
| `audio_weight`    | 0-1                                         | Необязательно                                      | Регулирует влияние аудио- или голосовых характеристик; без эталонной информации может быть проигнорирован моделью      |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`, `add_stem`                   | Регулирует стилевое разнообразие между результатами                     |
| `max_mode`        | boolean                                     | `generate` (требуется `custom=true`), `add_stem` | Усиливает согласованность и тарифицируется по усиленному режиму                   |
| `vocal_gender`    | `f` / `m`                                   | Операции генерации, поддерживающие управление вокалом                             | Параметр предпочтения, не гарантирует строгого соблюдения                     |
| `duration`        | Целое число 10-360                                   | Необязательно                                      | Желаемая длительность; конкретная операция, режим или модель могут проигнорировать             |

Платформа проверяет типы параметров и диапазоны значений, но не отклоняет эти необязательные параметры регулировки только из-за различий в action; конкретный эффект определяется операцией, режимом и моделью.

- `lyric_prompt`: prompt для генерации текста песни, действует тогда и только тогда, когда `custom` имеет значение `true` и `lyric` не передан.
- `callback_url`: URL, на который требуется отправить результат обратным вызовом.
- `async`: необязательно; когда установлено значение `true`, интерфейс немедленно возвращает `task_id`, предоставлять `callback_url` не требуется, после чего результат можно получить путём опроса соответствующего интерфейса запроса задач.

## Пользовательское создание

Если вы хотите пользовательски создать текст песни, можно ввести текст песни:

В этот момент в поле `lyric` можно передать содержимое, подобное следующему:

```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near

Если вы не знаете, как создавать текст песни, можно использовать API генерации текстов песен, предоставляемый AceDataCloud, для создания текста песни через prompt; API: [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics)。

Далее, чтобы пользовательски создать песню на основе текста песни, названия и стиля, можно указать следующее содержимое:

- lyric：текст песни
- custom：укажите `true`, что означает пользовательское создание; по умолчанию этот параметр имеет значение false, что означает создание с использованием `prompt`.
- title：название песни.
- style：стиль песни, необязательно.

## Функция создания в пользовательском стиле певца
Если вы хотите использовать стиль певца для генерации песни, сначала сгенерируйте песню с помощью базового использования, описанного выше,
в итоге необходимо настроить эту песню как стиль певца, затем нужно перейти в [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona), чтобы на основе официального ID сгенерированной музыки `audio_id` создать параметр ID стиля певца `persona_id`, конкретные параметры показаны на рисунке ниже:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

После заполнения автоматически генерируется следующий код:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

Соответствующий код Python:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

```json

## Функция продолжения генерации

Если вы хотите продолжить генерацию уже созданной песни Suno, можно установить для параметра `action` значение `extend` и ввести ID песни, генерацию которой нужно продолжить. ID песни получается через базовое использование; как видно из приведённого выше, в этот момент можно увидеть, что ID песни следующий:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Обратите внимание, что `id` в тексте песни здесь является ID песни после генерации; если вы не знаете, как генерировать песни, вы можете обратиться к базовому использованию выше для генерации песни.

Если вы хотите продолжить генерацию песни, загруженной вами самостоятельно, можно установить для параметра `action` значение `upload_extend` и ввести ID пользовательской загруженной песни, генерацию которой нужно продолжить. ID песни получается с помощью [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), как показано на рисунке ниже:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Далее необходимо заполнить текст песни для продолжаемого фрагмента, а также можно указать стиль:

- lyric：используется только для направления текста нового генерируемого фрагмента после `continue_at`, не заменяет текст в исходном аудио до этой временной точки.
- custom：установите значение `true`, что означает пользовательскую генерацию; по умолчанию этот параметр имеет значение false, что означает генерацию с использованием `prompt`.
- style：стиль песни для продолжаемого фрагмента, необязательно.
- continue_at：граница продолжения, в секундах. Например, 213.5 означает начало генерации последующего фрагмента с отметки 3 минуты 33.5 секунды.

> `extend` используется для продолжения создания уже существующей песни, а не для замены текста всей песни. Если вы хотите использовать новый текст для всей песни с самого начала, используйте `generate` для повторной генерации; если вы хотите переисполнить песню с опорой на существующую, можно использовать `cover`. При передаче нового текста целой песни исходный текст до `continue_at` всё равно не будет заменён.

Пример заполнения приведён ниже:

Ниже сохранён снимок реального исторического вызова, в котором `continue_at` равен 2 секундам, поэтому только первые 2 секунды относятся к исходному содержимому до границы продолжения. При фактическом продолжении вблизи конца песни это значение следует установить на секунду, с которой ожидается начало продолжения, и предоставлять в `lyric` только новый фрагмент, который должен исполняться после границы.

- action: значение — `concat`.

## Замена фрагмента

Если после генерации песни необходимо выполнить вторичное создание с отдельной операцией замены фрагмента песни, можно выполнить замену определённого фрагмента песни.

> ⚠️ **Внимание**：значение `replace_section_result_mode` по умолчанию — `full_song`：система отдельно склеит 2 новых сгенерированных кандидата и вернёт 2 полные песни. Если нужны только ещё не склеенные кандидаты заменяемых фрагментов, явно установите значение `candidates`, затем выберите кандидата и вызовите [Склейку музыки](#音乐拼接)。

Описание параметров следующее：

- action：значение `replace_section`。
- audio_id：ID исходной песни (исходной песни, в которой производится замена)。
- model: Модель генерации песни。
- lyric: Полный текст песни после замены (включая заменяемый фрагмент и его контекст, соответствует содержимому в `prompt`)。
- prompt：Новый текст песни для фрагмента, который необходимо заменить。
- style：Стиль песни, необязательно。
- replace_section_start：Время начала заменяемого фрагмента в исходной песне (секунды)。
- replace_section_end：Время окончания заменяемого фрагмента в исходной песне (секунды)。
- replace_section_result_mode：Режим возврата, по умолчанию `full_song`。`full_song` отдельно склеивает 2 кандидата и возвращает 2 полные песни；`candidates` возвращает 2 ещё не склеенных фрагмента-кандидата。

### Шаг 1: Запуск задачи замены фрагмента

```json

  "replace_section_start": 30.0,
  "replace_section_end": 60.0,
  "replace_section_result_mode": "full_song"
}
```

По умолчанию возвращаются 2 полные песни, каждая из которых составлена из одного из двух кандидатов. Если установить `replace_section_result_mode` в значение `candidates`, будут возвращены 2 ещё не склеенных заменяющих фрагмента со структурой, идентичной примеру ниже:

- action: значение — `stems`.

{

}

## Управление длительностью песни

По умолчанию длительность генерируемой песни определяется самой моделью и обычно составляет от 30 секунд до 4 минут. Если требуется более длинный или более короткий готовый результат, можно указать желаемую длительность через параметр `duration`, единица измерения — секунды, допустимы целые значения от 10 до 360.

Этот параметр используется для генерации песен в пользовательском режиме (`custom` имеет значение `true`). Следует особо отметить, что `duration` — это **ориентирующая подсказка, а не жёсткое ограничение**: модель будет учитывать это значение при создании, но не гарантирует его достижения; на практике фактическая длительность обычно значительно меньше ожидаемого значения, а длительность двух песен, возвращённых одним и тем же запросом, также может различаться в несколько раз. Даже при полностью одинаковых запросах длительность, полученная при многократной отправке, может значительно различаться. Поэтому не следует использовать его как точное управление длительностью; если в бизнес-логике требуется фиксированная длительность, после получения готового результата самостоятельно обрежьте его или повторите попытку.

Соответствующий код Python:
```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Следует отметить, что `duration` в запросе является **ожидаемой длительностью**, тогда как поле `duration` каждой песни в ответе `data` является **фактической длительностью** данной песни. Названия у них одинаковые, но значения различаются; фактическая длительность не гарантированно равна ожидаемому значению. Длина текста песни является одним из основных факторов, влияющих на длительность готового результата; если требуется более длинный результат, рекомендуется также предоставить более полный текст песни.

Интерфейс проверяет, что `duration` должно быть целым числом от 10 до 360; это всё ещё лишь цель генерации, а не гарантия длительности готового результата.

В августе 2025 года Suno представил новую функцию Add Insterumental. Сначала необходимо загрузить песню а капелла без озвучки, чтобы Suno помог вам добавить музыкальное сопровождение. Сначала можно загрузить песню а капелла без музыкального сопровождения через [Suno Upload API](https://platform.acedata.cloud/documents/suno-upload), соответствующие действия показаны на рисунке ниже:

- underpainting_start: время начала добавления сопровождения к загруженной песне, значение по умолчанию — 0.
- underpainting_end: время окончания добавления сопровождения к загруженной песне, должно быть меньше общей длительности песни.
- audio_id: ID загруженной песни а капелла без озвучки.

## Функция вдохновляющего творчества Inspo

Функция вдохновляющего творчества Inspo может генерировать новую музыку на основе 1–4 полных эталонных аудиозаписей и поддерживает перетаскивание или загрузку аудио в качестве источника вдохновения. API использует существующее действие `inspo`: клиент предоставляет общедоступные URL-адреса аудио, а сервис автоматически выполняет подготовку эталонного аудио и создание композиции; клиенту не требуется отдельно считывать текст, стиль или длительность, а затем собирать запрос. Она отличается как от описанного выше интервального сэмплирования, так и от Cover, воспроизводящего стиль оригинальной песни. При использовании необходимо заполнить следующие параметры:

- action: значение — `inspo`.
- audio_urls: список URL-адресов эталонного аудио; необходимо предоставить от 1 до 4 общедоступных аудиоадресов.
- model: используемая модель, рекомендуется `chirp-v6`.
- prompt: текст песни или подсказка для творчества (необязательно).

> Примечание: эталонное аудио должно быть общедоступным аудиофайлом. Если эталонное аудио полностью совпадает с известной записью в библиотеке треков платформы, Suno может отклонить генерацию из-за проверки авторских прав; рекомендуется использовать собственное аудио или аудио, сгенерированное Suno, в качестве источника вдохновения.

Соответствующий код Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Асинхронный обратный вызов

Поскольку Suno генерирует музыку относительно долго, примерно 1–2 минуты, если API долго не отвечает, HTTP-запрос будет постоянно поддерживать соединение, что приводит к дополнительному потреблению системных ресурсов, поэтому этот API также поддерживает асинхронные обратные вызовы.

Общий процесс таков: когда клиент инициирует запрос, он дополнительно указывает поле `callback_url`; после того как клиент инициирует API-запрос, API немедленно возвращает результат, содержащий поле `task_id`, представляющее ID текущей задачи. После завершения задачи результат сгенерированной музыки будет отправлен в виде POST JSON на указанный клиентом `callback_url`, который также включает поле `task_id`, благодаря чему результаты задач можно связать по ID.

Ниже мы на примере рассмотрим, как именно это работает.

Сначала, обратный вызов Webhook — это сервис, способный принимать HTTP-запросы, разработчик должен заменить его на URL собственного HTTP-сервера. Здесь для удобства демонстрации используется публичный сайт с примером Webhook https://webhook.site/; открыв этот сайт, можно получить Webhook URL, как показано на рисунке:

![](https://cdn.acedata.cloud/fwfqin.png)
