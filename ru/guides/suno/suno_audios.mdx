С расширением применения ИИ различные программы ИИ постепенно стали распространёнными. ИИ постепенно проникает во все аспекты работы и жизни людей. А отраслей, связанных с ИИ, становится всё больше: от первоначального написания текстов до медицины и образования, а теперь и до музыки.

Suno — это профессиональная высококачественная платформа для создания песен и музыки с помощью ИИ. Пользователю достаточно ввести простой текстовый промпт, чтобы на основе жанрового стиля и текста песни сгенерировать песню с вокалом. Этот генератор музыки на базе ИИ разработан членами команды из таких известных технологических компаний, как Meta, TikTok, Kensho и других; его цель — не требовать никаких инструментов, чтобы каждый мог создавать прекрасную музыку.

> Ограничения `lyric` и `style` в таблице выше являются верхними пределами в пользовательском режиме (`custom` равен `true`). В непользовательском режиме вдохновения (`custom` равен `false`) заполняется только `prompt`, его максимальная длина составляет 500 символов (одинаково для всех моделей).

Suno теперь поддерживает `chirp-v6`, `chirp-v6-wild` и `chirp-v6-mini`. Рекомендуется использовать `chirp-v6`; старые названия моделей остаются совместимыми.

Однако официальный Suno не предоставляет API, AceDataCloud предоставляет набор API Suno, имитирующий интеграцию с официальным Suno, с помощью которого можно удобно и быстро генерировать желаемую музыку.

## Получение и использование

Чтобы использовать Suno Audios Generation API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти, после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, не нужно подавать отдельную заявку для каждого сервиса.** При первой заявке будут предоставлены бесплатные квоты, можно бесплатно опробовать; при недостаточной квоте можно пополнить универсальный баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Базовое использование

О том, какие песни вы хотите, можно произвольно ввести один фрагмент текста, например, если я хочу сгенерировать песню о Рождестве, можно ввести `a song for Christmas`, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Можно увидеть, что здесь мы настроили Request Headers, включая:

- `accept`: в каком формате вы хотите получить результат ответа, здесь указано `application/json`, то есть формат JSON.
- `authorization`: ключ для вызова API, после получения можно напрямую выбрать из выпадающего списка.

Кроме того, настроен Request Body, включая:
- `action`: тип аудиозадачи, по умолчанию — `generate`. Поддерживает операции генерации, продолжения, кавера, объединения, разделения на дорожки, добавления аудиодорожки, извлечения указанной аудиодорожки, генерации звуковых эффектов и регулировки скорости и т. д.; все они вызываются через `POST /suno/audios`.
- `prompt`: подсказка для режима вдохновения Suno (действует, когда `custom` имеет значение `false`), максимум 500 символов.
- `model`: модель для этой задачи генерации музыки. Серия v6 включает `chirp-v6`, `chirp-v6-wild` и `chirp-v6-mini`; старые названия моделей остаются совместимыми.
- `max_mode`: расширенный режим генерации. Для `generate` включается только когда и `custom`, и `max_mode` имеют значение `true`, стоимость составляет 1.12 Credits; для `add_stem` может включаться напрямую, стоимость составляет 1.344 Credits. При отключении или пропуске стоимость составляет соответственно 0.56 и 0.672 Credits.
- `variety`: интенсивность разнообразия результатов генерации, доступны `off`, `normal`, `high`, `extra`, `max`. Используется только для `generate` и `add_stem`; передача для других action вернёт 400.
- `lyric`: содержание текста песни для пользовательского режима Suno. Для `chirp-v3-5` и `chirp-v4` максимум 3000 символов; для `chirp-v4-5` и выше (включая `chirp-v5`, `chirp-v5-5`) максимум 5000 символов.
- `custom`: использовать ли пользовательский режим, по умолчанию: `false`.
- `instrumental`: опция инструментальной музыки в режиме вдохновения Suno.
- `title`: название музыки для пользовательского режима Suno. Для `chirp-v3-5`, `chirp-v4` максимум 80 символов; для `chirp-v4-5` и выше максимум 100 символов.
- `style`: музыкальный стиль пользовательского режима Suno. Для `chirp-v3-5` и `chirp-v4` максимум 200 символов; для `chirp-v4-5` и выше (включая `chirp-v5`, `chirp-v5-5`) максимум 1000 символов.
- `negative_tags`: музыкальные стили или жанры, которые требуется исключить при пользовательской генерации; также может использоваться для `replace_section`. В настоящее время этот интерфейс не устанавливает фиксированное ограничение на количество символов для данного поля; слишком длинное содержимое всё ещё может не обрабатываться, рекомендуется сохранять описание кратким.
- `audio_weight`: вес влияния аудио или звуковых характеристик, диапазон 0-1, `0` также является допустимым значением. Может использоваться для операций генерации, продолжения, кавера, добавления аудиодорожки и согласованности голоса и т. д.; при отсутствии эталонного аудио или звуковых характеристик модель может ослабить или игнорировать это значение.
- `audio_id`: ID эталонной музыки, используется для последующих операций, таких как кавер, продолжение, разделение на дорожки и т. д. Аудиофайл всё ещё может быть доступен для скачивания, но это не означает, что последующая обработка этого ID всегда доступна; если возвращается `suno_processing_unavailable`, сохраните `task_id` и `trace_id` и обратитесь в поддержку.
- `overpainting_start`/`overpainting_end`: время начала и окончания добавления вокала к существующей инструментальной музыке, в секундах.
- `underpainting_start`/`underpainting_end`: время начала и окончания добавления сопровождения к а капелла, в секундах.
- `persona_id`: ID голоса, полученный через интерфейс создания Persona или голоса, а не `audio_id` песни.
- `continue_at`: граница продолжения, в секундах. Например, 213.5 означает начало генерации последующего фрагмента с отметки 3 минуты 33.5 секунды. `lyric` и `style` направляют только новое содержимое после границы и не заменяют текст или исполнение в исходном аудио до границы.
- `style_influence`: влияние стиля в пользовательском режиме, диапазон 0-1; чем больше значение, тем обычно точнее соответствие выбранному стилю; `0` передаётся как допустимое значение.
- `replace_section_end`: конечное время заменяемого фрагмента.
- `replace_section_start`: начальное время заменяемого фрагмента.
- `vocal_gender`: управляет предпочтением женского или мужского голоса: женский голос — `f`, мужской голос — `m`; действует для моделей 4.5 и выше; является предпочтительным параметром и не гарантирует строгого соблюдения.
- `weirdness`: степень необычности в пользовательском режиме, диапазон 0-1; чем больше значение, тем обычно выше креативность и экспериментальность; `0` передаётся как допустимое значение.
- `duration`: желаемая длительность песни, в секундах; должна быть целым числом в диапазоне от 10 до 360. В настоящее время этот параметр используется только `generate`, конкретный эффект зависит от режима и модели. Это ориентир, а не жёсткое ограничение: модель учитывает его, но не гарантирует достижения; фактическая длительность готового результата определяется полем `duration` в ответе и обычно короче желаемой.

### Область применения ID голоса

`generate`, `cover`, `upload_cover`, `artist_consistency`, `artist_consistency_vox` могут использовать `persona_id`. Последние два action должны предоставлять `persona_id`; также можно одновременно предоставить `audio_id` песни, использованной при создании этой Persona.

`extend`, `upload_extend` не используют дополнительный `persona_id`. Поддерживают ли `mashup`, `inspo` ID голоса, зависит от выбранного сервисного канала; для других action применение этого поля не гарантируется, используйте согласно описанию каждой операции. `vocal_gender` является необязательным предпочтением пола и не может заменить ID голоса.

Последующие творческие операции требуют действительного исходного `audio_id`; для `mashup` требуется как минимум два `mashup_audio_ids`. При отсутствии необходимых источников или временных параметров будет возвращён HTTP 400.

### Область применения расширенных параметров
| Параметр                | Значение                                          | Поддерживаемые action                              | Описание                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | Необязательно                                      | Регулирует экспериментальность, `0` — допустимое значение; эффект зависит от операции, режима и модели      |
| `style_influence` | 0-1                                         | Необязательно                                      | Регулирует склонность к следованию стилю, `0` — допустимое значение; эффект зависит от операции, режима и модели   |
| `audio_weight`    | 0-1                                         | Необязательно                                      | Регулирует влияние аудио или звуковых характеристик; при отсутствии справочной информации может игнорироваться моделью        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`、`add_stem`                   | Регулирует стилевое разнообразие между результатами                       |
| `max_mode`        | boolean                                     | `generate`（требует `custom=true`）、`add_stem` | Усиливает согласованность и тарифицируется в усиленном режиме                     |
| `vocal_gender`    | `f` / `m`                                   | Операции генерации, поддерживающие управление вокалом                             | Предпочтение, строгое соблюдение не гарантируется                       |
| `duration`        | целое число 10-360                                   | `generate`                              | Ожидаемая длительность; другие action в настоящее время не используют это поле, фактическая длина определяется результатом |

Платформа проверяет типы параметров и диапазоны значений, но не отклоняет эти необязательные параметры регулировки только из-за различий в action; конкретный эффект определяется операцией, режимом и моделью.

- `lyric_prompt`：prompt для генерации текста песни, действует тогда и только тогда, когда `custom` имеет значение `true` и `lyric` не передан.
- `callback_url`：URL, на который требуется отправить результат обратного вызова.
- `async`：необязательно, при установке в `true` интерфейс немедленно возвращает `task_id`, без необходимости предоставлять `callback_url`, после чего результат получается путём опроса соответствующего интерфейса запроса задач.

## Пользовательская генерация

Если вы хотите пользовательски сгенерировать текст песни, можно ввести текст песни:

В этот момент в поле `lyric` можно передать содержимое, подобное следующему:
```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> Обратите внимание: `\n` в тексте песни здесь является символом переноса строки. Если вы не знаете, как сгенерировать текст песни, вы можете использовать API генерации текстов песен, предоставляемый AceDataCloud, чтобы сгенерировать текст песни через prompt: [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Далее мы можем настраивать генерацию песни на основе текста, названия и стиля, указав следующее содержимое:

- lyric：текст песни
- custom：укажите `true`, что означает пользовательскую генерацию; по умолчанию этот параметр имеет значение false, что означает генерацию с использованием `prompt`.
- title：название песни.
- style：стиль песни, необязательно.

## Функция продолжения генерации
Если вы хотите продолжить генерацию уже созданной песни Suno, можно установить параметр `action` в значение `extend` и указать ID песни, которую нужно продолжить. ID песни получается на основе базового использования, как видно выше, в этот момент можно увидеть, что ID песни:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Обратите внимание, что `id` в тексте песни здесь — это ID сгенерированной песни. Если вы не знаете, как генерировать песни, можете обратиться к базовому использованию выше для генерации песни.

Если вы хотите продолжить генерацию собственной загруженной песни, можно установить параметр `action` в значение `upload_extend` и указать ID собственной загруженной песни, которую нужно продолжить. ID песни получается с помощью [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), как показано на изображении ниже:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Далее необходимо заполнить текст продолжения фрагмента, а также можно указать стиль:

- lyric: используется только для направления текста нового генерируемого фрагмента после `continue_at`, не заменяет текст в исходном аудио до этой временной точки.
- custom: укажите `true`, что означает пользовательскую генерацию; по умолчанию этот параметр равен false, что означает генерацию с использованием `prompt`.
- style: музыкальный стиль фрагмента продолжения, необязательно.
- continue_at: граница продолжения, в секундах. Например, 213.5 означает начало генерации последующего фрагмента с отметки 3 минуты 33,5 секунды.

Значение `continue_at` для `extend` и `upload_extend` должно быть больше 0, поддерживаются дробные секунды, например `30.792`; при отправке значение не будет округляться.

> `extend` используется для продолжения творчества после существующей песни, а не для замены текста всей песни. Если вы хотите использовать новый текст для всей песни с самого начала, используйте `generate` для повторной генерации; если вы хотите переисполнить песню, ориентируясь на существующую, можно использовать `cover`. При передаче полного нового текста исходный текст до `continue_at` всё равно не будет заменён.

Пример заполнения ниже:

При фактическом продолжении ближе к концу песни это значение следует установить на секунду, с которой вы хотите начать продолжение, и предоставить в `lyric` только новый фрагмент, который должен исполняться после границы.

- action：значение `concat`。

## Кавер-версия музыки

Когда песня продолжает генерироваться на основе исходной песни, стиль возвращённой песни может оказаться не совсем подходящим. Если необходимо создать кавер-версию ранее сгенерированной песни (также поддерживается пользовательская загруженная музыка), необходимо использовать метод создания кавер-версии музыки, при этом можно указать следующее содержимое:

- action：значение `cover`; при выполнении операции кавер-версии для пользовательской загруженной музыки обязательно необходимо указать значение：`upload_cover`。

## Замена фрагмента

`replace_section` повторно генерирует выбранный фрагмент в соответствии с временным интервалом исходной песни и вставляет результат обратно в оригинальную композицию. Значение `replace_section_result_mode` по умолчанию — `full_song`, возвращаются 2 полные песни, которые можно воспроизводить напрямую, без необходимости снова вызывать `concat`。

### Как заполнить входные данные
- `action`: `replace_section`.
- `audio_id`: полный ID песни, которую нужно редактировать. При повторном редактировании используйте `data[].id` полной песни, выбранной в предыдущий раз, а не `task_id`.
- `model`: модель генерации песни, например `chirp-v6`.
- `lyric`: **локальный новый текст**, который должен быть спет в выбранном интервале. Не нужно передавать полный текст песни ради получения полной песни.
- `prompt`: явно указывает локальный новый текст для этой замены. При изменении текста рекомендуется заполнить тем же содержимым, что и `lyric`, чтобы два поля не выражали разные тексты. Существующие запросы, передающие только локальный `lyric` и пропускающие `prompt`, по-прежнему можно использовать, но добавление `prompt` само по себе не гарантирует успешного изменения текста.
- `style`, `negative_tags`: необязательное описание стиля и исключения; `prompt` в этой операции не является обычным описанием вдохновения при создании песни.
- `replace_section_start`, `replace_section_end`: время начала и окончания выделенного интервала в исходной песне для этого запроса, в секундах, поддерживаются десятичные значения. Начальная точка не должна быть меньше 0, конечная точка должна быть больше начальной и не должна превышать длительность исходной песни.
- `replace_section_result_mode`: `full_song` (по умолчанию) возвращает 2 полные песни; `candidates` возвращает 2 ещё не объединённых кандидата на замену.

Не следует считать «`lyric` должен быть полным текстом после замены, а `prompt` должен быть локальным текстом» универсальным способом использования. Ввод полного текста в некоторых задачах может создавать слишком длинное заменяемое содержимое, из-за чего после объединения вся песня значительно удлиняется. Локальный ввод также не гарантирует фиксированную длительность или дословное следование тексту; это генеративное редактирование, и необходимо проверять фактическое аудио.

### Запуск задачи и получение полной песни

Ниже приведён пример формата запроса. Замените `YOUR_COMPLETED_AUDIO_ID` и временной интервал на ID своей исходной песни и фактический выбранный интервал; пример предполагает, что 30–50-я секунды соответствуют следующим четырём строкам.

```json
{
  "action": "replace_section",
  "audio_id": "YOUR_COMPLETED_AUDIO_ID",
  "model": "chirp-v6",
  "custom": false,
  "instrumental": false,
  "lyric": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "prompt": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "replace_section_start": 30.0,
  "replace_section_end": 50.0,
  "replace_section_result_mode": "full_song",
  "async": true
}
```

После отправки используйте возвращённый `task_id` для запроса `/suno/tasks`, тело запроса: `{"action":"retrieve","id":"YOUR_TASK_ID"}`. После завершения задачи получите `id`, `audio_url` и `duration` двух полных песен в `response.data` ответа задачи, прослушайте их и выберите одну. `success: true` означает, что задача выполнена успешно, но не означает, что новый текст был спет дословно или что длительность соответствует ожиданиям.

### Выбранный интервал, проверка результата и повторное редактирование

1. Сначала прослушайте исходную песню, затем определите выбранный интервал с учётом временной информации из `/suno/timing`, стараясь охватить полные музыкальные фразы. Не выбирайте интервал по фиксированным индексам массива текстов и не заменяйте несколькими строками текста интервал, содержащий больше музыкальных фраз, ожидая, что ритм останется полностью неизменным.
2. Количество строк, символов и ритм нового текста должны по возможности быть близки к исходному содержимому выбранного интервала. Даже при изменении лишь нескольких символов необходимо проверить результат прослушиванием, это не может гарантировать успех.
3. Проверьте, спет ли новый текст в целевом интервале, естественны ли переходы до и после него, а также разумна ли длительность всей песни. `full_song` означает возврат полной песни, а не то, что она будет той же длительности, что и исходная; когда заменяемый фрагмент становится длиннее, вторая половина соответственно сдвигается дальше. Параметр запроса `duration` используется только для обычной генерации и не может зафиксировать длительность заменяемого фрагмента.
4. Возвращаемый `lyric` является метаданными текста; в режиме полной песни полный текст будет объединён, если удаётся получить временную информацию текста исходной песни; если получить её невозможно, он может быть пустым. Это не аудиотранскрипция, и появление нового текста не доказывает, что аудио действительно спело новый текст. Информацию о временном выравнивании также следует сверять с прослушиванием, особенно для уже отредактированных результатов.
5. При повторном редактировании используйте выбранный **полный ID готового результата** как новый `audio_id` и повторно проверьте длительность этого результата и выбранный интервал. Не копируйте временные координаты из состояния до редактирования и не используйте напрямую полный `lyric`, возвращённый в прошлый раз, как локальный ввод для текущего запроса.

Если задача завершена, но по-прежнему поётся старый текст, пропущен текст или длительность значительно увеличилась, сначала проверьте ID исходной песни, выбранный интервал и локальный текст, затем проверьте второй результат. Увеличение частоты запросов состояния задачи не изменит уже сгенерированное содержимое. Если проблема сохраняется, сохраните `task_id`, ID исходной песни, поля запроса, выбранный интервал и результирующее аудио для проверки.

### Необязательно: сначала получить кандидатов, затем объединить вручную

Только если необходимо самостоятельно выбрать кандидата на замену, установите `replace_section_result_mode: "candidates"`. Кандидаты могут содержать контекст, поэтому нельзя считать их полными песнями только по их длительности. После выбора вызовите `concat` с `data[].id` кандидата, затем получите полный готовый результат.

`full_song` по умолчанию уже выполняет объединение, поэтому этот шаг не требуется.

## Разделение вокала и музыки

Тарификация: после успешного выполнения `action=stems` стандартная стоимость каждого запроса составляет **0.56 Credits**; возвращаемые одним запросом вокал и сопровождение вместе считаются одним разом. Применимые скидки на потребление определяются фактическим счётом, неуспешные запросы не тарифицируются. `all_stems` и `extract_stem` тарифицируются по соответствующим ценам.

Когда после генерации песни требуется вторичное творчество с отдельными операциями над сопровождением и вокалом, можно разделить чисто музыкальное сопровождение и вокал а капелла. Можно указать следующее содержимое:

- action: значение `stems`.

```json
{
  "action": "stems",

}
```

```json
{
  "action": "all_stems",
  "audio_id": "bdf23a5a-59f5-4103-b452-054a824a7f9f"
}
```

## Управление длительностью песни

По умолчанию длительность генерируемой песни определяется самой моделью и обычно составляет от 30 секунд до 4 минут. Если требуется более длинный или короткий готовый результат, можно указать желаемую длительность с помощью параметра `duration`, единица измерения — секунды, значение — целое число от 10 до 360.

Этот параметр используется для генерации песен в пользовательском режиме (`custom` равен `true`). Следует особо отметить, что `duration` — это **ориентир, а не жёсткое ограничение**: модель будет учитывать это значение при создании, но не гарантирует его достижение; на практике фактическая длительность обычно заметно короче ожидаемой, а длительность двух песен, возвращённых одним запросом, также может отличаться в несколько раз. Даже для полностью одинаковых запросов длительность, полученная при нескольких отправках, также может значительно различаться. Поэтому не следует использовать его как точное управление длительностью; если бизнесу требуется фиксированная длительность, самостоятельно обрежьте готовый результат или повторите попытку после его получения.

Соответствующий код Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Следует отметить, что `duration` в запросе — это **ожидаемая длительность**, а поле `duration` каждой песни в ответе `data` — это **фактическая длительность** данной песни. Их названия одинаковы, но значения различны; фактическая длительность не гарантированно равна ожидаемому значению. Длина текста песни является одним из основных факторов, влияющих на длительность готового результата; если требуется более длинный готовый результат, рекомендуется одновременно предоставить более полный текст песни.

Интерфейс проверяет, что `duration` должен быть целым числом от 10 до 360; он по-прежнему является лишь целью генерации, а не гарантией длины готового результата.

## Функция вдохновляющего творчества Inspo

Функция вдохновляющего творчества Inspo может генерировать новую музыку на основе от 1 до 4 полных эталонных аудиофайлов, поддерживая перетаскивание или загрузку аудио в качестве источника вдохновения. API использует существующее действие `inspo`: клиент предоставляет общедоступные URL аудио, а сервис автоматически завершает подготовку эталонных аудиофайлов и создание произведения, без необходимости клиенту отдельно считывать текст, стиль или длительность и затем собирать запрос. Она отличается как от выборки диапазона, описанной выше, так и от Cover, воспроизводящего стиль оригинальной песни. При использовании необходимо заполнить следующие параметры:

- action: значение `inspo`.
- audio_urls: список URL эталонных аудиофайлов; необходимо предоставить от 1 до 4 общедоступных аудиоадресов.
- model: используемая модель, рекомендуется `chirp-v6`.
- prompt: текст песни или подсказка для создания (необязательно).
- instrumental: при значении `true` генерация выполняется по запросу на инструментальную музыку, без использования текста песни.
- persona_id: использовать указанный голос в канале сервиса, поддерживающем эту комбинацию; эталонные аудиофайлы будут привязаны на этапе подготовки к ресурсной среде, необходимой для этого голоса.
- lyric_prompt: когда `custom=true` и `lyric` не предоставлен, используется для автоматической генерации текста песни.

> Примечание: эталонные аудиофайлы должны быть общедоступными аудиофайлами. Если эталонный аудиофайл полностью совпадает с известной записью из музыкальной библиотеки платформы, Suno может отклонить генерацию из-за проверки авторских прав; рекомендуется использовать собственное аудио или аудио, сгенерированное Suno, в качестве источника вдохновения.

Соответствующий код Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Асинхронный обратный вызов

Поскольку Suno относительно долго генерирует музыку, примерно 1–2 минуты, если API долго не отвечает, HTTP-запрос будет постоянно удерживать соединение, что приведёт к дополнительному потреблению системных ресурсов, поэтому данный API также предоставляет поддержку асинхронных обратных вызовов.

Общий процесс таков: когда клиент инициирует запрос, он дополнительно указывает поле `callback_url`; после того как клиент инициирует API-запрос, API немедленно возвращает результат, содержащий информацию в поле `task_id`, представляющем ID текущей задачи. После завершения задачи результат генерации музыки будет отправлен в виде POST JSON на указанный клиентом `callback_url`, где также включено поле `task_id`, таким образом результаты задачи можно связать по ID.

Ниже мы на примере рассмотрим, как именно это сделать.

Прежде всего, Webhook-обратный вызов — это сервис, способный принимать HTTP-запросы; разработчик должен заменить его URL-адресом собственного HTTP-сервера. Для удобства демонстрации здесь используется публичный пример сайта Webhook https://webhook.site/; открыв этот сайт, можно получить Webhook URL, как показано на изображении:
