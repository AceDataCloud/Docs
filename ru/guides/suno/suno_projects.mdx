`POST https://api.acedata.cloud/suno/projects` — это Beta-интерфейс для управления многодорожечными проектами. Создание, сохранение, генерация кандидатов, отправка кандидатов и экспорт различаются через `action`.

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: <每次写操作的新 UUID>
```

Кроме `retrieve`, **каждая операция требует** `Idempotency-Key`. Одинаковый ключ и одинаковый запрос возвращают только исходный результат; одинаковый ключ с разными запросами возвращает 409. При сетевом тайм-ауте платной генерации или неопределённости результата отправки сначала выполните запрос с исходным ID задачи или тем же ключом идемпотентности, нельзя напрямую повторно отправлять с другим ключом.

## Идентификаторы и единицы времени

| Название                             | Откуда получить                                                                                      | Где использовать                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | `data.id` ответа `create`                                                                      | Все последующие запросы для текущего проекта                                      |
| `version_id`                   | `data.version_id` из последнего `retrieve`, `save`, `add_track`, `commit_candidate` или `remove_track` | Изменение, генерация кандидатов и экспорт; необходимо использовать последнюю версию                              |
| `audio_id` / `source_audio_id` | `response.data.candidate.audio_id` в конечном состоянии `upload` или ID уже завершённого аудио                                | Ссылка на исходное аудио при `add_track`, генерации или замене                          |
| `render_audio_id`              | `response.data.audio_id` в конечном состоянии `render`                                                       | Ссылка на микс проекта для `generate_track`                         |
| `operation_id`                 | `response.data.operation_id` в конечном состоянии `generate_track` или `replace_section`                       | `commit_candidate`; обычно совпадает с `task_id` задачи генерации, но следует читать возвращаемое значение |
| `candidate_id`                 | `response.data.candidates[].id` в конечном состоянии генерации                                                       | Выбор кандидата для отправки                                         |
| `track_id`                     | `data.state.tracks[].id` проекта                                                                | Отправка кандидата или удаление дорожки                                        |
| `task_id`                      | Ответ на отправку асинхронной операции                                                                                   | Используйте `/suno/tasks` для запроса конечного состояния; это не ID проекта                   |

`start_seconds` / `end_seconds` — это **секунды внутри исходного аудио**; `start_beats` / `end_beats` — это **количество долей на временной шкале проекта**. `state.timing.bps` — это количество долей в секунду, по умолчанию 2. Например, для фрагмента длиной 41 секунду, начинающегося с доли 0, конечная точка по умолчанию — доля 82. Интервал в секундах для `generate_track` используется для указания ссылки генерации и не гарантирует, что кандидат будет иметь длину только этого интервала.

## Процесс операций

| Порядок  | `action`                             | Назначение                         | Способ возврата         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | Создание пустого проекта                      | Синхронные данные проекта       |
| 2   | `retrieve`                           | Чтение последней версии и полного `state`          | Синхронные данные проекта       |
| 3   | `save`                               | Первое сохранение или полное сохранение изменённого `state`      | Синхронные данные проекта       |
| 4   | `upload`                             | Создание материала из HTTPS-адреса аудио           | Асинхронная задача         |
| 5   | `add_track`                          | Добавление аудиоматериала в проект                  | Асинхронная задача, обновление версии    |
| 6   | `save`                               | Если нужно получать кандидатов для новой дорожки, сначала сохраните пустую целевую дорожку        | Синхронные данные проекта, обновление версии  |
| 7   | `render`                             | Экспорт текущих прослушиваемых дорожек, получение ссылки на микс `audio_id` | Асинхронная задача         |
| 8   | `generate_track` или `replace_section` | Генерация кандидатов новой дорожки или кандидатов локальной замены соответственно            | Асинхронная задача, проект пока не изменяется  |
| 9   | `commit_candidate`                   | Выбор и отправка кандидата                  | Асинхронная задача, версия обновляется после успеха |
| Необязательно  | `remove_track`                       | Удаление указанной дорожки                     | Синхронные данные проекта, обновление версии  |

Если выполняется только локальная замена, достаточно существующего доступного исходного аудио, предварительный `render` не требуется; если исходное аудио уже находится в проекте, также можно пропустить `upload` и `add_track`. `render_audio_id` является обязательной ссылкой только для `generate_track`.

При отправке асинхронной операции сначала возвращается `{ "task_id": "...", "trace_id": "..." }`, что **не означает успешную генерацию**. Опрос:

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步返回的 task_id"}
```

Задача считается успешной только если запись задачи имеет `finished_at` и её `response.success` имеет значение `true`; при `response.success=false` читайте `response.error`. Хотя `save` может содержать `task_id`, в этом интерфейсе оно завершается синхронно. `upload`, `render`, `generate_track`, `replace_section` не изменяют версию проекта; после успеха `save`, `add_track`, `commit_candidate`, `remove_track` следует получить новый `version_id`.

## Соглашения о запросах

| Параметр                | Тип и область применения                                                                                   | Описание                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | Обязательная строка                                                                                     | Фиксировано как одно из имён операций, перечисленных на этой странице; один запрос выполняет только одну операцию.                                      |
| `id`              | Обязательная строка, кроме `create`                                                                         | ID проекта, получаемый из `create.data.id`.                                      |
| `version_id`      | Обязательная строка при изменении, генерации кандидатов и экспорте; может быть опущена при первом `save` пустого проекта                                                         | Используйте последнюю версию, старая версия будет отклонена. `retrieve` не требует её.                                 |
| `Idempotency-Key` | Обязательный заголовок запроса, кроме `retrieve`, 1–128 символов                                                              | Используйте новый ключ для каждой новой операции; одинаковый ключ и одинаковый запрос возвращают исходный результат без повторной генерации или списания средств.                                   |
| `async`           | Необязательное логическое значение для `upload`, `add_track`, `generate_track`, `replace_section`, `commit_candidate`, `render` | Эти операции всегда асинхронны; `false` также не сделает генерацию синхронной.                                    |
| `callback_url`    | Необязательный URL для асинхронных операций                                                                                | Получение уведомления о конечном состоянии; если опущен, запрашивайте `/suno/tasks` по `task_id`. Всё равно необходимо проверять `response.success`. |

Следующие примеры последовательно демонстрируют передачу ID и версий между операциями. В ответах перечислены только поля, относящиеся к текущему шагу; при интеграции замените примерные ID значениями ответов текущего приложения.

## Сохранение состояния проекта

| Параметр | Тип и описание |
|---|---|
| `state` | Обязательный объект. Отправьте **полное состояние проекта**, а не частичный патч; используйте `data.state`, возвращённый последней операцией чтения или изменения, в качестве основы и сохраняйте неизвестные поля. |
| `title` | Необязательная строка; при пропуске используется `state.title`, а если его также нет — заголовок по умолчанию. |
| `version_id` | Может быть пропущен при первом сохранении нового пустого проекта; после этого необходимо использовать последнюю версию. |

`state.timing.bps` должен быть положительным числом, значение по умолчанию — 2. `state.tracks` — это массив дорожек; `clipId` существующих аудиоклипов ссылается на аудио-ID, а `startBeats`, `endBeats`, `readStartBeats` используют единицы ударов проекта. Самый безопасный способ редактирования — прочитать полное `state`, изменить только целевую дорожку или клип, а затем выполнить общий `save`. Новая пустая целевая дорожка должна как минимум иметь уникальный `id`, `type:"audio"`, `clips:[]`; полную структуру пустой дорожки смотрите в примере в разделе «Генерация новой аудиодорожки». Не используйте точки ударов из результатов анализа аудио напрямую в качестве координат временной шкалы проекта.

## Загрузка аудио и добавление дорожки

| Операция | Параметр | Тип и описание |
|---|---|---|
| `upload` | `audio_url` | Обязательный HTTPS URL, указывающий на общедоступное аудио, на использование которого у вас есть права. `candidate.audio_id` в конечном состоянии может использоваться для добавления дорожки. |
| `add_track` | `audio_id` | Обязательная строка; аудио-ID завершённого материала, а не URL. |
| `add_track` | `name`、`color` | Необязательные строки; имя дорожки по умолчанию берётся из заголовка аудио, рекомендуемый цвет — `#RRGGBB`, по умолчанию `#7251F7`. |
| `add_track` | `title` | Необязательная строка; также изменяет заголовок проекта, обычно пропускается. |
| `add_track` | `start_beats`、`end_beats` | Необязательные неотрицательные числа, конечная точка должна быть больше начальной; по умолчанию начинается с удара 0, конечная точка рассчитывается по длительности аудио и `timing.bps`. |
| `add_track` | `gain` | Необязательное неотрицательное число, по умолчанию 1; коэффициент громкости клипа и дорожки. |

## Генерация новой аудиодорожки

Кандидаты и версия проекта во время генерации связаны. Сначала сохраните пустую дорожку, принимающую кандидатов, затем экспортируйте текущий микс в качестве эталона для генерации; после завершения генерации выберите кандидата и отправьте его на эту пустую дорожку.

### Резервирование целевой дорожки: `save`

Кандидаты `generate_track` связаны с текущей версией проекта. Добавьте следующую пустую дорожку в `state.tracks` на основе **полного** `state`, возвращённого в конечном состоянии предыдущего `add_track`, затем сохраните с помощью `save`; все остальные существующие поля сохраните без изменений:
```
&#123;
"id": "bdec15b5-ce96-43fa-b681-26298e013b06",
"type": "audio",
"name": "Сгенерированное пианино",
"clips": [],
"takeLanes": [],
"mute": false,
"solo": false,
"amplitude": 1,
"instrument": &#123;
"type": "song"
&#125;,
"color": "#7251F7"
&#125;

```
Сохранение ответа：
```

&#123;
"success": true,

| Параметр | Тип и описание |
|---|---|
| `title` | Обязательная строка; заголовок экспортируемого аудио. |
| `lyrics`、`tags` | Необязательные строки; текст по умолчанию — `[Instrumental]`, `tags` — описание стиля. |
| `start_beats`、`end_beats` | Необязательные неотрицательные числа, конечная точка должна быть больше начальной; при пропуске охватываются все слышимые фрагменты. Беззвучные фрагменты не участвуют; при наличии solo-дорожек выбираются только solo-дорожки. |

### Генерация кандидатов：`generate_track`

| Параметр | Тип и описание |
|---|---|
| `source_audio_id` | Обязательный; ID завершённого исходного аудио. Сначала добавьте исходное аудио в проект, только после этого можно определить позиции кандидатов. |

## Ошибки и восстановление

| Результат | Значение | Следующий шаг |
|---|---|---|
| `project_version_conflict` / `project_candidate_stale`（409） | Версия проекта изменилась, или кандидат не принадлежит текущей версии. | Выполните `retrieve` последней версии проекта и заново спланируйте изменения; не воспроизводите старые кандидаты. |
| `bad_request` / `studio_state_invalid` / `studio_model_unsupported`（обычно 400） | Параметры, состояние дорожки, длительность кандидата или модель не соответствуют операции. | Просмотрите ошибку конечного состояния задачи, исправьте ввод; если кандидат невозможно безопасно соединить, сохраните исходный проект. |
| `studio_audio_unavailable` / `studio_access_denied` / `content_rejected`（403） | Эталонное аудио недоступно для операции проекта, доступ отсутствует или проверка контента отклонена. | Проверьте источник аудио и `trace_id` задачи; не приравнивайте уже сгенерированного кандидата к возможности экспортировать всю композицию. |
| `too_many_requests`（429） | Запрос ограничен по частоте. | Сначала запросите исходную задачу, затем решите, следует ли инициировать новую операцию с новым ключом идемпотентности. |
| `studio_unavailable` / `studio_model_unavailable`（503） | Обработка проекта или выбранная модель временно недоступны. | Сохраните результат исходной задачи; позже выполните явный повтор, не переключая модель автоматически. |
