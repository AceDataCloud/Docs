В этой статье будет представлена инструкция по интеграции Kling Videos Generation API, с помощью которого можно генерировать официальные видео Kling, вводя пользовательские параметры.

## Процесс подачи заявки

Чтобы использовать Kling Videos Generation API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти, после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, не нужно подавать отдельную заявку для каждого сервиса.** При первой заявке предоставляется бесплатная квота, которой можно воспользоваться для бесплатного тестирования; при недостатке квоты можно пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Базовое использование

Сначала разберёмся с базовым способом использования: необходимо ввести промпт `prompt`, действие генерации `action`, референсное изображение первого кадра `start_image_url` и модель `model`, после чего можно получить обработанный результат; сначала необходимо просто передать поле `action` со значением `text2video`, оно в основном включает три действия: генерация видео из текста (`text2video`), генерация видео из изображения (`image2video`), расширение видео (`extend`), затем также необходимо ввести модель `model`, в настоящее время основными являются модели `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`, конкретное содержание приведено ниже:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Можно увидеть, что здесь мы настроили Request Headers, включая:

- `accept`: какой формат ответа требуется получить, здесь указывается `application/json`, то есть формат JSON.
- `authorization`: ключ для вызова API, после получения заявки можно напрямую выбрать из выпадающего списка.

Также настроили Request Body, включая:

- `model`: модель для генерации видео, основными являются модели `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode`: режим генерации видео, доступны стандартный режим `std`, сверхбыстрый режим `pro` и нативный режим 4K `4k`. Среди них `4k` поддерживается только `kling-v3` и `kling-v3-omni` и несовместим с `camera_control` (управление движением камеры).
- `action`: действие этой задачи генерации видео, в основном включает три действия, а именно: генерация видео из текста (`text2video`), генерация видео из изображения (`image2video`), расширение видео (`extend`).
- `start_image_url`: ссылка на загружаемое референсное изображение первого кадра, обязательная при выборе действия генерации видео из изображения `image2video`.
- `end_image_url`: необязательно при генерации видео из изображения, указывает последний кадр.
- `duration`: длительность видео, в секундах. `kling-v3` и `kling-v3-omni` поддерживают целочисленную длительность от 3 до 15 секунд; `kling-o1` поддерживает только 5 секунд; другие модели поддерживают 5 или 10 секунд.
- `generate_audio`: генерировать ли аудио синхронно, необязательно, булево значение. Поддерживается `kling-v3`, `kling-v3-omni` и `kling-v2-6` (только режим pro). По умолчанию `false`.
- `aspect_ratio`: соотношение сторон видео, необязательно, поддерживаются `16:9`, `9:16`, `1:1`, по умолчанию `16:9`.
- `cfg_scale`: сила соответствия, диапазон [0,1], чем больше значение, тем точнее соответствует промпту.
- `camera_control`: необязательно, объектные параметры для управления движением камеры, поддерживаются пресеты type/simple, а также конфигурации horizontal, vertical, pan, tilt, roll, zoom и другие.
- `negative_prompt`: необязательно, негативный промпт с тем, что не должно появиться, не более 200 символов.
- `image_list`: список референсных изображений Omni, применяется к моделям `kling-o1` и `kling-v3-omni`, использование см. ниже в разделе «Универсальные референсы Omni».
- `video_list`: список референсных видео Omni (поддерживает редактирование видео), применяется к моделям `kling-o1` и `kling-v3-omni`, использование см. ниже в разделе «Универсальные референсы Omni».
- `prompt`: промпт.
- `callback_url`: URL, на который необходимо получить результат обратного вызова.
- `async`: необязательно, при значении `true` интерфейс немедленно возвращает `task_id`, не требуется предоставлять `callback_url`, после чего результат получается через опрос соответствующего интерфейса запроса задач.

После выбора можно обнаружить, что справа также сгенерирован соответствующий код, как показано на изображении:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Нажмите кнопку «Try», чтобы провести тестирование, как показано на изображении выше, здесь мы получили следующий результат:

```json

  "video_id": "900798310464749610",
  "video_url": "https://cdn.acedata.cloud/assets/examples/kling/6c68c267-065b-4423-b66b-a0e4c59ee0d5-6a664a591a53.mp4",
```

Возвращаемый результат содержит несколько полей, описание ниже:

- `success`, статус задачи генерации видео в данный момент.
- `task_id`, ID задачи генерации видео в данный момент.
- `video_id`, ID видео задачи генерации видео в данный момент.
- `video_url`, ссылка на видео задачи генерации видео в данный момент.
- `duration`, длительность видео задачи генерации видео в данный момент.

Можно увидеть, что мы получили удовлетворительную информацию о видео, нам нужно лишь получить сгенерированное видео Kling по адресу ссылки на видео `data` в результате.

Кроме того, если вы хотите сгенерировать соответствующий код интеграции, можно напрямую скопировать сгенерированный код, например код CURL выглядит следующим образом:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Матрица возможностей моделей

### Тарификация O1 и Omni для референсных видео

`kling-o1` тарифицируется в зависимости от режима и наличия `video_list`. Ниже приведены цены за 5-секундный готовый ролик:

| Режим  |         Без референсного видео |         С референсным видео |
| --- | ------------: | ------------: |
| std | 4.005 Credits | 6.010 Credits |
| pro | 5.340 Credits | 8.010 Credits |
Успешные запросы `kling-o1` и `kling-v3-omni` с референсными видео тарифицируются по оплачиваемым секундам: std — **1.202 Credits/секунда**, pro — **1.602 Credits/секунда**. Например, генерация 5 секунд в режиме std стоит 6.010 Credits. Отсутствие `video_list` не активирует тариф референсного видео; `image_list`, изображения первого и последнего кадра также не относятся к референсным видео. Референсное видео нельзя использовать одновременно с `generate_audio=true`.

Видеомонтаж с `refer_type=base` (по умолчанию) может следовать длительности референсного видео, а окончательная оплата рассчитывается по фактической длительности готового ролика, округлённой до целого числа секунд: например, 5.708 секунд считаются как 6 секунд, 5.041 секунд — как 5 секунд. `refer_type=feature` использует запрошенный `duration`. `usage.reference_video_seconds` в ответе указывает окончательное количество оплачиваемых секунд; оценочная цена во время запроса может отличаться от окончательного списания.

Поддержка параметров существенно различается между моделями. Следующая матрица составлена на основе [официальной документации Kling по video models](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels); перед вызовом сначала проверьте, поддерживает ли текущая комбинация `model` / `mode` / `duration` необходимую вам функцию, иначе будут возвращаться ошибки вида `model/mode/duration(...) is not supported with image_tail`.

| Модель              | Режим          | `end_image_url` (первый и последний кадры) | `generate_audio` (аудио) | `camera_control` (движение камеры) | Примечания                                      |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ Только `duration=5` | ❌                    | ✅ Только `duration=5` | `extend` не поддерживает `negative_prompt` и `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | Генерация видео из нескольких изображений, `extend` доступен во всех режимах |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Единственный режим, только `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Единственный режим, только `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | Единственная не-v3 модель, одновременно поддерживающая аудио |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | Диапазон `duration` — 3–15 секунд                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | Режим 4K несовместим с движением камеры                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Поддерживает только `duration=5`                             |

Примечания:

- `mode=4k` поддерживают только `kling-v3` и `kling-v3-omni`; кроме того, он взаимоисключающий с `camera_control` (движением камеры).
- `end_image_url` можно использовать вместе с `start_image_url` только при `action=image2video`. Передача только `end_image_url` (без `start_image_url`) будет отклонена.
- `kling-v3` / `kling-v3-omni` принимают любой целочисленный `duration` от 3 до 15 секунд; `kling-o1` принимает только 5; остальные модели принимают только 5 или 10.
- `generate_audio` по умолчанию имеет значение `false`. Поддерживается только `kling-v3`, `kling-v3-omni` и `kling-v2-6` (режим pro).

## Функция расширения видео

Если вы хотите продолжить генерацию уже созданного видео Kling, можно установить параметр `action` в значение `extend` и ввести ID видео, которое необходимо продолжить генерировать. ID видео получается согласно базовому использованию, как показано на рисунке ниже:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

В этот момент можно увидеть, что ID видео:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Обратите внимание, что `video_id` в данном видео — это ID видео после генерации. Если вы не знаете, как генерировать видео, можете обратиться к базовому использованию выше для генерации видео.

Далее нам необходимо заполнить подсказку, которую нужно расширить на следующем шаге, чтобы настроить генерацию видео, и можно указать следующее содержимое:

- `model`: модель для генерации видео, основными являются модели `kling-v1`, `kling-v1-5` и `kling-v1-6`.
- `mode`: режим генерации видео; доступные значения: стандартный режим `std`, скоростной режим `pro` и нативный режим 4K `4k` (поддерживается только `kling-v3` и `kling-v3-omni`, несовместим с управлением движением камеры).
- `duration`: длительность видео для этой задачи генерации видео, в основном включает 5 с и 10 с.
- `start_image_url`: при выборе поведения генерации видео из изображения `image2video` необходимо загрузить ссылку на референсное изображение первого кадра.
- `prompt`: подсказка.

Пример заполнения приведён ниже:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

После заполнения автоматически генерируется следующий код:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Соответствующий код Python:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Нажмите «Запустить», и можно увидеть, что будет получен следующий результат:

```json
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
```

Можно видеть, что содержимое результата совпадает с приведённым выше, таким образом реализуется функция расширения видео.

## Omni универсальная ссылка (редактирование видео / референсное видео / ссылка на несколько изображений)

`kling-o1` и `kling-v3-omni` — это две независимые модели, обе поддерживают возможность «универсальной ссылки». На основе генерации видео из текста (`action=text2video`) можно дополнительно передавать референсные изображения или референсные видео, реализуя **ссылку на несколько изображений, референсное видео, а также прямое редактирование существующего видео**.

**Основное соглашение**: референсные материалы должны быть указаны в `prompt` в форме `&lt;&lt;<image_1>>>`, `&lt;&lt;<video_1>>>` (нумерация начинается с 1), чтобы ссылаться на материалы в соответствующих позициях в `image_list` / `video_list`; только тогда модель применит эти референсы. Если передать только материалы, но не сослаться на них в подсказке, материалы будут проигнорированы.

> Примечание по безопасности: текущий API не предоставляет `element_list`. ID Kling Element Library не изолированы по арендаторам, поэтому до предоставления Element Management API с изоляцией арендаторов используйте `image_list` для передачи референсных изображений субъектов.

Omni-запросы не поддерживают `negative_prompt`, `cfg_scale` или `camera_control`, также нельзя использовать `mode=4k`. При наличии референсного видео `generate_audio` должен быть установлен в `false`.

### Референсное видео и редактирование видео (`video_list`)

`video_list` используется для передачи референсных видео и является наиболее распространённым сценарием этой возможности, поля элементов массива следующие:

- `video_url`: ссылка на референсное видео, не может быть пустой. Максимум 1 видео MP4/MOV, размер файла ≤200MB, частота кадров 24–60fps. `kling-o1` требует длительность 3–10 секунд, ширину и высоту по 700–2160px; `kling-v3-omni` требует длительность 3–15,5 секунд, ширину и высоту по 700–4553px, общее число пикселей ≤8 294 400, соотношение сторон 0,4–2.
- `refer_type`: тип референса, доступны `base` (по умолчанию, **базовое видео для редактирования**, то есть «прямое редактирование видео», позволяет добавлять/удалять/изменять элементы, менять композицию, стиль, цвет, погоду и т. д.) или `feature` (**референс характеристик**, заимствует его стиль / движение камеры / продолжает съёмку следующего кадра).
- `keep_original_sound`: сохранять ли оригинальное аудио видео, доступны `yes` (сохранить) или `no` (удалить).

> Примечание: при наличии референсного видео `generate_audio` должен быть `false`. Для видео с `refer_type=base` нельзя дополнительно указывать первый / последний кадр.

Ниже приведён пример CURL для редактирования существующего видео (изменение видео в аниме-стиль):

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Ссылка на несколько изображений (`image_list`)

`image_list` используется для передачи референсных изображений (элементов / сцен / стилей и т. д.), поля элементов массива следующие:

- `image_url`: ссылка на референсное изображение, не может быть пустой. Требования: формат .jpg/.jpeg/.png; размер файла ≤10MB; минимальная сторона ≥300px; соотношение сторон от 1:2,5 до 2,5:1.
- `type`: необязательно. Если не передаётся, используется как обычное референсное изображение; при передаче `first_frame` / `end_frame` используется соответственно как первый / последний кадр (эквивалентно `start_image_url` / `end_image_url`).

При использовании необходимо ссылаться в `prompt` как `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Ограничение количества: при отсутствии референсного видео референсных изображений ≤ 7; при наличии референсного видео референсных изображений ≤ 4. При передаче только первого / последнего кадра также можно напрямую использовать `start_image_url` / `end_image_url`, но последний кадр необходимо использовать вместе с первым кадром.

> Примечание: если одновременно передавать `start_image_url` / `end_image_url` и `image_list`, первый / последний кадры будут расположены перед `image_list`, что может повлиять на соответствие нумерации `&lt;&lt;<image_N>>>`. Рекомендуется выбрать один из двух способов: если требуются первый / последний кадры, указывайте `type` непосредственно в `image_list`, не смешивайте с `start_image_url` / `end_image_url`.

Пример CURL для генерации видео по нескольким референсным изображениям:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Асинхронный обратный вызов

Поскольку время генерации Kling Videos Generation API относительно длительное, примерно 1–2 минуты, если API долго не отвечает, HTTP-запрос будет постоянно сохранять соединение, что приведёт к дополнительному потреблению системных ресурсов, поэтому данный API также предоставляет поддержку асинхронных обратных вызовов.

Общий процесс таков: когда клиент инициирует запрос, он дополнительно указывает поле `callback_url`; после того как клиент инициирует API-запрос, API немедленно возвращает результат, содержащий поле `task_id`, представляющее ID текущей задачи. После завершения задачи результат генерации видео будет отправлен в форме POST JSON на указанный клиентом `callback_url`, где также содержится поле `task_id`, таким образом результаты задачи могут быть связаны по ID.

Ниже мы на примере разберёмся, как именно это выполнить.

Прежде всего, Webhook-обратный вызов — это сервис, который может принимать HTTP-запросы; разработчику следует заменить его на URL самостоятельно развёрнутого HTTP-сервера. Здесь для удобства демонстрации используется публичный сайт-пример Webhook https://webhook.site/; откройте этот сайт, чтобы получить Webhook URL, как показано на рисунке:

![](https://cdn.acedata.cloud/tbcnai.png)

Скопируйте этот URL, и его можно использовать в качестве Webhook; пример здесь: `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Далее мы можем установить для поля `callback_url` указанный выше Webhook URL и одновременно заполнить соответствующие параметры; конкретное содержимое показано на рисунке:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Нажмите «Выполнить», и можно увидеть, что немедленно будет получен результат, как показано ниже:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```
Подождите немного, мы можем наблюдать результат сгенерированного видео на `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, как показано на рисунке:

![](https://cdn.acedata.cloud/zv5u2q.png)

Содержимое следующее:

```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Можно увидеть, что в результате есть поле `task_id`, остальные поля аналогичны приведённым выше; через это поле можно реализовать связь задач.

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Неверный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `400 api_not_implemented`：Неверный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `401 invalid_token`：Не авторизовано, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили ограничение частоты.
- `500 api_error`：Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## Заключение

С помощью этого документа вы уже узнали, как использовать Kling Videos Generation API для генерации видео посредством входного текста-подсказки и эталонного изображения первого кадра. Надеемся, этот документ поможет вам лучше интегрировать и использовать данный API. Если у вас возникнут какие-либо вопросы, пожалуйста, свяжитесь с нашей командой технической поддержки в любое время.

### Kling 3.0 Turbo

`model="kling-v3-turbo"` поддерживает генерацию видео из текста и генерацию видео из изображения первого кадра, с длительностью в целых секундах от 3 до 15. `mode="std"` выводит 720p, `mode="pro"` выводит 1080p. Эта модель имеет встроенное нативное аудио и не предоставляет переключатель для его отключения; опустите `generate_audio` или установите его в `true`. Эта модель не поддерживает последний кадр, объекты движения камеры, отдельные негативные подсказки или `cfg_scale`. Пожалуйста, непосредственно опишите в `prompt` содержимое, которое необходимо или которого следует избегать.

### Многокадровое видео

`kling-v3` и `kling-v3-omni` поддерживают `multi_shot=true`. `shot_type="intelligence"` автоматически разбивает на сцены на основе `prompt`; `shot_type="customize"` предоставляет 1–6 сцен через `multi_prompt`, каждый элемент содержит непрерывно возрастающий с 1 `index`, `prompt` длиной не более 512 символов и целочисленную `duration` не менее 1 секунды. Сумма длительностей всех сцен должна быть равна общей `duration`. Пользовательские сцены не используют глобальный `prompt`. За многокадровые видео взимается плата в соответствии с выбранной моделью, качеством изображения, конфигурацией аудио и общей длительностью.
