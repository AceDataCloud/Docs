В этой статье будет представлена инструкция по интеграции Kling Videos Generation API, с помощью которого можно генерировать официальные видео Kling, вводя пользовательские параметры.

## Процесс подачи заявки

Чтобы использовать Kling Videos Generation API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа с предложением зарегистрироваться и войти в систему; после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первой заявке предоставляется бесплатный лимит, позволяющий бесплатно опробовать сервис; при недостаточном лимите можно пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Базовое использование

Сначала ознакомимся с базовым способом использования: введя промпт `prompt`, действие генерации `action`, эталонное изображение первого кадра `start_image_url` и модель `model`, можно получить обработанный результат. Сначала необходимо просто передать поле `action` со значением `text2video`; оно в основном включает три действия: генерация видео из текста (`text2video`), генерация видео из изображения (`image2video`) и расширение видео (`extend`). Затем также необходимо указать модель `model`; в настоящее время доступны модели `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`, подробности приведены ниже:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Можно увидеть, что здесь мы настроили Request Headers, включая:

- `accept`: какой формат ответа вы хотите получить; здесь указывается `application/json`, то есть формат JSON.
- `authorization`: ключ для вызова API, после получения заявки его можно напрямую выбрать из выпадающего списка.

Также был настроен Request Body, включая:

- `model`: модель для генерации видео; основные модели: `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode`: режим генерации видео; допустимые значения: стандартный режим `std`, сверхбыстрый режим `pro` и нативный режим 4K `4k`. Среди них `4k` поддерживается только `kling-v3` и `kling-v3-omni` и несовместим с `camera_control` (управление движением камеры).
- `action`: действие этой задачи генерации видео; оно в основном включает три действия: генерация видео из текста (`text2video`), генерация видео из изображения (`image2video`) и расширение видео (`extend`).
- `start_image_url`: ссылка на эталонное изображение первого кадра, которое необходимо загрузить при выборе действия генерации видео из изображения `image2video`.
- `end_image_url`: необязательно при генерации видео из изображения, задаёт последний кадр.
- `duration`: длительность видео в секундах. `kling-v3` и `kling-v3-omni` поддерживают целую длительность от 3 до 15 секунд; `kling-o1` поддерживает только 5 секунд; другие модели поддерживают 5 или 10 секунд.
- `generate_audio`: создавать ли аудио одновременно; необязательно, логическое значение. Поддерживается `kling-v3`, `kling-v3-omni` и `kling-v2-6` (только режим pro). По умолчанию `false`.
- `aspect_ratio`: соотношение сторон видео; необязательно, поддерживаются `16:9`, `9:16`, `1:1`, по умолчанию `16:9`.
- `cfg_scale`: сила релевантности, диапазон [0,1]; чем больше, тем точнее соответствует промпту.
- `camera_control`: необязательно, параметр объекта для управления движением камеры, поддерживает предустановки type/simple, а также настройки horizontal, vertical, pan, tilt, roll, zoom и другие.
- `negative_prompt`: необязательно, негативный промпт с тем, что не должно появляться, максимум 200 символов.
- `image_list`: список эталонных изображений Omni, применяется к моделям `kling-o1` и `kling-v3-omni`; использование см. ниже в разделе «Универсальные эталоны Omni».
- `video_list`: список эталонных видео Omni (поддерживает редактирование видео), применяется к моделям `kling-o1` и `kling-v3-omni`; использование см. ниже в разделе «Универсальные эталоны Omni».
- `prompt`: промпт.
- `callback_url`: URL, на который необходимо получить результат обратного вызова.
- `async`: необязательно; при установке в `true` интерфейс немедленно возвращает `task_id`, без необходимости предоставлять `callback_url`, после чего результат получается путём опроса соответствующего интерфейса запроса задач.

После выбора можно заметить, что справа также генерируется соответствующий код, как показано на рисунке:

Нажмите кнопку «Try», чтобы выполнить тестирование; как показано на рисунке выше, здесь мы получили следующий результат:


Возвращаемый результат содержит несколько полей, описание которых приведено ниже:

- `task_id`: ID задачи генерации видео в данный момент.
- `video_id`: ID видео задачи генерации видео в данный момент.
- `video_url`: ссылка на видео задачи генерации видео в данный момент.
- `duration`: длительность видео задачи генерации видео в данный момент.
- `state`: состояние задачи генерации видео в данный момент.

Можно увидеть, что мы получили удовлетворительную информацию о видео; нам нужно лишь получить сгенерированное видео Kling по адресу ссылки на видео в `data` результата.

Кроме того, если вы хотите сгенерировать соответствующий код интеграции, вы можете напрямую скопировать его, например, код CURL выглядит следующим образом:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Матрица возможностей моделей

Поддержка параметров существенно различается между разными моделями. Следующая матрица составлена на основе [официальной документации Kling по video models](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels); перед вызовом сначала проверьте, поддерживает ли текущая комбинация `model` / `mode` / `duration` нужные вам функции, иначе будут возвращаться ошибки, такие как `model/mode/duration(...) is not supported with image_tail`.
| Модель                  | Режим          | `end_image_url`（первый и последний кадры） | `generate_audio`（аудиосопровождение） | `camera_control`（движение камеры） | Примечания                                           |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ Только `duration=5` | ❌                    | ✅ Только `duration=5` | `extend` не поддерживает `negative_prompt` и `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | Генерация видео по нескольким изображениям, `extend` доступен во всех режимах                         |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Единый режим, только `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Единый режим, только `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | Единственная не-v3 модель, одновременно поддерживающая аудиосопровождение                             |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | Диапазон `duration` 3–15 секунд                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | Режим 4K несовместим с движением камеры                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Поддерживает только `duration=5`                             |

Примечания:

- `mode=4k` поддерживается только `kling-v3` и `kling-v3-omni`; также он взаимоисключается с `camera_control`（движением камеры）.
- `end_image_url` можно использовать только вместе с `start_image_url` при `action=image2video`. Передача только `end_image_url`（без `start_image_url`）будет отклонена.
- `kling-v3` / `kling-v3-omni` принимают любое целое значение `duration` от 3 до 15 секунд; `kling-o1` принимает только 5; остальные модели принимают только 5 или 10.
- Значение `generate_audio` по умолчанию — `false`. Поддерживается только `kling-v3`、`kling-v3-omni` и `kling-v2-6`（режим pro）.

## Функция расширения видео

Если вы хотите продолжить генерацию уже созданного видео Kling, можно установить параметр `action` в значение `extend` и ввести ID видео, которое необходимо продолжить генерировать. Получение ID видео выполняется на основе базового использования, как показано на изображении ниже:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

В этот момент можно увидеть, что ID видео:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Обратите внимание, что `video_id` в этом видео — это ID сгенерированного видео. Если вы не знаете, как сгенерировать видео, можете обратиться к базовому использованию выше для генерации видео.

Далее необходимо заполнить подсказку, которую нужно расширить на следующем шаге, чтобы настроить генерацию видео, и можно указать следующее содержимое:

- `model`：модель для генерации видео, в основном доступны модели `kling-v1`、`kling-v1-5` и `kling-v1-6`.
- `mode`：режим генерации видео, доступные значения: стандартный режим `std`、высокоскоростной режим `pro` и нативный режим 4K `4k`（поддерживается только `kling-v3` и `kling-v3-omni`, несовместим с управлением движением камеры）.
- `duration`：длительность видео для этой задачи генерации, в основном включает 5 с и 10 с.
- `start_image_url`：при выборе поведения генерации видео по изображению `image2video` необходимо загрузить ссылку на эталонное изображение первого кадра.
- `prompt`：текст подсказки.

Пример заполнения:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

После заполнения автоматически генерируется следующий код:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Соответствующий код Python:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Нажав «Запустить», можно увидеть, что будет получен следующий результат:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```

Можно увидеть, что содержимое результата совпадает с указанным выше, тем самым реализуется функция расширения видео.

## Универсальные ссылки Omni（редактирование видео / эталонное видео / ссылки на несколько изображений）

`kling-o1` и `kling-v3-omni` — две независимые модели, обе поддерживают возможности «универсальных ссылок». На основе генерации видео по тексту（`action=text2video`）можно дополнительно передавать эталонные изображения или эталонные видео, реализуя **ссылки на несколько изображений, эталонные видео, а также прямое редактирование существующих видео**.

**Основное соглашение**：эталонные материалы должны быть указаны в `prompt` в форме `&lt;&lt;<image_1>>>`、`&lt;&lt;<video_1>>>`（нумерация начинается с 1）для ссылки на материалы в соответствующей позиции в `image_list` / `video_list`, только тогда модель применит эти ссылки. Если передать только материалы, но не ссылаться на них в подсказке, материалы будут проигнорированы.

> Примечание по безопасности: текущий API не предоставляет `element_list`. ID Kling Element Library не изолированы между арендаторами, поэтому до предоставления API управления элементами с изоляцией арендаторов используйте `image_list` для передачи эталонных изображений объектов.

Omni-запросы не поддерживают `negative_prompt`、`cfg_scale` или `camera_control`, а также не могут использовать `mode=4k`. При наличии эталонного видео `generate_audio` должен быть `false`.

### Эталонное видео и редактирование видео（`video_list`）
`video_list` используется для передачи референсного видео и является наиболее часто используемым сценарием этой возможности, поля элементов массива следующие:

- `video_url`：ссылка на референсное видео, не может быть пустой. Не более 1 видео MP4/MOV, размер файла ≤200MB, частота кадров 24–60fps. Для `kling-o1` требуется длительность 3–10 секунд, ширина и высота по 700–2160px каждая; для `kling-v3-omni` требуется длительность 3–15.5 секунд, ширина и высота по 700–4553px каждая, общее количество пикселей ≤8,294,400, соотношение сторон 0.4–2.
- `refer_type`：тип референса, можно выбрать `base` (по умолчанию, **базовое видео для редактирования**, то есть «редактирование видео напрямую», можно добавлять/удалять/изменять элементы, менять композицию, стиль, цвета, погоду и т. д.) или `feature` (**референс характеристик**, используется его стиль / движение камеры / продолжение съёмки следующего кадра).
- `keep_original_sound`：сохранять ли оригинальное аудио видео, можно выбрать `yes` (сохранить) или `no` (удалить).

> Примечание: при наличии референсного видео `generate_audio` должен быть `false`. Для видео с `refer_type=base` нельзя дополнительно указывать первый кадр / последний кадр.

Пример CURL для редактирования существующего видео (изменение видео в стиль аниме):

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Референс по нескольким изображениям（`image_list`）

`image_list` используется для передачи референсных изображений (элементы / сцены / стили и т. д.), поля элементов массива следующие:

- `image_url`：ссылка на референсное изображение, не может быть пустой. Требования: формат .jpg/.jpeg/.png; размер файла ≤10MB; кратчайшая сторона ≥300px; соотношение сторон 1:2.5 ~ 2.5:1.
- `type`：необязательно. Если не передаётся, используется как чистое референсное изображение; при передаче `first_frame` / `end_frame` используется соответственно как первый кадр / последний кадр (эквивалентно `start_image_url` / `end_image_url`).

При использовании необходимо ссылаться в `prompt` как `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Ограничение по количеству: при отсутствии референсного видео референсных изображений ≤ 7; при наличии референсного видео референсных изображений ≤ 4. При передаче только первого / последнего кадра также можно напрямую использовать `start_image_url` / `end_image_url`, но последний кадр должен использоваться вместе с первым кадром.

> Примечание: если одновременно передаются `start_image_url` / `end_image_url` и `image_list`, первый / последний кадр будут расположены перед `image_list`, что может повлиять на соответствие порядковых номеров `&lt;&lt;<image_N>>>`. Рекомендуется выбрать один из двух вариантов: если нужны первый / последний кадры, напрямую указывайте `type` в `image_list`, не смешивайте с `start_image_url` / `end_image_url`.

Пример CURL генерации видео с референсом по нескольким изображениям:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
```

## Асинхронный обратный вызов

Поскольку время генерации Kling Videos Generation API относительно долгое, примерно 1–2 минуты, если API долго не отвечает, HTTP-запрос будет постоянно поддерживать соединение, что приведёт к дополнительному потреблению системных ресурсов, поэтому данный API также предоставляет поддержку асинхронных обратных вызовов.

Общий процесс таков: когда клиент инициирует запрос, он дополнительно указывает поле `callback_url`; после того как клиент инициирует API-запрос, API немедленно вернёт результат, содержащий информацию в поле `task_id`, представляющем ID текущей задачи. После завершения задачи результат сгенерированного видео будет отправлен в форме POST JSON на указанный клиентом `callback_url`, в нём также содержится поле `task_id`, таким образом результаты задачи можно связать по ID.

Ниже мы на примере рассмотрим, как именно это делать.

Сначала, обратный вызов Webhook — это сервис, способный принимать HTTP-запросы, разработчик должен заменить его на URL собственного HTTP-сервера. Здесь для удобства демонстрации используется публичный сайт-пример Webhook https://webhook.site/; при открытии этого сайта можно получить Webhook URL, как показано на рисунке:

![](https://cdn.acedata.cloud/tbcnai.png)

Скопируйте этот URL, и его можно использовать как Webhook; пример здесь — `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Далее мы можем установить для поля `callback_url` указанный выше Webhook URL и одновременно заполнить соответствующие параметры, конкретное содержимое показано на рисунке:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Нажмите запуск, и можно увидеть, что немедленно будет получен результат:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Немного подождав, мы можем наблюдать результат сгенерированного видео на `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, как показано на рисунке:

![](https://cdn.acedata.cloud/zv5u2q.png)

Содержимое следующее:

```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Можно увидеть, что в результате есть поле `task_id`, остальные поля аналогичны описанным выше; через это поле можно реализовать связь задач.

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Неверный запрос, возможно из-за отсутствующих или недопустимых параметров.
- `400 api_not_implemented`：Неверный запрос, возможно из-за отсутствующих или недопустимых параметров.
- `401 invalid_token`：Не авторизован, недопустимый или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили лимит частоты.
- `500 api_error`：Внутренняя ошибка сервера, что-то пошло не так на сервере.
### Пример ответа с ошибкой

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
