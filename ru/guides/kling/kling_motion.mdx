В этой статье будет представлена инструкция по интеграции Kling Motion Generation API, который позволяет генерировать официальные видео Kling посредством ввода пользовательских параметров.

## Процесс получения доступа

Чтобы использовать Kling Motion Generation API, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications), чтобы получить ваш API Token, и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти, после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первом получении предоставляется бесплатный лимит, который можно использовать для бесплатного ознакомления; при недостатке лимита вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Kling Motion Generation API →](https://platform.acedata.cloud/documents/kling-motion)

## Базовое использование

Сначала ознакомимся с базовым способом использования: достаточно ввести текст запроса `prompt`, референсное изображение `image_url` и ссылку на референсное видео `video_url`, чтобы получить обработанный результат, затем нам также необходимо ввести модель `mode`, в настоящее время доступны главным образом модели `std`, `pro`, конкретное содержание приведено ниже:

<p><img src="https://cdn.acedata.cloud/5qlpjt.png" width="500" className="m-auto" /></p>

Можно увидеть, что здесь мы установили Request Headers, включая:

- `accept`: формат результата ответа, который требуется получить; здесь указано `application/json`, то есть формат JSON.
- `authorization`: ключ для вызова API, после получения можно напрямую выбрать из выпадающего списка.

Также установлен Request Body, включая:

- `image_url`: URL изображения для референса внешности персонажа. Поддерживаются JPG/JPEG/PNG, файл ≤50MB, ширина и высота обе ≥300px, соотношение сторон 1:2.5～2.5:1; персонаж должен чётко отображать верхнюю часть тела или всё тело и голову.
- `video_url`: URL референсного видео движения. Поддерживаются MP4/MOV, файл ≤100MB, ширина и высота каждая 340–3850px, не менее 3 секунд; при `character_orientation=image` максимальная продолжительность 10 секунд, при `character_orientation=video` — максимальная продолжительность 30 секунд. Рекомендуется использовать непрерывное однокадровое видео, в котором персонаж всегда находится в кадре.
- `mode`: режим генерации видео, главным образом существуют стандартный режим `std` и сверхбыстрый режим `pro`.
- `keep_original_sound`: можно выбрать, сохранять ли оригинальный звук видео, значения перечисления: yes, no.
- `character_orientation`: ориентация персонажа в сгенерированном видео, можно выбрать соответствие изображению или соответствие видео, значения перечисления: image, video.
- `prompt`: текст запроса.
- `callback_url`: URL, на который необходимо отправить результат обратного вызова.
- `async`: необязательно, при установке `true` интерфейс немедленно возвращает `task_id`, без необходимости предоставлять `callback_url`, после чего результат получается посредством опроса соответствующего интерфейса запроса задач.

После выбора можно заметить, что справа также сгенерирован соответствующий код, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/buwczd.png" width="500" className="m-auto" /></p>

Нажмите кнопку «Try», чтобы выполнить тестирование, как показано на рисунке выше, здесь мы получили следующий результат:

```json
{
  "success": true,
  "video_id": "842578800134742051",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "5.066",
  "state": "succeed",
  "task_id": "363c7a84-e880-472e-a4d4-098e50cfc292"
}
```

Результат возврата содержит несколько полей, описание следующее:

- `success`, состояние задачи генерации видео в данный момент.
- `task_id`, ID задачи генерации видео в данный момент.
- `video_id`, ID видео задачи генерации видео в данный момент.
- `video_url`, ссылка на видео задачи генерации видео в данный момент.
- `duration`, длительность видео задачи генерации видео в данный момент.
- `state`, статус задачи генерации видео в данный момент.

Можно увидеть, что мы получили удовлетворительную информацию о видео, нам достаточно получить сгенерированное видео Kling по адресу ссылки на видео в `data` результата.

Кроме того, если вы хотите сгенерировать соответствующий код интеграции, можно напрямую скопировать сгенерированный код, например, код CURL выглядит следующим образом:

```shell
curl -X POST 'https://api.acedata.cloud/kling/motion' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
  "video_url": "https://cdn.acedata.cloud/odwfm5.mp4",
  "prompt": "让画面生动起来",
  "mode": "std",
  "character_orientation": "image"
}'
```

## Асинхронный обратный вызов

Поскольку время генерации Kling Motion Generation API относительно длительное, примерно 1–2 минуты, если API долго не отвечает, HTTP-запрос будет постоянно поддерживать соединение, что приводит к дополнительному потреблению системных ресурсов, поэтому данный API также предоставляет поддержку асинхронного обратного вызова.

Общий процесс следующий: когда клиент инициирует запрос, дополнительно указывается поле `callback_url`, после того как клиент инициирует API-запрос, API немедленно вернёт результат, содержащий информацию поля `task_id`, которое представляет ID текущей задачи. После завершения задачи результат генерации видео будет отправлен в виде POST JSON на указанный клиентом `callback_url`, в нём также содержится поле `task_id`, таким образом результаты задач могут быть связаны через ID.

Ниже мы на примере ознакомимся с тем, как конкретно выполнять операции.

Сначала, обратный вызов Webhook — это сервис, который может принимать HTTP-запросы, разработчик должен заменить его на URL самостоятельно развёрнутого HTTP-сервера. Здесь для удобства демонстрации используется публичный пример сайта Webhook https://webhook.site/, откройте этот сайт, чтобы получить Webhook URL, как показано на рисунке:

![](https://cdn.acedata.cloud/tbcnai.png)

Скопируйте этот URL, и его можно использовать в качестве Webhook, пример здесь: `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Далее мы можем установить поле `callback_url` в указанный выше Webhook URL, одновременно заполнив соответствующие параметры, конкретное содержание показано на рисунке:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Нажмите запуск, и можно заметить, что немедленно будет получен результат, как показано ниже:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Немного подождав, мы можем наблюдать результат сгенерированного видео на `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, как показано на рисунке:

![](https://cdn.acedata.cloud/zv5u2q.png)

Содержание следующее:
```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Можно увидеть, что в результате есть поле `task_id`, остальные поля аналогичны вышеописанным, с помощью этого поля можно реализовать связывание задач.

## Обработка ошибок

При вызове API, если возникает ошибка, API вернёт соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Некорректный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `400 api_not_implemented`：Некорректный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `401 invalid_token`：Не авторизовано, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили ограничение скорости.
- `500 api_error`：Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
