Основная функция API Kling Tasks заключается в том, чтобы запрашивать статус выполнения задач, используя идентификатор задачи, сгенерированный API Kling Videos Generation.

В этом документе подробно описывается интеграция API Kling Tasks, чтобы помочь вам легко интегрировать и в полной мере использовать мощные функции этого API. С помощью API Kling Tasks вы можете легко реализовать запрос статуса выполнения задач API Kling Videos Generation.

## Процесс подачи заявки

Чтобы использовать API Kling Tasks, сначала необходимо перейти на страницу заявки [Kling Videos Generation API](https://platform.acedata.cloud/documents/kling-videos) и подать заявку на соответствующую услугу, затем скопировать идентификатор задачи API Kling Videos Generation, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Затем перейдите на страницу API Tasks [Kling Tasks API](https://platform.acedata.cloud/documents/kling-tasks) и подайте заявку на соответствующую услугу, после перехода на страницу нажмите кнопку «Acquire», как показано на рисунке:

![Страница заявки](https://cdn.acedata.cloud/rci31i.png)

Если вы еще не вошли в систему или не зарегистрированы, вы будете автоматически перенаправлены на [страницу входа](https://platform.acedata.cloud), где вас пригласят зарегистрироваться и войти в систему. После регистрации и входа вы будете автоматически возвращены на текущую страницу.

При первой подаче заявки предоставляется бесплатный лимит, который позволяет бесплатно использовать этот API.

## Пример запроса

API Kling Tasks можно использовать для запроса результатов API Kling Videos Generation. Для получения информации о том, как использовать API Kling Videos Generation, пожалуйста, обратитесь к документации [Kling Videos Generation API](https://platform.acedata.cloud/documents/kling-videos).

Мы возьмем в качестве примера идентификатор задачи, возвращаемый службой API Kling Videos Generation, и продемонстрируем, как использовать этот API. Предположим, у нас есть идентификатор задачи: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, далее мы покажем, как передать этот идентификатор задачи.

### Установка заголовков запроса и тела запроса

**Request Headers** включает:

- `accept`: указывает на прием ответа в формате JSON, здесь указывается `application/json`.
- `authorization`: ключ для вызова API, после подачи заявки его можно выбрать из выпадающего списка.

**Request Body** включает:

- `id`: загруженный идентификатор задачи.
- `action`: способ выполнения операции над задачей.

Некоторые примеры кода:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## 错误处理

在调用 API 时，如果遇到错误，API 会返回相应的错误代码和信息。例如：

- `400 token_mismatched`：Неверный запрос, возможно, из-за отсутствия или недействительных параметров.
- `400 api_not_implemented`：Неверный запрос, возможно, из-за отсутствия или недействительных параметров.
- `401 invalid_token`：Неавторизован, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили лимит частоты.
- `500 api_error`：Внутренняя ошибка сервера, что-то пошло не так на сервере.
