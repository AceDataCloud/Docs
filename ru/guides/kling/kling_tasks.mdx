Основная функция Kling Tasks API — запрашивать статус выполнения задачи путём ввода ID задачи, сгенерированного Kling Videos Generation API.

В этом документе будет подробно представлено описание интеграции Kling Tasks API, что поможет вам легко интегрировать и в полной мере использовать мощные возможности этого API. С помощью Kling Tasks API вы можете легко реализовать запрос статуса выполнения задач Kling Videos Generation API.

## Процесс подачи заявки

Чтобы использовать Kling Videos Generation API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрированы, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти, после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, без необходимости подавать отдельную заявку для каждого сервиса.** При первой заявке предоставляется бесплатный лимит, позволяющий бесплатно попробовать сервис; при недостатке лимита вы можете пополнить универсальный баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Пример запроса

Kling Tasks API может использоваться для запроса результатов Kling Videos Generation API. О том, как использовать Kling Videos Generation API, см. документацию [Kling Videos Generation API ](https://platform.acedata.cloud/documents/kling-videos).

Мы возьмём в качестве примера один ID задачи, возвращённый сервисом Kling Videos Generation API, чтобы продемонстрировать, как использовать этот API. Предположим, у нас есть ID задачи: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, далее продемонстрируем, как посредством передачи одного ID задачи.

### Настройка заголовков и тела запроса

**Заголовки запроса** включают:

- `accept`: указывает получение результатов ответа в формате JSON, здесь указывается `application/json`.
- `authorization`: ключ для вызова API, после подачи заявки его можно выбрать непосредственно из выпадающего списка.

**Тело запроса** включает:

- `id`: ID загруженной задачи.
- `action`: способ операции с задачей.

Некоторые примеры кода приведены ниже:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Результат возврата содержит несколько полей, поле request — это request body при запуске задачи, а поле response — это response body, возвращаемое после завершения задачи. Описание полей приведено ниже.

- `id` — ID, генерирующий данную задачу видео, используется для уникальной идентификации данной задачи генерации видео.
- `request` — информация запроса в задаче запроса видео.
- `response` — информация ответа в задаче запроса видео.
- `created_at` — время создания задачи, временная метка Unix (секунды, с плавающей точкой).
- `started_at` — время начала выполнения задачи, временная метка Unix (секунды, с плавающей точкой).
- `finished_at` — время завершения задачи, временная метка Unix (секунды, с плавающей точкой). Это поле не возвращается, если задача не завершена.
- `elapsed` — время выполнения задачи, в секундах (с плавающей точкой, сохраняется 3 знака после запятой). Это поле не возвращается, если задача не завершена.

**Тело запроса** включает:

- `ids`: массив ID загруженных задач.
- `action`: способ операции с задачей.

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и сообщение. Например:

- `400 token_mismatched`: Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `400 api_not_implemented`: Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `401 invalid_token`: Не авторизован, недопустимый или отсутствующий токен авторизации.
- `429 too_many_requests`: Слишком много запросов, вы превысили ограничение частоты запросов.
- `500 api_error`: Внутренняя ошибка сервера, на сервере что-то пошло не так.
