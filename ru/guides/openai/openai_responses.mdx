Совместимые запросы моделей, принимаемые платформой, тарифицируются в зависимости от объёма ввода, вывода и кэша модели. Общий объём ввода Responses включает сообщённые кэшированные token, кэшированная часть рассчитывается по соответствующей цене кэша; переключение формата интерфейса не изменит тарификацию на фиксированное количество запросов. Стоимость определяется текущими ценами моделей в консоли и `usage.cost` в ответе.

Недавно OpenAI предоставила интерфейс для создания ответов модели. Предоставляйте текстовые или графические входные данные для генерации текстовых или графических выходных данных. Позвольте модели вызывать ваш собственный пользовательский код или использовать встроенные инструменты, такие как web-поиск или поиск по файлам, чтобы использовать ваши собственные данные в качестве входных данных для ответа модели.

В этом документе главным образом описывается процесс использования операций OpenAI Responses API, с его помощью мы можем легко использовать официальную функцию OpenAI для создания ответов модели.

## GPT-6.1 Terra

Используйте `model: "gpt-6.1-terra"` для выбора этой модели. Поддерживаются текстовый и графический ввод, потоковый вывод, инструменты-функции и структурированный вывод. Уровни рассуждений поддерживают `low`, `medium`, `high`, `xhigh` и `max`, рекомендуется начинать с `reasoning: {"effort": "low"}`; `none` и `minimal` не поддерживаются. Когда ввод превышает 272,000 tokens, применяется цена для длинного контекста, фактическая стоимость определяется текущими ценами в консоли и использованием в ответе.

## GPT-6.1 Sol

Используйте `model: "gpt-6.1-sol"` для выбора этой модели. Поддерживаются потоковый вывод, вызовы функций, структурированный вывод и графический ввод. В течение первой недели после открытия доступ предоставляется только подтверждённым владельцам ACE T1+ (не менее 100,000 ACE) или авторизованным пользователям; конкретное время открытия определяется подсказкой доступа в консоли.

Уровни рассуждений поддерживают `low`, `medium`, `high`, `xhigh` и `max`, `none` и `minimal` пока не поддерживаются. Рекомендуется начинать с `reasoning: {"effort": "low"}`. Когда ввод превышает 272,000 tokens, цена для длинного контекста применяется ко всему запросу, стоимость определяется текущими ценами в консоли.

## Процесс подачи заявки

Чтобы использовать OpenAI Responses API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа с предложением зарегистрироваться и войти, после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первой заявке предоставляется бесплатный лимит, который можно использовать для бесплатного ознакомления; при недостаточном лимите можно пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Базовое использование

Далее можно заполнить соответствующее содержимое в интерфейсе, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

При первом использовании этого интерфейса нам необходимо заполнить как минимум три поля: одно из них — `authorization`, его можно непосредственно выбрать из выпадающего списка. Другой параметр — `model`, `model` — это выбранная нами категория моделей с официального сайта OpenAI ChatGPT, здесь у нас в основном имеется 20 типов моделей, подробнее можно посмотреть предоставляемые нами модели. Последний параметр — `input`, `input` — это массив введённых нами запросов, это массив, означающий, что можно одновременно загрузить несколько запросов, каждый запрос содержит `role` и `content`, где `role` обозначает роль задающего вопрос, мы предоставляем три роли: `user`, `assistant`, `system`. А `content` — это конкретное содержание нашего запроса.

Одновременно вы можете заметить, что справа генерируется соответствующий код вызова, вы можете скопировать код и запустить его напрямую, а также можете непосредственно нажать кнопку «Try» для тестирования.

Часто используемые необязательные параметры:

- `max_tokens`: ограничивает максимальное количество token в одном ответе.
- `temperature`: случайность генерации, от 0 до 2, чем больше значение, тем более разнообразен результат.
- `n`: сколько кандидатных ответов генерировать за один раз.
- `response_format`: настройка формата возврата.
- `tools`: определение вызовов функций/инструментов.
- `background`: выполнять ли асинхронно в фоновом режиме.

## Потоковый ответ

Этот интерфейс также поддерживает потоковые ответы, что очень полезно для интеграции с веб-страницами и позволяет реализовать на веб-странице эффект посимвольного отображения.

Если вы хотите возвращать ответ в потоковом режиме, можно изменить параметр `stream ` в заголовке запроса на `true`.

Изменение показано на рисунке, однако код вызова должен иметь соответствующие изменения для поддержки потокового ответа.
<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

После изменения `stream` на `true` API будет построчно возвращать соответствующие данные JSON, и на уровне кода нам необходимо внести соответствующие изменения, чтобы получать построчные результаты.

Пример кода вызова на Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Можно увидеть, что в ответе имеется множество `data`, а `delta` внутри `data` — это самое новое содержимое ответа, что соответствует содержимому, представленному выше. `delta` — это добавленное содержимое ответа, вы можете интегрировать его в свою систему на основе результата. Потоковый ответ использует `response.completed` или `response.incomplete` в качестве конечного состояния; `usage` в конечном состоянии — это итоговое потребление token для этого запроса, а также основание для выставления счёта.

Если клиент разрывает соединение до наступления конечного состояния, этот запрос будет зарегистрирован как закрытый клиентом (499), и оплата не будет взиматься на основе локально рассчитанных token; если соединение завершается нормально, но конечное состояние и итоговое значение `usage` не получены, этот запрос будет зарегистрирован как неполный ответ (502), и оплата также не будет взиматься на основе расчётных token. При возникновении этих двух ситуаций повторно отправьте запрос.

Возвращаемый результат `data` содержит несколько полей, описание которых приведено ниже:

- `item_id` — ID созданной задачи этого диалога, используемый для уникальной идентификации этой задачи диалога.
- `type` — тип созданной задачи Responses этого диалога.
- `model ` — выбранная модель OpenAI ChatGPT с официального сайта.
- `delta` — информация об ответе, предоставленном ChatGPT на вопрос.


## Многораундовый диалог

Если вы хотите интегрировать функцию многораундового диалога, необходимо передать несколько вопросов в поле `input`; конкретный пример нескольких вопросов показан на рисунке ниже:

<p><img src="https://cdn.acedata.cloud/1jqwnf.png" width="400" className="m-auto" /></p>

Пример кода вызова Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"},{"role":"assistant","content":"Hello! How can I help you today? 😊"},{"role":"user","content":"What did I just say?"}]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Визуальная модель

gpt-4o — это мультимодальная большая языковая модель, разработанная OpenAI, которая добавляет возможности визуального понимания на основе GPT-4. Эта модель может одновременно обрабатывать текстовые и графические входные данные, реализуя кросс-модальное понимание и генерацию.

Текстовая обработка с использованием модели gpt-4o соответствует содержимому базового использования, приведённому выше; ниже кратко рассказывается, как использовать возможности модели по обработке изображений.

Возможности обработки изображений модели gpt-4o главным образом используются путём добавления поля `type` к исходному содержимому `content`; с помощью этого поля можно определить, загружается ли текст или изображение, и тем самым использовать возможности обработки изображений модели gpt-4o. Ниже главным образом описывается вызов этой функции двумя способами: Curl и Python.

- Способ с помощью скрипта Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Способ с помощью скрипта Python

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`: Некорректный запрос, возможно из-за отсутствующих или недействительных параметров.
- `400 api_not_implemented`: Некорректный запрос, возможно из-за отсутствующих или недействительных параметров.
- `401 invalid_token`: Не авторизован, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`: Слишком много запросов, вы превысили лимит скорости.
- `500 api_error`: Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
