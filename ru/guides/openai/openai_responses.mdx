OpenAI недавно предоставила интерфейс для создания ответов моделей. Предоставьте текстовый или графический ввод для генерации текстового или графического вывода. Позвольте модели вызывать ваш собственный пользовательский код или использовать встроенные инструменты, такие как web-поиск или поиск по файлам, чтобы использовать ваши собственные данные в качестве входных данных для ответов модели.

Этот документ в основном описывает процесс использования OpenAI Responses API, с его помощью мы можем легко использовать официальную функцию OpenAI для создания ответов моделей.

## GPT-6.1 Sol

Используйте `model: "gpt-6.1-sol"` для выбора этой модели. Поддерживаются потоковый вывод, вызов функций, структурированный вывод и ввод изображений. В течение первой недели после открытия она доступна только подтвержденным держателям ACE T1+ (не менее 100 000 ACE) или авторизованным пользователям; конкретное время открытия определяется подсказками доступа в консоли.

Уровень рассуждений поддерживает `low`, `medium`, `high`, `xhigh` и `max`, `none` или `minimal` пока не поддерживаются. Рекомендуется начать с `reasoning: {"effort": "low"}`. Когда ввод превышает 272 000 tokens, ко всему запросу применяется цена за длинный контекст, стоимость определяется текущими ценами в консоли.

## Процесс подачи заявки

Чтобы использовать OpenAI Responses API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications), оставьте его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы еще не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти, после завершения вы автоматически вернетесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, не нужно подавать отдельную заявку для каждого сервиса.** При первой заявке будет предоставлен бесплатный лимит, можно бесплатно попробовать; когда лимита недостаточно, можно пополнить универсальный баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация：[OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Базовое использование

Далее можно заполнить соответствующее содержимое в интерфейсе, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

При первом использовании этого интерфейса нам нужно заполнить как минимум три поля, одно из них — `authorization`, его можно выбрать непосредственно в выпадающем списке. Другой параметр — `model`, `model` — это категория модели, которую мы выбираем для использования на официальном сайте OpenAI ChatGPT, здесь у нас в основном есть 20 моделей, подробности можно посмотреть в предоставленных нами моделях. Последний параметр — `input`, `input` — это массив введенных нами запросов, это массив, который означает, что можно одновременно загрузить несколько запросов, каждый запрос содержит `role` и `content`, где `role` обозначает роль задающего вопрос, мы предоставляем три роли: `user`, `assistant`, `system`. Другой параметр `content` — это конкретное содержание нашего запроса.

В то же время вы можете заметить, что справа генерируется соответствующий код вызова, вы можете скопировать код и запустить его напрямую, либо непосредственно нажать кнопку «Try» для тестирования.

Часто используемые необязательные параметры:

- `max_tokens`: ограничивает максимальное число token в одном ответе.
- `temperature`: случайность генерации, от 0 до 2, чем больше значение, тем более разнообразным будет результат.
- `n`: сколько вариантов ответов генерировать за один раз.
- `response_format`: настройка формата возврата.
- `tools`: определение вызовов функций/инструментов.
- `background`: выполнять ли асинхронно в фоновом режиме.

## Потоковый ответ

Этот интерфейс также поддерживает потоковые ответы, что очень полезно для интеграции с веб-страницами и позволяет реализовать на веб-странице эффект посимвольного отображения.

Если вы хотите вернуть ответ потоком, можно изменить параметр `stream ` в заголовке запроса на `true`.

Изменение показано на рисунке, однако код вызова должен быть соответствующим образом изменен для поддержки потокового ответа.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

После изменения `stream` на `true` API будет построчно возвращать соответствующие JSON-данные, на уровне кода нам необходимо внести соответствующие изменения, чтобы получать результаты построчно.

Пример кода вызова на Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Можно увидеть, что в ответе содержится множество `data`, а `delta` внутри `data` — это самое новое содержимое ответа, что соответствует содержимому, описанному выше. `delta` — это добавленное содержимое ответа, вы можете на основе результата интегрировать его в свою систему. Потоковый ответ завершается состоянием `response.completed` или `response.incomplete`; `usage` в конечном состоянии — это итоговое количество token для данного запроса, а также основа для выставления счёта.

Если клиент разрывает соединение до достижения конечного состояния, данный запрос будет записан как закрытый клиентом (499), и тарификация по локально оценённым token не будет применяться; если соединение завершается нормально, но конечное состояние и итоговый `usage` не получены, данный запрос будет записан как неполный ответ (502), и тарификация по оценённым token также не будет применяться. При возникновении этих двух ситуаций повторно отправьте запрос.

Возвращаемый результат `data` содержит несколько полей, описание которых приведено ниже:

- `item_id` — ID созданной задачи данного диалога, используемый для уникальной идентификации этой задачи диалога.
- `type` — тип созданной задачи Responses данного диалога.
- `model ` — выбранная модель OpenAI ChatGPT с официального сайта.
- `delta` — информация ответа, предоставленная ChatGPT на вопрос.

JavaScript также поддерживается, например, код потокового вызова для Node.js приведён ниже:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```


Пример кода вызова Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"},{"role":"assistant","content":"Hello! How can I help you today? 😊"},{"role":"user","content":"What did I just say?"}]

response = requests.post(url, json=payload, headers=headers)
```

## Визуальная модель

gpt-4o — это мультимодальная большая языковая модель, разработанная OpenAI, которая на основе GPT-4 получила возможность визуального понимания. Эта модель может одновременно обрабатывать текстовые и графические входные данные, обеспечивая кросс-модальное понимание и генерацию.
Обработка текста с использованием модели gpt-4o соответствует основному содержанию использования, описанному выше, ниже будет кратко представлено, как использовать возможности модели по обработке изображений.

Использование возможностей обработки изображений модели gpt-4o в основном осуществляется путем добавления поля `type` на основе исходного содержимого `content`, с помощью этого поля можно определить, загружается текст или изображение, тем самым используя возможности обработки изображений модели gpt-4o. Ниже в основном рассказывается о вызове этой функции двумя способами: Curl и Python.

- Способ с помощью скрипта Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Способ с помощью скрипта Python

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и сообщение. Например:

- `400 token_mismatched`: Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `400 api_not_implemented`: Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `401 invalid_token`: Не авторизован, недопустимый или отсутствующий токен авторизации.
- `429 too_many_requests`: Слишком много запросов, вы превысили лимит частоты запросов.
- `500 api_error`: Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
