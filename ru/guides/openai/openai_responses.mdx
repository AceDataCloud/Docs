OpenAI недавно предоставила интерфейс для создания ответов модели. Предоставляйте текстовый или графический ввод для генерации текстового или графического вывода. Позвольте модели вызывать ваш собственный пользовательский код или использовать встроенные инструменты, такие как web-поиск или поиск по файлам, чтобы использовать ваши собственные данные в качестве ввода для ответов модели.

В этом документе в основном описывается процесс использования OpenAI Responses API. С его помощью мы можем легко использовать официальную функцию OpenAI для создания ответов модели.

## Процесс подключения

Чтобы использовать OpenAI Responses API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти в систему. После завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, без необходимости подавать отдельную заявку для каждого сервиса.** При первом подключении предоставляется бесплатный лимит, позволяющий пользоваться сервисом бесплатно; при недостатке лимита вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Базовое использование

Далее вы можете заполнить соответствующие данные в интерфейсе, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

При первом использовании этого интерфейса нам необходимо заполнить как минимум три поля: одно из них — `authorization`, которое можно просто выбрать в выпадающем списке. Другой параметр — `model`, `model` — это категория моделей, выбранная нами на официальном сайте OpenAI ChatGPT; здесь у нас имеется 20 моделей, подробнее можно посмотреть в предоставленном нами списке моделей. Последний параметр — `input`, `input` — это массив введённых нами запросов; он представляет собой массив, что означает возможность одновременной загрузки нескольких запросов. Каждый запрос содержит `role` и `content`, где `role` обозначает роль задающего вопрос; мы предоставляем три роли: `user`, `assistant`, `system`. Другой параметр `content` — это конкретное содержание нашего запроса.

В то же время вы можете заметить, что справа генерируется соответствующий код вызова. Вы можете скопировать код и запустить его напрямую, а также можете непосредственно нажать кнопку «Try» для тестирования.

Распространённые необязательные параметры:

- `max_tokens`：ограничивает максимальное количество token в одном ответе.
- `temperature`：случайность генерации, от 0 до 2; чем больше значение, тем более разнообразным будет результат.
- `n`：сколько вариантов ответов генерировать за один раз.
- `response_format`：настройка формата возврата.
- `tools`：определение вызовов функций/инструментов.
- `background`：запускать ли асинхронно в фоновом режиме.

## Потоковый ответ

Этот интерфейс также поддерживает потоковые ответы, что очень полезно для интеграции с веб-страницами и позволяет реализовать эффект посимвольного отображения на веб-странице.

Если вы хотите возвращать ответ в потоковом режиме, можно изменить параметр `stream ` в заголовке запроса на `true`.

Изменение показано на рисунке, однако код вызова необходимо соответствующим образом изменить, чтобы поддерживать потоковый ответ.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

После изменения `stream` на `true` API будет построчно возвращать соответствующие JSON-данные; на уровне кода необходимо внести соответствующие изменения, чтобы получать построчные результаты.

Пример кода вызова на Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Можно увидеть, что в ответе содержится множество `data`, а `delta` внутри `data` является самым новым содержимым ответа, что соответствует содержанию, представленному выше. `delta` — это добавленное содержимое ответа, вы можете интегрировать его в свою систему на основе результата. Потоковый ответ использует `response.completed` или `response.incomplete` в качестве конечного состояния; `usage` в конечном состоянии является итоговым расходом token для данного запроса, а также основанием для тарификации.

Если клиент отключается до достижения конечного состояния, данный запрос записывается как закрытый клиентом (499), и тарификация по локально оценённым token не применяется; если соединение завершается нормально, но конечное состояние и итоговый `usage` не получены, данный запрос записывается как неполный ответ (502), и тарификация по оценённым token также не применяется. При возникновении этих двух ситуаций повторно отправьте запрос.

Возвращаемый результат `data` содержит несколько полей, описание которых приведено ниже:

- `item_id` — ID созданной задачи данного диалога, используемый для уникальной идентификации данной задачи диалога.
- `type` — тип созданной задачи Responses данного диалога.
- `model ` — выбранная модель OpenAI ChatGPT с официального сайта.
- `delta` — информация ответа, предоставленная ChatGPT на вопрос.

JavaScript также поддерживается, например, код потокового вызова для Node.js приведён ниже:

```javascript

```

import requests

## Визуальная модель

gpt-4o — это мультимодальная большая языковая модель, разработанная OpenAI; она добавляет возможности визуального понимания на основе GPT-4. Эта модель может одновременно обрабатывать текстовые и графические входные данные, обеспечивая кросс-модальное понимание и генерацию.
Обработка текста с использованием модели gpt-4o аналогична базовому использованию, описанному выше. Ниже будет кратко рассказано о том, как использовать возможности модели по обработке изображений.

Использование возможностей обработки изображений модели gpt-4o в основном осуществляется путем добавления поля `type` к исходному содержимому `content`. С помощью этого поля можно определить, загружается ли текст или изображение, и таким образом использовать возможности обработки изображений модели gpt-4o. Ниже главным образом описывается вызов этой функции двумя способами: Curl и Python.

- Способ с использованием скрипта Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Способ с использованием скрипта Python

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `400 api_not_implemented`：Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `401 invalid_token`：Не авторизован, недопустимый или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили лимит частоты запросов.
- `500 api_error`：Внутренняя ошибка сервера, что-то пошло не так на сервере.

### Пример ответа об ошибке

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
