Вызовите `POST /tripo/animations`, используя `action` для выбора проверки скелета, автоматической привязки или переноса анимации. Передайте `async: true` для опроса `/tripo/tasks`, а `callback_url` — для получения окончательного результата.

1. **Проверка**. Отправьте `{"action":"rig_check","model_id":"5db97adc-a877-4587-af16-bbf443aa55de"}`. Элемент результата содержит логическое значение `riggable` и необязательное поле `rig_type`. Успешная проверка и `riggable: false` означают, что модель не подходит для привязки. Эта операция бесплатна.
2. **Привязка**. Отправьте `{"action":"rig","model_id":"5db97adc-a877-4587-af16-bbf443aa55de","model":"v3.0-20260909","rig_type":"biped","format":"GLB"}`. Результатом будет новая модель со скелетом, сохраните её `data[0].id`. Проверка и привязка также могут считывать существующий файл через `model_url`.
3. **Перенос**. Используйте ID результата привязки в качестве `model_id`. Например, `{"action":"retarget","model_id":"96a66a1d-69d2-48f0-846b-bdf02ed9bcc4","animations":["preset:walk","preset:idle"],"format":"GLB","async":true}`. Выбирайте пресеты, совместимые с версией и типом скелета; для одного передайте `animation`, для нескольких — `animations`, не более пяти, оплата взимается по количеству движений. Пакетный запрос может возвращать один файл, содержащий несколько анимационных дорожек.

Привязка и перенос поддерживают GLB и FBX. Используйте `export_with_geometry`, чтобы управлять включением геометрии в результат переноса, а `animate_in_place` — чтобы управлять сохранением перемещения. Адрес для скачивания файла модели находится в `data[0].model_url`.
