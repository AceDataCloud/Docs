---
title: "Запрос задач моделей Tripo"
description: "Tripo 3D API guide - Ace Data Cloud"
---

Вызовите `POST /tripo/tasks` с токеном AceDataCloud. Запрос бесплатный, используйте ту же учётную запись, что и при генерации. Для отдельной задачи используйте `id` или `trace_id`, значение `action` по умолчанию — `retrieve`.

```bash
curl -X POST https://api.acedata.cloud/tripo/tasks \
  -H "Authorization: Bearer ${ACEDATACLOUD_API_TOKEN}" \
  -H "Content-Type: application/json" \
  -d "{\"action\":\"retrieve\",\"id\":\"${TASK_ID}\"}"
```

Результат запроса отдельной задачи — запись задачи, содержащая `id`, `type`, `trace_id`, исходный запрос `request`, `started_at` и `progress`. Во время обработки можно повторять запрос с интервалом в несколько секунд. После завершения проверьте `response.success`: при успехе `response.data[0].model_url` содержит адрес для скачивания, при ошибке `response.error` содержит код и сообщение об ошибке. Временные метки, `finished_at` и затраченное время `elapsed` находятся на верхнем уровне записи задачи, единица измерения — секунда. При возникновении `submission_unknown` сохраните исходный ID задачи для сверки.

Для пакетного запроса используйте `{"action":"retrieve_batch","ids":["<ID задачи 1>","<ID задачи 2>"]}`, также можно использовать `trace_ids`; за один раз можно запросить не более 100 задач. Ответ имеет вид `{"items":[...],"count":2}`, порядок ввода и повторяющиеся элементы сохраняются. Для задачи, которая не найдена или на чтение которой нет прав, отдельный запрос возвращает `{}`, а пакетный запрос — `null` в соответствующей позиции.

Значение `type` в записи задачи — `generations`, `models` или `animations`. Для проверки скелета считывайте `response.data[0].riggable`, для операций с файлами — `response.data[0].model_url`.
