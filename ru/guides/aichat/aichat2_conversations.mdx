AI Chat v2 API (`/aichat2/conversations`) — это интерфейс нового поколения для диалогов, представляющий собой полное обновление [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). На основе простого и управляемого многоэтапного диалога v1 он расширяет следующие возможности:

- **Мультимодальный ввод пользователя**: передача текста + изображений + файловых блоков непосредственно через структурированное поле `message`, без необходимости предварительного косвенного прикрепления через `references`.
- **Вызов инструментов в режиме Agent**: встроенный набор инструментов для поиска в Интернете, извлечения веб-страниц, чтения файлов и других задач. Также можно подключать MCP-серверы, авторизованные пользователем (Google Drive, Notion, Slack, GitHub и др.). Модель может самостоятельно многократно вызывать инструменты в рамках одного запроса для выполнения сложных задач.
- **Структурированные потоковые события**: с помощью `accept: text/event-stream` или `application/x-ndjson` можно получать события по каждому токену, такие как `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` и другие, что позволяет отдельно отображать их на стороне интерфейса в соответствии с соответствующим типом.
- **Возможность прерывания / возобновления**: когда модели требуется дополнительная информация от пользователя, она отправляет событие `ask_user_question` и приостанавливает выполнение. При следующем вызове достаточно передать ответ через `tool_results`, чтобы продолжить работу.
- **Новые CRUD-действия**: на том же endpoint через поле `action` можно выполнять `retrieve` / `retrieve_batch` / `update` / `delete`, без необходимости в дополнительных API для управления сессиями.
- **Постоянно обновляемый список моделей**: по умолчанию доступны современные модели, такие как GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 и другие.

При этом на уровне тела запроса обеспечивается **полная обратная совместимость с v1**: достаточно передать только `model` + `question` (+ необязательные `stateful` / `id` / `references` / `preset`), чтобы получить эквивалентный v1 JSON-ответ `{answer, id}`. Поэтому при переходе с `/aichat/conversations` не требуется переписывать клиентскую часть — достаточно изменить путь на `/aichat2/conversations`.

> Если в настоящее время вы используете `/aichat/conversations`, старый интерфейс продолжит поддерживаться. Вы можете перейти на новую версию в удобном для вас темпе.

## Процесс получения доступа

Чтобы использовать AI Chat v2 API, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications), чтобы получить свой API Token и сохранить его для дальнейшего использования.

**Одного API Token достаточно для вызова всех сервисов платформы, отдельная заявка для каждого сервиса не требуется.** При первой подаче заявки предоставляется бесплатный лимит для ознакомления. ## Основное использование

Самый простой способ использования полностью совпадает с v1: передайте `model` + `question` и получите `{answer, id}`.

Пример CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Результат:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Пример Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Многоэтапный диалог

Как и в v1, передайте `stateful: true`, чтобы включить сохранение сессии. API вернёт `id`; в последующих запросах достаточно передавать тот же `id`, чтобы продолжить диалог, не поддерживая историю messages самостоятельно.

Первый запрос:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Ответ:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Второй запрос — передайте тот же `id`：
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` по умолчанию имеет значение `true`, поэтому его пропуск и явная передача `true` эквивалентны. Установка `stateful: false` пропускает загрузку истории предыдущих сообщений; это не означает, что результат текущего запроса не будет сохранён, и не подходит для процессов работы с инструментами, которые требуют приостановки и последующего продолжения.

### Длинные диалоги и сохранение исходного текста

Сжатие контекста упорядочивает только содержимое, отправляемое модели в текущем запросе, и не заменяет сохранённую историю чата. С помощью `action: retrieve` по-прежнему можно прочитать все сохранённые сообщения; явное редактирование и удаление диалога по-прежнему выполняются в соответствии с запросом.

Модель может искать и постранично читать исходный текст истории в рамках текущего диалога. При необходимости продолжить редактирование статьи, процитировать числа или подготовить публикацию следует прочитать соответствующий исходный текст, а не заменять основной текст кратким изложением. Эта возможность не восстанавливает автоматически сообщения, уже утраченные в предыдущих версиях.

Если упорядочивание контекста завершилось неудачей, сохраните ID диалога и проверьте событие `error`; сервис не будет перезаписывать исходный текст пустым резюме. Операции с инструментами, завершённые до сбоя, всё ещё могут быть действительными, поэтому сначала проверьте их результаты, чтобы избежать повторной генерации или повторной публикации. При достижении лимита хранилища для одного диалога будет явно возвращена ошибка; существующие сохранённые записи не будут обрезаны для освобождения места. Вы можете экспортировать необходимое содержимое, а затем начать новый диалог.

## Потоковая передача ответа

v2 поддерживает два потоковых формата, выбираемых с помощью заголовка `accept`:

| Сценарий                    | `accept`               | Формат данных                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Веб-интерфейс / EventSource  | `text/event-stream`    | `data: {json}\n\n`, последняя строка `data: [DONE]\n\n` |
| Сервер / CLI / потоковый парсер Node | `application/x-ndjson` | Один объект JSON в каждой строке                               |
| Потоковая передача не требуется                 | `application/json`（по умолчанию） | Однократный возврат `{answer, id}`                       |

### Пример NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # Совместимость с v1: инкрементальный фрагмент одновременно предоставляется через поле delta_answer
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Каждая строка NDJSON представляет собой структурированное событие. Наиболее распространённым является `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Пример SSE

В браузере `EventSource` не поддерживает пользовательское тело запроса, поэтому рекомендуется использовать `fetch` + ручное разделение и разбор по `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Типы потоковых событий

| `type`              | Значение                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Инкрементальный текстовый фрагмент ответа ассистента. `content` содержит новое содержимое; для совместимости с v1 то же событие также содержит `delta_answer` (равный `content`) и `id`. |
| `thinking`          | Процесс рассуждения модели (появляется только в том случае, если выбранная модель предоставляет reasoning). |
| `tool_use`          | Модель принимает решение вызвать инструмент; событие содержит `tool_id`, `tool_name`, `input`. |
| `tool_result`       | Результат выполнения инструмента, сопоставляемый с предыдущим `tool_use` через `tool_id`; `is_error` указывает, произошла ли ошибка. |
| `card`              | Структурированная карточка, созданная инструментом (например, изображение или предпросмотр ссылки), подходящая для непосредственного отображения. |
| `citation`          | URL источника, используемый для дополнения цитаты соответствующего текстового фрагмента. |
| `ask_user_question` | Отправляется, когда модели требуется дополнительная информация от пользователя; диалог переходит в состояние `awaiting_user_input`. Подробнее см. ниже: [Возобновление приостановленного диалога](#恢复暂停的对话). |
| `artifact`          | Самостоятельный результат, созданный моделью (например, блок кода или документ), который можно сохранить или скачать. |
| `system_message`    | Системное информационное сообщение (не является содержимым пользователя или ассистента), используется только для отображения уведомлений в интерфейсе. |
| `compact`           | Контекст модели был упорядочен; сохранённые исходные сообщения остаются неизменными, клиенту не нужно удалять историю чата. |
| `error`             | В текущем запросе произошла ошибка; `message` описывает её содержание. |
| `done`              | Финальная запись текущего диалога успешно сохранена; содержит `usage` (включая `prompt_tokens` / `completion_tokens` / `total_tokens`) и `terminal_reason`. Для определения того, выполнена ли задача, всё ещё необходимо учитывать причину завершения. |
Для клиентов, которые заботятся только об окончательном ответе, объединение `content` всех `text_delta` эквивалентно `answer` в режиме `application/json`.

## Мультимодальный ввод

Если пользовательский ввод содержит изображения или файлы, передавайте `message` (массив) вместо `question`. Каждый элемент массива представляет собой блок содержимого:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "Сколько кошек на этой картинке?" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Поддерживаемые типы блоков:

- `text` — обычный текст, обязательное поле `text`.
- `image_url` — изображение, обязательное поле `image_url.url`.
- `file_url` — файл (PDF, CSV, TXT и т. д.), обязательное поле `file_url.url`.

### Связь с `references` в v1

Для обеспечения совместимости со старыми клиентами v2 по-прежнему распознаёт поле `references: ["https://...", ...]`:

- URL с расширениями `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif` автоматически преобразуются в блоки `image_url`;
- URL с другими расширениями преобразуются в блоки `file_url`;
- Если одновременно предоставлен `question`, он добавляется в начало в качестве блока `text`.

Таким образом, если вы хотите перейти с v1, не изменяя тело запроса, достаточно заменить путь на `/aichat2/conversations`, и исходный способ использования `references` продолжит работать.

Если требуется более точное управление (например, размещение нескольких изображений между текстовыми фрагментами или соблюдение определённого порядка), используйте непосредственно массив `message`.

## Вызовы инструментов и MCP

Ключевое улучшение v2 заключается в том, что модель может самостоятельно вызывать инструменты для выполнения многоэтапных задач. **Эта функция включена по умолчанию**, и клиенту не требуется выполнять какие-либо дополнительные настройки в запросе. Типичные сценарии:

- Пользователь спрашивает: «Найди, пожалуйста, последние новые выставки в Шанхае» → модель вызывает встроенный web search → систематизирует результаты и формирует ответ.
- Пользователь спрашивает: «Прочитай этот PDF и составь краткое содержание» → модель вызывает file_read → составляет краткое содержание.
- Пользователь уже предоставил разрешение Google Drive / GitHub / Notion и других сервисов в разделе [Connections](https://platform.acedata.cloud/connections) → модель может вызывать соответствующие инструменты MCP для чтения и записи данных.

В потоках NDJSON / SSE вызовы инструментов представлены двумя типами событий: `tool_use` и `tool_result`, например:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Если вы не хотите отображать подробности вызовов инструментов на стороне интерфейса, просто игнорируйте события типов `tool_use` / `tool_result` / `card` / `citation`. Окончательный вывод модели по-прежнему будет передаваться через поток `text_delta`.

Параметр `max_turns` позволяет ограничить максимальное количество циклов самостоятельного вызова инструментов моделью в рамках текущего запроса. Допустимый диапазон — 1–500, значение по умолчанию при отсутствии параметра — 500. Установив небольшое значение (например, `max_turns: 1`), можно принудительно ограничить модель одним ответом без вызова каких-либо инструментов.

## Асинхронное выполнение и авторизация без участия пользователя

Если ваш запрос поступает из Webhook системы оповещений, CI/CD, системы мониторинга или другой фоновой задачи, можно установить `async: true`, чтобы интерфейс немедленно вернул идентификатор задачи, а выполнение продолжилось в фоновом режиме:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Сработало оповещение о моей службе. Уведоми группу WeChat «Команда AceDataCloud» через мой личный аккаунт WeChat..."
}
```

Пример ответа:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Затем можно использовать `action: retrieve` вместе с `id`, чтобы получить результат диалога. Также можно указать `callback_url`: после завершения задачи платформа отправит POST-запрос с данными `{ status, answer, usage, error }` на указанный адрес обратного вызова. `callback_url` должен использовать `http` / `https`, при этом нельзя напрямую указывать `localhost` или буквальный IP-адрес частной сети.

Для фоновых задач обычно нет человека, который мог бы нажать кнопку подтверждения. Если вы хотите, чтобы определённые Skill или MCP Server могли выполнять такие действия, как отправка, публикация и запись, в режиме без участия пользователя, явно передайте список предварительно авторизованных возможностей в теле запроса:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Сработало оповещение о моей службе. Уведоми группу WeChat «Команда AceDataCloud» через мой личный аккаунт WeChat..."
}
```

Значения в `allowed_skills` — это slug подключённых Skill; значения в `allowed_mcp_servers` — это slug подключённых MCP Server. Skill / MCP Server, не включённые в список предварительной авторизации, в режиме без участия пользователя по-прежнему смогут только предварительно просматривать действия, выполнять dry-run или отказываться от выполнения операций записи.

Для более детального управления также можно использовать эквивалентный объект `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Предварительная авторизация определяется непосредственно этими двумя списками: если список пуст, соответствующие возможности не авторизованы. Дополнительное поле-переключатель не требуется.

Обратите внимание: предварительная авторизация означает только то, что «в рамках текущего запроса этим возможностям разрешено пропускать подтверждение человеком в режиме без участия пользователя». При этом соответствующий Skill всё равно должен поддерживать `--unattended-confirm` или аналогичный механизм безопасности. В противном случае он продолжит выполнять только dry-run и не будет непосредственно выполнять операции записи.

## Возобновление приостановленных диалогов

Некоторые инструменты позволяют модели «задать пользователю уточняющий вопрос». В этом случае модель отправляет событие `ask_user_question`, а диалог переходит в замороженное состояние `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "На каком языке вы хотите создать отчёт — китайском или английском?",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

На стороне интерфейса отобразите это событие в виде карточки, чтобы пользователь мог выбрать ответ, а затем отправьте следующий запрос с тем же `id`, передав ответ обратно через `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

В теле запроса `tool_use_id` **обязательно** должен полностью совпадать с `tool_id` на момент приостановки; при несовпадении будет возвращена ошибка 400. Если в запросе одновременно присутствует `tool_results`, параметры `question` / `message` / `references` будут проигнорированы.

Если пользователь решит отказаться от этого вопроса, достаточно напрямую передать новый `question` / `message`, и платформа автоматически пометит приостановленный вызов инструмента как «пропущенный пользователем».

## Управление сессиями (CRUD)

В v2 для облегчённого управления сессиями используется поле `action` в том же endpoint, поэтому открывать отдельный API не требуется.

### `action: retrieve` —— Получение одной сессии

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Возвращается полный документ сессии (включая историю `messages`, `model`, `title`, `tools_used` и другие данные).

### `action: retrieve_batch` —— Получение списка кратких сведений о сессиях

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Возвращается `{ items: [...], total }`. **Краткие сведения не содержат `messages`**, поэтому подходят для отображения списка в боковой панели; если пользователь откроет определённую сессию, можно отдельно получить её полную историю сообщений с помощью `action: retrieve`.

Необязательные параметры фильтрации: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Изменение заголовка или перезапись истории

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "План путешествия по Ханчжоу"
}
```

Также можно передать `messages`, но сервер выполнит строгую проверку схемы (должен использоваться свёрнутый формат `ToolUseContent`), в противном случае будет возвращена ошибка 400. Обычно рекомендуется использовать этот метод только для изменения `title`.

### `action: delete` —— Удаление одной сессии

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Возвращается `{ id, success: true }`. После удаления восстановить сессию невозможно, поэтому перед вызовом необходимо убедиться в правильности действия.

## Плавный переход с v1

Если вы уже используете [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), переход на v2 практически не требует изменения кода:

1. Измените URL с `https://api.acedata.cloud/aichat/conversations` на `https://api.acedata.cloud/aichat2/conversations`.
2. Если ранее вы использовали названия моделей v1 (например, `gpt-3.5`, `gpt-4-browsing` и т. д.), при переходе на v2 рекомендуется обновить их до современных моделей (например, `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` и т. д.).
3. Поля потока NDJSON сохраняют обратную совместимость: каждое событие `text_delta` по-прежнему содержит `delta_answer` и `id`, поэтому клиентам, которые ранее разбирали `delta_answer` построчно, не требуется никаких изменений.

После миграции можно по мере необходимости включать новые возможности v2 (мультимодальный `message`, SSE, вызовы инструментов, CRUD через `action`) и постепенно внедрять их в удобном темпе.

## Обработка ошибок

Формат ответа с ошибкой унифицирован:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Распространённые ошибки:

- `400 bad_request`: отсутствуют обязательные поля, `tool_use_id` не совпадает, недопустимая схема `messages` и т. д.
- `401 invalid_token`: некорректный заголовок `authorization`.
- `404 not_found`: сессия, соответствующая `id`, не существует при выполнении `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: превышен лимит хранилища сессии, существующие сохранённые записи не перезаписаны.
- `429 too_many_requests`: превышено ограничение частоты запросов.
- `503 context_compaction_failed`: не удалось выполнить сжатие контекста, существующие записи сохранены.
- `500 conversation_persist_failed`: не удалось окончательно сохранить текущий запрос; получение текста не означает, что итоговая запись была успешно сохранена. Выполните запрос по ID сессии.
- `500 chat_error`: сервис временно недоступен или в текущем запросе не был сгенерирован контент (плата не взимается).

В потоковом ответе ошибки передаются в виде события `{"type":"error","message":"..."}`, после чего поток завершается. `[DONE]` означает только завершение передачи данных; при наличии `error` запрос нельзя считать успешным, и событие успешного завершения `done` отправлено не будет.

## Заключение

AI Chat v2 API, сохраняя обратную совместимость с v1, переводит диалог из формата «однораундовых / многораундовых вопросов и ответов» в формат «наблюдаемого диалога с использованием Agent»: мультимодальный ввод, вызовы инструментов, возможность приостановки / возобновления, структурированные потоковые события и встроенный CRUD. Для новых интеграций рекомендуется сразу использовать v2; существующие интеграции v1 можно постепенно и плавно перевести на новую версию. Если у вас возникнут вопросы, пожалуйста, обращайтесь в нашу службу технической поддержки.
