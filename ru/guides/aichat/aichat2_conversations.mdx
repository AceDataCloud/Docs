AI Chat v2 API (`/aichat2/conversations`) — это интерфейс диалогов нового поколения и полностью обновлённая версия [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). На основе лаконичного v1 с управляемыми многоходовыми диалогами он расширяет возможности:

- **Мультимодальный пользовательский ввод**: напрямую передавайте текст + изображения + файловые блоки через структурированное поле `message`, без необходимости косвенного прикрепления через `references`.
- **Вызовы инструментов в стиле Agent**: встроенный набор инструментов для поиска в интернете, извлечения веб-страниц, чтения файлов и т. д., а также возможность подключать авторизованные пользователем MCP-серверы (Google Drive, Notion, Slack, GitHub и т. д.); модель может самостоятельно вызывать инструменты в несколько раундов в рамках одного запроса для выполнения сложных задач.
- **Структурированные потоковые события**: через `accept: text/event-stream` или `application/x-ndjson` можно получать события `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` и другие на уровне отдельных токенов, что упрощает отдельный рендеринг соответствующих типов на фронтенде.
- **Возможность прерывания / возобновления**: когда модели требуется дополнительная информация от пользователя, она отправляет событие `ask_user_question` и приостанавливается; при следующем вызове можно передать ответ обратно через `tool_results`, чтобы продолжить.
- **Новые CRUD-действия**: используйте поле `action` на том же endpoint для выполнения `retrieve` / `retrieve_batch` / `update` / `delete`, без дополнительного API управления диалогами.
- **Постоянно обновляемый список моделей**: по умолчанию подключены современные модели, такие как GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 и другие.

При этом на уровне тела запроса он **полностью обратно совместим с v1**: достаточно передать `model` + `question` (+ опциональные `stateful` / `id` / `references` / `preset`), чтобы получить JSON-ответ `{answer, id}`, эквивалентный v1. Поэтому при миграции с `/aichat/conversations` не нужно переписывать клиент — достаточно заменить путь на `/aichat2/conversations`.

> Если вы сейчас используете `/aichat/conversations`, старый интерфейс продолжит обслуживаться, и вы можете мигрировать в удобном для вас темпе.

## Процесс подачи заявки

Чтобы использовать AI Chat v2 API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти; после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, не нужно подавать отдельную заявку для каждого сервиса.** При первом получении предоставляется бесплатный лимит для бесплатного тестирования; при недостатке лимита можно пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

## Базовое использование

Самый простой способ использования полностью совпадает с v1: передайте `model` + `question` и получите `{answer, id}`.

Пример CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Результат:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Пример Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

Доступные значения `model` можно увидеть непосредственно в выпадающем списке панели Try справа; распространённые категории включают:

## Многоходовые диалоги

Как и в v1, передайте `stateful: true`, чтобы включить сохранение диалога; API вернёт `id`; в последующих запросах передавайте этот `id`, чтобы продолжить диалог, без необходимости самостоятельно поддерживать историю messages.

Первый запрос:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Ответ:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Второй запрос, передайте тот же `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> Значение `stateful` по умолчанию — `true`; его пропуск эквивалентен явной передаче `true`. Если вы не хотите, чтобы сервер сохранял этот раунд диалога, можно явно установить `stateful: false`.

## Потоковый ответ

v2 поддерживает два формата потоковой передачи, выбираемых по заголовку `accept`:

| Сценарий                    | `accept`               | Формат данных                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Web-фронтенд / EventSource  | `text/event-stream`    | `data: {json}\n\n`, последняя строка — `data: [DONE]\n\n` |
| Сервер / CLI / потоковый парсинг Node | `application/x-ndjson` | Один JSON-объект в каждой строке                               |
| Потоковая передача не нужна                 | `application/json`（по умолчанию） | Однократно возвращает `{answer, id}`                       |

### Пример NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Каждая строка NDJSON является структурированным событием; наиболее распространённое — `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Пример SSE

Использование `EventSource` в браузере не поддерживает пользовательское тело запроса; рекомендуется использовать `fetch` + ручной разбор по фрагментам `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Типы потоковых событий

| `type`              | Значение                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `text_delta`        | Инкрементальный текстовый фрагмент ответа ассистента. `content` содержит новый контент; для совместимости с v1 то же событие также содержит `delta_answer` (равный `content`) и `id`.                  |
| `thinking`          | Процесс рассуждения модели (появляется только если выбранная модель предоставляет reasoning).                                                                |
| `tool_use`          | Модель решила вызвать инструмент; событие содержит `tool_id`, `tool_name`, `input`.                                                  |
| `tool_result`       | Результат выполнения инструмента; сопоставляется с предыдущим `tool_use` через `tool_id`, а `is_error` обозначает, произошла ли ошибка.                                       |
| `card`              | Структурированная карточка, созданная инструментом (например, изображение, предпросмотр ссылки), подходящая для прямого рендеринга.                                                                    |
| `citation`          | URL источника, используемый для дополнения ссылки на соответствующий текстовый фрагмент.                                                                            |
| `ask_user_question` | Отправляется, когда модели требуется, чтобы пользователь дополнил информацию; диалог переходит в состояние `awaiting_user_input`, см. ниже [Возобновление приостановленного диалога](#恢复暂停的对话)。                           |
| `artifact`          | Независимый артефакт, созданный моделью (например, блок кода, документ), который можно сохранить или скачать.                                                                      |
| `system_message`    | Системное информационное сообщение (не контент пользователя или ассистента), используется только для UI-подсказок.                                                                     |
| `compact`           | Событие сжатия внутреннего контекста, не требующее специальной обработки.                                                                             |
| `error`             | В этом раунде произошла ошибка; `message` описывает содержание ошибки.                                                                        |
| `done`              | Потоковый ответ завершён; содержит `usage` (включая `prompt_tokens` / `completion_tokens` / `total_tokens`) и `terminal_reason`. |

Для клиентов, которым важен только итоговый ответ, объединение `content` всех `text_delta` эквивалентно `answer` в режиме `application/json`.

## Мультимодальный ввод

Если пользовательский ввод содержит изображения или файлы, передавайте `message` (массив) вместо `question`. Каждый элемент массива является блоком контента:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Поддерживаемые типы блоков:

- `text` — обычный текст, обязательное поле `text`.
- `image_url` — изображение, обязательное поле `image_url.url`.
- `file_url` — файл (PDF, CSV, TXT и т. д.), обязательное поле `file_url.url`.

### Связь с `references` v1

Для совместимости со старыми клиентами v2 по-прежнему распознаёт поле `references: ["https://...", ...]`:
- Если суффикс URL — `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, автоматически преобразуется в блок `image_url`;
- Другие расширения преобразуются в блок `file_url`;
- Если одновременно предоставлен `question`, он добавляется перед ними как блок `text`.

Поэтому, если вы хотите только перейти с v1 и не хотите изменять тело запроса, достаточно заменить путь на `/aichat2/conversations`, исходное использование `references` продолжит работать как обычно.

Если нужен более точный контроль (например, размещать несколько изображений между текстом или если важен порядок), напрямую используйте массив `message`.

## Вызов инструментов и MCP

Основное улучшение v2 заключается в том, что модель может самостоятельно вызывать инструменты для выполнения многошаговых задач, **это включено по умолчанию**, и клиенту не нужно выполнять какую-либо дополнительную настройку в запросе. Распространённые сценарии:

- Пользователь спрашивает: «Помоги мне найти, какие новые выставки недавно проходят в Шанхае» → модель вызывает встроенный web search → упорядочивает результаты в ответ.
- Пользователь спрашивает: «Прочитай этот PDF и затем напиши краткое содержание» → модель вызывает file_read → пишет краткое содержание.
- Пользователь уже авторизовал Google Drive / GitHub / Notion и т. д. в [Connections](https://platform.acedata.cloud/connections) → модель может вызывать соответствующие MCP-инструменты для чтения и записи его данных.

В потоке NDJSON / SSE вызовы инструментов представлены двумя типами событий: `tool_use` и `tool_result`, например:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Если вы не хотите отображать во фронтенде подробности вызовов инструментов, просто игнорируйте события типов `tool_use` / `tool_result` / `card` / `citation`; итоговый вывод модели всё равно передаётся через поток `text_delta`.

`max_turns` может ограничивать максимальное число раундов самостоятельного вызова инструментов моделью в этом запросе, диапазон — 1–500, по умолчанию при пропуске — 500. Установка малого значения (например, `max_turns: 1`) может принудительно задать однократный ответ и запретить любые вызовы инструментов.

## Асинхронное выполнение и авторизация без участия пользователя

Если ваш вызов поступает из Webhook предупреждений, CI/CD, системы мониторинга или других фоновых задач, можно установить `async: true`, чтобы интерфейс немедленно вернул ID задачи, а выполнение продолжилось в фоне:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Мой сервис выдал предупреждение, уведомь группу WeChat «AceDataCloud团队» через личный WeChat……"
}
```

Пример ответа:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

После этого можно использовать `action: retrieve` + `id` для запроса результата беседы; также можно указать `callback_url`, и после завершения задачи платформа отправит `{ status, answer, usage, error }` методом POST на ваш адрес обратного вызова. `callback_url` должен использовать `http` / `https` и не может напрямую указывать `localhost` или литеральный адрес частного IP.

У фоновых задач обычно нет человека, который может нажать подтверждение. Если вы хотите, чтобы некоторые Skill или MCP Server выполняли действия отправки, публикации, записи и т. д. в режиме без участия пользователя, явно передайте список предварительной авторизации в теле запроса:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Мой сервис выдал предупреждение, уведомь группу WeChat «AceDataCloud团队» через личный WeChat……"
}
```

Значения в `allowed_skills` — это slug подключённых Skill; значения в `allowed_mcp_servers` — это slug подключённых MCP Server. Skill / MCP Server, не включённые в предварительную авторизацию, в режиме без участия пользователя по-прежнему могут только выполнять предварительный просмотр, dry-run или отказываться от выполнения операций записи.

Если требуется более детальный контроль, также можно использовать эквивалентный объект `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Предварительная авторизация — это сами эти два списка: пустой список означает, что никакие возможности не авторизованы, дополнительное поле-переключатель не требуется.

Обратите внимание: предварительная авторизация означает только «этому запросу разрешено пропускать ручное подтверждение для этих возможностей в режиме без участия пользователя». Конкретный Skill всё равно должен поддерживать `--unattended-confirm` или соответствующий механизм безопасности; в противном случае он продолжит выполнять dry-run и не будет напрямую выполнять операции записи.

## Возобновление приостановленных бесед

Некоторые инструменты заставляют модель «задать пользователю встречный вопрос»; в этот момент модель отправляет событие `ask_user_question`, а беседа замораживается в состоянии `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Вы хотите, чтобы сгенерированный отчёт был на китайском или английском?",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Во фронтенде отрисуйте это событие как карточку, чтобы пользователь выбрал ответ, затем отправьте следующий запрос с тем же `id`, передав ответ обратно через `tool_results`:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

`tool_use_id` в теле запроса **должен** полностью совпадать с `tool_id` на момент приостановки; при несовпадении будет возвращён 400. Когда в запросе одновременно присутствует `tool_results`, `question` / `message` / `references` будут проигнорированы.

Если пользователь решает отказаться от этого вопроса, просто передайте новый `question` / `message`, платформа автоматически пометит приостановленный вызов инструмента как «пропущен пользователем».

## Управление беседами (CRUD)

v2 предоставляет облегчённое управление беседами через поле `action` в том же endpoint, без необходимости открывать отдельный API.
### `action: retrieve` —— Получение беседы

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Возвращает полный документ беседы (включая историю `messages`, `model`, `title`, `tools_used` и т. д.).

### `action: retrieve_batch` —— Вывод сводок бесед

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Возвращает `{ items: [...], total }`. **Сводки не содержат `messages`**, поэтому подходят для списка на боковой панели; если пользователь открывает какую-либо беседу, затем используйте `action: retrieve`, чтобы отдельно получить её полные сообщения.

Необязательные параметры фильтрации: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Изменение заголовка или перезапись истории

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "План поездки в Ханчжоу"
}
```

Также можно передать `messages`, но сервер выполнит строгую проверку schema (обязательно должна быть свёрнутая форма `ToolUseContent`); при несоответствии будет возвращён код 400. Как правило, рекомендуется использовать это только для изменения `title`.

### `action: delete` —— Удаление беседы

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Возвращает `{ id, success: true }`. После удаления восстановление невозможно, подтвердите перед вызовом.

## Плавная миграция с v1

Если вы уже используете [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), миграция на v2 почти не требует изменения кода:

1. Измените URL с `https://api.acedata.cloud/aichat/conversations` на `https://api.acedata.cloud/aichat2/conversations`.
2. Если ранее вы передавали имя модели v1 (например, `gpt-3.5`, `gpt-4-browsing` и т. д.), при переходе на v2 рекомендуется обновиться до современных моделей (например, `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` и т. д.).
3. Поля потока NDJSON сохраняют обратную совместимость: каждое событие `text_delta` по-прежнему содержит `delta_answer` и `id`, поэтому клиентам, которые ранее построчно разбирали `delta_answer`, не нужно ничего менять.

После миграции можно по необходимости включать новые возможности v2 (мультимодальные `message`, SSE, вызов инструментов, CRUD через `action`) и внедрять их в удобном темпе.

## Обработка ошибок

Ответы с ошибками имеют единый формат:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Распространённые ошибки:

- `400 bad_request`: отсутствуют обязательные поля, не совпадает `tool_use_id`, schema `messages` недопустима и т. д.
- `401 invalid_token`: заголовок `authorization` указан неверно.
- `404 not_found`: при `action: retrieve / update / delete` беседа, соответствующая `id`, не существует.
- `429 too_many_requests`: сработало ограничение скорости.
- `500 chat_error`: ошибка вышестоящей LLM или в текущем раунде `completion_tokens=0` (обрабатывается как неиспользованный запрос, плата не взимается).

В потоковом ответе ошибка отправляется как событие `{"type":"error","message":"..."}`, после чего поток сразу завершается.

## Заключение

AI Chat v2 API, сохраняя обратную совместимость с v1, переводит диалог от «одиночных / многораундовых вопросов и ответов» к «наблюдаемому Agent-диалогу»: мультимодальный ввод, вызовы инструментов, возможность приостановки / возобновления, потоковые структурированные события, встроенный CRUD. Для новых интеграций рекомендуется сразу использовать v2; существующие интеграции v1 могут плавно мигрировать поэтапно. Если у вас возникнут какие-либо вопросы, пожалуйста, свяжитесь с нашей командой технической поддержки в любое время.
