AI Chat v2 API (`/aichat2/conversations`) — это интерфейс нового поколения для диалогов, представляющий собой комплексно обновлённую версию [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). На основе лаконичности v1 и управляемых многораундовых диалогов он расширяет возможности:

- **Мультимодальный пользовательский ввод**: напрямую передавайте текст + изображения + файловые блоки через структурированное поле `message`, без необходимости предварительно косвенно прикреплять их через `references`.
- **Вызов инструментов в Agent-режиме**: встроен набор инструментов для поиска в интернете, извлечения веб-страниц, чтения файлов и т. д., а также можно подключать авторизованные пользователем MCP-серверы (Google Drive, Notion, Slack, GitHub и т. д.). Модель может в рамках одного запроса самостоятельно многократно вызывать инструменты для выполнения сложных задач.
- **Структурированные потоковые события**: через `accept: text/event-stream` или `application/x-ndjson` можно получать события `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` и другие для каждого токена, что удобно для отдельного рендеринга соответствующих типов на фронтенде.
- **Возможность прерывания / возобновления**: когда модели требуется дополнительная информация от пользователя, она отправляет событие `ask_user_question` и приостанавливается; при следующем вызове можно продолжить работу, передав ответ через `tool_results`.
- **Новые CRUD-действия**: через поле `action` на том же endpoint можно выполнять `retrieve` / `retrieve_batch` / `update` / `delete` без необходимости в дополнительном API для управления диалогами.
- **Постоянно обновляемый список моделей**: по умолчанию подключены современные модели, такие как GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 и другие.

При этом на уровне тела запроса он **полностью обратно совместим с v1**: достаточно передать только `model` + `question` (+ опционально `stateful` / `id` / `references` / `preset`), чтобы получить JSON-ответ `{answer, id}`, эквивалентный v1. Поэтому при миграции с `/aichat/conversations` не нужно переписывать клиент — достаточно изменить путь на `/aichat2/conversations`.

> Если вы сейчас используете `/aichat/conversations`, старый интерфейс продолжит обслуживаться, и вы можете мигрировать в удобном для вас темпе.

## Процесс подачи заявки

Чтобы использовать AI Chat v2 API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти; после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, не нужно подавать отдельную заявку для каждого сервиса.** При первой заявке предоставляется бесплатный лимит, позволяющий бесплатно опробовать сервис; если лимита недостаточно, можно пополнить универсальный баланс в [консоли](https://platform.acedata.cloud/console/coin).

## Базовое использование

Самый простой способ использования полностью совпадает с v1: передайте `model` + `question` и получите `{answer, id}`.

Пример CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Возвращаемый результат:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Пример Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

Доступные значения `model` можно увидеть непосредственно в выпадающем списке панели Try справа; распространённые категории включают:

## Многораундовый диалог

Как и в v1, передайте `stateful: true`, чтобы включить сохранение диалога. API вернёт `id`; в последующих запросах достаточно передавать этот `id`, чтобы продолжить диалог, без необходимости самостоятельно поддерживать историю messages.

Первый запрос:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Возвращает:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Второй запрос — передайте тот же `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> По умолчанию `stateful` имеет значение `true`; его пропуск эквивалентен явной передаче `true`. Установка `stateful: false` пропускает загрузку предыдущей истории сеанса; это не означает, что результаты текущего раунда не будут сохранены, и не применяется к процессам с инструментами, которые необходимо продолжить после приостановки.

### Длинные сеансы и сохранение исходного текста

Сжатие контекста упорядочивает только содержимое, отправляемое модели в текущем раунде, и не заменяет уже сохранённые записи чата. Полные сохранённые сообщения по-прежнему можно прочитать через `action: retrieve`; явное редактирование и удаление сеанса также выполняются согласно запросу.

Модель может находить и постранично читать исходный текст истории в текущем сеансе. Когда необходимо продолжить редактирование статьи, процитировать числа или подготовить публикацию, следует прочитать соответствующий исходный текст; нельзя заменять основной текст сводкой. Эта возможность не восстанавливает автоматически сообщения, уже потерянные в старых версиях.

Если упорядочивание контекста завершилось неудачей, сохраните ID сеанса и проверьте событие `error`; сервис не заменит исходный текст пустой сводкой. Операции с инструментами, завершённые до ошибки, могут по-прежнему быть действительными; сначала запросите их результат, чтобы избежать повторной генерации или повторной публикации. При достижении лимита хранения одним сеансом будет возвращена явная ошибка; для освобождения места существующие сохранённые записи не будут обрезаны; после экспорта необходимого содержимого можно начать новый сеанс.

## Потоковые ответы

v2 поддерживает два формата потоковой передачи, выбираемых по заголовку `accept`:

| Сценарий                    | `accept`               | Формат данных                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Веб-фронтенд / EventSource  | `text/event-stream`    | `data: {json}\n\n`, последняя строка `data: [DONE]\n\n` |
| Сервер / CLI / потоковый парсинг Node | `application/x-ndjson` | Один объект JSON в строке                               |
| Потоковая передача не требуется                 | `application/json`（по умолчанию） | Однократный возврат `{answer, id}`                       |

### Пример NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Каждая строка NDJSON является структурированным событием; наиболее распространённое — `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Пример SSE

`EventSource` в браузере не поддерживает пользовательское тело запроса, рекомендуется использовать `fetch` + ручной разбор по фрагментам `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Типы потоковых событий

| `type`              | Значение                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Инкрементальный текстовый фрагмент ответа ассистента. `content` содержит новый контент; для совместимости с v1 то же событие также содержит `delta_answer` (равный `content`) и `id`.                                        |
| `thinking`          | Процесс рассуждений модели (появляется только если выбранная модель раскрывает reasoning).                                                                                      |
| `tool_use`          | Модель решила вызвать инструмент; событие содержит `tool_id`, `tool_name`, `input`.                                                                        |
| `tool_result`       | Результат выполнения инструмента; сопоставляется с предыдущим `tool_use` через `tool_id`, а `is_error` указывает, произошла ли ошибка.                                                             |
| `card`              | Структурированная карточка, созданная инструментом (например, изображение, предпросмотр ссылки), подходящая для прямого рендеринга.                                                                                          |
| `citation`          | URL источника, используемый для дополнения ссылки на соответствующий текстовый фрагмент.                                                                                                  |
| `ask_user_question` | Отправляется, когда модели требуется дополнительная информация от пользователя; диалог переходит в состояние `awaiting_user_input`, см. ниже [Возобновление приостановленного диалога](#возобновление-приостановленного-диалога).                                                 |
| `artifact`          | Независимый артефакт, созданный моделью (например, блок кода, документ), который можно сохранить или скачать.                                                                                            |
| `system_message`    | Системное информационное сообщение (не содержимое пользователя или ассистента), используется только для подсказок в UI.                                                                                           |
| `compact`           | Контекст модели был упорядочен; сохранённые исходные сообщения остаются неизменными, клиенту не нужно удалять записи чата.                                                                                    |
| `error`             | В текущем раунде произошла ошибка; `message` описывает её содержимое.                                                                                              |
| `done`              | Итоговая запись сеанса текущего раунда успешно сохранена; содержит `usage` (включая `prompt_tokens` / `completion_tokens` / `total_tokens`) и `terminal_reason`; всё равно необходимо определять завершение задачи по причине завершения. |
Для клиентов, которым важен только окончательный ответ, объединение всех `content` из `text_delta` эквивалентно `answer` в режиме `application/json`.

## Мультимодальный ввод

Если ввод пользователя содержит изображения или файлы, передавайте `message` (массив) вместо `question`. Каждый элемент массива является блоком содержимого:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Поддерживаемые типы блоков:

- `text` — обычный текст, поле `text` обязательно.
- `image_url` — изображение, `image_url.url` обязательно.
- `file_url` — файл (PDF, CSV, TXT и т. д.), `file_url.url` обязательно.

### Связь с v1 `references`

Для совместимости со старыми клиентами v2 по-прежнему распознаёт поле `references: ["https://...", ...]`:

- Если суффикс URL — `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, автоматически преобразуется в блок `image_url`;
- Другие расширения преобразуются в блок `file_url`;
- Если одновременно предоставлен `question`, он добавляется в начало как блок `text`.

Поэтому, если вы хотите только перейти с v1 и не менять тело запроса, достаточно изменить путь на `/aichat2/conversations`, а исходное использование `references` продолжит работать как обычно.

Если нужен более точный контроль (например, разместить несколько изображений между текстом или если порядок важен), используйте напрямую массив `message`.

## Вызов инструментов и MCP

Ключевое улучшение v2 состоит в том, что модель может самостоятельно вызывать инструменты для выполнения многошаговых задач, **это включено по умолчанию**, и клиенту не требуется делать какую-либо дополнительную настройку в запросе. Типичные сценарии:

- Пользователь спрашивает: «Помоги найти, какие новые выставки недавно появились в Шанхае» → модель вызывает встроенный web search → оформляет результаты в ответ.
- Пользователь спрашивает: «Прочитай этот PDF и напиши краткое содержание» → модель вызывает file_read → пишет краткое содержание.
- Пользователь уже авторизовал Google Drive / GitHub / Notion и т. д. в [Connections](https://platform.acedata.cloud/connections) → модель может вызывать соответствующие MCP-инструменты для чтения и записи их данных.

В потоках NDJSON / SSE вызовы инструментов представлены двумя типами событий: `tool_use` и `tool_result`, например:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Если вы не хотите отображать во фронтенде детали вызовов инструментов, просто игнорируйте события типов `tool_use` / `tool_result` / `card` / `citation`; итоговый вывод модели по-прежнему передаётся потоком через `text_delta`.

`max_turns` может ограничить максимальное количество раундов самостоятельного вызова инструментов моделью в этом запросе; диапазон — 1–500, по умолчанию при отсутствии параметра — 500. Установка малого значения (например, `max_turns: 1`) может принудительно задать однократный ответ и запретить любые вызовы инструментов.

## Асинхронное выполнение и авторизация без участия пользователя

Если ваш вызов поступает из Webhook оповещений, CI/CD, системы мониторинга или других фоновых задач, можно установить `async: true`, чтобы интерфейс немедленно вернул ID задачи, а выполнение продолжилось в фоне:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Пример ответа:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

После этого можно использовать `action: retrieve` + `id` для запроса результата диалога; также можно указать `callback_url`, и после завершения задачи платформа отправит `{ status, answer, usage, error }` методом POST на ваш адрес обратного вызова. `callback_url` должен использовать `http` / `https` и не может напрямую содержать `localhost` или литеральный адрес частного IP.

В фоновых задачах обычно некому нажать подтверждение. Если вы хотите, чтобы некоторые Skill или MCP Server выполняли действия отправки, публикации, записи и т. д. в режиме без участия пользователя, явно передайте в теле запроса список предварительной авторизации:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Значения в `allowed_skills` — slug подключённых Skill; значения в `allowed_mcp_servers` — slug подключённых MCP Server. Не включённые в предварительную авторизацию Skill / MCP Server в режиме без участия пользователя по-прежнему могут только выполнять предварительный просмотр, dry-run или отказываться от операций записи.

Если нужен более детальный контроль, также можно использовать эквивалентный объект `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Предварительная авторизация — это сами эти два списка: пустой список означает отсутствие авторизации для любых возможностей, без необходимости в дополнительном поле переключателя.

Обратите внимание: предварительная авторизация означает только, что «в этом запросе этим возможностям разрешено пропустить ручное подтверждение в режиме без участия пользователя». Конкретный Skill всё равно должен поддерживать `--unattended-confirm` или соответствующий механизм безопасности; в противном случае он продолжит выполнять dry-run и не будет напрямую выполнять операции записи.

## Возобновление приостановленных диалогов

Некоторые инструменты могут заставить модель «задать встречный вопрос пользователю». В этом случае модель отправляет событие `ask_user_question`, а диалог замораживается в состоянии `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

Отобразите это событие во фронтенде в виде карточки, чтобы пользователь выбрал ответ, затем отправьте следующий запрос с тем же `id`, передав ответ обратно через `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

В теле запроса `tool_use_id` **обязательно** должен полностью совпадать с `tool_id` на момент приостановки; при несовпадении будет возвращён 400. Когда в запросе одновременно присутствует `tool_results`, `question` / `message` / `references` будут проигнорированы.

Если пользователь решает отказаться от этого вопроса, достаточно напрямую передать новый `question` / `message`, и платформа автоматически пометит приостановленный вызов инструмента как «пропущен пользователем».

## Управление сессиями (CRUD)

v2 предоставляет облегчённое управление сессиями через поле `action` на том же endpoint, без необходимости открывать отдельный API.

### `action: retrieve` —— получение одной сессии

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Возвращает полный документ сессии (включая историю `messages`, `model`, `title`, `tools_used` и т. д.).

### `action: retrieve_batch` —— вывод сводок сессий

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Возвращает `{ items: [...], total }`. **Сводки не содержат `messages`**, что подходит для списка в боковой панели; если пользователь открывает определённую сессию, затем используйте `action: retrieve`, чтобы отдельно получить её полные сообщения.

Необязательные параметры фильтрации: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— изменение заголовка или перезапись истории

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

Также можно передать `messages`, но сервер выполнит строгую проверку schema (они обязательно должны иметь свёрнутую форму `ToolUseContent`); при несоответствии будет возвращён 400. Как правило, рекомендуется использовать это только для изменения `title`.

### `action: delete` —— удаление одной сессии

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Возвращает `{ id, success: true }`. После удаления восстановление невозможно, пожалуйста, подтвердите перед вызовом.

## Плавная миграция с v1

Если вы уже используете [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), миграция на v2 практически не потребует изменения кода:

1. Измените URL с `https://api.acedata.cloud/aichat/conversations` на `https://api.acedata.cloud/aichat2/conversations`.
2. Если ранее вы передавали имя модели v1 (например, `gpt-3.5`, `gpt-4-browsing` и т. д.), при переходе на v2 рекомендуется обновиться до современных моделей (например, `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` и т. д.).
3. Поля NDJSON-потока сохраняют обратную совместимость: каждое событие `text_delta` по-прежнему содержит `delta_answer` и `id`, поэтому клиентам, изначально построчно разбирающим `delta_answer`, не требуется вносить изменения.

После миграции можно по мере необходимости включать новые возможности v2 (мультимодальный `message`, SSE, вызовы инструментов, CRUD через `action`) и внедрять их в удобном темпе.

## Обработка ошибок

Ответы с ошибками имеют единый формат:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Распространённые ошибки:

- `400 bad_request`: отсутствуют обязательные поля, `tool_use_id` не совпадает, schema `messages` недопустима и т. д.
- `401 invalid_token`: заголовок `authorization` указан неверно.
- `404 not_found`: сессия, соответствующая `id`, не существует при `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: сессия превысила лимит хранения, существующая сохранённая запись не была перезаписана.
- `429 too_many_requests`: сработало ограничение частоты запросов.
- `503 context_compaction_failed`: не удалось выполнить уплотнение контекста, существующие записи сохранены.
- `500 conversation_persist_failed`: не удалось выполнить окончательное сохранение в этом раунде; уже полученный текст не означает, что итоговая запись успешно сохранена, пожалуйста, выполните запрос по ID сессии.
- `500 chat_error`: сервис временно недоступен либо в этом раунде не был сгенерирован контент (плата не взимается).

В потоковом ответе ошибка отправляется как событие `{"type":"error","message":"..."}`, после чего поток завершается. `[DONE]` означает только завершение передачи; при наличии `error` это нельзя считать успехом, и успешное событие `done` также не будет отправлено.

## Заключение

AI Chat v2 API, сохраняя обратную совместимость с v1, переводит диалоги от «одиночных / многораундовых вопросов и ответов» к «наблюдаемым Agent-диалогам»: мультимодальный ввод, вызовы инструментов, возможность приостановки / возобновления, потоковые структурированные события, встроенный CRUD. Для новых интеграций рекомендуется сразу использовать v2; существующие интеграции v1 могут плавно мигрировать поэтапно. Если у вас возникнут какие-либо вопросы, пожалуйста, свяжитесь с нашей командой технической поддержки в любое время.
