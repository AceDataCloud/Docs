Основная функция API запроса задач Maestro — по ID задачи, возвращённому [API генерации видео Maestro](/ru/guides/maestro/maestro_videos) (`POST /maestro/videos`), запрашивать статус выполнения и окончательный результат этой задачи.

В этом документе будет подробно описана интеграция API запроса задач Maestro. Поскольку генерация видео является асинхронной задачей, после отправки необходимо использовать этот интерфейс для опроса и получения прогресса и готового видео, **опрос бесплатный и не расходует баллы.**

`POST https://api.acedata.cloud/maestro/tasks`

## Процесс получения

Чтобы использовать API запроса задач Maestro, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications), чтобы получить ваш API Token и сохранить его для последующего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти в систему, после чего вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первом получении предоставляется бесплатный лимит, позволяющий бесплатно ознакомиться с сервисом; при недостатке лимита вы можете пополнить универсальный баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [API запроса задач Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Запрос одной задачи

О том, как создать задачу видео, смотрите документацию [API генерации видео Maestro](/ru/guides/maestro/maestro_videos). В качестве примера возьмём один из возвращённых им ID задач: `f57e99c4f60f4373a15517742ce2357d`, и покажем, как запросить его статус и результат.

### Настройка заголовков и тела запроса

**Request Headers** включают:

- `accept`: указывает получение результата ответа в формате JSON, здесь указывается `application/json`.
- `authorization`: ключ для вызова API, после получения можно напрямую выбрать из выпадающего списка.
- `content-type`: формат тела запроса, здесь указывается `application/json`.

**Request Body** включает:

| Поле       | Тип     | Обязательно при | Описание                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | Обязательно при запросе одной задачи | `task_id`, возвращаемый `POST /maestro/videos`              |
| `action` | string | Нет         | `retrieve` (по умолчанию, запрос одной задачи); при запросе списка истории фиксировано как `retrieve_batch` |

### Пример кода

Соответствующий CURL-код выглядит следующим образом:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Соответствующий Python-код выглядит следующим образом:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```


Описание полей результата ответа приведено ниже:

- `id`: ID этой задачи видео, используется для уникальной идентификации данной задачи генерации видео.
- `status`: статус задачи, возможные значения: `pending → planning → producing → succeeded` (или `failed`). Завершена ли задача, определяется по этому верхнеуровневому `status`.
- `elapsed`: затраченное задачей время (секунды).
- `progress`: верхнеуровневый объект прогресса, `percent` (0–100) после успешного выполнения задачи будет гарантированно равен 100; `stage` и `message` отражают последнее событие прогресса AI-режиссёра (поэтому после успеха `stage` всё ещё может быть последним этапом выполнения, например `producing`), и могут напрямую использоваться для отображения индикатора прогресса.
- `request`: тело запроса при запуске задачи.
- `response`: информация ответа задачи.
  - `success`: успешно ли выполнена задача.
  - `data.variants`: содержит объект готового видео на выбранном языке, включая `lang`, `aspect`, `title`, `output_url` (адрес скачивания готового видео) и другое.
  - `data.project`: результаты всего проекта, включая `tarball_url` (пакет проекта) и `outputs` (ссылки на готовые видео).
  - `data.progress`: массив событий прогресса, добавляемых по этапам (журнал только для добавления), может использоваться для отображения подробного прогресса в реальном времени.
- `created_at`: время создания задачи, Unix-временная метка (секунды).
- `started_at`: время начала выполнения задачи, Unix-временная метка (секунды). До начала выполнения задачи имеет значение null.
- `finished_at`: время завершения задачи, Unix-временная метка (секунды). До завершения задачи имеет значение null.

## Запрос списка истории

Передайте `action: retrieve_batch`, чтобы получить последние задачи текущего вошедшего исполнителя (в обратном порядке по времени создания); это можно использовать для страницы списка «Мои видео». Список истории изолирован по учётной записи входа.

**Request Body** включает:

| Поле               | Тип     | Обязательно  | Описание                              |
| ---------------- | ------ | --- | ------------------------------- |
| `action`         | string | Да   | Фиксировано как `retrieve_batch`            |
| `limit`          | int    | Нет   | Количество возвращаемых записей, по умолчанию 20; допустимый диапазон: 1–100          |
| `created_at_max` | int    | Нет   | Возвращать только задачи, созданные строго раньше этой Unix-временной метки (без граничного значения, для постраничного перехода) |
| `created_at_min` | int    | Нет   | Возвращать только задачи, созданные строго позже этой Unix-временной метки (без граничного значения)     |

### Пример кода

Соответствующий CURL-код выглядит следующим образом:
```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

## Рекомендации по опросу

Поскольку производство видео занимает длительное время, `status` будет проходить через `pending → planning → producing → succeeded`（или `failed`）。Рекомендуется выполнять опрос каждые 5–10 секунд, пока `status` не станет `succeeded` или `failed`。Для отображения индикатора прогресса в реальном времени можно использовать `progress.percent` верхнего уровня。**Опрос этого интерфейса бесплатен и не расходует баллы。**

## Обработка ошибок

При вызове API, если возникает ошибка, API вернёт соответствующий код ошибки и информацию. Например:

- `401 invalid_token`：Не авторизован, недействительный или отсутствующий токен авторизации.
- `404 not_found`：Задача не найдена, указанный task_id не существует.
- `429 too_many_requests`：Слишком много запросов, вы превысили лимит запросов.
- `500 api_error`：Внутренняя ошибка сервера, на сервере произошла ошибка.

### Пример ответа с ошибкой

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
