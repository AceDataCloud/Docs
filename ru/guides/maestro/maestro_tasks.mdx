Основная функция API запроса задач Maestro заключается в использовании ID задачи, возвращаемого [API генерации видео Maestro](development_maestro_videos.md) (`POST /maestro/videos`), для запроса статуса выполнения и конечного результата этой задачи.

В этом документе будет подробно представлено руководство по интеграции API запроса задач Maestro. Поскольку генерация видео является асинхронной задачей, после отправки необходимо использовать этот интерфейс для опроса и получения прогресса и готового видео, **опрос бесплатный и не расходует баллы.**

`POST https://api.acedata.cloud/maestro/tasks`

## Процесс подачи заявки

Чтобы использовать API запроса задач Maestro, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа с приглашением зарегистрироваться и войти в систему, после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первой заявке будет предоставлен бесплатный лимит для бесплатного ознакомления; при недостатке лимита можно пополнить универсальный баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [API запроса задач Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Запрос одной задачи

О том, как создать задачу генерации видео, см. документацию [API генерации видео Maestro](development_maestro_videos.md). Мы используем в качестве примера один из возвращаемых ею ID задач: `f57e99c4f60f4373a15517742ce2357d`, чтобы продемонстрировать, как запросить его статус и результат.

### Настройка заголовков запроса и тела запроса

**Request Headers** включают:

- `accept`: указывает получение результатов ответа в формате JSON, здесь указывается `application/json`.
- `authorization`: ключ для вызова API, после подачи заявки его можно напрямую выбрать из выпадающего списка.
- `content-type`: формат тела запроса, здесь указывается `application/json`.

**Request Body** включает:

| Поле       | Тип     | Обязательно        | Описание                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | Обязательно при запросе одной задачи | `task_id`, возвращаемый `POST /maestro/videos`              |
| `action` | string | Нет         | `retrieve` (по умолчанию, запрос одной задачи); при запросе списка истории фиксированно используется `retrieve_batch` |

### Пример кода

Соответствующий CURL-код выглядит следующим образом:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Соответствующий Python-код выглядит следующим образом:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Описание полей возвращаемого результата следующее:

- `id`: ID этой задачи генерации видео, используется для уникальной идентификации данной задачи генерации видео.
- `status`: статус задачи, значения: `pending → planning → producing → succeeded` (или `failed`). Завершена ли задача, определяется по этому верхнеуровневому `status`.
- `elapsed`: уже затраченное задачей время (секунды).
- `progress`: верхнеуровневый объект прогресса, `percent` (0–100) после успешного выполнения задачи будет принудительно установлен в 100; `stage` и `message` отражают последнее событие прогресса AI-режиссёра (поэтому после успеха `stage` всё ещё может быть последним этапом выполнения, например `producing`), и могут напрямую использоваться для отображения индикатора прогресса.
- `request`: тело запроса при запуске задачи.
- `response`: возвращаемая информация задачи.
  - `success`: успешно ли выполнена задача.
  - `data.variants`: каждому языку соответствует один объект готового видео, содержащий `lang`, `aspect`, `title`, `output_url` (адрес скачивания готового видео) и т. д.
  - `data.project`: результат всего проекта, содержащий `tarball_url` (пакет проекта) и `outputs` (все ссылки на готовые видео).
  - `data.progress`: массив событий прогресса, добавляемых по этапам (append-only журнал), который может использоваться для отображения подробного прогресса в реальном времени.
- `created_at`: время создания задачи, Unix-временная метка (секунды).
- `started_at`: время начала выполнения задачи, Unix-временная метка (секунды). Пока задача не началась, равно null.
- `finished_at`: время завершения задачи, Unix-временная метка (секунды). Пока задача не завершена, равно null.

## Запрос списка истории

Передайте `action: retrieve_batch`, чтобы получить последние задачи текущего вошедшего исполнителя (в обратном порядке по времени создания), что можно использовать для страницы списка «Мои видео». Список истории изолирован по личности входа в систему.

**Request Body** включает:
| Поле               | Тип     | Обязательно  | Описание                              |
| ---------------- | ------ | --- | ------------------------------- |
| `action`         | string | Да   | Фиксированное значение: `retrieve_batch`            |
| `limit`          | int    | Нет   | Количество возвращаемых записей, по умолчанию 20; допустимый диапазон — 1–100          |
| `created_at_max` | int    | Нет   | Возвращать только задачи, созданные строго раньше этой Unix-метки времени (без граничного значения, для постраничного вывода) |
| `created_at_min` | int    | Нет   | Возвращать только задачи, созданные строго позже этой Unix-метки времени (без граничного значения)     |

### Пример кода

Соответствующий CURL-код выглядит следующим образом:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

## Рекомендации по опросу

Поскольку производство видео занимает длительное время, `status` будет проходить через `pending → planning → producing → succeeded` (или `failed`). Рекомендуется выполнять опрос каждые 5–10 секунд, пока `status` не станет `succeeded` или `failed`. Для отображения индикатора выполнения в реальном времени можно использовать верхнеуровневый `progress.percent`. **Опрос этого интерфейса бесплатен и не расходует баллы.**

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и сообщение. Например:

- `401 invalid_token`：Не авторизован, недействительный или отсутствующий токен авторизации.
- `404 not_found`：Задача не найдена, указанный task_id не существует.
- `429 too_many_requests`：Слишком много запросов, вы превысили лимит частоты запросов.
- `500 api_error`：Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
