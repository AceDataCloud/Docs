Основная функция Maestro задача запрос API заключается в том, чтобы по ID задачи, возвращенному [Maestro видео генерация API](development_maestro_videos.md) (`POST /maestro/videos`), запросить статус выполнения этой задачи и конечный результат.

В этом документе подробно описывается интеграция Maestro задача запрос API. Поскольку генерация видео является асинхронной задачей, после отправки необходимо использовать этот интерфейс для опроса прогресса и готового видео, **опрос бесплатный, не расходует баллы.**

`POST https://api.acedata.cloud/maestro/tasks`

## Процесс подачи заявки

Чтобы использовать Maestro задача запрос API, сначала перейдите в [Ace Data Cloud консоль](https://platform.acedata.cloud/console/applications) и получите ваш API Token для резервного копирования.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Если вы еще не вошли в систему или не зарегистрированы, вы будете автоматически перенаправлены на страницу входа, где вас пригласят зарегистрироваться и войти в систему, после чего вы будете автоматически возвращены на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, не нужно запрашивать отдельно для каждого сервиса.** При первом запросе предоставляется бесплатный лимит, чтобы вы могли попробовать; при недостатке лимита можно пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Maestro задача запрос API →](https://platform.acedata.cloud/documents/maestro-tasks)

## Запрос одной задачи

О том, как создать видео задачу, смотрите документацию [Maestro видео генерация API](development_maestro_videos.md). Мы возьмем один ID задачи, возвращенный им: `f57e99c4f60f4373a15517742ce2357d`, и продемонстрируем, как запросить его статус и результат.

### Установка заголовков запроса и тела запроса

**Request Headers** включает:

- `accept`: указывает на прием ответа в формате JSON, здесь указывается `application/json`.
- `authorization`: ключ для вызова API, после запроса можно выбрать из выпадающего списка.
- `content-type`: формат тела запроса, здесь указывается `application/json`.

**Request Body** включает:

| Поле       | Тип     | Обязательное | Описание                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | Да        | `task_id`, возвращенный `POST /maestro/videos`              |
| `action` | string | Нет       | `retrieve` (по умолчанию, запрос одной задачи) / `retrieve_batch` (запрос списка исторических задач) |

### Пример кода

Соответствующий CURL код выглядит следующим образом:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Соответствующий Python код выглядит следующим образом:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Пример ответа

После успешного запроса API вернет статус и результат этого видео задания. Пример ответа, когда задача завершена, выглядит следующим образом (каждый язык соответствует одному `variant`):

```json
{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "status": "succeeded",
  "elapsed": 312,
  "progress": { "percent": 100, "stage": "producing", "message": "rendering scene 2" },
  "request": {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": ["zh-cn", "en"],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        { "lang": "zh-cn", "aspect": "9:16", "kind": "video", "title": "什么是向量数据库", "output_url": "https://…/zh.mp4" },
        { "lang": "en", "aspect": "9:16", "kind": "video", "title": "What is a vector database", "output_url": "https://…/en.mp4" }
      ],
      "project": { "tarball_url": "https://…/project.tar.gz", "outputs": ["https://…/zh.mp4", "https://…/en.mp4"] },
      "percent": 100,
      "stage": "producing",
      "progress": [ { "stage": "producing", "message": "rendering scene 2", "pct": 60, "t": 1750000000 } ]
    }
  }
}
```

Описание полей возвращаемого результата:

- `id`: ID этого видео задания, используемый для уникальной идентификации текущей задачи генерации видео.
- `status`: статус задачи, значения: `pending → planning → producing → succeeded` (или `failed`). Статус завершения задачи определяется по верхнему уровню `status`.
- `elapsed`: время, затраченное на задачу (в секундах).
- `progress`: объект прогресса верхнего уровня, `percent` (0–100) будет установлен на 100 после успешного завершения задачи; `stage` и `message` отражают последнее событие прогресса AI режиссера (поэтому после успешного завершения `stage` может оставаться на последнем этапе выполнения, например, `producing`), может быть использовано для отображения индикатора прогресса.
- `request`: тело запроса при запуске задачи.
- `response`: информация о возвращаемой задаче.
  - `success`: была ли задача успешной.
  - `data.variants`: для каждого языка соответствует один объект готового видео, содержащий `lang`, `aspect`, `title`, `output_url` (ссылка для скачивания готового видео) и т.д.
  - `data.project`: весь продукт проекта, содержащий `tarball_url` (архив проекта) и `outputs` (все ссылки на готовые видео).
  - `data.progress`: массив событий прогресса, добавляемых по этапам (только для добавления), может быть использован для отображения детального реального прогресса.

## Запрос исторического списка

Передав `action: retrieve_batch`, вы можете получить последние задачи текущего пользователя (в порядке убывания времени создания), которые могут быть использованы для страницы «Мои видео».

**Request Body** включает:

| Поле               | Тип     | Обязательное | Описание                      |
| ---------------- | ------ | --------- | ----------------------- |
| `action`         | string | Да        | Фиксированное значение `retrieve_batch`    |
| `limit`          | int    | Нет       | Количество возвращаемых записей, по умолчанию 20              |
| `created_at_max` | int    | Нет       | Возвращает только задачи, созданные до этого Unix временного штампа (для постраничного просмотра) |
| `created_at_min` | int    | Нет       | Возвращает только задачи, созданные после этого Unix временного штампа      |

### Пример кода

Соответствующий CURL код выглядит следующим образом:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### Пример ответа

После успешного запроса API вернет список исторических задач текущего пользователя:
```json
{
  "count": 2,
  "items": [
    {
      "id": "f57e99c4f60f4373a15517742ce2357d",
      "status": "succeeded",
      "progress": { "percent": 100, "stage": "producing", "message": "рендеринг сцены 2" },
      "request": { "prompt": "…", "langs": ["zh-cn", "en"], "aspect": "9:16", "duration": 20 },
      "response": { "success": true, "data": { "variants": [ { "lang": "zh-cn", "output_url": "https://…/zh.mp4" } ] } }
    }
  ]
}
```

Возвращаемые поля описаны ниже:

- `count`：Общее количество задач текущего пользователя.
- `items`：Массив задач, каждый элемент формата соответствует результату «Запроса одной задачи».

## Рекомендации по опросу

Поскольку производство видео занимает много времени, `status` будет проходить через `pending → planning → producing → succeeded` (или `failed`). Рекомендуется опрашивать каждые 5–10 секунд, пока `status` не изменится на `succeeded` или `failed`. Можно использовать верхний `progress.percent` для отображения текущей полосы прогресса. **Опрос этого интерфейса бесплатен и не расходует баллы.**

## Обработка ошибок

При вызове API, если возникнет ошибка, API вернет соответствующий код ошибки и информацию. Например:

- `401 invalid_token`：Неавторизован, недействительный или отсутствующий токен авторизации.
- `404 not_found`：Задача не найдена, указанный task_id не существует.
- `429 too_many_requests`：Слишком много запросов, вы превысили лимит частоты.
- `500 api_error`：Внутренняя ошибка сервера, что-то пошло не так на сервере.

### Пример ответа об ошибке

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "не удалось получить"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
