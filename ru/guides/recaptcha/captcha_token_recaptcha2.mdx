В данной статье будет представлена инструкция по интеграции API распознавания протокола Recaptcha2, которая позволяет пользователям не распознавать и не нажимать на изображения капчи Recaptcha2, а просто отправить Website Key для автоматического декодирования на сервере и завершения проверки.

## Процесс подачи заявки

Чтобы использовать API распознавания протокола Recaptcha2, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications) и получите ваш API Token для резервного копирования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы еще не вошли в систему или не зарегистрировались, вас автоматически перенаправят на страницу входа, чтобы пригласить вас зарегистрироваться и войти, после чего вы автоматически вернетесь на текущую страницу.

**Один API Token позволяет вызывать все услуги платформы, не нужно отдельно запрашивать для каждой услуги.** При первом запросе предоставляется бесплатный лимит, чтобы вы могли попробовать бесплатно; если лимит исчерпан, вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [API распознавания протокола Recaptcha2 →](https://platform.acedata.cloud/documents/captcha-token-recaptcha2)

## Основное использование

Сначала ознакомьтесь с основным способом использования, который заключается в вводе URL сайта, на котором нужно обработать капчу, чтобы получить обработанный результат. Сначала необходимо просто передать поле `website_url`, наш пример сайта: `https://www.google.com/recaptcha/api2/demo`, нам нужно получить `website_key` на странице `website_url`, для этого откройте эту веб-страницу, нажмите F12, чтобы войти в консоль, и затем выполните глобальный поиск по элементам на странице `recaptcha-demo`, мы можем получить следующий результат:

<p><img src="https://cdn.acedata.cloud/hvx41c.png" width="500" className="m-auto" /></p>

Где `data-sitekey` соответствует строке, которая является значением `website_key`, ниже приведены конкретные параметры результата:

<p><img src="https://cdn.acedata.cloud/8oowyw.png" width="500" className="m-auto" /></p>

Как видно, мы настроили заголовки запроса, включая:

- `accept`: какой формат ответа вы хотите получить, здесь указано `application/json`, то есть формат JSON.
- `authorization`: ключ для вызова API, после запроса вы можете выбрать его из выпадающего списка.

Также настроен тело запроса, включая:

- `website_url`: URL сайта, на котором нужно обработать капчу.
- `website_key`: идентификатор сайта в Recaptcha2.
- `proxy`: необязательный, собственный прокси (Bring Your Own Proxy). После настройки, сервер будет использовать предоставленный вами IP прокси для декодирования капчи, чтобы контролировать качество выходного IP (например, чтобы избежать блокировки целевым сайтом из-за использования общих прокси IP, что может привести к возврату `410 Gone`). Формат: `scheme://[user:pass@]host:port`, `scheme` поддерживает `http`/`https`/`socks4`/`socks5`, например `http://user:pass@1.2.3.4:8080`. Если не заполнено, будет использоваться прокси по умолчанию от платформы.

Из приведенного выше анализа видно, что URL этого POST-запроса: `https://www.google.com/recaptcha/api2/demo`, нам нужно только отправить параметр `g-recaptcha-response`, затем мы просто передаем обработанный токен в данные ниже, конкретный код CURL для вызова токена для проверки выглядит следующим образом:

```shell
curl 'https://www.google.com/recaptcha/api2/demo' \
  --data-raw 'g-recaptcha-response={token}’
```

Код Python для вызова проверки токена выглядит следующим образом:

```python
import requests

token = '{token}'

data = {
    'g-recaptcha-response': token,
}

response = requests.post('https://www.google.com/recaptcha/api2/demo',data=data)

if response.status_code:
    print(response.text)

```

Кроме того, если вы хотите сгенерировать соответствующий код интеграции, вы можете просто скопировать его, например, код CURL выглядит следующим образом:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo"
}'
```

Код интеграции на Python выглядит следующим образом:

```python
import requests

url = "https://api.acedata.cloud/captcha/token/recaptcha2"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
    "website_url": "https://www.google.com/recaptcha/api2/demo"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Асинхронный режим (async)

По умолчанию API является синхронным и блокирующим: один запрос будет ждать, пока обработка токена не завершится, прежде чем вернуться. Если вы делаете многократную ротацию кодов (multi-solver rotation) и хотите «сразу получить task_id после отправки задачи, сначала задействовать другие кодеры, а затем вернуться за результатом», вы можете передать `async: true` в теле запроса.

После передачи `async: true` интерфейс немедленно вернет `task_id`, не блокируя ожидание:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

Затем используйте этот `task_id` для опроса `POST /captcha/tasks` (рекомендуется каждые 3-5 секунд), чтобы получить результат:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

В процессе обработки будет возвращен `status: processing`:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

После завершения обработки будет возвращен `status: ready` и токен:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "token": "03AFcWeA5kjJyDQ9S1a9UYimR6nuxnpEnAs5x2Pixao0dXZhMB......"
}
```

Условия оплаты: в асинхронном режиме создание задачи и опрос «в процессе обработки» не подлежат оплате; **оплата производится только один раз при успешном получении результата** (по цене, аналогичной синхронному режиму). Поэтому отмена незавершенных задач в ротации не приведет к расходам. `/captcha/tasks` универсален для всех интерфейсов капчи (серии токенов и распознавания), можно использовать один и тот же `task_id` для опроса.

## Обработка ошибок

При вызове API, если возникает ошибка, API вернет соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`: Неверный запрос, возможно, из-за отсутствия или недействительных параметров.
- `400 api_not_implemented`: Неверный запрос, возможно, из-за отсутствия или недействительных параметров.
- `401 invalid_token`: Неавторизован, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`: Слишком много запросов, вы превысили лимит частоты.
- `500 api_error`: Внутренняя ошибка сервера, что-то пошло не так на сервере.

### Пример ответа об ошибке

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
