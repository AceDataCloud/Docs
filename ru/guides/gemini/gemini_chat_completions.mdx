Google Gemini — это очень мощная система диалогового ИИ: достаточно ввести промпт, и она сможет всего за несколько секунд сгенерировать плавный и естественный ответ. Gemini может предоставлять впечатляющую интеллектуальную помощь, значительно повышая эффективность работы и творческий потенциал человека.

В этом документе главным образом представлен процесс использования операций Gemini Chat Completion API, с помощью которого мы можем легко использовать диалоговые возможности официального Gemini.

## Процесс подачи заявки

Чтобы использовать Gemini Chat Completion API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти в систему; после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, без необходимости подавать отдельную заявку для каждого сервиса.** При первом запросе предоставляется бесплатный лимит для бесплатного ознакомления; при недостатке лимита вы можете пополнить универсальный баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## Базовое использование

Далее вы можете заполнить соответствующее содержимое в интерфейсе, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

При первом использовании этого интерфейса нам необходимо заполнить как минимум три поля: одно из них — `authorization`, которое можно напрямую выбрать в выпадающем списке. Другой параметр — `model`, `model` — это категория модели с официального сайта Gemini, которую мы выбираем для использования; доступные модели определяются перечислением `model` в документации интерфейса. Последний параметр — `messages`, `messages` — это массив введённых нами запросов; это массив, означающий, что можно одновременно загрузить несколько запросов, каждый из которых содержит `role` и `content`, где `role` обозначает роль задающего вопрос, и мы предоставляем три роли: `user`, `assistant`, `system`. Другой параметр `content` — это конкретное содержание нашего вопроса.

Одновременно вы можете заметить, что справа генерируется соответствующий код вызова; вы можете скопировать код и запустить его напрямую, а также можете напрямую нажать кнопку «Try» для тестирования.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

> **Подсказка**: flash серии `gemini-3.x` являются моделями с рассуждением и сначала расходуют reasoning tokens; установите `max_tokens` выше 512, иначе может вернуться только пустое содержимое. `gemini-3.8-flash` — текущая рекомендуемая Flash-модель, поддерживающая до 1 миллиона Token контекста, ввод изображений, вызов инструментов и потоковые ответы; в настоящее время вызывается через интерфейс Chat Completions.

## Понимание изображений (мультимодальный ввод)

Gemini — это нативная мультимодальная модель, которая может напрямую «видеть изображения». Чтобы передать изображение, измените `content` определённого сообщения со строки на **массив блоков содержимого**, и одновременно поместите в массив блок `text` и блок `image_url` — это полностью соответствует OpenAI и формату совместимости OpenAI официального Gemini.

`image_url.url` поддерживает два способа записи:

- **base64 `data:` URI (рекомендуется, наиболее стабильно)**: формат — `data:&lt;медиа-тип>;base64,&lt;данные>`, например `data:image/jpeg;base64,/9j/4AAQ...`. **Медиа-тип (MIME) уже указан в префиксе `data:`**, поэтому отдельное поле `media_type` не требуется и не существует.
- **Общедоступный URL изображения**: например `https://cdn.acedata.cloud/4hfydw.jpg`.

Поддерживаемые типы изображений: `png`, `jpeg`, `webp`, `heic`, `heif`.

Пример кода вызова Python (base64 data URI):
```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# 读取本地图片并转换为 base64 data URI
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Также можно напрямую передать общедоступный URL изображения:

```python
payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {

            ]

```

> 💡 `image_url` принимает только поле `url` (значением может быть URL изображения или base64 `data:` URI), а также необязательное поле `detail`. **Не передавайте `media_type`** — это поле изображения Anthropic Claude, оно не относится к формату `image_url` OpenAI / Gemini.

## Потоковый ответ

Этот интерфейс также поддерживает потоковые ответы, что очень полезно для интеграции с веб-страницами и позволяет реализовать эффект посимвольного отображения.

Если вы хотите получать ответ в потоковом режиме, можно изменить параметр `stream ` в заголовках запроса на `true`.

Изменения показаны на рисунке, однако код вызова также необходимо соответствующим образом изменить для поддержки потокового ответа.

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

После изменения `stream` на `true` API будет построчно возвращать соответствующие данные JSON, и на уровне кода нам необходимо внести соответствующие изменения, чтобы получить построчные результаты.

Пример кода вызова на Python:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Как можно увидеть, в ответе содержится много `data`, а `choices` внутри `data` — это самое последнее содержимое ответа, соответствующее описанному выше. `choices` — это добавленное содержимое ответа, которое вы можете использовать для интеграции в свою систему в соответствии с результатами. При этом завершение потокового ответа определяется по содержимому `data`: если содержимое равно `[DONE]`, это означает, что потоковый ответ полностью завершён. Возвращаемый результат `data` содержит несколько полей, описание которых приведено ниже:
- `id`，генерирует ID данной задачи диалога, используемый для уникальной идентификации данной задачи диалога.
- `model `，выбранная модель с официального сайта Gemini.
- `choices`，информация об ответе, предоставленном Gemini на запрос.

JavaScript также поддерживается, например, код потокового вызова для Node.js выглядит следующим образом:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

## Мультимодальная модель Gemini-3.1

`gemini-3.1-pro-preview` — это официальный ID текущей модели Gemini 3.1 Pro, поддерживающей мультимодальные входные данные, такие как текст, изображения и видео, и подходящей для сложных задач рассуждения, кодирования и понимания.

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Некорректный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `400 api_not_implemented`：Некорректный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `401 invalid_token`：Не авторизован, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили лимит частоты запросов.
- `500 api_error`：Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа об ошибке
```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
