Google Gemini — это очень мощная система AI-диалогов, которая может генерировать плавные и естественные ответы за несколько секунд посредством ввода подсказок. Этот документ в основном описывает способ использования Gemini Generate Content API — это официальный нативный формат API Google, поддерживающий два эндпоинта: `generateContent` и `streamGenerateContent`.

## Отличия от Chat Completions API

Gemini Generate Content API использует официальный нативный формат запросов Google (поле `contents`), а не совместимый с OpenAI формат (поле `messages`). Если вы уже используете Google Gemini SDK или знакомы с официальным форматом API, вы можете напрямую использовать этот API без изменения формата запроса.

## Текущая область поддержки

Интерфейс принимает текстовые, графические, видео- и аудиовходы (`inlineData` или `fileData`), конфигурации рассуждений и пользовательские объявления функций. Для таких нативных полей, как аудиовывод, встроенные инструменты и явное кэширование контекста, пока нет гарантии единой доступности; ориентируйтесь на фактический ответ конкретной модели.

При отправке аудио и других файлов с помощью `fileData.fileUri` убедитесь, что файл доступен напрямую через HTTPS, не зависит от состояния входа и что срок действия подписанной ссылки покрывает всё время обработки запроса. Непотоковый анализ аудио возвращает результат только после завершения обработки моделью, что может занять более 90 секунд; клиент должен устанавливать достаточно длительный общий тайм-аут в соответствии с размером файла и бизнес-сценарием, чтобы избежать разрыва соединения, пока сервер всё ещё обрабатывает запрос.

## Процесс получения

Перед использованием Gemini Generate Content API сначала перейдите на страницу [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) и нажмите кнопку «Получить», чтобы получить необходимые для запроса учётные данные.

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа. При первом обращении будет предоставлена бесплатная квота.

## Базовое использование

### Non-Streaming（непотоковый）

Отправьте POST-запрос на `/v1beta/models/{model}:generateContent`:

> **Подсказка**: flash серии `gemini-3.x` является моделью рассуждений и сначала расходует reasoning tokens; установите `generationConfig.maxOutputTokens` выше 512, иначе может быть возвращено только пустое содержимое.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Пример возвращаемого результата:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Поля token в `usageMetadata` тарифицируются в соответствии с нативной семантикой Gemini:

- `promptTokenCount` включает `cachedContentTokenCount`; часть, попавшая в кэш, рассчитывается по цене чтения из кэша и не учитывается повторно как обычный ввод.
- `promptTokensDetails` и `cacheTokensDetails` будут нормализованы в `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` и соответствующие детали `cached_*` в `usage.prompt_tokens_details`. Эти значения соответственно включены в `prompt_tokens` и `cached_tokens`; разные модальности пересчитываются только по своим ценам и не тарифицируются повторно.
- `candidatesTokenCount` и `thoughtsTokenCount` оба рассчитываются по цене выходных token.
- `toolUsePromptTokenCount` — это независимые token ввода инструмента, которые рассчитываются по цене входных token.

Ace Data Cloud дополнительно возвращает нормализованный объект `usage`; для разных протоколов моделей стоимость этого вызова единообразно считывается из `usage.cost`. `cost` — это необязательный предварительный просмотр стоимости; когда предварительный просмотр цены временно недоступен, ответ модели всё равно будет возвращён нормально, но может не содержать этого поля. Окончательный счёт определяется записями об использовании.

### Streaming（потоковый）

Отправьте POST-запрос на `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

Потоковый ответ будет постепенно возвращать содержимое в формате SSE (Server-Sent Events). Промежуточные события обычно содержат только инкрементальное содержимое; конечное событие с достоверными данными об использовании будет содержать `usageMetadata` и нормализованный `usage`, а стоимость по-прежнему находится в `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

Закрытие соединения означает завершение потока; нативный поток Gemini не отправляет `data: [DONE]`. Если предварительный просмотр конечной цены временно недоступен, `usage` всё равно вернёт использование token, но опустит `cost`.

### Внутреннее мышление и сводка мыслей

Внутреннее мышление модели и возврат вызывающей стороне сводки мыслей — это две независимые настройки:

- `thinkingBudget` или `thinkingLevel` управляет внутренним бюджетом или глубиной мышления модели; поддерживаемые поля и значения зависят от модели.
- `includeThoughts` управляет тем, возвращать ли сводку мыслей; по умолчанию имеет значение `false`. При пропуске этого поля или передаче `false` обычные JSON- и SSE-потоковые ответы не возвращают текст с пометкой `thought: true`; такой текст сохраняется только при явной передаче логического значения `true`.

Если в запросе не задан `includeThoughts`, интерфейс по умолчанию передаёт `false` моделям генерации, поддерживающим конфигурацию мышления, чтобы избежать запроса ненужных сводок; явно переданные клиентом значения, бюджет и уровень мышления сохраняются. Для `gemini-2.5-flash-image`, которая заведомо не поддерживает конфигурацию мышления, это поле не добавляется автоматически, а для запросов `countTokens` конфигурация генерации также не добавляется.

Отключение сводок не означает отключение внутреннего мышления и не гарантирует уменьшения количества token внутреннего мышления. Если ответ всё ещё содержит незапрошенный текст мыслей, обычные JSON- и SSE-выходы дополнительно его фильтруют, сохраняя обычный ответ, подписи и фактическое использование.

Если необходимо просматривать сводки, явно включите их следующим образом. Если модель не сгенерировала доступную сводку, текста мыслей может не быть даже при включении:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` — это зашифрованное состояние, необходимое для последующих ходов, а не текст сводки мыслей, и оно также не управляется переключателем `includeThoughts`. Подпись может находиться в обычном ответе, вызове функции или пустом текстовом Part; при фильтрации текста мыслей подписи и другие поля того же Part сохраняются, поэтому в ответе могут по-прежнему присутствовать Part, содержащие только подпись и пустой текст. При ручном ведении многоходовой истории следует сохранять порядок этих Part и расположение подписей, не перемещайте подписи и не объединяйте их.

`usageMetadata` и `usage` по-прежнему фиксируют фактическое использование. Сокрытие сводок не обнуляет `thoughtsTokenCount`, тарификация по-прежнему рассчитывается на основе фактического использования и текущих правил ценообразования.

См. официальные [пояснения Google по мышлению и сводкам мыслей](https://firebase.google.com/docs/ai-logic/thinking) и [правила подписей мыслей](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

### Вызов функций

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "北京现在的天气怎么样？"}]
    }
  ],
  "tools": [
    {
      "functionDeclarations": [
        {
          "name": "get_weather",
          "description": "获取指定城市的天气信息",
          "parameters": {
            "type": "object",
            "properties": {
              "city": {
                "type": "string",
                "description": "城市名称"
              }
            },
            "required": ["city"]
          }
        }
      ]
    }
  ]
}
```

```json
  "contents": [

      "parts": [{"text": "你好，我叫小明"}]

    {
      "role": "model",

    },
    {
      "role": "user",
      "parts": [{"text": "我叫什么名字？"}]
    }
  ]
}
```

## Настройки безопасности

Фильтрацией содержимого можно управлять через `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Обработка ошибок

| HTTP-код состояния | Значение             |
| -------- | -------------- |
| 400      | Недопустимые параметры запроса         |
| 401      | Ошибка аутентификации, проверьте Token |
| 403      | Содержимое заблокировано фильтром безопасности     |
| 429      | Слишком частые запросы         |
| 500      | Внутренняя ошибка сервера        |
