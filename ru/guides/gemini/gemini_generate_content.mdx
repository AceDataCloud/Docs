Google Gemini — это очень мощная система диалогового ИИ, которая может за несколько секунд генерировать плавные и естественные ответы посредством ввода подсказок. Этот документ в основном описывает способ использования Gemini Generate Content API. Это официальный нативный формат API Google, поддерживающий две конечные точки: `generateContent` и `streamGenerateContent`.

## Отличия от Chat Completions API

Gemini Generate Content API использует официальный нативный формат запросов Google (поле `contents`), а не совместимый с OpenAI формат (поле `messages`). Если вы уже используете Google Gemini SDK или знакомы с официальным форматом API, вы можете использовать этот API напрямую без изменения формата запросов.

## Текущая область поддержки

Интерфейс принимает текстовый, графический, видео- и аудиоввод (через `inlineData` или `fileData`), конфигурацию размышлений и объявления пользовательских функций. Для нативных полей, таких как аудиовывод, встроенные инструменты и явное кэширование контекста, пока нет гарантии единой доступности; ориентируйтесь на фактический ответ конкретной модели.

При отправке аудио и других файлов с помощью `fileData.fileUri` убедитесь, что файл доступен напрямую по HTTPS, не зависит от состояния входа и что срок действия подписанной ссылки покрывает всё время обработки запроса. Непотоковый анализ аудио возвращает результат только после завершения обработки моделью и может занимать более 90 секунд; клиенту следует устанавливать достаточно большой общий тайм-аут в зависимости от размера файла и бизнес-сценария, чтобы избежать разрыва соединения, пока сервер всё ещё выполняет обработку.

## Процесс получения доступа

Перед использованием Gemini Generate Content API сначала посетите страницу [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) и нажмите кнопку «Получить», чтобы получить учётные данные, необходимые для запроса.

Если вы ещё не вошли в систему или не зарегистрировались, будет выполнен автоматический переход на страницу входа. При первом запросе предоставляется бесплатная квота.

## Базовое использование

### Non-Streaming（непотоковый режим）

Отправьте POST-запрос на `/v1beta/models/{model}:generateContent`:

> **Подсказка**：flash серии `gemini-3.x` является моделью размышлений и сначала расходует reasoning tokens; установите `generationConfig.maxOutputTokens` выше 512, иначе может быть возвращён только пустой контент.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Пример возвращаемого результата:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Поля token в `usageMetadata` тарифицируются в соответствии с нативной семантикой Gemini:

- `promptTokenCount` включает `cachedContentTokenCount`; часть, попавшая в кэш, рассчитывается по цене чтения из кэша и не учитывается повторно как обычный ввод.
- `promptTokensDetails` и `cacheTokensDetails` будут нормализованы в `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` и соответствующие подробности `cached_*` в `usage.prompt_tokens_details`. Эти значения соответственно включены в `prompt_tokens` и `cached_tokens`; разные модальности пересчитываются только по своим ценам и не тарифицируются повторно.
- `candidatesTokenCount` и `thoughtsTokenCount` рассчитываются по цене output token.
- `toolUsePromptTokenCount` — это независимые tool input token, которые рассчитываются по цене input token.

Ace Data Cloud дополнительно возвращает нормализованный объект `usage`; для разных протоколов моделей стоимость этого вызова единообразно считывается из `usage.cost`. `cost` — это необязательный предварительный просмотр стоимости; когда предварительный просмотр цены временно недоступен, ответ модели всё равно возвращается нормально, но может не содержать это поле. Окончательный счёт основывается на записи об использовании.

### Streaming（потоковый режим）

Отправьте POST-запрос на `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

Потоковый ответ будет постепенно возвращать содержимое в формате SSE（Server-Sent Events）. Промежуточные события обычно содержат только инкрементное содержимое; финальное событие с достоверным использованием содержит `usageMetadata` и нормализованный `usage`, при этом стоимость по-прежнему находится в `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

Закрытие соединения означает окончание потока; нативный поток Gemini не отправляет `data: [DONE]`. Если предварительный просмотр цены в финальном состоянии временно недоступен, `usage` всё равно вернёт использование token, но без `cost`.

`gemini-4-carbon` и `gemini-4-hydrogen` в настоящее время можно вызывать через Chat Completions, нативный Generate Content пока недоступен. Официальные спецификации моделей перечисляют ввод текста, изображений, видео, аудио и PDF, а также вывод текста; это не означает, что текущая платформа уже проверила все типы ввода. После восстановления нативного вызова отправляйте запросы в соответствии с контрактом интерфейса на этой странице и отдельно проверяйте необходимые вводы и параметры. Миллионный вывод Token официального long decode не входит в текущий контракт интерфейса. Обе модели поддерживают только неявное кэширование, Token рассуждений рассчитываются по цене вывода; подготовленные правила ценообразования используют одинаковую цену входных Token для всех входных модальностей, а попадания в кэш рассчитываются по цене чтения из кэша, подробности смотрите на текущей странице цен.

## Расширенные функции

### Системные инструкции

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "你好"}]
    }
  ],
  "systemInstruction": {
    "parts": [{"text": "你是一个专业的诗人，所有回复都用诗歌形式。"}]
  }
}
```

### Конфигурация генерации

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "讲一个故事"}]
    }
  ],
  "generationConfig": {
    "temperature": 0.7,
    "maxOutputTokens": 1024,
    "topP": 0.9,
    "topK": 40
  }
}
```

### Режим JSON

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        {
          "text": "列出三个中国城市及其人口"
        }
      ]
    }
  ],
  "generationConfig": {
    "responseMimeType": "application/json",
    "responseSchema": {
      "type": "array",
      "items": {
        "type": "object",
        "properties": {
          "city": {
            "type": "string"
          },
          "population": {
            "type": "integer"
          }
        }
      }
    }
  }
}
```

### Внутренние рассуждения и сводки рассуждений

Внутренние рассуждения модели и возврат сводок рассуждений вызывающей стороне — это две независимые настройки:

- `thinkingBudget` или `thinkingLevel` управляют бюджетом или глубиной внутренних рассуждений модели, поддерживаемые поля и значения зависят от модели.
- `includeThoughts` управляет тем, возвращать ли сводки рассуждений, по умолчанию имеет значение `false`. При пропуске этого поля или передаче `false` обычные JSON- и потоковые SSE-ответы не возвращают текст с отметкой `thought: true`; этот текст сохраняется только при явной передаче булевого значения `true`.

Если в запросе не задан `includeThoughts`, интерфейс по умолчанию передаёт `false` моделям генерации, поддерживающим конфигурацию рассуждений, чтобы избежать запроса ненужных сводок; явно переданные клиентом значения, бюджет и уровень рассуждений сохраняются. Для `gemini-2.5-flash-image`, который, как известно, не поддерживает конфигурацию рассуждений, это поле не добавляется автоматически, а для запросов `countTokens` также не добавляется конфигурация генерации.

Отключение сводок не означает отключение внутренних рассуждений и не гарантирует сокращение внутренних token рассуждений. Если ответ всё же содержит незапрошенный текст рассуждений, обычные JSON- и SSE-выходы дополнительно фильтруют его, сохраняя обычный ответ, подписи и фактическое использование.

Если необходимо просмотреть сводку, явно включите её следующим образом. Если модель не сгенерировала доступную сводку, текст рассуждений может отсутствовать даже при включении:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` — это зашифрованное состояние, необходимое для последующих ходов, а не текст сводки рассуждений, и оно не управляется переключателем `includeThoughts`. Подпись может находиться в обычном ответе, вызове функции или Part с пустым текстом; при фильтрации текста рассуждений подпись и другие поля того же Part сохраняются, поэтому в ответе всё ещё могут быть Part, содержащие только подпись и пустой текст. При ручном ведении многоходовой истории следует сохранять порядок этих Part и положение подписей, не перемещать подписи и не объединять их.

`usageMetadata` и `usage` по-прежнему записывают фактическое использование. Сокрытие сводок не обнуляет `thoughtsTokenCount`, расчёт по-прежнему выполняется на основе фактического использования и текущих правил ценообразования.

См. официальные Google [описание рассуждений и сводок рассуждений](https://firebase.google.com/docs/ai-logic/thinking) и [правила подписей рассуждений](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

### Вызов функций

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "北京现在的天气怎么样？"}]
    }
  ],
  "tools": [
    {
      "functionDeclarations": [
        {
          "name": "get_weather",
          "description": "获取指定城市的天气信息",
          "parameters": {
            "type": "object",
            "properties": {
              "city": {
                "type": "string",
                "description": "城市名称"
              }
            },
            "required": ["city"]
          }
        }
      ]
    }
  ]
}
```

```json
  "contents": [
    {

      "parts": [{"text": "你好，我叫小明"}]
    },
    {
      "role": "model",
      "parts": [{"text": "你好小明！很高兴认识你。"}]
    },
    {
      "role": "user",
      "parts": [{"text": "我叫什么名字？"}]
    }
  ]
}
```

### Понимание изображений
```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        {"text": "Опишите это изображение"},
        {
          "inlineData": {
            "mimeType": "image/jpeg",

          }
        }
      ]
    }
  ]
}
```

## Настройки безопасности

Фильтрацией содержимого можно управлять с помощью `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Обработка ошибок

| Код состояния HTTP | Значение |
| -------- | -------------- |
| 400      | Недопустимые параметры запроса |
| 401      | Ошибка аутентификации, проверьте Token |
| 403      | Содержимое заблокировано фильтром безопасности |
| 429      | Слишком частые запросы |
| 500      | Внутренняя ошибка сервера |
