В этом документе описывается интерфейс запроса асинхронных задач CAPTCHA `POST /captcha/tasks`. Когда вы вызываете любой интерфейс CAPTCHA (серии token или recognition) с параметром `async: true`, интерфейс немедленно возвращает `task_id`, после чего вы можете использовать этот `task_id` для опроса данного интерфейса и получения окончательного результата. Подходит для сценариев с ротацией нескольких решателей (multi-solver rotation): после отправки задачи вы сразу получаете `task_id`, затем можете задействовать других решателей, а позже вернуться за результатом.

> 📘 Полная интерактивная документация (включая онлайн-отладку): [API запроса задач CAPTCHA →](https://platform.acedata.cloud/documents/captcha-tasks)

## Процесс подачи заявки

Чтобы использовать этот интерфейс, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications) и получите ваш API Token для резервного копирования. **Один API Token позволяет вызывать все сервисы платформы, не нужно запрашивать отдельный токен для каждого сервиса.**

## Основное использование

### Шаг 1: Создание задачи асинхронным способом

В теле запроса к любому интерфейсу CAPTCHA передайте `async: true`, интерфейс немедленно вернет `task_id` (HTTP 201), не блокируя ожидание:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

### Шаг 2: Опрос результата с помощью task_id

Используйте `task_id`, полученный на предыдущем шаге, для опроса `POST /captcha/tasks` (рекомендуется каждые 3-5 секунд):

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

В процессе обработки будет возвращен `status: processing`:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "processing"
}
```

По завершении обработки будет возвращен `status: ready` и соответствующее поле результата — структура полей полностью совпадает с синхронным режимом:

- **серия token** (hcaptcha, recaptcha2, recaptcha3) возвращает `token`:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "started_at": 1784885653.0,
  "finished_at": 1784885665.4,
  "elapsed": 12.4,
  "token": "03AFcWeA5kjJyDQ9S1a9UYimR6nuxnpEnAs5x2Pixao0dXZhMB......"
}
```

- **категория recognition** (recognition/recaptcha2, recognition/hcaptcha) возвращает `solution`; **recognition/image2text** возвращает `text`.

`/captcha/tasks` универсален для всех интерфейсов CAPTCHA (серии token и recognition), можно использовать один и тот же `task_id` для опроса.

Ответ с `status: ready` также будет содержать временные поля.

- `started_at`, время начала обработки задачи, Unix временная метка (секунды, с плавающей точкой).
- `finished_at`, время получения результата задачи, Unix временная метка (секунды, с плавающей точкой). При обработке не возвращается это поле.
- `elapsed`, время обработки задачи, в секундах (с плавающей точкой, с 3 знаками после запятой). При обработке не возвращается это поле.

## Условия оплаты

В асинхронном режиме создание задачи и опрос «в процессе» не облагаются платой; **плата взимается только при успешном получении результата** (по цене, аналогичной синхронному режиму). Поэтому отмена незавершенных задач в ротации не приведет к расходам.

## Обработка ошибок

При вызове этого интерфейса, если возникнет ошибка, будет возвращен соответствующий код ошибки и информация. Например:

- `400 invalid_request`: запрос не содержит параметра `task_id`.
- `401 invalid_token`: несанкционированный доступ, токен авторизации недействителен или отсутствует.
- `404 not_found`: `task_id` не существует или не принадлежит текущему аккаунту.

### Пример ответа об ошибке

```json
{
  "success": false,
  "error": {
    "code": "not_found",
    "message": "task not found"
  }
}
```
