В этой статье будет представлена инструкция по интеграции Veo Videos Generation API, который позволяет генерировать официальные видео Veo путем ввода пользовательских параметров.

## Процесс получения доступа

Чтобы использовать Veo Videos Generation API, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications), чтобы получить ваш API Token и сохранить его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы еще не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти, после чего вы автоматически вернетесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, без необходимости подавать отдельную заявку для каждого сервиса.** При первом получении предоставляются бесплатные лимиты для бесплатного ознакомления; при недостатке лимитов вы можете пополнить универсальный баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Veo Videos Generation API →](https://platform.acedata.cloud/documents/veo-videos)

## Базовое использование

Сначала рассмотрим базовый способ использования: введя промпт `prompt`, действие генерации `action`, массив эталонных изображений первого и последнего кадров `image_urls`, а также модель `model`, можно получить обработанный результат. Сначала необходимо просто передать поле `action` со значением `text2video`; оно главным образом включает три действия: генерация видео из текста (`text2video`), генерация видео из изображения (`image2video`), получение видео 1080p (`get1080p`), затем также необходимо указать модель `model`; в настоящее время основными являются модели `veo31-fast`, `veo3`, `veo31`, `veo3-fast` и `veo31-fast-ingredients`, подробности приведены ниже:

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

Здесь можно увидеть, что мы установили Request Headers, включая:

- `accept`: формат ответа, который требуется получить; здесь указывается `application/json`, то есть формат JSON.
- `authorization`: ключ для вызова API, после получения его можно напрямую выбрать из выпадающего списка.

Также установлен Request Body, включающий:

- `model`: модель для генерации видео; основными являются модели `veo31-fast`, `veo3`, `veo31`, `veo3-fast` и `veo31-fast-ingredients`.
- `action`: действие данной задачи генерации видео; главным образом включает три действия: генерация видео из текста (`text2video`), генерация видео из изображения (`image2video`), получение видео 1080p (`get1080p`).
- `image_urls`: ссылка на загружаемое эталонное изображение, обязательная при выборе действия генерации видео из изображения `image2video`. `veo31-fast-ingredients` поддерживает максимум 3 изображения (слияние нескольких изображений), остальные модели — максимум 2 изображения (режим первого и последнего кадров).
- `resolution`: выбор разрешения генерируемого видео; модель veo31 поддерживает разрешение 4k, другие модели его не поддерживают, все модели поддерживают разрешения 1080p и gif; если это значение не передано, по умолчанию используется разрешение 720p; основные варианты: `1080p`, `gif`, `4k`.
- `prompt`: промпт.
- `callback_url`: URL, на который необходимо отправить результат обратного вызова.
- `async`: необязательно; при установке `true` интерфейс немедленно возвращает `task_id`, без необходимости предоставлять `callback_url`, после чего результат получается путем опроса соответствующего интерфейса запроса задач.

### 📌 Сводка описания моделей

| **Название модели**                   | **Поддерживаемые режимы**                          | **Правила ввода изображений**                        |
| -------------------------- | --------------------------------- | --------------------------------- |
| **veo3-fast**              | Генерация видео из текста (без изображения)<br />Режим генерации видео из изображения (с изображением)           | **1 изображение** → режим первого кадра<br />**2 изображения** → режим первого и последнего кадров |
| **veo31-fast**             | Генерация видео из текста (без изображения)<br />Режим генерации видео из изображения (с изображением)           | **1 изображение** → режим первого кадра<br />**2 изображения** → режим первого и последнего кадров |
| **veo31-fast-ingredients** | ❌ Генерация видео из текста (не поддерживается)<br />✅ **обязательное слияние нескольких изображений** (необходимо передать изображения) | **1-3 изображения** → режим слияния нескольких изображений (максимум 3 изображения)        |
| **veo3**                   | Генерация видео из текста (без изображения)<br />Режим генерации видео из изображения (с изображением)           | **1 изображение** → режим первого кадра<br />**2 изображения** → режим первого и последнего кадров |
| **veo31**                  | Генерация видео из текста (без изображения)<br />Режим генерации видео из изображения (с изображением)           | **1 изображение** → режим первого кадра<br />**2 изображения** → режим первого и последнего кадров |

---

### 🔑 Описание ключевых правил

1. **Общая логика**:
   - **Без входных изображений** → автоматически активируется режим генерации видео из текста.
   - **С входными изображениями** → активируется режим генерации видео из изображения (конкретное поведение определяется количеством изображений).
2. **Типы режима генерации видео из изображения**:
   - **Режим первого кадра** (1 изображение): первый кадр фиксируется как входное изображение.
   - **Режим первого и последнего кадров** (2 изображения): первый и последний кадры фиксируются как входные изображения.
   - **Режим слияния нескольких изображений** (1-3 изображения): поддерживается только `veo31-fast-ingredients`, генерирует видео путем объединения содержимого нескольких изображений.
3. **Классификация режимов**:

  - **Режим Fast**: `veo3-fast`, `veo31-fast`, `veo31-fast-ingredients`.
   - **Режим Quality**: `veo3`, `veo31` (более высокое качество генерации).

---

### ⚠️ Примечания

- **Единственная модель с обязательной передачей изображений**: в `veo31-fast-ingredients` необходимо передать изображения (1-3), иначе она не сможет работать.
- **Ограничение количества изображений**:
  - `veo31-fast-ingredients` поддерживает ввод **1-3 изображений** (режим слияния нескольких изображений).
  - Остальные модели поддерживают ввод максимум **2 изображений** (режим первого и последнего кадров).

## Функция генерации видео из изображения

Если вы хотите сгенерировать видео на основе изображений начального и конечного кадров, можно установить параметр `action` в значение `image2video` и передать массив ссылок на изображения начального и конечного кадров `image_urls`.

Далее нам необходимо заполнить подсказки, которые нужно расширить на следующем шаге для пользовательской генерации видео, можно указать следующее содержимое:

- `model`：модель для генерации видео, в основном доступны `veo31-fast`、`veo3`、`veo31`、`veo3-fast` и `veo31-fast-ingredients`。
- `image_urls`：при выборе действия генерации видео из изображения `image2video` необходимо указать ссылки на загружаемые эталонные изображения。
- `prompt`：подсказка。

Пример заполнения приведён ниже:

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

После заполнения автоматически генерируется следующий код:

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

Соответствующий код Python:

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo31-fast",
    "prompt": "Let it dance",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Асинхронный обратный вызов

Поскольку время генерации Veo Videos Generation API относительно длительное, примерно 1–2 минуты, если API долго не отвечает, HTTP-запрос будет постоянно поддерживать соединение, что приводит к дополнительному потреблению системных ресурсов, поэтому данный API также предоставляет поддержку асинхронных обратных вызовов.

Общий процесс выглядит так: когда клиент инициирует запрос, дополнительно указывается поле `callback_url`, после того как клиент инициирует API-запрос, API немедленно возвращает результат, содержащий информацию поля `task_id`, которое представляет текущий ID задачи. После завершения задачи результат генерации видео будет отправлен в форме POST JSON на указанный клиентом `callback_url`, в котором также содержится поле `task_id`, таким образом результаты задач можно связать по ID.

Ниже мы на примере рассмотрим, как именно это сделать.

Прежде всего, Webhook-обратный вызов — это сервис, который может принимать HTTP-запросы, разработчику следует заменить его URL-адресом самостоятельно развёрнутого HTTP-сервера. Здесь для удобства демонстрации используется публичный сайт-пример Webhook https://webhook.site/, при открытии этого сайта можно получить Webhook URL, как показано на рисунке:

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `400 api_not_implemented`：Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `401 invalid_token`：Неавторизованно, недопустимый или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили ограничение частоты запросов.
- `500 api_error`：Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
