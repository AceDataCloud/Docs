В этой статье будет представлена инструкция по интеграции Flux Images Generation API — с его помощью можно генерировать официальные изображения Flux, вводя пользовательские параметры.

## Процесс получения доступа

Чтобы использовать Flux Images Generation API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам предложат зарегистрироваться и войти в систему; после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первом получении предоставляется бесплатная квота для бесплатного ознакомления; при недостатке квоты можно пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Базовое использование

Сначала рассмотрим базовый способ использования: достаточно ввести промпт `prompt`, действие генерации `action` и размер изображения `size`, чтобы получить обработанный результат. Сначала необходимо просто передать поле `action` со значением `generate`, затем также нужно ввести промпт. Конкретное содержимое выглядит следующим образом:

<p><img src="https://cdn.acedata.cloud/wz85jt.png" width="500" className="m-auto" /></p>

Можно увидеть, что здесь мы настроили Request Headers, включая:

- `accept`: в каком формате вы хотите получить результат ответа; здесь указывается `application/json`, то есть формат JSON.
- `authorization`: ключ для вызова API, после получения его можно непосредственно выбрать из выпадающего списка.

Также настроен Request Body, включающий:

- `action`: действие этой задачи генерации изображения.
- `size`: размер результата генерации изображения. **Для серий `flux-2-flex` / `flux-2-pro` / `flux-2-max` обязательно необходимо передавать соотношение сторон изображения (например, `1:1`, `16:9`); размеры в пикселях вроде `1024x1024` не принимаются, при отсутствии будет возвращена ошибка 400.**
- `count`: количество генерируемых изображений, значение по умолчанию — 1; этот параметр действует только для задач генерации изображений и не действует для задач редактирования.
- `prompt`: промпт.
- `model`: модель генерации, по умолчанию `flux-dev`; новейшими флагманскими моделями являются `flux-2-pro`, `flux-2-max` (более высокое качество изображения, требуется использовать соотношение сторон изображения `size`).
- `callback_url`: URL, на который необходимо отправить результат обратного вызова.
- `async`: необязательно; при установке значения `true` интерфейс немедленно возвращает `task_id`, без необходимости предоставлять `callback_url`, после чего результат можно получить путём опроса соответствующего интерфейса запроса задач.

Параметр `size` имеет некоторые особые ограничения, главным образом он делится на два типа: соотношение ширины и высоты `width x height` и соотношение сторон изображения `x:y`; подробнее:

| Модель               | Диапазон                                         |
| ---------------- | ------------------------------------------ |
| flux-dev         | Поддерживает соотношения ширины и высоты 1024x1024, 1024x1792, 1792x1024 или соотношения сторон изображения |
| flux-pro         | Поддерживает соотношения ширины и высоты 1024x1024, 1024x1792, 1792x1024 или соотношения сторон изображения |
| flux-2-flex      | Поддерживает только соотношения сторон изображения                                    |
| flux-2-pro       | Поддерживает только соотношения сторон изображения                                    |
| flux-2-max       | Поддерживает только соотношения сторон изображения                                    |
| flux-kontext-pro | Поддерживает только соотношения сторон изображения                                    |
| flux-kontext-max | Поддерживает только соотношения сторон изображения                                    |

Рекомендуемые соотношения сторон изображения: "21:9", "16:9", "4:3", "3:2", "1:1", "2:3", "3:4", "9:16", "9:21".

После выбора параметров справа автоматически будет сгенерирован соответствующий код. Перед копированием подтвердите, что в заголовке авторизации используется ваш собственный API Key, в документации и снимках экрана не должны присутствовать реальные учётные данные.

Нажмите кнопку «Try», чтобы выполнить тестирование; здесь мы получили следующий результат:

```json
{
  "success": true,
  "task_id": "5456c749-3bbb-4f10-9eb8-cfbcac297500",
  "trace_id": "ae4eecb8-1dd6-45b4-bfb3-a1c48872536e",
  "data": [
    {
      "image_url": "https://cdn.acedata.cloud/assets/examples/flux/5456c749-3bbb-4f10-9eb8-cfbcac297500-d0ef60485f73.jpg"
    }
  ]
}
```

Результат содержит несколько полей, описание которых приведено ниже:

- `success`: статус задачи генерации видео в данный момент.
- `task_id`: ID задачи генерации видео в данный момент.
- `trace_id`: ID отслеживания генерации видео в данный момент.
- `data`: список результатов задачи генерации изображения в данный момент.
  - `image_url`: ссылка на задачу генерации изображения в данный момент.
  - `prompt`: промпт.

Можно увидеть, что мы получили удовлетворительную информацию об изображении; нам нужно лишь получить сгенерированное изображение Flux по адресу ссылки на изображение в `data` результата.

Кроме того, если вы хотите сгенерировать соответствующий код интеграции, его можно скопировать напрямую; например, код CURL выглядит следующим образом:

```shell
curl -X POST 'https://api.acedata.cloud/flux/images' \
-H 'authorization: Bearer {token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "A photorealistic studio product shot of a frosted-glass perfume bottle on wet black slate, single softbox key light, water droplets, dark moody background, 85mm macro.",
  "model": "flux-2-pro",
  "size": "1:1"
}'
```

## Задача редактирования изображения

Если вы хотите отредактировать определённое изображение, сначала в параметр `image_url` необходимо передать ссылку на редактируемое изображение; в этом случае `action` поддерживает только `edit`, после чего можно указать следующее содержимое:

- model: модель, используемая для этой задачи редактирования изображения; поддерживаются `flux-dev`, `flux-pro`, `flux-kontext-pro`, `flux-kontext-max`, `flux-2-flex`, `flux-2-pro`, `flux-2-max`.
- image_url: загрузите изображение, которое необходимо отредактировать.

Пример заполнения выглядит следующим образом:

<p><img src="https://cdn.acedata.cloud/jn9da5.png" width="500" className="m-auto" /></p>

После заполнения автоматически генерируется следующий код:

<p><img src="https://cdn.acedata.cloud/6cwxb8.png" width="500" className="m-auto" /></p>

Соответствующий код:

```python
import requests

url = "https://api.acedata.cloud/flux/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "edit",
    "prompt": "a white siamese cat",
    "model": "flux-kontext-pro",
    "image_url": "https://cdn.acedata.cloud/ytj2qy.png"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Нажмите «Запустить», и можно обнаружить, что результат будет получен немедленно, как показано ниже:

```json
{
  "success": true,
  "task_id": "2a7979ff-1f77-4380-92c6-a2dc37c3b4c8",
  "trace_id": "732b65c0-48d9-49f7-b568-64e5acffe4c0",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "timings": 1752744073
    }
  ]
}
```
Можно увидеть, что сгенерированный эффект представляет собой редактирование исходного изображения, результат аналогичен описанному выше.

## Асинхронный обратный вызов

Поскольку Flux Images Generation API требует относительно длительного времени для генерации, примерно 1–2 минуты, если API долго не отвечает, HTTP-запрос будет постоянно поддерживать соединение, что приводит к дополнительному потреблению системных ресурсов, поэтому данный API также предоставляет поддержку асинхронных обратных вызовов.

Общий процесс таков: когда клиент инициирует запрос, он дополнительно указывает поле `callback_url`, после того как клиент отправляет API-запрос, API немедленно возвращает результат, содержащий информацию поля `task_id`, которое представляет ID текущей задачи. Когда задача завершена, результат генерации изображения будет отправлен в виде POST JSON на указанный клиентом `callback_url`, где также будет включено поле `task_id`, таким образом результаты задачи можно связать по ID.

Ниже мы на примере рассмотрим, как именно это сделать.

Прежде всего, Webhook обратного вызова — это сервис, способный принимать HTTP-запросы, разработчик должен заменить его URL-адресом самостоятельно развернутого HTTP-сервера. Для удобства демонстрации здесь используется публичный пример сайта Webhook https://webhook.site/, откройте этот сайт, чтобы получить Webhook URL, как показано на рисунке:

![](https://cdn.acedata.cloud/cjjfly.png)

Скопируйте этот URL, и его можно будет использовать в качестве Webhook, пример здесь: `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`.

Далее мы можем установить для поля `callback_url` указанный выше Webhook URL, одновременно заполнив соответствующие параметры, конкретное содержимое показано на рисунке:

<p><img src="https://cdn.acedata.cloud/wm6caw.png" width="500" className="m-auto" /></p>

Нажмите «Запустить», и можно увидеть, что сразу будет получен результат, как показано ниже:

Подождав немного, мы можем наблюдать результат сгенерированного изображения на `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`, как показано на рисунке:

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код и информацию об ошибке. Например:

- `400 token_mismatched`：Некорректный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `400 api_not_implemented`：Некорректный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `401 invalid_token`：Неавторизованно, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили ограничение частоты запросов.
- `500 api_error`：Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
