Основная функция Flux Tasks API — через ID задачи платформы, возвращаемый Flux Images Generation API или Flux Videos API, запрашивать статус выполнения этой задачи.

Этот документ подробно представит инструкции по интеграции Flux Tasks API, помогая вам легко интегрировать и в полной мере использовать мощные возможности этого API. С помощью Flux Tasks API вы можете легко реализовать запрос статуса выполнения задач Flux Images Generation API.

Полный пример отправки и опроса видео смотрите в [руководстве по интеграции Flux Videos API](https://platform.acedata.cloud/documents/flux-videos-integration). За запрос уже существующих задач дополнительная плата за генерацию не взимается.

## Процесс получения

Чтобы использовать Flux Images Generation API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти в систему; после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, без необходимости подавать отдельную заявку для каждого сервиса.** При первом получении предоставляется бесплатный лимит для бесплатного тестирования; при недостатке лимита вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Пример запроса

Flux Tasks API может использоваться для запроса результатов Flux Images Generation API. О том, как использовать Flux Images Generation API, обратитесь к документации [Flux Images Generation API ](https://platform.acedata.cloud/documents/flux-images-integration).

В качестве примера возьмём один ID задачи, возвращённый сервисом Flux Images Generation API, и покажем, как использовать этот API. Предположим, у нас есть ID задачи: 2db0168c-2373-4367-8d9a-9dc778802e8a, далее покажем, как передать ID задачи.

### Настройка заголовков и тела запроса

**Request Headers** включают:

- `accept`: указывает получение результатов ответа в формате JSON, здесь указывается `application/json`.
- `authorization`: ключ для вызова API, после получения можно напрямую выбрать из выпадающего списка.

**Request Body** включает:

- `id`: ID отправленной задачи.
- `action`: способ операции над задачей.

Настройте, как показано на изображении ниже:

### Пример кода

Можно увидеть, что в правой части страницы уже автоматически сгенерирован код на различных языках, как показано на изображении:

Некоторые примеры кода приведены ниже:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/flux/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/flux/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Результат содержит несколько полей: поле `request` — это request body при запуске задачи, а поле `response` — response body, возвращаемое после завершения задачи. Описание полей приведено ниже.

- `id`: ID созданной задачи изображения, используется для уникальной идентификации этой задачи генерации изображения.
- `request`: информация запроса в задаче запроса изображения.
- `response`: информация ответа в задаче запроса изображения.
- `created_at`: время создания задачи, временная метка Unix (секунды, с плавающей точкой).
- `started_at`: время начала выполнения задачи, временная метка Unix (секунды, с плавающей точкой).
- `finished_at`: время завершения задачи, временная метка Unix (секунды, с плавающей точкой). Если задача не завершена, это поле не возвращается.
- `elapsed`: длительность выполнения задачи, в секундах (с плавающей точкой, до 3 знаков после запятой). Если задача не завершена, это поле не возвращается.

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и сообщение. Например:

- `400 token_mismatched`：Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `400 api_not_implemented`：Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `401 invalid_token`：Не авторизован, недопустимый или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили ограничение частоты запросов.
- `500 api_error`：Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
