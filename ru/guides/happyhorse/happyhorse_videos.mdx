В этом документе описывается способ интеграции API HappyHorse Videos. Этот интерфейс поддерживает генерацию видео на основе текста, видео на основе первого кадра, видео на основе эталонного изображения и редактирование видео через единый входной пункт `/happyhorse/videos` и параметр `action`.

## Процесс подачи заявки

Чтобы использовать API HappyHorse Videos, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы еще не вошли в систему или не зарегистрированы, вы будете автоматически перенаправлены на страницу входа, где вас пригласят зарегистрироваться и войти в систему, после чего вы будете автоматически возвращены на текущую страницу.

**Один API Token позволяет использовать все услуги платформы, не нужно подавать отдельные заявки на каждую услугу.** При первой подаче заявки предоставляется бесплатный лимит, чтобы вы могли попробовать; при недостатке лимита вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [HappyHorse Videos API →](https://platform.acedata.cloud/documents/happyhorse-videos)

## Типы операций

`action` определяет режим генерации для данного запроса:

- `generate`: видео на основе текста, действие по умолчанию, поддерживает `happyhorse-1.0-t2v` и `happyhorse-1.1-t2v`, необходимо передать `prompt`.
- `image_to_video`: видео на основе первого кадра, поддерживает `happyhorse-1.0-i2v` и `happyhorse-1.1-i2v`, необходимо передать `image_url`.
- `reference_to_video`: видео на основе эталонного изображения, поддерживает `happyhorse-1.0-r2v` и `happyhorse-1.1-r2v`, необходимо передать `prompt` и 1–9 `image_urls`.
- `video_edit`: редактирование видео, поддерживает `happyhorse-1.0-video-edit`, необходимо передать `prompt` и `video_url`, можно дополнительно передать 0–5 эталонных изображений `image_urls`.

По умолчанию все действия используют модель 1.1; `video_edit` в настоящее время поддерживает только `happyhorse-1.0-video-edit`.

## Основное использование

Для генерации видео на основе текста достаточно предоставить `prompt`, также можно указать параметры `resolution`, `ratio`, `duration` и т.д.:

```json
{
  "action": "generate",
  "model": "happyhorse-1.1-t2v",
  "prompt": "Кинематографическая белая лошадь поднимает голову, грива нежно колышется на ветру рассвета, медленное приближение камеры, теплое киноосвещение",
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}
```

Пример возвращаемого результата:

```json
{
  "success": true,
  "task_id": "27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1",
  "trace_id": "6071ab5e-2f37-46f0-9e07-f1e378112e69",
  "data": [
    {
      "id": "9650580f-6d9e-4bc1-823a-29011790c5cb",
      "video_url": "https://platform2.cdn.acedata.cloud/happyhorse/27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1.mp4",
      "state": "succeeded",
      "duration": 5,
      "resolution": "720P",
      "ratio": null
    }
  ]
}
```

Описание полей:

- `success`: успешность данного запроса.
- `task_id`: ID задачи на стороне Ace Data Cloud, может быть использован для проверки статуса задачи.
- `trace_id`: ID отслеживания данного запроса, используется для устранения проблем.
- `data`: список результатов видео.
  - `id`: ID задачи на стороне HappyHorse.
  - `video_url`: CDN-ссылка на сгенерированное видео.
  - `state`: статус задачи, может быть `pending` / `succeeded` / `error`.
  - `duration`: продолжительность видео для расчета стоимости, в секундах; для `video_edit` это сумма продолжительности входного и выходного видео.
  - `resolution`: выходное разрешение.
  - `ratio`: выходное соотношение сторон.

Соответствующий код CURL выглядит следующим образом:

```shell
curl -X POST 'https://api.acedata.cloud/happyhorse/videos' \
-H 'authorization: Bearer ${bearer_token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "happyhorse-1.1-t2v",
  "prompt": "Кинематографическая белая лошадь поднимает голову, грива нежно колышется на ветру рассвета, медленное приближение камеры, теплое киноосвещение",
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}'
```

Соответствующий код на Python выглядит следующим образом:

```python
import requests

url = "https://api.acedata.cloud/happyhorse/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "action": "generate",
    "model": "happyhorse-1.1-t2v",
    "prompt": "Кинематографическая белая лошадь поднимает голову, грива нежно колышется на ветру рассвета, медленное приближение камеры, теплое киноосвещение",
    "resolution": "720P",
    "ratio": "16:9",
    "duration": 5,
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Видео на основе первого кадра

При использовании `image_to_video` `image_url` будет использоваться как первый кадр видео. Выходное соотношение сторон будет стремиться соответствовать изображению первого кадра, поэтому это действие не требует передачи `ratio`.

```json
{
  "action": "image_to_video",
  "model": "happyhorse-1.1-i2v",
  "image_url": "https://cdn.acedata.cloud/b1c82e4937.png",
  "prompt": "Кинематографическая белая лошадь поднимает голову, грива нежно колышется на ветру рассвета, медленное приближение камеры, теплое киноосвещение",
  "resolution": "1080P",
  "duration": 5
}
```

## Видео на основе эталонного изображения

При использовании `reference_to_video` можно передать 1–9 эталонных изображений в `image_urls`. В подсказке можно ссылаться на соответствующие изображения, используя `character1`, `character2` и т.д.

```json
{
  "action": "reference_to_video",
  "model": "happyhorse-1.1-r2v",
  "prompt": "character1 идет вперед по рассветному лугу в стиле теплой кожи и золотой отделки от character2",
  "image_urls": [
    "https://cdn.acedata.cloud/b1c82e4937.png",
    "https://cdn.acedata.cloud/eb75d88a3f.png"
  ],
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}
```

## Редактирование видео

При использовании `video_edit` необходимо передать `video_url` редактируемого видео и `prompt` с намерением редактирования. Дополнительные `image_urls` могут использоваться как эталонные изображения, например, для смены одежды, стилистической трансформации или частичной замены. `audio_setting` может быть `auto` или `origin`, где `origin` означает сохранение оригинального аудио видео.

```json
{
  "action": "video_edit",
  "model": "happyhorse-1.0-video-edit",
  "prompt": "Примените стиль теплой кожи и золотой отделки из эталонного изображения, сохраняя оригинальное движение камеры",
  "video_url": "https://platform2.cdn.acedata.cloud/happyhorse/27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1.mp4",
  "image_urls": [
    "https://cdn.acedata.cloud/eb75d88a3f.png"
  ],
  "resolution": "720P",
  "audio_setting": "auto"
}
```

## Асинхронный обратный вызов
Видео生成 требует определенного времени обработки. Если вы не хотите поддерживать длительное соединение в ожидании, вы можете передать `callback_url`, в этом случае API немедленно вернет `task_id`, а по завершении задачи окончательный результат будет отправлен на этот адрес:

```json
{
  "action": "generate",
  "prompt": "A horse running through a snowy forest",
  "duration": 5,
  "callback_url": "https://your-domain.com/callback/happyhorse"
}
```

Немедленно возвращаемый результат выглядит следующим образом:

```json
{
  "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea"
}
```

Если вы хотите только опрашивать, без необходимости в обратном вызове, вы также можете передать `"async": true`, а затем через [HappyHorse Tasks API](https://platform.acedata.cloud/documents/happyhorse-tasks) проверить результаты задачи.

## Условия оплаты

HappyHorse взимает плату за количество секунд выходного видео и разрешение:

- `720P`: от примерно $0.105 / сек.
- `1080P`: от примерно $0.18 / сек.
- `video_edit`: плата взимается за общую продолжительность входного и выходного видео, фактическое время оплаты определяется по статистике после завершения задачи.

Неудачные задачи не подлежат оплате и не занимают бесплатный лимит.

## Обработка ошибок

Когда возникает проблема с запросом, API возвращает соответствующий код ошибки и описание, наиболее распространенные из них:

- `400`: Ошибка в параметрах запроса, например, действие не соответствует модели, отсутствует `prompt` / `image_url` / `video_url`, или `duration` превышает диапазон 3–15 секунд.
- `401`: Ошибка аутентификации, токен недействителен или не соответствует API.
- `403`: Недостаточно средств, или подсказка попала под отказ в модерации контента.
- `429`: Слишком частые запросы, превышен лимит, пожалуйста, попробуйте позже.
- `500`: Внутренняя ошибка сервера или сбой генерации.
