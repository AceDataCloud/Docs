Основная функция SeeDream Tasks API заключается в том, чтобы запрашивать статус выполнения задачи, используя ID задачи, сгенерированный SeeDream Images Generation API.

В этом документе подробно описывается интеграция SeeDream Tasks API, чтобы помочь вам легко интегрировать и в полной мере использовать мощные возможности этого API. С помощью SeeDream Tasks API вы можете легко реализовать запрос статуса выполнения задач SeeDream Images Generation API.

## Процесс подачи заявки

Чтобы использовать SeeDream Images Generation API, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications) и получите ваш API Token для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы еще не вошли в систему или не зарегистрированы, вы будете автоматически перенаправлены на страницу входа, где вас пригласят зарегистрироваться и войти. После завершения вы будете автоматически возвращены на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, не нужно отдельно запрашивать для каждого сервиса.** При первом запросе предоставляется бесплатный лимит, чтобы вы могли попробовать; при недостатке лимита вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [SeeDream Images Generation API →](https://platform.acedata.cloud/documents/seedream-images)

## Пример запроса

SeeDream Tasks API можно использовать для запроса результатов SeeDream Images Generation API. Для получения информации о том, как использовать SeeDream Images Generation API, обратитесь к документации [SeeDream Images Generation API](https://platform.acedata.cloud/documents/seedream-images-integration).

Мы возьмем в качестве примера ID задачи, возвращаемый сервисом SeeDream Images Generation API, и продемонстрируем, как использовать этот API. Предположим, у нас есть ID задачи: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, далее мы покажем, как передать этот ID задачи.

### Установка заголовков запроса и тела запроса

**Request Headers** включает:

- `accept`: указывает на прием ответа в формате JSON, здесь указывается `application/json`.
- `authorization`: ключ для вызова API, который можно выбрать из выпадающего списка после запроса.

**Request Body** включает:

- `id`: загруженный ID задачи.
- `action`: способ выполнения операции над задачей.

Настройка, как показано на следующем изображении:

### Пример кода

Можно заметить, что на правой стороне страницы автоматически сгенерирован код на различных языках, как показано на изображении:

Некоторые примеры кода приведены ниже:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/seedream/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "a6e0d456-189b-4c78-9232-2fe72166ab39",
  "action": "retrieve"
}'
```

### Пример ответа

После успешного запроса API вернет информацию о деталях этой задачи. Например:

```json
{
  "success": true,
  "task_id": "84d1544a-9043-4dde-a98b-e889dacd75f6",
  "trace_id": "176acf03-7ca7-4fc6-85db-e3724d4f59eb",
  "data": [
    {
      "prompt": "a white siamese cat",
      "size": "2048x2048",
      "image_url": "https://platform.cdn.acedata.cloud/seedream/6e5f9085-cc4a-4801-b77b-31550129ff19.jpg"
    }
  ]
}
```

Возвращаемый результат содержит несколько полей, описание которых приведено ниже:

- `success`: статус выполнения задачи по генерации видео.
- `task_id`: ID задачи по генерации видео.
- `trace_id`: ID отслеживания видео.
- `data`: список результатов задачи по генерации изображений.
  - `image_url`: ссылка на задачу по генерации изображения.
  - `prompt`: подсказка.
  - `size`: пиксели сгенерированного изображения.

- `items`, все конкретные детали пакетных задач. Это массив, каждый элемент массива имеет такую же структуру, как и результат запроса одной задачи.

- `created_at`, время создания задачи, Unix временная метка (секунды, с плавающей точкой).

- `finished_at`, время завершения задачи, Unix временная метка (секунды, с плавающей точкой). Поле не возвращается, если задача не завершена.
- `elapsed`, время выполнения задачи, в секундах (с плавающей точкой, с 3 знаками после запятой). Поле не возвращается, если задача не завершена.

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Неверный запрос, возможно, из-за отсутствия или недействительных параметров.
- `400 api_not_implemented`：Неверный запрос, возможно, из-за отсутствия или недействительных параметров.
- `401 invalid_token`：Неавторизован, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили лимит частоты.
- `500 api_error`：Внутренняя ошибка сервера, что-то пошло не так на сервере.

### Пример ответа об ошибке

```json
{
  "success": false,
  "error": {

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
