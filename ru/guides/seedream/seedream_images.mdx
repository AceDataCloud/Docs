В этой статье будет представлено руководство по интеграции SeeDream Images Generation API, которое позволяет генерировать изображения с помощью официального SeeDream, используя пользовательские параметры.

## Процесс получения доступа

Чтобы использовать SeeDream Images Generation API, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications), чтобы получить свой API Token и сохранить его для дальнейшего использования.

![]()

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа с предложением зарегистрироваться или авторизоваться. После завершения этого процесса вы автоматически вернётесь на текущую страницу.

**Одного API Token достаточно для вызова всех сервисов платформы, нет необходимости отдельно подавать заявку на каждый сервис.** При первой подаче заявки предоставляется бесплатный лимит для ознакомления с сервисом; если лимита недостаточно, вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [SeeDream Images Generation API →](https://platform.acedata.cloud/documents/seedream-images)

## Выбор модели

| Модель | Подходящие сценарии использования |
| ----------------------------------------------------------- | ------------------------------- |
| `doubao-seedream-5-5-261028` | Многоэтапное редактирование, генерация прозрачных изображений по тексту, редактирование прозрачных изображений с использованием нескольких референсов, разделение слоёв и распознавание текстовых слоёв |
| `doubao-seedream-5-0-flash-260915` | Генерация одного изображения с низкой задержкой, редактирование с использованием нескольких референсов, редактирование прозрачных изображений и разделение слоёв |
| `doubao-seedream-5-0-pro-260628` | Генерация одного изображения, детальное редактирование, редактирование прозрачных изображений и разделение слоёв |
| `doubao-seedream-5-0-lite-260128` | Одно изображение, набор изображений, потоковая выдача и поиск в интернете |
| `doubao-seedream-4-5-251128` / `doubao-seedream-4-0-250828` | Предыдущие версии генерации и редактирования изображений |

Модели 5.5 и 5.0 Flash используют один и тот же `POST /seedream/images`, обе поддерживают `1K`, `1.5K`, `2K` и до 10 референсных изображений. Задачи разделения слоёв для обеих моделей принимают только одно изображение и возвращают URL. Для 5.5 можно установить `layer_decomposition_options: {"max_images": 12, "text_recognition": true}`. Максимальное количество выходных изображений — 100 (включая исходное изображение). Распознаваемые текстовые слои возвращают построчный текст и стили в `data[].text_recognition`. 5.0 Flash возвращает максимум 1 исходное изображение и 16 слоёв.

5.5 поддерживает непосредственную генерацию прозрачных PNG с помощью `background: "transparent"`. Для редактирования прозрачных изображений в 5.0 Flash требуется референсное изображение с альфа-каналом. 5.5 взимает плату в зависимости от пиксельного разрешения успешно созданного изображения, а также дополнительно 0.13 Credits за каждое входное референсное изображение. 5.0 Flash взимает 0.31 Credits за каждое успешно созданное изображение, референсные изображения бесплатны. Разделение слоёв оплачивается исходя из фактического количества успешно созданных изображений, включая исходное изображение. См. [Актуальные цены](https://platform.acedata.cloud/services/seedream?tab=pricing).

## Основное использование

Сначала ознакомимся с основным способом использования: достаточно ввести текстовый запрос `prompt`, действие генерации `action` и размер изображения `size`, чтобы получить обработанный результат. Для начала необходимо просто передать поле `action` со значением `generate`, затем также нужно ввести текстовый запрос. Конкретное содержимое выглядит следующим образом:

<p><img src="https://cdn.acedata.cloud/seedream_request_body.png" width="500" className="m-auto" /></p>

Как видно, здесь мы настроили Request Headers, включая:

- `accept`: формат ответа, который вы хотите получить. Здесь указано `application/json`, то есть формат JSON.
- `authorization`: ключ API для вызова сервиса. После получения ключа его можно выбрать непосредственно из выпадающего списка.

Кроме того, настроен Request Body, включающий:

- `prompt`: текстовый запрос.
- `model`: передайте полный идентификатор модели из таблицы выше.
- `image`: URL изображения, строка Base64 или массив. 5.5, 5.0 Pro и 5.0 Flash поддерживают до 10 референсных изображений.
- `size`: разрешение или `ширинаxвысота`. 5.5, 5.0 Pro и 5.0 Flash поддерживают `1K`, `1.5K`, `2K`. 5.0 Lite поддерживает `2K`, `3K`, `4K`.
- `sequential_image_generation`: генерация набора изображений: создание группы связанных между собой изображений на основе введённого вами содержимого. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` поддерживают этот параметр, значение по умолчанию — `disabled`.
- `stream`: управление включением режима потоковой выдачи. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` поддерживают этот параметр, значение по умолчанию — `false`.
- `response_format`: указание формата возвращаемого сгенерированного изображения. По умолчанию используется `url`, также поддерживается `b64_json`.
- `watermark`: определяет, следует ли добавлять водяной знак на сгенерированное изображение. По умолчанию — `true`.
- `output_format`: формат вывода — `jpeg` или `png`. Для 5.5 по умолчанию используется PNG, для 5.0 Pro/Flash/Lite — JPEG.
- `tools`: настройка инструментов, которые должна вызывать модель. В настоящее время поддерживается `web_search` (поиск в интернете). Поддерживается только Seedream 5.0 Lite.
- `optimize_prompt_options`: настройки оптимизации текстового запроса. 5.0 Pro поддерживает `standard`/`fast`; 5.5, 5.0 Flash, 5.0 Lite и 4.5 поддерживают только `standard`; 4.0 поддерживает `standard`/`fast`.
- `background`: поддерживает значения `transparent` и `opaque`. 5.5 дополнительно поддерживает `auto`. Для прозрачного вывода используется PNG.
- `layer_decomposition`: поддерживается моделями 5.5, 5.0 Pro и 5.0 Flash. При установке значения `true` необходимо передать одно изображение PNG/JPEG. Можно не передавать `prompt`, чтобы выполнить автоматическое разделение, либо указать элементы с помощью естественного языка/`<bbox>`. Параметр `size` поддерживает `auto`/`1K`/`1.5K`/`2K`. Этот режим нельзя использовать одновременно с генерацией набора изображений, потоковой выдачей, поиском в интернете или `background`.
- `callback_url`: URL для получения результата обратного вызова.
- `async`: определяет, следует ли обрабатывать запрос в асинхронном режиме. При установке значения `true` интерфейс немедленно возвращает `task_id`, при этом указывать `callback_url` не требуется. Затем результат можно получить путём опроса через `/seedream/tasks`.

После выбора можно увидеть, что справа также сгенерирован соответствующий код, как показано на рисунке:

```json
    }
  ]

```

Возвращаемый результат содержит несколько полей, описание которых приведено ниже:

- `success` — текущий статус задачи генерации видео.
- `task_id` — идентификатор задачи генерации видео.
- `trace_id` — идентификатор отслеживания генерации видео.
- `data` — список результатов задачи генерации изображений.
  - `image_url` — ссылка на сгенерированное изображение.
  - `prompt` — текстовый запрос.
  - `size` — разрешение сгенерированного изображения в пикселях.

Как видите, мы получили удовлетворительную информацию об изображении. Нам нужно лишь получить сгенерированное изображение SeeDream по ссылке на изображение из поля `data` в результате.

Кроме того, если вы хотите сгенерировать соответствующий код для интеграции, его можно просто скопировать. Например, код CURL выглядит следующим образом:

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "doubao-seedream-5-0-lite-260128",
  "prompt": "A single matte blue cube centered on a clean white studio background, neutral lighting"
}'
```

## Задача редактирования изображений

Если вы хотите отредактировать определённое изображение, прежде всего необходимо передать ссылку на изображение, которое требуется отредактировать, в параметре `image`.

- model: укажите полный ID модели, поддерживающей редактирование изображений, из таблицы выше.
- image: загрузите изображение, которое необходимо отредактировать, одно или несколько.

Пример заполнения выглядит следующим образом:

<p><img src="https://cdn.acedata.cloud/seedream_edit.png" width="500" className="m-auto" /></p>

Соответствующий код:

```python
import requests

url = "https://api.acedata.cloud/seedream/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedream-4-0-250828",
  "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
  "image": ["https://ark-project.tos-cn-beijing.volces.com/doc_image/seedream4_5_imageToimage.png"],
  "size": "2K",
  "watermark": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Нажав «Запустить», вы увидите, что результат будет получен немедленно, как показано ниже:

```json
{
  "success": true,
  "task_id": "c9aaffa2-b8ac-40ff-8468-43e77cb9ddde",
  "trace_id": "131a40c3-2eaf-44c9-af28-c9b408577286",
  "data": [
    {
      "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
      "size": "2048x2048",
      "image_url": "https://platform.cdn.acedata.cloud/seedream/3e88db7e-4771-4f6a-adbd-5ae4590c5d59.jpg"
    }
  ]
}
```

Как видите, результат представляет собой отредактированную версию исходного изображения, аналогично результату, рассмотренному выше.

## Разделение на слои (Seedream 5.0 Pro)

Разделение на слои преобразует одно входное изображение в 1 фоновое изображение и до 16 отдельных редактируемых прозрачных PNG-слоёв. В следующем запросе модель автоматически распознаёт основные элементы; если необходимо указать конкретные элементы, можно добавить `prompt`, а также использовать нормализованные координаты `<bbox>` в текстовом запросе.

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "https://example.com/poster.png",
  "layer_decomposition": true,
  "size": "2K",
  "watermark": false
}'
```

Возвращаемые данные `data` упорядочены снизу вверх по `z_index`. Фоновое изображение имеет `z_index`, равный 0; слои также содержат поля `name`, `description` и `bounding_box.absolute`/`normalized`. При повторной сборке с использованием абсолютных координат измените размер слоя до `[right-left, bottom-top]`, разместите его в точке `[left, top]`, а затем наложите слои в порядке возрастания `z_index`. Если генерация любого слоя завершится неудачей, вся операция разделения завершится ошибкой.

## Потоковая передача результатов

При установке `stream: true` для Lite/4.x в заголовке запроса необходимо использовать `accept: application/x-ndjson`. Интерфейс построчно возвращает события `image_generation.partial_succeeded` или `image_generation.partial_failed`, а в конце возвращает единственное событие `image_generation.completed` с итоговым значением `usage`; списание средств происходит только один раз при получении события завершения. Потоковый режим нельзя использовать совместно с `async` или `callback_url`.

## Асинхронный обратный вызов

Поскольку генерация через SeeDream Images Generation API занимает относительно много времени, примерно 1–2 минуты, при длительном отсутствии ответа от API HTTP-запрос будет продолжать удерживать соединение, что приведёт к дополнительному расходу системных ресурсов. Поэтому данный API также поддерживает асинхронные обратные вызовы.

Общий процесс выглядит следующим образом: при отправке запроса клиент дополнительно указывает поле `callback_url`. После отправки API-запроса API немедленно возвращает результат, содержащий поле `task_id`, которое представляет собой идентификатор текущей задачи. Когда задача будет завершена, результат генерации изображения будет отправлен клиенту в виде POST JSON на указанный `callback_url`. В нём также будет содержаться поле `task_id`, благодаря чему результат задачи можно будет связать с ней по идентификатору.

Если у вас нет общедоступного сетевого адреса для обратного вызова, вы также можете не указывать `callback_url`, а вместо этого установить поле `async` в запросе в значение `true`. В этом случае интерфейс также немедленно вернёт `task_id`, но результат не будет отправлен автоматически. Вам потребуется передавать этот `task_id` в интерфейс `/seedream/tasks`, чтобы периодически проверять статус задачи и получать окончательный результат.

Далее рассмотрим на примере, как именно это работает.

Нажав «Запустить», вы увидите, что результат будет получен немедленно, как показано ниже:

```
{
  "task_id": "c9aaffa2-b8ac-40ff-8468-43e77cb9ddde"
}
```

Содержимое выглядит следующим образом:
```json
{
    "success": true,
    "task_id": "c9aaffa2-b8ac-40ff-8468-43e77cb9ddde",
    "trace_id": "131a40c3-2eaf-44c9-af28-c9b408577286",
    "data": [
        {
            "prompt": "Сохраните позу модели и плавную форму струящейся жидкой одежды без изменений. Измените материал одежды с серебристого металла на полностью прозрачную воду (или стекло). Сквозь поток жидкости должны быть видны детали кожи модели. Эффект света и тени должен измениться с отражения на преломление.",
            "size": "2048x2048",
```

Как видно, в результате присутствует поле `task_id`, остальные поля аналогичны описанным выше. С помощью этого поля можно связать задачи между собой.

## Обработка ошибок

При вызове API в случае возникновения ошибки API возвращает соответствующий код и сообщение об ошибке. Например:

- `400 token_mismatched`: Неверный запрос, возможно, отсутствуют или указаны недопустимые параметры.
- `400 api_not_implemented`: Неверный запрос, возможно, отсутствуют или указаны недопустимые параметры.
- `401 invalid_token`: Неавторизованный доступ, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`: Слишком много запросов, превышен лимит частоты запросов.
- `500 api_error`: Внутренняя ошибка сервера, что-то пошло не так на сервере.

### Пример ответа с ошибкой

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
