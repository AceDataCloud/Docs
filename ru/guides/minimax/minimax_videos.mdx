В этой статье описывается интеграция и использование API генерации видео MiniMax H3. Этот интерфейс поддерживает генерацию видео на основе текста, управление первыми и последними кадрами, а также многомодальную генерацию видео, используя единую структуру `content` V2 для создания задач.

## Процесс подачи заявки

Чтобы использовать API генерации видео MiniMax H3, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications) и получите ваш API Token для резервного копирования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы еще не вошли в систему или не зарегистрированы, вы будете автоматически перенаправлены на страницу входа, где вас пригласят зарегистрироваться и войти. После завершения вы будете автоматически возвращены на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, не нужно отдельно запрашивать для каждого сервиса.** При первом запросе предоставляется бесплатный лимит, чтобы вы могли попробовать; если лимит исчерпан, вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [API генерации видео MiniMax H3 →](https://platform.acedata.cloud/documents/minimax-videos-integration)

Рекомендуется сохранить Token в виде переменной окружения, не записывайте его в исходный код и не отправляйте в репозиторий:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Обзор интерфейса

- **Базовый URL**: `https://api.acedata.cloud`
- **Конечная точка**: `POST /minimax/videos`
- **Метод аутентификации**: HTTP заголовок с `authorization: Bearer {token}`
- **Заголовки запроса**:
  - `accept: application/json`
  - `content-type: application/json`
- **Модель (model)**: `MiniMax-H3`
- **Структура ввода**: передача текста, изображений, видео и аудио через `content`
- **Режим вывода**: по умолчанию синхронное ожидание завершения генерации и возврат полного `task`; при передаче `async: true` или `callback_url` сразу возвращается `task_id` и `trace_id`
- **Запрос результатов**: получение статуса и готового видео через [API запроса задач MiniMax H3](/documents/minimax-tasks-integration)
- **Асинхронный обратный вызов**: опционально, получение окончательных результатов задачи через `callback_url`

Вам не нужно передавать `action` для выбора режима генерации, интерфейс автоматически определит назначение на основе типов материалов и `role` в `content`.

## Подходящие сценарии

| Сценарий         | Комбинация ввода                  | Распространенные применения                      |
| -------------- | --------------------- | ------------------------- |
| Генерация видео на основе текста       | Текст                    | Рекламные идеи, репетиции сцен, короткие видео, атмосферные кадры        |
| Генерация видео с первым кадром     | Текст + первое изображение             | Придание естественного движения изображения товара, постера, фотографии персонажа или иллюстрации      |
| Генерация видео с последним/первым кадром | Текст + последнее изображение, или текст + первое + последнее изображение | Управление началом и концом видео, переходами, изменениями и сравнением до и после      |
| Генерация видео с многомодальной ссылкой   | Текст + ссылочные изображения / видео / аудио   | Сохранение согласованности персонажей и продуктов, воспроизведение движений, ракурсов, тембра или ритма монтажа |

## Процесс вызова

По умолчанию, если не передавать `async`, `/minimax/videos` будет ожидать завершения генерации и сразу возвращать полный `task`. Если необходимо немедленно освободить соединение, передайте `async: true` или `callback_url`:

1. Сохраните `task_id` и `trace_id` из немедленного ответа.
2. Если обратный вызов не настроен, вызывайте `/minimax/tasks` для проверки статуса примерно каждые 10 секунд.
3. Когда `task.status` изменится на `succeeded`, получите видео из `task.content.url`.
4. Когда статус будет `failed` или `cancelled`, остановите опрос и прочитайте `task.error`.

## Параметры верхнего уровня запроса

| Параметр             | Тип       | Обязательный | Значение по умолчанию | Описание                                                |
| -------------- | -------- | ---- | ---------- | ------------------------------------------------- |
| `model`        | string   | Да    | -          | Фиксировано как `MiniMax-H3`                                  |
| `content`      | object[] | Да    | -          | Массив многомодального контента, должен содержать один непустой элемент `text`                         |
| `resolution`   | string   | Да    | -          | `768P` или `2K`                                     |
| `duration`     | integer  | Да    | -          | Длительность генерации, целое число от 4 до 15 секунд                                     |
| `ratio`        | string   | Условно обязательно | `adaptive` | `adaptive`, `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16` |
| `async`        | boolean  | Нет    | `false`    | При `true` немедленно возвращает идентификатор задачи, результаты можно получить через интерфейс задач                       |
| `callback_url` | string   | Нет    | -          | Публичный URL для обратного вызова, чтобы получить окончательные результаты задачи; при предоставлении автоматически включается асинхронный режим                     |

Правила для `ratio` зависят от рабочего процесса:

- **Генерация видео на основе текста**: обязательно, не может быть `adaptive`.
- **Генерация видео с первым, последним или обоими кадрами**: соотношение определяется входным изображением, рекомендуется опустить или передать `adaptive`.
- **Генерация видео с многомодальной ссылкой**: может быть опущена, по умолчанию `adaptive`; также можно явно указать фиксированное соотношение.

Интерфейс не принимает устаревшие или совместимые поля, такие как `prompt`, `image_urls`, `audio_urls`, `messages` и `first_frame_image`. При получении таких параметров с ошибкой, пожалуйста, удалите устаревшие поля и перенесите их в `content`; например, замените `"prompt": "котик машет"` на `"content": [{"type": "text", "text": "котик машет"}]`. Не отправляйте одновременно новые и старые форматы.

## Параметры элементов контента

Каждый элемент контента должен иметь `type`, остальные поля определяются типом:

| `type`      | Поля данных            | `role`            | Описание                                     |
| ----------- | --------------- | ----------------- | -------------------------------------- |
| `text`      | `text`          | Не передавать                | Каждый запрос должен содержать один непустой текстовый элемент, максимум 7000 символов             |
| `image_url` | `image_url.url` | `first_frame`     | Первое изображение; если только одно изображение и `role` опущен, также обрабатывается как первое изображение         |
| `image_url` | `image_url.url` | `last_frame`      | Последнее изображение; может использоваться отдельно или в комбинации с `first_frame` для управления началом и концом |
| `image_url` | `image_url.url` | `reference_image` | Ссылочное изображение, персонаж, продукт, одежда, сцена или стиль                    |
| `video_url` | `video_url.url` | `reference_video` | Ссылочное видео для движений, ракурсов, выступлений или структуры монтажа                        |
| `audio_url` | `audio_url.url` | `reference_audio` | Ссылочный звук, диалоги, музыка или ритм                          |

Адреса медиа поддерживают три формы:

- HTTPS URL, доступный из публичной сети, рекомендуется для больших файлов.
- `mm_file://{file_id}`, ссылка на уже загруженный или имеющийся файл.
- Соответствующий типу медиа Base64 data URI. Base64 увеличивает объем примерно на треть, убедитесь, что общий размер запроса не превышает 64 МБ.

## Ограничения по спецификациям и количеству материалов
| Материал | Формат                                      | Ограничение на файл | Размер / Длительность                                               | Ограничение по количеству                  |
| --- | ------------------------------------------- | --------- | --------------------------------------------------------------- | --------------------------- |
| Изображение | JPG, JPEG, PNG, WEBP, HEIC, HEIF                 | Не более 30 МБ | Ширина и высота от 256 до 5760 px; соотношение сторон от 0.4 до 2.5 | Не более 1 первого кадра, не более 1 последнего кадра, не более 9 эталонных изображений |
| Видео | MP4, MOV; H.264/AVC или H.265/HEVC; аудиодорожка AAC или MP3 | Не более 50 МБ | Каждое видео от 2 до 15 секунд, в сумме не более 15 секунд; ширина и высота от 256 до 5760 px; соотношение сторон от 0.4 до 2.5; 23.976-60 fps | Не более 3 эталонных видео                  |
| Аудио | WAV, MP3                                     | Не более 15 МБ | Каждое аудио от 2 до 15 секунд, в сумме не более 15 секунд        | Не более 3 эталонных аудио                  |

В многомодальных эталонных сценах общее количество изображений, видео и аудио не должно превышать 12 файлов. Сцены с первым и последним кадрами и эталонные материалы исключают друг друга: как только используется `reference_image`, `reference_video` или `reference_audio`, нельзя использовать `first_frame` или `last_frame`, и наоборот.

## Демонстрация производственных возможностей

Ниже представлены не концептуальные изображения или временные материалы, а реальные эталонные входные данные и фактический видеовыход официального производственного образца MiniMax H3. Три группы примеров охватывают брендовые короткометражные фильмы, живые повествования и модную электронную коммерцию, что подходит для оценки ключевых возможностей модели в коммерческом производстве.

| Возможности       | Основные наблюдения                    |
| -------- | --------------------------- |
| Согласованность персонажей и лиц | Стабильность черт лица, прически, макияжа и характера персонажа после смены ракурса     |
| Выражение лица     | Эмоции, микроэкспрессии, напряжение и естественные движения головы в крупном плане      |
| Сохранение структуры товара   | Контуры, материалы, способы ношения и зеркальные отражения таких продуктов, как очки и сумки    |
| Исполнение визуала бренда   | Атмосфера сцены, зернистость, цвет, логотип и ритм монтажа должны быть едиными |
| Кинематографическое повествование    | Изменения ракурса, расстановка персонажей, движение камеры, ритм и звук должны формировать завершенные сегменты  |

Здесь "возможности лица" относятся к согласованности внешнего вида персонажей, деталям лица и контролю за выступлениями в процессе генерации видео, а не к распознаванию личности, сравнению лиц или интерфейсам замены лиц.

Это более стабильно, чем обобщенно писать "создать рекламу очков".

## Генерация видео из текста

Когда есть только один текстовый элемент, это видео из текста. Подходит для прямой генерации изображения из креатива, сценария или описания кадра. Подсказки можно организовать в порядке "субъект + действие + сцена + кадр + свет + звук".

```bash
curl -X POST 'https://api.acedata.cloud/minimax/videos' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MiniMax-H3",
    "content": [
      {
        "type": "text",
        "text": "15 секундный рекламный ролик парфюмерии: на черных скалах у побережья рано утром прозрачная бутылка парфюма окружена туманом и морскими волнами. Макросъемка показывает капли воды на бутылке и преломление стекла, камера медленно поднимается от крупного плана продукта к обширному морю; серебристо-голубая палитра, естественный свет, высококлассная сдержанность, в конце фиксируется продукт."
      }
    ],
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }'
```

Режим синхронного выполнения по умолчанию вернет полную задачу после завершения генерации:

```json
{
  "task": {
    "id": "f5977217-ed2c-40da-adbe-93d08235618f",
    "model": "MiniMax-H3",
    "status": "succeeded",
    "content": { "url": "https://cdn.acedata.cloud/minimax/f5977217.mp4" },
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }
}
```

Если в запрос добавить `"async": true`, интерфейс сразу вернет:

```json
{
  "task_id": "f5977217-ed2c-40da-adbe-93d08235618f",
  "trace_id": "trace_7f8c2b1a"
}
```

## Генерация видео с первой рамкой

Пометив изображение как `first_frame`, модель начнет генерацию с этого кадра. Подходит для естественного движения постеров, изображений товаров, концепт-артов и фотографий.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "Персонаж естественно дышит и смотрит в окно, края одежды колышутся от легкого ветра, камера медленно приближается"
    },
    {
      "type": "image_url",
      "image_url": {
        "url": "https://cdn.acedata.cloud/b1c82e4937.png"
      },
      "role": "first_frame"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

## Видео с конечным и начальным кадрами
只提供 `last_frame` может позволить модели естественно сгенерировать до указанного кадра; одновременно предоставляя `first_frame` и `last_frame`, можно четко контролировать начальную и конечную точки. Подходит для переходов, изменений форм, процессов роста или сравнений до и после продукта.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "Девочка естественно растет из детства в юность, время проходит плавно, персонаж всегда находится в центре кадра"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_FIRST_FRAME_URL" },
      "role": "first_frame"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_LAST_FRAME_URL" },
      "role": "last_frame"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

Размеры и соотношение сторон первой и последней рамок должны быть как можно более схожими, положение объекта, композиция и различия в освещении не должны быть слишком большими, так будет легче получить естественный переход.

## Мультимодальные ссылки на видео

Ссылки на материалы могут комбинироваться: ссылки на изображения контролируют внешний вид персонажа или продукта, ссылки на видео контролируют действия и движение камеры, ссылки на аудио контролируют тональность диалогов, музыку или ритм монтажа. В подсказках должно быть четко указано, что должно контролироваться каждым типом материала, чтобы избежать загрузки материалов без указания взаимосвязи.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "Сохраните черты лица, прическу и одежду ссылочного персонажа, выполните модный короткометражный фильм согласно действиям из ссылочного видео; ритм камеры следует за ссылочным аудио, крупный план подчеркивает естественные выражения лица"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_CHARACTER_IMAGE_URL" },
      "role": "reference_image"
    },
    {
      "type": "video_url",
      "video_url": { "url": "YOUR_PERFORMANCE_VIDEO_URL" },
      "role": "reference_video"
    },
    {
      "type": "audio_url",
      "audio_url": { "url": "YOUR_AUDIO_URL" },
      "role": "reference_audio"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

## Уведомления о коллбэках

Передача `callback_url` автоматически включает асинхронный режим: интерфейс создания немедленно возвращает `task_id` и `trace_id`, и после завершения задачи отправляет POST с конечным результатом по этому адресу, структура соответствует ответу на запрос задачи.

Конечный статус в коллбэке может быть `succeeded`, `failed` или `cancelled`. Даже при использовании коллбэка рекомендуется сохранить `task_id`, чтобы иметь возможность активно запрашивать или компенсировать пропущенные уведомления.

## Распространенные ошибки

| HTTP статус-код | Значение           | Рекомендации по обработке                           |
| -------- | ------------ | ------------------------------ |
| `400`    | Ошибка параметров или недопустимая комбинация материалов | Проверьте обязательные поля, `role`, количество и формат материалов          |
| `401`    | Токен отсутствует или недействителен  | Проверьте `Authorization: Bearer ...` |
| `402`    | Недостаточно средств или лимитов      | Пополните общий баланс в консоли                     |
| `422`    | Проверка безопасности контента не пройдена    | Измените подсказки или материалы и повторно отправьте                  |
| `429`    | Слишком много запросов       | Повторите попытку после экспоненциального ожидания; рекомендуется интервал около 10 секунд для опроса задач         |
| `500`    | Сервис временно недоступен      | Сохраните информацию о запросе, повторите попытку позже                    |

Статус `task.status: succeeded` в синхронном ответе означает, что видео было сгенерировано; асинхронное подтверждение только указывает на то, что задача вошла в очередь. Только в случае успешного завершения задачи будет взиматься плата, запросы на проверку задачи бесплатны и не будут повторно взиматься.
