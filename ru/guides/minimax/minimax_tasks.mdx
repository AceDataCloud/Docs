В этой статье описывается интеграция и использование API запроса задач MiniMax H3. Этот интерфейс используется для запроса, массового перечисления или удаления асинхронных задач, созданных [MiniMax H3 Видео Генерация API](/documents/minimax-videos-integration).

## Процесс подачи заявки

Чтобы использовать API запроса задач MiniMax H3, сначала получите ваш API Token в [Ace Data Cloud Консоли](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы еще не вошли в систему или не зарегистрированы, вы будете автоматически перенаправлены на страницу входа, где вас пригласят зарегистрироваться и войти в систему, после чего вы будете автоматически возвращены на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, не нужно отдельно запрашивать для каждого сервиса.** При первом запросе предоставляется бесплатный лимит, чтобы вы могли попробовать; если лимит исчерпан, вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [MiniMax H3 Задача Запрос API →](https://platform.acedata.cloud/documents/minimax-tasks-integration)

При запросе задач следует использовать тот же Token, который использовался для создания этой задачи. Рекомендуется сохранить Token в переменной окружения, не записывайте его в исходный код и не отправляйте в репозиторий:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Обзор интерфейса

- **Базовый URL**: `https://api.acedata.cloud`
- **Конечная точка**: `POST /minimax/tasks`
- **Метод аутентификации**: HTTP заголовок с `authorization: Bearer {token}`
- **Заголовки запроса**:
  - `accept: application/json`
  - `content-type: application/json`
- **Запрос одного задания**: `action=retrieve`, передать `id`
- **Массовый запрос задач**: `action=retrieve_batch`, можно фильтровать по ID задач, диапазону времени и условиям пагинации
- **Удаление задач**: `action=delete`, передать `id`
- **Объяснение тарификации**: Запрос задач бесплатен, не будет повторной тарификации

После создания видео необходимо сохранить `task_id`. Рекомендуется запрашивать каждые 10 секунд, пока задача не перейдет в конечное состояние.

## Параметры запроса

| Параметр              | Тип       | Обязательный | Применимые действия         | Описание                                               |
| --------------------- | --------- | ------------ | -------------------------- | ----------------------------------------------------- |
| `action`              | string    | Нет          | Все                        | `retrieve`, `retrieve_batch` или `delete`; по умолчанию `retrieve` |
| `id`                  | string    | Условно обязательно | `retrieve`, `delete`     | ID одной задачи                                        |
| `ids`                 | string[]  | Нет          | `retrieve_batch`          | Возвращает только указанные ID задач; при пропуске перечисляет задачи по другим условиям |
| `limit`               | integer   | Нет          | `retrieve_batch`          | Максимальное количество задач, возвращаемых в этот раз |
| `offset`              | integer   | Нет          | `retrieve_batch`          | Количество задач, пропускаемых из списка результатов, для пагинации |
| `created_at_min`      | number    | Нет          | `retrieve_batch`          | Нижний предел времени создания, Unix временная метка, в секундах |
| `created_at_max`      | number    | Нет          | `retrieve_batch`          | Верхний предел времени создания, Unix временная метка, в секундах |

Назначение трех действий следующее:

| `action`              | Назначение                          | Обязательные параметры                  | Структура ответа                             |
| --------------------- | ---------------------------------- | -------------------------------------- | ------------------------------------------- |
| `retrieve`            | Запрос статуса и результата одной задачи | `id`                                  | `{ "task": {...} }`                         |
| `retrieve_batch`      | Массовый запрос по ID задач, времени и условиям пагинации | Опционально `ids`, диапазон времени, `offset`, `limit` | `{ "items": [...], "total": number }`     |
| `delete`              | Отмена или удаление записи задачи в зависимости от текущего состояния задачи | `id`                                  | `{ "id": "...", "deleted": true }`        |

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve",
```

## Статус задачи

| `status`    | Значение         | Обработка на клиенте                |
| ----------- | ---------------- | ---------------------------------- |
| `queued`    | В очереди, ожидает выполнения | Продолжайте опрос                   |
| `running`   | В процессе генерации       | Продолжайте опрос                   |
| `succeeded` | Генерация успешна       | Читайте `task.content.url`, остановите опрос |
| `failed`    | Генерация не удалась       | Читайте `task.error`, остановите опрос       |
| `cancelled` | Задача отменена      | Остановите опрос                   |

`succeeded`, `failed` и `cancelled` являются конечными состояниями. Не продолжайте опрос после достижения конечного состояния.

## Поля ответа task

| Поле                        | Тип      | Описание                              |
| --------------------------- | -------- | ------------------------------------- |
| `id`                        | string   | ID задачи                             |
| `model`                     | string   | Модель, используемая для задачи, в настоящее время `MiniMax-H3` |
| `status`                    | string   | Текущий статус задачи                 |
| `error.code`               | string   | Код ошибки при неудаче, возвращается только при неудаче |
| `error.message`            | string   | Причина неудачи, возвращается только при неудаче |
| `created_at`               | integer  | Время создания, Unix временная метка, в секундах |
| `updated_at`               | integer  | Время последнего обновления статуса, Unix временная метка, в секундах |
| `content.url`              | string   | URL видео после успешного завершения  |
| `resolution`                | string   | Выходное разрешение, `768P` или `2K` |
| `duration`                  | integer  | Длительность выходного видео, в секундах |
| `usage.total_seconds`       | integer  | Общая стоимость, равная сумме секунд входного и выходного видео |
| `usage.input_seconds`       | integer  | Стоимость, возникшая из входного видео |
| `usage.output_seconds`      | integer  | Стоимость, возникшая из выходного видео |
| `usage.input_image_count`   | integer  | Количество входных изображений в статистике тарификации |
| `ratio`                     | string   | Фактическое соотношение сторон; при использовании `adaptive` результат здесь считается основным |
| `task_type`                 | string   | Генерация видео задачи `generation`  |
| `modality`                  | string   | Видео задача `video`                 |

## Полный пример опроса на Python
以下代码从环境变量读取 Token，创建任务后每隔 10 秒查询一次：

```python
import os
import time

import requests

BASE_URL = "https://api.acedata.cloud"
HEADERS = {
    "Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_KEY']}",
    "Content-Type": "application/json",
}

create_response = requests.post(
    f"{BASE_URL}/minimax/videos",
    headers=HEADERS,
    json={
        "model": "MiniMax-H3",
        "content": [
            {
                "type": "text",
                "text": "Утром на берегу моря белый парусник плывет по спокойной воде, камера медленно перемещается вбок",
            }
        ],
        "resolution": "768P",
        "duration": 4,
        "ratio": "16:9",
    },
    timeout=30,
)
create_response.raise_for_status()
task_id = create_response.json()["task_id"]

while True:
    time.sleep(10)
    query_response = requests.post(
        f"{BASE_URL}/minimax/tasks",
        headers=HEADERS,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    query_response.raise_for_status()
    task = query_response.json()["task"]
    print(f"task={task_id} status={task['status']}")

    if task["status"] == "succeeded":
        print(f"video_url={task['content']['url']}")
        break
    if task["status"] in ("failed", "cancelled"):
        raise RuntimeError(task.get("error") or task["status"])
```

生产环境应为轮询设置总超时，并对 `429` 和临时 `5xx` 使用指数退避。网络超时不等于生成失败，可以使用同一个 `task_id` 继续查询。

## 批量查询

指定多个任务 ID：

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve_batch",
    "ids": ["TASK_ID_1", "TASK_ID_2"],
    "offset": 0,
    "limit": 20
  }'
```

按时间范围分页列出任务：

```json
{
  "action": "retrieve_batch",
  "created_at_min": 1786000000,
  "created_at_max": 1786200000,
  "offset": 0,
  "limit": 20
}
```

批量响应中的 `items` 使用与单任务查询相同的 task 字段，`total` 是筛选条件匹配的任务总数：

```json
{
  "items": [
    {
      "id": "TASK_ID_1",
      "model": "MiniMax-H3",
      "status": "running",
      "resolution": "2K",
      "duration": 5,
      "ratio": "adaptive",
      "task_type": "generation",
      "modality": "video"
    }
  ],
  "total": 1
}
```

任务查询窗口为最近 7 天。超过该窗口的 `task_id` 可能返回无效任务；业务系统应在创建任务时保存 ID，并在成功后及时持久化结果 URL。

## 取消或删除任务

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "delete",
    "id": "YOUR_TASK_ID"
  }'
```

动作取决于任务当前状态：

| 当前状态        | 行为            |
| ----------- | ------------- |
| `queued`    | 取消尚未开始的任务     |
| `succeeded` | 删除任务记录        |
| `failed`    | 删除任务记录        |
| `running`   | Не разрешается удалять или отменять, возвращает ошибку |
| `cancelled` | Не разрешается повторная операция, возвращает ошибку  |

删除成功示例：

```json
{
  "id": "YOUR_TASK_ID",
  "deleted": true
}
```

删除任务记录不会撤销已经完成的计费，也不能保证已保存的视频副本同时被删除。

## 失败响应与排查

失败任务仍以 HTTP 200 返回 task 对象，并在 `task.error` 中给出原因：

```json
{
  "task": {
    "id": "YOUR_TASK_ID",
    "model": "MiniMax-H3",
    "status": "failed",
    "error": {
      "code": "1026",
      "message": "описание видео содержит чувствительное содержимое"
    },
    "task_type": "generation",
    "modality": "video"
  }
}
```

接口本身返回 `400` 时应检查 `action` 与条件参数，`401` 表示 Token 无效，`429` 表示查询过于频繁，`500` 表示服务暂时不可用。生成失败的任务不计费；成功任务按最终 `usage` 记录用量。
