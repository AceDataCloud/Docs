## Динамический каталог моделей

Сначала можно открыть [каталог моделей](https://platform.acedata.cloud/models), чтобы посмотреть текущие названия моделей, например `claude-opus-5`, `gpt-6-sol`. Если необходимо подтвердить, соответствуют ли учётные данные Coding и протокол API, выполните запрос с действительными учётными данными Coding Application:

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_TOKEN"
```

Каталог моделей будет постоянно меняться, фиксированное количество или статический список моделей в этом документе не поддерживаются. `id` каждой записи в ответе — это **название модели**, которое можно напрямую передать параметру API `model`, например `{"id":"deepseek-v4-pro"}` соответствует значению `deepseek-v4-pro`; это не UUID сервиса, API или Application. `/v1/models` возвращает глобальный каталог моделей и не фильтруется автоматически по учётным данным Coding; перед настройкой всё равно необходимо перекрёстно проверить область API учётных данных, выбранный протокол и диапазон совместимости клиента.

## Распространённые способы устранения неполадок

- **Недостаточно средств**: перейдите в [консоль Applications](https://platform.acedata.cloud/console/applications), найдите Coding Application и вручную продлите покупку.
- **Клиент всё ещё запрашивает исходный адрес**: убедитесь, что конфигурация относится к тому же пользователю и рабочей области, которые запускают клиент, затем полностью закройте и перезапустите клиент.
- **Название модели недоступно**: повторно запросите `/v1/models`, проверьте, что указанное название модели полностью совпадает с `id` в каталоге, а также область API учётных данных и протокол, поддерживаемый клиентом.
- **Token не может вызвать интерфейс**: убедитесь, что учётные данные принадлежат Coding Application, и проверьте `allowed_api_ids` и разрешения API приложения.
