В данной статье будет представлена инструкция по интеграции API для распознавания удостоверений личности и проверки информации, которая позволяет проверить подлинность и соответствие имени и номера удостоверения личности, вводя изображение удостоверения или имя и номер удостоверения. Этот интерфейс предназначен для проверки подлинности и соответствия имени и номера удостоверения, вы можете предоставить необходимую информацию для проверки, введя имя и номер удостоверения или передав фотографию лицевой стороны удостоверения.

## Процесс подачи заявки

Чтобы использовать API для распознавания удостоверений личности и проверки информации, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications), чтобы получить ваш API Token и сохранить его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы еще не вошли в систему или не зарегистрированы, вас автоматически перенаправит на страницу входа, где вас пригласят зарегистрироваться и войти. После завершения вы будете автоматически возвращены на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, не нужно отдельно запрашивать для каждого сервиса.** При первом запросе предоставляется бесплатный лимит, чтобы вы могли попробовать бесплатно; если лимит исчерпан, вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [API для распознавания удостоверений личности и проверки информации →](https://platform.acedata.cloud/documents/identity-idcard-ocr)

## Основное использование

Сначала ознакомьтесь с основным способом использования, который заключается в том, что вы вводите ссылку на изображение удостоверения, и получаете обработанный результат проверки. Сначала необходимо просто передать поле `image_url`, после чего мы можем заполнить соответствующие поля на интерфейсе, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/qxy9rh.png" width="500" className="m-auto" /></p>

Как видно, мы настроили заголовки запроса, включая:

- `accept`: в каком формате вы хотите получить ответ, здесь указано `application/json`, то есть в формате JSON.
- `authorization`: ключ для вызова API, после запроса вы можете выбрать его из выпадающего списка.

Также настроено тело запроса, включая:

- `image_url`: ссылка на изображение удостоверения, которое нужно обработать.
- `encryption`: необязательный параметр шифрования для конфиденциальных полей (если необходимо отправить зашифрованные данные).

После выбора вы можете заметить, что справа также сгенерирован соответствующий код, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/uw90il.png" width="500" className="m-auto" /></p>

Нажмите кнопку «Попробовать», чтобы провести тестирование, как показано на рисунке, и мы получили следующий результат:

```json
{
  "result": "0",
  "description": "Имя и номер удостоверения совпадают",
  "name": "Имя на удостоверении",
  "id_card": "Номер удостоверения",
  "sex": "Пол на удостоверении",
  "nation": "Национальность на удостоверении",
  "birth": "Дата рождения на удостоверении",
  "address": "Домашний адрес на удостоверении"
}
```

Возвращаемый результат содержит несколько полей, описание которых приведено ниже:

- `result`, код результата проверки, условия оплаты следующие.
    - Платные коды результата:
        - 0: Имя и номер удостоверения совпадают
        - -1: Имя и номер удостоверения не совпадают
    - Бесплатные коды результата:
        - -2: Неверный номер удостоверения (длина, контрольная цифра и т.д. некорректны)
        - -3: Неверное имя (длина, формат и т.д. некорректны)
        - -4: Ошибка сервиса базы данных удостоверений
        - -5: Запись об этом удостоверении отсутствует в базе данных
        - -6: Система авторитетного сопоставления обновляется, попробуйте позже
        - -7: Превышено количество проверок за день.
- `description`, результат проверки имени и номера удостоверения.
- `name`, информация о имени на удостоверении, если изображение удостоверения не было загружено, то поле пустое.
- `id_card`, информация о номере удостоверения, если изображение удостоверения не было загружено, то поле пустое.
- `sex`, информация о поле на удостоверении, если изображение удостоверения не было загружено, то поле пустое.
- `nation`, информация о национальности на удостоверении, если изображение удостоверения не было загружено, то поле пустое.
- `birth`, информация о дате рождения на удостоверении, если изображение удостоверения не было загружено, то поле пустое.
- `address`, информация о домашнем адресе на удостоверении, если изображение удостоверения не было загружено, то поле пустое.

Можно увидеть, что информация о имени и номере удостоверения на удостоверении совпадает и является действительной, также использована технология OCR для извлечения другой информации и ее отображения.

Кроме того, если вы хотите сгенерировать соответствующий код интеграции, вы можете просто скопировать его, например, код CURL будет следующим:

```shell
curl -X POST 'https://api.acedata.cloud/identity/idcard/ocr' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": {image_url}
}'
```

Код интеграции на Python будет следующим:

```python
import requests

url = "https://api.acedata.cloud/identity/idcard/ocr"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "image_url": {image_url}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Проверка пользовательской информации

Мы также предоставляем способ проверки, не раскрывая информацию об изображении удостоверения, можно передать только имя `name` и номер удостоверения `id_card` для проверки подлинности и соответствия имени и номера удостоверения. Ниже приведены конкретные заполненные данные:

<p><img src="https://cdn.acedata.cloud/mc5bbw.png" width="500" className="m-auto" /></p>

После нажатия на запуск получаем следующий результат:

```json
{
    "address": "",
    "birth": "",
    "description": "Имя и номер удостоверения совпадают",
    "id_card": "Номер удостоверения",
    "name": "Имя на удостоверении",
    "nation": "",
    "result": "0",
    "sex": ""
 }
```

Таким образом, из результата не раскрываются другие конфиденциальные данные, что также позволяет проверить подлинность и соответствие имени и номера удостоверения.

## Обработка ошибок

При вызове API, если возникнет ошибка, API вернет соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`: Неверный запрос, возможно, из-за отсутствия или недействительных параметров.
- `400 api_not_implemented`: Неверный запрос, возможно, из-за отсутствия или недействительных параметров.
- `401 invalid_token`: Неавторизовано, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`: Слишком много запросов, вы превысили лимит частоты.
- `500 api_error`: Внутренняя ошибка сервера, что-то пошло не так на сервере.

### Пример ответа об ошибке

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
