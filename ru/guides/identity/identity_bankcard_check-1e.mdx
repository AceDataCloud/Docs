В этой статье будет представлена инструкция по интеграции API для запроса базовой информации о банковской карте, который можно использовать для получения базовой информации о банковской карте.

## Процесс подачи заявки

Чтобы использовать API для запроса базовой информации о банковской карте, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications), чтобы получить ваш API Token и сохранить его на всякий случай.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы еще не вошли в систему или не зарегистрированы, вы будете автоматически перенаправлены на страницу входа, где вас пригласят зарегистрироваться и войти. После завершения вы будете автоматически возвращены на текущую страницу.

**Один API Token позволяет использовать все услуги платформы, не нужно запрашивать отдельный токен для каждой услуги.** При первом запросе предоставляется бесплатный лимит, который можно использовать бесплатно; если лимит исчерпан, вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [API для запроса базовой информации о банковской карте →](https://platform.acedata.cloud/documents/identity-bankcard-check-1e)

## Основное использование

Сначала ознакомьтесь с основным способом использования, который заключается в том, что вы вводите номер банковской карты и получаете обработанный результат проверки. Сначала необходимо просто передать поле `bank_card`, после чего мы можем заполнить соответствующее содержимое на интерфейсе, как показано на изображении:

<p><img src="https://cdn.acedata.cloud/h41nrh.png" width="500" className="m-auto" /></p>

Как видно, мы настроили заголовки запроса, включая:

- `accept`: формат ответа, который вы хотите получить, здесь указано `application/json`, то есть формат JSON.
- `authorization`: ключ для вызова API, который можно выбрать из выпадающего списка после запроса.

Также настроено тело запроса, включая:

- `bank_card`: номер банковской карты.
- `encryption`: необязательный параметр шифрования для чувствительных данных (если необходимо отправить зашифрованные данные).

После выбора вы можете заметить, что справа также сгенерирован соответствующий код, как показано на изображении:

<p><img src="https://cdn.acedata.cloud/grfra7.png" width="500" className="m-auto" /></p>

Нажмите кнопку «Попробовать», чтобы провести тестирование, как показано на изображении, и вы получите следующий результат:

```json
{
  "result": "0",
  "description": "Запрос выполнен успешно",
  "account_bank": "Промышленный и коммерческий банк Китая",
  "account_type": 1
}
```

Возвращаемый результат содержит несколько полей, описание которых приведено ниже:

- `result`, код результата проверки, условия оплаты следующие.
    - Код результата оплаты:
        - 0: Запрос выполнен успешно
        - -1: Информация не найдена
    - Код без оплаты:
        - -2: Служба проверки занята
        - -3: Банковская карта не существует
- `description`, описание результата операции.
- `account_bank`, банк, в котором открыт счет.
- `account_type`, тип карты: 1. Дебетовая карта; 2. Кредитная карта; 3. Предоплаченная карта; 4. Карта с возможностью овердрафта.

Можно увидеть, что базовая информация о банковской карте уже получена.

Кроме того, если вы хотите сгенерировать соответствующий код интеграции, вы можете просто скопировать его, например, код CURL выглядит следующим образом:

```shell
curl -X POST 'https://api.acedata.cloud/identity/bankcard/check-1e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "bank_card": "****"
}'
```

Код интеграции на Python выглядит следующим образом:

```python
import requests

url = "https://api.acedata.cloud/identity/bankcard/check-1e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "bank_card": "****"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Обработка ошибок

При вызове API, если возникнет ошибка, API вернет соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`: Неверный запрос, возможно, из-за отсутствия или недействительных параметров.
- `400 api_not_implemented`: Неверный запрос, возможно, из-за отсутствия или недействительных параметров.
- `401 invalid_token`: Неавторизовано, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`: Слишком много запросов, вы превысили лимит частоты.
- `500 api_error`: Внутренняя ошибка сервера, что-то пошло не так на сервере.

### Пример ответа об ошибке

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "не удалось получить данные"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
