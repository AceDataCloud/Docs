В этой статье будет представлена инструкция по интеграции Producer Audios Generation API, который позволяет генерировать официальную музыку Producer с помощью ввода пользовательских параметров.

## Процесс подачи заявки

Чтобы использовать Producer Audios Generation API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти в систему; после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первой заявке предоставляется бесплатный лимит, позволяющий бесплатно опробовать сервис; если лимита недостаточно, вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Выбор обязательных параметров по операции

При `action=generate` и `custom=false` (по умолчанию) укажите `prompt`; при `custom=true`
и `instrumental=false` укажите `lyric`. Для пользовательской инструментальной музыки можно установить
`custom=true, instrumental=true`, без необходимости выдумывать текст песни или дополнительные подсказки.
Для `action=extend` требуются `audio_id` и `continue_at` больше 0, а в неинструментальном режиме также требуется
`lyric`. Кавер, вариант, замена фрагмента, обмен вокальными партиями и разделение аудиодорожек — всё это требует исходный `audio_id`;
текст песни и подсказки не должны быть безусловно обязательными для всех операций.

В MCP `producer_extend_music` и `producer_replace_section` при передаче `lyric`
выбирают режим пользовательского текста песни; для продолжения инструментальной музыки можно передать `instrumental=true` и не указывать текст песни.

## Базовое использование

О какой бы песне вы ни подумали, можно произвольно ввести какой-либо текст, например, если я хочу сгенерировать песню о Рождестве, можно ввести `a song for Christmas`, как показано на изображении:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Можно увидеть, что здесь мы установили Request Headers, включая:

- `accept`: в каком формате вы хотите получить результат ответа, здесь указано `application/json`, то есть формат JSON.
- `authorization`: ключ для вызова API, после подачи заявки можно напрямую выбрать из выпадающего списка.

Кроме того, параметры Request Body включают:

- `action`: действие для этой задачи генерации музыки, для генерации песни используется `generate`.
- `model`: модель, используемая для создания песни, в настоящее время основные модели: **FUZZ-2.0 Pro**、**FUZZ-2.0**、**FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**、**FUZZ-1.0 Pro**、**FUZZ-1.0**、**FUZZ-1.1**、**FUZZ-0.8**.
- `lyric`: содержание текста песни.
- `custom`: использовать ли пользовательский способ генерации песни.
- `prompt`: подсказка в режиме вдохновения.
- `title`: информация о названии песни.
- `audio_id`: ID эталонной песни, используется для продолжения/кавера и других операций.
- `continue_at`: продолжить песню с указанной секунды.
- `replace_section_start`/`replace_section_end`: время начала и окончания заменяемого фрагмента, в секундах.
- `lyrics_strength`: сила текста песни, обозначает степень влияния текста песни на генерацию аудио, может быть от 0 до 1, по умолчанию 0.7.
- `sound_strength`: сила аудиоподсказки, может быть от 0.2 до 1, по умолчанию 0.7.
- `cover_strength`: сила кавера от 0.2 до 1, по умолчанию 1.
- `weirdness`: степень необычности стиля, может быть от 0 до 1, по умолчанию 0.5
- `callback_url`: URL, на который необходимо получить результат обратного вызова.
- `async`: необязательно; при установке в `true` интерфейс немедленно возвращает `task_id`, не требуется указывать `callback_url`, после чего результат получается путём опроса соответствующего интерфейса запроса задач.
- `instrumental`: является ли режимом без текста песни.

Кроме того, если вы хотите сгенерировать соответствующий код интеграции, можно напрямую скопировать сгенерированный код, например, код CURL выглядит следующим образом:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Кавер-версия песни

Если вы хотите выполнить операцию создания кавер-версии для уже сгенерированной песни, можно ввести сгенерированную выше песню для создания кавер-версии; далее мы будем пользовательским образом генерировать песню на основе текста и названия.

Если вы хотите продолжить создавать кавер-версию для самостоятельно загруженной песни, можно установить параметр `action` в значение `upload_cover` и ввести ID пользовательской загруженной песни, для которой необходимо продолжить создание кавер-версии. Получение ID песни осуществляется с помощью [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), как показано на изображении ниже:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Можно указать следующее:

- action：действие задачи песни; в настоящее время поддерживаются: generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation; для этой кавер-версии используется параметр `cover`.
- lyric：текст песни
- title：название песни.
- custom：следует ли генерировать с использованием пользовательского режима; по умолчанию — false.
- audio_id：ID песни, для которой необходимо создать кавер-версию.

## Продолжение песни

Если вы хотите продолжить собственную загруженную песню, можно установить параметр `action` в значение `upload_extend`, а также ввести ID собственной загруженной песни, которую нужно продолжить. ## Асинхронный обратный вызов

Поскольку время генерации Producer Audios Generation API иногда может быть относительно долгим, если API долго не отвечает, HTTP-запрос будет постоянно поддерживать соединение, что приводит к дополнительному расходу системных ресурсов, поэтому данный API также предоставляет поддержку асинхронных обратных вызовов.

Общий процесс таков: когда клиент инициирует запрос, он дополнительно указывает поле `callback_url`, после того как клиент инициирует API-запрос, API немедленно вернёт результат, содержащий информацию о поле `task_id`, которое представляет ID текущей задачи. После завершения задачи результат задачи генерации будет отправлен в виде POST JSON на указанный клиентом `callback_url`, в котором также будет содержаться поле `task_id`, таким образом результаты задачи можно связать по ID.

Далее мы на примере узнаем, как именно это сделать.

Прежде всего, обратный вызов Webhook — это сервис, способный принимать HTTP-запросы, разработчик должен заменить его на URL собственного развёрнутого HTTP-сервера. Здесь для удобства демонстрации используется публичный сайт-пример Webhook [https://webhook.site/](https://webhook.site/), открыв этот сайт, можно получить Webhook URL, как показано на рисунке:

![](https://cdn.acedata.cloud/tbcnai.png)

Скопировав этот URL, его можно использовать как Webhook, пример здесь: [https://webhook.site/#!/view/0d73431d-f833-4be4-9276-b6e1690d55c1](https://webhook.site/#!/view/0d73431d-f833-4be4-9276-b6e1690d55c1).

Далее мы можем установить поле `callback_url` в указанный выше Webhook URL, одновременно заполнив соответствующие параметры, конкретное содержимое показано на рисунке:

<p><img src="https://cdn.acedata.cloud/wuzd4y.png" width="500" className="m-auto" /></p>

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Неверный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `400 api_not_implemented`：Неверный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `401 invalid_token`：Не авторизован, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили ограничение частоты.
- `500 api_error`：Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
