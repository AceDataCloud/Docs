В этой статье будет представлено описание интеграции Producer Audios Generation API, с помощью которого можно генерировать официальную музыку Producer, вводя пользовательские параметры.

## Процесс подачи заявки

Чтобы использовать Producer Audios Generation API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти, после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первой заявке предоставляется бесплатный лимит, который можно использовать для бесплатного ознакомления; при недостаточном лимите можно пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Выбор обязательных параметров в зависимости от операции

При `action=generate` и `custom=false` (по умолчанию) укажите `prompt`; при `custom=true`
и `instrumental=false` укажите `lyric`. Для пользовательской инструментальной музыки можно установить
`custom=true, instrumental=true`, без необходимости выдумывать текст или дополнительные подсказки.
Для `action=extend` требуются `audio_id` и `continue_at` больше 0, а в неинструментальном режиме также требуется
`lyric`. Кавер, вариант, замена фрагмента, обмен голосовыми партиями и разделение аудиодорожек требуют исходный `audio_id`;
текст и подсказки не должны быть безусловно обязательными для всех операций.

В MCP `producer_extend_music` и `producer_replace_section` при указании `lyric`
выберут режим пользовательского текста; для продолжения инструментальной музыки можно передать `instrumental=true` и не указывать текст.

## Базовое использование

О какой бы песне вы ни думали, можно произвольно ввести фрагмент текста, например, если я хочу сгенерировать песню о Рождестве, можно ввести `a song for Christmas`, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Можно увидеть, что здесь мы настроили Request Headers, включая:

- `accept`: в каком формате вы хотите получить результат ответа, здесь указано `application/json`, то есть формат JSON.
- `authorization`: ключ для вызова API, после подачи заявки его можно напрямую выбрать из выпадающего списка.

Кроме того, параметры Request Body включают:

- `action`: действие данной задачи генерации музыки, для генерации песни используется `generate`.
- `model`: модель, используемая для создания песни, в настоящее время основные: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: содержание текста песни.
- `custom`: использовать ли пользовательский способ для генерации песни.
- `prompt`: подсказка в режиме вдохновения.
- `title`: информация о названии песни.
- `audio_id`: ID эталонной песни, используется для продолжения/кавера и других операций.
- `continue_at`: продолжить песню с указанной секунды.
- `replace_section_start`/`replace_section_end`: время начала и окончания заменяемого фрагмента, в секундах.
- `lyrics_strength`: сила текста, обозначает степень влияния текста на генерацию аудио, доступный диапазон 0–1, по умолчанию 0.5.
- `sound_strength`: сила аудиоподсказки, доступный диапазон 0.2–1, по умолчанию 0.5.
- `cover_strength`: сила кавера в диапазоне 0.2–1, по умолчанию 1.
- `weirdness`: степень необычности стиля, доступный диапазон 0–1, по умолчанию 0.5
- `callback_url`: URL, на который необходимо вернуть результат обратного вызова.
- `async`: необязательно; когда установлено `true`, интерфейс немедленно возвращает `task_id`, нет необходимости предоставлять `callback_url`, после чего результат можно получить, опрашивая соответствующий интерфейс запроса задач.
- `instrumental`: является ли это режимом без текста.

Можно увидеть, что мы получили информацию о желаемой сгенерированной музыке, нам нужно лишь получить сгенерированную музыку Producer по адресу ссылки на музыку в `data` результата.

Кроме того, если вы хотите сгенерировать соответствующий код интеграции, можно напрямую скопировать сгенерированный код, например, код CURL выглядит следующим образом:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Кавер-версии песен

Если вы хотите выполнить операцию создания кавер-версии для уже сгенерированной песни, можно ввести сгенерированную выше песню для создания кавер-версии; далее мы будем пользовательским образом генерировать песню на основе текста и названия.

Если вы хотите продолжить создание кавер-версии для самостоятельно загруженной песни, можно установить параметр `action` в значение `upload_cover` и ввести ID самостоятельно загруженной песни, для которой требуется продолжить создание кавер-версии. Получить ID песни можно с помощью [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), как показано на изображении ниже:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Можно указать следующее содержимое:

- action：действие данной задачи песни; в настоящее время поддерживаются: generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation; для этой кавер-версии используется параметр `cover`.
- lyric：текст песни
- title：название песни.
- custom：следует ли генерировать в пользовательском режиме; по умолчанию — false.
- audio_id：ID песни, для которой нужно создать кавер-версию.

## Продолжение песни

Если вы хотите продолжить песню, нам необходимо передать значение параметра `action`: `extend`, далее мы можем настраивать генерацию песни на основе текста, названия и стиля.

Если вы хотите продолжить песню, загруженную самостоятельно, можно установить параметр `action` в значение `upload_extend`, а также ввести ID самостоятельно загруженной песни, которую нужно продолжить. ## Асинхронный обратный вызов

Поскольку время генерации Producer Audios Generation API иногда может быть относительно долгим, если API долго не отвечает, HTTP-запрос будет постоянно поддерживать соединение, что приводит к дополнительному потреблению системных ресурсов, поэтому данный API также предоставляет поддержку асинхронного обратного вызова.

Общий процесс таков: когда клиент инициирует запрос, он дополнительно указывает поле `callback_url`; после того как клиент инициирует API-запрос, API немедленно вернёт результат, содержащий информацию о поле `task_id`, которое представляет ID текущей задачи. Когда задача будет завершена, результат задачи генерации будет отправлен в форме POST JSON на указанный клиентом `callback_url`, который также включает поле `task_id`, таким образом результаты задачи можно связать по ID.

Далее мы на примере рассмотрим, как именно это сделать.

Прежде всего, Webhook-обратный вызов — это сервис, способный принимать HTTP-запросы, разработчик должен заменить его URL-адресом самостоятельно развернутого HTTP-сервера. Здесь для удобства демонстрации используется публичный пример Webhook-сайта [https://webhook.site/](https://webhook.site/); открыв этот сайт, можно получить Webhook URL, как показано на изображении:

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Неверный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `400 api_not_implemented`：Неверный запрос, возможно, из-за отсутствующих или недействительных параметров.
- `401 invalid_token`：Не авторизован, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили лимит запросов.
- `500 api_error`：Внутренняя ошибка сервера, что-то пошло не так на сервере.

### Пример ответа с ошибкой

```json
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
