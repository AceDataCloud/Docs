В этой статье будет представлена инструкция по интеграции API генерации аудио Producer, который позволяет генерировать официальную музыку Producer с помощью ввода пользовательских параметров.

## Процесс подачи заявки

Чтобы использовать API, сначала необходимо перейти на страницу [API генерации аудио Producer](https://platform.acedata.cloud/documents/producer-audios) и подать заявку на соответствующую услугу. После перехода на страницу нажмите кнопку «Acquire», как показано на изображении:

![](https://cdn.acedata.cloud/q6ytrc.png)

Если вы еще не вошли в систему или не зарегистрированы, вас автоматически перенаправит на страницу входа, где вас пригласят зарегистрироваться и войти в систему. После регистрации и входа вы автоматически вернетесь на текущую страницу.

При первой подаче заявки будет предоставлен бесплатный лимит, который можно использовать для бесплатного доступа к этому API.

## Основное использование

Если вы хотите создать какую-то песню, вы можете ввести любой текст, например, если я хочу сгенерировать песню о Рождестве, я могу ввести `a song for Christmas`, как показано на изображении:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Как видно, здесь мы настроили заголовки запроса, включая:

- `accept`: формат ответа, который вы хотите получить, здесь указано `application/json`, то есть формат JSON.
- `authorization`: ключ для вызова API, который можно выбрать из выпадающего списка после подачи заявки.

Кроме того, параметры тела запроса включают:

- `action`: действие для этой задачи генерации музыки, для генерации песни это `generate`.
- `model`: модель, используемая для создания песни, в настоящее время доступны: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**, **FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: текст песни.
- `custom`: использовать ли пользовательский способ генерации песни.
- `prompt`: подсказка в режиме вдохновения.
- `title`: информация о заголовке песни.
- `audio_id`: ID референсной песни, используемый для продолжения/перепевания и т.д.
- `continue_at`: продолжить написание песни с указанной секунды.
- `replace_section_start`/`replace_section_end`: время начала и окончания замены фрагмента, в секундах.
- `lyrics_strength`: сила текста, указывающая на степень влияния текста на генерацию аудио, может быть от 0 до 1, по умолчанию 0.7.
- `sound_strength`: сила подсказки для аудио, может быть от 0.2 до 1, по умолчанию 0.7.
- `cover_strength`: сила кавера от 0.2 до 1, по умолчанию 1.
- `weirdness`: степень необычности стиля, может быть от 0 до 1, по умолчанию 0.5.
- `callback_url`: URL для обратного вызова результата.
- `instrumental`: является ли это режимом без текста.

Как видно, мы получили информацию о желаемой музыке, и нам нужно просто получить сгенерированную музыку Producer по ссылке на аудио из результата `data`.

Кроме того, если вы хотите сгенерировать соответствующий код интеграции, вы можете просто скопировать его, например, код CURL будет следующим:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Перепевка песни

Если вы хотите перепеть уже сгенерированную песню, вы можете ввести текст песни, сгенерированный выше, для перепевки, далее мы будем настраивать создание песни на основе текста и заголовка.

Если вы хотите продолжить перепевку своей загруженной песни, вы можете установить параметр `action` в значение `upload_cover` и ввести ID песни, которую нужно продолжить перепевать. ID песни можно получить с помощью [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), как показано на следующем изображении:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Вы можете указать следующее содержимое:

- action: действие для этой задачи с песней, в настоящее время поддерживаются: generate, cover, extend, upload_cover, upload_extend, replace_section, swap_vocals, swap_instrumentals, variation, для этой перепевки используется параметр `cover`.
- lyric: текст песни
- title: заголовок песни.
- custom: использовать ли режим пользовательского создания, по умолчанию false.
- audio_id: ID песни, которую нужно перепеть.

## Продолжение песни

Если вы хотите продолжить песню, нам нужно передать параметр `action` со значением: `extend`, затем мы должны сгенерировать песню на основе текста, заголовка и стиля.

Если вы хотите продолжить свою загруженную песню, вы можете установить параметр `action` в значение `upload_extend` и ввести ID загруженной песни, ID песни можно получить с помощью [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), как показано на рисунке ниже:

Соответствующий код:

```shell

-H 'accept: application/json' \

-H 'content-type: application/json' \
-d '{
```

## Разделение текста и музыки

<p><img src="https://cdn.acedata.cloud/oq5iv5.png" width="500" class="m-auto"></p>

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "stems",
  "audio_id": "a54609c6-13e2-4176-be0f-4d7eebc68e1f"
}'
```

## Асинхронный обратный вызов

Поскольку время генерации API Producer Audios Generation иногда может быть относительно долгим, если API долго не отвечает, HTTP-запрос будет постоянно поддерживать соединение, что приведет к дополнительному потреблению системных ресурсов, поэтому этот API также предоставляет поддержку асинхронного обратного вызова.

Общий процесс: когда клиент инициирует запрос, дополнительно указывается поле `callback_url`, после того как клиент инициирует API-запрос, API немедленно возвращает результат, содержащий информацию о поле `task_id`, представляющем текущий ID задачи. Когда задача завершена, результат генерации задачи будет отправлен на указанный клиентом `callback_url` в формате POST JSON, в котором также включено поле `task_id`, так что результат задачи можно связать по ID.

Давайте рассмотрим, как это работает на примере.

Во-первых, обратный вызов Webhook - это служба, которая может принимать HTTP-запросы, разработчики должны заменить ее на URL своего собственного HTTP-сервера. Здесь для удобства демонстрации используется публичный сайт образца Webhook [https://webhook.site/](https://webhook.site/), открыв этот сайт, вы получите URL Webhook, как показано на изображении:

![](https://cdn.acedata.cloud/tbcnai.png)

Затем мы можем установить поле `callback_url` на указанный URL Webhook, а также заполнить соответствующие параметры, конкретное содержание показано на изображении:

## 错误处理

在调用 API 时，如果遇到错误，API 会返回相应的错误代码和信息。例如：

- `400 token_mismatched`：Неверный запрос, возможно, из-за отсутствия или недействительных параметров.
- `400 api_not_implemented`：Неверный запрос, возможно, из-за отсутствия или недействительных параметров.
- `401 invalid_token`：Неавторизован, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили лимит частоты.
- `500 api_error`：Внутренняя ошибка сервера, что-то пошло не так на сервере.

### 错误响应示例

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "не удалось получить"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
