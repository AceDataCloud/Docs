В этой статье будет представлена инструкция по интеграции Producer Audios Generation API, который позволяет генерировать официальную музыку Producer посредством ввода пользовательских параметров.

## Процесс подачи заявки

Чтобы использовать Producer Audios Generation API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти в систему; после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первой заявке предоставляется бесплатный лимит для бесплатного ознакомления; при недостатке лимита вы можете пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Базовое использование

О какой песне вы думаете — можно произвольно ввести текст. Например, если я хочу сгенерировать песню о Рождестве, можно ввести `a song for Christmas`, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Можно увидеть, что здесь мы установили Request Headers, включая:

- `accept`: в каком формате вы хотите получить результат ответа; здесь указывается `application/json`, то есть формат JSON.
- `authorization`: ключ для вызова API, после подачи заявки его можно непосредственно выбрать из выпадающего списка.

Кроме того, параметры Request Body включают:

- `action`: действие этой задачи генерации музыки; для генерации песни используется `generate`.
- `model`: модель, используемая для создания песни; в настоящее время основные модели: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: содержание текста песни.
- `custom`: использовать ли пользовательский способ генерации песни.
- `prompt`: подсказка в режиме вдохновения.
- `title`: информация о названии песни.
- `audio_id`: ID эталонной песни, используется для таких операций, как продолжение/кавер и т. д.
- `continue_at`: начать продолжение песни с указанной секунды.
- `replace_section_start`/`replace_section_end`: время начала и окончания заменяемого фрагмента в секундах.
- `lyrics_strength`: сила текста песни, обозначает степень влияния текста на генерацию аудио; доступно значение от 0 до 1, по умолчанию 0.7.
- `sound_strength`: сила подсказки аудио; доступно значение от 0.2 до 1, по умолчанию 0.7.
- `cover_strength`: сила кавера — от 0.2 до 1, по умолчанию 1.
- `weirdness`: степень необычности стиля; доступно значение от 0 до 1, по умолчанию 0.5.
- `callback_url`: URL, на который необходимо отправить результат обратного вызова.
- `async`: необязательно; если установлено значение `true`, интерфейс немедленно возвращает `task_id`, без необходимости предоставлять `callback_url`, после чего результат можно получить путём опроса соответствующего интерфейса запроса задач.
- `instrumental`: является ли это режимом без текста песни.

Кроме того, если вы хотите сгенерировать соответствующий код интеграции, можете непосредственно скопировать сгенерированный код, например, код CURL выглядит следующим образом:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Кавер-версии песен

Если вы хотите выполнить операцию создания кавер-версии для уже сгенерированной песни, вы можете ввести сгенерированную выше песню для создания кавер-версии; далее мы будем пользовательски генерировать песню на основе текста и названия.

Если вы хотите продолжить создание кавер-версии для самостоятельно загруженной песни, можно установить параметр `action` в значение `upload_cover` и ввести ID самостоятельно загруженной песни, для которой необходимо продолжить создание кавер-версии. ID песни получается с помощью [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), как показано на рисунке ниже:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Можно указать следующее содержимое:

- action：действие задачи данной песни; в настоящее время поддерживаются: generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation; для данной кавер-версии используется параметр `cover`.
- lyric：текст песни
- title：название песни.
- custom：использовать ли пользовательский режим для генерации; по умолчанию — false.
- audio_id：ID песни, для которой необходимо создать кавер-версию.

## Продолжение песни

Если вы хотите продолжить песню, загруженную вами самостоятельно, можно установить для параметра `action` значение `upload_extend` и ввести ID самостоятельно загруженной песни, которую необходимо продолжить. ## Асинхронный обратный вызов

Поскольку время генерации Producer Audios Generation API иногда может быть относительно долгим, если API долго не отвечает, HTTP-запрос будет постоянно поддерживать соединение, что приводит к дополнительному потреблению системных ресурсов, поэтому данный API также предоставляет поддержку асинхронных обратных вызовов.

Общий процесс таков: когда клиент инициирует запрос, он дополнительно указывает поле `callback_url`, после того как клиент инициирует API-запрос, API немедленно вернёт результат, содержащий информацию о поле `task_id`, которое представляет ID текущей задачи. После завершения задачи результат задачи генерации будет отправлен в формате POST JSON на указанный клиентом `callback_url`, который также включает поле `task_id`, таким образом результаты задачи можно связать по ID.

Ниже мы на примере узнаем, как именно это сделать.

Прежде всего, обратный вызов Webhook — это сервис, который может принимать HTTP-запросы, разработчик должен заменить его URL-адресом собственного развёрнутого HTTP-сервера. Здесь для удобства демонстрации используется публичный пример сайта Webhook [https://webhook.site/](https://webhook.site/), открыв этот сайт, можно получить URL Webhook, как показано на рисунке:

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `400 api_not_implemented`：Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `401 invalid_token`：Не авторизован, недопустимый или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили ограничение по частоте запросов.
- `500 api_error`：Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
