Основная функция Producer Tasks API — запрашивать статус выполнения задачи путем ввода ID задачи, сгенерированного Producer Audios Generation API.

Этот документ подробно познакомит вас с инструкциями по интеграции Producer Tasks API, помогая вам легко интегрировать и в полной мере использовать мощные возможности этого API. Через Producer Tasks API вы можете легко реализовать запрос статуса выполнения задач Producer Audios Generation API.

## Процесс подачи заявки

Чтобы использовать Producer Audios Generation API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы еще не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти в систему; после завершения вы автоматически вернетесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первой заявке предоставляется бесплатный лимит для бесплатного ознакомления; при недостаточном лимите вы можете пополнить универсальный баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Пример запроса

Producer Tasks API можно использовать для запроса результатов Producer Audios Generation API. О том, как использовать Producer Audios Generation API, пожалуйста, обратитесь к документации [Producer Audios Generation API](https://platform.acedata.cloud/documents/producer-audios-integration).

Мы возьмем в качестве примера один ID задачи, возвращенный сервисом Producer Audios Generation API, чтобы показать, как использовать этот API. Предположим, у нас есть ID задачи: 1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad, далее покажем, как путем передачи ID задачи.

### Настройка заголовков и тела запроса

**Request Headers** включают:

- `accept`: указывает получение результатов ответа в формате JSON, здесь указывается `application/json`.
- `authorization`: ключ для вызова API, после получения можно напрямую выбрать из выпадающего списка.

**Request Body** включает:

- `id`: ID загруженной задачи.
- `action`: способ операции над задачей.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

Результат ответа содержит несколько полей: поле request — это request body при запуске задачи, в то время как поле response — это response body, возвращаемое после завершения задачи. Описание полей приведено ниже.
- `id`，ID задачи генерации, используется для уникальной идентификации данной задачи генерации。
- `request`，информация о запросе в задаче запроса。
- `response`，информация о возврате в задаче запроса。
- `created_at`，время создания задачи, временная метка Unix (секунды, с плавающей точкой)。
- `started_at`，время начала выполнения задачи, временная метка Unix (секунды, с плавающей точкой)。
- `finished_at`，время завершения задачи, временная метка Unix (секунды, с плавающей точкой)。Это поле не возвращается, когда задача не завершена。
- `elapsed`，время выполнения задачи, единица измерения — секунды (с плавающей точкой, сохраняется 3 знака после запятой)。Это поле не возвращается, когда задача не завершена。

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `400 api_not_implemented`：Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `401 invalid_token`：Не авторизован, недопустимый или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили лимит частоты запросов.
- `500 api_error`：Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой
