Kimi — это серия AI-моделей, выпущенная Moonshot AI. В настоящее время рекомендуется `kimi-k3.1-pro`, подходящая для длительного программирования, сложных рассуждений, визуального понимания и работы со знаниями; `kimi-k3` по-прежнему доступна для использования. Вызов осуществляется через совместимый с OpenAI Chat Completions API.

Этот документ главным образом описывает процесс использования API Kimi Chat Completion, с помощью которого мы можем легко использовать официальную функцию диалога Kimi.

## Процесс подачи заявки

Чтобы использовать API Kimi Chat Completion, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти, после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости отдельно подавать заявку для каждого сервиса.** При первой заявке предоставляется бесплатный лимит, который можно использовать для бесплатного ознакомления; при недостатке лимита можно пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Базовое использование

Далее можно заполнить соответствующее содержимое в интерфейсе, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

При первом использовании этого интерфейса необходимо заполнить как минимум три поля: `authorization` можно напрямую выбрать из выпадающего списка; `model` используется для выбора модели Kimi, рекомендуется использовать `kimi-k3.1-pro`; `messages` — это массив сообщений диалога, каждое сообщение содержит `role` и `content`, при этом `role` поддерживает `user`, `assistant`, `system` и `tool`.

При этом вы можете заметить, что справа генерируется соответствующий код вызова, вы можете скопировать код и запустить его напрямую, а также можете напрямую нажать кнопку «Try» для тестирования.

<p><img src="https://cdn.acedata.cloud/six7e3.png" width="400" className="m-auto" /></p>

Ниже приведён реальный ответ K3, полученный с использованием `reasoning_effort: max` (неиспользуемые расширенные поля опущены):

```json
{
  "id": "msg_2D4Btbg1WgvkNE3tCYkR4xGA",
  "object": "chat.completion",
  "created": 1784466588,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 86,
    "completion_tokens": 206,
    "total_tokens": 292
  }
}
```

Результат возврата содержит несколько полей, описание которых приведено ниже:

- `id` — ID созданной задачи этого диалога, используемый для уникальной идентификации данной задачи диалога.
- `model ` — выбранная модель с официального сайта Kimi.
- `choices` — информация об ответе, предоставленном Kimi на запрос.
- `usage `: статистическая информация о token для данной пары вопрос-ответ.

Среди них `choices` содержит информацию об ответе Kimi, а `choices` внутри него — конкретную информацию об ответе Kimi, как можно увидеть на рисунке.

<p><img src="https://cdn.acedata.cloud/tv9rul.png" width="400" className="m-auto" /></p>

Можно увидеть, что поле `content` внутри `choices` содержит конкретное содержимое ответа Kimi; K3 также может вернуть `reasoning_content`, используемое для представления процесса рассуждения.

## Интенсивность рассуждения K3.1 Pro

`kimi-k3.1-pro` всегда включает рассуждение. В верхнем уровне тела запроса можно установить `reasoning_effort` в `low`, `high` или `max`; не передавайте конфигурацию, отключающую рассуждение. Модель поддерживает контекст до 1 048 576 token, но фактический лимит запроса по-прежнему определяется текущим интерфейсом. Стоимость рассчитывается на основе использования входных данных, выходных данных и попаданий в кэш; подробности смотрите в карточке Pricing каталога моделей.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Следующие примеры K3 сохранены для существующих интеграций, а пример ответа действительно получен запросом K3.

## Интенсивность рассуждения K3

`kimi-k3` всегда включает рассуждение. Верхний уровень тела запроса поддерживает поле `reasoning_effort`, и единственным поддерживаемым в настоящее время значением является `max`; при пропуске этого поля также используется `max`. `standard`, `high` или другие строки могут быть частично приняты совместимыми вышестоящими системами в мягком режиме, но не гарантируется, что они изменят поведение рассуждения, не полагайтесь на это.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

При использовании OpenAI SDK это поле можно передать напрямую:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

При многораундовом диалоге и вызове инструментов передавайте полное сообщение assistant из предыдущего раунда обратно в `messages`, включая `reasoning_content` и `tool_calls`.

### Официальные ссылки

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort): поясняет, что Kimi K3 всегда включает рассуждение, а единственным поддерживаемым в настоящее время значением `reasoning_effort` является `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview): сравнивает параметры рассуждения, окна контекста и различия вызова инструментов серий K3 и K2.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat): официальные запросы, ответы и определения полей OpenAPI Chat Completions от Moonshot.

## Потоковый ответ

Этот интерфейс также поддерживает потоковые ответы, что очень полезно для интеграции с веб-страницами и позволяет реализовать эффект отображения текста посимвольно.

Если вы хотите возвращать ответ потоково, можно изменить параметр `stream ` в заголовке запроса на `true`.

Изменение показано на рисунке, однако код вызова также должен быть соответствующим образом изменён для поддержки потокового ответа.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>

После изменения `stream` на `true` API будет возвращать соответствующие данные JSON построчно, и на уровне кода нам необходимо внести соответствующие изменения, чтобы получать построчные результаты.

Пример кода вызова Python:
```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Ниже приведены начальный, рассуждающий, основной, завершающий блоки и блок данных об использовании из одного и того же реального потокового ответа K3 Max:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Можно увидеть, что в ответе имеется множество `data`, а `choices` внутри `data` являются последним содержимым ответа, что соответствует содержимому, представленному выше. `choices` — это добавленное содержимое ответа, вы можете интегрировать его в свою систему согласно результату. При этом завершение потокового ответа определяется по содержимому `data`: если содержимое равно `[DONE]`, это означает, что потоковый ответ полностью завершён. Возвращаемый результат `data` содержит несколько полей, описание которых приведено ниже:

- `id` — ID сгенерированной задачи этого диалога, используемый для уникальной идентификации задачи этого диалога.
- `model ` — выбранная модель с официального сайта Kimi.
- `choices` — информация об ответе, предоставленном Kimi на запрос.

JavaScript также поддерживается, например, код потокового вызова для Node.js выглядит следующим образом:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Пример кода на Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Другие языки можно дополнительно адаптировать самостоятельно, принцип везде одинаковый.

## Многораундовый диалог

Если вы хотите подключить функцию многораундового диалога, необходимо передать несколько запросов в поле `messages`; конкретный пример нескольких запросов показан на рисунке ниже:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Пример кода вызова на Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Передавая несколько запросов, можно легко реализовать многораундовый диалог. Ниже приведён реальный ответ K3 Max, полученный этим запросом (неиспользуемые расширенные поля опущены):

```json
{
  "id": "msg_Rqp8nPGBDHWwBlL4VpxuafOp",
  "object": "chat.completion",
  "created": 1784466628,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "I’m Kimi, an AI assistant developed by Moonshot AI (月之暗面). I don’t have a specific public model version identifier to share from here."
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 134,
    "completion_tokens": 346,
    "total_tokens": 480
  }
}
```

Можно увидеть, что информация, содержащаяся в `choices`, соответствует содержимому базового использования; она содержит конкретное содержимое ответа Kimi на несколько диалогов, поэтому можно отвечать на соответствующие вопросы на основе содержимого нескольких диалогов.

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `400 api_not_implemented`：Неверный запрос, возможно, из-за отсутствующих или недопустимых параметров.
- `401 invalid_token`：Не авторизован, недопустимый или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили ограничение скорости.
- `500 api_error`：Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
