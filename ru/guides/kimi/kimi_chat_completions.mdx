Kimi — это серия моделей искусственного интеллекта, разработанная компанией Moonshot AI. В настоящее время рекомендуется `kimi-k3.1-pro`, которая подходит для длительного программирования, сложных рассуждений, понимания изображений и интеллектуальной работы; `kimi-k3` по-прежнему доступна для использования. Вызов осуществляется через API Chat Completions, совместимый с OpenAI.

В этом документе главным образом описывается процесс использования Kimi Chat Completion API, с помощью которого мы можем легко использовать официальную функцию диалога Kimi.

## Поддерживаемые модели

В настоящее время поддерживаются четыре модели: `kimi-k3.1-pro`, `kimi-k3`, `kimi-k2.6` и `kimi-k2.7-code`. K2.7 Code предназначена для сценариев программирования и вызова инструментов, тарифицируется по той же цене, что и K2.6; не передавайте ей переключатель `thinking` или `reasoning_effort` в запросе. Поддержка остальных моделей Kimi прекращена, поэтому явно выбирайте одну из этих четырёх моделей в клиенте.

## Процесс подачи заявки

Чтобы использовать Kimi Chat Completion API, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications), чтобы получить свой API Token и сохранить его для дальнейшего использования.

![]()

Если вы ещё не вошли в систему или не зарегистрировались, система автоматически перенаправит вас на страницу входа и предложит зарегистрироваться и войти в систему. После завершения процесса вы автоматически вернётесь на текущую страницу.

**Одного API Token достаточно для вызова всех сервисов платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первой подаче заявки предоставляется бесплатный лимит, который можно использовать для бесплатного ознакомления с сервисом; если лимита недостаточно, можно пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Основное использование

Далее можно заполнить соответствующие данные в интерфейсе, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

При первом использовании этого интерфейса необходимо заполнить как минимум три поля: `authorization` можно напрямую выбрать из выпадающего списка; `model` используется для выбора модели Kimi, рекомендуется использовать `kimi-k3.1-pro`; `messages` представляет собой массив сообщений диалога, каждое сообщение содержит `role` и `content`, при этом `role` поддерживает `user`, `assistant`, `system` и `tool`.

В то же время вы можете заметить, что справа автоматически генерируется соответствующий код вызова. Вы можете скопировать код и запустить его напрямую или сразу нажать кнопку «Try» для тестирования.

<p><img src="https://cdn.acedata.cloud/six7e3.png" width="400" className="m-auto" /></p>

Ниже приведён реальный ответ K3, полученный с использованием `reasoning_effort: max` (неиспользуемые дополнительные поля опущены):

```json
{
  "id": "msg_2D4Btbg1WgvkNE3tCYkR4xGA",
  "object": "chat.completion",
  "created": 1784466588,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 86,
    "completion_tokens": 206,
    "total_tokens": 292
  }
}
```

Результат возвращает несколько полей, описание которых приведено ниже:

- `id` — ID задачи генерации диалога, используемый для уникальной идентификации данной задачи.
- `model ` — выбранная модель с официального сайта Kimi.
- `choices` — информация об ответе Kimi на заданный запрос.
- `usage ` — статистическая информация о количестве токенов, использованных в данном вопросе и ответе.

Среди них `choices` содержит информацию об ответе Kimi, а вложенный в него `choices` содержит конкретную информацию об ответе Kimi, как показано на рисунке.

<p><img src="https://cdn.acedata.cloud/tv9rul.png" width="400" className="m-auto" /></p>

Как видно, поле `content` внутри `choices` содержит конкретный текст ответа Kimi; K3 также может возвращать `reasoning_content`, предназначенное для отображения процесса рассуждения.

## Интенсивность рассуждений K3.1 Pro

`kimi-k3.1-pro` всегда использует режим рассуждений. В верхнем уровне тела запроса можно установить `reasoning_effort` в значение `low`, `high` или `max`; не передавайте конфигурацию, отключающую рассуждения. Модель поддерживает контекст объёмом до 1 048 576 токенов, однако фактический лимит запроса по-прежнему определяется текущим API-интерфейсом. Стоимость рассчитывается на основе объёма входных, выходных данных и использования кэшированных данных; подробности смотрите в карточке Pricing в каталоге моделей.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Следующий пример K3 сохраняется для существующих интеграций, а пример ответа действительно получен в результате запроса к K3.

## Интенсивность рассуждений K3

`kimi-k3` всегда использует режим рассуждений. Верхний уровень тела запроса поддерживает поле `reasoning_effort`, единственным поддерживаемым в настоящее время значением которого является `max`; при пропуске этого поля также используется `max`. Используйте поддерживаемое значение.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

При использовании OpenAI SDK это поле можно передавать напрямую:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

При многоэтапных диалогах и вызове инструментов передавайте в `messages` полное сообщение assistant из предыдущего раунда, включая `reasoning_content` и `tool_calls`.

### Официальные справочные материалы

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort)：объясняет, что Kimi K3 всегда использует режим рассуждений, а единственным поддерживаемым в настоящее время значением `reasoning_effort` является `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview)：сравнивает параметры рассуждений, размеры контекстных окон и различия в вызове инструментов между сериями K3 и K2.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat)：официальное описание Moonshot запросов Chat Completions, ответов и определений полей OpenAPI.

## Потоковая передача ответов

Этот интерфейс также поддерживает потоковую передачу ответов, что очень полезно для интеграции с веб-страницами и позволяет реализовать эффект посимвольного отображения текста.

Если вы хотите получать ответы в потоковом режиме, измените параметр `stream ` в заголовке запроса, установив его значение в `true`.

Измените его, как показано на рисунке, однако код вызова также необходимо соответствующим образом изменить, чтобы он поддерживал потоковую передачу ответов.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>
После изменения `stream` на `true` API будет возвращать соответствующие данные JSON построчно. На уровне кода нам необходимо внести соответствующие изменения, чтобы получать результаты построчно.

Пример вызова на Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Ниже приведены начальные, промежуточные, основные, завершающие блоки данных и данные об использовании из одного реального потокового ответа K3 Max:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Как видно, в ответе содержится множество объектов `data`, а `choices` внутри `data` представляет собой актуальное содержимое ответа, что соответствует описанию выше. `choices` содержит новые фрагменты ответа, которые вы можете использовать для интеграции с вашей системой в соответствии с полученными результатами. Одновременно с этим завершение потокового ответа определяется по содержимому `data`: если его значение равно `[DONE]`, это означает, что потоковый ответ полностью завершён. Возвращаемый объект `data` содержит несколько полей, описание которых приведено ниже:

- `id` — идентификатор задачи текущего диалога, используемый для её уникальной идентификации.
- `model ` — выбранная модель с официального сайта Kimi.
- `choices` — информация об ответе Kimi на заданный запрос.

JavaScript также поддерживается. Например, код потокового вызова в Node.js выглядит следующим образом:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Пример кода на Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Для других языков программирования код можно самостоятельно адаптировать — принцип работы остаётся одинаковым.

## Многоэтапный диалог

Если вы хотите реализовать поддержку многоэтапного диалога, необходимо передать несколько запросов в поле `messages`. Конкретный пример передачи нескольких запросов показан на изображении ниже:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Пример вызова на Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Передавая несколько запросов, можно легко реализовать многоэтапный диалог. Ниже приведён реальный ответ K3 Max, полученный на этот запрос (неиспользуемые дополнительные поля опущены):

```json
{
  "id": "msg_Rqp8nPGBDHWwBlL4VpxuafOp",
  "object": "chat.completion",
  "created": 1784466628,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "I’m Kimi, an AI assistant developed by Moonshot AI (月之暗面). I don’t have a specific public model version identifier to share from here."
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 134,
    "completion_tokens": 346,
    "total_tokens": 480
  }
}
```

Как видно, информация, содержащаяся в `choices`, соответствует той, что описана в разделе базового использования. Она включает конкретный ответ Kimi на несколько сообщений диалога, что позволяет формировать ответы на основе содержания нескольких сообщений.

## Обработка ошибок

При вызове API в случае возникновения ошибки API возвращает соответствующий код и сообщение об ошибке. Например:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.

### Пример ответа с ошибкой

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
