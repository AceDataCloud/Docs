title: "Экспорт записей вызовов API платформы AceDataCloud"

Скачайте детали вызовов API текущего аккаунта напрямую в CSV, что подходит для финансовой сверки, офлайн-анализа или сохранения большого количества записей. Если нужно только просмотреть небольшое количество деталей на странице, сначала используйте [список записей вызовов](https://platform.acedata.cloud/documents/platform-usage-list)。

Диапазон запроса записей вызовов и сводок по выставлению счетов составляет последние 60 дней; тела запросов и ответов отдельно хранятся последние 30 дней. Истечение срока хранения тела не изменяет фактическое списание, использование или сводную статистику этой записи。

## Подготовка

1. Войдите на [платформу AceDataCloud](https://platform.acedata.cloud)。
2. Создайте токен аккаунта в [консоли Account Token](https://platform.acedata.cloud/console/platform-tokens) и немедленно сохраните его в менеджер паролей или Secret Manager。
3. По необходимости получите ID для фильтрации из [списка заявок на сервисы](https://platform.acedata.cloud/documents/platform-application-list)、[списка учетных данных API](https://platform.acedata.cloud/documents/platform-credential-list) или [списка API](https://platform.acedata.cloud/documents/platform-api-list)。

Полное описание токенов см. в разделе [управление токенами аккаунта](https://platform.acedata.cloud/documents/platform-token)。Токен аккаунта и Credential для вызова бизнес-API нельзя использовать взаимозаменяемо。

```shell
export PLATFORM_TOKEN='你的账户令牌'
```

## Обзор интерфейса

| Параметр           | Содержание                                                 |
| ----------------- | ---------------------------------------------------------- |
| Метод             | `GET`                                                      |
| URL               | `https://platform.acedata.cloud/api/v1/usage/apis/export/` |
| Аутентификация    | `Authorization: Bearer ${PLATFORM_TOKEN}`                  |
| OAuth Scope       | `usage:read`（`platform:read` / `platform` включают его）   |
| Ответ             | `200 text/csv; charset=utf-8`                              |
| Имя файла         | `usages.csv`                                               |

Этот интерфейс синхронно возвращает CSV потоком, не создает задачу экспорта и не возвращает JSON или ссылку для скачивания. Только когда обе границы начального и конечного времени не предоставлены, по умолчанию экспортируются записи от начала текущего календарного месяца до текущего момента; если предоставлена только одна граница, другая не будет автоматически дополнена границей текущего месяца。

## Параметры запроса

| Параметр          | Тип      | Обязательный | По умолчанию | Описание                                      |
| ----------------- | -------- | --- | ------ | --------------------------------------------- |
| `perspective`     | string   | Нет | `both` | `billing`、`actor` или `both`                 |
| `service_id`      | UUID     | Нет | —      | Фильтрация по сервису; поддерживает повторные параметры |
| `application_id`  | UUID     | Нет | —      | Фильтрация по Application; поддерживает повторные параметры |
| `api_id`          | UUID     | Нет | —      | Фильтрация по API; поддерживает повторные параметры |
| `credential_id`   | UUID     | Нет | —      | Фильтрация по учетным данным API; поддерживает повторные параметры |
| `status_code`     | integer  | Нет | —      | Поддерживает повторяющиеся или разделенные запятыми значения |
| `created_at_from` | datetime | Нет | —      | Начальное время ISO 8601                      |
| `created_at_to`   | datetime | Нет | —      | Конечное время ISO 8601                       |

Диапазон экспорта всегда ограничен записями, видимыми текущему аккаунту как плательщику и/или фактическому вызывающему пользователю, экспорт между аккаунтами не поддерживается。

## Примеры запросов

Напрямую сохранить CSV текущего месяца:

```shell
curl --fail-with-body --location \
  'https://platform.acedata.cloud/api/v1/usage/apis/export/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  --output usages.csv
```

Экспорт по Application, времени и коду состояния:

```shell
export APPLICATION_ID='你的 Application ID'

curl --fail-with-body --get \
  'https://platform.acedata.cloud/api/v1/usage/apis/export/' \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'status_code=200,500' \
  --data-urlencode 'created_at_from=2026-09-01T00:00:00Z' \
  --data-urlencode 'created_at_to=2026-09-08T00:00:00Z' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  --output usages.csv
```

Потоковое сохранение и проверка целостности в Python:

```python
import os
from pathlib import Path

import requests

url = "https://platform.acedata.cloud/api/v1/usage/apis/export/"
headers = {"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"}
params = {
    "created_at_from": "2026-09-01T00:00:00Z",
    "created_at_to": "2026-09-08T00:00:00Z",
    "perspective": "both",
}
output = Path("usages.csv")

with requests.get(url, headers=headers, params=params, stream=True, timeout=120) as response:
    response.raise_for_status()
    if not response.headers.get("content-type", "").startswith("text/csv"):
        raise RuntimeError("服务器没有返回 CSV")
    with output.open("wb") as file:
        for chunk in response.iter_content(chunk_size=64 * 1024):
            file.write(chunk)

last_line = output.read_text(encoding="utf-8").splitlines()[-1]
if last_line.startswith("# truncated:") or last_line.startswith("# error:"):
    raise RuntimeError(f"导出不完整：{last_line}")
```

## Столбцы CSV

Порядок заголовков CSV фиксирован:

```text
Usage ID,API,Status Code,Deducted Amount,Original Amount,Trace ID,Created At
```

| Столбец           | Описание                                      |
| ----------------- | --------------------------------------------- |
| `Usage ID`        | ID записи вызова                              |
| `API`             | Название API; при невозможности сопоставления может быть ID API или пустым значением |
| `Status Code`     | Код состояния HTTP                            |
| `Deducted Amount` | Итоговая фактически списанная сумма            |
| `Original Amount` | Исходная сумма до применения скидки Application |
| `Trace ID`        | Идентификатор отслеживания запроса             |
| `Created At`      | Время создания записи, ISO 8601                |

Единица квоты определяется `service.unit` соответствующего Application。

## Определение полноты экспорта

За один раз может быть выведено не более 1 000 000 записей. После того как сервер начал возвращать CSV, он не может изменить промежуточную ошибку на другой HTTP-статус, поэтому клиент обязан проверить последнюю строку:

- `# truncated:`：достигнут лимит количества строк; экспортируйте сегментами в меньших временных окнах。
- `# error:`：потоковое чтение прервано; уменьшите диапазон и экспортируйте повторно。

Если программа сверки обнаруживает любой marker, она обязана считать файл неполным и не может молча учитывать его в расчетах。

## Ошибки и повторные попытки

| Ситуация                    | Способ обработки                                      |
| --------------------------- | ----------------------------------------------------- |
| `400 usage_history_expired` | Используйте `available_from` из ответа для корректировки в диапазон последних 60 дней |
| `401 not_authenticated`     | Проверьте, что Account Token существует, корректен и не удален |
| Не-CSV ответ                | Не сохраняйте как успешный файл; сначала прочитайте ответ с ошибкой и исправьте запрос |
| Прерывание скачивания или marker | Уменьшите временное окно, используйте стратегию отката и повторно экспортируйте |
