Получение полной информации об отдельном сервисе по ID сервиса (UUID) или псевдониму (alias) — возвращаемые поля полнее, чем у [получения списка сервисов платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-service-list), дополнительно раскрываются связанные объекты, такие как `apis`, `proxies`, `datasets`, `packages` и другие. Подходит для таких сценариев, как страница сведений о сервисе, страница сравнения цен, описание инструментов Agent и других.

> ℹ️ Этот интерфейс относится к **API управления платформой AceDataCloud**, единый префикс: `https://platform.acedata.cloud/api/v1/`. Полный индекс интерфейсов см. в разделе [получение списка документов платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-document-list).

## Обзор интерфейса

| Пункт   | Содержание                                                            |
| --- | ------------------------------------------------------------- |
| Метод  | `GET`                                                         |
| URL | `https://platform.acedata.cloud/api/v1/services/{service_id}` |
| Авторизация  | ❌ Публичный                                                          |

`/services/{id}` и `/services/{id}/` в настоящее время оба доступны; в примерах единообразно используется форма без завершающего слеша.

## Описание авторизации

Этот интерфейс полностью публичный. **Однако после добавления токена аккаунта поле `applied` в ответе будет отражать фактический статус заявки текущего аккаунта**, иначе оно всегда будет `false`.

Способ получения токена аккаунта см. в разделе [управление токенами аккаунта платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

## Параметры пути

| Параметр           | Тип            | Обязательный  | Описание                                                    |
| ------------ | ------------- | --- | ----------------------------------------------------- |
| `service_id` | UUID / string | ✅   | ID сервиса (UUID) или псевдоним (`midjourney`, `openai`, `webextrator` и др.) |

## Примеры запросов

### cURL

```shell
# Запрос по UUID
curl 'https://platform.acedata.cloud/api/v1/services/8efa1d83-9b75-4562-b44a-af95ce563d05' \
  -H 'accept: application/json'

# Запрос по alias
curl 'https://platform.acedata.cloud/api/v1/services/midjourney' \
  -H 'accept: application/json'

# Просмотр статуса applied с токеном аккаунта
curl 'https://platform.acedata.cloud/api/v1/services/midjourney' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

resp = requests.get(
    "https://platform.acedata.cloud/api/v1/services/midjourney",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}",
    },
    timeout=10,
)
svc = resp.json()
print(f"服务: {svc['title']} ({svc['alias']})")
print(f"已申请: {svc['applied']}, 免费额度: {svc['free_amount']} {svc['unit']}")
print(f"API 数: {len(svc['apis'])}, 套餐数: {len(svc['packages'])}")
for pkg in svc["packages"]:
    print(f"  ¥{pkg['price']:>7.2f}  ->  {pkg['amount']} {svc['unit']}")
```

### Node.js

```javascript
const r = await fetch('https://platform.acedata.cloud/api/v1/services/midjourney', {
  headers: { accept: 'application/json' },
})
const svc = await r.json()
console.log(`${svc.title} - 套餐 ${svc.packages.length} 个 - API ${svc.apis.length} 个`)
```

## Описание полей ответа

Интерфейс сведений дополнительно к всем полям [интерфейса списка](https://platform.acedata.cloud/documents/platform-service-list) раскрывает:

| Поле         | Тип    | Описание                                                            |
| ---------- | ----- | ------------------------------------------------------------- |
| `apis`     | array | Полный список связанных объектов API (каждая запись содержит `id`, `name`, `title`, `path`, `stage`, `cost`) |
| `proxies`  | array | Полный список связанных объектов Proxy                                              |
| `datasets` | array | Связанные наборы данных (если `type=Dataset`)                                      |
| `packages` | array | Список пакетов, содержащий `type` (`Usage`/`Period`), `price`, `amount`, `duration`   |

Определения остальных полей см. в разделе [получение списка сервисов платформы AceDataCloud → описание полей ответа](https://platform.acedata.cloud/documents/platform-service-list).

## Обработка ошибок

| HTTP | code        | Значение                            |
| ---- | ----------- | ----------------------------- |
| 404  | `not_found` | `service_id` (UUID или alias) не существует |
| 500  | —           | Обычно завершающий слеш ошибочно добавлен в URL, удалите его и повторите попытку          |

## Практические советы

- **`alias` > `UUID`**: жёстко закодировать `alias` (например, `midjourney`) в коде стабильнее; UUID изменяется при миграции среды.
- **Поле `apis` не содержит определения OpenAPI**: полная схема OpenAPI 3.0 находится в интерфейсе [получение сведений об API платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-api-detail).
- **Получение «полных возможностей» сервиса**: получите `api_ids` через этот интерфейс, затем поочерёдно вызывайте `/apis/{api_id}` для получения сведений.
- **Если `applied=true`**, можно напрямую [создать API-учётные данные](https://platform.acedata.cloud/documents/platform-credential-create), чтобы получить 32-значный Token, необходимый для вызова бизнес-интерфейсов, без повторной подачи заявки.
