[LobeChat](https://lobehub.com/) — это клиент с открытым исходным кодом для ИИ, поддерживающий плагины, базы знаний и самостоятельное развёртывание; его можно использовать в онлайн-версии или развернуть через Docker. Он поддерживает пользовательские конечные точки, совместимые с OpenAI, поэтому его можно подключить к Ace Data Cloud. В этой статье описывается процесс настройки.

## Процесс получения

Чтобы подключить Ace Data Cloud в LobeChat, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications), получите ваш API Token и сохраните его для дальнейшего использования.

![Получение Ace Data Cloud API Key](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти; после входа или регистрации вы автоматически вернётесь на текущую страницу.

При первом получении предоставляется бесплатный лимит, который позволяет бесплатно опробовать модельные сервисы Ace Data Cloud.

## Настройка Ace Data Cloud

Перейдите в **Настройки приложения → Языковые модели** LobeChat, найдите карточку **OpenAI** и включите её, затем заполните:

| Поле       | Значение                              | Описание                         |
| -------- | ------------------------------ | -------------------------- |
| API Key  | Ваш Ace Data Cloud Token        | Token, скопированный из консоли               |
| Адрес API-прокси | `https://api.acedata.cloud/v1` | **Должен оканчиваться на `/v1`**           |
| Режим клиентских запросов  | Включить                             | Прямое подключение из браузера, Key не проходит через сервер LobeChat |

![Интерфейс настройки LobeChat OpenAI Provider](https://cdn.acedata.cloud/629ef9d3084a.png)

> При использовании интерфейса Chat Completions оставьте Responses API Specification выключенным.

LobeChat не добавляет `/v1` к Base URL автоматически; путь запроса напрямую имеет вид `{Адрес API-прокси}/chat/completions`:

| Адрес API-прокси                              | Фактический запрос                                                   | Результат                       |
| ------------------------------------- | ------------------------------------------------------ | ------------------------ |
| `https://api.acedata.cloud/v1`        | `https://api.acedata.cloud/v1/chat/completions`        | Правильно                       |
| `https://api.acedata.cloud/openai`    | `https://api.acedata.cloud/openai/chat/completions`    | Также можно использовать                      |
| `https://api.acedata.cloud/openai/v1` | `https://api.acedata.cloud/openai/v1/chat/completions` | 404 (в `/openai` нет `/v1`) |
| `https://api.acedata.cloud`           | `https://api.acedata.cloud/chat/completions`           | 404 (отсутствует `/v1`)             |

По умолчанию LobeChat вызывает `/v1/models` для автоматической загрузки моделей; если Ace Data Cloud возвращает много моделей, интерфейс будет очень длинным, поэтому рекомендуется вручную заполнить allow list в «Список моделей → Пользовательские названия моделей», разделяя значения английскими запятыми. Если требуется настроить отображаемое имя, можно использовать `=`, в формате `MODEL_ID=Отображаемое название`.

## Выбор модели

Каталог моделей будет постоянно обновляться. В приоритете используйте список моделей, автоматически загружаемый клиентом; если требуется заполнить его вручную, сначала выполните запрос `GET https://api.acedata.cloud/v1/models`, чтобы получить актуальные ID моделей, затем выбирайте в соответствии с поддерживаемыми клиентом возможностями контекста, изображений и вызова инструментов.

## Проверка подключения

Если вы не уверены, связана ли проблема с LobeChat или сетью, можно сначала напрямую проверить конечную точку с помощью curl (замените `{token}` на ваш Token):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

Возврат объекта `chat.completion`, совместимого с OpenAI, означает, что Token и конечная точка готовы; если возвращается `HTTP 403 used_up`, это означает, что Token действителен, но баланс недостаточен — пополните его в [консоли](https://platform.acedata.cloud/console/applications).

## Продвинутое использование: самостоятельное развёртывание Docker

Если вы хотите развернуть приватную версию для использования командой, можно запустить её одной командой Docker (замените `{token}` на ваш Token):

```bash
docker run -d \
  --name lobe-chat \
  -p 3210:3210 \
  -e OPENAI_API_KEY={token} \
  -e OPENAI_PROXY_URL=https://api.acedata.cloud/v1 \
  -e ACCESS_CODE=your-secret-password \
  -e OPENAI_MODEL_LIST="MODEL_ID" \
  lobehub/lobe-chat:latest
```

Откройте `http://IP-адрес_вашего_сервера:3210`, введите `ACCESS_CODE` и можете пользоваться; членам команды не нужно каждому отдельно заполнять Key. Полное описание переменных окружения, используемых выше, таких как `OPENAI_API_KEY`, `OPENAI_PROXY_URL`, `OPENAI_MODEL_LIST`, см. в [документации по переменным окружения провайдеров моделей LobeChat](https://lobehub.com/docs/self-hosting/environment-variables/model-provider). Если используете обратный прокси nginx с HTTPS, обязательно добавьте `proxy_buffering off;`, иначе потоковые ответы будут буферизироваться. Подробнее о других вариантах развёртывания см. в [руководстве по началу самостоятельного развёртывания LobeChat](https://lobehub.com/docs/self-hosting/start) и [развёртывании Docker Compose](https://lobehub.com/docs/self-hosting/platform/docker-compose).

## Часто задаваемые вопросы

### Появляется 404 Not Found

Обычно адрес API-прокси указан как `.../openai/v1` или отсутствует `/v1`. Измените его на `https://api.acedata.cloud/v1`.

### Список моделей пуст

Включите переключатель «Режим клиентских запросов»; или вручную заполните allow list моделей в «Пользовательские названия моделей».

### Появляется 401 Unauthorized

Пожалуйста, убедитесь, что в API Key вставлен Token Ace Data Cloud (без префикса `Bearer`, без лишних пробелов), а баланс соответствующего приложения достаточен.
