TypeScript — один из наиболее рекомендуемых способов интеграции Ace Data Cloud X402. Официальный SDK отвечает за обычные API-вызовы, опрос задач, обработку ошибок и автоматические повторы; `@acedatacloud/x402-client` отвечает за подпись заголовка запроса `PAYMENT-SIGNATURE` при возникновении `402 Payment Required`.

Исходный код и адреса пакетов:

- Репозиторий SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Репозиторий X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm SDK: [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)
- npm X402 Client: [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client)

## Установка зависимостей

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client
```

При использовании Base необходима возможность EVM-подписи:

```bash
npm install ethers
```

При использовании Solana необходим Solana wallet adapter или `@solana/web3.js`:

```bash
npm install @solana/web3.js
```

Вывод проверки установки и импорта в чистом npm-проекте:

```text
imports_ok true true true true true
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4
```

Объяснение результатов:

- `@acedatacloud/sdk` и `@acedatacloud/x402-client` могут быть установлены из npm и импортированы Node.js.
- `ethers` используется для подписи EVM typed data, `@solana/web3.js` используется для создания Solana transaction.

## Пример Base

В браузере можно напрямую использовать `window.ethereum`. В Node.js можно обернуть `ethers.Wallet` в provider в стиле EIP-1193.

```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});

console.log(result.choices[0].message.content);
```

## Пример браузерного кошелька

При использовании MetaMask, Coinbase Wallet или WalletConnect во frontend-приложении обычно напрямую передаётся EIP-1193 provider:

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const [address] = await window.ethereum.request({ method: 'eth_requestAccounts' });

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider: window.ethereum,
    evmAddress: address
  })
});

const image = await client.images.generate({
  provider: 'nano-banana',
  prompt: 'a yellow banana on a white background'
});
```

Браузерный кошелёк покажет подтверждение подписи. Пользователь подписывает не произвольное сообщение, а возвращённое API платёжное требование: адрес получателя, контракт USDC, сумма, срок действия и nonce включены в подпись.

## Пример Solana

Solana использует SPL USDC `TransferChecked`. Передаваемый wallet adapter должен предоставлять `publicKey` и `signAndSendTransaction`.

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'solana',
    solanaWallet: phantomWallet
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});
```

Путь Solana в настоящее время поддерживает только `exact` и не поддерживает `upto`. Если API возвращает несколько `accepts`, handler выберет элемент с `network = 'solana'`.

Путь Solana уже проверен на том же публичном API: paid retry может вернуть HTTP 200 и `ADC_SOLANA_E2E_OK`. Запросы к публичному RPC могут быть ограничены по частоте, поэтому в этой статье не указан Solana tx hash; если требуется сверка в сети, используйте собственный Solana RPC или подтверждение из записей консоли.

## Выбор `exact` или `upto`

Текущий TypeScript handler выберет первое payment requirement соответствующей сети, возвращённое сервером. API Ace Data Cloud обычно размещает `exact` той же сети перед `upto`, поэтому, если вы явно хотите использовать постоплату по учёту, необходимо передать `preferScheme: 'upto'`.

Пример:

```ts
const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address,
    preferScheme: 'upto'
  })
});
```

Если сервер не возвращает `upto` requirement этой сети, handler автоматически вернётся к первому доступному requirement этой сети, обычно это `exact`.

`upto` требует одноразовой авторизации Permit2. `upto` в настоящее время предоставляется только в Base, поэтому необходимо выполнить одну авторизацию только для Base USDC:

```bash
npx tsx scripts/approve-permit2.ts --network base
```

Base `upto` прошёл проверку на публичном API: HTTP 402 -> HTTP 200, post-settlement tx — `0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036`. Полный вывод приведён в описании схемы биллинга.

## Что делает SDK

transport `@acedatacloud/sdk` при получении 402 один раз выполняет payment handler:

```ts
type PaymentHandler = (ctx: {
  url: string;
  method: string;
  body?: unknown;
  accepts: PaymentRequirement[];
}) => Promise<{ headers: Record<string, string> }>;
```

Handler, возвращаемый `@acedatacloud/x402-client`, будет:

1. Выбирать из `ctx.accepts` payment requirement целевой сети.
2. Создавать в соответствии с сетью EVM EIP-712 подпись или Solana transfer transaction.
3. Сериализовать envelope в Base64.
4. Возвращать `{ headers: { 'PAYMENT-SIGNATURE': '<base64>' } }`.
5. SDK автоматически повторит попытку с исходным телом запроса.

Это означает, что бизнес-код нужно писать так же, как обычный вызов SDK, без необходимости вручную обрабатывать повтор 402.
