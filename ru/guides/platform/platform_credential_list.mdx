Постраничный вывод бизнес-API учётных данных. Этот ответ в настоящее время содержит чувствительные поля учётных данных Token или Identity и должен обрабатываться только на серверной стороне; запрещено записывать их в логи, аналитические платформы, постоянное хранилище фронтенда или публичные репозитории.

## Подготовка

Создайте [Account Token](https://platform.acedata.cloud/documents/platform-token) и получите UUID текущего аккаунта через `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='ваш токен аккаунта'
export USER_ID='ваш UUID аккаунта'
```

## Обзор интерфейса

| Пункт   | Содержание                                                   |
| --- | ---------------------------------------------------- |
| Метод  | `GET`                                                |
| URL | `https://platform.acedata.cloud/api/v1/credentials/` |
| Аутентификация  | Account Token, для OAuth token требуется `credentials:read`       |
| Пагинация  | `count` + `items`                                    |

Обычные пользователи должны передавать собственный `user_id` или авторизованный `application_id`, иначе при встрече с объектами без прав доступа во время пагинации может возвращаться `403`.

## Параметры запроса

| Параметр                 | Тип      | Обязательный  | Описание                             |
| ------------------ | ------- | --- | ------------------------------ |
| `user_id`          | string  | В зависимости от сценария | Владелец учётных данных; поддерживает повторяющиеся параметры                   |
| `application_id`   | UUID    | Нет   | Фильтрация по Application; поддерживает повторяющиеся параметры        |
| `host`             | string  | Нет   | Точная фильтрация по host; поддерживает повторяющиеся параметры             |
| `name`             | string  | Нет   | Точная фильтрация по имени; поддерживает повторяющиеся параметры                 |
| `granted`          | boolean | Нет   | `true` — учётные данные, предоставленные другим, `false` — учётные данные для собственного использования |
| `limit` / `offset` | integer | Нет   | Пагинация                             |
| `ordering`         | string  | Нет   | `created_at` или `-created_at`   |

`service_id`, `disabled`, `expired` в настоящее время не являются параметрами фильтрации.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/credentials/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Описание ответа

Проверенный в production ответ имеет вид `{count, items}`. Каждый элемент содержит `id`, `application_id`, `application`, `user_id`, `creator_id`, `name`, `type`, `limited_amount`, `used_amount`, `expired_at`, `allowed_api_ids`, `host`, `granted`, `granted_to_user_id`, `tags`, `metadata` и поля времени, а также в зависимости от типа возвращает `token` или `username/password`.

> Текущий ответ списка возвращает полные чувствительные значения. Не отображайте их в консоли браузера или системах сбора данных и не полагайтесь на восстановление открытого текста через список; клиент должен быть совместим с будущими стратегиями маскирования.
