«Заявка (Application)» обозначает отношение подписки текущего аккаунта к определённому сервису — необходимо сначала создать заявку, чтобы затем создать для неё API-учётные данные и вызывать бизнес-интерфейсы. При первом оформлении заявки на сервис Application получает текущее настроенное для этого сервиса значение `free_amount`; оно может быть равно 0.

> ℹ️ Этот интерфейс относится к **API управления платформой AceDataCloud** с единым префиксом `https://platform.acedata.cloud/api/v1/`. Полный индекс интерфейсов смотрите в разделе [Получение списка документов платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-document-list).

## Полный процесс интеграции

Новые пользователи обычно проходят эти 5 шагов от регистрации до успешного вызова первого бизнес-интерфейса:

1. **Получить токен аккаунта** → [Управление токенами аккаунта платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-token)
2. **Выбрать сервис** → [Получение списка сервисов платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-service-list)
3. **Создать заявку** (этот документ) → получить начальную квоту согласно настройкам сервиса
4. **Создать API-учётные данные** → [Создание API-учётных данных платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-credential-create)
5. **Вызвать бизнес-интерфейс** → использовать полученный 32-символьный Token для вызова `https://api.acedata.cloud/<path>`

## Обзор интерфейса

| Параметр            | Содержимое                                            |
| ------------ | ----------------------------------------------------- |
| Метод           | `POST`                                                |
| URL          | `https://platform.acedata.cloud/api/v1/applications/` |
| Авторизация           | ✅ Требуется токен аккаунта                                              |
| Content-Type | `application/json`                                    |

## Описание авторизации (как получить токен аккаунта)

Заголовок запроса:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Токен аккаунта (Account Token) — это «ключ уровня аккаунта», используемый разработчиком для управления ресурсами своего аккаунта через API. Способы получения:

1. **Создание в консоли одним нажатием (рекомендуется)**: войдите на [платформу AceDataCloud](https://platform.acedata.cloud) → [консоль Account Token](https://platform.acedata.cloud/console/platform-tokens) → нажмите «Создать», чтобы получить токен, начинающийся с `platform-v1-`.
2. **Создание через API**: используйте существующий токен аккаунта или JWT состояния входа браузера для вызова `POST /api/v1/platform-tokens/`; подробности смотрите в разделе [Управление токенами аккаунта платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

> ⚠️ Токен аккаунта столь же конфиденциален, как пароль; запрещено размещать его во фронтенд-коде или публичных репозиториях. При утечке немедленно удалите его в консоли и создайте новый.

## Тело запроса

| Параметр           | Тип   | Обязательный  | Описание                                                                                                  |
| ------------ | ---- | --- | --------------------------------------------------------------------------------------------------- |
| `service_id` | UUID | ✅   | ID сервиса, на который необходимо оформить заявку. Можно получить из `items[].id` в [списке сервисов](https://platform.acedata.cloud/documents/platform-service-list) |

## Примеры запросов

### cURL

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/applications/' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'content-type: application/json' \
  -d '{"service_id": "38ecf158-36f2-42f2-8e7f-6786cdfc2452"}'
```

### Python

```python
import os
import requests

PLATFORM_TOKEN = os.environ["PLATFORM_TOKEN"]
SERVICE_ID = "38ecf158-36f2-42f2-8e7f-6786cdfc2452"

resp = requests.post(
    "https://platform.acedata.cloud/api/v1/applications/",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {PLATFORM_TOKEN}",
        "content-type": "application/json",
    },
    json={"service_id": SERVICE_ID},
    timeout=10,
)

if resp.status_code == 201:
    app = resp.json()
    print(f"申请成功！application_id={app['id']}")
    print(f"初始额度：{app['remaining_amount']} {app.get('service', {}).get('unit', '')}")
elif resp.status_code == 400 and resp.json().get("code") == "duplication":
    print("⚠️ 已经申请过此服务，请到 /applications/ 列表里找到现成的 application_id")
else:
    print(f"申请失败：HTTP {resp.status_code} - {resp.text}")
```

### Node.js

```javascript
const PLATFORM_TOKEN = process.env.PLATFORM_TOKEN
const SERVICE_ID = '38ecf158-36f2-42f2-8e7f-6786cdfc2452'

const resp = await fetch('https://platform.acedata.cloud/api/v1/applications/', {
  method: 'POST',
  headers: {
    accept: 'application/json',
    authorization: `Bearer ${PLATFORM_TOKEN}`,
    'content-type': 'application/json',
  },
  body: JSON.stringify({ service_id: SERVICE_ID }),
})

if (resp.status === 201) {
  const app = await resp.json()
  console.log('application_id =', app.id)
} else {
  console.error(await resp.text())
}
```

### Заявка уже существует (HTTP 400)

```json
{
  "detail": "Item already exists.",
  "code": "duplication",
  "trace_id": "1a87524f8cbba0b790b2951e2e43117e"
}
```

Это жёсткое ограничение, предусмотренное дизайном: **у каждого пользователя может быть только один Application для каждого сервиса**. Если он уже существует, найдите имеющийся через [получение списка заявок на сервисы платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-application-list).

### Сервис не существует (HTTP 404)

```json
{
  "detail": "Service not found.",
  "code": "not_found",
  "trace_id": "..."
}
```

### Сервис требует проверки (HTTP 403)

```json
{
  "detail": "This service requires manual verification.",
  "code": "need_verify",
  "trace_id": "..."
}
```

Если у сервиса `need_verify=true` (это поле можно увидеть в списке сервисов), необходимо пройти процесс заявки через тикет для добавления в белый список.

## Обработка ошибок
| HTTP | код                 | Значение                   |
| ---- | ------------------- | -------------------------- |
| 400  | `duplication`       | Эта услуга уже была запрошена текущей учетной записью |
| 400  | `invalid`           | `service_id` отсутствует или имеет неверный формат |
| 401  | `not_authenticated` | Отсутствует токен учетной записи или токен был удален |
| 403  | `need_verify`       | Услуга требует проверки, пожалуйста, используйте процесс обращения в службу поддержки |
| 404  | `not_found`         | Услуга не существует или была отключена |

Единый формат ответа с ошибкой:

```json
{
  "detail": "...",
  "code": "...",
  "trace_id": "..."
}
```

## Практические советы

- **Само создание не списывает средства**: при первом создании начальная квота устанавливается в соответствии с текущим `free_amount` услуги; это значение может быть 0, и повторное создание Application того же типа не гарантирует повторное предоставление.
- **Необходимость оплаты определяется полем `paid`**: сразу после подачи заявки `paid=false`, после вызова [Создать заказ на пополнение платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-order-create) и завершения оплаты оно становится `true`.
- **`disabled=true` означает временное отключение** — например, при срабатывании контроля рисков, наличии задолженности и т. д. При отключении бизнес-интерфейс вернет `403`.
- **Не создавайте заявки с неограниченной параллельностью**: сначала получите целевой `service_id` из постраничного списка услуг, затем подавайте заявки поочередно в соответствии с бизнес-потребностями; при возникновении `duplication` используйте существующий Application.
