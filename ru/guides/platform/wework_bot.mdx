Разверните собственный экземпляр аккаунта корпоративного WeChat, войдите в систему, отсканировав QR-код корпоративного WeChat на телефоне, и используйте REST API или MCP для чтения аккаунта, контактов, бесед и локально синхронизированных сообщений. Экземпляр соответствует обычному аккаунту корпоративного WeChat и не требует частного сервера или настройки домена корпоративной электронной почты.

Сейчас Alpha. Чтение аккаунта прошло проверку в реальных беседах; отправка текстов от собственного имени и обратное чтение событий прошли реальную приёмку; операции с другими контактами, группами и восстановление новых экземпляров ещё требуют приёмки в среде развертывания. Отправка медиа, ответы с цитированием, реальные @, управление участниками групп и подтверждения доставки пока не открыты. Ориентируйтесь на возвращаемое экземпляром значение `/api/capabilities`.

## Развертывание и вход

В категории Deployment подключите сервис и выберите пакет длительности экземпляра. После развертывания откройте страницу управления и отсканируйте QR-код корпоративного WeChat с аккаунта владельца; если требуется подтверждение на телефоне или другие шаги входа, откройте удалённый рабочий стол и введите пароль рабочего стола этого экземпляра. Учётные данные API и пароль рабочего стола независимы. Данные входа сохраняются на диске экземпляра, при пересоздании контейнера диск сохраняется; удаление диска удалит локальную сессию.

Каждый экземпляр оплачивается отдельно и работает в течение приобретённого срока. Вызовы REST / MCP не тарифицируются отдельно за сообщения, фактическая цена определяется страницей пакета. В настоящее время по умолчанию используется тариф по длительности для бота WeChat в качестве ориентира; перед окончательным открытием необходимо подтвердить ценообразование с учётом используемых ресурсов.

## API и MCP

Используйте адрес API экземпляра на странице управления, все интерфейсы аккаунта передают `Authorization: Bearer <API token экземпляра>`. Эти пути относятся к выделенному экземпляру, а не к общему шлюзу API. Адрес MCP — это адрес экземпляра с добавлением `/mcp/`, используется тот же Bearer token.

| Интерфейс                                                       | Назначение                                          |
| -------------------------------------------------------- | ------------------------------------------- |
| `GET /api/status`、`GET /api/auth/status`                 | Готовность аккаунта и список возможностей                                 |
| `GET /api/auth/qr`                                       | PNG Base64 текущего QR-кода входа                          |
| `GET /api/account`                                       | Текущий аккаунт                                        |
| `GET /api/contacts?kind=all`                             | Внутренние коллеги и внешние контакты, можно указать internal / external          |
| `GET /api/conversations`                                 | Локальные беседы, исходные ID бесед сохраняются                              |
| `GET /api/messages`                                      | Локально синхронизированные сообщения; параметры conversation_id、after_rowid、limit |
| `POST /api/search`                                       | Поиск контактов, бесед и локальных текстов                               |
| `POST /api/messages`                                     | Асинхронная задача отправки текста, необходимо указать Idempotency-Key               |
| `POST /api/messages/send`                                | Тот же вход отправки, поддерживает одну или несколько целей                            |
| `GET /api/groups/{conversation_id}`                      | Локально синхронизированная информация о группе и участниках                                 |
| `GET /api/tasks`                                         | Последние задачи и результаты по каждой цели                                 |
| `GET /api/tasks/{id}`                                    | Запрос результата отправки                                      |
| `POST /api/tasks/{id}/cancel`                            | Отмена ещё не начатой задачи                                   |
| `POST /api/runtime/pause`、`POST /api/runtime/resume`     | Приостановить автоматизацию; возобновить после проверки владельца                               |
| `GET /api/diagnostics`、`GET /api/diagnostics/screenshot` | Состояние экземпляра и текущий экран, для обоих требуется авторизация                              |
| `GET /api/events?after=0`                                | События сообщений с восстанавливаемым курсором                                  |
| `WS /ws`                                                 | Поток событий сообщений, Bearer-аутентификация                             |

Тело отправки содержит `target`, `type: "text"` и `text`. `target` принимает ID беседы, ID контакта, ID корпоративного пользователя или уникальное полное имя; предпочтительно использовать ID; если отображаемое имя всё ещё не позволяет однозначно определить объект, экземпляр отклонит операцию и не будет угадывать объект. Для контакта без локальной беседы клиент сначала откроет беседу, а затем отправит сообщение после сверки фактического ID беседы. Заголовок запроса `Idempotency-Key` состоит из 8–128 букв, цифр или символов `_.:-`. Повторные запросы одной и той же операции должны использовать один и тот же ключ и одинаковое тело запроса.

Замена `target` на массив `targets` позволяет последовательно отправлять сообщения 1–50 явно указанным целям. Оба параметра нельзя передавать одновременно. Для всех целей сначала выполняется разрешение идентичности, различные псевдонимы, указывающие на один и тот же объект, будут отклонены. После сбоя одной цели последующие отправки прекращаются, результат задачи по каждому элементу записывается как `succeeded`, `failed`, `unknown` или `not_attempted`; не считайте частичный успех полным успехом. Этот процесс также должен пройти реальную приёмку указанных контактов в среде развертывания.

Задачи могут находиться в состояниях queued、running、submitting、succeeded、failed、unknown или cancelled. `succeeded` означает, что после отправки в записи соответствующей беседы был найден точный текст и серверный ID сообщения, `delivered` всё ещё равен null и не означает, что другая сторона получила сообщение. unknown означает, что результат неясен, проверьте историю и не повторяйте отправку с новым ключом. Экземпляр не будет автоматически повторно отправлять прерванные задачи.

История содержит только то, что уже синхронизировано клиентом, и не может гарантировать всю историю. Нетекстовые сообщения могут возвращаться с типом unknown, загрузка вложений пока не открыта. События хранятся в количестве последних 10,000, `gap` означает, что курсор уже вышел за окно хранения. При первом подключении старая история не будет повторно воспроизводиться как новые сообщения.

`server_accepted` и `server_id` в истории сообщений можно использовать для проверки того, принял ли сервер локальное сообщение; если присутствует только локальная запись без серверного ID, отправку нельзя считать успешной. Эти поля не означают, что получатель получил или прочитал сообщение. Записи событий сохраняют состояние на момент создания, для запроса текущего состояния подтверждения следует использовать интерфейс истории сообщений.

## Аккаунт и учётные данные

Входите только в аккаунты, которыми вы уполномочены управлять. Настройте API token в доверенных приложениях; он может получать доступ к данным аккаунта этого экземпляра. Не публикуйте пароли, QR-коды или скриншоты чатов в общедоступных местах. Приостановка экземпляра прервёт события в реальном времени. После выхода из аккаунта или удаления устройства на телефоне необходимо войти повторно.

Текущий ввод текста поддерживает только одну строку, переносы строк будут явно отклонены перед отправкой. Если клиент требует проверку безопасности или повторный вход, владелец аккаунта должен завершить это на удалённом рабочем столе; экземпляр не будет обходить проверку. Задачи после прерывания проверки могут вернуть unknown, сначала запросите записи сообщений, не отправляйте повторно с новым ключом идемпотентности.

После обнаружения подсказки о проверке безопасности, выхода из аккаунта или изменений очередь автоматизации будет приостановлена с сохранением состояния. После завершения проверки на телефоне можно через консоль экземпляра «Возобновить после проверки» продолжить ещё не выполненные задачи; уже отправленные, но с неопределённым результатом задачи не будут повторно отправлены. Обычная удалённая работа также может вызвать проверку безопасности корпоративного WeChat. Указанное в официальном описании окно в 24 часа без повторной блокировки после проверки не означает, что обнаружение уже устранено, и не означает, что экземпляр может гарантировать длительную работу без присмотра.
