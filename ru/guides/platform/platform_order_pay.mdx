Создать или обновить платёжную сессию для заказа `Pending`. Действие оплаты обращается к платёжному каналу и может изменить статус заказа; перед вызовом необходимо подтвердить ID заказа, сумму и способ оплаты.

## Обзор интерфейса

| Пункт    | Содержание                                                             |
| ---- | -------------------------------------------------------------- |
| Метод   | `POST`                                                         |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/` |
| Авторизация   | Управляемые перенаправляющие платежи могут быть анонимными; другие способы требуют состояния входа или Account Token                            |
| Body | JSON, для неоплаченных заказов необходимо указать `pay_way`                                       |

## Границы анонимной оплаты

Анонимный доступ используется для сценариев, когда состояние входа потеряно после открытия скопированной платёжной ссылки; долгосрочный Account Token не требуется и не должен передаваться. Анонимный вызов:

- разрешает только настроенные на сервере способы оплаты с управляемым перенаправлением;
- всегда использует страницу оплаты для настольных устройств;
- не может получить заказ с нулевой стоимостью;
- ограничивается по IP и по одному заказу;
- возвращает минимальную проекцию заказа, не содержащую аккаунт, Application или внутренние metadata.

Аутентифицированный вызывающий должен быть владельцем заказа или суперадминистратором. Способы, требующие пользовательского контекста, такие как X402 и обмен наград, не могут вызываться анонимно.

## Примеры запросов

```shell
export ORDER_ID='ID вашего заказа Pending'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"Stripe"}'
```

Способы оплаты, требующие аутентификации:

```shell
export PLATFORM_TOKEN='токен вашего аккаунта'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"X402"}'
```

`pay_way` использует фактические значения, поддерживаемые моделью заказа, например `WechatPay`, `AliPay`, `Stripe`, `Card`, `Airwallex`, `X402`, `PayPal`, `AppleIAP`, `Reward`, `BankTransfer`. Не каждое значение доступно для анонимных запросов или на каждом сайте.

## Описание ответа

Успешный ответ — это обновлённый объект заказа, обычно предоставляющий точку входа для следующего шага через `pay_url`; разные способы оплаты также могут возвращать в контролируемых полях информацию, необходимую клиенту для продолжения оплаты. Анонимный ответ использует минимальный белый список полей, а аутентифицированный владелец получает полные сведения.

Не полагайтесь на старые имена полей, такие как `payment_url`, `qr_code_url` или `payment_method`; текущий контракт Order использует `pay_url` и `pay_way`.

## Банковский перевод

Как вошедшие личные аккаунты, так и корпоративные аккаунты могут использовать `BankTransfer`, корпоративная верификация не требуется. Как внутренние переводы в китайских юанях, так и международные переводы в долларах США требуют, чтобы сумма заказа составляла не менее 300 долларов США; сумма к оплате в юанях определяется суммой, отображаемой во время оплаты.

Перед оплатой можно запросить доступные для текущего заказа маршруты перевода и пороги сумм через `GET /api/v1/orders/{order_id}/payment-options/`. Банковский перевод должен инициироваться владельцем заказа после входа в систему и ограничивается конфигурацией канала получения средств и областью применимости тарифа; анонимные запросы не могут его использовать.

## Внутриигровые покупки iOS

Вошедший владелец заказа может передать `pay_way: "AppleIAP"`. Этот запрос обновляет ожидающий оплаты заказ согласно `metadata.apple_price` выбранного тарифа и очищает скидки, не производит списания, не начисляет кредиты и не возвращает платёжную ссылку. Старые ожидающие оплаты заказы должны сначала завершить этот шаг, а затем инициировать нативную оплату Apple. Поддерживается только один тариф Usage с настроенными товаром и ценой Apple; неподдерживаемые тарифы или пакетные заказы возвращают `400`.

После нативной оплаты Apple необходимо отправить `transaction_id` через `/api/v1/orders/{id}/apple-verify/` для завершения серверной проверки и начисления кредитов. Количество кредитов берётся из тарифа; сумма использует независимую предустановленную цену Apple в долларах США, без наложения скидок участника или наценок сайта, а сумма списания в местной валюте для других регионов определяется страницей подтверждения Apple.

## Ошибки и повторные попытки

- Заказ не находится в статусе `Pending`: возвращается `400`; не создавайте платёжную сессию повторно.
- `pay_way` не предоставлен: для заказа с ненулевой суммой возвращается `400`.
- Анонимный вызов использует недопустимый способ или заказ с нулевой стоимостью: возвращается `403`, повторите попытку после входа как владелец.
- Аутентификация выполнена, но вызывающий не является владельцем заказа: возвращается `403`.
- Сбой платёжного канала: не отправляйте запросы повторно вслепую; сначала запросите сведения о заказе, подтвердите, что он всё ещё `Pending`, и затем повторите попытку.
