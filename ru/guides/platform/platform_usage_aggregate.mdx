title: "Получение агрегированной статистики объёма вызовов API платформы AceDataCloud"

Сводка количества запросов и фактически списанных единиц по датам и API для текущей учётной записи, подходит для подготовки ежемесячных отчётов, графиков тенденций и анализа затрат. Если требуется устранять ошибки по каждой записи, используйте [список записей вызовов](https://platform.acedata.cloud/documents/platform-usage-list); если требуются полные офлайн-детали, используйте [экспорт объёма вызовов](https://platform.acedata.cloud/documents/platform-usage-export).

Диапазон запросов для записей вызовов и сводок по тарификации составляет последние 60 дней; тела запросов и ответов отдельно хранятся последние 30 дней. Истечение срока хранения тела не изменяет фактическое списание, объём использования или агрегированную статистику этой записи.

## Подготовка

1. Войдите на [платформу AceDataCloud](https://platform.acedata.cloud).
2. Создайте токен учётной записи в [консоли Account Token](https://platform.acedata.cloud/console/platform-tokens) и сразу сохраните его.
3. Если нужно сузить область, получите соответствующий ID из [списка заявок на сервисы](https://platform.acedata.cloud/documents/platform-application-list), [списка учётных данных API](https://platform.acedata.cloud/documents/platform-credential-list) или [списка API](https://platform.acedata.cloud/documents/platform-api-list).

Полное описание токенов см. в разделе [управление токенами учётной записи](https://platform.acedata.cloud/documents/platform-token). Этот интерфейс использует Account Token, а не бизнес-учётные данные Credential.

```shell
export PLATFORM_TOKEN='твой токен учётной записи'
```

## Обзор интерфейса

| Пункт           | Содержание                                                   |
| --------------- | ------------------------------------------------------------ |
| Метод           | `GET`                                                        |
| URL             | `https://platform.acedata.cloud/api/v1/usage/apis/aggregate/` |
| Аутентификация  | `Authorization: Bearer ${PLATFORM_TOKEN}`                    |
| OAuth Scope     | `usage:read` (включается через `platform:read` / `platform`) |
| Область доступа | Для обычных пользователей фиксирована их собственным платным использованием; администратор может передать `user_id` |

## Параметры запроса

| Параметр          | Тип             | Обяз. | По умолчанию                                | Описание                                                        |
| ----------------- | --------------- | ----- | -------------------------------------------- | --------------------------------------------------------------- |
| `created_at_from` | date / datetime | Нет   | Первый день текущего месяца в выбранном часовом поясе | Время начала, рекомендуемое имя параметра                       |
| `created_at_to`   | date / datetime | Нет   | Текущее время                                | Время окончания, рекомендуемое имя параметра                    |
| `timezone`        | string          | Нет   | `UTC`                                        | Часовой пояс IANA, например `Asia/Shanghai`; недопустимое значение возвращается к UTC |
| `service_id`      | UUID            | Нет   | —                                            | Фильтрация по сервису; поддерживает повторяющиеся параметры     |
| `application_id`  | UUID            | Нет   | —                                            | Фильтрация по Application; поддерживает повторяющиеся параметры |
| `api_id`          | UUID            | Нет   | —                                            | Фильтрация по API; поддерживает повторяющиеся параметры         |
| `credential_id`   | UUID            | Нет   | —                                            | Фильтрация по учётным данным API; поддерживает повторяющиеся параметры |
| `include_models`  | boolean         | Нет   | `false`                                      | Вычислять ли дополнительно сводку по измерению моделей; увеличивает стоимость запроса |
| `user_id`         | UUID            | Нет   | Для обычных пользователей фиксирован самим пользователем; для администратора при отсутствии параметра — все учётные записи | Только администратор может указать любую учётную запись |

`start_time` / `end_time` всё ещё можно использовать как совместимые псевдонимы для старых клиентов; для новых интеграций единообразно используйте `created_at_from` / `created_at_to`. `created_at_to` в формате даты включает этот календарный день, то есть в качестве границы используется полночь следующего дня.

## Примеры запросов

Запросить ежедневную/API-сводку за текущий месяц по пекинскому времени с добавлением измерения моделей:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  --data-urlencode 'include_models=true' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Запросить объём использования за неделю для указанного Application:

```shell
export APPLICATION_ID='твой Application ID'

curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'created_at_from=2026-09-01' \
  --data-urlencode 'created_at_to=2026-09-07' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Пример Python:

```python
import os
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/usage/apis/aggregate/",
    headers={"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    params={
        "created_at_from": "2026-09-01",
        "created_at_to": "2026-09-07",
        "timezone": "Asia/Shanghai",
        "include_models": "true",
    },
    timeout=30,
)
response.raise_for_status()
data = response.json()
print("requests:", data["requests"], "deducted:", data["total"])
for row in data["items"]:
    print(row["date"], row["api_id"], row["amount"])
```

## Пример ответа

```json
{
  "items": [
    {
      "date": "2026-09-01",
      "api_id": "00000000-0000-4000-8000-000000000001",
      "amount": 12.5
    }
  ],
  "total": 12.5,
  "apis": {
    "00000000-0000-4000-8000-000000000001": {
      "title": "Example API"
    }
  },
  "requests": 42,
  "models": [
    {
      "model": "example-model",
      "amount": 12.5,
      "requests": 42
    }
  ]
}
```

## Поля ответа

| Поле       | Описание                                                                 |
| ---------- | ------------------------------------------------------------------------ |
| `items`    | Группировка по дате в выбранном часовом поясе и `api_id`; каждая строка содержит `date`, `api_id`, `amount` |
| `total`    | Сумма `deducted_amount` в диапазоне запроса                              |
| `apis`     | Сопоставление ID API со сводкой заголовков, для удобства отображения `items` |
| `requests` | Общее количество запросов в диапазоне запроса                            |
| `models`   | Вычисляется только при `include_models=true`; каждый элемент содержит `model`, `amount`, `requests` |

Единица измерения квоты зависит от `service.unit` соответствующего Application. Если запрос включает сервисы с разными единицами измерения, сначала выполните отдельную статистику по `service_id` или `application_id`, чтобы избежать прямого сравнения или сложения.

Если время окончания не больше времени начала, интерфейс возвращает полную пустую структуру: `items=[]`, `total=0`, `apis={}`, `requests=0`, `models=[]`.

## Рекомендации по ошибкам и производительности

| HTTP | `error`                 | Способ обработки                                           |
| ---- | ----------------------- | ---------------------------------------------------------- |
| 400  | `usage_history_expired` | Скорректируйте временной диапазон на период после `available_from` в ответе |
| 401  | `not_authenticated`     | Проверьте Account Token, не используйте по ошибке бизнес-учётные данные Credential |
| 403  | `permission_denied`     | Обычные пользователи не могут запрашивать другие учётные записи |

- По умолчанию не включайте `include_models`; активируйте его только если отчёту действительно требуется разбивка по моделям.
- Для запросов большого диапазона приоритетно разделяйте данные по `service_id` или `application_id`: это позволяет избежать смешивания единиц измерения и снизить стоимость запроса.
- Даты без вызовов не заполняются нулями автоматически; перед построением графика клиент должен дополнить ось дат.
