Запрос подробностей вызовов бизнес-API текущей учетной записи за последние 60 дней; подходит для сверки списаний, поиска неуспешных запросов, а также устранения неполадок по сервису, Application, API или учетным данным.

> На этой странице запрашиваются собственные записи вызовов учетной записи. Если нужно просмотреть только общедоступную статистику вызовов определенного API по всей платформе, используйте [Статистику вызовов API](https://platform.acedata.cloud/documents/platform-api-usage).

## Срок хранения данных

Записи вызовов и сводки по тарификации хранятся последние 60 дней; тела запросов и ответов хранятся последние 30 дней. Для записей за 30–60 дней по-прежнему можно запросить сводные данные, такие как trace, статус, время, модель, использование и фактическое списание; `metadata.request` и `metadata.response` в подробностях больше не возвращаются. Сводные данные, необходимые для статистики моделей и действительных результатов, хранятся до истечения срока хранения тел. Если требуется длительное хранение тел, сохраняйте их самостоятельно при вызове.

## Подготовка

### 1. Создание токена учетной записи

Этот интерфейс относится к API управления платформой и требует использования **Account Token (токена учетной записи)**:

1. Войдите на [платформу AceDataCloud](https://platform.acedata.cloud).
2. Откройте [консоль Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. Нажмите «Создать» и немедленно сохраните токен в менеджере паролей или Secret Manager.

Полное описание см. в разделе [Управление токенами учетной записи платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-token). Токен учетной записи используется для `platform.acedata.cloud/api/v1/**`; для вызова бизнес-интерфейсов `api.acedata.cloud/**` используются учетные данные API (Credential), и их нельзя смешивать.

```shell
export PLATFORM_TOKEN='ваш токен учетной записи'
```

Не записывайте токен в код фронтенда, журналы или публичные репозитории; при утечке немедленно удалите его в консоли и создайте заново.

### 2. Подготовка ID для фильтрации (необязательно)

Без передачи условий фильтрации можно просмотреть записи, к которым текущая учетная запись имеет доступ. Когда требуется сузить область:

- `application_id`: получите из [списка заявок на сервисы](https://platform.acedata.cloud/documents/platform-application-list);
- `credential_id`: получите из [списка учетных данных API](https://platform.acedata.cloud/documents/platform-credential-list);
- `api_id`: получите из [списка API](https://platform.acedata.cloud/documents/platform-api-list);
- `service_id`: получите из [списка сервисов](https://platform.acedata.cloud/documents/platform-service-list).

Обычным пользователям не нужно передавать `user_id`; при явной передаче он должен совпадать с текущей учетной записью, иначе возвращается `403`. Администраторы могут использовать этот параметр для межучетной фильтрации.

## Обзор интерфейса

| Пункт           | Содержание                                           |
| --------------- | ---------------------------------------------------- |
| Метод           | `GET`                                                |
| URL             | `https://platform.acedata.cloud/api/v1/usage/apis/`  |
| Аутентификация  | `Authorization: Bearer ${PLATFORM_TOKEN}`            |
| OAuth Scope     | `usage:read` (`platform:read` / `platform` включает) |
| Пагинация       | `count` + `items`, по умолчанию 10 записей на страницу |

## Область запроса

| `perspective` | Значение                                                  |
| ------------- | --------------------------------------------------------- |
| `both`        | Значение по умолчанию; возвращает записи, оплаченные или фактически вызванные текущей учетной записью |
| `billing`     | Возвращает только записи, оплаченные текущей учетной записью |
| `actor`       | Возвращает только записи, фактически вызванные текущей учетной записью |

## Параметры запроса

| Параметр          | Тип      | Обязательный | По умолчанию  | Описание                                      |
| ----------------- | -------- | ------------ | -------------- | --------------------------------------------- |
| `perspective`     | string   | Нет          | `both`         | `billing`, `actor` или `both`                 |
| `user_id`         | UUID     | Нет          | —              | Только администраторы: фильтрация по пользователю; поддерживает повторяющиеся параметры |
| `service_id`      | UUID     | Нет          | —              | Фильтрация по сервису; поддерживает повторяющиеся параметры |
| `application_id`  | UUID     | Нет          | —              | Фильтрация по Application; поддерживает повторяющиеся параметры |
| `api_id`          | UUID     | Нет          | —              | Фильтрация по API; поддерживает повторяющиеся параметры |
| `credential_id`   | UUID     | Нет          | —              | Фильтрация по учетным данным API; поддерживает повторяющиеся параметры |
| `status_code`     | integer  | Нет          | —              | Фильтрация по коду состояния HTTP; поддерживает повторяющиеся параметры или значения, разделенные запятыми |
| `created_at_from` | datetime | Нет          | —              | Нижняя граница времени создания, ISO 8601     |
| `created_at_to`   | datetime | Нет          | —              | Верхняя граница времени создания, ISO 8601     |
| `limit`           | integer  | Нет          | 10             | Число записей на страницу, максимум 100       |
| `offset`          | integer  | Нет          | 0              | Смещение пагинации                             |
| `ordering`        | string   | Нет          | `-created_at`  | Сортировка по времени создания в обратном порядке |

Когда время запроса раньше последних 60 дней, интерфейс возвращает ошибку проверки поля `400` с указанием, что полные сведения о вызовах хранятся только 60 дней.

## Примеры запросов

Запрос последних 100 записей:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/' \
  --data-urlencode 'perspective=both' \
  --data-urlencode 'limit=100' \
  --data-urlencode 'ordering=-created_at' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Фильтрация по времени, Application и статусу ошибки:

```shell
export APPLICATION_ID='ваш Application ID'

curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/' \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'created_at_from=2026-09-01T00:00:00Z' \
  --data-urlencode 'created_at_to=2026-09-02T00:00:00Z' \
  --data-urlencode 'status_code=500' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Пример пагинации на Python:

```python
import os
import requests

url = "https://platform.acedata.cloud/api/v1/usage/apis/"
headers = {"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"}
params = {"perspective": "both", "limit": 100, "offset": 0}

response = requests.get(url, headers=headers, params=params, timeout=30)
response.raise_for_status()
data = response.json()

for usage in data["items"]:
    print(usage["created_at"], usage["status_code"], usage["deducted_amount"], usage["trace_id"])

if params["offset"] + len(data["items"]) < data["count"]:
    params["offset"] += len(data["items"])
```

## Ключевые поля

| Поле                               | Описание                                  |
| -------------------------------- | ----------------------------------- |
| `user_id`                        | Учётная запись, с которой списывается плата за этот вызов                           |
| `actor_user_id`                  | Учётная запись, фактически инициировавшая вызов; при предоставлении другим лицам доступа к учётным данным может отличаться от `user_id` |
| `used_amount`                    | Объём использования для этого вызова, рассчитанный по исходным правилам                       |
| `original_amount`                | Исходный объём использования до применения скидки приложения                          |
| `deducted_amount`                | Итоговый фактически списанный лимит                           |
| `remaining_amount`               | Оставшийся лимит Application после завершения этого списания           |
| `elapsed`                        | Время выполнения вызова, зарегистрированное сервером, в секундах                     |
| `trace_id`                       | Идентификатор трассировки, используемый при диагностике отдельного запроса                      |
| `metadata`                       | Публичные метаданные; список не возвращает полное содержимое запроса или ответа               |
| `api` / `service` / `credential` | Сводка связанных объектов для удобного отображения; может быть пустой, если связанный объект больше не существует           |

Единица лимита определяется `service.unit` соответствующего Application и не должна по умолчанию считаться долларами США.

## Ошибки и повторные попытки

| HTTP | `error`                   | Значение             | Способ обработки                               |
| ---- | ------------------------- | -------------- | ---------------------------------- |
| 400  | Ошибка проверки поля                    | Диапазон запроса выходит за пределы 60-дневного срока хранения | Скорректируйте время начала, чтобы оно находилось в пределах последних 60 дней                  |
| 401  | `not_authenticated`       | Токен учётной записи отсутствует или недействителен      | Проверьте Account Token, не используйте по ошибке бизнес Credential |
| 403  | `permission_denied`       | Запрос содержит записи, для просмотра которых нет прав    | Удалите неавторизованные условия фильтрации пользователей                       |
| 429  | `usage_query_in_progress` | Полностью идентичный запрос всё ещё выполняется    | Подождите `Retry-After`, затем повторите попытку с экспоненциальной задержкой             |
| 503  | `usage_query_timeout`     | Запрос превысил безопасный лимит времени сервера    | Сузьте временной диапазон или добавьте условия фильтрации, затем повторите попытку                   |

Для одного набора параметров запроса допускается не более одного запроса в процессе выполнения. Для запросов большого диапазона в первую очередь используйте окно в один день или меньше, не накладывайте идентичные запросы с фиксированным интервалом.
