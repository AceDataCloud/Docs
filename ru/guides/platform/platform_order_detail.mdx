Запрос заказа по ID заказа. Этот эндпоинт поддерживает два режима чтения: анонимный доступ возвращает только минимальные поля, необходимые для страницы оплаты; владелец заказа с Account Token получает полные сведения.

## Обзор интерфейса

| Пункт   | Содержание                                                        |
| --- | --------------------------------------------------------- |
| Метод  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| Аутентификация  | Необязательно; анонимный доступ предоставляет минимальную проекцию, а аутентифицированный владелец — полную проекцию                                    |

`/orders/{id}` и `/orders/{id}/` в настоящее время оба доступны. ID заказа является частью платёжной ссылки и должен рассматриваться как конфиденциальный непрозрачный идентификатор, не распространяйте его публично.

## Анонимный запрос

Страница оплаты может выполнять прямое чтение при потере состояния входа:

```shell
export ORDER_ID='你的订单 ID'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

Анонимный ответ содержит только `id`, `description`, `price`, `state`, `pay_way`, `pay_url`, `expired_at`, `created_at`. Он не возвращает аккаунт, Application, Package, внутренние идентификаторы оплаты или metadata.

## Аутентифицированный запрос

```shell
export PLATFORM_TOKEN='你的账户令牌'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Владелец заказа получает полные сведения Order, включая `application` / `applications`, `package` / `packages`, `bank_details`, `invoice_automation` и поля модели. Если пользователь аутентифицирован, но не является владельцем заказа, возвращается `403`; за исключением суперадминистратора.

## Ключевые поля

| Поле            | Описание                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`, `Paid`, `Finished`, `Expired`, `Failed` или `Refunded` |
| `pay_way`     | Текущий способ оплаты заказа; имя поля не `payment_method`                             |
| `pay_url`     | Адрес размещённой страницы оплаты или QR-кода, может быть пустым                                           |
| `price`       | Итоговая сумма к оплате по заказу, текущая модель заказа не предоставляет поле `final_price`                         |
| `amount`      | Количество лимита пакета; доступно только в полном аутентифицированном ответе                                            |
| `finished_at` | Время завершения заказа; имя поля не `paid_at`                                      |

Полный ответ может содержать дополнительные поля в зависимости от способа оплаты, клиенты должны читать их по необходимости и всегда избегать записи конфиденциальных metadata из полного ответа.

## Обработка ошибок

- `404`: ID заказа не существует.
- `403`: пользователь вошёл в систему, но не является владельцем заказа.
- Анонимные запросы не возвращают `401`; они получают только минимальную публичную проекцию.
