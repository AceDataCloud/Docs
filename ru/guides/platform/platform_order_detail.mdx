Запрос заказа по ID заказа. Этот endpoint поддерживает два режима чтения: анонимный доступ возвращает только минимальные поля, необходимые для страницы оплаты; владелец заказа с Account Token получает полные сведения.

## Обзор интерфейса

| Пункт   | Содержание                                                        |
| --- | --------------------------------------------------------- |
| Метод  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| Авторизация  | Необязательна; анонимный доступ — минимальная проекция, авторизованный владелец — полная проекция                                    |

`/orders/{id}` и `/orders/{id}/` в настоящее время оба доступны. ID заказа является частью ссылки на оплату и должен рассматриваться как конфиденциальный непрозрачный идентификатор, не распространяйте его публично.

## Анонимный запрос

Страница оплаты может выполнять прямое чтение при потере состояния входа:

```shell
export ORDER_ID='你的订单 ID'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

Анонимный ответ содержит только `id`, `description`, `price`, `state`, `pay_way`, `pay_url`, `expired_at`, `created_at`. Он не возвращает аккаунт, Application, Package, внутренние идентификаторы оплаты или metadata.

## Авторизованный запрос

```shell
export PLATFORM_TOKEN='你的账户令牌'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Владелец заказа получает полные сведения Order, включая `application` / `applications`, `package` / `packages`, `bank_details`, `invoice_automation` и поля модели. Если пользователь авторизован, но не является владельцем заказа, возвращается `403`; за исключением супер-администраторов.

## Ключевые поля

| Поле            | Описание                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`, `Paid`, `Finished`, `Expired`, `Failed` или `Refunded` |
| `pay_way`     | Текущий способ оплаты заказа; имя поля не `payment_method`                             |
| `pay_url`     | Адрес размещённой страницы оплаты или QR-кода, может быть пустым                                           |
| `price`       | Окончательная сумма к оплате по заказу; текущая модель заказа не предоставляет поле `final_price`                         |
| `amount`      | Количество лимита пакета; видно только в полном авторизованном ответе                                            |
| `finished_at` | Время завершения заказа; имя поля не `paid_at`                                      |

Полный ответ может содержать дополнительные поля в зависимости от способа оплаты, клиенту следует читать их по необходимости и всегда избегать логирования конфиденциальных metadata из полного ответа.

## Обработка ошибок

- `404`: ID заказа не существует.
- `403`: пользователь вошёл в систему, но не является владельцем заказа.
- Анонимные запросы не возвращают `401`; они получают только минимальную публичную проекцию.

## Аннулирование счёта-фактуры и повторная заявка

Через `GET /api/v1/orders/{order_id}/invoice/` можно получить текущий счёт-фактуру заказа. После отправки автоматического аннулирования счёт-фактура по-прежнему имеет статус `Issued`, а `red_state` обозначает ход аннулирования; успешная отправка не означает завершения аннулирования. Во время ожидания подтверждения, оформления красного счёта или архивирования заказ не может повторно подать заявку на счёт-фактуру.

Когда администратор запрашивает аннулирование из-за ошибки в платёжной информации, такой как наименование или налоговый номер, причиной аннулирования является «ошибка при выставлении счёта»; автоматическое аннулирование, вызванное возвратом средств по заказу, по-прежнему использует «прекращение обслуживания».

После успешного оформления и архивирования красного счёта исходный счёт-фактура становится `Voided`, и только тогда заказ может подать повторную заявку. Исходный счёт-фактуру можно просмотреть в истории счетов-фактур. Если аннулирование не удалось или результат требует проверки, этим занимается финансовый отдел, и ограничение на выставление счёта для заказа не будет снято заранее. Счета-фактуры, оформленные вручную, необходимо сначала аннулировать или провести через красный счёт в налоговой или системе выставления счетов, после чего финансовый отдел подтвердит это на платформе.
