Постранично возвращает Application, которыми владеет учетная запись или на использование которых она получила разрешение, включая баланс, статус, сводку услуг и связанные учетные данные. Подходит для массового мониторинга баланса, поиска Application ID и перехода к управлению учетными данными.

## Подготовка

1. Войдите в [платформу AceDataCloud](https://platform.acedata.cloud).
2. Создайте токен учетной записи в [консоли Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. Обычные пользователи используют `user_id=me`; также можно получить свой UUID через `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='ваш токен учетной записи'
```

## Обзор интерфейса

| Пункт   | Содержание                                                    |
| --- | ----------------------------------------------------- |
| Метод  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Аутентификация  | Account Token, OAuth token требует `applications:read`       |
| Пагинация  | `count` + `items`                                     |

Обычные пользователи должны передавать `user_id=me`. Если не передавать, запрос сначала не сужается по учетной записи, и при пагинации объекты без прав доступа могут вернуть `403`; администраторы без передачи могут просматривать всю таблицу.

## Параметры запроса

| Параметр            | Тип          | Обязательный     | Описание                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Обязательно для обычных пользователей | Субъект запроса; поддерживает повторяющиеся параметры                                         |
| `affiliation` | string      | Нет      | `owner` (по умолчанию) или `granted`; можно повторно передать оба для получения объединения, действует только при наличии `user_id` |
| `service_id`  | UUID        | Нет      | Фильтрация по услуге; поддерживает повторяющиеся параметры                                        |
| `scope`       | string      | Нет      | `Individual` или `Global`; поддерживает повторяющиеся параметры                      |
| `type`        | string      | Нет      | `Usage` или `Period`; поддерживает повторяющиеся параметры                           |
| `limit`       | integer     | Нет      | Количество элементов на странице, максимум 100                                         |
| `offset`      | integer     | Нет      | Смещение пагинации                                               |
| `ordering`    | string      | Нет      | Поддерживаются только `created_at` или `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` и `tag` в настоящее время не являются параметрами серверной фильтрации. Для предупреждений о балансе после получения списка следует выполнять проверку на клиенте на основе `remaining_amount`, `service.unit` и бизнес-порогов каждого Application.

## Примеры запросов

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Одновременный просмотр Application, которыми вы владеете, и Application, на использование которых вам выданы разрешения другими:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Описание ответа

Ответ имеет вид `{count, items}`. Каждый элемент содержит поля модели Application, а также:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: сводка учетных данных, которые текущий вызывающий пользователь имеет право видеть;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`, `allow_overdraft`;
- фактическое значение `scope` — `Individual` или `Global`;
- фактическое значение `type` — `Usage` или `Period`.

`allow_overdraft` — это управляемое администратором доступное только для чтения булево поле, по умолчанию `false`. Для приложений с оплатой по использованию (`Usage`), в которых включен овердрафт, недостаточный баланс не будет блокировать вызовы, и плата по-прежнему взимается в соответствии с фактическим использованием; отрицательный баланс означает объем, ожидающий расчета. Отключение, истечение срока действия и ограничения API-учетных данных по-прежнему действуют.

`remaining_amount` может быть пустым; клиент должен сначала проверить его на пустоту, а затем выполнять числовое сравнение. Единица измерения квоты определяется `service.unit`.
