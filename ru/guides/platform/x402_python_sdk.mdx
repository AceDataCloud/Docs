Python SDK подходит для бэкенд-сервисов, задач обработки данных, автоматизированных Agent и пакетных скриптов. `acedatacloud` отвечает за API-вызовы, а `acedatacloud-x402` отвечает за формирование заголовка запроса `PAYMENT-SIGNATURE`.

Исходный код и адреса пакетов:

- Репозиторий SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Репозиторий X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- PyPI SDK: [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)
- PyPI X402 Client: [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)

## Установка зависимостей

```bash
pip install acedatacloud acedatacloud-x402
```

Если требуется использовать `upto`, также необходимо однократно вызвать Permit2 approve CLI, этот CLI зависит от `web3`:

```bash
pip install 'acedatacloud-x402[cli]'
```

Вывод установки и проверки импорта в чистом Python venv:

```text
acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
approve-permit2  One-time ERC-20 approve(Permit2, amount) needed before signing upto payments.
```

Пояснение результатов:

- `acedatacloud` и `acedatacloud-x402` можно установить и импортировать из PyPI.
- `pip install 'acedatacloud-x402[cli]'` включает CLI `approve-permit2`, используемый для предварительной авторизации `upto`.

## Пример Base

Приведённый ниже пример не требует API Token. Приватный ключ кошелька используется только для локальной подписи и не будет отправлен в Ace Data Cloud.

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)

print(res["choices"][0]["message"]["content"])
```

Python SDK в настоящее время возвращает `dict`, поэтому в примере используется `res["choices"][0]["message"]["content"]`. Не следует напрямую предполагать, что у него обязательно есть атрибут `.choices`.

## Пример Solana

Solana использует secret key в кодировке base58:

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import SolanaKeypairSigner, create_x402_payment_handler

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="solana",
        solana_signer=SolanaKeypairSigner.from_base58(os.environ["SOLANA_SECRET_KEY"]),
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

Путь Solana создаёт и отправляет транзакцию SPL USDC `TransferChecked`, затем помещает подпись транзакции в envelope `PAYMENT-SIGNATURE`.

Платный повтор Solana уже вернул HTTP 200 и `ADC_SOLANA_E2E_OK` в production API. В этом публичном RPC-запросе возникло ограничение частоты, поэтому не удалось стабильно подтвердить on-chain signature; при необходимости сверки используйте свой Solana RPC для запроса этой транзакции.

## Async-клиент

Тот же payment handler можно использовать для `AsyncAceDataCloud`:

```python
import os

from acedatacloud import AsyncAceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AsyncAceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = await client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

## Использование `upto` для постоплаты по фактическому потреблению

Фактическая стоимость API, таких как чат-дополнения и вызовы моделей, может быть известна только после завершения ответа. В этом случае API может одновременно возвращать `exact` и `upto`. Если требуется отдавать приоритет `upto`:

```python
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
        prefer_scheme="upto",
    )
)
```

Результат выполнения программы Base `upto`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
settlement tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
settled value 3 atomic USDC
```

Подтверждение в сети:

```text
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
transfer value 3 atomic USDC
```

Пояснение результатов:

- `content ADC_BASE_UPTO_OK` означает, что запрос действительно поступил в API модели.
- `settled value 3 atomic USDC` означает, что `upto` рассчитывается по фактическому использованию, а не списывает полный лимит.
- `settlement tx` можно открыть в BaseScan; при сверке сохраняйте tx hash, payer, completion id и сводку запроса.

`upto` использует Permit2 для авторизации лимита, фактическая сумма расчёта не может превышать этот лимит. Перед первым использованием необходимо однократно выполнить `approve(Permit2, amount)` для USDC в целевой сети.

Способ через CLI:

```bash
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Способ через программу:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Этот helper идемпотентен. Если allowance уже достаточно, он вернёт `{"skipped": true}` и не будет повторно отправлять on-chain транзакцию.

## Низкоуровневая подпись

Если вы не используете SDK, можно напрямую вызывать низкоуровневую функцию подписи:

```python
import base64
import json

from acedatacloud_x402 import EVMAccountSigner, sign_evm_payment

envelope = sign_evm_payment(requirement, EVMAccountSigner.from_private_key("0x..."))
x_payment = base64.b64encode(json.dumps(envelope, separators=(",", ":")).encode()).decode()
```

Низкоуровневые функции подходят для тестирования, прокси-слоя, интеграции шлюзов или неофициальных SDK. Для обычного бизнес-кода приоритетно использовать `create_x402_payment_handler`.
