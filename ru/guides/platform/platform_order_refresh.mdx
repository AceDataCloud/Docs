---
title: "Обновление статуса заказа на платформе AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Активно запросите последний статус соответствующего способа оплаты заказа и синхронизируйте его с платформой. Этот запрос может обращаться к платёжному сервису и изменять статус заказа, используйте его только при задержке обратного вызова или когда требуется немедленное подтверждение.

## Подготовка

- Используйте [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Получите ID своего заказа из [списка заказов](https://platform.acedata.cloud/documents/platform-order-list).

```shell
export PLATFORM_TOKEN='你的账户令牌'
export ORDER_ID='你的订单 ID'
```

## Обзор интерфейса

| Пункт    | Содержание                                                                 |
| ---- | ------------------------------------------------------------------ |
| Метод   | `POST`                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/refresh/` |
| Авторизация   | Владелец заказа или супер-администратор                                                        |
| Body | Обычно пустое; в сценариях обратного вызова PayPal могут потребоваться `payer_id` / `PayerID`                         |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/refresh/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

При успехе возвращается полный обновлённый объект Order. Используйте `state` для определения результата и `finished_at` в качестве времени завершения; в текущей модели отсутствует поле `paid_at`. Значения статуса включают `Pending`, `Paid`, `Finished`, `Expired`, `Failed`, `Refunded`.

Срок оплаты изменяет на `Expired` только заказы, всё ещё находящиеся в состоянии `Pending`. Уже возвращённые заказы `Refunded` остаются в возвращённом состоянии при обновлении или после получения отложенного обратного вызова оплаты.

## Рекомендации по повторным попыткам

- При обычной оплате в первую очередь полагайтесь на обратный вызов платформы; активно выполняйте refresh только если статус долго не обновляется.
- Не выполняйте фиксированный высокочастотный опрос. Рекомендуется экспоненциальная задержка и остановка после достижения явного конечного состояния.
- `401` означает недействительный токен; `403` означает, что вы не являетесь владельцем заказа; `404` означает, что заказ не существует.
- При ошибке запроса к платёжному сервису сохраните ID заказа и trace ID, повторите попытку позже; не создавайте дублирующие заказы вместо подтверждения статуса.
