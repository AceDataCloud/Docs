[Jan](https://jan.ai/) — это офлайн-ориентированный открытый настольный AI-клиент, который может как запускать модели локально, так и подключаться к совместимым с OpenAI конечным точкам через **Remote Engine**. В этой статье рассказывается, как подключить Ace Data Cloud.

## Процесс подачи заявки

Чтобы подключить Ace Data Cloud в Jan, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications), получите ваш API Token и сохраните его для дальнейшего использования.

![Получение Ace Data Cloud API Key](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти в систему; после входа или регистрации вы автоматически вернётесь на текущую страницу.

При первой подаче заявки предоставляется бесплатный лимит, позволяющий бесплатно опробовать модельные сервисы Ace Data Cloud.

## Скачать Jan

Перейдите на [официальный сайт Jan](https://jan.ai/) и скачайте версию для своей платформы (Windows, macOS, Linux). Для устройств Apple Silicon загрузите пакет arm64 для получения максимальной производительности.

## Настройка Ace Data Cloud

Jan разделяет модели на два типа: **Local Engine** (локальный запуск) и **Remote Engine** (сторонние API). Ace Data Cloud использует совместимый с OpenAI протокол и подключается через Remote Engine.

Откройте Jan, перейдите в **Settings → Model Providers**, найдите карточку **OpenAI** и отредактируйте её:

| Поле       | Значение                              | Описание                       |
| -------- | ------------------------------ | ------------------------ |
| API Key  | Ваш Ace Data Cloud Token        | Token, скопированный из консоли             |
| Base URL | `https://api.acedata.cloud/v1` | **Должен оканчиваться на `/v1`, без слэша в конце** |

> Требование, чтобы Base URL оканчивался на `/v1`, является явным соглашением в официальной документации Jan. Если вы не хотите перезаписывать исходную конфигурацию OpenAI, можно создать новый Provider типа `openai-compatible` через «+ Add Provider» и заполнить те же данные.

![Интерфейс настройки добавления AceDataCloud Provider в Jan](https://cdn.acedata.cloud/26017d28afa1.png)

После сохранения пользовательского Provider Jan сначала попытается вызвать `{Base URL}/models`, чтобы получить список моделей. Если текущая версия или конечная точка не возвращает доступный список, нажмите **+ Add Model** в нижней части той же страницы редактирования и вручную укажите ID модели. После добавления модель появится в выпадающем списке в левом верхнем углу и будет отмечена значком «Cloud», чтобы отличать удалённые модели от локальных.

![Интерфейс управления моделями Provider в Jan](https://cdn.acedata.cloud/ae485550946c.png)

> `MODEL_ID` — это заполнитель; перейдите в [каталог моделей](https://platform.acedata.cloud/models), чтобы посмотреть и заменить его названием целевой модели; при точной проверке ориентируйтесь на значение `id` в ответе `/v1/models`. Это значение является названием модели, используемым параметром API `model`, а не UUID сервиса или API.

## Выбор модели

[Каталог моделей](https://platform.acedata.cloud/models) постоянно обновляется. В приоритете используйте список моделей, автоматически загруженный клиентом; если требуется ручной ввод, сначала выполните запрос `GET https://api.acedata.cloud/v1/models`, скопируйте значение `id` целевой модели из массива `data` в ответе, затем выбирайте в соответствии с поддерживаемыми клиентом возможностями контекста, изображений и вызова инструментов.

## Проверка подключения

Если вы не уверены, в Jan ли проблема или в сети, можно сначала напрямую проверить конечную точку с помощью curl (замените `{token}` на ваш Token):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

Возврат совместимого с OpenAI объекта `chat.completion` означает, что Token и конечная точка готовы; если возвращается `HTTP 403 used_up`, это означает, что Token действителен, но баланс недостаточен — достаточно пополнить счёт в [консоли](https://platform.acedata.cloud/console/applications).

## Расширенно: гибридное использование локальных моделей + облака

Jan включает локальный совместимый с OpenAI API Server, который можно включить (Settings → Local API Server). После включения он прослушивает `http://localhost:1337/v1/chat/completions` и запускает загруженные вами локальные модели. Таким образом, в таких фреймворках, как LangChain / LlamaIndex, можно направить Base URL на локальный адрес для бесплатной отладки, а для сложных задач переключаться на удалённые модели Ace Data Cloud. При переключении моделей контекст диалога не будет потерян.

## Часто задаваемые вопросы

### Появляется Connection error или 404

Обычно это означает, что в Base URL отсутствует `/v1`. Измените его на `https://api.acedata.cloud/v1` (он должен оканчиваться на `/v1`, и не следует указывать `.../openai/v1`).

### Появляется 401 Unauthorized

Убедитесь, что в API Key вставлен Token Ace Data Cloud (без префикса `Bearer` и без лишних пробелов), а баланс соответствующего приложения достаточен.

### Удалённые модели не отображаются в выпадающем списке

Сначала нажмите кнопку обновления моделей, чтобы вызвать `/v1/models`; если автоматическое обнаружение не удалось, вручную нажмите **+ Add Model** и добавьте значение `id` модели из каталога без изменений.

### Можно ли загрузить изображение для анализа моделью

Можно, но необходимо выбрать модель из текущего каталога моделей, которая явно поддерживает визуальный ввод.
