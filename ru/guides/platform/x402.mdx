X402 — это протокол ончейн-платежей на основе HTTP `402 Payment Required`. Благодаря возможностям X402 от Ace Data Cloud вызывающая сторона может не создавать API Token, не пополнять баланс аккаунта заранее, а напрямую оплачивать USDC в сети при каждом API-запросе.

Этот набор документов организован в порядке реального подключения: сначала выполните один минимальный запрос, затем подключите SDK, после этого изучите сети, тарифные схемы, оплату заказов и Facilitator. Рекомендуется читать сверху вниз согласно таблице ниже.

## Рекомендуемый путь подключения

Если вы хотите только вызывать Ace Data Cloud API, в первую очередь используйте официальный SDK:

- TypeScript: `@acedatacloud/sdk` + `@acedatacloud/x402-client`
- Python: `acedatacloud` + `acedatacloud-x402`

Адреса открытых исходных кодов и пакетов:

| Проект                 | Адрес                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| Ace Data Cloud SDK | [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)                                         |
| X402 Client        | [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)                           |
| X402 Facilitator   | [https://github.com/AceDataCloud/FacilitatorX402](https://github.com/AceDataCloud/FacilitatorX402)                 |
| npm SDK            | [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)                 |
| npm X402 Client    | [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client) |
| PyPI SDK           | [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)                                   |
| PyPI X402 Client   | [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)                         |

SDK автоматически выполнит шаги первого запроса без аутентификации, разбора `402 Payment Required`, вызова payment handler и повторной попытки с `PAYMENT-SIGNATURE`. Вам нужно лишь подготовить кошелек с USDC и выбрать сеть, которую вы хотите использовать.

Если вы хотите, чтобы ваш собственный API также поддерживал прием платежей X402, вам необходимо прочитать документацию Facilitator и понять взаимосвязь между `paymentRequirements`, `paymentPayload`, `/verify` и `/settle`.

## Статус поддержки

Ace Data Cloud X402 прошел проверку на публичном API, официальных SDK, Facilitator и пути ончейн-расчетов. В таблице ниже приведен текущий статус по наиболее часто используемым возможностям при подключении разработчиков.

| Возможность                       | Статус                  | Описание                                                                 |
| ------------------------ | ------------------- | ------------------------------------------------------------------ |
| Facilitator capabilities | Доступно                  | `https://facilitator.acedata.cloud/.well-known/x402` возвращает платежные сети и конечные точки протокола.  |
| API 402 `accepts`        | Доступно                  | Неоплаченные запросы возвращают доступные payment requirement для Base и Solana.                    |
| TypeScript SDK           | Доступно                  | `@acedatacloud/sdk` и `@acedatacloud/x402-client` могут автоматически обрабатывать 402, подписи и повторные попытки. |
| Python SDK               | Доступно                  | `acedatacloud` и `acedatacloud-x402` могут автоматически обрабатывать 402, подписи и повторные попытки.              |
| Base `exact`             | Проверено в сети               | Подходит для API с фиксированной суммой и оплаты заказов.                                                  |
| Base `upto`              | Проверено в сети               | Подходит для API с последующим учетом, таких как чат-дополнения; в настоящее время это единственная сеть, предоставляющая `upto`.                                 |
| Solana `exact`           | HTTP paid retry проверен | Проверены API paid retry и ответы модели; для сверки ончейн-подписей рекомендуется использовать собственный Solana RPC.               |
| Оплата заказов                     | Проверено в сети               | Оплата заказов Base `exact` завершила ончейн-расчет и обновила статус заказа.                                   |

## Примечания по интеграции

При интеграции разработчикам следует в первую очередь обращать внимание на требования к оплате в реальном времени, возвращаемые текущим запросом, а не копировать примерные суммы или адреса из документации：

- `accepts[].maxAmountRequired` — максимальная сумма, которая может быть подписана для текущего запроса.
- `accepts[].asset` — контракт USDC или mint, который должен использоваться для этого запроса.
- `accepts[].extra.chainId`、`accepts[].extra.facilitatorAddress` и `accepts[].extra.verifyingContract` участвуют в подписи EVM typed data.
- Для `upto` кошелёк должен сначала авторизовать Permit2 для USDC целевой сети; при отсутствии авторизации будет возвращён `PERMIT2_ALLOWANCE_REQUIRED`.
- Если явно требуется использовать постоплатное измерение, передайте `preferScheme: 'upto'` в TypeScript SDK; в противном случае SDK выберет первое доступное requirement, возвращённое сервером для этой сети.

## Диапазон, который можно публично проверить

Перед интеграцией можно сначала проверить эти публичные точки входа и поведение SDK：

- API-запрос без `Authorization` или `PAYMENT-SIGNATURE` вернёт `402 Payment Required`; `accepts` в ответе является единственным основанием для подписи данного запроса.
- TypeScript SDK и Python SDK оба предоставляют payment handler; транспортный слой SDK после получения 402 вызовет handler и повторит запрос один раз.
- `https://facilitator.acedata.cloud/.well-known/x402`：возвращает сети, scheme и протокольные конечные точки, поддерживаемые Facilitator; цена API по-прежнему определяется 402, возвращаемым целевым запросом в реальном времени.
- `https://facilitator.acedata.cloud/supported`：возвращает сети и scheme, поддерживаемые Facilitator.
- Репозиторий X402Client содержит расширенные инструменты ончейн-проверки, которые могут использоваться для подтверждения подписи, повторной попытки и поведения settlement; вывод инструментов не заменяет `accepts`, возвращаемый онлайн API.

`upto` относится к постоплатному измерительному settlement и подходит для API, таких как чат-дополнения и вызовы моделей, где фактическое использование становится известно только после ответа. В настоящее время только Base предоставляет `upto`; если проверка подписи не удалась, проверьте, соответствуют ли chain id, адрес facilitator, spender, контракт USDC и Permit2 allowance ответу 402.
