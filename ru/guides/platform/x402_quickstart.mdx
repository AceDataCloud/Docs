В этом руководстве на примере минимального API-запроса объясняется полный процесс Ace Data Cloud X402. Цель — не сначала писать сложный код, а сначала понять: почему первый запрос возвращает 402, что содержится в `accepts` и как `PAYMENT-SIGNATURE` превращает тот же API-запрос в оплаченный запрос.

## Подготовка

Вам нужно подготовить:

| Пункт   | Описание                                                   |
| ---- | ---------------------------------------------------- |
| Кошелёк   | Кошелёк, поддерживающий целевую сеть. Base использует EVM-кошелёк, Solana использует Solana-кошелёк.      |
| USDC | В кошельке должно быть достаточно USDC. Фактическая сумма определяется `maxAmountRequired` в ответе 402. |
| Среда разработки | Для TypeScript рекомендуется Node.js 18+; для Python рекомендуется Python 3.10+.    |
| SDK  | Рекомендуется использовать официальный SDK, не рекомендуется вручную реализовывать детали подписи.                                |

При вызове Ace Data Cloud API через X402 API Token не требуется. Первый запрос SDK не содержит `Authorization`, Gateway вернёт `402 Payment Required` и требования к оплате; после подписи SDK автоматически повторит попытку.

## Установка SDK

Исходный код и адреса пакетов:

- Репозиторий SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Репозиторий X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm: `@acedatacloud/sdk`、`@acedatacloud/x402-client`
- PyPI: `acedatacloud`、`acedatacloud-x402`

TypeScript:

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client ethers
```

Python:

```bash
pip install acedatacloud acedatacloud-x402
```

Если нужно использовать Solana, также необходимо установить соответствующие зависимости:

```bash
npm install @solana/web3.js
```

Зависимости Solana signer для версии Python уже включены в `acedatacloud-x402`.

Вывод проверки установки и импорта в чистой временной среде:

## Первый запрос вернёт 402

Сначала можно использовать `curl`, чтобы посмотреть, что возвращает неоплаченный запрос. Приведённый ниже пример не приведёт к списанию средств, поскольку он не содержит `PAYMENT-SIGNATURE`:

```bash
curl -sS -X POST https://x402.acedata.cloud/openai/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "hi"}],
    "max_tokens": 1
  }'
```

Тело ответа будет содержать массив `accepts`, типичная структура выглядит следующим образом:

```json
{
  "x402Version": 2,
  "resource": {
    "url": "/openai/chat/completions",
    "description": "AceDataCloud API call",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "maxAmountRequired": "95215",
      "amount": "95215",
      "maxTimeoutSeconds": 3600,
      "resource": "/openai/chat/completions",
      "description": "...",
      "payTo": "0x...",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913"
      }
    }
  ],
  "error": "PAYMENT-SIGNATURE header is required"
}
```

То же содержимое challenge также размещается в заголовке ответа `PAYMENT-REQUIRED` в виде base64, чтобы клиент мог получать требования к оплате без разбора body.

Сводка программного вывода неоплаченного запроса к production API выглядит следующим образом:

```text
status=402
x402Version 2
accepts [
  ('eip155:8453', 'exact', '95215'),
  ('eip155:8453', 'upto', '95215'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '95215'),
]
```

Пояснение результатов:

- Первый запрос не содержит `Authorization` или `PAYMENT-SIGNATURE`, поэтому возвращается HTTP 402, списание средств не произойдёт.
- `accepts` — единственная достоверная основа для подписи этого запроса, содержащая доступные сети, scheme, лимит суммы, адрес получателя и адрес актива.
- `network` — идентификатор CAIP-2, клиент при выборе сети должен сопоставлять его по строке CAIP-2.
- Лимит суммы для этого минимального запроса чата `gpt-4o-mini` составляет `95215` atomic USDC, то есть `0.095215` USDC.
- Для каждого запроса следует читать текущий ответ 402, не следует жёстко кодировать примерную сумму в бизнес-коде.

Значение полей:

| Поле                  | Описание                                                             |
| ------------------- | -------------------------------------------------------------- |
| `scheme`            | Схема оплаты. `exact` означает фиксированную сумму, `upto` означает лимит авторизации и расчёт по фактическому использованию.                     |
| `network`           | Идентификатор CAIP-2 платёжной сети, например `eip155:8453`、`solana:5eykt4...`.           |
| `maxAmountRequired` | Максимальная сумма оплаты, единица измерения — USDC atomic units, `95215` означает `0.095215` USDC.       |
| `amount`            | Сумма для расчёта в этот раз; для `exact` она совпадает с `maxAmountRequired`, для `upto` она изменяется на этапе расчёта согласно фактическому использованию. |
| `payTo`             | Адрес получателя.                                                          |
| `asset`             | Адрес контракта USDC или адрес mint Solana.                                     |
| `extra`             | Расширенная информация, необходимая для подписи: chain ID, EIP-712 domain, адрес Permit2 и т. д.                      |

## Выполнение повторной попытки оплаты с помощью SDK

Ниже приведён минимальный пример TypeScript. Он указывает `network: 'base'`, handler выберет requirement для оплаты Base из текущего ответа 402; фактическая сумма и адрес получателя по-прежнему определяются `accepts`:
```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const response = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Reply with exactly: hello' }],
  max_tokens: 8
});

console.log(response.choices[0].message.content);
```

За этим кодом происходят четыре шага:

1. SDK отправляет обычный API-запрос без `Authorization`.
2. Gateway возвращает `402 Payment Required` и `accepts`.
3. `createX402PaymentHandler` выбирает payment requirement для `network = 'base'` и подписывает `PAYMENT-SIGNATURE`.
4. SDK повторяет попытку с тем же телом запроса, а Gateway вызывает Facilitator для проверки и расчёта, после чего пропускает запрос к целевому API.

## Просмотр поддерживаемых возможностей Facilitator

X402 API не зависит от каталога ресурсов. Клиент напрямую вызывает известный API и использует
возвращаемые этим запросом в реальном времени `402 Payment Required` и `accepts` как единственное основание для цены и подписи.

Объявление возможностей Facilitator находится по адресу:

```bash
curl https://facilitator.acedata.cloud/.well-known/x402
```

Оно описывает только `/supported`, `/verify`, `/settle` и текущие включённые платёжные сети, не перечисляя API-ресурсы.

Адрес production Facilitator Ace Data Cloud:

```text
https://facilitator.acedata.cloud
```

Можно посмотреть, какие сети и scheme он поддерживает:

```bash
curl https://facilitator.acedata.cloud/supported
```

Возвращаемые `kinds` перечисляют сети и scheme, поддерживаемые Facilitator. При фактическом вызове всё равно следует ориентироваться на `accepts`, возвращаемые API.

Вывод Facilitator `/supported`:

```text
kinds [
  ('eip155:8453', 'exact'),
  ('eip155:8453', 'upto', {'facilitatorAddress': '0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708'}),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact')
]
```

Результат означает:

- `/supported` указывает, что Facilitator обладает возможностями проверки и расчёта для этих сетей и scheme.
- Base и Solana обе поддерживают `exact`; `upto` в настоящее время предоставляется только в Base.
- Разрешает ли конкретный API определённую сеть, всё равно определяется его 402 `accepts`.
