Ace Data Cloud X402 в настоящее время использует расчёты в USDC и поддерживает два типа сетей: EVM и Solana. Способы подписания, адреса активов, поведение gas и сценарии применения различаются в разных сетях, поэтому перед интеграцией необходимо сначала выбрать сеть.

## Идентификаторы сетей используют CAIP-2

`accepts[].network` в x402 v2 — это идентификатор CAIP-2, а не сокращения вроде `base` или `skale`. При сопоставлении сети клиент должен сравнивать строки CAIP-2:

| Сеть             | Идентификатор CAIP-2                       |
| -------------- | ----------------------------------------- |
| Base           | `eip155:8453`                             |
| SKALE Base     | `eip155:1187947933`                       |
| Solana mainnet | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` |

## Матрица поддержки

| Сеть     | scheme  | Актив                 | Способ подписания                       | Сценарий применения                         |
| ------ | ------- | ------------------- | ------------------------------------ | ----------------------------------------- |
| Base   | `exact` | Base USDC           | EIP-3009 `TransferWithAuthorization` | Рекомендуется по умолчанию, зрелая поддержка кошельков и ликвидности. |
| Base   | `upto`  | Base USDC + Permit2 | Permit2 `PermitWitnessTransferFrom`  | API с пост-учётом, такие как чаты и модели. |
| SKALE  | `exact` | SKALE bridged USDC  | EIP-3009 `TransferWithAuthorization` | Низкая стоимость gas, подходит для проверки EVM-платежей и недорогих вызовов. |
| Solana | `exact` | Solana USDC         | SPL `TransferChecked`                | Сценарии с кошельками Solana, Agent или ончейн-приложениями. |

`upto` в настоящее время предоставляется только в Base. Фактически доступные варианты определяются `accepts`, возвращаемым API. Вы также можете проверить Facilitator:

```bash
curl https://facilitator.acedata.cloud/supported
```

Ответ Facilitator `/supported`:

```json
{
  "kinds": [
    { "x402Version": 2, "scheme": "exact", "network": "eip155:8453" },
    {
      "x402Version": 2,
      "scheme": "upto",
      "network": "eip155:8453",
      "extra": { "facilitatorAddress": "0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708" }
    },
    { "x402Version": 2, "scheme": "exact", "network": "eip155:1187947933" },
    {
      "x402Version": 2,
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "extra": { "feePayer": "3SPm6qbgsDkj24MuR8Ss4sH97fziqyCiqFKDyeVU2igq" }
    }
  ]
}
```

Пояснение результатов:

- `exact` для Base, SKALE и Solana — это путь оплаты с фиксированной суммой.
- Только Base предоставляет путь пост-учёта `upto`, зависящий от approve Permit2.
- `extra.facilitatorAddress` в записи `upto` — это адрес, который клиент должен записать в witness при подписании, и он должен совпадать со значением, возвращённым сервером.

## Base

Base использует официальный контракт USDC:

```text
0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
```

В схеме `exact` клиент подписывает EIP-712 `TransferWithAuthorization`. Содержимое подписи включает:

- `from`: адрес кошелька плательщика
- `to`: адрес получения Ace Data Cloud
- `value`: сумма текущего платежа
- `validAfter` / `validBefore`: временное окно действия подписи
- `nonce`: случайный nonce размером 32 байта

После проверки подписи Facilitator вызовет в сети `transferWithAuthorization` USDC для завершения перевода.

Base — наиболее рекомендуемая сеть для официальной интеграции, особенно для пост-учёта `upto`, поскольку экосистема Permit2, USDC и кошельков более зрелая.

Пример результата проверки Base `exact`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
content ADC_BASE_E2E_OK
tx 0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
block 46726299
explorer https://basescan.org/tx/0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
transfer value 95215 atomic USDC
```

Пояснение результатов:

- Повторная попытка API после оплаты возвращает содержимое модели `ADC_BASE_E2E_OK`.
- Ончейн-транзакция доступна в BaseScan, номер блока — `46726299`.
- `95215` atomic USDC соответствует `0.095215` USDC и является фактической суммой расчёта за этот вызов API.

Результат выполнения программы оплаты заказа Base `exact`:

```text
order 78481793-304e-47f7-bc0c-8231aec9cc1e
state Finished
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer value 1200000 atomic USDC
```

Пояснение результатов:

- Итоговый статус заказа на платформе — `Finished`.
- `pay_id` заказа записывается в тот же хеш транзакции Base.
- `1200000` atomic USDC соответствует `1.2` USDC и является исторически фактически уплаченной суммой этого заказа на 10 Credits по старой политике; новые заказы больше не получают дополнительную скидку за способ оплаты X402, конкретная сумма подписи определяется ответом 402 в этот раз.

## SKALE

SKALE использует bridged USDC, а способ подписания аналогичен Base — также EIP-3009. Он подходит для EVM-платежей с низкой стоимостью gas; фактические вызовы по-прежнему определяются `accepts`, возвращаемым API.

Типичный `accepts` 402 для SKALE будет содержать:

```json
{
  "network": "eip155:1187947933",
  "scheme": "exact",
  "extra": {
    "name": "Bridged USDC (SKALE Bridge)",
    "version": "2",
    "chainId": 1187947933,
    "verifyingContract": "0x85889c8c714505E0c94b30fcfcF64fE3Ac8FCb20"
  }
}
```

SKALE в настоящее время предоставляет только `exact`. Если вам необходим пост-учёт, используйте Base `upto`.

Пример результата проверки SKALE `exact`:

```text
content ADC_SKALE_E2E_OK
tx 0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
block 1969317
explorer https://skale-base-explorer.skalenodes.com/tx/0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
paid 0.095215 USDC
```

Пояснение результатов:
- API paid retry возвращает содержимое модели `ADC_SKALE_E2E_OK`。
- Транзакция доступна для проверки в SKALE explorer, номер блока — `1969317`。
- Сумма расчёта этого платежа `exact` составляет `0.095215` USDC。

## Solana

Solana использует SPL USDC `TransferChecked`. Клиент создаёт транзакцию перевода, подписывает и отправляет её, затем помещает подпись транзакции или сериализованную транзакцию в envelope `PAYMENT-SIGNATURE`.

Особенности Solana:

- Используется Solana wallet adapter или base58 secret key;
- Активом является Solana USDC mint;
- В настоящее время поддерживается только `exact`;
- Facilitator проверяет mint, destination, authority и amount инструкции transfer.

При использовании режима wallet fee payer кошелёк напрямую отправляет транзакцию, а Facilitator отвечает за подтверждение транзакции и возврат результата settlement.

Пример результата проверки Solana `exact`:

```text
payer AY2RmGm2zPxB1uKvvF4dKyYdr2VySyL3wcD1MKJZoLRd
HTTP 402 -> HTTP 200
content ADC_SOLANA_E2E_OK
chain signature not confirmed in this run
```

Пояснение результата:

- paid retry уже вернул HTTP 200, а модель вывела `ADC_SOLANA_E2E_OK`。
- При запросе chain signature через публичный RPC можно столкнуться с ограничением частоты запросов。
- Поскольку запросы к публичному RPC могут ограничиваться по частоте, Solana explorer здесь не указывается. Если требуется строгая сверка, используйте собственный Solana RPC или записи settlement со стороны платформы для подтверждения подписи транзакции.

## Как выбрать

| Что вы хотите сделать        | Рекомендуемая сеть                         |
| ------------ | ---------------------------- |
| Быстро пройти минимальный сценарий     | SKALE `exact` или Base `exact` |
| Для обычных пользователей Web3 | Base                         |
| Для постоплаты, например chat completion   | Base `upto`                  |
| Приложения экосистемы Solana  | Solana `exact`               |
| Низкозатратная проверка EVM-платежей | SKALE `exact`                |

Независимо от выбранной цепочки, не хардкодьте цены в клиенте. Цена определяется серверным `accepts[].maxAmountRequired`.

## Новые EVM-сети

Для платежей с фиксированной суммой нативного USDC в следующих сетях предоставлена поддержка в коде, включение выполняется по сетям по отдельности.
Доступность определяется `accepts`, возвращаемым заказом или API; это не означает, что все сети уже включены в production.

| Network      | Alias      | CAIP-2         | Native USDC                                  |
| ------------ | ---------- | -------------- | -------------------------------------------- |
| Arbitrum One | `arbitrum` | `eip155:42161` | `0xaf88d065e77c8cC2239327C5EDb3A432268e5831` |

Эти сети поддерживают только `exact`, а точность токена составляет 6. Не используйте одноимённый мостовой USDC.
При использовании официального TypeScript/Python X402 Client можно передать сокращённое имя из таблицы или идентификатор CAIP-2.
Клиент использует ID целевой цепочки для создания подписи; кошелёк должен поддерживать целевую сеть.

В официальной таблице поддержки расширения Phantom перечислены Arbitrum и Polygon; Optimism и Avalanche
в настоящее время в этой таблице не указаны, можно использовать Rabby или MetaMask, поддерживающие целевую цепочку. EVM-адреса могут совпадать в разных цепочках,
но балансы независимы друг от друга, а Solana-адреса не применимы к EVM USDC.
См. [таблицу поддержки кошелька Phantom](https://docs.phantom.com/wallet-sdks-overview#chain-support).

### Точка входа для постепенного включения новых сетей

Точки входа новых цепочек по умолчанию скрыты. При доступе к консоли или Studio можно использовать `?features=x402-arbitrum`,
чтобы включить соответствующую цепочку; несколько flag разделяются запятыми. Чтобы отключить одну цепочку, используйте `?features=-x402-arbitrum`,
а чтобы очистить локальные переопределения — `?features=none`. Переключатели сохраняются отдельно для каждого домена.
Котировки заказов и повторные попытки оплаты используют один и тот же переключатель, сервер выполняет независимую проверку; существующие записи платежей по-прежнему можно просматривать.
Включение только page flag не активирует ещё не настроенную цепочку; конкретные доступные для оплаты сети по-прежнему определяются актуальным `accepts`.
