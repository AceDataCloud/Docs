Ace Data Cloud X402 в настоящее время использует расчёты в USDC и поддерживает два типа сетей: EVM и Solana. Способы подписи, адреса активов, поведение gas и применимые сценарии различаются в зависимости от сети, поэтому перед интеграцией необходимо сначала выбрать сеть.

## Идентификаторы сетей используют CAIP-2

`accepts[].network` в x402 v2 — это идентификатор CAIP-2, а не сокращённые названия вроде `base` или `solana`. При сопоставлении сети клиент обязан сравнивать строки CAIP-2:

| Сеть             | Идентификатор CAIP-2                         |
| -------------- | ----------------------------------------- |
| Base           | `eip155:8453`                             |
| Solana mainnet | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` |

## Матрица поддержки

| Сеть     | scheme  | Актив                  | Способ подписи                                 | Применимый сценарий                     |
| ------ | ------- | ------------------- | ------------------------------------ | ------------------------ |
| Base   | `exact` | Base USDC           | EIP-3009 `TransferWithAuthorization` | Рекомендуется по умолчанию, зрелая поддержка кошельков и ликвидности.         |
| Base   | `upto`  | Base USDC + Permit2 | Permit2 `PermitWitnessTransferFrom`  | API с постфактумным учётом, такие как чат и модели.          |
| Solana | `exact` | Solana USDC         | SPL `TransferChecked`                | Сценарии с кошельками Solana, Agent или ончейн-приложениями. |

`upto` сейчас предоставляется только на Base. Фактически доступные варианты определяются значением `accepts`, возвращаемым API. Вы также можете проверить Facilitator:

```bash
curl https://facilitator.acedata.cloud/supported
```

Ответ Facilitator `/supported`:

```json
{
  "kinds": [
    { "x402Version": 2, "scheme": "exact", "network": "eip155:8453" },
    {
      "x402Version": 2,
      "scheme": "upto",
      "network": "eip155:8453",
      "extra": { "facilitatorAddress": "0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708" }
    },
    {
      "x402Version": 2,
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "extra": { "feePayer": "3SPm6qbgsDkj24MuR8Ss4sH97fziqyCiqFKDyeVU2igq" }
    }
  ]
}
```

Пояснение результатов:

- `exact` для Base и Solana — это путь оплаты с фиксированной суммой.
- Только Base предоставляет путь постфактумного учёта `upto`, зависящий от approve Permit2.
- `extra.facilitatorAddress` в записи `upto` — это адрес, который клиент должен записать в witness при подписи; он должен совпадать со значением, возвращённым сервером.

## Base

Base использует официальный контракт USDC:

```text
0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
```

В схеме `exact` клиент подписывает EIP-712 `TransferWithAuthorization`. Содержимое подписи включает:

- `from`: адрес кошелька плательщика
- `to`: адрес получателя Ace Data Cloud
- `value`: сумма этого платежа
- `validAfter` / `validBefore`: временное окно действия подписи
- `nonce`: случайный nonce длиной 32 байта

После проверки подписи Facilitator вызовет в сети `transferWithAuthorization` USDC для завершения перевода.

Base — наиболее рекомендуемая сеть для промышленной интеграции, особенно для постфактумного учёта `upto`, поскольку экосистема Permit2, USDC и кошельков более зрелая.

Пример результата проверки Base `exact`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
content ADC_BASE_E2E_OK
tx 0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
block 46726299
explorer https://basescan.org/tx/0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
transfer value 95215 atomic USDC
```

Пояснение результатов:

- Повторный paid-запрос API возвращает содержимое модели `ADC_BASE_E2E_OK`.
- Ончейн-транзакцию можно найти в BaseScan, номер блока — `46726299`.
- `95215` atomic USDC соответствует `0.095215` USDC и является фактической суммой расчёта за этот вызов API.

Результат выполнения программы оплаты заказа через Base `exact`:

```text
order 78481793-304e-47f7-bc0c-8231aec9cc1e
state Finished
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer value 1200000 atomic USDC
```

Пояснение результатов:

- Итоговый статус заказа на платформе — `Finished`.
- `pay_id` заказа записывается в тот же хеш транзакции Base.
- `1200000` atomic USDC соответствует `1.2` USDC и является исторической фактически уплаченной суммой для этого заказа на 10 Credits по старой политике; новые заказы больше не получают дополнительную скидку за способ оплаты X402, конкретная сумма подписи определяется ответом 402 текущего запроса.

## Solana

Solana использует SPL USDC `TransferChecked`. Клиент создаёт транзакцию перевода, подписывает и отправляет её, после чего помещает подпись транзакции или сериализованную транзакцию в envelope `PAYMENT-SIGNATURE`.

Особенности Solana:

- Используется Solana wallet adapter или base58 secret key;
- Активом является Solana USDC mint;
- В настоящее время поддерживается только `exact`;
- Facilitator проверяет mint, destination, authority и amount инструкции transfer.

При использовании режима wallet fee payer кошелёк напрямую отправляет транзакцию, а Facilitator отвечает за подтверждение транзакции и возврат результата settlement.

Пример результата проверки Solana `exact`:

```text
payer AY2RmGm2zPxB1uKvvF4dKyYdr2VySyL3wcD1MKJZoLRd
HTTP 402 -> HTTP 200
content ADC_SOLANA_E2E_OK
chain signature not confirmed in this run
```

Пояснение результатов:

- Повторный paid-запрос уже возвращает HTTP 200, а модель выводит `ADC_SOLANA_E2E_OK`.
- При запросе ончейн signature через публичный RPC может возникнуть ограничение частоты.
- Поскольку запросы через публичный RPC могут ограничиваться по частоте, Solana explorer здесь не указан. Если требуется строгая сверка, используйте собственный Solana RPC или записи о settlement на стороне платформы для подтверждения подписи транзакции.

## Как выбрать

| Что вы хотите сделать        | Рекомендуемая сеть           |
| ------------ | -------------- |
| Быстро запустить минимальный сценарий     | Base `exact`   |
| Ориентироваться на обычных Web3-пользователей | Base           |
| Выполнять постфактумный учёт для чат-дополнений и подобных сценариев   | Base `upto`    |
| Приложения экосистемы Solana  | Solana `exact` |

Независимо от выбранной сети не следует жёстко кодировать цену на стороне клиента. Цена определяется значением `accepts[].maxAmountRequired`, возвращённым сервером.

## Добавление новых EVM-сетей
Нативные платежи USDC с фиксированной суммой в следующих сетях получили поддержку в коде и открываются по одной сети.
Доступность определяется `accepts`, возвращаемым заказом или API; это не означает, что все сети включены в продакшене.

| Сеть         | Псевдоним  | CAIP-2         | Нативный USDC                                |
| ------------ | ---------- | -------------- | -------------------------------------------- |
| Arbitrum One | `arbitrum` | `eip155:42161` | `0xaf88d065e77c8cC2239327C5EDb3A432268e5831` |

Эти сети поддерживают только `exact`, точность валюты составляет 6. Не используйте мостовой USDC с тем же именем.
При использовании официального TypeScript/Python X402 Client можно передать сокращённое имя из таблицы или идентификатор CAIP-2.
Клиент использует ID целевой цепи для создания подписи; кошелёк должен поддерживать целевую сеть.

В официальной таблице поддержки расширения-кошелька Phantom указаны Arbitrum и Polygon; Optimism, Avalanche
в настоящее время не включены в эту таблицу, можно использовать Rabby или MetaMask, поддерживающие целевую сеть. EVM-адреса могут быть одинаковыми в разных цепях,
но балансы независимы друг от друга, адреса Solana не применимы к EVM USDC.
См. [таблицу поддержки кошелька Phantom](https://docs.phantom.com/wallet-sdks-overview#chain-support).

### Точка входа в поэтапное развёртывание новых сетей

Точки входа для новых цепей по умолчанию скрыты. При доступе к консоли или Studio можно использовать `?features=x402-arbitrum`,
чтобы включить соответствующую цепь; несколько флагов разделяются запятыми. Чтобы отключить одну цепь, используйте `?features=-x402-arbitrum`,
чтобы очистить локальные переопределения, используйте `?features=none`. Переключатели сохраняются отдельно для каждого домена.
Расценки заказов и повторные попытки оплаты используют один и тот же переключатель, сервер выполняет независимую проверку; существующие записи платежей по-прежнему можно просматривать.
Включение только флага страницы не активирует ещё не настроенную цепь, конкретные доступные для оплаты сети по-прежнему определяются актуальным `accepts`.
