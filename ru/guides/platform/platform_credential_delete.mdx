---
title: "Удаление API-учётных данных платформы AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Безвозвратно удалить одни API-учётные данные. После удаления **немедленное восстановление невозможно**, все бизнес-интерфейсы, использующие этот Token, сразу получат `401`.

> ℹ️ Этот интерфейс относится к **API управления платформой AceDataCloud**, единый префикс — `https://platform.acedata.cloud/api/v1/`.

## Обзор интерфейса

| Параметр   | Содержание                                                          |
| --- | ------------------------------------------------------------------- |
| Метод  | `DELETE`                                                            |
| URL | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}` |
| Авторизация  | ✅ Требуется токен аккаунта                                                            |

`/credentials/{id}` и `/credentials/{id}/` в настоящее время оба доступны; в примерах единообразно используется форма без завершающего слеша.

## Описание авторизации (как получить токен аккаунта)

Заголовок запроса:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Способ получения смотрите в разделе [Управление токенами аккаунта платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

## Параметры пути

| Параметр              | Тип   | Обязательный  | Описание        |
| --------------- | ---- | --- | --------- |
| `credential_id` | UUID | ✅   | ID удаляемых учётных данных |

## Примеры запросов

### cURL

```shell
curl -X DELETE 'https://platform.acedata.cloud/api/v1/credentials/df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

cred_id = "df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6"
resp = requests.delete(
    f"https://platform.acedata.cloud/api/v1/credentials/{cred_id}",
    headers={"authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    timeout=10,
)
assert resp.status_code == 204, resp.text
print("✅ 已删除")
```

### Node.js

```javascript
const credId = 'df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6'
const r = await fetch(`https://platform.acedata.cloud/api/v1/credentials/${credId}`, {
  method: 'DELETE',
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log('status:', r.status) // 204
```

## Ответ

- **Успех**: `HTTP 204 No Content`, **без тела ответа**.
- **Ошибка**: возвращается JSON с ошибкой, смотрите таблицу ниже.

## Обработка ошибок

| HTTP | code                | Значение         |
| ---- | ------------------- | ---------- |
| 401  | `not_authenticated` | Отсутствует токен аккаунта     |
| 403  | `permission_denied` | Эти учётные данные не принадлежат вам    |
| 404  | `not_found`         | Учётные данные не существуют или уже удалены |

## Практические советы

- **Удаление необратимо** — платформа не хранит копии Token. Если вы лишь подозреваете утечку и всё ещё хотите сохранить данные мониторинга, следует использовать [ротацию API-учётных данных платформы AceDataCloud](https://platform.acedata.cloud/documents/platform-credential-rotate), а не удаление.
- **Удаление не возвращает уже израсходованную квоту этих учётных данных**. Баланс Application списывается в реальном времени по мере потребления, удаление учётных данных не влияет на отображаемый баланс.
- После удаления можно через [список API-учётных данных](https://platform.acedata.cloud/documents/platform-credential-list) повторно подтвердить оставшиеся учётные данные по `application_id`.
- **Перед массовой очисткой сначала проверьте вызывающие стороны**: в списке сейчас нет поля времени последнего использования; следует сопоставить конфигурацию развёртывания и записи вызовов, чтобы подтвердить, что учётные данные больше не используются, и затем удалять их по одному.
