---
title: "Настройка глобального совместного использования баланса AceDataCloud Application"
description: "Platform API guide - Ace Data Cloud"
---

Настройте `allow_consume_global`. После включения соответствующие Applications с оплатой по мере использования могут продолжать использовать глобальный баланс аккаунта при недостаточном собственном балансе.

## Подготовка

- Создайте и безопасно сохраните [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Получите принадлежащий вам `application_id` из [списка заявок на сервисы](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='токен вашего аккаунта'
export APPLICATION_ID='ваш Application ID'
```

## Обзор интерфейса

| Пункт    | Содержимое                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------- |
| Метод   | `POST`                                                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/applications/{application_id}/update-allow-consume-global/` |
| Авторизация   | Account Token                                                                                      |
| Body | JSON                                                                                               |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/applications/${APPLICATION_ID}/update-allow-consume-global/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"allow_consume_global": true}'
```

При успехе возвращается обновлённый объект Application. Ориентируйтесь на `allow_consume_global` в ответе, а не исходите из того, что значение запроса обязательно было сохранено.

> Applications типа `Period` не разрешено расходовать глобальный баланс. Даже при запросе `true` сервер сохранит значение этого поля как `false`.

## Обработка ошибок

- `401`: Account Token недействителен или отсутствует.
- `403`: текущий аккаунт не является владельцем данного Application.
- `404`: Application ID не существует.

Для пополнения глобального баланса и доступных тарифов ориентируйтесь на консоль платформы и фактические тарифы, возвращаемые при [создании заказа](https://platform.acedata.cloud/documents/platform-order-create); не предполагайте наличие тарифов типа `Wallet`.

## Applications с разрешённым овердрафтом

Когда у Application с оплатой по мере использования доступное только для чтения поле `allow_overdraft=true`, это Application может продолжать списывать средства со своего баланса, даже если баланс становится отрицательным, и не переключается на глобальный аккаунт из-за недостатка баланса. Applications без включённого овердрафта по-прежнему следуют `allow_consume_global`; разрешён ли овердрафт после переключения, определяется настройками фактически списываемого глобального Application.

## Ограничение параллелизма для пробных аккаунтов

Система использует доступную только для чтения пользовательскую метку `has_recharged`, чтобы фиксировать, было ли когда-либо успешно выполнено платное пополнение или администратор вручную добавил кредиты; метка обновляется после успешной операции, а для исторических пользователей будет единообразно дополнена на основании заказов или явных записей о начислении. Для аккаунтов, которые не выполняли платного пополнения и которым администратор не добавлял кредиты вручную, во всём аккаунте одновременно разрешено выполнение только одного платного запроса; разные API Key и разные сервисы совместно используют это одно место. Вознаграждения, карты обмена и переведённые лимиты не считаются платным пополнением. Аккаунты, уже выполнившие платное пополнение или получившие ручное начисление кредитов от администратора, не подпадают под это ограничение пробного параллелизма и по-прежнему следуют исходным проверкам баланса и лимитов учётных данных.

Когда существующий запрос уже выполняется, новый запрос возвращает `429 too_many_requests`. Бесплатные интерфейсы опроса, такие как запрос статуса задачи, по-прежнему можно вызывать нормально. Аутентификация подключения Realtime использует исходный процесс поэтапного тарифицирования и не занимает это место для обычного запроса.

Когда асинхронный интерфейс возвращает «принято», задача всё ещё выполняется, и перед отправкой следующего запроса на генерацию необходимо дождаться окончательного результата. Обрыв сети или тайм-аут прокси не означает, что задача уже остановлена; если задача долго не получает конечный статус, предоставьте `trace_id` и обратитесь в поддержку для проверки.

Это ограничение не изменяет доступные для пробного использования интерфейсы и не изменяет исходные правила тарификации. Стоимость по-прежнему рассчитывается после завершения запроса по фактическому использованию.
