Получение полного статуса одной заявки на сервис по Application ID — по сравнению с интерфейсом списка добавлены такие поля, как полный объект `service` (включая тарифы `packages`), подходит для страницы подробностей.

> ℹ️ Этот интерфейс относится к **API управления AceDataCloud Platform**, единый префикс `https://platform.acedata.cloud/api/v1/`. Полный индекс интерфейсов см. в [получении списка документов AceDataCloud Platform](https://platform.acedata.cloud/documents/platform-document-list).

## Обзор интерфейса

| Пункт   | Содержание                                                                    |
| --- | --------------------------------------------------------------------- |
| Метод  | `GET`                                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/{application_id}` |
| Авторизация  | ✅ Требуется токен аккаунта                                                              |

`/applications/{id}` и `/applications/{id}/` в настоящее время оба доступны; в примерах единообразно используется форма без завершающего слеша.

## Описание авторизации (как получить токен аккаунта)

Заголовок запроса:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Подробный способ получения см. в [управлении токеном аккаунта AceDataCloud Platform](https://platform.acedata.cloud/documents/platform-token).

> ℹ️ В отличие от интерфейса списка, **проверка прав в интерфейсе подробностей выполняется непосредственно для отдельного объекта**, передавать `?user_id=` не нужно. Однако при доступе к чужой заявке вы получите `403 permission_denied`.

## Параметры пути

| Параметр               | Тип   | Обязательный  | Описание             |
| ---------------- | ---- | --- | -------------- |
| `application_id` | UUID | ✅   | Application ID |

## Примеры запросов

### cURL

```shell
curl 'https://platform.acedata.cloud/api/v1/applications/82f57141-2323-4453-8730-60f7d833a2da' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

app_id = "82f57141-2323-4453-8730-60f7d833a2da"
resp = requests.get(
    f"https://platform.acedata.cloud/api/v1/applications/{app_id}",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}",
    },
    timeout=10,
)
app = resp.json()
print(f"服务：{app['service']['title']}")
print(f"剩余 {app['remaining_amount']} {app['service']['unit']} / 已用 {app['used_amount']}")
```

### Node.js

```javascript
const appId = '82f57141-2323-4453-8730-60f7d833a2da'
const r = await fetch(`https://platform.acedata.cloud/api/v1/applications/${appId}`, {
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log(await r.json())
```

## Описание полей ответа

Значения полей совпадают с [интерфейсом списка](https://platform.acedata.cloud/documents/platform-application-list), дополнительно включено:

| Поле        | Тип     | Описание                                                        |
| --------- | ------ | --------------------------------------------------------- |
| `service` | object | Полный объект сервиса (включая тарифы `packages`, `unit`, `free_amount`), который можно напрямую использовать для отображения панели подробностей сервиса |

## Обработка ошибок

| HTTP | code                | Значение                  |
| ---- | ------------------- | ------------------- |
| 401  | `not_authenticated` | Отсутствует токен аккаунта              |
| 403  | `permission_denied` | Этот Application не принадлежит вам  |
| 404  | `not_found`         | Application не существует или удалён |

## Практические советы

- **Для массового мониторинга предпочтительнее использовать список**: после однократного получения списка Application оценивайте по единицам и порогам каждого сервиса, чтобы избежать запросов подробностей по одному.
- **Когда необходимо посмотреть количество учётных данных**: используйте [список API-учётных данных](https://platform.acedata.cloud/documents/platform-credential-list) с фильтрацией по `application_id`.
- **Подход к проверке `disabled=true`**: проверьте обращения в поддержку / уведомления по электронной почте, чтобы узнать, не был ли сервис отключён из-за контроля рисков, задолженности или нарушающих правила вызовов; снять ограничение через API нельзя, необходимо обратиться в службу поддержки.
