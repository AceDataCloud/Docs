Этот документ объясняет, как определяется цена при вызове Ace Data Cloud API с использованием X402 и как она связана с обычной ценой платформы в **Credits** (кредитах).

## Основной вывод

X402 — не отдельная система ценообразования. Каждый вызов API изначально имеет стоимость в **Credits**, которая является единым источником цены, общим для всех способов оплаты (списание Credits через API Token, баланс аккаунта, ончейн-платёж X402). X402 лишь конвертирует эту стоимость в Credits в ончейн USDC по фиксированному курсу:

> **1 Credit = 0.095215 USDC** (то есть `95215` atomic USDC, USDC имеет 6 знаков после запятой)

То есть:

```text
X402 price (USDC) = Credits cost of this call × 0.095215
```

Этот курс не установлен произвольно, он равен цене **оптимального тарифа (крупный объём)** Credits на платформе. Поэтому оплата через X402 ≈ покупка Credits по цене оптимального тарифа с последующим расходованием, **без наценки X402**; более того, вы сразу получаете самую низкую цену Credits, без необходимости предварительного пополнения и без API Token.

## Основа расчёта цены

| Пункт        | Значение                       | Описание                                                    |
| --------- | ------------------------------ | ----------------------------------------------------- |
| Курс конвертации      | `1 Credit = 0.095215 USDC`     | Единый фиксированный курс, установленный платформой                                           |
| atomic единица | `1 Credit = 95215 atomic USDC` | USDC имеет 6 знаков после запятой, `atomic = floor(credits × 0.095215 × 1e6)` |
| Минимальное списание      | `1 atomic USDC`（$0.000001）     | Даже если стоимость крайне низкая, списывается минимум 1 atomic                                 |
| Валюта расчёта      | USDC                           | Base использует ERC-20 USDC, Solana использует SPL USDC                  |

Конвертация выполняется платформой централизованно, а сумма одинакова для всех поддерживаемых сетей (Base, Solana); между сетями различаются только контракт актива и способ подписи, цена одинакова.

### Связь с обычной ценой Credits

Credits на платформе продаются по ступенчатой модели «чем больше объём, тем ниже цена за единицу». При оплате X402 за вызов всегда используется цена оптимального тарифа:

| Способ покупки/оплаты        | Примерная цена Credits за единицу            | Описание                   |
| -------------- | ------------------------ | -------------------- |
| Начальное / небольшое пополнение      | Около `$0.13 / Credit`       | Цена из прайс-листа, цена за единицу при покупке небольшого количества Credits |
| Крупный объём / оптимальный тариф       | `$0.095215 / Credit`     | Самая низкая цена за единицу               |
| **Оплата X402 за вызов** | **`$0.095215 / Credit`** | **Всегда равна цене оптимального тарифа**        |

Другими словами, X402 рассчитывает каждый вызов по цене Credits оптимального тарифа. У пользователей, покупающих Credits небольшими пополнениями, цена за единицу будет выше, чем при X402; только у пользователей с крупными пополнениями цена за единицу совпадает с X402.

## Две формы цены: `exact` и `upto`

В ответе 402 X402 поле `maxAmountRequired` — это сумма, которую вы должны подписать. Она имеет две формы:

- **`exact` (фиксированная цена)**: цена может быть определена до обработки запроса (изображения, видео, музыка, поиск, оплата заказа). `maxAmountRequired = Credits cost of this call × 0.095215`, то есть сумма к оплате за этот вызов (совпадает с `cost.amount` в успешном ответе).
- **`upto` (измерение потребления после выполнения)**: для интерфейсов вроде chat completions, где «количество использованных token становится известно только после завершения ответа». `maxAmountRequired` — это **верхний предел** (конвертируется из установленного для этой модели лимита: лимит Credits × 0.095215), фактический расчёт производится по реальному потреблению и не превышает верхний предел.

Подробности протокола об этих двух схемах см. в [схемах тарификации `exact` и `upto`](https://platform.acedata.cloud/documents/x402-metered-upto). Ниже рассматриваются только цены.

## Цены Chat (чат-дополнений)

Чат-дополнения используют измерение `upto`: оплата взимается по фактическому потреблению token prompt / completion. Цена за миллион (1M) token = `Credits cost of the model per 1M token × 0.095215`, что полностью совпадает с USD-ценой за единицу, отображаемой в публичном каталоге моделей платформы (`/api/v1/models?with_pricing=true`).

В таблице ниже указаны реальные цены (взяты из каталога моделей, рассчитаны по курсу X402), единица измерения — USD / 1M token:

| Модель                | Ввод / 1M | Вывод / 1M  | Лимит `upto`             |
| ----------------- | ------- | -------- | --------------------- |
| gpt-4o-mini       | $0.0796 | $0.3183  | 1 Credit（$0.095215）   |
| gemini-2.5-flash  | $0.1591 | $1.3262  | 5 Credits（$0.476074）  |
| gpt-5 / gpt-5.1   | $0.6631 | $5.3050  | 20 Credits（$1.904299） |
| gemini-2.5-pro    | $0.6631 | $5.3050  | 50 Credits（$4.760750） |
| gpt-4.1           | $1.0610 | $4.2440  | 20 Credits（$1.904299） |
| claude-sonnet-4-5 | $0.6006 | $3.0028  | 50 Credits（$4.760750） |
| grok-4            | $1.5915 | $7.9574  | 10 Credits（$0.952149） |
| claude-opus-4-1   | $3.0028 | $15.0140 | 50 Credits（$4.760750） |

Примечания:

- В таблице указаны цены за единицу при измерении по token; стоимость одного запроса = входные token × цена ввода за единицу + выходные token × цена вывода за единицу.
- Лимит `upto` — это максимальная сумма, разрешённая для подписи в одном запросе для этой модели; это не фактическое списание, большинство запросов значительно ниже лимита.
- Лимит определяет только «сколько может быть списано максимально», фактический расчёт выполняется по потреблению token.

### Пример: котировка и списание совпадают (`exact`)

Ниже приведён один **реальный платный вызов** к `serp/google`, выполненный официальным X402Client (Base `exact`). Он демонстрирует совпадение трёх величин: котировки 402, суммы подписи и возвращаемого в успешном ответе `cost`.

```text
# 1) Unpaid request -> 402, get quote (no charge)
POST /serp/google  ->  402
base/exact maxAmountRequired = 952 atomic = $0.000952 = 0.01 Credit
# 0.01 × 0.095215 = 0.00095215, round down to atomic = 952

# 2) Sign PAYMENT-SIGNATURE for 952 atomic with wallet, retry
POST /serp/google (PAYMENT-SIGNATURE) -> 200
body.cost = {"amount": 0.000952, "currency": "usdc", "settlement": "authorized"}
```
Возвращаемый `cost.amount` (0.000952 USDC) полностью соответствует котировке 402 и `Credits × 0.095215`. Поле `settlement` — это статус расчёта данного платежа (`authorized` = авторизован); ончейн-расчёт обрабатывается платформой, механизм описан в [схемах тарификации `exact` и `upto`](https://platform.acedata.cloud/documents/x402-metered-upto)。

### Расчёт котировки `upto` (чат)

Чат измеряется в токенах. Котировка (не верхний предел) для одного запроса рассчитывается по следующей формуле (на примере gpt-4o-mini):

```text
Credits = 1e-6 × (0.835733 × prompt_tokens + 3.342933 × completion_tokens)
USDC    = Credits × 0.095215
```

Для запроса на 500 prompt + 200 completion токенов:

```text
Credits = 1e-6 × (0.835733 × 500 + 3.342933 × 200) ≈ 0.001086 Credits
报价 USDC ≈ 0.001086 × 0.095215 ≈ $0.0001034
```

Клиент подписывает верхний предел `upto` (для gpt-4o-mini 1 Credit = `95215` atomic), это лишь **максимально возможная сумма списания**; фактическая котировка данного запроса (в приведённом примере около $0.0001) значительно ниже верхнего предела, расчёт производится по использованию токенов. Механизм ончейн-расчёта `upto` описан в [схемах тарификации `exact` и `upto`](https://platform.acedata.cloud/documents/x402-metered-upto)。

## Цены на другие сервисы (фиксированная цена `exact`)

Для таких API, как изображения, видео, музыка и поиск, цена может быть определена при запросе, используется `exact`. В таблице ниже приведены реальные цены, полученные из 402 `maxAmountRequired`, возвращаемого онлайн-API для неоплаченных запросов (запрос котировки не приводит к списанию средств):

Примечания:

- Цена одного и того же сервиса меняется в зависимости от **модели, разрешения, длительности и действия** (особенно для видео). В таблице выше указаны реальные значения для одного набора параметров, только для ориентира по масштабу.
- Для таких API с фиксированной ценой (`exact`) `maxAmountRequired` в ответе 402 данного запроса является суммой к оплате за этот запрос (совпадает с `cost.amount` успешного ответа, что уже проверено в предыдущем разделе).
- Каждая цена получается путём округления вниз `Credits × 0.095215` до единицы atomic (см. базу расчёта выше), используется та же конвертация, что и для чата. Из-за представления чисел с плавающей точкой и округления отдельные значения могут отличаться от простого произведения на 1 atomic ($0.000001); всегда ориентируйтесь на значение, возвращённое 402.

## Цена оплаты заказа

При оплате заказов через консоль X402 (покупка пакета / пополнение Credits) ориентируйтесь на цену, отображаемую на странице заказа, а `amount` в 402 является окончательным основанием для подписи. Оплата заказа проходит через API платформы и требует токена аккаунта; подробности см. в [руководстве по оплате заказа](https://platform.acedata.cloud/documents/x402-order-payment)。

Реальный пример из руководства по оплате заказа (покупка 10 Credits):

```text
description Ace Data Cloud Credits x 10.0
created price 1.26          # 订单创建价（USD）
settled    1.20 USDC        # 最终签名/结算金额（= 402 amount）
            = 1200000 atomic USDC
```

Обратите внимание: **оплата за вызовы** (выше: Chat / другие сервисы) и **оплата заказа** — это два разных пути. Для оплаты за вызовы единообразно используется оптимальная цена уровня `0.095215`/Credit; оплата заказа производится по цене пакета, а разница между ценой создания и суммой окончательного расчёта определяется [руководством по оплате заказа](https://platform.acedata.cloud/documents/x402-order-payment)。

## Как получать цены в реальном времени

Цены меняются в зависимости от модели и параметров, получайте их программно в реальном времени, не хардкодьте:

- **Цена за вызов**: отправьте целевому API запрос **без** `PAYMENT-SIGNATURE` (а также без `Authorization`) и прочитайте возвращённый 402 `accepts[].maxAmountRequired`. На этом этапе средства не списываются. Для API `exact` это окончательная цена; для API `upto` (чат) это верхний предел, а фактический расчёт производится по использованию.
- **Цена чата за токен**: `GET https://platform.acedata.cloud/api/v1/models?with_pricing=true&type=chat`, прочитайте `pricing.input_usd` / `pricing.output_usd` каждого модели (уже рассчитано по `credit_usd_rate`).
- **Проверка конвертации**: `atomic = floor(Credits × 0.095215 × 1e6)`, `USDC = atomic / 1e6` (то есть `USDC ≈ Credits × 0.095215`).

Пример минимального запроса для получения цены:

```bash
curl -sS -X POST https://x402.acedata.cloud/midjourney/imagine \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "a cat"}'
# 返回 402，accepts[].maxAmountRequired 即为该次（exact）调用价格
```

## Итог
- Цена X402 = стоимость Credits за этот вызов × `0.095215`, это **та же цена**, что и при обычном биллинге Credits, только расчёт производится в ончейн USDC.
- `0.095215`/Credit — это **лучший тариф** (для крупных объёмов) платформы за Credits; при небольших пополнениях цена Credits выше, поэтому X402 автоматически предоставляет лучшую цену.
- Для интерфейсов `exact` (изображения / видео / музыка / поиск / заказы) сумма подписи является суммой к оплате за этот вызов; для интерфейсов `upto` (чат) подписывается верхний лимит, а расчёт производится по фактическому использованию.
- Авторитетной ценой является `maxAmountRequired`, возвращаемый 402: для `exact` это сумма к оплате (совпадает с `cost.amount` в успешном ответе, проверено на практике); для `upto` это верхний лимит, а `cost.amount` в успешном ответе является фактической суммой, рассчитанной по использованию (≤ верхнего лимита).
