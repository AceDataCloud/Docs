Anthropic Claude — это очень мощная система диалогового ИИ: достаточно ввести промпт, и она сможет за несколько секунд сгенерировать плавный и естественный ответ. Claude выделяется в индустрии своими выдающимися способностями к пониманию и генерации языка. Сегодня Claude уже широко применяется в различных отраслях и сферах, а его влияние становится всё более значительным. Будь то повседневные диалоги, творческое письмо, профессиональные консультации или программирование кода, Claude способен предоставлять впечатляющую интеллектуальную помощь, значительно повышая эффективность работы и творческие способности человека.

В этом документе главным образом представлен процесс использования операций Claude Chat Completion API, с помощью которого мы можем легко использовать функцию диалога официального Claude.

## Процесс запроса

Чтобы использовать Claude Chat Completion API, сначала перейдите в [консоль Ace Data Cloud](https://platform.acedata.cloud/console/applications), чтобы получить ваш API Token и сохранить его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти в систему; после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первом запросе предоставляется бесплатный лимит, который можно использовать для бесплатного ознакомления; при недостаточном лимите можно пополнить универсальный баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Базовое использование

Далее можно заполнить соответствующее содержимое в интерфейсе, как показано на изображении:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

При первом использовании этого интерфейса нам необходимо заполнить как минимум три значения: одно из них — `authorization`, его можно выбрать непосредственно в выпадающем списке. Другой параметр — `model`, можно выбрать общедоступные модели, такие как `claude-opus-5-5`, `claude-fable-5-1` и другие; прежнюю `claude-fable-5` по-прежнему можно вызывать. Последний параметр — `messages`, это массив сообщений, каждый элемент которого содержит `role` и `content`; `role` поддерживает `user`, `assistant`, `system`, а `content` является конкретным содержимым. Если требуются полные блоки размышлений Claude, подписи и семантика нативных инструментов, по-прежнему используйте Messages API.

В то же время вы можете заметить, что справа генерируется соответствующий код вызова: вы можете скопировать код и запустить его напрямую, а также можете непосредственно нажать кнопку «Try» для тестирования.

Часто используемые необязательные параметры:

- `max_tokens`: ограничивает максимальное количество токенов в одном ответе.
- `temperature`: случайность генерации, от 0 до 2; чем больше значение, тем более разнообразным будет результат.
- `n`: сколько вариантов ответа генерировать за один раз.
- `response_format`: настройка формата возврата.

`claude-opus-5-5` поддерживает обычные и потоковые Chat Completions; эта модель допускает только `n=1`. Не задавайте для неё `temperature` ниже 1 или нестандартный `top_p`; для вызова инструментов используйте `tool_choice: "auto"`, не указывайте инструмент принудительно. Совместимый интерфейс Chat не возвращает нативные блоки размышлений.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

После вызова мы видим, что возвращаемый результат выглядит следующим образом:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }
}
```

Возвращаемый результат содержит несколько полей, описание которых приведено ниже:

- `id` — ID сгенерированной задачи диалога, используемый для уникальной идентификации этой задачи диалога.
- `model ` — выбранная модель с официального сайта Claude.
- `choices` — информация об ответе Claude на вопрос.
- `usage `: статистическая информация о токенах для текущей пары вопрос-ответ.

В формате Chat Completions `usage.prompt_tokens` — это общий объём входных данных; `prompt_tokens_details.cached_tokens` и `prompt_tokens_details.cache_write_tokens` соответственно записывают детали чтения и записи кэша. `completion_tokens_details.reasoning_tokens` является подмножеством `completion_tokens`, поэтому при подсчёте общего объёма или стоимости не добавляйте их повторно. Непотоковый ответ также может возвращать объект `usage.cost`, в котором `amount` — фактический расход лимита, `currency` — единица измерения, а `list_amount` — сумма до скидки (при наличии).

Название поля в Chat-compatible — `reasoning_tokens`; нативный Messages API использует `output_tokens_details.thinking_tokens`. Wire schema двух протоколов различаются, клиент не должен смешивать названия полей.

Среди них `choices` содержит информацию об ответе Claude, а `choices` внутри него представляет конкретную информацию об ответе Claude, как можно увидеть на изображении.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Можно увидеть, что поле `content` внутри `choices` содержит конкретное содержимое ответа Claude.

## Потоковый ответ

Этот интерфейс также поддерживает потоковые ответы, что очень полезно для интеграции с веб-страницами и позволяет реализовать эффект посимвольного отображения на веб-странице.

Если вы хотите получать ответ в потоковом режиме, можно изменить параметр `stream ` в заголовке запроса на `true`.

Изменение показано на изображении, однако код вызова должен быть соответствующим образом изменён для поддержки потокового ответа.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

После изменения `stream` на `true` API будет построчно возвращать соответствующие JSON-данные, и на уровне кода нам необходимо внести соответствующие изменения, чтобы получать построчные результаты.

Пример кода вызова на Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

```javascript

  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Глубокое мышление
Модели Claude нового поколения могут выполнять рассуждения в соответствии со стратегией модели по умолчанию, без необходимости активации через суффикс модели `-thinking`. Chat-compatible ответы используют совместимое с OpenAI поле usage `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` уже включены в `completion_tokens`, не суммируйте их повторно. Рассуждения и видимый основной текст используют общий лимит выходных token, поэтому при небольшом `max_tokens` основной текст может оказаться пустым или быть обрезанным; в таком случае увеличьте выходной бюджет или, если используемая модель это поддерживает, выберите меньший уровень усилий для рассуждений.

Если требуются нативные `thinking`, `output_config.effort`, блоки содержимого thinking и возврат подписей, используйте `/v1/messages`. Соответствующее для Messages поле usage — `output_tokens_details.thinking_tokens`, не смешивайте его с `completion_tokens_details.reasoning_tokens` из Chat-compatible.

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`：Неверный запрос, возможно из-за отсутствующих или недействительных параметров.
- `400 api_not_implemented`：Неверный запрос, возможно из-за отсутствующих или недействительных параметров.
- `401 invalid_token`：Не авторизовано, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`：Слишком много запросов, вы превысили ограничение скорости.
- `500 api_error`：Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

```
{
  "success": false,
  "error": {
    "code": "api_error",
```
