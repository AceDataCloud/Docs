Anthropic Claude — это очень мощная система диалогов с ИИ: достаточно ввести подсказку, и она сможет за несколько секунд сгенерировать плавный и естественный ответ. Claude выделяется в отрасли своими превосходными способностями к пониманию и генерации языка; сегодня Claude уже широко применяется в различных отраслях и сферах, а его влияние становится всё заметнее. Будь то повседневные диалоги, творческое письмо, профессиональные консультации или программирование кода, Claude способен предоставлять впечатляющую интеллектуальную помощь, значительно повышая эффективность работы и творческие способности человека.

Этот документ в основном представляет процесс использования операций Claude Chat Completion API, с его помощью мы можем легко использовать функцию диалога официального Claude.

## Claude Fable 5.2

Используйте полное название модели `claude-fable-5-2`. Эта модель подходит для сложных рассуждений и долгосрочных задач; когда требуются нативные блоки содержимого размышлений и взаимодействие с инструментами, приоритетно используйте Messages. Адаптивное мышление постоянно включено, опускайте `temperature`, `top_p`, `top_k`, для выбора инструментов используйте `auto`, не указывайте инструменты принудительно. `max_tokens` одновременно охватывает размышления и итоговый текст. В настоящее время интерфейсы Responses и Count Tokens для этой модели не предоставляются.

В пересчёте по текущему максимальному тарифу (142,800 Credits／$13,584), обычный ввод Fable 5.2 стоит $3.20, вывод — $16／миллион token; чтение кеша — $0.08, запись кеша на 5 минут／1 час — соответственно $4／$6.40／миллион token. Указанные цены составляют 40% от стандартной цены официального API (на 60% дешевле); по другим тарифам и дополнительным скидкам для аккаунтов ориентируйтесь на страницу ценообразования моделей и счёт.

## Процесс подачи заявки

Чтобы использовать Claude Chat Completion API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications) и сохраните его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти, после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первой заявке предоставляется бесплатный лимит, позволяющий бесплатно опробовать сервис; при недостаточном лимите можно пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

## Базовое использование

Далее можно заполнить соответствующее содержимое в интерфейсе, как показано на изображении:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

При первом использовании этого интерфейса нам необходимо заполнить как минимум три поля: одно из них — `authorization`, его можно непосредственно выбрать из выпадающего списка. Другой параметр — `model`, можно выбрать публичные модели, такие как `claude-opus-5-5`, `claude-fable-5-1`; исходную `claude-fable-5` по-прежнему можно вызывать. Последний параметр — `messages`, это массив подсказок-вопросов, каждый элемент содержит `role` и `content`; `role` поддерживает `user`, `assistant`, `system`, а `content` является конкретным содержимым. Когда требуются полные блоки содержимого размышлений Claude, подписи и нативная семантика инструментов, по-прежнему используйте Messages API.

Одновременно вы можете заметить, что справа генерируется соответствующий код вызова: вы можете скопировать код и запустить его напрямую, а также можете непосредственно нажать кнопку «Try» для тестирования.

Распространённые необязательные параметры:

- `max_tokens`: ограничивает максимальное количество token в одном ответе.
- `temperature`: случайность генерации, от 0 до 2, чем больше значение, тем более разнообразен результат.
- `n`: сколько кандидатных ответов генерировать за один раз.
- `response_format`: настройка формата возврата.

`claude-opus-5-5` поддерживает обычные и потоковые Chat Completions; эта модель допускает только `n=1`. Не устанавливайте для неё `temperature` ниже 1 или нестандартный `top_p`, для вызова инструментов используйте `tool_choice: "auto"`, не указывайте инструменты принудительно. Совместимый интерфейс Chat не возвращает нативные блоки содержимого размышлений.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

После вызова мы видим, что возвращаемый результат выглядит следующим образом:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }

```

Возвращаемый результат содержит несколько полей, описание следующее:

- `id` — ID сгенерированной задачи диалога, используется для уникальной идентификации этой задачи диалога.
- `model ` — выбранная модель Claude с официального сайта.
- `choices` — информация об ответе, данном Claude на подсказку-вопрос.
- `usage `: статистическая информация по token для текущих вопросов и ответов.

В формате Chat Completions `usage.prompt_tokens` — это общий объём ввода; `prompt_tokens_details.cached_tokens` и `prompt_tokens_details.cache_write_tokens` соответственно записывают сведения о чтении и записи кеша. `completion_tokens_details.reasoning_tokens` является подмножеством `completion_tokens`, при расчёте общего объёма или стоимости не складывайте их повторно. Непотоковый ответ также может возвращать объект `usage.cost`, в котором `amount` — фактический расход лимита, `currency` — единица измерения, а `list_amount` — сумма до скидки (если имеется).

Название поля в Chat-compatible — `reasoning_tokens`; нативный Messages API использует `output_tokens_details.thinking_tokens`. Wire schema двух протоколов различаются, клиент не должен смешивать названия полей.

Среди них `choices` содержит информацию об ответе Claude, его `choices` является конкретной информацией ответа Claude, как можно увидеть на изображении.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Можно увидеть, что поле `content` внутри `choices` содержит конкретное содержание ответа Claude.

## Потоковый ответ

Этот интерфейс также поддерживает потоковый ответ, что очень полезно для интеграции с веб-страницами и позволяет реализовать на странице эффект посимвольного отображения.

Если вы хотите возвращать ответ потоково, можно изменить параметр `stream ` в заголовке запроса на `true`.

Изменение показано на изображении, однако код вызова необходимо соответствующим образом изменить, чтобы он поддерживал потоковый ответ.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>
После изменения `stream` на `true` API будет построчно возвращать соответствующие данные JSON, и на уровне кода нам необходимо внести соответствующие изменения, чтобы получать построчные результаты.

Пример кода вызова на Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

JavaScript также поддерживается, например, код потокового вызова для Node.js выглядит следующим образом:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "claude-opus-4-20250514",
    messages: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/v1/chat/completions", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Глубокое мышление

Модели Claude нового поколения могут выполнять рассуждения в соответствии со стратегией модели по умолчанию, без необходимости активации через суффикс модели `-thinking`. Ответы, совместимые с Chat, используют совместимое с OpenAI поле usage `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` уже включены в `completion_tokens`, не суммируйте их повторно. Рассуждения и видимый основной текст используют общий лимит выходных token, поэтому при небольшом `max_tokens` основной текст может оказаться пустым или быть обрезанным; в таком случае увеличьте выходной бюджет или, если используемая модель поддерживает это, выберите меньший уровень вложений в рассуждения.

Если требуются нативные `thinking`, `output_config.effort`, блоки содержимого thinking и возврат подписи, используйте `/v1/messages`. Соответствующее Messages поле usage — `output_tokens_details.thinking_tokens`, не смешивайте его с `completion_tokens_details.reasoning_tokens` из Chat-compatible.

## Визуальная модель

claude-sonnet-4-20250514 — это мультимодальная большая языковая модель, разработанная Claude; она добавляет возможности визуального понимания на основе claude-4. Эта модель может одновременно обрабатывать текстовые и графические входные данные, реализуя межмодальное понимание и генерацию.

Текстовая обработка с использованием модели claude-sonnet-4-20250514 совпадает с описанным выше базовым использованием; ниже будет кратко представлено, как использовать возможности обработки изображений модели.


Можно увидеть, что содержание ответа основано на изображении, поэтому с помощью двух вышеуказанных способов можно легко использовать возможности текстовой обработки и обработки изображений модели claude-3-7-sonnet-20250219.

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`: Bad request, возможно, из-за отсутствующих или недействительных параметров.
- `400 api_not_implemented`: Bad request, возможно, из-за отсутствующих или недействительных параметров.
- `401 invalid_token`: Unauthorized, недействительный или отсутствующий токен авторизации.
- `429 too_many_requests`: Слишком много запросов, вы превысили ограничение частоты запросов.
- `500 api_error`: Внутренняя ошибка сервера, на сервере что-то пошло не так.

### Пример ответа с ошибкой

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
