Anthropic Claude — это очень мощная система ИИ-диалогов: достаточно ввести промпт, и она сможет всего за несколько секунд сгенерировать плавный и естественный ответ. Claude выделяется в отрасли своими превосходными возможностями понимания и генерации языка; сегодня Claude уже широко применяется в различных отраслях и сферах, а его влияние становится всё более значительным. Будь то повседневные диалоги, творческое письмо или профессиональные консультации, программирование кода — Claude может предоставлять впечатляющую интеллектуальную помощь, значительно повышая эффективность работы и творческие возможности человека.

Этот документ в основном представляет процесс использования операций Claude Chat Completion API, с его помощью мы можем легко использовать диалоговые функции официального Claude.

## Процесс подачи заявки

Чтобы использовать Claude Chat Completion API, сначала получите ваш API Token в [консоли Ace Data Cloud](https://platform.acedata.cloud/console/applications), чтобы оставить его для дальнейшего использования.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Если вы ещё не вошли в систему или не зарегистрировались, вы будете автоматически перенаправлены на страницу входа, где вам будет предложено зарегистрироваться и войти в систему; после завершения вы автоматически вернётесь на текущую страницу.

**Один API Token позволяет вызывать все сервисы платформы, нет необходимости подавать отдельную заявку для каждого сервиса.** При первой заявке предоставляется бесплатный лимит, который можно использовать для бесплатного тестирования; при недостаточном лимите можно пополнить общий баланс в [консоли](https://platform.acedata.cloud/console/coin).

> 📘 Полная документация: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Базовое использование

Далее можно заполнить соответствующее содержимое в интерфейсе, как показано на рисунке:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

При первом использовании этого интерфейса нам необходимо заполнить как минимум три поля: одно из них — `authorization`, его можно просто выбрать в выпадающем списке. Другой параметр — `model`, рекомендуется использовать новейшую флагманскую модель `claude-fable-5-1`; исходную `claude-fable-5` по-прежнему можно продолжать вызывать. Последний параметр — `messages`, это массив сообщений, каждый элемент содержит `role` и `content`; `role` поддерживает `user`, `assistant`, `system`, а `content` является конкретным содержимым. Claude Fable 5.1 поддерживает контекст в 1 миллион Token и максимальный вывод в 128K Token.

Одновременно вы можете заметить, что справа генерируется соответствующий код вызова: вы можете скопировать код и запустить его напрямую, а также можете напрямую нажать кнопку «Try» для тестирования.

Часто используемые необязательные параметры:

- `max_tokens`: ограничивает максимальное количество token в одном ответе.
- `temperature`: случайность генерации, от 0 до 2, чем больше значение, тем более разнообразным будет результат.
- `n`: сколько вариантов ответов генерировать за один раз.
- `response_format`: настройка формата возврата.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

После вызова мы видим, что возвращаемый результат выглядит следующим образом:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }
}
```

Возвращаемый результат содержит несколько полей, описание следующее:

- `id` — ID сгенерированной задачи диалога, используется для уникальной идентификации этой задачи диалога.
- `model ` — выбранная модель с официального сайта Claude.
- `choices` — информация об ответе Claude на промпт.
- `usage `: статистическая информация о token для этой пары вопрос-ответ.

В формате Chat Completions `usage.prompt_tokens` — это общий объём ввода; `prompt_tokens_details.cached_tokens` и `prompt_tokens_details.cache_write_tokens` соответственно записывают сведения о чтении и записи кеша. `completion_tokens_details.reasoning_tokens` является подмножеством `completion_tokens`; при расчёте общего объёма или стоимости не добавляйте его повторно. Непотоковый ответ также может возвращать объект `usage.cost`, где `amount` — это фактический расход лимита, `currency` — единица измерения, а `list_amount` — сумма до скидки (если имеется).

Имя поля, совместимого с Chat, — `reasoning_tokens`; нативный Messages API использует `output_tokens_details.thinking_tokens`. Wire schema двух протоколов различаются, клиент не должен смешивать имена полей.

Среди них `choices` содержит информацию об ответе Claude, его `choices` является конкретной информацией ответа Claude, как можно увидеть на рисунке.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Можно увидеть, что поле `content` внутри `choices` содержит конкретное содержимое ответа Claude.

## Потоковый ответ

Этот интерфейс также поддерживает потоковые ответы, что очень полезно для интеграции с веб-страницами и позволяет реализовать эффект отображения текста посимвольно.

Если вы хотите возвращать ответ в потоковом режиме, можно изменить параметр `stream ` в заголовке запроса на `true`.

Изменение показано на рисунке, однако код вызова должен быть соответствующим образом изменён, чтобы поддерживать потоковый ответ.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

После изменения `stream` на `true` API будет построчно возвращать соответствующие JSON-данные, на уровне кода нам необходимо внести соответствующие изменения, чтобы получать построчные результаты.

Пример кода вызова на Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Можно увидеть, что в ответе содержится много `data`, а `choices` внутри `data` — это новейшее содержимое ответа, что соответствует представленному выше содержанию. `choices` — это добавленное содержимое ответа, вы можете интегрировать его в свою систему в соответствии с результатом. При этом окончание потокового ответа определяется по содержимому `data`: если содержимое равно `[DONE]`, это означает, что потоковый ответ полностью завершён. - `id` — ID задачи генерации данного диалога, используемый для уникальной идентификации этой задачи диалога.
- `model ` — выбранная модель Claude с официального сайта.
- `choices` — информация об ответе, предоставленном Claude на запрос.

JavaScript также поддерживается, например, код потокового вызова для Node.js приведён ниже:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "claude-opus-4-20250514",
    messages: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/v1/chat/completions", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

Пример кода на Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "claude-opus-4-20250514");
jsonObject.put("messages", [{"role":"user","content":"Hello"}]);
jsonObject.put("stream", true);
MediaType mediaType = "application/json; charset=utf-8".toMediaType();
RequestBody body = jsonObject.toString().toRequestBody(mediaType);

  .url("https://api.acedata.cloud/v1/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.print(response.body!!.string())
```

Для других языков можно самостоятельно внести соответствующие изменения, принцип остаётся тем же.

## Многораундовый диалог

Если вы хотите интегрировать функцию многораундового диалога, необходимо отправить несколько запросов в поле `messages`; конкретный пример нескольких запросов показан на рисунке ниже:

Пример кода вызова на Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",

    "content-type": "application/json"

## Глубокое размышление
Модели Claude нового поколения могут выполнять рассуждения в соответствии со стратегией модели по умолчанию, без необходимости активации через суффикс модели `-thinking`. Chat-compatible ответы используют совместимое с OpenAI поле usage `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` уже включены в `completion_tokens`, не суммируйте их повторно. Рассуждения и видимый основной текст используют общий лимит выходных token, поэтому при небольшом `max_tokens` основной текст может быть пустым или обрезанным; в таком случае увеличьте выходной бюджет или, если используемая модель это поддерживает, выберите более низкий уровень рассуждений.

Если требуются нативные `thinking`, `output_config.effort`, блоки содержимого thinking и обратная передача подписей, используйте `/v1/messages`. Соответствующее для Messages поле usage — `output_tokens_details.thinking_tokens`, не смешивайте его с `completion_tokens_details.reasoning_tokens` из Chat-compatible.

## Визуальная модель

claude-sonnet-4-20250514 — это мультимодальная большая языковая модель, разработанная Claude, которая на основе claude-4 добавляет возможности визуального понимания. Эта модель может одновременно обрабатывать текстовые и графические входные данные, реализуя межмодальное понимание и генерацию.

Обработка текста с использованием модели claude-sonnet-4-20250514 соответствует основному содержимому использования выше, ниже будет кратко представлено, как использовать возможности модели по обработке изображений.

## Обработка ошибок

При вызове API, если возникает ошибка, API возвращает соответствующий код ошибки и информацию. Например:

- `400 token_mismatched`: Неверный запрос, возможно из-за отсутствующих или недопустимых параметров.
- `400 api_not_implemented`: Неверный запрос, возможно из-за отсутствующих или недопустимых параметров.
- `401 invalid_token`: Не авторизован, недопустимый или отсутствующий токен авторизации.
- `429 too_many_requests`: Слишком много запросов, вы превысили ограничение скорости.
- `500 api_error`: Внутренняя ошибка сервера, что-то пошло не так на сервере.

### Пример ответа с ошибкой

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
