> **目标读者：** Studio 用户，想在聊天里直接管理腾讯云（以及未来的 AWS / 阿里云）资源；或者实现方 / 评审者，想了解 BYOC 的安全模型。

## 是什么

普通的 Studio 连接器（GitHub、Notion、Slack 等）走 **OAuth**：你点连接 → 跳到对方授权页 → 我们换到一个 access token → 之后所有调用都拿这个 token。

但很多云厂商和 SaaS 不提供 OAuth API（只有控制台 SSO）—— 它们的 API 都是用 **用户自己持有的 SecretId / SecretKey 对** 来签名，比如腾讯云、阿里云、AWS。这类服务以前在 Studio 没法用。

**BYOC（Bring Your Own Credentials）** 就是为这类服务设计的连接器类型：
- 你在浏览器里把 SecretId / SecretKey 填进一个表单。
- 我们用 AES-256-GCM 加密落库；明文绝不写入数据库 / 日志 / API 响应。
- 当你装的某个 Studio 技能需要这套凭证时（比如 `acedata/tencentcloud-cos`），运行时只在沙盒内存里**短暂**解密注入为环境变量。

## 一对多：一个连接器，多个技能

设计上 **连接器 ≠ 技能**：

```
tencentcloud/tencentcloud  (一个 BYOC 连接器，存 SecretId/SecretKey)
       │
       ├── acedata/tencentcloud-cos        (对象存储)
       ├── acedata/tencentcloud-cls        (日志检索)
       ├── acedata/tencentcloud-cls-alarm  (告警策略)
       ├── acedata/tencentcloud-tke        (Kubernetes)
       ├── acedata/tencentcloud-dns        (DNSPod)
       └── acedata/tencentcloud-edgeone    (CDN / WAF)
```

你可以**只装你需要的子技能**。比如只想在聊天里管理对象存储，就只装 `tencentcloud-cos`；想管所有的就全装。连接器只装一次，密钥共享给所有子技能。

## 安全模型

| 阶段 | 凭证状态 |
|---|---|
| 用户在浏览器输入 | 明文，仅存在于浏览器内存 + HTTPS 传输 |
| 提交到 AuthBackend | 明文校验 → AES-256-GCM 加密（每次一个新的 12 字节 nonce）→ 写库 |
| 数据库静态 | 密文（带 GCM 认证 tag，防篡改）|
| 用户聊天触发技能调用 | AuthBackend 内存中解密 → 仅作为 HTTP 响应体回传给 chat worker（内部 token 鉴权 + HTTPS） |
| Chat sandbox | 仅作为环境变量注入（`TENCENTCLOUD_SECRET_ID` 等）；tool 调用结束即销毁 |
| Sandbox stdout / stderr | `redactSecrets` 兜底：任何 echo 出凭证值的输出（如 `env \| grep TC`）会被替换为 `[REDACTED]` |

明确**不会**发生的事：

- 不会写明文到数据库列。
- 不会写明文到 CLS / API access log。
- 不会出现在 API 错误响应（提交校验失败时，错误信息只说哪个字段缺失，不回显你提交了什么）。
- 不会出现在 chat 历史 / 模型 prompt（模型只看到环境变量**名字**，比如 `$TENCENTCLOUD_SECRET_ID`，不看到值）。

加密密钥（`CONNECTION_CRYPT_KEY`）由生产环境的 K8s Secret 注入，与 OAuth client_secret 同级安全要求。

## 用户操作流程

### 1. 装连接器

打开 [https://auth.acedata.cloud/user/connections](https://auth.acedata.cloud/user/connections) → 点「浏览连接器」→ 找到「腾讯云」→ 点「添加」。

弹出的对话框会按连接器声明的 **credential_schema** 渲染表单。腾讯云的字段是：

| 字段 | 类型 | 说明 |
|---|---|---|
| **SecretId** | 文本，必填 | 腾讯云访问密钥 ID，以 `AKID` 开头 |
| **SecretKey** | 密码（自动 mask），必填 | 与 SecretId 配对的私钥，仅在控制台创建时显示一次 |
| **默认地域** | 下拉，可选 | 默认调用使用的地域，可选 18 个 region；单条工具调用可临时覆盖 |

> ⚠️ **强烈建议使用 [CAM 子账号](https://console.cloud.tencent.com/cam/user)** 而不是主账号。给子用户绑定**只读** / **最小权限**策略（`QcloudCOSReadOnlyAccess`、`QcloudCLSReadOnlyAccess` 等），泄漏时影响面有限。

提交后卡片立刻变成「已添加」状态。

### 2. 装一个或多个技能

打开 [https://auth.acedata.cloud/user/skills](https://auth.acedata.cloud/user/skills) → 点「浏览技能」→ 发布者下拉选「AceDataCloud」→ 找到 `tencentcloud-*` 系列。每个独立装：

- `tencentcloud-cos` — COS 对象存储
- `tencentcloud-cls` — CLS 日志检索
- `tencentcloud-cls-alarm` — CLS 告警 / 通知组 / 屏蔽规则
- `tencentcloud-tke` — TKE Kubernetes 集群与工作负载
- `tencentcloud-dns` — DNSPod 解析记录
- `tencentcloud-edgeone` — EdgeOne CDN 缓存 / DNS / WAF

### 3. 在 Studio 里用

打开任一支持工具调用的 chat group（[Claude](https://studio.acedata.cloud/claude/conversations)、[GPT](https://studio.acedata.cloud/chatgpt/conversations)、[Grok](https://studio.acedata.cloud/grok/conversations)），直接用自然语言提问：

- *"列出我所有的腾讯云 COS 存储桶，并按对象数 / 总大小排序"*
- *"拉一下 platform-backend 最近 1 小时所有 5xx 错误日志，按 trace_id 去重"*
- *"把 tke-prod-hk 集群里 acedatacloud namespace 下 platform-backend deployment 扩到 4 副本"*
- *"给 acedata.cloud 加一个 mcp-tencentcloud CNAME 解析到 platform.acedata.cloud"*
- *"刷新 cdn.acedata.cloud 的 /logos/* 路径缓存"*

agent 会：

1. 识别需要调用对应技能（基于技能 `description` 中的关键字）。
2. 自动加载该技能（连同代码示例）。
3. 拿到注入的 `TENCENTCLOUD_SECRET_ID` / `_SECRET_KEY` / `_REGION` 环境变量。
4. 在 sandbox 里用官方 `tencentcloud-sdk-python` 完成调用，返回结果。

整个过程你不用写一行代码、不用切到控制台、不用记 API 路径。

### 4. 撤销凭证

回到 [https://auth.acedata.cloud/user/connections](https://auth.acedata.cloud/user/connections)，找到「腾讯云」卡片，点「断开」。所有用到这个连接器的技能立即失去访问权限（下一次工具调用会拿到 410）。

要彻底失效，建议同时去 [腾讯云 CAM 控制台](https://console.cloud.tencent.com/cam/capi) 把对应的 SecretId 也禁用 / 删除。

## 常见问题

**Q：我可以同时装两套腾讯云凭证吗（比如生产 + 测试两个账号）？**
A：目前每个用户每个 BYOC 连接器只能装一份凭证。要切换账号，先断开当前的、再装新的。多账号支持是 roadmap 项。

**Q：如果我的 SecretKey 在腾讯云控制台被轮换 / 删除了？**
A：下一次工具调用会从腾讯云那边拿到鉴权失败错误，agent 会把错误返回给你提示。回到 Studio 重新走一遍「断开 → 添加」流程录入新的密钥即可。

**Q：你们的加密密钥（`CONNECTION_CRYPT_KEY`）会轮换吗？轮换会发生什么？**
A：当前版本是单 Fernet-style 密钥。如果生产侧轮换密钥，旧密文无法解密；下一次工具调用会触发 `CredentialDecryptError` → AuthBackend 自动把那条 Connection 标记为 `REVOKED`，你会收到「请重新连接」的提示。轮换会做提前公告。后续会做 envelope encryption + KMS 支持平滑轮换。

**Q：有审计日志吗？我能看到自己的密钥被哪个技能用了几次吗？**
A：每次解密 + 注入会记录一条结构化日志（trace_id + skill identifier + 时间戳，**不含**凭证明文），保留 30 天。导出 / 自助查询的 UI 是 roadmap 项。

**Q：我自己想做一个新的 BYOC 连接器（比如阿里云 / AWS / Cloudflare），怎么办？**
A：开发流程见仓库 [`AuthBackend/app/seeds/connectors.yaml`](https://github.com/AceDataCloud/AuthBackend/blob/main/app/seeds/connectors.yaml) — 加一个 `auth_mode: byoc` 行 + `credential_schema` 字段，PR 里 cc `@germey`。配套技能放到 [`AceDataCloud/Skills`](https://github.com/AceDataCloud/Skills) 仓库的 `skills/<vendor>-<service>/` 目录，frontmatter 写 `connections: [<vendor>]`。

**Q：技能本身是开源的吗？**
A：是。[https://github.com/AceDataCloud/Skills](https://github.com/AceDataCloud/Skills) 下 Apache-2.0 / MIT。欢迎 fork / 提 PR。
