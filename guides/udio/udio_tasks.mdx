Udio Tasks API 的主要功能是通过输入 Udio Audios Generation API 生成的任务ID来查询该任务的执行情况。


本文档将详细介绍  Udio Tasks API  的对接说明，帮助您轻松集成并充分利用该 API 的强大功能。通过  Udio Tasks API ，您可以轻松实现查询  Udio Audios Generation API 的任务执行情况。

## 申请流程
要使用 Udio Tasks API，需要先到 申请页面 [Udio Audios Generation API ](https://platform.acedata.cloud/documents/c873dbad-c02f-4dd2-82ca-1f465baec490)申请相应的服务，然后复制 Udio Audios Generation API的任务ID，如图所示：

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" class="m-auto"></p>

最后进入Tasks API页面 [Udio Tasks API ](https://platform.acedata.cloud/documents/b06f0ef2-a638-483c-becf-abb9113aef1d)申请相应的服务，进入页面之后，点击「Acquire」按钮，如图所示：

![申请页面](https://cdn.acedata.cloud/rci31i.png)

如果您尚未登录或注册，会自动跳转到[登录页面](https://platform.acedata.cloud)邀请您来注册和登录，登录注册之后会自动返回当前页面。

首次申请时会有免费额度赠送，可以免费使用该 API。

## 请求示例
Udio Tasks API 可以用于查询 Udio Audios Generation API 的结果。关于怎样使用 Udio Audios Generation API，请参考文档 [Kling Videos Generation API ](https://platform.acedata.cloud/documents/3b921a16-a411-4557-8335-53f21d3f9e46)。

我们以 Udio Audios Generation API 服务返回的任务ID一个为例，演示如何使用该 API。假设我们有一个任务ID：20068983-0cc9-4c6a-aeb6-9c6a3c668be0，接下来演示如何通过传入一个任务ID来。

### 任务示例图

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" class="m-auto"></p>

### 设置请求头和请求体

**Request Headers** 包括：

- `accept`：指定接收 JSON 格式的响应结果，这里填写为 `application/json`。
- `authorization`：调用 API 的密钥，申请之后可以直接下拉选择。

**Request Body** 包括：

- `id`：上传的任务ID。
- `action`：对任务的操作方式。

设置如下图所示：

<p><img src="https://cdn.zhishuyun.com/o4hlcj.png" width="500" class="m-auto"></p>

### 代码示例

可以发现，在页面右侧已经自动生成了各种语言的代码，如图所示：

<p><img src="https://cdn.zhishuyun.com/2gu7p1.png" width="500" class="m-auto"></p>

部分代码示例如下：

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/udio/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "8aa0e153-2f15-41dd-9158-76bcd3254a9d",
  "action": "retrieve"
}'
```

## 批量查询操作

这是是针对多个任务ID来进行查询任务详情，与上面不同的是需要将action选中为retrieve_batch

- `ids`：上传的任务ID数组。
- `action`：对任务的操作方式。

## 错误处理

在调用 API 时，如果遇到错误，API 会返回相应的错误代码和信息。例如：

- `400 token_mismatched`：Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`：Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`：Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`：Too many requests, you have exceeded the rate limit.
- `500 api_error`：Internal server error, something went wrong on the server.

### 错误响应示例

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
