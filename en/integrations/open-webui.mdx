---
title: "Use AceDataCloud in Open WebUI"
description: "Connect Open WebUI to AceDataCloud chat models through the OpenAI-compatible API."
---

Open WebUI can call AceDataCloud through its built-in OpenAI-compatible **Chat Completions** connection. You do not need a custom Pipe. These steps were checked in Open WebUI v0.11.4.

## Before you start

- Get an AceDataCloud API token from the [application console](https://platform.acedata.cloud/console/applications). Give the application access to a chat model and check its current price.
- Use an Open WebUI account with admin rights to add a server-side connection. Keep this instance private or protect it with your normal authentication controls: anyone allowed to use the model can consume the token's credits.

## Add the connection

1. Open Open WebUI. In the user menu, choose **Admin Panel → Settings → Connections**.
2. Under **OpenAI API → Manage OpenAI API Connections**, click **Add Connection** (`+`).
3. Leave **Connection Type** at **External**. Set **URL** to `https://api.acedata.cloud/v1` (no trailing slash), **Auth** to **Bearer**, and **API Key** to your AceDataCloud API token. Leave **API Type** at **Chat Completions**.
4. Click **Verify Connection**. It checks the `/v1/models` endpoint; the button is optional when you save. Click **Save** in the connection dialog, then **Save** in the main Connections settings if prompted.
5. Start a new chat, open the model selector, choose a model such as `gpt-4o-mini`, and send a short prompt. Check the response in the chat and the corresponding entry in [AceDataCloud usage history](https://platform.acedata.cloud/console/usages).

`/v1/models` currently returns the model list for a valid token, so models can appear automatically. To show only chosen models, open the connection's **Advanced** section and add each exact ID under **Model IDs** using **Add** (`+`), then save. This is an allowlist: it replaces the full discovered list in Open WebUI. If verification fails but the token and chat route are valid, add a model ID manually and test a real chat. Use an ID from the [current chat model catalog](https://platform.acedata.cloud/documents/openai-chat-completions).

## Check the request and solve problems

The connection URL already contains `/v1`; Open WebUI appends `/models` for discovery and `/chat/completions` for messages. Do not enter the full chat endpoint as the connection URL. A blank or invalid token fails authentication. If the model appears but a chat fails, check the selected model ID, application access and remaining credits in AceDataCloud, then inspect the Open WebUI error. A successful **Verify Connection** checks model discovery only; a completed message proves the chat route.

Open WebUI also ships with a default OpenAI connection. If you do not use it, disable that connection in **Connections** to avoid selecting or probing it. The AceDataCloud token stays in Open WebUI's server-side connection settings. Anyone who administers that server can change or use the connection, so rotate the token if server access is compromised.

Each chat consumes credits. Open WebUI may make additional model requests for chat titles, tags, or follow-up suggestions; these can appear as separate charges. Review charges in [usage history](https://platform.acedata.cloud/console/usages); Open WebUI's local chat history is not the billing record. Tools, images, files, and other Open WebUI features depend on both the selected model and its API support. Validate each feature separately before enabling it for users. This guide covers text chat only.

For Open WebUI's current UI and connection rules, see its [OpenAI-compatible provider guide](https://docs.openwebui.com/getting-started/quick-start/connect-a-provider/starting-with-openai-compatible/). For the request schema, see [AceDataCloud Chat Completions](/en/guides/openai/openai_chat_completions).
