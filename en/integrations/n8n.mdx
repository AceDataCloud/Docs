title: "Use AceDataCloud in n8n"

The [sample workflow](https://raw.githubusercontent.com/AceDataCloud/Docs/main/examples/n8n/acedatacloud-chat.json) uses n8n's built-in Manual Trigger, Edit Fields, and HTTP Request nodes. It sends one non-streaming request to AceDataCloud Chat Completions and exposes the answer, response ID, model, and token counts. You do not need a community node.

## Import and run

1. Create an [AceDataCloud API token](https://platform.acedata.cloud/console/applications) with access to Chat Completions. Check the current model price and available balance in the console.
2. In n8n, create a workflow. Choose **Import from URL** and paste the [workflow JSON URL](https://raw.githubusercontent.com/AceDataCloud/Docs/main/examples/n8n/acedatacloud-chat.json). You can also download the JSON and choose **Import from File**.
3. Open **AceDataCloud chat**. **Authentication → Generic Credential Type** and **Generic Auth Type → Bearer Auth** are already set. Click **Connect to Bearer Auth**, then create or select an HTTP Bearer Auth credential. Enter the token **without** a `Bearer ` prefix. Select the credential and save the workflow before running it. Credentials are not included in the JSON.
4. In **Set prompt and model**, edit the prompt and, if needed, replace `gpt-4o-mini` with another model supported by [Chat Completions](/en/guides/openai/openai_chat_completions). The sample limits output to 80 tokens. Adjust `max_tokens` in the HTTP Request body if your task needs a longer answer.
5. Click **Execute workflow** once. Open **Read answer and usage** to inspect `answer`, `response_id`, `model`, and token counts. The workflow starts inactive and runs only when you click it.

Keep the token in the n8n credential, not in an Edit Fields node or the workflow JSON. Review n8n's execution-data retention settings before processing sensitive prompts.

## Connect your automation

Replace **Start a manual test** with your own trigger and map its text to `prompt` in **Set prompt and model**. The HTTP Request node posts to `https://api.acedata.cloud/openai/chat/completions` with `stream: false`. Downstream nodes can use `answer` and `response_id` from **Read answer and usage**.

Each execution can consume credits. The final node's token counts do not establish the amount charged: check the AceDataCloud usage record for the actual charge. Start with one manual run before adding a schedule or webhook. Monitor successful and failed n8n executions, duration, response IDs, token counts, and the matching AceDataCloud usage records.

## Handle errors and retries

The HTTP Request node fails the execution on an unsuccessful HTTP response. Open that node to inspect the status and error body:

| Status or symptom | Next step |
| --- | --- |
| `400` | Check the model, prompt, and request body. |
| `401` or `403` | Check the selected token and its access. Correct the credential before another run. |
| `429` | Check the rate limit and wait before retrying the failed execution. |
| Timeout or `5xx` | Check the AceDataCloud usage record and response ID, if one was returned, before retrying. The first request may have completed even if n8n did not receive its response. |

Automatic retries are disabled for this POST because replaying a completed request could incur a second charge. If you need retries, add them only after deciding how to reconcile ambiguous outcomes in your workflow.

This JSON is available for import directly. It will appear in n8n's built-in **Templates** search only after n8n publishes a separate template listing.
