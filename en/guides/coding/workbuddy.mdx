## 1. Obtain an API Key

Open the [Ace Data Cloud application list](https://platform.acedata.cloud/console/applications), enter an available application, and copy the API Key.

![Obtain Ace Data Cloud API Key](https://cdn.acedata.cloud/dvc3cg.jpg)

## 2. Add a Model

In WorkBuddy, go to **Settings → Models → Custom Models → Add Model**, then fill in:

| Field       | Value                                                                                            |
| -------- | ------------------------------------------------------------------------------------------------ |
| Provider | `Custom`                                                                                         |
| API Endpoint     | `https://api.acedata.cloud/v1`                                                                   |
| API Key  | The API Key you just copied                                                                                    |
| Model Name     | Go to the [model catalog](https://platform.acedata.cloud/models) to view, and fill in the name of the model to call exactly as is, for example, `claude-opus-5`, `gpt-6-sol` |
| Custom Protocol    | Disabled                                                                                               |

![WorkBuddy Custom Provider Configuration Interface](https://cdn.acedata.cloud/189027b68722.png)

> The `id` here is the model name used by the `model` parameter in API requests, not the UUID of a service, API, or Application, nor a custom display name. You can only enter `ds-4.0` when the live catalog returns `{"id":"ds-4.0"}`; if it is not in the catalog, it means it is currently unavailable. Do not guess or abbreviate it.

You can first view the available models in the [model catalog](https://platform.acedata.cloud/models); if you need to confirm the exact name that the current Coding credential can call, use the API Key you just copied to query the API catalog:

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Find the target model in the response's `data` array, and copy its `id` value exactly as is. Configure capability switches according to the model's actual supported capabilities.

When keeping “Custom Protocol” disabled, WorkBuddy will complete the path according to OpenAI Chat Completions rules. Enable advanced capability switches (tools, images, reasoning) only according to the actual capabilities of the selected model; if uncertain, keep the defaults first.

## 3. Verify

After saving, select the newly added model in the chat model selector and send `Reply only OK`. Then perform a read-only file or tool task to confirm that the required capabilities are available; call records can be viewed in [usage history](https://platform.acedata.cloud/console/usages).

If the model does not appear, confirm that the configuration has been saved and enabled; check the Key for 401; for 404, check whether the entered model name exactly matches the `id` in the catalog and whether the API endpoint is correct. WorkBuddy's official documentation states that the Key is stored in local configuration, but request content will still be sent to the configured model service.
