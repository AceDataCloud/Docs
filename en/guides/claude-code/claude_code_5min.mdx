This document has a single goal: to get you **up and running with your first Claude Code command via AceData Cloud proxy within 5 minutes**. For complete tutorials, see the IDE-specific sub-documents ([VS Code](https://platform.acedata.cloud/documents/claude-code-vscode-integrations) / [Cursor](https://platform.acedata.cloud/documents/claude-code-cursor-integration) / [JetBrains](https://platform.acedata.cloud/documents/claude-code-jetbrains-integrations)); this guide only covers the fastest path using the "**Terminal CLI** + **VS Code extension**".

> **Why use AceData Cloud to proxy Claude Code**:
> - Direct connection within China, no need to configure VPN
> - Lower cost compared to official pricing (billed by platform tokens)
> - The same key supports both Claude Messages API and Claude Code Token protocol simultaneously

## Minute 1: Apply for Credentials

Open the [Claude Messages service page](https://platform.acedata.cloud/documents/claude-messages) and click the "**Acquire**" button:

![](https://cdn.acedata.cloud/nyq0xz.png)

The platform will automatically create an Application for you and grant free quota. Note down the **Base URL** and **API Token** from the details page — you will need these for the next 5 steps.

| Field | Value | Purpose |
|-------|-------|---------|
| `BASE_URL` | `https://api.acedata.cloud` | Claude Messages compatible endpoint |
| `API_TOKEN` | `sk-...` (copyable from details page) | Anthropic-compatible authentication token |

## Minute 2: Install Claude Code

macOS / Linux / WSL:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows (native PowerShell):

```powershell
irm https://claude.ai/install.ps1 | iex
```

After installation, open a new terminal and verify:

```bash
claude --version
```

> You should see the version number. Claude Code bundles its own Node.js runtime, so it does not depend on the Node version installed on your machine.

## Minute 3: Point Environment Variables to AceData Cloud

Do not use the official `claude login` flow; instead, override with environment variables. Choose one of the two methods:

**Method A: Temporary (current shell session only)**

```bash
export ANTHROPIC_BASE_URL="https://api.acedata.cloud"
export ANTHROPIC_AUTH_TOKEN="sk-your-Token"
```

**Method B: Persistent (recommended)**

Append the above two lines to your `~/.zshrc` or `~/.bashrc` and then run `source` on the file.

> **Common pitfall**: The environment variable name is `ANTHROPIC_AUTH_TOKEN`, not `ANTHROPIC_API_KEY`; using the wrong name causes Claude Code to fall back to the official endpoint and return 401 errors.

## Minute 4: Run Your First Command

Navigate to any Git repository and run:

```bash
claude
```

If prompted to log in on first launch, press `Esc` to skip. Then enter:

```
List the dependencies of the current project and briefly explain the purpose of each.
```

You should see Claude invoking tools like `read_file` / `glob` / `grep` to browse the repo, then returning a list. As long as the model responds correctly without 401 errors, the proxy is active.

## Minute 5: Connect the VS Code Extension

1. Open VS Code → Extensions panel → search for `Claude Code` and install the official Anthropic extension;
2. Restart VS Code or run `Developer: Reload Window` in the command palette so the extension picks up the `~/.claude/settings.json` you wrote in Minute 3;
3. Click the ✦ Spark icon at the top-right of the editor, or click "✱ Claude Code" in the bottom status bar, to open the panel;
4. If prompted to sign in to the official Anthropic account on first launch, press `Esc` to skip — the extension automatically reuses the `ANTHROPIC_BASE_URL` / `ANTHROPIC_AUTH_TOKEN` configured in Minute 3.

> **Note**: The VS Code extension and the CLI share the same `~/.claude/settings.json`, so you do not need to configure anything separately inside VS Code. To override per-project, create `.claude/settings.local.json` (gitignored) in the repo root.

Once successful, you can drag files into the panel to ask questions or `@-mention` a file to propose edits. All billing flows through AceData Cloud.

## Verify You Are Using the Proxy

Run Claude Code once in `--debug` mode and confirm the actual request target is AceData Cloud:

```bash
claude --debug -p "say hi" 2>&1 | grep -iE 'base.?url|api\.acedata|anthropic\.com' | head
```

If you see `https://api.acedata.cloud` in the output, the proxy is in effect. If you see `api.anthropic.com` or get a 401, go back to Minute 3 and check your variable names (it must be `ANTHROPIC_AUTH_TOKEN`, not `ANTHROPIC_API_KEY`), and make sure `~/.claude/.credentials.json` does not still hold an official token from a previous `claude login` (delete that file if it does).

## 5 Most Frequently Asked Questions

**Q: I ran `claude login` then changed environment variables to AceData, but it doesn’t work?**  
A: `claude login` writes the official token to `~/.claude/.credentials.json`, which has higher priority than environment variables. Delete that file and then `source ~/.zshrc` to fix.

**Q: Can I use model names like `--model claude-opus-4-7`?**  
A: Yes. AceData Cloud proxy transparently passes the model field. All Anthropic public models plus our extended models `claude-opus-4-7` / `claude-haiku-4-5` / `claude-sonnet-4-5` are supported.

**Q: Can I configure multiple profiles (personal + work)?**  
A: Yes. Claude Code supports multiple profiles in `~/.claude/settings.json`; or the simplest way: write two shell functions `claude_personal` / `claude_work` that export different `ANTHROPIC_AUTH_TOKEN` values and then call `claude $@`.

**Q: Can I run this in GitHub Actions?**  
A: Yes. See the [Claude Code GitHub Actions configuration tutorial](https://platform.acedata.cloud/documents/claude-code-github-actions-integration).

**Q: What happens after the free quota is used up?**  
A: Go to [Application Management](https://platform.acedata.cloud/applications) → select your Claude Application → Topup to recharge (billed by actual token consumption), or switch to a subscription plan.
