This document has one goal: to get you **up and running with your first Claude Code command using the AceData Cloud proxy within 5 minutes**. For complete tutorials, see the IDE-specific sub-documents ([VS Code](https://platform.acedata.cloud/documents/claude-code-vscode-integrations) / [Cursor](https://platform.acedata.cloud/documents/claude-code-cursor-integration) / [JetBrains](https://platform.acedata.cloud/documents/claude-code-jetbrains-integrations)); this guide only covers the fastest path using the "**Terminal CLI** + **VS Code extension**".

> **Why use AceData Cloud proxy for Claude Code**:
> - Direct connection within China, no need to configure VPN
> - Lower cost compared to official pricing (billed by platform tokens)
> - The same key supports both Claude Messages API and Claude Code Token protocol simultaneously

## Minute 1: Apply for Credentials

Open the [Claude Messages service page](https://platform.acedata.cloud/documents/claude-messages) and click the "**Acquire**" button:

![](https://cdn.acedata.cloud/nyq0xz.png)

The platform will automatically create an Application for you and grant free credits. Note down the **Base URL** and **API Token** from the details page — you will need these for the next 5 steps.

| Field | Value | Purpose |
|-------|-------|---------|
| `BASE_URL` | `https://api.acedata.cloud` | Claude Messages compatible endpoint |
| `API_TOKEN` | `sk-...` (copyable from details page) | Anthropic-compatible authentication token |

## Minute 2: Install Claude Code

macOS / Linux / WSL:

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows (native PowerShell):

```powershell
irm https://claude.ai/install.ps1 | iex
```

After installation, open a new terminal and verify:

```bash
claude --version
```

> You should see the version number. Claude Code includes its own Node.js runtime and does not depend on your machine’s Node version.

## Minute 3: Point Environment Variables to AceData Cloud

Do not use the official `claude login` flow; instead, override with environment variables. Choose one of the two methods:

**Method A: Temporary (current shell session only)**

```bash
export ANTHROPIC_BASE_URL="https://api.acedata.cloud"
export ANTHROPIC_AUTH_TOKEN="sk-your-Token"
```

**Method B: Persistent (recommended)**

Append the above two lines to your `~/.zshrc` or `~/.bashrc`, then `source` the file.

> **Common pitfall**: The environment variable name is `ANTHROPIC_AUTH_TOKEN`, not `ANTHROPIC_API_KEY`; if you use the wrong name, Claude Code will fall back to the official endpoint and return 401 errors.

## Minute 4: Run Your First Command

Navigate to any Git repository and run:

```bash
claude
```

If prompted to log in on first launch, press `Esc` to skip. Then enter:

```
List the dependencies of the current project and briefly explain the purpose of each.
```

You should see Claude invoking tools like `read_file` / `glob` / `grep` to browse the repo, then output a list. If the model responds correctly without 401 errors, the proxy is working.

## Minute 5: Connect the VS Code Extension

1. Open VS Code → Extensions panel → search for `Claude Code` and install the official Anthropic extension;
2. Restart VS Code or run `Developer: Reload Window` from the command palette to let the extension load the `~/.claude/settings.json` configured in Minute 3;
3. Click the ✦ Spark icon at the top-right of the editor or the "✱ Claude Code" in the bottom status bar to open the panel;
4. On first use, if prompted to log in to the official account, press `Esc` to skip — the extension will automatically use the `ANTHROPIC_BASE_URL` and `ANTHROPIC_AUTH_TOKEN` you set in Minute 3.

> **Tip**: The VS Code extension and CLI share the same `~/.claude/settings.json`, so you don’t need to configure it separately in VS Code. To override with project-level config, create `.claude/settings.local.json` in the repo root (this file is gitignored).

Once connected, you can drag files into the panel to ask questions or use `@-mention` to reference files for modification suggestions. All billing goes through AceData Cloud.

## Verify You Are Actually Using the Proxy

Run once with `--debug` mode to confirm requests go to AceData Cloud:

```bash
claude --debug -p "say hi" 2>&1 | grep -iE 'base.?url|api\.acedata|anthropic\.com' | head
```

If you see `https://api.acedata.cloud`, the proxy is active; if you see `api.anthropic.com` or get 401 errors, revisit Minute 3 to check the environment variable names (must be `ANTHROPIC_AUTH_TOKEN`, not `ANTHROPIC_API_KEY`) and ensure `~/.claude/.credentials.json` does not contain the official token (delete that file if it does).

## 5 Most Frequently Asked Questions

**Q: I ran `claude login` then switched environment variables to AceData, but it doesn’t take effect?**  
A: `claude login` writes the official token to `~/.claude/.credentials.json`, which takes precedence over environment variables. Delete that file and `source ~/.zshrc` again.

**Q: Can I use model names like `--model claude-opus-4-7`?**  
A: Yes. AceData Cloud proxy transparently passes the model field. All Anthropic public models plus our extended models `claude-opus-4-7` / `claude-haiku-4-5` / `claude-sonnet-4-5` are supported.

**Q: Can I configure multiple profiles (personal + work)?**  
A: Yes. Claude Code supports multiple profiles in `~/.claude/settings.json`; or simply define two shell functions `claude_personal` / `claude_work` that export different `ANTHROPIC_AUTH_TOKEN` values before calling `claude $@`.

**Q: Can I run this in GitHub Actions?**  
A: Yes. See the [Claude Code GitHub Actions integration tutorial](https://platform.acedata.cloud/documents/claude-code-github-actions-integration).

**Q: What happens after free credits run out?**  
A: Go to [Application Management](https://platform.acedata.cloud/applications) → select your Claude Application → Topup to recharge (billed by actual token usage), or switch to subscription with points.
