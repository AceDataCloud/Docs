---
title: "Get the Proxy List Under an AceDataCloud Platform Service"
description: "Platform integration guide - Ace Data Cloud"
---

Return the Proxy endpoints mounted under the service by Service UUID with pagination. If only an alias is available, first call [Service Details](https://platform.acedata.cloud/documents/platform-service-detail) to obtain the `id`.

## API Overview

| Item   | Content                                                                |
| ------ | ---------------------------------------------------------------------- |
| Method | `GET`                                                                  |
| URL    | `https://platform.acedata.cloud/api/v1/services/{service_id}/proxies/` |
| Auth   | Public, no account token required                                      |
| Pagination | `count` + `items`                                                  |

## Parameters

| Parameter          | Location | Required | Description                                              |
| ------------------ | -------- | -------- | -------------------------------------------------------- |
| `service_id`       | path     | Yes      | Service UUID; alias is not supported                    |
| `limit` / `offset` | query    | No       | Pagination                                               |
| `ordering`         | query    | No       | Django ordering expression; `rank` or `-rank` recommended |

```shell
export SERVICE_ID='Your Service ID'
curl --get "https://platform.acedata.cloud/api/v1/services/${SERVICE_ID}/proxies/" \
  --data-urlencode 'limit=100' \
  -H 'Accept: application/json'
```

## Response Description

List items are serialized from the Proxy model. Fields verified online include `id`, `service_id`, `title`, `endpoint`, `price`, `stage`, `rank`, `tags`, `metadata`, `document_id`, `service`, and time fields.

- The business entry field is `endpoint`, not `path`.
- The pricing field is `price`, not `cost`.
- If the Service type is not Proxy or no Proxy is mounted, empty `items` are returned.

Public integrations should only rely on `endpoint` and published capabilities, and should not rely on unpublished implementation details.
