---
title: "Get the AceDataCloud Platform Model List"
description: "Platform integration guide - Ace Data Cloud"
---

Returns the platform's public model catalog. The response uses an OpenAI-style `{ "object": "list", "data": [...] }` structure. This catalog is used for model selection and capability discovery, and does not mean that the current account has necessarily applied for the corresponding services.

## API Overview

| Item   | Content                                              |
| --- | ----------------------------------------------- |
| Method  | `GET`                                           |
| URL | `https://platform.acedata.cloud/api/v1/models/` |
| Authentication  | Public, no account token required                                       |
| Pagination  | No pagination; all matching items are located in `data`                              |

## Query Parameters

| Parameter             | Type      | Required  | Description                                      |
| -------------- | ------- | --- | --------------------------------------- |
| `owned_by`     | string  | No   | Precisely filters by the model provider identifier in the catalog                        |
| `type`         | string  | No   | Precisely filters by model type, for example `chat`                     |
| `capability`   | string  | No   | Returns only models whose `capabilities` include this capability, for example `vision` |
| `with_pricing` | boolean | No   | Appends public pricing information when `1`, `true`, or `yes`            |

`service_id`, `tag`, `limit`, `offset`, and `ordering` are currently unsupported; passing them will not produce corresponding filtering or pagination effects.

## Request Examples

```shell
# All public models
curl 'https://platform.acedata.cloud/api/v1/models/' \
  -H 'Accept: application/json'

# Chat models that support vision, with pricing
curl --get 'https://platform.acedata.cloud/api/v1/models/' \
  --data-urlencode 'type=chat' \
  --data-urlencode 'capability=vision' \
  --data-urlencode 'with_pricing=true' \
  -H 'Accept: application/json'
```

```python
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/models/",
    params={"type": "chat", "capability": "vision", "with_pricing": "true"},
    timeout=10,
)
response.raise_for_status()
payload = response.json()
for model in payload["data"]:
    print(model["id"], model["capabilities"], model.get("pricing"))
```

## Actual Response Structure

```json
{
  "object": "list",
  "data": [
    {
      "id": "example-model",
      "label": "Example Model",
      "owned_by": "example",
      "service_prefix": "acedatacloud-example",
      "group_label": "Example",
      "type": "chat",
      "capabilities": [
        "vision"
      ],
      "object": "model",
      "pricing": {
        "currency": "USD",
        "unit": "token",
        "input_usd": 1e-06,
        "output_usd": 2e-06,
        "official_input_usd": 1e-06,
        "official_output_usd": 2e-06,
        "savings_pct": 0,
        "credit_usd_rate": 0.1
      }
    }
  ],
  "credit_usd_rate": 0.1
}
```

`pricing` and the top-level `credit_usd_rate` appear only when `with_pricing=true`; not every model has calculable `pricing`. Model objects are based on the public fields in `config/models.json`, and clients should ignore newly added fields.

> Pricing fields are catalog display data. Actual business calls are still subject to the billing rules and final usage records of the corresponding API/Service.
