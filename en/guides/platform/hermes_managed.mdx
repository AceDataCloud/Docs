Create an independent Hermes container instance for each Application. By default, a base image with a fixed release version is used, retaining native functionality; the platform provides purchasing, renewal, persistent storage, and deployment management.

## Creation and Purchase

1. Open [Hermes Deployment](https://platform.acedata.cloud/services/hermes) and create an Application.
2. Select a duration plan on the purchase page and complete payment.
3. Return to the configuration page, where you can select a platform chat model from the drop-down list and view the current model price. The platform will create independent API credentials for this instance; you can also disable platform integration and configure it yourself in the native console.
4. Choose to automatically generate access credentials, or set your own strong password/Token. Confirm to begin deployment. Access credentials and model API credentials are independent from each other.
5. Once the instance is ready, obtain the access address and login credentials from the management page.
6. Log in to the native console to configure channels. If platform model integration was disabled during deployment, you must also configure the model provider and credentials yourself before chat can be used.

Deployment fees are charged based on the plan duration; specific USD prices and durations are subject to the purchase page. Model invocation fees are charged separately; purchasing deployment duration does not include model credits. When platform integration is enabled, dedicated API credentials only provide access to the chat interface corresponding to the selected model, and usage is charged separately from your platform balance. Each Application is purchased, renewed, and managed separately.

## Passwords, Credentials, and Subsequent Configuration

Access credentials are set before the first startup. The automatic generation method uses random credentials, custom passwords must be at least 16 characters, and OpenClaw Tokens must be at least 32 characters. Drafts do not save passwords; you may need to enter them again after switching pages. After deployment, only the Application owner and administrators can view the access credentials.

The model API credentials for each instance are not shared, their validity is extended with deployment renewals, and they are revoked when the instance is deleted. If the platform model was not connected during the initial deployment, you can select a platform model on the configuration page of that Application and redeploy; the platform will update the default model while preserving conversations and other native settings. Afterwards, modify models and channels in the native console; if you switch to a model from another service, first adjust the authorization for the corresponding interface in platform credential management, or use the corresponding credentials. A normal redeployment will not overwrite native settings. Deployment environments that have not passed release verification will temporarily reject new deployments; please contact support.

## Versions and Data

The configuration page displays the currently released image version. New instances use the currently released version of the service; existing instances will not be automatically replaced when the catalog is updated. Redeployment applies the current service version; please back up first and confirm the upgrade requirements of the version you use.

Each instance provides 1 CPU, a 2 GiB memory limit, and 10 GiB of persistent storage by default. Instance data is retained after restarts. Deleting a deployment proactively or reclamation after expiration will delete storage; please export any data you need to retain in advance.

## Renewal and Expiration

Renew on the purchase page of the current Application, and the validity period will be extended according to the platform's existing duration rules. After expiration, the access entry is suspended, and renewal during the grace period restores access; after the grace period, the instance and data will be reclaimed. Refer to the expiration time, billing status, and deletion notices on the management page.

## Logging In to the Management Interface

Copy the Dashboard address, username `admin`, and password from the deployment management page, then open it and log in. Login information is only available to the owner of that Application and platform administrators. Models, skills, and channels are configured in the Hermes native interface.

## Frequently Asked Questions

- **Why can't the new instance respond yet?** Deployment completion only means that the container is ready. If platform model integration was disabled during deployment, you must select a platform model on the configuration page and redeploy, or configure the model and credentials yourself in the native interface.
- **Are additional plugins or model fallbacks preinstalled?** They are not added by default; configure them in the native interface as needed.
- **How do existing instances get updated?** Existing Applications and orders are retained, and the current service version is used during redeployment; back up data and check version compatibility before upgrading.
- **What should I do if startup fails?** First check the deployment logs and events, and configure the model after confirming that the instance is ready. Do not expose instance passwords and keys in public comments or screenshots.
