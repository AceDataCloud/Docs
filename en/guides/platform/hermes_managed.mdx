Create an independent Hermes container instance for each Application. By default, a base image with a fixed release version is used, retaining native functionality; the platform provides purchasing, renewal, persistent storage, and deployment management.

## Creation and Purchase

1. Open [Hermes Deployment](https://platform.acedata.cloud/services/hermes) and create an Application.
2. Select a duration plan on the purchase page and complete the payment.
3. Return to the configuration page, where you can select a platform chat model from the dropdown list and view the current model price. The platform will create independent API credentials for this instance; you can also disable platform access and configure it yourself in the native console.
4. Choose to automatically generate access credentials, or set your own strong password/Token; select A2A and EnvarPay as needed, then confirm to begin deployment. Access credentials and model API credentials are independent of each other.
5. After the instance is ready, obtain the access address and login credentials from the management page.
6. Log in to the native console to configure channels. If platform model access was disabled during deployment, you must also configure the model provider and credentials yourself before chat can be used.

Deployment fees are charged based on the plan duration. Refer to the purchase page for specific USD prices and durations. Model usage fees are charged separately; purchasing deployment duration does not include model credits. When platform access is enabled, the dedicated API credentials only expose the chat interface corresponding to the selected model, and usage is charged separately from your platform balance. Each Application is purchased, renewed, and managed separately.

## Passwords, Credentials, and Subsequent Configuration

Access credentials are set before the first startup. The automatically generated method uses random credentials, custom passwords must be at least 16 characters, and OpenClaw Tokens must be at least 32 characters. Drafts do not save passwords; you may need to re-enter them after switching pages. After deployment, only the Application owner and administrators can view the access credentials.

The model API credentials for each instance are not reused, their validity is extended with deployment renewal, and they are revoked when the instance is deleted. If the platform model was not connected during the initial deployment, you can select a platform model on that Application's configuration page and redeploy; the platform will update the default model while retaining conversations and other native settings. Afterwards, modify models and channels in the native console; if you select a model from another service, first adjust the authorization for the corresponding interface in platform credential management, or use the corresponding credentials. Normal redeployment will not overwrite native settings. Deployment environments that have not passed release verification will temporarily reject new deployments; please contact support.

## Optional Deployment Components

After selecting A2A, the deployment template will start the native Hermes A2A gateway and provide an owner token on the management page. Selecting EnvarPay will additionally install an independent service container and persistent ledger, and requires A2A to be enabled first. EnvarPay initially has only owner access credentials, with no service or payment-receiving identity, and will not automatically charge fees or make purchases on your behalf. Neither option will automatically register the instance with Envar; existing instances can enter configuration from the management page, enable them, and redeploy. Enabled components cannot currently be disabled in this wizard.

## Versions and Data

The configuration page displays the currently released image version. New instances use the service's currently released version; existing instances are not automatically replaced when the catalog is updated. Redeployment will apply the current service version; please back up first and confirm the upgrade requirements of the version you use.

Each instance provides 1 CPU, a 2 GiB memory limit, and 10 GiB of persistent storage by default. Instance data is retained after restarts. Actively deleting a deployment or expiration reclamation will delete storage; please export any data you need to retain in advance.

## Renewal and Expiration

Renew on the purchase page of the current Application, and the validity period will be extended according to the platform's existing duration rules. After expiration, the access entry is suspended; renewing during the grace period restores access. After the grace period, the instance and data will be reclaimed. Refer to the expiration time, billing status, and deletion notices on the management page.

## Logging In to the Management Interface

On the deployment management page, copy the Dashboard address, username `admin`, and password, then open it and log in. Login information is provided only to the owner of that Application and platform administrators. Models, skills, and channels are configured in the native Hermes interface.

## Frequently Asked Questions

- **Why can the new instance not respond yet?** Deployment completion only indicates that the container is ready. If platform model access was disabled during deployment, you must select a platform model on the configuration page and redeploy, or configure the model and credentials yourself in the native interface.
- **Are additional plugins or model fallbacks preinstalled?** None are added by default; configure them in the native interface as needed.
- **How do existing instances update?** The original Application and order are retained, and the current service version is used during redeployment; back up data and check version compatibility before upgrading.
- **What should I do if startup fails?** First check deployment logs and events, and configure the model only after confirming that the instance is ready. Do not expose instance passwords and keys in public comments or screenshots.
