Create an independent Hermes container instance for each Application. By default, use a base image with a fixed release version and retain native features; the platform provides purchase, renewal, persistent storage, and deployment management.

## Creation and Purchase

1. Open [Hermes Deployment](https://platform.acedata.cloud/services/hermes) and create an Application.
2. Select a duration plan on the purchase page and complete the payment.
3. Return to the configuration page, where you can select a platform chat model from the dropdown list and view the current model price. The platform will create independent API credentials for this instance; you can also disable platform access and configure it yourself in the native console.
4. Choose to automatically generate access credentials, or set your own strong password/Token, then confirm to begin deployment. Access credentials and model API credentials are independent of each other.
5. After the instance is ready, obtain the access address and login credentials from the management page.
6. Log in to the native console and configure your own model providers, keys, and channels.

Deployment fees are charged according to the plan duration. The specific USD price and duration are subject to the purchase page. Model invocation fees are charged separately; purchasing deployment duration does not include model credits. When platform access is enabled, the dedicated API credentials only expose the chat interface corresponding to the selected model, and usage is charged separately from your platform balance. Each Application is purchased, renewed, and managed separately.

## Passwords, Credentials, and Subsequent Configuration

Access credentials are set before the first startup. The automatic generation method uses random credentials, custom passwords must be at least 16 characters, and OpenClaw Tokens must be at least 32 characters. Drafts do not save passwords; you may need to re-enter them after switching pages. After deployment, only the Application owner and administrators can view the access credentials.

The model API credentials for each instance are not reused, their validity is extended with deployment renewal, and they are revoked when the instance is deleted. After deployment initialization, please modify models and channels in the native console; if you switch to models from other services, first adjust the corresponding interface authorization in platform credential management, or use the corresponding credentials. Normal redeployment will not overwrite native settings. Deployment environments that have not passed release validation will temporarily reject new deployments; please contact support.

## Versions and Data

The configuration page displays the currently released image version. New instances use the service's currently released version; existing instances will not be automatically replaced when the catalog is updated. Redeployment will apply the current service version; please back up first and confirm the upgrade requirements of the version in use.

Each instance provides 1 CPU, a 2 GiB memory limit, and 10 GiB of persistent storage by default. Instance data is retained after restarts. Actively deleting a deployment or expiration reclamation will delete storage; please export any data that needs to be retained in advance.

## Renewal and Expiration

Renew on the purchase page of the current Application, and the validity period will be extended according to the platform's existing duration rules. After expiration, the access entry is suspended, and renewing during the grace period restores access; after the grace period, the instance and data will be reclaimed. Refer to the expiration time, billing status, and deletion notices on the management page.

## Logging In to the Management Interface

Copy the Dashboard address, username `admin`, and password from the deployment management page, then open it and log in. Login information is provided only to the owner of that Application and platform administrators. Models, skills, and channels are configured in the Hermes native interface.

## Frequently Asked Questions

- **Why can the new instance not respond yet?** Deployment completion means the container is ready; you need to configure models and credentials in the native interface before you can start using it.
- **Are additional plugins or model fallbacks preinstalled?** They are not added by default; configure them in the native interface as needed.
- **How do existing instances get updated?** The original Application and order are retained, and the current service version is used during redeployment; back up data and check version compatibility before upgrading.
- **What should I do if startup fails?** First check deployment logs and events, and configure the model only after confirming that the instance is ready. Do not expose instance passwords and keys in public comments or screenshots.
