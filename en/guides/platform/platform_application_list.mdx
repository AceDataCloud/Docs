---
title: "Retrieve the AceDataCloud Platform Service Application List"
description: "Platform integration guide - Ace Data Cloud"
---

Returns, in pages, Applications that the account owns or is authorized to use, including balances, statuses, service summaries, and associated credentials. Suitable for bulk balance monitoring, finding Application IDs, and accessing credential management.

## Preparation

1. Log in to the [AceDataCloud Platform](https://platform.acedata.cloud).
2. Create an account token in the [Account Token Console](https://platform.acedata.cloud/console/platform-tokens).
3. Regular users use `user_id=me`; you can also obtain your own UUID from `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='your account token'
```

## API Overview

| Item   | Content                                               |
| --- | ----------------------------------------------------- |
| Method  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Authentication  | Account Token; OAuth token requires `applications:read`       |
| Pagination  | `count` + `items`                                     |

Regular users should pass `user_id=me`. If not passed, the query is not first narrowed by account, and pagination may return `403` when encountering unauthorized objects; administrators can view the entire table without passing it.

## Query Parameters

| Parameter            | Type          | Required     | Description                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Required for regular users | Query subject; supports repeated parameters                                         |
| `affiliation` | string      | No      | `owner` (default) or `granted`; both can be passed repeatedly to take the union, effective only when `user_id` is present |
| `service_id`  | UUID        | No      | Filter by service; supports repeated parameters                                        |
| `scope`       | string      | No      | `Individual` or `Global`; supports repeated parameters                      |
| `type`        | string      | No      | `Usage` or `Period`; supports repeated parameters                           |
| `limit`       | integer     | No      | Number of items per page, maximum 100                                         |
| `offset`      | integer     | No      | Pagination offset                                               |
| `ordering`    | string      | No      | Only `created_at` or `-created_at` is supported                    |

`paid`, `disabled`, `expired`, `low_balance`, and `tag` are currently not server-side filter parameters. For balance alerts, retrieve the list first, then determine on the client side based on each Application's `remaining_amount`, `service.unit`, and business thresholds.

## Request Examples

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

View both Applications you own and Applications that others have granted to you:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Response Description

The response is `{count, items}`. Each item contains Application model fields, with the following additions:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: credential summaries that the current caller is authorized to view;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`;
- The actual value of `scope` is `Individual` or `Global`;
- The actual value of `type` is `Usage` or `Period`.

`remaining_amount` may be empty; the client must check for null first before performing numerical comparisons. The quota unit is determined by `service.unit`.
