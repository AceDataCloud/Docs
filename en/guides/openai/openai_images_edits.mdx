## 3. Upload a Local Image

Use `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

You can pass `image` repeatedly. The GPT Image series supports up to 16 reference images. The `image` in JSON requests can be a single URL or an array of URLs; local files are uploaded using multipart.

## 4. Use a Mask for Local Editing

The official Images Edit API specifies the areas allowed to be modified through `mask`. Ace Data Cloud's `:official` models follow the same multipart contract:

- `mask` must be a PNG with an Alpha channel and must not exceed 4MB;
- The mask dimensions must exactly match the first `image`;
- Transparent pixels with an Alpha value of `0` indicate areas allowed to be edited, while non-transparent pixels indicate areas that should be preserved;
- RGB images that are only black and white but have no transparent channel cannot be used as valid masks;
- The prompt should describe the complete desired image, while clearly specifying the local modifications and the content that needs to remain unchanged.

First, generate a mask from the original image below. The example makes the central rectangle transparent, allowing the model to modify only that area:
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Then upload the original image and the mask together:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer Your API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

You can also continue using the `images.edit` calling method of the official OpenAI Python SDK; you only need to point `base_url` to Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="Your API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

When using `mask`, the original image and the mask must be uploaded separately in the same multipart request through `image=@input.png` and `mask=@mask.png`. Do not pass a URL original image mixed with a local mask file; pure URL editing requests do not support attaching an additional local `mask` file. The mask constrains the editing area, but the generation model may still naturally blend the edges; when strict boundaries are needed, clear Alpha edges should be used and the prompt should repeatedly specify which content must remain unchanged.

The above calling method is consistent with the mask examples in the [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) and the [official GPT Image Cookbook](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Common Parameters

| Field                | Description                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (faster), or `gpt-image-2.5-sunburst` (higher fidelity and control); all three can use their corresponding `:official` variants, and `gpt-image-2` also supports `:reverse` |
| `image`           | JSON uses a single URL or an array of up to 16 URLs; multipart uses one or more `image` file fields. Local image files must be uploaded when using `mask`                                              |
| `mask`            | Optional PNG mask, limited to multipart file uploads; must include an Alpha channel, have the same dimensions as the first `image`, and not exceed 4MB                                                                 |
| `prompt`          | Editing instruction                                                                                                                             |
| `size`            | `auto` or a `WIDTHxHEIGHT` that meets the restrictions                                                                                                     |
| `n`               | 1–10; only 1 is supported when `response_format=b64_json`                                                                                           |
| `response_format` | `url` or `b64_json`                                                                                                               |
| `callback_url`    | Optional asynchronous callback URL                                                                                                                         |

The size rules are the same as the generation endpoint: width and height must be multiples of 16, the longest side must not exceed 3840, total pixels must be 655,360–8,294,400, and the aspect ratio must not exceed 3:1. When `size` is omitted or `auto` is used, the model selects the canvas based on the prompt and the first reference image.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst`, and their `:reverse` aliases are billed by the number of successfully generated images; `gpt-image-2:official`, `gpt-image-2.5-flare:official`, and `gpt-image-2.5-sunburst:official` are billed based on the actual Tokens for text input, reference image input, and image output, with final usage records prevailing.

## 6. Asynchronous Callbacks and Troubleshooting

Long-running tasks can include the following in the request:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

The asynchronous 200 response is `{"task_id": "..."}`; the final result is returned through a callback after completion. Synchronous requests return `created` and `data`.

| Status  | Check                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Image format/count, parameter combinations, and size format; when using `mask`, check the PNG Alpha channel, the 4MB limit, and whether its dimensions match the first original image |
| 401 | API Key and Bearer Header                                           |
| 429 | Request frequency                                                              |
| 504 | Switch to asynchronous callbacks                                                            |

Error responses include `trace_id`. Provide this ID when reporting an issue; do not provide the API Key.

For complete fields and real-time enumerations, refer to the [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits) page. For pure text-to-image generation, see [GPT Image 2 / 2.5 / 2.6 Image Generation](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 continues to use the generation, editing, asynchronous task, and billing interfaces of 2.5:

| Model                                                          | Billing                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0.22 Credits/image                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0.22 Credits/image                   |
| `gpt-image-2.6-flare:official`                              | Same as 2.5 official, billed by actual Token usage |
| `gpt-image-2.6-sunburst:official`                           | Same as 2.5 official, billed by actual Token usage |

Available quality options are `auto`, `low`, `medium`, `high`, `xhigh`, and `max`; use `auto` for size or a `WIDTHxHEIGHT` that meets the above constraints. This endpoint supports `png`, `jpeg`, and `webp`; GPT Image 2.6 additionally supports native `gif` animations, while SVG is not currently supported. Editing supports JSON image URLs and multipart file uploads. `:reverse` is an explicit alias of the regular version with the same name. Please use the full model name; do not pass `gpt-image-2.6`.

### GPT Image 2.6 Image-to-GIF Animation
GPT Image 2.6 Flare, the standard version of Sunburst, `:reverse`, and `:official` can all use `output_format: "gif"`. Animation frames, loop information, and playback duration will be preserved; `frame_count` indicates the number of frames, `frame_duration_ms` indicates the milliseconds per frame, the frame count must be an integer from 2–16, the duration per frame must be an integer from 20–655350 milliseconds, and they are only used for GIF; encoding is rounded to the nearest 10ms. When unspecified, the default is 9 frames at 200 milliseconds per frame; when the GIF size is omitted or set to auto, the 512x512 preset is used.

It is recommended to first use `size: "512x512"`, `frame_count: 9`, and `frame_duration_ms: 200`. GIF has separate size and frame count limits, and static 4K specifications cannot be applied directly; some models will adjust the actual output size. `n` indicates the number of returned GIF files, not the number of animation frames. The standard version and `:reverse` are still billed by the number of successful files, while the official version is billed by actual Token usage.

```json
{
  "model": "gpt-image-2.6-flare",
  "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
  "prompt": "Animate the mug gently moving left and right. Keep its appearance and the background, no text.",
  "output_format": "gif",
  "size": "512x512",
  "quality": "medium",
  "frame_count": 9,
  "frame_duration_ms": 200,
  "n": 1,
  "async": true
}
```

### GPT Image 2.6 4K Static Images

Flare, Sunburst, and their `:reverse` and `:official` variants can all use the aforementioned 4K pixel presets, such as `3840x2160` and `2160x3840`. Both generation and editing pass specific pixels through `size`; `4K` is not a valid `size` value, and `4096x4096` also exceeds the current pixel limit. The above 4K specifications apply to static PNG/JPEG/WebP; for GIF, please use its dedicated parameters.

### GPT Image 2.6 Composition Complexity

`complexity` can be `low`, `medium`, or `high`; when omitted, the model default `high` is used. It controls planning complexity and is independent of `quality` rendering quality; it does not incur additional per-request charges, and the official version is still settled based on actual Token usage. Other models do not support this parameter.

GIF does not support masks, markup images, custom compression, prompt rewriting, or partial image streaming output; incompatible combinations will be rejected before generation. Size, frame count, and quantity are jointly limited by the model pixel budget; `1024x1024` with 2 frames has been verified to work for standard Flare, but this conclusion cannot be extended to all 1K combinations or 4K GIFs.

### Markup-Guided Editing

GPT Image 2.6 static editing supports `markup`. Upload a transparent PNG with the same dimensions as the first reference image, circle the area to be modified on a separate layer, and specify the modification requirements in `prompt`. The markup layer must contain transparent pixels; each of the two images must not exceed 16777216 pixels, and the markup image must not exceed 40MB. JSON can pass an HTTPS URL, a PNG base64 data URL, or `{ "image_url": "https://..." }`; multipart uploads the file through `markup`. The platform will pass the markup layer as a file. `markup` cannot be used together with `mask`, GIF, or `prompt_rewriter`, and does not support `file_id`.

`input_fidelity` does not apply to GPT Image 2.6; please omit it.
