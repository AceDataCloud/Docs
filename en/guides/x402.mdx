x402 is an on-chain payment protocol based on the HTTP 402 Payment Required standard, allowing callers to complete on-chain settlement simultaneously when initiating API requests. It is ideal for pay-per-call scenarios among automated programs, AI agents, and microservices. This guide enables you to programmatically complete AceDataCloud order payments within your system, achieving a "pay-as-you-request" experience.

Official references:

- x402 Overview Document: [https://docs.cdp.coinbase.com/x402/docs/overview](https://docs.cdp.coinbase.com/x402/docs/overview)
- x402 Open Source Examples: [https://github.com/coinbase/x402](https://github.com/coinbase/x402)

This document is intended for developers integrating AceDataCloud platform x402 payment capabilities into their business, detailing the complete process from environment preparation to payment invocation, and providing example code for Axios, Fetch, Python requests, and httpx. Key points:

- Payment settlement occurs on the **Base mainnet**, using **USDC** assets;
- You must use an **EVM private key** of the wallet holding the funds to generate the `X-PAYMENT` signature header;
- All APIs are under the domain `https://platform.acedata.cloud`, and the `Authorization` header must carry the **Platform Token**.

---

## 1. Preparation

### 1. Check the order and record payment information

Log in to the console at [https://platform.acedata.cloud](https://platform.acedata.cloud). You can view orders requiring payment in the order list or order detail page. The order details display:

- Order ID (e.g., `7744945e-5e77-4dcc-a9c4-528692d17b34`);
- Payment address `pay_to` (also returned in the 402 response; it is recommended to rely on the page information).

Please record the order ID and confirm the `pay_to` address, as it must be the destination for funds when signing.

### 2. Prepare the payment wallet and funds

- Prepare an EVM wallet supporting the Base mainnet and export the private key to be used;
- Deposit sufficient **USDC** on the Base mainnet (payment amounts are in atomic units with 6 decimals);
- The x402 Facilitator will cover network fees, so the payment wallet only needs enough USDC;
- The private key is used only for local signing; keep it secure and avoid exposing it in browsers or untrusted environments.

### 3. Create a Platform Token

The Platform Token is used to call platform APIs, similar to the user token used after login in the browser but does not expire. Follow these steps to create one:

1. Open the console page [https://platform.acedata.cloud/console/platform-tokens](https://platform.acedata.cloud/console/platform-tokens);
2. Click "Create Token" and fill in the remarks as prompted to generate it;
3. Copy the generated token (e.g., `platform-v1-xxxx`) and save it securely as `platform_token`.

![platform-token](https://cdn.acedata.cloud/6g86oz.png)

All subsequent API calls must include the header:

```
Authorization: Bearer {platform_token}
```

### 4. Request basic information

- API base domain: `https://platform.acedata.cloud`
- Payment request path: `/api/v1/orders/{order_id}/pay/`
- Requests and responses use JSON encoded in UTF-8.

## 2. Payment Process Overview

1. **Initiate payment request**: The first `POST` request without the `X-PAYMENT` header triggers a 402 Payment Required response from the platform;
2. **Read payment requirements**: Parse the `accepts` array in the 402 response, confirm `network` is `base`, `asset` is USDC, and `payTo` matches the order page;
3. **Generate `X-PAYMENT`**: Use the payment wallet private key, the requirements from the response body, and the EIP-712 domain returned by the Facilitator to generate the signature (usually done via the official SDK);
4. **Retry with signature**: Add the `X-PAYMENT` header to the same path request; the platform returns 200 upon successful verification;
5. **Parse results**: Read the `X-PAYMENT-RESPONSE` header from the response to obtain on-chain transaction hash, actual deducted amount, etc., for reconciliation.

## 3. Interaction Examples

### 1. Initial request (triggering 402)

```http
POST https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/
Authorization: Bearer {platform_token}
Content-Type: application/json

{
  "pay_way": "X402"
}
```

Typical 402 response (field order may vary):

```json
{
  "error": "Payment required for this order.",
  "accepts": [
    {
      "scheme": "exact",
      "network": "base",
      "asset": "0x833589fcd6edb6e08f4c7c32d4f71b54b268aa0e",
      "maxAmountRequired": "1250000",
      "payTo": "0x302afdd980aaefca3afa8df7222a6002774f6724",
      "extra": {
        "eip712": { "...": "..." }
      }
    }
  ],
  "paywall": { ... }
}
```

Key field explanations:

- `network`: must be `base` (Base mainnet);
- `asset`: Base USDC contract address (example is the official mainnet contract);
- `maxAmountRequired`: required USDC atomic units for this payment (1 USDC = 1,000,000 atomic units);
- `payTo`: platform payment address, should match the order detail page;
- `extra`: EIP-712 domain info and others needed for signing.

### 2. Generate `X-PAYMENT`

Common practice is to use the official SDKs (e.g., `x402-js`, `x402-fetch`, `x402.clients`):

1. Convert the payment wallet private key to an account object;
2. Record the `accepts` data from the 402 response and select the payment option where `network == "base"`;
3. Call the SDK's signing function to generate a Base64-encoded `X-PAYMENT` string (no direct client connection to the facilitator is needed; the platform backend handles facilitator calls for verify/settle);
4. It is recommended to verify if `maxAmountRequired` is within acceptable limits and prompt the user to top up if exceeded.

For manual implementation, refer to the official x402 documentation and construct the EIP-712 structure according to the `extra.eip712` domain info before signing.

### 3. Retry with signature

```http
POST https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/
Authorization: Bearer {platform_token}
Content-Type: application/json
X-PAYMENT: {base64_signed_payload}

{
  "pay_way": "X402"
}
```

If payment succeeds, the response status is 200, the response body returns updated order information, and includes:

```
X-PAYMENT-RESPONSE: eyJ0cmFuc2FjdGlvbiI6IjB4...==
```

`X-PAYMENT-RESPONSE` can be decoded using the SDK to obtain on-chain transaction hash, payment network, payer address, etc., for accounting or display.

## 4. Multi-language Example Code

The following examples assume environment variables or configuration injection:

- `ACE_PLATFORM_TOKEN`: Platform Token;
- `ACE_X402_ORDER_ID`: Order ID;
- `ACE_X402_PRIVATE_KEY`: Payment wallet private key (with `0x` prefix).

### 1. Axios (TypeScript)

```ts
import axios from "axios";
import { Hex } from "viem";
import { privateKeyToAccount } from "viem/accounts";
import { buildPaymentHeader, decodePaymentResponse } from "x402-js";

const baseURL = "https://platform.acedata.cloud";
const orderId = process.env.ACE_X402_ORDER_ID!;
const platformToken = process.env.ACE_PLATFORM_TOKEN!;
const privateKey = process.env.ACE_X402_PRIVATE_KEY as Hex;

const account = privateKeyToAccount(privateKey);
const api = axios.create({
  baseURL,
  headers: {
    Authorization: `Bearer ${platformToken}`,
    "Content-Type": "application/json",
  },
});

async function payOrder() {
  const payPath = `/api/v1/orders/${orderId}/pay/`;

  const initial = await api.post(
    payPath,
    { pay_way: "X402" },
    { validateStatus: () => true }
  );
  if (initial.status !== 402) {
    throw new Error(`unexpected status ${initial.status}`);
  }

  const requirement = initial.data.accepts.find(
    (item: any) => item.network === "base"
  );
  if (!requirement) {
    throw new Error("no base requirement returned");
  }

  const paymentHeader = await buildPaymentHeader({
    account,
    requirement,
  });

  const final = await api.post(
    payPath,
    { pay_way: "X402" },
    { headers: { "X-PAYMENT": paymentHeader } }
  );

  if (final.status >= 400) {
    throw new Error(`x402 payment failed: ${final.status} ${final.statusText}`);
  }
  const receipt = decodePaymentResponse(final.headers["x-payment-response"]);
  console.log("x402 receipt", receipt);
}

payOrder().catch(console.error);
```

### 2. Fetch (JavaScript)

```ts
import { wrapFetchWithPayment, decodePaymentResponse } from "x402-fetch";
import { privateKeyToAccount } from "viem/accounts";

const account = privateKeyToAccount(process.env.ACE_X402_PRIVATE_KEY!);
const platformToken = process.env.ACE_PLATFORM_TOKEN!;
const orderId = process.env.ACE_X402_ORDER_ID!;
const fetchWithPayment = wrapFetchWithPayment(fetch, account);

async function payOrder() {
  const url = `https://platform.acedata.cloud/api/v1/orders/${orderId}/pay/`;

  const response = await fetchWithPayment(url, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      Authorization: `Bearer ${platformToken}`,
    },
    body: JSON.stringify({ pay_way: "X402" }),
  });

  if (!response.ok) {
    const errorBody = await response.text();
    throw new Error(`x402 payment failed: ${response.status} ${errorBody}`);
  }

  const receipt = decodePaymentResponse(
    response.headers.get("x-payment-response")!
  );
  console.log("x402 receipt", receipt);
}

payOrder().catch(console.error);
```

### 3. Python requests

```python
import os
from eth_account import Account
from x402.clients.requests import x402_requests
from x402.clients.base import decode_x_payment_response

order_id = os.environ["ACE_X402_ORDER_ID"]
platform_token = os.environ["ACE_PLATFORM_TOKEN"]
account = Account.from_key(os.environ["ACE_X402_PRIVATE_KEY"])

session = x402_requests(
    account,
    payment_requirements_selector=lambda accepts, **_: next(
        req for req in accepts if req.network == "base" and req.scheme == "exact"
    ),
)

response = session.post(
    f"https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/",
    json={"pay_way": "X402"},
    headers={"Authorization": f"Bearer {platform_token}"},
)

response.raise_for_status()
receipt_header = response.headers.get("X-PAYMENT-RESPONSE")
if receipt_header:
    print("x402 receipt:", decode_x_payment_response(receipt_header))
```

### 4. Python httpx (async)

```python
import asyncio
import os
from eth_account import Account
from x402.clients.httpx import x402HttpxClient
from x402.clients.base import decode_x_payment_response

async def pay_order() -> None:
    order_id = os.environ["ACE_X402_ORDER_ID"]
    platform_token = os.environ["ACE_PLATFORM_TOKEN"]
    account = Account.from_key(os.environ["ACE_X402_PRIVATE_KEY"])

    async with x402HttpxClient(
        account=account,
        base_url="https://platform.acedata.cloud",
        headers={"Authorization": f"Bearer {platform_token}"},
        payment_requirements_selector=lambda accepts, **_: next(
            req for req in accepts if req.network == "base"
        ),
    ) as client:
        response = await client.post(
            f"/api/v1/orders/{order_id}/pay/",
            json={"pay_way": "X402"},
        )
        response.raise_for_status()
        receipt_header = response.headers.get("X-PAYMENT-RESPONSE")
        if receipt_header:
            print("x402 receipt:", decode_x_payment_response(receipt_header))

asyncio.run(pay_order())
```

> The examples demonstrate key calls only. In production, please add error handling, retry strategies, logging, and security controls.

## 5. Verification After Successful Payment

- **Console verification**: Visit the order detail page `https://platform.acedata.cloud/console/orders/{order_id}`. If the page shows "Payment Successful" or the order status changes to Paid/Completed, the on-chain settlement is complete.
- **API verification**: Call `GET https://platform.acedata.cloud/api/v1/orders/{order_id}/` with `Authorization: Bearer {platform_token}` and check the `state` field in the response (`PAID` or `FINISHED` indicates successful payment).
- **Response header**: Read the `X-PAYMENT-RESPONSE` header in the successful payment response to parse the on-chain transaction hash as final proof; it is recommended to save this information in system logs for reconciliation.

## 6. Common Troubleshooting

- **Still returning 402**: Confirm the payment address has sufficient USDC on Base mainnet; check if `maxAmountRequired` exceeds wallet balance or custom limits.
- **Signature failure**: Ensure the private key includes the `0x` prefix; strictly use the `extra` (EIP-712 domain) and `payTo` from the response without altering field order during signing.
- **Network mismatch**: Multiple requirements may exist in `accepts`; select the option where `network === "base"`.
- **Missing `X-PAYMENT-RESPONSE`**: Indicates no actual deduction occurred; retry based on error in response body; if on-chain congestion occurs, try again later.
- **Invalid Platform Token**: Confirm the token is not deleted and starts with `platform-v1-`; if the API returns 401, regenerate the token in the console.
