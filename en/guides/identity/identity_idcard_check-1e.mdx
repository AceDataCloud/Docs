This document introduces the ID Card Portrait Photo Verification API integration guide. It can be used to input the portrait side photo of an ID card, recognize the information on the ID card photo, and compare the name, ID number, and ID card portrait photo with the official database’s ID photo to determine whether they belong to the same person, thereby verifying the authenticity of the ID card information.

## Application Process

To use the API, you need to first apply for the corresponding service on the [ID Card Portrait Photo Verification API](https://platform.acedata.cloud/documents/7a3f14f7-f1eb-41c2-816c-9f18caca6883) page. After entering the page, click the "Acquire" button as shown below:

![](https://cdn.acedata.cloud/q6ytrc.png)

If you are not logged in or registered, you will be automatically redirected to the login page to register and log in. After logging in or registering, you will be automatically returned to the current page.

A free quota will be granted upon the first application, allowing you to use the API for free.

## Basic Usage

First, understand the basic usage method: input the ID card image URL to obtain the processed verification result. You need to simply pass an `image_url` field. You can then fill in the corresponding content on the interface as shown below:

<p><img src="https://cdn.acedata.cloud/zjxg3k.png" width="500" className="m-auto" /></p>

Here, we set the Request Headers, including:

- `accept`: The desired response format, here set to `application/json`, i.e., JSON format.
- `authorization`: The API key for calling the API, which can be selected from a dropdown after application.

Additionally, the Request Body is set, including:

- `image_url`: The URL of the ID card image to be processed.
- `config`: Optional configuration fields, boolean values defaulting to false, supporting `copy_warn`, `border_check_warn`, `reshoot_warn`, `detect_ps_warn`, `temp_id_warn`, `quality` (threshold 0-100).

After selection, the corresponding code is generated on the right side, as shown below:

<p><img src="https://cdn.acedata.cloud/4yh23p.png" width="500" className="m-auto" /></p>

Click the "Try" button to test. As shown above, the following result is obtained:

```json
{
  "sim": 99.76,
  "result": "Success",
  "description": "成功",
  "name": "身份证姓名",
  "sex": "身份证性别",
  "nation": "身份证民族",
  "birth": "身份证生日",

  "warnings": "",
  "quality": 0,
  "encryption": null

```

The returned result contains multiple fields, described as follows:

- `sim`: Similarity score, range [0.00, 100.00]. It is recommended to consider similarity ≥ 70 as the same person; you can adjust the threshold according to your specific scenario (threshold 70 has a false acceptance rate of 0.1%, threshold 80 has a false acceptance rate of 0.01%).
- `result`: Business error code, returns "Success" on success; for errors, please refer to the FailedOperation section in the error code list below.
- `description`: The verification result of the name and ID number.
- `name`: Name information from the ID card; empty if no ID card image was uploaded.
- `sex`: Gender information from the ID card; empty if no ID card image was uploaded.
- `nation`: Ethnicity information from the ID card; empty if no ID card image was uploaded.
- `birth`: Birthdate information from the ID card; empty if no ID card image was uploaded.
- `address`: Home address information from the ID card; empty if no ID card image was uploaded.
- `id_num`: ID number information from the ID card; empty if no ID card image was uploaded.
- `portrait`: Base64 encoding of the ID card portrait photo; if cropping fails, the entire ID card image will be used for comparison and this field will be empty.
- `warnings`: Warning information; if warnings are configured in Config, portrait comparison will stop, Result will return an error (FailedOperation.OcrWarningOccurred), and this warning information will be provided.
- `quality`: Image quality score, meaningful only if image blur warning is configured in Config; range (0–100), default threshold is 50, below which a blur warning is triggered.
- `encryption`: Sensitive data encryption information.

It can be seen that the ID card information has a high degree of authenticity.

Additionally, if you want to generate the corresponding integration code, you can directly copy the generated code. For example, the CURL code is as follows:

```shell
curl -X POST 'https://api.acedata.cloud/identity/idcard/check-1e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": {image_url}
}'
```

The Python integration code is as follows:

```python
import requests

url = "https://api.acedata.cloud/identity/idcard/check-1e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "image_url": {image_url}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Error Handling

When calling the API, if an error occurs, the API will return the corresponding error code and message. For example:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.
