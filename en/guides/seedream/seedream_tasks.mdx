The main function of the SeeDream Tasks API is to query the execution status of a task by inputting the task ID generated by the SeeDream Images Generation API.

This document provides a detailed guide on integrating the SeeDream Tasks API, helping you easily integrate and fully utilize the powerful features of this API. With the SeeDream Tasks API, you can effortlessly query the execution status of tasks from the SeeDream Images Generation API.

## Application Process
To use the SeeDream Tasks API, you first need to apply for the corresponding service on the application page [SeeDream Images Generation API](https://platform.acedata.cloud/documents/seedream-images), then copy the task ID from the SeeDream Images Generation API, as shown below:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Finally, go to the Tasks API page [SeeDream Tasks API](https://platform.acedata.cloud/documents/seedream-tasks) to apply for the corresponding service. After entering the page, click the "Acquire" button, as shown below:

![Application Page](https://cdn.acedata.cloud/rci31i.png)

If you are not logged in or registered, you will be automatically redirected to the [login page](https://platform.acedata.cloud) to register and log in. After logging in or registering, you will be automatically returned to the current page.

There is a free quota granted for the first application, allowing you to use the API for free.

## Request Example
The SeeDream Tasks API can be used to query the results of the SeeDream Images Generation API. For how to use the SeeDream Images Generation API, please refer to the documentation [SeeDream Images Generation API](https://platform.acedata.cloud/documents/seedream-images-integration).

We take a task ID returned by the SeeDream Images Generation API service as an example to demonstrate how to use this API. Suppose we have a task ID: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, and next we demonstrate how to query by passing in a task ID.

### Setting Request Headers and Body

**Request Headers** include:

- `accept`: Specifies to receive the response in JSON format, set as `application/json`.
- `authorization`: The API key for calling the API, which can be selected from the dropdown after application.

**Request Body** includes:

- `id`: The uploaded task ID.
- `action`: The operation type on the task.

Set as shown below:

<p><img src="https://cdn.acedata.cloud/yuyte9.png" width="500" className="m-auto" /></p>

### Code Example

On the right side of the page, code snippets in various languages are automatically generated, as shown below:

<p><img src="https://cdn.acedata.cloud/b0wt0d.png" width="500" className="m-auto" /></p>

Partial code example:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/seedream/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "a6e0d456-189b-4c78-9232-2fe72166ab39",
  "action": "retrieve"
}'
```

### Response Example

Upon a successful request, the API will return the detailed information of the task. For example:

```json
{
  "success": true,
  "task_id": "84d1544a-9043-4dde-a98b-e889dacd75f6",
  "trace_id": "176acf03-7ca7-4fc6-85db-e3724d4f59eb",
  "data": [
    {
      "prompt": "a white siamese cat",
      "size": "2048x2048",
      "image_url": "https://platform.cdn.acedata.cloud/seedream/6e5f9085-cc4a-4801-b77b-31550129ff19.jpg"
    }
  ]
}
```

The response contains multiple fields, described as follows:
- `success`: The status of the image generation task.
- `task_id`: The ID of the image generation task.
- `trace_id`: The trace ID for tracking the image generation.
- `data`: The list of results for the image generation task.
  - `image_url`: The URL of the generated image.
  - `prompt`: The prompt used.
  - `size`: The pixel size of the generated image.

## Batch Query Operation

This is for querying details of multiple task IDs. Unlike the above, the `action` should be set to `retrieve_batch`.

**Request Body** includes:

- `ids`: An array of uploaded task IDs.
- `action`: The operation type on the tasks.

Set as shown below:

<p><img src="https://cdn.acedata.cloud/ycc4th.png" width="500" className="m-auto" /></p>

### Code Example

Partial code example:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/seedance/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["84d1544a-9043-4dde-a98b-e889dacd75f6","84d1544a-9043-4dde-a98b-e889dacd75f6"],
  "action": "retrieve_batch"

```

## Error Handling

When calling the API, if an error occurs, the API will return the corresponding error code and message. For example:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.

### Error Response Example
