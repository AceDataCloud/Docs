Use `POST /acemusic/tasks` to retrieve song and lyrics tasks. Queries are free and require valid credentials plus API access. A zero balance does not prevent reading your own results. Supplying another user ID does not grant access to their work.

## Retrieve a task

```bash
curl --request POST 'https://api.acedata.cloud/acemusic/tasks' \
  --header 'Authorization: Bearer YOUR_API_KEY' \
  --header 'Content-Type: application/json' \
  --data '{"action":"retrieve","id":"YOUR_TASK_ID"}'
```

Use the platform `task_id` returned by generation. A task record contains state, public creation parameters, timing information and `response`. Final tracks are in `response.data`. A successful HTTP query is not proof of completed generation; inspect the task and individual track states.

## Batch retrieval and history

- Batch: `{"action":"retrieve_batch","ids":["TASK_ID_1","TASK_ID_2"]}`. At most 100 IDs.
- History: `{"action":"list","page":1,"page_size":20}`. Pages start at 1; at most 100 records per page.
- Both return an `items` array and `count`. Items follow the single-task format.

## State and recovery

Tasks progress through queueing, generation and delivery. A complete group has two downloadable tracks. A final partial failure uses `partial_failed` and preserves successful audio. Public errors include diagnostic codes; retain the platform task and trace IDs for support.

Poll every few seconds with increasing backoff, then stop at a final state. Continue querying the original task after a refresh or disconnection. Recovery does not automatically create a new paid generation. Uncertain acceptance may require investigation and is not permission to resubmit.

Play completed tracks using their `audio_url`. The actual returned file determines its format. A missing cover does not prevent playback; a track without an audio URL has not been delivered.
