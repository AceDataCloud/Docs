Kimi is a series of AI models launched by Moonshot AI. The currently recommended model is `kimi-k3.1-pro`, which is suitable for long-horizon programming, complex reasoning, visual understanding, and knowledge work; `kimi-k3` is still available. It is accessed through the OpenAI-compatible Chat Completions API.

This document mainly introduces the usage process for the Kimi Chat Completion API. With it, we can easily use the official Kimi conversational capabilities.

## Supported Models

Currently, four models are supported: `kimi-k3.1-pro`, `kimi-k3`, `kimi-k2.6`, and `kimi-k2.7-code`. K2.7 Code is designed for programming and tool-calling scenarios and is billed at the same price tier as K2.6; do not pass the `thinking` switch or `reasoning_effort` in requests to it. Other Kimi models are no longer supported. Please explicitly select one of these four models in your client.

To use the Kimi Chat Completion API, first go to the [Ace Data Cloud Console](https://platform.acedata.cloud/console/applications) to obtain your API Token and keep it for later use.

As you can see, the `content` field inside `choices` contains the specific content of Kimi's reply; K3 may also return `reasoning_content`, which represents the reasoning process.

## K3.1 Pro Reasoning Effort

`kimi-k3.1-pro` always has reasoning enabled. You can set `reasoning_effort` to `low`, `high`, or `max` at the top level of the request body; do not pass a configuration that disables reasoning. The model supports a context window of up to 1,048,576 tokens, but the actual request limit is still subject to the current API. Pricing is calculated based on input, output, and cache-hit usage. For details, see the Pricing card in the model catalog.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

The following K3 example is retained for existing integrations, and the example response was indeed obtained through a K3 request.

## K3 Reasoning Effort

`kimi-k3` always has reasoning enabled. The `reasoning_effort` field is supported at the top level of the request body, and the only currently supported value is `max`; omitting this field also uses `max`. Please use the supported value.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

When using the OpenAI SDK, you can pass this field directly:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

For multi-turn conversations and tool calls, please pass the complete assistant message from the previous turn back into `messages`, including `reasoning_content` and `tool_calls`.

## Streaming Responses

This interface also supports streaming responses, which is very useful for web integration and allows web pages to implement a character-by-character display effect.

If you want to return responses in a streaming manner, you can change the `stream ` parameter in the request header to `true`.

Make the modification as shown in the figure. However, the invocation code also needs corresponding changes to support streaming responses.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>
After changing `stream` to `true`, the API will return the corresponding JSON data line by line. At the code level, we need to make corresponding modifications to obtain the results line by line.

Python sample request code:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Below are excerpts from the beginning, reasoning, content, ending, and usage data blocks of an actual K3 Max streaming response from the same request:

```json

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

As you can see, there are many `data` entries in the response. The `choices` inside `data` represent the latest response content, consistent with the content introduced above. `choices` contains the newly generated response content, which you can integrate into your system based on the results. Meanwhile, the end of the streaming response is determined by the content of `data`. If the content is `[DONE]`, it indicates that the streaming response has completely finished. The returned `data` contains multiple fields, which are described below:

- `id`: The ID generated for this conversation task, used to uniquely identify the task.
- `model `: The Kimi official website model selected.
- `choices`: The response information provided by Kimi to the prompt.

JavaScript is also supported. For example, the streaming request code for Node.js is as follows:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Java sample code:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Other languages can be adapted independently. The underlying principle is the same.

## Multi-turn Conversations

If you want to integrate multi-turn conversation functionality, you need to upload multiple prompts in the `messages` field. A specific example of multiple prompts is shown in the image below:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Python sample request code:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

By uploading multiple prompts, you can easily implement multi-turn conversations. The following is the actual K3 Max response obtained from this request (unused extended fields have been omitted):


As you can see, the information contained in `choices` is consistent with that in basic usage. It contains the specific responses provided by Kimi to multiple conversation turns, allowing you to answer the corresponding questions based on the content of multiple conversations.

## Error Handling

When calling the API, if an error occurs, the API will return the corresponding error code and message. For example:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.
