## Basic Usage

For whatever kind of song you want, you can enter any piece of text. For example, if I want to generate a song about Christmas, I can enter `a song for Christmas`, as shown below:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

You can see that we have set the Request Headers here, including:

- `accept`: The format of the response result you want to receive. Here it is set to `application/json`, which is JSON format.
- `authorization`: The key for calling the API. After applying, you can directly select it from the dropdown.

Additionally, the Request Body is set, including:
- `action`: Audio task type; defaults to `generate`. Supports operations such as generation, extension, cover, mashup, stem separation, adding audio tracks, extracting specified audio tracks, generating sound effects, and adjusting speed, all invoked through `POST /suno/audios`.
- `prompt`: Suno's official inspiration mode prompt (effective when `custom` is `false`), with a maximum of 500 characters.
- `model`: The model for this music generation task. The v6 series includes `chirp-v6`, `chirp-v6-wild`, and `chirp-v6-mini`; legacy model names remain compatible.
- `max_mode`: Enhanced generation mode. `generate` is enabled only when both `custom` and `max_mode` are `true`, costing 1.12 Credits; `add_stem` can be enabled directly, costing 1.344 Credits. When disabled or omitted, the costs are 0.56 and 0.672 Credits respectively.
- `variety`: The diversity intensity of generated results; options are `off`, `normal`, `high`, `extra`, and `max`. Only used for `generate` and `add_stem`; passing it to other actions returns 400.
- `lyric`: Lyrics content for Suno's official custom mode. Maximum 3000 characters for `chirp-v3-5` and `chirp-v4`; maximum 5000 characters for `chirp-v4-5` and above (including `chirp-v5` and `chirp-v5-5`).
- `custom`: Whether to use custom mode; defaults to: `false`.
- `instrumental`: The instrumental music option for Suno's official inspiration mode.
- `title`: Music title for Suno's official custom mode. Maximum 80 characters for `chirp-v3-5` and `chirp-v4`; maximum 100 characters for `chirp-v4-5` and above.
- `style`: Music style for Suno's official custom mode. Maximum 200 characters for `chirp-v3-5` and `chirp-v4`; maximum 1000 characters for `chirp-v4-5` and above (including `chirp-v5` and `chirp-v5-5`).
- `negative_tags`: Music styles or genres to exclude during custom generation; can also be used for `replace_section`. This API currently has no fixed character limit for this field; overly long content may still be unprocessable, so it is recommended to keep descriptions concise.
- `audio_weight`: The influence weight of audio or voice characteristics, ranging from 0 to 1; `0` is also a valid value. It can be used for operations such as generation, extension, cover, adding audio tracks, and voice consistency; when there is no reference audio or voice characteristic, the model may weaken or ignore this value.
- `audio_id`: The ID of reference music, used for subsequent operations such as cover, extension, and stem separation. Audio files can still be downloaded, but this does not mean subsequent processing for that ID is always available; if `suno_processing_unavailable` is returned, retain the `task_id` and `trace_id` and contact support.
- `overpainting_start`/`overpainting_end`: The start and end times for adding vocals to existing instrumental music, in seconds.
- `underpainting_start`/`underpainting_end`: The start and end times for adding accompaniment to a cappella vocals, in seconds.
- `persona_id`: The voice ID obtained through the Persona or voice creation API, not the song's `audio_id`.
- `continue_at`: The extension boundary, in seconds. For example, 213.5 means generating the subsequent segment starting at 3 minutes and 33.5 seconds. `lyric` and `style` only guide new content after the boundary and will not replace lyrics or singing before the boundary in the source audio.
- `style_influence`: Style influence in custom mode, ranging from 0 to 1; larger values usually adhere more closely to the selected style; `0` is passed as a valid value.
- `replace_section_end`: The final time of the replacement segment.
- `replace_section_start`: The start time of the replacement segment.
- `vocal_gender`: Controls the preference for female or male vocals: female vocals `f`, male vocals `m`; effective for models 4.5 and above; it is a preference setting and is not guaranteed to be strictly followed.
- `weirdness`: Weirdness in custom mode, ranging from 0 to 1; larger values are usually more creative and experimental; `0` is passed as a valid value.
- `duration`: The desired song duration, in seconds; must be an integer, ranging from 10 to 360. Currently, only `generate` uses this parameter, and the specific effect depends on the mode and model. It is a preference prompt rather than a hard constraint: the model will refer to it but is not guaranteed to achieve it. The actual finished duration is subject to the `duration` field in the response and is usually shorter than the desired value.

### Scope of Voice ID Usage

`generate`, `cover`, `upload_cover`, `artist_consistency`, and `artist_consistency_vox` can use `persona_id`. The latter two actions must provide `persona_id`; they can also provide the `audio_id` of the song used when creating that Persona.

`extend` and `upload_extend` do not use an additional `persona_id`. Whether `mashup` and `inspo` support voice IDs depends on the selected service channel; other actions are not guaranteed to apply this field, so use it according to the instructions for each operation. `vocal_gender` is an optional gender preference and cannot replace a voice ID.

Subsequent creation operations require a valid source `audio_id`; `mashup` requires at least two `mashup_audio_ids`. HTTP 400 is returned when required sources or time parameters are missing.

### Scope of Advanced Parameters
| Parameter                | Value                                          | Supported action                              | Description                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | Optional                                      | Adjusts experimentalism; `0` is a valid value; the effect depends on the action, mode, and model      |
| `style_influence` | 0-1                                         | Optional                                      | Adjusts the tendency to follow style; `0` is a valid value; the effect depends on the action, mode, and model   |
| `audio_weight`    | 0-1                                         | Optional                                      | Adjusts the influence of audio or vocal characteristics; may be ignored by the model when no reference information is available        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`, `add_stem`                   | Adjusts style diversity between results                       |
| `max_mode`        | boolean                                     | `generate` (requires `custom=true`), `add_stem` | Enhances consistency and is billed according to enhanced mode                     |
| `vocal_gender`    | `f` / `m`                                   | Generation actions that support vocal control                             | Preference setting, strict adherence is not guaranteed                       |
| `duration`        | Integer 10-360                                   | `generate`                              | Expected duration; other actions do not currently use this field, and the actual length is subject to the result |

The platform validates parameter types and value ranges, but will not reject these optional adjustment fields solely because the action differs; the specific effect depends on the action, mode, and model.

- `lyric_prompt`: The prompt for generating lyrics, which takes effect if and only if `custom` is `true` and `lyric` is not provided.
- `callback_url`: The URL for receiving callback results.
- `async`: Optional. When set to `true`, the API immediately returns a `task_id`; there is no need to provide `callback_url`, and the result can then be obtained by polling through the corresponding task query API.

## Continue Generation Feature
If you want to continue generating an already generated Suno song, you can set the parameter `action` to `extend`, and enter the ID of the song that needs to be continued. The song ID is obtained according to the basic usage. As can be seen above, at this point you can see that the song ID is:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Note that the `id` in the lyrics here is the ID of the generated song. If you do not know how to generate a song, you can refer to the basic usage above to generate a song.

If you want to continue generating a song you uploaded yourself, you can set the parameter `action` to `upload_extend`, and enter the ID of the custom uploaded song that needs to be continued. The song ID is obtained using the [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), as shown below:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Next, you must fill in the lyrics for the continuation segment, and you can specify the style:

- lyric: Only used to guide the lyrics of the newly generated segment after `continue_at`; it will not replace the lyrics before this time point in the source audio.
- custom: Set to `true`, indicating custom generation. This parameter defaults to false, indicating generation using `prompt`.
- style: The song style of the continuation segment, optional.
- continue_at: The continuation boundary, in seconds. For example, 213.5 indicates that the subsequent segment starts being generated from 3 minutes and 33.5 seconds.

The `continue_at` for both `extend` and `upload_extend` must be greater than 0 and supports fractional seconds, for example, `30.792`; it will not be rounded when submitted.

> `extend` is used to continue creating after an existing song, not to replace the lyrics of the entire song. If you want to use new lyrics for the entire song from the beginning, please use `generate` to generate it again; if you want to reinterpret an existing song as a reference, you can use `cover`. When passing in an entire set of new lyrics, the original lyrics before `continue_at` will still not be replaced.

## Music Cover

After continuing to generate a song based on an existing song, the style of the returned song may not be quite suitable. If you want to create a cover version of a previously generated song (custom uploaded music is also supported), you need to use the music cover method, where you can specify the following content:

- action: The content is `cover`; when performing a cover operation on custom uploaded music, the content must be specified as: `upload_cover`.
- audio_id: The ID of the previously generated song.

If you need to use a specified voice for the cover, you can also pass `persona_id`. A private voice created through `/suno/voices` must first be used to upload the original song in `/suno/upload` with the same `persona_id`, and then the returned `audio_id` must be used for `upload_cover`. The same service channel must be used for all steps. There is no need to additionally specify `vocal_gender`; gender preference cannot replace a voice ID.

For example, if the previously generated song ID is: 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, then the parameters can be set as follows:

```json
{
  "action": "cover",
  "audio_id": "0a1e1b10-c36a-41c9-9bfb-b26d9d25db98",
  "prompt": "A song for Christmas",
  "model": "chirp-v4-5"
}
```

## Replace Segment

When secondary creation requires a separate operation to replace a song segment after generating a song, you can replace a certain segment of the song.
> ⚠️ **Note**: `replace_section_result_mode` defaults to `full_song`: the system will separately concatenate 2 newly generated candidates and return 2 complete songs. If only the un-concatenated replacement segment candidates are needed, explicitly set it to `candidates`, then select a candidate and call [Music Concatenation](#Music Concatenation).

The parameter descriptions are as follows:

- action: The content is `replace_section`.
- audio_id: The ID of the original song (the source song being replaced).
- model: Song generation model.
- lyric: The complete lyrics after replacement (including the replaced section and its context, consistent with the content in `prompt`).
- prompt: The new lyrics for the section that needs to be replaced.
- style: The style of the song, optional.
- negative_tags: Styles or genres to exclude, optional.
- replace_section_start: The start time of the replaced segment in the original song (seconds), required and must not be less than 0.
- replace_section_end: The end time of the replaced segment in the original song (seconds), required and must be greater than the start time.
- replace_section_result_mode: Return mode, defaults to `full_song`. `full_song` separately concatenates 2 candidates and returns 2 complete songs; `candidates` returns 2 un-concatenated candidate segments.

For example, if the original generated song ID is: 18db7ed0-2b8a-41db-91c1-b0781dcca0d4 (duration 94.12 seconds), and you want to replace the chorus from the 30th second to the 60th second with new lyrics, then you can set the parameters as follows:

```json
{
  "action": "replace_section",
  "audio_id": "18db7ed0-2b8a-41db-91c1-b0781dcca0d4",
```

## Add Stem

- Required: `action`, `audio_id`, `stem_type`.

## Extract Stem

`extract_stem` extracts the target stem from the specified audio while also returning a complementary version with that stem removed, called via `POST /suno/audios`.

- Required: `action`, `audio_id`, `stem_type`.
- Optional: `audio_format`; the current public dual-channel contract supports only `mp3`.
- Billing: 1.12 Credits.

```json
{
  "action": "extract_stem",

  "stem_type": "bass",
  "audio_format": "mp3",
  "async": true
}
```

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v4-5",
    "lyric": "Hello Hello Hello ",
    "custom": True,
    "weirdness": 0.4,
    "style_influence": 0.4,
    "audio_weight": 0.4
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Control Song Duration

By default, the duration of a generated song is determined by the model itself, usually between 30 seconds and 4 minutes. If a longer or shorter finished product is needed, you can specify the desired duration through the `duration` parameter, in seconds, with an integer value between 10 and 360.

This parameter is used for song generation in custom mode (where `custom` is `true`). It should be particularly noted that `duration` is a **preference prompt, not a hard constraint**: the model will refer to this value when creating, but it does not guarantee that it will be achieved. In actual testing, the actual duration is usually significantly shorter than the desired value, and the durations of the two songs returned by the same request may also differ by several times. Even for exactly the same request, the durations obtained from multiple submissions may vary greatly. Therefore, do not use it as precise duration control. If a fixed duration is required for business purposes, please trim it yourself or retry after obtaining the finished product.

The corresponding Python code:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

It should be noted that the `duration` in the request is the **desired duration**, while the `duration` field for each song in the response `data` is the **actual duration** of that song. They have the same name but different meanings, and the actual duration is not guaranteed to equal the desired value. Lyric length is one of the main factors affecting the duration of the finished product. If a longer finished product is needed, it is recommended to also provide more complete lyrics.

The API will validate that `duration` must be an integer between 10 and 360; it is still only a generation target, not a guarantee of the finished product's length.

## Inspo Inspiration Creation Feature

The Inspo inspiration creation feature can generate new music based on 1 to 4 complete reference audio clips, supporting dragging or uploading audio as an inspiration source. The API uses the existing `inspo` action: the client provides publicly accessible audio URLs, and the service automatically completes reference audio preparation and creation, without requiring the client to separately read lyrics, style, or duration before assembling the request. It differs from the interval sampling above, and also differs from Cover, which replicates the original song's style. The following parameters need to be filled in when using it:

- action: The content is `inspo`.
- audio_urls: A list of URLs for reference audio, requiring 1 to 4 publicly accessible audio addresses.
- model: The model used; `chirp-v6` is recommended.
- prompt: Lyrics or creation prompt (optional).
- instrumental: When set to `true`, it generates according to an instrumental music request and does not use lyrics.
- persona_id: Use the specified voice on service channels that support this combination; the reference audio will be bound during the preparation stage to the resource environment required by that voice.
- lyric_prompt: Used to automatically generate lyrics when `custom=true` and no `lyric` is provided.

> Note: Reference audio must be publicly accessible audio files. If the reference audio exactly matches a known recording in the platform's music library, Suno may reject generation due to copyright verification. It is recommended to use audio you own or audio generated by Suno as the inspiration source.

The corresponding Python code:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynchronous Callback

Since Suno takes a relatively long time to generate music, approximately 1–2 minutes, if the API remains unresponsive for a long time, the HTTP request will keep the connection open, resulting in additional system resource consumption. Therefore, this API also provides support for asynchronous callbacks.

The overall process is: when the client initiates a request, it additionally specifies a `callback_url` field. After the client initiates the API request, the API immediately returns a result containing a `task_id` field, representing the current task ID. When the task is completed, the result of the generated music will be sent in POST JSON format to the `callback_url` specified by the client, which also includes the `task_id` field, so that task results can be associated through the ID.

Below, we will use an example to understand how to operate specifically.
