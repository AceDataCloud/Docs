`POST https://api.acedata.cloud/suno/projects` is a Beta API for managing multi-track projects. A single endpoint distinguishes between creating, saving, generating candidates, committing candidates, and exporting through `action`. Callers only need to use the public fields below and do not need to fill in the internal request structure of the underlying generation service.

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: Use a new UUID for each modification operation
```

Except for `retrieve`, **every operation requires** `Idempotency-Key`. The same key with the same request only returns the original result; the same key with a different request returns 409. When paid generation encounters a network timeout or uncertain submission result, first query using the original task ID or the same idempotency key; do not directly resend with a different key.

## First distinguish these IDs and time units

| Name                           | Where to obtain it                                                                         | Where to use it                                      |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ---------------------------------------------------- |
| `id`                           | `data.id` in the `create` response                                                         | All subsequent requests for the current project      |
| `version_id`                   | `data.version_id` from the most recent `retrieve`, `save`, `add_track`, `commit_candidate`, or `remove_track` | Modifications, generating candidates, and exporting; the latest version must be used |
| `audio_id` / `source_audio_id` | `response.data.candidate.audio_id` when `upload` reaches its final state, or an existing completed audio ID | Reference original audio when `add_track`, generating, or replacing |
| `render_audio_id`              | `response.data.audio_id` when `render` reaches its final state                            | Project mix reference for `generate_track`           |
| `operation_id`                 | `response.data.operation_id` when `generate_track` or `replace_section` reaches its final state | `commit_candidate`; it is usually the same as the generation task's `task_id`, but the returned value should be read |
| `candidate_id`                 | `response.data.candidates[].id` when generation reaches its final state                   | Select a candidate to commit                         |
| `track_id`                     | `data.state.tracks[].id` of the project                                                   | Commit a candidate or delete a track                 |
| `task_id`                      | Asynchronous operation submission response                                                 | Query the final state using `/suno/tasks`; it is not a project ID |

`start_seconds` / `end_seconds` are **seconds within the source audio**; `start_beats` / `end_beats` are **beat counts on the project timeline**. `state.timing.bps` is beats per second, with a default of 2. For example, a 41-second clip starting at beat 0 has a default end at beat 82. The seconds range of `generate_track` is used to specify the generation reference and does not guarantee that the candidate only has the length of that range.

## Operation order and result determination

| Order | `action`                             | Purpose                                      | Return method                     |
| --- | ------------------------------------ | -------------------------------------------- | --------------------------------- |
| 1   | `create`                             | Create an empty project                      | Synchronous project data          |
| 2   | `retrieve`                           | Read the latest version and complete `state` | Synchronous project data          |
| 3   | `save`                               | Initial save or save the modified overall `state` | Synchronous project data      |
| 4   | `upload`                             | Create material from an HTTPS audio URL      | Asynchronous task                 |
| 5   | `add_track`                          | Put material audio into the project          | Asynchronous task, updates version |
| 6   | `save`                               | To receive new track candidates, first save an empty target track | Synchronous project data, updates version |
| 7   | `render`                             | Export currently audible tracks and obtain the mix reference `audio_id` | Asynchronous task |
| 8   | `generate_track` or `replace_section` | Generate new track candidates or partial replacement candidates respectively | Asynchronous task, does not modify the project yet |
| 9   | `commit_candidate`                   | Select and commit a candidate                | Asynchronous task, updates version after success |
| Optional | `remove_track`                   | Delete the specified track                   | Synchronous project data, updates version |

If only performing a partial replacement, existing usable source audio is sufficient and `render` is not required first; if the source audio is already in the project, `upload` and `add_track` can also be skipped. `render_audio_id` is only the required reference for `generate_track`.

When an asynchronous operation is submitted, it first returns `{ "task_id": "...", "trace_id": "..." }`, which **does not indicate successful generation**. Poll:

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"task_id returned in the previous step"}
```

A task is considered successful only when the task record has `finished_at` and its `response.success` is `true`; when `response.success=false`, read `response.error`. Although `save` may include `task_id`, it completes synchronously within this API. `upload`, `render`, `generate_track`, and `replace_section` do not modify the project version; after `save`, `add_track`, `commit_candidate`, and `remove_track` succeed, the new `version_id` should be obtained.

## Request parameters

### Common fields and request headers

| Parameter         | Type and applicable scope                                                                    | Description                                                     |
| ----------------- | -------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | Required string                                                                              | Fixed as one of the operation names listed on this page; one request executes only one operation. |
| `id`              | Required string except for `create`                                                          | Project ID, from `create.data.id`.                              |
| `version_id`      | Required string when modifying, generating candidates, or exporting; may be omitted for the first `save` of an empty project | Use the latest version; old versions will be rejected. `retrieve` does not require it. |
| `Idempotency-Key` | Required request header except for `retrieve`, 1–128 characters                              | Use a new key for each new operation; the same key and request returns the original result without regenerating or charging again. |
| `async`           | Optional boolean for `upload`, `add_track`, `generate_track`, `replace_section`, `commit_candidate`, and `render` | These operations are always asynchronous; `false` will not make generation synchronous. |
| `callback_url`    | Optional URL for the operations containing the optional asynchronous fields above             | Receives final-state notifications; when omitted, query `/suno/tasks` by `task_id`. `response.success` must still be checked. |

### Projects and materials
| `action`       | Specific Parameter          | Type and Conditions                    | Description                                                              |
| -------------- | --------------------------- | -------------------------------- | ------------------------------------------------------------------ |
| `create`       | `title`                     | Required string, 1–200 characters                   | New project title.                                                             |
| `retrieve`     | None                           | —                                | Only `action` and project `id` are required; returns the complete editable `state`.                              |
| `save`         | `state`                     | Required object                             | **Replaces the entire** project state, not a partial patch. Modify based on the most recent `retrieve.data.state` and submit it in full, preserving unknown fields. |
| `save`         | `title`                     | Optional string                            | Project title; when omitted, uses `state.title`, or the default title if that is also absent.                              |
| `upload`       | `audio_url`                 | Required HTTPS URL                     | Publicly accessible audio asset URL; after success, read the terminal `candidate.audio_id`. The caller should own the rights to use the asset.            |
| `add_track`    | `audio_id`                  | Required string                            | The audio ID of a completed asset, not a URL.                                                |
| `add_track`    | `name` / `color`            | Optional strings                            | New track name and color; the name defaults to the audio title, the recommended color is `#RRGGBB`, and the default is `#7251F7`.                    |
| `add_track`    | `title`                     | Optional string                            | Also modifies the project title; usually omitted.                                                     |
| `add_track`    | `start_beats` / `end_beats` | Optional non-negative numbers, `end_beats > start_beats` | The position of the clip on the project timeline. The start defaults to 0; the end defaults to `start + audio duration × timing.bps`.                  |
| `add_track`    | `gain`                      | Optional non-negative number, default 1                      | Volume coefficient for the clip and new track.                                                       |
| `remove_track` | `track_id`                  | Required string                            | The ID of the existing track to delete. Use the returned new version after success.                                           |

`state.timing.bps` must be a positive number, with a default of 2. `state.tracks` is the track array; the `clipId` of existing audio clips references an audio ID, and `startBeats`, `endBeats`, and `readStartBeats` use project beat units. The safest editing method is to retrieve the complete `state`, modify only the target track or clip, then `save` the entire state. A newly added empty target track should at minimum have a unique `id`, `type:"audio"`, and `clips:[]`; see step 5 below for the complete usable shape. Do not directly use beat points from audio analysis results as project timeline coordinates.

### Generation, Submission, and Export
| `action`                             | Specific Parameter                   | Type and Conditions                            | Description                                                                                                                                                        |
| ------------------------------------ | ---------------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generate_track` / `replace_section` | `source_audio_id`                  | Required string                                  | The completed source audio ID. First add the source audio to the project, so subsequent candidates can find the corresponding position.                                                                                                                        |
| `generate_track` / `replace_section` | `model`                            | Required enum string                                | Available options are `chirp-v3-5`, `chirp-v4`, `chirp-v4-5`, `chirp-v4-5-plus`, `chirp-v5`, `chirp-v5-5`, `chirp-v6`, `chirp-v6-wild`, `chirp-v6-mini`. Whether a model and operation are available is determined by the task terminal state; it will not automatically switch to another model. |
| `generate_track` / `replace_section` | `start_seconds` / `end_seconds`    | Required numbers, `0 ≤ start_seconds &lt; end_seconds` | Start and end seconds within the source audio; when replacing, the endpoint must also not exceed the actual duration of the source audio. They are not project beats, and do not guarantee the candidate output duration.                                                                                                         |
| `generate_track`                     | `render_audio_id`                  | Required string                                  | The `response.data.audio_id` after the current project is successfully `render`ed, used as the mix reference during generation.                                                                                                   |
| `generate_track`                     | `stem_control_tags`                | Required string                                  | Description of the new stem, for example `add Piano`, `add Drums`, `add Bass`; not a fixed enum.                                                                                                      |
| `generate_track`                     | `batch_size`                       | Optional integer 1–4, default 2                          | The number of candidates requested to generate.                                                                                                                                                |
| `generate_track`                     | `instrumental` / `vocal_gender`    | Optional boolean / enum string                            | `instrumental` defaults to `true`; vocal preference can be `f`, `m`, or `unspecified`, with a default of `unspecified`. Whether the preference is followed depends on the actual audio.                                                                     |
| `generate_track` / `replace_section` | `title` / `tags` / `negative_tags` | Optional string                                  | Candidate title, desired style description, and style tags to avoid. Pass empty strings when `tags` and `negative_tags` are omitted.                                                                                                  |
| `generate_track`                     | `prompt`                           | Optional string                                  | Text or lyric prompt for the new stem; may be omitted for pure instrumental music.                                                                                                                                       |
| `replace_section`                    | `prompt` / `replacement_lyrics`    | Optional string                                  | The former is the original song lyrics or contextual text, and the latter is the new lyrics for the replacement interval; pass empty strings when omitted.                                                                                                                      |
| `replace_section`                    | `fixed`                            | Optional boolean, default `false`                       | Requests a fixed-length replacement; when `true`, the interval must be shorter than 26 seconds, and the selected model may not support it. The real example in this test uses the default mode; `fixed=true` has not yet been verified.                                                                                    |
| `commit_candidate`                   | `operation_id` / `candidate_id`    | Required string                                  | Respectively take `data.operation_id` from the generation terminal state and the selected `data.candidates[].id`; the candidate must belong to the current project version.                                                                                    |
| `commit_candidate`                   | `track_id`                         | Required string                                  | New-track candidates should be committed to an **empty track saved before generation**; local replacement candidates are committed to the original track containing the unique source clip.                                                                                                              |
| `commit_candidate`                   | `start_beats` / `end_beats`        | Optional non-negative numbers for new-track candidates only                           | Specifies the position of the new clip on the project timeline; when omitted, the source clip start point is used, and the endpoint is calculated based on the actual candidate duration. Must not overlap with existing clips on the target track. **Local replacement candidates must omit these**.                                                                                      |
| `commit_candidate`                   | `name` / `gain`                    | Optional string / non-negative number for new-track candidates only                       | Generated clip name and volume coefficient; `gain` defaults to 1.                                                                                                                                  |
| `render`                             | `title`                            | Required string                                  | Exported audio title.                                                                                                                                                   |
| `render`                             | `lyrics` / `tags`                  | Optional string                                  | Lyrics text and style description during export; lyrics default to `[Instrumental]`.                                                                                                                      |
| `render`                             | `start_beats` / `end_beats`        | Optional non-negative numbers, with the end greater than the start                         | Exports a range of project beats; when omitted, uses the earliest start point and latest endpoint of all audible clips. Silent clips are excluded, and when solo tracks exist, only solo tracks are selected.                                                                                             |

Generation only produces candidates and **does not automatically place them into the project**. `commit_candidate` checks that the candidate still belongs to the current version. A local replacement candidate can only be automatically committed when its actual duration can be reliably matched with the complete source audio or the selected interval; when it does not match, the original project is retained and an error is returned, and it cannot be forcibly stitched together by manually guessing beats.

## Errors and Recovery

| Result                                                                        | Meaning                                                              | Next Step                                                                     |
| ----------------------------------------------------------------------------- | -------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `project_version_conflict` / `project_candidate_stale` (409)                 | The project version has changed, or the candidate does not belong to the current version. | `retrieve` the latest project and replan the modifications; do not replay old candidates. |
| `bad_request` / `studio_state_invalid` / `studio_model_unsupported` (usually 400) | Parameters, track state, candidate duration, or model does not match the operation. | Check the task terminal-state error and correct the input; retain the original project if the candidate cannot be safely stitched. |
| `studio_audio_unavailable` / `studio_access_denied` / `content_rejected` (403) | The referenced audio cannot be used for this project operation, access is denied, or content review rejected it. | Check the audio source and task `trace_id`; do not equate an already generated candidate with an exportable full song. |
| `too_many_requests` (429)                                                    | The request is rate-limited.                                        | Query the original task first, then decide whether to initiate a new operation with a new idempotency key. |
| `studio_unavailable` / `studio_model_unavailable` (503)                     | Project processing or the selected model is temporarily unavailable. | Retain the original task result; explicitly retry later, without automatically switching models. |
| `studio_processing_failed` / timeout (500/504)                               | Processing failed or the terminal state is uncertain.               | Query by `task_id` or the original idempotency key to avoid duplicate charged generations. |

Projects and candidates are bound to the application and execution environment that created them; do not assume cross-application reuse or automatic failover. Persist the final audio URL after a successful export, and retain the `trace_id` for troubleshooting.
