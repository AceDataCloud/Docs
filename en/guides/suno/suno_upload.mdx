SUNO allows us to upload reference audio for secondary creation. This document explains the integration method for the relevant APIs.

Standard upload only requires `audio_url`, which is a publicly accessible audio CDN URL. `mode` defaults to `standard`, so existing calls do not need to be modified. A successful standard upload consumes **0.06 Credits**; failed uploads are not charged.

Here, the `audio_url` we input is `https://cdn.acedata.cloud/suno_demo.mp3`, which is a publicly accessible CDN URL.

```bash
curl -X POST 'https://api.acedata.cloud/suno/upload' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3"
}'
```

As you can see, `data` is always an object, and `audio_id` is the song ID after upload. Analysis results such as `lyric`, `style`, `duration`, title, and media URLs are optional fields, subject to the actual returned content.

After obtaining the song ID, you can use the [Suno Audios Generation API](https://platform.acedata.cloud/documents/suno-audios) to call operations requiring `audio_id`, such as `upload_extend`, `upload_cover`, or segment sampling. To create new music based on 1 to 4 complete reference audio tracks through the Inspo inspiration creation feature, directly call `action=inspo` and pass in the list of original public audio URLs; the service will automatically complete upload and analysis, without requiring the client to assemble audio metadata.

## Uploading Original Cover Songs for Private Voice Covers

When creating a cover with a private voice created using `/suno/voices`, pass the `persona_id` of that voice in the standard upload request to associate the original song with the voice:

```json
{
  "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3",
  "mode": "standard",
  "persona_id": "<persona_id returned by the voice creation API>"
}
```

After a successful upload, use the returned `data.audio_id` to call `/suno/audios`, set `action: "upload_cover"`, and pass in the same `persona_id`. Do not continue using the previous audio ID that was not associated with that voice.

`persona_id` is supported only for standard uploads and cannot be used together with `mode: "enhanced"`. There is no need to additionally specify `vocal_gender`; gender preference cannot replace a voice ID. Voice creation, original song upload, and cover creation must use the same service channel.

## Enhanced Upload Mode

> `audio_url` is the input URL and will be passed directly to the audio processing workflow; it will not be pre-transferred by the final media persistence service. Please ensure that it is publicly accessible during task processing.

When standard upload cannot process audio that you own or are authorized to use, you can set `mode` to `enhanced`. This mode must also provide a `name` of 1 to 100 characters and use a publicly accessible HTTPS `audio_url`.

Enhanced upload always uses asynchronous processing and usually takes 2 minutes or longer. Successful processing consumes **1.87 Credits**; failed processing is not charged.

```bash
curl -X POST 'https://api.acedata.cloud/suno/upload' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3",
    "mode": "enhanced",
    "name": "My Song"
  }'
```

The API immediately returns `task_id` and `trace_id`. Use the [Suno Tasks API](https://platform.acedata.cloud/documents/suno-tasks) to query the task, and after success, read the uploaded audio ID from `response.data.audio_id`. You can also provide an HTTPS `callback_url` to receive the final state.
Enhance the uploaded `audio_id` to be usable for Cover, Samples, and Mashup. Accompaniment and MIDI extraction, full-track separation, and vocal/accompaniment separation may still be restricted by the account to which the audio belongs; operations not listed are not guaranteed to support cross-account use. The shorter the audio, the higher the processing success rate usually is.
