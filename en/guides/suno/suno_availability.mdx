---
title: "Suno Audio Availability Check API"
description: "Suno Music Generation integration guide - Ace Data Cloud"
---

`POST /suno/availability` looks for positive evidence, based on `audio_id`, that the audio can continue to be processed on the current route. It can be called before operations such as continuation or cover generation; the result reflects only the status at the time of the check and does not guarantee that a specific operation will succeed. This API returns synchronously, requires an API Token, and currently does not deduct Credits.

`audio_id` is the song ID returned by a completed Suno task, not `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Example successful response:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

When the check succeeds, `data.available` is `true`; when it cannot be confirmed, `503 availability_unknown` is returned and `false` is not returned. An invalid `audio_id` format returns 400, and rate limiting or service exceptions also return error responses. The status may still change between completion of the check and the actual operation.
