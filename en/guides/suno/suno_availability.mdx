---
title: "Suno Audio and Voice Availability Check API"
description: "Suno Music Generation integration guide - Ace Data Cloud"
---

`POST /suno/availability` accepts a resource ID. Pass `audio_id` to check a song, and pass `persona_id` to check a voice; one of the two is required. The check completes synchronously, requires an API Token, and currently does not deduct Credits.

## Request

`audio_id` comes from a completed song task and can be used for checks before continuation or cover generation.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

`persona_id` comes from the voice creation result. Using the original application and caller identity, send the following request body on a creation route that supports voice queries.

```json
{
  "persona_id": "33333333-3333-4333-8333-333333333333"
}
```

## Response

Both request types use the same successful response. `data.id` is the resource ID for this query.

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

`available: true` indicates that this check obtained positive evidence. For voices, the check verifies creation ownership and confirms that the associated account is currently reported online. Actual generation results are still subject to the generation task.

Private cloned voices created through `/suno/voices` depend on the account that created them. When that account is confirmed to be currently offline, the API returns HTTP 200, with `data` as shown below.

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

Clients can mark the voice as currently unavailable and check again later.

When it cannot be confirmed, the API returns HTTP 503 and `availability_unknown`, for example, when the resource cannot be found, old records lack the creation route, or the query times out. Public singer styles can be used across accounts, and HTTP 503 is also returned when the creating account is offline. Song queries still return `available: true` only when availability is confirmed.

Send only one valid UUID per request. All routes return HTTP 400 when receiving requests with both IDs or with both IDs missing. Routes that support only song queries return HTTP 400 when receiving requests containing only `persona_id`. Reduce query frequency when encountering HTTP 429.
