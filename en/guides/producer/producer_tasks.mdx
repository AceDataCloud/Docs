The main function of the Producer Tasks API is to query the execution status of a task by entering the task ID generated by the Producer Audios Generation API.

This document will introduce the integration instructions for the Producer Tasks API in detail, helping you easily integrate and fully utilize the powerful capabilities of this API. Through the Producer Tasks API, you can easily query the task execution status of the Producer Audios Generation API.

## Application Process

To use the Producer Audios Generation API, first go to the [Ace Data Cloud Console](https://platform.acedata.cloud/console/applications) to obtain your API Token and keep it for later use.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

If you have not yet logged in or registered, you will be automatically redirected to the login page and invited to register and log in. After completion, you will automatically return to the current page.

**One API Token can call all platform services; there is no need to apply separately for each service.** Your first application will receive free credits for a free trial; when credits are insufficient, you can top up your general balance in the [Console](https://platform.acedata.cloud/console/coin).

> 📘 Full documentation: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Request Example

The Producer Tasks API can be used to query the results of the Producer Audios Generation API. For how to use the Producer Audios Generation API, please refer to the documentation [Producer Audios Generation API](https://platform.acedata.cloud/documents/producer-audios-integration).

We use one task ID returned by the Producer Audios Generation API service as an example to demonstrate how to use this API. Suppose we have a task ID: `1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad`; next, we demonstrate how to do so by passing in a task ID.

### Set Request Headers and Request Body

**Request Headers** include:

- `accept`: Specifies receiving response results in JSON format; enter `application/json` here.
- `authorization`: The key for calling the API, which can be directly selected from the dropdown after application.

**Request Body** includes:

- `id`: The uploaded task ID.
- `action`: The operation method for the task.

Set as shown in the following image:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

There are multiple fields in the returned result. The `request` field is the request body when the task is initiated, while the `response` field is the response body returned after the task is completed. The field descriptions are as follows.
- `id`, the ID of the generation task, used to uniquely identify this generation task.
- `request`, the request information in the query task.
- `response`, the return information in the query task.
- `created_at`, task creation time, Unix timestamp (seconds, floating point).
- `started_at`, task execution start time, Unix timestamp (seconds, floating point).
- `finished_at`, task completion time, Unix timestamp (seconds, floating point). This field is not returned when the task is not completed.
- `elapsed`, task execution duration, in seconds (floating point, retained to 3 decimal places). This field is not returned when the task is not completed.

## Error Handling

When calling the API, if an error is encountered, the API will return the corresponding error code and information. For example:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.

### Error Response Example

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
