This article describes the integration for the Fish TTS API. The endpoint is fully compatible with the [Fish Audio official OpenAPI](https://docs.fish.audio/text-to-speech/text-to-speech) — code that previously called `https://api.fish.audio/v1/tts` can be migrated to `https://api.acedata.cloud/fish/tts` by simply swapping the authorization credentials, without any change to the request or response shape.

## Application Process

To use the API, first apply for the corresponding service on the [Fish TTS API](https://platform.acedata.cloud/services/caf99abc-ddcf-4714-b2a5-862d9b469509) page and click the "Acquire" button.

If you are not yet logged in or registered, you will be redirected to the login page; after signing in you will be returned to the current page.

A free quota is granted on the first acquisition so the API can be tried for free.

## Differences from the Official API

On top of preserving every field accepted by the Fish Audio official endpoint, this API adds a few platform-friendly enhancements:

- **Authentication**: use `Authorization: Bearer {token}` where `{token}` is the credential you obtained on this platform — not the Fish-Audio key.
- **TTS model selection**: pass the desired model through the `model` HTTP request header. Allowed values are `s1` and `s2-pro`; the default is `s2-pro`. This matches the Fish-Audio convention.
- **`latency` default**: the upstream `/fish/v1/tts` rejects requests that omit `latency`. This endpoint defaults it to `normal` (Fish-Audio's documented default) when the caller does not provide one.
- **Async callback (platform extension)**: when the request body contains a `callback_url` field, the API returns `{task_id, started_at}` immediately and POSTs the final `{audio_url, ...}` payload to the given URL once the upstream call resolves. This field is not part of the Fish-Audio spec — passing it switches into our async flow.

Apart from the differences above, every field in the TTS request body (`text`, `reference_id`, `references`, `prosody`, `format`, `sample_rate`, `mp3_bitrate`, `chunk_length`, `temperature`, `top_p`, ...) is forwarded to the upstream verbatim and behaves exactly as documented by Fish Audio.

## Basic Usage

The minimal request requires only `text`. Example:

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -H 'model: s2-pro' \
  -d '{
    "text": "The weather is great today, let us go for a walk."
  }'
```

The response is the Fish-native shape:

```json
{
  "audio_url": "https://platform.r2.fish.audio/task/8a72ff9840234006a9f74cb2fa04f978.mp3"
}
```

Fields:

- `audio_url`: URL of the generated audio, ready to download or stream.
- `latency_ms` (optional): upstream processing time in milliseconds.

To use a cloned voice, add `reference_id`:

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -H 'model: s2-pro' \
  -d '{
    "text": "The weather is great today, let us go for a walk.",
    "reference_id": "d7900c21663f485ab63ebdb7e5905036",
    "format": "mp3",
    "sample_rate": 44100
  }'
```

## Asynchronous Callback

Long-text TTS may take noticeably longer than a single HTTP request budget, so this API provides an async-callback flow as a non-breaking extension to the Fish Audio spec.

The flow: the client passes a `callback_url` field in the request body, the API returns a payload containing `task_id` immediately, and the final `audio_url` plus other fields are POSTed to the supplied URL once the upstream call completes. The callback body carries the same `task_id` so async results can be correlated to the original request.

Request example:

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -H 'model: s2-pro' \
  -d '{
    "text": "The weather is great today, let us go for a walk.",
    "callback_url": "https://webhook.site/4815f79f-a40f-4078-ac85-1cc126b6bb34"
  }'
```

Immediate response:

```json
{
  "task_id": "2725a2d3-f87e-4905-9c53-9988d5a7b2f5",
  "started_at": "2025-05-09T12:34:56.789Z"
}
```

After a short delay, the `callback_url` receives the final payload:

```json
{
  "task_id": "2725a2d3-f87e-4905-9c53-9988d5a7b2f5",
  "audio_url": "https://platform.r2.fish.audio/task/b627c2f7d38a4083a837570ba6d0962f.mp3"
}
```

You can also poll task status by `task_id` via the [Fish Tasks API](https://platform.acedata.cloud/documents/fc541fac-a941-47fd-b6f7-48d6cb9da523).

## Error Handling

HTTP status codes follow the Fish-Audio convention; the response body uses the platform-standard shape so error handling stays consistent with `/fish/audios` and `/fish/voices`:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.

### Error Response Example

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## Conclusion

The Fish TTS API is a drop-in replacement for the Fish Audio official OpenAPI, so existing code can be migrated with no changes besides the credential. The platform additionally provides unified authentication, usage metering, and the optional async-callback flow which is recommended for any long-text generation to avoid long-running connections.
