The main function of the Fish Tasks API is to query the execution status of tasks generated by the Fish Audios Generation API using the task ID.

This document provides detailed instructions for integrating the Fish Tasks API, helping you easily integrate and fully utilize the powerful features of this API. With the Fish Tasks API, you can effortlessly query the execution status of tasks from the Fish Audios Generation API.

## Application Process
To use the Fish Tasks API, you first need to apply for the corresponding service on the application page [Fish Audios Generation API](https://platform.acedata.cloud/documents/e681b715-54fd-4464-a59a-d7f14500e095), then copy the task ID from the Fish Audios Generation API, as shown below:

<p><img src="https://cdn.acedata.cloud/jxvue8.png" width="500" className="m-auto" /></p>

Finally, go to the Tasks API page [Fish Tasks API](https://platform.acedata.cloud/documents/44c93949-1419-4a45-8db5-8a8335de7151) to apply for the corresponding service. After entering the page, click the "Acquire" button, as shown below:

![Application Page](https://cdn.acedata.cloud/rci31i.png)

If you are not logged in or registered, you will be automatically redirected to the [login page](https://platform.acedata.cloud) to register and log in. After logging in or registering, you will be automatically returned to the current page.

A free quota is granted for the first application, allowing you to use this API for free.

## Request Example
The Fish Tasks API can be used to query the results of the Fish Audios Generation API. For how to use the Fish Audios Generation API, please refer to the documentation [Fish Videos Generation API](https://platform.acedata.cloud/documents/fish-audios-integration).

We take a task ID returned by the Fish Audios Generation API service as an example to demonstrate how to use this API. Suppose we have a task ID: 2725a2d3-f87e-4905-9c53-9988d5a7b2f5. Next, we demonstrate how to query by passing in a task ID.

### Setting Request Headers and Body

**Request Headers** include:

- `accept`: Specifies that the response should be in JSON format, set to `application/json`.
- `authorization`: The API key for calling the API, which can be selected from a dropdown after application.

**Request Body** includes:

- `id`: The uploaded task ID.
- `action`: The operation type on the task.

Set as shown below:

<p><img src="https://cdn.acedata.cloud/xc5ejq.png" width="500" className="m-auto" /></p>

### Code Example

You can see that various language code snippets are automatically generated on the right side of the page, as shown below:

<p><img src="https://cdn.acedata.cloud/851zv2.png" width="500" className="m-auto" /></p>

Partial code example:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/fish/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2725a2d3-f87e-4905-9c53-9988d5a7b2f5",
  "action": "retrieve"
}'
```

## Batch Query Operation

This operation is for querying details of multiple task IDs. Unlike above, the `action` should be set to `retrieve_batch`.

**Request Body** includes:

- `ids`: An array of uploaded task IDs.
- `action`: The operation type on the tasks.

Set as shown below:

<p><img src="https://cdn.acedata.cloud/64lid9.png" width="500" className="m-auto" /></p>

### Code Example

You can see that various language code snippets are automatically generated on the right side of the page, as shown below:

<p><img src="https://cdn.acedata.cloud/ezkzmw.png" width="500" className="m-auto" /></p>

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/fish/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["2725a2d3-f87e-4905-9c53-9988d5a7b2f5","2725a2d3-f87e-4905-9c53-9988d5a7b2f5"],

}'
```

## Error Handling

When calling the API, if an error occurs, the API will return the corresponding error code and message. For example:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.

### Error Response Example

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
