---
title: "Query Tripo Model Tasks"
description: "Tripo 3D integration guide - Ace Data Cloud"
---

Call `POST /tripo/tasks` with an AceDataCloud Token. Queries are free; use the same account used for generation. For a single task, use `id` or `trace_id`; `action` defaults to `retrieve`.

```bash
curl -X POST https://api.acedata.cloud/tripo/tasks \
  -H "Authorization: Bearer ${ACEDATACLOUD_API_TOKEN}" \
  -H "Content-Type: application/json" \
  -d "{\"action\":\"retrieve\",\"id\":\"${TASK_ID}\"}"
```

The result for a single task is a task record containing `id`, `type`, `trace_id`, the original request `request`, `started_at`, and `progress`. While processing, you can continue querying at intervals of a few seconds. After completion, check `response.success`; on success, `response.data[0].model_url` is the download URL, and on failure, `response.error` contains the error code and message. Timestamps, `finished_at`, and elapsed time `elapsed` are at the top level of the task record, in seconds. When encountering `submission_unknown`, retain the original task ID for verification.

For batch queries, use `{"action":"retrieve_batch","ids":["<Task ID 1>","<Task ID 2>"]}`; you can also use `trace_ids`, with a maximum of 100 tasks per request. The response is `{"items":[...],"count":2}`, preserving input order and duplicates. For tasks that cannot be found or that you do not have permission to read, a single query returns `{}`, and the corresponding position in a batch query is `null`.

The task record's `type` is `generations`, `models`, or `animations`. For rigging checks, read `response.data[0].riggable`; for file operations, read `response.data[0].model_url`.
