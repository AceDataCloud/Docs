---
title: "Tripo Model Processing"
description: "Tripo 3D integration guide - Ace Data Cloud"
---

Use `POST /tripo/models` to process existing models, passing in the required `action`. Synchronous and asynchronous processing, callbacks, account ownership, and task queries are the same as for 3D generation.

| action  | Input | Result |
| ------- | ----- | ------ |
| import  | `model_url`, a publicly accessible HTTPS GLB, GLTF, FBX, OBJ, or STL file, maximum 150 MiB | A model ID and GLB that can be referenced subsequently; returns `normalize_scale` and `normalize_translation` when data is available |
| texture | `model_id` or `model_url`; optionally, one of `prompt`, `image_url`, or `image_urls` | A new model, textures, and an optional preview |
| convert | `model_id` or `model_url`, and the target `format` | The converted model file |

```json
{"action":"texture","model_id":"5db97adc-a877-4587-af16-bbf443aa55de","prompt":"蓝色哑光表面","texture_quality":"standard","async":true}
```

Texture quality supports `fast`, `standard`, `detailed`, and `extreme`. When using a text prompt, `style_image_url` can be included; image and multiview references follow the generation API's format. See OpenAPI for more texture parameters.

Conversion supports `GLTF`, `FBX`, `USDZ`, `OBJ`, `STL`, and `3MF`. The `format` of a returned item indicates the actual delivery format; for example, a GLTF request may deliver a binary GLB. OBJ packages materials and textures in a ZIP. When requesting FBX, set `texture_packaging: "zip"` to obtain separate textures; the packaged result specifies `container: "ZIP"`. Enabling non-default mesh or texture settings may be billed as advanced conversion; see the service pricing for details.

Use `data[0].id` to reference models in this account. The normalization transform for imported models satisfies `normalized = original × normalize_scale + normalize_translation`. The model download URL is in `data[0].model_url`.
