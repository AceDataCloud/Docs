The main function of the Artistic QR Tasks API is to query the execution status of a task by inputting the task ID generated by the Artistic QR Generation API.

This document provides a detailed introduction to the integration of the Artistic QR Tasks API, helping you easily integrate and fully utilize the powerful features of this API. With the Artistic QR Tasks API, you can effortlessly query the execution status of tasks from the Artistic QR Generation API.

## Application Process
To use the Artistic QR Tasks API, you first need to apply for the corresponding service on the application page [Artistic QR Generation API](https://platform.acedata.cloud/documents/ee085d2a-a0b9-4f0e-8b4d-8da407345138), then copy the task ID from the Artistic QR Generation API, as shown below:

<p><img src="https://cdn.acedata.cloud/2wicjy.png" width="500" className="m-auto" /></p>

Finally, go to the Artistic QR Tasks API page [Artistic QR Tasks API](https://platform.acedata.cloud/documents/21de9d76-6e39-4ac3-b8b9-20e7194c02b4) to apply for the corresponding service. After entering the page, click the "Acquire" button, as shown below:

![Application Page](https://cdn.acedata.cloud/rci31i.png)

If you are not logged in or registered, you will be automatically redirected to the [login page](https://platform.acedata.cloud) to invite you to register and log in. After logging in or registering, you will be automatically returned to the current page.

A free quota is granted upon first application, allowing you to use the API for free.

## Request Example
The Artistic QR Tasks API can be used to query the result of a single Artistic QR Generation API task. For how to use the Artistic QR Generation API, please refer to the documentation [Artistic QR Generation API](https://platform.acedata.cloud/documents/ee085d2a-a0b9-4f0e-8b4d-8da407345138).

We take a task ID returned by the Artistic QR Generation API service as an example to demonstrate how to use this API. Suppose we have a task ID: e2c65b20-a970-431e-99c1-76721e799df8, next we demonstrate how to query by passing in a task ID.

### Setting Request Headers and Body

**Request Headers** include:

- `accept`: Specifies that the response should be in JSON format, set to `application/json`.
- `authorization`: The API key for calling the API, which can be selected from a dropdown after application.

**Request Body** includes:

- `id`: The uploaded task ID.
- `action`: The operation mode on the task.

Set as shown below:

<p><img src="https://cdn.acedata.cloud/use825.png" width="500" className="m-auto" /></p>

### Code Example

You can see that various language codes are automatically generated on the right side of the page, as shown below:

<p><img src="https://cdn.acedata.cloud/jejwy6.png" width="500" className="m-auto" /></p>

Partial code examples are as follows:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/qrart/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "e2c65b20-a970-431e-99c1-76721e799df8",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/qrart/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "e2c65b20-a970-431e-99c1-76721e799df8",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Batch Query Operation

This is for querying the details of multiple QR code tasks by their IDs. Different from above, the `action` should be set to `retrieve_batch`.

**Request Body** includes:

- `ids`: An array of uploaded task IDs.
- `action`: The operation mode on the tasks.

Set as shown below:

<p><img src="https://cdn.acedata.cloud/mrbxmr.png" width="500" className="m-auto" /></p>

### Code Example

You can see that various language codes are automatically generated on the right side of the page, as shown below:

<p><img src="https://cdn.acedata.cloud/u3b61d.png" width="500" className="m-auto" /></p>

Partial code examples are as follows:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/qrart/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["8c89e97b-6a79-4406-b2ce-e00f92540b4e","e2c65b20-a970-431e-99c1-76721e799df8"],
  "action": "retrieve_batch"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/qrart/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "ids": ["8c89e97b-6a79-4406-b2ce-e00f92540b4e","e2c65b20-a970-431e-99c1-76721e799df8"],
    "action": "retrieve_batch"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Error Handling

When calling the API, if an error occurs, the API will return the corresponding error code and message. For example:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.
