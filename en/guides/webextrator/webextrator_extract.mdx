`POST https://api.acedata.cloud/webextrator/extract`

The WebExtrator Intelligent Extraction API converts a URL into **typed, structured results** — articles, products,
recipes, videos, discussions, jobs, and more — along with cleaned Markdown and plain text. Use this API when you need "clean, structured data" rather than raw HTML.

## Application Process

To use the WebExtrator service page, first go to the [Ace Data Cloud Console](https://platform.acedata.cloud/console/applications) to obtain your API Token for backup.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

If you are not logged in or registered, you will be automatically redirected to the login page inviting you to register and log in, after which you will be automatically returned to the current page.

**One API Token can call all services on the platform, no need to apply separately for each service.** The first application will grant a free quota for a free trial; when the quota is insufficient, you can recharge the general balance in the [console](https://platform.acedata.cloud/console/coin).

> 📘 Complete documentation: [WebExtrator Service Page →](https://platform.acedata.cloud/service/webextrator)

## Authentication

```
Authorization: Bearer YOUR_API_KEY
Content-Type:  application/json
```

## Request Parameters

Extract accepts **all** parameters of the [Render API](/en/guides/webextrator/webextrator_render)
（`url`、`user_agent`、`timeout`、`wait_until`、`delay`、`wait_for_selector`、
`block_resources`、`headers`、`cookies`、`callback_url`、`bypass_cache`、
`cache_ttl_seconds`、`async`）, plus two Extract-specific fields:

| Field | Type | Required | Default | Description |
|------|------|:----:|------|------|
| `expected_type` | enum | ❌ | Auto-detect | Page type hint: `product` / `article` / `general`. Specifies the expected result type. |
| `enable_llm` | boolean | ❌ | `false` | Allows LLM extraction when schema.org is not found. On pages without JSON-LD, such as Amazon / HN / Greenhouse, this must be enabled to obtain typed results. |

### Top-level Fields

| Field | Type | Description |
|------|------|------|
| `kind` | string | Always `"extract"`. |
| `url` | string | The URL you submitted. |
| `finalUrl` | string | The final URL after redirects. |
| `contentType` | enum | Page type: `product` / `article` / `general`. |
| `title` | string | Page title. |
| `description` | string? | Page description or summary. |
| `byline` | string? | Author, channel, or company. |
| `language` | string? | `<html lang>`.  |
| `siteName` | string? | `og:site_name`.  |
| `publishedAt` | string? | Publication time in ISO 8601 format. |
| `images` | string[] | Up to 50 `<img src />`, resolved to absolute URLs, deduplicated, and with `data:` URIs discarded. |
| `links` | string[] | Up to 100 external links, with fragments / `javascript:` / `mailto:` / `tel:` filtered out. |
| `markdown` | string | The page's Markdown content. |
| `text` | string | Plain text of the page. |
| `structured` | object | The complete structured result; see below. |
| `rawSignals` | object | Diagnostic information for debugging. |
| `cached` | boolean? | `true` when a cache entry is hit. |
| `cacheStoredAt` | number? | Unix timestamp in milliseconds when the cache entry was first written. |

### `data.structured` Subfields

| Subfield | When it appears | Description |
|--------|---------|------|
| `schemaOrg` | Always | `{ primary, breadcrumbs, all }`. `primary` is the highest-priority typed entity; `null` if none is found. |
| `openGraph` | Always | `{ title, description, image, type }`, derived from `<meta property="og:*" />`. |
| `jsonLd` | Always | Raw JSON array of all `<script type="application/ld+json">` blocks. |
| `llm` | When the LLM runs and succeeds | `{ kind, data, model, promptCharCount }`, typed result. |
| `llmError` | When the LLM runs but fails | `{ kind, error, model }`, the request may still return other extracted fields. |
| `amazon` | When the URL is `amazon.*` | Legacy Amazon extension result; use typed results for new integrations. |

## schema.org Result Types

`structured.schemaOrg.primary` supports the following result types:

| schema.org Type | kind | Output Fields |
|----------------|----------|----------|
| `Product` | product | `name, sku, gtin, model, color, brand, url, images, offer.{price,currency,availability,condition,seller}, rating.{value,count}, reviews[], properties[]` |
| `Recipe` | recipe | `name, description, image, datePublished, author, cookTime, prepTime, totalTime, recipeYield, ingredients[], instructions[], nutrition, rating, keywords, recipeCategory, recipeCuisine` |
| `VideoObject` | video | `name, description, thumbnailUrl, uploadDate, duration, embedUrl, contentUrl, channel, interactionCount` |
| `JobPosting` | job | `title, description, datePosted, validThrough, hiringOrganization, jobLocation, baseSalary, employmentType` |
| `Event` (including `*Event`) | event | `name, description, startDate, endDate, location.{name,address}, organizer, offer.{url,price,currency}` |
| `Article` / `NewsArticle` / `BlogPosting` / `ScholarlyArticle` / `TechArticle` / `Report` / `*NewsArticle` | article | `subtype, headline, description, datePublished, dateModified, author, publisher, image[], url, sameAs[]` |
| `FAQPage` | faq | `questions[{question, answer}]` |
| `BreadcrumbList` | (attached to sibling) | Always output to `structured.schemaOrg.breadcrumbs[]`; it will not be used as the primary. |

## LLM Result Types

When `enable_llm: true` and the page has no available schema.org structured data, extraction results of the following types may be returned:

| Kind | Required Fields | Optional Fields |
|------|---------|---------|
| `article` | `headline` | `description, byline, publishedAt, language, topics[], sections[{heading,summary}]` |
| `product` | `name` | `description, brand, sku, price, currency, availability, rating.{value,count}, bullets[], specifications[{name,value}]` |
| `discussion` | `title` | `author, postedAt, points, commentCount, body, url` |
| `recipe` | `name` | `description, author, cookTime, prepTime, totalTime, recipeYield, ingredients[], instructions[], nutrition, rating, keywords[]` |
| `video` | `name` | `description, channel, uploadDate, duration, viewCount, likeCount, thumbnailUrl, transcript` |
| `job` | `title` | `description, company, location, remote, employmentType, datePosted, validThrough, salaryMin, salaryMax, salaryCurrency, salaryPeriod, responsibilities[], qualifications[]` |

## Caching

Cache results can be reused for the same URL, request parameters, `cookies`, and `headers`; `async`, `bypass_cache`, and `cache_ttl_seconds` are used to control execution mode and caching behavior.

| Field | Effect |
|------|------|
| `bypass_cache: true` | Skip reading; this result will still be written back to the cache, so the same request can hit the cache next time. |
| `cache_ttl_seconds: 0` | This response is **not cached**. |
| `cache_ttl_seconds: N` | Customize the TTL for this entry (default: 3600 seconds). |

Responses that hit the cache will include `data.cached: true` and `data.cacheStoredAt: <unix-ms>`.

## Asynchronous Mode and Callback

Set `async: true` to enter asynchronous mode (providing `callback_url` will also automatically enter). The platform immediately returns (HTTP 200):

```json
{
  "success": true,
  "task_id": "550e8400-...",
  "trace_id": "6ba7b810-...",
  "started_at": 1777717800.123
}
```

When the task is complete, it will `POST` the complete envelope to your `callback_url` (if configured). You can also actively query later through [`/webextrator/tasks`](/en/guides/webextrator/webextrator_tasks).

## Example

### 1. Wikipedia Article (schema.org hit, no LLM needed)

```bash
curl -X POST https://api.acedata.cloud/webextrator/extract \
  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://en.wikipedia.org/wiki/Diffbot",
    "expected_type": "article"
  }'
```

`data.structured.schemaOrg.primary` key fields:
```json
{
  "kind": "article",
  "subtype": "Article",
  "headline": "American machine learning and knowledge management company",
  "datePublished": "2007-08-08T05:47:27Z",
  "dateModified": "2025-07-10T20:42:45Z",
  "author": { "name": "Contributors to Wikimedia projects", "type": "Organization" },
  "publisher": { "name": "Wikimedia Foundation, Inc." }
}
```

### Python (requests)

```python
import os, requests

API_KEY = os.environ["ACEDATA_API_KEY"]

resp = requests.post(
    "https://api.acedata.cloud/webextrator/extract",
    headers={
        "Authorization": f"Bearer {API_KEY}",
        "Content-Type": "application/json",
    },
    json={
        "url": "https://en.wikipedia.org/wiki/Diffbot",
        "expected_type": "article",
    },
    timeout=120,
)
resp.raise_for_status()
data = resp.json()["data"]

primary = (data.get("structured") or {}).get("schemaOrg", {}).get("primary")
print("contentType:", data["contentType"])
print("title:      ", data["title"])
print("byline:     ", data.get("byline"))
print("publishedAt:", data.get("publishedAt"))
if primary and primary["kind"] == "article":
    print("headline:    ", primary["headline"])
    print("dateModified:", primary.get("dateModified"))
```

### Node.js (fetch)

```js
const apiKey = process.env.ACEDATA_API_KEY;

const res = await fetch('https://api.acedata.cloud/webextrator/extract', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${apiKey}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    url: 'https://www.allrecipes.com/recipe/16354/easy-meatloaf/',
  }),
});
const { data } = await res.json();
const recipe = data?.structured?.schemaOrg?.primary;
console.log(recipe.name, recipe.cookTime, recipe.ingredients.length, 'types of ingredients');
```

## Tips and Pitfalls

- **Pass `expected_type` when you need to specify a page type.** For example, use `article` for article pages and `product` for product pages.
- **`enable_llm: true` is free on pages matched by schema.org.** The LLM is only called when schema.org
  does not have a primary, so it is safe to enable by default.
- **Check `rawSignals.hasJsonLd` first when debugging.** If it is `true` but `structured.schemaOrg.primary`
  is `null`, the page's `@type` is not currently supported. Please send us feedback.
- **`structured.llmError` is informational.** The request can still successfully return other extracted fields. Check
  `llmError.error` to identify the cause (timeout, JSON parsing failure, or structure validation failure).
- **`links[]` for non-article pages does not perform relevance ranking.** It only does its best to clean based on "a maximum of 100 items + filtering invalid protocols"
  .
- **Cache hits are also billed.**
