---
title: "Async tasks"
description: "Submit a generation once, query its task ID, and retrieve the final result."
---

Endpoints that support `async: true` can return a task ID while generation continues. Save that ID immediately. Query the task until its documented terminal state, then read the result or error.

## Submit a generation

Sign in to [Applications](https://platform.acedata.cloud/console/applications?lang=en&utm_source=docs&utm_medium=referral&utm_campaign=evergreen) and open **General Application**. Click the copy button to the right of **API KEY**. Store the key on your server and use it for `YOUR_API_KEY` in the command below.

![API key in the General Application card](https://cdn.acedata.cloud/dvc3cg.jpg)

To [generate a song with ACE Music](https://platform.acedata.cloud/documents/acemusic-audios-integration?lang=en), set the key in your terminal and send this request once. The JSON examples below illustrate the documented response structure. Replace placeholder IDs and media URLs with values from your own responses.

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"

curl --fail-with-body https://api.acedata.cloud/acemusic/audios \
  --header "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{
    "action": "generate",
    "model": "acemusic-v1.1",
    "custom": false,
    "prompt": "An uplifting acoustic folk song about coming home",
    "async": true
  }'
```

### Submission response JSON

ACE Music accepts this asynchronous request with HTTP `202`. Save its `task_id` for every subsequent query.

```json
{
  "task_id": "YOUR_TASK_ID",
  "trace_id": "YOUR_TRACE_ID",
  "status": "created"
}
```

## Query the original task

Use the saved `task_id` as the query's `id`.

```bash
curl --fail-with-body https://api.acedata.cloud/acemusic/tasks \
  --header "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{"action":"retrieve","id":"YOUR_TASK_ID"}'
```

### Pending response JSON

An HTTP `200` task query can still describe a generation in progress.

```json
{
  "id": "YOUR_TASK_ID",
  "type": "audios",
  "state": "processing",
  "trace_id": "YOUR_TRACE_ID",
  "finished_at": null,
  "response": {
    "success": false,
    "task_id": "YOUR_TASK_ID",
    "status": "processing",
    "data": []
  }
}
```

Continue querying while `state` is `created`, `submitting`, `processing`, `storing` or `submission_unknown`. The nested `response.success` can be `false` during processing; check the task state before interpreting it as a failure.

### Completed response JSON

A complete song-generation group has `state=succeeded` and two tracks.

```json
{
  "id": "YOUR_TASK_ID",
  "type": "audios",
  "state": "succeeded",
  "trace_id": "YOUR_TRACE_ID",
  "response": {
    "success": true,
    "task_id": "YOUR_TASK_ID",
    "status": "succeeded",
    "data": [
      {
        "id": "FIRST_TRACK_ID",
        "model": "acemusic-v1.1",
        "state": "succeeded",
        "audio_url": "https://media.example.com/first-song.mp3"
      },
      {
        "id": "SECOND_TRACK_ID",
        "model": "acemusic-v1.1",
        "state": "succeeded",
        "audio_url": "https://media.example.com/second-song.mp3"
      }
    ]
  }
}
```

Open or download each `response.data[].audio_url`. Track `id` values identify songs for later cover or mashup operations. The original `task_id` identifies this generation request. `failed` and `partial_failed` are terminal states; inspect the error and any delivered tracks. Full fields are listed in the [ACE Music task guide](https://platform.acedata.cloud/documents/acemusic-tasks-integration?lang=en).

## Run the same workflow in Python

Use this Python version as an alternative to the cURL steps above. Install `requests` with `pip install requests`. It submits once, prints the task ID and polls until a terminal state.

```python
import os
import time
import requests

headers = {"Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_KEY']}"}
submitted = requests.post(
    "https://api.acedata.cloud/acemusic/audios",
    headers=headers,
    json={
        "action": "generate",
        "model": "acemusic-v1.1",
        "custom": False,
        "prompt": "An uplifting acoustic folk song about coming home",
        "async": True,
    },
    timeout=30,
)
submitted.raise_for_status()
task_id = submitted.json()["task_id"]
print("Save this task ID to resume later:", task_id, flush=True)

# Keep this ID when resuming. Submit the generation only once.
for attempt in range(180):
    response = requests.post(
        "https://api.acedata.cloud/acemusic/tasks",
        headers=headers,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    response.raise_for_status()
    task = response.json()
    state = task.get("state") or task.get("status")
    if state in {"succeeded", "failed", "partial_failed"}:
        result = task.get("response") or {}
        if state != "succeeded":
            raise RuntimeError({"task_id": task_id, "state": state, "error": result.get("error")})
        for track in result.get("data", []):
            print(track["audio_url"])
        break
    time.sleep(5)
else:
    print("Still pending. Resume querying this task ID:", task_id)

```

## Use the endpoint's task contract

Each service documents its own query path, request fields and terminal states. Use the corresponding [service guide](https://platform.acedata.cloud/services?lang=en) for Suno, Veo, Seedance and other APIs. A successful HTTP response to a task query may still describe a pending generation. Some operations return their full result synchronously or stream output.

If a query fails or reaches the polling limit, keep the original task ID and query it again later. A connection timeout during submission can leave the outcome uncertain. Check your task history or contact support with `trace_id` before submitting the same generation again.

## Webhook callbacks

Where supported by the endpoint, include `callback_url` in the original generation request to receive its final result. ACE Music accepts an HTTPS callback URL and uses asynchronous execution for that request.

```json
{
  "action": "generate",
  "model": "acemusic-v1.1",
  "custom": false,
  "prompt": "An uplifting acoustic folk song about coming home",
  "async": true,
  "callback_url": "https://your-app.example/callbacks/acemusic"
}
```

Save the submitted task ID in your application. Process callbacks idempotently by that ID and return a `2xx` response promptly. Treat a callback as a notification and query the recorded task to verify its result before updating your application. Polling also recovers a missing callback. For the exact callback payload, follow the selected endpoint's guide.
