---
title: "API keys and authentication"
description: "Create an application API key and authenticate requests to Ace Data Cloud."
---

Send an application API key in the `Authorization` header to call APIs at `https://api.acedata.cloud`.

## Get an API key

<Steps>
  <Step title="Open Applications">
    Open [Applications](https://platform.acedata.cloud/console/applications?lang=en&utm_source=docs&utm_medium=referral&utm_campaign=evergreen) and sign in or register.
  </Step>
  <Step title="Choose General application">
    Select **Initialize General Application** if it is missing. A general key can access services available to your account. A dedicated application's key is limited to its service.
  </Step>
  <Step title="Copy the API Key">
    Copy **API Key** from the application card. To create a separate key, open **Keys / Manage Keys → Create**, give it a name, and copy the new token from the key list.
  </Step>
</Steps>

Check the application balance against the selected [model price](https://platform.acedata.cloud/models?lang=en). Any trial allowance is shown in your account. When creating a key, configure **Expiration Time**, **Set Usage Limitation**, and **Allowed APIs** as needed for your integration. Include both generation and task-query operations when your workflow uses them.

## Use the key

Save the raw token in an environment variable and add `Bearer ` only in the HTTP header.

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"

curl --fail-with-body https://api.acedata.cloud/v1/chat/completions \
  --header "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  --header "Content-Type: application/json" \
  --data '{"model":"gpt-6-luna","messages":[{"role":"user","content":"Say hello in one sentence."}]}'
```

A client field named **API Key** or **API Token** takes the raw token value. Keep it in the client's credential store or your backend environment. Use the request's documented content type for file uploads and other non-JSON operations.

## Choose the correct credential

| Credential | Use |
| --- | --- |
| Application API key | Model generation and service calls. Access, limits and balance follow its application and key settings. |
| Platform token beginning with `platform-` | Account and platform management APIs. Create it through the [platform token guide](/en/guides/platform/platform_token). |
| Deployment or account-proxy credential | Follow the selected deployment's guide for its endpoint and authorization method. |

## Resolve a failed request

| Response | What to check |
| --- | --- |
| `invalid_token`, `token_expired` | Copy the complete current key and check its expiration. |
| `token_mismatched`, `disabled` | Check the application's service access and whether the application or key is enabled. |
| `used_up` | Check the application balance and key usage limit, then use the console's recharge option if needed. |
| `no_token`, `bad_request` | Check the Authorization header, JSON syntax and required fields. |
| `too_many_requests` | Wait for the active request to finish or follow the endpoint's retry guidance. Trial accounts may have one billable request active across the account. |

For a generation that already returned a task ID, continue [querying that task](/en/concepts/async-tasks). A timeout can occur while the original task is still running. Include `trace_id` and the task ID when contacting support.

Use [Quickstart](/en/quickstart) for the first response, or browse [all API services](/en/services).
