All Ace Data Cloud API traffic flows through the `api.acedata.cloud` gateway and uses **Bearer Token** authentication.

<Note>
  All gateways are **HTTPS-only**. HTTP requests get 301-redirected and the Authorization header is stripped.
</Note>

## Getting Your API Token

<Steps>
  <Step title="Sign up">
    Visit [platform.acedata.cloud](https://platform.acedata.cloud). New accounts come with trial credits.
  </Step>
  <Step title="Subscribe to a service">
    Open any service page (e.g. Midjourney, Suno) and click **Get**.
  </Step>
  <Step title="Create a credential">
    Inside the service, open **Credentials** → **Create credential**. Copy the returned token — that's your API key.
  </Step>
</Steps>

## Credential Types

| Type | Scope | When to use |
|---|---|---|
| **Service credential** | Bound to one service, billed against that subscription | Default, least privilege |
| **Global credential** | Works across all subscribed services, billed against your global balance | Convenient when you call many AI services |
| **Platform token** (`platform-*` prefix) | Platform-management APIs (account, subscriptions) | **Don't use for business API calls** |

## Request Headers

Every request needs:

```
Authorization: Bearer YOUR_API_TOKEN
Content-Type: application/json
```

| Header | Required | Note |
|---|---|---|
| `Authorization` | Yes | `Bearer ` prefix + token. **Case sensitive** |
| `Content-Type` | POST/PUT | Always `application/json`, UTF-8 encoded |
| `Accept-Language` | No | Controls language of error messages (e.g. `en`, `zh-CN`) |
| `X-Request-Id` | No | Custom request ID; helps support correlate logs |

## Request Rules

| Rule | Requirement |
|---|---|
| Protocol | HTTPS only |
| Method | As defined per endpoint |
| Encoding | UTF-8 |
| Body | `application/json` |
| File upload | Pass a public HTTPS URL, or upload first |

## Common Auth Errors

### 401 Unauthorized

```json
{
  "success": false,
  "error": {
    "code": "unauthorized",
    "message": "Authentication credentials were not provided or are invalid."
  }
}
```

Causes: missing `Authorization` header, typo in token (note the space after `Bearer`), revoked token, using `platform-*` token for a business call.

### 402 Payment Required

```json
{
  "success": false,
  "error": {
    "code": "insufficient_balance",
    "message": "Application balance is not enough for this request."
  }
}
```

Top up at [platform.acedata.cloud](https://platform.acedata.cloud).

### 403 Forbidden

```json
{
  "success": false,
  "error": {
    "code": "forbidden",
    "message": "Content moderation rejected this request."
  }
}
```

Reasons: moderation rejection (sensitive content, copyrighted material, blocked artist names) or the credential isn't authorized for that service.

### 429 Too Many Requests

```json
{
  "success": false,
  "error": {
    "code": "rate_limited",
    "message": "Request rate exceeded. Please retry later."
  }
}
```

Use exponential backoff. See [Concurrency & Rate Limits](/en/faq/concurrency).

## Security Best Practices

- **Never** hard-code tokens in browser / mobile apps — proxy through your own backend
- Store tokens in environment variables or a secrets manager (Vault, AWS Secrets Manager)
- Use separate tokens per environment (dev / staging / production)
- Rotate tokens periodically from the Credentials page
- Revoke immediately on suspected leak
