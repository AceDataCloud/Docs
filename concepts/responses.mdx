Ace Data Cloud 所有业务 API 都返回 **统一 JSON 包装**，无论同步还是异步任务，都遵循同一套字段约定。

## 成功响应

```json
{
  "success": true,
  "task_id": "1bae3bec-3ac4-4180-a148-74ee6cb68b98",
  "image_url": "https://cdn.acedata.cloud/midjourney/...",
  "image_width": 1024,
  "image_height": 1024,
  "actions": ["upscale1", "upscale2", "variation1", "variation2"]
}
```

公共字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `success` | `boolean` | **永远存在**。`true` 表示请求受理或完成 |
| `task_id` | `string` (UUID) | 异步任务的唯一 ID，用 `/tasks` 端点查结果 |

其余字段因服务而异——以各服务的 [API 参考](/api-reference) 为准。

## 失败响应

```json
{
  "success": false,
  "error": {
    "code": "insufficient_balance",
    "message": "Application balance is not enough for this request."
  },
  "trace_id": "f3b3c33b-265a-462a-bd9f-a2e678b18038"
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `success` | `boolean` | 永远是 `false` |
| `error.code` | `string` | 机器可识别的错误码，见下表 |
| `error.message` | `string` | 人类可读说明，可直接展示给最终用户 |
| `trace_id` | `string` (UUID) | 请求追踪 ID。**报障时务必提供此值**，我们用它查日志 |

## HTTP 状态码速查

| 状态 | 含义 | 客户端行为 |
|---|---|---|
| `200` | 成功 | 读 `success` 字段判断业务结果 |
| `202` | 已受理，异步处理中 | 用 `task_id` 轮询 |
| `400` | 请求参数错误 | 检查 `error.message`，**不要重试** |
| `401` | 认证失败 | 检查 `Authorization` 头，**不要重试** |
| `402` | 余额或额度不足 | 提示用户充值，**不要重试** |
| `403` | 内容审核拒绝 / 没有该服务权限 | **不要重试**，让用户改 prompt 或加订阅 |
| `404` | 资源不存在（如 task_id 拼写错误） | 检查 ID |
| `429` | 触发速率限制 | 指数退避后重试 |
| `500` | 服务器内部错误 | 退避重试，连续失败请上报 `trace_id` |
| `502` / `503` / `504` | 上游不可用 / 超时 | 退避重试，建议 3 次后熔断 |

## 常见错误码

| `error.code` | HTTP | 含义 |
|---|---|---|
| `unauthorized` | 401 | Token 缺失、错误或已撤销 |
| `insufficient_balance` | 402 | 订阅额度或全局余额不足 |
| `forbidden` | 403 | 内容审核拒绝或无访问权限 |
| `invalid_request` | 400 | 请求字段缺失、格式错误或超出范围 |
| `rate_limited` | 429 | 触发上游 / 网关速率限制 |
| `upstream_error` | 502 | 上游 AI 服务返回错误 |
| `upstream_timeout` | 504 | 上游处理超时 |
| `content_moderation` | 403 | 提示词命中内容审核 |
| `task_not_found` | 404 | `task_id` 不存在或已过期 |
| `task_failed` | 200 | 任务最终失败（`status: failed`，看 `error` 子字段） |

## 重试策略

<Note>
  并不是所有失败都该重试。**4xx 错误一般不要重试**，先修请求；**5xx / 429 可以退避重试**。
</Note>

推荐的指数退避：

```python
import time, random, requests

def call_with_retry(url, headers, json_body, max_attempts=5):
    for attempt in range(max_attempts):
        r = requests.post(url, headers=headers, json=json_body, timeout=300)
        if r.status_code < 500 and r.status_code != 429:
            return r.json()
        # 退避：1s, 2s, 4s, 8s, 16s + 0–1s 抖动
        delay = (2 ** attempt) + random.random()
        time.sleep(delay)
    raise RuntimeError("max retries exceeded")
```

## 上报问题

每次失败响应里都有 `trace_id`。报障时把它和**完整的请求/响应**贴给我们，定位最快。

- 在线：[platform.acedata.cloud](https://platform.acedata.cloud) 工单
- 邮件：`support@acedata.cloud`
- 紧急：[状态页](https://status.acedata.cloud) 上的 SLA 联系方式
