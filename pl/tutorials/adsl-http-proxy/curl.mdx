## Wprowadzenie

ADSL HTTP Proxy to usługa proxy sieciowego oferowana przez Ace Data Cloud, umożliwiająca pobieranie dynamicznych adresów IP ADSL. Dzięki zunifikowanemu API Ace Data Cloud możesz szybko wywoływać ADSL HTTP Proxy za pomocą cURL, realizując funkcje takie jak proxy HTTP/SOCKS, wielu operatorów, różne prowincje, niestandardowy czas trwania, biała lista IP i inne.

## Wymagania wstępne

- Posiadanie konta w [Ace Data Cloud](https://platform.acedata.cloud) oraz uzyskanie API Token
- Środowisko terminalowe z zainstalowanym cURL

## Podstawowe użycie

Główny endpoint API ADSL HTTP Proxy to:

```
POST https://api.acedata.cloud/adsl/extract
```

Przykładowe pełne polecenie cURL:

```bash
curl -X POST https://api.acedata.cloud/adsl/extract \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"number": 5, "type": "http", "duration": 300, "province": "广东", "isp": "电信"}'
```

Proszę zastąpić `YOUR_API_TOKEN` rzeczywistym tokenem uzyskanym na platformie Ace Data Cloud.

## Przykład odpowiedzi

Po pomyślnym wywołaniu zwracane są dane w formacie JSON, na przykład:

```json
{
  "status": "success",
  "data": {
    ...
  }
}
```

## Przetwarzanie odpowiedzi za pomocą jq

Zaleca się użycie narzędzia jq do formatowania wyjścia:

```bash
curl -s -X POST https://api.acedata.cloud/adsl/extract \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"number": 5, "type": "http", "duration": 300, "province": "广东", "isp": "电信"}' | jq .
```

## Obsługa błędów

Typowe kody błędów:

| Kod statusu | Opis                         |
|-------------|------------------------------|
| 401         | Nieautoryzowany, sprawdź API Token |
| 403         | Niewystarczające środki lub brak dostępu |
| 429         | Przekroczona częstotliwość zapytań |
| 500         | Błąd wewnętrzny serwera      |
