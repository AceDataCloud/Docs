W tym dokumencie przedstawimy instrukcję integracji z Producent Audios Generation API, które umożliwia generowanie oficjalnej muzyki Producenta za pomocą wprowadzonych parametrów.

## Proces aplikacji

Aby skorzystać z API, należy najpierw przejść na stronę [Producent Audios Generation API](https://platform.acedata.cloud/documents/producer-audios) i złożyć wniosek o odpowiednią usługę. Po wejściu na stronę, kliknij przycisk „Acquire”, jak pokazano na obrazku:

![](https://cdn.acedata.cloud/q6ytrc.png)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować. Po zalogowaniu lub rejestracji automatycznie wrócisz na bieżącą stronę.

Podczas pierwszej aplikacji otrzymasz darmowy limit, który pozwala na bezpłatne korzystanie z tego API.

## Podstawowe użycie

Chcąc wygenerować piosenkę, możesz wprowadzić dowolny tekst, na przykład, jeśli chcesz stworzyć piosenkę o tematyce świątecznej, możesz wpisać `a song for Christmas`, jak pokazano na obrazku:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Można zauważyć, że ustawiliśmy nagłówki żądania, w tym:

- `accept`: format odpowiedzi, który chcesz otrzymać, tutaj wpisano `application/json`, czyli format JSON.
- `authorization`: klucz do wywołania API, po złożeniu wniosku można go bezpośrednio wybrać z rozwijanej listy.

Dodatkowo parametry ciała żądania obejmują:

- `action`: działanie związane z generowaniem muzyki, w tym przypadku `generate`.
- `model`: model używany do tworzenia piosenki, obecnie dostępne są: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**, **FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: treść tekstu piosenki.
- `custom`: czy używać metody generacji dostosowanej.
- `prompt`: słowo kluczowe w trybie inspiracji.
- `title`: informacja o tytule piosenki.
- `audio_id`: ID referencyjnej piosenki, używane do kontynuacji/odtworzenia itp.
- `continue_at`: kontynuacja od określonej sekundy.
- `replace_section_start`/`replace_section_end`: czas rozpoczęcia i zakończenia wymiany fragmentu, w sekundach.
- `lyrics_strength`: siła tekstu, wskazująca na wpływ tekstu na generację audio, opcjonalnie od 0 do 1, domyślnie 0.7.
- `sound_strength`: siła słów kluczowych audio, opcjonalnie od 0.2 do 1, domyślnie 0.7.
- `cover_strength`: siła coveru od 0.2 do 1, domyślnie 1.
- `weirdness`: stopień dziwności stylu, opcjonalnie od 0 do 1, domyślnie 0.5.
- `callback_url`: URL, na który mają być zwracane wyniki.
- `instrumental`: czy ma to być tryb bez tekstu.

Dodatkowo, jeśli chcesz wygenerować odpowiedni kod integracyjny, możesz go bezpośrednio skopiować, na przykład kod CURL wygląda następująco:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Covering Songs

Jeśli chcesz wykonać cover już wygenerowanej piosenki, możesz wprowadzić wygenerowaną wcześniej piosenkę, aby wykonać cover, następnie musimy dostosować generowanie piosenki na podstawie tekstu, tytułu.

Jeśli chcesz kontynuować wykonywanie coveru swojej przesłanej piosenki, możesz ustawić parametr `action` na `upload_cover` i wprowadzić ID piosenki, którą chcesz kontynuować, ID piosenki można uzyskać za pomocą [Producer Upload API](https://platform.acedata.cloud/documents/7fd2cb52-772e-4cc4-a018-e2626ff6f447), jak pokazano na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Możesz określić następujące treści:

- action: działanie zadania piosenki, obecnie wspierane: generate, cover, extend, upload_cover, upload_extend, replace_section, swap_vocals, swap_instrumentals, variation, w tym przypadku używamy parametru `cover`.
- lyric: tekst piosenki
- title: tytuł piosenki.
- custom: czy używać trybu dostosowanego do generowania, domyślnie jest false.
- audio_id: ID piosenki, którą chcesz wykonać cover.

## Kontynuacja piosenki

Jeśli chcesz kontynuować piosenkę, musimy przekazać parametr `action` z wartością: `extend`, następnie musimy dostosować generowanie piosenki na podstawie tekstu, tytułu i stylu.

## Asynchroniczne wywołanie zwrotne

Ponieważ czas generacji API Producer Audios może być czasami stosunkowo długi, jeśli API nie odpowiada przez dłuższy czas, żądanie HTTP będzie utrzymywać połączenie, co prowadzi do dodatkowego zużycia zasobów systemowych, dlatego to API oferuje również wsparcie dla asynchronicznych wywołań zwrotnych.

Cały proces wygląda następująco: klient inicjuje żądanie, dodatkowo określając pole `callback_url`, po wysłaniu żądania API natychmiast zwraca wynik, zawierający pole `task_id`, które reprezentuje aktualne ID zadania. Po zakończeniu zadania, wynik generacji zadania zostanie wysłany do określonego przez klienta `callback_url` w formie POST JSON, w tym również pole `task_id`, dzięki czemu wynik zadania można powiązać za pomocą ID.

Poniżej przyjrzymy się, jak dokładnie to działa na przykładzie.

Najpierw, wywołanie zwrotne Webhook to usługa, która może odbierać żądania HTTP, deweloperzy powinni zastąpić to URL swojego własnego serwera HTTP. ## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Nieautoryzowany, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`: Błąd wewnętrzny serwera, coś poszło nie tak na serwerze.

### Przykład odpowiedzi błędu

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "pobieranie nie powiodło się"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
