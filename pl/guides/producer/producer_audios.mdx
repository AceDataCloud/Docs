W tym artykule zostanie przedstawiona instrukcja integracji z Producer Audios Generation API, które umożliwia generowanie oficjalnej muzyki Producer poprzez wprowadzenie niestandardowych parametrów.

## Proces składania wniosku

Aby korzystać z Producer Audios Generation API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany ani zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i logowania; po zakończeniu automatycznie powrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności składania osobnego wniosku dla każdej usługi.** Przy pierwszym wniosku otrzymasz bezpłatny limit, aby móc korzystać z bezpłatnego okresu próbnego; gdy limit będzie niewystarczający, możesz doładować wspólne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Podstawowe użycie

O jakich piosenkach myślisz, możesz dowolnie wpisać fragment tekstu, na przykład jeśli chcę wygenerować piosenkę o Bożym Narodzeniu, mogę wpisać `a song for Christmas`, jak pokazano na rysunku:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Można zobaczyć, że tutaj ustawiliśmy Request Headers, w tym:

- `accept`: format odpowiedzi, który chcesz otrzymać, tutaj wpisz `application/json`, czyli format JSON.
- `authorization`: klucz do wywoływania API, po złożeniu wniosku można go bezpośrednio wybrać z listy rozwijanej.

Ponadto parametry Request Body obejmują:

- `action`: działanie tego zadania generowania muzyki, generowanie piosenki to `generate`.
- `model`: model używany do tworzenia piosenki, obecnie głównie: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: treść tekstu piosenki.
- `custom`: czy piosenka jest generowana w trybie niestandardowym.
- `prompt`: podpowiedź w trybie inspiracji.
- `title`: informacje o tytule piosenki.
- `audio_id`: ID piosenki referencyjnej, używane do operacji takich jak kontynuacja/tworzenie coveru.
- `continue_at`: kontynuowanie piosenki od określonej liczby sekund.
- `replace_section_start`/`replace_section_end`: czas rozpoczęcia i zakończenia zastępowanego fragmentu, w sekundach.
- `lyrics_strength`: siła tekstu piosenki, określa stopień wpływu tekstu na generowanie audio, opcjonalnie od 0 do 1, domyślnie 0.7.
- `sound_strength`: siła podpowiedzi audio, opcjonalnie od 0.2 do 1, domyślnie 0.7.
- `cover_strength`: siła coveru, od 0.2 do 1, domyślnie 1.
- `weirdness`: stopień nietypowości stylu, opcjonalnie od 0 do 1, domyślnie 0.5
- `callback_url`: URL, pod który należy zwrócić wynik wywołania zwrotnego.
- `async`: opcjonalnie, gdy ustawione na `true`, interfejs natychmiast zwraca `task_id`, bez potrzeby podawania `callback_url`, a następnie wynik jest uzyskiwany przez odpytywanie odpowiedniego interfejsu zapytań o zadania.
- `instrumental`: czy jest to tryb bez tekstu piosenki.

Ponadto, jeśli chcesz wygenerować odpowiedni kod integracji, możesz go bezpośrednio skopiować, na przykład kod CURL wygląda następująco:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Cover piosenki

Jeśli chcesz wykonać operację coveru na już wygenerowanej piosence, możesz wprowadzić wygenerowaną powyżej piosenkę do wykonania coveru; następnie będziemy niestandardowo generować piosenkę na podstawie słów i tytułu.

Jeśli chcesz kontynuować wykonywanie coveru piosenki przesłanej przez siebie, możesz ustawić parametr `action` na `upload_cover` oraz wprowadzić ID piosenki przesłanej niestandardowo, dla której chcesz kontynuować wykonywanie coveru. ID piosenki można uzyskać za pomocą [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), jak pokazano na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Można wtedy określić następującą zawartość:

- action：działanie dla tego zadania piosenki, obecnie obsługiwane są: generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation; dla tego coveru używany jest parametr `cover`.
- lyric：tekst słów piosenki
- title：tytuł piosenki.
- custom：czy generować w trybie niestandardowym, domyślnie jest false.
- audio_id：ID piosenki, dla której ma zostać wykonany cover.

## Asynchroniczne wywołanie zwrotne

Ponieważ czas generowania przez Producer Audios Generation API może czasami być stosunkowo długi, jeśli API nie odpowiada przez długi czas, żądanie HTTP będzie stale utrzymywać połączenie, co prowadzi do dodatkowego zużycia zasobów systemowych, dlatego to API zapewnia również obsługę asynchronicznego wywołania zwrotnego.

Ogólny proces jest następujący: gdy klient inicjuje żądanie, dodatkowo określa pole `callback_url`, po zainicjowaniu przez klienta żądania API, API natychmiast zwróci wynik zawierający informację o polu `task_id`, które reprezentuje bieżące ID zadania. Po ukończeniu zadania wynik zadania generowania zostanie wysłany w formie POST JSON na `callback_url` określony przez klienta, który również zawiera pole `task_id`, dzięki czemu wyniki zadań mogą zostać powiązane za pomocą ID.

Poniżej na przykładzie poznamy szczegółowo, jak to zrobić.

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informację. Na przykład:

- `400 token_mismatched`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`：Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`：Zbyt wiele żądań, przekroczono limit częstotliwości.
- `500 api_error`：Wewnętrzny błąd serwera, coś poszło nie tak na serwerze.

### Przykład odpowiedzi z błędem

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
