W tym dokumencie przedstawimy instrukcję integracji z Producent Audios Generation API, która umożliwia generowanie oficjalnej muzyki Producenta za pomocą wprowadzonych parametrów.

## Proces aplikacji

Aby skorzystać z Producent Audios Generation API, najpierw przejdź do [Ace Data Cloud Console](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API, który należy zachować na przyszłość.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować, a po zakończeniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

**Jeden token API wystarczy do korzystania ze wszystkich usług platformy, nie ma potrzeby składania osobnych wniosków dla każdej usługi.** Przy pierwszym wniosku otrzymasz darmowy limit, aby móc go przetestować; w przypadku niewystarczającego limitu możesz doładować saldo ogólne w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Producent Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Podstawowe użycie

Chcąc stworzyć piosenkę, możesz wprowadzić dowolny tekst, na przykład, jeśli chcesz wygenerować piosenkę o tematyce świątecznej, możesz wpisać `a song for Christmas`, jak pokazano na obrazku:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Można zauważyć, że ustawiliśmy nagłówki żądania, w tym:

- `accept`: w jakim formacie chcesz otrzymać odpowiedź, tutaj wpisujemy `application/json`, czyli format JSON.
- `authorization`: klucz do wywołania API, po złożeniu wniosku można go bezpośrednio wybrać z rozwijanej listy.

Dodatkowo parametry ciała żądania obejmują:

- `action`: działanie związane z generowaniem muzyki, w przypadku generowania piosenki to `generate`.
- `model`: model używany do tworzenia piosenki, obecnie dostępne są głównie: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**, **FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: treść tekstu piosenki.
- `custom`: czy piosenka ma być generowana w sposób niestandardowy.
- `prompt`: słowo kluczowe w trybie inspiracji.
- `title`: informacja o tytule piosenki.
- `audio_id`: ID referencyjnej piosenki, używane do kontynuacji/odtworzenia itp.
- `continue_at`: kontynuacja od określonej sekundy.
- `replace_section_start`/`replace_section_end`: czas rozpoczęcia i zakończenia wymiany fragmentu, w sekundach.
- `lyrics_strength`: siła tekstu, wskazująca na wpływ tekstu na generowanie audio, opcjonalnie od 0 do 1, domyślnie 0.7.
- `sound_strength`: siła słowa kluczowego audio, opcjonalnie od 0.2 do 1, domyślnie 0.7.
- `cover_strength`: siła coveru od 0.2 do 1, domyślnie 1.
- `weirdness`: stopień dziwności stylu, opcjonalnie od 0 do 1, domyślnie 0.5.
- `callback_url`: URL, na który mają być zwracane wyniki.
- `async`: opcjonalnie, ustawione na `true`, interfejs natychmiast zwraca `task_id`, nie ma potrzeby podawania `callback_url`, a następnie można uzyskać wyniki, wykonując zapytania do odpowiedniego interfejsu zadań.
- `instrumental`: czy ma to być tryb bez tekstu.

Można zauważyć, że otrzymaliśmy informacje o muzyce, którą chcieliśmy wygenerować, wystarczy, że na podstawie adresu linku audio w `data` uzyskamy wygenerowaną muzykę Producenta.

Jeśli chcesz wygenerować odpowiedni kod do integracji, możesz go bezpośrednio skopiować, na przykład kod CURL wygląda następująco:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Przykład coveru piosenki

Jeśli chcesz wykonać cover już wygenerowanej piosenki, możesz wprowadzić wcześniej wygenerowaną piosenkę do wykonania coveru, następnie musimy dostosować generację piosenki na podstawie tekstu, tytułu.

Jeśli chcesz kontynuować wykonywanie coveru swojej przesłanej piosenki, możesz ustawić parametr `action` na `upload_cover` i wprowadzić ID piosenki, którą chcesz kontynuować, ID piosenki można uzyskać za pomocą [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), jak pokazano na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Możesz określić następujące treści:

- action：działanie zadania piosenki, obecnie wspiera: generate, cover, extend, upload_cover, upload_extend, replace_section, swap_vocals, swap_instrumentals, variation, w tym przypadku używamy parametru `cover`.
- lyric：tekst piosenki
- title：tytuł piosenki.
- custom：czy używać trybu niestandardowego do generacji, domyślnie jest false.
- audio_id：ID piosenki, którą chcesz wykonać cover.

## Asynchroniczne wywołanie zwrotne

Ponieważ czas generacji API Producer Audios może być czasami stosunkowo długi, jeśli API nie odpowiada przez dłuższy czas, żądanie HTTP będzie utrzymywać połączenie, co prowadzi do dodatkowego zużycia zasobów systemowych, dlatego to API oferuje również wsparcie dla asynchronicznych wywołań zwrotnych.

Cały proces polega na tym, że klient inicjuje żądanie, dodatkowo określając pole `callback_url`, po zainicjowaniu żądania API, API natychmiast zwraca wynik, zawierający pole `task_id`, które reprezentuje aktualne ID zadania. Gdy zadanie zostanie zakończone, wynik generacji zadania zostanie wysłany do określonego przez klienta `callback_url` w formie POST JSON, w tym również zawierając pole `task_id`, dzięki czemu wynik zadania można powiązać za pomocą ID.

Poniżej przyjrzymy się, jak dokładnie to działa na przykładzie.

Po pierwsze, wywołanie zwrotne Webhook to usługa, która może odbierać żądania HTTP, deweloperzy powinni zastąpić to URL swojego własnego serwera HTTP. W tym celu, dla wygody demonstracji, użyjemy publicznej strony przykładowej Webhook [https://webhook.site/](https://webhook.site/), otwierając tę stronę, można uzyskać URL Webhook, jak pokazano na obrazku:

![](https://cdn.acedata.cloud/tbcnai.png)

Skopiuj ten URL, aby użyć go jako Webhook, przykładowy URL to [https://webhook.site/#!/view/0d73431d-f833-4be4-9276-b6e1690d55c1](https://webhook.site/#!/view/0d73431d-f833-4be4-9276-b6e1690d55c1).

Następnie możemy ustawić pole `callback_url` na powyższy URL Webhook, a także wypełnić odpowiednie parametry, szczegóły jak na obrazku:

<p><img src="https://cdn.acedata.cloud/wuzd4y.png" width="500" className="m-auto" /></p>

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Nieautoryzowany, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczyłeś limit szybkości.
- `500 api_error`: Błąd wewnętrzny serwera, coś poszło nie tak na serwerze.
