Główną funkcją API Zadań Producenta jest możliwość sprawdzenia statusu wykonania zadania poprzez wprowadzenie ID zadania wygenerowanego przez API Generacji Dźwięków Producenta.

Dokument ten szczegółowo opisuje integrację API Zadań Producenta, aby pomóc Ci łatwo zintegrować i w pełni wykorzystać potężne możliwości tego API. Dzięki API Zadań Producenta możesz łatwo sprawdzić status wykonania zadań API Generacji Dźwięków Producenta.

## Proces aplikacji

Aby korzystać z API Zadań Producenta, najpierw należy przejść do strony aplikacji [API Generacji Dźwięków Producenta](https://platform.acedata.cloud/documents/producer-audios) i złożyć wniosek o odpowiednią usługę, a następnie skopiować ID zadania API Generacji Dźwięków Producenta, jak pokazano na obrazku:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Na koniec przejdź do strony API Zadań [API Zadań Producenta](https://platform.acedata.cloud/documents/622626b1-30a7-4799-a772-4946e1df3ac0) i złóż wniosek o odpowiednią usługę, po wejściu na stronę kliknij przycisk „Acquire”, jak pokazano na obrazku:

![Strona aplikacji](https://cdn.acedata.cloud/rci31i.png)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na [stronę logowania](https://platform.acedata.cloud), aby zarejestrować się i zalogować, po zalogowaniu lub rejestracji automatycznie wrócisz na bieżącą stronę.

Podczas pierwszej aplikacji otrzymasz darmowy limit, który pozwala na bezpłatne korzystanie z tego API.

## Przykład żądania

API Zadań Producenta może być używane do sprawdzania wyników API Generacji Dźwięków Producenta. Aby dowiedzieć się, jak korzystać z API Generacji Dźwięków Producenta, zapoznaj się z dokumentem [API Generacji Dźwięków Producenta](https://platform.acedata.cloud/documents/producer-audios-integration).

Użyjemy jako przykładu ID zadania zwróconego przez usługę API Generacji Dźwięków Producenta. Załóżmy, że mamy ID zadania: 1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad, a następnie pokażemy, jak to zrobić, przekazując ID zadania.

### Przykład zadania

### Ustawienia nagłówków żądania i ciała żądania

**Nagłówki żądania** obejmują:

- `accept`: określa, że oczekiwany jest wynik odpowiedzi w formacie JSON, tutaj wpisz `application/json`.
- `authorization`: klucz do wywołania API, po złożeniu wniosku można go bezpośrednio wybrać z rozwijanej listy.

**Ciało żądania** obejmuje:

- `id`: ID przesłanego zadania.
- `action`: sposób operacji na zadaniu.

Ustawienia są pokazane na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/bfe4ww.png" width="500" className="m-auto" /></p>

### Przykład kodu

Można zauważyć, że po prawej stronie strony automatycznie wygenerowano różne kody w różnych językach, jak pokazano na obrazku:

<p><img src="https://cdn.acedata.cloud/u4pb2f.png" width="500" className="m-auto" /></p>

Niektóre przykłady kodu są następujące:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Nieautoryzowany, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`: Błąd wewnętrzny serwera, coś poszło nie tak na serwerze.

### Przykład odpowiedzi błędu

    "message": "pobieranie nie powiodło się"

}
