Główną funkcją API zadań producenta jest możliwość sprawdzenia statusu wykonania zadania za pomocą ID zadania wygenerowanego przez API generacji audio producenta.

Dokument ten szczegółowo opisuje integrację API zadań producenta, aby pomóc Ci łatwo zintegrować i w pełni wykorzystać potężne możliwości tego API. Dzięki API zadań producenta możesz łatwo sprawdzić status wykonania zadań API generacji audio producenta.

## Proces aplikacji

Aby korzystać z API generacji audio producenta, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API, który należy zachować na przyszłość.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować, a po zakończeniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

**Jeden token API wystarczy do wywołania wszystkich usług platformy, nie ma potrzeby składania osobnych wniosków dla każdej usługi.** Pierwsze zgłoszenie daje darmowy limit, który można wykorzystać bezpłatnie; w przypadku niewystarczającego limitu można doładować saldo ogólne w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [API generacji audio producenta →](https://platform.acedata.cloud/documents/producer-audios)

## Przykład żądania

API zadań producenta może być używane do sprawdzania wyników API generacji audio producenta. Aby dowiedzieć się, jak korzystać z API generacji audio producenta, zapoznaj się z dokumentacją [API generacji audio producenta](https://platform.acedata.cloud/documents/producer-audios-integration).

### Ustawienie nagłówków żądania i ciała żądania

**Nagłówki żądania** obejmują:

- `accept`: określa, że oczekiwany jest wynik w formacie JSON, tutaj wpisz `application/json`.
- `authorization`: klucz do wywołania API, po złożeniu wniosku można go bezpośrednio wybrać z rozwijanej listy.

**Ciało żądania** obejmuje:

- `id`: ID przesłanego zadania.
- `action`: sposób operacji na zadaniu.

Ustawienia są pokazane na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/bfe4ww.png" width="500" className="m-auto" /></p>

### Przykład kodu

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpią błędy, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`：Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`：Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`：Nieautoryzowany, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`：Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`：Błąd wewnętrzny serwera, coś poszło nie tak na serwerze.
