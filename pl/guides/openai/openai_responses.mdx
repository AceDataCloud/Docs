OpenAI niedawno udostępniło interfejs do tworzenia odpowiedzi modeli. Udostępniaj wejścia tekstowe lub obrazowe, aby generować wyjścia tekstowe lub obrazowe. Pozwól modelowi wywoływać własny niestandardowy kod lub używać wbudowanych narzędzi, takich jak wyszukiwanie w sieci lub wyszukiwanie plików, aby używać własnych danych jako wejścia dla odpowiedzi modelu.

Ten dokument przedstawia głównie proces korzystania z operacji OpenAI Responses API, dzięki któremu możemy łatwo korzystać z oficjalnej funkcji OpenAI do tworzenia odpowiedzi modeli.

## Proces wnioskowania

Aby korzystać z OpenAI Responses API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany ani zarejestrowany, nastąpi automatyczne przekierowanie na stronę logowania z zaproszeniem do rejestracji i zalogowania się, a po zakończeniu automatycznie powrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności osobnego wnioskowania dla każdej usługi.** Przy pierwszym wnioskowaniu otrzymasz bezpłatny limit, który pozwala na darmowe wypróbowanie; gdy limit jest niewystarczający, możesz doładować wspólne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Podstawowe użycie

Następnie możesz wypełnić odpowiednią zawartość w interfejsie, jak pokazano na ilustracji:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Przy pierwszym użyciu tego interfejsu musimy wypełnić co najmniej trzy elementy, jednym z nich jest `authorization`, który można bezpośrednio wybrać z listy rozwijanej. Kolejnym parametrem jest `model`, `model` to wybrana przez nas kategoria modelu z oficjalnej strony OpenAI ChatGPT, tutaj mamy głównie 20 modeli, szczegóły można zobaczyć w udostępnionych przez nas modelach. Ostatnim parametrem jest `input`, `input` to tablica wprowadzanych przez nas zapytań, jest to tablica, co oznacza, że można jednocześnie przesłać wiele zapytań, każde zapytanie zawiera `role` i `content`, gdzie `role` oznacza rolę osoby zadającej pytanie, udostępniamy trzy tożsamości, a mianowicie `user`, `assistant`, `system`. Kolejne `content` to konkretna treść naszego zapytania.

Jednocześnie możesz zauważyć, że po prawej stronie znajduje się generowanie odpowiedniego kodu wywołania, możesz skopiować kod i uruchomić go bezpośrednio, możesz też bezpośrednio kliknąć przycisk „Try”, aby przeprowadzić test.

Często używane opcjonalne parametry:

- `max_tokens`: ogranicza maksymalną liczbę tokenów w pojedynczej odpowiedzi.
- `temperature`: losowość generowania, między 0 a 2, im większa wartość, tym większa rozbieżność.
- `n`: ile odpowiedzi kandydujących wygenerować jednocześnie.
- `response_format`: ustawienie formatu zwracanego wyniku.
- `tools`: definicja wywołań funkcji/narzędzi.
- `background`: czy uruchamiać asynchronicznie w tle.

## Odpowiedź strumieniowa

Ten interfejs obsługuje również odpowiedzi strumieniowe, co jest bardzo przydatne przy integracji ze stronami internetowymi i pozwala stronie osiągnąć efekt wyświetlania znak po znaku.

Jeśli chcesz zwracać odpowiedź strumieniowo, możesz zmienić parametr `stream ` w nagłówku żądania na `true`.

Modyfikacja jest pokazana na ilustracji, jednak kod wywołania musi zostać odpowiednio zmieniony, aby obsługiwać odpowiedź strumieniową.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Po zmianie `stream` na `true`, API będzie zwracać odpowiednie dane JSON wiersz po wierszu, a na poziomie kodu musimy wprowadzić odpowiednie zmiany, aby uzyskać wyniki wiersz po wierszu.

Przykładowy kod wywołania Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Można zauważyć, że odpowiedź zawiera wiele `data`, a `delta` w `data` jest najnowszą treścią odpowiedzi, zgodną z treścią przedstawioną powyżej. `delta` to nowo dodana treść odpowiedzi, którą możesz zintegrować ze swoim systemem na podstawie wyniku. Odpowiedź strumieniowa osiąga stan końcowy jako `response.completed` lub `response.incomplete`; `usage` w stanie końcowym to końcowe zużycie tokenów dla tego żądania, które stanowi również podstawę rozliczenia.

Jeśli klient rozłączy się przed osiągnięciem stanu końcowego, to żądanie zostanie zarejestrowane jako zamknięte przez klienta (499) i nie zostanie rozliczone na podstawie lokalnie szacowanych tokenów; jeśli połączenie zakończy się normalnie, ale nie zostanie odebrany stan końcowy ani końcowe `usage`, to żądanie zostanie zarejestrowane jako niekompletna odpowiedź (502) i również nie zostanie rozliczone na podstawie szacowanych tokenów. W przypadku wystąpienia tych dwóch sytuacji ponownie wyślij żądanie.

Zwrócony wynik `data` zawiera wiele pól, opisanych poniżej:

- `item_id`, ID zadania dialogowego wygenerowanego tym razem, używane do jednoznacznej identyfikacji tego zadania dialogowego.
- `type`, typ wygenerowanego tym razem zadania dialogowego Responses.
- `model `, wybrany model OpenAI ChatGPT z oficjalnej strony.
- `delta`, informacje odpowiedzi udzielone przez ChatGPT na zapytanie.

JavaScript jest również obsługiwany, na przykład kod wywołania strumieniowego w Node.js wygląda następująco:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Model wizyjny

gpt-4o to multimodalny duży model językowy opracowany przez OpenAI, który na podstawie GPT-4 zyskał zdolność rozumienia obrazu. Ten model może jednocześnie przetwarzać dane wejściowe w postaci tekstu i obrazów, realizując rozumienie i generowanie między modalnościami.
```
Przetwarzanie tekstu przy użyciu modelu gpt-4o jest zgodne z podstawową treścią użycia opisaną powyżej, poniżej zostanie krótko przedstawione, jak korzystać z możliwości przetwarzania obrazów przez model.

Korzystanie z możliwości przetwarzania obrazów przez model gpt-4o polega głównie na dodaniu pola `type` na podstawie pierwotnej zawartości `content`, dzięki temu polu można określić, czy przesyłany jest tekst, czy obraz, aby następnie korzystać z możliwości przetwarzania obrazów przez model gpt-4o. Poniżej opisano głównie wywoływanie tej funkcji za pomocą dwóch metod: Curl i Python.

- Metoda skryptu Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Metoda skryptu Python

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informację. Na przykład:

- `400 token_mismatched`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`: Wewnętrzny błąd serwera, coś poszło nie tak na serwerze.

}
```
