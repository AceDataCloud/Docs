OpenAI niedawno udostępniło interfejs do tworzenia odpowiedzi modeli. Udostępniaj dane wejściowe w postaci tekstu lub obrazów, aby generować dane wyjściowe w postaci tekstu lub obrazów. Pozwól modelowi wywoływać własny niestandardowy kod lub korzystać z wbudowanych narzędzi, takich jak wyszukiwanie w sieci lub wyszukiwanie plików, aby używać własnych danych jako danych wejściowych dla odpowiedzi modelu.

Ten dokument przedstawia głównie proces korzystania z OpenAI Responses API, dzięki któremu możemy łatwo korzystać z oficjalnej funkcji OpenAI do tworzenia odpowiedzi modeli.

## Proces składania wniosku

Aby korzystać z OpenAI Responses API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, aby zostać zaproszonym do rejestracji i logowania, a po zakończeniu automatycznie wrócisz na obecną stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności osobnego składania wniosku dla każdej usługi.** Przy pierwszym wniosku otrzymasz bezpłatny limit, z którego możesz korzystać bezpłatnie; gdy limit będzie niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Podstawowe użycie

Następnie możesz wypełnić odpowiednią zawartość w interfejsie, jak pokazano na ilustracji:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Przy pierwszym użyciu tego interfejsu musimy wypełnić co najmniej trzy elementy: jednym z nich jest `authorization`, który można wybrać bezpośrednio z listy rozwijanej. Kolejnym parametrem jest `model`, `model` oznacza kategorię modelu z oficjalnej strony OpenAI ChatGPT, z której wybieramy do użycia; tutaj mamy głównie 20 modeli, szczegóły można sprawdzić w udostępnionych przez nas modelach. Ostatnim parametrem jest `input`, `input` to tablica wprowadzanych przez nas zapytań, jest to tablica, co oznacza, że można jednocześnie przesłać wiele zapytań, każde zapytanie zawiera `role` i `content`, gdzie `role` oznacza rolę pytającego, udostępniamy trzy tożsamości: `user`, `assistant`, `system`. Drugie `content` to konkretna treść naszego zapytania.

Jednocześnie możesz zauważyć, że po prawej stronie generowany jest odpowiedni kod wywołania, możesz skopiować kod i uruchomić go bezpośrednio, możesz też bezpośrednio kliknąć przycisk „Try”, aby przeprowadzić test.

Często używane opcjonalne parametry:

- `max_tokens`: ogranicza maksymalną liczbę tokenów pojedynczej odpowiedzi.
- `temperature`: losowość generowania, od 0 do 2, im większa wartość, tym bardziej rozproszone wyniki.
- `n`: ile kandydackich odpowiedzi generować jednocześnie.
- `response_format`: ustawienie formatu zwracanych danych.
- `tools`: definicja wywołań funkcji/narzędzi.
- `background`: czy uruchamiać asynchronicznie w tle.

## Odpowiedź strumieniowa

Ten interfejs obsługuje również odpowiedzi strumieniowe, co jest bardzo przydatne przy integracji ze stronami internetowymi i pozwala stronie osiągnąć efekt wyświetlania znak po znaku.

Jeśli chcesz zwracać odpowiedź strumieniowo, możesz zmienić parametr `stream ` w nagłówku żądania na `true`.

Modyfikacja jest pokazana na ilustracji, jednak kod wywołania musi zostać odpowiednio zmieniony, aby obsługiwać odpowiedź strumieniową.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Po zmianie `stream` na `true` API będzie zwracać odpowiednie dane JSON wiersz po wierszu, a na poziomie kodu musimy wprowadzić odpowiednie zmiany, aby uzyskać wyniki wiersz po wierszu.

Przykładowy kod wywołania w Pythonie:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Odpowiedź strumieniowa ma `response.completed` lub `response.incomplete` jako stan końcowy; `usage` w stanie końcowym to ostateczne użycie tokenów dla tego żądania, a także podstawa naliczenia opłat.

Jeśli klient rozłączy się przed osiągnięciem stanu końcowego, to żądanie zostanie zarejestrowane jako zamknięte przez klienta (499) i nie zostanie rozliczone na podstawie lokalnie oszacowanych tokenów; jeśli połączenie zakończy się normalnie, ale nie zostanie otrzymany stan końcowy ani końcowe `usage`, to żądanie zostanie zarejestrowane jako niekompletna odpowiedź (502) i również nie zostanie rozliczone na podstawie oszacowanych tokenów. W przypadku wystąpienia tych dwóch sytuacji należy ponownie wysłać żądanie.

Zwrócony wynik `data` zawiera wiele pól, opisanych poniżej:

- `item_id`, ID wygenerowanego zadania tej rozmowy, używane do jednoznacznej identyfikacji tego zadania rozmowy.
- `type`, typ wygenerowanego zadania Responses tej rozmowy.
- `model `, wybrany model z oficjalnej strony OpenAI ChatGPT.
- `delta`, informacje odpowiedzi udzielone przez ChatGPT na zadane pytanie.

JavaScript jest również obsługiwany, na przykład kod wywołania strumieniowego w Node.js jest następujący:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

Przykładowy kod Java:

```java
JSONObject jsonObject = new JSONObject();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.print(response.body!!.string())
```

## Model wizualny

gpt-4o to wielomodalny duży model językowy opracowany przez OpenAI, który na podstawie GPT-4 zyskał zdolność rozumienia obrazu. Ten model może jednocześnie przetwarzać dane wejściowe w postaci tekstu i obrazów, realizując rozumienie i generowanie między modalnościami.
Przetwarzanie tekstu za pomocą modelu gpt-4o jest zgodne z podstawową zawartością użycia opisaną powyżej, poniżej krótko przedstawiono, jak korzystać ze zdolności modelu do przetwarzania obrazów.

Korzystanie ze zdolności modelu gpt-4o do przetwarzania obrazów polega głównie na dodaniu pola `type` na podstawie pierwotnej zawartości `content`, poprzez to pole można określić, czy przesyłany jest tekst, czy obraz, a tym samym korzystać ze zdolności modelu gpt-4o do przetwarzania obrazów. Poniżej opisano głównie wywoływanie tej funkcji na dwa sposoby: za pomocą Curl i Python.

- Sposób skryptu Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`: Wewnętrzny błąd serwera, coś poszło nie tak na serwerze.
