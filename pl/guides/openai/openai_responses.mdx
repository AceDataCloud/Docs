Żądania zgodnych modeli akceptowane przez platformę są rozliczane według zużycia wejścia, wyjścia i pamięci podręcznej modelu. Łączna liczba tokenów wejściowych Responses obejmuje zgłoszone tokeny pamięci podręcznej, a część z pamięci podręcznej jest rozliczana według odpowiedniej ceny pamięci podręcznej; zmiana formatu interfejsu nie powoduje przejścia na stałą opłatę za liczbę wywołań. Opłaty są określane na podstawie aktualnych cen modeli w konsoli oraz `usage.cost` w odpowiedzi.

OpenAI niedawno udostępniło interfejs do tworzenia odpowiedzi modelu. Dostarczaj wejście tekstowe lub obrazowe, aby generować wyjście tekstowe lub obrazowe. Pozwól modelowi wywoływać własny niestandardowy kod lub korzystać z wbudowanych narzędzi, takich jak wyszukiwanie w sieci lub wyszukiwanie plików, aby używać własnych danych jako wejścia dla odpowiedzi modelu.

Ten dokument przedstawia głównie proces korzystania z OpenAI Responses API, dzięki któremu możemy łatwo używać oficjalnej funkcji OpenAI do tworzenia odpowiedzi modelu.

## GPT-6.1 Terra

Użyj `model: "gpt-6.1-terra"`, aby wybrać ten model. Obsługuje wejście tekstowe i obrazowe, wyjście strumieniowe, narzędzia funkcyjne oraz ustrukturyzowane wyjście. Obsługiwane poziomy rozumowania to `low`, `medium`, `high`, `xhigh` i `max`; zaleca się rozpocząć od `reasoning: {"effort": "low"}`; nie obsługuje `none` ani `minimal`. Gdy wejście przekracza 272 000 tokenów, obowiązuje cena za długi kontekst, a rzeczywisty koszt zależy od aktualnej ceny w konsoli i użycia w odpowiedzi.

## GPT-6.1 Sol

Użyj `model: "gpt-6.1-sol"`, aby wybrać ten model. Obsługuje wyjście strumieniowe, wywoływanie funkcji, ustrukturyzowane wyjście i wejście obrazowe. W ciągu pierwszego tygodnia od udostępnienia jest dostępny wyłącznie dla zweryfikowanych posiadaczy ACE T1+ (co najmniej 100 000 ACE) lub upoważnionych użytkowników; szczegółowy czas udostępnienia zależy od komunikatu o dostępie w konsoli.

Obsługiwane poziomy rozumowania to `low`, `medium`, `high`, `xhigh` i `max`; `none` ani `minimal` nie są obecnie obsługiwane. Zaleca się rozpocząć od `reasoning: {"effort": "low"}`. Gdy wejście przekracza 272 000 tokenów, cena za długi kontekst obowiązuje dla całego żądania, a opłata zależy od aktualnej ceny w konsoli.

## Proces składania wniosku

Aby korzystać z OpenAI Responses API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go jako zapasowy.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany ani zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i zalogowania się, a po zakończeniu automatycznie powrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności składania osobnego wniosku dla każdej usługi.** Przy pierwszym wniosku otrzymasz darmowy limit, który pozwala na bezpłatne testowanie; gdy limit jest niewystarczający, możesz doładować wspólne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Podstawowe użycie

Następnie możesz wypełnić odpowiednią zawartość w interfejsie, jak pokazano na ilustracji:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Przy pierwszym użyciu tego interfejsu musimy wypełnić co najmniej trzy elementy. Jednym z nich jest `authorization`, który można bezpośrednio wybrać z listy rozwijanej. Kolejnym parametrem jest `model`, `model` to wybrana przez nas kategoria modelu z oficjalnej strony OpenAI ChatGPT; tutaj mamy głównie 20 modeli, szczegóły można zobaczyć w udostępnionych przez nas modelach. Ostatnim parametrem jest `input`, `input` to tablica wprowadzanych przez nas promptów; jest to tablica, co oznacza, że można jednocześnie przesłać wiele promptów, a każdy prompt zawiera `role` i `content`, gdzie `role` oznacza rolę osoby zadającej pytanie, oferujemy trzy tożsamości: `user`, `assistant`, `system`. Drugie `content` to konkretna treść naszego pytania.

Jednocześnie możesz zauważyć, że po prawej stronie generowany jest odpowiedni kod wywołania. Możesz skopiować kod i uruchomić go bezpośrednio, a także bezpośrednio kliknąć przycisk „Try”, aby przeprowadzić test.

Często używane parametry opcjonalne:

- `max_tokens`: ogranicza maksymalną liczbę tokenów w pojedynczej odpowiedzi.
- `temperature`: losowość generowania, od 0 do 2; im większa wartość, tym bardziej rozbieżny wynik.
- `n`: ile kandydatów na odpowiedź wygenerować jednorazowo.
- `response_format`: ustawienie formatu zwracanego wyniku.
- `tools`: definicje wywołań funkcji/narzędzi.
- `background`: czy uruchamiać asynchronicznie w tle.

## Odpowiedź strumieniowa

Ten interfejs obsługuje również odpowiedzi strumieniowe, co jest bardzo przydatne przy integracji ze stroną internetową i umożliwia uzyskanie efektu wyświetlania znak po znaku.

Jeśli chcesz zwracać odpowiedzi strumieniowo, możesz zmienić parametr `stream ` w nagłówku żądania na `true`.

Zmiana jest pokazana na ilustracji, jednak kod wywołania musi zostać odpowiednio zmieniony, aby obsługiwać odpowiedzi strumieniowe.
<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Po zmianie `stream` na `true` API będzie zwracać odpowiednie dane JSON wiersz po wierszu, a na poziomie kodu musimy wprowadzić odpowiednie zmiany, aby uzyskać wyniki wiersz po wierszu.

Przykładowy kod wywołania w Pythonie:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Można zauważyć, że w odpowiedzi znajduje się wiele `data`, a `delta` w `data` jest najnowszą treścią odpowiedzi, co jest zgodne z treścią przedstawioną powyżej. `delta` jest nowo dodaną treścią odpowiedzi, którą można na podstawie wyniku zintegrować z własnym systemem. Odpowiedź strumieniowa ma jako stan końcowy `response.completed` lub `response.incomplete`; `usage` w stanie końcowym jest końcowym zużyciem tokenów dla tego żądania i stanowi również podstawę rozliczenia.

Jeśli klient rozłączy się przed osiągnięciem stanu końcowego, to żądanie zostanie zapisane jako zamknięte przez klienta (499) i nie zostanie rozliczone na podstawie lokalnie szacowanych tokenów; jeśli połączenie zakończy się normalnie, ale nie zostanie otrzymany stan końcowy ani końcowe `usage`, to żądanie zostanie zapisane jako niekompletna odpowiedź (502) i również nie zostanie rozliczone na podstawie szacowanych tokenów. W przypadku wystąpienia tych dwóch sytuacji należy ponownie wysłać żądanie.

Zwrócony wynik `data` zawiera łącznie wiele pól, opisanych poniżej:

- `item_id`, ID wygenerowanego zadania tej rozmowy, używane do jednoznacznej identyfikacji tego zadania rozmowy.
- `type`, typ wygenerowanego zadania Responses tej rozmowy.
- `model `, wybrany model z oficjalnej strony OpenAI ChatGPT.
- `delta`, informacje odpowiedzi udzielonej przez ChatGPT na słowa pytania.

JavaScript jest również obsługiwany, na przykład kod wywołania strumieniowego w Node.js jest następujący:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Wieloturowa rozmowa

Jeśli chcesz zintegrować funkcję wieloturowej rozmowy, musisz przesłać wiele słów pytań w polu `input`, a konkretny przykład wielu słów pytań pokazano na poniższym obrazku:

Przykładowy kod wywołania w Pythonie:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"},{"role":"assistant","content":"Hello! How can I help you today? 😊"},{"role":"user","content":"What did I just say?"}]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Model wizualny

gpt-4o to wielomodalny duży model językowy opracowany przez OpenAI, który na bazie GPT-4 dodaje zdolność rozumienia obrazu. Model ten może jednocześnie przetwarzać dane wejściowe w postaci tekstu i obrazów, umożliwiając rozumienie i generowanie między modalnościami.

Przetwarzanie tekstu przy użyciu modelu gpt-4o jest zgodne z treścią podstawowego użycia opisaną powyżej, poniżej zostanie krótko przedstawione, jak korzystać ze zdolności modelu do przetwarzania obrazów.

Korzystanie ze zdolności przetwarzania obrazów modelu gpt-4o polega głównie na dodaniu pola `type` na podstawie pierwotnej zawartości `content`; za pomocą tego pola można określić, czy przesyłany jest tekst, czy obraz, a tym samym korzystać ze zdolności przetwarzania obrazów modelu gpt-4o. Poniżej opisano głównie wywołanie tej funkcji na dwa sposoby: Curl i Python.

- Metoda skryptu Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Metoda skryptu Python

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`：Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`：Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`：Wewnętrzny błąd serwera, coś poszło nie tak po stronie serwera.
