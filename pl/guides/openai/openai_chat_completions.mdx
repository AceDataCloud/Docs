OpenAI ChatGPT to bardzo potężny system konwersacyjny AI, który wystarczy zasilić poleceniem, aby w zaledwie kilka sekund wygenerował płynną i naturalną odpowiedź. ChatGPT wyróżnia się w branży dzięki swoim znakomitym możliwościom rozumienia i generowania języka, a obecnie ChatGPT jest już szeroko stosowany w różnych branżach i dziedzinach, a jego wpływ staje się coraz bardziej znaczący. Niezależnie od tego, czy chodzi o codzienne rozmowy, kreatywne pisanie, czy profesjonalne konsultacje i programowanie kodu, ChatGPT może zapewnić zachwycającą inteligentną pomoc, znacznie zwiększając wydajność pracy i kreatywność ludzi.

Ten dokument przedstawia głównie proces korzystania z operacji OpenAI Chat Completion API, dzięki któremu możemy łatwo korzystać z funkcji rozmów oficjalnego OpenAI ChatGPT.

Żądania kompatybilnych modeli akceptowane przez platformę są rozliczane według zużycia danych wejściowych, wyjściowych i pamięci podręcznej danego modelu. `prompt_tokens` w Chat Completions obejmuje tokeny pamięci podręcznej, a zgłoszona część pamięci podręcznej jest rozliczana według odpowiedniej ceny pamięci podręcznej; zmiana formatu interfejsu nie zmienia rozliczenia na stałą opłatę za liczbę wywołań. Opłaty są ustalane na podstawie bieżących cen modeli w konsoli oraz `usage.cost` w odpowiedzi.

## GPT-6.1 Terra

Użyj `model: "gpt-6.1-terra"`, aby wybrać ten model. Obsługuje dane wejściowe tekstowe i obrazowe oraz wyjście strumieniowe; narzędzia funkcyjne i ustrukturyzowane wyjście należy wywoływać zgodnie z formatem parametrów tego interfejsu. Poziomy rozumowania obsługują `low`, `medium`, `high`, `xhigh` i `max`, zaleca się rozpoczęcie od `reasoning_effort: "low"`; `none` ani `minimal` nie są obsługiwane. Gdy dane wejściowe przekraczają 272,000 tokenów, obowiązuje cena za długi kontekst, a rzeczywiste opłaty zależą od bieżącej ceny w konsoli i użycia w odpowiedzi.

## GPT-6.1 Sol

Użyj `model: "gpt-6.1-sol"`, aby wybrać ten model. Obsługuje wyjście strumieniowe, wywoływanie funkcji, ustrukturyzowane wyjście i dane wejściowe obrazowe. W ciągu pierwszego tygodnia od udostępnienia jest dostępny wyłącznie dla zweryfikowanych posiadaczy ACE T1+ (co najmniej 100,000 ACE) lub autoryzowanych użytkowników; szczegółowy czas udostępnienia zależy od komunikatu o dostępie w konsoli.

Poziomy rozumowania obsługują `low`, `medium`, `high`, `xhigh` i `max`, `none` ani `minimal` nie są obecnie obsługiwane. Zaleca się rozpoczęcie od `reasoning_effort: "low"`. Gdy dane wejściowe przekraczają 272,000 tokenów, cena za długi kontekst obowiązuje dla całego żądania, a opłaty zależą od bieżącej ceny w konsoli.

## Proces składania wniosku

Aby korzystać z OpenAI Chat Completion API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i logowania, a po zakończeniu automatycznie powrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności składania osobnego wniosku dla każdej usługi.** Przy pierwszym wniosku otrzymasz darmowy limit, z którego możesz korzystać bezpłatnie; gdy limit będzie niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

## Podstawowe użycie

Następnie możesz wypełnić odpowiednią zawartość w interfejsie, jak pokazano na rysunku:

<p><img src="https://cdn.acedata.cloud/jqgg1t.png" width="400" className="m-auto" /></p>

Podczas pierwszego użycia tego interfejsu musimy wypełnić co najmniej trzy elementy, jednym z nich jest `authorization`, który można wybrać bezpośrednio z listy rozwijanej. Kolejnym parametrem jest `model`, `model` to kategoria modelu z oficjalnej strony OpenAI ChatGPT, którą wybieramy do użycia, tutaj mamy głównie 20 modeli, szczegóły można zobaczyć w udostępnionych przez nas modelach. Ostatnim parametrem jest `messages`, `messages` to tablica wprowadzanych przez nas pytań, jest to tablica, co oznacza, że można jednocześnie przesłać wiele pytań, każde pytanie zawiera `role` i `content`, gdzie `role` oznacza rolę osoby zadającej pytanie, udostępniamy trzy tożsamości, a mianowicie `user`, `assistant`, `system`. Drugie `content` to konkretna treść naszego pytania.

Jednocześnie możesz zauważyć, że po prawej stronie znajduje się generowany odpowiedni kod wywołania, możesz skopiować kod i uruchomić go bezpośrednio, możesz też bezpośrednio kliknąć przycisk „Try”, aby przeprowadzić test.

Często używane opcjonalne parametry:

- `max_tokens`: ogranicza maksymalną liczbę tokenów w pojedynczej odpowiedzi.
- `temperature`: losowość generowania, od 0 do 2, im większa wartość, tym bardziej rozbieżny wynik.
- `n`: ile kandydatów odpowiedzi generować jednorazowo.
- `response_format`: ustawienie formatu zwracanego wyniku.

## Odpowiedź strumieniowa

Ten interfejs obsługuje również odpowiedź strumieniową, co jest bardzo przydatne przy integracji ze stroną internetową i umożliwia uzyskanie efektu wyświetlania znak po znaku.

Jeśli chcesz zwracać odpowiedź strumieniowo, możesz zmienić parametr `stream ` w nagłówku żądania na `true`.

Modyfikacja jest pokazana na rysunku, jednak kod wywołania wymaga odpowiednich zmian, aby obsługiwać odpowiedź strumieniową.

<p><img src="https://cdn.acedata.cloud/24scd4.png" width="400" className="m-auto" /></p>

Po zmianie `stream` na `true`, API będzie zwracać odpowiednie dane JSON wiersz po wierszu, a na poziomie kodu musimy wprowadzić odpowiednie zmiany, aby uzyskać wynik wiersz po wierszu.

Przykładowy kod wywołania w Pythonie:
```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4",
    "messages": [{"role":"user","content":"hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Integracja z OpenAI-Python

OpenAI Chat Completion API zachowuje zgodność z oficjalnym interfejsem OpenAI i może bezpośrednio korzystać z oficjalnego SDK [OpenAI-Python](https://github.com/openai/openai-python) do integracji. W tym artykule krótko przedstawimy sposób użycia.

1. Najpierw należy skonfigurować lokalne środowisko `Python`; ten proces można wyszukać w Google.
2. Pobierz i zainstaluj środowisko programistyczne, na przykład edytor VSCode.
3. Skonfiguruj zmienne środowiskowe `OpenAI`.

- W folderze projektu utwórz plik o nazwie `.env` i zapisz go
- Zawartość pliku `.env`:

```json
OPENAI_API_KEY="sk-xxx"
OPENAI_BASE_URL="https://api.acedata.cloud/openai"  # 再次提醒：如果你使用官网OpenAI的key，不要用这个地址。
```

Zastąp `sk-xxx` własnym kluczem. `OPENAI_BASE_URL` jest pośredniczącym interfejsem API do uzyskiwania dostępu do OpenAI.

4. Zainstaluj pakiety zależne od projektu

```shell
pip install openai
```

W systemie Mac OS polecenie to brzmi:

```shell
pip3 install openai
```

5. Utwórz przykładowy plik kodu źródłowego

Załóżmy, że utworzyliśmy przykładowy kod `index.py`, którego konkretna zawartość jest następująca:

```python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

response = client.chat.completions.create(
    messages=[
        {
            "role": "user",
            "content": "hello",
        }
    ],
    model="gpt-4",
)

print(response.text)
```

## Model wizualny

gpt-4o to multimodalny duży model językowy opracowany przez OpenAI, który na podstawie GPT-4 dodaje zdolność rozumienia obrazu. Model ten może jednocześnie przetwarzać dane wejściowe tekstowe i obrazowe, realizując rozumienie i generowanie między modalnościami.

Przetwarzanie tekstu przy użyciu modelu gpt-4o jest zgodne z opisanym powyżej podstawowym użyciem; poniżej krótko przedstawimy, jak korzystać ze zdolności modelu do przetwarzania obrazów.

Zdolność modelu gpt-4o do przetwarzania obrazów jest wykorzystywana głównie poprzez dodanie pola `type` do pierwotnej zawartości `content`. Za pomocą tego pola można określić, czy przesyłany jest tekst, czy obraz, a tym samym korzystać ze zdolności modelu gpt-4o do przetwarzania obrazów. Poniżej opisano głównie wywoływanie tej funkcji na dwa sposoby: za pomocą Curl i Pythona.

- Metoda skryptu Curl

```
curl -X POST 'https://api.acedata.cloud/openai/chat/completions' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4o",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "What'\''s in this image?"
          },
          {
            "type": "image_url",
            "image_url": {
              "url": "https://upload.wikimedia.org/wikipedia/commons/thumb/d/dd/Gfp-wisconsin-madison-the-nature-boardwalk.jpg/2560px-Gfp-wisconsin-madison-the-nature-boardwalk.jpg"
            }
          }
        ]
      }
    ]
  }'
```

- Metoda skryptu Python
```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4o",
    "messages": [
        {
            "role": "user",
            "content": [
                {
                    "type": "text", "text": "What's in this image?"
                },
                {
                    "type": "image_url",
                    "image_url": {
                        "url": "https://upload.wikimedia.org/wikipedia/commons/thumb/d/dd/Gfp-wisconsin-madison-the-nature-boardwalk.jpg/2560px-Gfp-wisconsin-madison-the-nature-boardwalk.jpg"
                    }
                },
            ],
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Oprócz gpt-4o istnieje także model o niższym koszcie, zwany gpt-4o-mini. gpt-4o-mini to najnowsza generacja dużego modelu językowego opracowanego przez OpenAI, który nie tylko szybko odpowiada, ale jest także tańszy i obsługuje multimodalność. Aby skorzystać z funkcji vision, można odwołać się do powyższej treści dotyczącej użycia modelu gpt-4o.

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i komunikat. Na przykład:

- `400 token_mismatched`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`: Wewnętrzny błąd serwera, coś poszło nie tak po stronie serwera.
