  -d '{

## 3. Przesyłanie lokalnego obrazu

Użyj `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` można przekazywać wielokrotnie, a seria GPT Image obsługuje maksymalnie 16 obrazów referencyjnych. `image` w żądaniu JSON może być pojedynczym adresem URL lub tablicą adresów URL; pliki lokalne przesyła się przez multipart.

### Modele i sposób rozliczania

| Model                                | Zastosowania i sposób rozliczania                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | Domyślny kanał odwrotny, stałe rozliczanie za liczbę pomyślnie wygenerowanych obrazów                               |
| `gpt-image-2:reverse`             | Jawny wybór kanału odwrotnego, stałe rozliczanie za liczbę pomyślnie wygenerowanych obrazów                             |
| `gpt-image-2:official`            | Oficjalny kanał API, wyższa stabilność, rozliczanie według faktycznego użycia tokenów                   |
| `gpt-image-2.5-flare`             | Koncentruje się na szybkości generowania, stałe rozliczanie za liczbę pomyślnie wygenerowanych obrazów                               |
| `gpt-image-2.6-flare`             | Koncentruje się na szybkości generowania, stałe rozliczanie za liczbę pomyślnie wygenerowanych obrazów                               |
| `gpt-image-2.5-flare:reverse`     | Jawny alias odwrotny, równoważny z `gpt-image-2.5-flare`, stałe rozliczanie za liczbę pomyślnie wygenerowanych obrazów    |
| `gpt-image-2.6-flare:reverse`     | Jawny alias odwrotny, równoważny z `gpt-image-2.6-flare`, stałe rozliczanie za liczbę pomyślnie wygenerowanych obrazów    |
| `gpt-image-2.5-flare:official`    | Oficjalny kanał API, wyższa stabilność i nacisk na szybkość generowania, rozliczanie według faktycznego użycia tokenów            |
| `gpt-image-2.6-flare:official`    | Oficjalny kanał API, wyższa stabilność i nacisk na szybkość generowania, rozliczanie według faktycznego użycia tokenów            |
| `gpt-image-2.5-sunburst`          | Koncentruje się na wysokiej wierności i precyzyjnej kontroli, stałe rozliczanie za liczbę pomyślnie wygenerowanych obrazów                           |
| `gpt-image-2.6-sunburst`          | Koncentruje się na wysokiej wierności i precyzyjnej kontroli, stałe rozliczanie za liczbę pomyślnie wygenerowanych obrazów                           |
| `gpt-image-2.5-sunburst:reverse`  | Jawny alias odwrotny, równoważny z `gpt-image-2.5-sunburst`, stałe rozliczanie za liczbę pomyślnie wygenerowanych obrazów |
| `gpt-image-2.6-sunburst:reverse`  | Jawny alias odwrotny, równoważny z `gpt-image-2.6-sunburst`, stałe rozliczanie za liczbę pomyślnie wygenerowanych obrazów |
| `gpt-image-2.5-sunburst:official` | Oficjalny kanał API, wyższa stabilność i nacisk na wysoką wierność oraz precyzyjną kontrolę, rozliczanie według faktycznego użycia tokenów        |
| `gpt-image-2.6-sunburst:official` | Oficjalny kanał API, wyższa stabilność i nacisk na wysoką wierność oraz precyzyjną kontrolę, rozliczanie według faktycznego użycia tokenów        |

Modele odwrotne 2.0 / 2.5 (w tym aliasy `:reverse`) mogą podczas automatycznego odzyskiwania używać GPT Image 2.5 Flare do ukończenia żądania; model żądania i sposób rozliczania za liczbę pomyślnie wygenerowanych obrazów pozostają bez zmian.

Ceny wyświetlane dla oficjalnego kanału API są szacowane przed żądaniem, a ostateczna wartość jest określana na podstawie faktycznego użycia tokenów w odpowiedzi i rekordów użycia.

`quality` obsługuje `auto`, `low`, `medium`, `high`; Flare i Sunburst 2.5 / 2.6 (w tym warianty `:reverse` i `:official`) dodatkowo obsługują `xhigh`, `max`. To pole można przekazać zarówno w edycji obrazu URL w formacie JSON, jak i w edycji pliku multipart; oficjalny kanał jest rozliczany według faktycznego użycia tokenów.

## 4. Używanie maski do lokalnej edycji

Oficjalny interfejs Images Edit określa obszar dozwolony do modyfikacji za pomocą `mask`. Modele `:official` Ace Data Cloud przestrzegają tej samej umowy multipart:

- `mask` musi być plikiem PNG z kanałem Alpha, o rozmiarze nie większym niż 4 MB;
- rozmiar maski musi być dokładnie taki sam jak pierwszego `image`;
- przezroczyste piksele z wartością Alpha `0` oznaczają, że edycja jest dozwolona, a nieprzezroczyste piksele oznaczają, że należy je zachować;
- obrazy RGB zawierające tylko kolory czarny i biały, ale bez kanału przezroczystości, nie mogą być używane jako prawidłowe maski;
- polecenie powinno opisywać oczekiwany pełny obraz, jednocześnie jasno określając lokalne modyfikacje oraz treść, która ma pozostać bez zmian.

Poniżej najpierw zostanie wygenerowana maska z obrazu oryginalnego. Przykład ustawia środkowy prostokąt jako przezroczysty, pozwalając modelowi modyfikować tylko ten obszar:
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Następnie prześlij razem oryginalny obraz i maskę:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Można również nadal używać sposobu wywołania `images.edit` z oficjalnego Python SDK OpenAI; wystarczy skierować `base_url` na Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Podczas używania `mask` oryginalny obraz i maska muszą zostać przesłane w tym samym żądaniu multipart odpowiednio przez `image=@input.png` i `mask=@mask.png`. Nie mieszaj oryginalnego obrazu URL z lokalnym plikiem maski; żądania edycji wyłącznie z URL nie obsługują dodatkowego lokalnego pliku `mask`. Maska ogranicza obszar edycji, ale model generujący może nadal naturalnie scalać krawędzie; gdy wymagane są ścisłe granice, należy użyć wyraźnych krawędzi Alpha i powtórzyć w poleceniu, które treści muszą pozostać niezmienione.

Powyższy sposób wywołania jest zgodny z przykładami masek w [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) oraz [oficjalnym Cookbook GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Często używane parametry

| Pole                | Opis                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (szybszy) lub `gpt-image-2.5-sunburst` (wyższa wierność i kontrola); wszystkie trzy mogą korzystać z odpowiedniego wariantu `:official`, a `gpt-image-2` obsługuje również `:reverse` |
| `image`           | JSON używa pojedynczego URL lub tablicy zawierającej maksymalnie 16 URL; multipart używa jednego lub wielu pól plików `image`. Podczas używania `mask` należy przesłać lokalny plik obrazu                                              |
| `mask`            | Opcjonalna maska PNG, wyłącznie dla przesyłania plików multipart; musi zawierać kanał Alpha, mieć ten sam rozmiar co pierwszy `image` i nie przekraczać 4 MB                                                                 |
| `prompt`          | Instrukcja edycji                                                                                                                             |
| `size`            | `auto` lub `WIDTHxHEIGHT` zgodne z ograniczeniami                                                                                                     |
| `n`               | 1–10; przy `response_format=b64_json` obsługiwane jest tylko 1                                                                                           |
| `response_format` | `url` lub `b64_json`                                                                                                               |
| `callback_url`    | Opcjonalny adres asynchronicznego wywołania zwrotnego                                                                                                                         |

Reguły dotyczące rozmiaru są takie same jak w interfejsie generowania: szerokość i wysokość muszą być wielokrotnościami 16, dłuższy bok nie może przekraczać 3840, łączna liczba pikseli musi wynosić 655 360–8 294 400, a proporcje obrazu nie mogą przekraczać 3:1. Gdy `size` zostanie pominięte lub użyte zostanie `auto`, model wybierze format obrazu na podstawie polecenia i pierwszego obrazu referencyjnego.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` oraz ich aliasy `:reverse` są rozliczane według liczby pomyślnie wygenerowanych obrazów; `gpt-image-2:official`, `gpt-image-2.5-flare:official` i `gpt-image-2.5-sunburst:official` są rozliczane na podstawie rzeczywistych Tokenów wejścia tekstowego, wejścia obrazu referencyjnego i wyjścia obrazu, a ostatecznym źródłem są dane użycia.

## 6. Asynchroniczne wywołania zwrotne i rozwiązywanie problemów

W przypadku długich zadań można dodać do żądania:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Asynchroniczna odpowiedź 200 ma postać `{"task_id": "..."}`; po ukończeniu wywoływany jest zwrotnie wynik końcowy. Żądania synchroniczne zwracają natomiast `created` i `data`.

| Status  | Sprawdź                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Format/liczbę obrazów, kombinacje parametrów i format rozmiaru; przy użyciu `mask` sprawdź kanał PNG Alpha, limit 4 MB oraz czy jej rozmiar jest zgodny z pierwszym oryginalnym obrazem |
| 401 | API Key i nagłówek Bearer                                           |
| 429 | Częstotliwość żądań                                                              |
| 504 | Użyj zamiast tego asynchronicznego wywołania zwrotnego                                                            |

Odpowiedzi błędów zawierają `trace_id`. Zgłaszając problem, podaj ten ID, nie podawaj API Key.

Pełne pola i bieżące wyliczenia znajdują się na stronie [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). W przypadku generowania obrazów z czystego tekstu zobacz [generowanie obrazów GPT Image 2 / 2.5 / 2.6](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 wykorzystuje interfejsy generowania, edycji, zadań asynchronicznych i rozliczeń z wersji 2.5:

| Model                                                          | Rozliczenie                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0.22 Credits/obraz                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0.22 Credits/obraz                   |
| `gpt-image-2.6-flare:official`                              | Takie samo jak 2.5 official, rozliczane według rzeczywistego zużycia Tokenów |
| `gpt-image-2.6-sunburst:official`                           | Takie samo jak 2.5 official, rozliczane według rzeczywistego zużycia Tokenów |

Dostępne jakości to `auto`, `low`, `medium`, `high`, `xhigh`, `max`; dla rozmiaru użyj `auto` lub `WIDTHxHEIGHT` zgodnego z powyższymi ograniczeniami. Ten interfejs obsługuje `png`, `jpeg`, `webp`; GPT Image 2.6 obsługuje także natywnie animowane GIF-y, SVG nie jest na razie obsługiwane. Edycja obsługuje obrazowe URL w JSON oraz przesyłanie plików multipart. `:reverse` jest jawnym aliasem zwykłej wersji o tej samej nazwie. Używaj pełnej nazwy modelu, nie przekazuj `gpt-image-2.6`.

### Konwersja obrazu do animowanego GIF w GPT Image 2.6
Zwykła wersja Flare, `:reverse`, `:official` oraz `gpt-image-2.6-sunburst:official` mogą używać `output_format: "gif"`. Zwykła wersja Sunburst oraz `:reverse` tymczasowo nie udostępniają GIF, nadal obsługują generowanie i edycję obrazów statycznych. Klatki animacji, informacje o pętli i czas odtwarzania zostaną zachowane; `frame_count` oznacza liczbę klatek, a `frame_duration_ms` oznacza liczbę milisekund na klatkę, oba muszą być dodatnimi liczbami całkowitymi i są używane wyłącznie dla GIF. Jeśli nie zostaną określone, domyślnie używanych jest 9 klatek po 200 milisekund każda; gdy `size` dla GIF zostanie pominięte lub ma wartość auto, używany jest preset 512x512.

Zaleca się najpierw użyć `size: "512x512"`, `frame_count: 9`, `frame_duration_ms: 200`. GIF ma niezależne ograniczenia dotyczące rozmiaru i liczby klatek, nie można bezpośrednio stosować specyfikacji statycznego 4K; niektóre modele dostosują rzeczywisty rozmiar wyjściowy. `n` oznacza liczbę zwracanych plików GIF, a nie liczbę klatek animacji. Zwykła wersja i `:reverse` nadal są rozliczane według liczby pomyślnie wygenerowanych plików, wersja oficjalna jest rozliczana według rzeczywistego zużycia Tokenów.

```json
{
  "model": "gpt-image-2.6-flare",
  "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
  "prompt": "Animate the mug gently moving left and right. Keep its appearance and the background, no text.",
  "output_format": "gif",
  "size": "512x512",
  "quality": "medium",
  "frame_count": 9,
  "frame_duration_ms": 200,
  "n": 1,
  "async": true
}
```

### GPT Image 2.6 Statyczne obrazy 4K

Flare, Sunburst oraz ich warianty `:reverse`, `:official` mogą używać wspomnianych wcześniej presetów pikseli 4K, takich jak `3840x2160` i `2160x3840`. Zarówno generowanie, jak i edycja przekazują konkretne piksele przez `size`; `4K` nie jest prawidłową wartością `size`, a `4096x4096` również przekracza obecny limit pikseli. Powyższe specyfikacje 4K dotyczą statycznych PNG/JPEG/WebP, dla GIF należy używać jego dedykowanych parametrów.
