## 2. Edycja za pomocą adresu URL obrazu

curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",

## 3. Przesyłanie lokalnego obrazu

Użyj `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

Można wielokrotnie przekazywać `image`; seria GPT Image obsługuje maksymalnie 16 obrazów referencyjnych. `image` w żądaniu JSON może być pojedynczym adresem URL lub tablicą adresów URL; lokalne pliki są przesyłane za pomocą multipart.

## 4. Lokalna edycja z użyciem maski

Oficjalny interfejs Images Edit określa obszar dozwolony do modyfikacji za pomocą `mask`. Model `:official` Ace Data Cloud stosuje ten sam kontrakt multipart:

- `mask` musi być plikiem PNG z kanałem Alpha, o rozmiarze nieprzekraczającym 4 MB;
- rozmiar maski musi być dokładnie taki sam jak pierwszego `image`;
- przezroczyste piksele o wartości Alpha `0` oznaczają obszary dozwolone do edycji, a nieprzezroczyste piksele oznaczają obszary, które należy zachować;
- obrazy RGB zawierające jedynie czarno-białe kolory, ale bez kanału przezroczystości, nie mogą być używane jako prawidłowe maski;
- prompt powinien opisywać oczekiwany kompletny obraz, a jednocześnie wyraźnie określać lokalne modyfikacje oraz treści, które powinny pozostać niezmienione.

Poniżej najpierw generowana jest maska z oryginalnego obrazu. Przykład ustawia środkowy prostokąt jako przezroczysty, pozwalając modelowi modyfikować tylko ten obszar:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Następnie prześlij razem oryginalny obraz i maskę:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Można również kontynuować używanie sposobu wywołania `images.edit` z oficjalnego Python SDK OpenAI — wystarczy skierować `base_url` na Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

`mask` jest obecnie udostępniana jako pole pliku multipart. Jeśli oryginalny obraz ma być przekazywany przez URL, również zmień żądanie na multipart: `image` może nadal być polem tekstowym URL, a `mask` przesyłaj za pomocą `@mask.png`. Maska ograniczy obszar edycji, ale model generatywny nadal może naturalnie scalać krawędzie; gdy wymagane są ścisłe granice, należy użyć wyraźnych krawędzi Alpha i powtórzyć w prompcie, które treści muszą pozostać niezmienione.

Powyższy sposób wywołania jest zgodny z przykładami masek w [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) oraz [oficjalnym Cookbook GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Często używane parametry

| Pole                | Opis                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (szybszy) lub `gpt-image-2.5-sunburst` (wyższa wierność i kontrola); wszystkie trzy mogą wybrać odpowiadający wariant `:official`, a `gpt-image-2` obsługuje również `:reverse` |
| `image`           | JSON używa pojedynczego URL lub tablicy maksymalnie 16 URL; multipart używa jednego lub wielu pól plików `image`                                                                    |
| `prompt`          | Instrukcja edycji                                                                                                                             |
| `size`            | `auto` lub zgodne z ograniczeniami `WIDTHxHEIGHT`                                                                                                     |
| `n`               | 1–10; przy `response_format=b64_json` obsługiwane jest wyłącznie 1                                                                                           |
| `response_format` | `url` lub `b64_json`                                                                                                               |
| `callback_url`    | Opcjonalny adres zwrotny asynchronicznego callbacku                                                                                                                         |

Zasady rozmiaru są takie same jak w interfejsie generowania: szerokość i wysokość muszą być wielokrotnością 16, dłuższy bok nie może przekraczać 3840, łączna liczba pikseli musi wynosić 655 360–8 294 400, a proporcje nie mogą przekraczać 3:1. W przypadku pominięcia `size` lub użycia `auto`, model wybierze format obrazu na podstawie promptu i pierwszego obrazu referencyjnego.
`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` oraz `gpt-image-2:reverse` są rozliczane według liczby pomyślnie wygenerowanych obrazów; `gpt-image-2:official`, `gpt-image-2.5-flare:official` i `gpt-image-2.5-sunburst:official` są rozliczane na podstawie rzeczywistych Tokenów wejściowych tekstu, wejściowych obrazów referencyjnych i wyjściowych obrazów, a ostateczną podstawą są zapisy użycia.

## 6. Asynchroniczne wywołania zwrotne i rozwiązywanie problemów

Do długich zadań można dodać w żądaniu:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Asynchroniczna odpowiedź 200 ma postać `{"task_id": "..."}`; po zakończeniu następuje wywołanie zwrotne z końcowym wynikiem. Żądania synchroniczne zwracają natomiast `created` i `data`.

| Status  | Sprawdź                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Format/liczbę obrazów, kombinacje parametrów i format rozmiaru; przy użyciu `mask` sprawdź kanał PNG Alpha, limit 4 MB oraz czy jego rozmiar jest zgodny z pierwszym oryginalnym obrazem |
| 401 | API Key i Bearer Header                                           |
| 429 | Częstotliwość żądań                                                              |
| 504 | Użyj asynchronicznego wywołania zwrotnego                                                            |

Odpowiedzi błędów zawierają `trace_id`. Podczas zgłaszania problemu podaj ten ID, nie podawaj API Key.

Pełne pola i bieżące wartości wyliczeniowe znajdują się na stronie [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). W przypadku generowania obrazów wyłącznie z tekstu zobacz [GPT Image 2 / 2.5 Generowanie obrazów](https://platform.acedata.cloud/documents/openai-images-generations).
