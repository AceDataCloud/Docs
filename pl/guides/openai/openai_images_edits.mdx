## 3. Przesyłanie lokalnego obrazu

Użyj `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` można przekazywać wielokrotnie, seria GPT Image obsługuje maksymalnie 16 obrazów referencyjnych. `image` w żądaniu JSON może być pojedynczym URL lub tablicą URL; lokalne pliki przesyła się przy użyciu multipart.

### Modele i sposób rozliczania

| Model                                | Zastosowania i sposób rozliczania                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | Domyślny kanał odwrotny, stałe rozliczanie za liczbę pomyślnie utworzonych obrazów                               |
| `gpt-image-2:reverse`             | Jawny wybór kanału odwrotnego, stałe rozliczanie za liczbę pomyślnie utworzonych obrazów                             |
| `gpt-image-2:official`            | Oficjalny kanał API, wyższa stabilność, rozliczanie według rzeczywistego zużycia Tokenów                   |
| `gpt-image-2.5-flare`             | Ukierunkowany na szybkość generowania, stałe rozliczanie za liczbę pomyślnie utworzonych obrazów                               |
| `gpt-image-2.6-flare`             | Ukierunkowany na szybkość generowania, stałe rozliczanie za liczbę pomyślnie utworzonych obrazów                               |
| `gpt-image-2.5-flare:reverse`     | Jawny alias odwrotny, równoważny `gpt-image-2.5-flare`, stałe rozliczanie za liczbę pomyślnie utworzonych obrazów    |
| `gpt-image-2.6-flare:reverse`     | Jawny alias odwrotny, równoważny `gpt-image-2.6-flare`, stałe rozliczanie za liczbę pomyślnie utworzonych obrazów    |
| `gpt-image-2.5-flare:official`    | Oficjalny kanał API, wyższa stabilność i ukierunkowanie na szybkość generowania, rozliczanie według rzeczywistego zużycia Tokenów            |
| `gpt-image-2.6-flare:official`    | Oficjalny kanał API, wyższa stabilność i ukierunkowanie na szybkość generowania, rozliczanie według rzeczywistego zużycia Tokenów            |
| `gpt-image-2.5-sunburst`          | Ukierunkowany na wysoką wierność i precyzyjną kontrolę, stałe rozliczanie za liczbę pomyślnie utworzonych obrazów                           |
| `gpt-image-2.6-sunburst`          | Ukierunkowany na wysoką wierność i precyzyjną kontrolę, stałe rozliczanie za liczbę pomyślnie utworzonych obrazów                           |
| `gpt-image-2.5-sunburst:reverse`  | Jawny alias odwrotny, równoważny `gpt-image-2.5-sunburst`, stałe rozliczanie za liczbę pomyślnie utworzonych obrazów |
| `gpt-image-2.6-sunburst:reverse`  | Jawny alias odwrotny, równoważny `gpt-image-2.6-sunburst`, stałe rozliczanie za liczbę pomyślnie utworzonych obrazów |
| `gpt-image-2.5-sunburst:official` | Oficjalny kanał API, wyższa stabilność i ukierunkowanie na wysoką wierność oraz precyzyjną kontrolę, rozliczanie według rzeczywistego zużycia Tokenów        |
| `gpt-image-2.6-sunburst:official` | Oficjalny kanał API, wyższa stabilność i ukierunkowanie na wysoką wierność oraz precyzyjną kontrolę, rozliczanie według rzeczywistego zużycia Tokenów        |

Modele odwrotne 2.0 / 2.5 (w tym aliasy `:reverse`) mogą podczas automatycznego odzyskiwania używać GPT Image 2.5 Flare do ukończenia żądania; model żądania i sposób stałego rozliczania za liczbę pomyślnie utworzonych obrazów pozostają bez zmian.

Cena na stronie oficjalnego kanału API jest szacowana przed żądaniem, a ostateczna cena zależy od rzeczywistego zużycia Tokenów w odpowiedzi i zapisów użycia.

`quality` obsługuje `auto`, `low`, `medium`, `high`; Flare i Sunburst 2.5 / 2.6 (w tym warianty `:reverse` i `:official`) dodatkowo obsługują `xhigh`, `max`. To pole można przekazać zarówno podczas edycji obrazów URL w JSON, jak i edycji plików multipart; oficjalny kanał rozlicza się według rzeczywistego zużycia Tokenów.

## 4. Lokalna edycja z użyciem maski

Oficjalny interfejs Images Edit wskazuje obszar dozwolony do modyfikacji za pomocą `mask`. Modele `:official` Ace Data Cloud przestrzegają tej samej umowy multipart:

- `mask` musi być plikiem PNG z kanałem Alpha, o rozmiarze nie większym niż 4 MB;
- rozmiar maski musi być dokładnie taki sam jak pierwszego `image`;
- przezroczyste piksele z wartością Alpha `0` oznaczają możliwość edycji, a nieprzezroczyste piksele oznaczają, że należy je zachować;
- obrazy RGB, które mają wyłącznie kolory czarny i biały, ale nie mają kanału przezroczystości, nie mogą być używane jako prawidłowe maski;
- prompt powinien opisywać oczekiwany pełny obraz, jednocześnie jasno określając lokalne modyfikacje i zawartość, która ma pozostać bez zmian.

Poniżej najpierw wygenerowana zostanie maska z oryginalnego obrazu. Przykład ustawia środkowy prostokąt jako przezroczysty, pozwalając modelowi modyfikować tylko ten obszar:
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Następnie prześlij razem obraz oryginalny i maskę:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Można również użyć sposobu wywołania `images.edit` z oficjalnego Python SDK OpenAI — wystarczy wskazać Ace Data Cloud w `base_url`:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Podczas używania `mask` obraz oryginalny i maska muszą zostać przesłane osobno w tym samym żądaniu multipart za pomocą `image=@input.png` oraz `mask=@mask.png`. Nie należy mieszać obrazów oryginalnych w URL z lokalnymi plikami masek; żądania edycji wyłącznie z URL nie obsługują dołączania lokalnego pliku `mask`. Maska ogranicza obszar edycji, lecz model generujący nadal może naturalnie scalać krawędzie; gdy wymagane są ścisłe granice, należy użyć wyraźnych krawędzi Alpha i powtórzyć w poleceniu, które treści muszą pozostać niezmienione.

Powyższy sposób wywołania jest zgodny z przykładami masek w [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) oraz [oficjalnym Cookbook GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Często używane parametry

| Pole                | Opis                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (szybszy) lub `gpt-image-2.5-sunburst` (wyższa wierność i kontrola); dla wszystkich trzech można wybrać odpowiedni wariant `:official`, a `gpt-image-2` obsługuje również `:reverse` |
| `image`           | JSON używa pojedynczego URL lub tablicy zawierającej maksymalnie 16 URL; multipart używa jednego lub wielu pól plików `image`. Podczas używania `mask` należy przesłać lokalny plik obrazu                                              |
| `mask`            | Opcjonalna maska PNG, wyłącznie dla przesyłania plików multipart; musi zawierać kanał Alpha, mieć taki sam rozmiar jak pierwszy `image` i nie przekraczać 4 MB                                                                 |
| `prompt`          | Instrukcja edycji                                                                                                                             |
| `size`            | `auto` lub `WIDTHxHEIGHT` zgodne z ograniczeniami                                                                                                     |
| `n`               | 1–10; przy `response_format=b64_json` obsługiwane jest tylko 1                                                                                           |
| `response_format` | `url` lub `b64_json`                                                                                                               |
| `callback_url`    | Opcjonalny adres zwrotny asynchronicznego callbacku                                                                                                                         |

Zasady dotyczące rozmiaru są takie same jak w interfejsie generowania: szerokość i wysokość muszą być wielokrotnościami 16, dłuższy bok nie może przekraczać 3840, całkowita liczba pikseli musi wynosić 655 360–8 294 400, a proporcje obrazu nie mogą przekraczać 3:1. Po pominięciu `size` lub użyciu `auto` model wybierze format obrazu na podstawie polecenia i pierwszego obrazu referencyjnego.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` oraz ich aliasy `:reverse` są rozliczane według liczby pomyślnie wygenerowanych obrazów; `gpt-image-2:official`, `gpt-image-2.5-flare:official` i `gpt-image-2.5-sunburst:official` są rozliczane na podstawie rzeczywistych Tokenów wejścia tekstowego, wejścia obrazu referencyjnego i wyjścia obrazu, a ostateczną podstawą są zapisy użycia.

## 6. Asynchroniczne callbacki i rozwiązywanie problemów

W przypadku długich zadań można dodać do żądania:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Asynchroniczna odpowiedź 200 ma postać `{"task_id": "..."}`; po ukończeniu callback zwraca wynik końcowy. Żądania synchroniczne zwracają natomiast `created` i `data`.

| Status  | Sprawdź                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Format/liczbę obrazów, kombinację parametrów i format rozmiaru; przy użyciu `mask` sprawdź kanał Alpha PNG, limit 4 MB oraz czy jej rozmiar jest zgodny z pierwszym obrazem oryginalnym |
| 401 | API Key i nagłówek Bearer                                           |
| 429 | Częstotliwość żądań                                                              |
| 504 | Użyj asynchronicznego callbacku                                                            |

Odpowiedzi błędów zawierają `trace_id`. Przy zgłaszaniu problemu podaj ten ID, nie podawaj API Key.

Pełne pola i aktualne wyliczenia znajdują się na stronie [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). W przypadku generowania obrazów z samego tekstu zobacz [Generowanie obrazów GPT Image 2 / 2.5 / 2.6](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 wykorzystuje interfejsy generowania, edycji, zadań asynchronicznych i rozliczeń z 2.5:

| Model                                                          | Rozliczenie                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0.22 Credits/obraz                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0.22 Credits/obraz                   |
| `gpt-image-2.6-flare:official`                              | Takie samo jak 2.5 official, rozliczane według rzeczywistego zużycia Tokenów |
| `gpt-image-2.6-sunburst:official`                           | Takie samo jak 2.5 official, rozliczane według rzeczywistego zużycia Tokenów |

Dostępne jakości to `auto`, `low`, `medium`, `high`, `xhigh`, `max`; dla rozmiaru użyj `auto` lub `WIDTHxHEIGHT` zgodnego z powyższymi ograniczeniami. Ten interfejs obsługuje `png`, `jpeg`, `webp`, natomiast SVG/GIF nie są obecnie obsługiwane. Edycja obsługuje obrazowe URL JSON i przesyłanie plików multipart. `:reverse` jest jawnym aliasem zwykłej wersji o tej samej nazwie. Używaj pełnej nazwy modelu, nie przekazuj `gpt-image-2.6`.
