## 2. Edycja przy użyciu URL obrazu

Oryginalny obraz:

![Oryginalny obraz do edycji GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://platform2.cdn.acedata.cloud/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0.png",
    "prompt": "Keep the mug, tabletop, camera angle, portrait layout, and soft shadow unchanged. Change only the mug color from white to vivid orange and the pale cream background to solid dark navy blue. No text and no logo.",
    "size": "1024x1536"
  }'
```

## 3. Przesyłanie lokalnego obrazu

Użyj `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

Parametr `image` można przekazać wielokrotnie; seria GPT Image obsługuje maksymalnie 16 obrazów referencyjnych. `image` w żądaniu JSON może być pojedynczym URL-em lub tablicą URL-i; lokalne pliki przesyła się przez multipart.

### Modele i sposób rozliczania

| Model                                | Zastosowanie i sposób rozliczania                                 |
| --------------------------------- | ----------------------------------------- |
| `gpt-image-2`                     | Domyślny kanał odwrotny, stała opłata za liczbę pomyślnie wygenerowanych obrazów                        |
| `gpt-image-2:reverse`             | Jawny wybór kanału odwrotnego, stała opłata za liczbę pomyślnie wygenerowanych obrazów                      |
| `gpt-image-2:official`            | Oficjalny kanał API, większa stabilność, rozliczanie według rzeczywistego użycia Tokenów            |
| `gpt-image-2.5-flare`             | Priorytet dla szybkości generowania, stała opłata za liczbę pomyślnie wygenerowanych obrazów                        |
| `gpt-image-2.5-flare:official`    | Oficjalny kanał API, większa stabilność i priorytet dla szybkości generowania, rozliczanie według rzeczywistego użycia Tokenów     |
| `gpt-image-2.5-sunburst`          | Priorytet dla wysokiej wierności i precyzyjnej kontroli, stała opłata za liczbę pomyślnie wygenerowanych obrazów                    |
| `gpt-image-2.5-sunburst:official` | Oficjalny kanał API, większa stabilność oraz priorytet dla wysokiej wierności i precyzyjnej kontroli, rozliczanie według rzeczywistego użycia Tokenów |

Cena na stronie dla oficjalnego kanału API jest szacowana przed żądaniem; ostateczna cena zależy od rzeczywistego użycia Tokenów w odpowiedzi i rejestrze użycia.

## 4. Edycja lokalna z użyciem maski

Oficjalny interfejs Images Edit określa obszar dozwolony do modyfikacji za pomocą `mask`. Modele Ace Data Cloud `:official` przestrzegają tego samego kontraktu multipart:

- `mask` musi być plikiem PNG z kanałem Alpha, o rozmiarze nieprzekraczającym 4 MB;
- rozmiar maski musi być dokładnie taki sam jak pierwszego `image`;
- przezroczyste piksele o Alpha równym `0` oznaczają możliwość edycji, a nieprzezroczyste piksele oznaczają, że należy je zachować;
- obrazy RGB mające wyłącznie kolory czarny i biały, ale bez kanału przezroczystości, nie mogą służyć jako prawidłowa maska;
- prompt powinien opisywać oczekiwany pełny obraz, jednocześnie jasno określając lokalne modyfikacje oraz elementy, które mają pozostać niezmienione.

Poniżej najpierw generowana jest maska z oryginalnego obrazu. Przykład ustawia środkowy prostokąt jako przezroczysty, zezwalając modelowi na modyfikację wyłącznie tego obszaru:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Następnie prześlij razem oryginalny obraz i maskę:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Można również zachować sposób wywołania `images.edit` z oficjalnego Python SDK OpenAI; wystarczy wskazać Ace Data Cloud jako `base_url`:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Podczas używania `mask` oryginalny obraz i maska muszą zostać przesłane w tym samym żądaniu multipart odpowiednio przez `image=@input.png` i `mask=@mask.png`. Nie należy mieszać oryginalnego obrazu URL z lokalnym plikiem maski; żądania edycji wyłącznie z URL-em nie obsługują dodatkowego lokalnego pliku `mask`. Maska ogranicza obszar edycji, ale model generujący nadal może naturalnie scalać krawędzie; gdy wymagane są ścisłe granice, należy użyć wyraźnych krawędzi Alpha i wielokrotnie wskazać w prompcie, które elementy muszą pozostać niezmienione.

Powyższy sposób wywołania jest zgodny z przykładami masek w [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) i [oficjalnym Cookbook GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Często używane parametry
| Pole                | Opis                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (szybszy) lub `gpt-image-2.5-sunburst` (wyższa wierność i kontrola); wszystkie trzy mogą wybrać odpowiedni wariant `:official`, a `gpt-image-2` obsługuje również `:reverse` |
| `image`           | JSON używa pojedynczego URL lub tablicy maksymalnie 16 URL; multipart używa jednego lub większej liczby pól plików `image`. Podczas używania `mask` należy przesłać lokalny plik obrazu                                              |
| `mask`            | Opcjonalna maska PNG, dostępna wyłącznie przy przesyłaniu plików multipart; musi zawierać kanał Alpha, mieć taki sam rozmiar jak pierwszy `image` i nie przekraczać 4 MB                                                                 |
| `prompt`          | Instrukcja edycji                                                                                                                             |
| `size`            | `auto` lub `WIDTHxHEIGHT` zgodne z ograniczeniami                                                                                                     |
| `n`               | 1–10; przy `response_format=b64_json` obsługiwane jest tylko 1                                                                                           |
| `response_format` | `url` lub `b64_json`                                                                                                               |
| `callback_url`    | Opcjonalny adres zwrotny asynchronicznego callbacku                                                                                                                         |

Zasady dotyczące rozmiaru są takie same jak w interfejsie generowania: szerokość i wysokość muszą być wielokrotnością 16, dłuższy bok nie może przekraczać 3840, łączna liczba pikseli wynosi 655 360–8 294 400, a proporcje obrazu nie mogą przekraczać 3:1. Gdy `size` zostanie pominięte lub użyte zostanie `auto`, model wybierze format na podstawie promptu i pierwszego obrazu referencyjnego.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` oraz `gpt-image-2:reverse` są rozliczane według liczby pomyślnie wygenerowanych obrazów; `gpt-image-2:official`, `gpt-image-2.5-flare:official` i `gpt-image-2.5-sunburst:official` są rozliczane na podstawie rzeczywistych Tokenów wejściowych tekstu, wejściowych obrazów referencyjnych i wyjściowych obrazów, a ostateczne rozliczenie opiera się na rekordach użycia.

## 6. Asynchroniczne callbacki i rozwiązywanie problemów

Do długich zadań można dodać w żądaniu:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Asynchroniczna odpowiedź 200 ma postać `{"task_id": "..."}`; po ukończeniu callback zwraca wynik końcowy. Żądania synchroniczne zwracają natomiast `created` i `data`.

| Status  | Sprawdź                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Format/liczbę obrazów, kombinację parametrów i format rozmiaru; podczas używania `mask` sprawdź kanał Alpha PNG, limit 4 MB oraz czy jego rozmiar jest zgodny z pierwszym oryginalnym obrazem |
| 401 | API Key i Bearer Header                                           |
| 429 | Częstotliwość żądań                                                              |
| 504 | Użyj asynchronicznego callbacku                                                            |

Odpowiedzi błędów zawierają `trace_id`. Podczas zgłaszania problemów podaj ten ID, nie podawaj API Key.

Pełne pola i bieżące wyliczenia znajdują się na stronie [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). W przypadku generowania obrazów wyłącznie z tekstu zobacz [GPT Image 2 / 2.5 Generowanie obrazów](https://platform.acedata.cloud/documents/openai-images-generations).
