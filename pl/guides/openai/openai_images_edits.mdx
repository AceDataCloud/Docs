## 2. Edycja przy użyciu URL obrazu

curl https://api.acedata.cloud/openai/images/edits \

  -H "Content-Type: application/json" \
  -d '{

## 3. Prześlij lokalny obraz

Użyj `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` można przekazywać wielokrotnie, seria GPT Image obsługuje maksymalnie 16 obrazów referencyjnych. `image` w żądaniu JSON może być pojedynczym URL lub tablicą URL; lokalne pliki są przesyłane za pomocą multipart.

| `gpt-image-2:reverse`             | Jawny wybór kanału reverse, stałe rozliczanie według liczby pomyślnie wygenerowanych obrazów                             |
| `gpt-image-2:official`            | Oficjalny kanał API, wyższa stabilność, rozliczanie według rzeczywistego zużycia Tokenów                   |
| `gpt-image-2.5-flare`             | Priorytet dla szybkości generowania, stałe rozliczanie według liczby pomyślnie wygenerowanych obrazów                               |
| `gpt-image-2.6-flare`             | Priorytet dla szybkości generowania, stałe rozliczanie według liczby pomyślnie wygenerowanych obrazów                               |
| `gpt-image-2.5-flare:reverse`     | Jawny alias reverse, równoważny `gpt-image-2.5-flare`, stałe rozliczanie według liczby pomyślnie wygenerowanych obrazów    |
| `gpt-image-2.6-flare:reverse`     | Jawny alias reverse, równoważny `gpt-image-2.6-flare`, stałe rozliczanie według liczby pomyślnie wygenerowanych obrazów    |

| `gpt-image-2.6-flare:official`    | Oficjalny kanał API, wyższa stabilność i priorytet dla szybkości generowania, rozliczanie według rzeczywistego zużycia Tokenów            |
| `gpt-image-2.5-sunburst`          | Priorytet dla wysokiej wierności i precyzyjnej kontroli, stałe rozliczanie według liczby pomyślnie wygenerowanych obrazów                           |
| `gpt-image-2.6-sunburst`          | Priorytet dla wysokiej wierności i precyzyjnej kontroli, stałe rozliczanie według liczby pomyślnie wygenerowanych obrazów                           |
| `gpt-image-2.5-sunburst:reverse`  | Jawny alias reverse, równoważny `gpt-image-2.5-sunburst`, stałe rozliczanie według liczby pomyślnie wygenerowanych obrazów |
| `gpt-image-2.6-sunburst:reverse`  | Jawny alias reverse, równoważny `gpt-image-2.6-sunburst`, stałe rozliczanie według liczby pomyślnie wygenerowanych obrazów |
| `gpt-image-2.5-sunburst:official` | Oficjalny kanał API, wyższa stabilność i priorytet dla wysokiej wierności oraz precyzyjnej kontroli, rozliczanie według rzeczywistego zużycia Tokenów        |
| `gpt-image-2.6-sunburst:official` | Oficjalny kanał API, wyższa stabilność i priorytet dla wysokiej wierności oraz precyzyjnej kontroli, rozliczanie według rzeczywistego zużycia Tokenów        |

Modele reverse 2.0 / 2.5 (w tym aliasy `:reverse`) mogą podczas automatycznego odzyskiwania używać GPT Image 2.5 Flare do ukończenia żądania; model żądania oraz sposób rozliczania według liczby pomyślnie wygenerowanych obrazów pozostają niezmienione.

Ceny na stronie dla oficjalnego kanału API są szacowane przed żądaniem, a ostateczne rozliczenie opiera się na rzeczywistym zużyciu Tokenów w odpowiedzi i historii użycia.

`quality` obsługuje `auto`, `low`, `medium`, `high`; Flare i Sunburst 2.5 / 2.6 (w tym warianty `:reverse` i `:official`) dodatkowo obsługują `xhigh`, `max`. To pole można przekazać zarówno w edycji obrazu przez JSON URL, jak i w edycji pliku multipart; oficjalny kanał rozlicza się według rzeczywistego zużycia Tokenów.

## 4. Użyj maski do lokalnej edycji

Oficjalny interfejs Images Edit używa `mask` do określenia obszaru, w którym dozwolone są modyfikacje. Modele `:official` Ace Data Cloud stosują tę samą umowę multipart:

- `mask` musi być plikiem PNG z kanałem Alpha, o rozmiarze nie większym niż 4 MB;
- rozmiar maski musi być dokładnie taki sam jak pierwszego `image`;
- przezroczyste piksele z Alpha równą `0` oznaczają, że edycja jest dozwolona, a nieprzezroczyste piksele oznaczają, że należy je zachować;
- obrazy RGB zawierające tylko kolory czarny i biały, ale bez kanału przezroczystości, nie mogą być używane jako prawidłowe maski;
- prompt powinien opisywać oczekiwany pełny obraz, jednocześnie jasno określając lokalne modyfikacje i elementy, które mają pozostać niezmienione.

Poniżej najpierw wygenerowano maskę z oryginalnego obrazu. Przykład ustawia środkowy prostokąt jako przezroczysty, pozwalając modelowi modyfikować tylko ten obszar:
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Następnie prześlij razem oryginalny obraz i maskę:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Można również użyć sposobu wywołania `images.edit` z oficjalnego Python SDK OpenAI; wystarczy skierować `base_url` na Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Podczas używania `mask` oryginalny obraz i maska muszą zostać przesłane osobno w tym samym żądaniu multipart poprzez `image=@input.png` oraz `mask=@mask.png`. Nie należy łączyć oryginalnego obrazu w URL z lokalnym plikiem maski; żądania edycji wyłącznie z URL nie obsługują dodatkowego lokalnego pliku `mask`. Maska ogranicza obszar edycji, ale model generujący nadal może naturalnie scalać krawędzie; gdy wymagane są ścisłe granice, należy użyć wyraźnych krawędzi Alpha i powtórzyć w poleceniu, które treści muszą pozostać niezmienione.

Powyższy sposób wywołania jest zgodny z przykładami masek w [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) oraz [oficjalnym Cookbook GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Często używane parametry

| Pole                | Opis                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (szybszy) lub `gpt-image-2.5-sunburst` (wyższa wierność i kontrola); dla wszystkich trzech można wybrać odpowiedni wariant `:official`, a `gpt-image-2` obsługuje również `:reverse` |
| `image`           | JSON używa pojedynczego URL lub tablicy zawierającej maksymalnie 16 URL; multipart używa jednego lub wielu pól plików `image`. Podczas używania `mask` należy przesłać lokalny plik obrazu                                              |
| `mask`            | Opcjonalna maska PNG, wyłącznie dla przesyłania plików multipart; musi zawierać kanał Alpha, mieć ten sam rozmiar co pierwszy `image` i nie przekraczać 4 MB                                                                 |
| `prompt`          | Instrukcja edycji                                                                                                                             |
| `size`            | `auto` lub `WIDTHxHEIGHT` zgodne z ograniczeniami                                                                                                     |
| `n`               | 1–10; przy `response_format=b64_json` obsługiwane jest tylko 1                                                                                           |
| `response_format` | `url` lub `b64_json`                                                                                                               |
| `callback_url`    | Opcjonalny adres asynchronicznego wywołania zwrotnego                                                                                                                         |

Zasady dotyczące rozmiaru są takie same jak w interfejsie generowania: szerokość i wysokość muszą być wielokrotnością 16, dłuższy bok nie może przekraczać 3840, łączna liczba pikseli musi wynosić 655 360–8 294 400, a współczynnik proporcji nie może przekraczać 3:1. Gdy `size` zostanie pominięty lub użyte zostanie `auto`, model wybierze format obrazu na podstawie polecenia i pierwszego obrazu referencyjnego.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` oraz ich aliasy `:reverse` są rozliczane według liczby pomyślnie wygenerowanych obrazów; `gpt-image-2:official`, `gpt-image-2.5-flare:official` i `gpt-image-2.5-sunburst:official` są rozliczane na podstawie rzeczywistych Tokenów wejściowych tekstu, wejściowych obrazów referencyjnych i wyjściowych obrazów, a ostatecznym źródłem są dane użycia.

## 6. Asynchroniczne wywołania zwrotne i rozwiązywanie problemów

Do długich zadań można dodać w żądaniu:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

Asynchroniczna odpowiedź 200 ma postać `{"task_id": "..."}`; po ukończeniu wywoływany jest zwrotnie wynik końcowy. Żądania synchroniczne zwracają natomiast `created` i `data`.

| Status  | Sprawdź                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Format/liczbę obrazów, kombinacje parametrów i format rozmiaru; przy użyciu `mask` sprawdź kanał PNG Alpha, limit 4 MB oraz czy jej rozmiar jest zgodny z pierwszym oryginalnym obrazem |
| 401 | API Key i nagłówek Bearer                                           |
| 429 | Częstotliwość żądań                                                              |
| 504 | Użyj asynchronicznego wywołania zwrotnego                                                            |

Odpowiedzi błędów zawierają `trace_id`. Przy zgłaszaniu problemu podaj ten ID, nie podawaj API Key.

Pełne pola i bieżące wartości wyliczeniowe znajdują się na stronie [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). W przypadku generowania obrazów z czystego tekstu zobacz [Generowanie obrazów GPT Image 2 / 2.5 / 2.6](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 korzysta z interfejsów generowania, edycji, zadań asynchronicznych i rozliczeń z wersji 2.5:

| Model                                                          | Rozliczenie                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0,22 Credits/obraz                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0,22 Credits/obraz                   |
| `gpt-image-2.6-flare:official`                              | Takie samo jak 2.5 official, rozliczane według rzeczywistego zużycia Tokenów |
| `gpt-image-2.6-sunburst:official`                           | Takie samo jak 2.5 official, rozliczane według rzeczywistego zużycia Tokenów |

Dostępne jakości to `auto`, `low`, `medium`, `high`, `xhigh`, `max`; dla rozmiaru należy użyć `auto` lub `WIDTHxHEIGHT` zgodnego z powyższymi ograniczeniami. Ten interfejs obsługuje `png`, `jpeg`, `webp`; GPT Image 2.6 obsługuje również natywne animacje `gif`, natomiast SVG nie jest obecnie obsługiwane. Edycja obsługuje URL obrazów JSON oraz przesyłanie plików multipart. `:reverse` jest jawnym aliasem zwykłej wersji o tej samej nazwie. Należy używać pełnej nazwy modelu, nie przekazywać `gpt-image-2.6`.

### Konwersja obrazu do animacji GIF w GPT Image 2.6
Zwykła wersja GPT Image 2.6 Flare, Sunburst, `:reverse`, `:official` mogą używać `output_format: "gif"`. Klatki animacji, informacje o pętli i czas odtwarzania zostaną zachowane; `frame_count` oznacza liczbę klatek, `frame_duration_ms` oznacza liczbę milisekund na klatkę, liczba klatek musi być liczbą całkowitą od 2 do 16, czas trwania każdej klatki musi być liczbą całkowitą od 20 do 655350 milisekund i dotyczy wyłącznie GIF; kodowanie jest zaokrąglane do najbliższych 10 ms. Gdy nie określono, domyślnie używanych jest 9 klatek, po 200 milisekund na klatkę; gdy `size` GIF jest pominięte lub ma wartość auto, używany jest preset 512x512.

Zaleca się najpierw użyć `size: "512x512"`, `frame_count: 9`, `frame_duration_ms: 200`. GIF ma niezależne ograniczenia rozmiaru i liczby klatek, nie można bezpośrednio stosować specyfikacji statycznego 4K; niektóre modele dostosują rzeczywisty rozmiar wyjściowy. `n` oznacza liczbę zwracanych plików GIF, a nie liczbę klatek animacji. Zwykła wersja i `:reverse` są nadal rozliczane według liczby pomyślnie utworzonych plików, wersja oficjalna jest rozliczana według rzeczywistego zużycia Tokenów.

```json
{
  "model": "gpt-image-2.6-flare",
  "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
  "prompt": "Animate the mug gently moving left and right. Keep its appearance and the background, no text.",
  "output_format": "gif",
  "size": "512x512",
  "quality": "medium",
  "frame_count": 9,
  "frame_duration_ms": 200,
  "n": 1,
  "async": true
}
```

### Statyczne obrazy GPT Image 2.6 4K

Flare, Sunburst oraz ich warianty `:reverse`, `:official` mogą wszystkie używać wcześniej wymienionych presetów pikseli 4K, takich jak `3840x2160` i `2160x3840`. Zarówno generowanie, jak i edycja przekazują konkretne piksele przez `size`; `4K` nie jest prawidłową wartością `size`, a `4096x4096` również przekracza obecny limit pikseli. Powyższe specyfikacje 4K dotyczą statycznych PNG/JPEG/WebP, dla GIF należy użyć jego dedykowanych parametrów.

### Złożoność kompozycji GPT Image 2.6

`complexity` może opcjonalnie przyjmować `low`, `medium`, `high`, a po pominięciu używana jest domyślna wartość modelu `high`. Kontroluje złożoność planowania i jest niezależne od jakości renderowania `quality`; nie powoduje dodatkowej opłaty za użycie, wersja oficjalna nadal jest rozliczana według rzeczywistych Tokenów. Inne modele nie obsługują tego parametru.

GIF nie obsługuje maski, obrazu oznaczeń, niestandardowej kompresji, przepisywania promptów ani częściowego strumieniowego przesyłania obrazów; niekompatybilne kombinacje zostaną odrzucone przed generowaniem. Rozmiar, liczba klatek i ilość są łącznie ograniczone przez budżet pikseli modelu; `1024x1024` i 2 klatki zwykłego Flare zostały zweryfikowane jako działające, nie można rozszerzać tego wniosku na wszystkie kombinacje 1K ani GIF 4K.

### Edycja kierowana oznaczeniami

Statyczna edycja GPT Image 2.6 obsługuje `markup`. Prześlij przezroczysty PNG o takim samym rozmiarze jak pierwszy obraz referencyjny, zaznacz na osobnej warstwie miejsce do zmiany i opisz wymagania zmiany w `prompt`. Warstwa oznaczeń musi zawierać przezroczyste piksele; każdy z dwóch obrazów nie może przekraczać 16777216 pikseli, a obraz oznaczeń nie może przekraczać 40 MB. JSON może przekazywać HTTPS URL, PNG base64 data URL lub `{ "image_url": "https://..." }`; multipart przesyła plik przez `markup`. Platforma przekaże warstwę oznaczeń w formie pliku. `markup` nie może być używane razem z `mask`, GIF ani `prompt_rewriter`, a `file_id` nie jest obsługiwane.

`input_fidelity` nie ma zastosowania do GPT Image 2.6, należy je pominąć.
