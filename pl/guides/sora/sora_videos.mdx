W tym dokumencie przedstawimy instrukcję integracji z API generowania wideo Sora Videos Generation API, które umożliwia generowanie oficjalnych wideo Sora na podstawie niestandardowych parametrów. API obsługuje dwa tryby wersji:

- **Version 1 (tryb klasyczny)**: obsługuje parametry `duration` (10/15/25 sekund), `orientation` (poziomy/pionowy), `size` (small/large rozdzielczość), obrazy referencyjne `image_urls`, link do postaci `character_url` itd.
- **Version 2 (tryb partnera)**: obsługuje parametry `seconds` (4/8/12 sekund), rozdzielczość pikselową `size` (np. 1280x720), obrazy referencyjne `input_reference` itd.

## Proces aplikacji

Aby korzystać z API, należy najpierw złożyć wniosek o odpowiednią usługę na stronie [Sora Videos Generation API](https://platform.acedata.cloud/documents/99a24421-2e22-4028-8201-e19cb834b67e). Po wejściu na stronę kliknij przycisk „Acquire”, jak pokazano na obrazku:

![](https://cdn.acedata.cloud/q6ytrc.png)

Jeśli nie jesteś zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, gdzie możesz się zarejestrować i zalogować. Po zalogowaniu zostaniesz automatycznie przekierowany z powrotem na tę stronę.

Przy pierwszym wniosku otrzymasz darmowy limit, który pozwala na bezpłatne korzystanie z API.

## Podstawowe użycie (Version 1)

Najpierw zapoznaj się z podstawowym sposobem użycia Version 1, polegającym na podaniu promptu `prompt`, tablicy linków do obrazów referencyjnych `image_urls` oraz modelu `model`, aby uzyskać przetworzony wynik. Szczegóły poniżej:

<p><img src="https://cdn.acedata.cloud/h8dyz3.png" width="500" className="m-auto" /></p>

Widzimy tutaj ustawione nagłówki żądania (Request Headers), w tym:

- `accept`: format odpowiedzi, tutaj `application/json` (format JSON).
- `authorization`: klucz API do wywołania, można go wybrać z listy po złożeniu wniosku.

Dodatkowo ustawiono ciało żądania (Request Body), które zawiera:

- `model`: model generujący wideo, obsługiwane wartości to `sora-2` (tryb standardowy) oraz `sora-2-pro` (tryb HD). Model `sora-2-pro` obsługuje wideo o długości 25 sekund, natomiast `sora-2` tylko 10 i 15 sekund.
- `size`: rozdzielczość wideo, `small` to standardowa rozdzielczość, `large` to HD (tylko Version 1).
- `duration`: długość wideo, obsługiwane wartości to 10, 15, 25 sekund, przy czym 25 sekund jest dostępne tylko w `sora-2-pro` (tylko Version 1).
- `orientation`: orientacja obrazu, obsługiwane wartości to `landscape` (poziomo), `portrait` (pionowo) (tylko Version 1).
- `image_urls`: tablica linków do obrazów referencyjnych, używana do generowania wideo na podstawie obrazów (tylko Version 1).
- `character_url`: link do postaci, wideo nie może zawierać prawdziwych osób (tylko Version 1).
- `character_start`/`character_end`: czas pojawienia się postaci w sekundach, zakres 1-3 sekund (tylko Version 1).
- `prompt`: prompt (wymagany).
- `callback_url`: URL do asynchronicznego callbacku.
- `version`: wersja API, `1` (domyślnie) lub `2`.

## Zadanie generowania wideo na podstawie obrazów (Version 1)

Aby wykonać zadanie generowania wideo na podstawie obrazów, parametr `image_urls` musi zawierać linki do obrazów referencyjnych. Można określić następujące elementy:

- `image_urls`: tablica linków do obrazów referencyjnych używanych do generowania wideo. Należy unikać przesyłania obrazów z prawdziwymi twarzami, ponieważ może to spowodować niepowodzenie zadania.

Przykład wypełnienia:

<p><img src="https://cdn.acedata.cloud/z1ud8l.png" width="500" className="m-auto" /></p>

Odpowiadający kod:

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
```

## Zadanie generowania wideo z postacią (Version 1)

Aby wykonać zadanie generowania wideo z postacią, parametr `character_url` musi zawierać link do wideo potrzebnego do stworzenia postaci. Wideo nie może zawierać prawdziwych osób, w przeciwnym razie zadanie zakończy się niepowodzeniem. Można określić następujące elementy:

- `character_url`: link do wideo potrzebnego do stworzenia postaci, wideo nie może zawierać prawdziwych osób.

Przykład wypełnienia:

<p><img src="https://cdn.acedata.cloud/2nhdr2.png" width="500" className="m-auto" /></p>

## Tryb Version 2

Oprócz trybu Version 1, API obsługuje również tryb Version 2, który można włączyć ustawiając parametr `version` na `2`. Tryb Version 2 obsługuje krótsze długości wideo oraz kontrolę rozdzielczości na poziomie pikseli.

### Opis parametrów Version 2

| Parametr       | Typ     | Wymagany | Opis                                              |
|----------------|---------|----------|--------------------------------------------------|
| `version`      | integer | tak      | Ustaw na `2`                                     |
| `prompt`       | string  | tak      | Prompt do generowania wideo                       |
| `model`        | string  | nie      | `sora-2` (domyślny) lub `sora-2-pro`             |
| `duration`     | integer | nie      | Długość wideo: `4` (domyślnie), `8`, `12` sekund |
| `size`         | string  | nie      | Rozdzielczość: `720x1280` (domyślnie), `1280x720`, `1024x1792`, `1792x1024` |
| `image_urls`   | array   | nie      | Tablica URL obrazów referencyjnych, używana tylko pierwsza grafika, rozmiar musi odpowiadać `size` |
| `callback_url` | string  | nie      | URL do asynchronicznego callbacku                 |

### Przykład podstawowy

```shell
curl -X POST 'https://api.acedata.cloud/sora/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "version": 2,
  "prompt": "cat running on the river",
  "model": "sora-2",
  "duration": 8,
  "size": "1280x720"
}'
```

Odpowiadający kod Python:

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "version": 2,
    "prompt": "cat running on the river",
    "model": "sora-2",
    "seconds": 8,
    "size": "1280x720"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Użycie obrazów referencyjnych (Version 2)

W trybie Version 2 można przekazać obrazy referencyjne przez parametr `image_urls` (używana jest tylko pierwsza grafika):

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "version": 2,
    "prompt": "a person walking through a beautiful garden",
    "model": "sora-2",
    "duration": 4,
    "size": "1280x720",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

> **Uwaga**: rozmiar obrazu referencyjnego powinien odpowiadać parametrowi `size`, np. jeśli `size` to `1280x720`, to obraz powinien mieć rozmiar 1280×720.

### Porównanie parametrów Version 1 i Version 2

| Parametr       | Version 1           | Version 2                                   |
|----------------|---------------------|---------------------------------------------|
| `version`      | 1 (domyślnie)       | 2                                           |
| `prompt`       | ✅                   | ✅                                           |
| `model`        | ✅ sora-2 / sora-2-pro | ✅ sora-2 / sora-2-pro                       |
| `duration`     | ✅ 10/15/25 sekund   | ✅ 4/8/12 sekund                             |
| `orientation`  | ✅ landscape/portrait | ❌ brak                                     |
| `size`         | ✅ small/large       | ✅ 720x1280/1280x720/1024x1792/1792x1024   |
| `image_urls`   | ✅ wiele obrazów     | ✅ tylko pierwszy obraz                      |
| `character_url`| ✅                   | ❌ brak                                     |
| `callback_url` | ✅                   | ✅                                           |

## Asynchroniczne callbacki

Ponieważ generowanie wideo w Sora Videos Generation API zajmuje około 1-2 minut, a długie oczekiwanie na odpowiedź HTTP powoduje zużycie zasobów systemowych, API oferuje wsparcie dla asynchronicznych callbacków.

Proces jest następujący: klient wysyła żądanie z dodatkowym polem `callback_url`. API natychmiast zwraca wynik zawierający `task_id`, który identyfikuje zadanie. Po zakończeniu generowania wideo wynik zostanie przesłany metodą POST w formacie JSON na wskazany `callback_url`, zawierając również `task_id`, co pozwala na powiązanie wyników z zadaniem.

## Obsługa błędów

W przypadku błędów API zwraca odpowiedni kod i komunikat błędu, np.:

- `400 token_mismatched`: złe żądanie, możliwe brak lub nieprawidłowe parametry.
- `400 api_not_implemented`: złe żądanie, możliwe brak lub nieprawidłowe parametry.
- `401 invalid_token`: brak autoryzacji, nieprawidłowy lub brakujący token.
- `429 too_many_requests`: zbyt wiele żądań, przekroczono limit.
- `500 api_error`: błąd wewnętrzny serwera.

### Przykład odpowiedzi błędu

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
