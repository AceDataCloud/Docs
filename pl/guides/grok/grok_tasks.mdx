Główna funkcja API Grok Tasks polega na sprawdzaniu statusu wykonania zadań za pomocą identyfikatora zadania (ID) wygenerowanego przez API Grok Videos Generation.

Dokument ten szczegółowo opisuje instrukcje integracji API Grok Tasks, aby pomóc Ci łatwo zintegrować i sprawdzić status wykonania zadań API Grok Videos Generation.

## Proces aplikacji

Aby korzystać z API Grok Videos Generation, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API, który należy zachować na przyszłość.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować, a po zakończeniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

**Jeden token API wystarczy do korzystania ze wszystkich usług platformy, nie ma potrzeby składania osobnych wniosków dla każdej usługi.** Przy pierwszym wniosku otrzymasz darmowy limit, aby móc skorzystać z usługi; gdy limit się wyczerpie, możesz doładować saldo ogólne w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Grok Videos Generation API →](https://platform.acedata.cloud/documents/grok-videos)

## Przykład żądania

API Grok Tasks może być używane do sprawdzania wyników API Grok Videos Generation.

### Ustawienie nagłówków żądania i ciała żądania

**Nagłówki żądania** obejmują:

- `accept`: określa, że oczekiwany jest wynik odpowiedzi w formacie JSON, tutaj wpisz `application/json`.
- `authorization`: klucz do wywołania API, po złożeniu wniosku można go bezpośrednio wybrać z rozwijanej listy.

**Ciało żądania** obejmuje:

- `id`: identyfikator zadania do sprawdzenia.
- `action`: sposób operacji na zadaniu, dla pojedynczego zapytania wpisz `retrieve`.

### Przykład kodu CURL

```bash
curl -X POST 'https://api.acedata.cloud/grok/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### Przykład odpowiedzi

Po pomyślnym wykonaniu żądania API zwróci szczegółowe informacje o tym zadaniu. Pole `request` to ciało żądania złożone podczas inicjowania zadania, a pole `response` to ciało odpowiedzi zwrócone po zakończeniu zadania, na przykład:

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "request": {
    "prompt": "Klatka filmowa z kociątkiem goniącym motyla w słonecznym ogrodzie",
    "model": "grok-imagine-video-1.5-fast:reverse",
    "resolution": "480p",
    "duration": 8
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "grok-imagine-video-1.5-fast:reverse:41eb9a5f-3b2d-4d1e-9f5a-6c2f1a0b9e77",
        "video_url": "https://cdn.acedata.cloud/c8cbf53aa0.mp4",
        "state": "succeeded"
      }
    ]
  }
}
```

Opis pól jest następujący:

- `id`: identyfikator wygenerowanego zadania, używany do unikalnej identyfikacji tego zadania.
- `request`: informacje o żądaniu w zadaniu.
- `response`: informacje o odpowiedzi w zadaniu.

## Operacje zbiorcze

Aby sprawdzić szczegóły wielu identyfikatorów zadań, ustaw `action` na `retrieve_batch` i przekaż tablicę identyfikatorów zadań przez `ids`:

**Ciało żądania** obejmuje:

- `ids`: tablica identyfikatorów zadań do sprawdzenia.
- `action`: sposób operacji na zadaniu, dla zapytań zbiorczych wpisz `retrieve_batch`.

```bash
curl -X POST 'https://api.acedata.cloud/grok/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```
