Główną funkcją Grok Tasks API jest możliwość sprawdzenia statusu zadania na podstawie ID zadania wygenerowanego przez Grok Videos Generation API.

Niniejsza dokumentacja szczegółowo opisuje sposób integracji Grok Tasks API, aby ułatwić Ci integrację i sprawdzanie statusu zadań z Grok Videos Generation API.

## Proces aplikacji

Aby korzystać z Grok Tasks API, najpierw należy złożyć wniosek o odpowiednią usługę na stronie [Grok Videos Generation API](https://platform.acedata.cloud/documents/grok-videos) i skopiować zwrócone ID zadania.

Następnie przejdź do strony [Grok Tasks API](https://platform.acedata.cloud/documents/grok-tasks) i złóż wniosek o odpowiednią usługę, klikając przycisk „Acquire”.

Jeśli nie jesteś zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na [stronę logowania](https://platform.acedata.cloud), gdzie możesz się zarejestrować i zalogować. Po zalogowaniu zostaniesz automatycznie przekierowany z powrotem na obecną stronę.

Przy pierwszym zgłoszeniu otrzymasz darmowy limit, który pozwala na bezpłatne korzystanie z API.

## Przykład zapytania

Grok Tasks API służy do sprawdzania wyników Grok Videos Generation API.

### Ustawienia nagłówków i ciała zapytania

**Nagłówki zapytania** obejmują:

- `accept`: określa format odpowiedzi jako JSON, wartość to `application/json`.
- `authorization`: klucz API do wywołania, który można wybrać z listy po złożeniu wniosku.

**Ciało zapytania** obejmuje:

- `id`: ID zadania, które chcemy sprawdzić.
- `action`: sposób operacji na zadaniu, dla pojedynczego zapytania wpisujemy `retrieve`.

### Przykład kodu CURL

```bash
curl -X POST 'https://api.acedata.cloud/grok/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### Przykład odpowiedzi

Po udanym zapytaniu API zwróci szczegóły dotyczące zadania. Pole `request` zawiera body zapytania wysłanego przy tworzeniu zadania, a pole `response` zawiera body odpowiedzi po zakończeniu zadania, na przykład:

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "request": {
    "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
    "model": "grok-imagine-video",
    "resolution": "480p",
    "duration": 8
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "grok-imagine-video:41eb9a5f-3b2d-4d1e-9f5a-6c2f1a0b9e77",
        "video_url": "https://cdn.acedata.cloud/c8cbf53aa0.mp4",
        "state": "succeeded"
      }
    ]
  }
}
```

Opis pól:

- `id`: ID zadania generowania, służy do unikalnej identyfikacji tego zadania.
- `request`: informacje o zapytaniu użytym do utworzenia zadania.
- `response`: informacje zwrócone po wykonaniu zadania.

## Operacje zapytań zbiorczych

Aby sprawdzić szczegóły wielu zadań na raz, ustaw `action` na `retrieve_batch` i przekaż tablicę ID zadań w polu `ids`:

**Ciało zapytania** obejmuje:

- `ids`: tablica ID zadań do sprawdzenia.
- `action`: sposób operacji na zadaniach, dla zapytania zbiorczego wpisujemy `retrieve_batch`.

```bash
curl -X POST 'https://api.acedata.cloud/grok/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```
