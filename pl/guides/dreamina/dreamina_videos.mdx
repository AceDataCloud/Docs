## API do generowania wideo z cyfrową postacią

`POST https://api.acedata.cloud/dreamina/videos`

Generowanie wideo z cyfrową postacią napędzaną dźwiękiem (OmniHuman 1.5). Podaj zdjęcie postaci i fragment dźwięku, aby wygenerować wideo, w którym postać mówi i synchronizuje ruchy ust.

### Nagłówki żądania

| Nagłówek        | Wartość                     |
| --------------- | --------------------------- |
| `Authorization` | `Bearer <twój klucz API>`   |
| `Content-Type`  | `application/json`          |

### Parametry żądania

| Parametr        | Typ      | Wymagane | Opis                                                                    |
| --------------- | -------- | -------- | ----------------------------------------------------------------------- |
| `model`        | string   | Nie      | Model, domyślnie `omnihuman-1.5`                                       |
| `image_url`    | string   | Tak      | Publiczny URL zdjęcia postaci, zaleca się wyraźne zdjęcie twarzy       |
| `audio_url`    | string   | Tak      | Publiczny URL dźwięku (mp3/wav), zaleca się &lt; 60 sekund               |
| `prompt`       | string   | Nie      | Kontrola wyrazu twarzy, emocji, stabilności i stylu                    |
| `mask_url`     | string[] | Nie      | URL maski dla obiektu, aby wskazać obiekt do napędu w przypadku wielu osób |
| `callback_url` | string   | Nie      | Jeśli podany, natychmiast zwraca `task_id`, a po wygenerowaniu wyników wywołuje ten adres |
| `async`        | boolean  | Nie      | Ustaw na `true`, aby natychmiast zwrócić `task_id`, bez potrzeby `callback_url`, poprzez `/dreamina/tasks` sprawdzaj wyniki |

### Sugestie dotyczące wejścia

- **Obraz**: Wyraźne, dobrze oświetlone zdjęcie twarzy jest najlepsze; twarz nie powinna być zasłonięta, a jej proporcje w kadrze powinny być odpowiednie.
- **Dźwięk**: mp3/wav, musi być dostępny publicznie. Zaleca się, aby czas trwania nie przekraczał 60 sekund (1080p zaleca się ≤30 sekund, 720p ≤60 sekund).
- `image_url` i `audio_url` muszą być dostępne publicznie.

### Przykład odpowiedzi

```json
{
  "success": true,
  "task_id": "0c0b4d3a-2f1e-4a6b-9c2d-2b3c4d5e6f70",
  "trace_id": "a9063166-26ed-4451-85b5-54e896817c69",
  "data": {
    "task_id": "362b4fed67bd11f1ad1100163e57d510",
    "status": "done",
    "video_url": "https://cdn.acedata.cloud/634d760216.mp4",
    "image_url": "https://cdn.acedata.cloud/4hfydw.jpg",
    "audio_url": "https://cdn.acedata.cloud/6f7d62b18b.wav"
  }
}
```

### Asynchroniczność i zapytania

Interfejs domyślnie zwraca ostateczne wideo synchronizacyjnie. Dla dłuższych zadań można użyć jednego z dwóch trybów asynchronicznych:

- Podaj `callback_url`: interfejs natychmiast zwraca `task_id`, a po wygenerowaniu wyników wywołuje ten adres.
- Podaj `async: true`: interfejs natychmiast zwraca `task_id`, a następnie sprawdzaj wyniki za pomocą `POST /dreamina/tasks` (bezpłatnie) według `task_id` lub `trace_id`.

Szczegóły dotyczące umowy dotyczącej sprawdzania wyników znajdują się w [Dreamina Tasks API](https://platform.acedata.cloud/documents/dreamina-tasks-integration).

### Obsługa błędów

| Kod statusu | kod                                      | Znaczenie                                   |
| ----------- | ---------------------------------------- | ------------------------------------------- |
| 400         | `bad_request`                            | Brak lub nieprawidłowy parametr (np. `image_url` / `audio_url`) |
| 401         | `authorization_missing` / `invalid_token` | Brak lub nieprawidłowy token autoryzacji   |
| 403         | `forbidden`                              | Niewystarczające saldo/kwoty lub brak autoryzacji upstream |
| 429         | `too_many_requests`                      | Zbyt wiele żądań, przekroczono limit szybkości |
| 500         | `api_error`                              | Błąd wewnętrzny serwera                     |

```json
{
  "error": {
    "code": "bad_request",
    "message": "image_url is required (a public URL of a portrait image)"
  },
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

### Rozliczenia

Opłaty są naliczane na podstawie długości generowanego wideo, maksymalny pakiet wynosi około **¥1/sekundę** (np. wideo 10-sekundowe kosztuje około ¥10).
