Claude Code to narzędzie **Agentic Coding** wydane przez Anthropic, znane również jako jeden z najsilniejszych agentów programistycznych na świecie. Aplikacja desktopowa Claude Code oferuje niezależny interfejs graficzny, wspierający funkcje przeglądania Diff, równoległych sesji (izolowanych przez Git Worktree), sesji zdalnych i inne, bez potrzeby korzystania z jakiegokolwiek IDE.

Dokument ten opisuje, jak skonfigurować i używać aplikacji desktopowej Claude Code za pośrednictwem usługi proxy AceData Cloud.

> **Uwaga**: Aplikacja desktopowa Claude Code jest obecnie w fazie podglądu (Preview) i obsługuje tylko macOS i Windows.

## Proces aplikacji

Aby korzystać z Claude Code, najpierw przejdź do [strony usługi Claude Messages](https://platform.acedata.cloud/documents/claude-messages) i kliknij przycisk „Acquire”, aby uzyskać wymagane poświadczenia:

![](https://cdn.acedata.cloud/nyq0xz.png)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować, a po zalogowaniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

Podczas pierwszej aplikacji otrzymasz darmowy limit, aby bezpłatnie wypróbować usługi Claude Code.

## Instalacja aplikacji desktopowej

### Wymagania systemowe

- macOS (Intel i Apple Silicon) lub Windows (x64 / ARM64)
- Linux nie obsługuje aplikacji desktopowej

### Pobieranie i instalacja

Przejdź do [oficjalnej strony pobierania Claude](https://claude.ai), aby pobrać odpowiedni pakiet instalacyjny dla swojej platformy:

- **macOS**: pobierz plik `.dmg`, przeciągnij do folderu Applications
- **Windows x64**: pobierz pakiet instalacyjny `.exe`, postępuj zgodnie z instrukcjami
- **Windows ARM64**: pobierz wersję ARM64 (uwaga: ARM64 nie obsługuje sesji lokalnych, należy używać sesji zdalnych)

![Strona pobierania aplikacji desktopowej Claude](https://cdn.acedata.cloud/c3c8c57264.png)

Po zakończeniu instalacji uruchom Claude z folderu Applications (macOS) lub menu Start (Windows).

## Konfiguracja API AceData Cloud

Po uruchomieniu aplikacji desktopowej należy zalogować się na konto Anthropic. Możemy skonfigurować zmienne środowiskowe, aby korzystać z API proxy AceData Cloud, **bez potrzeby posiadania oficjalnej subskrypcji**.

Aplikacja desktopowa odczytuje zmienne środowiskowe z twojego środowiska Shell, dlatego należy je ustawić w pliku konfiguracyjnym Shell.

### Konfiguracja zmiennych środowiskowych

**Użytkownicy macOS**

Dodaj poniższe treści do `~/.zshrc` (lub `~/.bashrc`), zastępując `{token}` swoim tokenem API:

```bash
# AceData Cloud - Konfiguracja proxy Claude Code
export ANTHROPIC_AUTH_TOKEN="{token}"
export ANTHROPIC_BASE_URL="https://api.acedata.cloud"
```

Po zapisaniu wykonaj:

```bash
source ~/.zshrc
```

**Użytkownicy Windows**

Dodaj poniższe zmienne środowiskowe systemu przez „Właściwości systemu → Zaawansowane → Zmienne środowiskowe”:

| Nazwa zmiennej            | Wartość                           |
| ---------------------- | ----------------------------- |
| `ANTHROPIC_AUTH_TOKEN` | `{token}` (zastąp swoim tokenem API)     |
| `ANTHROPIC_BASE_URL`   | `https://api.acedata.cloud` |

Lub użyj PowerShell:

```powershell
[System.Environment]::SetEnvironmentVariable("ANTHROPIC_AUTH_TOKEN", "{token}", "User")
[System.Environment]::SetEnvironmentVariable("ANTHROPIC_BASE_URL", "https://api.acedata.cloud", "User")
```

**Można również skonfigurować przez settings.json**

Edytuj `~/.claude/settings.json` (jeśli nie istnieje, utwórz):

```json
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "{token}",
    "ANTHROPIC_BASE_URL": "https://api.acedata.cloud"
  }
}
```

> **Wskazówka**: Token API można zobaczyć w [konsoli AceData Cloud](https://platform.acedata.cloud/console). Po zakończeniu konfiguracji należy **zrestartować aplikację desktopową**, aby zmienne środowiskowe zaczęły działać.

## Podstawowe użycie

### Otwórz projekt

1. Uruchom aplikację desktopową Claude
2. Kliknij zakładkę **Code** na górze
3. Wybierz tryb uruchomienia **Local**
4. Kliknij **Select folder**, aby wybrać katalog swojego projektu

### Rozpocznij rozmowę

W polu tekstowym wpisz naturalny opis swoich potrzeb:

- „Znajdź komentarze TODO i napraw je”
- „Dodaj testy do funkcji głównej”
- „Wyjaśnij architekturę tego projektu”

Claude przeanalizuje twoją bazę kodu, zaproponuje zmiany i wyświetli je w widoku Diff.

### Tryb uprawnień

Przełącz tryby za pomocą selektora obok przycisku wysyłania:

| Tryb       | Opis                 |
| -------- | ------------------ |
| **Ask**  | Pyta o potwierdzenie przed każdą zmianą (zalecane dla nowicjuszy)  |
| **Code** | Automatycznie akceptuje edycje plików, ale polecenia terminala nadal wymagają potwierdzenia |
| **Plan** | Najpierw opracowuje szczegółowy plan, czeka na zatwierdzenie, a następnie wykonuje |

### Równoległe sesje

Klikając **+ New session** w pasku bocznym, można uruchomić wiele równoległych sesji. Dla repozytoriów Git każda sesja uzyskuje niezależną kopię projektu przez Worktree, co pozwala na wzajemną izolację.

Worktree domyślnie przechowywane jest w katalogu `~/.claude-worktrees/`.

### Przegląd Diff

Gdy Claude zmodyfikuje pliki, wyświetli statystyki zmian (np. `+12 -1`), kliknięcie otworzy przeglądarkę Diff, aby przeglądać zmiany w poszczególnych plikach. Możesz również kliknąć konkretne linie kodu, aby dodać komentarze, a Claude dostosuje się do twoich uwag.

## Połączenie z narzędziami zewnętrznymi

Przed rozpoczęciem sesji kliknij przycisk **⋯**, wybierz **Connectors**, aby dodać integracje zewnętrzne:

- Google Calendar
- Slack
- GitHub
- Linear
- Notion
- Więcej...

Po połączeniu Claude może bezpośrednio odczytywać kalendarz, wysyłać wiadomości, tworzyć zgłoszenia itp.

## Relacja z CLI

Aplikacja desktopowa i CLI korzystają z tego samego silnika, dzieląc następujące konfiguracje:

- Pliki pamięci projektu `CLAUDE.md` / `CLAUDE.local.md`
- Konfiguracja serwera MCP w `~/.claude.json` / `.mcp.json`
- Ustawienia w `~/.claude/settings.json`
- Konfiguracja Hooks i Skills

Obie mogą działać jednocześnie w tym samym projekcie, każda z nich utrzymuje niezależną historię sesji.

## Często zadawane pytania

### Co zrobić, gdy połączenie nie działa?

1. Sprawdź, czy plik `~/.claude/config.json` został poprawnie utworzony
2. Upewnij się, że zmienne środowiskowe zostały poprawnie ustawione (zrestartuj aplikację desktopową, aby je aktywować)
3. Upewnij się, że token API jest ważny (można go zobaczyć w [konsoli](https://platform.acedata.cloud/console))
4. Jeśli używasz `settings.json` do konfiguracji zmiennych środowiskowych, upewnij się, że format pliku jest poprawny

### Co zrobić, gdy nie mogę znaleźć zainstalowanych narzędzi?

Jeśli Claude nie może znaleźć poleceń `npm`, `node` itp.:

1. Upewnij się, że te narzędzia działają poprawnie w zwykłym terminalu
2. Sprawdź, czy twój plik konfiguracyjny Shell (`~/.zshrc`, `~/.bashrc`) jest poprawnie ustawiony dla PATH
3. Zrestartuj aplikację desktopową, aby ponownie załadować zmienne środowiskowe

### Jak sprawdzić pozostały limit?

Zaloguj się do [konsoli AceData Cloud](https://platform.acedata.cloud/console), aby zobaczyć aktualny limit i stan wykorzystania konta.
