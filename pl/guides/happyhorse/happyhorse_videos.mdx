Niniejszy dokument opisuje sposób integracji z HappyHorse Videos API. Interfejs obsługuje generowanie wideo z tekstu, wideo z pierwszej klatki, wideo z obrazu referencyjnego oraz edycję wideo za pośrednictwem jednolitego punktu dostępu `/happyhorse/videos` oraz parametru `action`.

## Proces aplikacji

Aby korzystać z HappyHorse Videos API, najpierw przejdź do [Ace Data Cloud Console](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API, który należy zachować na przyszłość.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować, a po zakończeniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

**Jeden token API wystarczy do korzystania ze wszystkich usług platformy, nie ma potrzeby składania osobnych wniosków dla każdej usługi.** Przy pierwszym wniosku przyznawana jest darmowa pula, aby można było skorzystać z bezpłatnej wersji próbnej; w przypadku niewystarczającej puli można doładować saldo ogólne w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [HappyHorse Videos API →](https://platform.acedata.cloud/documents/happyhorse-videos)

## Typy operacji

`action` określa tryb generacji dla tego żądania:

- `generate`: wideo z tekstu, domyślny action, obsługuje `happyhorse-1.0-t2v` i `happyhorse-1.1-t2v`, musi być przekazany `prompt`.
- `image_to_video`: wideo z pierwszej klatki, obsługuje `happyhorse-1.0-i2v` i `happyhorse-1.1-i2v`, musi być przekazany `image_url`.
- `reference_to_video`: wideo z obrazu referencyjnego, obsługuje `happyhorse-1.0-r2v` i `happyhorse-1.1-r2v`, musi być przekazany `prompt` oraz 1–9 `image_urls`.
- `video_edit`: edycja wideo, obsługuje `happyhorse-1.0-video-edit`, musi być przekazany `prompt` oraz `video_url`, można dodatkowo przekazać 0–5 obrazów referencyjnych `image_urls`.

Każda akcja domyślnie używa modelu 1.1; `video_edit` obecnie obsługuje tylko `happyhorse-1.0-video-edit`.

## Podstawowe użycie

Aby wygenerować wideo z tekstu, wystarczy podać `prompt`, można również określić parametry `resolution`, `ratio`, `duration` itp.:

```json
{
  "action": "generate",
  "model": "happyhorse-1.1-t2v",
  "prompt": "Kino, biały koń podnosi głowę, grzywa delikatnie porusza się w wietrze o wschodzie słońca, powolne zbliżenie kamery, ciepłe oświetlenie filmowe",
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}
```

Przykład zwróconego wyniku:

```json
{
  "success": true,
  "task_id": "27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1",
  "trace_id": "6071ab5e-2f37-46f0-9e07-f1e378112e69",
  "data": [
    {
      "id": "9650580f-6d9e-4bc1-823a-29011790c5cb",
      "video_url": "https://platform2.cdn.acedata.cloud/happyhorse/27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1.mp4",
      "state": "succeeded",
      "duration": 5,
      "resolution": "720P",
      "ratio": null
    }
  ]
}
```

Opis pól:

- `success`: czy to żądanie zakończyło się sukcesem.
- `task_id`: identyfikator zadania po stronie Ace Data Cloud, może być użyty do sprawdzenia statusu zadania.
- `trace_id`: identyfikator śledzenia tego żądania, używany do rozwiązywania problemów.
- `data`: lista wyników wideo.
  - `id`: identyfikator zadania po stronie HappyHorse.
  - `video_url`: adres URL CDN wygenerowanego wideo.
  - `state`: status zadania, opcjonalnie `pending` / `succeeded` / `error`.
  - `duration`: czas trwania wideo do rozliczenia, w sekundach; `video_edit` to suma czasu trwania wideo wejściowego i wyjściowego.
  - `resolution`: rozdzielczość wyjściowa.
  - `ratio`: proporcje wyjściowe.

Odpowiedni kod CURL wygląda następująco:

```shell
curl -X POST 'https://api.acedata.cloud/happyhorse/videos' \
-H 'authorization: Bearer ${bearer_token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "happyhorse-1.1-t2v",
  "prompt": "Kino, biały koń podnosi głowę, grzywa delikatnie porusza się w wietrze o wschodzie słońca, powolne zbliżenie kamery, ciepłe oświetlenie filmowe",
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}'
```

Odpowiedni kod Python wygląda następująco:

```python
import requests

url = "https://api.acedata.cloud/happyhorse/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "action": "generate",
    "model": "happyhorse-1.1-t2v",
    "prompt": "Kino, biały koń podnosi głowę, grzywa delikatnie porusza się w wietrze o wschodzie słońca, powolne zbliżenie kamery, ciepłe oświetlenie filmowe",
    "resolution": "720P",
    "ratio": "16:9",
    "duration": 5,
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Wideo z pierwszej klatki

Podczas używania `image_to_video`, `image_url` będzie traktowane jako pierwsza klatka wideo. Proporcje wyjściowe będą starały się podążać za obrazem pierwszej klatki, dlatego ta akcja nie wymaga podawania `ratio`.

```json
{
  "action": "image_to_video",
  "model": "happyhorse-1.1-i2v",
  "image_url": "https://cdn.acedata.cloud/b1c82e4937.png",
  "prompt": "Kino, biały koń podnosi głowę, grzywa delikatnie porusza się w wietrze o wschodzie słońca, powolne zbliżenie kamery, ciepłe oświetlenie filmowe",
  "resolution": "1080P",
  "duration": 5
}
```

## Wideo z obrazu referencyjnego

Podczas używania `reference_to_video`, `image_urls` może zawierać od 1 do 9 obrazów referencyjnych. W promptach można używać `character1`, `character2` itp. do odniesienia się do odpowiednich obrazów w kolejności.

```json
{
  "action": "reference_to_video",
  "model": "happyhorse-1.1-r2v",
  "prompt": "character1 idzie do przodu przez łąkę o wschodzie słońca w stylu ciepłej skóry i złotych wykończeń z character2",
  "image_urls": [
    "https://cdn.acedata.cloud/b1c82e4937.png",
    "https://cdn.acedata.cloud/eb75d88a3f.png"
  ],
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}
```

## Edycja wideo

Podczas używania `video_edit` należy przekazać `video_url` wideo do edycji oraz intencję edycji `prompt`. Opcjonalne `image_urls` będą traktowane jako obrazy referencyjne, na przykład do zmiany stroju, stylu lub lokalnej zamiany. `audio_setting` może być ustawione na `auto` lub `origin`, gdzie `origin` oznacza zachowanie oryginalnego dźwięku wideo.

```json
{
  "action": "video_edit",
  "model": "happyhorse-1.0-video-edit",
  "prompt": "Zastosuj styl ciepłej skóry i złotych wykończeń z obrazu referencyjnego, zachowując oryginalny ruch kamery",
  "video_url": "https://platform2.cdn.acedata.cloud/happyhorse/27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1.mp4",
  "image_urls": [
    "https://cdn.acedata.cloud/eb75d88a3f.png"
  ],
  "resolution": "720P",
  "audio_setting": "auto"
}
```

## Asynchroniczne powiadomienia zwrotne
Generowanie wideo wymaga pewnego czasu przetwarzania. Jeśli nie chcesz utrzymywać długiego połączenia w oczekiwaniu, możesz przekazać `callback_url`, w takim przypadku API natychmiast zwróci `task_id`, a po zakończeniu zadania ostateczny wynik zostanie wysłany metodą POST na ten adres:

```json
{
  "action": "generate",
  "prompt": "Koń biegnący przez zaśnieżony las",
  "duration": 5,
  "callback_url": "https://your-domain.com/callback/happyhorse"
}
```

Natychmiast zwrócony wynik wygląda następująco:

```json
{
  "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea"
}
```

Jeśli chcesz tylko sprawdzać status, bez potrzeby używania callbacku, możesz również przekazać `"async": true`, a następnie sprawdzić wyniki zadania za pomocą [HappyHorse Tasks API](https://platform.acedata.cloud/documents/happyhorse-tasks).

## Opis rozliczeń

HappyHorse rozlicza na podstawie liczby sekund wideo i rozdzielczości:

- `720P`: od około $0.105 / sekunda.
- `1080P`: od około $0.18 / sekunda.
- `video_edit`: rozliczane na podstawie łącznego czasu trwania wideo wejściowego i wyjściowego, rzeczywisty czas rozliczeniowy oparty jest na statystykach po zakończeniu zadania.

Nieudane zadania nie są rozliczane i nie zajmują darmowego limitu.

## Obsługa błędów

Gdy wystąpi problem z żądaniem, API zwróci odpowiedni kod błędu i opis, najczęstsze to:

- `400`: Błędne parametry żądania, na przykład akcja i model się nie zgadzają, brakuje `prompt` / `image_url` / `video_url`, lub `duration` przekracza zakres 3–15 sekund.
- `401`: Nieudana autoryzacja, token jest nieważny lub niezgodny z API.
- `403`: Niewystarczające saldo lub słowo kluczowe zostało odrzucone w wyniku przeglądu treści.
- `429`: Zbyt częste żądania, przekroczono limit, spróbuj ponownie później.
- `500`: Błąd wewnętrzny serwera lub niepowodzenie generowania.
