---
title: "Pobieranie szczegółów zamówienia na platformie AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Zapytaj o zamówienie za pomocą identyfikatora zamówienia. Ten endpoint obsługuje dwa tryby odczytu: dostęp anonimowy zwraca tylko minimalne pola wymagane przez stronę płatności; właściciel zamówienia z tokenem Account otrzymuje pełne szczegóły.

## Przegląd interfejsu

| Pozycja   | Treść                                                        |
| --- | --------------------------------------------------------- |
| Metoda  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| Uwierzytelnianie  | Opcjonalne; anonimowo minimalna projekcja, uwierzytelniony właściciel pełna projekcja                                    |

`/orders/{id}` oraz `/orders/{id}/` są obecnie oba dostępne. Identyfikator zamówienia jest częścią linku płatności i powinien być traktowany jako poufny, nieprzezroczysty identyfikator, nie należy go publicznie rozpowszechniać.

## Zapytanie anonimowe

Strona płatności może odczytywać bezpośrednio po utracie stanu logowania:

```shell
export ORDER_ID='twój identyfikator zamówienia'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

Odpowiedź anonimowa zawiera tylko `id`, `description`, `price`, `state`, `pay_way`, `pay_url`, `expired_at`, `created_at`. Nie zwraca ona konta, Application, Package, wewnętrznych identyfikatorów płatności ani metadata.

## Zapytanie uwierzytelnione

```shell
export PLATFORM_TOKEN='twój token konta'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Właściciel zamówienia otrzyma pełne szczegóły Order, w tym `application` / `applications`, `package` / `packages`, `bank_details`, `invoice_automation` oraz pola modelu. Jeśli użytkownik jest uwierzytelniony, ale nie jest właścicielem zamówienia, zwracane jest `403`; z wyjątkiem superadministratorów.

## Kluczowe pola

| Pole            | Opis                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`, `Paid`, `Finished`, `Expired`, `Failed` lub `Refunded` |
| `pay_way`     | Bieżąca metoda płatności zamówienia; nazwa pola to nie `payment_method`                             |
| `pay_url`     | Adres hostowanej strony płatności lub kodu QR, może być pusty                                           |
| `price`       | Ostateczna kwota do zapłaty za zamówienie, bieżący model zamówienia nie udostępnia pola `final_price`                         |
| `amount`      | Liczba jednostek limitu pakietu; widoczna tylko w pełnej odpowiedzi uwierzytelnionej                                            |
| `finished_at` | Czas ukończenia zamówienia; nazwa pola to nie `paid_at`                                      |

Pełna odpowiedź może zawierać dodatkowe pola zależne od metody płatności, klient powinien odczytywać je w razie potrzeby i zawsze unikać rejestrowania poufnych metadata w pełnej odpowiedzi.

## Obsługa błędów

- `404`: identyfikator zamówienia nie istnieje.
- `403`: użytkownik jest zalogowany, ale nie jest właścicielem zamówienia.
- Żądanie anonimowe nie zwróci `401`; otrzyma jedynie minimalną publiczną projekcję.
