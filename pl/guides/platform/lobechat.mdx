[LobeChat](https://lobehub.com/) to klient AI typu open source obsługujący wtyczki, bazy wiedzy i samodzielne wdrażanie, dostępny w wersji online lub do wdrożenia za pomocą Docker. Obsługuje niestandardowe endpointy zgodne z OpenAI, dlatego można go połączyć z Ace Data Cloud. Ten artykuł przedstawia proces konfiguracji.

## Proces aplikacji

Aby połączyć Ace Data Cloud w LobeChat, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachowaj go do późniejszego użycia.

![Uzyskiwanie Ace Data Cloud API Key](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i zalogowania się; po zalogowaniu i rejestracji nastąpi automatyczny powrót na bieżącą stronę.

Przy pierwszej aplikacji otrzymasz darmowy limit, dzięki któremu możesz bezpłatnie wypróbować usługi modeli Ace Data Cloud.

## Konfiguracja Ace Data Cloud

Przejdź do **Ustawienia aplikacji → Modele językowe** w LobeChat, znajdź kartę **OpenAI** i ją włącz, a następnie wypełnij:

| Pole       | Wartość                              | Opis                         |
| -------- | ------------------------------ | -------------------------- |
| API Key  | Twój Ace Data Cloud Token        | Token skopiowany z konsoli               |
| Adres proxy API | `https://api.acedata.cloud/v1` | **Musi kończyć się na `/v1`**           |
| Tryb żądań klienta  | Włączony                             | Bezpośrednie połączenie z przeglądarki, Key nie przechodzi przez serwer LobeChat |

![Interfejs konfiguracji LobeChat OpenAI Provider](https://cdn.acedata.cloud/629ef9d3084a.png)

> Podczas korzystania z interfejsu Chat Completions zachowaj wyłączoną opcję Responses API Specification.

LobeChat nie dodaje automatycznie `/v1` do Base URL, a ścieżka żądania to bezpośrednio `{Adres proxy API}/chat/completions`:

| Adres proxy API                              | Rzeczywiste żądanie                                                   | Wynik                       |
| ------------------------------------- | ------------------------------------------------------ | ------------------------ |
| `https://api.acedata.cloud/v1`        | `https://api.acedata.cloud/v1/chat/completions`        | Poprawne                       |
| `https://api.acedata.cloud/openai`    | `https://api.acedata.cloud/openai/chat/completions`    | Również działa                      |
| `https://api.acedata.cloud/openai/v1` | `https://api.acedata.cloud/openai/v1/chat/completions` | 404 (brak `/v1` w `/openai`) |
| `https://api.acedata.cloud`           | `https://api.acedata.cloud/chat/completions`           | 404 (brakuje `/v1`)             |

LobeChat domyślnie wywołuje `/v1/models`, aby automatycznie pobrać modele. Gdy Ace Data Cloud zwraca wiele modeli, interfejs może stać się bardzo długi, dlatego zaleca się ręczne wpisanie allow list w „Lista modeli → Niestandardowe nazwy modeli”, oddzielając elementy przecinkami angielskimi. Jeśli potrzebujesz niestandardowej nazwy wyświetlanej, możesz użyć `=`, w formacie `MODEL_ID=wyświetlana nazwa`.

## Wybór modelu

Katalog modeli będzie stale aktualizowany. W pierwszej kolejności używaj listy modeli automatycznie załadowanej przez klienta; jeśli wymagane jest ręczne wpisanie, najpierw wyślij żądanie `GET https://api.acedata.cloud/v1/models`, aby uzyskać aktualny ID modelu, a następnie wybierz zgodnie z obsługiwanymi przez klienta możliwościami kontekstu, obrazów i wywoływania narzędzi.

## Weryfikacja integracji

Jeśli nie masz pewności, czy problem leży po stronie LobeChat, czy sieci, możesz najpierw bezpośrednio zweryfikować endpoint za pomocą curl (zamień `{token}` na swój Token):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

Zwrócenie obiektu `chat.completion` zgodnego z OpenAI oznacza, że zarówno Token, jak i endpoint są gotowe; jeśli zwrócony zostanie `HTTP 403 used_up`, oznacza to, że Token jest prawidłowy, ale saldo jest niewystarczające — wystarczy doładować konto w [konsoli](https://platform.acedata.cloud/console/applications).

## Zaawansowane: samodzielne wdrożenie Docker

Jeśli chcesz wdrożyć prywatną wersję dla zespołu, możesz uruchomić ją jednym poleceniem Docker (zamień `{token}` na swój Token):

```bash
docker run -d \
  --name lobe-chat \
  -p 3210:3210 \
  -e OPENAI_API_KEY={token} \
  -e OPENAI_PROXY_URL=https://api.acedata.cloud/v1 \
  -e ACCESS_CODE=your-secret-password \
  -e OPENAI_MODEL_LIST="MODEL_ID" \
  lobehub/lobe-chat:latest
```

Otwórz `http://IP_twojego_serwera:3210`, wprowadź `ACCESS_CODE`, aby rozpocząć korzystanie; członkowie zespołu nie muszą osobno wypełniać Key. Pełny opis zmiennych środowiskowych, takich jak `OPENAI_API_KEY`, `OPENAI_PROXY_URL` i `OPENAI_MODEL_LIST`, użytych powyżej, znajdziesz w [dokumentacji zmiennych środowiskowych dostawców modeli LobeChat](https://lobehub.com/docs/self-hosting/environment-variables/model-provider). Jeśli używasz odwrotnego proxy nginx z HTTPS, koniecznie dodaj `proxy_buffering off;`, w przeciwnym razie odpowiedzi strumieniowe będą buforowane. Więcej wariantów wdrożenia znajdziesz w [wprowadzeniu do samodzielnego wdrażania LobeChat](https://lobehub.com/docs/self-hosting/start) oraz [wdrażaniu Docker Compose](https://lobehub.com/docs/self-hosting/platform/docker-compose).

## Częste pytania

### Komunikat 404 Not Found

Zwykle adres proxy API został zapisany jako `.../openai/v1` lub pominięto `/v1`. Zmień na `https://api.acedata.cloud/v1`.

### Lista modeli jest pusta

Włącz przełącznik „Tryb żądań klienta”; lub ręcznie wpisz allow list modeli w „Niestandardowe nazwy modeli”.

### Komunikat 401 Unauthorized

Upewnij się, że w API Key wklejony jest Token Ace Data Cloud (bez prefiksu `Bearer`, bez dodatkowych spacji) oraz że saldo przypisanej aplikacji jest wystarczające.
