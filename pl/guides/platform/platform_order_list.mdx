---
title: "Pobieranie listy zamówień na platformie AceDataCloud"

Stronicowane zwracanie zamówień doładowań konta, odpowiednie do wyszukiwania ID zamówień, sprawdzania statusu płatności i uzgadniania rozliczeń.

## Przygotowanie

Utwórz [Account Token](https://platform.acedata.cloud/documents/platform-token) i pobierz UUID bieżącego konta z `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='twój token konta'
export USER_ID='UUID twojego konta'
```

## Przegląd interfejsu

| Pozycja   | Treść                                             |
| --- | ----------------------------------------------- |
| Metoda  | `GET`                                           |
| URL | `https://platform.acedata.cloud/api/v1/orders/` |
| Uwierzytelnianie  | Account Token, token OAuth wymaga `orders:read`       |
| Stronicowanie  | `count` + `items`                               |

Zwykli użytkownicy muszą przekazać własne `user_id`; w przeciwnym razie podczas stronicowania napotkanie obiektów bez uprawnień może zwrócić `403`.

## Parametry zapytania

| Parametr                    | Typ       | Wymagany     | Opis                                                        |
| --------------------- | -------- | ------ | --------------------------------------------------------- |
| `user_id`             | UUID     | Wymagany dla zwykłych użytkowników | Konto, do którego należy zamówienie; obsługuje powtarzane parametry                                             |
| `pay_way`             | string   | Nie      | Filtrowanie według sposobu płatności; obsługuje powtarzane wartości lub wartości rozdzielone przecinkami                                        |
| `state`               | string   | Nie      | Filtrowanie według statusu; obsługuje powtarzane wartości lub wartości rozdzielone przecinkami                                          |
| `created_at_from/to`  | datetime | Nie      | Zakres czasu utworzenia                                                    |
| `finished_at_from/to` | datetime | Nie      | Zakres czasu ukończenia                                                    |
| `limit` / `offset`    | integer  | Nie      | Stronicowanie                                                        |
| `ordering`            | string   | Nie      | `created_at`, `-created_at`, `finished_at` lub `-finished_at` |

Bieżąca lista nie obsługuje filtrowania według `application_id`, `service_id`, `package_id`, `payment_method` ani `tag`; nazwa pola sposobu płatności to `pay_way`.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/orders/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'state=Paid,Finished' \
  --data-urlencode 'pay_way=Stripe' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Opis odpowiedzi

Odpowiedź ma postać `{count, items}`. Pozycje listy online zawierają `id`, `user_id`, `application_id/application_ids`, `package_id/package_ids`, `price`, `amount`, `discount`, `remaining_amount`, `state`, `pay_way`, `pay_id`, `pay_url`, `finished_at`, `expired_at`, `invoice`, `metadata` oraz pola czasu.

- Rzeczywiste statusy to `Pending`, `Paid`, `Finished`, `Expired`, `Failed`, `Refunded`; nie ma `Cancelled`.
- Nazwy pól to `pay_way`, `finished_at`, `discount` i `price`, a nie `payment_method`, `paid_at`, `discount_rate` ani `final_price`.
- `price` jest końcową ceną zapisaną w zamówieniu; waluta i szczegóły rozliczenia mogą znajdować się w kontrolowanych metadata, dlatego nie można ich samodzielnie wywnioskować wyłącznie na podstawie sposobu płatności.
