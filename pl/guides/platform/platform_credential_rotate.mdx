---
title: "Rotacja poświadczeń API platformy AceDataCloud"

Wygeneruj nowy Token lub hasło dla istniejącego Credential. ID poświadczenia, powiązanie z Application, limity i inne pola pozostają bez zmian, a stary sekret natychmiast wygasa.

> Rotacja przerwie działanie klientów, które nadal używają starego sekretu. Najpierw przygotuj bezpieczną dystrybucję i plan wycofania, a następnie wykonaj operację zapisu.

## Przegląd interfejsu

| Element    | Treść                                                                       |
| ---------- | --------------------------------------------------------------------------- |
| Metoda     | `POST`                                                                      |
| URL        | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}/rotate/` |
| Uwierzytelnianie | Account Token                                                        |
| Body       | Brak lub `{}`                                                              |

Pobierz `credential_id` z [listy poświadczeń](https://platform.acedata.cloud/documents/platform-credential-list):

```shell
export PLATFORM_TOKEN='twój token konta'
export CREDENTIAL_ID='ID Credential do rotacji'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/credentials/${CREDENTIAL_ID}/rotate/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

W przypadku sukcesu zwracany jest zaktualizowany Credential. Gdy `type=Token`, odczytaj nowy `token`; gdy `type=Identity`, odczytaj nowe `password`. Traktuj pełną odpowiedź jako sekret i natychmiast zaktualizuj wywołujących.

## Obsługa błędów

- `401`: Account Token jest nieprawidłowy.
- `403`: Brak uprawnień do zarządzania tym poświadczeniem.
- `404`: Credential ID nie istnieje.
