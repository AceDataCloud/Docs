Pobierz pełny status pojedynczego wniosku o usługę za pomocą Application ID — w porównaniu z interfejsem listy zawiera dodatkowe pola, takie jak pełny obiekt `service` (w tym pakiety `packages`), i nadaje się do strony szczegółów.

> ℹ️ Ten interfejs należy do **API zarządzania platformą AceDataCloud**, ze wspólnym prefiksem `https://platform.acedata.cloud/api/v1/`. Pełny indeks interfejsów znajdziesz w sekcji [Pobieranie listy dokumentacji platformy AceDataCloud](https://platform.acedata.cloud/documents/platform-document-list).

## Przegląd interfejsu

| Pozycja   | Treść                                                                    |
| --- | --------------------------------------------------------------------- |
| Metoda  | `GET`                                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/{application_id}` |
| Uwierzytelnianie  | ✅ Wymagany token konta                                                              |

`/applications/{id}` oraz `/applications/{id}/` są obecnie dostępne; przykłady jednolicie używają formy bez końcowego ukośnika.

## Informacje o uwierzytelnianiu (jak uzyskać token konta)

Nagłówek żądania:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Szczegółowy sposób uzyskania znajdziesz w sekcji [Zarządzanie tokenem konta platformy AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

> ℹ️ W przeciwieństwie do interfejsu listy, **sprawdzanie uprawnień w interfejsie szczegółów jest wykonywane bezpośrednio na pojedynczym obiekcie**, więc nie trzeba przekazywać `?user_id=`. Jednak dostęp do wniosku innej osoby zwróci `403 permission_denied`.

## Parametry ścieżki

| Parametr               | Typ   | Wymagany  | Opis             |
| ---------------- | ---- | --- | -------------- |
| `application_id` | UUID | ✅   | Application ID |

## Przykłady żądań

### cURL

```shell
curl 'https://platform.acedata.cloud/api/v1/applications/82f57141-2323-4453-8730-60f7d833a2da' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

app_id = "82f57141-2323-4453-8730-60f7d833a2da"
resp = requests.get(
    f"https://platform.acedata.cloud/api/v1/applications/{app_id}",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}",
    },
    timeout=10,
)
app = resp.json()
print(f"服务：{app['service']['title']}")
print(f"剩余 {app['remaining_amount']} {app['service']['unit']} / 已用 {app['used_amount']}")
```

### Node.js

```javascript
const appId = '82f57141-2323-4453-8730-60f7d833a2da'
const r = await fetch(`https://platform.acedata.cloud/api/v1/applications/${appId}`, {
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log(await r.json())
```

## Opis pól odpowiedzi

Znaczenie pól jest takie samo jak w [interfejsie listy](https://platform.acedata.cloud/documents/platform-application-list), dodatkowo zawiera:

| Pole        | Typ     | Opis                                                        |
| --------- | ------ | --------------------------------------------------------- |
| `service` | object | Pełny obiekt usługi (w tym pakiety `packages`, `unit`, `free_amount`), który można bezpośrednio renderować w panelu szczegółów usługi |

## Obsługa błędów

| HTTP | code                | Znaczenie                  |
| ---- | ------------------- | ------------------- |
| 401  | `not_authenticated` | Brak tokena konta              |
| 403  | `permission_denied` | Ten Application nie należy do Ciebie  |
| 404  | `not_found`         | Application nie istnieje lub został usunięty |

## Praktyczne wskazówki

- **Do monitorowania zbiorczego w pierwszej kolejności używaj listy**: po jednorazowym pobraniu listy Application oceniaj według jednostek i progów poszczególnych usług, aby uniknąć żądań szczegółów pojedynczo.
- **Gdy chcesz sprawdzić liczbę poświadczeń**: użyj [listy poświadczeń API](https://platform.acedata.cloud/documents/platform-credential-list) z filtrowaniem według `application_id`.
- **Sposób diagnozowania `disabled=true`**: sprawdź zgłoszenia / powiadomienia e-mail, aby ustalić, czy usługa została wyłączona z powodu kontroli ryzyka, zaległości w płatnościach lub naruszających zasady wywołań; nie można jej ponownie włączyć przez API, należy skontaktować się z obsługą klienta.
