Zapytaj o rekordy użycia bieżącego konta w usługach typu Proxy. W przypadku zwykłych wywołań API użyj [rekordów wywołań API](https://platform.acedata.cloud/documents/platform-usage-list). Jeśli nie masz pewności co do typu usługi, możesz najpierw sprawdzić `type` w [szczegółach usługi](https://platform.acedata.cloud/documents/platform-service-detail).

## Przygotowanie

1. Zaloguj się na [platformę AceDataCloud](https://platform.acedata.cloud).
2. Utwórz token konta w [konsoli Account Token](https://platform.acedata.cloud/console/platform-tokens) i natychmiast zapisz go w menedżerze haseł lub Secret Manager.
3. Otwórz [stronę profilu](https://auth.acedata.cloud/user/profile), skopiuj UUID bieżącego konta i zapisz go jako `USER_ID`. Można również użyć `user_id` z odpowiedzi na utworzenie tokena konta.
4. Pobierz `application_id` usługi typu Proxy z [listy wniosków o usługi](https://platform.acedata.cloud/documents/platform-application-list). Gdy wymagane jest filtrowanie według punktu końcowego Proxy, pobierz `proxy_id` z [listy Proxy w usłudze](https://platform.acedata.cloud/documents/platform-service-proxies).

Pełny opis tokenów znajdziesz w [zarządzaniu tokenami konta](https://platform.acedata.cloud/documents/platform-token). Ten interfejs używa Account Token, a nie Credential używanego do wywoływania biznesowego API.

```shell
export PLATFORM_TOKEN='twoj token konta'
export USER_ID='twoj UUID konta'
export APPLICATION_ID='twoj Proxy Application ID'
```

## Przegląd interfejsu

| Element     | Treść                                                     |
| ----------- | --------------------------------------------------------- |
| Metoda      | `GET`                                                     |
| URL         | `https://platform.acedata.cloud/api/v1/usage/proxies/`    |
| Uwierzytelnianie | `Authorization: Bearer ${PLATFORM_TOKEN}`          |
| Scope       | `usage:read`                                              |
| Paginacja   | `count` + `items`, domyślnie 10 pozycji na stronę         |

Gdy właściciel Application wykonuje zapytanie według `application_id`, serwer najpierw synchronizuje dostępne rekordy tego Application, a następnie zwraca listę, dlatego czas odpowiedzi może być dłuższy niż w przypadku zwykłej listy API usage. Upoważnieni użytkownicy mogą odczytywać istniejące widoczne rekordy, ale nie uruchamiają synchronizacji po stronie właściciela.

## Parametry zapytania

| Parametr         | Typ       | Wymagany dla | Domyślnie     | Opis                                      |
| ---------------- | --------- | ------------ | ------------- | ----------------------------------------- |
| `user_id`        | UUID      | zwykłych użytkowników | —      | UUID bieżącego konta; przekazanie innego konta zwróci `403` |
| `application_id` | UUID      | zalecany     | —             | Filtruje według Proxy Application; obsługuje powtarzane parametry |
| `proxy_id`       | UUID      | nie          | —             | Filtruje według punktu końcowego Proxy; obsługuje powtarzane parametry |
| `limit`          | integer   | nie          | 10            | Liczba pozycji na stronę, maksymalnie 100 |
| `offset`         | integer   | nie          | 0             | Przesunięcie paginacji                    |
| `ordering`       | string    | nie          | `-created_at` | Malejąco według czasu utworzenia          |

Bieżący interfejs nie obsługuje bezpośredniego filtrowania według modelu, kodu statusu HTTP, Credential ani zakresu czasu, ani nie obsługuje parametru `perspective` interfejsu API usage. Nie dodawaj tych nieobsługiwanych parametrów do żądania i nie zakładaj, że zadziałają.

## Przykład żądania

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/proxies/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'limit=100' \
  --data-urlencode 'ordering=-created_at' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Przykład paginacji w Pythonie:

```python
import os
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/usage/proxies/",
    headers={"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    params={
        "user_id": os.environ["USER_ID"],
        "application_id": os.environ["APPLICATION_ID"],
        "limit": 100,
    },
    timeout=60,
)
response.raise_for_status()
data = response.json()

for usage in data["items"]:
    print(usage["created_at"], usage["deducted_amount"], usage["remaining_amount"])
```

## Kluczowe pola

| Pole                     | Opis                                                        |
| ------------------------ | ----------------------------------------------------------- |
| `user_id`                | Konto ponoszące opłatę za to użycie                         |
| `actor_user_id`          | Rzeczywisty wywołujący; starsze rekordy mogą być puste      |
| `application_id`         | Proxy Application, które wygenerowało ten rekord            |
| `proxy_id`               | Odpowiadający punkt końcowy Proxy                           |
| `credential_id`          | ID powiązanego poświadczenia; starsze rekordy mogą być puste |
| `used_amount`            | Użycie w pierwotnym rekordzie; może być puste               |
| `deducted_amount`        | Ostatecznie faktycznie odjęty limit                         |
| `remaining_amount`       | Pozostały limit Application po odjęciu opłaty               |
| `metadata`               | Publiczne metadane; mogą być puste                          |
| `service` / `credential` | Podsumowanie powiązanego obiektu ułatwiające prezentację; może być puste, gdy powiązany obiekt nie istnieje |

Jednostka limitu jest określana przez `service.unit` odpowiadającego Application.

## Obsługa błędów

| HTTP | Znaczenie                         | Sposób postępowania                                      |
| ---- | --------------------------------- | -------------------------------------------------------- |
| 401  | Token konta nie istnieje lub jest nieprawidłowy | Sprawdź Account Token, nie używaj omyłkowo biznesowego Credential |
| 403  | Brak uprawnień do wyświetlenia rekordów w żądaniu | Użyj Application należącego do bieżącego konta, usuń nieupoważnione `user_id` |
| 5xx  | Synchronizacja lub zapytanie tymczasowo nie powiodły się | Zachowaj warunki filtrowania i ponów próbę z wycofywaniem; w przypadku ciągłych niepowodzeń przekaż wsparciu Application ID oraz czas |
