---
title: "Pobieranie listy Proxy w ramach usługi platformy AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Zwraca stronicowaną listę punktów końcowych Proxy podpiętych do tej usługi za pomocą UUID usługi. Gdy dostępny jest tylko alias, najpierw wywołaj [szczegóły usługi](https://platform.acedata.cloud/documents/platform-service-detail), aby uzyskać `id`.

## Przegląd interfejsu

| Pozycja   | Treść                                                                  |
| --- | ---------------------------------------------------------------------- |
| Metoda  | `GET`                                                                  |
| URL | `https://platform.acedata.cloud/api/v1/services/{service_id}/proxies/` |
| Uwierzytelnianie  | Publiczne, nie wymaga tokena konta                                                              |
| Stronicowanie  | `count` + `items`                                                      |

## Parametry

| Parametr                 | Lokalizacja    | Wymagany  | Opis                               |
| ------------------ | ----- | --- | -------------------------------- |
| `service_id`       | path  | Tak   | UUID usługi, alias nie jest obsługiwany           |
| `limit` / `offset` | query | Nie   | Stronicowanie                               |
| `ordering`         | query | Nie   | Wyrażenie sortowania Django; zalecane `rank` lub `-rank` |

```shell
export SERVICE_ID='Twój Service ID'
curl --get "https://platform.acedata.cloud/api/v1/services/${SERVICE_ID}/proxies/" \
  --data-urlencode 'limit=100' \
  -H 'Accept: application/json'
```

## Opis odpowiedzi

Elementy listy są serializowane przez model Proxy; pola zweryfikowane w środowisku produkcyjnym obejmują `id`, `service_id`, `title`, `endpoint`, `price`, `stage`, `rank`, `tags`, `metadata`, `document_id`, `service` oraz pola czasu.

- Polowym polem wejściowym jest `endpoint`, a nie `path`.
- Polem cenowym jest `price`, a nie `cost`.
- Gdy typ Service nie jest Proxy lub nie podpięto Proxy, zwracane są puste `items`.

Publiczne integracje opierają się wyłącznie na `endpoint` i opublikowanych możliwościach oraz nie powinny zależeć od niepublicznych szczegółów implementacji.
