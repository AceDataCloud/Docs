Stronicowo zwraca punkty końcowe API widoczne w bieżącej witrynie. Nadaje się do wyszukiwania API według ścieżki biznesowej, usługi lub etapu publikacji; jeśli potrzebujesz tylko pełnej definicji jednego API, wywołaj bezpośrednio [szczegóły API](https://platform.acedata.cloud/documents/platform-api-detail).

## Przegląd interfejsu

| Pozycja   | Treść                                         |
| --- | --------------------------------------------- |
| Metoda  | `GET`                                         |
| URL | `https://platform.acedata.cloud/api/v1/apis/` |
| Uwierzytelnianie  | Publiczne, token konta nie jest wymagany                                     |
| Stronicowanie  | `count` + `items`                             |

## Parametry zapytania

| Parametr        | Typ      | Wymagany  | Opis                    |
| --------- | ------- | --- | --------------------- |
| `path`    | string  | Nie   | Dokładnie dopasowuje `path` lub `path2` |
| `service` | string  | Nie   | Alias usługi lub UUID       |
| `stage`   | string  | Nie   | Filtruje według etapu publikacji; można wielokrotnie przekazać wiele wartości      |
| `limit`   | integer | Nie   | Liczba pozycji na stronę, maksymalnie 100           |
| `offset`  | integer | Nie   | Przesunięcie stronicowania                 |

`id`, `service_id`, `tag` obecnie nie są parametrami filtrowania listy; ich przekazanie nie spowoduje odpowiedniego efektu filtrowania.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/apis/' \
  --data-urlencode 'service=midjourney' \
  --data-urlencode 'stage=Production' \
  --data-urlencode 'limit=20' \
  -H 'Accept: application/json'
```

```python
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/apis/",
    params={"service": "midjourney", "limit": 20},
    timeout=30,
)
response.raise_for_status()
for api in response.json()["items"]:
    print(api["id"], api["method"], api["path"])
```

## Opis odpowiedzi

Odpowiedź produkcyjna używa `{count, items}`. Każda pozycja listy obecnie zawiera pola modelu API, a także:

- `document_id`: powiązany identyfikator dokumentacji deweloperskiej, może być pusty;
- `service_id` / `service`: identyfikator głównej usługi i podsumowanie, mogą być puste;
- `definition`: definicja OpenAPI, może być duża;
- `method`, `path`, `path2`, `stage`, `cost`, `tags`, `metadata` itd.

Serializer listy obecnie zawiera `definition`; podczas pobierania pełnego katalogu należy używać stronicowania i ustawić limit czasu. Pola mogą być dodawane z zachowaniem kompatybilności wstecznej, klient powinien odczytywać tylko wymagane pola.
