Ace Data Cloud X402 obecnie rozlicza się wokół USDC i obsługuje dwa typy łańcuchów: EVM i Solana. Metody podpisywania, adresy aktywów, zachowanie gas oraz odpowiednie scenariusze różnią się w zależności od sieci, dlatego przed integracją należy najpierw wybrać sieć.

## Identyfikatory sieci używają CAIP-2

`accepts[].network` w x402 v2 jest identyfikatorem CAIP-2, a nie skróconą nazwą taką jak `base` czy `solana`. Podczas dopasowywania sieci klient musi porównywać ciągi CAIP-2:

| Sieć             | Identyfikator CAIP-2                       |
| -------------- | ----------------------------------------- |
| Base           | `eip155:8453`                             |
| Solana mainnet | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` |

## Macierz wsparcia

| Sieć     | scheme  | Aktywa              | Metoda podpisywania                      | Odpowiednie scenariusze            |
| ------ | ------- | ------------------- | ------------------------------------ | ------------------------ |
| Base   | `exact` | Base USDC           | EIP-3009 `TransferWithAuthorization` | Domyślnie zalecane, dojrzałe wsparcie portfeli i płynności. |
| Base   | `upto`  | Base USDC + Permit2 | Permit2 `PermitWitnessTransferFrom`  | API z rozliczaniem po użyciu, takie jak czat i modele. |
| Solana | `exact` | Solana USDC         | SPL `TransferChecked`                | Portfele Solana, Agent lub scenariusze aplikacji on-chain. |

`upto` jest obecnie dostępne tylko na Base. Rzeczywiście dostępne pozycje zależą od `accepts` zwracanego przez API. Możesz także sprawdzić Facilitator:

```bash
curl https://facilitator.acedata.cloud/supported
```

Odpowiedź Facilitator `/supported`:

```json
{
  "kinds": [
    { "x402Version": 2, "scheme": "exact", "network": "eip155:8453" },
    {
      "x402Version": 2,
      "scheme": "upto",
      "network": "eip155:8453",
      "extra": { "facilitatorAddress": "0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708" }
    },
    {
      "x402Version": 2,
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "extra": { "feePayer": "3SPm6qbgsDkj24MuR8Ss4sH97fziqyCiqFKDyeVU2igq" }
    }
  ]
}
```

Opis wyników:

- `exact` na Base i Solana jest ścieżką płatności o stałej kwocie.
- Tylko Base oferuje ścieżkę rozliczania po użyciu `upto`, zależną od approve Permit2.
- `extra.facilitatorAddress` w pozycji `upto` jest adresem, który klient musi wpisać do witness podczas podpisywania, i musi być zgodny z wartością zwróconą przez serwer.

## Base

Base używa oficjalnego kontraktu USDC:

```text
0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
```

W schemacie `exact` klient podpisuje EIP-712 `TransferWithAuthorization`. Treść podpisu obejmuje:

- `from`: adres portfela płatnika
- `to`: adres odbiorcy Ace Data Cloud
- `value`: kwota bieżącej płatności
- `validAfter` / `validBefore`: okno czasowe ważności podpisu
- `nonce`: 32-bajtowy losowy nonce

Po zweryfikowaniu podpisu Facilitator wywoła w łańcuchu `transferWithAuthorization` USDC, aby ukończyć transfer.

Base jest najbardziej zalecaną siecią do formalnej integracji, szczególnie odpowiednią dla rozliczania po użyciu `upto`, ponieważ ekosystem Permit2, USDC i portfeli jest bardziej dojrzały.

Przykład wyniku weryfikacji Base `exact`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
content ADC_BASE_E2E_OK
tx 0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
block 46726299
explorer https://basescan.org/tx/0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
transfer value 95215 atomic USDC
```

Opis wyników:

- Ponowienie API po płatności zwraca treść modelu `ADC_BASE_E2E_OK`.
- Transakcję on-chain można sprawdzić na BaseScan, numer bloku to `46726299`.
- `95215` atomic USDC odpowiada `0.095215` USDC i jest rzeczywistą kwotą rozliczenia tego wywołania API.

Wynik działania programu dla płatności zamówienia Base `exact`:

```text
order 78481793-304e-47f7-bc0c-8231aec9cc1e
state Finished
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer value 1200000 atomic USDC
```

Opis wyników:

- Końcowy status zamówienia na platformie to `Finished`.
- `pay_id` zamówienia zapisuje ten sam hash transakcji Base.
- `1200000` atomic USDC odpowiada `1.2` USDC i jest historyczną faktycznie zapłaconą kwotą tego zamówienia 10 Credits zgodnie ze starą polityką; nowe zamówienia nie otrzymują już dodatkowej zniżki za metodę płatności X402, a konkretna kwota podpisu zależy od bieżącej odpowiedzi 402.

## Solana

Solana używa SPL USDC `TransferChecked`. Klient konstruuje transakcję transferu, podpisuje ją i przesyła, a następnie umieszcza podpis transakcji lub zserializowaną transakcję w envelope `PAYMENT-SIGNATURE`.

Cechy Solana:

- Używa Solana wallet adapter lub base58 secret key;
- Aktywem jest Solana USDC mint;
- Obecnie obsługuje tylko `exact`;
- Facilitator zweryfikuje mint, destination, authority i amount instrukcji transferu.

Jeśli używany jest tryb wallet fee payer, portfel bezpośrednio przesyła transakcję, a Facilitator odpowiada za potwierdzenie transakcji i zwrócenie wyniku settlement.

Przykład wyniku weryfikacji Solana `exact`:

```text
payer AY2RmGm2zPxB1uKvvF4dKyYdr2VySyL3wcD1MKJZoLRd
HTTP 402 -> HTTP 200
content ADC_SOLANA_E2E_OK
chain signature not confirmed in this run
```

Opis wyników:

- Ponowienie po płatności zwróciło już HTTP 200, a model zwrócił `ADC_SOLANA_E2E_OK`.
- Podczas sprawdzania signature on-chain przez publiczne RPC można napotkać ograniczenie liczby żądań.
- Ponieważ publiczne zapytania RPC mogą być ograniczane, nie podajemy tutaj Solana explorer. Gdy wymagane jest ścisłe uzgodnienie, użyj własnego Solana RPC lub rekordów rozliczeniowych po stronie platformy, aby potwierdzić podpis transakcji.

## Jak wybrać

| Co chcesz zrobić        | Zalecana sieć           |
| ------------ | -------------- |
| Szybko uruchomić minimalny przepływ     | Base `exact`   |
| Obsłużyć zwykłych użytkowników Web3 | Base           |
| Tworzyć rozliczanie po użyciu, takie jak uzupełnianie czatu   | Base `upto`    |
| Aplikacje ekosystemu Solana  | Solana `exact` |

Niezależnie od wybranego łańcucha, nie koduj na sztywno cen po stronie klienta. Cena jest określana przez `accepts[].maxAmountRequired` zwracane przez serwer.

## Dodawanie nowych sieci EVM
Obsługa kodowa płatności natywnym USDC o stałej kwocie w poniższych sieciach została udostępniona i jest włączana kolejno dla każdej sieci.
O dostępności decyduje `accepts` zwracane przez zamówienie lub API; nie oznacza to, że wszystkie sieci zostały włączone na produkcji.

| Sieć         | Alias      | CAIP-2         | Natywny USDC                                 |
| ------------ | ---------- | -------------- | -------------------------------------------- |
| Arbitrum One | `arbitrum` | `eip155:42161` | `0xaf88d065e77c8cC2239327C5EDb3A432268e5831` |

Te sieci obsługują wyłącznie `exact`, a precyzja waluty wynosi 6. Nie używaj mostkowanego USDC o tej samej nazwie.
Podczas używania oficjalnego klienta TypeScript/Python X402 można przekazać skrót z tabeli lub identyfikator CAIP-2.
Klient używa docelowego ID łańcucha do skonstruowania podpisu; portfel musi obsługiwać docelową sieć.

Oficjalna tabela obsługi portfela rozszerzenia Phantom wymienia Arbitrum i Polygon; Optimism, Avalanche
obecnie nie są wymienione w tej tabeli, można użyć Rabby lub MetaMask obsługujących docelowy łańcuch. Adresy EVM mogą być takie same w różnych łańcuchach,
ale salda są niezależne od siebie, a adresy Solana nie mają zastosowania do EVM USDC.
Zobacz [tabelę obsługi portfela Phantom](https://docs.phantom.com/wallet-sdks-overview#chain-support).

### Wejście stopniowego wdrażania nowej sieci

Wejście dla nowego łańcucha jest domyślnie ukryte. Podczas odwiedzania konsoli lub Studio można użyć `?features=x402-arbitrum`,
aby włączyć odpowiedni łańcuch; wiele flag należy rozdzielać przecinkami. Aby wyłączyć pojedynczy łańcuch, użyj `?features=-x402-arbitrum`,
a aby wyczyścić lokalne nadpisania, użyj `?features=none`. Przełączniki są zapisywane osobno dla każdej domeny.
Wyceny zamówień i ponowienia płatności używają tego samego przełącznika, a serwer przeprowadza niezależną walidację; istniejące zapisy płatności nadal można wyświetlać.
Samo włączenie flagi strony nie aktywuje łańcucha, który nie został jeszcze skonfigurowany; konkretne sieci, w których można płacić, nadal zależą od bieżącego `accepts`.
