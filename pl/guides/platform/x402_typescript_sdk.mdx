TypeScript jest jednym z najbardziej zalecanych sposobów integracji z Ace Data Cloud X402. Oficjalny SDK odpowiada za zwykłe wywołania API, odpytywanie zadań, obsługę błędów i automatyczne ponawianie prób; `@acedatacloud/x402-client` odpowiada za podpisywanie nagłówka żądania `PAYMENT-SIGNATURE` po napotkaniu `402 Payment Required`.

Adresy kodu źródłowego i pakietów:

- Repozytorium SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Repozytorium X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm SDK: [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)
- npm X402 Client: [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client)

## Instalacja zależności

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client
```

Jeśli używasz Base, potrzebujesz możliwości podpisywania EVM:

```bash
npm install ethers
```

Jeśli używasz Solana, potrzebujesz adaptera portfela Solana lub `@solana/web3.js`:

```bash
npm install @solana/web3.js
```

Wynik instalacji i sprawdzenia importów w czystym projekcie npm:

```text
imports_ok true true true true true
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4
```

Objaśnienie wyników:

- `@acedatacloud/sdk` i `@acedatacloud/x402-client` można instalować z npm i importować przez Node.js.
- `ethers` służy do podpisywania typed data EVM, a `@solana/web3.js` do konstruowania transakcji Solana.

## Przykład Base

W przeglądarce można bezpośrednio użyć `window.ethereum`. W Node.js można użyć `ethers.Wallet`, aby opakować provider w stylu EIP-1193.

```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});

console.log(result.choices[0].message.content);
```

## Przykład portfela w przeglądarce

Podczas używania MetaMask, Coinbase Wallet lub WalletConnect w aplikacji frontendowej zazwyczaj bezpośrednio przekazuje się provider EIP-1193:

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const [address] = await window.ethereum.request({ method: 'eth_requestAccounts' });

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider: window.ethereum,
    evmAddress: address
  })
});

const image = await client.images.generate({
  provider: 'nano-banana',
  prompt: 'a yellow banana on a white background'
});
```

Portfel przeglądarkowy wyświetli prośbę o potwierdzenie podpisu. Użytkownik nie podpisuje dowolnej wiadomości, lecz wymaganie płatności zwrócone przez API: adres odbiorcy, kontrakt USDC, kwota, okres ważności i nonce są wszystkie zawarte w podpisie.

## Przykład Solana

Solana używa SPL USDC `TransferChecked`. Przekazany adapter portfela musi udostępniać `publicKey` i `signAndSendTransaction`.

```ts
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'solana',
    solanaWallet: phantomWallet
  })
});

const result = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Say hi in 3 words' }],
  max_tokens: 10
});
```

Ścieżka Solana obecnie obsługuje tylko `exact`, a nie obsługuje `upto`. Jeśli API zwróci wiele `accepts`, handler wybierze pozycję z `network = 'solana'`.

Ścieżka Solana została zweryfikowana na tym samym publicznym API: płatna ponowna próba może zwrócić HTTP 200 i `ADC_SOLANA_E2E_OK`. Publiczne zapytania RPC mogą podlegać ograniczeniom szybkości, dlatego ten artykuł nie podaje hash transakcji Solana; gdy wymagane jest uzgodnienie on-chain, użyj własnego Solana RPC lub potwierdź je w zapisach konsoli.

## Wybór `exact` lub `upto`

Obecny handler TypeScript wybiera pierwsze wymaganie płatności dla pasującej sieci zwrócone przez serwer. API Ace Data Cloud zazwyczaj umieszcza `exact` dla tej samej sieci przed `upto`, dlatego jeśli wyraźnie chcesz użyć rozliczania późniejszego, musisz przekazać `preferScheme: 'upto'`.

Przykład:

```ts
const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address,
    preferScheme: 'upto'
  })
});
```

Jeśli serwer nie zwróci requirement `upto` dla tej sieci, handler automatycznie powróci do pierwszego dostępnego requirement dla tej sieci, zazwyczaj `exact`.

`upto` wymaga jednorazowej autoryzacji Permit2. `upto` jest obecnie dostępne tylko na Base, dlatego wystarczy wykonać jedną autoryzację dla Base USDC:

```bash
npx tsx scripts/approve-permit2.ts --network base
```

Base `upto` zakończyło publiczną weryfikację API: HTTP 402 -> HTTP 200, a transakcja późniejszego settlement to `0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036`. Pełne dane wyjściowe znajdują się w opisie schematu rozliczeń.

## Co robi SDK

Transport `@acedatacloud/sdk` wykona handler płatności raz po otrzymaniu 402:

```ts
type PaymentHandler = (ctx: {
  url: string;
  method: string;
  body?: unknown;
  accepts: PaymentRequirement[];
}) => Promise<{ headers: Record<string, string> }>;
```

Handler zwrócony przez `@acedatacloud/x402-client` wykona:

1. Wybierze wymaganie płatności docelowej sieci z `ctx.accepts`.
2. Skonstruuje podpis EVM EIP-712 lub transakcję transferu Solana zgodnie z siecią.
3. Zserializuje envelope do Base64.
4. Zwróci `{ headers: { 'PAYMENT-SIGNATURE': '<base64>' } }`.
5. SDK automatycznie ponowi próbę z oryginalnym body żądania.

Oznacza to, że kod biznesowy wystarczy pisać tak jak zwykłe wywołania SDK, bez konieczności ręcznej obsługi ponownych prób 402.
