Ace Data Cloud oferuje oficjalne klienty SDK w trzech językach: TypeScript / Python / Go, które opakowują możliwości takie jak chat completions, images, video, music, search, x402 dostępne na `api.acedata.cloud` w silnie typizowane metody, eliminując potrzebę ręcznego pisania HTTP, SSE, cykli zadań, obsługi błędów i strategii ponownego próbowania.

Rozdział ten jest zorganizowany według rzeczywistej kolejności integracji: najpierw uzyskanie tokena API w konsoli, następnie wybór języka i zapoznanie się z odpowiednim rozdziałem, a na końcu omówienie zaawansowanych zastosowań związanych z cyklem zadań, odpowiedziami strumieniowymi i płatnościami na blockchainie X402.

## Repozytorium i pakiety

- Kod źródłowy SDK (monorepo): [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- TypeScript: [`@acedatacloud/sdk`](https://www.npmjs.com/package/@acedatacloud/sdk)
- Python: [`acedatacloud`](https://pypi.org/project/acedatacloud/)
- Go: [`github.com/AceDataCloud/SDK/go`](https://pkg.go.dev/github.com/AceDataCloud/SDK/go)
- Klient X402 (TypeScript): [`@acedatacloud/x402-client`](https://www.npmjs.com/package/@acedatacloud/x402-client)
- Klient X402 (Python): [`acedatacloud-x402`](https://pypi.org/project/acedatacloud-x402/)

## Macierz możliwości w trzech językach

| Możliwość                                                      | TypeScript  | Python                  | Go                    |
| ------------------------------------------------------------ | ----------- | ----------------------- | --------------------- |
| `chat.completions.create` (nie-strumieniowe)                | ✅           | ✅                       | ✅                     |
| `chat.completions.create` (strumieniowe SSE)                | ✅           | ✅                       | ✅                     |
| `images.generate` (Midjourney / Flux / NanoBanana / Seedream) | ✅           | ✅                       | 🚧 (alpha)             |
| `videos.generate` (Sora / Veo / Luma / Kling / Hailuo / Wan) | ✅           | ✅                       | 🚧 (alpha)             |
| `audios.generate` (Suno / Producer / Fish)                  | ✅           | ✅                       | 🚧 (alpha)             |
| `search.google` (Serp)                                      | ✅           | ✅                       | 🚧 (alpha)             |
| Asynchroniczne cykle zadań                                   | ✅ (ms)     | ✅ (s)                   | 🚧                     |
| Asynchroniczny klient                                         | ✅ (Promise) | ✅ (`AsyncAceDataCloud`) | ✅ (`context.Context`) |
| Automatyczne ponowne próby + wykładnicze opóźnienie          | ✅           | ✅                       | ✅                     |
| Typizowane wyjątki (`AuthenticationError` / `RateLimitError` …) | ✅           | ✅                       | ✅                     |
| X402 `paymentHandler` hook (płatności na blockchainie bez tokena) | ✅           | ✅                       | ❌ (planowane)         |

> Zasoby multimedialne SDK Go oraz cykle zadań są obecnie w fazie alpha (wersja pseudo `v0.0.0-20260505072132-4a3d921f9bb4`), stabilną możliwością jest `chat.completions`. W przypadku scenariuszy multimedialnych zaleca się wybór TypeScript lub Python.

## Kiedy używać SDK / MCP / natywnego HTTP / X402

| Scenariusz                                      | Zalecana metoda                                                        |
| ------------------------------------------- | ---------------------------------------------------------------------- |
| Usługi backendowe, CLI, skrypty automatyzacji, frameworki Agent | **SDK** (ten rozdział)                                                |
| Wywołania klientów MCP, takich jak Claude Desktop / Cursor / Cline | Serwery MCP                                                          |
| Jednorazowe weryfikacje curl, debugowanie, środowiska obsługujące tylko HTTP | Natywne HTTP (szybki start dla każdego serwisu)                      |
| Nie chcesz tworzyć tokena API, płatności w USDC na łańcuchu wywołań | [Przewodnik integracji X402](https://platform.acedata.cloud/documents/x402-integration) |

SDK i X402 nie wykluczają się nawzajem: SDK obsługuje zarówno „ścieżkę tokena”, jak i „ścieżkę `paymentHandler`”, szczegóły w [SDK + X402 płatności hook](https://platform.acedata.cloud/documents/sdk-x402-payment).

## Uzyskiwanie tokena API

Aby używać SDK, najpierw przejdź do [Konsoli Ace Data Cloud - Lista aplikacji](https://platform.acedata.cloud/console/applications) i uzyskaj token API:

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować, a po zalogowaniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

Podczas pierwszego wnioskowania otrzymasz darmowy limit, aby bezpłatnie wypróbować różne usługi AI oferowane przez Ace Data Cloud.

Skopiuj właśnie uzyskany token, poniżej będziemy go nazywać `{token}`.

## Ujednolicone zmienne środowiskowe

SDK w trzech językach automatycznie odczytuje tę samą zmienną środowiskową `ACEDATACLOUD_API_TOKEN`, zaleca się użycie `export` w shellu, aby SDK mogło ją automatycznie pobrać:

```bash
export ACEDATACLOUD_API_TOKEN={token}
# Opcjonalnie: domyślny https://api.acedata.cloud
# export ACEDATACLOUD_BASE_URL=https://api.acedata.cloud
```

Można również jawnie przekazać ją podczas tworzenia klienta, odpowiednie nazwy parametrów dla trzech języków to:

- TypeScript: `new AceDataCloud({ apiToken: '{token}' })`
- Python: `AceDataCloud(api_token="{token}")`
- Go: `adc.NewClient(adc.WithAPIToken("{token}"))`

> Uwaga: W repozytorium projektu AceDataCloud przyjęto konwencję `ACEDATACLOUD_API_KEY` (w `.env` / CI), ale te trzy SDK rozpoznają tylko `ACEDATACLOUD_API_TOKEN`. Jeśli w twoim środowisku jest tylko `ACEDATACLOUD_API_KEY`, proszę jawnie przekazać ją podczas tworzenia.

## 30 sekund do pierwszego przykładu

Poniższe trzy fragmenty kodu wykonują tę samą czynność: wywołują `gpt-4o-mini`, aby odpowiedział tylko `ADC_*_OK`. Każdy fragment zawiera **rzeczywiste wyniki działania**, które możesz powtórzyć używając własnego tokena.

### TypeScript

```ts
import { AceDataCloud } from '@acedatacloud/sdk';

const client = new AceDataCloud({ apiToken: process.env.ACEDATACLOUD_API_KEY });

const t0 = Date.now();
const res = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Reply with exactly: ADC_TS_SDK_OK' }],
  max_tokens: 20,
  temperature: 0
});
console.log('elapsed_ms', Date.now() - t0);
console.log('id', res.id);
console.log('model', res.model);
console.log('content', res.choices[0].message.content);
console.log('usage', JSON.stringify(res.usage));
```

> SDK obecnie deklaruje odpowiedź jako `Record<string, unknown>`, w czasie działania jest to zwykły obiekt JSON, do którego można uzyskać dostęp bezpośrednio przez pola. W projektach TS o ścisłej typizacji, jeśli napotkasz błędy typów, możesz tymczasowo użyć `as any`, lub zapoznać się z [cyklami zadań SDK i odpowiedziami strumieniowymi](https://platform.acedata.cloud/documents/sdk-tasks-and-streaming) w celu dostosowania typowanego wrappera.

Wynik działania programu:

```text
elapsed_ms 2543
id chatcmpl-DldCcLvkTFaioST8e6SjOl0wJScQA
model gpt-4o-mini
content ADC_TS_SDK_OK
usage {"prompt_tokens":16,"completion_tokens":6,"total_tokens":22}
```

### Python
```python
import os, time, json
from acedatacloud import AceDataCloud

client = AceDataCloud(api_token=os.environ["ACEDATACLOUD_API_KEY"])

t0 = time.time()
res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Odpowiedz dokładnie: ADC_PY_SDK_OK"}],
    max_tokens=20,
    temperature=0,
)
print("elapsed_ms", int((time.time() - t0) * 1000))
print("id", res["id"])
print("model", res["model"])
print("content", res["choices"][0]["message"]["content"])
print("usage", json.dumps({k: v for k, v in res["usage"].items()
                            if k in ("prompt_tokens","completion_tokens","total_tokens")}))
```

> Python SDK obecnie zwraca `dict`, więc używaj `res["id"]` zamiast `res.id`. To różni się od `openai-python`, na co należy zwrócić uwagę podczas migracji.

Wynik działania programu:

```text
elapsed_ms 2963
id chatcmpl-DldFdnIlhSUXINpupgsUmZL78MnBu
model gpt-4o-mini
content ADC_PY_SDK_OK
usage {"prompt_tokens": 17, "completion_tokens": 7, "total_tokens": 24}
```

### Go

```go
package main

import (
    "context"
    "fmt"
    "os"
    "time"

    adc "github.com/AceDataCloud/SDK/go"
)

func main() {
    client, err := adc.NewClient(adc.WithAPIToken(os.Getenv("ACEDATACLOUD_API_KEY")))
    if err != nil {
        panic(err)
    }
    ctx, cancel := context.WithTimeout(context.Background(), 60*time.Second)
    defer cancel()

    t0 := time.Now()
    res, err := client.OpenAI().Chat().Completions().Create(ctx, adc.ChatCompletionRequest{
        Model:     "gpt-4o-mini",
        Messages:  []map[string]any{{"role": "user", "content": "Odpowiedz dokładnie: ADC_GO_SDK_OK"}},
        MaxTokens: 20,
    })
    if err != nil {
        panic(err)
    }
    fmt.Println("elapsed_ms", time.Since(t0).Milliseconds())
    fmt.Println("id", res["id"])
    fmt.Println("model", res["model"])
    choices := res["choices"].([]any)
    msg := choices[0].(map[string]any)["message"].(map[string]any)
    fmt.Println("content", msg["content"])
    usage := res["usage"].(map[string]any)
    fmt.Printf("usage prompt=%v completion=%v total=%v\n",
        usage["prompt_tokens"], usage["completion_tokens"], usage["total_tokens"])
}
```

> Odpowiedzi SDK Go są jednolite jako `map[string]any`, nie ma silnie typowanych struktur, należy samodzielnie przeprowadzać asercję typów. Wszystkie zasoby są dostępne za pomocą łańcucha metod: `client.OpenAI().Chat().Completions().Create(...)`.

Wynik działania programu:

```text
elapsed_ms 6436
id chatcmpl-89DHExvFvBc4ciIPfolZYUOy7ivxv
model gpt-4o-mini
content ADC_GO_SDK_OK
usage prompt=16 completion=5 total=21
```

W odpowiedziach trzech języków `id`, `elapsed_ms`, `usage` pochodzą z tego samego źródła: autoryzacja przez PlatformGateway → docelowe API zgodne z OpenAI → zapisanie rekordów rozliczeniowych. Pole `content` to rzeczywiste wyjście modelu, użycie stałego identyfikatora `ADC_*_OK` ma na celu potwierdzenie, że odpowiedź nie została zmieniona przez SDK.
