title: "Pobieranie listy wniosków o usługę na platformie AceDataCloud"

Stronicowo zwraca Application należące do konta lub udostępnione do użycia, w tym saldo, status, podsumowanie usługi i powiązane poświadczenia. Nadaje się do masowego monitorowania salda, wyszukiwania Application ID i przechodzenia do zarządzania poświadczeniami.

## Przygotowanie

1. Zaloguj się do [platformy AceDataCloud](https://platform.acedata.cloud).
2. Utwórz token konta w [konsoli Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. Zwykli użytkownicy używają `user_id=me`; można również pobrać własny UUID z `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='twój token konta'
```

## Przegląd interfejsu

| Element   | Treść                                                    |
| --- | ----------------------------------------------------- |
| Metoda  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Uwierzytelnianie  | Account Token, token OAuth wymaga `applications:read`       |
| Stronicowanie  | `count` + `items`                                     |

Zwykli użytkownicy powinni przekazać `user_id=me`. Bez jego przekazania zapytanie nie jest najpierw zawężane według konta, a stronicowanie może zwrócić `403` po napotkaniu obiektu bez uprawnień; administratorzy mogą bez jego przekazania przeglądać całą tabelę.

## Parametry zapytania

| Parametr            | Typ          | Wymagany     | Opis                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Wymagany dla zwykłych użytkowników | Podmiot zapytania; obsługuje powtarzane parametry                                         |
| `affiliation` | string      | Nie      | `owner` (domyślnie) lub `granted`; można wielokrotnie przekazać oba, aby uzyskać ich sumę, działa tylko przy `user_id` |
| `service_id`  | UUID        | Nie      | Filtrowanie według usługi; obsługuje powtarzane parametry                                        |
| `scope`       | string      | Nie      | `Individual` lub `Global`; obsługuje powtarzane parametry                      |
| `type`        | string      | Nie      | `Usage` lub `Period`; obsługuje powtarzane parametry                           |
| `limit`       | integer     | Nie      | Liczba elementów na stronę, maksymalnie 100                                         |
| `offset`      | integer     | Nie      | Przesunięcie stronicowania                                               |
| `ordering`    | string      | Nie      | Obsługuje wyłącznie `created_at` lub `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` i `tag` nie są obecnie parametrami filtrowania po stronie serwera. Alerty salda powinny po pobraniu listy być oceniane po stronie klienta na podstawie `remaining_amount`, `service.unit` i progów biznesowych każdego Application.

## Przykład żądania

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Jednoczesne wyświetlanie Application należących do użytkownika i udostępnionych mu przez innych:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Opis odpowiedzi

Odpowiedź ma postać `{count, items}`. Każdy element zawiera pola modelu Application oraz dodatkowo:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: podsumowanie poświadczeń, które bieżący wywołujący ma prawo zobaczyć;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`;
- rzeczywista wartość `scope` to `Individual` lub `Global`;
- rzeczywista wartość `type` to `Usage` lub `Period`.

`remaining_amount` może być puste; klient musi najpierw sprawdzić, czy wartość jest pusta, a następnie wykonać porównanie liczbowe. Jednostkę limitu określa `service.unit`.
