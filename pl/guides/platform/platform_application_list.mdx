title: "Pobieranie listy wniosków o usługi platformy AceDataCloud"

Zwraca stronicowaną listę Application posiadanych przez konto lub autoryzowanych do użycia, w tym saldo, status, podsumowanie usługi i powiązane poświadczenia. Nadaje się do zbiorczego monitorowania salda, wyszukiwania Application ID i przechodzenia do zarządzania poświadczeniami.

## Przygotowanie

1. Zaloguj się do [platformy AceDataCloud](https://platform.acedata.cloud).
2. Utwórz token konta w [konsoli Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. Zwykli użytkownicy używają `user_id=me`; możesz również pobrać własny UUID z `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='twój token konta'
```

## Przegląd interfejsu

| Pozycja   | Treść                                                    |
| --- | ----------------------------------------------------- |
| Metoda  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Uwierzytelnianie  | Account Token, token OAuth wymaga `applications:read`       |
| Paginacja  | `count` + `items`                                     |

Zwykli użytkownicy powinni przekazać `user_id=me`. Bez jego przekazania zapytanie nie zostanie najpierw zawężone według konta, a paginacja może zwrócić `403` po napotkaniu obiektów bez uprawnień; administratorzy bez jego przekazania mogą przeglądać całą tabelę.

## Parametry zapytania

| Parametr            | Typ          | Wymagany     | Opis                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Wymagany dla zwykłych użytkowników | Podmiot zapytania; obsługuje powtarzane parametry                                         |
| `affiliation` | string      | Nie      | `owner` (domyślnie) lub `granted`; można wielokrotnie przekazać oba, aby uzyskać ich sumę, działa tylko przy `user_id` |
| `service_id`  | UUID        | Nie      | Filtrowanie według usługi; obsługuje powtarzane parametry                                        |
| `scope`       | string      | Nie      | `Individual` lub `Global`; obsługuje powtarzane parametry                      |
| `type`        | string      | Nie      | `Usage` lub `Period`; obsługuje powtarzane parametry                           |
| `limit`       | integer     | Nie      | Liczba pozycji na stronę, maksymalnie 100                                         |
| `offset`      | integer     | Nie      | Przesunięcie paginacji                                               |
| `ordering`    | string      | Nie      | Obsługuje wyłącznie `created_at` lub `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` i `tag` nie są obecnie parametrami filtrowania po stronie serwera. Alerty salda powinny po pobraniu listy być oceniane po stronie klienta na podstawie `remaining_amount`, `service.unit` i progów biznesowych każdego Application.

## Przykład żądania

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Jednoczesne wyświetlanie Application posiadanych przez siebie i autoryzowanych innym przez siebie:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Opis odpowiedzi

Odpowiedź ma postać `{count, items}`. Każda pozycja zawiera pola modelu Application oraz dodatkowo:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: podsumowanie poświadczeń, które aktualny wywołujący ma prawo zobaczyć;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`, `allow_overdraft`;
- rzeczywista wartość `scope` to `Individual` lub `Global`;
- rzeczywista wartość `type` to `Usage` lub `Period`.

`allow_overdraft` jest polem logicznym tylko do odczytu kontrolowanym przez administratora, domyślnie ustawionym na `false`. W przypadku aplikacji rozliczanych według użycia (`Usage`) z włączonym debetem niewystarczające saldo nie blokuje wywołań, a opłaty są nadal naliczane według rzeczywistego użycia; ujemne saldo oznacza limit oczekujący na rozliczenie. Wyłączenie, wygaśnięcie i limity poświadczeń API nadal obowiązują.

`remaining_amount` może być puste; klient musi najpierw sprawdzić, czy wartość nie jest pusta, a dopiero potem wykonać porównanie liczbowe. Jednostkę limitu określa `service.unit`.
