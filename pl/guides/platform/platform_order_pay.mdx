Utwórz lub odśwież sesję płatności dla zamówienia `Pending`. Działanie płatności uzyska dostęp do kanału płatności i może zmienić status zamówienia, przed wywołaniem należy potwierdzić ID zamówienia, kwotę i metodę płatności.

## Przegląd interfejsu

| Element    | Treść                                                             |
| ---- | -------------------------------------------------------------- |
| Metoda   | `POST`                                                         |
| URL   | `https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/` |
| Uwierzytelnianie   | Płatności hostowanego przekierowania mogą być anonimowe; inne metody wymagają sesji logowania lub Account Token                            |
| Body | JSON, nieopłacone zamówienia muszą podać `pay_way`                                       |

## Granice płatności anonimowej

Dostęp anonimowy jest przeznaczony dla scenariusza, w którym po otwarciu skopiowanego linku do płatności sesja logowania została utracona, nie wymaga ani nie powinien zawierać długoterminowego Account Token. Wywołania anonimowe:

- zezwalają wyłącznie na skonfigurowane po stronie serwera metody płatności hostowanego przekierowania;
- zawsze używają strony płatności dla komputerów stacjonarnych;
- nie mogą odebrać zamówień o zerowej cenie;
- podlegają ograniczeniom częstotliwości według IP i pojedynczego zamówienia;
- zwracają minimalną projekcję zamówienia, bez konta, Application ani wewnętrznych metadata.

Uwierzytelniony wywołujący musi być właścicielem zamówienia lub superadministratorem. Metody wymagające kontekstu użytkownika, takie jak X402 i wymiana nagród, nie mogą być wywoływane anonimowo.

## Przykład żądania

```shell
export ORDER_ID='ID Twojego zamówienia Pending'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"Stripe"}'
```

Metody płatności wymagające uwierzytelnienia:

```shell
export PLATFORM_TOKEN='Twój token konta'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"X402"}'
```

`pay_way` używa rzeczywistych wartości obsługiwanych przez model zamówienia, na przykład `WechatPay`, `AliPay`, `Stripe`, `Card`, `Airwallex`, `X402`, `PayPal`, `AppleIAP`, `Reward`, `BankTransfer`. Nie każda wartość jest dostępna dla żądań anonimowych lub na każdej stronie.

## Opis odpowiedzi

Pomyślna odpowiedź to zaktualizowany obiekt zamówienia, który zazwyczaj udostępnia punkt wejścia do następnego kroku za pośrednictwem `pay_url`; różne metody płatności mogą również zwracać w kontrolowanych polach informacje wymagane przez klienta do kontynuowania płatności. Odpowiedzi anonimowe używają minimalnej białej listy pól, uwierzytelniony właściciel otrzymuje pełne szczegóły.

Nie polegaj na starych nazwach pól, takich jak `payment_url`, `qr_code_url` lub `payment_method`; bieżący kontrakt Order używa `pay_url` i `pay_way`.

## Przelew bankowy

Zalogowane konta indywidualne i firmowe mogą używać `BankTransfer`, bez konieczności weryfikacji firmowej. Zarówno krajowe przelewy w RMB, jak i międzynarodowe przelewy w USD wymagają, aby kwota zamówienia wynosiła co najmniej 300 USD; należna kwota w RMB jest określana przez kwotę wyświetlaną w momencie płatności.

Przed płatnością można użyć `GET /api/v1/orders/{order_id}/payment-options/`, aby sprawdzić dostępne dla bieżącego zamówienia trasy przelewu i progi kwotowe. Przelew bankowy musi zostać zainicjowany po zalogowaniu przez właściciela zamówienia i podlega ograniczeniom konfiguracji kanału odbiorcy oraz zakresu zastosowania pakietu; żądania anonimowe nie mogą z niego korzystać.

## Zakupy w aplikacji iOS

Zalogowany właściciel zamówienia może przekazać `pay_way: "AppleIAP"`. To żądanie aktualizuje oczekujące na płatność zamówienie zgodnie z `metadata.apple_price` wybranego pakietu i usuwa zniżkę, nie powoduje obciążenia, nie przyznaje punktów ani nie zwraca linku do płatności. Stare zamówienie oczekujące na płatność powinno najpierw ukończyć ten krok, a następnie zainicjować natywną płatność Apple. Obsługiwany jest tylko jeden pakiet Usage ze skonfigurowanym produktem Apple i ceną; nieobsługiwane pakiety lub zamówienia zbiorcze zwracają `400`.

Po natywnej płatności Apple należy przesłać `transaction_id` przez `/api/v1/orders/{id}/apple-verify/`, aby ukończyć weryfikację po stronie serwera i przyznanie punktów. Liczba punktów pochodzi z pakietu; kwota używa niezależnej, wstępnie ustawionej ceny Apple w USD, bez nakładania zniżek członkowskich ani dopłat strony, a kwota obciążenia w lokalnej walucie w innych regionach jest określana przez stronę potwierdzenia Apple.

## Błędy i ponawianie

- Zamówienie nie jest `Pending`: zwraca `400`; nie twórz ponownie sesji płatności.
- Nie podano `pay_way`: zamówienia o wartości innej niż zero zwracają `400`.
- Wywołanie anonimowe używa niedozwolonej metody lub zamówienia o zerowej cenie: zwraca `403`, po zalogowaniu właściciel powinien ponowić próbę.
- Uwierzytelniony użytkownik nie jest właścicielem zamówienia: zwraca `403`.
- Kanał płatności zawiódł: nie przesyłaj ponownie bez zastanowienia; najpierw sprawdź szczegóły zamówienia, potwierdź, że nadal jest `Pending`, a następnie ponów próbę.
