[Jan](https://jan.ai/) to otwartoźródłowy klient AI na komputery stacjonarne, stawiający na działanie offline, który może zarówno uruchamiać modele lokalnie, jak i łączyć się z endpointami kompatybilnymi z OpenAI przez **Remote Engine**. W tym artykule opisano, jak połączyć się z Ace Data Cloud.

## Proces aplikowania

Aby połączyć Ace Data Cloud w Jan, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), uzyskaj swój API Token i zachowaj go na później.

![Uzyskiwanie Ace Data Cloud API Key](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i zalogowania się; po zalogowaniu i rejestracji automatycznie powrócisz na bieżącą stronę.

Przy pierwszym aplikowaniu otrzymasz darmowy limit, który pozwala bezpłatnie wypróbować usługi modelowe Ace Data Cloud.

## Pobieranie Jan

Przejdź na [oficjalną stronę Jan](https://jan.ai/) i pobierz wersję odpowiednią dla swojej platformy (Windows, macOS, Linux). W przypadku urządzeń Apple Silicon pobierz pakiet arm64, aby uzyskać najlepszą wydajność.

## Konfiguracja Ace Data Cloud

Jan dzieli modele na dwie kategorie: **Local Engine** (działanie lokalne) oraz **Remote Engine** (API stron trzecich). Ace Data Cloud korzysta z protokołu kompatybilnego z OpenAI i jest podłączane jako Remote Engine.

Otwórz Jan, przejdź do **Settings → Model Providers**, znajdź kartę **OpenAI** i edytuj ją:

| Pole       | Wartość                              | Opis                       |
| -------- | ------------------------------ | ------------------------ |
| API Key  | Twój Ace Data Cloud Token        | Token skopiowany z konsoli             |
| Base URL | `https://api.acedata.cloud/v1` | **Musi kończyć się na `/v1`, bez ukośnika na końcu** |

> To, że Base URL musi kończyć się na `/v1`, jest wyraźną konwencją w oficjalnej dokumentacji Jan. Jeśli nie chcesz nadpisywać oryginalnej konfiguracji OpenAI, możesz użyć „+ Add Provider”, aby utworzyć nowy Provider typu `openai-compatible` i wpisać tę samą zawartość.

![Ekran konfiguracji dodawania AceDataCloud Provider w Jan](https://cdn.acedata.cloud/26017d28afa1.png)

Po zapisaniu niestandardowego Provider Jan najpierw spróbuje wywołać `{Base URL}/models`, aby uzyskać listę modeli. Jeśli bieżąca wersja lub endpoint nie zwróci dostępnej listy, kliknij **+ Add Model** na dole tej samej strony edycji, aby ręcznie wpisać ID modelu. Po dodaniu model pojawi się na liście rozwijanej w lewym górnym rogu i będzie oznaczony ikoną „Cloud”, aby odróżnić go od modelu zdalnego / lokalnego.

![Interfejs zarządzania modelami Provider w Jan](https://cdn.acedata.cloud/ae485550946c.png)

> `MODEL_ID` jest symbolem zastępczym; przejdź do [katalogu modeli](https://platform.acedata.cloud/models), aby sprawdzić i zastąpić go nazwą docelowego modelu; przy dokładnej weryfikacji należy kierować się wartością `id` w odpowiedzi z `/v1/models`. Ta wartość to nazwa modelu używana przez parametr API `model`, a nie UUID usługi ani API.

## Wybór modelu

[Katalog modeli](https://platform.acedata.cloud/models) jest stale aktualizowany. W pierwszej kolejności użyj listy modeli automatycznie wczytanej przez klienta; gdy wymagane jest ręczne wpisanie, najpierw wyślij żądanie `GET https://api.acedata.cloud/v1/models`, skopiuj wartość `id` docelowego modelu z tablicy `data` w odpowiedzi, a następnie wybierz zgodnie z obsługiwanym przez klienta kontekstem, obrazami i możliwościami wywoływania narzędzi.

## Weryfikacja połączenia

Jeśli nie masz pewności, czy problem dotyczy Jan, czy sieci, możesz najpierw bezpośrednio zweryfikować endpoint za pomocą curl (zastąp `{token}` swoim Token):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

Zwrócenie obiektu `chat.completion` kompatybilnego z OpenAI oznacza, że Token i endpoint są gotowe; jeśli zwrócony zostanie `HTTP 403 used_up`, oznacza to, że Token jest prawidłowy, ale saldo jest niewystarczające — wystarczy doładować środki w [konsoli](https://platform.acedata.cloud/console/applications).

## Zaawansowane: połączenie lokalne + chmurowe

Jan ma wbudowany lokalny serwer API kompatybilny z OpenAI, który można włączyć (Settings → Local API Server). Po włączeniu nasłuchuje on pod adresem `http://localhost:1337/v1/chat/completions` i uruchamia pobrane przez Ciebie modele lokalne. Dzięki temu w frameworkach takich jak LangChain / LlamaIndex można skierować Base URL lokalnie do bezpłatnego debugowania, a w przypadku złożonych zadań przełączyć się na zdalne modele Ace Data Cloud. Podczas przełączania modeli kontekst rozmowy nie zostanie utracony.

## Często zadawane pytania

### Komunikat Connection error lub 404

Zwykle oznacza to, że w Base URL brakuje `/v1`. Zmień na `https://api.acedata.cloud/v1` (musi kończyć się na `/v1` i nie może być zapisane jako `.../openai/v1`).

### Komunikat 401 Unauthorized

Upewnij się, że w API Key wklejony został Token Ace Data Cloud (bez prefiksu `Bearer` i bez dodatkowych spacji) oraz że saldo powiązanej aplikacji jest wystarczające.

### Model zdalny nie pojawia się na liście rozwijanej

Najpierw kliknij przycisk odświeżania modeli, aby wywołać `/v1/models`; jeśli automatyczne wykrywanie nie powiedzie się, ręcznie użyj **+ Add Model** i dodaj bez zmian wartość `id` modelu z katalogu.

### Czy można przesłać obraz, aby model go przeanalizował

Tak, ale należy wybrać z bieżącego katalogu modeli model, który wyraźnie obsługuje wejście wizualne.
