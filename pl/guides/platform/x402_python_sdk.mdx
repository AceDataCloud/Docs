Python SDK nadaje się do usług backendowych, zadań danych, zautomatyzowanych Agentów i skryptów wsadowych. `acedatacloud` odpowiada za wywołania API, a `acedatacloud-x402` za podpisywanie nagłówka żądania `PAYMENT-SIGNATURE`.

Adresy kodu źródłowego i pakietów:

- Repozytorium SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Repozytorium X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- PyPI SDK: [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)
- PyPI X402 Client: [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)

## Instalacja zależności

```bash
pip install acedatacloud acedatacloud-x402
```

Aby używać `upto`, należy również jednorazowo wywołać CLI zatwierdzania Permit2, które zależy od `web3`:

```bash
pip install 'acedatacloud-x402[cli]'
```

Wynik instalacji i sprawdzenia importów w czystym Python venv:

```text
acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
approve-permit2  One-time ERC-20 approve(Permit2, amount) needed before signing upto payments.
```

Opis wyników:

- Zarówno `acedatacloud`, jak i `acedatacloud-x402` można instalować i importować z PyPI.
- `pip install 'acedatacloud-x402[cli]'` dołącza CLI `approve-permit2`, używane do wstępnego autoryzowania `upto`.

## Przykład Base

Poniższy przykład nie wymaga API Token. Klucz prywatny portfela jest podpisywany wyłącznie lokalnie i nie zostanie wysłany do Ace Data Cloud.

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)

print(res["choices"][0]["message"]["content"])
```

Python SDK obecnie zwraca `dict`, dlatego przykład używa `res["choices"][0]["message"]["content"]`. Nie zakładaj bezpośrednio, że z pewnością ma właściwość `.choices`.

## Przykład Solana

Solana używa secret key zakodowanego w base58:

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import SolanaKeypairSigner, create_x402_payment_handler

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="solana",
        solana_signer=SolanaKeypairSigner.from_base58(os.environ["SOLANA_SECRET_KEY"]),
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

Ścieżka Solana tworzy i przesyła transakcję SPL USDC `TransferChecked`, a następnie umieszcza podpis transakcji w envelope `PAYMENT-SIGNATURE`.

Płatna ponowna próba Solana zwróciła już HTTP 200 i `ADC_SOLANA_E2E_OK` w produkcyjnym API. To publiczne zapytanie RPC napotkało ograniczenie szybkości, więc podpis on-chain nie został stabilnie potwierdzony; jeśli potrzebne jest uzgodnienie, użyj własnego Solana RPC do sprawdzenia tej transakcji.

## Klient Async

Ten sam payment handler może być używany z `AsyncAceDataCloud`:

```python
import os

from acedatacloud import AsyncAceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AsyncAceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = await client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

## Używanie rozliczania po wykonaniu `upto`

Rzeczywisty koszt API, takich jak uzupełnienia czatu i wywołania modeli, może być znany dopiero po zakończeniu odpowiedzi. W takim przypadku API może jednocześnie zwracać `exact` i `upto`. Aby preferować `upto`:

```python
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
        prefer_scheme="upto",
    )
)
```

Wynik działania programu Base `upto`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
settlement tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
settled value 3 atomic USDC
```

Potwierdzenie on-chain:

```text
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
transfer value 3 atomic USDC
```

Opis wyników:

- `content ADC_BASE_UPTO_OK` wskazuje, że żądanie rzeczywiście dotarło do API modelu.
- `settled value 3 atomic USDC` wskazuje, że `upto` rozlicza się według rzeczywistego użycia, zamiast pobierać pełny limit.
- `settlement tx` można otworzyć w BaseScan; podczas uzgadniania zachowaj tx hash, payer, completion id i podsumowanie żądania.

`upto` używa autoryzacji Permit2 dla limitu, a rzeczywista kwota rozliczenia nie może przekroczyć tego limitu. Przed pierwszym użyciem należy jednokrotnie wykonać `approve(Permit2, amount)` dla USDC w docelowym łańcuchu.

Sposób CLI:

```bash
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Sposób programowy:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Ten helper jest idempotentny. Jeśli allowance jest już wystarczający, zwróci `{"skipped": true}` i nie wyśle ponownie transakcji on-chain.

## Podpisywanie niskopoziomowe

Jeśli nie używasz SDK, możesz także bezpośrednio wywołać funkcję podpisywania niskiego poziomu:

```python
import base64
import json

from acedatacloud_x402 import EVMAccountSigner, sign_evm_payment

envelope = sign_evm_payment(requirement, EVMAccountSigner.from_private_key("0x..."))
x_payment = base64.b64encode(json.dumps(envelope, separators=(",", ":")).encode()).decode()
```

Funkcje niskiego poziomu nadają się do testów, warstw proxy, integracji z bramami lub nieoficjalnych SDK. W zwykłym kodzie biznesowym w pierwszej kolejności używaj `create_x402_payment_handler`.
