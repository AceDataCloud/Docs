Dla każdej Application tworzona jest niezależna instancja kontenera Hermes. Domyślnie używany jest obraz bazowy o stałej wersji wydania, z zachowaniem natywnych funkcji; platforma zapewnia zakup, odnowienie, trwałą pamięć masową i zarządzanie wdrożeniem.

## Tworzenie i zakup

1. Otwórz [Wdrożenie Hermes](https://platform.acedata.cloud/services/hermes) i utwórz Application.
2. Na stronie zakupu wybierz pakiet czasowy i dokonaj płatności.
3. Wróć na stronę konfiguracji, możesz wybrać platformowy model czatu z listy rozwijanej i sprawdzić aktualną cenę modelu. Platforma utworzy niezależne poświadczenia API dla tej instancji; możesz również wyłączyć dostęp platformy i samodzielnie skonfigurować je w natywnej konsoli.
4. Wybierz automatyczne generowanie poświadczeń dostępu albo ustaw własne silne hasło/Token, po potwierdzeniu rozpocznie się wdrażanie. Poświadczenia dostępu i poświadczenia API modelu są od siebie niezależne.
5. Gdy instancja będzie gotowa, pobierz adres dostępu i poświadczenia logowania ze strony zarządzania.
6. Zaloguj się do natywnej konsoli, aby skonfigurować kanały. Jeżeli podczas wdrażania wyłączono dostęp do modeli platformy, musisz również samodzielnie skonfigurować dostawcę modelu i poświadczenia, aby czat mógł działać.

Opłata za wdrożenie jest naliczana według czasu trwania pakietu, a konkretna cena w USD i czas trwania są podane na stronie zakupu. Koszty wywołań modelu są naliczane osobno; zakup czasu wdrożenia nie daje bezpłatnego limitu modelu. Po włączeniu dostępu platformy dedykowane poświadczenia API udostępniają wyłącznie interfejs czatu odpowiadający wybranemu modelowi, a wywołania są dodatkowo rozliczane z salda platformy. Każda Application jest kupowana, odnawiana i zarządzana osobno.

## Hasła, poświadczenia i późniejsza konfiguracja

Poświadczenia dostępu są ustawiane przed pierwszym uruchomieniem. Automatycznie generowana metoda używa losowych poświadczeń, niestandardowe hasło musi mieć co najmniej 16 znaków, a OpenClaw Token co najmniej 32 znaki. Szkic nie zapisuje haseł; po przejściu na inną stronę może być konieczne ich ponowne wprowadzenie. Po wdrożeniu tylko właściciel Application i administratorzy mogą wyświetlać poświadczenia dostępu.

Poświadczenia API modelu każdej instancji nie są współdzielone, ich okres ważności jest przedłużany wraz z odnowieniem wdrożenia i są unieważniane po usunięciu instancji. Jeżeli podczas pierwszego wdrożenia nie połączono modelu platformy, możesz wybrać model platformy na stronie konfiguracji tej Application i wdrożyć ponownie; platforma zaktualizuje domyślny model, zachowując sesje i inne natywne ustawienia. Następnie zmodyfikuj modele i kanały w natywnej konsoli; jeśli wybierzesz model innej usługi, najpierw dostosuj autoryzację odpowiedniego interfejsu w zarządzaniu poświadczeniami platformy albo użyj odpowiednich poświadczeń. Zwykłe ponowne wdrożenie nie nadpisuje natywnych ustawień. Środowiska wdrożeniowe, które nie przeszły weryfikacji publikacji, tymczasowo odrzucają nowe wdrożenia, skontaktuj się z pomocą techniczną.

## Wersje i dane

Strona konfiguracji wyświetla aktualnie opublikowaną wersję obrazu. Nowe instancje używają aktualnie opublikowanej wersji usługi; istniejące instancje nie będą automatycznie zastępowane wraz z aktualizacjami katalogu. Ponowne wdrożenie zastosuje aktualną wersję usługi, najpierw wykonaj kopię zapasową i potwierdź wymagania dotyczące aktualizacji używanej wersji.

Każda instancja domyślnie zapewnia 1 CPU, limit pamięci 2 GiB oraz 10 GiB trwałej pamięci masowej. Ponowne uruchomienie zachowuje dane instancji. Aktywne usunięcie wdrożenia lub odzyskanie po wygaśnięciu usunie pamięć masową, wcześniej wyeksportuj dane, które chcesz zachować.

## Odnowienie i wygaśnięcie

Odnów na stronie zakupu bieżącej Application, okres ważności zostanie przedłużony zgodnie z obowiązującymi na platformie zasadami dotyczącymi czasu trwania. Po wygaśnięciu punkt dostępu zostaje wstrzymany, odnowienie w okresie karencji przywraca dostęp; po przekroczeniu okresu karencji instancja i dane zostaną odzyskane. Obowiązują czas wygaśnięcia, stan rozliczeń i komunikat o usunięciu na stronie zarządzania.

## Logowanie do interfejsu zarządzania

Na stronie zarządzania wdrożeniem skopiuj adres Dashboard, nazwę użytkownika `admin` i hasło, a następnie otwórz go i zaloguj się. Informacje logowania są udostępniane wyłącznie właścicielowi tej Application i administratorom platformy. Modele, umiejętności i kanały są konfigurowane w natywnym interfejsie Hermes.

## Często zadawane pytania

- **Dlaczego nowa instancja nadal nie może odpowiadać?** Zakończenie wdrożenia oznacza jedynie, że kontener jest gotowy. Jeżeli podczas wdrażania wyłączono dostęp do modeli platformy, należy wybrać model platformy na stronie konfiguracji i wdrożyć ponownie albo samodzielnie skonfigurować model i poświadczenia w natywnym interfejsie.
- **Czy dodatkowe wtyczki lub fallback modelu są preinstalowane?** Domyślnie nie są dodawane, skonfiguruj je w razie potrzeby w natywnym interfejsie.
- **Jak zaktualizować istniejącą instancję?** Pierwotna Application i zamówienie zostają zachowane, podczas ponownego wdrożenia używana jest aktualna wersja usługi; przed aktualizacją najpierw wykonaj kopię zapasową danych i sprawdź zgodność wersji.
- **Co zrobić w przypadku niepowodzenia uruchomienia?** Najpierw sprawdź dzienniki wdrożenia i zdarzenia, a po potwierdzeniu gotowości instancji skonfiguruj model. Nie ujawniaj hasła instancji ani kluczy w publicznych komentarzach lub zrzutach ekranu.
