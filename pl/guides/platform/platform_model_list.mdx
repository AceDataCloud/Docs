Zwraca publiczny katalog modeli platformy, a odpowiedź przyjmuje strukturę w stylu OpenAI `{ "object": "list", "data": [...] }`. Katalog służy do wyboru modeli i odkrywania możliwości oraz nie oznacza, że bieżące konto koniecznie złożyło wniosek o odpowiednią usługę.

## Przegląd interfejsu

| Pozycja   | Treść                                              |
| --- | ----------------------------------------------- |
| Metoda  | `GET`                                           |
| URL | `https://platform.acedata.cloud/api/v1/models/` |
| Uwierzytelnianie  | Publiczne, token konta nie jest wymagany                                       |
| Paginacja  | Brak paginacji, wszystkie pasujące pozycje znajdują się w `data`                              |

## Parametry zapytania

| Parametr             | Typ      | Wymagany  | Opis                                      |
| -------------- | ------- | --- | --------------------------------------- |
| `owned_by`     | string  | Nie   | Dokładne filtrowanie według identyfikatora dostawcy modelu w katalogu                        |
| `type`         | string  | Nie   | Dokładne filtrowanie według typu modelu, na przykład `chat`                     |
| `capability`   | string  | Nie   | Zwraca wyłącznie modele, których `capabilities` zawiera tę możliwość, na przykład `vision` |
| `with_pricing` | boolean | Nie   | Dołącza publiczne informacje o cenach, gdy ustawiono `1`, `true` lub `yes`            |

`service_id`, `tag`, `limit`, `offset` i `ordering` nie są obecnie obsługiwane; przekazanie ich nie spowoduje odpowiedniego filtrowania ani paginacji.

## Przykłady żądań

```shell
# Wszystkie publiczne modele
curl 'https://platform.acedata.cloud/api/v1/models/' \
  -H 'Accept: application/json'

# Modele chat obsługujące wizję, wraz z cenami
curl --get 'https://platform.acedata.cloud/api/v1/models/' \
  --data-urlencode 'type=chat' \
  --data-urlencode 'capability=vision' \
  --data-urlencode 'with_pricing=true' \
  -H 'Accept: application/json'
```

```python
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/models/",
    params={"type": "chat", "capability": "vision", "with_pricing": "true"},
    timeout=10,
)
response.raise_for_status()
payload = response.json()
for model in payload["data"]:
    print(model["id"], model["capabilities"], model.get("pricing"))
```

## Rzeczywista struktura odpowiedzi

```json
{
  "object": "list",
  "data": [
    {
      "id": "example-model",
      "label": "Example Model",
      "owned_by": "example",
      "service_prefix": "acedatacloud-example",
      "group_label": "Example",
      "type": "chat",
      "capabilities": [
        "vision"
      ],
      "object": "model",
      "pricing": {
        "currency": "USD",
        "unit": "token",
        "input_usd": 1e-06,
        "output_usd": 2e-06,
        "official_input_usd": 1e-06,
        "official_output_usd": 2e-06,
        "savings_pct": 0,
        "credit_usd_rate": 0.1
      }
    }
  ],
  "credit_usd_rate": 0.1
}
```

`pricing` oraz `credit_usd_rate` na najwyższym poziomie pojawiają się wyłącznie przy `with_pricing=true`; nie każdy model ma wyliczalne `pricing`. Obiekt modelu opiera się na publicznych polach z `config/models.json`, a klient powinien ignorować nowo dodane pola.

> Pola cenowe są danymi prezentowanymi w katalogu. Rzeczywiste wywołania biznesowe nadal podlegają zasadom rozliczania odpowiedniego API/Service oraz końcowym zapisom użycia.
