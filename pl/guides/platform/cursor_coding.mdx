Cursor obecnie oferuje ustawienia OpenAI API Key oraz **Override OpenAI Base URL**, co pozwala na połączenie z usługami kompatybilnymi z OpenAI. Ta funkcjonalność istnieje, ale różne wersje różnie obsługują `/chat/completions`, `/responses`, listy modeli oraz tryby Agent/Composer.

Zakres kompatybilności różnych wersji Cursor, systemów operacyjnych i trybów żądań może się różnić. Proszę wykonać rzeczywiste sprawdzenie trybu zgodnie z konfiguracją na tej stronie, nie opierając się na sukcesie pojedynczej rozmowy, aby wnioskować, że wszystkie funkcje są dostępne.

## Co obecnie gwarantuje Cursor w BYOK

Zgodnie z [oficjalną dokumentacją Cursor Bring your own API key](https://cursor.com/help/models-and-usage/api-keys):

- Wspiera poświadczenia OpenAI, Anthropic, Google, Azure OpenAI i AWS Bedrock;
- Niestandardowy API Key jest używany tylko dla modeli czatu, Tab completion nadal korzysta z wbudowanych modeli Cursor;
- API Key nie jest przechowywany na serwerze Cursor, ale przy każdym żądaniu klucz jest wysyłany do backendu Cursor w celu ostatecznego budowania promptu;
- Przy użyciu własnego klucza, polityka Zero Data Retention Cursor nie ma zastosowania, przetwarzanie danych podlega polityce wybranego dostawcy.

## Konfiguracja

1. Otwórz Ustawienia Cursor → Modele.
2. W polu OpenAI API Key wprowadź swój token API Ace Data Cloud.
3. Włącz **Override OpenAI Base URL**, wprowadzając `https://api.acedata.cloud/v1`.
4. Wybierz lub dodaj dokładny identyfikator modelu zgodny z aktualnym protokołem Cursor.
5. Najpierw wyślij `Reply only OK`, a następnie przetestuj osobno tryby Ask/Edit/Agent, które faktycznie używasz.

## Obecne ograniczenia

- Niestandardowy API Key jest używany tylko dla modeli czatu, Tab completion nadal korzysta z wbudowanych modeli Cursor.
- Cursor nadal może na serwerze zakończyć ostateczne budowanie promptu; proszę ocenić ścieżkę danych w kontekście oficjalnych informacji o prywatności.
- Override Base URL może pokrywać tylko część żądań lub z powodu zmian wersji przełączać się między Chat Completions/Responses.
- Nie należy twierdzić, że Agent, Auto, Composer lub zadania w tle są połączone, opierając się tylko na sukcesie jednego żądania czatu.

## Pełne sprawdzenie kompatybilności

Aby długoterminowo korzystać w produkcyjnym przepływie pracy, należy jednocześnie wykonać następujące kontrole:

1. Ustalona wersja Cursor i system operacyjny;
2. Wykonanie rzeczywistego testu smoke dla tej wersji klienta i zapisanie ostatecznego protokołu żądania oraz ścieżki;
3. Sukces żądania Chat Completions dla dokładnego modelu;
4. Wywołania narzędzi i żądania Agenta rzeczywiście przechodzą przez docelowy endpoint;
5. Możliwość weryfikacji zużycia i opłat;
6. Wyraźne zapisanie, czy żądanie przeszło przez serwer Cursor oraz odpowiadające ograniczenia prywatności.

Po aktualizacji klienta należy ponownie wykonać te kontrole, aby upewnić się, że protokół żądania, wywołania narzędzi i ścieżka danych nie uległy zmianie.
