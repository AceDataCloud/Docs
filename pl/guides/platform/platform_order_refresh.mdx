---
title: "Odświeżenie statusu zamówienia na platformie AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Aktywnie zapytaj o najnowszy status metody płatności odpowiadającej zamówieniu i zsynchronizuj go z platformą. To żądanie może uzyskać dostęp do usługi płatności i zmienić status zamówienia, używaj go tylko w przypadku opóźnienia callbacku lub gdy wymagane jest natychmiastowe potwierdzenie.

## Przygotowanie

- Użyj [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Pobierz własny identyfikator zamówienia z [listy zamówień](https://platform.acedata.cloud/documents/platform-order-list).

```shell
export PLATFORM_TOKEN='twój token konta'
export ORDER_ID='twój identyfikator zamówienia'
```

## Przegląd interfejsu

| Pozycja    | Treść                                                                 |
| ---- | ------------------------------------------------------------------ |
| Metoda   | `POST`                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/refresh/` |
| Autoryzacja   | Właściciel zamówienia lub superadministrator                                                        |
| Body | Zwykle puste; w scenariuszu callbacku PayPal może być wymagane `payer_id` / `PayerID`                         |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/refresh/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Po pomyślnym wykonaniu zwracany jest kompletny obiekt Order po odświeżeniu. Użyj `state`, aby określić wynik, oraz `finished_at` jako czasu ukończenia; bieżący model nie ma pola `paid_at`. Wartości statusu obejmują `Pending`, `Paid`, `Finished`, `Expired`, `Failed`, `Refunded`.

Termin płatności zmieni tylko zamówienia nadal znajdujące się w stanie `Pending` na `Expired`. Zamówienia `Refunded`, za które zwrócono środki, pozostają w stanie zwróconym po odświeżeniu lub otrzymaniu opóźnionego callbacku płatności.

## Zalecenia dotyczące ponawiania

- W przypadku normalnych płatności w pierwszej kolejności polegaj na callbacku platformy; aktywne refresh wykonuj tylko wtedy, gdy status przez długi czas się nie aktualizuje.
- Nie stosuj stałego, częstego odpytywania. Zalecany jest wykładniczy backoff oraz zatrzymanie po osiągnięciu wyraźnego stanu końcowego.
- `401` oznacza, że token jest nieprawidłowy; `403` oznacza, że użytkownik nie jest właścicielem zamówienia; `404` oznacza, że zamówienie nie istnieje.
- Gdy zapytanie do usługi płatności nie powiedzie się, zachowaj identyfikator zamówienia i trace ID, a następnie spróbuj ponownie później; nie twórz zduplikowanych zamówień jako zamiennika potwierdzenia statusu.
