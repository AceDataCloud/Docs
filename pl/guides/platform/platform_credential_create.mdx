Utwórz biznesowe poświadczenia API dla Application. Odpowiedź na utworzenie może zawierać Token umożliwiający bezpośrednie wywoływanie `https://api.acedata.cloud/**` lub nazwę użytkownika/hasło dla poświadczeń typu Proxy; należy traktować je jako tajne.

## Przygotowanie

1. Utwórz [Account Token](https://platform.acedata.cloud/documents/platform-token).
2. Pobierz należący do siebie `application_id` z [listy Application](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='twój token konta'
export APPLICATION_ID='twój Application ID'
```

## Przegląd interfejsu

| Element    | Treść                                                |
| ---------- | --------------------------------------------------- |
| Metoda     | `POST`                                              |
| URL        | `https://platform.acedata.cloud/api/v1/credentials/` |
| Uwierzytelnianie | Account Token, token OAuth wymaga `credentials:write` |
| Body       | JSON                                                |

## Treść żądania

| Pole                  | Typ              | Wymagane | Opis                                                        |
| --------------------- | ---------------- | -------- | ----------------------------------------------------------- |
| `application_id`      | UUID             | Tak      | Docelowe Application                                        |
| `name`                | string           | Nie      | Nazwa wyświetlana poświadczenia                             |
| `limited_amount`      | number / null    | Nie      | Limit użycia pojedynczego poświadczenia; `null` oznacza brak niezależnego limitu |
| `expired_at`          | datetime / null  | Nie      | Czas wygaśnięcia ISO 8601                                  |
| `allowed_api_ids`     | UUID[] / null    | Nie      | Zezwalaj tylko na wywoływanie tych API; pusta tablica zostanie znormalizowana jako brak ograniczeń |
| `host`                | string           | Nie      | Informacje hosta poświadczenia                              |
| `for_user_id`         | string           | Nie      | Używane podczas wystawiania autoryzowanych poświadczeń, gdy właścicielem Application jest inny użytkownik |
| `tags` / `metadata`   | array / object   | Nie      | Niestandardowe dane rozszerzeń                              |

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/credentials/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"name\":\"production\",\"limited_amount\":50}"
```

## Opis odpowiedzi

Pomyślna odpowiedź zwraca `201` oraz obiekt Credential:

- Usługi typu API/Agent zwykle zwracają `type=Token` oraz `token`;
- Usługi typu Proxy zwykle zwracają `type=Identity` oraz `username` / `password`, a jedno Proxy Application zezwala tylko na jedno poświadczenie;
- `id`, `user_id`, `creator_id`, `used_amount` oraz pola czasu są generowane przez serwer.

Obecne interfejsy listy i szczegółów również zwracają tekst jawny poświadczeń, ale klient nie powinien polegać na tym historycznym zachowaniu. Zapisz je natychmiast po utworzeniu, unikaj zapisywania odpowiedzi w logach; przyszłe interfejsy mogą zostać zmienione na zwracanie zamaskowanych danych.

## Obsługa błędów

- `400`: Błędny format pola, nieznane `allowed_api_ids`, Proxy Application ma już poświadczenie lub inne ograniczenia tworzenia.
- `401`: Account Token jest nieprawidłowy.
- `403/404`: Brak uprawnień dostępu do docelowego Application albo Application/użytkownik autoryzowany nie istnieje.
