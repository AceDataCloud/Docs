---
title: "Usuwanie poświadczenia API platformy AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Trwale usuń jedno poświadczenie API. Po usunięciu **nie można go natychmiast odzyskać**, a wszystkie interfejsy biznesowe używające tego Tokena natychmiast otrzymają `401`.

> ℹ️ Ten interfejs należy do **API zarządzania platformą AceDataCloud**, ze wspólnym prefiksem `https://platform.acedata.cloud/api/v1/`.

## Przegląd interfejsu

| Pozycja   | Treść                                                                  |
| --- | ------------------------------------------------------------------- |
| Metoda  | `DELETE`                                                            |
| URL | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}` |
| Uwierzytelnianie  | ✅ Wymagany token konta                                                            |

`/credentials/{id}` oraz `/credentials/{id}/` są obecnie dostępne; przykłady jednolicie używają formy bez końcowego ukośnika.

## Opis uwierzytelniania (jak uzyskać token konta)

Nagłówek żądania:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Sposób uzyskania znajduje się w sekcji [Zarządzanie tokenem konta platformy AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

## Parametry ścieżki

| Parametr              | Typ   | Wymagany  | Opis        |
| --------------- | ---- | --- | --------- |
| `credential_id` | UUID | ✅   | ID poświadczenia do usunięcia |

## Przykłady żądań

### cURL

```shell
curl -X DELETE 'https://platform.acedata.cloud/api/v1/credentials/df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

cred_id = "df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6"
resp = requests.delete(
    f"https://platform.acedata.cloud/api/v1/credentials/{cred_id}",
    headers={"authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    timeout=10,
)
assert resp.status_code == 204, resp.text
print("✅ 已删除")
```

### Node.js

```javascript
const credId = 'df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6'
const r = await fetch(`https://platform.acedata.cloud/api/v1/credentials/${credId}`, {
  method: 'DELETE',
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log('status:', r.status) // 204
```

## Odpowiedź

- **Sukces**: `HTTP 204 No Content`, **brak treści odpowiedzi**.
- **Niepowodzenie**: zwracany jest błędny JSON, patrz tabela poniżej.

## Obsługa błędów

| HTTP | code                | Znaczenie         |
| ---- | ------------------- | ---------- |
| 401  | `not_authenticated` | Brak tokena konta     |
| 403  | `permission_denied` | To poświadczenie nie należy do Ciebie    |
| 404  | `not_found`         | Poświadczenie nie istnieje lub zostało usunięte |

## Praktyczne wskazówki

- **Usunięcie jest nieodwracalne** — platforma nie przechowuje kopii Tokena. Jeśli jedynie podejrzewasz wyciek i nadal chcesz zachować dane monitoringu, powinieneś użyć [rotacji poświadczenia API platformy AceDataCloud](https://platform.acedata.cloud/documents/platform-credential-rotate) zamiast usuwania.
- **Usunięcie nie zwróci wykorzystanego przez to poświadczenie limitu**. Saldo Application jest odejmowane w czasie rzeczywistym zgodnie z wykorzystaniem, a usunięcie poświadczenia nie wpływa na stan salda.
- Po usunięciu możesz ponownie potwierdzić pozostałe poświadczenia według `application_id` poprzez [listę poświadczeń API](https://platform.acedata.cloud/documents/platform-credential-list).
- **Przed masowym czyszczeniem najpierw sprawdź wywołujących**: lista obecnie nie zawiera pola czasu ostatniego użycia; należy połączyć konfigurację wdrożenia i rekordy wywołań, aby potwierdzić, że poświadczenie nie jest już używane, a następnie usuwać je pojedynczo.
