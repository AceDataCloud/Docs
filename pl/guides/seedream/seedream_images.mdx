W tym artykule przedstawimy sposób integracji z API SeeDream Images Generation, które umożliwia generowanie oficjalnych obrazów SeeDream poprzez wprowadzanie niestandardowych parametrów.

## Proces uzyskiwania dostępu

Aby korzystać z API SeeDream Images Generation, najpierw przejdź do [panelu sterowania Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API (API Token), który będzie potrzebny w dalszych krokach.

![]()

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, gdzie będzie można się zarejestrować i zalogować. Po zakończeniu procesu automatycznie powrócisz na bieżącą stronę.

**Jeden token API wystarcza do korzystania ze wszystkich usług platformy. Nie ma potrzeby składania osobnych wniosków dla każdej usługi.** Przy pierwszym uzyskaniu dostępu otrzymasz bezpłatny limit środków, dzięki czemu możesz bezpłatnie przetestować usługę. Gdy limit się wyczerpie, możesz doładować uniwersalne saldo w [panelu sterowania](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [SeeDream Images Generation API →](https://platform.acedata.cloud/documents/seedream-images)

## Wybór modelu

| Model | Zastosowanie |
| ----------------------------------------------------------- | ------------------------------- |
| `doubao-seedream-5-5-261028` | Edycja wieloetapowa, generowanie przez tekst obrazów z przezroczystym tłem, edycja przezroczystych obrazów z wieloma obrazami referencyjnymi, rozdzielanie warstw i rozpoznawanie warstw tekstowych |
| `doubao-seedream-5-0-flash-260915` | Generowanie pojedynczych obrazów z niskim opóźnieniem, edycja z wieloma obrazami referencyjnymi, edycja przezroczystych obrazów i rozdzielanie warstw |
| `doubao-seedream-5-0-pro-260628` | Generowanie pojedynczych obrazów, precyzyjna edycja, edycja przezroczystych obrazów i rozdzielanie warstw |
| `doubao-seedream-5-0-lite-260128` | Pojedyncze obrazy, zestawy obrazów, przesyłanie strumieniowe i wyszukiwanie w Internecie |
| `doubao-seedream-4-5-251128` / `doubao-seedream-4-0-250828` | Starsze wersje generowania i edycji obrazów |

Modele 5.5 i 5.0 Flash korzystają z tego samego endpointu `POST /seedream/images`. Oba obsługują rozdzielczości `1K`, `1.5K`, `2K` oraz maksymalnie 10 obrazów referencyjnych. Zadania rozdzielania warstw w obu modelach przyjmują tylko jeden obraz i zwracają adres URL. W modelu 5.5 można ustawić `layer_decomposition_options: {"max_images": 12, "text_recognition": true}`. Można wygenerować maksymalnie 100 obrazów (łącznie z obrazem bazowym). Rozpoznawalne warstwy tekstowe zwracają tekst wiersz po wierszu oraz style w polu `data[].text_recognition`. Model 5.0 Flash zwraca maksymalnie 1 obraz bazowy i 16 warstw.

Model 5.5 obsługuje bezpośrednie generowanie przezroczystych plików PNG za pomocą `background: "transparent"`. Edycja przezroczystych obrazów w modelu 5.0 Flash wymaga obrazu referencyjnego z kanałem przezroczystości. Model 5.5 nalicza opłaty według poziomu rozdzielczości pomyślnie wygenerowanego obrazu, a także dodatkowo 0,13 Credits za każdy obraz wejściowy użyty jako referencja. Model 5.0 Flash pobiera 0,31 Credits za każdy pomyślnie wygenerowany obraz, a obrazy referencyjne są bezpłatne. Rozdzielanie warstw jest rozliczane na podstawie rzeczywistej liczby pomyślnie wygenerowanych obrazów, przy czym obraz bazowy również jest wliczany. Zobacz [cennik w czasie rzeczywistym](https://platform.acedata.cloud/services/seedream?tab=pricing).

## Podstawowe użytkowanie

Najpierw zapoznajmy się z podstawowym sposobem korzystania z usługi. Wystarczy wprowadzić polecenie `prompt`, określić działanie generowania `action` oraz rozmiar obrazu `size`, aby uzyskać przetworzony wynik. Na początek należy przekazać proste pole `action` o wartości `generate`, a następnie wprowadzić polecenie. Szczegóły przedstawiono poniżej:

<p><img src="https://cdn.acedata.cloud/seedream_request_body.png" width="500" className="m-auto" /></p>

Jak widać, skonfigurowaliśmy tutaj Request Headers, które obejmują:

- `accept`: określa format odpowiedzi, który chcemy otrzymać. W tym przypadku należy wpisać `application/json`, czyli format JSON.
- `authorization`: klucz używany do wywoływania API. Po uzyskaniu dostępu można go bezpośrednio wybrać z listy rozwijanej.

Dodatkowo skonfigurowaliśmy Request Body, które obejmuje:

- `prompt`: polecenie tekstowe.
- `model`: należy podać pełny identyfikator modelu z powyższej tabeli.
- `image`: wejściowy adres URL obrazu, ciąg znaków Base64 lub tablica. Modele 5.5, 5.0 Pro i 5.0 Flash obsługują maksymalnie 10 obrazów referencyjnych.
- `size`: poziom rozdzielczości lub `szerokośćxwysokość`. Modele 5.5, 5.0 Pro i 5.0 Flash obsługują `1K`, `1.5K` i `2K`. Model 5.0 Lite obsługuje `2K`, `3K` i `4K`.
- `sequential_image_generation`: zestaw obrazów: generuje grupę powiązanych ze sobą obrazów na podstawie wprowadzonych przez Ciebie treści. Parametr ten obsługują modele `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128` i `doubao-seedream-4-0-250828`. Domyślna wartość to `disabled`.
- `stream`: określa, czy włączyć tryb przesyłania strumieniowego. Parametr ten obsługują modele `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128` i `doubao-seedream-4-0-250828`. Domyślna wartość to `false`.
- `response_format`: określa format zwracanych wygenerowanych obrazów. Domyślna wartość to `url`. Obsługiwany jest również format `b64_json`.
- `watermark`: określa, czy na wygenerowanych obrazach ma być dodawany znak wodny. Domyślna wartość to `true`.
- `output_format`: format wyjściowy obrazu, `jpeg` lub `png`. Domyślnym formatem dla modelu 5.5 jest PNG, a dla modeli 5.0 Pro/Flash/Lite — JPEG.
- `tools`: konfiguruje narzędzia, z których model ma korzystać. Obecnie obsługiwane jest `web_search` (wyszukiwanie w Internecie). Funkcja ta jest dostępna wyłącznie w modelu Seedream 5.0 Lite.
- `optimize_prompt_options`: konfiguracja optymalizacji poleceń. Model 5.0 Pro obsługuje `standard`/`fast`; modele 5.5, 5.0 Flash, 5.0 Lite i 4.5 obsługują wyłącznie `standard`; model 4.0 obsługuje `standard`/`fast`.
- `background`: obsługuje wartości `transparent` i `opaque`. Model 5.5 obsługuje dodatkowo `auto`. Obrazy z przezroczystym tłem są generowane w formacie PNG.
- `layer_decomposition`: obsługiwane przez modele 5.5, 5.0 Pro i 5.0 Flash. Po ustawieniu wartości `true` należy przesłać jeden obraz w formacie PNG/JPEG. Można pominąć `prompt`, aby automatycznie rozdzielić warstwy, lub użyć języka naturalnego albo `<bbox>` do wskazania elementów. Parametr `size` obsługuje wartości `auto`/`1K`/`1.5K`/`2K`. Tego trybu nie można używać jednocześnie z generowaniem zestawów obrazów, przesyłaniem strumieniowym, wyszukiwaniem w Internecie ani parametrem `background`.
- `callback_url`: adres URL, na który mają być przesyłane wyniki za pomocą funkcji callback.
- `async`: określa, czy przetwarzanie ma odbywać się w trybie asynchronicznym. Po ustawieniu wartości `true` interfejs natychmiast zwraca `task_id`, bez konieczności podawania `callback_url`. Następnie można odpytywać endpoint `/seedream/tasks`, aby pobrać wyniki.


## Zadanie edycji obrazu

Jeśli chcesz edytować określony obraz, najpierw musisz przekazać link do obrazu, który ma zostać edytowany, za pomocą parametru `image`.

- model: przekaż pełny identyfikator modelu obsługującego edycję obrazów z powyższej tabeli.
- image: prześlij obraz lub obrazy, które mają zostać edytowane.

Przykład wypełnienia:

<p><img src="https://cdn.acedata.cloud/seedream_edit.png" width="500" className="m-auto" /></p>

Odpowiadający kod:

```python
import requests

url = "https://api.acedata.cloud/seedream/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedream-4-0-250828",
  "prompt": "Zachowaj niezmienioną pozę modelki oraz kształt płynącej, płynnej sukni. Zmień materiał ubrania ze srebrnego metalu na całkowicie przezroczystą wodę (lub szkło). Dzięki przepływowi cieczy widoczne są szczegóły skóry modelki. Efekt światła i cienia zmienia się z odbicia na załamanie światła.",
  "image": ["https://ark-project.tos-cn-beijing.volces.com/doc_image/seedream4_5_imageToimage.png"],
  "size": "2K",
  "watermark": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Podział na warstwy (Seedream 5.0 Pro)

Podział na warstwy rozdziela jeden obraz wejściowy na jeden obraz tła oraz maksymalnie 16 niezależnie edytowalnych przezroczystych warstw PNG. Poniższe żądanie pozwala modelowi automatycznie rozpoznać główne elementy. Jeśli chcesz określić konkretne elementy, możesz dodać `prompt`, a także użyć w poleceniu znormalizowanych współrzędnych `<bbox>`.

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "https://example.com/poster.png",
  "layer_decomposition": true,
  "size": "2K",
  "watermark": false
}'
```

Zwrócone elementy `data` są uporządkowane według `z_index`, od najniższej do najwyższej warstwy. Obraz tła ma wartość `z_index` równą 0. Warstwy zawierają również pola `name`, `description` oraz `bounding_box.absolute`/`normalized`. Podczas odtwarzania obrazu przy użyciu współrzędnych bezwzględnych należy przeskalować warstwę do rozmiaru `[right-left, bottom-top]`, umieścić ją w pozycji `[left, top]`, a następnie nakładać warstwy w kolejności rosnącej według `z_index`. Jeśli wygenerowanie dowolnej warstwy zakończy się niepowodzeniem, całe zadanie podziału zakończy się niepowodzeniem.

## Przesyłanie strumieniowe

W przypadku Lite/4.x po ustawieniu `stream: true` w nagłówku żądania należy użyć `accept: application/x-ndjson`. Interfejs API zwraca dane w kolejnych wierszach w postaci zdarzeń `image_generation.partial_succeeded` lub `image_generation.partial_failed`, a na końcu zwraca jedno zdarzenie `image_generation.completed` wraz z końcowym polem `usage`. Opłata jest naliczana tylko raz po wystąpieniu zdarzenia zakończenia. Trybu strumieniowego nie można używać jednocześnie z `async` ani `callback_url`.

## Wywołanie zwrotne asynchroniczne

Ponieważ generowanie obrazów przez SeeDream Images Generation API trwa stosunkowo długo, około 1–2 minut, jeśli API przez dłuższy czas nie odpowiada, połączenie HTTP pozostaje aktywne, co powoduje dodatkowe zużycie zasobów systemowych. Dlatego to API obsługuje również asynchroniczne wywołania zwrotne.

Ogólny przebieg jest następujący: podczas wysyłania żądania klient dodatkowo określa pole `callback_url`. Po wysłaniu żądania API natychmiast zwraca wynik zawierający pole `task_id`, które reprezentuje identyfikator bieżącego zadania. Po zakończeniu zadania wynik wygenerowanego obrazu jest wysyłany do adresu `callback_url` określonego przez klienta w formacie POST JSON. Zawiera on również pole `task_id`, dzięki czemu wynik zadania można powiązać za pomocą identyfikatora.

Jeśli nie masz publicznego adresu internetowego, na który można wysłać wywołanie zwrotne, możesz pominąć `callback_url` i zamiast tego ustawić pole `async` na `true` w żądaniu. W takim przypadku interfejs API również natychmiast zwróci `task_id`, ale nie prześle wyniku. Aby uzyskać wynik końcowy, należy użyć tego `task_id` do okresowego sprawdzania statusu zadania za pomocą interfejsu `/seedream/tasks`.

## Obsługa błędów

W przypadku wystąpienia błędu podczas wywoływania API, API zwróci odpowiedni kod błędu i komunikat. Na przykład:

- `400 token_mismatched`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit liczby żądań.
- `500 api_error`: Wewnętrzny błąd serwera, wystąpił problem po stronie serwera.

### Przykład odpowiedzi błędu
