W tym artykule przedstawimy sposób integracji API do rozpoznawania protokołów hCaptcha, które pozwala użytkownikom na automatyczne dekodowanie i weryfikację bez konieczności rozpoznawania i klikania w obrazy CAPTCHA, wystarczy przesłać klucz witryny.

## Proces aplikacji

Aby skorzystać z API do rozpoznawania protokołów hCaptcha, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API, który należy zachować na przyszłość.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować, a po zakończeniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

**Jeden token API wystarczy do korzystania ze wszystkich usług platformy, nie ma potrzeby składania osobnych wniosków dla każdej usługi.** Przy pierwszym wniosku otrzymasz darmowy limit, aby móc skorzystać z usługi; gdy limit się wyczerpie, możesz doładować saldo ogólne w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [API do rozpoznawania protokołów hCaptcha →](https://platform.acedata.cloud/documents/captcha-token-hcaptcha)

## Podstawowe użycie

Najpierw zapoznaj się z podstawowym sposobem użycia, polegającym na wprowadzeniu URL witryny, która wymaga przetworzenia CAPTCHA hCaptcha, aby uzyskać przetworzony wynik. Najpierw musisz przekazać pole `website_url`, nasza przykładowa witryna to: `https://accounts.hcaptcha.com/demo`, musimy uzyskać `website_key` na stronie `website_url`, najpierw otwórz tę stronę, naciśnij F12, aby przejść do konsoli, a następnie w zakładce Elementy wykonaj globalne wyszukiwanie `hcaptcha-demo`, uzyskując poniższy wynik:

<p><img src="https://cdn.acedata.cloud/bmx7ik.png" width="500" className="m-auto" /></p>

String odpowiadający `data-sitekey` to wartość `website_key`, poniżej znajdują się konkretne wyniki parametrów:

<p><img src="https://cdn.acedata.cloud/st6q7a.png" width="500" className="m-auto" /></p>

Można zauważyć, że ustawiliśmy nagłówki żądania, w tym:

- `accept`: jakiego formatu odpowiedzi oczekujesz, tutaj wpisujemy `application/json`, czyli format JSON.
- `authorization`: klucz do wywołania API, po złożeniu wniosku można go bezpośrednio wybrać z rozwijanej listy.

Dodatkowo ustawiono ciało żądania, w tym:

- `website_url`: URL witryny, która wymaga przetworzenia CAPTCHA.
- `website_key`: identyfikator klucza witryny w hCaptcha.
- `proxy`: opcjonalne, własny proxy (Bring Your Own Proxy). Po ustawieniu, upstream będzie używał dostarczonego przez Ciebie adresu IP proxy do rozwiązywania CAPTCHA, aby kontrolować jakość wyjściowego adresu IP (na przykład, aby uniknąć blokady przez docelową witrynę z powodu publicznego adresu IP proxy, co skutkuje zwróceniem `410 Gone`). Format to `scheme://[user:pass@]host:port`, `scheme` obsługuje `http`/`https`/`socks4`/`socks5`, na przykład `http://user:pass@1.2.3.4:8080`. Jeśli nie wypełnisz, użyje domyślnego proxy platformy.

Z analizy powyższego obrazu wynika, że URL żądania POST to: `https://accounts.hcaptcha.com/demo`, musimy tylko przesłać parametry `g-recaptcha-response`, `h-captcha-response` i `email`, a następnie wystarczy wprowadzić przetworzony token w poniższych danych, wywołując odpowiedni kod CURL do weryfikacji tokena:

```shell
curl 'https://accounts.hcaptcha.com/demo' \
  --data-raw 'email=&g-recaptcha-response={token}&h-captcha-response={token}'
```

Odpowiedni kod Python do weryfikacji tokena wygląda następująco:

```python
import requests

token = '{token}'

data = {
    'email': '',
    'g-recaptcha-response': token,
    'h-captcha-response': token
}

response = requests.post('https://accounts.hcaptcha.com/demo',
                        data=data)

if response.status_code == 200:
    print(response.text)

```

Dodatkowo, jeśli chcesz wygenerować odpowiedni kod do integracji, możesz po prostu skopiować wygenerowany kod, na przykład kod CURL wygląda następująco:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/hcaptcha' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "a5f74b19-9e45-40e0-b45d-47ff91b7a6c2",
  "website_url": "https://accounts.hcaptcha.com/demo"
}'
```

Kod integracji w Pythonie wygląda następująco:

```python
import requests

url = "https://api.acedata.cloud/captcha/token/hcaptcha"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "website_key": "a5f74b19-9e45-40e0-b45d-47ff91b7a6c2",
    "website_url": "https://accounts.hcaptcha.com/demo"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Tryb asynchroniczny (async)

Domyślnie API jest synchroniczne i blokujące: jedno żądanie będzie czekać, aż przetwarzanie tokena zostanie zakończone, zanim zwróci wynik. Jeśli wykonujesz rotację wielu rozwiązań (multi-solver rotation) i chcesz „natychmiast uzyskać task_id po złożeniu zadania, aby najpierw zlecić inne rozwiązania, a później wrócić po wyniki”, możesz wprowadzić `async: true` w ciele żądania.

Po wprowadzeniu `async: true` interfejs natychmiast zwróci `task_id`, nie blokując oczekiwania:

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

Następnie użyj tego `task_id`, aby cyklicznie wywoływać `POST /captcha/tasks` (zaleca się co 3-5 sekund), aby uzyskać wyniki:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

W trakcie przetwarzania zwróci `status: processing`:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

Po zakończeniu przetwarzania zwróci `status: ready` i token:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "token": "P1_eyJ0eXAiOiJKV1QiLCJhbGciOiJIUzI1Ni......"
}
```

Informacje o opłatach: w trybie asynchronicznym tworzenie zadań i cykliczne sprawdzanie „w trakcie przetwarzania” nie generuje opłat; **opłata jest naliczana tylko raz, gdy token zostanie pomyślnie uzyskany** (w tej samej wysokości co w trybie synchronicznym). Dlatego w przypadku rotacji anulowanie zadań, które nie zostały jeszcze zakończone, nie generuje kosztów. `/captcha/tasks` jest uniwersalne dla wszystkich interfejsów CAPTCHA (token i seria rozpoznawania, takich jak hcaptcha, recaptcha2, recaptcha3, recognition/* itp.), można używać tego samego `task_id` do cyklicznego sprawdzania.

## Obsługa błędów

Podczas wywoływania API, jeśli napotkasz błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Nieautoryzowany, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit.
- `500 api_error`: Błąd wewnętrzny serwera, coś poszło nie tak na serwerze.

### Przykład odpowiedzi błędu

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
