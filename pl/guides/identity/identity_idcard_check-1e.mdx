Niniejszy dokument przedstawia sposób integracji API weryfikacji zdjęcia z dowodu osobistego, które może być używane do przesyłania zdjęcia twarzy z dowodu osobistego, rozpoznawania informacji na zdjęciu oraz porównywania imienia, numeru dowodu osobistego i zdjęcia twarzy z autoryzowanym repozytorium zdjęć, aby sprawdzić, czy należy do tej samej osoby, w celu weryfikacji autentyczności informacji z dowodu osobistego.

## Proces aplikacji

Aby korzystać z API weryfikacji zdjęcia z dowodu osobistego, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API, który należy zachować na przyszłość.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować, a po zakończeniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

**Jeden token API wystarczy do korzystania ze wszystkich usług platformy, nie ma potrzeby składania osobnych wniosków dla każdej usługi.** Przy pierwszym wniosku przyznawana jest darmowa pula, aby można było skorzystać z bezpłatnej wersji próbnej; w przypadku niewystarczającej puli można doładować saldo ogólne w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [API weryfikacji zdjęcia z dowodu osobistego →](https://platform.acedata.cloud/documents/identity-idcard-check-1e)

## Podstawowe użycie

Najpierw zapoznaj się z podstawowym sposobem użycia, polegającym na wprowadzeniu linku do zdjęcia dowodu osobistego, aby uzyskać przetworzony wynik weryfikacji. Należy najpierw przekazać pole `image_url`, a następnie możemy wypełnić odpowiednie treści na interfejsie, jak pokazano na rysunku:

<p><img src="https://cdn.acedata.cloud/zjxg3k.png" width="500" className="m-auto" /></p>

Można zauważyć, że ustawiliśmy nagłówki żądania, w tym:

- `accept`: format odpowiedzi, który chcemy otrzymać, tutaj wpisujemy `application/json`, czyli format JSON.
- `authorization`: klucz do wywołania API, po złożeniu wniosku można go bezpośrednio wybrać z rozwijanej listy.

Dodatkowo ustawiono ciało żądania, w tym:

- `image_url`: link do zdjęcia dowodu osobistego, które ma być przetworzone.
- `config`: opcjonalne opcje konfiguracyjne, pole typu boolean, domyślnie wszystkie są ustawione na false, wspiera `copy_warn`, `border_check_warn`, `reshoot_warn`, `detect_ps_warn`, `temp_id_warn`, `quality` (próg 0-100).

Po dokonaniu wyboru, można zauważyć, że po prawej stronie wygenerowano odpowiedni kod, jak pokazano na rysunku:

<p><img src="https://cdn.acedata.cloud/4yh23p.png" width="500" className="m-auto" /></p>

Klikając przycisk „Try”, można przeprowadzić test, jak pokazano na powyższym rysunku, uzyskując następujący wynik:

```json
{
  "sim": 99.76,
  "result": "Success",
  "description": "Sukces",
  "name": "Imię z dowodu osobistego",
  "sex": "Płeć z dowodu osobistego",
  "nation": "Narodowość z dowodu osobistego",
  "birth": "Data urodzenia z dowodu osobistego",
  "address": "Adres zamieszkania z dowodu osobistego",
  "id_num": "Numer dowodu osobistego",
  "portrait": "/9j/4AAQSkZJRgABAQAAAQABAAD/2wBDAAEBAQEBAQEBAQEBAQEBAQEBAQEBA.....DEhE2lbPMcOtG3f/DLT/yX8if7Kxn/AD7h85wdttPifRf1e6//2Q==",
  "warnings": "",
  "quality": 0,
  "encryption": null
}
```

Wynik zwrotny zawiera wiele pól, które są opisane poniżej:

- `sim`, podobieństwo, zakres wartości [0.00, 100.00]. Zaleca się, aby podobieństwo większe lub równe 70 można uznać za tę samą osobę, można dostosować próg w zależności od konkretnego scenariusza (próg 70 ma wskaźnik fałszywych pozytywów na poziomie jednego na tysiąc, próg 80 ma wskaźnik fałszywych pozytywów na poziomie jednego na dziesięć tysięcy).
- `result`, kod błędu biznesowego, w przypadku sukcesu zwraca Success, w przypadku błędu proszę odwołać się do poniższej listy kodów błędów w sekcji FailedOperation.
- `description`, wynik weryfikacji imienia i numeru dowodu osobistego.
- `name`, informacja o imieniu z dowodu osobistego, jeśli nie przesłano zdjęcia dowodu osobistego, będzie pusta.
- `sex`, informacja o płci z dowodu osobistego, jeśli nie przesłano zdjęcia dowodu osobistego, będzie pusta.
- `nation`, informacja o narodowości z dowodu osobistego, jeśli nie przesłano zdjęcia dowodu osobistego, będzie pusta.
- `birth`, informacja o dacie urodzenia z dowodu osobistego, jeśli nie przesłano zdjęcia dowodu osobistego, będzie pusta.
- `address`, informacja o adresie zamieszkania z dowodu osobistego, jeśli nie przesłano zdjęcia dowodu osobistego, będzie pusta.
- `id_num`, informacja o numerze dowodu osobistego, jeśli nie przesłano zdjęcia dowodu osobistego, będzie pusta.
- `portrait`, kodowanie base64 zdjęcia z dowodu osobistego, jeśli wycięcie zdjęcia się nie powiedzie, zostanie porównane całe zdjęcie dowodu osobistego i zwróci puste.
- `warnings`, informacje o ostrzeżeniach, gdy w konfiguracji ustawiono informacje o ostrzeżeniach, porównanie twarzy zostanie zatrzymane, a wynik zwróci błąd (FailedOperation.OcrWarningOccurred) z tymi informacjami o ostrzeżeniach.
- `quality`, wynik jakości zdjęcia, gdy w konfiguracji żądania ustawiono ostrzeżenie o rozmyciu, ten parametr ma znaczenie, zakres wartości (0-100), obecnie domyślny próg to 50 punktów, poniżej 50 punktów wywoła ostrzeżenie o rozmyciu.
- `encryption`, informacje o szyfrowaniu danych wrażliwych.

Można zauważyć, że informacje z dowodu osobistego mają bardzo wysoką autentyczność.

Jeśli chcesz wygenerować odpowiedni kod do integracji, możesz go bezpośrednio skopiować, na przykład kod CURL wygląda następująco:

```shell
curl -X POST 'https://api.acedata.cloud/identity/idcard/check-1e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": {image_url}
}'
```

Kod do integracji w Pythonie wygląda następująco:

```python
import requests

url = "https://api.acedata.cloud/identity/idcard/check-1e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "image_url": {image_url}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Nieautoryzowany, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit.
- `500 api_error`: Błąd wewnętrzny serwera, coś poszło nie tak na serwerze.

### Przykład odpowiedzi błędu

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
