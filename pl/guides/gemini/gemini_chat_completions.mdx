Google Gemini to bardzo potężny system konwersacyjny AI, który po prostu po wprowadzeniu promptu może w ciągu kilku sekund wygenerować płynną i naturalną odpowiedź. Gemini może zapewnić niesamowite inteligentne wsparcie, znacznie zwiększając efektywność pracy i kreatywność ludzi.

Ten dokument głównie przedstawia proces korzystania z operacji Gemini Chat Completion API, dzięki któremu możemy łatwo korzystać z funkcji konwersacyjnych oficjalnego Gemini.

## Proces wnioskowania

Aby korzystać z Gemini Chat Completion API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany ani zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i zalogowania się, a po zakończeniu automatycznie wrócisz na bieżącą stronę.

**Jeden API Token może wywoływać wszystkie usługi platformy, bez potrzeby osobnego wnioskowania dla każdej usługi.** Przy pierwszym wnioskowaniu otrzymasz darmowy limit, z którego możesz korzystać bezpłatnie; gdy limit jest niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## Podstawowe użycie

Następnie możesz wypełnić odpowiednią zawartość w interfejsie, jak pokazano na ilustracji:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

Przy pierwszym użyciu tego interfejsu musimy wypełnić co najmniej trzy elementy. Jednym z nich jest `authorization`, który można wybrać bezpośrednio z listy rozwijanej. Kolejnym parametrem jest `model`, `model` to wybrana przez nas kategoria modeli z oficjalnej strony Gemini, a dostępne modele są zgodne z wyliczeniem `model` w dokumentacji interfejsu. Ostatnim parametrem jest `messages`, `messages` to tablica wprowadzonych przez nas promptów, jest to tablica, co oznacza, że można jednocześnie przesłać wiele promptów, przy czym każdy prompt zawiera `role` i `content`, gdzie `role` oznacza rolę osoby zadającej pytanie. Udostępniamy trzy tożsamości: `user`, `assistant`, `system`. Drugie `content` to konkretna treść naszego pytania.

Jednocześnie możesz zauważyć, że po prawej stronie generowany jest odpowiedni kod wywołania. Możesz skopiować kod i uruchomić go bezpośrednio, a także bezpośrednio kliknąć przycisk „Try”, aby przeprowadzić test.

## Rozumienie obrazów (wejście multimodalne)

Gemini jest natywnym modelem multimodalnym i może bezpośrednio „oglądać obrazy”. Aby przekazać obraz, zmień `content` danej wiadomości z ciągu znaków na **tablicę bloków treści**, a następnie umieść w tablicy jednocześnie blok `text` i blok `image_url` — jest to całkowicie zgodne z OpenAI oraz formatem kompatybilnym z OpenAI oficjalnego Gemini.

`image_url.url` obsługuje dwa sposoby zapisu:

- **base64 `data:` URI (zalecane, najbardziej stabilne)**: format to `data:<typ mediów>;base64,<dane>`, na przykład `data:image/jpeg;base64,/9j/4AAQ...`. **Typ mediów (MIME) jest już zapisany w prefiksie `data:`**, dlatego osobne pole `media_type` nie jest potrzebne ani nie istnieje.
- **Publicznie dostępny URL obrazu**: na przykład `https://cdn.acedata.cloud/4hfydw.jpg`.

Obsługiwane typy obrazów: `png`, `jpeg`, `webp`, `heic`, `heif`.

Przykładowy kod wywołania Python (base64 data URI):
```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# 把本地图片读成 base64 data URI
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Możesz także bezpośrednio przekazać publicznie dostępny adres URL obrazu:

> 💡 `image_url` akceptuje wyłącznie pole `url` (wartością może być adres URL obrazu lub base64 `data:` URI) oraz opcjonalne pole `detail`. **Nie przekazuj `media_type`** — jest to pole obrazu Anthropic Claude, które nie należy do formatu `image_url` OpenAI / Gemini.

## Odpowiedź strumieniowa

Ten interfejs obsługuje również odpowiedzi strumieniowe, co jest bardzo przydatne przy integracji ze stronami internetowymi i pozwala uzyskać efekt wyświetlania znak po znaku.

Jeśli chcesz zwracać odpowiedź strumieniowo, możesz zmienić parametr `stream ` w nagłówku żądania na `true`.

Wprowadź zmiany jak pokazano na ilustracji, jednak kod wywołania musi zostać odpowiednio zmieniony, aby obsługiwał odpowiedź strumieniową.

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

Po zmianie `stream` na `true` API będzie zwracać odpowiednie dane JSON wiersz po wierszu, a na poziomie kodu musimy wprowadzić odpowiednie zmiany, aby uzyskać wyniki wiersz po wierszu.

Przykładowy kod wywołania w Pythonie:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Obsługiwany jest również JavaScript, na przykład kod wywołania strumieniowego w Node.js wygląda następująco:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

## Model multimodalny Gemini-3.1

`gemini-3.1-pro-preview` jest obecnym oficjalnym ID modelu Gemini 3.1 Pro, obsługuje multimodalne dane wejściowe, takie jak tekst, obrazy i wideo, oraz nadaje się do złożonych zadań rozumowania, kodowania i rozumienia.

Przykład żądania:

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "图片的内容是什么？"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/qzx2z1.png"
          }

  "stream": false
}
```

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informację. Na przykład:

- `400 token_mismatched`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`: Wewnętrzny błąd serwera, coś poszło nie tak po stronie serwera.

### Przykład odpowiedzi błędu

```
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
