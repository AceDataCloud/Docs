Google Gemini to bardzo potężny system konwersacyjny AI, który po prostu po wprowadzeniu podpowiedzi może w zaledwie kilka sekund wygenerować płynną i naturalną odpowiedź. Gemini może zapewnić zdumiewające inteligentne wsparcie, znacznie zwiększając efektywność pracy i kreatywność człowieka.

Ten dokument przedstawia głównie proces korzystania z Gemini Chat Completion API; za jego pomocą możemy łatwo używać funkcji konwersacyjnych oficjalnego Gemini.

## Proces składania wniosku

Aby korzystać z Gemini Chat Completion API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany ani zarejestrowany, nastąpi automatyczne przekierowanie na stronę logowania z zaproszeniem do rejestracji i logowania, a po zakończeniu automatycznie powrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności składania osobnego wniosku dla każdej usługi.** Przy pierwszym wniosku otrzymasz bezpłatny limit, który umożliwia darmowe wypróbowanie; gdy limit będzie niewystarczający, możesz doładować wspólne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## Podstawowe użycie

Następnie możesz wypełnić odpowiednie treści w interfejsie, jak pokazano na ilustracji:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

Przy pierwszym użyciu tego interfejsu musimy wypełnić co najmniej trzy elementy. Jednym z nich jest `authorization`, które można wybrać bezpośrednio z listy rozwijanej. Kolejnym parametrem jest `model`, `model` oznacza kategorię modelu Gemini z oficjalnej strony, którą wybieramy do użycia; dostępne modele są zgodne z wyliczeniem `model` w dokumentacji interfejsu. Ostatnim parametrem jest `messages`, `messages` to tablica wprowadzonych przez nas pytań; jest to tablica, co oznacza, że można jednocześnie przesłać wiele pytań, a każde pytanie zawiera `role` i `content`, gdzie `role` oznacza rolę osoby zadającej pytanie; udostępniamy trzy tożsamości: `user`, `assistant`, `system`. Natomiast `content` to konkretna treść naszego pytania.

Jednocześnie możesz zauważyć, że po prawej stronie generowany jest odpowiedni kod wywołania; możesz skopiować kod i uruchomić go bezpośrednio albo kliknąć przycisk „Try”, aby przeprowadzić test.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

> **Wskazówka**: flash z serii `gemini-3.x` to modele rozumujące, które najpierw zużywają reasoning tokens; ustaw `max_tokens` na wartość powyżej 512, w przeciwnym razie może zostać zwrócona tylko pusta zawartość. `gemini-3.8-flash` jest obecnie zalecanym modelem Flash, obsługuje kontekst do 1 miliona Tokenów, wejście obrazów, wywoływanie narzędzi i odpowiedzi strumieniowe; obecnie jest wywoływany przez interfejs Chat Completions.

`gemini-4-argon` może również być używany w Chat Completions i obsługuje zwykłe oraz strumieniowe odpowiedzi tekstowe. Może przeznaczać część budżetu wyjściowego na rozumowanie, dlatego dla złożonych zadań należy pozostawić wystarczającą przestrzeń dla `max_tokens`; Google zaleca dla regularnych zadań tego modelu co najmniej 32768. Nie należy utożsamiać tego interfejsu z funkcją długich wyników działającą w tle w Google Interactions API.

`gemini-4-neon` — inżynieria oprogramowania i analiza danych. W polu `model` podaj ten identyfikator i zarezerwuj tokeny wyjściowe na rozumowanie oraz odpowiedź.

`gemini-4-carbon` i `gemini-4-hydrogen` również obsługują zwykłe oraz strumieniowe odpowiedzi tekstowe w tym interfejsie. Carbon jest przeznaczony do złożonego rozumowania i zadań inżynieryjnych, a Hydrogen do codziennego kodowania i zadań wieloetapowych. Oba zużywają Tokeny rozumowania, dlatego należy zachować wystarczający budżet dla `max_tokens`; długie wyniki o wielkości miliona Tokenów w natywnych modelach nie oznaczają, że ta funkcja jest dostępna w tym interfejsie. Pola obrazów i wywoływania narzędzi nadal podlegają publicznemu kontraktowi tego interfejsu oraz faktycznie zwracanym wynikom.

## Rozumienie obrazów (wejście multimodalne)
Gemini jest natywnym modelem multimodalnym, który może bezpośrednio „oglądać obrazy”. Aby przekazać obraz, zmień `content` danej wiadomości ze stringa na **tablicę bloków treści** i umieść w niej jednocześnie blok `text` oraz blok `image_url` — jest to całkowicie zgodne z formatem kompatybilnym z OpenAI zarówno dla OpenAI, jak i oficjalnego Gemini.

`image_url.url` obsługuje dwa sposoby zapisu:

- **base64 `data:` URI (zalecane, najbardziej stabilne)**: format to `data:<typ mediów>;base64,<dane>`, na przykład `data:image/jpeg;base64,/9j/4AAQ...`. **Typ mediów (MIME) jest już zapisany w prefiksie `data:`**, więc osobne pole `media_type` nie jest potrzebne ani nie istnieje.
- **Publicznie dostępny URL obrazu**: na przykład `https://cdn.acedata.cloud/4hfydw.jpg`.

Obsługiwane typy obrazów: `png`, `jpeg`, `webp`, `heic`, `heif`.

Przykładowy kod wywołania w Pythonie (base64 data URI):

```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# 把本地图片读成 base64 data URI
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Można również bezpośrednio przekazać publicznie dostępny URL obrazu:


> 💡 `image_url` akceptuje wyłącznie pole `url` (jego wartością może być URL obrazu lub base64 `data:` URI) oraz opcjonalne pole `detail`. **Nie przekazuj `media_type`** — jest to pole obrazu Anthropic Claude i nie należy do formatu `image_url` OpenAI / Gemini.

## Odpowiedź strumieniowa

Ten interfejs obsługuje również odpowiedzi strumieniowe, co jest bardzo przydatne przy integracji ze stronami internetowymi i pozwala na uzyskanie efektu wyświetlania tekstu znak po znaku.

Jeśli chcesz zwracać odpowiedź strumieniowo, możesz zmienić parametr `stream ` w nagłówkach żądania na `true`.

Zmiana jest pokazana na ilustracji, jednak kod wywołania musi zostać odpowiednio zmodyfikowany, aby obsługiwać odpowiedzi strumieniowe.

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

Po zmianie `stream` na `true` API będzie zwracać odpowiednie dane JSON wiersz po wierszu, a na poziomie kodu musimy wprowadzić odpowiednie zmiany, aby uzyskać wyniki wiersz po wierszu.

Przykładowy kod wywołania w Pythonie:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Obsługiwany jest również JavaScript, na przykład kod wywołania strumieniowego w Node.js wygląda następująco:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

## Model multimodalny Gemini-3.1

`gemini-3.1-pro-preview` jest obecnym oficjalnym identyfikatorem modelu Gemini 3.1 Pro, obsługuje multimodalne dane wejściowe, takie jak tekst, obrazy i wideo, i nadaje się do złożonego rozumowania, kodowania oraz zadań związanych ze zrozumieniem.

Przykład żądania:

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "图片的内容是什么？"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/qzx2z1.png"
          }
        }
      ]
    }
  ],
  "stream": false
}
```

Gemini 3.1 Pro również obsługuje rozumienie wideo:


Format zwracanych danych jest zgodny z Gemini 3.0 Pro; szczegóły znajdują się w opisie w powyższej sekcji dotyczącej modelu multimodalnego Gemini-3.0.

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`：Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`：Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`：Wewnętrzny błąd serwera, coś poszło nie tak na serwerze.

### Przykład odpowiedzi błędu

```
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
