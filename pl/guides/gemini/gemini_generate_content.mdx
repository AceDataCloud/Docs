Google Gemini to bardzo potężny system konwersacyjny AI, który poprzez wprowadzenie podpowiedzi może w kilka sekund wygenerować płynną i naturalną odpowiedź. Niniejszy dokument głównie opisuje sposób użycia Gemini Generate Content API, jest to oficjalny natywny format API Google, obsługujący dwa endpointy: `generateContent` i `streamGenerateContent`.

## Różnice względem Chat Completions API

Gemini Generate Content API używa oficjalnego natywnego formatu żądań Google (pole `contents`), zamiast formatu kompatybilnego z OpenAI (pole `messages`). Jeśli już używasz Google Gemini SDK lub znasz oficjalny format API, możesz bezpośrednio korzystać z tego API bez modyfikowania formatu żądań.

## Aktualnie obsługiwany zakres

Interfejs przyjmuje wejście tekstowe, obrazy, wideo i audio (`inlineData` lub `fileData`), konfigurację rozumowania oraz deklaracje niestandardowych funkcji. Natywne pola, takie jak wyjście audio, wbudowane narzędzia i jawne buforowanie kontekstu, nie mają jeszcze gwarancji jednolitej dostępności, należy kierować się faktyczną odpowiedzią konkretnego modelu.

Podczas przesyłania plików, takich jak audio, za pomocą `fileData.fileUri`, upewnij się, że plik jest bezpośrednio dostępny przez HTTPS, nie zależy od stanu logowania, a okres ważności podpisanego linku obejmuje cały czas przetwarzania żądania. Niestrumieniowa analiza audio zwraca wynik dopiero po zakończeniu przetwarzania przez model i może przekroczyć 90 sekund; klient powinien ustawić wystarczająco długi całkowity limit czasu zgodnie z rozmiarem pliku i scenariuszem biznesowym, aby uniknąć rozłączenia, gdy serwer nadal przetwarza dane.

## Proces uzyskania dostępu

Przed użyciem Gemini Generate Content API odwiedź najpierw stronę [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api), kliknij przycisk „Uzyskaj”, aby otrzymać poświadczenia wymagane do żądania.

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, nastąpi automatyczne przekierowanie na stronę logowania. Przy pierwszym wniosku dostępny jest bezpłatny limit.

## Podstawowe użycie

### Non-Streaming (niestumieniowe)

Wyślij żądanie POST do `/v1beta/models/{model}:generateContent`:

> **Wskazówka**: seria `gemini-3.x` flash to modele rozumujące, które najpierw zużywają reasoning tokens; ustaw `generationConfig.maxOutputTokens` na wartość powyżej 512, w przeciwnym razie może zostać zwrócona tylko pusta treść.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Przykład zwróconego wyniku:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Pola tokenów w `usageMetadata` są rozliczane zgodnie z natywną semantyką Gemini:

- `promptTokenCount` zawiera `cachedContentTokenCount`; część trafiająca do pamięci podręcznej jest obliczana według ceny odczytu z pamięci podręcznej i nie jest ponownie liczona jako zwykłe wejście.
- `promptTokensDetails` oraz `cacheTokensDetails` są normalizowane do `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` i odpowiadających im szczegółów `cached_*` w `usage.prompt_tokens_details`. Wartości te są odpowiednio zawarte w `prompt_tokens` i `cached_tokens`; różne modalności są przeliczane wyłącznie według swoich cen i nie są naliczane podwójnie.
- Zarówno `candidatesTokenCount`, jak i `thoughtsTokenCount` są obliczane według ceny tokenów wyjściowych.
- `toolUsePromptTokenCount` to niezależne tokeny wejściowe narzędzia, obliczane według ceny tokenów wejściowych.

Ace Data Cloud dodatkowo zwraca znormalizowany obiekt `usage`; we wszystkich protokołach modeli koszt tego wywołania jest odczytywany jednolicie z `usage.cost`. `cost` to opcjonalny podgląd kosztu; gdy podgląd cen jest tymczasowo niedostępny, odpowiedź modelu nadal zostanie normalnie zwrócona, ale może nie zawierać tego pola. Ostateczne rozliczenie zależy od rekordu użycia.

### Streaming (strumieniowe)

Wyślij żądanie POST do `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

Odpowiedź strumieniowa będzie stopniowo zwracać treść w formacie SSE (Server-Sent Events). Zdarzenia pośrednie zwykle zawierają tylko treść przyrostową; zdarzenie końcowe zawierające wiarygodne użycie będzie zawierać `usageMetadata` oraz znormalizowane `usage`, a koszt nadal znajduje się w `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

Zamknięcie połączenia oznacza zakończenie strumienia; natywny strumień Gemini nie wysyła `data: [DONE]`. Jeśli podgląd ceny końcowej jest tymczasowo niedostępny, `usage` nadal zwróci użycie tokenów, ale pominie `cost`.

`gemini-4-carbon` i `gemini-4-hydrogen` można obecnie wywoływać przez Chat Completions, natywne Generate Content jest tymczasowo niedostępne. Oficjalne specyfikacje modeli wymieniają wejścia tekstowe, obrazowe, wideo, audio i PDF oraz wyjście tekstowe; nie oznacza to, że bieżąca platforma zweryfikowała już wszystkie typy wejść. Po przywróceniu natywnego wywoływania należy przesyłać żądania zgodnie z kontraktem interfejsu na tej stronie oraz osobno zweryfikować wymagane wejścia i parametry. Milionowy Token wyjściowy oficjalnego long decode nie jest objęty bieżącym kontraktem interfejsu. Oba obsługują wyłącznie niejawne buforowanie, a Tokeny rozumowania są naliczane według ceny wyjściowej; przygotowane reguły cenowe stosują tę samą cenę jednostkową wejściowego Tokenu dla wszystkich modalności wejściowych, a trafienia w pamięci podręcznej są naliczane według ceny jednostkowej odczytu z pamięci podręcznej, szczegóły znajdują się na bieżącej stronie cenowej.

### Wewnętrzne rozumowanie i podsumowanie rozumowania

Wewnętrzne rozumowanie modelu i zwracanie podsumowania rozumowania wywołującemu są dwoma niezależnymi ustawieniami:

- `thinkingBudget` lub `thinkingLevel` kontroluje budżet lub głębokość wewnętrznego rozumowania modelu, obsługiwane pola i wartości zależą od modelu.
- `includeThoughts` kontroluje, czy zwracać podsumowanie rozumowania, domyślnie ma wartość `false`. Gdy to pole zostanie pominięte lub zostanie przekazane `false`, ani zwykłe odpowiedzi JSON, ani odpowiedzi strumieniowe SSE nie zwrócą tekstu oznaczonego jako `thought: true`; teksty te są zachowywane tylko wtedy, gdy jawnie zostanie przekazana wartość logiczna `true`.

Gdy żądanie nie ustawia `includeThoughts`, interfejs domyślnie przekazuje `false` modelom generującym obsługującym konfigurację rozumowania, aby uniknąć żądania niepotrzebnych podsumowań; wartość jawnie przekazana przez klienta, budżet rozumowania i poziom zostaną zachowane. Do znanego modelu `gemini-2.5-flash-image`, który nie obsługuje konfiguracji rozumowania, to pole nie będzie automatycznie dodawane, ani nie będzie dodawana konfiguracja generowania do żądań `countTokens`.

Wyłączenie podsumowania nie oznacza wyłączenia wewnętrznego rozumowania ani nie gwarantuje zmniejszenia liczby tokenów wewnętrznego rozumowania. Jeśli odpowiedź nadal zawiera nieżądany tekst rozumowania, zwykłe wyjścia JSON i SSE będą dalej filtrowane, zachowując normalną odpowiedź, podpisy i rzeczywiste zużycie.

Gdy wymagane jest wyświetlenie podsumowania, należy jawnie je włączyć w następujący sposób. Jeśli model nie wygenerował dostępnego podsumowania, tekst rozumowania może nie być obecny nawet po włączeniu:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` jest zaszyfrowanym stanem wymaganym w kolejnych turach, a nie tekstem podsumowania rozumowania, i nie jest kontrolowany przez przełącznik `includeThoughts`. Podpis może znajdować się w normalnej odpowiedzi, wywołaniu funkcji lub pustym Part tekstowym; podczas filtrowania tekstu rozumowania podpisy i inne pola tego samego Part są zachowywane, dlatego odpowiedź może nadal zawierać Part, który przenosi tylko podpis i ma pusty tekst. Przy ręcznym utrzymywaniu historii wieloturowej należy zachować kolejność tych Part i pozycje podpisów, nie należy przenosić podpisów ani ich scalać.

`usageMetadata` i `usage` nadal rejestrują rzeczywiste zużycie. Ukrycie podsumowania nie zeruje `thoughtsTokenCount`, a rozliczenie nadal jest obliczane na podstawie rzeczywistego zużycia i bieżących reguł cenowych.

Zobacz oficjalne Google [wyjaśnienie dotyczące rozumowania i podsumowań rozumowania](https://firebase.google.com/docs/ai-logic/thinking) oraz [reguły podpisów rozumowania](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

## Ustawienia bezpieczeństwa

Filtrowanie treści można kontrolować za pomocą `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Obsługa błędów

| Kod stanu HTTP | Znaczenie             |
| -------- | -------------- |
| 400      | Nieprawidłowe parametry żądania         |
| 401      | Uwierzytelnianie nie powiodło się, sprawdź Token |
| 403      | Treść została zablokowana przez filtr bezpieczeństwa     |
| 429      | Zbyt częste żądania         |
| 500      | Wewnętrzny błąd serwera        |
