Google Gemini to bardzo potężny system konwersacyjny AI, który może generować płynne i naturalne odpowiedzi w ciągu kilku sekund po wprowadzeniu promptu. Ten dokument opisuje głównie sposób użycia Gemini Generate Content API, czyli oficjalnego natywnego formatu API Google, obsługującego dwa endpointy: `generateContent` i `streamGenerateContent`.

## Różnice względem Chat Completions API

Gemini Generate Content API używa oficjalnego natywnego formatu żądań Google (pole `contents`), zamiast formatu kompatybilnego z OpenAI (pole `messages`). Jeśli korzystasz już z Google Gemini SDK lub znasz oficjalny format API, możesz używać tego API bez konieczności modyfikowania formatu żądań.

## Aktualnie obsługiwany zakres

Interfejs akceptuje wejścia tekstowe, obrazy, wideo i audio (`inlineData` lub `fileData`), konfigurację myślenia oraz deklaracje funkcji niestandardowych. Natywne pola, takie jak wyjście audio, wbudowane narzędzia i jawne buforowanie kontekstu, nie mają jeszcze gwarantowanej jednolitej dostępności; należy kierować się rzeczywistą odpowiedzią konkretnego modelu.

Podczas przesyłania plików, takich jak audio, za pomocą `fileData.fileUri`, upewnij się, że plik jest bezpośrednio dostępny przez HTTPS, nie zależy od stanu logowania, a okres ważności podpisanego linku obejmuje cały czas przetwarzania żądania. Niestrumieniowa analiza audio zwraca wynik dopiero po zakończeniu przetwarzania przez model i może trwać ponad 90 sekund; klient powinien ustawić wystarczająco długi całkowity limit czasu zależnie od rozmiaru pliku i scenariusza biznesowego, aby uniknąć rozłączenia, gdy serwer nadal przetwarza dane.

## Proces uzyskania dostępu

Przed użyciem Gemini Generate Content API odwiedź stronę [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) i kliknij przycisk „Uzyskaj”, aby otrzymać poświadczenia wymagane do wysłania żądania.

Jeśli nie jesteś jeszcze zalogowany(-a) ani zarejestrowany(-a), nastąpi automatyczne przekierowanie na stronę logowania. Przy pierwszym wniosku dostępny jest bezpłatny limit.

## Podstawowe użycie

### Non-Streaming (niestumieniowe)

Wyślij żądanie POST do `/v1beta/models/{model}:generateContent`:

> **Wskazówka**: flash z serii `gemini-3.x` to modele myślące, które najpierw zużywają reasoning tokens; ustaw `generationConfig.maxOutputTokens` na wartość powyżej 512, w przeciwnym razie może zostać zwrócona tylko pusta treść.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Przykład zwracanego wyniku:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Pola tokenów w `usageMetadata` są rozliczane zgodnie z natywną semantyką Gemini:

- `promptTokenCount` obejmuje `cachedContentTokenCount`; część trafiająca do pamięci podręcznej jest obliczana według ceny odczytu z pamięci podręcznej i nie jest ponownie liczona jako zwykłe wejście.
- `promptTokensDetails` oraz `cacheTokensDetails` są normalizowane do `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` oraz odpowiadających im szczegółów `cached_*` w `usage.prompt_tokens_details`. Wartości te są odpowiednio zawarte w `prompt_tokens` oraz `cached_tokens`; różne modalności są przeliczane wyłącznie według własnych cen i nie są naliczane podwójnie.
- Zarówno `candidatesTokenCount`, jak i `thoughtsTokenCount` są obliczane według ceny tokenów wyjściowych.
- `toolUsePromptTokenCount` to niezależne tokeny wejściowe narzędzi, obliczane według ceny tokenów wejściowych.

Ace Data Cloud dodatkowo zwraca znormalizowany obiekt `usage`; niezależnie od protokołu modelu koszt tego wywołania jest odczytywany jednolicie z `usage.cost`. `cost` jest opcjonalnym podglądem kosztu; gdy podgląd cen jest tymczasowo niedostępny, odpowiedź modelu nadal zostanie zwrócona normalnie, ale może nie zawierać tego pola. Ostateczne rozliczenie opiera się na rekordach użycia.

### Streaming (strumieniowe)

Wyślij żądanie POST do `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

Odpowiedź strumieniowa będzie stopniowo zwracać treść w formacie SSE (Server-Sent Events). Zdarzenia pośrednie zwykle zawierają wyłącznie treść przyrostową; zdarzenie końcowe zawierające autorytatywne dane o użyciu będzie zawierać `usageMetadata` oraz znormalizowane `usage`, a koszt nadal znajduje się w `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

Zamknięcie połączenia oznacza zakończenie strumienia; natywny strumień Gemini nie wysyła `data: [DONE]`. Jeśli podgląd ceny końcowej jest tymczasowo niedostępny, `usage` nadal zwróci użycie tokenów, ale pominie `cost`.

### Wewnętrzne myślenie i podsumowania myślenia

Wewnętrzne myślenie modelu i zwracanie podsumowań myślenia wywołującemu są dwoma niezależnymi ustawieniami:

- `thinkingBudget` lub `thinkingLevel` kontroluje budżet lub głębokość wewnętrznego myślenia modelu; obsługiwane pola i wartości zależą od modelu.
- `includeThoughts` kontroluje, czy zwracane są podsumowania myślenia; domyślnie ma wartość `false`. Gdy pole zostanie pominięte lub przekazana zostanie wartość `false`, ani zwykłe odpowiedzi JSON, ani strumieniowe odpowiedzi SSE nie zwrócą tekstu oznaczonego jako `thought: true`; teksty te są zachowywane tylko po jawnym przekazaniu wartości logicznej `true`.

Gdy żądanie nie ustawia `includeThoughts`, interfejs domyślnie przekazuje `false` do modeli generowania obsługujących konfigurację myślenia, aby uniknąć żądania niepotrzebnych podsumowań; wartości jawnie przekazane przez klienta, budżet myślenia i poziom zostaną zachowane. Do modelu `gemini-2.5-flash-image`, który zgodnie z wiedzą nie obsługuje konfiguracji myślenia, to pole nie zostanie dodane automatycznie, a do żądań `countTokens` również nie zostanie dodana konfiguracja generowania.

Wyłączenie podsumowań nie jest równoznaczne z wyłączeniem wewnętrznego myślenia ani nie gwarantuje zmniejszenia liczby tokenów wewnętrznego myślenia. Jeśli odpowiedź nadal zawiera niezamówiony tekst myślenia, zwykłe wyjścia JSON i SSE zostaną dodatkowo przefiltrowane, zachowując normalną odpowiedź, podpisy i rzeczywiste użycie.

Gdy potrzebne jest wyświetlenie podsumowań, włącz je jawnie w następujący sposób. Jeśli model nie wygeneruje dostępnego podsumowania, tekst myślenia może nie być obecny nawet po włączeniu:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "Wyjaśnij splątanie kwantowe"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` to zaszyfrowany stan potrzebny w kolejnych turach, a nie tekst podsumowania myślenia, i nie jest kontrolowany przez przełącznik `includeThoughts`. Podpis może znajdować się w normalnej odpowiedzi, wywołaniu funkcji lub pustym tekście Part; podczas filtrowania tekstu myślenia zachowywane są podpisy oraz inne pola tej samej Part, dlatego w odpowiedzi mogą nadal występować Part zawierające tylko podpis i pusty tekst. Podczas ręcznego utrzymywania historii wieloturowej należy zachować kolejność tych Part i pozycje podpisów, nie przenosić podpisów ani ich nie scalać.

`usageMetadata` i `usage` nadal rejestrują rzeczywiste użycie. Ukrycie podsumowań nie zeruje `thoughtsTokenCount`, a rozliczenie nadal jest obliczane na podstawie rzeczywistego użycia i aktualnych zasad cenowych.

Zobacz oficjalne informacje Google dotyczące [myślenia i podsumowań myślenia](https://firebase.google.com/docs/ai-logic/thinking) oraz [zasad podpisów myślenia](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

## Ustawienia bezpieczeństwa

Filtrowanie treści można kontrolować za pomocą `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```
