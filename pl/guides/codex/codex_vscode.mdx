Codex to agent programistyczny opracowany przez OpenAI. Oprócz interfejsu CLI w terminalu, oferuje również rozszerzenie do VS Code, które umożliwia czatowanie, czytanie plików, odwoływanie się do kontekstu, generowanie modyfikacji oraz podgląd zmian w panelu bocznym edytora.

W tym artykule opisano, jak skonfigurować i używać rozszerzenia Codex w VS Code za pomocą kompatybilnego proxy OpenAI Responses od Ace Data Cloud. Rozszerzenie Codex dla VS Code i CLI Codex korzystają z tego samego lokalnego systemu konfiguracji, więc wystarczy skierować `~/.codex/config.toml` na Ace Data Cloud, aby Codex w VS Code korzystał z `https://api.acedata.cloud/v1`.

## Proces rejestracji

Aby korzystać z Codex, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API i zachować go na później.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, gdzie możesz się zarejestrować i zalogować. Po zalogowaniu zostaniesz automatycznie przeniesiony z powrotem na bieżącą stronę.

Przy pierwszym wniosku otrzymasz darmowy limit, który pozwala na bezpłatne wypróbowanie usługi Codex.

## Instalacja rozszerzenia Codex

W sklepie rozszerzeń VS Code wyszukaj `Codex` i zainstaluj rozszerzenie **Codex - OpenAI's coding agent** wydane przez OpenAI. Jego identyfikator w Marketplace to:

```text
openai.chatgpt
```

Możesz też zainstalować je z linii poleceń:

```bash
code --install-extension openai.chatgpt
```

Po instalacji uruchom ponownie lub przeładuj VS Code. Jeśli nie widzisz wejścia do Codex, otwórz paletę poleceń (macOS: `Cmd+Shift+P`, Windows/Linux: `Ctrl+Shift+P`), wyszukaj i uruchom:

```text
Codex: Open Codex Sidebar
```

Domyślnie Codex pojawi się w prawym pasku bocznym VS Code. Możesz też przeciągnąć go z powrotem do lewego paska aktywności.

## Instalacja CLI Codex (do weryfikacji)

Oficjalna dokumentacja wskazuje, że rozszerzenie Codex dla VS Code i CLI Codex korzystają z tej samej warstwy konfiguracji. Aby zweryfikować token API i dostępność modelu przed konfiguracją VS Code, zaleca się zainstalowanie CLI Codex.

Jednym z rekomendowanych sposobów jest instalacja przez npm, wymagająca Node.js w wersji 18 lub wyższej:

```bash
npm install -g @openai/codex
```

Użytkownicy macOS mogą też zainstalować CLI przez Homebrew:

```bash
brew install --cask codex
```

Po instalacji sprawdź w terminalu, czy polecenie jest dostępne:

```bash
codex --version
```

Jeśli chcesz korzystać tylko z rozszerzenia VS Code, możesz pominąć weryfikację CLI; konfiguracja `~/.codex/config.toml` pozostaje ta sama.

## Konfiguracja API Ace Data Cloud

Rozszerzenie Codex dla VS Code i CLI Codex współdzielą plik konfiguracyjny. Domyślnie Codex prosi o zalogowanie się na oficjalne konto OpenAI lub podanie oficjalnego klucza API. Aby korzystać z Ace Data Cloud, musisz skonfigurować token API i plik `~/.codex/config.toml`.

### Krok 1: Ustawienie zmiennej środowiskowej

Zaleca się zapisanie tokenu API w pliku konfiguracyjnym powłoki, np. `~/.zshrc`, `~/.bashrc` lub `~/.bash_profile`:

```bash
export ACEDATACLOUD_API_KEY="{token}"
```

Gdzie `{token}` zastąp swoim tokenem API skopiowanym z konsoli Ace Data Cloud.

Po zapisaniu konfiguracji otwórz terminal ponownie lub wykonaj odpowiednie polecenie `source`, aby zmiana od razu zaczęła działać:

```bash
source ~/.zshrc
```

Jeśli VS Code jest otwarte, uruchom je ponownie lub przeładuj, aby rozszerzenie odczytało nowe zmienne środowiskowe.

### Krok 2: Edycja pliku konfiguracyjnego Codex

Plik konfiguracyjny użytkownika Codex znajduje się pod ścieżką `~/.codex/config.toml`. Jeśli nie istnieje, utwórz go:

```bash
mkdir -p ~/.codex
touch ~/.codex/config.toml
```

Wpisz następującą konfigurację:

```toml
model_provider = "acedatacloud"
model = "gpt-5"
model_reasoning_effort = "high"
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[model_providers.acedatacloud]
name = "Ace Data Cloud"
base_url = "https://api.acedata.cloud/v1"
env_key = "ACEDATACLOUD_API_KEY"
wire_api = "responses"
```

Opis pól:

| Pole | Opis |
| --- | --- |
| `model_provider` | Domyślny dostawca modelu, odpowiadający sekcji `[model_providers.acedatacloud]` poniżej |
| `model` | Domyślny identyfikator modelu |
| `model_reasoning_effort` | Siła wnioskowania, typowe wartości to `low`, `medium`, `high` |
| `approval_policy` | Polityka potwierdzania przed wykonaniem polecenia, zalecane `on-request` do codziennego użytku |
| `sandbox_mode` | Uprawnienia sandbox podczas wykonywania poleceń przez Codex, zalecane `workspace-write` do codziennego rozwoju |
| `base_url` | Adres API kompatybilnego z OpenAI Ace Data Cloud |
| `env_key` | Nazwa zmiennej środowiskowej, z której Codex odczytuje token API |
| `wire_api` | Typ protokołu, przy korzystaniu z OpenAI Responses API musi być `responses` |

Możesz też kliknąć ikonę koła zębatego w prawym górnym rogu rozszerzenia Codex, wybrać **Codex Settings > Open config.toml**, aby otworzyć ten plik bezpośrednio w VS Code.

### Konfiguracja na poziomie projektu

Jeśli chcesz, aby tylko dany projekt korzystał z innej konfiguracji, utwórz plik `.codex/config.toml` w katalogu głównym projektu. Codex najpierw odczyta konfigurację projektu, ale katalog projektu musi być oznaczony jako zaufany, aby załadować konfigurację z `.codex/`.

Przykład:

```toml
model = "gpt-5-mini"
model_reasoning_effort = "medium"
```

Zaleca się przechowywanie tokenów osobistych w zmiennych środowiskowych, a nie w repozytorium projektu. Decyzję o umieszczeniu pliku `.codex/config.toml` na poziomie projektu należy podjąć zgodnie z polityką zespołu.

## Czyszczenie zapisanych danych logowania OpenAI

Jeśli wcześniej logowałeś się w rozszerzeniu Codex na oficjalne konto OpenAI, lokalny stan logowania może być nadal zachowany. Przed przełączeniem na proxy Ace Data Cloud możesz w terminalu wykonać:

```bash
codex logout
```

Jeśli polecenie nie jest dostępne, możesz usunąć lokalny plik cache:

```bash
rm -f ~/.codex/auth.json
```

Następnie uruchom ponownie lub przeładuj VS Code.

## Podstawowe użycie

Po konfiguracji otwórz panel Codex po lewej lub prawej stronie VS Code i wpisz swoje zapytanie. Na przykład:

```text
Wyjaśnij strukturę katalogów bieżącego projektu i wskaż główny plik wejściowy.
```

Rozszerzenie Codex może wykorzystywać pliki i zaznaczony kod w edytorze jako kontekst. Możesz też odwoływać się do plików w polu wejściowym za pomocą `@`, np.:

```text
Odniesienie do @src/App.vue, pomóż rozbić tę stronę na bardziej przejrzyste komponenty.
```

Jeśli zaznaczysz fragment kodu, możesz z palety poleceń uruchomić:

```text
Codex: Add to Codex Thread
```

lub

```text
Codex: Add File to Codex Thread
```

aby dodać cały bieżący plik do kontekstu.

## Zmiana modelu i siły wnioskowania

Rozszerzenie Codex dla VS Code pozwala zmieniać model i poziom reasoning effort pod polem wejściowym. Przy korzystaniu z dostawcy Ace Data Cloud najbezpieczniej jest ustawić domyślny `model` w `~/.codex/config.toml`, a następnie w razie potrzeby zmieniać go w interfejsie. Zalecane domyślne ustawienia:

| Scenariusz | Zalecany model | Siła wnioskowania |
| --- | --- | --- |
| Codzienne czytanie kodu i drobne poprawki | `gpt-5-mini` | `medium` |
| Standardowe zadania programistyczne | `gpt-5` | `high` |
| Złożone refaktoryzacje i głębokie wnioskowanie | `gpt-5.5` lub `gpt-5.5-pro` | `high` |
| Zadania wymagające wzmocnionego wnioskowania | `o3` | `high` |

Jeśli w interfejsie nie ma modelu, którego potrzebujesz, zmodyfikuj pole `model` w `~/.codex/config.toml`, a następnie uruchom ponownie lub przeładuj VS Code. Pełną listę modeli znajdziesz w [dokumentacji usług OpenAI Ace Data Cloud](https://platform.acedata.cloud/documents/openai).

## Wybór trybu pracy

Rozszerzenie Codex obsługuje różne tryby pracy. Najczęstsze to:

| Tryb | Zastosowanie |
| --- | --- |
| `Chat` | Tylko dyskusja, wyjaśnianie kodu, planowanie, bez bezpośrednich zmian w plikach |
| `Agent` | Codzienne programowanie: czytanie plików, modyfikacje kodu, uruchamianie potrzebnych poleceń |
| `Agent (Full Access)` | Pełne uprawnienia i dostęp do sieci, do stosowania, gdy znasz ryzyko |

Zaleca się używanie trybu `Agent` z ustawieniem `approval_policy = "on-request"`. Wtedy Codex poprosi o potwierdzenie przed wykonaniem wrażliwych poleceń, dostępu poza workspace lub do sieci.

## Weryfikacja konfiguracji

Możesz najpierw zweryfikować działanie Codex przez Ace Data Cloud w terminalu, używając tej samej konfiguracji:

```bash
codex exec --model gpt-5-mini "Reply with exactly: ADC_Codex_OK"
```

Jeśli konfiguracja jest poprawna, otrzymasz odpowiedź:

```text
ADC_Codex_OK
```

Następnie wróć do VS Code, otwórz panel Codex i wpisz proste pytanie:

```text
Opisz w jednym zdaniu przeznaczenie bieżącego workspace.
```

Możesz też sprawdzić historię zapytań i szczegóły rozliczeń na [Ace Data Cloud konsoli - Historia użycia](https://platform.acedata.cloud/console/usages) oraz dostępny limit na [Ace Data Cloud konsoli - Lista aplikacji](https://platform.acedata.cloud/console/applications).

## Jak to działa

Rozszerzenie Codex dla VS Code nie posiada oddzielnej konfiguracji modelu. Używa lokalnego CLI Codex i współdzieli konfigurację:

1. Rozszerzenie VS Code uruchamia Codex i odczytuje użytkownikowy plik `~/.codex/config.toml`.
2. Jeśli projekt jest zaufany i zawiera `.codex/config.toml`, ładowana jest konfiguracja projektowa.
3. Gdy `model_provider` wskazuje na `acedatacloud`, Codex pobiera token API z `ACEDATACLOUD_API_KEY`.
4. Żądania są wysyłane zgodnie z protokołem OpenAI Responses do `https://api.acedata.cloud/v1/responses`.
5. Ace Data Cloud weryfikuje tożsamość, sprawdza limity, przekazuje żądania i rejestruje użycie.

Dlatego konfiguracja w terminalu i w rozszerzeniu VS Code jest zwykle jednokrotna. Po pomyślnej weryfikacji w terminalu rozszerzenie użyje tej samej konfiguracji.
