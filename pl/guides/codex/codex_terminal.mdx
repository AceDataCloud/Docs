Codex CLI to otwartoźródłowy lokalny agent programistyczny stworzony przez OpenAI, działający w Twoim terminalu. Potrafi czytać kod, modyfikować pliki, wykonywać polecenia, wyjaśniać błędy i pomagać w codziennych zadaniach programistycznych.

Codex CLI obsługuje niestandardowych dostawców modeli. Możesz korzystać z niego za pośrednictwem kompatybilnego proxy OpenAI Responses dostarczanego przez Ace Data Cloud, bez konieczności osobnej subskrypcji oficjalnego konta OpenAI. Po konfiguracji Codex CLI wysyła zapytania do `https://api.acedata.cloud/v1`.

## Proces rejestracji

Aby korzystać z Codex CLI, najpierw odwiedź [konsolę Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API na zapas.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany do strony logowania, gdzie możesz się zarejestrować i zalogować. Po zalogowaniu zostaniesz automatycznie przeniesiony z powrotem na tę stronę.

Przy pierwszym wniosku otrzymasz darmowy limit, dzięki czemu możesz bezpłatnie wypróbować usługę Codex CLI.

## Instalacja Codex CLI

Codex CLI obsługuje macOS, Linux, Windows oraz WSL. Możesz zainstalować go przez npm lub użyć Homebrew (tylko macOS).

### Instalacja przez npm (zalecane)

Jeśli masz już zainstalowany Node.js, możesz zainstalować go bezpośrednio przez npm. Wymaga to Node.js w wersji 18 lub wyższej.

```bash
npm install -g @openai/codex
```

### Instalacja przez Homebrew (macOS)

Użytkownicy macOS mogą również zainstalować Codex CLI przez Homebrew:

```bash
brew install --cask codex
```

### Sprawdzenie instalacji

Po instalacji otwórz ponownie terminal i sprawdź, czy polecenie jest dostępne:

```bash
codex --version
```

Jeśli pojawi się komunikat `command not found`, oznacza to zwykle, że terminal nie załadował nowej ścieżki PATH. Zamknij i otwórz terminal ponownie lub sprawdź konfigurację PATH podaną w komunikacie instalacyjnym.

## Konfiguracja Codex CLI

Po instalacji Codex CLI domyślnie próbuje łączyć się z oficjalną usługą OpenAI. Aby użyć Ace Data Cloud, musisz zadeklarować niestandardowego `model_provider` w pliku konfiguracyjnym Codex oraz umieścić token API w odpowiedniej zmiennej środowiskowej.

### Krok pierwszy: ustawienie zmiennej środowiskowej

Zaleca się zapisanie tokena API w pliku konfiguracyjnym powłoki, np. `~/.zshrc`, `~/.bashrc` lub `~/.bash_profile`:

```bash
export ACEDATACLOUD_API_KEY="{token}"
```

Zamień `{token}` na token API skopiowany z konsoli Ace Data Cloud.

Po konfiguracji otwórz terminal ponownie lub wykonaj odpowiednie polecenie `source`, aby zmiany od razu weszły w życie:

```bash
source ~/.zshrc
```

### Krok drugi: edycja pliku konfiguracyjnego Codex

Codex CLI używa pliku globalnej konfiguracji `~/.codex/config.toml`. Jeśli plik nie istnieje, utwórz go:

```bash
mkdir -p ~/.codex
touch ~/.codex/config.toml
```

Wklej poniższą zawartość do `~/.codex/config.toml`:

```toml
model_provider = "acedatacloud"
model = "gpt-5"
model_reasoning_effort = "high"

[model_providers.acedatacloud]
name = "Ace Data Cloud"
base_url = "https://api.acedata.cloud/v1"
env_key = "ACEDATACLOUD_API_KEY"
wire_api = "responses"
```

Opis pól:

| Pole | Opis |
| --- | --- |
| `model_provider` | Nazwa domyślnego dostawcy, odpowiada kluczowi w sekcji `[model_providers.<name>]` |
| `model` | Domyślny identyfikator modelu |
| `model_reasoning_effort` | Siła wnioskowania, typowe wartości to `low`, `medium`, `high` |
| `[model_providers.acedatacloud].base_url` | Adres proxy OpenAI Responses Ace Data Cloud |
| `[model_providers.acedatacloud].env_key` | Nazwa zmiennej środowiskowej, z której Codex CLI odczytuje token API |
| `[model_providers.acedatacloud].wire_api` | Typ protokołu, dla OpenAI Responses musi być `responses` |

### Czyszczenie zapisanych danych logowania OpenAI

Jeśli wcześniej logowałeś się do Codex CLI oficjalnym kontem OpenAI, lokalnie mogą być zapisane dane logowania (zwykle w `~/.codex/auth.json`). Przed przełączeniem na proxy Ace Data Cloud zaleca się usunięcie tych danych:

```bash
codex logout
```

Jeśli polecenie `codex logout` nie jest dostępne, możesz ręcznie usunąć plik:

```bash
rm -f ~/.codex/auth.json
```

Jeśli nigdy nie logowałeś się oficjalnym kontem OpenAI, możesz pominąć ten krok.

### Uruchomienie sesji

Przejdź do katalogu swojego projektu i uruchom Codex CLI:

```bash
cd /path/to/your/project
codex
```

Po pojawieniu się interfejsu Codex możesz wpisywać zapytania, np.:

```text
Wyjaśnij strukturę katalogów tego projektu
```

### Weryfikacja konfiguracji

Po wejściu do Codex CLI możesz sprawdzić aktualny model i dostawcę:

```text
/model
```

Powinieneś zobaczyć, że model pochodzi od dostawcy `acedatacloud`, np.:

```text
Model: gpt-5
Provider: acedatacloud
```

Jeśli dostawca nie jest `acedatacloud`, oznacza to, że konfiguracja nie została zastosowana. Sprawdź, czy plik `~/.codex/config.toml` został poprawnie zapisany oraz czy zmienna `ACEDATACLOUD_API_KEY` jest dostępna w bieżącym terminalu:

```bash
echo $ACEDATACLOUD_API_KEY
```

Możesz również sprawdzić historię użycia i szczegóły rozliczeń w [konsoli Ace Data Cloud - Historia użycia](https://platform.acedata.cloud/console/usages) oraz pozostały limit w [konsoli Ace Data Cloud - Lista aplikacji](https://platform.acedata.cloud/console/applications).

## Jak to działa

Codex CLI natywnie korzysta z protokołu OpenAI Responses API. Ace Data Cloud udostępnia kompatybilne proxy pod adresem `https://api.acedata.cloud/v1/responses`, więc Codex CLI nie wymaga lokalnego proxy ani dodatkowych wtyczek.

Proces działania:

1. Codex CLI odczytuje `model_provider` z `~/.codex/config.toml` i ładuje odpowiadającą sekcję `[model_providers.acedatacloud]`.
2. Codex CLI pobiera token API ze zmiennej środowiskowej wskazanej przez `env_key` (czyli `ACEDATACLOUD_API_KEY`).
3. Zapytania wysyłane są protokołem `wire_api = "responses"` na adres `base_url + /responses`, czyli `https://api.acedata.cloud/v1/responses`.
4. Ace Data Cloud weryfikuje token API, sprawdza limit i przekazuje zapytanie do dostępnego kanału modelu.
5. Po zakończeniu zapytania platforma rejestruje zużycie i odejmuje odpowiednią ilość z limitu.

Oznacza to, że nadal korzystasz z oryginalnego polecenia `codex` i natywnego interfejsu Codex CLI, ale z usługą modelu działającą przez Ace Data Cloud.

## Konfiguracja modelu

Pole `model` w `~/.codex/config.toml` określa domyślny model używany przez Codex. Usługa OpenAI Responses Ace Data Cloud obsługuje wiele modeli, najczęściej używane to:

| Model | Opis |
| --- | --- |
| `gpt-5` | Zalecany model domyślny, odpowiedni do większości zadań kodowania |
| `gpt-5-mini` | Lżejszy, szybszy, do prostych zadań |
| `gpt-5.5` | Nowsza wersja, bardziej zaawansowana |
| `gpt-5.5-pro` | Wersja rozszerzona, do złożonych zadań wnioskowania |
| `gpt-4.1` | Poprzednia główna wersja modelu |
| `o3` | Model z wzmocnionym wnioskowaniem, do zadań wymagających głębokiego rozumowania |
| `o4-mini-high-all` | Lekki model do wnioskowania |

Jeśli chcesz tymczasowo zmienić model, możesz podać go jako parametr przy uruchamianiu Codex:

```bash
codex --model gpt-5-mini
```

Możesz też bezpośrednio zmodyfikować pole `model` w `~/.codex/config.toml` i ponownie uruchomić program. Pełną listę modeli znajdziesz w [dokumentacji usługi OpenAI Ace Data Cloud](https://platform.acedata.cloud/documents/openai).

## Poziomy zaufania projektów

Codex CLI pozwala ustawić różne poziomy zaufania dla poszczególnych projektów, kontrolując, jakie operacje agent może wykonywać. Możesz dodać na końcu `~/.codex/config.toml`:

```toml
[projects."/path/to/trusted/project"]
trust_level = "trusted"

[projects."/path/to/untrusted/project"]
trust_level = "untrusted"
```

Znaczenie:

- `trusted`: Agent ma pełne uprawnienia, może wykonywać polecenia i modyfikować pliki.
- `untrusted`: Agent ma ograniczone uprawnienia, odpowiednie dla projektów, których nie znasz dobrze.
