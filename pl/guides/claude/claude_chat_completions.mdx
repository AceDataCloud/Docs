Anthropic Claude to bardzo potężny system konwersacyjny AI, który wystarczy zasilić poleceniem, aby w ciągu zaledwie kilku sekund wygenerował płynną i naturalną odpowiedź. Claude wyróżnia się w branży doskonałymi możliwościami rozumienia i generowania języka, a obecnie jest już szeroko stosowany w różnych branżach i dziedzinach, a jego wpływ staje się coraz bardziej znaczący. Niezależnie od tego, czy chodzi o codzienne rozmowy, kreatywne pisanie, czy profesjonalne konsultacje i programowanie kodu, Claude może zapewnić zachwycające inteligentne wsparcie, znacznie zwiększając wydajność pracy i kreatywność ludzi.

Ten dokument przedstawia głównie proces korzystania z operacji Claude Chat Completion API, dzięki któremu możemy łatwo korzystać z funkcji rozmów oficjalnego Claude.

## Proces składania wniosku

Aby korzystać z Claude Chat Completion API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany ani zarejestrowany, nastąpi automatyczne przekierowanie na stronę logowania, która zaprosi Cię do rejestracji i logowania, a po zakończeniu automatycznie powrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności składania osobnego wniosku dla każdej usługi.** Przy pierwszym wniosku otrzymasz darmowy limit, który pozwala na bezpłatne wypróbowanie; gdy limit jest niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Podstawowe użycie

Następnie możesz wypełnić odpowiednią zawartość w interfejsie, jak pokazano na ilustracji:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Przy pierwszym użyciu tego interfejsu musimy wypełnić co najmniej trzy elementy. Jednym z nich jest `authorization`, który można bezpośrednio wybrać z listy rozwijanej. Kolejnym parametrem jest `model`, można wybrać publicznie dostępne modele, takie jak `claude-opus-5-5`, `claude-fable-5-1` itd.; poprzedni `claude-fable-5` nadal może być wywoływany. Ostatnim parametrem jest `messages`, jest to tablica poleceń, a każdy element zawiera `role` i `content`; `role` obsługuje `user`, `assistant`, `system`, zaś `content` stanowi konkretną treść. Gdy potrzebne są kompletne bloki treści rozumowania Claude, podpisy i natywna semantyka narzędzi, nadal należy korzystać z Messages API.

Jednocześnie możesz zauważyć, że po prawej stronie generowany jest odpowiedni kod wywołania. Możesz skopiować kod i uruchomić go bezpośrednio albo kliknąć przycisk „Try”, aby przeprowadzić test.

Często używane opcjonalne parametry:

- `max_tokens`: ogranicza maksymalną liczbę tokenów w pojedynczej odpowiedzi.
- `temperature`: losowość generowania, od 0 do 2, im większa wartość, tym bardziej rozbieżny wynik.
- `n`: ile kandydatów odpowiedzi generować jednocześnie.
- `response_format`: ustawienie formatu zwracanego wyniku.

`claude-opus-5-5` obsługuje zwykłe i strumieniowe Chat Completions; ten model zezwala tylko na `n=1`. Nie ustawiaj dla niego `temperature` niższego niż 1 ani niestandardowego `top_p`; do wywoływania narzędzi używaj `tool_choice: "auto"` i nie wymuszaj określonego narzędzia. Interfejs kompatybilny z Chat nie zwraca natywnych bloków treści rozumowania.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Po wywołaniu zauważamy, że zwracany wynik jest następujący:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }

```

Zwracany wynik zawiera wiele pól, które przedstawiono poniżej:

- `id`, ID wygenerowanego zadania rozmowy, używane do jednoznacznej identyfikacji tego zadania rozmowy.
- `model `, wybrany model Claude z oficjalnej strony.
- `choices`, informacje o odpowiedzi udzielonej przez Claude na polecenie.
- `usage `: informacje statystyczne o tokenach dla tej sesji pytań i odpowiedzi.

W formacie Chat Completions `usage.prompt_tokens` oznacza całkowitą liczbę danych wejściowych; `prompt_tokens_details.cached_tokens` i `prompt_tokens_details.cache_write_tokens` rejestrują odpowiednio szczegóły odczytu i zapisu pamięci podręcznej. `completion_tokens_details.reasoning_tokens` jest podzbiorem `completion_tokens`, dlatego podczas obliczania całości lub kosztu nie należy dodawać go ponownie. Odpowiedzi niestrumieniowe mogą również zwracać obiekt `usage.cost`, gdzie `amount` oznacza rzeczywiste zużycie limitu, `currency` jest jednostką rozliczeniową, a `list_amount` jest kwotą przed rabatem (jeśli występuje).

Nazwa pola w wersji kompatybilnej z Chat to `reasoning_tokens`; natywne Messages API używa `output_tokens_details.thinking_tokens`. Schematy wire obu protokołów są różne, dlatego klient nie powinien mieszać nazw pól.

Wśród nich `choices` zawiera informacje o odpowiedzi Claude, a znajdujące się w nim `choices` to szczegółowe informacje o odpowiedzi Claude, co można zobaczyć na ilustracji.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Można zauważyć, że pole `content` w `choices` zawiera konkretną treść odpowiedzi Claude.

## Odpowiedź strumieniowa

Ten interfejs obsługuje również odpowiedzi strumieniowe, co jest bardzo przydatne przy integracji ze stronami internetowymi i może umożliwić efekt wyświetlania tekstu znak po znaku.

Jeśli chcesz zwracać odpowiedź strumieniowo, możesz zmienić parametr `stream ` w nagłówku żądania na `true`.

Modyfikacja została pokazana na ilustracji, jednak kod wywołania wymaga odpowiednich zmian, aby obsługiwać odpowiedź strumieniową.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

Po zmianie `stream` na `true` API będzie zwracać odpowiednie dane JSON wiersz po wierszu, a na poziomie kodu musimy wprowadzić odpowiednie zmiany, aby uzyskać wynik wiersz po wierszu.

Przykładowy kod wywołania w Pythonie:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Głębokie rozumowanie
Modele Claude nowej generacji mogą przeprowadzać rozumowanie zgodnie z domyślną strategią modelu, bez konieczności wywoływania go przez sufiks modelu `-thinking`. Odpowiedzi zgodne z Chat używają pola usage kompatybilnego z OpenAI: `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` są już zawarte w `completion_tokens`, nie dodawaj ich ponownie. Rozumowanie i widoczna treść współdzielą limit tokenów wyjściowych, dlatego przy małym `max_tokens` treść może być pusta lub obcięta; w takim przypadku zwiększ budżet wyjściowy lub, jeśli używany model to obsługuje, wybierz mniejszy nakład rozumowania.

Jeśli potrzebujesz natywnego `thinking`, `output_config.effort`, bloków treści thinking oraz zwracania podpisów, użyj `/v1/messages`. Odpowiadające Messages pole usage to `output_tokens_details.thinking_tokens`, nie mieszaj go z `completion_tokens_details.reasoning_tokens` z Chat-compatible.

## Modele wizualne

claude-sonnet-4-20250514 to multimodalny duży model językowy opracowany przez Claude, który na bazie claude-4 zwiększa możliwości rozumienia obrazu. Model ten może jednocześnie przetwarzać dane wejściowe w postaci tekstu i obrazów, realizując rozumienie i generowanie między modalnościami.

Przetwarzanie tekstu przy użyciu modelu claude-sonnet-4-20250514 jest zgodne z podstawowymi zasadami użycia opisanymi powyżej, poniżej krótko przedstawimy sposób użycia możliwości przetwarzania obrazów przez model.

Możliwość przetwarzania obrazów przez model claude-sonnet-4-20250514 jest realizowana głównie poprzez dodanie pola `type` do istniejącej zawartości `content`; za pomocą tego pola można określić, czy przesyłany jest tekst, czy obraz, a tym samym korzystać z możliwości przetwarzania obrazów modelu claude-sonnet-4-20250514. Poniżej opisano głównie dwa sposoby wywołania tej funkcji: za pomocą Curl i Python.

- Sposób skryptu Curl

```
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "claude-sonnet-4-20250514",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "What'\''s in this image?"
          },
          {
            "type": "image_url",
            "image_url": {
              "url": "https://cdn.acedata.cloud/ueugot.png"
            }
          }
        ]
      }
    ]
  }'
```

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informację. Na przykład:

- `400 token_mismatched`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`: Wewnętrzny błąd serwera, coś poszło nie tak po stronie serwera.
