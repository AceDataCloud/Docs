Anthropic Claude to bardzo potężny system konwersacyjny AI, który wystarczy zasilić promptem, aby w zaledwie kilka sekund wygenerował płynną i naturalną odpowiedź. Claude wyróżnia się w branży doskonałymi możliwościami rozumienia i generowania języka, a obecnie jest już szeroko stosowany w różnych branżach i dziedzinach, a jego wpływ staje się coraz bardziej znaczący. Niezależnie od tego, czy chodzi o codzienne rozmowy, kreatywne pisanie, profesjonalne konsultacje czy programowanie kodu, Claude może zapewnić zachwycającą inteligentną pomoc, znacznie zwiększając efektywność pracy i kreatywność ludzi.

Ten dokument przedstawia głównie proces korzystania z operacji Claude Chat Completion API, dzięki któremu możemy łatwo korzystać z funkcji konwersacji oficjalnego Claude.

## Proces składania wniosku

Aby korzystać z Claude Chat Completion API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i logowania, a po zakończeniu automatycznie wrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez potrzeby osobnego składania wniosku dla każdej usługi.** Przy pierwszym wniosku otrzymasz darmowy limit, który pozwala na bezpłatne wypróbowanie; gdy limit jest niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Podstawowe użycie

Następnie możesz wypełnić odpowiednią zawartość w interfejsie, jak pokazano na ilustracji:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Przy pierwszym użyciu tego interfejsu musimy wypełnić co najmniej trzy elementy. Jeden z nich to `authorization`, który można bezpośrednio wybrać z listy rozwijanej. Kolejny parametr to `model`, zalecane jest użycie najnowszego flagowego `claude-fable-5-1`; poprzedni `claude-fable-5` nadal może być wywoływany. Ostatni parametr to `messages`, jest to tablica promptów, każdy element zawiera `role` i `content`; `role` obsługuje `user`, `assistant`, `system`, a `content` to konkretna treść. Claude Fable 5.1 obsługuje kontekst 1 miliona Tokenów i maksymalny wynik 128K Tokenów.

Jednocześnie możesz zauważyć, że po prawej stronie generowany jest odpowiedni kod wywołania; możesz skopiować kod i uruchomić go bezpośrednio, a także bezpośrednio kliknąć przycisk „Try”, aby przeprowadzić test.

Często używane opcjonalne parametry:

- `max_tokens`: ogranicza maksymalną liczbę tokenów w pojedynczej odpowiedzi.
- `temperature`: losowość generowania, między 0 a 2, im większa wartość, tym bardziej rozbieżny wynik.
- `n`: ile kandydatów odpowiedzi wygenerować jednorazowo.
- `response_format`: ustawienie formatu zwracanego wyniku.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Po wywołaniu stwierdzamy, że zwracany wynik jest następujący:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }

```

Zwracany wynik zawiera wiele pól, których opis jest następujący:

- `id`, ID wygenerowanego zadania tej konwersacji, używane do jednoznacznego identyfikowania tego zadania konwersacji.
- `model `, wybrany model Claude z oficjalnej strony.
- `choices`, informacje o odpowiedzi udzielonej przez Claude na prompt.
- `usage `: informacje statystyczne dotyczące tokenów dla tej sesji pytań i odpowiedzi.

W formacie Chat Completions `usage.prompt_tokens` to całkowita ilość danych wejściowych; `prompt_tokens_details.cached_tokens` i `prompt_tokens_details.cache_write_tokens` rejestrują odpowiednio szczegóły odczytu i zapisu pamięci podręcznej. `completion_tokens_details.reasoning_tokens` jest podzbiorem `completion_tokens`; podczas obliczania łącznej liczby lub kosztu nie należy dodawać go ponownie. Odpowiedzi niestrumieniowe mogą również zwracać obiekt `usage.cost`, w którym `amount` oznacza faktyczne zużycie limitu, `currency` jest jednostką rozliczeniową, a `list_amount` jest kwotą przed rabatem (jeśli występuje).

Nazwa pola zgodna z Chat to `reasoning_tokens`; natywny Messages API używa `output_tokens_details.thinking_tokens`. Wire schema obu protokołów jest różny, dlatego klient nie powinien mieszać nazw pól.

Wśród nich `choices` zawiera informacje o odpowiedzi Claude, a `choices` w nim to konkretne informacje o odpowiedzi Claude, co można zobaczyć, jak pokazano na ilustracji.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Można zobaczyć, że pole `content` w `choices` zawiera konkretną treść odpowiedzi Claude.

## Odpowiedź strumieniowa

Ten interfejs obsługuje również odpowiedzi strumieniowe, co jest bardzo przydatne przy integracji ze stroną internetową i pozwala stronie osiągnąć efekt wyświetlania znak po znaku.

Jeśli chcesz zwracać odpowiedź strumieniowo, możesz zmienić parametr `stream ` w nagłówku żądania na `true`.

Modyfikacja jest pokazana na ilustracji, jednak kod wywołania wymaga odpowiednich zmian, aby obsługiwać odpowiedź strumieniową.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

Po zmianie `stream` na `true`, API będzie zwracać odpowiednie dane JSON wiersz po wierszu, a na poziomie kodu musimy wprowadzić odpowiednie modyfikacje, aby uzyskać wyniki wiersz po wierszu.

Przykładowy kod wywołania w Pythonie:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Głębokie rozumowanie
Modele Claude nowej generacji mogą prowadzić rozumowanie zgodnie z domyślną strategią modelu, bez konieczności wyzwalania go przez sufiks modelu `-thinking`. Odpowiedzi zgodne z Chat używają kompatybilnego z OpenAI pola usage `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` jest już zawarte w `completion_tokens`, nie należy ich dodawać ponownie. Rozumowanie i widoczna treść główna współdzielą limit tokenów wyjściowych, dlatego przy małej wartości `max_tokens` treść główna może być pusta lub obcięta; w takim przypadku należy zwiększyć budżet wyjściowy lub, jeśli używany model to obsługuje, wybrać niższy nakład rozumowania.

Jeśli potrzebne są natywne `thinking`, `output_config.effort`, bloki treści thinking oraz zwrot podpisów, należy użyć `/v1/messages`. Odpowiadające Messages pole usage to `output_tokens_details.thinking_tokens`, nie należy mieszać go z `completion_tokens_details.reasoning_tokens` dla Chat-compatible.

## Modele wizyjne

claude-sonnet-4-20250514 to multimodalny duży model językowy opracowany przez Claude, który na bazie claude-4 zwiększa możliwości rozumienia obrazu. Model ten może jednocześnie przetwarzać wejścia tekstowe i obrazowe, realizując rozumienie i generowanie między modalnościami.

Przetwarzanie tekstu przy użyciu modelu claude-sonnet-4-20250514 jest zgodne z podstawowym sposobem użycia opisanym powyżej, poniżej zostanie krótko przedstawione, jak używać możliwości przetwarzania obrazu przez model.

Możliwość przetwarzania obrazu przez model claude-sonnet-4-20250514 jest realizowana głównie poprzez dodanie pola `type` do pierwotnej zawartości `content`; dzięki temu polu można określić, czy przesyłany jest tekst czy obraz, a następnie użyć możliwości przetwarzania obrazu modelu claude-sonnet-4-20250514. Poniżej opisano głównie wywołanie tej funkcji na dwa sposoby: za pomocą Curl i Python.

- Metoda skryptu Curl

```

-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "claude-sonnet-4-20250514",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "What'\''s in this image?"
          },
          {
            "type": "image_url",
            "image_url": {
              "url": "https://cdn.acedata.cloud/ueugot.png"
            }
          }
        ]
      }
    ]
  }'
```

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`：Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`：Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`：Wewnętrzny błąd serwera, coś poszło nie tak po stronie serwera.
