Anthropic Claude to bardzo potężny system konwersacyjny AI, który wystarczy zasilić promptem, aby w zaledwie kilka sekund wygenerował płynną i naturalną odpowiedź. Claude wyróżnia się w branży swoimi doskonałymi możliwościami rozumienia i generowania języka, a obecnie jest już szeroko stosowany w różnych branżach i dziedzinach, a jego wpływ staje się coraz bardziej znaczący. Niezależnie od tego, czy chodzi o codzienne rozmowy, kreatywne pisanie, czy profesjonalne konsultacje i programowanie kodu, Claude może zapewnić zachwycającą inteligentną pomoc, znacznie zwiększając wydajność pracy i kreatywność ludzi.

Ten dokument przedstawia głównie proces korzystania z operacji Claude Chat Completion API, za pomocą którego możemy łatwo używać funkcji konwersacyjnych oficjalnego Claude.

## Claude Fable 5.2

Użyj pełnej nazwy modelu `claude-fable-5-2`. Ten model nadaje się do złożonego rozumowania i zadań długoterminowych; gdy wymagane są natywne bloki treści rozumowania i interakcje z narzędziami, preferuj Messages. Adaptacyjne rozumowanie jest stale włączone, pomiń `temperature`, `top_p`, `top_k`, dla wyboru narzędzi użyj `auto`, nie wymuszaj określonego narzędzia. `max_tokens` obejmuje jednocześnie rozumowanie i tekst końcowy. Obecnie dla tego modelu nie są dostępne interfejsy Responses i Count Tokens.

W przeliczeniu według obecnego maksymalnego pakietu (142,800 Credits／$13,584), zwykłe wejście Fable 5.2 kosztuje $3.20, a wyjście $16／milion tokenów; odczyt z pamięci podręcznej kosztuje $0.08, a zapis do pamięci podręcznej na 5 minut／1 godzinę kosztuje odpowiednio $4／$6.40／milion tokenów. Powyższe ceny stanowią 40% standardowej ceny jednostkowej oficjalnego API (60% taniej); w przypadku innych pakietów oraz dodatkowych rabatów dla kont należy kierować się stroną cen modeli i rozliczeniem.

## Proces składania wniosku

Aby korzystać z Claude Chat Completion API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany ani zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i logowania, a po zakończeniu automatycznie powrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności składania osobnego wniosku dla każdej usługi.** Przy pierwszym wniosku otrzymasz bezpłatny limit, który pozwala na darmowe wypróbowanie; gdy limit jest niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

## Podstawowe użycie

Następnie możesz wypełnić odpowiednią treść w interfejsie, jak pokazano na rysunku:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Przy pierwszym użyciu tego interfejsu musimy wypełnić co najmniej trzy elementy: jednym z nich jest `authorization`, który można wybrać bezpośrednio z listy rozwijanej. Kolejnym parametrem jest `model`, można wybrać publicznie dostępne modele, takie jak `claude-opus-5-5`, `claude-fable-5-1`; wcześniejszy `claude-fable-5` nadal może być wywoływany. Ostatnim parametrem jest `messages`, jest to tablica promptów, gdzie każdy element zawiera `role` i `content`; `role` obsługuje `user`, `assistant`, `system`, a `content` jest konkretną treścią. Gdy wymagane są pełne bloki treści rozumowania Claude, podpisy i natywna semantyka narzędzi, nadal używaj Messages API.

Jednocześnie możesz zauważyć, że po prawej stronie znajduje się generowany odpowiedni kod wywołania, możesz skopiować kod i uruchomić go bezpośrednio, możesz też bezpośrednio kliknąć przycisk „Try”, aby przeprowadzić test.

Często używane opcjonalne parametry:

- `max_tokens`: ogranicza maksymalną liczbę tokenów pojedynczej odpowiedzi.
- `temperature`: losowość generowania, od 0 do 2, im większa wartość, tym bardziej rozbieżny wynik.
- `n`: ile kandydujących odpowiedzi wygenerować jednorazowo.
- `response_format`: ustawienie formatu zwracanego wyniku.

`claude-opus-5-5` obsługuje zwykłe i strumieniowe Chat Completions; ten model pozwala tylko na `n=1`. Nie ustawiaj dla niego `temperature` niższego niż 1 ani niestandardowego `top_p`, do wywoływania narzędzi użyj `tool_choice: "auto"`, nie wymuszaj określonego narzędzia. Interfejs kompatybilny z Chat nie zwróci natywnych bloków treści rozumowania.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Po wywołaniu zauważamy, że zwrócony wynik jest następujący:

```json

    {
      "index": 0,

        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },

    }
  ],
  "usage": {
    "prompt_tokens": 8,

    "total_tokens": 20,
    "prompt_tokens_details": {

      "cache_write_tokens": 0
    },

      "reasoning_tokens": 0
    }

```

Zwrócony wynik zawiera wiele pól, których opis jest następujący:

- `id`, ID wygenerowanego zadania konwersacyjnego, używane do unikalnej identyfikacji tego zadania konwersacyjnego.
- `model `, wybrany model Claude z oficjalnej strony.
- `choices`, informacje o odpowiedzi udzielonej przez Claude na prompt.
- `usage `: informacje statystyczne o tokenach dla tej pary pytanie-odpowiedź.

W formacie Chat Completions `usage.prompt_tokens` oznacza całkowitą ilość wejścia; `prompt_tokens_details.cached_tokens` i `prompt_tokens_details.cache_write_tokens` rejestrują odpowiednio szczegóły odczytu i zapisu pamięci podręcznej. `completion_tokens_details.reasoning_tokens` jest podzbiorem `completion_tokens`, nie dodawaj go ponownie podczas obliczania całości lub kosztu. Odpowiedzi niestrumieniowe mogą również zwracać obiekt `usage.cost`, gdzie `amount` to rzeczywiste zużycie limitu, `currency` to jednostka miary, a `list_amount` to kwota przed rabatem (jeśli występuje).

Nazwa pola Chat-compatible to `reasoning_tokens`; natywne Messages API używa `output_tokens_details.thinking_tokens`. Schematy wire obu protokołów są różne, klient nie powinien mieszać nazw pól.

Wśród nich `choices` zawiera informacje o odpowiedzi Claude, a znajdujące się w nim `choices` to szczegółowe informacje o odpowiedzi Claude, co można zobaczyć jak na rysunku.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Można zobaczyć, że pole `content` w `choices` zawiera konkretną treść odpowiedzi Claude.

## Odpowiedź strumieniowa

Ten interfejs również obsługuje odpowiedzi strumieniowe, co jest bardzo przydatne przy integracji ze stronami internetowymi i może umożliwić stronie efekt wyświetlania znak po znaku.

Jeśli chcesz zwracać odpowiedź strumieniowo, możesz zmienić parametr `stream ` w nagłówku żądania na `true`.

Modyfikacja jest pokazana na rysunku, jednak kod wywołania wymaga odpowiednich zmian, aby obsługiwać odpowiedź strumieniową.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>
Po zmianie `stream` na `true` API będzie zwracać odpowiednie dane JSON wiersz po wierszu, a na poziomie kodu musimy wprowadzić odpowiednie zmiany, aby uzyskać wyniki wiersz po wierszu.

Przykładowy kod wywołania w Pythonie:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Głębokie myślenie

Modele Claude nowej generacji mogą przeprowadzać rozumowanie zgodnie z domyślną strategią modelu, bez konieczności wyzwalania go za pomocą sufiksu modelu `-thinking`. Odpowiedzi zgodne z Chat używają zgodnego z OpenAI pola usage `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` jest już zawarte w `completion_tokens`, nie dodawaj go ponownie. Rozumowanie i widoczna treść główna współdzielą limit tokenów wyjściowych, dlatego przy małej wartości `max_tokens` treść główna może być pusta lub obcięta; w takiej sytuacji zwiększ budżet wyjściowy albo, jeśli używany model to obsługuje, wybierz niższy poziom nakładu na rozumowanie.

Jeśli potrzebujesz natywnego `thinking`, `output_config.effort`, bloków treści thinking oraz zwracania podpisów, użyj `/v1/messages`. Odpowiadające Messages pole usage to `output_tokens_details.thinking_tokens`; nie mieszaj go z `completion_tokens_details.reasoning_tokens` z Chat-compatible.

## Model wizualny

claude-sonnet-4-20250514 to multimodalny duży model językowy opracowany przez Claude, który na bazie claude-4 dodaje zdolność rozumienia obrazu. Model ten może jednocześnie przetwarzać wejścia tekstowe i obrazowe, realizując rozumienie i generowanie między modalnościami.

Przetwarzanie tekstu przy użyciu modelu claude-sonnet-4-20250514 jest zgodne z opisem podstawowego użycia powyżej, a poniżej krótko przedstawiono sposób korzystania ze zdolności modelu do przetwarzania obrazów.

Korzystanie ze zdolności przetwarzania obrazów modelu claude-sonnet-4-20250514 polega głównie na dodaniu pola `type` do istniejącej treści `content`; za pomocą tego pola można określić, czy przesyłany jest tekst, czy obraz, a następnie użyć zdolności przetwarzania obrazów modelu claude-sonnet-4-20250514. Poniżej opisano głównie wywoływanie tej funkcji na dwa sposoby: za pomocą Curl i Python.

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`：Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`：Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`：Wewnętrzny błąd serwera, coś poszło nie tak po stronie serwera.
