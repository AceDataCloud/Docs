Ten interfejs oparty jest na [oficjalnym API Model Fish Audio](https://docs.fish.audio/resources/api-reference/model) i służy do **tworzenia nowego klonu brzmienia na podstawie próbki audio**. Adres to `POST https://api.acedata.cloud/fish/model`.

> Aby przeszukiwać istniejące brzmienia, zapoznaj się z [Fish Model Query API](https://platform.acedata.cloud/documents/fish-model-query); aby wyszukać szczegóły pojedynczego brzmienia według `_id`, zapoznaj się z [Fish Model Get API](https://platform.acedata.cloud/documents/fish-model-get).

## Proces aplikacji

Aby korzystać z Fish Model API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API, który należy zachować na przyszłość.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować, a po zakończeniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

**Jeden token API wystarczy do korzystania ze wszystkich usług platformy, nie ma potrzeby składania osobnych wniosków dla każdej usługi.** Pierwsze zgłoszenie otrzyma darmowy limit, aby móc skorzystać z doświadczenia; w przypadku niewystarczającego limitu można doładować saldo ogólne w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Fish Model API →](https://platform.acedata.cloud/services/fish)

## Pola ciała żądania

| Pole                     | Typ      | Wymagane | Opis                                                                            |
| ----------------------- | -------- | -------- | ------------------------------------------------------------------------------- |
| `title`                 | string   | Tak      | Nazwa brzmienia, używana do identyfikacji w liście w konsoli.                  |
| `voices`                | string   | Tak      | URL HTTP(S) próbki audio (**pojedynczy ciąg**, nie tablica). Ten interfejs nie obsługuje przesyłania multipart/binary, proszę najpierw umieścić audio w dowolnym publicznie dostępnym magazynie obiektów. |
| `description`           | string   | Nie      | Opis brzmienia.                                                                  |
| `cover_image`           | string   | Nie      | URL HTTP(S) do obrazu okładki.                                                |
| `tags`                  | string[] | Nie      | Tagów do przeszukiwania w bibliotece publicznej, na przykład `["male","narration","zh"]`. |
| `texts`                 | string[] | Nie      | Odpowiednie teksty referencyjne dla próbki (do korekty wymowy).                |
| `enhance_audio_quality` | boolean  | Nie      | Czy przed treningiem poprawić jakość próbki.                                   |
| `generate_sample`       | boolean  | Nie      | Czy po zakończeniu treningu automatycznie wygenerować próbkę audio.            |

> Pola są zgodne z danymi upstream, proszę również zapoznać się z [oficjalną dokumentacją Fish](https://docs.fish.audio/resources/api-reference/model).

## Przykład: Utwórz prywatny klon brzmienia

```shell
curl -X POST 'https://api.acedata.cloud/fish/model' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "title": "Moje klonowane brzmienie",
    "description": "Klonowane brzmienie w języku chińskim na podstawie nagrania podcastu",
    "voices": "https://example.com/sample-voice.mp3",
    "cover_image": "https://cdn.acedata.cloud/e724d7f13d.png"
  }'
```

> Uwaga: `voices` musi być **ciągiem** (pojedynczy URL audio), a nie tablicą. Przesłanie jako `["..."]` spowoduje odrzucenie przez upstream.

Pomyślna odpowiedź zwraca bezpośrednio obiekt ModelEntity platformy Fish (poniżej przykład minimalnego działającego brzmienia, usunięto niektóre długie pola dla lepszej czytelności):

```json

  "type": "tts",

  "description": "smoke test from api.acedata.cloud",
```

`_id` może być użyty jako wartość pola `reference_id` w późniejszym [Fish TTS API](https://platform.acedata.cloud/documents/fish-tts) do syntezowania mowy przy użyciu tego klonowanego brzmienia:

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "Cześć, to jest fragment mowy wygenerowanej przy użyciu właśnie stworzonego klonowanego brzmienia.",
    "reference_id": "e5c6db52c3ed417f9cb2e5a33fb04667",
    "format": "mp3"
  }'
```

## Wymagania dotyczące próbek

Wartości doświadczenia (zgodne z upstream, można zapoznać się z [oficjalną dokumentacją Fish](https://docs.fish.audio/resources/api-reference/model)):

- Czas trwania zalecany powyżej 30 sekund, najlepiej do 5 minut; powyżej 10 minut marginalne korzyści są niewielkie.
- Częstotliwość próbkowania 16 kHz i wyższa, mono lub stereo.
- Treść powinna być jak najczystsza: bez muzyki w tle, echa, wyraźnych hałasów otoczenia; ten sam mówca.
- Format zalecany to `mp3` / `wav`.

Jeśli nie masz pewności co do jakości próbki, możesz jednocześnie przesłać `enhance_audio_quality: true`, aby upstream najpierw poprawił jakość dźwięku.

## Informacje o opłatach

Tworzenie modelu klonowanego brzmienia (`POST /fish/model`) jest darmowe, nie pobiera się żadnych opłat; interfejsy do przeszukiwania brzmień ([Fish Model Query](https://platform.acedata.cloud/documents/fish-model-query), [Fish Model Get](https://platform.acedata.cloud/documents/fish-model-get)) również nie są płatne. Opłaty powstają tylko podczas późniejszego wywoływania [Fish TTS](https://platform.acedata.cloud/documents/fish-tts) do syntezowania mowy.

## Obsługa błędów

- `400 token_mismatched`: Brakujące lub nieprawidłowe parametry żądania (najczęściej `voices` nie jest URL, lub przesłano jako tablicę).
- `401 invalid_token`: Token autoryzacyjny nie istnieje lub jest nieprawidłowy.
- `429 too_many_requests`: Przekroczenie limitu szybkości konta.
- `500 api_error`: Błąd wewnętrzny serwera.

Przykład odpowiedzi błędu:
```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "głosy są wymagane i muszą być adresem URL HTTP(S) wskazującym na plik audio"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## Wnioski

Aby wywołać to API, wystarczy przygotować publicznie dostępny URL próbki audio, umieścić go w polu `voices`, aby uzyskać `_id`, a następnie podać go jako `reference_id` do `/fish/tts`, co zakończy proces „klonowania → syntezowania”. Częstym problemem jest to, że `voices` musi być ciągiem znaków, a nie tablicą.
