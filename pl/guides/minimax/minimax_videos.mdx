Niniejszy dokument przedstawia integrację i użycie API generowania wideo MiniMax H3. Interfejs ten obsługuje generowanie wideo na podstawie tekstu, kontrolę klatek początkowych i końcowych oraz multimodalne odniesienia do generowania wideo, wykorzystując jednolitą strukturę `content` V2 do tworzenia zadań.

## Proces aplikacji

Aby skorzystać z API generowania wideo MiniMax H3, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API, który należy zachować na przyszłość.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować, a po zakończeniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

**Jeden token API wystarczy do wywołania wszystkich usług platformy, nie ma potrzeby składania osobnych wniosków dla każdej usługi.** Przy pierwszym wniosku przyznawana jest darmowa kwota, aby można było skorzystać z bezpłatnej wersji; w przypadku niewystarczającego salda można doładować saldo ogólne w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [MiniMax H3 API generowania wideo →](https://platform.acedata.cloud/documents/minimax-videos-integration)

Zaleca się zapisanie tokena jako zmiennej środowiskowej, nie wpisując go w kodzie źródłowym ani nie przesyłając do repozytoriów:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Przegląd interfejsu

- **Podstawowy URL**: `https://api.acedata.cloud`
- **Endpoint**: `POST /minimax/videos`
- **Metoda autoryzacji**: W nagłówku HTTP należy przesłać `authorization: Bearer {token}`
- **Nagłówki żądania**:
  - `accept: application/json`
  - `content-type: application/json`
- **Model (model)**: `MiniMax-H3`
- **Struktura wejściowa**: Przesyłaj tekst, obrazy, wideo i dźwięk za pomocą jednolitej struktury `content`
- **Tryb wyjścia**: Domyślnie synchronizuje się, czekając na zakończenie generowania i zwracając pełne `task`; przesyłając `async: true` lub `callback_url`, natychmiast zwraca `task_id` i `trace_id`
- **Zapytanie o wyniki**: Uzyskaj status i gotowy materiał za pomocą [MiniMax H3 API zapytań o zadania](/documents/minimax-tasks-integration)
- **Asynchroniczny callback**: Opcjonalnie, odbierz ostateczny wynik zadania za pomocą `callback_url`

Nie musisz przesyłać `action`, aby wybrać tryb generowania, interfejs automatycznie oceni zastosowanie na podstawie typów materiałów i `role` w `content`.

## Odpowiednie scenariusze

| Scenariusz         | Kombinacja wejściowa                  | Typowe zastosowania                      |
| ------------------ | ------------------------------------- | --------------------------------------- |
| Wideo na podstawie tekstu | Tekst                                | Pomysły reklamowe, próby ujęć, krótkie wideo, ujęcia atmosferyczne |
| Wideo z pierwszą klatką | Tekst + obraz pierwszej klatki       | Ożywienie zdjęć produktów, plakatów, zdjęć osób lub ilustracji |
| Wideo z klatką końcową / pierwszą i końcową | Tekst + klatka końcowa, lub tekst + klatka pierwsza + klatka końcowa | Kontrola wprowadzenia i zakończenia, przejścia, zmiany wzrostu i porównania przed i po |
| Wideo z multimodalnym odniesieniem | Tekst + obraz / wideo / dźwięk odniesienia | Utrzymanie spójności postaci i produktów, replikacja ruchów, ujęć, barwy dźwięku lub rytmu montażu |

## Proces wywołania

Domyślnie, gdy nie przesyłasz `async`, `/minimax/videos` będzie czekać na zakończenie generowania i bezpośrednio zwróci pełne `task`. Aby natychmiast zwolnić połączenie, przekaż `async: true` lub `callback_url`:

1. Zapisz `task_id` i `trace_id` z natychmiastowej odpowiedzi.
2. Jeśli nie skonfigurowano callbacka, co około 10 sekund wywołuj `/minimax/tasks`, aby sprawdzić status.
3. Gdy `task.status` zmieni się na `succeeded`, uzyskaj wideo z `task.content.url`.
4. Gdy status to `failed` lub `cancelled`, zatrzymaj polling i odczytaj `task.error`.

## Parametry żądania najwyższego poziomu

| Parametr          | Typ       | Wymagany | Wartość domyślna | Opis                                                |
| ----------------- | --------- | -------- | ---------------- | --------------------------------------------------- |
| `model`           | string    | Tak      | -                | Ustalony na `MiniMax-H3`                            |
| `content`         | object[]  | Tak      | -                | Tablica treści multimodalnej, musi zawierać co najmniej jeden niepusty element `text` |
| `resolution`      | string    | Tak      | -                | `768P` lub `2K`                                     |
| `duration`        | integer   | Tak      | -                | Czas trwania generowania, liczba całkowita od 4 do 15 sekund |
| `ratio`           | string    | Warunkowo wymagany | `adaptive` | `adaptive`, `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16` |
| `async`           | boolean   | Nie      | `false`          | `true` zwraca natychmiast identyfikator zadania, wyniki można uzyskać przez interfejs zadań |
| `callback_url`    | string    | Nie      | -                | Publiczny URL do odbioru ostatecznego wyniku zadania; po podaniu automatycznie włącza tryb asynchroniczny |

Reguły dotyczące `ratio` zależą od przepływu pracy:

- **Wideo na podstawie tekstu**: wymagane, nie może być `adaptive`.
- **Wideo z pierwszą klatką, klatką końcową lub pierwszą i końcową**: proporcje określa obraz wejściowy, zaleca się pominięcie lub przesłanie `adaptive`.
- **Wideo z multimodalnym odniesieniem**: można pominąć, domyślnie `adaptive`; można również wyraźnie określić stały stosunek.

Interfejs nie akceptuje starych lub zgodnych pól, takich jak `prompt`, `image_urls`, `audio_urls`, `messages` i `first_frame_image`. W przypadku otrzymania błędów związanych z tymi parametrami, usuń stare pola i przenieś je do `content`; na przykład zmień `"prompt": "kot macha"` na `"content": [{"type": "text", "text": "kot macha"}]`. Nie wysyłaj jednocześnie obu formatów.

## Parametry elementów treści `content`

Każdy element treści musi mieć `type`, a pozostałe pola są określane przez typ:

| `type`        | Pola danych          | `role`            | Opis                                     |
| ------------- | -------------------- | ----------------- | ---------------------------------------- |
| `text`        | `text`               | Nie przesyłaj     | Każde żądanie musi zawierać co najmniej jeden niepusty element tekstowy, maksymalnie 7000 znaków |
| `image_url`   | `image_url.url`      | `first_frame`     | Obraz pierwszej klatki; gdy jest tylko jeden obraz i `role` jest pominięte, również traktowany jako pierwsza klatka |
| `image_url`   | `image_url.url`      | `last_frame`      | Obraz klatki końcowej; może być używany samodzielnie lub w połączeniu z `first_frame` do kontrolowania punktu początkowego i końcowego |
| `image_url`   | `image_url.url`      | `reference_image` | Obraz odniesienia, postaci, produktu, odzieży, scenerii lub stylu |
| `video_url`   | `video_url.url`      | `reference_video` | Wideo odniesienia do ruchu, ujęć, występów lub struktury montażu |
| `audio_url`   | `audio_url.url`      | `reference_audio` | Dźwięk odniesienia, dialog, muzyka lub rytm |

Adresy mediów obsługują trzy formy:

- Publicznie dostępny URL HTTPS, zalecany do dużych plików.
- `mm_file://{file_id}`, odniesienie do już przesłanego lub istniejącego pliku.
- Odpowiedni typ mediów w formacie Base64 data URI. Base64 zwiększa objętość o około jedną trzecią, upewnij się, że cały ładunek żądania nie przekracza 64 MB.

## Specyfikacje materiałów i ograniczenia ilościowe
| Materiał | Format                                        | Limit jednego pliku | Rozmiar / Czas trwania                                               | Limit ilościowy                  |
| --- | ------------------------------------------- | --------- | --------------------------------------------------------------- | --------------------------- |
| Obraz  | JPG, JPEG, PNG, WEBP, HEIC, HEIF                 | Nie więcej niż 30 MB | Szerokość i wysokość od 256 do 5760 px; proporcje 0.4-2.5          | Maksymalnie 1 obrazek na pierwszą klatkę, maksymalnie 1 obrazek na ostatnią klatkę, maksymalnie 9 obrazków referencyjnych |
| Wideo  | MP4, MOV; H.264/AVC lub H.265/HEVC; ścieżka dźwiękowa AAC lub MP3 | Nie więcej niż 50 MB | Każdy segment 2-15 sekund, łącznie nie więcej niż 15 sekund; szerokość i wysokość od 256 do 5760 px; proporcje 0.4-2.5; 23.976-60 fps | Maksymalnie 3 segmenty wideo referencyjnego                  |
| Dźwięk  | WAV, MP3                                     | Nie więcej niż 15 MB | Każdy segment 2-15 sekund, łącznie nie więcej niż 15 sekund        | Maksymalnie 3 segmenty dźwięku referencyjnego                  |

W przypadku multimodalnych scenariuszy referencyjnych maksymalnie 12 plików. Sceny z pierwszą i ostatnią klatką oraz materiały referencyjne są wzajemnie wykluczające: po użyciu `reference_image`, `reference_video` lub `reference_audio` nie można już używać `first_frame` lub `last_frame`, i odwrotnie.

## Wideo generowane z tekstu

Gdy jest tylko jeden element tekstowy, jest to wideo generowane z tekstu. Odpowiednie do bezpośredniego generowania obrazu z pomysłu, scenariusza lub opisu ujęcia. Słowa kluczowe można zorganizować w kolejności „podmiot + akcja + scena + ujęcie + światło + dźwięk”.

```bash
curl -X POST 'https://api.acedata.cloud/minimax/videos' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MiniMax-H3",
    "content": [
      {
        "type": "text",
        "text": "15 sekundowy filmowy reklamowy zapach: na czarnych skałach wybrzeża o poranku, przezroczysta butelka perfum otoczona mgłą i falami. Zbliżenie ukazuje krople wody na butelce i załamanie światła w szkle, kamera powoli przesuwa się od zbliżenia produktu do szerokiego widoku morza; srebrno-niebieska tonacja, naturalne światło, wysoka powściągliwość, zakończenie zatrzymuje się na produkcie."
      }
    ],
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }'
```

Domyślny tryb synchronizacji zwraca pełne zadanie po zakończeniu generowania:

```json
{
  "task": {
    "id": "f5977217-ed2c-40da-adbe-93d08235618f",
    "model": "MiniMax-H3",
    "status": "succeeded",
    "content": { "url": "https://cdn.acedata.cloud/minimax/f5977217.mp4" },
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }
}
```

Jeśli w żądaniu dodano `"async": true`, interfejs natychmiast zwraca:

```json
{
  "task_id": "f5977217-ed2c-40da-adbe-93d08235618f",
  "trace_id": "trace_7f8c2b1a"
}
```

## Wideo generowane z pierwszej klatki

Oznacz zdjęcie jako `first_frame`, a model zacznie generować od tego obrazu. Odpowiednie do naturalnego ożywienia plakatów, zdjęć produktów, rysunków postaci i dzieł fotograficznych.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "Postać naturalnie oddycha i patrzy przez okno, końcówka ubrania porusza się na wietrze, kamera powoli zbliża się"
    },
    {
      "type": "image_url",
      "image_url": {
        "url": "https://cdn.acedata.cloud/b1c82e4937.png"
      },
      "role": "first_frame"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

## Wideo z klatką końcową i pierwszą klatką
只提供 `last_frame` może pozwolić modelowi naturalnie wygenerować do określonej klatki; jednocześnie dostarczając `first_frame` i `last_frame`, można wyraźnie kontrolować punkt początkowy i końcowy. Odpowiednie do przejść, zmian formy, procesów wzrostu lub porównań przed i po produkcie.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "Dziewczyna naturalnie dorasta z dzieciństwa do młodości, czas płynie gładko, postać zawsze znajduje się w centrum obrazu"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_FIRST_FRAME_URL" },
      "role": "first_frame"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_LAST_FRAME_URL" },
      "role": "last_frame"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

Rozmiary i proporcje pierwszej i ostatniej klatki powinny być jak najbardziej zgodne, a różnice w położeniu głównego obiektu, kompozycji i oświetleniu nie powinny być zbyt duże, aby uzyskać naturalne przejście.

## Multimodalne odniesienia do generowania wideo

Materiał referencyjny można łączyć: obrazy referencyjne kontrolują wygląd postaci lub produktu, wideo referencyjne kontroluje ruch i ujęcia, a audio referencyjne kontroluje ton dialogów, muzykę lub rytm montażu. W wskazówkach należy wyraźnie określić, co ma kontrolować każdy rodzaj materiału, aby uniknąć przesyłania materiałów bez podania relacji.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "Zachowaj zgodność rysów twarzy, fryzury i ubioru postaci referencyjnej, wykonując modowy krótkometrażowy film zgodnie z działaniami przedstawionymi w wideo referencyjnym; rytm ujęć podąża za dźwiękiem referencyjnym, zbliżenia podkreślają naturalne wyrazy twarzy"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_CHARACTER_IMAGE_URL" },
      "role": "reference_image"
    },
    {
      "type": "video_url",
      "video_url": { "url": "YOUR_PERFORMANCE_VIDEO_URL" },
      "role": "reference_video"
    },
    {
      "type": "audio_url",
      "audio_url": { "url": "YOUR_AUDIO_URL" },
      "role": "reference_audio"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

## Powiadomienia zwrotne

Przekazanie `callback_url` automatycznie włącza tryb asynchroniczny: interfejs tworzenia natychmiast zwraca `task_id` i `trace_id`, a po zakończeniu zadania wysyła POST z ostatecznym wynikiem na ten adres, struktura jest zgodna z odpowiedzią zapytania o zadanie.

Ostateczny status w powiadomieniu zwrotnym to `succeeded`, `failed` lub `cancelled`. Nawet przy użyciu powiadomień zwrotnych zaleca się zapisanie `task_id`, aby móc aktywnie sprawdzić lub zrekompensować pominięte powiadomienia.

## Częste błędy

| Kod stanu HTTP | Znaczenie           | Zalecenia dotyczące obsługi                           |
| -------- | ------------ | ------------------------------ |
| `400`    | Błąd parametru lub nieprawidłowa kombinacja materiałów | Sprawdź wymagane pola, `role`, liczbę i format materiałów          |
| `401`    | Brak lub nieprawidłowy token  | Sprawdź `Authorization: Bearer ...` |
| `402`    | Niewystarczający saldo lub limit      | Uzupełnij saldo ogólne w konsoli                     |
| `422`    | Kontrola bezpieczeństwa treści nie powiodła się    | Dostosuj wskazówki lub materiały i przekaż ponownie                  |
| `429`    | Zbyt wiele żądań       | Spróbuj ponownie po wykładniczym opóźnieniu; sugerowany odstęp do sprawdzania zadań wynosi około 10 sekund         |
| `500`    | Usługa tymczasowo niedostępna      | Zachowaj informacje o żądaniu, spróbuj ponownie później                    |

Status `task.status: succeeded` w odpowiedzi synchronicznej oznacza, że wideo zostało wygenerowane; potwierdzenie asynchroniczne oznacza tylko, że zadanie weszło do kolejki. Tylko w przypadku ostatecznego sukcesu zadania nastąpi obciążenie, zapytania o zadanie są bezpłatne i nie będą powtarzane.
