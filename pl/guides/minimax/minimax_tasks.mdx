Niniejszy dokument przedstawia integrację i użycie API do zapytań o zadania MiniMax H3. Interfejs ten służy do zapytań, masowego wyświetlania lub usuwania asynchronicznych zadań utworzonych przez [MiniMax H3 API do generowania wideo](/documents/minimax-videos-integration).

## Proces aplikacji

Aby korzystać z API do zapytań o zadania MiniMax H3, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API, który należy zachować na przyszłość.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować, a po zakończeniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

**Jeden token API wystarczy do korzystania ze wszystkich usług platformy, nie ma potrzeby składania osobnych wniosków dla każdej usługi.** Przy pierwszym wniosku przyznawana jest darmowa kwota, aby można było skorzystać z bezpłatnej wersji; w przypadku niewystarczającej kwoty można doładować saldo ogólne w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [API do zapytań o zadania MiniMax H3 →](https://platform.acedata.cloud/documents/minimax-tasks-integration)

Podczas zapytań o zadania należy używać tego samego tokena, który został użyty do utworzenia zadania. Zaleca się zapisanie tokena jako zmiennej środowiskowej, nie należy go wpisywać w kodzie źródłowym ani przesyłać do repozytoriów:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Przegląd interfejsu

- **Podstawowy URL**: `https://api.acedata.cloud`
- **Endpoint**: `POST /minimax/tasks`
- **Metoda autoryzacji**: Nagłówek HTTP zawierający `authorization: Bearer {token}`
- **Nagłówki żądania**:
  - `accept: application/json`
  - `content-type: application/json`
- **Zapytanie o pojedyncze zadanie**: `action=retrieve`, przekazując `id`
- **Masowe zapytanie o zadania**: `action=retrieve_batch`, można filtrować według ID zadania, zakresu czasowego i warunków paginacji
- **Usunięcie zadania**: `action=delete`, przekazując `id`
- **Opis rozliczeń**: Zapytania o zadania są bezpłatne, nie generują podwójnych opłat

Po utworzeniu wideo należy zapisać `task_id`. Zaleca się zapytanie co około 10 sekund, aż zadanie wejdzie w stan końcowy.

## Parametry żądania

| Parametr            | Typ       | Wymagane | Zastosowanie akcji         | Opis                                                   |
| ------------------ | -------- | -------- | -------------------------- | ------------------------------------------------------ |
| `action`           | string   | Nie      | Wszystkie                  | `retrieve`, `retrieve_batch` lub `delete`; domyślnie `retrieve` |
| `id`               | string   | Warunkowo | `retrieve`, `delete`      | ID pojedynczego zadania                                  |
| `ids`              | string[] | Nie      | `retrieve_batch`          | Zwraca tylko określone ID zadań; pomijane, gdy zadania są wyświetlane według innych warunków |
| `limit`            | integer  | Nie      | `retrieve_batch`          | Maksymalna liczba zadań do zwrócenia w tej chwili      |
| `offset`           | integer  | Nie      | `retrieve_batch`          | Liczba zadań do pominięcia w liście wyników, używana do paginacji |
| `created_at_min`   | number   | Nie      | `retrieve_batch`          | Dolna granica czasu utworzenia, znacznik czasu Unix, w sekundach |
| `created_at_max`   | number   | Nie      | `retrieve_batch`          | Górna granica czasu utworzenia, znacznik czasu Unix, w sekundach |

Trzy rodzaje akcji mają następujące zastosowania:

| `action`           | Zastosowanie                          | Wymagane parametry                  | Struktura odpowiedzi                             |
| ------------------ | ------------------------------------- | ----------------------------------- | ----------------------------------------------- |
| `retrieve`         | Zapytanie o status i wynik pojedynczego zadania | `id`                               | `{ "task": {...} }`                             |
| `retrieve_batch`   | Masowe zapytanie według ID zadania, czasu i warunków paginacji | Opcjonalne `ids`, zakres czasowy, `offset`, `limit` | `{ "items": [...], "total": number }`         |
| `delete`           | Anulowanie lub usunięcie rekordu zadania na podstawie aktualnego statusu | `id`                               | `{ "id": "...", "deleted": true }`            |

## Zapytanie o pojedyncze zadanie

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve",
```

## Status zadania

| `status`    | Znaczenie                          | Obsługa klienta                  |
| ----------- | ---------------------------------- | -------------------------------- |
| `queued`    | Zadanie w kolejce, czeka na wykonanie | Kontynuuj odpytywanie            |
| `running`   | W trakcie generowania              | Kontynuuj odpytywanie            |
| `succeeded` | Generowanie zakończone sukcesem    | Odczytaj `task.content.url`, zatrzymaj odpytywanie |
| `failed`    | Generowanie nie powiodło się       | Odczytaj `task.error`, zatrzymaj odpytywanie       |
| `cancelled` | Zadanie zostało anulowane          | Zatrzymaj odpytywanie            |

`Succeeded`, `failed` i `cancelled` to stany końcowe. Nie kontynuuj odpytywania po osiągnięciu stanu końcowego.

## Pola odpowiedzi task

| Pole                        | Typ      | Opis                              |
| ------------------------- | ------- | --------------------------------- |
| `id`                      | string  | ID zadania                        |
| `model`                   | string  | Model użyty w zadaniu, obecnie `MiniMax-H3` |
| `status`                  | string  | Aktualny status zadania           |
| `error.code`              | string  | Kod błędu w przypadku niepowodzenia, zwracany tylko w przypadku błędu |
| `error.message`           | string  | Powód niepowodzenia, zwracany tylko w przypadku błędu |
| `created_at`              | integer | Czas utworzenia, znacznik czasu Unix, w sekundach |
| `updated_at`              | integer | Czas ostatniej aktualizacji statusu, znacznik czasu Unix, w sekundach |
| `content.url`             | string  | Adres wideo po pomyślnym zakończeniu |
| `resolution`              | string  | Rozdzielczość wyjściowa, `768P` lub `2K` |
| `duration`                | integer | Czas trwania wideo, w sekundach   |
| `usage.total_seconds`     | integer | Całkowity koszt, równy sumie sekund wideo wejściowego i wyjściowego |
| `usage.input_seconds`     | integer | Koszt związany z wideo wejściowym |
| `usage.output_seconds`    | integer | Koszt związany z wideo wyjściowym |
| `usage.input_image_count` | integer | Liczba obrazów wejściowych w statystyce kosztów |
| `ratio`                   | string  | Rzeczywisty współczynnik proporcji; przy użyciu `adaptive` należy kierować się tym wynikiem |
| `task_type`               | string  | Typ zadania generowania wideo to `generation` |
| `modality`                | string  | Typ zadania wideo to `video`      |

## Pełny przykład odpytywania w Pythonie
以下代码从环境变量读取 Token，创建任务后每隔 10 秒查询一次：

```python
import os
import time

import requests

BASE_URL = "https://api.acedata.cloud"
HEADERS = {
    "Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_KEY']}",
    "Content-Type": "application/json",
}

create_response = requests.post(
    f"{BASE_URL}/minimax/videos",
    headers=HEADERS,
    json={
        "model": "MiniMax-H3",
        "content": [
            {
                "type": "text",
                "text": "O świcie nad morzem, biała żaglówka przepływa po spokojnej tafli wody, kamera powoli przesuwa się w bok",
            }
        ],
        "resolution": "768P",
        "duration": 4,
        "ratio": "16:9",
    },
    timeout=30,
)
create_response.raise_for_status()
task_id = create_response.json()["task_id"]

while True:
    time.sleep(10)
    query_response = requests.post(
        f"{BASE_URL}/minimax/tasks",
        headers=HEADERS,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    query_response.raise_for_status()
    task = query_response.json()["task"]
    print(f"task={task_id} status={task['status']}")

    if task["status"] == "succeeded":
        print(f"video_url={task['content']['url']}")
        break
    if task["status"] in ("failed", "cancelled"):
        raise RuntimeError(task.get("error") or task["status"])
```

Produkcja powinna mieć ustawiony całkowity czas oczekiwania dla zapytań oraz stosować wykładnicze opóźnienie dla `429` i tymczasowych `5xx`. Czas oczekiwania na sieć nie oznacza niepowodzenia generacji, można używać tego samego `task_id` do dalszego zapytania.

## Batch Query

Określ wiele identyfikatorów zadań:

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve_batch",
    "ids": ["TASK_ID_1", "TASK_ID_2"],
    "offset": 0,
    "limit": 20
  }'
```

Wypisz zadania w paginacji według zakresu czasowego:

```json
{
  "action": "retrieve_batch",
  "created_at_min": 1786000000,
  "created_at_max": 1786200000,
  "offset": 0,
  "limit": 20
}
```

W odpowiedzi zbiorczej `items` używają tych samych pól `task`, co zapytanie pojedynczego zadania, `total` to całkowita liczba zadań pasujących do kryteriów:

```json
{
  "items": [
    {
      "id": "TASK_ID_1",
      "model": "MiniMax-H3",
      "status": "running",
      "resolution": "2K",
      "duration": 5,
      "ratio": "adaptive",
      "task_type": "generation",
      "modality": "video"
    }
  ],
  "total": 1
}
```

Okno zapytań zadań wynosi ostatnie 7 dni. `task_id` przekraczające ten okres mogą zwracać nieprawidłowe zadania; system biznesowy powinien zapisywać ID podczas tworzenia zadań i na czas utrwalać URL wyników po pomyślnym zakończeniu.

## Anulowanie lub usuwanie zadań

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "delete",
    "id": "YOUR_TASK_ID"
  }'
```

Działanie zależy od aktualnego stanu zadania:

| Aktualny stan        | Działanie            |
| ----------- | ------------- |
| `queued`    | Anuluj zadanie, które jeszcze się nie rozpoczęło     |
| `succeeded` | Usuń rekord zadania        |
| `failed`    | Usuń rekord zadania        |
| `running`   | Nie pozwala na usunięcie lub anulowanie, zwróć błąd |
| `cancelled` | Nie pozwala na powtórne działanie, zwróć błąd  |

Przykład udanego usunięcia:

```json
{
  "id": "YOUR_TASK_ID",
  "deleted": true
}
```

Usunięcie rekordu zadania nie cofa już zakończonego rozliczenia, ani nie gwarantuje, że zapisane kopie wideo zostaną jednocześnie usunięte.

## Odpowiedzi o błędach i diagnostyka

Nieudane zadania nadal zwracają obiekt zadania z HTTP 200, a przyczyna podana jest w `task.error`:

```json
{
  "task": {
    "id": "YOUR_TASK_ID",
    "model": "MiniMax-H3",
    "status": "failed",
    "error": {
      "code": "1026",
      "message": "opis wideo zawiera treści wrażliwe"
    },
    "task_type": "generation",
    "modality": "video"
  }
}
```

Gdy interfejs zwraca `400`, należy sprawdzić `action` i parametry warunkowe, `401` oznacza, że Token jest nieważny, `429` oznacza, że zapytania są zbyt częste, `500` oznacza, że usługa jest tymczasowo niedostępna. Nieudane zadania nie są rozliczane; pomyślne zadania są rejestrowane według ostatecznego `usage`.
