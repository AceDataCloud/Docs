Główną funkcją API do zapytania o zadania Maestro jest możliwość sprawdzenia statusu wykonania i ostatecznego wyniku zadania za pomocą ID zadania zwróconego przez [Maestro API do generowania wideo](development_maestro_videos.md) (`POST /maestro/videos`).

Dokument ten szczegółowo opisuje instrukcje integracji API do zapytania o zadania Maestro. Ponieważ generowanie wideo jest zadaniem asynchronicznym, po złożeniu należy użyć tego interfejsu do cyklicznego pobierania postępu i gotowego materiału, **cykliczne zapytania są darmowe i nie zużywają punktów.**

`POST https://api.acedata.cloud/maestro/tasks`

## Proces aplikacji

Aby korzystać z API do zapytania o zadania Maestro, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API, który należy zachować na przyszłość.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować, a po zakończeniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

**Jeden token API wystarczy do korzystania ze wszystkich usług platformy, nie ma potrzeby składania osobnych wniosków dla każdej usługi.** Przy pierwszym wniosku przyznawana jest darmowa pula, aby można było skorzystać z doświadczenia; w przypadku niewystarczającej puli można doładować saldo ogólne w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [API do zapytania o zadania Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Zapytanie o pojedyncze zadanie

Aby dowiedzieć się, jak utworzyć zadanie wideo, zapoznaj się z dokumentem [Maestro API do generowania wideo](development_maestro_videos.md). Użyjemy jako przykładu ID zadania, które zostało zwrócone: `f57e99c4f60f4373a15517742ce2357d`, aby pokazać, jak sprawdzić jego status i wynik.

### Ustawienie nagłówków żądania i ciała żądania

**Nagłówki żądania** obejmują:

- `accept`: określa, że oczekiwany jest wynik odpowiedzi w formacie JSON, tutaj wpisz `application/json`.
- `authorization`: klucz do wywołania API, po złożeniu wniosku można go bezpośrednio wybrać z rozwijanej listy.
- `content-type`: format ciała żądania, tutaj wpisz `application/json`.

**Ciało żądania** obejmuje:

| Pole       | Typ     | Wymagane | Opis                                                |
| -------- | ------ | --- | ------------------------------------------------- |
| `id`     | string | Tak   | `task_id` zwrócone przez `POST /maestro/videos`              |
| `action` | string | Nie   | `retrieve` (domyślnie, zapytanie o pojedyncze zadanie) / `retrieve_batch` (zapytanie o listę historycznych zadań) |

### Przykład kodu

Odpowiedni kod CURL wygląda następująco:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Odpowiedni kod w Pythonie wygląda następująco:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Przykład odpowiedzi

Po pomyślnym wykonaniu żądania API zwróci status i wynik tego zadania wideo. Przykład odpowiedzi po zakończeniu zadania wygląda następująco (każdy język odpowiada jednemu `variant`):

```json
{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "status": "succeeded",
  "elapsed": 312,
  "progress": { "percent": 100, "stage": "producing", "message": "rendering scene 2" },
  "request": {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": ["zh-cn", "en"],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        { "lang": "zh-cn", "aspect": "9:16", "kind": "video", "title": "什么是向量数据库", "output_url": "https://…/zh.mp4" },
        { "lang": "en", "aspect": "9:16", "kind": "video", "title": "What is a vector database", "output_url": "https://…/en.mp4" }
      ],
      "project": { "tarball_url": "https://…/project.tar.gz", "outputs": ["https://…/zh.mp4", "https://…/en.mp4"] },
      "percent": 100,
      "stage": "producing",
      "progress": [ { "stage": "producing", "message": "rendering scene 2", "pct": 60, "t": 1750000000 } ]
    }
  }
}
```

Opis pól w zwróconym wyniku jest następujący:

- `id`: ID tego zadania wideo, używane do unikalnej identyfikacji tego zadania generowania wideo.
- `status`: status zadania, przyjmuje wartości `pending → planning → producing → succeeded` (lub `failed`). Status ten określa, czy zadanie zostało zakończone.
- `elapsed`: czas, jaki upłynął od rozpoczęcia zadania (w sekundach).
- `progress`: obiekt postępu na najwyższym poziomie, `percent` (0–100) po pomyślnym zakończeniu zadania będzie wynosić 100; `stage` i `message` odzwierciedlają ostatnie zdarzenie postępu AI reżysera (dlatego po zakończeniu `stage` może nadal być ostatnim etapem wykonania, takim jak `producing`), można go bezpośrednio użyć do wyświetlenia paska postępu.
- `request`: ciało żądania przy składaniu zadania.
- `response`: informacje zwrotne dotyczące zadania.
  - `success`: czy zadanie zakończyło się sukcesem.
  - `data.variants`: każdy język odpowiada jednemu obiektowi gotowego materiału, zawierającemu `lang`, `aspect`, `title`, `output_url` (adres do pobrania gotowego materiału) itp.
  - `data.project`: cały produkt projektu, zawierający `tarball_url` (pakiet projektu) oraz `outputs` (wszystkie linki do gotowych materiałów).
  - `data.progress`: tablica zdarzeń postępu dodawanych według etapów (logi tylko do dodawania), można je wykorzystać do wyświetlenia szczegółowego postępu w czasie rzeczywistym.

## Zapytanie o historię zadań

Przekazując `action: retrieve_batch`, można uzyskać listę ostatnich zadań bieżącego użytkownika (w kolejności odwrotnej do daty utworzenia), co może być użyte do strony „Moje wideo”.

**Ciało żądania** obejmuje:

| Pole               | Typ     | Wymagane | Opis                      |
| ---------------- | ------ | --- | ----------------------- |
| `action`         | string | Tak   | Ustalona wartość `retrieve_batch`    |
| `limit`          | int    | Nie   | Liczba zwracanych pozycji, domyślnie 20              |
| `created_at_max` | int    | Nie   | Zwraca tylko zadania sprzed tego znacznika czasu Unix (do paginacji) |
| `created_at_min` | int    | Nie   | Zwraca tylko zadania po tym znaczniku czasu Unix      |

### Przykład kodu

Odpowiedni kod CURL wygląda następująco:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### Przykład odpowiedzi

Po pomyślnym wykonaniu żądania API zwróci listę historycznych zadań bieżącego użytkownika:
```json
{
  "count": 2,
  "items": [
    {
      "id": "f57e99c4f60f4373a15517742ce2357d",
      "status": "succeeded",
      "progress": { "percent": 100, "stage": "producing", "message": "rendering scene 2" },
      "request": { "prompt": "…", "langs": ["zh-cn", "en"], "aspect": "9:16", "duration": 20 },
      "response": { "success": true, "data": { "variants": [ { "lang": "zh-cn", "output_url": "https://…/zh.mp4" } ] } }
    }
  ]
}
```

Opis pól zwracanych wyników jest następujący:

- `count`：Całkowita liczba zadań bieżącego użytkownika.
- `items`：Tablica zadań, każdy element ma format zgodny z „wynikiem zapytania pojedynczego zadania”.

## Sugestie dotyczące polling

Ponieważ produkcja wideo zajmuje dużo czasu, `status` przechodzi przez `pending → planning → producing → succeeded` (lub `failed`). Zaleca się polling co 5–10 sekund, aż `status` zmieni się na `succeeded` lub `failed`. Można wykorzystać górny `progress.percent` do wyświetlenia paska postępu w czasie rzeczywistym. **Polling tego interfejsu jest bezpłatny i nie zużywa punktów.**

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `401 invalid_token`：Nieautoryzowany, nieprawidłowy lub brakujący token autoryzacyjny.
- `404 not_found`：Zadanie nie zostało znalezione, podany task_id nie istnieje.
- `429 too_many_requests`：Zbyt wiele żądań, przekroczyłeś limit szybkości.
- `500 api_error`：Błąd wewnętrzny serwera, coś poszło nie tak na serwerze.

### Przykład odpowiedzi błędu

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
