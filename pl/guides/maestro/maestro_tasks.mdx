Główną funkcją API zapytania o zadania Maestro jest użycie ID zadania zwróconego przez [API generowania wideo Maestro](development_maestro_videos.md) (`POST /maestro/videos`) do sprawdzenia statusu wykonania i końcowego wyniku tego zadania.

Ten dokument szczegółowo przedstawia instrukcję integracji API zapytania o zadania Maestro. Ponieważ generowanie wideo jest zadaniem asynchronicznym, po przesłaniu należy użyć tego interfejsu do odpytywania postępu i gotowego materiału, **odpytywanie jest bezpłatne i nie zużywa punktów.**

`POST https://api.acedata.cloud/maestro/tasks`

## Proces aplikowania

Aby używać API zapytania o zadania Maestro, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany ani zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania z zaproszeniem do rejestracji i zalogowania się, a po zakończeniu automatycznie wrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, nie ma potrzeby składania osobnego wniosku dla każdej usługi.** Przy pierwszym wniosku otrzymasz bezpłatny limit, aby móc bezpłatnie wypróbować usługę; gdy limit jest niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [API zapytania o zadania Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Zapytanie o pojedyncze zadanie

Informacje o tym, jak utworzyć zadanie wideo, znajdziesz w dokumentacji [API generowania wideo Maestro](development_maestro_videos.md). Jako przykład użyjemy zwróconego przez nie ID zadania: `f57e99c4f60f4373a15517742ce2357d`, aby zademonstrować, jak sprawdzić jego status i wynik.

### Ustawianie nagłówków żądania i treści żądania

**Request Headers** obejmują:

- `accept`: określa, że ma zostać odebrany wynik odpowiedzi w formacie JSON, tutaj należy wpisać `application/json`.
- `authorization`: klucz do wywołania API, po złożeniu wniosku można go bezpośrednio wybrać z listy rozwijanej.
- `content-type`: format treści żądania, tutaj należy wpisać `application/json`.

**Request Body** obejmuje:

| Pole       | Typ     | Wymagane podczas | Opis                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | wymagane przy zapytaniu o pojedyncze zadanie | `task_id` zwrócony przez `POST /maestro/videos`              |
| `action` | string | nie         | `retrieve` (domyślnie, zapytanie o pojedyncze zadanie); podczas zapytania o listę historii stała wartość `retrieve_batch` |

### Przykład kodu

Odpowiedni kod CURL jest następujący:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Odpowiedni kod Python jest następujący:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Przykład odpowiedzi

Po pomyślnym wysłaniu żądania API zwróci status i wynik tego zadania wideo. Przykład zwracany po ukończeniu zadania jest następujący (każdy język odpowiada jednemu `variant`):

```json

  "started_at": 1769262721.823,
  "finished_at": 1769264698.3,

  "status": "succeeded",
  "progress": {
    "percent": 100,
    "stage": "producing",
    "message": "rendering scene 2"
  },
  "request": {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": [
      "zh-cn",
      "en"
    ],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        {
          "lang": "zh-cn",
          "aspect": "9:16",
          "kind": "video",
          "title": "什么是向量数据库",
          "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-001"
        },
        {
          "lang": "en",
          "aspect": "9:16",
          "kind": "video",
          "title": "What is a vector database",
          "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-002"
        }
      ],
      "project": {
        "tarball_url": null,
        "outputs": [
          "https://…/zh.mp4",
          "https://…/en.mp4"
        ]
      },
      "percent": 100,
      "stage": "producing",
      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }
  }
}
```

Opis pól wyniku zwracanego jest następujący:

- `id`: ID tego zadania wideo, używane do jednoznacznej identyfikacji tego zadania generowania wideo.
- `status`: status zadania, przyjmuje wartości `pending → planning → producing → succeeded` (lub `failed`). O tym, czy zadanie zostało ukończone, decyduje ten najwyższego poziomu `status`.
- `elapsed`: czas trwania zadania (sekundy).
- `progress`: obiekt postępu najwyższego poziomu, `percent` (0–100) po pomyślnym zakończeniu zadania zostanie ustawiony na 100; `stage` i `message` odzwierciedlają ostatnie zdarzenie postępu reżysera AI (dlatego po sukcesie `stage` może nadal być ostatnim etapem wykonania, takim jak `producing`), może być bezpośrednio używany do wyświetlania paska postępu.
- `request`: treść żądania podczas uruchamiania zadania.
- `response`: informacje zwrotne zadania.
  - `success`: czy zadanie zakończyło się powodzeniem.
  - `data.variants`: każdemu językowi odpowiada jeden obiekt gotowego materiału, zawierający między innymi `lang`, `aspect`, `title`, `output_url` (adres pobierania gotowego materiału).
  - `data.project`: artefakty całego projektu, zawierające `tarball_url` (pakiet projektu) i `outputs` (wszystkie linki do gotowych materiałów).
  - `data.progress`: tablica zdarzeń postępu dodawanych według etapów (dziennik append-only), może być używana do wyświetlania szczegółowego postępu w czasie rzeczywistym.
- `created_at`: czas utworzenia zadania, znacznik czasu Unix (sekundy).
- `started_at`: czas rozpoczęcia wykonywania zadania, znacznik czasu Unix (sekundy). Wartość null, gdy zadanie jeszcze się nie rozpoczęło.
- `finished_at`: czas ukończenia zadania, znacznik czasu Unix (sekundy). Wartość null, gdy zadanie nie zostało ukończone.

## Zapytanie o listę historii

Przekaż `action: retrieve_batch`, aby uzyskać najnowsze zadania bieżącego zalogowanego wykonawcy (w odwrotnej kolejności według czasu utworzenia), co może być używane na stronie listy „Moje wideo”. Lista historii jest izolowana według tożsamości logowania.

**Request Body** obejmuje:
| Pole               | Typ     | Wymagane  | Opis                              |
| ---------------- | ------ | --- | ------------------------------- |
| `action`         | string | Tak   | Stała wartość `retrieve_batch`            |
| `limit`          | int    | Nie   | Liczba zwracanych pozycji, domyślnie 20; prawidłowy zakres to 1–100          |
| `created_at_max` | int    | Nie   | Zwraca tylko zadania ściśle wcześniejsze niż ten znacznik czasu Unix (bez wartości granicznej, do stronicowania) |
| `created_at_min` | int    | Nie   | Zwraca tylko zadania ściśle późniejsze niż ten znacznik czasu Unix (bez wartości granicznej)     |

### Przykład kodu

Odpowiedni kod CURL jest następujący:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

## Zalecenia dotyczące odpytywania

Ponieważ produkcja wideo zajmuje dużo czasu, `status` przejdzie przez `pending → planning → producing → succeeded` (lub `failed`). Zaleca się odpytywanie co 5–10 sekund, aż `status` zmieni się na `succeeded` lub `failed`. Można użyć najwyższego poziomu `progress.percent` do wyświetlania paska postępu w czasie rzeczywistym. **Odpytywanie tego interfejsu jest bezpłatne i nie zużywa punktów.**

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informację. Na przykład:

- `401 invalid_token`: Nieautoryzowano, nieprawidłowy lub brakujący token autoryzacyjny.
- `404 not_found`: Nie znaleziono zadania, podane task_id nie istnieje.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`: Wewnętrzny błąd serwera, coś poszło nie tak na serwerze.

### Przykład odpowiedzi błędu

```json
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"

```
