Maestro to **natywny dla Agentów** interfejs do produkcji wideo: za pomocą jednego naturalnego językowego `prompt` opisujesz wideo, które chcesz uzyskać (opcjonalnie dołączając obrazy referencyjne / wideo / audio poprzez `file_urls`), a bezgłowy „reżyser AI” automatycznie wykona wybór tematu, napisze scenariusz, wygeneruje obrazy, dubbing, muzykę, kompozycję i renderowanie, a ostatecznie stworzy gotowy film z napisami i prześle go do CDN.

W tym artykule szczegółowo przedstawimy instrukcję integracji API generowania wideo Maestro, aby pomóc Ci szybko zintegrować i w pełni wykorzystać możliwości tego API.

To interfejs **zadań asynchronicznych**: po przesłaniu natychmiast zwróci `task_id`, a następnie wynik można uzyskać poprzez odpytywanie [API zapytań o zadania Maestro](/pl/guides/maestro/maestro_tasks) (`POST /maestro/tasks`) (odpytywanie jest bezpłatne i nie jest naliczane). Aby kontynuować iterację na istniejącym wideo, można użyć `action: remix` / `edit` / `extend` wraz z `ref_task_id`.

## Proces aplikowania

Aby korzystać z API generowania wideo Maestro, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, nastąpi automatyczne przekierowanie na stronę logowania, która zaprosi Cię do rejestracji i zalogowania się, a po zakończeniu automatycznie wrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności składania osobnego wniosku dla każdej usługi.** Przy pierwszym uzyskaniu tokena otrzymasz darmowy limit, który pozwala na bezpłatne wypróbowanie; gdy limit będzie niewystarczający, możesz doładować ogólne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [API generowania wideo Maestro →](https://platform.acedata.cloud/documents/maestro-videos)

## Podstawowe użycie

`POST https://api.acedata.cloud/maestro/videos`

Najbardziej podstawowe użycie wymaga jedynie przekazania naturalnego językowego `prompt`, a reżyser AI automatycznie zdecyduje o scenariuszu, obrazie, dubbingu i montażu. Tutaj najpierw zapoznajmy się z nagłówkami i treścią żądania, które należy ustawić.

**Request Headers** obejmują:

- `accept`: format odpowiedzi, który chcesz otrzymać; tutaj wpisz `application/json`, czyli format JSON.
- `authorization`: klucz do wywołania API, który po uzyskaniu można bezpośrednio wybrać z listy rozwijanej.
- `content-type`: format treści żądania; tutaj wpisz `application/json`.

**Request Body** obejmuje głównie:

- `prompt`: opisz w naturalnym języku wideo, które chcesz stworzyć (temat, co ma zostać pokazane, styl, odbiorcy).
- `langs`: tablica języków gotowego filmu; każdorazowo przekazuj tylko jeden, np. `["zh-cn"]`, domyślnie `["zh-cn"]`.
- `aspect`: proporcje obrazu: `9:16` (domyślnie) / `16:9` / `1:1`.
- `duration`: docelowa długość (sekundy), domyślnie 30.

Wszystkie pola treści żądania przedstawia poniższa tabela:

| Pole            | Typ       | Wymagane  | Opis                                                                                                                                                                                                                           |
| ------------- | -------- | --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`      | string   | Tak   | Opisz w naturalnym języku wideo, które chcesz stworzyć (temat, co ma zostać pokazane, styl, odbiorcy). Scenariusz, obraz, dubbing i montaż są decydowane przez AI                                                                                                                                                                             |
| `action`      | string   | Nie   | `generate` (domyślnie, generuje nowe wideo) / `remix` / `edit` / `extend` (iteracja na istniejącym wideo, wymaga użycia z `ref_task_id`)                                                                                                                                                |
| `ref_task_id` | string   | Nie   | Wymagane, gdy `action` to remix / edit / extend: historyczne `task_id` używane jako punkt początkowy                                                                                                                                                                   |
| `file_urls`   | string[] | Nie   | Media referencyjne (obrazy / wideo / audio URL), np. zdjęcia produktów lub logo, które mają pojawić się w kadrze, albo fragmenty materiału, do których należy dodać napisy                                                                                                                                                                             |
| `langs`       | string[] | Nie   | Język gotowego filmu; każdorazowo można przekazać tylko jeden, np. `["zh-cn"]`, domyślnie `["zh-cn"]`                                                                                                                                                                                    |
| `aspect`      | string   | Nie   | `9:16` (domyślnie) / `16:9` / `1:1`, jednolity wynik 1080p/30fps                                                                                                                                                                                  |
| `duration`    | int      | Nie   | Docelowa długość (sekundy), domyślnie 30, obsługuje **5–300 sekund**. Opłata jest naliczana według rzeczywistej długości gotowego filmu, ale nie przekroczy żądanego czasu                                                                                                                                                                             |
| `scenario`    | string   | Nie   | Typ wideo: `auto` / `narrated` / `captions` / `avatar` / `drama`. `captions` wymaga przekazania źródłowego wideo, `avatar` wymaga przekazania wizerunku osoby                                                                                                                                    |
| `style`       | string   | Nie   | Presety stylu wizualnego: `auto` (domyślnie) / `cinematic` / `glass` / `luxury` / `swiss` / `modern` / `editorial` / `warm` / `vibrant` / `neon` / `mono` / `pastel` / `bold` / `industrial` / `futuristic` / `retro`; akceptowany jest również dowolny tekst jako miękka wskazówka. Jest niezależne od `scenario` i nie zmienia routingu |
| `voice`       | string   | Nie   | Barwa głosu narracji (niezależna od języka, uniwersalna między językami): `auto` (domyślnie) / `warm-female` / `bright-female` / `anchor-female` / `clean-female` / `calm-male` / `deep-male` / `documentary-male` / `energetic-male` / `storyteller-male`                                    |

Poniżej zademonstrujemy to na konkretnym przykładzie. Załóżmy, że chcemy wygenerować 20-sekundowe popularnonaukowe krótkie wideo po chińsku, w pionowym formacie. Odpowiedni kod CURL jest następujący:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
  "langs": ["zh-cn"],
  "aspect": "9:16",
  "duration": 20
}'
```

Odpowiedni kod Python jest następujący:

```python
import requests

url = "https://api.acedata.cloud/maestro/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": ["zh-cn"],
    "aspect": "9:16",
    "duration": 20
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Po kliknięciu uruchomienia można zauważyć, że natychmiast otrzymasz wynik, jak poniżej:

```json
{
  "success": true,
  "task_id": "f57e99c4f60f4373a15517742ce2357d",
  "trace_id": "70e1cb12-c619-4292-a416-90191205996b"
}
```

Opis pól wyniku zwracanego jest następujący:
- `success`: czy to zadanie zostało pomyślnie przesłane.
- `task_id`: ID tego zadania generowania wideo, użyj go później do odpytywania wyniku przez [API zapytań o zadania Maestro](/pl/guides/maestro/maestro_tasks).
- `trace_id`: ID śledzenia tego żądania, które można przekazać wsparciu technicznemu w razie problemów w celu ich zlokalizowania.

Ze względu na długi czas produkcji wideo interfejs **natychmiast zwraca tutaj `task_id`** i nie czeka na zakończenie renderowania wideo. Następnie należy użyć `task_id` do odpytywania wyniku, szczegóły znajdują się w sekcji „Pobieranie wyniku”.

## Określanie typu i stylu wideo (scenario / style)

Gdy `scenario` nie zostanie przekazane, AI automatycznie je określa (równe `auto`); jeśli chcesz przypisać wideo do określonego typu, przekaż je jawnie. Na przykład, aby stworzyć **pionowy krótki dramat**, możesz określić następującą zawartość:

- `scenario`: typ wideo, tutaj ustawiony na `drama` (krótki dramat z postaciami + dialogami).
- `style`: styl wizualny, tutaj ustawiony na `cinematic` (filmowy charakter).

Kod CURL przykładowego wypełnienia jest następujący:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "两个合租室友因为一只猫闹翻又和好，三幕反转，结尾温暖",
  "scenario": "drama",
  "style": "cinematic",
  "aspect": "9:16",
  "duration": 40
}'
```

Popularne sposoby łączenia:

- Krótki film z narracją: `scenario: "narrated"`.
- Automatyczne napisy: `scenario: "captions"`, należy przekazać źródłowe wideo za pomocą `file_urls`.
- Cyfrowy człowiek / wypowiedź do kamery: `scenario: "avatar"`, należy przekazać zdjęcie portretowe za pomocą `file_urls`.
- Krótki dramat: `scenario: "drama"` (postacie + dialogi).
- `style` to ustawienie wstępne stylu wizualnego (np. `modern` / `neon` / `luxury`), nie zmienia typu, a jedynie wpływa na odbiór wizualny.
- `voice` służy do określania barwy głosu narracji (np. `warm-female` / `deep-male`), nie zależy od języka i jest uniwersalne między językami.

Wynik zwracany jest tak samo jak w przypadku „Podstawowego użycia”, również natychmiast zwracany jest `task_id`.

## Język gotowego filmu

Jedno zadanie dostarcza tylko jeden gotowy film w jednym języku. `langs` może zawierać tylko jeden kod języka, na przykład `["zh-cn"]` lub `["en"]`; przekazanie wielu języków zwróci 400. Jeśli potrzebujesz filmów w różnych językach, utwórz osobne zadania. Wybór języka nie zmienia ceny za sekundę.

## Iterowanie na istniejącym wideo (remix / edit / extend)

Przekaż `action` oraz `ref_task_id` poprzedniego zadania, aby wprowadzać różnicowe zmiany na bazie oryginalnego projektu (np. „zmień tytuł sceny 2”, „zmień dubbing”, „przyciemnij całość”). Małe zmiany są szybkie, duże zmiany spowodują ponowne wykonanie:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "remix",
  "ref_task_id": "f57e99c4f60f4373a15517742ce2357d",
  "prompt": "把开场标题换成更有冲击力的一句，整体配色更暗一些"
}'
```

- `remix`: ponowna interpretacja na strukturze oryginalnego wideo (zachowuje temat, dostosowuje sposób przedstawienia).
- `edit`: precyzyjna edycja określonego fragmentu (np. zmiana tytułu, dubbingu, korekty kolorów).
- `extend`: rozszerzenie treści na bazie oryginalnego wideo.

Wynik również natychmiast zwraca nowe `task_id`, użyj go do odpytywania, aby uzyskać gotowy film po iteracji.

## Pobieranie wyniku

Ze względu na długi czas produkcji wideo ten interfejs natychmiast zwraca `task_id` po przesłaniu, musisz użyć go do odpytywania wyniku przez [API zapytań o zadania Maestro](/pl/guides/maestro/maestro_tasks):

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d"
}'
```

Po zakończeniu zadania zostaną zwrócone informacje o jednym gotowym filmie (znajdujące się w tablicy `variants`). `status` przejdzie przez `pending → planning → producing → succeeded` (lub `failed`), **odpytywanie jest bezpłatne i nie zużywa punktów**. Pełny format odpowiedzi oraz zapytania o listę historii znajdziesz w [instrukcji integracji API zapytań o zadania Maestro](/pl/guides/maestro/maestro_tasks).

## Rozliczanie

**Po pomyślnym wykonaniu zadania opłata naliczana jest według rzeczywistej długości dostarczonego gotowego filmu, niepowodzenie nie powoduje pobrania opłaty.** Czas rozliczeniowy jest liczony w pełnych sekundach i nie przekracza żądanego czasu; gdy nie można odczytać długości gotowego filmu, stosowany jest żądany czas. Samo przesłanie zadania nie jest rozliczane osobno, odpytywanie `/maestro/tasks` jest bezpłatne.

```
punkty = rzeczywista liczba rozliczanych sekund × 0.7
```

Wszystkie scenariusze, działania i języki korzystają z tej samej ceny, bez mnożników scenariuszy ani dopłat za język. Każde zadanie dostarcza tylko jeden gotowy film w jednym języku. Żądany docelowy czas trwania obsługuje od 5 do 300 sekund, ujednolicony wynik to 1080p / 30fps.

| Rzeczywisty czas rozliczeniowy | Punkty |
| ------------------- | --: |
| 30 sekund           |  21 |
| 60 sekund           |  42 |
| 120 sekund          |  84 |
| 300 sekund          | 210 |
| Odpytywanie `/maestro/tasks` | bezpłatne |

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 invalid_request`: Nieprawidłowe żądanie, prawdopodobnie z powodu braku `prompt` lub nieprawidłowych parametrów.
- `401 invalid_token`: Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `403 forbidden`: Dostęp zabroniony, niewystarczające saldo lub uprawnienia.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit częstotliwości.
- `500 api_error`: Wewnętrzny błąd serwera, coś poszło nie tak na serwerze.

### Przykład odpowiedzi błędu

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
