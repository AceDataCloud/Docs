Maestro to **natywny dla Agentów** interfejs produkcji wideo: używasz jednego naturalnego językowego `prompt`, aby opisać wideo, które chcesz stworzyć (opcjonalnie dołączając obrazy / wideo / audio referencyjne za pomocą `file_urls`), a bezgłowy „reżyser AI” automatycznie wykona wybór tematu, napisze scenariusz, wygeneruje obraz, lektora, muzykę, kompozycję i renderowanie, ostatecznie tworząc gotowy film z napisami i przesyłając go do CDN.

Ten artykuł szczegółowo przedstawia instrukcję integracji API generowania wideo Maestro, pomagając szybko zintegrować i w pełni wykorzystać możliwości tego API.

To interfejs **zadań asynchronicznych**: po przesłaniu natychmiast zwracany jest `task_id`, a następnie wyniki są pobierane przez odpytywanie za pomocą [API zapytania o zadania Maestro](/pl/guides/maestro/maestro_tasks) (`POST /maestro/tasks`) (odpytywanie jest bezpłatne i nie jest naliczane). Aby kontynuować iterację na istniejącym wideo, możesz użyć `action: remix` / `edit` / `extend` wraz z `ref_task_id`.

## Proces składania wniosku

Aby korzystać z API generowania wideo Maestro, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany ani zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i zalogowania się, a po zakończeniu automatycznie powrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności składania osobnego wniosku dla każdej usługi.** Przy pierwszym wniosku otrzymasz darmowy limit, umożliwiający bezpłatne wypróbowanie; gdy limit jest niewystarczający, możesz doładować wspólne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [API generowania wideo Maestro →](https://platform.acedata.cloud/documents/maestro-videos)

## Podstawowe użycie

`POST https://api.acedata.cloud/maestro/videos`

Najbardziej podstawowe użycie wymaga jedynie przekazania naturalnego językowego `prompt`, a reżyser AI automatycznie zdecyduje o scenariuszu, obrazie, lektorze i montażu. Tutaj najpierw zapoznamy się z nagłówkami żądania i treścią żądania, które należy ustawić.

**Request Headers** obejmują:

- `accept`: format odpowiedzi, który chcesz otrzymać, tutaj wpisz `application/json`, czyli format JSON.
- `authorization`: klucz do wywołania API, po złożeniu wniosku możesz go bezpośrednio wybrać z listy rozwijanej.
- `content-type`: format treści żądania, tutaj wpisz `application/json`.

**Request Body** obejmuje głównie:

- `prompt`: opisz w naturalnym języku wideo do stworzenia (temat, co ma zostać pokazane, styl, odbiorcy).
- `langs`: tablica języków gotowego filmu, za każdym razem przekazuj tylko jeden, np. `["zh-cn"]`, domyślnie `["zh-cn"]`.
- `aspect`: proporcje obrazu, `9:16` (domyślnie) / `16:9` / `1:1`.
- `duration`: docelowy czas trwania (sekundy), domyślnie 30.

Wszystkie pola treści żądania przedstawiono w poniższej tabeli:

| Pole            | Typ       | Wymagane  | Opis                                                                                                                                                                                                                                    |
| ------------- | -------- | --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`      | string   | Tak   | Opisz w naturalnym języku wideo do stworzenia (temat, co ma zostać pokazane, styl, odbiorcy). Scenariusz, obraz, lektor i montaż są określane przez AI                                                                                                                                                                                      |
| `action`      | string   | Nie   | `generate` (domyślnie, generowanie nowego wideo) / `remix` / `edit` / `extend` (iteracja na istniejącym wideo, wymaga użycia z `ref_task_id`)                                                                                                                                                         |
| `ref_task_id` | string   | Nie   | Wymagane, gdy `action` to remix / edit / extend: `task_id` historycznego zadania używany jako punkt początkowy                                                                                                                                                                            |
| `file_urls`   | string[] | Nie   | Media referencyjne (obrazy / wideo / audio URL), na przykład obraz produktu, logo, które ma pojawić się w kadrze, lub fragment materiału, do którego należy dodać napisy                                                                                                                                                                                      |
| `langs`       | string[] | Nie   | Język gotowego filmu, za każdym razem można przekazać tylko jeden, np. `["zh-cn"]`, domyślnie `["zh-cn"]`                                                                                                                                                                                             |
| `aspect`      | string   | Nie   | `9:16` (domyślnie) / `16:9` / `1:1`, jednolity wynik 1080p/30fps                                                                                                                                                                                           |
| `duration`    | int      | Nie   | Docelowy czas trwania (sekundy), domyślnie 30, obsługuje **5–300 sekund**. Opłata jest naliczana według rzeczywistego czasu trwania gotowego filmu, ale nie przekroczy czasu żądanego                                                                                                                                                                                      |
| `scenario`    | string   | Nie   | Typ wideo: `auto` / `narrated` / `captions` / `avatar` / `drama`. `captions` wymaga przekazania źródłowego wideo, `avatar` wymaga przekazania portretu                                                                                                                                             |
| `style`       | string   | Nie   | Ustawienie wizualnego stylu: `auto` (domyślnie) / `cinematic` / `glass` / `luxury` / `swiss` / `modern` / `editorial` / `warm` / `vibrant` / `neon` / `mono` / `pastel` / `bold` / `industrial` / `futuristic` / `retro`, akceptuje również dowolny tekst jako miękką wskazówkę. Jest ortogonalne względem `scenario` i nie zmienia routingu          |
| `voice`       | string   | Nie   | Barwa głosu lektora (niezależna od języka, uniwersalna między językami): `auto` (domyślnie) / `warm-female` / `bright-female` / `anchor-female` / `clean-female` / `calm-male` / `deep-male` / `documentary-male` / `energetic-male` / `storyteller-male`; obsługuje również 32-bitowe szesnastkowe `reference_id` barwy głosu, inne dowolne teksty nie są prawidłowymi ID barwy głosu |

Poniżej zademonstrujemy to na konkretnym przykładzie. Załóżmy, że chcemy wygenerować 20-sekundowe popularnonaukowe krótkie wideo po chińsku, w orientacji pionowej. Odpowiedni kod CURL jest następujący:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
  "langs": ["zh-cn"],
  "aspect": "9:16",
  "duration": 20
}'
```

Odpowiedni kod Python jest następujący:

```python
import requests

url = "https://api.acedata.cloud/maestro/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": ["zh-cn"],
    "aspect": "9:16",
    "duration": 20
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Kliknij uruchom, a zauważysz, że natychmiast otrzymasz wynik, jak poniżej:

```json
{
  "success": true,
  "task_id": "f57e99c4f60f4373a15517742ce2357d",
  "trace_id": "70e1cb12-c619-4292-a416-90191205996b"
}
```

Opis pól wyniku zwróconego jest następujący:
- `success`: czy to zadanie zostało pomyślnie przesłane.
- `task_id`: ID tego zadania generowania wideo, używane później do odpytywania wyników przez [API zapytań o zadania Maestro](/pl/guides/maestro/maestro_tasks).
- `trace_id`: ID śledzenia tego żądania, które można przekazać wsparciu technicznemu w przypadku problemów w celu ich zlokalizowania.

Ze względu na długi czas produkcji wideo interfejs **natychmiast zwraca `task_id`** i nie czeka na zakończenie renderowania wideo. Następnie należy użyć `task_id` do odpytywania wyników; szczegóły znajdziesz w sekcji „Pobieranie wyników”.

## Określanie typu i stylu wideo (scenario / style)

Jeśli `scenario` nie zostanie przekazane, AI określi je automatycznie (równoznaczne z `auto`); jeśli chcesz przypisać wideo do określonego typu, przekaż je jawnie. Na przykład, aby stworzyć **pionowy krótki dramat**, można określić następujące wartości:

- `scenario`: typ wideo, tutaj ustawiony na `drama` (krótki dramat z postaciami + dialogami).
- `style`: styl wizualny, tutaj ustawiony na `cinematic` (kinowa jakość).

Przykładowy kod CURL do wypełnienia jest następujący:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "两个合租室友因为一只猫闹翻又和好，三幕反转，结尾温暖",
  "scenario": "drama",
  "style": "cinematic",
  "aspect": "9:16",
  "duration": 40
}'
```

Typowe sposoby łączenia:

- Krótki film z narracją: `scenario: "narrated"`.
- Automatyczne napisy: `scenario: "captions"`, należy przekazać źródłowe wideo przez `file_urls`.
- Cyfrowy awatar / wypowiedź do kamery: `scenario: "avatar"`, należy przekazać jedno zdjęcie portretowe przez `file_urls`.
- Krótki dramat: `scenario: "drama"` (postacie + dialogi).
- `style` to ustawienie wstępne stylu wizualnego (np. `modern` / `neon` / `luxury`), nie zmienia typu, a jedynie wpływa na odbiór wizualny.
- `voice` służy do określenia barwy głosu narratora (np. `warm-female` / `deep-male`), jest niezależne od języka i uniwersalne między językami.

Wynik zwracany jest tak samo jak w „Podstawowym użyciu”, również natychmiast zwracany jest `task_id`.

## Język gotowego wideo

Jedno zadanie dostarcza tylko jedno gotowe wideo w jednym języku. `langs` może zawierać tylko jeden kod języka, na przykład `["zh-cn"]` lub `["en"]`; przekazanie wielu języków zwróci 400. Jeśli potrzebujesz wideo w różnych językach, utwórz osobne zadania. Wybór języka nie zmienia ceny za sekundę.

## Iterowanie na istniejącym wideo (remix / edit / extend)

Przekaż `action` oraz `ref_task_id` poprzedniego zadania, aby wprowadzić przyrostowe zmiany na podstawie oryginalnego projektu (np. „zmień tytuł sceny 2”, „zmień dubbing”, „ogólnie przyciemnij”). Małe zmiany są szybkie, duże zmiany powodują ponowne wykonanie:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "remix",
  "ref_task_id": "f57e99c4f60f4373a15517742ce2357d",
  "prompt": "把开场标题换成更有冲击力的一句，整体配色更暗一些"
}'
```

- `remix`: ponowna interpretacja na podstawie struktury oryginalnego wideo (zachowuje temat, dostosowuje formę).
- `edit`: precyzyjna edycja określonego fragmentu (np. zmiana tytułu, dubbingu, korekcja kolorów).
- `extend`: rozszerzenie treści na podstawie oryginalnego wideo.

Wynik również natychmiast zwraca nowy `task_id`; użyj go do odpytywania, aby uzyskać gotowe wideo po iteracji.

## Pobieranie wyników

Ze względu na długi czas produkcji wideo ten interfejs natychmiast zwraca `task_id` po przesłaniu; należy użyć go do odpytywania wyników przez [API zapytań o zadania Maestro](/pl/guides/maestro/maestro_tasks):

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d"
}'
```

Po zakończeniu zadania zwrócona zostanie informacja o jednym gotowym wideo (znajdująca się w tablicy `variants`). `status` przechodzi przez `pending → planning → producing → succeeded` (lub `failed`), **odpytywanie jest bezpłatne i nie zużywa punktów**. Pełny format odpowiedzi oraz zapytania o listę historii znajdziesz w [instrukcji integracji API zapytań o zadania Maestro](/pl/guides/maestro/maestro_tasks).

## Rozliczenia

**Po pomyślnym wykonaniu zadania opłata jest naliczana według rzeczywistego czasu trwania dostarczonego gotowego wideo; za niepowodzenie nie jest pobierana opłata.** Czas rozliczeniowy jest liczony w pełnych sekundach i nie przekracza żądanego czasu trwania; jeśli nie można odczytać czasu trwania gotowego wideo, używany jest żądany czas trwania. Samo przesłanie zadania nie jest rozliczane osobno, a odpytywanie `/maestro/tasks` jest bezpłatne.

```
punkty = rzeczywista liczba rozliczanych sekund × 0.7
```

Wszystkie scenariusze, działania i języki mają tę samą cenę, bez mnożników scenariusza ani dopłat za język. Każde zadanie dostarcza tylko jedno gotowe wideo w jednym języku. Żądany czas trwania obsługuje od 5 do 300 sekund, z jednolitym wyjściem 1080p / 30fps.

| Rzeczywisty czas rozliczeniowy | Punkty |
| ------------------- | --: |
| 30 sekund           |  21 |
| 60 sekund           |  42 |
| 120 sekund          |  84 |
| 300 sekund          | 210 |
| Odpytywanie `/maestro/tasks` | bezpłatne |

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informację. Na przykład:

- `400 invalid_request`: Nieprawidłowe żądanie, prawdopodobnie z powodu braku `prompt` lub nieprawidłowych parametrów.
- `401 invalid_token`: Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `403 forbidden`: Dostęp zabroniony, niewystarczające saldo lub uprawnienia.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`: Wewnętrzny błąd serwera, coś poszło nie tak na serwerze.

### Przykład odpowiedzi błędu

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
