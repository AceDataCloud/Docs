Kimi to seria modeli AI opracowana przez Moonshot AI. Obecnie zalecany jest model `kimi-k3.1-pro`, odpowiedni do długotrwałego programowania, złożonego wnioskowania, rozumienia obrazów i pracy z wiedzą; model `kimi-k3` jest nadal dostępny. Wywołania odbywają się za pośrednictwem zgodnego z OpenAI interfejsu Chat Completions API.

Niniejszy dokument przedstawia przede wszystkim procedurę korzystania z Kimi Chat Completion API. Dzięki niemu możemy z łatwością korzystać z oficjalnej funkcji konwersacji Kimi.

## Obsługiwane modele

Obecnie obsługiwane są cztery modele: `kimi-k3.1-pro`, `kimi-k3`, `kimi-k2.6` i `kimi-k2.7-code`. K2.7 Code jest przeznaczony do programowania i wywoływania narzędzi, a jego rozliczanie odbywa się według tej samej stawki co K2.6; w żądaniu nie należy przekazywać mu przełącznika `thinking` ani parametru `reasoning_effort`. Obsługa pozostałych modeli Kimi została zakończona, dlatego w kliencie należy jawnie wybrać jeden z tych czterech modeli.

## Proces uzyskiwania dostępu

Aby korzystać z Kimi Chat Completion API, należy najpierw przejść do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać token API, który będzie potrzebny później.

![]()

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, nastąpi automatyczne przekierowanie na stronę logowania, na której będzie można się zarejestrować i zalogować. Po zakończeniu procesu automatycznie powrócisz na bieżącą stronę.

**Jeden token API wystarczy do korzystania ze wszystkich usług platformy. Nie ma potrzeby składania osobnych wniosków dla każdej usługi.** Przy pierwszym uzyskaniu dostępu otrzymasz bezpłatny limit środków, dzięki czemu możesz bezpłatnie przetestować usługę; gdy limit okaże się niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Podstawowe użycie

Następnie możesz wypełnić odpowiednie pola w interfejsie, jak pokazano na ilustracji:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

Przy pierwszym korzystaniu z tego interfejsu należy wypełnić co najmniej trzy pola: `authorization` można wybrać bezpośrednio z listy rozwijanej; `model` służy do wyboru modelu Kimi, zalecany jest `kimi-k3.1-pro`; `messages` to tablica wiadomości konwersacji, w której każda wiadomość zawiera pola `role` i `content`, a pole `role` obsługuje wartości `user`, `assistant`, `system` i `tool`.

Możesz również zauważyć, że po prawej stronie generowany jest odpowiedni kod wywołania. Możesz skopiować kod i uruchomić go bezpośrednio albo kliknąć przycisk „Try”, aby przeprowadzić test.

Poniżej znajduje się rzeczywista odpowiedź K3 uzyskana przy użyciu `reasoning_effort: max` (pominięto nieużywane pola rozszerzone):

```json
{
```

Wynik zawiera kilka pól, których znaczenie przedstawiono poniżej:

- `id` – identyfikator wygenerowanego zadania konwersacji, służący do jego jednoznacznej identyfikacji.
- `model ` – wybrany model z oficjalnej strony Kimi.
- `choices` – informacje o odpowiedzi udzielonej przez Kimi na zadane pytanie.
- `usage ` – statystyki dotyczące liczby tokenów wykorzystanych w bieżącej wymianie.

Pole `choices` zawiera informacje o odpowiedzi Kimi. Znajdujące się w nim `choices` zawiera szczegółowe informacje o odpowiedzi Kimi, co można zauważyć na poniższej ilustracji.

Jak widać, pole `content` w `choices` zawiera konkretną treść odpowiedzi Kimi; K3 może również zwracać `reasoning_content`, który przedstawia proces wnioskowania.

## Intensywność wnioskowania K3.1 Pro

Model `kimi-k3.1-pro` zawsze ma włączone wnioskowanie. W głównym obiekcie żądania można ustawić parametr `reasoning_effort` na `low`, `high` lub `max`; nie należy przekazywać konfiguracji wyłączającej wnioskowanie. Model obsługuje kontekst o maksymalnej długości 1 048 576 tokenów, jednak rzeczywisty limit żądania nadal zależy od bieżącego interfejsu API. Opłaty są naliczane na podstawie wykorzystania tokenów wejściowych, wyjściowych i trafień pamięci podręcznej. Szczegóły można znaleźć na karcie Pricing w katalogu modeli.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Poniższe przykłady K3 pozostawiono z myślą o istniejących integracjach, a przedstawiona przykładowa odpowiedź rzeczywiście pochodzi z żądania K3.

## Intensywność wnioskowania K3

Model `kimi-k3` zawsze ma włączone wnioskowanie. Główny obiekt żądania obsługuje pole `reasoning_effort`, którego jedyną obecnie obsługiwaną wartością jest `max`; pominięcie tego pola również oznacza użycie wartości `max`. Należy korzystać z obsługiwanej wartości.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

W przypadku korzystania z OpenAI SDK można bezpośrednio przekazać to pole:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

W przypadku wieloetapowych konwersacji i wywoływania narzędzi należy przekazać z powrotem do `messages` pełną wiadomość assistant z poprzedniej tury, w tym `reasoning_content` i `tool_calls`.

### Oficjalne materiały referencyjne

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort)：wyjaśnia, że Kimi K3 zawsze ma włączone wnioskowanie, a jedyną obecnie obsługiwaną wartością `reasoning_effort` jest `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview)：porównuje parametry wnioskowania, okna kontekstowe i różnice w wywoływaniu narzędzi między serią K3 a K2.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat)：oficjalna dokumentacja Moonshot dotycząca żądań i odpowiedzi Chat Completions oraz definicji pól OpenAPI.

## Odpowiedź strumieniowa

Ten interfejs obsługuje również odpowiedzi strumieniowe, co jest bardzo przydatne przy integracji ze stronami internetowymi, ponieważ pozwala uzyskać efekt wyświetlania tekstu znak po znaku.

Aby otrzymywać odpowiedzi w trybie strumieniowym, można zmienić parametr `stream ` w nagłówku żądania na `true`.

Zmianę należy wprowadzić zgodnie z poniższą ilustracją. Kod wywołania również wymaga odpowiednich modyfikacji, aby obsługiwać odpowiedzi strumieniowe.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>
Po zmianie wartości `stream` na `true` API będzie zwracać odpowiednie dane JSON wiersz po wierszu. Na poziomie kodu musimy wprowadzić odpowiednie modyfikacje, aby uzyskać wyniki przesyłane wiersz po wierszu.

Przykładowy kod wywołania w Pythonie:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Poniżej przedstawiono wybrane bloki danych z początku, etapu rozumowania, treści głównej, zakończenia i informacji o zużyciu tokenów z tej samej rzeczywistej odpowiedzi strumieniowej K3 Max:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

```

Jak widać, odpowiedź zawiera wiele pól `data`, a `choices` znajdujące się w polu `data` zawiera najnowszą treść odpowiedzi, zgodnie z opisem przedstawionym powyżej. `choices` zawiera nowo wygenerowaną treść odpowiedzi, którą można wykorzystać do integracji z własnym systemem. Zakończenie odpowiedzi strumieniowej jest również określane na podstawie zawartości pola `data`. Jeśli jego wartością jest `[DONE]`, oznacza to, że odpowiedź strumieniowa została w całości zakończona. Zwracany wynik `data` zawiera kilka pól, które opisano poniżej:

- `id` – identyfikator wygenerowanego zadania konwersacji, służący do jego jednoznacznej identyfikacji.
- `model ` – wybrany model z oficjalnej strony Kimi.
- `choices` – informacje o odpowiedzi Kimi na zadane pytanie.

Obsługiwany jest również JavaScript. Poniżej przedstawiono przykładowy kod wywołania strumieniowego w Node.js:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Przykładowy kod w języku Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Kod dla innych języków można odpowiednio dostosować samodzielnie. Zasada działania pozostaje taka sama.

## Konwersacja wieloetapowa

Jeśli chcesz zintegrować funkcję konwersacji wieloetapowej, musisz przesłać wiele pytań w polu `messages`. Konkretny przykład wielu pytań przedstawiono na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Przykładowy kod wywołania w Pythonie:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Dzięki przesłaniu wielu pytań można łatwo zrealizować konwersację wieloetapową. Poniżej przedstawiono rzeczywistą odpowiedź K3 Max uzyskaną w wyniku tego żądania (pominięto nieużywane pola rozszerzone):

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i komunikat. Na przykład:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.
