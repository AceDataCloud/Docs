W tym artykule przedstawiono instrukcję integracji Veo Videos Generation API, które może generować oficjalne filmy Veo poprzez wprowadzanie niestandardowych parametrów.

## Proces aplikowania

Aby korzystać z Veo Videos Generation API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachowaj go do późniejszego użycia.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i zalogowania się; po zakończeniu automatycznie powrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności osobnego aplikowania dla każdej usługi.** Przy pierwszym wniosku otrzymasz bezpłatny limit, aby bezpłatnie wypróbować usługę; gdy limit będzie niewystarczający, możesz doładować wspólne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Veo Videos Generation API →](https://platform.acedata.cloud/documents/veo-videos)

## Podstawowe użycie

Najpierw zapoznajmy się z podstawowym sposobem użycia: wystarczy wprowadzić prompt `prompt`, działanie generowania `action`, tablicę obrazów referencyjnych pierwszej i ostatniej klatki `image_urls` oraz model `model`, aby uzyskać przetworzony wynik. Najpierw należy po prostu przekazać pole `action`, którego wartością jest `text2video`; obejmuje ono głównie trzy działania: tekst na wideo (`text2video`), obraz na wideo (`image2video`), pobieranie wideo 1080p (`get1080p`). Następnie musimy również wprowadzić model `model`; obecnie dostępne są głównie modele `veo31-fast`, `veo3`, `veo31`, `veo3-fast` i `veo31-fast-ingredients`, a szczegóły są następujące:

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

Można zauważyć, że ustawiliśmy tutaj Request Headers, w tym:

- `accept`: format odpowiedzi, który chcesz otrzymać; tutaj wpisz `application/json`, czyli format JSON.
- `authorization`: klucz do wywołania API, który po uzyskaniu można bezpośrednio wybrać z listy rozwijanej.

Dodatkowo ustawiliśmy Request Body, w tym:

- `model`: model generowania wideo; dostępne są głównie modele `veo31-fast`, `veo3`, `veo31`, `veo3-fast` i `veo31-fast-ingredients`.
- `action`: działanie dla tego zadania generowania wideo, obejmujące głównie trzy działania: tekst na wideo (`text2video`), obraz na wideo (`image2video`), pobieranie wideo 1080p (`get1080p`).
- `image_urls`: linki do obrazów referencyjnych, które należy przesłać, gdy wybrano działanie obraz na wideo `image2video`. `veo31-fast-ingredients` obsługuje maksymalnie 3 obrazy (łączenie wielu obrazów), a pozostałe modele obsługują maksymalnie 2 obrazy (tryb pierwszej i ostatniej klatki).
- `resolution`: wybór rozdzielczości generowanego wideo; model veo31 obsługuje rozdzielczość 4k, pozostałe modele jej nie obsługują. Wszystkie modele obsługują rozdzielczość 1080p oraz gif; jeśli ta wartość nie zostanie przekazana, domyślnie używana jest rozdzielczość 720p. Główne opcje to: `1080p`, `gif`, `4k`.
- `prompt`: prompt.
- `callback_url`: URL, na który ma zostać zwrócony wynik wywołania zwrotnego.
- `async`: opcjonalne; po ustawieniu na `true` interfejs natychmiast zwraca `task_id`, bez konieczności podawania `callback_url`, a następnie wynik można uzyskać przez odpytywanie odpowiedniego interfejsu zapytania o zadanie.

### 📌 Podsumowanie opisu modeli

| **Nazwa modelu**            | **Obsługiwane tryby**                              | **Zasady wprowadzania obrazów**                    |
| -------------------------- | --------------------------------- | --------------------------------- |
| **veo3-fast**              | Tekst na wideo (bez obrazu)<br />Tryb obraz na wideo (z obrazem) | **1 obraz** → tryb pierwszej klatki<br />**2 obrazy** → tryb pierwszej i ostatniej klatki |
| **veo31-fast**             | Tekst na wideo (bez obrazu)<br />Tryb obraz na wideo (z obrazem) | **1 obraz** → tryb pierwszej klatki<br />**2 obrazy** → tryb pierwszej i ostatniej klatki |
| **veo31-fast-ingredients** | ❌ Tekst na wideo (nieobsługiwane)<br />✅ **Wymuszone łączenie wielu obrazów** (obrazy muszą zostać przekazane) | **1-3 obrazy** → tryb łączenia wielu obrazów (maksymalnie 3 obrazy) |
| **veo3**                   | Tekst na wideo (bez obrazu)<br />Tryb obraz na wideo (z obrazem) | **1 obraz** → tryb pierwszej klatki<br />**2 obrazy** → tryb pierwszej i ostatniej klatki |
| **veo31**                  | Tekst na wideo (bez obrazu)<br />Tryb obraz na wideo (z obrazem) | **1 obraz** → tryb pierwszej klatki<br />**2 obrazy** → tryb pierwszej i ostatniej klatki |

---

### 🔑 Opis kluczowych zasad

1. **Ogólna logika**:
   - **Brak obrazu wejściowego** → automatycznie uruchamia tryb tekst na wideo.
   - **Obraz wejściowy obecny** → uruchamia tryb obraz na wideo (konkretne działanie zależy od liczby obrazów).
2. **Typy trybu obraz na wideo**:
   - **Tryb pierwszej klatki** (1 obraz): pierwsza klatka jest ustalona jako obraz wejściowy.
   - **Tryb pierwszej i ostatniej klatki** (2 obrazy): pierwsza i ostatnia klatka są ustalone jako obrazy wejściowe.
   - **Tryb łączenia wielu obrazów** (1-3 obrazy): obsługiwany wyłącznie przez `veo31-fast-ingredients`, łączy zawartość wielu obrazów w celu wygenerowania wideo.
3. **Klasyfikacja trybów**:

  - **Tryb Fast**: `veo3-fast`, `veo31-fast`, `veo31-fast-ingredients`.
   - **Tryb Quality**: `veo3`, `veo31` (wyższa jakość generowania).

---

### ⚠️ Uwagi

- **Jedyny model z obowiązkowym przekazaniem obrazu**: do `veo31-fast-ingredients` należy przekazać obrazy (1-3), w przeciwnym razie nie będzie mógł działać.
- **Limit liczby obrazów**:
  - `veo31-fast-ingredients` obsługuje wejście **1-3 obrazów** (tryb łączenia wielu obrazów).
  - Pozostałe modele obsługują maksymalnie **2 obrazy** wejściowe (tryb pierwszej i ostatniej klatki).

## Funkcja generowania wideo z obrazu

Jeśli chcesz wygenerować wideo na podstawie obrazów pierwszej i ostatniej klatki, możesz ustawić parametr `action` na `image2video` i wprowadzić tablicę linków do obrazów pierwszej i ostatniej klatki `image_urls`.

Następnie musimy wypełnić podpowiedzi, które należy rozszerzyć w kolejnym kroku, aby dostosować generowane wideo, można określić następującą zawartość:

- `model`：model do generowania wideo, głównie `veo31-fast`、`veo3`、`veo31`、`veo3-fast` i `veo31-fast-ingredients`。
- `image_urls`：gdy wybierzesz działanie generowania wideo z obrazu `image2video`, wymagane są linki do przesłanych obrazów referencyjnych.
- `prompt`：podpowiedź.

Przykład wypełnienia jest następujący:

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

Po wypełnieniu kod jest automatycznie generowany w następujący sposób:

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

Odpowiedni kod Python:

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo31-fast",
    "prompt": "Let it dance",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

- `model`：model do generowania wideo, głównie `veo31-fast`、`veo3`、`veo31`、`veo3-fast` i `veo31-fast-ingredients`。

## Asynchroniczne wywołanie zwrotne

Ponieważ czas generowania przez Veo Videos Generation API jest stosunkowo długi i wynosi około 1–2 minut, jeśli API przez długi czas nie odpowiada, żądanie HTTP będzie stale utrzymywać połączenie, co prowadzi do dodatkowego zużycia zasobów systemowych, dlatego to API obsługuje również asynchroniczne wywołania zwrotne.

Ogólny proces wygląda następująco: gdy klient inicjuje żądanie, dodatkowo określa pole `callback_url`; po wysłaniu przez klienta żądania API, API natychmiast zwróci wynik zawierający pole `task_id`, które reprezentuje ID bieżącego zadania. Po zakończeniu zadania wynik wygenerowanego wideo zostanie wysłany w formie POST JSON na określony przez klienta `callback_url`, zawierając również pole `task_id`, dzięki czemu wyniki zadania można powiązać za pomocą ID.

Dla wygody demonstracji użyjemy publicznej przykładowej strony Webhook https://webhook.site/; po otwarciu tej strony można uzyskać adres URL Webhook, jak pokazano na ilustracji:

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i komunikat. Na przykład:

- `400 token_mismatched`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`：Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`：Zbyt wiele żądań, przekroczono limit częstotliwości.
- `500 api_error`：Wewnętrzny błąd serwera, coś poszło nie tak na serwerze.

### Przykład odpowiedzi błędu

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
