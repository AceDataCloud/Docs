W tym artykule przedstawimy dokumentację integracji API zmiany wieku twarzy, które pozwala na zmianę wieku twarzy na zdjęciu poprzez wprowadzenie obrazu i wieku. Ogólny sposób użycia polega na tym, że użytkownik przesyła zdjęcie twarzy, a na podstawie algorytmu edycji i generowania twarzy, otrzymuje zdjęcie twarzy, które wygląda na starsze lub młodsze, wspierając realizację zmian wieku twarzy.

## Proces aplikacji

Aby skorzystać z API, należy najpierw przejść do strony [API zmiany wieku twarzy](https://platform.acedata.cloud/documents/face-change-age) i złożyć wniosek o odpowiednią usługę. Po wejściu na stronę, kliknij przycisk „Acquire”, jak pokazano na obrazku:

![](https://cdn.acedata.cloud/q6ytrc.png)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować. Po zalogowaniu lub rejestracji, automatycznie wrócisz na bieżącą stronę.

Podczas pierwszej aplikacji otrzymasz darmowy limit, który pozwala na bezpłatne korzystanie z tego API.

## Podstawowe użycie

Najpierw zapoznaj się z podstawowym sposobem użycia, czyli wprowadzeniem linku do obrazu oraz informacji o wieku, aby uzyskać przetworzony obraz. Najpierw musisz przekazać prosty parametr `image_url`, a zdjęcie twarzy wygląda jak na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/f5687u.png" width="500" className="m-auto" /></p>

Następnie musimy przesłać informacje o wieku twarzy w parametrze `age_infos`, który jest tablicą, w której możemy podać wiele informacji. Następnie możemy wypełnić odpowiednie treści na interfejsie, jak pokazano na obrazku:

<p><img src="https://cdn.acedata.cloud/cn95e8.png" width="500" className="m-auto" /></p>

Możemy zobaczyć, że ustawiliśmy nagłówki żądania, w tym:

- `accept`: jakiego formatu odpowiedzi oczekujemy, tutaj wpisujemy `application/json`, czyli format JSON.
- `authorization`: klucz do wywołania API, po złożeniu wniosku można go bezpośrednio wybrać z rozwijanej listy.

Dodatkowo ustawiono ciało żądania, w tym:

- `image_url`: link do przetwarzanej twarzy.
- `age_infos`: informacje o wieku i obszarze twarzy, gdzie wiek jest parametrem obowiązkowym.

Po dokonaniu wyboru, można zauważyć, że po prawej stronie wygenerowano odpowiedni kod, jak pokazano na obrazku:

<p><img src="https://cdn.acedata.cloud/zk8qkl.png" width="500" className="m-auto" /></p>

Kliknij przycisk „Try”, aby przeprowadzić test, jak pokazano na powyższym obrazku, a otrzymamy następujący wynik:

```json
{
  "image_url": "https://faceeffect-1254418846.cos.ap-guangzhou.myqcloud.com/ft/ChangeAgePic/1256437459/bfce1ab8-5fd7-464d-8878-b38433f84d0e"
}
```

Możemy zobaczyć, że w zwróconym wyniku znajduje się pole `image_url`, które zawiera zdjęcie twarzy po zmianie wieku. Zmiana wieku twarzy wygląda jak na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/01rmiv.png" width="500" className="m-auto" /></p>

Możemy zauważyć, że twarz na zdjęciu zmieniła się w zależności od wprowadzonego wieku.

Jeśli chcesz wygenerować odpowiedni kod integracyjny, możesz go bezpośrednio skopiować, na przykład kod CURL wygląda następująco:

```shell
curl -X POST 'https://api.acedata.cloud/face/change-age' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "age_infos": [{"age":60}],
  "image_url": "https://cdn.acedata.cloud/f5687u.png"
}'
```

Kod integracyjny w Pythonie wygląda następująco:

```python
import requests

url = "https://api.acedata.cloud/face/change-age"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "age_infos": [{"age":60}],
    "image_url": "https://cdn.acedata.cloud/f5687u.png"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Obsługa błędów

Podczas wywoływania API, jeśli napotkasz błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Nieautoryzowany, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit.
- `500 api_error`: Błąd wewnętrzny serwera, coś poszło nie tak na serwerze.

### Przykład odpowiedzi błędu

```json
{
  "success": false,
  "error": {

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
