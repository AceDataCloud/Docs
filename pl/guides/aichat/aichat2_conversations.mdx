AI Chat v2 API (`/aichat2/conversations`) jest interfejsem konwersacyjnym nowej generacji i kompleksowo ulepszoną wersją [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Na podstawie prostoty v1 i zarządzanych wieloturowych rozmów rozszerza on:

- **Wielomodalne dane wejściowe użytkownika**: poprzez ustrukturyzowane pole `message` można bezpośrednio przekazywać bloki tekstu + obrazów + plików, bez konieczności wcześniejszego pośredniego dołączania ich za pomocą `references`.
- **Wywoływanie narzędzi w stylu Agent**: wbudowany zestaw narzędzi do wyszukiwania w internecie, pobierania stron internetowych, odczytu plików itp. oraz możliwość podłączenia autoryzowanych przez użytkownika serwerów MCP (Google Drive, Notion, Slack, GitHub itd.); model może w jednym żądaniu autonomicznie wielokrotnie wywoływać narzędzia, aby wykonywać złożone zadania.
- **Ustrukturyzowane zdarzenia strumieniowe**: za pomocą `accept: text/event-stream` lub `application/x-ndjson` można uzyskać zdarzenia takie jak `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` itp. dla kolejnych tokenów, co ułatwia osobne renderowanie ich według odpowiednich typów w interfejsie frontendowym.
- **Możliwość przerwania / wznowienia**: gdy model potrzebuje, aby użytkownik uzupełnił informacje, wyśle zdarzenie `ask_user_question` i wstrzyma działanie; przy następnym wywołaniu można kontynuować, uzupełniając odpowiedź przez `tool_results`.
- **Nowe działania CRUD**: w tym samym endpointcie można wykonywać `retrieve` / `retrieve_batch` / `update` / `delete` za pomocą pola `action`, bez potrzeby dodatkowego API do zarządzania rozmowami.
- **Stale aktualizowana lista modeli**: domyślnie obsługiwane są współczesne modele, takie jak GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 itd.

Jednocześnie na poziomie body żądania jest on **w pełni wstecznie kompatybilny z v1**: wystarczy przekazać `model` + `question` (+ opcjonalnie `stateful` / `id` / `references` / `preset`), aby uzyskać odpowiedź JSON `{answer, id}` równoważną z v1. Dlatego migracja z `/aichat/conversations` nie wymaga przepisywania klienta — wystarczy zmienić ścieżkę na `/aichat2/conversations`.

> Jeśli obecnie korzystasz z `/aichat/conversations`, stary interfejs nadal będzie dostępny, więc możesz migrować we własnym tempie.

## Proces składania wniosku

Aby korzystać z AI Chat v2 API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany(-a) lub zarejestrowany(-a), nastąpi automatyczne przekierowanie na stronę logowania, gdzie zostaniesz zaproszony(-a) do rejestracji i zalogowania się; po zakończeniu automatycznie wrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności osobnego składania wniosku dla każdej usługi.** Przy pierwszym wniosku otrzymasz darmowy limit, który umożliwi bezpłatne testowanie; gdy limit będzie niewystarczający, możesz doładować wspólne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

## Podstawowe użycie

Najprostszy sposób użycia jest całkowicie taki sam jak w v1: przekaż `model` + `question`, aby otrzymać `{answer, id}`.

Przykład CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Wynik zwracany:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Przykład Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Rozmowy wieloturowe

Tak jak w v1, przekaż `stateful: true`, aby włączyć zapisywanie rozmowy; API zwróci `id`; w kolejnych żądaniach wystarczy przekazać z powrotem `id`, aby kontynuować rozmowę, bez samodzielnego utrzymywania historii messages.

Pierwsze żądanie:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Zwraca:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Drugie żądanie, z tym samym `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` domyślnie ma wartość `true`; pominięcie go jest równoważne z jawnym przekazaniem `true`. Jeśli nie chcesz, aby serwer zapisywał tę turę rozmowy, możesz jawnie ustawić `stateful: false`.

## Odpowiedzi strumieniowe

v2 obsługuje dwa formaty strumieniowe, wybierane za pomocą nagłówka `accept`:

| Scenariusz                    | `accept`               | Forma danych                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Frontend Web / EventSource  | `text/event-stream`    | `data: {json}\n\n`, ostatnia linia: `data: [DONE]\n\n` |
| Serwer / CLI / analiza strumieniowa Node | `application/x-ndjson` | Jeden obiekt JSON w każdej linii                               |
| Strumieniowanie nie jest potrzebne                 | `application/json`（domyślnie） | Jednorazowo zwraca `{answer, id}`                       |

### Przykład NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Każda linia NDJSON jest ustrukturyzowanym zdarzeniem; najczęściej występuje `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Przykład SSE

`EventSource` po stronie przeglądarki nie obsługuje niestandardowego treści żądania, zaleca się użycie `fetch` + ręczne analizowanie przez dzielenie według `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Typy zdarzeń strumieniowych

| `type`              | Znaczenie                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `text_delta`        | Przyrostowy fragment tekstu odpowiedzi asystenta. `content` zawiera nową treść; dla zgodności z v1 to samo zdarzenie zawiera także `delta_answer` (równe `content`) oraz `id`.                  |
| `thinking`          | Proces rozumowania modelu (pojawia się tylko wtedy, gdy wybrany model udostępnia reasoning).                                                                |
| `tool_use`          | Model decyduje się wywołać narzędzie; zdarzenie zawiera `tool_id`, `tool_name`, `input`.                                                  |
| `tool_result`       | Wynik wykonania narzędzia, sparowany z poprzednim `tool_use` za pomocą `tool_id`; `is_error` wskazuje, czy wystąpił błąd.                                       |
| `card`              | Ustrukturyzowana karta wygenerowana przez narzędzie (np. obraz, podgląd linku), odpowiednia do bezpośredniego renderowania.                                                                    |
| `citation`          | Adres URL źródła używany do uzupełnienia cytowania odpowiadającego fragmentu tekstu.                                                                            |
| `ask_user_question` | Emitowane, gdy model potrzebuje od użytkownika dodatkowych informacji; rozmowa przechodzi w stan `awaiting_user_input`; szczegóły poniżej w [Wznawianie wstrzymanej rozmowy](#恢复暂停的对话).                           |
| `artifact`          | Niezależny artefakt wygenerowany przez model (np. blok kodu, dokument), który można zapisać lub pobrać.                                                                      |
| `system_message`    | Komunikat systemowy (nie treść użytkownika ani asystenta), używany wyłącznie jako wskazówka dla UI.                                                                     |
| `compact`           | Zdarzenie, w którym wewnętrzny kontekst został skompresowany, niewymagające specjalnej obsługi.                                                                             |
| `error`             | W tej turze wystąpił błąd; `message` opisuje jego treść.                                                                        |
| `done`              | Odpowiedź strumieniowa zakończona; zawiera `usage` (w tym `prompt_tokens` / `completion_tokens` / `total_tokens`) oraz `terminal_reason`. |

W przypadku klientów, których interesuje tylko końcowa odpowiedź, połączenie wszystkich `content` z `text_delta` jest równoważne z `answer` w trybie `application/json`.

## Wejście multimodalne

Jeśli dane wejściowe użytkownika zawierają obrazy lub pliki, przekaż `message` (tablicę) zamiast `question`. Każdy element tablicy jest blokiem zawartości:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Obsługiwane typy bloków:

- `text` — zwykły tekst, wymagane pole `text`.
- `image_url` — obraz, wymagane `image_url.url`.
- `file_url` — plik (PDF, CSV, TXT itp.), wymagane `file_url.url`.

### Relacja z `references` w v1

Aby zachować zgodność ze starszymi klientami, v2 nadal rozpoznaje pole `references: ["https://...", ...]`:
- Jeśli sufiks URL to `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, automatycznie konwertuj na blok `image_url`;
- Inne rozszerzenia konwertuj na blok `file_url`;
- Jeśli jednocześnie podano `question`, umieść je na początku jako blok `text`.

Dlatego jeśli chcesz tylko przejść z v1 i nie chcesz zmieniać body żądania, wystarczy zmienić ścieżkę na `/aichat2/conversations`, a dotychczasowe użycie `references` nadal działa.

Jeśli potrzebujesz bardziej precyzyjnej kontroli (na przykład umieszczania wielu obrazów pomiędzy tekstem albo gdy kolejność jest bardzo ważna), użyj bezpośrednio tablicy `message`.

## Wywoływanie narzędzi i MCP

Kluczowym ulepszeniem v2 jest to, że model może samodzielnie wywoływać narzędzia, aby realizować zadania wieloetapowe, **jest to domyślnie włączone** i nie wymaga żadnej dodatkowej konfiguracji po stronie klienta w żądaniu. Typowe scenariusze:

- Użytkownik pyta „Pomóż mi wyszukać, jakie nowe wystawy są ostatnio w Szanghaju” → model wywołuje wbudowane web search → porządkuje wyniki w odpowiedź.
- Użytkownik pyta „Przeczytaj ten PDF, a następnie napisz podsumowanie” → model wywołuje file_read → pisze podsumowanie.
- Użytkownik autoryzował już Google Drive / GitHub / Notion itd. w [Connections](https://platform.acedata.cloud/connections) → model może wywoływać odpowiednie narzędzia MCP do odczytu i zapisu ich danych.

W strumieniu NDJSON / SSE wywołania narzędzi są przedstawiane przez dwa typy zdarzeń: `tool_use` i `tool_result`, na przykład:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Jeśli nie chcesz wyświetlać szczegółów wywołań narzędzi w frontendzie, wystarczy ignorować zdarzenia typu `tool_use` / `tool_result` / `card` / `citation`, a końcowe wyjście modelu nadal będzie przesyłane strumieniowo przez `text_delta`.

`max_turns` może ograniczyć maksymalną liczbę rund samodzielnego wywoływania narzędzi przez model w tym żądaniu; zakres wynosi 1–500, a domyślnie jest to 500, jeśli pole zostanie pominięte. Ustawienie małej wartości (na przykład `max_turns: 1`) może wymusić jednorazową odpowiedź i nie zezwolić na żadne wywołania narzędzi.

## Wykonanie asynchroniczne i autoryzacja bez nadzoru

Jeśli Twoje wywołanie pochodzi z alertu Webhook, CI/CD, systemu monitoringu lub innego zadania działającego w tle, możesz ustawić `async: true`, aby interfejs natychmiast zwrócił ID zadania, a wykonywanie było kontynuowane w tle:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Mój serwis zgłosił alarm, powiadom grupę WeChat „AceDataCloud团队” za pomocą prywatnego WeChat……"
}
```

Przykład odpowiedzi:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Następnie możesz użyć `action: retrieve` + `id`, aby sprawdzić wynik rozmowy; możesz też podać `callback_url`, a po ukończeniu zadania platforma wyśle metodą POST `{ status, answer, usage, error }` na Twój adres zwrotny. `callback_url` musi używać `http` / `https` i nie może bezpośrednio zawierać `localhost` ani literałowego adresu prywatnego IP.

Zadania działające w tle zwykle nie mają osoby, która może kliknąć potwierdzenie. Jeśli chcesz, aby niektóre Skill lub MCP Server wykonywały działania takie jak wysyłanie, publikowanie czy zapisywanie w trybie bez nadzoru, jawnie przekaż listę wstępnej autoryzacji w body żądania:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Mój serwis zgłosił alarm, powiadom grupę WeChat „AceDataCloud团队” za pomocą prywatnego WeChat……"
}
```

Wartości w `allowed_skills` to slug podłączonych Skill; wartości w `allowed_mcp_servers` to slug podłączonych MCP Server. Skill / MCP Server niewymienione we wstępnej autoryzacji mogą w trybie bez nadzoru nadal tylko wyświetlać podgląd, wykonywać dry-run lub odmawiać wykonania operacji zapisu.

Jeśli potrzebujesz bardziej szczegółowej kontroli, możesz również użyć równoważnego obiektu `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Wstępna autoryzacja to same te dwie listy: pusta lista oznacza brak autoryzacji dla jakichkolwiek możliwości, bez potrzeby stosowania dodatkowego pola przełącznika.

Uwaga: wstępna autoryzacja oznacza jedynie „to żądanie pozwala tym możliwościom pominąć ręczne potwierdzenie w trybie bez nadzoru”. Konkretny Skill nadal musi obsługiwać `--unattended-confirm` albo odpowiedni mechanizm bezpieczeństwa; w przeciwnym razie będzie nadal wykonywał dry-run i nie wykona bezpośrednio operacji zapisu.

## Wznawianie wstrzymanych rozmów

Niektóre narzędzia powodują, że model „zadaje użytkownikowi pytanie zwrotne”; wówczas model wysyła zdarzenie `ask_user_question`, a rozmowa zostaje zamrożona w stanie `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Czy raport, który chcesz wygenerować, ma być po chińsku czy po angielsku?",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

W frontendzie wyrenderuj to zdarzenie jako kartę, aby użytkownik wybrał odpowiedź, a następnie użyj tego samego `id`, aby wysłać kolejne żądanie i uzupełnić odpowiedź przez `tool_results`:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

`tool_use_id` w body żądania **musi** być dokładnie zgodne z `tool_id` w momencie wstrzymania; niezgodność zwróci 400. Gdy w żądaniu jednocześnie występuje `tool_results`, `question` / `message` / `references` zostaną zignorowane.

Jeśli użytkownik zdecyduje się porzucić to pytanie, wystarczy bezpośrednio przekazać nowe `question` / `message`, a platforma automatycznie oznaczy wstrzymane wywołanie narzędzia jako „pominięte przez użytkownika”.

## Zarządzanie rozmowami (CRUD)

v2 zapewnia lekkie zarządzanie rozmowami za pomocą pola `action` w tym samym endpointzie, bez potrzeby udostępniania dodatkowego API.
### `action: retrieve` —— pobranie rozmowy

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Zwraca kompletny dokument rozmowy (w tym historię `messages`, `model`, `title`, `tools_used` itd.).

### `action: retrieve_batch` —— wyświetlenie podsumowań rozmów

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Zwraca `{ items: [...], total }`. **Podsumowania nie zawierają `messages`**, dlatego nadają się do listy na pasku bocznym; jeśli użytkownik otworzy daną rozmowę, użyj następnie `action: retrieve`, aby osobno pobrać jej pełne wiadomości.

Opcjonalne parametry filtrowania: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— zmiana tytułu lub nadpisanie historii

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Plan podróży do Hangzhou"
}
```

Można również przekazać `messages`, ale serwer przeprowadzi rygorystyczną walidację schematu (musi to być zwinięta postać `ToolUseContent`); w przypadku niezgodności zwróci 400. Zazwyczaj zaleca się używanie tego wyłącznie do zmiany `title`.

### `action: delete` —— usunięcie rozmowy

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Zwraca `{ id, success: true }`. Po usunięciu nie można jej odzyskać, dlatego przed wywołaniem należy się upewnić.

## Płynna migracja z v1

Jeśli korzystasz już z [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), migracja do v2 prawie nie wymaga zmian w kodzie:

1. Zmień URL z `https://api.acedata.cloud/aichat/conversations` na `https://api.acedata.cloud/aichat2/conversations`.
2. Jeśli wcześniej przekazywałeś nazwy modeli v1 (takie jak `gpt-3.5`, `gpt-4-browsing` itd.), podczas przejścia na v2 zaleca się aktualizację do współczesnych modeli (takich jak `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` itd.).
3. Pola strumienia NDJSON zachowują kompatybilność wsteczną: każde zdarzenie `text_delta` nadal zawiera `delta_answer` i `id`, dlatego klienci, które pierwotnie parsowały wiersz po wierszu `delta_answer`, nie wymagają zmian.

Po migracji można w razie potrzeby włączyć nowe możliwości v2 (multimodalne `message`, SSE, wywoływanie narzędzi, CRUD `action`) i wdrażać je we własnym tempie.

## Obsługa błędów

Odpowiedzi błędów mają jednolity format:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Typowe błędy:

- `400 bad_request`: brak wymaganych pól, niezgodne `tool_use_id`, nieprawidłowy schemat `messages` itd.
- `401 invalid_token`: nagłówek `authorization` jest nieprawidłowy.
- `404 not_found`: podczas `action: retrieve / update / delete` rozmowa odpowiadająca `id` nie istnieje.
- `429 too_many_requests`: uruchomiono ograniczenie szybkości.
- `500 chat_error`: błąd nadrzędnego LLM lub `completion_tokens=0` w tej turze (traktowane jako niezużyte, opłata nie zostanie naliczona).

W odpowiedzi strumieniowej błędy są wysyłane jako zdarzenia `{"type":"error","message":"..."}`, po czym strumień natychmiast się zakończy.

## Wnioski

AI Chat v2 API, zachowując kompatybilność wsteczną z v1, podnosi rozmowy z „jednoturowych / wieloturowych pytań i odpowiedzi” do „obserwowalnych rozmów agentowych”: wejście multimodalne, wywoływanie narzędzi, możliwość wstrzymania / wznowienia, strumieniowe ustrukturyzowane zdarzenia, wbudowany CRUD. Zaleca się, aby nowe integracje bezpośrednio korzystały z v2; istniejące integracje v1 mogą być płynnie migrowane etapami. W razie jakichkolwiek pytań prosimy o kontakt z naszym zespołem wsparcia technicznego.
