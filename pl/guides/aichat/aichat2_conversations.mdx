AI Chat v2 API (`/aichat2/conversations`) to interfejs konwersacyjny nowej generacji, stanowiący kompleksowo ulepszoną wersję [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Na podstawie prostoty i hostowanej obsługi rozmów wieloturowych v1 rozszerza on:

- **Multimodalne dane wejściowe użytkownika**: bezpośrednie przekazywanie tekstu + obrazów + bloków plików za pomocą ustrukturyzowanego pola `message`, bez konieczności wcześniejszego pośredniego dołączania ich przez `references`.
- **Wywoływanie narzędzi w stylu Agentów**: wbudowany zestaw narzędzi do wyszukiwania w sieci, pobierania stron internetowych, odczytu plików itd., z możliwością podłączenia serwerów MCP autoryzowanych przez użytkownika (Google Drive, Notion, Slack, GitHub itd.); model może w ramach jednego żądania autonomicznie wielokrotnie wywoływać narzędzia, aby realizować złożone zadania.
- **Ustrukturyzowane zdarzenia strumieniowe**: przez `accept: text/event-stream` lub `application/x-ndjson` można otrzymywać zdarzenia `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` itd. dla poszczególnych tokenów, co ułatwia osobne renderowanie ich według odpowiednich typów w frontendzie.
- **Możliwość przerwania / wznowienia**: gdy model potrzebuje od użytkownika dodatkowych informacji, wyśle zdarzenie `ask_user_question` i wstrzyma działanie; przy następnym wywołaniu wystarczy uzupełnić odpowiedź przez `tool_results`, aby kontynuować.
- **Nowe działania CRUD**: za pomocą pola `action` na tym samym endpointcie można wykonać `retrieve` / `retrieve_batch` / `update` / `delete`, bez potrzeby dodatkowego API do zarządzania rozmowami.
- **Stale aktualizowana lista modeli**: domyślnie obejmuje współczesne modele, takie jak GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 itd.

Jednocześnie na poziomie treści żądania jest on **w pełni wstecznie kompatybilny z v1**: wystarczy przekazać `model` + `question` (+ opcjonalne `stateful` / `id` / `references` / `preset`), aby otrzymać odpowiedź JSON `{answer, id}` równoważną z v1. Dlatego migracja z `/aichat/conversations` nie wymaga przepisywania klienta — wystarczy zmienić ścieżkę na `/aichat2/conversations`.

> Jeśli obecnie korzystasz z `/aichat/conversations`, stary interfejs będzie nadal obsługiwany i możesz przeprowadzić migrację we własnym tempie.

## Proces uzyskania dostępu

Aby korzystać z AI Chat v2 API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go do późniejszego użycia.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany ani zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, gdzie zostaniesz poproszony o rejestrację i zalogowanie się; po zakończeniu automatycznie wrócisz na bieżącą stronę.

**Jeden API Token pozwala wywoływać wszystkie usługi platformy, bez konieczności osobnego wnioskowania o dostęp do każdej usługi.** Przy pierwszym uzyskaniu dostępu otrzymasz darmowy limit, umożliwiający bezpłatne przetestowanie usługi; gdy limit będzie niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [AI Chat v2 API →](https://platform.acedata.cloud/documents/aichat2-conversations)

## Podstawowe użycie

Najprostsze użycie jest całkowicie takie samo jak w v1: przekaż `model` + `question`, aby otrzymać `{answer, id}`.

Przykład CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Wynik zwracany:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Przykład Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Rozmowy wieloturowe

Tak jak w v1, przekaż `stateful: true`, aby włączyć zapisywanie rozmowy; API zwróci `id`; w kolejnych żądaniach wystarczy przekazać z powrotem `id`, aby kontynuować rozmowę, bez konieczności samodzielnego utrzymywania historii messages.

Pierwsze żądanie:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Zwracany wynik:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Drugie żądanie, z tym samym `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> Domyślną wartością `stateful` jest `true`; pominięcie go jest równoważne jawnemu przekazaniu `true`. Ustawienie `stateful: false` pominie ładowanie poprzedniej historii rozmowy; nie oznacza to, że wynik tej rundy nie zostanie zapisany, ani nie ma zastosowania do przepływów narzędziowych wymagających wznowienia po wstrzymaniu.

### Długie rozmowy i zachowanie oryginalnego tekstu

Kompresja kontekstu porządkuje tylko treść wysyłaną do modelu w tej rundzie, nie zastępując zapisanych rekordów czatu. Pełne zapisane wiadomości nadal można odczytać za pomocą `action: retrieve`; jawna edycja i usunięcie rozmowy nadal działają zgodnie z żądaniem.

Model może wyszukiwać i stronicować oryginalną historię w bieżącej rozmowie. Gdy trzeba dalej modyfikować artykuł, cytować liczby lub przygotować publikację, należy odczytać odpowiedni oryginalny tekst i nie można zastępować treści głównej podsumowaniem. Ta funkcja nie przywraca automatycznie wiadomości utraconych w starych wersjach.

Jeśli porządkowanie kontekstu się nie powiedzie, zachowaj ID rozmowy i sprawdź zdarzenie `error`; usługa nie nadpisze oryginalnego tekstu pustym podsumowaniem. Operacje narzędziowe zakończone przed błędem mogą nadal być skuteczne; najpierw sprawdź ich wyniki, aby uniknąć ponownego generowania lub publikowania. Gdy pojedyncza rozmowa osiągnie limit przechowywania, zostanie wyraźnie zgłoszony błąd; istniejące zapisane rekordy nie zostaną przycięte w celu zwolnienia miejsca; po wyeksportowaniu potrzebnej treści można rozpocząć nową rozmowę.

## Odpowiedzi strumieniowe

v2 obsługuje dwa formaty strumieniowe, wybierane zgodnie z nagłówkiem `accept`:

| Scenariusz                    | `accept`               | Format danych                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Frontend Web / EventSource  | `text/event-stream`    | `data: {json}\n\n`, ostatni wiersz `data: [DONE]\n\n` |
| Serwer / CLI / parsowanie strumieniowe Node | `application/x-ndjson` | Jeden obiekt JSON w każdym wierszu                               |
| Brak potrzeby strumieniowania                 | `application/json`（domyślnie） | Jednorazowy zwrot `{answer, id}`                       |

### Przykład NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Każdy wiersz NDJSON jest zdarzeniem strukturalnym, najczęstszym z nich jest `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Przykład SSE

`EventSource` po stronie przeglądarki nie obsługuje niestandardowego ciała żądania; zaleca się użycie `fetch` + ręczne parsowanie po segmentach `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Typy zdarzeń strumieniowych

| `type`              | Znaczenie                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Przyrostowy fragment tekstu odpowiedzi asystenta. `content` zawiera nową treść; dla zgodności z v1 to samo zdarzenie zawiera również `delta_answer` (równe `content`) oraz `id`.                                        |
| `thinking`          | Proces rozumowania modelu (pojawia się tylko wtedy, gdy wybrany model udostępnia reasoning).                                                                                      |
| `tool_use`          | Model zdecydował o wywołaniu narzędzia; zdarzenie zawiera `tool_id`, `tool_name`, `input`.                                                                        |
| `tool_result`       | Wynik wykonania narzędzia, sparowany z poprzednim `tool_use` przez `tool_id`; `is_error` wskazuje, czy wystąpił błąd.                                                             |
| `card`              | Ustrukturyzowana karta wygenerowana przez narzędzie (np. obraz, podgląd linku), odpowiednia do bezpośredniego renderowania.                                                                                          |
| `citation`          | Źródłowy URL używany do uzupełnienia cytowania odpowiedniego fragmentu tekstu.                                                                                                  |
| `ask_user_question` | Emitowane, gdy model potrzebuje od użytkownika dodatkowych informacji; rozmowa przechodzi w stan `awaiting_user_input`, szczegóły poniżej w [Wznawianie wstrzymanej rozmowy](#恢复暂停的对话).                                                 |
| `artifact`          | Niezależny artefakt wygenerowany przez model (np. blok kodu, dokument), który można zapisać lub pobrać.                                                                                            |
| `system_message`    | Informacja systemowa (nie treść użytkownika ani asystenta), używana wyłącznie do komunikatów UI.                                                                                           |
| `compact`           | Kontekst modelu został uporządkowany; zapisane oryginalne wiadomości pozostają niezmienione, klient nie musi usuwać historii czatu.                                                                                    |
| `error`             | W tej rundzie wystąpił błąd; `message` opisuje treść błędu.                                                                                              |
| `done`              | Końcowy rekord rozmowy tej rundy został pomyślnie zapisany; zawiera `usage` (w tym `prompt_tokens` / `completion_tokens` / `total_tokens`) oraz `terminal_reason`; nadal należy ocenić, czy zadanie zostało ukończone, na podstawie przyczyny zakończenia. |
Dla klientów, którym zależy tylko na końcowej odpowiedzi, połączenie wszystkich `content` z `text_delta` jest równoważne `answer` w trybie `application/json`.

## Wejście multimodalne

Jeśli dane wejściowe użytkownika zawierają obrazy lub pliki, przekaż `message` (tablicę) zamiast `question`. Każdy element tablicy jest blokiem zawartości:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Obsługiwane typy bloków:

- `text` — zwykły tekst, wymagane pole `text`.
- `image_url` — obraz, wymagane `image_url.url`.
- `file_url` — plik (PDF, CSV, TXT itd.), wymagane `file_url.url`.

### Relacja z `references` v1

Aby zachować kompatybilność ze starszymi klientami, v2 nadal rozpoznaje pole `references: ["https://...", ...]`:

- Jeśli rozszerzenie URL to `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, jest ono automatycznie konwertowane na blok `image_url`;
- Inne rozszerzenia są konwertowane na bloki `file_url`;
- Jeśli jednocześnie podano `question`, zostanie ono umieszczone na początku jako blok `text`.

Dlatego, jeśli chcesz tylko przejść z v1 i nie chcesz zmieniać treści żądania, wystarczy zmienić ścieżkę na `/aichat2/conversations`, a dotychczasowe użycie `references` będzie nadal działać.

Jeśli potrzebujesz bardziej precyzyjnej kontroli (na przykład umieszczenia wielu obrazów między tekstem albo gdy kolejność jest bardzo ważna), użyj bezpośrednio tablicy `message`.

## Wywoływanie narzędzi i MCP

Głównym usprawnieniem v2 jest to, że model może samodzielnie wywoływać narzędzia, aby realizować zadania wieloetapowe, **jest to domyślnie włączone** i nie wymaga żadnej dodatkowej konfiguracji w żądaniu po stronie klienta. Typowe scenariusze:

- Użytkownik pyta „Pomóż mi wyszukać, jakie nowe wystawy są ostatnio w Szanghaju” → model wywołuje wbudowane web search → porządkuje wyniki w odpowiedź.
- Użytkownik pyta „Przeczytaj ten PDF, a potem napisz podsumowanie” → model wywołuje file_read → pisze podsumowanie.
- Użytkownik autoryzował już Google Drive / GitHub / Notion itd. w [Connections](https://platform.acedata.cloud/connections) → model może wywoływać odpowiednie narzędzia MCP do odczytu i zapisu ich danych.

W strumieniu NDJSON / SSE wywołania narzędzi są prezentowane poprzez dwa typy zdarzeń: `tool_use` i `tool_result`, na przykład:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Jeśli nie chcesz wyświetlać w interfejsie szczegółów wywołań narzędzi, po prostu ignoruj zdarzenia `tool_use` / `tool_result` / `card` / `citation`; końcowe wyjście modelu nadal będzie przesyłane strumieniowo przez `text_delta`.

`max_turns` może ograniczyć maksymalną liczbę rund samodzielnego wywoływania narzędzi przez model w tym żądaniu, zakres wynosi 1–500, a domyślna wartość przy pominięciu to 500. Ustawienie małej wartości (na przykład `max_turns: 1`) może wymusić pojedynczą odpowiedź i nie zezwolić na żadne wywołania narzędzi.

## Wykonywanie asynchroniczne i autoryzacja bez nadzoru

Jeśli Twoje wywołanie pochodzi z Webhooka alertu, CI/CD, systemu monitorowania lub innego zadania działającego w tle, możesz ustawić `async: true`, aby interfejs natychmiast zwrócił ID zadania i kontynuował wykonywanie w tle:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Przykład odpowiedzi:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Następnie możesz użyć `action: retrieve` + `id`, aby sprawdzić wynik rozmowy; możesz również podać `callback_url`, a po ukończeniu zadania platforma wykona POST z `{ status, answer, usage, error }` na Twój adres zwrotny. `callback_url` musi używać `http` / `https` i nie może bezpośrednio wskazywać `localhost` ani literalnego adresu prywatnego IP.

Zadania w tle zwykle nie mają osoby, która mogłaby kliknąć potwierdzenie. Jeśli chcesz, aby określone Skill lub MCP Server wykonywały w trybie bez nadzoru działania takie jak wysyłanie, publikowanie czy zapisywanie, jawnie przekaż listę wstępnej autoryzacji w treści żądania:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Wartości w `allowed_skills` to slug podłączonych Skill; wartości w `allowed_mcp_servers` to slug podłączonych MCP Server. Skill / MCP Server niewymienione na liście wstępnej autoryzacji w trybie bez nadzoru nadal mogą tylko wyświetlać podgląd, wykonywać dry-run lub odmawiać wykonania operacji zapisu.

Jeśli potrzebujesz bardziej szczegółowej kontroli, możesz również użyć równoważnego obiektu `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Wstępna autoryzacja to same te dwie listy: pusta lista oznacza brak autoryzacji dla jakichkolwiek możliwości, bez potrzeby dodatkowego pola przełącznika.

Uwaga: wstępna autoryzacja oznacza jedynie, że „to żądanie pozwala tym możliwościom pominąć ręczne potwierdzenie w trybie bez nadzoru”. Konkretny Skill nadal musi obsługiwać `--unattended-confirm` lub odpowiedni mechanizm bezpieczeństwa; w przeciwnym razie będzie nadal wykonywać dry-run i nie wykona bezpośrednio operacji zapisu.

## Wznawianie wstrzymanych rozmów

Niektóre narzędzia powodują, że model „zadaje użytkownikowi pytanie zwrotne”; model w tym momencie emituje zdarzenie `ask_user_question`, a rozmowa zostaje zamrożona w stanie `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

W interfejsie wyrenderuj to zdarzenie jako kartę, aby użytkownik mógł wybrać odpowiedź, a następnie użyj tego samego `id`, aby rozpocząć kolejne żądanie i uzupełnić odpowiedź przez `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

W treści żądania `tool_use_id` **musi** być dokładnie zgodny z `tool_id` w momencie wstrzymania; niezgodność zwróci 400. Gdy w żądaniu jednocześnie występuje `tool_results`, `question` / `message` / `references` zostaną zignorowane.

Jeśli użytkownik zdecyduje się zrezygnować z tego pytania, wystarczy bezpośrednio przekazać nowe `question` / `message`, a platforma automatycznie oznaczy wstrzymane wywołanie narzędzia jako „pominięte przez użytkownika”.

## Zarządzanie sesjami (CRUD)

v2 zapewnia lekkie zarządzanie sesjami za pośrednictwem pola `action` w tym samym endpointcie, bez potrzeby otwierania dodatkowego API.

### `action: retrieve` —— Pobieranie jednej sesji

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Zwraca pełny dokument sesji (w tym historię `messages`, `model`, `title`, `tools_used` itd.).

### `action: retrieve_batch` —— Wyświetlanie podsumowań sesji

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Zwraca `{ items: [...], total }`. **Podsumowania nie zawierają `messages`**, co jest odpowiednie dla listy na pasku bocznym; jeśli użytkownik otworzy daną sesję, następnie użyj `action: retrieve`, aby osobno pobrać jej pełne wiadomości.

Opcjonalne parametry filtrowania: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Zmiana tytułu lub nadpisanie historii

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Plan podróży do Hangzhou"
}
```

Można również przekazać `messages`, ale serwer przeprowadzi rygorystyczną walidację schematu (musi to być zwinięta forma `ToolUseContent`); w przypadku niezgodności zwróci 400. Zazwyczaj zaleca się używanie tego wyłącznie do zmiany `title`.

### `action: delete` —— Usuwanie jednej sesji

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Zwraca `{ id, success: true }`. Po usunięciu nie można jej odzyskać, dlatego przed wywołaniem należy to potwierdzić.

## Płynna migracja z v1

Jeśli już korzystasz z [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), migracja do v2 praktycznie nie wymaga zmian w kodzie:

1. Zmień URL z `https://api.acedata.cloud/aichat/conversations` na `https://api.acedata.cloud/aichat2/conversations`.
2. Jeśli wcześniej przekazywałeś nazwę modelu v1 (np. `gpt-3.5`, `gpt-4-browsing` itd.), podczas przejścia na v2 zaleca się aktualizację do współczesnych modeli (np. `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` itd.).
3. Pola strumienia NDJSON zachowują kompatybilność wsteczną: każde zdarzenie `text_delta` nadal zawiera `delta_answer` i `id`, dlatego klient pierwotnie analizujący wiersz po wierszu `delta_answer` nie wymaga zmian.

Po migracji możesz w razie potrzeby włączyć nowe możliwości v2 (multimodalne `message`, SSE, wywołania narzędzi, CRUD `action`) i wdrażać je stopniowo.

## Obsługa błędów

Odpowiedzi błędów mają jednolity format:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Typowe błędy:

- `400 bad_request`: brak wymaganych pól, niezgodność `tool_use_id`, nieprawidłowy schemat `messages` itd.
- `401 invalid_token`: nagłówek `authorization` jest nieprawidłowy.
- `404 not_found`: podczas `action: retrieve / update / delete` sesja odpowiadająca `id` nie istnieje.
- `413 conversation_storage_limit`: sesja przekroczyła limit przechowywania, istniejące zapisane rekordy nie zostały nadpisane.
- `429 too_many_requests`: uruchomiono limit szybkości żądań.
- `503 context_compaction_failed`: porządkowanie kontekstu nie powiodło się, istniejące rekordy zostały zachowane.
- `500 conversation_persist_failed`: końcowy zapis tej rundy nie powiódł się; otrzymany tekst nie oznacza, że końcowy rekord został zapisany pomyślnie, sprawdź według ID sesji.
- `500 chat_error`: usługa jest tymczasowo niedostępna lub w tej rundzie nie wygenerowano treści (opłata nie zostanie naliczona).

W odpowiedzi strumieniowej błędy są wysyłane jako zdarzenie `{"type":"error","message":"..."}`, po czym strumień zostanie zakończony. `[DONE]` oznacza jedynie zakończenie transmisji; gdy występuje `error`, nie można uznać tego za sukces i nie zostanie również wysłane pomyślne zdarzenie `done`.

## Wnioski

AI Chat v2 API, zachowując kompatybilność wsteczną z v1, podnosi rozmowy z „jednorundowych / wielorundowych pytań i odpowiedzi” do „obserwowalnych rozmów z agentami”: wejście multimodalne, wywołania narzędzi, możliwość wstrzymania / wznowienia, strumieniowe zdarzenia strukturalne, wbudowane CRUD. Zaleca się, aby nowe integracje bezpośrednio korzystały z v2; istniejące integracje v1 mogą migrować płynnie etapami. W razie jakichkolwiek pytań prosimy o kontakt z naszym zespołem wsparcia technicznego.
