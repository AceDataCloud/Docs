AI Chat v2 API (`/aichat2/conversations`) to interfejs konwersacyjny nowej generacji, będący kompleksowo ulepszoną wersją [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Na bazie prostoty i hostowanej obsługi wieloturowych rozmów v1 rozszerza on:

- **Wielomodalne dane wejściowe użytkownika**: bezpośrednie przekazywanie tekstu + obrazów + bloków plików za pomocą ustrukturyzowanego pola `message`, bez potrzeby wcześniejszego pośredniego dołączania przez `references`.
- **Wywoływanie narzędzi w stylu Agent**: wbudowany zestaw narzędzi do wyszukiwania w Internecie, pobierania stron internetowych, odczytu plików itp., z możliwością podłączenia autoryzowanych przez użytkownika serwerów MCP (Google Drive, Notion, Slack, GitHub itd.), dzięki czemu model może autonomicznie wielokrotnie wywoływać narzędzia w ramach jednego żądania, aby wykonywać złożone zadania.
- **Ustrukturyzowane zdarzenia strumieniowe**: za pomocą `accept: text/event-stream` lub `application/x-ndjson` można otrzymywać zdarzenia takie jak `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` itd. dla każdego tokenu, co ułatwia ich osobne renderowanie na froncie według odpowiednich typów.
- **Możliwość przerwania / wznowienia**: gdy model potrzebuje, aby użytkownik uzupełnił informacje, wyśle zdarzenie `ask_user_question` i wstrzyma działanie; przy następnym wywołaniu wystarczy uzupełnić odpowiedź przez `tool_results`, aby kontynuować.
- **Nowe akcje CRUD**: w tym samym endpointcie można wykonywać `retrieve` / `retrieve_batch` / `update` / `delete` za pomocą pola `action`, bez potrzeby dodatkowego API zarządzania rozmowami.
- **Stale aktualizowana lista modeli**: domyślnie dostępne są współczesne modele, takie jak GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 itd.

Jednocześnie na poziomie treści żądania jest on **w pełni wstecznie kompatybilny z v1**: wystarczy przekazać `model` + `question` (+ opcjonalnie `stateful` / `id` / `references` / `preset`), aby otrzymać odpowiedź JSON `{answer, id}` równoważną v1, więc migracja z `/aichat/conversations` nie wymaga przepisywania klienta — wystarczy zmienić ścieżkę na `/aichat2/conversations`.

> Jeśli obecnie używasz `/aichat/conversations`, stary interfejs nadal będzie obsługiwany i możesz przeprowadzić migrację we własnym tempie.

## Proces składania wniosku

Aby korzystać z AI Chat v2 API, najpierw pobierz swój API Token w [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications) i zachowaj go do późniejszego użycia.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany ani zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i zalogowania się; po zakończeniu automatycznie wrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności osobnego wnioskowania dla każdej usługi.** Przy pierwszym wniosku otrzymasz darmowy limit, który pozwoli na bezpłatne wypróbowanie usługi; gdy limit będzie niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

## Podstawowe użycie

Najprostsze użycie jest dokładnie takie samo jak w v1: przekaż `model` + `question` i otrzymaj `{answer, id}`.

Przykład CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Wynik zwracany:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Przykład Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Wieloturowa rozmowa

Tak jak w v1, przekaż `stateful: true`, aby włączyć zapisywanie rozmowy; API zwróci `id`; w kolejnych żądaniach wystarczy przekazywać z powrotem `id`, aby kontynuować rozmowę, bez konieczności samodzielnego utrzymywania historii messages.

Pierwsze żądanie:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Zwraca:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Drugie żądanie, z tym samym `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> Domyślnie `stateful` ma wartość `true`; pominięcie go jest równoważne jawnemu przekazaniu `true`. Jeśli nie chcesz, aby serwer zapisywał tę turę rozmowy, możesz jawnie ustawić `stateful: false`.

## Odpowiedzi strumieniowe

v2 obsługuje dwa formaty strumieniowe, wybierane zgodnie z nagłówkiem `accept`:

| Scenariusz                    | `accept`               | Format danych                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Frontend Web / EventSource  | `text/event-stream`    | `data: {json}\n\n`, ostatnia linia `data: [DONE]\n\n` |
| Serwer / CLI / analiza strumieniowa Node | `application/x-ndjson` | Jeden obiekt JSON na linię                               |
| Strumieniowanie nie jest potrzebne                 | `application/json`（domyślnie） | Jednorazowo zwraca `{answer, id}`                       |

### Przykład NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Każda linia NDJSON jest ustrukturyzowanym zdarzeniem, a najczęstszym jest `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Przykład SSE

Użycie `EventSource` po stronie przeglądarki nie obsługuje niestandardowego ciała żądania; zaleca się użycie `fetch` + ręczne analizowanie przez podział na `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Typy zdarzeń strumieniowych

| `type`              | Znaczenie                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `text_delta`        | Przyrostowy fragment tekstu odpowiedzi asystenta. `content` to nowa treść; dla zgodności z v1 to samo zdarzenie zawiera także `delta_answer` (równe `content`) oraz `id`.                  |
| `thinking`          | Proces rozumowania modelu (pojawia się tylko wtedy, gdy wybrany model udostępnia reasoning).                                                                |
| `tool_use`          | Model decyduje się wywołać narzędzie; zdarzenie zawiera `tool_id`, `tool_name`, `input`.                                                  |
| `tool_result`       | Wynik wykonania narzędzia, sparowany z poprzednim `tool_use` przez `tool_id`; `is_error` wskazuje, czy wystąpił błąd.                                       |
| `card`              | Ustrukturyzowana karta wygenerowana przez narzędzie (np. obraz, podgląd linku), odpowiednia do bezpośredniego renderowania.                                                                    |
| `citation`          | Źródłowy URL używany do uzupełnienia cytowania odpowiedniego fragmentu tekstu.                                                                            |
| `ask_user_question` | Wysyłane, gdy model potrzebuje, aby użytkownik uzupełnił informacje; rozmowa przechodzi w stan `awaiting_user_input`, szczegóły poniżej w sekcji [wznawianie wstrzymanej rozmowy](#恢复暂停的对话).                           |
| `artifact`          | Niezależny artefakt wygenerowany przez model (np. blok kodu, dokument), który można zapisać lub pobrać.                                                                      |
| `system_message`    | Informacja systemowa (nie jest treścią użytkownika ani asystenta), używana wyłącznie jako komunikat UI.                                                                     |
| `compact`           | Zdarzenie, w którym wewnętrzny kontekst został skompresowany; nie wymaga specjalnej obsługi.                                                                             |
| `error`             | W tej turze wystąpił błąd; `message` opisuje treść błędu.                                                                        |
| `done`              | Odpowiedź strumieniowa została zakończona; zawiera `usage` (w tym `prompt_tokens` / `completion_tokens` / `total_tokens`) oraz `terminal_reason`. |

W przypadku klientów, którym zależy tylko na końcowej odpowiedzi, połączenie `content` ze wszystkich `text_delta` jest równoważne `answer` w trybie `application/json`.

## Dane wejściowe multimodalne

Jeśli dane wejściowe użytkownika zawierają obrazy lub pliki, przekaż `message` (tablicę) zamiast `question`. Każdy element tablicy jest blokiem treści:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Obsługiwane typy bloków:

- `text` — zwykły tekst, wymagane pole `text`.
- `image_url` — obraz, wymagane `image_url.url`.
- `file_url` — plik (PDF, CSV, TXT itd.), wymagane `file_url.url`.

### Relacja z `references` w v1

Aby zachować zgodność ze starszymi klientami, v2 nadal rozpoznaje pole `references: ["https://...", ...]`:
- Jeśli rozszerzenie URL to `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, jest automatycznie konwertowane na blok `image_url`;
- Inne rozszerzenia są konwertowane na blok `file_url`;
- Jeśli jednocześnie podano `question`, jest ono umieszczane z przodu jako blok `text`.

Dlatego jeśli chcesz tylko zmigrować z v1 i nie chcesz zmieniać body żądania, wystarczy zmienić ścieżkę na `/aichat2/conversations`, a dotychczasowe użycie `references` nadal działa.

Jeśli potrzebujesz bardziej szczegółowej kontroli (na przykład umieszczenia wielu obrazów pomiędzy tekstem albo gdy kolejność jest bardzo ważna), użyj bezpośrednio tablicy `message`.

## Wywoływanie narzędzi i MCP

Kluczowym ulepszeniem v2 jest możliwość samodzielnego wywoływania przez model narzędzi w celu wykonania zadań wieloetapowych, **jest to domyślnie włączone** i nie wymaga żadnej dodatkowej konfiguracji po stronie klienta w żądaniu. Typowe scenariusze:

- Użytkownik pyta: „Pomóż mi wyszukać, jakie nowe wystawy są ostatnio w Szanghaju” → model wywołuje wbudowane web search → porządkuje wyniki w odpowiedź.
- Użytkownik pyta: „Przeczytaj ten PDF, a potem napisz podsumowanie” → model wywołuje file_read → pisze podsumowanie.
- Użytkownik autoryzował już Google Drive / GitHub / Notion itd. w [Connections](https://platform.acedata.cloud/connections) → model może wywoływać odpowiednie narzędzia MCP do odczytu i zapisu ich danych.

W strumieniu NDJSON / SSE wywołania narzędzi są prezentowane za pomocą dwóch typów zdarzeń: `tool_use` i `tool_result`, na przykład:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Jeśli nie chcesz wyświetlać na froncie szczegółów wywołań narzędzi, wystarczy zignorować zdarzenia typu `tool_use` / `tool_result` / `card` / `citation`, a końcowy wynik modelu nadal będzie przesyłany strumieniowo przez `text_delta`.

`max_turns` może ograniczyć maksymalną liczbę rund samodzielnego wywoływania narzędzi przez model w tym żądaniu; zakres wynosi 1–500, a domyślnie, jeśli parametr zostanie pominięty, wynosi 500. Ustawienie małej wartości (na przykład `max_turns: 1`) może wymusić pojedynczą odpowiedź i nie zezwalać na żadne wywołania narzędzi.

## Wykonanie asynchroniczne i autoryzacja bez nadzoru

Jeśli Twoje wywołanie pochodzi z webhooka alertów, CI/CD, systemu monitorowania lub innych zadań backendowych, możesz ustawić `async: true`, aby interfejs natychmiast zwrócił ID zadania, a wykonanie było kontynuowane w tle:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Moja usługa zgłosiła alarm, powiadom grupę WeChat „AceDataCloud团队” przez osobisty WeChat……"
}
```

Przykład odpowiedzi:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Następnie można użyć `action: retrieve` + `id`, aby sprawdzić wynik rozmowy; można również podać `callback_url`, a po zakończeniu zadania platforma wykona POST z `{ status, answer, usage, error }` na Twój adres zwrotny. `callback_url` musi używać `http` / `https` i nie może bezpośrednio wskazywać `localhost` ani literałowego adresu prywatnego IP.

W zadaniach backendowych zwykle nie ma nikogo, kto mógłby kliknąć potwierdzenie. Jeśli chcesz, aby określone Skill lub MCP Server wykonywały w trybie bez nadzoru działania takie jak wysyłanie, publikowanie lub zapisywanie, jawnie przekaż listę preautoryzacji w body żądania:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Moja usługa zgłosiła alarm, powiadom grupę WeChat „AceDataCloud团队” przez osobisty WeChat……"
}
```

Wartości w `allowed_skills` to slugi połączonych Skill; wartości w `allowed_mcp_servers` to slugi połączonych MCP Server. Skill / MCP Server niewymienione w preautoryzacji w trybie bez nadzoru nadal mogą jedynie wyświetlać podgląd, wykonywać dry-run lub odmawiać wykonania operacji zapisu.

Jeśli potrzebujesz bardziej szczegółowej kontroli, możesz również użyć równoważnego obiektu `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Preautoryzacja to same te dwie listy: pusta lista oznacza brak autoryzacji jakichkolwiek możliwości, bez potrzeby stosowania dodatkowego pola przełącznika.

Uwaga: preautoryzacja oznacza jedynie, że „to żądanie zezwala tym możliwościom na pominięcie ręcznego potwierdzenia w trybie bez nadzoru”. Konkretny Skill nadal musi obsługiwać `--unattended-confirm` lub odpowiadający mu mechanizm bezpieczeństwa; w przeciwnym razie nadal będzie działać w trybie dry-run i nie wykona bezpośrednio operacji zapisu.

## Wznawianie wstrzymanych rozmów

Niektóre narzędzia powodują, że model „zadaje użytkownikowi pytanie zwrotne”; w tym momencie model emituje zdarzenie `ask_user_question`, a rozmowa zostaje zamrożona w stanie `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Czy chcesz, aby wygenerowany raport był po chińsku czy po angielsku?",
  "options": ["chiński", "angielski"],
  "id": "f2f4b3e8-..."
}
```

Na froncie wyrenderuj to zdarzenie jako kartę, aby użytkownik mógł wybrać odpowiedź, a następnie użyj tego samego `id`, aby wysłać kolejne żądanie i uzupełnić odpowiedź przez `tool_results`:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

`tool_use_id` w body żądania **musi** być dokładnie zgodne z `tool_id` z momentu wstrzymania; w przeciwnym razie zwracany jest błąd 400. Gdy w żądaniu jednocześnie występuje `tool_results`, `question` / `message` / `references` są ignorowane.

Jeśli użytkownik zdecyduje się porzucić to pytanie, wystarczy bezpośrednio przekazać nowe `question` / `message`, a platforma automatycznie oznaczy wstrzymane wywołanie narzędzia jako „pominięte przez użytkownika”.

## Zarządzanie rozmowami (CRUD)

v2 zapewnia lekkie zarządzanie rozmowami na tym samym endpointzie za pomocą pola `action`, bez potrzeby uruchamiania dodatkowego API.
### `action: retrieve` —— pobierz rozmowę

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Zwraca pełny dokument rozmowy (w tym historię `messages`, `model`, `title`, `tools_used` itd.).

### `action: retrieve_batch` —— wyświetl podsumowania rozmów

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Zwraca `{ items: [...], total }`. **Podsumowania nie zawierają `messages`**, co jest odpowiednie dla listy na pasku bocznym; jeśli użytkownik otworzy daną rozmowę, użyj następnie `action: retrieve`, aby osobno pobrać jej pełne wiadomości.

Opcjonalne parametry filtrowania: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— zmień tytuł lub nadpisz historię

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

Można również przekazać `messages`, ale serwer przeprowadzi ścisłą walidację schema (musi to być zwinięta forma `ToolUseContent`); w przypadku niezgodności zwróci 400. Zazwyczaj zaleca się używanie tego wyłącznie do zmiany `title`.

### `action: delete` —— usuń rozmowę

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Zwraca `{ id, success: true }`. Po usunięciu nie można przywrócić, dlatego przed wywołaniem upewnij się.

## Płynna migracja z v1

Jeśli korzystasz już z [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), migracja do v2 prawie nie wymaga zmian w kodzie:

1. Zmień URL z `https://api.acedata.cloud/aichat/conversations` na `https://api.acedata.cloud/aichat2/conversations`.
2. Jeśli wcześniej przekazywałeś nazwy modeli v1 (takie jak `gpt-3.5`, `gpt-4-browsing` itd.), podczas przejścia na v2 zaleca się aktualizację do współczesnych modeli (takich jak `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` itd.).
3. Pola strumienia NDJSON zachowują kompatybilność wsteczną: każde zdarzenie `text_delta` nadal zawiera `delta_answer` i `id`, dlatego klienci, którzy wcześniej analizowali `delta_answer` wiersz po wierszu, nie wymagają zmian.

Po migracji można w razie potrzeby włączać nowe możliwości v2 (multimodalne `message`, SSE, wywoływanie narzędzi, CRUD `action`), wdrażając je we własnym tempie.

## Obsługa błędów

Odpowiedzi błędów mają ujednoliconą postać:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Typowe błędy:

- `400 bad_request`: brakuje wymaganego pola, `tool_use_id` nie pasuje, schema `messages` jest nieprawidłowe itd.
- `401 invalid_token`: nagłówek `authorization` jest niepoprawny.
- `404 not_found`: podczas `action: retrieve / update / delete` rozmowa odpowiadająca `id` nie istnieje.
- `429 too_many_requests`: uruchomiono limit szybkości żądań.
- `500 chat_error`: błąd nadrzędnego LLM lub `completion_tokens=0` w tej rundzie (traktowane jako niezużyte, opłata nie zostanie naliczona).

W odpowiedzi strumieniowej błędy są wysyłane jako zdarzenie `{"type":"error","message":"..."}`, po czym strumień natychmiast się zakończy.

## Wnioski

API AI Chat v2, zachowując kompatybilność wsteczną z v1, podnosi rozmowy z „pytań i odpowiedzi jednokrotnych / wielokrotnych” do „obserwowalnych rozmów opartych na Agentach”: wejście multimodalne, wywoływanie narzędzi, możliwość wstrzymania / wznowienia, strumieniowe ustrukturyzowane zdarzenia, wbudowany CRUD. Zaleca się, aby nowe integracje bezpośrednio korzystały z v2; istniejące integracje v1 mogą przeprowadzić płynną migrację etapami. W razie jakichkolwiek pytań prosimy o kontakt z naszym zespołem wsparcia technicznego.
