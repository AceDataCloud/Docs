API AI Chat v2 (`/aichat2/conversations`) to interfejs konwersacyjny nowej generacji, stanowiący kompleksową aktualizację [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Oprócz prostoty i obsługi wieloetapowych rozmów zarządzanych przez serwer, znanych z wersji v1, rozszerzono go o:

- **Wielomodalne dane wejściowe użytkownika**: umożliwia bezpośrednie przesyłanie tekstu, obrazów i bloków plików za pomocą ustrukturyzowanego pola `message`, bez konieczności wcześniejszego pośredniego dołączania ich za pomocą `references`.
- **Wywoływanie narzędzi w modelu Agent**: zawiera wbudowany zestaw narzędzi do wyszukiwania w Internecie, pobierania stron internetowych, odczytywania plików itp. Można również podłączać serwery MCP autoryzowane przez użytkownika (Google Drive, Notion, Slack, GitHub itd.). Model może samodzielnie wielokrotnie wywoływać narzędzia w ramach jednego żądania, aby realizować złożone zadania.
- **Ustrukturyzowane zdarzenia strumieniowe**: za pomocą `accept: text/event-stream` lub `application/x-ndjson` można otrzymywać zdarzenia takie jak `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` itd. w miarę generowania kolejnych tokenów, co ułatwia ich oddzielne renderowanie w interfejsie użytkownika w zależności od typu zdarzenia.
- **Możliwość przerwania i wznowienia**: gdy model potrzebuje dodatkowych informacji od użytkownika, wysyła zdarzenie `ask_user_question` i wstrzymuje działanie. Przy kolejnym wywołaniu wystarczy uzupełnić odpowiedź za pomocą `tool_results`, aby kontynuować.
- **Nowe operacje CRUD**: w tym samym endpointcie można za pomocą pola `action` wykonywać operacje `retrieve` / `retrieve_batch` / `update` / `delete`, bez konieczności korzystania z dodatkowego API do zarządzania sesjami.
- **Stale aktualizowana lista modeli**: domyślnie obsługiwane są współczesne modele, takie jak GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 i inne.

Jednocześnie na poziomie treści żądania zachowano **pełną kompatybilność wsteczną z v1**: wystarczy przesłać `model` + `question` (+ opcjonalnie `stateful` / `id` / `references` / `preset`), aby otrzymać równoważną z v1 odpowiedź JSON `{answer, id}`. Dlatego migracja z `/aichat/conversations` nie wymaga przepisywania klienta — wystarczy zmienić ścieżkę na `/aichat2/conversations`.

> Jeśli obecnie korzystasz z `/aichat/conversations`, stary interfejs będzie nadal dostępny. Możesz przeprowadzić migrację we własnym tempie.

## Proces uzyskiwania dostępu

Aby korzystać z API AI Chat v2, najpierw przejdź do [panelu Ace Data Cloud](https://platform.acedata.cloud/console/applications) i pobierz swój token API, aby zachować go do późniejszego wykorzystania.

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, nastąpi automatyczne przekierowanie na stronę logowania, gdzie możesz się zarejestrować i zalogować. Po zakończeniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

**Jeden token API wystarczy do korzystania ze wszystkich usług platformy. Nie ma potrzeby ubiegania się o osobny token dla każdej usługi.** Przy pierwszym uzyskaniu dostępu otrzymasz bezpłatny limit środków, dzięki czemu możesz bezpłatnie przetestować usługę. Gdy limit będzie niewystarczający, możesz doładować wspólne saldo w [panelu sterowania](https://platform.acedata.cloud/console/coin).

## Podstawowe użycie

Najprostszy sposób użycia jest dokładnie taki sam jak w v1: prześlij `model` + `question` i otrzymaj `{answer, id}`.

Przykład CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Wynik odpowiedzi:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Przykład Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## Wieloetapowe rozmowy

Podobnie jak w v1, ustaw `stateful: true`, aby włączyć zapisywanie sesji. API zwróci identyfikator `id`. W kolejnych żądaniach wystarczy ponownie przesłać ten sam `id`, aby kontynuować rozmowę, bez konieczności samodzielnego przechowywania historii wiadomości w `messages`.

Pierwsze żądanie:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Odpowiedź:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Drugie żądanie, z tym samym `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "Jaką liczbę kazałem ci przed chwilą zapamiętać?"
  }'
```

```json
{
  "answer": "Liczba, którą kazałeś mi zapamiętać, to 42.",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` domyślnie ma wartość `true`, więc pominięcie tego parametru jest równoważne jawnemu przekazaniu `true`. Ustawienie `stateful: false` spowoduje pominięcie wczytywania wcześniejszej historii konwersacji; nie oznacza to, że wynik bieżącej rundy nie zostanie zapisany, ani nie ma zastosowania do procesów narzędziowych wymagających wstrzymania i późniejszego wznowienia.

### Długie konwersacje i zachowanie oryginalnej treści

Kompresja kontekstu porządkuje wyłącznie treść wysyłaną do modelu w bieżącej rundzie i nie zastępuje zapisanej historii czatu. Za pomocą `action: retrieve` nadal można odczytać wszystkie zapisane wiadomości; jawna edycja lub usunięcie konwersacji nadal obowiązuje zgodnie z żądaniem.

Model może wyszukiwać i stronicować oryginalną treść historii w ramach bieżącej konwersacji. W przypadku dalszej edycji artykułu, cytowania liczb lub przygotowywania publikacji należy odczytać odpowiedni oryginalny tekst, a nie zastępować go treścią streszczenia. Ta funkcja nie przywraca automatycznie wiadomości, które zostały już utracone w starszych wersjach.

Jeśli porządkowanie kontekstu zakończy się niepowodzeniem, zachowaj identyfikator konwersacji i sprawdź zdarzenie `error`; usługa nie zastąpi oryginalnej treści pustym streszczeniem. Operacje narzędziowe zakończone przed wystąpieniem błędu mogą nadal być aktywne, dlatego najpierw sprawdź ich wyniki, aby uniknąć ponownego generowania lub publikowania. Gdy pojedyncza konwersacja osiągnie limit przechowywania, zostanie zwrócony wyraźny komunikat o błędzie; istniejące zapisane dane nie zostaną przycięte w celu zwolnienia miejsca. Możesz wyeksportować potrzebną treść, a następnie rozpocząć nową konwersację.

## Odpowiedzi strumieniowe

v2 obsługuje dwa formaty strumieniowe, wybierane za pomocą nagłówka `accept`:

| Scenariusz | `accept` | Format danych |
| --------------------- | ---------------------- | ------------------------------------------ |
| Frontend WWW / EventSource | `text/event-stream` | `data: {json}\n\n`, ostatni wiersz `data: [DONE]\n\n` |
| Serwer / CLI / strumieniowe przetwarzanie Node | `application/x-ndjson` | Jeden obiekt JSON w każdym wierszu |
| Brak potrzeby odpowiedzi strumieniowej | `application/json` (domyślnie) | Jednorazowa odpowiedź `{answer, id}` |

### Przykład NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "Przedstaw Hangzhou w trzech zdaniach.",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # Zgodność z v1: fragment przyrostowy jest jednocześnie udostępniany w polu delta_answer
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Każdy wiersz NDJSON jest ustrukturyzowanym zdarzeniem. Najczęściej występuje `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Przykład SSE

Przeglądarkowy `EventSource` nie obsługuje niestandardowego treści żądania, dlatego zaleca się użycie `fetch` + ręczne dzielenie i analizowanie fragmentów według `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "Przedstaw Hangzhou w trzech zdaniach.",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Typy zdarzeń strumieniowych

| `type` | Znaczenie |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta` | Przyrostowy fragment tekstu odpowiedzi asystenta. `content` zawiera nową treść; dla zachowania zgodności z v1 to samo zdarzenie zawiera również `delta_answer` (równe `content`) oraz `id`. |
| `thinking` | Proces rozumowania modelu (pojawia się tylko wtedy, gdy wybrany model udostępnia reasoning). |
| `tool_use` | Model decyduje się wywołać narzędzie; zdarzenie zawiera `tool_id`, `tool_name`, `input`. |
| `tool_result` | Wynik wykonania narzędzia, powiązany z poprzednim `tool_use` za pomocą `tool_id`; `is_error` wskazuje, czy wystąpił błąd. |
| `card` | Ustrukturyzowana karta wygenerowana przez narzędzie (np. obraz, podgląd linku), odpowiednia do bezpośredniego renderowania. |
| `citation` | Adres URL źródła uzupełniający cytowanie odpowiedniego fragmentu tekstu. |
| `ask_user_question` | Wysyłane, gdy model potrzebuje dodatkowych informacji od użytkownika; konwersacja przechodzi w stan `awaiting_user_input`. Szczegóły znajdują się poniżej w sekcji [Wznawianie wstrzymanej konwersacji](#恢复暂停的对话). |
| `artifact` | Niezależny rezultat wygenerowany przez model (np. blok kodu, dokument), który można zapisać lub pobrać. |
| `system_message` | Informacja systemowa (niebędąca treścią użytkownika ani asystenta), przeznaczona wyłącznie do wyświetlania w interfejsie użytkownika. |
| `compact` | Kontekst modelu został uporządkowany; zapisane oryginalne wiadomości pozostają niezmienione, a klient nie musi usuwać historii czatu. |
| `error` | Wystąpił błąd w bieżącej rundzie; `message` opisuje jego treść. |
| `done` | Końcowy zapis konwersacji dla bieżącej rundy został pomyślnie zapisany. Zawiera `usage` (w tym `prompt_tokens` / `completion_tokens` / `total_tokens`) oraz `terminal_reason`; nadal należy ocenić, czy zadanie zostało ukończone, na podstawie przyczyny zakończenia. |
Dla klientów, którym zależy wyłącznie na końcowej odpowiedzi, połączenie wszystkich pól `content` z `text_delta` jest równoważne polu `answer` w trybie `application/json`.

## Wejście multimodalne

Jeśli dane wejściowe użytkownika zawierają obraz lub plik, przekaż `message` (tablicę) zamiast `question`. Każdy element tablicy jest blokiem treści:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "Ile kotów znajduje się na tym obrazku?" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Obsługiwane typy bloków:

- `text` — zwykły tekst, wymagane pole `text`.
- `image_url` — obraz, wymagane pole `image_url.url`.
- `file_url` — plik (PDF, CSV, TXT itp.), wymagane pole `file_url.url`.

### Relacja z `references` w wersji v1

W celu zapewnienia zgodności ze starszymi klientami wersja v2 nadal rozpoznaje pole `references: ["https://...", ...]`:

- Adresy URL z rozszerzeniami `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif` są automatycznie konwertowane na bloki `image_url`;
- Pozostałe rozszerzenia są konwertowane na bloki `file_url`;
- Jeśli jednocześnie podano `question`, zostanie ono dodane na początku jako blok `text`.

Dlatego jeśli chcesz przejść z v1 na v2, nie zmieniając treści żądania, wystarczy zmienić ścieżkę na `/aichat2/conversations`. Dotychczasowy sposób używania `references` będzie nadal działać.

Jeśli potrzebujesz bardziej precyzyjnej kontroli (na przykład umieszczenia wielu obrazów pomiędzy fragmentami tekstu lub zachowania określonej kolejności), użyj bezpośrednio tablicy `message`.

## Wywoływanie narzędzi i MCP

Głównym ulepszeniem wersji v2 jest możliwość samodzielnego wywoływania przez model narzędzi w celu realizacji wieloetapowych zadań. **Ta funkcja jest domyślnie włączona** i nie wymaga żadnej dodatkowej konfiguracji po stronie klienta. Typowe scenariusze:

- Użytkownik pyta: „Wyszukaj najnowsze wystawy w Szanghaju” → model wywołuje wbudowane wyszukiwanie internetowe → porządkuje wyniki i przygotowuje odpowiedź.
- Użytkownik pyta: „Przeczytaj ten plik PDF, a następnie napisz streszczenie” → model wywołuje file_read → tworzy streszczenie.
- Użytkownik wcześniej autoryzował Google Drive / GitHub / Notion itp. w sekcji [Connections](https://platform.acedata.cloud/connections) → model może wywoływać odpowiednie narzędzia MCP w celu odczytu i zapisu danych.

W strumieniach NDJSON / SSE wywołania narzędzi są prezentowane za pomocą dwóch typów zdarzeń: `tool_use` i `tool_result`, na przykład:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Jeśli nie chcesz wyświetlać szczegółów wywołań narzędzi w interfejsie użytkownika, wystarczy zignorować zdarzenia `tool_use` / `tool_result` / `card` / `citation`. Końcowy wynik modelu nadal będzie przesyłany za pomocą `text_delta`.

Parametr `max_turns` pozwala ograniczyć maksymalną liczbę rund samodzielnego wywoływania narzędzi przez model w ramach bieżącego żądania. Zakres wynosi 1–500, a domyślna wartość to 500, jeśli parametr zostanie pominięty. Ustawienie niskiej wartości (na przykład `max_turns: 1`) pozwala wymusić pojedynczą odpowiedź bez wywoływania jakichkolwiek narzędzi.

## Wykonywanie asynchroniczne i autoryzacja bez nadzoru

Jeśli żądanie pochodzi z webhooka alertów, systemu CI/CD, systemu monitorowania lub innego zadania działającego w tle, możesz ustawić `async: true`, aby interfejs API natychmiast zwrócił identyfikator zadania, podczas gdy jego wykonywanie będzie kontynuowane w tle:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Moja usługa zgłosiła alarm. Powiadom grupę WeChat „AceDataCloud团队” za pomocą mojego osobistego konta WeChat……"
}
```

Przykładowa odpowiedź:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Następnie możesz użyć `action: retrieve` wraz z `id`, aby pobrać wynik rozmowy. Możesz również podać `callback_url`, a po zakończeniu zadania platforma wyśle żądanie POST zawierające `{ status, answer, usage, error }` na wskazany adres zwrotny. `callback_url` musi używać protokołu `http` / `https` i nie może bezpośrednio wskazywać `localhost` ani prywatnego adresu IP.

W przypadku zadań działających w tle zazwyczaj nie ma użytkownika, który mógłby kliknąć przycisk potwierdzenia. Jeśli chcesz, aby określone Skill lub MCP Server wykonywały działania takie jak wysyłanie, publikowanie czy zapisywanie danych w trybie bez nadzoru, jawnie przekaż listę wstępnie autoryzowanych elementów w treści żądania:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Moja usługa zgłosiła alarm. Powiadom grupę WeChat „AceDataCloud团队” za pomocą mojego osobistego konta WeChat……"
}
```

Wartości w `allowed_skills` to identyfikatory slug połączonych Skill, a wartości w `allowed_mcp_servers` to identyfikatory slug połączonych MCP Server. Skill / MCP Server, które nie zostały uwzględnione na liście wstępnej autoryzacji, w trybie bez nadzoru nadal mogą jedynie wyświetlać podgląd, wykonywać dry-run lub odmawiać realizacji operacji zapisu.

Jeśli potrzebujesz bardziej szczegółowej kontroli, możesz również użyć równoważnego obiektu `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

Wstępna autoryzacja obejmuje wyłącznie te dwie listy: pusta lista oznacza brak autoryzacji jakichkolwiek uprawnień. Nie jest wymagane żadne dodatkowe pole przełącznika.

Uwaga: wstępna autoryzacja oznacza jedynie, że „w ramach bieżącego żądania te uprawnienia mogą pomijać ręczne potwierdzenie w trybie bez nadzoru”. Sam Skill nadal musi obsługiwać `--unattended-confirm` lub odpowiedni mechanizm bezpieczeństwa. W przeciwnym razie nadal będzie wykonywać dry-run i nie przeprowadzi bezpośrednio operacji zapisu.

## Wznawianie wstrzymanych rozmów

Niektóre narzędzia mogą sprawić, że model „zada użytkownikowi dodatkowe pytanie”. W takiej sytuacji model wygeneruje zdarzenie `ask_user_question`, a rozmowa zostanie zamrożona w stanie `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Czy chcesz, aby wygenerowany raport był w języku chińskim czy angielskim?",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

W interfejsie użytkownika wyświetl to zdarzenie jako kartę, aby użytkownik mógł wybrać odpowiedź, a następnie wyślij kolejne żądanie z tym samym `id`, przekazując odpowiedź za pomocą `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

W treści żądania `tool_use_id` **MUSI** być dokładnie zgodne z `tool_id` z momentu wstrzymania; w przeciwnym razie zostanie zwrócony błąd 400. Jeśli żądanie zawiera jednocześnie `tool_results`, pola `question` / `message` / `references` zostaną zignorowane.

Jeśli użytkownik zdecyduje się zrezygnować z tego pytania, wystarczy bezpośrednio przekazać nowe `question` / `message`, a platforma automatycznie oznaczy wstrzymane wywołanie narzędzia jako „pominięte przez użytkownika”.

## Zarządzanie sesjami (CRUD)

Wersja v2 udostępnia uproszczone zarządzanie sesjami za pomocą pola `action` w tym samym endpointcie, bez konieczności tworzenia osobnego API.

### `action: retrieve` — pobranie jednej sesji

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Zwraca pełny dokument sesji (zawierający historię `messages`, `model`, `title`, `tools_used` itp.).

### `action: retrieve_batch` — pobranie listy podsumowań sesji

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Zwraca `{ items: [...], total }`. **Podsumowania nie zawierają `messages`**, dzięki czemu nadają się do wyświetlania listy na pasku bocznym; gdy użytkownik otworzy daną sesję, należy użyć `action: retrieve`, aby osobno pobrać jej pełne wiadomości.

Opcjonalne parametry filtrowania: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` — zmiana tytułu lub przepisanie historii

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Plan podróży do Hangzhou"
}
```

Można również przekazać `messages`, ale serwer przeprowadzi ścisłą walidację schematu (musi to być złożona postać `ToolUseContent`); w przeciwnym razie zostanie zwrócony błąd 400. Zasadniczo zaleca się używanie tej funkcji wyłącznie do zmiany `title`.

### `action: delete` — usunięcie jednej sesji

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Zwraca `{ id, success: true }`. Po usunięciu sesji nie można jej przywrócić, dlatego przed wywołaniem należy to potwierdzić.

## Płynna migracja z v1

Jeśli korzystasz już z [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), migracja do v2 praktycznie nie wymaga zmian w kodzie:

1. Zmień URL z `https://api.acedata.cloud/aichat/conversations` na `https://api.acedata.cloud/aichat2/conversations`.
2. Jeśli wcześniej przekazywano nazwy modeli v1 (takie jak `gpt-3.5`, `gpt-4-browsing` itp.), podczas przełączania na v2 zaleca się aktualizację do współczesnych modeli (takich jak `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` itp.).
3. Pola w strumieniu NDJSON zachowują kompatybilność wsteczną: każde zdarzenie `text_delta` nadal zawiera `delta_answer` i `id`, dlatego klienci, którzy wcześniej analizowali wiersze `delta_answer`, nie wymagają żadnych zmian.

Po migracji można w razie potrzeby stopniowo włączać nowe funkcje v2 (wielomodalne `message`, SSE, wywoływanie narzędzi, CRUD za pomocą `action`).

## Obsługa błędów

Odpowiedzi błędów mają ujednolicony format:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Najczęstsze błędy:

- `400 bad_request`: brak wymaganych pól, niezgodność `tool_use_id`, nieprawidłowy schemat `messages` itp.
- `401 invalid_token`: nieprawidłowy nagłówek `authorization`.
- `404 not_found`: sesja odpowiadająca `id` nie istnieje podczas wykonywania `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: sesja przekroczyła limit przechowywania, a istniejące zapisane rekordy nie zostały nadpisane.
- `429 too_many_requests`: przekroczono limit szybkości żądań.
- `503 context_compaction_failed`: nie udało się uporządkować kontekstu, istniejące rekordy zostały zachowane.
- `500 conversation_persist_failed`: końcowy zapis tej rundy nie powiódł się; otrzymanie tekstu nie oznacza, że końcowy zapis został pomyślnie wykonany — należy wyszukać sesję według jej ID.
- `500 chat_error`: usługa jest tymczasowo niedostępna lub w tej rundzie nie wygenerowano żadnej treści (opłata nie zostanie naliczona).

W odpowiedzi strumieniowej błędy są przesyłane jako zdarzenia `{"type":"error","message":"..."}`, po czym strumień zostaje zakończony. `[DONE]` oznacza wyłącznie zakończenie transmisji; jeśli wystąpiło `error`, nie można uznać operacji za udaną i nie zostanie wysłane pomyślne zdarzenie `done`.

## Podsumowanie

Interfejs API AI Chat v2, zachowując kompatybilność wsteczną z v1, przekształca rozmowę z modelu „jednorundowych / wielorundowych pytań i odpowiedzi” w „obserwowalną rozmowę opartą na agentach”: obsługuje dane wejściowe multimodalne, wywoływanie narzędzi, wstrzymywanie / wznawianie, ustrukturyzowane zdarzenia strumieniowe oraz wbudowane operacje CRUD. Zaleca się, aby nowe integracje od razu korzystały z v2; istniejące integracje v1 można migrować płynnie etapami. W razie jakichkolwiek pytań prosimy o kontakt z naszym zespołem pomocy technicznej.
