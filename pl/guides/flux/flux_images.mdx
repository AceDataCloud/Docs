W tym artykule przedstawimy instrukcję integracji API Flux Images Generation, które umożliwia generowanie oficjalnych obrazów Flux poprzez wprowadzenie niestandardowych parametrów.

## Proces aplikowania

Aby korzystać z API Flux Images Generation, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania z zaproszeniem do rejestracji i zalogowania się, a po zakończeniu automatycznie wrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez potrzeby osobnego aplikowania dla każdej usługi.** Przy pierwszym wniosku otrzymasz darmowy limit, aby móc bezpłatnie wypróbować usługę; gdy limit będzie niewystarczający, możesz doładować saldo ogólne w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Podstawowe użycie

Najpierw zapoznaj się z podstawowym sposobem użycia: wprowadź prompt `prompt`, działanie generowania `action` oraz rozmiar obrazu `size`, aby uzyskać przetworzony wynik. Najpierw należy po prostu przekazać pole `action` o wartości `generate`, a następnie należy również wprowadzić prompt. Szczegóły są następujące:

<p><img src="https://cdn.acedata.cloud/wz85jt.png" width="500" className="m-auto" /></p>

Można zauważyć, że ustawiliśmy tutaj Request Headers, w tym:

- `accept`: format odpowiedzi, który chcesz otrzymać; tutaj należy wpisać `application/json`, czyli format JSON.
- `authorization`: klucz do wywołania API, który po uzyskaniu można bezpośrednio wybrać z listy rozwijanej.

Dodatkowo ustawiliśmy Request Body, w tym:

- `action`: działanie dla bieżącego zadania generowania obrazu.
- `size`: rozmiar wyniku generowania obrazu. **Serie `flux-2-flex` / `flux-2-pro` / `flux-2-max` muszą otrzymać proporcje obrazu (np. `1:1`, `16:9`), nie akceptują wymiarów w pikselach, takich jak `1024x1024`; brak wartości zwróci 400.**
- `count`: liczba generowanych obrazów, wartość domyślna to 1; ten parametr jest skuteczny tylko dla zadań generowania obrazów, a dla zadań edycji jest nieskuteczny.
- `prompt`: prompt.
- `model`: model generowania, domyślnie `flux-dev`; najnowsze modele flagowe to `flux-2-pro` i `flux-2-max` (wyższa jakość obrazu, wymagają proporcji obrazu `size`).
- `callback_url`: URL, na który należy zwrócić wynik poprzez callback.
- `async`: opcjonalne; gdy ustawione na `true`, interfejs natychmiast zwraca `task_id`, bez potrzeby podawania `callback_url`, a następnie wynik można uzyskać przez odpytywanie odpowiedniego interfejsu zapytania o zadanie.

Parametr `size` ma pewne szczególne ograniczenia, głównie dzieli się na dwa typy: proporcje szerokości i wysokości `width x height` oraz proporcje obrazu `x:y`. Szczegóły są następujące:

| Model               | Zakres                                         |
| ---------------- | ------------------------------------------ |
| flux-dev         | Obsługuje proporcje szerokości i wysokości 1024x1024, 1024x1792, 1792x1024 lub proporcje obrazu |
| flux-pro         | Obsługuje proporcje szerokości i wysokości 1024x1024, 1024x1792, 1792x1024 lub proporcje obrazu |
| flux-2-flex      | Obsługuje wyłącznie proporcje obrazu                                    |
| flux-2-pro       | Obsługuje wyłącznie proporcje obrazu                                    |
| flux-2-max       | Obsługuje wyłącznie proporcje obrazu                                    |
| flux-kontext-pro | Obsługuje wyłącznie proporcje obrazu                                    |
| flux-kontext-max | Obsługuje wyłącznie proporcje obrazu                                    |

Przykładowe proporcje obrazu: "21:9", "16:9", "4:3", "3:2", "1:1", "2:3", "3:4", "9:16", "9:21".

Po wybraniu parametrów odpowiedni kod zostanie automatycznie wygenerowany po prawej stronie. Przed skopiowaniem upewnij się, że nagłówek autoryzacji używa Twojego własnego API Key, a w dokumentacji i zrzutach ekranu nie powinny pojawiać się rzeczywiste dane uwierzytelniające.

Kliknij przycisk „Try”, aby przeprowadzić test. Tutaj otrzymaliśmy następujący wynik:

```json
{
  "success": true,
  "task_id": "5456c749-3bbb-4f10-9eb8-cfbcac297500",
  "trace_id": "ae4eecb8-1dd6-45b4-bfb3-a1c48872536e",
  "data": [
    {
      "image_url": "https://cdn.acedata.cloud/assets/examples/flux/5456c749-3bbb-4f10-9eb8-cfbcac297500-d0ef60485f73.jpg"
    }
  ]
}
```

Wynik zwracany zawiera wiele pól, które przedstawiono poniżej:

- `success`, status bieżącego zadania generowania wideo.
- `task_id`, ID bieżącego zadania generowania wideo.
- `trace_id`, ID śledzenia bieżącego generowania wideo.
- `data`, lista wyników bieżącego zadania generowania obrazu.
  - `image_url`, link do bieżącego zadania generowania obrazu.
  - `prompt`, prompt.

Można zauważyć, że uzyskaliśmy satysfakcjonujące informacje o obrazie. Wystarczy pobrać wygenerowany obraz Flux zgodnie z adresem linku obrazu w `data` wyniku.

Dodatkowo, jeśli chcesz wygenerować odpowiedni kod integracyjny, możesz go bezpośrednio skopiować. Na przykład kod CURL jest następujący:

```shell
curl -X POST 'https://api.acedata.cloud/flux/images' \
-H 'authorization: Bearer {token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "A photorealistic studio product shot of a frosted-glass perfume bottle on wet black slate, single softbox key light, water droplets, dark moody background, 85mm macro.",
  "model": "flux-2-pro",
  "size": "1:1"
}'
```

## Zadanie edycji obrazu

Jeśli chcesz edytować określony obraz, najpierw parametr `image_url` musi zawierać link do obrazu, który należy edytować. W tym przypadku `action` obsługuje wyłącznie `edit`, dzięki czemu można określić następujące treści:

- model: model używany przez bieżące zadanie edycji obrazu, obsługuje `flux-dev`, `flux-pro`, `flux-kontext-pro`, `flux-kontext-max`, `flux-2-flex`, `flux-2-pro`, `flux-2-max`.
- image_url: prześlij obraz, który należy edytować.

Przykład wypełnienia jest następujący:

<p><img src="https://cdn.acedata.cloud/jn9da5.png" width="500" className="m-auto" /></p>

Po wypełnieniu kod zostanie automatycznie wygenerowany w następujący sposób:

<p><img src="https://cdn.acedata.cloud/6cwxb8.png" width="500" className="m-auto" /></p>

Odpowiedni kod:

```python
import requests

url = "https://api.acedata.cloud/flux/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "edit",
    "prompt": "a white siamese cat",
    "model": "flux-kontext-pro",
    "image_url": "https://cdn.acedata.cloud/ytj2qy.png"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Kliknij uruchom, a zobaczysz, że wynik zostanie uzyskany natychmiast, jak poniżej:

```json
{
  "success": true,
  "task_id": "2a7979ff-1f77-4380-92c6-a2dc37c3b4c8",
  "trace_id": "732b65c0-48d9-49f7-b568-64e5acffe4c0",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "timings": 1752744073
    }
  ]
}
```
Można zauważyć, że wygenerowany efekt polega na edycji oryginalnego obrazu, a wynik jest podobny do opisanego powyżej.

## Asynchroniczne wywołanie zwrotne

Ponieważ czas generowania przez Flux Images Generation API jest stosunkowo długi i wynosi około 1–2 minut, jeśli API przez długi czas nie odpowiada, żądanie HTTP będzie stale utrzymywać połączenie, co prowadzi do dodatkowego zużycia zasobów systemowych, dlatego to API również zapewnia obsługę asynchronicznych wywołań zwrotnych.

Ogólny proces wygląda następująco: gdy klient inicjuje żądanie, dodatkowo określa pole `callback_url`, po wysłaniu przez klienta żądania API, API natychmiast zwróci wynik zawierający informacje o polu `task_id`, które reprezentuje ID bieżącego zadania. Po ukończeniu zadania wynik wygenerowanego obrazu zostanie wysłany w formie POST JSON na `callback_url` określony przez klienta, gdzie również zawarte będzie pole `task_id`, dzięki czemu wyniki zadania mogą zostać powiązane za pomocą ID.

Poniżej na przykładzie zobaczymy, jak konkretnie należy to zrobić.

Po pierwsze, wywołanie zwrotne Webhook to usługa, która może odbierać żądania HTTP, a programista powinien zastąpić je adresem URL własnego serwera HTTP. Dla wygody demonstracji użyto tutaj publicznej przykładowej strony Webhook https://webhook.site/; po otwarciu tej strony można uzyskać URL Webhook, jak pokazano na ilustracji:

![](https://cdn.acedata.cloud/cjjfly.png)

Skopiowanie tego URL umożliwia użycie go jako Webhooka, a przykładem w tym miejscu jest `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`.

Następnie możemy ustawić pole `callback_url` na powyższy URL Webhook, jednocześnie wypełniając odpowiednie parametry, a konkretna zawartość jest pokazana na ilustracji:

<p><img src="https://cdn.acedata.cloud/wm6caw.png" width="500" className="m-auto" /></p>

Kliknij uruchomienie, można zauważyć, że wynik zostanie uzyskany natychmiast, jak poniżej:

```
{
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c"
}
```

Po krótkiej chwili możemy zaobserwować wynik generowania obrazu na `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`, jak pokazano na ilustracji:

![](https://cdn.acedata.cloud/v23lot.png)

Treść jest następująca:

```json
{
  "success": true,
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c",
  "trace_id": "9b4b1ff3-90f2-470f-b082-1061ec2948cc",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "seed": 1698551532,
      "timings": {
        "inference": 3.328
      }
    }
  ]
}
```

Można zauważyć, że w wyniku znajduje się pole `task_id`, a pozostałe pola są podobne do opisanych powyżej; za pomocą tego pola można zrealizować powiązanie zadań.

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informację. Na przykład:

- `400 token_mismatched`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit częstotliwości.
- `500 api_error`: Wewnętrzny błąd serwera, coś poszło nie tak na serwerze.

### Przykład odpowiedzi błędu

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
