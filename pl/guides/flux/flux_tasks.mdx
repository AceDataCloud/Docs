Główną funkcją Flux Tasks API jest sprawdzanie statusu wykonania zadania poprzez wprowadzenie identyfikatora zadania platformy zwróconego przez Flux Images Generation API lub Flux Videos API.

Ten dokument szczegółowo przedstawi instrukcje dotyczące integracji Flux Tasks API, pomagając Ci łatwo zintegrować i w pełni wykorzystać zaawansowane funkcje tego API. Dzięki Flux Tasks API możesz łatwo realizować sprawdzanie statusu wykonania zadań Flux Images Generation API.

Pełny przykład przesyłania i odpytywania wideo znajdziesz w [przewodniku integracji Flux Videos API](https://platform.acedata.cloud/documents/flux-videos-integration). Sprawdzanie istniejących zadań nie wiąże się z dodatkowymi opłatami za generowanie.

## Proces aplikowania

Aby używać Flux Images Generation API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany ani zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i zalogowania się, a po zakończeniu automatycznie powrócisz na bieżącą stronę.

**Jeden API Token może wywoływać wszystkie usługi platformy, bez konieczności osobnego aplikowania dla każdej usługi.** Przy pierwszej aplikacji otrzymasz bezpłatny limit, który umożliwia darmowe wypróbowanie; gdy limit jest niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Przykład żądania

Flux Tasks API może służyć do sprawdzania wyników Flux Images Generation API. Informacje o tym, jak używać Flux Images Generation API, znajdziesz w dokumentacji [Flux Images Generation API ](https://platform.acedata.cloud/documents/flux-images-integration).

Jako przykład weźmiemy jeden identyfikator zadania zwrócony przez usługę Flux Images Generation API, aby zademonstrować, jak używać tego API. Załóżmy, że mamy identyfikator zadania: 2db0168c-2373-4367-8d9a-9dc778802e8a, następnie zademonstrujemy, jak poprzez przekazanie identyfikatora zadania.

### Ustawianie nagłówków żądania i treści żądania

**Request Headers** obejmują:

- `accept`: określa odbieranie wyników odpowiedzi w formacie JSON, tutaj należy wpisać `application/json`.
- `authorization`: klucz do wywoływania API, po złożeniu wniosku można go bezpośrednio wybrać z listy rozwijanej.

**Request Body** obejmuje:

- `id`: identyfikator przesłanego zadania.
- `action`: sposób działania na zadaniu.

Ustawienia są pokazane na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/fiasxz.png" width="500" className="m-auto" /></p>

### Przykład kodu

Można zauważyć, że po prawej stronie strony automatycznie wygenerowano już kod w różnych językach, jak pokazano na obrazku:

<p><img src="https://cdn.acedata.cloud/j6gn86.png" width="500" className="m-auto" /></p>

Niektóre przykłady kodu są następujące:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/flux/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/flux/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Wynik zwracany zawiera wiele pól, pole request jest request body podczas inicjowania zadania, natomiast pole response jest response body zwracanym po ukończeniu zadania. Opis pól jest następujący.

- `id`, ID wygenerowanego zadania obrazu, używane do jednoznacznej identyfikacji tego zadania generowania obrazu.
- `request`, informacje o żądaniu w sprawdzanym zadaniu obrazu.
- `response`, informacje zwrotne w sprawdzanym zadaniu obrazu.
- `created_at`, czas utworzenia zadania, znacznik czasu Unix (sekundy, liczba zmiennoprzecinkowa).
- `started_at`, czas rozpoczęcia wykonywania zadania, znacznik czasu Unix (sekundy, liczba zmiennoprzecinkowa).
- `finished_at`, czas ukończenia zadania, znacznik czasu Unix (sekundy, liczba zmiennoprzecinkowa). To pole nie jest zwracane, gdy zadanie nie zostało ukończone.
- `elapsed`, czas wykonania zadania, w sekundach (liczba zmiennoprzecinkowa, zachowane 3 miejsca po przecinku). To pole nie jest zwracane, gdy zadanie nie zostało ukończone.

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informację. Na przykład:

- `400 token_mismatched`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit częstotliwości.
- `500 api_error`: Wewnętrzny błąd serwera, coś poszło nie tak na serwerze.
