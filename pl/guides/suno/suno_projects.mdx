---
title: "Przewodnik po integracji projektu Suno Studio"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST https://api.acedata.cloud/suno/projects` to interfejs Beta do zarządzania projektami wielościeżkowymi. Tworzenie, zapisywanie, generowanie kandydatów, zatwierdzanie kandydatów i eksport są rozróżniane przez `action`.

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: <每次写操作的新 UUID>
```

Poza `retrieve`, **każda operacja wymaga** `Idempotency-Key`. Ten sam klucz i to samo żądanie jedynie odczytują ponownie pierwotny wynik; ten sam klucz z innym żądaniem zwraca 409. Gdy płatne generowanie napotka limit czasu sieciowego lub wynik zatwierdzenia jest niepewny, najpierw użyj oryginalnego ID zadania lub tego samego klucza idempotencji do zapytania — nie zmieniaj bezpośrednio klucza i nie wysyłaj ponownie.

## Identyfikatory i jednostki czasu

| Nazwa                             | Skąd pobrać                                                                                      | Gdzie używać                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | `create` odpowiedź `data.id`                                                                      | Wszystkie kolejne żądania bieżącego projektu                                      |
| `version_id`                   | Najnowsze `retrieve`, `save`, `add_track`, `commit_candidate` lub `remove_track` `data.version_id` | Modyfikowanie, generowanie kandydatów i eksport; należy używać najnowszej wersji                              |
| `audio_id` / `source_audio_id` | Stan końcowy `upload` `response.data.candidate.audio_id` lub istniejące ukończone ID audio                                | Odwoływanie się do oryginalnego audio podczas `add_track`, generowania lub zastępowania                          |
| `render_audio_id`              | Stan końcowy `render` `response.data.audio_id`                                                       | Referencja miksu projektu dla `generate_track`                         |
| `operation_id`                 | Stan końcowy `generate_track` lub `replace_section` `response.data.operation_id`                       | `commit_candidate`; zwykle taki sam jak `task_id` zadania generowania, ale należy odczytać wartość zwróconą |
| `candidate_id`                 | Stan końcowy generowania `response.data.candidates[].id`                                                       | Wybór kandydata do zatwierdzenia                                         |
| `track_id`                     | Projekt `data.state.tracks[].id`                                                                | Zatwierdzanie kandydata lub usuwanie ścieżki                                        |
| `task_id`                      | Odpowiedź przesłania operacji asynchronicznej                                                                                   | Użyj `/suno/tasks`, aby sprawdzić stan końcowy; nie jest to ID projektu                   |

`start_seconds` / `end_seconds` to **sekundy w źródłowym audio**; `start_beats` / `end_beats` to **liczby uderzeń na osi czasu projektu**. `state.timing.bps` to liczba uderzeń na sekundę, domyślnie 2. Na przykład fragment o długości 41 sekund, zaczynający się od uderzenia 0, ma domyślny punkt końcowy na uderzeniu 82. Zakres sekund `generate_track` służy do określania referencji generowania i nie gwarantuje, że kandydat będzie miał długość tylko tego zakresu.

## Przebieg operacji

| Kolejność  | `action`                             | Działanie                         | Sposób zwracania         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | Tworzenie pustego projektu                      | Synchroniczne dane projektu       |
| 2   | `retrieve`                           | Odczytywanie najnowszej wersji i pełnego `state`          | Synchroniczne dane projektu       |
| 3   | `save`                               | Pierwszy zapis lub całościowy zapis zmodyfikowanego `state`      | Synchroniczne dane projektu       |
| 4   | `upload`                             | Tworzenie materiału z adresu HTTPS audio           | Zadanie asynchroniczne         |
| 5   | `add_track`                          | Umieszczanie audio materiału w projekcie                  | Zadanie asynchroniczne, aktualizacja wersji    |
| 6   | `save`                               | Jeśli trzeba odebrać kandydata nowej ścieżki, najpierw zapisz pustą ścieżkę docelową        | Synchroniczne dane projektu, aktualizacja wersji  |
| 7   | `render`                             | Eksportowanie obecnie słyszalnych ścieżek, uzyskiwanie referencji miksu `audio_id` | Zadanie asynchroniczne         |
| 8   | `generate_track` lub `replace_section` | Odpowiednio generowanie kandydatów nowej ścieżki lub kandydatów lokalnego zastąpienia            | Zadanie asynchroniczne, tymczasowo nie modyfikuje projektu  |
| 9   | `commit_candidate`                   | Wybieranie i zatwierdzanie kandydata                  | Zadanie asynchroniczne, aktualizacja wersji po sukcesie |
| Opcjonalnie  | `remove_track`                       | Usuwanie określonej ścieżki                     | Synchroniczne dane projektu, aktualizacja wersji  |

Jeśli wykonywane jest tylko lokalne zastąpienie, wystarczy istniejące dostępne źródłowe audio i nie trzeba najpierw używać `render`; jeśli źródłowe audio znajduje się już w projekcie, można także pominąć `upload` i `add_track`. `render_audio_id` jest wyłącznie wymaganą referencją dla `generate_track`.

Podczas przesyłania operacji asynchronicznej najpierw zwracane jest `{ "task_id": "...", "trace_id": "..." }`, co **nie oznacza powodzenia generowania**. Odpytuj:

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步返回的 task_id"}
```

Zadanie jest uznawane za pomyślne dopiero, gdy rekord zadania ma `finished_at` oraz zawarte w nim `response.success` ma wartość `true`; gdy `response.success=false`, odczytaj `response.error`. Chociaż `save` może zawierać `task_id`, w ramach tego interfejsu jest wykonywane synchronicznie. `upload`, `render`, `generate_track`, `replace_section` nie modyfikują wersji projektu; po pomyślnym wykonaniu `save`, `add_track`, `commit_candidate`, `remove_track` należy pobrać nowe `version_id`.

## Konwencje żądań

| Parametr                | Typ i zakres zastosowania                                                                                   | Opis                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | Wymagany ciąg znaków                                                                                     | Ustalony jako jedna z nazw operacji wymienionych na tej stronie; jedno żądanie wykonuje tylko jedną operację.                                      |
| `id`              | Wymagany ciąg znaków poza `create`                                                                         | ID projektu, z `create.data.id`.                                      |
| `version_id`      | Wymagany ciąg znaków podczas modyfikowania, generowania kandydatów i eksportowania; można pominąć przy pierwszym `save` pustego projektu                                                         | Użyj najnowszej wersji, starsze wersje zostaną odrzucone. `retrieve` go nie wymaga.                                 |
| `Idempotency-Key` | Wymagany nagłówek żądania poza `retrieve`, 1–128 znaków                                                              | Użyj nowego klucza dla każdej nowej operacji; ten sam klucz i to samo żądanie odczytują ponownie pierwotny wynik, bez ponownego generowania lub naliczania opłat.                                   |
| `async`           | Opcjonalna wartość logiczna dla `upload`, `add_track`, `generate_track`, `replace_section`, `commit_candidate`, `render` | Te operacje zawsze są asynchroniczne; `false` również nie zmieni generowania na synchroniczne.                                    |
| `callback_url`    | Opcjonalny URL dla operacji asynchronicznych                                                                                | Odbiera powiadomienie o stanie końcowym; jeśli zostanie pominięty, odpytywanie `/suno/tasks` odbywa się według `task_id`. Nadal należy sprawdzić `response.success`. |

Poniższe przykłady przedstawiają łańcuchowo przekazywanie ID i wersji między operacjami. Odpowiedzi zawierają tylko pola związane z bieżącym krokiem; podczas integracji zastąp przykładowe ID wartościami odpowiedzi bieżącej aplikacji.

| Operacja         | Parametr      | Typ i opis                              |

## Zapisywanie stanu projektu

| Parametr | Typ i opis |
|---|---|
| `state` | Wymagany obiekt. Prześlij **pełny stan projektu**, a nie częściową poprawkę; oprzyj się na `data.state` zwróconym przez ostatnią operację odczytu lub modyfikacji i zachowaj nieznane pola. |
| `title` | Opcjonalny ciąg znaków; jeśli zostanie pominięty, używany jest `state.title`, a jeśli go również nie ma, używany jest domyślny tytuł. |
| `version_id` | Może zostać pominięty przy pierwszym zapisie nowo utworzonego pustego projektu; później należy używać najnowszej wersji. |

`state.timing.bps` musi być liczbą dodatnią, domyślnie 2. `state.tracks` jest tablicą ścieżek; `clipId` istniejących klipów audio odwołuje się do identyfikatora audio, a `startBeats`, `endBeats`, `readStartBeats` używają jednostki taktów projektu. Najbezpieczniejszym sposobem edycji jest odczytanie pełnego `state`, zmodyfikowanie tylko docelowej ścieżki lub klipu, a następnie zapisanie całości za pomocą `save`. Nowo dodana pusta ścieżka docelowa powinna mieć co najmniej unikalne `id`, `type:"audio"`, `clips:[]`; pełną strukturę pustej ścieżki pokazano w przykładzie w „Generowanie nowej ścieżki audio”. Nie traktuj bezpośrednio punktów taktów z wyników analizy audio jako współrzędnych osi czasu projektu.

## Przesyłanie audio i dodawanie ścieżek

| Operacja | Parametr | Typ i opis |
|---|---|---|
| `upload` | `audio_url` | Wymagany adres URL HTTPS wskazujący na publicznie dostępne audio, do którego masz prawo użycia. `candidate.audio_id` w stanie końcowym może zostać użyty do dodania ścieżki. |
| `add_track` | `audio_id` | Wymagany ciąg znaków; identyfikator audio ukończonego materiału, a nie URL. |
| `add_track` | `name`、`color` | Opcjonalne ciągi znaków; nazwa ścieżki domyślnie przyjmuje tytuł audio, zalecany kolor to `#RRGGBB`, domyślnie `#7251F7`. |
| `add_track` | `title` | Opcjonalny ciąg znaków; jednocześnie zmienia tytuł projektu, zwykle pomijany. |
| `add_track` | `start_beats`、`end_beats` | Opcjonalne nieujemne liczby; punkt końcowy musi być większy od punktu początkowego; domyślnie zaczyna się od taktu 0, a punkt końcowy jest obliczany na podstawie czasu trwania audio i `timing.bps`. |
| `add_track` | `gain` | Opcjonalna nieujemna liczba, domyślnie 1; współczynnik głośności klipu i ścieżki. |

## Generowanie nowej ścieżki audio

Kandydaci są powiązani z wersją projektu w momencie generowania. Najpierw zapisz pustą ścieżkę odbierającą kandydatów, następnie wyeksportuj bieżący miks jako odniesienie do generowania; po zakończeniu generowania wybierz jednego kandydata i zatwierdź go na tej pustej ścieżce.

### Rezerwowanie ścieżki docelowej：`save`

Kandydaci `generate_track` są powiązani z bieżącą wersją projektu. Do **pełnego** `state` zwróconego w stanie końcowym poprzedniego `add_track` dodaj następującą pustą ścieżkę do `state.tracks`, a następnie zapisz za pomocą `save`; pozostałe istniejące pola zachowaj bez zmian：

### Wygeneruj kandydatów: `generate_track`

| Parametr | Typ i opis |
|---|---|
| `source_audio_id` | Wymagane; ID ukończonego źródłowego audio. Najpierw dodaj źródłowe audio do projektu, aby później można było określić pozycję kandydata. |
| `render_audio_id` | Wymagane; `response.data.audio_id` ze stanu końcowego powyższego `render`, a nie adres URL audio. |
| `model` | Wymagane; opcje to `chirp-v3-5`、`chirp-v4`、`chirp-v4-5`、`chirp-v4-5-plus`、`chirp-v5`、`chirp-v5-5`、`chirp-v6`、`chirp-v6-wild`、`chirp-v6-mini`. To, czy konkretna kombinacja jest dostępna, zależy od stanu końcowego zadania. |
| `start_seconds`、`end_seconds` | Wymagane liczby, `0 ≤ start_seconds < end_seconds`; zakres sekund w źródłowym audio, a nie liczba taktów projektu, i nie gwarantuje długości wyjściowej. |
| `stem_control_tags` | Wymagany ciąg znaków; opis nowo dodanej partii, na przykład `add Piano`、`add Drums`、`add Bass`, nie jest stałą enumeracją. |
| `batch_size` | Opcjonalna liczba całkowita 1–4, domyślnie 2; liczba kandydatów. |
| `instrumental`、`vocal_gender` | Opcjonalne; czysto instrumentalne domyślnie to `true`, preferencje wokalne mogą mieć wartość `f`、`m`、`unspecified`, domyślnie `unspecified`. |
| `title`、`tags`、`negative_tags`、`prompt` | Opcjonalne ciągi znaków; są to odpowiednio tytuł kandydata, oczekiwany styl, style do uniknięcia, tekst lub podpowiedź tekstu dla nowej partii. |

```

&#123;
"action": "generate_track",
"id": "af0e104a-2a4c-40e0-9c70-7614566824a6",

## Zamiana istniejącego klipu

`replace_section` może bezpośrednio używać istniejącego źródłowego audio, bez konieczności wcześniejszego eksportowania miksu. Generowanie zwraca tylko kandydatów; podczas zatwierdzania wybierz oryginalną ścieżkę zawierającą jedyny klip źródłowy.

| Parametr | Typ i opis |
|---|---|
| `source_audio_id` | Wymagany; ID ukończonego źródłowego audio, które ma zostać zastąpione. |
| `model` | Wymagany; użyj publicznego modelu wymienionego w „Generowaniu kandydatów”, dostępność modelu i operacji zależy od końcowego stanu zadania. |
| `start_seconds`、`end_seconds` | Wymagane liczby, `0 ≤ start_seconds < end_seconds ≤ czas trwania źródłowego audio`; przedział sekund wewnątrz źródłowego audio. |
| `prompt`、`replacement_lyrics` | Opcjonalne ciągi znaków; pierwszy to oryginalne teksty lub kontekst, drugi to nowe teksty dla zastępowanego przedziału. |
| `title`、`tags`、`negative_tags` | Opcjonalne ciągi znaków; tytuł kandydata, oczekiwany styl i style, których należy unikać. |
| `fixed` | Opcjonalna wartość logiczna, domyślnie `false`; po ustawieniu na `true` przedział musi być krótszy niż 26 sekund, a model może tego nie obsługiwać. |

## Błędy i odzyskiwanie

| Wynik | Znaczenie | Następny krok |
|---|---|---|
| `project_version_conflict` / `project_candidate_stale`（409） | Wersja projektu uległa zmianie lub kandydat nie należy do bieżącej wersji. | Pobierz najnowszy projekt za pomocą `retrieve` i ponownie zaplanuj modyfikacje; nie odtwarzaj starych kandydatów. |
| `bad_request` / `studio_state_invalid` / `studio_model_unsupported`（zwykle 400） | Parametry, stan ścieżki, długość kandydata lub model nie są zgodne z operacją. | Sprawdź błąd stanu końcowego zadania, popraw dane wejściowe; zachowaj oryginalny projekt, jeśli kandydata nie można bezpiecznie połączyć. |
| `studio_audio_unavailable` / `studio_access_denied` / `content_rejected`（403） | Referencyjne audio nie jest dostępne dla operacji projektu, brak uprawnień dostępu lub kontrola treści odrzuciła zawartość. | Sprawdź źródło audio i `trace_id` zadania; nie utożsamiaj już wygenerowanego kandydata z możliwością wyeksportowania całego utworu. |
| `too_many_requests`（429） | Żądanie zostało objęte ograniczeniem częstotliwości. | Najpierw sprawdź oryginalne zadanie, a następnie zdecyduj, czy rozpocząć nową operację z nowym kluczem idempotencji. |
| `studio_unavailable` / `studio_model_unavailable`（503） | Przetwarzanie projektu lub wybrany model jest tymczasowo niedostępny. | Zachowaj wynik oryginalnego zadania; ponów próbę jawnie później, nie przełączaj automatycznie modelu. |
| `studio_processing_failed` / przekroczenie czasu（500/504） | Przetwarzanie nie powiodło się lub stan końcowy jest niepewny. | Sprawdź według `task_id` lub oryginalnego klucza idempotencji, aby uniknąć podwójnie płatnego generowania. |

Projekt i kandydaci są powiązani z aplikacją i środowiskiem wykonawczym, które je utworzyły; nie można zakładać ponownego użycia między aplikacjami ani automatycznego przełączania awaryjnego. Trwale zapisuj końcowy adres URL audio pomyślnie wyeksportowanego pliku i zachowuj `trace_id` w celu ułatwienia diagnostyki.
