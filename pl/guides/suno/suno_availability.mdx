---
title: "API sprawdzania dostępności audio Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` wyszukuje na podstawie `audio_id` pozytywne dowody na to, że audio może być dalej przetwarzane na bieżącej trasie. Można je wywołać przed operacjami takimi jak kontynuowanie lub tworzenie coverów; wynik odzwierciedla wyłącznie stan w chwili sprawdzenia i nie gwarantuje powodzenia konkretnej operacji. Interfejs zwraca odpowiedź synchronicznie, wymaga tokenu API i obecnie nie pobiera Credits.

`audio_id` to identyfikator utworu zwrócony przez zakończone zadanie Suno, a nie `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Przykład pomyślnej odpowiedzi:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

Gdy sprawdzenie zakończy się powodzeniem, `data.available` ma wartość `true`; gdy nie można tego potwierdzić, zwracane jest `503 availability_unknown`, bez `false`. Nieprawidłowy format `audio_id` zwraca błąd 400, a ograniczenie szybkości lub błąd usługi również zwrócą odpowiedź z błędem. Stan może się nadal zmienić między zakończeniem sprawdzenia a rzeczywistą operacją.
