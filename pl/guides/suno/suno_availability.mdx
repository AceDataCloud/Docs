title: "API sprawdzania dostępności audio i głosów Suno"

`POST /suno/availability` przyjmuje ID zasobu. Aby sprawdzić utwór, przekaż `audio_id`, aby sprawdzić głos, przekaż `persona_id`; jedno z nich jest wymagane. Sprawdzenie jest wykonywane synchronicznie, wymaga API Token i obecnie nie nalicza Credits.

## Żądanie

`audio_id` pochodzi z ukończonego zadania utworu i może być używany do sprawdzenia przed kontynuacją lub coverem.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

`persona_id` pochodzi z wyniku utworzenia głosu. Użyj oryginalnej aplikacji i tożsamości wywołującego, a następnie wyślij poniższe ciało żądania na linii tworzenia obsługującej zapytania o głosy.

```json
{"persona_id":"33333333-3333-4333-8333-333333333333"}
```

## Odpowiedź

Oba typy żądań używają tej samej pomyślnej odpowiedzi. `data.id` jest ID zasobu dla tego zapytania.

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

`available: true` oznacza, że to sprawdzenie uzyskało pozytywne potwierdzenie. W przypadku głosów sprawdzenie weryfikuje przynależność utworzenia i potwierdza, że powiązane konto jest obecnie zgłaszane jako online. Rzeczywisty wynik generowania nadal zależy od zadania generowania.

Prywatne klonowane głosy utworzone przez `/suno/voices` zależą od konta tworzącego. Gdy zostanie potwierdzone, że to konto jest obecnie offline, interfejs zwraca HTTP 200, a przykład `data` jest następujący.

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

Klient może oznaczyć ten głos jako obecnie niedostępny i sprawdzić ponownie później.

Gdy nie można potwierdzić, zwracane są HTTP 503 i `availability_unknown`, na przykład gdy nie można znaleźć zasobu, stare rekordy nie zawierają linii tworzenia lub wystąpił limit czasu zapytania. Publiczne style wokalistów mogą być używane między kontami i również zwracają 503, gdy konto tworzące jest offline. Zapytania o utwory nadal zwracają `available: true` tylko wtedy, gdy dostępność została potwierdzona.

Każde żądanie wysyła tylko jeden prawidłowy UUID. Wszystkie linie zwracają HTTP 400 po otrzymaniu żądania z podwójnym ID lub z brakiem obu ID. Linie obsługujące wyłącznie zapytania o utwory zwracają HTTP 400 po otrzymaniu żądania zawierającego tylko `persona_id`. W przypadku HTTP 429 należy zmniejszyć częstotliwość zapytań.
