---
title: "API sprawdzania dostępności audio Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` wyszukuje na podstawie `audio_id` pozytywne dowody, że audio może być dalej przetwarzane na obecnej linii. Można wywołać przed operacjami takimi jak kontynuacja, cover itp.; wynik odzwierciedla tylko stan w momencie sprawdzenia i nie gwarantuje, że konkretna operacja na pewno się powiedzie. Ten interfejs synchronicznie zwraca wynik, wymaga API Token i obecnie nie pobiera Credits.

`audio_id` to ID utworu zwrócone przez ukończone zadanie Suno, a nie `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Przykład pomyślnej odpowiedzi:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

Gdy sprawdzenie zakończy się powodzeniem, `data.available` może mieć wyłącznie wartość `true`. Status „offline” zwracany przez niektóre linie nie może potwierdzić, że kolejne operacje, takie jak kontynuacja, nie mogą się powieść, dlatego ten interfejs zwraca `503 availability_unknown`, gdy nie może tego potwierdzić, i nie zwraca `false`. Błędny format `audio_id` zwraca 400, ograniczenie liczby żądań lub awaria upstream również zwracają odpowiedź błędu. Stan może nadal ulec zmianie między zakończeniem sprawdzenia a faktyczną operacją.
