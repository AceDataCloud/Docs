Wraz z coraz szerszym zastosowaniem AI, różnego rodzaju programy AI stopniowo się upowszechniły. AI stopniowo przenika do wszystkich aspektów pracy i życia ludzi. A branż związanych z AI jest coraz więcej — od początkowego pisania, przez medycynę i edukację, aż po obecną muzykę.

Suno to profesjonalna, wysokiej jakości platforma AI do tworzenia piosenek i muzyki, na której użytkownicy muszą jedynie wprowadzić proste tekstowe słowa podpowiedzi, aby na podstawie stylu gatunkowego i tekstu wygenerować piosenki z wokalem. Ten generator muzyki AI został opracowany przez członków zespołu pochodzących z renomowanych firm technologicznych, takich jak Meta, TikTok i Kensho, a jego celem jest umożliwienie wszystkim tworzenia pięknej muzyki bez potrzeby używania jakichkolwiek instrumentów.

> Limity `lyric` i `style` w powyższej tabeli są górnymi limitami w trybie niestandardowym (`custom` ma wartość `true`). W nieniestandardowym trybie inspiracji (`custom` ma wartość `false`) należy wypełnić tylko `prompt`, którego maksymalna długość wynosi 500 znaków (jednakowa dla wszystkich modeli).

Suno obsługuje obecnie `chirp-v6`, `chirp-v6-wild` oraz `chirp-v6-mini`. Zaleca się korzystanie z `chirp-v6`; nazwy starszych modeli pozostają kompatybilne.

Jednak Suno oficjalnie nie udostępnia API, a AceDataCloud oferuje zestaw API Suno, który symuluje integrację z oficjalnym Suno, umożliwiając wygodne i szybkie generowanie pożądanej muzyki.

## Aplikowanie i użytkowanie

Aby korzystać z Suno Audios Generation API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i logowania, a po zakończeniu automatycznie powrócisz na bieżącą stronę.

**Jeden API Token pozwala wywoływać wszystkie usługi platformy, bez konieczności osobnego aplikowania dla każdej usługi.** Przy pierwszym uzyskaniu przyznawany jest bezpłatny limit, który umożliwia darmowe wypróbowanie; gdy limit jest niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Podstawowe użycie

Jakie piosenki chcesz, możesz dowolnie wpisać fragment tekstu. Na przykład, jeśli chcę wygenerować piosenkę o Bożym Narodzeniu, mogę wpisać `a song for Christmas`, jak pokazano na ilustracji:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Można zobaczyć, że tutaj ustawiliśmy Request Headers, w tym:

- `accept`: jaki format wyniku odpowiedzi chcesz otrzymać; tutaj wpisano `application/json`, czyli format JSON.
- `authorization`: klucz do wywołania API, po uzyskaniu można go bezpośrednio wybrać z listy rozwijanej.

Dodatkowo ustawiono Request Body, w tym:
- `action`: Działanie dla tego zadania generowania muzyki, domyślnie `generate`, głównie obejmuje: `extend`, `upload_extend`, `cover`, `upload_cover`, `replace_section`, `replace_section`, `concat`, `stems`, `all_stems`, `remaster`.
- `prompt`: Podpowiedź trybu inspiracji Suno Official (obowiązuje, gdy `custom` ma wartość `false`), maksymalnie 500 znaków.
- `model`: Model dla tego zadania generowania muzyki. Seria v6 obejmuje `chirp-v6`, `chirp-v6-wild` i `chirp-v6-mini`; nazwy starszych modeli nadal są kompatybilne.
- `lyric`: Treść tekstu piosenki w trybie niestandardowym Suno Official. `chirp-v3-5` i `chirp-v4` maksymalnie 3000 znaków; `chirp-v4-5` i nowsze (w tym `chirp-v5`, `chirp-v5-5`) maksymalnie 5000 znaków.
- `custom`: Czy używać trybu niestandardowego, domyślnie: `false`.
- `instrumental`: Opcja muzyki instrumentalnej w trybie inspiracji Suno Official.
- `title`: Tytuł utworu w trybie niestandardowym Suno Official. `chirp-v3-5`, `chirp-v4` maksymalnie 80 znaków; `chirp-v4-5` i nowsze maksymalnie 100 znaków.
- `style`: Styl muzyczny w trybie niestandardowym Suno Official. `chirp-v3-5` i `chirp-v4` maksymalnie 200 znaków; `chirp-v4-5` i nowsze (w tym `chirp-v5`, `chirp-v5-5`) maksymalnie 1000 znaków.
- `negative_tags`: Style muzyczne lub gatunki, które mają zostać wykluczone z wyników generowania w trybie niestandardowym (gdy `custom` ma wartość `true`).
- `audio_weight`: Udział przesłanego referencyjnego audio, zakres 0-1; im większy, tym większa zależność od referencyjnego audio.
- `audio_id`: ID referencyjnej muzyki.
- `overpainting_start`/`overpainting_end`: Czas rozpoczęcia i zakończenia dodawania wokalu do istniejącej muzyki instrumentalnej, w sekundach.
- `underpainting_start`/`underpainting_end`: Czas rozpoczęcia i zakończenia dodawania akompaniamentu do śpiewu a cappella, w sekundach.
- `persona_id`: ID utworu artysty.
- `continue_at`: Granica kontynuacji, w sekundach. Na przykład 213.5 oznacza rozpoczęcie generowania kolejnego fragmentu od 3 minut i 33.5 sekundy. `lyric` i `style` prowadzą jedynie nową treść po granicy i nie zastępują tekstu ani śpiewu przed granicą w źródłowym audio.
- `style_influence`: Zaawansowany parametr „Style Influence” w trybie niestandardowym, zakres 0-1; im większy, tym lepiej dopasowuje się do wybranego stylu.
- `replace_section_end`: Końcowy czas zastępowanego fragmentu.
- `replace_section_start`: Początkowy czas zastępowanego fragmentu.
- `vocal_gender`: Kontroluje preferencję głosu żeńskiego lub męskiego, głos żeński `f`, głos męski `m`; obowiązuje dla modeli 4.5 i nowszych; jest opcją preferencji i nie gwarantuje ścisłego przestrzegania.
- `weirdness`: Zaawansowany parametr „Weirdness” w trybie niestandardowym, zakres 0-1; im większy, tym większa kreatywność i eksperymentalność.
- `duration`: Oczekiwany czas trwania utworu, w sekundach, musi być liczbą całkowitą, zakres wartości od 10 do 360. Ten parametr jest używany do generowania utworów w trybie niestandardowym (gdy `custom` ma wartość `true`). Jest to wskazówka preferencyjna, a nie twarde ograniczenie: model bierze ją pod uwagę, ale nie gwarantuje jej osiągnięcia; rzeczywisty czas trwania gotowego utworu zależy od pola `duration` w odpowiedzi i zwykle jest krótszy niż oczekiwany.
- `lyric_prompt`: Prompt do generowania tekstu piosenki, obowiązuje wtedy i tylko wtedy, gdy `custom` ma wartość `true` oraz `lyric` nie został przekazany.
- `callback_url`: URL, pod który należy zwrócić wynik wywołania zwrotnego.
- `async`: Opcjonalne; gdy ustawione na `true`, interfejs natychmiast zwraca `task_id`, bez konieczności podawania `callback_url`, a następnie wynik można uzyskać przez odpytywanie odpowiedniego interfejsu zapytania o zadanie.

## Generowanie niestandardowe

Jeśli chcesz niestandardowo wygenerować tekst piosenki, możesz wprowadzić tekst:

W tym momencie do pola `lyric` można przekazać treść podobną do poniższej:

```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> Uwaga, `\n` w tekście piosenki tutaj jest znakiem nowej linii. Jeśli nie wiesz, jak wygenerować tekst piosenki, możesz użyć API generowania tekstów dostarczanego przez AceDataCloud, aby generować teksty za pomocą promptu. API to [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Następnie, aby niestandardowo wygenerować piosenkę na podstawie tekstu, tytułu i stylu, można określić następującą zawartość:

- lyric：tekst piosenki
- custom：ustaw na `true`, oznacza generowanie niestandardowe. Domyślna wartość tego parametru to false, co oznacza generowanie za pomocą `prompt`.
- title：tytuł piosenki.
- style：styl piosenki, opcjonalnie.

## Funkcja niestandardowego generowania w stylu wokalisty
Jeśli chcesz użyć stylu wokalisty do generowania piosenek, najpierw wygeneruj piosenkę poprzez podstawowe użycie opisane powyżej,
po czym otrzymasz potrzebę ustawienia tej piosenki jako stylu wokalisty, następnie musisz przejść do [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona), aby na podstawie oficjalnie wygenerowanego ID muzyki `audio_id` wygenerować parametr ID stylu wokalisty `persona_id`, konkretne parametry pokazano na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

Odpowiedni kod Python:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Funkcja kontynuacji generowania

Jeśli chcesz kontynuować generowanie już wygenerowanej piosenki Suno, możesz ustawić parametr `action` na `extend` oraz wprowadzić ID piosenki, której generowanie ma być kontynuowane; ID piosenki uzyskuje się zgodnie z podstawowym użyciem, z powyższego wynika, że w tym momencie ID piosenki to:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Uwaga, `id` w tekście piosenki tutaj jest ID piosenki po jej wygenerowaniu. Jeśli nie wiesz, jak wygenerować piosenkę, możesz zapoznać się z podstawowym użyciem powyżej, aby ją wygenerować.

Jeśli chcesz kontynuować generowanie własnej przesłanej piosenki, możesz ustawić parametr `action` na `upload_extend` oraz wprowadzić ID własnej przesłanej piosenki, której generowanie ma być kontynuowane; ID piosenki uzyskuje się za pomocą [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), jak pokazano na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Następnie musisz wypełnić tekst kontynuowanego fragmentu i możesz określić styl:

- lyric：używane tylko do kierowania tekstem nowo wygenerowanego fragmentu po `continue_at`, nie zastąpi tekstu w źródłowym audio przed tym punktem czasowym.
- custom：ustawienie na `true` oznacza generowanie niestandardowe, domyślna wartość tego parametru to false, co oznacza generowanie przy użyciu `prompt`.
- style：styl piosenki kontynuowanego fragmentu, opcjonalne.
- continue_at：granica kontynuacji, jednostką są sekundy. Na przykład 213.5 oznacza rozpoczęcie generowania kolejnego fragmentu od 3 minuty i 33.5 sekundy.

> `extend` służy do tworzenia dalszej części istniejącej piosenki, a nie do zmiany tekstu całej piosenki. Jeśli chcesz użyć nowego tekstu od początku całej piosenki, użyj `generate`, aby wygenerować ją ponownie; jeśli chcesz ponownie zinterpretować istniejącą piosenkę, możesz użyć `cover`. Po przekazaniu całego nowego tekstu oryginalny tekst przed `continue_at` nadal nie zostanie zastąpiony.

## Zastępowanie fragmentu

Gdy po wygenerowaniu utworu konieczna jest dodatkowa twórcza operacja polegająca na osobnym zastąpieniu fragmentu utworu, można wykonać operację zastąpienia określonego fragmentu utworu.

> ⚠️ **Uwaga**：`replace_section_result_mode` domyślnie ma wartość `full_song`：system osobno łączy 2 nowo wygenerowanych kandydatów i zwraca 2 kompletne utwory. Jeśli potrzebujesz tylko jeszcze niepołączonych kandydatów zastępowanego fragmentu, jawnie ustaw wartość `candidates`, a następnie wybierz kandydata i wywołaj [łączenie muzyki](#音乐拼接).

Opis parametrów jest następujący:

- action：wartość to `replace_section`。
- audio_id：ID oryginalnego utworu (źródłowego utworu, który zostanie zastąpiony).
- model: Model generowania utworu.
- lyric: Pełny tekst po zastąpieniu (obejmujący zastępowany fragment i jego kontekst, zgodny z zawartością w `prompt`).
- prompt：Nowy tekst dla fragmentu, który ma zostać zastąpiony.
- style：Styl utworu, opcjonalny.
- replace_section_start：Czas rozpoczęcia zastępowanego fragmentu w oryginalnym utworze (w sekundach).
- replace_section_end：Czas zakończenia zastępowanego fragmentu w oryginalnym utworze (w sekundach).
- replace_section_result_mode：Tryb zwracania, domyślnie `full_song`。`full_song` osobno łączy 2 kandydatów i zwraca 2 kompletne utwory；`candidates` zwraca 2 jeszcze niepołączone fragmenty kandydackie.

- action：wartość to `stems`。
- audio_id：ID wcześniej wygenerowanego utworu.

```json
{
  "action": "stems",
  "audio_id": "ec13e502-d043-4eb2-92ee-e900c6da69d1"
}
```

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v4-5",
    "lyric": "Hello Hello Hello ",
    "custom": True,
    "weirdness": 0.4,
    "style_influence": 0.4,
    "audio_weight": 0.4
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Kontrolowanie długości utworu

Domyślnie długość generowanego utworu jest określana przez model, zazwyczaj wynosi od 30 sekund do 4 minut. Jeśli potrzebny jest dłuższy lub krótszy gotowy utwór, można określić oczekiwaną długość za pomocą parametru `duration`, w sekundach, przyjmującego wartości całkowite od 10 do 360.

Ten parametr jest używany do generowania utworów w trybie niestandardowym (`custom` ma wartość `true`). Należy szczególnie zaznaczyć, że `duration` jest **wskazówką dotyczącą preferencji, a nie sztywnym ograniczeniem**: model będzie odnosił się do tej wartości podczas tworzenia, ale nie gwarantuje jej osiągnięcia; w testach rzeczywista długość jest zazwyczaj wyraźnie krótsza od oczekiwanej wartości, a długości dwóch utworów zwróconych w tym samym żądaniu mogą również różnić się kilkukrotnie. Nawet dla całkowicie identycznych żądań długości uzyskane przy wielokrotnym przesyłaniu mogą znacznie się różnić. Dlatego nie należy używać go jako precyzyjnej kontroli długości; jeśli biznesowo wymagana jest stała długość, po otrzymaniu gotowego utworu należy samodzielnie go przyciąć lub ponowić próbę.

Odpowiedni kod Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Należy zauważyć, że `duration` w żądaniu jest **oczekiwaną długością**, natomiast pole `duration` każdej piosenki w odpowiedzi `data` jest **rzeczywistą długością** tej piosenki. Mają tę samą nazwę, ale różne znaczenia; rzeczywista długość nie jest gwarantowana jako równa oczekiwanej wartości. Długość tekstu jest jednym z głównych czynników wpływających na długość gotowego utworu; jeśli potrzebny jest dłuższy gotowy utwór, zaleca się jednoczesne podanie pełniejszego tekstu.

Interfejs nie wykonuje dodatkowej walidacji `duration`, a parametr jest przekazywany do modelu w niezmienionej postaci. Jeśli zostanie przekazana wartość nieobsługiwana przez bieżący tryb lub model, może to skutkować zignorowaniem tej wartości; zaleca się najpierw potwierdzić efekt jednym żądaniem, a dopiero potem używać go masowo.

## Funkcja tworzenia inspirowanego Inspo

Funkcja tworzenia inspirowanego Inspo może generować nową muzykę na podstawie od 1 do 4 kompletnych referencyjnych nagrań audio, obsługując przeciąganie i upuszczanie lub przesyłanie plików audio jako źródeł inspiracji. API używa istniejącej akcji `inspo`: klient podaje publicznie dostępne adresy URL audio, a usługa automatycznie wykonuje przygotowanie referencyjnego audio i tworzenie, bez potrzeby osobnego odczytywania przez klienta tekstu, stylu lub czasu trwania, a następnie składania żądania. Różni się to od opisanego powyżej próbkowania zakresu, a także od Cover odtwarzającego styl oryginalnego utworu. Podczas użycia należy wypełnić następujące parametry:

- action: zawartość to `inspo`.
- audio_urls: lista adresów URL referencyjnego audio, należy podać od 1 do 4 publicznie dostępnych adresów audio.
- model: używany model, zalecany jest `chirp-v6`.
- prompt: tekst piosenki lub podpowiedź twórcza (opcjonalnie).

> Uwaga: referencyjne audio musi być publicznie dostępnym plikiem audio. Jeśli referencyjne audio całkowicie odpowiada znanemu nagraniu z katalogu utworów platformy, Suno może odmówić generowania z powodu weryfikacji praw autorskich; zaleca się użycie własnego audio lub audio wygenerowanego przez Suno jako źródła inspiracji.

Odpowiedni kod Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynchroniczne wywołanie zwrotne

Ponieważ generowanie muzyki przez Suno trwa stosunkowo długo, około 1–2 minut, jeśli API przez długi czas nie odpowiada, żądanie HTTP będzie stale utrzymywać połączenie, co prowadzi do dodatkowego zużycia zasobów systemowych, dlatego to API również obsługuje asynchroniczne wywołania zwrotne.

Ogólny proces wygląda następująco: gdy klient inicjuje żądanie, dodatkowo określa pole `callback_url`; po wysłaniu przez klienta żądania API, API natychmiast zwróci wynik zawierający informację w polu `task_id`, reprezentującym identyfikator bieżącego zadania. Po zakończeniu zadania wynik wygenerowanej muzyki zostanie wysłany w formie POST JSON na wskazany przez klienta `callback_url`, który również zawiera pole `task_id`, dzięki czemu wyniki zadania można powiązać za pomocą ID.

Poniżej, na przykładzie, zobaczymy, jak konkretnie to zrobić.

Dla wygody demonstracji użyto tutaj publicznej przykładowej strony Webhook https://webhook.site/; po otwarciu tej strony można uzyskać adres URL Webhook, jak pokazano na ilustracji:
