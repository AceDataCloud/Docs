Wraz z rozszerzaniem zastosowań AI, różnego rodzaju programy AI stopniowo zyskują popularność. AI stopniowo przenika do wszystkich aspektów pracy i życia ludzi. Coraz więcej jest także branż związanych z AI — od początkowego pisania, przez medycynę i edukację, aż po obecną muzykę.

Suno to profesjonalna, wysokiej jakości platforma do tworzenia piosenek i muzyki za pomocą AI. Użytkownicy muszą jedynie wprowadzić proste tekstowe podpowiedzi, aby na podstawie gatunku, stylu i tekstu wygenerować piosenki z wokalem. Ten generator muzyki AI został opracowany przez członków zespołów z renomowanych firm technologicznych, takich jak Meta, TikTok i Kensho, a jego celem jest umożliwienie każdemu tworzenia pięknej muzyki bez potrzeby używania jakichkolwiek instrumentów.

Jednak oficjalne Suno nie udostępnia API. AceDataCloud oferuje zestaw API Suno, które symuluje integrację z oficjalnym Suno i umożliwia wygodne oraz szybkie generowanie pożądanej muzyki.

Aby korzystać z Suno Audios Generation API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go do późniejszego użycia.

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, która zaprosi Cię do rejestracji i zalogowania się. Po zakończeniu automatycznie wrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności składania osobnego wniosku dla każdej usługi.** Przy pierwszym wniosku otrzymasz darmowy limit, który pozwala na bezpłatne wypróbowanie usługi; gdy limit jest niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

## Podstawowe użycie

Jakie piosenki chcesz, możesz dowolnie wprowadzić fragment tekstu. Na przykład, jeśli chcę wygenerować piosenkę o Bożym Narodzeniu, mogę wpisać `a song for Christmas`, jak pokazano na ilustracji:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Można zobaczyć, że ustawiliśmy tutaj Request Headers, w tym:

- `accept`: jaki format odpowiedzi chcesz otrzymać; tutaj wpisano `application/json`, czyli format JSON.
- `authorization`: klucz do wywoływania API, który po uzyskaniu można bezpośrednio wybrać z listy rozwijanej.

Dodatkowo ustawiono Request Body, w tym:
- `action`: typ zadania audio, domyślnie `generate`. Obsługuje generowanie, kontynuację, cover, łączenie, rozdzielanie ścieżek, dodawanie ścieżek audio, wyodrębnianie określonych ścieżek audio, generowanie efektów dźwiękowych i dostosowywanie prędkości oraz inne operacje, wywoływane jednolicie przez `POST /suno/audios`.
- `prompt`: podpowiedź trybu inspiracji Suno (obowiązuje, gdy `custom` ma wartość `false`), maksymalnie 500 znaków.
- `model`: model dla tego zadania generowania muzyki. Seria v6 obejmuje `chirp-v6`, `chirp-v6-wild` i `chirp-v6-mini`; nazwy starszych modeli są nadal kompatybilne.
- `max_mode`: ulepszony tryb generowania. `generate` jest włączany tylko wtedy, gdy zarówno `custom`, jak i `max_mode` mają wartość `true`, koszt wynosi 1.12 Credits; `add_stem` można włączyć bezpośrednio, koszt wynosi 1.344 Credits. Po wyłączeniu lub pominięciu koszty wynoszą odpowiednio 0.56 i 0.672 Credits.
- `variety`: intensywność różnorodności wyników generowania, opcje to `off`, `normal`, `high`, `extra`, `max`. Używane tylko dla `generate` i `add_stem`; przekazanie dla innych action zwróci 400.
- `lyric`: treść tekstu piosenki w niestandardowym trybie Suno. Maksymalnie 3000 znaków dla `chirp-v3-5` i `chirp-v4`; maksymalnie 5000 znaków dla `chirp-v4-5` i nowszych (w tym `chirp-v5`, `chirp-v5-5`).
- `custom`: czy używać trybu niestandardowego, domyślnie: `false`.
- `instrumental`: opcja muzyki instrumentalnej w trybie inspiracji Suno.
- `title`: tytuł utworu w niestandardowym trybie Suno. Maksymalnie 80 znaków dla `chirp-v3-5`, `chirp-v4`; maksymalnie 100 znaków dla `chirp-v4-5` i nowszych.
- `style`: styl muzyczny w niestandardowym trybie Suno. Maksymalnie 200 znaków dla `chirp-v3-5` i `chirp-v4`; maksymalnie 1000 znaków dla `chirp-v4-5` i nowszych (w tym `chirp-v5`, `chirp-v5-5`).
- `negative_tags`: style muzyczne lub gatunki, które mają zostać wykluczone podczas niestandardowego generowania, można również używać dla `replace_section`. Ten interfejs obecnie nie ustawia stałego limitu liczby znaków dla tego pola; zbyt długa treść nadal może nie zostać przetworzona, zaleca się zwięzłość opisu.
- `audio_weight`: waga wpływu cech audio lub głosu, zakres 0-1, `0` jest również prawidłową wartością. Może być używana do generowania, kontynuacji, coveru, dodawania ścieżek audio i spójności głosu oraz innych operacji; gdy nie ma referencyjnego audio ani cech głosu, model może osłabić lub zignorować tę wartość.
- `audio_id`: ID referencyjnej muzyki, używane do kolejnych operacji, takich jak cover, kontynuacja, rozdzielanie ścieżek itp. Plik audio nadal może być pobrany, co nie oznacza, że późniejsze przetwarzanie tego ID będzie zawsze dostępne; jeśli zostanie zwrócone `suno_processing_unavailable`, zachowaj `task_id` i `trace_id`, aby skontaktować się z pomocą techniczną.
- `overpainting_start`/`overpainting_end`: czas rozpoczęcia i zakończenia dodawania wokalu do istniejącej muzyki instrumentalnej, w sekundach.
- `underpainting_start`/`underpainting_end`: czas rozpoczęcia i zakończenia dodawania akompaniamentu do śpiewu a cappella, w sekundach.
- `persona_id`: ID głosu uzyskane przez interfejs tworzenia Persona lub głosu, nie jest to `audio_id` utworu.
- `continue_at`: granica kontynuacji, w sekundach. Na przykład 213.5 oznacza rozpoczęcie generowania kolejnego fragmentu od 3 minut i 33.5 sekundy. `lyric` i `style` prowadzą wyłącznie nową treść po granicy i nie zastępują tekstu ani śpiewu przed granicą w źródłowym audio.
- `style_influence`: wpływ stylu w trybie niestandardowym, zakres 0-1; im większy, tym zwykle lepiej odpowiada wybranemu stylowi; `0` zostanie przekazane jako prawidłowa wartość.
- `replace_section_end`: końcowy czas zastępowanego fragmentu.
- `replace_section_start`: początkowy czas zastępowanego fragmentu.
- `vocal_gender`: kontroluje preferencję głosu żeńskiego lub męskiego, głos żeński `f`, głos męski `m`, obowiązuje dla modeli 4.5 i nowszych; jest to preferencja i nie gwarantuje ścisłego przestrzegania.
- `weirdness`: stopień dziwności w trybie niestandardowym, zakres 0-1; im większy, tym zwykle bardziej kreatywny i eksperymentalny; `0` zostanie przekazane jako prawidłowa wartość.
- `duration`: oczekiwana długość utworu, w sekundach, musi być liczbą całkowitą, zakres wartości od 10 do 360. Obecnie tylko `generate` używa tego parametru, a konkretny efekt zależy od trybu i modelu. Jest to podpowiedź dotycząca preferencji, a nie twarde ograniczenie: model weźmie ją pod uwagę, ale nie gwarantuje jej osiągnięcia; rzeczywista długość gotowego utworu zależy od pola `duration` w odpowiedzi i zazwyczaj jest krótsza od oczekiwanej wartości.

### Zakres zastosowania ID głosu

`generate`, `cover`, `upload_cover`, `artist_consistency`, `artist_consistency_vox` mogą używać `persona_id`. Dwa ostatnie action muszą zawierać `persona_id`; można również jednocześnie podać `audio_id` utworu użytego podczas tworzenia tej Persona.

`extend`, `upload_extend` nie używają dodatkowego `persona_id`. To, czy `mashup`, `inspo` obsługują ID głosu, zależy od wybranego kanału usługi; inne action nie gwarantują zastosowania tego pola, należy używać go zgodnie z opisem poszczególnych operacji. `vocal_gender` jest opcjonalną preferencją płci i nie może zastępować ID głosu.

Kolejne operacje twórcze wymagają prawidłowego źródłowego `audio_id`; `mashup` wymaga co najmniej dwóch `mashup_audio_ids`. Brak niezbędnego źródła lub parametrów czasu zwróci HTTP 400.

### Zakres zastosowania zaawansowanych parametrów
| Parametr                | Wartość                                      | Obsługiwane action                         | Opis                              |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | Opcjonalne                              | Reguluje eksperymentalność, `0` jest prawidłową wartością; efekt zależy od operacji, trybu i modelu      |

Platforma sprawdza typy parametrów i zakresy wartości, ale nie odrzuca tych opcjonalnych ustawień regulacyjnych wyłącznie z powodu różnic w action; konkretny efekt zależy od operacji, trybu i modelu.

- `lyric_prompt`: prompt do generowania tekstu piosenki, działa wtedy i tylko wtedy, gdy `custom` ma wartość `true` i nie przekazano `lyric`.

## Generowanie niestandardowe

Jeśli chcesz niestandardowo wygenerować tekst piosenki, możesz wprowadzić tekst:

W tym momencie do pola `lyric` można przekazać treść podobną do poniższej:
```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> Uwaga, w tym tekście piosenki `\n` oznacza znak nowej linii. Jeśli nie wiesz, jak wygenerować tekst piosenki, możesz użyć interfejsu API generowania tekstów piosenek udostępnianego przez AceDataCloud, aby wygenerować tekst piosenki za pomocą promptu, API to [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Następnie chcemy wygenerować piosenkę na podstawie tekstu, tytułu i stylu niestandardowego, można więc określić następującą zawartość:

- lyric: tekst piosenki
- custom: ustaw na `true`, co oznacza niestandardowe generowanie; domyślna wartość tego parametru to false, co oznacza użycie `prompt` do generowania.
- title: tytuł piosenki.
- style: styl piosenki, opcjonalny.

## Funkcja niestandardowego generowania w stylu wokalisty

Jeśli chcesz użyć stylu wokalisty do wygenerowania piosenki, najpierw wygeneruj piosenkę poprzez podstawowe użycie opisane powyżej,
a na końcu musisz ustawić tę piosenkę jako styl wokalisty, następnie musisz przejść do [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona), aby na podstawie oficjalnie wygenerowanego identyfikatora muzyki `audio_id` wygenerować parametr id stylu wokalisty `persona_id`, konkretne parametry są pokazane na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Po wypełnieniu kod zostanie automatycznie wygenerowany w następujący sposób:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

Odpowiedni kod Python:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Kliknij uruchom, a zobaczysz, że otrzymasz wynik, jak poniżej:

```json

  "task_id": "7628b754-4fe7-4e79-bda4-806d0dd8bf6e",
  "data": {
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b"
  }
```

## Funkcja kontynuowania generowania
Jeśli chcesz kontynuować generowanie już wygenerowanej piosenki Suno, możesz ustawić parametr `action` na `extend` oraz wprowadzić ID piosenki, którą chcesz dalej generować. ID piosenki uzyskuje się zgodnie z podstawowym użyciem. Jak wynika z powyższego, w tym momencie można zobaczyć, że ID piosenki to:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Uwaga, tutaj `id` w tekście piosenki jest ID piosenki po wygenerowaniu. Jeśli nie wiesz, jak wygenerować piosenkę, możesz zapoznać się z podstawowym użyciem powyżej, aby wygenerować piosenkę.

Jeśli chcesz kontynuować generowanie piosenki przesłanej przez siebie, możesz ustawić parametr `action` na `upload_extend` oraz wprowadzić ID niestandardowo przesłanej piosenki, którą chcesz dalej generować. ID piosenki uzyskuje się za pomocą [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), jak pokazano na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Następnie należy wypełnić tekst fragmentu do kontynuacji i można określić styl:

- lyric: służy wyłącznie do kierowania tekstem nowo wygenerowanego fragmentu po `continue_at`; nie zastąpi tekstu w źródłowym audio przed tym punktem czasowym.
- custom: ustawienie na `true` oznacza niestandardowe generowanie; parametr ten domyślnie ma wartość false, co oznacza generowanie przy użyciu `prompt`.
- style: styl piosenki dla fragmentu kontynuacji, opcjonalny.
- continue_at: granica kontynuacji, w sekundach. Na przykład 213.5 oznacza rozpoczęcie generowania kolejnego fragmentu od 3 minuty i 33,5 sekundy.

Wartość `continue_at` dla `extend` i `upload_extend` musi być większa niż 0; obsługiwane są ułamkowe sekundy, na przykład `30.792`; podczas przesyłania wartość nie będzie zaokrąglana.

> `extend` służy do dalszego tworzenia na podstawie istniejącej piosenki, a nie do zmiany tekstu całej piosenki. Jeśli chcesz użyć nowego tekstu dla całej piosenki od początku, użyj `generate`, aby wygenerować ją ponownie; jeśli chcesz ponownie zinterpretować istniejącą piosenkę, możesz użyć `cover`. Po przekazaniu całego nowego tekstu oryginalny tekst przed `continue_at` nadal nie zostanie zastąpiony.

## Cover muzyczny

Gdy po dalszym generowaniu piosenki na podstawie istniejącej piosenki styl zwróconej piosenki może nie być odpowiedni. Jeśli chcesz wykonać cover wcześniej wygenerowanej piosenki (obsługiwana jest również muzyka przesłana niestandardowo), należy użyć metody coveru muzycznego, w której można określić następującą zawartość:

- action：wartość to `cover`; w przypadku wykonywania coveru niestandardowo przesłanej muzyki należy obowiązkowo określić wartość: `upload_cover`.

Jeśli wymagane jest wykonanie coveru z użyciem określonego głosu, można jednocześnie przekazać `persona_id`. ## Zastępowanie fragmentów

Gdy po wygenerowaniu piosenki potrzebna jest wtórna kreacja polegająca na osobnym zastępowaniu fragmentu piosenki, można wykonać operację zastąpienia określonego fragmentu piosenki.
> ⚠️ **Uwaga**: `replace_section_result_mode` domyślnie ma wartość `full_song`: system osobno scala 2 nowo wygenerowane kandydatury i zwraca 2 pełne utwory. Jeśli potrzebujesz tylko kandydatur fragmentów zastępczych, które nie zostały jeszcze scalone, ustaw jawnie wartość `candidates`, a następnie wybierz kandydaturę i wywołaj [scalanie muzyki](#音乐拼接).

Opis parametrów jest następujący:

- action: zawartość to `replace_section`.
- audio_id: ID oryginalnego utworu (źródłowego utworu, w którym dokonywana jest zamiana).
- model: model generowania utworów.
- lyric: pełny tekst po zamianie (obejmuje zastępowany fragment i jego kontekst, zgodny z zawartością w `prompt`).
- prompt: nowy tekst dla fragmentu, który ma zostać zastąpiony.
- style: styl utworu, opcjonalny.
- negative_tags: style lub gatunki, które mają zostać wykluczone, opcjonalne.
- replace_section_start: czas rozpoczęcia zastępowanego fragmentu w oryginalnym utworze (sekundy), wymagany i nie może być mniejszy niż 0.
- replace_section_end: czas zakończenia zastępowanego fragmentu w oryginalnym utworze (sekundy), wymagany i musi być większy niż czas rozpoczęcia.
- replace_section_result_mode: tryb zwracania, domyślnie `full_song`. `full_song` osobno scala 2 kandydatury i zwraca 2 pełne utwory; `candidates` zwraca 2 niescalone fragmenty kandydackie.

```json
{
  "action": "all_stems",
```

## Kontrolowanie długości piosenki

Domyślnie długość generowanej piosenki jest określana przez model, zwykle wynosi od 30 sekund do 4 minut. Jeśli potrzebny jest dłuższy lub krótszy gotowy utwór, można określić oczekiwaną długość za pomocą parametru `duration`, którego jednostką są sekundy, a wartością liczba całkowita od 10 do 360.

Ten parametr jest używany do generowania piosenek w trybie niestandardowym (`custom` ma wartość `true`). Należy szczególnie wyjaśnić, że `duration` jest **wskazówką dotyczącą preferencji, a nie twardym ograniczeniem**: model będzie uwzględniał tę wartość podczas tworzenia, ale nie gwarantuje jej osiągnięcia; w praktycznych testach rzeczywista długość jest zwykle wyraźnie krótsza od oczekiwanej wartości, a długości dwóch piosenek zwróconych przez to samo żądanie mogą również różnić się kilkukrotnie. Nawet w przypadku całkowicie identycznych żądań długości uzyskane przy wielokrotnym przesłaniu mogą znacznie się różnić. Dlatego nie należy traktować tego jako precyzyjnej kontroli długości; jeśli w zastosowaniu wymagana jest stała długość, po otrzymaniu gotowego utworu należy samodzielnie go przyciąć lub ponowić próbę.

Odpowiedni kod Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Należy zwrócić uwagę, że `duration` w żądaniu to **oczekiwana długość**, natomiast pole `duration` każdej piosenki w odpowiedzi `data` to **rzeczywista długość** tej piosenki. Obie nazwy są takie same, ale ich znaczenie jest różne; rzeczywista długość nie musi być równa wartości oczekiwanej. Długość tekstu jest jednym z głównych czynników wpływających na długość gotowego utworu; jeśli potrzebny jest dłuższy gotowy utwór, zaleca się jednoczesne podanie bardziej kompletnego tekstu.

Interfejs sprawdzi, czy `duration` jest liczbą całkowitą od 10 do 360; nadal jest to jedynie cel generowania, a nie gwarancja długości gotowego utworu.

## Funkcja Remaster

W grudniu 2025 roku suno wprowadziło nową funkcję Remaster. Ta funkcja może ponownie wygenerować piosenkę i nie może działać między kontami, a następnie należy również wypełnić następujące parametry:

- action：wartość to `remaster`。
- audio_id：ID piosenki, którą należy ponownie wygenerować。
- model：obsługuje tylko v4.5+、v5。
- variation_category：obsługiwane tylko w wersji v5 i wyższych, a dostępne są tylko 3 wartości: high, normal, subtle。

## Funkcja twórcza Inspo

Funkcja twórcza Inspo może generować nową muzykę na podstawie od 1 do 4 pełnych referencyjnych nagrań audio i obsługuje przeciąganie lub przesyłanie audio jako źródła inspiracji. API używa istniejącej akcji `inspo`: klient dostarcza publicznie dostępne adresy URL audio, a usługa automatycznie kończy przygotowanie referencyjnego audio i tworzenie utworu, bez konieczności odczytywania przez klienta tekstu, stylu lub czasu trwania osobno i składania żądania. Różni się to od opisanego powyżej próbkowania fragmentu, a także od Cover odtwarzającego styl oryginalnego utworu. Podczas użycia należy wypełnić następujące parametry:

- action：wartość to `inspo`。
- audio_urls：lista adresów URL referencyjnych nagrań audio; należy podać od 1 do 4 publicznie dostępnych adresów audio.
- model：używany model, zalecany jest `chirp-v6`。
- prompt：tekst utworu lub podpowiedź twórcza (opcjonalnie).
- instrumental：po ustawieniu na `true` generuje na żądanie utwór instrumentalny, bez użycia tekstu.
- persona_id：używa określonego głosu w kanałach usług obsługujących tę kombinację; referencyjne audio zostanie na etapie przygotowania powiązane ze środowiskiem zasobów wymaganym przez ten głos.
- lyric_prompt：gdy `custom=true` i nie podano `lyric`, służy do automatycznego generowania tekstu utworu.

> Uwaga：referencyjne audio musi być publicznie dostępnym plikiem audio. Jeśli referencyjne audio idealnie odpowiada znanemu nagraniu w bibliotece utworów platformy, Suno może odmówić generowania z powodu weryfikacji praw autorskich; zaleca się używanie własnego audio lub audio wygenerowanego przez Suno jako źródła inspiracji.

Odpowiedni kod Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
```

## Asynchroniczne wywołanie zwrotne

Ponieważ generowanie muzyki przez Suno trwa stosunkowo długo, około 1–2 minut, jeśli API przez długi czas nie odpowiada, żądanie HTTP będzie stale utrzymywać połączenie, co prowadzi do dodatkowego zużycia zasobów systemowych, dlatego to API również obsługuje asynchroniczne wywołania zwrotne.

Ogólny proces wygląda następująco: gdy klient inicjuje żądanie, dodatkowo określa pole `callback_url`, po wysłaniu przez klienta żądania API, API natychmiast zwróci wynik zawierający pole `task_id`, które reprezentuje identyfikator bieżącego zadania. Po zakończeniu zadania wynik generowania muzyki zostanie wysłany w formie POST JSON na określony przez klienta `callback_url`, który również zawiera pole `task_id`, dzięki czemu wynik zadania można powiązać za pomocą ID.
