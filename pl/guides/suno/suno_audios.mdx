Wraz z coraz szerszym zastosowaniem AI, różnego rodzaju programy AI stopniowo stają się powszechne. AI stopniowo przeniknęła do wszystkich aspektów pracy i życia ludzi. Coraz więcej jest również branż związanych z AI — od początkowego pisania, przez opiekę medyczną i edukację, aż po obecną muzykę.

Suno to profesjonalna platforma AI do tworzenia wysokiej jakości piosenek i muzyki. Użytkownicy muszą jedynie wprowadzić proste tekstowe podpowiedzi, aby na podstawie gatunku, stylu i tekstu wygenerować piosenki z wokalem. Ten generator muzyki AI został opracowany przez członków zespołu z renomowanych firm technologicznych, takich jak Meta, TikTok i Kensho, a jego celem jest umożliwienie wszystkim tworzenia pięknej muzyki bez potrzeby używania jakichkolwiek instrumentów.

Suno obsługuje obecnie `chirp-v6`, `chirp-v6-wild` i `chirp-v6-mini`. Zaleca się używanie `chirp-v6`; nazwy starszych modeli są nadal kompatybilne.

Jednak Suno oficjalnie nie udostępnia API. AceDataCloud oferuje zestaw API Suno, który symuluje integrację z oficjalnym Suno i umożliwia wygodne oraz szybkie generowanie wybranej muzyki.

## Aplikowanie i korzystanie

Aby korzystać z Suno Audios Generation API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachowaj go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany ani zarejestrowany, nastąpi automatyczne przekierowanie na stronę logowania z zaproszeniem do rejestracji i logowania. Po zakończeniu automatycznie wrócisz na bieżącą stronę.

**Jeden API Token pozwala wywoływać wszystkie usługi platformy, bez potrzeby osobnego aplikowania dla każdej usługi.** Przy pierwszym zgłoszeniu otrzymasz bezpłatny limit, aby móc korzystać z bezpłatnej wersji próbnej; gdy limit będzie niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

## Podstawowe użycie

Jakie piosenki chcesz, możesz dowolnie wprowadzić fragment tekstu. Na przykład, jeśli chcę wygenerować piosenkę o Bożym Narodzeniu, mogę wprowadzić `a song for Christmas`, jak pokazano na ilustracji:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Można zobaczyć, że ustawiliśmy tutaj Request Headers, w tym:

- `accept`: jaki format odpowiedzi chcesz otrzymać; tutaj wpisz `application/json`, czyli format JSON.
- `authorization`: klucz do wywoływania API, który po aplikowaniu można bezpośrednio wybrać z listy rozwijanej.

Dodatkowo ustawiono Request Body, w tym:
- `action`: typ zadania audio, domyślnie `generate`. Obsługuje operacje takie jak generowanie, kontynuacja, cover, łączenie, rozdzielanie ścieżek, dodawanie ścieżek audio, wyodrębnianie wskazanych ścieżek audio, generowanie efektów dźwiękowych i dostosowywanie prędkości itd.; wszystkie są wywoływane jednolicie przez `POST /suno/audios`.
- `prompt`: podpowiedź trybu inspiracji Suno Official (obowiązuje, gdy `custom` ma wartość `false`), maksymalnie 500 znaków.
- `model`: model dla tego zadania generowania muzyki. Seria v6 obejmuje `chirp-v6`, `chirp-v6-wild` i `chirp-v6-mini`; nazwy starszych modeli są nadal kompatybilne.
- `max_mode`: ulepszony tryb generowania. `generate` jest włączany tylko wtedy, gdy zarówno `custom`, jak i `max_mode` mają wartość `true`, a koszt wynosi 1.12 Credits; `add_stem` można włączyć bezpośrednio, a koszt wynosi 1.344 Credits. Gdy jest wyłączony lub pominięty, koszty wynoszą odpowiednio 0.56 i 0.672 Credits.
- `variety`: intensywność różnorodności wyników generowania, opcje to `off`, `normal`, `high`, `extra`, `max`. Używane tylko dla `generate` i `add_stem`; przekazanie dla innych action zwróci 400.
- `lyric`: treść tekstu piosenki w niestandardowym trybie Suno Official. Maksymalnie 3000 znaków dla `chirp-v3-5` i `chirp-v4`; maksymalnie 5000 znaków dla `chirp-v4-5` i wyższych (w tym `chirp-v5`, `chirp-v5-5`).
- `custom`: czy używać trybu niestandardowego, domyślnie: `false`.
- `instrumental`: opcja muzyki instrumentalnej w trybie inspiracji Suno Official.
- `title`: tytuł utworu w niestandardowym trybie Suno Official. Maksymalnie 80 znaków dla `chirp-v3-5`, `chirp-v4`; maksymalnie 100 znaków dla `chirp-v4-5` i wyższych.
- `style`: styl muzyczny w niestandardowym trybie Suno Official. Maksymalnie 200 znaków dla `chirp-v3-5` i `chirp-v4`; maksymalnie 1000 znaków dla `chirp-v4-5` i wyższych (w tym `chirp-v5`, `chirp-v5-5`).
- `negative_tags`: style muzyczne lub gatunki, które mają zostać wykluczone z wyników generowania w trybie niestandardowym (gdy `custom` ma wartość `true`).
- `audio_weight`: waga wpływu cech audio lub głosu, w zakresie 0-1; `0` również jest prawidłową wartością. Może być używana w operacjach generowania, kontynuacji, coveru, dodawania ścieżek audio i spójności głosu itd.; gdy nie ma referencyjnego audio ani cech głosu, model może osłabić lub zignorować tę wartość.
- `audio_id`: ID muzyki referencyjnej.
- `overpainting_start`/`overpainting_end`: czas rozpoczęcia i zakończenia dodawania wokalu do istniejącej muzyki instrumentalnej, w sekundach.
- `underpainting_start`/`underpainting_end`: czas rozpoczęcia i zakończenia dodawania akompaniamentu do śpiewu a cappella, w sekundach.
- `persona_id`: ID utworu artysty.
- `continue_at`: granica kontynuacji, w sekundach. Na przykład 213.5 oznacza rozpoczęcie generowania kolejnego fragmentu od 3 minuty i 33.5 sekundy. `lyric` i `style` kierują tylko nową treścią po granicy i nie zastępują tekstu ani śpiewu przed granicą w źródłowym audio.
- `style_influence`: wpływ stylu w trybie niestandardowym, w zakresie 0-1; większa wartość zazwyczaj lepiej dopasowuje do wybranego stylu; `0` zostanie przekazane jako prawidłowa wartość.
- `replace_section_end`: końcowy czas zastępowanego fragmentu.
- `replace_section_start`: początkowy czas zastępowanego fragmentu.
- `vocal_gender`: kontroluje preferencję głosu żeńskiego lub męskiego, głos żeński `f`, głos męski `m`; obowiązuje dla modeli 4.5 i wyższych; jest to preferencja i nie gwarantuje ścisłego przestrzegania.
- `weirdness`: dziwaczność w trybie niestandardowym, w zakresie 0-1; większa wartość zwykle oznacza więcej kreatywności i eksperymentalności; `0` zostanie przekazane jako prawidłowa wartość.
- `duration`: oczekiwany czas trwania utworu, w sekundach, musi być liczbą całkowitą w zakresie od 10 do 360. Ten parametr jest używany do generowania utworów w trybie niestandardowym (gdy `custom` ma wartość `true`). Jest to wskazówka dotycząca preferencji, a nie twarde ograniczenie: model weźmie ją pod uwagę, ale nie gwarantuje jej osiągnięcia; rzeczywisty czas trwania gotowego utworu zależy od pola `duration` w odpowiedzi i zazwyczaj jest krótszy niż oczekiwany.

### Zakres zastosowania parametrów zaawansowanych

| Parametr                | Wartość                                          | Obsługiwane action                              | Opis                              |
| ----------------- | ------------------------------------------- | --------------------------------------- | ------------------------------- |
| `weirdness`       | 0-1                                         | Opcjonalne                                      | Reguluje eksperymentalność, `0` jest prawidłową wartością; efekt zależy od operacji, trybu i modelu    |
| `style_influence` | 0-1                                         | Opcjonalne                                      | Reguluje tendencję do przestrzegania stylu, `0` jest prawidłową wartością; efekt zależy od operacji, trybu i modelu |
| `audio_weight`    | 0-1                                         | Opcjonalne                                      | Reguluje wpływ cech audio lub głosu; przy braku informacji referencyjnych może zostać zignorowany przez model      |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`, `add_stem`                   | Reguluje różnorodność stylów między wynikami                     |
| `max_mode`        | boolean                                     | `generate` (wymaga `custom=true`), `add_stem` | Zwiększa spójność i jest rozliczany według trybu ulepszonego                   |
| `vocal_gender`    | `f` / `m`                                   | Operacje generowania obsługujące kontrolę wokalu                             | Preferencja, nie gwarantuje ścisłego przestrzegania                     |
| `duration`        | Liczba całkowita 10-360                                   | Opcjonalne                                      | Oczekiwany czas trwania; konkretna operacja, tryb lub model może go zignorować             |

Platforma sprawdza typy parametrów i zakresy wartości, ale nie odrzuca tych opcjonalnych elementów regulacji wyłącznie z powodu różnic w action; konkretny efekt zależy od operacji, trybu i modelu.

- `lyric_prompt`: prompt do generowania tekstu piosenki, obowiązuje wtedy i tylko wtedy, gdy `custom` ma wartość `true` oraz `lyric` nie zostało przekazane.
- `callback_url`: URL, na który ma zostać przekazany wynik wywołania zwrotnego.
- `async`: opcjonalne; gdy ustawione na `true`, interfejs natychmiast zwraca `task_id`, bez konieczności podawania `callback_url`, a następnie wynik jest uzyskiwany przez odpytywanie odpowiedniego interfejsu zapytań o zadania.

## Generowanie niestandardowe

Jeśli chcesz niestandardowo wygenerować tekst piosenki, możesz wprowadzić tekst:

W tym momencie do pola `lyric` można przekazać treść podobną do poniższej:

```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> Uwaga, `\n` w tekście piosenki tutaj oznacza znak nowej linii. Jeśli nie wiesz, jak wygenerować tekst piosenki, możesz użyć interfejsu API generowania tekstów dostarczanego przez AceDataCloud, aby wygenerować tekst na podstawie promptu; API to [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Następnie, aby niestandardowo wygenerować piosenkę na podstawie tekstu, tytułu i stylu, można określić następującą zawartość:

- lyric：tekst piosenki
- custom：ustaw na `true`, co oznacza generowanie niestandardowe; domyślna wartość tego parametru to false, co oznacza generowanie przy użyciu `prompt`.
- title：tytuł piosenki.
- style：styl piosenki, opcjonalnie.

## Funkcja niestandardowego generowania stylu wokalisty
Jeśli chcesz użyć stylu piosenkarza do generowania piosenek, najpierw wygeneruj piosenkę poprzez podstawowe użycie opisane powyżej,
a następnie należy ustawić tę piosenkę jako styl piosenkarza. Potem należy przejść do [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona), aby na podstawie oficjalnie wygenerowanego identyfikatora muzyki `audio_id` wygenerować parametr id stylu piosenkarza `persona_id`; konkretne parametry są pokazane na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Po wypełnieniu automatycznie generowany jest następujący kod:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

Odpowiedni kod Python:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Kliknij uruchom, a zobaczysz, że otrzymasz wynik jak poniżej:

```json
{
  "success": true,
  "task_id": "7628b754-4fe7-4e79-bda4-806d0dd8bf6e",
  "data": {
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b"
  }
}
```

Jako przykładowe dane wykorzystamy powyższe `audio_id` i `persona_id`, odpowiednio `97efc9f4-0e8d-4b3e-88df-14568fa1b11f` oraz `e0d7319e-aa2a-44cb-b00a-916218d7cb0b`. Następnie można ustawić parametr `action` na `artist_consistency` (jeśli jest to nowa wersja stylu piosenkarza Persona-v2-vox, `action` musi być ustawione na `artist_consistency_vox`) i wprowadzić ID piosenki, której generowanie ma być kontynuowane, oraz ID stylu piosenkarza, jak pokazano w poniższym przykładzie:

<p><img src="https://cdn.acedata.cloud/fukijq.png" width="500" className="m-auto" /></p>

Po wypełnieniu automatycznie generowany jest następujący kod:

<p><img src="https://cdn.acedata.cloud/5uzk9d.png" width="500" className="m-auto" /></p>

Odpowiedni kod Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "artist_consistency",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b",
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Funkcja kontynuowania generowania

Jeśli chcesz kontynuować generowanie już wygenerowanej piosenki Suno, możesz ustawić parametr `action` na `extend` i wprowadzić ID piosenki, której generowanie ma być kontynuowane. ID piosenki uzyskuje się poprzez podstawowe użycie; z powyższego tekstu wiadomo, że w tym momencie ID piosenki to:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Uwaga, `id` w tekście piosenki tutaj jest ID piosenki po jej wygenerowaniu. Jeśli nie wiesz, jak wygenerować piosenkę, możesz zapoznać się z podstawowym użyciem opisanym powyżej, aby wygenerować piosenkę.

Jeśli chcesz kontynuować generowanie własnej przesłanej piosenki, możesz ustawić parametr `action` na `upload_extend` i wprowadzić ID własnej przesłanej piosenki, której generowanie ma być kontynuowane. ID piosenki uzyskuje się za pomocą [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), jak pokazano na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Następnie należy wypełnić tekst fragmentu kontynuacji i można określić styl:

- lyric：używane tylko do kierowania tekstem nowo wygenerowanego fragmentu po `continue_at`; nie zastąpi tekstu przed tym punktem czasowym w źródłowym audio.
- custom：ustawienie na `true` oznacza niestandardowe generowanie; domyślna wartość tego parametru to false, co oznacza generowanie z użyciem `prompt`.
- style：styl piosenki dla fragmentu kontynuacji, opcjonalny.
- continue_at：granica kontynuacji, w sekundach. Na przykład 213.5 oznacza rozpoczęcie generowania kolejnego fragmentu od 3 minut i 33.5 sekundy.

> `extend` służy do dalszego tworzenia na podstawie istniejącej piosenki, a nie do zmiany tekstu całej piosenki. Jeśli chcesz użyć nowego tekstu od początku całej piosenki, użyj `generate`, aby wygenerować ją ponownie; jeśli chcesz ponownie zinterpretować istniejącą piosenkę, możesz użyć `cover`. Po przekazaniu całego nowego tekstu oryginalny tekst przed `continue_at` nadal nie zostanie zastąpiony.

## Zastępowanie fragmentu

Gdy po wygenerowaniu utworu konieczne jest przeprowadzenie wtórnej kreacji polegającej na osobnej operacji zastąpienia fragmentu utworu, można wykonać operację zastąpienia określonego fragmentu utworu.

> ⚠️ **Uwaga**：`replace_section_result_mode` domyślnie ma wartość `full_song`: system osobno połączy 2 nowo wygenerowane kandydaty i zwróci 2 kompletne utwory. Jeśli potrzebujesz tylko jeszcze niepołączonych kandydatów zastępowanego fragmentu, jawnie ustaw wartość na `candidates`, a następnie wybierz kandydata i wywołaj [Łączenie muzyki](#音乐拼接).

Opis parametrów jest następujący:

- action：wartość to `replace_section`.
- audio_id：ID oryginalnego utworu (źródłowego utworu, który zostanie zastąpiony).
- model: model generowania utworu.
- lyric: pełny tekst po zastąpieniu (obejmujący zastępowany segment i jego kontekst, zgodny z treścią w `prompt`).
- prompt：nowy tekst dla segmentu, który ma zostać zastąpiony.
- style：styl utworu, opcjonalny.
- replace_section_start：czas rozpoczęcia zastępowanego fragmentu w oryginalnym utworze (w sekundach).
- replace_section_end：czas zakończenia zastępowanego fragmentu w oryginalnym utworze (w sekundach).
- replace_section_result_mode：tryb zwracania, domyślnie `full_song`. `full_song` osobno łączy 2 kandydatów i zwraca 2 kompletne utwory; `candidates` zwraca 2 jeszcze niepołączone fragmenty kandydackie.

## Separacja wokalu i muzyki

- action：wartość to `stems`。

```json
{
  "action": "stems",
  "audio_id": "ec13e502-d043-4eb2-92ee-e900c6da69d1"
}
```

## Kontrolowanie długości piosenki

Domyślnie długość generowanej piosenki jest określana przez model, zwykle wynosi od 30 sekund do 4 minut. Jeśli potrzebny jest dłuższy lub krótszy gotowy utwór, można określić oczekiwaną długość za pomocą parametru `duration`, jednostką są sekundy, a wartość jest liczbą całkowitą od 10 do 360.

Ten parametr jest używany do generowania piosenek w trybie niestandardowym (`custom` ma wartość `true`). Należy szczególnie wyjaśnić, że `duration` jest **wskazówką tendencji, a nie twardym ograniczeniem**: model będzie odnosił się do tej wartości podczas tworzenia, ale nie gwarantuje jej osiągnięcia; w testach rzeczywista długość jest zwykle wyraźnie krótsza od oczekiwanej wartości, a długości dwóch piosenek zwróconych w tym samym żądaniu mogą również różnić się kilkukrotnie. Nawet w przypadku całkowicie identycznych żądań długości uzyskane po wielokrotnym przesłaniu mogą również znacznie się różnić. Dlatego nie należy używać tego jako precyzyjnej kontroli długości; jeśli w zastosowaniu biznesowym potrzebna jest stała długość, należy samodzielnie przyciąć gotowy utwór lub ponowić próbę po jego otrzymaniu.

Odpowiedni kod Python:
```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Należy zauważyć, że `duration` w żądaniu jest **oczekiwanym czasem trwania**, natomiast pole `duration` każdej piosenki w odpowiedzi `data` jest **rzeczywistym czasem trwania** tej piosenki. Nazwy obu są takie same, ale ich znaczenia są różne; rzeczywisty czas trwania nie musi być równy oczekiwanej wartości. Długość tekstu jest jednym z głównych czynników wpływających na czas trwania gotowego utworu; jeśli potrzebny jest dłuższy gotowy utwór, zaleca się jednoczesne podanie pełniejszego tekstu.

Interfejs sprawdza, czy `duration` jest liczbą całkowitą od 10 do 360; nadal jest to jedynie cel generowania, a nie gwarancja długości gotowego utworu.

## Funkcja Remaster

W grudniu 2025 roku suno wprowadziło nową funkcję Remaster, funkcja ta może ponownie wygenerować piosenkę, nie można tego robić między kontami, następnie musimy jeszcze wypełnić następujące parametry:

- model：obsługuje tylko v4.5+、v5。

## Funkcja tworzenia inspirowanego Inspo

Funkcja tworzenia inspirowanego Inspo może generować nową muzykę na podstawie od 1 do 4 pełnych referencyjnych nagrań audio oraz obsługuje przeciąganie i upuszczanie lub przesyłanie audio jako źródła inspiracji. API używa istniejącej akcji `inspo`: klient podaje publicznie dostępne adresy URL audio, a usługa automatycznie kończy przygotowanie referencyjnego audio i tworzenie, bez konieczności osobnego odczytywania przez klienta tekstu, stylu lub długości i składania żądania. Różni się to od opisanego powyżej próbkowania zakresu, a także od Cover odtwarzającego styl oryginalnego utworu. Podczas użycia należy wypełnić następujące parametry:

- action: zawartością jest `inspo`.
- audio_urls: lista adresów URL referencyjnego audio; należy podać od 1 do 4 publicznie dostępnych adresów audio.
- model: używany model, zalecany jest `chirp-v6`.
- prompt: tekst piosenki lub wskazówki twórcze (opcjonalnie).

> Uwaga: referencyjne audio musi być publicznie dostępnym plikiem audio. Jeśli referencyjne audio idealnie odpowiada znanemu nagraniu w katalogu utworów platformy, Suno może odmówić generowania z powodu weryfikacji praw autorskich; zaleca się używanie własnego audio lub audio wygenerowanego przez Suno jako źródła inspiracji.

Odpowiedni kod Python:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Asynchroniczne wywołanie zwrotne

Ponieważ generowanie muzyki przez Suno trwa stosunkowo długo, około 1–2 minut, jeśli API przez długi czas nie odpowiada, żądanie HTTP będzie stale utrzymywać połączenie, co prowadzi do dodatkowego zużycia zasobów systemowych, dlatego to API również zapewnia obsługę asynchronicznych wywołań zwrotnych.

Ogólny proces wygląda następująco: gdy klient inicjuje żądanie, dodatkowo określa pole `callback_url`; po wysłaniu przez klienta żądania API, API natychmiast zwróci wynik zawierający informację w polu `task_id`, reprezentującą bieżący identyfikator zadania. Po zakończeniu zadania wynik generowania muzyki zostanie wysłany w formie POST JSON na `callback_url` określony przez klienta, który również zawiera pole `task_id`, dzięki czemu wynik zadania można powiązać za pomocą identyfikatora.

Poniżej zapoznamy się ze szczegółowym sposobem działania na przykładzie.

Po pierwsze, wywołanie zwrotne Webhook jest usługą, która może odbierać żądania HTTP; programista powinien zastąpić je adresem URL własnego serwera HTTP. W celu wygodnej prezentacji użyto tutaj publicznej przykładowej strony Webhook https://webhook.site/; po otwarciu tej strony można uzyskać adres URL Webhook, jak pokazano na rysunku:

![](https://cdn.acedata.cloud/fwfqin.png)

Skopiuj ten URL, aby użyć go jako Webhooka; przykładowy adres tutaj to https://webhook.site/03e60575-3d96-4132-b681-b713d78116e2.

Następnie możemy ustawić pole `callback_url` na powyższy adres URL Webhooka, jednocześnie wypełniając `prompt`, jak pokazano na rysunku:

![](https://cdn.acedata.cloud/x8xql1.png)

Kliknij uruchom, a zobaczysz, że wynik zostanie uzyskany natychmiast, jak poniżej:

```

  "task_id": "44472ab8-783b-4054-b861-5bf14e462f60"
```
