SUNO pozwala nam przesyłać referencyjne audio do wtórnej twórczości, ten dokument wyjaśnia metodę integracji powiązanego API.

Zwykłe przesyłanie wymaga jedynie `audio_url`, czyli publicznie dostępnego adresu CDN audio. Wartość domyślna `mode` to `standard`, dlatego istniejące wywołania nie wymagają modyfikacji. Pomyślne zwykłe przesłanie zużywa **0.06 Credits**; nieudane przesłanie nie jest płatne.

Wprowadzany tutaj `audio_url` to `https://cdn.acedata.cloud/suno_demo.mp3`, czyli publicznie dostępny adres CDN.

```bash
curl -X POST 'https://api.acedata.cloud/suno/upload' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3"
}'
```

Po uzyskaniu ID utworu można za pomocą [Suno Audios Generation API](https://platform.acedata.cloud/documents/suno-audios) wywoływać operacje wymagające `audio_id`, takie jak `upload_extend`, `upload_cover` lub próbkowanie zakresu. Jeśli chcesz tworzyć nową muzykę na podstawie 1 do 4 pełnych referencyjnych nagrań audio za pomocą funkcji twórczości inspirowanej Inspo, bezpośrednio wywołaj `action=inspo` i przekaż listę oryginalnych publicznych adresów URL audio; usługa automatycznie ukończy przesyłanie i analizę, bez potrzeby składania metadanych audio po stronie klienta.

## Przesyłanie oryginalnego utworu do coveru z prywatnym głosem

Podczas tworzenia coveru za pomocą prywatnego głosu utworzonego przez `/suno/voices`, przekaż `persona_id` tego głosu w żądaniu zwykłego przesyłania, aby powiązać oryginalny utwór z głosem:

```json
{
  "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3",
  "mode": "standard",
  "persona_id": "<声音创建接口返回的 persona_id>"
}
```

Po pomyślnym przesłaniu użyj zwróconego `data.audio_id`, aby wywołać `/suno/audios`, ustaw `action: "upload_cover"` i przekaż to samo `persona_id`. Nie kontynuuj używania ID audio, które wcześniej nie zostało powiązane z tym głosem.

`persona_id` obsługuje wyłącznie zwykłe przesyłanie i nie może być używane jednocześnie z `mode: "enhanced"`. Nie ma potrzeby dodatkowego określania `vocal_gender`; preferencja płci nie może zastąpić ID głosu. Tworzenie głosu, przesyłanie oryginalnego utworu i tworzenie coveru muszą korzystać z tego samego kanału usługi.

## Tryb rozszerzonego przesyłania

> `audio_url` jest adresem wejściowym i zostanie bezpośrednio przekazany do procesu przetwarzania audio; nie zostanie wcześniej przeniesiony przez usługę trwałego przechowywania mediów końcowych. Upewnij się, że jest publicznie dostępny podczas przetwarzania zadania.

Gdy zwykłe przesyłanie nie może przetworzyć audio, którego jesteś właścicielem lub do użycia którego masz upoważnienie, możesz ustawić `mode` na `enhanced`. Ten tryb musi również zawierać `name` o długości od 1 do 100 znaków i korzystać z publicznie dostępnego HTTPS `audio_url`.

Rozszerzone przesyłanie zawsze korzysta z przetwarzania asynchronicznego i zwykle wymaga 2 minut lub więcej. Pomyślne przetwarzanie zużywa **1.87 Credits**; nieudane przetwarzanie nie jest płatne.

```bash
curl -X POST 'https://api.acedata.cloud/suno/upload' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3",
    "mode": "enhanced",
    "name": "My Song"
  }'
```

Interfejs natychmiast zwróci `task_id` i `trace_id`. Użyj [Suno Tasks API](https://platform.acedata.cloud/documents/suno-tasks), aby sprawdzić zadanie, a po sukcesie odczytaj ID przesłanego audio z `response.data.audio_id`. Możesz również podać HTTPS `callback_url`, aby odbierać stan końcowy.
Ulepszone przesyłanie uzyskanego `audio_id` może być używane do Cover, Samples i Mashup. Ekstrakcja akompaniamentu i MIDI, separacja wszystkich ścieżek oraz separacja wokalu/akompaniamentu nadal mogą podlegać ograniczeniom wynikającym z konta, do którego należy audio; niewymienione operacje nie mają gwarantowanej obsługi użycia między kontami. Im krótsze audio, tym zwykle wyższy wskaźnik powodzenia przetwarzania.
