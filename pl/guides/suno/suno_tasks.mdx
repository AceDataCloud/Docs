Główną funkcją API Suno Tasks jest możliwość sprawdzania statusu wykonania zadań poprzez wprowadzenie ID zadania wygenerowanego przez API Suno Audios Generation lub API Suno Lyrics Generation.

Dokument ten szczegółowo opisuje instrukcje integracji API Suno Tasks, aby pomóc Ci łatwo zintegrować i w pełni wykorzystać potężne możliwości tego API. Dzięki API Suno Tasks możesz łatwo sprawdzić status wykonania zadań API Suno Lyrics Generation lub API Suno Audios Generation.

## Proces aplikacji

Aby korzystać z API Suno Audios Generation, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój token API, który należy zachować na przyszłość.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Jeśli nie jesteś zalogowany lub zarejestrowany, automatycznie zostaniesz przekierowany na stronę logowania, aby zarejestrować się i zalogować, a po zakończeniu zostaniesz automatycznie przekierowany z powrotem na bieżącą stronę.

**Jeden token API wystarczy do wywołania wszystkich usług platformy, nie ma potrzeby składania osobnych wniosków dla każdej usługi.** Przy pierwszym wniosku przyznawana jest darmowa pula, aby móc skorzystać z bezpłatnego doświadczenia; w przypadku niewystarczającej puli można doładować saldo ogólne w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Przykład żądania

Aby dowiedzieć się, jak korzystać z API Suno Lyrics Generation, zapoznaj się z [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics-generation-integration).

### Ustawienia nagłówków żądania i ciała żądania

**Nagłówki żądania** obejmują:

- `accept`: określa, że oczekiwany jest wynik odpowiedzi w formacie JSON, tutaj wpisz `application/json`.
- `authorization`: klucz do wywołania API, po złożeniu wniosku można go bezpośrednio wybrać z rozwijanej listy.

**Ciało żądania** obejmuje:

- `id`: ID przesłanego zadania.
- `action`: sposób operacji na zadaniu.

Ustawienia są pokazane na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/uo7t6n.png" width="500" className="m-auto" /></p>

### Przykład kodu

Można zauważyć, że po prawej stronie strony automatycznie wygenerowano kod w różnych językach, jak pokazano na obrazku:

<p><img src="https://cdn.acedata.cloud/p6vi9o.png" width="500" className="m-auto" /></p>

Niektóre przykłady kodu są następujące:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/suno/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "eae26f89-b64b-404d-a80c-761996660b1c",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/suno/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "eae26f89-b64b-404d-a80c-761996660b1c",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Zwróć wyniki, które zawierają wiele pól, w tym `items`, które zawierają szczegółowe informacje o zadaniach piosenek w partiach. Każda szczegółowa informacja o zadaniu piosenki jest taka sama jak format zwracany dla pojedynczego zadania w powyższym przykładzie.

- `items`, wszystkie szczegółowe informacje o zadaniach piosenek w partiach. Jest to tablica, a każdy element tablicy ma taki sam format jak wynik zapytania pojedynczego zadania.
- `count`, liczba zadań piosenek w tym zapytaniu partii.

```bash
curl -X POST 'https://api.acedata.cloud/suno/tasks' \
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/suno/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "ids": ["eae26f89-b64b-404d-a80c-761996660b1c","0d3ed03b-912b-4f7d-941b-8441323cb77b"],
    "action": "retrieve_batch"
}

response = requests.post(url, json=payload, headers=headers)

```

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpią błędy, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Złe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Nieautoryzowany, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit szybkości.
- `500 api_error`: Błąd wewnętrzny serwera, coś poszło nie tak na serwerze.
