Główną funkcją Kling Tasks API jest sprawdzanie statusu wykonania zadania poprzez wprowadzenie ID zadania wygenerowanego przez Kling Videos Generation API.

Ten dokument szczegółowo przedstawi opis integracji Kling Tasks API, pomagając Ci łatwo zintegrować i w pełni wykorzystać potężne funkcje tego API. Za pomocą Kling Tasks API możesz łatwo realizować sprawdzanie statusu wykonania zadań Kling Videos Generation API.

## Proces składania wniosku

Aby korzystać z Kling Videos Generation API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, nastąpi automatyczne przekierowanie na stronę logowania, która zaprosi Cię do rejestracji i logowania, a po zakończeniu automatycznie powrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności osobnego składania wniosku dla każdej usługi.** Przy pierwszym wniosku zostanie przyznany darmowy limit, który umożliwia bezpłatne wypróbowanie; gdy limit jest niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Przykład żądania

Kling Tasks API może być używane do sprawdzania wyników Kling Videos Generation API. Informacje o tym, jak korzystać z Kling Videos Generation API, znajdziesz w dokumentacji [Kling Videos Generation API ](https://platform.acedata.cloud/documents/kling-videos).

Jako przykład weźmiemy jedno ID zadania zwrócone przez usługę Kling Videos Generation API, aby zademonstrować, jak korzystać z tego API. Załóżmy, że mamy ID zadania: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, następnie zademonstrujemy, jak poprzez przekazanie ID zadania.

### Ustawianie nagłówków żądania i treści żądania

**Request Headers** obejmuje:

- `accept`: określa odbieranie wyników odpowiedzi w formacie JSON, tutaj należy wpisać `application/json`.
- `authorization`: klucz do wywołania API, po złożeniu wniosku można go bezpośrednio wybrać z listy rozwijanej.

**Request Body** obejmuje:

- `id`: przesłane ID zadania.
- `action`: sposób operacji na zadaniu.

Ustawienia są pokazane na poniższym obrazku:

<p><img src="https://cdn.acedata.cloud/xztiqi.png" width="500" className="m-auto" /></p>

### Przykład kodu

Można zauważyć, że po prawej stronie strony automatycznie wygenerowano już kod w różnych językach, jak pokazano na obrazku:

<p><img src="https://cdn.acedata.cloud/bsqh3i.png" width="500" className="m-auto" /></p>

Część przykładów kodu jest następująca:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Zwrócony wynik zawiera łącznie wiele pól, pole request jest request body podczas uruchamiania zadania, natomiast pole response jest response body zwróconym po zakończeniu zadania. Opis pól jest następujący.

- `id`, ID wygenerowanego zadania wideo, używane do jednoznacznej identyfikacji tego zadania generowania wideo.

- `response`, informacje zwrotne w zapytaniu o zadanie wideo.
- `created_at`, czas utworzenia zadania, znacznik czasu Unix (sekundy, zmiennoprzecinkowy).
- `started_at`, czas rozpoczęcia wykonywania zadania, znacznik czasu Unix (sekundy, zmiennoprzecinkowy).
- `finished_at`, czas zakończenia zadania, znacznik czasu Unix (sekundy, zmiennoprzecinkowy). To pole nie jest zwracane, gdy zadanie nie zostało ukończone.

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i komunikat. Na przykład:

- `400 token_mismatched`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`：Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`：Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`：Zbyt wiele żądań, przekroczono limit częstotliwości.
- `500 api_error`：Wewnętrzny błąd serwera, coś poszło nie tak na serwerze.
