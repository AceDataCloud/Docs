W tym artykule przedstawimy instrukcję integracji Kling Videos Generation API, która umożliwia generowanie oficjalnych filmów Kling poprzez wprowadzanie niestandardowych parametrów.

## Proces składania wniosku

Aby korzystać z Kling Videos Generation API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go na później.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania z zaproszeniem do rejestracji i zalogowania się, a po zakończeniu automatycznie wrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności osobnego składania wniosku dla każdej usługi.** Przy pierwszym wniosku otrzymasz bezpłatny limit, aby korzystać bezpłatnie w ramach wersji próbnej; gdy limit będzie niewystarczający, możesz doładować uniwersalne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Podstawowe użycie

Najpierw zapoznajmy się z podstawowym sposobem użycia: wystarczy wprowadzić słowo kluczowe `prompt`, działanie generowania `action`, obraz referencyjny pierwszej klatki `start_image_url` oraz model `model`, aby uzyskać przetworzony wynik. Najpierw należy po prostu przekazać pole `action` o wartości `text2video`; obejmuje ono głównie trzy działania: tekst na wideo (`text2video`), obraz na wideo (`image2video`) oraz rozszerzanie wideo (`extend`). Następnie musimy również wprowadzić model `model`; obecnie dostępne są głównie modele `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`, a szczegóły są następujące:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Można zobaczyć, że ustawiliśmy tutaj Request Headers, w tym:

- `accept`: format odpowiedzi, który chcesz otrzymać; tutaj wpisz `application/json`, czyli format JSON.
- `authorization`: klucz do wywoływania API, który po uzyskaniu można bezpośrednio wybrać z listy rozwijanej.

Dodatkowo ustawiliśmy Request Body, w tym:

- `model`: model do generowania wideo, głównie modele `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode`: tryb generowania wideo; dostępne wartości to tryb standardowy `std`, tryb ultraszybki `pro` i natywny tryb 4K `4k`. Wśród nich `4k` obsługuje tylko `kling-v3` i `kling-v3-omni` oraz nie jest kompatybilny z `camera_control` (kontrolą ruchu kamery).
- `action`: działanie tego zadania generowania wideo, obejmujące głównie trzy działania: tekst na wideo (`text2video`), obraz na wideo (`image2video`), rozszerzanie wideo (`extend`).
- `start_image_url`: link do referencyjnego obrazu pierwszej klatki, który należy przesłać po wybraniu działania obraz na wideo `image2video`.
- `end_image_url`: opcjonalne w przypadku obrazu na wideo, określa ostatnią klatkę.
- `duration`: czas trwania wideo, w sekundach. `kling-v3` i `kling-v3-omni` obsługują całkowity czas trwania od 3 do 15 sekund; `kling-o1` obsługuje tylko 5 sekund; inne modele obsługują 5 lub 10 sekund.
- `generate_audio`: czy jednocześnie generować audio, opcjonalne, wartość logiczna. Obsługiwane przez `kling-v3`, `kling-v3-omni` oraz `kling-v2-6` (tylko tryb pro). Domyślnie `false`.
- `aspect_ratio`: współczynnik proporcji wideo, opcjonalny, obsługuje `16:9`, `9:16`, `1:1`, domyślnie `16:9`.
- `cfg_scale`: siła zgodności, zakres [0,1], im większa wartość, tym lepiej odpowiada słowu kluczowemu.
- `camera_control`: opcjonalne, parametry obiektu do kontrolowania ruchu kamery, obsługuje ustawienia wstępne type/simple oraz konfiguracje takie jak horizontal, vertical, pan, tilt, roll, zoom.
- `negative_prompt`: opcjonalne, odwrotne słowo kluczowe, którego nie chcesz widzieć, maksymalnie 200 znaków.
- `image_list`: lista obrazów referencyjnych Omni, odpowiednia dla modeli `kling-o1` i `kling-v3-omni`; sposób użycia znajduje się poniżej w sekcji „Wszechstronne referencje Omni”.
- `video_list`: lista filmów referencyjnych Omni (obsługuje edycję wideo), odpowiednia dla modeli `kling-o1` i `kling-v3-omni`; sposób użycia znajduje się poniżej w sekcji „Wszechstronne referencje Omni”.
- `prompt`: słowo kluczowe.
- `callback_url`: URL, na który należy zwrócić wynik wywołania zwrotnego.
- `async`: opcjonalne; po ustawieniu na `true` interfejs natychmiast zwraca `task_id`, bez konieczności podawania `callback_url`, a następnie wynik można uzyskać przez odpytywanie odpowiedniego interfejsu zapytania o zadanie.

Po wyborze można zauważyć, że po prawej stronie wygenerowano również odpowiedni kod, jak pokazano na ilustracji:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Kliknij przycisk „Try”, aby przeprowadzić test. Jak pokazano powyżej, otrzymaliśmy następujący wynik:

```json
{
  "success": true,
  "video_id": "900798310464749610",
  "video_url": "https://cdn.acedata.cloud/assets/examples/kling/6c68c267-065b-4423-b66b-a0e4c59ee0d5-6a664a591a53.mp4",
  "duration": "5.041",
  "state": "succeed",
  "task_id": "6c68c267-065b-4423-b66b-a0e4c59ee0d5"
}
```

Zwrócony wynik zawiera wiele pól, opisanych poniżej:

- `success`, stan zadania generowania wideo w tym momencie.
- `task_id`, ID zadania generowania wideo w tym momencie.
- `video_id`, ID wideo zadania generowania wideo w tym momencie.
- `video_url`, link do wideo zadania generowania wideo w tym momencie.
- `duration`, czas trwania linku do wideo zadania generowania wideo w tym momencie.
- `state`, status zadania generowania wideo w tym momencie.

Można zobaczyć, że uzyskaliśmy satysfakcjonujące informacje o wideo; wystarczy pobrać wygenerowane wideo Kling na podstawie adresu linku wideo `data` w wyniku.

Ponadto, jeśli chcesz wygenerować odpowiedni kod integracji, możesz go bezpośrednio skopiować i wygenerować, na przykład kod CURL jest następujący:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Macierz możliwości modeli

### Rozliczanie za wideo referencyjne O1 i Omni

`kling-o1` jest rozliczany według trybu oraz tego, czy podano `video_list`. Poniżej przedstawiono ceny za gotowy film 5-sekundowy:

| Tryb  | Bez wideo referencyjnego | Z wideo referencyjnym |
| --- | ------------: | ------------: |
| std | 4.005 Credits | 6.010 Credits |
| pro | 5.340 Credits | 8.010 Credits |
Pomyślne żądania `kling-o1` i `kling-v3-omni` z filmem referencyjnym są rozliczane według naliczanych sekund: std to **1.202 Credits/s**, a pro to **1.602 Credits/s**. Na przykład wygenerowanie 5 sekund w trybie std kosztuje 6.010 Credits. Pominięcie `video_list` nie uruchamia poziomu filmu referencyjnego; `image_list`, obrazy pierwszej i ostatniej klatki również nie należą do filmów referencyjnych. Film referencyjny nie może być używany jednocześnie z `generate_audio=true`.

Edycja wideo z `refer_type=base` (domyślnie) może podążać za długością filmu referencyjnego, a końcowe rozliczenie następuje według rzeczywistej długości gotowego filmu, zaokrąglonej do całkowitej liczby sekund: na przykład 5.708 sekundy jest rozliczane jako 6 sekund, a 5.041 sekundy jako 5 sekund. `refer_type=feature` używa żądanego `duration`. `usage.reference_video_seconds` w odpowiedzi podaje końcową liczbę naliczanych sekund; szacowana cena podczas żądania może różnić się od końcowego obciążenia.

Obsługa parametrów znacznie różni się między modelami. Poniższa macierz została opracowana na podstawie [oficjalnej dokumentacji Kling video models](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels); przed wywołaniem najpierw sprawdź, czy bieżąca kombinacja `model` / `mode` / `duration` obsługuje wymaganą funkcję, w przeciwnym razie zostaną zwrócone błędy takie jak `model/mode/duration(...) is not supported with image_tail`.

| Model                  | Tryb             | `end_image_url` (pierwsza i ostatnia klatka) | `generate_audio` (dźwięk) | `camera_control` (ruch kamery) | Uwagi                                           |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ tylko `duration=5`     | ❌                    | ✅ tylko `duration=5`     | `extend` nie obsługuje `negative_prompt` ani `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | Wideo z wielu obrazów, `extend` dostępne we wszystkich trybach                         |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Jeden tryb, tylko `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Jeden tryb, tylko `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | Jedyny model inny niż v3, który jednocześnie obsługuje dźwięk                             |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | Zakres `duration` 3–15 sekund                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | Tryb 4K jest niezgodny z ruchem kamery                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Obsługuje tylko `duration=5`                             |

Uwagi:

- `mode=4k` obsługują tylko `kling-v3` i `kling-v3-omni`; jest on również wzajemnie wykluczający się z `camera_control` (ruchem kamery).
- `end_image_url` może być używany tylko razem z `start_image_url` przy `action=image2video`. Przekazanie wyłącznie `end_image_url` (bez `start_image_url`) zostanie odrzucone.
- `kling-v3` / `kling-v3-omni` akceptują dowolne całkowite `duration` od 3 do 15 sekund; `kling-o1` akceptuje wyłącznie 5; pozostałe modele akceptują tylko 5 lub 10.
- `generate_audio` domyślnie ma wartość `false`. Obsługują je tylko `kling-v3`, `kling-v3-omni` i `kling-v2-6` (tryb pro).

## Funkcja rozszerzania wideo

Jeśli chcesz kontynuować generowanie dla już wygenerowanego filmu Kling, możesz ustawić parametr `action` na `extend` i podać ID filmu, który ma być dalej generowany. ID filmu uzyskuje się zgodnie z podstawowym użyciem, jak pokazano poniżej:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

W tym momencie można zobaczyć, że ID filmu to:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Uwaga, `video_id` w tym filmie jest ID filmu po wygenerowaniu. Jeśli nie wiesz, jak wygenerować film, możesz zapoznać się z podstawowym użyciem powyżej, aby wygenerować film.

Następnie musimy wypełnić monit wymagany do rozszerzenia w następnym kroku, aby dostosować generowany film, i możemy określić następujące elementy:

- `model`: model do generowania filmu, obejmuje głównie modele `kling-v1`, `kling-v1-5` i `kling-v1-6`.
- `mode`: tryb generowania filmu, dostępne wartości to tryb standardowy `std`, tryb szybki `pro` i natywny tryb 4K `4k` (obsługiwany tylko przez `kling-v3` i `kling-v3-omni`, niezgodny z kontrolą ruchu kamery).
- `duration`: długość filmu dla tego zadania generowania wideo, obejmuje głównie 5 s i 10 s.
- `start_image_url`: link do obrazu referencyjnego pierwszej klatki, który należy przesłać przy wyborze działania wideo z obrazu `image2video`.
- `prompt`: monit.

Przykład wypełnienia jest następujący:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Po wypełnieniu kod jest generowany automatycznie w następujący sposób:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Odpowiedni kod Python:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Kliknij uruchom, a zobaczysz wynik jak poniżej:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```
Można zauważyć, że zawartość wyniku jest zgodna z powyższą, co realizuje funkcję rozszerzania wideo.

## Referencja Omni All-in-One (edycja wideo / referencyjne wideo / referencja wielu obrazów)

`kling-o1` i `kling-v3-omni` to dwa niezależne modele, oba obsługujące funkcję „referencji all-in-one”. Na podstawie generowania wideo z tekstu (`action=text2video`) można dodatkowo przekazać obrazy referencyjne lub wideo referencyjne, realizując **referencję wielu obrazów, wideo referencyjne oraz bezpośrednią edycję istniejącego wideo**.

**Kluczowa konwencja**: materiały referencyjne muszą być przywołane w `prompt` w formie `&lt;&lt;<image_1>>>`, `&lt;&lt;<video_1>>>` (numeracja zaczyna się od 1), aby odpowiadały materiałom na odpowiednich pozycjach w `image_list` / `video_list`; tylko wtedy model zastosuje te referencje. Jeśli przekażesz jedynie materiały bez przywołania ich w promptcie, materiały zostaną zignorowane.

> Informacja dotycząca bezpieczeństwa: obecne API nie udostępnia `element_list`. ID Kling Element Library nie są izolowane według tenantów, dlatego przed udostępnieniem Element Management API zapewniającego izolację tenantów należy użyć `image_list` do przekazywania obrazów referencyjnych obiektów.

Żądania Omni nie obsługują `negative_prompt`, `cfg_scale` ani `camera_control`, nie można również używać `mode=4k`. Gdy zawarte jest wideo referencyjne, `generate_audio` musi mieć wartość `false`.

### Wideo referencyjne i edycja wideo (`video_list`)

`video_list` służy do przekazywania wideo referencyjnego i jest najczęściej używanym scenariuszem tej funkcji. Pola elementów tablicy są następujące:

- `video_url`: link do wideo referencyjnego, nie może być pusty. Maksymalnie 1 wideo MP4/MOV, rozmiar pliku ≤200MB, liczba klatek 24–60fps. `kling-o1` wymaga długości 3–10 sekund oraz szerokości i wysokości po 700–2160px; `kling-v3-omni` wymaga długości 3–15.5 sekundy, szerokości i wysokości po 700–4553px, łącznej liczby pikseli ≤8,294,400 oraz proporcji obrazu 0.4–2.
- `refer_type`: typ referencji, opcjonalnie `base` (domyślnie, **podstawowe wideo do edycji**, czyli „bezpośrednia edycja wideo”, można dodawać/usuwać lub modyfikować elementy, zmieniać kompozycję, styl, kolory, pogodę itp.) lub `feature` (**referencja cech**, odniesienie do jego stylu / ruchu kamery / kontynuacja nagrania następnego ujęcia).
- `keep_original_sound`: czy zachować dźwięk oryginalnego wideo, opcjonalnie `yes` (zachowaj) lub `no` (usuń).

> Uwaga: gdy istnieje wideo referencyjne, `generate_audio` musi mieć wartość `false`. Dla wideo z `refer_type=base` nie można dodatkowo określić pierwszej / ostatniej klatki.

Przykład CURL edycji istniejącego wideo (zmiana wideo na styl anime) jest następujący:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Referencja wielu obrazów (`image_list`)

`image_list` służy do przekazywania obrazów referencyjnych (elementów / scen / stylów itp.). Pola elementów tablicy są następujące:

- `image_url`: link do obrazu referencyjnego, nie może być pusty. Wymagania: format .jpg/.jpeg/.png; rozmiar pliku ≤10MB; najkrótszy bok ≥300px; proporcje obrazu 1:2.5 ~ 2.5:1.
- `type`: opcjonalne. Jeśli nie zostanie przekazane, używane jako czysty obraz referencyjny; po przekazaniu `first_frame` / `end_frame` używane odpowiednio jako pierwsza / ostatnia klatka (równoważne `start_image_url` / `end_image_url`).

Podczas użycia należy odwołać się w `prompt` za pomocą `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Limity ilościowe: bez wideo referencyjnego liczba obrazów referencyjnych ≤ 7; z wideo referencyjnym liczba obrazów referencyjnych ≤ 4. Przy przekazywaniu wyłącznie pierwszej / ostatniej klatki można również bezpośrednio użyć `start_image_url` / `end_image_url`, jednak ostatnia klatka musi być używana razem z pierwszą klatką.

> Uwaga: jeśli jednocześnie przekażesz `start_image_url` / `end_image_url` oraz `image_list`, pierwsza / ostatnia klatka zostaną umieszczone przed `image_list`, co może wpłynąć na odpowiadanie numeracji `&lt;&lt;<image_N>>>`. Zaleca się wybrać jedną z dwóch metod: gdy potrzebujesz pierwszej / ostatniej klatki, określ `type` bezpośrednio w `image_list` i nie mieszaj tego z `start_image_url` / `end_image_url`.

Przykład CURL generowania wideo z referencją wielu obrazów:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Asynchroniczne wywołanie zwrotne

Ponieważ czas generowania przez Kling Videos Generation API jest stosunkowo długi, około 1–2 minut, jeśli API przez dłuższy czas nie odpowiada, żądanie HTTP będzie stale utrzymywać połączenie, powodując dodatkowe zużycie zasobów systemowych, dlatego to API zapewnia również obsługę asynchronicznych wywołań zwrotnych.

Ogólny proces wygląda następująco: gdy klient inicjuje żądanie, dodatkowo określa pole `callback_url`; po wysłaniu przez klienta żądania API, API natychmiast zwróci wynik zawierający informację w polu `task_id`, reprezentującą ID bieżącego zadania. Po ukończeniu zadania wynik wygenerowanego wideo zostanie wysłany w formie POST JSON na wskazany przez klienta `callback_url`, w tym również będzie zawarte pole `task_id`, dzięki czemu wynik zadania można powiązać przez ID.

Poniżej zapoznamy się ze szczegółową obsługą na podstawie przykładu.

Najpierw, wywołanie zwrotne Webhook jest usługą zdolną do odbierania żądań HTTP; programista powinien zastąpić je adresem URL własnego serwera HTTP. Dla wygody demonstracji używany jest tutaj publiczny przykładowy serwis Webhook https://webhook.site/; po otwarciu tej strony można uzyskać URL Webhook, jak pokazano na ilustracji:

![](https://cdn.acedata.cloud/tbcnai.png)

Skopiuj ten URL, aby używać go jako Webhook; przykładowo jest to `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Następnie możemy ustawić pole `callback_url` na powyższy URL Webhook, jednocześnie wypełniając odpowiednie parametry; konkretna zawartość jest pokazana na ilustracji:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Kliknij uruchom, a można zauważyć, że natychmiast otrzymasz wynik, jak poniżej:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```
Odczekaj chwilę, a będziemy mogli zaobserwować wynik wygenerowanego wideo na `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, jak pokazano na rysunku:

![](https://cdn.acedata.cloud/zv5u2q.png)

Treść jest następująca:

```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Można zauważyć, że w wyniku znajduje się pole `task_id`, a pozostałe pola są podobne do tych powyżej; za pomocą tego pola można realizować powiązanie zadań.

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informacje. Na przykład:

- `400 token_mismatched`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit częstotliwości.
- `500 api_error`: Wewnętrzny błąd serwera, coś poszło nie tak po stronie serwera.

### Przykład odpowiedzi błędu

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## Wnioski

Dzięki temu dokumentowi dowiedziałeś się już, jak korzystać z Kling Videos Generation API, aby generować wideo poprzez wprowadzenie tekstu podpowiedzi oraz obrazu referencyjnego pierwszej klatki. Mamy nadzieję, że ten dokument pomoże Ci lepiej zintegrować i używać tego API. W razie jakichkolwiek pytań prosimy o kontakt z naszym zespołem wsparcia technicznego.

### Kling 3.0 Turbo

`model="kling-v3-turbo"` obsługuje generowanie wideo z tekstu oraz generowanie wideo z obrazu pierwszej klatki, z czasem trwania będącym liczbą całkowitą od 3 do 15 sekund. `mode="std"` generuje 720p, a `mode="pro"` generuje 1080p. Model ten ma wbudowane natywne audio i nie udostępnia przełącznika wyłączania; pomiń `generate_audio` lub ustaw je na `true`. Model ten nie obsługuje ostatniej klatki, obiektów ruchu kamery, niezależnych negatywnych podpowiedzi ani `cfg_scale`. Opisz bezpośrednio w `prompt` treści, które mają się pojawić lub których należy unikać.

### Wideo wieloujęciowe

`kling-v3` i `kling-v3-omni` obsługują `multi_shot=true`. `shot_type="intelligence"` automatycznie tworzy podział na ujęcia na podstawie `prompt`; `shot_type="customize"` udostępnia 1–6 ujęć poprzez `multi_prompt`, gdzie każda pozycja zawiera rosnący kolejno od 1 `index`, `prompt` o długości maksymalnie 512 znaków oraz całkowity `duration` wynoszący co najmniej 1 sekundę. Suma czasów trwania wszystkich ujęć musi być równa całkowitemu `duration`. Dostosowane ujęcia nie używają globalnego `prompt`. Wideo wieloujęciowe jest rozliczane według wybranego modelu, jakości obrazu, konfiguracji audio i całkowitego czasu trwania.
