W tym artykule przedstawiono instrukcję integracji Kling Videos Generation API, które umożliwia generowanie oficjalnych filmów Kling poprzez wprowadzanie niestandardowych parametrów.

## Proces aplikacji

Aby korzystać z Kling Videos Generation API, najpierw przejdź do [konsoli Ace Data Cloud](https://platform.acedata.cloud/console/applications), aby uzyskać swój API Token i zachować go do późniejszego użycia.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Jeśli nie jesteś jeszcze zalogowany lub zarejestrowany, zostaniesz automatycznie przekierowany na stronę logowania, gdzie zostaniesz poproszony o rejestrację i zalogowanie się, a po zakończeniu automatycznie wrócisz na bieżącą stronę.

**Jeden API Token umożliwia wywoływanie wszystkich usług platformy, bez konieczności składania osobnego wniosku dla każdej usługi.** Pierwsze zgłoszenie zapewnia bezpłatny limit, umożliwiający darmowe wypróbowanie; gdy limit jest niewystarczający, możesz doładować wspólne saldo w [konsoli](https://platform.acedata.cloud/console/coin).

> 📘 Pełna dokumentacja: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Podstawowe użycie

Najpierw zapoznajmy się z podstawowym sposobem użycia: wystarczy wprowadzić prompt `prompt`, działanie generowania `action`, referencyjny obraz pierwszej klatki `start_image_url` oraz model `model`, aby uzyskać przetworzony wynik. Najpierw należy po prostu przekazać pole `action`, którego wartością jest `text2video`. Obejmuje ono głównie trzy działania: generowanie wideo z tekstu (`text2video`), generowanie wideo z obrazu (`image2video`) oraz rozszerzanie wideo (`extend`), a następnie należy również wprowadzić model `model`. Obecnie dostępne są głównie modele `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`, a szczegóły są następujące:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Można zobaczyć, że ustawiliśmy tutaj Request Headers, w tym:

- `accept`: jaki format odpowiedzi chcesz otrzymać; tutaj wpisz `application/json`, czyli format JSON.
- `authorization`: klucz do wywoływania API, po uzyskaniu można go bezpośrednio wybrać z listy rozwijanej.

Dodatkowo ustawiliśmy Request Body, w tym:

- `model`: model generowania wideo, głównie dostępne są modele `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode`: tryb generowania wideo; dostępne wartości to tryb standardowy `std`, tryb ultraszybki `pro` oraz natywny tryb 4K `4k`. Wśród nich `4k` obsługuje tylko `kling-v3` i `kling-v3-omni` oraz nie jest kompatybilny z `camera_control` (kontrolą ruchu kamery).
- `action`: działanie tego zadania generowania wideo, obejmujące głównie trzy działania: generowanie wideo z tekstu (`text2video`), generowanie wideo z obrazu (`image2video`), rozszerzanie wideo (`extend`).
- `start_image_url`: link do referencyjnego obrazu pierwszej klatki, który należy przesłać przy wyborze działania generowania wideo z obrazu `image2video`.
- `end_image_url`: opcjonalne podczas generowania wideo z obrazu, określa ostatnią klatkę.
- `duration`: długość wideo w sekundach. `kling-v3` i `kling-v3-omni` obsługują całkowite długości od 3 do 15 sekund; `kling-o1` obsługuje tylko 5 sekund; pozostałe modele obsługują 5 lub 10 sekund.
- `generate_audio`: czy jednocześnie generować dźwięk, opcjonalne, wartość logiczna. Obsługiwane przez `kling-v3`, `kling-v3-omni` oraz `kling-v2-6` (tylko tryb pro). Domyślna wartość to `false`.
- `aspect_ratio`: proporcje obrazu wideo, opcjonalne, obsługuje `16:9`, `9:16`, `1:1`, domyślnie `16:9`.
- `cfg_scale`: siła zgodności, zakres [0,1]; im większa wartość, tym bardziej zgodne z promptem.
- `camera_control`: opcjonalne, parametry obiektu kontrolującego ruch kamery, obsługuje ustawienia wstępne type/simple oraz konfiguracje takie jak horizontal, vertical, pan, tilt, roll, zoom.
- `negative_prompt`: opcjonalne, negatywny prompt określający elementy, których nie chcesz, maksymalnie 200 znaków.
- `image_list`: lista obrazów referencyjnych Omni, dla modeli `kling-o1` i `kling-v3-omni`; sposób użycia znajduje się poniżej w sekcji „Wszechstronne referencje Omni”.
- `video_list`: lista filmów referencyjnych Omni (obsługuje edycję wideo), dla modeli `kling-o1` i `kling-v3-omni`; sposób użycia znajduje się poniżej w sekcji „Wszechstronne referencje Omni”.
- `prompt`: prompt.
- `callback_url`: URL, na który mają zostać zwrócone wyniki wywołania zwrotnego.
- `async`: opcjonalne; po ustawieniu na `true` interfejs natychmiast zwraca `task_id`, bez konieczności podawania `callback_url`, a następnie wynik jest pobierany przez odpytywanie odpowiedniego interfejsu zapytania o zadanie.

Po wyborze można zauważyć, że po prawej stronie wygenerowano również odpowiedni kod, jak pokazano na ilustracji:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Kliknij przycisk „Try”, aby przeprowadzić test. Jak pokazano na powyższym obrazku, otrzymaliśmy tutaj następujący wynik:

```json
{
  "success": true,
  "video_id": "900798310464749610",
  "video_url": "https://cdn.acedata.cloud/assets/examples/kling/6c68c267-065b-4423-b66b-a0e4c59ee0d5-6a664a591a53.mp4",
  "duration": "5.041",
  "state": "succeed",
  "task_id": "6c68c267-065b-4423-b66b-a0e4c59ee0d5"
}
```

Zwrócony wynik zawiera wiele pól, opisanych poniżej:

- `success`, status zadania generowania wideo w tym momencie.
- `task_id`, ID zadania generowania wideo w tym momencie.
- `video_id`, ID wideo zadania generowania wideo w tym momencie.
- `video_url`, link do wideo zadania generowania wideo w tym momencie.
- `duration`, długość linku wideo zadania generowania wideo w tym momencie.
- `state`, stan zadania generowania wideo w tym momencie.

Można zauważyć, że otrzymaliśmy satysfakcjonujące informacje o wideo; wystarczy pobrać wygenerowane wideo Kling na podstawie adresu linku do wideo `data` w wyniku.

Ponadto, jeśli chcesz wygenerować odpowiedni kod integracji, możesz go bezpośrednio skopiować; na przykład kod CURL jest następujący:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Macierz możliwości modeli

Różne modele znacznie różnią się pod względem obsługi parametrów. Poniższa macierz została opracowana na podstawie [oficjalnej dokumentacji Kling video models](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels). Przed wywołaniem sprawdź, czy obecna kombinacja `model` / `mode` / `duration` obsługuje wymaganą funkcję, w przeciwnym razie zostanie zwrócony błąd taki jak `model/mode/duration(...) is not supported with image_tail`.
| Model                  | Tryb             | `end_image_url` (pierwsza i ostatnia klatka) | `generate_audio` (dźwięk towarzyszący) | `camera_control` (ruch kamery) | Uwagi                                           |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ tylko `duration=5`     | ❌                    | ✅ tylko `duration=5`     | `extend` nie obsługuje `negative_prompt` ani `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | Wideo z wielu obrazów, wszystkie tryby `extend` dostępne                         |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Pojedynczy tryb, tylko `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Pojedynczy tryb, tylko `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | Jedyny model inny niż v3, który jednocześnie obsługuje dźwięk towarzyszący                             |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | Zakres `duration`: 3–15 sekund                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | Tryb 4K jest niekompatybilny z ruchem kamery                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Obsługuje tylko `duration=5`                             |

Uwagi:

- `mode=4k` jest obsługiwany tylko przez `kling-v3` i `kling-v3-omni`; jest również wzajemnie wykluczający się z `camera_control` (ruchem kamery).
- `end_image_url` może być używany tylko razem z `start_image_url`, gdy `action=image2video`. Przekazanie wyłącznie `end_image_url` (bez `start_image_url`) zostanie odrzucone.
- `kling-v3` / `kling-v3-omni` akceptują dowolną całkowitą wartość `duration` od 3 do 15 sekund; `kling-o1` akceptuje tylko 5; pozostałe modele akceptują tylko 5 lub 10.
- Domyślna wartość `generate_audio` to `false`. Obsługują ją tylko `kling-v3`, `kling-v3-omni` oraz `kling-v2-6` (tryb pro).

## Funkcja rozszerzania wideo

Jeśli chcesz kontynuować generowanie już wygenerowanego wideo Kling, możesz ustawić parametr `action` na `extend` oraz wprowadzić ID wideo, które ma być dalej generowane. ID wideo uzyskuje się zgodnie z podstawowym użyciem, jak pokazano na poniższym obrazie:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

W tym momencie można zobaczyć, że ID wideo to:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Uwaga, `video_id` w tym wideo jest ID wygenerowanego wideo. Jeśli nie wiesz, jak wygenerować wideo, możesz zapoznać się z podstawowym użyciem powyżej, aby wygenerować wideo.

Następnie musimy koniecznie wypełnić słowa kluczowe potrzebne do rozszerzenia w następnym kroku, aby dostosować generowane wideo, można wtedy określić następującą zawartość:

- `model`: model do generowania wideo, głównie modele `kling-v1`, `kling-v1-5` i `kling-v1-6`.
- `mode`: tryb generowania wideo, opcjonalne wartości to tryb standardowy `std`, tryb ultraszybki `pro` oraz natywny tryb 4K `4k` (obsługiwany tylko przez `kling-v3` i `kling-v3-omni`, niekompatybilny z kontrolą ruchu kamery).
- `duration`: czas trwania wideo dla tego zadania generowania wideo, obejmuje głównie 5 s i 10 s.
- `start_image_url`: gdy wybierzesz działanie generowania wideo z obrazu `image2video`, wymagany jest link do przesłanego obrazu referencyjnego pierwszej klatki.
- `prompt`: słowa kluczowe.

Przykład wypełnienia jest następujący:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Po wypełnieniu kod zostanie automatycznie wygenerowany w następujący sposób:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Odpowiadający kod Python:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Kliknij uruchom, a zobaczysz, że otrzymasz wynik, jak poniżej:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```

Jak widać, zawartość wyniku jest zgodna z powyższą, co realizuje funkcję rozszerzania wideo.

## Wszechstronne odniesienie Omni (edycja wideo / wideo referencyjne / odniesienie do wielu obrazów)

`kling-o1` i `kling-v3-omni` to dwa niezależne modele, oba obsługujące możliwości „wszechstronnego odniesienia”. Na podstawie generowania wideo z tekstu (`action=text2video`) można dodatkowo przekazać obrazy referencyjne lub wideo referencyjne, aby realizować **odniesienie do wielu obrazów, wideo referencyjne oraz bezpośrednią edycję istniejącego wideo**.

**Główna konwencja**: materiały referencyjne muszą być przywoływane w `prompt` w formie `&lt;&lt;<image_1>>>`, `&lt;&lt;<video_1>>>` (numeracja zaczyna się od 1), aby odwoływać się do materiałów na odpowiednich pozycjach w `image_list` / `video_list`; tylko wtedy model zastosuje te odniesienia. Jeśli przekażesz jedynie materiały bez przywołania ich w słowach kluczowych, materiały zostaną zignorowane.

> Informacja dotycząca bezpieczeństwa: obecne API nie udostępnia `element_list`. ID biblioteki Kling Element Library nie są izolowane między dzierżawcami, dlatego przed udostępnieniem API Element Management zapewniającego izolację dzierżawców należy używać `image_list` do przekazywania obrazów referencyjnych obiektu.

Żądania Omni nie obsługują `negative_prompt`, `cfg_scale` ani `camera_control` i nie mogą używać `mode=4k`. Gdy zawierają wideo referencyjne, `generate_audio` musi mieć wartość `false`.

### Wideo referencyjne i edycja wideo (`video_list`)
`video_list` służy do przekazywania referencyjnych filmów i jest najczęściej używanym scenariuszem tej funkcji; pola elementów tablicy są następujące:

- `video_url`: link do referencyjnego filmu, nie może być pusty. Maksymalnie 1 film MP4/MOV, rozmiar pliku ≤200MB, liczba klatek 24–60fps. `kling-o1` wymaga długości 3–10 sekund oraz szerokości i wysokości po 700–2160px; `kling-v3-omni` wymaga długości 3–15.5 sekundy, szerokości i wysokości po 700–4553px, łącznej liczby pikseli ≤8,294,400 oraz proporcji obrazu 0.4–2.
- `refer_type`: typ referencji, opcjonalnie `base` (domyślnie, **bazowy film do edycji**, czyli „bezpośrednia edycja filmu”, umożliwiająca dodawanie/usuwanie/modyfikowanie elementów, zmianę kompozycji, stylu, kolorów, pogody itd.) lub `feature` (**referencja cech**, odniesienie do jego stylu / pracy kamery / kontynuacji nagrania w następnym ujęciu).
- `keep_original_sound`: czy zachować oryginalne audio filmu, opcjonalnie `yes` (zachowaj) lub `no` (usuń).

> Uwaga: gdy istnieje referencyjny film, `generate_audio` musi mieć wartość `false`. Dla filmu z `refer_type=base` nie można ponownie określić pierwszej / ostatniej klatki.

Przykład CURL edycji istniejącego filmu (zmiana filmu na styl anime) jest następujący:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Referencja wielu obrazów (`image_list`)

`image_list` służy do przekazywania referencyjnych obrazów (elementów / scen / stylów itd.); pola elementów tablicy są następujące:

- `image_url`: link do referencyjnego obrazu, nie może być pusty. Wymagania: format .jpg/.jpeg/.png; rozmiar pliku ≤10MB; krótszy bok ≥300px; proporcje obrazu 1:2.5 ~ 2.5:1.
- `type`: opcjonalne. Bez przekazania jest używany jako czysty obraz referencyjny; po przekazaniu `first_frame` / `end_frame` jest używany odpowiednio jako pierwsza / ostatnia klatka (równoważne `start_image_url` / `end_image_url`).

Podczas użycia należy odwoływać się w `prompt` za pomocą `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Limit liczby: gdy nie ma referencyjnego filmu, obrazy referencyjne ≤ 7; gdy istnieje referencyjny film, obrazy referencyjne ≤ 4. Przy przekazywaniu wyłącznie pierwszej / ostatniej klatki można również bezpośrednio użyć `start_image_url` / `end_image_url`, ale ostatnia klatka musi być używana razem z pierwszą klatką.

> Uwaga: jeśli jednocześnie przekazywane są `start_image_url` / `end_image_url` oraz `image_list`, pierwsza / ostatnia klatka zostaną umieszczone przed `image_list`, co może wpłynąć na relację numeracji `&lt;&lt;<image_N>>>`. Zaleca się wybór jednej z opcji: gdy potrzebne są pierwsza / ostatnia klatka, określ `type` bezpośrednio w `image_list` i nie mieszaj tego z `start_image_url` / `end_image_url`.

Przykład CURL generowania filmu na podstawie referencji wielu obrazów:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Asynchroniczne wywołanie zwrotne

Ponieważ czas generowania przez Kling Videos Generation API jest stosunkowo długi, około 1–2 minuty, jeśli API przez długi czas nie odpowiada, żądanie HTTP będzie stale utrzymywać połączenie, co prowadzi do dodatkowego zużycia zasobów systemowych, dlatego to API zapewnia również obsługę asynchronicznych wywołań zwrotnych.

Ogólny proces wygląda następująco: podczas wysyłania żądania klient dodatkowo określa pole `callback_url`; po wysłaniu żądania API, API natychmiast zwróci wynik zawierający pole `task_id`, reprezentujące identyfikator bieżącego zadania. Po ukończeniu zadania wynik wygenerowanego filmu zostanie wysłany w formie POST JSON na wskazany przez klienta `callback_url`, w tym również pole `task_id`, dzięki czemu wyniki zadań można powiązać za pomocą ID.

Poniżej poprzez przykład zobaczymy, jak konkretnie to wykonać.

Najpierw wywołanie zwrotne Webhook to usługa mogąca odbierać żądania HTTP; programista powinien zastąpić je adresem URL własnego serwera HTTP. Dla wygody demonstracji użyjemy publicznej przykładowej strony Webhook https://webhook.site/; po otwarciu tej strony można uzyskać adres URL Webhook, jak pokazano na ilustracji:

Skopiuj ten URL, aby użyć go jako Webhook; przykładowy adres tutaj to `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

## Obsługa błędów

Podczas wywoływania API, jeśli wystąpi błąd, API zwróci odpowiedni kod błędu i informację. Na przykład:

- `400 token_mismatched`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `400 api_not_implemented`: Nieprawidłowe żądanie, prawdopodobnie z powodu brakujących lub nieprawidłowych parametrów.
- `401 invalid_token`: Brak autoryzacji, nieprawidłowy lub brakujący token autoryzacyjny.
- `429 too_many_requests`: Zbyt wiele żądań, przekroczono limit częstotliwości.
- `500 api_error`: Wewnętrzny błąd serwera, coś poszło nie tak po stronie serwera.
### Przykład odpowiedzi błędu

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
