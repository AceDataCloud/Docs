Prześlij zadanie przez `POST /kling/virtual-try-on`, użyj istniejącego `POST /kling/tasks` do sprawdzania statusu zadania na platformie.

## Dane wejściowe

Należy dostarczyć dokładnie jedno product_image i jedno person_image. keep_face, keep_pose, keep_background domyślnie mają wartość true i można je niezależnie wyłączyć. Najdłuższy bok obrazu wejściowego nie może przekraczać 2048px, najkrótszy bok musi być większy niż 300px, a plik nie może przekraczać 10MB.

Poniżej znajduje się przykład struktury żądania, zastąp adres URL materiału przed wywołaniem.

```json
{
  "contents": [
    {
      "type": "product_image",
      "url": "https://your-cdn.example/product.jpg"
    },
    {
      "type": "person_image",
      "url": "https://your-cdn.example/person.jpg"
    }
  ],
  "async": true
}
```

## Wyniki i rozliczenia

Tryb synchroniczny zwraca wynik generowania; tryb asynchroniczny najpierw zwraca `task_id`, a ukończony wynik zawiera linki do wideo lub obrazów w `data` oraz obliczone przez serwer `usage`. `callback_url` służy do powiadamiania o ukończeniu; żądanie `watermark=true` jednocześnie zwraca wersję ze znakiem wodnym.

1.12 Credits/obraz, rozliczane według rzeczywistej liczby wygenerowanych obrazów. Wideo jest rozliczane według rzeczywistego czasu trwania generowania, cena bazowa za sekundę przed generowaniem nie reprezentuje całkowitej ceny całego zadania. Nieudane zadania nie są obciążane opłatą za generowanie.
