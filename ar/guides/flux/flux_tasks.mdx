تتمثل الوظيفة الرئيسية لـ Flux Tasks API في الاستعلام عن حالة تنفيذ المهمة من خلال إدخال معرّف مهمة المنصة الذي يتم إرجاعه بواسطة Flux Images Generation API أو Flux Videos API.

سيقدم هذا المستند بالتفصيل إرشادات تكامل Flux Tasks API، لمساعدتك على دمج هذه الواجهة والاستفادة الكاملة من وظائفها القوية بسهولة. من خلال Flux Tasks API، يمكنك بسهولة تنفيذ الاستعلام عن حالة تنفيذ مهام Flux Images Generation API.

للحصول على مثال كامل لإرسال الفيديو والاستعلام الدوري، راجع [دليل تكامل Flux Videos API](https://platform.acedata.cloud/documents/flux-videos-integration). لا يتم فرض رسوم إنشاء إضافية للاستعلام عن المهام الموجودة.

## عملية التقديم

لاستخدام Flux Images Generation API، انتقل أولاً إلى [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم تلقائيًا تحويلك إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائيًا إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** سيُمنحك رصيد مجاني عند التقديم لأول مرة، ويمكنك التجربة مجانًا؛ وعندما لا يكون الرصيد كافيًا، يمكنك إعادة شحن الرصيد العام في [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## مثال على الطلب

يمكن استخدام Flux Tasks API للاستعلام عن نتائج Flux Images Generation API. لمعرفة كيفية استخدام Flux Images Generation API، يرجى الرجوع إلى وثيقة [Flux Images Generation API ](https://platform.acedata.cloud/documents/flux-images-integration).

سنأخذ معرّف مهمة تم إرجاعه بواسطة خدمة Flux Images Generation API كمثال، لشرح كيفية استخدام هذه الواجهة. لنفترض أن لدينا معرّف مهمة: 2db0168c-2373-4367-8d9a-9dc778802e8a، وسنوضح بعد ذلك كيفية تمرير معرّف مهمة من خلال.

### إعداد رؤوس الطلب وجسم الطلب

**Request Headers** تتضمن:

- `accept`: تحدد استلام نتائج الاستجابة بتنسيق JSON، وهنا يتم تعبئتها بـ `application/json`.
- `authorization`: مفتاح استدعاء API، ويمكن اختياره مباشرة من القائمة المنسدلة بعد التقديم.

**Request Body** يتضمن:

- `id`: معرّف المهمة المرفوعة.
- `action`: طريقة التشغيل على المهمة.

الإعداد كما هو موضح في الشكل التالي:

يمكن ملاحظة أنه تم إنشاء أكواد بلغات مختلفة تلقائيًا بالفعل على الجانب الأيمن من الصفحة، كما هو موضح في الشكل:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/flux/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/flux/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

تحتوي نتيجة الإرجاع على عدة حقول، وحقل `request` هو request body عند بدء المهمة، بينما حقل `response` هو response body الذي يتم إرجاعه بعد اكتمال المهمة. تعريف الحقول كما يلي.

- `id`: معرّف مهمة إنشاء هذه الصورة، ويُستخدم لتحديد مهمة إنشاء الصورة هذه بشكل فريد.
- `request`: معلومات الطلب في الاستعلام عن مهمة الصورة.
- `response`: معلومات الإرجاع في الاستعلام عن مهمة الصورة.
- `created_at`: وقت إنشاء المهمة، طابع زمني Unix (بالثواني، رقم عشري).
- `started_at`: وقت بدء تنفيذ المهمة، طابع زمني Unix (بالثواني، رقم عشري).
- `finished_at`: وقت اكتمال المهمة، طابع زمني Unix (بالثواني، رقم عشري). لا يتم إرجاع هذا الحقل عندما لا تكتمل المهمة.
- `elapsed`: الوقت المستغرق في تنفيذ المهمة، بوحدة الثواني (رقم عشري، مع الاحتفاظ بـ 3 منازل عشرية). لا يتم إرجاع هذا الحقل عندما لا تكتمل المهمة.

## معالجة الأخطاء

عند استدعاء واجهة API، إذا واجهت خطأً، فستعيد واجهة API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح به، رمز التفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جدًا، لقد تجاوزت حد المعدل.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة الخطأ

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"

```

## الخلاصة

من خلال هذا المستند، أصبحت تعرف كيفية استخدام FLux Tasks API للاستعلام عن جميع معلومات التفاصيل المحددة لمهمة صورة واحدة أو مهام صور مجمّعة. نأمل أن يساعدك هذا المستند على التكامل مع واجهة API هذه واستخدامها بشكل أفضل. إذا كانت لديك أي أسئلة، فلا تتردد في الاتصال بفريق الدعم الفني لدينا.
