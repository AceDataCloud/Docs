ستقدم هذه المقالة شرحًا لتكامل واجهة API لتوليد صور Flux، والتي يمكنها إنشاء صور Flux الرسمية من خلال إدخال معلمات مخصصة.

## عملية التقديم

لاستخدام واجهة API لتوليد صور Flux، انتقل أولًا إلى [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائيًا إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** سيُمنح رصيد مجاني عند أول تقديم، ويمكنك التجربة مجانًا؛ وعندما لا يكون الرصيد كافيًا، يمكنك شحن الرصيد العام في [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [واجهة API لتوليد صور Flux →](https://platform.acedata.cloud/documents/flux-images)

## الاستخدام الأساسي

افهم أولًا طريقة الاستخدام الأساسية، وهي إدخال كلمة التوجيه `prompt`، وإجراء التوليد `action`، وحجم الصورة `size`، ثم يمكنك الحصول على النتيجة المعالجة. تحتاج أولًا إلى تمرير حقل `action` ببساطة، وتكون قيمته `generate`، ثم نحتاج أيضًا إلى إدخال كلمة التوجيه، والمحتوى المحدد كما يلي:

<p><img src="https://cdn.acedata.cloud/wz85jt.png" width="500" className="m-auto" /></p>

يمكنك رؤية أننا قمنا هنا بتعيين Request Headers، بما في ذلك:

- `accept`: تنسيق نتيجة الاستجابة الذي تريد تلقيه، وهنا يُملأ بـ `application/json`، أي تنسيق JSON.
- `authorization`: مفتاح استدعاء API، ويمكن اختياره مباشرة من القائمة المنسدلة بعد التقديم.

كما تم تعيين Request Body، بما في ذلك:

- `action`: إجراء مهمة توليد الصور هذه.
- `size`: حجم نتيجة توليد الصورة. **يجب أن تمرر سلسلة `flux-2-flex` / `flux-2-pro` / `flux-2-max` نسبة الصورة (مثل `1:1` و`16:9`)، ولا تقبل أبعاد البكسل مثل `1024x1024`، وسيتم إرجاع 400 عند عدم تحديدها.**
- `count`: عدد الصور التي يتم إنشاؤها، والقيمة الافتراضية هي 1. تكون هذه المعلمة فعالة فقط في مهمة توليد الصور، وغير فعالة في مهمة التحرير.
- `prompt`: كلمة التوجيه.
- `model`: نموذج التوليد، والقيمة الافتراضية هي `flux-dev`؛ وأحدث النماذج الرائدة هي `flux-2-pro` و`flux-2-max` (جودة صورة أعلى، وتتطلب استخدام نسبة الصورة `size`).
- `callback_url`: عنوان URL الذي يحتاج إلى استدعاء النتيجة.
- `async`: اختياري، عند تعيينه إلى `true`، تقوم الواجهة بإرجاع `task_id` فورًا، ولا حاجة لتوفير `callback_url`، ثم يتم الحصول على النتيجة عبر الاستعلام الدوري من خلال واجهة استعلام المهمة المقابلة.

توجد بعض القيود الخاصة على المعلمة `size`، وتنقسم أساسًا إلى نوعين: نسبة العرض إلى الارتفاع `width x height`، ونسبة الصورة `x:y`، والتفاصيل كما يلي:

| النموذج               | النطاق                                         |
| ---------------- | ------------------------------------------ |
| flux-dev         | يدعم نسبة العرض إلى الارتفاع 1024x1024 و1024x1792 و1792x1024، أو نسبة الصورة |
| flux-pro         | يدعم نسبة العرض إلى الارتفاع 1024x1024 و1024x1792 و1792x1024، أو نسبة الصورة |
| flux-2-flex      | يدعم نسبة الصورة فقط                                    |
| flux-2-pro       | يدعم نسبة الصورة فقط                                    |
| flux-2-max       | يدعم نسبة الصورة فقط                                    |
| flux-kontext-pro | يدعم نسبة الصورة فقط                                    |
| flux-kontext-max | يدعم نسبة الصورة فقط                                    |

نِسَب الصور المرجعية: "21:9"، "16:9"، "4:3"، "3:2"، "1:1"، "2:3"، "3:4"، "9:16"، "9:21".

بعد اختيار المعلمات، سيتم إنشاء الكود المقابل تلقائيًا على الجانب الأيمن. قبل النسخ، يرجى التأكد من أن رأس التفويض يستخدم API Key الخاص بك، ولا ينبغي أن تظهر بيانات اعتماد حقيقية في الوثائق ولقطات الشاشة.

انقر على زر «Try» لإجراء الاختبار، وهنا حصلنا على النتيجة التالية:

```json
{
  "success": true,
  "task_id": "5456c749-3bbb-4f10-9eb8-cfbcac297500",
  "trace_id": "ae4eecb8-1dd6-45b4-bfb3-a1c48872536e",
  "data": [
    {
      "image_url": "https://cdn.acedata.cloud/assets/examples/flux/5456c749-3bbb-4f10-9eb8-cfbcac297500-d0ef60485f73.jpg"
    }
  ]
}
```

تحتوي النتيجة المرجعة على عدة حقول، كما يلي:

- `success`، حالة مهمة توليد الفيديو في هذا الوقت.
- `task_id`، معرّف مهمة توليد الفيديو في هذا الوقت.
- `trace_id`، معرّف تتبع توليد الفيديو في هذا الوقت.
- `data`، قائمة نتائج مهمة توليد الصور في هذا الوقت.
  - `image_url`، رابط مهمة توليد الصور في هذا الوقت.
  - `prompt`، كلمة التوجيه.

يمكنك أن ترى أننا حصلنا على معلومات الصورة المُرضية، ونحتاج فقط إلى الحصول على صورة Flux المُولّدة وفقًا لعنوان رابط الصورة في `data` ضمن النتيجة.

بالإضافة إلى ذلك، إذا كنت ترغب في إنشاء كود التكامل المقابل، يمكنك نسخه مباشرةً، على سبيل المثال، كود CURL كما يلي:

```shell
curl -X POST 'https://api.acedata.cloud/flux/images' \
-H 'authorization: Bearer {token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "A photorealistic studio product shot of a frosted-glass perfume bottle on wet black slate, single softbox key light, water droplets, dark moody background, 85mm macro.",
  "model": "flux-2-pro",
  "size": "1:1"
}'
```

## مهمة تحرير الصور

إذا كنت ترغب في تحرير صورة معينة، فيجب أولًا تمرير رابط الصورة التي تحتاج إلى تحريرها في المعلمة `image_url`، وفي هذا الوقت يدعم `action` فقط `edit`، ويمكنك تحديد المحتوى التالي:

- model: النموذج المستخدم في مهمة تحرير الصور هذه، ويدعم `flux-dev` و`flux-pro` و`flux-kontext-pro` و`flux-kontext-max` و`flux-2-flex` و`flux-2-pro` و`flux-2-max`.
- image_url: ارفع الصورة التي تحتاج إلى تحريرها.

مثال على التعبئة كما يلي:

<p><img src="https://cdn.acedata.cloud/jn9da5.png" width="500" className="m-auto" /></p>

بعد إكمال التعبئة، يتم إنشاء الكود تلقائيًا كما يلي:

<p><img src="https://cdn.acedata.cloud/6cwxb8.png" width="500" className="m-auto" /></p>

الكود المقابل:

```python
import requests

url = "https://api.acedata.cloud/flux/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "edit",
    "prompt": "a white siamese cat",
    "model": "flux-kontext-pro",
    "image_url": "https://cdn.acedata.cloud/ytj2qy.png"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

انقر على التشغيل، وستجد أنه سيتم الحصول على نتيجة فورًا، كما يلي:

```json
{
  "success": true,
  "task_id": "2a7979ff-1f77-4380-92c6-a2dc37c3b4c8",
  "trace_id": "732b65c0-48d9-49f7-b568-64e5acffe4c0",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "timings": 1752744073
    }
  ]
}
```
يمكن ملاحظة أن التأثير المُولَّد هو تأثير تعديل للصورة الأصلية، والنتيجة مشابهة لما ورد أعلاه.

## الاستدعاء غير المتزامن

نظرًا لأن وقت إنشاء Flux Images Generation API طويل نسبيًا، ويستغرق حوالي 1-2 دقيقة، فإذا لم تستجب API لفترة طويلة، فسيظل طلب HTTP متصلًا باستمرار، مما يؤدي إلى استهلاك إضافي لموارد النظام، لذلك توفر هذه API أيضًا دعمًا للاستدعاء غير المتزامن.

التدفق العام هو: عند قيام العميل بإرسال طلب، يحدد بالإضافة إلى ذلك حقل `callback_url`، وبعد أن يرسل العميل طلب API، ستعيد API نتيجة فورًا، تتضمن معلومات حقل `task_id`، والذي يمثل معرّف المهمة الحالية. عند اكتمال المهمة، سيتم إرسال نتيجة إنشاء الصورة إلى `callback_url` الذي حدده العميل بصيغة POST JSON، وتتضمن أيضًا حقل `task_id`، وبهذه الطريقة يمكن ربط نتائج المهام عبر المعرّف.

فيما يلي سنتعرف من خلال مثال على كيفية التنفيذ بالتحديد.

أولًا، استدعاء Webhook هو خدمة يمكنها استقبال طلبات HTTP، ويجب على المطور استبداله بعنوان URL لخادم HTTP الذي أنشأه بنفسه. ولتسهيل العرض التوضيحي هنا، يتم استخدام موقع نموذج Webhook عام https://webhook.site/، ويمكن الحصول على عنوان Webhook URL عند فتح هذا الموقع، كما هو موضح في الشكل:

![](https://cdn.acedata.cloud/cjjfly.png)

## معالجة الأخطاء

عند استدعاء API، إذا حدث خطأ، فستعيد API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح به، رمز تفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جدًا، لقد تجاوزت حد المعدل.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة الخطأ

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
