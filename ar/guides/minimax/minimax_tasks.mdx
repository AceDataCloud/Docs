تتناول هذه الوثيقة تكامل واستخدام واجهة برمجة التطبيقات لاستعلام مهام MiniMax H3. تُستخدم هذه الواجهة لاستعلام، وإدراج، أو حذف دفعة من المهام غير المتزامنة التي تم إنشاؤها بواسطة [واجهة برمجة التطبيقات لإنشاء فيديو MiniMax H3](/documents/minimax-videos-integration).

## عملية التقديم

لاستخدام واجهة برمجة التطبيقات لاستعلام مهام MiniMax H3، يجب أولاً الحصول على رمز API الخاص بك من [وحدة التحكم في Ace Data Cloud](https://platform.acedata.cloud/console/applications) للاحتفاظ به.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد قمت بتسجيل الدخول أو التسجيل بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك للتسجيل وتسجيل الدخول، وبعد الانتهاء، سيتم إرجاعك تلقائيًا إلى الصفحة الحالية.

**يمكن استخدام رمز API واحد لاستدعاء جميع خدمات المنصة، دون الحاجة لتقديم طلب منفصل لكل خدمة.** عند التقديم لأول مرة، ستحصل على رصيد مجاني لتجربته؛ وعند نفاد الرصيد، يمكنك إعادة شحن الرصيد العام في [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [واجهة برمجة التطبيقات لاستعلام مهام MiniMax H3 →](https://platform.acedata.cloud/documents/minimax-tasks-integration)

عند استعلام المهام، يجب استخدام نفس الرمز الذي تم إنشاء المهمة به. يُنصح بحفظ الرمز كمتغير بيئي، وعدم كتابته في الشيفرة المصدرية أو رفعه إلى مستودع النسخ:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## نظرة عامة على الواجهة

- **Base URL**: `https://api.acedata.cloud`
- **Endpoint**: `POST /minimax/tasks`
- **طريقة المصادقة**: يتم تضمين `authorization: Bearer {token}` في رأس HTTP
- **رؤوس الطلب**:
  - `accept: application/json`
  - `content-type: application/json`
- **استعلام عن مهمة واحدة**: `action=retrieve`، تمرير `id`
- **استعلام عن مهام دفعة**: `action=retrieve_batch`، يمكن تصفية حسب معرف المهمة، نطاق الوقت، وظروف الترقيم
- **حذف مهمة**: `action=delete`، تمرير `id`
- **شرح الفوترة**: استعلام المهام مجاني، ولن يؤدي إلى رسوم متكررة

بعد إنشاء الفيديو، يجب حفظ `task_id`. يُوصى بالاستعلام كل حوالي 10 ثوانٍ حتى تدخل المهمة في الحالة النهائية.

## معلمات الطلب

| المعلمة              | النوع       | مطلوب   | الإجراء المناسب          | الشرح                                                   |
| ---------------- | -------- | ---- | ------------------- | ---------------------------------------------------- |
| `action`         | string   | لا    | جميع                  | `retrieve`، `retrieve_batch` أو `delete`؛ الافتراضي `retrieve` |
| `id`             | string   | مطلوب شرطي | `retrieve`، `delete` | معرف مهمة واحدة                                              |
| `ids`            | string[] | لا    | `retrieve_batch`    | إرجاع معرفات المهام المحددة فقط؛ عند الإغفال، يتم إدراج المهام حسب شروط أخرى                              |
| `limit`          | integer  | لا    | `retrieve_batch`    | الحد الأقصى لعدد المهام التي سيتم إرجاعها في هذه المرة                                          |
| `offset`         | integer  | لا    | `retrieve_batch`    | عدد المهام التي سيتم تخطيها من قائمة النتائج، للاستخدام في الترقيم                                   |
| `created_at_min` | number   | لا    | `retrieve_batch`    | الحد الأدنى لوقت الإنشاء، طابع زمني Unix، بالثواني                                 |
| `created_at_max` | number   | لا    | `retrieve_batch`    | الحد الأقصى لوقت الإنشاء، طابع زمني Unix، بالثواني                                 |

تُستخدم الأفعال الثلاثة كما يلي:

| `action`         | الاستخدام                 | المعلمات الضرورية                           | هيكل الاستجابة                                  |
| ---------------- | ------------------ | ------------------------------ | ------------------------------------- |
| `retrieve`       | استعلام عن حالة ونتيجة مهمة واحدة       | `id`                           | `{ "task": {...} }`                   |
| `retrieve_batch` | استعلام دفعة حسب معرف المهمة، الوقت وظروف الترقيم | المعلمات الاختيارية `ids`، نطاق الوقت، `offset`، `limit` | `{ "items": [...], "total": number }` |
| `delete`         | إلغاء أو حذف سجل المهمة بناءً على الحالة الحالية للمهمة  | `id`                           | `{ "id": "...", "deleted": true }`    |

## حالة المهمة

| `status`    | المعنى         | معالجة العميل                      |
| ----------- | ---------- | ---------------------------- |
| `queued`    | تم إدخاله في قائمة الانتظار، في انتظار التنفيذ | استمر في الاستعلام                       |
| `running`   | قيد الإنشاء       | استمر في الاستعلام                       |
| `succeeded` | تم الإنشاء بنجاح       | قراءة `task.content.url`، توقف عن الاستعلام |
| `failed`    | فشل الإنشاء       | قراءة `task.error`، توقف عن الاستعلام       |
| `cancelled` | تم إلغاء المهمة      | توقف عن الاستعلام                       |

تعتبر الحالات `succeeded`، `failed` و `cancelled` حالات نهائية. لا تستمر في الاستعلام بعد الدخول في الحالة النهائية.

## حقول استجابة المهمة

| الحقل                        | النوع      | الشرح                              |
| ------------------------- | ------- | ------------------------------- |
| `id`                      | string  | معرف المهمة                           |
| `model`                   | string  | النموذج المستخدم في المهمة، حاليًا هو `MiniMax-H3`        |
| `status`                  | string  | الحالة الحالية للمهمة                          |
| `error.code`              | string  | رمز الخطأ عند الفشل، يُرجع فقط عند الفشل                    |
| `error.message`           | string  | سبب الفشل، يُرجع فقط عند الفشل                     |
| `created_at`              | integer | وقت الإنشاء، طابع زمني Unix، بالثواني              |
| `updated_at`              | integer | آخر تحديث لحالة الوقت، طابع زمني Unix، بالثواني        |
| `content.url`             | string  | عنوان الفيديو بعد النجاح                        |
| `resolution`              | string  | دقة الإخراج، `768P` أو `2K`             |
| `duration`                | integer | مدة الفيديو الناتج، بالثواني                     |
| `usage.total_seconds`     | integer | إجمالي تكلفة الاستخدام، يساوي مجموع ثواني الفيديو المدخل والمخرج           |
| `usage.input_seconds`     | integer | تكلفة الاستخدام الناتجة عن الفيديو المدخل                   |
| `usage.output_seconds`    | integer | تكلفة الاستخدام الناتجة عن الفيديو المخرج                     |
| `usage.input_image_count` | integer | عدد الصور المدخلة في إحصائيات التكلفة                    |
| `ratio`                   | string  | نسبة العرض إلى الارتفاع الفعلية؛ عند استخدام `adaptive`، تكون النتيجة هنا هي المعتمدة |
| `task_type`               | string  | مهمة إنشاء الفيديو هي `generation`            |
| `modality`                | string  | مهمة الفيديو هي `video`                   |

## مثال كامل على الاستعلام باستخدام Python
以下代码从环境变量读取 Token，创建任务后每隔 10 秒查询一次：

```python
import os
import time

import requests

BASE_URL = "https://api.acedata.cloud"
HEADERS = {
    "Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_KEY']}",
    "Content-Type": "application/json",
}

create_response = requests.post(
    f"{BASE_URL}/minimax/videos",
    headers=HEADERS,
    json={
        "model": "MiniMax-H3",
        "content": [
            {
                "type": "text",
                "text": "清晨的海边，一艘白色帆船驶过平静海面，镜头缓慢横移",
            }
        ],
        "resolution": "768P",
        "duration": 4,
        "ratio": "16:9",
    },
    timeout=30,
)
create_response.raise_for_status()
task_id = create_response.json()["task_id"]

while True:
    time.sleep(10)
    query_response = requests.post(
        f"{BASE_URL}/minimax/tasks",
        headers=HEADERS,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    query_response.raise_for_status()
    task = query_response.json()["task"]
    print(f"task={task_id} status={task['status']}")

    if task["status"] == "succeeded":
        print(f"video_url={task['content']['url']}")
        break
    if task["status"] in ("failed", "cancelled"):
        raise RuntimeError(task.get("error") or task["status"])
```

生产环境应为轮询设置总超时，并对 `429` 和临时 `5xx` 使用指数退避。网络超时不等于生成失败，可以使用同一个 `task_id` 继续查询。

## 批量查询

指定多个任务 ID：

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve_batch",
    "ids": ["TASK_ID_1", "TASK_ID_2"],
    "offset": 0,
    "limit": 20
  }'
```

按时间范围分页列出任务：

```json
{
  "action": "retrieve_batch",
  "created_at_min": 1786000000,
  "created_at_max": 1786200000,
  "offset": 0,
  "limit": 20
}
```

批量响应中的 `items` 使用与单任务查询相同的 task 字段，`total` 是筛选条件匹配的任务总数：

```json
{
  "items": [
    {
      "id": "TASK_ID_1",
      "model": "MiniMax-H3",
      "status": "running",
      "resolution": "2K",
      "duration": 5,
      "ratio": "adaptive",
      "task_type": "generation",
      "modality": "video"
    }
  ],
  "total": 1
}
```

任务查询窗口为最近 7 天。超过该窗口的 `task_id` 可能返回无效任务；业务系统应在创建任务时保存 ID，并在成功后及时持久化结果 URL。

## 取消或删除任务

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "delete",
    "id": "YOUR_TASK_ID"
  }'
```

动作取决于任务当前状态：

| 当前状态        | 行为            |
| ----------- | ------------- |
| `queued`    | 取消尚未开始的任务     |
| `succeeded` | 删除任务记录        |
| `failed`    | 删除任务记录        |
| `running`   | 不允许删除或取消，返回错误 |
| `cancelled` | 不允许重复操作，返回错误  |

删除成功示例：

```json
{
  "id": "YOUR_TASK_ID",
  "deleted": true
}
```

删除任务记录不会撤销已经完成的计费，也不能保证已保存的视频副本同时被删除。

## 失败响应与排查

失败任务仍以 HTTP 200 返回 task 对象，并在 `task.error` 中给出原因：

```json
{
  "task": {
    "id": "YOUR_TASK_ID",
    "model": "MiniMax-H3",
    "status": "failed",
    "error": {
      "code": "1026",
      "message": "video description contains sensitive content"
    },
    "task_type": "generation",
    "modality": "video"
  }
}
```

接口本身返回 `400` 时应检查 `action` 与条件参数，`401` 表示 Token 无效，`429` 表示查询过于频繁，`500` 表示服务暂时不可用。生成失败的任务不计费；成功任务按最终 `usage` 记录用量。


عرض المهام حسب نطاق زمني مع التصفح:

```json
{

  "limit": 20
```

في الاستجابة الجماعية، يستخدم حقل `items` نفس حقل المهمة في الاستعلام الفردي، و `total` هو عدد المهام المطابقة للفلترة:

```json
{
  "items": [
    {
      "id": "TASK_ID_1",

      "status": "running",
      "resolution": "2K",

      "ratio": "adaptive",
```

نافذة استعلام المهام هي آخر 7 أيام. قد تعود معرفات المهام خارج هذه النافذة بمهام غير صالحة؛ يجب على النظام التجاري حفظ المعرف عند الإنشاء وتخزين رابط النتيجة عند النجاح.

## إلغاء أو حذف المهام

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "delete",
    "id": "YOUR_TASK_ID"
  }'
```

الإجراء يعتمد على حالة المهمة الحالية:

| الحالة الحالية    | السلوك               |
| -------------- | ------------------ |
| `queued`       | إلغاء المهمة التي لم تبدأ بعد |
| `succeeded`    | حذف سجل المهمة         |
| `failed`       | حذف سجل المهمة         |
| `running`      | لا يسمح بالحذف أو الإلغاء، يعيد خطأ |
| `cancelled`    | لا يسمح بالتكرار، يعيد خطأ  |

مثال على حذف ناجح:

```json
{
  "id": "YOUR_TASK_ID",
  "deleted": true
}
```

حذف سجل المهمة لا يلغي الفوترة التي تمت، ولا يضمن حذف نسخ الفيديو المحفوظة.

## استجابات الفشل والتحقق

المهام الفاشلة تعود مع كائن المهمة HTTP 200، مع سبب الخطأ في `task.error`:

```json
{
  "task": {
    "id": "YOUR_TASK_ID",
    "model": "MiniMax-H3",
    "status": "failed",
    "error": {
      "code": "1026",
      "message": "video description contains sensitive content"
    },
    "task_type": "generation",
    "modality": "video"
  }
}
```

عند عودة `400` من الواجهة، يجب التحقق من `action` والمعايير، `401` تعني أن الـ Token غير صالح، `429` تعني استعلام متكرر جداً، و `500` تعني أن الخدمة غير متاحة مؤقتاً. المهام الفاشلة لا تُحتسب في الفوترة؛ المهام الناجحة تُسجل حسب الاستخدام النهائي `usage`.
