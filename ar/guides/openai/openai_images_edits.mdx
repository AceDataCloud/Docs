OpenAI خدمة تعديل الصور، يمكن إدخال صورة وتعليمات، وإخراج الصورة المعدلة. يمكن لنموذج GPT Image سلسلة أن يستقبل ما يصل إلى 16 صورة مرجعية في نفس الوقت. حاليًا، تدعم الواجهة كل من `gpt-image-1`، وأحدث **`gpt-image-2`**، بالإضافة إلى نماذج سلسلة **`nano-banana` / `nano-banana-2-lite` / `nano-banana-2` / `nano-banana-pro`** المتصلة من خلال نفس الواجهة.

تتناول هذه الوثيقة بشكل رئيسي عملية استخدام OpenAI Images Edits API، مما يتيح لنا استخدام وظيفة تعديل الصور الرسمية من OpenAI بسهولة.

## 申请流程

لاستخدام OpenAI Images Edits API، يجب أولاً الذهاب إلى [لوحة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على رمز API الخاص بك، احتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد قمت بتسجيل الدخول أو التسجيل بعد، سيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك للتسجيل وتسجيل الدخول، وبعد الانتهاء، سيتم إرجاعك تلقائيًا إلى الصفحة الحالية.

**رمز API واحد يكفي لاستدعاء جميع خدمات المنصة، ولا حاجة لتقديم طلب منفصل لكل خدمة.** عند التقديم لأول مرة، ستحصل على رصيد مجاني لتجربته؛ عند نفاد الرصيد، يمكنك إعادة شحن الرصيد العام في [لوحة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثيقة الكاملة: [OpenAI Images Edits API →](https://platform.acedata.cloud/documents/openai-images-edits)

## نموذج GPT-Image-2

`gpt-image-2` في سيناريو تعديل الصور يظهر تحسينات ملحوظة مقارنة بـ `gpt-image-1`:

- **الحفاظ على الهيكل أكثر استقرارًا**: عند تغيير الجلد، أو الألوان، أو الخلفية، لن تتضرر تخطيط الصورة الأصلية تقريبًا.
- **احتفاظ النص بدقة أكبر**: تبقى النصوص في الصور مثل المعلومات الرسومية، والملصقات، والقوائم واضحة وقابلة للقراءة بعد التعديل.
- **دعم نقل URL مباشرة**: بالإضافة إلى تحميل الملفات التقليدي `multipart/form-data`، يدعم `gpt-image-2` أيضًا **نقل URL الصورة بطريقة JSON**، دون الحاجة لتحميل الصورة إلى الجهاز أولاً، مما يجعله مناسبًا تمامًا للاتصال بخطوط الخدمة.
- **دعم نقل base64 مباشرة**: مثل الرسمي، يمكن أيضًا تمرير حقل `image` مباشرة كـ base64 (`data:image/png;base64,...` أو base64 عاري)، دون الحاجة لتحميل الصورة المحلية إلى موقع تخزين الصور قبل التعديل.
- **دعم إعادة رسم بدقة عالية**: يمكن إدخال صورة أصلية بدقة 1K، وطلب إخراج 2K / 4K من خلال معلمة `size`، وسيقوم النموذج بإكمال التكبير أثناء عملية التعديل.

### خطوط المتغيرات (`:official` / `:reverse`)

`gpt-image-2` يسير بشكل افتراضي عبر الخط القياسي. يمكن اختيار الخط بشكل صريح من خلال لاحقة اسم النموذج:

- **`gpt-image-2:official`**: قناة رسمية، مستقرة ومتوافقة. تدعم دقة حقيقية 2K / 4K، **تُحسب الرسوم لكل صورة، والسعر هو ضعف السعر الافتراضي لـ `gpt-image-2`**. عند عدم توفر الخط، سيتم إرجاع خطأ مباشرة، ولن يتم التراجع تلقائيًا.
- **`gpt-image-2:reverse`**: يعادل تمامًا `gpt-image-2` الافتراضي، مع قيمة أفضل، والسعر يبقى كما هو.

### القيم المدعومة لـ `size`

يتوافق التحقق من تنسيق `size` في واجهة التعديل مع واجهة الإخراج - يحتاج `gpt-image-2` فقط إلى أن يكون `size` إما `auto`، أو فارغ، أو يتوافق مع تنسيق `WIDTHxHEIGHT`، أي شكل آخر سيعيد 400. **تُخصم جميع الأحجام (1K / 2K / 4K / مخصص) بشكل موحد لكل صورة، ولا تتعلق بدقة الصورة الأصلية أو قيمة طلب `size`.**

قيود الحجم: يجب أن تلبي الأحجام المخصصة أن تكون الأبعاد مضاعفات 16، وألا يتجاوز الطول 3840، وإجمالي عدد البكسلات ≤ 8,294,400، وإذا تجاوزت ذلك، ستعيد 4xx.

| النسبة   | 1K موصى به       | 2K موصى به       | 4K موصى به       |
| ---- | ----------- | ----------- | ----------- |
| 1:1  | `1024x1024` | `2048x2048` | `2880x2880` |
| 4:3  | `1536x1024` | `2048x1536` | `3264x2448` |
| 3:4  | `1024x1536` | `1536x2048` | `2448x3264` |
| 16:9 | `1792x1024` | `2048x1152` | `3840x2160` |
| 9:16 | `1024x1792` | `1152x2048` | `2160x3840` |

> على سبيل المثال: إذا كانت الصورة الأصلية `1024x1024`، وتم تمرير `size` كـ `2048x2048`، سيقوم النموذج بإعادة رسم الصورة وإخراج صورة 2K؛ إذا تم تمرير `size` كـ `3840x2160`، سيتم إخراج صورة 4K أفقية. الرسوم الثلاثة متساوية.
> عند تمرير `auto` (أو ترك `size` فارغًا)، سيكون الإخراج **مستندًا إلى نسبة العرض إلى الارتفاع للصورة المرجعية** - في المثال السابق، إذا كانت الصورة الأصلية 1:1، فسيتم الحصول على نتيجة 1:1، ولن يتم ضغطها إلى نسبة عرض أخرى. هذه النقطة تختلف عن واجهة الإخراج: لا تحتوي واجهة الإخراج على صورة مرجعية، و`auto` يتم تحديده بناءً على دلالة النص. إذا كنت ترغب في تغيير نسبة العرض، يجب تحديد `size` بشكل صريح.

> **حول معلمة `n`**
> تدعم واجهة تعديل `gpt-image-2` `n > 1`: يمكن أن تعيد الطلب الواحد عددًا من نتائج التعديل المقابلة (تتراوح قيم `n` من 1 إلى 10). ينطبق ذلك أيضًا على `gpt-image-1` / `gpt-image-1.5`، وكذلك سلسلة `nano-banana` / `nano-banana-2-lite` / `nano-banana-2` / `nano-banana-pro`. لاحظ أن `response_format=b64_json` يدعم فقط `n=1`، وعند استخدام `n>1`، يرجى استخدام الإرجاع الافتراضي URL. إذا فشلت بعض الصور في التوليد، سيتم إرجاع فقط الأجزاء الناجحة واحتساب الرسوم لها.

فيما يلي مثالان حقيقيان من زوايا مختلفة لتجربة قدرة تعديل `gpt-image-2`.

### طريقة الاستدعاء الأولى: JSON + URL الصورة (موصى به)

أرسل الطلب مباشرة بطريقة `application/json`، مع ملء حقل `image` برابط صورة واحدة، سيقوم النموذج بجلب تلك الصورة وتعديلها وفقًا لـ `prompt`.

على سبيل المثال، الصورة الأصلية أدناه تم إنشاؤها باستخدام `gpt-image-2` كصورة توضيحية علمية:

<p><img src="https://platform.cdn.acedata.cloud/gpt-image/5c9fa635-8794-4c6d-88f8-584d7f4716c6_0.png" width="500" className="m-auto" /></p>

نرغب في تغييرها إلى ألوان "وضع الليل". يمكننا استدعاءها بهذه الطريقة:
```shell
curl -X POST "https://api.acedata.cloud/openai/images/edits" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://platform.cdn.acedata.cloud/gpt-image/5c9fa635-8794-4c6d-88f8-584d7f4716c6_0.png",
    "prompt": "قم بتحويل هذه المعلومات الرسومية إلى وضع الظلام: خلفية بحرية داكنة، نص كريمي فاتح، بطاقات وحدات رمادية داكنة مستديرة مع ظلال ناعمة. احتفظ بجميع التخطيطات والهياكل وترتيب الوحدات كما هو — فقط عكس نظام الألوان.",
    "size": "1024x1536"
  }'
```

أو باستخدام بايثون:

```python
import requests

url = "https://api.acedata.cloud/openai/images/edits"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-image-2",
    "image": "https://platform.cdn.acedata.cloud/gpt-image/5c9fa635-8794-4c6d-88f8-584d7f4716c6_0.png",
    "prompt": "قم بتحويل هذه المعلومات الرسومية إلى وضع الظلام: خلفية بحرية داكنة، نص كريمي فاتح، بطاقات وحدات رمادية داكنة مستديرة مع ظلال ناعمة. احتفظ بجميع التخطيطات والهياكل وترتيب الوحدات كما هو — فقط عكس نظام الألوان.",
    "size": "1024x1536"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

يمكنك رؤية أن هيكل الوحدات، تقسيم المعلومات، وتنسيق الخطوط قد تم الاحتفاظ بها بدقة، فقط تم عكس الألوان إلى موضوع داكن.

> **تلميح**: حقل `image` يدعم أيضًا تمرير مصفوفة، مثل `"image": ["url1", "url2", "url3"]`، يمكن تمرير ما يصل إلى 16 صورة مرجعية في وقت واحد، مما يسمح للنموذج بالرجوع إلى صور متعددة لإجراء التعديلات.

> }
> requests.post("https://api.acedata.cloud/openai/images/edits", json=payload,
>               headers={"authorization": "Bearer {token}"})
> ```

### طريقة الاستدعاء الثالثة: multipart/form-data (متوافق مع OpenAI SDK)

إذا كنت تستخدم بالفعل OpenAI Python SDK، فإن طريقة التحميل الأصلية `multipart/form-data` لا تزال قابلة للتطبيق، فقط قم بتغيير `model` إلى `gpt-image-2`:

```python
import base64
from openai import OpenAI
client = OpenAI()

result = client.images.edit(
    model="gpt-image-2",
    image=[open("test.png", "rb")],
    prompt="قم بتحويل هذه الصورة إلى وضع الظلام مع الحفاظ على التخطيط كما هو."
)

image_base64 = result.data[0].b64_json
image_bytes = base64.b64decode(image_base64)
with open("edited.png", "wb") as f:
    f.write(image_bytes)
```

عند استخدام SDK، تحتاج إلى استيراد متغيرين بيئيين، `OPENAI_BASE_URL` يجب أن يكون `https://api.acedata.cloud/openai`، و`OPENAI_API_KEY` يجب أن يكون هو الرمز المميز الذي حصلت عليه:

```shell
export OPENAI_BASE_URL=https://api.acedata.cloud/openai
export OPENAI_API_KEY={token}
```

## سلسلة نماذج Nano Banana

سلسلة `nano-banana` قد دمجت أيضًا في سيناريوهات التحرير عبر `/openai/images/edits`، فقط قم بتغيير `model` إلى أي من النماذج في الجدول أدناه.
| النموذج                | التكلفة (Credits / مرة) | السيناريوهات المناسبة                     |
| -------------------- | --------------- | --------------------------------- |
| `nano-banana`        | 0.14            | تحرير الصور العادية، الأسرع والأقل تكلفة               |
| `nano-banana-2-lite` | 0.14            | نموذج صور خفيف Gemini 3.1، يدعم فقط 1K، تحرير منخفض التأخير |
| `nano-banana-2`      | 0.28            | تحسين ملحوظ في الجودة والتفاصيل                      |
| `nano-banana-pro`    | 0.35            | الرائد في السلسلة، يحتفظ بأفضل هيكل ونص وأسلوب            |

> **مهم: نطاق دعم المعلمات**
> يتصل Nano Banana عبر طبقة التكيف ببروتوكول OpenAI، ويدعم فقط المعلمات التالية: `model`، `prompt`، `image`، `n`.
> - يمكن رفع `image` إما عبر `multipart/form-data` (سيتم تحويل الملفات المحلية تلقائيًا إلى base64)، أو عبر حقل النموذج مباشرةً كـ URL للصورة.
> - لا تدعم المعلمات مثل `mask`، `size`، `response_format`؛ إذا تم ملؤها، سيتم تجاهلها. `n > 1` مدعوم (1–10)، وسيتم إرجاع نتائج التحرير المقابلة مع احتساب التكلفة حسب العدد.
> - تتبع بنية الإرجاع تنسيق OpenAI (`data[].url`)، لكن `created` ثابت عند `0`، ولن يتم إرجاع `b64_json`، و`revised_prompt` دائمًا يساوي `prompt` الأصلي.

### استدعاء عبر النموذج + URL الصورة

```shell
curl -X POST "https://api.acedata.cloud/openai/images/edits" \
  -H "Authorization: Bearer {token}" \
  -F "model=nano-banana" \
  -F "prompt=add a green leaf on top of the apple" \
  -F "image=https://platform.cdn.acedata.cloud/nanobanana/6870b330-65c4-436c-bb80-819fdae7a7a4.png"
```

```json
  "data": [
    {
      "url": "https://platform.cdn.acedata.cloud/nanobanana/311e95b6-5eb1-4c4a-8ee6-0cb03ee44f61.jpeg",
      "revised_prompt": "add a green leaf on top of the apple"
    }
  ]
}
```

### استدعاء عبر النموذج + ملف محلي

```python
import requests

url = "https://api.acedata.cloud/openai/images/edits"

headers = {
    "authorization": "Bearer {token}"
}

files = {
    "image": open("apple.png", "rb"),
}
data = {
    "model": "nano-banana-pro",
    "prompt": "add a green leaf on top of the apple"
}

response = requests.post(url, headers=headers, files=files, data=data)
print(response.text)
```

## الاستخدام الأساسي

يمكنك الآن استخدام الكود للاستدعاء، فيما يلي استدعاء عبر CURL:

```curl
curl -s -D >(grep -i x-request-id >&2) \
  -o >(jq -r '.data[0].b64_json' | base64 --decode > gift-basket.png) \
  -X POST "https://api.acedata.cloud/v1/images/edits" \
  -H "Authorization: Bearer {token}" \
  -F "model=gpt-image-1" \
  -F "image[]=@test.png" \
  -F 'prompt=Create a lovely gift basket with these this items in it'
```

عند استخدام هذه الواجهة لأول مرة، نحتاج على الأقل إلى ملء أربعة محتويات، أحدها هو `authorization`، يمكن اختيارها مباشرة من القائمة المنسدلة. المعلمة الأخرى هي `model`، حيث أن `model` هو نوع النموذج الذي نختار استخدامه من موقع OpenAI، هنا لدينا نموذج واحد رئيسي، يمكن الاطلاع على التفاصيل في النماذج المقدمة. المعلمة الأخرى هي `prompt`، حيث أن `prompt` هو النص الذي ندخله لتوليد الصورة. وأخيرًا، المعلمة `image`، وهي مسار الصورة التي نحتاج إلى تحريرها، كما هو موضح في الصورة أدناه:

> **تلميح**: يمكن أن تظهر `image[]` عدة مرات لتحميل صور مرجعية متعددة، مثل `-F "image[]=@a.png" -F "image[]=@b.png"`، تدعم نماذج سلسلة GPT Image ما يصل إلى 16 صورة (كل صورة لا تتجاوز 50MB، بصيغة png/webp/jpg). إذا تم تجاوز العدد، سيتم إرجاع 400.

<p><img src="https://cdn.acedata.cloud/jw9iwu.png" width="500" className="m-auto" /></p>

مثال على كود استدعاء Python بنفس التأثير:

```python
import base64
from openai import OpenAI
client = OpenAI()

prompt = """
Generate a photorealistic image of a gift basket on a white background 
labeled 'Relax & Unwind' with a ribbon and handwriting-like font, 
containing all the items in the reference pictures.
"""

result = client.images.edit(
    model="gpt-image-1",
    image=[
        open("test.png", "rb")
    ],
    prompt=prompt
)

image_base64 = result.data[0].b64_json
image_bytes = base64.b64decode(image_base64)

# Save the image to a file
with open("gift-basket.png", "wb") as f:
    f.write(image_bytes)
```

لاستخدام Python، نحتاج أولاً إلى استيراد متغيرين بيئيين، أحدهما `OPENAI_BASE_URL`، يمكن تعيينه إلى `https://api.acedata.cloud/openai`، والآخر هو متغير الاعتماد `OPENAI_API_KEY`، هذه القيمة يتم الحصول عليها من `authorization`، في نظام Mac OS يمكن تعيين المتغيرات البيئية باستخدام الأوامر التالية:

```shell
export OPENAI_BASE_URL=https://api.acedata.cloud/openai
export OPENAI_API_KEY={token} 
```

بعد الاستدعاء، سنجد أنه تم إنشاء صورة في الدليل الحالي باسم `gift-basket.png`، والنتيجة كما يلي:

<p><img src="https://cdn.acedata.cloud/574s8h.png" width="500" className="m-auto" /></p>

بهذا نكون قد أكملنا عملية تحرير الصورة، حاليًا تدعم واجهة Edits نموذجين هما `gpt-image-1` و `gpt-image-2`، حيث أن `gpt-image-2` هو النموذج الموصى به حاليًا، انظر القسم السابق [نموذج GPT-Image-2](#gpt-image-2-模型).

## ردود غير متزامنة

نظرًا لأن وقت تحرير الصور عبر OpenAI Images Edits API قد يكون طويلًا نسبيًا، إذا لم يكن هناك استجابة لفترة طويلة، ستظل طلبات HTTP متصلة، مما يؤدي إلى استهلاك موارد النظام الإضافية، لذا توفر هذه الواجهة أيضًا دعمًا للردود غير المتزامنة.

تتضمن العملية العامة: عند بدء العميل الطلب، يتم تحديد حقل `callback_url` إضافي، بعد أن يقوم العميل بإرسال طلب API، ستقوم الواجهة بإرجاع نتيجة على الفور، تحتوي على معلومات حقل `task_id`، الذي يمثل معرف المهمة الحالية. عند اكتمال المهمة، سيتم إرسال نتيجة تحرير الصورة إلى `callback_url` المحدد من قبل العميل بصيغة JSON POST، والتي تتضمن أيضًا حقل `task_id`، بحيث يمكن ربط نتيجة المهمة عبر المعرف. 

دعونا نفهم كيفية القيام بذلك من خلال مثال.
首先，Webhook 回调是一个可以接收 HTTP 请求的服务，开发者应该替换为自己搭建的 HTTP 服务器的 URL。此处为了方便演示，使用一个公开的 Webhook 样例网站 https://webhook.site/，打开该网站即可得到一个 Webhook URL，如图所示：

![](https://cdn.acedata.cloud/cjjfly.png)

将此 URL 复制下来，就可以作为 Webhook 来使用，此处的样例为 `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`。

接下来，我们可以设置字段 `callback_url` 为上述 Webhook URL，同时填入相应的参数，如以下代码所示：

```shell
curl -X POST "https://api.acedata.cloud/v1/images/edits" \
  -H "Authorization: Bearer {token}" \
  -F "model=gpt-image-1" \
  -F "image[]=@test.png" \
  -F "prompt=Create a lovely gift basket with these items in it" \
  -F "callback_url=https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab"
```

调用之后，可以发现会立即得到一个结果，如下：

```json
{
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c"
}
```

稍等片刻，我们可以在 Webhook URL 上观察到编辑图片的结果，内容如下：

```json
{
  "success": true,
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c",
  "trace_id": "9b4b1ff3-90f2-470f-b082-1061ec2948cc",
  "data": {
    "created": 1721626477,
    "data": [
      {
        "b64_json": "iVBORw0KGgo..."
      }
    ]
  }
}
```

可以看到结果中有一个 `task_id` 字段，`data` 字段包含了和同步调用一样的图片编辑结果，通过 `task_id` 字段即可实现任务的关联。

## 错误处理

在调用 API 时，如果遇到错误，API 会返回相应的错误代码和信息。例如：

- `400 token_mismatched`：请求错误，可能是由于缺少或无效的参数。
- `400 api_not_implemented`：请求错误，可能是由于缺少或无效的参数。
- `401 invalid_token`：未授权，授权令牌无效或缺失。
- `429 too_many_requests`：请求过多，您已超出速率限制。
- `500 api_error`：内部服务器错误，服务器出现问题。

### 错误响应示例

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
