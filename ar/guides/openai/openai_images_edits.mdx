OpenAI خدمة تحرير الصور، يمكن إدخال أي عدد من الصور والتعليمات، وإخراج الصور المعدلة. حاليًا، يدعم الواجهة كل من `gpt-image-1`، وأحدث **`gpt-image-2`**، بالإضافة إلى نماذج سلسلة **`nano-banana` / `nano-banana-2-lite` / `nano-banana-2` / `nano-banana-pro`** المتصلة من خلال نفس الواجهة.

تتناول هذه الوثيقة بشكل رئيسي عملية استخدام OpenAI Images Edits API، مما يتيح لنا استخدام وظيفة تحرير الصور الرسمية من OpenAI بسهولة.

## 申请流程

لاستخدام OpenAI Images Edits API، يجب أولاً الذهاب إلى [لوحة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على رمز API الخاص بك، احتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

إذا لم تكن قد قمت بتسجيل الدخول أو التسجيل بعد، سيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك للتسجيل وتسجيل الدخول، وبعد الانتهاء، سيتم إرجاعك تلقائيًا إلى الصفحة الحالية.

**رمز API واحد يكفي لاستدعاء جميع خدمات المنصة، ولا حاجة لتقديم طلب منفصل لكل خدمة.** عند التقديم لأول مرة، ستحصل على رصيد مجاني لتجربته؛ وعند نفاد الرصيد، يمكنك إعادة شحن الرصيد العام في [لوحة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثيقة الكاملة: [OpenAI Images Edits API →](https://platform.acedata.cloud/documents/openai-images-edits)

## نموذج GPT-Image-2

`gpt-image-2` في سيناريو تحرير الصور يقدم تحسينات ملحوظة مقارنة بـ `gpt-image-1`:

- **الحفاظ على الهيكل أكثر استقرارًا**: عند تغيير الجلد، أو الألوان، أو الخلفية، لن تتضرر تخطيط الصورة الأصلية تقريبًا.
- **احتفاظ النص بدقة أكبر**: تبقى النصوص في الصور مثل المعلومات الرسومية، والملصقات، والقوائم واضحة وقابلة للقراءة بعد التحرير.
- **دعم نقل URL مباشرة**: بالإضافة إلى تحميل الملفات التقليدي `multipart/form-data`، يدعم `gpt-image-2` أيضًا **نقل URL الصورة بطريقة JSON**، دون الحاجة لتحميل الصورة إلى الجهاز المحلي، مما يجعله مناسبًا تمامًا للاتصال بخطوط الخدمة.
- **دعم نقل base64 مباشرة**: مثل الرسمي، يمكن أيضًا تمرير حقل `image` مباشرة كـ base64 (`data:image/png;base64,...` أو base64 عاري)، دون الحاجة لتحميل الصورة المحلية إلى موقع تخزين الصور قبل التحرير.
- **دعم إعادة رسم بدقة عالية**: يمكن إدخال صورة بدقة 1K، وطلب إخراج 2K / 4K من خلال معلمة `size`، وسيقوم النموذج بإكمال التكبير أثناء عملية التحرير.

### متغيرات الخط (`:official` / `:reverse`)

`gpt-image-2` يسير بشكل افتراضي عبر الخط القياسي. يمكن اختيار الخط بشكل صريح من خلال لاحقة اسم النموذج:

- **`gpt-image-2:official`**: قناة رسمية، مستقرة ومتوافقة. تدعم دقة حقيقية 2K / 4K، **تُحسب الرسوم لكل صورة، والسعر هو ضعف السعر الافتراضي لـ `gpt-image-2`**. عند عدم توفر الخط، سيتم إرجاع خطأ مباشرة، ولن يتم التراجع تلقائيًا.
- **`gpt-image-2:reverse`**: يعادل تمامًا `gpt-image-2` الافتراضي، مع قيمة أفضل، والسعر يبقى كما هو.

### القيم المدعومة لـ `size`

تتطابق قيود واجهة التحرير على `size` تمامًا مع واجهة التوليد - يحتاج `gpt-image-2` فقط إلى أن يكون `size` إما `auto`، أو فارغ، أو يتوافق مع تنسيق `WIDTHxHEIGHT`، أي شكل آخر سيعيد 400. **تُخصم جميع الأحجام (1K / 2K / 4K / مخصص) بشكل موحد لكل صورة، ولا تتعلق بدقة الصورة الأصلية أو قيمة طلب `size`.**

قيود الحجم: يجب أن تلبي الأحجام المخصصة أن تكون الأبعاد مضاعفات 16، وألا يتجاوز الطول 3840، وإجمالي عدد البكسلات ≤ 8,294,400، وإذا تجاوزت، ستعيد 4xx.

| النسبة   | 1K موصى به       | 2K موصى به       | 4K موصى به       |
| ---- | ----------- | ----------- | ----------- |
| 1:1  | `1024x1024` | `2048x2048` | `2880x2880` |
| 4:3  | `1536x1024` | `2048x1536` | `3264x2448` |
| 3:4  | `1024x1536` | `1536x2048` | `2448x3264` |
| 16:9 | `1792x1024` | `2048x1152` | `3840x2160` |
| 9:16 | `1024x1792` | `1152x2048` | `2160x3840` |

> على سبيل المثال: إذا كانت الصورة الأصلية `1024x1024`، وتم تمرير `size` كـ `2048x2048`، سيقوم النموذج بإعادة رسم الصورة وفقًا لتعليمات التحرير وإخراج صورة بدقة 2K؛ إذا تم تمرير `size` كـ `3840x2160`، سيتم إخراج صورة بدقة 4K أفقية؛ إذا تم تمرير `auto` أو تم إغفاله، سيختار النموذج بنفسه. الثلاثة تُحسب بنفس الطريقة.

> **حول معلمة `n`**
> تدعم واجهة تحرير `gpt-image-2` `n > 1`: يمكن أن تعيد الطلب الواحد عددًا من نتائج التحرير المقابلة (قيمة `n` من 1 إلى 10). ينطبق ذلك أيضًا على `gpt-image-1` / `gpt-image-1.5`، وكذلك سلسلة `nano-banana` / `nano-banana-2-lite` / `nano-banana-2` / `nano-banana-pro`. لاحظ أن `response_format=b64_json` يدعم فقط `n=1`، وعند `n>1`، يرجى استخدام الإرجاع الافتراضي URL. إذا فشلت بعض الصور في التوليد، سيتم إرجاع فقط الأجزاء الناجحة واحتساب الرسوم لها.

فيما يلي مثالان حقيقيان من زوايا مختلفة لتجربة قدرة تحرير `gpt-image-2`.

### طريقة الاستدعاء الأولى: JSON + URL الصورة (موصى به)

أرسل الطلب مباشرة بطريقة `application/json`، مع ملء حقل `image` برابط صورة واحدة، سيقوم النموذج بجلب تلك الصورة وتحريرها وفقًا لـ `prompt`.

على سبيل المثال، الصورة الأصلية أدناه تم إنشاؤها باستخدام `gpt-image-2` كصورة توضيحية علمية:

<p><img src="https://platform.cdn.acedata.cloud/gpt-image/5c9fa635-8794-4c6d-88f8-584d7f4716c6_0.png" width="500" className="m-auto" /></p>

نرغب في تغييرها إلى ألوان "وضع الليل". يمكننا استدعاءها بهذه الطريقة:

```shell
curl -X POST "https://api.acedata.cloud/openai/images/edits" \
  -H "Authorization: Bearer {token}" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://platform.cdn.acedata.cloud/gpt-image/5c9fa635-8794-4c6d-88f8-584d7f4716c6_0.png",
    "prompt": "Convert this infographic to dark mode: dark navy background, light cream text, deep gray rounded module cards with soft shadows. Keep all layout, structure, and module arrangement identical — only invert the color scheme.",
    "size": "1024x1536"
  }'
```

أو باستخدام Python:
```python
import requests

url = "https://api.acedata.cloud/openai/images/edits"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-image-2",
    "image": "https://platform.cdn.acedata.cloud/gpt-image/5c9fa635-8794-4c6d-88f8-584d7f4716c6_0.png",
    "prompt": "حوّل هذه المعلومات الرسومية إلى وضع الظلام: خلفية بحرية داكنة، نص كريمي فاتح، بطاقات وحدات رمادية داكنة مستديرة مع ظلال ناعمة. احتفظ بجميع التخطيطات والهياكل وترتيب الوحدات كما هو — فقط عكس نظام الألوان.",
    "size": "1024x1536"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

>               headers={"authorization": "Bearer {token}"})
> ```

### طريقة الاستدعاء الثالثة: multipart/form-data (متوافق مع OpenAI SDK)

إذا كنت تستخدم بالفعل OpenAI Python SDK، فإن طريقة التحميل الأصلية `multipart/form-data` لا تزال قابلة للتطبيق، فقط قم بتغيير `model` إلى `gpt-image-2`:

```python
import base64
from openai import OpenAI
client = OpenAI()

result = client.images.edit(
    model="gpt-image-2",
    image=[open("test.png", "rb")],
    prompt="حوّل هذه الصورة إلى وضع الظلام مع الحفاظ على التخطيط كما هو."
)

image_base64 = result.data[0].b64_json
image_bytes = base64.b64decode(image_base64)
with open("edited.png", "wb") as f:
    f.write(image_bytes)
```

عند استخدام SDK، تحتاج إلى استيراد متغيرين بيئيين، `OPENAI_BASE_URL` يجب أن يكون `https://api.acedata.cloud/openai`، و`OPENAI_API_KEY` يجب أن يكون هو الرمز المميز الذي حصلت عليه:

```shell
export OPENAI_BASE_URL=https://api.acedata.cloud/openai
export OPENAI_API_KEY={token}
```

## سلسلة نماذج Nano Banana

سلسلة `nano-banana` قد تم دمجها أيضًا في سيناريوهات التحرير عبر `/openai/images/edits`، فقط قم بتغيير `model` إلى أي من النماذج في الجدول أدناه.

| النموذج                   | التكلفة (Credits / مرة) | السيناريوهات المناسبة                           |
| -------------------- | --------------- | ------------------------------ |
| `nano-banana`        | 0.14            | تحرير الصور العادية، الأسرع والأقل تكلفة               |
| `nano-banana-2-lite` | 0.14            | نموذج صور خفيف Gemini 3.1، يدعم فقط 1K، تحرير منخفض التأخير |
| `nano-banana-2`      | 0.28            | تحسين ملحوظ في الجودة والتفاصيل                      |
| `nano-banana-pro`    | 0.35            | الرائد في السلسلة، يحتفظ بأفضل هيكل ونص ونمط            |
> **مهم: نطاق دعم المعلمات**
> Nano Banana يتصل ببروتوكول OpenAI من خلال طبقة التكيف، ويدعم فقط المعلمات التالية: `model`، `prompt`، `image`، `n`.
> - يمكن رفع `image` إما من خلال `multipart/form-data` (سيتم تحويل الملفات المحلية تلقائيًا إلى base64)، أو يمكن تمرير سلسلة URL الصورة مباشرة من خلال حقل النموذج.
> - لا تدعم المعلمات مثل `mask`، `size`، `response_format`؛ إذا تم ملؤها، سيتم تجاهلها. `n > 1` مدعوم (1–10)، وسيتم إرجاع نتائج التحرير المقابلة للعدد المفوتر.
> - تتبع بنية الإرجاع تنسيق OpenAI (`data[].url`)، لكن `created` ثابت عند `0`، ولن يتم إرجاع `b64_json`، و`revised_prompt` دائمًا يساوي `prompt` الأصلي.

### استدعاء عبر النموذج + URL الصورة

```shell
curl -X POST "https://api.acedata.cloud/openai/images/edits" \
  -H "Authorization: Bearer {token}" \
  -F "model=nano-banana" \
  -F "prompt=add a green leaf on top of the apple" \
  -F "image=https://platform.cdn.acedata.cloud/nanobanana/6870b330-65c4-436c-bb80-819fdae7a7a4.png"
```

نتيجة الإرجاع كما يلي:

```json
{
  "created": 0,
  "data": [
    {
      "url": "https://platform.cdn.acedata.cloud/nanobanana/311e95b6-5eb1-4c4a-8ee6-0cb03ee44f61.jpeg",
      "revised_prompt": "add a green leaf on top of the apple"
    }
  ]
}
```

### استدعاء عبر النموذج + ملف محلي

```python
import requests

url = "https://api.acedata.cloud/openai/images/edits"

headers = {
    "authorization": "Bearer {token}"
}

files = {
    "image": open("apple.png", "rb"),
}
data = {
    "model": "nano-banana-pro",
    "prompt": "add a green leaf on top of the apple"
}

response = requests.post(url, headers=headers, files=files, data=data)
print(response.text)
```

## الاستخدام الأساسي

يمكنك الآن استخدام الكود لإجراء الاستدعاء، فيما يلي استدعاء عبر CURL:

```curl
curl -s -D >(grep -i x-request-id >&2) \
  -o >(jq -r '.data[0].b64_json' | base64 --decode > gift-basket.png) \
  -X POST "https://api.acedata.cloud/v1/images/edits" \
  -H "Authorization: Bearer {token}" \
  -F "model=gpt-image-1" \
  -F "image[]=@test.png" \
  -F 'prompt=Create a lovely gift basket with these this items in it'
```

عند استخدام هذه الواجهة لأول مرة، نحتاج على الأقل إلى ملء أربعة محتويات، أحدها هو `authorization`، يمكن اختيارها مباشرة من القائمة المنسدلة. المعلمة الأخرى هي `model`، `model` هو نوع النموذج الذي نختار استخدامه من موقع OpenAI، هنا لدينا نموذج واحد رئيسي، يمكن الاطلاع على التفاصيل في النماذج المقدمة. المعلمة الأخرى هي `prompt`، `prompt` هو النص الذي ندخله لتوليد الصورة. وأخيرًا، المعلمة `image`، هذه المعلمة تحتاج إلى مسار الصورة التي نريد تحريرها، والصورة التي تحتاج إلى التحرير موضحة في الصورة أدناه:

<p><img src="https://cdn.acedata.cloud/jw9iwu.png" width="500" className="m-auto" /></p>

كود استدعاء Python بنفس تأثير الاستدعاء:

```python
import base64
from openai import OpenAI
client = OpenAI()

prompt = """
Generate a photorealistic image of a gift basket on a white background 
labeled 'Relax & Unwind' with a ribbon and handwriting-like font, 
containing all the items in the reference pictures.
"""

result = client.images.edit(
    model="gpt-image-1",
    image=[
        open("test.png", "rb")
    ],
    prompt=prompt
)

image_base64 = result.data[0].b64_json
image_bytes = base64.b64decode(image_base64)

# Save the image to a file
with open("gift-basket.png", "wb") as f:
    f.write(image_bytes)
```

لاستخدام Python، نحتاج أولاً إلى استيراد متغيرين بيئيين، أحدهما `OPENAI_BASE_URL`، يمكن تعيينه إلى `https://api.acedata.cloud/openai`، والآخر هو متغير الاعتماد `OPENAI_API_KEY`، هذه القيمة يتم الحصول عليها من `authorization`، في نظام Mac OS يمكن تعيين المتغيرات البيئية باستخدام الأوامر التالية:

```shell
export OPENAI_BASE_URL=https://api.acedata.cloud/openai
export OPENAI_API_KEY={token} 
```

بعد الاستدعاء، سنجد أنه تم إنشاء صورة في الدليل الحالي باسم `gift-basket.png`، والنتيجة المحددة كما يلي:

<p><img src="https://cdn.acedata.cloud/574s8h.png" width="500" className="m-auto" /></p>

بهذا نكون قد أكملنا عملية تحرير الصورة، حاليًا تدعم واجهة Edits نموذجين `gpt-image-1` و `gpt-image-2`، حيث أن `gpt-image-2` هو النموذج الموصى به حاليًا، انظر القسم أعلاه [نموذج GPT-Image-2](#نموذج-gpt-image-2).

## رد غير متزامن

نظرًا لأن واجهة OpenAI Images Edits API قد تستغرق وقتًا طويلاً لتحرير الصور، إذا لم يكن هناك استجابة لفترة طويلة، ستظل طلبات HTTP متصلة، مما يؤدي إلى استهلاك موارد النظام الإضافية، لذا توفر هذه الواجهة أيضًا دعمًا للرد غير المتزامن.

تتضمن العملية العامة: عندما يقوم العميل بإرسال الطلب، يحدد حقل `callback_url` إضافي، بعد أن يقوم العميل بإرسال طلب API، ستقوم الواجهة على الفور بإرجاع نتيجة تحتوي على معلومات حقل `task_id`، تمثل معرف المهمة الحالية. عند الانتهاء من المهمة، سيتم إرسال نتيجة تحرير الصورة إلى `callback_url` المحدد من قبل العميل عبر POST JSON، والتي تتضمن أيضًا حقل `task_id`، بحيث يمكن ربط نتيجة المهمة بواسطة المعرف.

دعونا نفهم كيفية القيام بذلك من خلال مثال.

أولاً، رد Webhook هو خدمة يمكنها استقبال طلبات HTTP، يجب على المطور استبدالها بعنوان URL الخاص بخادم HTTP الذي قام بإنشائه. هنا، لتسهيل العرض، نستخدم موقع Webhook عينة عام https://webhook.site/، افتح هذا الموقع للحصول على عنوان URL Webhook، كما هو موضح في الصورة:

![](https://cdn.acedata.cloud/cjjfly.png)

انسخ هذا URL، يمكنك استخدامه كـ Webhook، وعنوان العينة هنا هو `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`.

بعد ذلك، يمكننا تعيين حقل `callback_url` إلى عنوان URL Webhook المذكور أعلاه، مع ملء المعلمات المناسبة، كما هو موضح في الكود التالي:

```shell
curl -X POST "https://api.acedata.cloud/v1/images/edits" \
  -H "Authorization: Bearer {token}" \
  -F "model=gpt-image-1" \
  -F "image[]=@test.png" \
  -F "prompt=Create a lovely gift basket with these items in it" \
  -F "callback_url=https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab"
```

بعد الاستدعاء، يمكن ملاحظة أنه سيتم الحصول على نتيجة على الفور، كما يلي:
```json
{
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c"
}
```

稍等片刻，我们可以在 Webhook URL 上观察到编辑图片的结果，内容如下：

```json
{
  "success": true,
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c",
  "trace_id": "9b4b1ff3-90f2-470f-b082-1061ec2948cc",
  "data": {
    "created": 1721626477,
    "data": [
      {
        "b64_json": "iVBORw0KGgo..."
      }
    ]
  }
}
```

يمكن رؤية أن النتيجة تحتوي على حقل `task_id`، وحقل `data` يحتوي على نفس نتائج تحرير الصور كما في الاستدعاء المتزامن، من خلال حقل `task_id` يمكن تحقيق ارتباط المهام.

## معالجة الأخطاء

عند استدعاء واجهة برمجة التطبيقات، إذا واجهت خطأ، ستقوم واجهة برمجة التطبيقات بإرجاع رمز الخطأ والمعلومات المناسبة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صحيح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صحيح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح، رمز تفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جداً، لقد تجاوزت الحد الأقصى لمعدل الطلبات.
- `500 api_error`：خطأ في الخادم الداخلي، حدث خطأ ما في الخادم.

### مثال على استجابة الخطأ

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
