خدمة متجهات الكلمات من OpenAI، تُستخدم لإنشاء نتائج متجهات الكلمات التي تمثل النص المُدخل.

يقدم هذا المستند بشكل أساسي عملية استخدام واجهة OpenAI Embeddings API، وباستخدامها يمكننا إنشاء متجهات تضمين تمثل النص المُدخل。。

## عملية التقديم

لاستخدام واجهة OpenAI Embeddings API، انتقل أولاً إلى [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تقم بتسجيل الدخول أو التسجيل بعد، فسيتم تلقائيًا الانتقال إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائيًا إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** سيُمنح رصيد مجاني عند التقديم لأول مرة، ويمكنك التجربة مجانًا؛ وعندما يكون الرصيد غير كافٍ، يمكنك شحن الرصيد العام في [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 المستند الكامل: [OpenAI Embeddings API →](https://platform.acedata.cloud/documents/openai-embeddings)

## الاستخدام الأساسي

بعد ذلك، يمكنك ملء المحتوى المقابل في الواجهة، كما هو موضح في الصورة:

<p><img src="https://cdn.acedata.cloud/4qtbvr.png" width="500" className="m-auto" /></p>

عند استخدام هذه الواجهة لأول مرة، نحتاج إلى ملء ثلاثة محتويات على الأقل، أحدها هو `authorization`، ويمكنك اختياره مباشرةً من القائمة المنسدلة. المعلمة الأخرى هي `model`، و`model` هي فئة النموذج من الموقع الرسمي لـ OpenAI التي نختار استخدامها، والنماذج المتاحة حاليًا هي `text-embedding-3-small` و`text-embedding-3-large`. تم إيقاف توفير `text-embedding-ada-002`؛ وإذا كانت فهارس المتجهات الحالية تستخدم هذا النموذج القديم، فلا يمكن خلط متجهات النموذج الجديد مباشرةً، ويجب إعادة إنشاء الفهرس. المعلمة الأخيرة هي `input`، و`input` هو نص متجهات الكلمات الذي نحتاج إلى تحويله.

في الوقت نفسه، يمكنك ملاحظة وجود إنشاء لرمز الاستدعاء المقابل على الجانب الأيمن، ويمكنك نسخ الرمز وتشغيله مباشرةً، أو يمكنك النقر مباشرةً على زر «Try» للاختبار.

المعلمات الاختيارية:

- `dimensions`: اقتطاع أبعاد المتجه، ويكون الإخراج الافتراضي بالأبعاد الكاملة.
- `encoding_format`: تنسيق الإرجاع، ويمكن أن يكون `float` أو `base64`.

<p><img src="https://cdn.acedata.cloud/gqulm9.png" width="500" className="m-auto" /></p>

رمز استدعاء نموذجي بلغة Python:

```python
import requests

url = "https://api.acedata.cloud/openai/embeddings"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "input": "The food was delicious and the waiter...",
    "model": "text-embedding-3-small",
    "encoding_format": "float"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

تحتوي النتيجة المُرجعة على عدة حقول، ويُقدَّم شرحها كما يلي:

- `model`، النموذج المُستخدم في تحويل هذا النص إلى متجهات كلمات.
- `usage`، معلومات token المستخدمة في تحويل هذا النص إلى متجهات كلمات.
- `data`، نتيجة متجهات الكلمات بعد تحويل النص.

من بينها، يحتوي `data` على المعلومات التفصيلية لمتجهات الكلمات المقابلة للنص، ويكون `embedding` داخله هو النتيجة التفصيلية لمتجهات الكلمات المُنشأة.

## معالجة الأخطاء

عند استدعاء API، إذا واجهت خطأً، فسيُرجع API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`: طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`: طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`: غير مصرح، رمز التفويض غير صالح أو مفقود.
- `429 too_many_requests`: عدد كبير جدًا من الطلبات، لقد تجاوزت حد المعدل.
- `500 api_error`: خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة الخطأ

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
