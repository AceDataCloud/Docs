OpenAI ChatGPT هو نظام محادثة بالذكاء الاصطناعي قوي جدًا، فما عليك سوى إدخال موجه حتى يتمكن من إنشاء ردود سلسة وطبيعية في بضع ثوانٍ قصيرة. يتميز ChatGPT في المجال بفضل قدراته الممتازة على فهم اللغة وتوليدها، واليوم، أصبح ChatGPT مستخدمًا على نطاق واسع في مختلف الصناعات والمجالات، وتأثيره يزداد وضوحًا. سواء في المحادثات اليومية أو الكتابة الإبداعية أو الاستشارات المهنية أو برمجة الأكواد، يستطيع ChatGPT تقديم مساعدة ذكية مذهلة، مما يحسن بشكل كبير كفاءة عمل البشر وإبداعهم.

تقدم هذه الوثيقة بشكل أساسي عملية استخدام عمليات OpenAI Chat Completion API، وباستخدامها يمكننا بسهولة استخدام وظيفة المحادثة الخاصة بـ OpenAI ChatGPT الرسمي.

تتم محاسبة طلبات النماذج المتوافقة التي تقبلها المنصة وفقًا لاستخدام الإدخال والإخراج والتخزين المؤقت لذلك النموذج. يتضمن `prompt_tokens` في Chat Completions رموز التخزين المؤقت، ويُحتسب جزء التخزين المؤقت المُبلّغ عنه وفقًا لسعر التخزين المؤقت المقابل؛ ولا يؤدي تبديل تنسيق الواجهة إلى التحول إلى رسوم ثابتة حسب عدد المرات. تعتمد الرسوم على سعر النموذج الحالي في لوحة التحكم وعلى `usage.cost` في الاستجابة.

## GPT-6.1 Terra

استخدم `model: "gpt-6.1-terra"` لاختيار هذا النموذج. يدعم إدخال النصوص والصور والإخراج المتدفق؛ يُرجى استدعاء أدوات الدوال والإخراج المنظم وفقًا لتنسيق معلمات هذه الواجهة. تدعم مستويات الاستدلال `low` و`medium` و`high` و`xhigh` و`max`، ويُوصى بالبدء بـ `reasoning_effort: "low"`؛ ولا يدعم `none` أو `minimal`. عند تجاوز الإدخال 272,000 tokens، يُطبق سعر السياق الطويل، وتعتمد الرسوم الفعلية على السعر الحالي في لوحة التحكم والاستخدام في الاستجابة.

## GPT-6.1 Sol

استخدم `model: "gpt-6.1-sol"` لاختيار هذا النموذج. يدعم الإخراج المتدفق واستدعاء الدوال والإخراج المنظم وإدخال الصور. خلال الأسبوع الأول من الإتاحة، سيكون متاحًا فقط لحاملي ACE T1+ الذين تم التحقق منهم (بحد أدنى 100,000 ACE) أو للمستخدمين المصرح لهم؛ ويعتمد وقت الإتاحة المحدد على إشعار الوصول في لوحة التحكم.

تدعم مستويات الاستدلال `low` و`medium` و`high` و`xhigh` و`max`، ولا تدعم مؤقتًا `none` أو `minimal`. يُوصى بالبدء بـ `reasoning_effort: "low"`. عند تجاوز الإدخال 272,000 tokens، يُطبق سعر السياق الطويل على الطلب بأكمله، وتعتمد الرسوم على السعر الحالي في لوحة التحكم.

## الاستخدام الأساسي

بعد ذلك، يمكنك ملء المحتوى المقابل في الواجهة، كما هو موضح في الشكل:

<p><img src="https://cdn.acedata.cloud/jqgg1t.png" width="400" className="m-auto" /></p>

عند استخدام هذه الواجهة للمرة الأولى، نحتاج إلى ملء ثلاثة محتويات على الأقل، أحدها هو `authorization`، ويمكنك اختياره مباشرة من القائمة المنسدلة. المعلمة الأخرى هي `model`، و`model` هي فئة نموذج OpenAI ChatGPT الرسمي التي نختار استخدامها، ولدينا هنا بشكل أساسي 20 نموذجًا، ويمكنك الاطلاع على التفاصيل في النماذج التي نوفرها. المعلمة الأخيرة هي `messages`، و`messages` هي مصفوفة كلمات الاستعلام التي ندخلها، وهي مصفوفة، ما يعني أنه يمكن رفع عدة كلمات استعلام في الوقت نفسه، ويحتوي كل استعلام على `role` و`content`، حيث يشير `role` إلى دور السائل، ونوفر ثلاث هويات، وهي `user` و`assistant` و`system`. أما `content` الآخر فهو المحتوى المحدد لاستعلامنا.

في الوقت نفسه، يمكنك ملاحظة وجود إنشاء كود استدعاء مطابق على الجانب الأيمن، ويمكنك نسخ الكود وتشغيله مباشرة، أو النقر مباشرة على زر «Try» للاختبار.

المعلمات الاختيارية الشائعة:

- `max_tokens`: يحد من الحد الأقصى لعدد الرموز في الرد الواحد.
- `temperature`: عشوائية التوليد، بين 0-2، وكلما زادت القيمة كان أكثر تشتتًا.
- `n`: عدد الردود المرشحة التي يتم توليدها في المرة الواحدة.
- `response_format`: إعداد تنسيق الإرجاع.

تحتوي نتيجة الإرجاع على عدة حقول، ويكون تقديمها كما يلي:

- `usage `: المعلومات الإحصائية للرموز الخاصة بهذا السؤال والجواب.

من بينها، يتضمن `choices` معلومات إجابة ChatGPT، و`choices` الموجود بداخله هو ChatGPT، ويمكن ملاحظته كما هو موضح في الشكل.

## الاستجابة المتدفقة

تدعم هذه الواجهة أيضًا الاستجابة المتدفقة، وهذا مفيد جدًا لربط صفحات الويب، إذ يمكنه تمكين صفحة الويب من تحقيق تأثير العرض حرفًا بحرف.

إذا أردت إرجاع الاستجابة بشكل متدفق، يمكنك تغيير معلمة `stream ` في رأس الطلب إلى `true`.

التعديل كما هو موضح في الشكل، لكن كود الاستدعاء يحتاج إلى التعديل المقابل حتى يدعم الاستجابة المتدفقة.

<p><img src="https://cdn.acedata.cloud/24scd4.png" width="400" className="m-auto" /></p>

بعد تعديل `stream` إلى `true`، ستُرجع API بيانات JSON المقابلة سطرًا بسطر، وعلى مستوى الكود نحتاج إلى إجراء التعديلات المقابلة للحصول على النتائج سطرًا بسطر.

مثال على كود الاستدعاء في Python:
```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4",
    "messages": [{"role":"user","content":"hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

يدعم JavaScript أيضًا ذلك، على سبيل المثال، رمز الاستدعاء المتدفق في Node.js كما يلي:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4",
    messages: [{ role: "user", content: "hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/chat/completions", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

رمز مثال Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "gpt-4");
jsonObject.put("messages", [{"role":"user","content":"hello"}]);
jsonObject.put("stream", true);
MediaType mediaType = "application/json; charset=utf-8".toMediaType();
RequestBody body = jsonObject.toString().toRequestBody(mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/openai/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.print(response.body!!.string())
```

يمكن إعادة كتابة اللغات الأخرى بشكل منفصل، والمبدأ واحد.

## التكامل مع OpenAI-Python

تتوافق واجهة OpenAI Chat Completion API مع واجهة OpenAI الرسمية، ويمكن استخدام SDK الرسمي [OpenAI-Python](https://github.com/openai/openai-python) مباشرةً للتكامل، وستقدم هذه المقالة بإيجاز طريقة الاستخدام.

1. تحتاج أولًا إلى إعداد بيئة `Python` محلية، ويمكن البحث عن هذه العملية في Google.
2. قم بتنزيل وتثبيت بيئة التطوير، مثل تثبيت محرر VSCode.
3. قم بتكوين متغيرات بيئة `OpenAI`.

- في مجلد المشروع، أنشئ ملفًا باسم `.env` واحفظه.
- محتوى ملف `.env`:

```json
OPENAI_API_KEY="sk-xxx"
OPENAI_BASE_URL="https://api.acedata.cloud/openai"  # تذكير مرة أخرى: إذا كنت تستخدم مفتاح OpenAI الرسمي، فلا تستخدم هذا العنوان.
```

استبدل `sk-xxx` بمفتاحك الخاص. يعد `OPENAI_BASE_URL` واجهة وكيل للوصول إلى OpenAI.

4. ثبّت الحزم التي يعتمد عليها المشروع

```shell
pip install openai
```

في Mac OS، يكون الأمر:

```shell
pip3 install openai
```

5. أنشئ ملف الشفرة المصدرية النموذجي

لنفترض أننا أنشأنا شفرة نموذجية باسم `index.py`، ويكون المحتوى المحدد كما يلي:

```python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

response = client.chat.completions.create(
    messages=[
        {
            "role": "user",
            "content": "hello",
        }
    ],
    model="gpt-4",
)

print(response.text)
```

يختلف نموذجا gpt-3.5-browsing و gpt-4-browsing عن النماذج الأخرى، إذ يمكنهما إجراء بحث عبر الإنترنت استنادًا إلى عبارة الاستفسار، وإرجاع نتائج البحث عبر الإنترنت بعد تعديلها بشكل مناسب، وستعرض هذه المقالة وظيفة الاتصال بالإنترنت من خلال مثال محدد، وبعد ذلك يمكن ملء المحتوى المقابل في واجهة OpenAI Chat Completion API، كما هو موضح في الصورة:

## النموذج البصري

gpt-4o هو نموذج لغوي كبير متعدد الوسائط طورته OpenAI، وقد أضاف قدرات الفهم البصري على أساس GPT-4. يمكن لهذا النموذج معالجة مدخلات النص والصور في الوقت نفسه، محققًا الفهم والتوليد عبر الوسائط.

تتوافق معالجة النص باستخدام نموذج gpt-4o مع محتوى الاستخدام الأساسي المذكور أعلاه، وفيما يلي مقدمة موجزة حول كيفية استخدام قدرات معالجة الصور في النموذج.

تُستخدم قدرات معالجة الصور في نموذج gpt-4o بشكل أساسي عن طريق إضافة حقل `type` على أساس محتوى `content` الأصلي، ومن خلال هذا الحقل يمكن معرفة ما إذا كان المرفوع نصًا أو صورة، وبالتالي استخدام قدرات معالجة الصور في نموذج gpt-4o، وفيما يلي شرح رئيسي لاستخدام هذه الوظيفة بطريقتين: Curl وPython.

- طريقة سكربت Curl

```
curl -X POST 'https://api.acedata.cloud/openai/chat/completions' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4o",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "What'\''s in this image?"
          },
          {
            "type": "image_url",
            "image_url": {
              "url": "https://upload.wikimedia.org/wikipedia/commons/thumb/d/dd/Gfp-wisconsin-madison-the-nature-boardwalk.jpg/2560px-Gfp-wisconsin-madison-the-nature-boardwalk.jpg"
            }
          }
        ]
      }
    ]
  }'
```

- طريقة سكربت Python
```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4o",
    "messages": [
        {
            "role": "user",
            "content": [
                {
                    "type": "text", "text": "What's in this image?"
                },
                {
                    "type": "image_url",
                    "image_url": {
                        "url": "https://upload.wikimedia.org/wikipedia/commons/thumb/d/dd/Gfp-wisconsin-madison-the-nature-boardwalk.jpg/2560px-Gfp-wisconsin-madison-the-nature-boardwalk.jpg"
                    }
                },
            ],
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

بعد ذلك يمكن الحصول على النتيجة التالية، حيث إن معلومات الحقول في النتيجة متسقة مع ما ورد أعلاه، والتفاصيل كما يلي:

## معالجة الأخطاء

عند استدعاء واجهة API، إذا واجهت خطأً، فستُرجع واجهة API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح به، رمز التفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جدًا، لقد تجاوزت حد المعدل.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة الخطأ

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
