قدّمت OpenAI مؤخرًا واجهة لإنشاء استجابات النماذج. وفّر مدخلات نصية أو صورًا لإنشاء مخرجات نصية أو صور. اجعل النموذج يستدعي التعليمات البرمجية المخصصة الخاصة بك أو يستخدم أدوات مدمجة، مثل البحث على الويب أو البحث في الملفات، لاستخدام بياناتك الخاصة كمدخلات لاستجابة النموذج.

يقدّم هذا المستند بشكل أساسي عملية استخدام عمليات OpenAI Responses API، وباستخدامها يمكننا بسهولة استخدام وظيفة إنشاء استجابات النماذج الرسمية من OpenAI.

## عملية التقديم

لاستخدام OpenAI Responses API، انتقل أولاً إلى [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائيًا إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** سيمنحك أول تقديم رصيدًا مجانيًا لتجربة الخدمة مجانًا؛ وعندما لا يكون الرصيد كافيًا، يمكنك شحن الرصيد العام من [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## الاستخدام الأساسي

بعد ذلك، يمكنك ملء المحتوى المقابل في الواجهة، كما هو موضح في الصورة:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

عند استخدام هذه الواجهة لأول مرة، نحتاج إلى ملء ثلاثة محتويات على الأقل، أحدها هو `authorization`، ويمكنك اختياره مباشرة من القائمة المنسدلة. المعلمة الأخرى هي `model`، و`model` هي فئة نموذج الموقع الرسمي لـ OpenAI ChatGPT التي نختار استخدامها، ولدينا هنا بشكل أساسي 20 نموذجًا، ويمكنك الاطلاع على التفاصيل في النماذج التي نوفرها. المعلمة الأخيرة هي `input`، و`input` هي مصفوفة عبارات الأسئلة التي ندخلها، وهي مصفوفة، مما يشير إلى إمكانية رفع عدة عبارات أسئلة في الوقت نفسه، وتتضمن كل عبارة سؤال `role` و`content`، حيث يشير `role` إلى دور السائل، ونوفر ثلاث هويات، وهي `user` و`assistant` و`system`. أما `content` الأخرى فهي المحتوى المحدد للسؤال الذي نطرحه.

وفي الوقت نفسه، يمكنك ملاحظة وجود إنشاء كود الاستدعاء المقابل على الجانب الأيمن، ويمكنك نسخ الكود وتشغيله مباشرة، أو النقر مباشرة على زر «Try» للاختبار.

المعلمات الاختيارية الشائعة:

- `max_tokens`: يحد من الحد الأقصى لعدد token في الاستجابة الواحدة.
- `temperature`: عشوائية التوليد، بين 0 و2، وكلما زادت القيمة زاد التشتت.
- `n`: عدد الاستجابات المرشحة التي يتم توليدها في المرة الواحدة.
- `response_format`: إعداد تنسيق الإرجاع.
- `tools`: تعريف استدعاء الدوال/الأدوات.
- `background`: ما إذا كان سيتم التشغيل بشكل غير متزامن في الخلفية.

## الاستجابة المتدفقة

تدعم هذه الواجهة أيضًا الاستجابة المتدفقة، وهذا مفيد جدًا لربط صفحات الويب، إذ يمكن أن يتيح للصفحة تحقيق تأثير العرض حرفًا بحرف.

إذا كنت تريد إرجاع الاستجابة بشكل متدفق، يمكنك تغيير معلمة `stream ` في رأس الطلب إلى `true`.

يظهر التعديل كما هو موضح في الصورة، لكن كود الاستدعاء يحتاج إلى تعديلات مقابلة لدعم الاستجابة المتدفقة.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

بعد تعديل `stream` إلى `true`، ستُرجع API بيانات JSON المقابلة سطرًا بسطر، وعلى مستوى الكود نحتاج إلى إجراء تعديلات مقابلة للحصول على النتائج سطرًا بسطر.

مثال على كود الاستدعاء في Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

يمكن ملاحظة أن الاستجابة تحتوي على العديد من `data`، و`delta` داخل `data` هو أحدث محتوى للإجابة، وهو متوافق مع المحتوى المقدم أعلاه. تمثل `delta` محتوى الإجابة المضاف حديثًا، ويمكنك الربط بنظامك وفقًا للنتيجة. تنتهي الاستجابة المتدفقة بـ `response.completed` أو `response.incomplete` كحالة نهائية؛ وتُعد `usage` في الحالة النهائية الاستخدام النهائي للرموز المميزة token لهذا الطلب، وهي أيضًا أساس الفوترة.

إذا قطع العميل الاتصال قبل وصول الحالة النهائية، فسيُسجل هذا الطلب على أنه مغلق من قِبل العميل (499)، ولن تُستخدم تقديرات token المحلية للفوترة؛ وإذا انتهى الاتصال بشكل طبيعي ولكن لم يتم استلام الحالة النهائية و`usage` النهائي، فسيُسجل هذا الطلب على أنه استجابة غير مكتملة (502)، ولن تُستخدم تقديرات token للفوترة أيضًا. عند مواجهة هاتين الحالتين، يرجى إعادة إرسال الطلب.

تحتوي نتيجة `data` المُعادة على عدة حقول، وهي موضحة كما يلي:

- `item_id`، معرّف مهمة المحادثة التي تم إنشاؤها هذه المرة، ويُستخدم لتمييز مهمة المحادثة هذه بشكل فريد.
- `type`، نوع مهمة Responses للمحادثة التي تم إنشاؤها هذه المرة.
- `model `، نموذج OpenAI ChatGPT الرسمي المحدد.
- `delta`، معلومات الإجابة التي يقدمها ChatGPT على كلمات السؤال.

JavaScript مدعوم أيضًا، فعلى سبيل المثال، يكون رمز الاستدعاء المتدفق لـ Node.js كما يلي:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

رمز عينة Java:


## محادثات متعددة الجولات

إذا كنت ترغب في ربط وظيفة المحادثات متعددة الجولات، فيجب تحميل عدة كلمات سؤال إلى حقل `input`، ويظهر المثال المحدد لكلمات السؤال المتعددة كما في الصورة أدناه:

<p><img src="https://cdn.acedata.cloud/1jqwnf.png" width="400" className="m-auto" /></p>

رمز استدعاء عينة Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"},{"role":"assistant","content":"Hello! How can I help you today? 😊"},{"role":"user","content":"What did I just say?"}]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## نموذج الرؤية

gpt-4o هو نموذج لغوي كبير متعدد الوسائط طورته OpenAI، وقد أضاف قدرات الفهم البصري على أساس GPT-4. يمكن لهذا النموذج معالجة مدخلات النصوص والصور في الوقت نفسه، محققًا فهمًا وتوليدًا عبر الوسائط.
تتوافق معالجة النصوص باستخدام نموذج gpt-4o مع محتوى الاستخدام الأساسي المذكور أعلاه، وفيما يلي مقدمة موجزة حول كيفية استخدام قدرات معالجة الصور الخاصة بالنموذج.

تُستخدم قدرات معالجة الصور في نموذج gpt-4o بشكل رئيسي عبر إضافة حقل `type` إلى محتوى `content` الأصلي، ومن خلال هذا الحقل يمكن معرفة ما إذا كان المرفوع نصًا أم صورة، وبالتالي استخدام قدرات معالجة الصور الخاصة بنموذج gpt-4o. وفيما يلي شرح رئيسي لطريقتين لاستدعاء هذه الوظيفة باستخدام Curl وPython.

- طريقة سكربت Curl


- طريقة سكربت Python

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## معالجة الأخطاء

عند استدعاء API، إذا واجهت خطأً، فستُرجع API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح به، رمز التفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جدًا، لقد تجاوزت حد معدل الطلبات.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة خطأ

```
  "success": false,

    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
