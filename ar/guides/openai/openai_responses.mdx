تُحتسب رسوم طلبات النماذج المتوافقة التي تقبلها المنصة وفقًا لاستخدام الإدخال والإخراج والتخزين المؤقت الخاص بالنموذج. يتضمن إجمالي إدخال Responses رموز التخزين المؤقت التي تم الإبلاغ عنها، ويُسوّى جزء التخزين المؤقت وفقًا لسعر التخزين المؤقت المقابل؛ ولن يؤدي تبديل تنسيق الواجهة إلى التحول إلى رسوم ثابتة حسب عدد المرات. تخضع الرسوم لأسعار النموذج الحالية في وحدة التحكم و`usage.cost` في الاستجابة.

قدمت OpenAI مؤخرًا واجهة لإنشاء استجابات النماذج. وفّر إدخالًا نصيًا أو صوريًا لإنشاء مخرجات نصية أو صورية. اجعل النموذج يستدعي تعليماتك البرمجية المخصصة أو يستخدم أدوات مدمجة، مثل البحث على الويب أو البحث في الملفات، لاستخدام بياناتك الخاصة كإدخال لاستجابة النموذج.

تقدم هذه الوثيقة بشكل رئيسي عملية استخدام واجهة OpenAI Responses API، وباستخدامها يمكننا بسهولة استخدام ميزة إنشاء استجابات النماذج من OpenAI الرسمية.

## GPT-6.1 Terra

استخدم `model: "gpt-6.1-terra"` لاختيار هذا النموذج. يدعم إدخال النصوص والصور، والمخرجات المتدفقة، وأدوات الدوال، والمخرجات المهيكلة. تدعم مستويات الاستدلال `low` و`medium` و`high` و`xhigh` و`max`، ويُوصى بالبدء من `reasoning: {"effort": "low"}`؛ ولا يدعم `none` أو `minimal`. عند تجاوز الإدخال 272,000 tokens، تُطبّق أسعار السياق الطويل، وتخضع الرسوم الفعلية للسعر الحالي في وحدة التحكم والاستخدام في الاستجابة.

## GPT-6.1 Sol

استخدم `model: "gpt-6.1-sol"` لاختيار هذا النموذج. يدعم المخرجات المتدفقة، واستدعاء الدوال، والمخرجات المهيكلة، وإدخال الصور. خلال الأسبوع الأول من الإتاحة، سيكون متاحًا فقط لحاملي ACE T1+ الذين تم التحقق منهم (بما لا يقل عن 100,000 ACE) أو للمستخدمين المصرح لهم؛ ويخضع وقت الإتاحة المحدد لإشعارات الوصول في وحدة التحكم.

تدعم مستويات الاستدلال `low` و`medium` و`high` و`xhigh` و`max`، ولا تدعم مؤقتًا `none` أو `minimal`. يُوصى بالبدء من `reasoning: {"effort": "low"}`. عند تجاوز الإدخال 272,000 tokens، تُطبّق أسعار السياق الطويل على الطلب بأكمله، وتخضع الرسوم للسعر الحالي في وحدة التحكم.

## عملية التقديم

لاستخدام OpenAI Responses API، انتقل أولًا إلى [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تقم بتسجيل الدخول أو التسجيل بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائيًا إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** سيُمنحك رصيد مجاني عند التقديم لأول مرة، ويمكنك التجربة مجانًا؛ وعندما لا يكون الرصيد كافيًا، يمكنك شحن الرصيد العام في [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## الاستخدام الأساسي

بعد ذلك، يمكنك ملء المحتوى المقابل في الواجهة، كما هو موضح في الصورة:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

عند استخدام هذه الواجهة لأول مرة، نحتاج إلى ملء ثلاثة عناصر على الأقل، أحدها هو `authorization`، ويمكنك اختياره مباشرة من القائمة المنسدلة. المعلمة الأخرى هي `model`، و`model` هي فئة نموذج OpenAI ChatGPT الرسمية التي نختار استخدامها، ولدينا هنا بشكل رئيسي 20 نوعًا من النماذج، ويمكنك الاطلاع على التفاصيل في النماذج التي نوفرها. المعلمة الأخيرة هي `input`، و`input` هي مصفوفة عبارات الأسئلة التي ندخلها، وهي مصفوفة تشير إلى إمكانية رفع عدة عبارات أسئلة في الوقت نفسه، وتحتوي كل عبارة سؤال على `role` و`content`، حيث يشير `role` إلى دور السائل، ونوفر ثلاث هويات، وهي `user` و`assistant` و`system`. أما `content` الآخر فهو المحتوى المحدد للسؤال الذي نطرحه.

وفي الوقت نفسه، يمكنك ملاحظة وجود إنشاء لكود الاستدعاء المقابل على الجانب الأيمن، ويمكنك نسخ الكود وتشغيله مباشرة، أو النقر مباشرة على زر «Try» للاختبار.

المعلمات الاختيارية الشائعة:

- `max_tokens`: تقييد الحد الأقصى لعدد الرموز في رد واحد.
- `temperature`: عشوائية التوليد، بين 0-2، وكلما زادت القيمة زاد التشتت.
- `n`: عدد الردود المرشحة التي يتم توليدها في المرة الواحدة.
- `response_format`: إعداد تنسيق الإرجاع.
- `tools`: تعريف استدعاء الدوال/الأدوات.
- `background`: ما إذا كان سيتم التشغيل بشكل غير متزامن في الخلفية.

## الاستجابة المتدفقة

تدعم هذه الواجهة أيضًا الاستجابة المتدفقة، وهذا مفيد جدًا لربط صفحات الويب، إذ يمكنه تمكين صفحة الويب من تحقيق تأثير العرض حرفًا بحرف.

إذا أردت إرجاع الاستجابة بشكل متدفق، فيمكنك تغيير معلمة `stream ` في رأس الطلب إلى `true`.

يتم التعديل كما هو موضح في الصورة، لكن كود الاستدعاء يحتاج إلى تعديلات مقابلة حتى يدعم الاستجابة المتدفقة.
<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

بعد تعديل `stream` إلى `true`، ستُرجع واجهة API بيانات JSON المقابلة سطرًا بسطر، وعلى مستوى الكود نحتاج إلى إجراء التعديلات المناسبة للحصول على النتائج سطرًا بسطر.

رمز استدعاء نموذجي بلغة Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

يمكن ملاحظة أن الاستجابة تحتوي على العديد من `data`، ويمثل `delta` داخل `data` أحدث محتوى للإجابة، وهو متوافق مع المحتوى المقدّم أعلاه. يمثل `delta` محتوى الإجابة المضاف حديثًا، ويمكنك ربطه بنظامك وفقًا للنتيجة. تنتهي الاستجابة المتدفقة بالحالة النهائية `response.completed` أو `response.incomplete`؛ ويُعد `usage` في الحالة النهائية هو الاستخدام النهائي للرموز المميزة لهذا الطلب، وهو أيضًا أساس الفوترة.

إذا قطع العميل الاتصال قبل وصول الحالة النهائية، فسيُسجَّل هذا الطلب على أنه مغلق من قبل العميل (499)، ولن يتم احتسابه باستخدام تقدير الرموز المميزة المحلي؛ وإذا انتهى الاتصال بشكل طبيعي ولكن لم تُستلم الحالة النهائية و`usage` النهائي، فسيُسجَّل هذا الطلب على أنه استجابة غير مكتملة (502)، وبالمثل لن يتم احتسابه باستخدام تقدير الرموز المميزة. عند مواجهة هاتين الحالتين، يُرجى إعادة إرسال الطلب.

تحتوي نتيجة `data` المُعادة على عدة حقول، كما يلي:

- `item_id`، معرّف مهمة المحادثة التي تم إنشاؤها هذه المرة، ويُستخدم لتمييز مهمة المحادثة هذه بشكل فريد.
- `type`، نوع مهمة Responses للمحادثة التي تم إنشاؤها هذه المرة.
- `model `، نموذج OpenAI ChatGPT الرسمي المحدد على الموقع.
- `delta`، معلومات الإجابة التي يقدمها ChatGPT على كلمة السؤال.

تدعم JavaScript أيضًا ذلك، على سبيل المثال، رمز الاستدعاء المتدفق في Node.js كما يلي:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

رمز مثال Java:

```java

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
```

## النموذج البصري

gpt-4o هو نموذج لغوي كبير متعدد الوسائط طورته OpenAI، وقد أضاف قدرات الفهم البصري على أساس GPT-4. يمكن لهذا النموذج معالجة مدخلات النصوص والصور في الوقت نفسه، مما يحقق الفهم والتوليد عبر الوسائط.

تتوافق معالجة النصوص باستخدام نموذج gpt-4o مع محتوى الاستخدام الأساسي أعلاه، وفيما يلي مقدمة موجزة لكيفية استخدام قدرات معالجة الصور في النموذج.

## معالجة الأخطاء

عند استدعاء API، إذا واجهت خطأً، فسيُرجع API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح به، رمز التفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جدًا، لقد تجاوزت حد المعدل.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة خطأ

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
