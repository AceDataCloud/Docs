ستقدم هذه الوثيقة توضيحًا لواجهة برمجة التطبيقات للتحقق من أربعة عناصر بطاقة البنك، والتي يمكن استخدامها لإدخال رقم بطاقة البنك، الاسم، رقم الهوية، ورقم الهاتف المحمول المرتبط بالحساب، للتحقق من صحة المعلومات وتوافقها.

## عملية التقديم

لاستخدام واجهة برمجة التطبيقات للتحقق من أربعة عناصر بطاقة البنك، يجب أولاً الذهاب إلى [وحدة التحكم في Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على رمز API الخاص بك، للاحتفاظ به كنسخة احتياطية.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد قمت بتسجيل الدخول أو التسجيل بعد، سيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك للتسجيل وتسجيل الدخول، وبعد الانتهاء سيتم العودة تلقائيًا إلى الصفحة الحالية.

**يمكن استخدام رمز API واحد لاستدعاء جميع خدمات المنصة، دون الحاجة لتقديم طلب منفصل لكل خدمة.** عند التقديم لأول مرة، ستحصل على رصيد مجاني لتجربته؛ وعند نفاد الرصيد، يمكنك إعادة شحن الرصيد العام في [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثيقة الكاملة: [واجهة برمجة التطبيقات للتحقق من أربعة عناصر بطاقة البنك →](https://platform.acedata.cloud/documents/identity-bankcard-check-4e)

## الاستخدام الأساسي

أولاً، يجب أن نفهم طريقة الاستخدام الأساسية، وهي إدخال معلومات رقم بطاقة البنك، للحصول على صورة نتيجة المعالجة، حيث نحتاج أولاً إلى تمرير حقل `bank_card`. بعد ذلك، يمكننا ملء المحتوى المقابل على الواجهة، كما هو موضح في الصورة:

<p><img src="https://cdn.acedata.cloud/1pl0y5.png" width="500" className="m-auto" /></p>

يمكننا أن نرى هنا أننا قمنا بتعيين رؤوس الطلب، بما في ذلك:

- `accept`: نوع الاستجابة التي ترغب في تلقيها، هنا يتم ملؤها بـ `application/json`، أي بتنسيق JSON.
- `authorization`: مفتاح استدعاء واجهة برمجة التطبيقات، يمكن اختياره مباشرة بعد التقديم.

كما تم تعيين جسم الطلب، بما في ذلك:

- `bank_card`: معلومات رقم بطاقة البنك التي تحتاج إلى المعالجة، وهي معلمة مطلوبة.
- `id_card`: رقم الهوية، وهو معلمة مطلوبة.
- `name`: اسم المستخدم، وهو معلمة مطلوبة.
- `phone`: رقم الهاتف المحمول المحجوز.
- `cert_type`: نوع وثيقة الهوية، يجب أن يتطابق مع وثيقة الهوية.
- `encryption`: اختياري، معلمة تشفير الحقول الحساسة (إذا كان هناك حاجة لإرسال نص مشفر).

بعد الاختيار، يمكننا أن نلاحظ أن الجانب الأيمن قد أنشأ أيضًا الكود المقابل، كما هو موضح في الصورة:

<p><img src="https://cdn.acedata.cloud/slajgv.png" width="500" className="m-auto" /></p>

يمكنك الضغط على زر "Try" لإجراء اختبار، كما هو موضح في الصورة أعلاه، وهنا حصلنا على النتيجة التالية:

```json
{
  "result": "0",
  "description": "تم التحقق بنجاح"
}
```

تتضمن النتيجة العائدة عدة حقول، كما هو موضح أدناه:

- `result`، رمز نتيجة التحقق، وتفاصيل الرسوم كما يلي.
    - رموز نتيجة الرسوم:
        - 0: تم التحقق بنجاح
        - -1: لم يتم التحقق
        - -4: معلومات حامل البطاقة غير صحيحة
        - -5: لم يتم تفعيل الدفع بدون بطاقة
        - -6: تم حجز هذه البطاقة
        - -7: رقم بطاقة غير صالح
        - -8: لا توجد جهة إصدار مطابقة لهذه البطاقة
        - -9: لم يتم تهيئة هذه البطاقة أو بطاقة نائمة
        - -10: بطاقة غش، تم ابتلاع البطاقة
        - -11: تم الإبلاغ عن فقدان هذه البطاقة
        - -12: انتهت صلاحية هذه البطاقة
        - -13: بطاقة مقيدة
        - -14: تجاوز عدد محاولات إدخال كلمة المرور الحد المسموح
        - -15: جهة الإصدار لا تدعم هذه المعاملة
    - رموز نتيجة غير الرسوم:
        - -2: فشل التحقق من الاسم
        - -3: رقم بطاقة البنك غير صحيح
        - -16: مركز التحقق مشغول
        - -17: تجاوز عدد مرات التحقق، يرجى المحاولة مرة أخرى في اليوم التالي
- `description`، وصف نتيجة العمل.

يمكننا أن نرى أن رقم بطاقة البنك، الاسم، رقم الهوية، ورقم الهاتف المحمول المرتبط بالحساب تتمتع بصحة وتوافق.

بالإضافة إلى ذلك، إذا كنت ترغب في إنشاء كود التكامل المقابل، يمكنك نسخه مباشرة، على سبيل المثال، كود CURL كما يلي:

```shell
curl -X POST 'https://api.acedata.cloud/identity/bankcard/check-4e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "phone": "***",
  "id_card": "***",
  "bank_card": "***"
}'
```

كود التكامل بلغة Python كما يلي:

```python
import requests

url = "https://api.acedata.cloud/identity/bankcard/check-4e"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "name": "胡印福",
    "phone": "***",
    "id_card": "***",
    "bank_card": "***"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## معالجة الأخطاء

عند استدعاء واجهة برمجة التطبيقات، إذا واجهت خطأ، ستقوم واجهة برمجة التطبيقات بإرجاع رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`: طلب غير صحيح، ربما بسبب معلمات مفقودة أو غير صحيحة.
- `400 api_not_implemented`: طلب غير صحيح، ربما بسبب معلمات مفقودة أو غير صحيحة.
- `401 invalid_token`: غير مصرح، رمز تفويض غير صالح أو مفقود.
- `429 too_many_requests`: عدد كبير جدًا من الطلبات، لقد تجاوزت الحد المسموح به.
- `500 api_error`: خطأ في الخادم الداخلي، حدث خطأ ما على الخادم.

### مثال على استجابة الخطأ

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "فشل في الاسترجاع"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
