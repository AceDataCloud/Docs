ستقدم هذه الوثيقة توضيحًا لواجهة برمجة التطبيقات للتحقق من عنصرين لبطاقة البنك، والتي يمكن استخدامها للتحقق من صحة وملاءمة الاسم ورقم بطاقة البنك.

## عملية التقديم

لاستخدام واجهة برمجة التطبيقات للتحقق من عنصرين لبطاقة البنك، يجب أولاً الذهاب إلى [وحدة التحكم في Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على رمز API الخاص بك، للاحتفاظ به كنسخة احتياطية.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد قمت بتسجيل الدخول أو التسجيل بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك للتسجيل وتسجيل الدخول، وبعد الانتهاء، سيتم إرجاعك تلقائيًا إلى الصفحة الحالية.

**يمكن استخدام رمز API واحد لاستدعاء جميع خدمات المنصة، دون الحاجة لتقديم طلب منفصل لكل خدمة.** سيتم منحك رصيد مجاني عند الطلب الأول، يمكنك تجربته مجانًا؛ وعند نفاد الرصيد، يمكنك إعادة شحن الرصيد العام في [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [واجهة برمجة التطبيقات للتحقق من عنصرين لبطاقة البنك →](https://platform.acedata.cloud/documents/identity-bankcard-check-2e)

## الاستخدام الأساسي

أولاً، يجب أن نفهم طريقة الاستخدام الأساسية، وهي إدخال معلومات رقم بطاقة البنك، للحصول على صورة نتيجة المعالجة، حيث نحتاج أولاً إلى تمرير حقل `bank_card`. بعد ذلك، يمكننا ملء المحتوى المقابل في الواجهة، كما هو موضح في الصورة:

<p><img src="https://cdn.acedata.cloud/u9bugq.png" width="500" className="m-auto" /></p>

يمكننا أن نرى هنا أننا قمنا بتعيين رؤوس الطلب، بما في ذلك:

- `accept`: نوع الاستجابة التي ترغب في تلقيها، هنا يتم ملؤها بـ `application/json`، أي بتنسيق JSON.
- `authorization`: مفتاح استدعاء واجهة برمجة التطبيقات، يمكن اختياره مباشرة بعد التقديم.

كما تم تعيين جسم الطلب، بما في ذلك:

- `bank_card`: معلومات رقم بطاقة البنك التي تحتاج إلى المعالجة، وهي معلمة مطلوبة.
- `name`: اسم المستخدم، وهو معلمة مطلوبة.
- `encryption`: اختياري، معلمة تشفير الحقول الحساسة (إذا كان هناك حاجة لإرسال نص مشفر).

بعد الاختيار، يمكننا أن نلاحظ أن الجانب الأيمن قد أنشأ أيضًا الكود المقابل، كما هو موضح في الصورة:

<p><img src="https://cdn.acedata.cloud/yn8yxf.png" width="500" className="m-auto" /></p>

يمكنك النقر على زر "Try" لإجراء اختبار، كما هو موضح في الصورة أعلاه، وهنا حصلنا على النتيجة التالية:

```json
{
  "result": "0",
  "description": "تمت المصادقة بنجاح"
}
```

تتضمن النتيجة العائدة عدة حقول، كما هو موضح أدناه:

- `result`، رمز نتيجة المصادقة، وتفاصيل الرسوم كما يلي.
    - رموز نتيجة الرسوم:
        - 0: تمت المصادقة بنجاح
        - -1: لم تتم المصادقة
        - -4: معلومات حامل البطاقة غير صحيحة
        - -5: لم يتم تفعيل الدفع بدون بطاقة
        - -6: تم حجز هذه البطاقة
        - -7: رقم بطاقة غير صالح
        - -8: لا توجد جهة إصدار مطابقة لهذه البطاقة
        - -9: لم يتم تهيئة هذه البطاقة أو بطاقة نائمة
        - -10: بطاقة غش، تم ابتلاع البطاقة
        - -11: تم الإبلاغ عن فقدان هذه البطاقة
        - -12: انتهت صلاحية هذه البطاقة
        - -13: بطاقة مقيدة
        - -14: تجاوز عدد محاولات إدخال كلمة المرور الحد المسموح
        - -15: جهة الإصدار لا تدعم هذه المعاملة
    - رموز نتيجة غير الرسوم:
        - -2: لم تتم المصادقة على الاسم
        - -3: رقم بطاقة البنك غير صحيح
        - -16: مركز التحقق مشغول
        - -17: تجاوز عدد مرات التحقق، يرجى المحاولة مرة أخرى في اليوم التالي
- `description`، وصف نتيجة العمل.

يمكننا أن نرى أن صحة وملاءمة الاسم ورقم بطاقة البنك قد تم التحقق منها.

بالإضافة إلى ذلك، إذا كنت ترغب في إنشاء كود التكامل المقابل، يمكنك نسخه مباشرة، على سبيل المثال، كود CURL كما يلي:

```shell
curl -X POST 'https://api.acedata.cloud/identity/bankcard/check-2e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "bank_card": "***"
}'
```

كود التكامل بلغة Python كما يلي:

```python
curl -X POST 'https://api.acedata.cloud/identity/bankcard/check-2e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "bank_card": "***"
}'
```

## معالجة الأخطاء

عند استدعاء واجهة برمجة التطبيقات، إذا واجهت خطأ، ستقوم واجهة برمجة التطبيقات بإرجاع رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`: طلب غير صحيح، ربما بسبب معلمات مفقودة أو غير صحيحة.
- `400 api_not_implemented`: طلب غير صحيح، ربما بسبب معلمات مفقودة أو غير صحيحة.
- `401 invalid_token`: غير مصرح، رمز تفويض غير صالح أو مفقود.
- `429 too_many_requests`: عدد كبير جدًا من الطلبات، لقد تجاوزت الحد المسموح به.
- `500 api_error`: خطأ في الخادم الداخلي، حدث خطأ ما على الخادم.

### مثال على استجابة الخطأ

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "فشل في الاسترجاع"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
