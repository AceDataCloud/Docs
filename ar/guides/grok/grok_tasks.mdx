الوظيفة الرئيسية لواجهة برمجة تطبيقات مهام Grok هي استعلام حالة تنفيذ المهمة من خلال إدخال معرف المهمة الذي تم إنشاؤه بواسطة واجهة برمجة تطبيقات توليد مقاطع فيديو Grok.

ستتناول هذه الوثيقة تفاصيل تكامل واجهة برمجة تطبيقات مهام Grok، لمساعدتك في دمج واستعلام حالة تنفيذ مهام واجهة برمجة تطبيقات توليد مقاطع فيديو Grok بسهولة.

## عملية التقديم

لاستخدام واجهة برمجة تطبيقات توليد مقاطع فيديو Grok، يجب أولاً الذهاب إلى [وحدة التحكم في Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على رمز API الخاص بك، للاحتفاظ به كنسخة احتياطية.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد قمت بتسجيل الدخول أو التسجيل بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك للتسجيل وتسجيل الدخول، وبعد الانتهاء، سيتم إرجاعك تلقائيًا إلى الصفحة الحالية.

**يمكن استخدام رمز API واحد لاستدعاء جميع خدمات المنصة، دون الحاجة لتقديم طلب منفصل لكل خدمة.** عند التقديم لأول مرة، ستحصل على رصيد مجاني لتجربته مجانًا؛ وعند نفاد الرصيد، يمكنك إعادة شحن الرصيد العام في [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثيقة الكاملة: [واجهة برمجة تطبيقات توليد مقاطع فيديو Grok →](https://platform.acedata.cloud/documents/grok-videos)

## مثال على الطلب

يمكن استخدام واجهة برمجة تطبيقات مهام Grok لاستعلام نتائج واجهة برمجة تطبيقات توليد مقاطع فيديو Grok.

### إعداد رأس الطلب وجسم الطلب

**رؤوس الطلب** تشمل:

- `accept`: تحديد استلام نتائج الاستجابة بتنسيق JSON، هنا يتم ملؤه بـ `application/json`.
- `authorization`: مفتاح استدعاء واجهة برمجة التطبيقات، يمكن اختياره مباشرة بعد التقديم.

**جسم الطلب** يشمل:

- `id`: معرف المهمة التي تريد استعلامها.
- `action`: طريقة إجراء العملية على المهمة، يتم ملء الاستعلام الفردي بـ `retrieve`.

### مثال على كود CURL

```bash
curl -X POST 'https://api.acedata.cloud/grok/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### مثال على الاستجابة

بعد نجاح الطلب، ستقوم واجهة برمجة التطبيقات بإرجاع تفاصيل هذه المهمة. حيث أن حقل `request` هو جسم الطلب عند بدء المهمة، وحقل `response` هو جسم الاستجابة الذي يتم إرجاعه بعد إكمال المهمة، على سبيل المثال:

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "started_at": 1769262721.823,
  "finished_at": 1769262729.623,
  "elapsed": 7.8,
  "request": {
    "prompt": "لقطة سينمائية لقط يتبع فراشة في حديقة مضاءة بأشعة الشمس",
    "model": "grok-imagine-video-1.5-fast:reverse",
    "resolution": "480p",
    "duration": 8
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "grok-imagine-video-1.5-fast:reverse:41eb9a5f-3b2d-4d1e-9f5a-6c2f1a0b9e77",
        "video_url": "https://cdn.acedata.cloud/c8cbf53aa0.mp4",
        "state": "succeeded"
      }
    ]
  }
}
```

تقديم الحقول كما يلي:

- `id`: معرف المهمة التي تم إنشاؤها، يستخدم لتحديد هذه المهمة بشكل فريد.
- `request`: معلومات الطلب في المهمة المستعلم عنها.
- `response`: معلومات الاستجابة في المهمة المستعلم عنها.
- `created_at`: وقت إنشاء المهمة، طابع زمني Unix (ثوانٍ، عائم).
- `started_at`: وقت بدء تنفيذ المهمة، طابع زمني Unix (ثوانٍ، عائم).
- `finished_at`: وقت إكمال المهمة، طابع زمني Unix (ثوانٍ، عائم). لا يتم إرجاع هذا الحقل إذا لم تكتمل المهمة.
- `elapsed`: الوقت المستغرق لتنفيذ المهمة، بوحدة الثواني (عائم، يحتفظ بـ 3 أرقام عشرية). لا يتم إرجاع هذا الحقل إذا لم تكتمل المهمة.

## عملية الاستعلام الجماعي

عند استعلام تفاصيل المهام لعدة معرفات مهام، يتم تعيين `action` إلى `retrieve_batch`، ويتم تمرير مصفوفة معرفات المهام عبر `ids`:

**جسم الطلب** يشمل:

- `ids`: مصفوفة معرفات المهام التي تريد استعلامها.
- `action`: طريقة إجراء العملية على المهام، يتم ملء الاستعلام الجماعي بـ `retrieve_batch`.

```bash
curl -X POST 'https://api.acedata.cloud/grok/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```
