الوظيفة الرئيسية لواجهة برمجة تطبيقات مهام Grok هي الاستعلام عن حالة تنفيذ المهمة من خلال إدخال معرف المهمة الذي تم إنشاؤه بواسطة واجهة برمجة تطبيقات إنشاء فيديوهات Grok.

توضح هذه الوثيقة بالتفصيل تعليمات تكامل واجهة برمجة تطبيقات مهام Grok، لمساعدتك على دمجها بسهولة والاستعلام عن حالة تنفيذ مهام واجهة برمجة تطبيقات إنشاء فيديوهات Grok.

## عملية التقديم

لاستخدام واجهة برمجة تطبيقات مهام Grok، يجب أولاً التقديم للحصول على الخدمة المناسبة من صفحة التقديم [Grok Videos Generation API](https://platform.acedata.cloud/documents/grok-videos) ونسخ معرف المهمة الذي تعيده واجهة برمجة تطبيقات إنشاء فيديوهات Grok.

بعد ذلك، انتقل إلى صفحة [Grok Tasks API](https://platform.acedata.cloud/documents/grok-tasks) للتقديم على الخدمة المناسبة، وعند الدخول إلى الصفحة، اضغط على زر "Acquire".

إذا لم تكن قد قمت بتسجيل الدخول أو التسجيل، فسيتم تحويلك تلقائيًا إلى [صفحة تسجيل الدخول](https://platform.acedata.cloud) لدعوتك للتسجيل وتسجيل الدخول، وبعد تسجيل الدخول أو التسجيل سيتم إرجاعك تلقائيًا إلى الصفحة الحالية.

عند التقديم لأول مرة، ستحصل على حصة مجانية يمكن استخدامها مجانًا لهذه الواجهة البرمجية.

## مثال على الطلب

يمكن استخدام واجهة برمجة تطبيقات مهام Grok للاستعلام عن نتائج واجهة برمجة تطبيقات إنشاء فيديوهات Grok.

### إعداد رؤوس الطلب وجسم الطلب

**رؤوس الطلب (Request Headers)** تشمل:

- `accept`: لتحديد استلام استجابة بصيغة JSON، يتم تعبئتها بـ `application/json`.
- `authorization`: مفتاح استدعاء الواجهة البرمجية، يمكن اختياره مباشرة من القائمة المنسدلة بعد التقديم.

**جسم الطلب (Request Body)** يشمل:

- `id`: معرف المهمة المراد الاستعلام عنها.
- `action`: طريقة التعامل مع المهمة، للاستعلام الفردي يتم تعبئتها بـ `retrieve`.

### مثال على كود CURL

```bash
curl -X POST 'https://api.acedata.cloud/grok/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### مثال على الاستجابة

بعد نجاح الطلب، ستعيد الواجهة تفاصيل المهمة هنا. حيث أن حقل `request` هو جسم الطلب عند بدء المهمة، وحقل `response` هو جسم الاستجابة بعد إكمال المهمة، على سبيل المثال:

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "request": {
    "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
    "model": "grok-imagine-video-1.5-fast",
    "resolution": "480p",
    "duration": 8
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "grok-imagine-video-1.5-fast:41eb9a5f-3b2d-4d1e-9f5a-6c2f1a0b9e77",
        "video_url": "https://cdn.acedata.cloud/c8cbf53aa0.mp4",
        "state": "succeeded"
      }
    ]
  }
}
```

تفسير الحقول كما يلي:

- `id`: معرف مهمة الإنشاء، يستخدم لتمييز مهمة الإنشاء هذه بشكل فريد.
- `request`: معلومات الطلب ضمن المهمة المستعلم عنها.
- `response`: معلومات الاستجابة ضمن المهمة المستعلم عنها.

## عمليات الاستعلام الجماعي

للاستعلام عن تفاصيل مهام متعددة باستخدام معرفات المهام، قم بتعيين `action` إلى `retrieve_batch`، ومرر مصفوفة معرفات المهام عبر `ids`:

**جسم الطلب** يشمل:

- `ids`: مصفوفة معرفات المهام المراد الاستعلام عنها.
- `action`: طريقة التعامل مع المهام، للاستعلام الجماعي تعبئتها بـ `retrieve_batch`.

```bash
curl -X POST 'https://api.acedata.cloud/grok/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```
