تتمثل الوظيفة الرئيسية لـ API للاستعلام عن مهام Maestro في الاستعلام عن حالة تنفيذ المهمة والنتيجة النهائية من خلال معرّف المهمة الذي تُرجعه [واجهة API لإنشاء فيديو Maestro](/ar/guides/maestro/maestro_videos) (`POST /maestro/videos`).

سيقدم هذا المستند بالتفصيل دليل تكامل API للاستعلام عن مهام Maestro. نظرًا لأن إنشاء الفيديو مهمة غير متزامنة، يلزم بعد الإرسال استخدام هذه الواجهة للاستعلام الدوري عن التقدم والفيديو النهائي، **والاستعلام الدوري مجاني ولا يستهلك الرصيد.**

`POST https://api.acedata.cloud/maestro/tasks`

## عملية التقديم

لاستخدام API للاستعلام عن مهام Maestro، انتقل أولاً إلى [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، ثم ستعود تلقائيًا إلى الصفحة الحالية بعد الإكمال.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** عند أول تقديم، سيتم منحك رصيد مجاني للتجربة المجانية؛ وعندما لا يكون الرصيد كافيًا، يمكنك شحن الرصيد العام من [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [API الاستعلام عن مهام Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## الاستعلام عن مهمة واحدة

لمعرفة كيفية إنشاء مهمة فيديو، يرجى الرجوع إلى وثيقة [واجهة API لإنشاء فيديو Maestro](/ar/guides/maestro/maestro_videos). سنأخذ معرّف مهمة أعادته كمثال: `f57e99c4f60f4373a15517742ce2357d`، لعرض كيفية الاستعلام عن حالتها ونتيجتها.

### إعداد رؤوس الطلب ونص الطلب

يتضمن **Request Headers** ما يلي:

- `accept`: يحدد استلام نتيجة استجابة بتنسيق JSON، ويُملأ هنا بـ `application/json`.
- `authorization`: مفتاح استدعاء API، ويمكن اختياره مباشرةً من القائمة المنسدلة بعد التقديم.
- `content-type`: تنسيق نص الطلب، ويُملأ هنا بـ `application/json`.

يتضمن **Request Body** ما يلي:

| الحقل       | النوع     | مطلوب عند        | الوصف                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | مطلوب عند الاستعلام عن مهمة واحدة | `task_id` الذي يعيده `POST /maestro/videos`              |
| `action` | string | لا         | `retrieve` (افتراضيًا، للاستعلام عن مهمة واحدة)؛ عند الاستعلام عن قائمة السجل يكون ثابتًا `retrieve_batch` |

### مثال على الكود

كود CURL المقابل كما يلي:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

كود Python المقابل كما يلي:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### مثال على الاستجابة

بعد نجاح الطلب، ستُرجع API حالة ونتيجة مهمة الفيديو هذه. مثال على القيمة المرجعة عند اكتمال المهمة كما يلي (تحتوي مصفوفة `variants` على فيديو نهائي واحد):

```json
{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "started_at": 1769262721.823,
  "finished_at": 1769264698.3,
  "elapsed": 1976.477,
  "status": "succeeded",
  "progress": {
    "percent": 100,
    "stage": "producing",
    "message": "rendering scene 2"
  },
  "request": {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": [
      "zh-cn"
    ],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        {
          "lang": "zh-cn",
          "aspect": "9:16",
          "kind": "video",
          "title": "什么是向量数据库",
          "output_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4?example=video-001"
        }
      ],
      "project": {
        "tarball_url": null,
        "outputs": [
          "https://…/zh.mp4"
        ]
      },
      "percent": 100,
      "stage": "producing",
      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }
  }
}
```

فيما يلي تعريف حقول النتيجة المرجعة:

- `id`: معرّف مهمة الفيديو هذه، ويُستخدم لتعريف مهمة إنشاء الفيديو هذه بشكل فريد.
- `status`: حالة المهمة، وقيمتها هي `pending → planning → producing → succeeded` (أو `failed`). يُعتمد على `status` العلوي هذا لتحديد ما إذا كانت المهمة قد اكتملت.
- `elapsed`: الوقت المنقضي للمهمة (بالثواني).
- `progress`: كائن التقدم العلوي، سيتم ضبط `percent` (من 0 إلى 100) إلى 100 كقيمة احتياطية بعد نجاح المهمة؛ ويعكس `stage` و`message` أحدث حدث تقدم لمخرج الذكاء الاصطناعي (لذلك قد تظل `stage` بعد النجاح في مرحلة التنفيذ الأخيرة مثل `producing`)، ويمكن استخدامها مباشرةً لعرض شريط التقدم.
- `request`: نص الطلب عند بدء المهمة.
- `response`: معلومات الاستجابة للمهمة.
  - `success`: ما إذا كانت المهمة ناجحة.
  - `data.variants`: يحتوي على كائن الفيديو النهائي للغة المختارة، بما في ذلك `lang` و`aspect` و`title` و`output_url` (عنوان تنزيل الفيديو النهائي) وغيرها.
  - `data.project`: مخرجات المشروع بأكمله، بما في ذلك `tarball_url` (حزمة المشروع) و`outputs` (روابط الفيديو النهائي).
  - `data.progress`: مصفوفة أحداث تقدم مضافة حسب المرحلة (سجل للملحقات فقط)، ويمكن استخدامها لعرض تقدم مفصل في الوقت الفعلي.
- `created_at`: وقت إنشاء المهمة، طابع زمني Unix (بالثواني).
- `started_at`: وقت بدء تنفيذ المهمة، طابع زمني Unix (بالثواني). يكون null عندما لا تبدأ المهمة بعد.
- `finished_at`: وقت اكتمال المهمة، طابع زمني Unix (بالثواني). يكون null عندما لا تكتمل المهمة.

## الاستعلام عن قائمة السجل

مرر `action: retrieve_batch` للحصول على أحدث مهام المنفذ المسجل دخوله حاليًا (بترتيب تنازلي حسب وقت الإنشاء)، ويمكن استخدامه لصفحة قائمة «فيديوهاتي». تُعزل قائمة السجل حسب هوية تسجيل الدخول.

يتضمن **Request Body** ما يلي:

| الحقل               | النوع     | مطلوب  | الوصف                              |
| ---------------- | ------ | --- | ------------------------------- |
| `action`         | string | نعم   | ثابتًا `retrieve_batch`            |
| `limit`          | int    | لا   | عدد العناصر المرجعة، الافتراضي 20؛ النطاق الفعّال من 1 إلى 100          |
| `created_at_max` | int    | لا   | يُرجع فقط المهام الأقدم بشكل صارم من طابع Unix الزمني هذا (دون قيمة الحد، للاستخدام في التصفح بين الصفحات) |
| `created_at_min` | int    | لا   | يُرجع فقط المهام الأحدث بشكل صارم من طابع Unix الزمني هذا (دون قيمة الحد)     |

### مثال على الكود

كود CURL المقابل كما يلي:
```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### مثال على الاستجابة

بعد نجاح الطلب، ستُرجع واجهة API قائمة بالمهام السابقة للمستخدم الحالي:

```json
{
  "count": 2,
  "items": [
    {
      "id": "f57e99c4f60f4373a15517742ce2357d",
      "started_at": 1769262721.823,
      "finished_at": 1769264698.3,
      "elapsed": 1976.477,
      "status": "succeeded",
      "progress": {
        "percent": 100,
        "stage": "producing",
        "message": "rendering scene 2"
      },
      "request": {
        "prompt": "…",
        "langs": [
          "zh-cn"
        ],
        "aspect": "9:16",
        "duration": 20
      },
      "response": {
        "success": true,
        "data": {
          "variants": [
            {
              "lang": "zh-cn",
              "output_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4?example=video-003"
            }
          ]
        }
      }
    }
  ]
}
```

فيما يلي وصف لحقول نتيجة الإرجاع:

- `count`: إجمالي عدد المهام المرئية للمنفّذ الذي سجل الدخول حالياً، ولا يتأثر بشروط الوقت أو `limit`.
- `items`: مصفوفة المهام المُصفّاة وفقاً لشروط الوقت و`limit`، والمرتبة ترتيباً تنازلياً حسب وقت الإنشاء؛ ويتطابق تنسيق كل عنصر مع نتيجة الإرجاع الخاصة بـ«الاستعلام عن مهمة واحدة».

## توصيات الاستعلام الدوري

نظراً لأن إنتاج الفيديو يستغرق وقتاً طويلاً، سيمر `status` بالمراحل `pending → planning → producing → succeeded` (أو `failed`). يُنصح بالاستعلام الدوري كل 5–10 ثوانٍ، حتى يتغير `status` إلى `succeeded` أو `failed`. يمكن استخدام `progress.percent` في المستوى الأعلى لعرض شريط تقدم في الوقت الفعلي. **الاستعلام الدوري عن هذه الواجهة مجاني ولا يستهلك نقاطاً.**

## معالجة الأخطاء

عند استدعاء واجهة API، إذا واجهت خطأً، فستُرجع واجهة API رمز الخطأ ومعلوماته المقابلة. على سبيل المثال:

- `401 invalid_token`: غير مصرح، رمز التفويض غير صالح أو مفقود.
- `404 not_found`: لم يتم العثور على المهمة، لا يوجد `task_id` المحدد.
- `429 too_many_requests`: طلبات كثيرة جداً، لقد تجاوزت حد المعدل.
- `500 api_error`: خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة خطأ

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

من خلال هذا المستند، تعرفت على كيفية استخدام واجهة API للاستعلام عن مهام Maestro للتحقق من حالة ونتيجة مهمة واحدة، وكذلك جلب قائمة المهام السابقة للمستخدم الحالي. نأمل أن يساعدك هذا المستند على التكامل مع واجهة API هذه واستخدامها بشكل أفضل. إذا كانت لديك أي أسئلة، فيرجى الاتصال بفريق الدعم الفني لدينا في أي وقت.
