الوظيفة الرئيسية لواجهة برمجة التطبيقات لاستعلام المهام في Maestro هي استعلام حالة التنفيذ والنتيجة النهائية لمهمة معينة من خلال معرف المهمة الذي تم إرجاعه بواسطة [واجهة برمجة التطبيقات لإنشاء الفيديو في Maestro](development_maestro_videos.md) (`POST /maestro/videos`).

ستتناول هذه الوثيقة بالتفصيل كيفية دمج واجهة برمجة التطبيقات لاستعلام المهام في Maestro. نظرًا لأن إنشاء الفيديو هو مهمة غير متزامنة، بعد الإرسال، تحتاج إلى استخدام هذه الواجهة للاستعلام عن التقدم والنتيجة، **الاستعلام مجاني ولا يستهلك نقاط.**

`POST https://api.acedata.cloud/maestro/tasks`

## عملية التقديم

لاستخدام واجهة برمجة التطبيقات لاستعلام المهام في Maestro، يجب أولاً الذهاب إلى [وحدة التحكم في Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على رمز API الخاص بك، للاحتفاظ به كنسخة احتياطية.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد قمت بتسجيل الدخول أو التسجيل بعد، سيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك للتسجيل وتسجيل الدخول، وبعد الانتهاء، سيتم إرجاعك تلقائيًا إلى الصفحة الحالية.

**يمكن استخدام رمز API واحد لاستدعاء جميع خدمات المنصة، دون الحاجة لتقديم طلب منفصل لكل خدمة.** عند التقديم لأول مرة، ستحصل على رصيد مجاني لتجربته؛ عند نفاد الرصيد، يمكنك إعادة شحن الرصيد العام في [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثيقة الكاملة: [واجهة برمجة التطبيقات لاستعلام المهام في Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## استعلام عن مهمة واحدة

للحصول على معلومات حول كيفية إنشاء مهمة فيديو، يرجى الرجوع إلى الوثيقة [واجهة برمجة التطبيقات لإنشاء الفيديو في Maestro](development_maestro_videos.md). سنستخدم معرف مهمة تم إرجاعه كمثال: `f57e99c4f60f4373a15517742ce2357d`، لعرض كيفية استعلام عن حالته ونتيجته.

### إعداد رأس الطلب وجسم الطلب

**رؤوس الطلب** تشمل:

- `accept`: تحديد استلام نتائج الاستجابة بتنسيق JSON، هنا يتم ملؤه بـ `application/json`.
- `authorization`: مفتاح استدعاء واجهة برمجة التطبيقات، يمكن اختياره مباشرة بعد التقديم.
- `content-type`: تنسيق جسم الطلب، هنا يتم ملؤه بـ `application/json`.

**جسم الطلب** يشمل:

| الحقل       | النوع     | إلزامي  | الشرح                                                |
| -------- | ------ | --- | ------------------------------------------------- |
| `id`     | string | نعم   | `task_id` الذي تم إرجاعه بواسطة `POST /maestro/videos`              |
| `action` | string | لا   | `retrieve` (افتراضي، استعلام عن مهمة واحدة) / `retrieve_batch` (استعلام عن قائمة المهام التاريخية) |

### مثال على الكود

الكود المقابل لـ CURL هو كما يلي:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

الكود المقابل لـ Python هو كما يلي:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### مثال على الاستجابة

بعد نجاح الطلب، ستقوم واجهة برمجة التطبيقات بإرجاع حالة ونتيجة مهمة الفيديو هذه. مثال على الاستجابة عند اكتمال المهمة هو كما يلي (كل لغة تتوافق مع `variant` واحد):

```json
{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "started_at": 1769262721.823,
  "finished_at": 1769264698.3,
  "elapsed": 1976.477,
  "status": "succeeded",
  "progress": {
    "percent": 100,
    "stage": "producing",
    "message": "rendering scene 2"
  },
  "request": {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": [
      "zh-cn",
      "en"
    ],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        {
          "lang": "zh-cn",
          "aspect": "9:16",
          "kind": "video",
          "title": "什么是向量数据库",
          "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-001"
        },
        {
          "lang": "en",
          "aspect": "9:16",
          "kind": "video",
          "title": "What is a vector database",
          "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-002"
        }
      ],
      "project": {
        "tarball_url": null,
        "outputs": [
          "https://…/zh.mp4",
          "https://…/en.mp4"
        ]
      },
      "percent": 100,
      "stage": "producing",
      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }
  }
}
```

تقديم معلومات حول حقول النتيجة كما يلي:

- `id`: معرف هذه المهمة الفيديو، يستخدم لتحديد مهمة إنشاء الفيديو هذه بشكل فريد.
- `status`: حالة المهمة، القيم الممكنة هي `pending → planning → producing → succeeded` (أو `failed`). يتم تحديد ما إذا كانت المهمة قد اكتملت بناءً على `status` العلوي.
- `elapsed`: الوقت المستغرق للمهمة (بالثواني).
- `progress`: كائن التقدم العلوي، `percent` (0–100) سيتم تعيينه إلى 100 بعد نجاح المهمة؛ `stage` و `message` تعكس أحدث حدث تقدم من AI، يمكن استخدامها مباشرة لعرض شريط التقدم.
- `request`: جسم الطلب عند بدء المهمة.
- `response`: معلومات العودة للمهمة.
  - `success`: ما إذا كانت المهمة ناجحة.
  - `data.variants`: كل لغة تتوافق مع كائن نتيجة، تحتوي على `lang`، `aspect`، `title`، `output_url` (رابط تحميل النتيجة) وغيرها.
  - `data.project`: المنتج الكامل للمشروع، يحتوي على `tarball_url` (حزمة المشروع) و `outputs` (جميع روابط النتائج).
  - `data.progress`: مصفوفة أحداث التقدم المضافة حسب المرحلة (سجل إضافي فقط)، يمكن استخدامها لعرض التقدم التفصيلي في الوقت الحقيقي.
- `created_at`: وقت إنشاء المهمة، طابع زمني Unix (بالثواني).
- `started_at`: وقت بدء تنفيذ المهمة، طابع زمني Unix (بالثواني). يكون null عندما لا تبدأ المهمة بعد.
- `finished_at`: وقت انتهاء المهمة، طابع زمني Unix (بالثواني). يكون null عندما لا تكتمل المهمة.

## استعلام عن القائمة التاريخية

يمكنك الحصول على المهام الأخيرة للمستخدم الحالي (مرتبة حسب وقت الإنشاء بترتيب تنازلي) عن طريق تمرير `action: retrieve_batch`، ويمكن استخدامها في صفحة "فيديوهاتي".

**جسم الطلب** يشمل:
| الحقل               | النوع     | مطلوب  | الشرح                      |
| ---------------- | ------ | --- | ----------------------- |
| `action`         | سلسلة | نعم   | ثابت كـ `retrieve_batch`    |
| `limit`          | عدد صحيح    | لا   | عدد النتائج، الافتراضي 20              |
| `created_at_max` | عدد صحيح    | لا   | يعيد فقط المهام التي تسبق طابع الوقت Unix هذا (للتصفح) |
| `created_at_min` | عدد صحيح    | لا   | يعيد فقط المهام التي تتجاوز طابع الوقت Unix هذا      |

### مثال على الكود

الكود المقابل لـ CURL هو كما يلي:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

      "status": "succeeded",
      "progress": {
        "percent": 100,
        "stage": "producing",
        "message": "rendering scene 2"
      },
      "request": {
        "prompt": "…",
        "langs": [
          "zh-cn",

- `items`：مصفوفة المهام، كل عنصر يتوافق مع تنسيق نتيجة "استعلام مهمة واحدة".

## اقتراحات الاستطلاع

نظرًا لأن إنتاج الفيديو يستغرق وقتًا طويلاً، فإن `status` سيتغير من `pending → planning → producing → succeeded` (أو `failed`). يُنصح بالاستطلاع كل 5-10 ثوانٍ حتى يتغير `status` إلى `succeeded` أو `failed`. يمكن استخدام `progress.percent` العلوي لعرض شريط تقدم في الوقت الحقيقي. **الاستطلاع على هذه الواجهة مجاني، ولا يستهلك نقاط.**

## معالجة الأخطاء

عند استدعاء API، إذا واجهت خطأ، ستعيد API رمز الخطأ والمعلومات ذات الصلة. على سبيل المثال:

- `401 invalid_token`：غير مصرح، رمز التفويض غير صالح أو مفقود.
- `404 not_found`：لم يتم العثور على المهمة، المعرف المعطى للمهمة غير موجود.
- `429 too_many_requests`：طلبات كثيرة جدًا، لقد تجاوزت حد المعدل.
- `500 api_error`：خطأ في الخادم الداخلي، حدث خطأ ما على الخادم.

### مثال على استجابة الخطأ

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
