تتمثل الوظيفة الرئيسية لـ API استعلام مهام Maestro في الاستعلام عن حالة تنفيذ المهمة ونتيجتها النهائية من خلال معرّف المهمة الذي تُرجعه [واجهة API لإنشاء فيديو Maestro](development_maestro_videos.md) (`POST /maestro/videos`).

ستعرض هذه الوثيقة بالتفصيل دليل تكامل API لاستعلام مهام Maestro. نظرًا لأن إنشاء الفيديو مهمة غير متزامنة، يجب استخدام هذه الواجهة للاستعلام الدوري عن التقدم والفيديو النهائي بعد الإرسال، **والاستعلام الدوري مجاني ولا يستهلك رصيدًا.**

`POST https://api.acedata.cloud/maestro/tasks`

## عملية التقديم

لاستخدام API استعلام مهام Maestro، انتقل أولًا إلى [لوحة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم تلقائيًا تحويلك إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وستعود تلقائيًا إلى الصفحة الحالية بعد الإكمال.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** سيُمنح رصيد مجاني عند أول تقديم، ويمكنك التجربة مجانًا؛ وعندما لا يكون الرصيد كافيًا، يمكنك شحن الرصيد العام من [لوحة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [API استعلام مهام Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## الاستعلام عن مهمة واحدة

لمعرفة كيفية إنشاء مهمة فيديو، يُرجى الرجوع إلى وثيقة [واجهة API لإنشاء فيديو Maestro](development_maestro_videos.md). سنأخذ معرّف مهمة أرجعته كمثال: `f57e99c4f60f4373a15517742ce2357d`، لعرض كيفية الاستعلام عن حالتها ونتيجتها.

### إعداد رؤوس الطلب وجسم الطلب

تشمل **رؤوس الطلب** ما يلي:

- `accept`: يحدد استجابة النتائج بتنسيق JSON، ويُملأ هنا بـ `application/json`.
- `authorization`: مفتاح استدعاء API، ويمكن اختياره مباشرةً من القائمة المنسدلة بعد التقديم.
- `content-type`: تنسيق جسم الطلب، ويُملأ هنا بـ `application/json`.

يشمل **جسم الطلب** ما يلي:

| الحقل       | النوع     | مطلوب عند        | الوصف                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | مطلوب عند الاستعلام عن مهمة واحدة | `task_id` الذي يُرجعه `POST /maestro/videos`              |
| `action` | string | لا         | `retrieve` (افتراضي، للاستعلام عن مهمة واحدة)؛ وعند الاستعلام عن قائمة السجل يكون ثابتًا `retrieve_batch` |

### مثال على الكود

كود CURL المقابل كما يلي:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

كود Python المقابل كما يلي:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### مثال على الاستجابة

بعد نجاح الطلب، ستُرجع API حالة ونتيجة مهمة الفيديو هذه. المثال التالي للاستجابة عند اكتمال المهمة (يقابل كل لغة `variant` واحد):

```json
{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "started_at": 1769262721.823,
  "finished_at": 1769264698.3,
  "elapsed": 1976.477,
  "status": "succeeded",
  "progress": {
    "percent": 100,
    "stage": "producing",
    "message": "rendering scene 2"
  },
  "request": {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": [
      "zh-cn",
      "en"
    ],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        {
          "lang": "zh-cn",
          "aspect": "9:16",
          "kind": "video",
          "title": "什么是向量数据库",
          "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-001"
        },
        {
          "lang": "en",
          "aspect": "9:16",
          "kind": "video",
          "title": "What is a vector database",
          "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-002"
        }
      ],
      "project": {
        "tarball_url": null,
        "outputs": [
          "https://…/zh.mp4",
          "https://…/en.mp4"
        ]
      },
      "percent": 100,
      "stage": "producing",
      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }
  }
}
```

فيما يلي تعريف حقول النتيجة المرجعة:

- `id`: معرّف مهمة الفيديو هذه، ويُستخدم لتمييز مهمة إنشاء الفيديو هذه بشكل فريد.
- `status`: حالة المهمة، وقيمتها هي `pending → planning → producing → succeeded` (أو `failed`). يعتمد اكتمال المهمة على `status` هذا في المستوى الأعلى.
- `elapsed`: الوقت المنقضي للمهمة (بالثواني).
- `progress`: كائن التقدم في المستوى الأعلى؛ سيُضبط `percent` (من 0 إلى 100) على 100 كقيمة احتياطية بعد نجاح المهمة؛ ويعكس `stage` و`message` أحدث حدث تقدم لمخرج الذكاء الاصطناعي (لذلك قد يبقى `stage` بعد النجاح في مرحلة التنفيذ الأخيرة مثل `producing`)، ويمكن استخدامه مباشرةً لعرض شريط التقدم.
- `request`: جسم الطلب عند بدء المهمة.
- `response`: معلومات إرجاع المهمة.
  - `success`: ما إذا كانت المهمة ناجحة.
  - `data.variants`: يقابل كل لغة كائن فيديو نهائي واحد، ويحتوي على `lang` و`aspect` و`title` و`output_url` (عنوان تنزيل الفيديو النهائي) وغيرها.
  - `data.project`: مخرجات المشروع بالكامل، وتحتوي على `tarball_url` (حزمة المشروع) و`outputs` (جميع روابط الفيديوهات النهائية).
  - `data.progress`: مصفوفة أحداث التقدم المضافة حسب المراحل (سجل append-only)، ويمكن استخدامها لعرض التقدم التفصيلي في الوقت الفعلي.
- `created_at`: وقت إنشاء المهمة، طابع زمني Unix (بالثواني).
- `started_at`: وقت بدء تنفيذ المهمة، طابع زمني Unix (بالثواني). تكون null عندما لم تبدأ المهمة بعد.
- `finished_at`: وقت اكتمال المهمة، طابع زمني Unix (بالثواني). تكون null عندما لا تكون المهمة مكتملة.

## الاستعلام عن قائمة السجل

مرر `action: retrieve_batch` للحصول على المهام الأخيرة للمنفذ المسجل دخوله حاليًا (مرتبة تنازليًا حسب وقت الإنشاء)، ويمكن استخدامه لصفحة قائمة «فيديوهاتي». تُعزل قائمة السجل حسب هوية تسجيل الدخول.

يشمل **جسم الطلب** ما يلي:
| الحقل               | النوع     | مطلوب  | الوصف                              |
| ---------------- | ------ | --- | ------------------------------- |
| `action`         | string | نعم   | ثابت على `retrieve_batch`            |
| `limit`          | int    | لا   | عدد النتائج المُعادة، الافتراضي 20؛ النطاق الفعّال هو 1–100          |
| `created_at_max` | int    | لا   | إرجاع المهام الأقدم بشكل صارم من طابع Unix الزمني هذا فقط (لا يشمل القيمة الحدية، للاستخدام في الترقيم) |
| `created_at_min` | int    | لا   | إرجاع المهام الأحدث بشكل صارم من طابع Unix الزمني هذا فقط (لا يشمل القيمة الحدية)     |

### مثال على الكود

كود CURL المقابل كما يلي:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### مثال على الاستجابة

بعد نجاح الطلب، ستُرجع API قائمة المهام السابقة للمستخدم الحالي:

```json
{
  "count": 2,
  "items": [
    {
      "id": "f57e99c4f60f4373a15517742ce2357d",
      "started_at": 1769262721.823,
      "finished_at": 1769264698.3,
      "elapsed": 1976.477,
      "status": "succeeded",
      "progress": {
        "percent": 100,
        "stage": "producing",
        "message": "rendering scene 2"
      },
      "request": {
        "prompt": "…",
        "langs": [
          "zh-cn",
          "en"
        ],
        "aspect": "9:16",
        "duration": 20
      },
      "response": {
        "success": true,
        "data": {
          "variants": [
            {
              "lang": "zh-cn",
              "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-003"
            }
          ]
        }
      }
    }
  ]
}
```

تعريف حقول النتائج المُعادة كما يلي:

- `count`: إجمالي عدد المهام المرئية للمنفّذ المسجّل دخوله حاليًا، ولا يتأثر بشروط الوقت أو `limit`.
- `items`: مصفوفة المهام التي تمت تصفيتها وفقًا لشروط الوقت و`limit`، ومرتبة ترتيبًا تنازليًا حسب وقت الإنشاء؛ يتطابق تنسيق كل عنصر مع نتيجة «الاستعلام عن مهمة واحدة».

## توصيات الاستطلاع

نظرًا لأن إنتاج الفيديو يستغرق وقتًا طويلًا، سيمر `status` عبر `pending → planning → producing → succeeded` (أو `failed`). يُوصى بالاستطلاع مرة كل 5–10 ثوانٍ، حتى يصبح `status` هو `succeeded` أو `failed`. يمكن استخدام `progress.percent` في المستوى الأعلى لعرض شريط التقدم في الوقت الفعلي. **استطلاع هذه الواجهة مجاني ولا يستهلك نقاطًا.**

## معالجة الأخطاء

عند استدعاء API، إذا واجهت خطأً، فستُرجع API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `401 invalid_token`: غير مصرّح، رمز التفويض غير صالح أو مفقود.
- `404 not_found`: لم يتم العثور على المهمة، وtask_id المحدد غير موجود.
- `429 too_many_requests`: طلبات كثيرة جدًا، لقد تجاوزت حد المعدل.
- `500 api_error`: خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة الخطأ

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## الخلاصة

من خلال هذا المستند، تعرفت بالفعل على كيفية استخدام API الاستعلام عن مهام Maestro للاستعلام عن حالة ونتيجة مهمة واحدة، وكذلك جلب قائمة المهام السابقة للمستخدم الحالي. نأمل أن يساعدك هذا المستند على الربط واستخدام API بشكل أفضل. إذا كانت لديك أي أسئلة، فيُرجى التواصل مع فريق الدعم الفني لدينا في أي وقت.
