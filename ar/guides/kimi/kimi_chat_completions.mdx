Kimi هي سلسلة نماذج ذكاء اصطناعي أطلقتها Moonshot AI. يُوصى حاليًا بـ `kimi-k3.1-pro`، وهو مناسب للبرمجة طويلة المدى، والاستدلال المعقد، والفهم البصري، والعمل المعرفي؛ ولا يزال `kimi-k3` متاحًا للاستخدام. يتم الاستدعاء عبر واجهة Chat Completions API المتوافقة مع OpenAI.

يقدم هذا المستند بشكل أساسي عملية استخدام واجهة Kimi Chat Completion API، وباستخدامها يمكننا بسهولة استخدام وظيفة المحادثة الرسمية لـ Kimi.

## عملية التقديم

لاستخدام واجهة Kimi Chat Completion API، انتقل أولًا إلى [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وستعود تلقائيًا إلى الصفحة الحالية بعد الإكمال.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** سيُمنح رصيد مجاني عند أول تقديم، مما يتيح تجربة مجانية؛ وعند عدم كفاية الرصيد، يمكنك شحن الرصيد العام من [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 المستند الكامل: [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## الاستخدام الأساسي

بعد ذلك، يمكنك ملء المحتوى المقابل في الواجهة، كما هو موضح في الشكل:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

عند استخدام هذه الواجهة لأول مرة، تحتاج إلى ملء ثلاثة محتويات على الأقل: يمكن اختيار `authorization` مباشرةً من القائمة المنسدلة؛ يُستخدم `model` لاختيار نموذج Kimi، ويُوصى باستخدام `kimi-k3.1-pro`؛ و`messages` هي مصفوفة رسائل المحادثة، وتحتوي كل رسالة على `role` و`content`، حيث يدعم `role` القيم `user` و`assistant` و`system` و`tool`.

في الوقت نفسه، يمكنك ملاحظة وجود توليد كود الاستدعاء المقابل على الجانب الأيمن، ويمكنك نسخ الكود وتشغيله مباشرةً، أو النقر مباشرةً على زر «Try» للاختبار.

<p><img src="https://cdn.acedata.cloud/six7e3.png" width="400" className="m-auto" /></p>

فيما يلي استجابة K3 حقيقية تم الحصول عليها باستخدام `reasoning_effort: max` (مع حذف الحقول الموسعة غير المستخدمة):

```json
{
  "id": "msg_2D4Btbg1WgvkNE3tCYkR4xGA",
  "object": "chat.completion",
  "created": 1784466588,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 86,
    "completion_tokens": 206,
    "total_tokens": 292
  }
}
```

تحتوي النتيجة المعادة على عدة حقول، وهي موضحة كما يلي:

- `id`، معرّف مهمة المحادثة التي تم إنشاؤها هذه المرة، ويُستخدم لتعريف مهمة المحادثة هذه بشكل فريد.
- `model `، نموذج موقع Kimi الرسمي المحدد.
- `choices` معلومات الإجابة التي يقدمها Kimi على نص السؤال.
- `usage `: معلومات إحصائية عن token لهذه المحادثة.

من بينها، يحتوي `choices` على معلومات إجابة Kimi، و`choices` الموجود بداخله هو المعلومات التفصيلية لإجابة Kimi، كما يمكن ملاحظته في الشكل.

<p><img src="https://cdn.acedata.cloud/tv9rul.png" width="400" className="m-auto" /></p>

يمكن ملاحظة أن حقل `content` داخل `choices` يحتوي على المحتوى التفصيلي لرد Kimi؛ وقد يعيد K3 أيضًا `reasoning_content`، ويُستخدم لتمثيل عملية الاستدلال.

## قوة استدلال K3.1 Pro

يُفعّل `kimi-k3.1-pro` الاستدلال دائمًا. يمكن تعيين `reasoning_effort` في المستوى الأعلى من نص الطلب إلى `low` أو `high` أو `max`؛ لا تمرر إعدادًا لتعطيل الاستدلال. يدعم النموذج سياقًا يصل إلى 1,048,576 token، لكن الحد الفعلي للطلب يظل خاضعًا للواجهة الحالية. تُحسب الأسعار وفقًا لاستخدام الإدخال والإخراج وضربات ذاكرة التخزين المؤقت، راجع بطاقة Pricing في كتالوج النماذج للتفاصيل.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

يُحتفظ بمثال K3 التالي للتكاملات الحالية، وقد تم الحصول على الاستجابة النموذجية بالفعل من طلب K3.

## قوة استدلال K3

يُفعّل `kimi-k3` الاستدلال دائمًا. يدعم المستوى الأعلى من نص الطلب حقل `reasoning_effort`، والقيمة الوحيدة المدعومة حاليًا هي `max`؛ وعند حذف هذا الحقل، يُستخدم `max` أيضًا. قد يتم قبول `standard` أو `high` أو سلاسل أخرى بشكل متساهل من بعض المصادر المتوافقة، لكن لا يوجد ضمان بأنها ستغير سلوك الاستدلال، لذا لا تعتمد عليها.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

عند استخدام OpenAI SDK، يمكن تمرير هذا الحقل مباشرةً:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

عند إجراء محادثات متعددة الجولات واستدعاء الأدوات، يُرجى إعادة تمرير رسالة assistant الكاملة من الجولة السابقة إلى `messages`، بما في ذلك `reasoning_content` و`tool_calls`.

### المراجع الرسمية

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort): يوضح أن Kimi K3 يفعّل الاستدلال دائمًا، وأن القيمة الوحيدة المدعومة حاليًا لـ `reasoning_effort` هي `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview): يقارن معلمات الاستدلال، ونافذة السياق، واختلافات استدعاء الأدوات بين K3 وسلسلة K2.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat): طلبات Chat Completions الرسمية من Moonshot، والاستجابات، وتعريفات حقول OpenAPI.

## الاستجابة المتدفقة

تدعم هذه الواجهة أيضًا الاستجابة المتدفقة، وهذا مفيد جدًا لتكامل صفحات الويب، إذ يمكن أن يتيح للصفحة تحقيق تأثير العرض حرفًا بحرف.

إذا أردت إعادة الاستجابة بشكل متدفق، يمكنك تغيير معلمة `stream ` في رأس الطلب إلى `true`.

يكون التعديل كما هو موضح في الشكل، لكن كود الاستدعاء يحتاج إلى تعديلات مقابلة حتى يدعم الاستجابة المتدفقة.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>

بعد تعديل `stream` إلى `true`، ستعيد API بيانات JSON المقابلة سطرًا بسطر، وعلى مستوى الكود نحتاج إلى إجراء التعديلات المقابلة للحصول على النتائج سطرًا بسطر.

كود استدعاء مثال Python:
```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

فيما يلي مقتطفات من كتل بيانات البداية والاستدلال والنص الأساسي والنهاية والاستخدام ضمن الاستجابة المتدفقة الحقيقية نفسها لـ K3 Max:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

يمكن ملاحظة أن الاستجابة تحتوي على العديد من `data`، و`choices` داخل `data` هي أحدث محتوى للإجابة، وهو متسق مع المحتوى المقدّم أعلاه. تمثل `choices` محتوى الإجابة المُضاف حديثًا، ويمكنك ربطها بنظامك وفقًا للنتائج. وفي الوقت نفسه، يتم تحديد نهاية الاستجابة المتدفقة وفقًا لمحتوى `data`؛ فإذا كان المحتوى هو `[DONE]`، فهذا يشير إلى أن إجابة الاستجابة المتدفقة قد انتهت بالكامل. تحتوي نتيجة `data` المُعادة على عدة حقول، وهي موضحة كما يلي:

- `id`، معرّف مهمة الحوار التي تم إنشاؤها هذه المرة، ويُستخدم لتمييز مهمة الحوار هذه بشكل فريد.
- `model `، نموذج Kimi الرسمي المحدد.
- `choices`، معلومات الإجابة التي يقدمها Kimi على كلمات الاستعلام.

يدعم JavaScript أيضًا، فعلى سبيل المثال، يكون رمز الاستدعاء المتدفق لـ Node.js كما يلي:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

رمز مثال Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

يمكن إعادة كتابة اللغات الأخرى بشكل منفصل، فالمبدأ هو نفسه.

## الحوار متعدد الجولات

إذا كنت ترغب في ربط وظيفة الحوار متعدد الجولات، فأنت بحاجة إلى رفع عدة كلمات استعلام إلى حقل `messages`، ويظهر المثال المحدد لكلمات الاستعلام المتعددة كما في الشكل أدناه:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

رمز استدعاء مثال Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"

payload = {
    "model": "kimi-k3",

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## معالجة الأخطاء

عند استدعاء API، إذا واجهت خطأً، فستُرجع API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صالح، وقد يكون ذلك بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صالح، وقد يكون ذلك بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح، رمز التفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جدًا، لقد تجاوزت حد المعدل.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة خطأ

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## الخلاصة

من خلال هذه الوثيقة، تكون قد فهمت كيفية استخدام Kimi Chat Completion API لتنفيذ المحادثات العادية والاستجابات المتدفقة والحوار متعدد الجولات، وكذلك التحكم في شدة استدلال K3 عبر `reasoning_effort`.
