Kimi هي سلسلة من نماذج الذكاء الاصطناعي التي أطلقتها شركة Moonshot AI. النموذج الموصى به حاليًا هو `kimi-k3.1-pro`، وهو مناسب للبرمجة طويلة المدى، والاستدلال المعقد، وفهم الصور، والأعمال المعرفية؛ ولا يزال بالإمكان استخدام `kimi-k3`. ويتم استدعاؤه من خلال واجهة Chat Completions API المتوافقة مع OpenAI.

تقدم هذه الوثيقة بشكل أساسي شرحًا لعملية استخدام واجهة Kimi Chat Completion API، والتي تتيح لنا الاستفادة بسهولة من وظائف المحادثة الرسمية لنموذج Kimi.

## النماذج المدعومة

تدعم الواجهة حاليًا أربعة نماذج: `kimi-k3.1-pro` و`kimi-k3` و`kimi-k2.6` و`kimi-k2.7-code`. يستهدف K2.7 Code سيناريوهات البرمجة واستدعاء الأدوات، وتُحتسب تكلفته وفق سعر الفئة نفسها من K2.6؛ ولا تمرّر إليه مفتاح `thinking` أو `reasoning_effort` في الطلب. تم إيقاف دعم نماذج Kimi الأخرى، لذا يُرجى تحديد أحد هذه النماذج الأربعة صراحةً في العميل.

## خطوات التقديم

لاستخدام واجهة Kimi Chat Completion API، انتقل أولاً إلى [لوحة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على رمز API Token الخاص بك، واحتفظ به لاستخدامه لاحقًا.

![]()

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد إكمال العملية ستتم إعادتك تلقائيًا إلى الصفحة الحالية.

**يمكن استخدام رمز API Token واحد لاستدعاء جميع خدمات المنصة، دون الحاجة إلى تقديم طلب منفصل لكل خدمة.** عند التقديم لأول مرة، ستحصل على رصيد مجاني يمكنك استخدامه للتجربة مجانًا؛ وعندما يصبح الرصيد غير كافٍ، يمكنك شحن الرصيد العام من خلال [لوحة التحكم](https://platform.acedata.cloud/console/coin).

## الاستخدام الأساسي

بعد ذلك، يمكنك ملء المحتويات المقابلة في الواجهة، كما هو موضح في الصورة:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

عند استخدام هذه الواجهة لأول مرة، يلزم ملء ثلاثة عناصر على الأقل: يمكن تحديد `authorization` مباشرةً من القائمة المنسدلة؛ ويُستخدم `model` لاختيار نموذج Kimi، ويوصى باستخدام `kimi-k3.1-pro`؛ أما `messages` فهي مصفوفة رسائل المحادثة، وتتضمن كل رسالة `role` و`content`، حيث يدعم `role` القيم `user` و`assistant` و`system` و`tool`.

وفي الوقت نفسه، يمكنك ملاحظة وجود كود الاستدعاء المقابل الذي يتم إنشاؤه على الجانب الأيمن، ويمكنك نسخ الكود وتشغيله مباشرةً، أو النقر مباشرةً على زر «Try» لإجراء الاختبار.

<p><img src="https://cdn.acedata.cloud/six7e3.png" width="400" className="m-auto" /></p>

فيما يلي استجابة حقيقية من K3 تم الحصول عليها باستخدام `reasoning_effort: max` (مع حذف الحقول الإضافية غير المستخدمة):

```json
{
  "id": "msg_2D4Btbg1WgvkNE3tCYkR4xGA",
  "object": "chat.completion",
  "created": 1784466588,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 86,
    "completion_tokens": 206,
    "total_tokens": 292
  }
}
```

تتضمن نتيجة الاستجابة عدة حقول، وفيما يلي شرحها:

- `id`: معرّف مهمة المحادثة التي تم إنشاؤها، ويُستخدم لتحديد مهمة المحادثة هذه بشكل فريد.
- `model `: نموذج Kimi الرسمي الذي تم اختياره.
- `choices`: معلومات الإجابة التي يقدمها Kimi استجابةً لنص السؤال.
- `usage `: إحصائيات استخدام الرموز (Token) الخاصة بعملية السؤال والجواب الحالية.

من بينها، يحتوي `choices` على معلومات إجابة Kimi، ويتضمن `choices` بداخله التفاصيل المحددة لإجابة Kimi، كما يمكن ملاحظة ذلك في الصورة التالية.

<p><img src="https://cdn.acedata.cloud/tv9rul.png" width="400" className="m-auto" /></p>

يمكن ملاحظة أن حقل `content` داخل `choices` يحتوي على المحتوى الفعلي لرد Kimi؛ وقد يُرجع K3 أيضًا `reasoning_content` لتمثيل عملية الاستدلال.

## مستوى الاستدلال في K3.1 Pro

يُفعّل `kimi-k3.1-pro` الاستدلال بشكل دائم. يمكنك تعيين `reasoning_effort` في المستوى الأعلى من جسم الطلب إلى `low` أو `high` أو `max`؛ ولا تمرّر أي إعداد لتعطيل الاستدلال. يدعم النموذج سياقًا يصل إلى 1,048,576 رمزًا (Token)، لكن الحد الأقصى الفعلي للطلب يظل خاضعًا للواجهة الحالية. تُحتسب الأسعار وفقًا لحجم الاستخدام من المدخلات والمخرجات والطلبات التي تحقق إصابة ذاكرة التخزين المؤقت، ويمكن الاطلاع على التفاصيل في بطاقة Pricing ضمن دليل النماذج.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

يتم الاحتفاظ بأمثلة K3 التالية لاستخدامها في عمليات التكامل الحالية، وقد تم بالفعل الحصول على استجابة المثال من طلب K3.

## مستوى الاستدلال في K3

يُفعّل `kimi-k3` الاستدلال بشكل دائم. يدعم المستوى الأعلى من جسم الطلب الحقل `reasoning_effort`، والقيمة الوحيدة المدعومة حاليًا هي `max`؛ وعند حذف هذا الحقل، يتم استخدام `max` أيضًا. يُرجى استخدام القيم المدعومة.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

عند استخدام OpenAI SDK، يمكنك تمرير هذا الحقل مباشرةً:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

عند إجراء محادثات متعددة الجولات واستدعاء الأدوات، يُرجى إعادة إرسال رسالة assistant الكاملة من الجولة السابقة إلى `messages`، بما في ذلك `reasoning_content` و`tool_calls`.

### المراجع الرسمية

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort): يوضح أن Kimi K3 يفعّل الاستدلال بشكل دائم، وأن القيمة الوحيدة المدعومة حاليًا لـ `reasoning_effort` هي `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview): يقارن معلمات الاستدلال، ونوافذ السياق، والاختلافات في استدعاء الأدوات بين سلسلتي K3 وK2.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat): تعريفات طلبات واستجابات Chat Completions الرسمية من Moonshot وحقول OpenAPI.

## الاستجابة المتدفقة

تدعم هذه الواجهة أيضًا الاستجابة المتدفقة، وهو أمر مفيد جدًا عند التكامل مع صفحات الويب، إذ يتيح للصفحة تنفيذ تأثير عرض النص حرفًا تلو الآخر.

إذا كنت ترغب في إرجاع الاستجابة بشكل متدفق، فيمكنك تغيير المعلمة `stream ` في ترويسة الطلب إلى `true`.

قم بإجراء التعديل كما هو موضح في الصورة، ولكن يجب تعديل كود الاستدعاء المقابل أيضًا حتى يدعم الاستجابة المتدفقة.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>
بعد تعديل `stream` إلى `true`، ستُرجع واجهة API بيانات JSON المقابلة سطرًا بسطر، وعلى مستوى الكود، نحتاج إلى إجراء التعديلات المناسبة للحصول على النتائج سطرًا بسطر.

مثال على كود الاستدعاء باستخدام Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

فيما يلي مقتطفات من كتل البيانات الأولية والاستدلالية والنصية والختامية وبيانات الاستخدام، ضمن استجابة تدفق حقيقية واحدة لنموذج K3 Max:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

كما يمكن ملاحظة أن الاستجابة تحتوي على العديد من عناصر `data`، وأن `choices` داخل `data` تمثل محتوى الإجابة الأحدث، وهو ما يتوافق مع المحتوى الموضح أعلاه. تمثل `choices` محتوى الإجابة الجديد، ويمكنكم ربطه بنظامكم وفقًا للنتائج. وفي الوقت نفسه، يتم تحديد انتهاء استجابة التدفق بناءً على محتوى `data`. فإذا كان المحتوى هو `[DONE]`، فهذا يعني أن استجابة التدفق قد انتهت بالكامل. تحتوي نتائج `data` المُرجعة على عدة حقول، وفيما يلي توضيح لها:

- `id`، معرّف مهمة المحادثة التي تم إنشاؤها، ويُستخدم لتحديد مهمة المحادثة هذه بشكل فريد.
- `model `، نموذج Kimi الرسمي الذي تم اختياره.
- `choices`، معلومات الإجابة التي يقدمها Kimi استجابةً لنص السؤال.

تدعم JavaScript هذه الميزة أيضًا، على سبيل المثال، فيما يلي كود استدعاء التدفق باستخدام Node.js:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

مثال على كود Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

يمكن تعديل اللغات الأخرى بشكل مستقل، فالمبدأ واحد في جميع الحالات.

## المحادثات متعددة الجولات

إذا كنتم ترغبون في دمج وظيفة المحادثات متعددة الجولات، فيجب إرسال عدة نصوص أسئلة ضمن الحقل `messages`. وفيما يلي مثال توضيحي محدد لنصوص الأسئلة المتعددة كما هو موضح في الصورة أدناه:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

مثال على كود الاستدعاء باستخدام Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

من خلال إرسال عدة نصوص أسئلة، يمكنكم بسهولة تنفيذ محادثات متعددة الجولات. فيما يلي استجابة K3 Max الحقيقية التي تم الحصول عليها من هذا الطلب (مع حذف الحقول الإضافية غير المستخدمة):

## معالجة الأخطاء

عند استدعاء API، إذا حدث خطأ، فستُرجع واجهة API رمز الخطأ والمعلومات المقابلة له. على سبيل المثال:

- `400 token_mismatched`：طلب غير صالح، ربما بسبب فقدان بعض المعلمات أو عدم صلاحيتها.
- `400 api_not_implemented`：طلب غير صالح، ربما بسبب فقدان بعض المعلمات أو عدم صلاحيتها.
- `401 invalid_token`：غير مصرح به، رمز التفويض غير صالح أو مفقود.
- `429 too_many_requests`：عدد كبير جدًا من الطلبات، لقد تجاوزتم الحد المسموح به لمعدل الطلبات.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة الخطأ

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## الخلاصة

من خلال هذه الوثيقة، أصبحتم على دراية بكيفية استخدام Kimi Chat Completion API لتنفيذ المحادثات العادية، واستجابات التدفق، والمحادثات متعددة الجولات، بالإضافة إلى التحكم في قوة الاستدلال لنموذج K3 من خلال `reasoning_effort`.
