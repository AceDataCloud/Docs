تتمثل الوظيفة الرئيسية لـ Fish Tasks API في الاستعلام عن حالة تنفيذ المهمة عبر إدخال معرّف المهمة الذي تم إنشاؤه بواسطة Fish Audios Generation API.

سيقدم هذا المستند بالتفصيل شرح تكامل Fish Tasks API، لمساعدتك على دمج والاستفادة الكاملة من الوظائف القوية لهذه الواجهة بسهولة. من خلال Fish Tasks API، يمكنك بسهولة تنفيذ الاستعلام عن حالة تنفيذ مهام Fish Audios Generation API.

## عملية التقديم

لاستخدام Fish Audios Generation API، انتقل أولاً إلى [لوحة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تقم بتسجيل الدخول أو التسجيل بعد، فسيتم تلقائيًا تحويلك إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائيًا إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** سيُمنحك رصيد مجاني عند التقديم لأول مرة، ويمكنك تجربته مجانًا؛ وعندما لا يكون الرصيد كافيًا، يمكنك شحن الرصيد العام من [لوحة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [Fish Audios Generation API →](https://platform.acedata.cloud/documents/fish-tts)

## مثال على الطلب

يمكن استخدام Fish Tasks API للاستعلام عن نتائج Fish Audios Generation API. حول كيفية استخدام Fish Audios Generation API، يرجى الرجوع إلى الوثائق [Fish Videos Generation API ](https://platform.acedata.cloud/documents/fish-tts-integration).

سنأخذ معرّف مهمة واحدًا تم إرجاعه بواسطة خدمة Fish Audios Generation API كمثال، لعرض كيفية استخدام هذه الواجهة. افترض أن لدينا معرّف مهمة: 2725a2d3-f87e-4905-9c53-9988d5a7b2f5، وسنعرض بعد ذلك كيفية القيام بذلك عبر تمرير معرّف مهمة.

### إعداد رؤوس الطلب وجسم الطلب

يتضمن **Request Headers**:

- `accept`: يحدد استقبال نتائج الاستجابة بتنسيق JSON، ويُملأ هنا بالقيمة `application/json`.
- `authorization`: مفتاح استدعاء API، ويمكن اختياره مباشرة من القائمة المنسدلة بعد التقديم.

يتضمن **Request Body**:

- `id`: معرّف المهمة المرفوع.
- `action`: طريقة تنفيذ العملية على المهمة.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/fish/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2725a2d3-f87e-4905-9c53-9988d5a7b2f5",
  "action": "retrieve"
}'
```


تحتوي النتيجة المُرجعة على عدة حقول، وحقل `request` هو `request body` عند إنشاء المهمة، بينما حقل `response` هو `response body` المُرجع بعد اكتمال المهمة. تعريف الحقول كما يلي.

- `id`، معرّف إنشاء هذه المهمة، ويُستخدم لتمييز مهمة الإنشاء هذه بشكل فريد.
- `request`، معلومات الطلب في مهمة الاستعلام.
- `response`، معلومات الإرجاع في مهمة الاستعلام؛ وعند النجاح النهائي، فإن `cost.amount` بداخله هو Credits التي تم خصمها فعليًا لهذه المرة من التركيب.
- `created_at`، وقت إنشاء المهمة، طابع زمني Unix (بالثواني، عدد عشري).
- `started_at`، وقت بدء تنفيذ المهمة، طابع زمني Unix (بالثواني، عدد عشري).
- `finished_at`، وقت اكتمال المهمة، طابع زمني Unix (بالثواني، عدد عشري). لا يتم إرجاع هذا الحقل عندما لا تكتمل المهمة.
- `elapsed`، الوقت المستغرق في تنفيذ المهمة، بوحدة الثواني (عدد عشري، مع الاحتفاظ بـ 3 منازل عشرية). لا يتم إرجاع هذا الحقل عندما لا تكتمل المهمة.

## معالجة الأخطاء

عند استدعاء API، إذا واجهت خطأً، فسيُرجع API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صالح، قد يكون بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صالح، قد يكون بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح به، رمز تفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جدًا، لقد تجاوزت حد المعدل.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة الخطأ

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
