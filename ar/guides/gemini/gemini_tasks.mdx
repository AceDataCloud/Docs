الوظيفة الرئيسية لواجهة برمجة تطبيقات مهام جمنّي هي استعلام حالة تنفيذ المهمة من خلال إدخال معرف المهمة الذي تم إنشاؤه بواسطة واجهة برمجة تطبيقات توليد فيديوهات جمنّي.

ستتناول هذه الوثيقة تفاصيل تكامل واجهة برمجة تطبيقات مهام جمنّي، لمساعدتك في دمج واستعلام حالة تنفيذ مهام واجهة برمجة تطبيقات توليد فيديوهات جمنّي بسهولة.

## عملية التقديم

لاستخدام واجهة برمجة تطبيقات توليد فيديوهات جمنّي، يجب أولاً الذهاب إلى [وحدة التحكم في سحابة Ace Data](https://platform.acedata.cloud/console/applications) للحصول على رمز API الخاص بك، للاحتفاظ به كنسخة احتياطية.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

إذا لم تكن قد قمت بتسجيل الدخول أو التسجيل بعد، سيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك للتسجيل وتسجيل الدخول، وبعد الانتهاء سيتم العودة تلقائيًا إلى الصفحة الحالية.

**يمكن استخدام رمز API واحد لاستدعاء جميع خدمات المنصة، دون الحاجة لتقديم طلب منفصل لكل خدمة.** عند التقديم لأول مرة، ستحصل على رصيد مجاني لتجربته مجانًا؛ وعند نفاد الرصيد، يمكنك إعادة شحن الرصيد العام في [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [واجهة برمجة تطبيقات توليد فيديوهات جمنّي →](https://platform.acedata.cloud/documents/gemini-videos)

## مثال على الطلب

يمكن استخدام واجهة برمجة تطبيقات مهام جمنّي لاستعلام نتائج واجهة برمجة تطبيقات توليد فيديوهات جمنّي.

### إعداد رأس الطلب وجسم الطلب

**رؤوس الطلب** تشمل:

- `accept`: تحديد استلام نتائج الاستجابة بتنسيق JSON، هنا يتم ملؤه بـ `application/json`.
- `authorization`: مفتاح استدعاء واجهة برمجة التطبيقات، يمكن اختياره مباشرة بعد التقديم.

**جسم الطلب** يشمل:

- `id`: معرف المهمة التي ترغب في استعلامها.
- `action`: طريقة تنفيذ العملية على المهمة، يتم ملؤها بـ `retrieve` للاستعلام الفردي.

### مثال على كود CURL

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### مثال على الاستجابة

بعد نجاح الطلب، ستقوم واجهة برمجة التطبيقات بإرجاع تفاصيل المهمة هنا. حيث أن حقل `request` هو جسم الطلب عند بدء المهمة، وحقل `response` هو جسم الاستجابة الذي يتم إرجاعه بعد إكمال المهمة، على سبيل المثال:

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "request": {
    "prompt": "لقطة سينمائية لقط صغير يطارد فراشة في حديقة مضاءة بأشعة الشمس",
    "model": "omni-flash",
    "aspect_ratio": "16:9"
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "omni-flash:job_01k777hjrbfrgs2060q5zvf2a5",
        "video_url": "https://cdn.acedata.cloud/gemini/example-video.mp4",
        "state": "succeeded"
      }
    ]
  }
}
```

تقديم الحقول كما يلي:

- `id`: معرف المهمة التي تم إنشاؤها، يستخدم لتحديد هذه المهمة بشكل فريد.
- `request`: معلومات الطلب في المهمة المستعلم عنها.
- `response`: معلومات الاستجابة في المهمة المستعلم عنها.
- `created_at`: وقت إنشاء المهمة، طابع زمني Unix (ثوانٍ، عائم).
- `started_at`: وقت بدء تنفيذ المهمة، سلسلة زمنية UTC ISO-8601.
- `finished_at`: وقت إكمال المهمة، طابع زمني Unix (ثوانٍ، عائم). لا يتم إرجاع هذا الحقل إذا لم تكتمل المهمة.
- `elapsed`: الوقت المستغرق لتنفيذ المهمة، بوحدة الثواني (عائم، يحتفظ بـ 3 أرقام عشرية). لا يتم إرجاع هذا الحقل إذا لم تكتمل المهمة.

## عمليات الاستعلام الجماعي

عند استعلام تفاصيل المهام لعدة معرفات مهام، يتم تعيين `action` إلى `retrieve_batch`، ويتم تمرير مصفوفة معرفات المهام عبر `ids`:

**جسم الطلب** يشمل:

- `ids`: مصفوفة معرفات المهام التي ترغب في استعلامها.
- `action`: طريقة تنفيذ العملية على المهام، يتم ملؤها بـ `retrieve_batch` للاستعلام الجماعي.

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```
