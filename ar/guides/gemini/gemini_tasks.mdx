الوظيفة الرئيسية لواجهة برمجة تطبيقات Gemini Tasks هي الاستعلام عن حالة تنفيذ المهمة من خلال إدخال معرف المهمة الذي تم إنشاؤه بواسطة واجهة برمجة تطبيقات Gemini Videos Generation.

ستوضح هذه الوثيقة تعليمات التكامل مع واجهة برمجة تطبيقات Gemini Tasks بالتفصيل، لمساعدتك على التكامل بسهولة والاستعلام عن حالة تنفيذ المهام في واجهة برمجة تطبيقات Gemini Videos Generation.

## عملية التقديم

لاستخدام واجهة برمجة تطبيقات Gemini Tasks، يجب أولاً التقديم للحصول على الخدمة المناسبة من صفحة التقديم [Gemini Videos Generation API](https://platform.acedata.cloud/documents/gemini-videos) ونسخ معرف المهمة الذي تم إرجاعه من واجهة برمجة تطبيقات Gemini Videos Generation.

بعد ذلك، انتقل إلى صفحة [Gemini Tasks API](https://platform.acedata.cloud/documents/gemini-tasks) للتقديم على الخدمة المناسبة، وبمجرد الدخول إلى الصفحة، اضغط على زر "Acquire".

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، سيتم تحويلك تلقائيًا إلى [صفحة تسجيل الدخول](https://platform.acedata.cloud) لدعوتك للتسجيل وتسجيل الدخول، وبعد تسجيل الدخول سيتم إرجاعك تلقائيًا إلى الصفحة الحالية.

عند التقديم لأول مرة، ستحصل على رصيد مجاني يمكن استخدامه مجانًا مع هذه الواجهة.

## مثال على الطلب

يمكن استخدام واجهة برمجة تطبيقات Gemini Tasks للاستعلام عن نتائج واجهة برمجة تطبيقات Gemini Videos Generation.

### إعداد رؤوس الطلب وجسم الطلب

**رؤوس الطلب (Request Headers)** تشمل:

- `accept`: لتحديد استلام استجابة بصيغة JSON، يتم تعيينها إلى `application/json`.
- `authorization`: مفتاح استدعاء API، يمكن اختياره مباشرة من القائمة المنسدلة بعد التقديم.

**جسم الطلب (Request Body)** يشمل:

- `id`: معرف المهمة المراد الاستعلام عنها.
- `action`: طريقة التعامل مع المهمة، للاستعلام الفردي يتم تعيينها إلى `retrieve`.

### مثال كود CURL

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### مثال الاستجابة

بعد نجاح الطلب، سترجع الواجهة تفاصيل المهمة هنا. حيث أن حقل `request` هو جسم الطلب الذي تم إرساله عند بدء المهمة، وحقل `response` هو جسم الاستجابة الذي تم إرجاعه بعد إتمام المهمة، على سبيل المثال:

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "request": {
    "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
    "model": "omni-flash",
    "aspect_ratio": "16:9"
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "omni-flash:job_01k777hjrbfrgs2060q5zvf2a5",
        "video_url": "https://cdn.acedata.cloud/gemini/example-video.mp4",
        "state": "succeeded"
      }
    ]
  }
}
```

شرح الحقول كما يلي:

- `id`: معرف مهمة الإنشاء، يستخدم لتمييز المهمة بشكل فريد.
- `request`: معلومات الطلب ضمن المهمة المستعلم عنها.
- `response`: معلومات الاستجابة ضمن المهمة المستعلم عنها.

## عملية الاستعلام الجماعي

للاستعلام عن تفاصيل مهام متعددة باستخدام معرفات المهام، قم بتعيين `action` إلى `retrieve_batch`، ومرر مصفوفة معرفات المهام عبر `ids`:

**جسم الطلب** يشمل:

- `ids`: مصفوفة معرفات المهام المراد الاستعلام عنها.
- `action`: طريقة التعامل مع المهمة، للاستعلام الجماعي يتم تعيينها إلى `retrieve_batch`.

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```
