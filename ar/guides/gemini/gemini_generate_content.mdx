Google Gemini هو نظام محادثة بالذكاء الاصطناعي قوي جدًا، يمكنه توليد ردود سلسة وطبيعية خلال ثوانٍ عبر إدخال مطالبات. يصف هذا المستند بشكل أساسي طريقة استخدام Gemini Generate Content API، وهي صيغة API أصلية رسمية من Google، وتدعم نقطتي النهاية `generateContent` و`streamGenerateContent`.

## الفرق عن Chat Completions API

يستخدم Gemini Generate Content API صيغة الطلب الأصلية الرسمية من Google (حقل `contents`)، بدلًا من الصيغة المتوافقة مع OpenAI (حقل `messages`). إذا كنت تستخدم بالفعل Google Gemini SDK أو كنت على دراية بصيغة API الرسمية، فيمكنك استخدام هذا الـ API مباشرةً دون الحاجة إلى تعديل صيغة الطلب.

## نطاق الدعم الحالي

تقبل الواجهة إدخال النصوص والصور والفيديو والصوت (عبر `inlineData` أو `fileData`)، وإعدادات التفكير وإعلانات الدوال المخصصة. لا يوجد ضمان لتوافر موحّد حاليًا للحقول الأصلية مثل إخراج الصوت والأدوات المضمنة والتخزين المؤقت الصريح للسياق؛ يرجى الرجوع إلى الاستجابة الفعلية للنموذج المحدد.

عند إرسال ملفات مثل الصوت باستخدام `fileData.fileUri`، يرجى التأكد من إمكانية الوصول إلى الملف مباشرةً عبر HTTPS، وألا يعتمد على حالة تسجيل الدخول، وأن تغطي مدة صلاحية الرابط الموقّع كامل وقت معالجة الطلب. لا تُرجع تحليلات الصوت غير المتدفقة النتائج إلا بعد انتهاء النموذج من المعالجة، وقد تتجاوز 90 ثانية؛ ينبغي للعميل تعيين مهلة إجمالية طويلة بما يكفي وفقًا لحجم الملف وسيناريو العمل، لتجنب قطع الاتصال بينما لا يزال الخادم يعالج الطلب.

## عملية التقديم

قبل استخدام Gemini Generate Content API، يرجى أولًا زيارة صفحة [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api)، والنقر على زر "الحصول" للحصول على بيانات الاعتماد المطلوبة للطلب.

إذا لم تسجل الدخول أو تسجل حسابًا بعد، فسيتم التحويل تلقائيًا إلى صفحة تسجيل الدخول. يتوفر رصيد مجاني عند التقديم لأول مرة.

## الاستخدام الأساسي

### Non-Streaming（غير متدفق）

أرسل طلب POST إلى `/v1beta/models/{model}:generateContent`:

> **تنبيه**: سلسلة `gemini-3.x` من flash هي نماذج تفكير، وستستهلك reasoning tokens أولًا؛ يرجى تعيين `generationConfig.maxOutputTokens` إلى 512 أو أكثر، وإلا فقد تُرجع محتوى فارغًا فقط.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

مثال على النتيجة المعادة:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

تتم محاسبة حقول token في `usageMetadata` وفقًا لدلالات Gemini الأصلية:

- يتضمن `promptTokenCount` قيمة `cachedContentTokenCount`، ويُحتسب الجزء الذي أصاب التخزين المؤقت بسعر قراءة التخزين المؤقت، ولن يُحتسب مرة أخرى كإدخال عادي.
- ستتم تسوية `promptTokensDetails` و`cacheTokensDetails` إلى `text_tokens` و`image_tokens` و`video_tokens` و`audio_tokens` والتفاصيل المقابلة لـ `cached_*` ضمن `usage.prompt_tokens_details`. تُضمَّن هذه القيم على التوالي في `prompt_tokens` و`cached_tokens`؛ ولا يُعاد احتساب الوسائط المختلفة إلا وفقًا لأسعارها الخاصة، ولن تُحاسب بشكل مكرر.
- يُحتسب كل من `candidatesTokenCount` و`thoughtsTokenCount` بسعر output token.
- إن `toolUsePromptTokenCount` هو tool input token مستقل، ويُحتسب بسعر input token.

تُرجع Ace Data Cloud بالإضافة إلى ذلك كائن `usage` موحّدًا، وتتم قراءة تكلفة هذه المكالمة بشكل موحّد عبر بروتوكولات النماذج من `usage.cost`. إن `cost` هو معاينة تكلفة اختيارية؛ عندما لا تتوفر معاينة السعر مؤقتًا، ستظل استجابة النموذج تُرجع بشكل طبيعي، لكنها قد لا تتضمن هذا الحقل. تخضع الفاتورة النهائية لسجل الاستخدام.

### Streaming（متدفق）

أرسل طلب POST إلى `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

ستُرجع الاستجابة المتدفقة المحتوى تدريجيًا بصيغة SSE ‏(Server-Sent Events). لا تتضمن الأحداث الوسيطة عادةً سوى المحتوى المتزايد؛ وسيحتوي الحدث النهائي ذو الاستخدام الموثوق على `usageMetadata` و`usage` الموحّد، بينما تظل التكلفة في `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

إغلاق الاتصال يعني انتهاء التدفق؛ لا يرسل تدفق Gemini الأصلي `data: [DONE]`. إذا لم تتوفر معاينة السعر النهائية مؤقتًا، فسيظل `usage` يُرجع استخدام token، لكنه سيحذف `cost`.

### التفكير الداخلي وملخص التفكير

تفكير النموذج الداخلي وإرجاع ملخص التفكير إلى المستدعي هما إعدادان مستقلان:

- يتحكم `thinkingBudget` أو `thinkingLevel` في ميزانية التفكير الداخلي للنموذج أو عمقه، وتعتمد الحقول والقيم المدعومة على النموذج.
- يتحكم `includeThoughts` في ما إذا كان سيتم إرجاع ملخص التفكير، والقيمة الافتراضية هي `false`. عند حذف هذا الحقل أو تمرير `false`، لن تعيد استجابات JSON العادية ولا الاستجابات المتدفقة عبر SSE نصًا موسومًا بـ `thought: true`؛ ولا يُحتفظ بهذه النصوص إلا عند تمرير القيمة المنطقية `true` صراحةً.

عندما لا يضبط الطلب `includeThoughts`، تمرر الواجهة افتراضيًا `false` إلى نماذج التوليد التي تدعم إعدادات التفكير، لتجنب طلب ملخصات غير مطلوبة؛ وتُحتفظ بالقيم التي يمررها العميل صراحةً، وميزانية التفكير ومستواه. لا يُضاف هذا الحقل تلقائيًا إلى `gemini-2.5-flash-image` المعروف بعدم دعمه لإعدادات التفكير، كما لا تُضاف إعدادات التوليد إلى طلبات `countTokens`.

إيقاف الملخص لا يعني إيقاف التفكير الداخلي، ولا يضمن تقليل token الخاصة بالتفكير الداخلي. إذا ظلت الاستجابة تتضمن نص تفكير غير مطلوب، فستقوم منافذ JSON العادية وSSE أيضًا بتصفيته، مع الاحتفاظ بالإجابة العادية والتوقيع والاستخدام الفعلي.

عند الحاجة إلى عرض الملخص، فعّله صراحةً بالطريقة التالية. عندما لا يولّد النموذج ملخصًا متاحًا، قد لا يكون هناك نص تفكير حتى عند تفعيله:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` هي حالة مشفرة مطلوبة في الجولات اللاحقة، وليست نص ملخص التفكير، ولا تخضع للتحكم عبر مفتاح `includeThoughts`. قد يوجد التوقيع في الإجابة العادية، أو استدعاء دالة، أو Part نصي فارغ؛ وعند تصفية نص التفكير، يُحتفظ بالتوقيع والحقول الأخرى في الـ Part نفسه، لذلك قد تظل هناك Parts في الاستجابة تحمل توقيعًا فقط ونصها فارغ. عند إدارة سجل متعدد الجولات يدويًا، يجب الاحتفاظ بترتيب هذه الـ Parts ومواضع التوقيعات، ولا تنقل التوقيعات أو تدمجها.

لا يزال `usageMetadata` و`usage` يسجلان الاستخدام الفعلي. إخفاء الملخص لا يصفر `thoughtsTokenCount`، وتظل الفوترة محسوبة وفقًا للاستخدام الفعلي وقواعد التسعير الحالية.

راجع [شرح التفكير وملخص التفكير](https://firebase.google.com/docs/ai-logic/thinking) الرسمي من Google و[قواعد توقيع التفكير](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

## إعدادات الأمان

يمكن التحكم في تصفية المحتوى عبر `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## معالجة الأخطاء

| رمز حالة HTTP | المعنى             |
| -------- | -------------- |
| 400      | معلمات الطلب غير صالحة         |
| 401      | فشلت المصادقة، يرجى التحقق من Token |
| 403      | تم اعتراض المحتوى بواسطة عامل تصفية الأمان     |
| 429      | الطلبات متكررة للغاية         |
| 500      | خطأ داخلي في الخادم        |
