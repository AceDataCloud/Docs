Google Gemini هو نظام محادثة بالذكاء الاصطناعي قوي للغاية، يمكنه إنشاء ردود سلسة وطبيعية في ثوانٍ من خلال إدخال مطالبات. يصف هذا المستند بشكل أساسي كيفية استخدام Gemini Generate Content API، وهي صيغة واجهة برمجة التطبيقات الأصلية الرسمية من Google، وتدعم نقطتي النهاية `generateContent` و`streamGenerateContent`.

## الفرق عن Chat Completions API

يستخدم Gemini Generate Content API صيغة الطلب الأصلية الرسمية من Google (الحقل `contents`) بدلاً من الصيغة المتوافقة مع OpenAI (الحقل `messages`). إذا كنت تستخدم بالفعل Google Gemini SDK أو كنت معتادًا على صيغة واجهة برمجة التطبيقات الرسمية، فيمكنك استخدام واجهة برمجة التطبيقات هذه مباشرةً دون تعديل صيغة الطلب.

## نطاق الدعم الحالي

تقبل الواجهة النصوص والصور والفيديو والصوت كمدخلات (`inlineData` أو `fileData`)، وتكوينات التفكير وتعريفات الدوال المخصصة. لا يوجد حتى الآن ضمان موحّد لإتاحة الحقول الأصلية مثل مخرجات الصوت والأدوات المضمنة والتخزين المؤقت الصريح للسياق؛ يرجى الرجوع إلى الاستجابة الفعلية للنموذج المحدد.

عند إرسال ملفات مثل الصوت باستخدام `fileData.fileUri`، يرجى التأكد من أن الملف قابل للوصول مباشرةً عبر HTTPS، ولا يعتمد على حالة تسجيل الدخول، وأن تغطي صلاحية الرابط الموقّع كامل وقت معالجة الطلب. لا تُرجع تحليلات الصوت غير المتدفقة النتائج إلا بعد أن ينتهي النموذج من المعالجة، وقد تتجاوز 90 ثانية؛ ينبغي للعميل تعيين مهلة إجمالية طويلة بما يكفي وفقًا لحجم الملف وسيناريو العمل، لتجنب قطع الاتصال بينما لا تزال الخدمة تعالج الطلب.

## عملية التقديم

قبل استخدام Gemini Generate Content API، يرجى أولاً زيارة صفحة [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api)، ثم النقر على زر "الحصول" للحصول على بيانات الاعتماد المطلوبة للطلب.

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول. سيحصل أول طلب على حصة مجانية.

## الاستخدام الأساسي

### Non-Streaming（غير متدفق）

أرسل طلب POST إلى `/v1beta/models/{model}:generateContent`:

> **تنبيه**: إن flash من سلسلة `gemini-3.x` هو نموذج تفكير، وسيستهلك reasoning tokens أولاً؛ يرجى ضبط `generationConfig.maxOutputTokens` على 512 أو أكثر، وإلا فقد يعيد محتوى فارغًا فقط.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

مثال على نتيجة الإرجاع:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

تُحتسب حقول token في `usageMetadata` وفقًا لدلالات Gemini الأصلية:

- يتضمن `promptTokenCount` قيمة `cachedContentTokenCount`، ويُحتسب الجزء الذي أصاب التخزين المؤقت بسعر قراءة التخزين المؤقت، ولن يُحتسب مرة أخرى كمدخل عادي.
- ستتم تسوية `promptTokensDetails` و`cacheTokensDetails` إلى `text_tokens` و`image_tokens` و`video_tokens` و`audio_tokens` وتفاصيل `cached_*` المقابلة لها ضمن `usage.prompt_tokens_details`. تُضمَّن هذه القيم على التوالي في `prompt_tokens` و`cached_tokens`؛ وتُعاد حساب الوسائط المختلفة وفق أسعارها الخاصة فقط، ولن تُحتسب الرسوم بشكل متكرر.
- يُحتسب كل من `candidatesTokenCount` و`thoughtsTokenCount` بسعر output token.
- `toolUsePromptTokenCount` هو token مستقل لإدخال الأداة، ويُحتسب بسعر input token.

تُرجع Ace Data Cloud أيضًا كائن `usage` موحّدًا إضافيًا، وتتم قراءة تكلفة هذه المكالمة بشكل موحّد عبر بروتوكولات النماذج من `usage.cost`. إن `cost` هو معاينة اختيارية للتكلفة؛ عندما لا تتوفر معاينة السعر مؤقتًا، ستظل استجابة النموذج تُرجع بشكل طبيعي، لكنها قد لا تتضمن هذا الحقل. تخضع الفاتورة النهائية لسجل الاستخدام.

### Streaming（متدفق）

أرسل طلب POST إلى `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

ستُرجع الاستجابة المتدفقة المحتوى تدريجيًا بصيغة SSE (Server-Sent Events). عادةً ما تحتوي الأحداث الوسيطة على محتوى تزايدي فقط؛ بينما سيتضمن الحدث النهائي الذي يحتوي على استخدام موثوق `usageMetadata` و`usage` الموحّد، وتبقى التكلفة في `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

يشير إغلاق الاتصال إلى نهاية التدفق؛ لا يرسل تدفق Gemini الأصلي `data: [DONE]`. إذا لم تتوفر معاينة السعر النهائية مؤقتًا، فسيظل `usage` يُرجع استخدام token، لكنه سيحذف `cost`.

### التفكير الداخلي وملخص التفكير

إن التفكير الداخلي للنموذج وإرجاع ملخص التفكير إلى المستدعي إعدادان مستقلان:

- يتحكم `thinkingBudget` أو `thinkingLevel` في ميزانية أو عمق التفكير الداخلي للنموذج، وتعتمد الحقول والقيم المدعومة على النموذج.
- يتحكم `includeThoughts` في ما إذا كان سيتم إرجاع ملخص التفكير، والقيمة الافتراضية هي `false`. عند حذف هذا الحقل أو تمرير `false`، فلن تُرجع استجابات JSON العادية ولا الاستجابات المتدفقة عبر SSE نصًا معلّمًا بـ `thought: true`؛ ولا يُحتفظ بهذه النصوص إلا عند تمرير القيمة المنطقية `true` صراحةً.

عندما لا يضبط الطلب `includeThoughts`، تمرر الواجهة افتراضيًا `false` إلى نماذج التوليد التي تدعم إعدادات التفكير، لتجنب طلب ملخصات غير لازمة؛ وتُحتفظ بالقيمة التي يمررها العميل صراحةً، وميزانية التفكير ومستواه. لا يُضاف هذا الحقل تلقائيًا إلى `gemini-2.5-flash-image` المعروف بعدم دعمه لإعدادات التفكير، كما لا تُضاف إعدادات التوليد إلى طلبات `countTokens`.

إيقاف الملخص لا يعني إيقاف التفكير الداخلي، ولا يضمن تقليل رموز التفكير الداخلية. إذا كانت الاستجابة لا تزال تتضمن نص تفكير غير مطلوب، فستُجرى تصفية إضافية في مخرجات JSON العادية وSSE، مع الاحتفاظ بالإجابة العادية والتوقيع والاستخدام الفعلي.

عند الحاجة إلى عرض الملخص، فعّله صراحةً بالطريقة التالية. إذا لم يُنشئ النموذج ملخصًا قابلًا للاستخدام، فقد لا يظهر نص التفكير حتى عند تفعيله:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` هو حالة مشفرة لازمة للأدوار اللاحقة، وليس نص ملخص التفكير، ولا يتحكم به مفتاح `includeThoughts`. قد يوجد التوقيع في الإجابة العادية أو استدعاء الدالة أو Part نصي فارغ؛ وعند تصفية نص التفكير، يُحتفظ بالتوقيع والحقول الأخرى في الـ Part نفسه، لذلك قد تظل هناك Parts في الاستجابة تحمل التوقيع فقط ويكون نصها فارغًا. عند إدارة سجل متعدد الأدوار يدويًا، يجب الاحتفاظ بترتيب هذه الـ Parts ومواضع التوقيعات، ولا تنقل التوقيعات أو تدمجها.

لا يزال `usageMetadata` و`usage` يسجلان الاستخدام الفعلي. لا يؤدي إخفاء الملخص إلى تصفير `thoughtsTokenCount`، وتُحسب الفوترة وفقًا للاستخدام الفعلي وقواعد التسعير الحالية.

راجع [شرح التفكير وملخص التفكير](https://firebase.google.com/docs/ai-logic/thinking) الرسمي من Google و[قواعد توقيعات التفكير](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

## إعدادات الأمان

يمكن التحكم في تصفية المحتوى عبر `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## معالجة الأخطاء

| رمز حالة HTTP | المعنى             |
| -------- | -------------- |
| 400      | معلمات الطلب غير صالحة         |
| 401      | فشلت المصادقة، يرجى التحقق من Token |
| 403      | تم اعتراض المحتوى بواسطة عامل تصفية الأمان     |
| 429      | الطلبات متكررة للغاية         |
| 500      | خطأ داخلي في الخادم        |
