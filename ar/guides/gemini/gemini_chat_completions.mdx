Google Gemini هو نظام محادثة بالذكاء الاصطناعي قوي للغاية، فما عليك سوى إدخال نص توجيهي ليتمكن من إنشاء ردود سلسة وطبيعية في غضون ثوانٍ قليلة. يمكن لـ Gemini تقديم مساعدة ذكية مذهلة، مما يحسن بشكل كبير كفاءة العمل والإبداع لدى البشر.

يقدم هذا المستند بشكل أساسي عملية استخدام Gemini Chat Completion API، ومن خلاله يمكننا استخدام وظيفة المحادثة الرسمية لـ Gemini بسهولة.

## عملية الطلب

لاستخدام Gemini Chat Completion API، انتقل أولًا إلى [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تقم بتسجيل الدخول أو التسجيل بعد، فسيتم تلقائيًا توجيهك إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائيًا إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة إلى التقدم بطلب منفصل لكل خدمة.** سيُمنحك رصيد مجاني عند التقديم لأول مرة، ويمكنك التجربة مجانًا؛ وعندما يكون الرصيد غير كافٍ، يمكنك إعادة شحن الرصيد العام في [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 المستند الكامل: [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## الاستخدام الأساسي

بعد ذلك، يمكنك ملء المحتوى المقابل في الواجهة، كما هو موضح في الشكل:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

عند استخدام هذه الواجهة لأول مرة، نحتاج إلى ملء ثلاثة محتويات على الأقل، أحدها هو `authorization`، ويمكنك اختياره مباشرة من القائمة المنسدلة. المعلمة الأخرى هي `model`، ويمثل `model` فئة النموذج الرسمية لـ Gemini التي نختار استخدامها، وتخضع النماذج المتاحة لتعداد `model` في وثائق الواجهة. المعلمة الأخيرة هي `messages`، و`messages` هي مصفوفة نصوص الأسئلة التي ندخلها، وهي مصفوفة، ما يعني أنه يمكن تحميل عدة نصوص أسئلة في الوقت نفسه، ويحتوي كل نص سؤال على `role` و`content`، حيث يمثل `role` دور السائل، وقد وفرنا ثلاث هويات، وهي `user` و`assistant` و`system`. أما `content` الآخر فهو المحتوى المحدد للسؤال الذي نطرحه.

وفي الوقت نفسه، يمكنك ملاحظة وجود إنشاء رمز الاستدعاء المقابل على الجانب الأيمن، ويمكنك نسخ الرمز وتشغيله مباشرة، أو النقر مباشرة على زر «Try» للاختبار.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

> **تنبيه**: سلسلة `gemini-3.x` flash هي نماذج تفكير، وستستهلك reasoning tokens أولًا؛ يرجى ضبط `max_tokens` على 512 أو أكثر، وإلا فقد يتم إرجاع محتوى فارغ فقط. يُعد `gemini-3.8-flash` نموذج Flash الموصى به حاليًا، ويدعم سياقًا يصل إلى مليون Token، وإدخال الصور، واستدعاء الأدوات، والاستجابات المتدفقة؛ ويُستدعى حاليًا عبر واجهة Chat Completions.

يمكن أيضًا استخدام `gemini-4-argon` في Chat Completions، ويدعم الردود النصية العادية والمتدفقة. قد يخصص جزءًا من ميزانية الإخراج للتفكير، لذا يرجى ترك مساحة كافية لـ `max_tokens` في المهام المعقدة؛ توصي Google بما لا يقل عن 32768 للمهام العادية لهذا الطراز. لا تعامل هذه الواجهة على أنها وظيفة الإخراج الطويل في الخلفية الخاصة بـ Google Interactions API.

تحتوي النتيجة المعادة على عدة حقول، ويُعرَّف كل منها كما يلي:

## فهم الصور (إدخال متعدد الوسائط)

Gemini هو نموذج متعدد الوسائط أصلي، ويمكنه «رؤية الصور» مباشرة. لتمرير صورة، غيّر `content` لإحدى الرسائل من سلسلة نصية إلى **مصفوفة كتل محتوى**، ثم ضع كتل `text` وكتل `image_url` معًا داخل المصفوفة — وهذا يتطابق تمامًا مع OpenAI، وكذلك مع تنسيق Gemini الرسمي المتوافق مع OpenAI.

يدعم `image_url.url` طريقتين للكتابة:
- **عنوان URI لـ `data:` بترميز base64 (موصى به، الأكثر استقرارًا)**: تنسيقه هو `data:&lt;نوع الوسائط>;base64,&lt;البيانات>`، مثلًا `data:image/jpeg;base64,/9j/4AAQ...`. **نوع الوسائط (MIME) مكتوب بالفعل في بادئة `data:`**، لذلك لا حاجة إلى حقل `media_type` منفصل، وهو غير موجود أيضًا.
- **عنوان URL لصورة متاح للعامة**: مثلًا `https://cdn.acedata.cloud/4hfydw.jpg`.

أنواع الصور المدعومة: `png`، `jpeg`، `webp`، `heic`، `heif`.

مثال على كود استدعاء Python (عنوان data URI بترميز base64):

```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# 把本地图片读成 base64 data URI
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

يمكن أيضًا تمرير عنوان URL لصورة متاح للعامة مباشرةً:

## الاستجابة المتدفقة

تدعم هذه الواجهة أيضًا الاستجابة المتدفقة، وهذا مفيد جدًا لتكامل صفحات الويب، إذ يمكن أن يتيح للصفحة تحقيق تأثير العرض كلمةً بكلمة.

إذا أردت إرجاع الاستجابة بشكل متدفق، يمكنك تغيير معامل `stream ` في رأس الطلب إلى `true`.

عدّل كما هو موضح في الصورة، لكن يحتاج كود الاستدعاء إلى التعديلات المقابلة لدعم الاستجابة المتدفقة.

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

بعد تعديل `stream` إلى `true`، ستُرجع API بيانات JSON المقابلة سطرًا بسطر، وعلى مستوى الكود نحتاج إلى إجراء التعديلات المناسبة للحصول على النتائج سطرًا بسطر.

مثال على كود استدعاء Python:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

كما يمكن ملاحظة ذلك، توجد العديد من `data` داخل الاستجابة، وتمثل `choices` الموجودة داخل `data` أحدث محتوى للإجابة، وهو متوافق مع المحتوى المقدّم أعلاه. تمثل `choices` محتوى الإجابة المضاف حديثًا، ويمكنك ربطه بنظامك بناءً على النتيجة. وفي الوقت نفسه، يتم تحديد انتهاء الاستجابة المتدفقة بناءً على محتوى `data`، فإذا كان المحتوى هو `[DONE]`، فهذا يعني أن إجابة الاستجابة المتدفقة قد انتهت بالكامل. تحتوي نتيجة `data` المُعادة على عدة حقول، ويتم تقديمها كما يلي:

- `id`، معرّف المهمة التي تم إنشاؤها لهذه المحادثة، ويُستخدم لتمييز مهمة المحادثة هذه بشكل فريد.
- `model `، نموذج Gemini الرسمي المحدد.
- `choices`، معلومات الإجابة التي يقدمها Gemini للكلمات المطروحة.

يدعم JavaScript أيضًا ذلك، فعلى سبيل المثال، يكون كود الاستدعاء المتدفق في Node.js كما يلي:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

## معالجة الأخطاء

عند استدعاء API، إذا واجهت خطأً، فسيُرجع API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح به، رمز التفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جدًا، لقد تجاوزت حد المعدل.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة خطأ
```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
