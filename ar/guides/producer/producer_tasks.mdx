الوظيفة الرئيسية لواجهة برمجة تطبيقات مهام المنتج هي الاستعلام عن حالة تنفيذ المهمة من خلال إدخال معرف المهمة الذي تم إنشاؤه بواسطة واجهة برمجة تطبيقات توليد صوتيات المنتج.

ستقدم هذه الوثيقة شرحًا تفصيليًا لكيفية تكامل واجهة برمجة تطبيقات مهام المنتج، لمساعدتك على دمجها بسهولة والاستفادة الكاملة من قدرات هذه الواجهة. من خلال واجهة برمجة تطبيقات مهام المنتج، يمكنك بسهولة الاستعلام عن حالة تنفيذ مهام واجهة برمجة تطبيقات توليد صوتيات المنتج.

## عملية التقديم

لاستخدام واجهة برمجة تطبيقات توليد صوتيات المنتج، قم أولاً بالحصول على رمز API الخاص بك من [لوحة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للاحتفاظ به كمرجع.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا، فسيتم توجيهك تلقائيًا إلى صفحة تسجيل الدخول لتسجيل الدخول أو التسجيل، وبعد الانتهاء ستعود تلقائيًا إلى الصفحة الحالية.

**رمز API واحد يكفي لاستدعاء جميع خدمات المنصة، ولا حاجة للتقديم لكل خدمة على حدة.** عند التقديم لأول مرة، ستحصل على رصيد مجاني لتجربة الخدمة؛ وعند نفاد الرصيد يمكنك إعادة شحن الرصيد العام من خلال [اللوحة](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [واجهة برمجة تطبيقات توليد صوتيات المنتج →](https://platform.acedata.cloud/documents/producer-audios)

## مثال على الطلب

يمكن استخدام واجهة برمجة تطبيقات مهام المنتج للاستعلام عن نتائج واجهة برمجة تطبيقات توليد صوتيات المنتج. لمزيد من التفاصيل حول كيفية استخدام واجهة برمجة تطبيقات توليد صوتيات المنتج، يرجى الرجوع إلى الوثيقة [واجهة برمجة تطبيقات توليد صوتيات المنتج](https://platform.acedata.cloud/documents/producer-audios-integration).

كمثال، سنأخذ معرف مهمة تم إرجاعه من خدمة واجهة برمجة تطبيقات توليد صوتيات المنتج، ونوضح كيفية استخدام هذه الواجهة. لنفترض أن لدينا معرف مهمة: 1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad، وسنوضح كيفية الاستعلام عن حالة المهمة من خلال تمرير هذا المعرف.

### إعداد رؤوس الطلب وجسم الطلب

**رؤوس الطلب (Request Headers)** تشمل:

- `accept`: لتحديد استلام استجابة بصيغة JSON، يتم تعبئتها بـ `application/json`.
- `authorization`: مفتاح استدعاء API، يمكن اختياره مباشرة بعد التقديم.

**جسم الطلب (Request Body)** يشمل:

- `id`: معرف المهمة المرفوع.
- `action`: طريقة التعامل مع المهمة.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

تحتوي النتيجة المرجعة على عدة حقول، حيث يمثل حقل request جسم الطلب الذي تم إرساله عند بدء المهمة، بينما يمثل حقل response جسم الاستجابة الذي تم إرجاعه بعد إتمام المهمة. فيما يلي شرح الحقول.
- `id`، معرف المهمة التي تم إنشاؤها، يستخدم لتحديد هذه المهمة بشكل فريد.
- `request`، معلومات الطلب في مهمة الاستعلام.
- `response`، معلومات الاستجابة في مهمة الاستعلام.
- `created_at`، وقت إنشاء المهمة، طابع زمني Unix (ثواني، عائم).
- `started_at`، وقت بدء تنفيذ المهمة، طابع زمني Unix (ثواني، عائم).
- `finished_at`، وقت إكمال المهمة، طابع زمني Unix (ثواني، عائم). لا يتم إرجاع هذا الحقل عند عدم اكتمال المهمة.
- `elapsed`، الوقت المستغرق لتنفيذ المهمة، وحدة بالثواني (عائم، يحتفظ بـ 3 أرقام عشرية). لا يتم إرجاع هذا الحقل عند عدم اكتمال المهمة.

## معالجة الأخطاء

عند استدعاء واجهة برمجة التطبيقات، إذا واجهت خطأ، ستقوم واجهة برمجة التطبيقات بإرجاع رمز الخطأ والمعلومات ذات الصلة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صحيح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صحيح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح به، رمز تفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جداً، لقد تجاوزت الحد الأقصى لمعدل الطلبات.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة الخطأ

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## الخاتمة

من خلال هذه الوثيقة، لقد فهمت كيفية استخدام واجهة برمجة تطبيقات مهام المنتج لاستعلام تفاصيل مهمة واحدة أو مجموعة من المهام. نأمل أن تساعدك هذه الوثيقة في التوصيل واستخدام هذه الواجهة بشكل أفضل. إذا كان لديك أي أسئلة، فلا تتردد في الاتصال بفريق الدعم الفني لدينا.
