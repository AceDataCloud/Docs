ستتناول هذه الوثيقة توضيح تكامل واجهة برمجة تطبيقات Veo Upsample. تُستخدم هذه الواجهة لرفع جودة مقطع فيديو تم إنشاؤه مسبقًا بواسطة Veo أو لإخراج معاينة متحركة.

## عملية التقديم

لاستخدام واجهة برمجة التطبيقات، يجب أولاً التوجه إلى الصفحة المقابلة لخدمات Veo لتقديم الطلب. إذا لم تكن قد قمت بتسجيل الدخول أو التسجيل، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول.

## الاستخدام الأساسي

يتطلب استدعاء هذه الواجهة تمرير معلمين:

- `video_id` : معرف مهمة الفيديو المصدر. يمكن أن يكون معرف فيديو تم إنشاؤه من أي من الواجهات `/veo/videos`، `/veo/extend`، `/veo/reshoot`، `/veo/objects`.
- `action` : إجراء الرفع، يدعم الأنواع الثلاثة التالية:
  - `1080p` : رفع جودة الفيديو إلى دقة 1080p.
  - `4k` : رفع جودة الفيديو إلى دقة 4K.
  - `gif` : تحويل الفيديو إلى معاينة متحركة (GIF).

مثال على الطلب:

```shell
curl -X POST 'https://api.acedata.cloud/veo/upsample' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "video_id": "dd01fc69-e1f7-4b68-aa8c-463f6b748d11",
    "action": "4k"
  }'
```

تكون نتيجة الاستجابة مشابهة لتلك الخاصة بـ `/veo/videos`، ولا تزال هيكل مهمة غير متزامنة، يمكن من خلالها استعلام حالة المهمة باستخدام `task_id` في واجهة `/veo/tasks`:

```json
{
  "success": true,
  "task_id": "8f5a90ae-3f86-4c4f-86f7-7126f5e92c76",
  "trace_id": "0f3e09c2-4c2e-46ea-9cdc-a31ec48b7c12",
  "data": [
    {
      "id": "253eedc47f1c4eb2a370ed2312168f4b",
      "video_url": "https://platform.cdn.acedata.cloud/veo/8f5a90ae.mp4",
      "created_at": "2025-07-25 16:07:43",
      "complete_at": "2025-07-25 16:10:28",
      "state": "succeeded"
    }
  ]
}
```

توضيح حقول الاستجابة:

- `success` : هل تم تقديم مهمة الرفع بنجاح.
- `task_id` : معرف مهمة الرفع الحالية.
- `data` : نتائج الفيديو بعد الرفع.
  - `video_url` : عنوان الفيديو بعد الرفع.

## توضيح الفوترة

- `action=1080p` : 0.16 ائتمان / مرة
- `action=4k` : 0.50 ائتمان / مرة
- `action=gif` : 0.13 ائتمان / مرة

إذا كان `action` المدخل غير موجود في القيم المذكورة أعلاه، فسيتم احتسابه افتراضيًا كـ 0.50 ائتمان. يُنصح بتمرير القيم المدعومة بشكل صريح.

## الاستدعاء غير المتزامن

تدعم الواجهة أيضًا الوضع غير المتزامن، يمكن تمرير `callback_url` لاستدعاء النتائج عبر طلب POST بعد إكمال المهمة. إذا لم يكن هناك عنوان استدعاء عام، يمكن أيضًا تعيين `async` إلى `true`، وستعيد الواجهة على الفور `task_id`، ثم يمكن استعلام النتائج من خلال واجهة استعلام المهمة المقابلة.
