ستقدّم هذه المقالة شرحًا لتكامل Veo Videos Generation API، والذي يمكنه إنشاء فيديوهات Veo الرسمية من خلال إدخال معلمات مخصصة.

## عملية التقديم

لاستخدام Veo Videos Generation API، احصل أولًا على API Token الخاص بك من [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائيًا إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** سيُمنح عند أول تقديم رصيد مجاني، ويمكن التجربة مجانًا؛ وعندما لا يكون الرصيد كافيًا، يمكن شحن الرصيد العام من [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [Veo Videos Generation API →](https://platform.acedata.cloud/documents/veo-videos)

## الاستخدام الأساسي

لنتعرّف أولًا على طريقة الاستخدام الأساسية، وهي إدخال كلمة التوجيه `prompt`، وسلوك الإنشاء `action`، ومصفوفة صور المراجع للإطارين الأول والأخير `image_urls`، والنموذج `model`، ثم يمكن الحصول على النتيجة المعالجة. نحتاج أولًا إلى تمرير حقل `action` ببساطة، وتكون قيمته `text2video`، وهو يتضمن بشكل أساسي ثلاثة سلوكيات: تحويل النص إلى فيديو (`text2video`)، وتحويل الصورة إلى فيديو (`image2video`)، والحصول على فيديو 1080p (`get1080p`). ثم نحتاج أيضًا إلى إدخال النموذج `model`، وتشمل النماذج الرئيسية حاليًا `veo31-fast` و`veo3` و`veo31` و`veo3-fast` و`veo31-fast-ingredients`، والمحتوى المحدد كما يلي:

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

يمكن ملاحظة أننا قمنا هنا بتعيين Request Headers، بما في ذلك:

- `accept`: تنسيق نتيجة الاستجابة التي تريد تلقيها، ويُملأ هنا بـ `application/json`، أي تنسيق JSON.
- `authorization`: مفتاح استدعاء API، ويمكن اختياره مباشرة من القائمة المنسدلة بعد التقديم.

كما تم تعيين Request Body، بما في ذلك:

- `model`: نموذج إنشاء الفيديو، وتشمل النماذج الرئيسية `veo31-fast` و`veo3` و`veo31` و`veo3-fast` و`veo31-fast-ingredients`.
- `action`: سلوك مهمة إنشاء الفيديو هذه، ويتضمن بشكل أساسي ثلاثة سلوكيات، وهي: تحويل النص إلى فيديو (`text2video`)، وتحويل الصورة إلى فيديو (`image2video`)، والحصول على فيديو 1080p (`get1080p`).
- `image_urls`: روابط صور المراجع التي يجب رفعها عند اختيار سلوك تحويل الصورة إلى فيديو `image2video`. يدعم `veo31-fast-ingredients` حتى 3 صور (دمج صور متعددة)، بينما تدعم النماذج الأخرى حتى صورتين (وضع الإطارين الأول والأخير).
- `resolution`: اختيار دقة الفيديو المُنشأ، حيث يدعم نموذج veo31 دقة 4k، ولا تدعمها النماذج الأخرى، وتدعم جميع النماذج دقة 1080p وgif، وإذا لم يتم تمرير هذه القيمة فسيتم استخدام دقة 720p افتراضيًا، وتنقسم بشكل أساسي إلى: `1080p`، `gif`، `4k`.
- `prompt`: كلمة التوجيه.
- `callback_url`: عنوان URL الذي يحتاج إلى نتيجة رد الاتصال.
- `async`: اختياري، عند تعيينه إلى `true`، تُرجع الواجهة `task_id` فورًا، ولا حاجة لتقديم `callback_url`، ثم يتم الحصول على النتيجة عبر الاستعلام الدوري من خلال واجهة الاستعلام عن المهمة المقابلة.

### 📌 ملخص شرح النماذج

| **اسم النموذج**                   | **الأوضاع المدعومة**                          | **قواعد إدخال الصور**                        |
| -------------------------- | --------------------------------- | --------------------------------- |
| **veo3-fast**              | تحويل النص إلى فيديو (بدون صور)<br />وضع تحويل الصورة إلى فيديو (مع صور)           | **صورة واحدة** → وضع الإطار الأول<br />**صورتان** → وضع الإطارين الأول والأخير |
| **veo31-fast**             | تحويل النص إلى فيديو (بدون صور)<br />وضع تحويل الصورة إلى فيديو (مع صور)           | **صورة واحدة** → وضع الإطار الأول<br />**صورتان** → وضع الإطارين الأول والأخير |
| **veo31-fast-ingredients** | ❌ تحويل النص إلى فيديو (غير مدعوم)<br />✅ **دمج صور متعددة إجباري** (يجب تمرير صور) | **1-3 صور** → وضع دمج الصور المتعددة (بحد أقصى 3 صور)        |
| **veo3**                   | تحويل النص إلى فيديو (بدون صور)<br />وضع تحويل الصورة إلى فيديو (مع صور)           | **صورة واحدة** → وضع الإطار الأول<br />**صورتان** → وضع الإطارين الأول والأخير |
| **veo31**                  | تحويل النص إلى فيديو (بدون صور)<br />وضع تحويل الصورة إلى فيديو (مع صور)           | **صورة واحدة** → وضع الإطار الأول<br />**صورتان** → وضع الإطارين الأول والأخير |

---

### 🔑 شرح القواعد الرئيسية

1. **المنطق العام**:
   - **لا يوجد إدخال صور** → يتم تلقائيًا تفعيل وضع تحويل النص إلى فيديو.
   - **يوجد إدخال صور** → يتم تفعيل وضع تحويل الصورة إلى فيديو (ويتم تحديد السلوك المحدد حسب عدد الصور).
2. **أنواع وضع تحويل الصورة إلى فيديو**:
   - **وضع الإطار الأول** (صورة واحدة): يتم تثبيت الإطار الأول على صورة الإدخال.
   - **وضع الإطارين الأول والأخير** (صورتان): يتم تثبيت الإطار الأول والإطار الأخير على صور الإدخال.
   - **وضع دمج الصور المتعددة** (1-3 صور): يدعمه `veo31-fast-ingredients` فقط، ويُنشئ فيديو من خلال دمج محتوى صور متعددة.
3. **تصنيف الأوضاع**:

  - **وضع Fast**: `veo3-fast` و`veo31-fast` و`veo31-fast-ingredients`.
   - **وضع Quality**: `veo3` و`veo31` (جودة إنشاء أعلى).

---

### ⚠️ ملاحظات

- **النموذج الوحيد الذي يفرض تمرير صور**: يجب تمرير صور إلى `veo31-fast-ingredients` (1-3 صور)، وإلا فلن يتمكن من التشغيل.
- **قيود عدد الصور**:
  - يدعم `veo31-fast-ingredients` إدخال **1-3 صور** (وضع دمج الصور المتعددة).
  - تدعم النماذج الأخرى إدخال **صورتين** كحد أقصى (وضع الإطارين الأول والأخير).

## ميزة إنشاء الفيديو من الصور

إذا أردت إنشاء فيديو استنادًا إلى صور الإطار الأول والأخير، يمكنك ضبط المعلمة `action` على `image2video`، وإدخال مصفوفة روابط صور الإطار الأول والأخير `image_urls`.

بعد ذلك، يجب علينا ملء الكلمات التلميحية التي تحتاج إلى توسيع في الخطوة التالية لتخصيص إنشاء الفيديو، ويمكن تحديد المحتوى التالي:

- `model`: نموذج إنشاء الفيديو، ويشمل بشكل أساسي `veo31-fast` و`veo3` و`veo31` و`veo3-fast` و`veo31-fast-ingredients`.
- `image_urls`: عند اختيار سلوك إنشاء الفيديو من الصور `image2video`، يجب إدخال رابط الصورة المرجعية المطلوب رفعها.
- `prompt`: الكلمات التلميحية.

مثال على التعبئة كما يلي:

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

بعد إكمال التعبئة، يتم إنشاء الكود تلقائيًا كما يلي:

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

كود Python المقابل:

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo31-fast",
    "prompt": "Let it dance",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## الاستدعاء غير المتزامن

نظرًا لأن وقت إنشاء Veo Videos Generation API طويل نسبيًا، إذ يستغرق تقريبًا 1-2 دقيقة، فإذا لم تستجب API لفترة طويلة، فسيظل طلب HTTP محتفظًا بالاتصال، مما يؤدي إلى استهلاك إضافي لموارد النظام، لذلك توفر هذه API أيضًا دعمًا للاستدعاء غير المتزامن.

التدفق العام هو: عند قيام العميل بإرسال طلب، يحدد بالإضافة إلى ذلك حقل `callback_url`، وبعد أن يرسل العميل طلب API، ستعيد API فورًا نتيجة تتضمن معلومات حقل `task_id`، والذي يمثل معرّف المهمة الحالية. عند اكتمال المهمة، سيتم إرسال نتيجة إنشاء الفيديو بصيغة POST JSON إلى `callback_url` الذي حدده العميل، والذي يتضمن أيضًا حقل `task_id`، وبهذه الطريقة يمكن ربط نتيجة المهمة عبر المعرّف.

فيما يلي سنتعرف من خلال مثال على كيفية التنفيذ بالتحديد.

أولًا، استدعاء Webhook هو خدمة يمكنها استقبال طلبات HTTP، ويجب على المطور استبدالها بعنوان URL لخادم HTTP الذي أنشأه بنفسه. هنا ولتسهيل العرض، نستخدم موقع نموذج Webhook عام https://webhook.site/، ويمكن الحصول على URL لـ Webhook بمجرد فتح هذا الموقع، كما هو موضح في الصورة:

## معالجة الأخطاء

عند استدعاء API، إذا واجهت خطأً، فستعيد API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح به، رمز التفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جدًا، لقد تجاوزت حد المعدل.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة الخطأ

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
