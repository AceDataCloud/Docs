أنشئ Token أو كلمة مرور جديدة لبيانات اعتماد موجودة. يبقى معرّف بيانات الاعتماد، وارتباط Application، والحصص، والحقول الأخرى دون تغيير، ويصبح السر القديم غير صالح فورًا.

> سيؤدي التدوير إلى تعطيل العملاء الذين لا يزالون يستخدمون السر القديم. جهّز أولًا خطة للتوزيع الآمن والتراجع، ثم نفّذ عملية الكتابة.

## نظرة عامة على الواجهة

| العنصر    | المحتوى                                                                          |
| ---- | --------------------------------------------------------------------------- |
| الطريقة   | `POST`                                                                      |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}/rotate/` |
| المصادقة   | Account Token                                                               |
| Body | لا شيء أو `{}`                                                                     |

احصل على `credential_id` من [قائمة بيانات الاعتماد](https://platform.acedata.cloud/documents/platform-credential-list):

```shell
export PLATFORM_TOKEN='你的账户令牌'
export CREDENTIAL_ID='要轮换的 Credential ID'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/credentials/${CREDENTIAL_ID}/rotate/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

يعيد النجاح Credential المحدَّث. عند `type=Token` اقرأ `token` الجديد؛ وعند `type=Identity` اقرأ `password` الجديدة. تعامل مع الاستجابة الكاملة على أنها سر، وحدّث الجهات المستدعية فورًا.

## معالجة الأخطاء

- `401`: Account Token غير صالح.
- `403`: لا تملك صلاحية إدارة بيانات الاعتماد هذه.
- `404`: Credential ID غير موجود.
