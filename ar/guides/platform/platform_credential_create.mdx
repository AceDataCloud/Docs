title: "إنشاء بيانات اعتماد API لمنصة AceDataCloud"

إنشاء بيانات اعتماد API للأعمال لتطبيق. قد تتضمن استجابة الإنشاء رمز Token يمكن استدعاؤه مباشرة عبر `https://api.acedata.cloud/**`، أو اسم المستخدم/كلمة المرور لبيانات اعتماد من نوع Proxy؛ ويجب التعامل معها كأسرار.

## الأعمال التحضيرية

1. أنشئ [Account Token](https://platform.acedata.cloud/documents/platform-token).
2. احصل على `application_id` الذي تملكه من [قائمة Application](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='你的账户令牌'
export APPLICATION_ID='你的 Application ID'
```

## نظرة عامة على الواجهة

| البند    | المحتوى                                                   |
| ---- | ---------------------------------------------------- |
| الطريقة   | `POST`                                               |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/` |
| المصادقة   | Account Token، يحتاج OAuth token إلى `credentials:write`      |
| Body | JSON                                                 |

## جسم الطلب

| الحقل                  | النوع              | مطلوب  | الوصف                            |
| ------------------- | --------------- | --- | ----------------------------- |
| `application_id`    | UUID            | نعم   | Application الهدف                |
| `name`              | string          | لا   | الاسم المعروض لبيانات الاعتماد                         |
| `limited_amount`    | number / null   | لا   | الحد الأعلى للاستخدام لبيانات اعتماد واحدة؛ يشير `null` إلى عدم تعيين حد مستقل       |
| `expired_at`        | datetime / null | لا   | وقت انتهاء ISO 8601                 |
| `allowed_api_ids`   | UUID[] / null   | لا   | يُسمح فقط باستدعاء واجهات API هذه؛ ستتم تسوية المصفوفة الفارغة إلى دون قيود       |
| `host`              | string          | لا   | معلومات host لبيانات الاعتماد                    |
| `for_user_id`       | string          | لا   | يُستخدم عند إصدار بيانات اعتماد مفوضة عندما يكون مالك Application مستخدمًا آخر |
| `tags` / `metadata` | array / object  | لا   | بيانات توسعة مخصصة                       |

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/credentials/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"name\":\"production\",\"limited_amount\":50}"
```

## وصف الاستجابة

تُرجع العملية الناجحة `201` وكائن Credential:

- تعيد الخدمات من نوع API/Agent عادةً `type=Token` و`token`؛
- تعيد الخدمات من نوع Proxy عادةً `type=Identity` و`username` / `password`، ولا يسمح Proxy Application واحد إلا ببيانات اعتماد واحدة؛
- يتم إنشاء `id` و`user_id` و`creator_id` و`used_amount` وحقول الوقت من جهة الخادم.

تعيد واجهات القائمة والتفاصيل الحالية أيضًا النص الصريح لبيانات الاعتماد، لكن يجب ألا يعتمد العميل على هذا السلوك التاريخي. احفظها فورًا بعد الإنشاء، وتجنب كتابة الاستجابة في السجلات؛ فقد تتغير الواجهات مستقبلًا لتعيد بيانات مخفية.

## معالجة الأخطاء

- `400`: خطأ في تنسيق الحقول، أو `allowed_api_ids` غير معروف، أو أن Proxy Application لديه بالفعل بيانات اعتماد أو قيود إنشاء أخرى.
- `401`: Account Token غير صالح.
- `403/404`: لا تملك صلاحية الوصول إلى Application الهدف، أو أن Application/المستخدم المفوض غير موجود.
