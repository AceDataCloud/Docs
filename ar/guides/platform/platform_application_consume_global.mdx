---
title: "إعداد مشاركة الرصيد العالمي لـ AceDataCloud Application"
description: "Platform API guide - Ace Data Cloud"
---

قم بإعداد `allow_consume_global`. بعد التفعيل، يمكن لـ Application المطابق للشروط والقائم على الدفع حسب الاستخدام الاستمرار في استخدام الرصيد العالمي للحساب عندما يكون رصيده الخاص غير كافٍ.

## الأعمال التحضيرية

- أنشئ واحفظ بأمان [Account Token](https://platform.acedata.cloud/documents/platform-token).
- احصل على `application_id` الذي تملكه من [قائمة طلبات الخدمة](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='رمز حسابك'
export APPLICATION_ID='معرّف Application الخاص بك'
```

## نظرة عامة على الواجهة

| البند    | المحتوى                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------- |
| الطريقة   | `POST`                                                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/applications/{application_id}/update-allow-consume-global/` |
| المصادقة   | Account Token                                                                                      |
| Body | JSON                                                                                               |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/applications/${APPLICATION_ID}/update-allow-consume-global/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"allow_consume_global": true}'
```

عند النجاح، يتم إرجاع كائن Application المحدَّث. يُرجى الاعتماد على `allow_consume_global` في الاستجابة، بدلاً من افتراض أن قيمة الطلب قد تم حفظها بالتأكيد.

> لا يُسمح لـ Application من نوع `Period` باستهلاك الرصيد العالمي. حتى عند طلب `true`، سيُبقي الخادم هذا الحقل على `false`.

## معالجة الأخطاء

- `401`: Account Token غير صالح أو مفقود.
- `403`: الحساب الحالي ليس مالك Application هذا.
- `404`: معرّف Application غير موجود.

يُرجى الاعتماد على مدخل شحن الرصيد العالمي والباقات المتاحة فعليًا في لوحة تحكم المنصة، وعلى الباقات الفعلية المعادة بواسطة [إنشاء الطلب](https://platform.acedata.cloud/documents/platform-order-create)؛ لا تفترض وجود باقات من نوع `Wallet`.

## التطبيقات المصرح لها بالسحب على المكشوف

عندما يكون الحقل للقراءة فقط `allow_overdraft=true` في تطبيق قائم على الدفع حسب الاستخدام، يمكن لهذا التطبيق الاستمرار في الخصم من رصيده الخاص، حتى إذا أصبح الرصيد سالبًا، ولن ينتقل إلى الحساب العالمي بسبب عدم كفاية الرصيد. تظل التطبيقات التي لم يُفعَّل فيها السحب على المكشوف ملتزمة بـ `allow_consume_global`؛ وبعد التبديل، يعتمد السماح بالسحب على المكشوف على إعدادات الـ Application العالمي الذي يتم الخصم منه فعليًا.

## حد التزامن لحسابات التجربة

يستخدم النظام علامة المستخدم للقراءة فقط `has_recharged` لتسجيل ما إذا كان قد تم إكمال شحن مدفوع بنجاح أو إضافة أرصدة يدويًا بواسطة مسؤول، ويتم تحديث العلامة بعد نجاح العملية، وستُستكمل بيانات المستخدمين التاريخيين بشكل موحّد استنادًا إلى الطلبات أو سجلات إضافة الأرصدة الصريحة. الحسابات التي لم تُجرِ شحنًا مدفوعًا ولم يُضف لها مسؤول أرصدة يدويًا، يُسمح لها بتنفيذ طلب واحد قابل للفوترة فقط في الوقت نفسه على مستوى الحساب بأكمله؛ تشترك مفاتيح API المختلفة والخدمات المختلفة في هذا المقعد الواحد. لا تُعد المكافآت وبطاقات الاستبدال والأرصدة المُحوَّلة شحنًا مدفوعًا. لا تخضع الحسابات التي أكملت شحنًا مدفوعًا أو أُضيفت لها أرصدة يدويًا بواسطة مسؤول لهذا الحد الخاص بتزامن التجربة، وتظل ملتزمة بفحوصات الرصيد وحصة بيانات الاعتماد الأصلية.

عند وجود طلب قائم قيد التنفيذ، يُرجع الطلب الجديد `429 too_many_requests`. تظل واجهات الاستعلام المجانية مثل استعلام المهام قابلة للاستدعاء بشكل طبيعي. تتبع مصادقة الاتصال في Realtime عملية الفوترة الأصلية لكل جولة، ولا تشغل مقعد الطلب العادي هذا.

عندما تُرجع الواجهة غير المتزامنة «تم القبول»، تظل المهمة قيد التنفيذ، ويجب انتظار النتيجة النهائية قبل إرسال طلب إنشاء جديد. لا يعني انقطاع الشبكة أو انتهاء مهلة الوكيل أن المهمة قد توقفت؛ إذا لم تصل المهمة إلى حالة نهائية لفترة طويلة، يُرجى تقديم `trace_id` للتواصل مع الدعم للتحقق.

لا يغيّر هذا الحد الواجهات المتاحة للتجربة، ولا يغيّر قواعد الفوترة الأصلية. تظل الرسوم تُسوّى حسب الاستخدام الفعلي بعد انتهاء الطلب.
