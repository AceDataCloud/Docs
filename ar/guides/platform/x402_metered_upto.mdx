يستخدم Ace Data Cloud X402 حاليًا نوعين من الـ scheme: `exact` و`upto`. وهما يعالجان مشكلات فوترة مختلفة.

## `exact`

تعني `exact` أنه يمكن تحديد السعر لهذا الطلب قبل دخوله إلى API الهدف. المبلغ الذي يوقّعه العميل هو مبلغ الخصم النهائي.

مناسب لـ:

- إنشاء الصور ذات السعر الثابت؛
- إنشاء مهام الفيديو ذات السعر الثابت؛
- واجهات API للبحث أو الأدوات ذات السعر الثابت؛
- دفع الطلبات.

يستخدم EVM `exact` آلية USDC EIP-3009 `TransferWithAuthorization`:

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "exact",
    "network": "eip155:8453"
  },
  "payload": {
    "authorization": {
      "from": "0x...",
      "to": "0x...",
      "value": "95215",
      "validAfter": "1780237345",
      "validBefore": "1780240945",
      "nonce": "0x..."
    },
    "signature": "0x..."
  }
}
```

يتحقق Facilitator من التوقيع والمبلغ في مرحلة `/verify`، ويُرسل هذا التفويض إلى السلسلة في مرحلة `/settle`.

## `upto`

تعني `upto` أن العميل يصرّح بحد أقصى، ويقوم Ace Data Cloud بالتسوية حسب الاستخدام الفعلي بعد اكتمال الطلب، ولا يمكن أن يتجاوز الخصم الفعلي الحد الأقصى.

مناسب لـ:

- إكمالات الدردشة: يعتمد السعر النهائي على prompt tokens وcompletion tokens؛
- الاستجابات المتدفقة: لا يُعرف طول الإخراج الحقيقي إلا بعد انتهائه؛
- واجهات API المستقبلية للقياس اللاحق.

يستخدم `upto` آلية Permit2 `PermitWitnessTransferFrom`. لا يوقّع العميل على تحويل ثابت، بل على تفويض حد أقصى مع witness:

```json
{
  "x402Version": 2,
  "accepted": {
    "scheme": "upto",
    "network": "eip155:8453"
  },
  "payload": {
    "permit2Authorization": {
      "from": "0x...",
      "spender": "0x4020A4f3b7b90ccA423B9fabCc0CE57C6C240002",
      "nonce": "123456789",
      "deadline": "1780240945",
      "permitted": {
        "token": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
        "amount": "95215"
      },
      "witness": {
        "to": "0x...",
        "facilitator": "0x...",
        "validAfter": "1780237345"
      }
    },
    "signature": "0x..."
  }
}
```

يمثل `permitted.amount` الحد الأقصى، وليس بالضرورة مبلغ الخصم النهائي. يحوّل Gateway الاستخدام الفعلي إلى `amount` ويمرره إلى Facilitator في مرحلة `/record`. لا يسمح Facilitator بالتسوية إلا عندما يكون `amount &lt;= permitted.amount`.

نتيجة تشغيل برنامج Base `upto`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
signed ceiling 95215 atomic USDC
transfer value 3 atomic USDC
```

التوضيح:

- الحد الأقصى للتفويض المُعاد في 402 هو `95215` atomic USDC، ويوقّع العميل وفقًا لهذا الحد الأقصى.
- بعد الاستجابة الفعلية للنموذج، تمت تسوية `3` atomic USDC فقط، ويمكن التحقق من المعاملة على السلسلة في BaseScan.
- توضح هذه النتيجة الفرق الأساسي في `upto`: مبلغ التوقيع هو الحد الأقصى، ويمكن أن تكون الـ settlement على السلسلة أقل من الحد الأقصى.
- إذا تجاوز الاستخدام الفعلي الحد الأقصى، يجب أن يرفض Facilitator الـ settlement، ويحتاج العميل إلى إعادة التفويض وفق حد أقصى أعلى.

يتوفر `upto` حاليًا على Base فقط. عند الحاجة إلى قياس لاحق، يُرجى استخدام Base.

## لماذا تحتاج إلى Permit2 approve

يقوم x402 proxy في النهاية بسحب USDC من محفظة الدفع عبر Permit2 باستخدام `upto`. قبل الاستخدام الأول، تحتاج محفظة الدفع إلى منح Permit2 ERC-20 allowance مرة واحدة.

Python CLI:

```bash
pip install 'acedatacloud-x402[cli]'
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

برمجيًا:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

بعد إكمال التفويض، لا يزال كل طلب يحتاج إلى توقيع envelope جديد لـ `upto`، لأن nonce وdeadline وwitness والحد الأقصى للمبلغ كلها مختلفة.

## تسوية المبلغ الصفري

يدعم `upto` الحالات التي يكون فيها المبلغ الفعلي 0. على سبيل المثال، إذا لم تنجح API الهدف في إنتاج استخدام قابل للفوترة، يمكن لـ Gateway تمرير `amount = "0"`. سيُرجع Facilitator النجاح، لكنه لن يُنشئ معاملة على السلسلة.

يمكن أن يتجنب ذلك مشكلة «عدم نجاح الطلب مع استمرار خصم رسوم على السلسلة».

## توصيات الاختيار

| السيناريو                   | التوصية                       |
| -------------------- | ------------------------ |
| API ذات السعر الثابت             | استخدم `exact`، فالمنطق بسيط.         |
| دفع الطلبات                 | استخدم `exact`.              |
| إكمالات الدردشة، والفوترة حسب token      | استخدم Base `upto`.          |
| لم تُجرِ Permit2 approve بعد | استخدم `exact` أولًا للتأكد من عمله، ثم انتقل إلى `upto`. |

إذا لم تكن متأكدًا مما ينبغي اختياره، فاستخدم سلوك SDK الافتراضي أولًا؛ سيختار SDK payment requirement للشبكة المطابقة التي يُرجعها الخادم.

## قائمة التحقق لـ Base `upto`

عند التكامل أو استكشاف الأخطاء وإصلاحها، يُرجى التأكد من أن المعلمات التالية تأتي من استجابة 402 نفسها، وتبقى متسقة عند توقيع العميل:

| المعلمة                         | نقطة التحقق                                          |
| -------------------------- | -------------------------------------------- |
| `network`                  | يجب أن تكون `eip155:8453`.                           |
| `scheme`                   | يجب أن تكون `upto`.                                  |
| `extra.chainId`            | معرّف سلسلة Base هو `8453`.                      |
| `asset`                    | استخدم عنوان عقد Base USDC من استجابة 402.                  |
| `extra.facilitatorAddress` | يجب أن يشارك في witness، وأن يتطابق مع Facilitator `/supported`. |
| Permit2 allowance          | تحتاج محفظة الدفع إلى تفويض Permit2 لـ Base USDC مسبقًا.               |

الأخطاء الشائعة وطرق التعامل معها:

| الخطأ                                           | طريقة التعامل                                                                          |
| -------------------------------------------- | ----------------------------------------------------------------------------- |
| `invalid_upto_evm_payload_invalid_signature` | تحقق مما إذا كان chain id وعنوان facilitator وPermit2 domain وspender وحساب التوقيع وwitness متطابقة مع استجابة 402. |
| `PERMIT2_ALLOWANCE_REQUIRED`                 | نفّذ Permit2 approve لـ USDC على السلسلة الهدف ثم أعد بدء الطلب.                                         |
| `amount exceeds permitted amount`            | يتجاوز الاستخدام الفعلي الحد الأقصى الموقّع، ويتطلب توقيعًا جديدًا بحد أقصى أعلى.                                                       |
