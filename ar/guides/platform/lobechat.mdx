[‏LobeChat](https://lobehub.com/) هو عميل AI مفتوح المصدر يدعم الإضافات وقواعد المعرفة والنشر الذاتي، ويمكن استخدامه عبر النسخة الإلكترونية أو نشره باستخدام Docker. وهو يدعم نقاط النهاية المتوافقة مع OpenAI المخصصة، لذلك يمكنه التكامل مع Ace Data Cloud. يشرح هذا المقال عملية الإعداد.

## عملية التقديم

للتكامل مع Ace Data Cloud في LobeChat، انتقل أولاً إلى [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications)، واحصل على API Token الخاص بك، واحتفظ به للاستخدام لاحقاً.

![الحصول على Ace Data Cloud API Key](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تقم بتسجيل الدخول أو التسجيل بعد، فستتم إعادة توجيهك تلقائياً إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد التسجيل وتسجيل الدخول ستعود تلقائياً إلى الصفحة الحالية.

عند التقديم لأول مرة، سيتم منحك رصيد مجاني، ويمكنك تجربة خدمات نماذج Ace Data Cloud مجاناً.

## إعداد Ace Data Cloud

ادخل إلى **إعدادات التطبيق → نماذج اللغة** في LobeChat، واعثر على بطاقة **OpenAI** وقم بتمكينها، ثم املأ:

| الحقل       | القيمة                              | الوصف                         |
| -------- | ------------------------------ | -------------------------- |
| API Key  | Ace Data Cloud Token الخاص بك        | الـ Token المنسوخ من وحدة التحكم               |
| عنوان وكيل API | `https://api.acedata.cloud/v1` | **يجب أن ينتهي بـ `/v1`**           |
| وضع طلب العميل  | مفعّل                             | اتصال مباشر من المتصفح، ولا يمر Key عبر خادم LobeChat |

![واجهة إعداد LobeChat OpenAI Provider](https://cdn.acedata.cloud/629ef9d3084a.png)

> عند استخدام واجهة Chat Completions، يرجى إبقاء Responses API Specification معطّلاً.

لا يقوم LobeChat تلقائياً بإلحاق `/v1` بـ Base URL، ويكون مسار الطلب مباشرةً `{عنوان وكيل API}/chat/completions`:

| عنوان وكيل API                              | الطلب الفعلي                                                   | النتيجة                       |
| ------------------------------------- | ------------------------------------------------------ | ------------------------ |
| `https://api.acedata.cloud/v1`        | `https://api.acedata.cloud/v1/chat/completions`        | صحيح                       |
| `https://api.acedata.cloud/openai`    | `https://api.acedata.cloud/openai/chat/completions`    | قابل للاستخدام أيضاً                      |
| `https://api.acedata.cloud/openai/v1` | `https://api.acedata.cloud/openai/v1/chat/completions` | 404 (لا يوجد `/v1` ضمن `/openai`) |
| `https://api.acedata.cloud`           | `https://api.acedata.cloud/chat/completions`           | 404 (يفتقد `/v1`)             |

يستدعي LobeChat افتراضياً `/v1/models` لجلب النماذج تلقائياً. وعندما يكون عدد النماذج التي يعيدها Ace Data Cloud كبيراً، تصبح الواجهة طويلة جداً، لذا يُنصح بملء allow list يدوياً في «قائمة النماذج → أسماء النماذج المخصصة»، مفصولة بفواصل إنجليزية. إذا كنت تحتاج إلى اسم عرض مخصص، يمكنك استخدام `=`، بالتنسيق `MODEL_ID=اسم العرض`.

## اختيار النموذج

سيستمر كتالوج النماذج في التحديث. استخدم قائمة النماذج التي يحمّلها العميل تلقائياً كأولوية؛ وعند الحاجة إلى الملء اليدوي، اطلب أولاً `GET https://api.acedata.cloud/v1/models` للحصول على MODEL ID الحالي، ثم اختر وفقاً لقدرات السياق والصور واستدعاء الأدوات التي يدعمها العميل.

## التحقق من التكامل

إذا لم تكن متأكداً مما إذا كانت المشكلة في LobeChat أو في الشبكة، يمكنك أولاً استخدام curl للتحقق مباشرةً من نقطة النهاية (استبدل `{token}` بـ Token الخاص بك):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

إن إرجاع كائن `chat.completion` متوافق مع OpenAI يعني أن Token ونقطة النهاية جاهزان؛ وإذا تم إرجاع `HTTP 403 used_up` فهذا يعني أن Token صالح لكن الرصيد غير كافٍ، ويمكنك إعادة الشحن من [وحدة التحكم](https://platform.acedata.cloud/console/applications).

## متقدم: النشر الذاتي باستخدام Docker

إذا كنت ترغب في نشر نسخة خاصة لاستخدام الفريق، يمكنك تشغيلها بأمر Docker من سطر واحد (استبدل `{token}` بـ Token الخاص بك):

```bash
docker run -d \
  --name lobe-chat \
  -p 3210:3210 \
  -e OPENAI_API_KEY={token} \
  -e OPENAI_PROXY_URL=https://api.acedata.cloud/v1 \
  -e ACCESS_CODE=your-secret-password \
  -e OPENAI_MODEL_LIST="MODEL_ID" \
  lobehub/lobe-chat:latest
```

افتح `http://IP-الخادم-الخاص-بك:3210`، وأدخل `ACCESS_CODE` للاستخدام، ولا يحتاج أعضاء الفريق إلى ملء Key الخاص بهم. للاطلاع على الوصف الكامل لمتغيرات البيئة مثل `OPENAI_API_KEY` و`OPENAI_PROXY_URL` و`OPENAI_MODEL_LIST` المستخدمة أعلاه، راجع [وثائق متغيرات بيئة موفري نماذج LobeChat](https://lobehub.com/docs/self-hosting/environment-variables/model-provider). إذا كنت تستخدم nginx كوكيل عكسي لإضافة HTTPS، فتأكد من إضافة `proxy_buffering off;`، وإلا فسيتم تخزين الاستجابات المتدفقة مؤقتاً. لمزيد من أشكال النشر، يرجى الرجوع إلى [دليل البدء بالنشر الذاتي لـ LobeChat](https://lobehub.com/docs/self-hosting/start) و[النشر باستخدام Docker Compose](https://lobehub.com/docs/self-hosting/platform/docker-compose).

## الأسئلة الشائعة

### ظهور 404 Not Found

عادةً ما يكون عنوان وكيل API مكتوباً بالشكل `.../openai/v1` أو أن `/v1` مفقود. غيّره إلى `https://api.acedata.cloud/v1`.

### قائمة النماذج فارغة

فعّل مفتاح «وضع طلب العميل»؛ أو املأ allow list للنماذج يدوياً في «أسماء النماذج المخصصة».

### ظهور 401 Unauthorized

يرجى التأكد من أن API Key الملصق هو Token الخاص بـ Ace Data Cloud (من دون بادئة `Bearer` ومن دون مسافات إضافية)، وأن رصيد التطبيق التابع له كافٍ.
