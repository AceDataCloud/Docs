توضح هذه الوثيقة كيفية تحديد الأسعار عند استدعاء Ace Data Cloud API باستخدام X402، وما علاقتها بأسعار **Credits** (الأرصدة) العادية في المنصة.

## الخلاصة الأساسية

X402 ليست نظام تسعير مستقلاً. لكل استدعاء API تكلفة أصلية محسوبة بـ **Credits**، وهي المصدر الوحيد للسعر المشترك بين جميع طرق الفوترة (خصم أرصدة API Token، رصيد الحساب، والدفع على السلسلة عبر X402). يقوم X402 فقط بتحويل تكلفة Credits هذه إلى USDC على السلسلة بسعر صرف ثابت:

> **1 Credit = 0.095215 USDC** (أي `95215` atomic USDC، حيث يحتوي USDC على 6 منازل عشرية)

أي:

```text
X402 السعر (USDC) = تكلفة Credits لذلك الاستدعاء × 0.095215
```

سعر الصرف هذا ليس محدداً بشكل اعتباطي، فهو يساوي **سعر الوحدة لأرصدة Credits في أفضل شريحة (الكمية الكبيرة)** على المنصة. لذا فإن الدفع باستخدام X402 ≈ شراء Credits بسعر أفضل شريحة ثم استهلاكها، **من دون علاوة X402**، بل مع الاستفادة مباشرة من أرخص سعر لوحدة Credits، ومن دون الحاجة إلى إعادة شحن مسبق أو API Token.

## أساس التسعير

| البند        | القيمة                          | الشرح                                                    |
| --------- | ------------------------------ | ----------------------------------------------------- |
| سعر التحويل      | `1 Credit = 0.095215 USDC`     | سعر صرف ثابت موحد تحدده المنصة                                           |
| وحدة atomic | `1 Credit = 95215 atomic USDC` | يحتوي USDC على 6 منازل عشرية، و`atomic = floor(credits × 0.095215 × 1e6)` |
| الحد الأدنى للخصم      | `1 atomic USDC`（$0.000001）     | حتى إذا كانت التكلفة منخفضة جداً، تتم تسوية 1 atomic على الأقل                                 |
| عملة التسعير      | USDC                           | يستخدم Base عملة ERC-20 USDC، ويستخدم Solana عملة SPL USDC                  |

تُجرى عملية التحويل بشكل موحد من قبل المنصة، وتكون المبالغ متطابقة لجميع الشبكات المدعومة (Base وSolana)؛ وتختلف الشبكات فقط في عقد الأصل وطريقة التوقيع، أما السعر فواحد.

### العلاقة بسعر Credits العادي

تبيع المنصة Credits بنظام شرائح «كلما زاد الاستخدام، انخفض سعر الوحدة». عند الفوترة لكل استدعاء، يستخدم X402 دائماً سعر أفضل شريحة:

| طريقة الشراء/الدفع        | سعر الوحدة التقريبي لـ Credits            | الشرح                   |
| -------------- | ------------------------ | -------------------- |
| إعادة شحن مبدئية / بمبلغ صغير      | حوالي `$0.13 / Credit`       | سعر القائمة، وسعر وحدة Credits عند شرائها بكميات صغيرة |
| كمية كبيرة / أفضل شريحة       | `$0.095215 / Credit`     | أرخص سعر للوحدة               |
| **الدفع عبر X402 لكل استدعاء** | **`$0.095215 / Credit`** | **يساوي دائماً سعر أفضل شريحة**        |

بعبارة أخرى، يسوّي X402 كل استدعاء بسعر Credits الخاص بأفضل شريحة. يكون سعر الوحدة للمستخدمين الذين يشترون Credits عبر إعادة شحن بمبالغ صغيرة أعلى من X402؛ ولا يتطابق سعر وحدتهم مع X402 إلا لمستخدمي إعادة الشحن بكميات كبيرة.

## شكلان للسعر: `exact` و`upto`

في استجابة 402 الخاصة بـ X402، تكون `maxAmountRequired` هي المبلغ الذي يجب عليك توقيعه. وله شكلان:

- **`exact` (سعر ثابت)**: يمكن تحديد السعر قبل معالجة الطلب (الصور، الفيديو، الموسيقى، البحث، دفع الطلبات). `maxAmountRequired = تكلفة Credits للاستدعاء × 0.095215`، أي المبلغ المستحق لذلك الاستدعاء (وهو متطابق مع `cost.amount` في استجابة النجاح).
- **`upto` (قياس الاستخدام لاحقاً)**: للواجهات مثل إكمال الدردشة التي «لا يُعرف عدد الـ token المستخدمة فيها إلا عند انتهاء الاستجابة». تمثل `maxAmountRequired` **حداً أعلى** (محسوباً وفق حد الأرصدة المعين لذلك النموذج: الحد الأقصى لـ Credits × 0.095215)، وتتم التسوية الفعلية وفق الاستخدام الحقيقي، من دون تجاوز الحد الأعلى.

للتفاصيل البروتوكولية المتعلقة بهذين المخططين، راجع [مخططي الفوترة `exact` و`upto`](https://platform.acedata.cloud/documents/x402-metered-upto). ما يلي يتناول الأسعار فقط.

## أسعار Chat (إكمال الدردشة)

يستخدم إكمال الدردشة قياس `upto`: وتتم الفوترة حسب الاستخدام الفعلي لـ prompt / completion token. السعر لكل مليون (1M) token = `تكلفة Credits لكل 1M token لذلك النموذج × 0.095215`، وهو مطابق تماماً لسعر USD المعروض في دليل النماذج العام للمنصة (`/api/v1/models?with_pricing=true`).

يوضح الجدول التالي الأسعار الفعلية (المأخوذة من دليل النماذج، والمحسوبة بسعر تحويل X402)، بوحدة USD / 1M token:

| النموذج                | الإدخال / 1M | الإخراج / 1M  | حد `upto`             |
| ----------------- | ------- | -------- | --------------------- |
| gpt-4o-mini       | $0.0796 | $0.3183  | 1 Credit（$0.095215）   |
| gemini-2.5-flash  | $0.1591 | $1.3262  | 5 Credits（$0.476074）  |
| gpt-5 / gpt-5.1   | $0.6631 | $5.3050  | 20 Credits（$1.904299） |
| gemini-2.5-pro    | $0.6631 | $5.3050  | 50 Credits（$4.760750） |
| gpt-4.1           | $1.0610 | $4.2440  | 20 Credits（$1.904299） |
| claude-sonnet-4-5 | $0.6006 | $3.0028  | 50 Credits（$4.760750） |
| grok-4            | $1.5915 | $7.9574  | 10 Credits（$0.952149） |
| claude-opus-4-1   | $3.0028 | $15.0140 | 50 Credits（$4.760750） |

ملاحظات:

- يعرض الجدول سعر الوحدة المقاس حسب token؛ تكلفة الطلب الواحد = token الإدخال × سعر وحدة الإدخال + token الإخراج × سعر وحدة الإخراج.
- حد `upto` هو أكبر مبلغ مسموح توقيعه لطلب واحد لذلك النموذج؛ وليس الخصم الفعلي، إذ تكون غالبية الطلبات أقل بكثير من الحد.
- يحدد الحد فقط «أقصى مبلغ يمكن خصمه»، بينما تُحسب التسوية الفعلية وفق استخدام token.

### مثال: تطابق عرض السعر والخصم (`exact`)

فيما يلي **استدعاء مدفوع حقيقي** تم إجراؤه باستخدام X402Client الرسمي إلى `serp/google` (Base `exact`). ويوضح تطابق العناصر الثلاثة: عرض سعر 402، ومبلغ التوقيع، و`cost` المعاد في استجابة النجاح.

```text
# 1) طلب غير مدفوع -> 402، الحصول على عرض السعر (لا يوجد خصم)
POST /serp/google  ->  402
base/exact maxAmountRequired = 952 atomic = $0.000952 = 0.01 Credit
# 0.01 × 0.095215 = 0.00095215، التقريب إلى الأسفل إلى atomic = 952

# 2) توقيع PAYMENT-SIGNATURE بقيمة 952 atomic باستخدام المحفظة، ثم إعادة المحاولة
POST /serp/google (PAYMENT-SIGNATURE) -> 200
body.cost = {"amount": 0.000952, "currency": "usdc", "settlement": "authorized"}
```
تتطابق `cost.amount` المُعادة (0.000952 USDC) تمامًا مع عرض سعر 402 ومع `Credits × 0.095215`. حقل `settlement` هو حالة تسوية هذه الدفعة (`authorized` = تم التفويض)؛ تتم معالجة التسوية على السلسلة بواسطة المنصة، وللاطلاع على الآلية راجع [خطط الفوترة `exact` و`upto`](https://platform.acedata.cloud/documents/x402-metered-upto).

### حساب عرض سعر `upto` (المحادثة)

تُقاس المحادثة حسب التوكنات. يُحسب عرض سعر طلب معيّن (وليس الحد الأعلى) بالصيغة التالية (باستخدام gpt-4o-mini كمثال):

```text
Credits = 1e-6 × (0.835733 × prompt_tokens + 3.342933 × completion_tokens)
USDC    = Credits × 0.095215
```

طلب واحد يحتوي على 500 توكن prompt + 200 توكن completion:

```text
Credits = 1e-6 × (0.835733 × 500 + 3.342933 × 200) ≈ 0.001086 Credits
报价 USDC ≈ 0.001086 × 0.095215 ≈ $0.0001034
```

يوقّع العميل وفق حد `upto` الأعلى (بالنسبة إلى gpt-4o-mini، 1 Credit = `95215` atomic)، وهذا هو فقط **الحد الأقصى الممكن خصمه**؛ عرض السعر الفعلي لهذا الطلب (نحو $0.0001 في المثال أعلاه) أقل بكثير من الحد الأعلى، وتتم التسوية وفق استخدام التوكنات. وللاطلاع على آلية التسوية على السلسلة لـ `upto`، راجع [خطط الفوترة `exact` و`upto`](https://platform.acedata.cloud/documents/x402-metered-upto).

## أسعار الخدمات الأخرى (`exact` بسعر ثابت)

يمكن تحديد سعر واجهات مثل الصور والفيديو والموسيقى والبحث عند الطلب، وتستخدم `exact`. يبين الجدول التالي الأسعار الفعلية، المأخوذة من `maxAmountRequired` في استجابة 402 التي تعيدها الواجهات عبر الإنترنت للطلبات غير المدفوعة (لن تترتب أي رسوم على الاستعلام عن عرض السعر):

| صورة   | nano-banana                 | 0.14    | $0.013330 | 13330   |

ملاحظات:

- يتغير سعر الخدمة نفسها وفقًا لـ **النموذج والدقة والمدة والحركة** (خصوصًا الفيديو). الجدول أعلاه هو قيمة فعلية لمجموعة معيّنة من المعاملات، وهو للرجوع إلى المستوى السعري فقط.
- بالنسبة إلى هذه الواجهات ذات السعر الثابت (`exact`)، فإن `maxAmountRequired` في استجابة 402 الخاصة بهذا الطلب هو المبلغ المستحق لهذه المرة (ويتطابق مع `cost.amount` في الاستجابة الناجحة، وقد تم اختباره فعليًا في القسم السابق).
- يُحتسب كل سعر عبر التقريب إلى الأسفل إلى وحدة atomic من `Credits × 0.095215` (راجع أساس التسعير أعلاه)، باستخدام نفس آلية التحويل المستخدمة في المحادثة. بسبب تمثيل الفاصلة العائمة والتقريب، قد تختلف بعض القيم عن حاصل الضرب المباشر بمقدار 1 atomic ($0.000001)، وتُعتمد قيمة 402 المُعادة دائمًا.

## سعر دفع الطلب

عند استخدام X402 لدفع طلبات وحدة التحكم (شراء باقات / شحن Credits)، يعتمد السعر على ما يظهر في صفحة الطلب، ويكون `amount` في 402 هو أساس التوقيع النهائي. تمر مدفوعات الطلبات عبر واجهة API للمنصة وتتطلب رمز حساب، وللتفاصيل راجع [دليل دفع الطلبات](https://platform.acedata.cloud/documents/x402-order-payment).

مثال فعلي من دليل دفع الطلبات (شراء 10 Credits):

```text
description Ace Data Cloud Credits x 10.0
created price 1.26          # 订单创建价（USD）
settled    1.20 USDC        # 最终签名/结算金额（= 402 amount）
            = 1200000 atomic USDC
```

ملاحظة: **الدفع حسب الاستدعاء** (المحادثة / الخدمات الأخرى أعلاه) و**دفع الطلبات** مساران مختلفان. يستخدم الدفع حسب الاستدعاء سعر أفضل شريحة موحّد قدره `0.095215`/Credit؛ أما دفع الطلبات فيعتمد على تسعير الباقات، ويخضع الفرق بين سعر إنشائه ومبلغ التسوية النهائي إلى [دليل دفع الطلبات](https://platform.acedata.cloud/documents/x402-order-payment).

## كيفية الحصول على الأسعار في الوقت الفعلي

تتغير الأسعار حسب النموذج والمعاملات، لذا استخدم برنامجًا للحصول عليها في الوقت الفعلي، ولا تُضمّنها بشكل ثابت:

- **سعر حسب الاستدعاء**: أرسل طلبًا واحدًا إلى واجهة API المستهدفة **من دون** `PAYMENT-SIGNATURE` (ومن دون `Authorization` أيضًا)، واقرأ `accepts[].maxAmountRequired` المُعاد في 402. لا تترتب أي رسوم على هذه الخطوة. بالنسبة إلى واجهات `exact`، فهو السعر النهائي؛ وبالنسبة إلى واجهات `upto` (المحادثة)، فهو الحد الأعلى، وتتم التسوية الفعلية حسب الاستخدام.
- **سعر المحادثة لكل توكن**: `GET https://platform.acedata.cloud/api/v1/models?with_pricing=true&type=chat`، اقرأ `pricing.input_usd` / `pricing.output_usd` لكل نموذج (تم احتسابها بالفعل وفقًا لـ `credit_usd_rate`).
- **التحقق من التحويل**: `atomic = floor(Credits × 0.095215 × 1e6)`، `USDC = atomic / 1e6` (أي `USDC ≈ Credits × 0.095215`).

مثال على أقل طلب للحصول على السعر:

```bash
curl -sS -X POST https://x402.acedata.cloud/midjourney/imagine \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "a cat"}'
# 返回 402，accepts[].maxAmountRequired 即为该次（exact）调用价格
```

## الخلاصة
- سعر X402 = تكلفة Credits لهذه العملية × `0.095215`، وهو **نفس السعر** مثل فوترة Credits العادية، لكن تتم التسوية باستخدام USDC على السلسلة.
- `0.095215`/Credit هو سعر وحدة Credits في **أفضل شريحة** (للكميات الكبيرة) على المنصة؛ سعر وحدة Credits عند الشحن بمبالغ صغيرة أعلى، لذلك يساوي X402 الحصول تلقائيًا على أفضل سعر للوحدة.
- مبلغ التوقيع لواجهات `exact` (الصور / الفيديو / الموسيقى / البحث / الطلبات) هو المبلغ المستحق لهذه العملية؛ أما واجهات `upto` (الدردشة) فيكون توقيعها للحد الأعلى، وتتم التسوية وفقًا للاستخدام الفعلي.
- السعر المعتمد هو `maxAmountRequired` الذي تُرجعه 402: في `exact` هو المبلغ المستحق (ومتطابق مع `cost.amount` في الاستجابة الناجحة، وقد تم اختباره فعليًا)؛ وفي `upto` هو الحد الأعلى، بينما `cost.amount` في الاستجابة الناجحة هو المبلغ الفعلي الذي تمت تسويته حسب الاستخدام (≤ الحد الأعلى).
