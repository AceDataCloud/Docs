[Open WebUI](https://openwebui.com/) (المعروف سابقًا باسم Ollama WebUI) هو عميل ذكاء اصطناعي مفتوح المصدر يدعم تعدد المستخدمين، وقواعد المعرفة، وRAG، والنشر الخاص. وهو يدعم نقاط النهاية المخصصة المتوافقة مع OpenAI، لذا يمكنه الاتصال بـ Ace Data Cloud. يشرح هذا المقال عملية الإعداد.

## عملية التقديم

لتوصيل Ace Data Cloud في Open WebUI، انتقل أولًا إلى [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications)، واحصل على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![الحصول على Ace Data Cloud API Key](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم إعادة توجيهك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد التسجيل وتسجيل الدخول ستعود تلقائيًا إلى الصفحة الحالية.

عند التقديم لأول مرة، سيتم منحك رصيد مجاني، ويمكنك تجربة خدمات نماذج Ace Data Cloud مجانًا.

## نشر وإعداد Ace Data Cloud

يتصل Open WebUI بنقطة نهاية متوافقة مع OpenAI عبر متغيرات البيئة، ويمكن نشره باستخدام أمر Docker واحد (استبدل `{token}` بالـ Token الخاص بك):

```bash
docker run -d \
  --name open-webui \
  -p 3000:8080 \
  -e WEBUI_SECRET_KEY=$(openssl rand -base64 32) \
  -e OPENAI_API_BASE_URL=https://api.acedata.cloud/v1 \
  -e OPENAI_API_KEY={token} \
  -v open-webui:/app/backend/data \
  ghcr.io/open-webui/open-webui:main
```

| متغير البيئة                              | الوظيفة                                 |
| --------------------------------- | ---------------------------------- |
| `OPENAI_API_BASE_URL`             | مدخل Ace Data Cloud، **يجب أن ينتهي بـ `/v1`** |
| `OPENAI_API_KEY`                  | الـ Token الخاص بك                           |
| `WEBUI_SECRET_KEY`                | مفتاح تشفير الجلسة، يتم إنشاؤه تلقائيًا                  |
| `-v open-webui:/app/backend/data` | حفظ بيانات المحادثات / المستخدمين بشكل دائم                       |

افتح `http://IPالخادم_الخاص_بك:3000`، وسيصبح أول حساب يتم تسجيله مسؤولًا تلقائيًا. انتبه إلى قواعد مسار Base URL:

| OPENAI_API_BASE_URL                   | الطلب الفعلي                                                   | النتيجة                       |
| ------------------------------------- | ------------------------------------------------------ | ------------------------ |
| `https://api.acedata.cloud/v1`        | `https://api.acedata.cloud/v1/chat/completions`        | صحيح                       |
| `https://api.acedata.cloud/openai`    | `https://api.acedata.cloud/openai/chat/completions`    | يعمل أيضًا                      |
| `https://api.acedata.cloud/openai/v1` | `https://api.acedata.cloud/openai/v1/chat/completions` | 404 (لا يوجد `/v1` ضمن `/openai`) |

بعد تسجيل الدخول، انتقل إلى **Admin Panel → Settings → Connections** وانقر على «Verify Connection» للتحقق؛ وفي **Settings → Models** يمكنك تصفية النماذج المستخدمة كثيرًا وتثبيتها.

> بالإضافة إلى استخدام متغيرات البيئة، يدعم Open WebUI أيضًا إضافة اتصال مباشرة من الواجهة: انتقل إلى **Admin Settings → Connections**، وانقر على ➕ وأدخل URL (`https://api.acedata.cloud/v1`) وAPI Key، وسيستدعي Open WebUI تلقائيًا `/models` لجلب قائمة النماذج. راجع الوثائق الرسمية [Starting With OpenAI-Compatible Servers](https://docs.openwebui.com/getting-started/quick-start/connect-a-provider/starting-with-openai-compatible) للتفاصيل.

![واجهة إعداد اتصال Open WebUI Ace Data Cloud](https://cdn.acedata.cloud/f366abfd935d.png)

> يُستخدم `MODEL_ID` فقط لعرض allow list اختياري؛ وعند تركه فارغًا، ستُعرض جميع النماذج التي يعيدها `/models`.

## اختيار نموذج

سيستمر تحديث دليل النماذج. استخدم قائمة النماذج التي يحمّلها العميل تلقائيًا بشكلٍ أساسي؛ وعند الحاجة إلى الإدخال اليدوي، اطلب أولًا `GET https://api.acedata.cloud/v1/models` للحصول على معرفات النماذج الحالية، ثم اختر وفقًا للسياق والصور وقدرات استدعاء الأدوات التي يدعمها العميل.

## التحقق من التكامل

إذا لم تكن متأكدًا مما إذا كانت المشكلة في Open WebUI أو في الشبكة، يمكنك أولًا استخدام curl للتحقق مباشرة من نقطة النهاية (استبدل `{token}` بالـ Token الخاص بك):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

إن أعاد كائن `chat.completion` متوافقًا مع OpenAI، فهذا يعني أن الـ Token ونقطة النهاية جاهزان؛ وإذا أعاد `HTTP 403 used_up`، فهذا يعني أن الـ Token صالح لكن الرصيد غير كافٍ، ويمكنك إعادة الشحن من [وحدة التحكم](https://platform.acedata.cloud/console/applications).

## متقدم: قاعدة المعرفة وتعدد المستخدمين

تستخدم قاعدة المعرفة (RAG) في Open WebUI افتراضيًا ChromaDB لتخزين المتجهات، ويمكن تعيين نموذج التضمين إلى `text-embedding-3-large` (عبر Ace Data Cloud)، ولا تُخزّن النصوص الأصلية للمستندات إلا على خادمك، ولا تُرسل إلى النموذج سوى المقاطع المطابقة. في **Admin Panel → Users** يمكنك إدارة أدوار المستخدمين (Pending / User / Admin)؛ ويوصى بتعيين «Default User Role» إلى `pending`، بحيث يحتاج المستخدمون الجدد إلى مراجعة قبل أن يتمكنوا من الاستخدام، لتجنب تسجيل الغرباء واستهلاك الرصيد بشكل عشوائي. إذا كنت تستخدم وكيل nginx العكسي، فأضف `proxy_buffering off;` و`client_max_body_size 100M;`.

## الأسئلة الشائعة

### ظهور Connection error / 404

عادةً ما يكون `OPENAI_API_BASE_URL` مكتوبًا كـ `.../openai/v1` أو يفتقد إلى `/v1`۔ غيّره إلى `https://api.acedata.cloud/v1`.

### تعذر إجراء محادثة بعد رفع مستند

في إعدادات RAG ضمن Admin Panel، اختر نموذج التضمين `text-embedding-3-large` (موفر OpenAI).

### فقدان البيانات بعد إعادة تشغيل الحاوية

يجب تحميل وحدة بيانات عند التشغيل: `-v open-webui:/app/backend/data`.
