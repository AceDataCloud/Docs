تتمحور Ace Data Cloud X402 حاليًا حول تسوية USDC، وتدعم نوعين من السلاسل: EVM وSolana. تختلف طريقة التوقيع وعنوان الأصل وسلوك gas وسيناريوهات التطبيق بين الشبكات المختلفة، لذا تحتاج إلى اختيار الشبكة مسبقًا قبل التكامل.

## تستخدم معرّفات الشبكة CAIP-2

إن `accepts[].network` في x402 v2 هو معرّف CAIP-2، وليس اختصارًا مثل `base` أو `skale`. يجب على العميل مطابقة الشبكة بالمقارنة وفق سلسلة CAIP-2:

| الشبكة             | معرّف CAIP-2                                 |
| -------------- | ----------------------------------------- |
| Base           | `eip155:8453`                             |
| SKALE Base     | `eip155:1187947933`                       |
| Solana mainnet | `solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp` |

## مصفوفة الدعم

| الشبكة     | scheme  | الأصل                  | طريقة التوقيع                                 | سيناريوهات التطبيق                        |
| ------ | ------- | ------------------- | ------------------------------------ | --------------------------- |
| Base   | `exact` | Base USDC           | EIP-3009 `TransferWithAuthorization` | موصى بها افتراضيًا، ودعم المحافظ والسيولة ناضج.            |
| Base   | `upto`  | Base USDC + Permit2 | Permit2 `PermitWitnessTransferFrom`  | واجهات API ذات القياس اللاحق مثل الدردشة والنماذج.             |
| SKALE  | `exact` | SKALE bridged USDC  | EIP-3009 `TransferWithAuthorization` | تكلفة gas منخفضة، مناسبة للتحقق من مدفوعات EVM والاستدعاءات منخفضة التكلفة. |
| Solana | `exact` | Solana USDC         | SPL `TransferChecked`                | سيناريوهات محافظ Solana أو Agent أو التطبيقات على السلسلة.    |

يتوفر `upto` حاليًا على Base فقط. تخضع العناصر المتاحة فعليًا لما تُرجعه واجهة API في `accepts`. يمكنك أيضًا الاطلاع على Facilitator:

```bash
curl https://facilitator.acedata.cloud/supported
```

استجابة Facilitator `/supported`:

```json
{
  "kinds": [
    { "x402Version": 2, "scheme": "exact", "network": "eip155:8453" },
    {
      "x402Version": 2,
      "scheme": "upto",
      "network": "eip155:8453",
      "extra": { "facilitatorAddress": "0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708" }
    },
    { "x402Version": 2, "scheme": "exact", "network": "eip155:1187947933" },
    {
      "x402Version": 2,
      "scheme": "exact",
      "network": "solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp",
      "extra": { "feePayer": "3SPm6qbgsDkj24MuR8Ss4sH97fziqyCiqFKDyeVU2igq" }
    }
  ]
}
```

توضيح النتائج:

- `exact` في Base وSKALE وSolana هو مسار دفع بمبلغ ثابت.
- تقدم Base فقط مسار القياس اللاحق `upto`، والذي يعتمد على موافقة Permit2.
- إن `extra.facilitatorAddress` في إدخال `upto` هو العنوان الذي يجب على العميل كتابته في witness عند التوقيع، ويجب أن يتطابق مع القيمة التي يعيدها الخادم.

## Base

تستخدم Base عقد USDC الرسمي:

```text
0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913
```

في مخطط `exact`، يوقّع العميل على EIP-712 `TransferWithAuthorization`. يتضمن محتوى التوقيع:

- `from`: عنوان محفظة الدفع
- `to`: عنوان استلام Ace Data Cloud
- `value`: مبلغ هذه الدفعة
- `validAfter` / `validBefore`: نافذة صلاحية التوقيع
- `nonce`: nonce عشوائي من 32 بايت

بعد أن يتحقق Facilitator من التوقيع، سيستدعي على السلسلة `transferWithAuthorization` الخاص بـ USDC لإتمام التحويل.

Base هي شبكة التكامل الرسمية الأكثر توصية، وهي مناسبة خصوصًا للقياس اللاحق `upto`، لأن منظومة Permit2 وUSDC والمحافظ أكثر نضجًا.

مثال على نتيجة التحقق من Base `exact`:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
content ADC_BASE_E2E_OK
tx 0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
block 46726299
explorer https://basescan.org/tx/0x408430ab3451bc22a51e510cdb4b063d6b9686724fea7a31fc109af20f5cd2f3
transfer value 95215 atomic USDC
```

توضيح النتائج:

- تُرجع إعادة محاولة الدفع عبر API محتوى النموذج `ADC_BASE_E2E_OK`.
- يمكن التحقق من المعاملة على السلسلة في BaseScan، ورقم الكتلة هو `46726299`.
- يقابل `95215` atomic USDC مقدار `0.095215` USDC، وهو مبلغ التسوية الفعلي لاستدعاء API هذا.

نتيجة تشغيل البرنامج لدفع طلب Base `exact`:

```text
order 78481793-304e-47f7-bc0c-8231aec9cc1e
state Finished
tx 0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
block 46726704
explorer https://basescan.org/tx/0xfec08cc00a159ea1ec692b32faa9bf3d17595a986301169e689d94f58bc44151
transfer value 1200000 atomic USDC
```

توضيح النتائج:

- الحالة النهائية لطلب المنصة هي `Finished`.
- يُكتب `pay_id` الخاص بالطلب في تجزئة معاملة Base نفسها.
- يقابل `1200000` atomic USDC مقدار `1.2` USDC، وهو مبلغ الدفع الفعلي التاريخي لطلب 10 Credits هذا بموجب السياسة القديمة؛ لم تعد الطلبات الجديدة تتمتع بخصم إضافي لطريقة دفع X402، ويخضع مبلغ التوقيع المحدد لاستجابة 402 هذه المرة.

## SKALE

تستخدم SKALE USDC المجسّر، وطريقة التوقيع مشابهة لـ Base، وهي أيضًا EIP-3009. وهي مناسبة لسيناريوهات دفع EVM ذات تكلفة gas منخفضة؛ وتظل الاستدعاءات الفعلية خاضعة لما تُرجعه واجهة API في `accepts`.

ستتضمن `accepts` النموذجية لـ 402 في SKALE:

```json
{
  "network": "eip155:1187947933",
  "scheme": "exact",
  "extra": {
    "name": "Bridged USDC (SKALE Bridge)",
    "version": "2",
    "chainId": 1187947933,
    "verifyingContract": "0x85889c8c714505E0c94b30fcfcF64fE3Ac8FCb20"
  }
}
```

توفر SKALE حاليًا `exact` فقط. إذا كنت تحتاج إلى القياس اللاحق، فاستخدم Base `upto`.

مثال على نتيجة التحقق من SKALE `exact`:

```text
content ADC_SKALE_E2E_OK
tx 0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
block 1969317
explorer https://skale-base-explorer.skalenodes.com/tx/0x9fd09901e74c763325fe118b2bc64765c3fca785b86b24a78b97964384db084f
paid 0.095215 USDC
```

توضيح النتائج:
- تُعيد محاولة الدفع عبر API محتوى النموذج `ADC_SKALE_E2E_OK`.
- يمكن العثور على المعاملة في مستكشف SKALE، ورقم الكتلة هو `1969317`.
- مبلغ التسوية لهذه الدفعة من نوع `exact` هو `0.095215` USDC.

## Solana

تستخدم Solana ‏SPL USDC ‏`TransferChecked`. سينشئ العميل معاملة تحويل، ويوقّعها ويرسلها، ثم يضع توقيع المعاملة أو المعاملة المتسلسلة في envelope ‏`PAYMENT-SIGNATURE`.

خصائص Solana:

- استخدام Solana wallet adapter أو base58 secret key؛
- الأصل هو Solana USDC mint؛
- يدعم حاليًا `exact` فقط؛
- سيتحقق Facilitator من mint وdestination وauthority وamount الخاصة بتعليمة التحويل.

إذا استُخدم نمط wallet fee payer، فسترسل المحفظة المعاملة مباشرةً، ويتولى Facilitator تأكيد المعاملة وإرجاع نتيجة settlement.

مثال على نتيجة تحقق Solana ‏`exact`:

```text
payer AY2RmGm2zPxB1uKvvF4dKyYdr2VySyL3wcD1MKJZoLRd
HTTP 402 -> HTTP 200
content ADC_SOLANA_E2E_OK
chain signature not confirmed in this run
```

توضيح النتيجة:

- أعادت paid retry بالفعل HTTP 200، وأخرج النموذج `ADC_SOLANA_E2E_OK`.
- قد تواجه استعلامات signature على السلسلة عبر RPC العام تقييدًا للمعدل.
- نظرًا لأن استعلامات RPC العامة قد تكون مقيّدة بالمعدل، فلا يُكتب هنا Solana explorer. عند الحاجة إلى مطابقة صارمة، يرجى استخدام Solana RPC الخاص بك أو سجلات settlement من جانب المنصة لتأكيد توقيع المعاملة.

## كيفية الاختيار

| ما الذي تريد فعله        | الشبكة الموصى بها                         |
| ------------ | ---------------------------- |
| تشغيل المسار الأدنى بسرعة     | SKALE `exact` أو Base `exact` |
| استهداف مستخدمي Web3 العاديين | Base                         |
| إجراء قياس لاحق مثل إكمال الدردشة   | Base `upto`                  |
| تطبيقات نظام Solana البيئي  | Solana `exact`               |
| التحقق من مدفوعات EVM منخفضة التكلفة | SKALE `exact`                |

بغض النظر عن السلسلة التي تختارها، لا تقم بترميز السعر بشكل ثابت في العميل. يحدده السعر الذي يعيده الخادم عبر `accepts[].maxAmountRequired`.

## شبكات EVM الجديدة

توفر الشبكات التالية دعمًا برمجيًا لمدفوعات USDC الأصلية ذات المبلغ الثابت، ويتم فتحها تدريجيًا حسب الشبكة.
يعتمد مدى توفرها على `accepts` الذي يعيده الطلب أو API؛ وهذا لا يعني أن جميع الشبكات مفعّلة في الإنتاج.

| Network      | Alias      | CAIP-2         | Native USDC                                  |
| ------------ | ---------- | -------------- | -------------------------------------------- |
| Arbitrum One | `arbitrum` | `eip155:42161` | `0xaf88d065e77c8cC2239327C5EDb3A432268e5831` |

تدعم هذه الشبكات `exact` فقط، ودقة العملة هي 6. لا تستخدم USDC المربوط الذي يحمل الاسم نفسه.
عند استخدام X402 Client الرسمي لـ TypeScript/Python، يمكنك تمرير الاسم المختصر في الجدول أو معرّف CAIP-2.
يستخدم العميل معرّف السلسلة المستهدفة لإنشاء التوقيع؛ ويجب أن تدعم المحفظة الشبكة المستهدفة.

يسرد جدول الدعم الرسمي لمحفظة Phantom الإضافية Arbitrum وPolygon؛ أما Optimism وAvalanche
فليستا مدرجتين حاليًا في الجدول، ويمكن استخدام Rabby أو MetaMask اللذين يدعمان السلسلة المستهدفة. يمكن أن تكون عناوين EVM متطابقة على سلاسل مختلفة،
لكن الأرصدة مستقلة عن بعضها، ولا تنطبق عناوين Solana على EVM USDC.
راجع [جدول دعم محفظة Phantom](https://docs.phantom.com/wallet-sdks-overview#chain-support).

### مدخل الإطلاق التدريجي للشبكات الجديدة

تكون مداخل السلاسل الجديدة مخفية افتراضيًا. عند زيارة لوحة التحكم أو Studio، يمكنك استخدام `?features=x402-arbitrum`
لتفعيل السلسلة المقابلة، وتُفصل عدة flags بفواصل. لتعطيل سلسلة واحدة استخدم `?features=-x402-arbitrum`،
ولمسح التجاوزات المحلية استخدم `?features=none`. يُحفظ المفتاح لكل نطاق بشكل منفصل.
تستخدم عروض أسعار الطلبات وإعادة محاولة الدفع المفتاح نفسه، وسيتحقق الخادم بشكل مستقل؛ ولا يزال بالإمكان عرض سجلات الدفع الحالية.
لن يؤدي تفعيل page flag فقط إلى تمكين سلسلة لم تُضبط بعد، وتظل الشبكات القابلة للدفع فعليًا خاضعة لقيمة `accepts` الفورية.
