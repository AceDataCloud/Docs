يشرح هذا الدليل العملية الكاملة لـ Ace Data Cloud X402 باستخدام طلب API بأقل قدر ممكن. الهدف ليس كتابة كود معقد أولًا، بل فهم: لماذا يعيد الطلب الأول 402، وما الذي يوجد داخل `accepts`، وكيف تجعل `PAYMENT-SIGNATURE` طلب API نفسه طلبًا مدفوعًا.

## التحضيرات

تحتاج إلى تجهيز:

| العنصر   | الوصف                                                   |
| ---- | ---------------------------------------------------- |
| المحفظة   | محفظة تدعم الشبكة المستهدفة. تستخدم Base محفظة EVM، وتستخدم Solana محفظة Solana.      |
| USDC | يجب أن تحتوي المحفظة على كمية كافية من USDC. يعتمد المبلغ الفعلي على `maxAmountRequired` في استجابة 402. |
| بيئة التطوير | يُوصى بـ Node.js 18+ لـ TypeScript؛ ويُوصى بـ Python 3.10+ لـ Python.    |
| SDK  | يُوصى باستخدام SDK الرسمي، ولا يُنصح بكتابة تفاصيل التوقيع يدويًا.                                |

لا تحتاج استدعاءات X402 إلى Ace Data Cloud API Token. لا يحمل الطلب الأول من SDK `Authorization`، وستعيد Gateway `402 Payment Required` ومتطلبات الدفع؛ ثم يعيد SDK المحاولة تلقائيًا بعد التوقيع.

## تثبيت SDK

عناوين المصدر والحزم:

- مستودع SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- مستودع X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- npm: `@acedatacloud/sdk`، `@acedatacloud/x402-client`
- PyPI: `acedatacloud`، `acedatacloud-x402`

TypeScript:

```bash
npm install @acedatacloud/sdk @acedatacloud/x402-client ethers
```

Python:

```bash
pip install acedatacloud acedatacloud-x402
```

إذا أردت استخدام Solana، تحتاج أيضًا إلى تثبيت الاعتمادات المقابلة:

```bash
npm install @solana/web3.js
```

اعتمادات signer الخاصة بـ Solana في إصدار Python مضمنة بالفعل في `acedatacloud-x402`.

مخرجات التثبيت والتحقق من الاستيراد في بيئة مؤقتة نظيفة:

```text
@acedatacloud/sdk@2026.504.2
@acedatacloud/x402-client@2026.531.3
ethers@6.16.0
@solana/web3.js@1.98.4

acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
```

توضيح النتائج:

- حزم npm وحزم PyPI كلاهما حزم منشورة فعلية، وليست أسماءً مؤقتة في الوثائق.
- يقوم `acedatacloud-x402[cli]` بتثبيت CLI، ويمكن استخدام الأمر الفرعي `approve-permit2` لتفويض Permit2 في سيناريوهات `upto`.

## يعيد الطلب الأول 402

يمكنك أولًا استخدام `curl` لمعرفة ما الذي يعيده الطلب غير المدفوع. لن ينتج المثال التالي أي رسوم، لأنه لا يحمل `PAYMENT-SIGNATURE`:

```bash
curl -sS -X POST https://x402.acedata.cloud/openai/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "gpt-4o-mini",
    "messages": [{"role": "user", "content": "hi"}],
    "max_tokens": 1
  }'
```

سيحتوي جسم الاستجابة على مصفوفة `accepts`، ويكون الهيكل الشائع كما يلي:

```json
{
  "x402Version": 2,
  "resource": {
    "url": "/openai/chat/completions",
    "description": "AceDataCloud API call",
    "mimeType": "application/json"
  },
  "accepts": [
    {
      "scheme": "exact",
      "network": "eip155:8453",
      "maxAmountRequired": "95215",
      "amount": "95215",
      "maxTimeoutSeconds": 3600,
      "resource": "/openai/chat/completions",
      "description": "...",
      "payTo": "0x...",
      "asset": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
      "extra": {
        "name": "USD Coin",
        "version": "2",
        "chainId": 8453,
        "verifyingContract": "0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913"
      }
    }
  ],
  "error": "PAYMENT-SIGNATURE header is required"
}
```

يوضع محتوى التحدي نفسه أيضًا بصيغة base64 في ترويسة الاستجابة `PAYMENT-REQUIRED`، لتسهيل قراءة العميل لمتطلبات الدفع دون تحليل body.

ملخص مخرجات البرنامج لطلب API إنتاجي غير مدفوع كما يلي:

```text
status=402
x402Version 2
accepts [
  ('eip155:8453', 'exact', '95215'),
  ('eip155:8453', 'upto', '95215'),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact', '95215'),
]
```

توضيح النتائج:

- لم يحمل الطلب الأول `Authorization` أو `PAYMENT-SIGNATURE`، لذلك يعيد HTTP 402 ولا ينتج رسومًا.
- `accepts` هو الأساس الوحيد الموثوق للتوقيع لهذا الطلب، ويتضمن الشبكات الاختيارية، وscheme، والحد الأقصى للمبلغ، وعنوان المستلم، وعنوان الأصل.
- `network` هو معرّف CAIP-2، ويجب على العميل المطابقة باستخدام سلسلة CAIP-2 عند اختيار الشبكة.
- الحد الأقصى للمبلغ لطلب المحادثة الأدنى هذا من `gpt-4o-mini` هو `95215` atomic USDC، أي `0.095215` USDC.
- يجب قراءة استجابة 402 الخاصة بكل طلب، ولا تضع مبلغ المثال في الكود التجاري بشكل ثابت.

معاني الحقول:

| الحقل                  | الوصف                                                             |
| ------------------- | -------------------------------------------------------------- |
| `scheme`            | مخطط الدفع. يشير `exact` إلى مبلغ ثابت، ويشير `upto` إلى حد تفويض علوي وتسوية وفقًا للاستخدام الفعلي.                     |
| `network`           | معرّف CAIP-2 لشبكة الدفع، مثل `eip155:8453` و`solana:5eykt4...`.           |
| `maxAmountRequired` | الحد الأقصى لمبلغ الدفع، ووحدته هي USDC atomic units، ويمثل `95215` قيمة `0.095215` USDC.       |
| `amount`            | المبلغ المطلوب تسويته هذه المرة؛ يكون `exact` مساويًا لـ `maxAmountRequired`، بينما يُعاد كتابة `upto` حسب الاستخدام الحقيقي في مرحلة التسوية. |
| `payTo`             | عنوان المستلم.                                                          |
| `asset`             | عنوان عقد USDC أو عنوان Solana mint.                                     |
| `extra`             | معلومات موسعة مطلوبة للتوقيع، مثل chain ID وEIP-712 domain وعنوان Permit2.                      |

## إكمال إعادة محاولة الدفع باستخدام SDK

فيما يلي مثال TypeScript بأقل قدر ممكن. يحدد `network: 'base'`، وسيختار handler payment requirement الخاص بـ Base من استجابة 402 لهذه المرة؛ بينما يبقى المبلغ الفعلي وعنوان المستلم معتمدين على `accepts`:
```ts
import { Wallet } from 'ethers';
import { AceDataCloud } from '@acedatacloud/sdk';
import { createX402PaymentHandler } from '@acedatacloud/x402-client';

const wallet = new Wallet(process.env.EVM_PRIVATE_KEY!);

const evmProvider = {
  async request({ method, params }: { method: string; params?: unknown[] }) {
    if (method !== 'eth_signTypedData_v4') {
      throw new Error(`unsupported method: ${method}`);
    }
    const [, typedDataJson] = params as [string, string];
    const typedData = JSON.parse(typedDataJson);
    return wallet.signTypedData(typedData.domain, typedData.types, typedData.message);
  }
};

const client = new AceDataCloud({
  paymentHandler: createX402PaymentHandler({
    network: 'base',
    evmProvider,
    evmAddress: wallet.address
  })
});

const response = await client.openai.chat.completions.create({
  model: 'gpt-4o-mini',
  messages: [{ role: 'user', content: 'Reply with exactly: hello' }],
  max_tokens: 8
});

console.log(response.choices[0].message.content);
```

تحدث أربع خطوات خلف هذه الشفرة:

1. ترسل SDK طلب API عاديًا، دون `Authorization`.
2. تعيد Gateway `402 Payment Required` و`accepts`.
3. يختار `createX402PaymentHandler` متطلب الدفع الخاص بـ `network = 'base'` ويوقّع `PAYMENT-SIGNATURE`.
4. تعيد SDK محاولة الطلب باستخدام نفس جسم الطلب، وتستدعي Gateway الـ Facilitator للتحقق والتسوية قبل السماح بالوصول إلى API الهدف.

## عرض القدرات التي يدعمها Facilitator

لا تعتمد X402 API على دليل الموارد. يستدعي العميل مباشرةً API المعروف، ويستخدم
`402 Payment Required` و`accepts` المعادَين لحظيًا من ذلك الطلب باعتبارهما الأساس الوحيد للسعر والتوقيع.

يوجد إعلان قدرات Facilitator في:

```bash
curl https://facilitator.acedata.cloud/.well-known/x402
```

وهو يصف فقط `/supported` و`/verify` و`/settle` وشبكات الدفع المفعّلة حاليًا، ولا يسرد موارد API.

عنوان Facilitator الإنتاجي لـ Ace Data Cloud هو:

```text
https://facilitator.acedata.cloud
```

يمكنك عرض الشبكات وscheme التي يدعمها:

```bash
curl https://facilitator.acedata.cloud/supported
```

ستسرد `kinds` المعادة الشبكات وscheme التي يدعمها Facilitator. عند الاستدعاء الفعلي، يظل المرجع هو `accepts` المعاد من API.

مخرجات Facilitator `/supported`:

```text
kinds [
  ('eip155:8453', 'exact'),
  ('eip155:8453', 'upto', {'facilitatorAddress': '0xd019238EAA8a9Ca13C5792Ca10B4029D6ce25708'}),
  ('solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp', 'exact')
]
```

توضح النتيجة:

- يوضح `/supported` أن Facilitator يمتلك قدرات التحقق والتسوية لهذه الشبكات وscheme.
- يدعم كل من Base وSolana `exact`؛ بينما يتوفر `upto` حاليًا على Base فقط.
- ما إذا كانت API محددة تسمح بشبكة معينة يظل خاضعًا لـ 402 `accepts` الخاصة بتلك API.
