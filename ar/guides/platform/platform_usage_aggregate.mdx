تجميع عدد الطلبات والمقدار الفعلي المخصوم للحساب الحالي حسب التاريخ وواجهة API، وهو مناسب لإعداد التقارير الشهرية، والمخططات الاتجاهية، وتحليل التكلفة. استخدم [قائمة سجلات الاستدعاء](https://platform.acedata.cloud/documents/platform-usage-list) عند الحاجة إلى استكشاف الأخطاء وإصلاحها لكل سجل، واستخدم [تصدير حجم الاستدعاءات](https://platform.acedata.cloud/documents/platform-usage-export) عند الحاجة إلى تفاصيل كاملة دون اتصال.

نطاق الاستعلام لسجلات الاستدعاء وملخصات الفوترة هو آخر 60 يومًا؛ بينما يُحتفظ بنصوص الطلبات والاستجابات بشكل منفصل لآخر 30 يومًا. لا يؤثر انتهاء صلاحية النص على الرسوم الفعلية أو الاستخدام أو الإحصاءات المجمّعة لذلك السجل.

## الأعمال التحضيرية

1. سجّل الدخول إلى [منصة AceDataCloud](https://platform.acedata.cloud).
2. أنشئ رمز حساب في [وحدة تحكم Account Token](https://platform.acedata.cloud/console/platform-tokens)، واحفظه فورًا.
3. إذا كنت بحاجة إلى تضييق النطاق، فاحصل على المعرّف المقابل من [قائمة طلبات الخدمة](https://platform.acedata.cloud/documents/platform-application-list)، أو [قائمة بيانات اعتماد API](https://platform.acedata.cloud/documents/platform-credential-list)، أو [قائمة API](https://platform.acedata.cloud/documents/platform-api-list).

راجع [إدارة رموز الحساب](https://platform.acedata.cloud/documents/platform-token) للحصول على شرح كامل للرمز. تستخدم هذه الواجهة Account Token، ولا تستخدم Credential الخاص بالعمل.

```shell
export PLATFORM_TOKEN='رمز حسابك'
```

## نظرة عامة على الواجهة

| العنصر           | المحتوى                                                            |
| --------------- | ------------------------------------------------------------------ |
| الطريقة          | `GET`                                                              |
| URL             | `https://platform.acedata.cloud/api/v1/usage/apis/aggregate/`      |
| المصادقة         | `Authorization: Bearer ${PLATFORM_TOKEN}`                          |
| OAuth Scope     | `usage:read` (يتضمن `platform:read` / `platform` بشكل موسّع)       |
| نطاق الصلاحيات   | المستخدم العادي يقتصر على استخدامه المدفوع؛ يمكن للمسؤول تمرير `user_id` |

## معلمات الاستعلام

| المعلمة             | النوع             | مطلوب | الافتراضي                                  | الوصف                                              |
| ------------------ | ---------------- | ----- | ------------------------------------------ | ------------------------------------------------- |
| `created_at_from`  | date / datetime  | لا    | اليوم الأول من الشهر الحالي في المنطقة الزمنية المحددة | وقت البدء، اسم المعلمة الموصى به                   |
| `created_at_to`    | date / datetime  | لا    | الوقت الحالي                                | وقت الانتهاء، اسم المعلمة الموصى به                 |
| `timezone`         | string           | لا    | `UTC`                                      | منطقة زمنية IANA، مثل `Asia/Shanghai`؛ تعود القيم غير الصالحة إلى UTC |
| `service_id`       | UUID             | لا    | —                                          | التصفية حسب الخدمة؛ تدعم المعلمات المتكررة          |
| `application_id`   | UUID             | لا    | —                                          | التصفية حسب Application؛ تدعم المعلمات المتكررة     |
| `api_id`           | UUID             | لا    | —                                          | التصفية حسب API؛ تدعم المعلمات المتكررة             |
| `credential_id`    | UUID             | لا    | —                                          | التصفية حسب بيانات اعتماد API؛ تدعم المعلمات المتكررة |
| `include_models`   | boolean          | لا    | `false`                                    | ما إذا كان سيتم حساب التجميع حسب بُعد النموذج إضافيًا؛ سيزيد تكلفة الاستعلام |
| `user_id`          | UUID             | لا    | المستخدم العادي يقتصر على نفسه؛ وجميع الحسابات للمسؤول عند عدم تمريره | يمكن للمسؤول فقط تحديد أي حساب                     |

لا يزال من الممكن استخدام `start_time` / `end_time` كأسماء مستعارة للتوافق مع العملاء القدامى، وتستخدم التكاملات الجديدة بشكل موحّد `created_at_from` / `created_at_to`. تشمل صيغة التاريخ لـ `created_at_to` ذلك اليوم التقويمي، أي باستخدام منتصف ليل اليوم التالي كحد فاصل.

## أمثلة الطلبات

استعلم عن التجميع اليومي/API للشهر الحالي بتوقيت بكين، مع تضمين بُعد النموذج:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  --data-urlencode 'include_models=true' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

استعلم عن استخدام أسبوع لـ Application محدد:

```shell
export APPLICATION_ID='معرّف Application الخاص بك'

curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'created_at_from=2026-09-01' \
  --data-urlencode 'created_at_to=2026-09-07' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

مثال Python:

```python
import os
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/usage/apis/aggregate/",
    headers={"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    params={
        "created_at_from": "2026-09-01",
        "created_at_to": "2026-09-07",
        "timezone": "Asia/Shanghai",
        "include_models": "true",
    },
    timeout=30,
)
response.raise_for_status()
data = response.json()
print("requests:", data["requests"], "deducted:", data["total"])
for row in data["items"]:
    print(row["date"], row["api_id"], row["amount"])
```

## مثال الاستجابة

```json
{
  "items": [
    {
      "date": "2026-09-01",
      "api_id": "00000000-0000-4000-8000-000000000001",
      "amount": 12.5
    }
  ],
  "total": 12.5,
  "apis": {
    "00000000-0000-4000-8000-000000000001": {
      "title": "Example API"
    }
  },
  "requests": 42,
  "models": [
    {
      "model": "example-model",
      "amount": 12.5,
      "requests": 42
    }
  ]
}
```

## حقول الاستجابة

| الحقل        | الوصف                                                                  |
| ------------ | ---------------------------------------------------------------------- |
| `items`      | مجمّعة حسب التاريخ في المنطقة الزمنية المحددة و`api_id`؛ يحتوي كل صف على `date` و`api_id` و`amount` |
| `total`      | مجموع `deducted_amount` ضمن نطاق الاستعلام                            |
| `apis`       | تعيين من معرّف API إلى ملخص العنوان، لتسهيل عرض `items`               |
| `requests`   | إجمالي عدد الطلبات ضمن نطاق الاستعلام                                |
| `models`     | يُحسب فقط عند `include_models=true`؛ يحتوي كل عنصر على `model` و`amount` و`requests` |

تعتمد وحدة الرصيد على `service.unit` الخاص بـ Application ذي الصلة. إذا كان الاستعلام يتضمن خدمات بوحدات مختلفة، فقم أولًا بالإحصاء بشكل منفصل حسب `service_id` أو `application_id`، لتجنب المقارنة المباشرة أو الجمع.

عندما لا يكون وقت الانتهاء أكبر من وقت البدء، تُرجع الواجهة بنية فارغة كاملة: `items=[]`، و`total=0`، و`apis={}`، و`requests=0`، و`models=[]`.

## اقتراحات الأخطاء والأداء

| HTTP | `error`                 | طريقة المعالجة                                          |
| ---- | ----------------------- | ------------------------------------------------------- |
| 400  | `usage_history_expired` | اضبط النطاق الزمني ليكون بعد `available_from` في الاستجابة |
| 401  | `not_authenticated`     | تحقق من Account Token، ولا تستخدم Credential الخاص بالعمل بالخطأ |
| 403  | `permission_denied`     | لا يمكن للمستخدمين العاديين الاستعلام عن حسابات أخرى    |

- لا تفعّل `include_models` افتراضيًا؛ فعّله فقط عندما يحتاج التقرير فعلًا إلى تقسيم حسب النموذج.
- بالنسبة إلى الاستعلامات واسعة النطاق، أعطِ الأولوية للتقسيم حسب `service_id` أو `application_id`، لتجنب خلط الوحدات وخفض تكلفة الاستعلام.
- لا تُستكمل التواريخ التي ليس فيها استدعاءات بصفر تلقائيًا؛ ويجب على العميل استكمال محور التاريخ قبل الرسم البياني.
