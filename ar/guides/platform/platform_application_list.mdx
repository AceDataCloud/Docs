إرجاع Application الذي يملكه الحساب أو المصرح له باستخدامه على صفحات، بما في ذلك الرصيد والحالة وملخص الخدمة وبيانات الاعتماد المرتبطة. مناسب لمراقبة الرصيد بالجملة، والعثور على Application ID، والدخول إلى إدارة بيانات الاعتماد.

## الأعمال التحضيرية

1. سجّل الدخول إلى [منصة AceDataCloud](https://platform.acedata.cloud).
2. أنشئ رمز الحساب في [وحدة تحكم Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. يستخدم المستخدمون العاديون `user_id=me`؛ ويمكن أيضًا الحصول على UUID الخاص بهم من `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='你的账户令牌'
```

## نظرة عامة على الواجهة

| العنصر   | المحتوى                                                    |
| --- | ----------------------------------------------------- |
| الطريقة  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| المصادقة  | Account Token، يتطلب OAuth token ‏`applications:read`       |
| الترقيم  | `count` + `items`                                     |

ينبغي للمستخدمين العاديين تمرير `user_id=me`. عند عدم تمريره، لا يتم تضييق الاستعلام أولًا حسب الحساب، وقد تعيد الصفحات `403` عند مواجهة كائنات دون صلاحية؛ وعند عدم تمريره للمسؤولين يمكنهم عرض الجدول بالكامل.

## معاملات الاستعلام

| المعامل            | النوع          | مطلوب     | الوصف                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | مطلوب للمستخدمين العاديين | موضوع الاستعلام؛ يدعم المعاملات المتكررة                                         |
| `affiliation` | string      | لا      | `owner` (افتراضي) أو `granted`؛ يمكن تمرير كليهما بشكل متكرر لأخذ الاتحاد، ولا يسري إلا عند وجود `user_id` |
| `service_id`  | UUID        | لا      | التصفية حسب الخدمة؛ يدعم المعاملات المتكررة                                        |
| `scope`       | string      | لا      | `Individual` أو `Global`؛ يدعم المعاملات المتكررة                      |
| `type`        | string      | لا      | `Usage` أو `Period`؛ يدعم المعاملات المتكررة                           |
| `limit`       | integer     | لا      | عدد العناصر في كل صفحة، والحد الأقصى 100                                         |
| `offset`      | integer     | لا      | إزاحة الترقيم                                               |
| `ordering`    | string      | لا      | يدعم فقط `created_at` أو `-created_at`                    |

لا تُعدّ `paid` و`disabled` و`expired` و`low_balance` و`tag` حاليًا معاملات تصفية من جانب الخادم. ينبغي لسياقات الرصيد سحب القائمة أولًا، ثم الحكم من جانب العميل وفقًا لـ `remaining_amount` و`service.unit` والعتبات التجارية لكل Application.

## مثال على الطلب

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

عرض Application التي تملكها وتلك التي فوضها لك الآخرون في الوقت نفسه:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## توضيح الاستجابة

تكون الاستجابة `{count, items}`. يحتوي كل عنصر على حقول نموذج Application، مع إضافة:

- `service`: ‏`id` و`alias` و`title` و`type` و`unit` و`icon_url`؛
- `credentials`: ملخص بيانات الاعتماد التي يحق للمتصل الحالي رؤيتها؛
- `paid` و`remaining_amount` و`used_amount` و`disabled` و`allow_consume_global`؛
- القيمة الحقيقية لـ `scope` هي `Individual` أو `Global`؛
- القيمة الحقيقية لـ `type` هي `Usage` أو `Period`.

قد يكون `remaining_amount` فارغًا؛ يجب على العميل التحقق من عدم كونه فارغًا أولًا، ثم إجراء المقارنة الرقمية. تُحدَّد وحدة الحصة بواسطة `service.unit`.
