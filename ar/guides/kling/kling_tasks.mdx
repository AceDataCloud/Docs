تتمثل الوظيفة الرئيسية لـ Kling Tasks API في الاستعلام عن حالة تنفيذ المهمة عبر إدخال معرّف المهمة الذي تم إنشاؤه بواسطة Kling Videos Generation API.

ستقدم هذه الوثيقة بالتفصيل تعليمات تكامل Kling Tasks API، لمساعدتك على دمجه بسهولة والاستفادة الكاملة من الوظائف القوية لهذا API. من خلال Kling Tasks API، يمكنك بسهولة تنفيذ الاستعلام عن حالة تنفيذ مهام Kling Videos Generation API.

## عملية التقديم

لاستخدام Kling Videos Generation API، انتقل أولاً إلى [لوحة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقاً.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تقم بتسجيل الدخول أو التسجيل بعد، فسيتم تحويلك تلقائياً إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائياً إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** سيمنحك أول تقديم رصيداً مجانياً للتجربة مجاناً؛ عند عدم كفاية الرصيد، يمكنك إعادة شحن الرصيد العام من [لوحة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

يمكن استخدام Kling Tasks API للاستعلام عن نتائج Kling Videos Generation API. لمعرفة كيفية استخدام Kling Videos Generation API، يرجى الرجوع إلى وثيقة [Kling Videos Generation API ](https://platform.acedata.cloud/documents/kling-videos).

سنأخذ معرّف مهمة واحداً تم إرجاعه بواسطة خدمة Kling Videos Generation API كمثال، لعرض كيفية استخدام هذا API. لنفترض أن لدينا معرّف مهمة: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0، وفيما يلي نعرض كيفية تمرير معرّف مهمة واحد.

### إعداد رؤوس الطلب وجسم الطلب

**Request Headers** تتضمن:

- `accept`: يحدد تلقي نتيجة استجابة بتنسيق JSON، ويتم تعبئته هنا بـ `application/json`.
- `authorization`: مفتاح استدعاء API، ويمكن اختياره مباشرة من القائمة المنسدلة بعد التقديم.

**Request Body** يتضمن:

- `id`: معرّف المهمة المرفوع.
- `action`: طريقة تشغيل المهمة.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

تتضمن النتيجة المعادة عدة حقول، وحقل request هو request body عند بدء المهمة، بينما حقل response هو response body المعاد بعد اكتمال المهمة. تعريف الحقول كما يلي.

- `id`: معرّف مهمة الفيديو التي تم إنشاؤها، ويستخدم لتمييز مهمة إنشاء الفيديو هذه بشكل فريد.
- `request`: معلومات الطلب في مهمة الاستعلام عن الفيديو.
- `response`: معلومات الإرجاع في مهمة الاستعلام عن الفيديو.
- `created_at`: وقت إنشاء المهمة، طابع Unix الزمني (بالثواني، رقم عشري).
- `started_at`: وقت بدء تنفيذ المهمة، طابع Unix الزمني (بالثواني، رقم عشري).
- `finished_at`: وقت اكتمال المهمة، طابع Unix الزمني (بالثواني، رقم عشري). لا يتم إرجاع هذا الحقل عندما لا تكتمل المهمة.
- `elapsed`: الوقت المستغرق في تنفيذ المهمة، بوحدة الثواني (رقم عشري، مع الاحتفاظ بثلاث منازل عشرية). لا يتم إرجاع هذا الحقل عندما لا تكتمل المهمة.

## معالجة الأخطاء

عند استدعاء واجهة API، إذا واجهت خطأً، فستُرجع واجهة API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح به، رمز تفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جدًا، لقد تجاوزت حد المعدل.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة خطأ
