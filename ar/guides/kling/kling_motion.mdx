ستعرّف هذه المقالة تعليمات تكامل Kling Motion Generation API، والذي يمكنه إنشاء مقاطع فيديو Kling الرسمية من خلال إدخال معلمات مخصصة.

## عملية التقديم

لاستخدام Kling Motion Generation API، انتقل أولاً إلى [لوحة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو سجّلت حسابًا بعد، فسيتم تلقائيًا الانتقال إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائيًا إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** سيُمنح رصيد مجاني عند التقديم لأول مرة، ويمكن التجربة مجانًا؛ وعند عدم كفاية الرصيد، يمكن شحن الرصيد العام من [لوحة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [Kling Motion Generation API →](https://platform.acedata.cloud/documents/kling-motion)

## الاستخدام الأساسي

تعرّف أولاً على طريقة الاستخدام الأساسية، وهي إدخال كلمة التوجيه `prompt`، والصورة المرجعية `image_url`، ورابط الفيديو المرجعي `video_url`، ثم يمكنك الحصول على النتيجة المعالجة، وبعد ذلك نحتاج أيضًا إلى إدخال النموذج `mode`، ويوجد حاليًا بشكل أساسي نموذجا `std` و`pro`، والمحتوى المحدد كما يلي:

<p><img src="https://cdn.acedata.cloud/5qlpjt.png" width="500" className="m-auto" /></p>

يمكنك أن ترى أننا قمنا هنا بتعيين Request Headers، وتشمل:

- `accept`: تنسيق نتيجة الاستجابة التي تريد تلقيها، ويُملأ هنا بـ `application/json`، أي تنسيق JSON.
- `authorization`: مفتاح استدعاء API، ويمكن اختياره مباشرة من القائمة المنسدلة بعد التقديم.

كما قمنا أيضًا بتعيين Request Body، وتشمل:

- `image_url`: رابط URL لصورة مرجعية لمظهر الشخصية. يدعم JPG/JPEG/PNG، الملف ≤50MB، والعرض والارتفاع كلاهما ≥300px، ونسبة العرض إلى الارتفاع 1:2.5～2.5:1؛ يجب أن تظهر الشخصية بوضوح في الجزء العلوي من الجسم أو الجسم الكامل والرأس.
- `video_url`: رابط URL لفيديو مرجعي للحركة. يدعم MP4/MOV، الملف ≤100MB، والعرض والارتفاع كل منهما 340–3850px، ولمدة 3 ثوانٍ على الأقل؛ عند `character_orientation=image` تكون المدة القصوى 10 ثوانٍ، وعند `character_orientation=video` تكون المدة القصوى 30 ثانية. يُوصى باستخدام فيديو بلقطة واحدة متواصلة تكون فيه الشخصية دائمًا داخل الإطار.
- `mode`: وضع إنشاء الفيديو، ويوجد بشكل أساسي وضعان هما الوضع القياسي `std` والوضع فائق السرعة `pro`.
- `keep_original_sound`: يمكن اختيار ما إذا كان سيتم الاحتفاظ بالصوت الأصلي للفيديو، والقيم المعدودة: yes، no.
- `character_orientation`: اتجاه الشخصية في الفيديو المُنشأ، ويمكن اختيار أن يكون متوافقًا مع الصورة أو متوافقًا مع الفيديو، والقيم المعدودة: image، video.
- `prompt`: كلمة التوجيه.
- `callback_url`: رابط URL الذي يحتاج إلى تلقي نتيجة الاستدعاء العكسي.
- `async`: اختياري، عند تعيينه إلى `true` تعيد الواجهة فورًا `task_id`، دون الحاجة إلى توفير `callback_url`، ثم يتم الحصول على النتيجة عبر الاستعلام الدوري باستخدام واجهة استعلام المهمة المقابلة.

بعد الاختيار، يمكنك ملاحظة أنه تم أيضًا إنشاء الكود المقابل على الجانب الأيمن، كما هو موضح في الصورة:

<p><img src="https://cdn.acedata.cloud/buwczd.png" width="500" className="m-auto" /></p>

انقر زر «Try» لإجراء الاختبار، كما هو موضح في الصورة أعلاه، وهنا حصلنا على النتيجة التالية:

```json
{
  "success": true,
  "video_id": "842578800134742051",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "5.066",
  "state": "succeed",
  "task_id": "363c7a84-e880-472e-a4d4-098e50cfc292"
}
```

تحتوي النتيجة المعادة على عدة حقول، وتقديمها كما يلي:

- `success`، حالة مهمة إنشاء الفيديو في هذا الوقت.
- `task_id`، معرّف مهمة إنشاء الفيديو في هذا الوقت.
- `video_id`، معرّف الفيديو لمهمة إنشاء الفيديو في هذا الوقت.
- `video_url`، رابط الفيديو لمهمة إنشاء الفيديو في هذا الوقت.
- `duration`، مدة رابط الفيديو لمهمة إنشاء الفيديو في هذا الوقت.
- `state`، حالة مهمة إنشاء الفيديو في هذا الوقت.

يمكنك أن ترى أننا حصلنا على معلومات الفيديو المُرضية، وكل ما نحتاج إليه هو الحصول على فيديو Kling المُنشأ وفقًا لعنوان رابط الفيديو في `data` ضمن النتيجة.

بالإضافة إلى ذلك، إذا كنت تريد إنشاء كود التكامل المقابل، يمكنك نسخه مباشرةً، على سبيل المثال كود CURL كما يلي:

```shell
curl -X POST 'https://api.acedata.cloud/kling/motion' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
  "video_url": "https://cdn.acedata.cloud/odwfm5.mp4",
  "prompt": "让画面生动起来",
  "mode": "std",
  "character_orientation": "image"
}'
```

## الاستدعاء العكسي غير المتزامن

نظرًا لأن الوقت الذي يستغرقه Kling Motion Generation API في الإنشاء طويل نسبيًا، ويحتاج تقريبًا إلى 1-2 دقيقة، فإذا لم تستجب API لفترة طويلة، سيظل طلب HTTP محتفظًا بالاتصال، مما يؤدي إلى استهلاك موارد نظام إضافية، لذلك توفر هذه API أيضًا دعم الاستدعاء العكسي غير المتزامن.

التدفق العام هو: عند قيام العميل بإطلاق طلب، يحدد بشكل إضافي حقل `callback_url`، وبعد أن يطلق العميل طلب API، ستعيد API فورًا نتيجة تحتوي على معلومات الحقل `task_id`، والذي يمثل معرّف المهمة الحالية. بعد اكتمال المهمة، سيتم إرسال نتيجة إنشاء الفيديو إلى `callback_url` الذي حدده العميل بصيغة POST JSON، ويتضمن ذلك أيضًا الحقل `task_id`، وبهذه الطريقة يمكن ربط نتيجة المهمة عبر المعرّف.

فيما يلي سنتعرف من خلال مثال على كيفية التشغيل المحددة.

أولاً، استدعاء Webhook العكسي هو خدمة يمكنها استقبال طلبات HTTP، وينبغي للمطورين استبداله برابط URL لخادم HTTP الذي قاموا بإنشائه بأنفسهم. هنا، ولتسهيل العرض التوضيحي، يتم استخدام موقع نموذج Webhook عام https://webhook.site/، ويمكن الحصول على Webhook URL بفتح هذا الموقع، كما هو موضح في الصورة:

![](https://cdn.acedata.cloud/tbcnai.png)

انسخ رابط URL هذا، ويمكن استخدامه كـ Webhook، والمثال هنا هو `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

بعد ذلك، يمكننا تعيين الحقل `callback_url` إلى Webhook URL المذكور أعلاه، مع تعبئة المعلمات المقابلة في الوقت نفسه، والمحتوى المحدد كما هو موضح في الصورة:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

انقر للتشغيل، ويمكنك ملاحظة أنه سيتم الحصول على نتيجة فورًا، كما يلي:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

انتظر قليلًا، ويمكننا ملاحظة نتيجة إنشاء الفيديو على `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`، كما هو موضح في الصورة:

![](https://cdn.acedata.cloud/zv5u2q.png)

المحتوى كما يلي:
```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

يمكن ملاحظة وجود حقل `task_id` في النتيجة، أما الحقول الأخرى فهي مشابهة لما سبق، ويمكن تحقيق ربط المهام من خلال هذا الحقل.

## معالجة الأخطاء

عند استدعاء واجهة API، إذا واجهت خطأً، فستُرجع واجهة API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح به، رمز التفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جدًا، لقد تجاوزت حد المعدل.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة خطأ

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
