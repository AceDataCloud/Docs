يُعد AI Chat v2 API (`/aichat2/conversations`) واجهة محادثة من الجيل الجديد، وهو إصدار مطوّر بالكامل من [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). وبالاستناد إلى بساطة v1 وإدارته المستضافة للمحادثات متعددة الجولات، فإنه يوسّع الميزات التالية:

- **إدخال مستخدم متعدد الوسائط**: يمكنك إرسال النص + الصور + كتل الملفات مباشرةً عبر حقل `message` المنظّم، دون الحاجة إلى إرفاقها بشكل غير مباشر باستخدام `references` أولاً.
- **استدعاء الأدوات بأسلوب Agent**: يتضمن مجموعة من الأدوات المدمجة مثل البحث عبر الإنترنت، واستخراج محتوى صفحات الويب، وقراءة الملفات، وغيرها، كما يمكن ربط خوادم MCP المصرّح بها من المستخدم (Google Drive وNotion وSlack وGitHub وغيرها)، ويمكن للنموذج استدعاء الأدوات ذاتيًا عبر جولات متعددة ضمن طلب واحد لإكمال المهام المعقدة.
- **أحداث تدفق منظّمة**: عبر `accept: text/event-stream` أو `application/x-ndjson`، يمكنك الحصول على أحداث مثل `text_delta` و`tool_use` و`tool_result` و`thinking` و`citation` و`card` و`artifact` على مستوى كل token، مما يسهل عرضها بشكل منفصل في الواجهة الأمامية وفقًا لنوعها.
- **قابل للمقاطعة / الاستئناف**: عندما يحتاج النموذج إلى أن يضيف المستخدم معلومات، فإنه يصدر حدث `ask_user_question` ويتوقف مؤقتًا؛ ويمكن متابعة العملية في الاستدعاء التالي عبر تعبئة الإجابة باستخدام `tool_results`.
- **إجراءات CRUD جديدة**: يمكنك تنفيذ `retrieve` / `retrieve_batch` / `update` / `delete` عبر حقل `action` على نفس نقطة النهاية، دون الحاجة إلى API إضافي لإدارة المحادثات.
- **قائمة نماذج محدّثة باستمرار**: تتصل افتراضيًا بنماذج معاصرة مثل GPT-5.4 وClaude Opus 4.8 وClaude Sonnet 4.6 وGemini 3.1 Pro وGLM 5.1 وDeepSeek V4 وKimi K3 وغيرها.

وفي الوقت نفسه، فهو **متوافق تمامًا مع v1 على مستوى جسم الطلب**: يكفي تمرير `model` + `question` (+ اختياريًا `stateful` / `id` / `references` / `preset`) للحصول على استجابة JSON مكافئة لـ v1 بصيغة `{answer, id}`. لذلك، لا تحتاج إلى إعادة كتابة العميل عند الترحيل من `/aichat/conversations`، بل يكفي تغيير المسار إلى `/aichat2/conversations`.

> إذا كنت تستخدم حاليًا `/aichat/conversations`، فستظل الواجهة القديمة قيد الخدمة، ويمكنك الترحيل وفقًا لوتيرتك الخاصة.

## إجراءات التقديم

لاستخدام AI Chat v2 API، انتقل أولًا إلى [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وستعود تلقائيًا إلى الصفحة الحالية بعد الإكمال.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة إلى التقديم بشكل منفصل لكل خدمة.** ستحصل على رصيد مجاني عند أول تقديم، ويمكنك التجربة مجانًا؛ وعندما لا يكفي الرصيد، يمكنك شحن الرصيد العام من [وحدة التحكم](https://platform.acedata.cloud/console/coin).

## الاستخدام الأساسي

أبسط استخدام مطابق تمامًا لـ v1: مرّر `model` + `question`، واحصل على `{answer, id}`.

مثال CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

نتيجة الإرجاع:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

مثال Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## المحادثات متعددة الجولات

كما في v1، مرّر `stateful: true` لتفعيل حفظ المحادثة، وستعيد API قيمة `id`؛ وفي الطلبات اللاحقة، يكفي إعادة تمرير `id` لمتابعة المحادثة، دون الحاجة إلى إدارة سجل messages بنفسك.

الطلب الأول:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

الإرجاع:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

الطلب الثاني، أرفق نفس `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> القيمة الافتراضية لـ `stateful` هي `true`، وحذفها يعادل تمرير `true` صراحةً. إذا كنت لا تريد أن يحفظ الخادم هذه الجولة من المحادثة، يمكنك تعيين `stateful: false` صراحةً.

## الاستجابة المتدفقة

يدعم v2 تنسيقين للتدفق، ويتم الاختيار وفقًا لترويسة `accept`:

| السيناريو                    | `accept`               | شكل البيانات                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| واجهة ويب أمامية / EventSource  | `text/event-stream`    | `data: {json}\n\n`، والسطر الأخير هو `data: [DONE]\n\n` |
| الخادم / CLI / تحليل التدفق في Node | `application/x-ndjson` | كائن JSON واحد في كل سطر                               |
| لا حاجة إلى التدفق                 | `application/json`（الافتراضي） | يعيد `{answer, id}` دفعةً واحدة                       |

### مثال NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

كل سطر في NDJSON هو حدث منظم، والأكثر شيوعًا هو `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### مثال SSE

استخدام `EventSource` في المتصفح لا يدعم جسم طلب مخصصًا، ويُوصى باستخدام `fetch` + التحليل اليدوي بالتقسيم وفقًا لـ `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### أنواع أحداث التدفق

| `type`              | المعنى                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `text_delta`        | جزء نصي تزايدي من إجابة المساعد. يمثل `content` المحتوى الجديد؛ وللتوافق مع v1، يحمل الحدث نفسه أيضًا `delta_answer` (يساوي `content`) و`id`.                  |
| `thinking`          | عملية تفكير النموذج (تظهر فقط عندما يكشف النموذج المحدد عن reasoning).                                                                |
| `tool_use`          | يقرر النموذج استدعاء أداة، ويحمل الحدث `tool_id` و`tool_name` و`input`.                                                  |
| `tool_result`       | نتيجة تنفيذ الأداة، وتقترن بـ `tool_use` السابق عبر `tool_id`، ويشير `is_error` إلى ما إذا كان قد فشل.                                       |
| `card`              | بطاقة منظمة تنتجها الأداة (مثل الصور ومعاينات الروابط)، ومناسبة للعرض المباشر.                                                                    |
| `citation`          | عنوان URL للمصدر يُستخدم لتكميل الاقتباس للنص المقابل.                                                                            |
| `ask_user_question` | يُصدره النموذج عندما يحتاج المستخدم إلى تقديم معلومات إضافية، وتدخل المحادثة حالة `awaiting_user_input`، راجع [استئناف المحادثة المتوقفة](#استئناف-المحادثة-المتوقفة) أدناه.                           |
| `artifact`          | مخرج مستقل ينشئه النموذج (مثل كتلة برمجية أو مستند)، ويمكن حفظه أو تنزيله.                                                                      |
| `system_message`    | معلومات تنبيه من النظام (ليست محتوى المستخدم أو المساعد)، وتُستخدم فقط لتنبيهات واجهة المستخدم.                                                                     |
| `compact`           | حدث تم فيه ضغط السياق الداخلي، ولا يتطلب معالجة خاصة.                                                                             |
| `error`             | حدث خطأ في هذه الجولة، ويصف `message` محتوى الخطأ.                                                                        |
| `done`              | انتهاء الاستجابة المتدفقة، ويحمل `usage` (بما في ذلك `prompt_tokens` / `completion_tokens` / `total_tokens`) و`terminal_reason`. |

بالنسبة إلى العملاء الذين يهتمون فقط بالإجابة النهائية، فإن جمع `content` لجميع أحداث `text_delta` يعادل `answer` في وضع `application/json`.

## الإدخال متعدد الوسائط

إذا كان إدخال المستخدم يحتوي على صور أو ملفات، مرّر `message` (مصفوفة) بدلًا من `question`. كل عنصر في المصفوفة هو كتلة محتوى:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

أنواع الكتل المدعومة:

- `text` — نص عادي، ويتطلب حقل `text`.
- `image_url` — صورة، ويتطلب `image_url.url`.
- `file_url` — ملف (PDF أو CSV أو TXT وغير ذلك)، ويتطلب `file_url.url`.

### العلاقة مع `references` في v1

للتوافق مع العملاء القدامى، لا يزال v2 يتعرف على الحقل `references: ["https://...", ...]`:
- لاحقة URL هي `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`، تُحوَّل تلقائيًا إلى كتلة `image_url`؛
- الامتدادات الأخرى تُحوَّل إلى كتلة `file_url`؛
- إذا تم توفير `question` أيضًا في الوقت نفسه، فيُوضَع ككتلة `text` في المقدمة.

لذلك، إذا كنت تريد فقط الترحيل من v1 ولا تريد تغيير جسم الطلب، فما عليك سوى تبديل المسار إلى `/aichat2/conversations`، وسيستمر استخدام `references` الأصلي في العمل كالمعتاد.

إذا كنت تحتاج إلى تحكم أدق (مثل وضع عدة صور بين النصوص، أو إذا كان الترتيب مهمًا) فاستخدم مصفوفة `message` مباشرة.

## استدعاء الأدوات و MCP

التحسين الأساسي في v2 هو أن النموذج يمكنه استدعاء الأدوات بشكل مستقل لإكمال المهام متعددة الخطوات، **وهذا مفعّل افتراضيًا**، ولا يحتاج العميل إلى إجراء أي إعدادات إضافية في الطلب. السيناريوهات الشائعة:

- يسأل المستخدم: «ساعدني في البحث عن المعارض الجديدة مؤخرًا في شانغهاي» → يستدعي النموذج بحث الويب المدمج → يرتب النتائج في إجابة.
- يسأل المستخدم: «اقرأ ملف PDF هذا ثم اكتب ملخصًا» → يستدعي النموذج file_read → يكتب ملخصًا.
- يكون المستخدم قد منح صلاحية لـ Google Drive / GitHub / Notion وغيرها في [Connections](https://platform.acedata.cloud/connections) → يمكن للنموذج استدعاء أدوات MCP المقابلة لقراءة بياناته وكتابتها.

في تدفقات NDJSON / SSE، تظهر استدعاءات الأدوات من خلال نوعي الأحداث `tool_use` و `tool_result`، على سبيل المثال:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

إذا كنت لا تريد عرض تفاصيل استدعاء الأدوات في الواجهة الأمامية، فتجاهل أنواع الأحداث `tool_use` / `tool_result` / `card` / `citation`، إذ سيستمر إخراج النموذج النهائي بالتدفق عبر `text_delta`.

يمكن لـ `max_turns` تقييد الحد الأقصى لعدد الجولات التي يمكن للنموذج فيها استدعاء الأدوات بنفسه ضمن هذا الطلب، ويتراوح من 1 إلى 500، والقيمة الافتراضية عند حذفه هي 500. تعيينه إلى قيمة صغيرة (مثل `max_turns: 1`) يمكن أن يفرض إجابة واحدة ولا يسمح بأي استدعاء للأدوات.

## التنفيذ غير المتزامن والتفويض دون إشراف

إذا كان استدعاؤك يأتي من Webhook للتنبيهات، أو CI/CD، أو نظام مراقبة، أو مهام خلفية أخرى، يمكنك تعيين `async: true` لكي تُرجع الواجهة فورًا معرّف المهمة، وتتابع التنفيذ في الخلفية:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

مثال على الاستجابة:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

يمكنك بعد ذلك استخدام `action: retrieve` + `id` للاستعلام عن نتيجة المحادثة؛ كما يمكنك توفير `callback_url`، وبعد اكتمال المهمة سترسل المنصة `{ status, answer, usage, error }` عبر POST إلى عنوان الاستدعاء العكسي الخاص بك. يجب أن يستخدم `callback_url` بروتوكول `http` / `https`، ولا يمكن إدخال `localhost` أو عنوان IP خاص حرفيًا مباشرة.

عادة لا يوجد أحد يمكنه النقر للتأكيد في مهام الخلفية. إذا كنت تريد أن تنفذ بعض Skill أو MCP Server إجراءات مثل الإرسال أو النشر أو الكتابة في الوضع دون إشراف، فيرجى تمرير قائمة التفويض المسبق صراحةً في جسم الطلب:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

القيم في `allowed_skills` هي slug للـ Skill المتصلة؛ والقيم في `allowed_mcp_servers` هي slug للـ MCP Server المتصلة. تظل Skill / MCP Server غير المدرجة في التفويض المسبق، في الوضع دون إشراف، قادرة فقط على المعاينة أو dry-run أو رفض تنفيذ عمليات الكتابة.

إذا كنت بحاجة إلى تحكم أكثر دقة، يمكنك أيضًا استخدام كائن `unattended_policy` المكافئ:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

التفويض المسبق هو هاتان القائمتان بحد ذاتهما: القائمة الفارغة تعني عدم تفويض أي قدرة، ولا حاجة إلى أي حقل تبديل إضافي.

ملاحظة: التفويض المسبق يعني فقط أن «هذا الطلب يسمح لهذه القدرات بتجاوز التأكيد البشري في الوضع دون إشراف». لا يزال يجب أن تدعم Skill المحددة `--unattended-confirm` أو آلية الأمان المقابلة؛ وإلا فستستمر في dry-run ولن تنفذ عمليات الكتابة مباشرة.

## استئناف المحادثات المتوقفة مؤقتًا

تجعل بعض الأدوات النموذج «يسأل المستخدم»، وعندها يرسل النموذج حدث `ask_user_question`، وتتجمد المحادثة في حالة `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

اعرض هذا الحدث في الواجهة الأمامية كبطاقة ليختار المستخدم الإجابة، ثم أرسل طلبًا تاليًا باستخدام نفس `id`، وأعد ملء الإجابة عبر `tool_results`:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

يجب أن يتطابق `tool_use_id` في جسم الطلب **تمامًا** مع `tool_id` عند الإيقاف المؤقت؛ وسيؤدي عدم التطابق إلى إرجاع 400. عندما يوجد `tool_results` في الطلب في الوقت نفسه، سيتم تجاهل `question` / `message` / `references` جميعها.

إذا قرر المستخدم التخلي عن هذا السؤال، فما عليك سوى تمرير `question` / `message` جديد، وستقوم المنصة تلقائيًا بوضع علامة «تم التخطي بواسطة المستخدم» على استدعاء الأداة المتوقف مؤقتًا.

## إدارة المحادثات (CRUD)

يوفر v2 إدارة خفيفة للمحادثات عبر الحقل `action` على نفس endpoint، دون الحاجة إلى فتح API إضافي.
### `action: retrieve` —— استرجاع جلسة

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

يعيد مستند الجلسة الكامل (بما في ذلك سجل `messages` و`model` و`title` و`tools_used` وغيرها).

### `action: retrieve_batch` —— عرض ملخصات الجلسات

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

يعيد `{ items: [...], total }`. **لا يتضمن الملخص `messages`**، وهو مناسب لإنشاء قائمة الشريط الجانبي؛ إذا فتح المستخدم جلسة معينة، فاستخدم بعد ذلك `action: retrieve` لاسترجاع رسائلها الكاملة بشكل منفصل.

معلمات التصفية الاختيارية: `user_id` و`application_id` و`model_group` و`model`.

### `action: update` —— تغيير العنوان أو إعادة كتابة السجل

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "خطة السفر إلى هانغتشو"
}
```

يمكن أيضًا تمرير `messages`، لكن الخادم سيجري تحققًا صارمًا من الـ schema (يجب أن يكون بصيغة `ToolUseContent` المطوية)، وسيعيد 400 إذا لم يكن مطابقًا. عمومًا، يُنصح باستخدامه فقط لتغيير `title`.

### `action: delete` —— حذف جلسة

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

يعيد `{ id, success: true }`. لا يمكن الاستعادة بعد الحذف، يرجى التأكيد قبل الاستدعاء.

## الترحيل السلس من v1

إذا كنت تستخدم بالفعل [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations)، فإن الترحيل إلى v2 لا يتطلب تقريبًا أي تعديل على الكود:

1. غيّر عنوان URL من `https://api.acedata.cloud/aichat/conversations` إلى `https://api.acedata.cloud/aichat2/conversations`.
2. إذا كنت تمرر سابقًا اسم نموذج v1 (مثل `gpt-3.5` أو `gpt-4-browsing` وغيرها)، فيُنصح عند التبديل إلى v2 بالترقية إلى النماذج الحديثة (مثل `gpt-5.4` أو `claude-opus-4-8` أو `gemini-3.1-pro-preview` وغيرها).
3. تظل حقول تدفق NDJSON متوافقة مع الإصدارات السابقة: لا يزال كل حدث `text_delta` يحتوي على `delta_answer` و`id`، لذلك لا يحتاج العميل الأصلي الذي يحلل `delta_answer` سطرًا بسطر إلى أي تعديل.

بعد الترحيل، يمكنك تفعيل قدرات v2 الجديدة حسب الحاجة (مثل `message` متعدد الوسائط، وSSE، واستدعاء الأدوات، وCRUD باستخدام `action`) والمضي قدمًا وفقًا لإيقاعك.

## معالجة الأخطاء

تكون استجابة الخطأ موحدة على النحو التالي:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

الأخطاء الشائعة:

- `400 bad_request`: حقول مطلوبة مفقودة، أو عدم تطابق `tool_use_id`، أو أن schema الخاص بـ `messages` غير صالح، وغير ذلك.
- `401 invalid_token`: ترويسة `authorization` غير صحيحة.
- `404 not_found`: الجلسة المقابلة لـ `id` غير موجودة عند استخدام `action: retrieve / update / delete`.
- `429 too_many_requests`: تم تفعيل حد المعدل.
- `500 chat_error`: أبلغ LLM المصدر عن خطأ أو `completion_tokens=0` في هذه الجولة (يُعامل على أنه غير مستهلك، ولن يتم الخصم).

في الاستجابة المتدفقة، تُرسل الأخطاء كحدث `{"type":"error","message":"..."}`، ثم ينتهي التدفق مباشرةً.

## الخلاصة

يحافظ AI Chat v2 API على التوافق مع v1، وفي الوقت نفسه يرقّي المحادثات من «أسئلة وأجوبة أحادية الجولة / متعددة الجولات» إلى «محادثات قابلة للرصد بأسلوب Agent»: إدخال متعدد الوسائط، واستدعاء الأدوات، وإمكانية الإيقاف / الاستئناف، وأحداث متدفقة منظمة، وCRUD مدمج. يُنصح باستخدام v2 مباشرةً لعمليات التكامل الجديدة؛ ويمكن لعمليات تكامل v1 الحالية الترحيل بسلاسة على مراحل. إذا كانت لديكم أي أسئلة، يرجى الاتصال بفريق الدعم الفني لدينا في أي وقت.
