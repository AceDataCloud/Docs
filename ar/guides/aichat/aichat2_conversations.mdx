تُعد واجهة برمجة التطبيقات AI Chat v2 (`/aichat2/conversations`) واجهة محادثة من الجيل الجديد، وهي نسخة مطوّرة بالكامل من [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). واستنادًا إلى بساطة الإصدار v1 ودعمه للمحادثات متعددة الجولات المُدارة، فإنها توسّع الإمكانات التالية:

- **إدخال متعدد الوسائط من المستخدم**: من خلال حقل `message` المنظّم، يمكن إرسال النصوص + الصور + كتل الملفات مباشرةً، دون الحاجة إلى إرفاقها بشكل غير مباشر باستخدام `references` أولاً.
- **استدعاء الأدوات بأسلوب الوكيل (Agent)**: تتضمن مجموعة مدمجة من الأدوات، مثل البحث عبر الإنترنت، واستخراج محتوى صفحات الويب، وقراءة الملفات، وغيرها، كما يمكن ربط خوادم MCP التي يصرّح بها المستخدم (مثل Google Drive وNotion وSlack وGitHub وغيرها)، مما يتيح للنموذج استدعاء الأدوات بشكل مستقل وعلى جولات متعددة ضمن طلب واحد لإنجاز المهام المعقدة.
- **أحداث تدفّق منظّمة**: من خلال `accept: text/event-stream` أو `application/x-ndjson`، يمكن الحصول على أحداث متتابعة مثل `text_delta` و`tool_use` و`tool_result` و`thinking` و`citation` و`card` و`artifact` وغيرها، مما يسهّل عرض كل نوع بشكل منفصل في الواجهة الأمامية.
- **إمكانية المقاطعة / الاستئناف**: عندما يحتاج النموذج إلى معلومات إضافية من المستخدم، فإنه يُصدر حدث `ask_user_question` ويتوقف مؤقتًا، ويمكن متابعة التنفيذ في الطلب التالي بمجرد إعادة الإجابة عبر `tool_results`.
- **إجراءات CRUD جديدة**: يمكن تنفيذ `retrieve` / `retrieve_batch` / `update` / `delete` من خلال حقل `action` على نقطة النهاية نفسها، دون الحاجة إلى واجهات API إضافية لإدارة المحادثات.
- **قائمة نماذج يتم تحديثها باستمرار**: تتضمن النماذج المتاحة افتراضيًا GPT-5.4 وClaude Opus 4.8 وClaude Sonnet 4.6 وGemini 3.1 Pro وGLM 5.1 وDeepSeek V4 وKimi K3 وغيرها من النماذج الحديثة.

وفي الوقت نفسه، لا يزال بإمكانها استقبال `model` + `question` (مع إمكانية اختيارية لاستخدام `stateful` / `id` / `references` / `preset`) للحصول على استجابة JSON مكافئة للإصدار v1 بصيغة `{answer, id}`، لذلك لا تتطلب عملية الانتقال من `/aichat/conversations` إعادة كتابة العميل، بل يكفي تغيير المسار إلى `/aichat2/conversations`.

> إذا كنت تستخدم حاليًا `/aichat/conversations`، فستظل الواجهة القديمة متاحة للخدمة، ويمكنك الانتقال وفقًا للوتيرة التي تناسبك.

## خطوات التقديم

لاستخدام واجهة برمجة التطبيقات AI Chat v2، انتقل أولاً إلى [لوحة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على رمز API الخاص بك، واحتفظ به لاستخدامه لاحقًا.

## الاستخدام الأساسي

أبسط طريقة للاستخدام مطابقة تمامًا للإصدار v1: أرسل `model` + `question` واحصل على `{answer, id}`.

مثال CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

النتيجة المُعادة:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

مثال Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

## المحادثات متعددة الجولات

كما هو الحال في الإصدار v1، أرسل `stateful: true` لتفعيل حفظ الجلسة، وستُعيد واجهة API قيمة `id`؛ وفي الطلبات اللاحقة، يكفي إعادة إرسال `id` لمتابعة المحادثة دون الحاجة إلى إدارة سجل messages بنفسك.

الطلب الأول:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

الاستجابة:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

الطلب الثاني، مع إرفاق `id` نفسه:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "ما الرقم الذي طلبت منك للتو أن تتذكره؟"
  }'
```

```json
{
  "answer": "الرقم الذي طلبت مني أن أتذكره هو 42.",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> تكون قيمة `stateful` الافتراضية هي `true`، وحذفها يعادل تمرير `true` صراحةً. يؤدي تعيين `stateful: false` إلى تخطي تحميل سجل المحادثة السابقة؛ وهذا لا يعني أن نتيجة هذه الجولة لن يتم حفظها، كما أنه لا ينطبق على عمليات الأدوات التي تتطلب الإيقاف المؤقت ثم المتابعة.

### المحادثات الطويلة والاحتفاظ بالنص الأصلي

لا يؤدي ضغط السياق إلا إلى تنظيم المحتوى المُرسل إلى النموذج في هذه الجولة، ولا يستبدل سجلات الدردشة المحفوظة. لا يزال من الممكن قراءة الرسائل المحفوظة بالكامل من خلال `action: retrieve`؛ وتظل تعديلات المحادثة أو عمليات حذفها الصريحة سارية وفقًا للطلب.

يمكن للنموذج البحث داخل المحادثة الحالية وقراءة النصوص الأصلية السابقة على صفحات. عند الحاجة إلى مواصلة تعديل مقال أو اقتباس أرقام أو الاستعداد للنشر، يجب قراءة النص الأصلي المقابل، ولا يجوز استخدام الملخص بدلًا من النص الكامل. لا تستعيد هذه الإمكانية تلقائيًا الرسائل التي فُقدت بالفعل في الإصدارات القديمة.

إذا فشلت عملية تنظيم السياق، فيُرجى الاحتفاظ بمعرّف المحادثة والتحقق من حدث `error`؛ فلن تستبدل الخدمة النص الأصلي بملخص فارغ. قد تظل عمليات الأدوات التي اكتملت قبل الفشل سارية، لذا يُرجى الاستعلام عن نتائجها أولًا لتجنب إنشاء المحتوى أو نشره بشكل متكرر. عند بلوغ الحد الأقصى للتخزين في محادثة واحدة، سيظهر خطأ واضح، ولن يتم توفير مساحة عن طريق اقتطاع السجلات المحفوظة الحالية؛ يمكنك تصدير المحتوى المطلوب ثم بدء محادثة جديدة.

## الاستجابات المتدفقة

يدعم الإصدار v2 تنسيقين للاستجابات المتدفقة، ويمكن الاختيار بينهما باستخدام ترويسة `accept`:

| السيناريو | `accept` | شكل البيانات |
| --------------------- | ---------------------- | ------------------------------------------ |
| واجهة Web الأمامية / EventSource | `text/event-stream` | `data: {json}\n\n`، ويكون السطر الأخير `data: [DONE]\n\n` |
| الخادم / CLI / تحليل التدفق في Node | `application/x-ndjson` | كائن JSON واحد في كل سطر |
| عدم الحاجة إلى التدفق | `application/json` (الافتراضي) | إرجاع `{answer, id}` دفعة واحدة |

### مثال NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "عرّف بمدينة هانغتشو في ثلاث جمل.",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # متوافق مع v1: يتم توفير المقاطع المتزايدة أيضًا عبر حقل delta_answer
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

كل سطر في NDJSON هو حدث منظم، وأكثرها شيوعًا هو `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### مثال SSE

لا يدعم `EventSource` في المتصفح أجسام الطلبات المخصصة، لذا يُنصح باستخدام `fetch` مع تقسيم البيانات يدويًا وتحليلها وفقًا لـ `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "عرّف بمدينة هانغتشو في ثلاث جمل.",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### أنواع الأحداث المتدفقة

| `type` | المعنى |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta` | مقطع نصي متزايد من إجابة المساعد. يمثل `content` المحتوى الجديد؛ وللتوافق مع v1، يحمل الحدث نفسه أيضًا `delta_answer` (وهو يساوي `content`) و`id`. |
| `thinking` | عملية تفكير النموذج (تظهر فقط عندما يكشف النموذج المحدد عن الاستدلال). |
| `tool_use` | يقرر النموذج استدعاء أداة، ويحمل الحدث `tool_id` و`tool_name` و`input`. |
| `tool_result` | نتيجة تنفيذ الأداة، وتُطابق حدث `tool_use` السابق عبر `tool_id`، ويحدد `is_error` ما إذا كان التنفيذ قد فشل. |
| `card` | بطاقة منظمة ناتجة عن الأداة (مثل الصور ومعاينات الروابط)، وهي مناسبة للعرض المباشر. |
| `citation` | عنوان URL للمصدر يُستخدم لإضافة مرجع إلى المقطع النصي المقابل. |
| `ask_user_question` | يصدر عندما يحتاج النموذج إلى معلومات إضافية من المستخدم، وتدخل المحادثة في حالة `awaiting_user_input`، راجع أدناه [استئناف المحادثات المتوقفة مؤقتًا](#استئناف-المحادثات-المتوقفة-مؤقتًا). |
| `artifact` | مخرج مستقل ينشئه النموذج (مثل كتل التعليمات البرمجية والمستندات)، ويمكن حفظه أو تنزيله. |
| `system_message` | رسالة معلوماتية من النظام (ليست محتوى من المستخدم أو المساعد)، وتُستخدم فقط لعرض التنبيهات في واجهة المستخدم. |
| `compact` | تم تنظيم سياق النموذج؛ وتظل الرسائل الأصلية المحفوظة دون تغيير، ولا يحتاج العميل إلى حذف سجل الدردشة. |
| `error` | حدث خطأ في هذه الجولة، ويصف `message` محتوى الخطأ. |
| `done` | تم حفظ سجل المحادثة النهائي لهذه الجولة بنجاح، ويحمل `usage` (بما في ذلك `prompt_tokens` / `completion_tokens` / `total_tokens`) و`terminal_reason`؛ ولا يزال يتعين تحديد ما إذا كانت المهمة قد اكتملت بناءً على سبب الإنهاء. |
بالنسبة للعملاء الذين يهتمون فقط بالإجابة النهائية، فإن دمج قيم `content` لجميع أحداث `text_delta` يعطي نتيجة مكافئة لقيمة `answer` في وضع `application/json`.

## الإدخال متعدد الوسائط

إذا كان إدخال المستخدم يتضمن صورًا أو ملفات، فاستخدم `message` (مصفوفة) بدلًا من `question`. كل عنصر في المصفوفة عبارة عن كتلة محتوى:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "كم عدد القطط الموجودة في هذه الصورة؟" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

أنواع الكتل المدعومة:

- `text` — نص عادي، ويتطلب حقل `text`.
- `image_url` — صورة، ويتطلب `image_url.url`.
- `file_url` — ملف (PDF وCSV وTXT وغيرها)، ويتطلب `file_url.url`.

### العلاقة مع `references` في v1

للتوافق مع العملاء القدامى، لا يزال v2 يتعرف على حقل `references: ["https://...", ...]`:

- إذا كان امتداد URL هو `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`، فسيتم تحويله تلقائيًا إلى كتلة `image_url`؛
- الامتدادات الأخرى يتم تحويلها إلى كتل `file_url`؛
- إذا تم تقديم `question` أيضًا، فسيتم إضافته ككتلة `text` في البداية.

لذلك، إذا كنت تريد فقط الترحيل من v1 دون تغيير جسم الطلب، فما عليك سوى تغيير المسار إلى `/aichat2/conversations`، وسيستمر استخدام `references` الأصلي كالمعتاد.

إذا كنت بحاجة إلى تحكم أكثر دقة (مثل وضع عدة صور بين أجزاء النص، أو عندما يكون الترتيب مهمًا)، فاستخدم مصفوفة `message` مباشرةً.

## استدعاء الأدوات وMCP

تتمثل التحسينات الأساسية في v2 في قدرة النموذج على استدعاء الأدوات بشكل مستقل لإكمال المهام متعددة الخطوات، **وهذه الميزة مفعّلة افتراضيًا**، ولا يحتاج العميل إلى إجراء أي إعدادات إضافية في الطلب. السيناريوهات الشائعة:

- يسأل المستخدم: «ابحث لي عن أحدث المعارض في شنغهاي» ← يستدعي النموذج أداة البحث المدمجة على الويب ← ينظم النتائج ويقدم الإجابة.
- يسأل المستخدم: «اقرأ ملف PDF هذا ثم اكتب ملخصًا له» ← يستدعي النموذج `file_read` ← يكتب الملخص.
- سبق للمستخدم أن منح الإذن لـ Google Drive / GitHub / Notion وغيرها في [Connections](https://platform.acedata.cloud/connections) ← يمكن للنموذج استدعاء أدوات MCP المقابلة لقراءة بياناته وكتابتها.

في تدفقات NDJSON / SSE، تظهر استدعاءات الأدوات من خلال نوعين من الأحداث هما `tool_use` و`tool_result`، على سبيل المثال:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"معارض شنغهاي ربيع 2026"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"حاليًا","delta_answer":"حاليًا","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"شنغهاي","delta_answer":"شنغهاي","id":"f2f4b3e8-..."}
...
```

إذا كنت لا تريد عرض تفاصيل استدعاء الأدوات في الواجهة الأمامية، فيمكنك تجاهل أنواع الأحداث التالية: `tool_use` / `tool_result` / `card` / `citation`، وستظل المخرجات النهائية للنموذج تُرسل عبر تدفق `text_delta`.

يمكن لـ `max_turns` تحديد الحد الأقصى لعدد الجولات التي يمكن للنموذج فيها استدعاء الأدوات ذاتيًا ضمن الطلب الحالي، ويتراوح النطاق بين 1–500، والقيمة الافتراضية هي 500 عند عدم تحديده. تعيين قيمة صغيرة له (مثل `max_turns: 1`) يفرض تقديم إجابة واحدة فقط، دون السماح بأي استدعاءات للأدوات.

## التنفيذ غير المتزامن والتفويض دون إشراف بشري

إذا كان الاستدعاء صادرًا عن Webhook للتنبيهات أو نظام CI/CD أو نظام مراقبة أو أي مهمة خلفية أخرى، فيمكنك تعيين `async: true` ليُرجع API معرّف المهمة فورًا، بينما يستمر التنفيذ في الخلفية:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "تلقيت تنبيهًا بشأن الخدمة الخاصة بي، أرسل إشعارًا إلى مجموعة WeChat «فريق AceDataCloud» باستخدام حساب WeChat الشخصي الخاص بي..."
}
```

مثال على الاستجابة:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

بعد ذلك، يمكنك استخدام `action: retrieve` مع `id` للاستعلام عن نتيجة المحادثة؛ ويمكنك أيضًا توفير `callback_url`، حيث سترسل المنصة طلب POST إلى عنوان الاستدعاء الخاص بك بعد اكتمال المهمة، متضمنًا `{ status, answer, usage, error }`. يجب أن يستخدم `callback_url` بروتوكول `http` / `https`، ولا يمكن أن يكون `localhost` أو عنوان IP خاصًا مكتوبًا مباشرةً.

عادةً لا يوجد شخص يمكنه النقر على زر التأكيد في المهام الخلفية. إذا كنت تريد أن تنفذ بعض مهارات Skill أو خوادم MCP إجراءات مثل الإرسال أو النشر أو الكتابة دون إشراف بشري، فيرجى تمرير قائمة التفويض المسبق صراحةً في جسم الطلب:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "تلقيت تنبيهًا بشأن الخدمة الخاصة بي، أرسل إشعارًا إلى مجموعة WeChat «فريق AceDataCloud» باستخدام حساب WeChat الشخصي الخاص بي..."
}
```

القيم الموجودة في `allowed_skills` هي معرّفات slug للمهارات المتصلة؛ والقيم الموجودة في `allowed_mcp_servers` هي معرّفات slug لخوادم MCP المتصلة. أما مهارات Skill / خوادم MCP غير المدرجة في التفويض المسبق، فلا يُسمح لها في وضع عدم الإشراف البشري إلا بالمعاينة أو التنفيذ التجريبي (dry-run) أو رفض تنفيذ عمليات الكتابة.

إذا كنت بحاجة إلى تحكم أكثر تفصيلًا، فيمكنك أيضًا استخدام كائن `unattended_policy` المكافئ:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

التفويض المسبق هو هاتان القائمتان نفسيهما: إذا كانت القائمة فارغة، فهذا يعني عدم تفويض أي إمكانيات، ولا حاجة إلى حقل تبديل إضافي.

ملاحظة: التفويض المسبق يعني فقط أن «الطلب الحالي يسمح لهذه الإمكانيات بتجاوز التأكيد اليدوي في وضع عدم الإشراف البشري». ويجب أن تدعم مهارة Skill نفسها `--unattended-confirm` أو آلية أمان مقابلة؛ وإلا فستواصل تنفيذ وضع dry-run، ولن تنفذ عمليات الكتابة مباشرةً.

## استئناف المحادثات المتوقفة مؤقتًا

بعض الأدوات تجعل النموذج «يطرح سؤالًا على المستخدم». في هذه الحالة، سيصدر النموذج حدث `ask_user_question`، وستتجمد المحادثة في حالة `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "هل تريد أن يكون التقرير المُنشأ باللغة الصينية أم الإنجليزية؟",
  "options": ["الصينية", "الإنجليزية"],
  "id": "f2f4b3e8-..."
}
```

في الواجهة الأمامية، اعرض هذا الحدث على شكل بطاقة تتيح للمستخدم اختيار الإجابة، ثم ابدأ الطلب التالي باستخدام `id` نفسه، وأرسل الإجابة من خلال `tool_results` لإدراجها مجددًا:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

في نص الطلب، يجب أن يتطابق `tool_use_id` **تمامًا** مع `tool_id` عند الإيقاف المؤقت؛ وإلا فسيتم إرجاع الخطأ 400. عندما يتضمن الطلب `tool_results` في الوقت نفسه، سيتم تجاهل كل من `question` / `message` / `references`.

إذا قرر المستخدم التخلي عن هذا السؤال، فما عليه سوى إرسال `question` / `message` جديد، وستقوم المنصة تلقائيًا بوضع علامة «تخطّي المستخدم» على استدعاء الأداة المعلّق.

## إدارة الجلسات (CRUD)

يوفر v2 إدارة خفيفة للجلسات من خلال حقل `action` على نقطة النهاية نفسها، دون الحاجة إلى إنشاء واجهة API أخرى.

### `action: retrieve` —— استرداد جلسة

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

إرجاع مستند الجلسة الكامل (بما في ذلك سجل `messages` و`model` و`title` و`tools_used` وغيرها).

### `action: retrieve_batch` —— عرض ملخصات الجلسات

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

إرجاع `{ items: [...], total }`. **لا تتضمن الملخصات `messages`**، وهي مناسبة لإنشاء قائمة الشريط الجانبي؛ وإذا نقر المستخدم على جلسة معينة، فيمكن استخدام `action: retrieve` لاسترداد رسائلها الكاملة بشكل منفصل.

معلمات التصفية الاختيارية: `user_id` و`application_id` و`model_group` و`model`.

### `action: update` —— تغيير العنوان أو إعادة كتابة السجل

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

يمكن أيضًا تمرير `messages`، لكن الخادم سيجري تحققًا صارمًا من المخطط (يجب أن تكون بصيغة `ToolUseContent` المطوية)، وإلا فسيتم إرجاع الخطأ 400. يُنصح عمومًا باستخدامه لتغيير `title` فقط.

### `action: delete` —— حذف جلسة

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

إرجاع `{ id, success: true }`. لا يمكن استعادة الجلسة بعد حذفها، لذا يُرجى التأكد قبل تنفيذ الاستدعاء.

## الانتقال السلس من v1

إذا كنت تستخدم بالفعل [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations)، فإن الانتقال إلى v2 لا يتطلب تقريبًا أي تغييرات في التعليمات البرمجية:

1. غيّر عنوان URL من `https://api.acedata.cloud/aichat/conversations` إلى `https://api.acedata.cloud/aichat2/conversations`.
2. إذا كنت قد أرسلت سابقًا أسماء نماذج v1 (مثل `gpt-3.5` و`gpt-4-browsing` وغيرها)، فيُنصح بالترقية إلى النماذج الحديثة عند الانتقال إلى v2 (مثل `gpt-5.4` و`claude-opus-4-8` و`gemini-3.1-pro-preview` وغيرها).
3. تظل حقول تدفق NDJSON متوافقة مع الإصدارات السابقة: لا يزال كل حدث `text_delta` يتضمن `delta_answer` و`id`، ولذلك لا تحتاج التطبيقات التي كانت تحلل `delta_answer` سطرًا بسطر إلى إجراء أي تعديلات.

بعد الانتقال، يمكنك تفعيل الإمكانات الجديدة في v2 حسب الحاجة (الرسائل متعددة الوسائط `message`، وSSE، واستدعاء الأدوات، وعمليات CRUD عبر `action`)، والتقدم وفقًا للوتيرة المناسبة.

## معالجة الأخطاء

تكون استجابات الأخطاء موحّدة على النحو التالي:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

الأخطاء الشائعة:

- `400 bad_request`: نقص الحقول المطلوبة، أو عدم تطابق `tool_use_id`، أو عدم صلاحية مخطط `messages`، وما إلى ذلك.
- `401 invalid_token`: ترويسة `authorization` غير صحيحة.
- `404 not_found`: الجلسة المقابلة لـ `id` غير موجودة عند تنفيذ `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: تجاوزت الجلسة حد التخزين، ولم يتم استبدال السجلات المحفوظة الموجودة.
- `429 too_many_requests`: تم تجاوز حد معدل الطلبات.
- `503 context_compaction_failed`: فشلت عملية تنظيم السياق، مع الاحتفاظ بالسجلات الموجودة.
- `500 conversation_persist_failed`: فشل الحفظ النهائي لهذه الجولة؛ إن استلام النص لا يعني نجاح حفظ السجل النهائي، لذا يُرجى الاستعلام باستخدام معرّف الجلسة.
- `500 chat_error`: الخدمة غير متاحة مؤقتًا، أو لم يتم إنشاء أي محتوى في هذه الجولة (لن يتم خصم أي رسوم).

في الاستجابة المتدفقة، يتم إرسال الأخطاء في حدث بالشكل `{"type":"error","message":"..."}`، ثم ينتهي التدفق. يشير `[DONE]` فقط إلى انتهاء الإرسال؛ وعند وجود `error`، لا يمكن اعتبار العملية ناجحة، ولن يتم إرسال حدث `done` الخاص بالنجاح.

## الخلاصة

ترتقي واجهة AI Chat v2 API بالمحادثات من «الأسئلة والأجوبة ذات الجولة الواحدة / الجولات المتعددة» إلى «محادثات قائمة على الوكلاء وقابلة للمراقبة»، مع الحفاظ على التوافق مع v1: إدخال متعدد الوسائط، واستدعاء الأدوات، وإمكانية الإيقاف المؤقت / الاستئناف، وأحداث متدفقة منظمة، وعمليات CRUD مدمجة. نوصي باستخدام v2 مباشرةً عند بدء أي تكامل جديد؛ ويمكن للتكاملات الحالية مع v1 الانتقال بسلاسة وعلى مراحل. إذا كانت لديك أي أسئلة، يُرجى التواصل مع فريق الدعم الفني لدينا في أي وقت.
