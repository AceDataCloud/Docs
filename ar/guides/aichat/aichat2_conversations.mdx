يُعد AI Chat v2 API (`/aichat2/conversations`) واجهة محادثة من الجيل الجديد، وهو إصدار مطوّر بشكل شامل من [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). وهو يوسّع، على أساس بساطة v1 واستضافة المحادثات متعددة الجولات، ما يلي:

- **إدخال مستخدم متعدد الوسائط**: عبر حقل `message` المنظّم يمكن إرسال نص + صور + كتل ملفات مباشرةً، دون الحاجة إلى إرفاقها بشكل غير مباشر أولًا باستخدام `references`.
- **استدعاء أدوات بأسلوب Agent**: يتضمن مجموعة أدوات مدمجة للبحث عبر الإنترنت، وجلب صفحات الويب، وقراءة الملفات وغيرها، ويمكن أيضًا ربط خوادم MCP المصرح بها من المستخدم (Google Drive وNotion وSlack وGitHub وغيرها)، ويمكن للنموذج استدعاء الأدوات ذاتيًا عدة مرات ضمن طلب واحد لإكمال المهام المعقدة.
- **أحداث تدفق منظّمة**: من خلال `accept: text/event-stream` أو `application/x-ndjson` يمكن الحصول على أحداث مثل `text_delta` و`tool_use` و`tool_result` و`thinking` و`citation` و`card` و`artifact` لكل token، مما يسهّل عرضها بشكل منفصل في الواجهة الأمامية حسب النوع المقابل.
- **قابل للإيقاف / الاستئناف**: عندما يحتاج النموذج إلى أن يكمّل المستخدم معلومات، فإنه يرسل حدث `ask_user_question` ويتوقف مؤقتًا، ويمكن في الاستدعاء التالي متابعة العمل عبر إعادة تعبئة الإجابة من خلال `tool_results`.
- **إجراءات CRUD جديدة**: يمكن إتمام `retrieve` / `retrieve_batch` / `update` / `delete` عبر حقل `action` على نفس الـ endpoint، دون الحاجة إلى API إضافي لإدارة المحادثات.
- **قائمة نماذج يتم تحديثها باستمرار**: يدعم افتراضيًا نماذج معاصرة مثل GPT-5.4 وClaude Opus 4.8 وClaude Sonnet 4.6 وGemini 3.1 Pro وGLM 5.1 وDeepSeek V4 وKimi K3 وغيرها.

وفي الوقت نفسه، فهو **متوافق تمامًا مع v1 على مستوى جسم الطلب**: يكفي إرسال `model` + `question` (+ اختياريًا `stateful` / `id` / `references` / `preset`) للحصول على استجابة JSON مكافئة لـ v1 بصيغة `{answer, id}`، لذا لا تحتاج إلى إعادة كتابة العميل عند الترحيل من `/aichat/conversations`، بل يكفي تغيير المسار إلى `/aichat2/conversations`.

> إذا كنت تستخدم حاليًا `/aichat/conversations`، فستبقى الواجهة القديمة متاحة، ويمكنك الترحيل وفق وتيرتك الخاصة.

## عملية التقديم

لاستخدام AI Chat v2 API، انتقل أولًا إلى [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم تلقائيًا تحويلك إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائيًا إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة إلى تقديم طلب منفصل لكل خدمة.** سيُمنح رصيد مجاني عند التقديم لأول مرة، ويمكنك التجربة مجانًا؛ وعندما لا يكون الرصيد كافيًا، يمكنك شحن الرصيد العام من [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [AI Chat v2 API →](https://platform.acedata.cloud/documents/aichat2-conversations)

## الاستخدام الأساسي

أبسط استخدام مطابق تمامًا لـ v1: أرسل `model` + `question`، واحصل على `{answer, id}`.

مثال CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

النتيجة المعادة:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

مثال Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

يمكن رؤية قيم `model` المتاحة مباشرةً في القائمة المنسدلة ضمن لوحة Try على اليمين، وتشمل الفئات الشائعة:

## المحادثات متعددة الجولات

كما في v1، أرسل `stateful: true` لتفعيل حفظ المحادثة، وستعيد API قيمة `id`؛ وفي الطلبات اللاحقة، يكفي إعادة إرسال `id` لمتابعة المحادثة، دون الحاجة إلى إدارة سجل messages بنفسك.

الطلب الأول:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

الإرجاع:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

الطلب الثاني، مع إرسال `id` نفسه:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> القيمة الافتراضية لـ `stateful` هي `true`، وحذفها يعادل تمرير `true` صراحةً. سيؤدي تعيين `stateful: false` إلى تخطي تحميل سجل المحادثة السابق؛ وهذا لا يعني أن نتيجة هذه الجولة لن تُحفظ، كما لا ينطبق على تدفقات الأدوات التي تحتاج إلى المتابعة بعد الإيقاف المؤقت.

### المحادثات الطويلة والاحتفاظ بالنص الأصلي

يعمل ضغط السياق فقط على تنظيم المحتوى المُرسل إلى النموذج في هذه الجولة، ولا يستبدل سجلات الدردشة المحفوظة. لا يزال بالإمكان قراءة الرسائل المحفوظة الكاملة عبر `action: retrieve`؛ ويظل التعديل الصريح أو حذف المحادثة نافذًا وفقًا للطلب.

يمكن للنموذج البحث عن النصوص الأصلية للسجل وقراءتها على صفحات ضمن المحادثة الحالية. عند الحاجة إلى متابعة تعديل مقال، أو اقتباس أرقام، أو التحضير للنشر، يجب قراءة النص الأصلي المقابل، ولا يمكن استخدام الملخص بدلًا من النص. لا تستعيد هذه القدرة تلقائيًا الرسائل التي فُقدت بالفعل في الإصدارات القديمة.

إذا فشل تنظيم السياق، فاحتفظ بمعرّف المحادثة وتحقق من حدث `error`؛ لن تستبدل الخدمة النص الأصلي بملخص فارغ. قد تظل عمليات الأدوات التي اكتملت قبل الفشل صالحة، لذا استعلم عن نتائجها أولًا لتجنب التوليد أو النشر المكرر. عند وصول محادثة واحدة إلى حد التخزين، سيظهر خطأ واضح، ولن تُفرغ مساحة من السجلات المحفوظة الحالية عبر الاقتطاع؛ يمكنك تصدير المحتوى المطلوب ثم بدء محادثة جديدة.

## الاستجابة المتدفقة

يدعم v2 تنسيقين للتدفق، ويُختار بينهما وفقًا لترويسة `accept`:

| السيناريو                    | `accept`               | شكل البيانات                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| واجهة ويب أمامية / EventSource  | `text/event-stream`    | `data: {json}\n\n`، والسطر الأخير `data: [DONE]\n\n` |
| خادم / CLI / تحليل تدفق Node | `application/x-ndjson` | كائن JSON واحد في كل سطر                               |
| لا حاجة إلى التدفق                 | `application/json`（الافتراضي） | إرجاع `{answer, id}` دفعة واحدة                       |

### مثال NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

كل سطر في NDJSON هو حدث منظم، وأكثرها شيوعًا هو `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### مثال SSE

لا يدعم استخدام `EventSource` في المتصفح جسم طلب مخصصًا، ويُوصى باستخدام `fetch` + التحليل اليدوي بالتقسيم وفق `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### أنواع الأحداث المتدفقة

| `type`              | المعنى                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | مقطع نصي متزايد من إجابة المساعد. يمثل `content` المحتوى الجديد؛ وللتوافق مع v1، يحمل الحدث نفسه أيضًا `delta_answer` (المساوي لـ `content`) و`id`.                                        |
| `thinking`          | عملية تفكير النموذج (تظهر فقط عندما يكشف النموذج المحدد عن reasoning).                                                                                      |
| `tool_use`          | يقرر النموذج استدعاء أداة، ويحمل الحدث `tool_id` و`tool_name` و`input`.                                                                        |
| `tool_result`       | نتيجة تنفيذ الأداة، وتُقرن مع `tool_use` السابقة عبر `tool_id`، ويحدد `is_error` ما إذا كان قد حدث فشل.                                                             |
| `card`              | بطاقة منظمة ناتجة عن الأداة (مثل الصور ومعاينات الروابط)، ومناسبة للعرض المباشر.                                                                                          |
| `citation`          | عنوان URL للمصدر المستخدم لتكملة الاستشهاد بمقطع النص المقابل.                                                                                                  |
| `ask_user_question` | يصدر عندما يحتاج النموذج إلى أن يضيف المستخدم معلومات، وتدخل المحادثة حالة `awaiting_user_input`، انظر [استئناف المحادثة المعلقة](#استئناف-المحادثة-المعلقة) أدناه.                                                 |
| `artifact`          | ناتج مستقل يولّده النموذج (مثل كتل التعليمات البرمجية والمستندات)، ويمكن حفظه أو تنزيله.                                                                                            |
| `system_message`    | معلومات تنبيه النظام (ليست من محتوى المستخدم أو المساعد)، وتُستخدم فقط لتنبيهات واجهة المستخدم.                                                                                           |
| `compact`           | تم تنظيم سياق النموذج؛ وتظل الرسائل الأصلية المحفوظة دون تغيير، ولا يحتاج العميل إلى حذف سجل الدردشة.                                                                                    |
| `error`             | حدث خطأ في هذه الجولة، ويصف `message` محتوى الخطأ.                                                                                              |
| `done`              | تم حفظ سجل المحادثة النهائي لهذه الجولة بنجاح، ويحمل `usage` (بما في ذلك `prompt_tokens` / `completion_tokens` / `total_tokens`) و`terminal_reason`؛ ولا يزال يلزم الحكم على ما إذا كانت المهمة مكتملة وفقًا لسبب الإنهاء. |
بالنسبة للعملاء الذين يهتمون فقط بالإجابة النهائية، فإن تجميع جميع قيم `content` الخاصة بـ `text_delta` يعادل `answer` في وضع `application/json`.

## الإدخال متعدد الوسائط

إذا كان إدخال المستخدم يتضمن صورًا أو ملفات، مرّر `message` (مصفوفة) بدلًا من `question`. كل عنصر في المصفوفة هو كتلة محتوى:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

أنواع الكتل المدعومة:

- `text` — نص عادي، وحقل `text` مطلوب.
- `image_url` — صورة، وحقل `image_url.url` مطلوب.
- `file_url` — ملف (PDF، CSV، TXT، إلخ)، وحقل `file_url.url` مطلوب.

### العلاقة مع `references` في v1

للتوافق مع العملاء القدامى، لا يزال v2 يتعرّف على الحقل `references: ["https://...", ...]`:

- إذا كانت لاحقة عنوان URL هي `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`، فيتم تحويله تلقائيًا إلى كتلة `image_url`؛
- تتحول الامتدادات الأخرى إلى كتلة `file_url`؛
- إذا تم أيضًا توفير `question` في الوقت نفسه، فيتم وضعه في البداية ككتلة `text`.

لذلك، إذا كنت تريد فقط الترحيل من v1 ولا تريد تعديل نص الطلب، فما عليك سوى تغيير المسار إلى `/aichat2/conversations`، وسيستمر استخدام `references` الأصلي بالعمل كما هو.

إذا كنت تحتاج إلى تحكم أدق (مثل وضع صور متعددة بين النصوص، أو عندما يكون الترتيب مهمًا) فاستخدم مصفوفة `message` مباشرةً.

## استدعاء الأدوات و MCP

التحسين الأساسي في v2 هو أن النموذج يمكنه استدعاء الأدوات ذاتيًا لإكمال المهام متعددة الخطوات، **وهذا مفعّل افتراضيًا**، ولا يحتاج العميل إلى إجراء أي إعدادات إضافية في الطلب. السيناريوهات الشائعة:

- يسأل المستخدم: «ساعدني في البحث عن المعارض الجديدة في شنغهاي مؤخرًا» → يستدعي النموذج web search المدمج → ينظم النتائج في إجابة.
- يسأل المستخدم: «اقرأ ملف PDF هذا ثم اكتب ملخصًا» → يستدعي النموذج file_read → يكتب الملخص.
- قام المستخدم مسبقًا بالتفويض لـ Google Drive / GitHub / Notion وغيرها في [Connections](https://platform.acedata.cloud/connections) → يمكن للنموذج استدعاء أدوات MCP المقابلة لقراءة بياناتها وكتابتها.

في تدفقات NDJSON / SSE، تظهر استدعاءات الأدوات عبر نوعي الأحداث `tool_use` و `tool_result`، على سبيل المثال:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

إذا كنت لا تريد عرض تفاصيل استدعاءات الأدوات في الواجهة الأمامية، فتجاهل أحداث `tool_use` / `tool_result` / `card` / `citation`، وسيظل الإخراج النهائي للنموذج يتدفق عبر `text_delta`.

يمكن لـ `max_turns` تقييد عدد الجولات التي يمكن للنموذج فيها استدعاء الأدوات ذاتيًا ضمن هذا الطلب، والنطاق هو 1–500، والقيمة الافتراضية عند الحذف هي 500. تعيينها إلى قيمة صغيرة (مثل `max_turns: 1`) يمكن أن يفرض إجابة واحدة، ولا يسمح بأي استدعاء للأدوات.

## التنفيذ غير المتزامن والتفويض غير المراقَب

إذا كان استدعاؤك يأتي من Webhook للتنبيهات، أو CI/CD، أو نظام مراقبة، أو مهام خلفية أخرى، يمكنك تعيين `async: true` لجعل الواجهة تُرجع معرّف المهمة فورًا وتتابع التنفيذ في الخلفية:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

مثال على الاستجابة:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

بعد ذلك، يمكنك استخدام `action: retrieve` + `id` للاستعلام عن نتيجة المحادثة؛ ويمكنك أيضًا توفير `callback_url`، وبعد اكتمال المهمة سترسل المنصة `{ status, answer, usage, error }` عبر POST إلى عنوان رد الاتصال الخاص بك. يجب أن يستخدم `callback_url` بروتوكول `http` / `https`، ولا يمكن إدخال `localhost` أو عنوان IP خاص حرفيًا مباشرةً.

عادةً لا يوجد أحد يستطيع النقر للتأكيد في المهام الخلفية. إذا كنت تريد أن تقوم بعض Skill أو MCP Server بتنفيذ إجراءات مثل الإرسال أو النشر أو الكتابة في وضع غير مراقَب، فمرّر قائمة تفويض مسبق صراحةً في نص الطلب:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

القيم في `allowed_skills` هي slug الخاصة بـ Skill المتصلة؛ والقيم في `allowed_mcp_servers` هي slug الخاصة بـ MCP Server المتصلة. تظل Skill / MCP Server غير المدرجة في التفويض المسبق في وضع غير مراقَب قادرة فقط على المعاينة أو dry-run أو رفض تنفيذ عمليات الكتابة.

إذا كنت تحتاج إلى تحكم أكثر تفصيلًا، يمكنك أيضًا استخدام كائن `unattended_policy` المكافئ:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

التفويض المسبق هو هاتان القائمتان نفسيهما: إذا كانت القوائم فارغة، فلا يتم تفويض أي قدرة، ولا حاجة إلى حقول تبديل إضافية.

ملاحظة: التفويض المسبق يعني فقط أن «هذا الطلب يسمح لهذه القدرات بتجاوز التأكيد البشري في وضع غير مراقَب». يجب أن تدعم Skill المحددة فعليًا `--unattended-confirm` أو آلية الأمان المقابلة؛ وإلا فستستمر في dry-run ولن تنفذ عمليات الكتابة مباشرةً.

## استئناف المحادثات المعلّقة

تجعل بعض الأدوات النموذج «يطرح سؤالًا على المستخدم»، وعندها يصدر النموذج حدث `ask_user_question`، وتتجمد المحادثة في حالة `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

في الواجهة الأمامية، اعرض هذا الحدث كبطاقة ليختار المستخدم الإجابة، ثم أرسل الطلب التالي باستخدام `id` نفسه، وأعد تعبئة الإجابة عبر `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

يجب أن يتطابق `tool_use_id` في جسم الطلب **تمامًا** مع `tool_id` عند الإيقاف المؤقت؛ وسيتم إرجاع 400 إذا لم يتطابقا. عند وجود `tool_results` في الطلب في الوقت نفسه، سيتم تجاهل `question` / `message` / `references`.

إذا قرر المستخدم التخلي عن هذا السؤال، فما عليه سوى تمرير `question` / `message` جديد مباشرةً، وستقوم المنصة تلقائيًا بوضع علامة «تخطّاه المستخدم» على استدعاء الأداة المتوقف مؤقتًا.

## إدارة المحادثات (CRUD)

يوفر v2 إدارة خفيفة للمحادثات عبر حقل `action` على نفس الـ endpoint، دون الحاجة إلى API إضافي.

### `action: retrieve` —— جلب محادثة واحدة

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

يعيد مستند المحادثة الكامل (بما في ذلك سجل `messages` و`model` و`title` و`tools_used` وغيرها).

### `action: retrieve_batch` —— سرد ملخصات المحادثات

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

يعيد `{ items: [...], total }`. **لا يتضمن الملخص `messages`**، وهو مناسب لإنشاء قائمة الشريط الجانبي؛ وإذا فتح المستخدم محادثة معينة، فاستخدم `action: retrieve` لجلب رسائلها الكاملة بشكل منفصل.

معلمات التصفية الاختيارية: `user_id`، `application_id`، `model_group`، `model`.

### `action: update` —— تغيير العنوان أو إعادة كتابة السجل

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "خطة رحلة هانغتشو"
}
```

يمكن أيضًا تمرير `messages`، لكن الخادم سيجري تحققًا صارمًا من الـ schema (ويجب أن تكون بصيغة `ToolUseContent` المطوية)، وسيعيد 400 إذا لم تتوافق. يُنصح عمومًا باستخدامه فقط لتغيير `title`.

### `action: delete` —— حذف محادثة واحدة

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

يعيد `{ id, success: true }`. لا يمكن الاستعادة بعد الحذف، يُرجى التأكيد قبل الاستدعاء.

## الترحيل السلس من v1

إذا كنت تستخدم بالفعل [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations)، فإن الترحيل إلى v2 لا يتطلب تقريبًا أي تعديلات على الكود:

1. غيّر URL من `https://api.acedata.cloud/aichat/conversations` إلى `https://api.acedata.cloud/aichat2/conversations`.
2. إذا كنت تمرر سابقًا اسم نموذج v1 (مثل `gpt-3.5` و`gpt-4-browsing` وغيرها)، فمن المستحسن عند التبديل إلى v2 الترقية إلى نموذج حديث (مثل `gpt-5.4` و`claude-opus-4-8` و`gemini-3.1-pro-preview` وغيرها).
3. تظل حقول تدفق NDJSON متوافقة مع الإصدارات السابقة: لا يزال كل حدث `text_delta` يحمل `delta_answer` و`id`، لذلك لا يحتاج العميل الأصلي الذي يحلل `delta_answer` سطرًا بسطر إلى أي تعديل.

بعد الترحيل، يمكنك تفعيل قدرات v2 الجديدة حسب الحاجة (مثل `message` متعدد الوسائط، وSSE، واستدعاء الأدوات، وCRUD عبر `action`) والتقدم بالوتيرة المناسبة.

## معالجة الأخطاء

تكون استجابة الخطأ موحدة كالتالي:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

الأخطاء الشائعة:

- `400 bad_request`: حقول مطلوبة مفقودة، أو عدم تطابق `tool_use_id`، أو أن schema الخاص بـ `messages` غير صالح، وغيرها.
- `401 invalid_token`: ترويسة `authorization` غير صحيحة.
- `404 not_found`: لا توجد المحادثة المطابقة لـ `id` عند استخدام `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: تجاوزت المحادثة حد التخزين، ولم يتم استبدال سجل الحفظ الموجود.
- `429 too_many_requests`: تم تفعيل حد معدل الطلبات.
- `503 context_compaction_failed`: فشل تنظيم السياق، وتم الاحتفاظ بالسجلات الموجودة.
- `500 conversation_persist_failed`: فشل الحفظ النهائي لهذه الجولة؛ لا يعني النص المستلَم أن حفظ السجل النهائي نجح، يُرجى الاستعلام باستخدام معرّف المحادثة.
- `500 chat_error`: الخدمة غير متاحة مؤقتًا، أو لم يتم إنشاء محتوى في هذه الجولة (لن يتم احتساب رسوم).

في الاستجابة المتدفقة، يُرسل الخطأ كحدث `{"type":"error","message":"..."}`، ثم ينتهي التدفق. يشير `[DONE]` فقط إلى انتهاء النقل؛ وعند وجود `error` لا يمكن اعتباره نجاحًا، ولن يتم إرسال حدث `done` ناجح.

## الخلاصة

يرتقي AI Chat v2 API، مع الحفاظ على التوافق مع v1، بالمحادثات من «أسئلة وأجوبة لجولة واحدة / عدة جولات» إلى «محادثات قابلة للمراقبة بأسلوب Agent»: إدخال متعدد الوسائط، واستدعاء أدوات، وقابلية الإيقاف المؤقت / الاستئناف، وأحداث متدفقة مهيكلة، وCRUD مدمج. يُنصح باستخدام v2 مباشرةً عند عمليات التكامل الجديدة؛ أما عمليات تكامل v1 الحالية فيمكن ترحيلها بسلاسة على مراحل. إذا كانت لديك أي أسئلة، يُرجى التواصل مع فريق الدعم الفني لدينا في أي وقت.
