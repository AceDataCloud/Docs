يُعد AI Chat v2 API (`/aichat2/conversations`) واجهة المحادثة من الجيل الجديد، وهو إصدار مطوّر بشكل شامل من [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). يستند إلى بساطة v1 وإدارة المحادثات متعددة الجولات، ويوسّعها عبر:

- **إدخال مستخدم متعدد الوسائط**: أرسل النص + الصور + كتل الملفات مباشرةً عبر حقل `message` المنظّم، دون الحاجة إلى إرفاقها بشكل غير مباشر باستخدام `references` أولًا.
- **استدعاء أدوات بأسلوب Agent**: يتضمن مجموعة أدوات مدمجة للبحث عبر الإنترنت وجلب صفحات الويب وقراءة الملفات وغيرها، كما يمكن إرفاق خوادم MCP المصرّح بها من المستخدم (Google Drive وNotion وSlack وGitHub وغيرها)، بحيث يستطيع النموذج استدعاء الأدوات ذاتيًا عدة مرات ضمن طلب واحد لإكمال المهام المعقدة.
- **أحداث تدفق منظّمة**: عبر `accept: text/event-stream` أو `application/x-ndjson`، يمكنك الحصول على أحداث مثل `text_delta` و`tool_use` و`tool_result` و`thinking` و`citation` و`card` و`artifact` لكل token، مما يسهّل عرض كل نوع على حدة في الواجهة الأمامية.
- **قابل للمقاطعة / الاستئناف**: عندما يحتاج النموذج إلى معلومات إضافية من المستخدم، سيصدر حدث `ask_user_question` ويتوقف مؤقتًا؛ وفي الاستدعاء التالي، يكفي إعادة ملء الإجابة عبر `tool_results` للمتابعة.
- **إجراءات CRUD جديدة**: أكمل `retrieve` / `retrieve_batch` / `update` / `delete` عبر حقل `action` على نفس endpoint، دون الحاجة إلى API إضافية لإدارة المحادثات.
- **قائمة نماذج يتم تحديثها باستمرار**: يتصل افتراضيًا بنماذج معاصرة مثل GPT-5.4 وClaude Opus 4.8 وClaude Sonnet 4.6 وGemini 3.1 Pro وGLM 5.1 وDeepSeek V4 وKimi K3 وغيرها.

وفي الوقت نفسه، فهو **متوافق بالكامل مع v1 من ناحية جسم الطلب**: يكفي تمرير `model` + `question` (+ اختياريًا `stateful` / `id` / `references` / `preset`) للحصول على استجابة JSON من `{answer, id}` مكافئة لـ v1، لذا لا تحتاج إلى إعادة كتابة العميل عند الترحيل من `/aichat/conversations`، بل يكفي تغيير المسار إلى `/aichat2/conversations`.

> إذا كنت تستخدم حاليًا `/aichat/conversations`، فستستمر الواجهة القديمة في تقديم الخدمة، ويمكنك الترحيل بالوتيرة التي تناسبك.

## عملية التقديم

لاستخدام AI Chat v2 API، انتقل أولًا إلى [لوحة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائيًا إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** ستحصل عند التقديم لأول مرة على رصيد مجاني لتجربة الخدمة مجانًا؛ وعند عدم كفاية الرصيد، يمكنك شحن الرصيد العام من [لوحة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [AI Chat v2 API →](https://platform.acedata.cloud/documents/aichat2-conversations)

## الاستخدام الأساسي

أبسط استخدام مطابق تمامًا لـ v1: مرّر `model` + `question`، واحصل على `{answer, id}`.

مثال CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

النتيجة المُعادة:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

مثال Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",
}

response = requests.post(url, json=payload, headers=headers)
print(response.json())
```

يمكن الاطلاع مباشرةً على قيم `model` المتاحة من القائمة المنسدلة في لوحة Try على اليمين، وتشمل الفئات الشائعة:

## محادثة متعددة الجولات

كما في v1، مرّر `stateful: true` لتفعيل حفظ المحادثة، وستُرجع API قيمة `id`؛ وفي الطلبات اللاحقة، يكفي إعادة إرسال `id` لمتابعة المحادثة، دون الحاجة إلى إدارة سجل messages بنفسك.

الطلب الأول:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

الإرجاع:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

الطلب الثاني، مع تضمين `id` نفسه:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> القيمة الافتراضية لـ `stateful` هي `true`، وحذفها يعادل تمرير `true` بشكل صريح. إذا كنت لا ترغب في أن يحفظ الخادم هذه الجولة من المحادثة، يمكنك تعيين `stateful: false` بشكل صريح.

## الاستجابة المتدفقة

يدعم الإصدار v2 تنسيقين للتدفق، ويتم الاختيار وفقًا لترويسة `accept`:

| السيناريو                    | `accept`               | شكل البيانات                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| واجهة ويب أمامية / EventSource  | `text/event-stream`    | `data: {json}\n\n`، والسطر الأخير `data: [DONE]\n\n` |
| خادم / CLI / تحليل تدفق Node | `application/x-ndjson` | كائن JSON واحد في كل سطر                               |
| لا حاجة إلى التدفق                 | `application/json`（افتراضي） | إرجاع `{answer, id}` دفعة واحدة                       |

### مثال NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

كل سطر في NDJSON هو حدث منظّم، وأكثرها شيوعًا هو `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### مثال SSE

لا يدعم استخدام `EventSource` في المتصفح نص طلب مخصصًا، ويُوصى باستخدام `fetch` + التحليل اليدوي بالتقسيم وفقًا لـ `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### أنواع الأحداث المتدفقة

| `type`              | المعنى                                                                                              |
| ------------------- | ----------------------------------------------------------------------------------------------- |
| `text_delta`        | مقطع نصي تزايدي من إجابة المساعد. يمثل `content` المحتوى الجديد؛ وللتوافق مع v1، يحمل الحدث نفسه أيضًا `delta_answer` (يساوي `content`) و`id`.                  |
| `thinking`          | عملية تفكير النموذج (تظهر فقط عندما يكشف النموذج المحدد عن reasoning).                                                                |
| `tool_use`          | يقرر النموذج استدعاء أداة، ويحمل الحدث `tool_id` و`tool_name` و`input`.                                                  |
| `tool_result`       | نتيجة تنفيذ الأداة، وتقترن مع `tool_use` السابقة عبر `tool_id`، ويشير `is_error` إلى ما إذا كان التنفيذ قد فشل.                                       |
| `card`              | بطاقة منظّمة تنتجها الأداة (مثل الصور ومعاينات الروابط)، ومناسبة للعرض المباشر.                                                                    |
| `citation`          | يُستخدم لتكملة عنوان URL للمصدر المرجعي لمقطع النص المقابل.                                                                            |
| `ask_user_question` | يصدر عندما يحتاج النموذج إلى أن يضيف المستخدم معلومات، وتدخل المحادثة في حالة `awaiting_user_input`، راجع [استئناف المحادثات المتوقفة](#恢复暂停的对话) أدناه.                           |
| `artifact`          | مخرج مستقل ينشئه النموذج (مثل كتلة كود أو مستند)، ويمكن حفظه أو تنزيله.                                                                      |
| `system_message`    | معلومات مطالبة من النظام (ليست محتوى المستخدم أو المساعد)، وتُستخدم فقط لتنبيهات واجهة المستخدم.                                                                     |
| `compact`           | حدث تم فيه ضغط السياق الداخلي، ولا يتطلب معالجة خاصة.                                                                             |
| `error`             | حدث خطأ في هذه الجولة، ويصف `message` محتوى الخطأ.                                                                        |
| `done`              | تنتهي الاستجابة المتدفقة، وتحمل `usage` (بما في ذلك `prompt_tokens` / `completion_tokens` / `total_tokens`) و`terminal_reason`. |

بالنسبة إلى العملاء الذين يهتمون فقط بالإجابة النهائية، فإن تجميع `content` لكل `text_delta` يعادل `answer` في وضع `application/json`.

## إدخال متعدد الوسائط

إذا كان إدخال المستخدم يتضمن صورة أو ملفًا، فمرّر `message` (مصفوفة) بدلًا من `question`. كل عنصر في المصفوفة هو كتلة محتوى:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

أنواع الكتل المدعومة:

- `text` — نص عادي، وحقل `text` مطلوب.
- `image_url` — صورة، وحقل `image_url.url` مطلوب.
- `file_url` — ملف (PDF أو CSV أو TXT وغيرها)، وحقل `file_url.url` مطلوب.

### العلاقة مع `references` في v1

للتوافق مع العملاء القدامى، لا يزال v2 يتعرّف على الحقل `references: ["https://...", ...]`:
- إذا كانت لاحقة URL هي `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`، فسيتم تحويلها تلقائيًا إلى كتلة `image_url`؛
- يتم تحويل الامتدادات الأخرى إلى كتلة `file_url`؛
- إذا تم توفير `question` أيضًا في الوقت نفسه، فسيتم وضعه في المقدمة ككتلة `text`.

لذلك، إذا كنت تريد فقط الترحيل من v1 ولا تريد تعديل جسم الطلب، فكل ما عليك هو تغيير المسار إلى `/aichat2/conversations`، وسيستمر استخدام `references` الأصلي في العمل كالمعتاد.

إذا كنت تحتاج إلى تحكم أكثر دقة (مثل وضع عدة صور بين النصوص، أو عندما يكون الترتيب مهمًا جدًا)، فاستخدم مصفوفة `message` مباشرةً.

## استدعاءات الأدوات و MCP

التحسين الأساسي في v2 هو أن النموذج يمكنه استدعاء الأدوات بشكل مستقل لإكمال المهام متعددة الخطوات، **وهذا مفعّل افتراضيًا**، ولا يحتاج العميل إلى إجراء أي إعدادات إضافية في الطلب. السيناريوهات الشائعة:

- يسأل المستخدم: «ساعدني في البحث عن المعارض الجديدة في شنغهاي مؤخرًا» → يستدعي النموذج بحث الويب المدمج → ينظم النتائج في إجابة.
- يسأل المستخدم: «اقرأ ملف PDF هذا ثم اكتب ملخصًا» → يستدعي النموذج file_read → يكتب ملخصًا.
- يكون المستخدم قد فوّض Google Drive / GitHub / Notion وغيرها في [Connections](https://platform.acedata.cloud/connections) → يمكن للنموذج استدعاء أدوات MCP المقابلة لقراءة بياناتها وكتابتها.

في تدفقات NDJSON / SSE، يتم عرض استدعاءات الأدوات من خلال نوعي الأحداث `tool_use` و `tool_result`، على سبيل المثال:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"معارض شنغهاي ربيع 2026"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"حاليًا","delta_answer":"حاليًا","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"شنغهاي","delta_answer":"شنغهاي","id":"f2f4b3e8-..."}
...
```

إذا كنت لا تريد عرض تفاصيل استدعاءات الأدوات في الواجهة الأمامية، فما عليك سوى تجاهل أنواع الأحداث `tool_use` / `tool_result` / `card` / `citation`، إذ سيستمر تدفق الإخراج النهائي للنموذج عبر `text_delta`.

يمكن لـ `max_turns` تقييد الحد الأقصى لعدد جولات استدعاء النموذج الذاتي للأدوات في هذا الطلب، ويتراوح من 1 إلى 500، والقيمة الافتراضية هي 500 عند حذفه. يمكن أن يؤدي تعيينه إلى قيمة صغيرة (مثل `max_turns: 1`) إلى فرض إجابة واحدة، وعدم السماح بأي استدعاء للأدوات.

## التنفيذ غير المتزامن والتفويض غير المراقب

إذا كان استدعاؤك يأتي من Webhook للتنبيهات، أو CI/CD، أو نظام مراقبة، أو مهام خلفية أخرى، يمكنك تعيين `async: true` لجعل الواجهة تُرجع معرّف المهمة فورًا وتستمر في التنفيذ في الخلفية:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "خدمتي أطلقت إنذارًا، أرسل إشعارًا إلى مجموعة WeChat «فريق AceDataCloud» باستخدام WeChat الشخصي..."
}
```

مثال على الاستجابة:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

بعد ذلك، يمكنك استخدام `action: retrieve` + `id` للاستعلام عن نتيجة المحادثة؛ كما يمكنك أيضًا تقديم `callback_url`، وبعد اكتمال المهمة ستقوم المنصة بإرسال `{ status, answer, usage, error }` عبر POST إلى عنوان رد الاتصال الخاص بك. يجب أن يستخدم `callback_url` بروتوكول `http` / `https`، ولا يمكن ملء `localhost` أو عنوان IP خاص حرفيًا مباشرةً.

عادةً لا يوجد شخص يمكنه النقر للتأكيد في المهام الخلفية. إذا كنت تريد أن تقوم بعض Skill أو MCP Server بتنفيذ إجراءات مثل الإرسال، أو النشر، أو الكتابة في الوضع غير المراقب، فالرجاء تمرير قائمة تفويض مسبق صراحةً في جسم الطلب:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "خدمتي أطلقت إنذارًا، أرسل إشعارًا إلى مجموعة WeChat «فريق AceDataCloud» باستخدام WeChat الشخصي..."
}
```

القيم في `allowed_skills` هي slug للـ Skill المتصلة؛ والقيم في `allowed_mcp_servers` هي slug للـ MCP Server المتصلة. لا يزال بإمكان Skill / MCP Server غير المدرجة في التفويض المسبق في الوضع غير المراقب المعاينة فقط، أو dry-run، أو رفض تنفيذ عمليات الكتابة.

إذا كنت تحتاج إلى تحكم أكثر دقة، يمكنك أيضًا استخدام كائن `unattended_policy` المكافئ:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

التفويض المسبق هو هاتان القائمتان نفسهما: تعني القائمة الفارغة عدم تفويض أي قدرة، ولا حاجة إلى حقل مفتاح إضافي.

ملاحظة: يمثل التفويض المسبق فقط أن «هذا الطلب يسمح لهذه القدرات بتجاوز التأكيد اليدوي في الوضع غير المراقب». يجب أن تدعم Skill المحددة أيضًا `--unattended-confirm` أو آلية الأمان المقابلة؛ وإلا فستستمر في dry-run، ولن تنفذ عمليات الكتابة مباشرةً.

## استئناف المحادثات المتوقفة

بعض الأدوات تجعل النموذج «يسأل المستخدم سؤالًا»، وعندها يصدر النموذج حدث `ask_user_question`، وتتجمد المحادثة في حالة `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "هل تريد أن يكون التقرير المُنشأ باللغة الصينية أم الإنجليزية؟",
  "options": ["الصينية", "الإنجليزية"],
  "id": "f2f4b3e8-..."
}
```

اعرض هذا الحدث كبطاقة في الواجهة الأمامية ليختار المستخدم الإجابة، ثم ابدأ الطلب التالي باستخدام `id` نفسه، وأعد تعبئة الإجابة عبر `tool_results`:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "الصينية"
      }
    ]
  }'
```

يجب أن يكون `tool_use_id` في جسم الطلب **مطابقًا تمامًا** لـ `tool_id` عند التوقف؛ وسيتم إرجاع 400 إذا لم يكن متطابقًا. عند وجود `tool_results` في الطلب في الوقت نفسه، سيتم تجاهل كل من `question` / `message` / `references`.

إذا قرر المستخدم التخلي عن هذا السؤال، فما عليه سوى تمرير `question` / `message` جديد، وستقوم المنصة تلقائيًا بوضع علامة «تخطاه المستخدم» على استدعاء الأداة المتوقف.

## إدارة المحادثات (CRUD)

يوفر v2 إدارة خفيفة للمحادثات عبر حقل `action` على نفس endpoint، دون الحاجة إلى فتح API إضافي.
### `action: retrieve` —— جلب محادثة

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

يعيد مستند المحادثة الكامل (بما في ذلك سجل `messages`، و`model`، و`title`، و`tools_used`، وغير ذلك).

### `action: retrieve_batch` —— إدراج ملخصات المحادثات

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

يعيد `{ items: [...], total }`. **لا يحتوي الملخص على `messages`**، وهو مناسب لقائمة الشريط الجانبي؛ إذا فتح المستخدم محادثة معيّنة، فاستخدم بعد ذلك `action: retrieve` لجلب رسائلها الكاملة بشكل منفصل.

معلمات التصفية الاختيارية: `user_id`، و`application_id`، و`model_group`، و`model`.

### `action: update` —— تغيير العنوان أو إعادة كتابة السجل

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

يمكن أيضًا تمرير `messages`، لكن الخادم سيجري تحققًا صارمًا من schema (ويجب أن تكون بصيغة `ToolUseContent` المطوية)، وسيعيد 400 إذا لم تتوافق. عمومًا، يُنصح باستخدامه فقط لتغيير `title`.

### `action: delete` —— حذف محادثة

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

يعيد `{ id, success: true }`. لا يمكن الاستعادة بعد الحذف، يُرجى التأكيد قبل الاستدعاء.

## الترحيل السلس من v1

إذا كنت تستخدم بالفعل [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations)، فإن الترحيل إلى v2 لا يتطلب تقريبًا أي تعديل في الكود:

1. غيّر URL من `https://api.acedata.cloud/aichat/conversations` إلى `https://api.acedata.cloud/aichat2/conversations`.
2. إذا كنت تمرر سابقًا اسم نموذج v1 (مثل `gpt-3.5`، و`gpt-4-browsing`، وغير ذلك)، فيُنصح عند التبديل إلى v2 بالترقية إلى نماذج حديثة (مثل `gpt-5.4`، و`claude-opus-4-8`، و`gemini-3.1-pro-preview`، وغير ذلك).
3. تبقى حقول تدفق NDJSON متوافقة مع الإصدارات السابقة: لا يزال كل حدث `text_delta` يحمل `delta_answer` و`id`، لذلك لا يحتاج العميل الذي كان يحلل `delta_answer` سطرًا بسطر إلى أي تعديل.

بعد الترحيل، يمكن تمكين قدرات v2 الجديدة حسب الحاجة (مثل `message` متعدد الوسائط، وSSE، واستدعاء الأدوات، وCRUD عبر `action`) والتقدم بالوتيرة المناسبة.

## معالجة الأخطاء

استجابة الخطأ موحدة كالتالي:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

الأخطاء الشائعة:

- `400 bad_request`: حقول إلزامية مفقودة، أو عدم تطابق `tool_use_id`، أو schema غير صالح لـ `messages`، وغير ذلك.
- `401 invalid_token`: رأس `authorization` غير صحيح.
- `404 not_found`: لا توجد المحادثة المطابقة لـ `id` عند `action: retrieve / update / delete`.
- `429 too_many_requests`: تم تفعيل حد المعدل.
- `500 chat_error`: خطأ من LLM العلوي أو `completion_tokens=0` في هذه الجولة (يُعامل على أنه غير مستهلك، ولن يتم فرض رسوم).

في الاستجابة المتدفقة، يُصدر الخطأ كحدث `{"type":"error","message":"..."}`، ثم ينتهي التدفق مباشرةً.

## الخلاصة

يرتقي AI Chat v2 API بالمحادثات، مع الحفاظ على التوافق مع v1، من «أسئلة وأجوبة لجولة واحدة / جولات متعددة» إلى «محادثات قابلة للرصد وموجهة بالـ Agent»: إدخال متعدد الوسائط، واستدعاء الأدوات، وإمكانية الإيقاف / الاستئناف، وأحداث منظمة متدفقة، وCRUD مدمج. يُنصح بالاستفادة من v2 مباشرةً عند التكامل الجديد؛ أما تكاملات v1 الحالية فيمكنها الترحيل بسلاسة على مراحل. إذا كانت لديكم أي أسئلة، يُرجى التواصل مع فريق الدعم الفني لدينا في أي وقت.
