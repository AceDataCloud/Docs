Anthropic Claude هو نظام محادثة بالذكاء الاصطناعي قوي جدًا، فما عليك سوى إدخال مطالبة ليُنشئ ردًا سلسًا وطبيعيًا في غضون ثوانٍ قليلة. يتميز Claude في المجال بقدراته الممتازة على فهم اللغة وتوليدها، واليوم أصبح Claude مستخدمًا على نطاق واسع في مختلف الصناعات والمجالات، وأصبح تأثيره أكثر وضوحًا. سواء في المحادثات اليومية أو الكتابة الإبداعية أو الاستشارات المهنية أو برمجة الأكواد، يمكن لـ Claude تقديم مساعدة ذكية مذهلة، مما يحسن بشكل كبير كفاءة العمل والإبداع لدى البشر.

تقدم هذه الوثيقة بشكل أساسي عملية استخدام Claude Chat Completion API، والتي تتيح لنا استخدام وظيفة المحادثة الرسمية لـ Claude بسهولة.

## عملية التقديم

لاستخدام Claude Chat Completion API، انتقل أولًا إلى [لوحة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد سجلت الدخول أو أنشأت حسابًا بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائيًا إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة للتقديم بشكل منفصل لكل خدمة.** ستحصل عند أول تقديم على رصيد مجاني لتجربة الخدمة مجانًا؛ وعندما لا يكون الرصيد كافيًا، يمكنك شحن الرصيد العام من [لوحة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثائق الكاملة: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## الاستخدام الأساسي

بعد ذلك، يمكنك تعبئة المحتوى المقابل في الواجهة، كما هو موضح في الشكل:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

عند استخدام هذه الواجهة لأول مرة، نحتاج إلى تعبئة ثلاثة عناصر على الأقل. أحدها هو `authorization`، ويمكنك اختياره مباشرة من القائمة المنسدلة. المعلمة الأخرى هي `model`، ويوصى باستخدام الإصدار الرائد الأحدث `claude-fable-5-1`؛ ولا يزال بالإمكان استدعاء الإصدار السابق `claude-fable-5`. المعلمة الأخيرة هي `messages`، وهي مصفوفة من عبارات الأسئلة، ويحتوي كل عنصر على `role` و`content`؛ يدعم `role` القيم `user` و`assistant` و`system`، بينما يمثل `content` المحتوى المحدد. يدعم Claude Fable 5.1 سياقًا يصل إلى مليون Token ومخرجات تصل إلى 128K Token كحد أقصى.

في الوقت نفسه، يمكنك ملاحظة وجود إنشاء لكود الاستدعاء المقابل على الجانب الأيمن، ويمكنك نسخ الكود وتشغيله مباشرة، أو النقر مباشرة على زر «Try» للاختبار.

المعلمات الاختيارية الشائعة:

- `max_tokens`: يحدد الحد الأقصى لعدد token في الرد الواحد.
- `temperature`: عشوائية التوليد، بين 0 و2، وكلما زادت القيمة زاد التشتت.
- `n`: عدد الردود المرشحة التي يتم إنشاؤها في المرة الواحدة.
- `response_format`: إعداد تنسيق الإرجاع.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

بعد الاستدعاء، نجد أن النتيجة المعادة كما يلي:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }

```

تحتوي النتيجة المعادة على عدة حقول، يتم تقديمها كما يلي:

- `id`، معرّف مهمة المحادثة التي تم إنشاؤها، ويُستخدم لتمييز مهمة المحادثة هذه بشكل فريد.
- `model `، نموذج Claude الرسمي المحدد.
- `choices`، معلومات الرد التي يقدمها Claude على عبارة السؤال.
- `usage `: معلومات إحصائية عن token لهذه الجولة من الأسئلة والأجوبة.

في تنسيق Chat Completions، يمثل `usage.prompt_tokens` إجمالي المدخلات؛ ويسجل `prompt_tokens_details.cached_tokens` و`prompt_tokens_details.cache_write_tokens` تفاصيل قراءة وكتابة ذاكرة التخزين المؤقت على التوالي. يمثل `completion_tokens_details.reasoning_tokens` مجموعة فرعية من `completion_tokens`، ولا تقم بإضافته مرة أخرى عند حساب الإجمالي أو التكلفة. قد تعيد الاستجابات غير المتدفقة أيضًا كائن `usage.cost`، حيث يمثل `amount` استهلاك الرصيد الفعلي، ويمثل `currency` وحدة القياس، ويمثل `list_amount` المبلغ قبل الخصم (إن وجد).

اسم الحقل المتوافق مع Chat هو `reasoning_tokens`؛ بينما تستخدم Messages API الأصلية `output_tokens_details.thinking_tokens`. يختلف wire schema للبروتوكولين، ويجب ألا يخلط العميل بين أسماء الحقول.

من بينها، `choices` تحتوي على معلومات رد Claude، أما `choices` الموجودة بداخلها فهي المعلومات المحددة لرد Claude، كما يمكن ملاحظته في الشكل.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

يمكنك رؤية أن حقل `content` داخل `choices` يحتوي على المحتوى المحدد لرد Claude.

## الاستجابة المتدفقة

تدعم هذه الواجهة أيضًا الاستجابة المتدفقة، وهذا مفيد جدًا لربط صفحات الويب، إذ يمكن أن يتيح للصفحة تحقيق تأثير العرض حرفًا بحرف.

إذا كنت تريد إرجاع الاستجابة بشكل متدفق، يمكنك تغيير المعلمة `stream ` في رأس الطلب إلى `true`.

يكون التعديل كما هو موضح في الشكل، لكن كود الاستدعاء يحتاج إلى تعديلات مقابلة لدعم الاستجابة المتدفقة.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

بعد تغيير `stream` إلى `true`، ستعيد API بيانات JSON المقابلة سطرًا بسطر، وعلى مستوى الكود نحتاج إلى إجراء التعديلات المناسبة للحصول على النتائج سطرًا بسطر.

كود استدعاء نموذجي بلغة Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## التفكير العميق
قد تقوم نماذج Claude من الجيل الجديد بالاستدلال وفقًا لسياسة النموذج الافتراضية، دون الحاجة إلى تشغيله عبر لاحقة نموذج `-thinking`. تستخدم الاستجابات المتوافقة مع Chat حقل usage المتوافق مع OpenAI وهو `completion_tokens_details.reasoning_tokens`. إن `reasoning_tokens` مشمولة بالفعل ضمن `completion_tokens`، لذا لا تقم بجمعها بشكل متكرر. يشترك الاستدلال والنص المرئي في الحد الأقصى لرموز الإخراج، لذلك عند انخفاض `max_tokens` قد يظهر النص فارغًا أو يتم اقتطاعه؛ عند مواجهة هذه الحالة، يرجى زيادة ميزانية الإخراج، أو اختيار مستوى استدلال أقل عندما يدعم النموذج المستخدم ذلك.

إذا كنت بحاجة إلى `thinking` الأصلي، و`output_config.effort`، وكتل محتوى thinking، وإرجاع التوقيع، فيرجى استخدام `/v1/messages`. حقل usage المقابل لـ Messages هو `output_tokens_details.thinking_tokens`، ولا تخلطه مع `completion_tokens_details.reasoning_tokens` المتوافق مع Chat.

## نماذج الرؤية

claude-sonnet-4-20250514 هو نموذج لغوي كبير متعدد الوسائط طورته Claude، ويضيف قدرة فهم الرؤية على أساس claude-4. يمكن لهذا النموذج معالجة مدخلات النصوص والصور في الوقت نفسه، مما يحقق الفهم والتوليد عبر الوسائط.

تتوافق معالجة النصوص باستخدام نموذج claude-sonnet-4-20250514 مع محتوى الاستخدام الأساسي المذكور أعلاه، وفيما يلي مقدمة موجزة عن كيفية استخدام قدرة معالجة الصور الخاصة بالنموذج.

يمكن ملاحظة أن محتوى الإجابة يعتمد على الصورة، ولذلك يمكن بسهولة استخدام قدرات معالجة النصوص والصور لنموذج claude-3-7-sonnet-20250219 من خلال الطريقتين المذكورتين أعلاه.

## معالجة الأخطاء

عند استدعاء API، إذا حدث خطأ، فستُرجع API رمز الخطأ والمعلومات المقابلة. على سبيل المثال:

- `400 token_mismatched`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `400 api_not_implemented`：طلب غير صالح، ربما بسبب معلمات مفقودة أو غير صالحة.
- `401 invalid_token`：غير مصرح به، رمز التفويض غير صالح أو مفقود.
- `429 too_many_requests`：طلبات كثيرة جدًا، لقد تجاوزت حد المعدل.
- `500 api_error`：خطأ داخلي في الخادم، حدث خطأ ما على الخادم.

### مثال على استجابة خطأ

```
    "code": "api_error",

  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
