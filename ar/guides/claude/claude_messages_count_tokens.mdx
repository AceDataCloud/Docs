يمكن لواجهة برمجة التطبيقات لحساب رموز رسائل كلود حساب عدد رموز الإدخال لرسالة معينة دون الحاجة إلى إنشاء الرسالة فعليًا، بما في ذلك عدد رموز المحتويات مثل الأدوات والصور والمستندات. هذا مفيد جدًا عند الحاجة إلى تقدير التكاليف أو التحقق مما إذا كان الإدخال يتجاوز قيود سياق النموذج.

تتناول هذه الوثيقة بشكل أساسي عملية استخدام واجهة برمجة التطبيقات لحساب رموز رسائل كلود.

## عملية الطلب

لاستخدام واجهة برمجة التطبيقات لحساب رموز رسائل كلود، يجب أولاً الذهاب إلى [وحدة التحكم في بيانات Ace](https://platform.acedata.cloud/console/applications) للحصول على رمز API الخاص بك، للاحتفاظ به كنسخة احتياطية.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تكن قد قمت بتسجيل الدخول أو التسجيل بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك للتسجيل وتسجيل الدخول، وبعد الانتهاء، سيتم إرجاعك تلقائيًا إلى الصفحة الحالية.

**يمكن استخدام رمز API واحد لاستدعاء جميع خدمات المنصة، دون الحاجة لتقديم طلب منفصل لكل خدمة.** ستمنحك أول عملية طلب رصيدًا مجانيًا لتجربته مجانًا؛ وعند نفاد الرصيد، يمكنك إعادة شحن الرصيد العام في [وحدة التحكم](https://platform.acedata.cloud/console/coin).

> 📘 الوثيقة الكاملة: [واجهة برمجة التطبيقات لحساب رموز رسائل كلود →](https://platform.acedata.cloud/documents/claude-messages-count-tokens)

## الاستخدام الأساسي

مسار طلب واجهة برمجة التطبيقات لحساب رموز رسائل كلود هو `/v1/messages/count_tokens`، وهو متوافق مع واجهة برمجة التطبيقات الرسمية من Anthropic. نحتاج على الأقل إلى تقديم معلمين أساسيين:

- `model`: اختيار نموذج كلود المستخدم، مثل أحدث نموذج رائد `claude-fable-5-1`؛ لا يزال النموذج الأصلي `claude-fable-5` متوافقًا.
- `messages`: مصفوفة الرسائل المدخلة، تحتوي كل رسالة على `role` (الدور) و `content` (المحتوى).

المعلمات الاختيارية الشائعة:

- `system`: عبارة النظام، ستؤخذ في الاعتبار عند حساب عدد الرموز.
- `tools`: تعريف الأدوات، ستؤخذ في الاعتبار عند حساب عدد الرموز.
- `thinking`: إعدادات التفكير الموسعة.
- `tool_choice`: إعدادات اختيار الأدوات.
- `cache_control`: إعدادات التحكم في التخزين المؤقت على مستوى الكتلة أو المحتوى.

تستخدم `messages` و `system` واستدعاءات أدوات التشغيل وإعادة تشغيل الصور URL وكتل المحتوى document/PDF نفس هيكل الطلب المستقر كما في واجهة برمجة التطبيقات للرسائل.

### مثال cURL

```bash
curl -X POST 'https://api.acedata.cloud/v1/messages/count_tokens' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "claude-fable-5-1",
    "messages": [
      {
        "role": "user",
        "content": "Hello, Claude"
      }
    ]
  }'
```

### مثال Python

```python
import httpx

url = "https://api.acedata.cloud/v1/messages/count_tokens"
headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}
payload = {
    "model": "claude-fable-5-1",
    "messages": [
        {
            "role": "user",
            "content": "Hello, Claude"
        }
    ],
}
response = httpx.post(url, headers=headers, json=payload)
print(response.json())
```

مثال على نتيجة العودة:

```json
{
  "input_tokens": 11
}
```

### استخدام SDK من Anthropic

تقبل واجهة برمجة التطبيقات لحساب رموز رسائل كلود هيكل الطلب المستقر من SDK من Anthropic، ويمكن استدعاؤها من خلال مكتبة `anthropic`. القيمة المرجعة الحالية يتم حسابها بواسطة مقدر محلي من Ace Data Cloud، وليست نتيجة دقيقة من tokenizer الرسمي من Anthropic؛ قد يكون هناك انحراف في عدد الرموز الفعلي للنماذج متعددة الوسائط والأدوات ونماذج كلود المختلفة.

```python
from anthropic import Anthropic

client = Anthropic(
    api_key="{token}",
    base_url="https://api.acedata.cloud",
)

result = client.messages.count_tokens(
    model="claude-opus-4-8",
    messages=[
        {
            "role": "user",
            "content": "Hello, Claude"
        }
    ],
)
print(result.input_tokens)
```

## حساب الرموز مع الأدوات

إذا كانت طلباتك تتضمن تعريفات الأدوات، فستؤخذ هذه الأدوات أيضًا في الاعتبار عند حساب عدد الرموز:

```python
result = client.messages.count_tokens(
    model="claude-opus-4-8",
    messages=[
        {
            "role": "user",
            "content": "What is the weather in San Francisco?"
        }
    ],
    tools=[
        {
            "name": "get_weather",
            "description": "Get the current weather in a given location",
            "input_schema": {
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "The city and state, e.g. San Francisco, CA"
                    }
                },
                "required": ["location"]
            }
        }
    ],
)
print(result.input_tokens)
```

## حساب الرموز مع عبارة النظام

ستؤخذ عبارة النظام أيضًا في الاعتبار عند حساب عدد الرموز:

```python
result = client.messages.count_tokens(
    model="claude-opus-4-8",
    system="You are a helpful assistant that speaks Chinese.",
    messages=[
        {
            "role": "user",
            "content": "Hello"
        }
    ],
)
print(result.input_tokens)
```

## ملاحظات

- تقوم هذه الواجهة بحساب عدد رموز الإدخال فقط، ولن تنتج أي مخرجات من النموذج.
- يمكن استخدام نتائج حساب الرموز لتقدير تقريبي لحجم الإدخال، ولا ينبغي اعتبارها أساسًا دقيقًا للفوترة أو قيود نافذة السياق أو مقارنة tokenizer للنموذج.
- لا يقوم المقدّر الحالي بحساب الرموز البصرية/المستندات بدقة للصور وPDF، ولا يمكنه عكس الفروق بين tokenizer الرسمي لنماذج كلود المختلفة.
- هذه الواجهة مجانية تمامًا، ولا تستهلك أي رصيد.
