Codex CLI هو وكيل برمجة محلي مفتوح المصدر أطلقته OpenAI، يعمل في الطرفية الخاصة بك. يمكنه قراءة الشيفرة، تعديل الملفات، تنفيذ الأوامر، تفسير الأخطاء، ومساعدتك في إتمام مهام التطوير اليومية.

يدعم Codex CLI تخصيص مزود النموذج، حيث يمكنك استخدام وكيل متوافق مع OpenAI Responses مقدم من Ace Data Cloud دون الحاجة للاشتراك في حساب OpenAI الرسمي. بعد الإعداد، سيرسل Codex CLI الطلبات إلى `https://api.acedata.cloud/v1`.

## عملية التقديم

لاستخدام Codex CLI، يمكنك أولاً الحصول على رمز API الخاص بك من خلال [لوحة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للاحتفاظ به.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

إذا لم تكن مسجلاً أو مسجلاً دخولك، سيتم توجيهك تلقائياً إلى صفحة تسجيل الدخول للتسجيل والدخول، وبعدها ستعود تلقائياً إلى الصفحة الحالية.

عند التقديم لأول مرة، ستحصل على رصيد مجاني لتجربة خدمة Codex CLI مجاناً.

## تثبيت Codex CLI

يدعم Codex CLI أنظمة macOS وLinux وWindows وWSL. يمكنك تثبيته عبر npm أو باستخدام Homebrew (لنظام macOS فقط).

### التثبيت عبر npm (موصى به)

إذا كنت قد ثبتت Node.js مسبقاً، يمكنك تثبيت Codex مباشرة عبر npm. يتطلب هذا Node.js إصدار 18 أو أحدث.

```bash
npm install -g @openai/codex
```

### التثبيت عبر Homebrew (لنظام macOS)

يمكن لمستخدمي macOS تثبيت Codex عبر Homebrew:

```bash
brew install --cask codex
```

### التحقق من التثبيت

بعد التثبيت، أعد فتح الطرفية وتحقق من توفر الأمر:

```bash
codex --version
```

إذا ظهر لك `command not found`، فهذا يعني أن الطرفية لم تقم بتحميل مسار PATH الجديد بعد. يرجى إغلاق الطرفية وإعادة فتحها، أو مراجعة مخرجات سكريبت التثبيت لمعرفة إعدادات PATH.

## إعداد Codex CLI

بعد التثبيت، يحاول Codex CLI الاتصال بخدمة OpenAI الرسمية بشكل افتراضي. لاستخدام Ace Data Cloud، يجب تعيين `model_provider` مخصص في ملف إعدادات Codex، ووضع رمز API في متغير بيئة مناسب.

### الخطوة الأولى: تعيين متغير البيئة

يوصى بكتابة رمز API في ملف إعدادات الشل مثل `~/.zshrc` أو `~/.bashrc` أو `~/.bash_profile`:

```bash
export ACEDATACLOUD_API_KEY="{token}"
```

استبدل `{token}` برمز API الذي نسخته من لوحة تحكم Ace Data Cloud.

بعد الإعداد، أعد فتح الطرفية أو نفذ الأمر التالي لتفعيل الإعداد فوراً:

```bash
source ~/.zshrc
```

### الخطوة الثانية: تحرير ملف إعدادات Codex

يستخدم Codex CLI الملف `~/.codex/config.toml` كملف إعدادات عام. إذا لم يكن موجوداً، يمكنك إنشاؤه:

```bash
mkdir -p ~/.codex
touch ~/.codex/config.toml
```

اكتب المحتوى التالي في `~/.codex/config.toml`:

```toml
model_provider = "acedatacloud"
model = "gpt-5"
model_reasoning_effort = "high"

[model_providers.acedatacloud]
name = "Ace Data Cloud"
base_url = "https://api.acedata.cloud/v1"
env_key = "ACEDATACLOUD_API_KEY"
wire_api = "responses"
```

تفسير الحقول:

| الحقل | الوصف |
| --- | --- |
| `model_provider` | اسم المزود الافتراضي، يتطابق مع المفتاح في `[model_providers.<name>]` أدناه |
| `model` | معرف النموذج الافتراضي المستخدم |
| `model_reasoning_effort` | قوة الاستدلال، القيم الشائعة: `low`، `medium`، `high` |
| `[model_providers.acedatacloud].base_url` | عنوان وكيل OpenAI Responses الخاص بـ Ace Data Cloud |
| `[model_providers.acedatacloud].env_key` | اسم متغير البيئة الذي يقرأ منه Codex CLI رمز API |
| `[model_providers.acedatacloud].wire_api` | نوع البروتوكول، لاستخدام OpenAI Responses API يجب أن يكون `responses` |

### تنظيف بيانات تسجيل الدخول المخزنة لـ OpenAI

إذا كنت قد سجلت دخولك مسبقاً بحساب OpenAI الرسمي في Codex CLI، قد يكون هناك حالة تسجيل دخول مخزنة محلياً (عادة في `~/.codex/auth.json`). قبل التبديل إلى وكيل Ace Data Cloud، يُنصح بتنظيف تسجيل الدخول القديم:

```bash
codex logout
```

إذا لم يكن الأمر `codex logout` متاحاً، يمكنك حذف ملف التخزين يدوياً:

```bash
rm -f ~/.codex/auth.json
```

إذا لم تسجل دخولك من قبل بحساب OpenAI الرسمي، يمكنك تخطي هذه الخطوة.

### بدء جلسة العمل

انتقل إلى مجلد مشروعك ثم شغّل Codex CLI:

```bash
cd /path/to/your/project
codex
```

عند ظهور واجهة التفاعل مع Codex، يمكنك إدخال طلباتك مباشرة، مثل:

```text
اشرح هيكل مجلدات هذا المشروع
```

### التحقق من الإعدادات

داخل Codex CLI، يمكنك عرض النموذج والمزود الحالي عبر الأمر:

```text
/model
```

يجب أن ترى أن النموذج الحالي من مزود `acedatacloud`، مثلاً:

```text
Model: gpt-5
Provider: acedatacloud
```

إذا لم يكن المزود المعروض هو `acedatacloud`، فهذا يعني أن الإعداد لم يُفعّل. يرجى مراجعة حفظ ملف `~/.codex/config.toml` والتأكد من أن متغير البيئة `ACEDATACLOUD_API_KEY` قابل للقراءة في الطرفية الحالية:

```bash
echo $ACEDATACLOUD_API_KEY
```

يمكنك أيضاً مراجعة سجل الطلبات والتفاصيل المالية عبر [لوحة تحكم Ace Data Cloud - سجل الاستخدام](https://platform.acedata.cloud/console/usages) ومتابعة الرصيد المتبقي عبر [لوحة تحكم Ace Data Cloud - قائمة التطبيقات](https://platform.acedata.cloud/console/applications).

## كيفية العمل

يستخدم Codex CLI بروتوكول OpenAI Responses API أصلاً. تقدم Ace Data Cloud خدمة وكيل متوافقة مع OpenAI Responses API على `https://api.acedata.cloud/v1/responses`، لذا لا يحتاج Codex CLI إلى وكيل محلي أو إضافات خارجية.

سير العمل:

1. يقرأ Codex CLI من `~/.codex/config.toml` قيمة `model_provider` ويحمل إعدادات `[model_providers.acedatacloud]`.
2. يقرأ رمز API من متغير البيئة المحدد بـ `env_key` (أي `ACEDATACLOUD_API_KEY`).
3. يرسل الطلب عبر بروتوكول `wire_api = "responses"` إلى `base_url + /responses`، أي `https://api.acedata.cloud/v1/responses`.
4. تتحقق Ace Data Cloud من هوية المستخدم ورصيده باستخدام رمز API، ثم تعيد توجيه الطلب إلى قناة النموذج المتاحة.
5. بعد إتمام الطلب، تسجل المنصة الاستخدام وتخصم الرصيد وفقاً للاستهلاك.

هذا يعني أنك تستخدم أمر `codex` الأصلي وتجربة Codex CLI كما هي، مع تبديل خدمة النموذج الأساسية إلى Ace Data Cloud.

## إعداد النموذج

يحدد حقل `model` في `~/.codex/config.toml` النموذج الافتراضي المستخدم في Codex. تدعم خدمة OpenAI Responses من Ace Data Cloud عدة نماذج شائعة، منها:

| النموذج | الوصف |
| --- | --- |
| `gpt-5` | النموذج الافتراضي الموصى به، مناسب لمعظم مهام البرمجة |
| `gpt-5-mini` | أخف وأسرع استجابة، مناسب للمهام البسيطة |
| `gpt-5.5` | نسخة محدثة وأقوى |
| `gpt-5.5-pro` | نسخة محسنة، مناسبة للمهام التي تتطلب استدلال معقد |
| `gpt-4.1` | النموذج الرئيسي للجيل السابق |
| `o3` | نموذج معزز للاستدلال، مناسب للمهام التي تحتاج استدلال عميق |
| `o4-mini-high-all` | نموذج استدلال خفيف |

يمكنك التبديل مؤقتاً للنموذج عند تشغيل Codex عبر خيار سطر الأوامر:

```bash
codex --model gpt-5-mini
```

أو تعديل حقل `model` في `~/.codex/config.toml` ثم إعادة التشغيل. يمكنك الاطلاع على القائمة الكاملة للنماذج في [توثيق خدمة OpenAI من Ace Data Cloud](https://platform.acedata.cloud/documents/openai).

## مستويات الثقة للمشاريع

يدعم Codex CLI تعيين مستويات ثقة مختلفة لمشاريع مختلفة للتحكم في صلاحيات الوكيل. يمكن إضافة التالي في نهاية `~/.codex/config.toml`:

```toml
[projects."/path/to/trusted/project"]
trust_level = "trusted"

[projects."/path/to/untrusted/project"]
trust_level = "untrusted"
```

التفاصيل:

- `trusted`: الوكيل يمتلك صلاحيات كاملة، يمكنه تنفيذ الأوامر وتعديل الملفات.
- `untrusted`: الوكيل يمتلك صلاحيات محدودة، مناسب للمشاريع غير المألوفة.
