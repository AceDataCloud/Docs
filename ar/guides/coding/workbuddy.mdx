## 1. الحصول على API Key

افتح [قائمة تطبيقات Ace Data Cloud](https://platform.acedata.cloud/console/applications)، وادخل إلى تطبيق متاح وانسخ API Key.

![الحصول على Ace Data Cloud API Key](https://cdn.acedata.cloud/dvc3cg.jpg)

## 2. إضافة نموذج

في WorkBuddy، انتقل إلى **الإعدادات → النماذج → النماذج المخصصة → إضافة نموذج**، ثم املأ:

| الحقل       | القيمة                                                                                                |
| -------- | ------------------------------------------------------------------------------------------------ |
| Provider | `Custom`                                                                                         |
| عنوان الواجهة     | `https://api.acedata.cloud/v1`                                                                   |
| API Key  | API Key الذي نسخته للتو                                                                                    |
| اسم النموذج     | انتقل إلى [دليل النماذج](https://platform.acedata.cloud/models) لعرضه، واملأ اسم النموذج المطلوب استدعاؤه كما هو، مثل `claude-opus-5` و`gpt-6-sol` |
| البروتوكول المخصص    | إيقاف                                                                                               |

![واجهة تكوين WorkBuddy Custom Provider](https://cdn.acedata.cloud/189027b68722.png)

> إن `id` هنا هو اسم النموذج المستخدم في معامل `model` ضمن طلب API، وليس UUID للخدمة أو API أو Application، وليس اسم عرض مخصصًا. لا يمكن ملء `ds-4.0` إلا عندما يعيد الدليل المباشر `{"id":"ds-4.0"}`؛ وإذا لم يكن موجودًا في الدليل، فهذا يعني أنه غير متاح حاليًا، فلا تخمّن أو تختصر.

يمكنك أولًا عرض النماذج المتاحة في [دليل النماذج](https://platform.acedata.cloud/models)؛ وإذا كنت تحتاج إلى تأكيد الاسم الدقيق الذي يمكن لبيانات اعتماد Coding الحالية استدعاؤه، فاستخدم API Key الذي نسخته للتو للاستعلام عن دليل API:

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_KEY"
```

اعثر على النموذج المستهدف في مصفوفة `data` ضمن الاستجابة، وانسخ قيمة `id` الخاصة به كما هي. يرجى تكوين مفاتيح القدرات وفقًا للدعم الفعلي لذلك النموذج.

عند إبقاء «البروتوكول المخصص» مغلقًا، سيكمل WorkBuddy المسار وفقًا لقواعد OpenAI Chat Completions. لا تُفعَّل مفاتيح القدرات المتقدمة (الأدوات، الصور، الاستدلال) إلا وفقًا للقدرات الفعلية للنموذج المحدد؛ وعند عدم التأكد، أبقِ الإعدادات الافتراضية أولًا.

## 3. التحقق

بعد الحفظ، اختر النموذج الذي أضفته للتو في محدد نماذج الدردشة وأرسل `Reply only OK`. ثم نفّذ مهمة ملف أو أداة للقراءة فقط مرة أخرى، للتأكد من أن القدرات المطلوبة متاحة؛ ويمكن عرض سجلات الاستدعاء في [سجل الاستخدام](https://platform.acedata.cloud/console/usages).

إذا لم يظهر النموذج، فتأكد من أن التكوين قد تم حفظه وتمكينه؛ افحص Key عند ظهور 401؛ وافحص ما إذا كان اسم النموذج المُدخل مطابقًا تمامًا لـ `id` في الدليل، وما إذا كان عنوان الواجهة صحيحًا عند ظهور 404. توضح الإرشادات الرسمية لـ WorkBuddy أن Key يُحفظ في التكوين المحلي، لكن محتوى الطلب سيظل يُرسل إلى خدمة النموذج التي تم تكوينها.
