## دليل النماذج الديناميكي

يمكنك أولاً فتح [دليل النماذج](https://platform.acedata.cloud/models) لعرض أسماء النماذج الحالية، مثل `claude-opus-5` و`gpt-6-sol`. عند الحاجة إلى تأكيد ما إذا كانت بيانات اعتماد Coding وبروتوكول API متطابقين، استخدم بيانات اعتماد Coding Application صالحة لطلب:

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_TOKEN"
```

سيتغير دليل النماذج باستمرار، ولا يتم الحفاظ في هذه الوثيقة على عدد ثابت أو قائمة نماذج ثابتة. يمثل `id` لكل عنصر في الاستجابة **اسم النموذج** الذي يمكن تمريره مباشرةً إلى معلمة API `model`، على سبيل المثال، يتوافق `{"id":"deepseek-v4-pro"}` مع إدخال `deepseek-v4-pro`؛ وهو ليس UUID لخدمة أو API أو Application. يعيد `/v1/models` دليل النماذج العام، ولا تتم تصفيته تلقائيًا وفقًا لبيانات اعتماد Coding؛ ولا يزال من الضروري قبل الإعداد التأكد بشكل متقاطع من نطاق API لبيانات الاعتماد والبروتوكول المحدد ونطاق التوافق للعميل.

## استكشاف الأخطاء الشائعة وإصلاحها

- **الرصيد غير كافٍ**: ادخل إلى [وحدة تحكم Applications](https://platform.acedata.cloud/console/applications)، واعثر على Coding Application وقم بالتجديد بشكل استباقي.
- **لا يزال العميل يطلب العنوان الأصلي**: تأكد من أن الإعداد ينتمي إلى المستخدم نفسه ومساحة العمل نفسها التي تشغّل العميل، ثم أخرج من العميل بالكامل وأعد تشغيله.
- **اسم النموذج غير متاح**: أعد طلب `/v1/models`، وتحقق مما إذا كان اسم النموذج المُدخل مطابقًا تمامًا لـ`id` في الدليل، وكذلك نطاق API لبيانات الاعتماد والبروتوكول الذي يدعمه العميل.
- **يتعذر على Token استدعاء الواجهة**: تأكد من أن بيانات الاعتماد تنتمي إلى Coding Application، وتحقق من `allowed_api_ids` وصلاحيات API للتطبيق.
