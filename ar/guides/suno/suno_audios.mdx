مع اتساع تطبيقات الذكاء الاصطناعي، أصبحت مختلف برامج الذكاء الاصطناعي منتشرة تدريجيًا. وقد تغلغل الذكاء الاصطناعي تدريجيًا في جميع جوانب عمل الناس وحياتهم. كما تزداد الصناعات التي يشملها الذكاء الاصطناعي، بدءًا من الكتابة في البداية، وصولًا إلى الرعاية الصحية والتعليم، ثم إلى الموسيقى الآن.

Suno هي منصة احترافية وعالية الجودة لإنشاء الأغاني والموسيقى بالذكاء الاصطناعي، حيث يحتاج المستخدمون فقط إلى إدخال كلمات توجيهية نصية بسيطة لإنشاء أغانٍ تحتوي على أصوات غنائية وفقًا لنمط النوع وكلمات الأغنية. طوّر مولّد الموسيقى هذا بالذكاء الاصطناعي أعضاء فريق من شركات تقنية معروفة مثل Meta وTikTok وKensho، ويهدف إلى تمكين الجميع من إنشاء موسيقى رائعة دون الحاجة إلى أي أدوات أو آلات موسيقية.

> حدود `lyric` و`style` في الجدول أعلاه هي الحدود القصوى في الوضع المخصص (حيث تكون `custom` بقيمة `true`). في وضع الإلهام غير المخصص (حيث تكون `custom` بقيمة `false`) يتم ملء `prompt` فقط، ويبلغ الحد الأقصى لطوله 500 حرف (وهو نفسه لجميع النماذج).

يدعم Suno الآن `chirp-v6` و`chirp-v6-wild` و`chirp-v6-mini`. يُوصى باستخدام `chirp-v6`؛ وتظل أسماء النماذج القديمة متوافقة.

لكن Suno الرسمي لا يوفر واجهة API، وتوفر AceDataCloud مجموعة من واجهات API لـ Suno، تحاكي التكامل مع Suno الرسمي، ويمكنها إنشاء الموسيقى المطلوبة بسهولة وسرعة.

## التقديم والاستخدام

لاستخدام Suno Audios Generation API، انتقل أولًا إلى [وحدة تحكم Ace Data Cloud](https://platform.acedata.cloud/console/applications) للحصول على API Token الخاص بك، واحتفظ به للاستخدام لاحقًا.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

إذا لم تقم بتسجيل الدخول أو التسجيل بعد، فسيتم تحويلك تلقائيًا إلى صفحة تسجيل الدخول لدعوتك إلى التسجيل وتسجيل الدخول، وبعد الإكمال ستعود تلقائيًا إلى الصفحة الحالية.

**يمكن لـ API Token واحد استدعاء جميع خدمات المنصة، ولا حاجة إلى التقديم بشكل منفصل لكل خدمة.** سيُمنح رصيد مجاني عند التقديم لأول مرة، ويمكنك تجربته مجانًا؛ وعند عدم كفاية الرصيد، يمكنك شحن الرصيد العام في [وحدة التحكم](https://platform.acedata.cloud/console/coin).

## الاستخدام الأساسي

أي نوع من الأغاني تريد، يمكنك إدخال أي نص، على سبيل المثال إذا كنت أريد إنشاء أغنية عن عيد الميلاد، فيمكنني إدخال `a song for Christmas`، كما هو موضح في الصورة:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

يمكن رؤية أننا قمنا هنا بتعيين Request Headers، بما في ذلك:

- `accept`: صيغة نتيجة الاستجابة التي تريد تلقيها، وهنا يتم تعبئتها بـ `application/json`، أي صيغة JSON.
- `authorization`: مفتاح استدعاء API، ويمكنك الاختيار مباشرة من القائمة المنسدلة بعد التقديم.

كما قمنا أيضًا بتعيين Request Body، بما في ذلك:
- `action`: نوع مهمة الصوت، القيمة الافتراضية هي `generate`. يدعم عمليات مثل التوليد، والتمديد، وإعادة الغناء، والدمج، وفصل المسارات، وإضافة مسار صوتي، واستخراج مسار صوتي محدد، وتوليد المؤثرات الصوتية، وضبط السرعة، وغيرها، ويتم استدعاؤها جميعًا عبر `POST /suno/audios`.
- `prompt`: نص موجه وضع الإلهام الرسمي من Suno (يكون فعالًا عندما تكون `custom` هي `false`)، بحد أقصى 500 حرف.
- `model`: نموذج مهمة توليد الموسيقى هذه. تتضمن سلسلة v6 كلاً من `chirp-v6` و`chirp-v6-wild` و`chirp-v6-mini`؛ وتبقى أسماء النماذج القديمة متوافقة.
- `max_mode`: وضع التوليد المحسن. لا يتم تفعيل `generate` إلا عندما تكون كل من `custom` و`max_mode` بقيمة `true`، وتكون التكلفة 1.12 Credits؛ ويمكن تفعيل `add_stem` مباشرة، وتكون التكلفة 1.344 Credits. عند الإيقاف أو الحذف، تكون 0.56 و0.672 Credits على التوالي.
- `variety`: شدة تنوع نتائج التوليد، والخيارات هي `off` و`normal` و`high` و`extra` و`max`. يُستخدم فقط مع `generate` و`add_stem`، وسيؤدي تمريره إلى إجراءات action أخرى إلى إرجاع 400.
- `lyric`: محتوى كلمات الأغنية لوضع Suno الرسمي المخصص. الحد الأقصى لـ `chirp-v3-5` و`chirp-v4` هو 3000 حرف؛ ولـ `chirp-v4-5` وما بعده (بما في ذلك `chirp-v5` و`chirp-v5-5`) هو 5000 حرف.
- `custom`: ما إذا كان سيتم اعتماد الوضع المخصص، والقيمة الافتراضية هي: `false`.
- `instrumental`: خيار الموسيقى الآلية البحتة لوضع الإلهام الرسمي من Suno.
- `title`: عنوان الموسيقى لوضع Suno الرسمي المخصص. الحد الأقصى لـ `chirp-v3-5` و`chirp-v4` هو 80 حرفًا؛ ولـ `chirp-v4-5` وما بعده هو 100 حرف.
- `style`: نمط موسيقى Suno الرسمي للوضع المخصص. الحد الأقصى لـ `chirp-v3-5` و`chirp-v4` هو 200 حرف؛ ولـ `chirp-v4-5` وما بعده (بما في ذلك `chirp-v5` و`chirp-v5-5`) هو 1000 حرف.
- `negative_tags`: الأنماط أو الأنواع الموسيقية المراد استبعادها عند التوليد المخصص، ويمكن استخدامها أيضًا مع `replace_section`. لا تضع هذه الواجهة حاليًا حدًا ثابتًا لعدد الأحرف لهذا الحقل؛ وقد تظل المحتويات الطويلة جدًا غير قابلة للمعالجة، ويوصى بإبقاء الوصف موجزًا.
- `audio_weight`: وزن تأثير خصائص الصوت أو الصوت البشري، ضمن النطاق 0-1، وتعد `0` أيضًا قيمة صالحة. يمكن استخدامه لعمليات مثل التوليد، والتمديد، وإعادة الغناء، وإضافة مسار صوتي، واتساق الصوت؛ وعند عدم وجود صوت مرجعي أو خصائص صوتية، قد يضعف النموذج هذه القيمة أو يتجاهلها.
- `audio_id`: معرّف الموسيقى المرجعية، ويُستخدم للعمليات اللاحقة مثل إعادة الغناء، والتمديد، وفصل المسارات. يظل ملف الصوت قابلًا للتنزيل، لكن هذا لا يعني أن المعالجة اللاحقة لهذا المعرّف متاحة دائمًا؛ إذا تم إرجاع `suno_processing_unavailable`، فيرجى الاحتفاظ بـ `task_id` و`trace_id` والاتصال بالدعم.
- `overpainting_start`/`overpainting_end`: وقتا البدء والانتهاء لإضافة غناء إلى موسيقى آلية موجودة، بوحدة الثواني.
- `underpainting_start`/`underpainting_end`: وقتا البدء والانتهاء لإضافة مرافقة موسيقية إلى غناء بدون مرافقة، بوحدة الثواني.
- `persona_id`: معرّف الصوت الذي يتم الحصول عليه عبر واجهة إنشاء Persona أو الصوت، وليس `audio_id` للأغنية.
- `continue_at`: حد التمديد، بوحدة الثواني. على سبيل المثال، يشير 213.5 إلى بدء توليد المقطع اللاحق من الدقيقة 3 والثانية 33.5. يوجّه `lyric` و`style` المحتوى الجديد بعد الحد فقط، ولا يستبدلان الكلمات أو الغناء قبل الحد في الصوت المصدر.
- `style_influence`: قوة تأثير النمط في الوضع المخصص، ضمن النطاق 0-1، وكلما زادت، كان عادةً أكثر توافقًا مع النمط المختار؛ ويتم تمرير `0` كقيمة صالحة.
- `replace_section_end`: الوقت النهائي للمقطع المستبدل.
- `replace_section_start`: وقت بدء المقطع المستبدل.
- `vocal_gender`: يتحكم في تفضيل الصوت الأنثوي أو الذكوري، الصوت الأنثوي `f`، والصوت الذكوري `m`، ويكون فعالًا في نماذج 4.5 وما بعدها؛ وهو عنصر تفضيل ولا يضمن الالتزام الصارم.
- `weirdness`: درجة الغرابة في الوضع المخصص، ضمن النطاق 0-1، وكلما زادت، كان عادةً أكثر إبداعًا وتجريبية؛ ويتم تمرير `0` كقيمة صالحة.
- `duration`: مدة الأغنية المتوقعة، بوحدة الثواني، ويجب أن تكون عددًا صحيحًا، ضمن النطاق من 10 إلى 360. حاليًا، يستخدم `generate` فقط هذه المعلمة، ويعتمد التأثير المحدد على الوضع والنموذج. إنها إشارة تفضيلية وليست قيدًا صارمًا: سيرجع إليها النموذج، لكنه لا يضمن تحقيقها، وتكون مدة المنتج الفعلية وفقًا لحقل `duration` في الاستجابة، وعادةً ما تكون أقصر من القيمة المتوقعة.

### نطاق تطبيق معرّف الصوت

يمكن لـ `generate` و`cover` و`upload_cover` و`artist_consistency` و`artist_consistency_vox` استخدام `persona_id`. يجب أن يوفر الإجراءان الأخيران `persona_id`؛ ويمكن أيضًا توفير `audio_id` للأغنية المستخدمة عند إنشاء Persona في الوقت نفسه.

لا يستخدم `extend` و`upload_extend` أي `persona_id` إضافي. يعتمد دعم `mashup` و`inspo` لمعرّف الصوت على قناة الخدمة المختارة؛ ولا تضمن إجراءات action الأخرى تطبيق هذا الحقل، لذا يرجى استخدامه وفقًا لتعليمات كل عملية. إن `vocal_gender` تفضيل اختياري للجنس، ولا يمكن أن يحل محل معرّف الصوت.

تتطلب عمليات الإنشاء اللاحقة `audio_id` مصدرًا صالحًا؛ ويتطلب `mashup` وجود اثنين على الأقل من `mashup_audio_ids`. عند غياب المصدر الضروري أو معلمات الوقت، سيتم إرجاع HTTP 400.

تتحقق المنصة من أنواع المعلمات ونطاقات القيم، لكنها لن ترفض عناصر الضبط الاختيارية هذه لمجرد اختلاف `action`؛ ويعتمد التأثير المحدد على العملية والوضع والنموذج.

- `lyric_prompt`：prompt لتوليد كلمات الأغنية، ويكون فعالًا فقط عندما تكون `custom` بقيمة `true` ولا يتم تمرير `lyric`.
- `callback_url`：عنوان URL الذي يحتاج إلى استدعاء النتيجة.
- `async`：اختياري، عند ضبطه على `true` تُرجع الواجهة فورًا `task_id`، دون الحاجة إلى تقديم `callback_url`، ثم يتم الحصول على النتيجة عبر الاستعلام الدوري باستخدام واجهة الاستعلام المقابلة عن المهام.

## التوليد المخصص

## ميزة متابعة الإنشاء
إذا أردت متابعة إنشاء أغنية Suno تم إنشاؤها بالفعل، يمكنك ضبط المعلمة `action` إلى `extend`، وإدخال معرّف الأغنية التي تحتاج إلى متابعة إنشائها. يتم الحصول على معرّف الأغنية وفقًا للاستخدام الأساسي، ومن خلال ما سبق يمكن معرفة أنه في هذا الوقت يمكن رؤية أن معرّف الأغنية هو:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> ملاحظة، إن `id` في كلمات الأغاني هنا هو معرّف الأغنية بعد إنشائها. إذا كنت لا تعرف كيفية إنشاء أغنية، يمكنك الرجوع إلى الاستخدام الأساسي أعلاه لإنشاء أغنية.

إذا أردت متابعة إنشاء أغنية رفعتها بنفسك، يمكنك ضبط المعلمة `action` إلى `upload_extend`، وإدخال معرّف الأغنية المرفوعة المخصصة التي تحتاج إلى متابعة إنشائها. يتم الحصول على معرّف الأغنية باستخدام [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload)، كما هو موضح في الصورة التالية:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

بعد ذلك، يجب تعبئة كلمات مقطع المتابعة، ويمكن تحديد النمط:

- lyric: يُستخدم فقط لتوجيه كلمات المقطع المُنشأ حديثًا بعد `continue_at`، ولن يستبدل الكلمات الموجودة في الصوت المصدر قبل هذه النقطة الزمنية.
- custom: عند تعبئته بالقيمة `true`، فإنه يعني إنشاءً مخصصًا. القيمة الافتراضية لهذه المعلمة هي false، ما يعني استخدام `prompt` للإنشاء.
- style: نمط أغنية مقطع المتابعة، اختياري.
- continue_at: حد المتابعة، بوحدة الثواني. على سبيل المثال، تشير 213.5 إلى بدء إنشاء المقطع اللاحق من الدقيقة 3 والثانية 33.5.

يجب أن تكون قيمة `continue_at` لكل من `extend` و`upload_extend` أكبر من 0، وهي تدعم الثواني العشرية، مثل `30.792`؛ ولن يتم تقريبها عند الإرسال.

> يُستخدم `extend` لمواصلة الإبداع بعد أغنية موجودة، وليس لتغيير كلمات الأغنية كاملة. إذا كنت تريد استخدام كلمات جديدة للأغنية بأكملها من البداية، فيرجى استخدام `generate` لإعادة الإنشاء؛ وإذا كنت تريد إعادة أداء الأغنية بالاستناد إلى أغنية موجودة، يمكنك استخدام `cover`. عند تمرير كلمات جديدة لأغنية كاملة، فلن يتم استبدال الكلمات الأصلية قبل `continue_at` أيضًا.

مثال على التعبئة كما يلي:

<p><img src="https://cdn.acedata.cloud/zp9s42.png" width="500" className="m-auto" /></p>

ما يلي هو لقطة حقيقية لاستدعاء سابق محفوظ، حيث تكون قيمة `continue_at` هي ثانيتين، لذلك فإن أول ثانيتين فقط تنتميان إلى المحتوى الأصلي قبل حد المتابعة. عند المتابعة الفعلية بالقرب من نهاية الأغنية، يجب ضبط هذه القيمة على الثانية التي ترغب في بدء المتابعة منها، وتقديم المقطع الجديد المراد غناؤه بعد الحد فقط في `lyric`.

    "custom": True,

## إعادة إنتاج الموسيقى

عند متابعة إنشاء أغنية استنادًا إلى أغنية موجودة، قد لا يكون أسلوب الأغنية المُعادة مناسبًا. إذا أردت إعادة إنتاج الأغنية التي أُنشئت سابقًا (كما يتم دعم الموسيقى المرفوعة مخصصًا أيضًا)، فيجب استخدام طريقة إعادة إنتاج الموسيقى، ويمكنك تحديد المحتوى التالي:

- action：المحتوى هو `cover`، وعند إجراء إعادة إنتاج للموسيقى المرفوعة مخصصًا، يجب تحديد المحتوى كالتالي: `upload_cover`。
- audio_id：معرّف الأغنية التي تم إنشاؤها سابقًا.

إذا كنت بحاجة إلى الغناء بصوت محدد، فيمكنك أيضًا تمرير `persona_id`. يجب أولًا رفع الأغنية الأصلية في `/suno/upload` باستخدام `persona_id` نفسه للصوت الخاص الذي أُنشئ عبر `/suno/voices`، ثم استخدام `audio_id` المُعاد لإجراء `upload_cover`. يجب أن تستخدم كل الخطوات قناة الخدمة نفسها. لا حاجة إلى تحديد `vocal_gender` إضافيًا، إذ لا يمكن لتفضيل الجنس أن يحل محل معرّف الصوت.

على سبيل المثال، إذا كان معرّف الأغنية التي تم إنشاؤها سابقًا هو: 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98، فيمكنك ضبط المعلمات كما يلي:

```json
{
  "action": "cover",
  "audio_id": "0a1e1b10-c36a-41c9-9bfb-b26d9d25db98",
  "prompt": "A song for Christmas",
  "model": "chirp-v4-5"
}
```

## استبدال المقاطع

عندما تحتاج، بعد إنشاء أغنية، إلى إجراء إبداع ثانوي يتضمن استبدال مقطع من الأغنية بشكل منفصل، يمكنك إجراء عملية استبدال لمقطع معين من الأغنية.
> ⚠️ **ملاحظة**: القيمة الافتراضية لـ `replace_section_result_mode` هي `full_song`: سيقوم النظام بدمج مرشحين مولّدين حديثًا على حدة، وإرجاع أغنيتين كاملتين. إذا كنت تحتاج فقط إلى مرشحي مقاطع الاستبدال التي لم تُدمج بعد، فيُرجى تعيينها صراحةً إلى `candidates`، ثم اختيار المرشح لاستدعاء [دمج الموسيقى](#音乐拼接).

وصف المعلمات كما يلي:

- action: المحتوى هو `replace_section`.
- audio_id: معرّف الأغنية الأصلية (الأغنية المصدر التي سيتم استبدالها).
- model: نموذج توليد الأغاني.
- lyric: الكلمات الكاملة بعد الاستبدال (بما في ذلك المقطع المستبدل وسياقه، مع الحفاظ على الاتساق مع المحتوى في `prompt`).
- prompt: الكلمات الجديدة لذلك المقطع الذي يحتاج إلى استبدال.
- style: نمط الأغنية، اختياري.
- negative_tags: الأنماط أو التصنيفات التي ترغب في استبعادها، اختياري.
- replace_section_start: وقت بداية المقطع المستبدل في الأغنية الأصلية (بالثواني)، مطلوب ويجب ألا يكون أقل من 0.
- replace_section_end: وقت نهاية المقطع المستبدل في الأغنية الأصلية (بالثواني)، مطلوب ويجب أن يكون أكبر من وقت البداية.
- replace_section_result_mode: وضع الإرجاع، والقيمة الافتراضية هي `full_song`. يقوم `full_song` بدمج المرشحين الاثنين على حدة وإرجاع أغنيتين كاملتين؛ ويقوم `candidates` بإرجاع مقطعين مرشحين لم يتم دمجهما بعد.

## التحكم في مدة الأغنية

افتراضيًا، يتم تحديد مدة الأغنية المُنشأة بواسطة النموذج نفسه، وعادةً ما تكون بين 30 ثانية و4 دقائق. إذا كانت هناك حاجة إلى منتج أطول أو أقصر، فيمكن تحديد المدة المتوقعة عبر المعلمة `duration`، ووحدتها الثانية، وقيمتها عدد صحيح بين 10 و360.

تُستخدم هذه المعلمة لإنشاء الأغاني في الوضع المخصص (حيث تكون `custom` بقيمة `true`). وتجدر الإشارة بشكل خاص إلى أن `duration` هو **تلميح توجهي وليس قيدًا صارمًا**: سيرجع النموذج إلى هذه القيمة أثناء الإنشاء، لكنه لا يضمن تحقيقها. في الاختبارات الفعلية، تكون المدة الفعلية عادةً أقصر بشكل واضح من القيمة المتوقعة، وقد تختلف مدة الأغنيتين اللتين يتم إرجاعهما من الطلب نفسه عدة مرات. حتى مع الطلبات المتطابقة تمامًا، قد تختلف المدد الناتجة من عمليات الإرسال المتعددة بشكل كبير. لذلك لا تستخدمها كتحكم دقيق في المدة؛ وإذا كانت هناك حاجة إلى مدة ثابتة من ناحية العمل، فقم بقص المنتج بنفسك أو أعد المحاولة بعد الحصول عليه.

كود Python المقابل:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

يجب ملاحظة أن `duration` في الطلب هي **المدة المتوقعة**، بينما حقل `duration` لكل أغنية في `data` ضمن الاستجابة هو **المدة الفعلية** لتلك الأغنية. لهما الاسم نفسه لكن المعنى مختلف، ولا يُضمن أن تساوي المدة الفعلية القيمة المتوقعة. يعد طول كلمات الأغنية أحد العوامل الرئيسية المؤثرة في مدة المنتج، وإذا كانت هناك حاجة إلى منتج أطول، فمن المستحسن تقديم كلمات أكثر اكتمالًا في الوقت نفسه.

ستتحقق الواجهة من أن `duration` عدد صحيح بين 10 و360؛ وهي تظل مجرد هدف للتوليد، وليست ضمانًا لطول المنتج.

## ميزة الإبداع بالإلهام Inspo

يمكن لميزة الإبداع بالإلهام Inspo إنشاء موسيقى جديدة بناءً على مقطع إلى 4 مقاطع صوتية مرجعية كاملة، وتدعم سحب الملفات الصوتية أو رفعها كمصادر للإلهام. تستخدم واجهة API الإجراء الحالي `inspo`: يوفّر العميل عنوان URL للصوت المتاح للعامة، وستُكمل الخدمة تلقائيًا إعداد الصوت المرجعي والإبداع، دون حاجة العميل إلى قراءة الكلمات أو النمط أو المدة بشكل منفصل ثم تجميع الطلب. وهي تختلف عن أخذ العيّنات ضمن نطاق المذكور أعلاه، كما تختلف عن Cover الذي يعيد إنتاج نمط الأغنية الأصلية. عند الاستخدام، يجب تعبئة المعلمات التالية:

- action: تكون القيمة `inspo`.
- audio_urls: قائمة بعناوين URL للصوت المرجعي، ويجب توفير عنوان صوتي متاح للعامة واحد إلى 4 عناوين.
- model: النموذج المستخدم، ويُوصى بـ `chirp-v6`.
- prompt: كلمات الأغنية أو نص توجيهي للإبداع (اختياري).
- instrumental: عند ضبطه على `true`، يتم التوليد بناءً على طلب موسيقى آلية خالصة، دون استخدام كلمات.
- persona_id: استخدام الصوت المحدد في قناة الخدمة التي تدعم هذه المجموعة؛ وسيتم ربط الصوت المرجعي أثناء مرحلة الإعداد ببيئة الموارد المطلوبة لذلك الصوت.
- lyric_prompt: عند `custom=true` وعدم توفير `lyric`، يُستخدم لتوليد كلمات الأغنية تلقائيًا.

> ملاحظة: يجب أن يكون الصوت المرجعي ملفًا صوتيًا متاحًا للعامة. إذا تطابق الصوت المرجعي تمامًا مع تسجيل معروف في مكتبة المنصة الموسيقية، فقد يرفض Suno التوليد بسبب التحقق من حقوق النشر، ويُنصح باستخدام صوت مملوك لك أو صوت تم توليده بواسطة Suno كمصدر للإلهام.

كود Python المقابل:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## الاستدعاء غير المتزامن

نظرًا إلى أن الوقت الذي يستغرقه Suno لإنشاء الموسيقى طويل نسبيًا، إذ يحتاج تقريبًا إلى 1-2 دقيقة، فإذا لم تستجب API لفترة طويلة، فسيبقى طلب HTTP متصلًا باستمرار، مما يؤدي إلى استهلاك موارد إضافية للنظام، لذلك توفر API هذه أيضًا دعمًا للاستدعاء غير المتزامن.

التدفق العام هو: عند قيام العميل بإرسال طلب، يتم تحديد حقل إضافي باسم `callback_url`، وبعد أن يرسل العميل طلب API، ستُعيد API نتيجة فورًا تتضمن معلومات حقل `task_id`، والذي يمثل معرّف المهمة الحالية. عند اكتمال المهمة، سيتم إرسال نتيجة إنشاء الموسيقى بصيغة POST JSON إلى `callback_url` الذي حدده العميل، ويتضمن ذلك أيضًا حقل `task_id`، وبهذه الطريقة يمكن ربط نتائج المهمة من خلال المعرّف.

فيما يلي، سنتعرف من خلال مثال على كيفية تنفيذ ذلك بالتحديد.
