---
title: "واجهة API للتحقق من توفر صوت Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

يبحث `POST /suno/availability`، استنادًا إلى `audio_id`، عن دليل إيجابي على إمكانية مواصلة معالجة الصوت على المسار الحالي. يمكن استدعاؤه قبل عمليات مثل المتابعة أو إعادة الغناء؛ وتعكس النتيجة الحالة وقت الفحص فقط، ولا تضمن نجاح عملية محددة. تُرجع هذه الواجهة النتيجة بشكل متزامن، وتتطلب API Token، ولا تخصم Credits حاليًا.

`audio_id` هو معرّف الأغنية الذي تُرجعه مهمة Suno مكتملة، وليس `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

مثال على استجابة ناجحة:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

عند نجاح الفحص، تكون قيمة `data.available` هي `true`؛ وعند تعذر التأكيد، تُرجع `503 availability_unknown` ولا تُرجع `false`. يؤدي تنسيق `audio_id` غير الصحيح إلى إرجاع 400، كما تُرجع قيود المعدل أو أعطال الخدمة استجابة خطأ أيضًا. قد تتغير الحالة بين اكتمال الفحص وتنفيذ العملية الفعلية.
