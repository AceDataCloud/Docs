يقبل `POST /suno/availability` معرّف مورد. للاستعلام عن أغنية مرّر `audio_id`، وللاستعلام عن بصمة صوتية مرّر `persona_id`، ويجب توفير أحدهما. يكتمل التحقق بشكل متزامن، ويتطلب API Token، ولا يخصم Credits حاليًا.

## الطلب

يأتي `audio_id` من مهمة أغنية مكتملة، ويمكن استخدامه للتحقق قبل المتابعة أو إعادة الغناء.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

يأتي `persona_id` من نتيجة إنشاء البصمة الصوتية. باستخدام التطبيق الأصلي وهوية المستدعي، أرسل نص الطلب التالي على مسار الإنشاء الذي يدعم الاستعلام عن البصمة الصوتية.

```json
{"persona_id":"33333333-3333-4333-8333-333333333333"}
```

## الاستجابة

يستخدم نوعا الطلبات نفس استجابة النجاح. `data.id` هو معرّف المورد لهذا الاستعلام.

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

يشير `available: true` إلى أن هذا التحقق حصل على دليل إيجابي. بالنسبة للبصمات الصوتية، يتحقق الفحص من ملكية الإنشاء، ويؤكد أن الحساب المرتبط يُبلّغ عنه حاليًا كمتصل. تظل نتائج الإنشاء الفعلية خاضعة لمهمة الإنشاء.

تعتمد البصمات الصوتية الخاصة المستنسخة التي أُنشئت عبر `/suno/voices` على حساب الإنشاء. عند تأكيد أن هذا الحساب غير متصل حاليًا، تعيد الواجهة HTTP 200، ويكون مثال `data` كما يلي.

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

يمكن للعميل وضع علامة على هذه البصمة الصوتية باعتبارها غير متاحة حاليًا، ثم الاستعلام مجددًا لاحقًا.

عند تعذر التأكيد، تعيد الواجهة HTTP 503 و`availability_unknown`، مثلًا عند عدم العثور على المورد، أو افتقار السجلات القديمة إلى مسار الإنشاء، أو انتهاء مهلة الاستعلام. يمكن استخدام أنماط المغنين العامة عبر الحسابات، وعند كون حساب الإنشاء غير متصل، تعيد أيضًا 503. لا تعيد استعلامات الأغاني `available: true` إلا عند تأكيد توفرها.

يرسل كل طلب UUID صالحًا واحدًا فقط. تعيد جميع المسارات HTTP 400 عند تلقي طلب يحتوي على كلا المعرّفين أو يفتقد كلا المعرّفين. تعيد المسارات التي تدعم استعلامات الأغاني فقط HTTP 400 عند تلقي طلب يحتوي على `persona_id` فقط. عند مواجهة HTTP 429، يرجى تقليل تكرار الاستعلامات.
