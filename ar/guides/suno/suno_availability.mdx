---
title: "واجهة برمجة تطبيقات التحقق من توفر صوت Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` تبحث بناءً على `audio_id` عن أدلة إيجابية تفيد بأن الصوت يمكن متابعة معالجته على المسار الحالي. يمكن استدعاؤها قبل عمليات مثل المتابعة الكتابية وإعادة الغناء؛ وتعكس النتيجة الحالة وقت الفحص فقط، ولا تضمن بالضرورة نجاح عملية محددة. تُرجع هذه الواجهة النتيجة بشكل متزامن، وتتطلب API Token، ولا تخصم Credits حاليًا.

`audio_id` هو معرّف الأغنية الذي تُرجعه مهمة Suno المكتملة، وليس `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

مثال على استجابة ناجحة:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

عند نجاح الفحص، لن تكون قيمة `data.available` سوى `true`. إن حالة «غير متصل» التي تُرجعها بعض المسارات لا يمكن أن تثبت أن عمليات لاحقة مثل المتابعة الكتابية لا يمكن أن تنجح، لذلك تُرجع هذه الواجهة `503 availability_unknown` عند تعذر التأكد، ولن تُرجع `false`. يؤدي خطأ في تنسيق `audio_id` إلى إرجاع 400، كما تُرجع أخطاء أيضًا عند تقييد المعدل أو تعطل الخدمة المصدر. قد تتغير الحالة أيضًا بين اكتمال الفحص وتنفيذ العملية الفعلية.
