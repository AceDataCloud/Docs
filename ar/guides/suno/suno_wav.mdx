تتيح لنا SUNO الحصول على ملفات الموسيقى بصيغة wav، يشرح هذا المستند طريقة تكامل واجهة برمجة التطبيقات ذات الصلة.

المعامل الأساسي لهذه الواجهة هو `audio_id`، وهو معرف الأغنية الذي تم إنشاؤه رسميًا؛ كما يدعم اختياريًا عنوان `callback_url` للاستدعاء غير المتزامن.

هنا نستخدم `audio_id` بقيمة `4e43116a-bf09-472c-8e1c-655eabf02682`.

```python
import requests

url = "https://api.acedata.cloud/suno/wav"

headers = {
    "accept": "application/json",
    "authorization": "Bearer aa287fa4cc54401087a9fab3f99630af",
    "content-type": "application/json"
}

payload = {
    "audio_id": "4e43116a-bf09-472c-8e1c-655eabf02682"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

النتيجة كما يلي:

```json
{
  "success": true,
  "task_id": "6a5a2099-d6d3-4930-9709-a30ac5dc7de5",
  "trace_id": "3fa70e81-6bb7-4ca8-b718-dd16a4eda7e8",
  "data": [
    {
      "file_url": "https://platform.cdn.acedata.cloud/suno/6a5a2099-d6d3-4930-9709-a30ac5dc7de5.wav"
    }
  ]
}
```

يمكننا ملاحظة أن حقل `file_url` ضمن `data` هو ملف الموسيقى بصيغة wav الذي تم الحصول عليه، وهو عنوان CDN يمكن الوصول إليه علنًا.

> **حول استمرارية رابط WAV**
>
> ملفات WAV على CDN الخاص بـ Suno الأصلي (`https://cdn1.suno.ai/{audio_id}.wav`) تُحتفظ بها لبضعة أيام فقط، وبعدها يتم حذفها، وعند الوصول إليها يتم إرجاع رمز 403.
> لتجنب انتهاء صلاحية الرابط، تقوم هذه الواجهة تلقائيًا قبل الإرجاع بنسخ ملف WAV الأصلي إلى CDN الخاص بنا (`https://platform.cdn.acedata.cloud/suno/{task_id}.wav`)، والرابط `file_url` الذي يتم إرجاعه هو العنوان المستقر بعد النسخ، ولن ينتهي صلاحيته بسبب انتهاء صلاحية CDN الأصلي.
> في حالة فشل النسخ (وهو أمر نادر جدًا)، سيتم الرجوع إلى رابط المصدر الأصلي، مما يحافظ على السلوك كما في السابق.
