`POST https://api.acedata.cloud/webextrator/extract`

A API de extração inteligente WebExtrator transforma uma URL em **resultados estruturados tipados** — artigos, produtos,
receitas, vídeos, discussões, vagas e muito mais — acompanhados de Markdown limpo e texto simples. Use esta interface quando quiser "dados estruturados limpos" em vez de HTML bruto.

## Processo de Solicitação

Para usar a página de serviços WebExtrator, primeiro acesse o [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu Token de API, que deve ser guardado.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver logado ou registrado, será redirecionado automaticamente para a página de login, convidando-o a se registrar e logar; após a conclusão, você será redirecionado de volta para a página atual.

**Um Token de API é suficiente para acessar todos os serviços da plataforma, não sendo necessário solicitar individualmente para cada serviço.** A primeira solicitação oferece um crédito gratuito, permitindo uma experiência sem custo; quando o crédito estiver baixo, você pode recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Página de serviços WebExtrator →](https://platform.acedata.cloud/service/webextrator)

## Autenticação

```
Authorization: Bearer YOUR_API_KEY
Content-Type:  application/json
```

## Parâmetros da solicitação

O Extract aceita **todos** os parâmetros da [API Render](/pt/guides/webextrator/webextrator_render)
（`url`、`user_agent`、`timeout`、`wait_until`、`delay`、`wait_for_selector`、
`block_resources`、`headers`、`cookies`、`callback_url`、`bypass_cache`、
`cache_ttl_seconds`、`async`），além de dois campos exclusivos do Extract:

| Campo | Tipo | Obrigatório | Padrão | Descrição |
|------|------|:----:|------|------|
| `expected_type` | enum | ❌ | Detecção automática | Dica de tipo de página: `product` / `article` / `general`. Especifique o tipo de resultado esperado. |
| `enable_llm` | boolean | ❌ | `false` | Permite chamar o LLM para extração quando schema.org não for encontrado. Em páginas sem JSON-LD, como Amazon / HN / Greenhouse, é necessário ativá-lo para obter resultados tipificados. |

### Campos de nível superior

| Campo | Tipo | Descrição |
|------|------|------|
| `kind` | string | Sempre `"extract"`. |
| `url` | string | A URL enviada por você. |
| `finalUrl` | string | A URL final após os redirecionamentos. |
| `contentType` | enum | Tipo de página: `product` / `article` / `general`. |
| `title` | string | Título da página. |
| `description` | string? | Descrição ou resumo da página. |
| `byline` | string? | Autor, canal ou empresa. |
| `language` | string? | `<html lang>`.  |
| `siteName` | string? | `og:site_name`.  |
| `publishedAt` | string? | Data de publicação, no formato ISO 8601. |
| `images` | string[] | Até 50 `<img src />`, resolvidos como URLs absolutas, sem duplicatas e descartando URIs `data:`. |
| `links` | string[] | Até 100 links externos, com fragmentos / `javascript:` / `mailto:` / `tel:` filtrados. |
| `markdown` | string | Conteúdo Markdown da página. |
| `text` | string | Texto simples da página. |
| `structured` | object | Resultado estruturado completo; veja abaixo. |
| `rawSignals` | object | Informações de diagnóstico para depuração. |
| `cached` | boolean? | `true` quando houver acerto no cache. |
| `cacheStoredAt` | number? | Carimbo de data/hora Unix em milissegundos da primeira gravação da entrada no cache. |

### Subcampos de `data.structured`

| Subcampo | Quando aparece | Descrição |
|--------|---------|------|
| `schemaOrg` | Sempre | `{ primary, breadcrumbs, all }`. `primary` é a entidade tipada de maior prioridade; se não for encontrada, será `null`. |
| `openGraph` | Sempre | `{ title, description, image, type }`, proveniente de `<meta property="og:*" />`. |
| `jsonLd` | Sempre | Array JSON bruto de todos os blocos `<script type="application/ld+json">`. |
| `llm` | Quando o LLM é executado e tem êxito | `{ kind, data, model, promptCharCount }`, resultado tipado. |
| `llmError` | Quando o LLM é executado, mas falha | `{ kind, error, model }`, a solicitação ainda pode retornar outros campos extraídos. |
| `amazon` | Quando a URL é `amazon.*` | Resultado da extensão legada da Amazon; para novas integrações, use resultados tipados. |

## Tipos de resultado schema.org

`structured.schemaOrg.primary` oferece suporte aos seguintes tipos de resultado:

| Tipo schema.org | kind | Campo de saída |
|----------------|----------|----------|
| `Product` | product | `name, sku, gtin, model, color, brand, url, images, offer.{price,currency,availability,condition,seller}, rating.{value,count}, reviews[], properties[]` |
| `Recipe` | recipe | `name, description, image, datePublished, author, cookTime, prepTime, totalTime, recipeYield, ingredients[], instructions[], nutrition, rating, keywords, recipeCategory, recipeCuisine` |
| `VideoObject` | video | `name, description, thumbnailUrl, uploadDate, duration, embedUrl, contentUrl, channel, interactionCount` |
| `JobPosting` | job | `title, description, datePosted, validThrough, hiringOrganization, jobLocation, baseSalary, employmentType` |
| `Event` (incluindo `*Event`) | event | `name, description, startDate, endDate, location.{name,address}, organizer, offer.{url,price,currency}` |
| `Article` / `NewsArticle` / `BlogPosting` / `ScholarlyArticle` / `TechArticle` / `Report` / `*NewsArticle` | article | `subtype, headline, description, datePublished, dateModified, author, publisher, image[], url, sameAs[]` |
| `FAQPage` | faq | `questions[{question, answer}]` |
| `BreadcrumbList` | (anexado a sibling) | Sempre é enviado para `structured.schemaOrg.breadcrumbs[]` e não será usado como primary. |

## Tipos de resultado de LLM

Quando `enable_llm: true` e a página não possui dados estruturados schema.org disponíveis, os seguintes tipos de resultados de extração podem ser retornados:

| Kind | Campos obrigatórios | Campos opcionais |
|------|---------|---------|
| `article` | `headline` | `description, byline, publishedAt, language, topics[], sections[{heading,summary}]` |
| `product` | `name` | `description, brand, sku, price, currency, availability, rating.{value,count}, bullets[], specifications[{name,value}]` |
| `discussion` | `title` | `author, postedAt, points, commentCount, body, url` |
| `recipe` | `name` | `description, author, cookTime, prepTime, totalTime, recipeYield, ingredients[], instructions[], nutrition, rating, keywords[]` |
| `video` | `name` | `description, channel, uploadDate, duration, viewCount, likeCount, thumbnailUrl, transcript` |
| `job` | `title` | `description, company, location, remote, employmentType, datePosted, validThrough, salaryMin, salaryMax, salaryCurrency, salaryPeriod, responsibilities[], qualifications[]` |

## Cache

A mesma URL, os parâmetros da solicitação, `cookies` e `headers` podem reutilizar resultados em cache; `async`, `bypass_cache` e `cache_ttl_seconds` são usados para controlar o modo de execução e o comportamento do cache.

| Campo | Efeito |
|------|------|
| `bypass_cache: true` | Pula a leitura; o resultado desta vez ainda será gravado no cache, e uma solicitação idêntica poderá acertá-lo na próxima vez. |
| `cache_ttl_seconds: 0` | Esta resposta **não será armazenada em cache**. |
| `cache_ttl_seconds: N` | Personalize o TTL desta entrada (padrão: 3600 segundos). |

As respostas encontradas no cache incluirão `data.cached: true` e `data.cacheStoredAt: <unix-ms>`.

## Modo assíncrono e callbacks

Defina `async: true` para entrar no modo assíncrono (fornecer `callback_url` também fará a transição automaticamente). A plataforma retorna imediatamente (HTTP 200):

```json
{
  "success": true,
  "task_id": "550e8400-...",
  "trace_id": "6ba7b810-...",
  "started_at": 1777717800.123
}
```

Quando a tarefa for concluída, o envelope completo será enviado via `POST` para seu `callback_url` (se configurado). Você também pode consultar ativamente através de [`/webextrator/tasks`](/pt/guides/webextrator/webextrator_tasks).

```bash

  -H "Authorization: Bearer $API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "url": "https://en.wikipedia.org/wiki/Diffbot",
    "expected_type": "article"
```

### Python (requests)

```python
import os, requests

API_KEY = os.environ["ACEDATA_API_KEY"]

resp = requests.post(
    "https://api.acedata.cloud/webextrator/extract",
    headers={
        "Authorization": f"Bearer {API_KEY}",
        "Content-Type": "application/json",
    },
    json={
        "url": "https://en.wikipedia.org/wiki/Diffbot",
        "expected_type": "article",
    },
    timeout=120,
)
resp.raise_for_status()
data = resp.json()["data"]

primary = (data.get("structured") or {}).get("schemaOrg", {}).get("primary")
print("contentType:", data["contentType"])
print("title:      ", data["title"])
print("byline:     ", data.get("byline"))
print("publishedAt:", data.get("publishedAt"))
if primary and primary["kind"] == "article":
    print("headline:    ", primary["headline"])
    print("dateModified:", primary.get("dateModified"))
```

### Node.js (fetch)

```js
const apiKey = process.env.ACEDATA_API_KEY;

const res = await fetch('https://api.acedata.cloud/webextrator/extract', {
  method: 'POST',
  headers: {
    Authorization: `Bearer ${apiKey}`,
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    url: 'https://www.allrecipes.com/recipe/16354/easy-meatloaf/',
  }),
});
const { data } = await res.json();
const recipe = data?.structured?.schemaOrg?.primary;
console.log(recipe.name, recipe.cookTime, recipe.ingredients.length, 'tipos de ingredientes');
```

## Dicas e armadilhas

- **Passe `expected_type` quando precisar especificar o tipo de página.** Por exemplo, use `article` para páginas de artigos e `product` para páginas de produtos.
- **`enable_llm: true` é gratuito em páginas com correspondência no schema.org.** O LLM só é chamado quando o schema.org
  não possui um primary, portanto é seguro mantê-lo ativado por padrão.
- **Durante a depuração, verifique primeiro `rawSignals.hasJsonLd`.** Se for `true`, mas `structured.schemaOrg.primary`
  for `null`, isso indica que o `@type` da página ainda não é compatível; envie-nos seu feedback.
- **`structured.llmError` é informativo.** A solicitação ainda pode retornar com êxito outros campos extraídos. Consulte
  `llmError.error` para identificar a causa (tempo esgotado, falha ao analisar JSON, falha na validação da estrutura).
- **`links[]` para páginas que não são de artigos não realiza classificação por relevância.** Apenas faz uma limpeza de melhor esforço com base em "limite de 100 itens + filtragem de protocolos inválidos"
  .
- **Acertos no cache também são cobrados.**
