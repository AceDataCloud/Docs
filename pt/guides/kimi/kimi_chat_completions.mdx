Kimi é uma série de modelos de IA lançada pela Moonshot AI. Atualmente, recomenda-se `kimi-k3.1-pro`, adequado para programação de longo prazo, raciocínio complexo, compreensão visual e trabalhos relacionados ao conhecimento; `kimi-k3` continua disponível. A chamada é realizada por meio da API Chat Completions compatível com OpenAI.

Este documento apresenta principalmente o processo de utilização da API Kimi Chat Completion, por meio da qual podemos utilizar facilmente a funcionalidade oficial de conversação do Kimi.

## Modelos suportados

Atualmente, são suportados quatro modelos: `kimi-k3.1-pro`, `kimi-k3`, `kimi-k2.6` e `kimi-k2.7-code`. O K2.7 Code é voltado para cenários de programação e chamadas de ferramentas, com preços equivalentes aos do K2.6; não passe a opção `thinking` nem `reasoning_effort` nas solicitações. Os demais modelos Kimi deixaram de ser suportados. Selecione explicitamente um desses quatro modelos no cliente.

## Processo de solicitação

Para utilizar a API Kimi Chat Completion, primeiro acesse o [painel de controle do Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e guardá-lo para uso posterior.

![]()

Se você ainda não tiver iniciado sessão ou registrado uma conta, será redirecionado automaticamente para a página de login, onde poderá se registrar e entrar. Após concluir o processo, você retornará automaticamente à página atual.

**Um único API Token permite chamar todos os serviços da plataforma, sem necessidade de solicitar um token separadamente para cada serviço.** Na primeira solicitação, você receberá uma quantidade gratuita de créditos para experimentar o serviço sem custos; quando os créditos forem insuficientes, você poderá adicionar saldo geral no [painel de controle](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Utilização básica

Em seguida, você poderá preencher os campos correspondentes na interface, conforme mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

Na primeira utilização desta interface, é necessário preencher pelo menos três campos: `authorization` pode ser selecionado diretamente na lista suspensa; `model` é utilizado para selecionar o modelo Kimi, sendo recomendado `kimi-k3.1-pro`; `messages` é um array de mensagens da conversa, no qual cada mensagem contém `role` e `content`, sendo que `role` suporta `user`, `assistant`, `system` e `tool`.

Ao mesmo tempo, você pode observar que, no lado direito, há a geração do código correspondente à chamada. Você pode copiar o código e executá-lo diretamente ou clicar no botão «Try» para realizar um teste.

O resultado retornado contém vários campos, apresentados a seguir:

- `model `: o modelo selecionado no site oficial do Kimi.
- `choices`: as informações da resposta fornecida pelo Kimi à pergunta.
- `usage `: as informações estatísticas sobre os tokens utilizados nesta sessão de perguntas e respostas.

Entre eles, `choices` contém as informações da resposta do Kimi. Dentro dele, `choices` contém as informações específicas da resposta do Kimi, conforme mostrado na imagem.

Como podemos observar, o campo `content` dentro de `choices` contém o conteúdo específico da resposta do Kimi; o K3 também pode retornar `reasoning_content`, utilizado para representar o processo de raciocínio.

## Intensidade de raciocínio do K3.1 Pro

`kimi-k3.1-pro` mantém o raciocínio sempre ativado. É possível definir `reasoning_effort` no nível superior do corpo da solicitação como `low`, `high` ou `max`; não envie configurações para desativar o raciocínio. O modelo suporta um contexto de até 1.048.576 tokens, mas o limite real de cada solicitação ainda depende da interface atual. O preço é calculado com base no uso de tokens de entrada, saída e acertos de cache. Consulte o cartão Pricing no catálogo de modelos para obter mais detalhes.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

O exemplo do K3 abaixo foi mantido para integrações existentes, e a resposta de exemplo foi realmente obtida por meio de uma solicitação ao K3.

## Intensidade de raciocínio do K3

`kimi-k3` mantém o raciocínio sempre ativado. O campo `reasoning_effort` é suportado no nível superior do corpo da solicitação, e o único valor atualmente suportado é `max`; quando esse campo é omitido, também é utilizado `max`. Utilize os valores suportados.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

Ao utilizar o SDK da OpenAI, você pode passar esse campo diretamente:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

Em conversas com várias rodadas e chamadas de ferramentas, envie novamente a mensagem completa do assistant da rodada anterior em `messages`, incluindo `reasoning_content` e `tool_calls`.

### Referências oficiais

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort): explica que o Kimi K3 mantém o raciocínio sempre ativado e que o único valor atualmente suportado para `reasoning_effort` é `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview): compara as diferenças entre os parâmetros de raciocínio, as janelas de contexto e as chamadas de ferramentas das séries K3 e K2.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat): definições oficiais da Moonshot para as solicitações, respostas e campos OpenAPI do Chat Completions.

## Resposta em fluxo contínuo

Esta interface também suporta respostas em fluxo contínuo, o que é muito útil para integrações com páginas da web, permitindo que a página apresente o efeito de exibição gradual de caracteres.

Se você quiser retornar respostas em fluxo contínuo, poderá alterar o parâmetro `stream ` no cabeçalho da solicitação para `true`.

Faça a alteração conforme mostrado na imagem. No entanto, o código de chamada também precisa ser modificado de maneira correspondente para oferecer suporte às respostas em fluxo contínuo.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>
Após modificar `stream` para `true`, a API retornará os dados JSON correspondentes linha por linha. No nível do código, precisamos fazer as modificações correspondentes para obter os resultados linha por linha.

Código de exemplo de chamada em Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Abaixo estão alguns blocos de dados iniciais, de raciocínio, de conteúdo principal, de encerramento e de utilização, extraídos de uma resposta real em fluxo contínuo do K3 Max na mesma solicitação:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Como podemos ver, há muitos `data` na resposta, e os `choices` dentro de `data` correspondem ao conteúdo mais recente da resposta, em conformidade com o conteúdo apresentado acima. `choices` contém o novo conteúdo da resposta, que pode ser integrado ao seu sistema de acordo com o resultado. Ao mesmo tempo, o fim da resposta em fluxo contínuo é determinado pelo conteúdo de `data`. Se o conteúdo for `[DONE]`, isso significa que a resposta em fluxo contínuo foi completamente concluída. Os dados `data` retornados contêm vários campos, descritos a seguir:

- `id`, o ID gerado para esta tarefa de conversa, utilizado para identificá-la exclusivamente.
- `model `, o modelo selecionado no site oficial do Kimi.
- `choices`, as informações de resposta fornecidas pelo Kimi à solicitação.

JavaScript também é compatível. Por exemplo, o código de chamada em fluxo contínuo do Node.js é o seguinte:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Código de exemplo em Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Para outras linguagens, você pode fazer as adaptações por conta própria. O princípio é o mesmo.

## Conversas com múltiplas interações

Se você quiser integrar a funcionalidade de conversas com múltiplas interações, precisará enviar várias mensagens no campo `messages`. Um exemplo específico de várias mensagens é apresentado na imagem abaixo:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Código de exemplo de chamada em Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Ao enviar várias mensagens, você pode implementar facilmente conversas com múltiplas interações. A seguir está a resposta real do K3 Max obtida por essa solicitação (os campos de extensão não utilizados foram omitidos):

```json
{
  "id": "msg_Rqp8nPGBDHWwBlL4VpxuafOp",
  "object": "chat.completion",
  "created": 1784466628,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "I’m Kimi, an AI assistant developed by Moonshot AI (月之暗面). I don’t have a specific public model version identifier to share from here."
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 134,
```

Como podemos ver, as informações contidas em `choices` são consistentes com as do uso básico. Elas incluem o conteúdo específico das respostas do Kimi a várias interações, permitindo responder às perguntas correspondentes com base no conteúdo de várias mensagens.

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e as informações de erro correspondentes. Por exemplo:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.
