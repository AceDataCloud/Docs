Kimi é uma série de modelos de IA lançada pela Moonshot AI. Atualmente, recomenda-se `kimi-k3.1-pro`, adequado para programação de longo prazo, raciocínio complexo, compreensão visual e trabalho de conhecimento; `kimi-k3` ainda pode ser usado. Chamadas são feitas por meio da API Chat Completions compatível com OpenAI.

Este documento apresenta principalmente o processo de uso das operações da API Kimi Chat Completion, com a qual podemos usar facilmente os recursos de conversa oficiais do Kimi.

## Processo de solicitação

Para usar a API Kimi Chat Completion, primeiro acesse o [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e guarde-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não fez login ou não se registrou, será automaticamente redirecionado para a página de login, onde será convidado a se registrar e fazer login; após concluir, você retornará automaticamente à página atual.

**Um API Token pode chamar todos os serviços da plataforma, não sendo necessário solicitar um separadamente para cada serviço.** A primeira solicitação concede uma cota gratuita, permitindo uma experiência grátis; quando a cota for insuficiente, é possível recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Uso básico

Em seguida, você pode preencher o conteúdo correspondente na interface, conforme mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

Ao usar esta interface pela primeira vez, é necessário preencher pelo menos três conteúdos: `authorization` pode ser selecionado diretamente na lista suspensa; `model` é usado para selecionar o modelo Kimi, sendo recomendado usar `kimi-k3.1-pro`; `messages` é um array de mensagens de conversa, e cada mensagem contém `role` e `content`, sendo que `role` oferece suporte a `user`, `assistant`, `system` e `tool`.

Ao mesmo tempo, você pode notar que há uma geração de código de chamada correspondente à direita; você pode copiar o código e executá-lo diretamente, ou clicar diretamente no botão «Try» para testar.

<p><img src="https://cdn.acedata.cloud/six7e3.png" width="400" className="m-auto" /></p>

A seguir está uma resposta real do K3 obtida com `reasoning_effort: max` (omitindo campos de extensão não utilizados):

```json
{
  "id": "msg_2D4Btbg1WgvkNE3tCYkR4xGA",
  "object": "chat.completion",
  "created": 1784466588,
  "model": "kimi-k3",

  "usage": {
    "prompt_tokens": 86,
    "completion_tokens": 206,

```

O resultado retornado possui vários campos, descritos a seguir:

- `id`, o ID gerado para esta tarefa de conversa, usado para identificar exclusivamente esta tarefa de conversa.
- `model `, o modelo oficial do Kimi selecionado.
- `choices`, as informações de resposta fornecidas pelo Kimi para a pergunta.
- `usage `: informações estatísticas sobre os tokens desta sessão de perguntas e respostas.

Entre eles, `choices` contém as informações de resposta do Kimi, e seus `choices` são as informações específicas da resposta do Kimi, como pode ser visto na imagem.

<p><img src="https://cdn.acedata.cloud/tv9rul.png" width="400" className="m-auto" /></p>

Pode-se ver que o campo `content` dentro de `choices` contém o conteúdo específico da resposta do Kimi; o K3 também pode retornar `reasoning_content`, usado para representar o processo de raciocínio.

## Intensidade de raciocínio do K3.1 Pro

`kimi-k3.1-pro` sempre ativa o raciocínio. É possível definir `reasoning_effort` no nível superior do corpo da solicitação como `low`, `high` ou `max`; não envie uma configuração para desativar o raciocínio. O modelo oferece suporte a até 1.048.576 tokens de contexto, mas o limite real da solicitação ainda está sujeito à interface atual. O preço é calculado com base no uso de entrada, saída e acertos de cache; consulte o cartão Pricing do catálogo de modelos para detalhes.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Os exemplos do K3 a seguir são mantidos para integrações existentes, e as respostas de exemplo foram de fato obtidas por solicitações ao K3.

## Intensidade de raciocínio do K3

`kimi-k3` sempre ativa o raciocínio. O nível superior do corpo da solicitação oferece suporte ao campo `reasoning_effort`, e o único valor atualmente aceito é `max`; ao omitir esse campo, também será usado `max`. `standard`, `high` ou outras strings podem ser aceitos de forma permissiva por algumas fontes upstream compatíveis, mas não há garantia de que alterem o comportamento de raciocínio; não dependa disso.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

Ao usar o SDK OpenAI, esse campo pode ser passado diretamente:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

Em conversas de múltiplas rodadas e chamadas de ferramentas, envie de volta a mensagem completa do assistant da rodada anterior para `messages`, incluindo `reasoning_content` e `tool_calls`.

### Referências oficiais

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort): explica que o Kimi K3 sempre ativa o raciocínio e que o único valor atualmente aceito para `reasoning_effort` é `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview): compara os parâmetros de raciocínio, janelas de contexto e diferenças de chamadas de ferramentas entre as séries K3 e K2.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat): definições oficiais da Moonshot para solicitações, respostas e campos OpenAPI do Chat Completions.

## Resposta em streaming

Esta interface também oferece suporte a respostas em streaming, o que é muito útil para integração com páginas web, permitindo que a página implemente um efeito de exibição palavra por palavra.

Se desejar retornar respostas em streaming, você pode alterar o parâmetro `stream ` no cabeçalho da solicitação para `true`.

A modificação é mostrada na imagem, mas o código de chamada precisa ter as alterações correspondentes para oferecer suporte a respostas em streaming.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>

Depois de modificar `stream` para `true`, a API retornará os dados JSON correspondentes linha por linha; no nível do código, precisamos fazer as modificações correspondentes para obter os resultados linha por linha.

Código de chamada de exemplo em Python:
```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

A seguir estão trechos dos blocos de dados de início, raciocínio, corpo, término e uso de uma resposta de streaming real do K3 Max na mesma ocasião:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Pode-se ver que há muitos `data` na resposta, e os `choices` dentro de `data` correspondem ao conteúdo mais recente da resposta, consistente com o conteúdo apresentado acima. `choices` representa o conteúdo de resposta adicionado, e você pode integrá-lo ao seu sistema com base no resultado. Ao mesmo tempo, o término da resposta de streaming é determinado com base no conteúdo de `data`; se o conteúdo for `[DONE]`, isso indica que a resposta de streaming foi totalmente concluída. O resultado de `data` retornado possui vários campos, apresentados a seguir:

- `id`, o ID gerado para esta tarefa de conversa, usado para identificar exclusivamente esta tarefa de conversa.
- `model `, o modelo selecionado no site oficial do Kimi.
- `choices`, as informações de resposta fornecidas pelo Kimi para a pergunta.

JavaScript também é suportado, por exemplo, o código de chamada de streaming em Node.js é o seguinte:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Código de exemplo em Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Outras linguagens podem ser adaptadas separadamente, o princípio é o mesmo.

## Conversas com múltiplos turnos

Se você quiser integrar a funcionalidade de conversa com múltiplos turnos, precisará enviar várias perguntas no campo `messages`; um exemplo específico de várias perguntas é mostrado na imagem abaixo:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Código de chamada de exemplo em Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Ao enviar várias perguntas, é possível implementar facilmente conversas com múltiplos turnos. A seguir está uma resposta real do K3 Max obtida por esta solicitação (campos de extensão não utilizados foram omitidos):

```json
{
  "id": "msg_Rqp8nPGBDHWwBlL4VpxuafOp",
  "object": "chat.completion",
  "created": 1784466628,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "I’m Kimi, an AI assistant developed by Moonshot AI (月之暗面). I don’t have a specific public model version identifier to share from here."
      },
      "logprobs": null,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 134,
    "completion_tokens": 346,
    "total_tokens": 480

```

Pode-se ver que as informações contidas em `choices` são consistentes com o conteúdo de uso básico; isso inclui o conteúdo específico das respostas do Kimi para várias conversas, de modo que é possível responder às perguntas correspondentes com base no conteúdo de várias conversas.

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e as informações de erro correspondentes. Por exemplo:

- `400 token_mismatched`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`：Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`：Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`：Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```

```
