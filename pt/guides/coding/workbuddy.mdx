## 1. Obter a API Key

Abra a [lista de aplicativos do Ace Data Cloud](https://platform.acedata.cloud/console/applications), entre em um aplicativo disponível e copie a API Key.

![Obter a API Key do Ace Data Cloud](https://cdn.acedata.cloud/dvc3cg.jpg)

## 2. Adicionar um modelo

No WorkBuddy, acesse **Configurações → Modelos → Modelos Personalizados → Adicionar Modelo** e preencha:

| Campo       | Valor                                                                                                |
| -------- | ------------------------------------------------------------------------------------------------ |
| Provider | `Custom`                                                                                         |
| Endereço da interface     | `https://api.acedata.cloud/v1`                                                                   |
| API Key  | A API Key que acabou de ser copiada                                                                                    |
| Nome do modelo     | Acesse o [catálogo de modelos](https://platform.acedata.cloud/models) para consultar e preencha exatamente o nome do modelo a ser chamado, por exemplo, `claude-opus-5`, `gpt-6-sol` |
| Protocolo personalizado    | Desativado                                                                                               |

![Interface de configuração do WorkBuddy Custom Provider](https://cdn.acedata.cloud/189027b68722.png)

> O `id` aqui é o nome do modelo usado pelo parâmetro `model` na solicitação da API, e não o UUID do serviço, da API ou da Application, nem um nome de exibição personalizado. Somente quando o catálogo em tempo real retornar `{"id":"ds-4.0"}` será possível preencher `ds-4.0`; se não estiver no catálogo, isso indica que ele não está disponível no momento; não faça suposições nem abreviações.

Você pode primeiro consultar os modelos disponíveis no [catálogo de modelos](https://platform.acedata.cloud/models); se precisar confirmar o nome exato que as credenciais Coding atuais podem chamar, use a API Key que acabou de copiar para consultar o catálogo da API:

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_KEY"
```

No array `data` da resposta, encontre o modelo de destino e copie exatamente o valor de seu `id`. Configure as opções de capacidade de acordo com o suporte real desse modelo.

Ao manter o “protocolo personalizado” desativado, o WorkBuddy completará o caminho de acordo com as regras do OpenAI Chat Completions. As opções avançadas de capacidade (ferramentas, imagens, raciocínio) devem ser ativadas apenas conforme as capacidades reais do modelo selecionado; em caso de dúvida, mantenha primeiro o padrão.

## 3. Verificação

Após salvar, selecione o modelo recém-adicionado no seletor de modelos de chat e envie `Reply only OK`. Em seguida, execute uma tarefa de arquivo somente leitura ou de ferramenta para confirmar que as capacidades necessárias estão disponíveis; os registros de chamadas podem ser consultados no [histórico de uso](https://platform.acedata.cloud/console/usages).

Se o modelo não aparecer, confirme que a configuração foi salva e ativada; para 401, verifique a Key; para 404, verifique se o nome do modelo informado corresponde exatamente ao `id` no catálogo e se o endereço da interface está correto. A documentação oficial do WorkBuddy informa que a Key é armazenada na configuração local, mas o conteúdo das solicitações ainda será enviado ao serviço de modelo configurado.
