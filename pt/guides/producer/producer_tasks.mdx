A principal função da API de Tarefas do Producer é consultar o status de execução da tarefa inserindo o ID da tarefa gerado pela API de Geração de Áudios do Producer.

Este documento apresentará detalhadamente as instruções de integração da API de Tarefas do Producer, ajudando você a integrar facilmente e aproveitar plenamente os poderosos recursos desta API. Por meio da API de Tarefas do Producer, você pode facilmente consultar o status de execução das tarefas da API de Geração de Áudios do Producer.

## Processo de solicitação

Para usar a API de Geração de Áudios do Producer, primeiro obtenha seu Token de API no [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) e guarde-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver conectado ou registrado, será automaticamente redirecionado para a página de login para se registrar e entrar; após a conclusão, você retornará automaticamente à página atual.

**Um Token de API pode chamar todos os serviços da plataforma, não sendo necessário solicitar separadamente para cada serviço.** Na primeira solicitação, será concedida uma cota gratuita para experimentar sem custos; quando a cota for insuficiente, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [API de Geração de Áudios do Producer →](https://platform.acedata.cloud/documents/producer-audios)

## Exemplo de solicitação

A API de Tarefas do Producer pode ser usada para consultar os resultados da API de Geração de Áudios do Producer. Para saber como usar a API de Geração de Áudios do Producer, consulte a documentação [API de Geração de Áudios do Producer](https://platform.acedata.cloud/documents/producer-audios-integration).

Usaremos como exemplo um ID de tarefa retornado pelo serviço da API de Geração de Áudios do Producer para demonstrar como usar esta API. Suponha que temos um ID de tarefa: 1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad; a seguir, demonstraremos como ao passar um ID de tarefa.

### Configurar cabeçalhos e corpo da solicitação

**Request Headers** incluem:

- `accept`: especifica o recebimento de resultados de resposta no formato JSON; aqui, preencha como `application/json`.
- `authorization`: a chave para chamar a API, que pode ser selecionada diretamente no menu suspenso após a solicitação.

**Request Body** inclui:

- `id`: o ID da tarefa enviada.
- `action`: o modo de operação da tarefa.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

O resultado retornado possui vários campos. O campo `request` é o request body ao iniciar a tarefa, enquanto o campo `response` é o response body retornado após a conclusão da tarefa. A introdução dos campos é a seguinte.
- `id`, o ID da tarefa de geração, usado para identificar exclusivamente esta tarefa de geração.
- `request`, as informações da solicitação na tarefa de consulta.
- `response`, as informações de retorno na tarefa de consulta.
- `created_at`, o horário de criação da tarefa, timestamp Unix (segundos, ponto flutuante).
- `started_at`, o horário de início da execução da tarefa, timestamp Unix (segundos, ponto flutuante).
- `finished_at`, o horário de conclusão da tarefa, timestamp Unix (segundos, ponto flutuante). Este campo não é retornado quando a tarefa não está concluída.
- `elapsed`, o tempo de execução da tarefa, em segundos (ponto flutuante, mantendo 3 casas decimais). Este campo não é retornado quando a tarefa não está concluída.

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `400 token_mismatched`: Solicitação incorreta, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`: Solicitação incorreta, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`: Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`: Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`: Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
