Este artigo apresentará uma instrução de integração da API Producer Audios Generation, que permite gerar músicas oficiais do Producer por meio da entrada de parâmetros personalizados.

## Processo de solicitação

Para usar a API Producer Audios Generation, primeiro obtenha seu API Token no [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) e guarde-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver conectado ou registrado, será automaticamente redirecionado para a página de login, onde será convidado a se registrar e entrar. Após concluir, você retornará automaticamente à página atual.

**Um API Token pode chamar todos os serviços da plataforma, não sendo necessário solicitar separadamente para cada serviço.** A primeira solicitação concede créditos gratuitos para uma experiência sem custo; quando os créditos forem insuficientes, você poderá recarregar o saldo geral no [Console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Selecione os parâmetros obrigatórios conforme a operação

Quando `action=generate` e `custom=false` (padrão), forneça `prompt`; quando `custom=true`
e `instrumental=false`, forneça `lyric`. Para música instrumental personalizada, é possível definir
`custom=true, instrumental=true`, sem necessidade de inventar letras ou palavras de prompt adicionais.
`action=extend` requer `audio_id` e `continue_at` maior que 0; o modo não instrumental também requer
`lyric`. Cover, variação, substituição de trecho, troca de vozes e separação de faixas exigem o `audio_id`
de origem; letras e palavras de prompt não devem ser obrigatórias incondicionalmente para todas as operações.

No MCP, `producer_extend_music` e `producer_replace_section`, ao fornecerem `lyric`,
selecionarão o modo de letras personalizadas; para continuação instrumental, é possível passar `instrumental=true` e omitir as letras.

## Uso básico

Para pensar em qualquer tipo de música, você pode inserir livremente um trecho de texto. Por exemplo, se eu quiser gerar uma música sobre o Natal, posso inserir `a song for Christmas`, como mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Pode-se ver que aqui configuramos os Request Headers, incluindo:

- `accept`: o formato de resultado de resposta que se deseja receber; aqui é preenchido como `application/json`, ou seja, formato JSON.
- `authorization`: a chave para chamar a API, que pode ser selecionada diretamente no menu suspenso após a solicitação.

Além disso, os parâmetros do Request Body incluem:

- `action`: o comportamento desta tarefa de geração de música; para gerar uma música, é `generate`.
- `model`: o modelo usado para criar a música. Atualmente, os principais são: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: o conteúdo da letra da música.
- `custom`: se deve usar um método personalizado para gerar a música.
- `prompt`: a palavra de prompt no modo de inspiração.
- `title`: as informações do título da música.
- `audio_id`: o ID da música de referência, usado para operações como continuação/cover.
- `continue_at`: continuar a música a partir do número de segundos especificado.
- `replace_section_start`/`replace_section_end`: os tempos de início e fim do trecho a ser substituído, em segundos.
- `lyrics_strength`: intensidade da letra, que indica o grau de influência da letra na geração de áudio, opcional entre 0 e 1, padrão 0,7.
- `sound_strength`: intensidade da palavra de prompt de áudio, opcional entre 0,2 e 1, padrão 0,7.
- `cover_strength`: intensidade do cover, entre 0,2 e 1, padrão 1.
- `weirdness`: grau de estranheza do estilo, opcional entre 0 e 1, padrão 0,5.
- `callback_url`: a URL que precisa receber o resultado do callback.
- `async`: opcional; quando definido como `true`, a interface retorna imediatamente `task_id`, não sendo necessário fornecer `callback_url`; em seguida, obtenha o resultado por meio de polling na interface de consulta de tarefas correspondente.
- `instrumental`: se está no modo sem letras.

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Regravar músicas

Se quiser realizar a operação de regravação em uma música já gerada, é possível inserir a música gerada acima para regravá-la; em seguida, vamos gerar uma música personalizada com base na letra e no título.

Se quiser continuar regravando uma música enviada por você, é possível definir o parâmetro `action` como `upload_cover` e inserir o ID da música enviada personalizada que precisa continuar sendo regravada. O ID da música é obtido usando a [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), como mostrado na imagem abaixo:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

É possível especificar o seguinte conteúdo:

- action: a ação desta tarefa de música, atualmente compatível com: generate, cover, extend, upload_cover, upload_extend, replace_section, swap_vocals, swap_instrumentals, variation; para esta regravação, use o parâmetro `cover`.
- lyric: texto da letra
- title: o título da música.
- custom: se deve usar o modo personalizado para gerar; o padrão é false.
- audio_id: o ID da música que precisa ser regravada.

## Continuar a música

## Callback assíncrono

Como o tempo de geração da Producer Audios Generation API às vezes pode ser relativamente longo, se a API não responder por muito tempo, a solicitação HTTP manterá a conexão, resultando em consumo adicional de recursos do sistema, portanto, esta API também fornece suporte para callback assíncrono.

O processo geral é: quando o cliente inicia uma solicitação, ele especifica adicionalmente um campo `callback_url`; após o cliente iniciar a solicitação de API, a API retornará imediatamente um resultado, incluindo informações de um campo `task_id`, que representa o ID da tarefa atual. Quando a tarefa for concluída, o resultado da tarefa de geração será enviado na forma de POST JSON para o `callback_url` especificado pelo cliente, que também inclui o campo `task_id`, para que os resultados da tarefa possam ser associados por meio do ID.

A seguir, vamos entender como operar especificamente por meio de um exemplo.

Primeiro, o callback Webhook é um serviço que pode receber solicitações HTTP, e o desenvolvedor deve substituí-lo pela URL do servidor HTTP que ele mesmo configurou. Aqui, para facilitar a demonstração, é usado um site de exemplo público de Webhook [https://webhook.site/](https://webhook.site/); ao abrir esse site, é possível obter uma URL de Webhook, como mostrado na imagem:

![](https://cdn.acedata.cloud/tbcnai.png)

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `400 token_mismatched`: Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`: Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`: Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`: Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`: Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
