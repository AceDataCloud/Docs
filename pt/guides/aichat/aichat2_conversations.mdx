A API AI Chat v2 (`/aichat2/conversations`) é a interface de conversação de nova geração, uma versão totalmente atualizada da [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Com base na simplicidade e no gerenciamento hospedado de conversas de múltiplas rodadas da v1, ela expandiu:

- **Entradas de usuário multimodais**: por meio do campo estruturado `message`, envie diretamente blocos de texto + imagens + arquivos, sem precisar anexá-los indiretamente primeiro usando `references`.
- **Chamadas de ferramentas orientadas por Agent**: integra um conjunto de ferramentas como pesquisa online, captura de páginas web, leitura de arquivos etc., e permite montar servidores MCP autorizados pelo usuário (Google Drive, Notion, Slack, GitHub etc.); o modelo pode chamar ferramentas autonomamente em múltiplas rodadas dentro de uma solicitação para concluir tarefas complexas.
- **Eventos estruturados de streaming**: por meio de `accept: text/event-stream` ou `application/x-ndjson`, é possível obter eventos como `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact` etc. token a token, facilitando renderizá-los separadamente no frontend de acordo com seus tipos correspondentes.
- **Interrompível / retomável**: quando o modelo precisar que o usuário complemente informações, ele emitirá um evento `ask_user_question` e pausará; na próxima chamada, basta preencher a resposta por meio de `tool_results` para continuar.
- **Novas ações CRUD**: conclua `retrieve` / `retrieve_batch` / `update` / `delete` no mesmo endpoint por meio do campo `action`, sem precisar de APIs adicionais de gerenciamento de conversas.
- **Lista de modelos continuamente atualizada**: por padrão, conecta modelos contemporâneos como GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 etc.

Ao mesmo tempo, no nível do corpo da solicitação, ela é **totalmente compatível retroativamente com a v1**: basta enviar `model` + `question` (+ opcionais `stateful` / `id` / `references` / `preset`) para obter uma resposta JSON `{answer, id}` equivalente à v1; portanto, ao migrar de `/aichat/conversations`, não é necessário reescrever o cliente, basta alterar o caminho para `/aichat2/conversations`.

> Se você está usando atualmente `/aichat/conversations`, a interface antiga continuará em serviço, e você pode migrar no seu próprio ritmo.

## Processo de solicitação

Para usar a API AI Chat v2, primeiro obtenha seu API Token no [console do Ace Data Cloud](https://platform.acedata.cloud/console/applications) e guarde-o como reserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não fez login ou se registrou, será redirecionado automaticamente para a página de login, que convidará você a se registrar e fazer login; após concluir, você retornará automaticamente à página atual.

**Um API Token pode chamar todos os serviços da plataforma, não sendo necessário solicitar separadamente para cada serviço.** A primeira solicitação concede uma cota gratuita, permitindo uma experiência gratuita; quando a cota for insuficiente, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

## Uso básico

O uso mais simples é exatamente igual ao da v1: envie `model` + `question` e obtenha `{answer, id}`.

Exemplo CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Resultado retornado:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Exemplo Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。",

response = requests.post(url, json=payload, headers=headers)
```

## Conversação de múltiplas rodadas

Assim como na v1, envie `stateful: true` para ativar o salvamento da conversa, e a API retornará um `id`; nas solicitações subsequentes, basta trazer o `id` de volta para continuar a conversa, sem precisar manter você mesmo o histórico de messages.

Primeira solicitação:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Retorno:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Segunda solicitação, incluindo o mesmo `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> O padrão de `stateful` é `true`; omiti-lo é equivalente a passar explicitamente `true`. Definir `stateful: false` ignorará o carregamento do histórico de conversas anterior; isso não significa que o resultado desta rodada não será salvo, nem se aplica a fluxos de ferramentas que precisam ser retomados após uma pausa.

### Conversas longas e preservação do texto original

A compactação de contexto apenas organiza o conteúdo enviado ao modelo nesta rodada, não substituindo os registros de chat já salvos. Por meio de `action: retrieve`, ainda é possível ler as mensagens salvas completas; a edição ou exclusão explícita da conversa continua tendo efeito conforme solicitado.

O modelo pode buscar e ler em páginas o texto original do histórico dentro da conversa atual. Quando for necessário continuar editando um artigo, citar números ou preparar uma publicação, o texto original correspondente deve ser lido, e um resumo não pode substituir o corpo do texto. Essa capacidade não restaura automaticamente mensagens que já foram perdidas em versões antigas.

Se a organização do contexto falhar, mantenha o ID da conversa e verifique o evento `error`; o serviço não sobrescreverá o texto original com um resumo vazio. As operações de ferramentas concluídas antes da falha ainda podem ser válidas; consulte seus resultados primeiro para evitar gerações ou publicações duplicadas. Quando uma única conversa atingir o limite de armazenamento, um erro explícito será retornado; os registros já salvos não liberarão espaço por meio de corte. Você pode exportar o conteúdo necessário e iniciar uma nova conversa.

## Resposta em streaming

O v2 oferece suporte a dois formatos de streaming, selecionados pelo cabeçalho `accept`:

| Cenário                    | `accept`               | Formato dos dados                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Front-end Web / EventSource  | `text/event-stream`    | `data: {json}\n\n`, com a última linha `data: [DONE]\n\n` |
| Servidor / CLI / análise de streaming Node | `application/x-ndjson` | Um objeto JSON por linha                               |
| Streaming não necessário                 | `application/json`（padrão） | Retorna `{answer, id}` de uma só vez                       |

### Exemplo de NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Cada linha de NDJSON é um evento estruturado, sendo o mais comum `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Exemplo de SSE

O uso de `EventSource` no navegador não oferece suporte a corpos de solicitação personalizados; recomenda-se usar `fetch` + análise manual por fatias de `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Tipos de eventos de streaming

| `type`              | Significado                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Fragmento de texto incremental da resposta do assistente. `content` é o conteúdo novo; para compatibilidade com v1, o mesmo evento também inclui `delta_answer` (igual a `content`) e `id`.                                        |
| `thinking`          | Processo de raciocínio do modelo (aparece apenas quando o modelo selecionado expõe reasoning).                                                                                      |
| `tool_use`          | O modelo decide chamar uma ferramenta; o evento inclui `tool_id`, `tool_name`, `input`.                                                                        |
| `tool_result`       | Resultado da execução da ferramenta, pareado com o `tool_use` anterior por meio de `tool_id`; `is_error` indica se houve falha.                                                             |
| `card`              | Cartão estruturado produzido pela ferramenta (como imagem, prévia de link), adequado para renderização direta.                                                                                          |
| `citation`          | URL da fonte usada para complementar a citação do fragmento de texto correspondente.                                                                                                  |
| `ask_user_question` | Emitido quando o modelo precisa que o usuário forneça informações adicionais; a conversa entra no estado `awaiting_user_input`, veja abaixo [retomar uma conversa pausada](#retomar-uma-conversa-pausada).                                                 |
| `artifact`          | Artefato independente gerado pelo modelo (como bloco de código, documento), que pode ser salvo ou baixado.                                                                                            |
| `system_message`    | Informação de aviso do sistema (não é conteúdo do usuário nem do assistente), usada apenas para avisos de UI.                                                                                           |
| `compact`           | O contexto do modelo foi organizado; as mensagens originais salvas permanecem inalteradas, e o cliente não precisa excluir os registros de chat.                                                                                    |
| `error`             | Ocorreu um erro nesta rodada; `message` descreve o conteúdo do erro.                                                                                              |
| `done`              | O registro final da conversa desta rodada foi salvo com sucesso; inclui `usage` (com `prompt_tokens` / `completion_tokens` / `total_tokens`) e `terminal_reason`; ainda é necessário determinar se a tarefa foi concluída conforme o motivo de término. |
Para clientes que se preocupam apenas com a resposta final, concatenar todos os `content` de `text_delta` é equivalente a `answer` no modo `application/json`.

## Entrada multimodal

Se a entrada do usuário incluir imagens ou arquivos, envie `message` (array) em vez de `question`. Cada elemento do array é um bloco de conteúdo:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "Quantos gatos há nesta imagem?" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Tipos de blocos suportados:

- `text` — texto comum, campo `text` obrigatório.
- `image_url` — imagem, `image_url.url` obrigatório.
- `file_url` — arquivo (PDF, CSV, TXT etc.), `file_url.url` obrigatório.

### Relação com `references` da v1

Para compatibilidade com clientes antigos, a v2 ainda reconhece o campo `references: ["https://...", ...]`:

- Se o sufixo da URL for `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, ela será automaticamente convertida em um bloco `image_url`;
- Outras extensões serão convertidas em blocos `file_url`;
- Se também for fornecido `question`, ele será colocado antes como um bloco `text`.

Portanto, se você quiser apenas migrar da v1 sem alterar o corpo da requisição, basta alterar o caminho para `/aichat2/conversations`, e o uso original de `references` continuará funcionando normalmente.

Se precisar de um controle mais preciso (por exemplo, colocar várias imagens entre textos, ou se a ordem for importante), use diretamente o array `message`.

## Chamada de ferramentas e MCP

O aprimoramento central da v2 é que o modelo pode chamar ferramentas autonomamente para concluir tarefas de várias etapas, **isso vem ativado por padrão**, sem exigir qualquer configuração adicional do cliente na requisição. Cenários comuns:

- O usuário pergunta “Pesquise para mim quais novas exposições há recentemente em Xangai” → o modelo chama a busca web integrada → organiza os resultados em uma resposta.
- O usuário pergunta “Leia este PDF e depois escreva um resumo” → o modelo chama `file_read` → escreve um resumo.
- O usuário já autorizou Google Drive / GitHub / Notion etc. em [Connections](https://platform.acedata.cloud/connections) → o modelo pode chamar as ferramentas MCP correspondentes para ler e escrever seus dados.

No fluxo NDJSON / SSE, as chamadas de ferramentas são apresentadas por meio de dois tipos de eventos, `tool_use` e `tool_result`, por exemplo:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"Exposições de primavera de 2026 em Xangai"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"Atualmente","delta_answer":"Atualmente","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"Xangai","delta_answer":"Xangai","id":"f2f4b3e8-..."}
...
```

Se você não quiser exibir os detalhes das chamadas de ferramentas no frontend, basta ignorar os eventos `tool_use` / `tool_result` / `card` / `citation`; a saída final do modelo continuará sendo transmitida por `text_delta`.

`max_turns` pode limitar o número máximo de rodadas em que o modelo chama ferramentas por conta própria nesta requisição, com intervalo de 1–500; se omitido, o padrão é 500. Defini-lo como um valor baixo (por exemplo, `max_turns: 1`) pode forçar uma resposta única, sem permitir nenhuma chamada de ferramenta.

## Execução assíncrona e autorização sem supervisão

Se sua chamada vier de um Webhook de alerta, CI/CD, sistema de monitoramento ou outra tarefa em segundo plano, você pode definir `async: true` para que a interface retorne imediatamente o ID da tarefa e continue a execução em segundo plano:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Meu serviço disparou um alerta, notifique o grupo do WeChat pessoal «AceDataCloud团队»…"
}
```

Exemplo de retorno:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Depois, você pode usar `action: retrieve` + `id` para consultar o resultado da conversa; também pode fornecer `callback_url`, e após a conclusão da tarefa a plataforma fará POST de `{ status, answer, usage, error }` para seu endereço de callback. `callback_url` deve usar `http` / `https` e não pode preencher diretamente `localhost` ou um endereço IP privado literal.

Normalmente, não há ninguém para clicar em uma confirmação para tarefas em segundo plano. Se você quiser que determinados Skills ou MCP Servers executem ações como enviar, publicar ou escrever no modo sem supervisão, transmita explicitamente uma lista de pré-autorização no corpo da requisição:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Meu serviço disparou um alerta, notifique o grupo do WeChat pessoal «AceDataCloud团队»…"
}
```

Os valores em `allowed_skills` são os slugs dos Skills conectados; os valores em `allowed_mcp_servers` são os slugs dos MCP Servers conectados. Skills / MCP Servers não incluídos na pré-autorização ainda poderão apenas visualizar, executar dry-run ou recusar operações de escrita no modo sem supervisão.

Se precisar de um controle mais detalhado, você também pode usar o objeto equivalente `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

A pré-autorização são essas duas listas em si: uma lista vazia significa não autorizar nenhuma capacidade, sem necessidade de campos de ativação adicionais.

Observação: a pré-autorização significa apenas que “esta requisição permite que essas capacidades pulem a confirmação humana no modo sem supervisão”. O Skill específico ainda deve oferecer suporte a `--unattended-confirm` ou a um mecanismo de segurança correspondente; caso contrário, ele continuará em dry-run e não executará diretamente operações de escrita.

## Retomar conversas pausadas

Algumas ferramentas fazem o modelo “fazer uma pergunta ao usuário”; nesse momento, o modelo emitirá um evento `ask_user_question`, e a conversa será congelada no estado `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Você deseja que o relatório gerado seja em chinês ou em inglês?",
  "options": ["Chinês", "Inglês"],
  "id": "f2f4b3e8-..."
}
```

No frontend, renderize esse evento como um cartão para que o usuário escolha uma resposta e, em seguida, inicie a próxima requisição usando o mesmo `id`, preenchendo a resposta por meio de `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

No corpo da solicitação, `tool_use_id` **deve** ser exatamente igual ao `tool_id` no momento da pausa; caso seja diferente, retornará 400. Quando `tool_results` existir simultaneamente na solicitação, `question` / `message` / `references` serão todos ignorados.

Se o usuário decidir abandonar esta pergunta, basta enviar diretamente um novo `question` / `message`, e a plataforma marcará automaticamente a chamada de ferramenta pausada como «ignorada pelo usuário».

## Gerenciamento de conversas (CRUD)

A v2 fornece gerenciamento leve de conversas no mesmo endpoint por meio do campo `action`, sem a necessidade de abrir outra API.

### `action: retrieve` —— Obter uma conversa

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Retorna o documento completo da conversa (incluindo histórico de `messages`, `model`, `title`, `tools_used` etc.).

### `action: retrieve_batch` —— Listar resumos de conversas

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Retorna `{ items: [...], total }`. **Os resumos não incluem `messages`**, sendo adequados para listas na barra lateral; se o usuário abrir uma conversa, use então `action: retrieve` para obter separadamente suas mensagens completas.

Parâmetros de filtro opcionais: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Alterar o título ou reescrever o histórico

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "杭州旅行计划"
}
```

`messages` também pode ser enviado, mas o servidor realizará uma validação rigorosa do schema (deve estar no formato `ToolUseContent` recolhido); se não estiver em conformidade, retornará 400. Em geral, recomenda-se usá-lo apenas para alterar o `title`.

### `action: delete` —— Excluir uma conversa

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Retorna `{ id, success: true }`. Após a exclusão, não será possível restaurar, portanto confirme antes de chamar.

## Migração suave da v1

Se você já estiver usando [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), a migração para a v2 quase não exige alterações no código:

1. Altere a URL de `https://api.acedata.cloud/aichat/conversations` para `https://api.acedata.cloud/aichat2/conversations`.
2. Se você anteriormente enviava nomes de modelos da v1 (como `gpt-3.5`, `gpt-4-browsing` etc.), ao mudar para a v2 é recomendável atualizar para modelos contemporâneos (como `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` etc.).
3. Os campos do fluxo NDJSON permanecem compatíveis com versões anteriores: cada evento `text_delta` continua incluindo `delta_answer` e `id`; portanto, clientes que originalmente analisavam `delta_answer` linha a linha não precisam ser alterados.

Após a migração, você pode habilitar conforme necessário os novos recursos da v2 (multimodal `message`, SSE, chamadas de ferramentas, CRUD por `action`) e avançar no seu próprio ritmo.

## Tratamento de erros

As respostas de erro são unificadas como:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Erros comuns:

- `400 bad_request`: campos obrigatórios ausentes, `tool_use_id` não corresponde, schema de `messages` inválido etc.
- `401 invalid_token`: cabeçalho `authorization` incorreto.
- `404 not_found`: a conversa correspondente ao `id` não existe ao usar `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: a conversa excede o limite de armazenamento, sem sobrescrever registros já salvos.
- `429 too_many_requests`: o limite de taxa foi acionado.
- `503 context_compaction_failed`: falha na organização do contexto, os registros existentes são preservados.
- `500 conversation_persist_failed`: a gravação final desta rodada falhou; o texto já recebido não significa que o registro final foi salvo com sucesso, consulte pelo ID da conversa.
- `500 chat_error`: o serviço está temporariamente indisponível ou nenhum conteúdo foi gerado nesta rodada (não haverá cobrança).

Na resposta em streaming, os erros são emitidos como eventos `{"type":"error","message":"..."}`, e em seguida o fluxo será encerrado. `[DONE]` indica apenas o fim da transmissão; quando há `error`, não pode ser considerado sucesso, e o evento `done` de sucesso também não será enviado.

## Conclusão

A API AI Chat v2, mantendo compatibilidade com versões anteriores da v1, atualiza as conversas de «perguntas e respostas de uma rodada / múltiplas rodadas» para «conversas observáveis orientadas por Agent»: entrada multimodal, chamadas de ferramentas, pausável / retomável, eventos estruturados em streaming e CRUD integrado. Recomenda-se que novas integrações usem diretamente a v2; integrações v1 existentes podem migrar suavemente em etapas. Caso tenha alguma dúvida, entre em contato com nossa equipe de suporte técnico a qualquer momento.
