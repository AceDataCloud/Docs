A API AI Chat v2 (`/aichat2/conversations`) é uma interface de conversação de nova geração e uma atualização abrangente da [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Com base na simplicidade e no gerenciamento de conversas com múltiplas interações da v1, ela foi expandida para incluir:

- **Entrada multimodal do usuário**: transmite diretamente texto + imagens + blocos de arquivos por meio do campo estruturado `message`, sem precisar anexá-los indiretamente usando `references`.
- **Chamadas de ferramentas no estilo Agent**: inclui um conjunto integrado de ferramentas, como pesquisa na Internet, extração de páginas da Web e leitura de arquivos, além de permitir a conexão de servidores MCP autorizados pelo usuário (Google Drive, Notion, Slack, GitHub etc.). O modelo pode chamar ferramentas autonomamente várias vezes em uma única solicitação para concluir tarefas complexas.
- **Eventos de streaming estruturados**: por meio de `accept: text/event-stream` ou `application/x-ndjson`, é possível obter eventos individuais, como `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card` e `artifact`, facilitando a renderização de cada tipo separadamente no frontend.
- **Interrupção / retomada**: quando precisar que o usuário forneça informações adicionais, o modelo emitirá um evento `ask_user_question` e pausará. Na próxima chamada, basta preencher a resposta por meio de `tool_results` para continuar.
- **Novas ações CRUD**: no mesmo endpoint, é possível executar `retrieve` / `retrieve_batch` / `update` / `delete` por meio do campo `action`, sem precisar de uma API adicional de gerenciamento de sessões.
- **Lista de modelos continuamente atualizada**: por padrão, oferece acesso a modelos contemporâneos, como GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3 etc.

Ao mesmo tempo, no nível do corpo da solicitação, ela é **totalmente compatível com versões anteriores da v1**: basta enviar `model` + `question` (+ `stateful` / `id` / `references` / `preset` opcionais) para obter uma resposta JSON `{answer, id}` equivalente à da v1. Portanto, a migração de `/aichat/conversations` não exige a reescrita do cliente; basta alterar o caminho para `/aichat2/conversations`.

> Se você estiver usando atualmente `/aichat/conversations`, a interface antiga continuará disponível. Você poderá migrar no seu próprio ritmo.

## Processo de solicitação

Para usar a API AI Chat v2, primeiro acesse o [painel de controle do Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e guardá-lo para uso posterior.

![]()

Se você ainda não estiver conectado ou registrado, será redirecionado automaticamente para a página de login, onde poderá se registrar e entrar. Após concluir o processo, você retornará automaticamente à página atual.

**Um único API Token permite chamar todos os serviços da plataforma, sem necessidade de solicitar acesso individualmente para cada serviço.** Na primeira solicitação, você receberá uma cota gratuita para experimentar o serviço sem custos. Quando a cota for insuficiente, poderá adicionar saldo geral no [painel de controle](https://platform.acedata.cloud/console/coin).

## Uso básico

O método mais simples é exatamente igual ao da v1: enviar `model` + `question` e obter `{answer, id}`.

Exemplo CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Resultado retornado:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Exemplo em Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",

## Conversas com múltiplas interações

Assim como na v1, envie `stateful: true` para ativar o salvamento da sessão. A API retornará um `id`; nas solicitações seguintes, basta enviar esse mesmo `id` para continuar a conversa, sem precisar manter por conta própria o histórico de messages.

Primeira solicitação:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Resposta:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Segunda solicitação, incluindo o mesmo `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "Qual é o número que pedi para você lembrar há pouco?"
  }'
```

```json
{
  "answer": "O número que você me pediu para lembrar é 42.",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` é `true` por padrão; omiti-lo é equivalente a passar explicitamente `true`. Definir `stateful: false` ignora o carregamento do histórico de conversas anterior; isso não significa que o resultado desta rodada não será salvo, nem se aplica a fluxos de ferramentas que precisam ser pausados e retomados.

### Conversas longas e preservação do texto original

A compactação do contexto apenas organiza o conteúdo enviado ao modelo nesta rodada, sem substituir o histórico de conversas salvo. Ainda é possível ler todas as mensagens salvas por meio de `action: retrieve`; as edições e exclusões explícitas de conversas continuam sendo aplicadas conforme solicitado.

O modelo pode pesquisar e ler o texto original do histórico da conversa atual de forma paginada. Ao continuar editando um artigo, citar números ou preparar uma publicação, deve-se ler o texto original correspondente, sem substituir o conteúdo principal por um resumo. Essa capacidade não recupera automaticamente mensagens que já foram perdidas em versões antigas.

Se a organização do contexto falhar, preserve o ID da conversa e verifique o evento `error`; o serviço não substituirá o texto original por um resumo vazio. As operações de ferramentas concluídas antes da falha ainda podem ser válidas. Consulte primeiro os resultados dessas operações para evitar gerar ou publicar conteúdo duplicado. Quando uma única conversa atingir o limite de armazenamento, será exibido um erro explícito. Os registros salvos existentes não terão espaço liberado por meio do corte de conteúdo; você pode exportar o conteúdo necessário e iniciar uma nova conversa.

## Respostas em streaming

A v2 oferece suporte a dois formatos de streaming, selecionados de acordo com o cabeçalho `accept`:

| Cenário                    | `accept`               | Formato dos dados                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Front-end Web / EventSource  | `text/event-stream`    | `data: {json}\n\n`, com a última linha `data: [DONE]\n\n` |
| Servidor / CLI / análise de streaming em Node | `application/x-ndjson` | Um objeto JSON por linha                               |
| Sem necessidade de streaming                 | `application/json` (padrão) | Retorno único de ` id}`                       |

### Exemplo de NDJSON

```SON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "Apresente Hangzhou em três frases.",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # Compatível com v1: os fragmentos incrementais também são fornecidos pelo campo delta_answer
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Cada linha do NDJSON é um evento estruturado. O mais comum é `text_delta`:

```json
{"type":"text_delta","content":"Han","delta_answer":"Han","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"g","delta_answer":"g","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"zhou","delta_answer":"zhou","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Exemplo de SSE

No navegador, `EventSource` não oferece suporte a corpos de solicitação personalizados. Recomenda-se usar `fetch` + divisão e análise manual por `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "Apresente Hangzhou em três frases.",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Tipos de eventos de streaming

| `type`              | Significado                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Fragmento incremental do texto da resposta do assistente. `content` contém o novo conteúdo; para manter a compatibilidade com v1, o mesmo evento também inclui `delta_answer` (igual a `content`) e `id`.                                        |
| `thinking`          | Processo de raciocínio do modelo (aparece apenas quando o modelo selecionado expõe o raciocínio).                                                                                      |
| `tool_use`          | O modelo decide chamar uma ferramenta. O evento contém `tool_id`, `tool_name` e `input`.                                                                        |
| `tool_result`       | Resultado da execução da ferramenta, associado ao evento `tool_use` anterior por meio de `tool_id`; `is_error` indica se houve falha.                                                             |
| `card`              | Cartão estruturado produzido pela ferramenta (como imagens e pré-visualizações de links), adequado para renderização direta.                                                                                          |
| `citation`          | URL da fonte utilizada para complementar a citação do fragmento de texto correspondente.                                                                                                  |
| `ask_user_question` | Emitido quando o modelo precisa que o usuário forneça informações adicionais. A conversa entra no estado `awaiting_user_input`. Consulte abaixo [Retomar uma conversa pausada](#retomar-uma-conversa-pausada).                                                 |
| `artifact`          | Artefato independente gerado pelo modelo (como blocos de código e documentos), que pode ser salvo ou baixado.                                                                                            |
| `system_message`    | Mensagem informativa do sistema (não faz parte do conteúdo do usuário nem do assistente), utilizada apenas para notificações na interface.                                                                                           |
| `compact`           | O contexto do modelo foi organizado; as mensagens originais salvas permanecem inalteradas, e o cliente não precisa excluir o histórico de conversas.                                                                                    |
| `error`             | Ocorreu um erro nesta rodada; `message` descreve o conteúdo do erro.                                                                                              |
| `done`              | O registro final da conversa desta rodada foi salvo com sucesso. Inclui `usage` (com `prompt_tokens` / `completion_tokens` / `total_tokens`) e `terminal_reason`; ainda é necessário determinar se a tarefa foi concluída de acordo com o motivo do encerramento. |
Para clientes que se preocupam apenas com a resposta final, concatenar o `content` de todos os `text_delta` é equivalente ao `answer` no modo `application/json`.

## Entrada multimodal

Se a entrada do usuário incluir imagens ou arquivos, envie `message` (um array) em vez de `question`. Cada elemento do array é um bloco de conteúdo:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "Quantos gatos há nesta imagem?" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Tipos de blocos suportados:

- `text` — texto comum, o campo `text` é obrigatório.
- `image_url` — imagem, `image_url.url` é obrigatório.
- `file_url` — arquivo (PDF, CSV, TXT etc.), `file_url.url` é obrigatório.

### Relação com `references` da v1

Para garantir a compatibilidade com clientes antigos, a v2 ainda reconhece o campo `references: ["https://...", ...]`:

- Sufixos de URL `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif` são convertidos automaticamente em blocos `image_url`;
- Outras extensões são convertidas em blocos `file_url`;
- Se `question` também for fornecido, ele será adicionado como um bloco `text` no início.

Portanto, se você quiser migrar apenas da v1 sem modificar o corpo da requisição, basta alterar o caminho para `/aichat2/conversations`, e o uso original de `references` continuará funcionando normalmente.

Se precisar de um controle mais preciso (por exemplo, colocar várias imagens entre blocos de texto ou quando a ordem for importante), use diretamente o array `message`.

## Chamadas de ferramentas e MCP

O principal aprimoramento da v2 é que o modelo pode chamar ferramentas autonomamente para concluir tarefas de várias etapas. **Esse recurso está ativado por padrão** e não exige nenhuma configuração adicional por parte do cliente na requisição. Cenários comuns:

- O usuário pergunta: «Ajude-me a pesquisar as exposições recentes em Xangai» → o modelo chama a ferramenta integrada de pesquisa na web → organiza os resultados em uma resposta.
- O usuário pergunta: «Leia este PDF e depois escreva um resumo» → o modelo chama `file_read` → escreve o resumo.
- O usuário já autorizou Google Drive / GitHub / Notion etc. em [Connections](https://platform.acedata.cloud/connections) → o modelo pode chamar as ferramentas MCP correspondentes para ler e gravar esses dados.

Nos fluxos NDJSON / SSE, as chamadas de ferramentas são apresentadas por meio de dois tipos de eventos: `tool_use` e `tool_result`, por exemplo:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Se você não quiser exibir os detalhes das chamadas de ferramentas no frontend, basta ignorar os eventos `tool_use` / `tool_result` / `card` / `citation`. A saída final do modelo continuará sendo transmitida por meio de `text_delta`.

`max_turns` pode limitar o número máximo de rodadas de chamadas autônomas de ferramentas que o modelo pode realizar nesta requisição. O intervalo é de 1–500, e o valor padrão é 500 quando omitido. Definir um valor pequeno (por exemplo, `max_turns: 1`) pode forçar uma única resposta, sem permitir nenhuma chamada de ferramenta.

## Execução assíncrona e autorização sem supervisão

Se sua chamada vier de um Webhook de alerta, CI/CD, sistema de monitoramento ou outra tarefa em segundo plano, você poderá definir `async: true` para que a interface retorne imediatamente um ID de tarefa enquanto a execução continua em segundo plano:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "Meu serviço disparou um alerta. Notifique o grupo do WeChat «AceDataCloud团队» usando minha conta pessoal do WeChat..."
}
```

Exemplo de retorno:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Posteriormente, você poderá consultar o resultado da conversa usando `action: retrieve` + `id`. Também poderá fornecer `callback_url`, e, quando a tarefa for concluída, a plataforma enviará `{ status, answer, usage, error }` por POST para o endereço de callback. `callback_url` deve usar `http` / `https` e não pode conter diretamente `localhost` ou um endereço IP privado literal.

Normalmente, ninguém pode clicar em confirmações em tarefas executadas em segundo plano. Se você quiser que determinadas Skills ou MCP Servers executem ações como enviar, publicar ou gravar dados no modo sem supervisão, forneça explicitamente a lista de pré-autorizações no corpo da requisição:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "Meu serviço disparou um alerta. Notifique o grupo do WeChat «AceDataCloud团队» usando minha conta pessoal do WeChat..."
}
```

Os valores em `allowed_skills` são os slugs das Skills já conectadas; os valores em `allowed_mcp_servers` são os slugs dos MCP Servers já conectados. Skills / MCP Servers que não estiverem incluídos na lista de pré-autorização ainda só poderão visualizar, executar um dry-run ou recusar operações de gravação no modo sem supervisão.

Se precisar de um controle mais detalhado, também poderá usar o objeto equivalente `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

A pré-autorização consiste apenas nessas duas listas: se uma lista estiver vazia, nenhuma capacidade será autorizada, não sendo necessário nenhum campo adicional de ativação.

Observação: a pré-autorização significa apenas que «esta requisição permite que essas capacidades ignorem a confirmação humana no modo sem supervisão». A Skill específica ainda precisa oferecer suporte a `--unattended-confirm` ou a um mecanismo de segurança correspondente; caso contrário, continuará executando um dry-run e não realizará diretamente operações de gravação.

## Retomar conversas pausadas

Algumas ferramentas fazem com que o modelo «faça uma pergunta ao usuário». Nesse momento, o modelo emitirá um evento `ask_user_question`, e a conversa ficará congelada no estado `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "Você deseja que o relatório gerado esteja em chinês ou inglês?",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

No frontend, renderize esse evento como um cartão para que o usuário possa selecionar uma resposta. Em seguida, envie uma nova requisição usando o mesmo `id` e preencha a resposta por meio de `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

No corpo da solicitação, `tool_use_id` **deve** ser exatamente igual ao `tool_id` no momento da pausa; caso contrário, será retornado o erro 400. Quando `tool_results` estiver presente na solicitação, `question` / `message` / `references` serão todos ignorados.

Se o usuário decidir abandonar essa questão, basta enviar um novo `question` / `message` diretamente, e a plataforma marcará automaticamente a chamada de ferramenta pausada como "usuário ignorou".

## Gerenciamento de sessões (CRUD)

O v2 oferece gerenciamento leve de sessões por meio do campo `action` no mesmo endpoint, sem necessidade de criar APIs adicionais.

### `action: retrieve` —— Recuperar uma sessão

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Retorna o documento completo da sessão (incluindo o histórico de `messages`, `model`, `title`, `tools_used` etc.).

### `action: retrieve_batch` —— Listar resumos das sessões

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Retorna `{ items: [...], total }`. **Os resumos não incluem `messages`**, sendo adequados para exibição em uma lista na barra lateral; quando o usuário abrir uma sessão, use `action: retrieve` para recuperar separadamente todas as mensagens dessa sessão.

Parâmetros de filtragem opcionais: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Alterar o título ou reescrever o histórico

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Plano de viagem para Hangzhou"
}
```

Também é possível enviar `messages`, mas o servidor realizará uma validação rigorosa do schema (deve estar no formato `ToolUseContent` já consolidado); caso contrário, será retornado o erro 400. Em geral, recomenda-se usar essa operação apenas para alterar o `title`.

### `action: delete` —— Excluir uma sessão

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Retorna `{ id, success: true }`. Após a exclusão, não será possível recuperar a sessão. Confirme antes de executar a chamada.

## Migração tranquila da v1

Se você já estiver usando [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), a migração para a v2 praticamente não exige alterações no código:

1. Altere a URL de `https://api.acedata.cloud/aichat/conversations` para `https://api.acedata.cloud/aichat2/conversations`.
2. Se anteriormente você utilizava nomes de modelos da v1 (como `gpt-3.5`, `gpt-4-browsing` etc.), recomenda-se atualizar para modelos atuais ao migrar para a v2 (como `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview` etc.).
3. Os campos do fluxo NDJSON permanecem compatíveis com versões anteriores: cada evento `text_delta` continua incluindo `delta_answer` e `id`. Portanto, os clientes que originalmente analisavam `delta_answer` linha por linha não precisam de alterações.

Após a migração, você poderá habilitar os novos recursos da v2 conforme necessário (mensagens multimodais `message`, SSE, chamadas de ferramentas, CRUD por meio de `action`), avançando no seu próprio ritmo.

## Tratamento de erros

As respostas de erro seguem um formato unificado:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Erros comuns:

- `400 bad_request`: ausência de campos obrigatórios, incompatibilidade de `tool_use_id`, schema de `messages` inválido etc.
- `401 invalid_token`: cabeçalho `authorization` incorreto.
- `404 not_found`: a sessão correspondente ao `id` não existe durante uma operação `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: a sessão excedeu o limite de armazenamento, sem substituir os registros salvos existentes.
- `429 too_many_requests`: limite de taxa atingido.
- `503 context_compaction_failed`: falha na compactação do contexto; os registros existentes são preservados.
- `500 conversation_persist_failed`: falha ao salvar definitivamente a rodada atual; o fato de o texto ter sido recebido não significa que o registro final tenha sido salvo com sucesso. Consulte a sessão pelo ID.
- `500 chat_error`: o serviço está temporariamente indisponível ou nenhum conteúdo foi gerado nesta rodada (nenhuma cobrança será realizada).

Nas respostas em fluxo, os erros são enviados como eventos `{"type":"error","message":"..."}`, após os quais o fluxo será encerrado. `[DONE]` indica apenas o fim da transmissão; se houver um evento `error`, a operação não deve ser considerada bem-sucedida, e nenhum evento `done` de sucesso será enviado.

## Conclusão

A API AI Chat v2, mantendo a compatibilidade com versões anteriores da v1, transforma as conversas de "perguntas e respostas de uma ou várias rodadas" em "conversas observáveis baseadas em agentes": entrada multimodal, chamadas de ferramentas, possibilidade de pausa e retomada, eventos estruturados em fluxo e CRUD integrado. Recomenda-se utilizar diretamente a v2 para novas integrações; as integrações existentes da v1 podem ser migradas gradualmente e sem interrupções.
