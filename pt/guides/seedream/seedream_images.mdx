Este artigo apresentará uma instrução de integração da API SeeDream Images Generation, que pode gerar imagens oficiais do SeeDream por meio da inserção de parâmetros personalizados.

## Processo de solicitação

Para usar a API SeeDream Images Generation, primeiro acesse o [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e guarde-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não fez login ou não se registrou, será automaticamente redirecionado para a página de login para convidá-lo a se registrar e fazer login, e retornará automaticamente à página atual após a conclusão.

**Um API Token pode chamar todos os serviços da plataforma, sem a necessidade de solicitar separadamente para cada serviço.** A primeira solicitação oferecerá créditos gratuitos para uma experiência gratuita; quando os créditos forem insuficientes, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [SeeDream Images Generation API →](https://platform.acedata.cloud/documents/seedream-images)

## Uso básico

Primeiro, vamos entender o método básico de uso: basta inserir o texto de instrução `prompt`, a ação de geração `action` e o tamanho da imagem `size` para obter o resultado processado. Primeiro, é necessário transmitir simplesmente um campo `action`, cujo valor é `generate`, e então também precisamos inserir o texto de instrução. O conteúdo específico é o seguinte:

<p><img src="https://cdn.acedata.cloud/seedream_request_body.png" width="500" className="m-auto" /></p>

Podemos ver que aqui configuramos os Request Headers, incluindo:

- `accept`: qual formato de resultado de resposta você deseja receber; aqui preencha com `application/json`, ou seja, formato JSON.
- `authorization`: a chave para chamar a API, que pode ser selecionada diretamente na lista suspensa após a solicitação.

Além disso, configuramos o Request Body, incluindo:

- `prompt`: texto de instrução.
- `model`: modelo de geração, o padrão é `doubao-seedream-5-0-lite-260128` (SeeDream 5.0 Lite, mais recente). Compatível com `doubao-seedream-5-0-pro-260628`, `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828`. Entre eles, `doubao-seedream-5-0-pro-260628` (SeeDream 5.0 Pro) é um modelo carro-chefe de imagem única, gerando apenas uma imagem, **não sendo compatível com grupo de imagens (`sequential_image_generation`), streaming (`stream`) e pesquisa na web (`tools`)**. **`model` deve receber a string completa do modelo (como `doubao-seedream-5-0-lite-260128`); transmitir uma abreviação como `doubao-seedream-5.0-lite` retornará 400.**
- `image`: informações da imagem de entrada, compatível com URL ou codificação Base64. `doubao-seedream-5-0-pro-260628` é compatível com entrada de uma ou várias imagens (até 10 imagens), enquanto `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` são compatíveis com entrada de uma ou várias imagens.
- `size`: especifica as informações de tamanho da imagem gerada e oferece suporte às duas formas a seguir, que não podem ser misturadas. Método 1 | Especificar a resolução da imagem gerada e descrever a proporção de largura e altura da imagem em linguagem natural no prompt. **As predefinições compatíveis variam entre os modelos**: `doubao-seedream-5-0-pro-260628` é compatível com `1K`/`1.5K`/`2K`; `doubao-seedream-5-0-lite-260128` é compatível com `2K`/`3K`/`4K`; `doubao-seedream-4-5-251128` é compatível apenas com `2K`/`4K`; `doubao-seedream-4-0-250828` é compatível com `1K`/`2K`/`4K`. Método 2 | Especificar os valores de pixels de largura e altura da imagem gerada: o padrão é `2048x2048`, e o intervalo de valores de pixels totais e de proporção de largura e altura varia conforme o modelo (por exemplo, o intervalo de pixels totais do 5.0 Pro é [921600, 4624220], o limite inferior de pixels totais do 5.0 Lite / 4.5 é 3,686,400, e o limite inferior do 4.0 é 921,600).
- `sequential_image_generation`: grupo de imagens: um grupo de imagens com conteúdo relacionado, gerado com base no conteúdo inserido por você. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` são compatíveis com esse parâmetro, cujo padrão é `disabled`.
- `stream`: controla se o modo de saída em streaming é ativado. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` são compatíveis com esse parâmetro, cujo padrão é `false`.
- `response_format`: especifica o formato de retorno da imagem gerada. O padrão é `url`, e `b64_json` também é compatível.
- `watermark`: se deve adicionar uma marca d'água à imagem gerada. O padrão é `true`.
- `output_format`: especifica o formato de arquivo da imagem gerada, compatível com `jpeg` (padrão) e `png`. Compatível apenas com `doubao-seedream-5-0-pro-260628` e `doubao-seedream-5-0-lite-260128`.
- `tools`: configura as ferramentas que o modelo deve chamar; atualmente, há suporte para `web_search` (pesquisa na web). Compatível apenas com Seedream 5.0 Lite.
- `optimize_prompt_options`: configuração de otimização de texto de instrução. O 5.0 Pro é compatível com `standard`/`fast`; o 5.0 Lite e o 4.5 são compatíveis apenas com `standard`; o 4.0 é compatível com `standard`/`fast`.
- `background`: compatível apenas com edição de imagem única do 5.0 Pro. `transparent` exige a entrada de uma PNG com canal de transparência, e `output_format` deve ser `png`; `opaque` corresponde a um fundo opaco comum.
- `layer_decomposition`: compatível apenas com 5.0 Pro. Quando definido como `true`, deve ser inserida uma PNG/JPEG; é possível não transmitir `prompt` para separar automaticamente, ou usar linguagem natural/`<bbox>` para especificar elementos; `size` é compatível com `auto`/`1K`/`1.5K`/`2K`. Esse modo não pode ser usado junto com grupo de imagens, streaming, pesquisa na web ou `background`.
- `callback_url`: URL que precisa receber o resultado de retorno de chamada.
- `async`: se deve processar no modo assíncrono. Quando definido como `true`, a interface retorna imediatamente `task_id`, sem a necessidade de fornecer `callback_url`; em seguida, obtenha o resultado por polling através de `/seedream/tasks`.

Além disso, se quiser gerar o código de integração correspondente, você pode copiá-lo diretamente. Por exemplo, o código CURL é o seguinte:

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "doubao-seedream-5-0-lite-260128",
  "prompt": "A single matte blue cube centered on a clean white studio background, neutral lighting"
}'
```

## Tarefa de edição de imagens

Se quiser editar uma imagem, primeiro o parâmetro `image` deve receber o link da imagem que precisa ser editada

- model: o modelo adotado para esta tarefa de edição de imagens; `doubao-seedream-5-0-pro-260628`, `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` oferecem suporte à entrada de imagens.
- image: envie a imagem que precisa ser editada, uma ou várias

O exemplo de preenchimento é o seguinte:

<p><img src="https://cdn.acedata.cloud/seedream_edit.png" width="500" className="m-auto" /></p>

O código correspondente:

```python
import requests

url = "https://api.acedata.cloud/seedream/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedream-4-0-250828",
  "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
  "image": ["https://ark-project.tos-cn-beijing.volces.com/doc_image/seedream4_5_imageToimage.png"],
  "size": "2K",
  "watermark": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Clique em executar, e você poderá perceber que um resultado será obtido imediatamente, como segue:

```json
{
  "success": true,
  "task_id": "c9aaffa2-b8ac-40ff-8468-43e77cb9ddde",
  "trace_id": "131a40c3-2eaf-44c9-af28-c9b408577286",
  "data": [
    {
      "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
      "size": "2048x2048",
      "image_url": "https://platform.cdn.acedata.cloud/seedream/3e88db7e-4771-4f6a-adbd-5ae4590c5d59.jpg"
    }
  ]
}
```

Pode-se ver que o efeito gerado é o efeito de edição da imagem original, e o resultado é semelhante ao descrito acima.

## Separação de camadas (Seedream 5.0 Pro)

A separação de camadas divide uma imagem de entrada em 1 imagem de fundo e até 16 camadas PNG transparentes que podem ser editadas de forma independente. A solicitação abaixo permite que o modelo reconheça automaticamente os elementos principais; se precisar especificar elementos, você pode adicionar `prompt`, e também pode usar coordenadas `<bbox>` normalizadas no texto de instrução.

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "https://example.com/poster.png",
  "layer_decomposition": true,
  "size": "2K",
  "watermark": false
}'
```

O `data` retornado é organizado de baixo para cima conforme o `z_index`. O `z_index` da imagem de fundo é 0; as camadas também incluem `name`, `description` e `bounding_box.absolute`/`normalized`. Ao recompor usando coordenadas absolutas, dimensione a camada para `[right-left, bottom-top]`, coloque-a em `[left, top]` e, em seguida, empilhe-as em ordem crescente de `z_index`. Se a geração de qualquer camada falhar, toda a separação falhará.

## Saída em streaming

Quando Lite/4.x define `stream: true`, use `accept: application/x-ndjson` no cabeçalho da solicitação. A interface retorna, linha por linha, `image_generation.partial_succeeded` ou `image_generation.partial_failed`, e por fim retorna o único evento `image_generation.completed` e o `usage` final; somente o evento de conclusão aciona uma cobrança. O modo de streaming não pode ser usado junto com `async` ou `callback_url`.

## Retorno de chamada assíncrono

Como o tempo de geração da SeeDream Images Generation API é relativamente longo, aproximadamente 1 a 2 minutos, se a API não responder por um longo período, a solicitação HTTP manterá a conexão aberta, causando consumo adicional de recursos do sistema. Portanto, esta API também oferece suporte a retornos de chamada assíncronos.

O fluxo geral é: quando o cliente inicia uma solicitação, ele especifica adicionalmente um campo `callback_url`. Depois que o cliente inicia a solicitação à API, a API retorna imediatamente um resultado contendo um campo `task_id`, que representa o ID da tarefa atual. Quando a tarefa é concluída, o resultado da geração da imagem será enviado na forma de POST JSON para o `callback_url` especificado pelo cliente, incluindo também o campo `task_id`, para que o resultado da tarefa possa ser associado pelo ID.

Se você não tiver um endereço público disponível para retorno de chamada, também poderá não especificar `callback_url` e definir o campo `async` como `true` na solicitação. Nesse momento, a interface também retornará imediatamente o `task_id`, mas não enviará o resultado; você precisará usar esse `task_id` para chamar a interface `/seedream/tasks` e consultar o status da tarefa para obter o resultado final.

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código de erro e as informações correspondentes. Por exemplo:

- `400 token_mismatched`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`：Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`：Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`：Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
