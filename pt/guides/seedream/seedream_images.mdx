Este artigo apresentará as instruções de integração da API de Geração de Imagens SeeDream, que permite gerar imagens oficiais do SeeDream por meio da inserção de parâmetros personalizados.

## Processo de Solicitação

Para utilizar a API de Geração de Imagens SeeDream, primeiro acesse o [painel de controle do Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e guardá-lo para uso posterior.

![]()

Se você ainda não estiver conectado ou registrado, será redirecionado automaticamente para a página de login, onde será convidado a se registrar e fazer login. Após a conclusão, retornará automaticamente à página atual.

**Um único API Token pode ser utilizado para chamar todos os serviços da plataforma, sem necessidade de solicitar um token separadamente para cada serviço.** Na primeira solicitação, você receberá uma cota gratuita para experimentar o serviço sem custos; quando a cota for insuficiente, você poderá recarregar o saldo geral no [painel de controle](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [API de Geração de Imagens SeeDream →](https://platform.acedata.cloud/documents/seedream-images)

## Seleção do Modelo

| Modelo | Cenários de utilização |
| ----------------------------------------------------------- | -------------------------------- |
| `doubao-seedream-5-5-261028` | Edição em várias etapas, geração de imagens transparentes a partir de texto, edição transparente com várias imagens de referência, separação de camadas e reconhecimento de camadas de texto |
| `doubao-seedream-5-0-flash-260915` | Geração de imagem única com baixa latência, edição com várias imagens de referência, edição de imagens transparentes e separação de camadas |
| `doubao-seedream-5-0-pro-260628` | Geração de imagem única, edição detalhada, edição de imagens transparentes e separação de camadas |
| `doubao-seedream-5-0-lite-260128` | Imagem única, conjunto de imagens, saída em fluxo e pesquisa na Internet |
| `doubao-seedream-4-5-251128` / `doubao-seedream-4-0-250828` | Geração e edição de imagens das versões anteriores |

O 5.5 e o 5.0 Flash utilizam o mesmo `POST /seedream/images`, ambos oferecem suporte a `1K`, `1.5K`, `2K` e até 10 imagens de referência. As tarefas de separação de camadas dos dois modelos aceitam apenas uma imagem e retornam uma URL. No 5.5, é possível definir `layer_decomposition_options: {"max_images": 12, "text_recognition": true}`. É possível gerar até 100 imagens (incluindo a imagem de fundo), e as camadas de texto reconhecidas retornam o texto linha por linha e seus estilos em `data[].text_recognition`. O 5.0 Flash retorna no máximo 1 imagem de fundo e 16 camadas.

O 5.5 oferece suporte à geração direta de PNG transparente usando `background: "transparent"`. A edição de imagens transparentes no 5.0 Flash requer uma imagem de referência com canal de transparência. O 5.5 cobra de acordo com a categoria de pixels da imagem gerada com sucesso e adiciona 0.13 Credits por cada imagem de referência de entrada. O 5.0 Flash cobra 0.31 Credits por cada imagem gerada com sucesso, e as imagens de referência são gratuitas. A separação de camadas é cobrada de acordo com o número real de imagens geradas com sucesso, incluindo a imagem de fundo. Consulte os [preços em tempo real](https://platform.acedata.cloud/services/seedream?tab=pricing).

## Utilização Básica

Primeiro, vamos entender o método básico de utilização: basta inserir o prompt `prompt`, o comportamento de geração `action` e o tamanho da imagem `size` para obter o resultado processado. Inicialmente, é necessário transmitir simplesmente um campo `action`, cujo valor é `generate`. Em seguida, também precisamos inserir o prompt. O conteúdo específico é o seguinte:

<p><img src="https://cdn.acedata.cloud/seedream_request_body.png" width="500" className="m-auto" /></p>

Como podemos ver, aqui configuramos os Request Headers, incluindo:

- `accept`: Que formato de resposta você deseja receber? Aqui, preenchemos com `application/json`, ou seja, o formato JSON.
- `authorization`: A chave para chamar a API, que pode ser selecionada diretamente no menu suspenso após a solicitação.

Além disso, configuramos o Request Body, incluindo:

- `prompt`: Prompt.
- `model`: Insira o ID completo do modelo apresentado na tabela acima.
- `image`: URL da imagem de entrada, string Base64 ou array. O 5.5, o 5.0 Pro e o 5.0 Flash aceitam no máximo 10 imagens de referência.
- `size`: Categoria de resolução ou `larguraxaltura`. O 5.5, o 5.0 Pro e o 5.0 Flash oferecem suporte a `1K`, `1.5K` e `2K`. O 5.0 Lite oferece suporte a `2K`, `3K` e `4K`.
- `sequential_image_generation`: Geração de conjuntos de imagens: com base no conteúdo inserido por você, gera um conjunto de imagens relacionadas entre si. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128` e `doubao-seedream-4-0-250828` oferecem suporte a esse parâmetro, cujo valor padrão é `disabled`.
- `stream`: Controla se o modo de saída em fluxo será ativado. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128` e `doubao-seedream-4-0-250828` oferecem suporte a esse parâmetro, cujo valor padrão é `false`.
- `response_format`: Especifica o formato de retorno das imagens geradas. O padrão é `url`, mas também oferece suporte a `b64_json`.
- `watermark`: Define se uma marca-d'água será adicionada às imagens geradas. O valor padrão é `true`.
- `output_format`: O formato de saída pode ser `jpeg` ou `png`. O padrão do 5.5 é PNG, enquanto o padrão do 5.0 Pro/Flash/Lite é JPEG.
- `tools`: Configura as ferramentas que o modelo deve chamar. Atualmente, oferece suporte a `web_search` (pesquisa na Internet). Apenas o Seedream 5.0 Lite oferece suporte a esse recurso.
- `optimize_prompt_options`: Configurações de otimização do prompt. O 5.0 Pro oferece suporte a `standard`/`fast`; o 5.5, o 5.0 Flash, o 5.0 Lite e o 4.5 oferecem suporte apenas a `standard`; o 4.0 oferece suporte a `standard`/`fast`.
- `background`: Oferece suporte a `transparent` e `opaque`. O 5.5 também oferece suporte a `auto`. A saída transparente utiliza PNG.
- `layer_decomposition`: Oferecido pelo 5.5, 5.0 Pro e 5.0 Flash. Quando definido como `true`, é necessário inserir uma imagem PNG/JPEG. É possível omitir `prompt` para realizar a separação automática ou utilizar linguagem natural/`<bbox>` para especificar os elementos; `size` oferece suporte a `auto`/`1K`/`1.5K`/`2K`. Esse modo não pode ser utilizado em conjunto com geração de conjuntos de imagens, saída em fluxo, pesquisa na Internet ou `background`.
- `callback_url`: URL para receber os resultados por meio de um callback.
- `async`: Define se o processamento será realizado no modo assíncrono. Quando definido como `true`, a interface retorna imediatamente um `task_id`, sem necessidade de fornecer `callback_url`. Posteriormente, é possível consultar os resultados por meio de `/seedream/tasks`.

Além disso, se você quiser gerar o código de integração correspondente, poderá simplesmente copiá-lo diretamente. Por exemplo, o código CURL é o seguinte:

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "doubao-seedream-5-0-lite-260128",
  "prompt": "A single matte blue cube centered on a clean white studio background, neutral lighting"
}'
```

## Tarefa de edição de imagens

Se você quiser editar uma determinada imagem, primeiro, o parâmetro `image` deve receber o link da imagem que precisa ser editada.

- model: informe o ID completo do modelo compatível com a edição de imagens na tabela acima.
- image: carregue a imagem que precisa ser editada, uma ou várias.

O exemplo de preenchimento é o seguinte:

<p><img src="https://cdn.acedata.cloud/seedream_edit.png" width="500" className="m-auto" /></p>

O código correspondente:

```python
import requests

url = "https://api.acedata.cloud/seedream/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedream-4-0-250828",
  "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
  "image": ["https://ark-project.tos-cn-beijing.volces.com/doc_image/seedream4_5_imageToimage.png"],
  "size": "2K",
  "watermark": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Ao clicar em executar, você verá que um resultado será obtido imediatamente, conforme mostrado abaixo:

```json

  "success": true,
  "task_id": "c9aaffa2-b8ac-40ff-8468-43e77cb9ddde",
  "trace_id": "131a40c3-2eaf-44c9-af28-c9b408577286",
  "data": [
    {
      "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
      "size": "2048x2048",
      "image_url": "https://platform.cdn.acedata.cloud/seedream/3e88db7e-4771-4f6a-adbd-5ae4590c5d59.jpg"
    }
  ]

```

Como podemos ver, o efeito gerado corresponde à edição da imagem original, e o resultado é semelhante ao apresentado acima.

## Separação de camadas (Seedream 5.0 Pro)

A separação de camadas divide uma imagem de entrada em uma imagem de fundo e até 16 camadas PNG transparentes que podem ser editadas independentemente. A solicitação a seguir permite que o modelo identifique automaticamente os elementos principais; se precisar especificar os elementos, você pode adicionar `prompt` ou usar coordenadas normalizadas `<bbox>` no texto do prompt.

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "https://example.com/poster.png",
  "layer_decomposition": true,
  "size": "2K",
  "watermark": false
}'
```

O `data` retornado é organizado de baixo para cima, de acordo com `z_index`. A imagem de fundo tem `z_index` igual a 0; as camadas também incluem `name`, `description` e `bounding_box.absolute`/`normalized`. Ao recompor usando coordenadas absolutas, redimensione a camada para `[right-left, bottom-top]`, posicione-a em `[left, top]` e, em seguida, sobreponha as camadas em ordem crescente de `z_index`. Se a geração de qualquer camada falhar, toda a operação de separação falhará.

## Saída em fluxo

Quando `stream: true` estiver definido no Lite/4.x, o cabeçalho da solicitação deverá usar `accept: application/x-ndjson`. A interface retornará uma linha por vez, com `image_generation.partial_succeeded` ou `image_generation.partial_failed`, e, por fim, retornará um único evento `image_generation.completed` e o `usage` final; somente o evento de conclusão acionará a cobrança uma vez. O modo de fluxo não pode ser usado em conjunto com `async` ou `callback_url`.

## Retorno de chamada assíncrono

Como o tempo de geração da SeeDream Images Generation API é relativamente longo, levando aproximadamente de 1 a 2 minutos, se a API não responder por muito tempo, a solicitação HTTP permanecerá conectada, causando consumo adicional de recursos do sistema. Por isso, esta API também oferece suporte a retornos de chamada assíncronos.

O fluxo geral é o seguinte: quando o cliente inicia uma solicitação, especifica adicionalmente um campo `callback_url`. Depois que o cliente envia a solicitação à API, a API retorna imediatamente um resultado contendo um campo `task_id`, que representa o ID da tarefa atual. Quando a tarefa for concluída, o resultado da imagem gerada será enviado ao `callback_url` especificado pelo cliente por meio de uma solicitação POST JSON, que também incluirá o campo `task_id`. Dessa forma, os resultados das tarefas poderão ser associados por meio do ID.

Se você não tiver um endereço público disponível para receber retornos de chamada, também poderá deixar de especificar `callback_url` e definir o campo `async` como `true` na solicitação. Nesse caso, a interface também retornará imediatamente o `task_id`, mas não enviará o resultado. Você precisará usar esse `task_id` para chamar a interface `/seedream/tasks` e consultar o status da tarefa até obter o resultado final.

A seguir, vamos entender como realizar a operação específica por meio de um exemplo.

Ao clicar em executar, você verá que um resultado será obtido imediatamente, conforme mostrado abaixo:

## Tratamento de erros

Ao chamar a API, se ocorrer algum erro, a API retornará o código e as informações correspondentes. Por exemplo:

- `400 token_mismatched`: Solicitação inválida, possivelmente devido à ausência de parâmetros ou a parâmetros inválidos.
- `400 api_not_implemented`: Solicitação inválida, possivelmente devido à ausência de parâmetros ou a parâmetros inválidos.
- `401 invalid_token`: Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`: Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`: Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
