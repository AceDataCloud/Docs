Este documento apresenta uma instrução para integração da API de Reconhecimento e Verificação de Identidade, que pode validar a autenticidade e consistência do nome e número de identidade através da imagem do documento ou do nome e número de identidade. Esta interface é usada para verificar a autenticidade e consistência do nome e número de identidade, podendo fornecer as informações necessárias para validação através do nome e número de identidade ou da foto do lado do retrato do documento.

## Processo de Solicitação

Para usar a API de Reconhecimento e Verificação de Identidade, primeiro acesse o [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu Token de API para uso futuro.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver logado ou registrado, será redirecionado automaticamente para a página de login para se registrar e entrar, e após isso retornará automaticamente para esta página.

**Um único Token de API pode ser usado para chamar todos os serviços da plataforma, não é necessário solicitar separadamente para cada serviço.** Na primeira solicitação, será concedida uma cota gratuita para teste; quando a cota acabar, você pode recarregar saldo geral no [Console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [API de Reconhecimento e Verificação de Identidade →](https://platform.acedata.cloud/documents/identity-idcard-ocr)

## Uso Básico

Primeiro, entenda o modo básico de uso, que é inserir o link da imagem do documento para obter o resultado da validação processada. Inicialmente, é necessário passar um campo `image_url` simples, e então podemos preencher o conteúdo correspondente na interface, conforme mostrado na figura:

<p><img src="https://cdn.acedata.cloud/qxy9rh.png" width="500" className="m-auto" /></p>

Aqui configuramos os Cabeçalhos da Requisição, incluindo:

- `accept`: o formato desejado para a resposta, aqui preenchido como `application/json`, ou seja, formato JSON.
- `authorization`: a chave para chamar a API, que pode ser selecionada diretamente após a solicitação.

Também configuramos o Corpo da Requisição, incluindo:

- `image_url`: o link da imagem do documento a ser processada.
- `encryption`: opcional, parâmetro para criptografia de campos sensíveis (se for necessário enviar texto cifrado).

Após a seleção, você pode ver que o código correspondente é gerado no lado direito, conforme mostrado na figura:

<p><img src="https://cdn.acedata.cloud/uw90il.png" width="500" className="m-auto" /></p>

Clique no botão "Try" para testar, conforme mostrado na figura acima, e obteremos o seguinte resultado:

```json
{
  "result": "0",
  "description": "Nome e número de identidade coincidem",
  "name": "Nome do documento",
  "id_card": "Número do documento",
  "sex": "Sexo do documento",
  "nation": "Nacionalidade do documento",
  "birth": "Data de nascimento do documento",
  "address": "Endereço residencial do documento"
}
```

O resultado retornado contém vários campos, descritos a seguir:

- `result`, código do resultado da autenticação, com as seguintes condições de cobrança.
    - Códigos cobrados:
        - 0: Nome e número de identidade coincidem
        - -1: Nome e número de identidade não coincidem
    - Códigos não cobrados:
        - -2: Número de identidade inválido (comprimento, dígito verificador incorreto, etc.)
        - -3: Nome inválido (comprimento, formato, etc.)
        - -4: Serviço da base de dados do documento com erro
        - -5: Nenhum registro deste documento na base de dados
        - -6: Sistema de comparação oficial em atualização, tente novamente mais tarde
        - -7: Limite diário de autenticações excedido.
- `description`, resultado da validação do nome e número de identidade.
- `name`, nome no documento, vazio se a imagem do documento não for enviada.
- `id_card`, número do documento, vazio se a imagem do documento não for enviada.
- `sex`, sexo no documento, vazio se a imagem do documento não for enviada.
- `nation`, nacionalidade no documento, vazio se a imagem do documento não for enviada.
- `birth`, data de nascimento no documento, vazio se a imagem do documento não for enviada.
- `address`, endereço residencial no documento, vazio se a imagem do documento não for enviada.

Pode-se observar que o nome e número de identidade no documento são consistentes e válidos, e outras informações também são extraídas e exibidas usando tecnologia OCR.

Além disso, se desejar gerar o código correspondente para integração, pode copiar diretamente o código gerado, por exemplo, o código CURL é o seguinte:

```shell
curl -X POST 'https://api.acedata.cloud/identity/idcard/ocr' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": {image_url}
}'
```

O código de integração em Python é o seguinte:

```python
import requests

url = "https://api.acedata.cloud/identity/idcard/ocr"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "image_url": {image_url}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Verificação Personalizada de Informações

Também oferecemos uma forma de verificar sem expor a imagem do documento, podendo apenas enviar o nome `name` e o número de identidade `id_card` para validar a autenticidade e consistência do nome e número de identidade. Abaixo está a informação preenchida:

<p><img src="https://cdn.acedata.cloud/mc5bbw.png" width="500" className="m-auto" /></p>

Após clicar em executar, obtemos o seguinte resultado:

```json
{
  "address": "",
  "birth": "",
  "description": "Nome e número de identidade coincidem",
  "id_card": "Número do documento",
  "name": "Nome do documento",
  "nation": "",
  "result": "0",
  "sex": ""
}
```

Assim, pelo resultado, outras informações privadas não são expostas, e ainda é possível validar a autenticidade e consistência do nome e número de identidade.

## Tratamento de Erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `400 token_mismatched`: Requisição inválida, possivelmente por parâmetros ausentes ou inválidos.
- `400 api_not_implemented`: Requisição inválida, possivelmente por parâmetros ausentes ou inválidos.
- `401 invalid_token`: Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`: Muitas requisições, limite de taxa excedido.
- `500 api_error`: Erro interno do servidor, algo deu errado no servidor.

### Exemplo de Resposta de Erro

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
