Este documento apresenta a integração e o uso da API de Consulta de Tarefas do MiniMax H3. Esta interface é utilizada para consultar, listar em massa ou excluir tarefas assíncronas criadas pela [API de Geração de Vídeos MiniMax H3](/documents/minimax-videos-integration).

## Processo de Solicitação

Para usar a API de Consulta de Tarefas do MiniMax H3, primeiro acesse o [Console da Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu Token de API, que deve ser guardado para referência futura.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver logado ou registrado, será redirecionado automaticamente para a página de login, onde será convidado a se registrar e fazer login. Após a conclusão, você será redirecionado de volta para a página atual.

**Um Token de API é suficiente para acessar todos os serviços da plataforma, não sendo necessário solicitar um para cada serviço individualmente.** A primeira solicitação oferece um crédito gratuito para que você possa experimentar; quando o crédito estiver baixo, você pode recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação Completa: [API de Consulta de Tarefas do MiniMax H3 →](https://platform.acedata.cloud/documents/minimax-tasks-integration)

Ao consultar uma tarefa, você deve usar o mesmo Token que foi utilizado para criar essa tarefa. Recomenda-se salvar o Token como uma variável de ambiente, não escrevê-lo no código-fonte ou enviá-lo para o repositório:

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Visão Geral da Interface

- **Base URL**: `https://api.acedata.cloud`
- **Endpoint**: `POST /minimax/tasks`
- **Método de Autenticação**: Inclua `authorization: Bearer {token}` no cabeçalho HTTP
- **Cabeçalhos da Solicitação**:
  - `accept: application/json`
  - `content-type: application/json`
- **Consultar uma Tarefa**: `action=retrieve`, forneça `id`
- **Consultar Tarefas em Massa**: `action=retrieve_batch`, pode filtrar por ID da tarefa, intervalo de tempo e condições de paginação
- **Excluir Tarefa**: `action=delete`, forneça `id`
- **Descrição de Cobrança**: A consulta de tarefas é gratuita e não gera cobranças duplicadas

Após criar o vídeo, é necessário salvar o `task_id`. Recomenda-se consultar a cada 10 segundos até que a tarefa entre em um estado final.

## Parâmetros da Solicitação

| Parâmetro            | Tipo      | Obrigatório | Ação Aplicável           | Descrição                                               |
| ------------------- | --------- | ----------- | ------------------------ | ------------------------------------------------------ |
| `action`            | string    | Não         | Todas                   | `retrieve`, `retrieve_batch` ou `delete`; padrão `retrieve` |
| `id`                | string    | Condicional | `retrieve`, `delete`    | ID de uma única tarefa                                   |
| `ids`               | string[]  | Não         | `retrieve_batch`        | Retorna apenas os IDs de tarefas especificados; se omitido, lista tarefas por outras condições |
| `limit`             | integer   | Não         | `retrieve_batch`        | Número máximo de tarefas a serem retornadas nesta solicitação |
| `offset`            | integer   | Não         | `retrieve_batch`        | Número de tarefas a serem puladas na lista de resultados, usado para paginação |
| `created_at_min`    | number    | Não         | `retrieve_batch`        | Limite inferior do tempo de criação, timestamp Unix, em segundos |
| `created_at_max`    | number    | Não         | `retrieve_batch`        | Limite superior do tempo de criação, timestamp Unix, em segundos |

As três ações têm os seguintes propósitos:

| `action`            | Propósito                          | Parâmetros Necessários                | Estrutura de Resposta                          |
| ------------------- | --------------------------------- | ------------------------------------- | --------------------------------------------- |
| `retrieve`          | Consultar o estado e resultado de uma tarefa | `id`                                 | `{ "task": {...} }`                           |
| `retrieve_batch`    | Consultar em massa por ID de tarefa, tempo e condições de paginação | Parâmetros opcionais `ids`, intervalo de tempo, `offset`, `limit` | `{ "items": [...], "total": number }`       |
| `delete`            | Cancelar ou excluir o registro da tarefa com base no estado atual | `id`                                 | `{ "id": "...", "deleted": true }`          |

## Consultar uma Tarefa

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f5977217-ed2c-40da-adbe-93d08235618f"
  }'
```

## Estado da Tarefa

| `status`    | Significado                     | Tratamento do Cliente               |
| ----------- | ------------------------------- | ----------------------------------- |
| `queued`    | Entrou na fila, aguardando execução | Continue a consultar                 |
| `running`   | Em processo de geração         | Continue a consultar                 |
| `succeeded` | Geração bem-sucedida           | Leia `task.content.url`, pare de consultar |
| `failed`    | Geração falhou                 | Leia `task.error`, pare de consultar  |
| `cancelled` | Tarefa cancelada               | Pare de consultar                   |

Os estados `succeeded`, `failed` e `cancelled` são estados finais. Não continue a consultar após entrar em um estado final.

## Campos de Resposta da Tarefa

| Campo                      | Tipo     | Descrição                                         |
| ------------------------- | -------- | ------------------------------------------------- |
| `id`                      | string   | ID da tarefa                                      |
| `model`                   | string   | Modelo utilizado pela tarefa, atualmente `MiniMax-H3` |
| `status`                  | string   | Estado atual da tarefa                            |
| `error.code`              | string   | Código de erro em caso de falha, retornado apenas em caso de falha |
| `error.message`           | string   | Motivo da falha, retornado apenas em caso de falha |
| `created_at`              | integer  | Data de criação, timestamp Unix, em segundos     |
| `updated_at`              | integer  | Data da última atualização de estado, timestamp Unix, em segundos |
| `content.url`             | string   | URL do vídeo após sucesso                         |
| `resolution`              | string   | Resolução de saída, `768P` ou `2K`               |
| `duration`                | integer  | Duração do vídeo de saída, em segundos            |
| `usage.total_seconds`     | integer  | Quantidade total de cobrança, igual à soma dos segundos do vídeo de entrada e saída |
| `usage.input_seconds`     | integer  | Quantidade de cobrança gerada pelo vídeo de entrada |
| `usage.output_seconds`    | integer  | Quantidade de cobrança gerada pelo vídeo de saída  |
| `usage.input_image_count` | integer  | Número de imagens de entrada na contagem de cobrança |
| `ratio`                   | string   | Proporção de aspecto real de saída; quando `adaptive`, este resultado é o que conta |
| `task_type`               | string   | Tarefa de geração de vídeo é `generation`        |
| `modality`                | string   | Tarefa de vídeo é `video`                         |

## Exemplo Completo de Polling em Python
以下代码从环境变量读取 Token，创建任务后每隔 10 秒查询一次：

```python
import os
import time

import requests

BASE_URL = "https://api.acedata.cloud"
HEADERS = {
    "Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_KEY']}",
    "Content-Type": "application/json",
}

create_response = requests.post(
    f"{BASE_URL}/minimax/videos",
    headers=HEADERS,
    json={
        "model": "MiniMax-H3",
        "content": [
            {
                "type": "text",
                "text": "Na manhã, à beira-mar, um veleiro branco navega por uma superfície de água calma, a câmera se move lentamente.",
            }
        ],
        "resolution": "768P",
        "duration": 4,
        "ratio": "16:9",
    },
    timeout=30,
)
create_response.raise_for_status()
task_id = create_response.json()["task_id"]

while True:
    time.sleep(10)
    query_response = requests.post(
        f"{BASE_URL}/minimax/tasks",
        headers=HEADERS,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    query_response.raise_for_status()
    task = query_response.json()["task"]
    print(f"task={task_id} status={task['status']}")

    if task["status"] == "succeeded":
        print(f"video_url={task['content']['url']}")
        break
    if task["status"] in ("failed", "cancelled"):
        raise RuntimeError(task.get("error") or task["status"])
```

Produção deve ter um tempo limite total para polling e usar backoff exponencial para `429` e temporários `5xx`. O tempo limite de rede não é igual a falha de geração, pode-se continuar consultando com o mesmo `task_id`.

## Consulta em Lote

Especificar múltiplos IDs de tarefa:

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve_batch",
    "ids": ["TASK_ID_1", "TASK_ID_2"],
    "offset": 0,
    "limit": 20
  }'
```

Listar tarefas paginadas por intervalo de tempo:

```json
{
  "action": "retrieve_batch",
  "created_at_min": 1786000000,
  "created_at_max": 1786200000,
  "offset": 0,
  "limit": 20
}
```

Na resposta em lote, `items` usa o mesmo campo de tarefa que a consulta de tarefa única, `total` é o número total de tarefas que correspondem aos critérios de filtragem:

```json
{
  "items": [
    {
      "id": "TASK_ID_1",
      "model": "MiniMax-H3",
      "status": "running",
      "resolution": "2K",
      "duration": 5,
      "ratio": "adaptive",
      "task_type": "generation",
      "modality": "video"
    }
  ],
  "total": 1
}
```

A janela de consulta de tarefas é de 7 dias. IDs de tarefa que excedem essa janela podem retornar tarefas inválidas; o sistema de negócios deve salvar o ID ao criar a tarefa e persistir a URL do resultado assim que for bem-sucedido.

## Cancelar ou Deletar Tarefas

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "delete",
    "id": "YOUR_TASK_ID"
  }'
```

A ação depende do estado atual da tarefa:

| Estado Atual        | Ação            |
| ----------- | ------------- |
| `queued`    | Cancelar tarefa que ainda não começou     |
| `succeeded` | Deletar registro da tarefa        |
| `failed`    | Deletar registro da tarefa        |
| `running`   | Não é permitido deletar ou cancelar, retorna erro |
| `cancelled` | Não é permitido repetir a operação, retorna erro  |

Exemplo de deleção bem-sucedida:

```json
{
  "id": "YOUR_TASK_ID",
  "deleted": true
}
```

Deletar o registro da tarefa não reverte a cobrança já concluída, nem garante que a cópia do vídeo salva também seja deletada.

## Respostas de Falha e Diagnóstico

Tarefas falhadas ainda retornam o objeto da tarefa com HTTP 200, e a razão é dada em `task.error`:

```json
{
  "task": {
    "id": "YOUR_TASK_ID",
    "model": "MiniMax-H3",
    "status": "failed",
    "error": {
      "code": "1026",
      "message": "a descrição do vídeo contém conteúdo sensível"
    },
    "task_type": "generation",
    "modality": "video"
  }
}
```

Quando a interface retorna `400`, deve-se verificar `action` e parâmetros de condição, `401` indica que o Token é inválido, `429` indica que a consulta é muito frequente, `500` indica que o serviço está temporariamente indisponível. Tarefas que falham na geração não são cobradas; tarefas bem-sucedidas registram o uso de acordo com o `usage` final.
