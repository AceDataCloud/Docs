---
title: "API de verificação de disponibilidade de áudio e persona do Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` aceita um ID de recurso. Para consultar uma música, envie `audio_id`; para consultar uma persona, envie `persona_id`; um dos dois é obrigatório. A verificação é concluída de forma síncrona, requer um Token de API e atualmente não desconta Credits.

## Solicitação

`audio_id` vem de uma tarefa de música concluída e pode ser usado para verificação antes de continuar ou fazer um cover.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

`persona_id` vem do resultado da criação de persona. Use a aplicação original e a identidade do chamador, e envie o seguinte corpo de solicitação na rota de criação que oferece suporte à consulta de persona.

```json
{
  "persona_id": "33333333-3333-4333-8333-333333333333"
}
```

## Resposta

Os dois tipos de solicitação usam a mesma resposta de sucesso. `data.id` é o ID do recurso desta consulta.

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

`available: true` indica que esta verificação obteve evidências positivas. Para personas, a verificação confirma a atribuição da criação e confirma que a conta associada está atualmente reportada como online. O resultado real da geração ainda prevalece conforme a tarefa de geração.

Personas privadas clonadas criadas por meio de `/suno/voices` dependem da conta de criação. Quando é confirmado que essa conta está atualmente offline, a interface retorna HTTP 200, e `data` é exemplificado abaixo.

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

O cliente pode marcar essa persona como atualmente indisponível e consultar novamente mais tarde.

Quando não puder ser confirmado, retorna HTTP 503 e `availability_unknown`, por exemplo, quando o recurso não é encontrado, registros antigos não possuem a rota de criação ou a consulta expira. Estilos de cantores públicos podem ser usados entre contas e também retornam 503 quando a conta de criação está offline. Consultas de músicas ainda retornam `available: true` somente quando a disponibilidade é confirmada.

Cada solicitação envia apenas um UUID válido. Todas as rotas retornam HTTP 400 ao receber solicitações com ambos os IDs ou com ambos os IDs ausentes. Rotas que oferecem suporte apenas à consulta de músicas retornam HTTP 400 ao receber solicitações contendo somente `persona_id`. Ao encontrar HTTP 429, reduza a frequência das consultas.
