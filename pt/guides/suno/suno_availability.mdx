---
title: "API de Verificação de Disponibilidade de Áudio do Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` procura evidências positivas de que o áudio pode continuar a ser processado na rota atual com base no `audio_id`. Pode ser chamado antes de operações como continuação e cover; o resultado reflete apenas o estado no momento da verificação e não garante que uma operação específica será bem-sucedida. Esta API retorna de forma síncrona, requer um Token de API e atualmente não consome Credits.

`audio_id` é o ID da música retornado por uma tarefa concluída do Suno, não o `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Exemplo de resposta bem-sucedida:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

Quando a verificação for bem-sucedida, `data.available` será apenas `true`. O estado de “offline” retornado por algumas rotas não pode provar que operações posteriores, como continuação, não serão bem-sucedidas; portanto, esta API retorna `503 availability_unknown` quando não é possível confirmar e não retorna `false`. Um formato incorreto de `audio_id` retorna 400, e limitação de taxa ou falhas upstream também retornam respostas de erro. O estado ainda pode mudar entre a conclusão da verificação e a operação real.
