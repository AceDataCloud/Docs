Com a ampliação das aplicações de IA, vários tipos de programas de IA foram gradualmente popularizados. A IA já penetrou gradualmente em todos os aspectos do trabalho e da vida das pessoas. E os setores envolvidos pela IA também estão se tornando cada vez mais numerosos, desde a escrita inicial, até a educação médica, e agora a música.

Suno é uma plataforma profissional e de alta qualidade de criação de músicas e canções por IA, os usuários só precisam inserir simples palavras de sugestão em texto para gerar canções com vocais com base no estilo do gênero e na letra. Este gerador de música por IA foi desenvolvido por membros de equipes de empresas de tecnologia conhecidas como Meta, TikTok, Kensho e outras, com o objetivo de não precisar de nenhuma ferramenta de instrumento, permitindo que todos possam criar músicas maravilhosas.

Suno agora oferece suporte a `chirp-v6`, `chirp-v6-wild` e `chirp-v6-mini`. Recomenda-se usar `chirp-v6`; os nomes dos modelos antigos continuam compatíveis.

No entanto, o Suno oficial não fornece API, a AceDataCloud fornece um conjunto de APIs do Suno, simulando a integração oficial do Suno, podendo gerar de forma conveniente e rápida a música desejada.

## Solicitação e uso

Para usar a Suno Audios Generation API, primeiro obtenha seu API Token no [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications), para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver conectado ou registrado, será automaticamente redirecionado para a página de login para convidá-lo a se registrar e entrar, e após a conclusão retornará automaticamente à página atual.

**Um API Token pode chamar todos os serviços da plataforma, não sendo necessário solicitar separadamente para cada serviço.** A primeira solicitação oferecerá uma cota gratuita, permitindo uma experiência gratuita; quando a cota for insuficiente, você poderá recarregar o saldo universal no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Uso básico

Que tipo de música você quer, você pode inserir arbitrariamente um trecho de texto, por exemplo, se eu quiser gerar uma música sobre o Natal, posso inserir `a song for Christmas`, como mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Pode-se ver que aqui configuramos os Request Headers, incluindo:

- `accept`: qual formato de resultado de resposta deseja receber, aqui é preenchido como `application/json`, ou seja, formato JSON.
- `authorization`: a chave para chamar a API, após a solicitação, você pode selecioná-la diretamente no menu suspenso.

Além disso, configuramos o Request Body, incluindo:
- `action`: a ação desta tarefa de geração de música, o padrão é `generate`, incluindo principalmente: `extend`, `upload_extend`, `cover`, `upload_cover`, `replace_section`, `replace_section`, `concat`, `stems`, `all_stems`, `remaster`.
- `prompt`: o texto de prompt do modo de inspiração oficial do Suno (tem efeito quando `custom` é `false`), máximo de 500 caracteres.
- `model`: o modelo desta tarefa de geração de música. A série v6 inclui `chirp-v6`, `chirp-v6-wild` e `chirp-v6-mini`; os nomes de modelos antigos continuam compatíveis.
- `lyric`: o conteúdo da letra do modo personalizado oficial do Suno. `chirp-v3-5` e `chirp-v4` têm no máximo 3000 caracteres; `chirp-v4-5` e superiores (incluindo `chirp-v5`, `chirp-v5-5`) têm no máximo 5000 caracteres.
- `custom`: se deve usar o modo personalizado, o padrão é: `false`.
- `instrumental`: a opção de música instrumental do modo de inspiração oficial do Suno.
- `title`: o título da música do modo personalizado oficial do Suno. `chirp-v3-5`, `chirp-v4` têm no máximo 80 caracteres; `chirp-v4-5` e superiores têm no máximo 100 caracteres.
- `style`: o estilo musical do modo personalizado oficial do Suno. `chirp-v3-5` e `chirp-v4` têm no máximo 200 caracteres; `chirp-v4-5` e superiores (incluindo `chirp-v5`, `chirp-v5-5`) têm no máximo 1000 caracteres.
- `negative_tags`: estilos ou gêneros musicais que se deseja excluir dos resultados gerados no modo personalizado (quando `custom` é `true`).
- `audio_weight`: a proporção do áudio de referência enviado, intervalo de 0 a 1; quanto maior, maior a dependência do áudio de referência.
- `audio_id`: o ID da música de referência.
- `overpainting_start`/`overpainting_end`: os tempos inicial e final para adicionar vocais a uma música instrumental existente, em segundos.
- `underpainting_start`/`underpainting_end`: os tempos inicial e final para adicionar acompanhamento a uma música a cappella, em segundos.
- `persona_id`: o ID da música do artista.
- `continue_at`: o limite de continuação, em segundos. Por exemplo, 213.5 indica gerar o trecho subsequente a partir de 3 minutos e 33,5 segundos. `lyric` e `style` orientam apenas o novo conteúdo após o limite e não substituem a letra ou o canto antes do limite no áudio de origem.
- `style_influence`: o parâmetro avançado «Style Influence» no modo personalizado, intervalo de 0 a 1; quanto maior, mais se ajusta ao estilo selecionado.
- `replace_section_end`: o tempo final do trecho a substituir.
- `replace_section_start`: o tempo inicial do trecho a substituir.
- `vocal_gender`: controla a preferência por voz feminina ou masculina, voz feminina `f`, voz masculina `m`, válido para modelos 4.5 e superiores; é um item de preferência, não garantindo adesão estrita.
- `weirdness`: o parâmetro avançado «Weirdness» no modo personalizado, intervalo de 0 a 1; quanto maior, mais criativo e experimental.
- `duration`: a duração esperada da música, em segundos, deve ser um número inteiro, com intervalo de 10 a 360. Este parâmetro é usado para a geração de músicas no modo personalizado (quando `custom` é `true`). É uma orientação de tendência, e não uma restrição rígida: o modelo irá considerá-lo, mas não garante que seja alcançado; a duração real do produto final deve seguir o campo `duration` na resposta, normalmente sendo menor que o valor esperado.
- `lyric_prompt`: o prompt para gerar a letra, tem efeito se e somente se `custom` for `true` e `lyric` não for enviado.
- `callback_url`: a URL que precisa receber o resultado por callback.
- `async`: opcional, quando definido como `true`, a interface retorna imediatamente `task_id`, sem necessidade de fornecer `callback_url`; em seguida, obtenha o resultado por meio de polling usando a interface de consulta de tarefa correspondente.

## Geração personalizada

Se quiser gerar letras personalizadas, você pode inserir letras:

Neste momento, o campo `lyric` pode receber conteúdo semelhante ao seguinte:

```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> Observação: nas letras aqui, `\n` é um caractere de quebra de linha. Se você não souber como gerar letras, pode usar a API de geração de letras fornecida pela AceDataCloud para gerar letras por meio de prompt; a API é [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Em seguida, para gerar músicas personalizadas com base na letra, no título e no estilo, você pode especificar o seguinte conteúdo:

- lyric: texto da letra
- custom: preencha como `true`, representando geração personalizada; o padrão desse parâmetro é false, representando a geração usando `prompt`.
- title: título da música.
- style: estilo da música, opcional.

O código Python correspondente:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Funcionalidade de continuar gerando

Se quiser continuar gerando uma música Suno já gerada, é possível definir o parâmetro `action` como `extend`, e inserir o ID da música que precisa continuar a ser gerada. A obtenção do ID da música é feita com base no uso básico; pelo texto acima, é possível ver que neste momento o ID da música é:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Observação: aqui, o `id` nas letras é o ID da música gerada. Se você não souber como gerar uma música, pode consultar o uso básico acima para gerar uma música.

Se quiser continuar gerando uma música enviada por você mesmo, é possível definir o parâmetro `action` como `upload_extend`, e inserir o ID da música enviada personalizada que precisa continuar a ser gerada. A obtenção do ID da música é feita usando a [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), conforme mostrado na imagem abaixo:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Em seguida, é obrigatório preencher as letras do trecho de continuação e é possível especificar o estilo:

- lyric: usado apenas para orientar as letras do novo trecho gerado após `continue_at`, não substituirá as letras anteriores a esse ponto no tempo no áudio de origem.
- custom: preencher como `true` representa geração personalizada; o padrão deste parâmetro é false, representando a geração usando `prompt`.
- style: o estilo musical do trecho de continuação, opcional.
- continue_at: o limite de continuação, em segundos. Por exemplo, 213.5 indica começar a gerar o trecho seguinte a partir de 3 minutos e 33,5 segundos.

> `extend` é usado para continuar criando uma música existente, e não para trocar as letras da música inteira. Se desejar usar novas letras desde o início para toda a música, use `generate` para gerar novamente; se desejar reinterpretar uma música existente como referência, pode usar `cover`. Ao enviar letras novas para uma música inteira, as letras originais anteriores a `continue_at` ainda não serão substituídas.

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
```

## Obter a música completa

O resultado de `extend` do modelo atual normalmente já inclui o áudio-fonte antes de `continue_at` e o novo conteúdo após o limite; primeiro, determine se já é uma música completa com base na duração real e no conteúdo do áudio retornado. Se o retorno for um trecho de continuação independente, ou se for necessário mesclar explicitamente o histórico de múltiplas continuações em uma música, use então a função de concatenação:

- action: o conteúdo é `concat`.

```json
{

}
```

## Substituir trecho

Quando for necessário realizar uma criação secundária após gerar uma música, substituindo separadamente um trecho da música, é possível realizar uma operação de substituição em um determinado trecho da música.

> ⚠️ **Observação**: `replace_section_result_mode` é, por padrão, `full_song`: o sistema concatenará separadamente 2 candidatos recém-gerados e retornará 2 músicas completas. Se forem necessários apenas os candidatos de trechos substituídos ainda não concatenados, defina explicitamente como `candidates` e, em seguida, selecione um candidato para chamar [Concatenação de música](#音乐拼接).

A descrição dos parâmetros é a seguinte:

- action: o conteúdo é `replace_section`.
- audio_id: o ID da música original (a música-fonte a ser substituída).
- model: modelo de geração de música.
- lyric: a letra completa após a substituição (incluindo o trecho substituído e seu contexto, mantendo consistência com o conteúdo em `prompt`).
- prompt: a nova letra do trecho que precisa ser substituído.
- style: o estilo da música, opcional.
- replace_section_start: o tempo de início (em segundos) do trecho substituído na música original.
- replace_section_end: o tempo de término (em segundos) do trecho substituído na música original.
- replace_section_result_mode: modo de retorno, o padrão é `full_song`. `full_song` concatena separadamente 2 candidatos e retorna 2 músicas completas; `candidates` retorna 2 trechos candidatos ainda não concatenados.

## Controlar a duração da música

Por padrão, a duração da música gerada é determinada pelo próprio modelo, normalmente entre 30 segundos e 4 minutos. Se for necessário um produto final mais longo ou mais curto, é possível especificar a duração desejada por meio do parâmetro `duration`, cuja unidade é segundos, com valores inteiros entre 10 e 360.

Esse parâmetro é usado para a geração de músicas no modo personalizado (`custom` é `true`). É especialmente importante observar que `duration` é uma **indicação de tendência, e não uma restrição rígida**: o modelo fará referência a esse valor durante a criação, mas não garante atingi-lo. Em testes, a duração real costuma ser significativamente menor que o valor desejado, e as durações das duas músicas retornadas pela mesma solicitação também podem diferir várias vezes. Mesmo para solicitações completamente idênticas, as durações obtidas em vários envios também podem ter grandes diferenças. Portanto, não o utilize como um controle preciso de duração; se for necessária uma duração fixa para o negócio, faça o recorte por conta própria ou tente novamente após obter o produto final.

O código Python correspondente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

É necessário observar que `duration` na solicitação é a **duração desejada**, enquanto o campo `duration` de cada música em `data` na resposta é a **duração real** dessa música. Os dois têm o mesmo nome, mas significados diferentes; não é garantido que a duração real seja igual ao valor desejado. O comprimento da letra é um dos principais fatores que afetam a duração do produto final; se for necessário um produto final mais longo, recomenda-se também fornecer uma letra mais completa.

A interface não realizará validação adicional em `duration`, e o parâmetro será passado ao modelo como está. Se for passado um valor não suportado pelo modo ou modelo atual, isso pode se manifestar como o valor sendo ignorado; recomenda-se primeiro confirmar o efeito com uma solicitação antes de usá-lo em lote.

## Funcionalidade Add Insterumental

Em agosto de 2025, o suno lançou a nova funcionalidade Add Insterumental. Primeiro, é necessário fazer upload de uma música a cappella sem acompanhamento, para que o suno faça o acompanhamento para você. Primeiro, você pode acessar a [Suno Upload API](https://platform.acedata.cloud/documents/suno-upload) para fazer upload de uma música a cappella sem acompanhamento, e a operação correspondente é mostrada na imagem abaixo:

<p><img src="https://cdn.acedata.cloud/fxl914.png" width="500" className="m-auto" /></p>

Em seguida, é necessário registrar o `audio_id` após o upload, e o resultado específico é mostrado na imagem abaixo:

<p><img src="https://cdn.acedata.cloud/47t6wj.png" width="500" className="m-auto" /></p>

Por fim, foi obtido um `audio_id`: 92254cab-3372-4d9e-bce9-cdcfdbc39070, e então ainda precisamos preencher os seguintes parâmetros:
- action: o conteúdo é `underpainting`。
- underpainting_start: o horário de início para adicionar acompanhamento à música enviada, o valor padrão é 0。
- underpainting_end: o horário de término para adicionar acompanhamento à música enviada, deve ser menor que a duração total da música。
- audio_id: o ID da música enviada, cantada a cappella e sem dublagem。
- style: o estilo do acompanhamento, de preferência sem letras, afinal é uma dublagem。

Após o preenchimento, o código é gerado automaticamente da seguinte forma:

## Funcionalidade de criação por inspiração Inspo

A funcionalidade de criação por inspiração Inspo pode gerar novas músicas com base em 1 a 4 áudios de referência completos, oferecendo suporte para arrastar ou enviar áudios como fontes de inspiração. A API usa a ação `inspo` existente: o cliente fornece URLs de áudio publicamente acessíveis, e o serviço concluirá automaticamente a preparação dos áudios de referência e a criação, sem a necessidade de o cliente ler separadamente letras, estilo ou duração para então montar a solicitação. Ela difere da amostragem de intervalos apresentada acima e também do Cover que reproduz o estilo da música original. Ao utilizá-la, é necessário preencher os seguintes parâmetros:

- action: o conteúdo é `inspo`.
- audio_urls: uma lista de URLs dos áudios de referência; é necessário fornecer de 1 a 4 endereços de áudio publicamente acessíveis.
- model: o modelo usado, sendo recomendado o `chirp-v6`.
- prompt: letra ou prompt de criação (opcional).

> Observação: os áudios de referência devem ser arquivos de áudio publicamente acessíveis.
```python
import requests

url = "https://api.acedata.cloud/suno/audios"

    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

    "action": "inspo",
    "model": "chirp-v6",

    ],
```

## Retorno de chamada assíncrono

Como o Suno leva um tempo relativamente longo para gerar música, cerca de 1 a 2 minutos, se a API não responder por muito tempo, a solicitação HTTP permanecerá conectada continuamente, resultando em consumo adicional de recursos do sistema, portanto, esta API também oferece suporte a retornos de chamada assíncronos.

O processo geral é: quando o cliente inicia uma solicitação, ele especifica adicionalmente um campo `callback_url`; após o cliente iniciar a solicitação da API, a API retornará imediatamente um resultado, contendo um campo `task_id`, que representa o ID da tarefa atual. Quando a tarefa for concluída, o resultado da geração de música será enviado na forma de POST JSON para o `callback_url` especificado pelo cliente, que também inclui o campo `task_id`, dessa forma os resultados da tarefa podem ser associados pelo ID.

A seguir, vamos entender como operar especificamente por meio de um exemplo.

Primeiramente, o retorno de chamada Webhook é um serviço que pode receber solicitações HTTP, e os desenvolvedores devem substituí-lo pela URL do servidor HTTP que eles próprios configuraram. Aqui, para facilitar a demonstração, utilizamos um site público de exemplo de Webhook https://webhook.site/; ao abrir este site, é possível obter uma URL de Webhook, como mostrado na imagem:

![](https://cdn.acedata.cloud/fwfqin.png)

## Tratamento de erros

Se ocorrer um erro, você receberá uma mensagem de erro semelhante à seguinte:

```json
{
  "success": false,
  "error": {
    "code": "forbidden",
    "message": "Song Description contained artist name: eminem"
  },
  "trace_id": "9bb7c2f4-3b7b-4965-b50a-f663874b1b6f",
  "task_id": "9bb3a2a6-c438-436d-a9f3-fa466abc077c"
}
```

> Observação: os limites e as mensagens de erro de diferentes contas upstream podem variar.
