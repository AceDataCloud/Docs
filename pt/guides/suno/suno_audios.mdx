Com a aplicação da IA se tornando mais ampla, vários programas de IA já se popularizaram gradualmente. A IA já se aprofundou gradualmente em todos os aspectos do trabalho e da vida das pessoas. E os setores envolvidos pela IA também estão se tornando cada vez mais numerosos, desde a escrita inicial, passando pela saúde e educação, até agora a música.

Suno é uma plataforma profissional e de alta qualidade de criação de músicas e composições musicais com IA. Os usuários só precisam inserir simples palavras de instrução em texto para gerar músicas com vocais de acordo com o estilo do gênero e as letras. Este gerador de música com IA foi desenvolvido por membros de equipe de conhecidas empresas de tecnologia como Meta, TikTok, Kensho etc., com o objetivo de não precisar de nenhuma ferramenta instrumental, permitindo que todos possam criar músicas maravilhosas.

No entanto, a Suno oficialmente não fornece uma API. A AceDataCloud fornece um conjunto de APIs da Suno, simulando a integração oficial da Suno, permitindo gerar de forma prática e rápida a música desejada.

## Solicitação e uso

Para usar a Suno Audios Generation API, primeiro acesse o [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e guarde-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não tiver feito login ou se registrado, será automaticamente redirecionado para a página de login, onde será convidado a se registrar e fazer login; após concluir, retornará automaticamente à página atual.

**Um único API Token pode chamar todos os serviços da plataforma, não sendo necessário solicitar um separadamente para cada serviço.** Na primeira solicitação, será concedida uma cota gratuita, permitindo uma experiência gratuita; quando a cota for insuficiente, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

## Uso básico

Que tipo de música você quer? Você pode inserir livremente um trecho de texto. Por exemplo, se eu quiser gerar uma música sobre o Natal, posso inserir `a song for Christmas`, como mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Podemos ver que aqui configuramos os Request Headers, incluindo:

- `accept`: qual formato de resultado de resposta se deseja receber; aqui é preenchido como `application/json`, ou seja, o formato JSON.
- `authorization`: a chave para chamar a API, que pode ser selecionada diretamente na lista suspensa após a solicitação.

Além disso, configuramos o Request Body, incluindo:
- `action`: tipo de tarefa de áudio, o padrão é `generate`. Suporta operações como geração, continuação, cover, concatenação, separação de faixas, adição de faixa de áudio, extração de uma faixa de áudio especificada, geração de efeitos sonoros e ajuste de velocidade, todas chamadas de forma unificada por meio de `POST /suno/audios`.
- `prompt`: prompt do modo de inspiração oficial do Suno (válido quando `custom` é `false`), máximo de 500 caracteres.
- `model`: o modelo para esta tarefa de geração de música. A série v6 inclui `chirp-v6`, `chirp-v6-wild` e `chirp-v6-mini`; os nomes de modelos antigos continuam compatíveis.
- `max_mode`: modo de geração aprimorado. `generate` é habilitado apenas quando `custom` e `max_mode` são ambos `true`, com custo de 1.12 Credits; `add_stem` pode ser habilitado diretamente, com custo de 1.344 Credits. Quando desativado ou omitido, os custos são 0.56 e 0.672 Credits, respectivamente.
- `variety`: intensidade da diversidade dos resultados gerados, com opções `off`, `normal`, `high`, `extra`, `max`. Usado apenas para `generate` e `add_stem`; passá-lo para outros actions retornará 400.
- `lyric`: conteúdo da letra no modo personalizado oficial do Suno. `chirp-v3-5` e `chirp-v4` têm máximo de 3000 caracteres; `chirp-v4-5` e superiores (incluindo `chirp-v5`, `chirp-v5-5`) têm máximo de 5000 caracteres.
- `custom`: se deve usar o modo personalizado, o padrão é: `false`.
- `instrumental`: opção de música instrumental no modo de inspiração oficial do Suno.
- `title`: título da música no modo personalizado oficial do Suno. `chirp-v3-5`, `chirp-v4` têm máximo de 80 caracteres; `chirp-v4-5` e superiores têm máximo de 100 caracteres.
- `style`: estilo musical do modo personalizado oficial do Suno. `chirp-v3-5` e `chirp-v4` têm máximo de 200 caracteres; `chirp-v4-5` e superiores (incluindo `chirp-v5`, `chirp-v5-5`) têm máximo de 1000 caracteres.
- `negative_tags`: estilos musicais ou gêneros que se deseja excluir dos resultados gerados no modo personalizado (`custom` é `true`).
- `audio_weight`: peso de influência de características de áudio ou voz, intervalo de 0-1, sendo que `0` também é um valor válido. Pode ser usado em operações como geração, continuação, cover, adição de faixa de áudio e consistência de voz; quando não há áudio de referência ou características de voz, o modelo pode enfraquecer ou ignorar esse valor.
- `audio_id`: ID da música de referência.
- `overpainting_start`/`overpainting_end`: horários de início e fim para adicionar vocais a uma música instrumental existente, em segundos.
- `underpainting_start`/`underpainting_end`: horários de início e fim para adicionar acompanhamento a uma performance a cappella, em segundos.
- `persona_id`: ID da música do artista.
- `continue_at`: limite de continuação, em segundos. Por exemplo, 213.5 indica gerar o trecho seguinte a partir de 3 minutos e 33.5 segundos. `lyric` e `style` orientam apenas o novo conteúdo após o limite e não substituem a letra ou o canto antes do limite no áudio de origem.
- `style_influence`: influência de estilo no modo personalizado, intervalo de 0-1; quanto maior, geralmente mais fiel será ao estilo selecionado; `0` será transmitido como um valor válido.
- `replace_section_end`: tempo final do trecho de substituição.
- `replace_section_start`: tempo inicial do trecho de substituição.
- `vocal_gender`: controla a preferência por voz feminina ou masculina, voz feminina `f`, voz masculina `m`, válido para modelos 4.5 e superiores; é um item de preferência, não sendo garantido que seja seguido rigorosamente.
- `weirdness`: grau de estranheza no modo personalizado, intervalo de 0-1; quanto maior, geralmente mais criativo e experimental; `0` será transmitido como um valor válido.
- `duration`: duração esperada da música, em segundos, deve ser um inteiro, com intervalo de 10 a 360. Este parâmetro é usado para geração de música no modo personalizado (`custom` é `true`). É uma sugestão de preferência e não uma restrição rígida: o modelo a considerará, mas não garante atingi-la; a duração real do produto final é determinada pelo campo `duration` na resposta e normalmente é menor que o valor esperado.

### Escopo de aplicação dos parâmetros avançados

| Parâmetro                | Valores                                          | actions suportadas                              | Descrição                              |
| ----------------- | ------------------------------------------- | --------------------------------------- | ------------------------------- |
| `weirdness`       | 0-1                                         | Opcional                                      | Ajusta a experimentalidade, `0` é um valor válido; o efeito depende da operação, modo e modelo    |
| `style_influence` | 0-1                                         | Opcional                                      | Ajusta a tendência de seguir o estilo, `0` é um valor válido; o efeito depende da operação, modo e modelo |
| `audio_weight`    | 0-1                                         | Opcional                                      | Ajusta a influência de características de áudio ou voz; pode ser ignorado pelo modelo sem informações de referência      |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`, `add_stem`                   | Ajusta a diversidade de estilos entre os resultados                     |
| `max_mode`        | boolean                                     | `generate` (requer `custom=true`), `add_stem` | Aprimora a consistência e cobra de acordo com o modo aprimorado                   |
| `vocal_gender`    | `f` / `m`                                   | Operações de geração que suportam controle vocal                             | Item de preferência, não sendo garantido que seja seguido rigorosamente                     |
| `duration`        | Inteiro 10-360                                   | Opcional                                      | Duração esperada; a operação, modo ou modelo específico pode ignorá-la             |

A plataforma validará os tipos de parâmetros e os intervalos numéricos, mas não rejeitará esses itens de ajuste opcionais apenas porque o action é diferente; os efeitos específicos são determinados pela operação, modo e modelo.

- `lyric_prompt`: prompt para gerar letras, válido se e somente se `custom` for `true` e `lyric` não for enviado.
- `callback_url`: URL para a qual os resultados precisam ser retornados por callback.
- `async`: opcional; quando definido como `true`, a interface retorna imediatamente `task_id`, sem necessidade de fornecer `callback_url`, e os resultados podem ser obtidos posteriormente por polling por meio da interface de consulta de tarefa correspondente.

## Geração personalizada

Se quiser gerar letras personalizadas, você pode inserir a letra:

Neste momento, o campo `lyric` pode receber conteúdo semelhante ao seguinte:

```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> Observação: na letra aqui, `\n` é um caractere de quebra de linha. Se você não souber como gerar a letra, pode usar a API de geração de letras fornecida pelo AceDataCloud para gerar letras por meio de um prompt; a API é [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Em seguida, para gerar uma música personalizada com base na letra, no título e no estilo, você pode especificar o seguinte conteúdo:

- lyric: texto da letra
- custom: preencha como `true`, representando a geração personalizada; este parâmetro é, por padrão, false, representando a geração usando `prompt`.
- title: o título da música.
- style: o estilo da música, opcional.

## Funcionalidade de geração personalizada de estilo de cantor
Se você quiser usar o estilo de cantor para gerar músicas, primeiro gere uma música por meio do uso básico acima,
por fim, é necessário configurar esta música como estilo de cantor, então é necessário acessar a [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) para gerar um parâmetro de id de estilo de cantor `persona_id` com base no ID da música gerada oficialmente `audio_id`, os parâmetros específicos são mostrados na imagem abaixo:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Após preencher, o código é gerado automaticamente da seguinte forma:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

O código Python correspondente:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Clique em executar e você poderá ver que obterá um resultado, como segue:

```json

  "data": {

Em seguida, você pode definir o parâmetro `action` como `artist_consistency` (se for o novo estilo de cantor Persona-v2-vox, `action` deve ser definido como `artist_consistency_vox`), e inserir o ID da música que precisa continuar sendo gerada e o ID do estilo de cantor, o exemplo de preenchimento é o seguinte:

## Funcionalidade de continuar gerando

Se quiser continuar gerando uma música Suno já gerada, você pode definir o parâmetro `action` como `extend` e inserir o ID da música que precisa continuar sendo gerada. O ID da música é obtido com base no uso básico; pelo texto acima, pode-se saber que, neste momento, o ID da música é:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Observe que aqui o `id` na letra é o ID da música após a geração. Se você não souber como gerar uma música, pode consultar o uso básico acima para gerar uma música.

Se quiser continuar gerando uma música enviada por você mesmo, você pode definir o parâmetro `action` como `upload_extend` e inserir o ID da música enviada personalizada que precisa continuar sendo gerada. O ID da música é obtido usando a [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), como mostrado na imagem abaixo:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Em seguida, é necessário preencher a letra do trecho de continuação, e é possível especificar o estilo:

- lyric: usado apenas para orientar a letra do trecho recém-gerado após `continue_at`, não substituirá a letra antes desse ponto no tempo no áudio de origem.
- custom: preencha com `true`, representando a geração personalizada; esse parâmetro é false por padrão, representando a geração usando `prompt`.
- style: o estilo da música do trecho de continuação, opcional.
- continue_at: limite de continuação, em segundos. Por exemplo, 213.5 representa gerar o trecho subsequente a partir de 3 minutos e 33,5 segundos.

> `extend` é usado para continuar criando a partir de uma música existente, não para trocar a letra de toda a música. Se desejar usar uma nova letra para toda a música desde o início, use `generate` para gerar novamente; se desejar reinterpretar com referência a uma música existente, pode usar `cover`. Ao enviar uma letra nova completa, a letra original antes de `continue_at` ainda não será substituída.

## Obter a música completa

Se o retorno for um trecho de continuação independente, ou se for necessário mesclar explicitamente o histórico de várias continuações em uma única música, use então a funcionalidade de concatenação:

- action: o conteúdo é `concat`.
- audio_id: o ID do último trecho de continuação.

{

}

## Substituir trecho

Quando, após gerar uma música, for necessário realizar uma segunda criação substituindo separadamente um trecho da música, é possível realizar uma operação de substituição em um determinado trecho da música.

> ⚠️ **Observação**: `replace_section_result_mode` tem como padrão `full_song`: o sistema concatena separadamente 2 candidatos recém-gerados e retorna 2 músicas completas. Se forem necessários apenas candidatos de trechos substituídos que ainda não foram concatenados, defina explicitamente como `candidates` e, em seguida, selecione um candidato para chamar [Concatenação de música](#音乐拼接).

A descrição dos parâmetros é a seguinte:

- action: o conteúdo é `replace_section`.
- audio_id: o ID da música original (a música-fonte a ser substituída).
- model: modelo de geração de música.
- lyric: a letra completa após a substituição (incluindo o trecho substituído e seu contexto, mantendo-se consistente com o conteúdo em `prompt`).
- prompt: o novo trecho de letra que precisa ser substituído.
- style: o estilo da música, opcional.
- replace_section_start: o tempo inicial (segundos) do trecho substituído na música original.
- replace_section_end: o tempo final (segundos) do trecho substituído na música original.
- replace_section_result_mode: modo de retorno, cujo padrão é `full_song`. `full_song` concatena separadamente 2 candidatos e retorna 2 músicas completas; `candidates` retorna 2 trechos candidatos que ainda não foram concatenados.

## Adicionar faixa de áudio

## Extrair faixa de áudio

`extract_stem` extrai a faixa de áudio de destino do áudio especificado e, ao mesmo tempo, retorna a versão complementar após a remoção dessa faixa de áudio, por meio da chamada `POST /suno/audios`.

{
  "action": "extract_stem",

## Controlar a duração da música

Por padrão, a duração da música gerada é determinada pelo próprio modelo, geralmente entre 30 segundos e 4 minutos. Se for necessário um produto final mais longo ou mais curto, é possível especificar a duração desejada por meio do parâmetro `duration`, em segundos, com valores inteiros entre 10 e 360.

Este parâmetro é usado para a geração de músicas no modo personalizado (`custom` como `true`). É necessário destacar que `duration` é uma **indicação de tendência, e não uma restrição rígida**: o modelo fará referência a esse valor durante a criação, mas não garante que o atingirá. Em testes reais, a duração efetiva geralmente é significativamente menor que o valor esperado, e as durações das duas músicas retornadas pela mesma solicitação também podem diferir por várias vezes. Mesmo para solicitações completamente idênticas, as durações obtidas após vários envios também podem ter grandes diferenças. Portanto, não o utilize como um controle preciso de duração; se forem necessárias durações fixas para o negócio, corte ou tente novamente por conta própria após obter o produto final.

O código Python correspondente:
```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

É importante observar que `duration` na solicitação é a **duração esperada**, enquanto o campo `duration` de cada música em `data` na resposta é a **duração real** daquela música. Os dois possuem o mesmo nome, mas significados diferentes; não é garantido que a duração real seja igual ao valor esperado. O comprimento da letra é um dos principais fatores que afetam a duração do produto final; se for necessário um produto final mais longo, recomenda-se também fornecer letras mais completas.

A interface validará que `duration` deve ser um número inteiro entre 10 e 360; ele ainda é apenas um objetivo de geração, não uma garantia da duração do produto final.

## Funcionalidade de criação por inspiração Inspo

A funcionalidade de criação por inspiração Inspo pode gerar novas músicas com base em 1 a 4 áudios de referência completos, oferecendo suporte para arrastar e soltar ou enviar áudios como fonte de inspiração. A API usa a action `inspo` existente: o cliente fornece URLs de áudio acessíveis publicamente, e o serviço conclui automaticamente a preparação dos áudios de referência e a criação, sem que o cliente precise ler separadamente letras, estilo ou duração e depois montar a solicitação. Ela é diferente da amostragem de intervalo descrita acima e também diferente do Cover que replica o estilo da música original. Ao usar, é necessário preencher os seguintes parâmetros:

- action：o conteúdo é `inspo`。
- audio_urls：lista de URLs dos áudios de referência; é necessário fornecer de 1 a 4 endereços de áudio acessíveis publicamente。
- model：o modelo utilizado; recomenda-se `chirp-v6`。
- prompt：letras ou texto de sugestão criativa (opcional)。

> Observação：os áudios de referência devem ser arquivos de áudio acessíveis publicamente. Se o áudio de referência corresponder exatamente a uma gravação conhecida no catálogo da plataforma, o Suno poderá recusar a geração devido à verificação de direitos autorais; recomenda-se usar áudios próprios ou gerados pelo Suno como fonte de inspiração。

O código Python correspondente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Retorno de chamada assíncrono

Como o Suno leva relativamente muito tempo para gerar música, cerca de 1 a 2 minutos, se a API ficar sem resposta por muito tempo, a solicitação HTTP permanecerá conectada, resultando em consumo adicional de recursos do sistema; portanto, esta API também fornece suporte para retornos de chamada assíncronos.

O processo geral é: quando o cliente inicia uma solicitação, ele especifica adicionalmente um campo `callback_url`; após o cliente iniciar a solicitação à API, a API retornará imediatamente um resultado, contendo um campo `task_id`, que representa o ID da tarefa atual. Quando a tarefa for concluída, o resultado da geração de música será enviado em formato POST JSON para o `callback_url` especificado pelo cliente, que também inclui o campo `task_id`, para que os resultados da tarefa possam ser associados por meio do ID.
