Com a ampliação das aplicações de IA, diversos tipos de programas de IA foram gradualmente popularizados. A IA vem gradualmente se aprofundando em todos os aspectos do trabalho e da vida das pessoas. E os setores envolvidos pela IA também são cada vez mais numerosos, desde a escrita inicial, passando pela educação médica, até a música atual.

Suno é uma plataforma profissional e de alta qualidade de criação de músicas e música com IA. Os usuários só precisam inserir simples palavras de sugestão em texto para gerar músicas com vocais com base no estilo do gênero e nas letras. Este gerador de música por IA foi desenvolvido por membros de equipes de empresas de tecnologia renomadas, como Meta, TikTok e Kensho, com o objetivo de não precisar de nenhuma ferramenta instrumental, permitindo que todos possam criar músicas maravilhosas.

> Os limites de `lyric` e `style` na tabela acima são os limites máximos no modo personalizado (`custom` é `true`). No modo de inspiração não personalizado (`custom` é `false`), preencha apenas `prompt`, cujo limite de comprimento é de 500 caracteres (igual para todos os modelos).

O Suno agora oferece suporte a `chirp-v6`, `chirp-v6-wild` e `chirp-v6-mini`. Recomenda-se usar `chirp-v6`; os nomes dos modelos antigos continuam compatíveis.

No entanto, o Suno oficial não fornece uma API. A AceDataCloud fornece um conjunto de APIs do Suno, simulando a integração com o Suno oficial, permitindo gerar de forma conveniente e rápida a música desejada.

## Solicitação e uso

Para usar a API Suno Audios Generation, primeiro obtenha seu API Token no [console da Ace Data Cloud](https://platform.acedata.cloud/console/applications) e guarde-o como reserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não tiver feito login ou se registrado, será automaticamente redirecionado para a página de login, que convidará você a se registrar e fazer login; após concluir, você retornará automaticamente à página atual.

**Um API Token pode chamar todos os serviços da plataforma, não sendo necessário solicitar separadamente para cada serviço.** A primeira solicitação oferecerá uma cota gratuita, permitindo uma experiência gratuita; quando a cota for insuficiente, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Uso básico

Para pensar em que músicas criar, você pode inserir arbitrariamente um trecho de texto. Por exemplo, se eu quiser gerar uma música sobre o Natal, posso inserir `a song for Christmas`, como mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Pode-se ver que aqui configuramos os Request Headers, incluindo:

- `accept`: qual formato de resultado de resposta se deseja receber; aqui é preenchido como `application/json`, ou seja, formato JSON.
- `authorization`: a chave para chamar a API, que pode ser selecionada diretamente em uma lista suspensa após a solicitação.

Além disso, configuramos o Request Body, incluindo:
- `action`: tipo de tarefa de áudio, o padrão é `generate`. Suporta operações como geração, continuação, cover, mixagem, separação de faixas, adição de faixa de áudio, extração de faixa de áudio especificada, geração de efeitos sonoros e ajuste de velocidade, todas chamadas de forma unificada por meio de `POST /suno/audios`.
- `prompt`: texto de prompt do modo de inspiração oficial do Suno (válido quando `custom` é `false`), máximo de 500 caracteres.
- `model`: o modelo desta tarefa de geração de música. A série v6 inclui `chirp-v6`, `chirp-v6-wild` e `chirp-v6-mini`; os nomes de modelos antigos continuam compatíveis.
- `max_mode`: modo de geração aprimorada. `generate` é ativado somente quando `custom` e `max_mode` são ambos `true`, com custo de 1.12 Credits; `add_stem` pode ser ativado diretamente, com custo de 1.344 Credits. Quando desativado ou omitido, os custos são 0.56 e 0.672 Credits, respectivamente.
- `variety`: intensidade da diversidade dos resultados gerados, com opções `off`, `normal`, `high`, `extra`, `max`. Usado apenas para `generate` e `add_stem`; passá-lo para outros action retornará 400.
- `lyric`: conteúdo das letras no modo personalizado oficial do Suno. `chirp-v3-5` e `chirp-v4` têm máximo de 3000 caracteres; `chirp-v4-5` e superiores (incluindo `chirp-v5`, `chirp-v5-5`) têm máximo de 5000 caracteres.
- `custom`: se deve usar o modo personalizado, o padrão é: `false`.
- `instrumental`: opção de música instrumental do modo de inspiração oficial do Suno.
- `title`: título da música no modo personalizado oficial do Suno. `chirp-v3-5`, `chirp-v4` têm máximo de 80 caracteres; `chirp-v4-5` e superiores têm máximo de 100 caracteres.
- `style`: estilo musical do modo personalizado oficial do Suno. `chirp-v3-5` e `chirp-v4` têm máximo de 200 caracteres; `chirp-v4-5` e superiores (incluindo `chirp-v5`, `chirp-v5-5`) têm máximo de 1000 caracteres.
- `negative_tags`: estilos ou gêneros musicais que se deseja excluir durante a geração personalizada, também pode ser usado para `replace_section`. Atualmente, esta interface não define um limite fixo de caracteres para este campo; conteúdos excessivamente longos ainda podem não ser processados, sendo recomendado manter a descrição concisa.
- `audio_weight`: peso de influência das características de áudio ou voz, intervalo de 0-1, e `0` também é um valor válido. Pode ser usado em operações como geração, continuação, cover, adição de faixa de áudio e consistência de voz; quando não há áudio de referência ou características de voz, o modelo pode reduzir ou ignorar esse valor.
- `audio_id`: ID da música de referência, usado em operações posteriores como cover, continuação e separação de faixas. O arquivo de áudio ainda pode ser baixado, o que não significa que o processamento posterior desse ID estará sempre disponível; se retornar `suno_processing_unavailable`, mantenha o `task_id` e o `trace_id` para contatar o suporte.
- `overpainting_start`/`overpainting_end`: horários de início e fim para adicionar vocais a uma música instrumental existente, em segundos.
- `underpainting_start`/`underpainting_end`: horários de início e fim para adicionar acompanhamento a uma faixa a cappella, em segundos.
- `persona_id`: ID de voz obtido por meio da interface de criação de Persona ou voz, não é o `audio_id` da música.
- `continue_at`: limite de continuação, em segundos. Por exemplo, 213.5 indica que o segmento subsequente será gerado a partir de 3 minutos e 33.5 segundos. `lyric` e `style` apenas orientam o novo conteúdo após o limite e não substituirão as letras ou o canto antes do limite no áudio de origem.
- `style_influence`: influência do estilo no modo personalizado, intervalo de 0-1; quanto maior, geralmente mais próximo será do estilo selecionado; `0` será transmitido como valor válido.
- `replace_section_end`: horário final do segmento a ser substituído.
- `replace_section_start`: horário inicial do segmento a ser substituído.
- `vocal_gender`: controla a preferência por voz feminina ou masculina, voz feminina `f`, voz masculina `m`, válido para modelos 4.5 e superiores; é um item de preferência, não sendo garantido que seja seguido rigorosamente.
- `weirdness`: grau de estranheza no modo personalizado, intervalo de 0-1; quanto maior, geralmente mais criativo e experimental; `0` será transmitido como valor válido.
- `duration`: duração esperada da música, em segundos, deve ser um inteiro, com valores de 10 a 360. Atualmente, apenas `generate` usa este parâmetro, e o efeito específico depende do modo e do modelo. É uma indicação de tendência, e não uma restrição rígida: o modelo a considerará, mas não garante que será atingida; a duração real do resultado final prevalece conforme o campo `duration` na resposta, sendo normalmente menor que o valor esperado.

### Escopo de aplicação do ID de voz

`generate`, `cover`, `upload_cover`, `artist_consistency`, `artist_consistency_vox` podem usar `persona_id`. Os dois últimos action devem fornecer `persona_id`; também podem fornecer simultaneamente o `audio_id` da música usada ao criar esta Persona.

`extend`, `upload_extend` não usam um `persona_id` adicional. O suporte de `mashup`, `inspo` a IDs de voz depende do canal de serviço selecionado; outros action não garantem a aplicação deste campo, use-o conforme as instruções de cada operação. `vocal_gender` é uma preferência de gênero opcional e não pode substituir o ID de voz.

As operações de criação subsequentes exigem um `audio_id` de origem válido; `mashup` exige pelo menos dois `mashup_audio_ids`. A ausência de fontes ou parâmetros de tempo necessários retornará HTTP 400.

### Escopo de aplicação dos parâmetros avançados
| Parâmetro                | Valores                                      | action compatível                         | Descrição                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | Opcional                                      | Ajusta a experimentalidade; `0` é um valor válido; o efeito depende da operação, modo e modelo      |
| `style_influence` | 0-1                                         | Opcional                                      | Ajusta a tendência de seguir o estilo; `0` é um valor válido; o efeito depende da operação, modo e modelo   |
| `audio_weight`    | 0-1                                         | Opcional                                      | Ajusta a influência de recursos de áudio ou voz; pode ser ignorado pelo modelo quando não há informações de referência        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`, `add_stem`                   | Ajusta a diversidade de estilo entre os resultados                       |
| `max_mode`        | boolean                                     | `generate` (requer `custom=true`), `add_stem` | Melhora a consistência e cobra de acordo com o modo aprimorado                     |
| `vocal_gender`    | `f` / `m`                                   | Operações de geração que suportam controle de voz                             | Item de preferência, não há garantia de adesão rigorosa                       |
| `duration`        | inteiro 10-360                                   | `generate`                              | Duração esperada; outras actions atualmente não usam este campo, o comprimento real depende do resultado |

A plataforma validará os tipos de parâmetros e os intervalos numéricos, mas não rejeitará esses itens opcionais de ajuste apenas porque a action é diferente; os efeitos específicos são determinados pela operação, modo e modelo.

- `lyric_prompt`: o prompt para gerar letras, entra em vigor se e somente se `custom` for `true` e `lyric` não for enviado.
- `callback_url`: URL que precisa receber o resultado via callback.
- `async`: opcional, quando definido como `true`, a interface retorna imediatamente `task_id`, não sendo necessário fornecer `callback_url`; em seguida, obtenha o resultado por polling através da interface de consulta de tarefas correspondente.

## Geração personalizada

Se quiser gerar letras personalizadas, você pode inserir letras:

Neste momento, o campo `lyric` pode receber conteúdo semelhante ao seguinte:
```
[Verse]\nSnowflakes falling all around\nGlistening white\nCovering the ground\nChildren laughing\nFull of delight\nIn this winter wonderland tonight\nSanta's sleigh\nUp in the sky\nRudolph's nose shining bright\nOh my\nHear the jingle bells\nRinging so clear\nBringing joy and holiday cheer\n[Verse 2]\nRoasting chestnuts by the fire's glow\nChristmas lights\nThey twinkle and show\nFamilies gathering with love and cheer\nSpreading warmth to everyone near
```

> Observação, as `\n` nas letras aqui são quebras de linha; se você não souber como gerar letras, pode usar a API de geração de letras fornecida pela AceDataCloud para gerar letras por meio de prompt, a API é [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Em seguida, geraremos uma música de forma personalizada com base nas letras, título e estilo, podendo especificar o seguinte conteúdo:

- lyric：texto das letras
- custom：preencha como `true`, representando a geração personalizada; esse parâmetro é `false` por padrão, representando o uso de `prompt` para gerar.
- title：o título da música.
- style：o estilo da música, opcional.

```shell
}'
```

O teste é permitido, e o efeito gerado é semelhante.

## Funcionalidade de geração personalizada de estilo de cantor

Se quiser usar o estilo de cantor para gerar uma música, primeiro gere uma música por meio do uso básico acima,
depois, ao final, é necessário definir esta música como estilo de cantor, e então é preciso acessar a [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) para gerar um parâmetro de id de estilo de cantor `persona_id` com base no ID da música `audio_id` gerado oficialmente. Os parâmetros específicos são mostrados na imagem abaixo:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Após o preenchimento, o código a seguir é gerado automaticamente:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

O código Python correspondente:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Clique em executar, e será possível descobrir que será obtido um resultado, conforme a seguir:

```json

  "data": {

  }
}
```

Usamos os `audio_id` e `persona_id` acima como `97efc9f4-0e8d-4b3e-88df-14568fa1b11f` e `e0d7319e-aa2a-44cb-b00a-916218d7cb0b`, respectivamente, como os dados de exemplo desta vez. Em seguida, é possível definir o parâmetro `action` como `artist_consistency` (se for o novo estilo de cantor Persona-v2-vox, `action` deve ser definido como `artist_consistency_vox`), e inserir o ID da música que precisa continuar sendo gerada e o ID do estilo de cantor.
```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "artist_consistency",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b",
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"

response = requests.post(url, json=payload, headers=headers)
```

## Funcionalidade de continuar gerando
Se quiser continuar gerando uma música Suno já gerada, você pode definir o parâmetro `action` como `extend` e inserir o ID da música que precisa continuar sendo gerada. A obtenção do ID da música é feita com base no uso básico. Pelo conteúdo acima, é possível ver que, neste momento, o ID da música é:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Observação: aqui, o `id` nas letras é o ID da música gerada. Se você não souber como gerar uma música, pode consultar o uso básico acima para gerar uma música.

Se quiser continuar gerando uma música enviada por você mesmo, você pode definir o parâmetro `action` como `upload_extend` e inserir o ID da música personalizada enviada que precisa continuar sendo gerada. A obtenção do ID da música é feita usando a [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), conforme mostrado na imagem abaixo:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Em seguida, é necessário preencher as letras do trecho de continuação e é possível especificar o estilo:

- lyric: usado apenas para orientar as letras do novo trecho gerado após `continue_at`; não substituirá as letras antes desse ponto no áudio de origem.
- custom: preencher como `true` representa geração personalizada; esse parâmetro é `false` por padrão, representando geração usando `prompt`.
- style: estilo da música do trecho de continuação, opcional.
- continue_at: limite de continuação, em segundos. Por exemplo, 213.5 representa gerar o trecho subsequente a partir de 3 minutos e 33,5 segundos.

O `continue_at` de `extend` e `upload_extend` deve ser maior que 0 e suporta segundos decimais, por exemplo, `30.792`; não será arredondado no envio.

> `extend` é usado para criar em seguida a uma música existente, não para trocar as letras da música inteira. Se desejar usar novas letras desde o início da música inteira, use `generate` para gerar novamente; se desejar reinterpretar uma música existente como referência, pode usar `cover`. Ao enviar letras novas para uma música inteira, as letras originais antes de `continue_at` ainda não serão substituídas.

## Versão cover da música

Após continuar gerando uma música com base em uma música existente, o estilo da música retornada pode não ser muito adequado. - action: o conteúdo é `cover`; ao realizar uma operação de versão cover em uma música carregada de forma personalizada, o conteúdo deve obrigatoriamente ser: `upload_cover`.
- audio_id: o ID da música gerada anteriormente.

Se precisar usar uma voz especificada para a versão cover, também é possível enviar `persona_id`. Para vozes privadas criadas por meio de `/suno/voices`, primeiro é necessário carregar a música original em `/suno/upload` usando o mesmo `persona_id`, e então usar o `audio_id` retornado para realizar `upload_cover`. ## Substituir trecho

Quando, após gerar uma música, for necessário realizar uma criação secundária com uma operação separada para substituir trechos da música, é possível substituir um determinado trecho da música.
> ⚠️ **Atenção**: `replace_section_result_mode` usa `full_song` por padrão: o sistema concatenará separadamente 2 novos candidatos gerados e retornará 2 músicas completas. Se você precisar apenas dos candidatos de trechos de substituição ainda não concatenados, defina explicitamente como `candidates` e, em seguida, selecione um candidato para chamar [Concatenação de música](#音乐拼接).

Os parâmetros são descritos a seguir:

- action: o conteúdo é `replace_section`.
- audio_id: o ID da música original (a música-fonte que será substituída).
- model: modelo de geração de música.
- lyric: a letra completa após a substituição (incluindo o trecho substituído e seu contexto, mantendo-se consistente com o conteúdo em `prompt`).
- prompt: a nova letra do trecho que precisa ser substituído.
- style: o estilo da música, opcional.
- negative_tags: estilos ou gêneros que se deseja excluir, opcional.
- replace_section_start: o tempo de início do trecho substituído na música original (segundos), obrigatório e não deve ser menor que 0.
- replace_section_end: o tempo de término do trecho substituído na música original (segundos), obrigatório e deve ser maior que o tempo de início.
- replace_section_result_mode: modo de retorno, usa `full_song` por padrão. `full_song` concatena separadamente 2 candidatos e retorna 2 músicas completas; `candidates` retorna 2 trechos candidatos ainda não concatenados.

## Separação de voz e música de todas as faixas

A tarefa aguardará até que todas as faixas de áudio sejam geradas antes de retornar ao estado final de sucesso. O aparecimento de um endereço reproduzível durante o processamento não significa que todo o grupo de faixas de áudio foi concluído.

Quando, após gerar uma música, for necessário realizar a operação de separação de voz e música de todas as faixas, é possível especificar o seguinte conteúdo:

- action: o conteúdo é `all_stems`.
- audio_id: o ID da música gerada anteriormente.

Por exemplo, se o ID da música gerada anteriormente for: bdf23a5a-59f5-4103-b452-054a824a7f9f, então é possível definir os parâmetros da seguinte forma:

```json
{
  "action": "all_stems",
  "audio_id": "bdf23a5a-59f5-4103-b452-054a824a7f9f"
}
```

## Extrair faixa de áudio

`extract_stem` extrai a faixa de áudio de destino do áudio especificado e, ao mesmo tempo, retorna a versão complementar após a remoção dessa faixa de áudio, chamado por meio de `POST /suno/audios`.

- Obrigatório: `action`, `audio_id`, `stem_type`.
- Opcional: `audio_format`; o contrato público atual de canal duplo suporta apenas `mp3`.
- Cobrança: 1.12 Credits.

```json
{
  "action": "extract_stem",
  "audio_id": "dead4ee5-df4d-417b-8f7e-717722fae51a",
  "stem_type": "bass",
  "audio_format": "mp3",
  "async": true
}
```

O `data` na resposta em estado final mantém uma lista plana de áudios, e `stem_sets` representa a relação correspondente entre a faixa de áudio de destino e a faixa de áudio complementar:

## Controlar a duração da música

Por padrão, a duração da música gerada é decidida pelo próprio modelo, geralmente entre 30 segundos e 4 minutos. Se for necessário um produto final mais longo ou mais curto, é possível especificar a duração desejada por meio do parâmetro `duration`, em segundos, com valor inteiro entre 10 e 360.

Esse parâmetro é usado para a geração de músicas no modo personalizado (`custom` é `true`). É importante observar que `duration` é uma **indicação de tendência, e não uma restrição rígida**: o modelo consultará esse valor ao criar, mas não garante alcançá-lo; em testes, a duração real geralmente é significativamente menor que o valor esperado, e as durações das duas músicas retornadas na mesma solicitação também podem diferir em várias vezes. Mesmo para solicitações completamente idênticas, as durações obtidas em vários envios também podem ter grandes diferenças. Portanto, não o utilize como um controle preciso de duração; se for necessária uma duração fixa para fins comerciais, corte ou tente novamente por conta própria após obter o produto final.

O código Python correspondente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

É necessário observar que `duration` na solicitação é a **duração esperada**, enquanto o campo `duration` de cada música em `data` na resposta é a **duração real** dessa música. Embora ambos tenham o mesmo nome, seus significados são diferentes, e a duração real não é garantida como igual ao valor esperado. O comprimento da letra é um dos principais fatores que afetam a duração do produto final; se for necessário um produto final mais longo, recomenda-se também fornecer letras mais completas.

A interface validará que `duration` deve ser um inteiro entre 10 e 360; ele ainda é apenas um objetivo de geração, não uma garantia do comprimento do produto final.

## Funcionalidade de criação por inspiração Inspo

A funcionalidade de criação por inspiração Inspo pode gerar novas músicas com base em 1 a 4 áudios de referência completos, oferecendo suporte para arrastar ou enviar áudios como fontes de inspiração. A API usa a ação `inspo` existente: o cliente fornece URLs de áudio publicamente acessíveis, e o serviço conclui automaticamente a preparação dos áudios de referência e a criação, sem que o cliente precise ler separadamente a letra, o estilo ou a duração para depois montar a solicitação. Ela é diferente da amostragem de intervalo descrita acima e também diferente de Cover, que reproduz o estilo da música original. Ao utilizá-la, é necessário preencher os seguintes parâmetros:

- action: o conteúdo é `inspo`.
- audio_urls: lista de URLs dos áudios de referência; é necessário fornecer de 1 a 4 endereços de áudio publicamente acessíveis.
- model: o modelo utilizado; recomenda-se `chirp-v6`.
- prompt: letra ou texto de instrução para criação (opcional).
- instrumental: quando definido como `true`, gera conforme uma solicitação de música instrumental, sem usar letra.
- persona_id: utiliza a voz especificada nos canais de serviço que suportam essa combinação; os áudios de referência serão vinculados, durante a etapa de preparação, ao ambiente de recursos necessário para essa voz.
- lyric_prompt: quando `custom=true` e `lyric` não é fornecido, é usado para gerar letras automaticamente.

> Observação: os áudios de referência devem ser arquivos de áudio publicamente acessíveis. Se o áudio de referência corresponder completamente a uma gravação conhecida no catálogo de músicas da plataforma, o Suno poderá recusar a geração devido à verificação de direitos autorais. Recomenda-se usar áudios próprios ou gerados pelo Suno como fontes de inspiração.

O código Python correspondente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Retorno de chamada assíncrono

Como o tempo de geração de música pelo Suno é relativamente longo, levando aproximadamente 1 a 2 minutos, se a API não responder por muito tempo, a solicitação HTTP permanecerá conectada, resultando em consumo adicional de recursos do sistema, por isso esta API também oferece suporte a retornos de chamada assíncronos.

O fluxo geral é: quando o cliente inicia uma solicitação, ele especifica adicionalmente um campo `callback_url`; após o cliente iniciar a solicitação de API, a API retornará imediatamente um resultado, contendo um campo `task_id`, que representa o ID da tarefa atual. Quando a tarefa for concluída, o resultado da geração da música será enviado via POST JSON para o `callback_url` especificado pelo cliente, que também inclui o campo `task_id`, dessa forma os resultados da tarefa podem ser associados por meio do ID.
