`POST https://api.acedata.cloud/suno/projects` é a interface Beta para gerenciar projetos multifaixa. Use `action` para distinguir criação, salvamento, geração de candidatos, envio de candidatos e exportação.

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: <每次写操作的新 UUID>
```

Exceto por `retrieve`, **cada operação exige** `Idempotency-Key`. A mesma chave com a mesma solicitação apenas retorna o resultado original; a mesma chave com uma solicitação diferente retorna 409. Quando uma geração cobrada encontrar timeout de rede ou o resultado do envio for incerto, consulte primeiro usando o ID da tarefa original ou a mesma chave de idempotência; não altere diretamente a chave para reenviar.

## Identificadores e unidades de tempo

| Nome                             | De onde obter                                                                                      | Onde usar                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | Resposta de `create` em `data.id`                                                                      | Todas as solicitações subsequentes do projeto atual                                      |
| `version_id`                   | `data.version_id` do `retrieve`, `save`, `add_track`, `commit_candidate` ou `remove_track` mais recente | Modificação, geração de candidatos e exportação; deve usar a versão mais recente                              |
| `audio_id` / `source_audio_id` | `response.data.candidate.audio_id` no estado final de `upload`, ou um ID de áudio concluído existente                                | Referenciar o áudio original ao usar `add_track`, gerar ou substituir                          |
| `render_audio_id`              | `response.data.audio_id` no estado final de `render`                                                       | Referência de mixagem do projeto para `generate_track`                         |
| `operation_id`                 | `response.data.operation_id` no estado final de `generate_track` ou `replace_section`                       | `commit_candidate`; normalmente é igual ao `task_id` da tarefa de geração, mas deve ler o valor retornado |
| `candidate_id`                 | `response.data.candidates[].id` no estado final da geração                                                       | Selecionar um candidato para enviar                                         |
| `track_id`                     | `data.state.tracks[].id` do projeto                                                                | Enviar candidato ou excluir faixa                                        |
| `task_id`                      | Resposta de envio de operação assíncrona                                                                                   | Consultar o estado final usando `/suno/tasks`; não é o ID do projeto                   |

`start_seconds` / `end_seconds` são os **segundos dentro do áudio de origem**; `start_beats` / `end_beats` são os **tempos na linha do tempo do projeto**. `state.timing.bps` é o número de tempos por segundo, com padrão de 2. Por exemplo, um trecho de 41 segundos que começa no tempo 0 terá, por padrão, o fim no tempo 82. O intervalo em segundos de `generate_track` é usado para especificar a referência de geração, sem garantir que o candidato tenha apenas a duração desse intervalo.

## Fluxo de operações

| Ordem  | `action`                             | Função                         | Forma de retorno         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | Criar um projeto vazio                      | Dados síncronos do projeto       |
| 2   | `retrieve`                           | Ler a versão mais recente e o `state` completo          | Dados síncronos do projeto       |
| 3   | `save`                               | Salvar pela primeira vez ou salvar integralmente o `state` modificado      | Dados síncronos do projeto       |
| 4   | `upload`                             | Criar material a partir de um endereço de áudio HTTPS           | Tarefa assíncrona         |
| 5   | `add_track`                          | Inserir o áudio do material no projeto                  | Tarefa assíncrona, atualiza a versão    |
| 6   | `save`                               | Caso seja necessário receber candidatos para uma nova faixa, salvar primeiro uma faixa de destino vazia        | Dados síncronos do projeto, atualiza a versão  |
| 7   | `render`                             | Exportar as faixas audíveis atuais e obter a referência de mixagem `audio_id` | Tarefa assíncrona         |
| 8   | `generate_track` ou `replace_section` | Gerar candidatos para nova faixa ou candidatos de substituição local, respectivamente            | Tarefa assíncrona, ainda não modifica o projeto  |
| 9   | `commit_candidate`                   | Selecionar e enviar um candidato                  | Tarefa assíncrona, atualiza a versão após sucesso |
| Opcional  | `remove_track`                       | Excluir a faixa especificada                     | Dados síncronos do projeto, atualiza a versão |

Se for feita apenas uma substituição local, basta existir um áudio de origem utilizável, sem necessidade de executar `render` primeiro; se o áudio de origem já estiver no projeto, também é possível pular `upload` e `add_track`. `render_audio_id` é apenas a referência obrigatória de `generate_track`.

Ao enviar uma operação assíncrona, primeiro é retornado `{ "task_id": "...", "trace_id": "..." }`, o que **não indica que a geração foi bem-sucedida**. Consulte periodicamente:

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步返回的 task_id"}
```

A tarefa só é considerada bem-sucedida quando possui `finished_at` e seu `response.success` é `true`; quando `response.success=false`, leia `response.error`. Embora `save` possa incluir `task_id`, ele é concluído de forma síncrona nesta interface. `upload`, `render`, `generate_track` e `replace_section` não modificam a versão do projeto; após o sucesso de `save`, `add_track`, `commit_candidate` e `remove_track`, deve-se obter o novo `version_id`.

## Convenções de solicitação

| Parâmetro                | Tipo e escopo de aplicação                                                                                   | Descrição                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | String obrigatória                                                                                     | Deve ser um nome de operação listado nesta página; uma solicitação executa apenas uma operação.                                      |
| `id`              | String obrigatória, exceto para `create`                                                                         | ID do projeto, proveniente de `create.data.id`.                                      |
| `version_id`      | String obrigatória ao modificar, gerar candidatos ou exportar; pode ser omitida no primeiro `save` de um projeto vazio                                                         | Use a versão mais recente; versões antigas serão rejeitadas. `retrieve` não precisa dela.                                 |
| `Idempotency-Key` | Cabeçalho de solicitação obrigatório, exceto para `retrieve`, com 1–128 caracteres                                                              | Use uma nova chave para cada nova operação; a mesma chave com a mesma solicitação retorna o resultado original, sem gerar novamente ou cobrar.                                   |
| `async`           | Booleano opcional para `upload`, `add_track`, `generate_track`, `replace_section`, `commit_candidate` e `render` | Essas operações são sempre assíncronas; `false` também não transforma a geração em síncrona.                                    |
| `callback_url`    | URL opcional para operações assíncronas                                                                                | Recebe notificações de estado final; quando omitida, consulte `/suno/tasks` pelo `task_id`. Ainda é necessário verificar `response.success`. |

Os exemplos a seguir mostram encadeadamente a transmissão de IDs e versões entre as operações. As respostas listam apenas os campos relevantes para a etapa atual; durante a integração, substitua os IDs de exemplo pelos valores de resposta da aplicação atual.

## Salvar estado do projeto

| Parâmetro | Tipo e descrição |
|---|---|
| `state` | Objeto obrigatório. Envie o **estado completo do projeto**, não um patch parcial; use como base o `data.state` retornado pela operação de leitura ou modificação mais recente, preservando campos desconhecidos. |
| `title` | String opcional; quando omitida, usa `state.title`; se também não houver, usa o título padrão. |
| `version_id` | Pode ser omitido ao salvar pela primeira vez um novo projeto vazio; depois disso, a versão mais recente deve ser usada. |

`state.timing.bps` deve ser um número positivo, com padrão 2. `state.tracks` é um array de faixas; a referência `clipId` de um clipe de áudio existente usa o ID do áudio, e `startBeats`, `endBeats`, `readStartBeats` usam unidades de batidas do projeto. A forma mais segura de editar é ler o `state` completo, modificar apenas a faixa ou o clipe de destino e, em seguida, fazer `save` do conjunto inteiro. Uma nova faixa de destino vazia deve ter pelo menos `id` exclusivo, `type:"audio"`, `clips:[]`; a estrutura completa de uma faixa vazia é mostrada no exemplo em “Gerar nova faixa de áudio”. Não use diretamente os pontos de batida nos resultados da análise de áudio como coordenadas da linha do tempo do projeto.

## Carregar áudio e adicionar faixa

| Operação | Parâmetro | Tipo e descrição |
|---|---|---|
| `upload` | `audio_url` | URL HTTPS obrigatória, apontando para um áudio acessível publicamente e que você tenha direito de usar. O `candidate.audio_id` no estado final pode ser usado para adicionar uma faixa. |
| `add_track` | `audio_id` | String obrigatória; o ID de áudio de um material concluído, não uma URL. |
| `add_track` | `name`、`color` | Strings opcionais; o nome da faixa usa por padrão o título do áudio, a cor recomendada é `#RRGGBB`, e o padrão é `#7251F7`. |
| `add_track` | `title` | String opcional; também modifica o título do projeto, geralmente omitida. |
| `add_track` | `start_beats`、`end_beats` | Números não negativos opcionais, o ponto final deve ser maior que o ponto inicial; por padrão começa na batida 0, e o ponto final é calculado de acordo com a duração do áudio e `timing.bps`. |
| `add_track` | `gain` | Número não negativo opcional, com padrão 1; o coeficiente de volume do clipe e da faixa. |

## Gerar nova faixa de áudio

Os candidatos estão vinculados à versão do projeto no momento da geração. Primeiro salve uma faixa vazia que receberá os candidatos, depois exporte a mixagem atual como referência de geração; após a geração ser concluída, selecione um candidato para enviar a essa faixa vazia.

### Reservar faixa de destino: `save`

Os candidatos de `generate_track` estão vinculados à versão atual do projeto. No `state` **completo** retornado pelo estado final do `add_track` anterior, adicione a seguinte faixa vazia a `state.tracks`, depois salve com `save`; preserve todos os outros campos existentes como estão:
```

"type": "audio",
"name": "Piano gerado",
"clips": [],
"takeLanes": [],
"mute": false,
"solo": false,
"amplitude": 1,

"type": "song"
&#125;,
"color": "#7251F7"
&#125;

```

### Gerar candidatos: `generate_track`

| Parâmetro | Tipo e descrição |
|---|---|
| `source_audio_id` | Obrigatório; ID do áudio de origem concluído. Primeiro adicione o áudio de origem ao projeto, depois será possível determinar a posição dos candidatos. |
| `render_audio_id` | Obrigatório; `response.data.audio_id` no estado final do `render` acima, não a URL do áudio. |
| `model` | Obrigatório; opcionalmente `chirp-v3-5`, `chirp-v4`, `chirp-v4-5`, `chirp-v4-5-plus`, `chirp-v5`, `chirp-v5-5`, `chirp-v6`, `chirp-v6-wild`, `chirp-v6-mini`. Se combinações específicas estão disponíveis depende do estado final da tarefa. |
| `start_seconds`、`end_seconds` | Números obrigatórios, `0 ≤ start_seconds < end_seconds`; intervalo em segundos dentro do áudio de origem, não batidas do projeto, nem há garantia da duração de saída. |
| `stem_control_tags` | String obrigatória; descrição da nova parte, por exemplo `add Piano`, `add Drums`, `add Bass`, não é uma enumeração fixa. |
| `batch_size` | Inteiro opcional de 1–4, padrão 2; quantidade de candidatos. |
| `instrumental`、`vocal_gender` | Opcionais; puramente instrumental é `true` por padrão, a preferência vocal pode ser preenchida com `f`, `m`, `unspecified`, e o padrão é `unspecified`. |
| `title`、`tags`、`negative_tags`、`prompt` | Strings opcionais; são, respectivamente, o título do candidato, o estilo desejado, o estilo a evitar, e o texto ou a sugestão de letra para a nova parte. |

### Adotar candidato: `commit_candidate`

| Parâmetro | Tipo e descrição |
|---|---|
| `operation_id` | Obrigatório; `data.operation_id` no estado final da tarefa de geração. |
| `candidate_id` | Obrigatório; o `data.candidates[].id` selecionado. |
| `track_id` | Obrigatório; `state.tracks[].id` da faixa vazia salva antes da geração. |

| `name`、`gain` | Opcional para candidato de nova faixa; nome do clipe e coeficiente de volume não negativo, `gain` tem padrão 1. |

A geração produz apenas candidatos, **não os coloca automaticamente no projeto**. `commit_candidate` verifica se o candidato ainda pertence à versão atual. ## Substituir clipes existentes

`replace_section` pode usar diretamente o áudio-fonte existente, sem precisar exportar primeiro a mixagem. A geração retorna apenas candidatos; ao enviar, selecione a faixa original que contém o único clipe-fonte.

| Parâmetro | Tipo e descrição |
|---|---|
| `source_audio_id` | Obrigatório; ID do áudio-fonte concluído a ser substituído. |
| `model` | Obrigatório; use os modelos públicos listados em “gerar candidatos”; a disponibilidade do modelo e da operação é determinada pelo estado final da tarefa. |
| `start_seconds`、`end_seconds` | Números obrigatórios, `0 ≤ start_seconds < end_seconds ≤ duração do áudio-fonte`; intervalo em segundos dentro do áudio-fonte. |
| `prompt`、`replacement_lyrics` | Strings opcionais; o primeiro são as letras originais ou o contexto, o segundo são as novas letras para o intervalo de substituição. |
| `title`、`tags`、`negative_tags` | Strings opcionais; título do candidato, estilo desejado e estilos a evitar. |
| `fixed` | Booleano opcional, o padrão é `false`; quando definido como `true`, o intervalo deve ser inferior a 26 segundos, e o modelo pode não oferecer suporte. |

## Erros e recuperação

| Resultado | Significado | Próxima etapa |
|---|---|---|
| `project_version_conflict` / `project_candidate_stale`（409） | A versão do projeto foi alterada, ou o candidato não pertence à versão atual. | Faça `retrieve` do projeto mais recente e planeje novamente as modificações; não reproduza candidatos antigos. |
| `bad_request` / `studio_state_invalid` / `studio_model_unsupported`（geralmente 400） | Os parâmetros, o estado da faixa, a duração do candidato ou o modelo não correspondem à operação. | Verifique o erro no estado terminal da tarefa, corrija a entrada; mantenha o projeto original quando os candidatos não puderem ser concatenados com segurança. |
| `studio_audio_unavailable` / `studio_access_denied` / `content_rejected`（403） | O áudio de referência não está disponível para esta operação do projeto, não há permissão de acesso, ou a verificação de conteúdo recusou. | Verifique a origem do áudio e o `trace_id` da tarefa; não equipare candidatos já gerados a uma música inteira exportável. |
| `too_many_requests`（429） | A solicitação está sujeita a limitação de frequência. | Consulte primeiro a tarefa original e, em seguida, decida se deve iniciar uma nova operação com uma nova chave de idempotência. |
| `studio_unavailable` / `studio_model_unavailable`（503） | O processamento do projeto ou o modelo selecionado está temporariamente indisponível. | Preserve o resultado da tarefa original; tente novamente explicitamente mais tarde, sem trocar automaticamente de modelo. |
| `studio_processing_failed` / tempo limite（500/504） | O processamento falhou ou o estado terminal é incerto. | Consulte por `task_id` ou pela chave de idempotência original, evitando geração com cobrança duplicada. |

Projetos e candidatos estão vinculados ao aplicativo e ao ambiente de execução que os criaram, e não se pode presumir reutilização entre aplicativos ou failover automático. Persista a URL final do áudio exportado com sucesso e mantenha o `trace_id` para facilitar a investigação.
