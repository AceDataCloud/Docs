`POST https://api.acedata.cloud/suno/projects` é a interface Beta para gerenciar projetos multifaixa. Um endpoint distingue criação, salvamento, geração de candidatos, confirmação de candidatos e exportação por meio de `action`. O chamador só precisa usar os campos públicos abaixo, sem precisar preencher a estrutura interna de solicitação do serviço de geração subjacente.

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: Use um novo UUID para cada operação de modificação
```

Exceto por `retrieve`, **cada operação exige** `Idempotency-Key`. A mesma chave e a mesma solicitação apenas retornam novamente o resultado original; a mesma chave com solicitações diferentes retorna 409. Quando uma geração cobrada encontrar um tempo limite de rede ou o resultado de confirmação for incerto, consulte primeiro usando o ID da tarefa original ou a mesma chave de idempotência, e não reenvie diretamente com outra chave.

## Primeiro, diferencie estes IDs e unidades de tempo

| Nome                             | De onde obter                                                                                      | Onde usar                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | `data.id` da resposta de `create`                                                                      | Todas as solicitações subsequentes do projeto atual                                      |
| `version_id`                   | `data.version_id` do `retrieve`, `save`, `add_track`, `commit_candidate` ou `remove_track` mais recente | Modificação, geração de candidatos e exportação; deve usar a versão mais recente                              |
| `audio_id` / `source_audio_id` | `response.data.candidate.audio_id` no estado final de `upload`, ou um ID de áudio concluído existente                                | Referenciar o áudio original ao usar `add_track`, gerar ou substituir                          |
| `render_audio_id`              | `response.data.audio_id` no estado final de `render`                                                       | Referência de mixagem do projeto para `generate_track`                         |
| `operation_id`                 | `response.data.operation_id` no estado final de `generate_track` ou `replace_section`                       | `commit_candidate`; normalmente é igual ao `task_id` da tarefa de geração, mas deve ler o valor retornado |
| `candidate_id`                 | `response.data.candidates[].id` no estado final da geração                                                       | Selecionar um candidato para confirmar                                         |
| `track_id`                     | `data.state.tracks[].id` do projeto                                                                | Confirmar um candidato ou excluir uma faixa                                        |
| `task_id`                      | Resposta de submissão de operação assíncrona                                                                                   | Consultar o estado final usando `/suno/tasks`; não é um ID de projeto                   |

`start_seconds` / `end_seconds` são os **segundos dentro do áudio de origem**; `start_beats` / `end_beats` são os **beats na linha do tempo do projeto**. `state.timing.bps` é o número de beats por segundo, sendo 2 por padrão. Por exemplo, um clipe de 41 segundos começa no beat 0 e, por padrão, termina no beat 82. O intervalo em segundos de `generate_track` é usado para especificar a referência de geração, mas não garante que o candidato tenha apenas a duração desse intervalo.

## Ordem das operações e determinação de resultados

| Ordem  | `action`                             | Função                         | Forma de retorno         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | Criar um projeto vazio                      | Dados síncronos do projeto       |
| 2   | `retrieve`                           | Ler a versão mais recente e o `state` completo          | Dados síncronos do projeto       |
| 3   | `save`                               | Salvar pela primeira vez ou salvar integralmente o `state` modificado      | Dados síncronos do projeto       |
| 4   | `upload`                             | Criar material a partir de um endereço de áudio HTTPS           | Tarefa assíncrona         |
| 5   | `add_track`                          | Inserir o áudio do material no projeto                  | Tarefa assíncrona, atualiza a versão    |
| 6   | `save`                               | Se precisar receber candidatos para uma nova faixa, primeiro salve uma faixa de destino vazia        | Dados síncronos do projeto, atualiza a versão  |
| 7   | `render`                             | Exportar as faixas atualmente audíveis e obter a referência de mixagem `audio_id` | Tarefa assíncrona         |
| 8   | `generate_track` ou `replace_section` | Gerar, respectivamente, candidatos para nova faixa ou candidatos de substituição local            | Tarefa assíncrona, não modifica o projeto por enquanto  |
| 9   | `commit_candidate`                   | Selecionar e confirmar um candidato                  | Tarefa assíncrona, atualiza a versão após sucesso |
| Opcional  | `remove_track`                       | Excluir a faixa especificada                     | Dados síncronos do projeto, atualiza a versão  |

Se fizer apenas uma substituição local, um áudio de origem utilizável existente é suficiente, sem precisar executar `render` primeiro; se o áudio de origem já estiver no projeto, também é possível ignorar `upload` e `add_track`. `render_audio_id` é apenas a referência obrigatória de `generate_track`.

Ao submeter uma operação assíncrona, primeiro é retornado `{ "task_id": "...", "trace_id": "..." }`, o que **não significa que a geração foi bem-sucedida**. Consulte periodicamente:

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"task_id retornado na etapa anterior"}
```

Somente é considerado bem-sucedido quando o registro da tarefa tem `finished_at` e seu `response.success` é `true`; quando `response.success=false`, leia `response.error`. Embora `save` possa incluir `task_id`, ele é concluído de forma síncrona nesta interface. `upload`, `render`, `generate_track` e `replace_section` não modificam a versão do projeto; após o sucesso de `save`, `add_track`, `commit_candidate` e `remove_track`, deve-se obter o novo `version_id`.

## Parâmetros da solicitação

### Campos e cabeçalhos comuns

| Parâmetro                | Tipo e escopo de aplicação                                                                                   | Descrição                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | String obrigatória                                                                                     | Fixo como um dos nomes de operação listados nesta página; uma solicitação executa apenas uma operação.                                      |
| `id`              | String obrigatória, exceto para `create`                                                                         | ID do projeto, proveniente de `create.data.id`.                                      |
| `version_id`      | String obrigatória ao modificar, gerar candidatos ou exportar; pode ser omitida no primeiro `save` de um projeto vazio                                                         | Use a versão mais recente; versões antigas serão rejeitadas. `retrieve` não precisa dela.                                 |
| `Idempotency-Key` | Cabeçalho obrigatório, exceto para `retrieve`, com 1–128 caracteres                                                              | Use uma nova chave para cada nova operação; a mesma chave e a mesma solicitação retornam novamente o resultado original, sem gerar novamente nem cobrar.                                   |
| `async`           | Booleano opcional para `upload`, `add_track`, `generate_track`, `replace_section`, `commit_candidate` e `render` | Essas operações são sempre assíncronas; `false` também não torna a geração síncrona.                                    |
| `callback_url`    | URL opcional para as operações que possuem os campos assíncronos opcionais acima                                                                       | Recebe notificações do estado final; quando omitida, consulte `/suno/tasks` pelo `task_id`. Ainda é necessário verificar `response.success`. |

### Projeto e materiais
| `action`       | Parâmetro exclusivo          | Tipo e condições                       | Descrição                                                              |
| -------------- | --------------------------- | -------------------------------------- | ---------------------------------------------------------------------- |
| `create`       | `title`                     | String obrigatória, 1–200 caracteres   | Título do novo projeto.                                                |
| `retrieve`     | Nenhum                      | —                                      | Apenas `action` e o `id` do projeto são necessários; retorna o `state` completo editável. |
| `save`         | `state`                     | Objeto obrigatório                     | **Substitui integralmente** o estado do projeto, não é um patch parcial. Modifique com base no `retrieve.data.state` mais recente e envie-o integralmente, preservando campos desconhecidos. |
| `save`         | `title`                     | String opcional                        | Título do projeto; quando omitido, usa `state.title`; se também não existir, usa o título padrão. |
| `upload`       | `audio_url`                 | URL HTTPS obrigatória                  | Endereço de material de áudio acessível publicamente; após o sucesso, leia o estado final `candidate.audio_id`. O material deve ter direitos de uso pertencentes ao chamador. |
| `add_track`    | `audio_id`                  | String obrigatória                     | ID de áudio de material concluído, não uma URL.                        |
| `add_track`    | `name` / `color`            | Strings opcionais                      | Nome e cor da nova faixa; por padrão, o nome é o título do áudio, a cor recomendada é `#RRGGBB`, e o padrão é `#7251F7`. |
| `add_track`    | `title`                     | String opcional                        | Modifica simultaneamente o título do projeto; normalmente omitido.     |
| `add_track`    | `start_beats` / `end_beats` | Números não negativos opcionais, `end_beats > start_beats` | Posição do clipe na linha do tempo do projeto. O ponto inicial padrão é 0; o ponto final padrão é `ponto inicial + duração do áudio × timing.bps`. |
| `add_track`    | `gain`                      | Número não negativo opcional, padrão 1 | Coeficiente de volume do clipe e da nova faixa.                        |
| `remove_track` | `track_id`                  | String obrigatória                     | ID da faixa existente a ser excluída. Após o sucesso, use a nova versão retornada. |

`state.timing.bps` deve ser um número positivo, com padrão 2. `state.tracks` é um array de faixas; o `clipId` dos clipes de áudio existentes referencia o ID de áudio, e `startBeats`, `endBeats`, `readStartBeats` usam unidades de batida do projeto. A forma mais segura de editar é ler o `state` completo, modificar apenas a faixa ou o clipe de destino e, em seguida, fazer um `save` integral. Uma nova faixa de destino vazia deve ter pelo menos um `id` único, `type:"audio"`, `clips:[]`; consulte a forma completa realmente utilizável na etapa 5 abaixo. Não use diretamente os pontos de batida nos resultados da análise de áudio como coordenadas da linha do tempo do projeto.

### Gerar, enviar e exportar
| `action`                             | Parâmetros específicos                   | Tipo e condições                              | Descrição                                                                                                                                                        |
| ------------------------------------ | ---------------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generate_track` / `replace_section` | `source_audio_id`                  | String obrigatória                                  | ID do áudio de origem concluído. Primeiro adicione o áudio de origem ao projeto, para que os candidatos subsequentes possam encontrar a posição correspondente.                                                                                                                        |
| `generate_track` / `replace_section` | `model`                            | String de enumeração obrigatória                                | Disponíveis: `chirp-v3-5`, `chirp-v4`, `chirp-v4-5`, `chirp-v4-5-plus`, `chirp-v5`, `chirp-v5-5`, `chirp-v6`, `chirp-v6-wild`, `chirp-v6-mini`. A disponibilidade do modelo e da operação é determinada pelo estado final da tarefa; não haverá mudança automática para outro modelo. |
| `generate_track` / `replace_section` | `start_seconds` / `end_seconds`    | Números obrigatórios, `0 ≤ start_seconds &lt; end_seconds` | Segundos de início e fim dentro do áudio de origem; durante a substituição, o ponto final também não deve exceder a duração real do áudio de origem. Eles não são batidas do projeto, nem garantem a duração da saída do candidato.                                                                                                         |
| `generate_track`                     | `render_audio_id`                  | String obrigatória                                  | O `response.data.audio_id` após um `render` bem-sucedido do projeto atual, usado como referência de mixagem durante a geração.                                                                                                   |
| `generate_track`                     | `stem_control_tags`                | String obrigatória                                  | Descrição da nova faixa, por exemplo `add Piano`, `add Drums`, `add Bass`; não é uma enumeração fixa.                                                                                                      |
| `generate_track`                     | `batch_size`                       | Inteiro opcional 1–4, padrão 2                          | Quantidade de candidatos solicitados para geração.                                                                                                                                                |
| `generate_track`                     | `instrumental` / `vocal_gender`    | Booleano opcional／string de enumeração                            | `instrumental` usa `true` por padrão; a preferência vocal pode ser `f`, `m`, `unspecified`, com padrão `unspecified`. A observância das preferências é determinada pelo áudio real.                                                                     |
| `generate_track` / `replace_section` | `title` / `tags` / `negative_tags` | String opcional                                  | Título do candidato, descrição do estilo desejado e tags de estilo a evitar. Quando `tags` e `negative_tags` forem omitidos, passe strings vazias.                                                                                                  |
| `generate_track`                     | `prompt`                           | String opcional                                  | Texto ou instrução de letra para a nova faixa; pode ser omitido para música puramente instrumental.                                                                                                                                       |
| `replace_section`                    | `prompt` / `replacement_lyrics`    | String opcional                                  | O primeiro é a letra da música original ou o texto de contexto, e o segundo é a nova letra para o intervalo substituído; quando omitidos, passe strings vazias.                                                                                                                      |
| `replace_section`                    | `fixed`                            | Booleano opcional, padrão `false`                       | Solicita uma substituição de duração fixa; quando `true`, o intervalo deve ser inferior a 26 segundos, e o modelo selecionado pode não oferecer suporte. Este exemplo real usa o modo padrão; `fixed=true` ainda não foi verificado.                                                                                    |
| `commit_candidate`                   | `operation_id` / `candidate_id`    | Strings obrigatórias                                  | Respectivamente, obtenha `data.operation_id` do estado final da geração e o `data.candidates[].id` selecionado; o candidato deve pertencer à versão atual do projeto.                                                                                    |
| `commit_candidate`                   | `track_id`                         | String obrigatória                                  | Um candidato de nova faixa deve ser confirmado na **faixa vazia salva antes da geração**; um candidato de substituição local deve ser confirmado na faixa original que contém o único clipe de origem.                                                                                                              |
| `commit_candidate`                   | `start_beats` / `end_beats`        | Números não negativos opcionais somente para candidatos de nova faixa                           | Especifica a posição do novo clipe na linha do tempo do projeto; quando omitidos, usa o ponto inicial do clipe de origem e calcula o ponto final com base na duração real do candidato. Não deve se sobrepor aos clipes existentes na faixa de destino. **Candidatos de substituição local devem omitir**.                                                                                      |
| `commit_candidate`                   | `name` / `gain`                    | String／número não negativo opcional somente para candidatos de nova faixa                       | Nome do clipe gerado e coeficiente de volume; o padrão de `gain` é 1.                                                                                                                                  |
| `render`                             | `title`                            | String obrigatória                                  | Título do áudio exportado.                                                                                                                                                   |
| `render`                             | `lyrics` / `tags`                  | String opcional                                  | Texto da letra e descrição do estilo na exportação; a letra usa `[Instrumental]` por padrão.                                                                                                                      |
| `render`                             | `start_beats` / `end_beats`        | Números não negativos opcionais, o fim deve ser maior que o início                         | Exporta o intervalo de batidas do projeto; quando omitido, usa o ponto inicial mais cedo e o ponto final mais tarde de todos os clipes audíveis. Clipes silenciosos não participam; quando existem faixas solo, apenas as faixas solo são selecionadas.                                                                                             |

A geração produz apenas candidatos, **não os coloca automaticamente no projeto**. `commit_candidate` verifica se o candidato ainda pertence à versão atual. Candidatos de substituição local só podem ser confirmados automaticamente quando a duração real puder corresponder de forma confiável ao áudio de origem completo ou ao intervalo selecionado; em caso de incompatibilidade, o projeto original é mantido e um erro é retornado, não sendo possível forçar a junção por meio de adivinhação manual de batidas.

## 2026-10-09 Solicitações e respostas reais

Os corpos de solicitação e os campos de resposta abaixo são todos provenientes de chamadas reais do mesmo projeto. Cada grupo de JSON, em ordem, corresponde à solicitação, à resposta de aceitação (se assíncrona) e à resposta do estado final da tarefa. Para facilitar a leitura, as respostas incluem apenas os campos necessários para concluir este fluxo; campos de conta, uso e duração não são exibidos. Os IDs de exemplo pertencem a esta aplicação de teste; na integração, você deve usar os IDs retornados por suas próprias solicitações e uma nova `Idempotency-Key`.

### 1. Criar e ler um projeto vazio: `create`, `retrieve`

Solicitação `create`:

```json
{
  "action": "create",
  "title": "Suno Projects Documentation Verification 2026-10-09"
}
```

```json
{
  "success": true,
  "trace_id": "42408a82-988b-4127-ba68-9b89348a7c56",
  "data": {
    "id": "af0e104a-2a4c-40e0-9c70-7614566824a6",
    "title": "Suno Projects Documentation Verification 2026-10-09",
    "state": {
      "tracks": [],
      "timing": {
        "bps": 2
      }
    }
  }
}
```

Em seguida, chame `retrieve`:

```json
{
  "action": "retrieve",
  "id": "af0e104a-2a4c-40e0-9c70-7614566824a6"
}
```

```json

  "success": true,
  "trace_id": "a335ceac-5cb7-4b1c-9773-77b9d5c84bd7",
```

### 5. Salvar uma faixa vazia para receber candidatos

Os candidatos de `generate_track` estão vinculados à versão atual do projeto. Nesta ocasião, primeiro use o `state` **completo** obtido por `retrieve` como base, adicione a seguinte faixa vazia real a `state.tracks` e depois salve usando `save`; mantenha os demais campos existentes inalterados:

```json
{
  "id": "bdec15b5-ce96-43fa-b681-26298e013b06",
  "type": "audio",
  "name": "Generated piano",
  "clips": [],
  "takeLanes": [],
  "mute": false,
  "solo": false,
  "amplitude": 1,
  "instrument": {
    "type": "song"
  },
  "color": "#7251F7"
}
```

```json
  "success": true,
```

## Erros e recuperação

| Resultado                                                                            | Significado                          | Próxima etapa                                    |
| ----------------------------------------------------------------------------- | --------------------------- | -------------------------------------- |
| `project_version_conflict` / `project_candidate_stale`（409）                   | A versão do projeto foi alterada, ou o candidato não pertence à versão atual.         | Faça `retrieve` do projeto mais recente e planeje novamente as modificações; não reproduza candidatos antigos.        |
| `bad_request` / `studio_state_invalid` / `studio_model_unsupported`（geralmente 400）   | Os parâmetros, o estado da faixa, a duração do candidato ou o modelo não correspondem à operação.      | Verifique o erro terminal da tarefa, corrija a entrada; mantenha o projeto original quando o candidato não puder ser unido com segurança.          |
| `studio_audio_unavailable` / `studio_access_denied` / `content_rejected`（403） | O áudio referenciado não pode ser usado para a operação do projeto, não há permissão de acesso, ou a verificação de conteúdo o rejeitou. | Verifique a origem do áudio e o `trace_id` da tarefa; não equipare candidatos já gerados a uma música inteira exportável. |
| `too_many_requests`（429）                                                      | A solicitação está sujeita a limitação de frequência.                   | Primeiro consulte a tarefa original e, em seguida, decida se deve iniciar uma nova operação com uma nova chave de idempotência.                |
| `studio_unavailable` / `studio_model_unavailable`（503）                        | O processamento do projeto ou o modelo selecionado está temporariamente indisponível.             | Preserve o resultado da tarefa original; tente novamente explicitamente mais tarde, sem trocar automaticamente de modelo.                |
| `studio_processing_failed` / tempo limite（500/504）                                      | O processamento falhou ou o estado terminal é incerto.                 | Consulte por `task_id` ou pela chave de idempotência original para evitar geração com cobrança duplicada.          |

Os projetos e candidatos estão vinculados ao aplicativo e ao ambiente de execução que os criaram; não se deve presumir reutilização entre aplicativos ou failover automático. Persista a URL final do áudio exportado com sucesso e mantenha o `trace_id` para facilitar a investigação.
