Este artigo apresentará uma instrução de integração da API Veo Videos Generation, que pode gerar vídeos oficiais do Veo por meio da entrada de parâmetros personalizados.

## Processo de solicitação

Para usar a API Veo Videos Generation, primeiro obtenha seu API Token no [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) e guarde-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não tiver feito login ou se registrado, será automaticamente redirecionado para a página de login, onde será convidado a se registrar e fazer login; após a conclusão, você retornará automaticamente à página atual.

**Um API Token pode chamar todos os serviços da plataforma, sem a necessidade de solicitar separadamente para cada serviço.** A primeira solicitação oferece créditos gratuitos para experimentação gratuita; quando os créditos forem insuficientes, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Veo Videos Generation API →](https://platform.acedata.cloud/documents/veo-videos)

## Uso básico

Primeiro, vamos entender o método básico de uso: basta inserir o prompt `prompt`, a ação de geração `action`, o array de imagens de referência de primeiro e último quadro `image_urls` e o modelo `model` para obter o resultado processado. Primeiro, é necessário passar simplesmente um campo `action`, cujo valor é `text2video`. Ele contém principalmente três comportamentos: texto para vídeo (`text2video`), imagem para vídeo (`image2video`) e obter vídeo em 1080p (`get1080p`). Em seguida, também precisamos inserir o modelo `model`; atualmente, há principalmente os modelos `veo31-fast`, `veo3`, `veo31`, `veo3-fast` e `veo31-fast-ingredients`, e os detalhes são os seguintes:

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

Podemos ver que aqui configuramos os Request Headers, incluindo:

- `accept`: qual formato de resultado de resposta deseja receber; aqui é preenchido como `application/json`, ou seja, o formato JSON.
- `authorization`: a chave para chamar a API, que pode ser selecionada diretamente em uma lista suspensa após a solicitação.

Além disso, configuramos o Request Body, incluindo:

- `model`: o modelo para gerar vídeos, principalmente os modelos `veo31-fast`, `veo3`, `veo31`, `veo3-fast` e `veo31-fast-ingredients`.
- `action`: o comportamento desta tarefa de geração de vídeo, contendo principalmente três comportamentos: texto para vídeo (`text2video`), imagem para vídeo (`image2video`) e obter vídeo em 1080p (`get1080p`).
- `image_urls`: ao selecionar o comportamento de imagem para vídeo `image2video`, são necessários links das imagens de referência a serem enviadas. `veo31-fast-ingredients` aceita no máximo 3 imagens (fusão de múltiplas imagens), e os demais modelos aceitam no máximo 2 imagens (modo de primeiro e último quadro).
- `resolution`: selecione a resolução do vídeo gerado; entre eles, o modelo veo31 suporta resolução 4k, enquanto os outros modelos não. Todos os modelos suportam resoluções 1080p e gif. Se este valor não for passado, a resolução 720p será usada por padrão. As opções principais são: `1080p`, `gif`, `4k`.
- `prompt`: prompt.
- `callback_url`: a URL que precisa receber o resultado de callback.
- `async`: opcional; quando definido como `true`, a interface retorna imediatamente o `task_id`, sem a necessidade de fornecer `callback_url`; posteriormente, o resultado é obtido por polling através da interface correspondente de consulta de tarefas.

### 📌 Resumo da descrição dos modelos

| **Nome do modelo**                   | **Modos suportados**                          | **Regras de entrada de imagem**                        |
| -------------------------- | --------------------------------- | --------------------------------- |
| **veo3-fast**              | Texto para vídeo (sem imagem)<br />Modo imagem para vídeo (com imagem)           | **1 imagem** → modo de primeiro quadro<br />**2 imagens** → modo de primeiro e último quadro |
| **veo31-fast**             | Texto para vídeo (sem imagem)<br />Modo imagem para vídeo (com imagem)           | **1 imagem** → modo de primeiro quadro<br />**2 imagens** → modo de primeiro e último quadro |
| **veo31-fast-ingredients** | ❌ Texto para vídeo (não suportado)<br />✅ **Fusão obrigatória de múltiplas imagens** (é necessário passar imagens) | **1-3 imagens** → modo de fusão de múltiplas imagens (no máximo 3 imagens)        |
| **veo3**                   | Texto para vídeo (sem imagem)<br />Modo imagem para vídeo (com imagem)           | **1 imagem** → modo de primeiro quadro<br />**2 imagens** → modo de primeiro e último quadro |
| **veo31**                  | Texto para vídeo (sem imagem)<br />Modo imagem para vídeo (com imagem)           | **1 imagem** → modo de primeiro quadro<br />**2 imagens** → modo de primeiro e último quadro |

---

### 🔑 Descrição das regras principais

1. **Lógica geral**:
   - **Sem entrada de imagem** → aciona automaticamente o modo de texto para vídeo.
   - **Com entrada de imagem** → aciona o modo de imagem para vídeo (o comportamento específico é determinado pela quantidade de imagens).
2. **Tipos do modo de imagem para vídeo**:
   - **Modo de primeiro quadro** (1 imagem): o primeiro quadro é fixado como a imagem de entrada.
   - **Modo de primeiro e último quadro** (2 imagens): o primeiro e o último quadro são fixados como as imagens de entrada.
   - **Modo de fusão de múltiplas imagens** (1-3 imagens): suportado apenas por `veo31-fast-ingredients`, combina o conteúdo de múltiplas imagens para gerar vídeos.
3. **Classificação dos modos**:

  - **Modo Fast**: `veo3-fast`, `veo31-fast`, `veo31-fast-ingredients`.
   - **Modo Quality**: `veo3`, `veo31` (maior qualidade de geração).

---

### ⚠️ Observações

- **Único modelo com envio obrigatório de imagens**: `veo31-fast-ingredients` deve receber imagens (1-3 imagens), caso contrário não poderá ser executado.
- **Limite de quantidade de imagens**:
  - `veo31-fast-ingredients` suporta entrada de **1-3 imagens** (modo de fusão de múltiplas imagens).
  - Os outros modelos suportam no máximo **2 imagens** de entrada (modo de primeiro e último quadro).

## Funcionalidade de imagem para vídeo

Se quiser gerar um vídeo com base em imagens do quadro inicial e final, você pode definir o parâmetro `action` como `image2video` e inserir o array de links das imagens dos quadros inicial e final `image_urls`.

Em seguida, precisamos preencher os prompts que precisam ser estendidos na próxima etapa para personalizar a geração do vídeo, podendo especificar o seguinte conteúdo:

- `model`: o modelo para gerar vídeos, principalmente `veo31-fast`, `veo3`, `veo31`, `veo3-fast` e `veo31-fast-ingredients`.
- `image_urls`: ao selecionar a ação de imagem para vídeo `image2video`, é obrigatório fornecer os links das imagens de referência a serem enviadas.
- `prompt`: o prompt.

O exemplo de preenchimento é o seguinte:

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

Após o preenchimento, o código é gerado automaticamente da seguinte forma:

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

O código Python correspondente:

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo31-fast",
    "prompt": "Let it dance",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Callback assíncrono

Como o tempo de geração da Veo Videos Generation API é relativamente longo, levando cerca de 1 a 2 minutos, se a API não responder por um longo período, a solicitação HTTP manterá a conexão ativa, resultando em consumo adicional de recursos do sistema. Portanto, esta API também oferece suporte a callbacks assíncronos.

O fluxo geral é: quando o cliente inicia uma solicitação, ele especifica adicionalmente um campo `callback_url`. Após o cliente iniciar uma solicitação de API, a API retornará imediatamente um resultado, contendo informações do campo `task_id`, que representa o ID da tarefa atual. Quando a tarefa for concluída, o resultado do vídeo gerado será enviado na forma de POST JSON para o `callback_url` especificado pelo cliente, que também inclui o campo `task_id`, permitindo assim que os resultados da tarefa sejam associados pelo ID.

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `400 token_mismatched`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`：Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`：Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`：Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
