---
title: "Consultar tarefas de modelos Tripo"
description: "Tripo 3D API guide - Ace Data Cloud"
---

Chame `POST /tripo/tasks` com o token AceDataCloud. A consulta é gratuita; use a mesma conta utilizada para a geração. Para uma consulta individual, use `id` ou `trace_id`; `action` é `retrieve` por padrão.

```bash
curl -X POST https://api.acedata.cloud/tripo/tasks \
  -H "Authorization: Bearer ${ACEDATACLOUD_API_TOKEN}" \
  -H "Content-Type: application/json" \
  -d "{\"action\":\"retrieve\",\"id\":\"${TASK_ID}\"}"
```

O resultado de uma consulta individual é o registro da tarefa, que inclui `id`, `type`, `trace_id`, a solicitação original `request`, `started_at` e `progress`. Durante o processamento, é possível continuar consultando em intervalos de alguns segundos. Após a conclusão, verifique `response.success`; em caso de sucesso, `response.data[0].model_url` é o endereço de download; em caso de falha, `response.error` contém o código e a mensagem de erro. Os carimbos de data e hora, `finished_at` e o tempo decorrido `elapsed` ficam no nível superior do registro da tarefa, em segundos. Ao encontrar `submission_unknown`, mantenha o ID original da tarefa para conferência.

Para consultas em lote, use `{"action":"retrieve_batch","ids":["<ID da tarefa 1>","<ID da tarefa 2>"]}`; também é possível usar `trace_ids`. São permitidos até 100 itens por consulta. A resposta é `{"items":[...],"count":2}`, mantendo a ordem de entrada e os itens duplicados. Para tarefas não encontradas ou sem permissão de leitura, a consulta individual retorna `{}`, e a posição correspondente na consulta em lote é `null`.

O `type` do registro da tarefa é `generations`, `models` ou `animations`. Para a verificação de rigging, leia `response.data[0].riggable`; para operações com arquivos, leia `response.data[0].model_url`.
