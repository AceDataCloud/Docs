Este documento apresenta a interface de consulta de tarefas assíncronas de captcha `POST /captcha/tasks`. Ao chamar qualquer interface de captcha (série token ou série recognition) e passar `async: true`, a interface retornará imediatamente um `task_id`, que poderá ser usado para fazer polling nesta interface e obter o resultado final. É adequado para cenários de rotação de múltiplos solucionadores (multi-solver rotation): após enviar a tarefa, você obtém imediatamente o `task_id`, pode agendar outros solucionadores e voltar mais tarde para pegar o resultado.

> 📘 Documentação interativa completa (inclui depuração online): [API de Consulta de Tarefas de Captcha →](https://platform.acedata.cloud/documents/captcha-tasks)

## Processo de Solicitação

Para usar esta interface, primeiro acesse o [Painel de Controle da Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu Token de API, que deve ser mantido em reserva. **Um Token de API é suficiente para chamar todos os serviços da plataforma, não é necessário solicitar um para cada serviço.**

## Uso Básico

### Passo 1: Criar Tarefa de Forma Assíncrona

No corpo da solicitação de qualquer interface de captcha, passe `async: true`, e a interface retornará imediatamente um `task_id` (HTTP 201), sem bloquear a espera:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

### Passo 2: Polling do Resultado com task_id

Use o `task_id` retornado na etapa anterior para fazer polling em `POST /captcha/tasks` (recomenda-se a cada 3~5 segundos):

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Durante o processamento, retornará `status: processing`:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "processing"
}
```

Quando o processamento estiver concluído, retornará `status: ready` e o campo de resultado correspondente — a estrutura do campo é idêntica ao modo síncrono:

- **Série token** (hcaptcha, recaptcha2, recaptcha3) retorna `token`:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "started_at": 1784885653.0,
  "finished_at": 1784885665.4,
  "elapsed": 12.4,
  "token": "03AFcWeA5kjJyDQ9S1a9UYimR6nuxnpEnAs5x2Pixao0dXZhMB......"
}
```

- **Classificação recognition** (recognition/recaptcha2, recognition/hcaptcha) retorna `solution`; **recognition/image2text** retorna `text`.

`/captcha/tasks` é aplicável a todas as interfaces de captcha (séries token e recognition), podendo usar o mesmo `task_id` para polling.

Se a tarefa não puder ser concluída dentro do tempo válido, retornará HTTP 504. Este estado é terminal, e o cliente deve parar o polling; consultas repetidas ao mesmo `task_id` retornarão consistentemente o mesmo resultado de falha:

```json
{
  "detail": "A tarefa de captcha expirou.",
  "code": "timeout",
  "success": false,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "failed",
  "started_at": 1784885653.0,
  "finished_at": 1784885765.4,
  "elapsed": 112.4
}
```

As respostas de estado `ready` e HTTP 504 incluirão campos de temporização.

- `started_at`, hora de início do processamento da tarefa, timestamp Unix (segundos, ponto flutuante).
- `finished_at`, hora de produção do resultado da tarefa, timestamp Unix (segundos, ponto flutuante). Não retorna este campo enquanto estiver em processamento.
- `elapsed`, tempo de processamento da tarefa, em segundos (ponto flutuante, com 3 casas decimais). Não retorna este campo enquanto estiver em processamento.

## Instruções de Cobrança

No modo assíncrono, a criação de tarefas e o polling "em processamento" não geram cobrança; **apenas quando o resultado for obtido com sucesso será cobrado uma vez** (com o mesmo preço do modo síncrono). O estado de falha HTTP 504 também não gera cobrança. Portanto, cancelar tarefas que ainda não foram concluídas durante a rotação, ou tarefas que falham no final, não gerará custos.

## Tratamento de Erros

Ao chamar esta interface, se encontrar um erro, retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `400 invalid_request`: A solicitação está faltando o parâmetro `task_id`.
- `401 invalid_token`: Não autorizado, Token de autorização inválido ou ausente.
- `404 not_found`: `task_id` não existe ou não pertence à conta atual.
- `504 timeout`: A tarefa foi encerrada e não produziu resultados; por favor, pare o polling desse `task_id`. Esta falha não gerará cobrança.

### Exemplo de Resposta de Erro

```json
{
  "success": false,
  "error": {
    "code": "not_found",
    "message": "tarefa não encontrada"
  }
}
```
