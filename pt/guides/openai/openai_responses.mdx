A OpenAI forneceu recentemente uma interface para criar respostas de modelos. Forneça entradas de texto ou imagem para gerar saídas de texto ou imagem. Faça o modelo chamar seu próprio código personalizado ou usar ferramentas integradas, como pesquisa na web ou pesquisa de arquivos, para usar seus próprios dados como entrada para as respostas do modelo.

Este documento apresenta principalmente o fluxo de uso das operações da API OpenAI Responses; com ela, podemos usar facilmente a funcionalidade oficial da OpenAI para criar respostas de modelos.

## Processo de solicitação

Para usar a API OpenAI Responses, primeiro acesse o [Console do Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e guarde-o como reserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver conectado ou registrado, será automaticamente redirecionado para a página de login, onde será convidado a se registrar e entrar; após concluir, retornará automaticamente à página atual.

**Um API Token pode chamar todos os serviços da plataforma, sem necessidade de solicitar separadamente para cada serviço.** A primeira solicitação oferece créditos gratuitos, permitindo uma experiência gratuita; quando os créditos forem insuficientes, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Uso básico

Em seguida, você pode preencher o conteúdo correspondente na interface, como mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Ao usar esta interface pela primeira vez, precisamos preencher pelo menos três conteúdos: um é `authorization`, que pode ser selecionado diretamente na lista suspensa. Outro parâmetro é `model`; `model` é a categoria de modelo oficial do OpenAI ChatGPT que escolhemos usar; aqui temos principalmente 20 tipos de modelos, e os detalhes podem ser vistos nos modelos que fornecemos. O último parâmetro é `input`; `input` é o array de perguntas que inserimos, ele é um array, indicando que várias perguntas podem ser enviadas ao mesmo tempo; cada pergunta contém `role` e `content`, em que `role` representa o papel de quem faz a pergunta, fornecemos três identidades: `user`, `assistant`, `system`. O outro, `content`, é o conteúdo específico da nossa pergunta.

Ao mesmo tempo, você pode observar que há a geração do código de chamada correspondente no lado direito; você pode copiar o código e executá-lo diretamente ou clicar diretamente no botão «Try» para testar.

Parâmetros opcionais comuns:

- `max_tokens`: limita o número máximo de tokens em uma única resposta.
- `temperature`: aleatoriedade da geração, entre 0 e 2; quanto maior o valor, mais disperso.
- `n`: quantas respostas candidatas gerar de uma vez.
- `response_format`: configuração do formato de retorno.
- `tools`: definição de chamada de funções/ferramentas.
- `background`: se deve executar de forma assíncrona em segundo plano.

## Resposta em streaming

Esta interface também suporta respostas em streaming, o que é muito útil para integração com páginas web, permitindo que a página implemente um efeito de exibição palavra por palavra.

Se quiser retornar a resposta em streaming, você pode alterar o parâmetro `stream ` no cabeçalho da solicitação para `true`.

A modificação é mostrada na imagem, mas o código de chamada precisa ter as alterações correspondentes para suportar respostas em streaming.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Após modificar `stream` para `true`, a API retornará os dados JSON correspondentes linha por linha; no nível do código, precisamos fazer as modificações correspondentes para obter os resultados linha por linha.

Código de chamada de exemplo em Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

A resposta em streaming usa `response.completed` ou `response.incomplete` como estado final; o `usage` no estado final é o uso final de tokens desta solicitação e também a base para cobrança.

Se o cliente desconectar antes da chegada do estado final, esta solicitação será registrada como cliente fechado (499), e não haverá cobrança com base na estimativa local de tokens; se a conexão terminar normalmente, mas o estado final e o `usage` final não forem recebidos, esta solicitação será registrada como resposta incompleta (502), e igualmente não haverá cobrança com base na estimativa de tokens. Ao encontrar essas duas situações, inicie novamente a solicitação.

- `item_id`, o ID da tarefa de diálogo gerada desta vez, usado para identificar de forma exclusiva esta tarefa de diálogo.
- `type`, o tipo da tarefa Responses deste diálogo gerada desta vez.
- `model `, o modelo selecionado no site oficial do OpenAI ChatGPT.
- `delta`, as informações de resposta fornecidas pelo ChatGPT para a pergunta.

JavaScript também é compatível, por exemplo, o código de chamada em streaming do Node.js é o seguinte:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

```python
import requests
```

## Modelo de visão

gpt-4o é um grande modelo de linguagem multimodal desenvolvido pela OpenAI; ele adiciona capacidade de compreensão visual com base no GPT-4. Este modelo pode processar simultaneamente entradas de texto e imagem, realizando compreensão e geração multimodais.
O processamento de texto usando o modelo gpt-4o é consistente com o conteúdo básico de uso descrito acima. A seguir, será apresentada brevemente a forma de usar a capacidade de processamento de imagens do modelo.

A capacidade de processamento de imagens usando o modelo gpt-4o é utilizada principalmente adicionando um campo `type` com base no conteúdo original de `content`. Por meio desse campo, é possível saber se o que foi enviado é texto ou imagem, permitindo assim utilizar a capacidade de processamento de imagens do modelo gpt-4o. A seguir, será descrito principalmente como chamar essa funcionalidade usando Curl e Python.

- Método de script Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```


Pode-se ver que o conteúdo da resposta é baseado na imagem. Portanto, por meio das duas formas acima, é possível usar facilmente as capacidades de processamento de texto e imagem do modelo gpt-4.1.

Além do gpt-4.1, há também um modelo de menor custo chamado gpt-4o-mini. O gpt-4o-mini é a mais recente geração de modelo de linguagem de grande porte desenvolvida pela OpenAI. Ele não apenas possui uma velocidade de resposta rápida, como também é mais barato e oferece suporte a multimodalidade. Para o uso da funcionalidade vision, consulte o conteúdo acima sobre o uso do modelo gpt-4.1.

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `400 token_mismatched`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`：Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`：Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`：Erro interno do servidor, algo deu errado no servidor.
