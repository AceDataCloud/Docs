A OpenAI forneceu recentemente uma interface para criar respostas de modelo. Forneça entradas de texto ou imagem para gerar saídas de texto ou imagem. Faça o modelo chamar seu próprio código personalizado ou usar ferramentas integradas, como pesquisa na web ou pesquisa de arquivos, para usar seus próprios dados como entrada para as respostas do modelo.

Este documento apresenta principalmente o fluxo de uso da OpenAI Responses API. Com ela, podemos usar facilmente o recurso oficial da OpenAI para criar respostas de modelo.

## Processo de solicitação

Para usar a OpenAI Responses API, primeiro acesse o [Console do Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e guarde-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não tiver feito login ou se registrado, será redirecionado automaticamente para a página de login, onde será convidado a se registrar e fazer login. Após a conclusão, você retornará automaticamente para a página atual.

**Um API Token pode chamar todos os serviços da plataforma, sem necessidade de solicitar um separadamente para cada serviço.** A primeira solicitação concede créditos gratuitos, permitindo uma experiência gratuita; quando os créditos forem insuficientes, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Uso básico

Em seguida, você pode preencher os conteúdos correspondentes na interface, como mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Ao usar essa interface pela primeira vez, precisamos preencher pelo menos três conteúdos. Um deles é `authorization`, que pode ser selecionado diretamente na lista suspensa. Outro parâmetro é `model`; `model` é a categoria de modelo do site oficial do OpenAI ChatGPT que escolhemos usar. Aqui, temos principalmente 20 modelos, e os detalhes podem ser consultados nos modelos que fornecemos. O último parâmetro é `input`; `input` é o array de palavras de pergunta que inserimos. Ele é um array, indicando que várias palavras de pergunta podem ser enviadas ao mesmo tempo. Cada palavra de pergunta inclui `role` e `content`, onde `role` representa o papel do solicitante. Fornecemos três identidades: `user`, `assistant` e `system`. O outro, `content`, é o conteúdo específico da nossa pergunta.

Ao mesmo tempo, você pode observar que há uma geração de código de chamada correspondente no lado direito. Você pode copiar o código e executá-lo diretamente, ou clicar diretamente no botão «Try» para testar.

Parâmetros opcionais comuns:

- `max_tokens`: limita o número máximo de tokens em uma única resposta.
- `temperature`: aleatoriedade de geração, entre 0 e 2; quanto maior o valor, mais divergente será.
- `n`: quantas respostas candidatas gerar de uma vez.
- `response_format`: configuração do formato de retorno.
- `tools`: definição de chamadas de funções/ferramentas.
- `background`: se deve executar de forma assíncrona em segundo plano.

## Resposta em streaming

Essa interface também oferece suporte a respostas em streaming, o que é muito útil para integração com páginas da web, permitindo que a página implemente um efeito de exibição caractere por caractere.

Se quiser retornar respostas em streaming, você pode alterar o parâmetro `stream ` no cabeçalho da solicitação para `true`.

A modificação é mostrada na imagem, mas o código de chamada precisa ser alterado de forma correspondente para oferecer suporte à resposta em streaming.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Após modificar `stream` para `true`, a API retornará os dados JSON correspondentes linha por linha. No nível de código, precisamos fazer as modificações correspondentes para obter os resultados linha por linha.

Código de chamada de exemplo em Python:

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

A resposta em streaming usa `response.completed` ou `response.incomplete` como estado final; o `usage` no estado final é o uso final de tokens desta solicitação e também a base para a cobrança.

Se o cliente desconectar antes da chegada do estado final, esta solicitação será registrada como fechada pelo cliente (499), e não será cobrada com base na estimativa local de tokens; se a conexão terminar normalmente, mas o estado final e o `usage` final não forem recebidos, esta solicitação será registrada como resposta incompleta (502), e também não será cobrada com base na estimativa de tokens. Ao encontrar essas duas situações, inicie a solicitação novamente.

- `model `, o modelo selecionado no site oficial do OpenAI ChatGPT.
- `delta`, as informações de resposta fornecidas pelo ChatGPT para a pergunta.

JavaScript também é compatível, por exemplo, o código de chamada em streaming do Node.js é o seguinte:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-4.1",
    input: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/openai/responses", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

```python
import requests

url = "https://api.acedata.cloud/openai/responses"
```

## Modelo de visão

gpt-4o é um grande modelo de linguagem multimodal desenvolvido pela OpenAI; ele adiciona capacidade de compreensão visual com base no GPT-4. Este modelo pode processar simultaneamente entradas de texto e imagem, realizando compreensão e geração multimodais.
O processamento de texto usando o modelo gpt-4o é consistente com o conteúdo básico de uso acima. A seguir, será apresentado brevemente como usar a capacidade de processamento de imagens do modelo.

A capacidade de processamento de imagens usando o modelo gpt-4o é realizada principalmente adicionando um campo `type` com base no conteúdo original de `content`. Por meio desse campo, é possível saber se o que foi enviado é texto ou imagem, utilizando assim a capacidade de processamento de imagens do modelo gpt-4o. A seguir, é descrito principalmente como chamar essa funcionalidade de duas formas: Curl e Python.

- Método de script Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código de erro e as informações correspondentes. Por exemplo:

- `400 token_mismatched`: Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`: Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`: Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`: Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`: Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```
{
  "success": false,
  "error": {

}
```
