## 1. Obter a API Key

Abra a [lista de aplicações do Ace Data Cloud](https://platform.acedata.cloud/console/applications), entre em uma aplicação disponível e copie a API Key.

## 2. Editar usando a URL da imagem

Imagem original:

![Imagem original para edição do GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
    "prompt": "Keep the mug, tabletop, camera angle, portrait layout, and soft shadow unchanged. Change only the mug color from white to vivid orange and the pale cream background to solid dark navy blue. No text and no logo.",
    "size": "1024x1536"
  }'
```

## 3. Enviar imagem local

Use `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

É possível enviar `image` repetidamente; a série GPT Image suporta até 16 imagens de referência. O `image` em requisições JSON pode ser uma única URL ou um array de URLs; arquivos locais usam upload multipart.

### Modelos e formas de cobrança

| Modelo                                | Cenários aplicáveis e forma de cobrança                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | Canal reverso padrão, cobrança fixa por quantidade de imagens bem-sucedidas                               |
| `gpt-image-2:reverse`             | Seleciona explicitamente o canal reverso, cobrança fixa por quantidade de imagens bem-sucedidas                             |
| `gpt-image-2:official`            | Canal oficial da API, maior estabilidade, cobrança pelo uso real de Tokens                   |
| `gpt-image-2.5-flare`             | Focado na velocidade de geração, cobrança fixa por quantidade de imagens bem-sucedidas                               |
| `gpt-image-2.6-flare`             | Focado na velocidade de geração, cobrança fixa por quantidade de imagens bem-sucedidas                               |
| `gpt-image-2.5-flare:reverse`     | Alias reverso explícito, equivalente a `gpt-image-2.5-flare`, cobrança fixa por quantidade de imagens bem-sucedidas    |
| `gpt-image-2.6-flare:reverse`     | Alias reverso explícito, equivalente a `gpt-image-2.6-flare`, cobrança fixa por quantidade de imagens bem-sucedidas    |
| `gpt-image-2.5-flare:official`    | Canal oficial da API, maior estabilidade e foco na velocidade de geração, cobrança pelo uso real de Tokens            |
| `gpt-image-2.6-flare:official`    | Canal oficial da API, maior estabilidade e foco na velocidade de geração, cobrança pelo uso real de Tokens            |
| `gpt-image-2.5-sunburst`          | Focado em alta fidelidade e controle refinado, cobrança fixa por quantidade de imagens bem-sucedidas                           |
| `gpt-image-2.6-sunburst`          | Focado em alta fidelidade e controle refinado, cobrança fixa por quantidade de imagens bem-sucedidas                           |
| `gpt-image-2.5-sunburst:reverse`  | Alias reverso explícito, equivalente a `gpt-image-2.5-sunburst`, cobrança fixa por quantidade de imagens bem-sucedidas |
| `gpt-image-2.6-sunburst:reverse`  | Alias reverso explícito, equivalente a `gpt-image-2.6-sunburst`, cobrança fixa por quantidade de imagens bem-sucedidas |
| `gpt-image-2.5-sunburst:official` | Canal oficial da API, maior estabilidade e foco em alta fidelidade e controle refinado, cobrança pelo uso real de Tokens        |
| `gpt-image-2.6-sunburst:official` | Canal oficial da API, maior estabilidade e foco em alta fidelidade e controle refinado, cobrança pelo uso real de Tokens        |

Os modelos reversos 2.0 / 2.5 (incluindo os aliases `:reverse`) podem usar o GPT Image 2.5 Flare para concluir a solicitação durante a recuperação automática; o modelo solicitado e a forma de cobrança por quantidade de imagens bem-sucedidas permanecem inalterados.

O preço exibido na página para o canal oficial da API é uma estimativa antes da solicitação; o valor final deve se basear no uso real de Tokens e nos registros de uso presentes na resposta.

`quality` oferece suporte a `auto`, `low`, `medium`, `high`; Flare e Sunburst 2.5 / 2.6 (incluindo as variantes `:reverse` e `:official`) oferecem adicionalmente suporte a `xhigh`, `max`. Tanto a edição de URL de imagem em JSON quanto a edição de arquivo multipart podem receber esse campo; o canal oficial cobra pelo uso real de Tokens.

## 4. Usar máscara para edição local

A interface oficial Images Edit especifica, por meio de `mask`, as áreas permitidas para modificação. Os modelos `:official` do Ace Data Cloud seguem o mesmo contrato multipart:

- `mask` deve ser um PNG com canal Alpha, com tamanho não superior a 4MB;
- O tamanho da máscara deve ser exatamente igual ao da primeira `image`;
- Pixels transparentes com Alpha igual a `0` indicam que a edição é permitida, enquanto pixels não transparentes indicam que devem ser preservados;
- Imagens RGB que possuem apenas cores preto e branco, mas não têm canal de transparência, não podem ser usadas como máscaras válidas;
- O prompt deve descrever a imagem completa esperada, ao mesmo tempo em que deixa claras as modificações locais e o conteúdo que precisa permanecer inalterado.

A seguir, primeiro gere uma máscara a partir da imagem original. O exemplo define o retângulo central como transparente, permitindo que o modelo modifique apenas essa área:
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Em seguida, envie a imagem original e a máscara juntas:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Também é possível continuar usando a forma de chamada `images.edit` do SDK oficial Python da OpenAI, bastando apontar `base_url` para o Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Ao usar `mask`, a imagem original e a máscara devem ser enviadas no mesmo pedido multipart separadamente por meio de `image=@input.png` e `mask=@mask.png`. Não misture uma imagem original por URL com um arquivo de máscara local; pedidos de edição somente por URL não permitem adicionar um arquivo `mask` local. A máscara restringe a área de edição, mas o modelo de geração ainda pode fazer uma fusão natural nas bordas; quando forem necessários limites rigorosos, devem ser usadas bordas Alpha nítidas e deve-se repetir no prompt quais conteúdos devem permanecer inalterados.

A forma de chamada acima é consistente com os exemplos de máscara da [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) e do [Cookbook oficial do GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Parâmetros comuns

| Campo                | Descrição                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (mais rápido) ou `gpt-image-2.5-sunburst` (maior fidelidade e controle); os três podem escolher a variante `:official` correspondente, e `gpt-image-2` também oferece suporte a `:reverse` |
| `image`           | Em JSON, use uma única URL ou um array de até 16 URLs; em multipart, use um ou mais campos de arquivo `image`. Ao usar `mask`, é obrigatório enviar um arquivo de imagem local                                              |
| `mask`            | Máscara PNG opcional, limitada a envio de arquivo multipart; deve ter canal Alpha, o mesmo tamanho da primeira `image` e não exceder 4 MB                                                                 |
| `prompt`          | Instrução de edição                                                                                                                             |
| `size`            | `auto` ou um `WIDTHxHEIGHT` que esteja de acordo com as restrições                                                                                                     |
| `n`               | 1–10; quando `response_format=b64_json`, apenas 1 é suportado                                                                                           |
| `response_format` | `url` ou `b64_json`                                                                                                               |
| `callback_url`    | Endereço de callback assíncrono opcional                                                                                                                         |

As regras de tamanho são as mesmas da interface de geração: largura e altura devem ser múltiplos de 16, o lado maior não pode exceder 3840, o total de pixels deve ser de 655.360–8.294.400, e a proporção entre largura e altura não pode exceder 3:1. Ao omitir `size` ou usar `auto`, o modelo escolherá o enquadramento com base no prompt e na primeira imagem de referência.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` e seus aliases `:reverse` são cobrados pelo número de imagens concluídas com sucesso; `gpt-image-2:official`, `gpt-image-2.5-flare:official` e `gpt-image-2.5-sunburst:official` são cobrados com base nos Tokens reais de entrada de texto, entrada de imagem de referência e saída de imagem, prevalecendo os registros de uso.

## 6. Callback assíncrono e solução de problemas

Tarefas longas podem incluir o seguinte no pedido:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

A resposta assíncrona 200 é `{"task_id": "..."}`; quando concluída, o resultado final será retornado pelo callback. Pedidos síncronos retornam `created` e `data`.

| Status  | Verificar                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Formato/quantidade de imagens, combinação de parâmetros e formato de tamanho; ao usar `mask`, verifique o canal Alpha do PNG, o limite de 4 MB e se seu tamanho é igual ao da primeira imagem original |
| 401 | API Key e Header Bearer                                           |
| 429 | Frequência de pedidos                                                              |
| 504 | Mude para callback assíncrono                                                            |

As respostas de erro incluirão `trace_id`. Ao reportar problemas, forneça esse ID, mas não forneça a API Key.

Os campos completos e as enumerações em tempo real devem seguir a página [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Para geração de imagens apenas por texto, consulte [Geração de Imagens GPT Image 2 / 2.5 / 2.6](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

O GPT Image 2.6 mantém as interfaces de geração, edição, tarefas assíncronas e cobrança da versão 2.5:

| Modelo                                                          | Cobrança                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0,22 Credits/imagem                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0,22 Credits/imagem                   |
| `gpt-image-2.6-flare:official`                              | Igual ao official 2.5, cobrado pelo uso real de Tokens |
| `gpt-image-2.6-sunburst:official`                           | Igual ao official 2.5, cobrado pelo uso real de Tokens |

A qualidade pode ser `auto`, `low`, `medium`, `high`, `xhigh` ou `max`; para o tamanho, use `auto` ou um `WIDTHxHEIGHT` que esteja de acordo com as restrições acima. Esta interface oferece suporte a `png`, `jpeg` e `webp`; o GPT Image 2.6 também oferece suporte nativo a GIFs animados, mas SVG ainda não é suportado. A edição oferece suporte a URLs de imagem JSON e envio de arquivos multipart. `:reverse` é um alias explícito da versão comum com o mesmo nome. Use o nome completo do modelo, não envie `gpt-image-2.6`.

### Conversão de imagem para GIF animado com GPT Image 2.6
GPT Image 2.6 Flare, Sunburst na versão normal, `:reverse`, `:official` podem usar `output_format: "gif"`. Os quadros de animação, as informações de loop e a duração de reprodução serão preservados; `frame_count` indica o número de quadros, `frame_duration_ms` indica o número de milissegundos por quadro, o número de quadros deve ser um inteiro de 2–16, a duração de cada quadro deve ser um inteiro de 20–655350 milissegundos e é usada apenas para GIF; a codificação é arredondada para os 10 ms mais próximos. Quando não especificado, o padrão é 9 quadros, 200 milissegundos por quadro; quando o `size` do GIF é omitido ou é auto, usa a predefinição 512x512.

Recomenda-se usar primeiro `size: "512x512"`, `frame_count: 9`, `frame_duration_ms: 200`. O GIF possui limites independentes de tamanho e número de quadros, e não é possível aplicar diretamente as especificações estáticas de 4K; alguns modelos ajustarão o tamanho real da saída. `n` indica o número de arquivos GIF retornados, não o número de quadros da animação. A versão normal e `:reverse` continuam sendo cobradas pela quantidade de arquivos bem-sucedidos, enquanto a versão oficial é cobrada pelo uso real de Tokens.

```json
{
  "model": "gpt-image-2.6-flare",
  "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
  "prompt": "Animate the mug gently moving left and right. Keep its appearance and the background, no text.",
  "output_format": "gif",
  "size": "512x512",
  "quality": "medium",
  "frame_count": 9,
  "frame_duration_ms": 200,
  "n": 1,
  "async": true
}
```

### Imagens estáticas 4K do GPT Image 2.6

Flare, Sunburst e suas variantes `:reverse`, `:official` podem usar as predefinições de pixels 4K mencionadas anteriormente, como `3840x2160` e `2160x3840`. Tanto a geração quanto a edição recebem pixels específicos por meio de `size`; `4K` não é um valor `size` válido, e `4096x4096` também excede o limite atual de pixels. As especificações 4K acima se aplicam a PNG/JPEG/WebP estáticos; para GIF, use seus parâmetros específicos.

### Complexidade de composição do GPT Image 2.6

`complexity` pode ser `low`, `medium`, `high`; quando omitido, usa o padrão `high` do modelo. Ele controla a complexidade do planejamento e é independente da qualidade de renderização `quality`; não haverá cobrança adicional por solicitação, e a versão oficial continua sendo liquidada com base nos Tokens realmente usados. Outros modelos não suportam este parâmetro.

GIF não suporta mask, imagem de marcação, compressão personalizada, reescrita de prompt ou saída parcial de imagem por streaming; combinações incompatíveis serão rejeitadas antes da geração. Tamanho, número de quadros e quantidade estão conjuntamente sujeitos ao limite de orçamento de pixels do modelo; `1024x1024`, 2 quadros do Flare normal foi verificado como utilizável, mas essa conclusão não pode ser estendida a todas as combinações 1K ou GIFs 4K.

### Edição guiada por marcação

A edição estática do GPT Image 2.6 suporta `markup`. Envie um PNG transparente do mesmo tamanho que a primeira imagem de referência, circule em uma camada independente a área a ser modificada e descreva os requisitos de modificação no `prompt`. A camada de marcação deve conter pixels transparentes; cada uma das duas imagens não pode exceder 16777216 pixels, e a imagem de marcação não pode exceder 40MB. JSON pode transmitir uma URL HTTPS, uma data URL base64 de PNG ou `{ "image_url": "https://..." }`; multipart envia o arquivo por meio de `markup`. A plataforma transmitirá a camada de marcação na forma de arquivo. `markup` não pode ser usado com `mask`, GIF ou `prompt_rewriter`, e não suporta `file_id`.

`input_fidelity` não se aplica ao GPT Image 2.6, omita-o.
