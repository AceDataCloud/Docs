## 1. Obter API Key

Abra a [lista de aplicações do Ace Data Cloud](https://platform.acedata.cloud/console/applications), entre em uma aplicação disponível e copie a API Key.

## 2. Editar usando URL da imagem

Imagem original:

![Imagem original para edição do GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",

```

## 3. Enviar imagem local

Use `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

É possível enviar `image` repetidamente, e a série GPT Image suporta até 16 imagens de referência. O `image` em requisições JSON pode ser uma única URL ou um array de URLs; arquivos locais usam upload multipart.

### Modelos e formas de cobrança

| Modelo                                | Cenários aplicáveis e forma de cobrança                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | Canal reverso padrão, cobrança fixa por quantidade de imagens bem-sucedidas                               |
| `gpt-image-2:reverse`             | Seleção explícita do canal reverso, cobrança fixa por quantidade de imagens bem-sucedidas                             |
| `gpt-image-2:official`            | Canal oficial da API, maior estabilidade, cobrança pelo uso real de Tokens                   |
| `gpt-image-2.5-flare`             | Foco na velocidade de geração, cobrança fixa por quantidade de imagens bem-sucedidas                               |
| `gpt-image-2.5-flare:reverse`     | Alias reverso explícito, equivalente a `gpt-image-2.5-flare`, cobrança fixa por quantidade de imagens bem-sucedidas    |
| `gpt-image-2.5-flare:official`    | Canal oficial da API, maior estabilidade e foco na velocidade de geração, cobrança pelo uso real de Tokens            |
| `gpt-image-2.5-sunburst`          | Foco em alta fidelidade e controle refinado, cobrança fixa por quantidade de imagens bem-sucedidas                           |
| `gpt-image-2.5-sunburst:reverse`  | Alias reverso explícito, equivalente a `gpt-image-2.5-sunburst`, cobrança fixa por quantidade de imagens bem-sucedidas |
| `gpt-image-2.5-sunburst:official` | Canal oficial da API, maior estabilidade e foco em alta fidelidade e controle refinado, cobrança pelo uso real de Tokens        |

Os modelos reversos (incluindo os aliases `:reverse`) podem usar o GPT Image 2.5 Flare para concluir a solicitação durante a recuperação automática; o modelo solicitado e a forma de cobrança por quantidade de imagens bem-sucedidas permanecem inalterados.

O preço exibido na página para o canal oficial da API é uma estimativa antes da solicitação; o valor final deve seguir o uso real de Tokens na resposta e os registros de uso.

`quality` suporta `auto`, `low`, `medium`, `high`; apenas `gpt-image-2.5-flare` e `gpt-image-2.5-sunburst` (incluindo as variantes `:reverse` e `:official`) também suportam `xhigh`, `max`. Tanto a edição de URL de imagem em JSON quanto a edição de arquivos multipart podem receber esse campo; o canal oficial cobra pelo uso real de Tokens.

## 4. Usar máscara para edição local

A interface oficial Images Edit especifica as áreas que podem ser modificadas por meio de `mask`. Os modelos `:official` do Ace Data Cloud seguem o mesmo contrato multipart:

- `mask` deve ser um PNG com canal Alpha, com tamanho máximo de 4MB;
- o tamanho da máscara deve ser exatamente igual ao da primeira `image`;
- pixels transparentes com Alpha igual a `0` indicam que a edição é permitida, e pixels não transparentes indicam que devem ser preservados;
- imagens RGB que têm apenas cores preto e branco, mas não possuem canal transparente, não podem ser usadas como máscaras válidas;
- o prompt deve descrever a imagem completa esperada, enquanto deixa claro as modificações locais e o conteúdo que deve permanecer inalterado.

A seguir, primeiro gere uma máscara a partir da imagem original. O exemplo define o retângulo central como transparente, permitindo que o modelo modifique apenas essa área:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Em seguida, envie a imagem original e a máscara juntas:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Também é possível continuar usando a forma de chamada `images.edit` do SDK oficial Python da OpenAI, bastando apontar o `base_url` para o Ace Data Cloud:
```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Ao usar `mask`, a imagem original e a máscara devem ser carregadas separadamente na mesma solicitação multipart por meio de `image=@input.png` e `mask=@mask.png`. Não misture uma imagem original por URL com um arquivo de máscara local; solicitações de edição somente por URL não oferecem suporte à adição de um arquivo `mask` local. A máscara restringe a área de edição, mas o modelo de geração ainda pode realizar uma fusão natural nas bordas; quando forem necessários limites rígidos, deve-se usar bordas Alpha nítidas e repetir no prompt quais conteúdos devem permanecer inalterados.

A forma de chamada acima é consistente com os exemplos de máscara da [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) e do [Cookbook oficial do GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Parâmetros comuns

| Campo                | Descrição                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (mais rápido) ou `gpt-image-2.5-sunburst` (maior fidelidade e controle); todos os três podem selecionar a variante `:official` correspondente, e `gpt-image-2` também oferece suporte a `:reverse` |
| `image`           | JSON usa uma única URL ou um array de até 16 URLs; multipart usa um ou mais campos de arquivo `image`. Ao usar `mask`, é obrigatório carregar arquivos de imagem locais                                              |
| `mask`            | Máscara PNG opcional, limitada a carregamento de arquivo multipart; deve ter canal Alpha, o mesmo tamanho da primeira `image` e não exceder 4 MB                                                                 |
| `prompt`          | Instrução de edição                                                                                                                             |
| `size`            | `auto` ou `WIDTHxHEIGHT` que atenda às restrições                                                                                                     |
| `n`               | 1–10; quando `response_format=b64_json`, apenas 1 é suportado                                                                                           |
| `response_format` | `url` ou `b64_json`                                                                                                               |
| `callback_url`    | Endereço de callback assíncrono opcional                                                                                                                         |

As regras de tamanho são consistentes com a interface de geração: largura e altura devem ser múltiplos de 16, o lado maior não pode exceder 3840, o total de pixels deve ser de 655.360–8.294.400, e a proporção entre largura e altura não pode exceder 3:1. Ao omitir `size` ou usar `auto`, o modelo escolherá o formato com base no prompt e na primeira imagem de referência.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` e seus aliases `:reverse` são cobrados pelo número de imagens bem-sucedidas; `gpt-image-2:official`, `gpt-image-2.5-flare:official` e `gpt-image-2.5-sunburst:official` são cobrados com base nos Tokens reais de entrada de texto, entrada de imagem de referência e saída de imagem, prevalecendo o registro de uso final.

## 6. Callback assíncrono e depuração

Tarefas longas podem adicionar o seguinte à solicitação:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

A resposta assíncrona 200 é `{"task_id": "..."}`; após a conclusão, o resultado final será enviado por callback. Solicitações síncronas retornam `created` e `data`.

| Status  | Verificar                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Formato/quantidade de imagens, combinação de parâmetros e formato de tamanho; ao usar `mask`, verifique o canal Alpha do PNG, o limite de 4 MB e se suas dimensões correspondem à primeira imagem original |
| 401 | API Key e Bearer Header                                           |
| 429 | Frequência de solicitações                                                              |
| 504 | Mude para callback assíncrono                                                            |

As respostas de erro incluirão `trace_id`. Ao reportar problemas, forneça esse ID, não forneça a API Key.

Os campos completos e as enumerações em tempo real estão sujeitos à página [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Para geração de imagens a partir de texto simples, consulte [Geração de imagens GPT Image 2 / 2.5](https://platform.acedata.cloud/documents/openai-images-generations).
