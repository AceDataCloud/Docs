## 1. Obter a API Key

Abra a [lista de aplicações do Ace Data Cloud](https://platform.acedata.cloud/console/applications), entre em uma aplicação disponível e copie a API Key.

## 2. Editar usando URL da imagem

Imagem original:

![Imagem original para edição do GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer sua API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
    "prompt": "Keep the mug, tabletop, camera angle, portrait layout, and soft shadow unchanged. Change only the mug color from white to vivid orange and the pale cream background to solid dark navy blue. No text and no logo.",
    "size": "1024x1536"
  }'
```

## 3. Fazer upload de imagem local

Use `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer sua API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

É possível enviar `image` repetidamente, e a série GPT Image suporta até 16 imagens de referência. O `image` em solicitações JSON pode ser uma única URL ou uma matriz de URLs; arquivos locais usam upload multipart.

### Modelos e formas de cobrança

| Modelo                                | Cenários aplicáveis e forma de cobrança                                 |
| --------------------------------- | ----------------------------------------- |
| `gpt-image-2`                     | Canal reverso padrão, cobrança fixa por quantidade de imagens bem-sucedidas                        |
| `gpt-image-2:reverse`             | Seleciona explicitamente o canal reverso, cobrança fixa por quantidade de imagens bem-sucedidas                      |
| `gpt-image-2:official`            | Canal de API oficial, maior estabilidade, cobrança pelo uso real de Tokens            |
| `gpt-image-2.5-flare`             | Focado na velocidade de geração, cobrança fixa por quantidade de imagens bem-sucedidas                        |
| `gpt-image-2.5-flare:official`    | Canal de API oficial, maior estabilidade e foco na velocidade de geração, cobrança pelo uso real de Tokens     |
| `gpt-image-2.5-sunburst`          | Focado em alta fidelidade e controle detalhado, cobrança fixa por quantidade de imagens bem-sucedidas                    |
| `gpt-image-2.5-sunburst:official` | Canal de API oficial, maior estabilidade e foco em alta fidelidade e controle detalhado, cobrança pelo uso real de Tokens |

O preço exibido na página para o canal de API oficial é uma estimativa antes da solicitação; o valor final depende do uso real de Tokens na resposta e dos registros de uso.

`quality` oferece suporte a `auto`, `low`, `medium`, `high`; apenas `gpt-image-2.5-flare` e `gpt-image-2.5-sunburst` (incluindo variantes `:official`) oferecem adicionalmente suporte a `xhigh`, `max`. Tanto a edição de URL de imagem JSON quanto a edição de arquivo multipart podem incluir esse campo; o canal oficial cobra pelo uso real de Tokens.

## 4. Edição local usando máscara

A interface oficial Images Edit especifica áreas permitidas para modificação por meio de `mask`. Os modelos `:official` do Ace Data Cloud seguem o mesmo contrato multipart:

- `mask` deve ser um PNG com canal Alpha, com tamanho máximo de 4 MB;
- O tamanho da máscara deve ser exatamente igual ao da primeira `image`;
- Pixels transparentes com Alpha igual a `0` indicam que a edição é permitida, enquanto pixels não transparentes indicam que devem ser preservados;
- Imagens RGB que têm apenas cores preto e branco, mas não possuem canal transparente, não podem ser usadas como máscaras válidas;
- O prompt deve descrever a imagem completa esperada, deixando claro ao mesmo tempo as modificações locais e o conteúdo que precisa permanecer inalterado.

Abaixo, primeiro gere uma máscara a partir da imagem original. O exemplo torna o retângulo central transparente, permitindo que o modelo modifique apenas essa área:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Em seguida, faça upload da imagem original e da máscara juntas:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer sua API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Também é possível continuar usando a forma de chamada `images.edit` do SDK Python oficial da OpenAI, bastando apontar `base_url` para o Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="sua API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```
Ao usar `mask`, a imagem original e a máscara devem ser enviadas no mesmo pedido multipart separadamente através de `image=@input.png` e `mask=@mask.png`. Não misture uma imagem original por URL com um ficheiro de máscara local; pedidos de edição somente por URL não suportam a adição de um ficheiro `mask` local. A máscara restringe a área de edição, mas o modelo de geração ainda pode realizar uma fusão natural nas bordas; quando forem necessários limites rigorosos, deve usar bordas Alpha nítidas e repetir no prompt quais conteúdos devem permanecer inalterados.

A forma de chamada acima é consistente com os exemplos de máscara da [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) e do [Cookbook oficial do GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Parâmetros comuns

| Campo                | Descrição                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (mais rápido) ou `gpt-image-2.5-sunburst` (maior fidelidade e controlo); os três podem selecionar a variante `:official` correspondente, e `gpt-image-2` também suporta `:reverse` |
| `image`           | JSON utiliza um único URL ou uma matriz de até 16 URLs; multipart utiliza um ou mais campos de ficheiro `image`. Ao utilizar `mask`, é obrigatório carregar um ficheiro de imagem local                                              |
| `mask`            | Máscara PNG opcional, limitada a carregamento de ficheiro multipart; deve ter canal Alpha, as mesmas dimensões da primeira `image` e não exceder 4 MB                                                                 |
| `prompt`          | Instrução de edição                                                                                                                             |
| `size`            | `auto` ou `WIDTHxHEIGHT` que cumpra as limitações                                                                                                     |
| `n`               | 1–10; quando `response_format=b64_json`, apenas 1 é suportado                                                                                           |
| `response_format` | `url` ou `b64_json`                                                                                                               |
| `callback_url`    | Endereço opcional de callback assíncrono                                                                                                                         |

As regras de dimensões são consistentes com a interface de geração: a largura e a altura devem ser múltiplos de 16, o lado maior não pode exceder 3840, o total de píxeis deve ser de 655.360–8.294.400 e a proporção entre largura e altura não pode exceder 3:1. Ao omitir `size` ou utilizar `auto`, o modelo selecionará o formato com base no prompt e na primeira imagem de referência.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` e `gpt-image-2:reverse` são cobrados pelo número de imagens concluídas com sucesso; `gpt-image-2:official`, `gpt-image-2.5-flare:official` e `gpt-image-2.5-sunburst:official` são cobrados com base nos Tokens efetivamente utilizados pela entrada de texto, entrada de imagem de referência e saída de imagem, prevalecendo o registo de utilização final.

## 6. Callback assíncrono e resolução de problemas

Tarefas longas podem adicionar ao pedido:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

A resposta assíncrona 200 é `{"task_id": "..."}`; após a conclusão, será feito callback do resultado final. Os pedidos síncronos retornam `created` e `data`.

| Estado  | Verificar                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Formato/quantidade de imagens, combinação de parâmetros e formato das dimensões; ao usar `mask`, verifique o canal Alpha do PNG, o limite de 4 MB e se as suas dimensões correspondem à primeira imagem original |
| 401 | API Key e Bearer Header                                           |
| 429 | Frequência de pedidos                                                              |
| 504 | Mude para callback assíncrono                                                            |

As respostas de erro incluirão `trace_id`. Ao reportar problemas, forneça este ID; não forneça a API Key.

Para os campos completos e enumerações em tempo real, consulte a página [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Para geração de imagens a partir de texto simples, consulte [Geração de imagens GPT Image 2 / 2.5](https://platform.acedata.cloud/documents/openai-images-generations).
