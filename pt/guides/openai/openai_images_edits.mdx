## 1. Obter a API Key

Abra a [lista de aplicações do Ace Data Cloud](https://platform.acedata.cloud/console/applications), entre em uma aplicação disponível e copie a API Key.

## 2. Editar usando URL da imagem

Imagem original:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
```

## 3. Carregar imagem local

Use `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

É possível enviar `image` repetidamente, e a série GPT Image oferece suporte a no máximo 16 imagens de referência. O `image` em solicitações JSON pode ser uma única URL ou uma matriz de URLs; arquivos locais são enviados usando multipart.

### Modelos e formas de cobrança

| Modelo                                | Cenários aplicáveis e forma de cobrança                                 |
| --------------------------------- | ----------------------------------------- |
| `gpt-image-2`                     | Canal reverso padrão, cobrança fixa pelo número de imagens bem-sucedidas                        |
| `gpt-image-2:reverse`             | Seleciona explicitamente o canal reverso, cobrança fixa pelo número de imagens bem-sucedidas                      |
| `gpt-image-2:official`            | Canal de API oficial, maior estabilidade, cobrança conforme o uso real de Tokens            |
| `gpt-image-2.5-flare`             | Focado na velocidade de geração, cobrança fixa pelo número de imagens bem-sucedidas                        |
| `gpt-image-2.5-flare:official`    | Canal de API oficial, maior estabilidade e foco na velocidade de geração, cobrança conforme o uso real de Tokens     |
| `gpt-image-2.5-sunburst`          | Focado em alta fidelidade e controle detalhado, cobrança fixa pelo número de imagens bem-sucedidas                    |
| `gpt-image-2.5-sunburst:official` | Canal de API oficial, maior estabilidade e foco em alta fidelidade e controle detalhado, cobrança conforme o uso real de Tokens |

O preço exibido na página para o canal de API oficial é uma estimativa antes da solicitação; o valor final deve ser baseado no uso real de Tokens na resposta e nos registros de uso.

## 4. Usar máscara para edição local

A interface oficial Images Edit usa `mask` para especificar as áreas permitidas para modificação. Os modelos `:official` do Ace Data Cloud seguem o mesmo contrato multipart:

- `mask` deve ser um PNG com canal Alpha e ter tamanho máximo de 4 MB;
- O tamanho da máscara deve ser exatamente igual ao da primeira `image`;
- Pixels transparentes com Alpha igual a `0` indicam que a edição é permitida, enquanto pixels não transparentes indicam que devem ser preservados;
- Imagens RGB que são apenas em preto e branco, mas não têm canal de transparência, não podem ser usadas como máscaras válidas;
- O prompt deve descrever a imagem completa esperada, ao mesmo tempo em que deixa claras as modificações locais e o conteúdo que precisa permanecer inalterado.

A seguir, gere primeiro uma máscara a partir da imagem original. O exemplo define o retângulo central como transparente, permitindo que o modelo modifique somente essa área:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Depois, envie a imagem original e a máscara juntas:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Também é possível continuar usando a forma de chamada `images.edit` do SDK Python oficial da OpenAI; basta apontar `base_url` para o Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Ao usar `mask`, a imagem original e a máscara devem ser enviadas no mesmo pedido multipart separadamente por meio de `image=@input.png` e `mask=@mask.png`. Não misture uma imagem original por URL com um arquivo de máscara local; solicitações de edição somente por URL não oferecem suporte à adição de um arquivo `mask` local. A máscara restringirá a área de edição, mas o modelo de geração ainda poderá fazer uma mesclagem natural nas bordas; quando forem necessários limites rigorosos, use bordas Alpha nítidas e repita no prompt quais conteúdos devem permanecer inalterados.

As formas de chamada acima são consistentes com os exemplos de máscara da [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) e do [Cookbook oficial do GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).
## 5. Parâmetros comuns

| Campo                | Descrição                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (mais rápido) ou `gpt-image-2.5-sunburst` (maior fidelidade e controle); todos os três podem selecionar a variante correspondente `:official`, e `gpt-image-2` também oferece suporte a `:reverse` |
| `image`           | JSON usa uma única URL ou um array de até 16 URLs; multipart usa um ou mais campos de arquivo `image`. Ao usar `mask`, é obrigatório enviar um arquivo de imagem local                                              |
| `mask`            | Máscara PNG opcional, limitada ao upload de arquivo multipart; deve ter canal Alpha, o mesmo tamanho da primeira `image` e não exceder 4 MB                                                                 |
| `prompt`          | Instrução de edição                                                                                                                             |
| `size`            | `auto` ou `WIDTHxHEIGHT` que atenda às restrições                                                                                                     |
| `n`               | 1–10; quando `response_format=b64_json`, somente 1 é suportado                                                                                           |
| `response_format` | `url` ou `b64_json`                                                                                                               |
| `callback_url`    | Endereço de callback assíncrono opcional                                                                                                                         |

As regras de tamanho são consistentes com a interface de geração: a largura e a altura devem ser múltiplos de 16, o lado maior não pode exceder 3840, o total de pixels deve ser de 655.360–8.294.400, e a proporção de aspecto não pode exceder 3:1. Ao omitir `size` ou usar `auto`, o modelo escolherá o formato com base no prompt e na primeira imagem de referência.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` e `gpt-image-2:reverse` são cobrados pelo número de imagens bem-sucedidas; `gpt-image-2:official`, `gpt-image-2.5-flare:official` e `gpt-image-2.5-sunburst:official` são cobrados com base nos Tokens reais de entrada de texto, entrada de imagem de referência e saída de imagem, prevalecendo os registros de uso.

## 6. Callback assíncrono e solução de problemas

Tarefas longas podem adicionar o seguinte à solicitação:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

A resposta assíncrona 200 é `{"task_id": "..."}`; após a conclusão, o resultado final é enviado por callback. Solicitações síncronas retornam `created` e `data`.

| Status  | Verificação                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Formato/quantidade de imagens, combinação de parâmetros e formato de tamanho; ao usar `mask`, verifique o canal Alpha do PNG, o limite de 4 MB e se suas dimensões correspondem à primeira imagem original |
| 401 | API Key e Bearer Header                                           |
| 429 | Frequência de solicitações                                                              |
| 504 | Use callback assíncrono                                                            |

As respostas de erro incluirão `trace_id`. Ao relatar problemas, forneça esse ID; não forneça a API Key.

Os campos completos e as enumerações em tempo real devem seguir a página [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Para geração de imagens a partir de texto puro, consulte [Geração de imagens GPT Image 2 / 2.5](https://platform.acedata.cloud/documents/openai-images-generations).
