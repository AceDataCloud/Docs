O SDK Python é adequado para serviços de backend, tarefas de dados, Agents automatizados e scripts de processamento em lote. `acedatacloud` é responsável pelas chamadas de API, e `acedatacloud-x402` é responsável por assinar o cabeçalho de requisição `PAYMENT-SIGNATURE`.

Código-fonte e endereços dos pacotes:

- Repositório do SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Repositório do Cliente X402: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- SDK PyPI: [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)
- Cliente X402 PyPI: [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)

## Instalar dependências

```bash
pip install acedatacloud acedatacloud-x402
```

Se for usar `upto`, também será necessário chamar uma vez a CLI de aprovação Permit2, e essa CLI depende de `web3`:

```bash
pip install 'acedatacloud-x402[cli]'
```

Saída da verificação de instalação e importação em um Python venv limpo:

```text
acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
approve-permit2  One-time ERC-20 approve(Permit2, amount) needed before signing upto payments.
```

Explicação dos resultados:

- Tanto `acedatacloud` quanto `acedatacloud-x402` podem ser instalados e importados a partir do PyPI.
- `pip install 'acedatacloud-x402[cli]'` inclui a CLI `approve-permit2`, usada para a autorização prévia de `upto`.

## Exemplo Base

O exemplo abaixo não requer API Token. A chave privada da carteira é usada apenas para assinatura local e não será enviada ao Ace Data Cloud.

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)

print(res["choices"][0]["message"]["content"])
```

Atualmente, o SDK Python retorna um `dict`, portanto o exemplo usa `res["choices"][0]["message"]["content"]`. Não assuma diretamente que ele necessariamente possui o atributo `.choices`.

## Exemplo Solana

Solana usa uma secret key codificada em base58:

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import SolanaKeypairSigner, create_x402_payment_handler

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="solana",
        solana_signer=SolanaKeypairSigner.from_base58(os.environ["SOLANA_SECRET_KEY"]),
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

O fluxo Solana construirá e enviará uma transação SPL USDC `TransferChecked` e, então, colocará a assinatura da transação no envelope `PAYMENT-SIGNATURE`.

A nova tentativa paga do Solana já retornou HTTP 200 e `ADC_SOLANA_E2E_OK` na API de produção. A consulta RPC pública desta vez encontrou limitação de taxa, e não confirmou de forma estável a signature on-chain; quando for necessário reconciliar, use seu próprio RPC Solana para consultar essa transação.

## Cliente Async

O mesmo payment handler pode ser usado com `AsyncAceDataCloud`:

```python
import os

from acedatacloud import AsyncAceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AsyncAceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = await client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

## Usar medição posterior com `upto`

O custo real de APIs como complementação de chat e chamadas de modelo pode só ser conhecido após o término da resposta. Nesse caso, a API pode retornar simultaneamente `exact` e `upto`. Se quiser priorizar `upto`:

```python
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
        prefer_scheme="upto",
    )
)
```

Resultado da execução do programa `upto` na Base:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
settlement tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
settled value 3 atomic USDC
```

Confirmação on-chain:

```text
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
transfer value 3 atomic USDC
```

Explicação dos resultados:

- `content ADC_BASE_UPTO_OK` indica que a requisição realmente entrou na API do modelo.
- `settled value 3 atomic USDC` indica que `upto` é liquidado de acordo com o uso real, em vez de descontar o limite máximo completo.
- `settlement tx` pode ser aberto no BaseScan; ao reconciliar, salve o tx hash, payer, completion id e o resumo da requisição.

`upto` usa Permit2 para autorizar um limite máximo, e o valor real da liquidação não pode exceder esse limite. Antes do primeiro uso, é necessário fazer uma vez `approve(Permit2, amount)` para o USDC na cadeia de destino.

Método CLI:

```bash
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Método programático:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Esse helper é idempotente. Se a allowance já for suficiente, ele retornará `{"skipped": true}` e não enviará novamente uma transação on-chain.

## Assinatura de baixo nível

Se não usar o SDK, você também pode chamar diretamente a função de assinatura de baixo nível:

```python
import base64
import json

from acedatacloud_x402 import EVMAccountSigner, sign_evm_payment

envelope = sign_evm_payment(requirement, EVMAccountSigner.from_private_key("0x..."))
x_payment = base64.b64encode(json.dumps(envelope, separators=(",", ":")).encode()).decode()
```

As funções de baixo nível são adequadas para testes, camada de proxy, integração de gateway ou SDKs não oficiais. Para código de negócios comum, dê prioridade a `create_x402_payment_handler`.
