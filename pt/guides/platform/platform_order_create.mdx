---
title: "Criar pedido de recarga na plataforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Crie pedidos pendentes de pagamento para uma ou mais Applications. A criação gravará o pedido, mas não concluirá o pagamento automaticamente; antes do pagamento, devem ser verificados o `price`, o pacote e a Application na resposta.

## Preparação

- Crie um [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Obtenha o `application_id` na [lista de Applications](https://platform.acedata.cloud/documents/platform-application-list).
- Selecione, entre os `packages` dos [detalhes do serviço](https://platform.acedata.cloud/documents/platform-service-detail), um `package_id` que corresponda ao tipo de Application e que possa ser adquirido.

```shell
export PLATFORM_TOKEN='你的账户令牌'
export APPLICATION_ID='你的 Application ID'
export PACKAGE_ID='你的 Package ID'
```

## Visão geral da interface

| Item    | Conteúdo                                        |
| ---- | ----------------------------------------------- |
| Método   | `POST`                                          |
| URL  | `https://platform.acedata.cloud/api/v1/orders/` |
| Autenticação   | Account Token, o token OAuth requer `orders:write`      |
| Body | JSON                                            |

## Corpo da solicitação

Pedidos de uma única Application usam `application_id` + `package_id`; pedidos em lote usam `application_ids` + `package_ids` com comprimentos correspondentes. Pedidos comuns selecionam o método de pagamento na solicitação `/pay/` subsequente. Pedidos de compra no app para iOS passam `pay_way: "AppleIAP"` durante a criação e só podem selecionar um pacote Usage com `metadata.apple_product_id` e `metadata.apple_price`. As compras no app da Apple usam preços predefinidos independentes em dólares americanos, sem acumular descontos de membros, descontos por método de pagamento ou acréscimos do site; o valor cobrado na moeda local em outras regiões está sujeito à página de confirmação de pagamento da Apple.

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/orders/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"package_id\":\"${PACKAGE_ID}\"}"
```

## Descrição da resposta

Em caso de sucesso, retorna `201` e o novo objeto Order. Os campos principais incluem `id`, `price`, `discount`, `state`, `application_id/application_ids`, `package_id/package_ids`, `expired_at` e campos de data e hora. Novos pedidos normalmente ficam como `Pending`; em seguida, chame [Pagar pedido](https://platform.acedata.cloud/documents/platform-order-pay).

- `price` é o valor a pagar calculado pelo servidor com base no pacote, no acréscimo do site e nos descontos; não deve ser calculado pelo cliente.
- Quando o Package e o serviço ou tipo da Application não correspondem, retorna `400`.
- Packages gratuitos e gerenciados pelo sistema não podem ser obtidos diretamente pela interface pública de pedidos.
- A criação de pedidos para uma Application que não pertence à conta atual será rejeitada.
