[LobeChat](https://lobehub.com/) é um cliente de IA de código aberto que oferece suporte a plugins, bases de conhecimento e autoimplantação, podendo ser usado na versão online ou implantado com Docker. Ele oferece suporte a endpoints compatíveis personalizados com OpenAI, portanto, pode ser integrado ao Ace Data Cloud. Este artigo apresenta o processo de configuração.

## Processo de solicitação

Para integrar o Ace Data Cloud ao LobeChat, primeiro acesse o [console do Ace Data Cloud](https://platform.acedata.cloud/console/applications), obtenha seu API Token e guarde-o para uso posterior.

![Obter a API Key do Ace Data Cloud](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não tiver feito login ou se registrado, será redirecionado automaticamente para a página de login, onde será convidado a se registrar e fazer login; após o login e o registro, você retornará automaticamente à página atual.

Na primeira solicitação, haverá uma cota gratuita oferecida, permitindo experimentar gratuitamente os serviços de modelos do Ace Data Cloud.

## Configurar o Ace Data Cloud

Acesse **Configurações do aplicativo → Modelos de linguagem** do LobeChat, localize o cartão **OpenAI** e habilite-o, preenchendo:

| Campo       | Valor                              | Descrição                         |
| -------- | ------------------------------ | -------------------------- |
| API Key  | Seu Token do Ace Data Cloud        | Token copiado do console               |
| Endereço de proxy da API | `https://api.acedata.cloud/v1` | **Deve terminar com `/v1`**           |
| Modo de solicitação do cliente  | Habilitado                             | Conexão direta do navegador, a Key não passa pelo servidor do LobeChat |

![Interface de configuração do Provider OpenAI do LobeChat](https://cdn.acedata.cloud/629ef9d3084a.png)

> Ao usar a interface Chat Completions, mantenha a Responses API Specification desativada.

O LobeChat não adiciona automaticamente `/v1` à Base URL; o caminho da solicitação é diretamente `{Endereço de proxy da API}/chat/completions`:

| Endereço de proxy da API                              | Solicitação real                                                   | Resultado                       |
| ------------------------------------- | ------------------------------------------------------ | ------------------------ |
| `https://api.acedata.cloud/v1`        | `https://api.acedata.cloud/v1/chat/completions`        | Correto                       |
| `https://api.acedata.cloud/openai`    | `https://api.acedata.cloud/openai/chat/completions`    | Também funciona                      |
| `https://api.acedata.cloud/openai/v1` | `https://api.acedata.cloud/openai/v1/chat/completions` | 404 (não há `/v1` em `/openai`) |
| `https://api.acedata.cloud`           | `https://api.acedata.cloud/chat/completions`           | 404 (falta `/v1`)             |

Por padrão, o LobeChat chama `/v1/models` para carregar automaticamente os modelos. Quando o Ace Data Cloud retorna muitos modelos, a interface pode ficar muito longa; recomenda-se preencher manualmente uma allow list em «Lista de modelos → Nomes de modelos personalizados», separada por vírgulas em inglês. Caso seja necessário personalizar o nome exibido, você pode usar `=`, no formato `MODEL_ID=Nome exibido`.

## Selecionar modelos

O catálogo de modelos será atualizado continuamente. Priorize a lista de modelos carregada automaticamente pelo cliente; se precisar preencher manualmente, primeiro solicite `GET https://api.acedata.cloud/v1/models` para obter os IDs dos modelos atuais e, em seguida, escolha de acordo com os recursos de contexto, imagens e chamadas de ferramentas suportados pelo cliente.

## Verificar a integração

Se não tiver certeza se o problema está no LobeChat ou na rede, primeiro você pode usar o curl para verificar diretamente o endpoint (substitua `{token}` pelo seu Token):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

O retorno de um objeto `chat.completion` compatível com OpenAI indica que tanto o Token quanto o endpoint estão prontos; se retornar `HTTP 403 used_up`, isso indica que o Token é válido, mas o saldo é insuficiente. Basta recarregar no [console](https://platform.acedata.cloud/console/applications).

## Avançado: autoimplantação com Docker

Se desejar implantar uma versão privada para uso da equipe, você pode iniciar com um único comando Docker (substitua `{token}` pelo seu Token):

```bash
docker run -d \
  --name lobe-chat \
  -p 3210:3210 \
  -e OPENAI_API_KEY={token} \
  -e OPENAI_PROXY_URL=https://api.acedata.cloud/v1 \
  -e ACCESS_CODE=your-secret-password \
  -e OPENAI_MODEL_LIST="MODEL_ID" \
  lobehub/lobe-chat:latest
```

Abra `http://IP-do-seu-servidor:3210`, insira o `ACCESS_CODE` para usar. Os membros da equipe não precisam preencher suas próprias Keys. Para a explicação completa das variáveis de ambiente como `OPENAI_API_KEY`, `OPENAI_PROXY_URL` e `OPENAI_MODEL_LIST` usadas acima, consulte a [documentação de variáveis de ambiente de provedores de modelos do LobeChat](https://lobehub.com/docs/self-hosting/environment-variables/model-provider). Se usar proxy reverso nginx com HTTPS, certifique-se de adicionar `proxy_buffering off;`, caso contrário, as respostas em streaming serão armazenadas em buffer. Para mais formas de implantação, consulte o [guia de introdução à autoimplantação do LobeChat](https://lobehub.com/docs/self-hosting/start) e a [implantação com Docker Compose](https://lobehub.com/docs/self-hosting/platform/docker-compose).

## Perguntas frequentes

### Mensagem 404 Not Found

Geralmente, o endereço de proxy da API foi definido como `.../openai/v1` ou está sem `/v1`. Altere para `https://api.acedata.cloud/v1`.

### A lista de modelos está vazia

Ative a opção «Modo de solicitação do cliente»; ou preencha manualmente uma allow list de modelos em «Nomes de modelos personalizados».

### Mensagem 401 Unauthorized

Confirme que a API Key contém o Token do Ace Data Cloud (sem o prefixo `Bearer`, sem espaços extras) e que o saldo do aplicativo ao qual pertence é suficiente.
