title: "Excluir credencial de API da plataforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Exclua permanentemente uma credencial de API. Após a exclusão, ela é **imediatamente irrecuperável**, e todas as interfaces de negócio que estiverem usando este Token receberão `401` imediatamente.

> ℹ️ Esta interface pertence à **API de gerenciamento da plataforma AceDataCloud**, com o prefixo unificado `https://platform.acedata.cloud/api/v1/`.

## Visão geral da interface

| Item   | Conteúdo                                                                  |
| --- | ------------------------------------------------------------------- |
| Método  | `DELETE`                                                            |
| URL | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}` |
| Autenticação  | ✅ Requer token da conta                                                            |

`/credentials/{id}` e `/credentials/{id}/` estão atualmente disponíveis; os exemplos usam uniformemente o formato sem barra final.

## Instruções de autenticação (como obter o token da conta)

Cabeçalho da solicitação:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Veja como obtê-lo em [Gerenciar token de conta da plataforma AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

## Parâmetros de caminho

| Parâmetro              | Tipo   | Obrigatório  | Descrição        |
| --------------- | ---- | --- | --------- |
| `credential_id` | UUID | ✅   | ID da credencial a ser excluída |

## Exemplos de solicitação

### cURL

```shell
curl -X DELETE 'https://platform.acedata.cloud/api/v1/credentials/df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

cred_id = "df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6"
resp = requests.delete(
    f"https://platform.acedata.cloud/api/v1/credentials/{cred_id}",
    headers={"authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    timeout=10,
)
assert resp.status_code == 204, resp.text
print("✅ 已删除")
```

### Node.js

```javascript
const credId = 'df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6'
const r = await fetch(`https://platform.acedata.cloud/api/v1/credentials/${credId}`, {
  method: 'DELETE',
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log('status:', r.status) // 204
```

## Resposta

- **Sucesso**: `HTTP 204 No Content`, **sem corpo de resposta**.
- **Falha**: retorna JSON de erro, veja a tabela abaixo.

## Tratamento de erros

| HTTP | code                | Significado         |
| ---- | ------------------- | ---------- |
| 401  | `not_authenticated` | Token da conta ausente     |
| 403  | `permission_denied` | Esta credencial não pertence a você    |
| 404  | `not_found`         | A credencial não existe ou já foi excluída |

## Dicas práticas

- **A exclusão é irreversível** — a plataforma não mantém uma cópia do Token. Se você apenas suspeita de vazamento e ainda deseja manter os dados de monitoramento, deve usar [Rotacionar credencial de API da plataforma AceDataCloud](https://platform.acedata.cloud/documents/platform-credential-rotate) em vez de excluir.
- **A exclusão não reembolsa a cota já consumida por esta credencial**. O saldo da Application é deduzido em tempo real conforme o consumo, e a exclusão da credencial não afeta o saldo contábil.
- Após a exclusão, é possível reconfirmar as credenciais restantes por `application_id` através da [Lista de credenciais de API](https://platform.acedata.cloud/documents/platform-credential-list).
- **Verifique os chamadores antes da limpeza em massa**: a lista atualmente não possui um campo de última hora de uso; você deve confirmar, com base na configuração de implantação e nos registros de chamadas, que a credencial não está mais em uso, antes de excluí-las uma a uma.
