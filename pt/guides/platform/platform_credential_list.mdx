---
title: "Obter a lista de credenciais de API da plataforma AceDataCloud"

Liste de forma paginada as credenciais de API de negócios. Atualmente, esta resposta contém campos sensíveis de credenciais Token ou Identity, que devem ser processados apenas no servidor e é proibido gravá-los em logs, plataformas de análise, persistência no frontend ou repositórios públicos.

## Preparação

Crie um [Account Token](https://platform.acedata.cloud/documents/platform-token) e obtenha o UUID da conta atual por meio de `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='seu token de conta'
export USER_ID='seu UUID de conta'
```

## Visão geral da interface

| Item   | Conteúdo                                                   |
| --- | ---------------------------------------------------- |
| Método  | `GET`                                                |
| URL | `https://platform.acedata.cloud/api/v1/credentials/` |
| Autenticação  | Account Token, o token OAuth requer `credentials:read`       |
| Paginação  | `count` + `items`                                    |

Usuários comuns devem passar seu próprio `user_id` ou um `application_id` já autorizado; caso contrário, um `403` poderá ser retornado ao encontrar objetos sem permissão durante a paginação.

## Parâmetros de consulta

| Parâmetro                 | Tipo      | Obrigatório  | Descrição                             |
| ------------------ | ------- | --- | ------------------------------ |
| `user_id`          | string  | Conforme o cenário | Titular da credencial; suporta parâmetros repetidos                   |
| `application_id`   | UUID    | Não   | Filtrar por Application; suporta parâmetros repetidos        |
| `host`             | string  | Não   | Filtrar precisamente por host; suporta parâmetros repetidos             |
| `name`             | string  | Não   | Filtrar precisamente por nome; suporta parâmetros repetidos                 |
| `granted`          | boolean | Não   | `true` para credenciais concedidas a outros, `false` para credenciais de uso próprio |
| `limit` / `offset` | integer | Não   | Paginação                             |
| `ordering`         | string  | Não   | `created_at` ou `-created_at`   |

`service_id`, `disabled` e `expired` atualmente não são parâmetros de filtro.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/credentials/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Descrição da resposta

A resposta validada online é `{count, items}`. Cada item contém `id`, `application_id`, `application`, `user_id`, `creator_id`, `name`, `type`, `limited_amount`, `used_amount`, `expired_at`, `allowed_api_ids`, `host`, `granted`, `granted_to_user_id`, `tags`, `metadata` e campos de tempo, e retorna `token` ou `username/password` conforme o tipo.

> Atualmente, a resposta da lista retorna valores sensíveis completos. Não os exiba no console do navegador ou em sistemas de coleta, nem dependa da recuperação de texto simples por meio da lista; o cliente deve ser compatível com futuras políticas de mascaramento.
