---
title: "Atualizar o estado do pedido na plataforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Consultar ativamente o estado mais recente do método de pagamento correspondente ao pedido e sincronizá-lo com a plataforma. Esta solicitação pode acessar o serviço de pagamento e alterar o estado do pedido; use-a apenas quando o callback estiver atrasado ou for necessária confirmação imediata.

## Preparação

- Use o [Token da Conta](https://platform.acedata.cloud/documents/platform-token).
- Obtenha o seu ID do pedido na [lista de pedidos](https://platform.acedata.cloud/documents/platform-order-list).

```shell
export PLATFORM_TOKEN='seu token da conta'
export ORDER_ID='seu ID do pedido'
```

## Visão geral da API

| Item    | Conteúdo                                                                 |
| ---- | ------------------------------------------------------------------ |
| Método   | `POST`                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/refresh/` |
| Autenticação   | Proprietário do pedido ou superadministrador                                                        |
| Body | Geralmente vazio; no cenário de callback do PayPal, pode ser necessário `payer_id` / `PayerID`                         |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/refresh/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Em caso de sucesso, retorna o objeto Order completo após a atualização. Use `state` para determinar o resultado e `finished_at` como o horário de conclusão; o modelo atual não possui o campo `paid_at`. Os valores de estado incluem `Pending`, `Paid`, `Finished`, `Expired`, `Failed`, `Refunded`.

O prazo de pagamento apenas altera pedidos que ainda estão em `Pending` para `Expired`. Pedidos `Refunded` já reembolsados permanecem no estado reembolsado após a atualização ou o recebimento de um callback de pagamento atrasado.

## Recomendações de repetição

- Para pagamentos normais, priorize depender do callback da plataforma; faça refresh ativamente apenas quando o estado demorar a ser atualizado.
- Não faça polling frequente fixo. Recomenda-se backoff exponencial e interromper após um estado terminal claro.
- `401` indica token inválido; `403` indica que não é o proprietário do pedido; `404` indica que o pedido não existe.
- Quando a consulta ao serviço de pagamento falhar, mantenha o ID do pedido e o ID de rastreamento, tente novamente mais tarde; não crie pedidos duplicados para substituir a confirmação de estado.
