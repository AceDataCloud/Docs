---
title: "Obter a lista de solicitações de serviço da plataforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Retorna de forma paginada as Applications que a conta possui ou está autorizada a usar, incluindo saldo, status, resumo do serviço e credenciais associadas. Adequado para monitoramento de saldo em lote, localização do ID da Application e acesso ao gerenciamento de credenciais.

## Preparação

1. Faça login na [plataforma AceDataCloud](https://platform.acedata.cloud).
2. Crie um token de conta no [console de Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. Usuários comuns usam `user_id=me`; também é possível obter seu próprio UUID em `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='seu token de conta'
```

## Visão geral da interface

| Item   | Conteúdo                                                    |
| --- | ----------------------------------------------------- |
| Método  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Autenticação  | Account Token, o token OAuth requer `applications:read`       |
| Paginação  | `count` + `items`                                     |

Usuários comuns devem informar `user_id=me`. Se não for informado, a consulta não será primeiro restrita por conta, e a paginação poderá retornar `403` ao encontrar objetos sem permissão; administradores podem visualizar a tabela inteira sem informá-lo.

## Parâmetros de consulta

| Parâmetro            | Tipo          | Obrigatório     | Descrição                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Obrigatório para usuários comuns | Sujeito da consulta; aceita parâmetros repetidos                                         |
| `affiliation` | string      | Não      | `owner` (padrão) ou `granted`; ambos podem ser passados repetidamente para obter a união, eficaz somente quando há `user_id` |
| `service_id`  | UUID        | Não      | Filtrar por serviço; aceita parâmetros repetidos                                        |
| `scope`       | string      | Não      | `Individual` ou `Global`; aceita parâmetros repetidos                      |
| `type`        | string      | Não      | `Usage` ou `Period`; aceita parâmetros repetidos                           |
| `limit`       | integer     | Não      | Itens por página, máximo de 100                                         |
| `offset`      | integer     | Não      | Deslocamento da paginação                                               |
| `ordering`    | string      | Não      | Suporta apenas `created_at` ou `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` e `tag` atualmente não são parâmetros de filtragem do servidor. Para alertas de saldo, após obter a lista, deve-se avaliar no cliente com base em `remaining_amount`, `service.unit` e no limite de negócio de cada Application.

## Exemplos de solicitação

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Visualizar ao mesmo tempo as Applications que você possui e as que outras pessoas autorizaram para você:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Descrição da resposta

A resposta é `{count, items}`. Cada item contém os campos do modelo Application e também:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: resumo das credenciais que o chamador atual tem permissão para visualizar;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`;
- o valor real de `scope` é `Individual` ou `Global`;
- o valor real de `type` é `Usage` ou `Period`.

`remaining_amount` pode estar vazio; o cliente deve primeiro verificar se está vazio antes de fazer comparações numéricas. A unidade da cota é determinada por `service.unit`.
