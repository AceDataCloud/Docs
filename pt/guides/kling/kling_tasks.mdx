A principal funcionalidade da API Kling Tasks é consultar o status de execução de uma tarefa inserindo o ID da tarefa gerado pela API Kling Videos Generation.

Este documento apresentará detalhadamente as instruções de integração da API Kling Tasks, ajudando você a integrar facilmente e aproveitar plenamente os poderosos recursos dessa API. Por meio da API Kling Tasks, você pode facilmente consultar o status de execução das tarefas da API Kling Videos Generation.

## Processo de solicitação

Para usar a API Kling Videos Generation, primeiro obtenha seu API Token no [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) e guarde-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver conectado ou registrado, será automaticamente redirecionado para a página de login, onde será convidado a se registrar e entrar. Após a conclusão, você retornará automaticamente à página atual.

**Um único API Token pode chamar todos os serviços da plataforma, sem necessidade de solicitar separadamente para cada serviço.** A primeira solicitação oferecerá créditos gratuitos para uma experiência sem custo; quando os créditos forem insuficientes, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Exemplo de solicitação

A API Kling Tasks pode ser usada para consultar os resultados da API Kling Videos Generation. Para saber como usar a API Kling Videos Generation, consulte a documentação [Kling Videos Generation API ](https://platform.acedata.cloud/documents/kling-videos)。

Usaremos como exemplo um ID de tarefa retornado pelo serviço API Kling Videos Generation para demonstrar como usar esta API. Suponha que temos um ID de tarefa: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0; em seguida, demonstraremos como fazer isso passando um ID de tarefa.

### Configurar cabeçalhos e corpo da solicitação

**Request Headers** incluem:

- `accept`: especifica o recebimento de resultados de resposta no formato JSON; aqui, preencha com `application/json`.
- `authorization`: a chave para chamar a API, que pode ser selecionada diretamente na lista suspensa após a solicitação.

**Request Body** inclui:

- `id`: o ID da tarefa enviada.
- `action`: o modo de operação da tarefa.

### Exemplo de código

É possível observar que vários códigos em diferentes linguagens já foram gerados automaticamente no lado direito da página, como mostrado na imagem:

Alguns exemplos de código são os seguintes:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

O resultado retornado possui vários campos. O campo `request` é o request body ao iniciar a tarefa, enquanto o campo `response` é o response body retornado após a conclusão da tarefa. A descrição dos campos é a seguinte.

- `id`, o ID que gera esta tarefa de vídeo, usado para identificar exclusivamente esta tarefa de geração de vídeo.
- `request`, as informações da solicitação na consulta da tarefa de vídeo.
- `response`, as informações de retorno na consulta da tarefa de vídeo.
- `created_at`, horário de criação da tarefa, timestamp Unix (segundos, ponto flutuante).
- `started_at`, horário de início da execução da tarefa, timestamp Unix (segundos, ponto flutuante).
- `finished_at`, horário de conclusão da tarefa, timestamp Unix (segundos, ponto flutuante). Este campo não é retornado quando a tarefa não foi concluída.
- `elapsed`, tempo de execução da tarefa, em segundos (ponto flutuante, com 3 casas decimais). Este campo não é retornado quando a tarefa não foi concluída.

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `400 token_mismatched`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`：Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`：Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`：Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```json
{

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
