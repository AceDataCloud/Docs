Este artigo apresentará um tipo de instrução de integração da API Kling Videos Generation, que pode gerar vídeos oficiais do Kling inserindo parâmetros personalizados.

## Processo de solicitação

Para usar a API Kling Videos Generation, primeiro acesse o [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e reserve-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver conectado ou registrado, será automaticamente redirecionado para a página de login, que o convidará a registrar-se e fazer login. Após a conclusão, você retornará automaticamente à página atual.

**Um único API Token pode chamar todos os serviços da plataforma, sem necessidade de solicitar um separadamente para cada serviço.** A primeira solicitação concederá créditos gratuitos para uma experiência gratuita; quando os créditos forem insuficientes, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Uso básico

Primeiro, vamos entender o método básico de uso: basta inserir o prompt `prompt`, a ação de geração `action`, a imagem de referência do primeiro quadro `start_image_url` e o modelo `model` para obter o resultado processado. Primeiro, é necessário passar simplesmente um campo `action`, cujo valor é `text2video`. Ele inclui principalmente três ações: texto para vídeo (`text2video`), imagem para vídeo (`image2video`) e extensão de vídeo (`extend`). Em seguida, também precisamos inserir o modelo `model`. Atualmente, há principalmente os modelos `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`; o conteúdo específico é o seguinte:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Podemos ver que aqui configuramos os Request Headers, incluindo:

- `accept`: qual formato de resultado de resposta deseja receber; aqui, preencha como `application/json`, ou seja, o formato JSON.
- `authorization`: a chave para chamar a API, que pode ser selecionada diretamente em uma lista suspensa após a solicitação.

Além disso, configuramos o Request Body, incluindo:

- `model`: o modelo para gerar vídeos, principalmente os modelos `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode`: o modo de geração de vídeo, com valores opcionais modo padrão `std`, modo rápido `pro` e modo 4K nativo `4k`. Entre eles, `4k` oferece suporte apenas a `kling-v3` e `kling-v3-omni`, e é incompatível com `camera_control` (controle de movimento da câmera).
- `action`: a ação desta tarefa de geração de vídeo, contendo principalmente três ações: texto para vídeo (`text2video`), imagem para vídeo (`image2video`) e extensão de vídeo (`extend`).
- `start_image_url`: o link da imagem de referência do primeiro quadro que deve ser carregada ao escolher a ação de imagem para vídeo `image2video`.
- `end_image_url`: opcional ao gerar vídeo a partir de imagem, especifica o quadro final.
- `duration`: duração do vídeo, em segundos. `kling-v3` e `kling-v3-omni` oferecem suporte a durações inteiras de 3 a 15 segundos; `kling-o1` oferece suporte apenas a 5 segundos; os outros modelos oferecem suporte a 5 ou 10 segundos.
- `generate_audio`: se deve gerar áudio simultaneamente, opcional, valor booleano. Compatível com `kling-v3`, `kling-v3-omni` e `kling-v2-6` (somente modo pro). O padrão é `false`.
- `aspect_ratio`: proporção de aspecto do vídeo, opcional, compatível com `16:9`, `9:16`, `1:1`, o padrão é `16:9`.
- `cfg_scale`: intensidade de relevância, intervalo [0,1]; quanto maior, mais fiel ao prompt.
- `camera_control`: opcional, parâmetro de objeto que controla o movimento da câmera, compatível com predefinições type/simple e configurações como horizontal, vertical, pan, tilt, roll e zoom.
- `negative_prompt`: opcional, prompt negativo para elementos que não se deseja que apareçam, com no máximo 200 caracteres.
- `image_list`: lista de imagens de referência Omni, aplicável aos modelos `kling-o1` e `kling-v3-omni`; consulte abaixo «Referência universal Omni» para o uso.
- `video_list`: lista de vídeos de referência Omni (compatível com edição de vídeo), aplicável aos modelos `kling-o1` e `kling-v3-omni`; consulte abaixo «Referência universal Omni» para o uso.
- `prompt`: prompt.
- `callback_url`: URL que precisa receber o resultado de retorno de chamada.
- `async`: opcional; quando definido como `true`, a interface retorna imediatamente `task_id`, sem necessidade de fornecer `callback_url`; em seguida, obtenha o resultado consultando periodicamente a interface de consulta de tarefas correspondente.

Após a seleção, é possível ver que o código correspondente também é gerado no lado direito, como mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

- `video_id`, o ID do vídeo da tarefa de geração de vídeo neste momento.
- `video_url`, o link do vídeo da tarefa de geração de vídeo neste momento.

- `state`, o estado da tarefa de geração de vídeo neste momento.

Podemos ver que obtivemos informações satisfatórias do vídeo. Só precisamos obter o vídeo Kling gerado com base no endereço do link de vídeo em `data` no resultado.

Além disso, se desejar gerar o código de integração correspondente, você poderá copiá-lo diretamente, por exemplo, o código CURL é o seguinte:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Matriz de capacidades dos modelos

### Cobrança de vídeos de referência O1 e Omni

`kling-o1` cobra de acordo com o modo e se `video_list` é fornecido. A seguir estão os preços para vídeos finais de 5 segundos:

| Modo  | Sem vídeo de referência | Com vídeo de referência |
| --- | ------------: | ------------: |
| std | 4.005 Credits | 6.010 Credits |
| pro | 5.340 Credits | 8.010 Credits |
As solicitações bem-sucedidas de `kling-o1` e `kling-v3-omni` com vídeos de referência são cobradas pelos segundos faturáveis: std custa **1.202 Credits/segundo**, e pro custa **1.602 Credits/segundo**. Por exemplo, gerar 5 segundos no modo std custa 6.010 Credits. Omitir `video_list` não acionará a modalidade de vídeo de referência; `image_list`, imagens de primeiro quadro e último quadro também não são considerados vídeos de referência. Vídeos de referência não podem ser usados simultaneamente com `generate_audio=true`.

A edição de vídeo com `refer_type=base` (padrão) pode seguir a duração do vídeo de referência, e o faturamento final é arredondado para o segundo inteiro mais próximo com base na duração real do vídeo final: por exemplo, 5.708 segundos são cobrados como 6 segundos, e 5.041 segundos como 5 segundos. `refer_type=feature` usa o `duration` solicitado. `usage.reference_video_seconds` na resposta fornece os segundos finais faturáveis; o preço estimado no momento da solicitação pode diferir da cobrança final.

O suporte a parâmetros varia consideravelmente entre os diferentes modelos. A matriz abaixo foi compilada a partir da [documentação oficial de video models da Kling](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels). Antes de chamar, verifique se a combinação atual de `model` / `mode` / `duration` suporta a funcionalidade necessária; caso contrário, erros como `model/mode/duration(...) is not supported with image_tail` serão retornados.

| Modelo                  | Modo             | `end_image_url` (primeiro e último quadro) | `generate_audio` (áudio) | `camera_control` (movimento de câmera) | Observações                                           |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ Apenas `duration=5`     | ❌                    | ✅ Apenas `duration=5`     | `extend` não suporta `negative_prompt` nem `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | Vídeo a partir de múltiplas imagens, todos os modos de `extend` disponíveis                         |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Modo único, apenas `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Modo único, apenas `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | O único modelo não v3 que também suporta áudio                             |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | Intervalo de `duration` de 3–15 segundos                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | O modo 4K é incompatível com movimento de câmera                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Apenas suporta `duration=5`                             |

Observações:

- `mode=4k` é suportado apenas por `kling-v3` e `kling-v3-omni`; além disso, é mutuamente exclusivo com `camera_control` (movimento de câmera).
- `end_image_url` só pode ser usado com `start_image_url` quando `action=image2video`. Enviar apenas `end_image_url` (sem `start_image_url`) será rejeitado.
- `kling-v3` / `kling-v3-omni` aceitam qualquer `duration` inteiro de 3–15 segundos; `kling-o1` aceita apenas 5; os demais modelos aceitam apenas 5 ou 10.
- `generate_audio` é `false` por padrão. Apenas `kling-v3`, `kling-v3-omni` e `kling-v2-6` (modo pro) oferecem suporte.

## Funcionalidade de extensão de vídeo

Se você quiser continuar gerando um vídeo Kling já gerado, pode definir o parâmetro `action` como `extend` e inserir o ID do vídeo que precisa continuar gerando. A obtenção do ID do vídeo é feita com base no uso básico, conforme mostrado na imagem abaixo:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Neste momento, é possível ver que o ID do vídeo é:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Observe que o `video_id` no vídeo aqui é o ID do vídeo após a geração. Se você não sabe como gerar um vídeo, pode consultar o uso básico acima para gerar um vídeo.

Em seguida, devemos obrigatoriamente preencher o prompt que precisa ser estendido na próxima etapa para personalizar o vídeo gerado, podendo especificar o seguinte conteúdo:

- `model`: o modelo para gerar vídeos, principalmente os modelos `kling-v1`, `kling-v1-5` e `kling-v1-6`.
- `mode`: o modo de geração de vídeo, com valores opcionais: modo padrão `std`, modo ultrarrápido `pro` e modo 4K nativo `4k` (suportado apenas por `kling-v3` e `kling-v3-omni`, incompatível com o controle de movimento de câmera).
- `duration`: a duração do vídeo desta tarefa de geração de vídeo, contendo principalmente 5s e 10s.
- `start_image_url`: o link da imagem de referência do primeiro quadro que deve ser enviado ao selecionar o comportamento de geração de vídeo a partir de imagem `image2video`.
- `prompt`: prompt.

O exemplo de preenchimento é o seguinte:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Após o preenchimento, o código é gerado automaticamente da seguinte forma:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

O código Python correspondente:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Clique em executar, e você poderá observar que um resultado será obtido, conforme abaixo:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```
Pode-se ver que o conteúdo do resultado é consistente com o anterior, e isso implementa a funcionalidade de extensão de vídeo.

## Referência Omni Completa (edição de vídeo / vídeo de referência / referência de múltiplas imagens)

`kling-o1` e `kling-v3-omni` são dois modelos independentes, ambos suportando a capacidade de «referência completa». Com base em texto para vídeo (`action=text2video`), é possível transmitir adicionalmente imagens de referência ou vídeos de referência, realizando **referência de múltiplas imagens, vídeo de referência e edição direta de vídeos existentes**.

**Convenção principal**: os materiais de referência devem ser referenciados no `prompt` no formato `&lt;&lt;<image_1>>>`, `&lt;&lt;<video_1>>>` (a numeração começa em 1), correspondendo aos materiais nas posições correspondentes de `image_list` / `video_list`, para que o modelo aplique essas referências. Se apenas os materiais forem transmitidos sem serem referenciados no prompt, eles serão ignorados.

> Aviso de segurança: a API atual não disponibiliza `element_list`. Os IDs da Kling Element Library não são isolados por locatário; antes de disponibilizar uma Element Management API com isolamento por locatário, use `image_list` para transmitir imagens de referência do sujeito.

Solicitações Omni não suportam `negative_prompt`, `cfg_scale` ou `camera_control`, nem podem usar `mode=4k`. Quando houver um vídeo de referência, `generate_audio` deve ser `false`.

### Vídeo de referência e edição de vídeo (`video_list`)

`video_list` é usado para transmitir vídeos de referência e é o cenário mais comum desta capacidade. Os campos dos elementos do array são os seguintes:

- `video_url`: link do vídeo de referência, não pode estar vazio. No máximo 1 vídeo MP4/MOV, tamanho do arquivo ≤200MB, taxa de quadros de 24–60fps. `kling-o1` exige duração de 3–10 segundos, largura e altura entre 700–2160px; `kling-v3-omni` exige duração de 3–15,5 segundos, largura e altura entre 700–4553px, total de pixels ≤8.294.400, proporção de aspecto de 0,4–2.
- `refer_type`: tipo de referência, opcional `base` (padrão, **vídeo base a ser editado**, ou seja, “editar diretamente o vídeo”, podendo adicionar/remover/modificar elementos, alterar composição, trocar estilo, trocar cores, trocar clima etc.) ou `feature` (**referência de características**, referenciando seu estilo / movimento de câmera / continuação da próxima tomada).
- `keep_original_sound`: se mantém o áudio original do vídeo, opcional `yes` (manter) ou `no` (remover).

> Observação: quando houver um vídeo de referência, `generate_audio` deve ser `false`. Um vídeo com `refer_type=base` não pode especificar novamente quadro inicial / quadro final.

Um exemplo CURL de edição de um vídeo existente (alterando o vídeo para estilo de animação) é o seguinte:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Referência de múltiplas imagens (`image_list`)

`image_list` é usado para transmitir imagens de referência (elementos / cenas / estilos etc.). Os campos dos elementos do array são os seguintes:

- `image_url`: link da imagem de referência, não pode estar vazio. Requisitos: formato .jpg/.jpeg/.png; tamanho do arquivo ≤10MB; lado mais curto ≥300px; proporção de aspecto de 1:2,5 ~ 2,5:1.
- `type`: opcional. Quando não transmitido, é usado como imagem de referência pura; quando transmitido como `first_frame` / `end_frame`, é usado respectivamente como quadro inicial / quadro final (equivalente a `start_image_url` / `end_image_url`).

Ao usar, é necessário referenciar no `prompt` com `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Limite de quantidade: quando não houver vídeo de referência, imagens de referência ≤ 7; quando houver vídeo de referência, imagens de referência ≤ 4. Quando apenas o quadro inicial / final for transmitido, também é possível usar diretamente `start_image_url` / `end_image_url`, mas o quadro final deve ser usado junto com o quadro inicial.

> Observação: se `start_image_url` / `end_image_url` e `image_list` forem transmitidos simultaneamente, os quadros inicial / final serão posicionados antes de `image_list`, o que pode afetar a relação de correspondência da numeração de `&lt;&lt;<image_N>>>`. Recomenda-se escolher um dos dois: quando forem necessários quadros inicial / final, especifique diretamente o `type` em `image_list`, não misture com `start_image_url` / `end_image_url`.

Exemplo CURL de geração de vídeo com referência de múltiplas imagens:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Callback assíncrono

Como o tempo de geração da Kling Videos Generation API é relativamente longo, aproximadamente 1–2 minutos, se a API não responder por muito tempo, a solicitação HTTP manterá a conexão aberta, resultando em consumo adicional de recursos do sistema; por isso, esta API também fornece suporte a callback assíncrono.

O fluxo geral é: quando o cliente inicia uma solicitação, especifica adicionalmente um campo `callback_url`; após o cliente iniciar a solicitação da API, a API retornará imediatamente um resultado contendo um campo `task_id`, que representa o ID da tarefa atual. Quando a tarefa for concluída, o resultado do vídeo gerado será enviado na forma de POST JSON para o `callback_url` especificado pelo cliente, incluindo também o campo `task_id`, permitindo que o resultado da tarefa seja associado pelo ID.

A seguir, vamos entender por meio de um exemplo como operar especificamente.

Primeiro, o callback Webhook é um serviço que pode receber solicitações HTTP; os desenvolvedores devem substituí-lo pela URL de um servidor HTTP criado por eles mesmos. Aqui, para facilitar a demonstração, é utilizado um site público de exemplo de Webhook, https://webhook.site/; ao abrir esse site, é possível obter uma URL de Webhook, como mostrado na imagem:

![](https://cdn.acedata.cloud/tbcnai.png)

Copie esta URL para poder usá-la como Webhook; o exemplo aqui é `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Em seguida, podemos definir o campo `callback_url` como a URL de Webhook acima e, ao mesmo tempo, preencher os parâmetros correspondentes; o conteúdo específico é mostrado na imagem:

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `400 token_mismatched`: Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`: Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`: Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`: Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`: Erro interno do servidor, algo deu errado no servidor.

## Conclusão

Por meio deste documento, você já aprendeu como usar a API Kling Videos Generation para gerar vídeos inserindo prompts e imagens de referência do primeiro quadro. Esperamos que este documento possa ajudá-lo a integrar e usar melhor esta API. Caso tenha alguma dúvida, entre em contato com nossa equipe de suporte técnico a qualquer momento.

### Kling 3.0 Turbo

`model="kling-v3-turbo"` oferece suporte à geração de vídeo a partir de texto e à geração de vídeo a partir de imagem do primeiro quadro, com duração em números inteiros de 3–15 segundos. `mode="std"` gera 720p, e `mode="pro"` gera 1080p. Este modelo possui áudio nativo e não oferece uma opção para desativá-lo; omita `generate_audio` ou defina-o como `true`. Este modelo não oferece suporte a quadro final, objeto de movimento de câmera, prompt negativo independente ou `cfg_scale`. Descreva diretamente no `prompt` o conteúdo que deseja ou deseja evitar que apareça.

### Vídeos com múltiplas cenas

`kling-v3` e `kling-v3-omni` oferecem suporte a `multi_shot=true`. `shot_type="intelligence"` cria automaticamente as cenas com base no `prompt`; `shot_type="customize"` fornece 1–6 cenas por meio de `multi_prompt`, cada item contendo um `index` que aumenta consecutivamente a partir de 1, um `prompt` de no máximo 512 caracteres e uma `duration` em número inteiro de pelo menos 1 segundo. A soma das durações de todas as cenas deve ser igual à `duration` total. As cenas personalizadas não usam o `prompt` global. Vídeos com múltiplas cenas são cobrados de acordo com o modelo selecionado, a qualidade, a configuração de áudio e a duração total.
