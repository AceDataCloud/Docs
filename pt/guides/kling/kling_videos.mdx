Este documento apresenta as instruções para integração da API de Geração de Vídeos Kling, que permite gerar vídeos oficiais da Kling a partir de parâmetros personalizados.

## Processo de Solicitação

Para usar a API, é necessário solicitar o serviço na página correspondente do [Kling Videos Generation API](https://platform.acedata.cloud/documents/3b921a16-a411-4557-8335-53f21d3f9e46). Ao acessar a página, clique no botão "Acquire", conforme mostrado na imagem:

![](https://cdn.acedata.cloud/q6ytrc.png)

Se você ainda não estiver logado ou registrado, será redirecionado automaticamente para a página de login, onde poderá se registrar e entrar. Após o login, você retornará automaticamente à página atual.

Na primeira solicitação, será concedida uma cota gratuita para uso da API.

## Uso Básico

Primeiro, entenda a forma básica de uso: basta fornecer o prompt `prompt`, a ação de geração `action`, a imagem de referência inicial `start_image_url` e o modelo `model` para obter o resultado processado. Inicialmente, é necessário passar o campo `action` com o valor `text2video`, que contempla três tipos de ação: geração de vídeo a partir de texto (`text2video`), geração de vídeo a partir de imagem (`image2video`) e extensão de vídeo (`extend`). Também precisamos informar o modelo `model`. Atualmente, os principais modelos são: `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni` e `kling-video-o1`. Veja a seguir:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Aqui configuramos os Headers da requisição, incluindo:

- `accept`: formato desejado para a resposta, aqui configurado como `application/json` (formato JSON).
- `authorization`: chave de acesso para chamar a API, que pode ser selecionada após a solicitação.

Além disso, configuramos o corpo da requisição (Request Body), incluindo:

- `model`: modelo para geração do vídeo, entre os modelos mencionados acima.
- `mode`: modo de geração do vídeo, com opções `std` (padrão), `pro` (rápido) e `4k` (4K nativo). O modo `4k` é suportado apenas pelos modelos `kling-v3` e `kling-v3-omni` e não é compatível com `camera_control` (controle de câmera).
- `action`: ação da tarefa de geração de vídeo, podendo ser `text2video`, `image2video` ou `extend`.
- `start_image_url`: URL da imagem de referência inicial, obrigatório para a ação `image2video`.
- `end_image_url`: opcional para `image2video`, especifica a imagem final.
- `duration`: duração do vídeo em segundos. Para os modelos `kling-v3` e `kling-v3-omni` é possível duração flexível entre 3 e 15 segundos (inteiros); para os demais modelos, apenas 5 ou 10 segundos.
- `generate_audio`: opcional, booleano que indica se o áudio será gerado simultaneamente. Suportado pelos modelos `kling-v3`, `kling-v3-omni` e `kling-v2-6` (apenas no modo `pro`). Padrão é `false`.
- `aspect_ratio`: proporção do vídeo, opcional, suporta `16:9`, `9:16` e `1:1`. Padrão é `16:9`.
- `cfg_scale`: intensidade de aderência ao prompt, valor entre [0,1], quanto maior, mais fiel ao prompt.
- `camera_control`: opcional, parâmetros para controlar o movimento da câmera, suporta presets `type/simple` e configurações como `horizontal`, `vertical`, `pan`, `tilt`, `roll`, `zoom`.
- `negative_prompt`: opcional, prompt negativo para evitar elementos indesejados, até 200 caracteres.
- `element_list`: lista de referências principais, aplicável apenas ao modelo `kling-video-o1`. Consulte o [documento oficial](https://docs.qingque.cn/d/home/eZQAyImcbaS0fz-8ANjXvU5ed?identityId=1oEG9JKKMFv#section=h.5t7wme23nn6z) para uso detalhado.
- `video_list`: vídeos de referência via URL, aplicável apenas ao modelo `kling-video-o1`. Consulte o [documento oficial](https://docs.qingque.cn/d/home/eZQAyImcbaS0fz-8ANjXvU5ed?identityId=1oEG9JKKMFv#section=h.5t7wme23nn6z) para uso detalhado.
- `prompt`: prompt de entrada.
- `callback_url`: URL para callback dos resultados.

Após configurar, o código correspondente é gerado no lado direito, conforme a imagem:

Clique no botão "Try" para testar. O resultado obtido será:

Os campos retornados são:

- `task_id`: ID da tarefa.
- `video_id`: ID do vídeo gerado.
- `video_url`: URL do vídeo gerado.
- `duration`: duração do vídeo.
- `state`: estado da tarefa.

Com o link do vídeo em `video_url`, você pode acessar o vídeo Kling gerado.

Para gerar o código de integração, basta copiar o código gerado, por exemplo, o CURL:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v1",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Função de Extensão de Vídeo

Para continuar a geração de um vídeo Kling já existente, defina o parâmetro `action` como `extend` e informe o ID do vídeo a ser estendido. O ID do vídeo pode ser obtido conforme o uso básico, como mostrado:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

O ID do vídeo é:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Atenção: o `video_id` é o ID do vídeo gerado. Se não souber como gerar o vídeo, consulte a seção de uso básico.

Em seguida, preencha o prompt para a extensão do vídeo, com os seguintes parâmetros:

- `model`: modelo para geração, como `kling-v1`, `kling-v1-5` ou `kling-v1-6`.
- `mode`: modo de geração, `std`, `pro` ou `4k` (este último apenas para `kling-v3` e `kling-v3-omni`, incompatível com controle de câmera).
- `duration`: duração do vídeo, geralmente 5 ou 10 segundos.
- `start_image_url`: obrigatório para ação `image2video`, URL da imagem inicial.
- `prompt`: prompt para a extensão.

Exemplo de preenchimento:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

O código gerado automaticamente é:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Código Python correspondente:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Ao executar, o resultado será:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7822108635/extendVideo/Cjil4mfBfs0AAAAAAKhr6A-0_raw_video_1.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```

O conteúdo do resultado é semelhante ao anterior, confirmando a funcionalidade de extensão de vídeo.

## Callback Assíncrono

Como a geração de vídeos pela Kling Videos Generation API pode levar de 1 a 2 minutos, a API oferece suporte a callbacks assíncronos para evitar que a requisição HTTP fique aberta por muito tempo, consumindo recursos do sistema.

O fluxo é: o cliente inclui o campo `callback_url` na requisição. A API retorna imediatamente um resultado com o campo `task_id`, identificando a tarefa. Quando a tarefa é concluída, o resultado da geração do vídeo é enviado via POST JSON para o `callback_url` informado, incluindo o `task_id` para associação.

Veja o exemplo a seguir.

Primeiro, o Webhook callback é um serviço que recebe requisições HTTP. O desenvolvedor deve substituir pelo URL do seu servidor HTTP. Para demonstração, usamos o site público https://webhook.site/, que gera um URL de Webhook, conforme imagem:

![](https://cdn.acedata.cloud/tbcnai.png)

Copie esse URL, por exemplo: `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Configure o campo `callback_url` com esse URL e preencha os demais parâmetros, conforme a imagem:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Ao executar, o resultado imediato será:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Após alguns instantes, no site `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3` você poderá ver o resultado da geração do vídeo, conforme imagem:

![](https://cdn.acedata.cloud/zv5u2q.png)

Conteúdo do callback:

```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7822108635/text2video/CjJzzGfBfqcAAAAAAKdVMQ-0_raw_video_1.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Note que o campo `task_id` permite associar o resultado à tarefa original.

## Tratamento de Erros

Ao chamar a API, se ocorrer algum erro, a API retornará um código e mensagem de erro correspondentes, por exemplo:

- `400 token_mismatched`: requisição inválida, possivelmente por parâmetros ausentes ou inválidos.
- `400 api_not_implemented`: requisição inválida, possivelmente por parâmetros ausentes ou inválidos.
- `401 invalid_token`: não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`: muitas requisições, limite de taxa excedido.
- `500 api_error`: erro interno do servidor.

### Exemplo de resposta de erro

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
