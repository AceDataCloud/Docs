Maestro é uma interface de produção de vídeo **nativa para Agent**: você usa um `prompt` em linguagem natural para descrever o vídeo desejado (opcionalmente anexando imagens / vídeos / áudios de referência com `file_urls`), e um «diretor de IA» sem interface gráfica concluirá automaticamente a seleção do tema, a escrita do roteiro, a geração de imagens, a narração, a trilha sonora, a composição e a renderização, produzindo por fim um vídeo final com legendas e fazendo upload para a CDN.

Este documento apresentará detalhadamente as instruções de integração da API de geração de vídeo Maestro, ajudando você a integrar rapidamente e aproveitar ao máximo os recursos desta API.

Esta é uma interface de **tarefa assíncrona**: após o envio, `task_id` será retornado imediatamente e, em seguida, o resultado será obtido por polling por meio da [API de consulta de tarefas Maestro](/pt/guides/maestro/maestro_tasks) (`POST /maestro/tasks`) (o polling é gratuito e não é cobrado). Para continuar iterando sobre um vídeo existente, você pode usar `action: remix` / `edit` / `extend` em conjunto com `ref_task_id`.

## Processo de solicitação

Para usar a API de geração de vídeo Maestro, primeiro acesse o [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e guarde-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver conectado ou registrado, será automaticamente redirecionado para a página de login, onde será convidado a se registrar e entrar; após a conclusão, retornará automaticamente à página atual.

**Um único API Token pode chamar todos os serviços da plataforma, sem necessidade de solicitar um separadamente para cada serviço.** A primeira solicitação concede créditos gratuitos para experimentar sem custo; quando os créditos forem insuficientes, você pode recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [API de geração de vídeo Maestro →](https://platform.acedata.cloud/documents/maestro-videos)

## Uso básico

`POST https://api.acedata.cloud/maestro/videos`

O uso mais básico requer apenas o envio de uma descrição em linguagem natural em `prompt`. O diretor de IA decidirá automaticamente o roteiro, as imagens, a narração e a edição. Primeiro, vamos entender os cabeçalhos e o corpo da solicitação que precisam ser configurados.

**Request Headers** incluem:

- `accept`: o formato em que você deseja receber a resposta. Preencha com `application/json`, ou seja, o formato JSON.
- `authorization`: a chave para chamar a API. Após solicitá-la, você poderá selecioná-la diretamente na lista suspensa.
- `content-type`: o formato do corpo da solicitação. Preencha com `application/json`.

**Request Body** inclui principalmente:

- `prompt`: descreva em linguagem natural o vídeo que deseja criar (tema, o que será exibido, estilo e público-alvo).
- `langs`: matriz de idiomas do vídeo final. Envie apenas um idioma por vez, como `["zh-cn"]`. O padrão é `["zh-cn"]`.
- `aspect`: proporção da imagem, `9:16` (padrão) / `16:9` / `1:1`.
- `duration`: duração desejada (segundos). O padrão é 30.

Todos os campos do corpo da solicitação são mostrados na tabela abaixo:

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `prompt` | string | Sim | Descreva em linguagem natural o vídeo que deseja criar (tema, o que será exibido, estilo e público-alvo). O roteiro, as imagens, a narração e a edição são decididos pela IA. |
| `action` | string | Não | `generate` (padrão, gera um novo vídeo) / `remix` / `edit` / `extend` (itera sobre um vídeo existente; requer `ref_task_id`) |
| `ref_task_id` | string | Não | Obrigatório quando `action` for remix / edit / extend: `task_id` da tarefa anterior usada como ponto de partida |
| `file_urls` | string[] | Não | Mídia de referência (URL de imagem / vídeo / áudio), por exemplo, imagem do produto ou logotipo a ser exibido, ou um trecho de material ao qual adicionar legendas |
| `langs` | string[] | Não | Idioma do vídeo final; apenas um pode ser enviado por vez, como `["zh-cn"]`. O padrão é `["zh-cn"]` |
| `aspect` | string | Não | `9:16` (padrão) / `16:9` / `1:1`; saída unificada em 1080p/30 fps |
| `duration` | int | Não | Duração desejada (segundos); o padrão é 30 e são aceitos **5–300 segundos**. A cobrança é baseada na duração real do vídeo final, mas não excederá a duração solicitada |
| `scenario` | string | Não | Tipo de vídeo: `auto` / `narrated` / `captions` / `avatar` / `drama`. `captions` requer o envio de um vídeo de origem, e `avatar` requer o envio de um retrato |
| `style` | string | Não | Predefinições de estilo visual: `auto` (padrão) / `cinematic` / `glass` / `luxury` / `swiss` / `modern` / `editorial` / `warm` / `vibrant` / `neon` / `mono` / `pastel` / `bold` / `industrial` / `futuristic` / `retro`. Texto livre também é aceito como uma instrução flexível. Pode ser definido independentemente de `scenario` |
| `voice` | string | Não | Voz da narração (independente do idioma e aplicável a vários idiomas): `auto` (padrão) / `warm-female` / `bright-female` / `anchor-female` / `clean-female` / `calm-male` / `deep-male` / `documentary-male` / `energetic-male` / `storyteller-male`; também há suporte para um reference_id de voz hexadecimal de 32 bits. Outros textos livres não são IDs de voz válidos |

A seguir, demonstraremos com um exemplo específico. Suponha que desejamos gerar um vídeo curto educativo em chinês, no formato vertical, com 20 segundos. O código CURL correspondente é o seguinte:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
  "langs": ["zh-cn"],
  "aspect": "9:16",
  "duration": 20
}'
```

O código Python correspondente é o seguinte:

```python
import requests

url = "https://api.acedata.cloud/maestro/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": ["zh-cn"],
    "aspect": "9:16",
    "duration": 20
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Clique em Executar e você verá que um resultado será retornado imediatamente, conforme mostrado abaixo:

```json
{
  "success": true,
  "task_id": "f57e99c4f60f4373a15517742ce2357d",
  "trace_id": "70e1cb12-c619-4292-a416-90191205996b"
}
```

Os campos do resultado retornado são descritos a seguir:

- `success`: indica se esta tarefa foi enviada com sucesso.
- `task_id`: o ID desta tarefa de geração de vídeo. Use-o posteriormente para consultar os resultados pela [API de consulta de tarefas do Maestro](/pt/guides/maestro/maestro_tasks).
- `trace_id`: o ID de rastreamento desta solicitação. Em caso de problemas, forneça-o ao suporte técnico para investigação.

Devido ao longo tempo de produção do vídeo, a API **retorna `task_id` imediatamente** e não aguarda a conclusão da renderização do vídeo. Em seguida, use `task_id` para consultar o resultado, conforme detalhado na seção «Obter resultado».

## Especificar tipo e estilo de vídeo (scenario / style)

Quando `scenario` não é enviado, ele é determinado automaticamente pela IA (equivalente a `auto`); se quiser fixar o vídeo em determinado tipo, envie-o explicitamente. Por exemplo, para criar um **drama curto vertical**, é possível especificar o seguinte:

- `scenario`: tipo de vídeo, definido aqui como `drama` (drama curto com personagens + diálogos).
- `style`: estilo visual, definido aqui como `cinematic` (qualidade cinematográfica).

O código CURL de exemplo de preenchimento é o seguinte:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "两个合租室友因为一只猫闹翻又和好，三幕反转，结尾温暖",
  "scenario": "drama",
  "style": "cinematic",
  "aspect": "9:16",
  "duration": 40
}'
```

Formas comuns de combinação:

- Vídeo curto narrado: `scenario: "narrated"`.
- Legendas automáticas: `scenario: "captions"`, é necessário usar `file_urls` para enviar o vídeo de origem.
- Avatar digital / fala para a câmera: `scenario: "avatar"`, é necessário usar `file_urls` para enviar uma imagem de retrato.
- Drama curto: `scenario: "drama"` (personagens + diálogos).
- `style` é uma predefinição de estilo visual (como `modern` / `neon` / `luxury`), não altera o tipo, apenas afeta a aparência.
- `voice` é usado para especificar o timbre da narração (como `warm-female` / `deep-male`), não está relacionado ao idioma e é aplicável entre idiomas.

O resultado retornado é igual ao de "Uso básico", retornando também o `task_id` imediatamente.

## Idioma do vídeo final

Uma tarefa entrega apenas um vídeo final em um único idioma. `langs` só pode conter um código de idioma, como `["zh-cn"]` ou `["en"]`; o envio de vários idiomas retornará 400. Se precisar de vídeos em idiomas diferentes, crie tarefas separadamente. A seleção de idioma não altera o preço por segundo.

## Iterar sobre um vídeo existente (remix / edit / extend)

Envie `action` e o `ref_task_id` da tarefa anterior para fazer modificações incrementais com base no projeto original (como "alterar o título da cena 2", "trocar a narração", "escurecer o conjunto"). Pequenas alterações são rápidas; grandes alterações refarão o vídeo:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "remix",
  "ref_task_id": "f57e99c4f60f4373a15517742ce2357d",
  "prompt": "把开场标题换成更有冲击力的一句，整体配色更暗一些"
}'
```

- `remix`: reinterpretar com base na estrutura do vídeo original (mantém o tema, ajusta a apresentação).
- `edit`: realizar refinamentos em partes específicas (como trocar o título, trocar a narração, fazer correção de cor).
- `extend`: estender o conteúdo com base no vídeo original.

O resultado retornado também retorna imediatamente um novo `task_id`; use-o para consultar e obter o vídeo final após a iteração.

## Obter resultados

Como a produção de vídeos leva bastante tempo, esta interface retorna imediatamente o `task_id` após o envio, e você precisa usá-lo para consultar os resultados na [API de consulta de tarefas do Maestro](/pt/guides/maestro/maestro_tasks):

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d"
}'
```

Quando a tarefa for concluída, uma informação de vídeo final será retornada (localizada no array `variants`). O `status` passará por `pending → planning → producing → succeeded` (ou `failed`), e a **consulta é gratuita e não consome créditos**. Para o formato completo da resposta e a consulta de listas históricas, consulte as [instruções de integração da API de consulta de tarefas do Maestro](/pt/guides/maestro/maestro_tasks).

## Cobrança

**Após o sucesso da tarefa, a cobrança é feita com base na duração real do vídeo final entregue; falhas não são cobradas.** A duração faturável é calculada em segundos inteiros e não excede a duração solicitada; quando não for possível ler a duração do vídeo final, será usada como alternativa a duração solicitada. O envio da tarefa em si não é cobrado separadamente, e a consulta de `/maestro/tasks` é gratuita.

```
Créditos = segundos faturáveis reais × 0.7
```

Todos os cenários, ações e idiomas usam o mesmo preço, sem multiplicadores por cenário ou cobranças adicionais por idioma. Cada tarefa entrega apenas um vídeo final em um único idioma. A duração-alvo solicitada suporta 5–300 segundos, com saída uniforme em 1080p / 30fps.

| Duração faturável real              | Créditos |
| ------------------- | --: |
| 30 segundos         |  21 |
| 60 segundos         |  42 |
| 120 segundos        |  84 |
| 300 segundos        | 210 |
| Consulta de `/maestro/tasks` | Gratuita |

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `400 invalid_request`: Solicitação inválida, possivelmente devido à ausência de `prompt` ou a parâmetros inválidos.
- `401 invalid_token`: Não autorizado, token de autorização inválido ou ausente.
- `403 forbidden`: Proibido, saldo ou acesso insuficiente.
- `429 too_many_requests`: Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`: Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
