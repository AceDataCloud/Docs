A principal funcionalidade da API de consulta de tarefas Maestro é consultar o status de execução e o resultado final da tarefa por meio do ID da tarefa retornado pela [API de geração de vídeo Maestro](development_maestro_videos.md) (`POST /maestro/videos`).

Este documento apresentará detalhadamente a documentação de integração da API de consulta de tarefas Maestro. Como a geração de vídeo é uma tarefa assíncrona, após o envio é necessário usar esta API para realizar polling e obter o progresso e o vídeo final, **o polling é gratuito e não consome créditos.**

`POST https://api.acedata.cloud/maestro/tasks`

## Processo de solicitação

Para usar a API de consulta de tarefas Maestro, primeiro obtenha seu API Token no [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) e guarde-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não fez login ou não se registrou, será redirecionado automaticamente para a página de login, que convidará você a se registrar e fazer login; após concluir, você retornará automaticamente à página atual.

**Um único API Token pode chamar todos os serviços da plataforma, sem necessidade de solicitar separadamente para cada serviço.** A primeira solicitação concederá uma cota gratuita, permitindo uma experiência gratuita; quando a cota for insuficiente, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [API de consulta de tarefas Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Consultar uma única tarefa

Para saber como criar uma tarefa de vídeo, consulte a documentação [API de geração de vídeo Maestro](development_maestro_videos.md). Usamos como exemplo um ID de tarefa retornado por ela: `f57e99c4f60f4373a15517742ce2357d`, para demonstrar como consultar seu status e resultado.

### Configurar os cabeçalhos e o corpo da solicitação

**Request Headers** incluem:

- `accept`: especifica que o resultado da resposta deve ser recebido no formato JSON; aqui deve ser preenchido como `application/json`.
- `authorization`: a chave para chamar a API; após a solicitação, ela pode ser selecionada diretamente no menu suspenso.
- `content-type`: o formato do corpo da solicitação; aqui deve ser preenchido como `application/json`.

**Request Body** inclui:

| Campo       | Tipo     | Obrigatório ao consultar uma única tarefa | Descrição                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | obrigatório ao consultar uma única tarefa | `task_id` retornado por `POST /maestro/videos`              |
| `action` | string | não         | `retrieve` (padrão, consulta uma única tarefa); ao consultar a lista de histórico, é fixo como `retrieve_batch` |

### Exemplo de código

O código CURL correspondente é o seguinte:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

O código Python correspondente é o seguinte:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Exemplo de resposta

Após a solicitação ser bem-sucedida, a API retornará o status e o resultado dessa tarefa de vídeo. O exemplo de retorno quando a tarefa é concluída é o seguinte (cada idioma corresponde a um `variant`):

```json
    "message": "rendering scene 2"
  },

    "langs": [
      "zh-cn",
      "en"
    ],

        }

          "https://…/zh.mp4",

        ]

      "stage": "producing",
      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }
  }

```

A introdução dos campos do resultado retornado é a seguinte:

- `id`: o ID desta tarefa de vídeo, usado para identificar exclusivamente esta tarefa de geração de vídeo.
- `status`: status da tarefa, com valores `pending → planning → producing → succeeded` (ou `failed`). Para determinar se a tarefa foi concluída, prevalece este `status` de nível superior.
- `elapsed`: tempo decorrido da tarefa (segundos).
- `progress`: objeto de progresso de nível superior; `percent` (0–100) será garantido como 100 após a tarefa ser bem-sucedida; `stage` e `message` refletem o evento de progresso mais recente do diretor de IA (portanto, após o sucesso, `stage` ainda pode ser a última etapa de execução, como `producing`), podendo ser usados diretamente para exibir a barra de progresso.
- `request`: o corpo da solicitação ao iniciar a tarefa.
- `response`: as informações de retorno da tarefa.
  - `success`: se a tarefa foi bem-sucedida.
  - `data.variants`: cada idioma corresponde a um objeto de vídeo final, incluindo `lang`, `aspect`, `title`, `output_url` (endereço de download do vídeo final) etc.
  - `data.project`: o resultado de todo o projeto, incluindo `tarball_url` (pacote do projeto) e `outputs` (todos os links dos vídeos finais).
  - `data.progress`: um array de eventos de progresso adicionados por etapa (log somente de anexação), que pode ser usado para exibir o progresso detalhado em tempo real.
- `created_at`: horário de criação da tarefa, timestamp Unix (segundos).
- `started_at`: horário de início da execução da tarefa, timestamp Unix (segundos). É null quando a tarefa ainda não foi iniciada.
- `finished_at`: horário de conclusão da tarefa, timestamp Unix (segundos). É null quando a tarefa ainda não foi concluída.

## Consultar lista de histórico

Basta enviar `action: retrieve_batch` para obter as tarefas recentes do executor atualmente conectado (em ordem decrescente de hora de criação), o que pode ser usado na página de lista «Meus vídeos». A lista de histórico é isolada por identidade de login.

**Request Body** inclui:
| Campo               | Tipo     | Obrigatório  | Descrição                              |
| ---------------- | ------ | --- | ------------------------------- |
| `action`         | string | Sim   | Fixo como `retrieve_batch`            |
| `limit`          | int    | Não   | Número de itens retornados, padrão 20; o intervalo válido é 1–100          |
| `created_at_max` | int    | Não   | Retorna apenas tarefas estritamente anteriores a este timestamp Unix (não inclui o valor de limite, usado para paginação) |
| `created_at_min` | int    | Não   | Retorna apenas tarefas estritamente posteriores a este timestamp Unix (não inclui o valor de limite)     |

### Exemplo de código

O código CURL correspondente é o seguinte:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### Exemplo de resposta

Após a solicitação ser bem-sucedida, a API retornará a lista de tarefas históricas do usuário atual:

```json
        "percent": 100,

      },
      "request": {
```

A introdução aos campos do resultado retornado é a seguinte:

- `count`：O número total de tarefas visíveis para o executor atualmente conectado, não afetado pelas condições de tempo ou por `limit`.
- `items`：Um array de tarefas filtradas pelas condições de tempo e por `limit`, ordenado em ordem decrescente de tempo de criação; o formato de cada elemento é consistente com o resultado retornado de «consultar uma única tarefa».

## Recomendações de polling

Como a produção de vídeo leva mais tempo, o `status` passará por `pending → planning → producing → succeeded` (ou `failed`). Recomenda-se realizar polling uma vez a cada 5–10 segundos, até que `status` se torne `succeeded` ou `failed`. Você pode usar o `progress.percent` de nível superior para exibir uma barra de progresso em tempo real. **O polling desta interface é gratuito e não consome créditos.**

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `401 invalid_token`：Não autorizado, token de autorização inválido ou ausente.
- `404 not_found`：Tarefa não encontrada, o task_id fornecido não existe.
- `429 too_many_requests`：Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`：Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
