A principal função da API de Consulta de Tarefas do Maestro é consultar o status de execução e o resultado final de uma tarefa, utilizando o ID da tarefa retornado pela [API de Geração de Vídeos do Maestro](development_maestro_videos.md) (`POST /maestro/videos`).

Este documento irá detalhar as instruções de integração da API de Consulta de Tarefas do Maestro. Como a geração de vídeos é uma tarefa assíncrona, após o envio, é necessário usar esta interface para consultar o progresso e o vídeo final, **a consulta é gratuita e não consome créditos.**

`POST https://api.acedata.cloud/maestro/tasks`

## Processo de Solicitação

Para usar a API de Consulta de Tarefas do Maestro, primeiro acesse o [Painel de Controle da Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu Token de API, que deve ser guardado para uso futuro.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver logado ou registrado, será redirecionado automaticamente para a página de login, onde será convidado a se registrar e logar; após a conclusão, você será redirecionado de volta para a página atual.

**Um Token de API é suficiente para acessar todos os serviços da plataforma, não sendo necessário solicitar um para cada serviço individualmente.** A primeira solicitação oferece um crédito gratuito, permitindo uma experiência sem custo; quando o crédito estiver baixo, você pode recarregar o saldo geral no [painel de controle](https://platform.acedata.cloud/console/coin).

> 📘 Documentação Completa: [API de Consulta de Tarefas do Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Consultar uma Tarefa Única

Para saber como criar uma tarefa de vídeo, consulte a documentação [API de Geração de Vídeos do Maestro](development_maestro_videos.md). Usaremos um ID de tarefa retornado como exemplo: `f57e99c4f60f4373a15517742ce2357d`, para demonstrar como consultar seu status e resultado.

### Configurar Cabeçalhos e Corpo da Solicitação

**Cabeçalhos da Solicitação** incluem:

- `accept`: especifica que a resposta deve ser no formato JSON, preenchido como `application/json`.
- `authorization`: chave para chamar a API, que pode ser selecionada diretamente após a solicitação.
- `content-type`: formato do corpo da solicitação, preenchido como `application/json`.

**Corpo da Solicitação** inclui:

| Campo     | Tipo    | Obrigatório | Descrição                                           |
|-----------|---------|-------------|----------------------------------------------------|
| `id`      | string  | Sim         | `task_id` retornado pelo `POST /maestro/videos`   |
| `action`  | string  | Não         | `retrieve` (padrão, consulta uma única tarefa) / `retrieve_batch` (consulta lista de tarefas históricas) |

### Exemplo de Código

O código CURL correspondente é o seguinte:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

O código Python correspondente é o seguinte:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Exemplo de Resposta

Após uma solicitação bem-sucedida, a API retornará o status e o resultado da tarefa de vídeo. Um exemplo de retorno quando a tarefa é concluída é o seguinte (cada idioma corresponde a um `variant`):

```json

  "status": "succeeded",

    "percent": 100,

    "message": "rendering scene 2"
  },

    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": [
      "zh-cn",
      "en"
    ],
    "aspect": "9:16",
    "duration": 20

        },
        {
          "lang": "en",
          "aspect": "9:16",
          "kind": "video",
          "title": "What is a vector database",
          "output_url": "https://platform2.cdn.acedata.cloud/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee.mp4?example=video-002"
        }
      ],
      "project": {
        "tarball_url": null,
        "outputs": [
          "https://…/zh.mp4",
          "https://…/en.mp4"
        ]
      },
      "percent": 100,
      "stage": "producing",
      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }
  }
}
```

A descrição dos campos do resultado retornado é a seguinte:

- `id`: ID desta tarefa de vídeo, usado para identificar exclusivamente esta tarefa de geração de vídeo.
- `status`: status da tarefa, com valores `pending → planning → producing → succeeded` (ou `failed`). O status de conclusão da tarefa é determinado pelo `status` de nível superior.
- `elapsed`: tempo já gasto na tarefa (em segundos).
- `progress`: objeto de progresso de nível superior, `percent` (0–100) será garantido como 100 após a conclusão da tarefa; `stage` e `message` refletem o evento de progresso mais recente do AI diretor (portanto, após o sucesso, `stage` pode ainda ser a última fase executada, como `producing`), podendo ser usado diretamente para exibir uma barra de progresso.
- `request`: corpo da solicitação ao iniciar a tarefa.
- `response`: informações retornadas da tarefa.
  - `success`: indica se a tarefa foi bem-sucedida.
  - `data.variants`: cada idioma corresponde a um objeto de vídeo final, contendo `lang`, `aspect`, `title`, `output_url` (endereço de download do vídeo final), etc.
  - `data.project`: produto total do projeto, contendo `tarball_url` (pacote do projeto) e `outputs` (todos os links dos vídeos finais).
  - `data.progress`: array de eventos de progresso acumulados por fase (log apenas de adição), podendo ser usado para exibir o progresso detalhado em tempo real.
- `created_at`: hora de criação da tarefa, timestamp Unix (em segundos).
- `started_at`: hora de início da execução da tarefa, timestamp Unix (em segundos). Será null se a tarefa ainda não tiver começado.
- `finished_at`: hora de conclusão da tarefa, timestamp Unix (em segundos). Será null se a tarefa não estiver concluída.

## Consultar Lista Histórica

Ao passar `action: retrieve_batch`, você pode obter as tarefas mais recentes do usuário atual (em ordem decrescente de criação), que podem ser usadas na página de lista "Meus Vídeos".

**Corpo da Solicitação** inclui:
| Campo             | Tipo    | Obrigatório | Descrição                     |
| ----------------- | ------- | ----------- | ----------------------------- |
| `action`          | string  | Sim         | Fixo como `retrieve_batch`    |
| `limit`           | int     | Não         | Número de retornos, padrão 20 |
| `created_at_max`  | int     | Não         | Retorna apenas tarefas antes deste timestamp Unix (para paginação) |
| `created_at_min`  | int     | Não         | Retorna apenas tarefas após este timestamp Unix      |

### Exemplo de Código

O código CURL correspondente é o seguinte:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

## Sugestão de Polling

Como a produção de vídeo leva tempo, o `status` passará por `pending → planning → producing → succeeded` (ou `failed`). Recomenda-se fazer polling a cada 5–10 segundos, até que o `status` mude para `succeeded` ou `failed`. Pode-se usar o `progress.percent` de nível superior para exibir uma barra de progresso em tempo real. **O polling desta interface é gratuito e não consome pontos.**

## Tratamento de Erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `401 invalid_token`: Não autorizado, token de autorização inválido ou ausente.
- `404 not_found`: Tarefa não encontrada, o `task_id` fornecido não existe.
- `429 too_many_requests`: Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`: Erro interno do servidor, algo deu errado no servidor.

### Exemplo de Resposta de Erro

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
