Este artigo apresentará uma instrução de integração da API Flux Images Generation, que pode gerar imagens oficiais do Flux por meio da inserção de parâmetros personalizados.

## Processo de solicitação

Para usar a API Flux Images Generation, primeiro acesse o [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e mantê-lo como reserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não tiver feito login ou se registrado, será automaticamente redirecionado para a página de login, onde será convidado a se registrar e fazer login; após a conclusão, você retornará automaticamente à página atual.

**Um único API Token pode chamar todos os serviços da plataforma, sem necessidade de solicitar um separadamente para cada serviço.** Na primeira solicitação, serão concedidos créditos gratuitos, permitindo uma experiência gratuita; quando os créditos forem insuficientes, é possível recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Uso básico

Primeiro, vamos entender o método básico de uso: basta inserir o termo de prompt `prompt`, a ação de geração `action` e o tamanho da imagem `size` para obter o resultado processado. Primeiro, é necessário simplesmente transmitir um campo `action`, cujo valor é `generate`, e então também precisamos inserir o termo de prompt. O conteúdo específico é o seguinte:

<p><img src="https://cdn.acedata.cloud/wz85jt.png" width="500" className="m-auto" /></p>

É possível ver que aqui configuramos os Request Headers, incluindo:

- `accept`: qual formato de resultado de resposta deseja receber; aqui, preencha como `application/json`, ou seja, formato JSON.
- `authorization`: a chave para chamar a API; após a solicitação, é possível selecioná-la diretamente na lista suspensa.

Além disso, configuramos o Request Body, incluindo:

- `action`: o comportamento desta tarefa de geração de imagem.
- `size`: o tamanho do resultado da geração de imagem. **As séries `flux-2-flex` / `flux-2-pro` / `flux-2-max` devem receber a proporção da imagem (como `1:1`, `16:9`), não aceitam tamanhos em pixels como `1024x1024`, e a ausência retornará 400.**
- `count`: a quantidade de imagens geradas; o valor padrão é 1. Este parâmetro só é válido para tarefas de geração de imagem e é inválido para tarefas de edição.
- `prompt`: termo de prompt.
- `model`: modelo de geração, o padrão é `flux-dev`; os mais recentes modelos principais são `flux-2-pro`, `flux-2-max` (maior qualidade de imagem, requerem a proporção da imagem `size`).
- `callback_url`: a URL que precisa receber o resultado de callback.
- `async`: opcional; quando definido como `true`, a interface retorna imediatamente o `task_id`, sem a necessidade de fornecer `callback_url`; em seguida, obtenha o resultado por polling por meio da interface de consulta de tarefa correspondente.

O parâmetro `size` tem algumas restrições especiais, divididas principalmente em dois tipos: proporção de largura e altura `width x height` e proporção da imagem `x:y`, especificamente como segue:

| Modelo               | Intervalo                                         |
| ---------------- | ------------------------------------------ |
| flux-dev         | Suporta proporções de largura e altura 1024x1024, 1024x1792, 1792x1024, ou proporção de imagem |
| flux-pro         | Suporta proporções de largura e altura 1024x1024, 1024x1792, 1792x1024, ou proporção de imagem |
| flux-2-flex      | Suporta apenas proporção de imagem                                    |
| flux-2-pro       | Suporta apenas proporção de imagem                                    |
| flux-2-max       | Suporta apenas proporção de imagem                                    |
| flux-kontext-pro | Suporta apenas proporção de imagem                                    |
| flux-kontext-max | Suporta apenas proporção de imagem                                    |

Proporções de imagem de referência: "21:9", "16:9", "4:3", "3:2", "1:1", "2:3", "3:4", "9:16", "9:21".

Após selecionar os parâmetros, o código correspondente será gerado automaticamente no lado direito. Antes de copiar, confirme que o cabeçalho de autorização usa sua própria API Key e que documentos e capturas de tela não devem conter credenciais reais.

Clique no botão «Try» para realizar o teste; aqui obtivemos o seguinte resultado:

```json
{
  "success": true,
  "task_id": "5456c749-3bbb-4f10-9eb8-cfbcac297500",
  "trace_id": "ae4eecb8-1dd6-45b4-bfb3-a1c48872536e",
  "data": [
    {
      "image_url": "https://cdn.acedata.cloud/assets/examples/flux/5456c749-3bbb-4f10-9eb8-cfbcac297500-d0ef60485f73.jpg"
    }
  ]
}
```

O resultado retornado possui vários campos, apresentados a seguir:

- `success`, o status da tarefa de geração de vídeo neste momento.
- `task_id`, o ID da tarefa de geração de vídeo neste momento.
- `trace_id`, o ID de rastreamento da geração de vídeo neste momento.
- `data`, a lista de resultados da tarefa de geração de imagem neste momento.
  - `image_url`, o link da tarefa de geração de imagem neste momento.
  - `prompt`, termo de prompt.

É possível ver que obtivemos informações satisfatórias da imagem; basta obter a imagem Flux gerada com base no endereço do link da imagem em `data` no resultado.

Além disso, se desejar gerar o código de integração correspondente, é possível copiá-lo diretamente; por exemplo, o código CURL é o seguinte:

```shell
curl -X POST 'https://api.acedata.cloud/flux/images' \
-H 'authorization: Bearer {token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "A photorealistic studio product shot of a frosted-glass perfume bottle on wet black slate, single softbox key light, water droplets, dark moody background, 85mm macro.",
  "model": "flux-2-pro",
  "size": "1:1"
}'
```

## Tarefa de edição de imagem

Se desejar editar uma determinada imagem, primeiro o parâmetro `image_url` deve receber o link da imagem que precisa ser editada. Neste momento, `action` suporta apenas `edit`, e é possível especificar o seguinte conteúdo:

- model: o modelo adotado nesta tarefa de edição de imagem; são suportados `flux-dev`, `flux-pro`, `flux-kontext-pro`, `flux-kontext-max`, `flux-2-flex`, `flux-2-pro`, `flux-2-max`.
- image_url: envie a imagem que precisa ser editada.

O exemplo de preenchimento é o seguinte:

<p><img src="https://cdn.acedata.cloud/jn9da5.png" width="500" className="m-auto" /></p>

Após o preenchimento, o código a seguir é gerado automaticamente:

<p><img src="https://cdn.acedata.cloud/6cwxb8.png" width="500" className="m-auto" /></p>

O código correspondente:

```python
import requests

url = "https://api.acedata.cloud/flux/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "edit",
    "prompt": "a white siamese cat",
    "model": "flux-kontext-pro",
    "image_url": "https://cdn.acedata.cloud/ytj2qy.png"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Clique para executar; é possível perceber que um resultado será obtido imediatamente, como segue:

```json
{
  "success": true,
  "task_id": "2a7979ff-1f77-4380-92c6-a2dc37c3b4c8",
  "trace_id": "732b65c0-48d9-49f7-b568-64e5acffe4c0",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "timings": 1752744073
    }
  ]
}
```
Pode-se observar que o efeito gerado é o de editar a imagem original, e o resultado é semelhante ao descrito acima.

## Retorno de chamada assíncrono

Como o tempo de geração da Flux Images Generation API é relativamente longo, levando cerca de 1-2 minutos, se a API não responder por um longo período, a solicitação HTTP permanecerá conectada, resultando em consumo adicional de recursos do sistema. Portanto, esta API também oferece suporte a retornos de chamada assíncronos.

O processo geral é: quando o cliente inicia uma solicitação, ele especifica adicionalmente um campo `callback_url`. Depois que o cliente inicia a solicitação da API, a API retorna imediatamente um resultado, incluindo as informações de um campo `task_id`, que representa o ID da tarefa atual. Quando a tarefa for concluída, o resultado da imagem gerada será enviado, na forma de POST JSON, para o `callback_url` especificado pelo cliente, que também inclui o campo `task_id`, permitindo assim que os resultados da tarefa sejam associados pelo ID.

A seguir, vamos entender como operar especificamente por meio de um exemplo.

Primeiro, o retorno de chamada Webhook é um serviço que pode receber solicitações HTTP, e o desenvolvedor deve substituí-lo pela URL do servidor HTTP que ele próprio configurou. Para facilitar a demonstração, é utilizado aqui um site público de exemplo de Webhook https://webhook.site/. Ao abrir esse site, é possível obter uma URL de Webhook, conforme mostrado na imagem:

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `400 token_mismatched`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`：Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`：Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`：Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
