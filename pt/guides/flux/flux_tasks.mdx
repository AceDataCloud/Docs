A principal funcionalidade da API Flux Tasks é consultar o status de execução de uma tarefa por meio do ID da tarefa da plataforma retornado pela API Flux Images Generation ou API Flux Videos.

Este documento apresentará detalhadamente as instruções de integração da API Flux Tasks, ajudando você a integrar facilmente e aproveitar plenamente os poderosos recursos desta API. Por meio da API Flux Tasks, você pode facilmente consultar o status de execução das tarefas da API Flux Images Generation.

Para um exemplo completo de envio e polling de vídeos, consulte o [Guia de integração da API Flux Videos](https://platform.acedata.cloud/documents/flux-videos-integration). A consulta de tarefas existentes não gera custos adicionais de geração.

## Processo de solicitação

Para usar a API Flux Images Generation, primeiro obtenha seu API Token no [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) e guarde-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver conectado ou registrado, será automaticamente redirecionado para a página de login, onde será convidado a se registrar e fazer login; após a conclusão, você retornará automaticamente para a página atual.

**Um único API Token pode chamar todos os serviços da plataforma, sem necessidade de solicitar separadamente para cada serviço.** A primeira solicitação oferece créditos gratuitos, permitindo uma experiência gratuita; quando os créditos forem insuficientes, você poderá recarregar o saldo universal no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [API Flux Images Generation →](https://platform.acedata.cloud/documents/flux-images)

## Exemplo de solicitação

A API Flux Tasks pode ser usada para consultar os resultados da API Flux Images Generation. Para saber como usar a API Flux Images Generation, consulte a documentação [API Flux Images Generation](https://platform.acedata.cloud/documents/flux-images-integration).

Usaremos como exemplo um ID de tarefa retornado pelo serviço API Flux Images Generation, demonstrando como usar esta API. Suponha que temos um ID de tarefa: 2db0168c-2373-4367-8d9a-9dc778802e8a, a seguir demonstraremos como por meio da passagem de um ID de tarefa.

### Configurar cabeçalhos e corpo da solicitação

**Request Headers** incluem:

- `accept`: especifica que os resultados de resposta recebidos estão no formato JSON, aqui preencha com `application/json`.
- `authorization`: a chave para chamar a API, após a solicitação você pode selecioná-la diretamente no menu suspenso.

**Request Body** inclui:

- `id`: o ID da tarefa enviada.
- `action`: o modo de operação da tarefa.

Configure conforme mostrado na imagem abaixo:

<p><img src="https://cdn.acedata.cloud/fiasxz.png" width="500" className="m-auto" /></p>

### Exemplo de código

É possível observar que vários códigos em diferentes linguagens já foram gerados automaticamente no lado direito da página, conforme mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/j6gn86.png" width="500" className="m-auto" /></p>

Alguns exemplos de código são os seguintes:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/flux/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/flux/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

O resultado retornado possui vários campos. O campo `request` é o request body ao iniciar a tarefa, enquanto o campo `response` é o response body retornado após a conclusão da tarefa. A descrição dos campos é a seguinte.

- `id`, o ID que gera esta tarefa de imagem, usado para identificar exclusivamente esta tarefa de geração de imagem.
- `request`, as informações da solicitação na consulta da tarefa de imagem.
- `response`, as informações de retorno na consulta da tarefa de imagem.
- `created_at`, hora de criação da tarefa, timestamp Unix (segundos, ponto flutuante).
- `started_at`, hora de início da execução da tarefa, timestamp Unix (segundos, ponto flutuante).
- `finished_at`, hora de conclusão da tarefa, timestamp Unix (segundos, ponto flutuante). Este campo não é retornado quando a tarefa não foi concluída.
- `elapsed`, tempo de execução da tarefa, em segundos (ponto flutuante, com 3 casas decimais). Este campo não é retornado quando a tarefa não foi concluída.

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e as informações de erro correspondentes. Por exemplo:

- `400 token_mismatched`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`：Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`：Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`：Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

