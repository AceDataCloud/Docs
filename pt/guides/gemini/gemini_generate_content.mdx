O Google Gemini é um sistema de conversa por IA muito poderoso, capaz de gerar respostas fluentes e naturais em segundos por meio da entrada de prompts. Este documento descreve principalmente como usar a API Gemini Generate Content, que é o formato de API nativo oficial do Google e oferece suporte aos dois endpoints `generateContent` e `streamGenerateContent`.

## Diferenças em relação à API Chat Completions

A API Gemini Generate Content usa o formato de solicitação nativo oficial do Google (campo `contents`), em vez do formato compatível com OpenAI (campo `messages`). Se você já usa o SDK do Google Gemini ou está familiarizado com o formato oficial da API, pode usar diretamente esta API sem modificar o formato da solicitação.

## Escopo de suporte atual

A interface aceita entradas de texto, imagens, vídeos e áudio (`inlineData` ou `fileData`), configurações de pensamento e declarações de funções personalizadas. Saída de áudio, ferramentas integradas e campos nativos como cache explícito de contexto ainda não têm garantia de disponibilidade unificada; consulte o retorno real de cada modelo específico.

Ao enviar arquivos como áudio usando `fileData.fileUri`, certifique-se de que o arquivo possa ser acessado diretamente via HTTPS, sem depender de estado de login, e faça com que o período de validade do link assinado cubra todo o tempo de processamento da solicitação. A análise de áudio não streaming só retorna resultados após o modelo concluir o processamento, podendo exceder 90 segundos; o cliente deve definir um tempo limite total suficientemente longo de acordo com o tamanho do arquivo e o cenário de negócio, evitando desconectar enquanto o servidor ainda está processando.

## Processo de solicitação

Antes de usar a API Gemini Generate Content, acesse a página [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) e clique no botão "Obter" para conseguir as credenciais necessárias para a solicitação.

Se ainda não tiver feito login ou se registrado, você será redirecionado automaticamente para a página de login. A primeira solicitação terá uma cota gratuita.

## Uso básico

### Non-Streaming (não streaming)

Envie uma solicitação POST para `/v1beta/models/{model}:generateContent`:

> **Dica**: a série `gemini-3.x` flash consiste em modelos de pensamento, que primeiro consomem reasoning tokens; defina `generationConfig.maxOutputTokens` como 512 ou mais, caso contrário poderá retornar apenas conteúdo vazio.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Exemplo de resultado retornado:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [
          {
            "text": "你好！很高兴与你交流。"
          }
        ]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Os campos de token em `usageMetadata` são cobrados de acordo com a semântica nativa do Gemini:

- `promptTokenCount` inclui `cachedContentTokenCount`; a parte atingida pelo cache é calculada de acordo com o preço de leitura do cache e não será contabilizada novamente como entrada comum.
- `promptTokensDetails` e `cacheTokensDetails` serão normalizados como `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` e os respectivos detalhes `cached_*` em `usage.prompt_tokens_details`. Esses valores estão incluídos respectivamente em `prompt_tokens` e `cached_tokens`; diferentes modalidades são recalculadas apenas de acordo com seus respectivos preços e não serão cobradas duplicadamente.
- `candidatesTokenCount` e `thoughtsTokenCount` são ambos calculados de acordo com o preço de tokens de saída.
- `toolUsePromptTokenCount` é um token de entrada de ferramenta independente, calculado de acordo com o preço de tokens de entrada.

A Ace Data Cloud retorna adicionalmente um objeto `usage` normalizado, lendo de forma unificada entre protocolos de modelos o custo desta chamada a partir de `usage.cost`. `cost` é uma prévia opcional de custo; quando a prévia de preços estiver temporariamente indisponível, a resposta do modelo ainda será retornada normalmente, mas poderá não incluir esse campo. A fatura final prevalece de acordo com os registros de uso.

### Streaming (streaming)

Envie uma solicitação POST para `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

O retorno em streaming retornará gradualmente o conteúdo no formato SSE (Server-Sent Events). Os eventos intermediários normalmente contêm apenas conteúdo incremental; o evento final com uso autoritativo incluirá `usageMetadata` e `usage` normalizado, e o custo continuará localizado em `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

O encerramento da conexão indica o fim do fluxo; o fluxo nativo do Gemini não enviará `data: [DONE]`. Se a prévia de preço final estiver temporariamente indisponível, `usage` ainda retornará o uso de tokens, mas omitirá `cost`.

### Pensamento interno e resumo de pensamento

O pensamento interno do modelo e o retorno de resumos de pensamento ao chamador são duas configurações independentes:

- `thinkingBudget` ou `thinkingLevel` controla o orçamento ou a profundidade do pensamento interno do modelo; os campos e valores compatíveis dependem do modelo.
- `includeThoughts` controla se os resumos de pensamento são retornados; o padrão é `false`. Quando este campo é omitido ou `false` é passado, nem as respostas JSON normais nem as respostas de streaming SSE retornam texto marcado como `thought: true`; esses textos são mantidos apenas quando o valor booleano `true` é explicitamente passado.

Quando a solicitação não define `includeThoughts`, a interface passa `false` por padrão aos modelos de geração que suportam configuração de pensamento, evitando resumos não necessários pela solicitação; os valores, orçamento de pensamento e nível explicitamente passados pelo cliente são preservados. O conhecido `gemini-2.5-flash-image`, que não suporta configuração de pensamento, não receberá este campo automaticamente, e solicitações `countTokens` também não receberão configuração de geração.

Desativar resumos não equivale a desativar o pensamento interno, nem garante a redução dos tokens de pensamento interno. Se a resposta ainda contiver texto de pensamento não solicitado, as saídas JSON normais e SSE o filtrarão adicionalmente, preservando a resposta normal, as assinaturas e o uso real.

Quando precisar visualizar resumos, ative-os explicitamente da seguinte maneira. Quando o modelo não gerar um resumo utilizável, talvez não haja texto de pensamento mesmo que esteja ativado:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` é o estado criptografado necessário para turnos subsequentes, não é texto de resumo de pensamento e tampouco é controlado pela opção `includeThoughts`. A assinatura pode estar em uma resposta normal, chamada de função ou Part de texto vazio; ao filtrar texto de pensamento, a assinatura e outros campos do mesmo Part são preservados; portanto, ainda podem existir na resposta Parts que carregam apenas uma assinatura e têm texto vazio. Ao manter manualmente o histórico de múltiplos turnos, a ordem desses Parts e a posição das assinaturas devem ser preservadas; não mova as assinaturas nem as mescle.

`usageMetadata` e `usage` continuam registrando o uso real. Ocultar resumos não zera `thoughtsTokenCount`; a cobrança continua sendo calculada conforme o uso real e as regras de preço atuais.

Consulte a [explicação oficial do Google sobre pensamento e resumos de pensamento](https://firebase.google.com/docs/ai-logic/thinking) e as [regras de assinaturas de pensamento](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

### Chamada de função

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "北京现在的天气怎么样？"}]
    }
  ],
  "tools": [
    {
      "functionDeclarations": [
        {
          "name": "get_weather",
          "description": "获取指定城市的天气信息",
          "parameters": {
            "type": "object",
            "properties": {
              "city": {
                "type": "string",
                "description": "城市名称"
              }
            },
            "required": ["city"]
          }
        }
      ]
    }
  ]
}
```


## Configurações de segurança

O filtro de conteúdo pode ser controlado por meio de `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Tratamento de erros

| Código de status HTTP | Significado             |
| -------- | -------------- |
| 400      | Parâmetros de solicitação inválidos         |
| 401      | Falha de autenticação, verifique o Token |
| 403      | Conteúdo interceptado pelo filtro de segurança     |
| 429      | Solicitações muito frequentes         |
| 500      | Erro interno do servidor        |
