Google Gemini é um sistema de diálogo de IA muito poderoso, capaz de gerar respostas fluentes e naturais em segundos por meio de prompts de entrada. Este documento descreve principalmente como usar a API Gemini Generate Content, que é o formato de API nativo oficial do Google e oferece suporte aos dois endpoints `generateContent` e `streamGenerateContent`.

## Diferenças em relação à API Chat Completions

A API Gemini Generate Content usa o formato de solicitação nativo oficial do Google (campo `contents`), em vez do formato compatível com OpenAI (campo `messages`). Se você já usa o SDK Google Gemini ou está familiarizado com o formato oficial da API, pode usar esta API diretamente sem modificar o formato da solicitação.

## Escopo de suporte atual

A interface aceita entradas de texto, imagem, vídeo e áudio (`inlineData` ou `fileData`), configuração de raciocínio e declarações de funções personalizadas. Saída de áudio, ferramentas integradas e campos nativos como cache explícito de contexto ainda não têm garantia de disponibilidade unificada; consulte o retorno real de modelos específicos.

Ao enviar arquivos como áudio usando `fileData.fileUri`, certifique-se de que o arquivo possa ser acessado diretamente por HTTPS, sem depender de estado de login, e que o período de validade do link assinado cubra todo o tempo de processamento da solicitação. A análise de áudio não fluida só retorna resultados após o modelo concluir o processamento, podendo exceder 90 segundos; o cliente deve definir um tempo limite total suficientemente longo de acordo com o tamanho do arquivo e o cenário de negócio, para evitar desconectar enquanto o servidor ainda está processando.

## Processo de solicitação

Antes de usar a API Gemini Generate Content, acesse a página [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) e clique no botão "Obter" para receber as credenciais necessárias para a solicitação.

Se ainda não tiver feito login ou se registrado, você será redirecionado automaticamente para a página de login. A primeira solicitação terá cota gratuita.

## Uso básico

### Non-Streaming (não fluido)

Envie uma solicitação POST para `/v1beta/models/{model}:generateContent`:

> **Dica**: os flash da série `gemini-3.x` são modelos de raciocínio e primeiro consomem reasoning tokens; defina `generationConfig.maxOutputTokens` como 512 ou mais, caso contrário poderá retornar apenas conteúdo vazio.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Exemplo de resultado retornado:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [
          {
            "text": "你好！很高兴与你交流。"
          }
        ]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Os campos de token em `usageMetadata` são cobrados de acordo com a semântica nativa do Gemini:

- `promptTokenCount` inclui `cachedContentTokenCount`; a parte atingida pelo cache é calculada pelo preço de leitura de cache e não é contabilizada novamente como entrada comum.
- `promptTokensDetails` e `cacheTokensDetails` serão normalizados como `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` e os respectivos detalhes `cached_*` em `usage.prompt_tokens_details`. Esses valores estão incluídos respectivamente em `prompt_tokens` e `cached_tokens`; modalidades diferentes são recalculadas apenas pelos seus respectivos preços e não são cobradas duas vezes.
- Tanto `candidatesTokenCount` quanto `thoughtsTokenCount` são calculados pelo preço de tokens de saída.
- `toolUsePromptTokenCount` são tokens independentes de entrada de ferramenta, calculados pelo preço de tokens de entrada.

Ace Data Cloud retorna adicionalmente o objeto `usage` normalizado, e o custo desta chamada é lido de forma unificada entre protocolos de modelos por meio de `usage.cost`. `cost` é uma prévia opcional de custo; quando a prévia de preço estiver temporariamente indisponível, a resposta do modelo ainda será retornada normalmente, mas poderá não incluir esse campo. A fatura final prevalece de acordo com os registros de uso.

### Streaming (fluido)

Envie uma solicitação POST para `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

O retorno fluido devolverá gradualmente o conteúdo no formato SSE (Server-Sent Events). Os eventos intermediários normalmente contêm apenas conteúdo incremental; o evento final com uso autorizado incluirá `usageMetadata` e `usage` normalizado, e o custo ainda estará em `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

O fechamento da conexão indica o fim do fluxo; o fluxo nativo do Gemini não envia `data: [DONE]`. Se a prévia de preço final estiver temporariamente indisponível, `usage` ainda retornará o uso de tokens, mas omitirá `cost`.

As especificações oficiais dos modelos listam entradas de texto, imagem, vídeo, áudio e PDF, e saída de texto; isso não significa que a plataforma atual tenha verificado todos os tipos de entrada. Após a recuperação da chamada nativa, envie solicitações conforme o contrato da interface desta página e verifique separadamente as entradas e os parâmetros necessários. A saída de um milhão de Tokens do long decode oficial não está incluída no contrato atual da interface. Ambos oferecem suporte apenas a cache implícito, e os Tokens de pensamento são cobrados pelo preço de saída; as regras de preço preparadas usam o mesmo preço unitário de Token de entrada para cada modalidade de entrada, e os acertos de cache são calculados pelo preço unitário de leitura de cache. Consulte a página de preços atual para detalhes.

### Pensamento interno e resumo de pensamento

O pensamento interno do modelo e o retorno de um resumo de pensamento ao chamador são duas configurações independentes:

- `thinkingBudget` ou `thinkingLevel` controla o orçamento ou a profundidade do pensamento interno do modelo; os campos e valores compatíveis dependem do modelo.
- `includeThoughts` controla se deve retornar o resumo de pensamento; o padrão é `false`. Quando esse campo é omitido ou `false` é passado, nem as respostas JSON normais nem as respostas em streaming SSE retornarão texto marcado como `thought: true`; esses textos são mantidos somente quando o valor booleano `true` é passado explicitamente.

Quando a solicitação não define `includeThoughts`, a interface passa `false` por padrão aos modelos de geração que oferecem suporte à configuração de pensamento, evitando solicitar resumos desnecessários; os valores explicitamente passados pelo cliente, o orçamento de pensamento e o nível são preservados. O conhecido `gemini-2.5-flash-image`, que não oferece suporte à configuração de pensamento, não terá esse campo adicionado automaticamente, e as solicitações `countTokens` também não terão uma configuração de geração adicionada.

Desativar o resumo não equivale a desativar o pensamento interno, nem garante a redução dos tokens de pensamento interno. Se a resposta ainda contiver texto de pensamento não solicitado, as saídas JSON normais e SSE o filtrarão adicionalmente, preservando a resposta normal, as assinaturas e o uso real.

Quando precisar ver o resumo, ative-o explicitamente da seguinte forma. Quando o modelo não gerar um resumo utilizável, poderá não haver texto de pensamento mesmo que esteja ativado:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` é um estado criptografado necessário para turnos subsequentes, não é texto de resumo de pensamento e não é controlado pela opção `includeThoughts`. A assinatura pode estar em uma resposta normal, chamada de função ou Part de texto vazio; ao filtrar texto de pensamento, a assinatura e os outros campos do mesmo Part são preservados, portanto ainda pode haver na resposta Parts que carregam apenas uma assinatura e têm texto vazio. Ao manter manualmente o histórico de vários turnos, deve-se preservar a ordem desses Parts e a posição das assinaturas, sem mover as assinaturas nem mesclá-los.

`usageMetadata` e `usage` continuam registrando o uso real. Ocultar o resumo não zera `thoughtsTokenCount`; a cobrança continua sendo calculada de acordo com o uso real e as regras de preço atuais.

Consulte a [explicação oficial do Google sobre pensamento e resumos de pensamento](https://firebase.google.com/docs/ai-logic/thinking) e as [regras de assinaturas de pensamento](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

### Chamada de função

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "北京现在的天气怎么样？"}]
    }
  ],
  "tools": [
    {
      "functionDeclarations": [
        {
          "name": "get_weather",
          "description": "获取指定城市的天气信息",
          "parameters": {
            "type": "object",
            "properties": {
              "city": {
                "type": "string",
                "description": "城市名称"
              }
            },
            "required": ["city"]
          }
        }
      ]
    }
  ]
}
```

### Conversa de vários turnos

```json
  "contents": [
    {

    },
    {
      "role": "model",

    },
    {
      "role": "user",
      "parts": [{"text": "我叫什么名字？"}]
    }
  ]
}
```

## Configurações de segurança

O filtro de conteúdo pode ser controlado por meio de `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Tratamento de erros

| Código de status HTTP | Significado                         |
| -------- | ----------------------------------- |
| 400      | Parâmetros de solicitação inválidos |
| 401      | Falha na autenticação, verifique o Token |
| 403      | Conteúdo bloqueado pelo filtro de segurança |
| 429      | Solicitações muito frequentes       |
| 500      | Erro interno do servidor            |
