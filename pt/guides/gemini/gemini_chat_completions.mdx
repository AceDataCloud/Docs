O Google Gemini é um sistema de diálogo de IA muito poderoso; basta inserir um prompt para que ele gere respostas fluentes e naturais em poucos segundos. O Gemini pode fornecer uma assistência inteligente surpreendente, melhorando enormemente a eficiência de trabalho e a criatividade dos humanos.

Este documento apresenta principalmente o processo de uso das operações da API Gemini Chat Completion; com ela, podemos usar facilmente os recursos de diálogo oficiais do Gemini.

## Processo de solicitação

Para usar a API Gemini Chat Completion, primeiro acesse o [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e guarde-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver conectado ou registrado, será automaticamente redirecionado para a página de login, onde será convidado a se registrar e entrar; após concluir, você retornará automaticamente à página atual.

**Um único API Token pode chamar todos os serviços da plataforma, não sendo necessário solicitar separadamente para cada serviço.** Na primeira solicitação, créditos gratuitos serão oferecidos para uma experiência sem custo; quando os créditos forem insuficientes, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## Uso básico

Em seguida, você pode preencher o conteúdo correspondente na interface, como mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

Ao usar esta interface pela primeira vez, precisamos preencher pelo menos três campos: um é `authorization`, que pode ser selecionado diretamente na lista suspensa. Outro parâmetro é `model`; `model` é a categoria de modelo do site oficial do Gemini que escolhemos usar, e os modelos disponíveis devem seguir a enumeração `model` na documentação da interface. O último parâmetro é `messages`; `messages` é o array de perguntas que inserimos. Ele é um array, indicando que várias perguntas podem ser enviadas ao mesmo tempo; cada pergunta contém `role` e `content`, onde `role` representa o papel do questionador. Fornecemos três identidades: `user`, `assistant` e `system`. O outro, `content`, é o conteúdo específico da nossa pergunta.

Ao mesmo tempo, você pode observar que há a geração do código de chamada correspondente no lado direito; você pode copiar o código e executá-lo diretamente, ou clicar diretamente no botão «Try» para testar.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

> **Dica**: a série flash `gemini-3.x` é um modelo de raciocínio e primeiro consome reasoning tokens; defina `max_tokens` para mais de 512, caso contrário poderá retornar apenas conteúdo vazio. `gemini-3.8-flash` é o modelo Flash atualmente recomendado, suportando até 1 milhão de Tokens de contexto, entrada de imagem, chamadas de ferramentas e respostas em streaming; atualmente é chamado por meio da interface Chat Completions.

`gemini-4-argon` também pode ser usado para Chat Completions, suportando respostas de texto normais e em streaming. Ele pode usar parte do orçamento de saída para raciocínio; para tarefas complexas, deixe espaço suficiente para `max_tokens`; o Google recomenda pelo menos 32768 para tarefas regulares deste modelo. Não equipare esta interface à funcionalidade de saída longa em segundo plano da Google Interactions API.

## Compreensão de imagens (entrada multimodal)

O Gemini é um modelo multimodal nativo e pode diretamente «ver imagens». Para enviar uma imagem, altere o `content` de uma mensagem de uma string para um **array de blocos de conteúdo**; basta colocar simultaneamente blocos `text` e `image_url` no array — isso é totalmente consistente com o OpenAI e com o formato compatível com OpenAI do Gemini oficial.

`image_url.url` oferece suporte a duas formas de escrita:
- **URI `data:` em base64 (recomendado, mais estável)**: o formato é `data:<tipo de mídia>;base64,<dados>`, por exemplo `data:image/jpeg;base64,/9j/4AAQ...`. **O tipo de mídia (MIME) já está escrito no prefixo `data:`**, portanto não é necessário, nem existe um campo `media_type` separado.
- **URL de imagem publicamente acessível**: por exemplo, `https://cdn.acedata.cloud/4hfydw.jpg`.

Tipos de imagem compatíveis: `png`, `jpeg`, `webp`, `heic`, `heif`.

Código de chamada de exemplo em Python (URI data em base64):

```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# 把本地图片读成 base64 data URI
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Também é possível transmitir diretamente uma URL de imagem publicamente acessível:

```python
payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",

            ]
        }
    ]

```

> 💡 `image_url` aceita apenas o campo `url` (o valor pode ser uma URL de imagem ou uma URI `data:` em base64), além do campo opcional `detail`. **Não transmita `media_type`** — esse é um campo de imagem do Anthropic Claude, não pertence ao formato `image_url` do OpenAI / Gemini.

## Resposta em streaming

Esta interface também oferece suporte a respostas em streaming, o que é muito útil para integração com páginas web, permitindo que a página implemente um efeito de exibição caractere por caractere.

Se desejar retornar respostas em streaming, você pode alterar o parâmetro `stream ` no cabeçalho da solicitação para `true`.

A modificação é mostrada na imagem, mas o código de chamada precisa ter as alterações correspondentes para oferecer suporte a respostas em streaming.

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

Depois de modificar `stream` para `true`, a API retornará os dados JSON correspondentes linha por linha; no nível do código, precisamos fazer as modificações correspondentes para obter os resultados linha por linha.

Código de chamada de exemplo em Python:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

JavaScript também é compatível; por exemplo, o código de chamada em fluxo do Node.js é o seguinte:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Código de chamada de exemplo em Python:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"

payload = {

response = requests.post(url, json=payload, headers=headers)

```

## Modelo multimodal Gemini-3.1

`gemini-3.1-pro-preview` é o ID oficial atual do modelo Gemini 3.1 Pro, que oferece suporte a entradas multimodais, como texto, imagens e vídeos, sendo adequado para tarefas complexas de raciocínio, codificação e compreensão.

Exemplo de solicitação:

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "图片的内容是什么？"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/qzx2z1.png"
          }
        }
      ]
    }
  ],
  "stream": false
}
```

O Gemini 3.1 Pro também oferece suporte à compreensão de vídeos:

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
```

O formato de retorno é consistente com o Gemini 3.0 Pro; consulte as instruções na seção do modelo multimodal Gemini-3.0 acima para mais detalhes.

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `400 token_mismatched`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`：Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`：Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`：Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro
```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
