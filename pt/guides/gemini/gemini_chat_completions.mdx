Google Gemini é um sistema de diálogo de IA muito poderoso, que, ao inserir uma palavra-chave, pode gerar respostas fluentes e naturais em poucos segundos. O Gemini oferece uma assistência inteligente impressionante, aumentando significativamente a eficiência e a criatividade humanas.

Este documento apresenta principalmente o processo de uso da API Gemini Chat Completion, que nos permite usar facilmente a funcionalidade de diálogo oficial do Gemini.

## Processo de Solicitação

Para usar a API Gemini Chat Completion, primeiro acesse o [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu Token de API, para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver logado ou registrado, será redirecionado automaticamente para a página de login, onde poderá se registrar e fazer login; após isso, retornará automaticamente para esta página.

**Um único Token de API pode chamar todos os serviços da plataforma, não é necessário solicitar separadamente para cada serviço.** A primeira solicitação oferece uma cota gratuita para experiência; quando a cota acabar, você pode recarregar saldo geral no [Console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## Uso Básico

Em seguida, você pode preencher os conteúdos correspondentes na interface, conforme mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

Ao usar esta interface pela primeira vez, precisamos preencher pelo menos três conteúdos: um é o `authorization`, que pode ser selecionado diretamente na lista suspensa. Outro parâmetro é o `model`, que é a categoria do modelo oficial do Gemini que escolhemos usar; aqui temos principalmente 6 tipos de modelos, detalhes podem ser vistos nos modelos que fornecemos. O último parâmetro é `messages`, que é o array de perguntas que inserimos; é um array que permite enviar várias perguntas simultaneamente, cada pergunta contém `role` e `content`, onde `role` indica o papel do questionador, e oferecemos três identidades: `user`, `assistant` e `system`. O outro `content` é o conteúdo específico da pergunta.

Você também pode notar que há um código correspondente gerado à direita, que pode ser copiado para execução direta ou você pode clicar no botão "Try" para testar.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

> **Dica**: A série `gemini-3.x` flash é um modelo de raciocínio, que consome tokens de raciocínio primeiro; defina `max_tokens` para 512 ou mais, caso contrário pode retornar conteúdo vazio. `gemini-3.6-flash` é o modelo Flash recomendado atualmente, suporta até 1 milhão de tokens de contexto, entrada de imagem, chamadas de ferramentas e resposta em streaming; atualmente chamado via interface Chat Completions.

## Compreensão de Imagem (Entrada Multimodal)

Gemini é um modelo multimodal nativo, que pode "ver imagens" diretamente. Para enviar uma imagem, altere o `content` de uma mensagem de string para um **array de blocos de conteúdo**, contendo simultaneamente blocos `text` e `image_url` — isso é totalmente compatível com o formato OpenAI e o formato oficial Gemini compatível com OpenAI.

`image_url.url` suporta duas formas de escrita:

- **URI base64 `data:` (recomendado, mais estável)**: formato `data:<tipo de mídia>;base64,<dados>`, por exemplo `data:image/jpeg;base64,/9j/4AAQ...`. **O tipo de mídia (MIME) já está no prefixo `data:`**, portanto não é necessário nem existe um campo separado `media_type`.
- **URL pública acessível da imagem**: por exemplo `https://cdn.acedata.cloud/4hfydw.jpg`.

Tipos de imagem suportados: `png`, `jpeg`, `webp`, `heic`, `heif`.

Exemplo de código Python para chamada (URI base64 data):
```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# Lê a imagem local como um URI de dados base64
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "Por favor, descreva esta imagem em uma frase."},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Também é possível enviar diretamente uma URL de imagem acessível publicamente:

```python
payload = {
    "model": "gemini-3.1-pro",
    "messages": [
        {
            "role": "user",

                {"type": "image_url", "image_url": {"url": "https://cdn.acedata.cloud/4hfydw.jpg"}}
            ]
        }
    ]
}
```

> 💡 `image_url` aceita apenas o campo `url` (o valor pode ser uma URL de imagem ou um URI de dados base64), além do campo opcional `detail`. **Não envie `media_type`** — isso é um campo de imagem do Anthropic Claude, que não pertence ao formato `image_url` do OpenAI / Gemini.

## Resposta em fluxo

Esta interface também suporta resposta em fluxo, o que é muito útil para integração com páginas da web, permitindo que a página exiba o conteúdo palavra por palavra.

Se você deseja retornar a resposta em fluxo, pode alterar o parâmetro `stream` no cabeçalho da solicitação para `true`.

A modificação é conforme mostrado na imagem, mas o código de chamada precisa ter as alterações correspondentes para suportar a resposta em fluxo.

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

Após alterar `stream` para `true`, a API retornará os dados JSON linha por linha, e no nível do código, precisamos fazer as modificações necessárias para obter os resultados linha por linha.

Exemplo de código de chamada em Python:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Olá, qual modelo você é?"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

JavaScript também é suportado, como no código de chamada em fluxo do Node.js abaixo:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Olá, qual modelo você é?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Se você deseja integrar a funcionalidade de diálogo em múltiplas rodadas, é necessário enviar múltiplas perguntas no campo `messages`, exemplos específicos de múltiplas perguntas são mostrados na imagem abaixo:

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
```

## Gemini-3.1 Modelo Multimodal

Gemini 3.1 Pro é a versão atualizada do Gemini 3.0 Pro, com o modelo subjacente sendo `gemini-3.1-pro-preview`, também suportando entradas multimodais como texto, imagem e vídeo, com capacidades de raciocínio e compreensão mais fortes. O uso é idêntico ao do Gemini 3.0 Pro, basta substituir o parâmetro `model` por `gemini-3.1-pro`.

Exemplo de solicitação:

```json
{
  "model": "gemini-3.1-pro",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "Qual é o conteúdo da imagem?"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/qzx2z1.png"
          }
        }
      ]
    }
  ],
  "stream": false
}
```

Gemini 3.1 Pro também suporta compreensão de vídeo:

```json
{
  "model": "gemini-3.1-pro",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "Qual é o conteúdo do vídeo?"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/58yioe.mp4"
          }
        }
      ]
    }
  ],
  "stream": false
}
```

O formato de retorno é o mesmo do Gemini 3.0 Pro, conforme descrito na seção acima sobre o modelo multimodal Gemini-3.0.

## Tratamento de Erros

Ao chamar a API, se ocorrer um erro, a API retornará o código de erro e a mensagem correspondente. Por exemplo:
- `400 token_mismatched`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`：Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`：Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`：Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "falha na busca"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
