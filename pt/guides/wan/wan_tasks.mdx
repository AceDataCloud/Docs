A principal função da API Wan Tasks é consultar o status de execução de uma tarefa através do ID da tarefa gerado pela API Wan Videos Generation.

Este documento irá detalhar as instruções de integração da API Wan Tasks, ajudando você a integrar facilmente e aproveitar ao máximo as poderosas funcionalidades dessa API. Com a API Wan Tasks, você pode consultar facilmente o status de execução das tarefas da API Wan Videos Generation.

## Processo de Solicitação

Para usar a API Wan Tasks, você precisa primeiro ir à página de solicitação [Wan Videos Generation API](https://platform.acedata.cloud/documents/52b0f490-1bbf-4fe5-b60e-96626d333d2c) para solicitar o serviço correspondente, e então copiar o ID da tarefa da API Wan Videos Generation, como mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Por fim, acesse a página da API Tasks [Wan Tasks API](https://platform.acedata.cloud/documents/240ef446-cbec-461c-a633-4a64178d7018) para solicitar o serviço correspondente. Após acessar a página, clique no botão "Acquire", como mostrado na imagem:

![Página de Solicitação](https://cdn.acedata.cloud/rci31i.png)

Se você ainda não estiver logado ou registrado, será redirecionado automaticamente para a [página de login](https://platform.acedata.cloud) que o convidará a se registrar e fazer login. Após o registro e login, você será redirecionado automaticamente de volta para a página atual.

Na primeira solicitação, haverá um crédito gratuito disponível, permitindo que você use essa API gratuitamente.

## Exemplo de Solicitação

A API Wan Tasks pode ser usada para consultar os resultados da API Wan Videos Generation. Para saber como usar a API Wan Videos Generation, consulte o documento [Wan Videos Generation API](https://platform.acedata.cloud/documents/52b0f490-1bbf-4fe5-b60e-96626d333d2c).

Usaremos um exemplo de ID de tarefa retornado pelo serviço da API Wan Videos Generation. Suponha que temos um ID de tarefa: a4bca552-d964-46a1-8ff7-fd922f916582, a seguir, demonstraremos como passar um ID de tarefa.

### Configurando Cabeçalhos e Corpo da Solicitação

**Request Headers** incluem:

- `accept`: especifica que a resposta deve ser no formato JSON, preenchido como `application/json`.
- `authorization`: a chave para chamar a API, que pode ser selecionada diretamente após a solicitação.

**Request Body** inclui:

- `id`: o ID da tarefa enviada.
- `action`: a forma de operação na tarefa.

Configuração conforme mostrado na imagem abaixo:

<p><img src="https://cdn.acedata.cloud/vr3hxw.png" width="500" className="m-auto" /></p>

### Exemplo de Código

Pode-se notar que, no lado direito da página, já foram gerados automaticamente códigos em várias linguagens, como mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/ehmsdi.png" width="500" className="m-auto" /></p>

Alguns exemplos de código são os seguintes:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/wan/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "a4bca552-d964-46a1-8ff7-fd922f916582",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/wan/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "a4bca552-d964-46a1-8ff7-fd922f916582",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Erro de tratamento

Ao chamar a API, se encontrar um erro, a API retornará o respectivo código de erro e informações. Por exemplo:

- `400 token_mismatched`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`：Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`：Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`：Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```json

  "error": {

    "message": "falha ao buscar"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
