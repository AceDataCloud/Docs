A principal função da API Wan Tasks é consultar o status de execução de uma tarefa através do ID da tarefa gerado pela API Wan Videos Generation.

Este documento irá detalhar as instruções de integração da API Wan Tasks, ajudando você a integrar facilmente e aproveitar ao máximo as poderosas funcionalidades dessa API. Com a API Wan Tasks, você pode consultar facilmente o status de execução das tarefas da API Wan Videos Generation.

## Processo de Solicitação

Para usar a API Wan Videos Generation, primeiro acesse o [Painel de Controle da Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu Token de API, que deve ser guardado para uso futuro.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver logado ou registrado, será redirecionado automaticamente para a página de login, onde será convidado a se registrar e logar. Após a conclusão, você será redirecionado de volta para a página atual.

**Um Token de API é suficiente para acessar todos os serviços da plataforma, não sendo necessário solicitar um para cada serviço.** A primeira solicitação oferece um crédito gratuito para que você possa experimentar; quando o crédito acabar, você pode recarregar o saldo geral no [painel de controle](https://platform.acedata.cloud/console/coin).

> 📘 Documentação Completa: [API Wan Videos Generation →](https://platform.acedata.cloud/documents/wan-videos)

## Exemplo de Solicitação

A API Wan Tasks pode ser usada para consultar os resultados da API Wan Videos Generation. Para saber como usar a API Wan Videos Generation, consulte a documentação [API Wan Videos Generation](https://platform.acedata.cloud/documents/wan-videos).

Usaremos um exemplo de ID de tarefa retornado pelo serviço da API Wan Videos Generation. Suponha que temos um ID de tarefa: a4bca552-d964-46a1-8ff7-fd922f916582, a seguir, demonstraremos como passar esse ID de tarefa.

### Configurando Cabeçalhos e Corpo da Solicitação

**Request Headers** incluem:

- `accept`: especifica que a resposta deve ser no formato JSON, preenchido como `application/json`.
- `authorization`: a chave para chamar a API, que pode ser selecionada diretamente após a solicitação.

**Request Body** inclui:

- `id`: o ID da tarefa enviada.
- `action`: a forma de operação na tarefa.

Configuração conforme mostrado na imagem abaixo:

### Exemplo de Código

Pode-se notar que, no lado direito da página, já foram gerados automaticamente códigos em várias linguagens, conforme mostrado na imagem:

Alguns exemplos de código são os seguintes:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/wan/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "a4bca552-d964-46a1-8ff7-fd922f916582",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/wan/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "a4bca552-d964-46a1-8ff7-fd922f916582",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```


O resultado retornado contém vários campos, o campo request é o corpo da solicitação ao iniciar a tarefa, enquanto o campo response é o corpo da resposta retornada após a conclusão da tarefa. A descrição dos campos é a seguinte:

- `id`, o ID que gerou esta tarefa de vídeo, usado para identificar exclusivamente esta tarefa de geração de vídeo.
- `request`, informações da solicitação na tarefa de vídeo.
- `response`, informações de retorno na tarefa de vídeo.
- `created_at`, data e hora de criação da tarefa, timestamp Unix (segundos, ponto flutuante).
- `started_at`, data e hora de início da execução da tarefa, timestamp Unix (segundos, ponto flutuante).
- `finished_at`, data e hora de conclusão da tarefa, timestamp Unix (segundos, ponto flutuante). Este campo não é retornado se a tarefa não estiver concluída.
- `elapsed`, tempo gasto na execução da tarefa, em segundos (ponto flutuante, com 3 casas decimais). Este campo não é retornado se a tarefa não estiver concluída.

## Tratamento de Erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `400 token_mismatched`: Requisição inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`: Requisição inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`: Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`: Muitas requisições, você excedeu o limite de taxa.
- `500 api_error`: Erro interno do servidor, algo deu errado no servidor.
