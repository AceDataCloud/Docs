Este documento apresenta a forma de integração com a API HappyHorse Videos. Esta interface suporta a geração de vídeos a partir de texto, vídeos a partir da primeira imagem, vídeos a partir de imagens de referência e edição de vídeos através do ponto de entrada unificado `/happyhorse/videos` e do parâmetro `action`.

## Processo de Solicitação

Para usar a API HappyHorse Videos, primeiro acesse o [Painel de Controle da Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu Token de API, que deve ser guardado para uso futuro.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Se você ainda não estiver logado ou registrado, será redirecionado automaticamente para a página de login, onde será convidado a se registrar e logar; após a conclusão, você será redirecionado de volta para a página atual.

**Um Token de API é suficiente para acessar todos os serviços da plataforma, não sendo necessário solicitar um para cada serviço individualmente.** A primeira solicitação oferece um crédito gratuito para que você possa experimentar; quando o crédito estiver baixo, você pode recarregar o saldo geral no [painel de controle](https://platform.acedata.cloud/console/coin).

> 📘 Documentação Completa: [HappyHorse Videos API →](https://platform.acedata.cloud/documents/happyhorse-videos)

## Tipos de Operação

O `action` determina o modo de geração desta solicitação:

- `generate`: vídeo a partir de texto, ação padrão, suporta `happyhorse-1.0-t2v` e `happyhorse-1.1-t2v`, deve incluir `prompt`.
- `image_to_video`: vídeo a partir da primeira imagem, suporta `happyhorse-1.0-i2v` e `happyhorse-1.1-i2v`, deve incluir `image_url`.
- `reference_to_video`: vídeo a partir de imagem de referência, suporta `happyhorse-1.0-r2v` e `happyhorse-1.1-r2v`, deve incluir `prompt` e de 1 a 9 `image_urls`.
- `video_edit`: edição de vídeo, suporta `happyhorse-1.0-video-edit`, deve incluir `prompt` e `video_url`, podendo incluir de 0 a 5 imagens de referência `image_urls`.

As ações usam por padrão o modelo 1.1; `video_edit` atualmente só possui `happyhorse-1.0-video-edit`.

## Uso Básico

Para gerar um vídeo a partir de texto, basta fornecer o `prompt`, podendo também especificar parâmetros como `resolution`, `ratio`, `duration`, entre outros:

```json
{
  "action": "generate",
  "model": "happyhorse-1.1-t2v",
  "prompt": "Um cavalo branco cinematográfico levanta a cabeça, a crina se move suavemente ao vento do amanhecer, câmera se aproximando lentamente, iluminação de filme quente",
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}
```

Um exemplo de resultado retornado é o seguinte:

```json
{
  "success": true,
  "task_id": "27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1",
  "trace_id": "6071ab5e-2f37-46f0-9e07-f1e378112e69",
  "data": [
    {
      "id": "9650580f-6d9e-4bc1-823a-29011790c5cb",
      "video_url": "https://platform2.cdn.acedata.cloud/happyhorse/27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1.mp4",
      "state": "succeeded",
      "duration": 5,
      "resolution": "720P",
      "ratio": null
    }
  ]
}
```

Descrição dos campos:

- `success`: indica se a solicitação foi bem-sucedida.
- `task_id`: ID da tarefa do lado da Ace Data Cloud, pode ser usado para consultar o status da tarefa.
- `trace_id`: ID de rastreamento da solicitação, usado para solucionar problemas.
- `data`: lista de resultados de vídeo.
  - `id`: ID da tarefa HappyHorse upstream.
  - `video_url`: endereço do link CDN do vídeo gerado.
  - `state`: estado da tarefa, podendo ser `pending` / `succeeded` / `error`.
  - `duration`: duração do vídeo cobrada, em segundos; `video_edit` é a soma da duração do vídeo de entrada e saída.
  - `resolution`: resolução de saída.
  - `ratio`: proporção de saída.

O código CURL correspondente é o seguinte:

```shell
curl -X POST 'https://api.acedata.cloud/happyhorse/videos' \
-H 'authorization: Bearer ${bearer_token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "happyhorse-1.1-t2v",
  "prompt": "Um cavalo branco cinematográfico levanta a cabeça, a crina se move suavemente ao vento do amanhecer, câmera se aproximando lentamente, iluminação de filme quente",
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}'
```

O código Python correspondente é o seguinte:

```python
import requests

url = "https://api.acedata.cloud/happyhorse/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "action": "generate",
    "model": "happyhorse-1.1-t2v",
    "prompt": "Um cavalo branco cinematográfico levanta a cabeça, a crina se move suavemente ao vento do amanhecer, câmera se aproximando lentamente, iluminação de filme quente",
    "resolution": "720P",
    "ratio": "16:9",
    "duration": 5,
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Vídeo a partir da Primeira Imagem

Ao usar `image_to_video`, `image_url` será a primeira imagem do vídeo. A proporção de saída tentará seguir a imagem da primeira imagem, portanto, esta ação não requer a passagem de `ratio`.

```json
{
  "action": "image_to_video",
  "model": "happyhorse-1.1-i2v",
  "image_url": "https://cdn.acedata.cloud/b1c82e4937.png",
  "prompt": "Um cavalo branco cinematográfico levanta a cabeça, a crina se move suavemente ao vento do amanhecer, câmera se aproximando lentamente, iluminação de filme quente",
  "resolution": "1080P",
  "duration": 5
}
```

## Vídeo a partir de Imagem de Referência

Ao usar `reference_to_video`, `image_urls` pode incluir de 1 a 9 imagens de referência. As palavras-chave podem referenciar as imagens na ordem correspondente usando `character1`, `character2`, etc.

```json
{
  "action": "reference_to_video",
  "model": "happyhorse-1.1-r2v",
  "prompt": "character1 caminha para frente através de um prado ao amanhecer com o estilo de couro quente e detalhes em ouro de character2",
  "image_urls": [
    "https://cdn.acedata.cloud/b1c82e4937.png",
    "https://cdn.acedata.cloud/eb75d88a3f.png"
  ],
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}
```

## Edição de Vídeo

Ao usar `video_edit`, é necessário fornecer o vídeo a ser editado `video_url` e a intenção de edição `prompt`. As `image_urls` opcionais servirão como imagens de referência, por exemplo, para troca de roupas, transferência de estilo ou substituição parcial. O `audio_setting` pode ser `auto` ou `origin`, onde `origin` indica que o áudio original do vídeo deve ser mantido.

```json
{
  "action": "video_edit",
  "model": "happyhorse-1.0-video-edit",
  "prompt": "Aplique o estilo de couro quente e detalhes em ouro da imagem de referência enquanto preserva o movimento da câmera original",
  "video_url": "https://platform2.cdn.acedata.cloud/happyhorse/27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1.mp4",
  "image_urls": [
    "https://cdn.acedata.cloud/eb75d88a3f.png"
  ],
  "resolution": "720P",
  "audio_setting": "auto"
}
```

## Callback Assíncrono
A geração de vídeo requer um certo tempo de processamento. Se não desejar manter uma conexão longa aguardando, pode passar `callback_url`, nesse caso a API retornará imediatamente `task_id`, e após a conclusão da tarefa, enviará o resultado final para esse endereço:

```json
{
  "action": "generate",
  "prompt": "Um cavalo correndo por uma floresta nevada",
  "duration": 5,
  "callback_url": "https://seu-dominio.com/callback/cavaloalegre"
}
```

O resultado retornado imediatamente é o seguinte:

```json
{
  "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea"
}
```

Se você deseja apenas fazer polling, sem precisar de callback, também pode passar `"async": true`, e então consultar o resultado da tarefa através da [API de Tarefas HappyHorse](https://platform.acedata.cloud/documents/happyhorse-tasks).

## Instruções de cobrança

HappyHorse cobra com base na duração do vídeo de saída e na resolução:

- `720P`: a partir de aproximadamente $0.105 / segundo.
- `1080P`: a partir de aproximadamente $0.18 / segundo.
- `video_edit`: cobrado com base na soma da duração do vídeo de entrada e do vídeo de saída, a duração real cobrada será conforme a estatística upstream após a conclusão da tarefa.

Tarefas falhadas não são cobradas e não ocupam a cota gratuita.

## Tratamento de erros

Quando há um problema com a solicitação, a API retornará o código de erro correspondente e a descrição, os mais comuns são:

- `400`: parâmetros da solicitação estão incorretos, por exemplo, action e model não correspondem, falta `prompt` / `image_url` / `video_url`, ou `duration` excede o intervalo de 3–15 segundos.
- `401`: falha na autenticação, token inválido ou não correspondente à API.
- `403`: saldo insuficiente, ou a palavra-chave atingiu a revisão de conteúdo e foi rejeitada.
- `429`: solicitações muito frequentes, acionando a limitação upstream, por favor, tente novamente mais tarde.
- `500`: erro interno do servidor ou falha na geração upstream.
