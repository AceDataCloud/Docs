Anthropic Claude é um sistema de diálogo de IA muito poderoso; basta inserir um prompt para que ele gere respostas fluentes e naturais em poucos segundos. Claude se destaca no setor por sua excelente capacidade de compreensão e geração de linguagem. Atualmente, Claude já é amplamente utilizado em diversos setores e áreas, e sua influência é cada vez mais significativa. Seja em conversas cotidianas, escrita criativa ou consultoria profissional e programação de código, Claude pode fornecer uma assistência inteligente surpreendente, melhorando enormemente a eficiência de trabalho e a criatividade humana.

Este documento apresenta principalmente o processo de uso das operações da API Claude Chat Completion; com ela, podemos usar facilmente a funcionalidade de diálogo do Claude oficial.

## Claude Fable 5.2

Use o modelo completo `claude-fable-5-2`. Este modelo é adequado para raciocínio complexo e tarefas de longo prazo; quando forem necessários blocos de conteúdo de pensamento nativo e interação com ferramentas, priorize o uso de Messages. O pensamento adaptativo permanece continuamente ativado; omita `temperature`, `top_p`, `top_k`, use `auto` para a seleção de ferramentas e não force a especificação de ferramentas. `max_tokens` abrange simultaneamente o pensamento e o texto final. Atualmente, as interfaces Responses e Count Tokens não são fornecidas para este modelo.

Com base no plano máximo atual (142.800 Credits／$13.584), a entrada comum do Fable 5.2 custa $3,20 e a saída $16／milhão de tokens; a leitura de cache custa $0,08, e a gravação de cache de 5 minutos／1 hora custa respectivamente $4／$6,40／milhão de tokens. Os preços acima correspondem a 40% do preço unitário padrão da API oficial (60% mais barato); para outros planos e descontos adicionais da conta, consulte a página de preços do modelo e a fatura.

## Processo de solicitação

Para usar a API Claude Chat Completion, primeiro acesse o [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e guarde-o como reserva.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver conectado ou registrado, será redirecionado automaticamente para a página de login, onde será convidado a se registrar e entrar; após a conclusão, retornará automaticamente à página atual.

**Um único API Token pode chamar todos os serviços da plataforma, sem necessidade de solicitar separadamente para cada serviço.** Na primeira solicitação, será concedida uma cota gratuita para experimentar sem custos; quando a cota for insuficiente, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Uso básico

Em seguida, você pode preencher o conteúdo correspondente na interface, como mostrado na imagem:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Ao usar esta interface pela primeira vez, precisamos preencher pelo menos três itens. Um deles é `authorization`, que pode ser selecionado diretamente na lista suspensa. Outro parâmetro é `model`, com opções como `claude-opus-5-5`, `claude-fable-5-1` e outros modelos públicos; o antigo `claude-fable-5` ainda pode continuar sendo chamado. O último parâmetro é `messages`, que é um array de prompts, e cada elemento contém `role` e `content`; `role` oferece suporte a `user`, `assistant`, `system`, e `content` é o conteúdo específico. Quando forem necessários blocos completos de conteúdo de pensamento do Claude, assinaturas e semântica de ferramentas nativas, continue usando a API Messages.

Ao mesmo tempo, você pode notar que há a geração do código de chamada correspondente à direita; você pode copiar o código e executá-lo diretamente, ou clicar diretamente no botão «Try» para testar.

Parâmetros opcionais comuns:

- `max_tokens`: limita o número máximo de tokens de uma única resposta.
- `temperature`: aleatoriedade da geração, entre 0 e 2; quanto maior o valor, mais disperso.
- `n`: quantas respostas candidatas gerar de uma vez.
- `response_format`: configuração do formato de retorno.

`claude-opus-5-5` oferece suporte a Chat Completions comuns e em streaming; este modelo permite apenas `n=1`. Não defina para ele uma `temperature` inferior a 1 nem um `top_p` não padrão; para chamadas de ferramentas, use `tool_choice: "auto"` e não force a especificação de ferramentas. A interface compatível com Chat não retornará blocos de conteúdo de pensamento nativo.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Após a chamada, descobrimos que o resultado retornado é o seguinte:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }
}
```

O resultado retornado possui vários campos, apresentados a seguir:

- `id`, o ID da tarefa de diálogo gerada desta vez, usado para identificar exclusivamente esta tarefa de diálogo.
- `model `, o modelo Claude do site oficial selecionado.
- `choices`, as informações de resposta fornecidas pelo Claude para o prompt.
- `usage `: as informações estatísticas de tokens para esta pergunta e resposta.

No formato Chat Completions, `usage.prompt_tokens` é o volume total de entrada; `prompt_tokens_details.cached_tokens` e `prompt_tokens_details.cache_write_tokens` registram respectivamente os detalhes de leitura e gravação de cache. `completion_tokens_details.reasoning_tokens` é um subconjunto de `completion_tokens`; ao calcular o total ou o custo, não some novamente. Respostas sem streaming também podem retornar o objeto `usage.cost`, no qual `amount` é o consumo real de cota, `currency` é a unidade de medição e `list_amount` é o valor antes do desconto (se houver).

O nome do campo em Chat-compatible é `reasoning_tokens`; a API Messages nativa usa `output_tokens_details.thinking_tokens`. O wire schema dos dois protocolos é diferente, e o cliente não deve misturar os nomes dos campos.

Entre eles, `choices` contém as informações de resposta do Claude, e o `choices` dentro dele são as informações específicas respondidas pelo Claude, como pode ser visto na imagem.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Pode-se ver que o campo `content` dentro de `choices` contém o conteúdo específico da resposta do Claude.

## Resposta em streaming

Esta interface também oferece suporte a respostas em streaming, o que é muito útil para integração com páginas web e permite que a página web implemente um efeito de exibição caractere por caractere.

Se quiser retornar a resposta em streaming, você pode alterar o parâmetro `stream ` no cabeçalho da solicitação para `true`.

A modificação é mostrada na imagem, mas o código de chamada precisa ter as alterações correspondentes para oferecer suporte à resposta em streaming.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>
Após modificar `stream` para `true`, a API retornará os dados JSON correspondentes linha por linha. No nível do código, precisamos fazer as modificações correspondentes para obter os resultados linha por linha.

Código de chamada de exemplo em Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

JavaScript também é suportado, por exemplo, o código de chamada em streaming do Node.js é o seguinte:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "claude-opus-4-20250514",
    messages: [{ role: "user", content: "Hello" }],
    stream: true,
  }),
};

fetch("https://api.acedata.cloud/v1/chat/completions", options)
  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

```python
import requests

## Raciocínio profundo

Os modelos Claude de nova geração podem raciocinar de acordo com a estratégia padrão do modelo, sem necessidade de acionamento por meio do sufixo de modelo `-thinking`. As respostas compatíveis com Chat usam o campo usage compatível com OpenAI `completion_tokens_details.reasoning_tokens`. Os `reasoning_tokens` já estão incluídos em `completion_tokens`, não os some novamente. O raciocínio e o corpo de texto visível compartilham o limite de tokens de saída, portanto, quando `max_tokens` for pequeno, o corpo de texto poderá ficar vazio ou ser truncado; nesse caso, aumente o orçamento de saída ou, quando o modelo utilizado oferecer suporte, escolha um menor esforço de raciocínio.

Se precisar de `thinking` nativo, `output_config.effort`, blocos de conteúdo thinking e retorno de assinatura, use `/v1/messages`. O campo usage correspondente a Messages é `output_tokens_details.thinking_tokens`, não o misture com o `completion_tokens_details.reasoning_tokens` compatível com Chat.

## Modelo visual

claude-sonnet-4-20250514 é um modelo de linguagem grande multimodal desenvolvido pela Claude, que adiciona capacidades de compreensão visual com base no claude-4. Este modelo pode processar simultaneamente entradas de texto e imagem, realizando compreensão e geração multimodais.

O processamento de texto usando o modelo claude-sonnet-4-20250514 é consistente com o conteúdo de uso básico acima. A seguir, será apresentada brevemente a capacidade de processamento de imagens do modelo.

A capacidade de processamento de imagens do modelo claude-sonnet-4-20250514 é utilizada principalmente adicionando um campo `type` com base no conteúdo original de `content`. Por meio desse campo, é possível saber se o que foi enviado é texto ou imagem, permitindo assim utilizar a capacidade de processamento de imagens do modelo claude-sonnet-4-20250514. A seguir, será explicado principalmente como chamar esse recurso usando Curl e Python.

- Método de script Curl

```

-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "claude-sonnet-4-20250514",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "What'\''s in this image?"
          },
          {
            "type": "image_url",
            "image_url": {
              "url": "https://cdn.acedata.cloud/ueugot.png"
            }
          }
        ]
      }
    ]
  }'
```

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e as informações de erro correspondentes. Por exemplo:

- `400 token_mismatched`: Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`: Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`: Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`: Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`: Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```
