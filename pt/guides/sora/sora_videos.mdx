Este documento apresenta as instruções para integração da API de Geração de Vídeos Sora, que permite gerar vídeos oficiais da Sora a partir de parâmetros personalizados. Esta API suporta dois modos de versão:

- **Versão 1 (modo clássico)**: suporta parâmetros como `duration` (10/15/25 segundos), `orientation` (paisagem/retrato), `size` (small/large resolução), imagens de referência `image_urls`, link de personagem `character_url` etc.
- **Versão 2 (modo parceiro)**: suporta `seconds` (4/8/12 segundos), resolução em pixels `size` (ex: 1280x720), imagens de referência `input_reference` etc.

## Processo de Solicitação

Para usar a API, é necessário solicitar o serviço na página correspondente do [Sora Videos Generation API](https://platform.acedata.cloud/documents/99a24421-2e22-4028-8201-e19cb834b67e). Após acessar a página, clique no botão "Acquire", conforme mostrado na imagem:

![](https://cdn.acedata.cloud/q6ytrc.png)

Se ainda não estiver logado ou registrado, será redirecionado automaticamente para a página de login, onde poderá se registrar e entrar. Após o login, retornará automaticamente para a página atual.

Na primeira solicitação, será concedida uma cota gratuita para uso da API.

## Uso Básico (Versão 1)

Primeiro, entenda o uso básico da Versão 1, que consiste em enviar o prompt `prompt`, um array de URLs de imagens de referência `image_urls` e o modelo `model` para obter o resultado processado. O conteúdo detalhado é o seguinte:

<p><img src="https://cdn.acedata.cloud/h8dyz3.png" width="500" className="m-auto" /></p>

Aqui configuramos os Request Headers, incluindo:

- `accept`: formato desejado para a resposta, aqui definido como `application/json` (formato JSON).
- `authorization`: chave para chamar a API, que pode ser selecionada após a solicitação.

Também configuramos o Request Body, incluindo:

- `model`: modelo para geração do vídeo, suportando `sora-2` (modo padrão) e `sora-2-pro` (modo HD). O `sora-2-pro` suporta vídeos de 25 segundos, enquanto o `sora-2` suporta apenas 10 e 15 segundos.
- `size`: resolução do vídeo, `small` para resolução padrão e `large` para HD (apenas Versão 1).
- `duration`: duração do vídeo, suportando 10, 15 e 25 segundos (25 segundos apenas para `sora-2-pro`, apenas Versão 1).
- `orientation`: orientação do vídeo, suportando `landscape` (paisagem) e `portrait` (retrato) (apenas Versão 1).
- `image_urls`: array de URLs de imagens de referência para geração de vídeo a partir de imagens (apenas Versão 1).
- `character_url`: link do personagem, vídeos não podem conter pessoas reais (apenas Versão 1).
- `character_start`/`character_end`: segundos de início e fim da aparição do personagem, intervalo de 1 a 3 segundos (apenas Versão 1).
- `prompt`: prompt (obrigatório).
- `callback_url`: URL para callback assíncrono.
- `version`: versão da API, `1` (padrão) ou `2`.

## Tarefa de Geração de Vídeo a partir de Imagem (Versão 1)

Para gerar vídeo a partir de imagem, o parâmetro `image_urls` deve ser preenchido com URLs de imagens de referência, podendo especificar o seguinte:

- `image_urls`: array de URLs de imagens usadas como referência para a geração de vídeo. Não envie imagens reais contendo rostos humanos, pois isso pode causar falha na tarefa.

Exemplo de preenchimento:

<p><img src="https://cdn.acedata.cloud/ch7x3t.png" width="500" className="m-auto" /></p>

O código gerado automaticamente é:

<p><img src="https://cdn.acedata.cloud/z1ud8l.png" width="500" className="m-auto" /></p>

Código correspondente:

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "size": "large",
    "duration": 15,
    "orientation": "landscape",
    "prompt": "cat running on the river",
    "model": "sora-2",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

- `character_url`: link do vídeo para criação do personagem, sem pessoas reais.

## Modo Versão 2

Além do modo Versão 1, a API suporta o modo Versão 2, ativado definindo o parâmetro `version` como `2`. O modo Versão 2 suporta vídeos mais curtos e controle de resolução em nível de pixel.

### Descrição dos Parâmetros da Versão 2

| Parâmetro      | Tipo    | Obrigatório | Descrição                                   |
|----------------|---------|-------------|---------------------------------------------|
| `version`      | integer | Sim         | Definir como `2`                            |
| `prompt`       | string  | Sim         | Prompt para geração do vídeo                |
| `model`        | string  | Não         | `sora-2` (padrão) ou `sora-2-pro`          |
| `duration`     | integer | Não         | Duração do vídeo: `4` (padrão), `8`, `12` segundos |
| `size`         | string  | Não         | Resolução: `720x1280` (padrão), `1280x720`, `1024x1792`, `1792x1024` |
| `image_urls`   | array   | Não         | Array de URLs de imagens de referência, usa apenas a primeira imagem, tamanho deve coincidir com `size` |
| `callback_url` | string  | Não         | URL para callback assíncrono                |

### Exemplo Básico

```shell
curl -X POST 'https://api.acedata.cloud/sora/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "version": 2,
  "prompt": "cat running on the river",
  "model": "sora-2",
  "duration": 8,
  "size": "1280x720"
}'
```

Código Python correspondente:

```python
import requests

url = "https://api.acedata.cloud/sora/videos"
```

### Uso de Imagem de Referência (Versão 2)

No modo Versão 2, é possível passar imagens de referência pelo parâmetro `image_urls` para guiar a geração do vídeo (apenas a primeira imagem é usada):

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "version": 2,
    "prompt": "a person walking through a beautiful garden",
    "model": "sora-2",
    "duration": 4,
    "size": "1280x720",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

> **Nota**: O tamanho da imagem de referência deve coincidir com o parâmetro `size`. Por exemplo, se `size` for `1280x720`, a imagem deve ter resolução 1280×720.

### Comparação de Parâmetros entre Versão 1 e Versão 2

| Parâmetro      | Versão 1           | Versão 2                                  |
|----------------|--------------------|-------------------------------------------|
| `version`      | 1 (padrão)         | 2                                         |
| `prompt`       | ✅                 | ✅                                         |
| `model`        | ✅ sora-2 / sora-2-pro | ✅ sora-2 / sora-2-pro                      |
| `duration`     | ✅ 10/15/25 segundos | ✅ 4/8/12 segundos                         |
| `orientation`  | ✅ landscape/portrait | ❌                                         |
| `size`         | ✅ small/large      | ✅ 720x1280/1280x720/1024x1792/1792x1024 |
| `image_urls`   | ✅ múltiplas imagens | ✅ apenas a primeira imagem                |
| `character_url`| ✅                  | ❌                                         |
| `callback_url` | ✅                  | ✅                                         |

## Callback Assíncrono

Como a geração de vídeos pela API Sora Videos Generation pode levar de 1 a 2 minutos, a requisição HTTP pode ficar aberta por muito tempo, consumindo recursos do sistema. Por isso, a API suporta callback assíncrono.

O fluxo é: o cliente envia a requisição com o campo `callback_url`. A API retorna imediatamente um resultado contendo o `task_id`. Quando a tarefa for concluída, o resultado da geração do vídeo será enviado via POST em JSON para o `callback_url` especificado, incluindo o campo `task_id` para associação da tarefa.

Vamos ver um exemplo prático.

Copie essa URL para usar como Webhook, por exemplo: `https://webhook.site/eb238c4f-da3b-47a5-a922-a93aa5405daa`.

Configure o campo `callback_url` com essa URL e preencha os demais parâmetros, conforme a imagem:

## Tratamento de Erros

Ao chamar a API, se ocorrer erro, a API retornará códigos e mensagens correspondentes, por exemplo:

- `400 token_mismatched`: requisição inválida, possivelmente por parâmetros ausentes ou inválidos.
- `400 api_not_implemented`: requisição inválida, possivelmente por parâmetros ausentes ou inválidos.
- `401 invalid_token`: não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`: muitas requisições, limite de taxa excedido.
- `500 api_error`: erro interno do servidor.

### Exemplo de Resposta de Erro

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
