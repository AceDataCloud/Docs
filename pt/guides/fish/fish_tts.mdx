Esta interface é baseada na [API oficial Fish Audio TTS](https://docs.fish.audio/text-to-speech/text-to-speech), com diferenças apenas no método de autenticação (uso do token desta plataforma) e no callback assíncrono (extensão `callback_url`), a estrutura do corpo da requisição é a mesma da fonte original. O endpoint é `POST https://api.acedata.cloud/fish/tts`.

## Processo de Solicitação

Para usar a Fish TTS API, primeiro obtenha seu API Token no [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) para uso futuro.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Se você ainda não estiver logado ou registrado, será redirecionado automaticamente para a página de login para se registrar e entrar, após o que retornará automaticamente para esta página.

**Um único API Token pode ser usado para chamar todos os serviços da plataforma, não é necessário solicitar um para cada serviço.** Na primeira solicitação, você receberá uma cota gratuita para experimentar; quando a cota acabar, você pode recarregar saldo geral no [Console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Fish TTS API →](https://platform.acedata.cloud/services/fish)

## Cabeçalhos da Requisição

| Header          | Obrigatório | Descrição                                                                                                     |
| --------------- | ----------- | ------------------------------------------------------------------------------------------------------------- |
| `authorization` | Sim         | `Bearer {token}`, onde `{token}` é a chave obtida nesta plataforma.                                           |
| `content-type`  | Sim         | `application/json`.                                                                                           |
| `accept`        | Não         | `application/json`.                                                                                           |
| `model`         | Não         | Modelo TTS, opcional `s1`, `s2-pro` ou `s2.1-pro`, padrão `s2-pro`. `s2.1-pro` é a geração mais recente, `s2-pro` tem alta expressividade; `s1` é mais estável e menos propenso a erros em textos longos. Todos têm o mesmo preço. |

## Campos do Corpo da Requisição

| Campo           | Tipo                | Obrigatório | Descrição                                                                                                                                                                  |
| --------------- | ------------------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`          | string              | Sim         | Texto a ser sintetizado, string não vazia.                                                                                                                                 |
| `format`        | string              | Não         | Formato do áudio de saída, opcional `mp3` (padrão), `wav`, `pcm`. `wav` e `pcm` retornam ambos em contêiner WAV. `opus` não é suportado, enviar causará erro `400`.          |
| `reference_id`  | string \| string[]  | Não         | ID do clone de voz (pode ser criado via [Fish Model API](https://platform.acedata.cloud/documents/fish-model) ou consultado em [Fish Model Query](https://platform.acedata.cloud/documents/fish-model-query)). |
| `references`    | object[]            | Não         | Amostras de referência inline, estrutura igual à fonte original, cada item contém `audio` e `text`. Usar em alternativa a `reference_id`.                                  |
| `sample_rate`   | integer             | Não         | Taxa de amostragem, comum usar `16000`, `22050`, `44100`. `format=mp3` padrão é 44100.                                                                                       |
| `mp3_bitrate`   | integer             | Não         | Taxa de bits MP3, opcional `64`, `128`, `192`. Válido apenas para `format=mp3`.                                                                                            |
| `prosody`       | object              | Não         | Sobrescrita de prosódia, suporta `speed` (velocidade, 1.0 é velocidade normal) e `volume` (ganho de volume em dB). Exemplo: `{"speed":1.2,"volume":0}`.                     |
| `chunk_length`  | integer             | Não         | Comprimento do fragmento upstream, padrão definido pela fonte original.                                                                                                    |
| `temperature`   | number              | Não         | Temperatura de amostragem, aproximadamente entre 0.0 e 1.0.                                                                                                               |
| `top_p`         | number              | Não         | Parâmetro de amostragem top-p.                                                                                                                                             |
| `latency`       | string              | Não         | `normal` ou `balanced`, padrão preenchido automaticamente como `normal` (enviar string vazia será rejeitado pela fonte original).                                          |
| `normalize`     | boolean             | Não         | Se o texto deve ser normalizado.                                                                                                                                            |
| `callback_url`  | string              | Não         | URL para callback assíncrono, veja seção abaixo “Callback Assíncrono”. **Esta é uma extensão em relação à interface oficial**.                                            |

> Os nomes dos campos são idênticos à fonte original. Exceto `callback_url`, os significados e valores dos demais campos seguem a [documentação oficial Fish TTS](https://docs.fish.audio/text-to-speech/text-to-speech).

## Exemplo 1: Requisição mínima (`text` + `format=mp3`)

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "Hello world.",
    "format": "mp3"
  }'
```

Resposta (teste real):

```json
{
  "audio_url": "https://platform2.cdn.acedata.cloud/fish/e2ffcc06-18da-4a8c-b9aa-9337d0f9ec1d.mp3"
}
```

`audio_url` aponta para o CDN da plataforma, pode ser baixado diretamente via GET ou reproduzido em `<audio>`. O link é válido a longo prazo, mas recomenda-se manter uma cópia no seu próprio armazenamento.

## Exemplo 2: Usando clone de voz `reference_id`

Aqui usamos uma voz pública em espanhol da plataforma Fish (`_id` pode ser consultado via [Fish Model Query](https://platform.acedata.cloud/documents/fish-model-query)):

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "Hermanos míos, hoy es un buen día.",
    "reference_id": "8d2c17a9b26d4d83888ea67a1ee565b2",
    "format": "mp3"
  }'
```

Resposta (teste real):

```json
{
  "audio_url": "https://platform2.cdn.acedata.cloud/fish/b6f161f2-a100-4818-add2-47694f234659.mp3"
}
```

## Exemplo 3: Ajustando velocidade / volume (`prosody`)

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "Faster speech with prosody overrides.",
    "prosody": { "speed": 1.2, "volume": 0 },
    "format": "mp3"
  }'
```

Resposta (teste real):

```json
{
  "audio_url": "https://platform2.cdn.acedata.cloud/fish/5ade0339-5f11-487e-aacc-06a908271706.mp3"
}
```

`speed` maior que 1 acelera, menor que 1 desacelera; `volume` em dB, 0 significa sem alteração, positivo aumenta, negativo diminui.

## Exemplo 4: Trocar modelo + controlar bitrate

Via cabeçalho HTTP `model: s1` para mudar para modelo estável, e no corpo da requisição adicionar `mp3_bitrate: 128` para controlar o bitrate MP3:
```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -H 'model: s1' \
  -d '{
    "text": "alta taxa de bits mp3",
    "format": "mp3",
    "mp3_bitrate": 128
  }'
```

Retorno (medido):

```json
{
  "audio_url": "https://platform2.cdn.acedata.cloud/fish/7e7abf3d-3d72-4c9f-8eb6-8af932d7c96e.mp3"
}
```

## Exemplo 5: Forma de onda PCM bruta

Para cenários que precisam de montagem em tempo real no navegador ou processamento posterior no cliente (mixagem, alteração de velocidade), recomenda-se usar `pcm`:

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "oi",
    "format": "pcm",
    "sample_rate": 16000
  }'
```

Retorno (medido):

```json
{
  "audio_url": "https://platform2.cdn.acedata.cloud/fish/64adc04b-c196-4a0f-9070-222ba101ce6c.wav"
}
```

> A extensão do link segue o `format` no pedido: `mp3` resulta em `.mp3`, `wav` e `pcm` resultam em `.wav` (container WAV, 16 bit PCM).

## Callback assíncrono (`callback_url`)

A síntese de textos longos pode levar de dez a várias dezenas de segundos, se a conexão for interrompida, é necessário tentar novamente. Ao passar `callback_url` no corpo do pedido, a interface retornará imediatamente `{task_id, started_at}`, e quando a tarefa for realmente concluída, o resultado completo será enviado como um POST JSON para essa URL, com o mesmo `task_id` no corpo do pedido.

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "Hoje o tempo está ótimo, vamos sair para dar uma volta.",
    "format": "mp3",
    "callback_url": "https://webhook.site/4815f79f-a40f-4078-ac85-1cc126b6bb34"
  }'
```

Retorno imediato (medido):

```json
{
  "task_id": "79d82713-2897-4eeb-9934-e7544d471aa7",
  "started_at": "2026-05-11T01:23:04.742Z"
}
```

Mais tarde, o `callback_url` receberá algo como:

```json
{
  "task_id": "79d82713-2897-4eeb-9934-e7544d471aa7",
  "audio_url": "https://platform2.cdn.acedata.cloud/fish/bd66b8c5-7543-4557-b684-baa72407e336.mp3"
}
```

Você também pode usar a [API de Tarefas Fish](https://platform.acedata.cloud/documents/fish-tasks) para puxar resultados ativamente por `task_id`, veja o documento para mais detalhes.

## Tratamento de erros

- `400 token_mismatched`: Parâmetros de solicitação ausentes ou inválidos (o mais comum é `text` vazio ou `format` com um valor diferente de `mp3`/`wav`/`pcm`).
- `401 invalid_token`: Token de autenticação inexistente ou inválido.
- `429 too_many_requests`: Limite de taxa da conta atingido.
- `500 api_error`: Erro interno do servidor.

Exemplo de resposta de erro:

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Erros de validação de parâmetros incluirão a mensagem de erro original do pydantic no campo `message`, facilitando a localização do campo inválido, por exemplo:

```json
{
  "status": 400,
  "message": "[{\"type\":\"literal_error\",\"loc\":[\"format\"],\"msg\":\"Input deve ser 'pcm' ou 'mp3'\",\"input\":\"wav\"}]"
}
```

## Conclusão

O custo mínimo para integrar o Fish TTS é: substituir a autenticação pelo token da plataforma no código que já chama `api.fish.audio/v1/tts`, e incluir explicitamente `format: "mp3"` no corpo do pedido. Para cenários de texto longo, recomenda-se usar `callback_url` para callback assíncrono; para descobrir o `reference_id` da clonagem de timbre, utilize a [Consulta de Modelos Fish](https://platform.acedata.cloud/documents/fish-model-query) e [Obter Modelo Fish](https://platform.acedata.cloud/documents/fish-model-get).
