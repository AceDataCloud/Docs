Esta interface é baseada na [API TTS oficial da Fish Audio](https://docs.fish.audio/text-to-speech/text-to-speech), com diferenças apenas na forma de autenticação (usando o token desta plataforma) e no callback assíncrono (extensão `callback_url`), a estrutura do corpo da solicitação é a mesma que a upstream. O endereço é `POST https://api.acedata.cloud/fish/tts`.

## Processo de Solicitação

Para usar a API Fish TTS, primeiro acesse o [console da Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu Token API, que deve ser guardado para uso futuro.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Se você ainda não estiver logado ou registrado, será redirecionado automaticamente para a página de login, convidando-o a se registrar e fazer login. Após a conclusão, você será redirecionado de volta para a página atual.

**Um Token API é suficiente para acessar todos os serviços da plataforma, não é necessário solicitar um para cada serviço.** A primeira solicitação oferece um crédito gratuito para que você possa experimentar; quando o crédito estiver baixo, você pode recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Fish TTS API →](https://platform.acedata.cloud/services/fish)

## Cabeçalho da Solicitação

| Cabeçalho       | Obrigatório | Descrição                                                                                                     |
| --------------- | ----------- | ------------------------------------------------------------------------------------------------------------ |
| `authorization` | Sim         | `Bearer {token}`, onde `{token}` é a chave solicitada nesta plataforma.                                     |
| `content-type`  | Sim         | `application/json`.                                                                                          |
| `accept`        | Não         | `application/json`.                                                                                          |
| `model`         | Não         | Modelo TTS, pode ser `s1`, `s2-pro` ou `s2.1-pro`, padrão `s2-pro`. `s2.1-pro` é a última geração, `s2-pro` tem forte expressividade; `s1` é mais estável, textos longos não se desviam facilmente. Todos têm o mesmo preço. |

## Campos do Corpo da Solicitação

| Campo            | Tipo              | Obrigatório | Descrição                                                                                                                                                                         |
| ---------------- | ----------------- | ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `text`           | string            | Sim         | Texto a ser sintetizado, string não vazia.                                                                                                                                     |
| `format`         | string            | Sim         | Formato de áudio de saída. **Atualmente deve ser explicitamente definido**, pode ser `mp3` ou `pcm`. Mesmo que a documentação oficial liste `wav`, `opus`, esta interface retornará `400 Input should be 'pcm' or 'mp3'`. |
| `reference_id`   | string | string[] | Não         | ID de clone de voz (pode ser criado pela [API Fish Model](https://platform.acedata.cloud/documents/fish-model) ou recuperado na [Consulta de Modelos Fish](https://platform.acedata.cloud/documents/fish-model-query)). |
| `references`     | object[]          | Não         | Amostras de referência inline, estrutura igual à upstream, cada item contém `audio` e `text`. Um dos dois com `reference_id`.                                                                 |
| `sample_rate`    | integer           | Não         | Taxa de amostragem, comumente `16000`, `22050`, `44100`. `format=mp3` padrão é 44100.                                                                                          |
| `mp3_bitrate`    | integer           | Não         | Taxa de bits MP3, pode ser `64`, `128`, `192`. Apenas `format=mp3` é efetivo.                                                                                                 |
| `prosody`        | object            | Não         | Cobertura de prosódia, suporta `speed` (velocidade da fala, 1.0 é a velocidade original) e `volume` (ganho de volume em dB). Por exemplo `{"speed":1.2,"volume":0}`.                              |
| `chunk_length`   | integer           | Não         | Comprimento do fragmento upstream, padrão decidido pela upstream.                                                                                                              |
| `temperature`    | number            | Não         | Temperatura de amostragem, faixa de aproximadamente 0.0–1.0.                                                                                                                  |
| `top_p`          | number            | Não         | Parâmetro de amostragem top-p.                                                                                                                                                 |
| `latency`        | string            | Não         | `normal` ou `balanced`, padrão é automaticamente preenchido como `normal` (enviar string vazia será rejeitado pela upstream).                                                  |
| `normalize`      | boolean           | Não         | Se deve normalizar o texto.                                                                                                                                                    |
| `callback_url`   | string            | Não         | Endereço de callback assíncrono, veja abaixo "Callback Assíncrono". **Esta é uma extensão em relação à interface oficial**.                                                      |

> A nomenclatura dos campos é idêntica à upstream. Exceto `callback_url`, os outros campos têm significados e valores conforme a [documentação oficial TTS da Fish](https://docs.fish.audio/text-to-speech/text-to-speech).

## Exemplo 1: Solicitação Mínima (`text` + `format=mp3`)

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "Hello world.",
    "format": "mp3"
  }'
```

Retorno (testado):

```json
{
  "audio_url": "https://platform.r2.fish.audio/task/05f81919f2e04e35bb404a88fb177854.mp3"
}
```

`audio_url` é o link direto do Fish R2, pode ser baixado diretamente via GET ou reproduzido em `<audio>`, a assinatura geralmente é válida por 1 hora, recomenda-se armazenar em seu próprio armazenamento de objetos após o download.

## Exemplo 2: Usando a Voz Clone `reference_id`

Abaixo, usando uma voz pública em espanhol da plataforma Fish (`_id` pode ser recuperado através da [Consulta de Modelos Fish](https://platform.acedata.cloud/documents/fish-model-query)):

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "Hermanos míos, hoy es un buen día.",
    "reference_id": "8d2c17a9b26d4d83888ea67a1ee565b2",
    "format": "mp3"
  }'
```

Retorno (testado):

```json
{
  "audio_url": "https://platform.r2.fish.audio/task/560078cf603d4584a2313ca4cd742056.mp3"
}
```

## Exemplo 3: Ajustando Velocidade / Volume (`prosody`)

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "Faster speech with prosody overrides.",
    "prosody": { "speed": 1.2, "volume": 0 },
    "format": "mp3"
  }'
```

Retorno (testado):

```json
{
  "audio_url": "https://platform.r2.fish.audio/task/f16759a3335748f1b4d1e56ed54d81dd.mp3"
}
```

`speed` maior que 1 acelera, menor que 1 desacelera; `volume` em dB, 0 significa sem alteração, números positivos aumentam, negativos diminuem.

## Exemplo 4: Mudando Modelo + Controlando Taxa de Bits

Através do cabeçalho HTTP `model: s1` mude para o modelo estável, adicione `mp3_bitrate: 128` no corpo da solicitação para controlar a taxa de bits MP3:
```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -H 'model: s1' \
  -d '{
    "text": "alta taxa de bits mp3",
    "format": "mp3",
    "mp3_bitrate": 128
  }'
```

Retorno (medido):

```json
{
  "audio_url": "https://platform.r2.fish.audio/task/6b660348776e40529e537aa30b1051d2.mp3"
}
```

## Exemplo 5: Forma de onda PCM bruta

Para cenários que precisam de montagem em tempo real no navegador ou processamento posterior no cliente (mixagem, alteração de velocidade), recomenda-se usar `pcm`:

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "oi",
    "format": "pcm",
    "sample_rate": 16000
  }'
```

Retorno (medido):

```json
{
  "audio_url": "https://platform.r2.fish.audio/task/2052cc1f33b049d99a18fcc496f4462e.mp3"
}
```

> A extensão do link de resposta atual é fixada como `.mp3`, o conteúdo real é o fluxo de bytes do `format` especificado na solicitação. Ao baixar, deve-se decidir como interpretar com base no `format` na solicitação.

## Callback assíncrono (`callback_url`)

A síntese de texto longo pode levar de dez a dezenas de segundos, se a conexão for interrompida, é necessário tentar novamente. Ao passar `callback_url` no corpo da solicitação, a interface retornará imediatamente `{task_id, started_at}`, e quando a tarefa for realmente concluída, o resultado completo será retornado via POST JSON para essa URL, com o mesmo `task_id` no corpo da solicitação.

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "Hoje o tempo está ótimo, vamos dar uma volta juntos.",
    "format": "mp3",
    "callback_url": "https://webhook.site/4815f79f-a40f-4078-ac85-1cc126b6bb34"
  }'
```

Retorno imediato (medido):

```json
{
  "task_id": "79d82713-2897-4eeb-9934-e7544d471aa7",
  "started_at": "2026-05-11T01:23:04.742Z"
}
```

Mais tarde, `callback_url` receberá algo como:

```json
{
  "task_id": "79d82713-2897-4eeb-9934-e7544d471aa7",
  "audio_url": "https://platform.r2.fish.audio/task/b627c2f7d38a4083a837570ba6d0962f.mp3"
}
```

Você também pode usar a [API de Tarefas Fish](https://platform.acedata.cloud/documents/fish-tasks) para puxar resultados ativamente por `task_id`, veja o documento para mais detalhes.

## Tratamento de erros

- `400 token_mismatched`: Parâmetros de solicitação ausentes ou inválidos (o mais comum é não passar `format`, `text` vazio).
- `401 invalid_token`: Token de autenticação inexistente ou inválido.
- `429 too_many_requests`: Limite de taxa da conta atingido.
- `500 api_error`: Erro interno do servidor.

Exemplo de resposta de erro:

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "falha ao buscar"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Erros de validação de parâmetros colocarão o texto de erro original do pydantic no campo `message`, facilitando a localização de qual campo é inválido, por exemplo:

```json
{
  "status": 400,
  "message": "[{\"type\":\"literal_error\",\"loc\":[\"format\"],\"msg\":\"A entrada deve ser 'pcm' ou 'mp3'\",\"input\":\"wav\"}]"
}
```

## Conclusão

O custo mínimo para integrar o Fish TTS é: substituir a autenticação pelo token da plataforma no código que já chama `api.fish.audio/v1/tts` e incluir explicitamente no corpo da solicitação `format: "mp3"`. Para cenários de texto longo, recomenda-se usar o callback assíncrono `callback_url`; para descobrir o `reference_id` da clonagem de timbre, utilize a [Consulta de Modelos Fish](https://platform.acedata.cloud/documents/fish-model-query) e [Obter Modelo Fish](https://platform.acedata.cloud/documents/fish-model-get).
