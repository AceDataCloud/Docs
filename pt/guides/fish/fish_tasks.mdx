A principal função da API Fish Tasks é consultar a situação de execução dessa tarefa inserindo o ID da tarefa gerado pela API Fish Audios Generation.

Este documento apresentará detalhadamente as instruções de integração da API Fish Tasks, ajudando você a integrar facilmente e aproveitar plenamente os poderosos recursos desta API. Por meio da API Fish Tasks, você pode facilmente consultar a situação de execução das tarefas da API Fish Audios Generation.

## Processo de solicitação

Para usar a API Fish Audios Generation, primeiro acesse o [Console Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obter seu API Token e guarde-o para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Se você ainda não estiver conectado ou registrado, será automaticamente redirecionado para a página de login, onde será convidado a se registrar e fazer login; após a conclusão, retornará automaticamente à página atual.

**Um API Token pode chamar todos os serviços da plataforma, sem a necessidade de solicitar separadamente para cada serviço.** Na primeira solicitação, será concedida uma cota gratuita para experimentação; quando a cota for insuficiente, você poderá recarregar o saldo geral no [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentação completa: [Fish Audios Generation API →](https://platform.acedata.cloud/documents/fish-tts)

## Exemplo de solicitação

A API Fish Tasks pode ser usada para consultar os resultados da API Fish Audios Generation. Sobre como usar a API Fish Audios Generation, consulte a documentação [Fish Videos Generation API ](https://platform.acedata.cloud/documents/fish-tts-integration).

Usamos como exemplo um ID de tarefa retornado pelo serviço API Fish Audios Generation para demonstrar como usar esta API. Suponha que temos um ID de tarefa: 2725a2d3-f87e-4905-9c53-9988d5a7b2f5, a seguir demonstramos como ao inserir um ID de tarefa.

### Configurar os cabeçalhos e o corpo da solicitação

**Request Headers** incluem:

- `accept`: especifica o recebimento de resultados de resposta no formato JSON, aqui preenchido como `application/json`.
- `authorization`: a chave para chamar a API, após a solicitação pode ser selecionada diretamente no menu suspenso.

**Request Body** inclui:

- `id`: o ID da tarefa enviada.
- `action`: a forma de operação da tarefa.

A configuração é mostrada na imagem abaixo:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/fish/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2725a2d3-f87e-4905-9c53-9988d5a7b2f5",
  "action": "retrieve"
}'
```


O resultado retornado possui vários campos; o campo request é o request body ao iniciar a tarefa, enquanto o campo response é o response body retornado após a conclusão da tarefa. A descrição dos campos é a seguinte.

- `id`, o ID que gera esta tarefa, usado para identificar exclusivamente esta tarefa de geração.
- `request`, as informações da solicitação na consulta da tarefa.
- `response`, as informações de retorno na consulta da tarefa; quando for finalmente bem-sucedida, o `cost.amount` nela contido são os Credits efetivamente deduzidos nesta síntese.
- `created_at`, horário de criação da tarefa, timestamp Unix (segundos, ponto flutuante).
- `started_at`, horário de início da execução da tarefa, timestamp Unix (segundos, ponto flutuante).
- `finished_at`, horário de conclusão da tarefa, timestamp Unix (segundos, ponto flutuante). Este campo não é retornado quando a tarefa não foi concluída.
- `elapsed`, tempo de execução da tarefa, em segundos (ponto flutuante, mantendo 3 casas decimais). Este campo não é retornado quando a tarefa não foi concluída.

## Tratamento de erros

Ao chamar a API, se ocorrer um erro, a API retornará o código e a mensagem de erro correspondentes. Por exemplo:

- `400 token_mismatched`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `400 api_not_implemented`：Solicitação inválida, possivelmente devido a parâmetros ausentes ou inválidos.
- `401 invalid_token`：Não autorizado, token de autorização inválido ou ausente.
- `429 too_many_requests`：Muitas solicitações, você excedeu o limite de taxa.
- `500 api_error`：Erro interno do servidor, algo deu errado no servidor.

### Exemplo de resposta de erro

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
