[MCP (Model Context Protocol)](https://modelcontextprotocol.io) est un protocole de contexte de modèle lancé par Anthropic, qui permet aux modèles d’IA (tels que Claude, GPT, etc.) d’appeler des outils externes via des interfaces standardisées. Grâce au Flux MCP Server fourni par AceData Cloud, vous pouvez générer et éditer directement des images IA dans des clients IA tels que Claude Desktop, VS Code, Cursor, etc.

## Aperçu des fonctionnalités

Flux MCP Server fournit les fonctionnalités principales suivantes :

- **Génération d’images à partir de texte** — Générer des images de haute qualité à partir d’invites textuelles
- **Édition d’images** — Éditer des images existantes à partir d’instructions textuelles
- **Prise en charge de plusieurs modèles** — Prend en charge plusieurs modèles tels que Flux Pro, Flux Dev, Flux 2, Flux Kontext, etc.
- **Consultation des modèles** — Afficher tous les modèles disponibles et leurs capacités
- **Consultation des tâches** — Surveiller la progression de la génération et obtenir les résultats

## Préparation préalable

Avant utilisation, vous devez obtenir un API Token AceData Cloud :

1. Inscrivez-vous ou connectez-vous à la [plateforme AceData Cloud](https://platform.acedata.cloud)
2. Accédez à la page [Flux Images API](https://platform.acedata.cloud/documents/flux-images)
3. Cliquez sur « Acquire » pour obtenir l’API Token (la première demande inclut un crédit gratuit)

## Méthode 1 : utiliser le MCP Server hébergé (recommandé, sans installation)

AceData Cloud héberge déjà le **Flux MCP Server** dans le cloud, **sans nécessiter l’installation locale d’aucune dépendance**. Il suffit de renseigner l’URL suivante dans le client IA pour l’utiliser :

```
https://flux.mcp.acedata.cloud/mcp
```

Méthode d’authentification : ajoutez `Authorization: Bearer votre API Token` dans l’en-tête de la requête (Claude.ai le fait automatiquement via OAuth, sans saisie manuelle du Token).

### Claude.ai (version web, connexion OAuth, le plus simple)

1. Ouvrez [Claude.ai](https://claude.ai) → **Customize** en bas à gauche → **Connectors** → **Add More**
2. Saisissez dans l’URL : `https://flux.mcp.acedata.cloud/mcp`
3. Terminez la connexion via l’autorisation OAuth (redirection automatique vers la page de connexion AceData Cloud)
4. Retournez à l’interface de conversation, l’outil est alors prêt à être utilisé

### Claude Desktop

Modifiez le fichier de configuration :

- macOS : `~/Library/Application Support/Claude/claude_desktop_config.json`
- Windows : `%APPDATA%\Claude\claude_desktop_config.json`

```json
{
  "mcpServers": {
    "flux": {
      "type": "http",
      "url": "https://flux.mcp.acedata.cloud/mcp",
      "headers": {
        "Authorization": "Bearer 你的API Token"
      }
    }
  }
}
```

Enregistrez puis redémarrez Claude Desktop pour appliquer les modifications.

### Claude Code (ligne de commande du terminal)

```bash
claude mcp add flux --transport http https://flux.mcp.acedata.cloud/mcp \
  -H "Authorization: Bearer 你的API Token"
```

### Autres clients prenant en charge MCP

Tout client prenant en charge le protocole MCP Streamable HTTP (Windsurf, Cline, ChatGPT Connectors, Gemini CLI, JetBrains AI Assistant, etc.) peut être connecté en renseignant les deux éléments suivants :

- **URL** : `https://flux.mcp.acedata.cloud/mcp`
- **Header** : `Authorization: Bearer votre API Token`

## Méthode 2 : exécution locale (installation pip / uvx)

Si vous devez exécuter hors ligne, personnaliser le code ou déployer sur un réseau interne, vous pouvez installer MCP Server localement et le démarrer via stdio.

### Installation

Installation avec pip (recommandée) :

```bash
pip install mcp-flux-pro
```

Ou installation depuis les sources :

```bash
git clone https://github.com/AceDataCloud/FluxMCP.git
cd FluxMCP
pip install -e .
```

Une fois l’installation terminée, vous pouvez utiliser la commande `mcp-flux-pro` pour démarrer le service.

### Utilisation dans Claude Desktop (local)

Modifiez le fichier de configuration de Claude Desktop :

- **macOS** : `~/Library/Application Support/Claude/claude_desktop_config.json`
- **Windows** : `%APPDATA%\Claude\claude_desktop_config.json`

Ajoutez la configuration suivante :

```json
{
  "mcpServers": {
    "flux": {
      "command": "mcp-flux-pro",
      "env": {
        "ACEDATACLOUD_API_TOKEN": "你的API Token"
      }
    }
  }
}
```

Si vous utilisez `uvx` (sans installer le package au préalable) :

```json
{
  "mcpServers": {
    "flux": {
      "command": "uvx",
      "args": ["mcp-flux-pro"],
      "env": {
        "ACEDATACLOUD_API_TOKEN": "你的API Token"
      }
    }
  }
}
```

Enregistrez la configuration puis redémarrez Claude Desktop pour appliquer les modifications.

### Utilisation dans VS Code / Cursor (local)

Créez `.vscode/mcp.json` à la racine du projet :

## Liste des outils disponibles

| Nom de l’outil                    | Description                       |
| ---------------------- | ------------------------ |
| `flux_generate_image`  | Générer des images à partir d’invites textuelles              |
| `flux_edit_image`      | Éditer des images existantes à partir d’instructions textuelles             |
| `flux_generate_video`  | Génération de texte-vers-vidéo / image-vers-vidéo FLUX 3 et amélioration de brouillons existants |
| `flux_get_task`        | Consulter l’état d’une tâche individuelle                 |
| `flux_get_tasks_batch` | Consulter l’état de tâches par lot                 |
| `flux_list_models`     | Lister tous les modèles disponibles et leurs capacités             |
| `flux_list_actions`    | Lister tous les outils disponibles et exemples de flux de travail           |

## Contraintes des modèles et des dimensions
`flux-2-flex`, `flux-2-pro`, `flux-2-max` et les modèles Kontext doivent utiliser
des proportions pour `size`, par exemple `1:1` ou `16:9`, et ne peuvent pas utiliser des dimensions en pixels telles que `1024x1024`.
`flux-2-klein` prend uniquement en charge la génération et ne fait pas partie des modèles sélectionnables dans `flux_edit_image`.

`flux_generate_video` distingue `t2v`, `i2v`, `v2v` et
`draft_enhance` via `request.mode`, et les entrées sont affichées selon le mode. L'amélioration de brouillon doit référencer son propre `draft_task_id` temporaire.
Les soumissions sont asynchrones par défaut ; conservez l'ID de tâche renvoyé et utilisez `flux_get_task` pour lire le résultat.
