## 1. Obtenir la clé API

Ouvrez la [liste des applications Ace Data Cloud](https://platform.acedata.cloud/console/applications), accédez aux applications disponibles et copiez la clé API.

![Obtenir la clé API Ace Data Cloud](https://cdn.acedata.cloud/dvc3cg.jpg)

Dans le **Settings → Secrets and variables → Actions** du dépôt GitHub cible, créez un Secret :

```text
ACEDATACLOUD_API_KEY
```

## 2. Installer l'application GitHub

Installez l'[application GitHub Claude](https://github.com/apps/claude) et autorisez le dépôt cible. Cette application officielle demandera un ensemble de permissions complètes fixes ; parmi lesquelles, l'Action Claude Code utilise réellement les permissions Contents, Issues et Pull requests, la page d'installation de GitHub ne peut pas cocher uniquement ces trois éléments. Si l'organisation exige des permissions minimales, veuillez créer une application GitHub personnalisée selon la documentation officielle.

## 3. Ajouter un Workflow

Créez `.github/workflows/claude.yml` :

```yaml
name: Claude Code

on:
  issue_comment:
    types: [created]
  pull_request_review_comment:
    types: [created]

jobs:
  claude:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write
      issues: write
      actions: read
      id-token: write
    env:
      ANTHROPIC_BASE_URL: https://api.acedata.cloud
      ANTHROPIC_CUSTOM_HEADERS: "Authorization: Bearer ${{ secrets.ACEDATACLOUD_API_KEY }}"
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: dummy-not-used
```

`claude-code-action` nécessite une entrée `anthropic_api_key` non vide ; la valeur de remplacement ici ne sera pas utilisée pour l'authentification de la plateforme. `ANTHROPIC_CUSTOM_HEADERS` remplacera l'en-tête Bearer requis par Ace Data Cloud, la clé réelle provient uniquement du Secret GitHub.

## 4. Vérification

Après avoir soumis le Workflow, envoyez dans un commentaire d'Issue ou de PR :

```text
@claude Reply only OK
```

En cas de succès, le workflow Actions sera complété et mettra à jour le résultat dans l'Issue/PR correspondant. Si l'Action indique qu'il manque des identifiants, vérifiez que `dummy-not-used` est toujours présent ; pour une erreur 401, vérifiez le Secret `ACEDATACLOUD_API_KEY`. Ne pas imprimer le Secret dans les journaux. Vous pouvez utiliser `claude_args` pour définir `--max-turns` ou choisir le modèle actuellement disponible, mais l'intégration du modèle n'est pas fixe.
