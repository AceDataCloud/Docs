Google Gemini est un système de conversation IA très puissant, capable de générer en quelques secondes des réponses fluides et naturelles à partir d'une invite. Ce document décrit principalement l'utilisation de l'API Gemini Generate Content, qui est le format d'API natif officiel de Google et prend en charge les deux points de terminaison `generateContent` et `streamGenerateContent`.

## Différences avec l'API Chat Completions

L'API Gemini Generate Content utilise le format de requête natif officiel de Google (champ `contents`), plutôt que le format compatible OpenAI (champ `messages`). Si vous utilisez déjà le SDK Google Gemini ou connaissez le format officiel de l'API, vous pouvez utiliser directement cette API sans modifier le format de la requête.

## Portée actuellement prise en charge

L'interface accepte les entrées texte, image, vidéo et audio (`inlineData` ou `fileData`), les configurations de réflexion et les déclarations de fonctions personnalisées. La disponibilité unifiée des champs natifs tels que la sortie audio, les outils intégrés et la mise en cache explicite du contexte n'est pas encore garantie ; veuillez vous référer au retour réel du modèle spécifique.

Lors de la soumission de fichiers tels que des fichiers audio avec `fileData.fileUri`, veuillez vous assurer que les fichiers sont directement accessibles via HTTPS, ne dépendent pas d'un état de connexion, et que la période de validité du lien signé couvre l'intégralité du temps de traitement de la requête. L'analyse audio non diffusée ne renvoie des résultats qu'après que le modèle a terminé le traitement, ce qui peut dépasser 90 secondes ; le client doit définir un délai d'attente total suffisamment long selon la taille du fichier et le scénario métier, afin d'éviter de fermer la connexion alors que le serveur traite encore la requête.

## Processus de demande

Avant d'utiliser l'API Gemini Generate Content, veuillez d'abord accéder à la page [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api), puis cliquer sur le bouton « Obtenir » afin d'obtenir les identifiants nécessaires à la requête.

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion. La première demande inclut un quota gratuit.

## Utilisation de base

### Non-Streaming（sans flux）

Envoyez une requête POST vers `/v1beta/models/{model}:generateContent` :

> **Astuce** : les modèles flash de la série `gemini-3.x` sont des modèles de réflexion et consomment d'abord des reasoning tokens ; veuillez définir `generationConfig.maxOutputTokens` à 512 ou plus, sinon seul un contenu vide pourrait être renvoyé.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Exemple de résultat retourné :

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Les champs de token dans `usageMetadata` sont facturés selon la sémantique native de Gemini :

- `promptTokenCount` inclut `cachedContentTokenCount` ; la partie atteinte par le cache est calculée selon le prix de lecture du cache et n'est pas à nouveau comptabilisée comme une entrée ordinaire.
- `promptTokensDetails` et `cacheTokensDetails` seront normalisés sous forme de `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` et des détails `cached_*` correspondants dans `usage.prompt_tokens_details`. Ces valeurs sont respectivement incluses dans `prompt_tokens` et `cached_tokens` ; les différentes modalités ne sont recalculées qu'à leur propre tarif et ne sont pas facturées deux fois.
- `candidatesTokenCount` et `thoughtsTokenCount` sont tous deux calculés au tarif des tokens de sortie.
- `toolUsePromptTokenCount` correspond à des tokens d'entrée d'outil indépendants, calculés au tarif des tokens d'entrée.

Ace Data Cloud renvoie en supplément l'objet normalisé `usage`, et les frais de cet appel sont lus de manière unifiée entre les protocoles de modèles depuis `usage.cost`. `cost` est un aperçu facultatif des frais ; lorsque l'aperçu des prix est temporairement indisponible, la réponse du modèle est toujours renvoyée normalement, mais peut ne pas inclure ce champ. La facturation finale dépend des enregistrements d'utilisation.

### Streaming（en flux）

Envoyez une requête POST vers `/v1beta/models/{model}:streamGenerateContent?alt=sse` :

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

La réponse en flux renvoie progressivement du contenu au format SSE (Server-Sent Events). Les événements intermédiaires ne contiennent généralement que du contenu incrémentiel ; l'événement final contenant l'utilisation faisant autorité inclut `usageMetadata` et le `usage` normalisé, tandis que les frais se trouvent toujours dans `usage.cost` :

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

La fermeture de la connexion indique la fin du flux ; le flux Gemini natif n'envoie pas `data: [DONE]`. Si l'aperçu des prix final est temporairement indisponible, `usage` renverra toujours l'utilisation des tokens, mais omettra `cost`.

### Réflexion interne et résumé de réflexion

La réflexion interne du modèle et le renvoi d’un résumé de réflexion à l’appelant sont deux paramètres indépendants :

- `thinkingBudget` ou `thinkingLevel` contrôle le budget ou la profondeur de réflexion interne du modèle ; les champs et valeurs pris en charge dépendent du modèle.
- `includeThoughts` contrôle si un résumé de réflexion est renvoyé, la valeur par défaut est `false`. Lorsque ce champ est omis ou que `false` est transmis, ni les réponses JSON ordinaires ni les réponses en flux SSE ne renvoient du texte marqué `thought: true` ; ces textes ne sont conservés que lorsqu’une valeur booléenne `true` est explicitement transmise.

Lorsqu’une requête ne définit pas `includeThoughts`, l’interface transmet par défaut `false` aux modèles de génération prenant en charge la configuration de réflexion, afin d’éviter de demander des résumés inutiles ; les valeurs, budgets et niveaux de réflexion explicitement transmis par le client sont conservés. Le champ n’est pas automatiquement ajouté au modèle `gemini-2.5-flash-image`, connu pour ne pas prendre en charge la configuration de réflexion, et aucune configuration de génération n’est ajoutée aux requêtes `countTokens`.

Désactiver les résumés ne signifie pas désactiver la réflexion interne, et ne garantit pas non plus une réduction des tokens de réflexion interne. Si la réponse contient encore du texte de réflexion non demandé, les sorties JSON ordinaires et SSE le filtrent davantage, en conservant la réponse normale, les signatures et l’utilisation réelle.

Lorsque vous devez consulter les résumés, activez-les explicitement de la manière suivante. Si le modèle ne génère pas de résumé utilisable, il peut ne pas y avoir de texte de réflexion même lorsqu’ils sont activés :

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` est l’état chiffré requis pour les tours suivants, et non le texte du résumé de réflexion ; il n’est pas non plus contrôlé par l’interrupteur `includeThoughts`. La signature peut se trouver dans une réponse normale, un appel de fonction ou une Part de texte vide ; lors du filtrage du texte de réflexion, la signature et les autres champs de la même Part sont conservés. Par conséquent, la réponse peut encore contenir des Parts qui ne portent qu’une signature et dont le texte est vide. Lors de la gestion manuelle de l’historique de plusieurs tours, vous devez conserver l’ordre de ces Parts et la position des signatures ; ne déplacez pas les signatures et ne les fusionnez pas.

`usageMetadata` et `usage` enregistrent toujours l’utilisation réelle. Masquer les résumés ne remet pas à zéro `thoughtsTokenCount` ; la facturation est toujours calculée selon l’utilisation réelle et les règles tarifaires en vigueur.

Consultez les explications officielles de Google sur la [réflexion et les résumés de réflexion](https://firebase.google.com/docs/ai-logic/thinking) et les [règles relatives aux signatures de réflexion](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

### Appel de fonction

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "北京现在的天气怎么样？"}]
    }
  ],
  "tools": [
    {
      "functionDeclarations": [
        {
          "name": "get_weather",
          "description": "获取指定城市的天气信息",
          "parameters": {
            "type": "object",
            "properties": {
              "city": {
                "type": "string",
                "description": "城市名称"
              }
            },
            "required": ["city"]
          }
        }
      ]
    }
  ]
}
```

```json
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "你好，我叫小明"}]
    },
    {
      "role": "model",

    },
    {
      "role": "user",
      "parts": [{"text": "我叫什么名字？"}]
    }
  ]
}
```

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [
        {"text": "描述这张图片"},
        {
          "inlineData": {

        }
      ]
    }
  ]
}
```

## Paramètres de sécurité

Le filtrage du contenu peut être contrôlé via `safetySettings` :

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Gestion des erreurs

| Code d’état HTTP | Signification             |
| -------- | -------------- |
| 400      | Paramètres de requête invalides         |
| 401      | Échec de l’authentification, veuillez vérifier le Token |
| 403      | Contenu bloqué par le filtre de sécurité     |
| 429      | Requêtes trop fréquentes         |
| 500      | Erreur interne du serveur        |
