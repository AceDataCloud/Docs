Google Gemini est un système de dialogue d'IA très puissant, capable de générer des réponses fluides et naturelles en quelques secondes à partir d'une invite. Ce document décrit principalement l'utilisation de l'API Gemini Generate Content, qui utilise le format d'API natif officiel de Google et prend en charge les deux points de terminaison `generateContent` et `streamGenerateContent`.

## Différences avec l'API Chat Completions

L'API Gemini Generate Content utilise le format de requête natif officiel de Google (champ `contents`), plutôt que le format compatible OpenAI (champ `messages`). Si vous utilisez déjà le SDK Google Gemini ou connaissez le format officiel de l'API, vous pouvez utiliser directement cette API sans modifier le format de la requête.

## Portée actuellement prise en charge

L'interface accepte les entrées de texte, d'image, de vidéo et d'audio (`inlineData` ou `fileData`), les configurations de réflexion ainsi que les déclarations de fonctions personnalisées. Les champs natifs tels que la sortie audio, les outils intégrés et la mise en cache explicite du contexte ne disposent pas encore d'une garantie de disponibilité unifiée ; veuillez vous référer aux retours réels du modèle spécifique.

Lors de la soumission de fichiers tels que des fichiers audio avec `fileData.fileUri`, assurez-vous que les fichiers sont directement accessibles via HTTPS, sans dépendre d'un état de connexion, et que la période de validité du lien signé couvre toute la durée de traitement de la requête. L'analyse audio non diffusée ne renvoie un résultat qu'après la fin du traitement par le modèle, ce qui peut dépasser 90 secondes ; le client doit définir un délai d'expiration total suffisamment long selon la taille du fichier et le scénario métier, afin d'éviter de couper la connexion alors que le serveur traite encore la requête.

## Processus de demande

Avant d'utiliser l'API Gemini Generate Content, veuillez d'abord accéder à la page [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api), puis cliquer sur le bouton « Obtenir » afin d'obtenir les identifiants nécessaires à la requête.

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion. Une première demande inclut un quota gratuit.

## Utilisation de base

### Non-Streaming (non diffusé)

Envoyez une requête POST à `/v1beta/models/{model}:generateContent` :

> **Conseil** : la série flash `gemini-3.x` correspond à des modèles de réflexion, qui consomment d'abord des reasoning tokens ; veuillez définir `generationConfig.maxOutputTokens` sur 512 ou plus, sinon seul un contenu vide pourrait être renvoyé.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Exemple de résultat renvoyé :

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [{"text": "你好！很高兴与你交流。"}]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Les champs de tokens dans `usageMetadata` sont facturés selon la sémantique native de Gemini :

- `promptTokenCount` inclut `cachedContentTokenCount` ; la partie servie depuis le cache est calculée au tarif de lecture du cache et n'est pas comptabilisée à nouveau comme entrée standard.
- `promptTokensDetails` et `cacheTokensDetails` sont normalisés en `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` et les détails `cached_*` correspondants sous `usage.prompt_tokens_details`. Ces valeurs sont respectivement incluses dans `prompt_tokens` et `cached_tokens` ; les différentes modalités sont recalculées uniquement selon leurs propres tarifs et ne sont pas facturées deux fois.
- `candidatesTokenCount` et `thoughtsTokenCount` sont tous deux calculés au tarif des tokens de sortie.
- `toolUsePromptTokenCount` est un token d'entrée d'outil indépendant, calculé au tarif des tokens d'entrée.

Ace Data Cloud renvoie en supplément un objet `usage` normalisé ; quel que soit le protocole de modèle, les frais de cet appel sont lus de manière unifiée depuis `usage.cost`. `cost` est un aperçu facultatif des frais ; lorsque l'aperçu tarifaire est temporairement indisponible, la réponse du modèle est tout de même renvoyée normalement, mais peut ne pas inclure ce champ. La facturation finale est basée sur les enregistrements d'utilisation.

### Streaming (diffusé)

Envoyez une requête POST à `/v1beta/models/{model}:streamGenerateContent?alt=sse` :

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

La réponse diffusée renvoie progressivement le contenu au format SSE (Server-Sent Events). Les événements intermédiaires ne contiennent généralement que du contenu incrémentiel ; l'événement final contenant l'utilisation faisant autorité inclut `usageMetadata` et le `usage` normalisé, tandis que les frais se trouvent toujours dans `usage.cost` :

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

La fermeture de la connexion indique la fin du flux ; le flux Gemini natif n'envoie pas `data: [DONE]`. Si l'aperçu tarifaire final est temporairement indisponible, `usage` renverra toujours l'utilisation des tokens, mais omettra `cost`.

`gemini-4-carbon` et `gemini-4-hydrogen` peuvent actuellement être appelés via Chat Completions, Generate Content natif n’est pas encore disponible. Les spécifications officielles des modèles répertorient les entrées de texte, d’images, de vidéos, d’audio et de PDF ainsi que les sorties de texte ; cela ne signifie pas que tous les types d’entrée ont été vérifiés sur la plateforme actuelle. Après le rétablissement des appels natifs, veuillez soumettre les requêtes selon le contrat d’interface de cette page et vérifier séparément les entrées et paramètres requis. La sortie d’un million de Tokens du long decode officiel n’est pas incluse dans le contrat d’interface actuel. Les deux prennent uniquement en charge le cache implicite, les Tokens de réflexion sont facturés au prix de sortie ; les règles de tarification préparées utilisent le même prix unitaire des Tokens d’entrée pour chaque modalité d’entrée, les accès au cache étant facturés au prix unitaire de lecture du cache, voir la page de tarification actuelle pour les détails.

### Réflexion interne et résumé de réflexion

La réflexion interne du modèle et le renvoi d’un résumé de réflexion à l’appelant sont deux paramètres indépendants :

- `thinkingBudget` ou `thinkingLevel` contrôle le budget ou la profondeur de réflexion interne du modèle, les champs et valeurs pris en charge dépendent du modèle.
- `includeThoughts` contrôle si un résumé de réflexion est renvoyé, la valeur par défaut est `false`. Lorsque ce champ est omis ou que `false` est transmis, ni les réponses JSON ordinaires ni les réponses SSE en streaming ne renvoient de texte marqué par `thought: true` ; ces textes ne sont conservés que lorsque la valeur booléenne `true` est explicitement transmise.

Lorsque la requête ne définit pas `includeThoughts`, l’interface transmet par défaut `false` aux modèles de génération qui prennent en charge la configuration de réflexion, afin d’éviter de demander des résumés inutiles ; les valeurs, budgets et niveaux de réflexion explicitement transmis par le client sont conservés. Le champ n’est pas automatiquement ajouté au modèle `gemini-2.5-flash-image`, connu pour ne pas prendre en charge la configuration de réflexion, et aucune configuration de génération n’est ajoutée aux requêtes `countTokens`.

Désactiver le résumé ne signifie pas désactiver la réflexion interne, et ne garantit pas la réduction des tokens de réflexion interne. Si la réponse contient encore du texte de réflexion non demandé, les sorties JSON ordinaires et SSE le filtreront davantage, tout en conservant la réponse normale, les signatures et l’utilisation réelle.

Lorsqu’il est nécessaire de consulter les résumés, activez-les explicitement de la façon suivante. Si le modèle ne génère pas de résumé utilisable, il est possible qu’il n’y ait aucun texte de réflexion même s’il est activé :

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` est un état chiffré nécessaire pour les tours suivants, ce n’est pas le texte du résumé de réflexion et il n’est pas contrôlé par l’interrupteur `includeThoughts`. La signature peut se trouver sur une réponse normale, un appel de fonction ou un Part de texte vide ; lors du filtrage du texte de réflexion, la signature et les autres champs du même Part sont conservés, il peut donc encore y avoir dans la réponse des Part ne contenant qu’une signature et dont le texte est vide. Lors de la maintenance manuelle de l’historique sur plusieurs tours, l’ordre de ces Part et la position des signatures doivent être conservés, ne déplacez pas les signatures et ne les fusionnez pas.

`usageMetadata` et `usage` continuent d’enregistrer l’utilisation réelle. Masquer les résumés ne remet pas `thoughtsTokenCount` à zéro, la facturation reste calculée selon l’utilisation réelle et les règles tarifaires actuelles.

Consultez les [explications officielles de Google sur la réflexion et les résumés de réflexion](https://firebase.google.com/docs/ai-logic/thinking) et les [règles de signature de réflexion](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

### Appel de fonction

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "北京现在的天气怎么样？"}]
    }
  ],
  "tools": [
    {
      "functionDeclarations": [
        {
          "name": "get_weather",
          "description": "获取指定城市的天气信息",
          "parameters": {
            "type": "object",
            "properties": {
              "city": {
                "type": "string",
                "description": "城市名称"
              }
            },
            "required": ["city"]
          }
        }
      ]
    }
  ]
}
```


## Paramètres de sécurité

Le filtrage du contenu peut être contrôlé via `safetySettings` :

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Gestion des erreurs

| Code d’état HTTP | Signification             |
| -------- | -------------- |
| 400      | Paramètres de requête non valides         |
| 401      | Échec de l’authentification, veuillez vérifier le Token |
| 403      | Contenu bloqué par le filtre de sécurité     |
| 429      | Requêtes trop fréquentes         |
| 500      | Erreur interne du serveur        |
