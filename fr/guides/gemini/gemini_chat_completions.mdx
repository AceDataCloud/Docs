Google Gemini est un système de conversation IA très puissant : il suffit de saisir un prompt pour générer des réponses fluides et naturelles en quelques secondes. Gemini peut fournir une assistance intelligente impressionnante, améliorant considérablement l’efficacité et la créativité humaines.

Ce document présente principalement le processus d’utilisation des opérations de l’API Gemini Chat Completion, grâce à laquelle nous pouvons facilement utiliser la fonctionnalité de conversation officielle de Gemini.

## Processus de demande

Pour utiliser l’API Gemini Chat Completion, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token, à conserver pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir à en demander un séparément pour chaque service.** Lors de votre première demande, un quota gratuit vous sera offert pour une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger votre solde universel dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Gemini Chat Completion API →](https://platform.acedata.cloud/documents/gemini-chat-completions)

## Utilisation de base

Vous pouvez ensuite remplir le contenu correspondant dans l’interface, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/f6ksts.png" width="400" className="m-auto" /></p>

Lors de la première utilisation de cette interface, nous devons remplir au moins trois éléments : le premier est `authorization`, qu’il suffit de sélectionner directement dans la liste déroulante. Un autre paramètre est `model`, `model` correspond à la catégorie de modèle du site officiel Gemini que nous choisissons d’utiliser ; les modèles disponibles sont déterminés par l’énumération `model` dans la documentation de l’interface. Le dernier paramètre est `messages`, `messages` est le tableau de prompts que nous saisissons ; c’est un tableau, ce qui signifie que plusieurs prompts peuvent être envoyés simultanément. Chaque prompt contient `role` et `content`, où `role` indique le rôle de l’utilisateur posant la question ; nous proposons trois identités : `user`, `assistant`, `system`. L’autre champ, `content`, correspond au contenu spécifique de notre question.

En même temps, vous pouvez remarquer que le code d’appel correspondant est généré à droite ; vous pouvez copier le code et l’exécuter directement, ou cliquer directement sur le bouton « Try » pour effectuer un test.

<p><img src="https://cdn.acedata.cloud/a3mdgy.png" width="400" className="m-auto" /></p>

> **Conseil** : les modèles flash de la série `gemini-3.x` sont des modèles de raisonnement et consomment d’abord des reasoning tokens ; veuillez définir `max_tokens` à plus de 512, sinon seul un contenu vide peut être renvoyé. `gemini-3.8-flash` est actuellement le modèle Flash recommandé ; il prend en charge jusqu’à 1 million de Token de contexte, l’entrée d’images, l’appel d’outils et les réponses en streaming ; il est actuellement appelé via l’interface Chat Completions.

`gemini-4-argon` peut également être utilisé pour Chat Completions et prend en charge les réponses textuelles ordinaires et en streaming. Il peut consacrer une partie du budget de sortie au raisonnement ; pour les tâches complexes, veuillez réserver suffisamment d’espace pour `max_tokens` ; Google recommande au moins 32768 pour les tâches habituelles de ce modèle. Ne considérez pas cette interface comme équivalente à la fonctionnalité de sortie longue en arrière-plan de l’API Google Interactions.

## Compréhension d’images (entrée multimodale)

Gemini est un modèle multimodal natif, qui peut directement « voir les images ». Pour transmettre une image, remplacez le `content` d’un message, qui est une chaîne de caractères, par un **tableau de blocs de contenu**, et placez à la fois un bloc `text` et un bloc `image_url` dans le tableau — cela est entièrement cohérent avec OpenAI, ainsi qu’avec le format compatible OpenAI officiel de Gemini.

`image_url.url` prend en charge deux syntaxes :
- **URI `data:` en base64 (recommandé, le plus stable)** : le format est `data:<type de média>;base64,<données>`, par exemple `data:image/jpeg;base64,/9j/4AAQ...`. **Le type de média (MIME) est déjà indiqué dans le préfixe `data:`**, il n'est donc pas nécessaire et il n'existe pas de champ `media_type` distinct.
- **URL d'image publiquement accessible** : par exemple `https://cdn.acedata.cloud/4hfydw.jpg`.

Types d'images pris en charge : `png`, `jpeg`, `webp`, `heic`, `heif`.

Exemple de code d'appel Python (URI data base64) :

```python
import base64
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

# 把本地图片读成 base64 data URI
with open("image.jpg", "rb") as f:
    base64_image = base64.b64encode(f.read()).decode("utf-8")
data_uri = f"data:image/jpeg;base64,{base64_image}"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {
            "role": "user",
            "content": [
                {"type": "text", "text": "请用一句话描述这张图片。"},
                {"type": "image_url", "image_url": {"url": data_uri}}
            ]
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Vous pouvez également transmettre directement une URL d'image publiquement accessible :

```python
payload = {
    "model": "gemini-3.1-pro-preview",
    "messages": [
        {

```

> 💡 `image_url` accepte uniquement le champ `url` (dont la valeur peut être une URL d'image ou une URI `data:` en base64), ainsi que le champ facultatif `detail`. **Ne transmettez pas `media_type`** — il s'agit d'un champ d'image d'Anthropic Claude, qui ne fait pas partie du format `image_url` d'OpenAI / Gemini.

## Réponse en streaming

Cette interface prend également en charge les réponses en streaming, ce qui est très utile pour l'intégration web et permet à une page web d'afficher le texte caractère par caractère.

Si vous souhaitez retourner une réponse en streaming, vous pouvez modifier le paramètre `stream ` dans l'en-tête de la requête en le définissant sur `true`.

La modification est illustrée ci-dessous, mais le code d'appel doit être modifié en conséquence pour prendre en charge les réponses en streaming.

<p><img src="https://cdn.acedata.cloud/o2blmi.png" width="400" className="m-auto" /></p>

Après avoir modifié `stream` en `true`, l'API renverra les données JSON correspondantes ligne par ligne ; au niveau du code, nous devons effectuer les modifications correspondantes pour obtenir les résultats ligne par ligne.

Exemple de code d'appel Python :

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello,What model are you?"}],
    "stream": True,
    "stream_options": {"include_usage": True}
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

JavaScript est également pris en charge, par exemple, le code d’appel en flux pour Node.js est le suivant :

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "gemini-2.5-pro",
    messages: [{ role: "user", content: "Hello, what model are you?" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/gemini/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

## Dialogue à plusieurs tours

Si vous souhaitez intégrer la fonctionnalité de dialogue à plusieurs tours, vous devez envoyer plusieurs questions dans le champ `messages`. Un exemple spécifique de plusieurs questions est présenté dans l’image ci-dessous :

<p><img src="https://cdn.acedata.cloud/qvzu06.png" width="400" className="m-auto" /></p>

Exemple de code d’appel Python :

```python
import requests

url = "https://api.acedata.cloud/gemini/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gemini-2.5-pro",
    "messages": [{"role":"user","content":"Hello"},{"role":"assistant","content":"Hello there! How can I help you today?"},{"role":"user","content":"What model are you?"}]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Modèle multimodal Gemini-3.1

`gemini-3.1-pro-preview` est l’ID officiel actuel du modèle Gemini 3.1 Pro, prenant en charge les entrées multimodales telles que le texte, les images et les vidéos, et adapté aux tâches de raisonnement complexe, de codage et de compréhension.

Exemple de requête :

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
          "text": "图片的内容是什么？"
        },
        {
          "type": "image_url",
          "image_url": {
            "url": "https://cdn.acedata.cloud/qzx2z1.png"
          }
        }
      ]
    }
  ],
  "stream": false
}
```

Gemini 3.1 Pro prend également en charge la compréhension des vidéos :

```json
{
  "model": "gemini-3.1-pro-preview",
  "messages": [
    {
      "role": "user",
      "content": [
        {
          "type": "text",
```

Le format de retour est identique à celui de Gemini 3.0 Pro ; consultez les explications de la section sur le modèle multimodal Gemini-3.0 ci-dessus pour plus de détails.

## Gestion des erreurs

Lors de l’appel de l’API, si une erreur est rencontrée, l’API renverra le code d’erreur et les informations correspondants. Par exemple :

- `400 token_mismatched` : Mauvaise requête, possiblement due à des paramètres manquants ou non valides.
- `400 api_not_implemented` : Mauvaise requête, possiblement due à des paramètres manquants ou non valides.
- `401 invalid_token` : Non autorisé, jeton d’autorisation non valide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d’erreur
```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
