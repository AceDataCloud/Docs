La principale fonctionnalité de l'API Gemini Tasks est de permettre la consultation de l'état d'exécution d'une tâche en entrant l'ID de tâche généré par l'API Gemini Videos Generation.

Ce document détaillera les instructions d'intégration de l'API Gemini Tasks, vous aidant à intégrer facilement et à consulter l'état d'exécution des tâches de l'API Gemini Videos Generation.

## Processus de demande

Pour utiliser l'API Gemini Videos Generation, commencez par obtenir votre token API sur le [tableau de bord Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour le garder en réserve.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion vous invitant à vous inscrire et à vous connecter, après quoi vous serez automatiquement renvoyé à la page actuelle.

**Un seul token API suffit pour appeler tous les services de la plateforme, sans avoir besoin de demander un pour chaque service.** La première demande vous donnera un quota gratuit pour une expérience sans frais ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans le [tableau de bord](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [API Gemini Videos Generation →](https://platform.acedata.cloud/documents/gemini-videos)

## Exemple de demande

L'API Gemini Tasks peut être utilisée pour consulter les résultats de l'API Gemini Videos Generation.

### Configuration des en-têtes de demande et du corps de la demande

**En-têtes de demande** comprennent :

- `accept` : spécifie que la réponse doit être au format JSON, ici rempli avec `application/json`.
- `authorization` : la clé pour appeler l'API, que vous pouvez sélectionner directement après la demande.

**Corps de la demande** comprend :

- `id` : l'ID de la tâche à consulter.
- `action` : la manière d'opérer sur la tâche, pour une consultation unique, remplissez `retrieve`.

### Exemple de code CURL

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### Exemple de réponse

Après une demande réussie, l'API renverra les détails de la tâche ici. Le champ `request` est le corps de la demande lors du lancement de la tâche, le champ `response` est le corps de la réponse renvoyé après l'achèvement de la tâche, par exemple :

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "started_at": 1769262721.823,
  "finished_at": 1769262730.723,
  "elapsed": 8.9,
  "request": {
    "prompt": "Une prise de vue cinématographique d'un chaton poursuivant un papillon dans un jardin ensoleillé",
    "model": "omni-flash",
    "aspect_ratio": "16:9"
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "omni-flash:job_01k777hjrbfrgs2060q5zvf2a5",
        "video_url": "https://cdn.acedata.cloud/gemini/example-video.mp4",
        "state": "succeeded"
      }
    ]
  }
}
```

La description des champs est la suivante :

- `id` : l'ID de la tâche générée, utilisé pour identifier de manière unique cette tâche de génération.
- `request` : les informations de demande dans la tâche consultée.
- `response` : les informations de réponse dans la tâche consultée.
- `created_at` : date de création de la tâche, timestamp Unix (secondes, flottant).
- `started_at` : date de début d'exécution de la tâche, timestamp Unix (secondes, flottant).
- `finished_at` : date de fin de la tâche, timestamp Unix (secondes, flottant). Ce champ ne sera pas renvoyé si la tâche n'est pas terminée.
- `elapsed` : durée d'exécution de la tâche, en secondes (flottant, avec 3 décimales). Ce champ ne sera pas renvoyé si la tâche n'est pas terminée.

## Opération de requête en masse

Pour consulter les détails de plusieurs ID de tâches, définissez `action` sur `retrieve_batch` et passez un tableau d'ID de tâches via `ids` :

**Corps de la demande** comprend :

- `ids` : tableau des ID de tâches à consulter.
- `action` : la manière d'opérer sur la tâche, pour une consultation en masse, remplissez `retrieve_batch`.

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```
