L'API Gemini Tasks permet principalement de vérifier l'état d'exécution d'une tâche en utilisant l'ID de tâche généré par l'API Gemini Videos Generation.

Ce document décrit en détail la procédure d'intégration de l'API Gemini Tasks, afin de faciliter votre intégration et la consultation de l'état d'exécution des tâches via l'API Gemini Videos Generation.

## Processus de demande

Pour utiliser l'API Gemini Tasks, vous devez d'abord accéder à la page de demande [Gemini Videos Generation API](https://platform.acedata.cloud/documents/gemini-videos) pour demander le service correspondant, puis copier l'ID de tâche retourné par l'API Gemini Videos Generation.

Ensuite, rendez-vous sur la page [Gemini Tasks API](https://platform.acedata.cloud/documents/gemini-tasks) pour demander le service correspondant. Une fois sur la page, cliquez sur le bouton « Acquire » pour continuer.

Si vous n'êtes pas connecté ou inscrit, vous serez automatiquement redirigé vers la [page de connexion](https://platform.acedata.cloud) pour vous inscrire ou vous connecter. Après connexion ou inscription, vous serez ramené automatiquement à la page en cours.

Une première demande donne droit à un quota gratuit, permettant d'utiliser cette API gratuitement.

## Exemple de requête

L'API Gemini Tasks peut être utilisée pour consulter les résultats de l'API Gemini Videos Generation.

### Configuration des en-têtes et du corps de la requête

**En-têtes de la requête** comprennent :

- `accept` : spécifie le format de réponse JSON, ici `application/json`.
- `authorization` : clé API pour l'appel, à sélectionner dans le menu déroulant après demande.

**Corps de la requête** comprend :

- `id` : l'ID de la tâche à consulter.
- `action` : la méthode d'opération sur la tâche, pour une seule requête, remplir `retrieve`.

### Exemple de code CURL

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### Exemple de réponse

Après une requête réussie, l'API retourne les détails de la tâche. Le champ `request` correspond au corps de la requête lors du lancement, et `response` contient la réponse une fois la tâche terminée, par exemple :

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "request": {
    "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
    "model": "omni-flash",
    "aspect_ratio": "16:9"
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "omni-flash:job_01k777hjrbfrgs2060q5zvf2a5",
        "video_url": "https://cdn.acedata.cloud/gemini/example-video.mp4",
        "state": "succeeded"
      }
    ]
  }
}
```

Les champs sont expliqués comme suit :

- `id` : l'ID de la tâche générée, pour identifier de façon unique cette tâche.
- `request` : les informations de la requête lors de la consultation.
- `response` : les informations retournées lors de la consultation.

## Opération de requête en lot

Pour consulter plusieurs tâches en une seule requête, il faut définir `action` à `retrieve_batch` et transmettre un tableau d'ID dans `ids` :

**Corps de la requête** :

- `ids` : tableau d'ID de tâches à consulter.
- `action` : méthode d'opération, pour une requête en lot, remplir `retrieve_batch`.

```bash
curl -X POST 'https://api.acedata.cloud/gemini/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```
