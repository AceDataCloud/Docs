title: "Guide d’intégration de l’API de clonage vocal Suno"

SUNO nous permet de créer des personnages vocaux personnalisés à partir de n’importe quel fichier audio, afin de réaliser un clonage vocal pour la génération musicale. Contrairement à l’API Persona existante (qui utilise un `audio_id` généré par Suno), cette API accepte une `audio_url` publiquement accessible, c’est-à-dire votre propre enregistrement vocal. Ce document explique la méthode d’intégration de l’API de clonage vocal.

Sur la ligne de création prenant en charge la vérification de la disponibilité du timbre vocal, vous pouvez utiliser l’application d’origine et l’identité de l’appelant pour transmettre le `persona_id` dans le résultat de création à `POST /suno/availability`. Lorsque le compte associé est en ligne, `data.available=true` est renvoyé ; lorsqu’il est confirmé hors ligne, `data.available=false` est renvoyé. [Guide de vérification de la disponibilité du timbre vocal](https://platform.acedata.cloud/documents/suno-availability-integration)

## Première étape : créer un personnage vocal

Facturation : après la création réussie d’un personnage vocal, le coût standard de chaque requête est de **0.15 Credits**. Les remises de consommation applicables sont soumises à la facture réelle ; les requêtes échouées ne sont pas facturées.

Cette API comporte trois paramètres d’entrée : `audio_url` (obligatoire), qui est l’URL d’un fichier audio MP3 ou WAV publiquement accessible contenant une voix claire d’une seule personne ; `name` et `description` (facultatifs), qui correspondent au nom et à la description du personnage vocal.

> **Exigences relatives au fichier audio**
> - Le format audio doit être `WAV` ou `MP3`
> - La durée audio doit être comprise entre `10~240 secondes` ; il est recommandé d’utiliser un extrait vocal sec, propre et d’une seule personne de `30~60 secondes`
> - L’audio doit contenir une **voix parlée ou chantée claire et identifiable d’une seule personne**
> - Veuillez impérativement éviter les **bruits de fond, accompagnements, échos, réverbérations** ; les chansons complètes avec accompagnement ne passent généralement pas la vérification d’empreinte vocale
> - Ne pas inclure **plusieurs locuteurs** ou **plusieurs voix**
> - Les extraits au volume trop faible, à la voix peu claire ou trop bruités peuvent entraîner un **échec du clonage** ou un **résultat généré de moindre qualité**
> **Description des restrictions d’utilisation**
> - Les personnages vocaux créés par téléversement audio sont des **ressources privées**
> - Ce personnage vocal **ne prend pas en charge la réutilisation entre comptes**
> - Il est recommandé de l’utiliser dès que possible après sa création réussie ; une longue période sans utilisation peut entraîner une **expiration ou une indisponibilité**
> - Le `name` renvoyé est généré automatiquement par le système ; veuillez vous référer au `persona_id` renvoyé

> **Traiter les échecs selon l’indicateur explicite de nouvelle tentative**
> `retryable` dans l’objet d’erreur est un champ booléen facultatif. Lorsque `error.retryable` est `true`, cela indique que cet échec permet de soumettre à nouveau ultérieurement la même ressource avec les mêmes paramètres. Une surcharge de service explicitement non prise en charge ou certains échecs temporaires de vérification d’empreinte vocale peuvent comporter cet indicateur ; il est recommandé d’utiliser des intervalles de temporisation progressive et de limiter le nombre de tentatives.
> Lorsque `retryable` est `false` ou que le champ est absent, ne renvoyez pas automatiquement la requête uniquement sur la base du HTTP 500, de `busy` ou du texte d’erreur. Les problèmes de format, de durée, de clarté, d’enregistrements en double et de modération de contenu doivent d’abord être corrigés ; en cas de délai d’expiration de soumission, d’interruption de connexion ou de résultat de création incertain, il faut en priorité utiliser le `task_id` d’origine pour interroger la tâche, afin d’éviter de créer des timbres vocaux en double. Les requêtes échouées ne sont pas facturées, et les nouvelles tentatives réussies sont facturées selon les règles normales.

```bash
curl -X POST 'https://api.acedata.cloud/suno/voices' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3",
  "name": "My Voice",
  "description": "单人清晰人声示例"
}'
```

> Le `https://cdn.acedata.cloud/suno_demo.mp3` ci-dessus est un extrait d’exemple directement utilisable (MP3, 41 secondes, voix sèche d’une seule personne).
> Pour un exemple au format `WAV`, vous pouvez utiliser
> `https://cdn.acedata.cloud/uploads/82d23b97-ec1c-4b41-91b8-989fc51f8765` (WAV, 41 secondes, mono 44.1kHz).

Le résultat est le suivant :

```json
{
  "success": true,
  "task_id": "0fa609a6-c8d9-4bb5-8574-e4c93bb55d02",
  "data": {
    "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16",
    "name": "VOICE_20260803037676",
    "is_public": false
  }
}
```

On peut voir que le champ `persona_id` de `data` est l’ID du personnage vocal créé. Le champ `is_public` est toujours `false`, car les personnages vocaux créés par téléversement audio sont privés. Notez que le `name` renvoyé est généré automatiquement par le système ; utilisez ensuite `persona_id` pour référencer ce personnage vocal.

## Deuxième étape : utiliser le personnage vocal pour générer de la musique

Une fois l’ID du personnage vocal obtenu, nous pouvons utiliser l’[API Suno Audios Generation](https://platform.acedata.cloud/documents/suno-audios) pour générer de la musique. Définissez `action` sur `generate`, puis définissez `persona_id` sur l’ID du personnage vocal renvoyé ci-dessus ; les chansons générées utiliseront la voix clonée pour chanter.

> **Remarque :** Le clonage vocal prend uniquement en charge les modèles `chirp-v4-5` et supérieurs (tels que `chirp-v4-5`, `chirp-v5`, `chirp-v5-5`) et ne prend pas en charge `chirp-v4`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "chirp-v5-5",
  "prompt": "A warm synth-pop song about city nights",
  "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16"
}'
```

Le résultat est le suivant :

```json
{
  "success": true,
  "task_id": "53d8a334-a972-43c5-895e-60c4454e88d5",
  "data": [
    {
      "id": "16463960-077c-4700-bbb3-3c7897b943d3",
      "title": "Soft Neon on My Skin",
      "audio_url": "https://cdn.acedata.cloud/assets/examples/fish/5ade0339-5f11-487e-aacc-06a908271706-8e3fcb0e5547.mp3",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "model": "chirp-v5-5",
      "state": "succeeded",
      "prompt": "A warm synth-pop song about city nights",
      "duration": 156.28
    }
  ]
}
```

`persona_id` peut être utilisé pour la génération `generate`, ainsi que pour les reprises `cover` / `upload_cover`. Il n’est pas nécessaire de renseigner simultanément `vocal_gender` lors de la spécification de la voix ; la similarité vocale dépend toujours du matériel de référence et du résultat généré.

Les voix créées via cette interface sont des ressources privées. Avant de reprendre une chanson existante, appelez d’abord `/suno/upload`, en transmettant l’`audio_url` de la chanson originale et le `persona_id` de cette voix ; après un téléversement réussi, appelez `/suno/audios` avec le `data.audio_id` renvoyé et le même `persona_id` :
```json
{
  "action": "upload_cover",
  "model": "chirp-v6",
  "audio_id": "<与该声音关联上传后返回的 audio_id>",
  "persona_id": "<声音创建接口返回的 persona_id>",
  "custom": true,
  "instrumental": false,
  "lyric": "[Verse]\n填写要演唱的歌词",
  "async": true
}
```

La création de voix, le téléversement de la chanson originale et la reprise doivent utiliser le même canal de service. Veuillez ne pas réutiliser directement un ID de chanson précédent qui n’est pas associé à cette voix privée ; pour plus de détails, consultez [Suno téléverser un audio de référence](https://platform.acedata.cloud/documents/suno-upload).
