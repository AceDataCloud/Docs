Avec l’élargissement des applications de l’IA, divers programmes d’IA se sont progressivement généralisés. L’IA s’est progressivement intégrée à tous les aspects du travail et de la vie des gens. Et les secteurs impliqués par l’IA sont également de plus en plus nombreux, de l’écriture initiale aux domaines médical et éducatif, jusqu’à la musique actuelle.

Suno est une plateforme professionnelle de création de chansons et de musique par IA de haute qualité. Les utilisateurs n’ont qu’à saisir de simples mots d’invite textuels pour générer des chansons avec voix selon le genre, le style et les paroles. Ce générateur de musique par IA a été développé par des membres d’équipe issus d’entreprises technologiques renommées telles que Meta, TikTok et Kensho, avec pour objectif de ne nécessiter aucun instrument ni outil, afin que tout le monde puisse créer de merveilleuses musiques.

> Les limites `lyric` et `style` du tableau ci-dessus correspondent aux plafonds en mode personnalisé (`custom` est `true`). Le mode d’inspiration non personnalisé (`custom` est `false`) ne remplit que `prompt`, dont la limite de longueur est de 500 caractères (identique pour tous les modèles).

Suno prend désormais en charge `chirp-v6`, `chirp-v6-wild` et `chirp-v6-mini`. Il est recommandé d’utiliser `chirp-v6` ; les anciens noms de modèles restent compatibles.

Cependant, Suno ne fournit officiellement pas d’API. AceDataCloud fournit un ensemble d’API Suno, simulant l’intégration officielle de Suno, permettant de générer facilement et rapidement la musique souhaitée.

## Demande et utilisation

Pour utiliser Suno Audios Generation API, récupérez d’abord votre API Token dans la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications), et conservez-le pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir besoin d’en demander un séparément pour chaque service.** La première demande offre un quota gratuit permettant une expérience sans frais ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Utilisation de base

Pour les chansons auxquelles vous pensez, vous pouvez saisir librement un texte, par exemple si je souhaite générer une chanson sur Noël, je peux saisir `a song for Christmas`, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Vous pouvez voir qu’ici nous avons défini les Request Headers, comprenant :

- `accept`：le format de résultat de réponse que vous souhaitez recevoir ; ici, remplissez `application/json`, c’est-à-dire le format JSON.
- `authorization`：la clé pour appeler l’API, qui peut être directement sélectionnée dans la liste déroulante après la demande.

Nous avons également défini le Request Body, comprenant :
- `action`：l’action de cette tâche de génération musicale, par défaut `generate`, comprend principalement : `extend`, `upload_extend`, `cover`, `upload_cover`, `replace_section`, `replace_section`, `concat`, `stems`, `all_stems`, `remaster`.
- `prompt`：le prompt du mode inspiration officiel de Suno (effectif lorsque `custom` est `false`), 500 caractères maximum.
- `model`：le modèle de cette tâche de génération musicale. La série v6 comprend `chirp-v6`, `chirp-v6-wild` et `chirp-v6-mini` ; les anciens noms de modèles restent compatibles.
- `lyric`：le contenu des paroles du mode personnalisé officiel de Suno. Maximum 3000 caractères pour `chirp-v3-5` et `chirp-v4` ; maximum 5000 caractères pour `chirp-v4-5` et versions ultérieures (y compris `chirp-v5`, `chirp-v5-5`).
- `custom`：indique si le mode personnalisé est utilisé, par défaut : `false`.
- `instrumental`：l’option de musique instrumentale du mode inspiration officiel de Suno.
- `title`：le titre musical du mode personnalisé officiel de Suno. Maximum 80 caractères pour `chirp-v3-5` et `chirp-v4` ; maximum 100 caractères pour `chirp-v4-5` et versions ultérieures.
- `style`：le style musical du mode personnalisé officiel de Suno. Maximum 200 caractères pour `chirp-v3-5` et `chirp-v4` ; maximum 1000 caractères pour `chirp-v4-5` et versions ultérieures (y compris `chirp-v5`, `chirp-v5-5`).
- `negative_tags`：les styles ou genres musicaux à exclure des résultats générés en mode personnalisé (`custom` est `true`).
- `audio_weight`：la proportion de l’audio de référence importé, plage de 0 à 1 ; plus la valeur est élevée, plus le résultat dépend de l’audio de référence.
- `audio_id`：l’ID de la musique de référence.
- `overpainting_start`/`overpainting_end`：les temps de début et de fin, en secondes, pour ajouter des voix à une musique instrumentale existante.
- `underpainting_start`/`underpainting_end`：les temps de début et de fin, en secondes, pour ajouter un accompagnement à un chant a cappella.
- `persona_id`：l’ID de chanson de l’artiste.
- `continue_at`：la limite de continuation, en secondes. Par exemple, 213.5 indique que les segments suivants sont générés à partir de 3 minutes et 33,5 secondes. `lyric` et `style` guident uniquement le nouveau contenu après la limite et ne remplacent pas les paroles ou le chant avant la limite dans l’audio source.
- `style_influence`：le paramètre avancé « Style Influence » en mode personnalisé, plage de 0 à 1 ; plus la valeur est élevée, plus le résultat correspond au style sélectionné.
- `replace_section_end`：le temps final du segment à remplacer.
- `replace_section_start`：le temps de début du segment à remplacer.
- `vocal_gender`：contrôle la préférence entre voix féminine et masculine, voix féminine `f`, voix masculine `m`, effectif pour les modèles 4.5 et ultérieurs ; il s’agit d’une préférence et le respect strict n’est pas garanti.
- `weirdness`：le paramètre avancé « Weirdness » en mode personnalisé, plage de 0 à 1 ; plus la valeur est élevée, plus le résultat est créatif et expérimental.
- `duration`：la durée souhaitée de la chanson, en secondes, doit être un entier, comprise entre 10 et 360. Ce paramètre est utilisé pour la génération de chansons en mode personnalisé (`custom` est `true`). C’est une indication de préférence et non une contrainte stricte : le modèle s’y référera, mais ne garantit pas de l’atteindre ; la durée réelle du résultat final dépend du champ `duration` dans la réponse et est généralement plus courte que la valeur souhaitée.
- `lyric_prompt`：le prompt pour générer les paroles, effectif si et seulement si `custom` est `true` et que `lyric` n’est pas fourni.
- `callback_url`：l’URL à laquelle les résultats doivent être renvoyés par callback.
- `async`：facultatif, lorsque défini sur `true`, l’interface renvoie immédiatement `task_id`, sans nécessiter de fournir `callback_url`, puis le résultat est obtenu en effectuant un polling via l’interface de requête de tâche correspondante.

## Fonction de génération personnalisée du style de chanteur

à la fin, vous obtenez la nécessité de définir cette chanson comme style de chanteur, puis vous devez accéder à [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) afin de générer un paramètre d'identifiant de style de chanteur `persona_id` selon l'ID de musique `audio_id` généré officiellement.
```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Fonctionnalité de continuation de génération

Si vous souhaitez continuer à générer une chanson Suno déjà générée, vous pouvez définir le paramètre `action` sur `extend`, et saisir l'ID de la chanson à continuer de générer. L'obtention de l'ID de la chanson se fait selon l'utilisation de base. D'après ce qui précède, vous pouvez voir qu'à ce moment-là, l'ID de la chanson est :

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Remarque : ici, l'`id` dans les paroles est l'ID de la chanson générée. Si vous ne savez pas comment générer une chanson, vous pouvez vous référer à l'utilisation de base ci-dessus pour générer une chanson.

Si vous souhaitez continuer à générer une chanson que vous avez vous-même téléversée, vous pouvez définir le paramètre `action` sur `upload_extend`, et saisir l'ID de la chanson téléversée personnalisée à continuer de générer. L'obtention de l'ID de la chanson se fait à l'aide de [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), comme indiqué dans l'image ci-dessous :

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Ensuite, vous devez obligatoirement remplir les paroles du segment à prolonger, et vous pouvez spécifier le style :

- lyric : utilisé uniquement pour guider les paroles du nouveau segment généré après `continue_at`, et ne remplacera pas les paroles avant ce point temporel dans l'audio source.
- custom : renseignez `true`, ce qui représente une génération personnalisée. La valeur par défaut de ce paramètre est false, ce qui représente une génération à l'aide de `prompt`.
- style : le style musical du segment à prolonger, facultatif.
- continue_at : la limite de continuation, en secondes. Par exemple, 213.5 indique que le segment suivant est généré à partir de 3 minutes et 33,5 secondes.

> `extend` est utilisé pour poursuivre la création à partir d'une chanson existante, et non pour remplacer les paroles de toute la chanson. Si vous souhaitez utiliser de nouvelles paroles pour toute la chanson depuis le début, veuillez utiliser `generate` pour la générer à nouveau ; si vous souhaitez réinterpréter une chanson existante en vous y référant, vous pouvez utiliser `cover`. Lors de la transmission de nouvelles paroles complètes, les paroles originales avant `continue_at` ne seront toujours pas remplacées.

Après avoir rempli les champs, le code suivant est généré automatiquement :

Ce qui est conservé ci-dessous est un instantané d'un appel historique réel, dans lequel `continue_at` est de 2 secondes ; par conséquent, seules les 2 premières secondes appartiennent au contenu original avant la limite de continuation. Lors d'une continuation réelle près de la fin de la chanson, cette valeur doit être définie sur le nombre de secondes auquel vous souhaitez commencer la continuation, et seules les nouvelles paroles à chanter après la limite doivent être fournies dans `lyric`.

Le code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/suno/audios"
```

- action : le contenu est `concat`.
- audio_id : l'ID du dernier segment de continuation.

## Reprise musicale

Après avoir continué à générer une chanson à partir d'une chanson existante, le style de la chanson renvoyée peut ne pas être très approprié. S'il faut faire une reprise de la chanson précédemment générée (la musique téléversée personnalisée est également prise en charge), il faut utiliser la méthode de reprise musicale, qui permet de spécifier le contenu suivant :

- action : le contenu est `cover`, lorsqu'il s'agit d'effectuer une opération de reprise sur de la musique téléversée personnalisée, le contenu doit obligatoirement être spécifié comme : `upload_cover`.
- audio_id : l'ID de la chanson générée précédemment.

Par exemple, si l'ID de la chanson générée précédemment est : 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, les paramètres peuvent alors être définis comme suit :

```json
{

}
```

## Remplacer un segment

Lorsqu'une seconde création nécessite une opération distincte de remplacement d'un segment de chanson après la génération d'une chanson, il est possible d'effectuer une opération de remplacement sur un certain segment de la chanson.

> ⚠️ **Remarque** : `replace_section_result_mode` est par défaut défini sur `full_song` : le système concatène respectivement 2 nouveaux candidats générés et renvoie 2 chansons complètes. Si seuls les candidats de segments de remplacement non encore concaténés sont nécessaires, définissez explicitement cette valeur sur `candidates`, puis sélectionnez un candidat pour appeler [Concaténation musicale](#音乐拼接).

Les paramètres sont décrits comme suit :

- action : le contenu est `replace_section`.
- audio_id : l'ID de la chanson originale (la chanson source à remplacer).
- model : le modèle de génération de chansons.
- lyric : les paroles complètes après remplacement (incluant le segment remplacé et son contexte, cohérent avec le contenu de `prompt`).
- prompt : les nouvelles paroles du segment à remplacer.
- style : le style de la chanson, facultatif.
- replace_section_start : l'heure de début du segment remplacé dans la chanson originale (secondes).
- replace_section_end : l'heure de fin du segment remplacé dans la chanson originale (secondes).
- replace_section_result_mode : le mode de retour, par défaut `full_song`. `full_song` concatène respectivement 2 candidats et renvoie 2 chansons complètes ; `candidates` renvoie 2 segments candidats non encore concaténés.

## Contrôler la durée de la chanson

Par défaut, la durée de la chanson générée est déterminée par le modèle lui-même, généralement entre 30 secondes et 4 minutes. Si vous avez besoin d’un produit fini plus long ou plus court, vous pouvez spécifier la durée souhaitée via le paramètre `duration`, l’unité est la seconde, et la valeur est un entier compris entre 10 et 360.

Ce paramètre est utilisé pour la génération de chansons en mode personnalisé (`custom` étant `true`). Il faut particulièrement préciser que `duration` est une **indication de tendance, et non une contrainte stricte** : le modèle se référera à cette valeur lors de la création, mais il n’est pas garanti qu’elle soit atteinte ; lors des tests, la durée réelle est généralement nettement plus courte que la valeur attendue, et les durées des deux chansons renvoyées par une même requête peuvent également différer de plusieurs fois. Même pour des requêtes totalement identiques, les durées obtenues après plusieurs soumissions peuvent également présenter des différences importantes. Ne l’utilisez donc pas comme un contrôle précis de la durée ; si votre activité nécessite une durée fixe, veuillez découper ou réessayer vous-même après avoir obtenu le produit fini.

Le code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Il convient de noter que le `duration` dans la requête est la **durée souhaitée**, tandis que le champ `duration` de chaque chanson dans les `data` de la réponse est la **durée réelle** de cette chanson. Les deux portent le même nom, mais leur signification est différente ; la durée réelle n’est pas garantie d’être égale à la valeur souhaitée. La longueur des paroles est l’un des principaux facteurs qui influencent la durée du produit fini ; si vous avez besoin d’un produit fini plus long, il est recommandé de fournir simultanément des paroles plus complètes.

L’interface ne procède pas à une validation supplémentaire de `duration`, le paramètre sera transmis tel quel au modèle. Si une valeur non prise en charge par le mode ou le modèle actuel est transmise, cela peut se manifester par l’ignorance de cette valeur ; il est recommandé de confirmer l’effet avec une requête avant de l’utiliser en lot.

## Fonctionnalité Add Insterumental

En août 2025, Suno a lancé la fonctionnalité Add Insterumental. Il faut d’abord téléverser une chanson a cappella sans accompagnement afin que Suno puisse vous aider à l’accompagner. Vous pouvez d’abord aller sur [Suno Upload API](https://platform.acedata.cloud/documents/suno-upload) pour téléverser une chanson a cappella sans accompagnement ; les opérations correspondantes sont présentées dans l’image ci-dessous :

Enfin, un `audio_id` a été obtenu : 92254cab-3372-4d9e-bce9-cdcfdbc39070, puis nous devons également renseigner les paramètres suivants :
- action : le contenu est `underpainting`.
- underpainting_start : l’heure de début pour ajouter un accompagnement à la chanson téléchargée, la valeur par défaut est 0.
- underpainting_end : l’heure de fin pour ajouter un accompagnement à la chanson téléchargée, elle doit être inférieure à la durée totale de la chanson.
- audio_id : l’ID de la chanson a cappella sans voix off téléchargée.
- style : le style de l’accompagnement, il est préférable de ne pas utiliser de paroles puisqu’il s’agit après tout d’une voix off.

```python
import requests

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

    "action": "underpainting",
```

## Fonction de création inspirée Inspo

La fonction de création inspirée Inspo peut générer de nouvelles musiques à partir de 1 à 4 extraits audio de référence complets, et prend en charge le glisser-déposer ou le téléversement d’audio comme source d’inspiration. L’API utilise l’action `inspo` existante : le client fournit des URL audio accessibles publiquement, et le service effectue automatiquement la préparation des audios de référence et la création, sans que le client ait besoin de lire séparément les paroles, le style ou la durée avant de composer la requête. Elle diffère de l’échantillonnage par intervalle ci-dessus, et diffère également du Cover qui reproduit le style de la chanson originale. Les paramètres suivants doivent être renseignés lors de son utilisation :

- action : le contenu est `inspo`.
- audio_urls : liste des URL des audios de référence, il faut fournir 1 à 4 adresses audio accessibles publiquement.
- model : le modèle utilisé, `chirp-v6` est recommandé.
- prompt : paroles ou invite de création (facultatif).

> Remarque : les audios de référence doivent être des fichiers audio accessibles publiquement. Si l’audio de référence correspond exactement à un enregistrement connu dans la bibliothèque musicale de la plateforme, Suno peut refuser la génération en raison de la vérification des droits d’auteur ; il est recommandé d’utiliser vos propres audios ou des audios générés par Suno comme sources d’inspiration.

Le code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```


## Rappel asynchrone

Étant donné que Suno met relativement longtemps à générer de la musique, environ 1 à 2 minutes, si l’API ne répond pas pendant une longue période, la requête HTTP maintiendra constamment la connexion, ce qui entraînera une consommation supplémentaire de ressources système. Cette API fournit donc également la prise en charge des rappels asynchrones.

Le processus global est le suivant : lorsque le client initie une requête, il spécifie en plus un champ `callback_url`. Après que le client a initié une requête API, l’API renvoie immédiatement un résultat, comprenant les informations d’un champ `task_id`, qui représente l’ID de la tâche actuelle. Une fois la tâche terminée, le résultat de la génération musicale sera envoyé sous la forme d’un POST JSON à l’adresse `callback_url` spécifiée par le client, contenant également le champ `task_id`, de sorte que les résultats de la tâche peuvent être associés via l’ID.

Nous allons maintenant comprendre plus précisément comment procéder à travers un exemple.

Tout d’abord, le rappel Webhook est un service capable de recevoir des requêtes HTTP ; le développeur doit le remplacer par l’URL de son propre serveur HTTP. Afin de faciliter la démonstration, nous utilisons ici un site d’exemple Webhook public https://webhook.site/ ; ouvrez ce site pour obtenir une URL Webhook, comme illustré ci-dessous :

![](https://cdn.acedata.cloud/fwfqin.png)

Copiez cette URL, elle peut alors être utilisée comme Webhook ; l’exemple ici est https://webhook.site/03e60575-3d96-4132-b681-b713d78116e2。

Ensuite, nous pouvons définir le champ `callback_url` sur l’URL Webhook ci-dessus, tout en renseignant `prompt`, comme illustré ci-dessous :

![](https://cdn.acedata.cloud/x8xql1.png)

Cliquez sur exécuter, vous constaterez qu’un résultat est immédiatement obtenu, comme suit :

```
}
```

En général, les restrictions de `style` pour `chirp-v3-5`/`chirp-v4` sont plus faibles (200), tandis que `chirp-v4-5` et les versions ultérieures prennent généralement en charge jusqu'à 1000 ; lors de l'utilisation d'un ancien fournisseur en amont, des messages de compatibilité tels que `Tags too long.` ou `style must be less than or equal 120` peuvent apparaître.
