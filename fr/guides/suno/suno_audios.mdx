Avec l’élargissement des applications de l’IA, divers programmes d’IA se sont progressivement généralisés. L’IA s’est progressivement intégrée à tous les aspects du travail et de la vie des personnes. Les secteurs concernés par l’IA sont également de plus en plus nombreux, de l’écriture initiale, aux soins médicaux et à l’éducation, jusqu’à la musique aujourd’hui.

Suno est une plateforme professionnelle et de haute qualité de création de chansons et de musique par IA. Les utilisateurs n’ont qu’à saisir de simples mots d’invite textuels pour générer des chansons avec voix selon le genre, le style et les paroles. Ce générateur de musique par IA est développé par des membres d’équipe issus d’entreprises technologiques renommées telles que Meta, TikTok et Kensho, avec pour objectif de permettre à tout le monde de créer de magnifiques musiques sans nécessiter aucun instrument.

Le mode d’inspiration non personnalisé (lorsque `custom` est défini sur `false`) ne renseigne que `prompt`, dont la longueur maximale est de 500 caractères (identique pour tous les modèles).

Suno prend désormais en charge `chirp-v6`, `chirp-v6-wild` et `chirp-v6-mini`. Il est recommandé d’utiliser `chirp-v6` ; les anciens noms de modèles restent compatibles.

Cependant, Suno ne fournit officiellement pas d’API. AceDataCloud fournit un ensemble d’API Suno qui simule l’intégration officielle de Suno, permettant de générer facilement et rapidement la musique souhaitée.

## Demande et utilisation

Pour utiliser Suno Audios Generation API, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) afin d’obtenir votre API Token et conservez-le pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter. Une fois terminé, vous retournerez automatiquement à la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, il n’est pas nécessaire d’en demander un séparément pour chaque service.** La première demande offre un quota gratuit permettant une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger le solde universel dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Utilisation de base

Quelle chanson souhaitez-vous ? Vous pouvez saisir librement un texte, par exemple si je souhaite générer une chanson sur Noël, je peux saisir `a song for Christmas`, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Vous pouvez voir que nous avons ici configuré les Request Headers, notamment :

- `accept` : le format de résultat de réponse que vous souhaitez recevoir ; renseignez ici `application/json`, c’est-à-dire le format JSON.
- `authorization` : la clé pour appeler l’API, qui peut être sélectionnée directement dans la liste déroulante après la demande.

Nous avons également configuré le Request Body, notamment :
- `action` : type de tâche audio, par défaut `generate`. Prend en charge des opérations telles que la génération, la continuation, la reprise, l’assemblage, la séparation en pistes, l’ajout de piste audio, l’extraction de pistes audio spécifiées, la génération d’effets sonores et l’ajustement de la vitesse, toutes appelées via `POST /suno/audios`.
- `prompt` : prompt du mode inspiration officiel de Suno (effectif lorsque `custom` est `false`), maximum 500 caractères.
- `model` : modèle de cette tâche de génération musicale. La série v6 inclut `chirp-v6`, `chirp-v6-wild` et `chirp-v6-mini` ; les anciens noms de modèles restent compatibles.
- `max_mode` : mode de génération amélioré. `generate` n’est activé que lorsque `custom` et `max_mode` sont tous deux définis sur `true`, avec un coût de 1.12 Credits ; `add_stem` peut être activé directement, avec un coût de 1.344 Credits. Lorsqu’il est désactivé ou omis, les coûts sont respectivement de 0.56 et 0.672 Credits.
- `variety` : intensité de diversité des résultats générés, options disponibles : `off`, `normal`, `high`, `extra`, `max`. Utilisé uniquement pour `generate` et `add_stem`, son envoi pour d’autres action renverra 400.
- `lyric` : contenu des paroles du mode personnalisé officiel de Suno. Maximum 3000 caractères pour `chirp-v3-5` et `chirp-v4` ; maximum 5000 caractères pour `chirp-v4-5` et versions ultérieures (y compris `chirp-v5`, `chirp-v5-5`).
- `custom` : indique s’il faut utiliser le mode personnalisé, par défaut : `false`.
- `instrumental` : option de musique instrumentale du mode inspiration officiel de Suno.
- `title` : titre musical du mode personnalisé officiel de Suno. Maximum 80 caractères pour `chirp-v3-5`, `chirp-v4` ; maximum 100 caractères pour `chirp-v4-5` et versions ultérieures.
- `style` : style musical du mode personnalisé officiel de Suno. Maximum 200 caractères pour `chirp-v3-5` et `chirp-v4` ; maximum 1000 caractères pour `chirp-v4-5` et versions ultérieures (y compris `chirp-v5`, `chirp-v5-5`).
- `negative_tags` : styles ou genres musicaux à exclure des résultats générés en mode personnalisé (`custom` est `true`).
- `audio_weight` : poids d’influence des caractéristiques audio ou vocales, plage 0-1, `0` est également une valeur valide. Peut être utilisé pour des opérations telles que la génération, la continuation, la reprise, l’ajout de piste audio et la cohérence vocale ; sans audio de référence ou caractéristiques vocales, le modèle peut atténuer ou ignorer cette valeur.
- `audio_id` : ID de la musique de référence.
- `overpainting_start`/`overpainting_end` : heures de début et de fin, en secondes, pour ajouter des voix à une musique instrumentale existante.
- `underpainting_start`/`underpainting_end` : heures de début et de fin, en secondes, pour ajouter un accompagnement à un chant a cappella.
- `persona_id` : ID de chanson de l’artiste.
- `continue_at` : limite de continuation, en secondes. Par exemple, 213.5 signifie générer le segment suivant à partir de 3 minutes et 33.5 secondes. `lyric` et `style` guident uniquement le nouveau contenu après la limite et ne remplacent pas les paroles ou le chant avant la limite dans l’audio source.
- `style_influence` : influence du style en mode personnalisé, plage 0-1 ; plus elle est élevée, plus le résultat correspond généralement au style sélectionné ; `0` est transmis comme valeur valide.
- `replace_section_end` : heure finale du segment à remplacer.
- `replace_section_start` : heure de début du segment à remplacer.
- `vocal_gender` : contrôle la préférence pour les voix féminines et masculines, voix féminine `f`, voix masculine `m`, effectif pour les modèles 4.5 et ultérieurs ; il s’agit d’une préférence, dont le respect strict n’est pas garanti.
- `weirdness` : degré d’étrangeté en mode personnalisé, plage 0-1 ; plus il est élevé, plus le résultat est généralement créatif et expérimental ; `0` est transmis comme valeur valide.
- `duration` : durée souhaitée de la chanson, en secondes, doit être un entier, plage de 10 à 360. Ce paramètre est utilisé pour la génération de chansons en mode personnalisé (`custom` est `true`). Il s’agit d’une indication d’orientation plutôt que d’une contrainte stricte : le modèle s’y référera, mais ne garantit pas de l’atteindre ; la durée réelle du produit final dépend du champ `duration` dans la réponse et est généralement inférieure à la valeur souhaitée.

### Portée d’application des paramètres avancés

| Paramètre                | Valeurs                                          | action prises en charge                              | Description                              |
| ----------------- | ------------------------------------------- | --------------------------------------- | ------------------------------- |
| `weirdness`       | 0-1                                         | Facultatif                                      | Ajuste l’expérimentation, `0` est une valeur valide ; l’effet dépend de l’opération, du mode et du modèle    |
| `style_influence` | 0-1                                         | Facultatif                                      | Ajuste la tendance à suivre le style, `0` est une valeur valide ; l’effet dépend de l’opération, du mode et du modèle |
| `audio_weight`    | 0-1                                         | Facultatif                                      | Ajuste l’influence des caractéristiques audio ou vocales ; peut être ignoré par le modèle en l’absence d’informations de référence      |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`, `add_stem`                   | Ajuste la diversité stylistique entre les résultats                     |
| `max_mode`        | boolean                                     | `generate` (requiert `custom=true`), `add_stem` | Améliore la cohérence et est facturé selon le mode amélioré                   |
| `vocal_gender`    | `f` / `m`                                   | Opérations de génération prenant en charge le contrôle vocal                             | Préférence, respect strict non garanti                     |
| `duration`        | Entier 10-360                                   | Facultatif                                      | Durée souhaitée ; certaines opérations, certains modes ou modèles peuvent l’ignorer             |

La plateforme vérifie les types de paramètres et les plages de valeurs, mais ne rejettera pas ces options de réglage facultatives uniquement parce que l’action est différente ; les effets spécifiques dépendent de l’opération, du mode et du modèle.

- `lyric_prompt` : prompt pour générer les paroles, effectif si et seulement si `custom` est `true` et que `lyric` n’est pas fourni.
- `callback_url` : URL à laquelle les résultats doivent être rappelés.
- `async` : facultatif, lorsque défini sur `true`, l’interface renvoie immédiatement `task_id`, sans nécessiter de fournir `callback_url`, puis récupère les résultats en interrogeant périodiquement l’interface de requête de tâche correspondante.

- style : style de la chanson, facultatif.

## Fonction de génération personnalisée de style de chanteur
Si vous souhaitez utiliser un style de chanteur pour générer une chanson, générez d'abord une chanson via l'utilisation de base ci-dessus,  
puis vous devez définir cette chanson comme style de chanteur. Ensuite, vous devez accéder à [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) pour générer un paramètre d'identifiant de style de chanteur `persona_id` à partir de l'ID de musique `audio_id` généré officiellement. Les paramètres spécifiques sont indiqués dans l'image ci-dessous :

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Une fois le remplissage terminé, le code suivant est généré automatiquement :

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

Le code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Ensuite, vous pouvez définir le paramètre `action` sur `artist_consistency` (s'il s'agit du nouveau style de chanteur Persona-v2-vox, `action` doit être défini sur `artist_consistency_vox`), puis saisir l'ID de la chanson à continuer de générer et l'ID du style de chanteur. ## Fonctionnalité de prolongation de génération

Si vous souhaitez prolonger la génération d'une chanson Suno déjà générée, vous pouvez définir le paramètre `action` sur `extend`, puis saisir l'ID de la chanson à continuer de générer. L'obtention de l'ID de la chanson se fait selon l'utilisation de base ; d'après ce qui précède, vous pouvez voir que l'ID de la chanson est alors :

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Remarque : ici, l'`id` dans les paroles est l'ID de la chanson générée. Si vous ne savez pas comment générer une chanson, vous pouvez vous référer à l'utilisation de base ci-dessus pour générer une chanson.

Si vous souhaitez prolonger la génération d'une chanson que vous avez vous-même téléversée, vous pouvez définir le paramètre `action` sur `upload_extend`, puis saisir l'ID de la chanson téléversée personnalisée à continuer de générer. L'obtention de l'ID de la chanson se fait en utilisant [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), comme indiqué dans l'image ci-dessous :

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Ensuite, vous devez obligatoirement renseigner les paroles du segment à prolonger, et vous pouvez spécifier le style :

- lyric : utilisé uniquement pour guider les paroles du nouveau segment généré après `continue_at`, et ne remplacera pas les paroles avant ce point temporel dans l'audio source.
- custom : renseignez `true`, ce qui représente une génération personnalisée ; ce paramètre est défini par défaut sur false, ce qui représente une génération à l'aide de `prompt`.
- style : le style musical du segment à prolonger, facultatif.
- continue_at : la limite de prolongation, en secondes. Par exemple, 213.5 signifie que le segment suivant sera généré à partir de 3 minutes 33,5 secondes.

> `extend` est utilisé pour continuer la création après une chanson existante, et non pour changer les paroles de toute la chanson. Si vous souhaitez utiliser de nouvelles paroles depuis le début pour toute la chanson, veuillez utiliser `generate` pour régénérer ; si vous souhaitez réinterpréter une chanson existante à titre de référence, vous pouvez utiliser `cover`. Lors de la transmission de nouvelles paroles complètes, les paroles originales avant `continue_at` ne seront toujours pas remplacées.

## Obtenir la chanson complète

Le résultat de `extend` du modèle actuel contient généralement déjà l'audio source avant `continue_at` et le nouveau contenu après la limite ; veuillez d'abord déterminer, en fonction de la durée réelle et du contenu de l'audio renvoyé, s'il s'agit déjà de la chanson complète. Si le résultat renvoyé est un segment de continuation indépendant, ou s'il est nécessaire de fusionner explicitement l'historique de plusieurs continuations en une seule chanson, utilisez ensuite la fonction de concaténation :

- action : la valeur est `concat`.
- audio_id : l'ID du dernier segment de continuation.

Par exemple, si l'ID de la chanson étendue est : 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, vous pouvez alors définir les paramètres comme suit :

```json
{
  "action": "concat",
  "audio_id": "0a1e1b10-c36a-41c9-9bfb-b26d9d25db98"
}
```

## Reprise musicale

Lorsqu'une chanson est générée à partir d'une chanson existante, le style de la chanson renvoyée peut ne pas être très approprié. Si vous souhaitez faire une reprise de la chanson précédemment générée (les musiques téléversées de manière personnalisée sont également prises en charge), vous devez utiliser la méthode de reprise musicale, qui permet de spécifier le contenu suivant :

- action : le contenu est `cover` ; lorsqu'il s'agit d'effectuer une opération de reprise sur une musique téléversée de manière personnalisée, le contenu doit obligatoirement être spécifié comme : `upload_cover`.
- audio_id : l'ID de la chanson générée précédemment.

Par exemple, si l'ID de la chanson générée précédemment est : 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, les paramètres peuvent être définis comme suit :

## Remplacer un segment

Lorsqu'après la génération d'une chanson, une seconde création nécessitant une opération distincte de remplacement d'un segment de la chanson doit être effectuée, il est possible de remplacer un certain segment de la chanson.

> ⚠️ **Remarque** : `replace_section_result_mode` est par défaut défini sur `full_song` : le système concatène respectivement 2 nouveaux candidats générés et renvoie 2 chansons complètes. Si seuls les candidats de segments de remplacement non encore concaténés sont nécessaires, définissez explicitement cette valeur sur `candidates`, puis sélectionnez un candidat pour appeler [Concaténation musicale](#音乐拼接).

Les paramètres sont décrits comme suit :

- action : le contenu est `replace_section`.
- audio_id : l'ID de la chanson originale (la chanson source à remplacer).
- model : le modèle de génération de chansons.
- lyric : les paroles complètes après remplacement (y compris le segment remplacé et son contexte, cohérents avec le contenu dans `prompt`).
- prompt : les nouvelles paroles du segment à remplacer.
- style : le style de la chanson, facultatif.
- replace_section_start : l'heure de début du segment remplacé dans la chanson originale (secondes).
- replace_section_end : l'heure de fin du segment remplacé dans la chanson originale (secondes).
- replace_section_result_mode : le mode de retour, défini par défaut sur `full_song`. `full_song` concatène respectivement 2 candidats et renvoie 2 chansons complètes ; `candidates` renvoie 2 segments candidats non encore concaténés.

## Séparation voix-musique de toutes les pistes

- action : la valeur est `all_stems`.

```json
{
```

## Extraire une piste audio

## Contrôler la durée de la chanson

Par défaut, la durée des chansons générées est déterminée par le modèle lui-même, généralement entre 30 secondes et 4 minutes. Si un résultat final plus long ou plus court est nécessaire, la durée souhaitée peut être spécifiée à l’aide du paramètre `duration`, en secondes, avec une valeur entière comprise entre 10 et 360.

Ce paramètre est utilisé pour la génération de chansons en mode personnalisé (`custom` est `true`). Il est particulièrement important de préciser que `duration` est une **indication de préférence, et non une contrainte stricte** : le modèle se référera à cette valeur lors de la création, mais ne garantit pas de l’atteindre ; lors des tests, la durée réelle est généralement nettement inférieure à la valeur souhaitée, et la durée des deux chansons renvoyées par une même requête peut également différer de plusieurs fois. Même pour des requêtes entièrement identiques, les durées obtenues après plusieurs soumissions peuvent présenter des différences importantes. Par conséquent, ne l’utilisez pas comme un contrôle précis de la durée ; si une durée fixe est nécessaire pour votre activité, veuillez recadrer ou réessayer vous-même après avoir obtenu le résultat final.

Le code Python correspondant :
```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Il faut noter que `duration` dans la requête est la **durée souhaitée**, tandis que le champ `duration` de chaque chanson dans les `data` de la réponse est la **durée réelle** de cette chanson. Les deux ont le même nom mais des significations différentes ; la durée réelle n'est pas garantie d'être égale à la valeur souhaitée. La longueur des paroles est l'un des principaux facteurs qui influencent la durée du produit final ; si vous avez besoin d'un produit final plus long, il est recommandé de fournir également des paroles plus complètes.

L'interface vérifiera que `duration` est un entier compris entre 10 et 360 ; cela reste uniquement un objectif de génération, et non une garantie sur la durée du produit final.

## Fonction de création inspirée Inspo

La fonction de création inspirée Inspo peut générer de nouvelles musiques à partir de 1 à 4 pistes audio de référence complètes, et prend en charge le glisser-déposer ou le téléversement d’audio comme source d’inspiration. L’API utilise l’action `inspo` existante : le client fournit des URL audio accessibles publiquement, et le service effectue automatiquement la préparation des audios de référence et la création, sans que le client ait besoin de lire séparément les paroles, le style ou la durée avant d’assembler la requête. Elle diffère de l’échantillonnage par intervalle ci-dessus, ainsi que du Cover qui reproduit le style de la chanson originale. Les paramètres suivants doivent être renseignés lors de l’utilisation :

- action : la valeur est `inspo`.
- audio_urls : liste d’URL des audios de référence ; fournissez 1 à 4 adresses audio accessibles publiquement.
- model : le modèle utilisé ; `chirp-v6` est recommandé.
- prompt : paroles ou invite de création (facultatif).

> Remarque : l’audio de référence doit être un fichier audio accessible publiquement. Si l’audio de référence correspond exactement à un enregistrement connu dans le catalogue musical de la plateforme, Suno peut refuser la génération en raison d’une vérification des droits d’auteur ; il est recommandé d’utiliser un audio vous appartenant ou généré par Suno comme source d’inspiration.

Le code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Rappel asynchrone

Étant donné que Suno met relativement longtemps à générer de la musique, environ 1 à 2 minutes, si l’API ne répond pas pendant une longue période, la requête HTTP restera connectée en continu, entraînant une consommation supplémentaire de ressources système ; cette API prend donc également en charge les rappels asynchrones.

Le processus global est le suivant : lorsque le client initie une requête, il spécifie en plus un champ `callback_url`. Après que le client a initié la requête API, l’API renvoie immédiatement un résultat, comprenant un champ `task_id`, qui représente l’ID de la tâche actuelle. Une fois la tâche terminée, le résultat de la génération musicale est envoyé au `callback_url` spécifié par le client sous la forme d’un POST JSON, qui inclut également le champ `task_id`, afin que les résultats de la tâche puissent être associés par ID.
