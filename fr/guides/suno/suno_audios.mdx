Avec l’élargissement des applications de l’IA, divers programmes d’IA se sont progressivement généralisés. L’IA s’est progressivement infiltrée dans tous les aspects du travail et de la vie des gens. Les secteurs impliqués par l’IA sont également de plus en plus nombreux, de l’écriture initiale aux soins de santé et à l’éducation, jusqu’à la musique actuelle.

Suno est une plateforme professionnelle et de haute qualité de création de chansons et de musique par IA. Les utilisateurs n’ont qu’à saisir de simples mots-clés textuels pour générer des chansons avec voix selon le genre, le style et les paroles. Ce générateur de musique par IA est développé par des membres d’équipes provenant d’entreprises technologiques renommées telles que Meta, TikTok et Kensho, avec pour objectif de permettre à tout le monde de créer de merveilleuse musique sans avoir besoin d’aucun instrument.

Suno prend désormais en charge `chirp-v6`, `chirp-v6-wild` et `chirp-v6-mini`. Il est recommandé d’utiliser `chirp-v6` ; les anciens noms de modèles restent compatibles.

Cependant, Suno officiel ne fournit pas d’API. AceDataCloud fournit un ensemble d’API Suno, simulant l’intégration avec Suno officiel, afin de générer facilement et rapidement la musique souhaitée.

## Demande et utilisation

Pour utiliser Suno Audios Generation API, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token, à conserver pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir besoin d’en demander un séparément pour chaque service.** La première demande offre un quota gratuit, permettant une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger le solde universel dans la [console](https://platform.acedata.cloud/console/coin).

## Utilisation de base

Quelle chanson souhaitez-vous, vous pouvez saisir librement un texte, par exemple si je souhaite générer une chanson sur Noël, je peux saisir `a song for Christmas`, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

On peut voir qu’ici nous avons configuré les Request Headers, y compris :

- `accept`：le format de résultat de réponse que vous souhaitez recevoir, ici renseignez `application/json`, c’est-à-dire le format JSON.
- `authorization`：la clé pour appeler l’API, après la demande vous pouvez directement la sélectionner dans la liste déroulante.

En outre, le Request Body a été configuré, y compris :
- `action` : type de tâche audio, par défaut `generate`. Prend en charge des opérations telles que la génération, la prolongation, la reprise, le mixage, la séparation de pistes, l’ajout de piste audio, l’extraction d’une piste audio spécifiée, la génération d’effets sonores et l’ajustement de la vitesse, toutes appelées uniformément via `POST /suno/audios`.
- `prompt` : invite du mode inspiration officiel de Suno (effective lorsque `custom` est `false`), maximum 500 caractères.
- `model` : modèle de cette tâche de génération musicale. La série v6 comprend `chirp-v6`, `chirp-v6-wild` et `chirp-v6-mini` ; les anciens noms de modèles restent compatibles.
- `max_mode` : mode de génération amélioré. `generate` est activé uniquement lorsque `custom` et `max_mode` sont tous deux `true`, pour un coût de 1.12 Credits ; `add_stem` peut être activé directement, pour un coût de 1.344 Credits. Lorsqu’il est désactivé ou omis, les coûts sont respectivement de 0.56 et 0.672 Credits.
- `variety` : intensité de diversité des résultats générés, au choix parmi `off`, `normal`, `high`, `extra`, `max`. Utilisé uniquement pour `generate` et `add_stem` ; le transmettre à d’autres action renverra 400.
- `lyric` : contenu des paroles du mode personnalisé officiel de Suno. Maximum 3000 caractères pour `chirp-v3-5` et `chirp-v4` ; maximum 5000 caractères pour `chirp-v4-5` et les versions ultérieures (y compris `chirp-v5`, `chirp-v5-5`).
- `custom` : indique s’il faut utiliser le mode personnalisé, par défaut : `false`.
- `instrumental` : option de musique instrumentale du mode inspiration officiel de Suno.
- `title` : titre musical du mode personnalisé officiel de Suno. Maximum 80 caractères pour `chirp-v3-5`, `chirp-v4` ; maximum 100 caractères pour `chirp-v4-5` et les versions ultérieures.
- `style` : style musical du mode personnalisé officiel de Suno. Maximum 200 caractères pour `chirp-v3-5` et `chirp-v4` ; maximum 1000 caractères pour `chirp-v4-5` et les versions ultérieures (y compris `chirp-v5`, `chirp-v5-5`).
- `negative_tags` : styles ou genres musicaux à exclure lors de la génération personnalisée, également utilisable pour `replace_section`. Cette interface ne définit actuellement aucune limite fixe de caractères pour ce champ ; un contenu trop long peut néanmoins ne pas être traité, il est recommandé de garder la description concise.
- `audio_weight` : poids d’influence des caractéristiques audio ou vocales, plage de 0 à 1, `0` est également une valeur valide. Peut être utilisé pour des opérations telles que la génération, la prolongation, la reprise, l’ajout de piste audio et la cohérence vocale ; en l’absence d’audio de référence ou de caractéristiques vocales, le modèle peut atténuer ou ignorer cette valeur.
- `audio_id` : ID de la musique de référence, utilisé pour des opérations ultérieures telles que la reprise, la prolongation et la séparation de pistes. Le fichier audio peut toujours être téléchargé, cela ne signifie pas que le traitement ultérieur de cet ID est toujours disponible ; si `suno_processing_unavailable` est renvoyé, conservez `task_id` et `trace_id` pour contacter le support.
- `overpainting_start`/`overpainting_end` : heures de début et de fin, en secondes, pour ajouter des voix à une musique instrumentale existante.
- `underpainting_start`/`underpainting_end` : heures de début et de fin, en secondes, pour ajouter un accompagnement à un chant a cappella.
- `persona_id` : ID vocal obtenu via l’interface de création Persona ou voix, ce n’est pas l’`audio_id` d’une chanson.
- `continue_at` : limite de prolongation, en secondes. Par exemple, 213.5 indique que la génération du segment suivant commence à 3 minutes 33.5 secondes. `lyric` et `style` guident uniquement le nouveau contenu après la limite et ne remplacent pas les paroles ou le chant avant la limite dans l’audio source.
- `style_influence` : influence du style en mode personnalisé, plage de 0 à 1 ; plus elle est élevée, plus le résultat correspond généralement au style sélectionné ; `0` sera transmis comme valeur valide.
- `replace_section_end` : heure finale du segment à remplacer.
- `replace_section_start` : heure de début du segment à remplacer.
- `vocal_gender` : contrôle la préférence pour une voix féminine ou masculine, voix féminine `f`, voix masculine `m`, valable pour les modèles 4.5 et ultérieurs ; il s’agit d’une préférence, sans garantie de respect strict.
- `weirdness` : degré d’étrangeté en mode personnalisé, plage de 0 à 1 ; plus il est élevé, plus le résultat est généralement créatif et expérimental ; `0` sera transmis comme valeur valide.
- `duration` : durée souhaitée de la chanson, en secondes, doit être un entier, avec une plage de 10 à 360. Actuellement, seul `generate` utilise ce paramètre, et l’effet spécifique dépend du mode et du modèle. Il s’agit d’une indication de préférence et non d’une contrainte stricte : le modèle s’y référera, sans garantir de l’atteindre ; la durée réelle du produit final est déterminée par le champ `duration` dans la réponse et est généralement inférieure à la valeur souhaitée.

### Champ d’application de l’ID vocal

`generate`, `cover`, `upload_cover`, `artist_consistency`, `artist_consistency_vox` peuvent utiliser `persona_id`. Les deux dernières action doivent fournir `persona_id` ; elles peuvent également fournir simultanément l’`audio_id` de la chanson utilisée lors de la création de cette Persona.

`extend`, `upload_extend` n’utilisent pas de `persona_id` supplémentaire. La prise en charge des ID vocaux par `mashup`, `inspo` dépend du canal de service sélectionné ; les autres action ne garantissent pas l’application de ce champ, veuillez l’utiliser selon les instructions de chaque opération. `vocal_gender` est une préférence de genre facultative et ne peut pas remplacer un ID vocal.

Les opérations de création ultérieures nécessitent un `audio_id` source valide ; `mashup` nécessite au moins deux `mashup_audio_ids`. En l’absence de source ou de paramètres temporels nécessaires, HTTP 400 sera renvoyé.

### Champ d’application des paramètres avancés
| Paramètre                | Valeur                                          | action prise en charge                              | Description                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | Optionnel                                      | Ajuste l’expérimentalité, `0` est une valeur valide ; l’effet dépend de l’opération, du mode et du modèle      |
| `style_influence` | 0-1                                         | Optionnel                                      | Ajuste la tendance à suivre le style, `0` est une valeur valide ; l’effet dépend de l’opération, du mode et du modèle   |
| `audio_weight`    | 0-1                                         | Optionnel                                      | Ajuste l’influence des caractéristiques audio ou vocales ; peut être ignoré par le modèle en l’absence d’informations de référence        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`、`add_stem`                   | Ajuste la diversité stylistique entre les résultats                       |
| `max_mode`        | boolean                                     | `generate`（nécessite `custom=true`）、`add_stem` | Renforce la cohérence et est facturé selon le mode renforcé                     |
| `vocal_gender`    | `f` / `m`                                   | Opérations de génération prenant en charge le contrôle vocal                             | Préférence, le respect strict n’est pas garanti                       |
| `duration`        | Entier 10-360                                   | `generate`                              | Durée souhaitée ; les autres action n’utilisent actuellement pas ce champ, la durée réelle dépend du résultat |

La plateforme valide les types de paramètres et les plages de valeurs, mais ne rejettera pas ces options de réglage facultatives uniquement parce que l’action est différente ; l’effet concret dépend de l’opération, du mode et du modèle.

- `lyric_prompt` : le prompt pour générer les paroles, prend effet si et seulement si `custom` est `true` et que `lyric` n’est pas transmis.
- `callback_url` : l’URL nécessitant le rappel des résultats.
- `async` : facultatif, lorsque défini sur `true`, l’interface renvoie immédiatement un `task_id`, sans nécessiter de fournir `callback_url`, puis les résultats sont obtenus par interrogation via l’interface de requête de tâche correspondante.

## Fonctionnalité de génération personnalisée selon le style d’un chanteur

Si vous souhaitez utiliser le style d’un chanteur pour générer une chanson, générez d’abord une chanson via l’utilisation de base ci-dessus.\
Enfin, vous devez définir cette chanson comme style de chanteur, puis accéder à [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) pour générer un paramètre d’identifiant de style de chanteur `persona_id` à partir de l’ID de musique officiel `audio_id`. Les paramètres spécifiques sont illustrés dans l’image ci-dessous :

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Après avoir rempli les champs, le code suivant est généré automatiquement :

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

Le code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Vous pouvez ensuite définir le paramètre `action` sur `artist_consistency` (s’il s’agit du nouveau style de chanteur Persona-v2-vox, `action` doit être défini sur `artist_consistency_vox`), et saisir l’ID de la chanson à continuer de générer ainsi que l’ID du style de chanteur.
```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "artist_consistency",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b",
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Fonctionnalité de génération continue
Si vous souhaitez continuer à générer une chanson Suno déjà générée, vous pouvez définir le paramètre `action` sur `extend`, et saisir l'ID de la chanson à continuer de générer. L'obtention de l'ID de la chanson se fait selon l'utilisation de base. Comme indiqué ci-dessus, vous pouvez alors voir que l'ID de la chanson est :

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Remarque : ici, l'`id` dans les paroles est l'ID de la chanson après génération. Si vous ne savez pas comment générer une chanson, vous pouvez vous référer à l'utilisation de base ci-dessus pour générer une chanson.

Si vous souhaitez continuer à générer une chanson que vous avez vous-même importée, vous pouvez définir le paramètre `action` sur `upload_extend`, et saisir l'ID de la chanson personnalisée importée à continuer de générer. L'obtention de l'ID de la chanson se fait à l'aide de [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), comme montré dans l'image ci-dessous :

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

Ensuite, vous devez renseigner les paroles du fragment à poursuivre, et vous pouvez spécifier le style :

- lyric : utilisé uniquement pour guider les paroles du nouveau fragment généré après `continue_at`, et ne remplacera pas les paroles avant ce point temporel dans l'audio source.
- custom : renseigner `true` représente une génération personnalisée ; ce paramètre est par défaut à false, ce qui représente une génération utilisant `prompt`.
- style : style musical du fragment à poursuivre, facultatif.
- continue_at : limite de continuation, en secondes. Par exemple, 213.5 indique que la génération du fragment suivant commence à 3 minutes et 33,5 secondes.

Le `continue_at` de `extend` et `upload_extend` doit être supérieur à 0, et prend en charge les secondes décimales, par exemple `30.792` ; aucune valeur n'est arrondie lors de l'envoi.

> `extend` est utilisé pour continuer à créer après une chanson existante, et non pour changer les paroles de toute la chanson. Si vous souhaitez utiliser de nouvelles paroles pour toute la chanson depuis le début, veuillez utiliser `generate` pour la générer à nouveau ; si vous souhaitez réinterpréter une chanson existante à titre de référence, vous pouvez utiliser `cover`. Lors de la transmission de paroles entièrement nouvelles, les paroles originales avant `continue_at` ne seront toujours pas remplacées.

- action : le contenu est `concat`.
- audio_id : l’ID du dernier segment de continuation.

## Reprise musicale

Après avoir continué à générer une chanson à partir d’une chanson existante, le style de la chanson retournée peut ne pas être très approprié. S’il faut faire une reprise de la chanson générée précédemment (les musiques personnalisées importées sont également prises en charge), il faut utiliser la méthode de reprise musicale, et le contenu suivant peut être spécifié :

- action : le contenu est `cover` ; lors d’une opération de reprise sur une musique personnalisée importée, le contenu doit être spécifié comme : `upload_cover`.
- audio_id : l’ID de la chanson générée précédemment.

Si vous devez utiliser une voix spécifiée pour la reprise, vous pouvez également transmettre `persona_id`. Pour une voix privée créée via `/suno/voices`, vous devez d’abord importer la chanson originale dans `/suno/upload` avec le même `persona_id`, puis utiliser l’`audio_id` retourné pour effectuer `upload_cover`. Toutes les étapes doivent utiliser le même canal de service. Il n’est pas nécessaire de spécifier `vocal_gender` en supplément, la préférence de genre ne peut pas remplacer l’ID de voix.

Par exemple, si l’ID de la chanson générée précédemment est : 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, les paramètres peuvent être définis comme suit :

```json
{
  "action": "cover",
  "audio_id": "0a1e1b10-c36a-41c9-9bfb-b26d9d25db98",

  "model": "chirp-v4-5"
}
```

Les autres paramètres restent inchangés, et le retour est une chanson reprise, c’est-à-dire le résultat de la reprise de la chanson générée précédemment, comme dans l’exemple suivant :

## Remplacer un segment

`replace_section` régénère le segment sélectionné selon l’intervalle temporel de la chanson source, puis réintègre le résultat dans la chanson originale. `replace_section_result_mode` est défini par défaut sur `full_song`, et retourne 2 chansons complètes, qui peuvent être lues directement, sans avoir à appeler de nouveau `concat`.

### Comment remplir les entrées
- `action` : `replace_section`.
- `audio_id` : l’ID complet de la chanson à modifier. Lors d’une nouvelle modification, utilisez le `data[].id` de la chanson complète sélectionnée précédemment, et non le `task_id`.
- `model` : le modèle de génération de chansons, par exemple `chirp-v6`.
- `lyric` : les **nouvelles paroles locales** à chanter dans la plage sélectionnée. Il n’est pas nécessaire de fournir les paroles complètes afin d’obtenir une chanson complète.
- `prompt` : spécifie clairement les nouvelles paroles locales de ce remplacement. Lors de la modification des paroles, il est recommandé de renseigner le même contenu que dans `lyric`, afin d’éviter que les deux champs expriment des paroles différentes. Les requêtes existantes qui ne transmettent que le `lyric` local et omettent `prompt` peuvent toujours être utilisées, mais ajouter `prompt` ne garantit pas en soi la réussite de la modification des paroles.
- `style`, `negative_tags` : descriptions de style et éléments à exclure facultatifs ; dans cette opération, `prompt` n’est pas une description d’inspiration comme lors de la création normale d’une chanson.
- `replace_section_start`, `replace_section_end` : les heures de début et de fin de la sélection dans la chanson source actuelle, en secondes, avec prise en charge des décimales. Le point de départ ne doit pas être inférieur à 0, et le point final doit être supérieur au point de départ sans dépasser la durée de la chanson source.
- `replace_section_result_mode` : `full_song` (par défaut) renvoie 2 chansons complètes ; `candidates` renvoie 2 candidats de remplacement qui n’ont pas encore été assemblés.

Ne considérez pas « `lyric` doit être les paroles complètes après remplacement, `prompt` doit être les paroles locales » comme une utilisation générale. La saisie de paroles complètes peut, dans certaines tâches, produire un contenu de remplacement trop long, rendant la chanson entière nettement plus longue après l’assemblage. Une saisie locale ne garantit pas non plus une durée fixe ni le respect mot à mot des paroles ; il s’agit d’une modification générative, et l’audio réel doit être vérifié.

### Lancer une tâche et obtenir une chanson complète

Voici un exemple de format de requête. Remplacez `YOUR_COMPLETED_AUDIO_ID` et la plage de temps par votre propre ID de chanson source et votre sélection réelle ; l’exemple suppose que les secondes 30 à 50 correspondent aux quatre lignes suivantes.

```json
{
  "action": "replace_section",
  "audio_id": "YOUR_COMPLETED_AUDIO_ID",
  "model": "chirp-v6",
  "custom": false,
  "instrumental": false,
  "lyric": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "prompt": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "replace_section_start": 30.0,
  "replace_section_end": 50.0,
  "replace_section_result_mode": "full_song",
  "async": true
}
```

Après la soumission, utilisez le `task_id` renvoyé pour interroger `/suno/tasks`, avec comme corps de requête `{"action":"retrieve","id":"YOUR_TASK_ID"}`. Une fois la tâche terminée, récupérez l’`id`, l’`audio_url` et la `duration` des deux chansons complètes dans `response.data` de la réponse de la tâche, puis écoutez-les avant d’en sélectionner une. `success: true` indique que la tâche a été exécutée avec succès, mais ne signifie pas que les nouvelles paroles ont été chantées mot à mot ou que la durée correspond aux attentes.

### Sélection, vérification des résultats et nouvelle modification

1. Écoutez d’abord la chanson source, puis déterminez la sélection à l’aide des informations temporelles de `/suno/timing`, en essayant de couvrir des phrases musicales complètes. Ne sélectionnez pas la plage selon des indices fixes du tableau de paroles, et ne remplacez pas une plage contenant davantage de phrases musicales par quelques lignes de paroles en espérant que le rythme reste exactement identique.
2. Le nombre de lignes, de caractères et le rythme des nouvelles paroles doivent autant que possible être proches du contenu existant dans la sélection. Même en ne modifiant que quelques caractères, une vérification par écoute est nécessaire ; cela ne permet pas de garantir la réussite.
3. Vérifiez si les nouvelles paroles sont chantées dans la plage cible, si les transitions avant et après sont naturelles, et si la durée totale de la chanson est raisonnable. `full_song` signifie qu’une chanson complète est renvoyée, et non qu’elle a la même durée que l’original ; si le segment remplacé devient plus long, la seconde moitié sera décalée en conséquence. Le paramètre de requête `duration` est utilisé uniquement pour la génération normale et ne peut pas verrouiller la durée du segment de remplacement.
4. Le `lyric` renvoyé est une métadonnée de paroles ; en mode chanson complète, les paroles complètes sont combinées lorsque les informations temporelles des paroles source sont disponibles ; sinon, elles peuvent être vides. Il ne s’agit pas d’une transcription audio : la présence de nouvelles paroles ne prouve pas qu’elles ont été chantées dans l’audio. Les informations d’alignement temporel doivent également être vérifiées à l’écoute, en particulier pour les productions déjà modifiées.
5. Lors d’une nouvelle modification, utilisez l’**ID du produit complet** sélectionné comme nouvel `audio_id`, et vérifiez à nouveau la durée et la sélection de ce produit. Ne réutilisez pas directement les coordonnées temporelles antérieures à la modification, et n’utilisez pas directement le `lyric` de la chanson entière renvoyé la dernière fois comme saisie locale de cette fois-ci.

Si la tâche est terminée mais que les anciennes paroles sont toujours chantées, que des paroles manquent ou que la chanson est nettement plus longue, vérifiez d’abord l’ID de la chanson source, la sélection et les paroles locales, puis vérifiez l’autre résultat. Augmenter la fréquence d’interrogation des tâches ne changera pas le contenu déjà généré. Si le problème persiste, conservez le `task_id`, l’ID de la chanson source, les champs de la requête, la sélection et l’audio résultant afin de faciliter la vérification.

### Facultatif : récupérer d’abord les candidats, puis assembler manuellement

Uniquement lorsqu’il est nécessaire de sélectionner vous-même un candidat de remplacement, définissez `replace_section_result_mode: "candidates"`. Les candidats peuvent contenir du contexte ; ils ne doivent pas être considérés comme des chansons complètes uniquement sur la base de leur durée. Après la sélection, appelez `concat` avec le `data[].id` du candidat, puis récupérez le produit complet.

Le `full_song` par défaut a déjà terminé l’assemblage, il n’est pas nécessaire d’effectuer cette étape.

## Séparation voix et musique

Facturation : après le succès de `action=stems`, le coût standard de chaque requête est de **0.56 Credits** ; la voix et l’accompagnement renvoyés dans une même requête sont comptabilisés comme une seule fois. Les remises de consommation applicables sont déterminées par la facture réelle, et les requêtes échouées ne sont pas facturées. `all_stems` et `extract_stem` sont facturés selon leurs prix respectifs.

Lorsqu’une création secondaire nécessitant des opérations distinctes sur l’accompagnement et la voix est requise après la génération d’une chanson, il est possible de séparer l’accompagnement instrumental pur et la voix a cappella. Le contenu suivant peut alors être spécifié :

- action : la valeur est `stems`.
- audio_id : l’ID de la chanson générée précédemment.

```json
  "action": "stems",
```

## Séparation voix-instrument de toutes les pistes

La tâche attendra que toutes les pistes audio aient terminé leur génération avant de renvoyer un état final de réussite. L’apparition d’une adresse lisible pendant le traitement ne signifie pas que l’ensemble des pistes audio est terminé.

Lorsqu’il est nécessaire d’effectuer une séparation voix-instrument de toutes les pistes après la génération d’une chanson, vous pouvez spécifier le contenu suivant :

- action : le contenu est `all_stems`.
- audio_id : l’ID de la chanson générée précédemment.

```json
{
  "action": "all_stems",
  "audio_id": "bdf23a5a-59f5-4103-b452-054a824a7f9f"
}
```

## Contrôle de la durée de la chanson

Par défaut, la durée de la chanson générée est déterminée par le modèle lui-même, généralement entre 30 secondes et 4 minutes. Si un produit fini plus long ou plus court est nécessaire, la durée souhaitée peut être spécifiée via le paramètre `duration`, en secondes, avec une valeur entière comprise entre 10 et 360.

Ce paramètre est utilisé pour la génération de chansons en mode personnalisé (`custom` étant défini sur `true`). Il est particulièrement important de préciser que `duration` est une **indication de tendance, et non une contrainte stricte** : le modèle se référera à cette valeur lors de la création, mais ne garantit pas de l’atteindre. Lors des tests, la durée réelle est généralement nettement inférieure à la valeur attendue, et les durées des deux chansons renvoyées par une même requête peuvent également différer de plusieurs fois. Même pour des requêtes complètement identiques, les durées obtenues après plusieurs soumissions peuvent présenter des différences importantes. Par conséquent, ne l’utilisez pas comme un contrôle précis de la durée ; si une durée fixe est requise pour votre activité, veuillez découper ou réessayer vous-même après avoir obtenu le produit fini.

Le code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Il convient de noter que `duration` dans la requête est la **durée souhaitée**, tandis que le champ `duration` de chaque chanson dans les `data` de la réponse correspond à la **durée réelle** de cette chanson. Les deux portent le même nom, mais ont des significations différentes ; la durée réelle n’est pas garantie comme étant égale à la valeur souhaitée. La longueur des paroles est l’un des principaux facteurs influençant la durée du produit fini ; si un produit fini plus long est nécessaire, il est recommandé de fournir en même temps des paroles plus complètes.

L’interface vérifie que `duration` doit être un entier compris entre 10 et 360 ; il reste toutefois uniquement un objectif de génération, et non une garantie de la durée du produit fini.

## Fonctionnalité de création inspirée Inspo

La fonctionnalité de création inspirée Inspo peut générer de nouvelle musique à partir de 1 à 4 pistes audio de référence complètes, et prend en charge le glisser-déposer ou le téléversement d’audio comme source d’inspiration. L’API utilise l’action `inspo` existante : le client fournit des URL audio accessibles publiquement, et le service effectue automatiquement la préparation des audios de référence et la création, sans que le client ait besoin de lire séparément les paroles, le style ou la durée avant d’assembler la requête. Elle diffère de l’échantillonnage par segment décrit ci-dessus, ainsi que du Cover qui reproduit le style de la chanson originale. Les paramètres suivants doivent être renseignés lors de l’utilisation :

- action : la valeur est `inspo`.
- audio_urls : liste d’URL des audios de référence, avec 1 à 4 adresses audio accessibles publiquement à fournir.
- model : le modèle utilisé, `chirp-v6` est recommandé.
- prompt : paroles ou invite de création (facultatif).
- instrumental : lorsqu’il est défini sur `true`, génère selon une requête de musique instrumentale, sans utiliser de paroles.
- persona_id : utilise la voix spécifiée sur les canaux de service qui prennent en charge cette combinaison ; les audios de référence seront liés, durant l’étape de préparation, à l’environnement de ressources requis par cette voix.
- lyric_prompt : lorsque `custom=true` et qu’aucun `lyric` n’est fourni, utilisé pour générer automatiquement les paroles.

> Remarque : les audios de référence doivent être des fichiers audio accessibles publiquement. Si l’audio de référence correspond exactement à un enregistrement connu dans la bibliothèque musicale de la plateforme, Suno peut refuser la génération en raison d’une vérification des droits d’auteur ; il est recommandé d’utiliser des audios vous appartenant ou générés par Suno comme sources d’inspiration.

Le code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Rappel asynchrone

Étant donné que Suno met relativement longtemps à générer de la musique, environ 1 à 2 minutes, si l’API ne répond pas pendant longtemps, la requête HTTP maintiendra continuellement la connexion, entraînant une consommation supplémentaire de ressources système. C’est pourquoi cette API prend également en charge les rappels asynchrones.

Le processus global est le suivant : lorsque le client lance une requête, il spécifie en supplément un champ `callback_url`. Après que le client a lancé la requête API, l’API renvoie immédiatement un résultat, incluant un champ `task_id`, qui représente l’ID de la tâche actuelle. Une fois la tâche terminée, le résultat de la génération de musique est envoyé sous forme de POST JSON à l’adresse `callback_url` spécifiée par le client, qui inclut également le champ `task_id`, permettant ainsi d’associer les résultats de la tâche par ID.
