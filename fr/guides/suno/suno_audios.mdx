Avec l'application croissante de l'IA, divers programmes d'IA sont devenus progressivement courants. L'IA s'est progressivement intégrée dans tous les aspects de la vie professionnelle et personnelle des gens. Les secteurs impliqués dans l'IA sont également de plus en plus nombreux, allant de l'écriture initiale, à l'éducation médicale, jusqu'à la musique actuelle.

Suno est une plateforme professionnelle de création de chansons et de musique de haute qualité, où les utilisateurs n'ont qu'à entrer de simples mots-clés pour générer des chansons avec voix en fonction du style et des paroles. Ce générateur de musique IA a été développé par des membres d'équipes de sociétés technologiques renommées telles que Meta, TikTok, Kensho, avec pour objectif de permettre à tous de créer de la musique merveilleuse sans avoir besoin d'instruments.

Voici l'avancement des mises à jour du modèle :

| Version | modèle           | Date de lancement | Limite de paroles | Limite de style | Durée maximale de la chanson |
| ------- | ---------------- | ----------------- | ---------------- | --------------- | ---------------------------- |
| v5.5   | chirp-v5-5      | 2026.03.27       | 5000             | 1000            | 8 minutes                    |
| v5     | chirp-v5        | 2025.09.23       | 5000             | 1000            | 8 minutes                    |
| v4.5+  | chirp-v4-5-plus | 2025.07.17       | 5000             | 1000            | 8 minutes                    |
| v4.5   | chirp-v4-5      | 2025.05.03       | 5000             | 1000            | 4 minutes                    |
| v4     | chirp-v4        | 2024.12.17       | 3000             | 200             | 150 secondes                 |
| v3.5   | chirp-v3-5      | ---               | 3000             | 200             | 120 secondes                 |

> La limite de `lyric` et de `style` dans le tableau ci-dessus est le maximum en mode personnalisé (`custom` est `true`). En mode inspiration non personnalisé (`custom` est `false`), seul `prompt` est rempli, avec une limite de longueur de 500 caractères (identique pour tous les modèles).

Suno prend désormais en charge le dernier modèle `chirp-v5-5`. Pour appeler la dernière version, il suffit de définir le paramètre `model` sur `chirp-v5-5` ; `chirp-v5` et les versions antérieures peuvent toujours être utilisées.

Cependant, Suno n'a pas fourni d'API officielle, AceDataCloud a mis à disposition un ensemble d'API Suno, simulant l'intégration de l'API officielle de Suno, permettant de générer facilement et rapidement la musique souhaitée.

## Demande et utilisation

Pour utiliser l'API de génération de sons Suno, commencez par obtenir votre API Token sur le [tableau de bord Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour le garder en réserve.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter, après quoi vous serez automatiquement renvoyé à la page actuelle.

**Un seul API Token suffit pour appeler tous les services de la plateforme, sans avoir besoin de demander séparément pour chaque service.** La première demande vous donnera un quota gratuit pour une expérience sans frais ; lorsque le quota est insuffisant, vous pouvez recharger le solde général sur le [tableau de bord](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [API de génération de sons Suno →](https://platform.acedata.cloud/documents/suno-audios)

## Utilisation de base

Pour générer des chansons, vous pouvez entrer n'importe quel texte, par exemple, si je veux générer une chanson sur Noël, je peux entrer `a song for Christmas`, comme montré ci-dessous :

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Ici, nous avons configuré les en-têtes de requête, y compris :

- `accept` : le format de réponse souhaité, ici rempli avec `application/json`, c'est-à-dire au format JSON.
- `authorization` : la clé pour appeler l'API, que vous pouvez sélectionner directement après la demande.

De plus, nous avons configuré le corps de la requête, y compris :
- `action` : L'action de cette tâche de génération musicale, par défaut `generate`, comprend principalement : `extend`, `upload_extend`, `cover`, `upload_cover`, `replace_section`, `replace_section`, `concat`, `stems`, `all_stems`, `remaster`.
- `prompt` : Le mot d'inspiration du mode officiel de Suno (valide lorsque `custom` est `false`), maximum 500 caractères.
- `model` : Le modèle de cette tâche de génération musicale, par défaut `chirp-v4`, comprend principalement : `chirp-v3`, `chirp-v4`, `chirp-v3-5`, `chirp-v4-5`, `chirp-v4-5-plus`, `chirp-v5`, `chirp-v5-5`.
- `lyric` : Le contenu des paroles du mode personnalisé de Suno. `chirp-v3-5` et `chirp-v4` maximum 3000 caractères ; `chirp-v4-5` et au-dessus (y compris `chirp-v5`, `chirp-v5-5`) maximum 5000 caractères.
- `custom` : Indique si le mode personnalisé est utilisé, par défaut : `false`.
- `instrumental` : L'option de musique pure du mode d'inspiration de Suno.
- `title` : Le titre de la musique du mode personnalisé de Suno. `chirp-v3-5`, `chirp-v4` maximum 80 caractères ; `chirp-v4-5` et au-dessus maximum 100 caractères.
- `style` : Le style musical du mode personnalisé de Suno. `chirp-v3-5` et `chirp-v4` maximum 200 caractères ; `chirp-v4-5` et au-dessus (y compris `chirp-v5`, `chirp-v5-5`) maximum 1000 caractères.
- `negative_tags` : Les styles ou genres musicaux à exclure des résultats générés dans le mode personnalisé (`custom` est `true`).
- `audio_weight` : La proportion de l'audio de référence téléchargé, plage de 0 à 1, plus c'est grand, plus cela dépend de l'audio de référence.
- `audio_id` : L'ID de la musique de référence.
- `overpainting_start`/`overpainting_end` : Le temps de début et de fin pour ajouter des voix à une musique pure existante, en secondes.
- `underpainting_start`/`underpainting_end` : Le temps de début et de fin pour ajouter un accompagnement à un chant, en secondes.
- `persona_id` : L'ID de la chanson de l'artiste.
- `continue_at` : Le temps en secondes pour continuer l'audio existant. Par exemple, 213.5 signifie continuer jusqu'à 3 minutes 33.5 secondes.
- `style_influence` : Le paramètre avancé « Style Influence » dans le mode personnalisé, plage de 0 à 1, plus c'est grand, plus cela correspond au style choisi.
- `replace_section_end` : Le temps final du segment à remplacer.
- `replace_section_start` : Le temps de début du segment à remplacer.
- `vocal_gender` : Contrôle la préférence pour les voix masculines ou féminines, voix féminine `f`, voix masculine `m`, valide pour les modèles 4.5 et supérieurs ; c'est une préférence, sans garantie de stricte conformité.
- `weirdness` : Le paramètre avancé « Weirdness » dans le mode personnalisé, plage de 0 à 1, plus c'est grand, plus c'est créatif et expérimental.
- `duration` : La durée souhaitée de la chanson, en secondes, doit être un entier, plage de 10 à 360. Ce paramètre est utilisé pour la génération de chansons en mode personnalisé (`custom` est `true`). C'est un indice de tendance plutôt qu'une contrainte stricte : le modèle s'y référera, mais ne garantit pas d'atteindre, la durée réelle du produit final sera conforme au champ `duration` dans la réponse, généralement inférieure à la valeur souhaitée.
- `lyric_prompt` : Le prompt pour générer des paroles, valide uniquement lorsque `custom` est `true` et que `lyric` n'est pas fourni.
- `callback_url` : L'URL pour laquelle les résultats doivent être rappelés.
- `async` : Optionnel, si défini sur `true`, l'interface renvoie immédiatement `task_id`, sans avoir besoin de fournir `callback_url`, puis interroge le résultat via l'interface de requête de tâche correspondante.

## Génération personnalisée

Si vous souhaitez générer des paroles personnalisées, vous pouvez entrer les paroles :

À ce moment-là, le champ `lyric` peut recevoir un contenu similaire à celui-ci :

```
[Verse]\nFlocons de neige tombant tout autour\nBlanc scintillant\nRecouvrant le sol\nEnfants riant\nPlein de délices\nDans ce pays des merveilles d'hiver ce soir\nLe traîneau du Père Noël\nDans le ciel\nLe nez de Rudolph brillant de mille feux\nOh mon\nEntendez les cloches\nSonner si clairement\nApportant joie et bonne humeur\n[Verse 2]\nChâtaignes rôties à la lueur du feu\nLumières de Noël\nElles scintillent et montrent\nLes familles se rassemblent avec amour et joie\nRépandant chaleur à tous ceux qui sont proches
```

> Remarque, ici dans les paroles, `\n` est un caractère de nouvelle ligne, si vous ne savez pas comment générer des paroles, vous pouvez utiliser l'API de génération de paroles fournie par AceDataCloud pour générer des paroles via un prompt, l'API est [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics).

Ensuite, nous devons personnaliser la génération de chansons en fonction des paroles, du titre et du style, nous pouvons spécifier le contenu suivant :

- lyric : texte des paroles
- custom : remplir avec `true`, représentant une génération personnalisée, ce paramètre est par défaut `false`, représentant l'utilisation de `prompt` pour générer.
- title : titre de la chanson.
- style : style de la chanson, optionnel.

## Obtenir la chanson complète

Lorsque vous générez une chanson en continu à partir d'une chanson existante, la chanson retournée ne contient pas le contenu de la chanson originale. Pour obtenir le contenu complet de la chanson, vous devez utiliser la fonction de concaténation, vous pouvez spécifier le contenu suivant :

- action : le contenu est `concat`.
- audio_id : l'ID du dernier segment.

Par exemple, l'ID de la chanson étendue est : 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, vous pouvez donc définir les paramètres comme suit :

```json
{
  "action": "concat",
  "audio_id": "0a1e1b10-c36a-41c9-9bfb-b26d9d25db98"
}
```

Les autres paramètres restent inchangés, le retour sera une chanson complète, c'est-à-dire le résultat de la concaténation de tous les segments de chanson, mais le résultat ne contiendra qu'une seule chanson, un exemple est donné ci-dessous :

## Reprise musicale
Lorsque vous générez une chanson basée sur une chanson existante, le style de la chanson retournée peut ne pas être approprié. - action : le contenu doit être `cover`, lorsque vous effectuez une opération de cover sur une musique téléchargée personnalisée, le contenu doit être spécifié comme : `upload_cover`.
- audio_id : l'ID de la chanson générée précédemment.

Par exemple, si l'ID de la chanson générée précédemment est : 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, vous pouvez définir les paramètres comme suit :

```json
{
  "action": "cover",
  "audio_id": "0a1e1b10-c36a-41c9-9bfb-b26d9d25db98",

  "model": "chirp-v4-5"
```

## Remplacement de section

Lorsque vous devez effectuer une création secondaire en remplaçant un segment de chanson après la génération de la chanson, vous pouvez remplacer un segment spécifique de la chanson.

> ⚠️ **Remarque** : `replace_section` utilisé seul **ne renverra que le nouveau "segment de remplacement" lui-même** (c'est-à-dire le nouvel audio de la section remplacée, d'une durée d'environ `replace_section_end - replace_section_start`, avec un peu de contexte), **et ne renverra pas la chanson complète assemblée**. Pour obtenir le produit final assemblé avec la chanson originale, vous devez, après le succès de `replace_section`, lancer une nouvelle tâche de [montage musical](#montage-musical) pour l'ID du segment retourné. Le processus complet est décrit ci-dessous.

Les paramètres sont les suivants :

- action : le contenu doit être `replace_section`.
- audio_id : l'ID de la chanson originale (la source de la chanson remplacée).
- model : le modèle de génération de chanson.
- lyric : les paroles complètes après remplacement (incluant le segment remplacé et son contexte, en cohérence avec le contenu de `prompt`).
- prompt : le nouveau texte des paroles à remplacer.
- style : le style de la chanson, optionnel.
- replace_section_start : le temps de début du segment remplacé dans la chanson originale (en secondes).
- replace_section_end : le temps de fin du segment remplacé dans la chanson originale (en secondes).

### Étape 1 : Lancer la tâche de remplacement de section

```json
{
  "action": "replace_section",
```

## Contrôle de la durée de la chanson

Par défaut, la durée de la chanson générée est déterminée par le modèle, généralement entre 30 secondes et 4 minutes. Si un produit plus long ou plus court est nécessaire, vous pouvez spécifier la durée souhaitée via le paramètre `duration`, en secondes, avec une valeur entière entre 10 et 360.

Ce paramètre est utilisé pour la génération de chansons en mode personnalisé (`custom` étant `true`). Il convient de noter que `duration` est un **indice de tendance, et non une contrainte stricte** : le modèle se référera à cette valeur lors de la création, mais ne garantit pas de l'atteindre. Dans les tests, la durée réelle est généralement nettement inférieure à la valeur attendue, et les durées des deux chansons retournées dans une même demande peuvent également varier considérablement. Même pour des demandes totalement identiques, les durées obtenues peuvent varier considérablement. Par conséquent, ne le considérez pas comme un contrôle de durée précis ; si une durée fixe est nécessaire pour des raisons commerciales, veuillez couper ou réessayer après avoir obtenu le produit.

Le code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Sous les lumières de la ville",
    "style": "lo-fi piano",
    "lyric": "[Couplet]\nLever du soleil\nOr sur le sol\n[Refrain]\nSous les lumières de la ville\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Il est important de noter que la `duration` dans la demande est la **durée souhaitée**, tandis que le champ `duration` de chaque chanson dans la réponse `data` est la **durée réelle** de cette chanson. Les deux noms sont identiques mais ont des significations différentes, la durée réelle n'est pas garantie d'être égale à la valeur souhaitée. La longueur des paroles est l'un des principaux facteurs influençant la durée du produit final ; si un produit plus long est nécessaire, il est conseillé de fournir des paroles plus complètes en même temps.

L'interface ne fera pas de vérification supplémentaire sur la `duration`, le paramètre sera transmis tel quel au modèle. Si une valeur non prise en charge par le mode ou le modèle actuel est fournie, cela peut se traduire par l'ignorance de cette valeur ; il est conseillé de confirmer l'effet avec une demande avant de l'utiliser en masse.

## Fonction de création d'inspiration

La nouvelle fonction de création d'inspiration de Suno peut générer de la musique entièrement nouvelle en utilisant de 1 à 4 segments d'audio de référence comme source d'inspiration. Contrairement aux reprises, l'inspiration ne reproduit pas la chanson originale, mais extrait l'inspiration stylistique des audios de référence, puis génère de nouvelles œuvres en combinant des mots-clés, des étiquettes de style, etc. Lors de l'utilisation, il est nécessaire de remplir les paramètres suivants :

- action : contenu `inspo`.
- audio_urls : liste des URL des audios de référence, nécessitant de fournir de 1 à 4 adresses audio accessibles au public.
- model : modèle utilisé, par exemple `chirp-v5`.
- prompt : paroles ou mots-clés de création (facultatif).
- tags : étiquettes de style musical, par exemple `acoustic, folk, warm` (facultatif).
- title : titre de la chanson (facultatif).
- audio_weight : poids d'influence des audios de référence sur le résultat généré, plage de valeurs de 0 à 1 (facultatif).

> Remarque : les audios de référence doivent être des fichiers audio accessibles au public. Si l'audio de référence correspond exactement à un enregistrement connu dans la bibliothèque de la plateforme, Suno peut refuser de générer en raison de la vérification des droits d'auteur, il est conseillé d'utiliser des audios propres ou générés par Suno comme source d'inspiration.

Le code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v5",

        "https://cdn1.suno.ai/935dd2f5-ddef-43cf-8e68-5a262425694d.mp3"
```

## Rappel asynchrone

Étant donné que le temps de génération de musique par Suno est relativement long, environ 1 à 2 minutes, si l'API ne répond pas pendant longtemps, la requête HTTP maintiendra la connexion, entraînant une consommation supplémentaire de ressources système. C'est pourquoi cette API propose également un support de rappel asynchrone.

Le processus global est le suivant : lorsque le client initie une demande, il spécifie un champ `callback_url` supplémentaire. Après que le client a lancé la demande API, l'API renverra immédiatement un résultat contenant un champ d'information `task_id`, représentant l'ID de la tâche actuelle. Lorsque la tâche est terminée, le résultat de la génération musicale sera envoyé au `callback_url` spécifié par le client sous forme de POST JSON, incluant également le champ `task_id`, permettant ainsi de relier le résultat de la tâche par ID.

Voyons comment procéder à travers un exemple.

Pour faciliter la démonstration, nous utilisons un site Web de Webhook public https://webhook.site/, en ouvrant ce site, vous obtiendrez une URL Webhook, comme illustré :
