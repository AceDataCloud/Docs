L’API du projet Suno Studio gère les projets musicaux multipistes via un seul point d’entrée :

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
```

Le champ `action` de la requête détermine le type d’opération. La clé primaire du Project utilise uniformément `id` ; `version_id` représente la version actuelle du projet, et toutes les opérations de modification et d’exportation doivent soumettre la version la plus récente afin d’éviter les écrasements dus à la concurrence.

## Aperçu des opérations

| action             | Mode  | Utilisation                      |
| ------------------ | --- | ----------------------- |
| `create`           | Synchrone  | Créer un projet vide                   |
| `retrieve`         | Synchrone  | Lire le projet et le `state` complet modifiable      |
| `save`             | Synchrone  | Enregistrer l’état complet du projet                |
| `upload`           | Asynchrone  | Initialiser une ressource pouvant être ajoutée au projet depuis une adresse audio HTTPS |
| `add_track`        | Asynchrone  | Ajouter un audio existant au projet               |
| `generate_track`   | Asynchrone  | Générer de nouveaux candidats de piste audio pour une plage spécifiée            |
| `replace_section`  | Asynchrone  | Générer des candidats de remplacement local                |
| `commit_candidate` | Asynchrone  | Valider le candidat sélectionné dans le projet             |
| `remove_track`     | Synchrone  | Supprimer la piste spécifiée                  |
| `render`           | Asynchrone  | Exporter une chanson complète à partir de la version enregistrée           |

Les opérations asynchrones renvoient immédiatement un `task_id`. Utilisez l’interface gratuite `/suno/tasks` pour interroger l’état, ou transmettez `callback_url` pour recevoir le résultat final.

## Création et lecture

```json
{"action":"create","title":"My Studio Project"}
```

Toutes les opérations de modification doivent envoyer un Header `Idempotency-Key` unique. Après une création réussie, le `data.id` dans la réponse est le Project ID. Un nouveau projet vide peut ne pas avoir de `version_id` avant le premier enregistrement.

```json
{"action":"retrieve","id":"PROJECT_ID"}
```

La réponse de lecture contient le `state` complet. Il est recommandé de lire d’abord, puis de modifier et d’enregistrer en fonction de la valeur renvoyée ; ne construisez pas manuellement à partir de zéro les structures internes de tempo et de pistes.

## Enregistrer l’état complet

```json
{
  "action":"save",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "title":"Edited Project",
  "state":{"tracks":[],"timing":{}}
}
```

Le premier enregistrement d’un nouveau projet vide peut omettre `version_id` ; une fois qu’une version est générée après le premier enregistrement, les enregistrements suivants doivent soumettre la valeur la plus récente. Si la version a déjà changé, l’interface renvoie HTTP 409. Dans ce cas, effectuez à nouveau `retrieve`, fusionnez les modifications puis soumettez avec une nouvelle clé d’idempotence ; ne réessayez pas aveuglément l’ancienne requête.

## Téléverser et ajouter des pistes

```json
{
  "action":"upload",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "audio_url":"https://cdn.example.com/reference.mp3",
  "async":true
}
```

Une fois le téléversement terminé, le résultat de la tâche renvoie le `audio_id` candidat. Ajoutez-le ensuite au projet :

```json
{
  "action":"add_track",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "audio_id":"AUDIO_ID",
  "name":"Backing Vocals"
}
```

## Génération et remplacement

`generate_track` génère des candidats de piste audio pour une plage du projet ; `replace_section` renvoie deux candidats de remplacement local. Aucune de ces deux opérations ne sélectionne automatiquement le résultat artistique.

```json
{
  "action":"replace_section",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "source_audio_id":"AUDIO_ID",
  "start_seconds":35.12,
  "end_seconds":48.76,
  "model":"chirp-v6",
  "replacement_lyrics":"nouvel extrait de paroles",
  "async":true
}
```

Après avoir sélectionné un candidat, validez-le :

```json
{
  "action":"commit_candidate",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "operation_id":"OPERATION_ID",
  "candidate_id":"CANDIDATE_ID",
  "track_id":"TRACK_ID"
}
```

Les candidats sont liés à la version du projet au moment de la génération. Si le projet a déjà changé, les anciens candidats ne peuvent pas être validés directement.

## Exporter une chanson complète

```json
{
  "action":"render",
  "id":"PROJECT_ID",
  "version_id":"CURRENT_VERSION_ID",
  "title":"Final Mix",
  "lyrics":"[Instrumental]",
  "async":true,
  "callback_url":"https://example.com/webhooks/suno"
}
```

Le serveur lit l’état autoritatif du projet de la version spécifiée et assemble les paramètres d’exportation. Le résultat final contient `render_id`, `audio_id`, `audio_url` et la durée. Le projet est lié à l’environnement d’exécution lors de sa création et ne peut pas être migré entre environnements ni basculer automatiquement en cas de défaillance.

> Vous ne pouvez téléverser ou traiter que des fichiers audio pour lesquels vous disposez de droits d’utilisation légaux. L’API de projet est actuellement en Beta ; veuillez conserver durablement les URL audio finales présentes dans les résultats importants.
