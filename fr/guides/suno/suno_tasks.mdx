La principale fonctionnalité de l'API Suno Tasks est de permettre la consultation de l'état d'exécution d'une tâche en utilisant l'ID de tâche généré par l'API Suno Audios Generation ou l'API Suno Lyrics Generation.

Ce document détaillera les instructions d'intégration de l'API Suno Tasks, vous aidant à intégrer facilement et à tirer pleinement parti de la puissance de cette API. Grâce à l'API Suno Tasks, vous pouvez facilement interroger l'état d'exécution des tâches de l'API Suno Lyrics Generation ou de l'API Suno Audios Generation.

## Processus de demande

Pour utiliser l'API Suno Audios Generation, commencez par obtenir votre token API sur le [tableau de bord Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour le garder en réserve.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion vous invitant à vous inscrire et à vous connecter, après quoi vous serez automatiquement renvoyé à la page actuelle.

**Un seul token API suffit pour appeler tous les services de la plateforme, sans avoir à en demander un pour chaque service.** La première demande vous donnera un quota gratuit pour une expérience sans frais ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans le [tableau de bord](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Exemple de demande

L'API Suno Tasks peut être utilisée pour interroger les résultats des deux API, Suno Audios Generation et Suno Lyrics Generation. Pour savoir comment utiliser l'API Suno Audios Generation, veuillez consulter la documentation [Suno Audios Generation API](https://platform.acedata.cloud/documents/suno-audios-integration). Pour savoir comment utiliser l'API Suno Lyrics Generation, veuillez consulter [Suno Lyrics Generation API](https://platform.acedata.cloud/documents/suno-lyrics-generation-integration).

Prenons un exemple avec un ID de tâche retourné par le service Suno Audios Generation. Supposons que nous ayons un ID de tâche : eae26f89-b64b-404d-a80c-761996660b1c, nous allons maintenant démontrer comment procéder en passant cet ID de tâche.

### Configuration des en-têtes de demande et du corps de la demande

**Request Headers** comprend :

- `accept` : spécifie que la réponse doit être au format JSON, ici rempli avec `application/json`.
- `authorization` : la clé pour appeler l'API, que vous pouvez sélectionner directement après la demande.

**Request Body** comprend :

- `id` : l'ID de la tâche téléchargée.
- `action` : la manière d'opérer sur la tâche.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/suno/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "eae26f89-b64b-404d-a80c-761996660b1c",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/suno/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "eae26f89-b64b-404d-a80c-761996660b1c",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

返回结果一共有多个字段，request 字段就是发起任务时的 request body，同时response 字段是任务完成后返回的response body。字段介绍如下。

- `id`，générer cette chanson tâche de l'ID, utilisé pour identifier de manière unique cette tâche de génération de chanson.
- `request`，demande d'informations dans la tâche de chanson.
- `response`，informations de retour dans la tâche de chanson.
- `created_at`，temps de création de la tâche, horodatage Unix (secondes, flottant).
- `started_at`，temps de début d'exécution de la tâche, chaîne de temps UTC ISO-8601.
- `finished_at`，temps de fin de la tâche, horodatage Unix (secondes, flottant). Ce champ n'est pas retourné si la tâche n'est pas terminée.
- `elapsed`，temps d'exécution de la tâche, unité en secondes (flottant, conservé à 3 décimales). Ce champ n'est pas retourné si la tâche n'est pas terminée.

## Gestion des erreurs

Lors de l'appel de l'API, si une erreur se produit, l'API renverra le code d'erreur et les informations correspondantes. Par exemple :

- `400 token_mismatched` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `400 api_not_implemented` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `401 invalid_token` : Non autorisé, jeton d'autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de taux.
- `500 api_error` : Erreur interne du serveur, quelque chose s'est mal passé sur le serveur.

### Exemple de réponse d'erreur

