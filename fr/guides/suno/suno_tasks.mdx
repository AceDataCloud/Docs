La principale fonction de l’API Suno Tasks est de consulter le statut d’exécution d’une tâche en saisissant l’ID de tâche généré par l’API Suno Audios Generation ou l’API Suno Lyrics Generation.

Ce document présentera en détail les instructions d’intégration de l’API Suno Tasks, afin de vous aider à intégrer facilement et à exploiter pleinement les puissantes fonctionnalités de cette API. Grâce à l’API Suno Tasks, vous pouvez facilement consulter le statut d’exécution des tâches de l’API Suno Lyrics Generation ou de l’API Suno Audios Generation.

## Processus de demande

Pour utiliser l’API Suno Audios Generation, accédez d’abord à la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token, à conserver pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter. Une fois cette étape terminée, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir besoin d’effectuer une demande séparée pour chaque service.** Une première demande offre un quota gratuit permettant une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger votre solde universel dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [API Suno Audios Generation →](https://platform.acedata.cloud/documents/suno-audios)

## Exemple de requête

L’API Suno Tasks peut être utilisée pour consulter les résultats des deux API Suno Audios Generation et Suno Lyrics Generation. Pour savoir comment utiliser l’API Suno Audios Generation, veuillez consulter la documentation [API Suno Audios Generation](https://platform.acedata.cloud/documents/suno-audios-integration). Pour savoir comment utiliser l’API Suno Lyrics Generation, veuillez consulter [API Suno Lyrics Generation](https://platform.acedata.cloud/documents/suno-lyrics-generation-integration).

Nous prenons comme exemple un ID de tâche renvoyé par le service API Suno Audios Generation, afin de démontrer comment utiliser cette API. Supposons que nous avons un ID de tâche : eae26f89-b64b-404d-a80c-761996660b1c, nous allons ensuite démontrer comment en transmettant un ID de tâche.

### Définir les en-têtes et le corps de la requête

Les **Request Headers** comprennent :

- `accept` : spécifie la réception de résultats de réponse au format JSON ; renseignez ici `application/json`.
- `authorization` : la clé pour appeler l’API, qui peut être directement sélectionnée dans une liste déroulante après la demande.

Le **Request Body** comprend :

- `id` : l’ID de la tâche téléversée.
- `action` : le mode d’opération sur la tâche.

La configuration est illustrée ci-dessous :

<p><img src="https://cdn.acedata.cloud/uo7t6n.png" width="500" className="m-auto" /></p>

### Exemple de code

Vous pouvez constater que le code dans différents langages a déjà été généré automatiquement sur le côté droit de la page, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/p6vi9o.png" width="500" className="m-auto" /></p>

Voici quelques exemples de code :

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/suno/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "eae26f89-b64b-404d-a80c-761996660b1c",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/suno/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "eae26f89-b64b-404d-a80c-761996660b1c",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Le résultat renvoyé contient plusieurs champs. Le champ `request` correspond au corps de la requête lors du lancement de la tâche, tandis que le champ `response` correspond au corps de la réponse renvoyée une fois la tâche terminée. Les champs sont décrits ci-dessous.

- `id`，l’ID de la tâche de génération de cette chanson, utilisé pour identifier de manière unique cette tâche de génération de chanson.
- `request`，les informations de requête dans la tâche de requête de chanson.
- `response`，les informations de réponse dans la tâche de requête de chanson.
- `created_at`，l’heure de création de la tâche, horodatage Unix (secondes, flottant).
- `started_at`，l’heure à laquelle la tâche commence à être exécutée, horodatage Unix (secondes, flottant).
- `finished_at`，l’heure de fin de la tâche, horodatage Unix (secondes, flottant). Ce champ n’est pas renvoyé lorsque la tâche n’est pas terminée.
- `elapsed`，le temps d’exécution de la tâche, en secondes (flottant, conservant 3 décimales). Ce champ n’est pas renvoyé lorsque la tâche n’est pas terminée.

- `ids`：le tableau des ID de tâches téléversés.
- `action`：le mode d’opération sur les tâches.

## Gestion des erreurs

Lors de l'appel de l'API, en cas d'erreur, l'API renverra le code d'erreur et les informations correspondants. Par exemple :

- `400 token_mismatched`：Requête incorrecte, peut-être en raison de paramètres manquants ou non valides.
- `400 api_not_implemented`：Requête incorrecte, peut-être en raison de paramètres manquants ou non valides.
- `401 invalid_token`：Non autorisé, jeton d'autorisation non valide ou manquant.
- `429 too_many_requests`：Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error`：Erreur interne du serveur, quelque chose s'est mal passé sur le serveur.

### Exemple de réponse d'erreur

