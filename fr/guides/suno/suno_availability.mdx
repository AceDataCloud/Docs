---
title: "API de vérification de disponibilité des audios et des voix Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` accepte un ID de ressource. Pour vérifier une chanson, transmettez `audio_id` ; pour vérifier une voix, transmettez `persona_id` ; l’un des deux est obligatoire. La vérification se termine de manière synchrone, nécessite un jeton API et ne déduit actuellement pas de Credits.

## Requête

`audio_id` provient d’une tâche de chanson terminée et peut être utilisé pour une vérification avant de poursuivre ou de reprendre une chanson.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

`persona_id` provient du résultat de création d’une voix. Utilisez l’application d’origine et l’identité de l’appelant, puis envoyez le corps de requête suivant sur une route de création prenant en charge les requêtes de voix.

```json
{"persona_id":"33333333-3333-4333-8333-333333333333"}
```

## Réponse

Les deux types de requêtes utilisent la même réponse de succès. `data.id` est l’ID de la ressource de cette requête.

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

`available: true` indique que cette vérification a obtenu des preuves positives. Pour les voix, la vérification valide l’appartenance de la création et confirme que le compte associé est actuellement signalé comme étant en ligne. Le résultat réel de génération reste soumis à la tâche de génération.

Les voix clonées privées créées via `/suno/voices` dépendent du compte créateur. Lorsqu’il est confirmé que ce compte est actuellement hors ligne, l’interface renvoie HTTP 200, avec un exemple de `data` ci-dessous.

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

Le client peut marquer cette voix comme actuellement indisponible et vérifier à nouveau plus tard.

Lorsqu’il est impossible de confirmer, l’interface renvoie HTTP 503 et `availability_unknown`, par exemple si la ressource est introuvable, si les anciens enregistrements ne contiennent pas la route de création ou si la requête expire. Les styles de chanteurs publics peuvent être utilisés entre comptes et renvoient également 503 lorsque le compte créateur est hors ligne. Les requêtes de chansons renvoient toujours `available: true` uniquement lorsque leur disponibilité est confirmée.

Chaque requête n’envoie qu’un UUID valide. Toutes les routes renvoient HTTP 400 lorsqu’elles reçoivent une requête avec deux ID ou avec les deux ID absents. Les routes prenant uniquement en charge les requêtes de chansons renvoient HTTP 400 lorsqu’elles reçoivent une requête contenant uniquement `persona_id`. En cas de HTTP 429, veuillez réduire la fréquence des requêtes.
