---
title: "API de vérification de disponibilité audio Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` recherche, selon `audio_id`, des preuves positives indiquant que l'audio peut continuer à être traité sur la ligne actuelle. Peut être appelé avant des opérations telles que la continuation, la reprise, etc. ; le résultat reflète uniquement l'état au moment de la vérification et ne garantit pas qu'une opération spécifique réussira forcément. Cette interface renvoie une réponse synchrone, nécessite un Token API et ne déduit actuellement pas de Credits.

`audio_id` est l'ID de chanson renvoyé par une tâche Suno terminée, et non le `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Exemple de réponse en cas de succès :

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

Lorsque la vérification réussit, `data.available` ne peut être que `true`. L'état « hors ligne » renvoyé par certaines lignes ne peut pas prouver que des opérations ultérieures telles que la continuation ne peuvent pas réussir ; par conséquent, lorsque cette interface ne peut pas confirmer, elle renvoie `503 availability_unknown` et ne renvoie pas `false`. Un format `audio_id` incorrect renvoie 400, et la limitation de débit ou une défaillance en amont renvoie également une réponse d'erreur. L'état peut encore changer entre la fin de la vérification et l'opération réelle.
