---
title: "API de vérification de disponibilité audio Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` recherche, en fonction de `audio_id`, des preuves positives indiquant que l’audio peut continuer à être traité sur l’itinéraire actuel. Peut être appelé avant des opérations telles que la continuation ou la reprise ; le résultat reflète uniquement l’état au moment de la vérification et ne garantit pas qu’une opération donnée réussira. Cette interface renvoie une réponse synchrone, nécessite un API Token et ne déduit actuellement aucun Credits.

`audio_id` est l’ID de la chanson renvoyé par une tâche Suno terminée, et non `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Exemple de réponse réussie :

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

Lorsque la vérification réussit, `data.available` est `true` ; lorsqu’elle ne peut pas être confirmée, `503 availability_unknown` est renvoyé et `false` n’est pas renvoyé. Un format `audio_id` incorrect renvoie une erreur 400 ; la limitation de débit ou une anomalie du service renvoie également une réponse d’erreur. L’état peut encore changer entre la fin de la vérification et l’opération réelle.
