Cet article présente l'intégration et l'utilisation de l'API de requête de tâches MiniMax H3. Cette interface est utilisée pour interroger, lister en masse ou supprimer des tâches asynchrones créées par l'[API de génération de vidéos MiniMax H3](/documents/minimax-videos-integration).

## Processus de demande

Pour utiliser l'API de requête de tâches MiniMax H3, commencez par obtenir votre Token API sur le [tableau de bord Ace Data Cloud](https://platform.acedata.cloud/console/applications) et conservez-le en lieu sûr.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter, après quoi vous serez automatiquement renvoyé à la page actuelle.

**Un Token API suffit pour appeler tous les services de la plateforme, sans avoir besoin de demander un pour chaque service.** La première demande vous donnera un quota gratuit pour une expérience sans frais ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans le [tableau de bord](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [API de requête de tâches MiniMax H3 →](https://platform.acedata.cloud/documents/minimax-tasks-integration)

Lors de la requête de tâches, vous devez utiliser le même Token que celui utilisé pour créer la tâche. Il est conseillé de sauvegarder le Token en tant que variable d'environnement, sans l'écrire dans le code source ou le soumettre au dépôt :

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Aperçu de l'API

- **Base URL** : `https://api.acedata.cloud`
- **Endpoint** : `POST /minimax/tasks`
- **Méthode d'authentification** : Inclure `authorization: Bearer {token}` dans l'en-tête HTTP
- **En-têtes de requête** :
  - `accept: application/json`
  - `content-type: application/json`
- **Interroger une tâche unique** : `action=retrieve`, passer `id`
- **Interroger des tâches en masse** : `action=retrieve_batch`, filtrer par ID de tâche, plage de temps et conditions de pagination
- **Supprimer une tâche** : `action=delete`, passer `id`
- **Explication de la facturation** : La requête de tâches est gratuite et ne génère pas de facturation répétée

Après la création de la vidéo, il est nécessaire de sauvegarder `task_id`. Il est recommandé de vérifier toutes les 10 secondes jusqu'à ce que la tâche atteigne un état terminal.

## Paramètres de requête

| Paramètre            | Type      | Obligatoire | Actions applicables         | Description                                           |
| ------------------- | --------- | ----------- | --------------------------- | ---------------------------------------------------- |
| `action`            | string    | Non         | Tous                        | `retrieve`, `retrieve_batch` ou `delete` ; par défaut `retrieve` |
| `id`                | string    | Obligatoire sous condition | `retrieve`, `delete`      | ID de la tâche unique                                  |
| `ids`               | string[]  | Non         | `retrieve_batch`           | Ne renvoie que les ID de tâches spécifiés ; omis, les tâches sont listées selon d'autres critères |
| `limit`             | integer   | Non         | `retrieve_batch`           | Nombre maximum de tâches à renvoyer cette fois-ci     |
| `offset`            | integer   | Non         | `retrieve_batch`           | Nombre de tâches à ignorer dans la liste des résultats, utilisé pour la pagination |
| `created_at_min`    | number    | Non         | `retrieve_batch`           | Limite inférieure de temps de création, timestamp Unix, en secondes |
| `created_at_max`    | number    | Non         | `retrieve_batch`           | Limite supérieure de temps de création, timestamp Unix, en secondes |

Les usages des trois actions sont les suivants :

| `action`            | Usage                          | Paramètres nécessaires                  | Structure de réponse                             |
| ------------------- | ------------------------------ | -------------------------------------- | ----------------------------------------------- |
| `retrieve`          | Interroger l'état et le résultat d'une tâche | `id`                                   | `{ "task": {...} }`                             |
| `retrieve_batch`    | Interroger en masse par ID de tâche, temps et conditions de pagination | Paramètres optionnels `ids`, plage de temps, `offset`, `limit` | `{ "items": [...], "total": number }`         |
| `delete`            | Annuler ou supprimer un enregistrement de tâche selon l'état actuel de la tâche | `id`                                   | `{ "id": "...", "deleted": true }`            |

## Interroger une tâche unique

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f5977217-ed2c-40da-adbe-93d08235618f"
  }'
```

## État de la tâche

| `status`    | Signification                     | Traitement côté client               |
| ----------- | --------------------------------- | ------------------------------------ |
| `queued`    | En attente dans la file d'attente | Continuer à interroger               |
| `running`   | En cours de génération            | Continuer à interroger               |
| `succeeded` | Génération réussie                | Lire `task.content.url`, arrêter l'interrogation |
| `failed`    | Échec de la génération            | Lire `task.error`, arrêter l'interrogation |
| `cancelled` | Tâche annulée                    | Arrêter l'interrogation              |

`succeeded`, `failed` et `cancelled` sont tous des états terminaux. Ne continuez pas à interroger après avoir atteint un état terminal.

## Champs de réponse de la tâche

| Champ                      | Type      | Description                                      |
| ------------------------- | --------- | ------------------------------------------------ |
| `id`                      | string    | ID de la tâche                                   |
| `model`                   | string    | Modèle utilisé pour la tâche, actuellement `MiniMax-H3` |
| `status`                  | string    | État actuel de la tâche                          |
| `error.code`              | string    | Code d'erreur en cas d'échec, renvoyé uniquement en cas d'échec |
| `error.message`           | string    | Raison de l'échec, renvoyée uniquement en cas d'échec |
| `created_at`              | integer   | Date de création, timestamp Unix, en secondes    |
| `updated_at`              | integer   | Date de la dernière mise à jour de l'état, timestamp Unix, en secondes |
| `content.url`             | string    | URL de la vidéo après succès                     |
| `resolution`              | string    | Résolution de sortie, `768P` ou `2K`            |
| `duration`                | integer   | Durée de la vidéo de sortie, en secondes         |
| `usage.total_seconds`     | integer   | Montant total facturé, égal à la somme des secondes de vidéo d'entrée et de sortie |
| `usage.input_seconds`     | integer   | Montant facturé pour la vidéo d'entrée           |
| `usage.output_seconds`    | integer   | Montant facturé pour la vidéo de sortie          |
| `usage.input_image_count` | integer   | Nombre d'images d'entrée dans la facturation     |
| `ratio`                   | string    | Rapport largeur/hauteur de sortie ; en cas d'utilisation de `adaptive`, ce résultat prévaut |
| `task_type`               | string    | Tâche de génération vidéo est `generation`      |
| `modality`                | string    | Tâche vidéo est `video`                          |

## Exemple complet de polling en Python
以下代码从环境变量读取 Token，创建任务后每隔 10 秒查询一次：

```python
import os
import time

import requests

BASE_URL = "https://api.acedata.cloud"
HEADERS = {
    "Authorization": f"Bearer {os.environ['ACEDATACLOUD_API_KEY']}",
    "Content-Type": "application/json",
}

create_response = requests.post(
    f"{BASE_URL}/minimax/videos",
    headers=HEADERS,
    json={
        "model": "MiniMax-H3",
        "content": [
            {
                "type": "text",
                "text": "Au bord de la mer au petit matin, un voilier blanc navigue sur une mer calme, la caméra se déplace lentement.",
            }
        ],
        "resolution": "768P",
        "duration": 4,
        "ratio": "16:9",
    },
    timeout=30,
)
create_response.raise_for_status()
task_id = create_response.json()["task_id"]

while True:
    time.sleep(10)
    query_response = requests.post(
        f"{BASE_URL}/minimax/tasks",
        headers=HEADERS,
        json={"action": "retrieve", "id": task_id},
        timeout=30,
    )
    query_response.raise_for_status()
    task = query_response.json()["task"]
    print(f"task={task_id} status={task['status']}")

    if task["status"] == "succeeded":
        print(f"video_url={task['content']['url']}")
        break
    if task["status"] in ("failed", "cancelled"):
        raise RuntimeError(task.get("error") or task["status"])
```

La production doit avoir un délai d'attente total pour le polling, et utiliser un backoff exponentiel pour `429` et les `5xx` temporaires. Un timeout réseau ne signifie pas un échec de génération, vous pouvez continuer à interroger avec le même `task_id`.

## Requête en lot

Spécifiez plusieurs ID de tâches :

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "retrieve_batch",
    "ids": ["TASK_ID_1", "TASK_ID_2"],
    "offset": 0,
    "limit": 20
  }'
```

Lister les tâches par plage de temps :

```json
{
  "action": "retrieve_batch",
  "created_at_min": 1786000000,
  "created_at_max": 1786200000,
  "offset": 0,
  "limit": 20
}
```

Dans la réponse en lot, les `items` utilisent le même champ de tâche que la requête de tâche unique, `total` est le nombre total de tâches correspondant aux critères de filtrage :

```json
{
  "items": [
    {
      "id": "TASK_ID_1",
      "model": "MiniMax-H3",
      "status": "running",
      "resolution": "2K",
      "duration": 5,
      "ratio": "adaptive",
      "task_type": "generation",
      "modality": "video"
    }
  ],
  "total": 1
}
```

La fenêtre de requête de tâche est de 7 jours. Les `task_id` dépassant cette fenêtre peuvent renvoyer des tâches invalides ; le système commercial doit enregistrer l'ID lors de la création de la tâche et persister l'URL de résultat en temps opportun après le succès.

## Annuler ou supprimer une tâche

```bash
curl -X POST 'https://api.acedata.cloud/minimax/tasks' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "action": "delete",
    "id": "YOUR_TASK_ID"
  }'
```

L'action dépend de l'état actuel de la tâche :

| État actuel     | Comportement                     |
| --------------- | -------------------------------- |
| `queued`        | Annuler une tâche non commencée  |
| `succeeded`     | Supprimer l'enregistrement de la tâche |
| `failed`        | Supprimer l'enregistrement de la tâche |
| `running`       | Suppression ou annulation non autorisée, renvoie une erreur |
| `cancelled`     | Répétition de l'opération non autorisée, renvoie une erreur  |

Exemple de suppression réussie :

```json
{
  "id": "YOUR_TASK_ID",
  "deleted": true
}
```

La suppression d'une tâche ne révoque pas la facturation déjà effectuée et ne garantit pas que les copies vidéo enregistrées soient également supprimées.

## Réponses d'échec et dépannage

Les tâches échouées renvoient toujours un objet de tâche avec HTTP 200, et la raison est donnée dans `task.error` :

```json
{
  "task": {
    "id": "YOUR_TASK_ID",
    "model": "MiniMax-H3",
    "status": "failed",
    "error": {
      "code": "1026",
      "message": "la description de la vidéo contient un contenu sensible"
    },
    "task_type": "generation",
    "modality": "video"
  }
}
```

Lorsque l'interface elle-même renvoie `400`, vérifiez `action` et les paramètres de condition, `401` indique que le Token est invalide, `429` indique que les requêtes sont trop fréquentes, `500` indique que le service est temporairement indisponible. Les tâches échouées ne sont pas facturées ; les tâches réussies enregistrent l'utilisation selon le `usage` final.
