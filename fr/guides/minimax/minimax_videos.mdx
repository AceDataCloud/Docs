Cet article présente l'intégration et l'utilisation de l'API de génération de vidéos MiniMax H3. Cette interface prend en charge la génération de vidéos à partir de texte, le contrôle des images de début et de fin, ainsi que la génération de vidéos de référence multimodales, en utilisant une structure `content` multimodale V2 unifiée pour créer des tâches.

## Processus de demande

Pour utiliser l'API de génération de vidéos MiniMax H3, commencez par obtenir votre API Token sur le [tableau de bord Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour le conserver en sécurité.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter, après quoi vous serez automatiquement renvoyé à la page actuelle.

**Un seul API Token suffit pour appeler tous les services de la plateforme, sans avoir besoin de demander séparément pour chaque service.** La première demande vous donnera un quota gratuit pour une expérience sans frais ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans le [tableau de bord](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [API de génération de vidéos MiniMax H3 →](https://platform.acedata.cloud/documents/minimax-videos-integration)

Il est conseillé de sauvegarder le Token en tant que variable d'environnement, ne pas l'écrire dans le code source ou le soumettre dans le dépôt :

```bash
export ACEDATACLOUD_API_KEY="YOUR_API_KEY"
```

## Vue d'ensemble de l'API

- **Base URL** : `https://api.acedata.cloud`
- **Endpoint** : `POST /minimax/videos`
- **Méthode d'authentification** : Inclure `authorization: Bearer {token}` dans l'en-tête HTTP
- **En-têtes de requête** :
  - `accept: application/json`
  - `content-type: application/json`
- **Modèle (model)** : `MiniMax-H3`
- **Structure d'entrée** : Transmettre le texte, les images, les vidéos et l'audio via `content`
- **Mode de sortie** : Par défaut, attendre la génération complète et retourner la `task` complète ; en passant `async: true` ou `callback_url`, retourner immédiatement `task_id` et `trace_id`
- **Consultation des résultats** : Obtenir l'état et le produit final via [l'API de consultation des tâches MiniMax H3](/documents/minimax-tasks-integration)
- **Callback asynchrone** : Optionnel, recevoir le résultat final de la tâche via `callback_url`

Vous n'avez pas besoin de transmettre `action` pour choisir le mode de génération, l'API déterminera automatiquement l'utilisation en fonction des types de matériel et de `role` dans `content`.

## Scénarios appropriés

| Scénario         | Combinaison d'entrée                  | Utilisation courante                      |
| -------------- | ---------------------------------- | ------------------------------------- |
| Vidéo à partir de texte       | Texte                              | Création publicitaire, répétition de scènes, vidéos courtes, plans d'ambiance        |
| Vidéo à partir de l'image de début | Texte + Image de début             | Faire bouger naturellement les images de produits, affiches, photos de personnes ou illustrations      |
| Vidéo de fin / Vidéo de début et de fin | Texte + Image de fin, ou Texte + Image de début + Image de fin | Contrôler l'introduction et la conclusion, les transitions, les changements de croissance et les comparaisons avant/après      |
| Vidéo de référence multimodale   | Texte + Image / Vidéo / Audio de référence   | Maintenir la cohérence des personnages et des produits, reproduire des actions, des mouvements de caméra, des tonalités ou des rythmes de montage |

## Processus d'appel

Par défaut, si `async` n'est pas transmis, `/minimax/videos` attendra la génération complète et retournera directement la `task` complète. Si vous devez libérer la connexion immédiatement, passez `async: true` ou `callback_url` :

1. Sauvegardez `task_id` et `trace_id` dans la réponse immédiate.
2. Si aucun rappel n'est configuré, interrogez `/minimax/tasks` toutes les 10 secondes environ.
3. Lorsque `task.status` devient `succeeded`, récupérez la vidéo à partir de `task.content.url`.
4. Lorsque l'état est `failed` ou `cancelled`, arrêtez le polling et lisez `task.error`.

## Paramètres de requête de niveau supérieur

| Paramètre             | Type       | Obligatoire   | Valeur par défaut | Description                                                |
| ------------------ | -------- | ------------ | ---------------- | ------------------------------------------------------- |
| `model`            | string   | Oui          | -                | Fixé à `MiniMax-H3`                                      |
| `content`          | object[] | Oui          | -                | Tableau de contenu multimodal, doit contenir un élément `text` non vide                         |
| `resolution`       | string   | Oui          | -                | `768P` ou `2K`                                         |
| `duration`         | integer  | Oui          | -                | Durée de génération, entier de 4 à 15 secondes                                     |
| `ratio`            | string   | Obligatoire si applicable | `adaptive` | `adaptive`, `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16` |
| `async`            | boolean  | Non          | `false`          | `true` pour retourner immédiatement l'identifiant de la tâche, obtenir les résultats via l'interface de tâche                       |
| `callback_url`     | string   | Non          | -                | URL de rappel publique pour recevoir le résultat final de la tâche ; activé automatiquement en mode asynchrone                     |

Les règles pour `ratio` dépendent du flux de travail :

- **Vidéo à partir de texte** : Obligatoire, ne peut pas être `adaptive`.
- **Vidéo à partir de l'image de début, de fin ou de début et de fin** : Le format est déterminé par l'image d'entrée, il est conseillé de l'omettre ou de passer `adaptive`.
- **Vidéo de référence multimodale** : Peut être omis, par défaut `adaptive` ; peut également spécifier un ratio fixe.

L'API n'accepte pas les anciens champs ou les champs de compatibilité, tels que `prompt`, `image_urls`, `audio_urls`, `messages` et `first_frame_image`. Lors de la réception de ce type de paramètres erronés, veuillez supprimer les anciens champs et migrer vers `content` ; par exemple, changer `"prompt": "Un chat agitant la patte"` en `"content": [{"type": "text", "text": "Un chat agitant la patte"}]`. Ne pas envoyer simultanément les deux formats, ancien et nouveau.

## Paramètres des éléments de contenu

Chaque élément de contenu doit avoir `type`, les autres champs étant déterminés par le type :

| `type`      | Champ de données            | `role`            | Description                                     |
| ----------- | --------------- | ----------------- | -------------------------------------- |
| `text`      | `text`          | Ne pas transmettre    | Chaque requête doit contenir un élément de texte non vide, maximum 7000 caractères             |
| `image_url` | `image_url.url` | `first_frame`     | Image de début ; si une seule image et `role` omis, elle est également traitée comme image de début         |
| `image_url` | `image_url.url` | `last_frame`      | Image de fin ; peut être utilisée seule ou combinée avec `first_frame` pour contrôler le début et la fin |
| `image_url` | `image_url.url` | `reference_image` | Image de référence pour le sujet, le personnage, le produit, les vêtements, la scène ou le style                    |
| `video_url` | `video_url.url` | `reference_video` | Vidéo de référence pour l'action, le mouvement de caméra, la performance ou la structure de montage                        |
| `audio_url` | `audio_url.url` | `reference_audio` | Audio de référence pour la tonalité, le dialogue, la musique ou le rythme                          |

Les adresses médias prennent en charge trois formes :

- URL HTTPS accessibles publiquement, recommandées pour les gros fichiers.
- `mm_file://{file_id}`, référence à un fichier déjà téléchargé ou à un résultat existant.
- URI de données Base64 correspondant au type de média. Base64 augmentera la taille d'environ un tiers, veuillez vous assurer que l'ensemble du corps de la requête ne dépasse pas 64 Mo.

## Spécifications et limites de matériel
| Matériau  | Format                                        | Limite par fichier | Taille / Durée                                                       | Limite de quantité                   |
| --- | ------------------------------------------- | --------- | --------------------------------------------------------------- | --------------------------- |
| Image  | JPG, JPEG, PNG, WEBP, HEIC, HEIF                 | Ne pas dépasser 30 Mo | Largeur et hauteur de 256-5760 px ; rapport d'aspect de 0,4-2,5                                    | Maximum 1 image de première image, maximum 1 image de dernière image, maximum 9 images de référence |
| Vidéo  | MP4, MOV ; H.264/AVC ou H.265/HEVC ; piste audio AAC ou MP3 | Ne pas dépasser 50 Mo | Chaque segment de 2-15 secondes, total ne dépassant pas 15 secondes ; largeur et hauteur de 256-5760 px ; rapport d'aspect de 0,4-2,5 ; 23,976-60 fps | Maximum 3 segments de vidéo de référence                  |
| Audio  | WAV, MP3                                     | Ne pas dépasser 15 Mo | Chaque segment de 2-15 secondes, total ne dépassant pas 15 secondes                                            | Maximum 3 segments de son de référence                  |

Dans les scènes de référence multimodales, le nombre total de fichiers d'images, de vidéos et d'audios ne doit pas dépasser 12. Les scènes de première et de dernière image et les scènes de matériel de référence sont mutuellement exclusives : une fois que `reference_image`, `reference_video` ou `reference_audio` est utilisé, `first_frame` ou `last_frame` ne peut plus être utilisé, et vice versa.

## Démonstration de capacités de production

Ce qui suit n'est pas un concept ou un matériel de remplacement, mais une entrée de référence réelle et une sortie vidéo de l'échantillon de capacités de production officiel MiniMax H3. Trois ensembles de cas couvrent respectivement des courts métrages de marque, des récits en direct et du commerce électronique de mode, adaptés pour évaluer les capacités les plus critiques du modèle dans la production commerciale.

| Capacité       | Observation clé                        |
| -------- | --------------------------- |
| Cohérence des personnages et des visages | Stabilité des traits, des coiffures, du maquillage et de l'aura des personnages après des changements de caméra     |
| Performance faciale     | Regard, micro-expressions, tension émotionnelle et mouvements naturels de la tête en gros plan      |
| Maintien de la structure des produits   | Contours, matériaux, relations de port et réflexions des produits tels que lunettes, sacs à main    |
| Exécution visuelle de la marque   | Atmosphère de la scène, grain cinématographique, couleurs, logo et rythme de montage unifiés |
| Narration cinématographique    | Changements de plan, mise en scène des personnages, mouvements de caméra, rythme et son peuvent-ils former un paragraphe complet  |

Ici, la "capacité faciale" fait référence à la cohérence de l'apparence des personnages, aux détails du visage et au contrôle de la performance dans la génération vidéo, et non à l'identification, à la comparaison de visages ou à l'interface de changement de visage.

## Vidéo générée par texte

Lorsqu'il n'y a qu'un seul élément texte, il s'agit d'une vidéo générée par texte. Elle convient pour générer directement des images à partir d'idées, de scénarios ou de descriptions de plans. Les mots-clés peuvent être organisés dans l'ordre "sujet + action + scène + plan + lumière + son".

```bash
curl -X POST 'https://api.acedata.cloud/minimax/videos' \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MiniMax-H3",
    "content": [
      {
        "type": "text",
        "text": "Publicité de parfum de niveau cinématographique de 15 secondes : sur les rochers noirs de la côte au petit matin, une bouteille de parfum transparente est entourée de brume et de vagues. Gros plan sur les gouttes d'eau et la réfraction du verre, la caméra s'élève lentement du gros plan du produit vers l'immense mer ; teintes argentées et bleues, lumière naturelle réaliste, élégance retenue, finissant par un arrêt sur le produit."
      }
    ],
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }'
```

Le mode synchrone par défaut renverra la tâche complète une fois la génération terminée :

```json
{
  "task": {
    "id": "f5977217-ed2c-40da-adbe-93d08235618f",
    "model": "MiniMax-H3",
    "status": "succeeded",
    "content": { "url": "https://cdn.acedata.cloud/minimax/f5977217.mp4" },
    "resolution": "2K",
    "duration": 15,
    "ratio": "16:9"
  }
}
```

Si la requête inclut `"async": true`, l'interface renvoie immédiatement :

```json
{
  "task_id": "f5977217-ed2c-40da-adbe-93d08235618f",
  "trace_id": "trace_7f8c2b1a"
}
```

## Vidéo générée à partir de la première image

Marquer l'image comme `first_frame`, le modèle commencera à générer à partir de cette image. Cela convient pour donner vie naturellement à des affiches, des images de produits, des images de personnages et des œuvres photographiques.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "Le personnage respire naturellement et regarde par la fenêtre, l'ourlet de son vêtement est agité par la brise, la caméra avance lentement."
    },
    {
      "type": "image_url",
      "image_url": {
        "url": "https://cdn.acedata.cloud/b1c82e4937.png"
      },
      "role": "first_frame"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

## Vidéo avec image de fin et de début
只提供 `last_frame` peut permettre au modèle de générer naturellement jusqu'à l'image spécifiée ; en fournissant à la fois `first_frame` et `last_frame`, il est possible de contrôler clairement le point de départ et le point d'arrivée. Cela convient aux transitions, aux changements de forme, aux processus de croissance ou aux comparaisons avant-après d'un produit.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "La fille grandit naturellement de l'enfance à la jeunesse, le temps s'écoule en douceur, le personnage reste toujours au centre de l'image"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_FIRST_FRAME_URL" },
      "role": "first_frame"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_LAST_FRAME_URL" },
      "role": "last_frame"
    }
  ],
  "resolution": "2K",
  "duration": 5,
  "ratio": "adaptive"
}
```

Les dimensions et le rapport hauteur/largeur de la première et de la dernière image doivent être aussi cohérents que possible, et les différences de position du sujet, de composition et de lumière ne doivent pas être trop grandes, afin d'obtenir une transition naturelle plus facilement.

## Référence multimodale pour la génération de vidéos

Les matériaux de référence peuvent être utilisés en combinaison : les images de référence contrôlent l'apparence des personnages ou des produits, les vidéos de référence contrôlent les actions et les mouvements de caméra, et les audios de référence contrôlent le ton des dialogues, la musique ou le rythme du montage. Les mots-clés doivent clairement indiquer ce que chaque type de matériel doit contrôler, afin d'éviter de simplement télécharger des matériaux sans établir de relations.

```json
{
  "model": "MiniMax-H3",
  "content": [
    {
      "type": "text",
      "text": "Maintenir les traits du visage, la coiffure et les vêtements du personnage de référence, réaliser un court-métrage de mode selon les actions de performance dans la vidéo de référence ; le rythme des plans suit l'audio de référence, les gros plans mettent en avant les expressions faciales naturelles"
    },
    {
      "type": "image_url",
      "image_url": { "url": "YOUR_CHARACTER_IMAGE_URL" },
      "role": "reference_image"
    },
    {
      "type": "video_url",
```

## Notification de rappel

L'entrée de `callback_url` active automatiquement le mode asynchrone : l'interface de création renvoie immédiatement `task_id` et `trace_id`, et envoie les résultats finaux à cette adresse par POST une fois la tâche terminée, la structure étant identique à celle de la réponse de requête de tâche.

L'état final dans le rappel est `succeeded`, `failed` ou `cancelled`. Même en utilisant des rappels, il est conseillé de conserver `task_id` pour permettre une requête proactive ou une compensation en cas de notification manquée.

## Erreurs courantes

| Code d'état HTTP | Signification           | Suggestions de traitement                           |
| -------- | ------------ | ------------------------------ |
| `400`    | Erreur de paramètres ou combinaison de matériaux non valide | Vérifiez les champs obligatoires, `role`, le nombre et le format des matériaux          |
| `401`    | Token manquant ou invalide  | Vérifiez `Authorization: Bearer ...` |
| `402`    | Solde ou quota insuffisant      | Complétez le solde général dans la console                     |
| `422`    | Vérification de sécurité du contenu non réussie    | Ajustez les mots-clés ou les matériaux puis soumettez à nouveau                  |
| `429`    | Trop de demandes fréquentes       | Réessayez après un retour exponentiel ; il est conseillé d'attendre environ 10 secondes entre les requêtes de tâche         |
| `500`    | Service temporairement indisponible      | Conservez les informations de demande, réessayez plus tard                    |

Un `task.status: succeeded` dans la réponse synchrone indique que la vidéo a été générée ; la confirmation asynchrone ne représente que le fait que la tâche est entrée dans la file d'attente. Seules les tâches finalement réussies seront facturées, la requête de tâche elle-même est gratuite et ne sera pas facturée à nouveau.
