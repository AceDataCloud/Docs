OpenAI ChatGPT est un système de dialogue IA très puissant qui, à condition de saisir un prompt, peut générer des réponses fluides et naturelles en quelques secondes seulement. ChatGPT se distingue dans le secteur par ses excellentes capacités de compréhension et de génération du langage. Aujourd’hui, ChatGPT est déjà largement utilisé dans divers secteurs et domaines, et son influence devient de plus en plus significative. Qu’il s’agisse de conversations quotidiennes, d’écriture créative, ou encore de conseils professionnels et de programmation de code, ChatGPT peut fournir une assistance intelligente étonnante, améliorant considérablement l’efficacité au travail et la créativité humaines.

Ce document présente principalement le processus d’utilisation des opérations de l’API OpenAI Chat Completion. Grâce à elle, nous pouvons facilement utiliser la fonctionnalité de dialogue de l’OpenAI ChatGPT officiel.

## GPT-6.1 Sol

Utilisez `model: "gpt-6.1-sol"` pour sélectionner ce modèle. Prend en charge la sortie en streaming, les appels de fonctions, les sorties structurées et les entrées d’images. Au cours de la première semaine d’ouverture, il est disponible uniquement pour les détenteurs vérifiés d’ACE T1+ (au moins 100 000 ACE) ou les utilisateurs autorisés ; l’heure d’ouverture précise dépend de l’invite d’accès dans la console.

Les niveaux de raisonnement pris en charge sont `low`, `medium`, `high`, `xhigh` et `max` ; `none` et `minimal` ne sont pas encore pris en charge. Il est recommandé de commencer avec `reasoning_effort: "low"`. Lorsque l’entrée dépasse 272 000 tokens, le tarif de long contexte s’applique à l’ensemble de la requête, et les frais sont soumis au tarif actuel de la console.

## Processus de demande

Pour utiliser l’API OpenAI Chat Completion, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token et le conserver en réserve.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter. Une fois terminé, vous reviendrez automatiquement sur la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, il n’est pas nécessaire de faire une demande séparée pour chaque service.** La première demande offre un quota gratuit permettant une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [OpenAI Chat Completion API →](https://platform.acedata.cloud/documents/openai-chat-completions)

## Utilisation de base

Ensuite, vous pouvez renseigner le contenu correspondant dans l’interface, comme illustré :

<p><img src="https://cdn.acedata.cloud/jqgg1t.png" width="400" className="m-auto" /></p>

Lors de la première utilisation de cette interface, nous devons au minimum renseigner trois éléments. Le premier est `authorization`, qui peut être sélectionné directement dans la liste déroulante. Un autre paramètre est `model`, `model` correspond à la catégorie de modèle du site officiel OpenAI ChatGPT que nous choisissons d’utiliser. Ici, nous avons principalement 20 modèles, et vous pouvez consulter les modèles que nous fournissons pour plus de détails. Le dernier paramètre est `messages`, `messages` est le tableau de prompts que nous saisissons. Il s’agit d’un tableau, ce qui signifie que plusieurs prompts peuvent être envoyés simultanément. Chaque prompt contient `role` et `content`, où `role` représente le rôle de la personne qui pose la question. Nous proposons trois identités : `user`, `assistant` et `system`. L’autre élément, `content`, est le contenu spécifique de notre question.

En même temps, vous pouvez remarquer qu’un code d’appel correspondant est généré sur la droite. Vous pouvez copier le code et l’exécuter directement, ou cliquer directement sur le bouton « Try » pour effectuer un test.

Paramètres optionnels couramment utilisés :

- `max_tokens` : limite le nombre maximal de tokens dans une seule réponse.
- `temperature` : caractère aléatoire de la génération, entre 0 et 2 ; plus la valeur est élevée, plus le résultat est divergent.
- `n` : nombre de réponses candidates générées à la fois.
- `response_format` : configuration du format de retour.

## Réponse en streaming

Cette interface prend également en charge les réponses en streaming, ce qui est très utile pour l’intégration web et permet à une page web d’obtenir un effet d’affichage caractère par caractère.

Si vous souhaitez retourner la réponse en streaming, vous pouvez modifier le paramètre `stream ` dans l’en-tête de la requête, en le définissant sur `true`.

La modification est illustrée ci-dessous, mais le code d’appel doit être modifié en conséquence pour prendre en charge la réponse en streaming.

<p><img src="https://cdn.acedata.cloud/24scd4.png" width="400" className="m-auto" /></p>

Après avoir modifié `stream` en `true`, l’API retournera les données JSON correspondantes ligne par ligne. Au niveau du code, nous devons effectuer les modifications correspondantes pour obtenir les résultats ligne par ligne.

Exemple de code d’appel Python :

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4",
    "messages": [{"role":"user","content":"hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Dialogue à plusieurs tours

Si vous souhaitez intégrer la fonctionnalité de dialogue à plusieurs tours, vous devez téléverser plusieurs mots de question dans le champ `messages`. Un exemple concret de plusieurs mots de question est présenté dans l'image ci-dessous :

<p><img src="https://cdn.acedata.cloud/oz4mar.png" width="400" className="m-auto" /></p>

Exemple de code d'appel Python :
```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"

payload = {
    "model": "gpt-4",
    "messages": [{"role":"user","content":"Hello"},{"role":"assistant","content":"Hi! How can I assist you today?"},{"role":"user","content":"What I say just now?"}]
```

## Intégration avec OpenAI-Python

L’API OpenAI Chat Completion reste compatible avec l’interface officielle OpenAI et peut être directement intégrée à l’aide du SDK officiel [OpenAI-Python](https://github.com/openai/openai-python). Cet article présentera brièvement la méthode d’utilisation.

1. Il faut d’abord mettre en place un environnement `Python` local ; vous pouvez rechercher ce processus sur Google.
2. Téléchargez et installez un environnement de développement, par exemple l’éditeur VSCode.
3. Configurez les variables d’environnement `OpenAI`.

- Dans le dossier du projet, créez un fichier nommé `.env`, puis enregistrez-le
- Contenu du fichier `.env` :

```json
OPENAI_API_KEY="sk-xxx"
OPENAI_BASE_URL="https://api.acedata.cloud/openai"  # 再次提醒：如果你使用官网OpenAI的key，不要用这个地址。
```

Remplacez `sk-xxx` par votre propre clé. `OPENAI_BASE_URL` est l’interface proxy permettant d’accéder à OpenAI.

4. Installez les paquets dont le projet dépend

```shell
pip install openai
```

Sous Mac OS, la commande est :

```shell
pip3 install openai
```

5. Créez un fichier de code source d’exemple

Supposons que nous ayons créé un exemple de code `index.py`, dont le contenu spécifique est le suivant :

```python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

response = client.chat.completions.create(
    messages=[
        {
            "role": "user",
            "content": "hello",
        }
    ],
    model="gpt-4",
)

print(response.text)
```

## Modèle visuel

gpt-4o est un grand modèle de langage multimodal développé par OpenAI ; il ajoute des capacités de compréhension visuelle sur la base de GPT-4. Ce modèle peut traiter simultanément des entrées de texte et d’images, permettant une compréhension et une génération multimodales.

Le traitement de texte avec le modèle gpt-4o est cohérent avec le contenu de l’utilisation de base présenté ci-dessus. Nous allons brièvement présenter ci-dessous comment utiliser les capacités de traitement d’images du modèle.

L’utilisation des capacités de traitement d’images du modèle gpt-4o consiste principalement à ajouter un champ `type` sur la base du contenu `content` existant. Grâce à ce champ, il est possible de savoir si le contenu téléchargé est du texte ou une image, afin d’utiliser les capacités de traitement d’images du modèle gpt-4o. Nous présenterons principalement ci-dessous l’appel de cette fonctionnalité de deux manières : Curl et Python.

- Méthode par script Curl

```
curl -X POST 'https://api.acedata.cloud/openai/chat/completions' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4o",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "What'\''s in this image?"
          },
          {
            "type": "image_url",
            "image_url": {
              "url": "https://upload.wikimedia.org/wikipedia/commons/thumb/d/dd/Gfp-wisconsin-madison-the-nature-boardwalk.jpg/2560px-Gfp-wisconsin-madison-the-nature-boardwalk.jpg"
            }
          }
        ]
      }
    ]
  }'
```

- Méthode par script Python
```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4o",
    "messages": [
        {
            "role": "user",
            "content": [
                {
                    "type": "text", "text": "What's in this image?"
                },
                {
                    "type": "image_url",
                    "image_url": {

                    }
                },
            ],
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Gestion des erreurs

Lors de l'appel de l'API, si une erreur survient, l'API renverra le code d'erreur et les informations correspondantes. Par exemple :

- `400 token_mismatched` : Mauvaise requête, probablement en raison de paramètres manquants ou non valides.
- `400 api_not_implemented` : Mauvaise requête, probablement en raison de paramètres manquants ou non valides.
- `401 invalid_token` : Non autorisé, jeton d'autorisation non valide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, quelque chose s'est mal passé sur le serveur.

### Exemple de réponse d'erreur

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
