OpenAI ChatGPT est un système de conversation IA très puissant qui peut générer des réponses fluides et naturelles en quelques secondes seulement en saisissant des prompts. ChatGPT se distingue dans le secteur par ses excellentes capacités de compréhension et de génération du langage. Aujourd’hui, ChatGPT est déjà largement utilisé dans divers secteurs et domaines, et son influence devient de plus en plus significative. Qu’il s’agisse de conversations quotidiennes, d’écriture créative, de consultations professionnelles ou de programmation de code, ChatGPT peut fournir une assistance intelligente impressionnante, améliorant considérablement l’efficacité au travail et la créativité des humains.

Ce document présente principalement le processus d’utilisation des opérations de l’API OpenAI Chat Completion. Grâce à elle, nous pouvons facilement utiliser la fonctionnalité de conversation de l’OpenAI ChatGPT officiel.

Les requêtes de modèles compatibles acceptées par la plateforme sont facturées selon l’utilisation en entrée, en sortie et en cache de ce modèle. Les `prompt_tokens` de Chat Completions incluent les tokens en cache, et la partie du cache rapportée est facturée au tarif de cache correspondant ; le changement de format d’interface ne devient pas une facturation à nombre fixe de fois. Les frais sont basés sur le prix actuel du modèle dans la console et sur `usage.cost` dans la réponse.

## GPT-6.1 Terra

Utilisez `model: "gpt-6.1-terra"` pour sélectionner ce modèle. Il prend en charge les entrées textuelles et d’images ainsi que les sorties en streaming ; les outils de fonction et les sorties structurées doivent être appelés selon le format de paramètres de cette interface. Les niveaux de raisonnement pris en charge sont `low`, `medium`, `high`, `xhigh` et `max` ; il est recommandé de commencer avec `reasoning_effort: "low"` ; `none` et `minimal` ne sont pas pris en charge. Lorsque l’entrée dépasse 272,000 tokens, le tarif de contexte long s’applique ; les frais réels sont basés sur le prix actuel dans la console et sur l’utilisation dans la réponse.

## GPT-6.1 Sol

Utilisez `model: "gpt-6.1-sol"` pour sélectionner ce modèle. Il prend en charge les sorties en streaming, les appels de fonctions, les sorties structurées et les entrées d’images. Au cours de la première semaine d’ouverture, il est uniquement accessible aux détenteurs vérifiés d’ACE T1+ (au moins 100,000 ACE) ou aux utilisateurs autorisés ; l’heure d’ouverture précise est soumise à l’indication d’accès dans la console.

Les niveaux de raisonnement pris en charge sont `low`, `medium`, `high`, `xhigh` et `max` ; `none` et `minimal` ne sont pas pris en charge pour le moment. Il est recommandé de commencer avec `reasoning_effort: "low"`. Lorsque l’entrée dépasse 272,000 tokens, le tarif de contexte long s’applique à l’ensemble de la requête ; les frais sont basés sur le prix actuel dans la console.

## Processus de demande

Pour utiliser l’API OpenAI Chat Completion, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token, à conserver en réserve.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter, puis vous reviendrez automatiquement sur la page actuelle une fois l’opération terminée.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir à en demander un séparément pour chaque service.** Une première demande offre un quota gratuit permettant de tester gratuitement ; lorsque le quota est insuffisant, vous pouvez recharger le solde universel dans la [console](https://platform.acedata.cloud/console/coin).

## Utilisation de base

Vous pouvez ensuite remplir le contenu correspondant dans l’interface, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/jqgg1t.png" width="400" className="m-auto" /></p>

Lors de la première utilisation de cette interface, nous devons remplir au moins trois éléments. Le premier est `authorization`, qui peut être directement sélectionné dans la liste déroulante. Un autre paramètre est `model`, `model` correspond à la catégorie de modèle du site officiel OpenAI ChatGPT que nous choisissons d’utiliser. Nous disposons ici principalement de 20 modèles ; pour les détails, vous pouvez consulter les modèles que nous proposons. Le dernier paramètre est `messages`, `messages` est le tableau de prompts que nous saisissons. Il s’agit d’un tableau, ce qui signifie que plusieurs prompts peuvent être envoyés simultanément. Chaque prompt contient `role` et `content`, où `role` représente le rôle de la personne qui pose la question. Nous proposons trois identités : `user`, `assistant`, `system`. L’autre élément, `content`, correspond au contenu précis de notre question.

En même temps, vous pouvez remarquer que le code d’appel correspondant est généré sur la droite. Vous pouvez copier le code pour l’exécuter directement, ou cliquer directement sur le bouton « Try » pour effectuer un test.

Paramètres optionnels courants :

- `max_tokens` : limite le nombre maximal de tokens d’une réponse unique.
- `temperature` : aléa de génération, entre 0 et 2 ; plus la valeur est élevée, plus le résultat est divergent.
- `n` : nombre de réponses candidates générées à la fois.
- `response_format` : paramètre de format de retour.

## Réponse en streaming

Cette interface prend également en charge les réponses en streaming, ce qui est très utile pour l’intégration web et permet à une page web d’obtenir un effet d’affichage caractère par caractère.

Si vous souhaitez retourner une réponse en streaming, vous pouvez modifier le paramètre `stream ` dans l’en-tête de requête en le définissant sur `true`.

La modification est illustrée ci-dessous, mais le code d’appel doit être modifié en conséquence pour prendre en charge les réponses en streaming.

<p><img src="https://cdn.acedata.cloud/24scd4.png" width="400" className="m-auto" /></p>

Après avoir modifié `stream` en `true`, l’API retournera les données JSON correspondantes ligne par ligne. Au niveau du code, nous devons effectuer les modifications correspondantes afin d’obtenir les résultats ligne par ligne.

Exemple de code d’appel Python :
```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4",
    "messages": [{"role":"user","content":"hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Si vous souhaitez intégrer la fonctionnalité de conversation multi-tours, vous devez téléverser plusieurs termes de requête dans le champ `messages`. Un exemple concret de plusieurs termes de requête est illustré dans l'image ci-dessous :

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"
```

## Intégration avec OpenAI-Python

L'API OpenAI Chat Completion reste compatible avec l'interface officielle OpenAI. Vous pouvez directement utiliser le SDK officiel [OpenAI-Python](https://github.com/openai/openai-python) pour l'intégration. Cet article présentera brièvement son utilisation.

1. Vous devez d'abord configurer un environnement local `Python`, ce processus peut être recherché sur Google.
2. Téléchargez et installez un environnement de développement, par exemple l'éditeur VSCode.
3. Configurez les variables d'environnement `OpenAI`.

- Dans le dossier du projet, créez un fichier nommé `.env` et enregistrez-le.
- Contenu du fichier `.env` :

```json
OPENAI_API_KEY="sk-xxx"
OPENAI_BASE_URL="https://api.acedata.cloud/openai"  # Rappel : si vous utilisez la clé OpenAI du site officiel, n'utilisez pas cette adresse.
```

Remplacez `sk-xxx` par votre propre clé. `OPENAI_BASE_URL` est l'interface proxy permettant d'accéder à OpenAI.

4. Installez les paquets dont dépend le projet.

```shell
pip install openai
```

La commande sous Mac OS est :

```shell
pip3 install openai
```

5. Créez un fichier de code source d'exemple.

Supposons que nous ayons créé un exemple de code `index.py`, dont le contenu spécifique est le suivant :

```python
import os
from openai import OpenAI

client = OpenAI(api_key=os.environ.get("OPENAI_API_KEY"))

response = client.chat.completions.create(
    messages=[
        {
            "role": "user",
            "content": "hello",
        }
    ],
    model="gpt-4",
)

print(response.text)
```

## Modèle visuel

gpt-4o est un grand modèle de langage multimodal développé par OpenAI. Il ajoute des capacités de compréhension visuelle sur la base de GPT-4. Ce modèle peut traiter simultanément des entrées textuelles et des images, permettant une compréhension et une génération intermodales.

Le traitement de texte avec le modèle gpt-4o est cohérent avec le contenu d'utilisation de base ci-dessus. Nous allons maintenant présenter brièvement comment utiliser les capacités de traitement d'images du modèle.

Les capacités de traitement d'images du modèle gpt-4o sont principalement utilisées en ajoutant un champ `type` au contenu `content` d'origine. Ce champ permet de savoir si le contenu téléversé est du texte ou une image, afin d'utiliser les capacités de traitement d'images du modèle gpt-4o. Nous allons principalement expliquer l'utilisation de cette fonctionnalité via Curl et Python.

- Méthode par script Curl

```
-d '{
    "model": "gpt-4o",
    "messages": [
      {
        "role": "user",
        "content": [
          {
```

```python
url = "https://api.acedata.cloud/openai/chat/completions"

}

payload = {

    "messages": [
        {
            "role": "user",
            "content": [
                {
                    "type": "text", "text": "What's in this image?"
```

En plus de gpt-4o, il existe un modèle à moindre coût appelé gpt-4o-mini. gpt-4o-mini est la dernière génération de grands modèles de langage développée par OpenAI. Il répond non seulement rapidement, mais il est également moins cher et prend aussi en charge le multimodal. Pour l'utilisation de la fonctionnalité vision, vous pouvez vous référer au contenu ci-dessus concernant l'utilisation du modèle gpt-4o.

## Gestion des erreurs

Lors de l'appel de l'API, si une erreur se produit, l'API renvoie le code d'erreur et les informations correspondantes. Par exemple :

- `400 token_mismatched`：Mauvaise requête, possiblement due à des paramètres manquants ou non valides.
- `400 api_not_implemented`：Mauvaise requête, possiblement due à des paramètres manquants ou non valides.
- `401 invalid_token`：Non autorisé, jeton d'autorisation non valide ou manquant.
- `429 too_many_requests`：Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error`：Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d'erreur

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
