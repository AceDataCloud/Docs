OpenAI a récemment fourni une interface permettant de créer des réponses de modèle. Fournissez des entrées de texte ou d’image pour générer des sorties de texte ou d’image. Permettez au modèle d’appeler votre propre code personnalisé ou d’utiliser des outils intégrés, tels que la recherche web ou la recherche de fichiers, afin d’utiliser vos propres données comme entrées pour les réponses du modèle.

Ce document présente principalement le processus d’utilisation des opérations de l’API OpenAI Responses, grâce auquel nous pouvons facilement utiliser la fonctionnalité officielle d’OpenAI de création de réponses de modèle.

## Processus de demande

Pour utiliser l’API OpenAI Responses, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token, à conserver pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter, puis vous reviendrez automatiquement sur la page actuelle une fois terminé.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir besoin d’en demander un séparément pour chaque service.** La première demande offre un quota gratuit, permettant une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger le solde commun dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Utilisation de base

Vous pouvez ensuite renseigner le contenu correspondant dans l’interface, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Lors de la première utilisation de cette interface, nous devons au minimum renseigner trois éléments. Le premier est `authorization`, que vous pouvez sélectionner directement dans la liste déroulante. L’autre paramètre est `model`, `model` correspond à la catégorie de modèle du site officiel OpenAI ChatGPT que nous choisissons d’utiliser ; nous proposons ici principalement 20 modèles, dont vous pouvez consulter les détails. Le dernier paramètre est `input`, `input` est le tableau des questions que nous saisissons ; il s’agit d’un tableau, ce qui indique que plusieurs questions peuvent être téléversées simultanément. Chaque question contient `role` et `content`, où `role` indique le rôle de la personne qui pose la question ; nous proposons trois identités, à savoir `user`, `assistant`, `system`. L’autre élément, `content`, correspond au contenu spécifique de notre question.

Vous pouvez également remarquer qu’un code d’appel correspondant est généré à droite ; vous pouvez copier le code pour l’exécuter directement, ou cliquer directement sur le bouton « Try » pour le tester.

Paramètres optionnels courants :

- `max_tokens` : limite le nombre maximal de tokens pour une seule réponse.
- `temperature` : caractère aléatoire de la génération, entre 0 et 2 ; plus la valeur est élevée, plus le résultat est divergent.
- `n` : nombre de réponses candidates générées à la fois.
- `response_format` : paramétrage du format de retour.
- `tools` : définition des appels de fonctions/outils.
- `background` : indique s’il faut exécuter de manière asynchrone en arrière-plan.

## Réponse en streaming

Cette interface prend également en charge les réponses en streaming, ce qui est très utile pour l’intégration sur une page web et permet à la page web d’obtenir un effet d’affichage mot par mot.

Si vous souhaitez retourner des réponses en streaming, vous pouvez modifier le paramètre `stream ` dans l’en-tête de la requête, en le définissant sur `true`.

La modification est illustrée ci-dessous, mais le code d’appel doit être modifié en conséquence afin de prendre en charge les réponses en streaming.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Après avoir modifié `stream` en `true`, l’API retournera les données JSON correspondantes ligne par ligne ; au niveau du code, nous devons effectuer les modifications correspondantes pour obtenir les résultats ligne par ligne.

Exemple de code d’appel Python :

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

- `model `, le modèle sélectionné sur le site officiel d’OpenAI ChatGPT.
- `delta`, les informations de réponse fournies par ChatGPT à la requête.

JavaScript est également pris en charge, par exemple le code d’appel en flux pour Node.js est le suivant :


## Conversation à plusieurs tours

Si vous souhaitez intégrer une fonctionnalité de conversation à plusieurs tours, vous devez envoyer plusieurs requêtes dans le champ `input`, un exemple concret de plusieurs requêtes est présenté dans l’image ci-dessous :

```python
import requests
```

## Modèle visuel

gpt-4o est un grand modèle de langage multimodal développé par OpenAI, qui ajoute des capacités de compréhension visuelle sur la base de GPT-4. Ce modèle peut traiter simultanément des entrées textuelles et d’images, réalisant une compréhension et une génération multimodales.
Le traitement de texte utilisant le modèle gpt-4o est cohérent avec le contenu d'utilisation de base ci-dessus. Nous allons brièvement présenter ci-dessous comment utiliser la capacité de traitement d'images du modèle.

L'utilisation de la capacité de traitement d'images du modèle gpt-4o consiste principalement à ajouter un champ `type` sur la base du contenu `content` d'origine. Ce champ permet de savoir si ce qui est téléversé est du texte ou une image, afin d'utiliser la capacité de traitement d'images du modèle gpt-4o. Nous décrirons principalement ci-dessous deux façons d'appeler cette fonctionnalité : Curl et Python.

- Méthode par script Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Méthode par script Python

## Gestion des erreurs

Lors de l’appel de l’API, en cas d’erreur, l’API renvoie le code d’erreur et les informations correspondants. Par exemple :

- `400 token_mismatched`：Mauvaise requête, possiblement en raison de paramètres manquants ou non valides.
- `400 api_not_implemented`：Mauvaise requête, possiblement en raison de paramètres manquants ou non valides.
- `401 invalid_token`：Non autorisé, jeton d’autorisation non valide ou manquant.
- `429 too_many_requests`：Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error`：Erreur interne du serveur, quelque chose s’est mal passé sur le serveur.

### Exemple de réponse d’erreur

```
}
```
