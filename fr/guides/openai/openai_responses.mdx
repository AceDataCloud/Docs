OpenAI a récemment fourni une interface pour créer des réponses de modèle. Fournissez des entrées textuelles ou d’images pour générer des sorties textuelles ou d’images. Permettez au modèle d’appeler votre propre code personnalisé ou d’utiliser des outils intégrés, tels que la recherche web ou la recherche de fichiers, afin d’utiliser vos propres données comme entrées pour les réponses du modèle.

Ce document présente principalement le processus d’utilisation des opérations de l’API OpenAI Responses ; grâce à elle, nous pouvons facilement utiliser la fonctionnalité officielle OpenAI de création de réponses de modèle.

## GPT-6.1 Sol

Utilisez `model: "gpt-6.1-sol"` pour sélectionner ce modèle. Il prend en charge la sortie en streaming, l’appel de fonctions, la sortie structurée et l’entrée d’images. Pendant la première semaine d’ouverture, il est uniquement accessible aux détenteurs ACE T1+ vérifiés (au moins 100 000 ACE) ou aux utilisateurs autorisés ; l’heure d’ouverture exacte dépend de l’invite d’accès de la console.

Les niveaux de raisonnement pris en charge sont `low`, `medium`, `high`, `xhigh` et `max` ; `none` et `minimal` ne sont pas encore pris en charge. Il est recommandé de commencer avec `reasoning: {"effort": "low"}`. Lorsque l’entrée dépasse 272 000 tokens, le prix du contexte long s’applique à l’ensemble de la requête ; les frais dépendent du prix actuel de la console.

## Processus de demande

Pour utiliser l’API OpenAI Responses, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token, à conserver en réserve.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement sur la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, il n’est pas nécessaire de faire une demande séparée pour chaque service.** Une première demande offre un quota gratuit pour une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger le solde universel dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Utilisation de base

Vous pouvez ensuite remplir le contenu correspondant dans l’interface, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Lors de la première utilisation de cette interface, nous devons au minimum remplir trois éléments : l’un est `authorization`, qui peut être directement sélectionné dans la liste déroulante. Un autre paramètre est `model`, `model` correspond à la catégorie de modèle du site officiel OpenAI ChatGPT que nous choisissons d’utiliser ; nous disposons ici principalement de 20 modèles, pour les détails vous pouvez consulter les modèles que nous fournissons. Le dernier paramètre est `input`, `input` est le tableau de prompts que nous saisissons ; c’est un tableau, ce qui indique que plusieurs prompts peuvent être téléversés simultanément. Chaque prompt contient `role` et `content`, où `role` indique le rôle de l’auteur de la question ; nous fournissons trois identités : `user`, `assistant`, `system`. L’autre champ, `content`, est le contenu spécifique de notre question.

En même temps, vous pouvez remarquer que le code d’appel correspondant est généré sur la droite ; vous pouvez copier le code et l’exécuter directement, ou cliquer directement sur le bouton « Try » pour effectuer un test.

Paramètres optionnels couramment utilisés :

- `max_tokens` : limite le nombre maximal de tokens pour une seule réponse.
- `temperature` : aléa de génération, entre 0 et 2 ; plus la valeur est grande, plus le résultat est diversifié.
- `n` : nombre de réponses candidates générées à la fois.
- `response_format` : paramètre du format de retour.
- `tools` : définition des appels de fonctions/outils.
- `background` : indique s’il faut exécuter de manière asynchrone en arrière-plan.

## Réponse en streaming

Cette interface prend également en charge les réponses en streaming, ce qui est très utile pour l’intégration web et permet à une page web de réaliser un effet d’affichage caractère par caractère.

Si vous souhaitez retourner une réponse en streaming, vous pouvez modifier le paramètre `stream ` dans l’en-tête de la requête en `true`.

La modification est illustrée ci-dessous, mais le code d’appel doit être modifié en conséquence pour prendre en charge la réponse en streaming.

<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Après avoir modifié `stream` en `true`, l’API retournera les données JSON correspondantes ligne par ligne ; au niveau du code, nous devons effectuer les modifications correspondantes afin d’obtenir les résultats ligne par ligne.

Exemple de code d’appel Python :

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

La réponse en streaming utilise `response.completed` ou `response.incomplete` comme état final ; le `usage` dans l’état final est l’utilisation finale de tokens pour cette requête, et constitue également la base de facturation.

Si le client se déconnecte avant l’arrivée de l’état final, cette requête est enregistrée comme fermée par le client (499), et la facturation ne sera pas basée sur une estimation locale des tokens ; si la connexion se termine normalement mais que l’état final et le `usage` final ne sont pas reçus, cette requête est enregistrée comme réponse incomplète (502), et la facturation ne sera pas non plus basée sur une estimation des tokens. Lorsque vous rencontrez ces deux situations, veuillez lancer à nouveau la requête.

Le résultat `data` retourné contient plusieurs champs, présentés comme suit :

- `item_id`, l’ID de la tâche de dialogue générée cette fois-ci, utilisé pour identifier de manière unique cette tâche de dialogue.
- `type`, le type de la tâche Responses de dialogue générée cette fois-ci.
- `model `, le modèle du site officiel OpenAI ChatGPT sélectionné.
- `delta`, les informations de réponse fournies par ChatGPT pour la question.

JavaScript est également pris en charge, par exemple le code d’appel en streaming de Node.js est le suivant :

```javascript
const options = {
  method: "post",
  headers: {

    authorization: "Bearer b82d32f570bc434d9ba9923aa0e7dce0",

  },

  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Modèle de vision

gpt-4o est un grand modèle de langage multimodal développé par OpenAI, qui ajoute des capacités de compréhension visuelle sur la base de GPT-4. Ce modèle peut traiter simultanément des entrées de texte et d’image, permettant une compréhension et une génération multimodales.
Le traitement de texte utilisant le modèle gpt-4o est cohérent avec le contenu d’utilisation de base ci-dessus. Ci-dessous, nous présenterons brièvement comment utiliser les capacités de traitement d’images du modèle.

L’utilisation des capacités de traitement d’images du modèle gpt-4o consiste principalement à ajouter un champ `type` au contenu `content` d’origine. Ce champ permet de savoir si ce qui est téléversé est du texte ou une image, afin d’utiliser les capacités de traitement d’images du modèle gpt-4o. Ci-dessous, nous expliquons principalement comment appeler cette fonctionnalité de deux manières : Curl et Python.

- Méthode par script Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Méthode par script Python

```python

url = "https://api.acedata.cloud/openai/chat/completions"

    "authorization": "Bearer {token}",
    "content-type": "application/json"

    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",

            "type": "input_image",

```

## Gestion des erreurs

Lors de l’appel de l’API, si une erreur se produit, l’API renvoie le code d’erreur et les informations correspondants. Par exemple :

- `400 token_mismatched`：Mauvaise requête, possiblement en raison de paramètres manquants ou non valides.
- `400 api_not_implemented`：Mauvaise requête, possiblement en raison de paramètres manquants ou non valides.
- `401 invalid_token`：Non autorisé, jeton d’autorisation non valide ou manquant.
- `429 too_many_requests`：Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error`：Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d’erreur

```
}
```
