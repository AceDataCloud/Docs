Les requêtes de modèles compatibles acceptées par la plateforme sont facturées selon l’utilisation en entrée, en sortie et en cache du modèle. Le total des entrées Responses inclut les tokens mis en cache rapportés, et la partie en cache est facturée selon le prix de cache correspondant ; le changement de format d’interface ne convertit pas la facturation en un nombre fixe d’appels. Les frais sont basés sur les prix actuels des modèles dans la console et sur `usage.cost` de la réponse.

OpenAI a récemment fourni une interface permettant de créer des réponses de modèle. Fournissez des entrées textuelles ou des images pour générer des sorties textuelles ou des images. Permettez au modèle d’appeler votre propre code personnalisé ou d’utiliser des outils intégrés, tels que la recherche web ou la recherche de fichiers, afin d’utiliser vos propres données comme entrées des réponses du modèle.

Ce document présente principalement le processus d’utilisation de l’API OpenAI Responses. Grâce à elle, nous pouvons facilement utiliser la fonctionnalité officielle OpenAI de création de réponses de modèle.

## GPT-6.1 Terra

Utilisez `model: "gpt-6.1-terra"` pour sélectionner ce modèle. Il prend en charge les entrées texte et image, les sorties en flux, les outils de fonction et les sorties structurées. Les niveaux de raisonnement pris en charge sont `low`, `medium`, `high`, `xhigh` et `max` ; il est recommandé de commencer par `reasoning: {"effort": "low"}` ; `none` et `minimal` ne sont pas pris en charge. Lorsque l’entrée dépasse 272,000 tokens, les tarifs de contexte long s’appliquent ; les frais réels sont basés sur les prix actuels de la console et l’utilisation dans la réponse.

## GPT-6.1 Sol

Utilisez `model: "gpt-6.1-sol"` pour sélectionner ce modèle. Il prend en charge les sorties en flux, les appels de fonction, les sorties structurées et les entrées image. Au cours de la première semaine suivant son ouverture, il est uniquement accessible aux détenteurs vérifiés d’ACE T1+ (au moins 100,000 ACE) ou aux utilisateurs autorisés ; l’heure d’ouverture précise est soumise à l’invite d’accès de la console.

Les niveaux de raisonnement pris en charge sont `low`, `medium`, `high`, `xhigh` et `max` ; `none` et `minimal` ne sont pas encore pris en charge. Il est recommandé de commencer par `reasoning: {"effort": "low"}`. Lorsque l’entrée dépasse 272,000 tokens, les tarifs de contexte long s’appliquent à l’intégralité de la requête ; les frais sont basés sur les prix actuels de la console.

## Processus de demande

Pour utiliser l’API OpenAI Responses, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token et le conserver en réserve.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir à en demander un séparément pour chaque service.** Lors de la première demande, un quota gratuit vous sera offert afin de pouvoir l’essayer gratuitement ; lorsque le quota est insuffisant, vous pouvez recharger le solde universel dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [OpenAI Responses API →](https://platform.acedata.cloud/documents/openai-responses)

## Utilisation de base

Vous pouvez ensuite remplir le contenu correspondant dans l’interface, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/8lu8di.png" width="400" className="m-auto" /></p>

Lors de la première utilisation de cette interface, nous devons au minimum renseigner trois éléments. Le premier est `authorization`, qu’il suffit de sélectionner directement dans la liste déroulante. Un autre paramètre est `model`, `model` correspond à la catégorie de modèle du site officiel OpenAI ChatGPT que nous choisissons d’utiliser ; nous proposons ici principalement 20 modèles, vous pouvez consulter les modèles que nous fournissons pour plus de détails. Le dernier paramètre est `input`, `input` est le tableau des requêtes que nous saisissons ; c’est un tableau, ce qui indique qu’il est possible de téléverser plusieurs requêtes simultanément. Chaque requête contient `role` et `content`, où `role` représente le rôle de l’utilisateur qui pose la question ; nous proposons trois identités : `user`, `assistant`, `system`. L’autre champ, `content`, correspond au contenu précis de notre requête.

Vous pouvez également remarquer que le code d’appel correspondant est généré à droite ; vous pouvez copier le code pour l’exécuter directement, ou cliquer directement sur le bouton « Try » pour effectuer un test.

Paramètres optionnels courants :

- `max_tokens` : limite le nombre maximal de tokens pour une seule réponse.
- `temperature` : aléa de génération, entre 0 et 2 ; plus la valeur est élevée, plus le résultat est divergent.
- `n` : nombre de réponses candidates générées à la fois.
- `response_format` : réglage du format de retour.
- `tools` : définition des appels de fonctions/outils.
- `background` : exécution asynchrone ou non en arrière-plan.

## Réponse en flux

Cette interface prend également en charge les réponses en flux, ce qui est très utile pour l’intégration web et permet à une page web d’obtenir un effet d’affichage caractère par caractère.

Si vous souhaitez retourner une réponse en flux, vous pouvez modifier le paramètre `stream ` dans l’en-tête de requête en le définissant sur `true`.

La modification est illustrée ci-dessous, mais le code d’appel doit être modifié en conséquence pour prendre en charge les réponses en flux.
<p><img src="https://cdn.acedata.cloud/xidnao.png" width="400" className="m-auto" /></p>

Après avoir modifié `stream` en `true`, l’API renverra les données JSON correspondantes ligne par ligne. Au niveau du code, nous devons effectuer les modifications correspondantes pour obtenir les résultats ligne par ligne.

Exemple de code d’appel Python :

```python
import requests

url = "https://api.acedata.cloud/openai/responses"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "gpt-4.1",
    "input": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

- `model `, le modèle OpenAI ChatGPT du site officiel sélectionné.
- `delta`, les informations de réponse fournies par ChatGPT pour le terme de question.

```python
import requests
```

## Modèle visuel

gpt-4o est un grand modèle de langage multimodal développé par OpenAI. Il ajoute des capacités de compréhension visuelle sur la base de GPT-4. Ce modèle peut traiter simultanément des entrées textuelles et des images, réalisant ainsi une compréhension et une génération multimodales.

Le traitement de texte avec le modèle gpt-4o est cohérent avec le contenu d'utilisation de base ci-dessus. Nous allons brièvement présenter ci-dessous comment utiliser les capacités de traitement d'images du modèle.

L'utilisation des capacités de traitement d'images du modèle gpt-4o consiste principalement à ajouter un champ `type` sur la base du contenu `content` d'origine. Ce champ permet de savoir si le contenu téléversé est du texte ou une image, afin d'utiliser les capacités de traitement d'images du modèle gpt-4o. Nous décrivons principalement ci-dessous l'appel de cette fonctionnalité de deux manières : Curl et Python.

- Méthode par script Curl

```
curl -X POST 'https://api.acedata.cloud/openai/responses' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "gpt-4.1",
    "input": [
      {
        "role": "user",
        "content": [
          {"type": "input_text", "text": "what is in this image?"},
          {
            "type": "input_image",
            "image_url": "https://cdn.acedata.cloud/e724d7f13d.png"
          }
        ]
      }
    ]
  }'
```

- Méthode par script Python

```python
import requests

url = "https://api.acedata.cloud/openai/chat/completions"
```

## Gestion des erreurs

Lors de l’appel de l’API, si une erreur survient, l’API renvoie le code d’erreur et les informations correspondants. Par exemple :

- `400 token_mismatched` : Requête incorrecte, possiblement due à des paramètres manquants ou non valides.
- `400 api_not_implemented` : Requête incorrecte, possiblement due à des paramètres manquants ou non valides.
- `401 invalid_token` : Non autorisé, jeton d’autorisation non valide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d’erreur

```
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
