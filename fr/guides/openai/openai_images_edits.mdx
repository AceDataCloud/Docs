## 2. Modifier à l’aide d’une URL d’image

Image originale :

![Image originale à modifier avec GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://platform2.cdn.acedata.cloud/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0.png",
    "prompt": "Keep the mug, tabletop, camera angle, portrait layout, and soft shadow unchanged. Change only the mug color from white to vivid orange and the pale cream background to solid dark navy blue. No text and no logo.",

```

## 3. Téléverser une image locale

Utilisez `multipart/form-data` :

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

Vous pouvez transmettre `image` de manière répétée ; la série GPT Image prend en charge jusqu’à 16 images de référence. Le champ `image` dans les requêtes JSON peut être une URL unique ou un tableau d’URL ; les fichiers locaux sont téléversés via multipart.

### Modèles et méthodes de facturation

| Modèle                                | Cas d’utilisation et méthode de facturation                                 |
| --------------------------------- | ----------------------------------------- |
| `gpt-image-2`                     | Canal inverse par défaut, facturation fixe selon le nombre d’images réussies                        |
| `gpt-image-2:reverse`             | Sélection explicite du canal inverse, facturation fixe selon le nombre d’images réussies                      |
| `gpt-image-2:official`            | Canal API officiel, stabilité plus élevée, facturation selon l’utilisation réelle de Tokens            |
| `gpt-image-2.5-flare`             | Axé sur la vitesse de génération, facturation fixe selon le nombre d’images réussies                        |
| `gpt-image-2.5-flare:official`    | Canal API officiel, stabilité plus élevée et axé sur la vitesse de génération, facturation selon l’utilisation réelle de Tokens     |
| `gpt-image-2.5-sunburst`          | Axé sur la haute fidélité et le contrôle précis, facturation fixe selon le nombre d’images réussies                    |
| `gpt-image-2.5-sunburst:official` | Canal API officiel, stabilité plus élevée et axé sur la haute fidélité et le contrôle précis, facturation selon l’utilisation réelle de Tokens |

Le prix affiché pour le canal API officiel est une estimation avant la requête ; le montant final dépend de l’utilisation réelle de Tokens dans la réponse et des enregistrements d’utilisation.

## 4. Utiliser un masque pour l’édition locale

L’interface officielle Images Edit utilise `mask` pour spécifier les zones autorisées à être modifiées. Les modèles `:official` d’Ace Data Cloud respectent le même contrat multipart :

- `mask` doit être un PNG avec canal Alpha, d’une taille maximale de 4 Mo ;
- les dimensions du masque doivent être exactement identiques à celles de la première `image` ;
- les pixels transparents dont l’Alpha est égal à `0` indiquent les zones autorisées à être modifiées, tandis que les pixels non transparents indiquent les zones à conserver ;
- les images RGB qui sont uniquement en noir et blanc, mais qui ne possèdent pas de canal de transparence, ne peuvent pas être utilisées comme masques valides ;
- le prompt doit décrire l’image complète souhaitée, tout en précisant clairement les modifications locales et le contenu qui doit rester inchangé.

Générez d’abord un masque à partir de l’image originale ci-dessous. L’exemple rend le rectangle central transparent, afin d’autoriser le modèle à modifier uniquement cette zone :

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Téléversez ensuite l’image originale et le masque ensemble :

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Vous pouvez également continuer à utiliser la méthode d’appel `images.edit` du SDK Python officiel d’OpenAI ; il suffit de pointer `base_url` vers Ace Data Cloud :

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Lorsque vous utilisez `mask`, l’image originale et le masque doivent être téléversés séparément dans la même requête multipart via `image=@input.png` et `mask=@mask.png`. Ne mélangez pas une image originale via URL avec un fichier de masque local ; les requêtes d’édition uniquement par URL ne prennent pas en charge l’ajout d’un fichier `mask` local. Le masque contraint la zone d’édition, mais le modèle de génération peut toujours effectuer un mélange naturel sur les bords ; lorsque des limites strictes sont requises, utilisez des bords Alpha nets et répétez dans le prompt quels éléments doivent rester inchangés.

Les méthodes d’appel ci-dessus sont cohérentes avec les exemples de masques de l’[API OpenAI Image Edit](https://developers.openai.com/api/reference/python/resources/images/methods/edit) et du [Cookbook officiel GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Paramètres courants
| Champ                | Description                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (plus rapide) ou `gpt-image-2.5-sunburst` (plus haute fidélité et contrôle) ; les trois peuvent sélectionner la variante `:official` correspondante, et `gpt-image-2` prend également en charge `:reverse` |
| `image`           | JSON utilise une seule URL ou un tableau contenant jusqu’à 16 URL ; multipart utilise un ou plusieurs champs de fichier `image`. Lors de l’utilisation de `mask`, un fichier image local doit être téléversé                                              |
| `mask`            | Masque PNG facultatif, téléversement de fichier multipart uniquement ; doit comporter un canal Alpha, avoir les mêmes dimensions que la première `image` et ne pas dépasser 4 Mo                                                                 |
| `prompt`          | Instruction de modification                                                                                                                             |
| `size`            | `auto` ou `WIDTHxHEIGHT` conforme aux restrictions                                                                                                     |
| `n`               | 1–10 ; seul 1 est pris en charge lorsque `response_format=b64_json`                                                                                           |
| `response_format` | `url` ou `b64_json`                                                                                                               |
| `callback_url`    | Adresse de rappel asynchrone facultative                                                                                                                         |

Les règles de dimensions sont identiques à celles de l’interface de génération : la largeur et la hauteur doivent être des multiples de 16, le côté le plus long ne doit pas dépasser 3840, le nombre total de pixels doit être de 655 360–8 294 400, et le rapport largeur/hauteur ne doit pas dépasser 3:1. Lorsque `size` est omis ou que `auto` est utilisé, le modèle sélectionne le format en fonction du prompt et de la première image de référence.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` et `gpt-image-2:reverse` sont facturés selon le nombre d’images réussies ; `gpt-image-2:official`, `gpt-image-2.5-flare:official` et `gpt-image-2.5-sunburst:official` sont facturés selon les Tokens réels de l’entrée texte, de l’entrée d’image de référence et de la sortie d’image, sous réserve des enregistrements d’utilisation.

## 6. Rappel asynchrone et dépannage

Les tâches longues peuvent inclure dans la requête :

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

La réponse asynchrone 200 est `{"task_id": "..."}` ; le résultat final est rappelé une fois terminé. Les requêtes synchrones renvoient quant à elles `created` et `data`.

| Statut  | Vérification                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Format/nombre d’images, combinaison de paramètres et format des dimensions ; lors de l’utilisation de `mask`, vérifiez le canal Alpha PNG, la limite de 4 Mo et si ses dimensions correspondent à la première image originale |
| 401 | API Key et en-tête Bearer                                           |
| 429 | Fréquence des requêtes                                                              |
| 504 | Utilisez plutôt le rappel asynchrone                                                            |

Les réponses d’erreur contiennent un `trace_id`. Fournissez cet ID lorsque vous signalez un problème, ne fournissez pas votre API Key.

Pour les champs complets et les énumérations en temps réel, consultez la page [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Pour la génération d’images à partir de texte brut, consultez [GPT Image 2 / 2.5 Génération d’images](https://platform.acedata.cloud/documents/openai-images-generations).
