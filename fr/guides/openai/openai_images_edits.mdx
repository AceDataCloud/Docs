## 2. Modifier en utilisant une URL d’image

Image originale :

![Image originale pour l’édition GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",

```

## 3. Téléverser une image locale

Utilisez `multipart/form-data` :

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

Vous pouvez transmettre `image` de manière répétée ; la série GPT Image prend en charge jusqu’à 16 images de référence. Le champ `image` dans une requête JSON peut être une URL unique ou un tableau d’URL ; les fichiers locaux sont téléversés via multipart.

### Modèles et modes de facturation

| Modèle | Cas d’utilisation et mode de facturation |
| --- | --- |
| `gpt-image-2` | Canal inversé par défaut, facturation fixe par image générée avec succès |
| `gpt-image-2:reverse` | Sélection explicite du canal inversé, facturation fixe par image générée avec succès |
| `gpt-image-2:official` | Canal d’API officiel, plus stable, facturé selon l’utilisation réelle de jetons |
| `gpt-image-2.5-flare` | Privilégie la vitesse de génération, facturation fixe par image générée avec succès |
| `gpt-image-2.6-flare` | Privilégie la vitesse de génération, facturation fixe par image générée avec succès |
| `gpt-image-2.5-flare:reverse` | Alias inversé explicite, équivalent à `gpt-image-2.5-flare`, facturation fixe par image générée avec succès |
| `gpt-image-2.6-flare:reverse` | Alias inversé explicite, équivalent à `gpt-image-2.6-flare`, facturation fixe par image générée avec succès |
| `gpt-image-2.5-flare:official` | Canal API officiel, offrant une meilleure stabilité et privilégiant la vitesse de génération ; facturation selon l’utilisation réelle de jetons |
| `gpt-image-2.6-flare:official` | Canal API officiel, offrant une meilleure stabilité et privilégiant la vitesse de génération ; facturation selon l’utilisation réelle de jetons |
| `gpt-image-2.5-sunburst` | Privilégie la haute fidélité et le contrôle précis ; facturation fixe par image générée avec succès |
| `gpt-image-2.6-sunburst` | Privilégie la haute fidélité et le contrôle précis ; facturation fixe par image générée avec succès |
| `gpt-image-2.5-sunburst:reverse` | Alias inverse explicite, équivalent à `gpt-image-2.5-sunburst` ; facturation fixe par image générée avec succès |
| `gpt-image-2.6-sunburst:reverse` | Alias inverse explicite, équivalent à `gpt-image-2.6-sunburst` ; facturation fixe par image générée avec succès |
| `gpt-image-2.5-sunburst:official` | Canal API officiel, offrant une meilleure stabilité et privilégiant la haute fidélité et le contrôle précis ; facturation selon l’utilisation réelle de jetons |
| `gpt-image-2.6-sunburst:official` | Canal API officiel, offrant une meilleure stabilité et privilégiant la haute fidélité et le contrôle précis ; facturation selon l’utilisation réelle de jetons |

Le prix affiché pour le canal API officiel est une estimation avant la requête ; le montant final se base sur l’utilisation réelle de jetons et les enregistrements d’utilisation dans la réponse.

`quality` prend en charge `auto`, `low`, `medium` et `high` ; les versions 2.5 / 2.6 Flare et Sunburst (y compris les variantes `:reverse` et `:official`) prennent également en charge `xhigh` et `max`. Ce champ peut être transmis aussi bien pour l’édition d’URL d’image JSON que pour l’édition de fichiers multipart ; le canal officiel est facturé selon l’utilisation réelle de jetons.

## 4. Utiliser un masque pour une édition locale

L’interface officielle Images Edit utilise `mask` pour spécifier les zones autorisées à être modifiées. Les modèles `:official` d’Ace Data Cloud respectent le même contrat multipart :

- `mask` doit être un PNG avec un canal Alpha, ne dépassant pas 4 Mo ;
- les dimensions du masque doivent être exactement identiques à celles de la première `image` ;
- les pixels transparents dont l’Alpha est égal à `0` indiquent les zones autorisées à être modifiées, les pixels non transparents indiquent les zones à conserver ;
- une image RGB uniquement en noir et blanc, mais sans canal de transparence, ne peut pas servir de masque valide ;
- le prompt doit décrire l’image complète attendue, tout en précisant clairement les modifications locales et les éléments qui doivent rester inchangés.

Générez d’abord un masque à partir de l’image originale ci-dessous. L’exemple définit le rectangle central comme transparent, afin d’autoriser uniquement le modèle à modifier cette zone :
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Ensuite, téléversez ensemble l’image originale et le masque :

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Vous pouvez également continuer à utiliser la méthode d’appel `images.edit` du SDK Python officiel d’OpenAI ; il suffit de faire pointer `base_url` vers Ace Data Cloud :

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Lors de l’utilisation de `mask`, l’image originale et le masque doivent être téléversés séparément dans la même requête multipart via `image=@input.png` et `mask=@mask.png`. Ne mélangez pas une image originale par URL et un fichier de masque local ; les requêtes d’édition utilisant uniquement des URL ne prennent pas en charge l’ajout d’un fichier `mask` local. Le masque contraint la zone d’édition, mais le modèle de génération peut toujours fusionner naturellement les bords ; lorsqu’une limite stricte est nécessaire, utilisez des bords Alpha nets et répétez dans le prompt quels éléments doivent rester inchangés.

Les méthodes d’appel ci-dessus sont conformes aux exemples de masques de l’[API OpenAI Image Edit](https://developers.openai.com/api/reference/python/resources/images/methods/edit) et du [Cookbook officiel GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Paramètres courants

| Champ                | Description                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (plus rapide) ou `gpt-image-2.5-sunburst` (fidélité et contrôle supérieurs) ; les trois peuvent choisir la variante `:official` correspondante, et `gpt-image-2` prend également en charge `:reverse` |
| `image`           | JSON utilise une seule URL ou un tableau d’au maximum 16 URL ; multipart utilise un ou plusieurs champs de fichier `image`. Lors de l’utilisation de `mask`, des fichiers image locaux doivent être téléversés                                              |
| `mask`            | Masque PNG facultatif, limité au téléversement de fichiers multipart ; doit comporter un canal Alpha, avoir les mêmes dimensions que la première `image` et ne pas dépasser 4 Mo                                                                 |
| `prompt`          | Instruction d’édition                                                                                                                             |
| `size`            | `auto` ou `WIDTHxHEIGHT` conforme aux limites                                                                                                     |
| `n`               | 1–10 ; seul 1 est pris en charge avec `response_format=b64_json`                                                                                           |
| `response_format` | `url` ou `b64_json`                                                                                                               |
| `callback_url`    | Adresse de rappel asynchrone facultative                                                                                                                         |

Les règles de dimensions sont les mêmes que pour l’interface de génération : la largeur et la hauteur doivent être des multiples de 16, le côté le plus long ne doit pas dépasser 3840, le total de pixels doit être de 655 360 à 8 294 400, et le rapport largeur/hauteur ne doit pas dépasser 3:1. Lorsque `size` est omis ou que `auto` est utilisé, le modèle choisit le format en fonction du prompt et de la première image de référence.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` et leurs alias `:reverse` sont facturés selon le nombre d’images générées avec succès ; `gpt-image-2:official`, `gpt-image-2.5-flare:official` et `gpt-image-2.5-sunburst:official` sont facturés selon les Tokens réellement utilisés pour l’entrée texte, l’entrée d’image de référence et la sortie d’image ; les enregistrements d’utilisation font foi.

## 6. Rappel asynchrone et dépannage

Les tâches longues peuvent inclure ce qui suit dans la requête :

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

La réponse asynchrone 200 est `{"task_id": "..."}` ; le résultat final est rappelé une fois terminé. Les requêtes synchrones renvoient quant à elles `created` et `data`.

| Statut  | Vérifier                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Le format/le nombre d’images, les combinaisons de paramètres et le format des dimensions ; lors de l’utilisation de `mask`, vérifiez le canal Alpha PNG, la limite de 4 Mo et si ses dimensions correspondent à celles de la première image originale |
| 401 | La clé API et l’en-tête Bearer                                           |
| 429 | La fréquence des requêtes                                                              |
| 504 | Utilisez plutôt un rappel asynchrone                                                            |

Les réponses d’erreur incluent `trace_id`. Lors d’un signalement de problème, fournissez cet ID, mais ne fournissez pas la clé API.

Consultez la page [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits) pour les champs complets et les énumérations en temps réel. Pour la génération d’images à partir de texte pur, consultez [Génération d’images GPT Image 2 / 2.5 / 2.6](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 reprend les interfaces de génération, d’édition, de tâches asynchrones et de facturation de la version 2.5 :

| Modèle                                                          | Facturation                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0.22 Credits/image                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0.22 Credits/image                   |
| `gpt-image-2.6-flare:official`                              | Identique à 2.5 official, facturé selon l’utilisation réelle de Tokens |
| `gpt-image-2.6-sunburst:official`                           | Identique à 2.5 official, facturé selon l’utilisation réelle de Tokens |

La qualité peut être `auto`, `low`, `medium`, `high`, `xhigh`, `max` ; les dimensions utilisent `auto` ou `WIDTHxHEIGHT` conforme aux contraintes ci-dessus. Cette interface prend en charge `png`, `jpeg`, `webp` ; GPT Image 2.6 prend également en charge les GIF animés natifs, mais ne prend pas encore en charge SVG. L’édition prend en charge les URL d’images JSON et le téléversement de fichiers multipart. `:reverse` est un alias explicite de la version standard du même nom. Utilisez le nom de modèle complet, ne transmettez pas `gpt-image-2.6`.

### Conversion d’images GPT Image 2.6 en GIF animés
GPT Image 2.6 Flare、Sunburst en version standard、`:reverse`、`:official` peuvent tous utiliser `output_format: "gif"`。Les images d’animation、les informations de boucle et la durée de lecture sont conservées；`frame_count` indique le nombre d’images，`frame_duration_ms` indique le nombre de millisecondes par image，le nombre d’images doit être un entier de 2 à 16，la durée de chaque image doit être un entier de 20 à 655350 millisecondes，et ils sont uniquement utilisés pour les GIF；l’encodage est arrondi aux 10 ms les plus proches。Lorsqu’ils ne sont pas spécifiés，la valeur par défaut est de 9 images、200 millisecondes par image；lorsque la taille du GIF est omise ou vaut auto，le préréglage 512x512 est utilisé。

Il est recommandé d’utiliser d’abord `size: "512x512"`、`frame_count: 9`、`frame_duration_ms: 200`。Les GIF ont des limites indépendantes de taille et de nombre d’images，les spécifications statiques 4K ne peuvent pas être appliquées directement；certains modèles ajustent la taille réelle de sortie。`n` indique le nombre de fichiers GIF renvoyés，et non le nombre d’images d’animation。La version standard et `:reverse` sont toujours facturés selon le nombre de fichiers réussis，la version officielle est facturée selon l’utilisation réelle de Tokens。

```json
{
  "model": "gpt-image-2.6-flare",
  "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
  "prompt": "Animate the mug gently moving left and right. Keep its appearance and the background, no text.",
  "output_format": "gif",
  "size": "512x512",
  "quality": "medium",
  "frame_count": 9,
  "frame_duration_ms": 200,
  "n": 1,
  "async": true
}
```

### Images statiques 4K de GPT Image 2.6

Flare、Sunburst et leurs variantes `:reverse`、`:official` peuvent tous utiliser les préréglages de pixels 4K susmentionnés，par exemple `3840x2160` et `2160x3840`。La génération et l’édition transmettent des pixels spécifiques via `size`；`4K` n’est pas une valeur `size` valide，`4096x4096` dépasse également la limite actuelle de pixels。Les spécifications 4K ci-dessus s’appliquent aux PNG/JPEG/WebP statiques，pour les GIF veuillez utiliser leurs paramètres dédiés。

### Complexité de composition de GPT Image 2.6

`complexity` peut être `low`、`medium`、`high`，lorsqu’il est omis，la valeur par défaut du modèle `high` est utilisée。Il contrôle la complexité de planification，indépendamment de la qualité de rendu `quality`；il n’entraîne pas de facturation supplémentaire par requête，la version officielle est toujours réglée selon les Tokens réellement utilisés。Les autres modèles ne prennent pas en charge ce paramètre。

Les GIF ne prennent pas en charge les mask、les images annotées、la compression personnalisée、la réécriture de prompt ou la sortie partielle d’images en streaming；les combinaisons incompatibles sont refusées avant la génération。La taille、le nombre d’images et la quantité sont conjointement soumis à la limite du budget de pixels du modèle；pour Flare standard，`1024x1024`、2 images ont été vérifiés comme utilisables，cette conclusion ne peut pas être étendue à toutes les combinaisons 1K ou aux GIF 4K。

### Édition guidée par annotation

L’édition statique de GPT Image 2.6 prend en charge `markup`。Téléversez un PNG transparent de la même taille que la première image de référence，entourez sur un calque indépendant l’emplacement à modifier，et décrivez les exigences de modification dans `prompt`。Le calque d’annotation doit contenir des pixels transparents；les deux images ne doivent pas dépasser 16777216 pixels chacune，l’image d’annotation ne doit pas dépasser 40MB。Le JSON peut transmettre une URL HTTPS、une data URL base64 PNG ou `{ "image_url": "https://..." }`；multipart téléverse le fichier via `markup`。La plateforme transmet le calque d’annotation sous forme de fichier。`markup` ne peut pas être utilisé avec `mask`、GIF ou `prompt_rewriter`，et ne prend pas en charge `file_id`。

`input_fidelity` ne s’applique pas à GPT Image 2.6，veuillez l’omettre。
