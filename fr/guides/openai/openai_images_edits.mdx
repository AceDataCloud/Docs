## 2. Éditer à l’aide d’une URL d’image

Image originale :

![Image originale pour l’édition GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
    "prompt": "Keep the mug, tabletop, camera angle, portrait layout, and soft shadow unchanged. Change only the mug color from white to vivid orange and the pale cream background to solid dark navy blue. No text and no logo.",
    "size": "1024x1536"
  }'
```

## 3. Télécharger une image locale

Utilisez `multipart/form-data` :

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

`image` peut être transmis de manière répétée ; la série GPT Image prend en charge jusqu’à 16 images de référence. Dans les requêtes JSON, `image` peut être une URL unique ou un tableau d’URL ; les fichiers locaux sont téléchargés avec multipart.

### Modèles et méthodes de facturation

| Modèle                                | Cas d’usage et méthode de facturation                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | Canal inversé par défaut, facturation fixe par nombre d’images réussies                               |
| `gpt-image-2:reverse`             | Sélection explicite du canal inversé, facturation fixe par nombre d’images réussies                             |
| `gpt-image-2:official`            | Canal API officiel, stabilité plus élevée, facturation selon l’utilisation réelle de Tokens                   |
| `gpt-image-2.5-flare`             | Axé sur la vitesse de génération, facturation fixe par nombre d’images réussies                               |
| `gpt-image-2.6-flare`             | Axé sur la vitesse de génération, facturation fixe par nombre d’images réussies                               |
| `gpt-image-2.5-flare:reverse`     | Alias inversé explicite, équivalent à `gpt-image-2.5-flare`, facturation fixe par nombre d’images réussies    |
| `gpt-image-2.6-flare:reverse`     | Alias inversé explicite, équivalent à `gpt-image-2.6-flare`, facturation fixe par nombre d’images réussies    |
| `gpt-image-2.5-flare:official`    | Canal API officiel, stabilité plus élevée et axé sur la vitesse de génération, facturation selon l’utilisation réelle de Tokens            |
| `gpt-image-2.6-flare:official`    | Canal API officiel, stabilité plus élevée et axé sur la vitesse de génération, facturation selon l’utilisation réelle de Tokens            |
| `gpt-image-2.5-sunburst`          | Axé sur la haute fidélité et le contrôle précis, facturation fixe par nombre d’images réussies                           |
| `gpt-image-2.6-sunburst`          | Axé sur la haute fidélité et le contrôle précis, facturation fixe par nombre d’images réussies                           |
| `gpt-image-2.5-sunburst:reverse`  | Alias inversé explicite, équivalent à `gpt-image-2.5-sunburst`, facturation fixe par nombre d’images réussies |
| `gpt-image-2.6-sunburst:reverse`  | Alias inversé explicite, équivalent à `gpt-image-2.6-sunburst`, facturation fixe par nombre d’images réussies |
| `gpt-image-2.5-sunburst:official` | Canal API officiel, stabilité plus élevée et axé sur la haute fidélité et le contrôle précis, facturation selon l’utilisation réelle de Tokens        |
| `gpt-image-2.6-sunburst:official` | Canal API officiel, stabilité plus élevée et axé sur la haute fidélité et le contrôle précis, facturation selon l’utilisation réelle de Tokens        |

Les modèles inversés 2.0 / 2.5 (y compris les alias `:reverse`) peuvent utiliser GPT Image 2.5 Flare pour effectuer les requêtes lors de la récupération automatique ; le modèle demandé et la méthode de facturation par nombre d’images réussies restent inchangés.

Le prix affiché pour le canal API officiel est une estimation avant la requête ; le montant final est basé sur l’utilisation réelle de Tokens dans la réponse et les relevés d’utilisation.

`quality` prend en charge `auto`, `low`, `medium`, `high` ; Flare et Sunburst 2.5 / 2.6 (y compris les variantes `:reverse` et `:official`) prennent également en charge `xhigh`, `max`. Ce champ peut être transmis aussi bien pour l’édition d’URL d’image JSON que pour l’édition de fichiers multipart ; le canal officiel facture selon l’utilisation réelle de Tokens.

## 4. Utiliser un masque pour l’édition locale

L’interface officielle Images Edit spécifie les zones autorisées à être modifiées via `mask`. Les modèles `:official` d’Ace Data Cloud respectent le même contrat multipart :

- `mask` doit être un PNG avec un canal Alpha, dont la taille ne dépasse pas 4 Mo ;
- les dimensions du masque doivent être exactement identiques à celles de la première `image` ;
- les pixels transparents dont l’Alpha est égal à `0` indiquent les zones autorisées à être éditées, les pixels non transparents indiquent les zones qui doivent être conservées ;
- les images RGB qui sont uniquement noires et blanches, mais qui n’ont pas de canal de transparence, ne peuvent pas servir de masque valide ;
- le prompt doit décrire l’image complète attendue, tout en indiquant clairement les modifications locales et le contenu qui doit rester inchangé.

Générez d’abord un masque à partir de l’image originale ci-dessous. L’exemple définit le rectangle central comme transparent et autorise uniquement le modèle à modifier cette zone :
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Ensuite, téléversez ensemble l’image originale et le masque :

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Vous pouvez également continuer à utiliser la méthode d’appel `images.edit` du SDK Python officiel d’OpenAI ; il suffit de faire pointer `base_url` vers Ace Data Cloud :

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Lors de l’utilisation de `mask`, l’image originale et le masque doivent être téléversés séparément dans la même requête multipart via `image=@input.png` et `mask=@mask.png`. Ne mélangez pas une image originale par URL avec un fichier de masque local ; les requêtes d’édition utilisant uniquement des URL ne prennent pas en charge l’ajout d’un fichier `mask` local. Le masque contraint la zone d’édition, mais le modèle de génération peut toujours effectuer une fusion naturelle sur les bords ; lorsque des limites strictes sont nécessaires, utilisez des bords Alpha nets et répétez dans l’invite quels éléments doivent rester inchangés.

Les méthodes d’appel ci-dessus sont cohérentes avec les exemples de masque de l’[API OpenAI Image Edit](https://developers.openai.com/api/reference/python/resources/images/methods/edit) et du [Cookbook officiel GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Paramètres courants

| Champ                | Description                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (plus rapide) ou `gpt-image-2.5-sunburst` (meilleure fidélité et contrôle) ; les trois peuvent tous sélectionner la variante `:official` correspondante, et `gpt-image-2` prend également en charge `:reverse` |
| `image`           | JSON utilise une seule URL ou un tableau d’au maximum 16 URL ; multipart utilise un ou plusieurs champs de fichier `image`. Lors de l’utilisation de `mask`, des fichiers image locaux doivent être téléversés                                              |
| `mask`            | Masque PNG facultatif, limité au téléversement de fichiers multipart ; doit comporter un canal Alpha, avoir les mêmes dimensions que la première `image` et ne pas dépasser 4 Mo                                                                 |
| `prompt`          | Instruction d’édition                                                                                                                             |
| `size`            | `auto` ou `WIDTHxHEIGHT` conforme aux limites                                                                                                     |
| `n`               | 1–10 ; seul 1 est pris en charge lorsque `response_format=b64_json`                                                                                           |
| `response_format` | `url` ou `b64_json`                                                                                                               |
| `callback_url`    | Adresse de rappel asynchrone facultative                                                                                                                         |

Les règles de taille sont cohérentes avec l’interface de génération : la largeur et la hauteur doivent être des multiples de 16, le côté le plus long ne doit pas dépasser 3840, le total de pixels doit être de 655 360 à 8 294 400, et le rapport largeur/hauteur ne doit pas dépasser 3:1. Lorsque `size` est omis ou que `auto` est utilisé, le modèle choisit le format en fonction de l’invite et de la première image de référence.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` et leurs alias `:reverse` sont facturés selon le nombre d’images générées avec succès ; `gpt-image-2:official`, `gpt-image-2.5-flare:official` et `gpt-image-2.5-sunburst:official` sont facturés selon les Tokens réels des entrées textuelles, des entrées d’images de référence et des sorties d’images ; les enregistrements d’utilisation font foi.

## 6. Rappel asynchrone et dépannage

Les tâches longues peuvent ajouter ce qui suit dans la requête :

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

La réponse asynchrone 200 est `{"task_id": "..."}` ; le résultat final est rappelé une fois terminé. Les requêtes synchrones renvoient quant à elles `created` et `data`.

| Statut  | Vérifier                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Le format/le nombre d’images, les combinaisons de paramètres et le format des dimensions ; lors de l’utilisation de `mask`, vérifiez le canal Alpha PNG, la limite de 4 Mo et que ses dimensions correspondent à celles de la première image originale |
| 401 | La clé API et l’en-tête Bearer                                           |
| 429 | La fréquence des requêtes                                                              |
| 504 | Utilisez plutôt un rappel asynchrone                                                            |

Les réponses d’erreur incluent `trace_id`. Lors d’un signalement de problème, fournissez cet ID, et non la clé API.

Pour les champs complets et les énumérations en temps réel, référez-vous à la page [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Pour la génération d’images à partir de texte pur, consultez [Génération d’images GPT Image 2 / 2.5 / 2.6](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 reprend les interfaces de génération, d’édition, de tâches asynchrones et de facturation de la version 2.5 :

| Modèle                                                          | Facturation                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0.22 Credits/image                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0.22 Credits/image                   |
| `gpt-image-2.6-flare:official`                              | Identique à 2.5 official, facturé selon l’utilisation réelle de Tokens |
| `gpt-image-2.6-sunburst:official`                           | Identique à 2.5 official, facturé selon l’utilisation réelle de Tokens |

Les qualités disponibles sont `auto`, `low`, `medium`, `high`, `xhigh`, `max` ; pour les dimensions, utilisez `auto` ou un `WIDTHxHEIGHT` conforme aux contraintes ci-dessus. Cette interface prend en charge `png`, `jpeg`, `webp`, mais ne prend pas encore en charge SVG/GIF. L’édition prend en charge les URL d’images JSON et le téléversement de fichiers multipart. `:reverse` est l’alias explicite de la version standard du même nom. Utilisez le nom complet du modèle, ne transmettez pas `gpt-image-2.6`.
