## 1. Obtenir une clé API

Ouvrez la [liste des applications Ace Data Cloud](https://platform.acedata.cloud/console/applications), accédez à une application disponible et copiez la clé API.

## 2. Éditer avec l’URL d’une image

Image originale :

![Image originale pour l’édition GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
    "prompt": "Keep the mug, tabletop, camera angle, portrait layout, and soft shadow unchanged. Change only the mug color from white to vivid orange and the pale cream background to solid dark navy blue. No text and no logo.",
    "size": "1024x1536"
  }'
```

Réponse réussie :

Voici le résultat de l’édition réellement effectuée via Ace Data Cloud le 8 septembre 2026 : la tasse est devenue orange, le fond est devenu bleu marine foncé, tout en conservant la composition originale et la taille de 1024×1536 :

## 3. Téléverser une image locale

Utilisez `multipart/form-data` :

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

Vous pouvez transmettre `image` à plusieurs reprises ; la série GPT Image prend en charge jusqu’à 16 images de référence. Le champ `image` dans une requête JSON peut être une seule URL ou un tableau d’URL ; les fichiers locaux sont téléversés via multipart.

### Modèles et modes de facturation

| Modèle                                | Cas d’usage et mode de facturation                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | Canal inversé par défaut, facturation fixe selon le nombre d’images réussies                               |
| `gpt-image-2:reverse`             | Sélection explicite du canal inversé, facturation fixe selon le nombre d’images réussies                             |
| `gpt-image-2:official`            | Canal API officiel, stabilité plus élevée, facturation selon l’utilisation réelle de Tokens                   |
| `gpt-image-2.5-flare`             | Axé sur la vitesse de génération, facturation fixe selon le nombre d’images réussies                               |
| `gpt-image-2.6-flare`             | Axé sur la vitesse de génération, facturation fixe selon le nombre d’images réussies                               |
| `gpt-image-2.5-flare:reverse`     | Alias inversé explicite, équivalent à `gpt-image-2.5-flare`, facturation fixe selon le nombre d’images réussies    |
| `gpt-image-2.6-flare:reverse`     | Alias inversé explicite, équivalent à `gpt-image-2.6-flare`, facturation fixe selon le nombre d’images réussies    |
| `gpt-image-2.5-flare:official`    | Canal API officiel, stabilité plus élevée et axé sur la vitesse de génération, facturation selon l’utilisation réelle de Tokens            |
| `gpt-image-2.6-flare:official`    | Canal API officiel, stabilité plus élevée et axé sur la vitesse de génération, facturation selon l’utilisation réelle de Tokens            |
| `gpt-image-2.5-sunburst`          | Axé sur la haute fidélité et le contrôle précis, facturation fixe selon le nombre d’images réussies                           |
| `gpt-image-2.6-sunburst`          | Axé sur la haute fidélité et le contrôle précis, facturation fixe selon le nombre d’images réussies                           |
| `gpt-image-2.5-sunburst:reverse`  | Alias inversé explicite, équivalent à `gpt-image-2.5-sunburst`, facturation fixe selon le nombre d’images réussies |
| `gpt-image-2.6-sunburst:reverse`  | Alias inversé explicite, équivalent à `gpt-image-2.6-sunburst`, facturation fixe selon le nombre d’images réussies |
| `gpt-image-2.5-sunburst:official` | Canal API officiel, stabilité plus élevée et axé sur la haute fidélité et le contrôle précis, facturation selon l’utilisation réelle de Tokens        |
| `gpt-image-2.6-sunburst:official` | Canal API officiel, stabilité plus élevée et axé sur la haute fidélité et le contrôle précis, facturation selon l’utilisation réelle de Tokens        |

Les modèles inversés 2.0 / 2.5 (y compris les alias `:reverse`) peuvent utiliser GPT Image 2.5 Flare pour effectuer les requêtes lors de la récupération automatique ; le modèle demandé et le mode de facturation selon le nombre d’images réussies restent inchangés.

Le prix affiché pour le canal API officiel est une estimation avant la requête ; le montant final se base sur l’utilisation réelle de Tokens dans la réponse et les enregistrements d’utilisation.

`quality` prend en charge `auto`, `low`, `medium`, `high` ; Flare et Sunburst 2.5 / 2.6 (y compris les variantes `:reverse` et `:official`) prennent également en charge `xhigh`, `max`. Ce champ peut être transmis aussi bien pour l’édition d’images par URL JSON que pour l’édition de fichiers multipart ; le canal officiel facture selon l’utilisation réelle de Tokens.

## 4. Utiliser un masque pour l’édition locale

L’interface officielle Images Edit utilise `mask` pour spécifier les zones dont la modification est autorisée. Les modèles `:official` d’Ace Data Cloud respectent le même contrat multipart :

- `mask` doit être un PNG avec un canal Alpha, d’une taille maximale de 4 Mo ;
- les dimensions du masque doivent être exactement identiques à celles de la première `image` ;
- les pixels transparents dont l’Alpha est `0` indiquent les zones autorisées à être éditées, tandis que les pixels non transparents indiquent les zones à conserver ;
- les images RGB qui sont seulement en noir et blanc, mais ne possèdent pas de canal de transparence, ne peuvent pas servir de masque valide ;
- le prompt doit décrire l’image complète souhaitée, tout en précisant clairement les modifications locales et les éléments qui doivent rester inchangés.

Générez d’abord un masque à partir de l’image originale ci-dessous. L’exemple définit le rectangle central comme transparent, afin d’autoriser le modèle à modifier uniquement cette zone :
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Ensuite, téléversez ensemble l’image originale et le masque :

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

Vous pouvez également utiliser la méthode d’appel `images.edit` du SDK Python officiel d’OpenAI ; il suffit de définir `base_url` sur Ace Data Cloud :

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Lors de l’utilisation de `mask`, l’image originale et le masque doivent être téléversés séparément dans la même requête multipart via `image=@input.png` et `mask=@mask.png`. Ne mélangez pas une image originale par URL et un fichier de masque local ; les requêtes d’édition avec uniquement une URL ne prennent pas en charge l’ajout d’un fichier `mask` local. Le masque contraint la zone d’édition, mais le modèle de génération peut toujours fusionner naturellement les bords ; lorsqu’une limite stricte est nécessaire, utilisez des bords Alpha nets et répétez dans le prompt quels éléments doivent rester inchangés.

Les méthodes d’appel ci-dessus sont cohérentes avec les exemples de masque de [l’API OpenAI Image Edit](https://developers.openai.com/api/reference/python/resources/images/methods/edit) et du [Cookbook officiel GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Paramètres courants

| Champ                | Description                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (plus rapide) ou `gpt-image-2.5-sunburst` (meilleure fidélité et contrôle) ; les trois permettent de choisir la variante `:official` correspondante, et `gpt-image-2` prend également en charge `:reverse` |
| `image`           | JSON utilise une seule URL ou un tableau pouvant contenir jusqu’à 16 URL ; multipart utilise un ou plusieurs champs de fichier `image`. Lors de l’utilisation de `mask`, vous devez téléverser un fichier image local                                              |
| `mask`            | Masque PNG facultatif, limité au téléversement de fichier multipart ; doit comporter un canal Alpha, avoir les mêmes dimensions que la première `image` et ne pas dépasser 4 Mo                                                                 |
| `prompt`          | Instruction d’édition                                                                                                                             |
| `size`            | `auto` ou `WIDTHxHEIGHT` conforme aux contraintes                                                                                                     |
| `n`               | 1–10 ; seul 1 est pris en charge lorsque `response_format=b64_json`                                                                                           |
| `response_format` | `url` ou `b64_json`                                                                                                               |
| `callback_url`    | Adresse de rappel asynchrone facultative                                                                                                                         |

Les règles de taille sont cohérentes avec l’interface de génération : la largeur et la hauteur doivent être des multiples de 16, le côté le plus long ne doit pas dépasser 3840, le nombre total de pixels doit être de 655 360–8 294 400, et le rapport largeur/hauteur ne doit pas dépasser 3:1. Lorsque `size` est omis ou que `auto` est utilisé, le modèle choisit le format en fonction du prompt et de la première image de référence.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` et leurs alias `:reverse` sont facturés selon le nombre d’images générées avec succès ; `gpt-image-2:official`, `gpt-image-2.5-flare:official` et `gpt-image-2.5-sunburst:official` sont facturés selon les Tokens réels des entrées textuelles, des images de référence et des images de sortie ; les enregistrements d’utilisation font foi.

## 6. Rappel asynchrone et dépannage

Pour les tâches longues, vous pouvez ajouter dans la requête :

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

La réponse asynchrone 200 est `{"task_id": "..."}` ; le résultat final est rappelé une fois terminé. Les requêtes synchrones renvoient quant à elles `created` et `data`.

| Statut  | Vérifier                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Le format/le nombre d’images, la combinaison des paramètres et le format des dimensions ; lors de l’utilisation de `mask`, vérifiez le canal Alpha PNG, la limite de 4 Mo et si ses dimensions correspondent à celles de la première image originale |
| 401 | La clé API et l’en-tête Bearer                                           |
| 429 | La fréquence des requêtes                                                              |
| 504 | Utilisez plutôt un rappel asynchrone                                                            |

Les réponses d’erreur contiennent un `trace_id`. Fournissez cet ID lorsque vous signalez un problème, et ne fournissez pas la clé API.

Pour les champs complets et les énumérations en temps réel, consultez la page [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Pour la génération d’images à partir de texte pur, consultez [Génération d’images GPT Image 2 / 2.5 / 2.6](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 reprend les interfaces de génération, d’édition, de tâches asynchrones et de facturation de la version 2.5 :

| Modèle                                                          | Facturation                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0.22 Credits/image                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0.22 Credits/image                   |
| `gpt-image-2.6-flare:official`                              | Identique à 2.5 official, facturé selon l’utilisation réelle de Tokens |
| `gpt-image-2.6-sunburst:official`                           | Identique à 2.5 official, facturé selon l’utilisation réelle de Tokens |

Les qualités disponibles sont `auto`, `low`, `medium`, `high`, `xhigh`, `max` ; pour la taille, utilisez `auto` ou `WIDTHxHEIGHT` conforme aux contraintes ci-dessus. Cette interface prend en charge `png`, `jpeg`, `webp` ; GPT Image 2.6 prend également en charge nativement les GIF animés `gif`, mais ne prend pas encore en charge SVG. L’édition prend en charge les URL d’images JSON et le téléversement de fichiers multipart. `:reverse` est un alias explicite de la version standard du même nom. Utilisez le nom complet du modèle, ne transmettez pas `gpt-image-2.6`.

### Conversion d’images GPT Image 2.6 en GIF animés
Les versions standard de Flare, `:reverse`, `:official`, ainsi que `gpt-image-2.6-sunburst:official` peuvent utiliser `output_format: "gif"`. La version standard de Sunburst et `:reverse` n’ouvrent pas encore les GIF, mais prennent toujours en charge la génération et l’édition d’images statiques. Les images d’animation, les informations de boucle et la durée de lecture sont conservées ; `frame_count` représente le nombre d’images, `frame_duration_ms` représente le nombre de millisecondes par image, les deux doivent être des entiers positifs et sont uniquement utilisés pour les GIF. Lorsqu’ils ne sont pas spécifiés, les valeurs par défaut sont de 9 images et 200 millisecondes par image ; lorsque la `size` du GIF est omise ou vaut auto, le préréglage 512x512 est utilisé.

Il est recommandé d’utiliser d’abord `size: "512x512"`, `frame_count: 9`, `frame_duration_ms: 200`. Les GIF ont des limites indépendantes de taille et de nombre d’images, et les spécifications statiques 4K ne peuvent pas être appliquées directement ; certains modèles ajusteront la taille réelle de sortie. `n` représente le nombre de fichiers GIF renvoyés, et non le nombre d’images d’animation. La version standard et `:reverse` sont toujours facturées selon le nombre de fichiers réussis, tandis que la version officielle est facturée selon l’utilisation réelle de Token.

```json
{
  "model": "gpt-image-2.6-flare",
  "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
  "prompt": "Animate the mug gently moving left and right. Keep its appearance and the background, no text.",
  "output_format": "gif",
  "size": "512x512",
  "quality": "medium",
  "frame_count": 9,
  "frame_duration_ms": 200,
  "n": 1,
  "async": true
}
```

### GPT Image 2.6 images statiques 4K

Flare, Sunburst et leurs variantes `:reverse`, `:official` peuvent tous utiliser les préréglages de pixels 4K mentionnés précédemment, par exemple `3840x2160` et `2160x3840`. La génération et l’édition reçoivent toutes deux des pixels spécifiques via `size` ; `4K` n’est pas une valeur `size` valide, et `4096x4096` dépasse également la limite actuelle de pixels. Les spécifications 4K ci-dessus s’appliquent aux PNG/JPEG/WebP statiques ; pour les GIF, veuillez utiliser leurs paramètres dédiés.
