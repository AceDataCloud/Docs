Kimi est une série de modèles d’IA lancée par Moonshot AI. `kimi-k3.1-pro` est actuellement recommandé, adapté à la programmation longue durée, au raisonnement complexe, à la compréhension visuelle et au travail de connaissance ; `kimi-k3` reste utilisable. Appelez-la via l’API Chat Completions compatible OpenAI.

Ce document présente principalement le processus d’utilisation de l’API Kimi Chat Completion. Grâce à elle, nous pouvons facilement utiliser la fonctionnalité de conversation officielle de Kimi.

## Processus de demande

Pour utiliser l’API Kimi Chat Completion, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) afin d’obtenir votre API Token et conservez-le pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir besoin d’en demander un séparément pour chaque service.** La première demande offre un quota gratuit, permettant un essai gratuit ; lorsque le quota est insuffisant, vous pouvez recharger le solde universel dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Utilisation de base

Vous pouvez ensuite renseigner le contenu correspondant dans l’interface, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/ej5ozg.png" width="400" className="m-auto" /></p>

Lors de la première utilisation de cette interface, vous devez au minimum renseigner trois éléments : `authorization` peut être sélectionné directement dans la liste déroulante ; `model` sert à sélectionner le modèle Kimi, il est recommandé d’utiliser `kimi-k3.1-pro` ; `messages` est un tableau de messages de conversation, chaque message contient `role` et `content`, parmi lesquels `role` prend en charge `user`, `assistant`, `system` et `tool`.

Vous pouvez également remarquer que le code d’appel correspondant est généré à droite ; vous pouvez copier le code et l’exécuter directement, ou cliquer directement sur le bouton « Try » pour effectuer un test.

Le résultat retourné comporte plusieurs champs, présentés comme suit :

- `id`, l’ID généré pour cette tâche de conversation, utilisé pour identifier de manière unique cette tâche de conversation.
- `model `, le modèle du site officiel Kimi sélectionné.
- `choices`, les informations de réponse fournies par Kimi pour la question.
- `usage ` : les informations statistiques sur les tokens pour cette session de questions-réponses.

Parmi eux, `choices` contient les informations de réponse de Kimi, et les `choices` à l’intérieur correspondent aux informations spécifiques de la réponse de Kimi, comme vous pouvez le constater sur l’image.

Vous pouvez voir que le champ `content` dans `choices` contient le contenu spécifique de la réponse de Kimi ; K3 peut également retourner `reasoning_content`, utilisé pour représenter le processus de raisonnement.

## Intensité de raisonnement K3.1 Pro

`kimi-k3.1-pro` active toujours le raisonnement. Vous pouvez définir `reasoning_effort` dans le niveau supérieur du corps de la requête sur `low`, `high` ou `max` ; ne transmettez pas de configuration désactivant le raisonnement. Le modèle prend en charge jusqu’à 1 048 576 tokens de contexte, mais la limite réelle des requêtes reste celle de l’interface actuelle. Le prix est calculé selon l’utilisation des entrées, des sorties et des accès au cache, consultez la carte Pricing du catalogue des modèles pour plus de détails.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

L’exemple K3 suivant est conservé pour les intégrations existantes, et l’exemple de réponse a bien été obtenu à partir d’une requête K3.

## Intensité de raisonnement K3

`kimi-k3` active toujours le raisonnement. Le niveau supérieur du corps de la requête prend en charge le champ `reasoning_effort`, dont la seule valeur actuellement prise en charge est `max` ; lorsque ce champ est omis, `max` est également utilisé. `standard`, `high` ou d’autres chaînes peuvent être acceptés de manière permissive par certains fournisseurs amont compatibles, mais ils ne sont pas garantis de modifier le comportement du raisonnement, veuillez ne pas vous y fier.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

Lors de l’utilisation du SDK OpenAI, vous pouvez transmettre directement ce champ :

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

Lors des conversations multi-tours et des appels d’outils, veuillez renvoyer le message assistant complet du tour précédent dans `messages`, y compris `reasoning_content` et `tool_calls`.

### Références officielles

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort) : explique que Kimi K3 active toujours le raisonnement, et que la seule valeur actuellement prise en charge par `reasoning_effort` est `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview) : compare les paramètres de raisonnement, les fenêtres de contexte et les différences d’appel d’outils entre les séries K3 et K2.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat) : définitions officielles Moonshot des champs de requête, de réponse et OpenAPI pour Chat Completions.

## Réponse en streaming

Cette interface prend également en charge les réponses en streaming, ce qui est très utile pour l’intégration web, permettant à la page web d’afficher les résultats caractère par caractère.

Si vous souhaitez retourner une réponse en streaming, vous pouvez modifier le paramètre `stream ` dans l’en-tête de la requête en `true`.

La modification est illustrée ci-dessous, mais le code d’appel doit être modifié en conséquence afin de prendre en charge les réponses en streaming.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>

Après avoir modifié `stream` en `true`, l’API retournera les données JSON correspondantes ligne par ligne ; au niveau du code, nous devons effectuer les modifications correspondantes afin d’obtenir les résultats ligne par ligne.

Exemple de code d’appel Python :
```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Ci-dessous figurent des extraits des blocs de données de début, de raisonnement, de corps, de fin et d’utilisation d’une même réponse en flux K3 Max réelle :

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Vous pouvez voir que la réponse contient de nombreux `data`, et que les `choices` dans les `data` correspondent au contenu le plus récent de la réponse, ce qui est cohérent avec le contenu présenté ci-dessus. `choices` correspond au contenu de réponse ajouté, et vous pouvez l’intégrer à votre système en fonction du résultat. Par ailleurs, la fin de la réponse en flux est déterminée selon le contenu de `data` : si le contenu est `[DONE]`, cela indique que la réponse en flux est entièrement terminée. Le résultat `data` renvoyé contient plusieurs champs, présentés ci-dessous :

- `id`, l’ID de la tâche de conversation générée cette fois-ci, utilisé pour identifier de manière unique cette tâche de conversation.
- `model `, le modèle Kimi du site officiel sélectionné.
- `choices`, les informations de réponse fournies par Kimi à la requête.

JavaScript est également pris en charge ; par exemple, le code d’appel en flux Node.js est le suivant :

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Exemple de code Java :

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Les autres langages peuvent être adaptés par vous-même ; le principe reste le même.

## Conversation multi-tours

Si vous souhaitez intégrer une fonctionnalité de conversation multi-tours, vous devez envoyer plusieurs requêtes dans le champ `messages`. Un exemple concret de plusieurs requêtes est présenté dans l’image ci-dessous :

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Exemple de code d’appel Python :

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

En envoyant plusieurs requêtes, vous pouvez facilement réaliser une conversation multi-tours. Voici la réponse K3 Max réelle obtenue par cette requête (les champs d’extension non utilisés sont omis) :

```json

    {

Vous pouvez constater que les informations contenues dans `choices` sont cohérentes avec celles de l’utilisation de base. Elles incluent le contenu spécifique des réponses de Kimi à plusieurs conversations, ce qui permet de répondre aux questions correspondantes en fonction de plusieurs contenus de conversation.

## Gestion des erreurs

Lors de l’appel de l’API, si une erreur survient, l’API renvoie le code et les informations d’erreur correspondants. Par exemple :

- `400 token_mismatched` : Requête incorrecte, probablement en raison de paramètres manquants ou non valides.
- `400 api_not_implemented` : Requête incorrecte, probablement en raison de paramètres manquants ou non valides.
- `401 invalid_token` : Non autorisé, jeton d’autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d’erreur

```
