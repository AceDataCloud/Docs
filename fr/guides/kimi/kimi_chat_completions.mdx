Kimi est une série de modèles d’IA lancée par Moonshot AI. Le modèle actuellement recommandé est `kimi-k3.1-pro`, adapté à la programmation à long terme, au raisonnement complexe, à la compréhension visuelle et aux tâches liées aux connaissances ; `kimi-k3` reste également disponible. L’API Chat Completions compatible avec OpenAI permet d’effectuer les appels.

Ce document présente principalement la procédure d’utilisation de l’API Kimi Chat Completion. Grâce à celle-ci, nous pouvons facilement utiliser les fonctionnalités conversationnelles officielles de Kimi.

## Modèles pris en charge

Quatre modèles sont actuellement pris en charge : `kimi-k3.1-pro`, `kimi-k3`, `kimi-k2.6` et `kimi-k2.7-code`. K2.7 Code est destiné aux scénarios de programmation et d’appel d’outils, et est facturé au même tarif que K2.6 ; ne transmettez pas de paramètre `thinking` ni de `reasoning_effort` dans les requêtes qui lui sont adressées. Les autres modèles Kimi ne sont plus pris en charge. Veuillez sélectionner explicitement l’un de ces quatre modèles dans le client.

## Procédure de demande

Pour utiliser l’API Kimi Chat Completion, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) afin d’obtenir votre API Token et de le conserver pour une utilisation ultérieure.

![]()

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion, où vous serez invité à vous inscrire et à vous connecter. Une fois cette opération terminée, vous serez automatiquement redirigé vers la page actuelle.

**Un seul API Token suffit pour appeler tous les services de la plateforme. Il n’est pas nécessaire d’en demander un séparément pour chaque service.** Un crédit gratuit est offert lors de la première demande, ce qui vous permet de tester gratuitement le service ; lorsque votre solde est insuffisant, vous pouvez recharger votre solde général dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Kimi Chat Completion API →](https://platform.acedata.cloud/documents/kimi-chat-completions)

## Utilisation de base

Vous pouvez ensuite renseigner les informations correspondantes dans l’interface, comme illustré ci-dessous :

Lors de la première utilisation de cette interface, vous devez renseigner au moins trois éléments : `authorization` peut être directement sélectionné dans la liste déroulante ; `model` permet de sélectionner le modèle Kimi, et il est recommandé d’utiliser `kimi-k3.1-pro` ; `messages` est un tableau de messages de conversation, chaque message contenant `role` et `content`, où `role` accepte les valeurs `user`, `assistant`, `system` et `tool`.

Vous pouvez également remarquer que le code d’appel correspondant est généré sur la droite. Vous pouvez copier le code et l’exécuter directement, ou cliquer directement sur le bouton « Try » pour effectuer un test.

Le résultat retourné contient plusieurs champs, présentés ci-dessous :

- `model ` : le modèle du site officiel Kimi sélectionné.
- `choices` : les informations de réponse fournies par Kimi à la question posée.
- `usage ` : les statistiques relatives aux tokens utilisés pour cette session de questions-réponses.

Parmi ces champs, `choices` contient les informations de réponse de Kimi. Le champ `choices` qu’il contient représente les informations détaillées de la réponse de Kimi, comme illustré ci-dessous.

Comme vous pouvez le constater, le champ `content` dans `choices` contient le contenu précis de la réponse de Kimi ; K3 peut également retourner `reasoning_content`, qui représente le processus de raisonnement.

## Intensité de raisonnement de K3.1 Pro

`kimi-k3.1-pro` active toujours le raisonnement. Vous pouvez définir `reasoning_effort` au niveau supérieur du corps de la requête sur `low`, `high` ou `max` ; ne transmettez pas de configuration désactivant le raisonnement. Le modèle prend en charge une fenêtre de contexte allant jusqu’à 1 048 576 tokens, mais la limite réelle des requêtes reste soumise aux paramètres de l’interface actuelle. Le prix est calculé en fonction de l’utilisation des tokens d’entrée, de sortie et des accès au cache. Pour plus de détails, consultez la fiche Pricing du catalogue des modèles.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Les exemples K3 ci-dessous sont conservés pour les intégrations existantes, et les réponses présentées dans les exemples ont bien été obtenues à partir de requêtes K3.

## Intensité de raisonnement de K3

`kimi-k3` active toujours le raisonnement. Le champ `reasoning_effort` est pris en charge au niveau supérieur du corps de la requête. La seule valeur actuellement prise en charge est `max` ; si ce champ est omis, la valeur `max` est également utilisée. Veuillez utiliser une valeur prise en charge.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

Lors de l’utilisation du SDK OpenAI, vous pouvez transmettre directement ce champ :

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

Lors des conversations à plusieurs tours et des appels d’outils, veuillez renvoyer le message complet de l’assistant du tour précédent dans `messages`, y compris `reasoning_content` et `tool_calls`.

### Références officielles

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort) : explique que Kimi K3 active toujours le raisonnement et que la seule valeur actuellement prise en charge pour `reasoning_effort` est `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview) : compare les paramètres de raisonnement, les fenêtres de contexte et les différences en matière d’appel d’outils entre K3 et la série K2.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat) : définition officielle de Moonshot des requêtes Chat Completions, des réponses et des champs OpenAPI.

## Réponse en streaming

Cette interface prend également en charge les réponses en streaming, ce qui est particulièrement utile pour l’intégration dans les pages Web et permet d’afficher progressivement le texte à l’écran.

Si vous souhaitez obtenir une réponse en streaming, vous pouvez modifier le paramètre `stream ` dans l’en-tête de la requête et le définir sur `true`.

Effectuez la modification comme illustré ci-dessous. Toutefois, le code d’appel doit également être modifié en conséquence pour prendre en charge les réponses en streaming.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>
Après avoir défini `stream` sur `true`, l’API renvoie les données JSON correspondantes ligne par ligne. Au niveau du code, nous devons apporter les modifications nécessaires afin d’obtenir les résultats ligne par ligne.

Exemple de code d’appel en Python :

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Voici un extrait des blocs de données de début, de raisonnement, de contenu principal, de fin et d’utilisation provenant d’une même réponse réelle en streaming de K3 Max :

```json

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: [DONE]
```

Comme vous pouvez le constater, la réponse contient de nombreux éléments `data`. Le champ `choices` à l’intérieur de `data` correspond au contenu de la réponse la plus récente, conformément à ce qui a été présenté précédemment. `choices` contient le nouveau contenu de la réponse, que vous pouvez utiliser pour l’intégrer à votre système en fonction du résultat. Par ailleurs, la fin de la réponse en streaming est déterminée par le contenu de `data`. Si le contenu est `[DONE]`, cela signifie que la réponse en streaming est entièrement terminée. Les données `data` renvoyées contiennent plusieurs champs, présentés ci-dessous :

- `id` : l’ID généré pour cette tâche de conversation, utilisé pour identifier de manière unique cette tâche.
- `model ` : le modèle du site officiel de Kimi sélectionné.
- `choices` : les informations de réponse fournies par Kimi à la question posée.

JavaScript est également pris en charge. Voici, par exemple, le code d’appel en streaming avec Node.js :

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Exemple de code en Java :

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Pour les autres langages, vous pouvez adapter le code vous-même. Le principe reste le même.

## Conversations à plusieurs tours

Si vous souhaitez intégrer la fonctionnalité de conversation à plusieurs tours, vous devez transmettre plusieurs questions dans le champ `messages`. Voici un exemple concret de plusieurs questions, comme illustré dans l’image ci-dessous :

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Exemple de code d’appel en Python :

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

En transmettant plusieurs questions, vous pouvez facilement mettre en œuvre des conversations à plusieurs tours. Voici la réponse réelle de K3 Max obtenue avec cette requête (les champs d’extension inutilisés sont omis) :


Comme vous pouvez le constater, les informations contenues dans `choices` sont identiques à celles utilisées dans le fonctionnement de base. Elles comprennent le contenu précis des réponses de Kimi à plusieurs échanges, ce qui permet de répondre aux questions correspondantes en fonction du contenu de ces différents échanges.

## Gestion des erreurs

Lors de l’appel à l’API, si une erreur survient, l’API renvoie le code et le message d’erreur correspondants. Par exemple :

- `400 token_mismatched` : Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented` : Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token` : Unauthorized, invalid or missing authorization token.
- `429 too_many_requests` : Too many requests, you have exceeded the rate limit.
- `500 api_error` : Internal server error, something went wrong on the server.

### Exemple de réponse d’erreur

```

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
