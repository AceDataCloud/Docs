---
title: "Obtenir la liste des commandes de la plateforme AceDataCloud"

Retourne de manière paginée les commandes de recharge du compte, adapté à la recherche d’ID de commande, à la consultation de l’état des paiements et au rapprochement comptable.

## Préparatifs

Créez un [Account Token](https://platform.acedata.cloud/documents/platform-token), et obtenez l’UUID du compte actuel depuis `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='votre jeton de compte'
export USER_ID='votre UUID de compte'
```

## Aperçu de l’interface

| Élément   | Contenu                                              |
| --- | ----------------------------------------------- |
| Méthode  | `GET`                                           |
| URL | `https://platform.acedata.cloud/api/v1/orders/` |
| Authentification  | Account Token, le token OAuth nécessite `orders:read`       |
| Pagination  | `count` + `items`                               |

Les utilisateurs ordinaires doivent transmettre leur propre `user_id` ; sinon, un `403` peut être renvoyé lorsque la pagination rencontre des objets non autorisés.

## Paramètres de requête

| Paramètre                    | Type       | Obligatoire     | Description                                                        |
| --------------------- | -------- | ------ | --------------------------------------------------------- |
| `user_id`             | UUID     | Obligatoire pour les utilisateurs ordinaires | Compte auquel appartient la commande ; prend en charge les paramètres répétés                                             |
| `pay_way`             | string   | Non      | Filtrer par méthode de paiement ; prend en charge les valeurs répétées ou séparées par des virgules                                        |
| `state`               | string   | Non      | Filtrer par état ; prend en charge les valeurs répétées ou séparées par des virgules                                          |
| `created_at_from/to`  | datetime | Non      | Plage de temps de création                                                    |
| `finished_at_from/to` | datetime | Non      | Plage de temps de finalisation                                                    |
| `limit` / `offset`    | integer  | Non      | Pagination                                                        |
| `ordering`            | string   | Non      | `created_at`, `-created_at`, `finished_at` ou `-finished_at` |

La liste actuelle ne prend pas en charge le filtrage par `application_id`, `service_id`, `package_id`, `payment_method` ou `tag` ; le nom du champ de méthode de paiement est `pay_way`.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/orders/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'state=Paid,Finished' \
  --data-urlencode 'pay_way=Stripe' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Description de la réponse

La réponse est `{count, items}`. Les éléments de la liste en production contiennent `id`, `user_id`, `application_id/application_ids`, `package_id/package_ids`, `price`, `amount`, `discount`, `remaining_amount`, `state`, `pay_way`, `pay_id`, `pay_url`, `finished_at`, `expired_at`, `invoice`, `metadata` et des champs de temps.

- Les états réels sont `Pending`, `Paid`, `Finished`, `Expired`, `Failed`, `Refunded`, il n’y a pas de `Cancelled`.
- Les noms des champs sont `pay_way`, `finished_at`, `discount` et `price`, et non `payment_method`, `paid_at`, `discount_rate` ou `final_price`.
- `price` est le prix final enregistré de la commande ; la devise et les détails de règlement peuvent se trouver dans des metadata contrôlées, et ne peuvent pas être déduits uniquement de la méthode de paiement.
