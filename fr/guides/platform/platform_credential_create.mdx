---
title: "Créer des identifiants API pour la plateforme AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Créez des identifiants API métier pour une Application. La réponse de création peut contenir un Token permettant d’appeler directement `https://api.acedata.cloud/**`, ou le nom d’utilisateur/mot de passe d’identifiants de type Proxy ; ils doivent être traités comme des secrets.

## Préparation

1. Créez un [Account Token](https://platform.acedata.cloud/documents/platform-token).
2. Récupérez le `application_id` dont vous êtes propriétaire depuis la [liste des Applications](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='votre jeton de compte'
export APPLICATION_ID='votre ID d’Application'
```

## Aperçu de l’interface

| Élément    | Contenu                                                   |
| ---- | ---------------------------------------------------- |
| Méthode   | `POST`                                               |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/` |
| Authentification   | Account Token, le token OAuth nécessite `credentials:write`      |
| Body | JSON                                                 |

## Corps de la requête

| Champ                  | Type              | Obligatoire  | Description                            |
| ------------------- | --------------- | --- | ----------------------------- |
| `application_id`    | UUID            | Oui   | Application cible                |
| `name`              | string          | Non   | Nom d’affichage des identifiants                         |
| `limited_amount`    | number / null   | Non   | Limite d’utilisation pour un seul identifiant ; `null` signifie qu’aucune limite individuelle n’est définie       |
| `expired_at`        | datetime / null | Non   | Heure d’expiration ISO 8601                 |
| `allowed_api_ids`   | UUID[] / null   | Non   | Autorise uniquement l’appel de ces API ; un tableau vide sera normalisé comme sans restriction       |
| `host`              | string          | Non   | Informations sur l’hôte des identifiants                    |
| `for_user_id`       | string          | Non   | Utilisé lorsque le propriétaire de l’Application émet des identifiants autorisés pour un autre utilisateur |
| `tags` / `metadata` | array / object  | Non   | Données d’extension personnalisées                       |

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/credentials/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"name\":\"production\",\"limited_amount\":50}"
```

## Description de la réponse

En cas de succès, retourne `201` et un objet Credential :

- Les services de type API/Agent retournent généralement `type=Token` et `token` ;
- Les services de type Proxy retournent généralement `type=Identity` et `username` / `password`, et une Proxy Application n’autorise qu’un seul identifiant ;
- `id`, `user_id`, `creator_id`, `used_amount` et les champs temporels sont générés par le serveur.

Les interfaces actuelles de liste et de détails retournent également les identifiants en clair, mais le client ne doit pas dépendre de ce comportement historique. Enregistrez-les immédiatement après la création et évitez d’écrire la réponse dans les journaux ; les interfaces futures pourront retourner des données masquées.

## Gestion des erreurs

- `400` : Format de champ incorrect, `allowed_api_ids` inconnu, Proxy Application possédant déjà des identifiants ou autres contraintes de création.
- `401` : Account Token invalide.
- `403/404` : Aucun droit d’accès à l’Application cible, ou l’Application/l’utilisateur autorisé n’existe pas.
