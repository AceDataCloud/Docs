---
title: "Configurer le partage global du solde pour une Application AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Configurez `allow_consume_global`. Une fois activé, les Applications à l'utilisation qui remplissent les conditions peuvent continuer à utiliser le solde global du compte lorsque leur propre solde est insuffisant.

## Préparatifs

- Créez et conservez en sécurité le [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Obtenez l'`application_id` dont vous êtes propriétaire depuis la [liste des demandes de service](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='votre jeton de compte'
export APPLICATION_ID='votre ID d’Application'
```

## Aperçu de l'interface

| Élément    | Contenu                                                                                                 |
| ---- | -------------------------------------------------------------------------------------------------- |
| Méthode   | `POST`                                                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/applications/{application_id}/update-allow-consume-global/` |
| Authentification   | Account Token                                                                                      |
| Body | JSON                                                                                               |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/applications/${APPLICATION_ID}/update-allow-consume-global/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"allow_consume_global": true}'
```

En cas de succès, l'objet Application mis à jour est renvoyé. Veuillez vous référer à `allow_consume_global` dans la réponse, plutôt que de supposer que la valeur demandée est nécessairement enregistrée.

> Les Applications de type `Period` ne sont pas autorisées à consommer le solde global. Même si vous demandez `true`, le serveur conservera ce champ à `false`.

## Gestion des erreurs

- `401` : le Account Token est invalide ou absent.
- `403` : le compte actuel n'est pas le propriétaire de cette Application.
- `404` : l'ID d'Application n'existe pas.

Le point d'entrée de recharge du solde global et les forfaits disponibles sont déterminés par la console de la plateforme ainsi que par les forfaits réellement renvoyés par la [création de commande](https://platform.acedata.cloud/documents/platform-order-create) ; ne supposez pas qu'il existe des forfaits de type `Wallet`.

## Applications avec découvert autorisé

Lorsque le champ en lecture seule `allow_overdraft=true` d'une Application à l'utilisation est défini, cette Application peut continuer à être débitée de son propre solde, même si celui-ci devient négatif, et ne basculera pas vers le compte global en raison d'un solde insuffisant. Les Applications sans découvert activé suivent toujours `allow_consume_global` ; après le basculement, l'autorisation de découvert dépend du paramétrage de l'Application globale effectivement débitée.
