---
title: "Obtenir les détails d’une commande sur la plateforme AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Interrogez une commande via son ID de commande. Ce point de terminaison prend en charge deux modes de lecture : l’accès anonyme ne renvoie que les champs minimaux nécessaires à la page de paiement ; le propriétaire de la commande, lorsqu’il fournit un Account Token, reçoit les détails complets.

## Aperçu de l’interface

| Élément   | Contenu                                                        |
| --- | --------------------------------------------------------- |
| Méthode  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| Authentification  | Optionnelle ; projection minimale en anonyme, projection complète pour le propriétaire authentifié                                    |

`/orders/{id}` et `/orders/{id}/` sont actuellement tous deux disponibles. L’ID de commande fait partie du lien de paiement et doit être considéré comme un identifiant opaque sensible ; ne le diffusez pas publiquement.

## Requête anonyme

La page de paiement peut être lue directement lorsque l’état de connexion est perdu :

```shell
export ORDER_ID='votre ID de commande'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

La réponse anonyme ne contient que `id`, `description`, `price`, `state`, `pay_way`, `pay_url`, `expired_at`, `created_at`. Elle ne renvoie pas le compte, l’Application, le Package, les identifiants internes de paiement ni les metadata.

## Requête authentifiée

```shell
export PLATFORM_TOKEN='votre jeton de compte'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Le propriétaire de la commande recevra les détails complets de la commande, y compris `application` / `applications`, `package` / `packages`, `bank_details`, `invoice_automation` et les champs du modèle. Si l’utilisateur est authentifié mais n’est pas le propriétaire de la commande, la réponse est `403` ; sauf pour les superadministrateurs.

## Champs clés

| Champ            | Description                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`, `Paid`, `Finished`, `Expired`, `Failed` ou `Refunded` |
| `pay_way`     | Méthode de paiement actuelle de la commande ; le nom du champ n’est pas `payment_method`                             |
| `pay_url`     | Adresse de la page de paiement hébergée ou du code QR, peut être vide                                           |
| `price`       | Montant final dû pour la commande ; le modèle de commande actuel ne fournit pas de champ `final_price`                         |
| `amount`      | Quantité de quota du forfait ; visible uniquement dans la réponse complète authentifiée                                            |
| `finished_at` | Heure de finalisation de la commande ; le nom du champ n’est pas `paid_at`                                      |

La réponse complète peut ajouter des champs selon la méthode de paiement ; les clients doivent les lire selon les besoins et toujours éviter d’enregistrer les metadata sensibles dans la réponse complète.

## Gestion des erreurs

- `404` : l’ID de commande n’existe pas.
- `403` : l’utilisateur est connecté mais n’est pas le propriétaire de la commande.
- Les requêtes anonymes ne renvoient pas `401` ; elles obtiennent uniquement la projection publique minimale.
