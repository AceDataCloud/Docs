---
title: "Obtenir les détails d'une commande sur la plateforme AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Interrogez une commande via son ID de commande. Ce point de terminaison prend en charge deux modes de lecture : l'accès anonyme ne renvoie que les champs minimaux requis par la page de paiement ; le propriétaire de la commande portant un Account Token reçoit les détails complets.

## Aperçu de l'API

| Élément   | Contenu                                                        |
| --- | --------------------------------------------------------- |
| Méthode  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| Authentification  | Optionnelle ; projection minimale en anonyme, projection complète pour le propriétaire authentifié                                    |

`/orders/{id}` et `/orders/{id}/` sont actuellement tous deux disponibles. L'ID de commande fait partie du lien de paiement et doit être considéré comme un identifiant opaque sensible ; ne le diffusez pas publiquement.

## Requête anonyme

La page de paiement peut effectuer une lecture directe lorsque l'état de connexion est perdu :

```shell
export ORDER_ID='votre ID de commande'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

La réponse anonyme contient uniquement `id`, `description`, `price`, `state`, `pay_way`, `pay_url`, `expired_at`, `created_at`. Elle ne renvoie pas le compte, l'Application, le Package, les identifiants internes de paiement ou les metadata.

## Requête authentifiée

```shell
export PLATFORM_TOKEN='votre jeton de compte'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Le propriétaire de la commande reçoit les détails complets de la commande, y compris `application` / `applications`, `package` / `packages`, `bank_details`, `invoice_automation` et les champs du modèle. Si l'utilisateur est authentifié mais n'est pas le propriétaire de la commande, la réponse est `403` ; à l'exception des super administrateurs.

## Champs clés

| Champ            | Description                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`, `Paid`, `Finished`, `Expired`, `Failed` ou `Refunded` |
| `pay_way`     | Méthode de paiement actuelle de la commande ; le nom du champ n'est pas `payment_method`                             |
| `pay_url`     | Adresse de la page de paiement hébergée ou du code QR, peut être vide                                           |
| `price`       | Montant final à payer pour la commande ; le modèle de commande actuel ne fournit pas de champ `final_price`                         |
| `amount`      | Quantité de quota du forfait ; visible uniquement dans la réponse complète authentifiée                                            |
| `finished_at` | Heure de finalisation de la commande ; le nom du champ n'est pas `paid_at`                                      |

La réponse complète peut inclure des champs supplémentaires selon la méthode de paiement ; les clients doivent les lire selon les besoins et toujours éviter d'enregistrer les metadata sensibles dans la réponse complète.

## Gestion des erreurs

- `404` : l'ID de commande n'existe pas.
- `403` : connecté, mais n'est pas le propriétaire de la commande.
- Les requêtes anonymes ne renvoient pas `401` ; elles reçoivent seulement la projection publique minimale.

## Annulation par note de crédit de facture et nouvelle demande

Vous pouvez lire la facture actuelle de la commande via `GET /api/v1/orders/{order_id}/invoice/`. Après la soumission d'une annulation automatique par note de crédit, la facture reste à l'état `Issued`, et `red_state` indique la progression de l'annulation ; une soumission réussie ne signifie pas que l'annulation est terminée. Pendant l'attente de confirmation, l'émission de la note de crédit ou l'archivage, la commande ne peut pas demander à nouveau une facture.

Lorsqu'un administrateur demande une annulation par note de crédit en raison d'une erreur dans les informations de facturation, telles que l'intitulé ou le numéro fiscal, la raison de l'annulation est « erreur de facturation » ; l'annulation automatique par note de crédit déclenchée par le remboursement d'une commande continue d'utiliser « interruption de service ».

Une fois la note de crédit émise et archivée avec succès, la facture d'origine devient `Voided`, et la commande peut alors demander à nouveau une facture. La facture d'origine peut être consultée dans l'historique des factures. En cas d'échec de l'annulation par note de crédit ou si le résultat doit être vérifié, le traitement est effectué après vérification par le service financier, et les restrictions de facturation de la commande ne seront pas levées prématurément. Les factures émises manuellement doivent d'abord être annulées ou faire l'objet d'une note de crédit dans le système fiscal ou de facturation, puis être confirmées sur la plateforme par le service financier.
