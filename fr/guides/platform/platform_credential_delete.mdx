---
title: "Supprimer les identifiants API de la plateforme AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Supprime définitivement un identifiant API. Après suppression, il est **immédiatement impossible à récupérer**, et toutes les interfaces métier utilisant ce Token recevront immédiatement un `401`.

> ℹ️ Cette interface appartient à l’**API de gestion de la plateforme AceDataCloud**, avec le préfixe unifié `https://platform.acedata.cloud/api/v1/`.

## Aperçu de l’interface

| Élément   | Contenu                                                             |
| --- | ------------------------------------------------------------------- |
| Méthode  | `DELETE`                                                            |
| URL | `https://platform.acedata.cloud/api/v1/credentials/{credential_id}` |
| Authentification  | ✅ Jeton de compte requis                                                            |

`/credentials/{id}` et `/credentials/{id}/` sont actuellement tous deux disponibles ; les exemples utilisent uniformément la forme sans barre oblique finale.

## Description de l’authentification (comment obtenir un jeton de compte)

En-tête de requête :

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Pour la méthode d’obtention, voir [Gérer les jetons de compte de la plateforme AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

## Paramètres de chemin

| Paramètre              | Type   | Requis  | Description        |
| --------------- | ---- | --- | --------- |
| `credential_id` | UUID | ✅   | ID de l’identifiant à supprimer |

## Exemples de requête

### cURL

```shell
curl -X DELETE 'https://platform.acedata.cloud/api/v1/credentials/df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

cred_id = "df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6"
resp = requests.delete(
    f"https://platform.acedata.cloud/api/v1/credentials/{cred_id}",
    headers={"authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    timeout=10,
)
assert resp.status_code == 204, resp.text
print("✅ 已删除")
```

### Node.js

```javascript
const credId = 'df3e1b1b-9e72-4c4f-9a83-1e23f7c8b4d6'
const r = await fetch(`https://platform.acedata.cloud/api/v1/credentials/${credId}`, {
  method: 'DELETE',
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log('status:', r.status) // 204
```

## Réponse

- **Succès** : `HTTP 204 No Content`, **sans corps de réponse**.
- **Échec** : renvoie un JSON d’erreur, voir le tableau ci-dessous.

## Gestion des erreurs

| HTTP | code                | Signification         |
| ---- | ------------------- | ---------- |
| 401  | `not_authenticated` | Jeton de compte manquant     |
| 403  | `permission_denied` | Cet identifiant ne vous appartient pas    |
| 404  | `not_found`         | L’identifiant n’existe pas ou a été supprimé |

## Conseils pratiques

- **La suppression est irréversible** — la plateforme ne conserve pas de copie du Token. Si vous suspectez seulement une fuite mais souhaitez conserver les données de surveillance, vous devez utiliser la [rotation des identifiants API de la plateforme AceDataCloud](https://platform.acedata.cloud/documents/platform-credential-rotate) plutôt que la suppression.
- **La suppression ne rembourse pas le quota déjà consommé par cet identifiant**. Le solde de l’Application est déduit en temps réel selon la consommation, et la suppression de l’identifiant n’affecte pas le solde comptable.
- Après suppression, vous pouvez confirmer à nouveau les identifiants restants par `application_id` via la [liste des identifiants API](https://platform.acedata.cloud/documents/platform-credential-list).
- **Vérifiez d’abord les appelants avant un nettoyage en masse** : la liste ne contient actuellement pas de champ de dernière utilisation ; vous devez confirmer, à l’aide de la configuration de déploiement et des journaux d’appel, que l’identifiant n’est plus utilisé, puis les supprimer un par un.
