Renvoie de manière paginée les points de terminaison API visibles sur le site actuel. Convient pour rechercher des API par chemin métier, service ou étape de publication ; si vous avez uniquement besoin de la définition complète d’une API, appelez directement les [détails de l’API](https://platform.acedata.cloud/documents/platform-api-detail).

## Vue d’ensemble de l’interface

| Élément   | Contenu                                            |
| --- | --------------------------------------------- |
| Méthode  | `GET`                                         |
| URL | `https://platform.acedata.cloud/api/v1/apis/` |
| Authentification  | Publique, aucun jeton de compte requis                                     |
| Pagination  | `count` + `items`                             |

## Paramètres de requête

| Paramètre        | Type      | Requis  | Description                    |
| --------- | ------- | --- | --------------------- |
| `path`    | string  | Non   | Correspondance exacte avec `path` ou `path2` |
| `service` | string  | Non   | Alias ou UUID du service       |
| `stage`   | string  | Non   | Filtrer par étape de publication ; plusieurs valeurs peuvent être transmises de manière répétée      |
| `limit`   | integer | Non   | Nombre d’éléments par page, maximum 100           |
| `offset`  | integer | Non   | Décalage de pagination                 |

`id`, `service_id` et `tag` ne sont actuellement pas des paramètres de filtrage de liste ; leur transmission ne produira pas l’effet de filtrage correspondant.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/apis/' \
  --data-urlencode 'service=midjourney' \
  --data-urlencode 'stage=Production' \
  --data-urlencode 'limit=20' \
  -H 'Accept: application/json'
```

```python
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/apis/",
    params={"service": "midjourney", "limit": 20},
    timeout=30,
)
response.raise_for_status()
for api in response.json()["items"]:
    print(api["id"], api["method"], api["path"])
```

## Description de la réponse

La réponse en production utilise `{count, items}`. Chaque élément de liste contient actuellement les champs du modèle API, ainsi que :

- `document_id` : ID du document développeur associé, peut être vide ;
- `service_id` / `service` : ID et résumé du service principal, peuvent être vides ;
- `definition` : définition OpenAPI, peut être volumineuse ;
- `method`, `path`, `path2`, `stage`, `cost`, `tags`, `metadata`, etc.

Le serializer de liste contient actuellement `definition` ; lors de la récupération du catalogue complet, vous devez paginer et définir un délai d’expiration. Des champs peuvent être ajoutés de manière rétrocompatible ; le client ne doit lire que les champs requis.
