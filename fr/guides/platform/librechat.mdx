[LibreChat](https://www.librechat.ai/) est un client AI open source hautement configurable, qui utilise `librechat.yaml` pour décrire les fournisseurs, les modèles et les règles de routage. Il prend en charge des points de terminaison compatibles avec OpenAI personnalisés, permettant ainsi de se connecter à Ace Data Cloud. Cet article décrit le processus de configuration.

## Processus de demande

Pour intégrer Ace Data Cloud dans LibreChat, commencez par vous rendre sur le [tableau de bord Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre jeton API, à conserver pour référence.

![Obtenir la clé API Ace Data Cloud](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter. Après vous être connecté ou inscrit, vous serez automatiquement renvoyé à la page actuelle.

Lors de votre première demande, un quota gratuit sera offert, vous permettant d'expérimenter gratuitement les services de modèle d'Ace Data Cloud.

## Déployer LibreChat

LibreChat se déploie via Docker Compose, commencez par préparer le répertoire et télécharger la configuration officielle :

```bash
mkdir -p ~/librechat && cd ~/librechat
curl -O https://raw.githubusercontent.com/danny-avila/LibreChat/main/docker-compose.yml
curl -O https://raw.githubusercontent.com/danny-avila/LibreChat/main/.env.example
mv .env.example .env
```

Dans le fichier `.env`, générez `JWT_SECRET`, `JWT_REFRESH_SECRET`, `CREDS_KEY`, `CREDS_IV` et d'autres clés de sécurité avec `openssl rand -hex 32`, et configurez `ALLOW_REGISTRATION` selon vos besoins.

## Configurer Ace Data Cloud

Créez `librechat.yaml`, en ajoutant Ace Data Cloud comme point de terminaison OpenAI compatible personnalisé (pour une description complète des champs, voir la [documentation officielle des points de terminaison personnalisés](https://www.librechat.ai/docs/quick_start/custom_endpoints), remplacez `{token}` par votre jeton) :

```yaml
version: 1.0.5
cache: true

endpoints:
  custom:
    - name: "Ace Data Cloud"
      apiKey: "{token}"
      baseURL: "https://api.acedata.cloud/v1"
      models:
        default:
          - "MODEL_ID"
        fetch: true
      titleConvo: true
      titleModel: "MODEL_ID"
      modelDisplayLabel: "Ace Data Cloud"
```

Dans le fichier `docker-compose.yml`, montez ce fichier dans le service `api`, puis démarrez avec `docker compose up -d` :

```yaml
    volumes:
      - type: bind
        source: ./librechat.yaml
        target: /app/librechat.yaml
```

Notez les règles de chemin pour `baseURL` :

| baseURL                               | Requête réelle                                           | Résultat                   |
| ------------------------------------- | ------------------------------------------------------ | -------------------------- |
| `https://api.acedata.cloud/v1`        | `https://api.acedata.cloud/v1/chat/completions`      | Correct                    |
| `https://api.acedata.cloud/openai`    | `https://api.acedata.cloud/openai/chat/completions`  | Également utilisable       |
| `https://api.acedata.cloud/openai/v1` | `https://api.acedata.cloud/openai/v1/chat/completions` | 404 (`/openai` n'a pas `/v1`) |
| `https://api.acedata.cloud`           | `https://api.acedata.cloud/chat/completions`         | 404 (manque `/v1`)        |

## Choisir un modèle

Le répertoire des modèles sera mis à jour en continu. Utilisez de préférence la liste des modèles chargée automatiquement par le client ; si vous devez remplir manuellement, demandez d'abord `GET https://api.acedata.cloud/v1/models` pour obtenir l'ID du modèle actuel, puis choisissez en fonction des capacités de contexte, d'image et d'appel d'outils prises en charge par le client.

## Vérifier l'intégration

Si vous n'êtes pas sûr que le problème provienne de LibreChat ou du réseau, vous pouvez d'abord vérifier le point de terminaison directement avec curl (remplacez `{token}` par votre jeton) :

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

Le retour d'un objet `chat.completion` compatible avec OpenAI indique que le jeton et le point de terminaison sont prêts ; si vous recevez `HTTP 403 used_up`, cela signifie que le jeton est valide mais que le solde est insuffisant, rechargez sur le [tableau de bord](https://platform.acedata.cloud/console/applications).

## Avancé : astuces de configuration yaml

`librechat.yaml` prend en charge plusieurs groupes de points de terminaison, vous pouvez utiliser `apiKey: "user_provided"` pour permettre à chaque utilisateur de remplir sa propre clé ; `titleModel` spécifie le modèle pour générer le titre de la conversation ; `dropParams` peut être utilisé pour supprimer uniformément les paramètres non pris en charge par l'API cible. Pour plus de détails, voir [détails de la configuration de librechat.yaml](https://www.librechat.ai/docs/configuration/librechat_yaml).

## Questions fréquentes

### Pas de point de terminaison Ace Data Cloud après le démarrage

Il s'agit généralement d'un problème de montage du yaml dans le conteneur ou d'une erreur d'indentation. Vérifiez les volumes dans `docker-compose.yml` et validez l'indentation du yaml.

### Message 404

Le `baseURL` a été écrit comme `.../openai/v1` ou `/v1` a été omis. Modifiez-le en `https://api.acedata.cloud/v1`.

### Liste des modèles vide

Si `fetch: true` mais que `/v1/models` échoue, changez en `fetch: false` et listez manuellement `default`.

### Modifications du yaml non effectives

Il est nécessaire de redémarrer le conteneur : `docker compose restart api`.
