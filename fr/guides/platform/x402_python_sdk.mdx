Le SDK Python convient aux services backend, aux tâches de données, aux Agents automatisés et aux scripts de traitement par lots. `acedatacloud` est responsable des appels API, et `acedatacloud-x402` est responsable de la signature de l’en-tête de requête `PAYMENT-SIGNATURE`.

Adresses du code source et des packages :

- Dépôt SDK : [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Dépôt X402 Client : [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- SDK PyPI : [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)
- X402 Client PyPI : [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)

## Installer les dépendances

```bash
pip install acedatacloud acedatacloud-x402
```

Si vous souhaitez utiliser `upto`, vous devez également appeler une fois la CLI d’approbation Permit2, cette CLI dépend de `web3` :

```bash
pip install 'acedatacloud-x402[cli]'
```

La sortie de vérification de l’installation et des imports dans un venv Python propre :

```text
acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
approve-permit2  One-time ERC-20 approve(Permit2, amount) needed before signing upto payments.
```

Explication des résultats :

- `acedatacloud` et `acedatacloud-x402` peuvent tous deux être installés et importés depuis PyPI.
- `pip install 'acedatacloud-x402[cli]'` inclut la CLI `approve-permit2`, utilisée pour l’autorisation préalable de `upto`.

## Exemple Base

L’exemple suivant ne nécessite pas de Token API. La clé privée du portefeuille est uniquement utilisée pour signer localement et ne sera pas envoyée à Ace Data Cloud.

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)

print(res["choices"][0]["message"]["content"])
```

Le SDK Python renvoie actuellement un `dict`, l’exemple utilise donc `res["choices"][0]["message"]["content"]`. Ne supposez pas directement qu’il possède nécessairement un attribut `.choices`.

## Exemple Solana

Solana utilise une clé secrète encodée en base58 :

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import SolanaKeypairSigner, create_x402_payment_handler

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="solana",
        solana_signer=SolanaKeypairSigner.from_base58(os.environ["SOLANA_SECRET_KEY"]),
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

Le chemin Solana construit et soumet une transaction SPL USDC `TransferChecked`, puis place la signature de la transaction dans l’enveloppe `PAYMENT-SIGNATURE`.

La nouvelle tentative payante Solana a renvoyé HTTP 200 et `ADC_SOLANA_E2E_OK` sur l’API de production. Cette requête RPC publique a rencontré une limitation de débit et n’a pas permis de confirmer de manière stable la signature on-chain ; lorsque vous devez effectuer un rapprochement, veuillez utiliser votre propre RPC Solana pour interroger cette transaction.

## Client Async

Le même payment handler peut être utilisé avec `AsyncAceDataCloud` :

```python
import os

from acedatacloud import AsyncAceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AsyncAceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = await client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

## Utiliser la facturation différée `upto`

Le coût réel d’API telles que les complétions de chat et les appels de modèles peut ne être connu qu’après la fin de la réponse. Dans ce cas, l’API peut renvoyer simultanément `exact` et `upto`. Si vous souhaitez utiliser `upto` en priorité :

```python
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
        prefer_scheme="upto",
    )
)
```

Résultat d’exécution du programme Base `upto` :

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
settlement tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
settled value 3 atomic USDC
```

Confirmation on-chain :

```text
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
transfer value 3 atomic USDC
```

Explication des résultats :

- `content ADC_BASE_UPTO_OK` indique que la requête est réellement entrée dans l’API du modèle.
- `settled value 3 atomic USDC` indique que `upto` est réglé selon l’utilisation réelle, plutôt que de déduire la limite complète.
- `settlement tx` peut être ouvert dans BaseScan ; lors du rapprochement, conservez le hash tx, le payer, l’id de complétion et le résumé de la requête.

`upto` utilise l’autorisation Permit2 pour autoriser une limite supérieure, et le montant réel du règlement ne peut pas dépasser cette limite. Avant la première utilisation, vous devez effectuer une fois `approve(Permit2, amount)` pour l’USDC sur la chaîne cible.

Méthode CLI :

```bash
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Méthode programmatique :

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Ce helper est idempotent. Si l’allowance est déjà suffisante, il renverra `{"skipped": true}` et n’enverra pas à nouveau de transaction on-chain.

## Signature de bas niveau

Si vous n’utilisez pas le SDK, vous pouvez également appeler directement la fonction de signature de bas niveau :

```python
import base64
import json

from acedatacloud_x402 import EVMAccountSigner, sign_evm_payment

envelope = sign_evm_payment(requirement, EVMAccountSigner.from_private_key("0x..."))
x_payment = base64.b64encode(json.dumps(envelope, separators=(",", ":")).encode()).decode()
```

Les fonctions de bas niveau conviennent aux tests, à la couche proxy, à l’intégration de passerelles ou aux SDK non officiels. Le code métier ordinaire doit utiliser en priorité `create_x402_payment_handler`.
