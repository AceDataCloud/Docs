Interrogez les enregistrements d’utilisation du compte actuel sous les services de type Proxy. Pour les appels API ordinaires, veuillez utiliser les [enregistrements d’appels API](https://platform.acedata.cloud/documents/platform-usage-list). Si vous n’êtes pas certain du type de service, vous pouvez d’abord consulter le `type` dans les [détails du service](https://platform.acedata.cloud/documents/platform-service-detail).

## Préparatifs

1. Connectez-vous à la [plateforme AceDataCloud](https://platform.acedata.cloud).
2. Créez un jeton de compte dans la [console Account Token](https://platform.acedata.cloud/console/platform-tokens), et enregistrez-le immédiatement dans un gestionnaire de mots de passe ou un Secret Manager.
3. Ouvrez la [page de profil](https://auth.acedata.cloud/user/profile) pour copier l’UUID du compte actuel, et enregistrez-le comme `USER_ID`. Le `user_id` dans la réponse de création du jeton de compte peut également être utilisé.
4. Obtenez l’`application_id` du service de type Proxy depuis la [liste des demandes de service](https://platform.acedata.cloud/documents/platform-application-list). Lorsqu’un filtrage par point de terminaison Proxy est nécessaire, obtenez le `proxy_id` depuis la [liste des Proxy sous le service](https://platform.acedata.cloud/documents/platform-service-proxies).

Consultez [gérer les jetons de compte](https://platform.acedata.cloud/documents/platform-token) pour les instructions complètes sur les jetons. Cette interface utilise un Account Token, et non le Credential utilisé pour appeler l’API métier.

```shell
export PLATFORM_TOKEN='votre jeton de compte'
export USER_ID='votre UUID de compte'
export APPLICATION_ID='votre ID d’application Proxy'
```

## Aperçu de l’interface

| Élément     | Contenu                                                     |
| ----------- | ----------------------------------------------------------- |
| Méthode     | `GET`                                                       |
| URL         | `https://platform.acedata.cloud/api/v1/usage/proxies/`     |
| Authentification | `Authorization: Bearer ${PLATFORM_TOKEN}`              |
| Scope       | `usage:read`                                                |
| Pagination  | `count` + `items`, 10 éléments par page par défaut          |

Lorsque le propriétaire de l’Application effectue une requête avec `application_id`, le serveur synchronise d’abord les enregistrements disponibles de cette Application, puis renvoie la liste ; le temps de réponse peut donc être plus long que celui d’une liste d’utilisation API ordinaire. Les utilisateurs autorisés peuvent lire les enregistrements visibles existants, mais ne déclenchent pas la synchronisation côté propriétaire.

## Paramètres de requête

| Paramètre        | Type    | Obligatoire pour les utilisateurs ordinaires | Par défaut      | Description                                           |
| ---------------- | ------- | -------------------------------------------- | ---------------- | ----------------------------------------------------- |
| `user_id`        | UUID    | Oui                                          | —                | UUID du compte actuel ; un autre compte renvoie `403` |
| `application_id` | UUID    | Recommandé                                  | —                | Filtre par Proxy Application ; prend en charge les paramètres répétés |
| `proxy_id`       | UUID    | Non                                          | —                | Filtre par point de terminaison Proxy ; prend en charge les paramètres répétés |
| `limit`          | integer | Non                                          | 10               | Nombre d’éléments par page, maximum 100               |
| `offset`         | integer | Non                                          | 0                | Décalage de pagination                                |
| `ordering`       | string  | Non                                          | `-created_at`    | Ordre décroissant par heure de création               |

L’interface actuelle ne prend pas en charge le filtrage direct par modèle, code d’état HTTP, Credential ou plage temporelle, et ne prend pas non plus en charge le paramètre `perspective` de l’interface d’utilisation API. N’ajoutez pas ces paramètres non pris en charge à la requête en supposant qu’ils ont pris effet.

## Exemple de requête

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/proxies/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'limit=100' \
  --data-urlencode 'ordering=-created_at' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Exemple de pagination Python :

```python
import os
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/usage/proxies/",
    headers={"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    params={
        "user_id": os.environ["USER_ID"],
        "application_id": os.environ["APPLICATION_ID"],
        "limit": 100,
    },
    timeout=60,
)
response.raise_for_status()
data = response.json()

for usage in data["items"]:
    print(usage["created_at"], usage["deducted_amount"], usage["remaining_amount"])
```

## Champs clés

| Champ                    | Description                                                       |
| ------------------------ | ----------------------------------------------------------------- |
| `user_id`                | Compte qui supporte cette déduction                                |
| `actor_user_id`          | Appelant réel ; les anciens enregistrements peuvent être vides    |
| `application_id`         | Proxy Application ayant généré cet enregistrement                  |
| `proxy_id`               | Point de terminaison Proxy correspondant                           |
| `credential_id`          | ID du Credential associé ; les anciens enregistrements peuvent être vides |
| `used_amount`            | Utilisation de l’enregistrement d’origine ; peut être vide        |
| `deducted_amount`        | Montant finalement déduit                                         |
| `remaining_amount`       | Solde d’Application restant après la déduction                    |
| `metadata`               | Métadonnées publiques ; peuvent être vides                        |
| `service` / `credential` | Résumés des objets associés pour faciliter l’affichage ; peuvent être vides lorsque les objets associés n’existent pas |

L’unité de quota est déterminée par `service.unit` de l’Application correspondante.

## Gestion des erreurs

| HTTP | Signification                              | Méthode de traitement                                              |
| ---- | ------------------------------------------ | ------------------------------------------------------------------ |
| 401  | Jeton de compte manquant ou invalide       | Vérifiez l’Account Token, n’utilisez pas par erreur le Credential métier |
| 403  | Pas autorisé à consulter les enregistrements demandés | Utilisez l’Application du compte actuel, supprimez le `user_id` non autorisé |
| 5xx  | Échec temporaire de synchronisation ou de requête | Conservez les conditions de filtrage et réessayez avec un délai progressif ; en cas d’échec continu, fournissez l’ID d’Application et l’heure au support |
