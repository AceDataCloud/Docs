Le modèle Provider, l'IDE Extension et le MCP d'OpenCode sont trois capacités indépendantes. L'IDE Extension se connecte au runtime OpenCode local et réutilise la même configuration de Provider ; elle ne représente pas le support natif de l'éditeur hôte pour Ace Data Cloud.

| Route                           | Description                                               | Lien                                                                                     | État       |
| ------------------------------ | ------------------------------------------------------- | -------------------------------------------------------------------------------------- | ---------- |
| Terminal / CLI / TUI Provider  | Utilise `opencode.json[c]` et les Chat Completions     | [Configuration du Provider](https://platform.acedata.cloud/documents/opencode-terminal-integration) | Configuration validée |
| IDE Extension                  | VS Code, Cursor, Windsurf, VSCodium et autres hôtes se connectant au runtime OpenCode | [Configuration de l'IDE](https://platform.acedata.cloud/documents/opencode-ide-integration)           | Expérimental |
| MCP                            | Appel d'outils distants dans OpenCode                    | [Aperçu du MCP](https://platform.acedata.cloud/documents/opencode-mcp-all)                   | Capacité indépendante |

Une fois la configuration du Provider réussie, l'IDE Extension doit utiliser le même Provider et modèle. Il est toujours nécessaire de valider séparément les discussions, la lecture de fichiers, l'édition et les appels d'outils dans l'IDE, et il ne faut pas extrapoler automatiquement une demande ordinaire du CLI à toutes les capacités de l'IDE.

L'ID du modèle est basé sur le [répertoire en temps réel](https://platform.acedata.cloud/models).
