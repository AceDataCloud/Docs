---
title: "Obtenir la liste des modèles de la plateforme AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Renvoie le catalogue public des modèles de la plateforme, avec une réponse utilisant la structure de style OpenAI `{ "object": "list", "data": [...] }`. Ce catalogue est utilisé pour la sélection des modèles et la découverte des capacités, et ne signifie pas que le compte actuel a nécessairement demandé les services correspondants.

## Vue d’ensemble de l’interface

| Élément   | Contenu                                              |
| --- | ----------------------------------------------- |
| Méthode  | `GET`                                           |
| URL | `https://platform.acedata.cloud/api/v1/models/` |
| Authentification  | Public, aucun jeton de compte requis                                       |
| Pagination  | Pas de pagination, tous les éléments correspondants se trouvent dans `data`                              |

## Paramètres de requête

| Paramètre             | Type      | Obligatoire  | Description                                      |
| -------------- | ------- | --- | --------------------------------------- |
| `owned_by`     | string  | Non   | Filtre exactement selon l’identifiant du fournisseur de modèles dans le catalogue                        |
| `type`         | string  | Non   | Filtre exactement selon le type de modèle, par exemple `chat`                     |
| `capability`   | string  | Non   | Renvoie uniquement les modèles dont `capabilities` contient cette capacité, par exemple `vision` |
| `with_pricing` | boolean | Non   | Ajoute les informations de prix publiques lorsque la valeur est `1`, `true` ou `yes`            |

`service_id`, `tag`, `limit`, `offset` et `ordering` ne sont actuellement pas pris en charge ; les transmettre ne produira pas les effets de filtrage ou de pagination correspondants.

## Exemples de requêtes

```shell
# Tous les modèles publics
curl 'https://platform.acedata.cloud/api/v1/models/' \
  -H 'Accept: application/json'

# Modèles chat prenant en charge la vision, avec les prix
curl --get 'https://platform.acedata.cloud/api/v1/models/' \
  --data-urlencode 'type=chat' \
  --data-urlencode 'capability=vision' \
  --data-urlencode 'with_pricing=true' \
  -H 'Accept: application/json'
```

```python
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/models/",
    params={"type": "chat", "capability": "vision", "with_pricing": "true"},
    timeout=10,
)
response.raise_for_status()
payload = response.json()
for model in payload["data"]:
    print(model["id"], model["capabilities"], model.get("pricing"))
```

## Structure de réponse réelle

```json
{
  "object": "list",
  "data": [
    {
      "id": "example-model",
      "label": "Example Model",
      "owned_by": "example",
      "service_prefix": "acedatacloud-example",
      "group_label": "Example",
      "type": "chat",
      "capabilities": [
        "vision"
      ],
      "object": "model",
      "pricing": {
        "currency": "USD",
        "unit": "token",
        "input_usd": 1e-06,
        "output_usd": 2e-06,
        "official_input_usd": 1e-06,
        "official_output_usd": 2e-06,
        "savings_pct": 0,
        "credit_usd_rate": 0.1
      }
    }
  ],
  "credit_usd_rate": 0.1
}
```

`pricing` et `credit_usd_rate` au niveau supérieur apparaissent uniquement lorsque `with_pricing=true` ; tous les modèles ne disposent pas nécessairement d’un `pricing` calculable. Les objets de modèle sont basés sur les champs publics de `config/models.json`, et les clients doivent ignorer les nouveaux champs ajoutés.

> Les champs de prix sont des données d’affichage du catalogue. Les appels métier réels restent soumis aux règles de facturation de l’API/du Service correspondant et aux enregistrements d’utilisation finaux.
