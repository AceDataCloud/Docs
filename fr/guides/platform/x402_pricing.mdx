Ce document explique comment les prix sont définis lors de l'appel de l'API Ace Data Cloud avec X402, ainsi que leur relation avec les prix habituels des **Credits** (crédits) de la plateforme.

## Conclusion essentielle

X402 n'est pas un système de tarification indépendant. Chaque appel d'API possède déjà un coût en **Credits**, qui constitue l'unique source de prix partagée par tous les modes de facturation (déduction de crédits par API Token, solde du compte, paiement on-chain X402). X402 ne fait que convertir ce coût en Credits en USDC on-chain selon un taux de change fixe :

> **1 Credit = 0.095215 USDC** (soit `95215` atomic USDC, USDC ayant 6 décimales)

Autrement dit :

```text
Prix X402 (USDC) = coût en Credits de cet appel × 0.095215
```

Ce taux de change n'est pas défini arbitrairement : il est égal au **prix unitaire des Credits au meilleur palier (grand volume)** de la plateforme. Ainsi, payer avec X402 ≈ acheter des Credits au prix unitaire du meilleur palier puis les consommer, **sans majoration X402** ; vous bénéficiez au contraire directement du prix unitaire des Credits le plus bas, sans prérechargement ni API Token.

## Base de tarification

| Élément        | Valeur                              | Description                                                    |
| --------- | ------------------------------ | ----------------------------------------------------- |
| Taux de conversion      | `1 Credit = 0.095215 USDC`     | Taux de conversion fixe défini uniformément par la plateforme                                           |
| Unité atomic | `1 Credit = 95215 atomic USDC` | USDC a 6 décimales, `atomic = floor(credits × 0.095215 × 1e6)` |
| Facturation minimale      | `1 atomic USDC`（$0.000001）     | Même si le coût est très faible, au moins 1 atomic est facturé                                 |
| Devise de tarification      | USDC                           | Base utilise ERC-20 USDC, Solana utilise SPL USDC                  |

La conversion est effectuée uniformément par la plateforme, et le montant est identique sur tous les réseaux pris en charge (Base, Solana) ; les différents réseaux ne diffèrent que par le contrat d'actif et le mode de signature, le prix est le même.

### Relation avec le prix unitaire habituel des Credits

Les Credits de la plateforme sont vendus par paliers selon le principe « plus le volume est élevé, plus le prix unitaire est bas ». Lors de la facturation à l'appel, X402 utilise uniformément le prix unitaire du meilleur palier :

| Méthode d'achat/paiement        | Prix unitaire approximatif des Credits            | Description                   |
| -------------- | ------------------------ | -------------------- |
| Recharge débutant / faible montant      | Environ `$0.13 / Credit`       | Prix catalogue, prix unitaire lors de l'achat d'un faible montant de Credits |
| Grand volume / meilleur palier       | `$0.095215 / Credit`     | Prix unitaire le plus bas               |
| **Paiement X402 à l'appel** | **`$0.095215 / Credit`** | **Toujours égal au prix unitaire du meilleur palier**        |

En d'autres termes, X402 règle chaque appel au prix unitaire des Credits du meilleur palier. Le prix unitaire des utilisateurs qui achètent des Credits avec des recharges de faible montant est plus élevé que celui de X402 ; seul le prix unitaire des utilisateurs effectuant de grandes recharges est identique à celui de X402.

## Deux formes de prix : `exact` et `upto`

Dans la réponse 402 de X402, `maxAmountRequired` est le montant que vous devez signer. Il existe sous deux formes :

- **`exact` (prix fixe)** : le prix peut être déterminé avant le traitement de la requête (images, vidéos, musique, recherche, paiement de commandes). `maxAmountRequired = coût en Credits de cet appel × 0.095215`, soit le montant dû pour cet appel (identique à `cost.amount` dans la réponse réussie).
- **`upto` (mesure de l'utilisation après coup)** : pour les interfaces telles que les complétions de chat, où « le nombre de tokens utilisés n'est connu qu'à la fin de la réponse ». `maxAmountRequired` est un **plafond** (converti selon le plafond de crédits défini pour ce modèle : plafond de Credits × 0.095215), le règlement réel se fait selon l'utilisation réelle et ne dépasse pas ce plafond.

Pour les détails du protocole concernant ces deux schemes, consultez les [schémas de facturation `exact` et `upto`](https://platform.acedata.cloud/documents/x402-metered-upto). Seuls les prix sont abordés ci-dessous.

## Prix de Chat (complétion de chat)

La complétion de chat utilise la mesure `upto` : elle est facturée selon l'utilisation réelle des tokens prompt / completion. Le prix par million (1M) de tokens = `coût en Credits du modèle par 1M de tokens × 0.095215`, ce qui est exactement identique au prix unitaire en USD affiché dans le catalogue public des modèles de la plateforme (`/api/v1/models?with_pricing=true`).

Le tableau suivant présente les prix réels (issus du catalogue de modèles, calculés selon le taux de change X402), en USD / 1M tokens :

| Modèle                | Entrée / 1M | Sortie / 1M  | Plafond `upto`             |
| ----------------- | ------- | -------- | --------------------- |
| gpt-4o-mini       | $0.0796 | $0.3183  | 1 Credit（$0.095215）   |
| gemini-2.5-flash  | $0.1591 | $1.3262  | 5 Credits（$0.476074）  |
| gpt-5 / gpt-5.1   | $0.6631 | $5.3050  | 20 Credits（$1.904299） |
| gemini-2.5-pro    | $0.6631 | $5.3050  | 50 Credits（$4.760750） |
| gpt-4.1           | $1.0610 | $4.2440  | 20 Credits（$1.904299） |
| claude-sonnet-4-5 | $0.6006 | $3.0028  | 50 Credits（$4.760750） |
| grok-4            | $1.5915 | $7.9574  | 10 Credits（$0.952149） |
| claude-opus-4-1   | $3.0028 | $15.0140 | 50 Credits（$4.760750） |

Remarques :

- Le tableau présente les prix unitaires mesurés par token ; le coût d'une requête = tokens d'entrée × prix unitaire d'entrée + tokens de sortie × prix unitaire de sortie.
- Le plafond `upto` est le montant maximal autorisé à la signature pour une requête de ce modèle ; il ne correspond pas au montant réellement débité, et la grande majorité des requêtes reste bien en dessous du plafond.
- Le plafond détermine uniquement « le montant maximal pouvant être débité » ; le règlement réel est calculé selon l'utilisation des tokens.

### Exemple : le devis et le débit sont identiques (`exact`)

Voici un **appel payant réel** à `serp/google` effectué avec le X402Client officiel (Base `exact`). Il démontre la cohérence entre les trois éléments : le devis 402, le montant signé et le `cost` renvoyé dans la réponse réussie.

```text
# 1) Requête non payée -> 402, obtention du devis (aucun débit)
POST /serp/google  ->  402
base/exact maxAmountRequired = 952 atomic = $0.000952 = 0.01 Credit
# 0.01 × 0.095215 = 0.00095215, arrondi vers le bas à atomic = 952

# 2) Signer PAYMENT-SIGNATURE de 952 atomic avec le portefeuille, puis réessayer
POST /serp/google (PAYMENT-SIGNATURE) -> 200
body.cost = {"amount": 0.000952, "currency": "usdc", "settlement": "authorized"}
```
Le `cost.amount` renvoyé (0.000952 USDC) est entièrement cohérent avec le devis 402, et avec `Credits × 0.095215`. Le champ `settlement` est le statut de règlement de ce paiement (`authorized` = autorisé) ; le règlement on-chain est traité par la plateforme, voir le mécanisme des [schémas de facturation `exact` et `upto`](https://platform.acedata.cloud/documents/x402-metered-upto).

### Calcul du devis `upto` (chat)

Le chat est mesuré en tokens. Le devis d'une requête (et non le plafond) est calculé selon la formule suivante (en prenant gpt-4o-mini comme exemple) :

```text
Credits = 1e-6 × (0.835733 × prompt_tokens + 3.342933 × completion_tokens)
USDC    = Credits × 0.095215
```

Une requête de 500 tokens de prompt + 200 tokens de completion :

```text
Credits = 1e-6 × (0.835733 × 500 + 3.342933 × 200) ≈ 0.001086 Credits
Devis USDC ≈ 0.001086 × 0.095215 ≈ $0.0001034
```

Le client signe selon le plafond `upto` (pour gpt-4o-mini, 1 Credit = `95215` atomic), ce qui indique seulement le **montant maximal susceptible d'être débité** ; le devis réel de cette requête (environ $0.0001 dans l'exemple ci-dessus) est bien inférieur au plafond et est réglé selon l'utilisation en tokens. Voir le mécanisme de règlement on-chain de `upto` dans les [schémas de facturation `exact` et `upto`](https://platform.acedata.cloud/documents/x402-metered-upto).

## Prix des autres services (`exact` à prix fixe)

Le prix des interfaces telles que les images, vidéos, musiques et recherches peut être déterminé lors de la requête, elles utilisent donc `exact`. Remarques :

- Le prix d'un même service varie selon le **modèle, la résolution, la durée et les actions** (en particulier pour les vidéos). Le tableau ci-dessus présente des valeurs réelles pour un ensemble donné de paramètres, uniquement à titre indicatif d'ordre de grandeur.
- Pour ce type d'interface à prix fixe (`exact`), le `maxAmountRequired` dans la réponse 402 de cette requête correspond au montant dû pour cette requête (cohérent avec le `cost.amount` de la réponse réussie, déjà vérifié dans la section précédente).
- Chaque prix est obtenu en arrondissant à l'inférieur en unités atomic `Credits × 0.095215` (voir la base tarifaire ci-dessus), avec le même taux de conversion que celui utilisé pour le chat. En raison de la représentation en virgule flottante et de l'arrondi, certaines valeurs peuvent différer de 1 atomic ($0.000001) du produit naïf ; la valeur renvoyée par 402 prévaut systématiquement.

## Prix des paiements de commande

Lors du paiement de commandes du tableau de bord avec X402 (achat de forfaits / recharge de Credits), le prix affiché sur la page de commande prévaut, et le `amount` de 402 constitue la base finale de signature. Le paiement de commande passe par l'API de la plateforme et nécessite un jeton de compte, voir le [tutoriel de paiement de commande](https://platform.acedata.cloud/documents/x402-order-payment).

Un exemple réel du tutoriel de paiement de commande (achat de 10 Credits) :

```text
description Ace Data Cloud Credits x 10.0
created price 1.26          # prix de création de la commande (USD)
settled    1.20 USDC        # montant final de signature/règlement (= 402 amount)
            = 1200000 atomic USDC
```

Attention : le **paiement à l'utilisation** (Chat / autres services ci-dessus) et le **paiement de commande** sont deux parcours distincts. Le paiement à l'utilisation emploie uniformément le tarif optimal de `0.095215`/Credit ; le paiement de commande suit la tarification des forfaits, et la différence entre son prix de création et son montant final de règlement est soumise au [tutoriel de paiement de commande](https://platform.acedata.cloud/documents/x402-order-payment).

## Comment obtenir les prix en temps réel

Les prix varient selon les modèles et les paramètres ; veuillez les obtenir en temps réel par programme, sans les coder en dur :

- **Prix à l'utilisation** : envoyez une requête à l'API cible **sans** `PAYMENT-SIGNATURE` (et sans `Authorization`), puis lisez le `accepts[].maxAmountRequired` 402 renvoyé. Cette étape n'entraîne aucun débit. Pour les interfaces `exact`, il s'agit du prix final ; pour les interfaces `upto` (chat), il s'agit du plafond, le règlement réel étant effectué selon l'utilisation.
- **Prix du chat par token** : `GET https://platform.acedata.cloud/api/v1/models?with_pricing=true&type=chat`, lisez `pricing.input_usd` / `pricing.output_usd` de chaque modèle (déjà calculés selon `credit_usd_rate`).
- **Vérification de conversion** : `atomic = floor(Credits × 0.095215 × 1e6)`, `USDC = atomic / 1e6` (c'est-à-dire `USDC ≈ Credits × 0.095215`).

Exemple de requête minimale pour obtenir un prix :

```bash
curl -sS -X POST https://x402.acedata.cloud/midjourney/imagine \
  -H 'Content-Type: application/json' \
  -d '{"prompt": "a cat"}'
# Renvoie 402, accepts[].maxAmountRequired est le prix de cet appel (exact)
```

## Résumé
- Prix X402 = le coût en Credits de cet appel × `0.095215`, c’est **le même prix** que la facturation normale en Credits, mais réglé en USDC on-chain.
- `0.095215`/Credit est le prix unitaire des Credits au **meilleur palier** (volume élevé) de la plateforme ; les petites recharges achètent les Credits à un prix unitaire plus élevé, donc X402 équivaut à obtenir automatiquement le meilleur prix unitaire.
- Le montant signé pour les interfaces `exact` (images / vidéos / musique / recherche / commandes) est le montant à payer pour cet appel ; les interfaces `upto` (chat) signent le plafond et règlent selon l’utilisation réelle.
- Le prix faisant autorité est basé sur le `maxAmountRequired` retourné par 402 : pour `exact`, il s’agit du montant à payer (identique au `cost.amount` de la réponse réussie, testé) ; pour `upto`, il s’agit du plafond, et seul le `cost.amount` de la réponse réussie est le montant réel réglé selon l’utilisation (≤ plafond).
