Interrogez les détails des appels d’API métier du compte actuel au cours des 60 derniers jours, ce qui convient pour vérifier la facturation, localiser les requêtes échouées, ainsi que rechercher des problèmes par service, Application, API ou identifiant.

> Cette page interroge le journal d’appels du propre compte. Si vous souhaitez uniquement consulter les statistiques publiques d’appels d’une API sur l’ensemble de la plateforme, utilisez les [statistiques d’appels d’API](https://platform.acedata.cloud/documents/platform-api-usage).

## Plage de conservation des données

Les enregistrements d’appels et les résumés de facturation sont conservés pendant les 60 derniers jours ; les corps des requêtes et des réponses sont conservés pendant les 30 derniers jours. Les enregistrements de 30 à 60 jours peuvent toujours interroger des résumés tels que trace, statut, heure, modèle, utilisation et montant réellement déduit ; `metadata.request` et `metadata.response` dans les détails ne sont plus renvoyés. Les résumés requis pour les agrégations de modèles et les statistiques de résultats valides sont conservés avant l’expiration des corps. Si vous devez conserver les corps à long terme, veuillez les enregistrer vous-même lors de l’appel.

## Préparatifs

### 1. Créer un jeton de compte

Cette interface appartient à l’API de gestion de la plateforme et nécessite l’utilisation d’un **Account Token (jeton de compte)** :

1. Connectez-vous à la [plateforme AceDataCloud](https://platform.acedata.cloud).
2. Ouvrez la [console Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. Cliquez sur « Créer », puis enregistrez immédiatement le jeton dans un gestionnaire de mots de passe ou Secret Manager.

Pour les instructions complètes, consultez [Gérer les jetons de compte de la plateforme AceDataCloud](https://platform.acedata.cloud/documents/platform-token). Les jetons de compte sont utilisés pour `platform.acedata.cloud/api/v1/**` ; les interfaces métier `api.acedata.cloud/**` utilisent des identifiants API (Credential), et les deux ne peuvent pas être mélangés.

```shell
export PLATFORM_TOKEN='你的账户令牌'
```

N’écrivez pas le jeton dans le code frontend, les journaux ou les dépôts publics ; s’il est divulgué, supprimez-le et recréez-le immédiatement dans la console.

### 2. Préparer les ID de filtrage (facultatif)

Vous pouvez consulter les enregistrements auxquels le compte actuel a accès sans transmettre de conditions de filtrage. Si vous devez réduire le périmètre :

- `application_id` : obtenez-le depuis la [liste des demandes de service](https://platform.acedata.cloud/documents/platform-application-list) ;
- `credential_id` : obtenez-le depuis la [liste des identifiants API](https://platform.acedata.cloud/documents/platform-credential-list) ;
- `api_id` : obtenez-le depuis la [liste des API](https://platform.acedata.cloud/documents/platform-api-list) ;
- `service_id` : obtenez-le depuis la [liste des services](https://platform.acedata.cloud/documents/platform-service-list).

Les utilisateurs ordinaires n’ont pas besoin de transmettre `user_id` ; s’il est explicitement transmis, il doit correspondre au compte actuel, sinon `403` est renvoyé. Les administrateurs peuvent utiliser ce paramètre pour filtrer entre les comptes.

## Aperçu de l’interface

| Élément       | Contenu                                                   |
| ------------- | --------------------------------------------------------- |
| Méthode       | `GET`                                                     |
| URL           | `https://platform.acedata.cloud/api/v1/usage/apis/`       |
| Authentification | `Authorization: Bearer ${PLATFORM_TOKEN}`              |
| OAuth Scope   | `usage:read` (`platform:read` / `platform` peuvent inclure) |
| Pagination    | `count` + `items`, 10 éléments par page par défaut        |

## Périmètre de requête

| `perspective` | Signification                                      |
| ------------- | -------------------------------------------------- |
| `both`        | Valeur par défaut ; renvoie les enregistrements payés ou effectivement appelés par le compte actuel |
| `billing`     | Renvoie uniquement les enregistrements payés par le compte actuel |
| `actor`       | Renvoie uniquement les enregistrements effectivement appelés par le compte actuel |

## Paramètres de requête

| Paramètre         | Type       | Obligatoire | Par défaut     | Description                                      |
| ----------------- | ---------- | ----------- | -------------- | ------------------------------------------------ |
| `perspective`     | string     | Non         | `both`         | `billing`, `actor` ou `both`                     |
| `user_id`         | UUID       | Non         | —              | Filtrage par utilisateur réservé aux administrateurs ; prend en charge les paramètres répétés |
| `service_id`      | UUID       | Non         | —              | Filtrage par service ; prend en charge les paramètres répétés |
| `application_id`  | UUID       | Non         | —              | Filtrage par Application ; prend en charge les paramètres répétés |
| `api_id`          | UUID       | Non         | —              | Filtrage par API ; prend en charge les paramètres répétés |
| `credential_id`   | UUID       | Non         | —              | Filtrage par identifiant API ; prend en charge les paramètres répétés |
| `status_code`     | integer    | Non         | —              | Filtrage par code de statut HTTP ; prend en charge les valeurs répétées ou séparées par des virgules |
| `created_at_from` | datetime   | Non         | —              | Limite inférieure de l’heure de création, ISO 8601 |
| `created_at_to`   | datetime   | Non         | —              | Limite supérieure de l’heure de création, ISO 8601 |
| `limit`           | integer    | Non         | 10             | Nombre d’éléments par page, maximum 100          |
| `offset`          | integer    | Non         | 0              | Décalage de pagination                           |
| `ordering`        | string     | Non         | `-created_at`  | Ordre décroissant par heure de création          |

Lorsque l’heure de requête est antérieure aux 60 derniers jours, l’interface renvoie une erreur de validation de champ `400`, indiquant que les détails complets des appels ne sont conservés que pendant 60 jours.

## Exemples de requêtes

Interroger les 100 derniers enregistrements :

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/' \
  --data-urlencode 'perspective=both' \
  --data-urlencode 'limit=100' \
  --data-urlencode 'ordering=-created_at' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Filtrer par heure, Application et statut d’échec :

```shell
export APPLICATION_ID='你的 Application ID'

curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/' \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'created_at_from=2026-09-01T00:00:00Z' \
  --data-urlencode 'created_at_to=2026-09-02T00:00:00Z' \
  --data-urlencode 'status_code=500' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Exemple de pagination Python :

```python
import os
import requests

url = "https://platform.acedata.cloud/api/v1/usage/apis/"
headers = {"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"}
params = {"perspective": "both", "limit": 100, "offset": 0}

response = requests.get(url, headers=headers, params=params, timeout=30)
response.raise_for_status()
data = response.json()

for usage in data["items"]:
    print(usage["created_at"], usage["status_code"], usage["deducted_amount"], usage["trace_id"])

if params["offset"] + len(data["items"]) < data["count"]:
    params["offset"] += len(data["items"])
```

## Champs clés

| Champ                               | Description                                  |
| -------------------------------- | ----------------------------------- |
| `user_id`                        | Le compte qui prend en charge cette déduction                           |
| `actor_user_id`                  | Le compte qui effectue réellement l'appel ; il peut être différent de `user_id` lorsqu'une personne est autorisée à utiliser les identifiants |
| `used_amount`                    | La consommation de cet appel calculée selon les règles d'origine                       |
| `original_amount`                | La consommation d'origine avant la remise de l'application                          |
| `deducted_amount`                | Le quota effectivement déduit au final                           |
| `remaining_amount`               | Le quota restant de l'Application après cette déduction           |
| `elapsed`                        | La durée d'appel enregistrée côté serveur, en secondes                     |
| `trace_id`                       | L'identifiant de traçage utilisé pour diagnostiquer une requête individuelle                      |
| `metadata`                       | Métadonnées publiques ; la liste ne renvoie pas le contenu complet de la requête ou de la réponse               |
| `api` / `service` / `credential` | Résumés des objets associés pour faciliter l'affichage ; ils peuvent être vides si les objets associés n'existent plus           |

L'unité de quota est déterminée par `service.unit` de l'Application correspondante et ne doit pas être considérée comme des dollars par défaut.

## Erreurs et tentatives

| HTTP | `error`                   | Signification             | Méthode de traitement                               |
| ---- | ------------------------- | -------------- | ---------------------------------- |
| 400  | Erreur de validation des champs                    | La plage de requête est antérieure à la période de conservation de 60 jours | Ajustez l'heure de début pour qu'elle se situe dans les 60 derniers jours                  |
| 401  | `not_authenticated`       | Jeton de compte manquant ou invalide      | Vérifiez l'Account Token, n'utilisez pas par erreur le Credential métier |
| 403  | `permission_denied`       | La requête contient des enregistrements que vous n'êtes pas autorisé à consulter    | Supprimez les conditions de filtrage des utilisateurs non autorisés                       |
| 429  | `usage_query_in_progress` | Une requête entièrement identique est toujours en cours d'exécution    | Réessayez avec un délai d'attente progressif après `Retry-After`             |
| 503  | `usage_query_timeout`     | La requête dépasse le délai de sécurité côté serveur    | Réessayez après avoir réduit la plage temporelle ou ajouté des conditions de filtrage                   |

Un seul appel en cours est conservé au maximum pour le même ensemble de paramètres de requête. Pour les requêtes à grande échelle, utilisez de préférence une fenêtre d'un jour ou moins, et n'empilez pas de requêtes identiques à intervalle fixe.
