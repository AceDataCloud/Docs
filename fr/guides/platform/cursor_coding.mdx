description: "Platform API guide - Ace Data Cloud"

Cursor propose actuellement une clé API OpenAI et un paramètre **Override OpenAI Base URL**, permettant de se connecter à des services compatibles avec OpenAI. Cette capacité existe, mais les différentes versions traitent `/chat/completions`, `/responses`, la liste des modèles ainsi que les modes Agent/Composer de manière pas entièrement cohérente.

La compatibilité peut varier selon les différentes versions de Cursor, les systèmes d'exploitation et les modes de requête. Veuillez suivre la configuration de cette page pour compléter la vérification des modes réels, ne déduisez pas que toutes les fonctionnalités sont disponibles sur la base d'un seul chat réussi.

## Ce que Cursor garantit actuellement pour BYOK

Selon la [documentation officielle de Cursor sur Bring your own API key](https://cursor.com/help/models-and-usage/api-keys) :

- Prise en charge des identifiants OpenAI, Anthropic, Google, Azure OpenAI et AWS Bedrock ;
- La clé API personnalisée est uniquement utilisée pour les modèles de chat, la complétion d'onglet continue d'utiliser les modèles intégrés de Cursor ;
- La clé API n'est pas persistée sur le serveur Cursor, mais est envoyée à chaque requête au backend de Cursor, pour la construction finale du prompt ;
- Lors de l'utilisation de votre propre clé, la politique de Zero Data Retention de Cursor ne s'applique pas, le traitement des données suit la politique du fournisseur choisi.

## Configuration

1. Ouvrez les paramètres de Cursor → Modèles.
2. Remplissez votre jeton API Ace Data Cloud dans OpenAI API Key.
3. Activez **Override OpenAI Base URL**, remplissez `https://api.acedata.cloud/v1`.
4. Sélectionnez ou ajoutez un ID de modèle précis compatible avec le protocole actuel de Cursor.
5. Envoyez d'abord `Reply only OK`, puis testez séparément les modes Ask/Edit/Agent que vous utilisez réellement.

## Limites actuelles

- La clé API personnalisée est uniquement utilisée pour les modèles de chat, la complétion d'onglet continue d'utiliser les modèles intégrés de Cursor.
- Cursor peut encore compléter la construction finale du prompt sur le serveur ; veuillez évaluer le chemin des données en fonction des explications de confidentialité officielles.
- L'Override de l'URL de base peut ne couvrir qu'une partie des requêtes, ou changer en raison de variations de version entre Chat Completions/Responses.
- On ne doit pas affirmer que les modes Agent, Auto, Composer ou les tâches en arrière-plan sont tous connectés simplement sur la base d'une requête de chat réussie.

## Vérification complète de la compatibilité

Pour une utilisation à long terme dans un flux de travail de production, veuillez également compléter les vérifications suivantes :

1. Version de Cursor et système d'exploitation fixes ;
2. Réaliser un test de fumée avec un client réel pour cette version, et enregistrer le protocole et le chemin de la requête finale ;
3. La requête de Chat Completions pour le modèle exact réussit ;
4. Les appels d'outils et les requêtes d'Agent passent bien par le point de terminaison cible ;
5. La consommation et la facturation peuvent être vérifiées ;
6. Enregistrer clairement si la requête est passée par le serveur Cursor et les restrictions de confidentialité correspondantes.

Les vérifications doivent être répétées après une mise à niveau du client pour s'assurer que le protocole de requête, les appels d'outils et le chemin des données n'ont pas changé.
