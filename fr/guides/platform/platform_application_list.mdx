---
title: "Obtenir la liste des demandes de services de la plateforme AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Renvoie de manière paginée les Applications détenues par le compte ou dont l'utilisation est autorisée, y compris le solde, le statut, le résumé du service et les identifiants associés. Convient à la surveillance groupée des soldes, à la recherche d'Application ID et à l'accès à la gestion des identifiants.

## Préparatifs

1. Connectez-vous à la [plateforme AceDataCloud](https://platform.acedata.cloud).
2. Créez un jeton de compte dans la [console Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. Les utilisateurs ordinaires utilisent `user_id=me` ; vous pouvez également obtenir votre propre UUID depuis `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='votre jeton de compte'
```

## Aperçu de l'interface

| Élément   | Contenu                                                    |
| --- | ----------------------------------------------------- |
| Méthode  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Authentification  | Account Token, le jeton OAuth nécessite `applications:read`       |
| Pagination  | `count` + `items`                                     |

Les utilisateurs ordinaires doivent transmettre `user_id=me`. Sans cela, la requête n'est pas d'abord restreinte par compte, et la pagination peut renvoyer `403` lorsqu'elle rencontre des objets non autorisés ; les administrateurs peuvent consulter toute la table sans le transmettre.

## Paramètres de requête

| Paramètre            | Type          | Obligatoire     | Description                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Obligatoire pour les utilisateurs ordinaires | Sujet de la requête ; prend en charge les paramètres répétés                                         |
| `affiliation` | string      | Non      | `owner` (par défaut) ou `granted` ; les deux peuvent être transmis de manière répétée pour prendre leur union, ne prend effet qu'en présence de `user_id` |
| `service_id`  | UUID        | Non      | Filtrer par service ; prend en charge les paramètres répétés                                        |
| `scope`       | string      | Non      | `Individual` ou `Global` ; prend en charge les paramètres répétés                      |
| `type`        | string      | Non      | `Usage` ou `Period` ; prend en charge les paramètres répétés                           |
| `limit`       | integer     | Non      | Nombre d'éléments par page, maximum 100                                         |
| `offset`      | integer     | Non      | Décalage de pagination                                               |
| `ordering`    | string      | Non      | Prend uniquement en charge `created_at` ou `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` et `tag` ne sont actuellement pas des paramètres de filtrage côté serveur. Les alertes de solde doivent récupérer la liste, puis déterminer côté client selon `remaining_amount`, `service.unit` et les seuils métier de chaque Application.

## Exemple de requête

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Consulter simultanément les Applications que vous détenez et celles que d'autres vous ont autorisé à utiliser :

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Description de la réponse

La réponse est `{count, items}`. Chaque élément contient les champs du modèle Application, et ajoute :

- `service` : `id`, `alias`, `title`, `type`, `unit`, `icon_url` ;
- `credentials` : le résumé des identifiants que l'appelant actuel est autorisé à voir ;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`, `allow_overdraft` ;
- la valeur réelle de `scope` est `Individual` ou `Global` ;
- la valeur réelle de `type` est `Usage` ou `Period`.

`allow_overdraft` est un champ booléen en lecture seule contrôlé par l'administrateur, avec une valeur par défaut de `false`. Pour les applications à l'usage (`Usage`) dont le découvert est activé, un solde insuffisant ne bloque pas les appels et la facturation s'effectue toujours selon l'utilisation réelle ; un solde négatif représente un montant en attente de règlement. La désactivation, l'expiration et les limites des identifiants API restent applicables.

`remaining_amount` peut être vide ; le client doit d'abord vérifier qu'il n'est pas vide avant d'effectuer une comparaison numérique. L'unité du quota est déterminée par `service.unit`.
