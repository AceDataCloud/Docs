Obtenez l’état complet d’une seule demande de service via l’Application ID — par rapport à l’interface de liste, elle ajoute des champs tels que l’objet `service` complet (y compris les forfaits `packages`), adaptée aux pages de détails.

> ℹ️ Cette interface appartient à l’**API de gestion de la plateforme AceDataCloud**, avec le préfixe unifié `https://platform.acedata.cloud/api/v1/`. Pour l’index complet des interfaces, consultez [Obtenir la liste de la documentation de la plateforme AceDataCloud](https://platform.acedata.cloud/documents/platform-document-list).

## Aperçu de l’interface

| Élément   | Contenu                                                               |
| --- | --------------------------------------------------------------------- |
| Méthode  | `GET`                                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/{application_id}` |
| Authentification  | ✅ Jeton de compte requis                                                              |

`/applications/{id}` et `/applications/{id}/` sont actuellement tous deux disponibles ; les exemples utilisent tous le format sans barre oblique finale.

## Instructions d’authentification (comment obtenir un jeton de compte)

En-tête de requête :

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Pour la méthode d’obtention détaillée, consultez [Gérer les jetons de compte de la plateforme AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

> ℹ️ Contrairement à l’interface de liste, **la vérification des autorisations de l’interface de détails est effectuée directement sur un objet unique**, il n’est pas nécessaire de transmettre `?user_id=`. Mais si vous accédez à la demande d’une autre personne, vous recevrez `403 permission_denied`.

## Paramètres de chemin

| Paramètre               | Type   | Obligatoire  | Description             |
| ---------------- | ---- | --- | -------------- |
| `application_id` | UUID | ✅   | Application ID |

## Exemples de requêtes

### cURL

```shell
curl 'https://platform.acedata.cloud/api/v1/applications/82f57141-2323-4453-8730-60f7d833a2da' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

app_id = "82f57141-2323-4453-8730-60f7d833a2da"
resp = requests.get(
    f"https://platform.acedata.cloud/api/v1/applications/{app_id}",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}",
    },
    timeout=10,
)
app = resp.json()
print(f"服务：{app['service']['title']}")
print(f"剩余 {app['remaining_amount']} {app['service']['unit']} / 已用 {app['used_amount']}")
```

### Node.js

```javascript
const appId = '82f57141-2323-4453-8730-60f7d833a2da'
const r = await fetch(`https://platform.acedata.cloud/api/v1/applications/${appId}`, {
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log(await r.json())
```

## Description des champs de réponse

La signification des champs est identique à celle de [l’interface de liste](https://platform.acedata.cloud/documents/platform-application-list), avec en supplément :

| Champ        | Type     | Description                                                        |
| --------- | ------ | --------------------------------------------------------- |
| `service` | object | Objet de service complet (y compris les forfaits `packages`, `unit`, `free_amount`), permettant d’afficher directement le panneau des détails du service |

## Gestion des erreurs

| HTTP | code                | Signification                  |
| ---- | ------------------- | ------------------- |
| 401  | `not_authenticated` | Jeton de compte manquant              |
| 403  | `permission_denied` | Cette Application ne vous appartient pas  |
| 404  | `not_found`         | L’Application n’existe pas ou a été supprimée |

## Conseils pratiques

- **Pour la surveillance en masse, utilisez en priorité la liste** : récupérez la liste des Applications en une seule fois, puis évaluez selon l’unité et le seuil de chaque service, afin d’éviter de demander les détails un par un.
- **Lorsque vous devez consulter le nombre de justificatifs** : utilisez la [liste des identifiants API](https://platform.acedata.cloud/documents/platform-credential-list) et filtrez par `application_id`.
- **Piste d’investigation pour `disabled=true`** : vérifiez les tickets / notifications par e-mail pour savoir si le service a été suspendu en raison du contrôle des risques, d’impayés ou d’appels non conformes ; il ne peut pas être réactivé via l’API, vous devez contacter le service client.
