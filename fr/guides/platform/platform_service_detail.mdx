Obtenez les informations complètes d’un seul service via l’ID du service (UUID) ou l’alias (alias) — les champs retournés sont plus complets que ceux de la [liste des services de la plateforme AceDataCloud](https://platform.acedata.cloud/documents/platform-service-list), avec les objets associés tels que `apis`, `proxies`, `datasets`, `packages`, etc. développés en supplément. Convient aux scénarios tels que les pages de détails des services, les pages de comparaison des tarifs, les descriptions d’outils Agent, etc.

> ℹ️ Cette interface appartient à l’**API de gestion de la plateforme AceDataCloud**, avec le préfixe unifié `https://platform.acedata.cloud/api/v1/`. Consultez l’index complet des interfaces dans [Obtenir la liste des documents de la plateforme AceDataCloud](https://platform.acedata.cloud/documents/platform-document-list).

## Aperçu de l’interface

| Élément   | Contenu                                                            |
| --- | ------------------------------------------------------------- |
| Méthode  | `GET`                                                         |
| URL | `https://platform.acedata.cloud/api/v1/services/{service_id}` |
| Authentification  | ❌ Publique                                                          |

`/services/{id}` et `/services/{id}/` sont actuellement tous deux disponibles ; les exemples utilisent uniformément la forme sans barre oblique finale.

## Description de l’authentification

Cette interface est entièrement publique. **Cependant, après avoir fourni un jeton de compte, le champ `applied` dans la réponse reflétera l’état réel de la demande du compte actuel**, sinon il sera toujours égal à `false`.

Consultez [Gérer les jetons de compte de la plateforme AceDataCloud](https://platform.acedata.cloud/documents/platform-token) pour savoir comment obtenir un jeton de compte.

## Paramètres de chemin

| Paramètre           | Type            | Obligatoire  | Description                                                    |
| ------------ | ------------- | --- | ----------------------------------------------------- |
| `service_id` | UUID / string | ✅   | ID du service (UUID) ou alias (`midjourney`, `openai`, `webextrator`, etc.) |

## Exemples de requêtes

### cURL

```shell
# 按 UUID 查询
curl 'https://platform.acedata.cloud/api/v1/services/8efa1d83-9b75-4562-b44a-af95ce563d05' \
  -H 'accept: application/json'

# 按 alias 查询
curl 'https://platform.acedata.cloud/api/v1/services/midjourney' \
  -H 'accept: application/json'

# 带账户令牌看 applied 状态
curl 'https://platform.acedata.cloud/api/v1/services/midjourney' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

resp = requests.get(
    "https://platform.acedata.cloud/api/v1/services/midjourney",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}",
    },
    timeout=10,
)
svc = resp.json()
print(f"服务: {svc['title']} ({svc['alias']})")
print(f"已申请: {svc['applied']}, 免费额度: {svc['free_amount']} {svc['unit']}")
print(f"API 数: {len(svc['apis'])}, 套餐数: {len(svc['packages'])}")
for pkg in svc["packages"]:
    print(f"  ¥{pkg['price']:>7.2f}  ->  {pkg['amount']} {svc['unit']}")
```

### Node.js

```javascript
const r = await fetch('https://platform.acedata.cloud/api/v1/services/midjourney', {
  headers: { accept: 'application/json' },
})
const svc = await r.json()
console.log(`${svc.title} - 套餐 ${svc.packages.length} 个 - API ${svc.apis.length} 个`)
```

## Description des champs de réponse

L’interface de détails développe en supplément, au-delà de tous les champs de l’[interface de liste](https://platform.acedata.cloud/documents/platform-service-list) :

| Champ         | Type    | Description                                                            |
| ---------- | ----- | ------------------------------------------------------------- |
| `apis`     | array | Liste complète des objets API associés (chaque entrée contient `id`, `name`, `title`, `path`, `stage`, `cost`) |
| `proxies`  | array | Liste complète des objets Proxy associés                                              |
| `datasets` | array | Jeux de données associés (si `type=Dataset`)                                      |
| `packages` | array | Liste des forfaits, contenant `type` (`Usage`/`Period`), `price`, `amount`, `duration`   |

Pour les définitions des autres champs, consultez [Obtenir la liste des services de la plateforme AceDataCloud → Description des champs de réponse](https://platform.acedata.cloud/documents/platform-service-list).

## Gestion des erreurs

| HTTP | code        | Signification                            |
| ---- | ----------- | ----------------------------- |
| 404  | `not_found` | `service_id` (UUID ou alias) n’existe pas |
| 500  | —           | Généralement, une barre oblique a été ajoutée par erreur à la fin de l’URL ; supprimez-la puis réessayez          |

## Conseils pratiques

- **`alias` > `UUID`** : encoder en dur l’`alias` (tel que `midjourney`) dans le code est plus stable ; l’UUID change lors de la migration d’environnements.
- **Le champ `apis` ne contient pas la définition OpenAPI** : le schéma OpenAPI 3.0 complet se trouve dans l’interface [Obtenir les détails de l’API de la plateforme AceDataCloud](https://platform.acedata.cloud/documents/platform-api-detail).
- **Récupérer les « capacités complètes » d’un service** : utilisez cette interface pour obtenir `api_ids`, puis appelez `/apis/{api_id}` un par un afin de récupérer les détails.
- **Si `applied=true`**, vous pouvez directement [créer des identifiants API](https://platform.acedata.cloud/documents/platform-credential-create) pour obtenir le Token de 32 caractères nécessaire à l’appel des interfaces métier, sans avoir à effectuer une nouvelle demande.
