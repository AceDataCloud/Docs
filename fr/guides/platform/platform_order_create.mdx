---
title: "Créer une commande de recharge sur la plateforme AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Créez une commande en attente de paiement pour une ou plusieurs Applications. La création enregistrera la commande, mais ne finalisera pas automatiquement le paiement ; avant le paiement, vérifiez le `price`, le forfait et l'Application dans la réponse.

## Préparatifs

- Créez un [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Obtenez le `application_id` depuis la [liste des Applications](https://platform.acedata.cloud/documents/platform-application-list).
- Sélectionnez dans les `packages` des [détails du service](https://platform.acedata.cloud/documents/platform-service-detail) un `package_id` correspondant au type d'Application et pouvant être acheté.

```shell
export PLATFORM_TOKEN='你的账户令牌'
export APPLICATION_ID='你的 Application ID'
export PACKAGE_ID='你的 Package ID'
```

## Aperçu de l'interface

| Élément    | Contenu                                         |
| ---- | ----------------------------------------------- |
| Méthode   | `POST`                                          |
| URL  | `https://platform.acedata.cloud/api/v1/orders/` |
| Authentification   | Account Token, le jeton OAuth nécessite `orders:write`      |
| Body | JSON                                            |

## Corps de la requête

Les commandes pour une seule Application utilisent `application_id` + `package_id` ; les commandes par lot utilisent `application_ids` + `package_ids` de longueurs correspondantes. Les commandes ordinaires sélectionnent le mode de paiement dans la requête `/pay/` ultérieure. Les commandes d'achat intégré iOS transmettent `pay_way: "AppleIAP"` lors de leur création, et ne peuvent sélectionner qu'un seul forfait Usage contenant `metadata.apple_product_id` et `metadata.apple_price`. Les achats intégrés Apple utilisent un prix prédéfini indépendant en dollars américains, sans cumul de remise membre, de remise liée au mode de paiement ou de majoration du site ; le montant du débit dans la devise locale pour les autres régions prévaut selon la page de confirmation de paiement Apple.

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/orders/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"package_id\":\"${PACKAGE_ID}\"}"
```

## Description de la réponse

En cas de succès, renvoie `201` et le nouvel objet Order créé. Les champs clés incluent `id`, `price`, `discount`, `state`, `application_id/application_ids`, `package_id/package_ids`, `expired_at` et les champs temporels. Les nouvelles commandes sont généralement `Pending`, puis appelez [Payer une commande](https://platform.acedata.cloud/documents/platform-order-pay).

- `price` est le montant payable calculé par le serveur selon le forfait, la majoration du site et les remises ; ne le calculez pas vous-même côté client.
- Si le Package ne correspond pas au service ou au type de l'Application, renvoie `400`.
- Les Packages gratuits et gérés par le système ne peuvent pas être obtenus directement via l'interface publique des commandes.
- La création d'une commande pour une Application n'appartenant pas au compte actuel sera refusée.
