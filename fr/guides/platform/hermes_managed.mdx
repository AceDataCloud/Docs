Créez une instance de conteneur Hermes indépendante pour chaque Application. Par défaut, une image de base d'une version publiée fixe est utilisée, en conservant les fonctionnalités natives ; la plateforme fournit l'achat, le renouvellement, le stockage persistant et la gestion du déploiement.

## Création et achat

1. Ouvrez [Déploiement Hermes](https://platform.acedata.cloud/services/hermes) et créez une Application.
2. Sélectionnez un forfait de durée sur la page d'achat et finalisez le paiement.
3. Retournez à la page de configuration, sélectionnez un modèle de chat de la plateforme dans la liste déroulante et consultez le prix actuel du modèle. La plateforme créera des identifiants API indépendants pour cette instance ; vous pouvez aussi désactiver l'accès à la plateforme et effectuer la configuration vous-même dans la console native.
4. Choisissez de générer automatiquement les identifiants d'accès, ou définissez votre propre mot de passe/Token fort ; cochez A2A et EnvarPay selon vos besoins, puis confirmez pour commencer le déploiement. Les identifiants d'accès et les identifiants API du modèle sont indépendants les uns des autres.
5. Une fois l'instance prête, récupérez l'adresse d'accès et les identifiants de connexion depuis la page de gestion.
6. Connectez-vous à la console native pour configurer les canaux. Si l'accès au modèle de la plateforme a été désactivé lors du déploiement, vous devez également configurer vous-même le fournisseur de modèles et les identifiants pour pouvoir utiliser le chat.

Les frais de déploiement sont facturés selon la durée du forfait ; les prix exacts en dollars américains et les durées sont indiqués sur la page d'achat. Les frais d'appel de modèle sont facturés séparément ; l'achat d'une durée de déploiement n'offre pas de crédit de modèle. Lorsque l'accès à la plateforme est activé, les identifiants API dédiés n'ouvrent que l'interface de chat correspondant au modèle sélectionné, et les appels sont facturés séparément sur votre solde de plateforme. Chaque Application est achetée, renouvelée et gérée séparément.

## Mots de passe, identifiants et configuration ultérieure

Les identifiants d'accès sont définis avant le premier démarrage. La génération automatique utilise des identifiants aléatoires, le mot de passe personnalisé doit comporter au moins 16 caractères, et le Token OpenClaw au moins 32 caractères. Les brouillons n'enregistrent pas les mots de passe ; il peut être nécessaire de les saisir à nouveau après avoir changé de page. Après le déploiement, seuls le propriétaire et les administrateurs de l'Application peuvent consulter les identifiants d'accès.

Les identifiants API de modèle de chaque instance ne sont pas réutilisés entre elles, leur validité est prolongée avec le renouvellement du déploiement et ils sont révoqués lors de la suppression de l'instance. Si le modèle de la plateforme n'a pas été connecté lors du premier déploiement, vous pouvez sélectionner un modèle de plateforme sur la page de configuration de cette Application et redéployer ; la plateforme mettra à jour le modèle par défaut, tout en conservant les sessions et les autres paramètres natifs. Modifiez ensuite les modèles et les canaux dans la console native ; si vous choisissez à la place un modèle d'un autre service, ajustez d'abord l'autorisation de l'interface correspondante dans la gestion des identifiants de la plateforme, ou utilisez les identifiants appropriés. Un redéploiement normal n'écrase pas les paramètres natifs. Les environnements de déploiement non validés pour publication refuseront temporairement les nouveaux déploiements ; contactez le support.

## Composants de déploiement optionnels

Après avoir coché A2A, le modèle de déploiement démarrera la passerelle A2A native de Hermes et fournira un jeton de propriétaire dans la page de gestion. En cochant EnvarPay, un conteneur de service indépendant et un registre persistant seront installés en supplément ; A2A doit d'abord être activé. EnvarPay ne dispose initialement que des identifiants d'accès du propriétaire, sans identité de service ni de paiement, et ne facture ni n'achète automatiquement pour vous. Aucune des deux options n'enregistre automatiquement l'instance auprès d'Envar ; les instances existantes peuvent accéder à la configuration depuis la page de gestion, puis redéployer après l'activation. Les composants déjà activés ne peuvent pas encore être désactivés dans cet assistant.

## Versions et données

La page de configuration affiche la version d'image actuellement publiée. Les nouvelles instances utilisent la version actuellement publiée du service ; les instances existantes ne sont pas automatiquement remplacées lors des mises à jour du catalogue. Le redéploiement applique la version actuelle du service ; effectuez d'abord une sauvegarde et confirmez les exigences de mise à niveau de la version utilisée.

Chaque instance fournit par défaut 1 CPU, une limite de mémoire de 2 GiB et 10 GiB de stockage persistant. Les données de l'instance sont conservées après un redémarrage. La suppression active du déploiement ou la récupération à l'expiration supprimera le stockage ; exportez à l'avance les données à conserver.

## Renouvellement et expiration

Renouvelez sur la page d'achat de l'Application actuelle ; la durée de validité est prolongée selon les règles de durée existantes de la plateforme. Après l'expiration, le point d'accès est suspendu, et un renouvellement pendant la période de grâce rétablit l'accès ; après la période de grâce, l'instance et les données seront récupérées. Référez-vous à l'heure d'expiration, au statut de facturation et aux avertissements de suppression sur la page de gestion.

## Connexion à l'interface de gestion

Copiez l'adresse du Dashboard, le nom d'utilisateur `admin` et le mot de passe depuis la page de gestion du déploiement, puis ouvrez-la pour vous connecter. Les informations de connexion sont fournies uniquement au propriétaire de cette Application et aux administrateurs de la plateforme. Les modèles, compétences et canaux sont configurés dans l'interface native de Hermes.

## Questions fréquentes

- **Pourquoi la nouvelle instance ne peut-elle pas encore répondre ?** La fin du déploiement indique seulement que le conteneur est prêt. Si l'accès au modèle de la plateforme a été désactivé lors du déploiement, vous devez sélectionner un modèle de plateforme sur la page de configuration et redéployer, ou configurer vous-même le modèle et les identifiants dans l'interface native.
- **Des plugins supplémentaires ou un fallback de modèle sont-ils préinstallés ?** Aucun n'est ajouté par défaut ; configurez-les selon vos besoins dans l'interface native.
- **Comment mettre à jour une instance existante ?** L'Application et la commande existantes sont conservées, et la version actuelle du service est utilisée lors du redéploiement ; sauvegardez d'abord les données et vérifiez la compatibilité de version avant la mise à niveau.
- **Que faire en cas d'échec du démarrage ?** Consultez d'abord les journaux et les événements de déploiement, puis configurez le modèle une fois que l'instance est prête. N'exposez pas le mot de passe et les clés de l'instance dans des commentaires publics ou des captures d'écran.
