Créez une instance de conteneur Hermes indépendante pour chaque Application. Par défaut, une image de base d’une version publiée fixe est utilisée, en conservant les fonctionnalités natives ; la plateforme fournit l’achat, le renouvellement, le stockage persistant et la gestion du déploiement.

## Création et achat

1. Ouvrez [Déploiement Hermes](https://platform.acedata.cloud/services/hermes) et créez une Application.
2. Sélectionnez une formule de durée sur la page d’achat et effectuez le paiement.
3. Revenez à la page de configuration, sélectionnez un modèle de chat de la plateforme dans la liste déroulante et consultez le prix actuel du modèle. La plateforme créera des identifiants API indépendants pour cette instance ; vous pouvez également désactiver l’accès à la plateforme et effectuer vous-même la configuration dans la console native.
4. Choisissez de générer automatiquement des identifiants d’accès, ou définissez votre propre mot de passe/Token robuste, puis confirmez pour démarrer le déploiement. Les identifiants d’accès et les identifiants API du modèle sont indépendants l’un de l’autre.
5. Une fois l’instance prête, obtenez l’adresse d’accès et les identifiants de connexion depuis la page de gestion.
6. Connectez-vous à la console native pour configurer les canaux. Si l’accès au modèle de la plateforme a été désactivé lors du déploiement, vous devez également configurer vous-même le fournisseur du modèle et les identifiants pour pouvoir utiliser le chat.

Les frais de déploiement sont facturés selon la durée de la formule ; les prix exacts en dollars américains et les durées font foi sur la page d’achat. Les frais d’appel de modèle sont facturés séparément ; l’achat d’une durée de déploiement n’offre pas de crédits de modèle. Lorsque l’accès à la plateforme est activé, les identifiants API dédiés n’ouvrent que l’interface de chat correspondant au modèle sélectionné, et les appels sont facturés séparément sur votre solde de plateforme. Chaque Application est achetée, renouvelée et gérée séparément.

## Mots de passe, identifiants et configuration ultérieure

Les identifiants d’accès sont définis avant le premier démarrage. La génération automatique utilise des identifiants aléatoires, les mots de passe personnalisés doivent comporter au moins 16 caractères, et les OpenClaw Token au moins 32 caractères. Les brouillons n’enregistrent pas les mots de passe ; vous devrez peut-être les saisir à nouveau après avoir changé de page. Après le déploiement, seuls le propriétaire de l’Application et les administrateurs peuvent consulter les identifiants d’accès.

Les identifiants API du modèle de chaque instance ne sont pas réutilisés entre elles, leur validité est prolongée avec le renouvellement du déploiement et ils sont révoqués lorsque l’instance est supprimée. Si vous n’avez pas connecté le modèle de la plateforme lors du premier déploiement, vous pouvez sélectionner un modèle de plateforme dans la page de configuration de cette Application et redéployer ; la plateforme mettra à jour le modèle par défaut tout en conservant les sessions et les autres paramètres natifs. Ensuite, modifiez les modèles et les canaux dans la console native ; si vous sélectionnez le modèle d’un autre service, ajustez d’abord l’autorisation de l’interface correspondante dans la gestion des identifiants de la plateforme, ou utilisez les identifiants appropriés. Un redéploiement ordinaire n’écrasera pas les paramètres natifs. Les environnements de déploiement qui n’ont pas été validés pour publication refuseront temporairement les nouveaux déploiements ; contactez le support.

## Version et données

La page de configuration affiche la version de l’image actuellement publiée. Les nouvelles instances utilisent la version actuellement publiée du service ; les instances existantes ne sont pas automatiquement remplacées lors des mises à jour du catalogue. Le redéploiement appliquera la version actuelle du service ; sauvegardez d’abord vos données et confirmez les exigences de mise à niveau de la version utilisée.

Chaque instance fournit par défaut 1 CPU, une limite de mémoire de 2 Gio et 10 Gio de stockage persistant. Les données de l’instance sont conservées après un redémarrage. La suppression volontaire du déploiement ou la récupération à expiration supprimera le stockage ; exportez à l’avance les données que vous souhaitez conserver.

## Renouvellement et expiration

Renouvelez sur la page d’achat de l’Application actuelle ; la période de validité sera prolongée selon les règles de durée existantes de la plateforme. Après expiration, le point d’accès est suspendu ; un renouvellement pendant la période de grâce rétablit l’accès. Après la période de grâce, l’instance et les données seront récupérées. Référez-vous à la date d’expiration, à l’état de facturation et aux avertissements de suppression dans la page de gestion.

## Connexion à l’interface de gestion

Sur la page de gestion du déploiement, copiez l’adresse Dashboard, le nom d’utilisateur `admin` et le mot de passe, puis ouvrez-la pour vous connecter. Les informations de connexion sont fournies uniquement au propriétaire de cette Application et aux administrateurs de la plateforme. Les modèles, compétences et canaux sont configurés dans l’interface native de Hermes.

## Questions fréquentes

- **Pourquoi la nouvelle instance ne peut-elle pas encore répondre ?** La fin du déploiement signifie uniquement que le conteneur est prêt. Si l’accès au modèle de la plateforme a été désactivé lors du déploiement, vous devez sélectionner un modèle de plateforme dans la page de configuration et redéployer, ou configurer vous-même le modèle et les identifiants dans l’interface native.
- **Des plugins supplémentaires ou un fallback de modèle sont-ils préinstallés ?** Aucun n’est ajouté par défaut ; configurez-les selon vos besoins dans l’interface native.
- **Comment mettre à jour une instance existante ?** L’Application et la commande existantes sont conservées, et la version actuelle du service est utilisée lors du redéploiement ; sauvegardez les données et vérifiez la compatibilité des versions avant la mise à niveau.
- **Que faire en cas d’échec du démarrage ?** Consultez d’abord les journaux et les événements du déploiement, puis configurez le modèle après avoir confirmé que l’instance est prête. N’exposez pas les mots de passe et les clés de l’instance dans des commentaires ou captures d’écran publics.
