Créer une instance de conteneur Hermes indépendante pour chaque Application. Utilise par défaut une image de base d’une version publiée fixe, en conservant les fonctionnalités natives ; la plateforme fournit l’achat, le renouvellement, le stockage persistant et la gestion du déploiement.

## Création et achat

1. Ouvrez [Déploiement Hermes](https://platform.acedata.cloud/services/hermes) et créez une Application.
2. Sélectionnez une formule de durée sur la page d’achat et terminez le paiement.
3. Retournez à la page de configuration, où vous pouvez sélectionner un modèle de chat de la plateforme dans la liste déroulante et consulter le prix actuel du modèle. La plateforme créera des identifiants API indépendants pour cette instance ; vous pouvez également désactiver l’accès à la plateforme et effectuer vous-même la configuration dans la console native.
4. Choisissez de générer automatiquement des identifiants d’accès, ou définissez votre propre mot de passe/Token fort, puis confirmez pour démarrer le déploiement. Les identifiants d’accès et les identifiants API du modèle sont indépendants les uns des autres.
5. Une fois l’instance prête, récupérez l’adresse d’accès et les identifiants de connexion depuis la page de gestion.
6. Connectez-vous à la console native et configurez vos propres fournisseurs de modèles, clés et canaux.

Les frais de déploiement sont facturés selon la durée de la formule ; les prix précis en dollars américains et les durées prévalent selon la page d’achat. Les frais d’appel de modèle sont facturés séparément ; l’achat d’une durée de déploiement n’offre pas de crédits de modèle. Lorsque l’accès à la plateforme est activé, les identifiants API dédiés n’ouvrent que l’interface de chat correspondant au modèle sélectionné, et les appels sont facturés séparément sur le solde de votre plateforme. Chaque Application est achetée, renouvelée et gérée séparément.

## Mots de passe, identifiants et configuration ultérieure

Les identifiants d’accès sont définis avant le premier démarrage. La génération automatique utilise des identifiants aléatoires, le mot de passe personnalisé comporte au moins 16 caractères, et le Token OpenClaw au moins 32 caractères. Les brouillons n’enregistrent pas les mots de passe ; il peut être nécessaire de les saisir à nouveau après un changement de page. Après le déploiement, seuls le propriétaire et les administrateurs de l’Application peuvent consulter les identifiants d’accès.

Les identifiants API de modèle de chaque instance ne sont pas réutilisés, leur validité est prolongée avec le renouvellement du déploiement, et ils sont révoqués lors de la suppression de l’instance. Après l’initialisation du déploiement, veuillez modifier les modèles et les canaux dans la console native ; si vous choisissez plutôt le modèle d’un autre service, ajustez d’abord l’autorisation de l’interface correspondante dans la gestion des identifiants de la plateforme, ou utilisez les identifiants correspondants. Un redéploiement ordinaire n’écrasera pas les paramètres natifs. Les environnements de déploiement non validés pour la publication refuseront temporairement les nouveaux déploiements ; veuillez contacter le support.

## Version et données

La page de configuration affiche la version d’image actuellement publiée. Les nouvelles instances utilisent la version actuellement publiée du service ; les instances existantes ne sont pas automatiquement remplacées avec les mises à jour du catalogue. Le redéploiement appliquera la version actuelle du service ; veuillez d’abord effectuer une sauvegarde et confirmer les exigences de mise à niveau de la version utilisée.

Chaque instance fournit par défaut 1 CPU, une limite de 2 GiB de mémoire et 10 GiB de stockage persistant. Les redémarrages conservent les données de l’instance. La suppression active du déploiement ou la récupération à l’expiration supprimera le stockage ; veuillez exporter à l’avance les données devant être conservées.

## Renouvellement et expiration

Renouvelez sur la page d’achat de l’Application actuelle ; la période de validité est prolongée selon les règles de durée existantes de la plateforme. Après expiration, le point d’accès est suspendu, et un renouvellement pendant la période de grâce rétablit l’accès ; après la période de grâce, l’instance et les données seront récupérées. Référez-vous à la date d’expiration, à l’état de facturation et aux indications de suppression sur la page de gestion.

## Connexion à l’interface de gestion

Sur la page de gestion du déploiement, copiez l’adresse Dashboard, le nom d’utilisateur `admin` et le mot de passe, puis ouvrez-la pour vous connecter. Les informations de connexion sont fournies uniquement au propriétaire de cette Application et aux administrateurs de la plateforme. Les modèles, compétences et canaux sont configurés dans l’interface native de Hermes.

## Questions fréquentes

- **Pourquoi la nouvelle instance ne peut-elle pas encore répondre ?** La fin du déploiement signifie que le conteneur est prêt ; vous devez configurer les modèles et les identifiants dans l’interface native avant de pouvoir commencer à l’utiliser.
- **Des plugins supplémentaires ou un fallback de modèle sont-ils préinstallés ?** Aucun n’est ajouté par défaut ; configurez-les selon vos besoins dans l’interface native.
- **Comment mettre à jour une instance existante ?** L’Application et la commande d’origine sont conservées, et la version actuelle du service est utilisée lors du redéploiement ; sauvegardez d’abord les données et vérifiez la compatibilité des versions avant la mise à niveau.
- **Que faire en cas d’échec du démarrage ?** Consultez d’abord les journaux et les événements du déploiement, puis configurez le modèle après avoir confirmé que l’instance est prête. N’exposez pas le mot de passe et les clés de l’instance dans des commentaires publics ou des captures d’écran.
