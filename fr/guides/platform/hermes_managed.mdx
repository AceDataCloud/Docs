Créez une instance de conteneur Hermes indépendante pour chaque Application. Utilise par défaut une image de base d’une version publiée fixe, en conservant les fonctionnalités natives ; la plateforme fournit l’achat, le renouvellement, le stockage persistant et la gestion du déploiement.

## Création et achat

1. Ouvrez [Déploiement Hermes](https://platform.acedata.cloud/services/hermes) et créez une Application.
2. Sélectionnez une formule de durée sur la page d’achat, puis terminez le paiement.
3. Retournez à la page de configuration, sélectionnez un modèle de chat de la plateforme dans la liste déroulante, et consultez le prix actuel du modèle. La plateforme créera des identifiants API indépendants pour cette instance ; vous pouvez aussi désactiver l’accès à la plateforme et effectuer la configuration vous-même dans la console native.
4. Choisissez de générer automatiquement des identifiants d’accès, ou définissez votre propre mot de passe/Token robuste ; cochez A2A et EnvarPay selon vos besoins, puis confirmez pour commencer le déploiement. Les identifiants d’accès et les identifiants API du modèle sont indépendants les uns des autres.
5. Une fois l’instance prête, obtenez l’adresse d’accès et les identifiants de connexion depuis la page de gestion.
6. Connectez-vous à la console native pour configurer les canaux. Si l’accès aux modèles de la plateforme a été désactivé lors du déploiement, vous devez aussi configurer vous-même le fournisseur de modèles et les identifiants pour pouvoir utiliser le chat.

Les frais de déploiement sont facturés selon la durée de la formule ; les prix précis en dollars américains et les durées font foi sur la page d’achat. Les frais d’appel des modèles sont facturés séparément ; l’achat d’une durée de déploiement n’offre pas de quota de modèle. Lorsque l’accès à la plateforme est activé, les identifiants API dédiés n’ouvrent que l’interface de chat correspondant au modèle sélectionné, et les appels sont facturés séparément sur votre solde de plateforme. Chaque Application est achetée, renouvelée et gérée séparément.

## Mots de passe, identifiants et configuration ultérieure

Les identifiants d’accès sont définis avant le premier démarrage. La génération automatique utilise des identifiants aléatoires, les mots de passe personnalisés doivent comporter au moins 16 caractères, et les OpenClaw Token au moins 32 caractères. Les brouillons n’enregistrent pas les mots de passe ; vous devrez peut-être les saisir de nouveau après avoir changé de page. Après le déploiement, seuls le propriétaire et les administrateurs de l’Application peuvent consulter les identifiants d’accès.

Les identifiants API de modèle de chaque instance ne sont pas réutilisés, leur période de validité est prolongée avec le renouvellement du déploiement, et ils sont révoqués lorsque l’instance est supprimée. Si vous n’avez pas connecté le modèle de la plateforme lors du premier déploiement, vous pouvez sélectionner un modèle de plateforme dans la page de configuration de cette Application et redéployer ; la plateforme mettra à jour le modèle par défaut, tout en conservant les conversations et les autres paramètres natifs. Modifiez ensuite les modèles et les canaux dans la console native ; si vous sélectionnez un modèle d’un autre service, ajustez d’abord l’autorisation de l’interface correspondante dans la gestion des identifiants de la plateforme, ou utilisez les identifiants correspondants. Un redéploiement ordinaire n’écrase pas les paramètres natifs. Les environnements de déploiement non validés par publication refuseront temporairement les nouveaux déploiements ; contactez le support.

## Composants de déploiement optionnels

Après avoir coché A2A, le modèle de déploiement démarrera la passerelle A2A native de Hermes et fournira un jeton de propriétaire sur la page de gestion. Cocher EnvarPay installera en plus un conteneur de service indépendant et un registre persistant, et nécessite d’abord l’activation de A2A. EnvarPay ne possède initialement que les identifiants d’accès du propriétaire, sans identité de service ou de paiement, et ne facturera ni n’achètera automatiquement. Les deux options n’enregistreront pas automatiquement l’instance auprès d’Envar ; les instances existantes peuvent accéder à la configuration depuis la page de gestion, puis redéployer après activation. Les composants déjà activés ne peuvent pas encore être désactivés dans cet assistant.

Une fois A2A activé et l’instance prête, la carte d’adresse d’accès sur la page de gestion affichera une adresse Agent Card pouvant être copiée. Le A2A natif de Hermes utilise une adresse publique indépendante ; l’adresse de connexion Dashboard ne peut pas être utilisée comme adresse Agent Card. Si EnvarPay est également activé, la page de gestion affichera aussi l’« adresse d’intégration Envar » correspondante ; lors de l’intégration d’un service à Envar, copiez de préférence cette URL.

## Version et données

La page de configuration affiche la version d’image actuellement publiée. Les nouvelles instances utilisent la version actuellement publiée du service ; les instances existantes ne sont pas automatiquement remplacées lors des mises à jour du catalogue. Le redéploiement appliquera la version actuelle du service ; effectuez d’abord une sauvegarde et confirmez les exigences de mise à niveau de la version utilisée.

Chaque instance fournit par défaut 1 CPU, une limite de mémoire de 2 GiB et 10 GiB de stockage persistant. Les données de l’instance sont conservées lors du redémarrage. La suppression active du déploiement ou la récupération à l’expiration supprimera le stockage ; exportez à l’avance les données à conserver.

## Renouvellement et expiration

Renouvelez sur la page d’achat de l’Application actuelle ; la période de validité sera prolongée selon les règles de durée existantes de la plateforme. Après l’expiration, le point d’accès est suspendu, et un renouvellement pendant la période de grâce rétablit l’accès ; après la période de grâce, l’instance et les données seront récupérées. Référez-vous à l’heure d’expiration, à l’état de facturation et aux indications de suppression de la page de gestion.

## Connexion à l’interface de gestion

Copiez l’adresse Dashboard, le nom d’utilisateur `admin` et le mot de passe depuis la page de gestion du déploiement, puis ouvrez-la pour vous connecter. Les informations de connexion sont fournies uniquement au propriétaire de cette Application et aux administrateurs de la plateforme. Les modèles, compétences et canaux sont configurés dans l’interface native de Hermes.

## Questions fréquentes

- **Pourquoi une nouvelle instance ne peut-elle pas encore répondre ?** La fin du déploiement indique uniquement que le conteneur est prêt. Si l’accès aux modèles de la plateforme a été désactivé lors du déploiement, sélectionnez les modèles de la plateforme dans la page de configuration et redéployez, ou configurez vous-même les modèles et les identifiants dans l’interface native.
- **Des plugins supplémentaires sont-ils préinstallés ?** Aucun n’est ajouté par défaut ; vous pouvez les configurer selon vos besoins dans l’interface d’administration.
- **Comment mettre à jour une instance existante ?** L’application et la commande existantes sont conservées ; lors du redéploiement, utilisez la version actuelle du service. Avant la mise à niveau, sauvegardez les données et vérifiez la compatibilité des versions.
- **Que faire en cas d’échec du démarrage ?** Consultez d’abord les journaux et les événements de déploiement, puis configurez les modèles après avoir confirmé que l’instance est prête. N’exposez pas le mot de passe ni les clés de l’instance dans des commentaires publics ou des captures d’écran.
