---
title: "Obtenir les statistiques agrégées du volume d'appels API de la plateforme AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Agrège par date et par API le nombre de requêtes et le montant réellement déduit pour le compte actuel, adapté à la création de rapports mensuels, de graphiques de tendances et d'analyses de coûts. Pour le débogage entrée par entrée, utilisez la [liste des enregistrements d'appels](https://platform.acedata.cloud/documents/platform-usage-list) ; pour les détails hors ligne complets, utilisez l'[export du volume d'appels](https://platform.acedata.cloud/documents/platform-usage-export).

La période de consultation des enregistrements d'appels et des résumés de facturation couvre les 60 derniers jours ; les corps des requêtes et des réponses sont conservés séparément pendant les 30 derniers jours. L'expiration des corps ne modifie pas les frais réels, l'utilisation ou les statistiques agrégées de cet enregistrement.

## Préparatifs

1. Connectez-vous à la [plateforme AceDataCloud](https://platform.acedata.cloud).
2. Créez un jeton de compte dans la [console Account Token](https://platform.acedata.cloud/console/platform-tokens), puis enregistrez-le immédiatement.
3. Pour restreindre le périmètre, obtenez les ID correspondants depuis la [liste des demandes de service](https://platform.acedata.cloud/documents/platform-application-list), la [liste des identifiants API](https://platform.acedata.cloud/documents/platform-credential-list) ou la [liste des API](https://platform.acedata.cloud/documents/platform-api-list).

Pour une description complète des jetons, consultez [Gérer les jetons de compte](https://platform.acedata.cloud/documents/platform-token). Cette interface utilise un Account Token et n'utilise pas de Credential métier.

```shell
export PLATFORM_TOKEN='你的账户令牌'
```

## Aperçu de l'interface

| Élément           | Contenu                                                       |
| ----------------- | ------------------------------------------------------------- |
| Méthode           | `GET`                                                         |
| URL               | `https://platform.acedata.cloud/api/v1/usage/apis/aggregate/` |
| Authentification  | `Authorization: Bearer ${PLATFORM_TOKEN}`                     |
| OAuth Scope       | `usage:read`（`platform:read` / `platform` 可展开包含）              |
| Périmètre des autorisations | Les utilisateurs ordinaires sont limités à leur propre utilisation payante ; les administrateurs peuvent transmettre `user_id`                                |

## Paramètres de requête

| Paramètre         | Type              | Obligatoire | Par défaut                              | Description                                   |
| ----------------- | --------------- | ----------- | --------------------------------------- | --------------------------------------------- |
| `created_at_from` | date / datetime | Non         | Premier jour du mois en cours dans le fuseau horaire sélectionné | Heure de début, nom de paramètre recommandé                           |
| `created_at_to`   | date / datetime | Non         | Heure actuelle                          | Heure de fin, nom de paramètre recommandé                           |
| `timezone`        | string          | Non         | `UTC`                                   | Fuseau horaire IANA, par exemple `Asia/Shanghai` ; les valeurs non valides reviennent à UTC |
| `service_id`      | UUID            | Non         | —                                       | Filtrer par service ; prend en charge les paramètres répétés                         |
| `application_id`  | UUID            | Non         | —                                       | Filtrer par Application ; prend en charge les paramètres répétés              |
| `api_id`          | UUID            | Non         | —                                       | Filtrer par API ; prend en charge les paramètres répétés                      |
| `credential_id`   | UUID            | Non         | —                                       | Filtrer par identifiant API ; prend en charge les paramètres répétés                    |
| `include_models`  | boolean         | Non         | `false`                                 | Calculer en plus l'agrégation par dimension de modèle ; augmente le coût de la requête                 |
| `user_id`         | UUID            | Non         | Les utilisateurs ordinaires sont limités à eux-mêmes ; tous les comptes si les administrateurs ne le transmettent pas | Seuls les administrateurs peuvent spécifier n'importe quel compte                          |

`start_time` / `end_time` peuvent toujours être utilisés comme alias de compatibilité pour les anciens clients ; les nouvelles intégrations utilisent uniformément `created_at_from` / `created_at_to`. La forme date de `created_at_to` inclut ce jour civil, c'est-à-dire que minuit du jour suivant est utilisé comme limite.

## Exemples de requêtes

Interroger l'agrégation quotidienne/API du mois en cours à l'heure de Pékin, avec la dimension de modèle :

```shell
curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  --data-urlencode 'include_models=true' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Interroger l'utilisation d'une semaine pour une Application spécifiée :

```shell
export APPLICATION_ID='你的 Application ID'

curl --get 'https://platform.acedata.cloud/api/v1/usage/apis/aggregate/' \
  --data-urlencode "application_id=${APPLICATION_ID}" \
  --data-urlencode 'created_at_from=2026-09-01' \
  --data-urlencode 'created_at_to=2026-09-07' \
  --data-urlencode 'timezone=Asia/Shanghai' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Exemple Python :

```python
import os
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/usage/apis/aggregate/",
    headers={"Authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}"},
    params={
        "created_at_from": "2026-09-01",
        "created_at_to": "2026-09-07",
        "timezone": "Asia/Shanghai",
        "include_models": "true",
    },
    timeout=30,
)
response.raise_for_status()
data = response.json()
print("requests:", data["requests"], "deducted:", data["total"])
for row in data["items"]:
    print(row["date"], row["api_id"], row["amount"])
```

## Exemple de réponse

```json
{
  "items": [
    {
      "date": "2026-09-01",
      "api_id": "00000000-0000-4000-8000-000000000001",
      "amount": 12.5
    }
  ],
  "total": 12.5,
  "apis": {
    "00000000-0000-4000-8000-000000000001": {
      "title": "Example API"
    }
  },
  "requests": 42,
  "models": [
    {
      "model": "example-model",
      "amount": 12.5,
      "requests": 42
    }
  ]
}
```

## Champs de réponse

| Champ      | Description                                                           |
| ---------- | --------------------------------------------------------------------- |
| `items`    | Regroupé par date dans le fuseau horaire sélectionné et par `api_id` ; chaque ligne contient `date`, `api_id`, `amount`          |
| `total`    | Somme de `deducted_amount` dans le périmètre de la requête                                  |
| `apis`     | Mappage des ID API vers les résumés de titres, facilitant l'affichage de `items`                                 |
| `requests` | Nombre total de requêtes dans le périmètre de la requête                                                   |
| `models`   | Calculé uniquement lorsque `include_models=true` ; chaque élément contient `model`, `amount`, `requests` |

L'unité de crédit dépend de `service.unit` de l'Application associée. Si la requête inclut des services ayant des unités différentes, effectuez d'abord des statistiques séparées par `service_id` ou `application_id`, afin d'éviter les comparaisons ou additions directes.

Lorsque l'heure de fin n'est pas supérieure à l'heure de début, l'interface renvoie une structure vide complète : `items=[]`, `total=0`, `apis={}`, `requests=0`, `models=[]`.

## Erreurs et recommandations de performance

| HTTP | `error`                 | Méthode de traitement                               |
| ---- | ----------------------- | --------------------------------------------------- |
| 400  | `usage_history_expired` | Ajustez la période afin qu'elle soit postérieure à `available_from` dans la réponse     |
| 401  | `not_authenticated`     | Vérifiez l'Account Token, n'utilisez pas par erreur un Credential métier |
| 403  | `permission_denied`     | Les utilisateurs ordinaires ne peuvent pas interroger d'autres comptes                       |

- N'activez pas `include_models` par défaut ; activez-le uniquement lorsque le rapport nécessite réellement une répartition par modèle.
- Pour les requêtes à grande échelle, séparez en priorité par `service_id` ou `application_id`, afin d'éviter de mélanger les unités et de réduire le coût de la requête.
- Les dates sans appels ne sont pas automatiquement complétées avec zéro ; le client doit compléter l'axe des dates avant le traçage du graphique.
