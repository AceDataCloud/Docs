[LobeChat](https://lobehub.com/) est un client IA open source prenant en charge les plugins, les bases de connaissances et l’auto-hébergement. Il peut être utilisé en ligne ou déployé avec Docker. Il prend en charge les points de terminaison personnalisés compatibles avec OpenAI, et peut donc être connecté à Ace Data Cloud. Cet article présente le processus de configuration.

## Processus de demande

Pour connecter Ace Data Cloud dans LobeChat, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications), récupérez votre API Token et conservez-le pour plus tard.

![Obtenir une clé API Ace Data Cloud](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter. Après la connexion ou l’inscription, vous reviendrez automatiquement à la page actuelle.

Lors de la première demande, un quota gratuit est offert, permettant d’essayer gratuitement les services de modèles d’Ace Data Cloud.

## Configurer Ace Data Cloud

Accédez à **Paramètres de l’application → Modèles de langage** dans LobeChat, trouvez la carte **OpenAI** et activez-la, puis renseignez :

| Champ       | Valeur                              | Description                         |
| -------- | ------------------------------ | -------------------------- |
| Clé API  | Votre Ace Data Cloud Token        | Token copié depuis la console               |
| Adresse proxy API | `https://api.acedata.cloud/v1` | **Doit se terminer par `/v1`**           |
| Mode de requête client  | Activé                             | Connexion directe depuis le navigateur, la clé ne passe pas par le serveur LobeChat |

![Interface de configuration du fournisseur OpenAI de LobeChat](https://cdn.acedata.cloud/629ef9d3084a.png)

> Lors de l’utilisation de l’interface Chat Completions, veuillez laisser Responses API Specification désactivé.

LobeChat n’ajoute pas automatiquement `/v1` à l’URL de base ; le chemin de requête est directement `{adresse proxy API}/chat/completions` :

| Adresse proxy API                              | Requête réelle                                                   | Résultat                       |
| ------------------------------------- | ------------------------------------------------------ | ------------------------ |
| `https://api.acedata.cloud/v1`        | `https://api.acedata.cloud/v1/chat/completions`        | Correct                       |
| `https://api.acedata.cloud/openai`    | `https://api.acedata.cloud/openai/chat/completions`    | Également utilisable                      |
| `https://api.acedata.cloud/openai/v1` | `https://api.acedata.cloud/openai/v1/chat/completions` | 404 (il n’y a pas de `/v1` sous `/openai`) |
| `https://api.acedata.cloud`           | `https://api.acedata.cloud/chat/completions`           | 404 (`/v1` manquant)             |

LobeChat appelle par défaut `/v1/models` pour récupérer automatiquement les modèles. Lorsque Ace Data Cloud renvoie de nombreux modèles, l’interface peut devenir très longue ; il est recommandé de renseigner manuellement une liste d’autorisation dans « Liste des modèles → Noms de modèles personnalisés », séparée par des virgules anglaises. Pour personnaliser le nom d’affichage, vous pouvez utiliser `=`, au format `MODEL_ID=nom d’affichage`.

## Choisir un modèle

Le catalogue de modèles sera continuellement mis à jour. Utilisez en priorité la liste de modèles chargée automatiquement par le client ; lorsqu’une saisie manuelle est nécessaire, envoyez d’abord une requête à `GET https://api.acedata.cloud/v1/models` pour obtenir les ID de modèles actuels, puis choisissez selon les capacités de contexte, d’images et d’appel d’outils prises en charge par le client.

## Vérifier l’intégration

Si vous ne savez pas si le problème provient de LobeChat ou du réseau, vous pouvez d’abord utiliser curl pour vérifier directement le point de terminaison (remplacez `{token}` par votre Token) :

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

Le retour d’un objet `chat.completion` compatible avec OpenAI indique que le Token et le point de terminaison sont prêts ; si `HTTP 403 used_up` est renvoyé, cela signifie que le Token est valide mais que le solde est insuffisant. Il suffit de recharger le compte depuis la [console](https://platform.acedata.cloud/console/applications).

## Avancé : auto-hébergement avec Docker

Si vous souhaitez déployer une version privée pour votre équipe, vous pouvez utiliser une commande Docker pour la démarrer (remplacez `{token}` par votre Token) :

```bash
docker run -d \
  --name lobe-chat \
  -p 3210:3210 \
  -e OPENAI_API_KEY={token} \
  -e OPENAI_PROXY_URL=https://api.acedata.cloud/v1 \
  -e ACCESS_CODE=your-secret-password \
  -e OPENAI_MODEL_LIST="MODEL_ID" \
  lobehub/lobe-chat:latest
```

Ouvrez `http://IP_de_votre_serveur:3210`, saisissez `ACCESS_CODE` pour l’utiliser ; les membres de l’équipe n’ont pas besoin de renseigner chacun leur clé. Pour une description complète des variables d’environnement telles que `OPENAI_API_KEY`, `OPENAI_PROXY_URL` et `OPENAI_MODEL_LIST` utilisées ci-dessus, consultez la [documentation des variables d’environnement des fournisseurs de modèles de LobeChat](https://lobehub.com/docs/self-hosting/environment-variables/model-provider). Si vous utilisez un proxy inverse nginx avec HTTPS, veillez à ajouter `proxy_buffering off;`, sinon les réponses en streaming seront mises en mémoire tampon. Pour davantage de formes de déploiement, consultez le [guide de démarrage de l’auto-hébergement LobeChat](https://lobehub.com/docs/self-hosting/start) et le [déploiement avec Docker Compose](https://lobehub.com/docs/self-hosting/platform/docker-compose).

## Questions fréquentes

### Message 404 Not Found

En général, l’adresse proxy API a été définie comme `.../openai/v1` ou `/v1` a été omis. Remplacez-la par `https://api.acedata.cloud/v1`.

### La liste des modèles est vide

Activez l’interrupteur « Mode de requête client » ; ou renseignez manuellement une liste d’autorisation de modèles dans « Noms de modèles personnalisés ».

### Message 401 Unauthorized

Veuillez confirmer que la clé API contient le Token Ace Data Cloud collé (sans préfixe `Bearer`, ni espaces supplémentaires), et que le solde de l’application concernée est suffisant.
