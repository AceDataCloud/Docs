Cet article présentera une méthode d’intégration de l’API Producer Audios Generation, qui permet de générer de la musique officielle Producer en saisissant des paramètres personnalisés.

## Processus de demande

Pour utiliser l’API Producer Audios Generation, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token, à conserver pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement sur la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, il n’est pas nécessaire d’en demander un séparément pour chaque service.** Lors de la première demande, un quota gratuit sera offert pour une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger votre solde commun dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Sélectionner les paramètres requis selon l’opération

Lorsque `action=generate` et `custom=false` (par défaut), fournissez `prompt` ; lorsque `custom=true`
et `instrumental=false`, fournissez `lyric`. Pour une musique instrumentale personnalisée, vous pouvez définir
`custom=true, instrumental=true`, sans avoir besoin d’inventer des paroles ou des mots-clés supplémentaires.
`action=extend` nécessite `audio_id` et un `continue_at` supérieur à 0 ; le mode non instrumental nécessite également
`lyric`. Les reprises, variantes, remplacements de segments, échanges de parties vocales et séparations de pistes nécessitent tous l’`audio_id` source ;
les paroles et les mots-clés ne doivent pas être obligatoires sans condition pour toutes les opérations.

Dans MCP, `producer_extend_music` et `producer_replace_section` sélectionneront le mode de paroles personnalisées lorsque `lyric`
est fourni ; pour une continuation instrumentale, vous pouvez transmettre `instrumental=true` et omettre les paroles.

## Utilisation de base

Pour les chansons auxquelles vous pensez, vous pouvez saisir librement un texte, par exemple si je souhaite générer une chanson sur Noël, je peux saisir `a song for Christmas`, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Vous pouvez voir qu’ici nous avons défini les Request Headers, y compris :

- `accept` : le format de résultat de réponse que vous souhaitez recevoir ; ici, renseignez `application/json`, c’est-à-dire le format JSON.
- `authorization` : la clé pour appeler l’API, que vous pouvez sélectionner directement dans la liste déroulante après l’avoir demandée.

De plus, les paramètres du Request Body incluent :

- `action` : le comportement de cette tâche de génération musicale ; pour générer une chanson, il s’agit de `generate`.
- `model` : le modèle utilisé pour créer la chanson ; actuellement, les principaux sont : **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric` : le contenu des paroles de la chanson.
- `custom` : si la chanson est générée en utilisant une méthode personnalisée.
- `prompt` : les mots-clés en mode inspiration.
- `title` : les informations du titre de la chanson.
- `audio_id` : l’ID de la chanson de référence, utilisé pour des opérations telles que la continuation/la reprise.
- `continue_at` : continuer la chanson à partir du nombre de secondes spécifié.
- `replace_section_start`/`replace_section_end` : les heures de début et de fin du segment à remplacer, en secondes.
- `lyrics_strength` : l’intensité des paroles, indiquant le degré d’influence des paroles dans la génération audio ; peut être comprise entre 0 et 1, avec une valeur par défaut de 0.7.
- `sound_strength` : l’intensité des mots-clés audio, peut être comprise entre 0.2 et 1, avec une valeur par défaut de 0.7.
- `cover_strength` : l’intensité de la reprise, entre 0.2 et 1, avec une valeur par défaut de 1.
- `weirdness` : le degré d’originalité du style, peut être compris entre 0 et 1, avec une valeur par défaut de 0.5
- `callback_url` : l’URL qui doit recevoir le résultat de rappel.
- `async` : facultatif ; lorsqu’il est défini sur `true`, l’interface renvoie immédiatement `task_id`, sans avoir à fournir `callback_url`, puis récupère le résultat en interrogeant l’interface de requête de tâche correspondante.
- `instrumental` : s’il s’agit d’un mode sans paroles.

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Reprise de chanson

Si vous souhaitez effectuer une opération de reprise sur une chanson déjà générée, vous pouvez saisir la chanson générée ci-dessus afin d’en faire une reprise ; ensuite, nous allons générer une chanson personnalisée selon les paroles et le titre.

Si vous souhaitez continuer à faire une reprise d’une chanson que vous avez vous-même importée, vous pouvez définir le paramètre `action` sur `upload_cover`, et saisir l’ID de la chanson importée de manière personnalisée dont vous souhaitez continuer la reprise. L’obtention de l’ID de la chanson se fait à l’aide de [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), comme indiqué dans l’image ci-dessous :

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Vous pouvez alors spécifier le contenu suivant :

- action : le comportement de cette tâche de chanson ; actuellement pris en charge : generate, cover, extend, upload_cover, upload_extend, replace_section, swap_vocals, swap_instrumentals, variation ; cette reprise utilise le paramètre `cover`.
- lyric : texte des paroles
- title : le titre de la chanson.
- custom : indique s’il faut générer en mode personnalisé ; la valeur par défaut est false.
- audio_id : l’ID de la chanson à reprendre.

## Rappel asynchrone

Étant donné que le temps de génération de l’API Producer Audios Generation peut parfois être relativement long, si l’API ne répond pas pendant longtemps, la requête HTTP maintiendra continuellement la connexion, entraînant une consommation supplémentaire de ressources système. Cette API fournit donc également la prise en charge des rappels asynchrones.

Le processus global est le suivant : lorsque le client lance une requête, il spécifie en plus un champ `callback_url`. Après que le client a lancé une requête API, l’API renvoie immédiatement un résultat, contenant les informations d’un champ `task_id`, qui représente l’ID de la tâche actuelle. Une fois la tâche terminée, le résultat de la tâche de génération sera envoyé sous forme de POST JSON à l’adresse `callback_url` spécifiée par le client, incluant également le champ `task_id`, afin que le résultat de la tâche puisse être associé par ID.

Nous allons maintenant comprendre le fonctionnement concret à travers un exemple.

Tout d’abord, le rappel Webhook est un service pouvant recevoir des requêtes HTTP ; les développeurs doivent le remplacer par l’URL de leur propre serveur HTTP. Pour faciliter la démonstration, un site d’exemple Webhook public [https://webhook.site/](https://webhook.site/) est utilisé ici. Ouvrez ce site pour obtenir une URL Webhook, comme indiqué sur l’image :

![](https://cdn.acedata.cloud/tbcnai.png)

## Gestion des erreurs

Lors de l’appel de l’API, si une erreur est rencontrée, l’API renverra le code d’erreur et les informations correspondants. Par exemple :

- `400 token_mismatched` : Mauvaise requête, possiblement due à des paramètres manquants ou invalides.
- `400 api_not_implemented` : Mauvaise requête, possiblement due à des paramètres manquants ou invalides.
- `401 invalid_token` : Non autorisé, jeton d’autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, quelque chose s’est mal passé sur le serveur.

### Exemple de réponse d’erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
