Cet article présentera une méthode d’intégration de l’API Producer Audios Generation, qui permet de générer de la musique officielle Producer en saisissant des paramètres personnalisés.

## Processus de demande

Pour utiliser l’API Producer Audios Generation, obtenez d’abord votre API Token dans la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications), et conservez-le pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter, puis vous reviendrez automatiquement sur la page actuelle une fois cela terminé.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir besoin d’en demander un séparément pour chaque service.** Lors de la première demande, un quota gratuit sera offert pour permettre un essai gratuit ; lorsque le quota est insuffisant, vous pouvez recharger votre solde général dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [API Producer Audios Generation →](https://platform.acedata.cloud/documents/producer-audios)

## Utilisation de base

Pour toute chanson à laquelle vous pensez, vous pouvez saisir librement un texte, par exemple si je veux générer une chanson sur Noël, je peux saisir `a song for Christmas`, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Vous pouvez voir que nous avons défini ici les Request Headers, notamment :

- `accept`：le format de résultat de réponse que vous souhaitez recevoir, renseignez ici `application/json`, c’est-à-dire le format JSON.
- `authorization`：la clé pour appeler l’API, qui peut être directement sélectionnée dans la liste déroulante après la demande.

En outre, les paramètres du Request Body comprennent :

- `action`：l’action de cette tâche de génération musicale, la génération d’une chanson est `generate`.
- `model`：le modèle utilisé pour créer la chanson, actuellement les principaux sont : **FUZZ-2.0 Pro**、**FUZZ-2.0**、**FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**、**FUZZ-1.0 Pro**、**FUZZ-1.0**、**FUZZ-1.1**、**FUZZ-0.8**。
- `lyric`：le contenu des paroles de la chanson.
- `custom`：indique si la chanson est générée de manière personnalisée.
- `prompt`：le texte d’invite en mode inspiration.
- `title`：les informations du titre de la chanson.
- `audio_id`：l’ID de la chanson de référence, utilisé pour des opérations telles que la continuation/la reprise.
- `continue_at`：continuer l’écriture de la chanson à partir du nombre de secondes spécifié.
- `replace_section_start`/`replace_section_end`：les heures de début et de fin du segment à remplacer, en secondes.
- `lyrics_strength`：l’intensité des paroles, qui indique le degré d’influence des paroles dans la génération audio, facultatif entre 0 et 1, 0,7 par défaut.
- `sound_strength`：l’intensité du texte d’invite audio, facultative entre 0,2 et 1, 0,7 par défaut.
- `cover_strength`：l’intensité de la reprise, entre 0,2 et 1, 1 par défaut.
- `weirdness`：le degré d’étrangeté du style, facultatif entre 0 et 1, 0,5 par défaut
- `callback_url`：l’URL nécessitant un résultat de rappel.
- `async`：facultatif, lorsque défini sur `true`, l’interface renvoie immédiatement `task_id`, sans avoir besoin de fournir `callback_url`, puis le résultat est obtenu par interrogation via l’interface de requête de tâche correspondante.
- `instrumental`：indique s’il s’agit du mode sans paroles.

De plus, si vous souhaitez générer le code d’intégration correspondant, vous pouvez le copier directement. Par exemple, le code CURL est le suivant :

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Reprise de chanson

Si vous souhaitez effectuer une reprise d’une chanson déjà générée, vous pouvez saisir la chanson générée ci-dessus pour en faire une reprise ; ensuite, nous allons générer une chanson personnalisée selon les paroles et le titre.

Si vous souhaitez poursuivre la reprise d’une chanson que vous avez vous-même téléversée, vous pouvez définir le paramètre `action` sur `upload_cover`, et saisir l’ID de la chanson téléversée personnalisée dont vous souhaitez poursuivre la reprise. L’obtention de l’ID de la chanson se fait à l’aide de [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), comme indiqué dans l’image ci-dessous :

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Vous pouvez alors spécifier le contenu suivant :

- action : le comportement de cette tâche de chanson prend actuellement en charge : generate, cover, extend, upload_cover, upload_extend, replace_section, swap_vocals, swap_instrumentals, variation ; cette reprise utilise le paramètre `cover`.
- lyric : texte des paroles
- title : le titre de la chanson.
- custom : si la génération utilise le mode personnalisé, la valeur par défaut est false.
- audio_id : l’ID de la chanson à reprendre.

## Rappel asynchrone

Comme le temps de génération de l’API Producer Audios Generation peut parfois être relativement long, si l’API ne répond pas pendant une longue période, la requête HTTP maintiendra constamment la connexion, entraînant une consommation supplémentaire de ressources système. Cette API prend donc également en charge les rappels asynchrones.

Le processus global est le suivant : lorsque le client lance une requête, il spécifie en plus un champ `callback_url`. Après que le client a lancé une requête API, l’API renvoie immédiatement un résultat, contenant un champ `task_id`, qui représente l’ID de la tâche actuelle. Une fois la tâche terminée, le résultat de la tâche de génération sera envoyé sous forme de POST JSON vers le `callback_url` spécifié par le client, incluant également le champ `task_id`, afin que les résultats de la tâche puissent être associés via l’ID.

Ci-dessous, nous allons comprendre plus précisément comment procéder à travers un exemple.

Tout d’abord, le rappel Webhook est un service capable de recevoir des requêtes HTTP ; les développeurs doivent le remplacer par l’URL de leur propre serveur HTTP. Pour faciliter la démonstration, nous utilisons ici un site d’exemple Webhook public [https://webhook.site/](https://webhook.site/). Ouvrez ce site pour obtenir une URL Webhook, comme illustré ci-dessous :

![](https://cdn.acedata.cloud/tbcnai.png)

Copiez cette URL, elle peut alors être utilisée comme Webhook. L’exemple ici est [https://webhook.site/#!/view/0d73431d-f833-4be4-9276-b6e1690d55c1](https://webhook.site/#!/view/0d73431d-f833-4be4-9276-b6e1690d55c1).

## Gestion des erreurs

Lors de l'appel de l'API, en cas d'erreur, l'API renvoie le code d'erreur et les informations correspondants. Par exemple :

- `400 token_mismatched`：Requête incorrecte, probablement en raison de paramètres manquants ou non valides.
- `400 api_not_implemented`：Requête incorrecte, probablement en raison de paramètres manquants ou non valides.
- `401 invalid_token`：Non autorisé, jeton d'autorisation non valide ou manquant.
- `429 too_many_requests`：Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error`：Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d'erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
