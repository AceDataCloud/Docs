La fonction principale de l’API Producer Tasks est de consulter l’état d’exécution d’une tâche en saisissant l’ID de tâche généré par l’API Producer Audios Generation.

Ce document présentera en détail les instructions d’intégration de l’API Producer Tasks, afin de vous aider à intégrer facilement et à exploiter pleinement les puissantes fonctionnalités de cette API. Grâce à l’API Producer Tasks, vous pouvez facilement consulter l’état d’exécution des tâches de l’API Producer Audios Generation.

## Processus de demande

Pour utiliser l’API Producer Audios Generation, obtenez d’abord votre API Token dans la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) et conservez-le pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion qui vous invitera à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, il n’est pas nécessaire d’en demander un séparément pour chaque service.** Lors de la première demande, un quota gratuit vous sera offert pour une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Exemple de requête

L’API Producer Tasks peut être utilisée pour consulter les résultats de l’API Producer Audios Generation. Pour savoir comment utiliser l’API Producer Audios Generation, consultez la documentation [Producer Audios Generation API ](https://platform.acedata.cloud/documents/producer-audios-integration)。

Nous prenons comme exemple un ID de tâche renvoyé par le service API Producer Audios Generation afin de montrer comment utiliser cette API. Supposons que nous avons un ID de tâche : 1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad, nous allons ensuite montrer comment en transmettant un ID de tâche.

### Définir les en-têtes et le corps de la requête

Les **Request Headers** incluent :

- `accept` : spécifie la réception des résultats de réponse au format JSON, renseignez ici `application/json`.
- `authorization` : la clé pour appeler l’API, qui peut être directement sélectionnée dans la liste déroulante après la demande.

Les **Request Body** incluent :

- `id` : l’ID de la tâche envoyée.
- `action` : le mode d’opération sur la tâche.

La configuration est illustrée ci-dessous :

### Exemple de code

Vous pouvez constater que divers codes dans différents langages ont déjà été générés automatiquement sur le côté droit de la page, comme illustré ci-dessous :

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

Le résultat renvoyé contient plusieurs champs ; le champ request est le request body lors du lancement de la tâche, tandis que le champ response est le response body renvoyé une fois la tâche terminée. La présentation des champs est la suivante.
- `id`, l’ID de la tâche générée, utilisé pour identifier de manière unique cette tâche de génération.
- `request`, les informations de requête dans la tâche de consultation.
- `response`, les informations de retour dans la tâche de consultation.
- `created_at`, l’heure de création de la tâche, horodatage Unix (secondes, flottant).
- `started_at`, l’heure de début d’exécution de la tâche, horodatage Unix (secondes, flottant).
- `finished_at`, l’heure de fin de la tâche, horodatage Unix (secondes, flottant). Ce champ n’est pas renvoyé lorsque la tâche n’est pas terminée.
- `elapsed`, le temps d’exécution de la tâche, en secondes (flottant, conservé à 3 décimales). Ce champ n’est pas renvoyé lorsque la tâche n’est pas terminée.

## Opération de consultation par lot

Ceci permet de consulter les détails de plusieurs tâches à partir de leurs ID, la différence avec ce qui précède est qu’il faut sélectionner `retrieve_batch` pour l’action.

Le **Request Body** comprend :

- `ids` : le tableau des ID de tâches téléversés.
- `action` : le mode d’opération sur les tâches.

## Gestion des erreurs

Lors de l'appel de l'API, en cas d'erreur, l'API renvoie le code et les informations d'erreur correspondants. Par exemple :

- `400 token_mismatched`：Requête incorrecte, probablement en raison de paramètres manquants ou non valides.
- `400 api_not_implemented`：Requête incorrecte, probablement en raison de paramètres manquants ou non valides.
- `401 invalid_token`：Non autorisé, jeton d'autorisation non valide ou manquant.
- `429 too_many_requests`：Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error`：Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d'erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
