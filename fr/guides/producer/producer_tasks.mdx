La principale fonctionnalité de l'API Producer Tasks est de permettre la consultation de l'état d'exécution d'une tâche en entrant l'ID de tâche généré par l'API Producer Audios Generation.

Ce document détaillera les instructions d'intégration de l'API Producer Tasks, vous aidant à intégrer facilement et à tirer pleinement parti de la puissance de cette API. Grâce à l'API Producer Tasks, vous pouvez facilement interroger l'état d'exécution des tâches de l'API Producer Audios Generation.

## Processus de demande

Pour utiliser l'API Producer Tasks, vous devez d'abord vous rendre sur la page de demande [Producer Audios Generation API](https://platform.acedata.cloud/documents/producer-audios) pour demander le service correspondant, puis copier l'ID de tâche de l'API Producer Audios Generation, comme indiqué dans l'image ci-dessous :

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Enfin, accédez à la page de l'API Tasks [Producer Tasks API](https://platform.acedata.cloud/documents/622626b1-30a7-4799-a772-4946e1df3ac0) pour demander le service correspondant. Une fois sur la page, cliquez sur le bouton « Acquire », comme indiqué dans l'image ci-dessous :

![Page de demande](https://cdn.acedata.cloud/rci31i.png)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la [page de connexion](https://platform.acedata.cloud) vous invitant à vous inscrire et à vous connecter. Après vous être connecté ou inscrit, vous serez automatiquement renvoyé à la page actuelle.

Lors de votre première demande, un quota gratuit sera offert, vous permettant d'utiliser cette API gratuitement.

## Exemple de demande

L'API Producer Tasks peut être utilisée pour interroger les résultats de l'API Producer Audios Generation. Pour savoir comment utiliser l'API Producer Audios Generation, veuillez consulter le document [Producer Audios Generation API](https://platform.acedata.cloud/documents/producer-audios-integration).

Prenons un exemple avec un ID de tâche retourné par le service Producer Audios Generation. Supposons que nous ayons un ID de tâche : 1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad, nous allons maintenant démontrer comment passer cet ID de tâche.

### Configuration des en-têtes de demande et du corps de la demande

**Request Headers** comprend :

- `accept` : spécifie que la réponse doit être au format JSON, ici rempli avec `application/json`.
- `authorization` : la clé d'API pour appeler l'API, que vous pouvez sélectionner directement après la demande.

**Request Body** comprend :

- `id` : l'ID de la tâche téléchargée.
- `action` : la manière d'opérer sur la tâche.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

## Gestion des erreurs

Lors de l'appel de l'API, si une erreur se produit, l'API renverra le code d'erreur et les informations correspondantes. Par exemple :

- `400 token_mismatched` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `400 api_not_implemented` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `401 invalid_token` : Non autorisé, jeton d'autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de taux.
- `500 api_error` : Erreur interne du serveur, quelque chose s'est mal passé sur le serveur.

### Exemple de réponse d'erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "échec de la récupération"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
