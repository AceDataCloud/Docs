Avec l’élargissement des applications de l’IA, divers programmes d’IA se sont progressivement popularisés. L’IA s’est progressivement intégrée à tous les aspects du travail et de la vie des gens. Et les secteurs impliqués par l’IA sont également de plus en plus nombreux, de l’écriture initiale, aux soins médicaux et à l’éducation, jusqu’à la vidéo actuelle.

Luma est une plateforme professionnelle de génération de vidéos de haute qualité, les utilisateurs n’ont qu’à téléverser des ressources pour générer automatiquement des vidéos de haute qualité selon différents styles et effets. Ce générateur de vidéos par IA est développé par des membres d’équipe issus d’entreprises technologiques renommées, avec pour objectif de permettre à chacun de créer facilement d’excellentes vidéos sans outils de montage complexes.

Cependant, Luma ne fournit officiellement pas d’API, AceDataCloud fournit un ensemble d’API Luma, simulant l’intégration officielle de Suno, permettant de générer facilement et rapidement les vidéos souhaitées.

## Demande et utilisation

Pour utiliser Luma Videos Generation API, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token, à conserver en réserve.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion qui vous invitera à vous inscrire et à vous connecter, puis vous reviendrez automatiquement sur la page actuelle une fois terminé.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir à en demander un séparément pour chaque service.** La première demande offre un quota gratuit, permettant une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger le solde commun dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Luma Videos Generation API →](https://platform.acedata.cloud/documents/luma-videos)

## Utilisation de base

Pour générer n’importe quelle vidéo, vous pouvez saisir librement un texte, par exemple si je veux générer une vidéo sur des astronautes voyageant entre l’espace et un volcan, je peux saisir `Astronauts shuttle from space to volcano`, comme illustré :

Le code généré est le suivant :

<p><img src="https://cdn.acedata.cloud/ieq7yn.png" width="500" className="m-auto" /></p>

Principaux paramètres de requête :

- `prompt` : l’invite pour générer la vidéo.
- `aspect_ratio` : le rapport largeur-hauteur de la vidéo, 16:9 par défaut.
- `end_image_url` : facultatif, spécifie l’image de fin.
- `enhancement` : facultatif, interrupteur d’amélioration de la netteté.
- `loop` : indique s’il faut générer une vidéo en boucle, `false` par défaut.
- `timeout` : facultatif, nombre de secondes avant expiration.
- `callback_url` : adresse de rappel asynchrone.
- `async` : facultatif, lorsque défini sur `true`, l’interface renvoie immédiatement `task_id`, sans nécessiter de fournir `callback_url`, puis le résultat est obtenu par interrogation via l’interface de requête de tâche correspondante.

Vous pouvez cliquer sur le bouton « Try » pour tester directement l’API, attendre 1 à 2 minutes, le résultat est le suivant :

```json
  "thumbnail_width": 1360,
  "thumbnail_height": 752
}
```

Nous pouvons voir qu’à ce moment, nous avons obtenu les informations relatives à cette vidéo, y compris l’ID de la vidéo, le lien de la vidéo, la couverture de la vidéo et d’autres contenus.

Les descriptions des champs sont les suivantes :

- success : indique si la génération a réussi, vaut `true` en cas de succès, sinon `false`
- task_id : l’ID unique de la tâche de génération de vidéo ici
- video_id : l’ID unique de la vidéo produite par la tâche de génération de vidéo ici
- prompt : les mots-clés de la tâche de génération de vidéo ici
- video_url : le lien de la vidéo résultante de la tâche de génération de vidéo ici
- video_height : la hauteur de l’image de couverture vidéo générée
- video_width : la largeur de l’image de couverture vidéo générée
- state : l’état de la tâche de génération de vidéo ici, vaut `completed` si la tâche est terminée.
- thumbnail_url : le lien de l’image de couverture vidéo générée
- thumbnail_width : la largeur de l’image de couverture vidéo générée
- thumbnail_height : la hauteur de l’image de couverture vidéo générée

## Génération personnalisée avec images de début et de fin

Si vous souhaitez générer une vidéo en personnalisant les images de début et de fin de la vidéo, vous pouvez saisir les liens d’images des images de début et de fin :

À ce moment, le champ `start_image_url` de l’image de début de la vidéo peut transmettre l’image suivante comme image de début de la vidéo :

![Image de début](https://cdn.acedata.cloud/r9vsv9.png)

Ensuite, si nous voulons générer une vidéo personnalisée selon les images de début et de fin ainsi que les mots-clés, nous pouvons spécifier les contenus suivants :

- action : le comportement de la tâche de génération de vidéo, généralement la génération normale `generate` et la génération d’extension `extend`, `generate` par défaut.
- start_image_url : spécifie l’image de début de la vidéo générée.
- end_image_url : spécifie l’image de fin de la vidéo générée.
- prompt : le contenu des mots-clés pour générer la vidéo.

L’exemple de remplissage est le suivant :

<p><img src="https://cdn.acedata.cloud/zvzydx.png" width="500" className="m-auto" /></p>

Une fois le remplissage terminé, le code suivant est automatiquement généré :

<p><img src="https://cdn.acedata.cloud/tx80pu.png" width="500" className="m-auto" /></p>

Le code correspondant :

```python
import requests

url = "https://api.acedata.cloud/luma/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "start_image_url": "https://cdn.acedata.cloud/r9vsv9.png",
    "action": "generate",
    "prompt": "Astronauts shuttle from space to volcano"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Le résultat obtenu est le suivant :

## Fonction d'extension vidéo

Si vous souhaitez continuer à générer la vidéo créée, vous pouvez définir le paramètre `action` sur `extend`, puis saisir l'ID ou le lien de la vidéo à continuer de générer. L'obtention de l'ID et du lien de la vidéo se fait selon l'utilisation de base, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/fwknj4.png" width="500" className="m-auto" /></p>

À ce moment-là, vous pouvez voir que l'ID de la vidéo est :

```
"video_id": "0105c090-03a5-425a-8026-523341cd575b",
"video_url": "https://platform.cdn.acedata.cloud/luma/12a18694-fd4b-47e7-9c50-34f30862cff6.mp4"
```

> Remarque : les `video_id` et `video_url` de la vidéo ici sont l'ID et le lien de la vidéo générée. Si vous ne savez pas comment générer une vidéo, vous pouvez vous référer à l'utilisation de base ci-dessus pour générer une vidéo.

Pour continuer à générer une vidéo, vous devez téléverser le lien de la vidéo ou son ID. Ci-dessous, nous montrons comment utiliser l'ID de la vidéo pour l'étendre. Ensuite, nous devons renseigner des mots-clés pour générer une vidéo personnalisée, et nous pouvons spécifier le contenu suivant :

- action : le comportement d'extension de la vidéo à ce moment-là, qui doit ici être `extend`.
- prompt : les mots-clés de la vidéo à étendre.
- video_url : le lien de la vidéo à générer par extension.
- video_id : l'ID unique de la vidéo à générer par extension.
- end_image_url : le lien de l'image de dernière image pouvant être spécifiée pour la vidéo générée par extension, paramètre facultatif.

## Rappel asynchrone

Étant donné que le temps de génération de vidéos par Luma est relativement long, environ 1 à 2 minutes, si l'API ne répond pas pendant longtemps, la requête HTTP restera connectée, entraînant une consommation supplémentaire de ressources système. Cette API prend donc également en charge les rappels asynchrones.
Le processus global est le suivant : lorsque le client initie une requête, il spécifie en supplément un champ `callback_url`. Après que le client a initié une requête API, l’API renvoie immédiatement un résultat contenant les informations du champ `task_id`, qui représente l’ID de la tâche actuelle. Lorsque la tâche est terminée, le résultat de la génération de musique est envoyé sous forme de POST JSON au `callback_url` spécifié par le client, incluant également le champ `task_id`, de sorte que le résultat de la tâche peut être associé via l’ID.

Ci-dessous, nous allons comprendre comment procéder concrètement à travers un exemple.

Tout d’abord, le rappel Webhook est un service capable de recevoir des requêtes HTTP ; les développeurs doivent le remplacer par l’URL de leur propre serveur HTTP déployé. Afin de faciliter la démonstration ici, un site d’exemple Webhook public https://webhook.site/ est utilisé. Ouvrez ce site pour obtenir une URL Webhook, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/q78okf.png" width="500" className="m-auto" /></p>

Copiez cette URL, elle peut alors être utilisée comme Webhook ; l’exemple ici est https://webhook.site/0c87ca0e-cd74-4577-8d68-f2b80fbf8a13.

Ensuite, nous pouvons définir le champ `callback_url` sur l’URL Webhook ci-dessus, tout en renseignant `prompt`, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/n2fjvi.png" width="500" className="m-auto" /></p>

Cliquez sur Exécuter, et vous constaterez qu’un résultat est immédiatement obtenu, comme suit :

```json
{
  "task_id": "732f8282-7cf8-401c-95f2-42c33aa079a6"
}
```

Patientez un instant, nous pouvons observer le résultat de la génération de chanson sur https://webhook.site/0c87ca0e-cd74-4577-8d68-f2b80fbf8a13, comme illustré ci-dessous :
