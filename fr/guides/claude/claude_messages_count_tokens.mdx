L’API Claude Messages Count Tokens peut calculer le nombre de Tokens d’entrée d’un Message sans réellement créer de message, y compris le comptage des Tokens pour les outils, les images et les documents. Cela est très utile lorsqu’il est nécessaire d’estimer les coûts ou de vérifier si l’entrée dépasse la limite de contexte du modèle.

Ce document présente principalement le processus d’utilisation de l’API Claude Messages Count Tokens.

## Processus de demande

Pour utiliser l’API Claude Messages Count Tokens, rendez-vous d’abord dans la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token, à conserver en réserve.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter, puis vous reviendrez automatiquement sur la page actuelle une fois terminé.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir besoin d’en demander un séparément pour chaque service.** Une demande initiale offre un quota gratuit permettant une utilisation d’essai gratuite ; lorsque le quota est insuffisant, vous pouvez recharger votre solde général dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Claude Messages Count Tokens API →](https://platform.acedata.cloud/documents/claude-messages-count-tokens)

## Utilisation de base

Le chemin de requête de l’API Claude Messages Count Tokens est `/v1/messages/count_tokens`, ce qui est cohérent avec l’API officielle d’Anthropic. Nous devons fournir au minimum deux paramètres obligatoires :

- `model` : sélectionnez le modèle Claude à utiliser ; `claude-opus-5-5` peut être utilisé pour Messages Token Count, comme le dernier modèle phare `claude-fable-5-1` ; l’ancien `claude-fable-5` reste compatible et conservé.
- `messages` : tableau des messages d’entrée, chaque message contenant `role` (rôle) et `content` (contenu).

Paramètres optionnels courants :

- `system` : invite système, qui sera incluse dans le nombre de Tokens.
- `tools` : définitions d’outils, qui seront incluses dans le nombre de Tokens.
- `thinking` : configuration de réflexion étendue.
- `tool_choice` : configuration de sélection d’outil.
- `cache_control` : configuration de contrôle du cache de niveau supérieur ou au niveau des blocs de contenu.

Les blocs de contenu `messages`, `system`, la relecture d’appels d’outils, les images URL et les documents/PDF utilisent la même structure de requête stable que l’API Messages.

### Exemple cURL

```bash
curl -X POST 'https://api.acedata.cloud/v1/messages/count_tokens' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "claude-fable-5-1",
    "messages": [
      {
        "role": "user",
        "content": "Hello, Claude"
      }
    ]
  }'
```

### Exemple Python

```python
import httpx

url = "https://api.acedata.cloud/v1/messages/count_tokens"
headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}
payload = {
    "model": "claude-fable-5-1",
    "messages": [
        {
            "role": "user",
            "content": "Hello, Claude"
        }
    ],
}
response = httpx.post(url, headers=headers, json=payload)
print(response.json())
```

Exemple de résultat retourné :

```json
{
  "input_tokens": 11
}
```

### Utiliser le SDK Anthropic

L’API Claude Messages Count Tokens accepte la structure de requête stable du SDK Anthropic et peut être appelée via la bibliothèque `anthropic`. L’interface utilise la capacité native Count Tokens correspondant au modèle sélectionné pour compter l’entrée, et peut être utilisée pour vérifier la taille de l’entrée avant d’envoyer une requête Messages.

```python
from anthropic import Anthropic

client = Anthropic(
    api_key="{token}",
    base_url="https://api.acedata.cloud",
)

result = client.messages.count_tokens(
    model="claude-opus-4-8",
    messages=[
        {
            "role": "user",
            "content": "Hello, Claude"
        }
    ],
)
print(result.input_tokens)
```

## Comptage des Tokens incluant des outils

Si votre requête contient des définitions d’outils, ces outils seront également inclus dans le nombre de Tokens :

```python
result = client.messages.count_tokens(
    model="claude-opus-4-8",
    messages=[
        {
            "role": "user",
            "content": "What is the weather in San Francisco?"
        }
    ],
    tools=[
        {
            "name": "get_weather",
            "description": "Get the current weather in a given location",
            "input_schema": {
                "type": "object",
                "properties": {
                    "location": {
                        "type": "string",
                        "description": "The city and state, e.g. San Francisco, CA"
                    }
                },
                "required": ["location"]
            }
        }
    ],
)
print(result.input_tokens)
```

## Comptage des Tokens incluant une invite système

L’invite système sera également incluse dans le nombre de Tokens :

```python
result = client.messages.count_tokens(
    model="claude-opus-4-8",
    system="You are a helpful assistant that speaks Chinese.",
    messages=[
        {
            "role": "user",
            "content": "Hello"
        }
    ],
)
print(result.input_tokens)
```

## Remarques

- Cette API calcule uniquement le nombre de Tokens d’entrée et ne produit aucune sortie de modèle.
- Le résultat du comptage des Tokens peut être utilisé pour estimer la taille de l’entrée et vérifier la fenêtre de contexte ; la facturation finale est basée sur `usage` dans la réponse Messages réelle.
- Les images, les PDF, les définitions d’outils, les invites système et la configuration thinking seront inclus dans le résultat conformément aux règles d’entrée du modèle sélectionné.
- Cette API est entièrement gratuite et ne consomme aucun quota.
