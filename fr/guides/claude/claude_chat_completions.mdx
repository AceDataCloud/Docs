Anthropic Claude est un système de conversation IA très puissant qui peut générer des réponses fluides et naturelles en quelques secondes seulement en saisissant des prompts. Claude se distingue dans le secteur par ses excellentes capacités de compréhension et de génération du langage. Aujourd’hui, Claude est déjà largement utilisé dans divers secteurs et domaines, et son influence devient de plus en plus significative. Qu’il s’agisse de conversations quotidiennes, d’écriture créative, de consultations professionnelles ou de programmation de code, Claude peut fournir une assistance intelligente étonnante, améliorant considérablement l’efficacité au travail et la créativité des humains.

Ce document présente principalement le processus d’utilisation des opérations de l’API Claude Chat Completion. Grâce à elle, nous pouvons facilement utiliser la fonction de conversation officielle de Claude.

## Processus de demande

Pour utiliser l’API Claude Chat Completion, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token et le conserver pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter. Une fois terminé, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, il n’est pas nécessaire d’en demander un séparément pour chaque service.** Une demande initiale offre un quota gratuit, permettant une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger le solde universel dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Utilisation de base

Vous pouvez ensuite remplir le contenu correspondant dans l’interface, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Lors de la première utilisation de cette interface, nous devons au minimum renseigner trois éléments. Le premier est `authorization`, qu’il suffit de sélectionner directement dans la liste déroulante. Un autre paramètre est `model`, avec des modèles publics disponibles tels que `claude-opus-5-5`, `claude-fable-5-1`, etc. ; l’ancien `claude-fable-5` peut toujours être appelé. Le dernier paramètre est `messages`, qui est un tableau de prompts, chaque élément contenant `role` et `content` ; `role` prend en charge `user`, `assistant`, `system`, et `content` correspond au contenu spécifique. Si vous avez besoin des blocs complets de réflexion Claude, des signatures et de la sémantique native des outils, veuillez continuer à utiliser l’API Messages.

En même temps, vous pouvez remarquer que le code d’appel correspondant est généré à droite. Vous pouvez copier le code pour l’exécuter directement, ou cliquer directement sur le bouton « Try » pour tester.

Paramètres optionnels courants :

- `max_tokens` : limite le nombre maximal de tokens pour une seule réponse.
- `temperature` : aléa de génération, entre 0 et 2, plus la valeur est élevée, plus la réponse est divergente.
- `n` : nombre de réponses candidates générées à la fois.
- `response_format` : réglage du format de retour.

`claude-opus-5-5` prend en charge les Chat Completions normaux et en streaming ; ce modèle autorise uniquement `n=1`. Ne définissez pas pour lui une `temperature` inférieure à 1 ou un `top_p` non par défaut ; pour les appels d’outils, utilisez `tool_choice: "auto"`, ne forcez pas la spécification d’un outil. L’interface compatible Chat ne renvoie pas les blocs natifs de contenu de réflexion.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Après l’appel, nous constatons que le résultat retourné est le suivant :


Le résultat retourné comporte plusieurs champs, présentés comme suit :

- `id`, l’ID de la tâche de conversation générée cette fois-ci, utilisé pour identifier de manière unique cette tâche de conversation.
- `model `, le modèle Claude officiel sélectionné.
- `choices`, les informations de réponse fournies par Claude pour le prompt.
- `usage ` : les informations statistiques sur les tokens pour cette session de questions-réponses.

Dans le format Chat Completions, `usage.prompt_tokens` correspond au volume total d’entrée ; `prompt_tokens_details.cached_tokens` et `prompt_tokens_details.cache_write_tokens` enregistrent respectivement les détails de lecture et d’écriture du cache. `completion_tokens_details.reasoning_tokens` est un sous-ensemble de `completion_tokens`, ne l’ajoutez pas une nouvelle fois lors du calcul du total ou du coût. Les réponses non streaming peuvent également renvoyer un objet `usage.cost`, où `amount` correspond à la consommation réelle de quota, `currency` est l’unité de mesure, et `list_amount` est le montant avant réduction (le cas échéant).

Le nom de champ de Chat-compatible est `reasoning_tokens` ; l’API Messages native utilise `output_tokens_details.thinking_tokens`. Les wire schemas des deux protocoles sont différents, les clients ne doivent pas mélanger les noms de champs.

Parmi eux, `choices` contient les informations de réponse de Claude ; les `choices` qu’il contient sont les informations spécifiques de la réponse de Claude, comme illustré ci-dessous.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Vous pouvez voir que le champ `content` dans `choices` contient le contenu spécifique de la réponse de Claude.

## Réponse en streaming

Cette interface prend également en charge les réponses en streaming, ce qui est très utile pour l’intégration web et permet à une page web d’obtenir un effet d’affichage mot par mot.

Si vous souhaitez renvoyer des réponses en streaming, vous pouvez modifier le paramètre `stream ` dans l’en-tête de la requête en le définissant sur `true`.

La modification est illustrée ci-dessous, mais le code d’appel doit être modifié en conséquence pour prendre en charge les réponses en streaming.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

Après avoir modifié `stream` en `true`, l’API renverra les données JSON correspondantes ligne par ligne. Au niveau du code, nous devons effectuer les modifications correspondantes pour obtenir les résultats ligne par ligne.

Exemple de code d’appel Python :

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```


## Conversation à plusieurs tours

## Réflexion approfondie
Les modèles Claude de nouvelle génération peuvent effectuer un raisonnement selon la stratégie par défaut du modèle, sans nécessiter d’être déclenchés via le suffixe de modèle `-thinking`. Les réponses compatibles avec Chat utilisent le champ usage compatible avec OpenAI `completion_tokens_details.reasoning_tokens`. Les `reasoning_tokens` sont déjà inclus dans `completion_tokens`, ne les additionnez pas deux fois. Le raisonnement et le corps visible partagent la limite de tokens de sortie, par conséquent lorsque `max_tokens` est faible, le corps peut être vide ou tronqué ; dans ce cas, veuillez augmenter le budget de sortie, ou sélectionner un effort de raisonnement plus faible lorsque le modèle utilisé le prend en charge.

Si vous avez besoin de `thinking` natif, de `output_config.effort`, de blocs de contenu thinking et du renvoi de signature, veuillez utiliser `/v1/messages`. Le champ usage correspondant à Messages est `output_tokens_details.thinking_tokens`, ne le mélangez pas avec `completion_tokens_details.reasoning_tokens` de Chat-compatible.

## Modèle visuel

claude-sonnet-4-20250514 est un grand modèle de langage multimodal développé par Claude, il ajoute des capacités de compréhension visuelle sur la base de claude-4. Ce modèle peut traiter simultanément des entrées textuelles et des images, réalisant ainsi une compréhension et une génération intermodales.

Le traitement de texte utilisant le modèle claude-sonnet-4-20250514 est cohérent avec le contenu d’utilisation de base présenté ci-dessus, nous allons maintenant présenter brièvement comment utiliser les capacités de traitement d’images du modèle.

Les capacités de traitement d’images du modèle claude-sonnet-4-20250514 s’utilisent principalement en ajoutant un champ `type` au contenu `content` existant ; ce champ permet de savoir si le contenu téléversé est du texte ou une image, afin d’utiliser les capacités de traitement d’images du modèle claude-sonnet-4-20250514. Nous allons principalement expliquer ci-dessous comment appeler cette fonctionnalité à l’aide de Curl et Python.

- Méthode par script Curl

```

-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "claude-sonnet-4-20250514",

      {
        "role": "user",
        "content": [
          {
            "type": "text",

  }'
```

## Gestion des erreurs

Lors de l’appel de l’API, si une erreur survient, l’API renverra le code d’erreur et les informations correspondants. Par exemple :

- `400 token_mismatched`：Requête incorrecte, possiblement en raison de paramètres manquants ou non valides.
- `400 api_not_implemented`：Requête incorrecte, possiblement en raison de paramètres manquants ou non valides.
- `401 invalid_token`：Non autorisé, jeton d’autorisation non valide ou manquant.
- `429 too_many_requests`：Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error`：Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d’erreur

```
{
  "success": false,

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
