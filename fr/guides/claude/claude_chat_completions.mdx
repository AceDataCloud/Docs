Anthropic Claude est un système de dialogue IA très puissant qui, à partir d'une simple saisie d'invite, peut générer des réponses fluides et naturelles en quelques secondes. Claude se distingue dans le secteur par ses excellentes capacités de compréhension et de génération du langage. Aujourd'hui, Claude est déjà largement utilisé dans divers secteurs et domaines, et son influence devient de plus en plus significative. Qu'il s'agisse de conversations quotidiennes, d'écriture créative, de conseil professionnel ou de programmation de code, Claude peut fournir une assistance intelligente impressionnante, améliorant considérablement l'efficacité du travail et la créativité humaines.

Ce document présente principalement le processus d'utilisation des opérations de l'API Claude Chat Completion, qui nous permet d'utiliser facilement la fonctionnalité de dialogue officielle de Claude.

## Processus de demande

Pour utiliser l'API Claude Chat Completion, commencez par obtenir votre API Token dans la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications), et conservez-le pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement sur la page actuelle.

**Un seul API Token permet d'appeler tous les services de la plateforme, sans avoir besoin d'en demander un séparément pour chaque service.** Lors de la première demande, un quota gratuit est offert pour une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Utilisation de base

Ensuite, vous pouvez renseigner le contenu correspondant dans l'interface, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Lors de la première utilisation de cette interface, nous devons remplir au moins trois éléments. Le premier est `authorization`, qu'il suffit de sélectionner directement dans la liste déroulante. Un autre paramètre est `model`, pour lequel il est recommandé d'utiliser le dernier modèle phare `claude-fable-5-1` ; l'ancien `claude-fable-5` peut toujours continuer à être appelé. Le dernier paramètre est `messages`, qui est un tableau d'invites ; chaque élément contient `role` et `content` ; `role` prend en charge `user`, `assistant`, `system`, et `content` est le contenu spécifique. Claude Fable 5.1 prend en charge un contexte de 1 million de Token et une sortie maximale de 128K Token.

En même temps, vous pouvez remarquer à droite la génération du code d'appel correspondant ; vous pouvez copier le code et l'exécuter directement, ou cliquer directement sur le bouton « Try » pour effectuer un test.

Paramètres optionnels courants :

- `max_tokens` : limite le nombre maximal de token pour une seule réponse.
- `temperature` : caractère aléatoire de la génération, entre 0 et 2 ; plus la valeur est élevée, plus le résultat est divergent.
- `n` : nombre de réponses candidates générées à la fois.
- `response_format` : paramètre du format de retour.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Le résultat retourné comporte plusieurs champs, présentés comme suit :

- `id`, l'ID généré pour cette tâche de dialogue, utilisé pour identifier de manière unique cette tâche de dialogue.
- `model `, le modèle Claude officiel sélectionné.
- `choices`, les informations de réponse fournies par Claude pour l'invite.
- `usage ` : les informations statistiques sur les token pour cette session de questions-réponses.

Dans le format Chat Completions, `usage.prompt_tokens` est le volume total d'entrée ; `prompt_tokens_details.cached_tokens` et `prompt_tokens_details.cache_write_tokens` enregistrent respectivement les détails de lecture et d'écriture du cache. `completion_tokens_details.reasoning_tokens` est un sous-ensemble de `completion_tokens` ; ne les additionnez pas à nouveau lors du calcul du total ou des frais. Les réponses non streamées peuvent également renvoyer un objet `usage.cost`, dans lequel `amount` est la consommation réelle de quota, `currency` est l'unité de mesure, et `list_amount` est le montant avant remise (le cas échéant).

Le nom de champ compatible avec Chat est `reasoning_tokens` ; l'API Messages native utilise `output_tokens_details.thinking_tokens`. Le wire schema des deux protocoles est différent, les clients ne doivent pas mélanger les noms de champs.

Parmi eux, `choices` contient les informations de réponse de Claude, et les `choices` qu'il contient sont les informations spécifiques de la réponse de Claude, comme le montre l'illustration.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Nous pouvons voir que le champ `content` dans `choices` contient le contenu spécifique de la réponse de Claude.

## Réponse en streaming

Cette interface prend également en charge les réponses en streaming, ce qui est très utile pour l'intégration web et permet à la page web de réaliser un effet d'affichage mot par mot.

Si vous souhaitez renvoyer une réponse en streaming, vous pouvez modifier le paramètre `stream ` dans l'en-tête de requête, en le définissant sur `true`.

La modification est illustrée ci-dessous, mais le code d'appel doit être modifié en conséquence pour prendre en charge les réponses en streaming.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

Après avoir modifié `stream` en `true`, l'API renverra les données JSON correspondantes ligne par ligne ; au niveau du code, nous devons effectuer les modifications correspondantes afin d'obtenir les résultats ligne par ligne.

Exemple de code d'appel Python :

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

JavaScript est également pris en charge, par exemple, le code d’appel en streaming pour Node.js est le suivant :

```javascript
const options = {
  method: "post",

  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Réflexion approfondie
Les modèles Claude de nouvelle génération peuvent effectuer un raisonnement selon la stratégie par défaut du modèle, sans nécessiter d’être déclenchés via le suffixe de modèle `-thinking`. Les réponses compatibles avec Chat utilisent le champ usage compatible OpenAI `completion_tokens_details.reasoning_tokens`. Les `reasoning_tokens` sont déjà inclus dans les `completion_tokens`, ne les additionnez pas une seconde fois. Le raisonnement et le corps visible partagent la limite supérieure des tokens de sortie, donc lorsque `max_tokens` est faible, le corps peut être vide ou tronqué ; dans ce cas, veuillez augmenter le budget de sortie, ou sélectionner un effort de raisonnement plus faible lorsque le modèle utilisé le prend en charge.

Si vous avez besoin de `thinking` natif, de `output_config.effort`, de blocs de contenu thinking et du renvoi de signature, veuillez utiliser `/v1/messages`. Le champ usage correspondant à Messages est `output_tokens_details.thinking_tokens`, ne le mélangez pas avec le `completion_tokens_details.reasoning_tokens` de Chat-compatible.

## Modèles visuels

claude-sonnet-4-20250514 est un grand modèle de langage multimodal développé par Claude, il ajoute des capacités de compréhension visuelle sur la base de claude-4. Ce modèle peut traiter simultanément des entrées textuelles et des images, réalisant une compréhension et une génération multimodales.

Le traitement de texte utilisant le modèle claude-sonnet-4-20250514 est cohérent avec le contenu d’utilisation de base ci-dessus, nous allons brièvement présenter ci-dessous comment utiliser les capacités de traitement d’images du modèle.

## Gestion des erreurs

Lors de l’appel de l’API, si vous rencontrez une erreur, l’API renverra le code d’erreur et les informations correspondants. Par exemple :

- `400 token_mismatched` : Mauvaise requête, probablement en raison de paramètres manquants ou non valides.
- `400 api_not_implemented` : Mauvaise requête, probablement en raison de paramètres manquants ou non valides.
- `401 invalid_token` : Non autorisé, jeton d’autorisation non valide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, quelque chose s’est mal passé sur le serveur.

### Exemple de réponse d’erreur

```
{
  "success": false,
  "error": {

  },

}
```
