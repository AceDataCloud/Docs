Anthropic Claude est un système de conversation IA très puissant qui peut générer des réponses fluides et naturelles en quelques secondes seulement en saisissant une invite. Claude se distingue dans le secteur par ses excellentes capacités de compréhension et de génération du langage. Aujourd’hui, Claude est déjà largement utilisé dans divers secteurs et domaines, et son influence devient de plus en plus significative. Qu’il s’agisse de conversations quotidiennes, d’écriture créative, ou encore de consultations professionnelles et de programmation de code, Claude peut fournir une assistance intelligente étonnante, améliorant considérablement l’efficacité au travail et la créativité des humains.

Ce document présente principalement le processus d’utilisation des opérations de l’API Claude Chat Completion. Grâce à elle, nous pouvons facilement utiliser la fonction de conversation officielle de Claude.

## Claude Fable 5.2

Utilisez le modèle complet `claude-fable-5-2`. Ce modèle convient au raisonnement complexe et aux tâches de longue durée ; lorsqu’un bloc de contenu de réflexion natif et des interactions avec des outils sont nécessaires, utilisez en priorité Messages. La réflexion adaptative reste activée en continu, omettez `temperature`, `top_p`, `top_k`, utilisez `auto` pour la sélection d’outils, ne forcez pas la spécification d’un outil. `max_tokens` couvre à la fois la réflexion et le texte final. Actuellement, les interfaces Responses et Count Tokens ne sont pas fournies pour ce modèle.

Selon le forfait maximal actuel (142,800 Credits／$13,584), le coût d’entrée standard de Fable 5.2 est de $3.20 et la sortie de $16／million de tokens ; la lecture du cache est de $0.08, et l’écriture du cache de 5 minutes／1 heure est respectivement de $4／$6.40／million de tokens. Les prix ci-dessus correspondent à 40 % du tarif API standard officiel (60 % moins cher) ; pour les autres forfaits et les réductions supplémentaires du compte, veuillez vous référer à la page de tarification des modèles et à la facturation.

## Processus de demande

Pour utiliser l’API Claude Chat Completion, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token et le conserver en réserve.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir besoin d’en demander un séparément pour chaque service.** Une demande initiale offre un quota gratuit, permettant une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger le solde universel dans la [console](https://platform.acedata.cloud/console/coin).

## Utilisation de base

Vous pouvez ensuite remplir le contenu correspondant dans l’interface, comme indiqué sur l’image :

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Lors de la première utilisation de cette interface, nous devons remplir au moins trois éléments. Le premier est `authorization`, que vous pouvez sélectionner directement dans la liste déroulante. Un autre paramètre est `model`, avec des modèles publics disponibles tels que `claude-opus-5-5`, `claude-fable-5-1`, etc. ; l’ancien `claude-fable-5` peut toujours être appelé. Le dernier paramètre est `messages`, qui est un tableau d’invites, chaque élément contenant `role` et `content` ; `role` prend en charge `user`, `assistant`, `system`, et `content` est le contenu spécifique. Si vous avez besoin de blocs de réflexion Claude complets, de signatures et d’une sémantique d’outils native, veuillez toujours utiliser l’API Messages.

En même temps, vous pouvez remarquer que le code d’appel correspondant est généré à droite ; vous pouvez copier le code pour l’exécuter directement, ou cliquer directement sur le bouton « Try » pour tester.

Paramètres optionnels courants :

- `max_tokens` : limite le nombre maximal de tokens d’une réponse unique.
- `temperature` : caractère aléatoire de la génération, entre 0 et 2 ; plus la valeur est élevée, plus le résultat est divergent.
- `n` : combien de réponses candidates générer à la fois.
- `response_format` : réglage du format de retour.

`claude-opus-5-5` prend en charge les Chat Completions standard et en streaming ; ce modèle autorise uniquement `n=1`. Ne lui définissez pas une `temperature` inférieure à 1 ou un `top_p` non par défaut ; pour les appels d’outils, utilisez `tool_choice: "auto"`, ne forcez pas la spécification d’un outil. L’interface compatible Chat ne renverra pas les blocs de contenu de réflexion natifs.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Après l’appel, nous constatons que le résultat retourné est le suivant :

Le résultat retourné comporte plusieurs champs, présentés comme suit :

- `id`, l’ID généré pour cette tâche de conversation, utilisé pour identifier de manière unique cette tâche de conversation.
- `model `, le modèle Claude officiel sélectionné.
- `choices`, les informations de réponse fournies par Claude à l’invite.
- `usage ` : les informations statistiques sur les tokens pour cette session de questions-réponses.

Dans le format Chat Completions, `usage.prompt_tokens` correspond au volume total d’entrée ; `prompt_tokens_details.cached_tokens` et `prompt_tokens_details.cache_write_tokens` enregistrent respectivement les détails de lecture et d’écriture du cache. `completion_tokens_details.reasoning_tokens` est un sous-ensemble de `completion_tokens`, ne l’ajoutez pas à nouveau lors du calcul du total ou du coût. Les réponses non en streaming peuvent également renvoyer l’objet `usage.cost`, où `amount` est la consommation réelle de quota, `currency` est l’unité de mesure, et `list_amount` est le montant avant réduction (le cas échéant).

Le nom de champ compatible Chat est `reasoning_tokens` ; l’API Messages native utilise `output_tokens_details.thinking_tokens`. Les wire schemas des deux protocoles sont différents, les clients ne doivent pas mélanger les noms de champs.

Parmi eux, `choices` contient les informations de réponse de Claude ; les `choices` qu’il contient sont les informations spécifiques de la réponse de Claude, comme indiqué sur l’image.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Vous pouvez voir que le champ `content` dans `choices` contient le contenu spécifique de la réponse de Claude.

## Réponse en streaming

Cette interface prend également en charge les réponses en streaming, ce qui est très utile pour l’intégration web et permet à une page web de réaliser un effet d’affichage mot par mot.

Si vous souhaitez renvoyer une réponse en streaming, vous pouvez modifier le paramètre `stream ` dans l’en-tête de requête, en le définissant sur `true`.

La modification est indiquée sur l’image, mais le code d’appel doit être modifié en conséquence pour prendre en charge les réponses en streaming.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>
Après avoir modifié `stream` en `true`, l’API renverra les données JSON correspondantes ligne par ligne. Au niveau du code, nous devons effectuer les modifications correspondantes afin d’obtenir les résultats ligne par ligne.

Code d’appel d’exemple Python :

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Réflexion approfondie

Les modèles Claude de nouvelle génération peuvent effectuer un raisonnement selon la stratégie par défaut du modèle, sans nécessiter d'être déclenchés via le suffixe de modèle `-thinking`. Les réponses compatibles avec Chat utilisent le champ usage compatible avec OpenAI `completion_tokens_details.reasoning_tokens`. Les `reasoning_tokens` sont déjà inclus dans `completion_tokens`, ne les additionnez pas deux fois. Le raisonnement et le corps de texte visible partagent la limite de tokens de sortie, donc lorsque `max_tokens` est faible, le corps de texte peut être vide ou tronqué ; dans ce cas, augmentez le budget de sortie, ou choisissez un effort de raisonnement plus faible lorsque le modèle utilisé le prend en charge.

Si vous avez besoin de `thinking` natif, de `output_config.effort`, de blocs de contenu thinking et du renvoi de signature, veuillez utiliser `/v1/messages`. Le champ usage correspondant à Messages est `output_tokens_details.thinking_tokens`, ne le mélangez pas avec le `completion_tokens_details.reasoning_tokens` compatible avec Chat.

## Modèle visuel

claude-sonnet-4-20250514 est un grand modèle de langage multimodal développé par Claude. Il ajoute des capacités de compréhension visuelle sur la base de claude-4. Ce modèle peut traiter simultanément des entrées textuelles et des images, réalisant ainsi une compréhension et une génération multimodales.

Le traitement de texte utilisant le modèle claude-sonnet-4-20250514 est cohérent avec le contenu de l'utilisation de base ci-dessus. Nous allons maintenant présenter brièvement comment utiliser les capacités de traitement d'images du modèle.

L'utilisation des capacités de traitement d'images du modèle claude-sonnet-4-20250514 consiste principalement à ajouter un champ `type` au contenu `content` existant. Ce champ permet de savoir si le contenu envoyé est du texte ou une image, afin d'utiliser les capacités de traitement d'images du modèle claude-sonnet-4-20250514. Nous allons principalement expliquer ci-dessous comment appeler cette fonctionnalité à l'aide de Curl et Python.

## Gestion des erreurs

Lors de l'appel de l'API, si une erreur se produit, l'API renvoie le code et les informations d'erreur correspondants. Par exemple :

- `400 token_mismatched` : Mauvaise requête, probablement en raison de paramètres manquants ou non valides.
- `400 api_not_implemented` : Mauvaise requête, probablement en raison de paramètres manquants ou non valides.
- `401 invalid_token` : Non autorisé, jeton d'autorisation non valide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d'erreur

```
{
  "success": false,

    "message": "fetch failed"
  },

}
```
