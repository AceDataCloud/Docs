---
title: "Consulter les tâches de modèle Tripo"
description: "Tripo 3D API guide - Ace Data Cloud"
---

Appelez `POST /tripo/tasks` avec un jeton AceDataCloud. La consultation est gratuite ; utilisez le même compte que pour la génération. Pour une tâche unique, utilisez `id` ou `trace_id` ; `action` vaut `retrieve` par défaut.

```bash
curl -X POST https://api.acedata.cloud/tripo/tasks \
  -H "Authorization: Bearer ${ACEDATACLOUD_API_TOKEN}" \
  -H "Content-Type: application/json" \
  -d "{\"action\":\"retrieve\",\"id\":\"${TASK_ID}\"}"
```

Le résultat d’une consultation individuelle est un enregistrement de tâche contenant `id`, `type`, `trace_id`, la requête d’origine `request`, `started_at` et `progress`. Pendant le traitement, vous pouvez poursuivre les consultations à quelques secondes d’intervalle. Une fois la tâche terminée, vérifiez `response.success` ; en cas de succès, `response.data[0].model_url` est l’adresse de téléchargement ; en cas d’échec, `response.error` contient le code et le message d’erreur. Les horodatages, `finished_at` et la durée `elapsed` se trouvent au premier niveau de l’enregistrement de tâche, en secondes. En cas de `submission_unknown`, conservez l’ID de tâche d’origine pour vérification.

Pour une consultation par lot, utilisez `{"action":"retrieve_batch","ids":["<ID de tâche 1>","<ID de tâche 2>"]}` ; vous pouvez également utiliser `trace_ids` ; chaque lot contient au maximum 100 éléments. La réponse est `{"items":[...],"count":2}` et conserve l’ordre et les doublons de l’entrée. Pour une tâche introuvable ou dont la lecture n’est pas autorisée, la consultation individuelle renvoie `{}` et la position correspondante dans la consultation par lot contient `null`.

Le `type` de l’enregistrement de tâche est `generations`, `models` ou `animations`. Pour la vérification du squelette, lisez `response.data[0].riggable` ; pour les opérations sur les fichiers, lisez `response.data[0].model_url`.
