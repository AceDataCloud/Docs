Cet article présente la méthode d'intégration de l'API HappyHorse Videos. Cette interface prend en charge la génération de vidéos à partir de texte, de la première image, d'images de référence et de l'édition vidéo via un point d'entrée unifié `/happyhorse/videos` et le paramètre `action`.

## Processus de demande

Pour utiliser l'API HappyHorse Videos, commencez par obtenir votre token API sur le [tableau de bord Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour le garder en réserve.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion qui vous invite à vous inscrire et à vous connecter, après quoi vous serez automatiquement renvoyé à la page actuelle.

**Un seul token API suffit pour appeler tous les services de la plateforme, sans avoir besoin de demander un pour chaque service.** La première demande vous donnera un quota gratuit pour une expérience sans frais ; lorsque le quota est insuffisant, vous pouvez recharger le solde général sur le [tableau de bord](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [HappyHorse Videos API →](https://platform.acedata.cloud/documents/happyhorse-videos)

## Types d'opérations

`action` détermine le mode de génération de cette demande :

- `generate` : vidéo générée à partir de texte, action par défaut, prend en charge `happyhorse-1.0-t2v` et `happyhorse-1.1-t2v`, `prompt` doit être fourni.
- `image_to_video` : vidéo générée à partir de la première image, prend en charge `happyhorse-1.0-i2v` et `happyhorse-1.1-i2v`, `image_url` doit être fourni.
- `reference_to_video` : vidéo générée à partir d'images de référence, prend en charge `happyhorse-1.0-r2v` et `happyhorse-1.1-r2v`, `prompt` et 1 à 9 `image_urls` doivent être fournis.
- `video_edit` : édition vidéo, prend en charge `happyhorse-1.0-video-edit`, `prompt` et `video_url` doivent être fournis, et 0 à 5 images de référence `image_urls` peuvent être ajoutées.

Chaque action utilise par défaut le modèle 1.1 ; `video_edit` n'a actuellement que `happyhorse-1.0-video-edit`.

## Utilisation de base

Pour générer une vidéo à partir de texte, il suffit de fournir `prompt`, vous pouvez également spécifier des paramètres tels que `resolution`, `ratio`, `duration` :

```json
{
  "action": "generate",
  "model": "happyhorse-1.1-t2v",
  "prompt": "Un cheval blanc cinématographique lève la tête, la crinière se déplace doucement dans le vent du lever du soleil, lent mouvement de caméra, éclairage de film chaleureux",
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}
```

Exemple de résultat retourné :

```json
{
  "success": true,
  "task_id": "27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1",
  "trace_id": "6071ab5e-2f37-46f0-9e07-f1e378112e69",
  "data": [
    {
      "id": "9650580f-6d9e-4bc1-823a-29011790c5cb",
      "video_url": "https://platform2.cdn.acedata.cloud/happyhorse/27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1.mp4",
      "state": "succeeded",
      "duration": 5,
      "resolution": "720P",
      "ratio": null
    }
  ]
}
```

Description des champs :

- `success` : indique si la demande a réussi.
- `task_id` : ID de tâche côté Ace Data Cloud, utilisé pour vérifier l'état de la tâche.
- `trace_id` : ID de suivi de cette demande, utilisé pour résoudre les problèmes.
- `data` : liste des résultats vidéo.
  - `id` : ID de tâche côté HappyHorse.
  - `video_url` : adresse du lien CDN de la vidéo générée.
  - `state` : état de la tâche, options `pending` / `succeeded` / `error`.
  - `duration` : durée de la vidéo facturée, en secondes ; pour `video_edit`, c'est la somme des durées des vidéos d'entrée et de sortie.
  - `resolution` : résolution de sortie.
  - `ratio` : rapport largeur/hauteur de sortie.

Le code CURL correspondant est le suivant :

```shell
curl -X POST 'https://api.acedata.cloud/happyhorse/videos' \
-H 'authorization: Bearer ${bearer_token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "happyhorse-1.1-t2v",
  "prompt": "Un cheval blanc cinématographique lève la tête, la crinière se déplace doucement dans le vent du lever du soleil, lent mouvement de caméra, éclairage de film chaleureux",
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}'
```

Le code Python correspondant est le suivant :

```python
import requests

url = "https://api.acedata.cloud/happyhorse/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "action": "generate",
    "model": "happyhorse-1.1-t2v",
    "prompt": "Un cheval blanc cinématographique lève la tête, la crinière se déplace doucement dans le vent du lever du soleil, lent mouvement de caméra, éclairage de film chaleureux",
    "resolution": "720P",
    "ratio": "16:9",
    "duration": 5,
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Vidéo générée à partir de la première image

Lors de l'utilisation de `image_to_video`, `image_url` sera utilisé comme première image de la vidéo. Le rapport largeur/hauteur de sortie suivra autant que possible l'image de la première image, donc cette action n'a pas besoin de transmettre `ratio`.

```json
{
  "action": "image_to_video",
  "model": "happyhorse-1.1-i2v",
  "image_url": "https://cdn.acedata.cloud/b1c82e4937.png",
  "prompt": "Un cheval blanc cinématographique lève la tête, la crinière se déplace doucement dans le vent du lever du soleil, lent mouvement de caméra, éclairage de film chaleureux",
  "resolution": "1080P",
  "duration": 5
}
```

## Vidéo générée à partir d'images de référence

Lors de l'utilisation de `reference_to_video`, `image_urls` peut contenir de 1 à 9 images de référence. Les mots-clés peuvent faire référence aux images dans l'ordre correspondant en utilisant `character1`, `character2`, etc.

```json
{
  "action": "reference_to_video",
  "model": "happyhorse-1.1-r2v",
  "prompt": "character1 avance à travers un pré au lever du soleil avec le style en cuir chaud et les garnitures dorées de character2",
  "image_urls": [
    "https://cdn.acedata.cloud/b1c82e4937.png",
    "https://cdn.acedata.cloud/eb75d88a3f.png"
  ],
  "resolution": "720P",
  "ratio": "16:9",
  "duration": 5
}
```

## Édition vidéo

Lors de l'utilisation de `video_edit`, il est nécessaire de fournir l'URL de la vidéo à éditer `video_url` et l'intention d'édition `prompt`. Les `image_urls` optionnels serviront d'images de référence, par exemple pour changer de tenue, appliquer un style ou remplacer des parties. `audio_setting` peut être `auto` ou `origin`, où `origin` signifie conserver l'audio de la vidéo d'origine.

```json
{
  "action": "video_edit",
  "model": "happyhorse-1.0-video-edit",
  "prompt": "Appliquez le style en cuir chaud et les garnitures dorées de l'image de référence tout en préservant le mouvement de caméra d'origine",
  "video_url": "https://platform2.cdn.acedata.cloud/happyhorse/27837f92-d1c1-4db4-ad9a-4e6e81d9f6c1.mp4",
  "image_urls": [
    "https://cdn.acedata.cloud/eb75d88a3f.png"
  ],
  "resolution": "720P",
  "audio_setting": "auto"
}
```

## Callback asynchrone
La génération de vidéos nécessite un certain temps de traitement. Si vous ne souhaitez pas maintenir une connexion longue en attendant, vous pouvez passer un `callback_url`, dans ce cas, l'API renverra immédiatement un `task_id`, et une fois la tâche terminée, elle enverra le résultat final par POST à cette adresse :

```json
{
  "action": "generate",
  "prompt": "Un cheval courant à travers une forêt enneigée",
  "duration": 5,
  "callback_url": "https://your-domain.com/callback/happyhorse"
}
```

Le résultat renvoyé immédiatement est le suivant :

```json
{
  "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea"
}
```

Si vous souhaitez simplement faire du polling sans besoin de callback, vous pouvez également passer `"async": true`, puis consulter les résultats de la tâche via [HappyHorse Tasks API](https://platform.acedata.cloud/documents/happyhorse-tasks).

## Explication de la facturation

HappyHorse facture en fonction du nombre de secondes de vidéo produites et de la résolution :

- `720P` : aussi bas que $0.105 / seconde.
- `1080P` : aussi bas que $0.18 / seconde.
- `video_edit` : facturé en fonction de la durée totale de la vidéo d'entrée et de la vidéo de sortie, la durée de facturation réelle sera basée sur les statistiques après l'achèvement de la tâche.

Les tâches échouées ne sont pas facturées et ne consomment pas de quota gratuit.

## Gestion des erreurs

Lorsque la demande rencontre un problème, l'API renvoie le code d'erreur correspondant et une explication, les plus courants sont les suivants :

- `400` : Les paramètres de la demande sont incorrects, par exemple, action et modèle ne correspondent pas, manque de `prompt` / `image_url` / `video_url`, ou `duration` dépasse la plage de 3 à 15 secondes.
- `401` : Échec de l'authentification, token invalide ou ne correspondant pas à l'API.
- `403` : Solde insuffisant, ou le contenu du prompt a été rejeté par la modération.
- `429` : Demande trop fréquente, déclenchement de la limitation de débit, veuillez réessayer plus tard.
- `500` : Erreur interne du serveur ou échec de la génération.
