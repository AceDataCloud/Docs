La principale fonction de Flux Tasks API est de consulter l’état d’exécution de cette tâche en saisissant l’ID de tâche de plateforme retourné par Flux Images Generation API ou Flux Videos API.

Ce document présentera en détail les instructions d’intégration de Flux Tasks API, afin de vous aider à intégrer facilement et à exploiter pleinement les puissantes fonctionnalités de cette API. Grâce à Flux Tasks API, vous pouvez facilement consulter l’état d’exécution des tâches de Flux Images Generation API.

Pour un exemple complet de soumission et d’interrogation de vidéos, consultez le [guide d’intégration de Flux Videos API](https://platform.acedata.cloud/documents/flux-videos-integration). La consultation de tâches existantes n’entraîne pas de frais de génération supplémentaires.

## Processus de demande

Pour utiliser Flux Images Generation API, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) afin d’obtenir votre API Token, à conserver pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir besoin d’en demander un séparément pour chaque service.** La première demande offre un quota gratuit pour une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger le solde universel dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Exemple de requête

Flux Tasks API peut être utilisée pour consulter les résultats de Flux Images Generation API. Pour savoir comment utiliser Flux Images Generation API, veuillez consulter la documentation [Flux Images Generation API ](https://platform.acedata.cloud/documents/flux-images-integration)。

Nous prenons comme exemple un ID de tâche retourné par le service Flux Images Generation API, afin de démontrer comment utiliser cette API. Supposons que nous ayons un ID de tâche : 2db0168c-2373-4367-8d9a-9dc778802e8a, nous allons ensuite démontrer comment en passant un ID de tâche.

### Configurer les en-têtes et le corps de la requête

Les **Request Headers** incluent :

- `accept` : spécifie la réception de résultats de réponse au format JSON, renseignez ici `application/json`.
- `authorization` : la clé pour appeler l’API, qui peut être directement sélectionnée dans la liste déroulante après la demande.

Les **Request Body** incluent :

- `id` : l’ID de tâche téléversé.
- `action` : le mode d’opération sur la tâche.

La configuration est illustrée ci-dessous :

<p><img src="https://cdn.acedata.cloud/fiasxz.png" width="500" className="m-auto" /></p>

### Exemple de code

Vous pouvez constater que le code dans différents langages a déjà été généré automatiquement sur le côté droit de la page, comme illustré :

Quelques exemples de code sont les suivants :

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/flux/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/flux/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Le résultat retourné comporte plusieurs champs ; le champ `request` est le request body lors du lancement de la tâche, tandis que le champ `response` est le response body retourné une fois la tâche terminée. La présentation des champs est la suivante.

- `id`, l’ID de génération de cette tâche d’image, utilisé pour identifier de manière unique cette tâche de génération d’image.
- `request`, les informations de requête dans la consultation de la tâche d’image.
- `response`, les informations de retour dans la consultation de la tâche d’image.
- `created_at`, l’heure de création de la tâche, horodatage Unix (secondes, flottant).
- `started_at`, l’heure de début d’exécution de la tâche, horodatage Unix (secondes, flottant).
- `finished_at`, l’heure de fin de la tâche, horodatage Unix (secondes, flottant). Ce champ n’est pas retourné lorsque la tâche n’est pas terminée.
- `elapsed`, la durée d’exécution de la tâche, en secondes (flottant, conservé à 3 décimales). Ce champ n’est pas retourné lorsque la tâche n’est pas terminée.

## Gestion des erreurs

Lors de l’appel de l’API, si une erreur se produit, l’API renvoie le code d’erreur et les informations correspondants. Par exemple :

- `400 token_mismatched` : Mauvaise requête, peut-être en raison de paramètres manquants ou invalides.
- `400 api_not_implemented` : Mauvaise requête, peut-être en raison de paramètres manquants ou invalides.
- `401 invalid_token` : Non autorisé, jeton d’autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d’erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
