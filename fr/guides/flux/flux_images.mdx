Cet article présentera des instructions d’intégration de l’API Flux Images Generation, qui permet de générer des images officielles Flux en saisissant des paramètres personnalisés.

## Processus de demande

Pour utiliser l’API Flux Images Generation, obtenez d’abord votre API Token dans la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications), et conservez-le pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir besoin d’en demander un séparément pour chaque service.** Lors de la première demande, un quota gratuit est offert pour une utilisation gratuite ; lorsque le quota est insuffisant, vous pouvez recharger votre solde général dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Utilisation de base

Commençons par comprendre l’utilisation de base : il suffit de saisir le mot-clé `prompt`, l’action de génération `action` et la taille de l’image `size` pour obtenir le résultat traité. Il faut d’abord transmettre simplement un champ `action`, dont la valeur est `generate`, puis nous devons également saisir le mot-clé. Le contenu spécifique est le suivant :

<p><img src="https://cdn.acedata.cloud/wz85jt.png" width="500" className="m-auto" /></p>

Vous pouvez voir que nous avons défini ici les Request Headers, y compris :

- `accept` : le format de résultat de réponse que vous souhaitez recevoir ; ici, renseignez `application/json`, c’est-à-dire le format JSON.
- `authorization` : la clé permettant d’appeler l’API ; après la demande, vous pouvez directement la sélectionner dans la liste déroulante.

Les Request Body suivants ont également été définis, y compris :

- `action` : l’action de cette tâche de génération d’images.
- `size` : les dimensions du résultat de génération d’image. **Les séries `flux-2-flex` / `flux-2-pro` / `flux-2-max` doivent recevoir un ratio d’image (tel que `1:1`, `16:9`), et n’acceptent pas de dimensions en pixels comme `1024x1024` ; l’absence de ce paramètre renverra 400.**
- `count` : le nombre d’images à générer ; la valeur par défaut est 1. Ce paramètre n’est valide que pour les tâches de génération d’images et n’est pas valide pour les tâches d’édition.
- `prompt` : le mot-clé.
- `model` : le modèle de génération, `flux-dev` par défaut ; les derniers modèles phares sont `flux-2-pro` et `flux-2-max` (qualité d’image supérieure, à utiliser avec le ratio d’image `size`).
- `callback_url` : l’URL nécessitant le résultat du rappel.
- `async` : facultatif ; lorsque défini sur `true`, l’interface renvoie immédiatement un `task_id`, sans avoir à fournir de `callback_url`, puis le résultat est obtenu par interrogation via l’interface de requête de tâche correspondante.

Le paramètre `size` présente certaines restrictions particulières, principalement divisées en deux types : le ratio largeur x hauteur `width x height` et le ratio d’image `x:y`, comme suit :

| Modèle               | Plage                                         |
| ---------------- | ------------------------------------------ |
| flux-dev         | Prend en charge les ratios largeur x hauteur 1024x1024, 1024x1792, 1792x1024, ou les ratios d’image |
| flux-pro         | Prend en charge les ratios largeur x hauteur 1024x1024, 1024x1792, 1792x1024, ou les ratios d’image |
| flux-2-flex      | Prend uniquement en charge les ratios d’image                                    |
| flux-2-pro       | Prend uniquement en charge les ratios d’image                                    |
| flux-2-max       | Prend uniquement en charge les ratios d’image                                    |
| flux-kontext-pro | Prend uniquement en charge les ratios d’image                                    |
| flux-kontext-max | Prend uniquement en charge les ratios d’image                                    |

Ratios d’image de référence : "21:9", "16:9", "4:3", "3:2", "1:1", "2:3", "3:4", "9:16", "9:21".

Après avoir sélectionné les paramètres, le code correspondant sera automatiquement généré à droite. Avant de copier, veuillez confirmer que l’en-tête d’autorisation utilise votre propre API Key ; les documents et captures d’écran ne doivent pas contenir de véritables identifiants.

Cliquez sur le bouton « Try » pour effectuer un test, nous obtenons ici le résultat suivant :

```json
{
  "success": true,
  "task_id": "5456c749-3bbb-4f10-9eb8-cfbcac297500",
  "trace_id": "ae4eecb8-1dd6-45b4-bfb3-a1c48872536e",
  "data": [
    {
      "image_url": "https://cdn.acedata.cloud/assets/examples/flux/5456c749-3bbb-4f10-9eb8-cfbcac297500-d0ef60485f73.jpg"
    }
  ]
}
```

Le résultat renvoyé contient plusieurs champs, présentés comme suit :

- `success`, l’état de la tâche de génération vidéo à ce moment-là.
- `task_id`, l’ID de la tâche de génération vidéo à ce moment-là.
- `trace_id`, l’ID de suivi de génération vidéo à ce moment-là.
- `data`, la liste des résultats de la tâche de génération d’images à ce moment-là.
  - `image_url`, le lien de la tâche de génération d’image à ce moment-là.
  - `prompt`, le mot-clé.

Vous pouvez constater que nous avons obtenu des informations d’image satisfaisantes ; il suffit d’obtenir l’image Flux générée à partir de l’adresse du lien de l’image dans `data` du résultat.

De plus, si vous souhaitez générer le code d’intégration correspondant, vous pouvez le copier directement. Par exemple, le code CURL est le suivant :

```shell
curl -X POST 'https://api.acedata.cloud/flux/images' \
-H 'authorization: Bearer {token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "prompt": "A photorealistic studio product shot of a frosted-glass perfume bottle on wet black slate, single softbox key light, water droplets, dark moody background, 85mm macro.",
  "model": "flux-2-pro",
  "size": "1:1"
}'
```

## Tâche d’édition d’image

Si vous souhaitez éditer une image, le paramètre `image_url` doit d’abord obligatoirement contenir le lien de l’image à éditer. À ce moment-là, `action` ne prend en charge que `edit`, et vous pouvez spécifier le contenu suivant :

- model : le modèle utilisé par cette tâche d’édition d’image ; prend en charge `flux-dev`, `flux-pro`, `flux-kontext-pro`, `flux-kontext-max`, `flux-2-flex`, `flux-2-pro`, `flux-2-max`.
- image_url : importez l’image à éditer.

L’exemple de remplissage est le suivant :

<p><img src="https://cdn.acedata.cloud/jn9da5.png" width="500" className="m-auto" /></p>

Une fois le remplissage terminé, le code suivant est automatiquement généré :

<p><img src="https://cdn.acedata.cloud/6cwxb8.png" width="500" className="m-auto" /></p>

Le code correspondant :

```python
import requests

url = "https://api.acedata.cloud/flux/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "edit",
    "prompt": "a white siamese cat",
    "model": "flux-kontext-pro",
    "image_url": "https://cdn.acedata.cloud/ytj2qy.png"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Cliquez sur exécuter, vous constaterez qu’un résultat est immédiatement obtenu, comme suit :

```json
{
  "success": true,
  "task_id": "2a7979ff-1f77-4380-92c6-a2dc37c3b4c8",
  "trace_id": "732b65c0-48d9-49f7-b568-64e5acffe4c0",
  "data": [
    {
      "prompt": "a white siamese cat",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "timings": 1752744073
    }
  ]
}
```
On peut voir que l’effet généré consiste à éditer l’image originale, et le résultat est similaire à celui décrit ci-dessus.

## Rappel asynchrone

Étant donné que le temps de génération de Flux Images Generation API est relativement long, environ 1 à 2 minutes, si l’API ne répond pas pendant longtemps, la requête HTTP maintiendra constamment la connexion, entraînant une consommation supplémentaire de ressources système. Cette API prend donc également en charge les rappels asynchrones.

Le processus global est le suivant : lorsque le client initie une requête, il spécifie en supplément un champ `callback_url`. Après que le client a initié la requête API, l’API renvoie immédiatement un résultat, qui contient un champ `task_id`, représentant l’ID de la tâche actuelle. Une fois la tâche terminée, le résultat de la génération d’image est envoyé au `callback_url` spécifié par le client sous la forme d’un POST JSON, qui inclut également le champ `task_id`, afin que les résultats de la tâche puissent être associés via l’ID.

Voyons ci-dessous comment procéder concrètement à l’aide d’un exemple.

Tout d’abord, le rappel Webhook est un service capable de recevoir des requêtes HTTP. Les développeurs doivent le remplacer par l’URL de leur propre serveur HTTP. Afin de faciliter la démonstration, nous utilisons ici un site d’exemple Webhook public https://webhook.site/ ; en ouvrant ce site, vous pouvez obtenir une URL Webhook, comme indiqué sur l’image :

![](https://cdn.acedata.cloud/cjjfly.png)

Copiez cette URL, elle peut alors être utilisée comme Webhook ; l’exemple ici est `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`.

Ensuite, nous pouvons définir le champ `callback_url` sur l’URL Webhook ci-dessus, tout en renseignant les paramètres correspondants ; le contenu spécifique est illustré comme suit :

<p><img src="https://cdn.acedata.cloud/wm6caw.png" width="500" className="m-auto" /></p>

Cliquez sur exécuter, et vous constaterez qu’un résultat est immédiatement obtenu, comme suit :

```
{
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c"
}
```

Après avoir attendu un instant, nous pouvons observer le résultat de la génération d’image sur `https://webhook.site/3d32690d-6780-4187-a65c-870061e8c8ab`, comme indiqué sur l’image :

![](https://cdn.acedata.cloud/v23lot.png)

Le contenu est le suivant :

```json

  "success": true,
  "task_id": "6a97bf49-df50-4129-9e46-119aa9fca73c",
  "trace_id": "9b4b1ff3-90f2-470f-b082-1061ec2948cc",
  "data": [
```

On peut voir qu’il y a un champ `task_id` dans le résultat ; les autres champs sont similaires à ceux décrits ci-dessus. Ce champ permet d’établir l’association avec la tâche.

## Gestion des erreurs

Lors de l’appel de l’API, si une erreur se produit, l’API renvoie le code d’erreur et les informations correspondants. Par exemple :

- `400 token_mismatched` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `400 api_not_implemented` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `401 invalid_token` : Non autorisé, jeton d’autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d’erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
