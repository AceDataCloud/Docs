Codex est un agent de programmation lancé par OpenAI. En plus de l'interface CLI terminal, il propose également une extension VS Code, permettant de discuter dans la barre latérale de l'éditeur, lire des fichiers, référencer le contexte, générer des modifications et prévisualiser les changements.

Cet article explique comment configurer et utiliser l'extension Codex dans VS Code via l'agent compatible OpenAI Responses d'Ace Data Cloud. L'extension Codex VS Code et le CLI Codex utilisent le même système de configuration local, il suffit donc de pointer `~/.codex/config.toml` vers Ace Data Cloud pour que Codex dans VS Code utilise `https://api.acedata.cloud/v1`.

## Processus de demande

Pour utiliser Codex, commencez par obtenir votre API Token sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications), à conserver pour usage ultérieur.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inscrire et vous connecter, puis vous reviendrez automatiquement à cette page.

Un quota gratuit est offert lors de la première inscription, permettant d'essayer gratuitement le service Codex.

## Installation de l'extension Codex

Dans le marketplace des extensions VS Code, recherchez `Codex` et installez l'extension **Codex - OpenAI's coding agent** publiée par OpenAI. Son ID Marketplace est :

```text
openai.chatgpt
```

Vous pouvez également l'installer via la ligne de commande :

```bash
code --install-extension openai.chatgpt
```

Après installation, redémarrez ou rechargez VS Code. Si vous ne voyez pas l'entrée Codex, ouvrez la palette de commandes (macOS : `Cmd+Shift+P`, Windows/Linux : `Ctrl+Shift+P`), recherchez et exécutez :

```text
Codex: Open Codex Sidebar
```

Par défaut, Codex apparaît dans la barre latérale droite de VS Code. Vous pouvez aussi le glisser vers la barre d'activités à gauche.

## Installation du CLI Codex (pour vérification)

La documentation officielle indique que l'extension Codex VS Code et le CLI Codex partagent la même couche de configuration. Pour vérifier la validité de votre API Token et modèle avant de configurer VS Code, il est recommandé d'installer également le CLI Codex.

Une méthode recommandée est l'installation via npm, nécessitant Node.js 18 ou supérieur :

```bash
npm install -g @openai/codex
```

Les utilisateurs macOS peuvent aussi installer via Homebrew :

```bash
brew install --cask codex
```

Après installation, vérifiez que la commande est disponible dans le terminal :

```bash
codex --version
```

Si vous souhaitez uniquement utiliser l'extension VS Code, vous pouvez passer l'étape de vérification CLI ; la configuration `~/.codex/config.toml` reste la même.

## Configuration de l'API Ace Data Cloud

L'extension Codex VS Code et le CLI Codex partagent le fichier de configuration. Par défaut, Codex invite à se connecter avec un compte officiel OpenAI ou à configurer une clé API officielle. Pour utiliser Ace Data Cloud, il faut configurer l'API Token et le fichier `~/.codex/config.toml`.

### Première étape : définir la variable d'environnement

Il est recommandé d’écrire l’API Token dans le fichier de configuration du shell, par exemple `~/.zshrc`, `~/.bashrc` ou `~/.bash_profile` :

```bash
export ACEDATACLOUD_API_KEY="{token}"
```

Remplacez `{token}` par l’API Token copié depuis la console Ace Data Cloud.

Après configuration, rouvrez le terminal ou exécutez la commande `source` correspondante pour appliquer immédiatement la configuration :

```bash
source ~/.zshrc
```

Si VS Code est déjà ouvert, redémarrez ou rechargez-le pour que l’extension prenne en compte la nouvelle variable d’environnement.

### Deuxième étape : éditer le fichier de configuration Codex

Le fichier de configuration utilisateur de Codex se trouve à `~/.codex/config.toml`. S’il n’existe pas, créez-le :

```bash
mkdir -p ~/.codex
touch ~/.codex/config.toml
```

Écrivez la configuration suivante :

```toml
model_provider = "acedatacloud"
model = "gpt-5"
model_reasoning_effort = "high"
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[model_providers.acedatacloud]
name = "Ace Data Cloud"
base_url = "https://api.acedata.cloud/v1"
env_key = "ACEDATACLOUD_API_KEY"
wire_api = "responses"
```

Explications des champs :

| Champ | Description |
| --- | --- |
| `model_provider` | Fournisseur de modèle par défaut, correspondant à `[model_providers.acedatacloud]` ci-dessous |
| `model` | ID du modèle par défaut |
| `model_reasoning_effort` | Intensité du raisonnement, valeurs courantes : `low`, `medium`, `high` |
| `approval_policy` | Politique de confirmation avant exécution des commandes, recommandé `on-request` pour usage quotidien |
| `sandbox_mode` | Permissions sandbox lors de l’exécution des commandes par Codex, recommandé `workspace-write` pour développement quotidien |
| `base_url` | URL de l’API compatible OpenAI d’Ace Data Cloud |
| `env_key` | Nom de la variable d’environnement contenant l’API Token |
| `wire_api` | Type de protocole, pour l’API OpenAI Responses doit être `responses` |

Vous pouvez aussi ouvrir ce fichier directement depuis VS Code en cliquant sur l’icône d’engrenage en haut à droite de l’extension Codex, puis **Codex Settings > Open config.toml**.

### Configuration au niveau du projet

Si vous souhaitez qu’un projet utilise une configuration différente, créez un fichier `.codex/config.toml` à la racine du projet. Codex chargera prioritairement cette configuration projet, à condition que le projet soit marqué comme trusted.

Exemple :

```toml
model = "gpt-5-mini"
model_reasoning_effort = "medium"
```

Il est conseillé de stocker les tokens personnels dans les variables d’environnement et non dans le dépôt du projet. La soumission du fichier `.codex/config.toml` projet dépendra des pratiques de votre équipe.

## Nettoyer la connexion OpenAI mise en cache

Si vous vous êtes déjà connecté avec un compte OpenAI officiel dans l’extension Codex, un état de connexion peut être conservé localement. Avant de passer à l’agent Ace Data Cloud, exécutez dans le terminal :

```bash
codex logout
```

Si la commande n’est pas disponible, supprimez manuellement le fichier de cache local :

```bash
rm -f ~/.codex/auth.json
```

Puis redémarrez ou rechargez VS Code.

## Utilisation de base

Une fois la configuration terminée, ouvrez le panneau Codex à gauche ou à droite dans VS Code et saisissez directement votre demande. Par exemple :

```text
Explique la structure des dossiers du projet actuel et indique le fichier d’entrée principal.
```

L’extension Codex peut utiliser les fichiers ouverts et le code sélectionné dans l’éditeur comme contexte. Vous pouvez aussi référencer un fichier avec `@` dans la zone de saisie, par exemple :

```text
Réfère-toi à @src/App.vue, aide-moi à découper cette page en composants plus clairs.
```

Si vous sélectionnez un morceau de code, vous pouvez l’ajouter au fil de discussion via la palette de commandes :

```text
Codex: Add to Codex Thread
```

Ou ajouter le fichier entier :

```text
Codex: Add File to Codex Thread
```

## Changer de modèle et d’intensité de raisonnement

L’extension Codex VS Code permet de changer de modèle et d’ajuster l’effort de raisonnement via le sélecteur sous la zone de saisie. Avec le fournisseur personnalisé Ace Data Cloud, la méthode la plus fiable est de définir un modèle par défaut dans `~/.codex/config.toml`, puis de changer à la volée dans l’interface si besoin. Voici les recommandations par scénario :

| Scénario | Modèle recommandé | Intensité de raisonnement |
| --- | --- | --- |
| Lecture de code et petites modifications quotidiennes | `gpt-5-mini` | `medium` |
| Tâches de développement classiques | `gpt-5` | `high` |
| Refactorisations complexes et raisonnement approfondi | `gpt-5.5` ou `gpt-5.5-pro` | `high` |
| Tâches nécessitant un raisonnement renforcé | `o3` | `high` |

Si le modèle souhaité n’apparaît pas dans l’interface, modifiez directement le champ `model` dans `~/.codex/config.toml` puis redémarrez ou rechargez VS Code. La liste complète des modèles est disponible dans la [documentation OpenAI d’Ace Data Cloud](https://platform.acedata.cloud/documents/openai).

## Choix du mode de travail

L’extension Codex supporte différents modes de travail. Les modes courants sont :

| Mode | Scénario d’utilisation |
| --- | --- |
| `Chat` | Pour discuter, expliquer du code, planifier sans que Codex modifie directement les fichiers |
| `Agent` | Pour que Codex lise les fichiers, modifie le code et exécute les commandes nécessaires, recommandé pour le développement quotidien |
| `Agent (Full Access)` | Pour autoriser des permissions plus élevées et l’accès réseau, adapté aux scénarios où vous comprenez les risques |

L’usage quotidien recommande le mode `Agent` avec `approval_policy = "on-request"`. Ainsi, Codex demandera confirmation avant d’exécuter des commandes sensibles, d’accéder à des chemins hors de l’espace de travail ou au réseau.

## Vérification de la configuration

Vous pouvez vérifier dans le terminal si Codex fonctionne via Ace Data Cloud avec cette commande :

```bash
codex exec --model gpt-5-mini "Reply with exactly: ADC_Codex_OK"
```

Si la configuration est correcte, vous devriez voir une réponse similaire :

```text
ADC_Codex_OK
```

Ensuite, dans VS Code, ouvrez le panneau Codex et posez une question simple :

```text
Décris en une phrase l’usage de l’espace de travail actuel.
```

Vous pouvez aussi consulter l’historique des requêtes et les détails de facturation via la [console Ace Data Cloud - Historique d’utilisation](https://platform.acedata.cloud/console/usages), et vérifier le quota restant via la [console Ace Data Cloud - Liste des applications](https://platform.acedata.cloud/console/applications).

## Fonctionnement interne

L’extension Codex VS Code ne possède pas une configuration de modèle indépendante. Elle utilise le CLI Codex natif et partage la couche de configuration Codex :

1. L’extension VS Code lance Codex et lit la configuration utilisateur `~/.codex/config.toml`.
2. Si le projet est trusted et contient un fichier `.codex/config.toml`, Codex charge aussi la configuration projet.
3. Quand `model_provider` est `acedatacloud`, Codex récupère l’API Token depuis `ACEDATACLOUD_API_KEY`.
4. Les requêtes sont envoyées via le protocole OpenAI Responses à `https://api.acedata.cloud/v1/responses`.
5. Ace Data Cloud authentifie, vérifie le quota, relaie la requête et enregistre l’utilisation.

Ainsi, la configuration CLI et VS Code est généralement unique. Une fois la vérification terminal réussie, l’extension VS Code utilise la même configuration.
