Codex CLI est un agent de programmation local open source lancé par OpenAI, fonctionnant dans votre terminal. Il peut lire du code, modifier des fichiers, exécuter des commandes, expliquer des erreurs et aider à accomplir les tâches de développement quotidiennes.

Codex CLI prend en charge les fournisseurs de modèles personnalisés. Vous pouvez l'utiliser via un proxy compatible OpenAI Responses fourni par Ace Data Cloud, sans avoir besoin d'un abonnement séparé au compte officiel OpenAI. Une fois configuré, Codex CLI enverra les requêtes à `https://api.acedata.cloud/v1`.

## Processus de demande

Pour utiliser Codex CLI, commencez par obtenir votre token API sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications), à conserver pour usage futur.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inscrire et vous connecter. Après connexion ou inscription, vous reviendrez automatiquement à cette page.

Lors de la première demande, un quota gratuit est offert pour tester le service Codex CLI gratuitement.

## Installation de Codex CLI

Codex CLI est compatible avec macOS, Linux, Windows et WSL. Vous pouvez l'installer via npm ou Homebrew (uniquement macOS).

### Installation via npm (recommandée)

Si Node.js est déjà installé, vous pouvez installer directement via npm. Cette méthode nécessite Node.js 18 ou une version supérieure.

```bash
npm install -g @openai/codex
```

### Installation via Homebrew (macOS)

Les utilisateurs macOS peuvent aussi installer via Homebrew :

```bash
brew install --cask codex
```

### Vérification de l'installation

Après l'installation, rouvrez le terminal puis vérifiez si la commande est disponible :

```bash
codex --version
```

Si vous obtenez `command not found`, cela signifie généralement que le nouveau PATH n'a pas encore été chargé dans le terminal actuel. Fermez et rouvrez le terminal, ou vérifiez la configuration du PATH indiquée lors de l'installation.

## Configuration de Codex CLI

Par défaut, Codex CLI tente de se connecter au service officiel OpenAI. Pour utiliser Ace Data Cloud, vous devez déclarer un `model_provider` personnalisé dans le fichier de configuration de Codex et placer le token API dans la variable d'environnement correspondante.

### Première étape : définir la variable d'environnement

Il est recommandé d'ajouter le token API dans le fichier de configuration de votre shell, par exemple `~/.zshrc`, `~/.bashrc` ou `~/.bash_profile` :

```bash
export ACEDATACLOUD_API_KEY="{token}"
```

Remplacez `{token}` par le token API copié depuis la console Ace Data Cloud.

Après configuration, rouvrez le terminal ou exécutez la commande `source` correspondante pour appliquer immédiatement la configuration :

```bash
source ~/.zshrc
```

### Deuxième étape : modifier le fichier de configuration Codex

Codex CLI utilise `~/.codex/config.toml` comme fichier de configuration global. S'il n'existe pas, créez-le :

```bash
mkdir -p ~/.codex
touch ~/.codex/config.toml
```

Insérez le contenu suivant dans `~/.codex/config.toml` :

```toml
model_provider = "acedatacloud"
model = "gpt-5"
model_reasoning_effort = "high"

[model_providers.acedatacloud]
name = "Ace Data Cloud"
base_url = "https://api.acedata.cloud/v1"
env_key = "ACEDATACLOUD_API_KEY"
wire_api = "responses"
```

Description des champs :

| Champ | Description |
| --- | --- |
| `model_provider` | Nom du fournisseur par défaut, correspondant à la clé `[model_providers.<name>]` ci-dessous |
| `model` | ID du modèle utilisé par défaut |
| `model_reasoning_effort` | Intensité du raisonnement, valeurs courantes : `low`, `medium`, `high` |
| `[model_providers.acedatacloud].base_url` | Adresse du proxy OpenAI Responses d'Ace Data Cloud |
| `[model_providers.acedatacloud].env_key` | Nom de la variable d'environnement où Codex CLI lit le token API |
| `[model_providers.acedatacloud].wire_api` | Type de protocole, doit être `responses` pour l'API OpenAI Responses |

### Nettoyer les connexions OpenAI mises en cache

Si vous vous êtes déjà connecté à Codex CLI avec un compte officiel OpenAI, un état de connexion peut être mis en cache localement (généralement dans `~/.codex/auth.json`). Avant de passer au proxy Ace Data Cloud, il est conseillé de nettoyer cette ancienne connexion :

```bash
codex logout
```

Si la commande `codex logout` n'est pas disponible, vous pouvez supprimer manuellement le fichier de cache :

```bash
rm -f ~/.codex/auth.json
```

Si vous ne vous êtes jamais connecté avec un compte officiel OpenAI, vous pouvez ignorer cette étape.

### Démarrer une session

Accédez au répertoire de votre projet, puis lancez Codex CLI :

```bash
cd /path/to/your/project
codex
```

Une fois l'interface interactive Codex affichée, vous pouvez saisir vos demandes, par exemple :

```text
Explique la structure des dossiers de ce projet
```

### Vérifier la configuration

Dans Codex CLI, vous pouvez vérifier le modèle et le fournisseur actuels avec :

```text
/model
```

Vous devriez voir que le modèle provient du fournisseur `acedatacloud`, par exemple :

```text
Model: gpt-5
Provider: acedatacloud
```

Si le fournisseur affiché n'est pas `acedatacloud`, la configuration n'a pas été prise en compte. Veuillez vérifier que `~/.codex/config.toml` a bien été sauvegardé et que `ACEDATACLOUD_API_KEY` est accessible dans le terminal courant :

```bash
echo $ACEDATACLOUD_API_KEY
```

Vous pouvez également consulter l'historique des requêtes et les détails de facturation via la [console Ace Data Cloud - Historique d'utilisation](https://platform.acedata.cloud/console/usages), et vérifier le quota restant via la [console Ace Data Cloud - Liste des applications](https://platform.acedata.cloud/console/applications).

## Fonctionnement

Codex CLI utilise nativement le protocole OpenAI Responses API. Ace Data Cloud fournit un service proxy compatible OpenAI Responses API à l'adresse `https://api.acedata.cloud/v1/responses`, ce qui évite d'avoir un proxy local ou des plugins supplémentaires.

Le flux de travail est le suivant :

1. Codex CLI lit `model_provider` dans `~/.codex/config.toml` et charge la configuration correspondante `[model_providers.acedatacloud]`.
2. Codex CLI lit le token API depuis la variable d'environnement indiquée par `env_key` (`ACEDATACLOUD_API_KEY`).
3. La requête est envoyée via le protocole `wire_api = "responses"` à `base_url + /responses`, soit `https://api.acedata.cloud/v1/responses`.
4. Ace Data Cloud valide votre identité avec le token API, vérifie le quota, puis transmet la requête vers un canal de modèle en amont disponible.
5. Après traitement, la plateforme enregistre la consommation réelle et déduit le quota.

Cela signifie que vous continuez à utiliser la commande originale `codex` et l'expérience interactive native de Codex CLI, mais avec le service de modèle sous-jacent basculé vers Ace Data Cloud.

## Configuration du modèle

Le champ `model` dans `~/.codex/config.toml` détermine le modèle par défaut utilisé par Codex. Le service OpenAI Responses d'Ace Data Cloud prend en charge plusieurs modèles courants :

| Modèle | Description |
| --- | --- |
| `gpt-5` | Modèle recommandé par défaut, adapté à la plupart des tâches de codage |
| `gpt-5-mini` | Plus léger et plus rapide, adapté aux tâches simples |
| `gpt-5.5` | Version mise à jour, plus puissante |
| `gpt-5.5-pro` | Version améliorée, adaptée aux tâches de raisonnement complexes |
| `gpt-4.1` | Modèle principal de la génération précédente |
| `o3` | Modèle renforcé pour un raisonnement profond |
| `o4-mini-high-all` | Modèle léger pour raisonnement |

Pour changer temporairement de modèle, vous pouvez spécifier le modèle au lancement de Codex via la ligne de commande :

```bash
codex --model gpt-5-mini
```

Vous pouvez aussi modifier directement le champ `model` dans `~/.codex/config.toml` puis redémarrer. La liste complète des modèles est disponible dans la [documentation du service OpenAI d'Ace Data Cloud](https://platform.acedata.cloud/documents/openai).

## Niveau de confiance du projet

Codex CLI permet de définir différents niveaux de confiance par projet, contrôlant les actions que l'agent peut effectuer. Ajoutez à la fin de `~/.codex/config.toml` :

```toml
[projects."/path/to/trusted/project"]
trust_level = "trusted"

[projects."/path/to/untrusted/project"]
trust_level = "untrusted"
```

Où :

- `trusted` : l'agent dispose de tous les droits, peut exécuter des commandes et modifier des fichiers.
- `untrusted` : l'agent a des droits restreints, adapté aux projets moins familiers.
