Ce document présente les instructions d’intégration de l’API Kling Videos Generation, qui permet de générer des vidéos officielles Kling en saisissant des paramètres personnalisés.

## Processus de demande

Pour utiliser l’API, vous devez d’abord faire une demande de service sur la page correspondante de [Kling Videos Generation API](https://platform.acedata.cloud/documents/3b921a16-a411-4557-8335-53f21d3f9e46). Une fois sur la page, cliquez sur le bouton « Acquire », comme illustré ci-dessous :

![](https://cdn.acedata.cloud/q6ytrc.png)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inscrire et vous connecter. Après connexion, vous serez automatiquement ramené à la page actuelle.

Lors de la première demande, un quota gratuit est offert, vous permettant d’utiliser l’API gratuitement.

## Utilisation de base

Commençons par comprendre la méthode d’utilisation de base : en saisissant un mot-clé `prompt`, une action `action`, une image de référence pour la première image `start_image_url` et un modèle `model`, vous pouvez obtenir le résultat traité. Il faut d’abord transmettre un champ `action` dont la valeur est `text2video`. Cette action comprend principalement trois comportements : texte vers vidéo (`text2video`), image vers vidéo (`image2video`) et extension vidéo (`extend`). Ensuite, il faut également spécifier le modèle `model`. Les modèles principaux disponibles sont `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni` et `kling-video-o1`. Voici les détails :

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

On peut voir ici que nous avons configuré les en-têtes de la requête (Request Headers), comprenant :

- `accept` : le format de réponse souhaité, ici `application/json` pour un format JSON.
- `authorization` : la clé d’API pour appeler l’API, sélectionnable directement après la demande.

Le corps de la requête (Request Body) comprend :

- `model` : le modèle utilisé pour générer la vidéo, parmi `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-video-o1`.
- `mode` : le mode de génération vidéo, options possibles : mode standard `std`, mode rapide `pro` et mode natif 4K `4k`. Le mode `4k` est uniquement compatible avec `kling-v3` et `kling-v3-omni`, et incompatible avec `camera_control` (contrôle de la caméra).
- `action` : le comportement de la tâche de génération vidéo, comprenant trois types : texte vers vidéo (`text2video`), image vers vidéo (`image2video`), extension vidéo (`extend`).
- `start_image_url` : obligatoire pour l’action `image2video`, lien de l’image de référence pour la première image.
- `end_image_url` : optionnel pour `image2video`, spécifie l’image finale.
- `duration` : durée de la vidéo en secondes. Pour les modèles `kling-v3` et `kling-v3-omni`, la durée est flexible entre 3 et 15 secondes (entier), pour les autres modèles, 5 ou 10 secondes.
- `generate_audio` : optionnel, booléen indiquant si un audio doit être généré simultanément. Supporté par `kling-v3`, `kling-v3-omni` et `kling-v2-6` (mode pro uniquement). Par défaut `false`.
- `aspect_ratio` : ratio largeur/hauteur de la vidéo, optionnel, supporte `16:9`, `9:16`, `1:1`, par défaut `16:9`.
- `cfg_scale` : intensité de corrélation, plage [0,1], plus la valeur est élevée, plus la vidéo correspond au prompt.
- `camera_control` : optionnel, paramètres pour contrôler le mouvement de la caméra, supporte les presets type/simple ainsi que horizontal, vertical, pan, tilt, roll, zoom, etc.
- `negative_prompt` : optionnel, mots-clés négatifs à ne pas inclure, maximum 200 caractères.
- `element_list` : liste de références principales, applicable uniquement au modèle `kling-video-o1`. Pour son utilisation détaillée, voir la [documentation officielle](https://docs.qingque.cn/d/home/eZQAyImcbaS0fz-8ANjXvU5ed?identityId=1oEG9JKKMFv#section=h.5t7wme23nn6z).
- `video_list` : vidéos de référence via URL, applicable uniquement au modèle `kling-video-o1`. Pour son utilisation détaillée, voir la [documentation officielle](https://docs.qingque.cn/d/home/eZQAyImcbaS0fz-8ANjXvU5ed?identityId=1oEG9JKKMFv#section=h.5t7wme23nn6z).
- `prompt` : le prompt.
- `callback_url` : URL pour recevoir le résultat en callback.

Après sélection, le code correspondant est généré à droite, comme illustré :

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Cliquez sur le bouton « Try » pour tester. Comme montré ci-dessus, nous obtenons le résultat suivant :

Le résultat contient plusieurs champs, décrits ci-dessous :

- `task_id` : ID de la tâche de génération vidéo.
- `video_id` : ID de la vidéo générée.

- `state` : état de la tâche.

Nous avons ainsi obtenu les informations vidéo souhaitées. Il suffit d’utiliser le lien vidéo dans `data` pour accéder à la vidéo Kling générée.

Pour générer le code d’intégration correspondant, vous pouvez copier directement le code généré, par exemple le code CURL suivant :

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v1",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Fonctionnalité d’extension vidéo

Pour continuer à générer une vidéo Kling déjà créée, définissez le paramètre `action` sur `extend` et saisissez l’ID de la vidéo à prolonger, que vous pouvez obtenir via l’utilisation de base comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Ici, l’ID de la vidéo est :

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Notez que ce `video_id` est l’ID de la vidéo générée. Si vous ne savez pas comment générer une vidéo, référez-vous à la section d’utilisation de base ci-dessus.

Ensuite, vous devez saisir le prompt d’extension pour personnaliser la génération de la vidéo, avec les paramètres suivants :

- `model` : modèle utilisé, parmi `kling-v1`, `kling-v1-5` et `kling-v1-6`.
- `mode` : mode de génération, options : standard `std`, rapide `pro` et 4K natif `4k` (seulement `kling-v3` et `kling-v3-omni`, incompatible avec contrôle caméra).
- `duration` : durée de la vidéo générée, généralement 5s ou 10s.
- `start_image_url` : obligatoire pour `image2video`, lien de la première image de référence.
- `prompt` : prompt.

Exemple de saisie :

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Après saisie, le code est automatiquement généré comme suit :

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

En exécutant, vous obtiendrez un résultat comme suit :

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7822108635/extendVideo/Cjil4mfBfs0AAAAAAKhr6A-0_raw_video_1.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```

On constate que le contenu du résultat est similaire à celui présenté précédemment, ce qui permet d’étendre la vidéo.

## Callback asynchrone

La génération via l’API Kling Videos Generation prend généralement 1 à 2 minutes. Si l’API ne répond pas rapidement, la requête HTTP reste ouverte, consommant des ressources système supplémentaires. C’est pourquoi l’API supporte également les callbacks asynchrones.

Le processus global est : lors de la requête client, un champ `callback_url` est spécifié. Après l’appel API, un résultat est immédiatement retourné, contenant un champ `task_id` représentant l’ID de la tâche. Une fois la tâche terminée, le résultat de la vidéo générée est envoyé en POST JSON à l’URL `callback_url` spécifiée par le client, incluant également le champ `task_id` pour associer la tâche et son résultat.

Voyons un exemple concret.

D’abord, le webhook callback est un service pouvant recevoir des requêtes HTTP. Le développeur doit remplacer cette URL par celle de son propre serveur HTTP. Pour la démonstration, nous utilisons un site public d’exemple de webhook https://webhook.site/. En ouvrant ce site, vous obtenez une URL webhook, comme illustré :

![](https://cdn.acedata.cloud/tbcnai.png)

Copiez cette URL, par exemple `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, elle servira de webhook.

Ensuite, définissez le champ `callback_url` sur cette URL webhook et saisissez les autres paramètres, comme montré ci-dessous :

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

En cliquant sur exécuter, vous obtenez immédiatement un résultat :

```

}
```

Après un court délai, vous pouvez observer sur `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3` le résultat de la vidéo générée, comme illustré :

    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"

On remarque un champ `task_id` et d’autres champs similaires à ceux vus précédemment, ce qui permet d’associer la tâche au résultat.

## Gestion des erreurs

Lors de l’appel de l’API, en cas d’erreur, l’API retourne un code d’erreur et un message correspondant. Par exemple :

- `400 token_mismatched` : requête incorrecte, paramètres manquants ou invalides.
- `400 api_not_implemented` : requête incorrecte, paramètres manquants ou invalides.
- `401 invalid_token` : non autorisé, token d’autorisation invalide ou manquant.
- `429 too_many_requests` : trop de requêtes, dépassement de la limite de fréquence.
- `500 api_error` : erreur interne du serveur.

### Exemple de réponse d’erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
