Cet article présentera une méthode d’intégration de l’API Kling Videos Generation, qui permet de générer des vidéos officielles Kling en saisissant des paramètres personnalisés.

## Processus de demande

Pour utiliser l’API Kling Videos Generation, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token, à conserver en réserve.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter, puis vous reviendrez automatiquement sur la page actuelle une fois terminé.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans devoir faire une demande séparée pour chaque service.** Lors de la première demande, un quota gratuit est offert pour une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger le solde commun depuis la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Utilisation de base

Commençons d’abord par comprendre le mode d’utilisation de base : saisissez le mot-clé `prompt`, l’action de génération `action`, l’image de référence de la première image `start_image_url` ainsi que le modèle `model`, et vous pourrez obtenir le résultat traité. Il faut d’abord transmettre simplement un champ `action`, dont la valeur est `text2video` ; il contient principalement trois comportements : texte vers vidéo (`text2video`), image vers vidéo (`image2video`), vidéo étendue (`extend`). Ensuite, nous devons également saisir le modèle `model`. Les modèles actuellement principaux sont `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`, dont le contenu spécifique est le suivant :

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Vous pouvez voir que nous avons ici défini les Request Headers, incluant :

- `accept` : le format de résultat de réponse que vous souhaitez recevoir ; ici, renseignez `application/json`, c’est-à-dire le format JSON.
- `authorization` : la clé permettant d’appeler l’API, qui peut être directement sélectionnée dans la liste déroulante après la demande.

Les Request Body sont également définis, incluant :

- `model` : le modèle de génération vidéo, comprenant principalement les modèles `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode` : le mode de génération vidéo ; les valeurs possibles sont le mode standard `std`, le mode rapide `pro` et le mode 4K natif `4k`. Parmi eux, `4k` ne prend en charge que `kling-v3` et `kling-v3-omni`, et est incompatible avec `camera_control` (contrôle du mouvement de caméra).
- `action` : le comportement de cette tâche de génération vidéo, comprenant principalement trois comportements : texte vers vidéo (`text2video`), image vers vidéo (`image2video`), vidéo étendue (`extend`).
- `start_image_url` : le lien de l’image de référence de la première image à téléverser, obligatoire lorsque le comportement image vers vidéo `image2video` est sélectionné.
- `end_image_url` : facultatif lors de la génération d’image vers vidéo, spécifie la dernière image.
- `duration` : la durée de la vidéo, en secondes. `kling-v3` et `kling-v3-omni` prennent en charge des durées entières de 3 à 15 secondes ; `kling-o1` ne prend en charge que 5 secondes ; les autres modèles prennent en charge 5 ou 10 secondes.
- `generate_audio` : s’il faut générer l’audio de manière synchronisée, facultatif, valeur booléenne. Pris en charge par `kling-v3`, `kling-v3-omni` et `kling-v2-6` (mode pro uniquement). La valeur par défaut est `false`.
- `aspect_ratio` : le ratio largeur/hauteur de la vidéo, facultatif, prend en charge `16:9`, `9:16`, `1:1`, avec `16:9` par défaut.
- `cfg_scale` : l’intensité de corrélation, plage [0,1] ; plus elle est élevée, plus le résultat correspond au mot-clé.
- `camera_control` : facultatif, paramètre objet qui contrôle le mouvement de la caméra, prend en charge les préréglages type/simple ainsi que les configurations horizontal, vertical, pan, tilt, roll, zoom, etc.
- `negative_prompt` : facultatif, mot-clé négatif que vous ne souhaitez pas voir apparaître, jusqu’à 200 caractères.
- `image_list` : liste d’images de référence Omni, applicable aux modèles `kling-o1` et `kling-v3-omni`, voir ci-dessous « Référence Omni polyvalente » pour l’utilisation.
- `video_list` : liste de vidéos de référence Omni (prend en charge l’édition vidéo), applicable aux modèles `kling-o1` et `kling-v3-omni`, voir ci-dessous « Référence Omni polyvalente » pour l’utilisation.
- `prompt` : le mot-clé.
- `callback_url` : l’URL nécessitant un résultat de rappel.
- `async` : facultatif ; lorsque défini sur `true`, l’interface retourne immédiatement `task_id`, sans nécessiter de fournir `callback_url`, puis le résultat est obtenu en interrogeant périodiquement l’interface de requête de tâche correspondante.

Après la sélection, vous pouvez constater que le code correspondant est également généré à droite, comme indiqué sur l’image :

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Cliquez sur le bouton « Try » pour effectuer le test. Comme indiqué ci-dessus, nous obtenons ici le résultat suivant :

```json

  "video_id": "900798310464749610",
  "video_url": "https://cdn.acedata.cloud/assets/examples/kling/6c68c267-065b-4423-b66b-a0e4c59ee0d5-6a664a591a53.mp4",
  "duration": "5.041",
```

Le résultat retourné comporte plusieurs champs, présentés ci-dessous :

- `success`, l’état de la tâche de génération vidéo à ce moment.
- `task_id`, l’ID de la tâche de génération vidéo à ce moment.
- `video_id`, l’ID vidéo de la tâche de génération vidéo à ce moment.
- `video_url`, le lien vidéo de la tâche de génération vidéo à ce moment.
- `duration`, la durée du lien vidéo de la tâche de génération vidéo à ce moment.
- `state`, l’état de la tâche de génération vidéo à ce moment.

Vous pouvez constater que nous avons obtenu des informations vidéo satisfaisantes ; il nous suffit d’obtenir la vidéo Kling générée à partir de l’adresse du lien vidéo dans `data` du résultat.

De plus, si vous souhaitez générer le code d’intégration correspondant, vous pouvez directement le copier ; par exemple, le code CURL est le suivant :

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Matrice des capacités des modèles

Les différents modèles présentent des différences importantes dans leur prise en charge des paramètres. La matrice suivante est organisée à partir de la [documentation officielle Kling video models](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels). Avant l’appel, veuillez d’abord vérifier si la combinaison actuelle `model` / `mode` / `duration` prend en charge les fonctionnalités dont vous avez besoin ; sinon, des erreurs telles que `model/mode/duration(...) is not supported with image_tail` seront retournées.
| Modèle              | Mode           | `end_image_url` (première et dernière image) | `generate_audio` (audio d'accompagnement) | `camera_control` (mouvement de caméra) | Remarques                                    |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ uniquement `duration=5` | ❌                    | ✅ uniquement `duration=5` | `extend` ne prend pas en charge `negative_prompt` ni `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | La génération de vidéo à partir de plusieurs images et tous les modes `extend` sont disponibles |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Mode unique, uniquement `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Mode unique, uniquement `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | Le seul modèle non-v3 prenant simultanément en charge l'audio d'accompagnement |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | Plage de `duration` : 3–15 secondes                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | Le mode 4K est incompatible avec le mouvement de caméra                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Prend uniquement en charge `duration=5`                             |

Remarques :

- `mode=4k` est uniquement pris en charge par `kling-v3` et `kling-v3-omni` ; il est également mutuellement exclusif avec `camera_control` (mouvement de caméra).
- `end_image_url` peut uniquement être utilisé avec `start_image_url` lorsque `action=image2video`. Transmettre uniquement `end_image_url` (sans `start_image_url`) sera refusé.
- `kling-v3` / `kling-v3-omni` acceptent toute `duration` entière de 3 à 15 secondes ; `kling-o1` accepte uniquement 5 ; les autres modèles acceptent uniquement 5 ou 10.
- `generate_audio` est défini sur `false` par défaut. Seuls `kling-v3`, `kling-v3-omni` et `kling-v2-6` (mode pro) sont pris en charge.

## Fonctionnalité d'extension vidéo

Si vous souhaitez poursuivre la génération d'une vidéo Kling déjà générée, vous pouvez définir le paramètre `action` sur `extend`, puis saisir l'ID de la vidéo à poursuivre. L'obtention de l'ID de la vidéo se fait selon l'utilisation de base, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

À ce moment, vous pouvez voir que l'ID de la vidéo est :

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Remarque : le `video_id` de la vidéo ici est l'ID de la vidéo générée. Si vous ne savez pas comment générer une vidéo, vous pouvez vous référer à l'utilisation de base ci-dessus pour générer une vidéo.

Ensuite, nous devons obligatoirement remplir le prompt à étendre à l'étape suivante afin de personnaliser la vidéo générée, et vous pouvez spécifier le contenu suivant :

- `model` : le modèle de génération vidéo, comprenant principalement les modèles `kling-v1`, `kling-v1-5` et `kling-v1-6`.
- `mode` : le mode de génération vidéo, les valeurs disponibles étant le mode standard `std`, le mode rapide `pro` et le mode 4K natif `4k` (uniquement pris en charge par `kling-v3` et `kling-v3-omni`, incompatible avec le contrôle des mouvements de caméra).
- `duration` : la durée vidéo de cette tâche de génération vidéo, comprenant principalement 5 s et 10 s.
- `start_image_url` : lorsque le comportement de génération de vidéo à partir d'image `image2video` est sélectionné, le lien de l'image de référence de la première image à téléverser est obligatoire.
- `prompt` : le prompt.

L'exemple de remplissage est le suivant :

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Une fois le remplissage terminé, le code suivant est automatiquement généré :

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Le code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Cliquez sur Exécuter, vous constaterez qu'un résultat est obtenu, comme suit :

On peut constater que le contenu du résultat est cohérent avec celui ci-dessus, ce qui permet de réaliser la fonctionnalité d'extension vidéo.

## Référence universelle Omni (montage vidéo / vidéo de référence / référence multi-images)

`kling-o1` et `kling-v3-omni` sont deux modèles indépendants, tous deux prenant en charge la capacité de « référence universelle ». Sur la base de la génération de vidéo à partir de texte (`action=text2video`), vous pouvez également transmettre des images de référence ou des vidéos de référence afin de réaliser la **référence multi-images, la vidéo de référence ainsi que le montage direct de vidéos existantes**.

**Convention principale** : les ressources de référence doivent être citées dans le `prompt` sous la forme `&lt;&lt;<image_1>>>`, `&lt;&lt;<video_1>>>` (la numérotation commence à 1) afin de référencer la ressource à la position correspondante dans `image_list` / `video_list`, pour que le modèle applique ces références. Si vous transmettez uniquement les ressources sans les citer dans le prompt, elles seront ignorées.

> Consigne de sécurité : l'API actuelle ne donne pas accès à `element_list`. Les ID de la Kling Element Library ne sont pas isolés par locataire ; avant la fourniture d'une API Element Management avec isolation par locataire, veuillez utiliser `image_list` pour transmettre les images de référence du sujet.

Les requêtes Omni ne prennent pas en charge `negative_prompt`, `cfg_scale` ou `camera_control`, et ne peuvent pas non plus utiliser `mode=4k`. Lorsqu'une vidéo de référence est incluse, `generate_audio` doit être `false`.

### Vidéos de référence et montage vidéo (`video_list`)
`video_list` est utilisé pour transmettre des vidéos de référence, ce qui constitue le scénario le plus courant de cette fonctionnalité. Les champs des éléments du tableau sont les suivants :

- `video_url` : lien de la vidéo de référence, ne peut pas être vide. Au maximum 1 vidéo MP4/MOV, taille de fichier ≤200MB, fréquence d’images 24–60fps. `kling-o1` exige une durée de 3–10 secondes, une largeur et une hauteur de 700–2160px chacune ; `kling-v3-omni` exige une durée de 3–15.5 secondes, une largeur et une hauteur de 700–4553px chacune, un total de pixels ≤8,294,400, et un ratio largeur/hauteur de 0.4–2.
- `refer_type` : type de référence, peut être `base` (par défaut, **vidéo de base à éditer**, c’est-à-dire « éditer directement la vidéo », permettant d’ajouter/supprimer/modifier des éléments, de changer la composition, le style, les couleurs, la météo, etc.) ou `feature` (**référence de caractéristiques**, référencer son style / ses mouvements de caméra / continuer le plan suivant).
- `keep_original_sound` : indique s’il faut conserver l’audio de la vidéo originale, peut être `yes` (conserver) ou `no` (supprimer).

> Remarque : lorsqu’une vidéo de référence est présente, `generate_audio` doit être `false`. Une vidéo avec `refer_type=base` ne peut plus spécifier une première image / une dernière image.

L’exemple CURL suivant montre comment éditer une vidéo existante (transformer la vidéo en style anime) :

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Référence multi-images (`image_list`)

`image_list` est utilisé pour transmettre des images de référence (éléments / scènes / styles, etc.). Les champs des éléments du tableau sont les suivants :

- `image_url` : lien de l’image de référence, ne peut pas être vide. Exigences : format .jpg/.jpeg/.png ; taille de fichier ≤10MB ; côté le plus court ≥300px ; ratio largeur/hauteur 1:2.5 ~ 2.5:1.
- `type` : facultatif. Lorsqu’il n’est pas transmis, il est utilisé comme image de référence pure ; lorsque `first_frame` / `end_frame` est transmis, il est respectivement utilisé comme première image / dernière image (équivalent à `start_image_url` / `end_image_url`).

Lors de l’utilisation, il faut les référencer dans `prompt` avec `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Limite de quantité : lorsqu’il n’existe pas de vidéo de référence, les images de référence ≤ 7 ; lorsqu’une vidéo de référence existe, les images de référence ≤ 4. Lorsqu’on transmet uniquement une première / dernière image, on peut aussi utiliser directement `start_image_url` / `end_image_url`, mais la dernière image doit être utilisée avec la première image.

> Remarque : si `start_image_url` / `end_image_url` et `image_list` sont transmis simultanément, les premières / dernières images seront placées avant `image_list`, ce qui peut affecter la relation de correspondance des indices `&lt;&lt;<image_N>>>`. Il est recommandé de choisir l’une des deux options : lorsqu’une première / dernière image est nécessaire, spécifiez directement `type` dans `image_list`, ne le mélangez pas avec `start_image_url` / `end_image_url`.

Exemple CURL de génération de vidéo avec référence multi-images :

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Rappel asynchrone

Étant donné que le temps de génération de Kling Videos Generation API est relativement long, environ 1 à 2 minutes, si l’API ne répond pas pendant longtemps, la requête HTTP maintiendra continuellement la connexion, entraînant une consommation supplémentaire de ressources système ; cette API fournit donc également la prise en charge des rappels asynchrones.

Le processus global est le suivant : lorsque le client lance une requête, il spécifie en plus un champ `callback_url` ; après que le client a lancé une requête API, l’API renvoie immédiatement un résultat incluant un champ `task_id`, représentant l’ID de la tâche actuelle. Une fois la tâche terminée, le résultat de la génération de vidéo sera envoyé sous forme de POST JSON au `callback_url` spécifié par le client, incluant également le champ `task_id`, afin que les résultats de la tâche puissent être associés via l’ID.

Ci-dessous, nous allons comprendre comment procéder concrètement à travers un exemple.

Tout d’abord, un rappel Webhook est un service capable de recevoir des requêtes HTTP ; le développeur doit le remplacer par l’URL de son propre serveur HTTP. Ici, afin de faciliter la démonstration, nous utilisons un site d’exemple Webhook public https://webhook.site/ ; ouvrez ce site pour obtenir une URL Webhook, comme montré sur l’image :

![](https://cdn.acedata.cloud/tbcnai.png)

Copiez cette URL, elle peut alors être utilisée comme Webhook ; l’exemple ici est `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

Ensuite, nous pouvons définir le champ `callback_url` sur l’URL Webhook ci-dessus, tout en renseignant les paramètres correspondants ; le contenu spécifique est montré sur l’image :

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Cliquez sur exécuter, vous pouvez constater qu’un résultat est obtenu immédiatement, comme suit :

```

}
```

Après un court instant, nous pouvons observer le résultat de la génération de vidéo sur `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, comme montré sur l’image :

![](https://cdn.acedata.cloud/zv5u2q.png)

Le contenu est le suivant :

```json
    "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
    "duration": "5.1",
```

## Gestion des erreurs

Lors de l’appel de l’API, en cas d’erreur, l’API renverra le code et les informations d’erreur correspondants. Par exemple :

- `400 token_mismatched` : Requête incorrecte, possiblement en raison de paramètres manquants ou invalides.
- `400 api_not_implemented` : Requête incorrecte, possiblement en raison de paramètres manquants ou invalides.
- `401 invalid_token` : Non autorisé, jeton d’autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, une erreur est survenue sur le serveur.
### Exemple de réponse d’erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
```
