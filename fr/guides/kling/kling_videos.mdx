Cet article présentera un guide d'intégration de l'API Kling Videos Generation, qui permet de générer des vidéos officielles Kling en saisissant des paramètres personnalisés.

## Processus de demande

Pour utiliser l'API Kling Videos Generation, obtenez d'abord votre API Token dans la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) et conservez-le pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d'appeler tous les services de la plateforme, sans avoir besoin d'en demander un séparément pour chaque service.** Lors de la première demande, un quota gratuit est offert pour une utilisation d'essai gratuite ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Utilisation de base

Commençons par comprendre le mode d'utilisation de base : saisissez l'invite `prompt`, l'action de génération `action`, l'image de référence de la première image `start_image_url` ainsi que le modèle `model`, et vous pourrez obtenir le résultat traité. Tout d'abord, vous devez simplement transmettre un champ `action`, dont la valeur est `text2video`. Il comprend principalement trois actions : texte vers vidéo (`text2video`), image vers vidéo (`image2video`) et extension de vidéo (`extend`). Nous devons ensuite saisir le modèle `model` ; actuellement, les principaux modèles sont `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`. Le contenu spécifique est le suivant :

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Vous pouvez voir qu'ici nous avons défini les Request Headers, notamment :

- `accept` : le format de réponse que vous souhaitez recevoir ; renseignez ici `application/json`, c'est-à-dire le format JSON.
- `authorization` : la clé pour appeler l'API, qui peut être directement sélectionnée dans une liste déroulante après la demande.

Les Request Body sont également définis, notamment :

- `model` : le modèle de génération vidéo ; les principaux modèles sont `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode` : le mode de génération vidéo ; les valeurs disponibles sont le mode standard `std`, le mode rapide `pro` et le mode natif 4K `4k`. Parmi eux, `4k` prend uniquement en charge `kling-v3` et `kling-v3-omni`, et n'est pas compatible avec `camera_control` (contrôle des mouvements de caméra).
- `action` : l'action de cette tâche de génération vidéo ; elle comprend principalement trois actions : texte vers vidéo (`text2video`), image vers vidéo (`image2video`) et extension de vidéo (`extend`).
- `start_image_url` : le lien de l'image de référence de la première image qui doit être téléchargée lorsque l'action image vers vidéo `image2video` est sélectionnée.
- `end_image_url` : facultatif pour la génération image vers vidéo, permet de spécifier l'image finale.
- `duration` : la durée de la vidéo, en secondes. `kling-v3` et `kling-v3-omni` prennent en charge des durées entières de 3 à 15 secondes ; `kling-o1` prend uniquement en charge 5 secondes ; les autres modèles prennent en charge 5 ou 10 secondes.
- `generate_audio` : indique s'il faut générer simultanément l'audio ; facultatif, valeur booléenne. Pris en charge par `kling-v3`, `kling-v3-omni` ainsi que `kling-v2-6` (uniquement en mode pro). La valeur par défaut est `false`.
- `aspect_ratio` : le rapport largeur-hauteur de la vidéo ; facultatif, prend en charge `16:9`, `9:16`, `1:1`, avec `16:9` par défaut.
- `cfg_scale` : intensité de pertinence, plage [0,1] ; plus la valeur est élevée, plus le résultat correspond à l'invite.
- `camera_control` : facultatif, paramètres d'objet permettant de contrôler le mouvement de la caméra ; prend en charge les préréglages type/simple ainsi que des configurations telles que horizontal, vertical, pan, tilt, roll, zoom.
- `negative_prompt` : facultatif, invite négative indiquant les éléments indésirables, 200 caractères maximum.
- `image_list` : liste d'images de référence Omni, applicable aux modèles `kling-o1` et `kling-v3-omni` ; voir ci-dessous « Référence Omni tout-en-un » pour l'utilisation.
- `video_list` : liste de vidéos de référence Omni (prend en charge l'édition vidéo), applicable aux modèles `kling-o1` et `kling-v3-omni` ; voir ci-dessous « Référence Omni tout-en-un » pour l'utilisation.
- `prompt` : l'invite.
- `callback_url` : l'URL nécessitant un résultat de rappel.
- `async` : facultatif ; lorsqu'il est défini sur `true`, l'interface renvoie immédiatement `task_id`, sans qu'il soit nécessaire de fournir `callback_url`, puis le résultat est récupéré par interrogation via l'interface de requête de tâche correspondante.

Après la sélection, vous pouvez constater que le code correspondant est également généré à droite, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Cliquez sur le bouton « Try » pour effectuer un test. Comme illustré ci-dessus, nous obtenons ici le résultat suivant :


- `video_id`, l'ID vidéo de la tâche de génération vidéo à ce moment.
- `video_url`, le lien vidéo de la tâche de génération vidéo à ce moment.
- `duration`, la durée du lien vidéo de la tâche de génération vidéo à ce moment.
- `state`, l'état de la tâche de génération vidéo à ce moment.

Vous pouvez voir que nous avons obtenu des informations vidéo satisfaisantes ; il nous suffit de récupérer la vidéo Kling générée à partir de l'adresse du lien vidéo `data` dans le résultat.

De plus, si vous souhaitez générer le code d'intégration correspondant, vous pouvez le copier directement. Par exemple, le code CURL est le suivant :

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Matrice des capacités des modèles

### Tarification des vidéos de référence O1 et Omni

La tarification de `kling-o1` dépend du mode et de la présence ou non de `video_list`. Voici les prix pour une vidéo finale de 5 secondes :

| Mode  | Sans vidéo de référence | Avec vidéo de référence |
| --- | ------------: | ------------: |
| std | 4.005 Credits | 6.010 Credits |
| pro | 5.340 Credits | 8.010 Credits |
Les requêtes réussies de `kling-o1` et `kling-v3-omni` avec vidéo de référence sont facturées selon les secondes facturables : std à **1.202 Credits/seconde**, pro à **1.602 Credits/seconde**. Par exemple, générer 5 secondes en mode std coûte 6.010 Credits. Omettre `video_list` ne déclenche pas le niveau vidéo de référence ; `image_list`, ainsi que les images de première et dernière image, ne sont pas non plus des vidéos de référence. Les vidéos de référence ne peuvent pas être utilisées en même temps que `generate_audio=true`.

Le montage vidéo avec `refer_type=base` (par défaut) peut suivre la durée de la vidéo de référence, et est finalement facturé selon la durée réelle de la vidéo finale, arrondie à la seconde entière : par exemple, 5.708 secondes sont facturées comme 6 secondes, 5.041 secondes comme 5 secondes. `refer_type=feature` utilise le `duration` demandé. `usage.reference_video_seconds` dans la réponse indique les secondes finales facturables ; le prix estimé lors de la requête peut différer du débit final.

La prise en charge des paramètres varie considérablement selon les modèles. La matrice suivante est compilée à partir de la [documentation officielle Kling video models](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels). Avant l'appel, veuillez d'abord vérifier si la combinaison actuelle `model` / `mode` / `duration` prend en charge la fonctionnalité dont vous avez besoin, sinon des erreurs telles que `model/mode/duration(...) is not supported with image_tail` seront renvoyées.

| Modèle              | Mode             | `end_image_url`（première et dernière image） | `generate_audio`（audio） | `camera_control`（mouvement de caméra） | Remarques                                           |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ uniquement `duration=5`     | ❌                    | ✅ uniquement `duration=5`     | `extend` ne prend pas en charge `negative_prompt` ni `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | Vidéo à partir de plusieurs images, tous les modes `extend` disponibles                         |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Mode unique, uniquement `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Mode unique, uniquement `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | Le seul modèle non-v3 prenant simultanément en charge l'audio                             |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | Plage de `duration` de 3 à 15 secondes                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | Le mode 4K est incompatible avec le mouvement de caméra                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Prend uniquement en charge `duration=5`                             |

Remarques :

- `mode=4k` est pris en charge uniquement par `kling-v3` et `kling-v3-omni` ; il est également mutuellement exclusif avec `camera_control`（mouvement de caméra）.
- `end_image_url` ne peut être utilisé avec `start_image_url` que lorsque `action=image2video`. Transmettre uniquement `end_image_url` (sans `start_image_url`) sera refusé.
- `kling-v3` / `kling-v3-omni` acceptent n'importe quelle `duration` entière de 3 à 15 secondes ; `kling-o1` accepte uniquement 5 ; les autres modèles acceptent uniquement 5 ou 10.
- `generate_audio` est défini sur `false` par défaut. Seuls `kling-v3`, `kling-v3-omni` et `kling-v2-6` (mode pro) le prennent en charge.

## Fonctionnalité d'extension vidéo

Si vous souhaitez continuer à générer une vidéo Kling déjà générée, vous pouvez définir le paramètre `action` sur `extend`, et vous devez saisir l'ID de la vidéo à continuer de générer. L'obtention de l'ID de la vidéo se fait selon l'utilisation de base, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

Vous pouvez alors voir que l'ID de la vidéo est :

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Notez que le `video_id` dans cette vidéo est l'ID de la vidéo après génération. Si vous ne savez pas comment générer une vidéo, vous pouvez vous référer à l'utilisation de base ci-dessus pour générer une vidéo.

Ensuite, nous devons obligatoirement renseigner le prompt à étendre à l'étape suivante pour personnaliser la vidéo générée, et vous pouvez spécifier le contenu suivant :

- `model` : le modèle qui génère la vidéo, principalement les modèles `kling-v1`, `kling-v1-5` et `kling-v1-6`.
- `mode` : le mode de génération de vidéo, les valeurs possibles sont le mode standard `std`, le mode rapide `pro` et le mode 4K natif `4k` (pris en charge uniquement par `kling-v3` et `kling-v3-omni`, incompatible avec le contrôle du mouvement de caméra).
- `duration` : la durée vidéo de cette tâche de génération vidéo, comprenant principalement 5 s et 10 s.
- `start_image_url` : lorsque le comportement de génération vidéo à partir d'image `image2video` est sélectionné, le lien de l'image de référence de première image qui doit être téléversée.
- `prompt` : le prompt.

L'exemple de remplissage est le suivant :

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Après avoir rempli, le code suivant est généré automatiquement :

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Le code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Référence Omni tout-en-un (édition vidéo / vidéo de référence / référence multi-images)

`kling-o1` et `kling-v3-omni` sont deux modèles indépendants, et tous deux prennent en charge la capacité de « référence tout-en-un ». Sur la base de la génération de vidéo à partir de texte (`action=text2video`), il est possible de transmettre en supplément des images de référence ou des vidéos de référence, afin de réaliser la **référence multi-images, la vidéo de référence ainsi que l’édition directe de vidéos existantes**.

**Convention principale** : les matériaux de référence doivent être cités dans `prompt` sous la forme `&lt;&lt;<image_1>>>`, `&lt;&lt;<video_1>>>` (la numérotation commence à 1), afin de référencer les matériaux à la position correspondante dans `image_list` / `video_list`, sinon le modèle appliquera ces références. Si seuls les matériaux sont transmis sans être cités dans le prompt, ils seront ignorés.

> Note de sécurité : l’API actuelle n’ouvre pas `element_list`. Les ID de Kling Element Library ne sont pas isolés par locataire ; avant de fournir une Element Management API avec isolation par locataire, veuillez utiliser `image_list` pour transmettre les images de référence des sujets.

Les requêtes Omni ne prennent pas en charge `negative_prompt`, `cfg_scale` ou `camera_control`, et ne peuvent pas non plus utiliser `mode=4k`. Lorsqu’une vidéo de référence est incluse, `generate_audio` doit être défini sur `false`.

### Vidéo de référence et édition vidéo (`video_list`)

`video_list` est utilisé pour transmettre des vidéos de référence, ce qui constitue le scénario le plus courant de cette capacité. Les champs des éléments du tableau sont les suivants :

- `video_url` : lien de la vidéo de référence, ne peut pas être vide. Au maximum 1 vidéo MP4/MOV, taille de fichier ≤200MB, fréquence d’images 24–60fps. `kling-o1` exige une durée de 3–10 secondes, une largeur et une hauteur de 700–2160px chacune ; `kling-v3-omni` exige une durée de 3–15.5 secondes, une largeur et une hauteur de 700–4553px chacune, un total de pixels ≤8,294,400, et un rapport largeur-hauteur de 0.4–2.
- `refer_type` : type de référence, peut être `base` (par défaut, **vidéo de base à éditer**, c’est-à-dire « éditer directement la vidéo », permettant d’ajouter, supprimer/modifier des éléments, modifier la composition, changer le style, les couleurs, la météo, etc.) ou `feature` (**référence de caractéristiques**, référence de son style / de ses mouvements de caméra / continuation de la prise suivante).
- `keep_original_sound` : conserver ou non l’audio de la vidéo d’origine, peut être `yes` (conserver) ou `no` (supprimer).

> Attention : lorsqu’une vidéo de référence est présente, `generate_audio` doit être défini sur `false`. Une vidéo avec `refer_type=base` ne peut plus spécifier d’image de début / de fin.

Voici un exemple CURL pour éditer une vidéo existante (transformer la vidéo en style anime) :

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Référence multi-images (`image_list`)

`image_list` est utilisé pour transmettre des images de référence (éléments / scènes / styles, etc.). Les champs des éléments du tableau sont les suivants :

- `image_url` : lien de l’image de référence, ne peut pas être vide. Exigences : format .jpg/.jpeg/.png ; taille de fichier ≤10MB ; côté le plus court ≥300px ; rapport largeur-hauteur de 1:2.5 à 2.5:1.
- `type` : facultatif. En l’absence de transmission, il est utilisé comme simple image de référence ; lorsqu’il est transmis comme `first_frame` / `end_frame`, il sert respectivement d’image de début / de fin (équivalent à `start_image_url` / `end_image_url`).

Lors de l’utilisation, il faut citer `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>` dans `prompt`. Limites de quantité : en l’absence de vidéo de référence, les images de référence ≤ 7 ; en présence d’une vidéo de référence, les images de référence ≤ 4. Lorsque seules l’image de début / de fin sont transmises, il est également possible d’utiliser directement `start_image_url` / `end_image_url`, mais l’image de fin doit être utilisée avec l’image de début.

> Attention : si `start_image_url` / `end_image_url` et `image_list` sont transmis en même temps, les images de début / de fin seront placées avant `image_list`, ce qui peut affecter la correspondance de la numérotation de `&lt;&lt;<image_N>>>`. Il est recommandé de choisir l’une des deux méthodes : lorsqu’une image de début / de fin est nécessaire, spécifiez directement `type` dans `image_list`, ne le mélangez pas avec `start_image_url` / `end_image_url`.

Exemple CURL de génération de vidéo avec référence multi-images :

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Rappel asynchrone

Étant donné que le temps de génération de Kling Videos Generation API est relativement long, environ 1 à 2 minutes, si l’API ne répond pas pendant longtemps, la requête HTTP maintiendra continuellement la connexion, entraînant une consommation supplémentaire de ressources système. Cette API fournit donc également la prise en charge des rappels asynchrones.

Le processus global est le suivant : lorsque le client lance une requête, il spécifie en supplément un champ `callback_url`. Après que le client a lancé une requête API, l’API renverra immédiatement un résultat, contenant les informations du champ `task_id`, qui représente l’ID de la tâche actuelle. Une fois la tâche terminée, le résultat de la génération de vidéo sera envoyé sous forme de POST JSON au `callback_url` spécifié par le client, contenant également le champ `task_id`, afin que le résultat de la tâche puisse être associé via l’ID.

Ci-dessous, nous allons comprendre le fonctionnement concret à travers un exemple.

Tout d’abord, le rappel Webhook est un service capable de recevoir des requêtes HTTP ; les développeurs doivent le remplacer par l’URL de leur propre serveur HTTP. Afin de faciliter la démonstration, un site d’exemple Webhook public https://webhook.site/ est utilisé ici ; ouvrez ce site pour obtenir une URL Webhook, comme illustré :

![](https://cdn.acedata.cloud/tbcnai.png)

Copiez cette URL pour pouvoir l’utiliser comme Webhook ; l’exemple ici est `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

## Gestion des erreurs

Lors de l'appel de l'API, en cas d'erreur, l'API renverra le code d'erreur et les informations correspondantes. Par exemple :

- `400 token_mismatched` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `400 api_not_implemented` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `401 invalid_token` : Non autorisé, jeton d'autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d'erreur

```json
{

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Nous espérons que ce document vous aidera à mieux intégrer et utiliser cette API. Pour toute question, veuillez contacter notre équipe d'assistance technique à tout moment.

### Kling 3.0 Turbo

`model="kling-v3-turbo"` prend en charge la génération de vidéos à partir de texte et la génération de vidéos à partir d'une image de première image, pour des durées entières de 3 à 15 secondes. `mode="std"` produit du 720p, et `mode="pro"` produit du 1080p. Ce modèle intègre un audio natif et ne fournit pas d'option pour le désactiver ; omettez `generate_audio` ou définissez-le sur `true`. Ce modèle ne prend pas en charge l'image finale, les objets de mouvement de caméra, les invites négatives indépendantes ou `cfg_scale`. Veuillez décrire directement dans `prompt` le contenu souhaité ou à éviter.

### Vidéos à plans multiples

`kling-v3` et `kling-v3-omni` prennent en charge `multi_shot=true`. `shot_type="intelligence"` génère automatiquement le découpage des plans en fonction de `prompt` ; `shot_type="customize"` fournit 1 à 6 plans via `multi_prompt`, chaque élément contenant un `index` commençant à 1 et augmentant consécutivement, un `prompt` de 512 caractères maximum et une `duration` entière d'au moins 1 seconde. La somme des durées de tous les plans doit être égale à la `duration` totale. Les plans personnalisés n'utilisent pas le `prompt` global. Les vidéos à plans multiples sont facturées selon le modèle sélectionné, la qualité d'image, la configuration audio et la durée totale.
