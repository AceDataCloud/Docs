La fonction principale de l’API Kling Tasks est de consulter l’état d’exécution d’une tâche en saisissant l’ID de tâche généré par l’API Kling Videos Generation.

Ce document présentera en détail les instructions d’intégration de l’API Kling Tasks, afin de vous aider à intégrer facilement et à exploiter pleinement les puissantes fonctionnalités de cette API. Grâce à l’API Kling Tasks, vous pouvez facilement consulter l’état d’exécution des tâches de l’API Kling Videos Generation.

## Processus de demande

Pour utiliser l’API Kling Videos Generation, accédez d’abord à la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre jeton API, à conserver pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter, puis vous reviendrez automatiquement sur la page actuelle une fois terminé.

**Un seul jeton API permet d’appeler tous les services de la plateforme, sans qu’il soit nécessaire d’en demander un séparément pour chaque service.** Lors de votre première demande, des crédits gratuits vous seront offerts afin de vous permettre d’essayer gratuitement ; lorsque les crédits sont insuffisants, vous pouvez recharger votre solde général dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Exemple de requête

L’API Kling Tasks peut être utilisée pour consulter les résultats de l’API Kling Videos Generation. Pour savoir comment utiliser l’API Kling Videos Generation, veuillez consulter la documentation [Kling Videos Generation API ](https://platform.acedata.cloud/documents/kling-videos)。

Nous prenons comme exemple un ID de tâche renvoyé par le service API Kling Videos Generation, afin de montrer comment utiliser cette API. Supposons que nous ayons un ID de tâche : 20068983-0cc9-4c6a-aeb6-9c6a3c668be0, nous allons ensuite montrer comment en transmettant un ID de tâche.

### Définir les en-têtes et le corps de la requête

Les **Request Headers** comprennent :

- `accept` : spécifie la réception des résultats de réponse au format JSON, ici renseignez `application/json`.
- `authorization` : la clé pour appeler l’API, qui peut être directement sélectionnée dans la liste déroulante après la demande.

Le **Request Body** comprend :

- `id` : l’ID de tâche téléversé.
- `action` : le mode d’opération sur la tâche.

La configuration est illustrée ci-dessous :

### Exemple de code

Vous pouvez constater que le code dans différents langages a déjà été généré automatiquement sur le côté droit de la page, comme illustré ci-dessous :

<p><img src="https://cdn.acedata.cloud/bsqh3i.png" width="500" className="m-auto" /></p>

Voici quelques exemples de code :

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Le résultat renvoyé comporte plusieurs champs : le champ request est le request body lors du lancement de la tâche, tandis que le champ response est le response body renvoyé après la fin de la tâche. La présentation des champs est la suivante.

- `id`, l’ID généré pour cette tâche vidéo, utilisé pour identifier de manière unique cette tâche de génération vidéo.
- `request`, les informations de requête dans la consultation de la tâche vidéo.
- `response`, les informations de retour dans la consultation de la tâche vidéo.
- `created_at`, l’heure de création de la tâche, horodatage Unix (secondes, flottant).
- `started_at`, l’heure de début d’exécution de la tâche, horodatage Unix (secondes, flottant).
- `finished_at`, l’heure de fin de la tâche, horodatage Unix (secondes, flottant). Ce champ n’est pas renvoyé lorsque la tâche n’est pas terminée.
- `elapsed`, la durée d’exécution de la tâche, en secondes (flottant, conservé à 3 décimales). Ce champ n’est pas renvoyé lorsque la tâche n’est pas terminée.

## Gestion des erreurs

Lors de l’appel de l’API, si une erreur survient, l’API renvoie le code et les informations d’erreur correspondants. Par exemple :

- `400 token_mismatched` : Requête incorrecte, possiblement en raison de paramètres manquants ou non valides.
- `400 api_not_implemented` : Requête incorrecte, possiblement en raison de paramètres manquants ou non valides.
- `401 invalid_token` : Non autorisé, jeton d’autorisation non valide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d’erreur

```json
{

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
