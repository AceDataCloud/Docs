Cet article présentera les instructions pour l'intégration de l'API Sora Videos Generation. Grâce à cette API, vous pouvez entrer des paramètres personnalisés pour générer des vidéos officielles de Sora. Cette API prend en charge deux modes de version :

- **Version 1 (mode classique)** : prend en charge `duration` (10/15/25 secondes), `orientation` (paysage/portrait), `size` (petite/grande définition), image de référence `image_urls`, lien **###** `character_url`, etc.
- **Version 2 (mode partenaire)** : prend en charge `seconds` (4/8/12 secondes), résolution au niveau des pixels `size` (comme 1280x720), image de référence `input_reference`, etc.

## Processus de demande

Pour utiliser l'API Sora Videos Generation, commencez par obtenir votre API Token sur le [tableau de bord Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour le garder en réserve.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter, après quoi vous serez automatiquement renvoyé à la page actuelle.

**Un seul API Token suffit pour appeler tous les services de la plateforme, il n'est pas nécessaire de demander un pour chaque service.** La première demande vous donnera un quota gratuit pour une expérience sans frais ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans le [tableau de bord](https://platform.acedata.cloud/console/coin).

## Utilisation de base (Version 1)

Tout d'abord, comprenez la méthode d'utilisation de base de la Version 1, qui consiste à entrer le mot-clé `prompt`, un tableau de liens d'images de référence `image_urls` et le modèle `model`, pour obtenir le résultat traité, le contenu spécifique est comme suit :

<p><img src="https://cdn.acedata.cloud/h8dyz3.png" width="500" className="m-auto" /></p>

Nous pouvons voir ici que nous avons défini les en-têtes de requête, y compris :

- `accept` : le format de réponse souhaité, ici rempli avec `application/json`, c'est-à-dire au format JSON.
- `authorization` : la clé pour appeler l'API, que vous pouvez sélectionner directement après la demande.

De plus, nous avons défini le corps de la requête, y compris :

- `model` : le modèle pour générer la vidéo, prenant en charge `sora-2` (mode standard) et `sora-2-pro` (mode haute définition). Le `sora-2-pro` peut prendre en charge une `duration` de 25 secondes, tandis que le `sora-2` ne prend en charge que 10 et 15 secondes.
- `size` : la clarté de la vidéo, `small` pour la clarté standard, `large` pour la clarté HD (uniquement Version 1).
- `duration` : la durée de la vidéo, prenant en charge 10, 15, 25 secondes, dont 25 secondes uniquement prises en charge par `sora-2-pro` (uniquement Version 1).
- `orientation` : l'orientation de l'image, prenant en charge `landscape` (paysage), `portrait` (portrait) (uniquement Version 1).
- `image_urls` : tableau de liens d'images de référence, utilisé pour générer des vidéos (uniquement Version 1).
- `character_url` : lien **###**, les vidéos ne peuvent pas contenir de vraies personnes (uniquement Version 1).
- `character_start`/`character_end` : secondes de début et de fin de l'apparition du personnage, avec une plage de différence de 1 à 3 secondes (uniquement Version 1).
- `prompt` : mot-clé (obligatoire).
- `callback_url` : URL pour le retour asynchrone des résultats.
- `async` : optionnel, si défini sur `true`, l'interface renvoie immédiatement `task_id`, sans avoir besoin de fournir `callback_url`, puis vous pouvez interroger le résultat via l'interface de requête de tâche correspondante.
- `version` : version de l'API, `"1.0"` (par défaut) ou `"2.0"`.

## Tâche de génération de vidéo à partir d'images (Version 1)

Si vous souhaitez effectuer une tâche de génération de vidéo à partir d'images, le paramètre `image_urls` doit d'abord être passé avec des liens d'images de référence, vous pouvez spécifier le contenu suivant :

- `image_urls` : tableau de liens d'images de référence utilisés pour cette tâche de génération de vidéo. Notez qu'il ne faut pas transmettre de véritables images de personnes avec des visages, sinon cela pourrait entraîner l'échec de la tâche.

Exemple de saisie comme suit :

<p><img src="https://cdn.acedata.cloud/ch7x3t.png" width="500" className="m-auto" /></p>

Une fois rempli, le code suivant a été généré automatiquement :

<p><img src="https://cdn.acedata.cloud/z1ud8l.png" width="500" className="m-auto" /></p>

Le code correspondant :
```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "size": "large",
    "duration": 15,
    "orientation": "landscape",
    "prompt": "un chat courant sur la rivière",
    "model": "sora-2",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Mode Version 2.0

En plus du mode Version 1.0 ci-dessus, cette API prend également en charge le mode Version 2.0, qui peut être activé en définissant le paramètre `version` sur `"2.0"`. Le mode Version 2.0 prend en charge une durée vidéo plus courte et un contrôle de résolution au niveau des pixels.

### Description des paramètres de la Version 2.0

| Paramètre        | Type     | Obligatoire | Description                                             |
| ---------------- | -------- | ----------- | ------------------------------------------------------ |
| `version`        | string   | Oui         | Défini sur `"2.0"`                                    |
| `prompt`         | string   | Oui         | Mot-clé pour générer la vidéo                          |
| `model`          | string   | Non         | `sora-2` (par défaut) ou `sora-2-pro`                  |
| `duration`       | integer  | Non         | Durée de la vidéo : `4` (par défaut), `8`, `12` secondes |
| `size`           | string   | Non         | Résolution : `720x1280` (par défaut), `1280x720`, `1024x1792`, `1792x1024` |
| `image_urls`     | array    | Non         | Tableau d'URL d'images de référence, seule la première image est utilisée, la taille de l'image doit correspondre au paramètre `size` |
| `callback_url`   | string   | Non         | URL de rappel asynchrone                               |

### Exemple de base

```shell
curl -X POST 'https://api.acedata.cloud/sora/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "version": "2.0",
  "prompt": "un chat courant sur la rivière",
  "model": "sora-2",
  "duration": 8,
  "size": "1280x720"
}'
```

Le code Python correspondant :


### Utilisation d'images de référence (Version 2.0)

En mode Version 2.0, vous pouvez passer des images de référence via le paramètre `image_urls` pour guider la génération de vidéos (en utilisant uniquement la première image) :

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "version": "2.0",
    "prompt": "une personne marchant à travers un beau jardin",
    "model": "sora-2",
    "duration": 4,
    "size": "1280x720",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

> **Remarque** : La taille des images de référence doit correspondre au paramètre `size`, par exemple lorsque `size` est `1280x720`, la taille de l'image de référence doit être de 1280×720.

### Comparaison des paramètres Version 1.0 et Version 2.0

| Paramètre        | Version 1.0           | Version 2.0                             |
| ---------------- | --------------------- | --------------------------------------- |
| `version`        | 1.0 (par défaut)     | 2.0                                     |
| `prompt`         | ✅                     | ✅                                       |
| `model`          | ✅ sora-2 / sora-2-pro | ✅ sora-2 / sora-2-pro                   |
| `duration`       | ✅ 10/15/25 secondes   | ✅ 4/8/12 secondes                       |
| `orientation`    | ✅ paysage/portrait    | ❌                                       |
| `size`           | ✅ petit/grand         | ✅ 720x1280/1280x720/1024x1792/1792x1024 |
| `image_urls`     | ✅ plusieurs images de référence | ✅ uniquement la première image            |
| `character_url`  | ✅                     | ❌                                       |
| `callback_url`   | ✅                     | ✅                                       |

## Rappel asynchrone

Étant donné que le temps de génération de l'API Sora Videos Generation est relativement long, environ 1 à 2 minutes, si l'API ne répond pas pendant longtemps, la requête HTTP maintiendra la connexion, entraînant une consommation supplémentaire de ressources système. Par conséquent, cette API propose également un support de rappel asynchrone.

Le processus global est le suivant : lorsque le client initie une requête, il spécifie un champ `callback_url` supplémentaire. Après que le client ait lancé la requête API, l'API renverra immédiatement un résultat contenant un champ `task_id`, représentant l'ID de la tâche actuelle. Lorsque la tâche est terminée, le résultat de la vidéo générée sera envoyé au `callback_url` spécifié par le client sous forme de POST JSON, incluant également le champ `task_id`, permettant ainsi de relier les résultats de la tâche par ID.

Voyons comment procéder avec un exemple.

Tout d'abord, le rappel Webhook est un service capable de recevoir des requêtes HTTP, les développeurs doivent le remplacer par l'URL de leur propre serveur HTTP. ## Gestion des erreurs

Lors de l'appel de l'API, si une erreur se produit, l'API renverra le code d'erreur et les informations correspondantes. Par exemple :

- `400 token_mismatched` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `400 api_not_implemented` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `401 invalid_token` : Non autorisé, jeton d'autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de taux.
- `500 api_error` : Erreur interne du serveur, quelque chose s'est mal passé sur le serveur.

### Exemple de réponse d'erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "échec de la récupération"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
