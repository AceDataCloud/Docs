Ce document présente les instructions d’intégration de l’API de génération de vidéos Sora, qui permet de générer des vidéos officielles Sora en entrant des paramètres personnalisés. Cette API prend en charge deux modes de version :

- **Version 1 (mode classique)** : prend en charge les paramètres `duration` (10/15/25 secondes), `orientation` (paysage/portrait), `size` (small/large résolution), images de référence `image_urls`, lien de personnage `character_url`, etc.
- **Version 2 (mode partenaire)** : prend en charge les paramètres `seconds` (4/8/12 secondes), résolution en pixels `size` (par exemple 1280x720), images de référence `input_reference`, etc.

## Processus de demande

Pour utiliser l’API, vous devez d’abord demander le service correspondant sur la page [Sora Videos Generation API](https://platform.acedata.cloud/documents/99a24421-2e22-4028-8201-e19cb834b67e). Une fois sur la page, cliquez sur le bouton « Acquire », comme illustré ci-dessous :

![](https://cdn.acedata.cloud/q6ytrc.png)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inscrire et vous connecter. Après connexion, vous serez automatiquement ramené à cette page.

Lors de la première demande, un quota gratuit est offert, vous permettant d’utiliser l’API gratuitement.

## Utilisation de base (Version 1)

Commençons par comprendre l’utilisation de base de la Version 1, qui consiste à saisir un mot-clé `prompt`, un tableau de liens d’images de référence `image_urls` ainsi que le modèle `model`, pour obtenir le résultat traité. Voici les détails :

<p><img src="https://cdn.acedata.cloud/h8dyz3.png" width="500" className="m-auto" /></p>

On peut voir ici que nous avons configuré les en-têtes de la requête (Request Headers), incluant :

- `accept` : le format de réponse souhaité, ici `application/json` (format JSON).
- `authorization` : la clé d’API pour appeler l’API, sélectionnable directement après la demande.

Le corps de la requête (Request Body) comprend :

- `model` : le modèle de génération vidéo, supportant `sora-2` (mode standard) et `sora-2-pro` (mode HD). Le modèle `sora-2-pro` supporte la durée de 25 secondes, tandis que `sora-2` ne supporte que 10 et 15 secondes.
- `size` : la résolution vidéo, `small` pour standard, `large` pour HD (Version 1 uniquement).
- `duration` : durée de la vidéo, supporte 10, 15, 25 secondes, 25 secondes uniquement avec `sora-2-pro` (Version 1 uniquement).
- `orientation` : orientation de l’image, supporte `landscape` (paysage) et `portrait` (portrait) (Version 1 uniquement).
- `image_urls` : tableau de liens d’images de référence pour la génération vidéo à partir d’images (Version 1 uniquement).
- `character_url` : lien du personnage, la vidéo ne doit pas contenir de personnes réelles (Version 1 uniquement).
- `character_start` / `character_end` : secondes de début et de fin d’apparition du personnage, intervalle de 1 à 3 secondes (Version 1 uniquement).
- `prompt` : mot-clé (obligatoire).
- `callback_url` : URL de rappel asynchrone.
- `version` : version de l’API, `1` (par défaut) ou `2`.

```shell
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "size": "large",
  "duration": 15,
  "orientation": "landscape",
  "prompt": "cat running on the river",
  "model": "sora-2"
}'
```

## Tâche de génération vidéo à partir d’images (Version 1)

Pour effectuer une tâche de génération vidéo à partir d’images, le paramètre `image_urls` doit contenir les liens des images de référence, ce qui permet de spécifier :

- `image_urls` : tableau de liens des images de référence utilisées pour la génération vidéo. Attention, il ne faut pas fournir d’images de personnes réelles avec visage, sous peine d’échec de la tâche.

Exemple de remplissage :

<p><img src="https://cdn.acedata.cloud/ch7x3t.png" width="500" className="m-auto" /></p>

Le code généré automatiquement est le suivant :

<p><img src="https://cdn.acedata.cloud/z1ud8l.png" width="500" className="m-auto" /></p>

Code correspondant :

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "size": "large",
    "duration": 15,
    "orientation": "landscape",
    "prompt": "cat running on the river",
    "model": "sora-2",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Mode Version 2

En plus du mode Version 1, cette API prend également en charge le mode Version 2, activable en définissant le paramètre `version` à `2`. Le mode Version 2 supporte des durées plus courtes et un contrôle de résolution au niveau pixel.

### Description des paramètres Version 2

| Paramètre       | Type    | Obligatoire | Description                                         |
|-----------------|---------|-------------|-----------------------------------------------------|
| `version`       | integer | Oui         | Doit être défini à `2`                              |
| `prompt`        | string  | Oui         | Mot-clé pour la génération vidéo                    |
| `model`         | string  | Non         | `sora-2` (par défaut) ou `sora-2-pro`               |
| `duration`      | integer | Non         | Durée vidéo : `4` (par défaut), `8`, `12` secondes  |
| `size`          | string  | Non         | Résolution : `720x1280` (par défaut), `1280x720`, `1024x1792`, `1792x1024` |
| `image_urls`    | array   | Non         | Tableau d’URLs d’images de référence, seule la première est utilisée, la taille doit correspondre à `size` |
| `callback_url`  | string  | Non         | URL de rappel asynchrone                            |

### Exemple de base

```shell
curl -X POST 'https://api.acedata.cloud/sora/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "version": 2,
  "prompt": "cat running on the river",
  "model": "sora-2",
  "duration": 8,
  "size": "1280x720"
}'
```

Code Python correspondant :


### Utilisation d’images de référence (Version 2)

En mode Version 2, vous pouvez passer un paramètre `image_urls` avec une image de référence pour guider la génération vidéo (seule la première image est utilisée) :

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "version": 2,
    "prompt": "a person walking through a beautiful garden",
    "model": "sora-2",
    "duration": 4,
    "size": "1280x720",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

> **Remarque** : la taille de l’image de référence doit correspondre au paramètre `size`. Par exemple, si `size` est `1280x720`, l’image doit faire 1280×720 pixels.

### Comparaison des paramètres Version 1 et Version 2

| Paramètre       | Version 1           | Version 2                                          |
|-----------------|---------------------|---------------------------------------------------|
| `version`       | 1 (par défaut)       | 2                                                 |
| `prompt`        | ✅                   | ✅                                                 |
| `model`         | ✅ sora-2 / sora-2-pro | ✅ sora-2 / sora-2-pro                             |
| `duration`      | ✅ 10/15/25 secondes | ✅ 4/8/12 secondes                                 |
| `orientation`   | ✅ landscape/portrait| ❌                                                 |
| `size`          | ✅ small/large       | ✅ 720x1280/1280x720/1024x1792/1792x1024          |
| `image_urls`    | ✅ plusieurs images  | ✅ seule la première image                          |
| `character_url` | ✅                   | ❌                                                 |
| `callback_url`  | ✅                   | ✅                                                 |

## Rappel asynchrone (callback)

La génération de vidéos via l’API Sora Videos Generation prend environ 1 à 2 minutes. Si l’API ne répond pas rapidement, la connexion HTTP reste ouverte, ce qui peut entraîner une consommation excessive de ressources système. Pour cela, l’API propose un support de rappel asynchrone.

Le processus est le suivant : lors de la requête client, un champ `callback_url` est spécifié. L’API retourne immédiatement un résultat contenant un `task_id` représentant l’ID de la tâche. Une fois la tâche terminée, le résultat de la génération vidéo est envoyé en POST JSON à l’URL `callback_url` spécifiée, incluant également le champ `task_id` pour associer la réponse à la tâche.

Voici un exemple d’utilisation.

Un webhook est un service pouvant recevoir des requêtes HTTP. Le développeur doit remplacer l’URL par celle de son propre serveur HTTP. Pour la démonstration, nous utilisons un site public de webhook https://webhook.site/, qui génère une URL webhook, comme illustré :

![](https://cdn.acedata.cloud/cjjfly.png)

Copiez cette URL, par exemple `https://webhook.site/eb238c4f-da3b-47a5-a922-a93aa5405daa`.

Ensuite, définissez le champ `callback_url` avec cette URL webhook et remplissez les autres paramètres, comme illustré :

## Gestion des erreurs

Lors de l’appel à l’API, en cas d’erreur, l’API retourne un code et un message d’erreur. Par exemple :

- `400 token_mismatched` : requête incorrecte, paramètres manquants ou invalides.
- `400 api_not_implemented` : requête incorrecte, paramètres manquants ou invalides.
- `401 invalid_token` : non autorisé, token d’autorisation invalide ou manquant.
- `429 too_many_requests` : trop de requêtes, limite de fréquence dépassée.
- `500 api_error` : erreur interne du serveur.

### Exemple de réponse d’erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
