La principale fonction de l’API Hailuo Tasks est de consulter l’état d’exécution d’une tâche en saisissant l’ID de tâche généré par l’API Hailuo Videos Generation.

Ce document présente en détail les instructions d’intégration de l’API Hailuo Tasks, afin de vous aider à intégrer facilement et à exploiter pleinement les puissantes fonctionnalités de cette API. Grâce à l’API Hailuo Tasks, vous pouvez facilement interroger l’état d’exécution des tâches de l’API Hailuo Videos Generation.

## Processus de demande

Pour utiliser l’API Hailuo Videos Generation, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre token API, à conserver pour usage ultérieur.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et vous connecter, puis vous serez automatiquement ramené à la page actuelle.

**Un seul token API suffit pour appeler tous les services de la plateforme, il n’est pas nécessaire d’en demander un pour chaque service.** Une fois la première demande effectuée, un quota gratuit est offert pour une expérience gratuite ; en cas de quota insuffisant, vous pouvez recharger un solde universel dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Hailuo Videos Generation API →](https://platform.acedata.cloud/documents/hailuo-videos-integration)

## Exemple de requête

L’API Hailuo Tasks peut être utilisée pour interroger les résultats de l’API Hailuo Videos Generation. Pour savoir comment utiliser l’API Hailuo Videos Generation, veuillez consulter la documentation [Hailuo Videos Generation API](https://platform.acedata.cloud/documents/hailuo-videos-generation-integration).

Prenons un ID de tâche retourné par le service Hailuo Videos Generation API comme exemple pour démontrer comment utiliser cette API. Supposons que nous ayons un ID de tâche : 58cc618b-9639-4ee7-add2-d2fcf260d9a3, nous allons montrer comment interroger en transmettant cet ID de tâche.

### Configuration des en-têtes et du corps de la requête

**Les en-têtes de requête** comprennent :

- `accept` : spécifie que la réponse doit être au format JSON, ici `application/json`.
- `authorization` : la clé d’API pour appeler l’API, sélectionnable directement après la demande.

**Le corps de la requête** comprend :

- `id` : l’ID de la tâche à interroger.
- `action` : le type d’opération à effectuer sur la tâche.

La configuration est illustrée dans l’image suivante :

Extraits de code :

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/hailuo/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "58cc618b-9639-4ee7-add2-d2fcf260d9a3",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/hailuo/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "58cc618b-9639-4ee7-add2-d2fcf260d9a3",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Le résultat retourné contient plusieurs champs. Le champ `request` correspond au corps de la requête lors du lancement de la tâche, tandis que le champ `response` correspond au corps de la réponse une fois la tâche terminée. Description des champs :

- `id` : ID unique de la tâche vidéo générée, identifiant cette tâche de génération vidéo.
- `request` : informations de la requête dans la tâche vidéo.
- `response` : informations de la réponse dans la tâche vidéo.
- `created_at` : date de création de la tâche, timestamp Unix (secondes, flottant).
- `started_at` : date de début d’exécution de la tâche, timestamp Unix (secondes, flottant).
- `finished_at` : date de fin de la tâche, timestamp Unix (secondes, flottant). Ce champ n’est pas retourné si la tâche n’est pas terminée.
- `elapsed` : durée d’exécution de la tâche en secondes (flottant, 3 décimales). Ce champ n’est pas retourné si la tâche n’est pas terminée.

## Erreur de traitement

Lors de l'appel de l'API, si une erreur se produit, l'API renverra le code d'erreur et les informations correspondantes. Par exemple :

- `400 token_mismatched` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `400 api_not_implemented` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `401 invalid_token` : Non autorisé, jeton d'autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de taux.
- `500 api_error` : Erreur interne du serveur, quelque chose s'est mal passé sur le serveur.

### Exemple de réponse d'erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "échec de la récupération"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
