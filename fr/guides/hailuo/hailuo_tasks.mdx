La principale fonctionnalité de l'API Hailuo Tasks est de permettre la consultation de l'état d'exécution d'une tâche en entrant l'ID de tâche généré par l'API Hailuo Videos Generation.

Ce document détaillera les instructions d'intégration de l'API Hailuo Tasks, vous aidant à intégrer facilement et à tirer pleinement parti de la puissance de cette API. Grâce à l'API Hailuo Tasks, vous pouvez facilement interroger l'état d'exécution des tâches de l'API Hailuo Videos Generation.

## Processus de demande

Pour utiliser l'API Hailuo Tasks, vous devez d'abord vous rendre sur la page de demande [Hailuo Videos Generation API](https://platform.acedata.cloud/documents/hailuo-videos-integration) pour demander le service correspondant, puis copier l'ID de tâche de l'API Hailuo Videos Generation, comme indiqué sur l'image :

<p><img src="https://cdn.acedata.cloud/4f9d95.png" width="500" className="m-auto" /></p>

Enfin, accédez à la page de l'API Tasks [Hailuo Tasks API](https://platform.acedata.cloud/documents/hailuo-tasks) pour demander le service correspondant. Une fois sur la page, cliquez sur le bouton « Acquire », comme indiqué sur l'image :

![Page de demande](https://cdn.acedata.cloud/rci31i.png)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la [page de connexion](https://platform.acedata.cloud) vous invitant à vous inscrire et à vous connecter. Après vous être connecté ou inscrit, vous serez automatiquement renvoyé à la page actuelle.

Lors de votre première demande, un quota gratuit sera offert, vous permettant d'utiliser cette API gratuitement.

## Exemple de demande

L'API Hailuo Tasks peut être utilisée pour interroger les résultats de l'API Hailuo Videos Generation. Pour savoir comment utiliser l'API Hailuo Videos Generation, veuillez consulter le document [Hailuo Videos Generation API](https://platform.acedata.cloud/documents/hailuo-videos-generation-integration).

Prenons un exemple avec un ID de tâche retourné par le service Hailuo Videos Generation. Supposons que nous ayons un ID de tâche : 58cc618b-9639-4ee7-add2-d2fcf260d9a3, nous allons maintenant démontrer comment procéder en passant cet ID de tâche.

### Configuration des en-têtes de demande et du corps de la demande

**Request Headers** comprend :

- `accept` : spécifie que la réponse doit être au format JSON, ici rempli avec `application/json`.
- `authorization` : la clé d'API pour appeler l'API, que vous pouvez sélectionner directement après la demande.

**Request Body** comprend :

- `id` : l'ID de la tâche téléchargée.
- `action` : la méthode d'opération sur la tâche.

Configurez comme indiqué sur l'image ci-dessous :

<p><img src="https://cdn.acedata.cloud/e9btl5.png" width="500" className="m-auto" /></p>

### Exemple de code

Vous pouvez constater que divers langages de code ont déjà été générés automatiquement sur le côté droit de la page, comme indiqué sur l'image :

<p><img src="https://cdn.acedata.cloud/tfn261.png" width="500" className="m-auto" /></p>

Voici quelques exemples de code :

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/hailuo/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "58cc618b-9639-4ee7-add2-d2fcf260d9a3",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/hailuo/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "58cc618b-9639-4ee7-add2-d2fcf260d9a3",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Gestion des erreurs

Lors de l'appel de l'API, si une erreur se produit, l'API renverra le code d'erreur et les informations correspondantes. Par exemple :

- `400 token_mismatched` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `400 api_not_implemented` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `401 invalid_token` : Non autorisé, jeton d'autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de taux.
- `500 api_error` : Erreur interne du serveur, quelque chose s'est mal passé sur le serveur.

### Exemple de réponse d'erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "échec de la récupération"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
