Cet article présente une documentation sur l'intégration de l'API Veo Videos Generation, qui permet de générer des vidéos officielles de Veo en entrant des paramètres personnalisés.

## Processus de demande

Pour utiliser l'API Veo Videos Generation, commencez par obtenir votre token API sur le [tableau de bord Ace Data Cloud](https://platform.acedata.cloud/console/applications) et conservez-le pour référence.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter, après quoi vous serez automatiquement renvoyé à la page actuelle.

**Un seul token API suffit pour appeler tous les services de la plateforme, sans avoir besoin de demander un pour chaque service.** La première demande vous donnera un quota gratuit pour une expérience sans frais ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans le [tableau de bord](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Veo Videos Generation API →](https://platform.acedata.cloud/documents/veo-videos)

## Utilisation de base

Tout d'abord, comprenez la méthode d'utilisation de base, qui consiste à entrer le mot clé `prompt`, l'action `action`, le tableau d'images de référence `image_urls` et le modèle `model`, pour obtenir le résultat traité. Vous devez d'abord transmettre un champ `action`, dont la valeur est `text2video`, qui comprend principalement trois actions : vidéo générée par texte (`text2video`), vidéo générée par image (`image2video`), obtenir une vidéo en 1080p (`get1080p`). Ensuite, nous devons également entrer le modèle `model`, qui comprend principalement les modèles `veo31-fast`, `veo3`, `veo31`, `veo3-fast` et `veo31-fast-ingredients`, dont le contenu est le suivant :

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

Ici, nous avons configuré les en-têtes de requête, y compris :

- `accept` : le format de réponse souhaité, ici rempli comme `application/json`, c'est-à-dire au format JSON.
- `authorization` : la clé pour appeler l'API, que vous pouvez sélectionner directement après la demande.

Nous avons également configuré le corps de la requête, y compris :

- `model` : le modèle pour générer la vidéo, principalement `veo31-fast`, `veo3`, `veo31`, `veo3-fast` et `veo31-fast-ingredients`.
- `action` : l'action de la tâche de génération de vidéo, qui comprend principalement trois actions : vidéo générée par texte (`text2video`), vidéo générée par image (`image2video`), obtenir une vidéo en 1080p (`get1080p`).
- `image_urls` : lorsque vous choisissez l'action vidéo générée par image `image2video`, vous devez télécharger les liens d'images de référence. `veo31-fast-ingredients` nécessite jusqu'à 3 images (fusion multi-images), les autres modèles nécessitent jusqu'à 2 images (mode première et dernière image).
- `resolution` : choisissez la résolution de la vidéo générée, où le modèle veo31 prend en charge la résolution 4k, les autres modèles ne le prennent pas en charge, tous les modèles prennent en charge la résolution 1080p et gif, si cette valeur n'est pas transmise, la résolution par défaut est 720p, principalement divisée en : `1080p`, `gif`, `4k`.
- `prompt` : le mot clé.
- `callback_url` : l'URL pour recevoir les résultats.
- `async` : optionnel, si défini sur `true`, l'interface renvoie immédiatement `task_id`, sans avoir besoin de fournir `callback_url`, puis vous pouvez interroger le résultat via l'interface de requête de tâche correspondante.

### 📌 Résumé des modèles

| **Nom du modèle**                   | **Modes pris en charge**                          | **Règles d'entrée d'image**                        |
| -------------------------- | --------------------------------- | --------------------------------- |
| **veo3-fast**              | Vidéo générée par texte (sans image)<br />Mode vidéo générée par image (avec image)           | **1 image** → Mode première image<br />**2 images** → Mode première et dernière image |
| **veo31-fast**             | Vidéo générée par texte (sans image)<br />Mode vidéo générée par image (avec image)           | **1 image** → Mode première image<br />**2 images** → Mode première et dernière image |
| **veo31-fast-ingredients** | ❌ Vidéo générée par texte (non pris en charge)<br />✅ **Fusion multi-images obligatoire** (doit transmettre des images) | **1-3 images** → Mode fusion multi-images (maximum 3 images)        |
| **veo3**                   | Vidéo générée par texte (sans image)<br />Mode vidéo générée par image (avec image)           | **1 image** → Mode première image<br />**2 images** → Mode première et dernière image |
| **veo31**                  | Vidéo générée par texte (sans image)<br />Mode vidéo générée par image (avec image)           | **1 image** → Mode première image<br />**2 images** → Mode première et dernière image |

---

### 🔑 Règles clés

1. **Logique générale** :
   - **Pas d'entrée d'image** → Déclenche automatiquement le mode vidéo générée par texte.
   - **Entrée d'image** → Déclenche le mode vidéo générée par image (le comportement spécifique dépend du nombre d'images).
2. **Types de mode vidéo générée par image** :
   - **Mode première image** (1 image) : La première image est fixe à l'image d'entrée.
   - **Mode première et dernière image** (2 images) : La première et la dernière image sont fixes aux images d'entrée.
   - **Mode fusion multi-images** (1-3 images) : Seul `veo31-fast-ingredients` est pris en charge, fusionnant le contenu de plusieurs images pour générer une vidéo.
3. **Classification des modes** :

  - **Mode rapide** : `veo3-fast`, `veo31-fast`, `veo31-fast-ingredients`.
   - **Mode qualité** : `veo3`, `veo31` (génération de qualité supérieure).

---

### ⚠️ Remarques

- **Modèle nécessitant obligatoirement des images** : `veo31-fast-ingredients` doit recevoir des images (1-3 images), sinon il ne pourra pas fonctionner.
- **Limite de nombre d'images** :
  - `veo31-fast-ingredients` prend en charge **1-3 images** en entrée (mode fusion multi-images).
  - Les autres modèles prennent en charge au maximum **2 images** en entrée (mode première et dernière image).

## Fonctionnalité de génération de vidéo à partir d'images

Si vous souhaitez générer une vidéo à partir d'images de début et de fin, vous pouvez définir le paramètre `action` sur `image2video` et entrer un tableau d'URL d'images de début et de fin `image_urls`.

Ensuite, nous devons remplir les mots-clés d'invite nécessaires pour personnaliser la génération de la vidéo, ce qui nous permet de spécifier le contenu suivant :

- `model`：le modèle de génération de vidéo, principalement `veo31-fast`、`veo3`、`veo31`、`veo3-fast` et `veo31-fast-ingredients`.
- `image_urls`：lorsque l'on choisit l'action de génération de vidéo `image2video`, il est nécessaire de télécharger les liens d'images de référence.
- `prompt`：les mots-clés d'invite.

Exemple de remplissage :

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

Une fois rempli, le code généré automatiquement est comme suit :

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

Code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo31-fast",
    "prompt": "Laissez-le danser",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Callback asynchrone

Étant donné que le temps de génération de l'API Veo Videos Generation est relativement long, environ 1 à 2 minutes, si l'API ne répond pas pendant longtemps, la requête HTTP maintiendra la connexion, entraînant une consommation supplémentaire de ressources système. C'est pourquoi cette API propose également un support de callback asynchrone.

Le processus global est le suivant : lorsque le client initie une requête, il spécifie un champ `callback_url` supplémentaire. Après que le client ait lancé la requête API, l'API renverra immédiatement un résultat contenant un champ d'information `task_id`, représentant l'ID de la tâche actuelle. Lorsque la tâche est terminée, le résultat de la vidéo générée sera envoyé au `callback_url` spécifié par le client sous forme de POST JSON, incluant également le champ `task_id`, permettant ainsi de relier le résultat de la tâche par ID.

Voyons maintenant un exemple pour comprendre comment procéder concrètement.

Tout d'abord, le callback Webhook est un service capable de recevoir des requêtes HTTP, les développeurs doivent le remplacer par l'URL de leur propre serveur HTTP. ## Gestion des erreurs

Lors de l'appel de l'API, si une erreur se produit, l'API renverra le code d'erreur et les informations correspondantes. Par exemple :

- `400 token_mismatched` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `400 api_not_implemented` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `401 invalid_token` : Non autorisé, jeton d'autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de taux.
- `500 api_error` : Erreur interne du serveur, quelque chose s'est mal passé sur le serveur.

### Exemple de réponse d'erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
