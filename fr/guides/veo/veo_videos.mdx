Cet article présentera un guide d'intégration de l'API Veo Videos Generation, qui permet de générer des vidéos officielles Veo en saisissant des paramètres personnalisés.

## Processus de demande

Pour utiliser l'API Veo Videos Generation, obtenez d'abord votre API Token depuis la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications), et conservez-le pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter, puis vous reviendrez automatiquement sur cette page après finalisation.

**Un seul API Token permet d'appeler tous les services de la plateforme, sans devoir en demander un séparément pour chaque service.** La première demande offre un quota gratuit permettant un essai gratuit ; lorsque le quota est insuffisant, vous pouvez recharger le solde commun dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Veo Videos Generation API →](https://platform.acedata.cloud/documents/veo-videos)

## Utilisation de base

Commençons par comprendre la méthode d'utilisation de base : il suffit de saisir le prompt `prompt`, l'action de génération `action`, le tableau d'images de référence pour les première et dernière images `image_urls`, ainsi que le modèle `model`, pour obtenir le résultat traité. Il faut d'abord simplement transmettre un champ `action`, dont la valeur est `text2video` ; il comprend principalement trois actions : texte vers vidéo (`text2video`), image vers vidéo (`image2video`) et obtention d'une vidéo 1080p (`get1080p`). Ensuite, nous devons également saisir le modèle `model`. Les principaux modèles actuellement disponibles sont `veo31-fast`, `veo3`, `veo31`, `veo3-fast` et `veo31-fast-ingredients`. Le contenu détaillé est le suivant :

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

Vous pouvez voir que nous avons défini ici les Request Headers, notamment :

- `accept` : le format de résultat de réponse que vous souhaitez recevoir ; saisissez ici `application/json`, c'est-à-dire le format JSON.
- `authorization` : la clé pour appeler l'API, qui peut être directement sélectionnée dans la liste déroulante après la demande.

Nous avons également défini le Request Body, notamment :

- `model` : le modèle de génération de vidéos, principalement les modèles `veo31-fast`, `veo3`, `veo31`, `veo3-fast` et `veo31-fast-ingredients`.
- `action` : l'action de cette tâche de génération de vidéo, qui comprend principalement trois actions : texte vers vidéo (`text2video`), image vers vidéo (`image2video`) et obtention d'une vidéo 1080p (`get1080p`).
- `image_urls` : lorsque l'action image vers vidéo `image2video` est sélectionnée, les liens des images de référence à téléverser sont obligatoires. `veo31-fast-ingredients` accepte jusqu'à 3 images (fusion multi-images), tandis que les autres modèles acceptent jusqu'à 2 images (mode première et dernière images).
- `resolution` : sélectionnez la résolution de la vidéo générée. Parmi elles, le modèle veo31 prend en charge la résolution 4k, les autres modèles ne la prennent pas en charge ; tous les modèles prennent en charge les résolutions 1080p et gif. Si cette valeur n'est pas transmise, la résolution 720p est utilisée par défaut. Les principales options sont : `1080p`, `gif`, `4k`.
- `prompt` : le prompt.
- `callback_url` : l'URL nécessitant le résultat de rappel.
- `async` : optionnel ; lorsque défini sur `true`, l'interface renvoie immédiatement un `task_id`, sans nécessiter de fournir un `callback_url`, puis le résultat est obtenu par interrogation via l'interface de requête de tâche correspondante.

### 📌 Résumé des descriptions des modèles

| **Nom du modèle**                   | **Modes pris en charge**                          | **Règles d'entrée des images**                        |
| -------------------------- | --------------------------------- | --------------------------------- |
| **veo3-fast**              | Texte vers vidéo (sans image)<br />Mode image vers vidéo (avec image)           | **1 image** → Mode première image<br />**2 images** → Mode première et dernière images |
| **veo31-fast**             | Texte vers vidéo (sans image)<br />Mode image vers vidéo (avec image)           | **1 image** → Mode première image<br />**2 images** → Mode première et dernière images |
| **veo31-fast-ingredients** | ❌ Texte vers vidéo (non pris en charge)<br />✅ **Fusion multi-images obligatoire** (images obligatoires) | **1-3 images** → Mode de fusion multi-images (jusqu'à 3 images)        |
| **veo3**                   | Texte vers vidéo (sans image)<br />Mode image vers vidéo (avec image)           | **1 image** → Mode première image<br />**2 images** → Mode première et dernière images |
| **veo31**                  | Texte vers vidéo (sans image)<br />Mode image vers vidéo (avec image)           | **1 image** → Mode première image<br />**2 images** → Mode première et dernière images |

---

### 🔑 Description des règles clés

1. **Logique générale** :
   - **Aucune image en entrée** → Déclenche automatiquement le mode texte vers vidéo.
   - **Image(s) en entrée** → Déclenche le mode image vers vidéo (le comportement spécifique est déterminé par le nombre d'images).
2. **Types du mode image vers vidéo** :
   - **Mode première image** (1 image) : la première image est fixée comme l'image d'entrée.
   - **Mode première et dernière images** (2 images) : la première et la dernière image sont fixées comme les images d'entrée.
   - **Mode fusion multi-images** (1-3 images) : pris en charge uniquement par `veo31-fast-ingredients`, fusionne le contenu de plusieurs images pour générer une vidéo.
3. **Classification des modes** :

  - **Mode Fast** : `veo3-fast`, `veo31-fast`, `veo31-fast-ingredients`.
   - **Mode Quality** : `veo3`, `veo31` (qualité de génération supérieure).

---

### ⚠️ Précautions

- **Seul modèle exigeant obligatoirement des images** : `veo31-fast-ingredients` doit recevoir des images (1-3), sinon il ne peut pas fonctionner.
- **Limite du nombre d'images** :
  - `veo31-fast-ingredients` prend en charge l'entrée de **1-3 images** (mode fusion multi-images).
  - Les autres modèles prennent en charge jusqu'à **2 images** en entrée (mode première et dernière images).

## Fonction de génération vidéo à partir d’images

Si vous souhaitez générer une vidéo à partir des images de début et de fin, vous pouvez définir le paramètre `action` sur `image2video` et saisir le tableau de liens des images de début et de fin `image_urls`.

Ensuite, nous devons remplir les mots-clés à étendre à l’étape suivante afin de personnaliser la génération de vidéo, et nous pouvons spécifier le contenu suivant :

- `model` : le modèle de génération de vidéo, principalement `veo31-fast`, `veo3`, `veo31`, `veo3-fast` et `veo31-fast-ingredients`.
- `image_urls` : lorsque le comportement de génération de vidéo à partir d’images `image2video` est sélectionné, les liens des images de référence à téléverser sont obligatoires.
- `prompt` : les mots-clés.

L’exemple de remplissage est le suivant :

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

Une fois le remplissage terminé, le code suivant est généré automatiquement :

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

Le code Python correspondant :

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo31-fast",
    "prompt": "Let it dance",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Rappel asynchrone

Étant donné que le temps de génération de la Veo Videos Generation API est relativement long, nécessitant environ 1 à 2 minutes, si l’API ne répond pas pendant longtemps, la requête HTTP maintiendra continuellement la connexion, entraînant une consommation supplémentaire de ressources système. Cette API fournit donc également la prise en charge des rappels asynchrones.

Le processus global est le suivant : lorsque le client initie une requête, il spécifie en supplément un champ `callback_url`. Après que le client a initié la requête API, l’API renvoie immédiatement un résultat contenant un champ `task_id`, qui représente l’ID de la tâche actuelle. Une fois la tâche terminée, le résultat de la vidéo générée est envoyé sous forme de JSON POST à l’adresse `callback_url` spécifiée par le client, qui inclut également le champ `task_id`, permettant ainsi d’associer les résultats de la tâche par ID.

Voyons ci-dessous comment procéder concrètement à l’aide d’un exemple.

Tout d’abord, le rappel Webhook est un service capable de recevoir des requêtes HTTP ; les développeurs doivent le remplacer par l’URL de leur propre serveur HTTP. ## Gestion des erreurs

Lors de l’appel de l’API, en cas d’erreur, l’API renvoie le code d’erreur et le message correspondants. Par exemple :

- `400 token_mismatched`：Requête incorrecte, probablement en raison de paramètres manquants ou non valides.
- `400 api_not_implemented`：Requête incorrecte, probablement en raison de paramètres manquants ou non valides.
- `401 invalid_token`：Non autorisé, jeton d’autorisation invalide ou manquant.
- `429 too_many_requests`：Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error`：Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d’erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
