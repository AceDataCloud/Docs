La fonction principale de l'API Grok Tasks est de consulter l'état d'exécution d'une tâche en fournissant l'ID de tâche généré par l'API Grok Videos Generation.

Ce document présente en détail les instructions d'intégration de l'API Grok Tasks pour vous aider à intégrer facilement et à consulter l'état d'exécution des tâches de l'API Grok Videos Generation.

## Processus de demande

Pour utiliser l'API Grok Tasks, vous devez d'abord demander le service correspondant sur la page [Grok Videos Generation API](https://platform.acedata.cloud/documents/grok-videos) et copier l'ID de tâche retourné par l'API Grok Videos Generation.

Ensuite, rendez-vous sur la page [Grok Tasks API](https://platform.acedata.cloud/documents/grok-tasks) pour demander le service correspondant. Une fois sur la page, cliquez sur le bouton « Acquire ».

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la [page de connexion](https://platform.acedata.cloud) pour vous inviter à vous inscrire et vous connecter. Après la connexion ou l'inscription, vous serez automatiquement redirigé vers la page actuelle.

Lors de la première demande, un quota gratuit est offert, vous permettant d'utiliser cette API gratuitement.

## Exemple de requête

L'API Grok Tasks peut être utilisée pour consulter les résultats de l'API Grok Videos Generation.

### Configuration des en-têtes et du corps de la requête

**En-têtes de la requête** comprennent :

- `accept` : spécifie que la réponse doit être au format JSON, ici `application/json`.
- `authorization` : la clé d'API pour appeler l'API, sélectionnable directement après la demande.

**Corps de la requête** comprend :

- `id` : l'ID de la tâche à interroger.
- `action` : l'action à effectuer sur la tâche, pour une requête unique, utilisez `retrieve`.

### Exemple de code CURL

```bash
curl -X POST 'https://api.acedata.cloud/grok/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### Exemple de réponse

Après une requête réussie, l'API retourne les détails de la tâche. Le champ `request` contient le corps de la requête lors du lancement de la tâche, et le champ `response` contient le corps de la réponse une fois la tâche terminée, par exemple :

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "request": {
    "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
    "model": "grok-imagine-video-1.5-fast",
    "resolution": "480p",
    "duration": 8
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "grok-imagine-video-1.5-fast:41eb9a5f-3b2d-4d1e-9f5a-6c2f1a0b9e77",
        "video_url": "https://cdn.acedata.cloud/c8cbf53aa0.mp4",
        "state": "succeeded"
      }
    ]
  }
}
```

Description des champs :

- `id` : l'ID de la tâche générée, utilisé pour identifier de manière unique cette tâche.
- `request` : les informations de la requête de la tâche consultée.
- `response` : les informations retournées de la tâche consultée.

## Opération de consultation en lot

Pour consulter les détails de plusieurs tâches en même temps, définissez `action` sur `retrieve_batch` et transmettez un tableau d'IDs de tâches via `ids` :

**Corps de la requête** comprend :

- `ids` : tableau des IDs des tâches à consulter.
- `action` : l'action à effectuer sur les tâches, pour une consultation en lot, utilisez `retrieve_batch`.

```bash
curl -X POST 'https://api.acedata.cloud/grok/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```
