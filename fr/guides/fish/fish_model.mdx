Cette interface est basée sur [Fish Audio Official Model API](https://docs.fish.audio/resources/api-reference/model) et est utilisée pour **créer un nouveau clone de timbre à partir d'un échantillon audio**. L'adresse est `POST https://api.acedata.cloud/fish/model`.

> Pour la recherche paginée des timbres existants, veuillez consulter [Fish Model Query API](https://platform.acedata.cloud/documents/fish-model-query) ; pour interroger les détails d'un timbre unique par `_id`, veuillez consulter [Fish Model Get API](https://platform.acedata.cloud/documents/fish-model-get).

## Processus de demande

Pour utiliser l'API Fish Model, commencez par obtenir votre API Token sur [Ace Data Cloud Console](https://platform.acedata.cloud/console/applications) pour référence.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n'êtes pas encore connecté ou enregistré, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter, après quoi vous serez automatiquement renvoyé à la page actuelle.

**Un API Token suffit pour appeler tous les services de la plateforme, il n'est pas nécessaire de demander séparément pour chaque service.** La première demande vous donnera un quota gratuit pour une expérience sans frais ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [Fish Model API →](https://platform.acedata.cloud/services/fish)

## Champs du corps de la requête

| Champ                     | Type       | Obligatoire | Description                                                                         |
| ------------------------ | -------- | ----------- | --------------------------------------------------------------------------------- |
| `title`                  | string    | Oui         | Nom du timbre, utilisé pour l'identification dans la liste de la console.        |
| `voices`                 | string    | Oui         | URL HTTP(S) de l'échantillon audio (**une seule chaîne**, pas un tableau). Cette interface ne prend pas en charge le téléchargement multipart/binaire, veuillez d'abord placer l'audio dans un stockage d'objets accessible publiquement. |
| `description`            | string    | Non         | Description du timbre.                                                             |
| `cover_image`            | string    | Non         | URL HTTP(S) de l'image de couverture.                                             |
| `visibility`             | string    | Non         | `private` ou `public`, par défaut `private`. `public` signifie publié dans la bibliothèque de timbres publics de Fish pour utilisation par d'autres. |
| `tags`                   | string[]  | Non         | Étiquettes de recherche pour la bibliothèque publique, par exemple `["male","narration","zh"]`. |
| `texts`                  | string[]  | Non         | Textes de référence correspondant à l'échantillon (utilisés pour corriger la prononciation). |
| `enhance_audio_quality`  | boolean   | Non         | Indique si la qualité audio de l'échantillon doit être améliorée avant l'entraînement. |
| `generate_sample`        | boolean   | Non         | Indique si un échantillon audio doit être automatiquement généré après l'entraînement. |

> Les champs sont identiques à ceux de l'upstream, veuillez également consulter [Fish Documentation Officielle](https://docs.fish.audio/resources/api-reference/model).

## Exemple : Créer un timbre de clone privé

```shell
curl -X POST 'https://api.acedata.cloud/fish/model' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "title": "Mon timbre de clone",
    "description": "Timbre chinois cloné à partir d'un enregistrement de podcast",
    "voices": "https://example.com/sample-voice.mp3",
    "cover_image": "https://cdn.acedata.cloud/e724d7f13d.png",
    "visibility": "private"
  }'
```

> Remarque : `voices` doit être une **chaîne** (une seule URL audio), pas un tableau. Si vous le transmettez sous la forme `["..."]`, l'upstream le rejettera.

La réponse réussie renvoie directement l'objet ModelEntity de la plateforme Fish (l'exemple ci-dessous est le timbre minimal utilisable que nous avons testé, certaines longues chaînes ont été supprimées pour faciliter la lecture) :

`_id` peut être utilisé comme valeur du champ `reference_id` dans le [Fish TTS API](https://platform.acedata.cloud/documents/fish-tts) pour utiliser ce timbre de clone pour la synthèse vocale :

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "Bonjour, ceci est une voix synthétisée utilisant le timbre de clone que je viens de créer.",
    "reference_id": "e5c6db52c3ed417f9cb2e5a33fb04667",
    "format": "mp3"
  }'
```

## Exigences d'échantillon

Valeurs d'expérience (identiques à l'upstream, vous pouvez vous référer à [Fish Documentation Officielle](https://docs.fish.audio/resources/api-reference/model)) :

- La durée recommandée est de plus de 30 secondes et de moins de 5 minutes pour un meilleur effet ; au-delà de 10 minutes, le rendement marginal est faible.
- Taux d'échantillonnage de 16 kHz ou plus, mono ou stéréo.
- Le contenu doit être aussi propre que possible : pas de musique de fond, d'écho, de bruit environnemental évident ; même locuteur.
- Formats recommandés : `mp3` / `wav`.

Si vous n'êtes pas sûr de la qualité de l'échantillon, vous pouvez également transmettre `enhance_audio_quality: true` pour permettre à l'upstream d'améliorer d'abord la qualité audio.

## Informations de facturation

La création d'un modèle de timbre cloné (`POST /fish/model`) est gratuite, aucun frais n'est facturé ; les interfaces de requête de timbre ([Fish Model Query](https://platform.acedata.cloud/documents/fish-model-query), [Fish Model Get](https://platform.acedata.cloud/documents/fish-model-get)) ne sont également pas facturées. Les frais ne sont générés que lors de l'appel ultérieur de [Fish TTS](https://platform.acedata.cloud/documents/fish-tts) pour la synthèse vocale.

## Gestion des erreurs
- `400 token_mismatched` : Paramètre de demande manquant ou non valide (le plus souvent, `voices` n'est pas une URL, ou a été transmis sous forme de tableau).
- `401 invalid_token` : Le token d'authentification n'existe pas ou est invalide.
- `429 too_many_requests` : Limite de taux du compte atteinte.
- `500 api_error` : Erreur interne du serveur.

Exemple de réponse d'erreur :

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "voices est requis et doit être une URL HTTP(S) pointant vers un fichier audio"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## Conclusion

Pour appeler cette interface, il suffit de préparer une URL d'échantillon audio accessible publiquement, de la placer dans le champ `voices` pour obtenir le `_id`, puis de l'alimenter dans le `reference_id` de `/fish/tts` pour compléter le processus de bout en bout « clonage → synthèse ». Un point commun à éviter est que `voices` doit être une chaîne de caractères, pas un tableau.
