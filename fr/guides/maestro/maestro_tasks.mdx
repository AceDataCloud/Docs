La principale fonctionnalité de l'API de requête de tâche Maestro est de permettre la consultation de l'état d'exécution et du résultat final d'une tâche via l'ID de tâche retourné par [l'API de génération de vidéos Maestro](development_maestro_videos.md) (`POST /maestro/videos`).

Ce document détaillera les instructions d'intégration de l'API de requête de tâche Maestro. Étant donné que la génération de vidéos est une tâche asynchrone, il est nécessaire d'utiliser cette interface pour interroger le progrès et le produit final après soumission, **l'interrogation est gratuite et ne consomme pas de crédits.**

`POST https://api.acedata.cloud/maestro/tasks`

## Processus de demande

Pour utiliser l'API de requête de tâche Maestro, commencez par obtenir votre API Token sur [le tableau de bord Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour le garder en réserve.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion qui vous invite à vous inscrire et à vous connecter, après quoi vous serez automatiquement renvoyé à la page actuelle.

**Un seul API Token suffit pour appeler tous les services de la plateforme, il n'est pas nécessaire de demander un pour chaque service.** La première demande vous donnera un quota gratuit pour une expérience sans frais ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans [le tableau de bord](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [API de requête de tâche Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Requête d'une tâche unique

Pour savoir comment créer une tâche vidéo, veuillez consulter le document [API de génération de vidéos Maestro](development_maestro_videos.md). Prenons un exemple avec un ID de tâche retourné : `f57e99c4f60f4373a15517742ce2357d`, pour démontrer comment interroger son état et son résultat.

### Configuration des en-têtes de requête et du corps de requête

**Request Headers** inclut :

- `accept` : spécifie que la réponse doit être au format JSON, ici rempli avec `application/json`.
- `authorization` : la clé d'API pour appeler l'API, sélectionnable directement après la demande.
- `content-type` : le format du corps de la requête, ici rempli avec `application/json`.

**Request Body** inclut :

| Champ       | Type     | Obligatoire | Description                                                |
| ----------- | -------- | ----------- | --------------------------------------------------------- |
| `id`       | string   | Oui         | `task_id` retourné par `POST /maestro/videos`            |
| `action`   | string   | Non         | `retrieve` (par défaut, interroger une tâche unique) / `retrieve_batch` (interroger la liste des tâches historiques) |

### Exemple de code

Le code CURL correspondant est le suivant :

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Le code Python correspondant est le suivant :

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Exemple de réponse

Après une requête réussie, l'API renverra l'état et le résultat de la tâche vidéo. Un exemple de réponse lorsque la tâche est terminée est le suivant (chaque langue correspondant à un `variant`) :

```json

  "finished_at": 1769264698.3,

  "status": "succeeded",
  "progress": {
    "percent": 100,
    "stage": "producing",
    "message": "rendering scene 2"
  },
  "request": {
    "prompt": "Expliquer en 20 secondes ce qu'est une base de données vectorielle, adapté à un public sans connaissances préalables, avec une phrase mémorable à la fin",
    "langs": [
      "zh-cn",
      "en"
    ],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        {
          "lang": "zh-cn",
          "aspect": "9:16",
          "kind": "video",
          "title": "Qu'est-ce qu'une base de données vectorielle",
          "output_url": "https://…/zh.mp4"
        },
        {
          "lang": "en",
          "aspect": "9:16",
          "kind": "video",
          "title": "What is a vector database",
          "output_url": "https://…/en.mp4"
        }
      ],
      "project": {
        "tarball_url": "https://…/project.tar.gz",
        "outputs": [
          "https://…/zh.mp4",
          "https://…/en.mp4"
        ]
      },
      "percent": 100,
      "stage": "producing",
      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }
  }
}
```

La description des champs de la réponse est la suivante :

- `id` : l'ID de cette tâche vidéo, utilisé pour identifier de manière unique cette tâche de génération vidéo.
- `status` : l'état de la tâche, avec des valeurs possibles `pending → planning → producing → succeeded` (ou `failed`). L'achèvement de la tâche est déterminé par ce `status` de niveau supérieur.
- `elapsed` : le temps écoulé pour la tâche (en secondes).
- `progress` : objet de progression de niveau supérieur, `percent` (0–100) sera fixé à 100 après le succès de la tâche ; `stage` et `message` reflètent le dernier événement de progression du réalisateur AI (ainsi, après le succès, `stage` peut encore être la dernière étape exécutée comme `producing`), pouvant être utilisé directement pour afficher une barre de progression.
- `request` : le corps de la requête lors de l'initiation de la tâche.
- `response` : les informations de retour de la tâche.
  - `success` : indique si la tâche a réussi.
  - `data.variants` : chaque langue correspondant à un objet de produit final, contenant `lang`, `aspect`, `title`, `output_url` (adresse de téléchargement du produit final), etc.
  - `data.project` : le produit final du projet, contenant `tarball_url` (package du projet) et `outputs` (tous les liens vers les produits finaux).
  - `data.progress` : tableau d'événements de progression ajoutés par étape (journal en ajout uniquement), pouvant être utilisé pour afficher des progrès en temps réel détaillés.
- `created_at` : date de création de la tâche, horodatage Unix (en secondes).
- `started_at` : date de début d'exécution de la tâche, horodatage Unix (en secondes). Si la tâche n'a pas encore commencé, c'est null.
- `finished_at` : date de fin de la tâche, horodatage Unix (en secondes). Si la tâche n'est pas terminée, c'est null.

## Requête de la liste historique

En passant `action: retrieve_batch`, vous pouvez obtenir les tâches récentes de l'utilisateur actuel (par ordre décroissant de date de création), pouvant être utilisées pour la page de liste « Mes vidéos ».

**Request Body** inclut :

| Champ               | Type     | Obligatoire | Description                      |
| ------------------- | -------- | ----------- | -------------------------------- |
| `action`            | string   | Oui         | Fixe à `retrieve_batch`          |
| `limit`             | int      | Non         | Nombre de retours, par défaut 20 |
| `created_at_max`    | int      | Non         | Ne renvoie que les tâches antérieures à cet horodatage Unix (pour pagination) |
| `created_at_min`    | int      | Non         | Ne renvoie que les tâches postérieures à cet horodatage Unix      |

### Exemple de code

Le code CURL correspondant est le suivant :
```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### Exemple de réponse

Après un appel réussi, l'API renverra la liste des tâches historiques de l'utilisateur actuel :

La description des champs du résultat est la suivante :

- `count` : le nombre total de tâches de l'utilisateur actuel.
- `items` : tableau des tâches, chaque élément ayant le même format que le résultat de « requête d'une seule tâche ».

## Suggestions de polling

Étant donné que la production vidéo prend beaucoup de temps, le `status` passera par `pending → planning → producing → succeeded` (ou `failed`). Il est conseillé de faire un polling toutes les 5 à 10 secondes, jusqu'à ce que le `status` devienne `succeeded` ou `failed`. Vous pouvez utiliser le `progress.percent` de niveau supérieur pour afficher une barre de progression en temps réel. **Le polling de cette interface est gratuit et ne consomme pas de points.**

## Gestion des erreurs

Lors de l'appel de l'API, si une erreur se produit, l'API renverra le code d'erreur et les informations correspondantes. Par exemple :

- `401 invalid_token` : Non autorisé, token d'autorisation invalide ou manquant.
- `404 not_found` : Tâche non trouvée, l'identifiant de tâche donné n'existe pas.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de taux.
- `500 api_error` : Erreur interne du serveur, quelque chose s'est mal passé sur le serveur.

### Exemple de réponse d'erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
