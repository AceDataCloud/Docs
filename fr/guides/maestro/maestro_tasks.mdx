La fonction principale de l'API de requête de tâches Maestro est d'interroger l'état d'exécution et le résultat final d'une tâche à l'aide de l'ID de tâche renvoyé par l'[API de génération de vidéos Maestro](/fr/guides/maestro/maestro_videos) (`POST /maestro/videos`).

Ce document présentera en détail la documentation d'intégration de l'API de requête de tâches Maestro. Étant donné que la génération de vidéos est une tâche asynchrone, après la soumission, cette interface doit être utilisée pour interroger la progression et la vidéo finale, **l'interrogation est gratuite et ne consomme pas de crédits.**

`POST https://api.acedata.cloud/maestro/tasks`

## Processus de demande

Pour utiliser l'API de requête de tâches Maestro, commencez par obtenir votre API Token dans la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications), afin de le conserver pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d'appeler tous les services de la plateforme, sans nécessiter une demande distincte pour chaque service.** La première demande offre un quota gratuit pour une expérience gratuite ; lorsque le quota est insuffisant, vous pouvez recharger votre solde commun dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [API de requête de tâches Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Interroger une tâche unique

Pour savoir comment créer une tâche vidéo, veuillez consulter la documentation [API de génération de vidéos Maestro](/fr/guides/maestro/maestro_videos). Nous prenons comme exemple l'un des ID de tâche qu'elle renvoie : `f57e99c4f60f4373a15517742ce2357d`, pour démontrer comment interroger son état et son résultat.

### Définir les en-têtes et le corps de la requête

Les **Request Headers** incluent :

- `accept` : spécifie la réception de résultats de réponse au format JSON, ici renseignez `application/json`.
- `authorization` : la clé pour appeler l'API, qui peut être directement sélectionnée dans la liste déroulante après la demande.
- `content-type` : le format du corps de la requête, ici renseignez `application/json`.

Le **Request Body** inclut :

| Champ       | Type     | Obligatoire lors de l'interrogation d'une tâche unique | Description                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | Obligatoire lors de l'interrogation d'une tâche unique | Le `task_id` renvoyé par `POST /maestro/videos`              |
| `action` | string | Non         | `retrieve` (par défaut, interroge une tâche unique) ; lors de l'interrogation d'une liste d'historique, vaut obligatoirement `retrieve_batch` |

### Exemple de code

Le code CURL correspondant est le suivant :

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Le code Python correspondant est le suivant :

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Exemple de réponse

Une fois la requête réussie, l'API renverra l'état et le résultat de cette tâche vidéo. L'exemple de retour une fois la tâche terminée est le suivant (le tableau `variants` contient une vidéo finale) :

```json
{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "started_at": 1769262721.823,
  "finished_at": 1769264698.3,
  "elapsed": 1976.477,
  "status": "succeeded",
  "progress": {
    "percent": 100,
    "stage": "producing",
    "message": "rendering scene 2"
  },
  "request": {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": [
      "zh-cn"
    ],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        {
          "lang": "zh-cn",
          "aspect": "9:16",
          "kind": "video",
          "title": "什么是向量数据库",
          "output_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4?example=video-001"
        }
      ],
      "project": {
        "tarball_url": null,
        "outputs": [
          "https://…/zh.mp4"
        ]
      },
      "percent": 100,
      "stage": "producing",
      "progress": [
        {
          "stage": "producing",
          "message": "rendering scene 2",
          "pct": 60,
          "t": 1750000000
        }
      ]
    }
  }
}
```

La présentation des champs du résultat renvoyé est la suivante :

- `id` : l'ID de cette tâche vidéo, utilisé pour identifier de manière unique cette tâche de génération de vidéo.
- `status` : l'état de la tâche, les valeurs sont `pending → planning → producing → succeeded` (ou `failed`). La réalisation de la tâche dépend de ce `status` de niveau supérieur.
- `elapsed` : durée écoulée de la tâche (secondes).
- `progress` : objet de progression de niveau supérieur, `percent` (0–100) sera complété à 100 après la réussite de la tâche ; `stage` et `message` reflètent l'événement de progression le plus récent du réalisateur IA (ainsi, après une réussite, `stage` peut encore être la dernière étape d'exécution telle que `producing`), et peuvent être directement utilisés pour afficher une barre de progression.
- `request` : le corps de la requête lors du lancement de la tâche.
- `response` : les informations de retour de la tâche.
  - `success` : si la tâche a réussi.
  - `data.variants` : contient un objet de vidéo finale dans la langue sélectionnée, incluant `lang`, `aspect`, `title`, `output_url` (adresse de téléchargement de la vidéo finale), etc.
  - `data.project` : l'ensemble des livrables du projet, incluant `tarball_url` (package de projet) et `outputs` (liens vers les vidéos finales).
  - `data.progress` : un tableau d'événements de progression ajoutés par étape (journal append-only), qui peut être utilisé pour afficher une progression détaillée en temps réel.
- `created_at` : heure de création de la tâche, horodatage Unix (secondes).
- `started_at` : heure de début d'exécution de la tâche, horodatage Unix (secondes). Vaut null lorsque la tâche n'a pas encore commencé.
- `finished_at` : heure de fin de la tâche, horodatage Unix (secondes). Vaut null lorsque la tâche n'est pas terminée.

## Interroger la liste de l'historique

Transmettez `action: retrieve_batch` pour obtenir les tâches récentes de l'exécutant actuellement connecté (par ordre décroissant de création), ce qui peut être utilisé pour la page de liste « Mes vidéos ». La liste de l'historique est isolée selon l'identité de connexion.

Le **Request Body** inclut :

| Champ               | Type     | Obligatoire  | Description                              |
| ---------------- | ------ | --- | ------------------------------- |
| `action`         | string | Oui   | Fixé à `retrieve_batch`            |
| `limit`          | int    | Non   | Nombre de résultats renvoyés, 20 par défaut ; plage valide de 1 à 100          |
| `created_at_max` | int    | Non   | Renvoie uniquement les tâches strictement antérieures à cet horodatage Unix (valeur limite exclue, pour la pagination) |
| `created_at_min` | int    | Non   | Renvoie uniquement les tâches strictement postérieures à cet horodatage Unix (valeur limite exclue)     |

### Exemple de code

Le code CURL correspondant est le suivant :
```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### Exemple de réponse

Après une requête réussie, l’API renverra la liste des tâches historiques de l’utilisateur actuel :

```json
{
  "count": 2,
  "items": [
    {
      "id": "f57e99c4f60f4373a15517742ce2357d",
      "started_at": 1769262721.823,
      "finished_at": 1769264698.3,
      "elapsed": 1976.477,
      "status": "succeeded",
      "progress": {
        "percent": 100,
        "stage": "producing",
        "message": "rendering scene 2"
      },
      "request": {
        "prompt": "…",
        "langs": [
          "zh-cn"
        ],
        "aspect": "9:16",
        "duration": 20
      },
      "response": {
        "success": true,
        "data": {
          "variants": [
            {
              "lang": "zh-cn",
              "output_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4?example=video-003"
            }
          ]
        }
      }
    }
  ]

```

Les champs du résultat retourné sont décrits comme suit :

- `count` : le nombre total de tâches visibles pour l’exécuteur actuellement connecté, non affecté par les conditions temporelles ou `limit`.
- `items` : le tableau de tâches filtré selon les conditions temporelles et `limit`, trié par ordre décroissant de date de création ; le format de chaque élément est identique au résultat retourné par « Consulter une tâche unique ».

## Recommandations de sondage

Comme la production de vidéos prend relativement longtemps, le `status` passera par `pending → planning → producing → succeeded` (ou `failed`). Il est recommandé d’effectuer un sondage toutes les 5 à 10 secondes, jusqu’à ce que le `status` devienne `succeeded` ou `failed`. Vous pouvez utiliser le `progress.percent` de niveau supérieur pour afficher une barre de progression en temps réel. **Le sondage de cette interface est gratuit et ne consomme pas de crédits.**

## Gestion des erreurs

Lors de l’appel de l’API, si une erreur se produit, l’API renverra le code d’erreur et les informations correspondantes. Par exemple :

- `401 invalid_token` : Non autorisé, jeton d’autorisation invalide ou manquant.
- `404 not_found` : Tâche introuvable, le `task_id` fourni n’existe pas.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d’erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
