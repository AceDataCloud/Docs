La fonction principale de l’API de requête de tâches Maestro est d’interroger l’état d’exécution et le résultat final d’une tâche à l’aide de l’ID de tâche renvoyé par l’[API de génération vidéo Maestro](development_maestro_videos.md) (`POST /maestro/videos`).

Ce document présentera en détail les instructions d’intégration de l’API de requête de tâches Maestro. Étant donné que la génération de vidéos est une tâche asynchrone, après la soumission, vous devez utiliser cette interface pour interroger périodiquement la progression et la vidéo finale, **les interrogations périodiques sont gratuites et ne consomment pas de crédits.**

`POST https://api.acedata.cloud/maestro/tasks`

## Processus de demande

Pour utiliser l’API de requête de tâches Maestro, accédez d’abord à la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token, à conserver pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter, puis vous reviendrez automatiquement sur la page actuelle une fois terminé.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans devoir effectuer une demande séparée pour chaque service.** Lors de votre première demande, un quota gratuit vous sera offert pour vous permettre d’essayer gratuitement ; si votre quota est insuffisant, vous pouvez recharger votre solde universel dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [API de requête de tâches Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Interroger une tâche unique

Pour savoir comment créer une tâche vidéo, veuillez consulter la documentation [API de génération vidéo Maestro](development_maestro_videos.md). Nous prenons comme exemple un ID de tâche qu’elle renvoie : `f57e99c4f60f4373a15517742ce2357d`, afin de démontrer comment interroger son état et son résultat.

### Configurer les en-têtes et le corps de la requête

Les **Request Headers** incluent :

- `accept` : spécifie la réception d’un résultat de réponse au format JSON, indiquez ici `application/json`.
- `authorization` : la clé permettant d’appeler l’API, vous pouvez la sélectionner directement dans la liste déroulante après l’avoir demandée.
- `content-type` : le format du corps de la requête, indiquez ici `application/json`.

Le **Request Body** inclut :

| Champ       | Type   | Obligatoire lors de       | Description                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | l’interrogation d’une tâche unique | Le `task_id` renvoyé par `POST /maestro/videos`              |
| `action` | string | Non         | `retrieve` (par défaut, interroge une tâche unique) ; fixé à `retrieve_batch` lors de l’interrogation de la liste d’historique |

### Exemple de code

Le code CURL correspondant est le suivant :

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

Le code Python correspondant est le suivant :

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Exemple de réponse

Une fois la requête réussie, l’API renverra l’état et le résultat de cette tâche vidéo. Voici un exemple de retour lorsque la tâche est terminée (chaque langue correspond à un `variant`) :

```json
    "langs": [
      "zh-cn",

          "t": 1750000000
        }
      ]
    }

```

Les champs du résultat renvoyé sont présentés ci-dessous :

- `id` : l’ID de cette tâche vidéo, utilisé pour identifier de manière unique cette tâche de génération vidéo.
- `status` : l’état de la tâche, les valeurs sont `pending → planning → producing → succeeded` (ou `failed`). La complétion de la tâche dépend de ce `status` de niveau supérieur.
- `elapsed` : le temps déjà écoulé pour la tâche (secondes).
- `progress` : objet de progression de niveau supérieur, `percent` (0–100) sera fixé à 100 une fois la tâche réussie ; `stage` et `message` reflètent l’événement de progression le plus récent du réalisateur IA (ainsi, après la réussite, `stage` peut encore être la dernière étape d’exécution telle que `producing`), et peuvent être directement utilisés pour afficher une barre de progression.
- `request` : le corps de la requête lors du lancement de la tâche.
- `response` : les informations de retour de la tâche.
  - `success` : si la tâche a réussi.
  - `data.variants` : chaque langue correspond à un objet de vidéo finale, incluant `lang`, `aspect`, `title`, `output_url` (adresse de téléchargement de la vidéo finale), etc.
  - `data.project` : le produit de l’ensemble du projet, incluant `tarball_url` (paquet de projet) et `outputs` (tous les liens des vidéos finales).
  - `data.progress` : un tableau d’événements de progression ajoutés par étape (journal append-only), utilisable pour afficher une progression détaillée en temps réel.
- `created_at` : heure de création de la tâche, horodatage Unix (secondes).
- `started_at` : heure de début d’exécution de la tâche, horodatage Unix (secondes). Vaut null lorsque la tâche n’a pas encore commencé.
- `finished_at` : heure de fin de la tâche, horodatage Unix (secondes). Vaut null lorsque la tâche n’est pas terminée.

## Interroger la liste d’historique

Transmettez `action: retrieve_batch` pour obtenir les tâches les plus récentes de l’exécutant actuellement connecté (par ordre décroissant de création), ce qui peut être utilisé pour la page de liste « Mes vidéos ». La liste d’historique est isolée selon l’identité de connexion.

Le **Request Body** inclut :
| Champ               | Type     | Obligatoire  | Description                              |
| ---------------- | ------ | --- | ------------------------------- |
| `action`         | string | Oui   | Fixé à `retrieve_batch`            |
| `limit`          | int    | Non   | Nombre de résultats retournés, 20 par défaut ; la plage valide est de 1 à 100          |
| `created_at_max` | int    | Non   | Retourne uniquement les tâches strictement antérieures à cet horodatage Unix (valeur limite non incluse, utilisé pour la pagination) |
| `created_at_min` | int    | Non   | Retourne uniquement les tâches strictement postérieures à cet horodatage Unix (valeur limite non incluse)     |

### Exemple de code

Le code CURL correspondant est le suivant :

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### Exemple de réponse

Une fois la requête réussie, l’API retournera la liste des tâches historiques de l’utilisateur actuel :

```json

  "items": [
    {
      "id": "f57e99c4f60f4373a15517742ce2357d",
      "started_at": 1769262721.823,
      "finished_at": 1769264698.3,
      "elapsed": 1976.477,
      "status": "succeeded",
      "progress": {
        "percent": 100,
        "stage": "producing",
        "message": "rendering scene 2"
      },
      "request": {
        "prompt": "…",
        "langs": [
          "zh-cn",
          "en"
        ],
        "aspect": "9:16",
```

La présentation des champs du résultat retourné est la suivante :

- `count` : le nombre total de tâches visibles par l’exécuteur actuellement connecté, non affecté par les conditions de temps ou par `limit`.
- `items` : le tableau des tâches filtrées par les conditions de temps et `limit`, trié par ordre décroissant de date de création ; le format de chaque élément est identique au résultat retourné par « Consulter une tâche unique ».

## Recommandations de sondage

Étant donné que la production vidéo prend relativement longtemps, `status` passera par `pending → planning → producing → succeeded` (ou `failed`). Il est recommandé d’effectuer un sondage toutes les 5 à 10 secondes, jusqu’à ce que `status` devienne `succeeded` ou `failed`. Vous pouvez utiliser `progress.percent` au niveau supérieur pour afficher une barre de progression en temps réel. **Le sondage de cette interface est gratuit et ne consomme pas de crédits.**

## Gestion des erreurs

Lors de l’appel de l’API, si une erreur est rencontrée, l’API retournera le code et les informations d’erreur correspondants. Par exemple :

- `401 invalid_token` : Non autorisé, jeton d’autorisation invalide ou manquant.
- `404 not_found` : Tâche introuvable, le task_id fourni n’existe pas.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, une erreur s’est produite sur le serveur.

### Exemple de réponse d’erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
