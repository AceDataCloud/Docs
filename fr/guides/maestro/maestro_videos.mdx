Maestro est une interface de production vidéo **native Agent** : vous utilisez une phrase en langage naturel `prompt` pour décrire la vidéo souhaitée (vous pouvez éventuellement joindre des images / vidéos / audios de référence avec `file_urls`), et un « réalisateur IA » sans interface graphique réalisera automatiquement le choix du sujet, l’écriture du script, la génération des visuels, le doublage, la musique, la composition et le rendu, pour finalement produire une vidéo finale avec sous-titres et la téléverser sur le CDN.

Cet article présentera en détail le guide d’intégration de l’API de génération vidéo Maestro, afin de vous aider à l’intégrer rapidement et à exploiter pleinement les capacités de cette API.

Il s’agit d’une interface de **tâches asynchrones** : après la soumission, elle renvoie immédiatement un `task_id`, puis vous récupérez le résultat par interrogation via l’[API de consultation des tâches Maestro](/fr/guides/maestro/maestro_tasks) (`POST /maestro/tasks`) (l’interrogation est gratuite et non facturée). Pour continuer à itérer sur une vidéo existante, vous pouvez utiliser `action: remix` / `edit` / `extend` avec `ref_task_id`.

## Processus de demande

Pour utiliser l’API de génération vidéo Maestro, commencez par obtenir votre API Token dans la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications), et conservez-le pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement sur cette page.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans avoir à en demander un séparément pour chaque service.** La première demande offre des crédits gratuits pour une expérience gratuite ; lorsque les crédits sont insuffisants, vous pouvez recharger le solde universel dans la [console](https://platform.acedata.cloud/console/coin).

## Utilisation de base

`POST https://api.acedata.cloud/maestro/videos`

L’utilisation la plus basique nécessite uniquement de transmettre un `prompt` en langage naturel ; le réalisateur IA décidera automatiquement du script, des visuels, du doublage et du montage. Nous allons d’abord découvrir les en-têtes et le corps de requête à définir.

Les **Request Headers** comprennent :

- `accept` : le format de réponse que vous souhaitez recevoir ; indiquez ici `application/json`, c’est-à-dire le format JSON.
- `authorization` : la clé pour appeler l’API, que vous pouvez sélectionner directement dans la liste déroulante après l’avoir demandée.
- `content-type` : le format du corps de requête ; indiquez ici `application/json`.

Le **Request Body** comprend principalement :

- `prompt` : décrivez en langage naturel la vidéo à créer (thème, ce qui doit être montré, style, public).
- `langs` : tableau de langues de la vidéo finale ; ne transmettez qu’une seule langue à la fois, par exemple `["zh-cn"]`, la valeur par défaut est `["zh-cn"]`.
- `aspect` : ratio de l’image, `9:16` (par défaut) / `16:9` / `1:1`.
- `duration` : durée cible (secondes), 30 par défaut.

Tous les champs du corps de requête sont indiqués dans le tableau suivant :

| Champ            | Type       | Obligatoire  | Description                                                                                                                                                                                                                                    |
| ------------- | -------- | --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`      | string   | Oui   | Décrivez en langage naturel la vidéo à créer (thème, ce qui doit être montré, style, public). Le script, les visuels, le doublage et le montage sont tous décidés par l’IA                                                                                                                                                                                      |
| `action`      | string   | Non   | `generate` (par défaut, génère une nouvelle vidéo) / `remix` / `edit` / `extend` (itère sur une vidéo existante, doit être utilisé avec `ref_task_id`)                                                                                                                                                         |
| `ref_task_id` | string   | Non   | Obligatoire lorsque `action` vaut remix / edit / extend : le `task_id` de la tâche historique servant de point de départ                                                                                                                                                                            |
| `file_urls`   | string[] | Non   | Médias de référence (URL d’images / vidéos / audios), par exemple l’image du produit ou le logo qui doit apparaître, ou un extrait source auquel ajouter des sous-titres                                                                                                                                                                                      |
| `langs`       | string[] | Non   | Langue de la vidéo finale, une seule peut être transmise à chaque fois, par exemple `["zh-cn"]`, la valeur par défaut est `["zh-cn"]`                                                                                                                                                                                             |
| `aspect`      | string   | Non   | `9:16` (par défaut) / `16:9` / `1:1`, sortie uniforme en 1080p/30fps                                                                                                                                                                                           |
| `duration`    | int      | Non   | Durée cible (secondes), 30 par défaut, prend en charge **5–300 secondes**. Facturé selon la durée réelle de la vidéo finale, mais ne dépassera pas la durée demandée                                                                                                                                                                                      |
| `scenario`    | string   | Non   | Type de vidéo : `auto` / `narrated` / `captions` / `avatar` / `drama`. `captions` nécessite de transmettre la vidéo source, `avatar` nécessite de transmettre un portrait                                                                                                                                             |
| `style`       | string   | Non   | Préréglages de style visuel : `auto` (par défaut) / `cinematic` / `glass` / `luxury` / `swiss` / `modern` / `editorial` / `warm` / `vibrant` / `neon` / `mono` / `pastel` / `bold` / `industrial` / `futuristic` / `retro`, accepte également du texte libre comme indication souple. Orthogonal à `scenario`, ne modifie pas le routage          |
| `voice`       | string   | Non   | Timbre de la narration (indépendant de la langue, universel entre les langues) : `auto` (par défaut) / `warm-female` / `bright-female` / `anchor-female` / `clean-female` / `calm-male` / `deep-male` / `documentary-male` / `energetic-male` / `storyteller-male` ; prend également en charge un `reference_id` de timbre hexadécimal à 32 bits, les autres textes libres ne sont pas des ID de timbre valides |

Nous allons présenter cela à travers un exemple concret. Supposons que nous souhaitions générer une courte vidéo de vulgarisation scientifique en chinois, au format vertical, de 20 secondes ; le code CURL correspondant est le suivant :

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
  "langs": ["zh-cn"],
  "aspect": "9:16",
  "duration": 20
}'
```

Le code Python correspondant est le suivant :

```python
import requests

url = "https://api.acedata.cloud/maestro/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": ["zh-cn"],
    "aspect": "9:16",
    "duration": 20
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Cliquez sur exécuter, vous constaterez qu’un résultat est immédiatement obtenu, comme suit :

```json
{
  "success": true,
  "task_id": "f57e99c4f60f4373a15517742ce2357d",
  "trace_id": "70e1cb12-c619-4292-a416-90191205996b"
}
```

La présentation des champs du résultat retourné est la suivante :
- `success` : indique si cette tâche a été soumise avec succès.
- `task_id` : l’ID de cette tâche de génération vidéo, à utiliser ensuite pour interroger le résultat via l’[API de requête des tâches Maestro](/fr/guides/maestro/maestro_tasks).
- `trace_id` : l’ID de traçage de cette requête, qui peut être fourni au support technique en cas de problème.

Comme la production vidéo prend relativement longtemps, l’interface **renvoie immédiatement `task_id`** ici, sans attendre la fin du rendu vidéo. Vous devez ensuite utiliser `task_id` pour interroger le résultat ; voir la section « Récupérer le résultat » pour plus de détails.

## Spécifier le type et le style de la vidéo (scenario / style)

Lorsque `scenario` n’est pas transmis, il est déterminé automatiquement par l’IA (équivaut à `auto`) ; si vous souhaitez définir la vidéo sur un type spécifique, transmettez-le explicitement. Par exemple, pour créer une **courte série dramatique en format vertical**, vous pouvez spécifier les éléments suivants :

- `scenario` : le type de vidéo, défini ici sur `drama` (courte série avec personnages + dialogues).
- `style` : le style visuel, défini ici sur `cinematic` (rendu cinématographique).

Voici le code CURL de l’exemple de remplissage :

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "两个合租室友因为一只猫闹翻又和好，三幕反转，结尾温暖",
  "scenario": "drama",
  "style": "cinematic",
  "aspect": "9:16",
  "duration": 40
}'
```

Associations courantes :

- Courte vidéo commentée : `scenario: "narrated"`.
- Sous-titres automatiques : `scenario: "captions"`, le fichier vidéo source doit être transmis via `file_urls`.
- Avatar numérique / présentation face caméra : `scenario: "avatar"`, une image de portrait doit être transmise via `file_urls`.
- Courte série dramatique : `scenario: "drama"` (personnages + dialogues).
- `style` correspond à un préréglage de style visuel (par exemple `modern` / `neon` / `luxury`) ; il ne modifie pas le type, seulement le rendu visuel.
- `voice` permet de spécifier le timbre de la voix off (par exemple `warm-female` / `deep-male`) ; il est indépendant de la langue et utilisable dans toutes les langues.

Le résultat renvoyé est identique à celui de « Utilisation de base » : `task_id` est également renvoyé immédiatement.

## Langue de la vidéo finale

Une tâche ne livre qu’une seule vidéo finale dans une seule langue. `langs` ne peut contenir qu’un seul code langue, tel que `["zh-cn"]` ou `["en"]` ; transmettre plusieurs langues renverra une erreur 400. Si vous avez besoin de vidéos dans différentes langues, veuillez créer les tâches séparément. Le choix de la langue ne modifie pas le prix par seconde.

## Itérer sur une vidéo existante (remix / edit / extend)

Transmettez `action` et le `ref_task_id` de la tâche précédente pour effectuer des modifications incrémentielles à partir du projet original (par exemple « modifier le titre de la scène 2 », « changer la voix off », « assombrir l’ensemble »). Les petites modifications sont rapides ; les modifications importantes entraînent une nouvelle production :

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "remix",
  "ref_task_id": "f57e99c4f60f4373a15517742ce2357d",
  "prompt": "把开场标题换成更有冲击力的一句，整体配色更暗一些"
}'
```

- `remix` : réinterprète la vidéo sur la structure originale (conserve le thème, ajuste la présentation).
- `edit` : effectue une retouche précise sur une partie spécifiée (par exemple changer le titre, la voix off ou l’étalonnage).
- `extend` : prolonge le contenu à partir de la vidéo originale.

Le résultat renvoyé est également un nouveau `task_id` immédiatement ; utilisez-le pour interroger et obtenir la vidéo finale après itération.

## Récupérer le résultat

Comme la production vidéo prend relativement longtemps, cette interface renvoie `task_id` immédiatement après la soumission ; vous devez l’utiliser pour interroger le résultat via l’[API de requête des tâches Maestro](/fr/guides/maestro/maestro_tasks) :

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d"
}'
```

Une fois la tâche terminée, les informations d’une vidéo finale sont renvoyées (dans le tableau `variants`). `status` passera par `pending → planning → producing → succeeded` (ou `failed`), et **l’interrogation est gratuite et ne consomme pas de crédits**. Pour le format de réponse complet et la requête de l’historique, consultez les [instructions d’intégration de l’API de requête des tâches Maestro](/fr/guides/maestro/maestro_tasks).

## Facturation

**Après la réussite de la tâche, la facturation est calculée selon la durée réelle de la vidéo finale livrée ; aucun frais n’est facturé en cas d’échec.** La durée facturée est comptabilisée en secondes entières et ne dépasse pas la durée demandée ; lorsqu’il est impossible de lire la durée de la vidéo finale, la durée demandée est utilisée par défaut. La soumission de tâche elle-même n’est pas facturée séparément, et l’interrogation de `/maestro/tasks` est gratuite.

```
Crédits = secondes réellement facturées × 0.7
```

Tous les scénarios, actions et langues utilisent le même tarif, sans multiplicateur selon le scénario ni supplément selon la langue. Chaque tâche ne livre qu’une seule vidéo finale dans une seule langue. La durée cible demandée prend en charge de 5 à 300 secondes, avec une sortie uniforme en 1080p / 30fps.

| Durée réelle facturée              | Crédits |
| ------------------- | --: |
| 30 secondes         |  21 |
| 60 secondes         |  42 |
| 120 secondes        |  84 |
| 300 secondes        | 210 |
| Interrogation `/maestro/tasks` | Gratuit |

## Gestion des erreurs

Lors de l’appel de l’API, en cas d’erreur, l’API renvoie le code et les informations d’erreur correspondants. Par exemple :

- `400 invalid_request` : Requête incorrecte, possiblement en raison d’un `prompt` manquant ou de paramètres non valides.
- `401 invalid_token` : Non autorisé, jeton d’autorisation non valide ou manquant.
- `403 forbidden` : Interdit, solde ou accès insuffisant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, un problème est survenu côté serveur.

### Exemple de réponse d’erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

L’API prend également en charge la spécification du type de vidéo, du style, du timbre de voix, de la langue de la vidéo finale, ainsi que l’itération sur des vidéos existantes.
