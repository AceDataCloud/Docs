Maestro est une interface de production vidéo **native pour les Agents** : vous décrivez la vidéo souhaitée dans un `prompt` en langage naturel (et pouvez éventuellement joindre des images / vidéos / audios de référence avec `file_urls`), puis un « réalisateur IA » sans interface effectue automatiquement la sélection du sujet, l’écriture du script, la génération des images, le doublage, la musique, le compositing et le rendu, pour finalement produire une vidéo finale sous-titrée et la téléverser sur le CDN.

Cet article présentera en détail le guide d’intégration de l’API de génération vidéo Maestro, afin de vous aider à l’intégrer rapidement et à exploiter pleinement ses capacités.

Il s’agit d’une interface de **tâche asynchrone** : après la soumission, elle renvoie immédiatement un `task_id`, puis vous obtenez le résultat en interrogeant [l’API de consultation des tâches Maestro](/fr/guides/maestro/maestro_tasks) (`POST /maestro/tasks`) (l’interrogation est gratuite et non facturée). Pour continuer à itérer sur une vidéo existante, vous pouvez utiliser `action: remix` / `edit` / `extend` avec `ref_task_id`.

## Processus de demande

Pour utiliser l’API de génération vidéo Maestro, obtenez d’abord votre jeton API sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications), et conservez-le pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement sur cette page.

**Un seul jeton API permet d’appeler tous les services de la plateforme, sans devoir effectuer une demande séparée pour chaque service.** La première demande vous offrira un quota gratuit pour tester le service sans frais ; si le quota est insuffisant, vous pouvez recharger votre solde général dans la [console](https://platform.acedata.cloud/console/coin).

## Utilisation de base

`POST https://api.acedata.cloud/maestro/videos`

L’utilisation la plus élémentaire nécessite uniquement de transmettre un `prompt` en langage naturel ; le réalisateur IA décidera automatiquement du script, des images, du doublage et du montage. Découvrons d’abord les en-têtes et le corps de requête à définir.

Les **Request Headers** comprennent :

- `accept` : le format dans lequel vous souhaitez recevoir le résultat de la réponse ; indiquez ici `application/json`, c’est-à-dire le format JSON.
- `authorization` : la clé pour appeler l’API, qui peut être directement sélectionnée dans la liste déroulante après la demande.
- `content-type` : le format du corps de la requête ; indiquez ici `application/json`.

Le **Request Body** comprend principalement :

- `prompt` : décrivez la vidéo à réaliser en langage naturel (thème, ce qui doit être présenté, style, public).
- `langs` : tableau des langues de la vidéo finale ; transmettez une seule langue à chaque fois, par exemple `["zh-cn"]`, la valeur par défaut étant `["zh-cn"]`.
- `aspect` : ratio de l’image, `9:16` (par défaut) / `16:9` / `1:1`.
- `duration` : durée cible (secondes), 30 par défaut.

Tous les champs du corps de requête sont présentés dans le tableau ci-dessous :

| Champ            | Type       | Obligatoire  | Description                                                                                                                                                                                                                           |
| ------------- | -------- | --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `prompt`      | string   | Oui   | Décrivez la vidéo à réaliser en langage naturel (thème, ce qui doit être présenté, style, public). Le script, les images, le doublage et le montage sont tous décidés par l’IA                                                                                                                                                                             |
| `action`      | string   | Non   | `generate` (par défaut, génère une nouvelle vidéo) / `remix` / `edit` / `extend` (itère sur une vidéo existante, nécessite `ref_task_id`)                                                                                                                                                |
| `ref_task_id` | string   | Non   | Obligatoire lorsque `action` est remix / edit / extend : le `task_id` de la tâche historique servant de point de départ                                                                                                                                                                   |
| `file_urls`   | string[] | Non   | Médias de référence (URL d’image / vidéo / audio), par exemple l’image du produit ou le logo à afficher, ou un extrait vidéo auquel ajouter des sous-titres                                                                                                                                                                             |
| `langs`       | string[] | Non   | Langue de la vidéo finale, une seule langue peut être transmise à chaque fois, par exemple `["zh-cn"]`, la valeur par défaut étant `["zh-cn"]`                                                                                                                                                                                    |
| `aspect`      | string   | Non   | `9:16` (par défaut) / `16:9` / `1:1`, sortie uniforme en 1080p/30fps                                                                                                                                                                                  |
| `duration`    | int      | Non   | Durée cible (secondes), 30 par défaut, prend en charge **5–300 secondes**. La facturation est basée sur la durée réelle de la vidéo finale, sans toutefois dépasser la durée demandée                                                                                                                                                                             |
| `scenario`    | string   | Non   | Type de vidéo : `auto` / `narrated` / `captions` / `avatar` / `drama`. `captions` nécessite de transmettre la vidéo source, `avatar` nécessite de transmettre un portrait                                                                                                                                    |
| `style`       | string   | Non   | Préréglage de style visuel : `auto` (par défaut) / `cinematic` / `glass` / `luxury` / `swiss` / `modern` / `editorial` / `warm` / `vibrant` / `neon` / `mono` / `pastel` / `bold` / `industrial` / `futuristic` / `retro`, accepte également du texte libre comme indication souple. Orthogonal à `scenario`, ne modifie pas le routage |
| `voice`       | string   | Non   | Timbre de voix off (indépendant de la langue, utilisable dans toutes les langues) : `auto` (par défaut) / `warm-female` / `bright-female` / `anchor-female` / `clean-female` / `calm-male` / `deep-male` / `documentary-male` / `energetic-male` / `storyteller-male`                                    |

Démontrons cela à l’aide d’un exemple concret. Supposons que nous souhaitions générer une courte vidéo de vulgarisation scientifique en chinois, au format vertical, de 20 secondes ; le code CURL correspondant est le suivant :

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
  "langs": ["zh-cn"],
  "aspect": "9:16",
  "duration": 20
}'
```

Le code Python correspondant est le suivant :

```python
import requests

url = "https://api.acedata.cloud/maestro/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "prompt": "用 20 秒讲清楚什么是向量数据库，适合零基础观众，结尾给一句记忆点",
    "langs": ["zh-cn"],
    "aspect": "9:16",
    "duration": 20
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

En cliquant sur exécuter, vous constaterez qu’un résultat est immédiatement obtenu, comme suit :

```json
{
  "success": true,
  "task_id": "f57e99c4f60f4373a15517742ce2357d",
  "trace_id": "70e1cb12-c619-4292-a416-90191205996b"
}
```

La présentation des champs du résultat retourné est la suivante :
- `success`：si cette tâche a été soumise avec succès.
- `task_id`：l’ID de cette tâche de génération vidéo, à utiliser ensuite avec l’[API de requête des tâches Maestro](/fr/guides/maestro/maestro_tasks) pour interroger le résultat.
- `trace_id`：l’ID de suivi de cette requête, qui peut être fourni au support technique en cas de problème.

La production vidéo prenant beaucoup de temps, l’interface **renvoie immédiatement `task_id`** ici, sans attendre la fin du rendu vidéo. Vous devez ensuite utiliser `task_id` pour interroger le résultat ; consultez la section « Obtenir le résultat » pour plus de détails.

## Spécifier le type et le style de vidéo (scenario / style)

Lorsque `scenario` n’est pas transmis, il est déterminé automatiquement par l’IA (équivalent à `auto`) ; si vous souhaitez fixer la vidéo à un certain type, transmettez-le explicitement. Par exemple, pour créer une **courte série dramatique en format vertical**, vous pouvez spécifier le contenu suivant :

- `scenario`：le type de vidéo, défini ici sur `drama` (courte série avec personnages + dialogues).
- `style`：le style visuel, défini ici sur `cinematic` (rendu cinématographique).

Voici le code CURL de l’exemple de remplissage :

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "prompt": "两个合租室友因为一只猫闹翻又和好，三幕反转，结尾温暖",
  "scenario": "drama",
  "style": "cinematic",
  "aspect": "9:16",
  "duration": 40
}'
```

Combinaisons courantes :

- Courte vidéo commentée : `scenario: "narrated"`.
- Sous-titres automatiques : `scenario: "captions"` ; utilisez `file_urls` pour transmettre la vidéo source.
- Avatar numérique / présentation orale : `scenario: "avatar"` ; utilisez `file_urls` pour transmettre un portrait.
- Courte série dramatique : `scenario: "drama"` (personnages + dialogues).
- `style` est un préréglage de style visuel (tel que `modern` / `neon` / `luxury`) ; il ne modifie pas le type, mais influence uniquement le rendu visuel.
- `voice` est utilisé pour spécifier le timbre de la voix off (tel que `warm-female` / `deep-male`) ; il est indépendant de la langue et universel entre les langues.

Le résultat retourné est identique à celui de « Utilisation de base » : `task_id` est également renvoyé immédiatement.

## Langue de la vidéo finale

Une tâche ne livre qu’une seule vidéo finale dans une seule langue. `langs` ne peut contenir qu’un seul code langue, tel que `["zh-cn"]` ou `["en"]` ; transmettre plusieurs langues renverra 400. Si vous avez besoin de vidéos dans différentes langues, veuillez créer des tâches séparées. Le choix de la langue ne modifie pas le prix par seconde.

## Itérer sur une vidéo existante (remix / edit / extend)

Transmettez `action` et le `ref_task_id` de la tâche précédente pour effectuer des modifications différentielles sur la base du projet original (par exemple : « modifier le titre de la scène 2 », « changer la voix off », « assombrir l’ensemble »). Les petites modifications sont rapides ; les grandes modifications nécessitent une nouvelle production :

```bash
curl -X POST 'https://api.acedata.cloud/maestro/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "remix",
  "ref_task_id": "f57e99c4f60f4373a15517742ce2357d",
  "prompt": "把开场标题换成更有冲击力的一句，整体配色更暗一些"
}'
```

- `remix`：réinterprète la structure de la vidéo originale (conserve le thème, ajuste la présentation).
- `edit`：effectue une retouche précise sur une partie spécifiée (par exemple, changer le titre, changer la voix off, ajuster les couleurs).
- `extend`：étend le contenu sur la base de la vidéo originale.

Le résultat retourne également immédiatement un nouveau `task_id`, que vous pouvez utiliser pour interroger et obtenir la vidéo finale après itération.

## Obtenir le résultat

La production vidéo prenant beaucoup de temps, cette interface renvoie immédiatement `task_id` après la soumission ; vous devez l’utiliser avec l’[API de requête des tâches Maestro](/fr/guides/maestro/maestro_tasks) pour interroger le résultat :

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d"
}'
```

Lorsque la tâche est terminée, les informations d’une vidéo finale sont retournées (dans le tableau `variants`). `status` passera par `pending → planning → producing → succeeded` (ou `failed`), et **l’interrogation est gratuite et ne consomme pas de crédits**. Pour le format de réponse complet et la requête de liste d’historique, consultez les [instructions d’intégration de l’API de requête des tâches Maestro](/fr/guides/maestro/maestro_tasks).

## Tarification

**Une fois la tâche réussie, la facturation est basée sur la durée réelle de la vidéo finale livrée ; aucun frais n’est facturé en cas d’échec.** La durée facturée est comptabilisée en secondes entières et ne dépasse pas la durée demandée ; lorsqu’il est impossible de lire la durée de la vidéo finale, la durée demandée est utilisée par défaut. La soumission de tâche elle-même n’est pas facturée séparément, et l’interrogation de `/maestro/tasks` est gratuite.

```
Crédits = secondes réellement facturées × 0.7
```

Tous les scénarios, actions et langues utilisent le même tarif, sans multiplicateur de scénario ni supplément de langue. Chaque tâche ne livre qu’une seule vidéo finale dans une seule langue. La durée cible demandée prend en charge 5 à 300 secondes, avec une sortie uniforme en 1080p / 30fps.

| Durée réelle facturée              |  Crédits |
| ------------------- | --: |
| 30 secondes                |  21 |
| 60 secondes                |  42 |
| 120 secondes               |  84 |
| 300 secondes               | 210 |
| Interrogation `/maestro/tasks` |  Gratuite |

## Gestion des erreurs

Lors de l’appel de l’API, en cas d’erreur, l’API renverra le code d’erreur et les informations correspondantes. Par exemple :

- `400 invalid_request`：Requête incorrecte, possiblement en raison d’un `prompt` manquant ou de paramètres non valides.
- `401 invalid_token`：Non autorisé, jeton d’autorisation invalide ou manquant.
- `403 forbidden`：Interdit, solde ou accès insuffisant.
- `429 too_many_requests`：Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error`：Erreur interne du serveur, un problème est survenu sur le serveur.

### Exemple de réponse d’erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Elle prend également en charge la spécification du type de vidéo, du style, du timbre vocal, de la langue de la vidéo finale, ainsi que l’itération sur des vidéos existantes.
