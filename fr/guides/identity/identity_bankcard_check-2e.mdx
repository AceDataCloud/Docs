Cet article présente une documentation sur l'API de vérification des deux éléments de la carte bancaire, qui peut être utilisée pour vérifier la véracité et la cohérence du nom et du numéro de carte bancaire.

## Processus de demande

Pour utiliser l'API de vérification des deux éléments de la carte bancaire, commencez par obtenir votre token API sur le [tableau de bord d'Ace Data Cloud](https://platform.acedata.cloud/console/applications) et conservez-le pour référence.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n'êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion pour vous inviter à vous inscrire et à vous connecter, après quoi vous serez automatiquement renvoyé à la page actuelle.

**Un seul token API suffit pour appeler tous les services de la plateforme, il n'est pas nécessaire de demander un token séparé pour chaque service.** La première demande vous donnera un quota gratuit pour une expérience sans frais ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans le [tableau de bord](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [API de vérification des deux éléments de la carte bancaire →](https://platform.acedata.cloud/documents/identity-bankcard-check-2e)

## Utilisation de base

Tout d'abord, comprenez la méthode d'utilisation de base, qui consiste à entrer les informations du numéro de carte bancaire pour obtenir une image du résultat traité. Vous devez d'abord transmettre un champ `bank_card`. Nous pouvons ensuite remplir le contenu correspondant sur l'interface, comme indiqué dans l'image :

<p><img src="https://cdn.acedata.cloud/u9bugq.png" width="500" className="m-auto" /></p>

Ici, nous avons configuré les en-têtes de requête, y compris :

- `accept` : le format de réponse souhaité, ici rempli comme `application/json`, c'est-à-dire au format JSON.
- `authorization` : la clé pour appeler l'API, que vous pouvez sélectionner directement après la demande.

De plus, nous avons configuré le corps de la requête, y compris :

- `bank_card` : les informations du numéro de carte bancaire à traiter, c'est un paramètre obligatoire.
- `name` : le nom de l'utilisateur, c'est un paramètre obligatoire.
- `encryption` : optionnel, paramètre de cryptage pour les champs sensibles (si vous devez envoyer des données chiffrées).

Après avoir fait votre sélection, vous pouvez voir que le code correspondant a également été généré à droite, comme indiqué dans l'image :

<p><img src="https://cdn.acedata.cloud/yn8yxf.png" width="500" className="m-auto" /></p>

Cliquez sur le bouton « Essayer » pour effectuer un test, comme montré dans l'image ci-dessus, et nous avons obtenu le résultat suivant :

```json
{
  "result": "0",
  "description": "Certification réussie"
}
```

Le résultat de la réponse contient plusieurs champs, décrits comme suit :

- `result` : code de résultat de la certification, les frais sont les suivants.
    - Codes de résultat avec frais :
        - 0 : Certification réussie
        - -1 : Certification échouée
        - -4 : Informations sur le titulaire de la carte incorrectes
        - -5 : Paiement sans carte non activé
        - -6 : Cette carte a été confisquée
        - -7 : Numéro de carte invalide
        - -8 : Cette carte n'a pas d'émetteur correspondant
        - -9 : Cette carte n'est pas initialisée ou est une carte dormante
        - -10 : Carte frauduleuse, carte avalée
        - -11 : Cette carte a été déclarée perdue
        - -12 : Cette carte a expiré
        - -13 : Carte restreinte
        - -14 : Nombre d'erreurs de mot de passe dépassé
        - -15 : L'émetteur de la carte ne prend pas en charge cette transaction
    - Codes de résultat sans frais :
        - -2 : Vérification du nom échouée
        - -3 : Numéro de carte bancaire incorrect
        - -16 : Service du centre de vérification occupé
        - -17 : Nombre de vérifications dépassé, veuillez réessayer le lendemain
- `description` : description du résultat commercial.

On peut voir que la véracité et la cohérence du nom et du numéro de carte bancaire ont été validées.

De plus, si vous souhaitez générer le code d'intégration correspondant, vous pouvez le copier directement, par exemple, le code CURL est le suivant :

```shell
curl -X POST 'https://api.acedata.cloud/identity/bankcard/check-2e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "bank_card": "***"
}'
```

Le code d'intégration Python est le suivant :

```python
curl -X POST 'https://api.acedata.cloud/identity/bankcard/check-2e' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "name": "***",
  "bank_card": "***"
}'
```

## Gestion des erreurs

Lors de l'appel de l'API, si une erreur se produit, l'API renverra le code d'erreur et les informations correspondantes. Par exemple :

- `400 token_mismatched` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `400 api_not_implemented` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `401 invalid_token` : Non autorisé, token d'autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de taux.
- `500 api_error` : Erreur interne du serveur, quelque chose s'est mal passé sur le serveur.

### Exemple de réponse d'erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "échec de la récupération"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
