## 1. Obtenir la clé API

Ouvrez la [liste des applications Ace Data Cloud](https://platform.acedata.cloud/console/applications), accédez à une application disponible et copiez la clé API.

![Obtenir la clé API Ace Data Cloud](https://cdn.acedata.cloud/dvc3cg.jpg)

## 2. Ajouter un modèle

Dans WorkBuddy, accédez à **Paramètres → Modèles → Modèles personnalisés → Ajouter un modèle**, puis renseignez :

| Champ       | Valeur                                                                                                |
| -------- | ------------------------------------------------------------------------------------------------ |
| Provider | `Custom`                                                                                         |
| Adresse de l’interface     | `https://api.acedata.cloud/v1`                                                                   |
| Clé API  | La clé API que vous venez de copier                                                                                    |
| Nom du modèle     | Accédez au [catalogue de modèles](https://platform.acedata.cloud/models) pour consulter et renseigner exactement le nom du modèle à appeler, par exemple `claude-opus-5`、`gpt-6-sol` |
| Protocole personnalisé    | Désactivé                                                                                               |

![Interface de configuration du fournisseur personnalisé WorkBuddy](https://cdn.acedata.cloud/189027b68722.png)

> L’`id` ici est le nom du modèle utilisé par le paramètre `model` dans la requête API ; ce n’est ni l’UUID du service, de l’API ou de l’Application, ni un nom d’affichage personnalisé. Vous ne pouvez renseigner `ds-4.0` que lorsque le catalogue en temps réel retourne `{"id":"ds-4.0"}` ; s’il n’est pas dans le catalogue, cela signifie qu’il n’est pas actuellement disponible, veuillez ne pas deviner ou abréger.

Vous pouvez d’abord consulter les modèles disponibles dans le [catalogue de modèles](https://platform.acedata.cloud/models) ; si vous devez confirmer le nom exact appelable par les identifiants Coding actuels, utilisez ensuite la clé API que vous venez de copier pour interroger le catalogue API :

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_KEY"
```

Dans le tableau `data` de la réponse, trouvez le modèle cible et copiez exactement la valeur de son `id`. Configurez les commutateurs de capacités selon la prise en charge réelle de ce modèle.

En gardant le « protocole personnalisé » désactivé, WorkBuddy complétera le chemin selon les règles OpenAI Chat Completions. Les commutateurs de capacités avancées (outils, images, raisonnement) ne doivent être activés que selon les capacités réelles du modèle sélectionné ; en cas de doute, conservez d’abord les valeurs par défaut.

## 3. Vérification

Après l’enregistrement, sélectionnez le modèle que vous venez d’ajouter dans le sélecteur de modèles de chat et envoyez `Reply only OK`. Exécutez ensuite une tâche de fichier en lecture seule ou une tâche d’outil afin de confirmer que les capacités requises sont disponibles ; les enregistrements d’appels peuvent être consultés dans l’[historique d’utilisation](https://platform.acedata.cloud/console/usages).

Si le modèle n’apparaît pas, vérifiez que la configuration a été enregistrée et activée ; pour une erreur 401, vérifiez la clé ; pour une erreur 404, vérifiez si le nom de modèle renseigné correspond exactement à l’`id` du catalogue, ainsi que si l’adresse de l’interface est correcte. La documentation officielle de WorkBuddy indique que la clé est stockée dans la configuration locale, mais que le contenu des requêtes sera tout de même envoyé au service de modèle configuré.
