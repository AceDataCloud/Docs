Les identifiants spécifiques peuvent également être limités par `allowed_api_ids` et par l’étendue des autorisations de l’application.

## Catalogue dynamique de modèles

Vous pouvez d’abord ouvrir le [catalogue de modèles](https://platform.acedata.cloud/models) pour consulter les noms de modèles actuels, tels que `claude-opus-5` et `gpt-6-sol`. Lorsque vous devez confirmer que les identifiants Coding et le protocole API correspondent, utilisez des identifiants Coding Application valides pour effectuer la requête :

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer YOUR_API_TOKEN"
```

Le catalogue de modèles évolue continuellement ; cet article ne maintient pas de quantité fixe ni de liste statique de modèles. Le `id` de chaque entrée dans la réponse est le **nom du modèle** qui peut être directement transmis au paramètre API `model`, par exemple `{"id":"deepseek-v4-pro"}` correspond à `deepseek-v4-pro` ; ce n’est pas l’UUID d’un service, d’une API ou d’une Application. `/v1/models` renvoie le catalogue global de modèles et ne le filtre pas automatiquement selon les identifiants Coding ; avant la configuration, vous devez toujours effectuer une vérification croisée avec l’API scope des identifiants, le protocole sélectionné et l’étendue de compatibilité du client.

## Dépannage courant

- **Solde insuffisant** : accédez à la [console Applications](https://platform.acedata.cloud/console/applications), trouvez la Coding Application et renouvelez activement votre achat.
- **Le client continue de demander l’adresse d’origine** : confirmez que la configuration appartient au même utilisateur et au même espace de travail que le client démarré, puis quittez complètement et redémarrez le client.
- **Le nom du modèle n’est pas disponible** : demandez à nouveau `/v1/models`, vérifiez que le nom du modèle renseigné correspond exactement au `id` dans le catalogue, ainsi que l’API scope des identifiants et le protocole pris en charge par le client.
- **Le Token ne peut pas appeler l’interface** : confirmez que les identifiants appartiennent à une Coding Application, puis vérifiez `allowed_api_ids` et les autorisations API de l’application.
