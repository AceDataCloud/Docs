Cet article présente une méthode d’intégration de l’API de génération d’images SeeDream Images Generation API, qui permet de générer des images officielles SeeDream en saisissant des paramètres personnalisés.

## Procédure de demande

Pour utiliser l’API SeeDream Images Generation API, accédez d’abord à la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) afin d’obtenir votre API Token, que vous conserverez pour une utilisation ultérieure.

![]()

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion, qui vous invitera à vous inscrire et à vous connecter. Une fois cette étape terminée, vous serez automatiquement redirigé vers la page actuelle.

**Un seul API Token suffit pour appeler tous les services de la plateforme, sans avoir à en demander un séparément pour chaque service.** Lors de votre première demande, un crédit gratuit vous sera offert pour vous permettre de tester le service gratuitement. Lorsque votre solde est insuffisant, vous pouvez recharger votre solde général dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [SeeDream Images Generation API →](https://platform.acedata.cloud/documents/seedream-images)

## Sélection du modèle

| Modèle                                                          | Scénarios d’utilisation                            |
| ----------------------------------------------------------- | ------------------------------- |
| `doubao-seedream-5-5-261028`                                | Édition en plusieurs étapes, génération d’images transparentes à partir de texte, édition transparente avec plusieurs images de référence, séparation des calques et reconnaissance des calques de texte |
| `doubao-seedream-5-0-flash-260915`                          | Génération d’images uniques à faible latence, édition avec plusieurs images de référence, édition d’images transparentes et séparation des calques       |
| `doubao-seedream-5-0-pro-260628`                            | Génération d’images uniques, édition précise, édition d’images transparentes et séparation des calques            |
| `doubao-seedream-5-0-lite-260128`                           | Images uniques, ensembles d’images, sortie en continu et recherche en ligne                 |
| `doubao-seedream-4-5-251128` / `doubao-seedream-4-0-250828` | Anciennes versions de génération et d’édition d’images                       |

Les modèles 5.5 et 5.0 Flash utilisent le même `POST /seedream/images` et prennent tous deux en charge les résolutions `1K`, `1.5K`, `2K` ainsi que jusqu’à 10 images de référence. Pour les deux modèles, les tâches de séparation des calques n’acceptent qu’une seule image et renvoient une URL. Le modèle 5.5 permet de définir `layer_decomposition_options: {"max_images": 12, "text_recognition": true}`. Il peut générer jusqu’à 100 images (image de base incluse). Les calques de texte reconnaissables renvoient le texte ligne par ligne et les styles dans `data[].text_recognition`. Le modèle 5.0 Flash renvoie au maximum 1 image de base et 16 calques.

Le modèle 5.5 prend en charge la génération directe de PNG transparents à l’aide de `background: "transparent"`. Pour l’édition d’images transparentes avec le modèle 5.0 Flash, une image de référence disposant d’un canal alpha est nécessaire. Le modèle 5.5 facture selon la catégorie de pixels de chaque image générée avec succès et ajoute 0.13 Credits pour chaque image de référence fournie. Le modèle 5.0 Flash facture 0.31 Credits pour chaque image générée avec succès, les images de référence étant gratuites. La séparation des calques est facturée selon le nombre réel d’images générées avec succès, l’image de base étant également comptabilisée. Consultez les [tarifs en temps réel](https://platform.acedata.cloud/services/seedream?tab=pricing).

## Utilisation de base

Commençons par comprendre le mode d’utilisation de base : il suffit de saisir une invite `prompt`, un comportement de génération `action` et une taille d’image `size` pour obtenir le résultat traité. Tout d’abord, il faut transmettre simplement un champ `action`, dont la valeur est `generate`, puis saisir l’invite. Le contenu spécifique est le suivant :

<p><img src="https://cdn.acedata.cloud/seedream_request_body.png" width="500" className="m-auto" /></p>

Comme vous pouvez le constater, nous avons configuré ici les Request Headers, notamment :

- `accept` : le format de réponse que vous souhaitez recevoir. Ici, indiquez `application/json`, c’est-à-dire le format JSON.
- `authorization` : la clé API permettant d’appeler l’API. Après l’avoir obtenue, vous pouvez la sélectionner directement dans la liste déroulante.

Nous avons également configuré le Request Body, notamment :

- `prompt` : l’invite.
- `model` : veuillez saisir l’identifiant complet du modèle indiqué dans le tableau ci-dessus.
- `image` : URL de l’image d’entrée, chaîne Base64 ou tableau. Les modèles 5.5, 5.0 Pro et 5.0 Flash acceptent jusqu’à 10 images de référence.
- `size` : niveau de résolution ou `largeurxhauteur`. Les modèles 5.5, 5.0 Pro et 5.0 Flash prennent en charge `1K`, `1.5K` et `2K`. Le modèle 5.0 Lite prend en charge `2K`, `3K` et `4K`.
- `sequential_image_generation` : génération d’un ensemble d’images : génération d’un groupe d’images liées entre elles à partir du contenu que vous saisissez. Les modèles `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128` et `doubao-seedream-4-0-250828` prennent en charge ce paramètre, désactivé par défaut (`disabled`).
- `stream` : contrôle l’activation ou non du mode de sortie en continu. Les modèles `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128` et `doubao-seedream-4-0-250828` prennent en charge ce paramètre, dont la valeur par défaut est `false`.
- `response_format` : spécifie le format de retour des images générées. La valeur par défaut est `url`, mais `b64_json` est également pris en charge.
- `watermark` : indique s’il faut ajouter un filigrane aux images générées. La valeur par défaut est `true`.
- `output_format` : format de sortie `jpeg` ou `png`. Le modèle 5.5 utilise PNG par défaut, tandis que les modèles 5.0 Pro/Flash/Lite utilisent JPEG par défaut.
- `tools` : configure les outils que le modèle doit appeler. Actuellement, `web_search` (recherche en ligne) est pris en charge. Seul Seedream 5.0 Lite est compatible.
- `optimize_prompt_options` : configuration de l’optimisation des invites. Le modèle 5.0 Pro prend en charge `standard`/`fast` ; les modèles 5.5, 5.0 Flash, 5.0 Lite et 4.5 prennent uniquement en charge `standard` ; le modèle 4.0 prend en charge `standard`/`fast`.
- `background` : prend en charge `transparent` et `opaque`. Le modèle 5.5 prend également en charge `auto`. La sortie transparente utilise le format PNG.
- `layer_decomposition` : pris en charge par les modèles 5.5, 5.0 Pro et 5.0 Flash. Lorsque ce paramètre est défini sur `true`, une image PNG/JPEG doit être fournie. Il est possible de ne pas transmettre de `prompt` pour effectuer une séparation automatique des calques, ou d’utiliser le langage naturel/`<bbox>` pour spécifier les éléments ; `size` prend en charge `auto`/`1K`/`1.5K`/`2K`. Ce mode ne peut pas être utilisé simultanément avec la génération d’ensembles d’images, la sortie en continu, la recherche en ligne ou `background`.
- `callback_url` : URL permettant de recevoir les résultats via un rappel.
- `async` : indique si le traitement doit être effectué en mode asynchrone. Lorsque ce paramètre est défini sur `true`, l’interface renvoie immédiatement un `task_id`, sans qu’il soit nécessaire de fournir un `callback_url`. Les résultats peuvent ensuite être récupérés par interrogation via `/seedream/tasks`.

Par ailleurs, si vous souhaitez générer le code d'intégration correspondant, vous pouvez le copier directement. Voici, par exemple, le code CURL :

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "doubao-seedream-5-0-lite-260128",
  "prompt": "Un seul cube bleu mat centré sur un fond blanc épuré de studio, avec un éclairage neutre"
}'
```

## Tâche de modification d'image

Si vous souhaitez modifier une image, vous devez tout d'abord renseigner dans le paramètre `image` le lien de l'image à modifier.

- model : renseignez l'identifiant complet d'un modèle prenant en charge la modification d'images, parmi ceux présentés dans le tableau ci-dessus.
- image : téléversez une ou plusieurs images à modifier.

Voici un exemple de saisie :

<p><img src="https://cdn.acedata.cloud/seedream_edit.png" width="500" className="m-auto" /></p>

Le code correspondant :

```python
import requests

url = "https://api.acedata.cloud/seedream/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedream-4-0-250828",
  "prompt": "Conservez la pose du modèle et la forme fluide du vêtement liquide sans aucune modification. Remplacez le matériau du vêtement, actuellement en métal argenté, par de l'eau (ou du verre) complètement transparent(e). Les détails de la peau du modèle doivent être visibles à travers l'écoulement du liquide. L'effet de lumière et d'ombre passe de la réflexion à la réfraction.",
  "image": ["https://ark-project.tos-cn-beijing.volces.com/doc_image/seedream4_5_imageToimage.png"],
  "size": "2K",
  "watermark": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Séparation des calques (Seedream 5.0 Pro)

La séparation des calques divise une image d'entrée en une image d'arrière-plan et jusqu'à 16 calques PNG transparents pouvant être modifiés indépendamment. La requête suivante demande au modèle d'identifier automatiquement les principaux éléments. Si vous souhaitez spécifier des éléments, vous pouvez ajouter un `prompt` ou utiliser des coordonnées `<bbox>` normalisées dans l'invite.

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "https://example.com/poster.png",
  "layer_decomposition": true,
  "size": "2K",
  "watermark": false
}'
```

Les éléments `data` renvoyés sont classés par `z_index`, de l'arrière-plan vers le premier plan. L'image d'arrière-plan possède un `z_index` de 0. Chaque calque comprend également `name`, `description` et `bounding_box.absolute`/`normalized`. Pour recomposer l'image à l'aide des coordonnées absolues, redimensionnez chaque calque aux dimensions `[right-left, bottom-top]`, placez-le à la position `[left, top]`, puis superposez les calques par ordre croissant de `z_index`. Si la génération d'un seul calque échoue, l'ensemble de l'opération de séparation échoue.

## Sortie en continu

Lorsque `stream: true` est défini pour Lite/4.x, l'en-tête de la requête doit utiliser `accept: application/x-ndjson`. L'interface renvoie les événements `image_generation.partial_succeeded` ou `image_generation.partial_failed` ligne par ligne, puis renvoie un unique événement final `image_generation.completed` accompagné de `usage` final. Seul l'événement de fin déclenche une facturation, une seule fois. Le mode de diffusion en continu ne peut pas être utilisé conjointement avec `async` ou `callback_url`.

## Rappel asynchrone

Étant donné que la génération d'images avec l'API SeeDream Images Generation prend relativement longtemps, environ 1 à 2 minutes, si l'API ne répond pas pendant une période prolongée, la requête HTTP reste connectée, ce qui entraîne une consommation supplémentaire des ressources système. C'est pourquoi cette API prend également en charge les rappels asynchrones.

Le processus général est le suivant : lorsque le client envoie une requête, il spécifie en plus un champ `callback_url`. Après l'envoi de la requête API par le client, l'API renvoie immédiatement un résultat contenant un champ `task_id`, qui représente l'identifiant de la tâche en cours. Une fois la tâche terminée, le résultat de la génération d'image est envoyé au `callback_url` spécifié par le client sous la forme d'une requête POST JSON, qui comprend également le champ `task_id`. Le résultat de la tâche peut ainsi être associé à son identifiant.

Si vous ne disposez pas d'une adresse publique accessible pour recevoir les rappels, vous pouvez également ne pas spécifier de `callback_url` et définir le champ `async` sur `true` dans la requête. Dans ce cas, l'interface renvoie également immédiatement le `task_id`, mais ne transmet pas le résultat. Vous devez utiliser ce `task_id` pour appeler l'interface `/seedream/tasks` et interroger régulièrement l'état de la tâche afin d'obtenir le résultat final.

## Gestion des erreurs

Lors de l'appel à l'API, si une erreur se produit, l'API renvoie le code d'erreur et le message correspondants. Par exemple :

- `400 token_mismatched` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `400 api_not_implemented` : Mauvaise requête, probablement en raison de paramètres manquants ou invalides.
- `401 invalid_token` : Non autorisé, jeton d'autorisation invalide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, un problème s'est produit sur le serveur.

### Exemple de réponse d'erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
