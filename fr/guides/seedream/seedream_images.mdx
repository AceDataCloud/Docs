Cet article présentera une méthode d’intégration de l’API SeeDream Images Generation, qui permet de générer des images officielles de SeeDream en saisissant des paramètres personnalisés.

## Processus de demande

Pour utiliser l’API SeeDream Images Generation, rendez-vous d’abord sur la [console Ace Data Cloud](https://platform.acedata.cloud/console/applications) pour obtenir votre API Token et le conserver pour une utilisation ultérieure.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si vous n’êtes pas encore connecté ou inscrit, vous serez automatiquement redirigé vers la page de connexion afin de vous inviter à vous inscrire et à vous connecter ; une fois terminé, vous reviendrez automatiquement à la page actuelle.

**Un seul API Token permet d’appeler tous les services de la plateforme, sans devoir faire une demande séparée pour chaque service.** La première demande offre un quota gratuit pour une expérience sans frais ; lorsque le quota est insuffisant, vous pouvez recharger le solde général dans la [console](https://platform.acedata.cloud/console/coin).

> 📘 Documentation complète : [SeeDream Images Generation API →](https://platform.acedata.cloud/documents/seedream-images)

## Utilisation de base

Commençons par comprendre le mode d’utilisation de base : saisissez le prompt `prompt`, l’action de génération `action` et la taille de l’image `size`, afin d’obtenir le résultat traité. Vous devez d’abord simplement transmettre un champ `action`, dont la valeur est `generate`, puis nous devons également saisir le prompt ; le contenu spécifique est le suivant :

<p><img src="https://cdn.acedata.cloud/seedream_request_body.png" width="500" className="m-auto" /></p>

Vous pouvez voir que nous avons configuré les Request Headers, y compris :

- `accept` : le format de résultat de réponse que vous souhaitez recevoir ; saisissez ici `application/json`, c’est-à-dire le format JSON.
- `authorization` : la clé pour appeler l’API, qui peut être directement sélectionnée dans la liste déroulante après la demande.

Nous avons également configuré le Request Body, y compris :

- `prompt` : le prompt.
- `model` : le modèle de génération, par défaut `doubao-seedream-5-0-lite-260128` (SeeDream 5.0 Lite, le plus récent). Prend en charge `doubao-seedream-5-0-pro-260628`, `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828`. Parmi eux, `doubao-seedream-5-0-pro-260628` (SeeDream 5.0 Pro) est un modèle phare à image unique, générant uniquement une image unique, **ne prenant pas en charge les groupes d’images (`sequential_image_generation`), le streaming (`stream`) ni la recherche web (`tools`)**. **`model` doit recevoir la chaîne complète du modèle (par exemple `doubao-seedream-5-0-lite-260128`) ; transmettre une forme abrégée telle que `doubao-seedream-5.0-lite` retournera une erreur 400.**
- `image`: informations sur l’image d’entrée, prenant en charge l’URL ou l’encodage Base64. `doubao-seedream-5-0-pro-260628` prend en charge l’entrée d’une image unique ou de plusieurs images (jusqu’à 10), tandis que `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` prennent en charge l’entrée d’une image unique ou de plusieurs images.
- `size`: spécifie les informations de taille de l’image générée, prend en charge les deux méthodes suivantes, qui ne peuvent pas être mélangées. Méthode 1 | Spécifier la résolution de l’image générée, et décrire le rapport largeur-hauteur de l’image en langage naturel dans le prompt. **Les préréglages pris en charge varient selon les modèles** : `doubao-seedream-5-0-pro-260628` prend en charge `1K`/`1.5K`/`2K` ; `doubao-seedream-5-0-lite-260128` prend en charge `2K`/`3K`/`4K` ; `doubao-seedream-4-5-251128` prend uniquement en charge `2K`/`4K` ; `doubao-seedream-4-0-250828` prend en charge `1K`/`2K`/`4K`. Méthode 2 | Spécifier les valeurs en pixels de la largeur et de la hauteur de l’image générée : la valeur par défaut est `2048x2048`, la plage de valeurs du nombre total de pixels et du rapport largeur-hauteur varie selon le modèle (par exemple, la plage totale de pixels de 5.0 Pro est [921600, 4624220], la limite inférieure du total de pixels de 5.0 Lite / 4.5 est 3,686,400, celle de 4.0 est 921,600).
- `sequential_image_generation`: groupe d’images : un groupe d’images dont le contenu est lié, généré à partir du contenu que vous avez saisi. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` prennent en charge ce paramètre, avec `disabled` par défaut.
- `stream`: contrôle l’activation ou non du mode de sortie en streaming. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` prennent en charge ce paramètre, la valeur par défaut étant `false`.
- `response_format`: spécifie le format de retour de l’image générée. La valeur par défaut est `url`, et `b64_json` est également pris en charge.
- `watermark`: indique s’il faut ajouter un filigrane à l’image générée. La valeur par défaut est `true`.
- `output_format`: spécifie le format de fichier de l’image générée, prend en charge `jpeg` (par défaut) et `png`. Seuls `doubao-seedream-5-0-pro-260628` et `doubao-seedream-5-0-lite-260128` le prennent en charge.
- `tools`: configure les outils que le modèle doit appeler, prend actuellement en charge `web_search` (recherche web). Seul Seedream 5.0 Lite le prend en charge.
- `optimize_prompt_options`: configuration d’optimisation des prompts. 5.0 Pro prend en charge `standard`/`fast` ; 5.0 Lite et 4.5 prennent uniquement en charge `standard` ; 4.0 prend en charge `standard`/`fast`.
- `background`: uniquement pris en charge pour l’édition d’image unique de 5.0 Pro. `transparent` exige l’entrée d’une image PNG avec canal de transparence, et `output_format` doit être `png` ; `opaque` correspond à un arrière-plan opaque ordinaire.
- `layer_decomposition`: uniquement pris en charge par 5.0 Pro. Lorsqu’il est défini sur `true`, une image PNG/JPEG doit être saisie ; il est possible de ne pas transmettre `prompt` pour une décomposition automatique, ou de spécifier des éléments en langage naturel/avec `<bbox>` ; `size` prend en charge `auto`/`1K`/`1.5K`/`2K`. Ce mode ne peut pas être utilisé avec les groupes d’images, le streaming, la recherche web ou `background`.
- `callback_url` : l’URL qui nécessite un résultat de rappel.
- `async` : indique si le traitement s’effectue en mode asynchrone. Lorsqu’il est défini sur `true`, l’interface retourne immédiatement `task_id`, sans qu’il soit nécessaire de fournir `callback_url`, puis le résultat est récupéré par interrogation via `/seedream/tasks`.

De plus, si vous souhaitez générer le code d’intégration correspondant, vous pouvez le copier directement, par exemple le code CURL est le suivant :

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "doubao-seedream-5-0-lite-260128",
  "prompt": "A single matte blue cube centered on a clean white studio background, neutral lighting"
}'
```

## Tâche d’édition d’image

Si vous souhaitez éditer une image, le paramètre `image` doit d’abord transmettre le lien de l’image à éditer

- model : le modèle utilisé pour cette tâche d’édition d’image, `doubao-seedream-5-0-pro-260628`, `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128`, `doubao-seedream-4-0-250828` prennent tous en charge l’entrée d’images.
- image : téléversez l’image à éditer, une ou plusieurs

L’exemple de remplissage est le suivant :

<p><img src="https://cdn.acedata.cloud/seedream_edit.png" width="500" className="m-auto" /></p>

Le code correspondant :

```python
import requests

url = "https://api.acedata.cloud/seedream/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedream-4-0-250828",
  "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
  "image": ["https://ark-project.tos-cn-beijing.volces.com/doc_image/seedream4_5_imageToimage.png"],
  "size": "2K",
  "watermark": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Cliquez sur Exécuter, vous constaterez qu’un résultat est immédiatement obtenu, comme suit :

## Décomposition des calques (Seedream 5.0 Pro)

La décomposition des calques divise une image d’entrée en 1 image de fond et jusqu’à 16 calques PNG transparents éditables indépendamment. La requête suivante permet au modèle d’identifier automatiquement les éléments principaux ; si vous devez spécifier des éléments, vous pouvez ajouter `prompt`, et vous pouvez également utiliser des coordonnées `<bbox>` normalisées dans le prompt.

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "https://example.com/poster.png",
  "layer_decomposition": true,
  "size": "2K",
  "watermark": false
}'
```

Les `data` retournées sont triées de bas en haut selon `z_index`. Le `z_index` de l’image de fond est 0 ; les calques contiennent également `name`, `description` et `bounding_box.absolute`/`normalized`. Lors de la recomposition avec des coordonnées absolues, redimensionnez les calques à `[right-left, bottom-top]`, placez-les à `[left, top]`, puis superposez-les dans l’ordre croissant de `z_index`. Si la génération d’un seul calque échoue, l’ensemble de la décomposition échoue.

## Sortie en flux

Lorsque Lite/4.x définit `stream: true`, l’en-tête de requête utilise `accept: application/x-ndjson`. L’interface retourne ligne par ligne `image_generation.partial_succeeded` ou `image_generation.partial_failed`, puis retourne finalement le seul événement `image_generation.completed` ainsi que le `usage` final ; seul l’événement de fin déclenche une facturation unique. Le mode flux ne peut pas être utilisé avec `async` ou `callback_url`.

## Rappel asynchrone

Étant donné que le temps de génération de SeeDream Images Generation API est relativement long, environ 1 à 2 minutes, si l’API ne répond pas pendant longtemps, la requête HTTP restera connectée en permanence, entraînant une consommation supplémentaire de ressources système ; cette API fournit donc également la prise en charge des rappels asynchrones.

Le processus global est le suivant : lorsque le client lance une requête, il spécifie en plus un champ `callback_url`. Après que le client a lancé la requête API, l’API retourne immédiatement un résultat comprenant un champ `task_id`, représentant l’ID de la tâche actuelle. Une fois la tâche terminée, le résultat de la génération d’image sera envoyé sous forme de POST JSON au `callback_url` spécifié par le client, incluant également le champ `task_id`, afin que le résultat de la tâche puisse être associé par ID.

Si vous ne disposez pas d’une adresse publique pour le rappel, vous pouvez également ne pas spécifier `callback_url`, et définir à la place le champ `async` sur `true` dans la requête. Dans ce cas, l’interface retournera également immédiatement `task_id`, mais ne transmettra pas le résultat ; vous devrez appeler l’interface `/seedream/tasks` avec ce `task_id` afin d’interroger l’état de la tâche et obtenir le résultat final.

Ci-dessous, nous allons comprendre comment procéder concrètement à travers un exemple.

Cliquez sur Exécuter, vous constaterez qu’un résultat est immédiatement obtenu, comme suit :

```
{
  "task_id": "c9aaffa2-b8ac-40ff-8468-43e77cb9ddde"
}
```

Le contenu est le suivant :
```json

    "task_id": "c9aaffa2-b8ac-40ff-8468-43e77cb9ddde",
    "trace_id": "131a40c3-2eaf-44c9-af28-c9b408577286",
    "data": [
        {
            "prompt": "Gardez inchangées la pose du modèle et la forme fluide du vêtement liquide. Changez le matériau du vêtement du métal argenté en eau (ou verre) complètement transparente. À travers le flux liquide, les détails de la peau du modèle sont visibles. L'effet de lumière et d'ombre passe de la réflexion à la réfraction.",
            "size": "2048x2048",
```

On peut voir qu'il y a un champ `task_id` dans le résultat, les autres champs sont similaires à ceux ci-dessus, et ce champ permet d'associer les tâches.

## Gestion des erreurs

Lors de l'appel de l'API, en cas d'erreur, l'API renvoie le code d'erreur et les informations correspondants. Par exemple :

- `400 token_mismatched` : Mauvaise requête, possiblement due à des paramètres manquants ou non valides.
- `400 api_not_implemented` : Mauvaise requête, possiblement due à des paramètres manquants ou non valides.
- `401 invalid_token` : Non autorisé, jeton d'autorisation non valide ou manquant.
- `429 too_many_requests` : Trop de requêtes, vous avez dépassé la limite de débit.
- `500 api_error` : Erreur interne du serveur, quelque chose s'est mal passé sur le serveur.

### Exemple de réponse d'erreur

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
