Este documento presentará una guía sobre la integración de la API de generación de videos de Veo, que permite generar videos oficiales de Veo mediante la entrada de parámetros personalizados.

## Proceso de Solicitud

Para utilizar la API de generación de videos de Veo, primero dirígete a [Ace Data Cloud Console](https://platform.acedata.cloud/console/applications) para obtener tu token de API y guardarlo para uso futuro.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si aún no has iniciado sesión o registrado, serás redirigido automáticamente a la página de inicio de sesión que te invitará a registrarte e iniciar sesión; una vez completado, serás devuelto automáticamente a la página actual.

**Un token de API es suficiente para acceder a todos los servicios de la plataforma, no es necesario solicitar uno para cada servicio.** La primera solicitud incluirá un crédito gratuito para que puedas probarlo; si el crédito es insuficiente, puedes recargar el saldo general en [la consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Veo Videos Generation API →](https://platform.acedata.cloud/documents/veo-videos)

## Uso Básico

Primero, es importante entender la forma básica de uso, que consiste en ingresar la palabra clave `prompt`, la acción `action`, un array de imágenes de referencia `image_urls` y el modelo `model`, para obtener el resultado procesado. Primero, necesitas pasar un campo `action`, cuyo valor será `text2video`, que incluye tres tipos de acciones: video generado por texto (`text2video`), video generado por imagen (`image2video`), y obtener video en 1080p (`get1080p`). Luego, también necesitamos ingresar el modelo `model`, que actualmente incluye los modelos `veo31-fast`, `veo3`, `veo31`, `veo2-fast`, `veo3-fast` y `veo31-fast-ingredients`, con los siguientes detalles:

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

Aquí podemos ver que hemos configurado los encabezados de la solicitud, que incluyen:

- `accept`: el formato de respuesta que deseas recibir, aquí se establece como `application/json`, es decir, formato JSON.
- `authorization`: la clave para llamar a la API, que puedes seleccionar directamente después de solicitarla.

Además, se ha configurado el cuerpo de la solicitud, que incluye:

- `model`: el modelo para generar el video, que incluye `veo31-fast`, `veo3`, `veo31`, `veo2-fast`, `veo3-fast` y `veo31-fast-ingredients`.
- `action`: la acción de la tarea de generación de video, que incluye tres tipos de acciones: video generado por texto (`text2video`), video generado por imagen (`image2video`), y obtener video en 1080p (`get1080p`).
- `image_urls`: cuando se selecciona la acción de video generado por imagen `image2video`, es necesario subir los enlaces de las imágenes de referencia. `veo2-fast` solo admite 1 imagen, `veo31-fast-ingredients` admite hasta 3 imágenes (fusión de múltiples imágenes), y los demás modelos admiten hasta 2 imágenes (modo de primer y último fotograma).
- `resolution`: selecciona la resolución del video generado, donde el modelo veo31 admite resolución 4k, los demás modelos no la admiten, todos los modelos admiten 1080p y resolución gif, si no se proporciona este valor, se utilizará por defecto la resolución 720p, que se clasifica en: `1080p`, `gif`, `4k`.
- `prompt`: palabra clave.
- `callback_url`: URL para recibir el resultado de la llamada.
- `async`: opcional, si se establece en `true`, la interfaz devuelve inmediatamente `task_id`, sin necesidad de proporcionar `callback_url`, y luego se puede consultar el resultado a través de la interfaz de consulta de tareas correspondiente.

### 📌 Resumen de la Descripción del Modelo

| **Nombre del Modelo**                   | **Modos Soportados**                          | **Reglas de Entrada de Imágenes**                        |
| -------------------------- | --------------------------------- | --------------------------------- |
| **veo2-fast**              | Video generado por texto (sin imagen)<br />Modo de video generado por imagen (con imagen)           | Solo admite **1 imagen** → Modo de primer fotograma                |
| **veo3-fast**              | Video generado por texto (sin imagen)<br />Modo de video generado por imagen (con imagen)           | **1 imagen** → Modo de primer fotograma<br />**2 imágenes** → Modo de primer y último fotograma |
| **veo31-fast**             | Video generado por texto (sin imagen)<br />Modo de video generado por imagen (con imagen)           | **1 imagen** → Modo de primer fotograma<br />**2 imágenes** → Modo de primer y último fotograma |
| **veo31-fast-ingredients** | ❌ Video generado por texto (no soportado)<br />✅ **Fusión de múltiples imágenes obligatoria** (debe proporcionar imágenes) | **1-3 imágenes** → Modo de fusión de múltiples imágenes (máximo 3 imágenes)        |
| **veo3**                   | Video generado por texto (sin imagen)<br />Modo de video generado por imagen (con imagen)           | **1 imagen** → Modo de primer fotograma<br />**2 imágenes** → Modo de primer y último fotograma |
| **veo31**                  | Video generado por texto (sin imagen)<br />Modo de video generado por imagen (con imagen)           | **1 imagen** → Modo de primer fotograma<br />**2 imágenes** → Modo de primer y último fotograma |

---

### 🔑 Resumen de Reglas Clave

1. **Lógica General**:
   - **Sin entrada de imagen** → Activa automáticamente el modo de video generado por texto.
   - **Con entrada de imagen** → Activa el modo de video generado por imagen (el comportamiento específico depende de la cantidad de imágenes).
2. **Tipos de Modo de Video Generado por Imagen**:
   - **Modo de primer fotograma** (1 imagen): el primer fotograma se fija en la imagen de entrada.
   - **Modo de primer y último fotograma** (2 imágenes): el primer y último fotograma se fijan en las imágenes de entrada.
   - **Modo de fusión de múltiples imágenes** (1-3 imágenes): solo soportado por `veo31-fast-ingredients`, fusiona el contenido de múltiples imágenes para generar un video.
3. **Clasificación de Modos**:
   - **Modo Rápido**: `veo2-fast`, `veo3-fast`, `veo31-fast`, `veo31-fast-ingredients`.
   - **Modo de Calidad**: `veo3`, `veo31` (genera calidad más alta).

---

### ⚠️ Consideraciones Importantes

- **Modelo que requiere obligatoriamente imágenes**: `veo31-fast-ingredients` debe recibir imágenes (1-3 imágenes), de lo contrario, no podrá ejecutarse.
- **Límite de cantidad de imágenes**:
  - `veo2-fast` solo admite **1 imagen** de entrada (modo de primer fotograma).
  - `veo31-fast-ingredients` admite **1-3 imágenes** de entrada (modo de fusión de múltiples imágenes).
  - Otros modelos admiten un máximo de **2 imágenes** de entrada (modo de primer y último fotograma).

## Función de generación de video a partir de imágenes

Si se desea generar un video a partir de imágenes de inicio y fin, se puede establecer el parámetro `action` como `image2video`, y proporcionar un array de enlaces de imágenes de inicio y fin `image_urls`.

A continuación, debemos completar el siguiente paso con las palabras clave que necesitamos para personalizar la generación del video, especificando el siguiente contenido:

- `model`: el modelo para generar el video, que incluye `veo31-fast`, `veo3`, `veo31`, `veo2-fast`, `veo3-fast` y `veo31-fast-ingredients`.
- `image_urls`: cuando se elige la acción de generar video a partir de imágenes `image2video`, es necesario subir los enlaces de las imágenes de referencia.
- `prompt`: palabras clave.

Un ejemplo de llenado es el siguiente:

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

Una vez completado, se generó automáticamente el siguiente código:

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

El código correspondiente en Python:

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo31-fast",
    "prompt": "Déjalo bailar",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Callback Asíncrono

Dado que el tiempo de generación de la API Veo Videos Generation es relativamente largo, aproximadamente de 1 a 2 minutos, si la API no responde durante mucho tiempo, la solicitud HTTP mantendrá la conexión, lo que provocará un consumo adicional de recursos del sistema. Por lo tanto, esta API también ofrece soporte para callbacks asíncronos.

El flujo general es: cuando el cliente inicia la solicitud, se especifica un campo adicional `callback_url`. Después de que el cliente inicia la solicitud a la API, la API devolverá inmediatamente un resultado que incluye un campo `task_id`, que representa el ID de la tarea actual. Cuando la tarea se completa, el resultado del video generado se enviará al `callback_url` especificado por el cliente en formato JSON POST, que también incluirá el campo `task_id`, de modo que el resultado de la tarea se pueda asociar mediante el ID.

## Manejo de Errores

Al llamar a la API, si se encuentra con un error, la API devolverá el código de error y la información correspondiente. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o inválidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o inválidos.
- `401 invalid_token`: No autorizado, token de autorización inválido o faltante.
- `429 too_many_requests`: Demasiadas solicitudes, ha superado el límite de tasa.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de Respuesta de Error
