Este artículo presentará un método de integración de Veo Videos Generation API, que permite generar videos oficiales de Veo introduciendo parámetros personalizados.

## Proceso de solicitud

Para usar Veo Videos Generation API, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; al completarlo, regresará automáticamente a la página actual.

**Un API Token puede invocar todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluye una cuota gratuita para poder probarlo sin costo; cuando la cuota sea insuficiente, puede recargar el saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Veo Videos Generation API →](https://platform.acedata.cloud/documents/veo-videos)

## Uso básico

Primero conozcamos el método básico de uso: introduciendo el texto de indicación `prompt`, la acción de generación `action`, el arreglo de imágenes de referencia para el primer y último fotograma `image_urls` y el modelo `model`, se puede obtener el resultado procesado. Primero es necesario pasar simplemente un campo `action`, cuyo valor es `text2video`. Este incluye principalmente tres comportamientos: texto a video (`text2video`), imagen a video (`image2video`) y obtener video en 1080p (`get1080p`). Luego también necesitamos introducir el modelo `model`; actualmente, los modelos principales son `veo31-fast`, `veo3`, `veo31`, `veo3-fast` y `veo31-fast-ingredients`. El contenido específico es el siguiente:

<p><img src="https://cdn.acedata.cloud/vv5pe8.png" width="500" className="m-auto" /></p>

Aquí podemos ver que configuramos los Request Headers, incluyendo:

- `accept`: el formato de respuesta que se desea recibir; aquí se establece como `application/json`, es decir, formato JSON.
- `authorization`: la clave para invocar la API; después de solicitarla, puede seleccionarse directamente desde la lista desplegable.

Además, configuramos el Request Body, incluyendo:

- `model`: el modelo para generar videos; los principales son `veo31-fast`, `veo3`, `veo31`, `veo3-fast` y `veo31-fast-ingredients`.
- `action`: el comportamiento de esta tarea de generación de video; incluye principalmente tres comportamientos: texto a video (`text2video`), imagen a video (`image2video`) y obtener video en 1080p (`get1080p`).
- `image_urls`: cuando se selecciona el comportamiento de imagen a video `image2video`, se requieren enlaces a las imágenes de referencia que deben cargarse. `veo31-fast-ingredients` admite hasta 3 imágenes (fusión de múltiples imágenes), y los demás modelos admiten hasta 2 imágenes (modo de primer y último fotograma).
- `resolution`: selecciona la resolución del video generado. El modelo veo31 admite resolución 4k, mientras que los demás modelos no la admiten; todos los modelos admiten resoluciones 1080p y gif. Si no se pasa este valor, se utiliza por defecto la resolución 720p. Se divide principalmente en: `1080p`, `gif`, `4k`.
- `prompt`: texto de indicación.
- `callback_url`: URL que necesita recibir el resultado de la devolución de llamada.
- `async`: opcional; cuando se establece en `true`, la interfaz devuelve inmediatamente `task_id`, no es necesario proporcionar `callback_url`, y posteriormente se obtiene el resultado mediante sondeo a través de la interfaz de consulta de tareas correspondiente.

### 📌 Resumen de la descripción de modelos

| **Nombre del modelo**                   | **Modos compatibles**                          | **Reglas de entrada de imágenes**                        |
| -------------------------- | --------------------------------- | --------------------------------- |
| **veo3-fast**              | Texto a video (sin imagen)<br />Modo imagen a video (con imagen)           | **1 imagen** → modo de primer fotograma<br />**2 imágenes** → modo de primer y último fotograma |
| **veo31-fast**             | Texto a video (sin imagen)<br />Modo imagen a video (con imagen)           | **1 imagen** → modo de primer fotograma<br />**2 imágenes** → modo de primer y último fotograma |
| **veo31-fast-ingredients** | ❌ Texto a video (no compatible)<br />✅ **fusión forzada de múltiples imágenes** (se deben pasar imágenes) | **1-3 imágenes** → modo de fusión de múltiples imágenes (máximo 3 imágenes)        |
| **veo3**                   | Texto a video (sin imagen)<br />Modo imagen a video (con imagen)           | **1 imagen** → modo de primer fotograma<br />**2 imágenes** → modo de primer y último fotograma |
| **veo31**                  | Texto a video (sin imagen)<br />Modo imagen a video (con imagen)           | **1 imagen** → modo de primer fotograma<br />**2 imágenes** → modo de primer y último fotograma |

---

### 🔑 Explicación de reglas clave

1. **Lógica general**:
   - **Sin entrada de imágenes** → activa automáticamente el modo de texto a video.
   - **Con entrada de imágenes** → activa el modo de imagen a video (el comportamiento específico se determina por la cantidad de imágenes).
2. **Tipos de modo de imagen a video**:
   - **Modo de primer fotograma** (1 imagen): el primer fotograma se fija como la imagen de entrada.
   - **Modo de primer y último fotograma** (2 imágenes): el primer y el último fotograma se fijan como las imágenes de entrada.
   - **Modo de fusión de múltiples imágenes** (1-3 imágenes): solo compatible con `veo31-fast-ingredients`, fusiona el contenido de múltiples imágenes para generar un video.
3. **Clasificación de modos**:

  - **Modo Fast**: `veo3-fast`, `veo31-fast`, `veo31-fast-ingredients`.
   - **Modo Quality**: `veo3`, `veo31` (mayor calidad de generación).

---

### ⚠️ Precauciones

- **Único modelo que requiere imágenes obligatoriamente**: `veo31-fast-ingredients` debe recibir imágenes (1-3), de lo contrario no podrá ejecutarse.
- **Límite de cantidad de imágenes**:
  - `veo31-fast-ingredients` admite entrada de **1-3 imágenes** (modo de fusión de múltiples imágenes).
  - Los demás modelos admiten como máximo **2 imágenes** de entrada (modo de primer y último fotograma).

## Función de imagen a video

Si desea generar un video según imágenes del primer y último fotograma, puede establecer el parámetro `action` en `image2video` e introducir el arreglo de enlaces de imágenes del primer y último fotograma `image_urls`.

A continuación, debemos completar las palabras clave que deben ampliarse en el siguiente paso para personalizar la generación de video, y se puede especificar el siguiente contenido:

- `model`: el modelo para generar video, principalmente `veo31-fast`, `veo3`, `veo31`, `veo3-fast` y `veo31-fast-ingredients`.
- `image_urls`: al seleccionar la acción de imagen a video `image2video`, se requieren los enlaces de las imágenes de referencia que se deben cargar.
- `prompt`: palabras clave.

El ejemplo de llenado es el siguiente:

<p><img src="https://cdn.acedata.cloud/8wvlqd.png" width="500" className="m-auto" /></p>

Después de completar, se genera automáticamente el siguiente código:

<p><img src="https://cdn.acedata.cloud/tgzfxi.png" width="500" className="m-auto" /></p>

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/veo/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "image2video",
    "model": "veo31-fast",
    "prompt": "Let it dance",
    "image_urls": ["https://cdn.acedata.cloud/7p1jhy.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Devolución de llamada asíncrona

Dado que el tiempo de generación de la API de Veo Videos Generation es relativamente largo, aproximadamente 1-2 minutos, si la API no responde durante mucho tiempo, la solicitud HTTP mantendrá continuamente la conexión, lo que provoca un consumo adicional de recursos del sistema, por lo que esta API también proporciona soporte para devoluciones de llamada asíncronas.

El proceso general es: cuando el cliente inicia una solicitud, especifica adicionalmente un campo `callback_url`; después de que el cliente inicia la solicitud de la API, la API devolverá inmediatamente un resultado, que incluye la información de un campo `task_id`, que representa el ID de la tarea actual. Cuando la tarea se complete, el resultado del video generado se enviará mediante POST JSON al `callback_url` especificado por el cliente, que también incluye el campo `task_id`, de modo que el resultado de la tarea puede asociarse mediante el ID.

## Manejo de errores

Al llamar a la API, si se encuentra un error, la API devolverá el código y la información de error correspondientes. Por ejemplo:

- `400 token_mismatched`：Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`：Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`：No autorizado, token de autorización no válido o faltante.
- `429 too_many_requests`：Demasiadas solicitudes, ha excedido el límite de velocidad.
- `500 api_error`：Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
