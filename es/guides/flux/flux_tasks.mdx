La función principal de Flux Tasks API es consultar el estado de ejecución de una tarea mediante el ID de tarea de la plataforma devuelto por Flux Images Generation API o Flux Videos API.

Este documento presentará en detalle las instrucciones de integración de Flux Tasks API, ayudándole a integrar fácilmente y aprovechar al máximo las potentes funciones de esta API. A través de Flux Tasks API, puede implementar fácilmente la consulta del estado de ejecución de las tareas de Flux Images Generation API.

Para un ejemplo completo de envío y sondeo de vídeos, consulte la [Guía de integración de Flux Videos API](https://platform.acedata.cloud/documents/flux-videos-integration). Consultar tareas existentes no genera cargos adicionales de generación.

## Proceso de solicitud

Para utilizar Flux Images Generation API, primero vaya a la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obtener su API Token y guárdelo para su uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; al finalizar, regresará automáticamente a la página actual.

**Un API Token puede invocar todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluirá créditos gratuitos para que pueda probar el servicio sin coste; cuando los créditos sean insuficientes, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Flux Images Generation API →](https://platform.acedata.cloud/documents/flux-images)

## Ejemplo de solicitud

Flux Tasks API puede utilizarse para consultar los resultados de Flux Images Generation API. Para saber cómo utilizar Flux Images Generation API, consulte la documentación de [Flux Images Generation API ](https://platform.acedata.cloud/documents/flux-images-integration).

Tomamos como ejemplo un ID de tarea devuelto por el servicio Flux Images Generation API para demostrar cómo utilizar esta API. Supongamos que tenemos un ID de tarea: 2db0168c-2373-4367-8d9a-9dc778802e8a; a continuación se demuestra cómo mediante la introducción de un ID de tarea.

### Configurar encabezados y cuerpo de la solicitud

**Request Headers** incluyen:

- `accept`: especifica que se reciban resultados de respuesta en formato JSON; aquí se rellena como `application/json`.
- `authorization`: la clave para invocar la API; después de solicitarla, puede seleccionarse directamente desde la lista desplegable.

**Request Body** incluye:

- `id`: el ID de la tarea cargada.
- `action`: el modo de operación sobre la tarea.

Algunos ejemplos de código son los siguientes:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/flux/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/flux/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "2c454ff3-4f8f-47f0-8147-acb29a84d1c2",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

El resultado devuelto contiene varios campos; el campo `request` es el request body al iniciar la tarea, mientras que el campo `response` es el response body devuelto después de que la tarea se complete. La descripción de los campos es la siguiente.

- `id`, el ID que genera esta tarea de imagen, utilizado para identificar de forma única esta tarea de generación de imágenes.
- `request`, la información de solicitud en la consulta de la tarea de imagen.
- `response`, la información de retorno en la consulta de la tarea de imagen.
- `created_at`, la hora de creación de la tarea, marca de tiempo Unix (segundos, punto flotante).
- `started_at`, la hora de inicio de ejecución de la tarea, marca de tiempo Unix (segundos, punto flotante).
- `finished_at`, la hora de finalización de la tarea, marca de tiempo Unix (segundos, punto flotante). Este campo no se devuelve cuando la tarea no se ha completado.
- `elapsed`, el tiempo de ejecución de la tarea, en segundos (punto flotante, conservando 3 decimales). Este campo no se devuelve cuando la tarea no se ha completado.

## Manejo de errores

Al llamar a la API, si se produce un error, la API devolverá el código de error y la información correspondientes. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`: No autorizado, token de autorización no válido o faltante.
- `429 too_many_requests`: Demasiadas solicitudes, ha superado el límite de tasa.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error
