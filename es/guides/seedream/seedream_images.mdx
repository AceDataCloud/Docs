Este artículo presenta las instrucciones de integración de SeeDream Images Generation API, que permite generar imágenes oficiales de SeeDream mediante la introducción de parámetros personalizados.

## Proceso de solicitud

Para utilizar SeeDream Images Generation API, primero acceda a la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obtener su API Token y guárdelo para utilizarlo posteriormente.

![]()

Si aún no ha iniciado sesión o no se ha registrado, será redirigido automáticamente a la página de inicio de sesión, donde se le invitará a registrarse e iniciar sesión. Una vez completado el proceso, volverá automáticamente a la página actual.

**Un único API Token permite acceder a todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** Al realizar la primera solicitud, recibirá una cuota gratuita que podrá utilizar para probar el servicio sin coste. Cuando el saldo sea insuficiente, podrá recargar el saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [SeeDream Images Generation API →](https://platform.acedata.cloud/documents/seedream-images)

## Selección del modelo

| Modelo | Escenarios de uso |
| ----------------------------------------------------------- | -------------------------------- |
| `doubao-seedream-5-5-261028` | Edición en múltiples rondas, generación de imágenes transparentes a partir de texto, edición transparente con múltiples imágenes de referencia, separación de capas y reconocimiento de capas de texto |
| `doubao-seedream-5-0-flash-260915` | Generación de imágenes individuales con baja latencia, edición con múltiples imágenes de referencia, edición de imágenes transparentes y separación de capas |
| `doubao-seedream-5-0-pro-260628` | Generación de imágenes individuales, edición detallada, edición de imágenes transparentes y separación de capas |
| `doubao-seedream-5-0-lite-260128` | Imágenes individuales, conjuntos de imágenes, salida en streaming y búsqueda en Internet |
| `doubao-seedream-4-5-251128` / `doubao-seedream-4-0-250828` | Generación y edición de imágenes de versiones anteriores |

5.5 y 5.0 Flash utilizan el mismo `POST /seedream/images`. Ambos admiten `1K`, `1.5K`, `2K` y hasta 10 imágenes de referencia. Las tareas de separación de capas de ambos modelos solo aceptan una imagen y devuelven una URL. En 5.5 se puede configurar `layer_decomposition_options: {"max_images": 12, "text_recognition": true}`. Se pueden generar hasta 100 imágenes (incluida la imagen base), y las capas de texto reconocibles devolverán el texto línea por línea y sus estilos en `data[].text_recognition`. 5.0 Flash devuelve como máximo 1 imagen base y 16 capas.

5.5 admite la generación directa de PNG transparentes mediante `background: "transparent"`. Para editar imágenes transparentes con 5.0 Flash, es necesario proporcionar una imagen de referencia que tenga un canal de transparencia. 5.5 cobra según el nivel de píxeles de las imágenes generadas correctamente y añade un cargo de 0.13 Credits por cada imagen de referencia introducida. 5.0 Flash cobra 0.31 Credits por cada imagen generada correctamente, y las imágenes de referencia son gratuitas. La separación de capas se factura según el número real de imágenes generadas correctamente, incluida la imagen base. Consulte los [precios en tiempo real](https://platform.acedata.cloud/services/seedream?tab=pricing).

## Uso básico

Primero, conozcamos el método básico de uso. Basta con introducir el prompt `prompt`, el comportamiento de generación `action` y el tamaño de la imagen `size` para obtener el resultado procesado. En primer lugar, es necesario transmitir un campo `action` sencillo, cuyo valor debe ser `generate`. A continuación, también debemos introducir el prompt. El contenido específico es el siguiente:

<p><img src="https://cdn.acedata.cloud/seedream_request_body.png" width="500" className="m-auto" /></p>

Como puede observarse, aquí hemos configurado los Request Headers, que incluyen:

- `accept`: qué formato de respuesta deseamos recibir. Aquí se establece como `application/json`, es decir, el formato JSON.
- `authorization`: la clave para llamar a la API. Después de solicitarla, se puede seleccionar directamente desde el menú desplegable.

Además, hemos configurado el Request Body, que incluye:

- `prompt`: el prompt.
- `model`: introduzca el ID completo del modelo indicado en la tabla anterior.
- `image`: URL de la imagen de entrada, cadena Base64 o matriz. 5.5, 5.0 Pro y 5.0 Flash admiten hasta 10 imágenes de referencia.
- `size`: nivel de resolución o `ancho x alto`. 5.5, 5.0 Pro y 5.0 Flash admiten `1K`, `1.5K` y `2K`. 5.0 Lite admite `2K`, `3K` y `4K`.
- `sequential_image_generation`: conjunto de imágenes: genera un grupo de imágenes relacionadas entre sí basándose en el contenido que usted introduce. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128` y `doubao-seedream-4-0-250828` admiten este parámetro, cuyo valor predeterminado es `disabled`.
- `stream`: controla si se activa el modo de salida en streaming. `doubao-seedream-5-0-lite-260128`, `doubao-seedream-4-5-251128` y `doubao-seedream-4-0-250828` admiten este parámetro, cuyo valor predeterminado es `false`.
- `response_format`: especifica el formato de retorno de las imágenes generadas. El valor predeterminado es `url`, y también admite `b64_json`.
- `watermark`: indica si se debe añadir una marca de agua a las imágenes generadas. El valor predeterminado es `true`.
- `output_format`: el formato de salida puede ser `jpeg` o `png`. El formato predeterminado de 5.5 es PNG, mientras que el de 5.0 Pro/Flash/Lite es JPEG.
- `tools`: configura las herramientas que debe utilizar el modelo. Actualmente admite `web_search` (búsqueda en Internet). Solo Seedream 5.0 Lite admite esta función.
- `optimize_prompt_options`: configuración de optimización del prompt. 5.0 Pro admite `standard`/`fast`; 5.5, 5.0 Flash, 5.0 Lite y 4.5 solo admiten `standard`; 4.0 admite `standard`/`fast`.
- `background`: admite `transparent` y `opaque`. 5.5 también admite `auto`. La salida transparente utiliza PNG.
- `layer_decomposition`: compatible con 5.5, 5.0 Pro y 5.0 Flash. Cuando se establece en `true`, es obligatorio introducir una imagen PNG/JPEG. Se puede omitir `prompt` para realizar la separación automática, o utilizar lenguaje natural/`<bbox>` para especificar los elementos. `size` admite `auto`/`1K`/`1.5K`/`2K`. Este modo no se puede utilizar junto con la generación de conjuntos de imágenes, el modo de streaming, la búsqueda en Internet ni `background`.
- `callback_url`: URL a la que se deben enviar los resultados mediante una devolución de llamada.
- `async`: indica si el procesamiento se realiza en modo asíncrono. Cuando se establece en `true`, la interfaz devuelve inmediatamente un `task_id`, sin necesidad de proporcionar `callback_url`. Posteriormente, se pueden consultar los resultados mediante `/seedream/tasks`.

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "doubao-seedream-5-0-lite-260128",
  "prompt": "A single matte blue cube centered on a clean white studio background, neutral lighting"
}'
```

## Tarea de edición de imágenes

Si queremos editar una imagen determinada, primero debemos introducir obligatoriamente en el parámetro `image` el enlace de la imagen que necesitamos editar.

- model: introducir el ID completo de un modelo compatible con la edición de imágenes de la tabla anterior.
- image: cargar la imagen que se necesita editar, una o varias.

El ejemplo de configuración es el siguiente:

<p><img src="https://cdn.acedata.cloud/seedream_edit.png" width="500" className="m-auto" /></p>

El código correspondiente:

```python
import requests

url = "https://api.acedata.cloud/seedream/images"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "doubao-seedream-4-0-250828",
  "prompt": "Keep the model pose and the liquid garment flowing shape unchanged. Change the clothing material from silver metal to completely transparent water (or glass). Through the liquid flow, the details of the model skin are visible. The light and shadow effect shifts from reflection to refraction.",
  "image": ["https://ark-project.tos-cn-beijing.volces.com/doc_image/seedream4_5_imageToimage.png"],
  "size": "2K",
  "watermark": False
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Separación de capas (Seedream 5.0 Pro)

La separación de capas divide una imagen de entrada en 1 imagen de fondo y hasta 16 capas PNG transparentes que se pueden editar de forma independiente. La siguiente solicitud permite que el modelo identifique automáticamente los elementos principales; si es necesario especificar los elementos, se puede añadir `prompt` y también se pueden utilizar coordenadas `<bbox>` normalizadas en el texto del prompt.

```shell
curl -X POST 'https://api.acedata.cloud/seedream/images' \
-H 'accept: application/json' \
-H 'authorization: Bearer ${token}' \
-H 'content-type: application/json' \
-d '{
  "model": "doubao-seedream-5-0-pro-260628",
  "image": "https://example.com/poster.png",
  "layer_decomposition": true,
  "size": "2K",
  "watermark": false
}'
```

El `data` devuelto está ordenado de abajo hacia arriba según `z_index`. La imagen de fondo tiene un `z_index` de 0; las capas también incluyen `name`, `description` y `bounding_box.absolute`/`normalized`. Al recomponer utilizando coordenadas absolutas, se debe escalar cada capa a `[right-left, bottom-top]`, colocarla en `[left, top]` y, a continuación, superponerlas en orden ascendente de `z_index`. Si falla la generación de cualquier capa, toda la operación de separación falla.

## Salida en streaming

Cuando Lite/4.x configura `stream: true`, el encabezado de la solicitud utiliza `accept: application/x-ndjson`. La interfaz devuelve línea por línea `image_generation.partial_succeeded` o `image_generation.partial_failed` y, finalmente, devuelve el único evento `image_generation.completed` junto con el `usage` final; solo el evento de finalización activa la facturación una vez. El modo streaming no se puede utilizar junto con `async` ni con `callback_url`.

## Devolución de llamada asíncrona

Debido a que la generación mediante la API SeeDream Images Generation requiere relativamente mucho tiempo, aproximadamente entre 1 y 2 minutos, si la API no responde durante mucho tiempo, la solicitud HTTP mantendrá la conexión abierta, lo que provocará un consumo adicional de recursos del sistema. Por ello, esta API también ofrece compatibilidad con devoluciones de llamada asíncronas.

El proceso general es el siguiente: cuando el cliente inicia una solicitud, especifica adicionalmente un campo `callback_url`. Después de que el cliente inicia la solicitud a la API, la API devuelve inmediatamente un resultado que contiene la información de un campo `task_id`, que representa el ID de la tarea actual. Cuando la tarea finaliza, el resultado de la imagen generada se envía al `callback_url` especificado por el cliente mediante una solicitud POST JSON, que también incluye el campo `task_id`, de modo que los resultados de las tareas se pueden vincular mediante el ID.

Si no tienes una dirección pública disponible para recibir devoluciones de llamada, también puedes omitir `callback_url` y establecer el campo `async` en `true` en la solicitud. En este caso, la interfaz también devolverá inmediatamente `task_id`, pero no enviará el resultado. Deberás utilizar ese `task_id` para llamar a la interfaz `/seedream/tasks` y consultar periódicamente el estado de la tarea hasta obtener el resultado final.

## Gestión de errores

Al llamar a la API, si se produce un error, la API devolverá el código y la información de error correspondientes. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`: No autorizado, token de autorización no válido o ausente.
- `429 too_many_requests`: Demasiadas solicitudes, se ha superado el límite de frecuencia.
- `500 api_error`: Error interno del servidor, se ha producido un problema en el servidor.

### Ejemplo de respuesta de error

