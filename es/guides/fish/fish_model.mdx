Esta interfaz se basa en la [API Model de Fish Audio](https://docs.fish.audio/resources/api-reference/model) y se utiliza para **crear un nuevo clon de timbre basado en una muestra de audio**. La dirección es `POST https://api.acedata.cloud/fish/model`.

> Para la búsqueda paginada de timbres existentes, consulte la [API Fish Model Query](https://platform.acedata.cloud/documents/fish-model-query); para consultar los detalles de un solo timbre por `_id`, consulte la [API Fish Model Get](https://platform.acedata.cloud/documents/fish-model-get).

## Proceso de Solicitud

Para usar la API Fish Model, primero dirígete a la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obtener tu API Token, que debes guardar para uso futuro.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no has iniciado sesión o registrado, serás redirigido automáticamente a la página de inicio de sesión que te invitará a registrarte e iniciar sesión; una vez completado, serás devuelto automáticamente a la página actual.

**Un API Token es suficiente para acceder a todos los servicios de la plataforma, no es necesario solicitar uno por cada servicio.** La primera solicitud te otorgará un crédito gratuito para que puedas probar; si el crédito es insuficiente, puedes recargar el saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Fish Model API →](https://platform.acedata.cloud/services/fish)

## Campos del Cuerpo de Solicitud

| Campo                    | Tipo       | Requerido | Descripción                                                                      |
| ----------------------- | -------- | -------- | ----------------------------------------------------------------------------- |
| `title`                 | string   | Sí       | Nombre del timbre, utilizado para identificar en la lista de la consola.      |
| `voices`                | string   | Sí       | URL HTTP(S) de la muestra de audio (**una sola cadena**, no un array). Esta interfaz no admite carga multipart/binaria, coloca el audio en cualquier almacenamiento de objetos accesible públicamente. |
| `description`           | string   | No       | Descripción del timbre.                                                         |
| `cover_image`           | string   | No       | URL HTTP(S) de la imagen de portada.                                          |
| `tags`                  | string[] | No       | Etiquetas de búsqueda de la biblioteca pública, por ejemplo `["male","narration","zh"]`. |
| `texts`                 | string[] | No       | Texto de referencia correspondiente a la muestra (para corregir la pronunciación). |
| `enhance_audio_quality` | boolean  | No       | Si se debe mejorar la calidad del audio de la muestra antes del entrenamiento. |
| `generate_sample`       | boolean  | No       | Si se debe generar automáticamente un audio de muestra después de completar el entrenamiento. |

> Los campos son idénticos a los de upstream, consulte también la [documentación oficial de Fish](https://docs.fish.audio/resources/api-reference/model).

## Ejemplo: Crear un timbre de clon privado

```shell
curl -X POST 'https://api.acedata.cloud/fish/model' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "title": "Mi timbre de clon",
    "description": "Timbre en chino clonado de una grabación de podcast",
    "voices": "https://example.com/sample-voice.mp3",
    "cover_image": "https://cdn.acedata.cloud/e724d7f13d.png"
  }'
```

> Nota: `voices` debe ser **una cadena** (una sola URL de audio), no un array. Si se envía como `["..."]`, upstream lo rechazará.

`_id` puede ser utilizado como el valor del campo `reference_id` en la posterior [API Fish TTS](https://platform.acedata.cloud/documents/fish-tts) para realizar la síntesis de voz con este timbre clonado:

```shell
curl -X POST 'https://api.acedata.cloud/fish/tts' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "text": "Hola, esta es una voz sintetizada usando el timbre de clon que acabo de crear.",
    "reference_id": "e5c6db52c3ed417f9cb2e5a33fb04667",
    "format": "mp3"
  }'
```

## Requisitos de la Muestra

Valores de experiencia (coinciden con upstream, consulte la [documentación oficial de Fish](https://docs.fish.audio/resources/api-reference/model)):

- La duración recomendada es de más de 30 segundos y menos de 5 minutos; más de 10 minutos tiene un rendimiento marginal.
- La tasa de muestreo debe ser de 16 kHz o más, se puede usar mono o estéreo.
- El contenido debe ser lo más limpio posible: sin música de fondo, ecos, ruido ambiental evidente; un solo hablante.
- Se recomienda el formato `mp3` / `wav`.

Si no estás seguro de la calidad de la muestra, puedes enviar `enhance_audio_quality: true` para que upstream realice primero la mejora de calidad.

## Descripción de la Facturación

Crear un modelo de clon de timbre (`POST /fish/model`) es gratuito, no se cobra ninguna tarifa; la interfaz de consulta de timbres ([Fish Model Query](https://platform.acedata.cloud/documents/fish-model-query), [Fish Model Get](https://platform.acedata.cloud/documents/fish-model-get)) también es gratuita. Los costos solo se generan al llamar a [Fish TTS](https://platform.acedata.cloud/documents/fish-tts) para sintetizar voz según el uso.

## Manejo de Errores

- `400 token_mismatched`: Parámetros de solicitud faltantes o no válidos (lo más común es que `voices` no sea una URL, o se haya enviado como un array).
- `401 invalid_token`: El token de autenticación no existe o es inválido.
- `429 too_many_requests`: Se ha activado el límite de velocidad de la cuenta.
- `500 api_error`: Error interno del servidor.

Ejemplo de respuesta de error:
```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "se requiere voices y debe ser una URL HTTP(S) que apunte a un archivo de audio"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## Conclusión

Llamar a esta interfaz solo requiere preparar una URL de audio de muestra que sea accesible públicamente, ponerla en el campo `voices` para obtener el `_id`, y luego alimentarlo al `reference_id` de `/fish/tts` para completar el proceso de extremo a extremo de "clonación → síntesis". Un punto común de error es que `voices` debe ser una cadena, no un arreglo.
