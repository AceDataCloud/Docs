La función principal de Fish Tasks API es consultar el estado de ejecución de una tarea introduciendo el ID de tarea generado por Fish Audios Generation API.

Este documento presentará en detalle las instrucciones de integración de Fish Tasks API, ayudándole a integrar fácilmente y aprovechar plenamente las potentes funciones de esta API. A través de Fish Tasks API, puede implementar fácilmente la consulta del estado de ejecución de tareas de Fish Audios Generation API.

## Proceso de solicitud

Para utilizar Fish Audios Generation API, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo para su uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión ni se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; una vez completado, regresará automáticamente a la página actual.

**Un API Token puede invocar todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluirá créditos gratuitos para que pueda probar el servicio sin costo; cuando los créditos sean insuficientes, puede recargar el saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Fish Audios Generation API →](https://platform.acedata.cloud/documents/fish-tts)

## Ejemplo de solicitud

Fish Tasks API puede utilizarse para consultar los resultados de Fish Audios Generation API. Para saber cómo utilizar Fish Audios Generation API, consulte la documentación de [Fish Videos Generation API ](https://platform.acedata.cloud/documents/fish-tts-integration)。

### Configurar los encabezados y el cuerpo de la solicitud

**Request Headers** incluyen:

- `accept`: especifica que se reciban resultados de respuesta en formato JSON; aquí se completa como `application/json`.
- `authorization`: la clave para invocar la API, que puede seleccionarse directamente en el menú desplegable después de solicitarla.

**Request Body** incluye:

- `id`: el ID de tarea cargado.
- `action`: el método de operación sobre la tarea.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/fish/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "2725a2d3-f87e-4905-9c53-9988d5a7b2f5",
  "action": "retrieve"
}'
```


El resultado devuelto tiene varios campos. El campo `request` es el request body al iniciar la tarea, mientras que el campo `response` es el response body devuelto después de que se complete la tarea. La descripción de los campos es la siguiente.

- `id`, el ID que genera esta tarea, utilizado para identificar de forma única esta tarea de generación.
- `request`, la información de solicitud en la tarea de consulta.
- `response`, la información devuelta en la tarea de consulta; cuando finalmente tiene éxito, `cost.amount` dentro de este representa los Credits realmente deducidos para esta síntesis.
- `created_at`, hora de creación de la tarea, marca de tiempo Unix (segundos, punto flotante).
- `started_at`, hora de inicio de ejecución de la tarea, marca de tiempo Unix (segundos, punto flotante).
- `finished_at`, hora de finalización de la tarea, marca de tiempo Unix (segundos, punto flotante). Este campo no se devuelve cuando la tarea no está completada.
- `elapsed`, tiempo de ejecución de la tarea, en segundos (punto flotante, conserva 3 decimales). Este campo no se devuelve cuando la tarea no está completada.

## Manejo de errores

Al llamar a la API, si se produce un error, la API devolverá el código de error y el mensaje correspondientes. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`: No autorizado, token de autorización no válido o faltante.
- `429 too_many_requests`: Demasiadas solicitudes, ha excedido el límite de frecuencia.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {

    "message": "fetch failed"

  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
