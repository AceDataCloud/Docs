Este documento presentará la integración del Sora Videos Generation API, a través del cual se pueden ingresar parámetros personalizados para generar videos oficiales de Sora. Esta API admite dos modos de versión:

- **Versión 1 (modo clásico)**: admite parámetros como `duration` (10/15/25 segundos), `orientation` (horizontal/vertical), `size` (pequeño/grande), imágenes de referencia `image_urls`, video de personaje `character_url`, entre otros.
- **Versión 2 (modo colaborador)**: admite parámetros como `seconds` (4/8/12 segundos), resolución a nivel de píxel `size` (por ejemplo, 1280x720), imágenes de referencia `input_reference`, entre otros.

## Proceso de Solicitud

Para utilizar el Sora Videos Generation API, primero dirígete a [Ace Data Cloud Console](https://platform.acedata.cloud/console/applications) para obtener tu API Token, que debes guardar como respaldo.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si aún no has iniciado sesión o registrado, serás redirigido automáticamente a la página de inicio de sesión que te invitará a registrarte e iniciar sesión, y una vez completado, regresarás automáticamente a la página actual.

**Un API Token es suficiente para acceder a todos los servicios de la plataforma, no es necesario solicitar uno por cada servicio.** La primera solicitud incluirá un crédito gratuito para que puedas probar; si el crédito es insuficiente, puedes recargar el saldo general en [la consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Sora Videos Generation API →](https://platform.acedata.cloud/documents/sora-videos)

## Uso Básico (Versión 1)

Primero, comprende la forma básica de uso de la Versión 1, que consiste en ingresar la palabra clave `prompt`, un array de enlaces de imágenes de referencia `image_urls` y el modelo `model`, para obtener el resultado procesado. El contenido específico es el siguiente:

<p><img src="https://cdn.acedata.cloud/h8dyz3.png" width="500" className="m-auto" /></p>

Aquí podemos ver que hemos configurado los Request Headers, que incluyen:

- `accept`: el formato de respuesta que deseas recibir, aquí se establece como `application/json`, es decir, en formato JSON.
- `authorization`: la clave para llamar a la API, que puedes seleccionar directamente después de solicitarla.

Además, se configuró el Request Body, que incluye:

- `model`: el modelo para generar el video, admite `sora-2` (modo estándar) y `sora-2-pro` (modo de alta definición). El `sora-2-pro` puede soportar videos con `duration` de 25 segundos, mientras que el `sora-2` solo admite 10 y 15 segundos.
- `size`: la claridad del video, `small` es claridad estándar, `large` es claridad HD (solo Versión 1).
- `duration`: la duración del video, admite 10, 15 y 25 segundos, donde 25 segundos solo es compatible con `sora-2-pro` (solo Versión 1).
- `orientation`: la dirección del marco, admite `landscape` (horizontal), `portrait` (vertical) (solo Versión 1).
- `image_urls`: array de enlaces de imágenes de referencia, utilizado para generar video a partir de imágenes (solo Versión 1).
- `character_url`: enlace del video del personaje, no se pueden incluir personas reales en el video (solo Versión 1).
- `character_start`/`character_end`: segundos de inicio y fin de la aparición del personaje, con un rango de diferencia de 1-3 segundos (solo Versión 1).
- `prompt`: palabra clave (requerido).
- `callback_url`: URL para la devolución de llamada asíncrona de resultados.
- `async`: opcional, si se establece en `true`, la interfaz devuelve inmediatamente `task_id`, sin necesidad de proporcionar `callback_url`, y luego se puede consultar el resultado a través de la interfaz de consulta de tareas correspondiente.
- `version`: versión de la API, `"1.0"` (por defecto) o `"2.0"`.

## Tarea de Video a partir de Imágenes (Versión 1)

Si deseas realizar una tarea de video a partir de imágenes, primero el parámetro `image_urls` debe incluir enlaces de imágenes de referencia, lo que te permitirá especificar el siguiente contenido:

- `image_urls`: array de enlaces de imágenes de referencia utilizados en esta tarea de video a partir de imágenes. Ten en cuenta que no se pueden enviar imágenes de personas reales con rostros, ya que esto podría causar que la tarea falle.

Un ejemplo de llenado es el siguiente:

<p><img src="https://cdn.acedata.cloud/ch7x3t.png" width="500" className="m-auto" /></p>

Una vez completado, se generó automáticamente el siguiente código:

<p><img src="https://cdn.acedata.cloud/z1ud8l.png" width="500" className="m-auto" /></p>

El código correspondiente:
```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "size": "large",
    "duration": 15,
    "orientation": "landscape",
    "prompt": "gato corriendo por el río",
    "model": "sora-2",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Modo Versión 2.0

Además del modo Versión 1.0 mencionado anteriormente, esta API también admite el modo Versión 2.0, que se puede habilitar configurando el parámetro `version` como `"2.0"`. El modo Versión 2.0 admite una duración de video más corta y un control de resolución a nivel de píxel.

### Descripción de parámetros de la Versión 2.0

| Parámetro        | Tipo     | ¿Es obligatorio? | Descripción                                           |
| ---------------- | -------- | ---------------- | ----------------------------------------------------- |
| `version`        | string   | Sí               | Configurado como `"2.0"`                             |
| `prompt`         | string   | Sí               | Palabra clave para generar el video                   |
| `model`          | string   | No               | `sora-2` (predeterminado) o `sora-2-pro`             |
| `duration`       | integer  | No               | Duración del video: `4` (predeterminado), `8`, `12` segundos |
| `size`           | string   | No               | Resolución: `720x1280` (predeterminado), `1280x720`, `1024x1792`, `1792x1024` |
| `image_urls`     | array    | No               | Array de URL de imágenes de referencia, solo se usa la primera imagen, el tamaño de la imagen debe coincidir con el parámetro `size` |
| `callback_url`   | string   | No               | URL de callback asíncrono                             |

### Ejemplo básico

```shell
curl -X POST 'https://api.acedata.cloud/sora/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "version": "2.0",
  "prompt": "gato corriendo por el río",
  "model": "sora-2",
  "duration": 8,
  "size": "1280x720"
}'
```

Código correspondiente en Python:

### Uso de imágenes de referencia (Versión 2.0)

En el modo de Versión 2.0, se puede pasar imágenes de referencia a través del parámetro `image_urls` para guiar la generación de video (solo se utiliza la primera imagen):

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "version": "2.0",
    "prompt": "una persona caminando por un hermoso jardín",
    "model": "sora-2",
    "duration": 4,
    "size": "1280x720",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

> **Nota**: Las dimensiones de la imagen de referencia deben coincidir con el parámetro `size`, por ejemplo, si `size` es `1280x720`, las dimensiones de la imagen de referencia deben ser 1280×720.

### Comparación de parámetros entre Versión 1.0 y Versión 2.0

| Parámetro         | Versión 1.0           | Versión 2.0                             |
| ----------------- | --------------------- | --------------------------------------- |
| `version`         | 1.0 (predeterminado)  | 2.0                                     |
| `prompt`          | ✅                     | ✅                                       |
| `model`           | ✅ sora-2 / sora-2-pro | ✅ sora-2 / sora-2-pro                   |
| `duration`        | ✅ 10/15/25 segundos    | ✅ 4/8/12 segundos                        |
| `orientation`     | ✅ paisaje/retrato     | ❌                                       |
| `size`            | ✅ pequeño/grande      | ✅ 720x1280/1280x720/1024x1792/1792x1024 |
| `image_urls`      | ✅ múltiples imágenes de referencia | ✅ solo se utiliza la primera              |
| `character_url`   | ✅                     | ❌                                       |
| `callback_url`    | ✅                     | ✅                                       |

## Callback asíncrono

Debido a que el tiempo de generación de la API de Sora Videos es relativamente largo, aproximadamente 1-2 minutos, si la API no responde durante mucho tiempo, la solicitud HTTP mantendrá la conexión, lo que provocará un consumo adicional de recursos del sistema, por lo que esta API también ofrece soporte para callbacks asíncronos.

El flujo general es: cuando el cliente inicia la solicitud, especifica un campo adicional `callback_url`, después de que el cliente inicia la solicitud de API, la API devolverá inmediatamente un resultado que contiene un campo de información `task_id`, que representa el ID de la tarea actual. Cuando la tarea se completa, el resultado del video generado se enviará al `callback_url` especificado por el cliente en formato JSON POST, que también incluye el campo `task_id`, de modo que el resultado de la tarea se pueda asociar mediante el ID.

## Manejo de errores

Al llamar a la API, si se encuentra con un error, la API devolverá el código de error y la información correspondiente. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o inválidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o inválidos.
- `401 invalid_token`: No autorizado, token de autorización inválido o faltante.
- `429 too_many_requests`: Demasiadas solicitudes, ha superado el límite de tasa.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {

    "message": "la recuperación falló"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
