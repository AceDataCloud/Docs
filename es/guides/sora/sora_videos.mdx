Este documento presenta las instrucciones para la integración de la API de Generación de Videos Sora, mediante la cual se pueden generar videos oficiales de Sora ingresando parámetros personalizados. Esta API soporta dos modos de versión:

- **Versión 1 (modo clásico)**: soporta parámetros como `duration` (10/15/25 segundos), `orientation` (horizontal/vertical), `size` (small/large resolución), imágenes de referencia `image_urls`, enlace de personaje `character_url`, entre otros.
- **Versión 2 (modo colaborador)**: soporta `seconds` (4/8/12 segundos), resolución a nivel de píxel `size` (por ejemplo 1280x720), imágenes de referencia `input_reference`, entre otros parámetros.

## Proceso de solicitud

Para usar la API, primero debe solicitar el servicio correspondiente en la página de [Sora Videos Generation API](https://platform.acedata.cloud/documents/99a24421-2e22-4028-8201-e19cb834b67e). Al ingresar, haga clic en el botón «Acquire», como se muestra en la imagen:

![](https://cdn.acedata.cloud/q6ytrc.png)

Si aún no ha iniciado sesión o registrado, será redirigido automáticamente a la página de inicio de sesión para registrarse e ingresar; después de hacerlo, volverá automáticamente a esta página.

Al solicitar por primera vez, se otorgará un crédito gratuito para usar la API sin costo.

## Uso básico (Versión 1)

Primero, conozcamos la forma básica de uso de la Versión 1, que consiste en ingresar la palabra clave `prompt`, un arreglo de enlaces de imágenes de referencia `image_urls` y el modelo `model` para obtener el resultado procesado. El contenido específico es el siguiente:

<p><img src="https://cdn.acedata.cloud/h8dyz3.png" width="500" className="m-auto" /></p>

Aquí configuramos los encabezados de la solicitud (Request Headers), incluyendo:

- `accept`: formato de respuesta deseado, aquí se usa `application/json` para formato JSON.
- `authorization`: clave para llamar a la API, que puede seleccionarse tras la solicitud.

Además, configuramos el cuerpo de la solicitud (Request Body), que incluye:

- `model`: modelo para generar el video, soporta `sora-2` (modo estándar) y `sora-2-pro` (modo HD). `sora-2-pro` soporta videos de 25 segundos, mientras que `sora-2` solo 10 o 15 segundos (solo Versión 1).
- `size`: resolución del video, `small` para estándar y `large` para HD (solo Versión 1).
- `duration`: duración del video, soporta 10, 15 y 25 segundos; 25 segundos solo con `sora-2-pro` (solo Versión 1).
- `orientation`: orientación del video, soporta `landscape` (horizontal) y `portrait` (vertical) (solo Versión 1).
- `image_urls`: arreglo de enlaces de imágenes de referencia para generación de video a partir de imágenes (solo Versión 1).
- `character_url`: enlace de personaje, no debe aparecer persona real en el video (solo Versión 1).
- `character_start`/`character_end`: segundos de inicio y fin de aparición del personaje, rango de 1 a 3 segundos (solo Versión 1).
- `prompt`: palabra clave (obligatorio).
- `callback_url`: URL para callback asíncrono.
- `version`: versión de la API, `1` (por defecto) o `2`.

## Tarea de generación de video a partir de imágenes (Versión 1)

Para realizar una tarea de generación de video a partir de imágenes, debe pasar el parámetro `image_urls` con enlaces de imágenes de referencia, que pueden incluir:

- `image_urls`: arreglo de enlaces de imágenes para la tarea de generación de video. No debe incluir imágenes reales con rostros humanos, ya que puede causar fallo en la tarea.

Ejemplo de llenado:

<p><img src="https://cdn.acedata.cloud/ch7x3t.png" width="500" className="m-auto" /></p>

Al completar, se genera automáticamente el código:

<p><img src="https://cdn.acedata.cloud/z1ud8l.png" width="500" className="m-auto" /></p>

Código correspondiente:

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "size": "large",
    "duration": 15,
    "orientation": "landscape",
    "prompt": "cat running on the river",
    "model": "sora-2",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
```

## Tarea de generación de video con personaje (Versión 1)

- `character_url`: enlace del video para crear el personaje, sin personas reales.

## Modo Versión 2

Además del modo Versión 1, esta API también soporta el modo Versión 2, que se activa configurando el parámetro `version` a `2`. El modo Versión 2 soporta videos de menor duración y control de resolución a nivel de píxel.

### Descripción de parámetros de la Versión 2

| Parámetro      | Tipo    | Obligatorio | Descripción                                      |
|----------------|---------|-------------|-------------------------------------------------|
| `version`      | integer | Sí          | Debe establecerse en `2`                         |
| `prompt`       | string  | Sí          | Palabra clave para generar el video              |
| `model`        | string  | No          | `sora-2` (por defecto) o `sora-2-pro`            |
| `duration`     | integer | No          | Duración del video: `4` (por defecto), `8`, `12` segundos |
| `size`         | string  | No          | Resolución: `720x1280` (por defecto), `1280x720`, `1024x1792`, `1792x1024` |
| `image_urls`   | array   | No          | Arreglo de URLs de imágenes de referencia, solo se usa la primera imagen, la dimensión debe coincidir con `size` |
| `callback_url` | string  | No          | URL para callback asíncrono                       |

### Ejemplo básico

```shell
curl -X POST 'https://api.acedata.cloud/sora/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "version": 2,
  "prompt": "cat running on the river",
  "model": "sora-2",
  "duration": 8,
  "size": "1280x720"
}'
```

Código Python correspondiente:


### Uso de imágenes de referencia (Versión 2)

En el modo Versión 2, puede pasar imágenes de referencia mediante el parámetro `image_urls` para guiar la generación del video (solo se usa la primera imagen):

```python
import requests

url = "https://api.acedata.cloud/sora/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "version": 2,
    "prompt": "a person walking through a beautiful garden",
    "model": "sora-2",
    "duration": 4,
    "size": "1280x720",
    "image_urls": ["https://cdn.acedata.cloud/11wfp4.png"]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

> **Nota**: La dimensión de la imagen de referencia debe coincidir con el parámetro `size`. Por ejemplo, si `size` es `1280x720`, la imagen debe tener dimensiones 1280×720.

### Comparación de parámetros entre Versión 1 y Versión 2

| Parámetro       | Versión 1           | Versión 2                                    |
|-----------------|---------------------|----------------------------------------------|
| `version`       | 1 (por defecto)      | 2                                            |
| `prompt`        | ✅                  | ✅                                           |
| `model`         | ✅ sora-2 / sora-2-pro | ✅ sora-2 / sora-2-pro                        |
| `duration`      | ✅ 10/15/25 segundos | ✅ 4/8/12 segundos                            |
| `orientation`   | ✅ landscape/portrait | ❌                                           |
| `size`          | ✅ small/large       | ✅ 720x1280/1280x720/1024x1792/1792x1024     |
| `image_urls`    | ✅ múltiples imágenes | ✅ solo la primera imagen                      |
| `character_url` | ✅                   | ❌                                           |
| `callback_url`  | ✅                   | ✅                                           |

## Callback asíncrono

Dado que la generación de videos con la API Sora Videos Generation puede tardar entre 1 y 2 minutos, si la API no responde en ese tiempo, la conexión HTTP se mantiene abierta, consumiendo recursos del sistema. Por ello, la API soporta callbacks asíncronos.

El flujo es: el cliente realiza la solicitud incluyendo un campo adicional `callback_url`. La API responde inmediatamente con un resultado que incluye un `task_id` que identifica la tarea. Cuando la tarea finaliza, el resultado se envía mediante POST en formato JSON a la URL `callback_url` especificada, incluyendo también el `task_id`, lo que permite relacionar la respuesta con la tarea.

![](https://cdn.acedata.cloud/cjjfly.png)

Copie esta URL para usarla como webhook, por ejemplo: `https://webhook.site/eb238c4f-da3b-47a5-a922-a93aa5405daa`.

Luego, configure el campo `callback_url` con esta URL y complete los demás parámetros, como se muestra:

## Manejo de errores

Al llamar a la API, si ocurre un error, esta devolverá un código y mensaje de error correspondiente. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente por parámetros faltantes o inválidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente por parámetros faltantes o inválidos.
- `401 invalid_token`: No autorizado, token de autorización inválido o ausente.
- `429 too_many_requests`: Demasiadas solicitudes, se ha excedido el límite de tasa.
- `500 api_error`: Error interno del servidor.

### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
