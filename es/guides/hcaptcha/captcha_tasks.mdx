Este documento presenta la interfaz de consulta de tareas asíncronas de captcha `POST /captcha/tasks`. Cuando llames a cualquier interfaz de captcha (serie de token o serie de reconocimiento) pasando `async: true`, la interfaz devolverá inmediatamente un `task_id`, que luego podrás usar para sondear esta interfaz y obtener el resultado final. Es adecuado para escenarios de rotación de múltiples decodificadores (multi-solver rotation): después de enviar la tarea, obtienes inmediatamente el `task_id`, primero puedes programar otros decodificadores y luego volver más tarde a obtener el resultado.

> 📘 Documentación interactiva completa (incluida la depuración en línea): [API de consulta de tareas de captcha →](https://platform.acedata.cloud/documents/captcha-tasks)

## Proceso de solicitud

Para usar esta interfaz, primero ve a [la consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obtener tu API Token, que debes guardar como respaldo. **Un API Token es suficiente para acceder a todos los servicios de la plataforma, no es necesario solicitar uno por cada servicio.**

## Uso básico

### Paso 1: Crear una tarea de forma asíncrona

En el cuerpo de la solicitud de cualquier interfaz de captcha, pasa `async: true`, la interfaz devolverá inmediatamente un `task_id` (HTTP 201), sin bloquear la espera:

```shell
curl -X POST 'https://api.acedata.cloud/captcha/token/recaptcha2' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "website_key": "6Le-wvkSAAAAAPBMRTvw0Q4Muexq9bi0DJwx_mJ-",
  "website_url": "https://www.google.com/recaptcha/api2/demo",
  "async": true
}'
```

```json
{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "trace_id": "2efa9340-b21b-4e26-9e14-4aac95f343ab"
}
```

### Paso 2: Sondear resultados con task_id

Usa el `task_id` devuelto en el paso anterior para sondear `POST /captcha/tasks` (se recomienda cada 3~5 segundos):

```shell
curl -X POST 'https://api.acedata.cloud/captcha/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002"
}'
```

Mientras se procesa, devolverá `status: processing`:

```json
{ "success": true, "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002", "status": "processing" }
```

Cuando se complete el procesamiento, devolverá `status: ready` y el campo de resultado correspondiente; la estructura del campo es completamente consistente con el modo sincrónico:

- **Serie de token** (hcaptcha, recaptcha2, recaptcha3) devuelve `token`:

```json
{
  "success": true,
  "task_id": "61138bb6-19aa-11ec-a9c8-0242ac110002",
  "status": "ready",
  "token": "03AFcWeA5kjJyDQ9S1a9UYimR6nuxnpEnAs5x2Pixao0dXZhMB......"
}
```

- **Clasificación de reconocimiento** (recognition/recaptcha2, recognition/hcaptcha) devuelve `solution`; **recognition/image2text** devuelve `text`.

`/captcha/tasks` es común para todas las interfaces de captcha (serie de token y reconocimiento), puedes sondear con el mismo `task_id`.

La respuesta de `status: ready` también incluirá campos de tiempo.

- `started_at`, tiempo de inicio del procesamiento de la tarea, marca de tiempo Unix (segundos, flotante).
- `finished_at`, tiempo de producción del resultado de la tarea, marca de tiempo Unix (segundos, flotante). No se devuelve este campo mientras se esté procesando.
- `elapsed`, tiempo de procesamiento de la tarea, en segundos (flotante, con 3 decimales). No se devuelve este campo mientras se esté procesando.

## Instrucciones de facturación

En modo asíncrono, la creación de tareas y el sondeo de "procesando" no generan costos; **solo se cobra una vez al obtener el resultado exitosamente** (el mismo precio que en modo sincrónico). Por lo tanto, cancelar tareas no completadas en la rotación no generará costos.

## Manejo de errores

Al llamar a esta interfaz, si encuentras un error, se devolverá el código y la información de error correspondiente. Por ejemplo:

- `400 invalid_request`: falta el parámetro `task_id` en la solicitud.
- `401 invalid_token`: no autorizado, el Token de autorización es inválido o está ausente.
- `404 not_found`: `task_id` no existe o no pertenece a la cuenta actual.

### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {
    "code": "not_found",
    "message": "tarea no encontrada"
  }
}
```
