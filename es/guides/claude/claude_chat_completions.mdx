Anthropic Claude es un sistema de conversación de IA muy potente que, con solo ingresar un prompt, puede generar respuestas fluidas y naturales en apenas unos segundos. Claude se distingue en la industria por sus excelentes capacidades de comprensión y generación de lenguaje. Hoy en día, Claude ya se utiliza ampliamente en diversas industrias y ámbitos, y su influencia es cada vez más notable. Ya sea para conversaciones cotidianas, escritura creativa, consultas profesionales o programación de código, Claude puede proporcionar una asistencia inteligente sorprendente, mejorando enormemente la eficiencia laboral y la creatividad humanas.

Este documento presenta principalmente el proceso de uso de las operaciones de Claude Chat Completion API; con ella podemos utilizar fácilmente la función de conversación oficial de Claude.

## Proceso de solicitud

Para utilizar Claude Chat Completion API, primero ve a la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obtener tu API Token y conservarlo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no has iniciado sesión o no te has registrado, serás redirigido automáticamente a la página de inicio de sesión para invitarte a registrarte e iniciar sesión; al finalizar, volverás automáticamente a la página actual.

**Un solo API Token puede invocar todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluye crédito gratuito, que permite una experiencia sin costo; cuando el crédito sea insuficiente, puedes recargar saldo universal en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Uso básico

A continuación, puedes completar el contenido correspondiente en la interfaz, como se muestra en la imagen:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Al utilizar esta interfaz por primera vez, necesitamos completar al menos tres elementos. Uno es `authorization`, que puede seleccionarse directamente en la lista desplegable. Otro parámetro es `model`, y puedes elegir modelos públicos como `claude-opus-5-5`, `claude-fable-5-1`, etc.; el anterior `claude-fable-5` aún puede seguir utilizándose. El último parámetro es `messages`, que es un arreglo de prompts de consulta; cada elemento contiene `role` y `content`; `role` admite `user`, `assistant`, `system`, y `content` es el contenido específico. Cuando se requieran bloques completos de contenido de razonamiento de Claude, firmas y semántica de herramientas nativas, sigue utilizando Messages API.

Al mismo tiempo, puedes notar que a la derecha se genera el código de llamada correspondiente; puedes copiar el código y ejecutarlo directamente, o hacer clic directamente en el botón «Try» para realizar pruebas.

Parámetros opcionales comunes:

- `max_tokens`: limita el número máximo de tokens en una sola respuesta.
- `temperature`: aleatoriedad de la generación, entre 0 y 2; cuanto mayor sea el valor, más divergente será.
- `n`: cuántas respuestas candidatas se generan de una vez.
- `response_format`: configuración del formato de retorno.

`claude-opus-5-5` admite Chat Completions normales y en streaming; este modelo solo permite `n=1`. No establezcas para él una `temperature` inferior a 1 ni un `top_p` no predeterminado; para llamadas de herramientas utiliza `tool_choice: "auto"` y no fuerces la especificación de una herramienta. La interfaz compatible con Chat no devolverá bloques de contenido de razonamiento nativo.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Después de la llamada, observamos que el resultado devuelto es el siguiente:

```json

  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },

    }
  ],

    "prompt_tokens": 8,

    "total_tokens": 20,

    },

      "reasoning_tokens": 0
    }

```

El resultado devuelto tiene varios campos, que se presentan a continuación:

- `id`, el ID generado para esta tarea de conversación, utilizado para identificar de forma única esta tarea de conversación.
- `model `, el modelo de Claude seleccionado en el sitio web oficial.
- `choices`, la información de respuesta proporcionada por Claude para el prompt de consulta.
- `usage `: información estadística de tokens para esta sesión de preguntas y respuestas.

En el formato Chat Completions, `usage.prompt_tokens` es el total de entrada; `prompt_tokens_details.cached_tokens` y `prompt_tokens_details.cache_write_tokens` registran respectivamente los detalles de lectura y escritura de caché. `completion_tokens_details.reasoning_tokens` es un subconjunto de `completion_tokens`; no los vuelvas a sumar al calcular el total o el costo. Las respuestas no en streaming también pueden devolver un objeto `usage.cost`, donde `amount` es el consumo real de crédito, `currency` es la unidad de medida y `list_amount` es el importe antes del descuento (si corresponde).

El nombre de campo de Chat-compatible es `reasoning_tokens`; la API nativa de Messages utiliza `output_tokens_details.thinking_tokens`. El esquema wire de ambos protocolos es diferente, y el cliente no debe mezclar los nombres de los campos.

Entre ellos, `choices` contiene la información de respuesta de Claude, y sus `choices` contienen la información específica de la respuesta de Claude, como se puede observar en la imagen.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Se puede ver que el campo `content` dentro de `choices` contiene el contenido específico de la respuesta de Claude.

## Respuesta en streaming

Esta interfaz también admite respuestas en streaming, lo cual es muy útil para la integración con páginas web y permite lograr un efecto de visualización carácter por carácter en la página.

Si deseas devolver respuestas en streaming, puedes cambiar el parámetro `stream ` en el encabezado de la solicitud a `true`.

La modificación se muestra en la imagen; sin embargo, el código de llamada debe tener los cambios correspondientes para admitir respuestas en streaming.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

Después de modificar `stream` a `true`, la API devolverá los datos JSON correspondientes línea por línea; a nivel de código, necesitamos realizar las modificaciones correspondientes para obtener los resultados línea por línea.

Código de llamada de ejemplo en Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

JavaScript también es compatible; por ejemplo, el código de llamada en streaming de Node.js es el siguiente:

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",

  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

## Razonamiento profundo
Los modelos Claude de nueva generación pueden realizar razonamiento según la estrategia predeterminada del modelo, sin necesidad de activarlo mediante el sufijo de modelo `-thinking`. Las respuestas compatibles con Chat utilizan el campo usage compatible con OpenAI `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` ya está incluido en `completion_tokens`, no los sume por duplicado. El razonamiento y el texto visible comparten el límite de tokens de salida, por lo que cuando `max_tokens` es bajo, el texto puede quedar vacío o truncado; si ocurre esto, aumente el presupuesto de salida o, cuando el modelo utilizado lo admita, seleccione un menor esfuerzo de razonamiento.

Si necesita `thinking` nativo, `output_config.effort`, bloques de contenido thinking y la devolución de firmas, utilice `/v1/messages`. El campo usage correspondiente a Messages es `output_tokens_details.thinking_tokens`; no lo mezcle con `completion_tokens_details.reasoning_tokens` de Chat-compatible.

## Modelo visual

claude-sonnet-4-20250514 es un modelo de lenguaje grande multimodal desarrollado por Claude; añade capacidades de comprensión visual sobre la base de claude-4. Este modelo puede procesar simultáneamente entradas de texto e imágenes, logrando comprensión y generación multimodal.

El procesamiento de texto con el modelo claude-sonnet-4-20250514 es coherente con el contenido básico de uso anterior; a continuación se presentará brevemente cómo utilizar las capacidades de procesamiento de imágenes del modelo.

La capacidad de procesamiento de imágenes del modelo claude-sonnet-4-20250514 se utiliza principalmente agregando un campo `type` sobre la base del contenido original de `content`. Mediante este campo se puede saber si se ha subido texto o una imagen, utilizando así la capacidad de procesamiento de imágenes del modelo claude-sonnet-4-20250514. A continuación se explica principalmente cómo llamar a esta función mediante Curl y Python.

## Manejo de errores

Al llamar a la API, si se produce un error, la API devolverá el código de error y la información correspondientes. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`: No autorizado, token de autorización no válido o faltante.
- `429 too_many_requests`: Demasiadas solicitudes, ha superado el límite de tasa.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

