Anthropic Claude es un sistema de conversación de IA muy potente; basta con introducir un prompt para generar respuestas fluidas y naturales en solo unos segundos. Claude destaca de forma única en la industria por sus excelentes capacidades de comprensión y generación del lenguaje. Hoy en día, Claude ya se utiliza ampliamente en diversos sectores y ámbitos, y su influencia es cada vez más significativa. Ya sea para conversaciones cotidianas, escritura creativa, consultas profesionales o programación de código, Claude puede proporcionar una asistencia inteligente sorprendente, mejorando enormemente la eficiencia laboral y la creatividad humanas.

Este documento presenta principalmente el proceso de uso de las operaciones de Claude Chat Completion API; utilizándolo podemos emplear fácilmente la función de conversación de Claude oficial.

## Proceso de solicitud

Para utilizar Claude Chat Completion API, primero vaya a la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obtener su API Token y guárdelo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; al finalizar, volverá automáticamente a la página actual.

**Un solo API Token permite llamar a todos los servicios de la plataforma, sin necesidad de solicitarlo por separado para cada servicio.** La primera solicitud incluirá crédito gratuito, que puede usarse para una experiencia gratuita; cuando el crédito sea insuficiente, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Claude Chat Completion API →](https://platform.acedata.cloud/documents/claude-chat-completions)

## Uso básico

A continuación, puede completar el contenido correspondiente en la interfaz, como se muestra en la imagen:

<p><img src="https://cdn.acedata.cloud/ejeq57.png" width="400" className="m-auto" /></p>

Al utilizar esta interfaz por primera vez, necesitamos completar al menos tres elementos: uno es `authorization`, que puede seleccionarse directamente en la lista desplegable. Otro parámetro es `model`; se recomienda usar el buque insignia más reciente `claude-fable-5-1`; el anterior `claude-fable-5` puede seguir utilizándose. El último parámetro es `messages`, que es un arreglo de prompts; cada elemento contiene `role` y `content`; `role` admite `user`, `assistant`, `system`, y `content` es el contenido específico. Claude Fable 5.1 admite un contexto de 1 millón de Tokens y una salida máxima de 128K Tokens.

Al mismo tiempo, puede observar que a la derecha se genera el código de llamada correspondiente; puede copiar el código y ejecutarlo directamente, o puede hacer clic directamente en el botón «Try» para realizar pruebas.

Parámetros opcionales comunes:

- `max_tokens`: limita el número máximo de tokens de una sola respuesta.
- `temperature`: aleatoriedad de la generación, entre 0 y 2; cuanto mayor sea el valor, más disperso será.
- `n`: cuántas respuestas candidatas se generan de una vez.
- `response_format`: configuración del formato de retorno.

<p><img src="https://cdn.acedata.cloud/v6lbjo.png" width="400" className="m-auto" /></p>

Después de realizar la llamada, encontramos que el resultado devuelto es el siguiente:

```json
{
  "id": "msg_bdrk_01Q6WN27v95ypCa1kbanAQ6K",
  "model": "claude-opus-4-8",
  "object": "chat.completion",
  "created": 1768619365,
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": "Hello! How can I help you today?"
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 8,
    "completion_tokens": 12,
    "total_tokens": 20,
    "prompt_tokens_details": {
      "cached_tokens": 0,
      "cache_write_tokens": 0
    },
    "completion_tokens_details": {
      "reasoning_tokens": 0
    }
  }
}
```

El resultado devuelto tiene varios campos, que se presentan a continuación:

- `id`, el ID de la tarea de conversación generada esta vez, utilizado para identificar de forma única esta tarea de conversación.
- `model `, el modelo de Claude del sitio web oficial seleccionado.
- `choices`, la información de respuesta proporcionada por Claude para el prompt.
- `usage `: información estadística de tokens para esta sesión de preguntas y respuestas.

En el formato Chat Completions, `usage.prompt_tokens` es el total de entrada; `prompt_tokens_details.cached_tokens` y `prompt_tokens_details.cache_write_tokens` registran respectivamente los detalles de lectura y escritura de caché. `completion_tokens_details.reasoning_tokens` es un subconjunto de `completion_tokens`; no lo sume nuevamente al calcular el total o el coste. Las respuestas no en streaming también pueden devolver un objeto `usage.cost`, donde `amount` es el consumo real de crédito, `currency` es la unidad de medida y `list_amount` es el importe antes del descuento (si lo hubiera).

El nombre de campo compatible con Chat es `reasoning_tokens`; la API nativa Messages utiliza `output_tokens_details.thinking_tokens`. El esquema wire de los dos protocolos es diferente, y el cliente no debe mezclar los nombres de los campos.

Entre ellos, `choices` contiene la información de respuesta de Claude, y los `choices` dentro de este son la información específica de la respuesta de Claude, como se puede observar en la imagen.

<p><img src="https://cdn.acedata.cloud/2ulyhw.png" width="400" className="m-auto" /></p>

Se puede ver que el campo `content` dentro de `choices` contiene el contenido específico de la respuesta de Claude.

## Respuesta en streaming

Esta interfaz también admite respuestas en streaming, lo cual es muy útil para la integración web, ya que permite que la página web implemente un efecto de visualización carácter por carácter.

Si desea devolver la respuesta en streaming, puede cambiar el parámetro `stream ` en el encabezado de la solicitud a `true`.

La modificación se muestra en la imagen; sin embargo, el código de llamada necesita los cambios correspondientes para admitir respuestas en streaming.

<p><img src="https://cdn.acedata.cloud/ueugot.png" width="400" className="m-auto" /></p>

Después de modificar `stream` a `true`, la API devolverá los datos JSON correspondientes línea por línea; a nivel de código, debemos realizar las modificaciones correspondientes para obtener los resultados línea por línea.

Código de llamada de ejemplo en Python:

```python
import requests

url = "https://api.acedata.cloud/v1/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "claude-opus-4-20250514",
    "messages": [{"role":"user","content":"Hello"}],
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

```javascript
const options = {
  method: "post",
  headers: {
    accept: "application/json",

    stream: true,

  .then((response) => response.json())
  .then((response) => console.log(response))
  .catch((err) => console.error(err));
```

Si desea integrar la función de conversación de múltiples turnos, necesita cargar múltiples palabras de consulta en el campo `messages`; el ejemplo específico de múltiples palabras de consulta se muestra en la siguiente imagen:

## Pensamiento profundo
Los modelos Claude de nueva generación pueden realizar razonamiento según la estrategia predeterminada del modelo, sin necesidad de activarlo mediante el sufijo de modelo `-thinking`. Las respuestas compatibles con Chat utilizan el campo usage compatible con OpenAI `completion_tokens_details.reasoning_tokens`. `reasoning_tokens` ya está incluido en `completion_tokens`, no los sume dos veces. El razonamiento y el cuerpo visible comparten el límite de tokens de salida, por lo que cuando `max_tokens` es pequeño, el cuerpo puede estar vacío o truncado; si ocurre esta situación, aumente el presupuesto de salida o, si el modelo utilizado lo admite, seleccione una menor inversión en razonamiento.

Si necesita `thinking` nativo, `output_config.effort`, bloques de contenido thinking y devolución de firmas, utilice `/v1/messages`. El campo usage correspondiente a Messages es `output_tokens_details.thinking_tokens`, no lo mezcle con `completion_tokens_details.reasoning_tokens` de Chat-compatible.

## Modelo visual

claude-sonnet-4-20250514 es un modelo de lenguaje grande multimodal desarrollado por Claude, que añade capacidades de comprensión visual sobre la base de claude-4. Este modelo puede procesar simultáneamente entradas de texto e imagen, logrando comprensión y generación multimodales.

El procesamiento de texto utilizando el modelo claude-sonnet-4-20250514 es coherente con el contenido básico de uso anterior; a continuación se presentará brevemente cómo utilizar la capacidad de procesamiento de imágenes del modelo.

La capacidad de procesamiento de imágenes del modelo claude-sonnet-4-20250514 se utiliza principalmente añadiendo un campo `type` sobre la base del contenido original de `content`; mediante este campo se puede saber si se ha cargado texto o una imagen, utilizando así la capacidad de procesamiento de imágenes del modelo claude-sonnet-4-20250514. A continuación se explica principalmente cómo invocar esta función mediante Curl y Python.

```

-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
    "model": "claude-sonnet-4-20250514",
    "messages": [
      {
        "role": "user",
        "content": [
          {
            "type": "text",
            "text": "What'\''s in this image?"
          },
          {
            "type": "image_url",
```

## Manejo de errores

Al invocar la API, si se produce un error, la API devolverá el código de error y la información correspondientes. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`: No autorizado, token de autorización no válido o faltante.
- `429 too_many_requests`: Demasiadas solicitudes, ha superado el límite de velocidad.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```

```
