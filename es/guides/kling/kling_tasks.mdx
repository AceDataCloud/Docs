La función principal de Kling Tasks API es consultar el estado de ejecución de una tarea introduciendo el ID de tarea generado por Kling Videos Generation API.

Este documento presentará en detalle las instrucciones de integración de Kling Tasks API, ayudándole a integrar fácilmente y aprovechar plenamente las potentes funciones de esta API. A través de Kling Tasks API, puede consultar fácilmente el estado de ejecución de las tareas de Kling Videos Generation API.

## Proceso de solicitud

Para utilizar Kling Videos Generation API, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; una vez completado, regresará automáticamente a la página actual.

**Un API Token puede invocar todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluirá crédito gratuito para una experiencia sin costo; cuando el crédito sea insuficiente, puede recargar saldo común en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Ejemplo de solicitud

Kling Tasks API se puede utilizar para consultar los resultados de Kling Videos Generation API. Para saber cómo utilizar Kling Videos Generation API, consulte la documentación [Kling Videos Generation API ](https://platform.acedata.cloud/documents/kling-videos)。

Tomamos como ejemplo uno de los ID de tarea devueltos por el servicio Kling Videos Generation API para demostrar cómo utilizar esta API. Supongamos que tenemos un ID de tarea: 20068983-0cc9-4c6a-aeb6-9c6a3c668be0; a continuación se demuestra cómo hacerlo pasando un ID de tarea.

### Configurar los encabezados y el cuerpo de la solicitud

**Request Headers** incluyen:

- `accept`: especifica que se reciban resultados de respuesta en formato JSON; aquí se completa como `application/json`.
- `authorization`: la clave para invocar la API; después de solicitarla, se puede seleccionar directamente desde el menú desplegable.

**Request Body** incluye:

- `id`: el ID de la tarea cargada.
- `action`: el modo de operación sobre la tarea.

Algunos ejemplos de código son los siguientes:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/kling/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/kling/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

El resultado devuelto contiene múltiples campos. El campo request es el request body al iniciar la tarea, mientras que el campo response es el response body devuelto después de que la tarea se complete. La descripción de los campos es la siguiente.

- `id`: el ID que genera esta tarea de video, utilizado para identificar de forma única esta tarea de generación de video.
- `request`: la información de solicitud en la consulta de la tarea de video.
- `response`: la información devuelta en la consulta de la tarea de video.
- `created_at`: hora de creación de la tarea, marca de tiempo Unix (segundos, punto flotante).
- `started_at`: hora en la que la tarea comienza a ejecutarse, marca de tiempo Unix (segundos, punto flotante).
- `finished_at`: hora de finalización de la tarea, marca de tiempo Unix (segundos, punto flotante). Este campo no se devuelve cuando la tarea no se ha completado.
- `elapsed`: tiempo de ejecución de la tarea, en segundos (punto flotante, conservando 3 decimales). Este campo no se devuelve cuando la tarea no se ha completado.

## Manejo de errores

Al llamar a la API, si encuentra un error, la API devolverá el código de error y la información correspondientes. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`: No autorizado, token de autorización no válido o faltante.
- `429 too_many_requests`: Demasiadas solicitudes, ha superado el límite de frecuencia.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error
