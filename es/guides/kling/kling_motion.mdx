Este artículo presentará unas instrucciones de integración de Kling Motion Generation API, que permite generar los videos oficiales de Kling mediante la introducción de parámetros personalizados.

## Proceso de solicitud

Para utilizar Kling Motion Generation API, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo para usarlo posteriormente.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión ni se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; tras completarlo, volverá automáticamente a la página actual.

**Un API Token permite llamar a todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluye créditos gratuitos para una experiencia sin coste; cuando los créditos sean insuficientes, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Kling Motion Generation API →](https://platform.acedata.cloud/documents/kling-motion)

## Uso básico

Primero, comprendamos el método básico de uso: basta con introducir el texto de indicación `prompt`, la imagen de referencia `image_url` y el enlace de video de referencia `video_url` para obtener el resultado procesado; después también necesitamos introducir el modelo `mode`, actualmente existen principalmente los modelos `std`, `pro`, y el contenido específico es el siguiente:

<p><img src="https://cdn.acedata.cloud/5qlpjt.png" width="500" className="m-auto" /></p>

Aquí podemos ver que hemos configurado los Request Headers, incluidos:

- `accept`: el formato de resultado de respuesta que desea recibir; aquí se completa como `application/json`, es decir, formato JSON.
- `authorization`: la clave para llamar a la API, que puede seleccionarse directamente desde el menú desplegable después de solicitarla.

Además, se ha configurado el Request Body, incluido:

- `image_url`: URL de la imagen de referencia de la apariencia del personaje. Admite JPG/JPEG/PNG, archivo ≤50MB, ancho y alto ≥300px, relación de aspecto de 1:2.5～2.5:1; el personaje debe mostrar claramente la parte superior del cuerpo o el cuerpo completo y la cabeza.
- `video_url`: URL del video de referencia de movimiento. Admite MP4/MOV, archivo ≤100MB, ancho y alto de 340–3850px, al menos 3 segundos; cuando `character_orientation=image`, el máximo es de 10 segundos, y cuando `character_orientation=video`, el máximo es de 30 segundos. Se recomienda utilizar un video continuo de una sola toma donde el personaje permanezca siempre dentro del encuadre.
- `mode`: el modo para generar videos, principalmente el modo estándar `std` y el modo rápido `pro`.
- `keep_original_sound`: permite elegir si se conserva el sonido original del video; valores de enumeración: yes, no.
- `character_orientation`: la orientación del personaje en el video generado; se puede elegir que coincida con la imagen o con el video; valores de enumeración: image, video.
- `prompt`: texto de indicación.
- `callback_url`: URL que necesita recibir el resultado de la devolución de llamada.
- `async`: opcional; cuando se establece en `true`, la interfaz devuelve inmediatamente `task_id`, no es necesario proporcionar `callback_url`, y posteriormente se obtiene el resultado mediante sondeo a través de la interfaz de consulta de tareas correspondiente.

Después de seleccionar, puede observar que también se genera el código correspondiente a la derecha, como se muestra en la imagen:

<p><img src="https://cdn.acedata.cloud/buwczd.png" width="500" className="m-auto" /></p>

Haga clic en el botón «Try» para realizar una prueba; como se muestra en la imagen anterior, aquí obtenemos el siguiente resultado:

```json
{
  "success": true,
  "video_id": "842578800134742051",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "5.066",
  "state": "succeed",
  "task_id": "363c7a84-e880-472e-a4d4-098e50cfc292"
}
```

El resultado devuelto tiene varios campos, que se presentan a continuación:

- `success`, el estado de la tarea de generación de video en este momento.
- `task_id`, el ID de la tarea de generación de video en este momento.
- `video_id`, el ID de video de la tarea de generación de video en este momento.
- `video_url`, el enlace de video de la tarea de generación de video en este momento.
- `duration`, la duración del enlace de video de la tarea de generación de video en este momento.
- `state`, el estado de la tarea de generación de video en este momento.

Podemos ver que hemos obtenido información satisfactoria del video; solo necesitamos obtener el video de Kling generado según la dirección del enlace de video en `data` del resultado.

Además, si desea generar el código de integración correspondiente, puede copiarlo directamente; por ejemplo, el código CURL es el siguiente:

```shell
curl -X POST 'https://api.acedata.cloud/kling/motion' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
  "video_url": "https://cdn.acedata.cloud/odwfm5.mp4",
  "prompt": "让画面生动起来",
  "mode": "std",
  "character_orientation": "image"
}'
```

## Devolución de llamada asíncrona

Debido a que el tiempo de generación de Kling Motion Generation API es relativamente largo, aproximadamente 1-2 minutos, si la API no responde durante mucho tiempo, la solicitud HTTP mantendrá la conexión abierta, lo que provocará un consumo adicional de recursos del sistema, por lo que esta API también proporciona soporte para devoluciones de llamada asíncronas.

El proceso general es: cuando el cliente inicia una solicitud, especifica adicionalmente un campo `callback_url`; después de que el cliente inicia la solicitud a la API, la API devuelve inmediatamente un resultado que contiene la información de un campo `task_id`, que representa el ID de la tarea actual. Cuando la tarea se completa, el resultado del video generado se enviará mediante POST JSON al `callback_url` especificado por el cliente, que también incluye el campo `task_id`, de modo que el resultado de la tarea puede asociarse mediante el ID.

A continuación, comprendamos mediante un ejemplo cómo operar específicamente.

Primero, una devolución de llamada Webhook es un servicio que puede recibir solicitudes HTTP; el desarrollador debe reemplazarlo por la URL de un servidor HTTP construido por sí mismo. Aquí, para facilitar la demostración, se utiliza un sitio web público de ejemplo de Webhook https://webhook.site/; al abrir este sitio web se puede obtener una URL de Webhook, como se muestra en la imagen:

![](https://cdn.acedata.cloud/tbcnai.png)

Copie esta URL para usarla como Webhook; el ejemplo aquí es `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`.

A continuación, podemos establecer el campo `callback_url` como la URL de Webhook anterior y, al mismo tiempo, completar los parámetros correspondientes; el contenido específico se muestra en la imagen:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Haga clic en ejecutar y podrá observar que se obtiene inmediatamente un resultado, como el siguiente:

```

  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Espere un momento y podremos observar el resultado del video generado en `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, como se muestra en la imagen:

![](https://cdn.acedata.cloud/zv5u2q.png)

El contenido es el siguiente:
```json

  "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
```

Se puede ver que hay un campo `task_id` en el resultado, los demás campos son similares a los anteriores, y la asociación de tareas se puede lograr mediante este campo.

## Manejo de errores

Al llamar a la API, si se encuentra un error, la API devolverá el código de error y la información correspondientes. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`: No autorizado, token de autorización no válido o faltante.
- `429 too_many_requests`: Demasiadas solicitudes, ha superado el límite de tasa.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
