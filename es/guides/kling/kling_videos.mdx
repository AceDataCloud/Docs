Este documento presenta una guía para la integración de la API de generación de videos Kling, que permite crear videos oficiales de Kling mediante la entrada de parámetros personalizados.

## Proceso de solicitud

Para usar la API, primero debe solicitar el servicio correspondiente en la página de [Kling Videos Generation API](https://platform.acedata.cloud/documents/3b921a16-a411-4557-8335-53f21d3f9e46). Al ingresar, haga clic en el botón "Acquire", como se muestra en la imagen:

![](https://cdn.acedata.cloud/q6ytrc.png)

Si aún no ha iniciado sesión o registrado, será redirigido automáticamente a la página de inicio de sesión para registrarse o ingresar. Tras iniciar sesión, volverá automáticamente a esta página.

Al solicitar por primera vez, se otorga un crédito gratuito para usar la API sin costo.

## Uso básico

Primero, conozcamos la forma básica de uso: ingresando el prompt, la acción `action`, la imagen de referencia inicial `start_image_url` y el modelo `model` para obtener el resultado procesado. Se debe enviar un campo `action` con el valor `text2video`, que incluye tres tipos de acciones: generación de video desde texto (`text2video`), generación de video desde imagen (`image2video`) y extensión de video (`extend`). Además, se debe especificar el modelo `model`. Actualmente, los modelos principales son `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni` y `kling-video-o1`, como se muestra a continuación:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Aquí configuramos los encabezados de la solicitud (Request Headers), que incluyen:

- `accept`: formato de respuesta deseado, aquí se usa `application/json` para recibir JSON.
- `authorization`: clave para llamar a la API, que se puede seleccionar tras la solicitud.

También configuramos el cuerpo de la solicitud (Request Body), que incluye:

- `model`: modelo para generar el video, entre los modelos mencionados arriba.
- `mode`: modo de generación, puede ser estándar `std`, rápido `pro` o 4K nativo `4k`. El modo `4k` solo es compatible con `kling-v3` y `kling-v3-omni`, y no es compatible con `camera_control` (control de cámara).
- `action`: acción para la tarea de generación de video, con las tres opciones mencionadas.
- `start_image_url`: URL de la imagen de referencia inicial, obligatorio para la acción `image2video`.
- `end_image_url`: opcional para `image2video`, especifica la imagen final.
- `duration`: duración del video en segundos. Para modelos `kling-v3` y `kling-v3-omni` se admite duración flexible de 3 a 15 segundos (enteros), otros modelos soportan 5 o 10 segundos.
- `generate_audio`: booleano opcional para generar audio simultáneamente. Soportado en `kling-v3`, `kling-v3-omni` y `kling-v2-6` (solo modo pro). Por defecto es `false`.
- `aspect_ratio`: relación de aspecto del video, opcional, soporta `16:9`, `9:16` y `1:1`, por defecto `16:9`.
- `cfg_scale`: intensidad de correlación, rango [0,1], mayor valor significa más adherencia al prompt.
- `camera_control`: opcional, parámetros para controlar el movimiento de cámara, soporta presets `type/simple` y configuraciones como horizontal, vertical, pan, tilt, roll, zoom, etc.
- `negative_prompt`: prompt negativo opcional, hasta 200 caracteres, para evitar elementos no deseados.
- `element_list`: lista de referencias principales, solo para modelo `kling-video-o1`. Consulte el [documento oficial](https://docs.qingque.cn/d/home/eZQAyImcbaS0fz-8ANjXvU5ed?identityId=1oEG9JKKMFv#section=h.5t7wme23nn6z) para su uso.
- `video_list`: videos de referencia mediante URL, solo para modelo `kling-video-o1`. Consulte el [documento oficial](https://docs.qingque.cn/d/home/eZQAyImcbaS0fz-8ANjXvU5ed?identityId=1oEG9JKKMFv#section=h.5t7wme23nn6z).
- `prompt`: prompt o texto de entrada.
- `callback_url`: URL para recibir el resultado mediante callback.

Tras seleccionar, se genera el código correspondiente a la derecha, como se muestra:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Haga clic en el botón "Try" para probar. El resultado será como el siguiente:

```json
{
  "success": true,
  "video_id": "af9a1af0-9aa0-4638-81c1-d41d6143c508",
  "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7485378259/text2video/Cjil4mfBfs0AAAAAAKbMQQ-0_raw_video_1.mp4",
  "duration": "5.1",
  "state": "succeed",
  "task_id": "e3a575aa-a4bd-49c8-9b12-cde38d5462e0"
}
```

Los campos devueltos son:

- `success`: estado de la tarea de generación de video.
- `task_id`: ID de la tarea.
- `video_id`: ID del video generado.
- `video_url`: URL del video generado.
- `duration`: duración del video generado.
- `state`: estado de la tarea.

Con esta información, solo debe obtener el video Kling mediante la URL en `video_url`.

Si desea generar el código de integración, puede copiarlo directamente. Por ejemplo, el código CURL es:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v1",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Función de extensión de video

Para continuar generando un video Kling ya creado, configure `action` como `extend` e ingrese el ID del video a extender. El ID se obtiene según el uso básico, como se muestra:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

El ID del video es:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Nota: el `video_id` es el ID del video generado. Si no sabe cómo generar un video, consulte la sección de uso básico.

Luego debe ingresar el prompt para la extensión personalizada, con los siguientes parámetros:

- `model`: modelo para generar video, principalmente `kling-v1`, `kling-v1-5` y `kling-v1-6`.
- `mode`: modo de generación, estándar `std`, rápido `pro` o 4K nativo `4k` (solo para `kling-v3` y `kling-v3-omni`, no compatible con control de cámara).
- `duration`: duración del video generado, típicamente 5 o 10 segundos.
- `start_image_url`: URL de imagen inicial para `image2video`.
- `prompt`: prompt o texto.

Ejemplo de llenado:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Después se genera el código automáticamente:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Al ejecutar, se obtiene un resultado como:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7822108635/extendVideo/Cjil4mfBfs0AAAAAAKhr6A-0_raw_video_1.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```

El resultado es similar al anterior, logrando la función de extensión de video.

## Callback asíncrono

Dado que la generación de videos con Kling Videos Generation API toma aproximadamente 1-2 minutos, si la API no responde en ese tiempo, la conexión HTTP se mantiene abierta, consumiendo recursos del sistema. Por ello, la API soporta callbacks asíncronos.

El flujo es: el cliente envía la solicitud incluyendo un campo `callback_url`. La API responde inmediatamente con un resultado que contiene `task_id`, identificador de la tarea. Cuando la tarea finaliza, el resultado del video se envía mediante POST JSON al `callback_url` especificado, incluyendo también el `task_id` para relacionar la tarea.

Veamos un ejemplo.

Primero, el webhook callback es un servicio que recibe solicitudes HTTP. El desarrollador debe reemplazarlo por su propio servidor HTTP. Para demostración, usamos el sitio público https://webhook.site/, que genera una URL de webhook, como se muestra:

![](https://cdn.acedata.cloud/tbcnai.png)

Copie esta URL, por ejemplo `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3`, para usarla como webhook.

Luego configure el campo `callback_url` con esta URL y llene los demás parámetros, como se muestra:

<p><img src="https://cdn.acedata.cloud/vdx12s.png" width="500" className="m-auto" /></p>

Al ejecutar, se obtiene inmediatamente:

```
{
  "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Después de un momento, en `https://webhook.site/624b2c78-6dbd-4618-9d2b-b32eade6d8c3` se puede observar el resultado generado, como se muestra:

![](https://cdn.acedata.cloud/zv5u2q.png)

Contenido:

```json
{
    "success": true,
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7822108635/text2video/CjJzzGfBfqcAAAAAAKdVMQ-0_raw_video_1.mp4",
    "duration": "5.1",
    "state": "succeed",
    "task_id": "20068983-0cc9-4c6a-aeb6-9c6a3c668be0"
}
```

Se observa el campo `task_id`, que permite relacionar la tarea con el resultado.

## Manejo de errores

Al llamar a la API, si ocurre un error, esta devuelve un código y mensaje de error. Por ejemplo:

- `400 token_mismatched`: solicitud incorrecta, posiblemente por parámetros faltantes o inválidos.
- `400 api_not_implemented`: solicitud incorrecta, posiblemente por parámetros faltantes o inválidos.
- `401 invalid_token`: no autorizado, token inválido o faltante.
- `429 too_many_requests`: demasiadas solicitudes, se excedió el límite de tasa.
- `500 api_error`: error interno del servidor.

### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
