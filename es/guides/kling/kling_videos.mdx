Este artículo presentará una instrucción de integración de Kling Videos Generation API, que permite generar los videos oficiales de Kling mediante la introducción de parámetros personalizados.

## Proceso de solicitud

Para utilizar Kling Videos Generation API, primero vaya a la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obtener su API Token y conservarlo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; tras completarlo, regresará automáticamente a la página actual.

**Un solo API Token puede invocar todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluirá créditos gratuitos, que permiten una experiencia gratuita; cuando los créditos sean insuficientes, puede recargar saldo común en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Uso básico

Primero entendamos el método básico de uso: basta con introducir el texto de indicación `prompt`, la acción de generación `action`, la imagen de referencia del primer fotograma `start_image_url` y el modelo `model` para obtener el resultado procesado. Primero se debe pasar simplemente un campo `action`, cuyo valor es `text2video`; este incluye principalmente tres acciones: texto a video (`text2video`), imagen a video (`image2video`) y extensión de video (`extend`). Luego también necesitamos introducir el modelo `model`; actualmente existen principalmente los modelos `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`; el contenido específico es el siguiente:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Aquí podemos ver que configuramos los Request Headers, incluyendo:

- `accept`: qué formato de resultado de respuesta se desea recibir; aquí se completa como `application/json`, es decir, formato JSON.
- `authorization`: la clave para invocar la API; después de solicitarla, puede seleccionarse directamente desde el menú desplegable.

Además, configuramos el Request Body, incluyendo:

- `model`: el modelo para generar videos; incluye principalmente los modelos `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode`: el modo para generar videos; los valores opcionales son modo estándar `std`, modo ultrarrápido `pro` y modo nativo 4K `4k`. Entre ellos, `4k` solo admite `kling-v3` y `kling-v3-omni`, y no es compatible con `camera_control` (control de movimiento de cámara).
- `action`: la acción de esta tarea de generación de video; incluye principalmente tres acciones: texto a video (`text2video`), imagen a video (`image2video`) y extensión de video (`extend`).
- `start_image_url`: el enlace de la imagen de referencia del primer fotograma que debe cargarse al seleccionar la acción de imagen a video `image2video`.
- `end_image_url`: opcional al generar video a partir de imágenes, especifica el fotograma final.
- `duration`: duración del video, en segundos. `kling-v3` y `kling-v3-omni` admiten duraciones enteras de 3 a 15 segundos; `kling-o1` solo admite 5 segundos; los demás modelos admiten 5 o 10 segundos.
- `generate_audio`: si se genera audio de forma sincronizada, opcional, valor booleano. Compatible con `kling-v3`, `kling-v3-omni` y `kling-v2-6` (solo modo pro). El valor predeterminado es `false`.
- `aspect_ratio`: relación de aspecto del video, opcional, compatible con `16:9`, `9:16`, `1:1`, el valor predeterminado es `16:9`.
- `cfg_scale`: intensidad de relevancia, rango [0,1]; cuanto mayor sea, más se ajustará al texto de indicación.
- `camera_control`: opcional, parámetro de objeto para controlar el movimiento de la cámara; admite preajustes type/simple y configuraciones como horizontal, vertical, pan, tilt, roll, zoom, entre otras.
- `negative_prompt`: opcional, texto de indicación negativo que no se desea que aparezca, hasta 200 caracteres.
- `image_list`: lista de imágenes de referencia Omni, aplicable a los modelos `kling-o1` y `kling-v3-omni`; consulte a continuación «Referencia integral Omni» para el uso.
- `video_list`: lista de videos de referencia Omni (admite edición de video), aplicable a los modelos `kling-o1` y `kling-v3-omni`; consulte a continuación «Referencia integral Omni» para el uso.
- `prompt`: texto de indicación.
- `callback_url`: URL que requiere la devolución de resultados.
- `async`: opcional; cuando se establece en `true`, la interfaz devuelve inmediatamente `task_id`, sin necesidad de proporcionar `callback_url`; posteriormente, los resultados se obtienen mediante sondeo a través de la interfaz de consulta de tareas correspondiente.

```shell
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Matriz de capacidades de modelos

### Facturación de videos de referencia O1 y Omni

`kling-o1` se factura según el modo y si se proporciona `video_list`. Los siguientes son los precios para videos terminados de 5 segundos:

| Modo  |         Sin video de referencia |         Con video de referencia |
| --- | ------------: | ------------: |
| std | 4.005 Créditos | 6.010 Créditos |
| pro | 5.340 Créditos | 8.010 Créditos |
Las solicitudes exitosas de `kling-o1` y `kling-v3-omni` con video de referencia se cobran según los segundos facturados: std cuesta **1.202 Credits/segundo**, y pro cuesta **1.602 Credits/segundo**. Por ejemplo, generar 5 segundos en modo std cuesta 6.010 Credits. Omitir `video_list` no activa la tarifa de video de referencia; `image_list`, las imágenes del primer fotograma y del último fotograma tampoco se consideran videos de referencia. Los videos de referencia no pueden utilizarse simultáneamente con `generate_audio=true`.

La edición de video con `refer_type=base` (predeterminado) puede seguir la duración del video de referencia, y finalmente se cobra según la duración real del video terminado, redondeada a segundos enteros: por ejemplo, 5.708 segundos se cobran como 6 segundos, y 5.041 segundos como 5 segundos. `refer_type=feature` utiliza el `duration` solicitado. `usage.reference_video_seconds` en la respuesta proporciona los segundos finales facturados; el precio estimado al realizar la solicitud puede diferir del cargo final.

Los distintos modelos varían considerablemente en cuanto a la compatibilidad de parámetros. La siguiente matriz se ha recopilado de la [documentación oficial de video models de Kling](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels); antes de llamar, comprueba si la combinación actual de `model` / `mode` / `duration` admite la función que necesitas; de lo contrario, devolverá errores como `model/mode/duration(...) is not supported with image_tail`.

| Modelo                  | Modo             | `end_image_url` (primer y último fotograma) | `generate_audio` (audio) | `camera_control` (movimiento de cámara) | Notas                                           |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ Solo `duration=5`     | ❌                    | ✅ Solo `duration=5`     | `extend` no admite `negative_prompt` ni `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | Video a partir de múltiples imágenes, todos los modos de `extend` disponibles                         |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Modo único, solo `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Modo único, solo `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | El único modelo no v3 que también admite audio                             |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | Rango de `duration` de 3–15 segundos                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | El modo 4K es incompatible con el movimiento de cámara                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Solo admite `duration=5`                             |

Notas:

- `mode=4k` solo es compatible con `kling-v3` y `kling-v3-omni`; además, es mutuamente excluyente con `camera_control` (movimiento de cámara).
- `end_image_url` solo puede utilizarse junto con `start_image_url` cuando `action=image2video`. Enviar únicamente `end_image_url` (sin `start_image_url`) será rechazado.
- `kling-v3` / `kling-v3-omni` aceptan cualquier `duration` entero de 3–15 segundos; `kling-o1` solo acepta 5; los demás modelos solo aceptan 5 o 10.
- `generate_audio` es `false` de forma predeterminada. Solo `kling-v3`, `kling-v3-omni` y `kling-v2-6` (modo pro) lo admiten.

## Función de extensión de video

Si deseas continuar generando un video de Kling ya generado, puedes establecer el parámetro `action` en `extend`, e introducir el ID del video que necesita continuar generándose. El ID del video se obtiene según el uso básico, como se muestra en la siguiente imagen:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

En este momento puedes ver que el ID del video es:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Ten en cuenta que aquí el `video_id` en el video es el ID del video generado. Si no sabes cómo generar un video, puedes consultar el uso básico anterior para generar un video.

A continuación, debemos completar obligatoriamente el prompt que se necesita extender en el siguiente paso para personalizar el video generado, y se puede especificar el siguiente contenido:

- `model`: el modelo para generar video, principalmente los modelos `kling-v1`, `kling-v1-5` y `kling-v1-6`.
- `mode`: el modo para generar video, los valores opcionales son modo estándar `std`, modo rápido `pro` y modo 4K nativo `4k` (solo compatible con `kling-v3` y `kling-v3-omni`, incompatible con el control de movimiento de cámara).
- `duration`: la duración del video para esta tarea de generación de video, incluye principalmente 5 s y 10 s.
- `start_image_url`: el enlace de la imagen de referencia del primer fotograma que se debe cargar al elegir el comportamiento de generación de video a partir de imagen `image2video`.
- `prompt`: prompt.

El ejemplo de cumplimentación es el siguiente:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Después de completar, el código se genera automáticamente de la siguiente manera:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

```json
  "video_url": "https://cdn.acedata.cloud/assets/examples/gemini/04a043bd-6b23-4b4e-945c-ce48158c3eee-3a89912507c7.mp4",
  "duration": "9.6",
  "state": "succeed",
```

Se puede ver que el contenido del resultado es consistente con el anterior, lo que también implementa la función de extensión de video.

## Referencia Omni Todo-en-Uno (edición de video / video de referencia / referencia de múltiples imágenes)

`kling-o1` y `kling-v3-omni` son dos modelos independientes, ambos admiten la capacidad de «referencia todo-en-uno». Sobre la base de texto a video (`action=text2video`), se pueden pasar adicionalmente imágenes de referencia o videos de referencia, para lograr **referencia de múltiples imágenes, video de referencia y edición directa de videos existentes**.

**Convención principal**: los materiales de referencia deben citarse en `prompt` en la forma `&lt;&lt;<image_1>>>`, `&lt;&lt;<video_1>>>` (la numeración comienza desde 1) para los materiales en la posición correspondiente de `image_list` / `video_list`, para que el modelo aplique estas referencias. Si solo se pasan materiales sin citarlos en el prompt, los materiales serán ignorados.

> Explicación de seguridad: actualmente la API no abre `element_list`. Los ID de Kling Element Library no están aislados por tenant; antes de proporcionar una Element Management API con aislamiento por tenant, utilice `image_list` para pasar imágenes de referencia del sujeto.

Las solicitudes Omni no admiten `negative_prompt`, `cfg_scale` ni `camera_control`, y tampoco pueden usar `mode=4k`. Cuando se incluye un video de referencia, `generate_audio` debe ser `false`.

### Video de referencia y edición de video (`video_list`)

`video_list` se utiliza para pasar videos de referencia, siendo el escenario más común de esta capacidad; los campos de los elementos del array son los siguientes:

- `video_url`: enlace del video de referencia, no puede estar vacío. Como máximo 1 video MP4/MOV, tamaño de archivo ≤200MB, tasa de fotogramas 24–60fps. `kling-o1` requiere una duración de 3–10 segundos y ancho y alto de 700–2160px cada uno; `kling-v3-omni` requiere una duración de 3–15.5 segundos, ancho y alto de 700–4553px cada uno, píxeles totales ≤8,294,400 y relación de aspecto 0.4–2.
- `refer_type`: tipo de referencia, opcional `base` (predeterminado, **video base que se va a editar**, es decir, "editar directamente el video", pudiendo añadir/eliminar/modificar elementos, cambiar composición, cambiar estilo, cambiar color, cambiar clima, etc.) o `feature` (**referencia de características**, para referenciar su estilo / movimiento de cámara / continuar filmando el siguiente plano).
- `keep_original_sound`: si se conserva el audio del video original, opcional `yes` (conservar) o `no` (eliminar).

> Nota: cuando existe un video de referencia, `generate_audio` debe ser `false`. Al video con `refer_type=base` no se le puede especificar además un fotograma inicial / fotograma final.

El ejemplo CURL para editar un video existente (cambiar el video a estilo anime) es el siguiente:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Referencia de múltiples imágenes (`image_list`)

`image_list` se utiliza para pasar imágenes de referencia (elementos / escenas / estilos, etc.); los campos de los elementos del array son los siguientes:

- `image_url`: enlace de la imagen de referencia, no puede estar vacío. Requisitos: formato .jpg/.jpeg/.png; tamaño de archivo ≤10MB; lado más corto ≥300px; relación de aspecto 1:2.5 ~ 2.5:1.
- `type`: opcional. Si no se pasa, se utiliza como imagen de referencia pura; si se pasa `first_frame` / `end_frame`, se utiliza respectivamente como fotograma inicial / fotograma final (equivalente a `start_image_url` / `end_image_url`).

Al usarlo, debe citarse en `prompt` mediante `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Límite de cantidad: cuando no existe video de referencia, imágenes de referencia ≤ 7; cuando existe video de referencia, imágenes de referencia ≤ 4. Al pasar solo el fotograma inicial / final, también se puede usar directamente `start_image_url` / `end_image_url`, pero el fotograma final debe utilizarse junto con el fotograma inicial.

> Nota: si se pasan simultáneamente `start_image_url` / `end_image_url` e `image_list`, los fotogramas inicial / final se colocarán antes de `image_list`, lo que puede afectar la correspondencia de numeración de `&lt;&lt;<image_N>>>`. Se recomienda elegir uno de los dos: cuando se necesiten fotogramas inicial / final, especifique directamente `type` en `image_list`; no lo mezcle con `start_image_url` / `end_image_url`.

Ejemplo CURL para generar un video con referencia de múltiples imágenes:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Devolución de llamada asíncrona

Debido a que el tiempo de generación de Kling Videos Generation API es relativamente largo, aproximadamente 1-2 minutos, si la API no responde durante mucho tiempo, la solicitud HTTP permanecerá conectada continuamente, lo que provoca un consumo adicional de recursos del sistema; por lo tanto, esta API también proporciona soporte para devoluciones de llamada asíncronas.

El proceso general es: cuando el cliente inicia una solicitud, especifica adicionalmente un campo `callback_url`; después de que el cliente inicia la solicitud de API, la API devolverá inmediatamente un resultado que contiene información de un campo `task_id`, que representa el ID de la tarea actual. Cuando la tarea se complete, el resultado del video generado se enviará mediante POST JSON a la `callback_url` especificada por el cliente, incluyendo también el campo `task_id`, de modo que el resultado de la tarea se puede asociar mediante el ID.

A continuación, conoceremos mediante un ejemplo cómo realizar la operación específica.

En primer lugar, la devolución de llamada Webhook es un servicio que puede recibir solicitudes HTTP; el desarrollador debe reemplazarlo por la URL de un servidor HTTP construido por sí mismo. Para facilitar la demostración, aquí se utiliza un sitio web público de ejemplo de Webhook https://webhook.site/; al abrir este sitio web se puede obtener una URL de Webhook, como se muestra en la imagen:

## Manejo de errores

Al llamar a la API, si se produce un error, la API devolverá el código de error y la información correspondientes. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`: No autorizado, token de autorización no válido o faltante.
- `429 too_many_requests`: Demasiadas solicitudes, ha superado el límite de velocidad.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

## Conclusión

A través de este documento, ya ha comprendido cómo utilizar la API de generación de videos Kling para generar videos mediante la introducción de indicaciones y una imagen de referencia del primer fotograma. Esperamos que este documento pueda ayudarle a integrar y utilizar mejor esta API. Si tiene alguna pregunta, no dude en contactar con nuestro equipo de soporte técnico.

### Kling 3.0 Turbo

`model="kling-v3-turbo"` admite video generado a partir de texto y video generado a partir de una imagen del primer fotograma, con duraciones enteras de 3–15 segundos. `mode="std"` genera 720p y `mode="pro"` genera 1080p. Este modelo incluye audio nativo y no proporciona un interruptor para desactivarlo; omita `generate_audio` o establézcalo en `true`. Este modelo no admite el fotograma final, objetos de movimiento de cámara, indicaciones negativas independientes ni `cfg_scale`. Describa directamente en `prompt` el contenido que necesita o desea evitar que aparezca.

### Video de múltiples tomas

`kling-v3` y `kling-v3-omni` admiten `multi_shot=true`. `shot_type="intelligence"` divide automáticamente en tomas según `prompt`; `shot_type="customize"` proporciona 1–6 tomas mediante `multi_prompt`, donde cada elemento contiene un `index` que aumenta continuamente desde 1, un `prompt` de hasta 512 caracteres y una `duration` entera de al menos 1 segundo. La suma de las duraciones de todas las tomas debe ser igual a la `duration` total. Las tomas personalizadas no utilizan el `prompt` global. Las múltiples tomas se cobran según el modelo seleccionado, la calidad de imagen, la configuración de audio y la duración total.
