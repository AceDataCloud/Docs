Este documento presentará una guía de integración de la API de generación de videos Kling, que permite generar videos oficiales de Kling mediante la entrada de parámetros personalizados.

## Proceso de solicitud

Para utilizar la API de generación de videos Kling, primero dirígete a [la consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obtener tu token de API, que debes guardar para uso futuro.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si aún no has iniciado sesión o registrado, serás redirigido automáticamente a la página de inicio de sesión que te invitará a registrarte e iniciar sesión; una vez completado, serás devuelto automáticamente a la página actual.

**Un token de API es suficiente para acceder a todos los servicios de la plataforma, no es necesario solicitar uno para cada servicio.** La primera solicitud incluirá un crédito gratuito para que puedas probarlo; si el crédito es insuficiente, puedes recargar el saldo general en [la consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [API de generación de videos Kling →](https://platform.acedata.cloud/documents/kling-videos)

## Uso básico

Primero, es importante entender la forma básica de uso, que consiste en ingresar la palabra clave `prompt`, la acción de generación `action`, la imagen de referencia del primer fotograma `start_image_url` y el modelo `model`, para obtener el resultado procesado. Primero, necesitas pasar un campo `action`, cuyo valor es `text2video`, que incluye principalmente tres acciones: video a partir de texto (`text2video`), video a partir de imagen (`image2video`), y video extendido (`extend`). Luego, también necesitamos ingresar el modelo `model`, que actualmente incluye principalmente los modelos `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-video-o1`, cuyos detalles son los siguientes:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Aquí podemos ver que hemos configurado los encabezados de la solicitud, que incluyen:

- `accept`: el formato de respuesta que deseas recibir, aquí se establece como `application/json`, es decir, formato JSON.
- `authorization`: la clave para llamar a la API, que puedes seleccionar directamente después de solicitarla.

Además, se ha configurado el cuerpo de la solicitud, que incluye:

- `model`: el modelo para generar el video, que incluye principalmente `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-video-o1`.
- `mode`: el modo de generación de video, con valores opcionales de modo estándar `std`, modo rápido `pro` y modo nativo 4K `4k`. El `4k` solo es compatible con `kling-v3` y `kling-v3-omni`, y no es compatible con `camera_control` (control de cámara).
- `action`: la acción de la tarea de generación de video, que incluye principalmente tres acciones: video a partir de texto (`text2video`), video a partir de imagen (`image2video`), video extendido (`extend`).
- `start_image_url`: cuando se elige la acción de video a partir de imagen `image2video`, es necesario subir el enlace de la imagen de referencia del primer fotograma.
- `end_image_url`: opcional al generar video a partir de imagen, especifica el fotograma final.
- `duration`: duración del video, en segundos. Para los modelos `kling-v3` y `kling-v3-omni`, se admite una duración flexible de 3 a 15 segundos (números enteros), otros modelos admiten 5 o 10 segundos.
- `generate_audio`: si se debe generar audio de forma sincronizada, opcional, valor booleano. Admite `kling-v3`, `kling-v3-omni` y `kling-v2-6` (solo en modo pro). Por defecto es `false`.
- `aspect_ratio`: relación de aspecto del video, opcional, admite `16:9`, `9:16`, `1:1`, por defecto `16:9`.
- `cfg_scale`: intensidad de correlación, rango [0,1], cuanto mayor, más se ajusta a la palabra clave.
- `camera_control`: opcional, parámetros para controlar el movimiento de la cámara, admite configuraciones predefinidas type/simple y horizontal, vertical, paneo, inclinación, rotación, zoom, etc.
- `negative_prompt`: opcional, palabras clave inversas que no deseas que aparezcan, hasta 200 caracteres.
- `element_list`: lista de referencias de sujetos, solo aplicable al modelo `kling-video-o1`, utilizada para referenciar los ID de elementos en la biblioteca de sujetos, ver más abajo "Referencia Omni".
- `image_list`: lista de imágenes de referencia (referencia de múltiples imágenes), solo aplicable al modelo `kling-video-o1`, ver más abajo "Referencia Omni".
- `video_list`: lista de videos de referencia (admite edición de video), solo aplicable al modelo `kling-video-o1`, ver más abajo "Referencia Omni".
- `prompt`: palabra clave.
- `callback_url`: URL para recibir el resultado de la llamada.
- `async`: opcional, si se establece en `true`, la interfaz devuelve inmediatamente `task_id`, sin necesidad de proporcionar `callback_url`, luego puedes consultar el resultado a través de la interfaz de consulta de tareas correspondiente.

Después de seleccionar, puedes ver que también se ha generado el código correspondiente a la derecha, como se muestra en la imagen:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Haz clic en el botón "Probar" para realizar una prueba, como se muestra en la imagen anterior, aquí hemos obtenido el siguiente resultado:

```json
{
  "success": true,
  "video_id": "900798310464749610",
  "video_url": "https://platform2.cdn.acedata.cloud/kling/6c68c267-065b-4423-b66b-a0e4c59ee0d5.mp4",
  "duration": "5.041",
  "state": "succeed",
  "task_id": "6c68c267-065b-4423-b66b-a0e4c59ee0d5"
}
```

El resultado devuelto tiene varios campos, que se describen a continuación:

- `success`, el estado de la tarea de generación de video en ese momento.
- `task_id`, el ID de la tarea de generación de video en ese momento.
- `video_id`, el ID del video generado en esa tarea.
- `video_url`, el enlace del video generado en esa tarea.
- `duration`, la duración del video generado en esa tarea.
- `state`, el estado de la tarea de generación de video en ese momento.

Podemos ver que hemos obtenido información satisfactoria sobre el video, solo necesitamos acceder al enlace del video generado en `data` para obtener el video de Kling.

Además, si deseas generar el código de integración correspondiente, puedes copiarlo directamente, por ejemplo, el código de CURL es el siguiente:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "Taza de café de cerámica blanca sobre una encimera de mármol brillante con luz de ventana de la mañana. La cámara rota lentamente 360 grados alrededor de la taza, deteniéndose brevemente en el asa."
}'
```

## Matriz de capacidades del modelo
不同 modelos tienen un soporte de parámetros que varía considerablemente. La siguiente matriz se organiza a partir de la [documentación de modelos de video de Kling](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels), por favor verifica antes de llamar si la combinación actual de `model` / `mode` / `duration` soporta la funcionalidad que necesitas, de lo contrario, el sistema devolverá errores como `model/mode/duration(...) is not supported with image_tail`.

| Modelo                | Modo             | `end_image_url` (fotogramas inicial y final) | `generate_audio` (audio) | `camera_control` (control de cámara) | Notas                                           |
| --------------------- | ---------------- | ---------------------------------------------- | ------------------------- | ------------------------------------- | ----------------------------------------------- |
| `kling-v1`            | std / pro        | ✅ solo `duration=5`                          | ❌                       | ✅ solo `duration=5`                 | `extend` no soporta `negative_prompt` ni `cfg_scale` |
| `kling-v1-6`          | std              | ❌                                            | ❌                       | ❌                                   | Video de múltiples imágenes, `extend` disponible en todos los modos |
| `kling-v1-6`          | pro              | ✅                                            | ❌                       | ❌                                   |                                               |
| `kling-v2-master`     | —                | ❌                                            | ❌                       | ❌                                   | Modo único, solo `duration=5/10`               |
| `kling-v2-1-master`   | —                | ❌                                            | ❌                       | ❌                                   | Modo único, solo `duration=5/10`               |
| `kling-v2-5-turbo`    | std              | ❌                                            | ❌                       | ❌                                   |                                               |
| `kling-v2-5-turbo`    | pro              | ✅                                            | ❌                       | ❌                                   |                                               |
| `kling-v2-6`          | std              | ❌                                            | ❌                       | ❌                                   |                                               |
| `kling-v2-6`          | pro              | ✅                                            | ✅                       | ❌                                   | Único modelo no v3 que soporta audio simultáneamente |
| `kling-v3`            | std / pro        | ✅                                            | ✅                       | ✅                                   | Rango de `duration` de 3 a 15 segundos         |
| `kling-v3`            | 4k               | ✅                                            | ✅                       | ❌                                   | Modo 4K incompatible con control de cámara      |
| `kling-v3-omni`       | std / pro / 4k   | ✅                                            | ✅                       | ❌                                   |                                               |
| `kling-video-o1`      | std / pro        | ✅                                            | ❌                       | ❌                                   | Solo soporta `duration=5/10`                   |

Notas:

- `mode=4k` solo es soportado por `kling-v3` y `kling-v3-omni`; además, es incompatible con `camera_control` (control de cámara).
- `end_image_url` solo puede usarse junto con `start_image_url` cuando la acción es `action=image2video`. Solo enviar `end_image_url` (sin `start_image_url`) será rechazado.
- `kling-v3` / `kling-v3-omni` aceptan cualquier duración entera de 3 a 15 segundos; los demás modelos solo aceptan 5 o 10.
- `generate_audio` es `false` por defecto. Solo `kling-v3`, `kling-v3-omni` y `kling-v2-6` (modo pro) lo soportan.

## Funcionalidad de video extendido

Si deseas continuar generando un video de Kling que ya ha sido creado, puedes establecer el parámetro `action` como `extend`, e ingresar el ID del video que deseas continuar generando. El ID del video se obtiene según el uso básico, como se muestra en la siguiente imagen:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

En este momento, puedes ver que el ID del video es:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Nota: el `video_id` aquí es el ID del video generado. Si no sabes cómo generar un video, puedes consultar el uso básico mencionado anteriormente.

A continuación, debemos completar los siguientes pasos con las palabras clave que necesitamos para personalizar la generación del video, especificando el siguiente contenido:

- `model`: el modelo para generar el video, principalmente `kling-v1`, `kling-v1-5` y `kling-v1-6`.
- `mode`: el modo para generar el video, los valores opcionales son modo estándar `std`, modo rápido `pro` y modo nativo 4K `4k` (solo soportado por `kling-v3` y `kling-v3-omni`, incompatible con el control de cámara).
- `duration`: la duración del video para esta tarea de generación, principalmente 5s y 10s.
- `start_image_url`: cuando se elige la acción de imagen a video `image2video`, es necesario subir el enlace de la imagen de referencia del primer fotograma.
- `prompt`: palabras clave.

Ejemplo de llenado:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Una vez completado, se generará automáticamente el siguiente código:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

Código correspondiente en Python:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "Taza de café de cerámica blanca sobre una encimera de mármol brillante con luz de ventana de la mañana. La cámara rota lentamente 360 grados alrededor de la taza, deteniéndose brevemente en el asa.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Al hacer clic en ejecutar, se puede observar que se obtiene un resultado como el siguiente:

```json
{
  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7822108635/extendVideo/Cjil4mfBfs0AAAAAAKhr6A-0_raw_video_1.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```

Se puede ver que el contenido del resultado es consistente con lo mencionado anteriormente, lo que también logra la funcionalidad de extensión de video.

## Referencia Omni (edición de video / video de referencia / múltiples imágenes / referencia de sujeto)

El modelo `kling-video-o1` soporta la capacidad de "referencia omnidireccional": sobre la base de la generación de video a partir de texto (`action=text2video`), se pueden pasar imágenes de referencia, sujetos de referencia o videos de referencia adicionales, lo que permite **referencias de múltiples imágenes, referencias de sujetos, videos de referencia, y editar videos existentes directamente**.

**Convenio central**: el material de referencia debe ser citado en `prompt` en la forma `&lt;&lt;<image_1>>>`, `&lt;&lt;<element_1>>>`, `&lt;&lt;<video_1>>>` (numeración comenzando desde 1) para que el modelo aplique estas referencias. Si solo se envía el material sin citarlo en las palabras clave, será ignorado.

### Videos de referencia y edición de video (`video_list`)
`video_list` se utiliza para pasar videos de referencia, es el escenario más común de esta capacidad, los campos de los elementos del array son los siguientes:

- `video_url`: enlace del video de referencia, no puede estar vacío. Requisitos: formato MP4/MOV; resolución 720px–2160px; duración 3–10 segundos; tasa de cuadros 24–60fps; tamaño del archivo ≤200MB; máximo 1 video.
- `refer_type`: tipo de referencia, puede ser `base` (por defecto, **video base a editar**, es decir, "editar directamente el video", se pueden agregar/eliminar/modificar elementos, cambiar la composición, cambiar el estilo, cambiar el color, cambiar el clima, etc.) o `feature` (**referencia de características**, referencia de su estilo / movimiento de cámara / continuación de la siguiente toma).
- `keep_original_sound`: si se debe mantener el audio original del video, puede ser `yes` (mantener) o `no` (eliminar).

> Nota: Si hay un video de referencia, `generate_audio` debe ser `false`. El video con `refer_type=base` no puede especificar el primer cuadro / último cuadro.

Ejemplo de CURL para editar un video existente (cambiar el video a estilo de anime):

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-video-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "cambiar <<<video_1>>> a un estilo de anime de nivel cinematográfico, manteniendo el movimiento y la composición originales",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Referencia de múltiples imágenes (`image_list`)

`image_list` se utiliza para pasar imágenes de referencia (elementos / escenas / estilos, etc.), los campos de los elementos del array son los siguientes:

- `image_url`: enlace de la imagen de referencia, no puede estar vacío. Requisitos: formato .jpg/.jpeg/.png; tamaño del archivo ≤10MB; lado más corto ≥300px; relación de aspecto 1:2.5 ~ 2.5:1.
- `type`: opcional. Si no se pasa, se considera como imagen de referencia pura; si se pasa `first_frame` / `end_frame`, se considera como primer cuadro / último cuadro (equivalente a `start_image_url` / `end_image_url`).

Al usarlo, se debe referenciar en `prompt` como `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Límite de cantidad: si no hay video de referencia, la suma de imágenes de referencia + sujetos de múltiples imágenes ≤ 7; si hay video de referencia, ≤ 4. Si solo se pasan el primer / último cuadro, también se puede usar directamente `start_image_url` / `end_image_url`.

> Nota: Si se pasan simultáneamente `start_image_url` / `end_image_url` y `image_list`, el primer / último cuadro se colocará antes de `image_list`, lo que puede afectar la relación de correspondencia de los números de `&lt;&lt;<image_N>>>`. Se recomienda elegir uno: si se necesita el primer / último cuadro, especifíquelo directamente en `image_list` usando `type`, no mezcle con `start_image_url` / `end_image_url`.

Ejemplo de CURL para generar un video con referencia de múltiples imágenes:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-video-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "hacer que los personajes en <<<image_1>>> estén en la escena de <<<image_2>>>, con iluminación cinematográfica",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

### Referencia de elementos (`element_list`)

`element_list` se utiliza para referenciar elementos ya subidos en la "biblioteca de sujetos", el campo del elemento es `element_id` (ID del elemento en la biblioteca de sujetos, entero). Al usarlo, también se debe referenciar en `prompt` como `&lt;&lt;<element_1>>>`. La cantidad de sujetos de referencia debe sumarse a la cantidad de imágenes de referencia: si hay video de referencia, la suma de ambos ≤ 4, si no hay video de referencia, ≤ 7.

## Callback asíncrono

Dado que el tiempo de generación de la API de Kling Videos es relativamente largo, aproximadamente 1-2 minutos, si la API no responde durante mucho tiempo, la solicitud HTTP mantendrá la conexión, lo que provocará un consumo adicional de recursos del sistema, por lo que esta API también ofrece soporte para callbacks asíncronos.

El flujo general es: cuando el cliente inicia la solicitud, se especifica un campo adicional `callback_url`, después de que el cliente inicia la solicitud de API, la API devolverá inmediatamente un resultado que incluye un campo `task_id`, que representa el ID de la tarea actual. Cuando la tarea se completa, el resultado del video generado se enviará a la `callback_url` especificada por el cliente en formato JSON POST, que también incluye el campo `task_id`, de modo que el resultado de la tarea se pueda asociar mediante el ID.

Primero, el callback de Webhook es un servicio que puede recibir solicitudes HTTP, el desarrollador debe reemplazarlo con la URL de su propio servidor HTTP. ## Manejo de errores

Al llamar a la API, si se encuentra con un error, la API devolverá el código de error correspondiente y la información. Por ejemplo:
- `400 token_mismatched`：Solicitud incorrecta, posiblemente debido a parámetros faltantes o inválidos.
- `400 api_not_implemented`：Solicitud incorrecta, posiblemente debido a parámetros faltantes o inválidos.
- `401 invalid_token`：No autorizado, token de autorización inválido o faltante.
- `429 too_many_requests`：Demasiadas solicitudes, ha superado el límite de tasa.
- `500 api_error`：Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "la recuperación falló"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
