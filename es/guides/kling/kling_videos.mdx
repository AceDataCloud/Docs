Este artículo presentará unas instrucciones de integración de Kling Videos Generation API, que permite generar los videos oficiales de Kling introduciendo parámetros personalizados.

## Proceso de solicitud

Para utilizar Kling Videos Generation API, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, se le redirigirá automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; una vez completado, volverá automáticamente a la página actual.

**Un API Token permite llamar a todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluye una cuota gratuita para probarlo sin coste; cuando la cuota sea insuficiente, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Kling Videos Generation API →](https://platform.acedata.cloud/documents/kling-videos)

## Uso básico

Primero, conozcamos el método básico de uso: introduciendo el prompt `prompt`, la acción de generación `action`, la imagen de referencia del primer fotograma `start_image_url` y el modelo `model`, puede obtener el resultado procesado. Primero es necesario pasar simplemente un campo `action`, cuyo valor es `text2video`; este incluye principalmente tres comportamientos: texto a video (`text2video`), imagen a video (`image2video`) y extensión de video (`extend`). Después, también necesitamos introducir el modelo `model`; actualmente, los principales modelos son `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`; el contenido específico es el siguiente:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Aquí puede verse que hemos configurado los Request Headers, incluyendo:

- `accept`: el formato de resultado de respuesta que se desea recibir; aquí se establece como `application/json`, es decir, formato JSON.
- `authorization`: la clave para llamar a la API, que puede seleccionarse directamente en el menú desplegable después de solicitarla.

Además, se ha configurado el Request Body, incluyendo:

- `model`: el modelo para generar videos; los principales modelos son `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-o1`.
- `mode`: el modo para generar videos; los valores opcionales son modo estándar `std`, modo ultrarrápido `pro` y modo nativo 4K `4k`. Entre ellos, `4k` solo es compatible con `kling-v3` y `kling-v3-omni`, y no es compatible con `camera_control` (control de movimiento de cámara).
- `action`: el comportamiento de esta tarea de generación de video, que incluye principalmente tres comportamientos: texto a video (`text2video`), imagen a video (`image2video`) y extensión de video (`extend`).
- `start_image_url`: el enlace de la imagen de referencia del primer fotograma que se debe cargar al seleccionar el comportamiento de imagen a video `image2video`.
- `end_image_url`: opcional para imagen a video; especifica el fotograma final.
- `duration`: duración del video, en segundos. `kling-v3` y `kling-v3-omni` admiten duraciones enteras de 3 a 15 segundos; `kling-o1` solo admite 5 segundos; los demás modelos admiten 5 o 10 segundos.
- `generate_audio`: si se genera audio de forma sincronizada, opcional, valor booleano. Compatible con `kling-v3`, `kling-v3-omni` y `kling-v2-6` (solo en modo pro). El valor predeterminado es `false`.
- `aspect_ratio`: relación de aspecto del video, opcional; admite `16:9`, `9:16`, `1:1`, con valor predeterminado `16:9`.
- `cfg_scale`: intensidad de relevancia, rango [0,1]; cuanto mayor sea, más se ajustará al prompt.
- `camera_control`: opcional, parámetro de objeto para controlar el movimiento de cámara; admite preajustes type/simple y configuraciones como horizontal, vertical, pan, tilt, roll, zoom, etc.
- `negative_prompt`: opcional, prompt negativo de elementos que no se desean mostrar, con un máximo de 200 caracteres.
- `image_list`: lista de imágenes de referencia Omni, aplicable a los modelos `kling-o1` y `kling-v3-omni`; consulte a continuación «Referencia integral Omni» para su uso.
- `video_list`: lista de videos de referencia Omni (admite edición de video), aplicable a los modelos `kling-o1` y `kling-v3-omni`; consulte a continuación «Referencia integral Omni» para su uso.
- `prompt`: prompt.
- `callback_url`: la URL que necesita recibir el resultado de la devolución de llamada.
- `async`: opcional; cuando se establece como `true`, la interfaz devuelve inmediatamente `task_id`, sin necesidad de proporcionar `callback_url`; posteriormente, el resultado se obtiene mediante sondeo a través de la interfaz de consulta de tareas correspondiente.

Además, si desea generar el código de integración correspondiente, puede copiarlo directamente; por ejemplo, el código CURL es el siguiente:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle."
}'
```

## Matriz de capacidades de los modelos

Existen diferencias considerables en la compatibilidad de parámetros entre distintos modelos. La siguiente matriz se ha recopilado a partir de la [documentación oficial de Kling sobre video models](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels); antes de realizar la llamada, compruebe primero si la combinación actual de `model` / `mode` / `duration` admite la función que necesita; de lo contrario, se devolverán errores como `model/mode/duration(...) is not supported with image_tail`.
| Modelo              | Modo             | `end_image_url`（fotogramas inicial y final） | `generate_audio`（audio de acompañamiento） | `camera_control`（movimiento de cámara） | Notas                                        |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ Solo `duration=5`  | ❌                    | ✅ Solo `duration=5`  | `extend` no admite `negative_prompt` ni `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | Vídeo a partir de múltiples imágenes, `extend` disponible en todos los modos |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | Modo único, solo `duration=5/10`             |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | Modo único, solo `duration=5/10`             |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | El único modelo no v3 que admite simultáneamente audio de acompañamiento |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | Rango de `duration` de 3–15 segundos         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | El modo 4K es incompatible con el movimiento de cámara |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-o1`          | std / pro      | ✅                    | ❌                    | ❌                    | Solo admite `duration=5`                     |

Notas:

- `mode=4k` solo es compatible con `kling-v3` y `kling-v3-omni`; además, es mutuamente excluyente con `camera_control`（movimiento de cámara）.
- `end_image_url` solo puede usarse junto con `start_image_url` cuando `action=image2video`. Enviar solo `end_image_url`（sin `start_image_url`）será rechazado.
- `kling-v3` / `kling-v3-omni` aceptan cualquier `duration` entero de 3–15 segundos; `kling-o1` solo acepta 5; los demás modelos solo aceptan 5 o 10.
- `generate_audio` es `false` de forma predeterminada. Solo `kling-v3`, `kling-v3-omni` y `kling-v2-6`（modo pro）son compatibles.

## Función de extensión de vídeo

Si desea continuar generando un vídeo de Kling ya generado, puede establecer el parámetro `action` como `extend` e introducir el ID del vídeo que necesita seguir generándose. La obtención del ID del vídeo se realiza según el uso básico, como se muestra en la siguiente imagen:

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

En este momento puede ver que el ID del vídeo es:

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> Tenga en cuenta que el `video_id` del vídeo aquí es el ID del vídeo después de generarse. Si no sabe cómo generar un vídeo, puede consultar el uso básico anterior para generar un vídeo.

A continuación, debemos completar las palabras clave que deben ampliarse en el siguiente paso para personalizar el vídeo generado, y se puede especificar el siguiente contenido:

- `model`: El modelo para generar vídeos, incluye principalmente los modelos `kling-v1`, `kling-v1-5` y `kling-v1-6`.
- `mode`: El modo para generar vídeos, los valores opcionales son el modo estándar `std`, el modo ultrarrápido `pro` y el modo 4K nativo `4k`（solo compatible con `kling-v3` y `kling-v3-omni`, incompatible con el control de movimiento de cámara）.
- `duration`: La duración del vídeo para esta tarea de generación de vídeo, incluye principalmente 5 s y 10 s.
- `start_image_url`: Al elegir la acción de vídeo a partir de imagen `image2video`, se requiere obligatoriamente el enlace de la imagen de referencia del fotograma inicial que debe cargarse.
- `prompt`: Palabras clave.

El ejemplo de relleno es el siguiente:

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

Después de completar, se genera automáticamente el siguiente código:

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Referencia omnipotente Omni（edición de vídeo / vídeo de referencia / referencia de múltiples imágenes）

`kling-o1` y `kling-v3-omni` son dos modelos independientes, ambos admiten la capacidad de «referencia omnipotente». Sobre la base de vídeo a partir de texto（`action=text2video`）, se pueden introducir adicionalmente imágenes de referencia o vídeos de referencia para lograr **referencia de múltiples imágenes, vídeo de referencia y editar directamente vídeos existentes**.

**Convención principal**: Los materiales de referencia deben citar los materiales en las posiciones correspondientes de `image_list` / `video_list` en el `prompt` mediante la forma `&lt;&lt;<image_1>>>`, `&lt;&lt;<video_1>>>`（la numeración comienza desde 1）, para que el modelo aplique estas referencias. Si solo se envían materiales sin citarlos en las palabras clave, los materiales se ignorarán.

> Nota de seguridad: La API actual no abre `element_list`. El ID de Kling Element Library no está aislado por inquilino; antes de proporcionar la API de gestión de elementos con aislamiento por inquilino, utilice `image_list` para introducir imágenes de referencia del sujeto.

Las solicitudes Omni no admiten `negative_prompt`, `cfg_scale` ni `camera_control`, y tampoco pueden usar `mode=4k`. Cuando se incluyen vídeos de referencia, `generate_audio` debe ser `false`.

### Vídeo de referencia y edición de vídeo（`video_list`）
`video_list` se utiliza para pasar videos de referencia y es el escenario más utilizado de esta capacidad; los campos de los elementos del arreglo son los siguientes:

- `video_url`: enlace del video de referencia, no puede estar vacío. Como máximo 1 video MP4/MOV, tamaño de archivo ≤200MB, frecuencia de fotogramas 24–60fps. `kling-o1` requiere una duración de 3–10 segundos, y ancho y alto de 700–2160px cada uno; `kling-v3-omni` requiere una duración de 3–15.5 segundos, ancho y alto de 700–4553px cada uno, píxeles totales ≤8,294,400 y relación de aspecto 0.4–2.
- `refer_type`: tipo de referencia, opcional entre `base` (predeterminado, **video base que se va a editar**, es decir, "editar directamente el video", permite añadir/eliminar/modificar elementos, cambiar la composición, cambiar el estilo, cambiar los colores, cambiar el clima, etc.) o `feature` (**referencia de características**, hace referencia a su estilo / movimiento de cámara / continuación de la siguiente toma).
- `keep_original_sound`: si se conserva el audio del video original, opcional entre `yes` (conservar) o `no` (eliminar).

> Nota: cuando existe un video de referencia, `generate_audio` debe ser `false`. No se puede especificar de nuevo un fotograma inicial / final para el video con `refer_type=base`.

El ejemplo de CURL para editar un video existente (cambiar el video a estilo anime) es el siguiente:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "把 <<<video_1>>> 改成电影级动漫风格，保留原有的运动和构图",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Referencia de múltiples imágenes (`image_list`)

`image_list` se utiliza para pasar imágenes de referencia (elementos / escenas / estilos, etc.); los campos de los elementos del arreglo son los siguientes:

- `image_url`: enlace de la imagen de referencia, no puede estar vacío. Requisitos: formato .jpg/.jpeg/.png; tamaño de archivo ≤10MB; lado más corto ≥300px; relación de aspecto 1:2.5 ~ 2.5:1.
- `type`: opcional. Cuando no se pasa, se utiliza como imagen de referencia pura; al pasar `first_frame` / `end_frame`, se utiliza respectivamente como fotograma inicial / final (equivalente a `start_image_url` / `end_image_url`).

Al usarlo, se debe hacer referencia en `prompt` mediante `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Límite de cantidad: cuando no existe un video de referencia, las imágenes de referencia ≤ 7; cuando existe un video de referencia, las imágenes de referencia ≤ 4. Al pasar únicamente fotogramas iniciales / finales, también se puede usar directamente `start_image_url` / `end_image_url`, pero el fotograma final debe usarse junto con el fotograma inicial.

> Nota: si se pasan simultáneamente `start_image_url` / `end_image_url` e `image_list`, los fotogramas iniciales / finales se colocarán antes de `image_list`, lo que puede afectar la correspondencia de los números de secuencia de `&lt;&lt;<image_N>>>`. Se recomienda elegir uno de los dos: cuando se necesiten fotogramas iniciales / finales, especifíquelos directamente mediante `type` en `image_list`, y no los mezcle con `start_image_url` / `end_image_url`.

Ejemplo de CURL para generar un video con referencia de múltiples imágenes:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "让 <<<image_1>>> 里的人物站在 <<<image_2>>> 的场景中，电影感光线",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

## Devolución de llamada asíncrona

Debido a que el tiempo de generación de Kling Videos Generation API es relativamente largo, aproximadamente 1-2 minutos, si la API no responde durante mucho tiempo, la solicitud HTTP mantendrá la conexión abierta continuamente, lo que provocará un consumo adicional de recursos del sistema; por ello, esta API también proporciona soporte para devoluciones de llamada asíncronas.

El flujo general es: cuando el cliente inicia una solicitud, especifica adicionalmente un campo `callback_url`; después de que el cliente inicia la solicitud de API, la API devolverá inmediatamente un resultado, que incluye un campo `task_id`, el cual representa el ID de la tarea actual. Cuando la tarea se completa, el resultado del video generado se enviará mediante POST JSON a la `callback_url` especificada por el cliente, donde también se incluye el campo `task_id`, de modo que los resultados de las tareas pueden asociarse mediante el ID.

A continuación, veremos mediante un ejemplo cómo operar específicamente.

En primer lugar, la devolución de llamada Webhook es un servicio que puede recibir solicitudes HTTP; el desarrollador debe reemplazarla con la URL de un servidor HTTP construido por sí mismo. ## Manejo de errores

Al llamar a la API, si se encuentra un error, la API devolverá el código y la información de error correspondientes. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`: No autorizado, token de autorización no válido o faltante.
- `429 too_many_requests`: Demasiadas solicitudes, ha superado el límite de frecuencia.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.
### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
