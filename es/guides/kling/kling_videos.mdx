Este documento presentará una guía de integración de la API de generación de videos Kling, que permite generar videos oficiales de Kling mediante la entrada de parámetros personalizados.

## Proceso de solicitud

Para utilizar la API de generación de videos Kling, primero dirígete a [la consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obtener tu token de API, que debes guardar para uso futuro.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si aún no has iniciado sesión o registrado, serás redirigido automáticamente a la página de inicio de sesión que te invitará a registrarte e iniciar sesión; una vez completado, regresarás automáticamente a la página actual.

**Un token de API es suficiente para acceder a todos los servicios de la plataforma, no es necesario solicitar uno por cada servicio.** La primera solicitud incluirá un crédito gratuito para que puedas probarlo; si el crédito es insuficiente, puedes recargar el saldo general en [la consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [API de generación de videos Kling →](https://platform.acedata.cloud/documents/kling-videos)

## Uso básico

Primero, es importante entender la forma básica de uso, que consiste en ingresar la palabra clave `prompt`, la acción de generación `action`, la imagen de referencia del primer fotograma `start_image_url` y el modelo `model`, para obtener el resultado procesado. Primero, necesitas pasar un campo `action`, cuyo valor es `text2video`, que incluye principalmente tres acciones: video generado por texto (`text2video`), video generado por imagen (`image2video`), y video extendido (`extend`). Luego, también necesitamos ingresar el modelo `model`, que actualmente incluye principalmente los modelos `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-video-o1`, cuyos detalles son los siguientes:

<p><img src="https://cdn.acedata.cloud/ke1bok.png" width="500" className="m-auto" /></p>

Aquí podemos ver que hemos configurado los encabezados de la solicitud, que incluyen:

- `accept`: el formato de respuesta que deseas recibir, aquí se establece como `application/json`, es decir, en formato JSON.
- `authorization`: la clave para llamar a la API, que puedes seleccionar directamente después de solicitarla.

Además, se ha configurado el cuerpo de la solicitud, que incluye:

- `model`: el modelo para generar el video, que incluye principalmente `kling-v1`, `kling-v1-6`, `kling-v2-master`, `kling-v2-1-master`, `kling-v2-5-turbo`, `kling-v2-6`, `kling-v3`, `kling-v3-omni`, `kling-video-o1`.
- `mode`: el modo de generación de video, con valores opcionales de modo estándar `std`, modo rápido `pro` y modo nativo 4K `4k`. El `4k` solo es compatible con `kling-v3` y `kling-v3-omni`, y no es compatible con `camera_control` (control de cámara).
- `action`: la acción de la tarea de generación de video, que incluye principalmente tres acciones: video generado por texto (`text2video`), video generado por imagen (`image2video`), video extendido (`extend`).
- `start_image_url`: cuando se elige la acción de video generado por imagen `image2video`, es necesario subir el enlace de la imagen de referencia del primer fotograma.
- `end_image_url`: opcional al generar video por imagen, especifica el fotograma final.
- `duration`: duración del video, en segundos. Para los modelos `kling-v3` y `kling-v3-omni`, se admite una duración flexible de 3 a 15 segundos (números enteros), mientras que otros modelos admiten 5 o 10 segundos.
- `generate_audio`: si se debe generar audio de forma sincronizada, opcional, valor booleano. Admite `kling-v3`, `kling-v3-omni` y `kling-v2-6` (solo en modo pro). Por defecto es `false`.
- `aspect_ratio`: relación de aspecto del video, opcional, admite `16:9`, `9:16`, `1:1`, por defecto `16:9`.
- `cfg_scale`: intensidad de correlación, rango [0,1], cuanto mayor sea, más se ajustará a la palabra clave.
- `camera_control`: opcional, parámetros de objeto para controlar el movimiento de la cámara, admite configuraciones predefinidas type/simple y horizontal, vertical, paneo, inclinación, rotación, zoom, etc.
- `negative_prompt`: opcional, palabras clave inversas que no deseas que aparezcan, hasta 200 caracteres.
- `element_list`: lista de referencias de sujetos, solo aplicable al modelo `kling-video-o1`, utilizada para referenciar los ID de elementos de la biblioteca de sujetos, consulta la sección "Referencia Omni" a continuación.
- `image_list`: lista de imágenes de referencia (referencia múltiple), solo aplicable al modelo `kling-video-o1`, consulta la sección "Referencia Omni" a continuación.
- `video_list`: lista de videos de referencia (admite edición de video), solo aplicable al modelo `kling-video-o1`, consulta la sección "Referencia Omni" a continuación.
- `prompt`: palabra clave.
- `callback_url`: URL para recibir el resultado de la llamada.
- `async`: opcional, si se establece en `true`, la interfaz devuelve inmediatamente `task_id`, sin necesidad de proporcionar `callback_url`, y luego se puede consultar el resultado a través de la interfaz de consulta de tareas correspondiente.

Después de seleccionar, puedes ver que también se ha generado el código correspondiente a la derecha, como se muestra en la imagen:

<p><img src="https://cdn.acedata.cloud/3yjql0.png" width="500" className="m-auto" /></p>

Haz clic en el botón "Probar" para realizar una prueba, como se muestra en la imagen anterior, y obtendremos el siguiente resultado:

```json
{
  "success": true,
  "video_id": "900798310464749610",
  "video_url": "https://platform2.cdn.acedata.cloud/kling/6c68c267-065b-4423-b66b-a0e4c59ee0d5.mp4",
  "duration": "5.041",
  "state": "succeed",
  "task_id": "6c68c267-065b-4423-b66b-a0e4c59ee0d5"
```

El resultado devuelto tiene varios campos, que se describen a continuación:

- `success`, el estado de la tarea de generación de video en ese momento.
- `task_id`, el ID de la tarea de generación de video en ese momento.
- `video_id`, el ID del video de la tarea de generación de video en ese momento.
- `video_url`, el enlace del video de la tarea de generación de video en ese momento.
- `duration`, la duración del video de la tarea de generación de video en ese momento.
- `state`, el estado de la tarea de generación de video en ese momento.

Podemos ver que hemos obtenido información satisfactoria sobre el video, y solo necesitamos acceder al enlace del video generado en `data` para obtener el video de Kling.

Además, si deseas generar el código de integración correspondiente, puedes copiarlo directamente, por ejemplo, el código de CURL es el siguiente:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-v3",
  "prompt": "Taza de café de cerámica blanca sobre una encimera de mármol brillante con luz de ventana de la mañana. La cámara rota lentamente 360 grados alrededor de la taza, deteniéndose brevemente en el asa."
}'
```

## Matriz de capacidades del modelo
不同模型对参数的支持情况差异较大。以下矩阵整理自 [Kling 官方 video models 文档](https://app.klingai.com/global/dev/document-api/apiReference/model/videoModels)，调用前请先核对当前 `model` / `mode` / `duration` 组合是否支持你所需的功能，否则上游会返回 `model/mode/duration(...) is not supported with image_tail` 等错误。

| 模型                  | 模式             | `end_image_url`（首尾帧） | `generate_audio`（伴音） | `camera_control`（运镜） | 备注                                           |
| ------------------- | -------------- | -------------------- | -------------------- | -------------------- | -------------------------------------------- |
| `kling-v1`          | std / pro      | ✅ 仅 `duration=5`     | ❌                    | ✅ 仅 `duration=5`     | `extend` 不支持 `negative_prompt` 与 `cfg_scale` |
| `kling-v1-6`        | std            | ❌                    | ❌                    | ❌                    | 多图生视频、`extend` 全模式可用                         |
| `kling-v1-6`        | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-master`   | —              | ❌                    | ❌                    | ❌                    | 单一模式，仅 `duration=5/10`                       |
| `kling-v2-1-master` | —              | ❌                    | ❌                    | ❌                    | 单一模式，仅 `duration=5/10`                       |
| `kling-v2-5-turbo`  | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-5-turbo`  | pro            | ✅                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | std            | ❌                    | ❌                    | ❌                    |                                              |
| `kling-v2-6`        | pro            | ✅                    | ✅                    | ❌                    | 唯一同时支持伴音的非 v3 模型                             |
| `kling-v3`          | std / pro      | ✅                    | ✅                    | ✅                    | `duration` 范围 3–15 秒                         |
| `kling-v3`          | 4k             | ✅                    | ✅                    | ❌                    | 4K 模式与运镜不兼容                                  |
| `kling-v3-omni`     | std / pro / 4k | ✅                    | ✅                    | ❌                    |                                              |
| `kling-video-o1`    | std / pro      | ✅                    | ❌                    | ❌                    | 仅支持 `duration=5`                             |

注意事项：

- `mode=4k` 仅 `kling-v3` 与 `kling-v3-omni` 支持；并且与 `camera_control`（运镜）互斥。
- `end_image_url` 只能在 `action=image2video` 时配合 `start_image_url` 使用。仅传 `end_image_url`（无 `start_image_url`）会被拒绝。
- `kling-v3` / `kling-v3-omni` 接受任意 3–15 秒的整数 `duration`；`kling-video-o1` 仅接受 5；其余模型只接受 5 或 10。
- `generate_audio` 默认 `false`。仅 `kling-v3`、`kling-v3-omni` 和 `kling-v2-6`（pro 模式）支持。

## 扩展视频功能

如果想对已经生成的Kling视频进行继续生成的话，可以将参数 `action` 设置为 `extend` ，并且输入需要继续生成视频的 ID，视频 ID 的获取是根据基本使用来获取，如下图所示：

<p><img src="https://cdn.acedata.cloud/om6p6g.png" width="500" className="m-auto" /></p>

这时候可以看到视频的 ID 为：

```
"video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c"
```

> 注意，这里的视频中 `video_id` 是生成后视频的 ID，如果你不知道如何生成视频，可以参考上文的基本使用来生成视频。

接下来我们要必须填下一步需要扩展的提示词来自定义生成视频，就可以指定如下内容：

- `model`：生成视频的模型，主要有 `kling-v1` 、`kling-v1-5` 和 `kling-v1-6` 模型。
- `mode`：生成视频的模式，可选值为标准模式 `std`、极速模式 `pro` 和原生 4K 模式 `4k`（仅 `kling-v3` 和 `kling-v3-omni` 支持，与运镜控制不兼容）。
- `duration`：此次视频生成任务的视频时长，主要包含5s和10s。
- `start_image_url`：当选择图生视频行为 `image2video` 就必须需要上传的首帧参考图片链接。
- `prompt`：提示词。

填写样例如下：

<p><img src="https://cdn.acedata.cloud/ejimqy.png" width="500" className="m-auto" /></p>

填写完毕之后自动生成了代码如下：

<p><img src="https://cdn.acedata.cloud/52x4u5.png" width="500" className="m-auto" /></p>

对应的 Python 代码：

```python
import requests

url = "https://api.acedata.cloud/kling/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "model": "kling-v1",
    "video_id": "030bb06d-98d4-4044-9042-0aa0822e8c8c",
    "prompt": "White ceramic coffee mug on glossy marble countertop with morning window light. Camera slowly rotates 360 degrees around the mug, pausing briefly at the handle.",
    "duration": 10
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

点击运行，可以发现会得到一个结果，如下：

```json

  "success": true,
  "video_id": "bbc3b105-ac72-4de2-8390-0cb37dc7d41e",
  "video_url": "https://cdn.klingai.com/bs2/upload-kling-api/7822108635/extendVideo/Cjil4mfBfs0AAAAAAKhr6A-0_raw_video_1.mp4",
  "duration": "9.6",
  "state": "succeed",
  "task_id": "3ece87e6-3ee3-4f5e-bd70-5ae5eca89a23"
}
```

可以看出，结果内容与上文的是一致的，这也就实现视频的扩展视频功能。

## Omni 全能参考（视频编辑 / 参考视频 / 多图 / 主体参考）

`kling-video-o1` 模型支持「全能参考」能力：在文生视频（`action=text2video`）的基础上，额外传入参考图片、参考主体或参考视频，即可实现**多图参考、主体参考、参考视频、以及直接对已有视频进行编辑**。

**核心约定**：参考素材必须在 `prompt` 中以 `&lt;&lt;<image_1>>>`、`&lt;&lt;<element_1>>>`、`&lt;&lt;<video_1>>>` 的形式（序号从 1 开始）引用 `image_list` / `element_list` / `video_list` 中对应位置的素材，模型才会应用这些参考。若只传素材而不在提示词中引用，素材会被忽略。
### Videos de referencia y edición de video (`video_list`)

`video_list` se utiliza para pasar videos de referencia, es el escenario más común de esta capacidad, los campos de los elementos del arreglo son los siguientes:

- `video_url`: enlace del video de referencia, no puede estar vacío. Requisitos: formato MP4/MOV; resolución 720px–2160px; duración 3–10 segundos; tasa de cuadros 24–60fps; tamaño del archivo ≤200MB; máximo 1 video.
- `refer_type`: tipo de referencia, puede ser `base` (por defecto, **video base a editar**, es decir, "editar directamente el video", se pueden agregar/eliminar/modificar elementos, cambiar la composición, cambiar el estilo, cambiar el color, cambiar el clima, etc.) o `feature` (**referencia de características**, referencia de su estilo / movimiento de cámara / continuación de la siguiente toma).
- `keep_original_sound`: si se debe conservar el audio original del video, puede ser `yes` (conservar) o `no` (eliminar).

> Nota: Si hay un video de referencia, `generate_audio` debe ser `false`. Los videos con `refer_type=base` no pueden especificar el primer cuadro / último cuadro.

Ejemplo de CURL para editar un video existente (cambiar el video a estilo de anime):

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-video-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "cambiar <<<video_1>>> a un estilo de anime de nivel cinematográfico, conservando el movimiento y la composición originales",
  "video_list": [
    {
      "video_url": "https://cdn.acedata.cloud/your-reference-video.mp4",
      "refer_type": "base",
      "keep_original_sound": "no"
    }
  ]
}'
```

### Referencia de múltiples imágenes (`image_list`)

`image_list` se utiliza para pasar imágenes de referencia (elementos / escenas / estilos, etc.), los campos de los elementos del arreglo son los siguientes:

- `image_url`: enlace de la imagen de referencia, no puede estar vacío. Requisitos: formato .jpg/.jpeg/.png; tamaño del archivo ≤10MB; lado más corto ≥300px; relación de aspecto 1:2.5 ~ 2.5:1.
- `type`: opcional. Si no se pasa, se considera como imagen de referencia pura; si se pasa `first_frame` / `end_frame`, se considera como primer cuadro / último cuadro (equivalente a `start_image_url` / `end_image_url`).

Al usarlo, se debe referenciar en `prompt` como `&lt;&lt;<image_1>>>`, `&lt;&lt;<image_2>>>`. Límite de cantidad: si no hay video de referencia, la suma de imágenes de referencia + sujetos de múltiples imágenes ≤ 7; si hay video de referencia, ≤ 4. También se puede usar directamente `start_image_url` / `end_image_url` al pasar solo el primer / último cuadro.

> Nota: Si se pasan simultáneamente `start_image_url` / `end_image_url` y `image_list`, el primer / último cuadro se colocará antes de `image_list`, lo que puede afectar la relación de correspondencia de los números de `&lt;&lt;<image_N>>>`. Se recomienda elegir uno: si se necesita el primer / último cuadro, se debe especificar directamente en `image_list` usando `type`, no mezclar con `start_image_url` / `end_image_url`.

Ejemplo de CURL para generar un video con referencia de múltiples imágenes:

```shell
curl -X POST 'https://api.acedata.cloud/kling/videos' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "text2video",
  "model": "kling-video-o1",
  "mode": "std",
  "duration": 5,
  "prompt": "hacer que los personajes de <<<image_1>>> estén en la escena de <<<image_2>>>, con iluminación cinematográfica",
  "image_list": [
    { "image_url": "https://cdn.acedata.cloud/subject.png" },
    { "image_url": "https://cdn.acedata.cloud/scene.png" }
  ]
}'
```

### Referencia de elementos (`element_list`)

`element_list` se utiliza para referenciar elementos ya subidos en la "biblioteca de sujetos", el campo del arreglo es `element_id` (ID del elemento en la biblioteca de sujetos, entero). Al usarlo, también se debe referenciar en `prompt` como `&lt;&lt;<element_1>>>`. La cantidad de sujetos de referencia debe sumarse a la cantidad de imágenes de referencia: si hay video de referencia, la suma de ambos ≤ 4, si no hay video de referencia, ≤ 7.

## Callback asíncrono

Dado que el tiempo de generación de la API de Kling Videos es relativamente largo, aproximadamente 1-2 minutos, si la API no responde durante mucho tiempo, la solicitud HTTP mantendrá la conexión, lo que provocará un consumo adicional de recursos del sistema, por lo que esta API también ofrece soporte para callbacks asíncronos.

El flujo general es: cuando el cliente inicia la solicitud, se especifica un campo adicional `callback_url`, después de que el cliente inicia la solicitud de API, la API devolverá inmediatamente un resultado que incluye un campo `task_id`, que representa el ID de la tarea actual. Cuando la tarea se completa, el resultado del video generado se enviará a la `callback_url` especificada por el cliente en formato JSON POST, que también incluye el campo `task_id`, de modo que el resultado de la tarea se pueda asociar mediante el ID.

A continuación, veamos un ejemplo de cómo operar.

Primero, el callback de Webhook es un servicio que puede recibir solicitudes HTTP, el desarrollador debe reemplazarlo con la URL de su propio servidor HTTP. ## Manejo de errores

Al llamar a la API, si se encuentra un error, la API devolverá el código de error correspondiente y la información. Por ejemplo:
- `400 token_mismatched`：Solicitud incorrecta, posiblemente debido a parámetros faltantes o inválidos.
- `400 api_not_implemented`：Solicitud incorrecta, posiblemente debido a parámetros faltantes o inválidos.
- `401 invalid_token`：No autorizado, token de autorización inválido o faltante.
- `429 too_many_requests`：Demasiadas solicitudes, ha superado el límite de tasa.
- `500 api_error`：Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```json
{

  },

}
```
