Envía una tarea mediante `POST /kling/virtual-try-on` y utiliza el existente `POST /kling/tasks` para consultar el estado de la tarea en la plataforma.

## Entrada

Se debe proporcionar exactamente una product_image y una person_image. keep_face, keep_pose y keep_background son true por defecto y pueden desactivarse de forma independiente. El lado más largo de la imagen de entrada no debe superar 2048px, el lado más corto debe ser mayor de 300px y el archivo no debe superar 10MB.

A continuación se muestra un ejemplo de estructura de solicitud; reemplaza las URL de los recursos antes de realizar la llamada.

```json
{
  "contents": [
    {
      "type": "product_image",
      "url": "https://your-cdn.example/product.jpg"
    },
    {
      "type": "person_image",
      "url": "https://your-cdn.example/person.jpg"
    }
  ],
  "async": true
}
```

## Resultados y facturación

El modo síncrono devuelve el resultado generado; el modo asíncrono primero devuelve `task_id`, y el resultado completado incluye los enlaces de video o imagen en `data` y el `usage` calculado por el servidor. `callback_url` se utiliza para las notificaciones de finalización; una solicitud con `watermark=true` devuelve simultáneamente una versión con marca de agua.

1,12 Credits/imagen, facturados según el número real de imágenes de salida. Los videos se liquidan según la duración real generada; el precio base por segundo antes de la generación no representa el precio total de toda la tarea. Las tareas fallidas no incurren en cargos de generación.
