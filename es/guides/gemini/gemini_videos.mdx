Este documento presentará las instrucciones de integración de la API de generación de videos de Gemini, que puede generar videos de Google Gemini (omni-flash) a través de la entrada de texto de indicación (y una imagen de referencia opcional).

## Proceso de solicitud

Para utilizar la API de generación de videos de Gemini, primero dirígete a [la consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obtener tu token de API, que debes guardar para uso futuro.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si aún no has iniciado sesión o registrado, serás redirigido automáticamente a la página de inicio de sesión que te invitará a registrarte e iniciar sesión; una vez completado, serás devuelto automáticamente a la página actual.

**Un token de API es suficiente para acceder a todos los servicios de la plataforma, no es necesario solicitar uno por cada servicio.** La primera solicitud te otorgará un crédito gratuito para que puedas probarlo; si el crédito es insuficiente, puedes recargar el saldo general en [la consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [API de generación de videos de Gemini →](https://platform.acedata.cloud/documents/gemini-videos)

## Uso básico

Primero, comprende la forma básica de uso, ingresando la palabra clave `prompt`, el modelo `model` y la relación de aspecto `aspect_ratio`, lo que generará el video correspondiente.

Aquí podemos ver que hemos configurado los encabezados de la solicitud, que incluyen:

- `accept`: el formato de respuesta que deseas recibir, aquí se establece como `application/json`, es decir, formato JSON.
- `authorization`: la clave para llamar a la API, que puedes seleccionar directamente después de solicitarla.

Además, se ha configurado el cuerpo de la solicitud, que incluye:

- `prompt`: la palabra clave de texto que describe el contenido del video que deseas generar, **obligatorio**.
- `model`: el modelo para generar el video, actualmente solo se admite `omni-flash`, que es el valor predeterminado.
- `aspect_ratio`: la relación de aspecto del video generado, puede ser `16:9` (horizontal) o `9:16` (vertical), el valor predeterminado es `16:9`.
- `resolution`: la resolución de salida opcional, puede ser `720p` o `1080p`, el valor predeterminado es `720p`.
- `image_urls`: un array de enlaces de imágenes de referencia opcionales, que se utilizan para guiar la generación del video; los campos vacíos se ignorarán. Cuando se utiliza `video_urls` para la edición de video, este parámetro es obligatorio (al menos una imagen).
- `video_urls`: un array de enlaces de videos de referencia opcionales (máximo 1), para **edición de video / referencia de video**; si se proporciona, se debe proporcionar al menos una `image_urls`.
- `callback_url`: dirección de callback asíncrono, al configurarla, la API devolverá inmediatamente `task_id`, y cuando la tarea esté completa, enviará el resultado a esa dirección.
- `async`: opcional, si se establece en `true`, la interfaz devolverá inmediatamente `task_id`, sin necesidad de proporcionar `callback_url`, y luego se puede consultar el resultado a través de la interfaz de consulta de tareas correspondiente.

Haz clic en el botón "Try" para realizar una prueba, y el resultado obtenido será similar al siguiente:

```json
{
  "success": true,
  "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
  "data": [
    {
      "id": "omni-flash:job_01k777hjrbfrgs2060q5zvf2a5",
      "video_url": "https://cdn.acedata.cloud/gemini/example-video.mp4",
      "state": "succeeded"
    }
  ]
}
```

El resultado devuelto tiene varios campos, que se describen a continuación:

- `success`: si la solicitud de generación de video fue exitosa.
- `task_id`: el ID de la tarea de generación de video.
- `trace_id`: el ID de seguimiento de la solicitud, utilizado para resolver problemas.
- `data`: lista de resultados del video generado.
  - `id`: identificador único del video generado.
  - `video_url`: dirección del enlace del video generado.
  - `state`: estado de la tarea de generación de video, puede ser `pending` / `succeeded` / `failed`.

Solo necesitamos obtener el video generado a través de la dirección del enlace `video_url` en `data`.

El código CURL correspondiente es el siguiente:

```shell
curl -X POST 'https://api.acedata.cloud/gemini/videos' \
-H 'authorization: Bearer ${bearer_token}' \
-H 'accept: application/json' \
-H 'content-type: application/json' \
-d '{
  "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
  "model": "omni-flash",
  "aspect_ratio": "16:9"
}'
```

El código Python correspondiente es el siguiente:

```python
import requests

url = "https://api.acedata.cloud/gemini/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
    "model": "omni-flash",
    "aspect_ratio": "16:9"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Generación de video a partir de imágenes

Si deseas generar un video basado en imágenes de referencia, puedes pasar uno o más enlaces de imágenes en `image_urls`, que se utilizarán para guiar la generación del video:

```json
{
  "prompt": "The character slowly turns around and smiles at the camera",
  "model": "omni-flash",
  "aspect_ratio": "9:16",
  "image_urls": [
    "https://cdn.acedata.cloud/example-reference.png"
  ]
}
```

## Edición de video / Video de referencia

Se admite la edición directa de videos existentes o su referencia: pasa un enlace de video de referencia (máximo 1) en `video_urls`, y **simultáneamente** proporciona al menos una imagen de referencia en `image_urls` (requisito estricto). Puedes describir el efecto de edición deseado en `prompt` (cambiar estilo, cambiar escena, agregar o eliminar elementos, etc.):

```json
{
  "prompt": "Restyle the video into cinematic anime, keep the motion",
  "model": "omni-flash",
  "aspect_ratio": "16:9",
  "resolution": "720p",
  "image_urls": [
    "https://cdn.acedata.cloud/example-reference.png"
  ],
  "video_urls": [
    "https://cdn.acedata.cloud/example-source.mp4"
  ]
}
```

> Nota: máximo 1 video de referencia; y al proporcionar `video_urls`, se debe proporcionar al menos una `image_urls` (de lo contrario, se devolverá un error de parámetro).

## Callback asíncrono

La generación de video requiere un tiempo de procesamiento. Si no deseas mantener una conexión larga esperando, puedes pasar `callback_url`, en este caso, la API devolverá inmediatamente `task_id`, y cuando la tarea esté completa, enviará el resultado final a esa dirección:

```json
{
  "prompt": "A cinematic shot of a kitten chasing a butterfly in a sunlit garden",
  "model": "omni-flash",
  "aspect_ratio": "16:9",
  "callback_url": "https://your-domain.com/callback/gemini"
}
```

El resultado devuelto inmediatamente es el siguiente:

```json
{
  "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea"
}
```

## Consulta de resultados de tareas

Si utilizaste un callback asíncrono o deseas consultar el estado de la tarea de forma proactiva, puedes consultar el estado y los resultados más recientes de la tarea a través de [la API de tareas de Gemini](https://platform.acedata.cloud/documents/gemini-tasks) (`POST https://api.acedata.cloud/gemini/tasks`) según `task_id`.

## Manejo de errores

Cuando hay un problema con la solicitud, la API devolverá el código de error correspondiente y la descripción, siendo los más comunes los siguientes:
- `400`: Los parámetros de la solicitud son incorrectos, por ejemplo, falta `prompt` o el valor de `aspect_ratio` es inválido.
- `401`: Fallo de autenticación, el token es inválido o no coincide con la API.
- `403`: Saldo insuficiente, o la palabra clave ha sido rechazada por la revisión de contenido.
- `500`: Error interno del servidor o fallo en la generación upstream.
