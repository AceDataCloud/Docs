Google Gemini es un sistema de conversación de IA muy potente que puede generar respuestas fluidas y naturales en segundos mediante la introducción de indicaciones. Este documento describe principalmente cómo utilizar la API Gemini Generate Content, que es el formato de API nativo oficial de Google y admite los dos endpoints `generateContent` y `streamGenerateContent`.

## Diferencias con la API Chat Completions

La API Gemini Generate Content utiliza el formato de solicitud nativo oficial de Google (el campo `contents`), en lugar del formato compatible con OpenAI (el campo `messages`). Si ya utilizas el SDK de Google Gemini o estás familiarizado con el formato oficial de la API, puedes utilizar esta API directamente sin modificar el formato de la solicitud.

## Alcance de soporte actual

La interfaz acepta entradas de texto, imágenes, vídeo y audio (`inlineData` o `fileData`), configuración de razonamiento y declaraciones de funciones personalizadas. Los campos nativos como salida de audio, herramientas integradas y caché de contexto explícita aún no tienen una garantía de disponibilidad unificada; consulta el retorno real del modelo específico.

Al enviar archivos como audio mediante `fileData.fileUri`, asegúrate de que el archivo sea accesible directamente a través de HTTPS, no dependa de un estado de inicio de sesión y que el periodo de validez del enlace firmado cubra todo el tiempo de procesamiento de la solicitud. El análisis de audio no fluido solo devuelve resultados después de que el modelo termina de procesar, lo que puede superar los 90 segundos; el cliente debe establecer un tiempo de espera total suficientemente largo según el tamaño del archivo y el escenario de negocio, para evitar desconectar mientras el servidor aún está procesando.

## Proceso de solicitud

Antes de utilizar la API Gemini Generate Content, visita primero la página [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api) y haz clic en el botón "Obtener" para conseguir las credenciales necesarias para la solicitud.

Si aún no has iniciado sesión o no te has registrado, serás redirigido automáticamente a la página de inicio de sesión. La primera solicitud tendrá cuota gratuita.

## Uso básico

### Non-Streaming（no fluido）

Envía una solicitud POST a `/v1beta/models/{model}:generateContent`:

> **Nota**: la serie flash de `gemini-3.x` son modelos de razonamiento y primero consumirán reasoning tokens; establece `generationConfig.maxOutputTokens` en 512 o más, de lo contrario podría devolver solo contenido vacío.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Ejemplo de resultado devuelto:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [
          {
            "text": "你好！很高兴与你交流。"
          }
        ]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Los campos de token en `usageMetadata` se facturarán según la semántica nativa de Gemini:

- `promptTokenCount` incluye `cachedContentTokenCount`; la parte alcanzada por la caché se calcula según el precio de lectura de caché y no se vuelve a contar como entrada normal.
- `promptTokensDetails` y `cacheTokensDetails` se normalizarán como `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` y los detalles `cached_*` correspondientes bajo `usage.prompt_tokens_details`. Estos valores están incluidos respectivamente en `prompt_tokens` y `cached_tokens`; las distintas modalidades solo se recalculan según sus respectivos precios y no se facturan de forma duplicada.
- Tanto `candidatesTokenCount` como `thoughtsTokenCount` se calculan según el precio de los tokens de salida.
- `toolUsePromptTokenCount` son tokens de entrada de herramientas independientes y se calculan según el precio de los tokens de entrada.

Ace Data Cloud devuelve adicionalmente un objeto `usage` normalizado, y los costes de esta llamada se leen de manera unificada entre protocolos de modelos desde `usage.cost`. `cost` es una vista previa de coste opcional; cuando la vista previa de precios no está disponible temporalmente, la respuesta del modelo seguirá devolviéndose con normalidad, pero puede no incluir este campo. La factura final prevalecerá según los registros de uso.

### Streaming（flujo）

Envía una solicitud POST a `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

La respuesta en flujo devolverá gradualmente contenido en formato SSE (Server-Sent Events). Los eventos intermedios normalmente solo contienen contenido incremental; el evento final con uso autorizado incluirá `usageMetadata` y `usage` normalizado, y el coste seguirá estando en `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

El cierre de la conexión indica el final del flujo; el flujo nativo de Gemini no enviará `data: [DONE]`. Si la vista previa de precios final no está disponible temporalmente, `usage` seguirá devolviendo el uso de tokens, pero omitirá `cost`.

### Pensamiento interno y resumen del pensamiento

El pensamiento interno del modelo y la devolución de un resumen del pensamiento a quien realiza la llamada son dos configuraciones independientes:

- `thinkingBudget` o `thinkingLevel` controlan el presupuesto o la profundidad del pensamiento interno del modelo; los campos y valores admitidos dependen del modelo.
- `includeThoughts` controla si se devuelve el resumen del pensamiento; el valor predeterminado es `false`. Cuando se omite este campo o se pasa `false`, ni las respuestas JSON normales ni las respuestas en streaming SSE devolverán texto marcado como `thought: true`; estos textos solo se conservan cuando se pasa explícitamente el valor booleano `true`.

Cuando la solicitud no establece `includeThoughts`, la interfaz pasa por defecto `false` a los modelos de generación que admiten configuración de pensamiento, para evitar resúmenes que la solicitud no necesita; se conservarán los valores proporcionados explícitamente por el cliente, el presupuesto de pensamiento y el nivel. Al conocido `gemini-2.5-flash-image`, que no admite configuración de pensamiento, no se le añadirá automáticamente este campo, y tampoco se añadirá configuración de generación a las solicitudes de `countTokens`.

Desactivar el resumen no equivale a desactivar el pensamiento interno, ni garantiza reducir los tokens de pensamiento interno. Si la respuesta aún contiene texto de pensamiento no solicitado, las salidas JSON normales y SSE lo filtrarán adicionalmente, conservando la respuesta normal, las firmas y el uso real.

Cuando necesite ver el resumen, actívelo explícitamente de la siguiente manera. Cuando el modelo no genera un resumen utilizable, es posible que no haya texto de pensamiento incluso si está activado:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` es el estado cifrado necesario para turnos posteriores, no el texto del resumen del pensamiento, y tampoco está controlado por el interruptor `includeThoughts`. La firma puede ubicarse en una respuesta normal, una llamada de función o un Part de texto vacío; al filtrar texto de pensamiento, se conservarán la firma y los demás campos del mismo Part, por lo que la respuesta aún puede contener Part que solo lleva la firma y cuyo texto está vacío. Al mantener manualmente el historial de múltiples turnos, se debe conservar el orden de estos Part y la posición de las firmas; no mueva las firmas ni las fusione.

`usageMetadata` y `usage` siguen registrando el uso real. Ocultar el resumen no pone `thoughtsTokenCount` en cero; la facturación se sigue calculando según el uso real y las reglas de precios actuales.

Consulte la [explicación oficial de Google sobre pensamiento y resúmenes de pensamiento](https://firebase.google.com/docs/ai-logic/thinking) y las [reglas de firmas de pensamiento](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

### Llamada de funciones

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "北京现在的天气怎么样？"}]
    }
  ],
  "tools": [
    {
      "functionDeclarations": [
        {
          "name": "get_weather",
          "description": "获取指定城市的天气信息",
          "parameters": {
            "type": "object",
            "properties": {
              "city": {
                "type": "string",
                "description": "城市名称"
              }
            },
            "required": ["city"]
          }
        }
      ]
    }
  ]
}
```


## Configuración de seguridad

El filtrado de contenido se puede controlar mediante `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Manejo de errores

| Código de estado HTTP | Significado             |
| -------- | -------------- |
| 400      | Parámetros de solicitud no válidos         |
| 401      | Error de autenticación, verifique el Token |
| 403      | Contenido interceptado por el filtro de seguridad     |
| 429      | Solicitudes demasiado frecuentes         |
| 500      | Error interno del servidor        |
