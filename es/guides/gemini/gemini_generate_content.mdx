Google Gemini es un sistema de diálogo de IA muy potente que puede generar respuestas fluidas y naturales en segundos mediante la entrada de indicaciones. Este documento describe principalmente el método de uso de Gemini Generate Content API, que es el formato de API nativo oficial de Google y admite los dos endpoints `generateContent` y `streamGenerateContent`.

## Diferencias con Chat Completions API

Gemini Generate Content API utiliza el formato de solicitud nativo oficial de Google (el campo `contents`), en lugar del formato compatible con OpenAI (el campo `messages`). Si ya utilizas Google Gemini SDK o estás familiarizado con el formato oficial de API, puedes utilizar directamente esta API sin modificar el formato de solicitud.

## Alcance de soporte actual

La interfaz acepta entradas de texto, imágenes, vídeo y audio (`inlineData` o `fileData`), configuración de razonamiento y declaraciones de funciones personalizadas. Los campos nativos como salida de audio, herramientas integradas y caché de contexto explícita aún no tienen una garantía de disponibilidad unificada; consulta el retorno real del modelo específico.

Al enviar archivos como audio mediante `fileData.fileUri`, asegúrate de que el archivo pueda accederse directamente mediante HTTPS, que no dependa de un estado de inicio de sesión y que el período de validez del enlace firmado cubra todo el tiempo de procesamiento de la solicitud. El análisis de audio no streaming necesita devolver el resultado después de que el modelo complete el procesamiento, y puede superar los 90 segundos; el cliente debe establecer un tiempo de espera total suficientemente largo según el tamaño del archivo y el escenario de negocio, para evitar desconectarse mientras el servidor aún está procesando.

## Proceso de solicitud

Antes de utilizar Gemini Generate Content API, visita primero la página [Gemini Generate Content API](https://platform.acedata.cloud/documents/gemini-generate-content-api), y haz clic en el botón "Obtener" para obtener las credenciales necesarias para la solicitud.

Si aún no has iniciado sesión o te has registrado, serás redirigido automáticamente a la página de inicio de sesión. La primera solicitud tendrá cuota gratuita.

## Uso básico

### Non-Streaming (no streaming)

Envía una solicitud POST a `/v1beta/models/{model}:generateContent`:

> **Aviso**: la serie `gemini-3.x` flash es un modelo de razonamiento y primero consumirá reasoning tokens; establece `generationConfig.maxOutputTokens` en 512 o más, de lo contrario es posible que solo devuelva contenido vacío.

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-3.5-flash:generateContent" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "你好，请介绍一下你自己"
          }
        ]
      }
    ]
  }'
```

Ejemplo de resultado devuelto:

```json
{
  "candidates": [
    {
      "content": {
        "role": "model",
        "parts": [
          {
            "text": "你好！很高兴与你交流。"
          }
        ]
      },
      "finishReason": "MAX_TOKENS"
    }
  ],
  "usageMetadata": {
    "promptTokenCount": 6,
    "candidatesTokenCount": 19,
    "thoughtsTokenCount": 489,
    "totalTokenCount": 514
  },
  "usage": {
    "prompt_tokens": 6,
    "completion_tokens": 19,
    "total_tokens": 514,
    "thoughts_tokens": 489,
    "cost": {
      "amount": 0.008860916380159999,
      "currency": "credit",
      "list_amount": 0.009631430847999998
    }
  },
  "modelVersion": "gemini-3.5-flash",
  "model": "gemini-3.5-flash"
}
```

Los campos de token en `usageMetadata` se facturarán según la semántica nativa de Gemini:

- `promptTokenCount` incluye `cachedContentTokenCount`, y la parte alcanzada por la caché se calcula según el precio de lectura de caché, sin volver a contabilizarse como entrada normal.
- `promptTokensDetails` y `cacheTokensDetails` se normalizarán como los detalles `text_tokens`, `image_tokens`, `video_tokens`, `audio_tokens` y los correspondientes `cached_*` bajo `usage.prompt_tokens_details`. Estos valores están incluidos respectivamente en `prompt_tokens` y `cached_tokens`; las diferentes modalidades solo se recalculan según sus respectivos precios, sin facturación duplicada.
- `candidatesTokenCount` y `thoughtsTokenCount` se calculan ambos según el precio de los tokens de salida.
- `toolUsePromptTokenCount` es un token de entrada de herramienta independiente, calculado según el precio de los tokens de entrada.

Ace Data Cloud devuelve adicionalmente el objeto normalizado `usage`, y la tarifa de esta llamada se lee de forma unificada entre protocolos de modelos desde `usage.cost`. `cost` es una vista previa de tarifa opcional; cuando la vista previa de precios no está disponible temporalmente, la respuesta del modelo seguirá devolviéndose normalmente, pero podría no incluir este campo. La facturación final se basa en los registros de uso.

### Streaming (streaming)

Envía una solicitud POST a `/v1beta/models/{model}:streamGenerateContent?alt=sse`:

```bash
curl -X POST "https://api.acedata.cloud/v1beta/models/gemini-2.5-flash:streamGenerateContent?alt=sse" \
  -H "Authorization: Bearer your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "contents": [
      {
        "role": "user",
        "parts": [
          {
            "text": "写一首关于春天的诗"
          }
        ]
      }
    ]
  }'
```

La respuesta streaming devolverá contenido gradualmente en formato SSE (Server-Sent Events). Los eventos intermedios normalmente solo contienen contenido incremental; el evento final que contiene el uso autorizado incluirá `usageMetadata` y el `usage` normalizado, y la tarifa seguirá estando en `usage.cost`:

```text
data: {"candidates":[{"content":{"parts":[{"text":"Hello!"}],"role":"model"},"index":0}],"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

data: {"candidates":[{"content":{"parts":[],"role":"model"},"finishReason":"STOP","index":0}],"usageMetadata":{"promptTokenCount":7,"candidatesTokenCount":89,"totalTokenCount":96},"usage":{"prompt_tokens":7,"completion_tokens":89,"total_tokens":96,"cost":{"amount":0.00026161075472,"currency":"credit","list_amount":0.000284359516}},"modelVersion":"gemini-3.1-flash-lite","model":"gemini-3.1-flash-lite"}

```

El cierre de la conexión indica el final del flujo; el flujo nativo de Gemini no envía `data: [DONE]`. Si la vista previa de precio final no está disponible temporalmente, `usage` seguirá devolviendo el uso de tokens, pero omitirá `cost`.

| `gemini-3.1-flash-lite`  | Modelo ligero de versión estable                                   |
| `gemini-3.1-pro-preview` | Modelo de razonamiento complejo y codificación                                 |

| `gemini-3-pro-image`     | Modelo de generación de imágenes de alta calidad                                 |
| `gemini-2.5-flash-image` | Modelo de generación de imágenes Gemini 2.5                         |

`gemini-4-carbon` y `gemini-4-hydrogen` actualmente se pueden invocar mediante Chat Completions, y Generate Content nativo no está disponible temporalmente. Las especificaciones oficiales del modelo enumeran entradas de texto, imagen, video, audio y PDF, y salida de texto; esto no significa que la plataforma actual haya verificado todos los tipos de entrada. Después de que se restablezca la llamada nativa, envíe solicitudes según el contrato de interfaz de esta página y verifique por separado las entradas y parámetros necesarios. La salida de un millón de Tokens de long decode oficial no está incluida en el contrato de interfaz actual. Ambos solo admiten caché implícita, los Tokens de pensamiento se calculan según el precio de salida; las reglas de precios preparadas usan el mismo precio unitario de Token de entrada para cada modalidad de entrada, y los aciertos de caché se calculan según el precio unitario de lectura de caché; consulte la página de precios actual para más detalles.

```json
{
  "contents": [
    {

```

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "讲一个故事"}]
    }
  ],
  "generationConfig": {
    "temperature": 0.7,
    "maxOutputTokens": 1024,
    "topP": 0.9,
    "topK": 40
  }
}
```

```json

    {
      "role": "user",

        {
          "text": "列出三个中国城市及其人口"

```

### Pensamiento interno y resumen de pensamiento

El pensamiento interno del modelo y la devolución de un resumen de pensamiento al invocador son dos configuraciones independientes:

- `thinkingBudget` o `thinkingLevel` controlan el presupuesto o la profundidad del pensamiento interno del modelo; los campos y valores admitidos dependen del modelo.
- `includeThoughts` controla si se devuelve un resumen de pensamiento, y el valor predeterminado es `false`. Cuando se omite este campo o se pasa `false`, ni las respuestas JSON normales ni las respuestas en streaming SSE devolverán texto marcado como `thought: true`; estos textos solo se conservan cuando se pasa explícitamente el valor booleano `true`.

Cuando la solicitud no configura `includeThoughts`, la interfaz pasa de forma predeterminada `false` a los modelos de generación que admiten configuración de pensamiento, evitando resúmenes que la solicitud no necesita; se conservarán el valor pasado explícitamente por el cliente, el presupuesto de pensamiento y el nivel. Al conocido `gemini-2.5-flash-image`, que no admite configuración de pensamiento, no se le añadirá automáticamente este campo, y a las solicitudes `countTokens` tampoco se les añadirá configuración de generación.

Desactivar el resumen no equivale a desactivar el pensamiento interno, ni garantiza reducir los tokens de pensamiento interno. Si la respuesta aún contiene texto de pensamiento no solicitado, las salidas JSON normales y SSE lo filtrarán adicionalmente, conservando la respuesta normal, las firmas y el uso real.

Cuando necesite ver el resumen, actívelo explícitamente de la siguiente manera. Cuando el modelo no genere un resumen disponible, es posible que no haya texto de pensamiento incluso si está activado:

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "解释量子纠缠"}]
    }
  ],
  "generationConfig": {
    "thinkingConfig": {
      "includeThoughts": true
    }
  }
}
```

`thoughtSignature` es el estado cifrado necesario para los turnos posteriores, no es texto de resumen de pensamiento, y tampoco está controlado por el interruptor `includeThoughts`. La firma puede estar ubicada en una respuesta normal, una llamada de función o un Part de texto vacío; al filtrar el texto de pensamiento, se conservarán la firma y los demás campos del mismo Part, por lo que puede haber todavía en la respuesta Parts que solo contienen firmas y tienen texto vacío. Al mantener manualmente el historial de varios turnos, se deben conservar el orden de estos Parts y las posiciones de las firmas, no mueva las firmas ni las combine.

`usageMetadata` y `usage` siguen registrando el uso real. Ocultar el resumen no pondrá `thoughtsTokenCount` a cero; la facturación seguirá calculándose según el uso real y las reglas de precios actuales.

Consulte la [explicación oficial de Google sobre pensamiento y resúmenes de pensamiento](https://firebase.google.com/docs/ai-logic/thinking) y las [reglas de firmas de pensamiento](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/thinking/thought-signatures).

### Llamada de función

```json
{
  "contents": [
    {
      "role": "user",
      "parts": [{"text": "北京现在的天气怎么样？"}]
    }
  ],
  "tools": [
    {
      "functionDeclarations": [
        {
          "name": "get_weather",
          "description": "获取指定城市的天气信息",
          "parameters": {
            "type": "object",
            "properties": {
              "city": {
                "type": "string",
                "description": "城市名称"
              }
            },
            "required": ["city"]
          }
        }
      ]
    }
  ]
}
```

### Conversación de varios turnos

    },
    {

    },
    {
      "role": "user",
      "parts": [{"text": "我叫什么名字？"}]
    }
  ]
}
```

```

## Security settings

Content filtering can be controlled through `safetySettings`:

```json
{
  "contents": [...],
  "safetySettings": [
    {
      "category": "HARM_CATEGORY_HARASSMENT",
      "threshold": "BLOCK_ONLY_HIGH"
    }
  ]
}
```

## Error handling

| HTTP status code | Meaning             |
| -------- | -------------- |
| 400      | Invalid request parameters         |
| 401      | Authentication failed, please check the Token |
| 403      | Content blocked by the safety filter     |
| 429      | Requests are too frequent         |
| 500      | Internal server error        |
