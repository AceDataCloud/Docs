Google SERP (Search Engine Results Page) es la página de resultados que los usuarios ven después de ingresar una consulta en el motor de búsqueda de Google. Muestra resultados de búsqueda orgánicos, anuncios, fragmentos destacados, gráficos de conocimiento y diversos contenidos como imágenes y videos, con el objetivo de proporcionar a los usuarios la información más relevante.

Este artículo presentará en detalle Google SERP API, que puede proporcionar resultados al ingresar consultas en el motor de búsqueda de Google; el contenido de los resultados también incluye muchos tipos, como fragmentos destacados, gráficos de conocimiento e imágenes, entre muchos otros resultados.

Este documento presentará las instrucciones de integración de Google SERP API.

## Proceso de solicitud

Para usar Google SERP API, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo para uso posterior.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarlo a registrarse e iniciar sesión; al finalizar, regresará automáticamente a la página actual.

**Un API Token puede invocar todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluye créditos gratuitos, que pueden usarse para una experiencia gratuita; cuando los créditos sean insuficientes, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Google SERP API →](https://platform.acedata.cloud/documents/serp-google)

## Uso básico

Ingrese palabras clave y el tipo de recurso de búsqueda para obtener resultados: use `query` para transmitir las palabras clave y `type` para seleccionar tipos de búsqueda como páginas web, imágenes, noticias, etc.; esta interfaz no requiere transmitir `model`.

Por ejemplo, para buscar: información sobre “apple inc”, a continuación podemos completar el contenido correspondiente en la interfaz, como se muestra en la imagen:

<p><img src="https://cdn.acedata.cloud/lnqiye.png" width="500" className="m-auto" /></p>

Aquí podemos ver que configuramos los Request Headers, incluidos:

- `accept`: qué formato de respuesta se desea recibir; aquí se completa como `application/json`, es decir, formato JSON.
- `authorization`: la clave para invocar la API, que puede seleccionarse directamente en el menú desplegable después de solicitarla.

Además, configuramos el Request Body, incluido:

- `type`: el tipo de recurso de búsqueda; actualmente solo se admiten seis tipos, y el valor predeterminado es `search`.
- `query`: las palabras clave de búsqueda.
- `country`: el país donde se encuentran los resultados de búsqueda personalizados; el valor predeterminado es Estados Unidos (US).
- `language`: el idioma de los resultados de búsqueda personalizados; el valor predeterminado es inglés (en).
- `range`: el rango de tiempo de los resultados de búsqueda personalizados; el valor predeterminado es sin límite.
- `number`: el tamaño de página de la paginación de los resultados de búsqueda personalizados; el valor predeterminado es 10.
- `page`: el número de página de la paginación de los resultados de búsqueda personalizados; el valor predeterminado es 1.

Además, si desea generar el código de integración correspondiente, puede copiarlo y generarlo directamente; por ejemplo, el código CURL es el siguiente:

```shell
curl -X POST 'https://api.acedata.cloud/serp/google' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "query": "apple inc"
}'
```

El código de integración de Python es el siguiente:

```python
import requests

url = "https://api.acedata.cloud/serp/google"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "query": "apple inc"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Tipo de búsqueda personalizado

Si personaliza el tipo de recursos de búsqueda, podemos modificar el parámetro `type`, que incluye respectivamente recursos normales `search`, recursos de imágenes `images`, recursos de noticias `news`, recursos de mapas `maps`, recursos de regiones `places` y recursos de videos `videos`; este artículo utilizará los recursos de videos `videos` como demostración.

A continuación, demostraremos las operaciones específicas.

Primero, establezca el parámetro `type` en `videos` y pase el parámetro `query` normalmente, como se muestra en la imagen:
<p><img src="https://cdn.acedata.cloud/czlt12.png" width="500" className="m-auto" /></p>

El código correspondiente es el siguiente:

```shell
curl -X POST 'https://api.acedata.cloud/serp/google' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "type": "videos",
  "query": "apple inc"
}'
```

## Personalizar el intervalo de tiempo de los resultados de búsqueda
Este artículo también puede personalizar el intervalo de tiempo de los resultados de búsqueda, incluyendo cinco tipos: `qdr:h` (la última hora), `qdr:d` (el último día), `qdr:w` (la última semana), `qdr:m` (el último mes) y sin restricciones de forma predeterminada. Podemos pasar el intervalo de tiempo correspondiente mediante `range`; por ejemplo, aquí se establece como `qdr:d`, lo que indica la búsqueda de resultados del último día, por lo que la entrada es la siguiente:

<p><img src="https://cdn.acedata.cloud/qccfib.png" width="500" className="m-auto" /></p>

El código correspondiente es el siguiente:

```shell
curl -X POST 'https://api.acedata.cloud/serp/google' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "range": "qdr:d",
  "query": "apple inc"
}'
```

## Personalizar la paginación de los resultados de búsqueda
