Este artículo presentará unas instrucciones de integración de la API de generación de audios de Producer, que permite generar música oficial de Producer introduciendo parámetros personalizados.

## Proceso de solicitud

Para utilizar la API de generación de audios de Producer, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; al finalizar, regresará automáticamente a la página actual.

**Un API Token permite llamar a todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluirá créditos gratuitos para una experiencia sin costo; cuando los créditos sean insuficientes, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Seleccione los parámetros obligatorios según la operación

Cuando `action=generate` y `custom=false` (predeterminado), proporcione `prompt`; cuando `custom=true`
y `instrumental=false`, proporcione `lyric`. Para música instrumental personalizada, puede establecer
`custom=true, instrumental=true`, sin necesidad de inventar letras ni palabras clave adicionales.
`action=extend` requiere `audio_id` y un `continue_at` mayor que 0, y el modo no instrumental también requiere
`lyric`. Las versiones, variaciones, reemplazo de fragmentos, intercambio de partes y separación de pistas requieren el `audio_id` de origen;
las letras y las palabras clave no deben ser obligatorias incondicionalmente para todas las operaciones.

En MCP, `producer_extend_music` y `producer_replace_section` seleccionarán el modo de letras personalizadas al proporcionar
`lyric`; para continuar música instrumental, puede pasar `instrumental=true` y omitir las letras.

## Uso básico

Si quiere pensar en alguna canción, puede introducir cualquier texto, por ejemplo, si quiero generar una canción sobre Navidad, puedo introducir `a song for Christmas`, como se muestra en la imagen:

<p><img src="https://cdn.acedata.cloud/lg9bb0.png" width="600" className="m-auto" /></p>

Puede ver que aquí configuramos los Request Headers, incluyendo:

- `accept`: qué formato de resultado de respuesta desea recibir; aquí se completa con `application/json`, es decir, formato JSON.
- `authorization`: la clave para llamar a la API, que puede seleccionar directamente desde la lista desplegable después de solicitarla.

Además, los parámetros de Request Body incluyen:

- `action`: la acción de esta tarea de generación de música; para generar una canción es `generate`.
- `model`: el modelo utilizado para crear canciones; actualmente los principales son: **FUZZ-2.0 Pro**, **FUZZ-2.0**, **FUZZ-2.0 Raw**,**FUZZ-1.1 Pro**, **FUZZ-1.0 Pro**, **FUZZ-1.0**, **FUZZ-1.1**, **FUZZ-0.8**.
- `lyric`: el contenido de la letra de la canción.
- `custom`: si se utiliza un método personalizado para generar la canción.
- `prompt`: la palabra clave en el modo de inspiración.
- `title`: la información del título de la canción.
- `audio_id`: el ID de la canción de referencia, utilizado para operaciones como continuación/nueva versión.
- `continue_at`: continuar la canción desde el segundo especificado.
- `replace_section_start`/`replace_section_end`: la hora de inicio y finalización del fragmento de reemplazo, en segundos.
- `lyrics_strength`: la intensidad de las letras, que indica el grado de influencia de las letras en la generación de audio; opcional entre 0 y 1, con valor predeterminado de 0.7.
- `sound_strength`: la intensidad de las palabras clave de audio, opcional entre 0.2 y 1, con valor predeterminado de 0.7.
- `cover_strength`: la intensidad de la versión, entre 0.2 y 1, con valor predeterminado de 1.
- `weirdness`: el grado de singularidad del estilo, opcional entre 0 y 1, con valor predeterminado de 0.5
- `callback_url`: la URL que necesita recibir el resultado de la devolución de llamada.
- `async`: opcional; al establecerlo en `true`, la interfaz devuelve inmediatamente `task_id`, sin necesidad de proporcionar `callback_url`, y posteriormente obtiene el resultado mediante sondeo a través de la interfaz de consulta de tareas correspondiente.
- `instrumental`: si está en modo sin letras.

Además, si desea generar el código de integración correspondiente, puede copiarlo directamente para generarlo; por ejemplo, el código de CURL es el siguiente:

```shell
curl -X POST 'https://api.acedata.cloud/producer/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "FUZZ-2.0 Pro",
  "prompt": "A song for Christmas"
}'
```

## Versionar canciones

Si se desea realizar una operación de versionado sobre una canción ya generada, se puede introducir la canción generada anteriormente para versionarla; a continuación, vamos a generar una canción personalizada según la letra y el título.

Si se desea continuar versionando una canción subida por uno mismo, se puede establecer el parámetro `action` como `upload_cover` e introducir el ID de la canción subida de forma personalizada que se necesita continuar versionando. El ID de la canción se obtiene utilizando la [Producer Upload API](https://platform.acedata.cloud/documents/producer-upload), como se muestra en la siguiente imagen:

<p><img src="https://cdn.acedata.cloud/z7r5fd.png" width="500" className="m-auto" /></p>

Se puede especificar el siguiente contenido:

- action：el comportamiento de esta tarea de canción; actualmente admite: generate、cover、extend、upload_cover、upload_extend、replace_section、swap_vocals、swap_instrumentals、variation; para este versionado se utiliza el parámetro `cover`.
- lyric：texto de la letra
- title：el título de la canción.
- custom：si se utiliza el modo personalizado para generar; el valor predeterminado es false.
- audio_id：el ID de la canción que se necesita versionar.

## Continuar una canción

## Devolución de llamada asíncrona

Dado que el tiempo de generación de la API Producer Audios Generation a veces puede ser relativamente largo, si la API no responde durante mucho tiempo, la solicitud HTTP mantendrá la conexión continuamente, lo que provoca un consumo adicional de recursos del sistema, por lo que esta API también proporciona soporte para devoluciones de llamada asíncronas.

El flujo general es: cuando el cliente inicia una solicitud, especifica adicionalmente un campo `callback_url`; después de que el cliente inicia la solicitud a la API, la API devolverá inmediatamente un resultado que contiene información de un campo `task_id`, que representa el ID de la tarea actual. Cuando la tarea se completa, el resultado de la tarea de generación se enviará mediante POST JSON a la `callback_url` especificada por el cliente, que también incluye el campo `task_id`, de esta manera el resultado de la tarea puede asociarse mediante el ID.

A continuación, entendamos mediante un ejemplo cómo operar específicamente.

En primer lugar, la devolución de llamada Webhook es un servicio que puede recibir solicitudes HTTP, el desarrollador debe reemplazarla por la URL de su propio servidor HTTP configurado. Aquí, para facilitar la demostración, se utiliza un sitio web público de ejemplo de Webhook [https://webhook.site/](https://webhook.site/); al abrir este sitio web se puede obtener una URL de Webhook, como se muestra en la imagen:

![](https://cdn.acedata.cloud/tbcnai.png)

## Manejo de errores

Al llamar a la API, si se produce un error, la API devolverá el código de error y la información correspondientes. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`: No autorizado, token de autorización no válido o faltante.
- `429 too_many_requests`: Demasiadas solicitudes, ha superado el límite de frecuencia.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
