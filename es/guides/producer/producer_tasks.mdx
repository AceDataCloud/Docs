La función principal de Producer Tasks API es consultar el estado de ejecución de una tarea introduciendo el ID de la tarea generado por Producer Audios Generation API.

Este documento presentará en detalle las instrucciones de integración de Producer Tasks API, ayudándole a integrar fácilmente y aprovechar plenamente las potentes funciones de esta API. A través de Producer Tasks API, puede implementar fácilmente la consulta del estado de ejecución de las tareas de Producer Audios Generation API.

## Proceso de solicitud

Para utilizar Producer Audios Generation API, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo para usarlo posteriormente.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; al completarlo, volverá automáticamente a la página actual.

**Un API Token puede invocar todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluirá créditos gratuitos, que podrá utilizar para una experiencia gratuita; cuando los créditos sean insuficientes, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Producer Audios Generation API →](https://platform.acedata.cloud/documents/producer-audios)

## Ejemplo de solicitud

Producer Tasks API puede utilizarse para consultar los resultados de Producer Audios Generation API. Para saber cómo utilizar Producer Audios Generation API, consulte la documentación [Producer Audios Generation API ](https://platform.acedata.cloud/documents/producer-audios-integration).

Tomamos como ejemplo un ID de tarea devuelto por el servicio Producer Audios Generation API, para demostrar cómo utilizar esta API. Supongamos que tenemos un ID de tarea: 1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad; a continuación, se demostrará cómo mediante la introducción de un ID de tarea.

### Configurar encabezados y cuerpo de la solicitud

**Request Headers** incluyen:

- `accept`: especifica la recepción de resultados de respuesta en formato JSON; aquí se rellena como `application/json`.
- `authorization`: la clave para invocar la API, que puede seleccionarse directamente desde la lista desplegable después de solicitarla.

**Request Body** incluye:

- `id`: el ID de la tarea subida.
- `action`: el método de operación de la tarea.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

## Operación de consulta por lotes

Esto es para consultar los detalles de la tarea para múltiples ID de tarea. A diferencia de lo anterior, es necesario seleccionar `retrieve_batch` como action.

El **Request Body** incluye:

- `ids`: el array de ID de tareas subidas.
- `action`: el método de operación para las tareas.


## Manejo de errores

Al llamar a la API, si se encuentra un error, la API devolverá el código de error y la información correspondientes. Por ejemplo:

- `400 token_mismatched`：Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`：Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`：No autorizado, token de autorización no válido o faltante.
- `429 too_many_requests`：Demasiadas solicitudes, ha excedido el límite de frecuencia.
- `500 api_error`：Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
