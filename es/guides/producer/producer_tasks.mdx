La función principal de la API de Tareas del Productor es consultar el estado de ejecución de una tarea mediante el ID de tarea generado por la API de Generación de Audios del Productor.

Este documento detallará las instrucciones de integración de la API de Tareas del Productor, ayudándole a integrar y aprovechar al máximo las potentes funciones de esta API. A través de la API de Tareas del Productor, puede consultar fácilmente el estado de ejecución de las tareas de la API de Generación de Audios del Productor.

## Proceso de Solicitud

Para utilizar la API de Generación de Audios del Productor, primero debe obtener su Token de API en el [Consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guardarlo para su uso posterior.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si aún no ha iniciado sesión o registrado, será redirigido automáticamente a la página de inicio de sesión que le invita a registrarse e iniciar sesión, y una vez completado, regresará automáticamente a la página actual.

**Un Token de API es suficiente para acceder a todos los servicios de la plataforma, sin necesidad de solicitar uno por cada servicio.** La primera solicitud incluirá un crédito gratuito para que pueda experimentar sin costo; si se queda sin créditos, puede recargar el saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [API de Generación de Audios del Productor →](https://platform.acedata.cloud/documents/producer-audios)

## Ejemplo de Solicitud

La API de Tareas del Productor se puede utilizar para consultar los resultados de la API de Generación de Audios del Productor. Para saber cómo utilizar la API de Generación de Audios del Productor, consulte la documentación [API de Generación de Audios del Productor](https://platform.acedata.cloud/documents/producer-audios-integration).

### Configuración de Encabezados de Solicitud y Cuerpo de Solicitud

**Encabezados de Solicitud** incluyen:

- `accept`: especifica que se aceptan respuestas en formato JSON, aquí se debe llenar como `application/json`.
- `authorization`: la clave para llamar a la API, que puede seleccionarse directamente después de la solicitud.

**Cuerpo de Solicitud** incluye:

- `id`: el ID de tarea cargado.
- `action`: el método de operación sobre la tarea.

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/producer/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "1a6ac2ad-10f2-4e2b-b500-66ec27fe82ad",
  "action": "retrieve"
}'
```

El resultado devuelto tiene múltiples campos, el campo request es el cuerpo de la solicitud al iniciar la tarea, mientras que el campo response es el cuerpo de respuesta devuelto después de completar la tarea. La descripción de los campos es la siguiente.
- `id`，generar ID de tarea, utilizado para identificar de manera única esta tarea de generación.
- `request`，información de solicitud en la tarea de consulta.
- `response`，información de respuesta en la tarea de consulta.
- `created_at`，hora de creación de la tarea, marca de tiempo Unix (segundos, flotante).
- `started_at`，hora de inicio de ejecución de la tarea, marca de tiempo Unix (segundos, flotante).
- `finished_at`，hora de finalización de la tarea, marca de tiempo Unix (segundos, flotante). Este campo no se devuelve si la tarea no está completa.
- `elapsed`，tiempo de ejecución de la tarea, en segundos (flotante, con 3 decimales). Este campo no se devuelve si la tarea no está completa.

```bash
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \

}'
```

## Manejo de errores

Al llamar a la API, si se encuentra con un error, la API devolverá el código de error correspondiente y la información. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o inválidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o inválidos.
- `401 invalid_token`: No autorizado, token de autorización inválido o faltante.
- `429 too_many_requests`: Demasiadas solicitudes, ha superado el límite de tasa.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```json

  "success": false,
  "error": {

  },

}
```
