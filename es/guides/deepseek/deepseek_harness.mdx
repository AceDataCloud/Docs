[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) es un agente de programación que se ejecuta localmente. Lee el espacio de trabajo, llama a herramientas y ejecuta comandos, y luego invoca el modelo a través de la interfaz de Chat Completions compatible con OpenAI.

> Este documento es aplicable a `deepseek-harness-sdk==0.1.0rc6` y `deepseek-harness-runtime-bin==0.1.0rc6`. Después de actualizar el cliente, complete nuevamente la prueba de archivo de solo lectura a continuación.

## Alcance de Soporte

| Proyecto       | Configuración                             |
| -------------- | ---------------------------------------- |
| URL Base de API| `https://api.acedata.cloud/v1`         |
| Modelo         | `deepseek-v4-pro`                       |
| Protocolo      | Chat Completions compatible con OpenAI (streaming) |
| Capacidades    | Texto, proceso de razonamiento, llamadas a herramientas de funciones, bucle de herramientas Bash local, estadísticas de uso |

El directorio de modelos puede cambiar. Antes de ejecutar, consulte el directorio en tiempo real con la clave exclusiva del Plan de Codificación:

```bash
curl https://api.acedata.cloud/v1/models \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY"
```

Confirme que la respuesta incluya `deepseek-v4-pro`. No considere `deepseek-v4-flash` como un reemplazo equivalente para el modo de herramienta de este documento; en esta validación de versión fija, su historial de razonamiento de múltiples turnos y la reproducción de herramientas no pasaron.

## 1. Preparar la Clave Exclusiva

Abra [la aplicación del Plan de Codificación](https://platform.acedata.cloud/console/applications), acceda a la Aplicación de Codificación comprada, y cree o copie la clave API exclusiva de esa aplicación. El Plan de Codificación no utiliza saldo general, las claves de otras aplicaciones no pueden representar los permisos del paquete.

Coloque la clave solo en el shell actual:

```bash
export ACEDATACLOUD_API_KEY="PEGA_TU_CLAVE_DE_CODIFICACIÓN_AQUÍ"
export DEEPSEEK_BASE_URL="https://api.acedata.cloud/v1"
export DEEPSEEK_API_KEY="$ACEDATACLOUD_API_KEY"
```

No escriba la clave real en scripts, repositorios de configuración, capturas de pantalla de terminal o registros de sesión.

## 2. Crear un Espacio de Trabajo Aislado

El runtime empaquetado de Harness incluye herramientas Bash locales. En la primera validación, no apunte a proyectos reales o al directorio principal; cree un directorio desechable sin secretos:

```bash
mkdir -p /tmp/deepseek-harness-demo/workspace
mkdir -p /tmp/deepseek-harness-demo/sessions
printf 'compatibility fixture\n' > /tmp/deepseek-harness-demo/workspace/fixture.txt
python3 -m venv /tmp/deepseek-harness-demo/venv
/tmp/deepseek-harness-demo/venv/bin/pip install \
  "deepseek-harness-sdk==0.1.0rc6"
```

Si la red de la empresa utiliza un espejo privado de PyPI, confirme primero que el mismo versión de `deepseek-harness-runtime-bin` esté presente en el espejo. No use `danger-full-access` para ampliar el alcance de acceso a archivos; el ejemplo de este documento solo pasa el directorio desechable a `cwd`.

## 3. Ejecutar el SDK de Python Oficial

Guarde el siguiente contenido como `/tmp/deepseek-harness-demo/run.py`:

```python
import os

from deepseek_harness import DeepSeekHarness

with DeepSeekHarness(
    provider="deepseek-official",
    model="deepseek-v4-pro",
    max_tokens=160,
    cwd="/tmp/deepseek-harness-demo/workspace",
    session_root="/tmp/deepseek-harness-demo/sessions",
    base_url=os.environ["DEEPSEEK_BASE_URL"],
    api_key=os.environ["DEEPSEEK_API_KEY"],
    request_timeout_seconds=180,
) as harness:
    result = harness.run(
        "Read fixture.txt once, then reply with exactly: sdk-harness-ok",
        session_id="acedatacloud-compat",
    )

print(result.final_response)
print(result.finish_reason)
```

Ejecutar:

```bash
/tmp/deepseek-harness-demo/venv/bin/python \
  /tmp/deepseek-harness-demo/run.py
```

Resultado esperado:

```text
sdk-harness-ok
completed
```

Este paso valida simultáneamente la autenticación Bearer, `/v1/chat/completions`, SSE, contenido de razonamiento, llamadas a herramientas y la devolución de resultados de herramientas. Después de completar, puede eliminar `/tmp/deepseek-harness-demo`; si el directorio de sesión contiene contexto del proyecto, también debe ser almacenado con el mismo nivel de sensibilidad que el repositorio de código.

## Preguntas Frecuentes

- **401**: Verifique si `ACEDATACLOUD_API_KEY` está exportado al mismo shell que ejecuta Python.
- **403 o aviso de cuota**: Confirme que la clave pertenece a la Aplicación de Codificación actual, que el paquete sigue siendo válido y que hay saldo restante.
- **Modelo no disponible**: Vuelva a consultar `/v1/models`, no adivine el nombre del modelo basándose en capturas de pantalla antiguas.
- **Error en `reasoning_content` / reproducción de herramientas**: Confirme que tanto el SDK como el runtime son la versión fija de este documento y que está utilizando `deepseek-v4-pro`.
- **Número de ejecuciones de herramientas anómalo**: Detenga la ejecución de tareas que puedan tener efectos secundarios, primero valide la versión actual del servicio con el fixture de solo lectura de este documento.
- **Instalación fallida**: Confirme que Python 3.10+, la arquitectura del sistema operativo son compatibles con el wheel actual, y verifique que las versiones del SDK/runtime sean consistentes.

## Límites de Capacidades

Este documento solo valida el SDK de Python local hasta las Chat Completions en texto y bucles de herramientas. Imágenes, API de Archivos, `/v1/responses`, `/v1/messages`, espacios de trabajo remotos y sandbox alojados no están dentro del alcance prometido de este tutorial; los permisos del espacio de trabajo y los riesgos de comandos locales son responsabilidad de la máquina y la configuración que ejecuta Harness.
