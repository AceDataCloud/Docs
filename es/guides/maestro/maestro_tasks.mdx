La función principal de la API de consulta de tareas de Maestro es consultar el estado de ejecución y el resultado final de una tarea a través del ID de tarea devuelto por la [API de generación de videos de Maestro](development_maestro_videos.md) (`POST /maestro/videos`).

Este documento presentará en detalle las instrucciones de integración de la API de consulta de tareas de Maestro. Dado que la generación de video es una tarea asíncrona, después de enviarla es necesario usar esta API para consultar periódicamente el progreso y el video final, **la consulta periódica es gratuita y no consume créditos.**

`POST https://api.acedata.cloud/maestro/tasks`

## Proceso de solicitud

Para usar la API de consulta de tareas de Maestro, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; al completarlo, volverá automáticamente a la página actual.

**Un solo API Token puede llamar a todos los servicios de la plataforma, no es necesario solicitar uno por separado para cada servicio.** La primera solicitud incluirá créditos gratuitos para una experiencia sin costo; cuando los créditos sean insuficientes, puede recargar el saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [API de consulta de tareas de Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Consultar una sola tarea

Para saber cómo crear una tarea de video, consulte la documentación de la [API de generación de videos de Maestro](development_maestro_videos.md). Tomaremos como ejemplo uno de los ID de tarea que devuelve: `f57e99c4f60f4373a15517742ce2357d`, para demostrar cómo consultar su estado y resultado.

### Configurar encabezados y cuerpo de la solicitud

Los **Request Headers** incluyen:

- `accept`: especifica que se recibirá un resultado de respuesta en formato JSON; aquí se completa con `application/json`.
- `authorization`: la clave para llamar a la API; después de solicitarla puede seleccionarse directamente en la lista desplegable.
- `content-type`: el formato del cuerpo de la solicitud; aquí se completa con `application/json`.

El **Request Body** incluye:

| Campo       | Tipo     | Obligatorio al consultar una sola tarea | Descripción                                                |
| -------- | ------ | --------- | ------------------------------------------------- |
| `id`     | string | Obligatorio al consultar una sola tarea | El `task_id` devuelto por `POST /maestro/videos`              |
| `action` | string | No         | `retrieve` (predeterminado, consulta una sola tarea); al consultar una lista de historial se fija en `retrieve_batch` |

### Ejemplo de código

El código CURL correspondiente es el siguiente:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

El código Python correspondiente es el siguiente:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Ejemplo de respuesta

Después de que la solicitud tenga éxito, la API devolverá el estado y el resultado de esta tarea de video. El ejemplo de respuesta cuando la tarea está completada es el siguiente (cada idioma corresponde a un `variant`):

```json
    "langs": [
      "zh-cn",
      "en"
    ],
    "aspect": "9:16",

          "pct": 60,
          "t": 1750000000
        }
      ]
    }

```

La introducción de los campos del resultado devuelto es la siguiente:

- `id`: el ID de esta tarea de video, utilizado para identificar de forma única esta tarea de generación de video.
- `status`: estado de la tarea; los valores son `pending → planning → producing → succeeded` (o `failed`). Para determinar si la tarea se ha completado, prevalece este `status` de nivel superior.
- `elapsed`: tiempo transcurrido de la tarea (segundos).
- `progress`: objeto de progreso de nivel superior; `percent` (0–100) se establecerá en 100 como valor de respaldo después de que la tarea tenga éxito; `stage` y `message` reflejan el evento de progreso más reciente del director de IA (por lo tanto, después de tener éxito, `stage` puede seguir siendo la última etapa de ejecución, como `producing`), y puede utilizarse directamente para mostrar la barra de progreso.
- `request`: el cuerpo de la solicitud al iniciar la tarea.
- `response`: la información de respuesta de la tarea.
  - `success`: si la tarea tuvo éxito.
  - `data.variants`: cada idioma corresponde a un objeto de video final, que incluye `lang`, `aspect`, `title`, `output_url` (dirección de descarga del video final), etc.
  - `data.project`: los resultados de todo el proyecto, que incluyen `tarball_url` (paquete del proyecto) y `outputs` (todos los enlaces de los videos finales).
  - `data.progress`: un arreglo de eventos de progreso añadidos por etapa (registro de solo anexión), que puede utilizarse para mostrar el progreso detallado en tiempo real.
- `created_at`: hora de creación de la tarea, marca de tiempo Unix (segundos).
- `started_at`: hora en que la tarea comenzó a ejecutarse, marca de tiempo Unix (segundos). Es null cuando la tarea aún no ha comenzado.
- `finished_at`: hora de finalización de la tarea, marca de tiempo Unix (segundos). Es null cuando la tarea no se ha completado.

## Consultar la lista de historial

Al pasar `action: retrieve_batch`, puede obtener las tareas recientes del ejecutor actualmente autenticado (en orden descendente por hora de creación), lo que puede usarse para la página de lista «Mis videos». La lista de historial está aislada según la identidad de inicio de sesión.

El **Request Body** incluye:
| Campo               | Tipo     | Obligatorio  | Descripción                              |
| ---------------- | ------ | --- | ------------------------------- |
| `action`         | string | Sí   | Fijo como `retrieve_batch`            |
| `limit`          | int    | No   | Número de resultados devueltos, el valor predeterminado es 20; el rango válido es 1–100          |
| `created_at_max` | int    | No   | Solo devuelve tareas estrictamente anteriores a esta marca de tiempo Unix (sin incluir el valor límite, para paginación) |
| `created_at_min` | int    | No   | Solo devuelve tareas estrictamente posteriores a esta marca de tiempo Unix (sin incluir el valor límite)     |

### Ejemplo de código

El código CURL correspondiente es el siguiente:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### Ejemplo de respuesta

Después de que la solicitud tenga éxito, la API devolverá la lista de tareas históricas del usuario actual:

La descripción de los campos del resultado devuelto es la siguiente:

- `count`: El número total de tareas visibles para el ejecutor actualmente conectado, no afectado por las condiciones de tiempo ni por `limit`.
- `items`: El arreglo de tareas filtrado por las condiciones de tiempo y `limit`, ordenado en orden descendente por hora de creación; el formato de cada elemento es coherente con el resultado devuelto de «consultar una sola tarea».

## Recomendaciones de sondeo

Dado que la producción de video tarda bastante tiempo, `status` pasará por `pending → planning → producing → succeeded` (o `failed`). Se recomienda sondear una vez cada 5–10 segundos, hasta que `status` cambie a `succeeded` o `failed`. Puede utilizar `progress.percent` de nivel superior para mostrar una barra de progreso en tiempo real. **El sondeo de esta interfaz es gratuito y no consume créditos.**

## Manejo de errores

Al llamar a la API, si encuentra un error, la API devolverá el código y la información de error correspondientes. Por ejemplo:

- `401 invalid_token`: No autorizado, token de autorización no válido o ausente.
- `404 not_found`: Tarea no encontrada, el task_id proporcionado no existe.
- `429 too_many_requests`: Demasiadas solicitudes, ha excedido el límite de frecuencia.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
