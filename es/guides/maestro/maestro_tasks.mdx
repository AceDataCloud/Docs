La principal función de la API de consulta de tareas de Maestro es consultar el estado de ejecución y el resultado final de una tarea a través del ID de tarea devuelto por la [API de generación de videos de Maestro](development_maestro_videos.md) (`POST /maestro/videos`).

Este documento detallará la descripción de la integración de la API de consulta de tareas de Maestro. Dado que la generación de videos es una tarea asíncrona, después de enviarla, se necesita utilizar esta interfaz para sondear el progreso y el producto final, **el sondeo es gratuito y no consume puntos.**

`POST https://api.acedata.cloud/maestro/tasks`

## Proceso de solicitud

Para utilizar la API de consulta de tareas de Maestro, primero dirígete a la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obtener tu token de API, que debes guardar como respaldo.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si aún no has iniciado sesión o registrado, serás redirigido automáticamente a la página de inicio de sesión que te invitará a registrarte e iniciar sesión; una vez completado, serás redirigido automáticamente a la página actual.

**Un token de API es suficiente para acceder a todos los servicios de la plataforma, no es necesario solicitar uno por cada servicio.** La primera solicitud incluirá un crédito gratuito para que puedas probarlo; si el crédito es insuficiente, puedes recargar el saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [API de consulta de tareas de Maestro →](https://platform.acedata.cloud/documents/maestro-tasks)

## Consultar una sola tarea

Para saber cómo crear una tarea de video, consulta el documento [API de generación de videos de Maestro](development_maestro_videos.md). Usaremos un ID de tarea devuelto como ejemplo: `f57e99c4f60f4373a15517742ce2357d`, para demostrar cómo consultar su estado y resultado.

### Configurar encabezados de solicitud y cuerpo de solicitud

**Request Headers** incluye:

- `accept`: especifica que se aceptan respuestas en formato JSON, aquí se debe llenar como `application/json`.
- `authorization`: la clave para llamar a la API, que puedes seleccionar directamente después de solicitarla.
- `content-type`: el formato del cuerpo de la solicitud, aquí se debe llenar como `application/json`.

**Request Body** incluye:

| Campo       | Tipo     | Obligatorio | Descripción                                           |
| ----------- | -------- | ----------- | ---------------------------------------------------- |
| `id`       | string   | Sí          | `task_id` devuelto por `POST /maestro/videos`       |
| `action`   | string   | No          | `retrieve` (por defecto, consulta una sola tarea) / `retrieve_batch` (consulta la lista de tareas históricas) |

### Ejemplo de código

El código CURL correspondiente es el siguiente:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "action": "retrieve"
}'
```

El código Python correspondiente es el siguiente:

```python
import requests

url = "https://api.acedata.cloud/maestro/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "f57e99c4f60f4373a15517742ce2357d",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

### Ejemplo de respuesta

Después de una solicitud exitosa, la API devolverá el estado y el resultado de la tarea de video. Un ejemplo de respuesta cuando la tarea se completa es el siguiente (cada idioma corresponde a un `variant`):

```json
{
  "id": "f57e99c4f60f4373a15517742ce2357d",
  "status": "succeeded",
  "elapsed": 312,
  "progress": { "percent": 100, "stage": "producing", "message": "rendering scene 2" },
  "request": {
    "prompt": "Explicar en 20 segundos qué es una base de datos vectorial, adecuada para una audiencia sin conocimientos previos, y terminar con un punto de memoria",
    "langs": ["zh-cn", "en"],
    "aspect": "9:16",
    "duration": 20
  },
  "response": {
    "success": true,
    "data": {
      "variants": [
        { "lang": "zh-cn", "aspect": "9:16", "kind": "video", "title": "什么是向量数据库", "output_url": "https://…/zh.mp4" },
        { "lang": "en", "aspect": "9:16", "kind": "video", "title": "What is a vector database", "output_url": "https://…/en.mp4" }
      ],
      "project": { "tarball_url": "https://…/project.tar.gz", "outputs": ["https://…/zh.mp4", "https://…/en.mp4"] },
      "percent": 100,
      "stage": "producing",
      "progress": [ { "stage": "producing", "message": "rendering scene 2", "pct": 60, "t": 1750000000 } ]
    }
  }
}
```

La descripción de los campos de la respuesta es la siguiente:

- `id`: el ID de esta tarea de video, utilizado para identificar de manera única esta tarea de generación de video.
- `status`: estado de la tarea, con valores `pending → planning → producing → succeeded` (o `failed`). Si la tarea se ha completado, se debe considerar el `status` de nivel superior.
- `elapsed`: tiempo transcurrido de la tarea (en segundos).
- `progress`: objeto de progreso de nivel superior, `percent` (0–100) se establecerá en 100 después de que la tarea tenga éxito; `stage` y `message` reflejan el evento de progreso más reciente del director AI (por lo tanto, después de que tenga éxito, `stage` puede seguir siendo la última etapa ejecutada como `producing`), que se puede utilizar directamente para mostrar una barra de progreso.
- `request`: cuerpo de la solicitud al iniciar la tarea.
- `response`: información devuelta de la tarea.
  - `success`: indica si la tarea fue exitosa.
  - `data.variants`: cada idioma corresponde a un objeto de producto final, que incluye `lang`, `aspect`, `title`, `output_url` (dirección de descarga del producto final), etc.
  - `data.project`: el producto completo del proyecto, que incluye `tarball_url` (paquete del proyecto) y `outputs` (todos los enlaces de productos finales).
  - `data.progress`: un array de eventos de progreso acumulados por etapas (registro de solo adición), que se puede utilizar para mostrar un progreso detallado en tiempo real.

## Consultar lista histórica

Al pasar `action: retrieve_batch`, se puede obtener la lista de tareas recientes del usuario actual (ordenadas por fecha de creación en orden descendente), que se puede utilizar para la página de "Mis videos".

**Request Body** incluye:

| Campo               | Tipo     | Obligatorio | Descripción                      |
| ------------------- | -------- | ----------- | -------------------------------- |
| `action`            | string   | Sí          | Fijo como `retrieve_batch`      |
| `limit`             | int      | No          | Número de resultados, por defecto 20 |
| `created_at_max`    | int      | No          | Solo devuelve tareas anteriores a esta marca de tiempo Unix (para paginación) |
| `created_at_min`    | int      | No          | Solo devuelve tareas posteriores a esta marca de tiempo Unix |

### Ejemplo de código

El código CURL correspondiente es el siguiente:

```bash
curl -X POST 'https://api.acedata.cloud/maestro/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "retrieve_batch",
  "limit": 20
}'
```

### Ejemplo de respuesta

Después de una solicitud exitosa, la API devolverá la lista de tareas históricas del usuario actual:
```json
{
  "count": 2,
  "items": [
    {
      "id": "f57e99c4f60f4373a15517742ce2357d",
      "status": "succeeded",
      "progress": { "percent": 100, "stage": "producing", "message": "renderizando la escena 2" },
      "request": { "prompt": "…", "langs": ["zh-cn", "en"], "aspect": "9:16", "duration": 20 },
      "response": { "success": true, "data": { "variants": [ { "lang": "zh-cn", "output_url": "https://…/zh.mp4" } ] } }
    }
  ]
}
```

Los campos de la respuesta se describen a continuación:

- `count`: El número total de tareas del usuario actual.
- `items`: Array de tareas, cada elemento tiene el mismo formato que el resultado de "consultar una sola tarea".

## Sugerencias de sondeo

Dado que la producción de video lleva tiempo, el `status` pasará por `pending → planning → producing → succeeded` (o `failed`). Se recomienda sondear cada 5-10 segundos, hasta que el `status` cambie a `succeeded` o `failed`. Se puede utilizar el `progress.percent` superior para mostrar una barra de progreso en tiempo real. **El sondeo de esta interfaz es gratuito y no consume puntos.**

## Manejo de errores

Al llamar a la API, si se encuentra un error, la API devolverá el código de error y la información correspondiente. Por ejemplo:

- `401 invalid_token`: No autorizado, token de autorización inválido o faltante.
- `404 not_found`: Tarea no encontrada, el task_id dado no existe.
- `429 too_many_requests`: Demasiadas solicitudes, ha superado el límite de tasa.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```json
{
  "success": false,
  "error": {
    "code": "api_error",
    "message": "la recuperación falló"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
