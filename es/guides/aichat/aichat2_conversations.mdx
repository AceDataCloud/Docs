La API AI Chat v2 (`/aichat2/conversations`) es una interfaz de conversación de nueva generación y una versión completamente mejorada de [AI Chat API](https://platform.acedata.cloud/documents/aichat-conversations). Sobre la base de la simplicidad y la gestión de conversaciones multivuelta de v1, amplía:

- **Entrada de usuario multimodal**: mediante el campo estructurado `message`, envía directamente bloques de texto + imágenes + archivos, sin necesidad de adjuntarlos indirectamente primero con `references`.
- **Llamada de herramientas tipo Agent**: integra un conjunto de herramientas como búsqueda en Internet, extracción de páginas web, lectura de archivos, etc., y permite montar servidores MCP autorizados por el usuario (Google Drive, Notion, Slack, GitHub, etc.). El modelo puede llamar autónomamente a herramientas en múltiples rondas dentro de una única solicitud para completar tareas complejas.
- **Eventos de streaming estructurados**: mediante `accept: text/event-stream` o `application/x-ndjson`, se pueden obtener eventos como `text_delta`, `tool_use`, `tool_result`, `thinking`, `citation`, `card`, `artifact`, etc., token por token, lo que facilita renderizar por separado en el frontend según el tipo correspondiente.
- **Interrumpible / reanudable**: cuando el modelo necesita que el usuario complemente información, emitirá un evento `ask_user_question` y se pausará; en la siguiente llamada, basta con rellenar la respuesta mediante `tool_results` para continuar.
- **Nuevas acciones CRUD**: completa `retrieve` / `retrieve_batch` / `update` / `delete` mediante el campo `action` en el mismo endpoint, sin necesidad de una API de gestión de conversaciones adicional.
- **Lista de modelos actualizada continuamente**: incluye por defecto modelos contemporáneos como GPT-5.4, Claude Opus 4.8, Claude Sonnet 4.6, Gemini 3.1 Pro, GLM 5.1, DeepSeek V4, Kimi K3, etc.

Al mismo tiempo, es **completamente compatible hacia atrás con v1** a nivel del cuerpo de la solicitud: al enviar únicamente `model` + `question` (+ opcionalmente `stateful` / `id` / `references` / `preset`), se puede obtener una respuesta JSON `{answer, id}` equivalente a la de v1. Por lo tanto, no es necesario reescribir el cliente al migrar desde `/aichat/conversations`; solo se debe cambiar la ruta a `/aichat2/conversations`.

> Si actualmente utiliza `/aichat/conversations`, la interfaz antigua seguirá estando disponible, y puede migrar a su propio ritmo.

## Proceso de solicitud

Para utilizar la API AI Chat v2, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; al completarlo, regresará automáticamente a la página actual.

**Un solo API Token permite llamar a todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluye crédito gratuito para probarlo sin coste; cuando el crédito sea insuficiente, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [AI Chat v2 API →](https://platform.acedata.cloud/documents/aichat2-conversations)

## Uso básico

El uso más sencillo es completamente igual al de v1: envíe `model` + `question` y reciba `{answer, id}`.

Ejemplo de CURL:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "question": "用一句话介绍下 AceDataCloud。"
  }'
```

Resultado devuelto:

```json
{
  "answer": "AceDataCloud 是一个聚合主流 AI 模型与多模态服务的统一 API 平台，开发者通过一个密钥即可调用 GPT、Claude、Gemini、Midjourney、Suno、Veo 等多家服务。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Ejemplo de Python:

```python
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
```

## Conversaciones multivuelta

Al igual que en v1, envíe `stateful: true` para habilitar el guardado de la conversación; la API devolverá un `id`; en solicitudes posteriores, incluya nuevamente el `id` para continuar la conversación, sin necesidad de mantener usted mismo el historial de messages.

Primera solicitud:

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "question": "记住一个数字：42。"
  }'
```

Devuelve:

```json
{
  "answer": "好的，我已经记住了 42。需要我用它做什么吗？",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Segunda solicitud, incluya el mismo `id`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "question": "我刚才让你记住的数字是多少？"
  }'
```

```json
{
  "answer": "你让我记住的数字是 42。",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

> `stateful` es `true` de forma predeterminada; omitirlo es equivalente a pasar explícitamente `true`. Establecer `stateful: false` omitirá la carga del historial de conversaciones anterior; esto no significa que el resultado de esta ronda no se guarde, y tampoco se aplica a los flujos de herramientas que necesitan continuar después de una pausa.

### Conversaciones largas y conservación del texto original

La compresión de contexto solo organiza el contenido enviado al modelo en esta ronda, y no reemplaza los registros de chat ya guardados. Aún se pueden leer los mensajes completos guardados mediante `action: retrieve`; la edición o eliminación explícita de conversaciones sigue teniendo efecto según la solicitud.

El modelo puede buscar y leer por páginas el texto original del historial dentro de la conversación actual. Cuando sea necesario continuar modificando un artículo, citar cifras o preparar una publicación, se debe leer el texto original correspondiente y no se puede usar un resumen en lugar del cuerpo del texto. Esta capacidad no restaura automáticamente los mensajes que ya se perdieron en versiones anteriores.

Si falla la organización del contexto, conserve el ID de la conversación y revise el evento `error`; el servicio no sobrescribirá el texto original con un resumen vacío. Las operaciones de herramientas completadas antes del fallo podrían seguir siendo válidas; primero consulte sus resultados para evitar la generación o publicación duplicada. Cuando una sola conversación alcance el límite de almacenamiento, se informará claramente de un error; los registros ya guardados no liberarán espacio mediante recortes; puede exportar el contenido necesario y luego iniciar una nueva conversación.

## Respuesta en streaming

v2 admite dos formatos de streaming, seleccionados según la cabecera `accept`:

| Escenario                    | `accept`               | Forma de los datos                                       |
| --------------------- | ---------------------- | ------------------------------------------ |
| Frontend web / EventSource  | `text/event-stream`    | `data: {json}\n\n`, la última línea es `data: [DONE]\n\n` |
| Servidor / CLI / análisis de streaming de Node | `application/x-ndjson` | Un objeto JSON por línea                               |
| No se necesita streaming                 | `application/json`（predeterminado） | Devuelve `{answer, id}` de una sola vez                       |

### Ejemplo de NDJSON

```python
import json
import requests

url = "https://api.acedata.cloud/aichat2/conversations"

headers = {
    "accept": "application/x-ndjson",
    "authorization": "Bearer {token}",
    "content-type": "application/json",
}

payload = {
    "model": "gpt-5.4",
    "stateful": True,
    "question": "用三句话介绍杭州。",
}

with requests.post(url, json=payload, headers=headers, stream=True) as resp:
    answer = ""
    for line in resp.iter_lines():
        if not line:
            continue
        event = json.loads(line)
        if event.get("type") == "text_delta":
            # 与 v1 兼容：增量片段同时通过 delta_answer 字段提供
            answer += event["content"]
            print(event["delta_answer"], end="", flush=True)
        elif event.get("type") == "done":
            print()
            print("usage =", event.get("usage"))
```

Cada línea de NDJSON es un evento estructurado; el más común es `text_delta`:

```json
{"type":"text_delta","content":"杭","delta_answer":"杭","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"州","delta_answer":"州","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"是","delta_answer":"是","id":"f2f4b3e8-..."}
...
{"type":"done","conversation_id":"f2f4b3e8-...","usage":{"prompt_tokens":21,"completion_tokens":58,"total_tokens":79},"terminal_reason":"natural_stop"}
```

### Ejemplo de SSE

El uso de `EventSource` en el navegador no admite cuerpos de solicitud personalizados; se recomienda usar `fetch` + análisis manual por segmentos de `\n\n`:

```javascript
const resp = await fetch("https://api.acedata.cloud/aichat2/conversations", {
  method: "POST",
  headers: {
    accept: "text/event-stream",
    authorization: "Bearer {token}",
    "content-type": "application/json",
  },
  body: JSON.stringify({
    model: "gpt-5.4",
    stateful: true,
    question: "用三句话介绍杭州。",
  }),
});

const reader = resp.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buffer += decoder.decode(value, { stream: true });
  const blocks = buffer.split("\n\n");
  buffer = blocks.pop() ?? "";
  for (const block of blocks) {
    const dataLine = block.split("\n").find((l) => l.startsWith("data: "));
    if (!dataLine) continue;
    const payload = dataLine.slice(6);
    if (payload === "[DONE]") return;
    const event = JSON.parse(payload);
    if (event.type === "text_delta") process.stdout.write(event.content);
  }
}
```

### Tipos de eventos de streaming

| `type`              | Significado                                                                                                                    |
| ------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `text_delta`        | Fragmento de texto incremental de la respuesta del asistente. `content` es el contenido nuevo; para compatibilidad con v1, el mismo evento también incluye `delta_answer` (igual a `content`) e `id`.                                        |
| `thinking`          | Proceso de razonamiento del modelo (solo aparece cuando el modelo seleccionado expone reasoning).                                                                                      |
| `tool_use`          | El modelo decide llamar a una herramienta; el evento incluye `tool_id`, `tool_name`, `input`.                                                                        |
| `tool_result`       | Resultado de la ejecución de la herramienta, emparejado con el `tool_use` anterior mediante `tool_id`; `is_error` indica si falló.                                                             |
| `card`              | Tarjeta estructurada producida por la herramienta (como imágenes o vistas previas de enlaces), adecuada para renderizar directamente.                                                                                          |
| `citation`          | URL de la fuente utilizada para complementar la cita del fragmento de texto correspondiente.                                                                                                  |
| `ask_user_question` | Se emite cuando el modelo necesita que el usuario proporcione información adicional; la conversación entra en el estado `awaiting_user_input`; consulte [reanudar una conversación pausada](#恢复暂停的对话) a continuación.                                                 |
| `artifact`          | Producto independiente generado por el modelo (como bloques de código o documentos), que puede guardarse o descargarse.                                                                                            |
| `system_message`    | Mensaje de aviso del sistema (no contenido del usuario ni del asistente), utilizado solo para avisos de la UI.                                                                                           |
| `compact`           | El contexto del modelo se ha organizado; los mensajes originales guardados permanecen sin cambios y el cliente no necesita eliminar los registros de chat.                                                                                    |
| `error`             | Se produjo un error en esta ronda; `message` describe el contenido del error.                                                                                              |
| `done`              | El registro final de la conversación de esta ronda se guardó correctamente; incluye `usage` (con `prompt_tokens` / `completion_tokens` / `total_tokens`) y `terminal_reason`; aún se debe determinar si la tarea se completó según el motivo de finalización. |
Para los clientes que solo se preocupan por la respuesta final, concatenar todos los `content` de `text_delta` equivale a `answer` en el modo `application/json`.

## Entrada multimodal

Si la entrada del usuario contiene imágenes o archivos, pase `message` (matriz) en lugar de `question`. Cada elemento de la matriz es un bloque de contenido:

```json
{
  "model": "gpt-5.4",
  "stateful": true,
  "message": [
    { "type": "text", "text": "这张图片里有几只猫？" },
    { "type": "image_url", "image_url": { "url": "https://cdn.acedata.cloud/cats.jpg" } }
  ]
}
```

Tipos de bloques compatibles:

- `text` — Texto normal, el campo `text` es obligatorio.
- `image_url` — Imagen, `image_url.url` es obligatorio.
- `file_url` — Archivo (PDF, CSV, TXT, etc.), `file_url.url` es obligatorio.

### Relación con `references` de v1

Para ser compatible con clientes antiguos, v2 sigue reconociendo el campo `references: ["https://...", ...]`:

- Si el sufijo de la URL es `jpg / jpeg / png / gif / bmp / webp / svg / heic / heif`, se convierte automáticamente en un bloque `image_url`;
- Otras extensiones se convierten en bloques `file_url`;
- Si también se proporciona `question`, se antepone como un bloque `text`.

Por lo tanto, si solo desea migrar desde v1 y no quiere modificar el cuerpo de la solicitud, basta con cambiar la ruta a `/aichat2/conversations`, y el uso original de `references` seguirá funcionando como de costumbre.

Si necesita un control más preciso (por ejemplo, colocar varias imágenes entre textos, o si el orden es importante), utilice directamente la matriz `message`.

## Llamadas a herramientas y MCP

La mejora principal de v2 es que el modelo puede llamar autónomamente a herramientas para completar tareas de varios pasos, **esto está habilitado de forma predeterminada**, y no requiere ninguna configuración adicional por parte del cliente en la solicitud. Escenarios comunes:

- El usuario pregunta «Ayúdame a buscar qué exposiciones nuevas hay recientemente en Shanghái» → el modelo llama a la búsqueda web integrada → organiza los resultados en una respuesta.
- El usuario pregunta «Lee este PDF y luego escribe un resumen» → el modelo llama a file_read → escribe un resumen.
- El usuario ya ha autorizado Google Drive / GitHub / Notion, etc., en [Connections](https://platform.acedata.cloud/connections) → el modelo puede llamar a las herramientas MCP correspondientes para leer y escribir sus datos.

En los flujos NDJSON / SSE, las llamadas a herramientas se presentan mediante dos tipos de eventos, `tool_use` y `tool_result`, por ejemplo:

```json
{"type":"tool_use","tool_id":"toolu_01ABCDEF","tool_name":"web_search","input":{"query":"上海 2026 春季展览"},"id":"f2f4b3e8-..."}
{"type":"tool_result","tool_id":"toolu_01ABCDEF","output":"...","is_error":false,"id":"f2f4b3e8-..."}
{"type":"text_delta","content":"目前","delta_answer":"目前","id":"f2f4b3e8-..."}
{"type":"text_delta","content":"上海","delta_answer":"上海","id":"f2f4b3e8-..."}
...
```

Si no desea mostrar los detalles de las llamadas a herramientas en el frontend, basta con ignorar los eventos `tool_use` / `tool_result` / `card` / `citation`; la salida final del modelo seguirá fluyendo mediante `text_delta`.

`max_turns` puede limitar el número máximo de rondas en las que el modelo puede llamarse a sí mismo para usar herramientas dentro de esta solicitud, con un rango de 1–500; si se omite, el valor predeterminado es 500. Establecerlo en un valor pequeño (por ejemplo, `max_turns: 1`) puede forzar una respuesta única y no permitir ninguna llamada a herramientas.

## Ejecución asíncrona y autorización no supervisada

Si su llamada proviene de un Webhook de alertas, CI/CD, sistema de monitorización u otra tarea de backend, puede establecer `async: true` para que la interfaz devuelva inmediatamente el ID de la tarea y continúe ejecutándose en segundo plano:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Ejemplo de respuesta:

```json
{
  "task_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "conversation_id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "status": "queued"
}
```

Después, puede usar `action: retrieve` + `id` para consultar el resultado de la conversación; también puede proporcionar `callback_url`, y, cuando la tarea se complete, la plataforma hará POST de `{ status, answer, usage, error }` a su dirección de devolución de llamada. `callback_url` debe utilizar `http` / `https`, y no puede indicar directamente `localhost` ni una dirección IP privada literal.

Normalmente, no hay nadie que pueda hacer clic para confirmar las tareas en segundo plano. Si desea que determinadas Skill o MCP Server ejecuten acciones como enviar, publicar o escribir en modo no supervisado, pase explícitamente una lista de preautorización en el cuerpo de la solicitud:

```json
{
  "model": "gpt-5.5",
  "async": true,
  "allowed_skills": ["acedatacloud/personal-wechat"],
  "allowed_mcp_servers": [],
  "question": "我的服务报警了，用个人微信通知微信群「AceDataCloud团队」……"
}
```

Los valores en `allowed_skills` son los slug de las Skill conectadas; los valores en `allowed_mcp_servers` son los slug de los MCP Server conectados. Las Skill / MCP Server no incluidas en la preautorización, en modo no supervisado, solo podrán previsualizar, hacer dry-run o rechazar la ejecución de operaciones de escritura.

Si necesita un control más detallado, también puede utilizar el objeto equivalente `unattended_policy`:

```json
{
  "unattended_policy": {
    "allowed_skills": ["acedatacloud/personal-wechat"],
    "allowed_mcp_servers": [],
    "expires_at": 1790000000
  }
}
```

La preautorización consiste en estas dos listas: una lista vacía significa no autorizar ninguna capacidad, sin necesidad de campos de interruptor adicionales.

Nota: la preautorización solo significa «esta solicitud permite que estas capacidades omitan la confirmación manual en modo no supervisado». La Skill específica debe seguir admitiendo `--unattended-confirm` o el mecanismo de seguridad correspondiente; de lo contrario, seguirá en dry-run y no ejecutará directamente operaciones de escritura.

## Reanudar conversaciones pausadas

Algunas herramientas hacen que el modelo «haga una pregunta al usuario»; en ese momento, el modelo emitirá un evento `ask_user_question`, y la conversación quedará congelada en el estado `awaiting_user_input`:

```json
{
  "type": "ask_user_question",
  "tool_id": "toolu_01XYZW",
  "tool_name": "ask_user_question",
  "question": "你希望生成的报告是中文还是英文？",
  "options": ["中文", "英文"],
  "id": "f2f4b3e8-..."
}
```

En el frontend, renderice este evento como una tarjeta para que el usuario elija una respuesta y, a continuación, inicie la siguiente solicitud con el mismo `id`, rellenando la respuesta mediante `tool_results`:
```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: text/event-stream' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "model": "gpt-5.4",
    "stateful": true,
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
    "tool_results": [
      {
        "tool_use_id": "toolu_01XYZW",
        "output": "中文"
      }
    ]
  }'
```

El `tool_use_id` en el cuerpo de la solicitud **debe** coincidir exactamente con el `tool_id` al momento de la pausa; si no coincide, devolverá 400. Cuando existen simultáneamente `tool_results` en la solicitud, `question` / `message` / `references` se ignorarán.

Si el usuario decide abandonar esta pregunta, basta con pasar directamente un nuevo `question` / `message`, y la plataforma marcará automáticamente la llamada de herramienta pausada como «omitida por el usuario».

## Gestión de conversaciones (CRUD)

v2 proporciona una gestión ligera de conversaciones mediante el campo `action` en el mismo endpoint, sin necesidad de abrir otra API.

### `action: retrieve` —— Obtener una conversación

```shell
curl -X POST 'https://api.acedata.cloud/aichat2/conversations' \
  -H 'accept: application/json' \
  -H 'authorization: Bearer {token}' \
  -H 'content-type: application/json' \
  -d '{
    "action": "retrieve",
    "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
  }'
```

Devuelve el documento completo de la conversación (incluye el historial de `messages`, `model`, `title`, `tools_used`, etc.).

### `action: retrieve_batch` —— Listar resúmenes de conversaciones

```json
{
  "action": "retrieve_batch",
  "model_group": "chatgpt",
  "limit": 20,
  "offset": 0
}
```

Devuelve `{ items: [...], total }`. **Los resúmenes no incluyen `messages`**, por lo que son adecuados para listas de barras laterales; si el usuario abre una conversación, utilice entonces `action: retrieve` para obtener sus mensajes completos por separado.

Parámetros de filtrado opcionales: `user_id`, `application_id`, `model_group`, `model`.

### `action: update` —— Cambiar el título o reescribir el historial

```json
{
  "action": "update",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44",
  "title": "Plan de viaje a Hangzhou"
}
```

También se puede pasar `messages`, pero el servidor realizará una validación estricta del schema (debe tener la forma `ToolUseContent` plegada); si no cumple, devolverá 400. Por lo general, solo se recomienda usarlo para cambiar `title`.

### `action: delete` —— Eliminar una conversación

```json
{
  "action": "delete",
  "id": "f2f4b3e8-0c0a-4d3a-aaa2-7ff80c0a1c44"
}
```

Devuelve `{ id, success: true }`. Después de la eliminación no se puede recuperar, confirme antes de llamar.

## Migración fluida desde v1

Si ya está utilizando [`/aichat/conversations`](https://platform.acedata.cloud/documents/aichat-conversations), migrar a v2 casi no requiere cambios de código:

1. Cambie la URL de `https://api.acedata.cloud/aichat/conversations` a `https://api.acedata.cloud/aichat2/conversations`.
2. Si anteriormente utilizaba nombres de modelos v1 (como `gpt-3.5`, `gpt-4-browsing`, etc.), al cambiar a v2 se recomienda actualizar a modelos contemporáneos (como `gpt-5.4`, `claude-opus-4-8`, `gemini-3.1-pro-preview`, etc.).
3. Los campos del flujo NDJSON mantienen compatibilidad hacia atrás: cada evento `text_delta` sigue incluyendo `delta_answer` e `id`, por lo que los clientes originales que analizan `delta_answer` línea por línea no necesitan cambios.

Después de la migración, puede habilitar según sea necesario las nuevas capacidades de v2 (multimodal `message`, SSE, llamadas de herramientas, CRUD con `action`) y avanzar a su propio ritmo.

## Manejo de errores

Las respuestas de error se unifican como:

```json
{
  "error": {
    "code": "chat_error",
    "message": "model service returned an error"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```

Errores comunes:

- `400 bad_request`: faltan campos obligatorios, `tool_use_id` no coincide, el schema de `messages` no es válido, etc.
- `401 invalid_token`: el encabezado `authorization` es incorrecto.
- `404 not_found`: la conversación correspondiente al `id` no existe al usar `action: retrieve / update / delete`.
- `413 conversation_storage_limit`: la conversación supera el límite de almacenamiento, sin sobrescribir los registros guardados existentes.
- `429 too_many_requests`: se activó el límite de velocidad.
- `503 context_compaction_failed`: falló la organización del contexto, los registros existentes se conservan.
- `500 conversation_persist_failed`: falló el guardado final de esta ronda; haber recibido texto no significa que el registro final se haya guardado correctamente, consulte mediante el ID de conversación.
- `500 chat_error`: el servicio no está disponible temporalmente, o no se generó contenido en esta ronda (no se cobrará).

En las respuestas de streaming, los errores se emiten mediante eventos `{"type":"error","message":"..."}`, y posteriormente el flujo termina. `[DONE]` solo indica que la transmisión ha finalizado; cuando hay `error`, no puede considerarse exitoso, y tampoco se enviará un evento `done` exitoso.

## Conclusión

AI Chat v2 API, al mantener compatibilidad hacia atrás con v1, actualiza las conversaciones de «preguntas y respuestas de una o múltiples rondas» a «conversaciones observables orientadas a agentes»: entradas multimodales, llamadas de herramientas, pausables / reanudables, eventos estructurados en streaming y CRUD integrado. Se recomienda que las nuevas integraciones utilicen v2 directamente; las integraciones v1 existentes pueden migrarse de forma fluida por fases. Si tiene alguna pregunta, no dude en contactar con nuestro equipo de soporte técnico.
