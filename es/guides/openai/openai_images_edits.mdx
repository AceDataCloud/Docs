## 2. Editar usando la URL de una imagen

Imagen original:

![Imagen original para edición de GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",

    "size": "1024x1536"
  }'
```

## 3. Subir una imagen local

Usa `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

Se puede enviar repetidamente `image`; la serie GPT Image admite hasta 16 imágenes de referencia. El `image` en las solicitudes JSON puede ser una única URL o un arreglo de URL; los archivos locales se suben mediante multipart.

| `gpt-image-2.6-flare:reverse`     | Alias inverso explícito, equivalente a `gpt-image-2.6-flare`, facturación fija por número de imágenes exitosas    |
| `gpt-image-2.5-flare:official`    | Canal de API oficial, mayor estabilidad y prioridad en la velocidad de generación, facturación según el uso real de Token            |

| `gpt-image-2.5-sunburst`          | Prioriza la alta fidelidad y el control detallado, facturación fija por número de imágenes exitosas                           |

| `gpt-image-2.5-sunburst:official` | Canal de API oficial, mayor estabilidad y prioridad en la alta fidelidad y el control detallado, facturación según el uso real de Token        |

Los modelos inversos 2.0 / 2.5 (incluidos los alias `:reverse`) pueden usar GPT Image 2.5 Flare para completar solicitudes durante la recuperación automática; el modelo solicitado y el método de facturación por número de imágenes exitosas permanecen sin cambios.

El precio mostrado para el canal de API oficial es una estimación previa a la solicitud; el importe final se basa en el uso real de Token y los registros de uso en la respuesta.

`quality` admite `auto`, `low`, `medium`, `high`; Flare y Sunburst 2.5 / 2.6 (incluidas las variantes `:reverse` y `:official`) admiten adicionalmente `xhigh`, `max`. Tanto la edición de URL de imagen JSON como la edición de archivos multipart pueden incluir este campo; el canal oficial factura según el uso real de Token.

## 4. Usar una máscara para edición local

La interfaz oficial Images Edit especifica las áreas que se permite modificar mediante `mask`. Los modelos `:official` de Ace Data Cloud siguen el mismo contrato multipart:

- `mask` debe ser un PNG con canal Alpha y no debe superar los 4 MB;
- el tamaño de la máscara debe ser exactamente igual al de la primera `image`;
- los píxeles transparentes con Alpha de `0` indican que se permite editar, y los píxeles no transparentes indican que deben conservarse;
- las imágenes RGB que solo son en blanco y negro, pero no tienen un canal transparente, no pueden utilizarse como máscaras válidas;
- el prompt debe describir la imagen completa que se espera obtener, al mismo tiempo que aclara la modificación local y el contenido que debe permanecer sin cambios.

A continuación, primero se genera una máscara a partir de la imagen original. El ejemplo establece el rectángulo central como transparente, permitiendo que el modelo modifique solo esa área:
```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Luego sube la imagen original y la máscara juntas:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

También puedes seguir usando el método de llamada `images.edit` del SDK oficial de Python de OpenAI; solo necesitas apuntar `base_url` a Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Al usar `mask`, la imagen original y la máscara deben subirse por separado en la misma solicitud multipart mediante `image=@input.png` y `mask=@mask.png`. No mezcles una imagen original por URL con un archivo local de máscara; las solicitudes de edición exclusivamente por URL no admiten adjuntar además un archivo `mask` local. La máscara restringirá el área de edición, pero el modelo generativo aún puede realizar una fusión natural en los bordes; cuando se requieran límites estrictos, se deben usar bordes Alpha claros y repetir en el prompt qué contenido debe permanecer sin cambios.

Los métodos de llamada anteriores son coherentes con los ejemplos de máscaras de [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) y del [Cookbook oficial de GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Parámetros comunes

| Campo                | Descripción                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (más rápido) o `gpt-image-2.5-sunburst` (mayor fidelidad y control); los tres pueden elegir la variante `:official` correspondiente, y `gpt-image-2` también admite `:reverse` |
| `image`           | JSON utiliza una sola URL o un array de hasta 16 URL; multipart utiliza uno o más campos de archivo `image`. Al utilizar `mask`, se debe subir un archivo de imagen local                                              |
| `mask`            | Máscara PNG opcional, limitada a la carga de archivos multipart; debe incluir un canal Alpha, tener el mismo tamaño que la primera `image` y no superar 4 MB                                                                 |
| `prompt`          | Instrucción de edición                                                                                                                             |
| `size`            | `auto` o un `WIDTHxHEIGHT` que cumpla las restricciones                                                                                                     |
| `n`               | 1–10; cuando `response_format=b64_json`, solo se admite 1                                                                                           |
| `response_format` | `url` o `b64_json`                                                                                                               |
| `callback_url`    | Dirección opcional de devolución de llamada asíncrona                                                                                                                         |

Las reglas de tamaño son coherentes con la interfaz de generación: el ancho y la altura deben ser múltiplos de 16, el lado largo no debe superar 3840, el total de píxeles debe ser de 655.360–8.294.400 y la relación de aspecto no debe superar 3:1. Al omitir `size` o usar `auto`, el modelo seleccionará el formato basándose en el prompt y la primera imagen de referencia.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` y sus alias `:reverse` se cobran por el número de imágenes generadas correctamente; `gpt-image-2:official`, `gpt-image-2.5-flare:official` y `gpt-image-2.5-sunburst:official` se liquidan según los Tokens reales de entrada de texto, entrada de imagen de referencia y salida de imagen; el registro de uso final prevalece.

## 6. Devoluciones de llamada asíncronas y resolución de errores

Para tareas largas, puedes añadir lo siguiente en la solicitud:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

La respuesta asíncrona 200 es `{"task_id": "..."}`; tras completarse, se devuelve el resultado final mediante devolución de llamada. Las solicitudes síncronas devuelven `created` y `data`.

| Estado  | Comprobar                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Formato/cantidad de imágenes, combinaciones de parámetros y formato de tamaño; al usar `mask`, comprueba el canal Alpha de PNG, el límite de 4 MB y si sus dimensiones coinciden con la primera imagen original |
| 401 | API Key y Bearer Header                                           |
| 429 | Frecuencia de solicitudes                                                              |
| 504 | Cambiar a devolución de llamada asíncrona                                                            |

Las respuestas de error incluirán `trace_id`. Al informar de problemas, proporciona este ID; no proporciones la API Key.

Los campos completos y las enumeraciones en tiempo real se rigen por la página de [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Para la generación de imágenes exclusivamente a partir de texto, consulta [Generación de imágenes GPT Image 2 / 2.5 / 2.6](https://platform.acedata.cloud/documents/openai-images-generations).

## GPT Image 2.6

GPT Image 2.6 mantiene las interfaces de generación, edición, tareas asíncronas y facturación de 2.5:

| Modelo                                                          | Facturación                               |
| ----------------------------------------------------------- | -------------------------------- |
| `gpt-image-2.6-flare` / `gpt-image-2.6-flare:reverse`       | 0,22 Credits/imagen                   |
| `gpt-image-2.6-sunburst` / `gpt-image-2.6-sunburst:reverse` | 0,22 Credits/imagen                   |
| `gpt-image-2.6-flare:official`                              | Igual que 2.5 official, facturado según el uso real de Tokens |
| `gpt-image-2.6-sunburst:official`                           | Igual que 2.5 official, facturado según el uso real de Tokens |

La calidad puede ser `auto`, `low`, `medium`, `high`, `xhigh`, `max`; el tamaño utiliza `auto` o un `WIDTHxHEIGHT` que cumpla las restricciones anteriores. Esta interfaz admite `png`, `jpeg`, `webp`; GPT Image 2.6 también admite animaciones `gif` nativas, pero SVG no se admite por el momento. La edición admite URL de imágenes JSON y carga de archivos multipart. `:reverse` es un alias explícito de la versión normal del mismo nombre. Utiliza el nombre completo del modelo; no pases `gpt-image-2.6`.

### Conversión de imágenes a animaciones GIF con GPT Image 2.6
GPT Image 2.6 Flare, Sunburst en su versión estándar, `:reverse`, `:official` pueden usar `output_format: "gif"`. Se conservarán los fotogramas de animación, la información de bucle y la duración de reproducción; `frame_count` indica el número de fotogramas, `frame_duration_ms` indica los milisegundos por fotograma, el número de fotogramas debe ser un entero de 2–16, la duración de cada fotograma debe ser un entero de 20–655350 milisegundos, y solo se usa para GIF; la codificación se redondea a los 10 ms más cercanos. Si no se especifica, el valor predeterminado es 9 fotogramas y 200 milisegundos por fotograma; cuando se omite el `size` del GIF o es auto, se utiliza el preajuste de 512x512.

Se recomienda usar primero `size: "512x512"`, `frame_count: 9`, `frame_duration_ms: 200`. Los GIF tienen límites independientes de tamaño y número de fotogramas, y no se pueden aplicar directamente las especificaciones estáticas 4K; algunos modelos ajustarán el tamaño real de salida. `n` indica la cantidad de archivos GIF devueltos, no el número de fotogramas de animación. La versión estándar y `:reverse` siguen cobrando según la cantidad de archivos exitosos, mientras que la versión oficial cobra según el uso real de Tokens.

```json
{
  "model": "gpt-image-2.6-flare",
  "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
  "prompt": "Animate the mug gently moving left and right. Keep its appearance and the background, no text.",
  "output_format": "gif",
  "size": "512x512",
  "quality": "medium",
  "frame_count": 9,
  "frame_duration_ms": 200,
  "n": 1,
  "async": true
}
```

### Imágenes estáticas 4K de GPT Image 2.6

Flare, Sunburst y sus variantes `:reverse`, `:official` pueden usar los preajustes de píxeles 4K antes mencionados, como `3840x2160` y `2160x3840`. Tanto la generación como la edición reciben píxeles específicos mediante `size`; `4K` no es un valor de `size` válido, y `4096x4096` también supera el límite actual de píxeles. Las especificaciones 4K anteriores se aplican a PNG/JPEG/WebP estáticos; para GIF use sus parámetros específicos.

### Complejidad de composición de GPT Image 2.6

`complexity` puede ser `low`, `medium`, `high`, y si se omite se usa el valor predeterminado del modelo `high`. Controla la complejidad de planificación y es independiente de la calidad de renderizado de `quality`; no se cobrará un costo adicional por uso, y la versión oficial seguirá liquidándose según los Tokens realmente utilizados. Otros modelos no admiten este parámetro.

GIF no admite mask, imágenes de marcado, compresión personalizada, reescritura de prompts ni salida de imágenes parcial en streaming; las combinaciones incompatibles se rechazarán antes de la generación. El tamaño, el número de fotogramas y la cantidad están sujetos conjuntamente al límite de presupuesto de píxeles del modelo; se ha verificado que `1024x1024` y 2 fotogramas de Flare estándar son utilizables, pero esta conclusión no puede extenderse a todas las combinaciones 1K ni a GIF 4K.

### Edición guiada por marcado

La edición estática de GPT Image 2.6 admite `markup`. Cargue un PNG transparente del mismo tamaño que la primera imagen de referencia, marque en una capa independiente la ubicación que se va a modificar y explique los requisitos de modificación en `prompt`. La capa de marcado debe contener píxeles transparentes; cada una de las dos imágenes no debe superar los 16777216 píxeles, y la imagen de marcado no debe superar los 40MB. JSON puede pasar una URL HTTPS, una URL de datos PNG base64 o `{ "image_url": "https://..." }`; multipart carga el archivo mediante `markup`. La plataforma transmitirá la capa de marcado en forma de archivo. `markup` no puede usarse junto con `mask`, GIF o `prompt_rewriter`, y no admite `file_id`.

`input_fidelity` no se aplica a GPT Image 2.6, omítalo.
