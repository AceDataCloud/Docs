## 2. Editar usando la URL de una imagen

Imagen original:

![Imagen original para edición de GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://cdn.acedata.cloud/assets/examples/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0-18240dc44b9c.png",
    "prompt": "Keep the mug, tabletop, camera angle, portrait layout, and soft shadow unchanged. Change only the mug color from white to vivid orange and the pale cream background to solid dark navy blue. No text and no logo.",
    "size": "1024x1536"
  }'
```

## 3. Subir una imagen local

Usa `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

Se puede enviar `image` repetidamente; la serie GPT Image admite hasta 16 imágenes de referencia. La `image` en las solicitudes JSON puede ser una sola URL o un arreglo de URL; los archivos locales se suben mediante multipart.

### Modelos y métodos de facturación

| Modelo                                | Escenarios aplicables y método de facturación                                        |
| --------------------------------- | ------------------------------------------------ |
| `gpt-image-2`                     | Canal inverso predeterminado, facturación fija por número de imágenes exitosas                               |
| `gpt-image-2:reverse`             | Selecciona explícitamente el canal inverso, facturación fija por número de imágenes exitosas                             |
| `gpt-image-2:official`            | Canal de API oficial, mayor estabilidad, facturación según el uso real de Token                   |
| `gpt-image-2.5-flare`             | Prioriza la velocidad de generación, facturación fija por número de imágenes exitosas                               |
| `gpt-image-2.5-flare:reverse`     | Alias inverso explícito, equivalente a `gpt-image-2.5-flare`, facturación fija por número de imágenes exitosas    |
| `gpt-image-2.5-flare:official`    | Canal de API oficial, mayor estabilidad y prioriza la velocidad de generación, facturación según el uso real de Token            |
| `gpt-image-2.5-sunburst`          | Prioriza alta fidelidad y control detallado, facturación fija por número de imágenes exitosas                           |
| `gpt-image-2.5-sunburst:reverse`  | Alias inverso explícito, equivalente a `gpt-image-2.5-sunburst`, facturación fija por número de imágenes exitosas |
| `gpt-image-2.5-sunburst:official` | Canal de API oficial, mayor estabilidad y prioriza alta fidelidad y control detallado, facturación según el uso real de Token        |

Los modelos inversos (incluidos los alias `:reverse`) pueden usar GPT Image 2.5 Flare para completar solicitudes durante la recuperación automática; el modelo solicitado y el método de facturación por número de imágenes exitosas permanecen sin cambios.

El precio mostrado en la página para el canal de API oficial es una estimación antes de la solicitud; el resultado final se basa en el uso real de Token y los registros de uso en la respuesta.

`quality` admite `auto`, `low`, `medium`, `high`; solo `gpt-image-2.5-flare` y `gpt-image-2.5-sunburst` (incluidas las variantes `:reverse` y `:official`) admiten adicionalmente `xhigh`, `max`. Tanto la edición de URL de imagen JSON como la edición de archivos multipart pueden incluir este campo; el canal oficial factura según el uso real de Token.

## 4. Usar una máscara para edición local

La interfaz oficial Images Edit especifica las áreas que se permite modificar mediante `mask`. Los modelos `:official` de Ace Data Cloud siguen el mismo contrato multipart:

- `mask` debe ser un PNG con canal Alpha, de un tamaño no superior a 4 MB;
- El tamaño de la máscara debe coincidir exactamente con la primera `image`;
- Los píxeles transparentes con Alpha igual a `0` indican que se permite editar, y los píxeles no transparentes indican que deben conservarse;
- Las imágenes RGB que solo son en blanco y negro, pero no tienen un canal transparente, no pueden utilizarse como máscaras válidas;
- El prompt debe describir la imagen completa esperada y, al mismo tiempo, aclarar las modificaciones locales y el contenido que debe permanecer sin cambios.

A continuación, primero se genera una máscara a partir de la imagen original. El ejemplo establece el rectángulo central como transparente, permitiendo que el modelo modifique únicamente esa área:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Después, sube juntas la imagen original y la máscara:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

También se puede seguir usando la forma de llamada `images.edit` del SDK oficial de Python de OpenAI; solo es necesario dirigir `base_url` a Ace Data Cloud:
```python
from openai import OpenAI

client = OpenAI(
    api_key="Tu API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Mantén la composición, la iluminación y todos los objetos fuera de la "
            "máscara transparente sin cambios. Dentro del área enmascarada, reemplaza "
            "la superficie vacía de la mesa con un pequeño jarrón de cerámica azul."
        ),
    )

print(result.data[0].url)
```

Al usar `mask`, la imagen original y la máscara deben cargarse por separado en la misma solicitud multipart mediante `image=@input.png` y `mask=@mask.png`. No mezcles la imagen original por URL con el archivo de máscara local; las solicitudes de edición con solo URL no admiten adjuntar además un archivo `mask` local. La máscara restringirá el área de edición, pero el modelo de generación aún puede realizar una fusión natural en los bordes; cuando se requieran límites estrictos, se deben usar bordes Alpha claros y repetir en el prompt qué contenido debe permanecer sin cambios.

El método de llamada anterior es coherente con los ejemplos de máscaras de [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) y del [Cookbook oficial de GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Parámetros comunes

| Campo                | Descripción                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (más rápido) o `gpt-image-2.5-sunburst` (mayor fidelidad y control); los tres pueden seleccionar la variante `:official` correspondiente, y `gpt-image-2` también admite `:reverse` |
| `image`           | JSON utiliza una sola URL o un arreglo de hasta 16 URL; multipart utiliza uno o varios campos de archivo `image`. Al usar `mask`, se deben cargar archivos de imagen locales                                              |
| `mask`            | Máscara PNG opcional, limitada a la carga de archivos multipart; debe incluir canal Alpha, tener el mismo tamaño que la primera `image` y no superar 4 MB                                                                 |
| `prompt`          | Instrucción de edición                                                                                                                             |
| `size`            | `auto` o `WIDTHxHEIGHT` que cumpla las restricciones                                                                                                     |
| `n`               | 1–10; cuando `response_format=b64_json`, solo se admite 1                                                                                           |
| `response_format` | `url` o `b64_json`                                                                                                               |
| `callback_url`    | Dirección de callback asíncrono opcional                                                                                                                         |

Las reglas de tamaño son coherentes con la interfaz de generación: el ancho y la altura deben ser múltiplos de 16, el lado largo no debe superar 3840, el total de píxeles debe ser de 655,360–8,294,400 y la relación de aspecto no debe superar 3:1. Al omitir `size` o usar `auto`, el modelo elegirá el formato basándose en el prompt y la primera imagen de referencia.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` y sus alias `:reverse` se facturan según el número de imágenes generadas correctamente; `gpt-image-2:official`, `gpt-image-2.5-flare:official` y `gpt-image-2.5-sunburst:official` se cobran según los Tokens reales de entrada de texto, entrada de imagen de referencia y salida de imagen, y prevalecerán los registros de uso finales.

## 6. Callback asíncrono y depuración

Las tareas largas pueden añadir lo siguiente en la solicitud:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

La respuesta asíncrona 200 es `{"task_id": "..."}`; tras completarse, se realiza el callback con el resultado final. Las solicitudes síncronas devuelven `created` y `data`.

| Estado  | Verificar                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Formato/cantidad de imágenes, combinación de parámetros y formato de tamaño; al usar `mask`, verifica el canal Alpha de PNG, el límite de 4 MB y si sus dimensiones coinciden con la primera imagen original |
| 401 | API Key y Bearer Header                                           |
| 429 | Frecuencia de solicitudes                                                              |
| 504 | Cambiar a callback asíncrono                                                            |

Las respuestas de error incluirán `trace_id`. Al informar problemas, proporciona este ID, no proporciones la API Key.

Los campos completos y las enumeraciones en tiempo real se rigen por la página [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Para la generación de imágenes a partir de texto puro, consulta [Generación de imágenes GPT Image 2 / 2.5](https://platform.acedata.cloud/documents/openai-images-generations).
