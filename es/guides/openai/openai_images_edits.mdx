## 2. Editar usando la URL de la imagen

Imagen original:

![Imagen original para edición de GPT Image 2](https://cdn.acedata.cloud/18240dc44b9c.png)

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "gpt-image-2",
    "image": "https://platform2.cdn.acedata.cloud/gpt-image/d56455e2-e7f7-4bcd-b935-475b0a1e0948_0.png",

```

## 3. Subir una imagen local

Usa `multipart/form-data`:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2" \
  -F "image=@input.png" \
  -F "prompt=Replace the background with a bright modern studio"
```

Se puede enviar `image` repetidamente; la serie GPT Image admite hasta 16 imágenes de referencia. `image` en las solicitudes JSON puede ser una única URL o un arreglo de URL; los archivos locales se suben mediante multipart.

## 4. Usar una máscara para edición local

La interfaz oficial Images Edit especifica las áreas que se pueden modificar mediante `mask`. El modelo `:official` de Ace Data Cloud sigue el mismo contrato multipart:

- `mask` debe ser un PNG con canal Alpha y no puede superar los 4 MB;
- el tamaño de la máscara debe coincidir exactamente con la primera `image`;
- los píxeles transparentes con Alpha de `0` indican que se permite la edición, y los píxeles no transparentes indican que se deben conservar;
- las imágenes RGB que solo son en blanco y negro, pero no tienen canal transparente, no pueden utilizarse como máscaras válidas;
- el prompt debe describir la imagen completa que se espera obtener, al mismo tiempo que deja claro el cambio local y el contenido que debe permanecer sin cambios.

A continuación, primero se genera una máscara a partir de la imagen original. El ejemplo establece el rectángulo central como transparente y solo permite que el modelo modifique esa área:

```python
from PIL import Image, ImageDraw

source = Image.open("input.png").convert("RGBA")
mask = Image.new("RGBA", source.size, (0, 0, 0, 255))
draw = ImageDraw.Draw(mask)
width, height = source.size
draw.rectangle(
    (width // 4, height // 4, width * 3 // 4, height * 3 // 4),
    fill=(0, 0, 0, 0),
)
mask.save("mask.png")
```

Luego sube la imagen original y la máscara juntas:

```bash
curl https://api.acedata.cloud/openai/images/edits \
  -H "Authorization: Bearer 你的 API Key" \
  -F "model=gpt-image-2:official" \
  -F "image=@input.png" \
  -F "mask=@mask.png" \
  -F "prompt=Keep the composition, lighting, and all objects outside the transparent mask unchanged. Inside the masked area, replace the empty tabletop with a small blue ceramic vase."
```

También se puede seguir la forma de llamada `images.edit` del SDK oficial de Python de OpenAI; solo es necesario apuntar `base_url` a Ace Data Cloud:

```python
from openai import OpenAI

client = OpenAI(
    api_key="你的 API Key",
    base_url="https://api.acedata.cloud/openai",
)

with open("input.png", "rb") as image, open("mask.png", "rb") as mask:
    result = client.images.edit(
        model="gpt-image-2:official",
        image=image,
        mask=mask,
        prompt=(
            "Keep the composition, lighting, and all objects outside the "
            "transparent mask unchanged. Inside the masked area, replace "
            "the empty tabletop with a small blue ceramic vase."
        ),
    )

print(result.data[0].url)
```

Al usar `mask`, la imagen original y la máscara deben subirse en la misma solicitud multipart mediante `image=@input.png` y `mask=@mask.png`, respectivamente. No mezcles una imagen original por URL con un archivo de máscara local; las solicitudes de edición únicamente por URL no admiten añadir un archivo `mask` local. La máscara restringirá el área de edición, pero el modelo de generación aún puede realizar una fusión natural en los bordes; cuando se requieran límites estrictos, se deben utilizar bordes Alpha nítidos y repetir en el prompt qué contenido debe permanecer sin cambios.

Los métodos de llamada anteriores son coherentes con los ejemplos de máscaras de [OpenAI Image Edit API](https://developers.openai.com/api/reference/python/resources/images/methods/edit) y del [Cookbook oficial de GPT Image](https://developers.openai.com/cookbook/examples/generate_images_with_gpt_image).

## 5. Parámetros comunes

| Campo                | Descripción                                                                                                                               |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `model`           | `gpt-image-2`, `gpt-image-2.5-flare` (más rápido) o `gpt-image-2.5-sunburst` (mayor fidelidad y control); los tres pueden seleccionar la variante `:official` correspondiente, y `gpt-image-2` también admite `:reverse` |
| `image`           | JSON usa una única URL o un arreglo de hasta 16 URL; multipart usa uno o varios campos de archivo `image`. Al usar `mask`, se deben subir archivos de imagen locales                                              |
| `mask`            | Máscara PNG opcional, limitada a la subida de archivos multipart; debe tener canal Alpha, el mismo tamaño que la primera `image` y no superar los 4 MB                                                                 |
| `prompt`          | Instrucción de edición                                                                                                                             |
| `size`            | `auto` o `WIDTHxHEIGHT` que cumpla las restricciones                                                                                                     |
| `n`               | 1–10; cuando `response_format=b64_json`, solo se admite 1                                                                                           |
| `response_format` | `url` o `b64_json`                                                                                                               |
| `callback_url`    | Dirección de devolución de llamada asíncrona opcional                                                                                                                         |
Las reglas de tamaño son coherentes con la API de generación: el ancho y el alto deben ser múltiplos de 16, el lado más largo no debe superar 3840, el total de píxeles debe ser de 655,360–8,294,400 y la relación de aspecto no debe superar 3:1. Al omitir `size` o usar `auto`, el modelo seleccionará el formato combinando el prompt y la primera imagen de referencia.

`gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` y `gpt-image-2:reverse` se facturan según la cantidad de imágenes generadas correctamente; `gpt-image-2:official`, `gpt-image-2.5-flare:official` y `gpt-image-2.5-sunburst:official` se liquidan según los Tokens reales de la entrada de texto, la entrada de imágenes de referencia y la salida de imágenes; prevalecerán los registros de uso.

## 6. Devoluciones de llamada asíncronas y depuración

Para tareas largas, se puede añadir a la solicitud:

```json
{
  "callback_url": "https://example.com/webhooks/images"
}
```

La respuesta asíncrona 200 es `{"task_id": "..."}`; tras completarse, se devuelve el resultado final mediante devolución de llamada. Las solicitudes síncronas devuelven `created` y `data`.

| Estado  | Comprobación                                                                |
| --- | ----------------------------------------------------------------- |
| 400 | Formato/cantidad de imágenes, combinación de parámetros y formato de tamaño; al usar `mask`, compruebe el canal Alpha de PNG, el límite de 4MB y si sus dimensiones coinciden con la primera imagen original |
| 401 | API Key y Bearer Header                                           |
| 429 | Frecuencia de solicitudes                                                              |
| 504 | Cambie a una devolución de llamada asíncrona                                                            |

Las respuestas de error incluirán `trace_id`. Proporcione este ID al informar de problemas; no proporcione la API Key.

Para los campos completos y las enumeraciones en tiempo real, consulte la página de [OpenAI Images Edits API](https://platform.acedata.cloud/documents/openai-images-edits). Para generar imágenes a partir de texto sin formato, consulte [Generación de imágenes GPT Image 2 / 2.5](https://platform.acedata.cloud/documents/openai-images-generations).
