Este artículo presentará unas instrucciones de integración de SeeDance Videos Generation API, que permite generar videos oficiales de SeeDance introduciendo parámetros personalizados.

## Proceso de solicitud

Para utilizar SeeDance Videos Generation API, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, se le redirigirá automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; al completarlo, regresará automáticamente a la página actual.

**Un solo API Token permite llamar a todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluye cuota gratuita, que permite una experiencia gratuita; cuando la cuota sea insuficiente, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [SeeDance Videos Generation API →](https://platform.acedata.cloud/documents/seedance-videos)

## Uso básico

Primero conozcamos el método de uso básico: basta con introducir el texto de indicación `content.text`, el tipo `content.type=text` y el modelo `model` para obtener el resultado procesado; el contenido específico es el siguiente:

<p><img src="https://cdn.acedata.cloud/seedance_parameters.png" width="500" className="m-auto" /></p>

Aquí podemos ver que configuramos los Request Headers, incluidos:

- `accept`: el formato de resultado de respuesta que se desea recibir; aquí se completa como `application/json`, es decir, formato JSON.
- `authorization`: la clave para llamar a la API; después de solicitarla, puede seleccionarla directamente desde el menú desplegable.

También configuramos el Request Body, incluido:

- `model`: el modelo para generar videos.
  - **Serie Seedance 1.x**: `doubao-seedance-1-0-pro-250528`, `doubao-seedance-1-0-pro-fast-251015`, `doubao-seedance-1-5-pro-251215`, `doubao-seedance-1-0-lite-t2v-250428`, `doubao-seedance-1-0-lite-i2v-250428`.
  - **Serie Seedance 2.0** (admite referencias multimodales de personajes y audio/video): `doubao-seedance-2-0-260128` (estándar), `doubao-seedance-2-0-fast-260128` (rápido), `doubao-seedance-2-0-mini-260615` (ligero).
  - **Seedance 2.5**: `doubao-seedance-2-5-260628`, admite hasta 30 segundos, referencia de audio puro, más materiales, edición y extensión de video.
- `content`: matriz de contenido de entrada; `type` puede ser `text` (texto de indicación), `image_url` (imagen de referencia), `audio_url` (audio de referencia), `video_url` (video de referencia). Las imágenes pueden especificar su uso mediante `role`: `first_frame` (primer fotograma) / `last_frame` (último fotograma) / `reference_image` (referencia de personaje / sujeto).
- `resolution`: resolución de salida; opcional entre `480p` / `720p` / `1080p` / `4k`. La versión 2.5 admite 480p, 720p y 1080p; 2.0 Fast/Mini admite 480p y 720p; 2.0 Standard admite hasta 4k.
- `ratio`: relación de aspecto; opcional entre `16:9` / `4:3` / `1:1` / `3:4` / `9:16` / `21:9` / `adaptive`.
- `duration`: duración del video (segundos, entero). Serie 1.0: 2–12; 1.5 Pro: 4–12; serie 2.0: 4–15; 2.5: 4–30. 1.5/2.x admite `-1` (duración automática).
- `seed`: semilla aleatoria, entero, de -1 a 4294967295.
- `camerafixed`: si se fija la cámara, `true` / `false`.
- `watermark`: si se añade una marca de agua, `true` / `false`.
- `generate_audio`: si se genera video con sonido, `true` / `false`; Seedance 1.5 Pro y la serie 2.x lo admiten.
- `return_last_frame`: si se devuelve la URL de la imagen del último fotograma del video en el resultado.
- `omni_reference_task_type`: solo 2.5; `auto` / `reference` / `edit` / `extend`.
- `output_format`: solo 2.5; `mp4` / `mov`, el valor predeterminado es `mp4`.
- `tools`: solo 2.5; actualmente admite la herramienta de búsqueda en línea `web_search`, que puede limitar la cantidad de resultados, la cantidad de palabras clave y las fuentes de búsqueda.
- `priority`: prioridad de tarea opcional para 2.5, entero 0–9, el valor predeterminado es 0.
- `safety_identifier`: identificador estable y anónimo del usuario final de hasta 64 caracteres; utilice un hash o ID anónimo interno, no introduzca nombres, correos electrónicos ni números de teléfono.
- `execution_expires_after`: tiempo de espera de la tarea (segundos), rango 3600–259200.
- `callback_url`: dirección de devolución de llamada asíncrona; después de configurarla, la API devuelve inmediatamente `task_id`, y al completarse la tarea enviará el resultado mediante POST a esta dirección.
- `async`: opcional; cuando se establece en `true`, la interfaz devuelve inmediatamente `task_id`, sin necesidad de proporcionar `callback_url`; posteriormente, obtenga el resultado mediante sondeo a través de la interfaz de consulta de tareas correspondiente.

```shell
  "ratio": "16:9",
  "duration": 5

```

## Descripción de parámetros en línea

Al final del prompt `content[].text`, se pueden pasar parámetros de generación añadiendo `--parameter value` (método anterior, validación débil, si se completa incorrectamente se utilizan automáticamente los valores predeterminados). La lista completa de parámetros es la siguiente:

| Parámetro en línea       | Campo correspondiente              | Descripción      | Rango de valores                                                          |
| ---------- | ----------------- | ------- | ------------------------------------------------------------- |
| `--rs`     | `resolution`      | Resolución de salida   | `480p` / `720p` / `1080p`                                     |
| `--rt`     | `ratio`           | Relación de aspecto     | `16:9` / `4:3` / `1:1` / `3:4` / `9:16` / `21:9` / `adaptive` |
| `--dur`    | `duration`        | Duración del video (segundos) | 2–12                                                          |
| `--frames` | `frames`          | Número de fotogramas del video    | Enteros de [29, 289] que cumplen 25+4n (**solo compatible con la serie 1.0**)                       |
| `--fps`    | `framespersecond` | Tasa de fotogramas      | Solo compatible con `24`                                                      |
| `--seed`   | `seed`            | Semilla aleatoria    | -1 a 4294967295                                               |
| `--cf`     | `camerafixed`     | Si se fija la cámara | `true` / `false`                                              |
| `--wm`     | `watermark`       | Si se añade marca de agua  | `true` / `false`                                              |

> **Práctica recomendada**: use directamente los campos de nivel superior correspondientes en el Request Body (como `resolution`, `ratio`, etc.); es el modo de validación estricta, y se devolverán mensajes de error claros cuando los parámetros se completen incorrectamente, lo que facilita la resolución de problemas.

## Generar videos con audio

Seedance 1.5 Pro y la serie 2.x admiten la generación de videos con audio mediante el parámetro `generate_audio`:

```json
{
  "model": "doubao-seedance-1-5-pro-251215",
  "content": [
    {
      "type": "text",
      "text": "A girl holds a fox, the wind blows her hair, you can hear the sound of the wind"
    }
  ],
  "generate_audio": true,
  "ratio": "16:9",
  "duration": 5
}
```

La serie 1.0 no admite este parámetro.

## Generación, edición y extensión multimodal completa de Seedance 2.5

`doubao-seedance-2-5-260628` admite 480p / 720p / 1080p, 4–30 segundos o duración automática, y aumenta el límite de materiales a 30 imágenes de referencia, 10 videos de referencia y 10 audios de referencia (hasta 50 en total). 2.5 también admite transmitir solo audio de referencia, sin requerir ya proporcionar simultáneamente imágenes o videos.

La generación multimodal completa normal puede omitir `omni_reference_task_type`, establecerlo en `auto` o establecerlo explícitamente en `reference`. La edición y extensión de video deben incluir `reference_video`:

```json
{
  "model": "doubao-seedance-2-5-260628",
  "content": [
    {"type": "text", "text": "Replace the sky with a warm sunset while preserving the subject and camera motion."},
    {"type": "video_url", "role": "reference_video", "video_url": {"url": "https://cdn.acedata.cloud/input.mp4"}}
  ],
  "resolution": "720p",
  "ratio": "adaptive",
  "duration": -1,
  "omni_reference_task_type": "edit",
  "output_format": "mov"
}
```

- `reference`: incluya al menos un `reference_image`, `reference_video` o `reference_audio`; 2.5 admite transmitir solo audio de referencia.
- `edit`: debe usar `ratio: adaptive` y `duration: -1`; la duración de salida se cobra según el resultado real.
- `extend`: debe usar `ratio: adaptive`; `duration` puede ser 4–30 o `-1`.
- `auto`: el modelo selecciona automáticamente generación, edición o extensión según el prompt y los materiales.
- Cuando el tipo de tarea no coincide con los materiales o el prompt, la tarea fallará y devolverá un error de parámetro localizable; ajústelo según las restricciones anteriores y vuelva a enviarlo.

## Primer fotograma de video a partir de imagen

Si se desea una tarea de video a partir de imagen, primero el parámetro `content` debe incluir un elemento cuyo `type` sea `image_url`, y el campo `image_url` debe tener formato de objeto: `{"url": "https://..."}` o formato Base64 `{"url": "data:image/png;base64,..."}`.

> **Nota**: `image_url` no admite transmitir directamente en formato de cadena (como `"image_url": "https://cdn.acedata.cloud/e724d7f13d.png"`), se debe usar el formato de objeto `"image_url": {"url": "https://..."}`, de lo contrario se devolverá un error 400.

El código correspondiente:

```python
import requests

url = "https://api.acedata.cloud/seedance/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "content": [
        {
            "type": "image_url",
            "image_url": {
                "url": "https://ark-project.tos-cn-beijing.volces.com/doc_image/i2v_foxrgirl.png"
            }
        },
        {
            "type": "text",
            "text": "A girl holds a fox in her arms. She opens her eyes and gazes tenderly at the camera, while the fox affectionately holds her back. As the camera slowly pulls away, her hair is gently blown by the wind. --ratio adaptive  --dur 5"
        }
    ],
    "model": "doubao-seedance-1-0-pro-250528"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Al hacer clic en ejecutar, se puede observar que se obtiene inmediatamente un resultado, como se muestra a continuación:

```
  "data": {
    "task_id": "cgt-20251222072003-x2259",
```

Se puede ver que el efecto generado es de video generado a partir de imagen, y el resultado es similar al anterior.

## Primer y último fotograma de video a partir de imagen

Si se desea el primer y último fotograma de video a partir de imagen, primero el parámetro `content` debe incluir el tipo `image_url`, y establecer respectivamente `role` como `first_frame` y `last_frame`, para poder especificar el siguiente contenido:

- role: especifica el primer fotograma o el último fotograma.
- image_url
  - url enlace de la imagen
    Al mismo tiempo, `content` también debe introducir el tipo `text` como prompt

El código correspondiente:
```python
import requests

url = "https://api.acedata.cloud/seedance/videos"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
   "model": "doubao-seedance-1-0-pro-250528",
    "content": [
         {
            "type": "text",
            "text": "360-degree shot"
        },
        {
            "type": "image_url",
            "image_url": {
                "url": "https://ark-project.tos-cn-beijing.volces.com/doc_image/seepro_first_frame.jpeg"
            },
            "role": "first_frame"
        },
        {
            "type": "image_url",
            "image_url": {
                "url": "https://ark-project.tos-cn-beijing.volces.com/doc_image/seepro_last_frame.jpeg"
            },
            "role": "last_frame"
        }
    ]
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Haz clic para ejecutar; podrás observar que se obtiene un resultado de inmediato, como se muestra a continuación:

## Referencias multimodales de personajes y audio/video (Seedance 2.0)

La **serie Seedance 2.0** (`doubao-seedance-2-0-260128`, `doubao-seedance-2-0-fast-260128`, `doubao-seedance-2-0-mini-260615`) admite `reference_image`, `reference_audio` y `reference_video`. Se pueden usar materiales propios o autorizados para mantener la coherencia de personajes, sujetos, movimientos, movimiento de cámara, sonido y ritmo.

> Sube únicamente materiales de personas reales y personajes que sean propios o estén autorizados. Los distintos modelos admiten los materiales de personas reales de maneras diferentes; el formato de la solicitud se mantiene sin cambios y se devolverá un error claro si el material no cumple los requisitos.

Puntos clave de uso:

- Solo los modelos de la **serie Seedance 2.0** admiten `reference_image`; para los modelos 1.x, utiliza `first_frame` / `last_frame` (primer y último fotograma de imagen a video).
- El primer fotograma de imagen a video, el primer y último fotograma de imagen a video y la referencia multimodal completa son tres escenarios mutuamente excluyentes: `first_frame` / `last_frame` no se pueden mezclar con `reference_image` / `reference_video` / `reference_audio`.
- Si deseas especificar el primer y último fotograma en la referencia multimodal completa, marca las imágenes como `reference_image` e indica en el prompt “imagen 1 como primer fotograma” o “imagen 2 como último fotograma”; si necesitas bloquear estrictamente el primer y último fotograma, utiliza únicamente `first_frame` / `last_frame`.
- Límite de cantidad de referencias multimodales: hasta **9** `image_url`; 2.0 también admite `audio_url` (`role` es `reference_audio`, hasta 3 elementos) y `video_url` (`role` es `reference_video`, hasta 3 elementos).
- **Requisitos del material de audio de referencia (`audio_url`)**: formatos `wav` / `mp3`; **duración por elemento de 2 a 15 segundos**, hasta 3 elementos y una **duración total de no más de 15 segundos**; cada elemento no debe superar los 15 MB. Superar el intervalo de duración provocará un error durante la fase de procesamiento del material.
- **Requisitos del material de video de referencia (`video_url`)**: formatos `mp4` / `mov`; **duración por elemento de 2 a 15 segundos**, hasta 3 elementos y una **duración total de no más de 15 segundos**.
- Se recomienda que las imágenes de referencia sean fotos de **una sola persona, de frente, nítidas y sin obstrucciones**; cuanto más claro sea el rostro, mayor será la similitud.

Pasa una foto de un rostro para que la persona sonría y salude a la cámara. El código correspondiente:

```python
    "content-type": "application/json"
}

    "model": "doubao-seedance-2-0-fast-260128",
    "content": [
        {
            "type": "text",
            "text": "The woman looks at the camera, gives a warm natural smile and waves her hand, soft studio lighting, gentle camera push-in."
        },
        {
            "type": "image_url",

    "resolution": "480p",
    "ratio": "9:16",
    "duration": 5
}

response = requests.post(url, json=payload, headers=headers)
```

## Devolución de llamada asíncrona

Dado que la API de generación de videos de SeeDance tarda bastante tiempo en generar (aproximadamente 1-2 minutos), puede usar el modo asíncrono mediante el campo `callback_url`, evitando que la conexión HTTP permanezca ocupada durante mucho tiempo.

Flujo general: el cliente especifica `callback_url` al iniciar la solicitud, la API devuelve inmediatamente una respuesta que contiene `task_id`; una vez completada la tarea, la plataforma envía el resultado generado a `callback_url` en forma de POST JSON, y el resultado también contiene `task_id` para facilitar la asociación.

```json
{
  "task_id": "f7096c6c-9430-4392-8201-d259632d7afd"
}
```

Cuando la tarea se completa, el contenido que la plataforma envía a `callback_url` es el siguiente:

```json
{
  "success": true,
  "task_id": "f7096c6c-9430-4392-8201-d259632d7afd",
  "trace_id": "4a4a3721-00fb-43d2-aff2-3b516ac01a8a",
  "data": {
    "task_id": "cgt-20251222073134-54qcw",
    "status": "succeeded",
    "video_url": "https://platform.cdn.acedata.cloud/seedance/95f9f5f0-fc50-4c71-bc6f-e154582c141e.mp4",

```

El campo `task_id` en el resultado es coherente con el devuelto al realizar la solicitud; mediante este campo se puede lograr la asociación de tareas.

## Manejo de errores

Al llamar a la API, si se produce un error, la API devolverá el código de error y la información correspondientes. Por ejemplo:

- `400 token_mismatched`：Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`：Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`：No autorizado, token de autorización no válido o faltante.
- `429 too_many_requests`：Demasiadas solicitudes, ha superado el límite de tasa.
- `500 api_error`：Error interno del servidor, algo salió mal en el servidor.

### Ejemplo de respuesta de error

```json
{
  "success": false,

  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"
}
```
