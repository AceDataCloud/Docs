La API de HappyHorse Tasks se utiliza para consultar las tareas de generación o edición de videos creadas con la API de HappyHorse Videos.

## Proceso de solicitud

Para usar la API de HappyHorse Videos, primero obtenga su Token API en la [Consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) para tenerlo a mano.

![](https://cdn.acedata.cloud/5hmkdg.jpg)

Si aún no ha iniciado sesión o registrado, se redirigirá automáticamente a la página de inicio de sesión para invitarlo a registrarse e iniciar sesión, y luego volverá automáticamente a esta página.

**Un solo Token API puede llamar a todos los servicios de la plataforma, no es necesario solicitar uno por cada servicio.** La primera solicitud incluye un crédito gratuito para probar; cuando el crédito se agote, puede recargar saldo general en la [Consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [HappyHorse Videos API →](https://platform.acedata.cloud/documents/happyhorse-videos)

## Ejemplo de solicitud

La API de HappyHorse Tasks se puede usar para consultar los resultados de la API de HappyHorse Videos.

### Configuración de encabezados y cuerpo de la solicitud

**Encabezados de la solicitud** incluyen:

- `accept`: especifica que se recibe la respuesta en formato JSON, aquí se pone `application/json`.
- `authorization`: la clave para llamar a la API, que puede seleccionarse directamente tras solicitarla.

**Cuerpo de la solicitud** incluye:

- `id`: el ID de la tarea a consultar.
- `action`: la acción sobre la tarea, para consulta individual se pone `retrieve`.

### Ejemplo de código CURL

```bash
curl -X POST 'https://api.acedata.cloud/happyhorse/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "action": "retrieve"
}'
```

### Ejemplo de respuesta

Tras una solicitud exitosa, la API devolverá los detalles de la tarea. El campo `request` es el cuerpo de la solicitud al crear la tarea, y el campo `response` es la respuesta devuelta tras completar la tarea, por ejemplo:

```json
{
  "id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
  "started_at": 1769262721.823,
  "finished_at": 1769262774.423,
  "elapsed": 52.6,
  "request": {
    "action": "generate",
    "model": "happyhorse-1.1-t2v",
    "prompt": "A cinematic shot of a white horse running across a moonlit beach",
    "resolution": "720P",
    "duration": 5
  },
  "type": "videos",
  "response": {
    "success": true,
    "task_id": "b8976e18-32dc-4718-9ed8-1ea090fcb6ea",
    "trace_id": "fb751e1e-4705-49ea-9fd4-5024b7865ea2",
    "data": [
      {
        "id": "1469cfc3-3004-4d9e-ab10-xxxxxx",
        "video_url": "https://cdn.acedata.cloud/happyhorse/c8cbf53aa0.mp4",
        "state": "succeeded",
        "duration": 5,
        "resolution": "720P",
        "ratio": "16:9"
      }
    ]
  }
}
```

Descripción de los campos:

- `id`: ID de la tarea generada, usado para identificarla de forma única.
- `request`: información de la solicitud al crear la tarea.
- `response`: información actual o final devuelta por la tarea.
- `created_at`: hora de creación de la tarea, timestamp Unix (segundos, flotante).
- `started_at`: hora de inicio de la tarea, timestamp Unix (segundos, flotante).
- `finished_at`: hora de finalización de la tarea, timestamp Unix (segundos, flotante). No se devuelve si la tarea no ha terminado.
- `elapsed`: tiempo de ejecución de la tarea en segundos (flotante, con 3 decimales). No se devuelve si la tarea no ha terminado.

## Consulta por lotes

Para consultar detalles de múltiples tareas, establezca `action` en `retrieve_batch` y pase un arreglo de IDs en `ids`:

```bash
curl -X POST 'https://api.acedata.cloud/happyhorse/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "ids": ["b8976e18-32dc-4718-9ed8-1ea090fcb6ea"],
  "action": "retrieve_batch"
}'
```

La respuesta incluirá los campos `items` y `count`, donde `items` es un arreglo con los detalles de las tareas y `count` es la cantidad de tareas coincidentes en esta consulta.
