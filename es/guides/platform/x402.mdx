X402 es un protocolo de pagos en cadena basado en HTTP `402 Payment Required`. Mediante la capacidad X402 de Ace Data Cloud, los solicitantes pueden completar pagos en cadena directamente con USDC en cada solicitud de API, sin crear un API Token ni recargar previamente el saldo de la cuenta.

Este conjunto de documentos está organizado según el orden real de integración: primero complete una solicitud mínima, luego integre el SDK y después comprenda las redes, los esquemas de facturación, el pago de pedidos y el Facilitator. Se recomienda leer de arriba abajo según la siguiente tabla.

## Ruta de integración recomendada

Si solo desea llamar a la API de Ace Data Cloud, priorice el uso del SDK oficial:

- TypeScript：`@acedatacloud/sdk` + `@acedatacloud/x402-client`
- Python：`acedatacloud` + `acedatacloud-x402`

Código fuente público y direcciones de paquetes:

| Proyecto                 | Dirección                                                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------------------------------------ |
| Ace Data Cloud SDK | [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)                                         |
| X402 Client        | [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)                           |
| X402 Facilitator   | [https://github.com/AceDataCloud/FacilitatorX402](https://github.com/AceDataCloud/FacilitatorX402)                 |
| npm SDK            | [https://www.npmjs.com/package/@acedatacloud/sdk](https://www.npmjs.com/package/@acedatacloud/sdk)                 |
| npm X402 Client    | [https://www.npmjs.com/package/@acedatacloud/x402-client](https://www.npmjs.com/package/@acedatacloud/x402-client) |
| PyPI SDK           | [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)                                   |
| PyPI X402 Client   | [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)                         |

El SDK completará automáticamente los pasos de la primera solicitud sin autenticación, el análisis de `402 Payment Required`, la llamada al payment handler y el reintento con `PAYMENT-SIGNATURE`. Solo necesita preparar una billetera con USDC y seleccionar la red que desea utilizar.

Si desea que su propia API también admita cobros con X402, deberá leer la documentación de Facilitator para comprender la relación entre `paymentRequirements`, `paymentPayload`, `/verify` y `/settle`.

## Consideraciones de integración

Al realizar la integración, los desarrolladores deben priorizar los requisitos de pago en tiempo real devueltos por la solicitud actual, en lugar de copiar los importes o direcciones de ejemplo de la documentación:

- `accepts[].maxAmountRequired` es el importe máximo que se puede firmar para la solicitud actual.
- `accepts[].asset` es el contrato o mint de USDC que se utilizará para esta solicitud.
- `accepts[].extra.chainId`, `accepts[].extra.facilitatorAddress` y `accepts[].extra.verifyingContract` participarán en la firma de datos tipados EVM.
- `upto` requiere que la billetera autorice primero Permit2 para USDC en la cadena de destino; si no está autorizado, devolverá `PERMIT2_ALLOWANCE_REQUIRED`.
- Si deseas explícitamente utilizar la medición posterior, pasa `preferScheme: 'upto'` en el SDK de TypeScript; de lo contrario, el SDK seleccionará el primer requirement disponible devuelto por el servidor en esa red.

## Alcance que se puede verificar públicamente

Antes de la integración, se pueden verificar primero estos puntos de acceso públicos y comportamientos del SDK:

- Las solicitudes de API sin `Authorization` ni `PAYMENT-SIGNATURE` devolverán `402 Payment Required`, y el `accepts` de la respuesta es la única base de firma para esta solicitud.
- Tanto el SDK de TypeScript como el SDK de Python proporcionan un payment handler; la capa de transporte del SDK llamará al handler y volverá a intentarlo una vez después de recibir un 402.
- `https://facilitator.acedata.cloud/.well-known/x402`: devuelve las redes, schemes y puntos de acceso de protocolo compatibles con el Facilitator; el precio de la API sigue estando sujeto al 402 devuelto en tiempo real por la solicitud de destino.
- `https://facilitator.acedata.cloud/supported`: devuelve las redes y schemes compatibles con el Facilitator.
- El repositorio X402Client incluye herramientas avanzadas de verificación en cadena, que pueden utilizarse para confirmar firmas, reintentos y comportamientos de settlement; la salida de las herramientas no sustituye al `accepts` devuelto por la API en línea.

`upto` pertenece al settlement de medición posterior y es adecuado para API cuyo uso real solo se conoce después de la respuesta, como completados de chat y llamadas a modelos. Actualmente, solo Base ofrece `upto`; si falla la verificación de la firma, comprueba que el chain id, la dirección del facilitator, el spender, el contrato USDC y el allowance de Permit2 coincidan con la respuesta 402.
