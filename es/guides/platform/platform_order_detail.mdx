title: "Obtener los detalles de un pedido de la plataforma AceDataCloud"

Consulta un pedido mediante el ID del pedido. Este endpoint admite dos modos de lectura: el acceso anónimo solo devuelve los campos mínimos necesarios para la página de pago; el propietario del pedido con un Account Token devuelve los detalles completos.

## Resumen de la API

| Elemento   | Contenido                                                        |
| --- | --------------------------------------------------------- |
| Método  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| Autenticación  | Opcional; anónimo para proyección mínima, propietario autenticado para proyección completa                                    |

`/orders/{id}` y `/orders/{id}/` están disponibles actualmente. El ID del pedido forma parte del enlace de pago y debe considerarse un identificador opaco sensible; no lo divulgue públicamente.

## Consulta anónima

La página de pago puede leerse directamente cuando se pierde la sesión de inicio:

```shell
export ORDER_ID='tu ID de pedido'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

La respuesta anónima solo contiene `id`, `description`, `price`, `state`, `pay_way`, `pay_url`, `expired_at`, `created_at`. No devuelve cuenta, Application, Package, identificadores internos de pago ni metadata.

## Consulta autenticada

```shell
export PLATFORM_TOKEN='tu token de cuenta'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

El propietario del pedido recibirá los detalles completos de Order, incluidos `application` / `applications`, `package` / `packages`, `bank_details`, `invoice_automation` y los campos del modelo. Si está autenticado pero no es el propietario del pedido, devuelve `403`; excepto los superadministradores.

## Campos clave

| Campo            | Descripción                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`, `Paid`, `Finished`, `Expired`, `Failed` o `Refunded` |
| `pay_way`     | Método de pago actual del pedido; el nombre del campo no es `payment_method`                             |
| `pay_url`     | Página de pago alojada o dirección de código QR, puede estar vacía                                           |
| `price`       | Importe final pagadero del pedido; el modelo de pedido actual no proporciona el campo `final_price`                         |
| `amount`      | Cantidad de cuota del paquete; visible solo en la respuesta completa autenticada                                            |
| `finished_at` | Hora de finalización del pedido; el nombre del campo no es `paid_at`                                      |

La respuesta completa puede incluir campos adicionales según el método de pago; el cliente debe leerlos según sea necesario y evitar siempre registrar metadata sensible de la respuesta completa.

## Manejo de errores

- `404`: el ID del pedido no existe.
- `403`: ha iniciado sesión, pero no es el propietario del pedido.
- Las solicitudes anónimas no devuelven `401`; solo obtienen la proyección pública mínima.

## Reversión de factura y nueva solicitud

Mediante `GET /api/v1/orders/{order_id}/invoice/` se puede leer la factura actual del pedido. Después de enviar la reversión automática, la factura sigue siendo `Issued`, y `red_state` indica el progreso de la reversión; un envío exitoso no equivale a que la reversión se haya completado. Mientras se espera la confirmación, se emite la factura roja o se archiva, el pedido no puede volver a solicitar una factura.

Cuando un administrador solicita una reversión debido a errores en la información de facturación, como el encabezado o el número de identificación fiscal, el motivo de la reversión es «error de facturación»; la reversión automática activada por el reembolso del pedido sigue utilizando «cancelación del servicio».

Después de que la factura roja se emita y archive correctamente, la factura original pasa a ser `Voided`, y solo entonces el pedido puede volver a solicitarse. La factura original puede consultarse en el historial de facturas. Si la reversión falla o el resultado está pendiente de verificación, el departamento financiero se encargará de la comprobación, y el pedido no eliminará anticipadamente la restricción de facturación. Las facturas emitidas manualmente deben primero anularse o revertirse en el sistema fiscal o de facturación, y luego ser confirmadas por el departamento financiero en la plataforma.
