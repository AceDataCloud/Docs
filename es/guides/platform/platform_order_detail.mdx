---
title: "Obtener los detalles de un pedido de la plataforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Consulta un pedido mediante el ID del pedido. Este endpoint admite dos modos de lectura: el acceso anónimo solo devuelve los campos mínimos requeridos por la página de pago; el propietario del pedido con un Account Token devuelve los detalles completos.

## Descripción general de la API

| Elemento   | Contenido                                                        |
| --- | --------------------------------------------------------- |
| Método  | `GET`                                                     |
| URL | `https://platform.acedata.cloud/api/v1/orders/{order_id}` |
| Autenticación  | Opcional; anónimo para proyección mínima, propietario autenticado para proyección completa                                    |

`/orders/{id}` y `/orders/{id}/` están actualmente disponibles. El ID del pedido es parte del enlace de pago y debe tratarse como un identificador opaco sensible, no lo difunda públicamente.

## Consulta anónima

La página de pago puede leerse directamente cuando se pierde el estado de inicio de sesión:

```shell
export ORDER_ID='tu ID de pedido'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json'
```

La respuesta anónima solo contiene `id`, `description`, `price`, `state`, `pay_way`, `pay_url`, `expired_at`, `created_at`. No devolverá cuenta, Application, Package, identificadores internos de pago ni metadata.

## Consulta autenticada

```shell
export PLATFORM_TOKEN='tu token de cuenta'
curl "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}" \
  -H 'Accept: application/json' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

El propietario del pedido recibirá los detalles completos de Order, incluidos `application` / `applications`, `package` / `packages`, `bank_details`, `invoice_automation` y los campos del modelo. Si está autenticado pero no es el propietario del pedido, devuelve `403`; excepto los superadministradores.

## Campos clave

| Campo            | Descripción                                                          |
| ------------- | ----------------------------------------------------------- |
| `state`       | `Pending`, `Paid`, `Finished`, `Expired`, `Failed` o `Refunded` |
| `pay_way`     | El método de pago actual del pedido; el nombre del campo no es `payment_method`                             |
| `pay_url`     | Página de pago alojada o dirección de código QR, puede estar vacía                                           |
| `price`       | El importe final a pagar del pedido; el modelo de pedido actual no proporciona el campo `final_price`                         |
| `amount`      | Cantidad de cuota del paquete; visible solo en la respuesta completa autenticada                                            |
| `finished_at` | Hora de finalización del pedido; el nombre del campo no es `paid_at`                                      |

La respuesta completa puede incluir campos adicionales según el método de pago; los clientes deben leerlos según sea necesario y siempre evitar registrar metadata sensible en la respuesta completa.

## Manejo de errores

- `404`: el ID del pedido no existe.
- `403`: ha iniciado sesión pero no es el propietario del pedido.
- Las solicitudes anónimas no devolverán `401`; solo obtienen la proyección pública mínima.
