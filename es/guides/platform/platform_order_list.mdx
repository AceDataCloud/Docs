---
title: "Obtener la lista de pedidos de la plataforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Devuelve de forma paginada los pedidos de recarga de la cuenta, adecuado para buscar ID de pedidos, ver el estado de pago y realizar conciliaciones.

## Preparación

Cree un [Account Token](https://platform.acedata.cloud/documents/platform-token) y obtenga el UUID de la cuenta actual desde `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='tu token de cuenta'
export USER_ID='tu UUID de cuenta'
```

## Resumen de la interfaz

| Elemento   | Contenido                                      |
| --- | ----------------------------------------------- |
| Método  | `GET`                                           |
| URL | `https://platform.acedata.cloud/api/v1/orders/` |
| Autenticación  | Account Token, el token OAuth requiere `orders:read`       |
| Paginación  | `count` + `items`                               |

Los usuarios normales deben pasar su propio `user_id`; de lo contrario, puede devolver `403` al encontrar objetos sin autorización durante la paginación.

## Parámetros de consulta

| Parámetro                    | Tipo       | Obligatorio     | Descripción                                                        |
| --------------------- | -------- | ------ | --------------------------------------------------------- |
| `user_id`             | UUID     | Obligatorio para usuarios normales | Cuenta a la que pertenece el pedido; admite parámetros repetidos                                             |
| `pay_way`             | string   | No      | Filtra por método de pago; admite valores repetidos o separados por comas                                        |
| `state`               | string   | No      | Filtra por estado; admite valores repetidos o separados por comas                                          |
| `created_at_from/to`  | datetime | No      | Rango de tiempo de creación                                                    |
| `finished_at_from/to` | datetime | No      | Rango de tiempo de finalización                                                    |
| `limit` / `offset`    | integer  | No      | Paginación                                                        |
| `ordering`            | string   | No      | `created_at`, `-created_at`, `finished_at` o `-finished_at` |

La lista actual no admite filtrado por `application_id`, `service_id`, `package_id`, `payment_method` o `tag`; el nombre del campo de método de pago es `pay_way`.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/orders/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'state=Paid,Finished' \
  --data-urlencode 'pay_way=Stripe' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Descripción de la respuesta

La respuesta es `{count, items}`. Los elementos de la lista en producción incluyen `id`, `user_id`, `application_id/application_ids`, `package_id/package_ids`, `price`, `amount`, `discount`, `remaining_amount`, `state`, `pay_way`, `pay_id`, `pay_url`, `finished_at`, `expired_at`, `invoice`, `metadata` y campos de tiempo.

- Los estados reales son `Pending`, `Paid`, `Finished`, `Expired`, `Failed`, `Refunded`; no existe `Cancelled`.
- Los nombres de campo son `pay_way`, `finished_at`, `discount` y `price`, no `payment_method`, `paid_at`, `discount_rate` ni `final_price`.
- `price` es el precio final registrado del pedido; la moneda y los detalles de liquidación pueden estar en metadata controlada, y no se pueden inferir por cuenta propia únicamente a partir del método de pago.
