---
title: "Obtener la lista de credenciales de API de la plataforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Enumera de forma paginada las credenciales de API de negocio. Esta respuesta actualmente contiene campos sensibles de credenciales Token o Identity, y debe procesarse únicamente en el servidor; está prohibido escribirlos en registros, plataformas de análisis, persistencia de frontend o repositorios públicos.

## Preparativos

Crea un [Account Token](https://platform.acedata.cloud/documents/platform-token) y obtén el UUID de la cuenta actual mediante `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='tu token de cuenta'
export USER_ID='tu UUID de cuenta'
```

## Descripción general de la interfaz

| Elemento   | Contenido                                                   |
| --- | ---------------------------------------------------- |
| Método  | `GET`                                                |
| URL | `https://platform.acedata.cloud/api/v1/credentials/` |
| Autenticación  | Account Token; el token OAuth requiere `credentials:read`       |
| Paginación  | `count` + `items`                                    |

Los usuarios normales deben pasar su propio `user_id` o un `application_id` autorizado; de lo contrario, puede devolver `403` al encontrar objetos sin autorización durante la paginación.

## Parámetros de consulta

| Parámetro                 | Tipo      | Obligatorio  | Descripción                             |
| ------------------ | ------- | --- | ------------------------------ |
| `user_id`          | string  | Según el escenario | Propietario de la credencial; admite parámetros repetidos                   |
| `application_id`   | UUID    | No   | Filtra por Application; admite parámetros repetidos        |
| `host`             | string  | No   | Filtra exactamente por host; admite parámetros repetidos             |
| `name`             | string  | No   | Filtra exactamente por nombre; admite parámetros repetidos                 |
| `granted`          | boolean | No   | `true` son credenciales otorgadas a otros, `false` son credenciales de uso propio |
| `limit` / `offset` | integer | No   | Paginación                             |
| `ordering`         | string  | No   | `created_at` o `-created_at`   |

`service_id`, `disabled` y `expired` actualmente no son parámetros de filtrado.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/credentials/' \
  --data-urlencode "user_id=${USER_ID}" \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Descripción de la respuesta

La respuesta verificada en línea es `{count, items}`. Cada elemento incluye `id`, `application_id`, `application`, `user_id`, `creator_id`, `name`, `type`, `limited_amount`, `used_amount`, `expired_at`, `allowed_api_ids`, `host`, `granted`, `granted_to_user_id`, `tags`, `metadata` y campos de tiempo, y devuelve `token` o `username/password` según el tipo.

> La respuesta actual de la lista devuelve valores sensibles completos. No los muestres en la consola del navegador ni en sistemas de recopilación, y tampoco dependas de recuperar texto sin cifrar mediante la lista; el cliente debe ser compatible con futuras estrategias de ocultación.
