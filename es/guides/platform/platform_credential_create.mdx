---
title: "Crear credenciales de API de la plataforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Crea credenciales de API de negocio para una Application. La respuesta de creación puede incluir un Token que puede llamar directamente a `https://api.acedata.cloud/**`, o el nombre de usuario/contraseña de credenciales de tipo Proxy; deben tratarse como secretos.

## Preparativos

1. Crea un [Account Token](https://platform.acedata.cloud/documents/platform-token).
2. Obtén el `application_id` que posees de la [lista de Applications](https://platform.acedata.cloud/documents/platform-application-list).

```shell
export PLATFORM_TOKEN='tu token de cuenta'
export APPLICATION_ID='tu ID de Application'
```

## Resumen de la interfaz

| Elemento    | Contenido                                            |
| ---- | ---------------------------------------------------- |
| Método   | `POST`                                               |
| URL  | `https://platform.acedata.cloud/api/v1/credentials/` |
| Autenticación   | Account Token, el token OAuth requiere `credentials:write`      |
| Body | JSON                                                 |

## Cuerpo de la solicitud

| Campo                  | Tipo              | Obligatorio  | Descripción                            |
| ------------------- | --------------- | --- | ----------------------------- |
| `application_id`    | UUID            | Sí   | Application de destino                |
| `name`              | string          | No   | Nombre para mostrar de la credencial                         |
| `limited_amount`    | number / null   | No   | Límite de uso por credencial; `null` indica que no se establece un límite independiente       |
| `expired_at`        | datetime / null | No   | Hora de expiración ISO 8601                 |
| `allowed_api_ids`   | UUID[] / null   | No   | Solo permite llamar a estas API; un arreglo vacío se normalizará como sin restricciones       |
| `host`              | string          | No   | Información de host de la credencial                    |
| `for_user_id`       | string          | No   | Se usa al emitir credenciales autorizadas para otro usuario como propietario de la Application |
| `tags` / `metadata` | array / object  | No   | Datos de extensión personalizados                       |

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/credentials/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"name\":\"production\",\"limited_amount\":50}"
```

## Descripción de la respuesta

Una respuesta exitosa devuelve `201` y un objeto Credential:

- Los servicios de tipo API/Agent suelen devolver `type=Token` y `token`;
- Los servicios de tipo Proxy suelen devolver `type=Identity` y `username` / `password`, y una Proxy Application solo permite una credencial;
- `id`, `user_id`, `creator_id`, `used_amount` y los campos de tiempo son generados por el servidor.

Las interfaces actuales de lista y detalle también devuelven las credenciales en texto plano, pero el cliente no debe depender de este comportamiento histórico. Guárdalas inmediatamente después de la creación y evita escribir la respuesta en los registros; las interfaces futuras podrían devolverlas enmascaradas.

## Manejo de errores

- `400`: Formato de campo incorrecto, `allowed_api_ids` desconocidos, la Proxy Application ya tiene una credencial u otras restricciones de creación.
- `401`: El Account Token no es válido.
- `403/404`: No tienes permiso para acceder a la Application de destino, o la Application/el usuario autorizado no existe.
