[Jan](https://jan.ai/) es un cliente de escritorio de IA de código abierto con prioridad offline, que puede ejecutar modelos tanto localmente como conectarse a endpoints compatibles con OpenAI mediante **Remote Engine**. Este artículo explica cómo conectar Ace Data Cloud.

## Proceso de solicitud

Para conectar Ace Data Cloud en Jan, primero ve a la [Consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications), obtén tu API Token y guárdalo para usarlo después.

![Obtener Ace Data Cloud API Key](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no has iniciado sesión o te has registrado, serás redirigido automáticamente a la página de inicio de sesión para invitarte a registrarte e iniciar sesión; después de iniciar sesión o registrarte, volverás automáticamente a la página actual.

En la primera solicitud se otorgará una cuota gratuita, con la que puedes probar gratuitamente los servicios de modelos de Ace Data Cloud.

## Descargar Jan

Ve al [sitio web oficial de Jan](https://jan.ai/) para descargar según tu plataforma (Windows, macOS, Linux). Para equipos Apple Silicon, descarga el paquete arm64 para obtener el mejor rendimiento.

## Configurar Ace Data Cloud

Jan divide los modelos en dos tipos: **Local Engine** (ejecución local) y **Remote Engine** (API de terceros). Ace Data Cloud utiliza el protocolo compatible con OpenAI y se conecta como Remote Engine.

Abre Jan, entra en **Settings → Model Providers**, busca la tarjeta **OpenAI** y edítala:

| Campo       | Valor                              | Descripción                       |
| -------- | ------------------------------ | ------------------------ |
| API Key  | Tu Ace Data Cloud Token        | El Token copiado desde la consola             |
| Base URL | `https://api.acedata.cloud/v1` | **Debe terminar en `/v1`, sin barra al final** |

> Que Base URL debe terminar en `/v1` es una convención explícita de la documentación oficial de Jan. Si no quieres sobrescribir la configuración original de OpenAI, puedes usar «+ Add Provider» para crear un nuevo Provider de tipo `openai-compatible` e introducir el mismo contenido.

![Interfaz de configuración para añadir AceDataCloud Provider en Jan](https://cdn.acedata.cloud/26017d28afa1.png)

Después de guardar el Provider personalizado, Jan intentará primero llamar a `{Base URL}/models` para obtener la lista de modelos. Si la versión actual o el endpoint no devuelve una lista disponible, haz clic en **+ Add Model** en la parte inferior de la misma página de edición para completar manualmente el ID del modelo. Después de añadirlo, el modelo aparecerá en el menú desplegable de la esquina superior izquierda y tendrá un icono de «Cloud» para distinguirlo de los modelos remotos / locales.

![Interfaz de gestión de modelos Provider de Jan](https://cdn.acedata.cloud/ae485550946c.png)

> `MODEL_ID` es un marcador de posición; ve al [catálogo de modelos](https://platform.acedata.cloud/models) para consultarlo y reemplázalo por el nombre del modelo objetivo; para una validación precisa, prevalece el valor de `id` en la respuesta de `/v1/models`. Este valor es el nombre del modelo utilizado por el parámetro API `model`, no el UUID del servicio o de la API.

## Seleccionar un modelo

El [catálogo de modelos](https://platform.acedata.cloud/models) se actualiza continuamente. Da prioridad a la lista de modelos cargada automáticamente por el cliente; si necesitas completarla manualmente, primero solicita `GET https://api.acedata.cloud/v1/models`, copia el valor de `id` del modelo objetivo desde el array `data` de la respuesta y, después, selecciona según las capacidades de contexto, imágenes y llamadas a herramientas compatibles con el cliente.

## Verificar la integración

Si no estás seguro de si el problema está en Jan o en la red, primero puedes usar curl para verificar directamente el endpoint (reemplaza `{token}` por tu Token):

```bash
curl -X POST 'https://api.acedata.cloud/v1/chat/completions' \
  -H 'Authorization: Bearer {token}' \
  -H 'Content-Type: application/json' \
  -d '{
    "model": "MODEL_ID",
    "messages": [{"role": "user", "content": "ping"}]
  }'
```

Que se devuelva un objeto `chat.completion` compatible con OpenAI indica que tanto el Token como el endpoint están listos; si se devuelve `HTTP 403 used_up`, significa que el Token es válido, pero el saldo es insuficiente; recarga saldo en la [consola](https://platform.acedata.cloud/console/applications).

## Avanzado: combinación local + nube

Jan incorpora un API Server local compatible con OpenAI que puede activarse (Settings → Local API Server); después de activarlo, escucha en `http://localhost:1337/v1/chat/completions` y ejecuta los modelos locales que hayas descargado. De esta forma, puedes apuntar Base URL a local en frameworks como LangChain / LlamaIndex para realizar depuración gratuita, y cambiar a los modelos remotos de Ace Data Cloud para tareas complejas. Al cambiar de modelo, el contexto de la conversación no se perderá.

## Preguntas frecuentes

### Aparece Connection error o 404

Normalmente se debe a que falta `/v1` en Base URL. Cámbialo a `https://api.acedata.cloud/v1` (debe terminar en `/v1` y no debe escribirse como `.../openai/v1`).

### Aparece 401 Unauthorized

Confirma que en API Key hayas pegado el Token de Ace Data Cloud (sin el prefijo `Bearer` y sin espacios adicionales), y que el saldo de la aplicación correspondiente sea suficiente.

### El modelo remoto no aparece en el menú desplegable

Primero haz clic en el botón de actualizar modelos para activar `/v1/models`; si el descubrimiento automático falla, añade manualmente con **+ Add Model** el valor `id` del modelo del catálogo sin modificarlo.

### ¿Se pueden subir imágenes para que el modelo las analice?

Sí, pero debes seleccionar un modelo que admita explícitamente entrada visual en el catálogo de modelos actual.
