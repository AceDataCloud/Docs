---
title: "Crear pedidos de recarga en la plataforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Crea pedidos pendientes de pago para una o más Applications. La creación escribirá el pedido, pero no completará el pago automáticamente; antes de pagar se debe verificar el `price`, el paquete y la Application en la respuesta.

## Preparativos

- Crea un [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Obtén el `application_id` de la [lista de Applications](https://platform.acedata.cloud/documents/platform-application-list).
- Selecciona de los `packages` en los [detalles del servicio](https://platform.acedata.cloud/documents/platform-service-detail) un `package_id` que coincida con el tipo de Application y que se pueda comprar.

```shell
export PLATFORM_TOKEN='tu token de cuenta'
export APPLICATION_ID='tu ID de Application'
export PACKAGE_ID='tu ID de Package'
```

## Resumen de la interfaz

| Elemento    | Contenido                                       |
| ---- | ----------------------------------------------- |
| Método   | `POST`                                          |
| URL  | `https://platform.acedata.cloud/api/v1/orders/` |
| Autenticación   | Account Token, el token OAuth requiere `orders:write`      |
| Body | JSON                                            |

## Cuerpo de la solicitud

Los pedidos de una sola Application utilizan `application_id` + `package_id`; los pedidos por lotes utilizan `application_ids` + `package_ids` con longitudes correspondientes. Los pedidos normales seleccionan el método de pago en la solicitud posterior `/pay/`. Los pedidos de compra dentro de la aplicación de iOS pasan `pay_way: "AppleIAP"` al crearse, y solo pueden seleccionar un paquete Usage con `metadata.apple_product_id` y `metadata.apple_price`. Las compras dentro de la aplicación de Apple utilizan precios preestablecidos independientes en dólares estadounidenses, sin acumular descuentos de membresía, descuentos por método de pago ni recargos del sitio; el importe del cobro en moneda local en otras regiones estará sujeto a la página de confirmación de pago de Apple.

```shell
curl -X POST 'https://platform.acedata.cloud/api/v1/orders/' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d "{\"application_id\":\"${APPLICATION_ID}\",\"package_id\":\"${PACKAGE_ID}\"}"
```

## Descripción de la respuesta

Cuando tiene éxito, devuelve `201` y el nuevo objeto Order. Los campos clave incluyen `id`, `price`, `discount`, `state`, `application_id/application_ids`, `package_id/package_ids`, `expired_at` y los campos de tiempo. Los nuevos pedidos normalmente están en `Pending`; a continuación, llama a [pagar pedido](https://platform.acedata.cloud/documents/platform-order-pay).

- `price` es el importe pagadero calculado por el servidor según el paquete, el recargo del sitio y los descuentos; no debe calcularse por el cliente.
- Cuando el servicio o tipo de Package no coincide con la Application, devuelve `400`.
- Los Packages gratuitos y administrados por el sistema no se pueden obtener por cuenta propia mediante la interfaz pública de pedidos.
- Se rechazará la creación de pedidos para Applications que no pertenezcan a la cuenta actual.
