Devuelve de forma paginada los puntos finales de API visibles en el sitio actual. Adecuado para buscar API por ruta de negocio, servicio o fase de publicación; si solo necesita la definición completa de una API, llame directamente a los [detalles de la API](https://platform.acedata.cloud/documents/platform-api-detail).

## Descripción general de la interfaz

| Elemento   | Contenido                                      |
| --- | --------------------------------------------- |
| Método  | `GET`                                         |
| URL | `https://platform.acedata.cloud/api/v1/apis/` |
| Autenticación  | Pública, no se requiere token de cuenta                                     |
| Paginación  | `count` + `items`                             |

## Parámetros de consulta

| Parámetro        | Tipo      | Obligatorio  | Descripción                    |
| --------- | ------- | --- | --------------------- |
| `path`    | string  | No   | Coincidencia exacta de `path` o `path2` |
| `service` | string  | No   | Alias o UUID del servicio       |
| `stage`   | string  | No   | Filtrar por fase de publicación; se pueden pasar múltiples valores repetidamente      |
| `limit`   | integer | No   | Número de elementos por página, máximo 100           |
| `offset`  | integer | No   | Desplazamiento de paginación                 |

`id`, `service_id` y `tag` actualmente no son parámetros de filtro de lista; pasarlos no producirá el efecto de filtrado correspondiente.

```shell
curl --get 'https://platform.acedata.cloud/api/v1/apis/' \
  --data-urlencode 'service=midjourney' \
  --data-urlencode 'stage=Production' \
  --data-urlencode 'limit=20' \
  -H 'Accept: application/json'
```

```python
import requests

response = requests.get(
    "https://platform.acedata.cloud/api/v1/apis/",
    params={"service": "midjourney", "limit": 20},
    timeout=30,
)
response.raise_for_status()
for api in response.json()["items"]:
    print(api["id"], api["method"], api["path"])
```

## Descripción de la respuesta

La respuesta en línea utiliza `{count, items}`. Cada elemento de la lista actualmente incluye los campos del modelo de API, así como:

- `document_id`: ID del documento de desarrollador asociado, puede estar vacío;
- `service_id` / `service`: ID y resumen del servicio principal, pueden estar vacíos;
- `definition`: definición de OpenAPI, puede ser grande;
- `method`, `path`, `path2`, `stage`, `cost`, `tags`, `metadata`, etc.

El serializador de lista actualmente incluye `definition`; al obtener el catálogo completo, debe paginar y establecer un tiempo de espera. Los campos pueden añadirse de manera compatible con versiones anteriores, y el cliente solo debe leer los campos necesarios.
