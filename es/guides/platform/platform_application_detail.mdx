Obtiene el estado completo de una única solicitud de servicio mediante el ID de Application; incluye campos adicionales como el objeto completo `service` (incluidos los paquetes `packages`) en comparación con la interfaz de lista, y es adecuado para la página de detalles.

> ℹ️ Esta interfaz pertenece a la **API de administración de la plataforma AceDataCloud**, con el prefijo unificado `https://platform.acedata.cloud/api/v1/`. Consulte el índice completo de interfaces en [Obtener la lista de documentos de la plataforma AceDataCloud](https://platform.acedata.cloud/documents/platform-document-list).

## Resumen de la interfaz

| Elemento   | Contenido                                                             |
| --- | --------------------------------------------------------------------- |
| Método  | `GET`                                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/{application_id}` |
| Autenticación  | ✅ Se requiere token de cuenta                                                              |

Actualmente, tanto `/applications/{id}` como `/applications/{id}/` están disponibles; los ejemplos utilizan de forma uniforme la versión sin barra final.

## Descripción de autenticación (cómo obtener el token de cuenta)

Encabezado de solicitud:

```http
Authorization: Bearer ${PLATFORM_TOKEN}
```

Consulte el método detallado de obtención en [Administrar el token de cuenta de la plataforma AceDataCloud](https://platform.acedata.cloud/documents/platform-token).

> ℹ️ A diferencia de la interfaz de lista, **la comprobación de permisos de la interfaz de detalles se realiza directamente sobre un único objeto**, sin necesidad de pasar `?user_id=`. Sin embargo, si accede a la solicitud de otra persona, recibirá `403 permission_denied`.

## Parámetros de ruta

| Parámetro               | Tipo   | Obligatorio  | Descripción             |
| ---------------- | ---- | --- | -------------- |
| `application_id` | UUID | ✅   | ID de Application |

## Ejemplos de solicitud

### cURL

```shell
curl 'https://platform.acedata.cloud/api/v1/applications/82f57141-2323-4453-8730-60f7d833a2da' \
  -H 'accept: application/json' \
  -H "authorization: Bearer ${PLATFORM_TOKEN}"
```

### Python

```python
import os
import requests

app_id = "82f57141-2323-4453-8730-60f7d833a2da"
resp = requests.get(
    f"https://platform.acedata.cloud/api/v1/applications/{app_id}",
    headers={
        "accept": "application/json",
        "authorization": f"Bearer {os.environ['PLATFORM_TOKEN']}",
    },
    timeout=10,
)
app = resp.json()
print(f"服务：{app['service']['title']}")
print(f"剩余 {app['remaining_amount']} {app['service']['unit']} / 已用 {app['used_amount']}")
```

### Node.js

```javascript
const appId = '82f57141-2323-4453-8730-60f7d833a2da'
const r = await fetch(`https://platform.acedata.cloud/api/v1/applications/${appId}`, {
  headers: { authorization: `Bearer ${process.env.PLATFORM_TOKEN}` },
})
console.log(await r.json())
```

## Descripción de los campos de respuesta

El significado de los campos es el mismo que en la [interfaz de lista](https://platform.acedata.cloud/documents/platform-application-list), e incluye adicionalmente:

| Campo        | Tipo     | Descripción                                                        |
| --------- | ------ | --------------------------------------------------------- |
| `service` | object | Objeto de servicio completo (incluidos los paquetes `packages`, `unit` y `free_amount`), que puede renderizar directamente el panel de detalles del servicio |

## Manejo de errores

| HTTP | code                | Significado                  |
| ---- | ------------------- | ------------------- |
| 401  | `not_authenticated` | Falta el token de cuenta              |
| 403  | `permission_denied` | Esta Application no te pertenece  |
| 404  | `not_found`         | La Application no existe o ha sido eliminada |

## Consejos prácticos

- **Para la monitorización por lotes, priorice el uso de la lista**: después de obtener la lista de Applications de una vez, determine según la unidad y el umbral de cada servicio, para evitar solicitar los detalles uno por uno.
- **Cuando necesite consultar la cantidad de credenciales**: utilice la [lista de credenciales de API](https://platform.acedata.cloud/documents/platform-credential-list) y filtre por `application_id`.
- **Idea para investigar `disabled=true`**: revise los tickets / notificaciones por correo electrónico para comprobar si se suspendió debido a control de riesgos, pagos pendientes o llamadas infractoras; no puede habilitarse mediante la API, debe contactar con el servicio de atención al cliente.
