El SDK de Python es adecuado para servicios de backend, tareas de datos, Agent de automatización y scripts de procesamiento por lotes. `acedatacloud` se encarga de las llamadas a la API, y `acedatacloud-x402` se encarga de firmar el encabezado de solicitud `PAYMENT-SIGNATURE`.

Código fuente y direcciones de los paquetes:

- Repositorio del SDK: [https://github.com/AceDataCloud/SDK](https://github.com/AceDataCloud/SDK)
- Repositorio de X402 Client: [https://github.com/AceDataCloud/X402Client](https://github.com/AceDataCloud/X402Client)
- SDK en PyPI: [https://pypi.org/project/acedatacloud/](https://pypi.org/project/acedatacloud/)
- X402 Client en PyPI: [https://pypi.org/project/acedatacloud-x402/](https://pypi.org/project/acedatacloud-x402/)

## Instalar dependencias

```bash
pip install acedatacloud acedatacloud-x402
```

Si se desea utilizar `upto`, también es necesario llamar una vez al CLI de approve de Permit2, y este CLI depende de `web3`:

```bash
pip install 'acedatacloud-x402[cli]'
```

Salida de la comprobación de instalación e importación en un Python venv limpio:

```text
acedatacloud 2026.4.26.1
acedatacloud-x402 2026.5.31.3
imports_ok True True True True True True
usage: acedatacloud-x402 [-h] {approve-permit2} ...
approve-permit2  One-time ERC-20 approve(Permit2, amount) needed before signing upto payments.
```

Explicación de los resultados:

- Tanto `acedatacloud` como `acedatacloud-x402` se pueden instalar e importar desde PyPI.
- `pip install 'acedatacloud-x402[cli]'` incluirá el CLI `approve-permit2`, utilizado para la autorización previa de `upto`.

## Ejemplo de Base

El siguiente ejemplo no requiere un API Token. La clave privada de la billetera solo firma localmente y no se enviará a Ace Data Cloud.

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)

print(res["choices"][0]["message"]["content"])
```

Actualmente, el SDK de Python devuelve un `dict`, por lo que el ejemplo utiliza `res["choices"][0]["message"]["content"]`. No asuma directamente que necesariamente tiene una propiedad `.choices`.

## Ejemplo de Solana

Solana utiliza una secret key codificada en base58:

```python
import os

from acedatacloud import AceDataCloud
from acedatacloud_x402 import SolanaKeypairSigner, create_x402_payment_handler

client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="solana",
        solana_signer=SolanaKeypairSigner.from_base58(os.environ["SOLANA_SECRET_KEY"]),
    )
)

res = client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

La ruta de Solana construirá y enviará una transacción SPL USDC `TransferChecked`, y luego colocará la firma de la transacción en el envelope `PAYMENT-SIGNATURE`.

El paid retry de Solana ya devolvió HTTP 200 y `ADC_SOLANA_E2E_OK` en la API de producción. Esta consulta pública de RPC encontró limitación de tasa y no confirmó de forma estable la signature en cadena; si se necesita conciliar, utilice su propio RPC de Solana para consultar esta transacción.

## Cliente Async

El mismo payment handler puede utilizarse para `AsyncAceDataCloud`:

```python
import os

from acedatacloud import AsyncAceDataCloud
from acedatacloud_x402 import EVMAccountSigner, create_x402_payment_handler

signer = EVMAccountSigner.from_private_key(os.environ["EVM_PRIVATE_KEY"])

client = AsyncAceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
    )
)

res = await client.openai.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Say hi in 3 words"}],
    max_tokens=10,
)
```

## Usar la medición posterior `upto`

El costo real de API como las completions de chat y las llamadas a modelos puede conocerse solo después de que termine la respuesta. En este momento, la API puede devolver simultáneamente `exact` y `upto`. Si desea priorizar el uso de `upto`:

```python
client = AceDataCloud(
    payment_handler=create_x402_payment_handler(
        network="base",
        evm_signer=signer,
        prefer_scheme="upto",
    )
)
```

Resultado de ejecución del programa `upto` de Base:

```text
payer 0x5d4f08D5c2bb60703284bc06671Eb680fA41B105
elapsed_ms 5104
content ADC_BASE_UPTO_OK
id chatcmpl-DlcbyS4IT8kUAMo4Ri97HiIHc9T8V
settlement tx 0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
settled value 3 atomic USDC
```

Confirmación en cadena:

```text
explorer https://basescan.org/tx/0x4b0b836ce1cd1171cdbc37df1637150b024214ec28e7f6f2d09122f15cbfc036
block 46726437
transfer value 3 atomic USDC
```

Explicación de los resultados:

- `content ADC_BASE_UPTO_OK` indica que la solicitud realmente entró en la API del modelo.
- `settled value 3 atomic USDC` indica que `upto` se liquida según el uso real, en lugar de cobrar el límite máximo completo.
- `settlement tx` puede abrirse en BaseScan; al conciliar, guarde el tx hash, payer, completion id y el resumen de la solicitud.

`upto` utiliza Permit2 para autorizar un límite máximo, y el importe de liquidación real no puede superar dicho límite. Antes del primer uso, es necesario realizar una vez `approve(Permit2, amount)` para USDC en la cadena de destino.

Método CLI:

```bash
X402_PRIVATE_KEY=0x... acedatacloud-x402 approve-permit2 --network base
```

Método programático:

```python
from acedatacloud_x402 import EVMAccountSigner, approve_permit2

approve_permit2(
    rpc_url="https://mainnet.base.org",
    signer=EVMAccountSigner.from_private_key("0x..."),
    token_address="0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913",
)
```

Este helper es idempotente. Si el allowance ya es suficiente, devolverá `{"skipped": true}` y no enviará repetidamente transacciones en cadena.

## Firma de bajo nivel

Si no utiliza el SDK, también puede llamar directamente a la función de firma de bajo nivel:

```python
import base64
import json

from acedatacloud_x402 import EVMAccountSigner, sign_evm_payment

envelope = sign_evm_payment(requirement, EVMAccountSigner.from_private_key("0x..."))
x_payment = base64.b64encode(json.dumps(envelope, separators=(",", ":")).encode()).decode()
```

Las funciones de bajo nivel son adecuadas para pruebas, capas de proxy, integración de gateways o SDK no oficiales. El código de negocio común debe priorizar el uso de `create_x402_payment_handler`.
