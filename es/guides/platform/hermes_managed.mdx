Crea una instancia de contenedor Hermes independiente para cada Application. De forma predeterminada, se utiliza una imagen base de una versión de lanzamiento fija, conservando las funciones nativas; la plataforma proporciona compra, renovación, almacenamiento persistente y gestión de despliegue.

## Creación y compra

1. Abre [Despliegue de Hermes](https://platform.acedata.cloud/services/hermes) y crea una Application.
2. En la página de compra, selecciona un plan de duración y completa el pago.
3. Regresa a la página de configuración, donde puedes seleccionar un modelo de chat de la plataforma desde la lista desplegable y consultar el precio actual del modelo. La plataforma creará credenciales de API independientes para esta instancia; también puedes desactivar el acceso de la plataforma y configurarlo tú mismo en la consola nativa.
4. Elige generar automáticamente las credenciales de acceso o establece tu propia contraseña/Token seguro, y comienza el despliegue tras confirmar. Las credenciales de acceso y las credenciales de API del modelo son independientes entre sí.
5. Cuando la instancia esté lista, obtén la dirección de acceso y las credenciales de inicio de sesión desde la página de administración.
6. Inicia sesión en la consola nativa y configura tus propios proveedores de modelos, claves y canales.

La tarifa de despliegue se cobra según la duración del plan; los precios específicos en dólares estadounidenses y las duraciones estarán sujetos a la página de compra. Los costos de invocación de modelos se cobran por separado; comprar tiempo de despliegue no incluye crédito de modelo. Cuando se habilita el acceso de la plataforma, las credenciales de API dedicadas solo habilitan la interfaz de chat correspondiente al modelo seleccionado, y las invocaciones se cobran adicionalmente de tu saldo de plataforma. Cada Application se compra, renueva y administra por separado.

## Contraseñas, credenciales y configuración posterior

Las credenciales de acceso se establecen antes del primer inicio. La generación automática utiliza credenciales aleatorias; la contraseña personalizada debe tener al menos 16 caracteres y el Token de OpenClaw al menos 32 caracteres. Los borradores no guardan contraseñas; es posible que debas volver a introducirlas después de cambiar de página. Tras el despliegue, solo el propietario y los administradores de la Application pueden ver las credenciales de acceso.

Las credenciales de API de modelo de cada instancia no se reutilizan entre sí, su período de validez se extiende con la renovación del despliegue y se revocan al eliminar la instancia. Después de la inicialización del despliegue, modifica los modelos y canales en la consola nativa; si cambias para seleccionar modelos de otros servicios, ajusta primero la autorización de la interfaz correspondiente en la gestión de credenciales de la plataforma, o utiliza las credenciales correspondientes. Un redespliegue normal no sobrescribirá la configuración nativa. Los entornos de despliegue que no hayan superado la validación de publicación rechazarán temporalmente nuevos despliegues; contacta con soporte.

## Versiones y datos

La página de configuración muestra la versión de imagen publicada actualmente. Las nuevas instancias utilizan la versión publicada actual del servicio; las instancias existentes no se reemplazarán automáticamente con las actualizaciones del catálogo. El redespliegue aplicará la versión actual del servicio; realiza primero una copia de seguridad y confirma los requisitos de actualización de la versión utilizada.

Cada instancia proporciona de forma predeterminada 1 CPU, un límite de memoria de 2 GiB y 10 GiB de almacenamiento persistente. Los reinicios conservan los datos de la instancia. La eliminación activa del despliegue o la recuperación tras el vencimiento eliminarán el almacenamiento; exporta con antelación los datos que necesites conservar.

## Renovación y vencimiento

Renueva en la página de compra de la Application actual; el período de validez se extenderá según las reglas de duración vigentes de la plataforma. Tras el vencimiento, el acceso se suspende; renovar durante el período de gracia restablece el acceso. Si se supera el período de gracia, la instancia y los datos se recuperarán. Prevalecerán la hora de vencimiento, el estado de facturación y los avisos de eliminación de la página de administración.

## Inicio de sesión en la interfaz de administración

En la página de gestión del despliegue, copia la dirección del Dashboard, el nombre de usuario `admin` y la contraseña, y ábrela para iniciar sesión. La información de inicio de sesión solo se proporciona al propietario de esa Application y a los administradores de la plataforma. Los modelos, habilidades y canales se configuran en la interfaz nativa de Hermes.

## Preguntas frecuentes

- **¿Por qué la nueva instancia aún no puede responder?** La finalización del despliegue significa que el contenedor está listo; debes configurar el modelo y las credenciales en la interfaz nativa antes de poder empezar a utilizarlo.
- **¿Se preinstalan complementos adicionales o fallback de modelos?** No se añaden de forma predeterminada; configúralos según sea necesario en la interfaz nativa.
- **¿Cómo se actualiza una instancia existente?** La Application y el pedido originales se conservan, y se utiliza la versión actual del servicio al redesplegar; realiza primero una copia de seguridad de los datos y comprueba la compatibilidad de versiones antes de actualizar.
- **¿Qué hacer si el inicio falla?** Primero consulta los registros y eventos del despliegue, y configura el modelo después de confirmar que la instancia está lista. No expongas las contraseñas y claves de la instancia en comentarios públicos o capturas de pantalla.
