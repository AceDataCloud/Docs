Crear una instancia de contenedor Hermes independiente para cada Application. Por defecto se utiliza una imagen base de versión de lanzamiento fija, conservando las funciones nativas; la plataforma proporciona compra, renovación, almacenamiento persistente y gestión de despliegue.

## Creación y compra

1. Abre [Despliegue de Hermes](https://platform.acedata.cloud/services/hermes) y crea una Application.
2. En la página de compra, selecciona un plan de duración y completa el pago.
3. Regresa a la página de configuración, donde puedes seleccionar un modelo de chat de la plataforma desde la lista desplegable y consultar el precio actual del modelo. La plataforma creará credenciales de API independientes para esta instancia; también puedes desactivar el acceso de la plataforma y configurarlo tú mismo en la consola nativa.
4. Elige generar automáticamente las credenciales de acceso o establece tu propia contraseña segura/Token; marca A2A y EnvarPay según sea necesario, y comienza el despliegue tras confirmar. Las credenciales de acceso y las credenciales de API del modelo son independientes entre sí.
5. Cuando la instancia esté lista, obtén la dirección de acceso y las credenciales de inicio de sesión desde la página de administración.
6. Inicia sesión en la consola nativa para configurar los canales. Si desactivaste el acceso al modelo de la plataforma durante el despliegue, también debes configurar tú mismo el proveedor de modelos y las credenciales para poder usar el chat.

La tarifa de despliegue se cobra según la duración del plan; los precios concretos en dólares estadounidenses y las duraciones se rigen por la página de compra. Los costos de llamadas al modelo se cobran por separado; comprar tiempo de despliegue no incluye créditos de modelo. Cuando se habilita el acceso de la plataforma, las credenciales de API dedicadas solo habilitan la interfaz de chat correspondiente al modelo seleccionado, y las llamadas se cobran adicionalmente desde el saldo de tu plataforma. Cada Application se compra, renueva y administra por separado.

## Contraseñas, credenciales y configuración posterior

Las credenciales de acceso se configuran antes del primer inicio. La generación automática utiliza credenciales aleatorias, las contraseñas personalizadas deben tener al menos 16 caracteres y los Tokens de OpenClaw al menos 32 caracteres. Los borradores no guardan contraseñas; es posible que debas introducirlas de nuevo después de cambiar de página. Después del despliegue, solo el propietario y los administradores de la Application pueden ver las credenciales de acceso.

Las credenciales de API del modelo de cada instancia no se reutilizan entre sí, extienden su vigencia con la renovación del despliegue y se revocan al eliminar la instancia. Si no conectaste un modelo de la plataforma durante el primer despliegue, puedes seleccionar un modelo de la plataforma en la página de configuración de esa Application y volver a desplegar; la plataforma actualizará el modelo predeterminado y conservará las conversaciones y otras configuraciones nativas. Después, modifica los modelos y canales en la consola nativa; si cambias a un modelo de otro servicio, primero ajusta la autorización de la interfaz correspondiente en la gestión de credenciales de la plataforma, o utiliza las credenciales correspondientes. Un redespliegue normal no sobrescribirá las configuraciones nativas. Los entornos de despliegue que no hayan superado la validación de publicación rechazarán temporalmente nuevos despliegues; contacta con soporte.

## Componentes de despliegue opcionales

Después de marcar A2A, la plantilla de despliegue iniciará la puerta de enlace A2A nativa de Hermes y proporcionará un token de propietario en la página de administración. Marcar EnvarPay instalará adicionalmente un contenedor de servicio independiente y un libro mayor persistente, y requiere habilitar primero A2A. Inicialmente, EnvarPay solo tiene credenciales de acceso de propietario, sin servicio ni identidad de cobro, y no cobrará ni realizará compras en tu nombre automáticamente. Ninguna de las dos opciones registrará automáticamente la instancia en Envar; las instancias existentes pueden acceder a la configuración desde la página de administración y volver a desplegar después de habilitarlas. Los componentes ya habilitados todavía no se pueden desactivar en este asistente.

## Versión y datos

La página de configuración muestra la versión de imagen publicada actualmente. Las nuevas instancias utilizan la versión actualmente publicada del servicio; las instancias existentes no se reemplazarán automáticamente con las actualizaciones del catálogo. El redespliegue aplicará la versión actual del servicio; realiza primero una copia de seguridad y confirma los requisitos de actualización de la versión utilizada.

Cada instancia proporciona por defecto 1 CPU, un límite de 2 GiB de memoria y 10 GiB de almacenamiento persistente. Los reinicios conservan los datos de la instancia. La eliminación activa del despliegue o la recuperación al vencimiento eliminarán el almacenamiento; exporta con antelación los datos que necesites conservar.

## Renovación y vencimiento

Renueva en la página de compra de la Application actual; el período de validez se extenderá conforme a las reglas de duración existentes de la plataforma. Tras el vencimiento, el punto de acceso se suspende y la renovación durante el período de gracia restaura el acceso; una vez superado el período de gracia, se recuperarán la instancia y los datos. Prevalecen la hora de vencimiento, el estado de facturación y los avisos de eliminación de la página de administración.

## Inicio de sesión en la interfaz de administración

En la página de administración del despliegue, copia la dirección del Dashboard, el nombre de usuario `admin` y la contraseña, y abre la dirección para iniciar sesión. La información de inicio de sesión solo se proporciona al propietario de esa Application y a los administradores de la plataforma. Los modelos, habilidades y canales se configuran en la interfaz nativa de Hermes.

## Preguntas frecuentes

- **¿Por qué la nueva instancia aún no puede responder?** La finalización del despliegue solo indica que el contenedor está listo. Si desactivaste el acceso al modelo de la plataforma durante el despliegue, debes seleccionar un modelo de la plataforma en la página de configuración y volver a desplegar, o configurar tú mismo el modelo y las credenciales en la interfaz nativa.
- **¿Se preinstalan plugins adicionales o fallback de modelos?** No se añaden por defecto; configúralos según sea necesario en la interfaz nativa.
- **¿Cómo se actualizan las instancias existentes?** La Application y el pedido originales se conservan, y se utiliza la versión actual del servicio al volver a desplegar; antes de actualizar, realiza una copia de seguridad de los datos y comprueba la compatibilidad de versiones.
- **¿Qué hacer si falla el inicio?** Primero consulta los registros y eventos del despliegue, y configura el modelo después de confirmar que la instancia está lista. No expongas la contraseña y las claves de la instancia en comentarios públicos o capturas de pantalla.
