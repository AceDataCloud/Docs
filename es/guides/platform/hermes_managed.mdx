Cree una instancia de contenedor Hermes independiente para cada Application. De forma predeterminada se utiliza una imagen base de versión de lanzamiento fija, conservando las funciones nativas; la plataforma proporciona compra, renovación, almacenamiento persistente y gestión de despliegues.

## Creación y compra

1. Abra [Despliegue de Hermes](https://platform.acedata.cloud/services/hermes) y cree una Application.
2. En la página de compra, seleccione un plan de duración y complete el pago.
3. Regrese a la página de configuración, donde puede seleccionar un modelo de chat de la plataforma desde la lista desplegable y consultar el precio actual del modelo. La plataforma creará credenciales de API independientes para esta instancia; también puede desactivar la integración de la plataforma y configurarla usted mismo en la consola nativa.
4. Elija generar automáticamente las credenciales de acceso, o establezca su propia contraseña/Token seguro; marque A2A y EnvarPay según sea necesario, y confirme para iniciar el despliegue. Las credenciales de acceso y las credenciales de API del modelo son independientes entre sí.
5. Una vez que la instancia esté lista, obtenga la dirección de acceso y las credenciales de inicio de sesión desde la página de administración.
6. Inicie sesión en la consola nativa para configurar los canales. Si desactivó la integración de modelos de la plataforma durante el despliegue, también deberá configurar usted mismo el proveedor del modelo y las credenciales para poder utilizar el chat.

La tarifa de despliegue se cobra según la duración del plan; los precios específicos en dólares estadounidenses y las duraciones estarán sujetos a la página de compra. Los costos de llamada al modelo se cobran por separado; comprar tiempo de despliegue no otorga créditos de modelo. Al activar la integración de la plataforma, las credenciales de API exclusivas solo habilitan la interfaz de chat correspondiente al modelo seleccionado, y las llamadas se cobran por separado de su saldo de la plataforma. Cada Application se compra, renueva y administra por separado.

## Contraseñas, credenciales y configuración posterior

Las credenciales de acceso se configuran antes del primer inicio. El método de generación automática utiliza credenciales aleatorias, las contraseñas personalizadas deben tener al menos 16 caracteres y los Tokens de OpenClaw deben tener al menos 32 caracteres. Los borradores no guardan contraseñas; es posible que deba volver a ingresarlas después de cambiar de página. Tras el despliegue, solo el propietario y los administradores de la Application pueden ver las credenciales de acceso.

Las credenciales de API del modelo de cada instancia no se reutilizan entre sí, su validez se extiende con la renovación del despliegue y se revocan al eliminar la instancia. Si no conectó un modelo de la plataforma durante el primer despliegue, puede seleccionar un modelo de la plataforma en la página de configuración de esa Application y volver a desplegar; la plataforma actualizará el modelo predeterminado, conservando las conversaciones y otras configuraciones nativas. Posteriormente, modifique los modelos y los canales en la consola nativa; si cambia a un modelo de otro servicio, ajuste primero la autorización de la interfaz correspondiente en la gestión de credenciales de la plataforma, o utilice las credenciales correspondientes. Un redespliegue normal no sobrescribirá la configuración nativa. Los entornos de despliegue que no hayan superado la validación de publicación rechazarán temporalmente nuevos despliegues; póngase en contacto con soporte.

## Componentes de despliegue opcionales

Después de marcar A2A, la plantilla de despliegue iniciará la puerta de enlace A2A nativa de Hermes y proporcionará un token de propietario en la página de administración. Al marcar EnvarPay, se instalarán adicionalmente un contenedor de servicio independiente y un libro mayor persistente; primero debe activar A2A. Inicialmente, EnvarPay solo tiene credenciales de acceso de propietario, no tiene servicio ni identidad de cobro, y no cobrará ni realizará compras automáticamente. Ninguna de las dos opciones registrará automáticamente la instancia en Envar; las instancias existentes pueden acceder a la configuración desde la página de administración, activarla y volver a desplegar. Los componentes activados todavía no se pueden desactivar en este asistente.

Después de activar A2A y de que la instancia esté lista, la tarjeta de dirección de acceso en la página de administración mostrará una dirección de Agent Card que se puede copiar. La A2A nativa de Hermes utiliza una dirección pública independiente; la dirección de inicio de sesión de Dashboard no se puede utilizar como dirección de Agent Card. Si también activa EnvarPay, la página de administración mostrará además la correspondiente «dirección de integración de Envar»; al integrarse con el servicio Envar, copie preferentemente esta URL.

## Versiones y datos

La página de configuración muestra la versión de imagen actualmente publicada. Las instancias nuevas utilizan la versión actualmente publicada del servicio; las instancias existentes no se reemplazarán automáticamente con las actualizaciones del catálogo. El redespliegue aplicará la versión actual del servicio; haga una copia de seguridad primero y confirme los requisitos de actualización de la versión utilizada.

Cada instancia proporciona de forma predeterminada 1 CPU, un límite de 2 GiB de memoria y 10 GiB de almacenamiento persistente. Los reinicios conservan los datos de la instancia. La eliminación activa del despliegue o la recuperación al vencimiento eliminarán el almacenamiento; exporte con antelación los datos que necesite conservar.

## Renovación y vencimiento

Renueve en la página de compra de la Application actual; el período de validez se extenderá según las reglas de duración actuales de la plataforma. Tras el vencimiento, se suspende el acceso; renovar durante el período de gracia restablece el acceso; después del período de gracia, se recuperarán la instancia y los datos. Prevalecerán la hora de vencimiento, el estado de facturación y los avisos de eliminación de la página de administración.

## Inicio de sesión en la interfaz de administración

En la página de administración del despliegue, copie la dirección de Dashboard, el nombre de usuario `admin` y la contraseña, y abra la dirección para iniciar sesión. La información de inicio de sesión solo se proporciona al propietario de esa Application y a los administradores de la plataforma. Los modelos, las habilidades y los canales se configuran en la interfaz nativa de Hermes.

## Preguntas frecuentes

- **¿Por qué la nueva instancia todavía no puede responder?** Que el despliegue se haya completado solo significa que el contenedor está listo. Si desactivó la integración de modelos de la plataforma durante el despliegue, debe seleccionar un modelo de la plataforma en la página de configuración y volver a desplegar, o configurar usted mismo el modelo y las credenciales en la interfaz nativa.
- **¿Se preinstalan complementos adicionales o fallback de modelos?** No se añaden de forma predeterminada; configúrelos según sea necesario en la interfaz nativa.
- **¿Cómo se actualizan las instancias existentes?** La Application y el pedido originales se conservan, y se utiliza la versión actual del servicio al volver a desplegar; antes de actualizar, haga una copia de seguridad de los datos y compruebe la compatibilidad de la versión.
- **¿Qué hacer si falla el inicio?** Primero consulte los registros y eventos del despliegue, y configure el modelo después de confirmar que la instancia está lista. No exponga contraseñas ni claves de la instancia en comentarios públicos o capturas de pantalla.
