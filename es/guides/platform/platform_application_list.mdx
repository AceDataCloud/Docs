---
title: "Obtener la lista de solicitudes de servicio de la plataforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Devuelve de forma paginada las Application que la cuenta posee o está autorizada a usar, incluidos el saldo, estado, resumen del servicio y credenciales asociadas. Adecuado para la monitorización masiva de saldos, buscar Application ID y acceder a la gestión de credenciales.

## Preparación

1. Inicie sesión en la [plataforma AceDataCloud](https://platform.acedata.cloud).
2. Cree un token de cuenta en la [consola de Account Token](https://platform.acedata.cloud/console/platform-tokens).
3. Los usuarios normales usan `user_id=me`; también puede obtener su propio UUID desde `GET /api/v1/platform-tokens/me/`.

```shell
export PLATFORM_TOKEN='tu token de cuenta'
```

## Resumen de la interfaz

| Elemento   | Contenido                                                    |
| --- | ----------------------------------------------------- |
| Método  | `GET`                                                 |
| URL | `https://platform.acedata.cloud/api/v1/applications/` |
| Autenticación  | Account Token, el token OAuth requiere `applications:read`       |
| Paginación  | `count` + `items`                                     |

Los usuarios normales deben pasar `user_id=me`. Si no se pasa, la consulta no se restringe primero por cuenta, y la paginación puede devolver `403` al encontrar objetos sin autorización; los administradores pueden ver la tabla completa si no lo pasan.

## Parámetros de consulta

| Parámetro            | Tipo          | Obligatorio     | Descripción                                                  |
| ------------- | ----------- | ------ | --------------------------------------------------- |
| `user_id`     | UUID / `me` | Obligatorio para usuarios normales | Sujeto de la consulta; admite parámetros repetidos                                         |
| `affiliation` | string      | No      | `owner` (predeterminado) o `granted`; se pueden pasar ambos repetidamente para obtener la unión, solo tiene efecto cuando hay `user_id` |
| `service_id`  | UUID        | No      | Filtrar por servicio; admite parámetros repetidos                                        |
| `scope`       | string      | No      | `Individual` o `Global`; admite parámetros repetidos                      |
| `type`        | string      | No      | `Usage` o `Period`; admite parámetros repetidos                           |
| `limit`       | integer     | No      | Número de elementos por página, máximo 100                                         |
| `offset`      | integer     | No      | Desplazamiento de paginación                                               |
| `ordering`    | string      | No      | Solo admite `created_at` o `-created_at`                    |

`paid`, `disabled`, `expired`, `low_balance` y `tag` actualmente no son parámetros de filtrado del servidor. Las alertas de saldo deben obtener la lista y luego evaluarse en el cliente según `remaining_amount`, `service.unit` y el umbral de negocio de cada Application.

## Ejemplo de solicitud

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'limit=100' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Ver simultáneamente las Application que posee y las que otros le han autorizado:

```shell
curl --get 'https://platform.acedata.cloud/api/v1/applications/' \
  --data-urlencode 'user_id=me' \
  --data-urlencode 'affiliation=owner' \
  --data-urlencode 'affiliation=granted' \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

## Descripción de la respuesta

La respuesta es `{count, items}`. Cada elemento contiene los campos del modelo Application y añade:

- `service`: `id`, `alias`, `title`, `type`, `unit`, `icon_url`;
- `credentials`: el resumen de credenciales que el llamador actual tiene permiso para ver;
- `paid`, `remaining_amount`, `used_amount`, `disabled`, `allow_consume_global`, `allow_overdraft`;
- el valor real de `scope` es `Individual` o `Global`;
- el valor real de `type` es `Usage` o `Period`.

`allow_overdraft` es un campo booleano de solo lectura controlado por el administrador, con valor predeterminado `false`. Para las aplicaciones por uso (`Usage`) con sobregiro habilitado, un saldo insuficiente no impedirá las llamadas y se seguirá cobrando según el uso real; un saldo negativo representa una cuota pendiente de liquidación. La desactivación, el vencimiento y los límites de las credenciales de API siguen vigentes.

`remaining_amount` puede estar vacío; el cliente debe comprobar primero si es nulo antes de realizar comparaciones numéricas. La unidad de cuota se determina mediante `service.unit`.
