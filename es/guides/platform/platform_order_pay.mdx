---
title: "Pagar un pedido de la plataforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Cree o actualice una sesión de pago para un pedido `Pending`. La acción de pago accederá al canal de pago y puede cambiar el estado del pedido; antes de realizar la llamada, debe confirmar el ID del pedido, el importe y el método de pago.

## Descripción general de la interfaz

| Elemento    | Contenido                                                             |
| ---- | -------------------------------------------------------------- |
| Método   | `POST`                                                         |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/pay/` |
| Autenticación   | Los pagos de redirección alojados pueden ser anónimos; otros métodos requieren una sesión iniciada o un Account Token                            |
| Body | JSON; los pedidos no pagados deben proporcionar `pay_way`                                       |

## Límites del pago anónimo

El acceso anónimo se utiliza para situaciones en las que se pierde la sesión después de abrir un enlace de pago copiado, y no necesita ni debe incluir un Account Token de larga duración. Las llamadas anónimas:

- Solo permiten métodos de pago de redirección alojados configurados por el servidor;
- Utilizan de forma fija la página de pago de escritorio;
- No pueden reclamar pedidos de precio cero;
- Están sujetas a limitación de frecuencia por IP y por pedido individual;
- Devuelven una proyección mínima del pedido, sin incluir cuenta, Application ni metadata interna.

Los llamadores autenticados deben ser el propietario del pedido o un superadministrador. Los métodos que requieren contexto de usuario, como X402 y el canje de recompensas, no pueden llamarse de forma anónima.

## Ejemplo de solicitud

```shell
export ORDER_ID='tu ID de pedido Pending'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"Stripe"}'
```

Métodos de pago que requieren autenticación:

```shell
export PLATFORM_TOKEN='tu token de cuenta'

curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/pay/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}" \
  -H 'Content-Type: application/json' \
  -d '{"pay_way":"X402"}'
```

`pay_way` utiliza valores reales admitidos por el modelo de pedido, por ejemplo, `WechatPay`, `AliPay`, `Stripe`, `Card`, `Airwallex`, `X402`, `PayPal`, `AppleIAP`, `Reward`, `BankTransfer`. No todos los valores están disponibles para solicitudes anónimas ni para todos los sitios.

## Descripción de la respuesta

La respuesta exitosa es el objeto de pedido actualizado, que normalmente proporciona la entrada del siguiente paso a través de `pay_url`; los distintos métodos de pago también pueden devolver en campos controlados la información necesaria para que el cliente continúe con el pago. La respuesta anónima utiliza una lista blanca mínima de campos; el propietario autenticado obtiene los detalles completos.

No dependa de nombres de campos antiguos como `payment_url`, `qr_code_url` o `payment_method`; el contrato actual de Order utiliza `pay_url` y `pay_way`.

## Compras dentro de la aplicación de iOS

El propietario del pedido que ha iniciado sesión puede enviar `pay_way: "AppleIAP"`. Esta solicitud actualiza el pedido pendiente de pago según `metadata.apple_price` del plan seleccionado y elimina los descuentos, no genera ningún cobro, no otorga créditos ni devuelve un enlace de pago. Los pedidos pendientes antiguos deben completar primero este paso y luego iniciar el pago nativo de Apple. Solo se admite un plan Usage con un producto y precio de Apple configurados; los planes no admitidos o los pedidos por lotes devuelven `400`.

Después del pago nativo de Apple, envíe `transaction_id` mediante `/api/v1/orders/{id}/apple-verify/` para completar la verificación del servidor y la concesión de créditos. La cantidad de créditos proviene del plan; el importe utiliza el precio preestablecido independiente en dólares estadounidenses de Apple, sin acumular descuentos de membresía ni recargos del sitio, y el importe de cobro en moneda local de otras regiones se rige por la página de confirmación de Apple.

## Errores y reintentos

- El pedido no está en `Pending`: devuelve `400`; no cree repetidamente sesiones de pago.
- No se proporcionó `pay_way`: los pedidos con importe distinto de cero devuelven `400`.
- Una llamada anónima utilizó un método no permitido o un pedido de precio cero: devuelve `403`; inicie sesión y vuelva a intentarlo como propietario.
- Autenticado, pero no es el propietario del pedido: devuelve `403`.
- Fallo del canal de pago: no vuelva a enviar ciegamente; primero consulte los detalles del pedido y, tras confirmar que sigue en `Pending`, vuelva a intentarlo.
