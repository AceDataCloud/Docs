---
title: "Actualizar el estado de pedido de la plataforma AceDataCloud"
description: "Platform API guide - Ace Data Cloud"
---

Consulta activamente el estado más reciente del método de pago correspondiente al pedido y lo sincroniza con la plataforma. Esta solicitud puede acceder al servicio de pago y cambiar el estado del pedido; úsala solo cuando la devolución de llamada se retrase o se requiera confirmación inmediata.

## Preparativos

- Utiliza el [Account Token](https://platform.acedata.cloud/documents/platform-token).
- Obtén tu propio ID de pedido de la [lista de pedidos](https://platform.acedata.cloud/documents/platform-order-list).

```shell
export PLATFORM_TOKEN='tu token de cuenta'
export ORDER_ID='tu ID de pedido'
```

## Resumen de la API

| Elemento    | Contenido                                                          |
| ---- | ------------------------------------------------------------------ |
| Método   | `POST`                                                             |
| URL  | `https://platform.acedata.cloud/api/v1/orders/{order_id}/refresh/` |
| Autorización   | Propietario del pedido o superadministrador                                                        |
| Body | Normalmente vacío; el escenario de devolución de llamada de PayPal puede requerir `payer_id` / `PayerID`                         |

```shell
curl -X POST \
  "https://platform.acedata.cloud/api/v1/orders/${ORDER_ID}/refresh/" \
  -H "Authorization: Bearer ${PLATFORM_TOKEN}"
```

Una respuesta exitosa devuelve el objeto Order completo actualizado. Utiliza `state` para determinar el resultado y `finished_at` como hora de finalización; el modelo actual no tiene el campo `paid_at`. Los valores de estado incluyen `Pending`, `Paid`, `Finished`, `Expired`, `Failed` y `Refunded`.

La fecha límite de pago solo cambiará los pedidos que aún estén en `Pending` a `Expired`. Los pedidos `Refunded` que ya han sido reembolsados permanecen en estado reembolsado después de actualizarse o de recibir una devolución de llamada de pago retrasada.

## Recomendaciones de reintento

- Para los pagos normales, prioriza las devoluciones de llamada de la plataforma; realiza un refresh activo solo cuando el estado no se actualice durante mucho tiempo.
- No realices sondeos frecuentes a intervalos fijos. Se recomienda retroceso exponencial y detenerse al alcanzar un estado terminal claro.
- `401` indica que el token no es válido; `403` indica que no eres el propietario del pedido; `404` indica que el pedido no existe.
- Cuando falle la consulta del servicio de pago, conserva el ID del pedido y el ID de trace, y vuelve a intentarlo más tarde; no crees pedidos duplicados como sustituto de la confirmación del estado.
