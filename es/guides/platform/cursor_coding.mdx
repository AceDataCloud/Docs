Cursor actualmente proporciona la clave de API de OpenAI y la configuración de **Override OpenAI Base URL**, lo que permite conectar con servicios compatibles con OpenAI. Esta capacidad existe, pero el manejo de `/chat/completions`, `/responses`, la lista de modelos y los modos de Agent/Composer no es completamente consistente entre diferentes versiones.

El rango de compatibilidad puede variar según la versión de Cursor, el sistema operativo y el modo de solicitud. Por favor, complete la verificación del modo real según la configuración de esta página, no infiera que todas las funciones están disponibles basándose en el éxito de una sola conversación.

## Qué garantiza actualmente Cursor BYOK

Según la [documentación oficial de Cursor sobre Bring your own API key](https://cursor.com/help/models-and-usage/api-keys):

- Soporte para credenciales de OpenAI, Anthropic, Google, Azure OpenAI y AWS Bedrock;
- La clave de API personalizada se utiliza únicamente para modelos de chat, la finalización de pestañas sigue utilizando el modelo integrado de Cursor;
- La clave de API no se persiste en el servidor de Cursor, pero se envía la clave al backend de Cursor con cada solicitud, para la construcción final del prompt;
- Al usar su propia clave, la política de Zero Data Retention de Cursor no se aplica, el procesamiento de datos sigue la política del proveedor seleccionado.

## Configuración

1. Abra Configuración de Cursor → Modelos.
2. En la clave de API de OpenAI, ingrese su token de API de Ace Data Cloud.
3. Habilite **Override OpenAI Base URL**, ingrese `https://api.acedata.cloud/v1`.
4. Seleccione o agregue un ID de modelo exacto compatible con el protocolo actual de Cursor.
5. Primero envíe `Reply only OK`, luego pruebe los modos Ask/Edit/Agent que realmente utiliza.

## Límites actuales

- La clave de API personalizada se utiliza únicamente para modelos de chat, la finalización de pestañas sigue utilizando el modelo integrado de Cursor.
- Cursor aún puede completar la construcción final del prompt en el servidor; evalúe la ruta de datos en combinación con la declaración de privacidad oficial.
- La anulación de la URL base puede cubrir solo algunas solicitudes, o cambiar entre Chat Completions/Responses debido a cambios de versión.
- No se debe afirmar que Agent, Auto, Composer o tareas en segundo plano están conectados solo porque una solicitud de chat fue exitosa.

## Verificación completa de compatibilidad

Para un uso a largo plazo en flujos de trabajo de producción, complete las siguientes verificaciones:

1. Versión fija de Cursor y sistema operativo;
2. Realice una prueba de humo con un cliente real para esa versión y registre el protocolo y la ruta de la solicitud final;
3. Solicitudes de Chat Completions del modelo exacto exitosas;
4. Las llamadas a herramientas y solicitudes de Agent realmente pasan por el endpoint objetivo;
5. El uso y la facturación son verificables;
6. Registre claramente si las solicitudes pasaron por el servidor de Cursor y las restricciones de privacidad correspondientes.

Después de una actualización del cliente, se deben volver a realizar estas verificaciones para confirmar que no ha habido cambios en el protocolo de solicitud, las llamadas a herramientas y la ruta de datos.
