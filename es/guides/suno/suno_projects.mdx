`POST https://api.acedata.cloud/suno/projects` es la interfaz Beta para gestionar proyectos multipista. Distingue entre crear, guardar, generar candidatos, confirmar candidatos y exportar mediante `action`.

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: <每次写操作的新 UUID>
```

Excepto `retrieve`, **cada operación requiere** `Idempotency-Key`. La misma clave y la misma solicitud solo devuelven el resultado original; la misma clave con una solicitud diferente devuelve 409. Cuando una generación de pago encuentra un tiempo de espera de red o el resultado de la confirmación es incierto, primero consulte usando el ID de tarea original o la misma clave de idempotencia, y no cambie directamente la clave para reenviar.

## Identificadores y unidades de tiempo

| Nombre                         | De dónde obtenerlo                                                                                      | Dónde usarlo                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | `data.id` de la respuesta de `create`                                                                      | Todas las solicitudes posteriores del proyecto actual                                      |
| `version_id`                   | `data.version_id` del `retrieve`, `save`, `add_track`, `commit_candidate` o `remove_track` más reciente | Modificar, generar candidatos y exportar; se debe usar la versión más reciente                              |
| `audio_id` / `source_audio_id` | `response.data.candidate.audio_id` en estado final de `upload`, o un ID de audio completado existente                                | Referenciar el audio original al usar `add_track`, generar o reemplazar                          |
| `render_audio_id`              | `response.data.audio_id` en estado final de `render`                                                       | Referencia de mezcla del proyecto para `generate_track`                         |
| `operation_id`                 | `response.data.operation_id` en estado final de `generate_track` o `replace_section`                       | `commit_candidate`; normalmente es igual al `task_id` de la tarea de generación, pero se debe leer el valor devuelto |
| `candidate_id`                 | `response.data.candidates[].id` en estado final de generación                                                       | Seleccionar un candidato para confirmar                                         |
| `track_id`                     | `data.state.tracks[].id` del proyecto                                                                | Confirmar un candidato o eliminar una pista                                        |
| `task_id`                      | Respuesta de envío de operación asíncrona                                                                                   | Usar `/suno/tasks` para consultar el estado final; no es el ID del proyecto                   |

`start_seconds` / `end_seconds` son los **segundos dentro del audio fuente**; `start_beats` / `end_beats` son los **pulsos en la línea de tiempo del proyecto**. `state.timing.bps` es la cantidad de pulsos por segundo, con un valor predeterminado de 2. Por ejemplo, un fragmento de 41 segundos que comienza en el pulso 0 tiene un punto final predeterminado en el pulso 82. El intervalo en segundos de `generate_track` se utiliza para especificar la referencia de generación, y no garantiza que el candidato tenga solo la duración de dicho intervalo.

## Flujo de operaciones

| Orden  | `action`                             | Función                         | Método de devolución         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | Crear un proyecto vacío                      | Datos de proyecto síncronos       |
| 2   | `retrieve`                           | Leer la versión más reciente y el `state` completo          | Datos de proyecto síncronos       |
| 3   | `save`                               | Guardar por primera vez o guardar globalmente el `state` modificado      | Datos de proyecto síncronos       |
| 4   | `upload`                             | Crear material desde una URL de audio HTTPS           | Tarea asíncrona         |
| 5   | `add_track`                          | Colocar el audio del material en el proyecto                  | Tarea asíncrona, actualiza la versión    |
| 6   | `save`                               | Si necesita recibir candidatos de pista nuevos, primero guarde una pista objetivo vacía        | Datos de proyecto síncronos, actualiza la versión  |
| 7   | `render`                             | Exportar las pistas audibles actuales y obtener la referencia de mezcla `audio_id` | Tarea asíncrona         |
| 8   | `generate_track` o `replace_section` | Generar candidatos de pista nueva o candidatos de reemplazo parcial, respectivamente            | Tarea asíncrona, no modifica el proyecto por ahora  |
| 9   | `commit_candidate`                   | Seleccionar y confirmar un candidato                  | Tarea asíncrona, actualiza la versión tras el éxito |
| Opcional  | `remove_track`                       | Eliminar la pista especificada                     | Datos de proyecto síncronos, actualiza la versión  |

Si solo realiza un reemplazo parcial, basta con tener un audio fuente disponible y no es necesario ejecutar primero `render`; si el audio fuente ya está en el proyecto, también puede omitir `upload` y `add_track`. `render_audio_id` es solo la referencia obligatoria de `generate_track`.

Al enviar una operación asíncrona, primero se devuelve `{ "task_id": "...", "trace_id": "..." }`, lo que **no significa que la generación haya tenido éxito**. Sondeo:

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步返回的 task_id"}
```

Solo se considera exitoso cuando el registro de la tarea tiene `finished_at` y su `response.success` es `true`; cuando `response.success=false`, lea `response.error`. Aunque `save` puede incluir `task_id`, se completa de forma síncrona dentro de esta interfaz. `upload`, `render`, `generate_track` y `replace_section` no modifican la versión del proyecto; después de que `save`, `add_track`, `commit_candidate` y `remove_track` tengan éxito, se debe obtener el nuevo `version_id`.

## Convenciones de solicitud

| Parámetro                | Tipo y ámbito de aplicación                                                                                   | Descripción                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | Cadena obligatoria                                                                                     | Se fija en uno de los nombres de operación enumerados en esta página; una solicitud ejecuta solo una operación.                                      |
| `id`              | Cadena obligatoria excepto para `create`                                                                         | ID del proyecto, obtenido de `create.data.id`.                                      |
| `version_id`      | Cadena obligatoria al modificar, generar candidatos o exportar; se puede omitir en el primer `save` de un proyecto vacío                                                         | Use la versión más reciente; las versiones antiguas serán rechazadas. `retrieve` no lo necesita.                                 |
| `Idempotency-Key` | Encabezado de solicitud obligatorio excepto para `retrieve`, de 1–128 caracteres                                                              | Use una nueva clave para cada nueva operación; la misma clave con la misma solicitud devuelve el resultado original, sin volver a generar ni cobrar.                                   |
| `async`           | Booleano opcional para `upload`, `add_track`, `generate_track`, `replace_section`, `commit_candidate`, `render` | Estas operaciones siempre son asíncronas; `false` tampoco convierte la generación en síncrona.                                    |
| `callback_url`    | URL opcional para operaciones asíncronas                                                                                | Recibe notificaciones de estado final; si se omite, consulte `/suno/tasks` mediante `task_id`. Aún debe comprobar `response.success`. |

Los siguientes ejemplos encadenan y muestran la transmisión de ID y versiones entre las operaciones. Las respuestas solo enumeran los campos relacionados con el paso actual; durante la integración, reemplace los ID de ejemplo con los valores de respuesta de la aplicación actual.

## Guardar el estado del proyecto

| Parámetro | Tipo y descripción |
|---|---|
| `state` | Objeto obligatorio. Envíe el **estado completo del proyecto**, no un parche parcial; tome como base el `data.state` devuelto por la operación más reciente de lectura o modificación, y conserve los campos desconocidos. |
| `title` | Cadena opcional; si se omite, se mantiene `state.title`; si tampoco existe, se utiliza el título predeterminado. |
| `version_id` | Puede omitirse al guardar por primera vez un nuevo proyecto vacío; después de eso, debe utilizarse la versión más reciente. |

`state.timing.bps` debe ser un número positivo, con un valor predeterminado de 2. `state.tracks` es el arreglo de pistas; el `clipId` de los fragmentos de audio existentes hace referencia al ID de audio, y `startBeats`, `endBeats` y `readStartBeats` utilizan unidades de pulsos del proyecto. La forma más segura de editar es leer el `state` completo, modificar solo la pista o el fragmento objetivo y luego realizar un `save` completo. Una nueva pista objetivo vacía debe tener al menos un `id` único, `type:"audio"` y `clips:[]`; consulte el ejemplo en “Generar una nueva pista de audio” para ver la estructura completa de una pista vacía. No utilice directamente los puntos de pulso de los resultados del análisis de audio como coordenadas de la línea de tiempo del proyecto.

## Cargar audio y añadir una pista

| Operación | Parámetro | Tipo y descripción |
|---|---|---|
| `upload` | `audio_url` | URL HTTPS obligatoria, que apunte a audio accesible públicamente y que tenga derecho a utilizar. El `candidate.audio_id` en el estado final puede utilizarse para añadir una pista. |
| `add_track` | `audio_id` | Cadena obligatoria; el ID de audio de un recurso completado, no una URL. |
| `add_track` | `name`、`color` | Cadenas opcionales; el nombre de la pista toma de forma predeterminada el título del audio, el color recomendado es `#RRGGBB`, y el predeterminado es `#7251F7`. |
| `add_track` | `title` | Cadena opcional; también modifica el título del proyecto, normalmente se omite. |
| `add_track` | `start_beats`、`end_beats` | Números no negativos opcionales; el punto final debe ser mayor que el punto inicial; de forma predeterminada comienza en el pulso 0, y el punto final se calcula según la duración del audio y `timing.bps`. |
| `add_track` | `gain` | Número no negativo opcional, el valor predeterminado es 1; el coeficiente de volumen del fragmento y de la pista. |

## Generar una nueva pista de audio

Los candidatos y el proyecto durante la generación están vinculados a una versión. Primero guarde la pista vacía que recibirá los candidatos y luego exporte la mezcla actual como referencia de generación; después de completar la generación, seleccione un candidato para enviarlo a esa pista vacía.

### Reservar pista objetivo: `save`

Los candidatos de `generate_track` están vinculados a la versión actual del proyecto. En el `state` **completo** devuelto en el estado final de `add_track` anterior, añada la siguiente pista vacía a `state.tracks` y luego guárdela con `save`; conserve sin cambios los demás campos existentes:
```

"type": "audio",
"name": "Generated piano",
"clips": [],
"takeLanes": [],
"mute": false,
"solo": false,
"amplitude": 1,
"instrument": &#123;
"type": "song"
&#125;,
"color": "#7251F7"
&#125;

```

### Generar candidatos: `generate_track`

| Parámetro | Tipo y descripción |
|---|---|
| `source_audio_id` | Obligatorio; ID del audio fuente completado. Primero agregue el audio fuente al proyecto, y posteriormente podrá determinarse la posición del candidato. |
| `render_audio_id` | Obligatorio; `response.data.audio_id` en el estado final de `render` mencionado anteriormente, no la URL del audio. |
| `model` | Obligatorio; puede ser `chirp-v3-5`, `chirp-v4`, `chirp-v4-5`, `chirp-v4-5-plus`, `chirp-v5`, `chirp-v5-5`, `chirp-v6`, `chirp-v6-wild`, `chirp-v6-mini`. Que una combinación específica esté disponible depende del estado final de la tarea. |
| `start_seconds`、`end_seconds` | Números obligatorios, `0 ≤ start_seconds < end_seconds`; intervalo de segundos dentro del audio fuente, no los compases del proyecto, ni se garantiza la duración de salida. |
| `stem_control_tags` | Cadena obligatoria; descripción de la nueva parte, por ejemplo `add Piano`, `add Drums`, `add Bass`, no es una enumeración fija. |
| `batch_size` | Entero opcional de 1–4, el valor predeterminado es 2; cantidad de candidatos. |
| `instrumental`、`vocal_gender` | Opcionales; el valor predeterminado para puramente instrumental es `true`, la preferencia vocal puede ser `f`, `m`, `unspecified`, el valor predeterminado es `unspecified`. |

### Adoptar candidato: `commit_candidate`

| Parámetro | Tipo y descripción |
|---|---|
| `operation_id` | Obligatorio; `data.operation_id` del estado final de la tarea de generación. |
| `candidate_id` | Obligatorio; el `data.candidates[].id` seleccionado. |
| `track_id` | Obligatorio; `state.tracks[].id` de la pista vacía guardada antes de la generación. |
| `start_beats`、`end_beats` | Opcionales para candidatos de nueva pista; especifican el rango de pulsos del proyecto y no pueden superponerse con los clips existentes en la pista de destino. Si se omiten, se reutiliza el punto inicial del clip fuente y se calcula el punto final según la duración del candidato. |
| `name`、`gain` | Opcionales para candidatos de nueva pista; nombre del clip y coeficiente de volumen no negativo; `gain` es 1 de forma predeterminada. |

La generación solo produce candidatos y **no los coloca automáticamente en el proyecto**. `commit_candidate` comprobará que el candidato aún pertenezca a la versión actual. Los candidatos de reemplazo parcial solo pueden enviarse automáticamente cuando su duración real puede coincidir de forma fiable con el audio fuente completo o el intervalo seleccionado; si no coincide, se conserva el proyecto original y se devuelve un error, y no se puede forzar el empalme adivinando manualmente los pulsos.

## Reemplazar un clip existente

`replace_section` puede usar directamente un audio fuente existente, sin necesidad de exportar primero la mezcla. La generación solo devuelve candidatos; al enviar, se selecciona la pista original que contiene el único clip fuente.

| Parámetro | Tipo y descripción |
|---|---|
| `source_audio_id` | Obligatorio; ID del audio fuente completado que se va a reemplazar. |
| `model` | Obligatorio; utiliza los modelos públicos enumerados en “generar candidatos”; la disponibilidad del modelo y de la operación se basa en el estado final de la tarea. |
| `start_seconds`、`end_seconds` | Números obligatorios, `0 ≤ start_seconds < end_seconds ≤ duración del audio fuente`; intervalo en segundos dentro del audio fuente. |
| `prompt`、`replacement_lyrics` | Cadenas opcionales; el primero son las letras originales o el contexto, y el segundo son las letras nuevas para el intervalo de reemplazo. |
| `title`、`tags`、`negative_tags` | Cadenas opcionales; título del candidato, estilo deseado y estilos que se deben evitar. |
| `fixed` | Booleano opcional, `false` de forma predeterminada; cuando se establece en `true`, el intervalo debe ser inferior a 26 segundos y es posible que el modelo no lo admita. |

## Errores y recuperación

| Resultado | Significado | Siguiente paso |
|---|---|---|
| `project_version_conflict` / `project_candidate_stale`（409） | La versión del proyecto ha cambiado, o el candidato no pertenece a la versión actual. | `retrieve` el proyecto más reciente y vuelva a planificar las modificaciones; no reproduzca candidatos antiguos. |
| `bad_request` / `studio_state_invalid` / `studio_model_unsupported`（normalmente 400） | Los parámetros, el estado de la pista, la duración del candidato o el modelo no coinciden con la operación. | Revise el error del estado final de la tarea, corrija la entrada; conserve el proyecto original cuando el candidato no pueda concatenarse de forma segura. |
| `studio_audio_unavailable` / `studio_access_denied` / `content_rejected`（403） | El audio de referencia no está disponible para esta operación del proyecto, no se tiene permiso de acceso, o la revisión de contenido lo rechaza. | Verifique la fuente del audio y el `trace_id` de la tarea; no equipare candidatos ya generados con la posibilidad de exportar la canción completa. |
| `too_many_requests`（429） | La solicitud está limitada por frecuencia. | Primero consulte la tarea original y luego decida si inicia una nueva operación con una nueva clave de idempotencia. |
| `studio_unavailable` / `studio_model_unavailable`（503） | El procesamiento del proyecto o el modelo seleccionado no está disponible temporalmente. | Conserve el resultado de la tarea original; vuelva a intentarlo explícitamente más tarde, sin cambiar de modelo automáticamente. |
| `studio_processing_failed` / tiempo de espera（500/504） | El procesamiento falló o el estado final es incierto. | Consulte mediante `task_id` o la clave de idempotencia original para evitar generación con cargos duplicados. |

Los proyectos y candidatos están vinculados a la aplicación y al entorno de ejecución que los crearon, y no se debe asumir la reutilización entre aplicaciones ni la conmutación automática por error. Persista la URL final del audio exportado correctamente y conserve `trace_id` para facilitar la investigación.
