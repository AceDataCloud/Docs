`POST https://api.acedata.cloud/suno/projects` es la interfaz Beta para gestionar proyectos multipista. Un endpoint distingue entre crear, guardar, generar candidatos, enviar candidatos y exportar mediante `action`. El llamador solo necesita usar los campos públicos a continuación, y no necesita completar la estructura interna de solicitud del servicio de generación subyacente.

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: 每次修改操作使用新的 UUID
```

Excepto `retrieve`, **cada operación requiere** `Idempotency-Key`. La misma clave y la misma solicitud solo devuelven el resultado original; la misma clave con una solicitud diferente devuelve 409. Cuando una generación de pago encuentra un tiempo de espera de red o un resultado de envío incierto, primero consulte usando el ID de tarea original o la misma clave de idempotencia, y no cambie directamente la clave para reenviar.

## Primero distinga estos ID y unidades de tiempo

| Nombre                         | De dónde obtenerlo                                                                                      | Dónde usarlo                                             |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | Respuesta de `create` `data.id`                                                                      | Todas las solicitudes posteriores del proyecto actual                                      |
| `version_id`                   | `data.version_id` del `retrieve`, `save`, `add_track`, `commit_candidate` o `remove_track` más reciente | Modificar, generar candidatos y exportar; debe usar la versión más reciente                              |
| `audio_id` / `source_audio_id` | `response.data.candidate.audio_id` del estado final de `upload`, o un ID de audio completado existente                                | Referenciar el audio original al usar `add_track`, generar o reemplazar                          |
| `render_audio_id`              | `response.data.audio_id` del estado final de `render`                                                       | Referencia de mezcla del proyecto para `generate_track`                         |
| `operation_id`                 | `response.data.operation_id` del estado final de `generate_track` o `replace_section`                       | `commit_candidate`; normalmente es igual al `task_id` de la tarea de generación, pero se debe leer el valor devuelto |
| `candidate_id`                 | `response.data.candidates[].id` del estado final de generación                                                       | Seleccionar un candidato para enviar                                         |
| `track_id`                     | `data.state.tracks[].id` del proyecto                                                                | Enviar un candidato o eliminar una pista                                        |
| `task_id`                      | Respuesta de envío de operación asíncrona                                                                                   | Usar `/suno/tasks` para consultar el estado final; no es un ID de proyecto                   |

`start_seconds` / `end_seconds` son **segundos dentro del audio fuente**; `start_beats` / `end_beats` son **tiempos en la línea temporal del proyecto**. `state.timing.bps` es el número de tiempos por segundo, con un valor predeterminado de 2. Por ejemplo, para un fragmento de 41 segundos que comienza en el tiempo 0, el punto final predeterminado es el tiempo 82. El intervalo de segundos de `generate_track` se utiliza para especificar la referencia de generación y no garantiza que el candidato tenga solo la duración de dicho intervalo.

## Orden de operaciones y determinación de resultados

| Orden  | `action`                             | Función                         | Método de respuesta         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | Crear un proyecto vacío                      | Datos del proyecto síncronos       |
| 2   | `retrieve`                           | Leer la versión más reciente y el `state` completo          | Datos del proyecto síncronos       |
| 3   | `save`                               | Guardar por primera vez o guardar globalmente el `state` modificado      | Datos del proyecto síncronos       |
| 4   | `upload`                             | Crear material desde una dirección de audio HTTPS           | Tarea asíncrona         |
| 5   | `add_track`                          | Colocar el audio de material en el proyecto                  | Tarea asíncrona, actualiza la versión    |
| 6   | `save`                               | Si necesita recibir candidatos para una nueva pista, primero guarde una pista objetivo vacía        | Datos del proyecto síncronos, actualiza la versión  |
| 7   | `render`                             | Exportar las pistas actualmente audibles y obtener la referencia de mezcla `audio_id` | Tarea asíncrona         |
| 8   | `generate_track` o `replace_section` | Generar respectivamente candidatos de nueva pista o de reemplazo local            | Tarea asíncrona, no modifica temporalmente el proyecto  |
| 9   | `commit_candidate`                   | Seleccionar y enviar un candidato                  | Tarea asíncrona, actualiza la versión tras completarse correctamente |
| Opcional  | `remove_track`                       | Eliminar la pista especificada                     | Datos del proyecto síncronos, actualiza la versión |

Si solo realiza un reemplazo local, basta con tener audio fuente utilizable y no es necesario ejecutar primero `render`; si el audio fuente ya está en el proyecto, también puede omitir `upload` y `add_track`. `render_audio_id` es únicamente una referencia obligatoria de `generate_track`.

Al enviar una operación asíncrona, primero se devuelve `{ "task_id": "...", "trace_id": "..." }`, lo que **no indica que la generación haya tenido éxito**. Sondeo:

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步返回的 task_id"}
```

Solo se considera exitoso cuando el registro de tarea tiene `finished_at` y el `response.success` dentro de este es `true`; cuando `response.success=false`, lea `response.error`. Aunque `save` puede incluir `task_id`, se completa de forma síncrona dentro de esta interfaz. `upload`, `render`, `generate_track`, `replace_section` no modifican la versión del proyecto; tras completarse correctamente `save`, `add_track`, `commit_candidate`, `remove_track`, se debe obtener el nuevo `version_id`.

## Parámetros de solicitud

### Campos comunes y encabezados de solicitud

| Parámetro                | Tipo y ámbito de aplicación                                                                                   | Descripción                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | Cadena obligatoria                                                                                     | Se fija como uno de los nombres de operación enumerados en esta página; una solicitud ejecuta solo una operación.                                      |
| `id`              | Cadena obligatoria excepto para `create`                                                                         | ID del proyecto, procedente de `create.data.id`.                                      |
| `version_id`      | Cadena obligatoria al modificar, generar candidatos y exportar; puede omitirse en el primer `save` de un proyecto vacío                                                         | Use la versión más reciente; las versiones antiguas serán rechazadas. `retrieve` no lo necesita.                                 |
| `Idempotency-Key` | Encabezado de solicitud obligatorio excepto para `retrieve`, de 1 a 128 caracteres                                                              | Use una nueva clave para cada nueva operación; con la misma clave y la misma solicitud se devuelve el resultado original, sin generar ni cobrar de nuevo.                                   |
| `async`           | Booleano opcional para `upload`, `add_track`, `generate_track`, `replace_section`, `commit_candidate`, `render` | Estas operaciones siempre son asíncronas; `false` tampoco convierte la generación en síncrona.                                    |
| `callback_url`    | URL opcional para las operaciones que contienen los campos asíncronos opcionales anteriores                                                                       | Recibe notificaciones del estado final; si se omite, consulte `/suno/tasks` según `task_id`. Aún debe comprobar `response.success`. |

### Proyecto y material
| `action`       | Parámetro específico          | Tipo y condiciones                     | Descripción                                                              |
| -------------- | --------------------------- | -------------------------------- | ------------------------------------------------------------------ |
| `create`       | `title`                     | Cadena obligatoria, 1–200 caracteres    | Título del nuevo proyecto.                                                |
| `retrieve`     | Ninguno                     | —                                | Solo se necesitan `action` y el `id` del proyecto; devuelve el `state` completo editable. |
| `save`         | `state`                     | Objeto obligatorio                    | **Reemplaza por completo** el estado del proyecto, no es un parche parcial. Modifique sobre la base del `retrieve.data.state` más reciente y envíelo completo, conservando los campos desconocidos. |
| `save`         | `title`                     | Cadena opcional                       | Título del proyecto; si se omite, se usa `state.title`; si tampoco existe, se usa el título predeterminado. |
| `upload`       | `audio_url`                 | URL HTTPS obligatoria                  | Dirección de material de audio accesible públicamente; tras el éxito, lea el estado final `candidate.audio_id`. El material debe ser de uso autorizado por quien llama. |
| `add_track`    | `audio_id`                  | Cadena obligatoria                    | ID de audio del material ya completado, no una URL.                       |
| `add_track`    | `name` / `color`            | Cadenas opcionales                    | Nombre y color de la nueva pista; el nombre toma por defecto el título del audio, se recomienda el color `#RRGGBB`, el predeterminado es `#7251F7`. |
| `add_track`    | `title`                     | Cadena opcional                       | Modifica simultáneamente el título del proyecto; normalmente se omite.    |
| `add_track`    | `start_beats` / `end_beats` | Números no negativos opcionales, `end_beats > start_beats` | Posición del clip en la línea de tiempo del proyecto. El punto inicial predeterminado es 0; el punto final predeterminado es `punto inicial + duración del audio × timing.bps`. |
| `add_track`    | `gain`                      | Número no negativo opcional, predeterminado 1 | Coeficiente de volumen del clip y de la nueva pista.                     |
| `remove_track` | `track_id`                  | Cadena obligatoria                    | ID de la pista existente que se va a eliminar. Tras el éxito, use la nueva versión devuelta. |

`state.timing.bps` debe ser un número positivo, el valor predeterminado es 2. `state.tracks` es un arreglo de pistas; el `clipId` de los clips de audio existentes hace referencia al ID de audio, y `startBeats`, `endBeats`, `readStartBeats` usan unidades de pulsos del proyecto. La forma más segura de editar es leer el `state` completo, modificar solo la pista o el clip objetivo y luego realizar un `save` completo. Una nueva pista objetivo vacía debe tener al menos un `id` único, `type:"audio"`, `clips:[]`; la forma completa realmente utilizable se muestra en el paso 5 a continuación. No trate directamente los puntos de pulso de los resultados de análisis de audio como coordenadas de la línea de tiempo del proyecto.

### Generar, enviar y exportar
| `action`                             | Parámetros específicos               | Tipo y condiciones                           | Descripción                                                                                                                                                        |
| ------------------------------------ | ---------------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generate_track` / `replace_section` | `source_audio_id`                  | Cadena obligatoria                                  | ID del audio fuente completado. Primero añade el audio fuente al proyecto; solo entonces los candidatos posteriores podrán encontrar la posición correspondiente.                                                                                                                        |
| `generate_track` / `replace_section` | `model`                            | Cadena de enumeración obligatoria                                | Se puede elegir `chirp-v3-5`, `chirp-v4`, `chirp-v4-5`, `chirp-v4-5-plus`, `chirp-v5`, `chirp-v5-5`, `chirp-v6`, `chirp-v6-wild`, `chirp-v6-mini`. La disponibilidad del modelo y de la operación se determina por el estado final de la tarea; no cambiará automáticamente a otro modelo. |
| `generate_track` / `replace_section` | `start_seconds` / `end_seconds`    | Número obligatorio, `0 ≤ start_seconds &lt; end_seconds` | Segundos de inicio y fin dentro del audio fuente; al reemplazar, el punto final tampoco debe superar la duración real del audio fuente. No son pulsos del proyecto ni garantizan la duración de salida del candidato.                                                                                                         |
| `generate_track`                     | `render_audio_id`                  | Cadena obligatoria                                  | El `response.data.audio_id` después de un `render` exitoso del proyecto actual, utilizado como referencia de mezcla durante la generación.                                                                                                   |
| `generate_track`                     | `stem_control_tags`                | Cadena obligatoria                                  | Descripción de la nueva pista, por ejemplo `add Piano`, `add Drums`, `add Bass`; no es una enumeración fija.                                                                                                      |
| `generate_track`                     | `batch_size`                       | Entero opcional 1–4, predeterminado 2                          | Cantidad de candidatos solicitados para generar.                                                                                                                                                |
| `generate_track`                     | `instrumental` / `vocal_gender`    | Booleano opcional／cadena de enumeración                            | `instrumental` tiene como valor predeterminado `true`; la preferencia vocal puede ser `f`, `m`, `unspecified`, con valor predeterminado `unspecified`. Que se respeten las preferencias depende del audio real.                                                                     |
| `generate_track` / `replace_section` | `title` / `tags` / `negative_tags` | Cadena opcional                                  | Título del candidato, descripción del estilo deseado, etiquetas de estilo que se desean evitar. Cuando se omiten `tags` y `negative_tags`, se pasan cadenas vacías.                                                                                                  |
| `generate_track`                     | `prompt`                           | Cadena opcional                                  | Indicación de texto o letra para la nueva pista; puede omitirse para música puramente instrumental.                                                                                                                                       |
| `replace_section`                    | `prompt` / `replacement_lyrics`    | Cadena opcional                                  | El primero es la letra de la canción original o el texto de contexto, y el segundo es la nueva letra para el intervalo de reemplazo; cuando se omiten, se pasan cadenas vacías.                                                                                                                      |
| `replace_section`                    | `fixed`                            | Booleano opcional, predeterminado `false`                       | Solicita un reemplazo de longitud fija; cuando es `true`, el intervalo debe ser menor de 26 segundos, y el modelo seleccionado podría no ser compatible. El ejemplo real de esta vez utiliza el modo predeterminado; `fixed=true` aún no ha sido verificado.                                                                                    |
| `commit_candidate`                   | `operation_id` / `candidate_id`    | Cadena obligatoria                                  | Se toman respectivamente de `data.operation_id` en el estado final de la generación y de `data.candidates[].id` seleccionado; el candidato debe pertenecer a la versión actual del proyecto.                                                                                    |
| `commit_candidate`                   | `track_id`                         | Cadena obligatoria                                  | El candidato de nueva pista debe enviarse a la **pista vacía guardada antes de la generación**; el candidato de reemplazo local se envía a la pista original que contiene el único fragmento fuente.                                                                                                              |
| `commit_candidate`                   | `start_beats` / `end_beats`        | Números no negativos opcionales solo para candidatos de nueva pista                           | Especifican la posición del nuevo fragmento en la línea de tiempo del proyecto; al omitirse, se utiliza el punto de inicio del fragmento fuente y se calcula el punto final según la duración real del candidato. No debe superponerse con fragmentos existentes en la pista de destino. **Los candidatos de reemplazo local deben omitirse**.                                                                                      |
| `commit_candidate`                   | `name` / `gain`                    | Cadena／número no negativo opcional solo para candidatos de nueva pista                       | Nombre del fragmento generado y coeficiente de volumen; `gain` tiene como valor predeterminado 1.                                                                                                                                  |
| `render`                             | `title`                            | Cadena obligatoria                                  | Título del audio exportado.                                                                                                                                                   |
| `render`                             | `lyrics` / `tags`                  | Cadena opcional                                  | Texto de la letra y descripción de estilo durante la exportación; la letra tiene como valor predeterminado `[Instrumental]`.                                                                                                                      |
| `render`                             | `start_beats` / `end_beats`        | Números no negativos opcionales, el final debe ser mayor que el inicio                         | Exporta el rango de pulsos del proyecto; al omitirse, toma el punto de inicio más temprano y el punto final más tardío de todos los fragmentos audibles. Los fragmentos silenciosos no participan, y cuando existen pistas solo se seleccionan las pistas solo.                                                                                             |

La generación solo produce candidatos, **no los coloca automáticamente en el proyecto**. `commit_candidate` comprobará que el candidato siga perteneciendo a la versión actual. Los candidatos de reemplazo local solo pueden enviarse automáticamente cuando su duración real puede coincidir de forma fiable con el audio fuente completo o el intervalo seleccionado; si no coinciden, se conserva el proyecto original y se devuelve un error, y no se puede forzar el empalme adivinando manualmente los pulsos.

## 2026-10-09 Solicitudes y respuestas reales

Los siguientes cuerpos de solicitud y campos de respuesta proceden de llamadas reales del mismo proyecto. Cada grupo de JSON corresponde, en orden, a la solicitud, la respuesta de aceptación (si es asíncrona) y la respuesta del estado final de la tarea. Para facilitar la lectura, las respuestas solo incluyen los campos necesarios para completar este flujo; no se muestran los campos de cuenta, uso y duración. Los ID de ejemplo pertenecen a esta aplicación de prueba; al integrarse, se deben usar los ID devueltos por las propias solicitudes y un nuevo `Idempotency-Key`.

### 1. Crear y leer un proyecto vacío: `create`, `retrieve`

Solicitud de `create`:

```json
{
  "action": "create",
  "title": "Suno Projects Documentation Verification 2026-10-09"
}
```

```json
{
  "success": true,
  "trace_id": "42408a82-988b-4127-ba68-9b89348a7c56",
  "data": {
    "id": "af0e104a-2a4c-40e0-9c70-7614566824a6",
    "title": "Suno Projects Documentation Verification 2026-10-09",

      "tracks": [],
      "timing": {
        "bps": 2
      }
    }
  }

```

### 5. Guardar la pista vacía que recibe candidatos

Los candidatos de `generate_track` están vinculados a la versión actual del proyecto. Esta vez, primero se utiliza el `state` **completo** obtenido mediante `retrieve` como base, se añade la siguiente pista vacía real a `state.tracks` y luego se guarda con `save`; los demás campos existentes se conservan sin cambios:

```json
{
  "id": "bdec15b5-ce96-43fa-b681-26298e013b06",
  "type": "audio",
  "name": "Generated piano",
  "clips": [],
  "takeLanes": [],
  "mute": false,
  "solo": false,
  "amplitude": 1,
  "instrument": {
    "type": "song"
  },
  "color": "#7251F7"
}
```

## Errores y recuperación

| Resultado                                                                            | Significado                          | Siguiente paso                                    |
| ----------------------------------------------------------------------------- | --------------------------- | -------------------------------------- |
| `project_version_conflict` / `project_candidate_stale`（409）                   | La versión del proyecto ha cambiado, o el candidato no pertenece a la versión actual.         | `retrieve` el proyecto más reciente y vuelva a planificar las modificaciones; no reproduzca candidatos antiguos.        |
| `bad_request` / `studio_state_invalid` / `studio_model_unsupported`（normalmente 400）   | Los parámetros, el estado de la pista, la duración del candidato o el modelo no coinciden con la operación.      | Consulte el error del estado final de la tarea, corrija la entrada; conserve el proyecto original cuando el candidato no pueda ensamblarse de forma segura.          |
| `studio_audio_unavailable` / `studio_access_denied` / `content_rejected`（403） | El audio referenciado no puede usarse para la operación del proyecto, no hay permiso de acceso, o la revisión de contenido lo rechazó. | Compruebe la fuente de audio y el `trace_id` de la tarea; no equipare un candidato ya generado con que la canción completa pueda exportarse. |
| `too_many_requests`（429）                                                      | La solicitud está limitada por frecuencia.                   | Consulte primero la tarea original y luego decida si inicia una nueva operación con una nueva clave de idempotencia.                |
| `studio_unavailable` / `studio_model_unavailable`（503）                        | El procesamiento del proyecto o el modelo seleccionado no están disponibles temporalmente.             | Conserve el resultado de la tarea original; vuelva a intentarlo explícitamente más tarde, sin cambiar automáticamente de modelo.                |
| `studio_processing_failed` / tiempo de espera（500/504）                                      | El procesamiento falló o el estado final es incierto.                 | Consulte mediante `task_id` o la clave de idempotencia original para evitar una generación cobrada duplicada.          |

Los proyectos y candidatos están vinculados a la aplicación y al entorno de ejecución que los crearon, y no se debe asumir su reutilización entre aplicaciones ni la conmutación automática por error. Conserve de forma persistente la URL de audio final exportada correctamente y mantenga el `trace_id` para facilitar la investigación.
