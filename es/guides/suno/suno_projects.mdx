`POST https://api.acedata.cloud/suno/projects` es la interfaz Beta para gestionar proyectos multipista. Se distinguen la creación, guardado, generación de candidatos, envío de candidatos y exportación mediante `action`.

```http
POST /suno/projects
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
Idempotency-Key: <每次写操作的新 UUID>
```

Excepto `retrieve`, **cada operación requiere** `Idempotency-Key`. La misma clave y la misma solicitud solo vuelven a leer el resultado original; la misma clave con solicitudes diferentes devuelve 409. Cuando una generación con coste encuentra un tiempo de espera de red o el resultado del envío es incierto, primero consulte usando el ID de tarea original o la misma clave de idempotencia; no cambie directamente la clave para reenviar.

## Identificadores y unidades de tiempo

| Nombre                         | De dónde obtenerlo                                                                          | Dónde usarlo                                      |
| ------------------------------ | ------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `id`                           | `data.id` de la respuesta de `create`                                                      | Todas las solicitudes posteriores del proyecto actual |
| `version_id`                   | `data.version_id` del último `retrieve`, `save`, `add_track`, `commit_candidate` o `remove_track` | Modificación, generación de candidatos y exportación; se debe usar la versión más reciente |
| `audio_id` / `source_audio_id` | `response.data.candidate.audio_id` en el estado final de `upload`, o un ID de audio completado existente | Referenciar el audio original al usar `add_track`, generar o reemplazar |
| `render_audio_id`              | `response.data.audio_id` en el estado final de `render`                                    | Referencia de mezcla del proyecto para `generate_track` |
| `operation_id`                 | `response.data.operation_id` en el estado final de `generate_track` o `replace_section`   | `commit_candidate`; normalmente es igual al `task_id` de la tarea de generación, pero se debe leer el valor devuelto |
| `candidate_id`                 | `response.data.candidates[].id` en el estado final de generación                          | Seleccionar un candidato para enviar             |
| `track_id`                     | `data.state.tracks[].id` del proyecto                                                      | Enviar un candidato o eliminar una pista         |
| `task_id`                      | Respuesta de envío de la operación asíncrona                                               | Usar `/suno/tasks` para consultar el estado final; no es un ID de proyecto |

`start_seconds` / `end_seconds` son **segundos dentro del audio fuente**; `start_beats` / `end_beats` son **pulsos en la línea de tiempo del proyecto**. `state.timing.bps` es el número de pulsos por segundo, con un valor predeterminado de 2. Por ejemplo, un fragmento de 41 segundos que comienza en el pulso 0 tiene como punto final predeterminado el pulso 82. El intervalo en segundos de `generate_track` se usa para especificar la referencia de generación y no garantiza que el candidato tenga solo la duración de dicho intervalo.

## Flujo de operaciones

| Orden | `action`                             | Función                         | Método de retorno         |
| --- | ------------------------------------ | -------------------------- | ------------ |
| 1   | `create`                             | Crear un proyecto vacío                      | Datos síncronos del proyecto       |
| 2   | `retrieve`                           | Leer la versión más reciente y el `state` completo          | Datos síncronos del proyecto       |
| 3   | `save`                               | Guardar por primera vez o guardar globalmente el `state` modificado      | Datos síncronos del proyecto       |
| 4   | `upload`                             | Crear un recurso desde una dirección de audio HTTPS           | Tarea asíncrona         |
| 5   | `add_track`                          | Colocar el audio del recurso en el proyecto                  | Tarea asíncrona, actualiza la versión    |
| 6   | `save`                               | Si se necesitan recibir candidatos de nueva pista, primero guardar una pista objetivo vacía        | Datos síncronos del proyecto, actualiza la versión  |
| 7   | `render`                             | Exportar las pistas audibles actuales y obtener la referencia de mezcla `audio_id` | Tarea asíncrona         |
| 8   | `generate_track` o `replace_section` | Generar candidatos de nueva pista o candidatos de reemplazo local respectivamente            | Tarea asíncrona, no modifica temporalmente el proyecto  |
| 9   | `commit_candidate`                   | Seleccionar y enviar un candidato                  | Tarea asíncrona, actualiza la versión tras completarse |
| Opcional  | `remove_track`                       | Eliminar la pista especificada                     | Datos síncronos del proyecto, actualiza la versión  |

Si solo se realiza un reemplazo local, basta con tener audio fuente disponible y no es necesario ejecutar primero `render`; si el audio fuente ya está en el proyecto, también se pueden omitir `upload` y `add_track`. `render_audio_id` es solo una referencia obligatoria para `generate_track`.

Al enviar una operación asíncrona, primero se devuelve `{ "task_id": "...", "trace_id": "..." }`, lo cual **no indica que la generación haya tenido éxito**. Sondeo:

```http
POST /suno/tasks
Content-Type: application/json

{"action":"retrieve","id":"上一步返回的 task_id"}
```

Solo se considera exitoso cuando el registro de tarea tiene `finished_at` y su `response.success` es `true`; cuando `response.success=false`, lea `response.error`. Aunque `save` puede incluir `task_id`, se completa de forma síncrona dentro de esta interfaz. `upload`, `render`, `generate_track` y `replace_section` no modifican la versión del proyecto; tras el éxito de `save`, `add_track`, `commit_candidate` y `remove_track`, se debe obtener el nuevo `version_id`.

## Convenciones de solicitud

| Parámetro                | Tipo y ámbito de aplicación                                                                                   | Descripción                                                              |
| ----------------- | ----------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| `action`          | Cadena obligatoria                                                                                     | Se fija en uno de los nombres de operación enumerados en esta página; una solicitud ejecuta solo una operación.                                      |
| `id`              | Cadena obligatoria excepto para `create`                                                                         | ID del proyecto, procedente de `create.data.id`.                                      |
| `version_id`      | Cadena obligatoria al modificar, generar candidatos o exportar; puede omitirse en el primer `save` de un proyecto vacío                                                         | Use la versión más reciente; las versiones antiguas serán rechazadas. `retrieve` no la necesita.                                 |
| `Idempotency-Key` | Encabezado de solicitud obligatorio excepto para `retrieve`, de 1 a 128 caracteres                                                              | Use una nueva clave para cada operación nueva; la misma clave y solicitud vuelven a leer el resultado original, sin volver a generar ni cobrar.                                   |
| `async`           | Booleano opcional para `upload`, `add_track`, `generate_track`, `replace_section`, `commit_candidate`, `render` | Estas operaciones siempre son asíncronas; `false` tampoco convertirá la generación en síncrona.                                    |
| `callback_url`    | URL opcional para operaciones asíncronas                                                                                | Recibe notificaciones del estado final; si se omite, consulte `/suno/tasks` según el `task_id`. Aún se debe comprobar `response.success`. |

Los siguientes ejemplos muestran de forma encadenada la transmisión de ID y versiones entre las operaciones. Las respuestas solo enumeran los campos relacionados con el paso actual; durante la integración, sustituya los ID de ejemplo por los valores de respuesta de la aplicación actual.

## Guardar estado del proyecto

| Parámetro | Tipo y descripción |
|---|---|
| `state` | Objeto obligatorio. Envíe el **estado completo del proyecto**, no un parche parcial; use como base el `data.state` devuelto por la operación de lectura o modificación más reciente, y conserve los campos desconocidos. |
| `title` | Cadena opcional; cuando se omite, se conserva `state.title`; si tampoco existe, se utiliza el título predeterminado. |
| `version_id` | Puede omitirse al guardar por primera vez un nuevo proyecto vacío; posteriormente debe utilizarse la versión más reciente. |

`state.timing.bps` debe ser un número positivo; el valor predeterminado es 2. `state.tracks` es un arreglo de pistas; el `clipId` de los fragmentos de audio existentes hace referencia al ID de audio, y `startBeats`, `endBeats`, `readStartBeats` utilizan unidades de pulsos del proyecto. La forma más segura de editar es leer el `state` completo, modificar solo la pista o el fragmento objetivo y luego realizar un `save` global. Una nueva pista objetivo vacía debe tener al menos un `id` único, `type:"audio"`, `clips:[]`; consulte el ejemplo de estructura completa de una pista vacía en “Generar una nueva pista de audio”. No use directamente los puntos de pulso de los resultados de análisis de audio como coordenadas de la línea de tiempo del proyecto.

## Subir audio y agregar una pista

| Operación | Parámetro | Tipo y descripción |
|---|---|---|
| `upload` | `audio_url` | URL HTTPS obligatoria, que apunte a audio públicamente accesible y que usted tenga derecho a utilizar. El `candidate.audio_id` en el estado final puede utilizarse para agregar una pista. |
| `add_track` | `audio_id` | Cadena obligatoria; el ID de audio de material ya completado, no una URL. |
| `add_track` | `name`、`color` | Cadenas opcionales; el nombre de la pista toma por defecto el título del audio, se recomienda el color `#RRGGBB`, y el valor predeterminado es `#7251F7`. |
| `add_track` | `title` | Cadena opcional; también modifica el título del proyecto, normalmente se omite. |
| `add_track` | `start_beats`、`end_beats` | Números no negativos opcionales; el punto final debe ser mayor que el punto inicial; por defecto comienza desde el pulso 0, y el punto final se calcula según la duración del audio y `timing.bps`. |
| `add_track` | `gain` | Número no negativo opcional, el valor predeterminado es 1; el coeficiente de volumen del fragmento y la pista. |

## Generar una nueva pista de audio

Los candidatos y las generaciones están vinculados a la versión del proyecto en el momento de la generación. Primero guarde la pista vacía que recibirá los candidatos, luego exporte la mezcla actual como referencia de generación; una vez completada la generación, seleccione un candidato para enviarlo a esa pista vacía.

### Reservar pista objetivo: `save`

Los candidatos de `generate_track` están vinculados a la versión actual del proyecto. Sobre el `state` **completo** devuelto en el estado final del `add_track` anterior, agregue la siguiente pista vacía a `state.tracks`, luego guárdela con `save`; conserve sin cambios los demás campos existentes:

### Generar candidatos: `generate_track`

Cada vez se envían exactamente 2 candidatos.

| Parámetro | Tipo y descripción |
|---|---|
| `source_audio_id` | Obligatorio; ID del audio fuente completado. Primero agregue el audio fuente al proyecto, y después podrá determinar la posición de los candidatos. |
| `render_audio_id` | Obligatorio; `response.data.audio_id` en el estado final de `render` anterior, no la URL del audio. |
| `model` | Obligatorio; se puede elegir entre `chirp-v3-5`, `chirp-v4`, `chirp-v4-5`, `chirp-v4-5-plus`, `chirp-v5`, `chirp-v5-5`, `chirp-v6`, `chirp-v6-wild`, `chirp-v6-mini`. La disponibilidad de combinaciones específicas se determina por el estado final de la tarea. |
| `start_seconds`、`end_seconds` | Números obligatorios, `0 ≤ start_seconds < end_seconds`; el intervalo en segundos dentro del audio fuente, no los compases del proyecto, ni garantiza la duración de salida. |
| `stem_control_tags` | Cadena obligatoria; descripción de la nueva voz, por ejemplo `add Piano`, `add Drums`, `add Bass`, no es una enumeración fija. |
| `instrumental`、`vocal_gender` | Opcionales; el valor predeterminado para instrumental puro es `true`, la preferencia vocal puede ser `f`, `m`, `unspecified`, el valor predeterminado es `unspecified`. |
| `title`、`tags`、`negative_tags`、`prompt` | Cadenas opcionales; son respectivamente el título del candidato, el estilo deseado, los estilos que se deben evitar, y la indicación de texto o letra de la nueva voz. |

### Adoptar candidato: `commit_candidate`

| Parámetro | Tipo y descripción |
|---|---|
| `operation_id` | Obligatorio; `data.operation_id` del estado final de la tarea de generación. |
| `candidate_id` | Obligatorio; el `data.candidates[].id` seleccionado. |
| `track_id` | Obligatorio; `state.tracks[].id` de una pista vacía guardada antes de la generación. |
| `start_beats`、`end_beats` | Opcional para candidatos de nueva pista; especifica el rango de pulsos del proyecto y no puede superponerse con fragmentos existentes en la pista de destino. Si se omite, se conserva el punto de inicio del fragmento fuente y se calcula el punto final según la duración del candidato. |
| `name`、`gain` | Opcional para candidatos de nueva pista; nombre del fragmento y coeficiente de volumen no negativo; `gain` es 1 por defecto. |

La generación solo produce candidatos y **no los coloca automáticamente en el proyecto**. `commit_candidate` comprobará que el candidato siga perteneciendo a la versión actual. Los candidatos de reemplazo parcial solo pueden enviarse automáticamente cuando su duración real puede coincidir de forma fiable con el audio fuente completo o el intervalo seleccionado; si no coincide, se conserva el proyecto original y se devuelve un error, y no se puede forzar el empalme adivinando manualmente los pulsos.

## Reemplazar fragmentos existentes

`replace_section` puede usar directamente el audio fuente existente, sin necesidad de exportar primero la mezcla. La generación solo devuelve candidatos; al enviar, seleccione la pista original que contiene el único fragmento fuente.

| Parámetro | Tipo y descripción |
|---|---|
| `source_audio_id` | Obligatorio; el ID del audio fuente completado que se va a reemplazar. |
| `model` | Obligatorio; use los modelos públicos enumerados en «Generar candidatos»; la disponibilidad del modelo y de la operación está sujeta al estado final de la tarea. |
| `start_seconds`、`end_seconds` | Números obligatorios, `0 ≤ start_seconds < end_seconds ≤ duración del audio fuente`; intervalo en segundos dentro del audio fuente. |
| `prompt`、`replacement_lyrics` | Cadenas opcionales; la primera son las letras originales o el contexto, y la segunda son las nuevas letras para el intervalo de reemplazo. |
| `title`、`tags`、`negative_tags` | Cadenas opcionales; título del candidato, estilo deseado y estilos que deben evitarse. |
| `fixed` | Booleano opcional, `false` por defecto; cuando se establece en `true`, el intervalo debe ser inferior a 26 segundos y es posible que el modelo no lo admita. |

## Errores y recuperación

| Resultado | Significado | Siguiente paso |
|---|---|---|
| `project_version_conflict` / `project_candidate_stale`(409) | La versión del proyecto ha cambiado o el candidato no pertenece a la versión actual. | `retrieve` Último proyecto y vuelve a planificar las modificaciones; no reproduzcas candidatos antiguos. |
| `bad_request` / `studio_state_invalid` / `studio_model_unsupported` (normalmente 400) | Los parámetros, el estado de la pista, la duración del candidato o el modelo no coinciden con la operación. | Revisa el error del estado final de la tarea y corrige la entrada; conserva el proyecto original si el candidato no puede concatenarse de forma segura. |
| `studio_audio_unavailable` / `studio_access_denied` / `content_rejected`(403) | El audio de referencia no está disponible para esta operación del proyecto, no tienes permisos de acceso o la revisión de contenido lo rechazó. | Verifica la fuente de audio y la tarea `trace_id`; no equipares un candidato ya generado con una canción completa exportable. |
| `too_many_requests`(429) | La solicitud está limitada por frecuencia. | Consulta primero la tarea original y luego decide si inicias una nueva operación con una nueva clave de idempotencia. |
| `studio_unavailable` / `studio_model_unavailable`(503) | El procesamiento del proyecto o el modelo seleccionado no está disponible temporalmente. | Conserva el resultado de la tarea original; vuelve a intentarlo explícitamente más tarde, sin cambiar automáticamente de modelo. |
| `studio_processing_failed` / tiempo de espera agotado (500/504) | El procesamiento falló o el estado final es incierto. | Consulta mediante `task_id` o la clave de idempotencia original para evitar generaciones duplicadas con cobro. |

Los proyectos y candidatos están vinculados a la aplicación que los creó; usa la aplicación original para acceder a ellos. Conserva de forma persistente la URL final del audio exportado correctamente y mantén `trace_id` para facilitar la investigación de problemas.
