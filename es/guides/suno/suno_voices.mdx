title: "Guía de integración de la API de clonación de voz de Suno"

SUNO nos permite crear personajes de voz personalizados a través de cualquier archivo de audio, implementando la clonación de voz para la generación de música. A diferencia de la API Persona existente (que utiliza el `audio_id` generado por Suno), esta API acepta un `audio_url` públicamente accesible, es decir, tu propia grabación de voz. Este documento explica el método de integración de la API de clonación de voz.

En las rutas de creación que admiten la consulta de timbre de voz, se puede usar la aplicación original y la identidad del llamador para pasar el `persona_id` de los resultados de creación a `POST /suno/availability`. Cuando la cuenta asociada está en línea, devuelve `data.available=true`; cuando se confirma que está fuera de línea, devuelve `data.available=false`. [Guía de consulta de disponibilidad de timbre de voz](https://platform.acedata.cloud/documents/suno-availability-integration)

## Primer paso: crear un personaje de voz

Facturación: después de crear correctamente un personaje de voz, el coste estándar de cada solicitud es de **0.15 Credits**. Los descuentos de consumo aplicables se basarán en la factura real, y las solicitudes fallidas no se cobrarán.

Esta API tiene tres parámetros de entrada: `audio_url` (obligatorio), que es una URL de archivo de audio MP3 o WAV públicamente accesible que contiene una voz humana clara de una sola persona; `name` y `description` (opcionales), que son el nombre y la descripción del personaje de voz.

> **Requisitos del archivo de audio**
> - El formato de audio debe ser `WAV` o `MP3`
> - La duración del audio debe estar entre `10~240 segundos`; se recomienda usar material vocal limpio y sin acompañamiento de una sola persona de `30~60 segundos`
> - El audio debe contener una **voz hablada o cantada clara y reconocible de una sola persona**
> - Asegúrate de evitar **ruido de fondo, acompañamiento, eco y reverberación**; las canciones completas con acompañamiento normalmente no pueden superar la verificación de huella vocal
> - No incluyas **varios hablantes** ni **múltiples voces**
> - El material con volumen demasiado bajo, voz poco clara o ruido excesivo puede provocar **fallos de clonación** o **resultados de generación deficientes**
> **Descripción de las restricciones de uso**
> - Los personajes de voz creados mediante la carga de audio son **recursos privados**
> - Este personaje de voz **no admite reutilización entre cuentas**
> - Se recomienda usarlo lo antes posible después de crearlo correctamente; si no se usa durante mucho tiempo, puede **caducar o dejar de estar disponible**
> - El `name` devuelto se genera automáticamente por el sistema; toma como referencia el `persona_id` devuelto

> **Gestionar los fallos según la marca explícita de reintento**
> `retryable` en el objeto de error es un campo booleano opcional. Cuando `error.retryable` es `true`, indica que este fallo permite volver a solicitar más tarde usando el mismo material y los mismos parámetros. Los rechazos explícitos por servicio ocupado o algunos fallos temporales de verificación de huella vocal pueden incluir esta marca; se recomienda utilizar intervalos de espera progresiva y limitar el número de reintentos.
> Cuando `retryable` sea `false` o el campo no exista, no reenvíes automáticamente basándote únicamente en HTTP 500, `busy` o el texto del error. Los problemas de formato, duración, claridad, grabaciones duplicadas y revisión de contenido deben corregirse primero; en caso de tiempo de espera de envío, interrupción de conexión o resultado de creación poco claro, se debe priorizar la consulta de la tarea usando el `task_id` original para evitar crear timbres de voz duplicados. Las solicitudes fallidas no se cobrarán, y las solicitudes reenviadas correctamente se cobrarán según las reglas normales.

```bash
curl -X POST 'https://api.acedata.cloud/suno/voices' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "audio_url": "https://cdn.acedata.cloud/suno_demo.mp3",
  "name": "My Voice",
  "description": "单人清晰人声示例"
}'
```

> El anterior `https://cdn.acedata.cloud/suno_demo.mp3` es material de ejemplo que puede llamarse directamente (MP3, 41 segundos, voz sin acompañamiento de una sola persona).
> Si necesitas un ejemplo en formato `WAV`, puedes utilizar
> `https://cdn.acedata.cloud/uploads/82d23b97-ec1c-4b41-91b8-989fc51f8765` (WAV, 41 segundos, mono 44.1kHz).

El resultado es el siguiente:

```json
{
  "success": true,
  "task_id": "0fa609a6-c8d9-4bb5-8574-e4c93bb55d02",
  "data": {
    "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16",
    "name": "VOICE_20260803037676",
    "is_public": false
  }
}
```

Como se puede ver, el campo `persona_id` de `data` es el ID del personaje de voz creado. El campo `is_public` siempre es `false`, porque los personajes de voz creados mediante la carga de audio son privados. Ten en cuenta que el `name` devuelto se genera automáticamente por el sistema; posteriormente, utiliza `persona_id` para hacer referencia a este personaje de voz.

## Segundo paso: usar el personaje de voz para generar música

Después de tener el ID del personaje de voz, podemos usar la [API de generación de audios de Suno](https://platform.acedata.cloud/documents/suno-audios) para generar música. Establece `action` como `generate` y `persona_id` como el ID del personaje de voz devuelto anteriormente; la canción generada utilizará la voz clonada para cantar.

> **Nota:** La clonación de voz solo admite los modelos `chirp-v4-5` y superiores (como `chirp-v4-5`, `chirp-v5`, `chirp-v5-5`), y no admite `chirp-v4`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/audios' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "action": "generate",
  "model": "chirp-v5-5",
  "prompt": "A warm synth-pop song about city nights",
  "persona_id": "1ab79a71-a229-4350-8f02-402ff02eac16"
}'
```

El resultado es el siguiente:

```json
{
  "success": true,
  "task_id": "53d8a334-a972-43c5-895e-60c4454e88d5",
  "data": [
    {
      "id": "16463960-077c-4700-bbb3-3c7897b943d3",
      "title": "Soft Neon on My Skin",
      "audio_url": "https://cdn.acedata.cloud/assets/examples/fish/5ade0339-5f11-487e-aacc-06a908271706-8e3fcb0e5547.mp3",
      "image_url": "https://cdn.acedata.cloud/e724d7f13d.png",
      "model": "chirp-v5-5",
      "state": "succeeded",
      "prompt": "A warm synth-pop song about city nights",
      "duration": 156.28
    }
  ]
}
```

`persona_id` puede utilizarse para la generación con `generate`, así como para versiones con `cover` / `upload_cover`. No es necesario completar `vocal_gender` al especificar una voz; la similitud de voz sigue dependiendo del material de referencia y del resultado generado.

Las voces creadas a través de esta interfaz son recursos privados. Antes de versionar una canción existente, llama primero a `/suno/upload`, pasando el `audio_url` de la canción original y el `persona_id` de esta voz; después de cargarla correctamente, llama a `/suno/audios` con el `data.audio_id` devuelto y el mismo `persona_id`:
```json
{
  "action": "upload_cover",
  "model": "chirp-v6",
  "audio_id": "<audio_id devuelto después de la carga asociada con esta voz>",
  "persona_id": "<persona_id devuelto por la interfaz de creación de voz>",
  "custom": true,
  "instrumental": false,
  "lyric": "[Verse]\nIntroduce la letra que se va a cantar",
  "async": true
}
```

La creación de voz, la carga de la canción original y la versión deben usar el mismo canal de servicio. No reutilices directamente un ID de canción anterior que no esté asociado con esta voz privada; consulta los detalles en [Audio de referencia para carga de Suno](https://platform.acedata.cloud/documents/suno-upload).
