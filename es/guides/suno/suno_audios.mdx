Con la expansión de las aplicaciones de IA, diversos programas de IA se han popularizado gradualmente. La IA ha ido penetrando poco a poco en todos los aspectos del trabajo y la vida de las personas. Y las industrias involucradas por la IA también son cada vez más numerosas, desde la escritura inicial, hasta la educación médica, y ahora la música.

Suno es una plataforma profesional de creación de canciones y música con IA de alta calidad. Los usuarios solo necesitan introducir indicaciones de texto simples para generar canciones con voces según el estilo del género y la letra. Este generador de música con IA fue desarrollado por miembros de equipos de conocidas empresas tecnológicas como Meta, TikTok y Kensho, con el objetivo de que no se necesiten instrumentos ni herramientas y que todos puedan crear música maravillosa.

> Los límites de `lyric` y `style` de la tabla anterior son los límites máximos en el modo personalizado (`custom` es `true`). El modo de inspiración no personalizado (`custom` es `false`) solo rellena `prompt`, y su límite de longitud es de 500 caracteres (igual para todos los modelos).

Suno ahora admite `chirp-v6`, `chirp-v6-wild` y `chirp-v6-mini`. Se recomienda utilizar `chirp-v6`; los nombres de modelos antiguos siguen siendo compatibles.

Sin embargo, Suno oficialmente no proporciona una API. AceDataCloud proporciona un conjunto de API de Suno, simulando la integración oficial de Suno, que permite generar de forma cómoda y rápida la música deseada.

## Solicitud y uso

Para utilizar Suno Audios Generation API, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión ni se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; al completarlo, volverá automáticamente a la página actual.

**Un API Token puede llamar a todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud otorgará créditos gratuitos para una experiencia sin costo; cuando los créditos sean insuficientes, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Uso básico

Para la canción que desee, puede introducir arbitrariamente un fragmento de texto; por ejemplo, si quiero generar una canción sobre Navidad, puedo introducir `a song for Christmas`, como se muestra en la imagen:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Aquí podemos ver que configuramos los Request Headers, incluyendo:

- `accept`: qué formato de resultado de respuesta se desea recibir; aquí se rellena con `application/json`, es decir, formato JSON.
- `authorization`: la clave para llamar a la API; después de solicitarla, puede seleccionarse directamente desde el menú desplegable.

Además, configuramos el Request Body, incluyendo:
- `action`: tipo de tarea de audio, el valor predeterminado es `generate`. Admite operaciones como generación, continuación, versión, combinación, separación de pistas, adición de pistas, extracción de pistas especificadas, generación de efectos de sonido y ajuste de velocidad, todas llamadas de forma unificada mediante `POST /suno/audios`.
- `prompt`: texto de indicación del modo de inspiración oficial de Suno (efectivo cuando `custom` es `false`), máximo 500 caracteres.
- `model`: el modelo para esta tarea de generación de música. La serie v6 incluye `chirp-v6`, `chirp-v6-wild` y `chirp-v6-mini`; los nombres de modelos antiguos siguen siendo compatibles.
- `max_mode`: modo de generación mejorada. `generate` solo se habilita cuando tanto `custom` como `max_mode` son `true`, con un costo de 1.12 Credits; `add_stem` puede habilitarse directamente, con un costo de 1.344 Credits. Cuando se desactiva o se omite, los costos son respectivamente 0.56 y 0.672 Credits.
- `variety`: intensidad de diversidad de los resultados generados, opcional entre `off`, `normal`, `high`, `extra`, `max`. Solo se usa para `generate` y `add_stem`; pasarlo a otras action devolverá 400.
- `lyric`: contenido de letras del modo personalizado oficial de Suno. `chirp-v3-5` y `chirp-v4` tienen un máximo de 3000 caracteres; `chirp-v4-5` y superiores (incluidos `chirp-v5`, `chirp-v5-5`) tienen un máximo de 5000 caracteres.
- `custom`: si se utiliza el modo personalizado, el valor predeterminado es: `false`.
- `instrumental`: opción de música instrumental del modo de inspiración oficial de Suno.
- `title`: título de la música del modo personalizado oficial de Suno. `chirp-v3-5`, `chirp-v4` tienen un máximo de 80 caracteres; `chirp-v4-5` y superiores tienen un máximo de 100 caracteres.
- `style`: estilo musical del modo personalizado oficial de Suno. `chirp-v3-5` y `chirp-v4` tienen un máximo de 200 caracteres; `chirp-v4-5` y superiores (incluidos `chirp-v5`, `chirp-v5-5`) tienen un máximo de 1000 caracteres.
- `negative_tags`: estilos musicales o géneros que se desean excluir durante la generación personalizada, también puede utilizarse para `replace_section`. Actualmente, esta interfaz no establece un límite fijo de caracteres para este campo; es posible que el contenido demasiado largo siga sin poder procesarse, se recomienda mantener la descripción concisa.
- `audio_weight`: peso de influencia de las características de audio o voz, rango de 0-1, `0` también es un valor válido. Puede usarse para operaciones como generación, continuación, versión, adición de pistas y consistencia de voz; cuando no hay audio de referencia o características de voz, el modelo puede reducir o ignorar este valor.
- `audio_id`: ID de la música de referencia, utilizado para operaciones posteriores como versión, continuación y separación de pistas. Los archivos de audio aún pueden descargarse, lo que no representa que el procesamiento posterior de este ID esté siempre disponible; si devuelve `suno_processing_unavailable`, conserve `task_id` y `trace_id` para contactar con soporte.
- `overpainting_start`/`overpainting_end`: tiempo de inicio y finalización para añadir voces a música instrumental existente, en segundos.
- `underpainting_start`/`underpainting_end`: tiempo de inicio y finalización para añadir acompañamiento a una interpretación a capela, en segundos.
- `persona_id`: ID de voz obtenido mediante la interfaz de creación de Persona o voz, no es el `audio_id` de la canción.
- `continue_at`: límite de continuación, en segundos. Por ejemplo, 213.5 indica que se comienza a generar el fragmento posterior desde los 3 minutos y 33.5 segundos. `lyric` y `style` solo guían el contenido nuevo después del límite y no reemplazarán las letras o el canto antes del límite en el audio fuente.
- `style_influence`: influencia del estilo en el modo personalizado, rango de 0-1; cuanto mayor sea, normalmente más se ajustará al estilo seleccionado; `0` se transmitirá como un valor válido.
- `replace_section_end`: tiempo final del fragmento de reemplazo.
- `replace_section_start`: tiempo de inicio del fragmento de reemplazo.
- `vocal_gender`: controla la preferencia por voz femenina o masculina, voz femenina `f`, voz masculina `m`, efectivo en modelos 4.5 y superiores; es un elemento de preferencia y no se garantiza que se siga estrictamente.
- `weirdness`: nivel de rareza en el modo personalizado, rango de 0-1; cuanto mayor sea, normalmente será más creativo y experimental; `0` se transmitirá como un valor válido.
- `duration`: duración esperada de la canción, en segundos, debe ser un entero, con un rango de 10 a 360. Actualmente solo `generate` utiliza este parámetro; el efecto específico depende del modo y del modelo. Es una indicación de tendencia y no una restricción estricta: el modelo la tomará como referencia, pero no se garantiza que se alcance; la duración real del producto final prevalece según el campo `duration` en la respuesta y normalmente es inferior al valor esperado.

### Ámbito de aplicación del ID de voz

`generate`, `cover`, `upload_cover`, `artist_consistency`, `artist_consistency_vox` pueden utilizar `persona_id`. Las dos últimas action deben proporcionar `persona_id`; también pueden proporcionar simultáneamente el `audio_id` de la canción utilizada al crear esta Persona.

`extend`, `upload_extend` no utilizan un `persona_id` adicional. Que `mashup`, `inspo` admitan ID de voz depende del canal de servicio seleccionado; no se garantiza que otras action apliquen este campo, utilícelo según las instrucciones de cada operación. `vocal_gender` es una preferencia de género opcional y no puede sustituir el ID de voz.

Las operaciones de creación posteriores requieren un `audio_id` fuente válido; `mashup` requiere al menos dos `mashup_audio_ids`. Cuando faltan las fuentes o los parámetros de tiempo necesarios, se devolverá HTTP 400.

### Ámbito de aplicación de los parámetros avanzados
| Parámetro                | Valores                                          | action compatibles                              | Descripción                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | Opcional                                      | Ajusta la experimentalidad, `0` es un valor válido; el efecto depende de la operación, el modo y el modelo      |
| `style_influence` | 0-1                                         | Opcional                                      | Ajusta la tendencia a seguir el estilo, `0` es un valor válido; el efecto depende de la operación, el modo y el modelo   |
| `audio_weight`    | 0-1                                         | Opcional                                      | Ajusta la influencia de las características de audio o voz; puede ser ignorado por el modelo si no hay información de referencia        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`, `add_stem`                   | Ajusta la diversidad de estilo entre los resultados                       |
| `max_mode`        | boolean                                     | `generate` (requiere `custom=true`), `add_stem` | Mejora la consistencia y se factura según el modo mejorado                     |
| `vocal_gender`    | `f` / `m`                                   | Operaciones de generación que admiten control vocal                             | Es una preferencia, no se garantiza que se siga estrictamente                       |
| `duration`        | Entero 10-360                                   | `generate`                              | Duración esperada; otras action actualmente no usan este campo, la duración real depende del resultado |

La plataforma validará los tipos de parámetros y los rangos de valores, pero no rechazará estos elementos de ajuste opcionales únicamente porque la action sea diferente; el efecto específico depende de la operación, el modo y el modelo.

- `lyric_prompt`: prompt para generar letras, solo tiene efecto cuando `custom` es `true` y no se proporciona `lyric`.
- `callback_url`: URL que necesita recibir los resultados mediante callback.
- `async`: opcional, cuando se establece en `true`, la interfaz devuelve inmediatamente `task_id`, no es necesario proporcionar `callback_url`, y posteriormente se obtienen los resultados mediante sondeo a través de la interfaz de consulta de tareas correspondiente.

## Función de generación personalizada de estilo de cantante

Si deseas usar un estilo de cantante para generar una canción, primero genera una canción mediante el uso básico anterior,
al final necesitas configurar esta canción como estilo de cantante, y luego debes acceder a [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) para generar un parámetro de id de estilo de cantante `persona_id` basándote en el ID de música generado oficialmente `audio_id`; los parámetros específicos se muestran en la siguiente imagen:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Después de completar, el código se genera automáticamente de la siguiente manera:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Luego puedes establecer el parámetro `action` como `artist_consistency` (si se trata del nuevo estilo de cantante Persona-v2-vox, `action` debe establecerse como `artist_consistency_vox`), e introducir el ID de la canción que necesita continuar generándose y el ID del estilo de cantante; el ejemplo de cumplimentación es el siguiente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "artist_consistency",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b",
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Función de continuar generación
Si desea continuar generando una canción de Suno ya generada, puede establecer el parámetro `action` en `extend` e introducir el ID de la canción que necesita continuar generando. El ID de la canción se obtiene según el uso básico; como se puede ver arriba, en este momento puede verse que el ID de la canción es:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Nota: aquí el `id` en la letra es el ID de la canción después de generarse. Si no sabe cómo generar una canción, puede consultar el uso básico anterior para generar una canción.

Si desea continuar generando una canción que usted mismo ha subido, puede establecer el parámetro `action` en `upload_extend` e introducir el ID de la canción personalizada subida que necesita continuar generando. El ID de la canción se obtiene utilizando la [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), como se muestra en la siguiente imagen:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

A continuación, debe completar la letra del fragmento de continuación y puede especificar el estilo:

- lyric: se utiliza únicamente para guiar la letra del fragmento recién generado después de `continue_at`; no reemplazará la letra anterior a ese punto temporal en el audio de origen.
- custom: completar con `true` representa la generación personalizada; este parámetro es false de forma predeterminada, lo que representa la generación usando `prompt`.
- style: el estilo de canción del fragmento de continuación, opcional.
- continue_at: límite de continuación, en segundos. Por ejemplo, 213.5 indica que los fragmentos posteriores comienzan a generarse desde los 3 minutos y 33.5 segundos.

El `continue_at` de `extend` y `upload_extend` debe ser mayor que 0, y admite segundos decimales, por ejemplo, `30.792`; no se redondeará al enviarlo.

> `extend` se utiliza para continuar creando después de una canción existente, no para cambiar la letra de toda la canción. Si desea que toda la canción use una letra nueva desde el principio, utilice `generate` para generarla de nuevo; si desea reinterpretarla tomando como referencia una canción existente, puede utilizar `cover`. Al introducir una letra nueva completa, la letra original anterior a `continue_at` seguirá sin reemplazarse.

El ejemplo de completado es el siguiente:

Después de completar, el código se genera automáticamente de la siguiente manera:

Cuando se continúa cerca del final de la canción en la práctica, este valor debe establecerse en el segundo deseado para comenzar la continuación, y solo se debe proporcionar en `lyric` el nuevo fragmento que se cantará después del límite.

## Versión de música

Cuando se continúa generando una canción basada en una canción existente, el estilo de la canción devuelta puede no ser muy adecuado. Si desea crear una versión de una canción generada previamente (también se admite música cargada de forma personalizada), debe utilizar el método de versión de música, y puede especificar el siguiente contenido:

- action: el contenido es `cover`; cuando se realiza una operación de versión sobre música cargada de forma personalizada, se debe especificar el contenido como: `upload_cover`.
- audio_id: el ID de la canción generada previamente.

Si necesita cantar una versión con una voz especificada, también puede proporcionar `persona_id`. Para las voces privadas creadas mediante `/suno/voices`, primero debe cargar la canción original en `/suno/upload` con el mismo `persona_id`, y luego utilizar el `audio_id` devuelto para realizar `upload_cover`. {

## Reemplazar fragmentos

Cuando, después de generar una canción, se necesita realizar una creación secundaria mediante una operación independiente de reemplazo de fragmentos de la canción, se puede realizar una operación de reemplazo sobre un fragmento de la canción.
> ⚠️ **Nota**: `replace_section_result_mode` tiene como valor predeterminado `full_song`: el sistema concatenará respectivamente 2 candidatos recién generados y devolverá 2 canciones completas. Si solo se necesitan los candidatos de fragmentos de reemplazo que aún no se han concatenado, establezca explícitamente como `candidates`, y luego seleccione un candidato para llamar a [concatenación de música](#concatenación-de-música).

La descripción de los parámetros es la siguiente:

- action: el contenido es `replace_section`.
- audio_id: el ID de la canción original (la canción fuente que se reemplaza).
- model: modelo de generación de canciones.
- lyric: la letra completa después del reemplazo (incluye el fragmento reemplazado y su contexto, manteniéndose consistente con el contenido de `prompt`).
- prompt: la nueva letra de la sección que necesita reemplazarse.
- style: el estilo de la canción, opcional.
- negative_tags: los estilos o géneros que se desean excluir, opcional.
- replace_section_start: el tiempo de inicio del fragmento reemplazado en la canción original (segundos), obligatorio y no debe ser menor que 0.
- replace_section_end: el tiempo de finalización del fragmento reemplazado en la canción original (segundos), obligatorio y debe ser mayor que el tiempo de inicio.
- replace_section_result_mode: modo de retorno, el valor predeterminado es `full_song`. `full_song` concatena respectivamente 2 candidatos y devuelve 2 canciones completas; `candidates` devuelve 2 fragmentos candidatos que aún no se han concatenado.

## Separación de voz e instrumental de todas las pistas

La tarea esperará a que se complete la generación de todas las pistas de audio antes de devolver el estado final de éxito. Que aparezca una dirección reproducible durante el procesamiento no significa que todo el grupo de pistas de audio ya se haya completado.

Cuando, después de generar una canción, se necesita realizar una operación de separación de voz e instrumental de todas las pistas, se puede especificar el siguiente contenido:

- action: el contenido es `all_stems`.
- audio_id: el ID de la canción generada anteriormente.

```json
{
  "action": "all_stems",
```

## Controlar la duración de la canción

De forma predeterminada, la duración de las canciones generadas la determina el propio modelo, normalmente entre 30 segundos y 4 minutos. Si se necesita un producto final más largo o más corto, se puede especificar la duración esperada mediante el parámetro `duration`, cuya unidad es segundos y cuyo valor es un número entero entre 10 y 360.

Este parámetro se utiliza para la generación de canciones en modo personalizado (`custom` es `true`). Cabe señalar especialmente que `duration` es una **indicación de tendencia, no una restricción rígida**: el modelo hará referencia a este valor al crear, pero no se garantiza que lo alcance; en pruebas reales, la duración efectiva suele ser claramente inferior al valor esperado, y las duraciones de las dos canciones devueltas por la misma solicitud también pueden diferir varias veces. Incluso para solicitudes completamente idénticas, las duraciones obtenidas mediante varios envíos también pueden tener diferencias grandes. Por lo tanto, no lo utilices como un control preciso de la duración; si se necesita una duración fija para el negocio, recorta o vuelve a intentarlo después de obtener el producto final.

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Cabe señalar que `duration` en la solicitud es la **duración esperada**, mientras que el campo `duration` de cada canción en los `data` de la respuesta es la **duración real** de esa canción. Ambos tienen el mismo nombre, pero significados diferentes; no se garantiza que la duración real sea igual al valor esperado. La longitud de la letra es uno de los principales factores que afectan la duración del producto final; si se necesita un producto final más largo, se recomienda proporcionar también una letra más completa.

La interfaz validará que `duration` debe ser un número entero entre 10 y 360; sigue siendo solo un objetivo de generación, no una garantía de la duración del producto final.

## Generación de canciones mediante muestreo Samples

- action: el contenido es `samples`.

## Función de creación por inspiración de Inspo

La función de creación por inspiración de Inspo puede generar música nueva basándose en 1 a 4 segmentos completos de audio de referencia, y admite arrastrar o cargar audio como fuente de inspiración. La API utiliza la acción existente `inspo`: el cliente proporciona URL de audio accesibles públicamente, y el servicio completa automáticamente la preparación y la creación del audio de referencia, sin necesidad de que el cliente lea por separado la letra, el estilo o la duración y luego arme la solicitud. Se diferencia del muestreo por intervalos anterior y también del Cover que reproduce el estilo de la canción original. Al utilizarla, se deben completar los siguientes parámetros:

- action: el contenido es `inspo`.
- audio_urls: lista de URL de audio de referencia; se deben proporcionar de 1 a 4 direcciones de audio accesibles públicamente.
- model: el modelo utilizado; se recomienda `chirp-v6`.
- prompt: letra o indicación de creación (opcional).
- instrumental: cuando se establece en `true`, genera según una solicitud de música instrumental, sin utilizar letra.
- persona_id: utiliza la voz especificada en los canales de servicio que admiten esta combinación; el audio de referencia se vinculará durante la fase de preparación al entorno de recursos requerido por esa voz.
- lyric_prompt: cuando `custom=true` y no se proporciona `lyric`, se utiliza para generar letras automáticamente.

> Nota: El audio de referencia debe ser un archivo de audio accesible públicamente. Si el audio de referencia coincide por completo con una grabación conocida de la biblioteca musical de la plataforma, Suno puede rechazar la generación debido a la verificación de derechos de autor; se recomienda utilizar audio propio o generado por Suno como fuente de inspiración.

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Devolución de llamada asíncrona

Debido a que Suno tarda relativamente mucho tiempo en generar música, aproximadamente 1-2 minutos, si la API no responde durante mucho tiempo, la solicitud HTTP mantendrá la conexión abierta, lo que provoca un consumo adicional de recursos del sistema, por lo que esta API también proporciona soporte para devoluciones de llamada asíncronas.

El flujo general es: cuando el cliente inicia una solicitud, especifica adicionalmente un campo `callback_url`; después de que el cliente inicia la solicitud a la API, la API devolverá inmediatamente un resultado, que contiene la información de un campo `task_id`, que representa el ID de la tarea actual. Cuando la tarea se complete, el resultado de la música generada se enviará mediante POST JSON al `callback_url` especificado por el cliente, que también incluye el campo `task_id`, de esta manera el resultado de la tarea puede asociarse mediante el ID.
