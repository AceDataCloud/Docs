A medida que la aplicación de la IA se ha ampliado, diversos programas de IA se han popularizado gradualmente. La IA se ha integrado progresivamente en todos los aspectos del trabajo y la vida de las personas. Y las industrias involucradas con la IA también son cada vez más numerosas, desde la escritura inicial, hasta la medicina y la educación, y ahora la música.

Suno es una plataforma profesional de creación de canciones y música con IA de alta calidad. Los usuarios solo necesitan introducir indicaciones de texto simples para generar canciones con voces según el estilo de género y la letra. Este generador de música con IA fue desarrollado por miembros de equipos de conocidas empresas tecnológicas como Meta, TikTok y Kensho, con el objetivo de que todos puedan crear música maravillosa sin necesitar ningún instrumento.

> Los límites de `lyric` y `style` de la tabla anterior son los límites máximos en el modo personalizado (`custom` es `true`). El modo de inspiración no personalizado (`custom` es `false`) solo rellena `prompt`, y su límite de longitud es de 500 caracteres (igual para todos los modelos).

Suno ahora admite `chirp-v6`, `chirp-v6-wild` y `chirp-v6-mini`. Se recomienda utilizar `chirp-v6`; los nombres de los modelos antiguos siguen siendo compatibles.

Sin embargo, Suno oficialmente no proporciona una API. AceDataCloud ofrece un conjunto de API de Suno que simula la integración oficial de Suno, permitiendo generar de forma cómoda y rápida la música deseada.

## Solicitud y uso

Para utilizar Suno Audios Generation API, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; al completarlo, regresará automáticamente a la página actual.

**Un API Token permite llamar a todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud otorgará una cuota gratuita para experimentar sin costo; cuando la cuota sea insuficiente, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Uso básico

Para la canción que desee crear, puede introducir cualquier texto, por ejemplo, si quiero generar una canción sobre Navidad, puedo introducir `a song for Christmas`, como se muestra en la imagen:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Aquí podemos ver que hemos configurado Request Headers, incluyendo:

- `accept`: qué formato de resultado de respuesta se desea recibir; aquí se rellena con `application/json`, es decir, formato JSON.
- `authorization`: la clave para llamar a la API, que puede seleccionarse directamente en la lista desplegable después de solicitarla.

Además, se configuró Request Body, incluyendo:
- `action`: tipo de tarea de audio, el valor predeterminado es `generate`. Admite operaciones como generación, continuación, cover, combinación, separación de pistas, adición de pista de audio, extracción de una pista de audio especificada, generación de efectos de sonido y ajuste de velocidad, todas invocadas mediante `POST /suno/audios`.
- `prompt`: palabras clave del modo de inspiración oficial de Suno (efectivas cuando `custom` es `false`), máximo 500 caracteres.
- `model`: modelo para esta tarea de generación de música. La serie v6 incluye `chirp-v6`, `chirp-v6-wild` y `chirp-v6-mini`; los nombres de modelos antiguos siguen siendo compatibles.
- `max_mode`: modo de generación mejorado. `generate` solo se habilita cuando tanto `custom` como `max_mode` son `true`, con un coste de 1.12 Credits; `add_stem` puede habilitarse directamente, con un coste de 1.344 Credits. Cuando está desactivado o se omite, son respectivamente 0.56 y 0.672 Credits.
- `variety`: intensidad de diversidad de los resultados generados, opcional entre `off`, `normal`, `high`, `extra`, `max`. Solo se utiliza para `generate` y `add_stem`; si se pasa en otras action, devolverá 400.
- `lyric`: contenido de letras del modo personalizado oficial de Suno. `chirp-v3-5` y `chirp-v4` tienen un máximo de 3000 caracteres; `chirp-v4-5` y superiores (incluidos `chirp-v5`, `chirp-v5-5`) tienen un máximo de 5000 caracteres.
- `custom`: si se adopta el modo personalizado, el valor predeterminado es: `false`.
- `instrumental`: opción de música instrumental del modo de inspiración oficial de Suno.
- `title`: título de la música del modo personalizado oficial de Suno. `chirp-v3-5`, `chirp-v4` tienen un máximo de 80 caracteres; `chirp-v4-5` y superiores tienen un máximo de 100 caracteres.
- `style`: estilo musical del modo personalizado oficial de Suno. `chirp-v3-5` y `chirp-v4` tienen un máximo de 200 caracteres; `chirp-v4-5` y superiores (incluidos `chirp-v5`, `chirp-v5-5`) tienen un máximo de 1000 caracteres.
- `negative_tags`: estilos musicales o géneros que se desean excluir durante la generación personalizada, también puede utilizarse para `replace_section`. Actualmente esta interfaz no establece un límite fijo de caracteres para este campo; es posible que el contenido excesivamente largo siga sin poder procesarse, se recomienda mantener la descripción concisa.
- `audio_weight`: peso de influencia de las características de audio o voz, rango de 0-1, `0` también es un valor válido. Puede utilizarse para operaciones como generación, continuación, cover, adición de pista de audio y consistencia de voz; cuando no hay audio de referencia o características de voz, el modelo puede reducir o ignorar este valor.
- `audio_id`: ID de la música de referencia, utilizado para operaciones posteriores como cover, continuación, separación de pistas, etc. El archivo de audio aún puede descargarse, pero esto no significa que el procesamiento posterior de este ID esté siempre disponible; si devuelve `suno_processing_unavailable`, conserve `task_id` y `trace_id` para contactar con soporte.
- `overpainting_start`/`overpainting_end`: hora de inicio y finalización para añadir voces a música instrumental existente, en segundos.
- `underpainting_start`/`underpainting_end`: hora de inicio y finalización para añadir acompañamiento a una interpretación a capela, en segundos.
- `persona_id`: ID de voz obtenido mediante la interfaz de creación de Persona o voz, no es el `audio_id` de una canción.
- `continue_at`: límite de continuación, en segundos. Por ejemplo, 213.5 indica que se comienza a generar el fragmento posterior desde el minuto 3 segundo 33.5. `lyric` y `style` solo guían el contenido nuevo después del límite, y no reemplazarán las letras ni el canto antes del límite en el audio de origen.
- `style_influence`: influencia del estilo en modo personalizado, rango de 0-1; cuanto mayor sea, normalmente más se ajustará al estilo seleccionado; `0` se transmitirá como un valor válido.
- `replace_section_end`: hora final del fragmento a reemplazar.
- `replace_section_start`: hora de inicio del fragmento a reemplazar.
- `vocal_gender`: controla la preferencia de voz femenina o masculina, voz femenina `f`, voz masculina `m`, efectivo en modelos 4.5 y superiores; es un elemento de preferencia, no se garantiza que se siga estrictamente.
- `weirdness`: grado de rareza en modo personalizado, rango de 0-1; cuanto mayor sea, normalmente más creativo y experimental será; `0` se transmitirá como un valor válido.
- `duration`: duración esperada de la canción, en segundos, debe ser un entero, con un rango de 10 a 360. Actualmente solo `generate` utiliza este parámetro, el efecto específico depende del modo y del modelo. Es una sugerencia de tendencia y no una restricción estricta: el modelo la tomará como referencia, pero no se garantiza que la alcance; la duración real del producto terminado prevalece según el campo `duration` en la respuesta, y normalmente es menor que el valor esperado.

### Ámbito de aplicación del ID de voz

`generate`, `cover`, `upload_cover`, `artist_consistency`, `artist_consistency_vox` pueden usar `persona_id`. Las dos últimas action deben proporcionar `persona_id`; también pueden proporcionar simultáneamente el `audio_id` de la canción utilizada al crear esta Persona.

`extend`, `upload_extend` no utilizan un `persona_id` adicional. Que `mashup`, `inspo` admitan ID de voz depende del canal de servicio seleccionado; no se garantiza que otras action apliquen este campo, utilícelo según las instrucciones de cada operación. `vocal_gender` es una preferencia de género opcional y no puede sustituir al ID de voz.

Las operaciones de creación posteriores requieren un `audio_id` de origen válido; `mashup` requiere al menos dos `mashup_audio_ids`. Cuando faltan las fuentes o los parámetros de tiempo necesarios, se devolverá HTTP 400.

### Ámbito de aplicación de los parámetros avanzados
| Parámetro                | Valores                                          | action compatible                              | Descripción                                |
| ----------------- | ------------------------------------------- | --------------------------------------- | --------------------------------- |
| `weirdness`       | 0-1                                         | Opcional                                      | Ajusta la experimentalidad, `0` es un valor válido; el efecto depende de la operación, el modo y el modelo      |
| `style_influence` | 0-1                                         | Opcional                                      | Ajusta la tendencia a seguir el estilo, `0` es un valor válido; el efecto depende de la operación, el modo y el modelo   |
| `audio_weight`    | 0-1                                         | Opcional                                      | Ajusta la influencia de las características de audio o voz; puede ser ignorado por el modelo si no hay información de referencia        |
| `variety`         | `off` / `normal` / `high` / `extra` / `max` | `generate`, `add_stem`                   | Ajusta la diversidad de estilo entre los resultados                       |
| `max_mode`        | boolean                                     | `generate` (requiere `custom=true`), `add_stem` | Mejora la consistencia y se cobra según el modo mejorado                     |
| `vocal_gender`    | `f` / `m`                                   | Operaciones de generación que admiten control vocal                             | Elemento de preferencia, no se garantiza un seguimiento estricto                       |
| `duration`        | Entero 10-360                                   | `generate`                              | Duración esperada; otras action actualmente no usan este campo, la duración real depende del resultado |

La plataforma validará los tipos de parámetros y los rangos de valores, pero no rechazará estos elementos de ajuste opcionales únicamente porque la action sea diferente; los efectos específicos dependen de la operación, el modo y el modelo.

- `lyric_prompt`: prompt para generar letras, solo tiene efecto cuando `custom` es `true` y no se ha enviado `lyric`.
- `callback_url`: URL que necesita recibir los resultados mediante callback.
- `async`: opcional, cuando se establece en `true`, la interfaz devuelve inmediatamente `task_id`, no es necesario proporcionar `callback_url`, y posteriormente se obtienen los resultados mediante sondeo a través de la interfaz de consulta de tareas correspondiente.

## Función de generación personalizada de estilo de cantante

Si deseas usar un estilo de cantante para generar una canción, primero genera una canción mediante el uso básico anterior,
al final necesitas configurar esta canción como estilo de cantante, luego debes entrar en [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) para generar un parámetro de id de estilo de cantante `persona_id` según el ID de música oficial generado `audio_id`; los parámetros específicos se muestran en la siguiente imagen:

<p><img src="https://cdn.acedata.cloud/pmzo3l.png" width="500" className="m-auto" /></p>

Después de completar, el código se genera automáticamente de la siguiente manera:

<p><img src="https://cdn.acedata.cloud/a5g0nj.png" width="500" className="m-auto" /></p>

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Luego puedes establecer el parámetro `action` como `artist_consistency` (si es el nuevo estilo de cantante Persona-v2-vox, `action` debe establecerse como `artist_consistency_vox`), e introducir el ID de la canción que necesita seguir generándose y el ID del estilo de cantante; el ejemplo de completado es el siguiente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "artist_consistency",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
    "persona_id": "e0d7319e-aa2a-44cb-b00a-916218d7cb0b",
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Función de continuar generando
Si deseas continuar generando una canción de Suno ya generada, puedes establecer el parámetro `action` en `extend` e introducir el ID de la canción que necesita continuar generándose. La obtención del ID de la canción se realiza según el uso básico; según lo anterior, en este momento puedes ver que el ID de la canción es:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Nota: aquí, el `id` en la letra es el ID de la canción después de generarse. Si no sabes cómo generar una canción, puedes consultar el uso básico anterior para generar una canción.

Si deseas continuar generando una canción que hayas subido tú mismo, puedes establecer el parámetro `action` en `upload_extend` e introducir el ID de la canción subida personalizada que necesita continuar generándose. La obtención del ID de la canción se realiza mediante la [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), como se muestra en la siguiente imagen:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

A continuación, debes completar la letra del fragmento de continuación y puedes especificar el estilo:

- lyric: solo se utiliza para guiar la letra del fragmento recién generado después de `continue_at`; no reemplazará la letra anterior a ese punto temporal en el audio de origen.
- custom: establecerlo en `true` representa generación personalizada; este parámetro es false de forma predeterminada, lo que representa la generación usando `prompt`.
- style: el estilo de la canción del fragmento de continuación, opcional.
- continue_at: límite de continuación, en segundos. Por ejemplo, 213.5 indica que se comienza a generar el fragmento posterior desde los 3 minutos y 33.5 segundos.

El `continue_at` de `extend` y `upload_extend` debe ser mayor que 0 y admite segundos decimales, por ejemplo, `30.792`; no se redondeará al enviarlo.

> `extend` se utiliza para continuar creando después de una canción existente, no para cambiar la letra de toda la canción. Si deseas usar una letra nueva desde el principio para toda la canción, utiliza `generate` para volver a generarla; si deseas reinterpretarla tomando como referencia una canción existente, puedes utilizar `cover`. Al introducir una letra nueva completa, la letra original anterior a `continue_at` tampoco será reemplazada.

El ejemplo de completado es el siguiente:

Después de completar, el código se genera automáticamente de la siguiente manera:

- action: el contenido es `cover`; cuando se realiza una operación de versión sobre música subida de forma personalizada, se debe especificar el contenido como: `upload_cover`.

## Reemplazar fragmentos

`replace_section` regenera el fragmento seleccionado según el intervalo de tiempo de la canción fuente y vuelve a unir el resultado a la canción original. `replace_section_result_mode` tiene como valor predeterminado `full_song`, devuelve 2 canciones completas que pueden reproducirse directamente, sin necesidad de volver a llamar a `concat`.

### Cómo completar la entrada
- `action`: `replace_section`.
- `audio_id`: el ID completo de la canción que se va a editar. Al editar de nuevo, usa el `data[].id` de la canción completa seleccionada la vez anterior, no el `task_id`.
- `model`: modelo de generación de canciones, por ejemplo `chirp-v6`.
- `lyric`: las **nuevas letras locales** que se cantarán en el intervalo seleccionado. No es necesario enviar las letras de toda la canción para obtener una canción completa.
- `prompt`: especifica claramente las nuevas letras locales de este reemplazo. Al cambiar letras, se recomienda rellenar el mismo contenido que en `lyric`, para evitar que los dos campos expresen letras diferentes. Las solicitudes existentes que solo envían `lyric` local y omiten `prompt` aún pueden utilizarse, pero añadir `prompt` en sí no garantiza que el cambio de letra tenga éxito.
- `style`, `negative_tags`: descripciones de estilo y elementos a excluir opcionales; `prompt` en esta operación no es una descripción de inspiración como al crear canciones normalmente.
- `replace_section_start`, `replace_section_end`: los tiempos de inicio y fin de la selección en la canción fuente de esta vez, en segundos, admiten decimales. El punto de inicio no debe ser menor que 0, y el punto final debe ser mayor que el punto de inicio y no debe exceder la duración de la canción fuente.
- `replace_section_result_mode`: `full_song` (predeterminado) devuelve 2 canciones completas; `candidates` devuelve 2 candidatos de reemplazo que aún no se han unido.

No uses “`lyric` debe ser la letra completa después del reemplazo, `prompt` debe ser la letra local” como uso general. La entrada de letras completas puede producir contenido de reemplazo demasiado largo en algunas tareas, haciendo que la canción completa se alargue significativamente después de la unión. La entrada local tampoco garantiza una duración fija ni seguir las letras palabra por palabra; esta es una edición generativa, y es necesario comprobar el audio real.

### Iniciar la tarea y obtener la canción completa

A continuación se muestra un ejemplo de formato de solicitud. Reemplaza `YOUR_COMPLETED_AUDIO_ID` y el intervalo de tiempo por el ID de tu propia canción fuente y la selección real; el ejemplo supone que los segundos 30–50 corresponden a las siguientes cuatro líneas.

```json
{
  "action": "replace_section",
  "audio_id": "YOUR_COMPLETED_AUDIO_ID",
  "model": "chirp-v6",
  "custom": false,
  "instrumental": false,
  "lyric": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "prompt": "晚风吹过安静的街巷\n绿色风筝停在我身旁\n我们沿着河岸轻轻唱\n把今天的故事放心上",
  "replace_section_start": 30.0,
  "replace_section_end": 50.0,
  "replace_section_result_mode": "full_song",
  "async": true
}
```

Después de enviar, usa el `task_id` devuelto para consultar `/suno/tasks`, con el cuerpo de solicitud `{"action":"retrieve","id":"YOUR_TASK_ID"}`. Una vez completada la tarea, obtén los `id`, `audio_url` y `duration` de las dos canciones completas en `response.data` de la respuesta de la tarea, y selecciona una de ellas después de escucharla. `success: true` significa que la tarea se ejecutó correctamente, no que las nuevas letras se hayan cantado palabra por palabra ni que la duración cumpla con lo esperado.

### Selección, comprobación de resultados y edición de nuevo

1. Primero escucha la canción fuente y luego determina la selección combinando la información de tiempo de `/suno/timing`, procurando cubrir frases musicales completas. No elijas la selección según índices fijos de un arreglo de letras, ni reemplaces un intervalo que contiene más frases musicales con unas pocas líneas de letras esperando que el ritmo permanezca exactamente igual.
2. Procura que el número de líneas, de caracteres y el ritmo de las nuevas letras sean cercanos al contenido original de la selección. Incluso al cambiar solo unos pocos caracteres, es necesario verificarlo escuchando; no se puede garantizar el éxito por ello.
3. Comprueba si se cantan las nuevas letras en el intervalo objetivo, si la transición antes y después es natural, y si la duración de toda la canción es razonable. `full_song` significa que devuelve una canción completa, no que tenga la misma duración que la canción original; cuando el fragmento reemplazado se alarga, la segunda mitad se desplazará en consecuencia. El parámetro de solicitud `duration` solo se utiliza para la generación normal y no puede fijar la duración del fragmento reemplazado.
4. El `lyric` devuelto son metadatos de letras; el modo de canción completa combinará las letras completas cuando se pueda obtener la información temporal de las letras fuente; si no se puede obtener, puede estar vacío. No es una transcripción de audio; que aparezcan letras nuevas no demuestra que el audio haya cantado las nuevas letras. La información de alineación temporal también debe verificarse junto con la escucha, especialmente en productos que ya han sido editados.
5. Al editar de nuevo, utiliza el **ID del producto completo** seleccionado como el nuevo `audio_id`, y vuelve a comprobar la duración y la selección de ese producto. No copies directamente las coordenadas de tiempo anteriores a la edición, ni uses directamente el `lyric` de toda la canción devuelto la vez anterior como entrada local de esta vez.

Si la tarea ya se completó pero aún se cantan las letras antiguas, faltan letras o la duración se alarga significativamente, primero comprueba el ID de la canción fuente, la selección y las letras locales, y después comprueba el otro resultado. Aumentar la frecuencia de consulta de tareas no cambiará el contenido ya generado. Si la anomalía persiste, conserva el `task_id`, el ID de la canción fuente, los campos de solicitud, la selección y el audio resultante para facilitar la verificación.

### Opcional: obtener primero los candidatos y luego unir manualmente

Solo cuando necesites seleccionar tú mismo un candidato de reemplazo, configura `replace_section_result_mode: "candidates"`. Los candidatos pueden contener contexto, y no debes considerarlos como canciones completas solo basándote en la duración del candidato. Después de seleccionar uno, llama a `concat` con el `data[].id` del candidato y luego obtén el producto completo.

El `full_song` predeterminado ya ha completado la unión, por lo que no es necesario realizar este paso.

{
  "action": "all_stems",

## Controlar la duración de las canciones

De forma predeterminada, la duración de las canciones generadas la decide el propio modelo, normalmente entre 30 segundos y 4 minutos. Si se necesita un producto final más largo o más corto, se puede especificar la duración deseada mediante el parámetro `duration`, cuya unidad son segundos y cuyo valor es un número entero entre 10 y 360.

Este parámetro se utiliza para la generación de canciones en modo personalizado (`custom` es `true`). Cabe destacar especialmente que `duration` es una **indicación de tendencia, no una restricción rígida**: el modelo consultará este valor al crear, pero no garantiza alcanzarlo; en pruebas, la duración real suele ser notablemente inferior al valor esperado, y las duraciones de las dos canciones devueltas por la misma solicitud también pueden diferir varias veces. Incluso para solicitudes completamente idénticas, las duraciones obtenidas tras múltiples envíos también pueden presentar grandes diferencias. Por lo tanto, no lo utilice como un control preciso de duración; si el negocio requiere una duración fija, recorte o vuelva a intentarlo después de obtener el producto final.

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Cabe señalar que el `duration` de la solicitud es la **duración esperada**, mientras que el campo `duration` de cada canción en los `data` de la respuesta es la **duración real** de esa canción. Ambos tienen el mismo nombre, pero significados diferentes; no se garantiza que la duración real sea igual al valor esperado. La longitud de la letra es uno de los principales factores que influyen en la duración del producto final; si se necesita un producto final más largo, se recomienda proporcionar al mismo tiempo una letra más completa.

La interfaz validará que `duration` debe ser un número entero entre 10 y 360; sigue siendo solo un objetivo de generación, no una garantía de duración del producto final.

## Samples Generación de canciones por muestreo

Aquí, `samples` es un muestreo de intervalo de un solo audio: se seleccionan el tiempo de inicio y de finalización de un audio existente, y este fragmento se utiliza como material de muestreo para la creación. Es diferente de la función de creación inspirada Inspo que utiliza de 1 a 4 segmentos completos de audio de referencia a continuación. Se deben completar los siguientes parámetros:

- action: el contenido es `samples`.
- samples_start: tiempo de inicio del muestreo (segundos), el valor predeterminado es 0 y no debe ser inferior a 0.
- samples_end: tiempo de finalización del muestreo (segundos), es obligatorio y debe ser mayor que el tiempo de inicio.
- audio_id: el ID de la canción de referencia que se necesita muestrear.

## Función de creación por inspiración Inspo

La función de creación por inspiración Inspo puede generar música nueva basándose en 1 a 4 segmentos completos de audio de referencia, y permite arrastrar o cargar audio como fuente de inspiración. La API utiliza la acción existente `inspo`: el cliente proporciona URL de audio accesibles públicamente, y el servicio completa automáticamente la preparación del audio de referencia y la creación, sin necesidad de que el cliente lea por separado la letra, el estilo o la duración para luego ensamblar la solicitud. Es diferente del muestreo por intervalos mencionado anteriormente, y también diferente de Cover, que replica el estilo de la canción original. Al utilizarla, se deben completar los siguientes parámetros:

- action: el contenido es `inspo`.
- audio_urls: lista de URL de audio de referencia; se deben proporcionar de 1 a 4 direcciones de audio accesibles públicamente.
- model: el modelo utilizado; se recomienda `chirp-v6`.
- prompt: letra o indicación de creación (opcional).
- instrumental: cuando se establece en `true`, genera según una solicitud de música instrumental, sin utilizar letra.
- persona_id: utiliza la voz especificada en los canales de servicio que admiten esta combinación; el audio de referencia se vinculará durante la fase de preparación al entorno de recursos requerido por esa voz.
- lyric_prompt: cuando `custom=true` y no se proporciona `lyric`, se utiliza para generar letras automáticamente.

> Nota: el audio de referencia debe ser un archivo de audio accesible públicamente. Si el audio de referencia coincide completamente con una grabación conocida de la biblioteca musical de la plataforma, Suno podría rechazar la generación debido a la verificación de derechos de autor; se recomienda utilizar audio propio o generado por Suno como fuente de inspiración.

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Devolución de llamada asíncrona

Debido a que Suno tarda relativamente mucho tiempo en generar música, aproximadamente 1-2 minutos, si la API no responde durante mucho tiempo, la solicitud HTTP mantendrá la conexión abierta, lo que genera un consumo adicional de recursos del sistema, por lo que esta API también proporciona soporte para devoluciones de llamada asíncronas.

El flujo general es: cuando el cliente inicia una solicitud, especifica adicionalmente un campo `callback_url`; después de que el cliente inicia la solicitud a la API, la API devolverá inmediatamente un resultado que incluye la información de un campo `task_id`, que representa el ID de la tarea actual. Cuando la tarea se complete, el resultado de la música generada se enviará mediante POST JSON al `callback_url` especificado por el cliente, que también incluye el campo `task_id`, de modo que el resultado de la tarea puede asociarse mediante el ID.

A continuación, conoceremos cómo operar específicamente a través de un ejemplo.
