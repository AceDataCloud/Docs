Con la ampliación de las aplicaciones de IA, diversos programas de IA se han popularizado gradualmente. La IA ha ido penetrando gradualmente en todos los aspectos del trabajo y la vida de las personas. Y las industrias que involucra la IA también son cada vez más numerosas, desde la escritura inicial, hasta la medicina y la educación, y ahora la música.

Suno es una plataforma profesional y de alta calidad de creación de canciones y música con IA, los usuarios solo necesitan introducir simples palabras de indicación de texto para generar canciones con voces según el estilo de género y la letra. Este generador de música con IA fue desarrollado por miembros de equipos de reconocidas empresas tecnológicas como Meta, TikTok y Kensho, con el objetivo de no necesitar ninguna herramienta instrumental y permitir que todos puedan crear música maravillosa.

Sin embargo, Suno oficialmente no proporciona una API, AceDataCloud proporciona un conjunto de API de Suno, simulando la integración oficial de Suno, y puede generar de forma cómoda y rápida la música deseada.

## Solicitud y uso

Para usar Suno Audios Generation API, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y consérvelo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión, y al completarlo volverá automáticamente a la página actual.

**Un API Token puede invocar todos los servicios de la plataforma, no es necesario solicitar uno por separado para cada servicio.** La primera solicitud ofrecerá crédito gratuito, que permite una experiencia gratuita; cuando el crédito sea insuficiente, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Uso básico

Para las canciones que quiera, puede introducir arbitrariamente un texto, por ejemplo, si quiero generar una canción sobre Navidad, puedo introducir `a song for Christmas`, como se muestra en la imagen:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Aquí podemos ver que configuramos los Request Headers, incluyendo:

- `accept`: qué formato de resultado de respuesta se desea recibir, aquí se rellena como `application/json`, es decir, formato JSON.
- `authorization`: la clave para invocar la API, después de solicitarla puede seleccionarse directamente en el menú desplegable.

Además se configuró el Request Body, incluyendo:
- `action`: el comportamiento de esta tarea de generación de música, el valor predeterminado es `generate`, e incluye principalmente: `extend`, `upload_extend`, `cover`, `upload_cover`, `replace_section`, `replace_section`, `concat`, `stems`, `all_stems`, `remaster`.
- `prompt`: la palabra clave del modo de inspiración oficial de Suno (surte efecto cuando `custom` es `false`), máximo 500 caracteres.
- `model`: el modelo de esta tarea de generación de música. La serie v6 incluye `chirp-v6`, `chirp-v6-wild` y `chirp-v6-mini`; los nombres de modelos antiguos siguen siendo compatibles.
- `lyric`: el contenido de la letra del modo personalizado oficial de Suno. `chirp-v3-5` y `chirp-v4` admiten un máximo de 3000 caracteres; `chirp-v4-5` y superiores (incluidos `chirp-v5`, `chirp-v5-5`) admiten un máximo de 5000 caracteres.
- `custom`: si se utiliza el modo personalizado, el valor predeterminado es: `false`.
- `instrumental`: la opción de música instrumental del modo de inspiración oficial de Suno.
- `title`: el título de la música del modo personalizado oficial de Suno. `chirp-v3-5`, `chirp-v4` admiten un máximo de 80 caracteres; `chirp-v4-5` y superiores admiten un máximo de 100 caracteres.
- `style`: el estilo musical del modo personalizado oficial de Suno. `chirp-v3-5` y `chirp-v4` admiten un máximo de 200 caracteres; `chirp-v4-5` y superiores (incluidos `chirp-v5`, `chirp-v5-5`) admiten un máximo de 1000 caracteres.
- `negative_tags`: estilos musicales o géneros que se desea excluir de los resultados generados en el modo personalizado (cuando `custom` es `true`).
- `audio_weight`: la proporción del audio de referencia cargado, rango de 0 a 1; cuanto mayor sea, más dependerá del audio de referencia.
- `audio_id`: el ID de la música de referencia.
- `overpainting_start`/`overpainting_end`: la hora de inicio y finalización para añadir voces a música instrumental existente, en segundos.
- `underpainting_start`/`underpainting_end`: la hora de inicio y finalización para añadir acompañamiento a canto a capela, en segundos.
- `persona_id`: el ID de la canción del artista.
- `continue_at`: el límite de continuación, en segundos. Por ejemplo, 213.5 indica que se comienza a generar el fragmento posterior desde los 3 minutos y 33.5 segundos. `lyric` y `style` solo guían el contenido nuevo después del límite, y no reemplazarán la letra ni el canto antes del límite en el audio de origen.
- `style_influence`: el parámetro avanzado «Style Influence» en el modo personalizado, rango de 0 a 1; cuanto mayor sea, más se ajustará al estilo seleccionado.
- `replace_section_end`: la hora final del fragmento que se va a reemplazar.
- `replace_section_start`: la hora inicial del fragmento que se va a reemplazar.
- `vocal_gender`: controla la preferencia de voz femenina o masculina; voz femenina `f`, voz masculina `m`, válido para modelos 4.5 y superiores; es una opción de preferencia y no se garantiza que se siga estrictamente.
- `weirdness`: el parámetro avanzado «Weirdness» en el modo personalizado, rango de 0 a 1; cuanto mayor sea, más creativo y experimental será.
- `duration`: la duración esperada de la canción, en segundos, debe ser un entero, con un rango de 10 a 360. Este parámetro se utiliza para la generación de canciones en modo personalizado (cuando `custom` es `true`). Es una indicación de tendencia y no una restricción estricta: el modelo la tendrá en cuenta, pero no se garantiza que la alcance; la duración real del producto final se rige por el campo `duration` de la respuesta y normalmente es menor que el valor esperado.
- `lyric_prompt`: el prompt para generar letras, surte efecto si y solo si `custom` es `true` y no se proporciona `lyric`.
- `callback_url`: la URL que necesita recibir los resultados mediante callback.
- `async`: opcional; cuando se establece como `true`, la interfaz devuelve inmediatamente `task_id`, no es necesario proporcionar `callback_url`, y posteriormente se obtiene el resultado mediante sondeo a través de la interfaz de consulta de tareas correspondiente.

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Función de continuación de generación

Si desea continuar generando una canción de Suno ya generada, puede establecer el parámetro `action` en `extend` e introducir el ID de la canción que necesita seguir generando. El ID de la canción se obtiene según el uso básico; como se puede saber en lo anterior, en este momento puede ver que el ID de la canción es:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Tenga en cuenta que el `id` en la letra aquí es el ID de la canción generada. Si no sabe cómo generar una canción, puede consultar el uso básico anterior para generar una canción.

Si desea continuar generando una canción que haya subido usted mismo, puede establecer el parámetro `action` en `upload_extend` e introducir el ID de la canción subida personalizada que necesita seguir generando. El ID de la canción se obtiene mediante [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), como se muestra en la siguiente imagen:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

A continuación, debe completar la letra del fragmento de continuación y puede especificar el estilo:

- lyric: se utiliza únicamente para guiar la letra del fragmento recién generado después de `continue_at`; no reemplazará la letra anterior a ese punto temporal en el audio de origen.
- custom: complete con `true`, lo que representa generación personalizada; este parámetro tiene como valor predeterminado false, lo que representa la generación mediante `prompt`.
- style: el estilo de la canción del fragmento de continuación, opcional.
- continue_at: límite de continuación, en segundos. Por ejemplo, 213.5 indica que se generarán fragmentos posteriores a partir de los 3 minutos y 33.5 segundos.

> `extend` se utiliza para continuar creando a partir de una canción existente, no para cambiar la letra de toda la canción. Si desea utilizar una letra nueva para toda la canción desde el principio, utilice `generate` para volver a generarla; si desea reinterpretar una canción existente como referencia, puede utilizar `cover`. Al proporcionar una letra nueva completa, la letra original antes de `continue_at` seguirá sin ser reemplazada.

El ejemplo de llenado es el siguiente:

<p><img src="https://cdn.acedata.cloud/zp9s42.png" width="500" className="m-auto" /></p>

Después de completar la información, se genera automáticamente el siguiente código:

<p><img src="https://cdn.acedata.cloud/wwpw78.png" width="500" className="m-auto" /></p>
A continuación se conserva una instantánea de una llamada histórica real, en la que `continue_at` es de 2 segundos, por lo tanto, solo los primeros 2 segundos pertenecen al contenido original antes del límite de continuación. Al continuar realmente cerca del final de una canción, este valor debe establecerse en el número de segundos esperado para comenzar la continuación, y solo se debe proporcionar en `lyric` el nuevo fragmento que se cantará después del límite.

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
```

## Obtener la canción completa

El resultado de `extend` del modelo actual normalmente ya incluye el audio fuente antes de `continue_at` y el nuevo contenido después del límite; primero determine si ya es una canción completa según la duración real y el contenido del audio devuelto. Si lo que se devuelve es un fragmento de continuación independiente, o si se necesita combinar explícitamente el historial de múltiples continuaciones en una sola canción, utilice entonces la función de concatenación:

- action: el contenido es `concat`.
- audio_id: el ID del último fragmento de continuación.

Por ejemplo, si el ID de la canción extendida es: 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, entonces se pueden establecer los parámetros de la siguiente manera:

```json
{
  "action": "concat",
  "audio_id": "0a1e1b10-c36a-41c9-9bfb-b26d9d25db98"
}
```

## Versión de música

- action: el contenido es `cover`; cuando se realiza una operación de versión sobre música personalizada subida, se debe especificar el contenido como: `upload_cover`.
- audio_id: el ID de la canción generada previamente.

Por ejemplo, si el ID de la canción generada originalmente es: 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, entonces se pueden establecer los parámetros de la siguiente manera:

```json
{
  "action": "cover",

  "prompt": "A song for Christmas",
  "model": "chirp-v4-5"
```

## Reemplazar fragmento

Cuando, después de generar una canción, se necesita realizar una creación secundaria para reemplazar por separado un fragmento de la canción, se puede realizar una operación de reemplazo sobre un fragmento de la canción.

> ⚠️ **Nota**: `replace_section_result_mode` tiene como valor predeterminado `full_song`: el sistema concatenará respectivamente 2 candidatos generados nuevos y devolverá 2 canciones completas. Si solo se necesitan los candidatos de fragmentos de reemplazo aún no concatenados, establezca explícitamente el valor en `candidates` y luego seleccione un candidato para llamar a [Concatenación de música](#音乐拼接).

La descripción de los parámetros es la siguiente:

- action: el contenido es `replace_section`.
- audio_id: el ID de la canción original (la canción fuente que se reemplaza).
- model: el modelo de generación de canciones.
- lyric: la letra completa después del reemplazo (incluye el fragmento reemplazado y su contexto, y se mantiene coherente con el contenido en `prompt`).
- prompt: la nueva letra de esa sección que necesita reemplazarse.
- style: el estilo de la canción, opcional.
- replace_section_start: el tiempo de inicio (en segundos) del fragmento reemplazado en la canción original.
- replace_section_end: el tiempo de finalización (en segundos) del fragmento reemplazado en la canción original.
- replace_section_result_mode: el modo de devolución, cuyo valor predeterminado es `full_song`. `full_song` concatena respectivamente 2 candidatos y devuelve 2 canciones completas; `candidates` devuelve 2 fragmentos candidatos aún no concatenados.

## Controlar la duración de la canción

De forma predeterminada, la duración de las canciones generadas la decide el propio modelo, normalmente entre 30 segundos y 4 minutos. Si se necesita un producto terminado más largo o más corto, se puede especificar la duración esperada mediante el parámetro `duration`, cuya unidad son segundos y cuyo valor es un entero entre 10 y 360.

Este parámetro se utiliza para la generación de canciones en modo personalizado (cuando `custom` es `true`). Cabe destacar especialmente que `duration` es una **indicación de tendencia, no una restricción estricta**: el modelo hará referencia a este valor al crear, pero no garantiza alcanzarlo. En pruebas reales, la duración real suele ser notablemente menor que el valor esperado, y las duraciones de las dos canciones devueltas por la misma solicitud también pueden diferir varias veces. Incluso para solicitudes completamente idénticas, las duraciones obtenidas tras múltiples envíos también pueden variar considerablemente. Por lo tanto, no lo uses como un control preciso de duración; si se requiere una duración fija para fines de negocio, recorta o vuelve a intentar después de obtener el producto terminado.

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Cabe señalar que `duration` en la solicitud es la **duración esperada**, mientras que el campo `duration` de cada canción en `data` de la respuesta es la **duración real** de esa canción. Ambos tienen el mismo nombre, pero significados diferentes; no se garantiza que la duración real sea igual al valor esperado. La longitud de la letra es uno de los principales factores que afectan la duración del producto terminado; si se necesita un producto terminado más largo, se recomienda proporcionar al mismo tiempo una letra más completa.

La interfaz no realizará validaciones adicionales sobre `duration`, y el parámetro se transmitirá al modelo tal cual. Si se introduce un valor que no es compatible con el modo o modelo actual, puede manifestarse como que el valor se ignore; se recomienda confirmar primero el efecto con una solicitud antes de utilizarlo por lotes.

## Función Add Insterumental

En agosto de 2025, suno lanzó la nueva función Add Insterumental. Primero es necesario subir una canción a capela sin acompañamiento, para que suno te ayude a añadirle música. Primero puedes ir a [Suno Upload API](https://platform.acedata.cloud/documents/suno-upload) para subir una canción a capela sin acompañamiento; las operaciones correspondientes se muestran en la siguiente imagen:

Finalmente se obtuvo un `audio_id`: 92254cab-3372-4d9e-bce9-cdcfdbc39070, y luego también necesitamos completar los siguientes parámetros:
- action：el contenido es `underpainting`。
- underpainting_start：el tiempo de inicio para añadir acompañamiento a la canción subida, el valor predeterminado es 0。
- underpainting_end：el tiempo de finalización para añadir acompañamiento a la canción subida, debe ser menor que la duración total de la canción。
- audio_id：el ID de la canción a capela subida sin acompañamiento。
- style：el estilo del acompañamiento, es mejor no usar letra después de todo es acompañamiento。

## Función de creación por inspiración Inspo

La función de creación por inspiración Inspo puede generar música nueva a partir de 1 a 4 fragmentos completos de audio de referencia, y permite arrastrar o subir audio como fuente de inspiración. La API utiliza la acción `inspo` existente: el cliente proporciona URL de audio públicamente accesibles, y el servicio completará automáticamente la preparación del audio de referencia y la creación, sin necesidad de que el cliente lea por separado la letra, el estilo o la duración y luego ensamble la solicitud. Es diferente del muestreo por intervalos mencionado anteriormente y también diferente de Cover, que reproduce el estilo de la canción original. Al usarla, se deben completar los siguientes parámetros:

- action: el contenido es `inspo`.
- audio_urls: lista de URL de audio de referencia; se deben proporcionar de 1 a 4 direcciones de audio públicamente accesibles.
- model: el modelo utilizado; se recomienda `chirp-v6`.
- prompt: letra o texto de indicación creativa (opcional).

> Nota: El audio de referencia debe ser un archivo de audio públicamente accesible. Si el audio de referencia coincide completamente con una grabación conocida de la biblioteca musical de la plataforma, Suno podría rechazar la generación debido a la verificación de derechos de autor; se recomienda utilizar audio propio o generado por Suno como fuente de inspiración.

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Devolución de llamada asíncrona

Dado que el tiempo de generación de música de Suno es relativamente largo, aproximadamente de 1 a 2 minutos, si la API no responde durante mucho tiempo, la solicitud HTTP mantendrá la conexión continuamente, lo que provoca un consumo adicional de recursos del sistema, por lo que esta API también proporciona soporte para devoluciones de llamada asíncronas.

El proceso general es: cuando el cliente inicia una solicitud, especifica adicionalmente un campo `callback_url`; después de que el cliente inicia la solicitud a la API, la API devolverá inmediatamente un resultado que incluye la información de un campo `task_id`, que representa el ID de la tarea actual. Cuando la tarea se complete, el resultado de la música generada se enviará mediante POST JSON al `callback_url` especificado por el cliente, que también incluye el campo `task_id`, de esta manera los resultados de la tarea pueden asociarse mediante el ID.

A continuación, veamos cómo operar específicamente mediante un ejemplo.
