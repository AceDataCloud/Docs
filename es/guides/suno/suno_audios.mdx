A medida que la aplicación de la IA se amplía, diversos programas de IA se han ido popularizando gradualmente. La IA se ha ido integrando gradualmente en todos los aspectos del trabajo y la vida de las personas. Y las industrias involucradas por la IA también son cada vez más numerosas, desde la escritura inicial, hasta la medicina y la educación, y ahora la música.

Suno es una plataforma profesional y de alta calidad para la creación de canciones y música con IA; los usuarios solo necesitan introducir simples palabras de indicación de texto para generar canciones con voces según el estilo del género y la letra. Este generador de música con IA fue desarrollado por miembros de equipos de conocidas empresas tecnológicas como Meta, TikTok y Kensho, con el objetivo de no requerir ninguna herramienta instrumental y permitir que todos puedan crear música maravillosa.

El modo de inspiración no personalizado (cuando `custom` es `false`) solo completa `prompt`, cuyo límite de longitud es de 500 caracteres (igual para todos los modelos).

Suno ahora admite `chirp-v6`, `chirp-v6-wild` y `chirp-v6-mini`. Se recomienda utilizar `chirp-v6`; los nombres de los modelos antiguos siguen siendo compatibles.

Sin embargo, Suno oficialmente no proporciona una API, y AceDataCloud ofrece un conjunto de API de Suno que simula la integración oficial de Suno, permitiendo generar de forma cómoda y rápida la música deseada.

## Solicitud y uso

Para utilizar Suno Audios Generation API, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o no se ha registrado, se redirigirá automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; al completarlo, volverá automáticamente a la página actual.

**Un API Token puede llamar a todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluye crédito gratuito, que permite una experiencia gratuita; cuando el crédito sea insuficiente, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Uso básico

Puede pensar en cualquier canción e introducir arbitrariamente un texto; por ejemplo, si quiero generar una canción sobre Navidad, puedo introducir `a song for Christmas`, como se muestra en la imagen:

<p><img src="https://cdn.acedata.cloud/2kuuup.png" width="500" className="m-auto" /></p>

Aquí podemos ver que hemos configurado los Request Headers, incluidos:

- `accept`: qué formato de resultado de respuesta se desea recibir; aquí se completa como `application/json`, es decir, formato JSON.
- `authorization`: la clave para llamar a la API, que puede seleccionarse directamente desde la lista desplegable después de solicitarla.

Además, se configuró el Request Body, que incluye:
- `action`: La acción de esta tarea de generación de música, el valor predeterminado es `generate`, incluye principalmente: `extend`, `upload_extend`, `cover`, `upload_cover`, `replace_section`, `replace_section`, `concat`, `stems`, `all_stems`, `remaster`.
- `prompt`: La palabra clave del modo de inspiración oficial de Suno (tiene efecto cuando `custom` es `false`), máximo 500 caracteres.
- `model`: El modelo de esta tarea de generación de música. La serie v6 incluye `chirp-v6`, `chirp-v6-wild` y `chirp-v6-mini`; los nombres de modelos antiguos siguen siendo compatibles.
- `lyric`: El contenido de la letra del modo personalizado oficial de Suno. `chirp-v3-5` y `chirp-v4` tienen un máximo de 3000 caracteres; `chirp-v4-5` y superiores (incluidos `chirp-v5`, `chirp-v5-5`) tienen un máximo de 5000 caracteres.
- `custom`: Si se utiliza el modo personalizado, el valor predeterminado es: `false`.
- `instrumental`: La opción de música instrumental del modo de inspiración oficial de Suno.
- `title`: El título de la música del modo personalizado oficial de Suno. `chirp-v3-5`, `chirp-v4` tienen un máximo de 80 caracteres; `chirp-v4-5` y superiores tienen un máximo de 100 caracteres.
- `style`: El estilo musical del modo personalizado oficial de Suno. `chirp-v3-5` y `chirp-v4` tienen un máximo de 200 caracteres; `chirp-v4-5` y superiores (incluidos `chirp-v5`, `chirp-v5-5`) tienen un máximo de 1000 caracteres.
- `negative_tags`: Estilos musicales o géneros que se desean excluir de los resultados generados en el modo personalizado (cuando `custom` es `true`).
- `audio_weight`: La proporción del audio de referencia cargado, rango 0-1; cuanto mayor sea, más dependerá del audio de referencia.
- `audio_id`: El ID de la música de referencia.
- `overpainting_start`/`overpainting_end`: El tiempo de inicio y fin para añadir voces a música instrumental existente, en segundos.
- `underpainting_start`/`underpainting_end`: El tiempo de inicio y fin para añadir acompañamiento a canto a capela, en segundos.
- `persona_id`: El ID de la canción del artista.
- `continue_at`: El límite de continuación, en segundos. Por ejemplo, 213.5 indica generar el fragmento posterior a partir de los 3 minutos y 33.5 segundos. `lyric` y `style` solo guían el contenido nuevo posterior al límite y no reemplazan la letra ni el canto anteriores al límite en el audio fuente.
- `style_influence`: El parámetro avanzado «Style Influence» en el modo personalizado, rango 0-1; cuanto mayor sea, más se ajustará al estilo seleccionado.
- `replace_section_end`: El tiempo final del fragmento que se va a reemplazar.
- `replace_section_start`: El tiempo de inicio del fragmento que se va a reemplazar.
- `vocal_gender`: Controla la preferencia de voz femenina o masculina, voz femenina `f`, voz masculina `m`; válido para modelos 4.5 y superiores; es un elemento de preferencia, no se garantiza un cumplimiento estricto.
- `weirdness`: El parámetro avanzado «Weirdness» en el modo personalizado, rango 0-1; cuanto mayor sea, más creativo y experimental será.
- `duration`: La duración esperada de la canción, en segundos, debe ser un entero, con un rango de 10 a 360. Este parámetro se utiliza para la generación de canciones en modo personalizado (cuando `custom` es `true`). Es una indicación de preferencia y no una restricción estricta: el modelo la tendrá en cuenta, pero no garantiza alcanzarla; la duración real del producto final se rige por el campo `duration` de la respuesta y normalmente es menor que el valor esperado.
- `lyric_prompt`: El prompt para generar la letra, tiene efecto si y solo si `custom` es `true` y no se ha enviado `lyric`.
- `callback_url`: La URL que necesita recibir el resultado mediante callback.
- `async`: Opcional, cuando se establece en `true` la interfaz devuelve inmediatamente `task_id`, no es necesario proporcionar `callback_url`, y posteriormente se obtiene el resultado mediante sondeo a través de la interfaz de consulta de tareas correspondiente.

finalmente se obtiene que es necesario configurar esta canción como estilo de cantante, luego debe ingresar a [Suno Persona API](https://platform.acedata.cloud/documents/suno-persona) para generar un parámetro de id de estilo de cantante `persona_id` según el ID de música oficial generado `audio_id`; los parámetros específicos se muestran en la siguiente imagen:

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/persona"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "audio_id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f",
    "name": "test"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

## Función de continuación de generación

Si desea continuar generando una canción de Suno que ya ha sido generada, puede configurar el parámetro `action` como `extend` e introducir el ID de la canción que debe seguir generándose. La obtención del ID de la canción se realiza según el uso básico; mediante lo anterior se puede saber que, en este momento, se puede ver que el ID de la canción es:

```
"id": "97efc9f4-0e8d-4b3e-88df-14568fa1b11f"
```

> Tenga en cuenta que el `id` en la letra aquí es el ID de la canción generada. Si no sabe cómo generar una canción, puede consultar el uso básico anterior para generar una canción.

Si desea continuar generando una canción que haya subido usted mismo, puede configurar el parámetro `action` como `upload_extend` e introducir el ID de la canción personalizada subida que debe seguir generándose. La obtención del ID de la canción se realiza utilizando [Suno Upload Generation API](https://platform.acedata.cloud/documents/suno-upload), como se muestra en la siguiente imagen:

<p><img src="https://cdn.acedata.cloud/a0mn5e.png" width="500" className="m-auto" /></p>

A continuación, debe completar la letra del fragmento de continuación y puede especificar el estilo:

- lyric: solo se utiliza para guiar la letra del fragmento recién generado después de `continue_at`; no reemplazará la letra anterior a ese punto de tiempo en el audio de origen.
- custom: complete con `true`, lo que representa generación personalizada; este parámetro tiene como valor predeterminado false, lo que representa la generación mediante `prompt`.
- style: el estilo de canción del fragmento de continuación, opcional.
- continue_at: límite de continuación, en segundos. Por ejemplo, 213.5 indica que se comenzará a generar el fragmento posterior desde los 3 minutos y 33.5 segundos.

> `extend` se utiliza para continuar creando a partir de una canción existente, no para cambiar la letra de toda la canción. Si desea utilizar una nueva letra desde el principio para toda la canción, utilice `generate` para volver a generarla; si desea reinterpretar una canción existente como referencia, puede utilizar `cover`. Al pasar una letra nueva completa, la letra original anterior a `continue_at` seguirá sin ser reemplazada.

El ejemplo de llenado es el siguiente:

<p><img src="https://cdn.acedata.cloud/zp9s42.png" width="500" className="m-auto" /></p>

Después de completar, se genera automáticamente el siguiente código:
<p><img src="https://cdn.acedata.cloud/wwpw78.png" width="500" className="m-auto" /></p>

Lo que se conserva a continuación es una instantánea de una llamada histórica real, donde `continue_at` es de 2 segundos, por lo que solo los primeros 2 segundos pertenecen al contenido original anterior al límite de continuación. Al continuar realmente cerca del final de una canción, este valor debe establecerse en el segundo en el que se espera comenzar la continuación, y solo se debe proporcionar en `lyric` el nuevo fragmento que se cantará después del límite.

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "extend",
    "prompt": "A song for Christmas",
    "model": "chirp-v4-5",
```

## Obtener la canción completa

El resultado de `extend` del modelo actual normalmente ya incluye el audio de origen anterior a `continue_at` y el nuevo contenido posterior al límite; primero determine si ya es una canción completa según la duración real y el contenido del audio devuelto. Si lo devuelto es un fragmento de continuación independiente, o si necesita combinar explícitamente el historial de varias continuaciones en una canción, utilice entonces la función de concatenación:

- action: el contenido es `concat`.
- audio_id: el ID del último fragmento de continuación.

```json
{

}
```

## Versión de música

- action: el contenido es `cover`; cuando se realiza una operación de versión sobre música personalizada subida, se debe especificar el contenido como: `upload_cover`.
- audio_id: el ID de la canción generada anteriormente.

Por ejemplo, si el ID de la canción generada originalmente es: 0a1e1b10-c36a-41c9-9bfb-b26d9d25db98, entonces se pueden establecer los parámetros de la siguiente manera:

```json
{
  "action": "cover",
```

## Reemplazar fragmento

Cuando, después de generar una canción, se necesita realizar una segunda creación mediante una operación independiente de reemplazo de fragmentos de la canción, se puede realizar una operación de reemplazo en un fragmento de la canción.

> ⚠️ **Nota**: `replace_section_result_mode` tiene como valor predeterminado `full_song`: el sistema ensamblará respectivamente 2 candidatos generados nuevos y devolverá 2 canciones completas. Si solo se necesitan los candidatos de fragmentos de reemplazo que aún no se han ensamblado, establezca explícitamente como `candidates`, y luego seleccione un candidato para llamar a [ensamblaje de música](#音乐拼接).

La descripción de los parámetros es la siguiente:

- action: el contenido es `replace_section`.
- audio_id: el ID de la canción original (la canción fuente que se reemplaza).
- model: el modelo de generación de canciones.
- lyric: la letra completa después del reemplazo (incluye el fragmento reemplazado y su contexto, y se mantiene coherente con el contenido de `prompt`).
- prompt: la nueva letra del fragmento que se necesita reemplazar.
- style: el estilo de la canción, opcional.
- replace_section_start: el tiempo de inicio del fragmento reemplazado en la canción original (segundos).
- replace_section_end: el tiempo de finalización del fragmento reemplazado en la canción original (segundos).
- replace_section_result_mode: el modo de devolución, cuyo valor predeterminado es `full_song`. `full_song` ensambla respectivamente 2 candidatos y devuelve 2 canciones completas; `candidates` devuelve 2 fragmentos candidatos que aún no se han ensamblado.

## Controlar la duración de la canción

De forma predeterminada, la duración de las canciones generadas la decide el propio modelo, normalmente entre 30 segundos y 4 minutos. Si se necesita un producto final más largo o más corto, se puede especificar la duración esperada mediante el parámetro `duration`, cuya unidad son segundos y cuyo valor es un número entero entre 10 y 360.

Este parámetro se utiliza para la generación de canciones en modo personalizado (`custom` es `true`). Cabe señalar especialmente que `duration` es una **indicación de tendencia, no una restricción estricta**: el modelo hará referencia a este valor al crear, pero no garantiza alcanzarlo; en las pruebas, la duración real suele ser claramente menor que el valor esperado, y las duraciones de las dos canciones devueltas por la misma solicitud también pueden diferir varias veces. Incluso con solicitudes completamente idénticas, las duraciones obtenidas tras varios envíos también pueden tener grandes diferencias. Por lo tanto, no lo utilices como un control preciso de duración; si se necesita una duración fija para el negocio, recorta o vuelve a intentarlo por tu cuenta después de obtener el producto final.

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "generate",
    "model": "chirp-v5-5",
    "custom": True,
    "title": "Under the City Lights",
    "style": "lo-fi piano",
    "lyric": "[Verse]\nSunrise creepin\nGold on the floor\n[Chorus]\nUnder the city lights\n",
    "duration": 330
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Cabe señalar que el `duration` de la solicitud es la **duración esperada**, mientras que el campo `duration` de cada canción en los `data` de la respuesta es la **duración real** de esa canción. Ambos tienen el mismo nombre, pero significados diferentes; no se garantiza que la duración real sea igual al valor esperado. La longitud de la letra es uno de los principales factores que afectan a la duración del producto final; si se necesita un producto final más largo, se recomienda proporcionar al mismo tiempo una letra más completa.

La interfaz no realizará validaciones adicionales sobre `duration`; el parámetro se pasará al modelo tal cual. Si se proporciona un valor no compatible con el modo o modelo actual, puede ocurrir que dicho valor se ignore; se recomienda confirmar el efecto con una solicitud antes de utilizarlo en lotes.

## Función Añadir instrumental

En agosto de 2025, Suno lanzó la nueva función Añadir instrumental. Primero es necesario subir una canción a capela sin acompañamiento, para que Suno te ayude a añadir música. Primero puedes ir a [Suno Upload API](https://platform.acedata.cloud/documents/suno-upload) para subir una canción a capela sin acompañamiento; las operaciones correspondientes se muestran en la siguiente imagen:

<p><img src="https://cdn.acedata.cloud/fxl914.png" width="500" className="m-auto" /></p>

Luego debes registrar el `audio_id` después de la carga; el resultado específico se muestra en la siguiente imagen:

<p><img src="https://cdn.acedata.cloud/47t6wj.png" width="500" className="m-auto" /></p>

Finalmente se obtiene un `audio_id`: 92254cab-3372-4d9e-bce9-cdcfdbc39070, y luego también debemos completar los siguientes parámetros:
- action: el contenido es `underpainting`.
- underpainting_start: la hora de inicio para añadir acompañamiento a la canción subida, el valor predeterminado es 0.
- underpainting_end: la hora de finalización para añadir acompañamiento a la canción subida, debe ser menor que la duración total de la canción.
- audio_id: el ID de la canción a capela subida sin doblaje.
- style: el estilo del acompañamiento, es mejor no usar letra después de todo es doblaje.

Después de completar, se genera automáticamente el siguiente código:

<p><img src="https://cdn.acedata.cloud/8x1ic6.png" width="500" className="m-auto" /></p>

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "underpainting",
    "model": "chirp-v4-5",
    "style": "Pop rap, uplifting, magnetic male vocals, piano, synth, electric guitar, driving bass, clear structure",
```

## Función Add Vocals

En agosto de 2025, suno lanzó la nueva función Add Vocals. Primero es necesario subir una pieza de música pura, para que suno escriba la letra y produzca canto vocal. ## Función de creación por inspiración de Inspo

La función de creación por inspiración de Inspo puede generar música nueva basándose en 1 a 4 segmentos completos de audio de referencia, y admite arrastrar o cargar audio como fuente de inspiración. La API utiliza la acción existente `inspo`: el cliente proporciona URL de audio de acceso público, y el servicio completa automáticamente la preparación del audio de referencia y la creación, sin necesidad de que el cliente lea por separado la letra, el estilo o la duración para luego ensamblar la solicitud. Es diferente del muestreo por intervalo mencionado anteriormente, y también diferente del Cover que replica el estilo de la canción original. Al usarla, se deben completar los siguientes parámetros:

- action: el contenido es `inspo`.
- audio_urls: lista de URL de audio de referencia; se deben proporcionar de 1 a 4 direcciones de audio de acceso público.
- model: el modelo utilizado; se recomienda `chirp-v6`.
- prompt: letra o indicación creativa (opcional).

> Nota: El audio de referencia debe ser un archivo de audio de acceso público. Si el audio de referencia coincide completamente con una grabación conocida en la biblioteca musical de la plataforma, Suno puede rechazar la generación debido a la verificación de derechos de autor; se recomienda utilizar audio propio o generado por Suno como fuente de inspiración.

El código Python correspondiente:

```python
import requests

url = "https://api.acedata.cloud/suno/audios"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "action": "inspo",
    "model": "chirp-v6",
    "audio_urls": [
        "https://cdn.acedata.cloud/uploads/a0bc051f-42c2-4a46-aeb4-582dcc884ad2"
    ],
    "prompt": "Rework these references as warm acoustic folk with soft vocals"
}

response = requests.post(url, json=payload, headers=headers)
```

## Devolución de llamada asíncrona

Dado que el tiempo de generación de música de Suno es relativamente largo, aproximadamente de 1 a 2 minutos, si la API no responde durante mucho tiempo, la solicitud HTTP mantendrá la conexión de forma continua, lo que provoca un consumo adicional de recursos del sistema; por lo tanto, esta API también proporciona soporte para devoluciones de llamada asíncronas.

El flujo general es: cuando el cliente inicia una solicitud, especifica adicionalmente un campo `callback_url`; después de que el cliente inicia la solicitud a la API, la API devolverá inmediatamente un resultado que contiene la información del campo `task_id`, que representa el ID de la tarea actual. Cuando la tarea se complete, el resultado de la generación de música se enviará mediante POST JSON a la `callback_url` especificada por el cliente, que también incluye el campo `task_id`, de modo que los resultados de la tarea pueden asociarse mediante el ID.
