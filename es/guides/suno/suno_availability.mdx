---
title: "API de comprobación de disponibilidad de audio de Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` busca evidencia positiva de que el audio puede seguir procesándose en la línea actual según `audio_id`. Puede llamarse antes de operaciones como continuar escribiendo, hacer un cover, etc.; el resultado solo refleja el estado en el momento de la comprobación y no garantiza que una operación específica tenga éxito. Esta interfaz devuelve de forma síncrona, requiere un Token de API y actualmente no descuenta Credits.

`audio_id` es el ID de la canción devuelto por una tarea de Suno completada, no `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Ejemplo de respuesta exitosa:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

Cuando la comprobación tiene éxito, `data.available` solo será `true`. El estado «no disponible» devuelto por algunas líneas no puede demostrar que operaciones posteriores, como continuar escribiendo, no puedan tener éxito, por lo que esta interfaz devuelve `503 availability_unknown` cuando no puede confirmarlo, y no devuelve `false`. Un formato incorrecto de `audio_id` devuelve 400, y la limitación de velocidad o los fallos del upstream también devuelven una respuesta de error. El estado aún puede cambiar entre la finalización de la comprobación y la operación real.
