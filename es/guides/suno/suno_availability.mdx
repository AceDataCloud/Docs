---
title: "API de comprobación de disponibilidad de audio y voces de Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` acepta un ID de recurso. Para consultar canciones, envíe `audio_id`; para consultar voces, envíe `persona_id`; uno de los dos es obligatorio. La comprobación se completa de forma síncrona, requiere un Token de API y actualmente no consume Credits.

## Solicitud

`audio_id` proviene de una tarea de canción completada y puede usarse para una comprobación antes de continuar o hacer una versión.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

`persona_id` proviene del resultado de creación de voz. Use la aplicación original y la identidad del solicitante, y envíe el siguiente cuerpo de solicitud en la ruta de creación que admite consultas de voz.

```json
{
  "persona_id": "33333333-3333-4333-8333-333333333333"
}
```

## Respuesta

Ambos tipos de solicitud usan la misma respuesta exitosa. `data.id` es el ID del recurso consultado esta vez.

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

`available: true` indica que esta comprobación obtuvo evidencia positiva. Para las voces, la comprobación verifica la pertenencia de la creación y confirma que actualmente se informa que la cuenta asociada está en línea. El resultado real de la generación sigue estando sujeto a la tarea de generación.

Las voces clonadas privadas creadas mediante `/suno/voices` dependen de la cuenta creadora. Cuando se confirma que esa cuenta está actualmente fuera de línea, la interfaz devuelve HTTP 200 y `data` es como se muestra a continuación.

```json
{"id":"33333333-3333-4333-8333-333333333333","available":false}
```

El cliente puede marcar esta voz como actualmente no disponible y volver a consultarla más tarde.

Cuando no se puede confirmar, devuelve HTTP 503 y `availability_unknown`, por ejemplo, cuando no se encuentra el recurso, faltan rutas de creación en registros antiguos o se agota el tiempo de espera de la consulta. Los estilos de cantantes públicos pueden usarse entre cuentas y también devuelven 503 cuando la cuenta creadora está fuera de línea. Las consultas de canciones siguen devolviendo `available: true` solo cuando se confirma que están disponibles.

Cada solicitud solo envía un UUID válido. Todas las rutas devolverán HTTP 400 cuando reciban solicitudes con ambos ID o con ambos ID ausentes. Las rutas que solo admiten consultas de canciones devuelven HTTP 400 cuando reciben solicitudes que contienen únicamente `persona_id`. Si encuentra HTTP 429, reduzca la frecuencia de consulta.
