---
title: "API de comprobación de disponibilidad de audio de Suno"
description: "Suno Music Generation API guide - Ace Data Cloud"
---

`POST /suno/availability` busca evidencia positiva, según `audio_id`, de que el audio puede seguir procesándose en la ruta actual. Puede invocarse antes de operaciones como continuar o crear una versión; el resultado solo refleja el estado en el momento de la comprobación y no garantiza que una operación específica vaya a realizarse correctamente. Esta API responde de forma síncrona, requiere un token de API y actualmente no descuenta Credits.

`audio_id` es el ID de la canción devuelto por una tarea de Suno completada, no `task_id`.

```bash
curl -X POST 'https://api.acedata.cloud/suno/availability' \
  -H 'Authorization: Bearer YOUR_API_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"audio_id":"33333333-3333-4333-8333-333333333333"}'
```

Ejemplo de respuesta exitosa:

```json
{
  "success": true,
  "task_id": "11111111-1111-4111-8111-111111111111",
  "trace_id": "22222222-2222-4222-8222-222222222222",
  "data": {
    "id": "33333333-3333-4333-8333-333333333333",
    "available": true
  }
}
```

Cuando la comprobación tiene éxito, `data.available` es `true`; si no se puede confirmar, se devuelve `503 availability_unknown` y no se devuelve `false`. Un formato incorrecto de `audio_id` devuelve 400; los límites de tasa o las excepciones del servicio también devuelven una respuesta de error. El estado aún puede cambiar entre la finalización de la comprobación y la operación real.
