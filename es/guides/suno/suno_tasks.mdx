La función principal de Suno Tasks API es consultar el estado de ejecución de una tarea introduciendo el ID de tarea generado por Suno Audios Generation API o Suno Lyrics Generation API.

Este documento presentará en detalle las instrucciones de integración de Suno Tasks API, ayudándole a integrar fácilmente y aprovechar al máximo las potentes funciones de esta API. A través de Suno Tasks API, puede realizar fácilmente consultas sobre el estado de ejecución de las tareas de Suno Lyrics Generation API o Suno Audios Generation API.

## Proceso de solicitud

Para utilizar Suno Audios Generation API, primero obtenga su API Token en la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) y guárdelo como respaldo.

![](https://cdn.acedata.cloud/dvc3cg.jpg)

Si aún no ha iniciado sesión o se ha registrado, será redirigido automáticamente a la página de inicio de sesión para invitarle a registrarse e iniciar sesión; una vez completado, volverá automáticamente a la página actual.

**Un solo API Token puede llamar a todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** La primera solicitud incluye créditos gratuitos para una experiencia sin costo; cuando los créditos sean insuficientes, puede recargar saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [Suno Audios Generation API →](https://platform.acedata.cloud/documents/suno-audios)

## Ejemplo de solicitud

Suno Tasks API puede utilizarse para consultar los resultados de los dos API, Suno Audios Generation API y Suno Lyrics Generation API. Para saber cómo utilizar Suno Audios Generation API, consulte la documentación [Suno Audios Generation API ](https://platform.acedata.cloud/documents/suno-audios-integration). Para saber cómo utilizar Suno Lyrics Generation API, consulte [Suno Lyrics Generation API ](https://platform.acedata.cloud/documents/suno-lyrics-generation-integration).

### Configurar encabezados y cuerpo de la solicitud

**Request Headers** incluye:

- `accept`: especifica que se reciban resultados de respuesta en formato JSON; aquí se completa como `application/json`.
- `authorization`: la clave para llamar a la API, después de solicitarla puede seleccionarse directamente en la lista desplegable.

**Request Body** incluye:

- `id`: el ID de tarea cargado.
- `action`: el método de operación sobre la tarea.

Algunos ejemplos de código son los siguientes:

#### CURL

```bash
curl -X POST 'https://api.acedata.cloud/suno/tasks' \
-H 'accept: application/json' \
-H 'authorization: Bearer {token}' \
-H 'content-type: application/json' \
-d '{
  "id": "eae26f89-b64b-404d-a80c-761996660b1c",
  "action": "retrieve"
}'
```

#### Python

```python
import requests

url = "https://api.acedata.cloud/suno/tasks"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "id": "eae26f89-b64b-404d-a80c-761996660b1c",
    "action": "retrieve"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

El resultado devuelto tiene varios campos en total; el campo `request` es el request body al iniciar la tarea, mientras que el campo `response` es el response body devuelto tras completar la tarea. La descripción de los campos es la siguiente.

- `id`, el ID de la tarea de generación de esta canción, utilizado para identificar de forma única esta tarea de generación de canciones.
- `request`, la información de la solicitud en la consulta de la tarea de canción.
- `response`, la información de respuesta en la consulta de la tarea de canción.
- `created_at`, hora de creación de la tarea, marca de tiempo Unix (segundos, punto flotante).
- `started_at`, hora de inicio de ejecución de la tarea, marca de tiempo Unix (segundos, punto flotante).
- `finished_at`, hora de finalización de la tarea, marca de tiempo Unix (segundos, punto flotante). Este campo no se devuelve cuando la tarea no está finalizada.
- `elapsed`, tiempo de ejecución de la tarea, en segundos (punto flotante, conservando 3 decimales). Este campo no se devuelve cuando la tarea no está finalizada.

## Manejo de errores

Al llamar a la API, si se encuentra un error, la API devolverá el código de error y la información correspondientes. Por ejemplo:

- `400 token_mismatched`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `400 api_not_implemented`: Solicitud incorrecta, posiblemente debido a parámetros faltantes o no válidos.
- `401 invalid_token`: No autorizado, token de autorización no válido o faltante.
- `429 too_many_requests`: Demasiadas solicitudes, ha superado el límite de frecuencia.
- `500 api_error`: Error interno del servidor, algo salió mal en el servidor.
