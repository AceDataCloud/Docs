---
title: "Consultar tareas de modelos de Tripo"
description: "Tripo 3D API guide - Ace Data Cloud"
---

Llama a `POST /tripo/tasks` con un token de AceDataCloud. La consulta es gratuita; utiliza la misma cuenta que para la generación. Para una sola tarea, usa `id` o `trace_id`; `action` es `retrieve` de forma predeterminada.

```bash
curl -X POST https://api.acedata.cloud/tripo/tasks \
  -H "Authorization: Bearer ${ACEDATACLOUD_API_TOKEN}" \
  -H "Content-Type: application/json" \
  -d "{\"action\":\"retrieve\",\"id\":\"${TASK_ID}\"}"
```

El resultado de una consulta individual es un registro de tarea que incluye `id`, `type`, `trace_id`, la solicitud original `request`, `started_at` y `progress`. Mientras se procesa, puedes seguir consultando a intervalos de unos segundos. Una vez completada, comprueba `response.success`; si tiene éxito, `response.data[0].model_url` es la dirección de descarga, y si falla, `response.error` contiene el código y el mensaje de error. Las marcas de tiempo, `finished_at` y la duración `elapsed` se encuentran en el nivel superior del registro de tarea y se expresan en segundos. Si aparece `submission_unknown`, conserva el ID de la tarea original para verificarlo.

Para consultas por lotes, usa `{"action":"retrieve_batch","ids":["<ID de tarea 1>","<ID de tarea 2>"]}`; también puedes usar `trace_ids`. Se admiten hasta 100 tareas por consulta. La respuesta es `{"items":[...],"count":2}` y conserva el orden de entrada y los elementos duplicados. Para las tareas que no se encuentren o para las que no se tenga permiso de lectura, la consulta individual devuelve `{}` y la posición correspondiente en la consulta por lotes es `null`.

El `type` del registro de tarea es `generations`, `models` o `animations`. Para la comprobación del esqueleto, consulta `response.data[0].riggable`; para las operaciones con archivos, consulta `response.data[0].model_url`.
