Kimi es una serie de modelos de IA lanzada por Moonshot AI. Actualmente se recomienda `kimi-k3.1-pro`, adecuado para programación de largo alcance, razonamiento complejo, comprensión visual y trabajo basado en el conocimiento; `kimi-k3` sigue estando disponible. Se puede acceder a ellos mediante la API Chat Completions compatible con OpenAI.

Este documento presenta principalmente el proceso de uso de la API Kimi Chat Completion, que nos permite utilizar fácilmente la función de conversación oficial de Kimi.

## Modelos compatibles

Actualmente son compatibles cuatro modelos: `kimi-k3.1-pro`, `kimi-k3`, `kimi-k2.6` y `kimi-k2.7-code`. K2.7 Code está orientado a escenarios de programación y llamadas a herramientas, y se factura al mismo precio que K2.6; no se deben enviar el interruptor `thinking` ni `reasoning_effort` en las solicitudes dirigidas a este modelo. Los demás modelos de Kimi han dejado de ser compatibles. Selecciona explícitamente uno de estos cuatro modelos en el cliente.

## Proceso de solicitud

Para utilizar la API Kimi Chat Completion, primero accede a la [consola de Ace Data Cloud](https://platform.acedata.cloud/console/applications) para obtener tu API Token y guardarlo para utilizarlo posteriormente.

![]()

Si todavía no has iniciado sesión o no te has registrado, serás redirigido automáticamente a la página de inicio de sesión, donde se te invitará a registrarte e iniciar sesión. Una vez completado el proceso, volverás automáticamente a la página actual.

**Un solo API Token permite llamar a todos los servicios de la plataforma, sin necesidad de solicitar uno por separado para cada servicio.** Al solicitarlo por primera vez, recibirás una cuota gratuita que podrás utilizar para probar el servicio sin coste; cuando la cuota sea insuficiente, podrás recargar el saldo general en la [consola](https://platform.acedata.cloud/console/coin).

> 📘 Documentación completa: [API Kimi Chat Completion →](https://platform.acedata.cloud/documents/kimi-chat-completions)

A continuación, puedes introducir el contenido correspondiente en la interfaz, como se muestra en la imagen:

La primera vez que utilices esta interfaz, deberás rellenar al menos tres campos: `authorization` se puede seleccionar directamente desde la lista desplegable; `model` se utiliza para seleccionar el modelo de Kimi, y se recomienda utilizar `kimi-k3.1-pro`; `messages` es un array de mensajes de conversación, cada uno de los cuales contiene `role` y `content`, donde `role` admite `user`, `assistant`, `system` y `tool`.

Al mismo tiempo, puedes observar que a la derecha se genera el código correspondiente para realizar la llamada. Puedes copiar el código y ejecutarlo directamente, o hacer clic en el botón «Try» para realizar una prueba.

El resultado devuelto contiene varios campos, que se describen a continuación:

- `id`: el ID generado para esta tarea de conversación, utilizado para identificarla de forma única.
- `model `: el modelo del sitio web oficial de Kimi seleccionado.
- `choices`: la información de respuesta que Kimi proporciona a la pregunta.
- `usage `: las estadísticas de tokens correspondientes a esta sesión de preguntas y respuestas.

Entre ellos, `choices` contiene la información de respuesta de Kimi. Su contenido incluye los detalles específicos de la respuesta de Kimi, como se puede observar en la imagen.

Como puedes ver, el campo `content` dentro de `choices` contiene el contenido específico de la respuesta de Kimi; K3 también puede devolver `reasoning_content`, que se utiliza para representar el proceso de razonamiento.

## Intensidad de razonamiento de K3.1 Pro

`kimi-k3.1-pro` siempre tiene el razonamiento habilitado. Puedes establecer `reasoning_effort` en el nivel superior del cuerpo de la solicitud con el valor `low`, `high` o `max`; no envíes ninguna configuración para desactivar el razonamiento. El modelo admite un contexto de hasta 1.048.576 tokens, pero el límite real de cada solicitud sigue dependiendo de la interfaz actual. El precio se calcula según el uso de tokens de entrada, salida y aciertos de caché. Para obtener más información, consulta la tarjeta Pricing del catálogo de modelos.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3.1-pro",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "low"
  }'
```

Los siguientes ejemplos de K3 se conservan para las integraciones existentes; las respuestas de ejemplo se obtuvieron efectivamente mediante solicitudes a K3.

## Intensidad de razonamiento de K3

`kimi-k3` siempre tiene el razonamiento habilitado. El nivel superior del cuerpo de la solicitud admite el campo `reasoning_effort`, cuyo único valor compatible actualmente es `max`; si se omite este campo, también se utilizará `max`. Utiliza los valores compatibles.

```bash
curl https://api.acedata.cloud/kimi/chat/completions \
  -H "Authorization: Bearer $ACEDATACLOUD_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kimi-k3",
    "messages": [{"role": "user", "content": "审查这段代码并给出修复方案"}],
    "reasoning_effort": "max"
  }'
```

Al utilizar el SDK de OpenAI, puedes pasar directamente este campo:

```python
response = client.chat.completions.create(
    model="kimi-k3",
    messages=[{"role": "user", "content": "设计一个可靠的任务队列"}],
    reasoning_effort="max",
)
```

En las conversaciones de varias rondas y las llamadas a herramientas, devuelve el mensaje completo del assistant de la ronda anterior a `messages`, incluidos `reasoning_content` y `tool_calls`.

### Referencias oficiales

- [Thinking Effort](https://platform.kimi.ai/docs/guide/use-thinking-effort): explica que Kimi K3 siempre tiene el razonamiento habilitado y que el único valor compatible actualmente para `reasoning_effort` es `max`.
- [Model Parameter Reference](https://platform.kimi.ai/docs/api/models-overview): compara las diferencias entre K3 y la serie K2 en cuanto a parámetros de razonamiento, ventanas de contexto y llamadas a herramientas.
- [Create Chat Completion](https://platform.kimi.ai/docs/api/chat): definiciones oficiales de Moonshot para las solicitudes, respuestas y campos OpenAPI de Chat Completions.

## Respuesta en streaming

Esta interfaz también admite respuestas en streaming, lo que resulta muy útil para la integración en páginas web, ya que permite implementar un efecto de visualización progresiva, palabra por palabra.

Si deseas obtener una respuesta en streaming, puedes modificar el parámetro `stream ` de los encabezados de la solicitud y cambiarlo a `true`.

Modifícalo como se muestra en la imagen. Sin embargo, el código de llamada también debe modificarse correspondientemente para admitir las respuestas en streaming.

<p><img src="https://cdn.acedata.cloud/a3nzpw.png" width="400" className="m-auto" /></p>
Después de modificar `stream` a `true`, la API devolverá los datos JSON correspondientes línea por línea. A nivel de código, debemos realizar los cambios necesarios para obtener los resultados línea por línea.

Código de ejemplo de llamada en Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"user","content":"Hello"}],
    "reasoning_effort": "max",
    "stream": True
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

A continuación, se muestran fragmentos iniciales, de razonamiento, del contenido principal, de finalización y de uso de una misma respuesta real en streaming de K3 Max:

```json
data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"","role":"assistant"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"reasoning_content":"The"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{"content":"Hello"},"finish_reason":null}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":null}

data: {"id":"msg_er7WZjyv2kD3TG2yzbFPu5ZJ","object":"chat.completion.chunk","created":1784466598,"model":"kimi-k3","choices":[],"usage":{"prompt_tokens":172,"completion_tokens":168,"total_tokens":340}}

data: [DONE]
```

Como puede observarse, la respuesta contiene numerosos `data`, y los `choices` dentro de `data` corresponden al contenido más reciente de la respuesta, tal como se ha explicado anteriormente. `choices` contiene el nuevo contenido de la respuesta, que puede integrarse en su sistema según los resultados obtenidos. Al mismo tiempo, la finalización de la respuesta en streaming se determina según el contenido de `data`. Si el contenido es `[DONE]`, significa que la respuesta en streaming ha finalizado por completo. Los resultados `data` devueltos contienen varios campos. A continuación, se describen:

- `id`: el ID generado para esta tarea de conversación, que se utiliza para identificarla de forma única.
- `model `: el modelo del sitio web oficial de Kimi seleccionado.
- `choices`: la información de respuesta que Kimi proporciona a la pregunta formulada.

JavaScript también es compatible. Por ejemplo, el código de llamada en streaming de Node.js es el siguiente:

```javascript
const options = {
  method: "POST",
  headers: {
    accept: "application/json",
    authorization: "Bearer {token}",
    "content-type": "application/json"
  },
  body: JSON.stringify({
    model: "kimi-k3",
    messages: [{ role: "user", content: "Hello" }],
    stream: true
  })
};

const response = await fetch("https://api.acedata.cloud/kimi/chat/completions", options);
const reader = response.body.getReader();
const decoder = new TextDecoder("utf-8");
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  process.stdout.write(decoder.decode(value));
}
```

Código de ejemplo en Java:

```java
JSONObject jsonObject = new JSONObject();
jsonObject.put("model", "kimi-k3");
jsonObject.put("messages", new JSONArray().put(new JSONObject().put("role", "user").put("content", "Hello")));
jsonObject.put("stream", true);
MediaType mediaType = MediaType.parse("application/json; charset=utf-8");
RequestBody body = RequestBody.create(jsonObject.toString(), mediaType);
Request request = new Request.Builder()
  .url("https://api.acedata.cloud/kimi/chat/completions")
  .post(body)
  .addHeader("accept", "application/json")
  .addHeader("authorization", "Bearer {token}")
  .addHeader("content-type", "application/json")
  .build();

OkHttpClient client = new OkHttpClient();
Response response = client.newCall(request).execute();
System.out.println(response.body().string());
```

Para otros lenguajes, puede realizar la adaptación por su cuenta. El principio es el mismo.

## Conversaciones de múltiples turnos

Si desea integrar la función de conversaciones de múltiples turnos, debe enviar varias preguntas en el campo `messages`. A continuación, se muestra un ejemplo concreto de varias preguntas:

<p><img src="https://cdn.acedata.cloud/g85v2a.png" width="400" className="m-auto" /></p>

Código de ejemplo de llamada en Python:

```python
import requests

url = "https://api.acedata.cloud/kimi/chat/completions"

headers = {
    "accept": "application/json",
    "authorization": "Bearer {token}",
    "content-type": "application/json"
}

payload = {
    "model": "kimi-k3",
    "messages": [{"role":"assistant","content":"Hello! How can I help you today?"},{"role":"user","content":"What model are you?"}],
    "reasoning_effort": "max"
}

response = requests.post(url, json=payload, headers=headers)
print(response.text)
```

Al enviar varias preguntas, puede implementar fácilmente conversaciones de múltiples turnos. A continuación, se muestra la respuesta real de K3 Max obtenida mediante esta solicitud (se omiten los campos de extensión no utilizados):

```json
{
  "id": "msg_Rqp8nPGBDHWwBlL4VpxuafOp",
  "object": "chat.completion",
  "created": 1784466628,
  "model": "kimi-k3",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",

      },
      "logprobs": null,

    }

  "usage": {
```

Como puede observarse, la información incluida en `choices` es coherente con la del uso básico. Contiene las respuestas específicas que Kimi proporciona a los distintos turnos de conversación, lo que permite responder a las preguntas correspondientes según el contenido de cada conversación.

## Gestión de errores

Al llamar a la API, si se produce algún error, la API devolverá el código y la información de error correspondientes. Por ejemplo:

- `400 token_mismatched`: Bad request, possibly due to missing or invalid parameters.
- `400 api_not_implemented`: Bad request, possibly due to missing or invalid parameters.
- `401 invalid_token`: Unauthorized, invalid or missing authorization token.
- `429 too_many_requests`: Too many requests, you have exceeded the rate limit.
- `500 api_error`: Internal server error, something went wrong on the server.

### Ejemplo de respuesta de error

```
{

    "message": "fetch failed"
  },
  "trace_id": "2cf86e86-22a4-46e1-ac2f-032c0f2a4e89"

```
